## Xulosa

OmniRoute endi `/api/v1/relay/chat/completions` uchun uchta relay rejimini qoʻllab-quvvatlaydi:

- `ts`: TypeScript relay’dan jarayon ichida foydalanadi.
- `bifrost`: Bifrost shlyuzidan majburiy foydalanadi.
- `auto`: Mavjud boʻlganda Bifrost’ni afzal koʻradi, xatolik yuz bersa TypeScript’ga qaytadi.

Yuqori soʻrov tezligida (kuniga koʻp sonli tokenlar, deyarli uzluksiz trafik) ishlayotganingizda, eng yaxshi strategiya — asosiy ishlov berish yoʻli ishlamayotgan sidecar sababli hech qachon bloklanmasligi uchun zaxira yoʻlini aniq va tez saqlashdir.

## Rejimlarning ishlashi

- `ts`
  - Eng past operatsion murakkablik.
  - Barcha marshrutlash va tekshirish ishlari Node’da bajariladi.
  - Ishlash imkoniyati sidecar’ga bogʻliq emas.
- `bifrost`
  - Barcha soʻrovlarni sidecar shlyuzi orqali majburiy oʻtkazadi.
  - Avtomatik zaxira yoʻliga oʻtish mavjud emas.
  - Faqat sidecar holati va kechikishi kafolatlanganida foydali.
- `auto`
  - Sidecar yoqilgan va unga ulanish mumkin boʻlganda undan foydalaniladi.
  - Muvaffaqiyatsiz urinishlar zaxira yoʻliga oʻtish sarlavhalarini ishga tushiradi va soʻrovlar muvaffaqiyati cheklangan vaqt ichida taʼminlanishi uchun trafikni TS’ga qaytaradi.
  - Ishlash uzluksizligi faqat sidecar orqali qatʼiy marshrutlashdan muhimroq boʻlgan ishlab chiqarish muhitlari uchun bu rejim eng xavfsiz tanlovdir.

## Bugungi kunda 9router va CLIPROXYAPI

9router va CLIPROXYAPI — tarixan yuqori oqim provayderlari uchun moslik yoʻllarini taqdim etgan integratsiyalardir.

- 9router — yuqori oqimni muvofiqlashtirish va moslik mexanizmlari uchun ichki yoʻl.
- CLIPROXYAPI — CLI / SDK uslubidagi trafik uchun proksi API koʻprigi.
- Maxsus sidecar’ga oʻxshash oraliq bosqich va past kechikishli lokal taqsimlash zarur boʻlganda, Bifrost tashqi yoʻl sifatida barqarorlashtirilmoqda.

Agar hozirda 9router/CLIPROXYAPI’ni taqqoslayotgan boʻlsangiz:

- Soʻrovni imzolash, ruxsat etilganlar roʻyxatini tekshirish va DB siyosati shlyuzlarini uzatishdan oldin API marshrutida saqlang.
- Agar ish jarayoni qatʼiy sidecar ishlashini va har bir soʻrov boʻyicha kamroq tafovutni talab qilsa, `OMNIROUTE_RELAY_BACKEND=bifrost` dan foydalaning.
- Agar nosozlik holatlarida bosqichma-bosqich yomonlashish bilan sidecar bardoshliligi kerak boʻlsa, `OMNIROUTE_RELAY_BACKEND=auto` dan foydalaning.

## Backend chegarasi shartnomasi

Barqaror mahsulot chegarasi boshqaruv paneli implementatsiyasi emas, balki OmniRoute relay API hisoblanadi. Next.js boshqaruv paneli lokal xizmatlarni oʻrnatishi, sozlashi va nazorat qilishi mumkin, biroq soʻrovlarni marshrutlash relay API orqali kirib, shu chegara ortida uzatilishi kerak.

Uzoq muddatli backend tanlovlari:

- TypeScript relay’ni jarayon ichidagi siyosat va zaxira yoʻli sifatida saqlang. Autentifikatsiya, ruxsat etilganlar roʻyxati, soʻrovlarni normallashtirish, hisobga olish va xavfsizlik tekshiruvlari har qanday backend’ga uzatishdan oldin shu yerda qoladi.
- Joylashtirish kamroq marshrutlash tafovuti, provayderlarni markazlashtirilgan almashtirish yoki bir nechta OmniRoute nusxalari boʻylab masshtablashni talab qilganda, Bifrost’dan afzal koʻriladigan yuqori oʻtkazuvchanlikka ega Tier-1 sidecar sifatida foydalaning.
- 9router va CLIPROXYAPI’ni ichki moslik xizmatlari sifatida saqlang. Ular nazorat qilinadigan lokal jarayonlar sifatida ishlaydi va ularning provayder/CLI xatti-harakati kerakli adapter boʻlganda foydalidir, biroq ular standart Tier-1 marshrutlash mexanizmiga aylanmasligi kerak.
- Boshqaruv paneliga ixtiyoriy xizmat URL’larini asosiy ishlov berish yoʻliga uzatish imkonini bermang. UI tomonidan taqdim etilgan URL’lar konfiguratsiya kirish maʼlumotlaridir; marshrutlash kodi server tomoni sozlamalari va nazoratchi holatidan roʻyxatdan oʻtgan, holati tekshirilgan backend’larni aniqlashi kerak.
- Bugungi kunda nazorat qilinadigan xizmatlar uchun loopback HTTP’ni afzal koʻring, chunki boshqariladigan jarayonlar allaqachon HTTP bilan mos API’larni taqdim etadi, marshrut himoyachisi chegarani audit qila oladi va xatolik/zaxira yoʻliga oʻtish xatti-harakati soʻrov jurnallarida koʻrinadi. Kelajakdagi SDK yoki soket transportini faqat u izolyatsiya yoki zaxira yoʻliga oʻtish semantikasini zaiflashtirmasdan p99 marshrutlash kechikishini sezilarli darajada kamaytirsagina qoʻshishga arziydi.

Shuning uchun juda yuqori oʻtkazuvchanlikka ega joylashtirish uchun standart javob — Bifrost yoqilgan holda `auto`: muvaffaqiyat darajasini taʼminlash uchun TypeScript zaxira yoʻlini saqlagan holda asosiy ishlov berish yoʻlida Go sidecar’dan foydalaning. `bifrost` dan faqat qatʼiy ravishda sidecar orqali ishlash bosqichma-bosqich yomonlashishdan muhimroq boʻlganda foydalaning.

## Yuqori oʻtkazuvchanlik boʻyicha tavsiyalar

Barqaror yuqori RPM/RPS va qatʼiy muvaffaqiyat SLO uchun:

1. Amaliy sovish davri va xatolik telemetriyasi bilan `auto` dan foydalaning.
2. Yuqori oqim tekshiruvlari va API kaliti tekshiruvlarini TypeScript marshrut chegarasida saqlang.
3. Ogohlantirish tizimingiz zaxira yoʻliga oʻtish chastotasi va sabablarini koʻrishi uchun aniq sarlavhalar/hisoblagichlarni yoqing.
4. Sidecar kutish vaqtlarini cheksiz kutishga emas, tez xato qaytarishga sozlang.
5. Zaxira yoʻliga oʻtish haqiqatan ham istisno boʻlib qolishi uchun xizmatni avtomatik qayta ishga tushirish va holat telemetriyasi siklini sogʻlom saqlang.

## Tavsiya etilgan boshlangʻich sozlamalar

- `OMNIROUTE_RELAY_BACKEND=auto`
- `BIFROST_ENABLED=1`
- API kalitlari, ruxsat etilganlar roʻyxati, sanitarizator va tezlikni cheklash tekshiruvlarini marshrut ishlov beruvchilarida yoqilgan holda saqlang (ular quyi oqimga uzatishdan oldin har doim bajariladi).
- Sidecar uzilishlari bir daqiqa ichida koʻrinishi uchun zaxira yoʻliga oʻtish metrikalarini teskari proksi va soʻrov jurnallaridan eksport qiling.

## Provayder plagini shartnomasi

Sidecar’lar TypeScript ijrochi mexanizmining ichki qismlariga bogʻlanish oʻrniga provayder metamaʼlumotlarini JSON uchun xavfsiz provayder plagini manifesti orqali import qilishi kerak. Sidecar muvofiqligi shartnomasi va migratsiya bosqichlari uchun [Provayder plagini manifesti](./PROVIDER_PLUGIN_MANIFEST.md) bilan tanishing.
