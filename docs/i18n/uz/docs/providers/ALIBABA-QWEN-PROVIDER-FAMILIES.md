Ushbu hujjatda
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854) uchun amalga oshirish qarori qayd etilgan. Ommaviy mahsulotlar
toʻrtta provayder oilasi sifatida taqdim etiladi. Mintaqa alohida mahsulot emas, balki ulanish maʼlumotidir.

## Qaror

| Provayder oilasi                                         | OmniRoute ID            | Global mintaqa | Xitoy mintaqasi |
| -------------------------------------------------------- | ----------------------- | -------------- | --------------- |
| Alibaba Cloud Model Studio (foydalanish boʻyicha toʻlov) | `alibaba`               | Singapur       | Pekin           |
| Alibaba Cloud Token Plan                                 | `bailian-coding-plan`   | Singapur       | Pekin           |
| Qwen Cloud (foydalanish boʻyicha toʻlov)                 | `qwen-cloud`            | Global         | Pekin           |
| Qwen Cloud Token Plan                                    | `qwen-cloud-token-plan` | Singapur       | Pekin           |

Mavjud `alibaba-cn` ID saqlangan ulanishlar, model
yoʻnalishlari, kombinatsiyalar va tarixiy foydalanish uchun ish vaqtidagi muvofiqlik taxallusi sifatida saqlanib qoladi. Uning boshqaruv panelidagi kartasi `alibaba` ichiga birlashtiriladi; maʼlumotlar bazasini
qayta yozish talab qilinmaydi.

Qwen Cloudʼning foydalanish boʻyicha toʻlovli mahsuloti va Alibaba Cloud Model Studio hozirda DashScope bilan mos
ish vaqti hostlaridan birgalikda foydalanadi, ammo ular alohida provayder identifikatorlari boʻlib qoladi, chunki foydalanuvchilar kalitlarni turli mahsulot interfeyslari orqali oladi va
hisoblarni shu interfeyslar orqali boshqaradi. Alibaba va Qwen Cloud Token Plan mahsulotlari
turli endpoint oilalaridan foydalanadi, shuning uchun barcha toʻrtta mahsulot alohida provayder IDlari sifatida qoladi.

API kaliti va endpoint bir xil mahsulot hamda mintaqaga tegishli boʻlishi kerak. Mintaqani tanlash
tekshiruv va odatiy soʻrovlar uchun ishlatiladigan oldindan sozlangan endpointni oʻzgartiradi.

## Ulanish shartnomasi

Yangi ulanishlar barqaror mintaqa kalitini `providerSpecificData` ichida saqlaydi:

```json
{
  "region": "global-sg"
}
```

Ruxsat etilgan qiymatlar: `global-sg` va `china-beijing`. Endpoint provayder IDsi va mintaqadan
markazlashgan tarzda hosil qilinadi. Oldindan sozlanmagan `providerSpecificData.baseUrl` operator tomonidan belgilangan aniq
ustun sozlama sifatida qoladi, eski saqlangan oldindan sozlangan URLlar esa mintaqaviy
matritsaga muvofiq qayta normallashtiriladi.

Bu ulanish sxemasining kengaytirilishini taʼminlaydi: boshqa mintaqani yangi provayder kartasini
yaratmasdan yoki saqlangan provayder IDlarini oʻzgartirmasdan resolverga qoʻshish mumkin.

## Moslik va bosqichma-bosqich joriy etish

1. Hududiy endpoint aniqlagichini qoʻshing va joriy global standart sozlamalarni saqlab qoling.
2. `alibaba`, uning `alibaba-cn` moslik IDsi va `qwen-cloud` uchun hududiy DashScope `/models` model aniqlash mexanizmidan real vaqtda foydalaning. Ularning javoblari avval matn yaratish modellariga moʻljallangan bitta filtrdan oʻtadi, chunki umumiy endpoint tasvir, video, audio, embedding va chat uchun moʻljallanmagan boshqa modellarni ham qaytaradi. Shundan soʻng `qwen-cloud` oʻz provayder reyestrida eʼlon qilingan, qoʻllab-quvvatlanadigan ruxsat etilgan roʻyxatni qoʻllaydi. Alibaba Model Studio va Qwen Cloud hozirda bir xil bajarish xostlaridan foydalansa-da, alohida saralangan kataloglarni saqlaydi.
3. `qwen-cloud-token-plan`ni joriy Token Plan matn modellari uchun ruxsat etilgan roʻyxat bilan roʻyxatdan oʻtkazing.
4. Ulanishni qoʻshish/tahrirlash dialoglariga tiplashtirilgan hudud tanlagichini qoʻshing.
5. Takroriy `alibaba-cn` kartasini yashiring va uning mavjud ulanishlarini `alibaba` provayderi sahifasiga kiriting.
6. Kengaytirilgan va ish maydoniga xos joylashtirishlar uchun maxsus endpoint almashtirishlarini saqlab qoling.

Token Plan media modellari chat katalogidan tashqarida qoladi, chunki ular maxsus endpointlardan foydalanadi.
`wan2.7-image` va `wan2.7-image-pro` `open-sse/config/imageRegistry.ts`da roʻyxatdan oʻtkazilgan;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` va `happyhorse-1.1-r2v` esa
`open-sse/config/videoRegistry.ts`da roʻyxatdan oʻtkazilgan. Ikkala reyestr ham `qwen-cloud-token-plan` ulanish
identifikatori va uning hududga xos hisob maʼlumotlaridan qayta foydalanadi.

Oddiy Qwen Cloud `qwen-cloud`
identifikatori ostida foydalanishga qarab toʻlanadigan alohida tasvir va video kataloglariga ega. Uning tasvir modellari: `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` va `z-image-turbo`. Uning video
modellari: `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` va
`wan2.7-videoedit`. Bu modellar faqat oddiy `qwen-cloud` ulanishi va hududiy
DashScope media endpointidan qayta foydalanadi. Token Plan va foydalanishga qarab toʻlanadigan reyestrlar bir-birining
model roʻyxatlarini meros qilib olmaydi yoki birlashtirmaydi.

`bailian-coding-plan` identifikatori ham oʻz media uchun ruxsat etilgan roʻyxatlariga ega:
tasvir yaratish uchun `wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` va `qwen-image-2.0-pro`,
video yaratish uchun esa
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` va `happyhorse-1.1-r2v`.
U faqat Bailian Coding Plan ulanishi va hududiy Coding Plan endpointidan foydalanadi.
Uning tasvir va video reyestrlari Qwen Cloud provayderlarining hech biridan meros olmaydi yoki ular bilan birlashtirilmaydi.

Oddiy `alibaba` identifikatori alohida tasvir va video uchun ruxsat etilgan roʻyxatlarga ega. Uning tasvir modellari:
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` va `wan2.6-t2i`. Uning qoʻshilgan video modellari: `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` va `wan2.7-videoedit`. Bu modellar faqat Alibaba Model Studio
ulanishi va uning tanlangan hududiy media endpointidan foydalanadi; ular hech qanday Coding Plan yoki Qwen
Cloud reyestriga qoʻshilmaydi.

Qwen Cloud Token Plan chat katalogi Individual rejasining aynan mos keladigan satrlardan iborat matn uchun ruxsat etilgan roʻyxatiga amal qiladi:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` va
`deepseek-v4-pro`. Wan va HappyHorse yozuvlari tasvir/video yaratish uchun alohida APIlarga tegishli.

Alibaba Token Plan xuddi shu oltita joriy matn yaratish modeli IDsini oʻzining
Anthropic bilan mos endpointi orqali taqdim etadi. Uning Singapore varianti mavjud `global-sg` hudud kalitini saqlaydi;
faqat foydalanuvchiga koʻrsatiladigan yorliq hududni Global deb ataydigan provayder oilalaridan farq qiladi.

Oddiy Qwen Cloud chat katalogi ataylab real vaqtdagi toʻliq matn javobidan torroq qilingan. Uning
qoʻllab-quvvatlanadigan ruxsat etilgan roʻyxati `open-sse/config/providers/registry/qwen-cloud/index.ts`da joylashgan; real vaqtdagi
aniqlash faqat yuqori oqim javobida ham, ushbu reyestr roʻyxatida ham mavjud boʻlgan IDlarni qaytaradi.

Alibaba Model Studio `open-sse/config/providers/registry/alibaba/index.ts`dagi mustaqil ravishda qoʻllab-quvvatlanadigan
ruxsat etilgan roʻyxati bilan ayni real vaqt kesishmasi qoidasiga amal qiladi. `alibaba-cn` moslik
provayderi aniqlashni Beijing endpointi orqali bajarib, shu katalogdan qayta foydalanadi.
