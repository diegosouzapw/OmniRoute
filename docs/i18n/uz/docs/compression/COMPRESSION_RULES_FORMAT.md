Siqish qoidalari ish vaqtida yuklanadigan JSON fayllardir. Ular ataylab faqat maʼlumotlardan iborat qilingan, shunda yangi til paketlari va RTK buyruq filtrlari dvigatel kodini oʻzgartirmasdan ko‘rib chiqilishi mumkin.

> **Kanonik sxema (asosiy manba):** [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) (JSON Schema draft 2020-12).
> Quyidagi misollar faqat namuna sifatida keltirilgan — shubha tugʻilganda paketingizni `_schema.json` asosida tekshiring.

## Caveman qoida paketlari

Caveman qoida paketlari quyidagi joyda saqlanadi:

```txt
open-sse/services/compression/rules/<language>/<pack>.json
```

Har bir paket himoyalangan hududlar ajratib olingandan keyin oddiy nasriy matnga qoʻllanadigan almashtirishlarni oʻz ichiga oladi.

```json
{
  "language": "en",
  "category": "filler",
  "rules": [
    {
      "name": "question_to_directive",
      "pattern": "\\b(?:Can you explain why|Could you show me how)\\b\\s*",
      "replacement": "Explain why ",
      "replacementMap": {
        "can you explain why": "Explain why ",
        "could you show me how": "Show how "
      },
      "flags": "gi",
      "context": "all",
      "category": "context",
      "minIntensity": "lite",
      "description": "Convert verbose questions into direct requests."
    }
  ]
}
```

### Caveman maydonlari

| Maydon                   | Majburiy | Tavsif                                                               |
| ------------------------ | -------- | -------------------------------------------------------------------- |
| `language`               | ha       | `en`, `pt-BR`, `es` kabi BCP-47 uslubidagi til kaliti                |
| `category`               | ha       | Paket toifasi fayl nomi/toifasi, masalan `filler` yoki `dedup`       |
| `rules`                  | ha       | Regex almashtirish qoidalari massivi                                 |
| `rules[].name`           | ha       | Barqaror qoida nomi                                                  |
| `rules[].pattern`        | ha       | JavaScript regex manbasi                                             |
| `rules[].flags`          | yoʻq     | JavaScript regex bayroqlari; standart qiymat `gi`                    |
| `rules[].replacement`    | yoʻq     | Almashtirish satri yoki `replacementMap` mos kelmagandagi zaxira     |
| `rules[].replacementMap` | yoʻq     | Normallashtirilgan mos matn bilan kalitlangan maxsus almashtirishlar |
| `rules[].context`        | yoʻq     | `all`, `user`, `assistant` yoki `system`; standart qiymat `all`      |
| `rules[].category`       | yoʻq     | `filler`, `context`, `structural`, `dedup`, `terse` yoki `ultra`     |
| `rules[].minIntensity`   | yoʻq     | `lite`, `full` yoki `ultra`; standart qiymat `lite`                  |
| `rules[].description`    | yoʻq     | Qoida haqida inson tushunadigan qisqacha tavsif                      |

Katta-kichik harflarga sezgir moslashtirish muhim boʻlganda `flags` dan foydalaning, masalan, kichik harf bilan yozilgan nasriy matn oldidan artiklni olib tashlashda `the OpenAI API` ni olib tashlamaslik uchun. Bitta regex turli natijalarni talab qiladigan bir nechta muqobilga ega boʻlsa, `replacementMap` dan foydalaning; bu JSON qoida paketlarini faqat maʼlumotlardan iborat holda saqlaydi va shu bilan birga kengroq imkoniyatlarga ega ichki TypeScript almashtirish funksiyalarining xatti-harakatini saqlab qoladi.

## RTK filtr paketlari

RTK filtrlari quyidagi manzilda joylashadi:

```txt
open-sse/services/compression/engines/rtk/filters/<filter>.json
```

Har bir filtr buyruq chiqishlari oilasini qanday aniqlash va siqishni tavsiflaydi.

```json
{
  "id": "test-vitest",
  "label": "Vitest output",
  "category": "test",
  "priority": 92,
  "match": {
    "outputTypes": ["test-vitest"],
    "commands": ["vitest", "npm test", "npm run test"],
    "patterns": ["\\bFAIL\\b", "\\bPASS\\b", "\\bTest Files\\b"]
  },
  "rules": {
    "stripAnsi": true,
    "replace": [{ "pattern": "\\s+\\[[0-9]+ms\\]", "replacement": "" }],
    "matchOutput": [
      {
        "pattern": "All tests passed",
        "message": "vitest: ok",
        "unless": "FAIL|Error:"
      }
    ],
    "includePatterns": ["FAIL", "Error:", "Test Files", "Tests"],
    "dropPatterns": ["^\\s*$", "Duration\\s+\\d+"],
    "collapsePatterns": ["^\\s+at "],
    "deduplicate": true,
    "truncateLineAt": 240,
    "maxLines": 160,
    "headLines": 24,
    "tailLines": 40,
    "onEmpty": "vitest: ok",
    "filterStderr": false
  },
  "preserve": {
    "errorPatterns": ["FAIL", "Error:", "AssertionError"],
    "summaryPatterns": ["Test Files", "Tests", "Snapshots"]
  },
  "tests": [
    {
      "name": "keeps failing tests",
      "command": "vitest",
      "input": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed",
      "expected": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed"
    }
  ]
}
```

### RTK maydonlari

| Maydon                     | Majburiy | Tavsif                                                                                      |
| -------------------------- | -------- | ------------------------------------------------------------------------------------------- |
| `id`                       | ha       | Barqaror filtr identifikatori                                                               |
| `label`                    | ha       | Boshqaruv panelida o‘qiladigan nom                                                          |
| `category`                 | ha       | Filtr oilasi: git, test, build, shell, docker, package, infra, cloud, generic               |
| `priority`                 | yo‘q     | Bir nechta filtr mos kelganda ustuvorligi yuqoriroq bo‘lgani tanlanadi                      |
| `match.outputTypes`        | yo‘q     | Ushbu filtrni tanlaydigan detektor chiqish identifikatorlari                                |
| `match.commands`           | yo‘q     | Ushbu filtrni tanlaydigan buyruq tokenlari                                                  |
| `match.patterns`           | yo‘q     | Chiqish matnidan ushbu filtrni tanlaydigan regex andozalari                                 |
| `rules.stripAnsi`          | yo‘q     | Regex bosqichlaridan oldin ANSI escape ketma-ketliklarini olib tashlash                     |
| `rules.replace`            | yo‘q     | Satrma-satr qo‘llanadigan tartiblangan regex almashtirishlari                               |
| `rules.matchOutput`        | yo‘q     | Ixtiyoriy `unless` shartiga ega, chiqishni qisqa tutashtiruvchi qoidalar                    |
| `rules.includePatterns`    | yo‘q     | Saqlab qolish afzal bo‘lgan satrlar                                                         |
| `rules.dropPatterns`       | yo‘q     | Shovqin sifatida olib tashlanadigan satrlar                                                 |
| `rules.collapsePatterns`   | yo‘q     | Ixchamlashtirilishi mumkin bo‘lgan takroriy mos satrlar                                     |
| `rules.deduplicate`        | yo‘q     | Takroriy normallashtirilgan satrlarni ixchamlashtirish                                      |
| `rules.truncateLineAt`     | yo‘q     | Har bir satr uchun Unicode-xavfsiz belgilar chegarasi                                       |
| `rules.maxLines`           | yo‘q     | Oxirgi satrlarni saqlashdan oldin qoldiriladigan satrlarning maksimal soni                  |
| `rules.headLines`          | yo‘q     | Qisqartirish paytida saqlab qolinadigan bosh satrlar                                        |
| `rules.tailLines`          | yo‘q     | So‘nggi kontekst uchun saqlab qolinadigan oxirgi satrlar                                    |
| `rules.onEmpty`            | yo‘q     | Filtrlash barcha kontentni olib tashlaganda ishlatiladigan zaxira xabar                     |
| `rules.filterStderr`       | yo‘q     | Keyingi filtrlash bosqichlaridan oldin keng tarqalgan stderr prefikslarini normallashtirish |
| `preserve.errorPatterns`   | yo‘q     | Qisqartirishdan keyin ham saqlanishi kerak bo‘lgan xato satrlari                            |
| `preserve.summaryPatterns` | yo‘q     | Qisqartirishdan keyin ham saqlanishi kerak bo‘lgan xulosa satrlari                          |
| `tests[]`                  | yo‘q     | RTK verify nazoratida ishlatiladigan ichki tekshiruv namunalari                             |

RTK deklarativ bosqichlarni quyidagi tartibda qo‘llaydi: `stripAnsi`, `filterStderr`, `replace`,
`matchOutput`, `dropPatterns`/`includePatterns`, `truncateLineAt`, `headLines`/`tailLines`,
`maxLines` va `onEmpty`.

Maxsus filtrlarni quyidagi manbalardan yuklash mumkin:

1. Loyiha `.rtk/filters.json` fayllari — faqat mos `.rtk/trust.json` xeshi mavjud bo‘lgandan yoki
   `trustProjectFilters` yoqilgandan keyin.
2. Global `DATA_DIR/rtk/filters.json`.
3. Ichki filtrlar.

Loyiha/global maxsus fayllar bitta filtr obyekti yoki filtr obyektlari massivini o‘z ichiga olishi mumkin. Yaroqsiz
maxsus filtrlar diagnostika xabarlari bilan o‘tkazib yuboriladi; yaroqsiz ichki filtrlar validatsiyaning muvaffaqiyatsiz tugashiga olib keladi.

Loyiha ishonch fayli:

```json
{
  "filtersSha256": "0123456789abcdef..."
}
```

`OMNIROUTE_RTK_TRUST_PROJECT_FILTERS=1` muhit o‘zgaruvchisi orqali bekor qilish loyiha filtrlariga xeshsiz
ishonadi va faqat nazorat qilinadigan mahalliy ishlab chiqish muhiti bilan cheklanishi kerak.

## Xavfsizlik qoidalari

- Qoidalarni idempotent saqlang: bir xil filtrni ikki marta ishga tushirish chiqishni buzmasligi kerak.
- Imkon qadar xatolarning aniq matnini, fayl yoʻllarini, satr raqamlarini va buyruqlar xulosalarini saqlab qoling.
- Kod bloklari, JSON foydali yuklamalari, URL manzillari yoki sirlarni oʻzgartiradigan qoidalardan saqlaning.
- Detektor/filtr testlarida yangi buyruqlar oilalari uchun modul testlari qamrovini qoʻshing.
- Har bir ichki filtrga va umumiy maxsus filtrlarga `tests[]` namunalarini qoʻshing.

## Tekshirish

Qoidalar toʻplamlari foydalanishdan oldin tekshiriladi. Ichki Caveman toʻplamlari va ichki RTK filtrlari tezda xato bilan toʻxtaydi,
shunda buzilgan reliz resurslari yetkazib berishdan oldin aniqlanadi. Maxsus RTK filtrlari sintaktik tahlil yoki ishonchlilik tekshiruvi muvaffaqiyatsiz tugaganda
diagnostika bilan oʻtkazib yuboriladi.

Yoʻnaltirilgan tekshirish:

```bash
node --import tsx/esm --test tests/unit/compression/rule-loader.test.ts tests/unit/compression/language-packs.test.ts
node --import tsx/esm --test tests/unit/compression/rtk-verify.test.ts tests/unit/compression/rtk-dsl-pipeline.test.ts
```
