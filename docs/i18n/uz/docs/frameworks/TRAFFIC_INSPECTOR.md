Traffic Inspector — OmniRoute’ning o‘rnatilgan HTTPS trafik tuzatuvchisi bo‘lib, Charles Proxy / mitmweb / HTTP Toolkit’ga o‘xshash, ammo **LLM’dan xabardor** va **agentdan xabardor** vositadir. U `/dashboard/tools/traffic-inspector` manzilida joylashgan va bir vaqtning o‘zida 5 tagacha trafikni yozib olish manbasidan jonli trafikni qabul qiladi.

**Boshqaruv panelidagi joylashuvi:** `/dashboard/tools/traffic-inspector`
**Yon panel guruhi:** Vositalar (AgentBridge’dan keyin)
**Shuningdek qarang:** [`AGENTBRIDGE.md`](./AGENTBRIDGE.md) — AgentBridge — 1-yozib olish rejimi.

### Arxitektura bir xatboshida

`TrafficBuffer` (`src/mitm/inspector/buffer.ts`) — umumiy xotira ichidagi halqali bufer (standart bo‘yicha 1000 ta yozuv, `INSPECTOR_BUFFER_SIZE` orqali sozlanadi). Barcha yozib olish manbalari unga `push()` orqali ma’lumot yozadi. Bufer har bir yozuvni `kindDetector.ts` yordamida tasniflaydi (uning LLM so‘rovi ekanini aniqlaydi), `contextKey` qiymatini (tizim promptining SHA-256 raqamli izini) hisoblaydi va `globalTrafficBuffer.subscribe()` orqali barcha WebSocket obunachilariga uzatadi. Boshqaruv paneli `GET /api/tools/traffic-inspector/ws` orqali ulanadi va ulanish vaqtida oniy holat nusxasini, so‘ngra `new`/`update`/`clear` hodisalarini qabul qiladi.

## §2 Trafikni yozib olish rejimlari

Traffic Inspector **bir vaqtning o‘zida 5 ta trafikni yozib olish manbasini** qo‘llab-quvvatlaydi. Ularning har birini mustaqil ravishda yoqish yoki o‘chirish mumkin. Har bir `InterceptedRequest` (`src/mitm/inspector/types.ts`) obyektidagi `source` maydoni `"agent-bridge"`, `"custom-host"`, `"http-proxy"`, `"system-proxy"` yoki `"tproxy"` qiymatlaridan biriga ega bo‘ladi.

### 1-rejim — AgentBridge (standart, doimo yoqilgan)

**Manba:** AgentBridge ishlov beruvchilari (`src/mitm/handlers/base.ts`)
**Mexanizm:** `MitmHandlerBase` ichidagi har bir `intercept()` chaqiruvi yo‘naltirishdan oldin `hookBufferStart()` funksiyasini, yakunlanganda esa `hookBufferUpdate()` funksiyasini chaqiradi. Hech qanday qo‘shimcha sozlama kerak emas — AgentBridge ishga tushishi bilan ishlaydi.
**Qamrov:** AgentBridge’da sozlangan 9 ta IDE agenti
**Eslatma:** `InterceptedRequest` ichidagi `source` maydoni = `"agent-bridge"`

### 2-rejim — Maxsus hostlar (DNS orqali qayta yo‘naltirish)

**Manba:** Foydalanuvchi belgilagan hostlar ro‘yxati (`inspector_custom_hosts` jadvali)
**Mexanizm:** UI orqali host qo‘shilganda `/etc/hosts` fayliga `127.0.0.1 <host>` yozuvi qo‘shiladi (sudo talab qilinadi). Mavjud AgentBridge MITM serveri (443-port) yangi host uchun SNI sertifikatini dinamik ravishda yaratadi.
**Qamrov:** Qo‘shilgan hostdan foydalanadigan istalgan ilova — ilova konfiguratsiyasini o‘zgartirish talab qilinmaydi
**Eslatma:** `source` = `"custom-host"`

Foydalanish misollari:

- Python skriptlaridan `api.openai.com` trafikini kuzatish
- `my-internal-llm.company.com` bilan bog‘liq muammolarni tuzatish
- Bir xil tarmoqdagi mobil qurilmalar trafikini yozib olish (ARP spoofing orqali — ilg‘or usul)

### 3-rejim — HTTP_PROXY tinglovchisi (8080-port)

**Manba:** `HTTP_PROXY`/`HTTPS_PROXY` muhit o‘zgaruvchilaridan foydalanadigan ilovalar
**Mexanizm:** Standart ochiq HTTP/HTTPS proksi sifatida ishlaydigan 8080-portdagi ikkilamchi tinglovchi (`src/mitm/inspector/httpProxyServer.ts`). `CONNECT` tunnellarini (HTTPS) va to‘g‘ridan-to‘g‘ri HTTP so‘rovlarini qabul qiladi.
**Qamrov:** `HTTP_PROXY` muhit o‘zgaruvchisiga rioya qiladigan istalgan ilova — DNS o‘zgarishi ham, sudo ham talab qilinmaydi
**Eslatma:** `source` = `"http-proxy"`

```bash
# Bitta buyruq uchun trafikni tezkor yozib olish:
HTTPS_PROXY=http://127.0.0.1:8080 curl https://api.openai.com/v1/models

# Shell seansi davomida doimiy yozib olish:
export HTTP_PROXY=http://127.0.0.1:8080
export HTTPS_PROXY=http://127.0.0.1:8080
```

**TLS cheklovi:** HTTPS `CONNECT` tunnellari faqat metama’lumotlar (host, port, vaqt ko‘rsatkichlari) sifatida yozib olinadi — TLS tanasi standart holatda shifrdan chiqarilmaydi. Tananing to‘liq tarkibini tekshirish uchun “Proksi rejimida HTTPS shifrini yechish” tugmasini yoqing (ixtiyoriy, AgentBridge sertifikati ishonchli deb tan olingan bo‘lishi kerak).

**Port to‘qnashuvi:** Agar 8080-port band bo‘lsa, AgentBridge tuzilmaviy xato bilan 409 javobini qaytaradi. Portni `INSPECTOR_HTTP_PROXY_PORT` muhit o‘zgaruvchisi orqali o‘zgartiring.

### 4-rejim — Tizim miqyosidagi proksi (ilg‘or, ixtiyoriy)

**Manba:** Operatsion tizim darajasidagi proksi sozlamalari (qurilmadagi barcha ilovalarga tatbiq etiladi)
**Mexanizm:** Barcha HTTP/HTTPS trafikni HTTP_PROXY tinglovchisi orqali yo‘naltirish uchun operatsion tizim API’laridan foydalanadi:

- **macOS:** `networksetup -setwebproxy / -setsecurewebproxy`
- **Linux:** `gsettings set org.gnome.system.proxy` + `/etc/environment`
- **Windows:** `netsh winhttp set proxy 127.0.0.1:8080`
  **Qamrov:** Qurilmadagi tizim proksi sozlamalariga rioya qiladigan har bir ilova
  **Eslatma:** `source` = `"system-proxy"`

**Xavfsizlik mexanizmlari:**

- Avtomatik o‘chirish taymeri (standart qiymat 30 daqiqa, `INSPECTOR_SYSTEM_PROXY_GUARD_MINUTES` orqali sozlanadi)
- Tizim proksisining oldingi holati ma’lumotlar bazasida saqlanadi va bekor qilishda qayta tiklanadi
- Agar foydalanuvchi funksiya faol paytda boshqa sahifaga o‘tsa, boshqaruv paneli “Tizim proksisi qayta tiklanmoqda” so‘rovini ko‘rsatadi
- UI’da `⚠ Ilg‘or` nishoni va aniq tasdiqlash katakchasi ko‘rsatiladi

### 5-rejim — TPROXY orqali shaffof shifrni yechish (Linux, root, ixtiyoriy)

**Manba:** Yadro TPROXY mexanizmi + siyosat asosidagi marshrutlash (`src/mitm/tproxy/`)
**Mexanizm:** `mangle OUTPUT` ichida maqsadli portga (standart `443`) yo‘naltirilgan yangi mahalliy chiquvchi TCP ulanishlarini belgilaydi, `ip rule` belgilangan paketlarni mahalliy yetkazishga qayta yo‘naltiradi, `mangle PREROUTING` ichidagi `TPROXY` nishoni esa ularni shaffof (**IP_TRANSPARENT**) tinglovchiga (standart port `8443`) uzatadi. Tinglovchi dinamik CA tomonidan **talab asosida har bir SNI host nomi uchun** chiqarilgan yakuniy sertifikat yordamida TLS ulanishini yakunlaydi, shifrdan chiqarilgan almashinuvni yozib oladi va so‘rovni qayta shifrlab, asl manzilga yo‘naltiradi.
**Qamrov:** Maqsadli portdagi **istalgan** manzil hostlari — `/etc/hosts` orqali soxtalashtirish, `HTTP_PROXY` muhiti yoki tizim miqyosidagi proksini o‘zgartirish talab qilinmaydi. Trafiki tutib qolinayotgan jarayon konfiguratsiyasini o‘zgartirish shart emas, ammo u dinamik CA’ga ishonishi kerak.
**Eslatma:** `source` = `"tproxy"`

**Talablar:** Faqat Linux (**IP_TRANSPARENT** faqat Linux’da mavjud), **CAP_NET_ADMIN** imkoniyati (root) va C vositalar to‘plami yordamida qurilishi kerak bo‘lgan mahalliy N-API qo‘shimchasi (`npm run build:native:tproxy`). Ular mavjud bo‘lmaganda boshqaruv panelidagi tugma o‘chirib qo‘yiladi va “TPROXY shifrini yechish uchun Linux + root + mahalliy qo‘shimcha talab qilinadi” ko‘rsatmasi namoyish etiladi. Fayervol qoidalari tranzaksion tarzda qo‘llanadi va bekor qilinadi (nosozlik hech qachon `mangle` qoidasini qoldirmaydi) hamda qayta yuklashda tozalanadi. SO_MARK asosidagi sikldan himoya mexanizmi proksining o‘zi qayta shifrlab yo‘naltirgan trafikning yana tutib olinishiga yo‘l qo‘ymaydi.

Bu o‘zining alohida operator qo‘llanmasiga ega bo‘lgan yirik quyi tizimdir — fayervolning to‘liq retsepti, har bir SNI uchun dinamik CA + ishonchli sertifikatlar ombori o‘rnatuvchisi, faqat mahalliy marshrut, sikldan himoya tafsilotlari va konfiguratsiya sxemasi uchun `docs/security/MITM-TPROXY-DECRYPT.md` fayliga qarang (git ichida; `/docs` tarkibiga kompilyatsiya qilinmaydi). Tugma `GET / POST / DELETE /api/tools/agent-bridge/tproxy` orqali boshqariladi (eslatma: marshrut Traffic Inspector prefiksi ostida emas, AgentBridge prefiksi ostida joylashgan).

- **Virtuallashtirilgan** (`useVirtualList` + `ResizeObserver`): 1000 ta elementni qotib qolmasdan boshqaradi

- **Holat rang bilan kodlanadi**: yashil (2xx), sariq (3xx), qizil (4xx/5xx), kulrang (bajarilmoqda)
- **Agent emojisi**: 🔵 Antigravity, 🟢 Copilot, 🟠 Kiro, 🟣 Codex, 🔷 Cursor, 🟤 Zed, 🟡 Claude Code, ⚫ Open Code, 🌐 maxsus host
- **Kontekst rangli chizigʻi**: `contextKey` (tizim promptining SHA-256 xeshi) asosida ranglangan 1px chap chegara — oʻzaro bogʻliq suhbatlarni vizual tarzda guruhlaydi
- **Kechiktirib yuklanadigan tana**: tafsilotlar varaqlarida faqat tanlangan soʻrovning tanasi moddiylashtiriladi (1000 × 1MB hajmdagi tanalarni render qilishning oldini oladi)

| Host filtri      | `host` maydonida quyi satr mosligini tekshiradi                                           |
| Agent filtri     | Ochiladigan roʻyxat: Barchasi / har bir agent boʻyicha                                    |
| Holat filtri     | Barchasi / 2xx / 3xx / 4xx / 5xx / xato                                                   |
| Manba filtri     | Barchasi / agent-bridge / custom-host / http-proxy / system-proxy / tproxy                |
| **Jonli** filtr  | Faqat bajarilayotgan (ochiq) soʻrovlarni koʻrsatadi — `liveOnly` tugmasi (§4.6 ga qarang) |

### 3.5 Oʻlchami oʻzgartiriladigan panellar

- Roʻyxat va tafsilotlar paneli sudrash tutqichi bilan ajratilgan
- Roʻyxat kengligi: kamida 280px, koʻpi bilan 720px, `localStorage`da (`inspector.listWidth`) saqlanadi
- 48px relsgacha yigʻish mumkin (faqat ikonka); kengaytirish uchun relsdagi qatorni bosing

## §4 LLM-dan xabardor funksiyalar

### 4.1 Tur aniqlagichi (`src/mitm/inspector/kindDetector.ts`)

Har bir soʻrovni 4 ta signal yordamida `"llm"`, `"app"` yoki `"unknown"` sifatida tasniflaydi:

1. **Xost reyestri** — ~18 ta maʼlum LLM API xost nomi (OpenAI, Anthropic, Gemini, Groq, Mistral, Together, Fireworks, Cohere, Perplexity, Hugging Face, OpenRouter, xAI, Moonshot va boshqalar)
2. **Yoʻl andozalari** — `/v1/chat/completions`, `/v1/messages`, `/generateContent`, `/v1/responses` va boshqalar
3. **Tana tuzilishi** — `messages[]` (OpenAI/Claude), `contents[]` (Gemini), `prompt`, `input` maydonlarini aniqlaydi
4. **User-agent ishoralari** — UA satrida `codex`, `claude`, `gemini`, `antigravity`, `kiro`, `copilot`, `cursor`

Mode 2 orqali qoʻshilgan maxsus xostlar oʻzlarining `kind` qiymatini forma kiritmasidan oladi (standart qiymat — `"custom"`).

### 4.2 SSE birlashtirgichi (`src/mitm/inspector/sseMerger.ts`)

**Mustaqil clean-room implementatsiyasi.** Hodisalarni tahlil qilish
[WHATWG serverdan yuboriladigan hodisalar algoritmi](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream)ga amal qiladi,
qayta tiklash esa ommaviy [OpenAI](https://platform.openai.com/docs/api-reference/chat/create),
[Anthropic](https://platform.claude.com/docs/en/build-with-claude/streaming) va
[Gemini](https://ai.google.dev/api/generate-content#method:-models.streamgeneratecontent)
oqim sxemalariga amal qiladi.

Xom SSE delta hodisalaridan yordamchining yakuniy xabarini qayta tiklaydi:

- **Anthropic**: `content_block_delta`ni indeks boʻyicha toʻplaydi; `text_delta`, `input_json_delta` (vosita chaqiruvlari), `thinking_delta`ni qayta ishlaydi
- **OpenAI**: Chat Completions tanlovlari/vosita chaqiruvlari va Responses API chiqish elementlarini
  indeks boʻyicha toʻplaydi
- **Gemini**: `candidates[i].content.parts`ni toʻplaydi
- **Unknown**: xom hodisalarni oʻz holicha qaytaradi

Response ichki oynasida quyidagi almashtirgich koʻrsatiladi: **"Xom hodisalar ↔ Birlashtirilgan"**.

### 4.3 Suhbat normallashtirgichi (`src/mitm/inspector/conversationNormalizer.ts`)

**Mustaqil clean-room implementatsiyasi.** Normallashtirish mahalliy black-box
shartnomalari hamda ommaviy OpenAI, Anthropic va Gemini xabar sxemalari orqali belgilanadi; hech qanday tashqi
implementatsiya manba kodidan foydalanilmaydi.

OpenAI, Anthropic va Gemini xabar formatlarini renderlashdan oldin yagona `NormalizedConversation` formatiga oʻzgartiradi:

```ts
interface NormalizedConversation {
  request: NormalizedTurn[]; // soʻrov tanasidagi messages / contents / prompt
  response: NormalizedTurn[]; // yordamchi javobi (sseMerger orqali birlashtirilgan)
  contextKey: string | null; // tizim promptining SHA-256 raqamli izi
}
```

Blok turlari: `text`, `tool_use`, `tool_result`. Conversation ichki oynasi provayderdan qatʼi nazar ushbu tuzilmadan foydalanadi.

### 4.4 Kontekst kalitini ranglash (`src/mitm/inspector/contextKey.ts`)

- Tizim promptining `SHA-256` qiymatini hisoblaydi (birinchi `role:system` xabari, `system` maydoni yoki Gemini `systemInstruction`)
- 12 belgili hex prefiksini qaytaradi (`"a3f9c2..."`)
- Frontend chap chegara paneli uchun kalitni deterministik HSL rangiga moslaydi
- **"Bir xil kontekst" filtri**: `ctx #a3f` chipi bosilganda faqat raqamli izi bir xil boʻlgan soʻrovlarni koʻrsatish uchun filtr qoʻshiladi

Bu bir xil agent seansida ishlayotgan turli «personalar» yoki vazifalarni vizual tarzda oson ajratish imkonini beradi.

### 4.5 LLM metamaʼlumotlarini ajratib olish

LLM soʻrovlari uchun LLM Details ichki oynasi quyidagilarni ajratib oladi:

```ts
interface LlmMetadata {
  provider: string | null; // "openai" | "anthropic" | "gemini" | ...
  apiKind: string | null; // "chat.completions" | "messages" | "embeddings" | ...
  model: string | null; // soʻrov tanasi yoki javobdan
  messages: number; // almashinuvlar soni
  tokensIn: number | null; // usage.prompt_tokens / usage.input_tokens
  tokensOut: number | null; // usage.completion_tokens / usage.output_tokens
  streamed: boolean; // SSE javobi boʻlsa true
  mappedTo: string | null; // x-omniroute-mapped sarlavhasi
  costEstimateUsd: number | null; // OmniRoute narxlari asosidagi taxminiy xarajat
}
```

### 4.6 Jarayondagi jonli soʻrovlar filtri

Soʻrovning `status` maydoni `number | "in-flight" | "error"` turiga ega — soʻrov
boshlanishi bilan yozuv `"in-flight"` sifatida qoʻshiladi va javob (yoki xato)
kelganida **oʻsha joyning oʻzida yangilanadi**. Asboblar panelidagi **"Jonli"** almashtirgichi
(`liveOnly`, i18n kaliti `trafficInspector.liveOnly`) roʻyxatni
`status === "in-flight"` boʻlgan yozuvlar bilan cheklaydi va ochiq ulanishlarni real vaqtda kuzatish imkonini beradi.

Filtr `src/lib/inspector/matchesTrafficFilter.ts` ichidagi sof, mijoz tomonidagi predikatdir:

```ts
if (f.liveOnly && req.status !== "in-flight") return false;
```

Almashtirgich holati `useTrafficFilters`da (inspektor boshqaruv paneli huklari) saqlanadi va
boshqa filtrlar (profil, xost, agent, manba, holat, kontekst) bilan birlashtiriladi.

### 4.7 Jarayonga tegishlilikni aniqlash (Linux)

Linux tizimida har bir ushlangan soʻrovni **uni yaratgan mahalliy
jarayonga** bogʻlash mumkin. `InterceptedRequest`ga ikkita ixtiyoriy maydon qoʻshiladi:

```ts
pid?: number;          // soʻrovni yaratgan jarayon identifikatori (faqat Linux)
processName?: string;  // soʻrovni yaratgan jarayon nomi (faqat Linux)
```

`src/mitm/inspector/processAttribution.ts` ulanishning _mijoz_
vaqtinchalik portini PID + nomga quyidagicha moslaydi:

1. Portga tegishli socket inode qiymatini topish uchun `/proc/net/tcp` va `/proc/net/tcp6`ni
   oʻqiydi (`parseProcNetTcpForInode`, fixture bilan sof testlanadigan parser).
2. `socket:[<inode>]`ga ishora qiluvchi ramziy havolani topish uchun `/proc/<pid>/fd/`ni skanerlaydi.
3. Jarayon nomini `/proc/<pid>/comm`dan oʻqiydi.

1 soniyalik TTL keshi yuklama ostida procfs skanerlash xarajatini cheklaydi. Tegishlilikni aniqlash
**imkon qadar** bajariladi — har qanday xato `null` bilan yakunlanadi va trafikni ushlashni hech qachon bloklamaydi.
macOS/Windows tizimlarida funksiya `null` qaytaradi (stub; `lsof`/`GetExtendedTcpTable`
qoʻllab-quvvatlashi keyinchalik qoʻshiladi).

## §5 Seanslar

### 5.1 Seansni yozib olish

1. Asboblar panelidagi **"● Seansni yozib olish"** tugmasini bosing → nom kiriting (ixtiyoriy)

## §6 Xavfsizlik

Traffic Inspector **barcha ushlangan HTTPS trafikni**, jumladan avtorizatsiya sarlavhalari va so‘rov tanalarini ko‘rsatadi. Quyidagi boshqaruv vositalari mavjud:

| Boshqaruv vositasi                  | Tafsilotlar                                                                                                                                                                                                           |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LOCAL_ONLY**                      | Barcha marshrutlar va WebSocket yakuniy nuqtasiga faqat loopback orqali kirish mumkin (autentifikatsiyadan oldin `routeGuard.ts` ichida majburiy ta’minlanadi)                                                        |
| **Sirlarni niqoblash**              | Chiziqli `maskSecret()` skaneri `TrafficBuffer.push()` dan oldin RFC 6750 Bearer hisob ma’lumotlari, provayder prefiksli kalitlar va uzun noaniq tokenlarni yashiradi                                                 |
| **Tana hajmi cheklovi**             | `INSPECTOR_MAX_BODY_KB` dan katta tanalar (standart qiymat 1024 KB) `"(unumdorlik uchun qisqartirildi)"` bildirishnomasi bilan qisqartiriladi                                                                         |
| **Sarlavhalarni xavfsizlashtirish** | Nomlar kichik harflarga o‘tkaziladi; freymlash/hop-by-hop va proksi autentifikatsiyasi sarlavhalari olib tashlanadi; cookie fayllari to‘liq yashiriladi; hisob ma’lumotlari qiymatlari `maskSecret()` ga topshiriladi |
| **CSP**                             | Kiritilgan javob tanalari orqali XSS hujumlarini oldini olish uchun Traffic Inspector sahifalarida qat’iy Content Security Policy qo‘llanadi                                                                          |
| **Standart holatda saqlanmaydi**    | `TrafficBuffer` xotirada saqlanadi va server qayta ishga tushirilganda yo‘qoladi. Seanslar faqat aniq ravishda yozib olinganda doimiy saqlanadi                                                                       |

### Qo‘llaniladigan qat’iy qoidalar

| Qoida                             | Qo‘llanishi                                                                                  |
| --------------------------------- | -------------------------------------------------------------------------------------------- |
| **#12** `sanitizeErrorMessage`    | Traffic Inspector marshrutlaridan qaytarilgan barcha HTTP xato javoblari xavfsizlashtiriladi |
| **#15 + #17** `isLocalOnlyPath()` | `/api/tools/traffic-inspector/` — LOCAL_ONLY + SPAWN_CAPABLE (tizim proksisi buyruqlari)     |

### Ma’lum cheklovlar

- **Tizim miqyosidagi proksi rejimi** kompyuterdagi barcha ilovalarga, jumladan VPN mijozlari va SSO ga ta’sir qiladi. Har doim avtomatik o‘chirish taymeri bilan foydalaning. Umumiy foydalaniladigan kompyuterlarda ishlatmang.
- **CONNECT tunnel HTTPS**: TLS ushlash yoqilmagan bo‘lsa, 3-rejim (HTTP_PROXY) HTTPS manzillari uchun faqat tunnel metama’lumotlarini ushlaydi. Bu ataylab shunday ishlab chiqilgan — AgentBridge sertifikatiga ishonch bildirilmagan holda shaffof ushlash ushbu ilovalarning TLS tekshiruvini buzadi.
- **Ayrim komponentlardagi kodga qat’iy yozilgan satrlar**: Ayrim UI komponentlarida (F7/F8) hali i18n kalitlari bilan qamrab olinmagan oz sonli kodga qat’iy yozilgan satrlar mavjud. Ular i18n bo‘shliqlari hisobotida Ma’lum cheklov sifatida hujjatlashtirilgan; keyingi bosqichda ular ko‘chiriladi. Tegishli satrlar funksional foydalanish uchun tarjima talab qilmaydigan UI dekorativ yorliqlaridir.

## §7 Muammolarni bartaraf etish

### WebSocket ulanishining uzilishi

Agar jonli oqimda "Ulanish uzildi" ko‘rsatilsa:

1. Server hali ham ishlayotganini tekshiring: `GET /api/tools/traffic-inspector/capture-modes`
2. Sahifani qayta yuklang — WebSocket qayta ulanadi va yangi holat nusxasini oladi
3. Agar server qayta ishga tushirilgan bo‘lsa, xotiradagi bufer tozalangan bo‘ladi — seans yozib olinmagan bo‘lsa, eski yozuvlar yo‘qoladi

### 8080 porti ziddiyati

Agar HTTP_PROXY rejimi ishga tushmasa:

```bash
lsof -i :8080    # jarayonni topish
```

Portni o‘zgartiring:

```bash
# .env
INSPECTOR_HTTP_PROXY_PORT=8888
```

### Tizim proksisi asl holatiga qaytarilmagan

Agar butun tizim proksi rejimi faol bo‘lgan vaqtda OmniRoute ishdan chiqsa:

**macOS:**

```bash
networksetup -setwebproxystate Wi-Fi off
networksetup -setsecurewebproxystate Wi-Fi off
```

**Linux (GNOME):**

```bash
gsettings set org.gnome.system.proxy mode 'none'
```

**Windows:**

```cmd
netsh winhttp reset proxy
```

Agar boshqaruv paneli DB holatida proksi faol bo‘lganini aniqlasa, keyingi yuklanishda "Tizim proksisini asl holatiga qaytarish" variantini ham taklif qiladi.

### Bufer to‘lgan

Bufer `INSPECTOR_BUFFER_SIZE` qiymatiga (standart qiymat — 1000) yetganda, yangi yozuvlar eng eski yozuvlarni chiqarib yuboradi. Agar muhim so‘rovlar yo‘qolayotgan bo‘lsa:

- `INSPECTOR_BUFFER_SIZE` qiymatini oshiring (masalan, 5000) — bu saqlash davomiyligini oshirish evaziga ko‘proq xotira sarflaydi
- Tegishli vaqt oralig‘ini DB bazasida saqlab qolish uchun seansni yozib oling
