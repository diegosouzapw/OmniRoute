> **Qisqacha**: `open-sse/` — OmniRoute’dagi har bir LLM soʻrovini boshqaradigan asosiy oqimli uzatish mexanizmi. U soʻrov konveyeri, ijrochilar, xizmatlar, MCP serveri va tarjima qatlamini amalga oshiruvchi ~1 400 ta faylni oʻz ichiga oladi. Ushbu qoʻllanma bu qismlar qanday birgalikda ishlashini tushuntiradi.

**Manba:** `open-sse/` (ish maydoni paketi, testga oid boʻlmagan ~1 440 ta `.ts` fayl)

## Nima uchun alohida ish maydoni paketi?

`open-sse/` bir nechta sabablarga koʻra OmniRoute monoreposida **mustaqil ish maydoni** hisoblanadi:

1. **Qayta foydalanish imkoniyati** — `open-sse` npm’da `@omniroute/open-sse` sifatida chop etiladi, shuning uchun boshqa loyihalar undan mustaqil ravishda foydalanishi mumkin
2. **Aniq chegaralar** — oqimli uzatish mexanizmi OmniRoute’ga xos UI/DB qatlamidan ajratilgan
3. **Unumdorlik** — mexanizmda Next.js bogʻliqliklari yoʻq, bu CLI/serverless muhitlarida sovuq ishga tushishni tezlashtiradi
4. **Versiyalash** — `open-sse` oʻz jadvali boʻyicha reliz chiqarishi mumkin

```json
// package.json
"workspaces": ["open-sse"]
```

## Soʻrov konveyeri

Har bir LLM soʻrovi **5 bosqichli konveyer** orqali oʻtadi:

```
                              ┌──────────────┐
   HTTP soʻrovi                │  1. YOʻNALTIRISH│   kombinatsiyani aniqlash, modelni tanlash
   (Next.js marshruti)         └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  2. TARJIMA  │   formatni oʻzgartirish (OpenAI ↔ Claude ↔ Gemini)
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  3. BAJARISH │   provayder ijrochisi, HTTP, qayta urinish, uzgich
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  4. OQIM     │   SSE transformatsiyasi, teskari bosim
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  5. QAYD     │   foydalanishni kuzatish, chaqiruv jurnali, xatoni tasniflash
                              └──────┬───────┘
                                     │
                                     ▼
                              HTTP javobi (SSE yoki JSON)
```

### 1-bosqich: Yoʻnaltirish (services/combo.ts)

**Kirish nuqtasi**: `services/combo.ts` ichidagi `handleComboChat()`

Soʻrovni aniq `(provider, model, account, credentials)` kortejiga moslaydi:

- Kombinatsiyani ID boʻyicha topish (yoki `auto/*` modellari uchun virtual kombinatsiya yaratish)
- Yoʻnaltirish strategiyasini qoʻllash (ustuvorlik, vaznli, navbatma-navbat va boshqalar)
- Nosogʻlom provayderlarni chiqarib tashlash (avtomatik uzgich)
- Keyingi yaroqli nishonni tanlash

`auto/*` modellari uchun bu bosqich quyidagilarni ham bajaradi:

- **16 omilli baholash** algoritmini ishga tushiradi (`services/autoCombo/`)
- Sogʻlomlik, xarajat, kechikish va boshqa omillar asosida `provider+model` juftligini tanlaydi

### 2-bosqich: Tarjima (translator/)

Agar manba formati (masalan, OpenAI) maqsad formatidan (masalan, Claude) farq qilsa, soʻrov **tarjima qilinadi**:

- Tizim prompti → tizim xabari
- Vosita taʼriflari → provayderga xos vosita formati
- Mulohaza/yuritmali fikrlash parametrlari → provayderga xos muqobillar
- Xabar rollarini meʼyorlashtirish (OpenAI boʻlmaganlar uchun `developer` → `system`)

`translator/index.ts` quyidagilarni taqdim etadi:

```ts
translateRequest(body, sourceFormat, targetFormat): TranslatedRequest
needsTranslation(source, target): boolean
```

### 3-bosqich: Bajarish (executors/)

**Kirish nuqtasi**: `getExecutor(providerId).execute(request, options)`

Barcha provayderlar `getExecutor()` fabrikasining zaxira varianti orqali `DefaultExecutor` (`executors/default.ts`)dan foydalanadi. Ijrochi:

- Yuqori oqim URL manzilini tuzadi (`buildUrl()`)
- Provayderga xos sarlavhalarni qoʻshadi (`buildHeaders()`)
- Soʻrov tanasini oʻzgartiradi (`transformRequest()`)
- HTTP soʻrovini qayta urinish va eksponensial kechiktirish bilan yuboradi
- Zarur boʻlsa, autentifikatsiyani yangilaydi (OAuth provayderlari)

Barcha ijrochilar `BaseExecutor` (`executors/base.ts`, 1170 qator kod)ni kengaytiradi, u quyidagilarni taqdim etadi:

- Umumiy qayta urinish mantigʻi
- Proksi integratsiyasi
- Avtomatik uzgich integratsiyasi
- Foydalanishni qayd etish ilgaklari

### 4-bosqich: Oqim (utils/stream.ts)

Oqimli javoblar uchun ijrochi **ReadableStream** qaytaradi. Ishlovchi:

- SSE transformatsiyasi orqali oʻtkazadi (`createSSETransformStreamWithLogger`)
- Uzilib qolgan ulanishlarni aniqlash uchun davriy signal pinglarini qoʻllaydi
- Mijoz uzilishini muammosiz boshqaradi (`pipeWithDisconnect`)
- Oqimsiz mijozlar uchun SSE → JSON oʻzgartirishini bajaradi

Oqimsiz javoblar uchun ijrochi tahlil qilingan JSON obyektini qaytaradi va u oʻzgartirilmasdan uzatiladi.

### 5-bosqich: Qayd etish (services/usage.ts)

Javobdan soʻng (muvaffaqiyatli yoki muvaffaqiyatsiz), foydalanish qayd etiladi:

- Javobdan olingan `prompt_tokens`, `completion_tokens`, `cached_tokens`
- Narxlash maʼlumotlari asosida hisoblangan `cost_usd`
- Muvaffaqiyatsiz boʻlsa, `latency_ms`, `status`, `error_class`
- `usage_history` jadvaliga saqlanadi

Chaqiruv jurnali artefaktlari (agar yoqilgan boʻlsa) `${DATA_DIR}/call_logs/` manziliga yoziladi.

## Asosiy fayllarni chuqur tahlil qilish

### chatCore.ts (5977 qator)

**Asosiy so'rov ishlovchisi**. Hajmiga qaramay, u aniq tuzilishga ega:

```ts
// chatCore.ts ning psevdo-tuzilishi
export async function handleChat(request: NextRequest) {
  // 1. Autentifikatsiya + CORS
  await authenticateRequest(request);
  applyCorsHeaders(response);

  // 2. Body validatsiyasi
  const body = await parseRequestBody(request);

  // 3. Formatni aniqlash + konvertatsiya
  const sourceFormat = detectFormat(request);
  const targetFormat = getTargetFormat(providerId);
  if (needsTranslation(sourceFormat, targetFormat)) {
    body = translateRequest(body, sourceFormat, targetFormat);
  }

  // 4. Combo marshrutlashi
  const targets = await resolveComboTargets(comboId, body);
  for (const target of targets) {
    try {
      const result = await executeOnTarget(target, body);
      await recordUsage(result);
      return result;
    } catch (err) {
      // Keyingi targetga o'tish
    }
  }

  // 5. Favqulodda fallback
  return await emergencyFallback(body);
}
```

Bitta ulkan funksiya bo'lishiga qaramay, u 5 bosqichli pipeline'ga mos keladigan **izohlangan bo'limlar** ko'rinishida tashkil etilgan.

### combo.ts (4456 LOC)

// services/combo.ts
export async function handleComboChat(body, comboId): Promise<ChatResult> {
  const targets = await resolveComboTargets(comboId, body);
  for (const target of targets) {
    try {
      return await handleSingleModel(target, body);
    } catch (err) {
      log.warn("target failed, trying next", { target, err });
    }

  throw new ComboExhaustedError("All targets failed");
}

## Ijrochilar (150 modul)

Asosan har bir provayderga bitta fayl toʻgʻri keladi. Barcha ijrochi klasslar `BaseExecutor`dan meros oladi va farq qiladigan qismlarni qayta yozadi; qolgan modullar — provayderga xos yordamchilar (tool sxemalari, fetch/TTS adapterlari, quirk handlerlari).

### Umumiy naqshlar

Provayderlar `getExecutor(providerId)` orqali aniqlanadi, u sozlangan ijrochini qaytaradi. OpenAI/Anthropic-mos provayderlar `DefaultExecutor`dan (`executors/default.ts`) foydalanadi. Provayderga xos xatti-harakat (asosiy URL, auth sarlavhalari, API versiyasi) `open-sse/config/providers/` katalogida sozlanadi, soʻrov tanasi transformatsiyalari esa `open-sse/translator/` da bajariladi.

**Maxsus URL** provayder konfiguratsiyasi orqali oʻrnatiladi:

```ts
// Provayder konfiguratsiyasi open-sse/config/providers/ ichida
export default {
  id: "together",
  baseURL: "https://api.together.xyz/v1/chat/completions",
}
````

**Maxsus auth** provayder reyestrining auth konfiguratsiyasi orqali amalga oshiriladi (API kalit, OAuth, sarlavha profillari).

**Maxsus soʻrov tanasi** transformatsiyalari (masalan, Anthropicning `system`ni `messages`dan ajratishi) har bir provayder uchun `open-sse/translator/` da roʻyxatga olinadi.

````

### Ijrochi fabrikasi

`executors/index.ts` `getExecutor(providerId)` ni eksport qiladi:

```ts
import { getExecutor } from "@omniroute/open-sse/executors";

const executor = getExecutor("anthropic");
const result = await executor.execute({
  model: "claude-sonnet-4-5",
  messages: [...],
});
````

Aniqlash `ExecutorRegistry` (`executors/registry.ts`) orqali oʻtadi: har bir ixtisoslashgan ijrochi `executors/index.ts` dagi oʻrnatilgan jadvalda eʼlon qilinadi va modul yuklanishida `registerExecutor(alias, instance)` orqali roʻyxatga olinadi; `getExecutor()` reyestrga murojaat qiladi va ixtisoslashgan yozuvga ega boʻlmagan har qanday provayder uchun memoizatsiya qilingan `DefaultExecutor`ga qaytadi. Toʻliq alias → ijrochi moslashuvi `tests/unit/executor-map-golden.test.ts` golden testi bilan xarakterlangan.

## Tarjimonlar

**3 ta format** o‘rtasida tarjima qiladi: OpenAI, Anthropic, Gemini, shuningdek yangi Responses API.

### Tarjima qachon amalga oshiriladi

```ts
import { needsTranslation, translateRequest } from "@omniroute/open-sse/translator";

if (needsTranslation(sourceFormat, targetFormat)) {
  body = translateRequest(body, sourceFormat, targetFormat);
}
```

Keng tarqalgan tarjimalar:

- `OpenAI → Anthropic`: alohida `system` maydoni, `x-api-key` sarlavhasi
- `OpenAI → Gemini`: `messages` o‘rniga `contents`, `systemInstruction`
- `OpenAI → Responses API`: `input` massivi, `previous_response_id` holati

### Qo‘llab-quvvatlanadigan chekka holatlar

- `developer` roli → OpenAI bo‘lmagan tizimlar uchun `system`
- `system` roli → GLM/ERNIE uchun birinchi foydalanuvchi xabariga birlashtiriladi
- `json_schema` → Gemini’ning `responseMimeType` + `responseSchema`
- `tools` → provayderga xos vosita formati
- Fikrlash parametrlari (o1, Claude) → provayderga xos muqobillar

## MCP serveri

`open-sse/mcp-server/` **Model Context Protocol** serverini amalga oshiradi:

- **110 ta vosita** (provayderlarni boshqarish, kombinatsiyalar, xotira, kesh, siqish, proksi, ko‘nikmalar, geymifikatsiya, plaginlar, Notion, Obsidian, mahalliy korpus)
- **3 ta transport**: stdio, SSE, Streamable HTTP
- Batafsil avtorizatsiya uchun **33 ta doira**

### Vositalarni ro‘yxatdan o‘tkazish

Vositalar `open-sse/mcp-server/tools/` ichida alohida fayllar sifatida ro‘yxatdan o‘tkaziladi, ularning har biri nom, sxema, ishlov beruvchi va doirani eksport qiladi:

```ts
// open-sse/mcp-server/tools/getHealth.ts
import { z } from "zod";
export default {
  name: "omniroute_get_health",
  description: "Tizim holatining joriy tasvirini olish",
  scope: "read:health",
  inputSchema: z.object({}),
  handler: async (_args, ctx) => {
    return await getSystemHealth();
  },
};
```

### Transportlar

```ts
// stdio (CLI orqali foydalanish)
startMcpStdio(server);

// SSE (HTTP asosidagi oqimli uzatish)
startMcpSse(server, port);

// Streamable HTTP (zamonaviy MCP)
startMcpStreamable(server, port);
```

### Avtorizatsiya

Har bir vosita chaqiruvi doira tekshiruvlaridan o‘tadi (`open-sse/mcp-server/auth/`):

```ts
if (!hasScope(apiKey, "providers:read")) {
  throw new Error("Doira yetarli emas");
}
```

## Transformatorlar

`open-sse/transformer/` **Chat Completions** va **Responses API** formatlari o‘rtasida o‘zgartirishni amalga oshiradi.

### Nima uchun alohida transformator kerak?

Responses API — OpenAI’ning **holatni saqlovchi suhbatlar** (`previous_response_id`) imkoniyatiga ega yangi formati. Mijoz Responses so‘rovini yuborganda, OmniRoute:

1. Responses formatini ichki tarzda Chat Completions formatiga o‘zgartiradi
2. Provayderga yuboradi (Chat Completions’ni qo‘llab-quvvatlaydigan istalgan provayder)
3. Javobni qayta Responses formatiga o‘zgartiradi
4. O‘zgartirilgan javobni mijozga oqim tarzida uzatadi

Transformator (`transformer/responsesTransformer.ts`) quyidagini taqdim etadi:

```ts
createResponsesApiTransformStream(): TransformStream
```

U quyidagilarni boshqaradi:

- `response.output_item.added` hodisalari
- `response.output_text.delta` hodisalari
- `response.completed` hodisasi
- Vosita chaqiruvlarini moslashtirish (`function_call` ↔ `tool_calls`)
