AgentBridge — OmniRoute’ning MITM (Man-in-the-Middle) proksisi bo‘lib, IDE AI agentlarining HTTPS trafigini ushlab qoladi va uni OmniRoute’ning yagona marshrutlash mexanizmi orqali qayta yo‘naltiradi. U **10 ta IDE agentini** — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code va Trae (o‘rganilmoqda) — qo‘llab-quvvatlaydi, bu esa OmniRoute’ni bozordagi AI dasturlash yordamchilari uchun eng keng qamrovli MITM proksisiga aylantiradi.

**Boshqaruv panelidagi joylashuvi:** `/dashboard/tools/agent-bridge`
**Yon panel guruhi:** Vositalar (Cloud Agents’dan keyin)
**Shuningdek qarang:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — barcha ushlangan trafikni real vaqt rejimida kuzatish; `docs/security/MITM-TPROXY-DECRYPT.md` (git; `/docs` tarkibiga kompilyatsiya qilinmaydi) — `/api/tools/agent-bridge/tproxy` marshruti orqali boshqariladigan Linux TPROXY shaffof deshifrlash va yozib olish rejimi.

## §1 Umumiy ma’lumot

### AgentBridge nima?

IDE agenti (masalan, GitHub Copilot, Cursor, Claude Code) API chaqiruvini amalga oshirganda, u to‘g‘ridan-to‘g‘ri yuqori oqimdagi AI provayderiga (OpenAI, Anthropic va boshqalar) ulanadi. AgentBridge ushbu ulanishni TLS darajasida shaffof tarzda — agent konfiguratsiyasini o‘zgartirishni talab qilmasdan — ushlab qoladi va so‘rovni OmniRoute orqali qayta yo‘naltiradi.

Bu sizga quyidagilarni amalga oshirish imkonini beradi:

- **Istalgan agentni istalgan provayderga qayta yo‘naltirish**: Copilot OpenAI bilan ishlayaptimi? Uni Anthropic Claude, Gemini yoki OmniRoute’dagi 352 ta provayderdan istalgan biriga yo‘naltiring.
- **Model mosliklarini qo‘llash**: `gemini-3-flash` → `claude-sonnet-4.7` mosligini ishlov beruvchi darajasida shaffof tarzda qo‘llang.
- **Barcha agent trafigini kuzatish**: har bir ushlangan so‘rov [Traffic Inspector](./TRAFFIC_INSPECTOR.md) xizmatiga yuboriladi.
- **OmniRoute barqarorlik imkoniyatlarini qo‘llash**: kombinatsiyalangan marshrutlash, avtomatik uzgichlar, zaxira yo‘nalishlar va xarajatlarni kuzatish IDE agentlari trafigi uchun ham ishlaydi.

## §2 Arxitektura

### 2.1 Komponentlar haqida umumiy maʼlumot

```
IDE agenti (VS Code / Cursor / va boshqalar)
    │  HTTPS (443-port)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← DNS qayta yoʻnaltirishi
    │
    ▼
src/mitm/server.cjs  (443-port, CJS yordamchi jarayoni)
    │  nishonni Host sarlavhasidagi SNI orqali aniqlaydi
    │  AgentBridge CA tomonidan imzolangan har bir SNI uchun TLS sertifikatini yaratadi
    ├── Chetlab oʻtish roʻyxatiga mosmi? → TCP orqali bevosita oʻtkazish (shifrdan yechilmaydi)
    ├── Nishonga mosmi? → fetch → OmniRoute marshrutizatori (20128-port)
    │       └── handler.intercept() — TypeScript
    │               ├── soʻrov tanasi/sarlavhalarida maskSecrets()
    │               ├── TrafficBuffer.push() — Traffic Inspector xizmatiga yuboradi
    │               └── fetchRouter() → /v1/chat/completions
    └── Moslik yoʻqmi? → TCP orqali bevosita oʻtkazish (shifrdan yechilmaydi)
```

### 2.2 MITM serveri (`src/mitm/server.cjs`)

Asosiy MITM serveri Node.js CJS yordamchi jarayoni sifatida ishlaydi (mavjud CJS kod bazasini qayta yozmaslik uchun). U:

- 443-portni tinglaydi (imtiyoz yoki `authbind`/`setcap` talab qilinadi)
- Operatsion tizimdan CONNECT tunnellarini qabul qiladi (`/etc/hosts` DNS qayta yoʻnaltirishi orqali)
- AgentBridge CA (`DATA_DIR/mitm/ca.crt`) tomonidan imzolangan har bir SNI uchun TLS sertifikatlarini yaratadi
- `targets/index.ts` reyestri orqali Host sarlavhasi asosida nishon agentini aniqlaydi
- HTTP orqali TypeScript ishlov beruvchi qatlamiga `http://127.0.0.1:20128` manzilida uzatadi

`TARGET_HOSTS` `DATA_DIR/mitm/targets.json` faylidan yuklanadi (ishga tushirish vaqtida `targets/index.ts` tomonidan yoziladi), bu CJS serverini qayta ishga tushirmasdan dinamik yangilash imkonini beradi.

> **Root-CA modeli (#6684).** Yuqoridagi CA tomonidan imzolangan har bir SNI uchun sertifikat tavsifi
> #6684 da qoʻshilgan doimiy root-CA modelidir (`src/mitm/cert/rootCa.ts` +
> `src/mitm/_internal/rootCaShim.cjs`, bunda `src/mitm/tproxy/dynamicCert.ts` faylida
> TPROXY uchun allaqachon sinalgan CA/barg kriptografiyasi qayta ishlatiladi) — u diskdagi oddiy
> `server.crt`/`server.key` juftligi mavjudligini bildiruvchi, faqat antigravity hostlari doirasida
> qoladigan eski yagona statik, oʻzi imzolagan barg sertifikatini
> (`src/mitm/cert/generate.ts`) almashtiradi. **Migratsiya xatti-harakati**: yangi oʻrnatish
> (avvalgi `server.crt` mavjud boʻlmasa) root-CA modelini avtomatik ravishda oladi; eski statik barg
> sertifikatiga allaqachon ishongan oʻrnatish operator `MITM_ROOT_CA_ENABLED=true` qiymatini
> oʻrnatib, koʻprikni qayta ishga tushirmaguncha undan foydalanishda davom etadi
> (`src/mitm/cert/migration.ts` — sof qaror qabul qilish funksiyasi; **istalgan** host uchun
> barg sertifikatini imzolay oladigan ishonchli MITM CA eski, qatʼiy SAN barg sertifikatidan
> ancha kuchliroq, shuning uchun allaqachon ishonch bildirilgan oʻrnatishda oʻtish hech qachon
> yashirin amalga oshirilmaydi). CA sertifikati eski barg sertifikati foydalangan ayni
> `omniroute-mitm.crt` ishonch ombori uyasiga oʻrnatiladi
> (`cert/install.ts::installCaCert`) — ikkita ishonch yozuvini tozalash talab qilinmaydi.

### 2.3 Ishlov beruvchi asosi (`src/mitm/handlers/base.ts`)

Barcha agent ishlov beruvchilari `MitmHandlerBase` klassini kengaytiradi:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // Himoyalangan yordamchilar: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

Har bir ishlov beruvchi proksilashdan oldin `hookBufferStart()` funksiyasini va jarayon tugagach `hookBufferUpdate()` funksiyasini chaqiradi. Ular `InterceptedRequest` yozuvlarini `globalTrafficBuffer` buferiga yuboradi ([Traffic Inspector](./TRAFFIC_INSPECTOR.md) §4 bo‘limiga qarang).

### 2.4 Nishonlar reyestri (`src/mitm/targets/`)

Har bir agent deklarativ nishon fayliga ega:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

Reyestr (`targets/index.ts`) `ALL_TARGETS` ni eksport qiladi va ishga tushirish vaqtida `DATA_DIR/mitm/targets.json` faylini yaratadi.

### 2.5 Bevosita oʻtkazish va chetlab oʻtish roʻyxati (`src/mitm/passthrough.ts`)

**Chetlab oʻtish roʻyxati** (birinchi boʻlib tekshiriladi va nishonga moslikdan ustun turadi):

- Standart andozalar: bank hostlari, `.gov.`, OAuth/SSO provayderlari (Okta, Auth0) va boshqalar
- Foydalanuvchi andozalari: `agent_bridge_bypass` maʼlumotlar bazasi jadvalida saqlanadi
- Chetlab oʻtiladigan hostlar shaffof TCP tunnelini oladi — TLS **hech qachon shifrdan yechilmaydi**

**Standart bevosita oʻtkazish** (nishonga moslik yoʻq va chetlab oʻtish roʻyxatida emas):

- U ham TCP tunnelini oladi — ulanishlar hech qachon uzilmaydi
- AgentBridge umumiy tizim HTTPS trafigiga xalaqit berishining oldini oladi

Marshrutlash ustuvorligi:

```
chetlab oʻtish roʻyxati → nishonga moslik → bevosita oʻtkazish
```

### 2.6 Yuqori oqim CA sertifikati (`src/mitm/upstreamTrust.ts`)

Maxsus CA ishlatiladigan korporativ tarmoq muhitlari uchun:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

Bu qiymat oʻrnatilganda, `undici` global dispetcheri qoʻshimcha CA sertifikati bilan sozlanadi va AgentBridge korporativ TLS terminatsiya proksilari orqali yuqori oqim provayderlariga ulana oladi.

### 2.7 Maxfiy maʼlumotlarni niqoblash (`src/mitm/maskSecrets.ts`)

Mustaqil, toza muhitda yaratilgan skaner soʻrov tanalari va hisobga olish maʼlumotlari sarlavhalariga
ular Traffic Inspector buferiga yoki biror jurnalga kirishidan **oldin** qoʻllanadi. U bitta chiziqli oʻtishni amalga oshiradi:

- `sk-` / `ak-` / `pk-` prefiksli tokenlar (OpenAI/Anthropic uslubida)
- RFC 6750 `Authorization: Bearer <token>` hisobga olish maʼlumotlari, bunda butun token ustuvorlikka ega
- Umumiy uzun shaffof boʻlmagan tokenlar (≥40 ta belgi), jumladan nuqtali va toʻldirilgan shakllar

`sanitizeHeaders()` saqlab qolinadigan nomlarni kichik harflarga oʻtkazadi, massiv qiymatlarini deterministik tarzda birlashtiradi, umumiy hop-by-hop/freyming taqiqlash roʻyxatidagi sarlavhalarni (jumladan proksi autentifikatsiyasini) olib tashlaydi, `cookie` va `set-cookie` qiymatlarini toʻliq yashiradi hamda hisobga olish maʼlumotlari qiymatlarini skanerga topshiradi.

## §3 Sozlash

### 3.1 MITM serverini ishga tushirish/toʻxtatish

`/dashboard/tools/agent-bridge` manzilidagi AgentBridge Server kartasidan foydalaning:

| Amal                           | Tavsif                                                                                                         |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| Serverni ishga tushirish       | 443-portda `src/mitm/server.cjs` jarayonini ishga tushiradi                                                    |
| Serverni toʻxtatish            | Quyi jarayonni xavfsiz tarzda toʻxtatadi                                                                       |
| Serverni qayta ishga tushirish | Toʻxtatish + ishga tushirish (maqsad oʻzgarishlarini qoʻllaydi)                                                |
| Sertifikatga ishonish          | `DATA_DIR/mitm/ca.crt` faylini OT ishonchli sertifikatlar omboriga oʻrnatadi                                   |
| Sertifikatni yuklab olish      | Qoʻlda oʻrnatish uchun `ca.crt` faylini yuklab oladi                                                           |
| Sertifikatni qayta yaratish    | Yangi CA kalitlar juftligini yaratadi (har bir agent uchun mavjud barcha sertifikatlar yaroqsiz boʻlib qoladi) |

### 3.2 Sertifikatga ishonish

IDEʼlar MITM ulanishini qabul qilishi uchun AgentBridge CA sertifikati OT tomonidan ishonchli deb tan olinishi kerak.

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Keychain):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

Yoki boshqaruv panelidagi "Sertifikatga ishonish" tugmasidan foydalaning (u OT uchun mos buyruqni ishga tushiradi va zarur boʻlsa sudo soʻrovini koʻrsatadi).

#### Electron asosidagi IDEʼlar OT ishonchli sertifikatlar omborini eʼtiborsiz qoldiradi (`NODE_EXTRA_CA_CERTS`)

Ayrim IDEʼlar — xususan **Antigravity IDE** va Electron / VS Code asosidagi boshqa ilovalar — tashqi
`fetch`/HTTPS soʻrovlari uchun **OT ishonchli sertifikatlar omboriga murojaat qilmaydigan**
oʻz Node.js bajarilish muhitini oʻz ichiga oladi. CAʼga OT/NSS darajasida ishonish IDEʼning mahalliy **backend**
qismi (masalan, OT CA toʻplamidan foydalanadigan Go til serveri) uchun yetarli, ammo **Electron frontend**
qismida TLS baribir muvaffaqiyatsiz tugaydi — MITM jurnali backendʼning boshlangʻich soʻrovlari `200`
qaytarayotganini koʻrsatsa ham, bu ilovada foydalanuvchi _tizimdan chiqarilgandek_ yoki
_"ulanish xatosi"_ koʻrsatilishi sifatida namoyon boʻladi. Ikki qadam talab qilinadi va ikkalasi ham muhim:

1. Bajarilish muhitiga CA manzilini aniq koʻrsating:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **IDEʼni aynan shu shelldan ishga tushiring.** Uni ish stoli belgisi / Dock / Start menyusi orqali
   ishga tushirish shell eksportlarini **meros qilib olmaydi**, `~/.config/environment.d/*.conf` esa faqat
   yangi grafik kirishdan keyin qoʻllanadi. Avval IDEʼdan toʻliq chiqing — Electronʼning yagona nusxa qulfi
   sababli ikkinchi ishga tushirish faqat mavjud jarayonni fokuslaydi va yangi muhit eʼtiborsiz qoldiriladi.

Yuqoridagi OT ishonchi + NSS qadami baribir zarur (ayrim autentifikatsiya jarayonlari foydalanadigan Chromium
tarmoq steki har bir foydalanuvchining NSS omborini oʻqiydi hamda `*.googleapis.com` uchun oʻzining statik
pinlariga ega boʻlib, mahalliy ishonchli CA ularni bekor qiladi). `NODE_EXTRA_CA_CERTS` buning ustiga Node
`fetch` yoʻlini qamrab oladi.

### 3.3 DNS yoʻnaltirish

Tutib qolmoqchi boʻlgan har bir agent uchun uning API hosti yoki hostlari `127.0.0.1` manziliga aniqlanishi kerak. Sozlash ustasida agent uchun DNSʼni yoqqaningizda AgentBridge `/etc/hosts` yozuvlarini avtomatik boshqaradi.

GitHub Copilot uchun `/etc/hosts` yozuvlari namunasi:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 Model moslashtirish

Manba → maqsad mosliklarini belgilash uchun har bir agent kartasidagi Model Mapping jadvalidan foydalaning:

| Manba modeli (agentga xos) | Maqsad modeli (OmniRoute) |
| -------------------------- | ------------------------- |
| `gpt-4o`                   | `claude-sonnet-4.7`       |
| `*` (joker belgi)          | `claude-haiku-4.7`        |

`*` joker belgisi tanilmagan har qanday modelni koʻrsatilgan maqsadga moslaydi. Maʼlumotlar `agent_bridge_mappings` jadvalida saqlanadi.

> **Maslahat — agentning haqiqiy model IDʼlarini aniqlang.** IDE oʻz interfeysidagi yorliqlardan farq qiladigan
> va asosiy versiyalar oʻrtasida oʻzgaradigan model nomlarini yuborishi mumkin. Masalan, **Antigravity 2**
> tarmoq orqali `gemini-3.1-pro-low`, `gemini-pro-agent` va `gemini-3.1-flash-lite` qiymatlarini yuboradi —
> eski hujjatlarda koʻrsatilgan `gemini-2.5-pro` qiymatini emas. Mos keluvchi xaritalash mavjud boʻlmagan
> holda bitta chat yuboring: MITM aniq kiruvchi `model:` qiymatini jurnalga yozadi va soʻrovni oʻtkazib yuboradi.
> Aynan shu qiymatni moslang, shunda keyingi soʻrov tutib qolinadi va maqsadingizga yoʻnaltiriladi.

### 3.5 Xavf haqida ogohlantirish

AgentBridge IDE yuqori oqim provayderlari bilan autentifikatsiya qilish uchun foydalanadigan hisob maʼlumotlarini (OAuth tokenlari, API kalitlari) tutib qoladi. Ular **jurnalga yozilishidan oldin maskalanadi** (§2.7 ga qarang), biroq OmniRouteʼning MITM qatlamiga koʻrinadi. Har bir agent birinchi marta faollashtirilganda yopish mumkin boʻlgan xavf haqidagi ogohlantirish modal oynasi koʻrsatiladi.

Boshqaruv panelida avval interfeysga ega boʻlmagan operatsion MITM yoʻnalishlarini koʻrsatadigan **Texnik xizmat va diagnostika** kartasi (`AgentBridgeMaintenanceCard`, `src/app/(dashboard)/dashboard/tools/agent-bridge/components/` ichida) mavjud. | Tugma                               | Yoʻnalish                              | Vazifasi                                                                                                                                                                                                                                       |
| ----------------------------------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| **Tuzatish**                        | `POST /api/tools/agent-bridge/repair`  | Nosozlik yoki SIGKILL tufayli qolib ketgan egasiz MITM tizim holatini (DNS soxtalashtirish yozuvlari, ildiz CA, tizim proksisi) bekor qiladi. Idempotent — holat toza boʻlsa, «Tuzatiladigan hech narsa yoʻq» deb xabar beradi.                |

Har bir agent kartasida oʻzining **Standart holatni tiklash** tugmasi ham mavjud (`POST
/api/tools/agent-bridge/agents/{id}/reset`) — bu bir marta bosish orqali har bir agent uchun bekor qilish amali boʻlib, faqat shu
agent hostlarining soxtalashtirilishini bekor qiladi, uning saqlangan model mosliklarini tozalaydi va `dns_enabled`/`setup_completed`
holatini qayta oʻrnatadi, natijada IDE toʻliq qayta ishga tushirilgach, yana haqiqiy yuqori oqim xizmatiga ulanadi. U umumiy
MITM serveri yoki ildiz CAga **tegmaydi** (boshqa agentlar hali ham ularga bogʻliq boʻlishi mumkin) — ularga yuqoridagi Server kartasi va
**CAni oʻchirish** amali orqali kirish mumkin boʻlib qoladi. Windows tizimida u imkon qadar

| Tekshiruv nomi     | Nimani tekshiradi                                                      | Nosozlik yuz bergandagi tavsiya                                                                                                                                   |
| ------------------ | ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server-running`   | MITM server jarayoni faol ekanini                                      | «MITM serveri ishlamayapti. Uni AgentBridge varagʻidan ishga tushiring.»                                                                                          |
| `server-reachable` | MITM serveri oʻz portida ulanishlarni qabul qilishini (TCP tekshiruvi) | «MITM serveri oʻz portida ulanishlarni qabul qilmayapti. Port boʻsh ekanini va uni bogʻlash uchun imtiyozlaringiz borligini tekshiring.»                          |

| `cert-trusted`     | MITM ildiz CA OT ishonchli sertifikatlar omborida mavjudligini         | «MITM ildiz CAsiga OT ombori ishonmaydi, shu sababli TLS tutib olish ishlamaydi. Sertifikatni AgentBridge varagʻidan ishonchli deb belgilang.»                    |
| `dns-configured`   | Maqsadli host nomlari `/etc/hosts` ichida soxtalashtirilganini         | «Maqsadli host nomlari /etc/hosts ichida soxtalashtirilmagan, shu sababli trafik proksiga yetib bormaydi. Qamrab olmoqchi boʻlgan agent(lar) uchun DNSni yoqing.» |

**Egasiz holat banneri:** sahifa nosozlikdan keyin qolib ketgan holatni (DNS soxtalashtirish / CA / tizim proksisi) aniqlasa, kartada qahrabo rangli banner — _«Avvalgi seans tizim holatini (DNS soxtalashtirish, CA yoki tizim proksisi) qoldirib ketgan. Uni tozalash uchun Tuzatishni ishga tushiring.»_ — koʻrsatiladi va **Tuzatish** tugmasi ajratib koʻrsatiladi. `Repair` ProxyBridgeʼning `--cleanup` bayrogʻiga ilova qatlami darajasidagi muqobildir (u vazifani `src/mitm/manager.ts` ichidagi `repairMitm()`ga topshiradi).

> Qayta-qayta sudo soʻrovlarini oldini olish uchun MITM ildiz CA toʻxtatish/ishga tushirishlar orasida oʻrnatilgan holda
> saqlanadi (mitmproxy/Charles bilan bir xil xatti-harakat), shu sababli uni olib tashlash toʻxtatish paytida avtomatik
> bajariladigan amal emas, balki aniq **CAni oʻchirish** amalidir.

### 3.7 Koʻchma konfiguratsiyani import/eksport qilish

AgentBridge sozlamani turli mashinalarda takrorlash mumkin boʻlishi uchun **operator sozlay oladigan** holatni versiyalangan JSON obyektiga serializatsiya qila oladi. Serializator — `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`), u `AgentBridgeConfigSchema` orqali tekshiriladi.

Eksport aynan uchta qismni oʻz ichiga oladi (ichki standart qiymatlar ataylab eksport qilinmaydi, shuning uchun import qilish ularni hech qachon takrorlamaydi yoki ular bilan ziddiyatga kirmaydi):

| Maydon           | Manba                                                                      | Izohlar                                                                   |
| ---------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `bypassPatterns` | foydalanuvchi belgilagan chetlab oʻtish andozalari (`agent_bridge_bypass`) | standart bank/gov/okta andozalari chiqarib tashlanadi                     |
| `customHosts`    | Traffic Inspector maxsus hostlari (`inspector_custom_hosts`)               | har biri: `{ host, kind: "llm"\|"app"\|"custom", label? }`                |
| `agentMappings`  | har bir agent uchun model mosliklari (`agent_bridge_mappings`)             | mosliklarga ega har bir agent uchun `{ [agentId]: [{ source, target }] }` |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**Import qilish tartibi** (`POST /api/tools/agent-bridge/config`): chetlab oʻtish andozalari va har bir agent uchun mosliklar **toʻliq almashtiriladi**; maxsus hostlar **idempotent tarzda** qoʻshiladi (`INSERT OR IGNORE`). Javobda har biridan nechtasi qoʻllangani koʻrsatiladi:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

Konfiguratsiyaga **KIRITILMAYDIGAN** maʼlumotlar: serverning ishlash holati, sertifikat yoʻllari, har bir agentning DNS holati, yuqori oqim CA yoʻli va TPROXY sozlamalari — bular koʻchma parametrlar emas, balki host/ish vaqti holatidir.

### Maxfiy hostlar uchun chetlab o‘tish ro‘yxati

Chetlab o‘tish ro‘yxati moliyaviy muassasalar, OAuth/SSO provayderlari va boshqa maxfiy hostlar **hech qachon deshifrlanmasligini** ta’minlaydi. Ularning TLS trafigi shaffof TCP tunneli orqali o‘tadi — OmniRoute hech qachon ochiq matnni ko‘rmaydi.

Standart chetlab o‘tish andozalariga quyidagilar kiradi:

- `*.bank.*`, `*.gov.*` (moliya/hukumat)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/identifikatsiya)
- `*.apple.com`, `*.icloud.com` (Apple tizim xizmatlari)

Foydalanuvchi qo‘shgan chetlab o‘tish andozalari `agent_bridge_bypass` jadvalida saqlanadi va barcha boshqa qoidalardan ustun turadi.

### Sirlarni niqoblash

`src/mitm/maskSecrets.ts` faylidagi `maskSecrets()` quyidagi hollarda qo‘llaniladi:

- Har bir so‘rov tanasiga `TrafficBuffer.push()` dan oldin
- Har bir sarlavhaga jurnalga yozish yoki uzatishdan oldin

Andozalar: `sk-`/`ak-`/`pk-` prefiksli tokenlar, `Bearer` tokenlari va uzunligi ≥40 belgidan iborat umumiy tokenlar.

### Yuqori oqim CA sertifikati

`AGENTBRIDGE_UPSTREAM_CA_CERT` o‘rnatilganda, fayl ishga tushirish vaqtida o‘qiladi. Agar yo‘l mavjud bo‘lsa-yu, faylni o‘qib bo‘lmasa, AgentBridge aniq xatoni jurnalga yozadi va ishga tushishni rad etadi (korporativ muhitlarda yashirin TLS nosozliklarining oldini oladi).

### Ma’lum cheklovlar

- **443-port imtiyoz talab qiladi**: Linux’da AgentBridge Node binar fayli uchun `setcap 'cap_net_bind_service=+ep'` talab qiladi yoki `authbind` orqali ishga tushirilishi kerak. Sozlash ustasi operatsion tizimga xos ko‘rsatmalarni namoyish etadi.
- **IDE’ni qayta ishga tushirish talab qilinadi**: DNS qayta yo‘naltirilgandan keyin yangi host aniqlanishi kuchga kirishi uchun IDE qayta ishga tushirilishi kerak.
- **Qat’iy belgilangan OAuth tokenlari**: Ayrim agentlar (Kiro, Antigravity) OAuth yangilash tokenlarini lokal saqlaydi. Bular AgentBridge uchun shaffof — u har bir so‘rovdagi Bearer tokenini ko‘radi va jurnalga yozishdan oldin uni niqoblaydi.
- **Electron frontendlariga `NODE_EXTRA_CA_CERTS` kerak**: Frontendi ichki Node/Electron muhitida ishlaydigan IDE’lar operatsion tizim/NSS ishonchli sertifikatlar omborini e’tiborsiz qoldiradi va `NODE_EXTRA_CA_CERTS` o‘rnatilgan shell orqali ishga tushirilishi kerak (§3.2 ga qarang). U mavjud bo‘lmagandagi alomat: IDE backendi autentifikatsiyadan o‘tadi (MITM `200` javoblarini ko‘rsatadi), ammo UI tizimga kirmagan holatda qoladi.
- **Bitta IDE’ning bir nechta o‘rnatilishi mustaqildir**: tizim darajasidagi o‘rnatish (masalan, `/usr/share/antigravity/antigravity`) va foydalanuvchi uchun lokal «Full» o‘rnatish (masalan, `~/AntigravityIDE_Full/antigravity-ide`) o‘z bajarish muhitlariga ega alohida jarayonlardir — har biri CA kiritilgan holda qayta ishga tushirilishi kerak. Qayta ishga tushirishdan oldin binar fayl yo‘li orqali aynan qaysi biri ishlayotganini aniqlang.
- **Identifikatsiyani yo‘naltirilgan model emas, agentning tizim prompti belgilaydi**: agent modelini boshqa provayderga moslashtirganingizda ham javob agentning asl identifikatsiyasini da’vo qiladi (masalan, Antigravity «Meni Gemini quvvatlantiradi» deb javob beradi), chunki IDE buni tizim promptiga kiritadi. Haqiqiy backendni modeldan uning kimligini so‘rab emas, `call_logs` / `proxy_logs` ichidagi (`provider`, `model`, `target_format`) orqali tasdiqlang.

## §6 Muammolarni bartaraf etish

### 443-port ziddiyati

Agar boshqa jarayon allaqachon 443-portni tinglayotgan boʻlsa (veb-server, VPN va hokazo):

```bash
lsof -i :443          # jarayonni topish
sudo fuser -k 443/tcp  # majburan toʻxtatish (ehtiyotkorlik bilan ishlating)
```

Muqobil ravishda, AgentBridge sozlamalarida imtiyozsiz portni sozlang va `iptables` / `pf` qayta yoʻnaltirish qoidalarini oʻrnating.

### Sertifikat ishonchli deb topilmadi

Agar AgentBridge ishga tushirilgandan keyin IDE TLS xatolarini koʻrsatsa:

1. Sertifikat oʻrnatilganini tekshiring: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) yoki `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. Ayrim ilovalar oʻz ishonchli sertifikatlar omborini yuritadi (Firefox, Linux’dagi Chrome). "Trust Cert" amalini yana bajaring va NSS/Firefox’ga xos sertifikatlar omborini tekshiring.
3. Ishonch oʻrnatilgandan keyin IDE’ni qayta ishga tushiring — davom etayotgan TLS seanslari eski ishonch holatidan foydalanadi.

### Ishonchli CA mavjudligiga qaramay, IDE tizimdan chiqib ketgan / "connection error"

Alomat: DNS qayta yoʻnaltirilib, CA’ga ishonch oʻrnatilgandan keyin Electron asosidagi IDE (masalan, Antigravity)
**tizimdan chiqilgan** holatda ochiladi yoki autentifikatsiya/ulanish xatosini koʻrsatadi, ammo MITM jurnalida
boshlangʻich chaqiruvlar (`loadCodeAssist`, `fetchAvailableModels`, …) `200` qaytarayotgani koʻrinadi.

Sabab: IDE bilan birga taqdim etilgan **Node/Electron bajarilish muhiti operatsion tizimning ishonchli sertifikatlar omborini eʼtiborsiz qoldiradi**. Mahalliy
bekend (Go til serveri) operatsion tizim CA sertifikatiga ishonadi va autentifikatsiyadan oʻtadi, biroq Electron frontendi
ishonmaydi — shu sababli UI oʻzini oflayn deb hisoblaydi.

Yechim (har ikki qadam): `NODE_EXTRA_CA_CERTS=<ca.crt>` ni eksport qiling **va IDE’ni ish stoli
belgisidan emas, aynan shu qobiqdan qayta ishga tushiring**. Avval IDE’dan toʻliq chiqing — Electron’ning yagona nusxa qulfi
sababli ikkinchi ishga tushirish mavjud jarayonni shunchaki fokuslaydi va yangi muhit eʼtiborsiz qoldiriladi. §3.2 ga qarang.
Bu mustaqil agent MITM orqali ishlaydigan, ammo IDE
varianti ayni sozlama ostida ishlamay qoladigan ochiq yuqori oqim hisobotidagi holatni takrorlaydi.

### DNS tarqalmadi

`/etc/hosts` yangilanganini tekshiring:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

DNS keshini tozalang:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

Avtomatik aniqlash keng tarqalgan oʻrnatish yoʻllaridan foydalanadi. Agar aniqlash muvaffaqiyatsiz tugasa, ammo IDE oʻrnatilgan boʻlsa:

- IDE binar fayli nostandart joylashuvda ekanini tekshiring
- Setup Wizard ishlashda davom etadi — aniqlashdagi muvaffaqiyatsizlik shunchaki nishonchada oʻrnatish yoʻli koʻrsatilmasligini anglatadi

### Handler xatolari (yuqori oqimdan olish muvaffaqiyatsiz)

Agar AgentBridge soʻrovlarni tutib olsa-yu, lekin barcha soʻrovlar muvaffaqiyatsiz tugasa:

3. `OMNIROUTE_BASE_URL` toʻgʻri marshrutizator soʻnggi nuqtasiga ishora qilayotganini tekshiring (standart: `http://127.0.0.1:20128`)

## §8 Yo‘l xaritasi

### Trae’ni o‘rganish

Trae — nisbatan yangi AI kod yozish yordamchisi. Handler’ni amalga oshirishdan oldin:

1. VS Code / JetBrains marketpleyslarida yoki mustaqil ilova sifatida binar fayl/kengaytmani aniqlash
2. API hostlari va endpoint tuzilmalarini aniqlash uchun mitmproxy yordamida trafikni yozib olish
3. Autentifikatsiya mexanizmini aniqlash
4. TOS va API’ni aniqlash imkoniyatiga asoslanib, davom etish yoki etmaslikni baholash

O‘rganish yakunlangunga qadar boshqaruv panelidagi Trae kartasida "Yaroqliligini bildirish" havolasi bilan "O‘rganilmoqda" belgisi ko‘rsatiladi. `src/mitm/handlers/trae.ts` dagi handler zagotovkasi tuzilmaviy `Hali amalga oshirilmagan` xatosini chiqaradi.

### Rejadagi agentlar (MITM talab qilinadi — maxsus asosiy URL’ni qo‘llab-quvvatlamaydi)

Quyidagi vositalarning joriy versiyalari maxsus asosiy URL’larni qo‘llab-quvvatlamaydi, shu sababli MITM trafikni tutib olishning yagona usuli hisoblanadi. Yaroqlilikni baholash kutilmoqda:

- **Windsurf** (Codeium/Cognition)
- **Amp** (Sourcegraph)
- **Amazon Q / Kiro CLI** (AWS Bedrock — Kiro IDE’dan alohida)
- **Cowork** (Anthropic desktop)

Eslatma: GitHub Copilot CLI ≥v1.0.19 `COPILOT_PROVIDER_BASE_URL`’ni qo‘llab-quvvatlaydi — bu vosita uchun MITM o‘rniga bevosita konfiguratsiyadan foydalaning.
