## TLS raqamli iz qatlami

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

Doimiy `wreq-js` seanslari har bir hisob doirasi va aniqlangan proksi uchun zarurat tugʻilganda yaratiladi. Jarayon miqyosidagi `TlsClient` Cloudflare ortidagi yuqori oqim xizmatlari uchun **macOS tizimidagi Chrome 124** sifatida koʻrinadigan koʻpi bilan 128 ta seansni jamlaydi. Mahalliy bajarish muhiti mavjud boʻlmaganda `TlsClient.fetch()` xavfsiz tarzda xato bilan yakunlanadi; chaqiruvchi ushbu oʻramdan tashqarida zaxira variantini aniq tanlashi mumkin.

- Seans profili: `browser: "chrome_124", os: "macos"`
- Proksini aniqlash (ustuvorlik tartibida): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (kichik harfli variantlari ham)
- Taym-aut: `TLS_CLIENT_TIMEOUT_MS` (`FETCH_TIMEOUT_MS` qiymatini meros qilib oladi, standart qiymat 600000)
- `wreq-js` Response fetch bilan mos keladi (`headers`, `text()`, `json()`, `clone()`, `body`).
- Birinchi bayt kuzatuvchisi (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656): yuqori oqim sarlavhalari kelishi bilanoq `TlsClient.fetch()` yakunlanadi, shu sababli faqat `TLS_CLIENT_TIMEOUT_MS` hech qachon birinchi baytni bermaydigan tanani cheklay olmaydi. `guardTlsFirstByte()` tananing birinchi `read()` chaqiruvini `TLS_FIRST_BYTE_WATCHDOG_MS` (standart qiymat `10000`, `0` uni oʻchiradi) bilan poygalashtiradi; sogʻlom tana taʼsirlanmaydi, toʻxtab qolgan tana esa wreq oʻquvchisini bekor qiladi va `proxyFetch` ichidagi mavjud TLS zaxira mantigʻiga bevosita/proksi dispetcheriga oʻtish imkonini beradi (qayta ijro etish xavfsiz boʻlmagan soʻrov, masalan, tanaga ega POST, yashirincha qayta urinish oʻrniga baribir xato chiqaradi).

### Veb-cookie provayder transporti — wreq-js 3.2.0

`open-sse/services/tlsClientBase.ts` quyidagi beshta ixtisoslashtirilgan veb-cookie transporti uchun umumiy adapterdir. Har bir yupqa provayder oʻrami brauzer/OS profilini tanlaydi. Adapter `open-sse/utils/tlsClient.ts` ichidagi yagona wreq bajarish muhiti yuklagichi va transport pulidan foydalanadi; ular profil + OS + aniqlangan proksi boʻyicha kalitlanadi, har bir soʻrov esa `cookieMode: "ephemeral"` dan foydalanadi. Shu sababli hisoblar va soʻrovlar transport darajasidagi ulanishlarni ulashadi, ammo hech qachon wreq seansi yoki cookie omborini ulashmaydi.

| Provayder  | Profil        | Emulyatsiya qilingan OS | Oqim EOF siyosati                     |
| ---------- | ------------- | ----------------------- | ------------------------------------- |
| Claude     | `chrome_146`  | Linux                   | `[DONE]` ni kiritish                  |
| Perplexity | `firefox_148` | macOS                   | `event: end_of_stream` ni kiritish    |
| Grok       | `chrome_146`  | Linux                   | `[DONE]` ni chiqarib tashlash         |
| Notion     | `chrome_146`  | Windows                 | `[DONE]` ni kiritish                  |
| LMArena    | `chrome_146`  | Windows                 | sentinel yoʻq; mahalliy EOF’da yopish |

- Oqim uzatish mahalliy javob `ReadableStream` obyektini toʻgʻridan-toʻgʻri isteʼmol qiladi; vaqtinchalik fayl yoki yordamchi jarayon yaratilmaydi.
- Oqimni taqdim etishdan oldin dastlabki 256 baytgacha boʻlgan qism tekshiriladi. SSE provayderlari SSE boʻlmagan xatolarni buferlaydi; Grok/LMArena Cloudflare tekshiruvlarini `403` ga, HTML oraliq sahifalarini esa `502` ga moslaydi.
- Mahalliy soʻrov taym-auti mutlaq JS qatʼiy muddati bilan oʻralgan holda qoladi. Osilib qolish faqat taʼsirlangan profil/OS/proksi transportini yaroqsiz qiladi va yopadi, keyingi soʻrov esa uni qayta yaratadi.
- Proksini aniqlash ustuvorligi: har bir chaqiruvdagi `proxyUrl` → soʻrov doirasidagi hisob/boshqaruv paneli konteksti → `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (kichik harfli variantlari bilan birga). Aniqlash xatolari bevosita ulanish sizib chiqishiga yoʻl qoʻymasdan, xavfsiz tarzda xato bilan yakunlanadi. LMArena ataylab `arena.ai` ga nisbatan aniqlashni amalga oshiradi.
- `byteResponse` UTF-8 buzilishisiz kontent turi koʻrsatilgan `data:` URL qaytaradi.
- Xatolar: `TlsClientUnavailableError` (paket/addon mavjud emas), `TlsClientHangError` (muddat oshib ketdi) va barcha 128 ta cheklangan profil/OS/proksi uyasi faol yoki yopilayotgan boʻlsa, `WreqTransportCapacityError` (umumiy seans sigʻimi xato kodi).

Yuqoridagi umumiy `TlsClient` seansi brauzer tomonidan qoʻllab-quvvatlanadigan doimiy cookie holati uchun ixtisoslashtirilganligicha qoladi. Har ikkala yoʻl bitta keshlangan wreq modul yuklagichi va jarayon hayot sikli ilgagidan qayta foydalanadi; ularning pullari alohida qoladi, chunki cookie xizmat muddatlari ataylab farqlanadi.

Profillar mahkamlangan paket tomonidan qoʻllab-quvvatlanadi, biroq haqiqiy WAF qabul qilishi mahalliy kontrakt sinovlaridan mustaqil ravishda oʻzgarishi mumkin. Yuqori oqim brauzeri bilan tenglikni daʼvo qilishdan oldin raqamli iz oʻzgarishlarini foydalanishga aniq ruxsat berilgan jonli hisob orqali tekshiring.

## Claude Code yashirinlik toʻplami

`cliCompatMode` yoqilganida, OmniRoute chiquvchi Claude soʻrovlarini `claude-cli` trafigidan ajratib boʻlmaydigan tarzda qayta shakllantiradi. Uchta modul birgalikda ishlaydi:

### `claudeCodeFingerprint.ts`

Billing sarlavhasiga joylashtiriladigan 3 belgili `cc_version` raqamli izini hisoblaydi:

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (kodga qatʼiy yozilgan; rasmiy mijozga mos keladi)
- Kirish maʼlumotlari: birinchi foydalanuvchi xabari matnining 4, 7 va 20-indekslaridagi belgilar + versiya satri
- Chiqish: 3 belgili o‘n oltilik prefiks

### `claudeCodeCCH.ts` (Mijoz kontenti xeshi)

Rasmiy Claude Code CLI Bun/Zig orqali hisoblaydigan server tomonidagi yaxlitlik tekshiruvi. OmniRoute uni `xxhash-wasm` yordamida qayta amalga oshiradi:

1. Asosiy qismni `cch=00000;` toʻldiruvchisi bilan serializatsiya qilish
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. Nol bilan toʻldirilgan, kichik harflardagi 5 belgili o‘n oltilik qiymat
4. `cch=00000;` ni hisoblangan token bilan almashtirish

Konstantalar:

- Boshlangʻich qiymat: `0x6e52736ac806831e`
- Andoza: `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

Yuqori oqim filtrlari ularni grep orqali topa olmasligi uchun “sezgir” mijoz nomlarining birinchi belgisidan keyin Unicode **nol kenglikdagi birlashtiruvchi** (`U+200D`) belgisini kiritadi. Standart soʻzlar roʻyxati:

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

Quyidagilarga qoʻllanadi: `system` bloklari, barcha `messages[].content` hamda `tools[].description` / `tools[].function.description`. Operator `setSensitiveWords()` orqali buni oʻzgartirishi mumkin.

### `claudeCodeCompatible.ts` — `anthropic-compatible-cc-*` provayderlari

Faqat “haqiqiy Claude Code” trafigini qabul qiladigan uchinchi tomon Anthropic reley serverlari uchun:

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.258 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- Standart holatda `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"`
- Har bir ulanish uchun “Enable redact-thinking beta” tugmasi, CC Compatible yuqori oqimi aynan tahrirlangan fikrlash oqimlarini talab qilganida, `redact-thinking-2026-02-12` ni qoʻshadi
- Har bir ulanish uchun “Enable summarized thinking display” tugmasi `providerSpecificData.requestDefaults.summarizeThinking` qiymatini saqlaydi va koʻrsatish rejimi avvaldan belgilanmagan CC Compatible fikrlash soʻrovlariga `display: "summarized"` ni qoʻshadi
- `CONTEXT_1M_BETA_HEADER = "context-1m-2025-08-07"` (Opus/Sonnet 4.x oilasi)
- Standart yoʻl: `/v1/messages?beta=true`

Shu toʻplamdagi yordamchi modullar:

- `claudeCodeConstraints.ts` — harorat + keshni boshqarish qoidalari
- `claudeCodeToolRemapper.ts` — vosita nomlarini qayta moslashtirish
- `claudeCodeExtraRemap.ts` — qoʻshimcha foydali yukni meʼyorlashtirish

## Antigravity yashirinligi

Antigravity soʻrovlari chaqiruvchi matnini baytma-bayt saqlaydi. OmniRoute IDE mijoziga taqlid qilish uchun promptlarga nol kenglikdagi belgilarni kiritmaydi yoki vositalarni qayta nomlamaydi/kiritmaydi.

### `antigravityHeaderScrub.ts`

Yoʻnaltirishdan oldin Stainless SDK belgilarini (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`) olib tashlaydi.

### ⚠️ Xavf: `ANTIGRAVITY_CREDITS=always` (hisob bloklanishi uchun eng xavfli nuqta)

`ANTIGRAVITY_CREDITS=always` (`open-sse/executors/antigravity.ts` tomonidan ishlatiladi) Google’ning bepul tarif kvotasi soʻrovlarni cheklashiga yoʻl qoʻyish oʻrniga **har bir** soʻrovni Antigravity AI Credit Overages (Google’ning pulli kreditlari) orqali yoʻnaltiradi. Bu imkoniyat sifatida hujjatlashtirilgan, ammo u **biz koʻradigan Xizmat koʻrsatish shartlari buzilishi haqidagi xabarlarning eng keng tarqalgan yagona sababidir** — bir nechta Google Ultra hisobi `=always` bilan bir necha soat ishlaganidan soʻng `403 / "service disabled for ToS violation" / insufficient_quota` xatosi bilan bloklangan.

Yuqori oqimdagi nazorat **Google tomonida** amalga oshiriladi va OmniRoute buning oldini ola olmaydi. Muhit oʻzgaruvchisining nomi va mavjud hujjatlar uni yoqish xavfsizdek koʻrsatadi; aslida esa bunday emas.

**Nega bu faqat bepul tarifdan foydalanishga qaraganda suiisteʼmolni aniqlash tizimlarini faolroq ishga tushiradi:**

- Bitta Google hisobidan davomli avtomatlashtirilgan xarajat bepul tarifning kvotaga yetib, toʻxtab qolishidan boshqacha belgilanishiga sabab boʻladi.
- Ortiqcha kreditlar uchun tezlik chegarasi yoʻq, shu sababli notoʻgʻri sozlangan mijoz bir necha daqiqada bir necha yuz USD sarflashi va API kalitlarini qayta sotish yoki bot trafigiga oʻxshab koʻrinishi mumkin.
- Bir xil tashqi IP manzildan parallel ravishda ortiqcha kreditlardan foydalanayotgan bir nechta OmniRoute foydalanuvchisi signalni kuchaytiradi.

**Tavsiya etiladigan yondashuv:**

1. Operator pulli kreditlar va hisobga nisbatan choralar koʻrilishi xavfini aniq qabul qilmasa, standart `ANTIGRAVITY_CREDITS=off` holatini saqlang. `retry` avval odatiy soʻrovni yuboradi va mos keluvchi kvota 429 xatosidan keyin kreditlarni koʻpi bilan bir marta kiritadi; `always` esa kreditlarni birinchi soʻrovdayoq kiritadi.
2. Bitta Antigravity hisobini haddan tashqari yuklash oʻrniga **Auto-Combo orqali yukni provayderlar boʻylab taqsimlang** (`model: "auto"` yoki `kr/glm/etc`-combo).
3. Antigravity provayderining tahrirlash sahifasida **har bir ulanish uchun RPM chegaralarini belgilang** (Dashboard → Providers → Antigravity → ulanish → tezlik chegarasi). Uzoq muddatli foydalanish uchun 30–60 RPM asosli yuqori chegara hisoblanadi.
4. **Barqaror, operator nazoratidagi yuqori oqim tarmogʻidan foydalaning** va bitta hisobni bir-biriga aloqasiz foydalanuvchilar yoki ish yuklari oʻrtasida ulashishdan saqlaning.
5. **Agar bloklansa**: Google yuborgan aniq `quota_exceeded` / `service disabled` javob tanasi bilan `support.google.com` → “Restore Workspace/Account access” orqali apellyatsiya yuboring. Hisobning tiklanishi kafolatlanmaydi.

Muhit maʼlumotnomasida har bir kredit rejimining hisob va xarajatga taʼsiri hujjatlashtirilgan.

Tegishli nuqtalar:

- `open-sse/executors/antigravity.ts` — `process.env.ANTIGRAVITY_CREDITS` ni oʻqiydi
- `src/lib/oauth/providers/antigravity.ts` — hisob maʼlumotlarini ulash
- Dastlabki hodisa hisoboti: Muhokama [#1183](https://github.com/diegosouzapw/OmniRoute/discussions/1183)

## CLI barmoq izi reyestri — `open-sse/config/cliFingerprints.ts`

Rasmiy CLI’larning mitmproxy izlaridan olingan sarlavhalarning **aniq** tartibi va JSON tanasi maydonlarining tartibini belgilaydigan har bir provayder uchun jadval. Hozirda roʻyxatdan oʻtganlar: `codex`, `claude`, shuningdek, `antigravity` va `github` uchun `providerHeaderProfiles.ts` ichida bajarilish vaqtida hosil qilinadigan profillar.

```ts
interface CliFingerprint {
  headerOrder: string[]; // katta-kichik harflarga sezgir
  bodyFieldOrder: string[]; // yuqori darajadagi JSON kalitlari
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

Har bir provayder uchun env orqali yoqing yoki oʻchiring (quyiga qarang). Oʻchirilganda, sarlavhalar/tana kalitlari Node/JSON ularni taqdim etgan tartibda paydo boʻladi — barmoq izini aniqlash osonlashadi.

## MITM proksi (Antigravity, Linux/macOS/Windows)

Binar fayllarini `OPENAI_BASE_URL` orqali qayta yoʻnaltirib boʻlmaydigan CLI’lar uchun OmniRoute TLS’ni yakunlovchi mahalliy proksini ishga tushiradi. Endpointlar `src/app/api/cli-tools/antigravity-mitm/` ichida joylashgan.

| Metod  | Endpoint                                | Maqsad                                                             |
| ------ | --------------------------------------- | ------------------------------------------------------------------ |
| GET    | `/api/cli-tools/antigravity-mitm`       | Holat — ishlayapti, pid, dnsConfigured, certExists                 |
| POST   | `/api/cli-tools/antigravity-mitm`       | MITM’ni ishga tushirish (`apiKey` + `sudoPassword` talab qilinadi) |
| DELETE | `/api/cli-tools/antigravity-mitm`       | MITM’ni toʻxtatish                                                 |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | Model taxalluslarini roʻyxatlash                                   |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | Vosita uchun model taxalluslarini saqlash                          |

Ushlab qolinadigan maqsadli host: **`daily-cloudcode-pa.googleapis.com`** (Antigravity’ning yuqori oqim serveri).

### Ishga tushirish ketma-ketligi (`src/mitm/manager.ts::startMitm`)

1. `selfsigned` orqali oʻzi imzolagan sertifikatni yarating (RSA-2048, SHA-256, 1 yil) — `cert/generate.ts`
2. Sertifikatni tizimning ishonchli sertifikatlar omboriga oʻrnating — `cert/install.ts`
3. Hosts yozuvini qoʻshing: `127.0.0.1 daily-cloudcode-pa.googleapis.com` — `dns/dnsConfig.ts`
4. `ROUTER_API_KEY` + `MITM_LOCAL_PORT` (standart qiymat `443`) bilan `src/mitm/server.cjs` jarayonini ishga tushiring
5. PID’ni `<DATA_DIR>/mitm/.mitm.pid` manziliga saqlang

### Linux’da dinamik ishonchli sertifikatlar omborini aniqlash — `cert/install.ts`

`getLinuxCertConfig()` ustuvorlik roʻyxatini koʻrib chiqadi va mavjud boʻlgan birinchi katalogni tanlaydi:

| Distributiv oilasi       | Katalog                                     | Yangilash buyrugʻi       |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

Sertifikat fayli nomi: `omniroute-mitm.crt`. Barmoq izi `getCertFingerprint()` orqali moslashtiriladi (DER’ning SHA-1 xeshi).

Bundan tashqari, `certutil` mavjud boʻlganda, `updateNssDatabases()` har bir foydalanuvchining NSS maʼlumotlar bazalariga oʻrnatadi: `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, barcha Firefox profillari (jumladan snap), **`OmniRoute MITM Root CA`** taxallusi ostida.

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** yuqori huquqli PowerShell → `certutil -addstore Root`

### Autentifikatsiya

Barcha MITM endpointlari boshqaruv autentifikatsiyasini (`requireCliToolsAuth`) talab qiladi. Sudo paroli modul doirasida keshlanadi (hech qachon `globalThis` ichida emas) va `stopMitm()` chaqirilganda tozalanadi.
