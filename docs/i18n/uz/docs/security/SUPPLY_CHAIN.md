OmniRoute npm + Docker artefaktlarini eʼlon qiladi. Ushbu nazorat darvozalari kelib chiqish maʼlumotlari,
inventarizatsiya (SBOM) va CVE skanerlashni taʼminlaydi; ularning barchasi OSS bo‘lib, reliz ish jarayonlariga ulangan.
**Avval tavsiya** yondashuvi — ular hozircha hisobot beradi va birinchi
muvaffaqiyatli relizdan so‘ng bloklovchi rejimga o‘tkaziladi.

| Nazorat darvozasi         | Vosita                                         | Qayerda                              | Bloklaydimi?                              | Natija                                                                       |
| ------------------------- | ---------------------------------------------- | ------------------------------------ | ----------------------------------------- | ---------------------------------------------------------------------------- |
| SLSA kelib chiqishi (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`                    | faqat eʼlon qilish muvaffaqiyatsiz bo‘lsa | npmjs belgisi / `npm audit signatures`                                       |
| SBOM npm                  | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`                    | faqat yaratish muvaffaqiyatsiz bo‘lsa     | Reliz resursi + artefakt                                                     |
| SBOM tasviri              | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (birlashtirish) | tavsiya xarakterida                       | CycloneDX artefakti                                                          |
| Trivy CVE (SARIF)         | `aquasecurity/trivy-action`                    | `docker-publish.yml` (birlashtirish) | tavsiya xarakterida                       | SARIF (HIGH+CRITICAL) → Xavfsizlik varag‘i                                   |
| Trivy CRITICAL darvozasi  | `aquasecurity/trivy-action`                    | `docker-publish.yml` (birlashtirish) | **bloklovchi**                            | Tuzatilishi mumkin bo‘lgan CRITICAL uchun `exit-code: '1'`                   |
| osv vulnCount             | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`)        | **bloklovchi**                            | `metrics.vulnCount` qiymatini bosqichma-bosqich cheklaydi (`direction:down`) |
| OpenSSF Scorecard         | `ossf/scorecard-action`                        | `scorecard.yml` (cron)               | tavsiya xarakterida                       | SARIF → Xavfsizlik + belgi                                                   |

Tasvirdagi CVE qiymatini bosqichma-bosqich cheklash `docker-publish.yml` ichida **ikki bosqichdan** foydalanadi: SARIF bosqichi
(`HIGH,CRITICAL`, `exit-code: 0`) HIGH+CRITICAL muammolarini Xavfsizlik varag‘ida
bloklamasdan ko‘rinadigan holatda saqlaydi; _CRITICAL darvozasi_ bosqichi (`severity: CRITICAL`, `ignore-unfixed: true`,
`exit-code: 1`) **tuzatish mavjud bo‘lgan** CRITICAL CVE aniqlansa, relizni muvaffaqiyatsiz qiladi. `ignore-unfixed`
yuqori oqim yamog‘i mavjud bo‘lmagan asosiy tasvir CVEsi tufayli reliz bloklanishining oldini oladi.

## ⚠️ CVE o‘zgaruvchanligi (bloklovchi osv/Trivy darvozalari)

osv va Trivy bog‘liqliklarni **doimiy ravishda kengayib boradigan** CVE maʼlumotlar bazalari bilan taqqoslaydi. **Hech qanday bog‘liqlikka
tegmaydigan** PR mavjud bog‘liqlikda yangi CVE oshkor qilingani sababli kutilmaganda qizil holatga o‘tishi mumkin
(osv: o‘lchangan `vulnCount` > bazaviy qiymat; Trivy: tasvirda tuzatilishi mumkin bo‘lgan yangi
CRITICAL). **Bu bloklovchi CVE darvozasining KUTILGAN operatsion xatti-harakati bo‘lib,
mahsulot regressiyasi emas.**

Yangi oshkor qilingan CVE sababli osv yoki Trivy qizil holatga o‘tsa, yechim quyidagicha:

1. **Taʼsirlangan bog‘liqlik versiyasini oshiring** (afzal) — `package.json` ichidagi
   `overrides` orqali yamalgan versiyaga yangilang (tranzitiv bog‘liqliklar) yoki tasvirni yamalgan asosdan qayta yarating.
2. **Agar yuqori oqimda tuzatish bo‘lmasa:**
   - **osv:** `config/quality/quality-baseline.json` ichidagi `metrics.vulnCount` uchun yangi bazaviy qiymat belgilang
     (`npm run quality:ratchet -- --update` maxsus darvozalarni qamrab olmaydi — qiymatni
     asoslovchi izoh + kuzatuv muammosi bilan qo‘lda tahrirlang, `direction:down`).
   - **Trivy:** `.trivyignore` fayliga asoslovchi izoh + kuzatuv muammosi bilan yozuv
     qo‘shing (har bir qatorda CVE-ID). `ignore-unfixed: true` yamog‘i mavjud bo‘lmagan
     CVElarni allaqachon avtomatik ravishda qamrab oladi.

Vosita mavjud bo‘lmasa yoki o‘lchash muvaffaqiyatsiz tugasa
(osv-scanner PATH ichida yo‘q, osv.dev/tarmoq bilan bog‘lanib bo‘lmaydi, JSON noto‘g‘ri), ikkala darvoza ham **muammosiz SKIP qiladi**
(exit 0) — **o‘lchashdagi** xato hech qachon bloklamaydi, faqat **o‘lchangan** regressiya bloklaydi.

## Rejalar: Scorecard tavsiya rejimidan → bloklovchi rejimga

Scorecard hisobotiga ega birinchi muvaffaqiyatli relizdan so‘ng:

- Scorecard: ballni bosqichma-bosqich cheklash (o‘lchangan ballni qotirib qo‘yadi; u pasaya olmaydi).

7-bosqich darvozalarini (osv-scanner, gitleaks, actionlint+zizmor) to‘ldiradi: zizmor
ish jarayonlarining o‘zini audit qiladi; Scorecard esa repozitoriyning umumiy holatini o‘lchaydi.
