Ushbu hujjat `omniroute@3.8.5` bo‘yicha qayd etilgan oltita
`AI-detected potential malware` topilmasi va `omniroute@3.8.6` da qo‘llangan
yumshatish choralari uchun loyiha kuzatuvchisi tomonidan yozilgan attestatsiyadir. Uning maqsadlari:

1. Xavfsizlik konveyeri operatorlari topilmalarni haqiqiy manba kodi bilan
   solishtirib baholashlari kerak bo‘lganda havola qilishlari uchun yagona manbani taqdim etish.
2. Kelajakdagi AI skanerlari belgilangan har bir yo‘l ataylab yaratilgani,
   faqat foydalanuvchi roziligi bilan ishga tushishi va hujjatlashtirilgani haqidagi
   loyiha kuzatuvchisi imzolagan bayonotni aniqlay olishi.
3. Har bir chaqiruv joyi _nima uchun_ aynan shunday tuzilganining yozma qaydiga ega bo‘lish —
   toki kelajakdagi refaktoring ataylab olib tashlangan raqamli izni
   tasodifan qayta kiritmasin.

Agar v3.8.6 yumshatish choralari chiqarilganidan keyin quyidagi chaqiruv
joylaridan birortasi skaneringiz tomonidan yana belgilansa, skanerlash trassasi bilan muammo oching,
biz esa bu attestatsiyani shu yerda kengaytiramiz.

## §1 — MITM ildiz CA sertifikatini o‘rnatish (`77484.js`)

**Manba fayllari**:

- `src/mitm/cert/install.ts` — ochiq `installCert()` / `uninstallCert()`,
  har bir platformaga xos `installCertWindows/Mac/Linux`.
- `src/mitm/systemCommands.ts` — o‘rnatish yo‘llari foydalanadigan umumiy `execFile` / `spawn` / PowerShell
  yordamchi funksiyalari.

**Ishga tushirish sharti**: foydalanuvchi mahalliy boshqaruv panelidagi
`/dashboard/cli-tools/mitm` sahifasida "MITM proksisini yoqish" tugmasini bosadi. Bu marshrut faqat loopback orqali ishlaydi —
`CLAUDE.md` faylidagi 17-qat’iy qoida va `src/server/authz/routeGuard.ts::isLocalOnlyPath()` ga
qarang. Tunnel orqali oshkor bo‘lgan JWT bu kod yo‘lini ishga tushira
**olmaydi**.

**Bajariladigan imtiyozli amallar (platformalar bo‘yicha)**:

| OT                     | Buyruq(lar)                                                                                                       |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | UAC orqali `certutil -addstore Root <cert>`                                                                       |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | `certutil -d sql:<profile>` orqali har bir profil uchun NSS DB yangilanishi                                       |

Bular `mitmproxy`, Charles Proxy, Fiddler va Caddy ishlatadigan buyruqlarning
o‘zidir. Ularning OmniRoute tarkibida mavjudligi
`docs/security/STEALTH_GUIDE.md` da hujjatlashtirilgan.

**v3.8.6 yumshatish chorasi**:

- `runElevatedPowerShell()` endi `-EncodedCommand <base64utf16le>` dan foydalanmaydi.
  Yuqori huquqli bajariladigan kod har bir chaqiruv uchun vaqtinchalik `.ps1` fayliga yoziladi (0o600 rejimida,
  xususiy `mkdtempSync` katalogi ichida) va unga `-File` orqali murojaat qilinadi.
  Fayl `finally` ichida o‘chiriladi. Bu Socket.dev AI
  klassifikatori belgilagan PowerShell orqali base64-kodlangan yuqori huquq olishga xos klassik raqamli izni olib tashlaydi.
- `installCertWindows` shu yerga yo‘naltiruvchi ichki `SECURITY-AUDITOR-NOTE:` blokini
  o‘z ichiga oladi.

**Nega uni saqlab qolamiz**: MITM proksisi
`docs/security/STEALTH_GUIDE.md` va `docs/frameworks/MITM-PROXY.md` da ishlatiladigan hujjatlashtirilgan funksiyadir. Uni olib tashlash
agent-ko‘prik funksiyalari to‘plamini buzadi.

## §2 — Zed hisob ma’lumotlarini import qilish (`app/api/providers/zed/import/route.js`)

**Manba fayllar**:

- `src/app/api/providers/zed/discover/route.ts` _(v3.8.6 da yangi)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(v3.8.6 da yangi)_

**Ishga tushirish sharti**: foydalanuvchi lokal boshqaruv panelining Provayderlar
sahifasida «Zed’dan import qilish» tugmasini bosadi. Endpoint `requireManagementAuth`
bilan himoyalangan. Zed muharririning o‘zi provayder API kalitlarini hujjatlashtirilgan
xizmat nomlari ostida operatsion tizim kalitlar zanjiriga yozadi — qarang:
https://zed.dev/docs/ai/llm-providers.

**v3.8.5 dagi xatti-harakat (Socket.dev belgilagan holat)**:

`POST /import` hisob ma’lumotlarini topib, ularni bitta so‘rov-javob jarayonida
lokal SQLite omboriga avtomatik ravishda saqlardi. Har bir hisob uchun tasdiqlash
ham, raqamli iz ham yo‘q edi — shunchaki «N ta token topildi, barchasi import qilindi».

**v3.8.6 dagi xavfni kamaytirish chorasi — 2 bosqichli tasdiqlash**:

1. **`POST /api/providers/zed/discover`**
   `{ candidates: [{ provider, service, account, fingerprint }] }` ni qaytaradi. Xom
   token **hech qachon** uzatilmaydi. Raqamli iz:
   `sha256(service|account|token).slice(0,16)`.
2. Boshqaruv paneli nomzodlar ro‘yxatini ko‘rsatadi, operator import qilinadiganlarini
   tanlaydi va `{ confirmedAccounts: [{ service, account, fingerprint }] }` ni
   **`POST /api/providers/zed/import`** ga yuboradi.
3. Import endpointi **serverdagi kalitlar zanjirini qayta o‘qiydi** va
   `(service, account, fingerprint)` bo‘yicha filtrlaydi. O‘zgartirilgan yoki qayta
   yuborilgan aniqlash javobi import endpointini aloqasi bo‘lmagan tokenni saqlashga
   majbur qila olmaydi — agar joriy token aniqlashdan keyin o‘zgargan bo‘lsa, raqamli
   iz endi mos kelmaydi va hisob ma’lumoti o‘tkazib yuboriladi.

`OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` muhit bayrog‘i avtomatlashtirish
jarayonlarini hali yangilamagan operatorlar uchun v3.8.5 dagi xatti-harakatni
saqlab qoladi. U v3.9 da olib tashlanadi.

**Nega uni saqlab qolamiz**: Zed importi Zed’dan allaqachon foydalanadigan va
provayder kalitlarini qayta kiritmasdan OmniRoute’ga ko‘chirmoqchi bo‘lgan
foydalanuvchilar uchun eng qulay boshlang‘ich sozlash usulidir.

## §3 — `execFile` / `spawn` / yuqori huquqli PowerShell (`21843.js`)

**Manba fayllar**: `src/mitm/systemCommands.ts`.

**Nega belgilangan**: chunk `execFileWithPassword`,
`runElevatedPowerShell` va umumiy `quotePowerShell` yordamchi funksiyasini qayta
eksport qiladi. Socket.dev’ning sun’iy intellekt klassifikatori ularni umumiy
«xostda bajarish + imtiyozlarni oshirish vositalari to‘plami» sifatida ko‘radi.
OmniRoute ichida ular faqat MITM sertifikatini o‘rnatish yo‘lida (§1) hamda
`sudo` buyruqlarini bajarish uchun `execFileWithPassword` tomonidan ishlatiladi.

**v3.8.6 dagi xavfni kamaytirish choralari**:

- `runElevatedPowerShell` refaktoringi (qarang: §1).
- `runElevatedPowerShell` va `execFileWithPassword` yonidagi ichki
  `SECURITY-AUDITOR-NOTE:` bloklari ruxsat etilgan chaqiruvchilar va qat’iy
  belgilangan bajariluvchi fayllar ro‘yxatini hujjatlashtiradi.
- `execFileWithPassword` ichidagi `spawn()` chaqiruvi yordamchi funksiya qabul
  qilishi mumkin bo‘lgan bajariluvchi fayllarning ruxsat etilgan ro‘yxati bilan
  `nosemgrep` belgisiga ega — foydalanuvchi kiritgan ma’lumotlardan
  `finalCommand`/`finalArgs` ga olib boruvchi **hech qanday yo‘l yo‘q**.

## §4 / §6 — 9router xizmat nazoratchisi (`api/services/9router/{start,restart}/route.js`)

**Manba fayllar**:

- `src/app/api/services/9router/_lib.ts` — nazoratchi fabrikasi.
- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`.
- `src/lib/services/ServiceSupervisor.ts` — umumiy spawn / holatni tekshirish / jurnal buferi.

**Ishga tushirish sharti**: foydalanuvchi lokal boshqaruv panelidagi o‘rnatilgan
xizmatlar sahifasida «O‘rnatish» / «Ishga tushirish» tugmasini bosadi.

**Avvaldan mavjud himoya choralari**:

- Barcha `/api/services/*` marshrutlari
  `src/server/authz/routeGuard.ts` ga ko‘ra LOCAL_ONLY hisoblanadi (qat’iy
  qoida #17). Loopback nazorati har qanday autentifikatsiya tekshiruvidan oldin
  amalga oshiriladi — sizib chiqqan JWT ham ularga kira olmaydi.
- 9router ma’lumotlar bazasi qatori `status='not_installed', auto_start=0`
  qiymatlari bilan boshlang‘ich tarzda yaratiladi (qarang:
  `src/lib/db/migrations/071_services.sql:19`). Xizmat birinchi ishga tushirishda
  **ishga tushmaydi**.
- `spawn()` `src/lib/services/installers/ninerouter.ts` ichidagi
  `resolveSpawnArgs(apiKey, PORT)` qaytargan ikkilik fayl yo‘li bilan chaqiriladi;
  bu qo‘llab-quvvatlanadigan ikkilik fayllarning qat’iy ruxsat etilgan ro‘yxatidir.
- Stdout/stderr xotirada buferlanadi (5 MB cheklov, qarang: `_lib.ts`) — foydalanuvchi
  boshqaruv panelidan jurnal yuritishni yoqmaguncha diskka hech narsa yozilmaydi.

**v3.8.6 dagi xavfni kamaytirish chorasi**: funksional o‘zgarish yo‘q. Minimal
yig‘ish profili (`OMNIROUTE_BUILD_PROFILE=minimal`) imtiyozli yo‘llarni to‘plamdan
jismonan olib tashlashni istagan foydalanuvchilar uchun
`src/lib/services/installers/ninerouter.ts` faylini stub bilan almashtiradi.

**Nega uni saqlab qolamiz**: 9router — ixtiyoriy ravishda lokal o‘rnatiladigan
hamroh xizmat (WordPress uslubidagi plagin kabi) bo‘lib, undan foydalanish uchun
qat’iy ravishda aniq rozilik talab etiladi.

## §5 — OmniRoute Cloud Sync hisob maʼlumotlarini qayta yozish (`api/keys/[id]/route.js`)

**Manba fayllar**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`.
- `src/app/api/keys/[id]/route.ts` — `syncKeysToCloudIfEnabled()` funksiyasini chaqiradi.

**Ishga tushish sharti**: `isCloudEnabled()` `true` qiymatini qaytaradi (boshqaruv panelidan sozlanadi) **va**
`CLOUD_URL` sozlangan. Ikkalasi ham o‘chirilgan bo‘lsa, Cloud endpoint’iga
hech qanday chiquvchi tarmoq so‘rovi yuborilmaydi.

**v3.8.5 xatti-harakati (Socket.dev to‘g‘ri aniqlagan xato)**:

`cloudUpdatedAt > localUpdatedAt` bo‘lganda, `updateLocalTokens()` Cloud
javobidagi `accessToken`, `refreshToken` va `providerSpecificData`
qiymatlari bilan mahalliy qiymatlarni qayta yozardi. HMAC ham, imzo ham,
nazorat summasi ham yo‘q edi. Noto‘g‘ri sozlangan yoki zararli `CLOUD_URL`
(yoki kanaldagi MITM) provayderning OAuth tokenlarini sezdirmasdan
almashtirishi mumkin edi.

**v3.8.6 himoya chorasi**:

1. **HMAC tekshiruvi**: `verifyCloudSignature(rawBody, sigHeader)` JSON’ni
   tahlil qilishdan oldin `X-Cloud-Sig` sarlavhasini
   (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET, rawBody)`) tekshiradi. Maxfiy
   kalit o‘rnatilgan bo‘lsa, imzo majburiydir. Aks holda (eskirgan rejimda)
   ogohlantirish jurnalga yoziladi va javob qabul qilinadi — v3.9 versiyasidan
   boshlab maxfiy kalit majburiy bo‘ladi.
2. **Maxfiy maydonlarni ixtiyoriy yoqish**: `accessToken` / `refreshToken` /
   `providerSpecificData` qiymatlari **faqat**
   `OMNIROUTE_CLOUD_SYNC_SECRETS=true` bo‘lganda qayta yoziladi. Standart
   rejimda faqat hisob maʼlumotlari bo‘lmagan metamaʼlumotlar (`expiresAt`,
   `status`, `lastError*`, `rateLimitedUntil`, `updatedAt`) sinxronlanadi.
   Bu masofaviy token sinxronlashiga tayangan foydalanuvchilar uchun
   **moslikni buzuvchi o‘zgarish** — ular bu imkoniyatni aniq yoqishlari kerak.

**Nega uni saqlab qolamiz**: Cloud Sync — OmniRoute Cloud ijarachisi uchun
jamoa hisob maʼlumotlarini markazlashtirishning yagona usuli. Tuzatish
tahdid modelini aniq qiladi: «server imzolaydi, mijoz tekshiradi, operator
ixtiyoriy ravishda yoqadi».

## Qurish profili: `minimal`

Socket’ga mos artefakt kerak bo‘lgan foydalanuvchilar quyidagi buyruq bilan
qurishlari mumkin:

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

webpack `NormalModuleReplacementPlugin` orqali to‘rtta modulni stub’larga
yo‘naltiradi:

| Modul                                       | Stub                                             |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

Har bir stub ayni interfeysni eksport qiladi, biroq har bir funksiya bajarilish
vaqtida `featureDisabledError(name)` xatosini chiqaradi. O‘chirilgan modulga
bog‘liq marshrutlar sezgir kod yo‘lini faollashtirish o‘rniga aniq xabar bilan
HTTP 503 javobini qaytaradi.

Hosil bo‘lgan to‘plam `omniroute-secure` sifatida eʼlon qilish uchun
mo‘ljallangan. Eʼlon qilish tartibi uchun `docs/ops/PUBLISHING_SECURE.md`
fayliga qarang.

## Plaginni ajratish (v4 uchun kuzatilmoqda)

Uzoq muddatli istiqbolda npm paketini alohida audit qilinadigan modullarga
ajratmoqchimiz. Kuzatuv masalasi uchun GitHub muammolar kuzatuvchisidagi v4 bosqichiga
qarang.
