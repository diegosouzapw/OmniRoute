## 1. Antigravity va Antigravity CLI (agy) taqqoslanishi

Har ikkala provayder ham **bir xil Google backend tizimidan** foydalanadi — OAuth mijozi, tokenni yangilash, endpointlar va Google hisoblari bir xil. Farq sizga qaysi modellar koʻrsatilishidadir.

> Googlening rasmiy taqqoslashini [Antigravity CLI eʼloni](https://antigravity.google/blog/introducing-google-antigravity-cli) sahifasida koʻring.

| Jihat                           | `antigravity` (IDE)                                          | `agy` (CLI)                                                              |
| ------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------ |
| **Google mahsuloti**            | Antigravity 2.0 / Antigravity IDE                            | Antigravity CLI                                                          |
| **Backend**                     | Xuddi shu Google Cloud Code API                              | Xuddi shu Google Cloud Code API                                          |
| **OAuth / Token**               | Xuddi shu mijoz, xuddi shu yangilash mexanizmi               | Xuddi shu mijoz, xuddi shu yangilash mexanizmi                           |
| **Modellar katalogi**           | Statik saralangan roʻyxat (OmniRoute ichiga qatʼiy yozilgan) | Google orqali `:fetchAvailableModels` yordamida real vaqtda tekshiriladi |
| **Claude modellari**            | Sonnet 4.6, Opus 4.6 (har biri 4 ta variantda)               | Sonnet 4.6, Opus 4.6 (har biri 4 ta variantda)                           |
| **Gemini nomlanishi**           | Sodda yorliqlar (Low/Medium/High)                            | Yuqori oqim identifikatorlari (extra-low/low/agent)                      |
| **Qoʻshimcha modellar**         | `gpt-oss-120b-medium`                                        | Googledan qoʻshimcha modellarni ham oʻz ichiga olishi mumkin             |
| **Standart foydalanish holati** | IDE integratsiyasi (VS Code, JetBrains)                      | CLI / API orqali foydalanish                                             |
| **Kvota**                       | agy bilan umumiy (bir xil Google hisobi)                     | antigravity bilan umumiy (bir xil Google hisobi)                         |

**Mavjud modellar (tajriba orqali tasdiqlangan, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (turli fikrlash darajalari)
- Claude: Sonnet 4.6, Opus 4.6 (har biri default/low/medium/high variantlari bilan)
- Boshqalar: GPT-OSS 120B Medium
- **Claude Sonnet 5 mavjud EMAS** — faqat 4.6 variantlari qoʻllab-quvvatlanadi

**Modellar katalogi nega farq qiladi**: Googlening CLI vositasi (Googlening rasmiy blogiga koʻra) «tezlik va kam resurs sarfi uchun optimallashtirilgan» hamda «Gemini modellari bilan birgalikda optimallashtirilgan». Web/IDE mahsuloti esa «keng qamrovlilik uchun optimallashtirilgan». CLI modellarni dinamik ravishda aniqlash uchun `:fetchAvailableModels` dan foydalanadi, IDE esa statik saralangan roʻyxatdan foydalanadi.

**Amalda**: Gemini modellari uchun `agy/` prefiksidan foydalaning (masalan, `agy/gemini-3.7-flash-high`). Statik saralangan roʻyxat uchun `antigravity/` dan foydalaning. Har ikkisi ham bir xil Google backend tizimiga murojaat qiladi, ammo model nomlarini turlicha taqdim etadi. Kvota umumiy — istalgan provayderdan foydalanish ayni Google hisobining limitlariga hisoblanadi.

## 2. Google One AI Pro: Kvota tizimi

> Rasmiy kvota tafsilotlari uchun [Antigravity hujjatlari: Tariflar](https://antigravity.google/docs/plans), narxlardagi soʻnggi yangilanishlar uchun esa [Antigravity tariflaridagi oʻzgarishlar](https://antigravity.google/blog/changes-to-antigravity-plans) sahifasiga qarang.

Google Antigravity xabarlar soniga emas, balki “Bajarilgan ish”ga (hisoblash ogʻirligiga) asoslangan **ikki qatlamli kvota**dan foydalanadi.

### Ikki qatlam

| Qatlam                    | Bu nima                               | Yangilanish davri                                                                                   |
| ------------------------- | ------------------------------------- | --------------------------------------------------------------------------------------------------- |
| **5 soatlik sprint**      | Bevosita “bajarilgan ish” jamgʻarmasi | Seansdagi birinchi soʻrovdan 5 soat oʻtgach qayta tiklanadi                                         |
| **7 kunlik asosiy limit** | Haftalik qatʼiy cheklov               | Unga yetilsa, 5 soatlik yangilanishni bekor qiladi va keyingi 7 kunlik davrgacha kirishni bloklaydi |

**“Bajarilgan ish” qanday hisoblanadi**: Agentdan faol foydalanadigan vazifalar (masalan, “Bu butun repozitoriyni refaktor qiling”) kvotani oddiy vazifalarga (masalan, “Bu funksiyani tuzating”) qaraganda ancha tez sarflaydi. Sarfni koʻrsatadigan real vaqt boshqaruv paneli mavjud emas.

### Tarif darajalari

| ------------ | ---------- | -------------------------------------------------------- | ------------------------------------------------------- |
| Free         | $0         | Yetarli kvota, har hafta yangilanadi                     | Ha                                                      |
| AI Pro       | $19.99/oy  | Yuqori kvota, har 5 soatda bosqichma-bosqich yangilanadi | Ha (unga yetilsa, 5 soatlik yangilanishni bekor qiladi) |

### Gemini va Gemini boʻlmagan modellar

- **Gemini modellari** (Flash + Pro): API narxlari asosida sarflanadigan yagona tezlik cheklovini boʻlishadi. Agar Flash Pro’dan 8x arzon boʻlsa, siz 8x koʻproq Flash tokenlariga ega boʻlasiz.
- **Gemini boʻlmagan modellar** (Claude, GPT-OSS): **Alohida** tezlik cheklovlariga ega. Hatto Gemini bloklanganida ham ulardan foydalanish mumkin boʻlishi mumkin.

### AI kreditlari (Limitdan ortiq foydalanish)

> Kreditlar qanday ishlashi haqida maʼlumot olish uchun [Google One AI kreditlari](https://support.google.com/googleone/answer/14534406) sahifasiga qarang.

Asosiy kvota tugaganda:

- **Hech qachon**: Kvota yangilanishini kutadi; “Asosiy model kvotasiga yetildi” xabarini koʻrsatadi
- **Har doim**: AI kreditlaridan avtomatik foydalanadi; asosiy kvota yangilanganda unga qaytadi

Kreditlar alohida sotib olinadi va standart API narxlari boʻyicha yechib olinadi.

### Muhim tafsilotlar

- Kvota **hisob darajasida umumiy** — Antigravity IDE, CLI va OmniRoute’da ayni bir Google hisobi bitta kvota jamgʻarmasidan foydalanadi
- Har bir Google hisobi oʻzining mustaqil kvotasiga ega — bir nechta hisob = bir nechta kvota jamgʻarmasi
- AI Pro foydalanuvchilari haftalik asosiy limitga yetganda 5 soatlik qayta tiklanish oʻrniga **7 kunlik bloklanishlar** haqida xabar berishgan (Google bu yuqori talab uchun ataylab shunday qilinganini tasdiqladi)

**Hisobingiz kvotasi tugaganda**: OmniRoute kombinatsiyalangan marshrutdagi keyingi mavjud hisob bilan soʻrovni avtomatik ravishda qayta yuboradi. Qoʻlda aralashish talab qilinmaydi.

## 3. projectId’ni qanday olish mumkin

Har bir antigravity/agy ulanishi uchun Google Cloud Code `projectId` talab qilinadi. Usiz `/v1internal:models` endpoint’i 404 javobini qaytaradi.

### A usuli: Avtomatik (Tavsiya etiladi)

OmniRoute buni avtomatik ravishda bajaradi. Dashboard OAuth orqali yangi Google hisobini qoʻshganingizda:

1. OmniRoute tokenni yangilaydi
2. projectId’ni aniqlash uchun `loadCodeAssist`ni chaqiradi
3. Agar loyiha mavjud boʻlmasa, uni yaratish uchun `onboardUser`ni chaqiradi
4. Yangi yaratilgan projectId’ni olish uchun `loadCodeAssist`ni qayta chaqiradi
5. Uni maʼlumotlar bazasiga saqlaydi

**Bu aksariyat hisoblar uchun ishlaydi** — qoʻlda bajariladigan qadamlar talab qilinmaydi.

### B usuli: agy CLI orqali qoʻlda

Agar avtomatik aniqlash muvaffaqiyatsiz tugasa (bu qachon yuz berishi haqida 5-boʻlimga qarang):

```bash
# agy CLI’ni o‘rnating (agar hali o‘rnatilmagan bo‘lsa)
npm install -g @anthropic-ai/agy

# Google hisobingiz bilan tizimga kiring
agy login

# Ro‘yxatdan o‘tkazilishi kerak bo‘lgan hisobni tanlang
# Bu Cloud Code’da ro‘yxatdan o‘tishni ishga tushiradi va projectId tayinlaydi
```

`agy login` muvaffaqiyatli yakunlangach, OmniRoute Dashboard’da tokenni yangilang. projectId avtomatik ravishda aniqlanadi.

### Qanday tekshirish mumkin

Maʼlumotlar bazasini tekshiring:

```bash
# OmniRoute konteyneri ichida
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Yoki jurnallarni tekshiring:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. OAuth qayta yoʻnaltirish URI manzili

### Muammo

Google OAuth yaroqli qayta yoʻnaltirish URI manzilini talab qiladi. OmniRoute sukut boʻyicha `http://127.0.0.1:20128/callback` (loopback) manzilidan foydalanadi. Bu lokal buildlar uchun ishlaydi, ammo **masofaviy joylashtirishlarda ishlamaydi** (masalan, LAN IP orqali kiriladigan serverda).

Google quyidagi qayta yoʻnaltirish URI manzillarini rad etadi:

- IP manzillardan foydalanadigan (`.com`, `.org` va hokazo bilan tugaydigan domen boʻlishi kerak)
- OAuth mijoz konfiguratsiyasida roʻyxatdan oʻtkazilgan qayta yoʻnaltirish URI manzillariga mos kelmaydigan

### Yechim

**A variant: Ichki OAuth jarayonidan foydalanish (standart)**

- OmniRoute xizmatiga `localhost` yoki `127.0.0.1` orqali kirganingizda ishlaydi
- Hech qanday konfiguratsiya talab qilinmaydi

**B variant: Maxsus OAuth hisob maʼlumotlari**

- Muhitingizda `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` qiymatini oʻrnating
- Oʻzingizning Google OAuth hisob maʼlumotlaringizni kiriting:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Google Cloud Console ichida `https://your-domain.com/callback` manzilini ruxsat etilgan qayta yoʻnaltirish URI manzili sifatida roʻyxatdan oʻtkazing

**C variant: Dastlabki kirish uchun agy CLI vositasidan foydalanish**

- OmniRoute xizmatiga kiradigan kompyuterda `agy login` buyrugʻini ishga tushiring
- OAuth jarayoni lokal ravishda yakunlanadi va tokenlar saqlanadi
- Dashboard orqali ulanishni OmniRoute tizimiga import qiling

### Cheklovlar

- Maxsus OAuth hisob maʼlumotlari domen nomini talab qiladi (Google IP manzillarni qayta yoʻnaltirish URI manzillari sifatida qabul qilmaydi)
- Agar domeningiz boʻlmasa, uning oʻrniga A yoki C variantidan foydalaning

## 5. Muammolarni bartaraf etish: Avtomatik sozlash ishlamasa

OmniRoute aksariyat hisoblar uchun projectId aniqlash va boshlangʻich sozlash jarayonlarini avtomatik ravishda bajaradi. Bu ishlamasa, asosiy sabab odatda quyidagilardan biri boʻladi:

### Hisob hududi bloklangan

**Alomat**: `agy login` buyrugʻi "Eligibility check failed: Your current account is not eligible for Antigravity, because it is not currently available in your location." xabarini qaytaradi.

**Asosiy sabab**: Google hisoblarida roʻyxatdan oʻtish vaqtida belgilanadigan ichki "Country Association" maydoni mavjud. agy CLI va Cloud Code API bu maydonni qatʼiy tekshiradi — faqat joriy IP manzilingizni tekshiradigan veb Gemini xizmatidan farqli ravishda.

> Hisobingizga bogʻlangan hududni tekshirish yoki oʻzgartirish uchun [Google Country Association Form](https://policies.google.com/country-association-form) sahifasiga tashrif buyuring.

**Nima uchun veb Gemini ishlaydi, ammo agy ishlamaydi**:

- Veb Gemini / Google One: faqat joriy IP manzilni tekshiradi (proksi orqali oʻtadi)
- agy CLI / Cloud Code API: ichki Country Association maydonini oʻqiydi (proksi yordam bermaydi)

**Tuzatish**:

1. AQSH IP manzilidan foydalanib, [Google Country Association Form](https://policies.google.com/country-association-form) sahifasiga tashrif buyuring
2. Hududni oʻzgartirish soʻrovini yuboring ("I live in a different country" bandini tanlang)
3. Google soʻrovni qayta ishlashi va elektron pochta orqali bildirishnoma yuborishi uchun 1-24 soat kuting
4. Shundan soʻng `agy login` muvaffaqiyatli ishlashi kerak

### Hisobda Cloud Code loyihasi mavjud emas

**Alomat**: Jurnallarda `loadCodeAssist returned no project id` va `onboardUser failed (400)` xabarlari koʻrsatiladi.

**Asosiy sabab**: Hisob hech qachon Google Cloud Code xizmatida roʻyxatdan oʻtkazilmagan va avtomatik boshlangʻich sozlash muvaffaqiyatsiz tugagan.

**Tuzatish**: Cloud Code roʻyxatdan oʻtkazish jarayonini ishga tushirish uchun `agy login` buyrugʻini qoʻlda bajaring, soʻng OmniRoute Dashboard panelida tokenni yangilang.

### Tokenning amal qilish muddati tugagan yoki u bekor qilingan

**Alomat**: Jurnallarda 401 xatolari yoki "Token has expired" xabarlari koʻrsatiladi.

**Tuzatish**: Dashboard → Providers → agy boʻlimiga oʻting → Yangilash belgisini bosing. Agar yangilash tokenining oʻzi bekor qilingan boʻlsa, OAuth orqali qayta autentifikatsiyadan oʻtishingiz kerak.
