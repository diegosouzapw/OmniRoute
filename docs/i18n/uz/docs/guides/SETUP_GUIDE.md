## Oʻrnatish usullari

### npm (tavsiya etiladi)

```bash
npm install -g omniroute
omniroute
```

Boshqaruv paneli `http://localhost:20128` manzilida ochiladi va API asosiy URL manzili `http://localhost:20128/v1` boʻladi.

### pnpm

```bash
pnpm add -g omniroute@latest --allow-build=better-sqlite3 --allow-build=@swc/core
omniroute
```

> **pnpm foydalanuvchilari:** `better-sqlite3` va `@swc/core` uchun mahalliy qurish skriptlarini yoqish maqsadida `--allow-build` bayrogʻi talab qilinadi. `pnpm approve-builds -g` buyrugʻi pnpm v11 da global oʻrnatishlar uchun qoʻllab-quvvatlanmaydi.

### Arch Linux (AUR)

```bash
yay -S omniroute-bin
systemctl --user enable --now omniroute.service
```

[AUR paketi](https://aur.archlinux.org/packages/omniroute-bin) OmniRouteʼni oʻrnatadi va systemd foydalanuvchi xizmatini taqdim etadi.

### Manba kodidan

```bash
npm install
PORT=20128 DASHBOARD_PORT=20129 NEXT_PUBLIC_BASE_URL=http://localhost:20129 npm run dev
```

> **Windows uchun eslatma:** Agar eski `%USERPROFILE%\.omniroute` katalogi mavjud boʻlmasa, OmniRoute standart holatda `%APPDATA%\omniroute` katalogidan foydalanadi. Boshqa maʼlumotlar katalogi joylashuvini tanlash uchun `DATA_DIR` ni belgilang.

> **Eslatma:** Birinchi ishga tushirishda `npm install` `.env.example` asosida `.env` faylini avtomatik yaratadi. Keyingi oʻrnatishlar mavjud `.env` faylining ustiga yozmaydi, shu sababli maxsus sozlamalar saqlanib qoladi. Uni qayta yaratish uchun qayta ishga tushirishdan oldin `.env` faylini oʻchiring.

### Docker

Compose profillari va Caddy HTTPS bilan birga Dockerʼni toʻliq sozlash uchun [Docker qoʻllanmasi](./DOCKER_GUIDE.md)ga qarang.

### Ish stoli ilovasi (Electron)

OmniRoute Electron 41 + electron-builder 26.10 asosida yaratilgan ish stoli qobigʻi bilan taqdim etiladi. Mavjud skriptlar (ish maydoni ildizi):

```bash
npm run electron:dev          # Ish stoli ilovasini tezkor qayta yuklash bilan ishga tushirish
npm run electron:build        # Joriy OT uchun qurish (avtomatik aniqlanadi)
npm run electron:build:win    # Windows oʻrnatuvchisi (NSIS + portativ)
npm run electron:build:mac    # macOS (dmg + zip, arm64+x64)
npm run electron:build:linux  # Linux (AppImage + deb + rpm)
npm run electron:smoke:packaged  # Paketlangan qurilishni tezkor sinovdan oʻtkazish
```

Ish stoli oʻrnatuvchilarining relizlari GitHub Releases sahifasiga biriktiriladi. Electron haqida batafsil maʼlumot (imzolash, IPC koʻprigi, distributivlar) uchun [`ELECTRON_GUIDE.md`](./ELECTRON_GUIDE.md) fayliga qarang _(keyingi bosqichda yaratilgan)_.

### Interfeyssiz server (CI/avtomatlashtirish)

Avtomatik sozlashlar (Docker, Kubernetes, CI) uchun quyidagilardan foydalaning:

```bash
omniroute setup --non-interactive
omniroute providers test-batch
```

Muhit oʻzgaruvchilari (`INITIAL_PASSWORD`, `OMNIROUTE_WS_BRIDGE_SECRET` va boshqalar) bilan birgalikda bu OmniRoute nusxasini toʻliq skript orqali ishga tushirish imkonini beradi.

### CLI parametrlari

| Buyruq                  | Tavsif                                                                                             |
| ----------------------- | -------------------------------------------------------------------------------------------------- |
| `omniroute`             | Serverni ishga tushirish (`PORT=20128`, API va boshqaruv paneli bir portda)                        |
| `omniroute setup`       | Parol va birinchi provayderni sozlash uchun yoʻnaltirilgan CLI jarayoni                            |
| `omniroute doctor`      | Serverni ishga tushirmasdan mahalliy holat tekshiruvlarini bajarish                                |
| `omniroute providers`   | CLI orqali provayderlarni topish, roʻyxatlash, tekshirish va sinash                                |
| `omniroute config`      | CLI vositasini sozlash — konfiguratsiyalarni roʻyxatlash, olish, oʻrnatish va tekshirish           |
| `omniroute status`      | Oflayn holat paneli — versiya, MB, vositalar, konfiguratsiya                                       |
| `omniroute logs`        | APIʼdan foydalanish jurnallarini oqimda koʻrsatish (`--follow` qoʻllab-quvvatlanadi)               |
| `omniroute update`      | OmniRoute yangilanishlarini tekshirish yoki qoʻllash                                               |
| `omniroute provider`    | Provayder ulanishlarini boshqarish — qoʻshish, roʻyxatlash, olib tashlash, sinash, standart qilish |
| `omniroute --port 3000` | Kanonik/API portini 3000 ga oʻrnatish                                                              |
| `omniroute --mcp`       | MCP serverini ishga tushirish (stdio transporti)                                                   |
| `omniroute --no-open`   | Brauzerni avtomatik ochmaslik                                                                      |
| `omniroute --help`      | Yordamni koʻrsatish                                                                                |

Interfeyssiz sozlashni bayroqlar yoki muhit oʻzgaruvchilari yordamida skriptlashtirish mumkin:

```bash
omniroute setup --non-interactive --password "$OMNIROUTE_PASSWORD"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY" --test-provider
```

Boshqaruv panelini ochmasdan mahalliy diagnostikani ishga tushiring:

```bash
omniroute doctor
omniroute doctor --json
omniroute doctor --no-liveness
```

Boshqaruv panelini ochmasdan SSH yoki skriptlar orqali provayderlarni boshqaring:

```bash
omniroute providers available
omniroute providers available --search openai
omniroute providers available --category api-key
omniroute providers list
omniroute providers test <id-or-name>
omniroute providers test-all
omniroute providers validate
```

## CLI vositasini sozlash

### 1) Provayderlarni ulang va API kalitini yarating

1. Dashboard → `Providers` bo‘limini oching va kamida bitta provayderni ulang (OAuth yoki API kaliti).
2. Dashboard → `Endpoints` bo‘limini oching va API kalitini yarating.
3. (Ixtiyoriy) Dashboard → `Combos` bo‘limini oching va zaxira zanjiringizni sozlang.

### 2) Dasturlash vositangizni yo‘naltiring

```txt
Asosiy URL: http://localhost:20128/v1
API kaliti: [Endpoint sahifasidan nusxalang]
Model:      if/qwen3.8-max-preview (yoki istalgan provayder/model prefiksi)
```

Agar muharriringiz `Authorization: Bearer ...` sarlavhasini yubora olmasa, uning o‘rniga token kiritilgan moslik uchun asosiy URL manzilidan foydalaning:

```txt
Asosiy URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/
Modellar URL manzili: http://localhost:20128/api/v1/vscode/YOUR_KEY/models
Chat URL manzili: http://localhost:20128/api/v1/vscode/YOUR_KEY/chat/completions
Ollama teglari URL manzili: http://localhost:20128/api/v1/vscode/YOUR_KEY/api/tags
```

Claude Code, Codex CLI, Cursor, Cline, OpenClaw, OpenCode va OpenAI bilan mos SDKlar bilan ishlaydi.

#### `setup-*` yordamida avtomatik sozlash

Asosiy URL va kalitni qo‘lda kiritish o‘rniga, OmniRoute har bir vositaning
o‘z konfiguratsiyasini joriy modellar katalogi asosida yozishiga ruxsat bering. Har bir vosita uchun bittadan buyruq:

```bash
omniroute setup-codex        # ~/.codex/<name>.config.toml profillari
omniroute setup-claude       # ~/.claude/profiles/<name>/settings.json
omniroute setup-opencode     # ~/.config/opencode/opencode.json (OpenAI bilan mos)
omniroute setup-cline        # Cline CLI + VS Code kengaytmasi sozlamalari
omniroute setup-kilo         # Kilo Code
omniroute setup-continue     # ~/.continue/config.yaml (Continue / cn)
omniroute setup-cursor       # Cursor ilovasidagi bajariladigan qadamlarni chiqaradi
omniroute setup-roo          # Roo Code importi + autoImport ko‘rsatkichi
omniroute setup-crush        # ~/.config/crush/crush.json
omniroute setup-goose        # ~/.config/goose/config.yaml
omniroute setup-aider        # ~/.aider.conf.yml
omniroute setup-qwen         # ~/.qwen/settings.json + ~/.qwen/.env
```

Har biri mahalliy vositani **masofaviy** OmniRoute bilan ishlash uchun sozlash maqsadida `--remote <url> --api-key <key>` parametrlarini, shuningdek, natijani oldindan ko‘rish uchun `--dry-run` parametrini qabul qiladi. To‘g‘ri
muhit o‘zgaruvchilari kiritilgan va umuman hech qanday konfiguratsiya yozilmagan holda CLI vositasini ishga tushirish uchun umumiy
`omniroute run <target>` ishga tushirgichidan foydalaning (claude, codex, aider, goose, opencode, qwen, gemini);
har bir vosita uchun eski `omniroute launch` (Claude Code) va
`omniroute launch-codex` (Codex) ishga tushirgichlaridan ham foydalanish mumkin.

To‘liq jadvalni (har bir buyruq nimalarni yozishi, barcha parametrlar, mahalliy va masofaviy rejimlar, asosiy URL
`/v1` qoidalari) ko‘rish uchun **[CLI integratsiyalari](./CLI-INTEGRATIONS.md)** sahifasiga qarang.

Har bir vosita uchun batafsil konfiguratsiyani (Claude Code, Codex CLI, Cursor, Cline, OpenClaw, Kilo Code, Copilot va boshqalar) ko‘rish uchun maxsus **[CLI vositalari bo‘yicha qo‘llanma](../reference/CLI-TOOLS.md)** sahifasiga qarang.

## Protokolni sozlash (MCP + A2A)

### MCP sozlamalari (Model konteksti protokoli)

MCP transportini stdio rejimida ishga tushiring:

```bash
omniroute --mcp
```

Tavsiya etilgan tekshirish jarayoni:

```bash
# 1. MCP serverini ishga tushiring
omniroute --mcp

# 2. MCP mijozingizdan quyidagilarni chaqiring:
omniroute_get_health        # Tizim holatini qaytarishi kerak
omniroute_list_combos       # Faol kombinatsiyalarni qaytarishi kerak

# 3. Yoki to‘liq E2E testlar to‘plamini ishga tushiring:
npm run test:protocols:e2e
```

#### MCP mijozini sozlash

**Claude Code:**

```bash
claude mcp add-server omniroute --type http --url http://localhost:20128/api/mcp/stream
```

**Cursor / Cline:**

MCP sozlamalaringizga qo‘shing:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"],
      "env": {}
    }
  }
}
```

**To‘liq MCP hujjatlari:** [MCP Server README](../../open-sse/mcp-server/README.md) — 110 ta vosita, IDE konfiguratsiyalari, Python/TS/Go mijozlari.

### A2A sozlamalari (Agentlararo protokol)

Agent kartasini tekshiring:

```bash
curl http://localhost:20128/.well-known/agent.json
```

Vazifa yuboring:

```bash
curl -X POST http://localhost:20128/a2a \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":"quickstart","method":"message/send","params":{"skill":"quota-management","messages":[{"role":"user","content":"Give me a short quota summary."}]}}'
```

**To‘liq A2A hujjatlari:** [A2A Server README](../../src/lib/a2a/README.md) — JSON-RPC 2.0, ko‘nikmalar, oqimli uzatish, vazifaning hayot sikli.

## Taym-aut sozlamalari

### Asosiy taym-autlar

Koʻpgina joylashtirishlarda sizga faqat ushbu ikkita oʻzgaruvchi kerak boʻladi:

| Oʻzgaruvchi              | Standart qiymat                                  | Maqsad                                                                                                                                                                       |
| ------------------------ | ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `REQUEST_TIMEOUT_MS`     | `600000`                                         | Yuqori oqim javobi boshlanishi taym-auti, yashirin Undici taym-autlari, TLS raqamli izi soʻrovlari hamda API koʻprigi soʻrovi/proksi taym-autlari uchun umumiy asosiy qiymat |
| `STREAM_IDLE_TIMEOUT_MS` | `REQUEST_TIMEOUT_MS` qiymatini meros qilib oladi | OmniRoute SSE oqimini bekor qilishidan oldin oqim qismlari orasidagi maksimal tanaffus                                                                                       |

Orqaga muvofiqlik saqlanadi: mavjud `FETCH_TIMEOUT_MS`, `API_BRIDGE_PROXY_TIMEOUT_MS` va boshqa qatlamga xos taym-aut oʻzgaruvchilari ishlashda davom etadi hamda umumiy asosiy qiymatni bekor qiladi.

### Provayderga xos eslatmalar

Claude Code bilan mos yuqori oqimlar (`anthropic-compatible-cc-*`) uchun OmniRoute chiquvchi `X-Stainless-Timeout` sarlavhasini aniqlangan olish taym-autidan hosil qiladi, shunda provayder tomonidagi oʻqish taym-autlari muhit konfiguratsiyangiz bilan mos boʻlib qoladi.

Uchinchi tomon Claude Code bilan mos teskari proksilar uchun OmniRoute standart `anthropic-beta` toʻplamini konservativ holatda saqlaydi va `Client Cache Control` parametri `Auto` holatida qoldirilganda, faqat mijoz taqdim etgan `cache_control` belgilarini uzatadi. Har bir ulanish uchun “Enable redact-thinking beta” parametrini faqat yuqori oqim maxsus ravishda tahrirlangan Claude fikrlash oqimlarini talab qilganda yoqing.

### Kengaytirilgan taym-aut almashtirishlari

| Oʻzgaruvchi                              | Standart qiymat                                                | Maqsad                                                                               |
| ---------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `FETCH_TIMEOUT_MS`                       | `REQUEST_TIMEOUT_MS` qiymatini meros qilib oladi               | Javob sarlavhalari kelguncha ishlatiladigan yuqori oqim javobi boshlanishi taym-auti |
| `FETCH_HEADERS_TIMEOUT_MS`               | `FETCH_TIMEOUT_MS` qiymatini meros qilib oladi                 | Yuqori oqim javob sarlavhalarini olish uchun Undici vaqt chegarasi                   |
| `FETCH_BODY_TIMEOUT_MS`                  | `FETCH_TIMEOUT_MS` qiymatini meros qilib oladi                 | Yuqori oqim tanasi qismlari orasidagi Undici vaqt chegarasi (`0` uni oʻchiradi)      |
| `FETCH_CONNECT_TIMEOUT_MS`               | `30000`                                                        | Undici TCP ulanish taym-auti                                                         |
| `FETCH_KEEPALIVE_TIMEOUT_MS`             | `4000`                                                         | Undici faol boʻlmagan keep-alive soketi taym-auti                                    |
| `TLS_CLIENT_TIMEOUT_MS`                  | `FETCH_TIMEOUT_MS` qiymatini meros qilib oladi                 | `wreq-js` orqali amalga oshiriladigan TLS raqamli izi soʻrovlari taym-auti           |
| `API_BRIDGE_PROXY_TIMEOUT_MS`            | `REQUEST_TIMEOUT_MS` yoki `600000` qiymatini meros qilib oladi | API portidan boshqaruv paneli portiga `/v1` proksi yoʻnaltirishi taym-auti           |
| `API_BRIDGE_SERVER_REQUEST_TIMEOUT_MS`   | `max(API_BRIDGE_PROXY_TIMEOUT_MS, 300000)`                     | API koʻprigi serveridagi kiruvchi soʻrov taym-auti                                   |
| `API_BRIDGE_SERVER_HEADERS_TIMEOUT_MS`   | `60000`                                                        | API koʻprigi serveridagi kiruvchi sarlavhalar taym-auti                              |
| `API_BRIDGE_SERVER_KEEPALIVE_TIMEOUT_MS` | `5000`                                                         | API koʻprigi serveridagi keep-alive taym-auti                                        |
| `API_BRIDGE_SERVER_SOCKET_TIMEOUT_MS`    | `0`                                                            | API koʻprigi serveridagi soket nofaolligi taym-auti (`0` uni oʻchiradi)              |

> **Eslatma:** Oqimli soʻrovlar uchun `FETCH_TIMEOUT_MS` faqat ulanishni sozlash / yuqori oqimdan birinchi javobni kutish jarayonini qamrab oladi. Oqim faollashgach, OmniRoute uni faqat haqiqiy toʻxtab qolish (`STREAM_IDLE_TIMEOUT_MS`) yoki Undici tanasi nofaolligi (`FETCH_BODY_TIMEOUT_MS`) yuz berganda bekor qiladi.

### Teskari proksi bilan muvofiqlik

Agar OmniRoute’ni Nginx, Caddy, Cloudflare yoki boshqa teskari proksi ortida ishga tushirsangiz, proksi taym-autlari ham OmniRoute oqim/olish taym-autlaridan yuqori ekaniga ishonch hosil qiling.

## Void Linux (xbps-src) shabloni

Void Linux foydalanuvchilari `xbps-src` yordamida mahalliy paket yaratishlari mumkin. Ushbu blokni `srcpkgs/omniroute/template` sifatida saqlang:

```bash
# 'omniroute' uchun shablon fayli
pkgname=omniroute
version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"
maintainer="zenobit <zenobit@disroot.org>"
license="MIT"
homepage="https://github.com/diegosouzapw/OmniRoute"
distfiles="https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz"
# Har bir reliz uchun nazorat summasini quyidagicha qayta yarating:
#   curl -L -o /tmp/omniroute.tar.gz "https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz" && sha256sum /tmp/omniroute.tar.gz
checksum=PLACEHOLDER_REGENERATE_PER_RELEASE
system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	NODE_ENV=development npm ci --ignore-scripts
	npm run build
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	rm -rf .next/standalone/node_modules/@img

	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
		touch "${DESTDIR}/usr/lib/omniroute/${_d}/.keep"
	done

	cat > "${WRKDIR}/omniroute" <<'EOF'
#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"
mkdir -p "${DATA_DIR}"
exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```
