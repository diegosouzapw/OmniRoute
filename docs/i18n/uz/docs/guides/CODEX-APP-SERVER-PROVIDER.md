---

OmniRoute OpenAI Codex’dan foydalanishning **ikki** usulini taqdim etadi:

| Provayder              | OpenAI bilan qanday aloqa qiladi                                                                                                                                                                                                 | Foydalanish bo‘yicha ogohlantirish                                              |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| **`codex`**            | ChatGPT/OpenAI OAuth tokeningizni to‘g‘ridan-to‘g‘ri Responses API’ga qayta uzatadi                                                                                                                                              | **Ha** — rasmiy sessiyadan proksi/router orqali foydalanishga ruxsat berilmagan |
| **`codex-app-server`** | **Codex CLI’ning o‘z `codex app-server` xizmatini** JSON-RPC/WebSocket orqali boshqaradi; CLI interaktiv `codex` sessiyasidagi kabi o‘z OAuth ma’lumotlariga (`~/.codex/auth.json`) egalik qiladi va ularni avtomatik yangilaydi | **Yo‘q** — OmniRoute hech qachon tokenni API’ga qayta uzatmaydi                 |

`codex-app-server` hech qachon tokenni qayta uzatmagani sababli, unga
sessiyani qayta uzatish bo‘yicha foydalanish ogohlantirishi taalluqli emas. Biroq u
**sozlangan app-server URL manzilida foydalanish mumkin bo‘lgan Codex CLI’ni**
talab qiladi va ushbu CLI tizimga **kirgan** bo‘lishi kerak.

---

## 1. Arxitektura

```
┌─ OmniRoute ilovasi ─────────────┐        ┌─ codex-app-server yordamchi konteyneri ┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                     │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456           │
│  (+ imkoniyat tokeni)            │  JSON  │  --ws-auth capability-token           │
│                                  │  RPC   │  OpenAI OAuth’ni o‘zi boshqaradi       │
└──────────────────────────────────┘        │  (~/.codex/auth.json, avtomatik yangilash) │
        │ ulashadi (compose jildlari)        └────────────────────────────────────────┘
        ▼
  codex-appserver-token   → WS imkoniyat tokeni (ikkalasi ham uni ulaydi)
  codex-appserver-home    → ~/.codex (auth.json boshqaruv paneli tomonidan yoziladi,
                             yordamchi konteynerdagi codex app-server tomonidan o‘qiladi)
```

- Yordamchi konteyner imkoniyat tokeni bilan himoyalangan holda **faqat** ichki compose
  tarmog‘ida (`ws://codex-app-server:1456`) tinglaydi. U **hech qachon**
  xost yoki internetga ochilmaydi.
- Codex CLI `omniroute:base` ichiga oldindan o‘rnatilgan, shu sababli yordamchi
  konteynerni ishga tushirganda xostga yoki foydalanuvchi qurilmasiga codex o‘rnatish
  shart emas.

## 2. Ishga tushirish

```bash
# Stekni codex app-server yordamchi konteyner profili BILAN ishga tushiring:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

Yordamchi konteyner ilk ishga tushganda o‘zining WS imkoniyat tokenini yaratadi
va uni umumiy `codex-appserver-token` jildiga joylaydi, ilova esa ayni tokenni
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE` orqali o‘qiydi. Tokenni qo‘lda
ulash shart emas.

## 3. Ulanish va tizimga kirish

1. Boshqaruv panelida **OpenAI Codex (App-Server)** uchun ulanish qo‘shing. Hech qanday API
   kaliti yoki token talab qilinmaydi (bu autentifikatsiyasiz provayder — autentifikatsiyani
   yordamchi konteyner boshqaradi).
2. Agar yordamchi konteynerdagi Codex CLI hali **tizimga kirmagan** bo‘lsa, ulanish holati
   tekshiruvi _«ishlamoqda, ammo tizimga kirilmagan»_ deb xabar beradi (qizil autentifikatsiya
   xatosi emas). **Sign in with ChatGPT** tugmasidan foydalaning: bu brauzeringizda
   standart Codex qurilma OAuth jarayonini ishga tushiradi, so‘ng **Apply auth** orqali
   `~/.codex/auth.json` faylini umumiy jildga yozadi (bitta kirish `codex` va
   `codex-app-server` provayderlarining ikkalasiga ham xizmat qiladi).
3. Tizimga kirilgach, holat tekshiruvi yashil rangga o‘tadi (u `/readyz` **va**
   `account/read`’ni, ya’ni xizmat ishga tushganini _hamda_ autentifikatsiyadan
   o‘tganini tekshiradi) va xizmat ishlay boshlaydi.

Boshqaruv paneli mavjud sog‘lom `~/.codex/auth.json` faylini hech qachon qayta
yozmaydi — u faqat fayl mavjud bo‘lmaganda yoki uning tokeni eskirganda yozadi
(har doim zaxira nusxa olinadi).

## 4. Joylashtirish ssenariylari

- **Codex CLI’da allaqachon autentifikatsiyadan o‘tgan operator** — xostingizdagi
  `~/.codex` jildini yordamchi konteynerga (`codex-appserver-home`) ulang va tizimga
  kirish bosqichini o‘tkazib yuboring.
- **Ommaviy foydalanuvchi, mahalliy qurilmada codex o‘rnatilmagan** — bu ahamiyatsiz:
  yordamchi konteynerda CLI mavjud. Foydalanuvchi faqat boshqaruv paneli orqali
  autentifikatsiyadan o‘tadi.
- **Bare-metal OmniRoute (yordamchi konteyner yo‘q, xostda codex mavjud)** —
  `OMNIROUTE_CODEX_APPSERVER_WS`’ni o‘zingizning `codex app-server` xizmatingizga
  yo‘naltiring va xostdagi codex tizimga kirganiga ishonch hosil qiling; agar bajariluvchi
  fayl mavjud bo‘lmasa, «codex o‘rnatilmagan» maslahati ko‘rsatiladi.

## 5. Uy tarmog‘i / UDP chiqish trafiki (operator uchun qo‘shimcha, paketga kiritilmagan)

Yuqoridagi umumiy yordamchi konteyner chiqish trafigini konteynerning odatiy tarmog‘i
orqali yuboradi. Codex trafigini **uy tarmog‘i chiqish nuqtasi** orqali yuborishi kerak
bo‘lgan operator (masalan, TCP + UDP/QUIC tashuvchi TUN tailscale yordamchi konteyneri)
buni alohida compose qayta sozlamasi sifatida ishga tushiradi; u ataylab tarqatiladigan
`codex-app-server` profiliga **kiritilmagan**. Ushbu sozlama uchun ichki ekspluatatsiya
yo‘riqnomasiga qarang.
