Ushbu qoʻllanma Kiro (AWS tomonidan joylashtirilgan sunʼiy intellekt yordamidagi dasturlash assistenti) hisoblarini OmniRouteʼga qoʻshish jarayonini tushuntiradi hamda seanslar ziddiyatisiz bir vaqtning oʻzida bir nechta hisobni ishga tushirishga alohida eʼtibor qaratadi.

---

## Asosiy maʼlumot: Kiro hisoblari nega ziddiyatga kirishishi mumkin

Kiro backend tizimi faol seanslarni kuzatish uchun AWS SSO OIDC mijoz roʻyxatdan oʻtkazishlaridan foydalanadi.
Muhim cheklov: **har bir OIDC mijoz roʻyxatdan oʻtkazishi bir vaqtning oʻzida faqat bitta faol
seansni qoʻllab-quvvatlaydi**. Ikkinchi qurilma yoki foydalanuvchi ayni roʻyxatdan oʻtkazilgan
mijozdan foydalanib autentifikatsiyadan oʻtganda, backend birinchi hisobning yangilash tokenini bekor qiladi.

Xuddi shu mexanizm boshqa Kiro hisobi allaqachon tizimga kirgan kompyuterda
`kiro-cli login` ishga tushirilganda muammolarga sabab boʻladi — yangi kirish
birinchi hisobning tokenini bekor qiladi.

---

## OmniRoute buni qanday hal qiladi (v3.8.0+)

v3.8.0 dan boshlab OmniRoute har bir Kiro ulanishini import qilish vaqtida
`registerClient()` (AWS SSO OIDC) funksiyasini chaqiradi. Bu har bir OmniRoute ulanishiga alohida ajratilgan OIDC
mijoz roʻyxatdan oʻtkazishini beradi. Har bir mijoz roʻyxatdan oʻtkazishi mustaqil boʻlgani sababli, bitta hisobni
yangilash yoki qayta autentifikatsiya qilish boshqa hisoblarning yangilash tokenlariga taʼsir qilmaydi.

Izolyatsiya yangilash tokenini import qilish usullariga tatbiq etiladi, API kalit orqali autentifikatsiya esa
OIDC yangilash seanslaridan butunlay foydalanmaydi:

| Import usuli                                                   | Izolyatsiya holati                                                                                                                           |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| AWS Builder ID / IDC qurilma kodi oqimi                        | Qurilma kodi oqimi joriy etilganidan beri izolyatsiyalangan                                                                                  |
| **Tokenni import qilish** (yangilash tokenini qoʻlda kiritish) | v3.8.0 dan boshlab izolyatsiyalangan                                                                                                         |
| **Google / GitHub ijtimoiy tarmoq orqali kirish**              | v3.8.0 dan boshlab izolyatsiyalangan                                                                                                         |
| **Avtomatik import** (kiro-cli SQLite)                         | v3.8.0 dan boshlab izolyatsiyalangan (SQLite yoʻli avvaldan izolyatsiyalangan edi; SSO keshiga qaytish mexanizmi ham endi izolyatsiyalangan) |
| **API kaliti** (uzoq muddatli CodeWhisperer kaliti)            | Yangilash seansi yoʻq; kalit tekshiriladi va bearer hisob maʼlumoti sifatida saqlanadi                                                       |

## v3.8.0 dan oldin yaratilgan ulanishlar uchun migratsiya eslatmasi

v3.8.0 dan oldin import qilingan ulanishlarda `providerSpecificData` ichida
alohida ajratilgan OIDC mijoz roʻyxatdan oʻtkazishi saqlanmagan. Bu ulanishlar ishlashda davom etadi, ammo umumiy
ijtimoiy autentifikatsiya yangilash endpointidan foydalanadi, yaʼni bunday ikkita ulanish hanuz bir-birining
tokenini bekor qilishi mumkin.

**Izolyatsiyaga ega boʻlish uchun:** eski ulanishni **Boshqaruv paneli → Provayderlar** boʻlimidan oʻchiring va
qoʻllab-quvvatlanadigan import oqimlaridan birini ishlatib uni qayta import qiling. Barcha yangi yaratilgan ulanishlar
avtomatik ravishda oʻz mijoz roʻyxatdan oʻtkazishiga ega boʻladi.

## Ikkita Kiro hisobini yonma-yon qoʻshish

### Talablar

- OmniRoute v3.8.0 yoki undan keyingi versiyasi.
- Ishlaydigan Kiro hisobi (elektron pochta + parol, Google yoki GitHub orqali kirish).
- Ixtiyoriy ravishda ikkinchi Kiro hisobi.

### 1-qadam: Birinchi hisobni import qilish

1. **Boshqaruv paneli → Provayderlar → Provayder qoʻshish → Kiro** boʻlimini oching.
2. Quyidagilardan birini tanlang:
   - **Tokenni import qilish** — `aorAAAAAG` bilan boshlanadigan yangilash tokenini kiriting.
   - **API kaliti** — uzoq muddatli Kiro / CodeWhisperer API kalitini kiriting.
   - **Google / GitHub orqali kirish** — brauzerda OAuth oqimini yakunlang.
   - **Avtomatik import** — tugmani bosing; OmniRoute hisob maʼlumotlarini
     mahalliy kiro-cli maʼlumotlar bazasidan yoki `~/.aws/sso/cache` ichidan oʻqiydi.
3. Ulanish saqlanadi. Yangilash tokeni oqimlari avtomatik ravishda alohida ajratilgan
   OIDC mijozini roʻyxatdan oʻtkazadi. API kaliti oqimlari kalitni AWS orqali tekshiradi va yangilash tokenini saqlamaydi.

### 2-qadam: Ikkinchi hisobni import qilish

Ikkinchi hisob uchun 1-qadamni takrorlang. Har bir import alohida OIDC
mijoz roʻyxatdan oʻtkazishini yaratgani sababli, ikkala ulanish ham toʻliq izolyatsiyalangan boʻladi.

### 3-qadam: Ikkala ulanish ham faol ekanini tekshirish

1. **Boshqaruv paneli → Provayderlar** — ikkala Kiro ulanishi ham **Faol** holatini koʻrsatishi kerak.
2. **Boshqaruv paneli → Holat** — ikkala ulanish ham token holati tekshiruvidan muvaffaqiyatli oʻtishi kerak.

### 4-qadam: Hisoblar oʻrtasida yoʻnaltirish uchun kombodan foydalanish

Ular oʻrtasida yuklamani muvozanatlash yoki zaxira ulanishga oʻtish uchun ikkala ulanishni ham nishon sifatida belgilagan kombo yarating:

```
kiro/kiro-dev → kiro/kiro-pro
```

Kombo konfiguratsiyasi uchun [FEATURES.md](./FEATURES.md) va yoʻnaltirish hujjatlariga qarang.

## Korporativ / IDC foydalanuvchilari

AWS IAM Identity Center (IDC) hisoblari uchun **Boshqaruv paneli → Provayderlar → Kiro → Qurilma kodi** orqali **AWS Builder ID / IDC qurilma kodi**
oqimidan foydalaning. Qurilma kodi oqimi har doim toʻliq izolyatsiya qilingan.
Bu ulanishlarni qayta import qilish shart emas.

Standart boʻlmagan AWS hududida ishlaydigan korporativ foydalanuvchilar Import Token API orqali
import qilishda hududni koʻrsatishi mumkin:

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/import \
  -H "Content-Type: application/json" \
  -d '{"refreshToken": "aorAAAAAG...", "region": "eu-west-1"}'
```

`region` maydoni koʻrsatilmasa, standart qiymat sifatida `us-east-1` ishlatiladi.

## API kalitini import qilish oqimi

API kaliti orqali autentifikatsiya uzoq muddat amal qiladigan Kiro / AWS CodeWhisperer bearer hisob maʼlumotlari uchun moʻljallangan. U
OAuth yangilashidan foydalanmaydi, shuning uchun umumiy OIDC seansi bekor qilinishining oldini oladi.

### Boshqaruv paneli

1. **Boshqaruv paneli -> Provayderlar -> Kiro** boʻlimini oching.
2. **API kaliti**ni tanlang.
3. API kalitini va ixtiyoriy AWS hududini kiriting (standart qiymat — `us-east-1`).
4. OmniRoute kalitni tekshiradi va ulanishni saqlaydi.

### API

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/api-key \
  -H "Content-Type: application/json" \
  -d '{"apiKey": "kiro_or_codewhisperer_key", "region": "us-east-1"}'
```

### Ichki shartnoma

API marshruti kalitni `KiroService.validateApiKey()` funksiyasini chaqirish orqali tekshiradi; bu funksiya
hududga mos CodeWhisperer/Amazon Q soʻnggi nuqtasiga `ListAvailableProfiles` soʻrovini yuboradi
va `profileArn` qiymatini aniqlaydi.

Saqlangan ulanish quyidagilardan foydalanadi:

```json
{
  "authType": "apikey",
  "providerSpecificData": {
    "authMethod": "api_key",
    "region": "us-east-1",
    "profileArn": "arn:aws:codewhisperer:..."
  }
}
```

Ishlash vaqtida `KiroExecutor.buildHeaders()` kalitni
`Authorization: Bearer <key>` sifatida yuboradi va `tokentype: API_KEY` qiymatini qoʻshadi. Kvota/profil chaqiruvlari
ham xuddi shu belgidan foydalanadi, shuning uchun AWS bearer maʼlumotini OIDC yoki ijtimoiy tarmoq kirish tokeni sifatida emas,
balki uzoq muddat amal qiladigan API kaliti sifatida qabul qiladi.

## OIDC mijozi amal qilish muddatining tugashi

AWS SSO OIDC ommaviy mijozlarining amal qilish muddati odatda 90 kundan keyin tugaydi
(`clientSecretExpiresAt`). Kuzatuvchanlik uchun OmniRoute ushbu vaqt belgisini `providerSpecificData`
ichida saqlaydi. Agar ulanish taxminan 90 kundan keyin yangilanishni toʻxtatsa, yangi OIDC mijoz
roʻyxatga olish maʼlumotlarini olish uchun ulanishni qayta import qiling. Amal qilish muddati tugaganda
avtomatik qayta roʻyxatdan oʻtkazish kelajakdagi takomillashtirish sifatida rejalashtirilgan.

API kaliti ulanishlarida OIDC mijozi amal qilish muddatining tugashi mavjud emas, chunki ular
AWS SSO OIDC orqali yangilanmaydi.

## Muammolarni bartaraf etish

### Ikkinchi hisob tizimdan chiqarilishda davom etmoqda

- **Boshqaruv paneli → Provayderlar** boʻlimida ikkala ulanishni tekshiring va ularning har birida xom
  JSON ichidagi `clientId` qiymati null emasligini tasdiqlang (maʼlumot belgisini bosish orqali koʻrish mumkin). Agar ulanishlardan birida
  `clientId` boʻlmasa, u v3.8.0 dan oldin import qilingan — uni qayta import qiling.

### Import qilishda "Tokenni tekshirish amalga oshmadi" xatosi yuz berdi

- Yangilash tokeni `aorAAAAAG` bilan boshlanishiga ishonch hosil qiling.
- OmniRoute `https://oidc.us-east-1.amazonaws.com` manziliga (yoki sozlangan
  hududga) ulana olishiga ishonch hosil qiling. Agar korporativ proksi ortida boʻlsangiz,
  **Boshqaruv paneli → Sozlamalar → Proksilar** boʻlimida provayder darajasidagi proksini sozlang.

### API kalitini import qilish amalga oshmadi

- Kalit yangilash tokeni emas, balki Kiro / CodeWhisperer API kaliti ekanligini tasdiqlang.
- AWS hududi kalit/hisobga mos kelishini tasdiqlang. Standart qiymat — `us-east-1`.
- Kalit `ListAvailableProfiles` chaqiruvini bajara olishi kerak; aks holda OmniRoute
  talab qilinadigan `profileArn` qiymatini aniqlay olmaydi.

Boshqa muammolar uchun asosiy [TROUBLESHOOTING.md](./TROUBLESHOOTING.md) fayliga qarang.
