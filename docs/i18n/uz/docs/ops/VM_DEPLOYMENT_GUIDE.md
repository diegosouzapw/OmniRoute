## 1. VM’ni sozlash

### 1.1 Instansiyani yaratish

Oʻzingiz tanlagan VPS provayderida:

- Ubuntu 24.04 LTS’ni tanlang
- Minimal tarifni tanlang (1 vCPU / 1 GB RAM)
- Kuchli root parolini oʻrnating yoki SSH kalitini sozlang
- **Ommaviy IP** manzilini yozib oling (masalan, `203.0.113.10`)

### 1.2 SSH orqali ulanish

```bash
ssh root@203.0.113.10
```

### 1.3 Tizimni yangilash

```bash
apt update && apt upgrade -y
```

### 1.4 Docker’ni oʻrnatish

```bash
# Bogʻliqliklarni oʻrnatish
apt install -y ca-certificates curl gnupg

# Rasmiy Docker repozitoriysini qoʻshish
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
chmod a+r /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $ (. /etc/os-release && echo "$VERSION_CODENAME") stable" | tee /etc/apt/sources.list.d/docker.list > /dev/null
apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

### 1.5 nginx’ni oʻrnatish

```bash
apt install -y nginx
```

### 1.6 Fayervolni (UFW) sozlash

```bash
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp    # SSH
ufw allow 80/tcp    # HTTP (qayta yoʻnaltirish)
ufw allow 443/tcp   # HTTPS
ufw enable
```

> **Maslahat**: Maksimal xavfsizlik uchun 80 va 443-portlarga kirishni faqat Cloudflare IP manzillari bilan cheklang. [Kengaytirilgan xavfsizlik](#advanced-security) boʻlimiga qarang.

## 2. OmniRoute’ni oʻrnatish

### 2.1 Konfiguratsiya katalogini yaratish

```bash
mkdir -p /opt/omniroute
```

### 2.2 Muhit oʻzgaruvchilari faylini yaratish

```bash
cat > /opt/omniroute/.env << 'EOF'
# === Xavfsizlik ===
JWT_SECRET=CHANGE-TO-A-UNIQUE-64-CHAR-SECRET-KEY
INITIAL_PASSWORD=YourSecurePassword123!
API_KEY_SECRET=REPLACE-WITH-ANOTHER-SECRET-KEY
STORAGE_ENCRYPTION_KEY=REPLACE-WITH-THIRD-SECRET-KEY
STORAGE_ENCRYPTION_KEY_VERSION=v1
MACHINE_ID_SALT=CHANGE-TO-A-UNIQUE-SALT
OMNIROUTE_WS_BRIDGE_SECRET=REPLACE-WITH-WS-BRIDGE-SECRET  # Ishlab chiqarish muhitida TALAB QILINADI: Codex Responses WS koʻprigi tomonidan ishlatiladi

# === Ilova ===
PORT=20128
NODE_ENV=production
HOSTNAME=0.0.0.0
DATA_DIR=/app/data
APP_LOG_TO_FILE=true
AUTH_COOKIE_SECURE=true
REQUIRE_API_KEY=false

# === URL manzillari (domeningizga oʻzgartiring) ===
# Rejalashtirilgan vazifalar / oʻz-oʻziga soʻrovlar uchun ichki serverlararo asosiy URL.
BASE_URL=http://127.0.0.1:20128
# OAuth qayta chaqiruvlari, boshqaruv paneli havolalari va yaratilgan ommaviy URL manzillari uchun ishlatiladigan brauzerga moʻljallangan URL.
NEXT_PUBLIC_BASE_URL=https://llms.seudominio.com
# Yaratilgan ommaviy resurs URL manzillari uchun ixtiyoriy aniq ommaviy manba qiymatini qayta belgilash.
# OMNIROUTE_PUBLIC_BASE_URL=https://llms.seudominio.com

# === Bulutli sinxronlash (ixtiyoriy) ===
# CLOUD_URL=https://cloud.omniroute.online
# NEXT_PUBLIC_CLOUD_URL=https://cloud.omniroute.online
EOF
```

> ⚠️ **MUHIM**: Noyob maxfiy kalitlarni yarating! Har bir kalit uchun `openssl rand -hex 32` buyrugʻidan foydalaning.

### 2.3 Konteynerni ishga tushirish

```bash
docker pull diegosouzapw/omniroute:latest

docker run -d \
  --name omniroute \
  --restart unless-stopped \
  --env-file /opt/omniroute/.env \
  -p 20128:20128 \
  -v omniroute-data:/app/data \
  diegosouzapw/omniroute:latest
```

### 2.4 Uning ishlayotganini tekshirish

```bash
docker ps | grep omniroute
docker logs omniroute --tail 20
```

Quyidagilar koʻrsatilishi kerak: `[DB] SQLite database ready` va `listening on port 20128`.

## 3. nginx'ni sozlash (teskari proksi)

### 3.1 SSL sertifikatini yaratish (Cloudflare Origin)

Cloudflare boshqaruv panelida:

1. **SSL/TLS → Origin Server** bo‘limiga o‘ting
2. **Create Certificate** tugmasini bosing
3. Standart sozlamalarni saqlang (15 yil, \*.yourdomain.com)
4. **Origin Certificate** va **Private Key** nusxalarini oling

```bash
mkdir -p /etc/nginx/ssl

# Sertifikatni joylashtiring
nano /etc/nginx/ssl/origin.crt

# Maxfiy kalitni joylashtiring
nano /etc/nginx/ssl/origin.key

chmod 600 /etc/nginx/ssl/origin.key
```

### 3.2 Nginx konfiguratsiyasi

```bash
cat > /etc/nginx/sites-available/omniroute << 'NGINX'
# Standart server — IP orqali to‘g‘ridan-to‘g‘ri kirishni bloklaydi
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    listen 443 ssl default_server;
    listen [::]:443 ssl default_server;
    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    server_name _;
    return 444;
}

# OmniRoute — HTTPS
server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name llms.yourdomain.com;  # O‘z domeningizga almashtiring

    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    client_max_body_size 100M;

    location / {
        proxy_pass http://127.0.0.1:20128;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket qo‘llab-quvvatlashi
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # SSE (server tomonidan yuboriladigan hodisalar) — sun’iy intellekt javoblarini oqimli uzatish
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }
}

# HTTP → HTTPS yo‘naltirish
server {
    listen 80;
    listen [::]:80;
    server_name llms.yourdomain.com;
    return 301 https://$server_name$request_uri;
}
NGINX
```

Teskari proksi oqimining kutish vaqtlarini OmniRoute kutish vaqti muhit o‘zgaruvchilari bilan moslashtiring. Agar
`FETCH_TIMEOUT_MS` / `STREAM_IDLE_TIMEOUT_MS` qiymatlarini oshirsangiz, `proxy_read_timeout` / `proxy_send_timeout`
qiymatlarini ham xuddi shu chegaradan yuqoriga oshiring.

OmniRoute OAuth qayta chaqiruvlari va yaratiladigan ochiq havolalar uchun brauzerga yo‘naltirilgan asosiy manzil sifatida `NEXT_PUBLIC_BASE_URL` dan foydalanadi. Autentifikatsiyadan o‘tgan boshqaruv panelidagi yozuv amallari bir xil manbali so‘rovlardan hamda seansga bog‘langan CSRF himoyasidan foydalanadi, shuning uchun ular statik ochiq asosiy URL manzilini talab qilmaydi. Yuqoridagi `X-Forwarded-*` sarlavhalari marshrutlash uchun foydali metama’lumot bo‘lib qoladi, biroq OAuth yoki brauzer uchun yaratiladigan havolalar talab qilganda ular aniq ochiq URL manzilini sozlash o‘rnini bosa olmaydi. `OMNIROUTE_TRUST_PROXY` parametrini faqat OmniRoute mijozlar uchun to‘g‘ridan-to‘g‘ri ochiq bo‘lmasa va proksingiz kiruvchi uzatilgan sarlavhalarni olib tashlab, qayta yaratsa yoqing.

### 3.3 Yoqish va sinash

```bash
# Standart konfiguratsiyani olib tashlang
rm -f /etc/nginx/sites-enabled/default

# OmniRoute'ni yoqing
ln -sf /etc/nginx/sites-available/omniroute /etc/nginx/sites-enabled/omniroute

# Tekshiring va qayta yuklang
nginx -t && systemctl reload nginx
```

## 5. Ishlatish va texnik xizmat koʻrsatish

### Yangi versiyaga yangilash

```bash
docker pull diegosouzapw/omniroute:latest
docker stop omniroute && docker rm omniroute
docker run -d --name omniroute --restart unless-stopped \
  --env-file /opt/omniroute/.env \
  -p 20128:20128 \
  -v omniroute-data:/app/data \
  diegosouzapw/omniroute:latest
```

### Jurnallarni koʻrish

```bash
docker logs -f omniroute          # Real vaqt rejimidagi oqim
docker logs omniroute --tail 50   # Oxirgi 50 ta satr
```

### Maʼlumotlar bazasini qoʻlda zaxiralash

```bash
# Maʼlumotlarni jilddan xostga nusxalash
docker cp omniroute:/app/data ./backup-$(date +%F)

# Yoki butun jildni siqish
docker run --rm -v omniroute-data:/data -v $(pwd):/backup \
  alpine tar czf /backup/omniroute-data-$(date +%F).tar.gz /data
```

### Zaxira nusxasidan tiklash

```bash
docker stop omniroute
docker run --rm -v omniroute-data:/data -v $(pwd):/backup \
  alpine sh -c "rm -rf /data/* && tar xzf /backup/omniroute-data-YYYY-MM-DD.tar.gz -C /"
docker start omniroute
```

```bash
cat > /etc/nginx/cloudflare-ips.conf << 'CF'

set_real_ip_from 173.245.48.0/20;
set_real_ip_from 103.21.244.0/22;
set_real_ip_from 103.22.200.0/22;
set_real_ip_from 103.31.4.0/22;
set_real_ip_from 141.101.64.0/18;
set_real_ip_from 108.162.192.0/18;
set_real_ip_from 190.93.240.0/20;
set_real_ip_from 188.114.96.0/20;
set_real_ip_from 197.234.240.0/22;
set_real_ip_from 198.41.128.0/17;
set_real_ip_from 162.158.0.0/15;
set_real_ip_from 104.16.0.0/13;
set_real_ip_from 104.24.0.0/14;
set_real_ip_from 172.64.0.0/13;
set_real_ip_from 131.0.72.0/22;
real_ip_header CF-Connecting-IP;

```

`nginx.conf` faylidagi `http {}` blokiga quyidagini qoʻshing:

```nginx
include /etc/nginx/cloudflare-ips.conf;
```

### fail2ban'ni oʻrnatish

```bash
apt install -y fail2ban
systemctl enable fail2ban
systemctl start fail2ban

# Holatni tekshirish
fail2ban-client status sshd
```

### Docker portiga toʻgʻridan-toʻgʻri kirishni bloklash

```bash
# 20128-portga tashqaridan toʻgʻridan-toʻgʻri kirishni taqiqlash
iptables -I DOCKER-USER -p tcp --dport 20128 -j DROP
iptables -I DOCKER-USER -i lo -p tcp --dport 20128 -j ACCEPT

# Qoidalarni doimiy saqlash
apt install -y iptables-persistent
netfilter-persistent save
```

## Kam xotirali / kichik VPS uchun optimallashtirish

Kichik VPS nusxalarida (1 GB RAM yoki kamroq) joylashtirish uchun:

- **Fon xizmatlarini oʻchiring** — rejalashtiruvchi, MCP serveri va davriy texnik xizmat vazifalarini oʻtkazib yuborish uchun `OMNIROUTE_DISABLE_BACKGROUND_SERVICES=1` ni oʻrnating. `docs/reference/ENVIRONMENT.md` ga qarang.
- **SQLite WAL rejimidan foydalaning** — sukut boʻyicha yoqilgan va bir vaqtdagi oʻqishlar paytida xotiraning eng yuqori sarfini kamaytiradi.
- **V8 uyumini cheklang** — bajarilish muhiti VM hajmidan kattaroq chegarani hisoblamasligi uchun `OMNIROUTE_MEMORY_MB` ni (masalan, `512`) oʻrnating. `docs/reference/ENVIRONMENT.md` ga qarang.
- **Ogʻir soʻrovlarni qabul qilish uyum chegarasiga qarab avtomatik masshtablanadi** -- yuqorida `OMNIROUTE_MEMORY_MB` oʻrnatilgach, qabul qilinuvchi baytlar byudjeti (`OMNIROUTE_CHAT_MAX_INFLIGHT_BYTES`) ayni shu chegaradan kelib chiqadi, shu sababli xotirasi cheklangan VM hech qanday qoʻshimcha sozlashsiz bir vaqtdagi soʻrovlar uchun kichikroq byudjetga ega boʻladi; ortiqcha soʻrovlar xotira uchun raqobatlashish oʻrniga `Retry-After` bilan qayta urinish mumkin boʻlgan `503` javobini oladi. Bunga qoʻshimcha ravishda qatʼiy chegara kerak boʻlsagina eski `OMNIROUTE_CHAT_MAX_HEAVY_IN_FLIGHT` soʻrovlar soni chegarasini oʻrnating.
- **VPS da `next build` dan foydalanmang** — loyihani mahalliy muhitda yigʻing va mustaqil natijani (`.next/standalone/`) joylashtiring.
- **`top` / `free -m` orqali kuzating** — OmniRoute odatda 1 GB li VM da boʻsh turganida 200-400 MB RSS ishlatadi.
