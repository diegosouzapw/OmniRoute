Ushbu hujjat OmniRoute’ni Fly.io’ga amalda joylashtirish jarayonini quyidagi holatlar bo‘yicha tavsiflaydi:

- Joriy loyihani Fly.io’ga ilk bor joylashtirish
- Keyingi kod yangilanishlarini e’lon qilish
- Xuddi shu joylashtirish jarayonidan foydalanadigan yangi loyihalar

Ushbu qo‘llanma joriy loyiha uchun tekshirilgan va ishlaydigan konfiguratsiyaga asoslangan. Ilova nomi — `omniroute`.

---

## 1. Joylashtirish maqsadlari

- Platforma: Fly.io
- Joylashtirish usuli: Mahalliy `flyctl` orqali bevosita e’lon qilish
- Ishlash muhiti: Repozitoriydagi mavjud `Dockerfile` va `fly.toml` fayllaridan foydalanish
- Ma’lumotlarni doimiy saqlash: `/data` manziliga ulangan Fly Volume
- Kirish URL manzili: `https://omniroute.fly.dev/`

---

## 2. Joriy loyihaning asosiy konfiguratsiyasi

Joriy repozitoriydagi `fly.toml` quyidagi asosiy bandlarni o‘z ichiga olishi tasdiqlangan:

```toml
app = 'omniroute'
primary_region = 'sin'

[[mounts]]
  source = 'data'
  destination = '/data'

[processes]
  app = 'node run-standalone.mjs'

[http_service]
  internal_port = 20128

[env]
  TZ = "Asia/Shanghai"
  HOST = "0.0.0.0"
  HOSTNAME = "0.0.0.0"
  BIND = "0.0.0.0"
```

Izohlar:

- `app = 'omniroute'` joylashtirish qaysi Fly ilovasiga yo‘naltirilishini belgilaydi
- `destination = '/data'` doimiy jild ulanadigan katalogni belgilaydi
- Ushbu loyihada `DATA_DIR=/data` sozlanishi shart, aks holda ma’lumotlar bazasi va kalitlar konteynerning vaqtinchalik katalogiga yoziladi

### 4.2 Ilova nomini tasdiqlash

Agar o‘zingizning yangi ilovangizga joylashtirayotgan bo‘lsangiz, uni global miqyosda noyob nomga o‘zgartirishingiz mumkin, masalan:

```toml
app = 'omniroute-yourname'
```


Agar ilova nomini o‘zgartirgan bo‘lsangiz, `omniroute` o‘rniga tanlagan nomingizni kiriting.

```powershell
flyctl deploy
```

## 5. Majburiy parametrlar

Ushbu loyiha Fly.io’da kamida quyidagi parametrlarni sozlashni tavsiya qiladi.

### 5.1 Tekshirilgan parametrlar

Ushbu parametrlar joriy `omniroute` ilovasining amaldagi joylashtirishlarida ishlatilgan:

- `API_KEY_SECRET`
- `DATA_DIR`
- `JWT_SECRET`
- `MACHINE_ID_SALT`
- `NEXT_PUBLIC_BASE_URL`
- `OMNIROUTE_WS_BRIDGE_SECRET` (ishlab chiqarish muhitida majburiy — WebSocket ko‘prigini autentifikatsiya qilish uchun ishlatiladi)
- `STORAGE_ENCRYPTION_KEY`

### 5.2 `INITIAL_PASSWORD` haqida

Joriy loyihada `INITIAL_PASSWORD` sozlanmagan, chunki ushbu joylashtirish uchun u talab qilinmaydi.

Agar u sozlanmasa:

- Ishga tushirish jurnalida standart parol `CHANGEME` ekanligi ko‘rsatiladi
- Joylashtirishdan so‘ng imkon qadar tezroq tizim sozlamalarida kirish parolini o‘zgartirishingiz kerak

Agar backend parolini foydalanuvchi aralashuvisiz dastlabki sozlashni xohlasangiz, uni keyinroq qo‘shishingiz mumkin:

- `INITIAL_PASSWORD`

## 6. Tavsiya etilgan parametrlar

### 6.1 Sirlarni sozlash

Fly Secrets uchun quyidagi o‘zgaruvchilar tavsiya etiladi:

| O‘zgaruvchi                         | Tavsiya                     | Tavsif                                                        |
| ----------------------------------- | --------------------------- | ------------------------------------------------------------- |
| `API_KEY_SECRET`                    | Majburiy                    | API kalitini yaratish va tekshirish uchun ishlatiladi         |
| `JWT_SECRET`                        | Majburiy                    | Kirish seanslari va JWT imzolash uchun ishlatiladi            |
| `OMNIROUTE_WS_BRIDGE_SECRET`        | Ishlab chiqarishda majburiy | WebSocket ko‘prigini autentifikatsiya qilish siri             |
| `STORAGE_ENCRYPTION_KEY`            | Qat’iy tavsiya etiladi      | Saqlangan maxfiy ulanish ma’lumotlarini shifrlaydi            |
| `MACHINE_ID_SALT`                   | Tavsiya etiladi             | Barqaror mashina identifikatorini yaratadi                    |
| `INITIAL_PASSWORD`                  | Ixtiyoriy                   | Birinchi joylashtirishda dastlabki backend parolini o‘rnatadi |
| OAuth/API maxfiy hisob ma’lumotlari | Zaruratga qarab             | Tashqi platforma autentifikatsiyasi konfiguratsiyasi          |

### 6.2 Joriy loyiha uchun tavsiya etilgan qiymatlar

| O‘zgaruvchi            | Tavsiya etilgan qiymat      |
| ---------------------- | --------------------------- |
| `DATA_DIR`             | `/data`                     |
| `NEXT_PUBLIC_BASE_URL` | `https://omniroute.fly.dev` |

Izohlar:

- `DATA_DIR=/data` juda muhim va Fly Volume ulash nuqtasiga mos kelishi kerak
- `NEXT_PUBLIC_BASE_URL` rejalashtiruvchi, frontend qayta chaqiruvlari va shunga o‘xshash holatlarda ishlatiladi

### 6.3 OAuth qayta chaqiruv URL manzilini sozlash

Agar Fly.io joylashtirishida OAuth asosidagi provayderlarni (masalan, Antigravity, Gemini, Cursor) yoqishingiz kerak bo‘lsa, quyidagi ikki jihatga e’tibor bering:

1. **`NEXT_PUBLIC_BASE_URL` qiymatini ommaviy HTTPS domeningizga o‘rnating**

   ```powershell
   flyctl secrets set NEXT_PUBLIC_BASE_URL=https://omniroute.fly.dev -a omniroute
   ```

   Agar maxsus domendan foydalanayotgan bo‘lsangiz, uni tegishli domen bilan almashtiring (masalan, `https://omniroute.yourdomain.com`).

2. **Provayder konsolida qayta chaqiruv URL manzilini sozlang**

   Barcha OAuth provayderlari yagona `/callback` qayta chaqiruv yo‘lidan foydalanadi — har bir provayder uchun alohida qayta chaqiruv yo‘nalishi YO‘Q:

   ```text
   <NEXT_PUBLIC_BASE_URL>/callback
   ```

   Masalan, Gemini, Antigravity, Cursor yoki GitLab Duo bo‘lishidan qat’i nazar:
   - `https://omniroute.fly.dev/callback`

   Agar `NEXT_PUBLIC_BASE_URL` provayderda ro‘yxatdan o‘tkazilgan qayta chaqiruv URL manziliga mos kelmasa, OAuth jarayoni brauzerni qayta yo‘naltirish bosqichida muvaffaqiyatsiz tugaydi.

## 7. Sirlarni bitta buyruq bilan sozlash

Quyidagi buyruqlar xavfsiz tasodifiy qiymatlarni yaratadi va joriy loyiha uchun barcha majburiy parametrlarni bir bosqichda Fly Secrets’ga yozadi.

Izohlar:

- `INITIAL_PASSWORD` kiritilmagan
- Joriy `omniroute` loyihasi uchun mo‘ljallangan

```powershell
$apiKeySecret = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$jwtSecret = [Convert]::ToHexString((1..64 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$machineIdSalt = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$storageKey = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$wsBridgeSecret = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()

flyctl secrets set `
  API_KEY_SECRET=$apiKeySecret `
  JWT_SECRET=$jwtSecret `
  MACHINE_ID_SALT=$machineIdSalt `
  STORAGE_ENCRYPTION_KEY=$storageKey `
  OMNIROUTE_WS_BRIDGE_SECRET=$wsBridgeSecret `
  DATA_DIR=/data `
  NEXT_PUBLIC_BASE_URL=https://omniroute.fly.dev `
  -a omniroute
```

Linux / macOS tizimlarida `openssl rand -hex 32` buyrug‘idan ham foydalanishingiz mumkin:

```bash
flyctl secrets set OMNIROUTE_WS_BRIDGE_SECRET=$(openssl rand -hex 32) -a omniroute
```

Izohlar:

- `OMNIROUTE_WS_BRIDGE_SECRET` ishlab chiqarish muhitida majburiy; uning mavjud emasligi WebSocket ko‘prigi bilan qo‘l siqish jarayonini buzadi

Agar dastlabki parolni ham o‘rnatmoqchi bo‘lsangiz:

```powershell
flyctl secrets set INITIAL_PASSWORD=your-strong-password -a omniroute
```

## 9. Keyingi yangilanishlar va relizlar

Kod yangilangandan keyin reliz jarayoni oddiy:

```powershell
git pull
flyctl deploy
```

Agar kodni oʻzgartirmasdan faqat parametrlarni yangilash kerak boʻlsa:

```powershell
flyctl secrets set KEY=value -a omniroute
```

Fly mashinalarni avtomatik ravishda bosqichma-bosqich yangilaydi.

### 9.1 Forkingizdagi `fly.toml` faylini saqlagan holda yuqori oqim repozitoriysi yangilanishlarini kuzatish

Agar joriy repozitoriy fork boʻlsa va `https://github.com/diegosouzapw/OmniRoute` yuqori oqim repozitoriysidagi yangilanishlarni sinxronlashtirmoqchi boʻlsangiz, quyidagi ish jarayoniga amal qiling.

Avval masofaviy repozitoriylaringizni tekshiring:

```powershell
git remote -v
```

Kamida quyidagilar koʻrinishi kerak:

- `origin` oʻzingizning forkingizga ishora qilishi
- `upstream` asl repozitoriyga ishora qilishi

Agar `upstream` sozlanmagan boʻlsa, uni qoʻshing:

```powershell
git remote add upstream https://github.com/diegosouzapw/OmniRoute.git
```

Yuqori oqim bilan sinxronlashtirishdan oldin, eng soʻnggi commitlar va teglarni oling:

```powershell
git fetch upstream --tags
```

Joriy versiya va yuqori oqim teglarini tekshiring:

```powershell
git describe --tags --always
git show --no-patch --oneline v3.4.7
```

> Eslatma: Loyihaning joriy versiyasi `v3.8.0`. Quyidagi `v3.4.7` havolalari faqat tarixiy misollar sifatida saqlangan. Amaldagi relizlar uchun `:latest` yoki joriy versiya tegidan (masalan, `:v3.8.0`) foydalaning.

Agar forkingizdagi `fly.toml` faylini majburan saqlagan holda yuqori oqimdagi eng soʻnggi `main` tarmogʻini birlashtirmoqchi boʻlsangiz, quyidagi ish jarayoniga amal qiling:

```powershell
git merge upstream/main
git checkout HEAD~1 -- fly.toml
git add -- fly.toml
git commit -m "chore(deploy): keep fork fly.toml"
git push origin main
```

Eslatmalar:

- `git merge upstream/main` asl repozitoriydagi eng soʻnggi kodni sinxronlashtiradi
- `git checkout HEAD~1 -- fly.toml` forkingizning birlashtirishdan oldingi `fly.toml` faylini tiklaydi
- Agar yuqori oqimda `fly.toml` oʻzgartirilmagan boʻlsa, bu qadam hech qanday farq kiritmaydi
- Agar yuqori oqimda `fly.toml` oʻzgartirilgan boʻlsa, bu qadam Fly ilovangiz nomi, jild ulanishi, hududi va boshqa forkka xos joylashtirish sozlamalari ustiga yozilmasligini taʼminlaydi

Agar muayyan reliz tegiga (masalan, `v3.4.7`) moslashmoqchi boʻlsangiz, avval teg `upstream/main` tarkibiga allaqachon kiritilganini tekshiring:

```powershell
git merge-base --is-ancestor v3.4.7 upstream/main
```

Buyruq muvaffaqiyatli bajarilsa, `upstream/main` ushbu versiyani allaqachon oʻz ichiga olganini anglatadi; shunchaki `upstream/main` tarmogʻini birlashtirishingiz mumkin.

### 9.2 Yuqori oqim bilan sinxronlashtirilgandan keyingi standart reliz ketma-ketligi

Asl repozitoriy bilan sinxronlashtirilgandan keyin quyidagi tavsiya etilgan reliz tartibiga amal qiling:

1. `git fetch upstream --tags`
2. `git merge upstream/main`
3. Forkning `fly.toml` faylini tiklang
4. `git push origin main`
5. `flyctl deploy`
6. `flyctl status -a omniroute`
7. `flyctl logs --no-tail -a omniroute`

Bu joriy loyihani `v3.4.7` versiyasiga yangilashda amalda qoʻllangan ish jarayonidir (misol tarixiy versiyaga tegishli; joriy amaldagi versiya — `v3.8.0`).

## 11. Muvaffaqiyat koʻrsatkichlari

Muvaffaqiyatli joylashtirishdan soʻng jurnallarda quyidagiga oʻxshash mazmun koʻrsatilishi kerak:

```text
[bootstrap] Maxfiy maʼlumotlar quyidagi manzilda saqlandi: /data/server.env
[DB] SQLite maʼlumotlar bazasi tayyor: /data/storage.sqlite
```

Quyidagi ikki jihat juda muhim:

- `/data/server.env` bajarilish vaqtidagi maxfiy maʼlumotlar doimiy jildga yozilganini tasdiqlaydi
- `/data/storage.sqlite` maʼlumotlar bazasi doimiy jildga yozilganini tasdiqlaydi

Agar uning oʻrniga `/app/data/...` koʻrsatilsa, `DATA_DIR` notoʻgʻri sozlangan va darhol tuzatilishi kerak.

## 12. Keng tarqalgan muammolar

### 12.1 `Secrets` sahifasi boʻsh

Buning odatda ikkita sababi bor:

- Siz hali `flyctl secrets set` buyrugʻini bajarmagansiz
- Siz boshqa ilovani koʻryapsiz (masalan, `omniroute` oʻrniga `oroute`)

### 12.2 `flyctl deploy` buyrugʻi `app not found` xabarini beradi

Avval ilovani yarating:

```powershell
flyctl apps create omniroute
```

### 12.3 `fly.toml` faylini tahlil qilish muvaffaqiyatsiz tugaydi

Quyidagilarni tekshiring:

- Izohlarda buzilgan belgilar mavjud yoki mavjud emasligini
- TOML qoʻshtirnoqlari va chekinishlari toʻgʻri yoki notoʻgʻriligini

### 12.4 Maʼlumotlar doimiy saqlanmayapti

Quyidagilarning ikkalasini ham tekshiring:

- `fly.toml` faylida `destination = '/data'` mavjud
- `DATA_DIR` qiymati `/data` etib belgilangan

### 12.5 `INITIAL_PASSWORD`siz ishlay oladimi?

Ha, ishlay oladi. Bunday holatda standart `CHANGEME` parolidan foydalaniladi. Ishlab chiqarish muhitida backend parolini imkon qadar tezroq oʻzgartirish tavsiya etiladi.

---

## 13. Yangi loyihalar uchun qayta foydalanish

Agar ushbu hujjat boʻyicha yangi loyihani joylashtirayotgan boʻlsangiz, faqat quyidagilarni oʻzgartirishingiz kerak:

1. `fly.toml` faylidagi `app` qiymatini oʻzgartiring
2. `NEXT_PUBLIC_BASE_URL` qiymatini oʻzgartiring
3. `DATA_DIR=/data` qiymatini saqlab qoling
4. `API_KEY_SECRET`, `JWT_SECRET`, `MACHINE_ID_SALT` va `STORAGE_ENCRYPTION_KEY` qiymatlarini qayta yarating
5. Birinchi joylashtirishdan keyin jurnallar `/data` manziliga yozilayotganini tekshiring

Oldingi loyihaning kalitlarini qayta ishlatmang.

## 14. Joriy loyiha uchun minimal reliz nazorat roʻyxati

Keyingi relizlar uchun eng koʻp ishlatiladigan buyruqlar:

```powershell
flyctl auth whoami
flyctl status -a omniroute
flyctl secrets list -a omniroute
flyctl deploy
flyctl logs --no-tail -a omniroute
```

Oddiy reliz uchun asosiy buyruq:

```powershell
flyctl deploy
```

Yangi muhitga birinchi marta joylashtirish uchun asosiy qadamlar:

1. `flyctl auth login`
2. `flyctl apps create omniroute`
3. `flyctl secrets set ... -a omniroute`
4. `flyctl deploy`
5. `flyctl logs --no-tail -a omniroute`
