Tavsiya etilgan boshlang‘ich ko‘rsatkich — optimallashtirish uchun asos bo‘ladigan ko‘rsatkich.

## Qoidalar

- Qamrov maqsadlari `tests/**`ga emas, manba fayllariga nisbatan qo‘llanadi.
- `open-sse/**` mahsulotning bir qismi va qamrov doirasida qolishi shart.
- Yangi kod o‘zgartirilgan sohalardagi qamrovni kamaytirmasligi kerak.
- Amalga oshirish tafsilotlaridan ko‘ra xatti-harakatlar va tarmoq natijalarini sinashni afzal ko‘ring.
- `src/lib/db/**` uchun keng qamrovli moklardan ko‘ra vaqtinchalik SQLite ma’lumotlar bazalari va kichik test ma’lumotlarini afzal ko‘ring.

## Joriy buyruqlar to‘plami

- `npm run test:coverage`
  - Birlik testlari to‘plami uchun asosiy manba qamrovi nazorat chegarasi
  - `text-summary`, `html`, `json-summary` va `lcov`ni yaratadi
- `npm run coverage:report`
  - Eng so‘nggi ishga tushirishdan olingan, har bir fayl bo‘yicha batafsil hisobot
- `npm run test:coverage:legacy`
  - Faqat tarixiy taqqoslash uchun

## Ratchet siyosati

`npm run test:coverage` chegaralarini faqat loyiha keyingi bosqichdan yetarlicha zaxira bilan amalda oshib o‘tgandan keyin yangilang.

**Joriy chegara:** `npm run test:coverage` **60 ta bayonot / 60 ta satr / 60 ta funksiya / 60 ta tarmoq** talabini qo‘llaydi (ko‘rsatkich Quality-Gates 6A.1-bosqichida qayta bazalangan — avvalgi 82.58% bazaviy ko‘rsatkichi test fayllarini hisobga olgani va `open-sse`ni istisno qilgani sababli sun’iy ravishda yuqori edi). `test:coverage:legacy` buyrug‘i tarixiy taqqoslash uchun eski 50/50/50 ko‘rsatkichini saqlab qoladi.

Eng so‘nggi hisobot asosida maxsus chegara tekshiruvlari uchun quyidagidan foydalaning:

```bash
node scripts/check/test-report-summary.mjs --threshold 75
```

## Ma’lum kamchilik

Joriy qamrov buyrug‘i asosiy Node modul testlari to‘plamini o‘lchaydi va u orqali qamrab olingan manba kodini, jumladan `open-sse`ni ham o‘z ichiga oladi.
