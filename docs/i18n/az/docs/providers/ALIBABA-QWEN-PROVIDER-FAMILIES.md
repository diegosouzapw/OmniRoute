Bu sənəd
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854) üçün implementasiya qərarını qeydə alır. İctimai məhsullar dörd provayder ailəsi kimi təqdim olunur. Region ayrıca məhsul deyil, bağlantı məlumatıdır.

## Qərar

| Provayder ailəsi                                    | OmniRoute ID-si         | Qlobal region | Çin regionu |
| --------------------------------------------------- | ----------------------- | ------------- | ----------- |
| Alibaba Cloud Model Studio (istifadəyə görə ödəniş) | `alibaba`               | Sinqapur      | Pekin       |
| Alibaba Cloud Token Plan                            | `bailian-coding-plan`   | Sinqapur      | Pekin       |
| Qwen Cloud (istifadəyə görə ödəniş)                 | `qwen-cloud`            | Qlobal        | Pekin       |
| Qwen Cloud Token Plan                               | `qwen-cloud-token-plan` | Sinqapur      | Pekin       |

Mövcud `alibaba-cn` ID-si saxlanılmış bağlantılar, model marşrutları, kombinasiyalar və tarixi istifadə məlumatları üçün icra zamanı uyğunluq aliası olaraq qalır. Onun idarəetmə panelindəki kartı `alibaba` kartına birləşdirilir; verilənlər bazasının yenidən yazılması tələb olunmur.

Qwen Cloud-un istifadəyə görə ödənişli məhsulu və Alibaba Cloud Model Studio hazırda DashScope ilə uyğun icra hostlarını paylaşır, lakin istifadəçilər açarları fərqli məhsul interfeyslərindən əldə etdikləri və hesabları həmin interfeyslər vasitəsilə idarə etdikləri üçün onlar ayrı-ayrı provayder identifikatorları olaraq qalır. Alibaba və Qwen Cloud Token Plan məhsulları fərqli son nöqtə ailələrindən istifadə etdiyinə görə, dörd məhsulun hamısı ayrıca provayder ID-ləri olaraq qalır.

## Son nöqtələr matrisi

| Provayder ailəsi        | `global-sg`                                                              | `china-beijing`                                                      | Məlumat mübadiləsi formatı |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | -------------------------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI                     |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic                  |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI                     |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI                     |

API açarı və son nöqtə eyni məhsula və regiona aid olmalıdır. Regionun seçilməsi doğrulama və adi sorğular üçün istifadə edilən əvvəlcədən təyin edilmiş son nöqtəni dəyişir.

## Bağlantı müqaviləsi

Yeni bağlantılar sabit region açarını `providerSpecificData` daxilində saxlayır:

```json
{
  "region": "global-sg"
}
```

İcazə verilən dəyərlər `global-sg` və `china-beijing`-dir. Son nöqtə provayder ID-si və region əsasında mərkəzləşdirilmiş şəkildə müəyyən edilir. Əvvəlcədən təyin edilməmiş `providerSpecificData.baseUrl` açıq operator əvəzetməsi olaraq qalır və üstünlüyə malikdir; köhnə saxlanılmış əvvəlcədən təyin edilmiş URL-lər isə yenidən regional matrisə uyğun normallaşdırılır.

Bu, bağlantı sxeminin genişləndirilə bilməsini təmin edir: başqa bir region yeni provayder kartı yaratmadan və ya saxlanılmış provayder ID-lərini dəyişdirmədən rezolverə əlavə edilə bilər.

## Uyğunluq və tətbiqə buraxılma

1. Regional son nöqtə həlledicisini əlavə edin və mövcud qlobal standartları saxlayın.
2. `alibaba`, onun `alibaba-cn` uyğunluq ID-si və `qwen-cloud` üçün canlı regional DashScope `/models` aşkarlanmasından istifadə edin. Ümumi son nöqtə şəkil, video, audio, embedding və digər çat olmayan modelləri də qaytardığı üçün onların cavabları əvvəlcə mətn generasiyası filtrindən keçir. Bundan sonra `qwen-cloud` öz provayder reyestrində elan edilmiş və dəstəklənən icazə siyahısını tətbiq edir. Alibaba Model Studio və Qwen Cloud hazırda eyni icra zamanı hostlarından istifadə etsələr də, ayrı-ayrı seçilmiş kataloqları saxlayırlar.
3. `qwen-cloud-token-plan` identifikatorunu cari Token Plan mətn modeli icazə siyahısı ilə qeydiyyatdan keçirin.
4. Bağlantı əlavə etmə/redaktə etmə dialoqlarına tipləşdirilmiş region seçicisi əlavə edin.
5. Təkrarlanan `alibaba-cn` kartını gizlədin və onun mövcud bağlantılarını `alibaba` provayder səhifəsinə daxil edin.
6. Təkmil və iş məkanına xas yerləşdirmələr üçün fərdi son nöqtə əvəzləmələrini əlçatan saxlayın.

Token Plan media modelləri xüsusi son nöqtələrdən istifadə etdikləri üçün çat kataloqundan kənarda qalır.
`wan2.7-image` və `wan2.7-image-pro` `open-sse/config/imageRegistry.ts` faylında qeydiyyatdan keçirilib;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` və `happyhorse-1.1-r2v` isə
`open-sse/config/videoRegistry.ts` faylında qeydiyyatdan keçirilib. Hər iki reyestr `qwen-cloud-token-plan` bağlantı
identifikatorundan və onun regiona xas giriş məlumatlarından təkrar istifadə edir.

Adi Qwen Cloud `qwen-cloud` identifikatoru altında ayrıca istifadəyə görə ödənişli şəkil və video kataloqlarına malikdir. Onun şəkil modelləri `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` və `z-image-turbo` modelləridir. Onun video
modelləri `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` və
`wan2.7-videoedit` modelləridir. Bu modellər yalnız adi `qwen-cloud` bağlantısından və regional
DashScope media son nöqtəsindən təkrar istifadə edir. Token Plan və istifadəyə görə ödənişli reyestrlər bir-birinin model siyahılarını miras almır və ya birləşdirmir.

`bailian-coding-plan` identifikatorunun da öz media icazə siyahıları var:
şəkil generasiyası üçün `wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` və `qwen-image-2.0-pro`,
video generasiyası üçün isə
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` və `happyhorse-1.1-r2v`.
O, yalnız Bailian Coding Plan bağlantısından və regional Coding Plan son nöqtəsindən istifadə edir.
Onun şəkil və video reyestrləri heç bir Qwen Cloud provayderindən miras almır və ya onlarla birləşmir.

Adi `alibaba` identifikatorunun ayrıca şəkil və video icazə siyahıları var. Onun şəkil modelləri
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` və `wan2.6-t2i` modelləridir. Onun əlavə edilmiş video modelləri `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` və `wan2.7-videoedit` modelləridir. Bu modellər yalnız Alibaba Model Studio
bağlantısından və onun seçilmiş regional media son nöqtəsindən istifadə edir; onlar heç bir Coding Plan və ya Qwen
Cloud reyestrinə əlavə edilmir.

Qwen Cloud Token Plan çat kataloqu Individual planının dəqiq sətir uyğunluğuna əsaslanan mətn icazə siyahısını izləyir:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` və
`deepseek-v4-pro`. Wan və HappyHorse qeydləri ayrıca şəkil/video generasiyası API-lərinə aiddir.

Alibaba Token Plan eyni altı cari mətn generasiyası model ID-sini
Anthropic-uyğun son nöqtəsi vasitəsilə təqdim edir. Onun Sinqapur seçimi mövcud `global-sg` region açarını saxlayır;
yalnız istifadəçiyə göstərilən etiket regionu Global adlandıran provayder ailələrindən fərqlənir.

Adi Qwen Cloud çat kataloqu qəsdən tam canlı mətn cavabından daha məhduddur. Onun
dəstəklənən icazə siyahısı `open-sse/config/providers/registry/qwen-cloud/index.ts` faylında yerləşir; canlı
aşkarlama yalnız həm yuxarı axın cavabında, həm də həmin reyestr siyahısında mövcud olan ID-ləri qaytarır.

Alibaba Model Studio `open-sse/config/providers/registry/alibaba/index.ts` faylında müstəqil şəkildə saxlanılan
icazə siyahısı ilə eyni canlı kəsişmə qaydasına əməl edir. `alibaba-cn` uyğunluq
provayderi aşkarlamanı Pekin son nöqtəsinə qarşı həll edərkən həmin kataloqdan təkrar istifadə edir.
