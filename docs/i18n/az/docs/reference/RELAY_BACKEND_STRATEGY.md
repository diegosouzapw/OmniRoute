## Xülasə

OmniRoute artıq `/api/v1/relay/chat/completions` üçün üç retranslyasiya rejimini dəstəkləyir:

- `ts`: TypeScript retranslyasiyasını proses daxilində istifadə edir.
- `bifrost`: Bifrost şlüzündən istifadəni məcburi edir.
- `auto`: Mövcud olduqda Bifrost-a üstünlük verir, nasazlıq zamanı TypeScript-ə geri keçir.

Yüksək sorğu tezliyi ilə işləyərkən (gündə çox sayda token, demək olar ki, fasiləsiz ötürmə qabiliyyəti) ən yaxşı strategiya ehtiyat yolu aydın və sürətli saxlamaqdır ki, intensiv istifadə olunan yol işləməyən yan prosesə görə heç vaxt bloklanmasın.

## Rejimlərin davranışı

- `ts`
  - Ən aşağı əməliyyat mürəkkəbliyi.
  - Bütün marşrutlaşdırma və doğrulama Node daxilində icra olunur.
  - Əlçatanlıq üçün yan prosesdən asılılıq yoxdur.
- `bifrost`
  - Bütün sorğuları yan proses şlüzündən keçməyə məcbur edir.
  - Avtomatik ehtiyat keçidi yoxdur.
  - Yalnız yan prosesin işləkliyinə və gecikməsinə zəmanət verildikdə faydalıdır.
- `auto`
  - Yan proses əlçatan və aktiv olduqda istifadə edilir.
  - Uğursuz cəhdlər ehtiyat keçid başlıqlarını işə salır və sorğuların uğurla tamamlanma müddətini məhdud saxlamaq üçün trafiki TS-ə qaytarır.
  - İşləmə müddətinin davamlılığı yalnız yan proses vasitəsilə ciddi marşrutlaşdırmadan daha vacib olduqda, bu rejim istehsal mühiti üçün ən təhlükəsiz seçimdir.

## Hazırda 9router və CLIPROXYAPI müqayisəsi

9router və CLIPROXYAPI tarixən yuxarı axın provayderləri üçün uyğunluq yolları təqdim etmiş inteqrasiyalardır.

- 9router yuxarı axın orkestrasiya və uyğunluq davranışı üçün daxilə yerləşdirilmiş yoldur.
- CLIPROXYAPI CLI / SDK tipli trafik üçün proksi API körpüsüdür.
- Xüsusi yan proses tipli keçid və aşağı gecikməli lokal yönləndirmə tələb olunduqda xariciləşdirilmiş yol kimi Bifrost sabitləşdirilir.

Hazırda 9router/CLIPROXYAPI müqayisəsi aparırsınızsa:

- Təhvil vermədən əvvəl sorğunun imzalanmasını, icazə siyahısı yoxlamalarını və DB siyasəti nəzarətlərini API marşrutunda saxlayın.
- İş axını yan prosesin ciddi istifadəsini və hər sorğu üzrə daha aşağı dəyişkənliyi tələb edirsə, `OMNIROUTE_RELAY_BACKEND=bifrost` istifadə edin.
- Hadisə şəraitində tədricən zəifləmə ilə yan proses dayanıqlılığına ehtiyacınız varsa, `OMNIROUTE_RELAY_BACKEND=auto` istifadə edin.

## Backend sərhədi müqaviləsi

Sabit məhsul sərhədi idarə panelinin reallaşdırılması deyil, OmniRoute retranslyasiya API-sidir. Next.js idarə paneli lokal xidmətləri quraşdıra, konfiqurasiya edə və nəzarətdə saxlaya bilər, lakin sorğu marşrutlaşdırması retranslyasiya API-si vasitəsilə daxil olmalı və həmin sərhədin arxasında təhvil verilməlidir.

Uzunmüddətli backend seçimləri:

- TypeScript retranslyasiyasını prosesdaxili siyasət və ehtiyat yol kimi saxlayın. Hər hansı backend-ə təhvil vermədən əvvəl autentifikasiya, icazə siyahıları, sorğuların normallaşdırılması, uçot və təhlükəsizlik yoxlamaları burada qalır.
- Yerləşdirmə daha aşağı marşrutlaşdırma dəyişkənliyi, mərkəzləşdirilmiş provayder rotasiyası və ya bir neçə OmniRoute replikası üzrə miqyaslanma tələb etdikdə, üstünlük verilən yüksək ötürmə qabiliyyətli Tier-1 yan prosesi kimi Bifrost-dan istifadə edin.
- 9router və CLIPROXYAPI-ni daxilə yerləşdirilmiş uyğunluq xidmətləri kimi saxlayın. Onlar nəzarət olunan lokal proseslər kimi işləyir və onların provayder/CLI davranışı arzu olunan adapter olduqda faydalıdır, lakin standart Tier-1 marşrutlaşdırma mühərrikinə çevrilməməlidirlər.
- İdarə panelinin intensiv istifadə olunan yola ixtiyari xidmət URL-ləri ötürməsinə imkan verməyin. UI tərəfindən təqdim olunan URL-lər konfiqurasiya girişləridir; marşrutlaşdırma kodu qeydiyyatdan keçmiş və işləkliyi yoxlanmış backend-ləri server tərəfli parametrlərdən və nəzarətçi vəziyyətindən müəyyən etməlidir.
- Hazırda nəzarət olunan xidmətlər üçün loopback HTTP-yə üstünlük verin, çünki idarə olunan proseslər artıq HTTP ilə uyğun API-lər təqdim edir, marşrut qoruyucusu sərhədi audit edə bilir və nasazlıq/ehtiyat keçid davranışı sorğu jurnallarında görünür. Gələcək SDK və ya soket nəqli yalnız izolyasiyanı və ya ehtiyat keçid semantikasını zəiflətmədən p99 marşrutlaşdırma gecikməsini nəzərəçarpacaq dərəcədə azaldarsa əlavə edilməyə dəyər.

Buna görə də çox yüksək ötürmə qabiliyyətli yerləşdirmə üçün standart cavab Bifrost aktiv edilmiş `auto` rejimidir: uğur göstəricisini qorumaq üçün TypeScript ehtiyat yolunu saxlayaraq intensiv istifadə olunan yolda Go yan prosesindən istifadə edin. `bifrost` rejimini yalnız yan prosesin ciddi və müstəsna istifadəsi tədricən zəifləmədən daha vacib olduqda istifadə edin.

## Yüksək ötürmə qabiliyyəti üçün tövsiyələr

Davamlı yüksək RPM/RPS və ciddi uğur SLO-su üçün:

1. Praktik gözləmə müddəti və nasazlıq telemetriyası ilə `auto` istifadə edin.
2. Yuxarı axın doğrulamasını və API açarı yoxlamalarını TypeScript marşrut sərhədində saxlayın.
3. Xəbərdarlıq sisteminizin ehtiyat keçid tezliyini və səbəblərini görməsi üçün aydın başlıqları/sayğacları aktivləşdirin.
4. Yan prosesin vaxt aşımı parametrlərini sonsuzadək gözləmək əvəzinə sürətlə uğursuz olmaq üçün tənzimləyin.
5. Xidmətin avtomatik yenidən başladılmasını və işləkliyin telemetriya dövrəsini sağlam saxlayın ki, ehtiyat keçid həqiqətən istisna hal olsun.

## Təklif edilən baza konfiqurasiyası

- `OMNIROUTE_RELAY_BACKEND=auto`
- `BIFROST_ENABLED=1`
- API açarlarını, icazə siyahısını, təmizləyicini və tezlik məhdudiyyəti yoxlamalarını marşrut emalçılarında aktiv saxlayın (onlar həmişə aşağı axına yönləndirmədən əvvəl icra olunur).
- Yan proses kəsintilərinin bir dəqiqə ərzində görünməsi üçün əks proksinizdən və sorğu jurnallarından ehtiyat keçid metriklərini ixrac edin.

## Provayder plagini müqaviləsi

Yan proseslər TypeScript icra mexanizminin daxili komponentlərindən asılı olmaq əvəzinə, provayder metadatasını JSON üçün təhlükəsiz provayder plagini
manifesti vasitəsilə idxal etməlidir. Yan proses
uyğunluğu müqaviləsi və miqrasiya mərhələləri üçün [Provayder Plagini Manifesti](./PROVIDER_PLUGIN_MANIFEST.md) sənədinə baxın.
