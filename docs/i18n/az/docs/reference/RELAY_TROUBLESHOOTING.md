Relelər (Vercel, Deno, Cloudflare) yuxarı axın bağlantısını serverless backend-də sonlandırır ki, OmniRoute provayderin API açarını server tərəfində saxlayaraq sabit regiondan çıxış edə bilsin. Bu sənəddə operatorların istehsal mühitində qarşılaşdığı iki nasazlıq rejimi və OmniRoute-un hər biri üçün təqdim etdiyi bərpa yolları izah olunur.

## Rele autentifikasiya məlumatlarının saxlanması

**Settings → Proxy Pool → Deploy Relay** bölməsindən rele yerləşdirdiyiniz zaman yerləşdirmə prosesi relenin autentifikasiya tokenini proksinin `notes` JSON sahəsində saxlayır:

- `STORAGE_ENCRYPTION_KEY` təyin edilibsə, token `relayAuthEnc` kimi yazılır
  (saxlanma zamanı AES ilə şifrələnir).
- Əks halda, o, açıq mətn şəklində `relayAuth` kimi yazılır.

Sorğu zamanı `extractRelayAuth(notes)` mövcud olan formanı qaytarır, buna görə də rele yenidən başlatmalardan sonra işləməyə davam edir.

## Nasazlıq rejimi 1 — açar rotasiyasından sonra deşifrə edilə bilməyən token

**Əlamət:** əvvəllər işləyən relelər mühitdə və ya məxfi məlumat menecerində `STORAGE_ENCRYPTION_KEY` rotasiyasından sonra yuxarı axından `401`/autentifikasiya xətaları qaytarır. Saxlanmış `relayAuthEnc` bloku artıq deşifrə edilə bilmir, buna görə `extractRelayAuth` boş sətir qaytarır və rele autentifikasiya məlumatı göndərmir.

**Bərpa — yerində təmir (yenidən yerləşdirmə olmadan):**

1. **Settings → Proxy Pool** bölməsini açın.
2. Autentifikasiya məlumatı olmayan rele sətirlərində sarı `auth missing` nişanı və
   **Repair** düyməsi göstərilir.
3. **Repair** düyməsinə klikləyin. OmniRoute
   `POST /api/settings/proxies/[id]/repair-relay` çağırışını edir və bu çağırış:
   - `relayAuthEnc` məlumatını **cari** açarla deşifrə edir,
   - açıq mətn şəklindəki `relayAuth` məlumatını yenidən `notes` sahəsinə yazır,
   - `{ repaired: true, mode: "recovered" }` qaytarır.

Rele heç bir yerləşdirmə giriş məlumatını yenidən daxil etmədən xidmət göstərməyə davam edir.

Bu, yalnız cari `STORAGE_ENCRYPTION_KEY` hələ də bloku deşifrə edə bildiyi halda işləyir. Açarı miqrasiya **etmədən** rotasiya etmisinizsə, bloku bərpa etmək mümkün deyil.

## Nasazlıq rejimi 2 — bərpa edilə bilməyən token (köhnə açar artıq mövcud deyil)

**Əlamət:** **Repair** düyməsinə klikləmisiniz və
`{ repaired: false, mode: "redeploy", status: 409 }` cavabını almısınız.

**Bərpa — yenidən yerləşdirmə:**

Saxlanmış token cari açarla bərpa edilə bilməz. Releni əvvəlcə istifadə etdiyiniz eyni modal pəncərədən (**Deploy Relay** menyusu → Vercel / Deno / Cloudflare) yenidən yerləşdirin. Yerləşdirmə prosesi yeni token yazır (cari açarla şifrələnmiş şəkildə) və sətirdəki `auth missing` nişanı yox olur.

İstifadəçi interfeysində tokeni bərpa etmək mümkün olmadıqda **Repair** düyməsinin özü yenidən yerləşdirmə modal pəncərəsini açır, buna görə onu əl ilə axtarmağa ehtiyac qalmır.

## Nasazlıq rejimi 3 — rele əlçatandır, lakin düzgün işləmir

**Əlamət:** proksi testi (`speed` düyməsi) relenin işlək olduğunu göstərir, lakin sorğular yenə də fasilələrlə uğursuz olur.

OmniRoute-un avtomatik test yoxlaması tərəfindən qaytarılan rele məlumatlılığı başlıqlarını yoxlayın
(**Settings → Proxy Pool** bölməsinə və `relayTested` / `relayAlive` sayğaclarına baxın):

- `x-relay-url` — hansı rele backend-inin cavab verdiyi.
- `x-relay-mode` — həmin sorğu üçün `ts` | `bifrost` | `auto`.
- `x-relay-attempts` — uğurlu nəticədən əvvəl neçə rele keçidinin sınaqdan keçirildiyi.
- `x-relay-fallback` — sorğu üstünlük verilən backend-dən TypeScript relesinə keçdikdə `true` olur.

Aşağı `relayAlive` göstəricisi ilə birlikdə yüksək `x-relay-fallback` tezliyi sidecar backend-inin işlək olmadığını göstərir və siz onu düzəltməli və ya rele backend strategiyasını `ts` olaraq dəyişməlisiniz (`RELAY_BACKEND_STRATEGY.md` sənədinə baxın).

## API arayışı

| Metod  | Yol                                       | Gövdə                   | Uğurlu nəticə                                                                                                                              | Uğursuz nəticə                                                                                   |
| ------ | ----------------------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| `POST` | `/api/settings/proxies/[id]/repair-relay` | `{ "id": "<proxyId>" }` | Yenidən əldə edildikdə `200 { repaired: true, mode: "recovered" }`; açıq mətn artıq mövcud olduqda `200 { repaired: false, mode: "noop" }` | Bərpa edilə bilmədikdə `409 { mode: "redeploy" }`; rele növü olmadıqda `400`; tapılmadıqda `404` |

Siyahı marşrutu `GET /api/settings/proxies` hər elementə məxfi məlumat ehtiva etməyən `relayInfo: { isRelay, authMissing, repairMode }` əlavə edir ki, idarəetmə paneli tokeni heç vaxt ifşa etmədən təmir imkanını göstərə bilsin.
