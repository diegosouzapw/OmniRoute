AgentBridge, IDE süni intellekt agentlərindən gələn HTTPS trafikini ələ keçirərək OmniRoute-un vahid marşrutlaşdırma mühərriki vasitəsilə yönləndirən MITM (Man-in-the-Middle) proksisidir. O, **10 IDE agentini** — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code və Trae (araşdırılır) — dəstəkləyir və bununla da OmniRoute-u bazarda süni intellekt kodlaşdırma köməkçiləri üçün ən geniş əhatə dairəsinə malik MITM proksisinə çevirir.

**İdarə panelindəki yeri:** `/dashboard/tools/agent-bridge`
**Yan panel qrupu:** Alətlər (Cloud Agents-dən sonra)
**Həmçinin baxın:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — ələ keçirilmiş bütün trafiki real vaxt rejimində izləyin; `docs/security/MITM-TPROXY-DECRYPT.md` (git; `/docs` daxilində kompilyasiya edilmir) — `/api/tools/agent-bridge/tproxy` marşrutu tərəfindən idarə olunan Linux TPROXY şəffaf deşifrləmə rejimi.

## §1 İcmal

### AgentBridge nədir?

IDE agenti (məsələn, GitHub Copilot, Cursor, Claude Code) API çağırışı etdikdə birbaşa yuxarı axın süni intellekt provayderinə (OpenAI, Anthropic və s.) qoşulur. AgentBridge bu bağlantını TLS səviyyəsində şəffaf şəkildə — agent konfiqurasiyasında heç bir dəyişiklik tələb etmədən — ələ keçirir və sorğunu OmniRoute vasitəsilə yenidən yönləndirir.

Bu o deməkdir ki, siz:

- **İstənilən agenti istənilən provayderə yenidən yönləndirə bilərsiniz**: Copilot OpenAI ilə əlaqə saxlayır? Onu Anthropic Claude, Gemini və ya OmniRoute-un 352 provayderindən hər hansı birinə yönləndirin.
- **Model uyğunlaşdırmalarını tətbiq edə bilərsiniz**: `gemini-3-flash` → `claude-sonnet-4.7` emalçı səviyyəsində şəffaf şəkildə.
- **Bütün agent trafikini müşahidə edə bilərsiniz**: ələ keçirilmiş hər bir sorğu [Traffic Inspector](./TRAFFIC_INSPECTOR.md)-da yayımlanır.
- **OmniRoute dayanıqlılığını tətbiq edə bilərsiniz**: kombinə edilmiş marşrutlaşdırma, dövrə açarları, ehtiyat keçidlər və xərc izləmə IDE agent trafiki üçün də işləyir.

## §2 Arxitektura

### 2.1 Komponentlərə ümumi baxış

```
IDE agenti (VS Code / Cursor / və s.)
    │  HTTPS (port 443)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← DNS yönləndirməsi
    │
    ▼
src/mitm/server.cjs  (port 443, CJS törəmə prosesi)
    │  hədəfi Host başlığının SNI dəyərinə əsasən müəyyən edir
    │  AgentBridge CA tərəfindən imzalanmış hər SNI üçün TLS sertifikatı yaradır
    ├── Yan keçmə siyahısına uyğundur? → TCP tranziti (şifrələmə açılmır)
    ├── Hədəfə uyğundur? → fetch → OmniRoute marşrutlayıcısı (port 20128)
    │       └── handler.intercept() — TypeScript
    │               ├── sorğu gövdəsində/başlıqlarında maskSecrets()
    │               ├── TrafficBuffer.push() — Traffic Inspector-a yayımlayır
    │               └── fetchRouter() → /v1/chat/completions
    └── Uyğunluq yoxdur? → TCP tranziti (şifrələmə açılmır)
```

### 2.2 MITM serveri (`src/mitm/server.cjs`)

Əsas MITM serveri Node.js CJS törəmə prosesi kimi işləyir (mövcud CJS kod bazasının yenidən yazılmasının qarşısını almaq üçün). O:

- 443 portunu dinləyir (imtiyaz və ya `authbind`/`setcap` tələb edir)
- Əməliyyat sistemindən CONNECT tunellərini qəbul edir (`/etc/hosts` DNS yönləndirməsi vasitəsilə)
- AgentBridge CA (`DATA_DIR/mitm/ca.crt`) tərəfindən imzalanmış hər SNI üçün TLS sertifikatları yaradır
- `targets/index.ts` reyestri vasitəsilə Host başlığına əsasən hədəf agenti müəyyən edir
- `http://127.0.0.1:20128` ünvanına HTTP vasitəsilə TypeScript emal qatına yönləndirir

`TARGET_HOSTS`, CJS serverini yenidən başlatmadan dinamik yeniləmələrə imkan verən `DATA_DIR/mitm/targets.json` faylından (başlanğıc zamanı `targets/index.ts` tərəfindən yazılır) yüklənir.

> **Kök CA modeli (#6684).** Yuxarıda təsvir edilən, hər SNI üçün CA tərəfindən
> imzalanmış sertifikat modeli #6684-də əlavə edilmiş qalıcı kök CA modelidir
> (`src/mitm/cert/rootCa.ts` + `src/mitm/_internal/rootCaShim.cjs`; burada
> `src/mitm/tproxy/dynamicCert.ts` daxilində TPROXY üçün artıq sınaqdan keçirilmiş
> CA/yarpaq kriptoqrafiyası təkrar istifadə olunur) — o, diskdə sadə
> `server.crt`/`server.key` cütlüyünün mövcudluğu ilə göstərilən, daha köhnə
> vahid statik özünü imzalamış yarpaq sertifikatını (`src/mitm/cert/generate.ts`,
> hələ də yalnız antigravity hostları ilə məhdudlaşır) əvəz edir.
> **Miqrasiya davranışı**: yeni quraşdırma (əvvəlki `server.crt` olmadan) kök CA
> modelini avtomatik əldə edir; köhnə statik yarpaq sertifikatına artıq etibar
> edən quraşdırma isə operator `MITM_ROOT_CA_ENABLED=true` təyin edib körpünü
> yenidən başladana qədər ondan istifadə etməyə davam edir
> (`src/mitm/cert/migration.ts` yalnız qərar verən saf funksiyadır — **istənilən**
> host üçün yarpaq sertifikatı imzalaya bilən etibarlı MITM CA köhnə, sabit SAN-lı
> yarpaq sertifikatından əhəmiyyətli dərəcədə daha güclüdür, buna görə artıq
> etibar edilmiş quraşdırmada keçid heç vaxt səssiz baş vermir). CA sertifikatı
> köhnə yarpaq sertifikatının istifadə etdiyi eyni `omniroute-mitm.crt` etibar
> anbarı yuvasına quraşdırılır (`cert/install.ts::installCaCert`) — ikili etibarın
> təmizlənməsinə ehtiyac yoxdur.

### 2.3 Emal bazası (`src/mitm/handlers/base.ts`)

Bütün agent emalçıları `MitmHandlerBase` sinfini genişləndirir:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // Qorunan köməkçilər: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

Hər bir emalçı proksiləmədən əvvəl `hookBufferStart()`, tamamlandıqda isə `hookBufferUpdate()` çağırır. Bunlar `InterceptedRequest` qeydlərini `globalTrafficBuffer` daxilinə ötürür (bax: [Traffic Inspector](./TRAFFIC_INSPECTOR.md) §4).

### 2.4 Hədəflər reyestri (`src/mitm/targets/`)

Hər agentin deklarativ hədəf faylı var:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

Reyestr (`targets/index.ts`) `ALL_TARGETS` ixrac edir və başlanğıc zamanı `DATA_DIR/mitm/targets.json` faylını yaradır.

### 2.5 Tranzit və yan keçmə siyahısı (`src/mitm/passthrough.ts`)

**Yan keçmə siyahısı** (əvvəlcə yoxlanılır və hədəf uyğunluğundan üstündür):

- Standart nümunələr: bank hostları, `.gov.`, OAuth/SSO provayderləri (Okta, Auth0) və s.
- İstifadəçi nümunələri: `agent_bridge_bypass` verilənlər bazası cədvəlində saxlanılır
- Yan keçilən hostlar şəffaf TCP tuneli əldə edir — TLS şifrəsi **heç vaxt açılmır**

**Standart tranzit** (hədəf uyğunluğu yoxdur və yan keçmə siyahısında deyil):

- Həmçinin TCP tuneli əldə edir — bağlantılar heç vaxt kəsilmir
- AgentBridge-in ümumi sistem HTTPS trafikini pozmasının qarşısını alır

Marşrutlaşdırma üstünlüyü:

```
yan keçmə siyahısı → hədəf uyğunluğu → tranzit
```

### 2.6 Yuxarı axın CA sertifikatı (`src/mitm/upstreamTrust.ts`)

Fərdi CA istifadə edən korporativ şəbəkə mühitləri üçün:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

Təyin edildikdə, `undici`-nin qlobal dispetçerini əlavə CA sertifikatı ilə konfiqurasiya edir və AgentBridge-in korporativ TLS sonlandırma proksiləri vasitəsilə yuxarı axın provayderlərinə çatmasına imkan verir.

### 2.7 Məxfi məlumatların maskalanması (`src/mitm/maskSecrets.ts`)

Müstəqil, təmiz otaq prinsipi ilə hazırlanmış skaner sorğu gövdələrinə və identifikasiya məlumatı başlıqlarına Traffic Inspector buferinə və ya hər hansı jurnala daxil olmalarından **əvvəl** tətbiq edilir. O, bir xətti keçid həyata keçirir:

- `sk-` / `ak-` / `pk-` prefiksli tokenlər (OpenAI/Anthropic üslubunda)
- Bütöv token üstünlüyü ilə RFC 6750 `Authorization: Bearer <token>` identifikasiya məlumatları
- Nöqtəli və doldurulmuş formalar daxil olmaqla, ümumi uzun qeyri-şəffaf tokenlər (≥40 simvol)

`sanitizeHeaders()` saxlanılan adları kiçik hərflərə çevirir, massiv dəyərlərini deterministik şəkildə birləşdirir, ortaq keçiddən-keçidə/çərçivələmə qadağa siyahısını (proksi autentifikasiyası daxil olmaqla) çıxarır, `cookie` və `set-cookie` dəyərlərini tamamilə redaktə edir və identifikasiya məlumatlarının dəyərlərini skanerə həvalə edir.

## §3 Quraşdırma

### 3.1 MITM serverini başladın/dayandırın

`/dashboard/tools/agent-bridge` ünvanındakı AgentBridge Server Card-dan istifadə edin:

| Əməl                        | Təsvir                                                                              |
| --------------------------- | ----------------------------------------------------------------------------------- |
| Serveri başladın            | 443 portunda `src/mitm/server.cjs` prosesini yaradır                                |
| Serveri dayandırın          | Alt prosesi təhlükəsiz şəkildə dayandırır                                           |
| Serveri yenidən başladın    | Dayandırır + başladır (hədəf dəyişikliklərini tətbiq edir)                          |
| Sertifikata etibar edin     | `DATA_DIR/mitm/ca.crt` faylını ƏS-in etibar deposuna quraşdırır                     |
| Sertifikatı endirin         | Əl ilə quraşdırmaq üçün `ca.crt` faylını endirir                                    |
| Sertifikatı yenidən yaradın | Yeni CA açar cütü yaradır (agentlər üçün mövcud bütün sertifikatlar etibarsız olur) |

### 3.2 Sertifikata etibar edin

IDE-lərin MITM bağlantısını qəbul etməsi üçün AgentBridge CA sertifikatına əməliyyat sistemi tərəfindən etibar edilməlidir.

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Keychain):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

Yaxud idarəetmə panelindəki "Sertifikata etibar edin" düyməsindən istifadə edin (ƏS-iniz üçün uyğun əmri icra edir və lazım olduqda sudo sorğusu göstərir).

#### Electron əsaslı IDE-lər ƏS-in etibar deposunu nəzərə almır (`NODE_EXTRA_CA_CERTS`)

Bəzi IDE-lər — xüsusilə **Antigravity IDE** və digər Electron / VS Code əsaslı tətbiqlər — çıxış
`fetch`/HTTPS sorğuları üçün **ƏS-in etibar deposuna müraciət etməyən** öz Node.js icra mühitlərini
özlərində birləşdirir. CA-ya ƏS/NSS səviyyəsində etibar edilməsi IDE-nin yerli **backend**-i
üçün (məsələn, ƏS-in CA paketindən istifadə edən Go dil serveri) kifayətdir, lakin **Electron frontend**
yenə də TLS xətası verəcək — MITM jurnalı backend-in ilkin yükləmə çağırışlarının `200` qaytardığını
göstərsə belə, bu, tətbiqdə hesabdan _çıxılmış_ vəziyyət və ya _"bağlantı xətası"_ kimi görünür. İki addım
tələb olunur və hər ikisi vacibdir:

1. İcra mühitinə CA-nı açıq şəkildə göstərin:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **IDE-ni həmin shell-dən başladın.** Onu iş masası ikonundan / Dock-dan / Start menyusundan
   başlatmaq shell export-larını **ötürmür**, `~/.config/environment.d/*.conf` isə yalnız
   yeni qrafik girişdən sonra tətbiq olunur. Əvvəlcə IDE-dən tamamilə çıxın — Electron-un singleton kilidi
   səbəbindən ikinci başlatma sadəcə mövcud prosesi ön plana keçirir və yeni mühit nəzərə alınmır.

Yuxarıdakı ƏS etibarı + NSS addımı yenə də zəruridir (bəzi autentifikasiya axınlarının istifadə etdiyi
Chromium şəbəkə steki istifadəçi üzrə NSS deposunu oxuyur və `*.googleapis.com` üçün lokal olaraq
etibar edilən CA-nın ləğv etdiyi öz statik pin-lərinə malikdir). `NODE_EXTRA_CA_CERTS` isə əlavə olaraq
Node `fetch` yolunu əhatə edir.

### 3.3 DNS yönləndirilməsi

Ələ keçirmək istədiyiniz hər agent üçün onun API host-u və ya host-ları `127.0.0.1` ünvanına həll olunmalıdır. Quraşdırma sehrbazında agent üçün DNS-i aktivləşdirib-deaktivləşdirdiyiniz zaman AgentBridge `/etc/hosts` qeydlərini avtomatik idarə edir.

GitHub Copilot üçün nümunə `/etc/hosts` qeydləri:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 Model uyğunlaşdırılması

Mənbə → hədəf uyğunluqlarını müəyyənləşdirmək üçün hər agent kartındakı Model Mapping Table-dan istifadə edin:

| Mənbə modeli (agentə məxsus) | Hədəf modeli (OmniRoute) |
| ---------------------------- | ------------------------ |
| `gpt-4o`                     | `claude-sonnet-4.7`      |
| `*` (əvəzedici simvol)       | `claude-haiku-4.7`       |

`*` əvəzedici simvolu tanınmayan istənilən modeli göstərilən hədəfə uyğunlaşdırır. `agent_bridge_mappings` cədvəlində saxlanılır.

> **Məsləhət — agentin həqiqi model ID-lərini müəyyənləşdirin.** IDE, interfeysindəki etiketlərdən fərqlənən
> və əsas versiyalar arasında dəyişən model adları göndərə bilər. Məsələn, **Antigravity 2** şəbəkə üzərindən
> köhnə sənədlərdə göstərilən `gemini-2.5-pro` deyil, `gemini-3.1-pro-low`, `gemini-pro-agent` və
> `gemini-3.1-flash-lite` göndərir. Uyğun uyğunlaşdırma olmadan bir söhbət göndərin: MITM dəqiq daxil olan
> `model:` dəyərini jurnala yazır və sorğunu dəyişdirmədən ötürür. Həmin literal dəyəri uyğunlaşdırın, bundan
> sonra növbəti sorğu ələ keçirilərək hədəfinizə yönləndiriləcək.

### 3.5 Risk bildirişi

AgentBridge IDE-nin yuxarı səviyyəli provayderlərdə autentifikasiya üçün istifadə etdiyi giriş məlumatlarını (OAuth tokenləri, API açarları) ələ keçirir. Bunlar **jurnala yazılmadan əvvəl maskalanır** (§2.7-yə baxın), lakin OmniRoute-un MITM qatına görünür. Hər agent ilk dəfə aktivləşdirildikdə bağlana bilən risk bildirişi modal pəncərəsi göstərilir.

### 3.6 Texniki xidmət və diaqnostika

İdarəetmə panelində əvvəllər istifadəçi interfeysi olmayan əməliyyat MITM marşrutlarını təqdim edən **Maintenance & Diagnostics** kartı (`AgentBridgeMaintenanceCard`, `src/app/(dashboard)/dashboard/tools/agent-bridge/components/` daxilində) mövcuddur. Onun alt başlığı: _"Ələkeçirmə konveyerini özünü sınaqdan keçirin, sistemdə qalan vəziyyəti geri qaytarın və quraşdırmanızı maşınlar arasında köçürün."_ Kartın klient köməkçi funksiyaları `src/lib/inspector/agentBridgeMaintenanceApi.ts` daxilində yerləşir.

| Düymə                        | Marşrut                                | Nə edir                                                                                                                                                                                                                           |
| ---------------------------- | -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Diaqnostika**              | `GET /api/tools/agent-bridge/diagnose` | Tutma konveyerinin özünü sınağını işə salır və hər yoxlama üzrə hesabat göstərir (✓/✗ + aradan qaldırma ipucu).                                                                                                                   |
| **Təmir**                    | `POST /api/tools/agent-bridge/repair`  | Qəza və ya SIGKILL-dən sonra qalmış sahibsiz MITM sistem vəziyyətini (DNS saxtalaşdırma qeydləri, kök CA, sistem proksisi) geri qaytarır. İdempotentdir — vəziyyət təmiz olduqda "Təmir ediləcək heç nə yoxdur" hesabatını verir. |
| **CA-nı sil**                | `DELETE /api/tools/agent-bridge/cert`  | MITM kök CA-sını ƏS-in etibar deposundan çıxarır və silir (aşkar, idempotent). Yalnız CA hazırda etibarlı olduqda göstərilir; sətirdaxili "CA silinsin?" təsdiqi tələb edir.                                                      |
| **Konfiqurasiyanı ixrac et** | `GET /api/tools/agent-bridge/config`   | Portativ konfiqurasiya JSON-unu endirir (bax: §3.7).                                                                                                                                                                              |
| **Konfiqurasiyanı idxal et** | `POST /api/tools/agent-bridge/config`  | Əvvəllər ixrac edilmiş konfiqurasiya JSON-unu yükləyir (bax: §3.7).                                                                                                                                                               |

**Diaqnostika yoxlamaları** (`src/mitm/inspector/diagnostics.ts` daxilində `summarizeDiagnostics()`). Marşrut hər biri üçün təsirli yoxlamanı işə salır və Bul qiymətlərini saf yekunlaşdırıcıya ötürür; vahid `healthy` qərarı və hər nasazlıq üçün ipucu qaytarılır:

| Yoxlama adı        | Nəyi yoxlayır                                                    | Nasazlıq zamanı ipucu                                                                                                                                  |
| ------------------ | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `server-running`   | MITM server prosesi aktivdir                                     | "MITM serveri işləmir. Onu AgentBridge nişanından başladın."                                                                                           |
| `server-reachable` | MITM serveri öz portunda bağlantıları qəbul edir (TCP yoxlaması) | "MITM serveri öz portunda bağlantıları qəbul etmir. Portun boş olduğunu və ona bağlanmaq üçün lazımi imtiyazlara sahib olduğunuzu yoxlayın."           |
| `cert-exists`      | MITM sertifikatı diskdə yaradılıb                                | "Hələ heç bir MITM sertifikatı yaradılmayıb. AgentBridge nişanından sertifikat yaradın."                                                               |
| `cert-trusted`     | MITM kök CA-sı ƏS-in etibar deposundadır                         | "MITM kök CA-sına ƏS deposu etibar etmir, buna görə TLS ələkeçirməsi uğursuz olacaq. AgentBridge nişanından sertifikata etibar edin."                  |
| `dns-configured`   | Hədəf host adları `/etc/hosts` daxilində saxtalaşdırılıb         | "Hədəf host adları /etc/hosts daxilində saxtalaşdırılmayıb, buna görə trafik proksiyə çatmır. Tutmaq istədiyiniz agent(lər) üçün DNS-i aktivləşdirin." |

**Sahibsiz vəziyyət banneri:** səhifə qəza nəticəsində qalmış vəziyyəti (DNS saxtalaşdırması / CA / sistem proksisi) aşkar etdikdə kart kəhrəba rəngli banner göstərir — _"Əvvəlki sessiyadan qalan sistem vəziyyəti var (DNS saxtalaşdırması, CA və ya sistem proksisi). Onu təmizləmək üçün Təmiri işə salın."_ — və **Təmir** düyməsini vurğulayır. `Repair`, ProxyBridge-in `--cleanup` bayrağının tətbiq qatı analoqudur (`src/mitm/manager.ts` daxilində `repairMitm()` funksiyasına həvalə edir).

> Təkrar sudo sorğularının qarşısını almaq üçün MITM kök CA-sı dayandırma/başlatma
> arasında quraşdırılmış vəziyyətdə saxlanılır (mitmproxy/Charles ilə eyni davranış),
> buna görə onun silinməsi dayandırma zamanı avtomatik baş verən əməliyyat deyil,
> aşkar **CA-nı sil** əməliyyatıdır.

### 3.7 Portativ konfiqurasiyanın idxalı/ixracı

AgentBridge, quraşdırmanın maşınlar arasında təkrarlana bilməsi üçün **operator tərəfindən tənzimlənə bilən** vəziyyəti versiyalaşdırılmış JSON blobuna seriallaşdıra bilər. Seriallaşdırıcı `src/lib/inspector/configPortability.ts` faylıdır (`exportConfig()` / `importConfig()`), doğrulama isə `AgentBridgeConfigSchema` tərəfindən həyata keçirilir.

İxraca dəqiq olaraq üç hissə daxildir (daxili standart dəyərlər qəsdən ixrac **EDİLMİR**, beləliklə idxal onları heç vaxt təkrarlamır və ya onlarla ziddiyyət yaratmır):

| Sahə             | Mənbə                                                                              | Qeydlər                                                                     |
| ---------------- | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `bypassPatterns` | istifadəçi tərəfindən müəyyən edilmiş yan keçmə nümunələri (`agent_bridge_bypass`) | standart bank/gov/okta nümunələri daxil edilmir                             |
| `customHosts`    | Traffic Inspector fərdi hostları (`inspector_custom_hosts`)                        | hər biri: `{ host, kind: "llm"\|"app"\|"custom", label? }`                  |
| `agentMappings`  | hər agent üzrə model uyğunlaşdırmaları (`agent_bridge_mappings`)                   | uyğunlaşdırmaları olan hər agent üçün `{ [agentId]: [{ source, target }] }` |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**İdxal davranışı** (`POST /api/tools/agent-bridge/config`): yan keçmə nümunələri və hər agent üzrə uyğunlaşdırmalar **tam şəkildə əvəz olunur**; fərdi hostlar **idempotent şəkildə** əlavə edilir (`INSERT OR IGNORE`). Cavab hər birindən neçəsinin tətbiq edildiyini bildirir:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

Konfiqurasiyaya **DAXİL OLMAYANLAR**: serverin işləmə vəziyyəti, sertifikat yolları, hər agent üzrə DNS vəziyyəti, yuxarı axın CA yolu və TPROXY parametrləri — bunlar daşına bilən seçimlər deyil, host/işləmə mühiti vəziyyətidir.

### Həssas hostlar üçün yan keçmə siyahısı

Yan keçmə siyahısı maliyyə təşkilatlarının, OAuth/SSO provayderlərinin və digər həssas hostların **heç vaxt deşifrə edilməməsini** təmin edir. Onların TLS trafiki şəffaf TCP tuneli vasitəsilə ötürülür — OmniRoute açıq mətni heç vaxt görmür.

Defolt yan keçmə nümunələrinə daxildir:

- `*.bank.*`, `*.gov.*` (maliyyə/dövlət)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/identifikasiya)
- `*.apple.com`, `*.icloud.com` (Apple sistem xidmətləri)

İstifadəçinin əlavə etdiyi yan keçmə nümunələri `agent_bridge_bypass` cədvəlində saxlanılır və hər şeydən üstün tutulur.

### Məxfi məlumatların maskalanması

`src/mitm/maskSecrets.ts` faylındakı `maskSecrets()` tətbiq edilir:

- `TrafficBuffer.push()` çağırışından əvvəl hər sorğu gövdəsinə
- Jurnala yazılmadan və ya yayımlanmadan əvvəl hər başlığa

Nümunələr: `sk-`/`ak-`/`pk-` prefiksli tokenlər, `Bearer` tokenləri və uzunluğu ≥40 simvol olan ümumi tokenlər.

### Yuxarı axın CA sertifikatı

`AGENTBRIDGE_UPSTREAM_CA_CERT` təyin edildikdə fayl işə salınma zamanı oxunur. Yol mövcuddursa, lakin fayl oxuna bilmirsə, AgentBridge aydın xəta qeydə alır və işə başlamaqdan imtina edir (korporativ mühitlərdə səssiz TLS xətalarının qarşısını alır).

### Məlum məhdudiyyətlər

- **443-cü port imtiyaz tələb edir**: Linux-da AgentBridge üçün Node binar faylında `setcap 'cap_net_bind_service=+ep'` tələb olunur və ya `authbind` vasitəsilə işə salınmalıdır. Quraşdırma sehrbazı əməliyyat sisteminə xas təlimatları göstərir.
- **IDE-ni yenidən başlatmaq tələb olunur**: DNS yönləndirməsindən sonra yeni host həllinin qüvvəyə minməsi üçün IDE yenidən başladılmalıdır.
- **Sərt kodlaşdırılmış OAuth tokenləri**: Bəzi agentlər (Kiro, Antigravity) OAuth yeniləmə tokenlərini lokal olaraq saxlayır. Bunlar AgentBridge üçün şəffafdır — o, hər sorğuda `Bearer` tokenini görür və token jurnala yazılmazdan əvvəl maskalanır.
- **Electron interfeysləri üçün `NODE_EXTRA_CA_CERTS` tələb olunur**: İnterfeysi paketlənmiş Node/Electron icra mühitində işləyən IDE-lər əməliyyat sisteminin/NSS-in etibar anbarını nəzərə almır və `NODE_EXTRA_CA_CERTS` təyin edilmiş shell-dən başladılmalıdır (§3.2-yə baxın). Təyin edilmədikdə müşahidə olunan əlamət: IDE-nin arxa tərəfi autentifikasiyadan keçir (MITM `200` cavablarını göstərir), lakin istifadəçi interfeysi sistemdən çıxmış vəziyyətdə qalır.
- **Eyni IDE-nin bir neçə quraşdırması bir-birindən asılı deyil**: sistem quraşdırması (məsələn, `/usr/share/antigravity/antigravity`) və istifadəçinin lokal „Full“ quraşdırması (məsələn, `~/AntigravityIDE_Full/antigravity-ide`) öz icra mühitlərinə malik ayrı-ayrı proseslərdir — hər biri CA daxil edilməklə yenidən başladılmalıdır. Yenidən başlatmazdan əvvəl hansının işlədiyini binar faylının yolu ilə müəyyənləşdirin.
- **Kimlik yönləndirilmiş model tərəfindən deyil, agentin sistem promptu tərəfindən təyin edilir**: agentin modelini başqa provayderə uyğunlaşdırdığınız zaman cavab yenə də agentin ilkin kimliyinə aid olduğunu bildirir (məsələn, Antigravity „Mən Gemini tərəfindən dəstəklənirəm“ cavabını verir), çünki IDE bunu sistem promptuna daxil edir. Həqiqi arxa tərəfi modeldən kim olduğunu soruşmaqla deyil, `call_logs` / `proxy_logs` daxilində (`provider`, `model`, `target_format`) yoxlayın.

## §6 Nasazlıqların aradan qaldırılması

### Port 443 münaqişəsi

Əgər başqa bir proses artıq port 443-ü dinləyirsə (veb server, VPN və s.):

```bash
lsof -i :443          # prosesi tapın
sudo fuser -k 443/tcp  # məcburi dayandırın (ehtiyatla istifadə edin)
```

Alternativ olaraq, AgentBridge parametrlərində imtiyaz tələb etməyən port konfiqurasiya edin və `iptables` / `pf` yönləndirmə qaydaları qurun.

### Sertifikata etibar edilmir

AgentBridge işə salındıqdan sonra IDE TLS xətaları göstərirsə:

1. Sertifikatın quraşdırıldığını yoxlayın: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) və ya `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. Bəzi tətbiqlər öz etibar anbarını saxlayır (Firefox, Linux-da Chrome). "Trust Cert" əməliyyatını yenidən başladın və NSS/Firefox-a məxsus sertifikat anbarını yoxlayın.
3. Etibar verdikdən sonra IDE-ni yenidən başladın — davam edən TLS sessiyaları köhnə etibar vəziyyətindən istifadə edir.

### Etibarlı CA olmasına baxmayaraq IDE-dən çıxış edilib / "connection error"

Əlamət: DNS yönləndirildikdən və CA-ya etibar verildikdən sonra Electron əsaslı IDE (məsələn, Antigravity) **hesabdan çıxmış** vəziyyətdə açılır və ya autentifikasiya/bağlantı xətası göstərir, lakin MITM jurnalı başlanğıc çağırışlarının (`loadCodeAssist`, `fetchAvailableModels`, …) `200` cavabı qaytardığını göstərir.

Səbəb: IDE-nin **daxilində gələn Node/Electron icra mühiti əməliyyat sisteminin etibar anbarını nəzərə almır**. Yerli bekend (Go dil serveri) əməliyyat sisteminin CA-sına etibar edir və autentifikasiyadan keçir, lakin Electron frontendi bunu etmir — buna görə də UI oflayn olduğunu düşünür.

Həll (hər iki addım): `NODE_EXTRA_CA_CERTS=<ca.crt>` dəyişənini ixrac edin **və IDE-ni masaüstü ikonundan deyil, həmin shell-dən yenidən başladın**. Əvvəlcə IDE-dən tam çıxın — Electron-un tək nüsxə kilidi səbəbindən ikinci işəsalma yalnız mövcud prosesi ön plana gətirir və yeni mühit nəzərə alınmır. §3.2-yə baxın. Bu, ayrıca agentin MITM vasitəsilə işlədiyi, lakin IDE variantının eyni quraşdırmada uğursuz olduğu açıq upstream hesabatındakı vəziyyətə uyğundur.

### DNS yayılmayıb

`/etc/hosts` faylının yeniləndiyini yoxlayın:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

DNS keşini təmizləyin:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### IDE aşkarlanmayıb

Avtomatik aşkarlama standart quraşdırma yollarından istifadə edir. Aşkarlama uğursuz olarsa, lakin IDE quraşdırılıbsa:

- IDE binar faylının qeyri-standart yerdə olub-olmadığını yoxlayın
- Quraşdırma köməkçisi yenə də işləyir — aşkarlamanın uğursuz olması sadəcə nişanda quraşdırma yolunun göstərilməyəcəyi deməkdir

### Emalçı xətaları (upstream sorğusu uğursuz olur)

AgentBridge sorğuları ələ keçirir, lakin bütün sorğular uğursuz olursa:

1. `/dashboard/providers` ünvanında ən azı bir provayderin qoşulduğunu yoxlayın
2. OmniRoute server jurnallarını yoxlayın: `.env` daxilində `APP_LOG_LEVEL=debug`
3. `OMNIROUTE_BASE_URL` dəyişəninin düzgün router son nöqtəsinə yönəldiyini yoxlayın (standart: `http://127.0.0.1:20128`)

## §8 Yol xəritəsi

### Trae araşdırması

Trae nisbətən yeni süni intellekt əsaslı kodlaşdırma köməkçisidir. Emal modulunu tətbiq etməzdən əvvəl:

1. VS Code / JetBrains marketlərində və ya ayrıca tətbiq kimi binar faylı/genişləndirməni müəyyənləşdirin
2. API hostlarını və endpoint strukturlarını aşkar etmək üçün trafiki mitmproxy ilə qeydə alın
3. Autentifikasiya mexanizmini müəyyənləşdirin
4. İstifadə şərtləri və API-nin aşkarlana bilməsi əsasında davam edib-etməmək barədə qərar verin

Araşdırma tamamlanana qədər idarəetmə panelindəki Trae kartında "Həyata keçirilə bilməsi barədə hesabat verin" keçidi ilə birlikdə "Araşdırılır" nişanı göstərilir. `src/mitm/handlers/trae.ts` ünvanındakı emal modulu şablonu strukturlaşdırılmış `Hələ tətbiq edilməyib` xətası yaradır.

### Gözləyən agentlər (MITM tələb olunur — fərdi baza URL-i dəstəklənmir)

Aşağıdakı alətlər cari versiyalarında fərdi baza URL-lərini dəstəkləmir, buna görə də MITM yeganə ələkeçirmə yoludur. Həyata keçirilmə imkanının qiymətləndirilməsi gözlənilir:

- **Windsurf** (Codeium/Cognition)
- **Amp** (Sourcegraph)
- **Amazon Q / Kiro CLI** (AWS Bedrock — Kiro IDE-dən ayrıdır)
- **Cowork** (Anthropic masaüstü tətbiqi)

Qeyd: GitHub Copilot CLI ≥v1.0.19 `COPILOT_PROVIDER_BASE_URL` dəyişənini dəstəkləyir — həmin alət üçün MITM əvəzinə birbaşa konfiqurasiyadan istifadə edin.
