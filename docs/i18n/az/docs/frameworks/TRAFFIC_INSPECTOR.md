Traffic Inspector OmniRoute-un daxili HTTPS trafik sazlama alətidir — Charles Proxy / mitmweb / HTTP Toolkit-ə bənzər, **LLM-lərdən xəbərdar** və **agentlərdən xəbərdar** bir alətdir. O, `/dashboard/tools/traffic-inspector` ünvanında yerləşir və eyni vaxtda 5-ə qədər trafik ələkeçirmə mənbəyindən canlı trafik qəbul edir.

**İdarəetmə panelindəki yeri:** `/dashboard/tools/traffic-inspector`
**Yan panel qrupu:** Alətlər (AgentBridge-dən sonra)
**Həmçinin baxın:** [`AGENTBRIDGE.md`](./AGENTBRIDGE.md) — AgentBridge 1-ci ələkeçirmə rejimidir.

### Bir abzasda arxitektura

`TrafficBuffer` (`src/mitm/inspector/buffer.ts`) ortaq, yaddaşdaxili halqavari buferdir (standart olaraq 1000 qeyd; `INSPECTOR_BUFFER_SIZE` vasitəsilə konfiqurasiya edilə bilər). Bütün ələkeçirmə mənbələri `push()` vasitəsilə ona yazır. Bufer hər qeydi `kindDetector.ts` istifadə edərək təsnif edir (onun LLM sorğusu olub-olmadığını müəyyənləşdirir), `contextKey` hesablayır (sistem göstərişinin SHA-256 rəqəmsal izi) və `globalTrafficBuffer.subscribe()` vasitəsilə bütün WebSocket abunəçilərinə yayımlayır. İdarəetmə paneli `GET /api/tools/traffic-inspector/ws` vasitəsilə qoşulur və qoşulma zamanı ani görüntü, ardınca isə `new`/`update`/`clear` hadisələrini qəbul edir.

## §2 Tutma rejimləri

Traffic Inspector **eyni vaxtda 5 tutma mənbəyini** dəstəkləyir. Hər biri müstəqil şəkildə aktivləşdirilə və deaktivləşdirilə bilər. Hər `InterceptedRequest` (`src/mitm/inspector/types.ts`) daxilindəki `source` sahəsi `"agent-bridge"`, `"custom-host"`, `"http-proxy"`, `"system-proxy"` və ya `"tproxy"` dəyərlərindən biridir.

### Rejim 1 — AgentBridge (standart, həmişə aktiv)

**Mənbə:** AgentBridge işləyiciləri (`src/mitm/handlers/base.ts`)
**Mexanizm:** `MitmHandlerBase` daxilində hər `intercept()` çağırışı yönləndirmədən əvvəl `hookBufferStart()`, tamamlandıqda isə `hookBufferUpdate()` çağırır. Heç bir əlavə konfiqurasiya tələb olunmur — AgentBridge işə düşən kimi işləyir.
**Əhatə dairəsi:** AgentBridge-də konfiqurasiya edilmiş 9 IDE agenti
**Qeyd:** `InterceptedRequest` daxilindəki `source` sahəsi = `"agent-bridge"`

### Rejim 2 — Fərdi hostlar (DNS yönləndirməsi)

**Mənbə:** İstifadəçi tərəfindən müəyyən edilmiş host siyahısı (`inspector_custom_hosts` cədvəli)
**Mexanizm:** UI vasitəsilə host əlavə edildikdə `/etc/hosts` faylına `127.0.0.1 <host>` əlavə olunur (sudo tələb edir). Mövcud AgentBridge MITM serveri (port 443) yeni host üçün dinamik olaraq SNI sertifikatı yaradır.
**Əhatə dairəsi:** Əlavə edilmiş hostdan istifadə edən istənilən tətbiq — tətbiq konfiqurasiyasını dəyişməyə ehtiyac yoxdur
**Qeyd:** `source` = `"custom-host"`

İstifadə nümunələri:

- Python skriptlərindən `api.openai.com` trafikini izləmək
- `my-internal-llm.company.com` ünvanında sazlama aparmaq
- Eyni şəbəkədəki mobil cihazlardan gələn trafiki tutmaq (ARP saxtalaşdırması vasitəsilə — qabaqcıl)

### Rejim 3 — HTTP_PROXY dinləyicisi (port 8080)

**Mənbə:** `HTTP_PROXY`/`HTTPS_PROXY` mühit dəyişənlərindən istifadə edən tətbiqlər
**Mexanizm:** Standart açıq HTTP/HTTPS proksisi kimi fəaliyyət göstərən 8080 portundakı ikinci dərəcəli dinləyici (`src/mitm/inspector/httpProxyServer.ts`). `CONNECT` tunellərini (HTTPS) və birbaşa HTTP sorğularını qəbul edir.
**Əhatə dairəsi:** `HTTP_PROXY` mühit dəyişənini nəzərə alan istənilən tətbiq — DNS dəyişikliyi və sudo tələb olunmur
**Qeyd:** `source` = `"http-proxy"`

```bash
# Tək bir əmr üçün sürətli tutma:
HTTPS_PROXY=http://127.0.0.1:8080 curl https://api.openai.com/v1/models

# Shell sessiyasında daimi tutma:
export HTTP_PROXY=http://127.0.0.1:8080
export HTTPS_PROXY=http://127.0.0.1:8080
```

**TLS məhdudiyyəti:** HTTPS `CONNECT` tunelləri yalnız metadata (host, port, vaxt göstəriciləri) kimi tutulur — standart olaraq TLS gövdəsinin şifrəsi açılmır. Gövdəni tam yoxlamaq üçün "Proksi rejimində HTTPS-in şifrəsini aç" keçidini aktivləşdirin (istəyə bağlıdır, AgentBridge sertifikatına etibar edilməsini tələb edir).

**Port münaqişəsi:** 8080 portu istifadədədirsə, AgentBridge strukturlaşdırılmış xəta ilə 409 cavabı qaytarır. Portu `INSPECTOR_HTTP_PROXY_PORT` mühit dəyişəni vasitəsilə dəyişdirin.

### Rejim 4 — Sistem miqyaslı proksi (qabaqcıl, istəyə bağlı)

**Mənbə:** ƏS səviyyəli proksi parametrləri (maşındakı bütün tətbiqlərə şamil olunur)
**Mexanizm:** Bütün HTTP/HTTPS trafikini HTTP_PROXY dinləyicisi vasitəsilə yönləndirmək üçün ƏS API-lərindən istifadə edir:

- **macOS:** `networksetup -setwebproxy / -setsecurewebproxy`
- **Linux:** `gsettings set org.gnome.system.proxy` + `/etc/environment`
- **Windows:** `netsh winhttp set proxy 127.0.0.1:8080`
  **Əhatə dairəsi:** Maşında sistem proksi parametrlərini nəzərə alan hər bir tətbiq
  **Qeyd:** `source` = `"system-proxy"`

**Təhlükəsizlik mexanizmləri:**

- Avtomatik deaktivləşdirmə taymeri (standart olaraq 30 dəqiqə, `INSPECTOR_SYSTEM_PROXY_GUARD_MINUTES` vasitəsilə konfiqurasiya edilə bilər)
- Əvvəlki sistem proksi vəziyyəti verilənlər bazasında saxlanılır və geri qaytarılarkən bərpa olunur
- İstifadəçi aktiv olduğu müddətdə səhifədən ayrılarsa, idarəetmə paneli "Sistem proksisi geri qaytarılır" bildirişini göstərir
- UI `⚠ Qabaqcıl` nişanını və açıq təsdiq xanasını göstərir

### Rejim 5 — TPROXY şəffaf şifrəaçma (Linux, root, istəyə bağlı)

**Mənbə:** Kernel TPROXY + siyasət əsaslı marşrutlaşdırma (`src/mitm/tproxy/`)
**Mexanizm:** `mangle OUTPUT` daxilində hədəf porta (standart olaraq `443`) açılan yeni lokal çıxış TCP bağlantılarını işarələyir, `ip rule` işarələnmiş paketləri lokal çatdırılmaya yönləndirir və `mangle PREROUTING` bölməsinin `TPROXY` hədəfi onları şəffaf (**IP_TRANSPARENT**) dinləyiciyə (standart port `8443`) ötürür. Dinləyici dinamik CA tərəfindən **hər SNI host adı üçün tələb əsasında** verilən yarpaq sertifikatı ilə TLS-i sonlandırır, şifrəsi açılmış mübadiləni tutur və sorğunu yenidən şifrələyərək ilkin təyinat nöqtəsinə yönləndirir.
**Əhatə dairəsi:** Hədəf portdakı **istənilən** təyinat hostu — `/etc/hosts` saxtalaşdırması, `HTTP_PROXY` mühit dəyişəni və sistem miqyaslı proksi dəyişikliyi tələb olunmur. Tutulan proses üçün konfiqurasiya dəyişikliyi lazım deyil, lakin o, dinamik CA-ya etibar etməlidir.
**Qeyd:** `source` = `"tproxy"`

**Tələblər:** Yalnız Linux (**IP_TRANSPARENT** yalnız Linux-da mövcuddur), **CAP_NET_ADMIN** imkanı (root) və C alətlər dəsti ilə yığılmalı olan yerli N-API əlavəsi (`npm run build:native:tproxy`). Əlçatan olmadıqda idarəetmə panelindəki keçid "TPROXY şifrəaçması Linux + root + yerli əlavə tələb edir" alət ipucu ilə deaktiv edilir. Fayervol qaydaları tranzaksiyalı şəkildə tətbiq edilir/geri qaytarılır (nasazlıq heç vaxt geridə `mangle` qaydası saxlamır) və yenidən başlatma zamanı təmizlənir. SO_MARK əsaslı dövrə əleyhinə mexanizm proksinin öz yenidən şifrələnmiş yönləndirməsinin təkrar tutulmasının qarşısını alır.

Bu, özünə məxsus ayrıca operator təlimatı olan əhəmiyyətli bir altsistemdir — fayervol üzrə tam göstərişlər, hər SNI üçün dinamik CA + etibar anbarı quraşdırıcısı, yalnız lokal marşrut, dövrə əleyhinə təfərrüatlar və konfiqurasiya sxemi üçün `docs/security/MITM-TPROXY-DECRYPT.md` sənədinə baxın (git; `/docs` daxilinə kompilyasiya edilmir). Keçid `GET / POST / DELETE /api/tools/agent-bridge/tproxy` tərəfindən idarə olunur (qeyd: marşrut Traffic Inspector prefiksi deyil, AgentBridge prefiksi altında yerləşir).

### 3.2 Sorğu siyahısı (sol panel)

- **Virtuallaşdırılmışdır** (`useVirtualList` + `ResizeObserver`): donmadan 1000 elementi idarə edir
- Yoxlama zamanı dayandırmaq üçün keçid ilə **avtomatik sürüşdürmə**
- **Statusların rənglə kodlanması**: yaşıl (2xx), sarı (3xx), qırmızı (4xx/5xx), boz (icra olunur)
- **Agent emojisi**: 🔵 Antigravity, 🟢 Copilot, 🟠 Kiro, 🟣 Codex, 🔷 Cursor, 🟤 Zed, 🟡 Claude Code, ⚫ Open Code, 🌐 fərdi host
- **Kontekst rəng zolağı**: `contextKey` (sistem sorğusunun SHA-256 heşi) ilə rənglənmiş 1px-lik sol haşiyə — əlaqəli söhbətləri vizual olaraq qruplaşdırır
- **Tənbəl gövdə yüklənməsi**: təfərrüat vərəqlərində yalnız seçilmiş sorğunun gövdəsi materiallaşdırılır (1000 × 1MB həcmində gövdələrin render edilməsinin qarşısını alır)

## §4 LLM-dən xəbərdar funksiyalar

### 4.1 Növ aşkarlayıcısı (`src/mitm/inspector/kindDetector.ts`)

Hər sorğunu 4 siqnaldan istifadə etməklə `"llm"`, `"app"` və ya `"unknown"` kimi təsnif edir:

1. **Host reyestri** — ~18 məlum LLM API host adı (OpenAI, Anthropic, Gemini, Groq, Mistral, Together, Fireworks, Cohere, Perplexity, Hugging Face, OpenRouter, xAI, Moonshot və s.)
2. **Yol nümunələri** — `/v1/chat/completions`, `/v1/messages`, `/generateContent`, `/v1/responses` və s.
3. **Gövdə quruluşu** — `messages[]` (OpenAI/Claude), `contents[]` (Gemini), `prompt`, `input` sahələrini aşkarlayır
4. **User-agent ipucları** — UA sətrində `codex`, `claude`, `gemini`, `antigravity`, `kiro`, `copilot`, `cursor`

Mode 2 vasitəsilə əlavə edilən fərdi hostlar öz `kind` dəyərini forma girişindən miras alır (standart olaraq `"custom"`).

### 4.2 SSE birləşdiricisi (`src/mitm/inspector/sseMerger.ts`)

**Müstəqil, sıfırdan hazırlanmış tətbiq.** Hadisələrin təhlili
[WHATWG server tərəfindən göndərilən hadisələr alqoritminə](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream)
uyğun aparılır, rekonstruksiya isə ictimai [OpenAI](https://platform.openai.com/docs/api-reference/chat/create),
[Anthropic](https://platform.claude.com/docs/en/build-with-claude/streaming) və
[Gemini](https://ai.google.dev/api/generate-content#method:-models.streamgeneratecontent)
axın sxemlərinə əsaslanır.

Xam SSE delta hadisələrindən yekun assistent mesajını rekonstruksiya edir:

- **Anthropic**: `content_block_delta` dəyərlərini indeks üzrə toplayır; `text_delta`, `input_json_delta` (alət çağırışları), `thinking_delta` növlərini emal edir
- **OpenAI**: Chat Completions seçimlərini/alət çağırışlarını və Responses API çıxış elementlərini
  indeks üzrə toplayır
- **Gemini**: `candidates[i].content.parts` dəyərlərini toplayır
- **Naməlum**: xam hadisələri olduğu kimi qaytarır

Response tabında keçid göstərilir: **"Xam hadisələr ↔ Birləşdirilmiş"**.

### 4.3 Söhbət normallaşdırıcısı (`src/mitm/inspector/conversationNormalizer.ts`)

**Müstəqil, sıfırdan hazırlanmış tətbiq.** Normallaşdırma lokal qara qutu
müqavilələri və ictimai OpenAI, Anthropic və Gemini mesaj sxemləri ilə müəyyən edilir;
heç bir yuxarı axın tətbiqinin mənbə kodundan istifadə olunmur.

OpenAI, Anthropic və Gemini mesaj formatlarını render etməzdən əvvəl vahid `NormalizedConversation` formatına çevirir:

```ts
interface NormalizedConversation {
  request: NormalizedTurn[]; // sorğu gövdəsindən messages / contents / prompt
  response: NormalizedTurn[]; // assistent cavabı (sseMerger vasitəsilə birləşdirilir)
  contextKey: string | null; // sistem promptunun SHA-256 rəqəmsal izi
}
```

Blok növləri: `text`, `tool_use`, `tool_result`. Conversation tabı provayderdən asılı olmayaraq bu quruluşdan istifadə edir.

### 4.4 Kontekst açarının rəngləndirilməsi (`src/mitm/inspector/contextKey.ts`)

- Sistem promptunun `SHA-256` dəyərini hesablayır (ilk `role:system` mesajı, yaxud `system` sahəsi, yaxud Gemini `systemInstruction`)
- 12 simvoldan ibarət onaltılıq prefiks qaytarır (`"a3f9c2..."`)
- Frontend sol haşiyə zolağı üçün açarı deterministik HSL rənginə uyğunlaşdırır
- **"Eyni kontekst" filtri**: `ctx #a3f` çipinə klikləmək yalnız eyni rəqəmsal izə malik sorğuları göstərən filtr əlavə edir

Bu, eyni agent sessiyasında işləyən müxtəlif "personaları" və ya tapşırıqları vizual olaraq asanlıqla fərqləndirməyə imkan verir.

### 4.5 LLM metadata-sının çıxarılması

LLM sorğuları üçün LLM Details tabı aşağıdakı məlumatları çıxarır:

```ts
interface LlmMetadata {
  provider: string | null; // "openai" | "anthropic" | "gemini" | ...
  apiKind: string | null; // "chat.completions" | "messages" | "embeddings" | ...
  model: string | null; // sorğu gövdəsindən və ya cavabdan
  messages: number; // növbələrin sayı
  tokensIn: number | null; // usage.prompt_tokens / usage.input_tokens
  tokensOut: number | null; // usage.completion_tokens / usage.output_tokens
  streamed: boolean; // SSE cavabıdırsa true
  mappedTo: string | null; // x-omniroute-mapped başlığı
  costEstimateUsd: number | null; // OmniRoute qiymətlərinə əsaslanan təxmini xərc
}
```

### 4.6 Aktiv icra olunan sorğular üçün canlı filtr

Sorğunun `status` sahəsi `number | "in-flight" | "error"` növündədir — sorğu başlayan
kimi qeyd `"in-flight"` statusu ilə əlavə edilir və cavab (və ya xəta) gəldikdə
**yerində yenilənir**. Alətlər panelindəki **"Canlı"** keçidi
(`liveOnly`, i18n açarı `trafficInspector.liveOnly`) siyahını
`status === "in-flight"` olan qeydlərlə məhdudlaşdıraraq açıq bağlantıları real vaxtda
izləməyə imkan verir.

Filtr `src/lib/inspector/matchesTrafficFilter.ts` faylında yerləşən saf, müştəri tərəfində işləyən predikatdır:

```ts
if (f.liveOnly && req.status !== "in-flight") return false;
```

Keçidin vəziyyəti `useTrafficFilters` daxilində (inspektor idarəetmə panelinin hukları)
saxlanılır və digər filtrlərlə (profil, host, agent, mənbə, status, kontekst) birlikdə
işləyir.

### 4.7 Prosesə aidetmə (Linux)

Linux-da ələ keçirilən hər bir sorğu **onu yaradan lokal
prosesə** aid edilə bilər. `InterceptedRequest` strukturuna iki istəyə bağlı sahə əlavə olunur:

```ts
pid?: number;          // sorğunu yaradan prosesin identifikatoru (yalnız Linux)
processName?: string;  // sorğunu yaradan prosesin adı (yalnız Linux)
```

`src/mitm/inspector/processAttribution.ts` bağlantının _müştəri_
efemer portunu PID + adla aşağıdakı qaydada uyğunlaşdırır:

1. Port üçün soket inode-unu tapmaq məqsədilə `/proc/net/tcp` və `/proc/net/tcp6`
   fayllarını oxuyur (`parseProcNetTcpForInode`, fiksturlarla sınaqdan keçirilə bilən saf parser).
2. `socket:[<inode>]` simvolik keçidini tapmaq üçün `/proc/<pid>/fd/` qovluğunu skan edir.
3. Prosesin adını `/proc/<pid>/comm` faylından oxuyur.

1 saniyəlik TTL keş yük altında procfs skanının xərcini məhdudlaşdırır. Aidetmə
**mümkün olduğu qədər** həyata keçirilir — istənilən uğursuzluq `null` ilə nəticələnir və
ələ keçirməni heç vaxt bloklamır. macOS/Windows sistemlərində funksiya `null` qaytarır
(stub; `lsof`/`GetExtendedTcpTable` dəstəyi sonrakı işdir).

## §5 Sessiyalar

### 5.1 Sessiyanın qeydə alınması

1. Alətlər panelində **"● Sessiyanı qeydə al"** düyməsinə klikləyin → ad daxil edin (istəyə bağlıdır)

### 5.2 Qeydə alınmış sessiyaya baxış

- Banner göstərilir: `Qeydə alınmış "<ad>" sessiyasına baxılır — [Canlı rejimə qayıt]`
- Recharts aqreqatları ilə Statistika tabı əlçatan olur

### 5.3 İxrac formatları

Hər sessiya aşağıdakı formatlarda ixrac edilə bilər:

| Format                     | İstifadə                                                                         |
| -------------------------- | -------------------------------------------------------------------------------- |
| **HAR** (HTTP Archive 1.2) | Chrome DevTools, Charles və Fiddler ilə uyğundur — oflayn təhlil üçün idxal edin |

## §6 Təhlükəsizlik

Traffic Inspector avtorizasiya başlıqları və sorğu gövdələri daxil olmaqla, **ələ keçirilmiş bütün HTTPS trafikini** göstərir. Aşağıdakı nəzarət mexanizmləri tətbiq edilir:

| Nəzarət mexanizmi                           | Təfərrüatlar                                                                                                                                                                                               |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LOCAL_ONLY**                              | Bütün marşrutlara və WebSocket son nöqtəsinə yalnız loopback vasitəsilə giriş mümkündür (autentifikasiyadan əvvəl `routeGuard.ts` daxilində məcburi şəkildə tətbiq edilir)                                 |
| **Məxfi məlumatların maskalanması**         | Xətti `maskSecret()` skaneri RFC 6750 Bearer giriş məlumatlarını, provayder prefiksli açarları və uzun qeyri-şəffaf tokenləri `TrafficBuffer.push()` çağırışından əvvəl redaktə edir                       |
| **Gövdə ölçüsü limiti**                     | `INSPECTOR_MAX_BODY_KB` həddindən böyük gövdələr (standart olaraq 1024 KB) `"(performans üçün qısaldılıb)"` bildirişi ilə qısaldılır                                                                       |
| **Başlıqların sanitizasiyası**              | Adlar kiçik hərflərə çevrilir; çərçivələmə/hop-by-hop və proksi autentifikasiyası başlıqları silinir; kukilər tamamilə redaktə edilir; giriş məlumatlarının dəyərləri `maskSecret()` funksiyasına ötürülür |
| **CSP**                                     | Daxil edilmiş cavab gövdələri vasitəsilə XSS hücumlarının qarşısını almaq üçün Traffic Inspector səhifələrində sərt Content Security Policy tətbiq edilir                                                  |
| **Standart olaraq davamlı saxlanma yoxdur** | `TrafficBuffer` yaddaşdaxilidir və server yenidən başladıldıqda itirilir. Sessiyalar yalnız açıq şəkildə qeydə alındıqda davamlı yaddaşda saxlanılır                                                       |

### Tətbiq edilən sərt qaydalar

| Qayda                             | Tətbiqi                                                                                      |
| --------------------------------- | -------------------------------------------------------------------------------------------- |
| **#12** `sanitizeErrorMessage`    | Traffic Inspector marşrutlarından gələn bütün HTTP xəta cavabları sanitizasiya edilir        |
| **#15 + #17** `isLocalOnlyPath()` | `/api/tools/traffic-inspector/` LOCAL_ONLY + SPAWN_CAPABLE-dır (sistem proksisi komandaları) |

### Məlum məhdudiyyətlər

- **Sistem miqyaslı proksi rejimi** VPN klientləri və SSO daxil olmaqla, maşındakı bütün tətbiqlərə təsir edir. Həmişə avtomatik söndürmə taymeri ilə istifadə edin. Paylaşılan maşınlarda istifadə etməyin.
- **CONNECT tuneli üzərindən HTTPS**: TLS ələ keçirilməsi aktiv edilmədiyi halda, Rejim 3 (HTTP_PROXY) HTTPS təyinatları üçün yalnız tunel metadatasını ələ keçirir. Bu, layihələndirmədən irəli gəlir — AgentBridge sertifikatına etibar edilmədən şəffaf ələ keçirmə həmin tətbiqlər üçün TLS yoxlamasını pozardı.
- **Bəzi komponentlərdə sərt kodlaşdırılmış sətirlər**: Bəzi UI komponentlərində (F7/F8) hələ i18n açarları ilə əhatə olunmayan az sayda sərt kodlaşdırılmış sətir var. Bunlar i18n boşluqları hesabatında Məlum Məhdudiyyət kimi sənədləşdirilib; növbəti mərhələdə miqrasiya ediləcək. Təsirə məruz qalan sətirlər funksional istifadə üçün tərcümə tələb etməyən dekorativ UI etiketləridir.

## §7 Nasazlıqların aradan qaldırılması

### WebSocket bağlantısının kəsilməsi

Canlı izləmədə "Bağlantı kəsildi" göstərilirsə:

1. Serverin hələ də işlədiyini yoxlayın: `GET /api/tools/traffic-inspector/capture-modes`
2. Səhifəni yenidən yükləyin — WebSocket yenidən qoşulur və yeni ani görüntü alır
3. Server yenidən başladılıbsa, yaddaşdaxili bufer təmizlənib — sessiya qeydə alınmayıbsa, köhnə qeydlər artıq yoxdur

### 8080 portu konflikti

HTTP_PROXY rejimi işə düşmürsə:

```bash
lsof -i :8080    # prosesi tapın
```

Portu dəyişdirin:

```bash
# .env
INSPECTOR_HTTP_PROXY_PORT=8888
```

### Sistem proksisi əvvəlki vəziyyətinə qaytarılmır

Sistem miqyaslı proksi rejimi aktiv olduğu zaman OmniRoute çökərsə:

**macOS:**

```bash
networksetup -setwebproxystate Wi-Fi off
networksetup -setsecurewebproxystate Wi-Fi off
```

**Linux (GNOME):**

```bash
gsettings set org.gnome.system.proxy mode 'none'
```

**Windows:**

```cmd
netsh winhttp reset proxy
```

İdarəetmə paneli növbəti dəfə yüklənərkən DB vəziyyətinin proksinin aktiv olduğunu göstərdiyini aşkarlayarsa, "Sistem proksisini əvvəlki vəziyyətinə qaytar" seçimini də təklif edəcək.

### Bufer doludur

Bufer `INSPECTOR_BUFFER_SIZE` həddinə (standart olaraq 1000) çatdıqda, yeni qeydlər ən köhnə qeydləri buferdən çıxarır. Vacib sorğular itirilirsə:

- `INSPECTOR_BUFFER_SIZE` dəyərini artırın (məsələn, 5000) — daha uzun saxlama müddəti üçün daha çox yaddaş istifadə olunur
- Müvafiq zaman aralığını DB-də saxlamaq üçün sessiyanı qeydə alın
