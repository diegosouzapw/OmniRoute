> `src/lib/db/obsidian.ts` (tokenun / əsas URL-in / WebDAV məlumatlarının saxlanması),

> (22 MCP aləti), `src/app/api/settings/obsidian/route.ts` +
> `src/app/api/settings/obsidian/webdav/route.ts` (parametrlər API-ləri). Alətlərin qeydiyyatı
> və əhatə dairəsinin əlaqələndirilməsi `open-sse/mcp-server/server.ts` daxilindədir.

## Bu nədir

OmniRoute **Obsidian** anbarına **kontekst mənbəyi** kimi qoşulur — bu, agentlərin
daxili MCP serveri vasitəsilə oxuduğu və yazdığı lokal Markdown bilik bazasıdır.
İnteqrasiya masaüstü tətbiqinin daxilində işləyən icma tərəfindən hazırlanmış
**Obsidian Local REST API** plaqini ilə əlaqə qurur. Bunun sayəsində agentlər qeydlərdə
axtarış edə, faylları oxuya/yaza/dəyişdirə, anbarın məzmununu siyahıya ala, gündəlik/həftəlik
dövri qeydlərlə işləyə, teqləri idarə edə, Obsidian əmrlərini icra edə və (istəyə bağlı olaraq)
ikiistiqamətli masaüstü↔mobil anbar sinxronizasiyasını koordinasiya edə bilərlər.

Klient (`src/lib/obsidian/api.ts`) Local REST API-ni aşağıdakı imkanlarla əhatə edir:

- Keçici `5xx` xətaları üçün **artan gözləmə müddəti ilə təkrar cəhd**, `AbortController` vasitəsilə **30 saniyəlik vaxt limiti**.
- **Tipləşdirilmiş xəta təsnifatı** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- Tez-tez rast gəlinən port səhvini (MCP son nöqtəsinin `27124` portu **deyil**, HTTP-nin
  `27123` portu) və Tailscale formatını qeyd edən, istifadəçi üçün anlaşıqlı
  **“Obsidian ilə əlaqə yaratmaq mümkün deyil” tövsiyəsi**.
- Boşluqlar və əyri xətlər olan qeyd yollarının təhlükəsizliyini təmin edən, anbara nəzərən
  **yol kodlaşdırması**.

## Quraşdırma

Obsidian tokenu və ya əsas URL üçün **heç bir mühit dəyişəni yoxdur** — hər ikisi
`src/lib/db/obsidian.ts` vasitəsilə SQLite `key_value` cədvəlində (`obsidian` ad sahəsi)
saxlanılır. Token **saxlanma zamanı şifrələnir** (AES-256-GCM, açıq mətnlə geriyə
uyğunluq üçün ehtiyat mexanizmi ilə). Endpoint idarəetmə panelinin **Context Sources**
vərəqindən (`ObsidianSourceCard`) və ya parametrlər REST API-si vasitəsilə konfiqurasiya edin.

> [!IMPORTANT]
> **Obsidian Local REST API** plaqini quraşdırılmış və işlək olmalıdır. Onun REST
> interfeysi **HTTP `127.0.0.1:27123`** ünvanını dinləyir (standart əsas URL). `27124`
> portu _ayrıca_ MCP/HTTPS son nöqtəsidir və parametrlər marşrutu tərəfindən açıq şəkildə
> rədd edilir. Başqa cihazdan qoşulursunuzsa, `http://<tailscale-ip>:27123` istifadə edin.

### Konfiqurasiya açarları (SQLite `key_value`, `obsidian` ad sahəsi)

| Açar              | Təyinatı                                                  | Şifrələnir |
| ----------------- | --------------------------------------------------------- | ---------- |
| `api_key`         | Local REST API daşıyıcı tokenu                            | bəli       |
| `base_url`        | REST əsas URL-i (standart `http://127.0.0.1:27123`)       | xeyr       |
| `vault_path`      | Anbar qovluğuna mütləq yol (sinxronizasiya üçün)          | xeyr       |
| `webdav_username` | Yaradılmış WebDAV istifadəçi adı (anbar sinxronizasiyası) | xeyr       |
| `webdav_password` | Yaradılmış WebDAV parolu (anbar sinxronizasiyası)         | bəli       |
| `webdav_enabled`  | WebDAV anbar sinxronizasiyasının aktiv olub-olmaması      | xeyr       |

### REST vasitəsilə konfiqurasiya

```bash
# Local REST API tokenunu yadda saxla + doğrula (POST status yoxlaması vasitəsilə doğrulayır)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Bağlantı statusunu yoxla (connected, hasToken, baseUrl, vaultPath qaytarır)
curl http://localhost:20128/api/settings/obsidian

# Bağlantını kəs (saxlanmış tokenu silir)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Bütün metodlar idarəetmə panelində autentifikasiya tələb edir. `POST` `27124` portundakı
istənilən URL-i rədd edir və tokenu yadda saxlamazdan əvvəl Local REST API status son
nöqtəsinə sorğu göndərərək onu doğrulayır.

### WebDAV anbar sinxronizasiyası

`src/app/api/settings/obsidian/webdav/route.ts`, `src/lib/obsidianSync.ts` tərəfindən
idarə olunan, istəyə bağlı WebDAV əsaslı anbar sinxronizasiyasını idarə edir. Bu funksiya
aktivləşdirildikdə OmniRoute lokal anbar qovluğuna yönəldilir və təsadüfi WebDAV istifadəçi
adı/parol cütü yaradılır:

```bash
# Anbar qovluğu üçün WebDAV sinxronizasiyasını aktivləşdir (istifadəçi adı/parol yaradır)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# WebDAV sinxronizasiya statusunu əldə et (giriş məlumatları yalnız aktiv olduqda qaytarılır)
curl http://localhost:20128/api/settings/obsidian/webdav

# WebDAV sinxronizasiyasını deaktiv et (giriş məlumatlarını + idarə olunan .stignore faylını silir)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Hər API açarı üçün kontekst mənbəyi (istəyə bağlı)

Obsidian konfiqurasiyası `api_key_context_sources` cədvəli
(`src/lib/db/apiKeyContextSources.ts`) vasitəsilə **hər API açarı üçün** ayrıca əhatə
dairəsinə salına bilər. MCP çağırışı autentifikasiya olunmuş API açarı identifikatoru
daşıdıqda, `getObsidianConfigForApiKey()` həmin açarın öz tokenuna/əsas URL-inə/anbar yoluna
(`source: "api_key"`) üstünlük verir, bunlar olmadıqda isə qlobal konfiqurasiyadan
(`source: "global"`) istifadə edir.

## MCP alətləri (22)

`open-sse/mcp-server/tools/obsidianTools.ts` faylında müəyyən edilib. Token/baza URL-i hər çağırış üçün müəyyənləşdirilir (əvvəlcə API açarına aid olan, sonra qlobal). OmniRoute **sinxronizasiya serverinə** müraciət edən alətlər (dörd `obsidian_sync_*` aləti) əlavə olaraq OmniRoute parametrlərində konfiqurasiya edilmiş sinxronizasiya autentifikasiya tokenini tələb edir.

### Oxuma alətləri (`read:obsidian`)

| Alət                         | Təsvir                                                                                                              |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Local REST API-nin əlçatan və autentifikasiya edilmiş olub-olmadığını yoxlayır.                                     |
| `obsidian_search_simple`     | Qeyd məzmununda tam mətn axtarışı aparır; fayl yolları ilə birlikdə fraqmentləri qaytarır.                          |
| `obsidian_search_structured` | JSON Logic ifadəsindən istifadə edərək axtarış aparır (and/or/regex/path filtrləri).                                |
| `obsidian_read_note`         | Anbara nəzərən nisbi yol ilə qeydi oxuyur; istəyə görə konkret başlığı/bloku/frontmatter-i oxuyur.                  |
| `obsidian_list_vault`        | Anbardakı fayl və qovluqları siyahıya alır (elementlər ağacı).                                                      |
| `obsidian_get_document_map`  | Qeydin başlıq strukturunu başlıqlar → sətir nömrələri xəritəsi kimi əldə edir.                                      |
| `obsidian_get_note_metadata` | Tam məzmun olmadan frontmatter-i, teqləri, keçidləri, simvol/söz sayını əldə edir.                                  |
| `obsidian_get_active_file`   | Hazırda Obsidian-da aktiv olan faylın yolunu və məzmununu əldə edir.                                                |
| `obsidian_get_periodic_note` | Verilmiş tarix üçün gündəlik/həftəlik/aylıq dövri qeydi əldə edir (buraxılarsa, bu gün).                            |
| `obsidian_get_tags`          | Bütün anbar teqlərini istifadə tezlikləri ilə birlikdə siyahıya alır.                                               |
| `obsidian_list_commands`     | Mövcud Obsidian əmr ID-lərini siyahıya alır (`obsidian_execute_command` ilə istifadə üçün).                         |
| `obsidian_sync_status`       | OmniRoute sinxronizasiya serverinin statusu: işləmə vəziyyəti, anbar adı, port, işləmə müddəti, son sinxronizasiya. |
| `obsidian_sync_conflicts`    | Həll olunmamış sinxronizasiya münaqişələrini siyahıya alır (yol, münaqişə yolu, aşkarlanma vaxtı).                  |

### Yazma alətləri (`write:obsidian`)

| Alət                             | Təsvir                                                                                                                           |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Verilmiş Markdown məzmunu ilə qeyd yaradır və ya mövcud qeydin üzərinə yazır.                                                    |
| `obsidian_append_note`           | Qeydə məzmun əlavə edir; istəyə görə konkret başlığa/bloka.                                                                      |
| `obsidian_patch_note`            | Başlıq, blok və ya frontmatter sahəsində dəqiq şəkildə sona/əvvələ əlavə edir və ya əvəzləyir.                                   |
| `obsidian_delete_note`           | Qeydi anbardan birdəfəlik silir.                                                                                                 |
| `obsidian_move_note`             | Anbar daxilində qeydi köçürür və ya adını dəyişir.                                                                               |
| `obsidian_execute_command`       | Obsidian əmrini onun əmr ID-si ilə icra edir.                                                                                    |
| `obsidian_open_file`             | Obsidian-da faylı açır (mövcud deyilsə, yaradır).                                                                                |
| `obsidian_sync_trigger`          | Dərhal ikitərəfli masaüstü↔mobil anbar sinxronizasiyasını başladır.                                                              |
| `obsidian_sync_resolve_conflict` | Sinxronizasiya münaqişəsini həll edir: `local` (mobil), `remote` (masaüstü) saxlayır və ya `keep-both` ilə hər ikisini saxlayır. |

> [!NOTE]
> `obsidian_patch_note` hədəfləri `heading | block | frontmatter` `targetType`-ını
> və `append | prepend | replace` `operation`-ını, həmçinin istəyə bağlı
> `createTargetIfMissing` parametrini qəbul edir. Dörd `obsidian_sync_*` aləti yerli sinxronizasiya
> serveri ilə əlaqə saxlayır (standart olaraq `http://127.0.0.1:27781`) və sinxronizasiya tokenini tələb edir.

### Əhatə dairələri

Oxuma alətləri `read:obsidian`, yazma alətləri isə `write:obsidian` tələb edir. Tətbiqetmə
Notion ilə eynidir — `open-sse/mcp-server/server.ts` faylındakı `withScopeEnforcement()`
tərəfindən idarə olunur, `OMNIROUTE_MCP_ENFORCE_SCOPES=true` ilə aktivləşdirilir və icazə verilən
əhatə dairələri `OMNIROUTE_MCP_SCOPES` dəyişənindən və ya API açarının əhatə dairəsi kontekstindən əldə edilir. Baxın:
[MCP-SERVER.md](./MCP-SERVER.md).

## İstifadə halları

- **Kataloqa əsaslanan cavablar** — əvvəl `obsidian_search_simple` / `obsidian_search_structured`,
  sonra isə `obsidian_read_note` istifadə olunur ki, agent real qeydləriniz əsasında cavab versin.
- **Qeyd yazma / gündəlik aparma** — agentin çıxışını, xülasələri və ya gündəlik qeydləri
  (`obsidian_get_periodic_note`) kataloqa yazmaq üçün `obsidian_write_note`, `obsidian_append_note`
  və ya dəqiq dəyişikliklər edən `obsidian_patch_note`.
- **Kataloqda naviqasiya** — oxuma/yazmadan əvvəl strukturu araşdırmaq üçün
  `obsidian_list_vault`, `obsidian_get_document_map` və `obsidian_get_tags`.
- **Obsidian avtomatlaşdırması** — plaginləri/əmrləri agent vasitəsilə idarə etmək üçün
  `obsidian_list_commands` + `obsidian_execute_command`; qeydi istifadəçi interfeysində
  göstərmək üçün `obsidian_open_file`.
- **Mobil sinxronizasiya** — WebDAV sinxronizasiyasını aktivləşdirin, sonra masaüstü↔mobil
  sinxronizasiyanı koordinasiya etmək və ziddiyyətləri həll etmək üçün `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  istifadə edin.
