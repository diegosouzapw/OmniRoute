## npm Trusted Publishing (v3.8.51-dən etibarən standartdır) — sorğu əsasında mərhələli, ehtiyat variant kimi birbaşa

`npm-publish.yml` standart olaraq **npm Trusted Publishing (OIDC)** vasitəsilə dərc edir:
`stage-npm` işi (GitHub tərəfindən host edilir) həmin icra üçün GitHub-ın id-token-ini qısamüddətli npm
etimadnaməsi ilə dəyişir — repozitoriya sirlərində uzunmüddətli npm tokeni yoxdur, 2FA sorğusu yoxdur, mənşə məlumatı əlavə olunur.
2FA-dan yan keçən tokenlər istifadədən çıxarıldığı üçün npm-in hazırda təsdiqlədiyi yan keçmə üsulu budur;
bu, WS1.3 zəmanətini qoruyaraq layihənin v3.8.48-ə qədər malik olduğu tam avtomatik prosesi bərpa edir
(sızdırılmış token təkbaşına dərc edə bilməz — çünki token yoxdur).

**Birdəfəlik quraşdırma (sahib):** npmjs.com → `omniroute` paketi → Settings → _Trusted
Publisher_ → GitHub: sahib `diegosouzapw`, repo `OmniRoute`, iş axını `npm-publish.yml`
(mühit: yoxdur). Bu mövcud olana qədər avtomatik addım `ENEEDAUTH` ilə uğursuz olur:
`publish_mode=staged` (aşağıda) və ya `direct` ilə yenidən başladın.

### Mərhələli dərc (sorğu əsasında — `publish_mode=staged`)

npm-publish iş axını artıq birbaşa dərc etmir: paketlənmiş tarball faylını işə salır
(`check:pack-boot`) və sonra `npm stage publish` əmrini icra edir — dəqiq baytlar reyestrdə saxlanılır,
lakin sahib təsdiqləyənədək **quraşdırıla bilməz**. İnsan tərəfindən keçilən 2FA mərhələsi
sübutdan əvvəl deyil, SONRA yerinə yetirilir.

**İş axını uğurla tamamlandıqdan sonra sahibin yerinə yetirəcəyi proses:**

1. `npm stage list omniroute` — mərhələ identifikatorunu tapın (iş axını xülasəsində də göstərilir).
2. Mərhələlənmiş baytları yoxlayın (tövsiyə olunur): `npm stage download <id>`, sonra endirilmiş
   tarball faylını müvəqqəti prefiksə quraşdırın və işə salın (`npm run check:pack-boot` CI daxilində
   eyni paketləmə→quraşdırma→işə salma nəticəsini avtomatlaşdırır).
3. `npm stage approve <id>` — 2FA sorğusu ELƏ dərcin özüdür. `npm stage reject <id>` ləğv edir.
4. Dərcdən sonrakı qoruyucu yoxlama: dərcdən sonrakı yoxlayıcı (v3.8.49 planının WS1.4 hissəsi)
   dərc edilmiş versiyanı ictimai reyestrdən təmiz konteynerə quraşdırır və işə salır.

**Fövqəladə ehtiyat variant:** `publish_mode=direct` ilə `workflow_dispatch` köhnə dərhal
`npm publish` davranışını bərpa edir (yalnız mərhələləmənin özü düzgün işləmədikdə istifadə edin; səbəbini qeyd edin).

**Birdəfəlik sərtləşdirmə (sahib, npmjs.com):** `omniroute` üçün Trusted Publisher-i
yalnız mərhələləmə rejimində konfiqurasiya edin ki, sızdırılmış uzunmüddətli token heç bir yerdən birbaşa
`npm publish` edə bilməsin — CI yalnız mərhələləyə bilər; yalnız sahibin 2FA təsdiqi buraxılışı dərc edir.

**Zədələnmiş artefakt üzrə fəaliyyət planı (dəyişməyib):** standart ilk addım kimi
`npm deprecate omniroute@<bad> "<reason> — use <fixed>"` istifadə edin (dəqiqələr çəkir, geri qaytarıla bilər);
`npm unpublish` yalnız 72 saat/asılılığı olmayanlar pəncərəsi daxilində və heç vaxt ilk addım kimi istifadə edilməməlidir.
Docker: versiya teqini heç vaxt yenidən yazmayın — geri qaytarma `latest` teqini son işlək digest-ə yönləndirməkdir.

**Docker Hub `latest` (hər stabil SemVer dərci üçün tələb olunur):**
`docker-publish` iş axını **həm** `X.Y.Z` teqini, **həm də**
`should-promote-latest.sh` bunun ən yüksək stabil SemVer olduğunu təsdiqlədikdə `:latest` teqini
**eyni digest** ilə qeyd etməlidir. İşdən sonra: Hub-dakı `latest` digest-i yeni SemVer digest-inə bərabər olmalı
və `last_updated` yenilənməlidir. Buraxılış qeydlərində yalnız git-də mövcud olan düzəlişlərdən bəhs edilərkən
`:latest` teqini köhnə yığımda saxlamayın. Compose ilə sürətli başlama nümunələri `:latest` istifadə edir;
GitOps isə `X.Y.Z` versiyasına sabitlənməyə davam etməlidir. [Docker buraxılış kanalları](../guides/DOCKER_GUIDE.md#release-channels)
və #10317-yə baxın.

## Təcili Düzəliş üçün Sürətli Zolaq (`hotfix` etiketi)

`hotfix` etiketi verilmiş PR ağır CI matrisini (9 şardlı E2E, əhatə ratçeti,
quality-gate, quality-extended) ötürür və sürətli, yüksək siqnallı yoxlamaları saxlayır: build,
unit şardları, integration, vitest, lint/typecheck, docs-sync, `check:pack-artifact`
və tarball ilkin işəsalma tüstü testi (`check:pack-boot`). Hədəf: ~33 dəqiqə əvəzinə ≤15 dəqiqəyə yaşıl nəticə.

**Giriş qaydası — dördünün də yerinə yetirilməsi tələb olunur (Chromium/VS Code/Node təcili zolaqları əsasında modelləşdirilib):**

1. **Ciddilik**: istehsal mühiti pozulub — dərc edilmiş artefakt ilkin işəsalma zamanı çökür /
   təhlükəsizlik düzəlişidir / buraxılışın hər bir istifadəçisinə təsir edir. «Vacib» olmaq «pozulmuş» olmaq demək deyil.
2. **Səlahiyyət**: `hotfix` etiketini yalnız repozitoriyanın sahibi tətbiq edir. Etiket
   təsdiqin ÖZÜDÜR — kampaniya PR-ında bunu heç vaxt özünüz tətbiq etməyin.
3. **Sübut**: PR təsvirində əvvəlki tam yaşıl ağır icraya (ötürülmüş işlərin yenidən yoxlayacağı dəst)
   və düzəlişin əvvəl uğursuz, sonra uğurlu olan öz testinə keçid verilir.
4. **Əhatə dairəsi**: yalnız cherry-pick — minimal düzəliş; refaktorinq və əlavə dəyişikliklər yoxdur.

Ötürülmüş əhatə/ratçet sahəsi release budağındakı növbəti tam icra
(davamlı yaşıl buraxılış) tərəfindən yenidən yoxlanılır — zolaq yoxlamanı deyil, yalnız GÖZLƏMƏNİ ötürür.
Yalnız testlərdən ibarət fərqlər (bütün fayllar `tests/` altındadır, heç biri `tests/e2e/` altında deyil)
heç bir etiket olmadan E2E matrisini avtomatik ötürür.

### Huklar (Husky tərəfindən yoxlanılıb)

### Yığım Strukturu

Repozitoriya üç fərqli çıxış kataloqundan istifadə edir — onları heç vaxt qarışdırmayın:

| Kataloq   | Məqsəd                                                         | İzlənilir?        |
| --------- | -------------------------------------------------------------- | ----------------- |
| `src/`    | Tətbiqin mənbə kodu (TypeScript / TSX)                         | Bəli              |
| `.build/` | Yığımın aralıq faylları — `next build` çıxışı (`distDir`)      | Xeyr (gitignored) |
| `dist/`   | Paylanmağa hazır npm paketi — `assembleStandalone` ilə yığılır | Xeyr (gitignored) |

> **Operator qeydi:** uzaq VPS təsvirindəki kataloq `/usr/lib/node_modules/omniroute/app/` olaraq qalır.
> Yalnız **repozitoriya daxilindəki** yığım çıxışı köçürülüb (`app/` → `dist/`). Deploy bacarıqları
> `dist/` məzmununu uzaq `app/` kataloquna rsync edir — VPS yollarında dəyişiklik tələb olunmur.

**Tək yığım axını:**

```
npm run build:release
  └─ rm -rf .build dist          (təmizləmə)
  └─ next build → .build/next/   (aralıq fayllar)
  └─ assembleStandalone          (standalone + static + public + natives fayllarını → dist/ kataloquna köçürür)
  └─ dist/BUILD_SHA yazır        (HEAD nəzarət göstəricisi)
```

Deploy üçün `npm run build` əmrindən sonra ayrıca `npm run build:cli` əmrini işə salmayın — bir əmrlə təmiz yenidən yığım və nəzarət göstəricisi yaradan
`npm run build:release` əmrindən istifadə edin.

## Geri qaytarma

Buraxılışda kritik problem varsa:

1. `gh release edit vX.Y.Z --prerelease` (ən son buraxılış kimi işarələnməsini ləğv edir)
2. `git tag -d vX.Y.Z && git push --delete origin vX.Y.Z` (yalnız istifadəçilər tərəfindən hələ mənimsənilməyibsə)
3. Və ya: `release/vX.Y.0` üzərində təcili düzəliş → `vX.Y.(Z+1)` yamaq buraxılışı
4. Dərhal GitHub Discussions və Discord-da məlumat verin

- Heç vaxt birbaşa `main` budağına commit etməyin
