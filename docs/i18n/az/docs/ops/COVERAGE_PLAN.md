Hesabatın hesablanma üsulundan asılı olaraq bir neçə əhatə göstəricisi mövcuddur. Planlaşdırma üçün onlardan yalnız biri faydalıdır.

| Köhnə                          | Köhnə `npm run test:coverage`                                       |              79.42% |   75.15% |      67.94% | Şişirdilib: test fayllarını sayır və `open-sse`-ni istisna edir  |

## Qaydalar

- Əhatə hədəfləri `tests/**` üçün deyil, mənbə faylları üçün tətbiq olunur.
- `open-sse/**` məhsulun bir hissəsidir və əhatə dairəsində qalmalıdır.
- Yeni kod toxunulan sahələrdə əhatəni azaltmamalıdır.
- Tətbiq detalları əvəzinə davranışın və budaqlanma nəticələrinin sınaqdan keçirilməsinə üstünlük verin.
- `src/lib/db/**` üçün geniş miqyaslı moklar əvəzinə müvəqqəti SQLite verilənlər bazalarına və kiçik sınaq məlumatlarına üstünlük verin.

## Cari əmrlər dəsti

- `npm run test:coverage`
  - Vahid testlər dəsti üçün əsas mənbə əhatəsi həddi
  - `text-summary`, `html`, `json-summary` və `lcov` yaradır
- `npm run coverage:report`
  - Son icradan əldə edilən fayl-fayl ətraflı hesabat
- `npm run test:coverage:legacy`
  - Yalnız tarixi müqayisə üçün

## Ratchet siyasəti

`npm run test:coverage` hədlərini yalnız layihə növbəti mərhələni rahat ehtiyatla faktiki olaraq keçdikdən sonra yeniləyin.

**Cari keçid həddi:** `npm run test:coverage` **60 ifadə / 60 sətir / 60 funksiya / 60 budaq** tələb edir (metrik Quality-Gates Mərhələ 6A.1-də yenidən əsaslandırılıb — əvvəlki 82.58% baza göstəricisi test fayllarını saydığı və `open-sse`-ni istisna etdiyi üçün süni şəkildə yüksək idi). `test:coverage:legacy` əmri tarixi müqayisə üçün köhnə 50/50/50 metrikini qoruyur.

Ən son hesabata əsasən xüsusi hədd yoxlamaları üçün istifadə edin:

```bash
node scripts/check/test-report-summary.mjs --threshold 75
```

Tövsiyə olunan ratchet ardıcıllığı (sıralama `ifadələr-sətirlər / budaqlar / funksiyalar` şəklindədir):

1. 55/60/55
2. 60/62/58
3. 65/64/62
4. 70/66/66
5. 75/70/72 <-- cari keçid həddi (75/70/75)
6. 80/75/78
7. 85/80/84
8. 90/85/88

Budaq əhatəsi ardıcıl iki icrada 78%-dən yuxarı qaldıqdan sonra növbəti ratchet hədəfi `80/75/78` olacaq.

## Məlum boşluq

Cari əhatə əmri əsas Node modul test dəstini ölçür və ondan icra edilən mənbə kodunu, o cümlədən `open-sse`-ni əhatə edir. O, hələlik Vitest əhatəsini vahid hesabatda birləşdirmir. Bu birləşdirməni daha sonra etmək məqsədəuyğundur, lakin bu, 60%-dən 80%-ə yüksəlişə başlamaq üçün maneə deyil.
