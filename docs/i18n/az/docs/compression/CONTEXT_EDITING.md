Delegasiya edilmiş **Kontekst Redaktəsi** yalnız Claude üçün nəzərdə tutulmuş kontekst idarəetmə xüsusiyyətidir. OmniRoute-un lokal sıxışdırma mexanizmlərindən (Caveman, RTK, LLMLingua, yığılmış konveyerlər) fərqli olaraq — bunlar sorğu gövdəsini proksidən çıxmazdan _əvvəl_ yenidən yazır — Kontekst Redaktəsi **provayderdən** öz aktiv kontekst pəncərəsindən köhnəlmiş alət istifadəsi / alət nəticəsi bloklarını təmizləməyi xahiş edir. OmniRoute yalnız gövdə parametri (`context_management.edits[]`) əlavə edir; faktiki təmizləməni Claude öz tokenizatoruna əsasən həyata keçirir.

Bu, mahiyyət etibarilə delegasiya edilmiş imkandır: digər provayderlər bu parametri rədd edir, buna görə OmniRoute onu ciddi şəkildə Claude və Claude-Code ilə uyğun relelərlə məhdudlaşdırır.

Həqiqət mənbəyi: `open-sse/config/contextEditing.ts` (strategiya identifikatorları, gövdəyə əlavəetmə, telemetriyanın çıxarılması), `open-sse/executors/base.ts` (əlavəetmə şərti + 400 ehtiyat mexanizmi) və `open-sse/services/compression/types.ts` (konfiqurasiya strukturu + standart dəyər).

## `clear_tool_uses` nə edir

OmniRoute çıxış Anthropic Messages gövdəsinə tək bir redaktə əlavə edir:

```json
{
  "context_management": {
    "edits": [
      {
        "type": "clear_tool_uses_20250919",
        "trigger": { "type": "input_tokens", "value": 100000 },
        "keep": { "type": "tool_uses", "value": 3 }
      }
    ]
  }
}
```

- `type: "clear_tool_uses_20250919"` — tarixli Anthropic strategiya identifikatoru (`CLEAR_TOOL_USES_STRATEGY`).
- `trigger.value: 100000` — sorğunun giriş tokenlərinin sayı bu həddi keçdikdə Claude köhnə alət istifadəsi/nəticəsi cütlərini təmizləməyə başlayır (`CONTEXT_EDITING_DEFAULT_TRIGGER_TOKENS`, Anthropic-in standart dəyəri).
- `keep.value: 3` — ən son N alət istifadəsi/nəticəsi cütü toxunulmaz saxlanılır (`CONTEXT_EDITING_DEFAULT_KEEP_TOOL_USES`).

Beta versiyası `anthropic-beta: context-management-2025-06-27` başlığı vasitəsilə elan edilir; OmniRoute artıq Claude sorğularında bu başlığı göndərir.

Əlavəetmə `applyContextEditingToBody()` tərəfindən həyata keçirilir və **idempotentdir**: gövdədə artıq `clear_tool_uses` redaktəsi varsa (əvvəlki çağırış tərəfindən əlavə edilibsə və ya müştəri tərəfindən təqdim olunubsa), gövdə olduğu kimi saxlanılır. `clear_thinking_20251015` redaktəsi də mövcuddursa, OmniRoute `clear_thinking` redaktəsini sabit çeşidləmə ilə önə keçirir, çünki Anthropic `edits[]` massivində `clear_thinking` redaktəsinin `clear_tool_uses` redaktəsindən əvvəl gəlməsini tələb edir.

## Hər kombinasiya üçün aktivləşdirmə keçidi

Kontekst Redaktəsi **standart olaraq söndürülüb** və ayrıca aktivləşdirilməlidir. Keçid sıxışdırma konfiqurasiyasında saxlanılan tək bir boolean dəyəridir:

- Parametr açarı: `contextEditing.enabled` (camelCase — `context_editing` / `context-editing` **deyil**).
- Tip: `open-sse/services/compression/types.ts` daxilində `ContextEditingConfig { enabled: boolean }`.
- Standart dəyər: `DEFAULT_CONTEXT_EDITING_CONFIG = { enabled: false }`.
- Zod sxemi: `src/shared/validation/compressionConfigSchemas.ts` daxilində `contextEditingConfigSchema`.
- Saxlama: digər sıxışdırma parametrləri ilə birlikdə davamlı saxlanılır (`src/lib/db/compression.ts` daxilində normallaşdırılır).

İdarəetmə panelində keçid sıxışdırma mərkəzində (`src/app/(dashboard)/dashboard/context/combos/CompressionHub.tsx`) yerləşir və `saveSettings()` vasitəsilə `{ contextEditing: { enabled: … } }` dəyərini geri yazır. O, sıxışdırma parametrləri obyektinin tərkibində daşındığı üçün tam müstəqil interfeys olmaq əvəzinə hər kombinasiya üçün sıxışdırma profili ilə birlikdə işləyir — konfiqurasiya yalnız aktiv/deaktiv bayrağını daşıyır; bütün hədlər (`trigger`, `keep`) yuxarıda sənədləşdirilmiş sabitlərdir.

## Yalnız Claude üçün məhdudlaşdırma

İnyeksiya yalnız həqiqi Claude və ya Claude-Code ilə uyğun relelər üçün baş verir.
`open-sse/executors/base.ts` daxilindəki yoxlama belədir:

```ts
if (
  (this.provider === "claude" || isClaudeCodeCompatible(this.provider)) &&
  contextEditing?.enabled &&
  !contextEditingDisabled
) {
  applyContextEditingToBody(transformedBody, { enabled: true });
}
```

- `this.provider === "claude"` — həqiqi Anthropic açarı/OAuth.
- `isClaudeCodeCompatible(this.provider)` — provayder identifikatoru
  `anthropic-compatible-cc-` prefiksi ilə başlayan relelər (onlar Claude Code uyğunluğunu bəyan edir, buna görə də beta funksiyasını
  qəbul etmə ehtimalı ən yüksək olan relelərdir). Baxın: `open-sse/services/provider.ts`.

Qəsdən **istisna edilənlər**:

- `claude-web` — `context_management` parametrini heç vaxt görməyən, `create_conversation_params` sorğu strukturuna malik brauzer relesi.
- Ümumi `anthropic-compatible-*` releləri (`-cc-` prefiksi olmayanlar) — beta dəstəyi
  qeyri-müəyyən olan üçüncü tərəf son nöqtələri.

Keçid aktiv olsa belə, Claude olmayan provayderlər heç vaxt `context_management` parametrini almır.

## 400 ehtiyat mexanizmi / rele əhatəsi

Claude ilə uyğun rele beta funksiyasını dəstəklədiyini bəyan edə, lakin yenə də `context_management` parametrini
HTTP 400 xətası ilə rədd edə bilər. Sorğunu uğursuz etmək əvəzinə funksionallığı uyğun şəkildə azaltmaq üçün icraçı parametri silir və eyni URL üzrə **bir dəfə** yenidən cəhd edir:

```ts
if (
  response.status === HTTP_STATUS.BAD_REQUEST &&
  contextEditing?.enabled &&
  !contextEditingDisabled &&
  transformedBody?.context_management !== undefined
) {
  const errText = await response
    .clone()
    .text()
    .catch(() => "");
  if (/context[_-]management|context editing/i.test(errText)) {
    contextEditingDisabled = true;
    delete transformedBody.context_management;
    let retryBody = JSON.stringify(transformedBody);
    if (isClaudeCodeCompatible(this.provider) || this.provider === "claude") {
      retryBody = await signRequestBody(retryBody);
    }
    response = await fetch(url, { ...fetchOptions, body: retryBody });
  }
}
```

Davranış:

1. Yalnız kontekst redaktəsi aktiv olduqda, gövdə həqiqətən
   `context_management` daşıdıqda və `400` xətası baş verdikdə işə düşür.
2. Uyğunluq olmayan yol üçün ilkin cavabın toxunulmaz qalması məqsədilə 400 cavabının gövdəsi `clone()` vasitəsilə oxunur.
3. Xəta mətni `/context[_-]management|context editing/i` ifadəsinə uyğun gəlməlidir — əlaqəsiz 400 xətası (məsələn,
   `max_tokens must be >= 1`) ehtiyat mexanizmini **işə salmır**; ilkin xəta ötürülür.
4. Uyğunluq olduqda `contextEditingDisabled = true` təyin edir (sonradan təkrar cəhd/ehtiyat URL üçün yeni
   `transformedBody` yaradılarsa, bu, yenidən inyeksiyanın qarşısını alır), `context_management` parametrini silir,
   Claude / Claude-Code ilə uyğun relelər üçün gövdəni yenidən imzalayır (`signRequestBody`) və eyni URL üzrə bir dəfə yenidən cəhd edir.

Həqiqi Claude beta parametrini `ANTHROPIC_BETA_BASE` daxilində daşıyır və bu ehtiyat mexanizmi yoluna daxil olmur.

## `applied_edits` telemetriyası

Claude cavabından sonra OmniRoute provayderin faktiki olaraq nə qədər konteksti təmizlədiyini qeydə alır. Bu,
**axınla ötürülmür** — axınsız cavab gövdəsindən mümkün qədər çıxarılır və heç vaxt
cavaba təsir etmir (telemetriya xətaları nəzərə alınmır).

- Çıxarış: `open-sse/config/contextEditing.ts` daxilində `extractContextEditingTelemetry(responseBody)`.
  Cavab strukturuna qarşı qoruyucu yanaşma olaraq `applied_edits` üç yerdə yoxlanılır:
  - `context_management.applied_edits`
  - `usage.context_management.applied_edits`
  - `usage.applied_edits`
- Hər bir qeyddən oxunan sahələr: `cleared_input_tokens` və `cleared_tool_uses`
  (snake_case, Anthropic-in yerli formatı), ehtiyat variantlar kimi `clearedInputTokens` / `clearedToolUses` camelCase formaları ilə.
- Heç bir `applied_edits` massivi tapılmadıqda və ya faktiki olaraq heç nə təmizlənmədikdə `null` qaytarır.

Qəbz strukturu `ContextEditingTelemetry { editCount, clearedInputTokens, clearedToolUses }` şəklindədir.
Qeydiyyat `open-sse/handlers/chatCore.ts` daxilində (`provider === "claude"` ilə məhdudlaşdırılaraq)
`recordContextEditingTelemetry()` (`src/lib/db/compressionAnalytics.ts`) vasitəsilə aparılır və aşağıdakı kimi işarələnmiş sıxışdırma
analitikası sətri yazılır:

- `mode: "context-editing"`
- `engine: "context-editing"`
- `tokens_saved` / `original_tokens` = təmizlənmiş giriş tokenlərinin sayı
- `request_id` sonuna `::context-editing` əlavə edilir

Beləliklə, həvalə edilmiş təmizləmə yerli mühərriklərlə yanaşı sıxışdırma analitikasında
`context-editing` mühərrik etiketi altında görünür və RTK/Caveman/LLMLingua qənaətlərindən fərqləndirilə bilir.

## Yerli sıxışdırma mühərrikləri ilə əlaqəsi

| Aspekt               | Yerli mühərriklər (Caveman / RTK / LLMLingua / stacked) | Həvalə edilmiş kontekst redaktəsi                          |
| -------------------- | ------------------------------------------------------- | ---------------------------------------------------------- |
| Harada işləyir       | Sorğu proksidən çıxmazdan əvvəl OmniRoute daxilində     | Provayderdə (Claude), server tərəfində                     |
| Nəyi redaktə edir    | Prompt / kontekst / alət nəticəsinin mətni              | Köhnə alət istifadəsi / alət nəticəsi blokları             |
| Provayder əhatəsi    | Bütün provayderlər                                      | Yalnız `claude` + `anthropic-compatible-cc-*`              |
| Aktivləşdirmə        | Sıxışdırma rejimi parametrləri                          | `contextEditing.enabled`                                   |
| Xəta rejimi          | Xəta zamanı davametmə (orijinal mətn)                   | 400 ehtiyat mexanizmi: parametri sil, bir dəfə təkrar sına |
| Qənaət telemetriyası | `engine: <engine id>`                                   | `engine: "context-editing"`                                |

Bu iki yanaşma bir-birini tamamlayır: yerli mühərriklər OmniRoute-un göndərdiyi baytları sıxışdırır; Kontekst Redaktəsi isə
Claude-a ardıcıl sorğular boyunca cari konteksti budamağa imkan verir. Onlar birlikdə aktivləşdirilə bilər.
