> **Əhatə dairəsi qeydi:** `socket.yml` Socket.dev xidmətinin npm artefaktı üçün reyestr tərəfində, dərcdən sonra apardığı skanı konfiqurasiya edir (`tests/`, `docs/` və yığım hesabatları kimi paketə daxil edilməyən məzmun üçün nəzərə alınmayan yollar). O, CI/PR birləşdirmə nəzarətini qoşmur — `.github/workflows` daxilində heç bir iş axını, heç bir `package.json` skripti və heç bir `Makefile` hədəfi Socket.dev xidmətini çağırmır.

Bu sənəd `omniroute@3.8.5` üçün bildirilmiş altı
`Süni intellekt tərəfindən aşkarlanmış potensial zərərli proqram` tapıntısı və
`omniroute@3.8.6` versiyasında tətbiq edilmiş yumşaltma tədbirləri barədə müşayiətçi tərəfindən hazırlanmış təsdiq bəyanatıdır. Bu sənəd aşağıdakı məqsədlər üçün mövcuddur:

1. Təhlükəsizlik konveyerinin operatorları tapıntıları faktiki mənbə kodu ilə
   müqayisəli şəkildə qiymətləndirməli olduqda istinad edə biləcəkləri vahid mənbəyə malik olsunlar.
2. Gələcək süni intellekt skanerləri işarələnmiş hər bir yolun məqsədli,
   seçim əsasında aktivləşdirilən və sənədləşdirilmiş olduğuna dair müşayiətçi tərəfindən imzalanmış bəyanatı aşkarlaya bilsinlər.
3. Hər bir çağırış nöqtəsinin _niyə_ məhz bu şəkildə qurulduğuna dair yazılı qeydimiz olsun —
   beləliklə, gələcək refaktorinq qəsdən aradan qaldırılmış bir barmaq izini
   təsadüfən yenidən təqdim etməsin.

v3.8.6 üçün yumşaltma tədbirləri yayımlandıqdan sonra aşağıdakı çağırış
nöqtələrindən hər hansı birini yenidən işarələyən skaner işlədirsinizsə, skan izi ilə birlikdə problem bildirişi açın və
biz buradakı təsdiq bəyanatını genişləndirəcəyik.

## §1 — MITM kök CA quraşdırılması (`77484.js`)

**Mənbə faylları**:

- `src/mitm/cert/install.ts` — açıq `installCert()` / `uninstallCert()`,
  hər platforma üçün `installCertWindows/Mac/Linux`.
- `src/mitm/systemCommands.ts` — quraşdırma yollarının istifadə etdiyi ortaq `execFile` / `spawn` / PowerShell
  köməkçiləri.

**Tətikləyici**: istifadəçi `/dashboard/cli-tools/mitm` ünvanındakı lokal idarəetmə panelində
"MITM proksisini aktivləşdir" düyməsinə klikləyir. Marşrut yalnız geridöngə interfeysi üçündür — `CLAUDE.md`
faylındakı sərt qayda #17-yə və `src/server/authz/routeGuard.ts::isLocalOnlyPath()` funksiyasına baxın. Tunel vasitəsilə
ifşa edilmiş JWT bu kod yolunu **tətikləyə bilməz**.

**Yerinə yetirilən imtiyazlı əməliyyatlar (platforma üzrə)**:

| ƏS                     | Əmr(lər)                                                                                                          |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | UAC vasitəsilə `certutil -addstore Root <cert>`                                                                   |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | `certutil -d sql:<profile>` vasitəsilə hər profil üzrə NSS DB yeniləməsi                                          |

Bunlar `mitmproxy`, Charles Proxy, Fiddler və Caddy tərəfindən istifadə olunan eyni əmrlərdir.
Onların OmniRoute daxilində mövcud olması
`docs/security/STEALTH_GUIDE.md` sənədində qeyd edilib.

**v3.8.6 qarşı tədbiri**:

- `runElevatedPowerShell()` artıq `-EncodedCommand <base64utf16le>` istifadə etmir.
  Yüksəldilmiş imtiyazlarla icra ediləcək faydalı yük hər çağırış üçün müvəqqəti `.ps1` faylına (`mkdtempSync`
  ilə yaradılmış məxfi qovluğun daxilində, 0o600 rejimində) yazılır və ona `-File` vasitəsilə istinad edilir.
  Fayl `finally` daxilində silinir. Bu, Socket.dev-in süni intellekt
  təsnifatçısı tərəfindən işarələnmiş PowerShell vasitəsilə base64 yüksəltməsinin klassik izini aradan qaldırır.
- `installCertWindows` buraya yönləndirən sətirdaxili `SECURITY-AUDITOR-NOTE:` bloku
  ehtiva edir.

**Niyə bunu saxlayırıq**: MITM proksisi
`docs/security/STEALTH_GUIDE.md` və `docs/frameworks/MITM-PROXY.md` tərəfindən istifadə olunan sənədləşdirilmiş funksiyadır. Onun silinməsi
agent-körpüsü funksiyalar dəstini pozardı.

## §2 — Zed giriş məlumatlarının idxalı (`app/api/providers/zed/import/route.js`)

**Mənbə faylları**:

- `src/app/api/providers/zed/discover/route.ts` _(v3.8.6-da yenidir)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(v3.8.6-da yenidir)_

**Tətikləyici**: istifadəçi lokal idarəetmə panelinin Provayderlər
səhifəsində "Zed-dən idxal et" düyməsini klikləyir. Son nöqtə `requireManagementAuth`
ilə qorunur. Zed redaktoru öz provayder API açarlarını sənədləşdirilmiş xidmət
adları altında ƏS-in açarlar zəncirinə yazır — baxın: https://zed.dev/docs/ai/llm-providers.

**v3.8.5 davranışı (Socket.dev tərəfindən işarələnən)**:

`POST /import` giriş məlumatlarını aşkarlayır və onları bir sorğu-cavab dövründə
lokal SQLite yaddaşına avtomatik saxlayırdı. Hər hesab üzrə təsdiq və rəqəmsal
iz yox idi; sadəcə "N token tapıldı, hamısı idxal edildi."

**v3.8.6 təhlükəsizlik tədbiri — 2 mərhələli təsdiq**:

1. **`POST /api/providers/zed/discover`**
   `{ candidates: [{ provider, service, account, fingerprint }] }` qaytarır. Xam
   token **heç vaxt** ötürülmür. Rəqəmsal iz
   `sha256(service|account|token).slice(0,16)` şəklindədir.
2. İdarəetmə paneli namizədlərin siyahısını göstərir, operator idxal ediləcəkləri
   seçir və `{ confirmedAccounts: [{ service, account, fingerprint }] }`
   məlumatını **`POST /api/providers/zed/import`** son nöqtəsinə göndərir.
3. İdxal son nöqtəsi **serverdə açarlar zəncirini yenidən oxuyur** və
   `(service, account, fingerprint)` üzrə filtrləyir. Dəyişdirilmiş və ya təkrar
   istifadə edilmiş aşkarlama cavabı idxal son nöqtəsini əlaqəsi olmayan tokeni
   saxlamağa məcbur edə bilməz — canlı token aşkarlamadan sonra dəyişibsə,
   rəqəmsal iz artıq uyğun gəlmir və giriş məlumatı ötürülür.

`OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` mühit bayrağı avtomatlaşdırmasını
hələ yeniləməmiş operatorlar üçün v3.8.5 davranışını qoruyur. Bu bayraq
v3.9-da silinəcək.

**Onu saxlamağımızın səbəbi**: Zed idxalı artıq Zed-dən istifadə edən və
provayder açarlarını yenidən yapışdırmadan OmniRoute-a köçürmək istəyən
istifadəçilər üçün ən rahat ilkin quraşdırma yoludur.

## §3 — `execFile` / `spawn` / yüksəldilmiş səlahiyyətli PowerShell (`21843.js`)

**Mənbə faylları**: `src/mitm/systemCommands.ts`.

**İşarələnməsinin səbəbi**: fraqment `execFileWithPassword`,
`runElevatedPowerShell` və ortaq `quotePowerShell` köməkçi funksiyasını yenidən
ixrac edir. Socket.dev-in süni intellekt təsnifatçısı onları ümumi "hostda
icra + imtiyazların yüksəldilməsi alətləri dəsti" kimi qəbul edir. OmniRoute
daxilində onlar yalnız MITM sertifikatının quraşdırılması yolu (§1) və `sudo`
əmrlərinin icrası üçün `execFileWithPassword` tərəfindən istifadə olunur.

**v3.8.6 təhlükəsizlik tədbiri**:

- `runElevatedPowerShell` refaktorinqi (baxın: §1).
- Həm `runElevatedPowerShell`, həm də `execFileWithPassword` daxilindəki
  `SECURITY-AUDITOR-NOTE:` bloku icazə verilmiş çağıranları və sabitlənmiş
  icraolunan fayllar siyahısını sənədləşdirir.
- `execFileWithPassword` daxilindəki `spawn()` çağırışı köməkçi funksiyanın
  qəbul etməsinə icazə verilən icraolunan faylların icazə siyahısı ilə birlikdə
  `nosemgrep` işarəsini daşıyır — istifadəçi girişindən
  `finalCommand`/`finalArgs`-a aparan **heç bir yol yoxdur**.

## §4 / §6 — 9router xidmət nəzarətçisi (`api/services/9router/{start,restart}/route.js`)

**Mənbə faylları**:

- `src/app/api/services/9router/_lib.ts` — nəzarətçi fabriki.
- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`.
- `src/lib/services/ServiceSupervisor.ts` — ümumi proses başlatma / sağlamlıq yoxlaması / jurnal buferi.

**Tətikləyici**: istifadəçi lokal idarəetmə panelinin daxili xidmətlər
səhifəsində "Quraşdır" / "Başlat" düyməsini klikləyir.

**Artıq mövcud olan qoruma tədbirləri**:

- Bütün `/api/services/*` marşrutları
  `src/server/authz/routeGuard.ts` üzrə LOCAL_ONLY-dır (sərt qayda #17).
  Loopback məhdudiyyətinin tətbiqi hər hansı autentifikasiya yoxlamasından əvvəl
  baş verir — sızdırılmış JWT onlara çata bilməz.
- 9router verilənlər bazası sətri `status='not_installed', auto_start=0` kimi
  ilkinləşdirilir (baxın: `src/lib/db/migrations/071_services.sql:19`). Xidmət
  ilk işəsalmada **başlamır**.
- `spawn()` funksiyası
  `src/lib/services/installers/ninerouter.ts` daxilindəki
  `resolveSpawnArgs(apiKey, PORT)` tərəfindən qaytarılan binar fayl yolu ilə
  çağırılır; bu, dəstəklənən binar faylların sabit icazə siyahısıdır.
- Stdout/stderr yaddaşda buferlənir (5 MB həddi, baxın: `_lib.ts`) — istifadəçi
  idarəetmə panelindən jurnal yazılmasını aktivləşdirmədiyi halda diskə heç nə
  yazılmır.

**v3.8.6 təhlükəsizlik tədbiri**: funksional dəyişiklik yoxdur. Minimal yığım
profili (`OMNIROUTE_BUILD_PROFILE=minimal`) imtiyazlı yolların paketdən fiziki
olaraq silinməsini istəyən istifadəçilər üçün
`src/lib/services/installers/ninerouter.ts` faylını stub ilə əvəz edir.

**Onu saxlamağımızın səbəbi**: 9router istəyə bağlı, lokal olaraq quraşdırıla
bilən köməkçi xidmətdir (WordPress üslublu plagin kimi düşünün) — yalnız açıq
şəkildə seçim edildikdə aktivləşdirilir.

## §5 — OmniRoute Cloud Sync etimadnamələrinin geri yazılması (`api/keys/[id]/route.js`)

**Mənbə faylları**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`.
- `src/app/api/keys/[id]/route.ts` — `syncKeysToCloudIfEnabled()` funksiyasını çağırır.

**Tətikləyici**: `isCloudEnabled()` `true` qaytarır (idarəetmə panelindən təyin edilir) **və**
`CLOUD_URL` konfiqurasiya edilib. Hər ikisi deaktiv olduqda Bulud son nöqtəsinə
heç bir xarici şəbəkə çağırışı edilmir.

**v3.8.5 davranışı (Socket.dev-in düzgün şəkildə aşkarladığı xəta)**:

`cloudUpdatedAt > localUpdatedAt` olduqda `updateLocalTokens()` Bulud cavabındakı
`accessToken`, `refreshToken` və `providerSpecificData` dəyərlərinin üzərinə
yazırdı. HMAC, imza və yoxlama cəmi yox idi. Səhv konfiqurasiya edilmiş və ya
zərərli `CLOUD_URL` (yaxud kanaldakı MITM) provayderin OAuth tokenlərini
səssizcə dəyişdirə bilərdi.

**v3.8.6 təhlükəsizlik tədbiri**:

1. **HMAC yoxlaması**: `verifyCloudSignature(rawBody, sigHeader)` JSON-u
   təhlil etməzdən əvvəl `X-Cloud-Sig` başlığını
   (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET, rawBody)`) yoxlayır. Məxfi açar
   təyin edilibsə, imza məcburidir. Təyin edilməyibsə (köhnə rejim), xəbərdarlıq
   qeydə alınır və cavab qəbul edilir — v3.9 versiyasında məxfi açar məcburi olacaq.
2. **Məxfi sahələr üçün açıq razılıq**: `accessToken` / `refreshToken` /
   `providerSpecificData` sahələrinin üzərinə **yalnız**
   `OMNIROUTE_CLOUD_SYNC_SECRETS=true` olduqda yazılır. Standart rejim yalnız
   etimadnamə olmayan metadatanı (`expiresAt`, `status`, `lastError*`,
   `rateLimitedUntil`, `updatedAt`) sinxronlaşdırır. Bu, uzaqdan token
   sinxronizasiyasına güvənən istifadəçilər üçün **geriyə uyğun olmayan dəyişiklikdir**
   — onlar bunu açıq şəkildə aktivləşdirməlidirlər.

**Niyə bunu saxlayırıq**: Cloud Sync, OmniRoute Cloud tenantının komanda
etimadnamələrini mərkəzləşdirməsinin yeganə yoludur. Düzəliş təhdid modelini
dürüst edir: "server imzalayır, müştəri yoxlayır, operator açıq razılıq verir."

## Qurma profili: `minimal`

Socket ilə uyğun artefakta ehtiyacı olan istifadəçilər aşağıdakı əmrlə qura bilərlər:

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

webpack `NormalModuleReplacementPlugin` vasitəsilə dörd modulu stub-larla əvəz edir:

| Modul                                       | Stub                                             |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

Hər bir stub eyni interfeysi ixrac edir, lakin hər bir funksiya icra zamanı
`featureDisabledError(name)` xətası yaradır. Deaktiv edilmiş moduldan asılı olan
marşrutlar həssas kod yolunu aktivləşdirmək əvəzinə aydın mesajla HTTP 503
cavabı qaytarır.

Yaranan paket `omniroute-secure` kimi dərc edilmək üçün nəzərdə tutulub. Dərc
təlimatları üçün `docs/ops/PUBLISHING_SECURE.md` sənədinə baxın.

## Plaginin bölünməsi (v4 üçün izlənilir)

Uzunmüddətli perspektivdə npm paketini ayrıca audit edilə bilən modullara
bölmək niyyətindəyik. İzləmə məsələsi üçün GitHub məsələ izləyicisindəki v4 mərhələsinə
baxın.
