## İcmal

Kvota Paylaşma Mühərriki provayderin vaxta əsaslanan kvotasını (məsələn, Codex
üçün 5 saatlıq pəncərə, Kimi üçün 1500 sorğu/saat) eyni bağlantını paylaşan
çoxsaylı API açarları arasında ədalətli şəkildə bölüşdürür.

**Həll etdiyi problem:** OmniRoute çoxsaylı API açarlarının sorğularını eyni yuxarı
axın provayder hesabına proksiləyir. Paylaşma məntiqi olmadıqda, A açarından gələn
sorğu sıçrayışı provayderin saatlıq kvotasını tükədə bilər və pəncərə sıfırlanana
qədər B və C açarlarını bloklanmış vəziyyətdə qoya bilər. Mühərrik bunun qarşısını
aşağıdakı üsullarla alır:

1. Hər açarın hər ölçü üzrə sürüşən istehlakını (%, sorğular, tokenlər, $) izləyir.
2. İşi qoruyan ədalətli paylaşma alqoritmini tətbiq edir: qlobal hovuz doyma həddinə
   çatmadığı müddətdə açar boş qalan paylardan istifadə edə bilər.
3. Sorğu yuxarı axın icraçısına çatmazdan əvvəl nəticəni sürətli icra yolunda
   (`chatCore.ts`) tətbiq edir.

## Alqoritm: İşi qoruyan ədalətli paylaşma

`src/lib/quota/fairShare.ts` faylında həyata keçirilib.

### Rejimlər

| Şərt                                       | Rejim         | Davranış                                                                     |
| ------------------------------------------ | ------------- | ---------------------------------------------------------------------------- |
| `globalUsedPercent < saturationThreshold`  | **Səxavətli** | Açar qlobal limitdən ümumi istehlakı çıxmaqla alınan həddədək borc ala bilər |
| `globalUsedPercent >= saturationThreshold` | **Sərt**      | Fərdi ədalətli payı ciddi şəkildə tətbiq et                                  |

Standart `saturationThreshold = 0.5` (mühit dəyişəni `QUOTA_SATURATION_THRESHOLD`).

### Hər ölçü üzrə qərar

Hovuzdakı hər aktiv ölçü üçün mühərrik aşağıdakıları hesablayır:

```
fairShareAllowed = poolLimit × (allocationWeight / 100)
consumed        = bu açar üçün cari sürüşən dəyər (QuotaStore.peek-dən)
remaining       = fairShareAllowed - consumed
```

Sonra:

- **`policy = hard`**: əgər `consumed > fairShareAllowed` və rejim sərtdirsə → **blokla**.
- **`policy = soft`**: əgər `consumed > fairShareAllowed` və rejim sərtdirsə → **cərimələ** (kombinasiyada prioritetini azaldır; heç vaxt tam bloklamır).
- **`policy = burst`**: ədalətli paydan asılı olmayaraq qlobal ehtiyat mövcud olduğu müddətdə icazə ver.

### Mütləq hədd

Paylanmadakı `capValue` + `capUnit` rejimdən və ya siyasətdən asılı olmayan sərt
yuxarı həddir. `consumed >= capValue` olan istənilən ölçü sorğunu həmişə
**bloklayır**.

### Çoxölçülü yoxlama

Hovuzdakı **hər hansı** bir ölçü sorğunu bloklayarsa, sorğu bloklanır. Ölçülər
müstəqildir — 5h% kvotasının tükənməsi weekly% ölçüsünə təsir etmir.

### Borclanma

Səxavətli rejimdə paylanmış kvotasını tam istehlak etməmiş açar digər açarların
istifadə olunmamış paylarından yararlana bilər. Düstur belədir:

```
maxAllowed = globalLimit - consumedByOtherKeys
```

burada `consumedByOtherKeys = consumedTotal - consumedByThisKey`. Qlobal yuxarı
hədd (həmin ölçü üçün hovuzun `limit` dəyəri) həmişə sərt hədd olaraq qalır.

## Sürüşən pəncərə sayğacı

`src/lib/quota/sqliteQuotaStore.ts` və `redisQuotaStore.ts` fayllarında həyata keçirilib.

Hər `(apiKeyId, dimensionKey)` üçün iki seqment:

- `curr`: cari seqment (`floor(nowMs / windowMs)`)
- `prev`: əvvəlki seqment (`curr - 1`)

Effektiv sürüşən dəyər:

```
effectiveBucketIndex = floor(nowMs / windowMs)
bucketStartMs        = effectiveBucketIndex × windowMs
elapsed              = nowMs - bucketStartMs
weight               = 1 - elapsed / windowMs

effective = prev × weight + curr
```

**Dəqiqlik**: təxminən 99% dəqiqdir. Xəta seqmentlər arasındakı sərhəddə pəncərə
ölçüsünün ən çoxu 1%-ni təşkil edir (2 seqmentli aproksimasiyaya xasdır).

### Paralel icra

SQLite drayveri: hər `(apiKeyId | dimensionKey)` açarı üçün yaddaşdaxili mutex
oxu-dəyiş-yaz yarış vəziyyətinin qarşısını alır. Nümunə `src/sse/services/auth.ts`
faylındakı izdihamlı paralel sorğulara qarşı yanaşmanı təkrarlayır.

Redis drayveri: atomik artırma üçün Lua EVAL skripti — vahid Redis əmri kimi icra olunur.

## Drayverlər

### SQLite (standart, quraşdırma tələb etmir)

- Cədvəl: `quota_consumption` (`073_quota_pools.sql` / `074_quota_consumption.sql` miqrasiyalarına baxın).
- Tək instanslı yerləşdirmələr üçün ən uyğundur.
- Bütün davamlı məlumatlar mövcud OmniRoute SQLite verilənlər bazasında (`DATA_DIR/storage.sqlite`) saxlanılır.

### Redis (istəyə bağlı, çox instanslı)

- `ioredis` npm paketini tələb edir.
- Sayğaclar Redis-də saxlanılır; metaməlumatlar (hovuzlar/ayırmalar) isə SQLite-da qalır.
- Sayğacların paylaşılmalı olduğu çox replikalı yerləşdirmələr üçün ən uyğundur.

### Drayverlərin dəyişdirilməsi

Parametrlər interfeysi (`/dashboard/settings` → Quota Store) və ya mühit dəyişənləri vasitəsilə:

```bash
QUOTA_STORE_DRIVER=redis
QUOTA_STORE_REDIS_URL=redis://localhost:6379
```

Verilənlər bazasındakı parametr mühit dəyişənindən daha yüksək prioritetə malikdir. Əgər `driver=redis` olsa, lakin URL mövcud olmasa və ya
`ioredis` quraşdırılmasa, fabrika SQLite-a geri keçir və xəbərdarlıq qeydə alır.

Drayverin seçim ardıcıllığı:

1. Verilənlər bazası parametri `quotaStore.driver`
2. Mühit dəyişəni `QUOTA_STORE_DRIVER`
3. Standart: `sqlite`

## Konveyerə İnteqrasiya

### PRE qoşması (`open-sse/handlers/chatCore.ts`)

Autentifikasiya və siyasət yoxlamalarından sonra, yuxarı axın icraçısından əvvəl işə salınır:

```
resolveComboTargets / handleSingleModel
  → enforceQuotaShare(apiKeyId, connectionId, provider, estimatedCost)
      → hər ölçü üçün getQuotaStore().peek()
      → fairShare.decideFairShare()
      → bloklanarsa → 429 qaytar (buildErrorBody, Sərt Qayda #12)
      → icazə verilərsə + prioritet azaldılarsa → namizəd üçün quotaSoftPenalty=true təyin et
  → executor.execute()
```

**Xəta zamanı icazə**: `enforceQuotaShare` istisna atarsa, sorğunun keçməsinə
icazə verilir və `pino.warn` qeydi yaradılır. Bu, kvota mexanizmindəki xətanın bütün
trafiki bloklamasının qarşısını alır.

### POST qoşması (istehlakın qeydə alınması)

Uğurlu cavabdan sonra:

```
icraçı uğurlu nəticə qaytarır
  → spendRecorder.recordConsumption(apiKeyId, connectionId, provider, actualCost)
      → hər ölçü üçün getQuotaStore().consume()
      → xəta zamanı icazə: xətalar pino.warn kimi qeydə alınır, heç vaxt müştəriyə ötürülmür
```

**Yayınma qeydi**: cavabdan sonra `consume` uğursuz olarsa, sürüşən sayğac faktiki istehlakı
olduğundan az hesablayır. Provayderdən gələn doyma siqnalı (məsələn, `anthropic-ratelimit-unified-5h-utilization`)
növbəti sorğuda qlobal qiymətləndirməni düzəldir.

### Combo yumşaq cəriməsi (`open-sse/services/combo.ts`)

`decision.deprioritize === true` olduqda:

```ts
if (candidate.quotaSoftPenalty) {
  score *= QUOTA_SOFT_DEPRIORITIZE_FACTOR; // standart 0.7
}
```

Cərimə bütün digər qiymətləndirmə amillərindən sonra tətbiq olunur. Bu, sərt şəkildə
bloklamadan, doymuş açarın avtomatik combo tərəfindən seçilmə ehtimalını azaldır.

## Problemlərin aradan qaldırılması

### Redis konfiqurasiya edilib, lakin qoşulmur

`ioredis` paketinin quraşdırıldığını (`npm ls ioredis`) və `QUOTA_STORE_REDIS_URL`
ünvanının əlçatan olduğunu yoxlayın. Bağlantı uğursuz olarsa, fabrika SQLite-a
geri keçir (hadisə `warn` səviyyəsində jurnala yazılır).

### `peek` köhnəlmiş nəticə qaytarır / açıq rejimdə uğursuz olur

`peek` xəta verərsə, `enforceQuotaShare` nəticəni «icazə ver» kimi qəbul edir (uğursuzluq zamanı açıq rejim).
Əsas səbəbi müəyyən etmək üçün `pino` jurnallarında `quota:enforce` və
`quota:factory` qeydlərini yoxlayın.

### İstehlak sayğacında yayınma

Provayderin faktiki istifadəsi sayğaclardan fərqlənirsə, bu gözləniləndir —
2-seqmentli sürüşən pəncərənin sərhədlərində təxminən 1% xəta olur və `consume`
cavabdan sonra nəticə gözlənilmədən icra edilir. Doyma siqnalı (`saturationSignals.ts`)
30 saniyəlik TTL ilə provayderin faktiki istifadə səviyyəsini oxuyur və
`globalUsedPercent` dəyərini müvafiq olaraq tənzimləyir.

### Hovuz sərfiyyat sürəti üçün «məlumat yoxdur» göstərir

`computeBurnRate` ən azı 2 tarixi nümunə tələb edir. Əvvəlki `consume`
çağırışları olmayan yeni hovuzlar `tokensPerSecond: 0` və `timeToExhaustionMs: null`
göstərəcək.

## localStorage-dan miqrasiya

`/dashboard/costs/quota-share` ilk dəfə yükləndikdə `useLocalStoragePoolMigration` hook-u aşağıdakıları yoxlayır:

1. `localStorage.getItem("omniroute:quota-share:pools")` boş deyil.
2. `GET /api/quota/pools` sorğusu `[]` qaytarır (DB boşdur).

Hər iki şərt doğru olarsa, hər bir köhnə hovuz paket şəklində `POST /api/quota/pools` ünvanına göndərilir, sonra isə localStorage açarı silinir. Miqrasiya idempotentdir: 2-ci şərt təkrar miqrasiyanın qarşısını alır.

## Daxili Strategiya Təsnifatı

`quota-share`, **yalnız daxili istifadə üçün** nəzərdə tutulmuş marşrutlaşdırma strategiyasıdır (`src/shared/constants/routingStrategies.ts` faylındakı `INTERNAL_ROUTING_STRATEGY_VALUES`). O, yalnız sistem tərəfindən yaradılan `qtSd/` hovuz kombinasiyalarında istifadə olunur və UI və ya API-də heç vaxt istifadəçinin seçə biləcəyi seçim kimi görünməməsi üçün qəsdən `ROUTING_STRATEGY_VALUES` siyahısına daxil edilməyib.

## Test Əhatəsi

Quota-share mühərriki iki səviyyəli avtomatlaşdırılmış test əhatəsi ilə təqdim olunur:

| Test dəsti          | Əmr                                                                    | Nələri əhatə edir                                                                                                                                                                                                                                       |
| :------------------ | :--------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Modul (29 test)     | `node --import tsx/esm --test tests/unit/quota-share-strategy.test.ts` | DRR planlaşdırıcısı, doyma nəzarəti, paralellik limitləri, fairShare hesablamaları, növbəyə yığılma                                                                                                                                                     |
| İnteqrasiya matrisi | `npm run test:combo:matrix`                                            | Real kombinasiya konveyeri vasitəsilə başdan sona marşrutlaşdırma qərarı; canlı inteqrasiya nöqtələri (`registerQuotaFetcher`, `setLKGP`, `__setHeadroomSaturationFetcherForTests`) vasitəsilə DRR ədalətliliyi və doyma zamanı prioritetin azaldılması |

İnteqrasiya matrisi CI-də bütün 19 açıq strategiya ilə birlikdə icra olunur. Modul test dəsti ayrıca icra edilə bilər.

## DB Sxeminin Xülasəsi

`078`, `079` və `085` miqrasiyaları ilə əlavə edilmiş üç cədvəl:

- `quota_pools` + `quota_allocations` — hovuz tərifləri və hər açar üzrə ayırmalar.
- `quota_consumption` — hər `(apiKeyId, dimensionKey)` üçün sürüşən 2-buketli sayğaclar.
- `provider_plans` — provayder planlarının əl ilə verilən əvəzləmələri (hər connectionId üçün ölçülər JSON formatında).

Bütün cədvəllər idempotent `CREATE TABLE IF NOT EXISTS` miqrasiyaları vasitəsilə əlavə edilib.
