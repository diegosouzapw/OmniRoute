## 1. Texnologiya steki

| Sahə              | Seçim                                                                                                                           |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Veb freymvork     | **Next.js 16** (App Router, müstəqil çıxış, qlobal middleware yoxdur)                                                           |
| Dil               | **TypeScript 6.0+** — hədəf `ES2022`, `module: esnext`, `moduleResolution: bundler`, `strict: false`                            |
| İcra mühiti       | **Node.js** `>=22.22.2 <23` və ya `>=24.0.0 <27` (`engines` + `SUPPORTED_NODE_RANGE` vasitəsilə məcburi tətbiq olunur)          |
| Verilənlər bazası | `better-sqlite3` vasitəsilə **SQLite** (tək instansiya, WAL jurnallaşdırması)                                                   |
| Masaüstü          | **Electron 41** + `electron-builder` 26.10 (`electron/` daxilində ayrıca iş sahəsi)                                             |
| Testlər           | **Node-un daxili test icraedicisi** (vahid/inteqrasiya), **Vitest** (MCP, autoCombo, keş), **Playwright** (e2e + protocols-e2e) |
| Qurma             | `scripts/build/build-next-isolated.mjs` vasitəsilə Next.js müstəqil qurması                                                     |
| Lint/format       | ESLint düz konfiqurasiyası + Prettier (Husky pre-commit vasitəsilə `lint-staged`)                                               |
| Modul sistemi     | Hər yerdə ESM (`"type": "module"`)                                                                                              |
| İş sahələri       | npm iş sahəsi — `open-sse` yeganə alt iş sahəsidir                                                                              |

Yol aliasları (`tsconfig.json`):

- `@/*` → `src/*`
- `@omniroute/open-sse` → `open-sse/index.ts`
- `@omniroute/open-sse/*` → `open-sse/*`

Defolt HTTP portu: **`20128`** (API və idarəetmə paneli eyni prosesi paylaşır). Verilənlər
qovluğu `DATA_DIR` mühit dəyişəni ilə təyin olunur və defolt olaraq `~/.omniroute/` istifadə edilir.

### 3.1 `src/app/` — App Router

App Router həm idarəetmə paneli interfeysini, həm də ictimai/idarəetmə HTTP API-sini təqdim edir.
**Qlobal middleware yoxdur** — müdaxilə hər marşrut üzrə həyata keçirilir.

`src/app/` altındakı yuxarı səviyyəli seqmentlər:

| Yol                                                                           | Təyinatı                                                         |
| ----------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| `api/`                                                                        | Bütün HTTP API marşrutları (aşağıdakı bölgüyə baxın)             |
| `a2a/`                                                                        | A2A JSON-RPC 2.0 son nöqtəsi (`POST /a2a`)                       |
| `.well-known/agent.json/`                                                     | A2A Agent Card aşkarlama sənədi                                  |
| `(dashboard)/`                                                                | İdarəetmə paneli interfeysi (marşrut qrupu, URL prefiksi yoxdur) |
| `auth/`, `login/`, `forgot-password/`, `callback/`                            | Autentifikasiya axınları                                         |
| `landing/`                                                                    | Marketinq/tanıtım səhifəsi                                       |
| `docs/`                                                                       | Daxili API sənədləri görüntüləyicisi                             |
| `status/`, `maintenance/`, `offline/`                                         | Əməliyyat səhifələri                                             |
| `privacy/`, `terms/`                                                          | Hüquqi səhifələr                                                 |
| `400/`, `401/`, `403/`, `408/`, `429/`, `500/`, `502/`, `503/`                | Statik xəta səhifələri                                           |
| `error.tsx`, `global-error.tsx`, `not-found.tsx`, `forbidden/`, `loading.tsx` | Freymvorkun xəta/yüklənmə sərhədləri                             |
| `layout.tsx`, `page.tsx`, `globals.css`, `manifest.ts`                        | Kök örtük                                                        |

#### 3.1.2a `src/app/api/services/` — Daxili xidmətlərin idarə edilməsi

9Router və CLIProxyAPI-ni quraşdırmaq, başlatmaq, dayandırmaq və izləmək üçün marşrutlar.
Bütün yollar **LOCAL_ONLY** (yalnız loopback, sərt qayda #17) kimi təsnif edilir, çünki onlar
`npm install` əmrini işə sala və alt proseslər yarada bilər.

```
src/app/api/services/
├── 9router/
│   ├── _lib.ts             getOrInitSupervisor() köməkçisi
│   ├── install/route.ts    POST — execFile vasitəsilə npm install
│   ├── start/route.ts      POST — supervisor.start()
│   ├── stop/route.ts       POST — supervisor.stop()
│   ├── restart/route.ts    POST — supervisor.restart()
│   ├── update/route.ts     POST — daha yeni versiyanın npm install ilə quraşdırılması
│   ├── rotate-key/route.ts POST — yeni API açarı yaratmaq + yenidən başlatmaq
│   ├── status/route.ts     GET  — canlı + DB statusu + versiya metadatası
│   └── auto-start/route.ts POST — auto_start bayrağını dəyişdirmək
├── cliproxy/
│   ├── _lib.ts             getOrInitSupervisor() köməkçisi
│   ├── install/route.ts    POST — npm install
│   ├── start/route.ts      POST — supervisor.start()
│   ├── stop/route.ts       POST — supervisor.stop()
│   ├── restart/route.ts    POST — supervisor.restart()
│   ├── update/route.ts     POST — daha yeni versiyanın npm install ilə quraşdırılması
│   ├── status/route.ts     GET  — canlı + DB statusu + versiya metadatası

    └── logs/route.ts       GET  — SSE jurnalının son hissəsi (bütün xidmətlər tərəfindən paylaşılır)
```

Müvafiq idarə paneli istifadəçi interfeysi:

`src/app/(dashboard)/dashboard/providers/services/[name]/embed/[[...path]]/route.ts`

Ətraflı məlumat: `docs/frameworks/EMBEDDED-SERVICES.md`

## 11. Konvensiyalar

- **Kod üslubu**: 2 boşluqluq abzas, qoşa dırnaqlar, 100 simvol eni, nöqtəli vergüllər,
  `es5` son vergülləri — `lint-staged` vasitəsilə Prettier tərəfindən məcburi tətbiq edilir.
- **İdxallar**: xarici → daxili (`@/`, `@omniroute/open-sse`) → nisbi.
- **Adlandırma**: fayllar `camelCase` və ya `kebab-case`, komponentlər `PascalCase`,
  sabitlər `UPPER_SNAKE`.
- **ESLint**: `no-eval`, `no-implied-eval`, `no-new-func` = hər yerdə `error`;
  `no-explicit-any` = `open-sse/` və `tests/` daxilində `warn`, digər yerlərdə isə xəta.
- **TypeScript**: `strict: false` (köhnə yanaşma). Modullar arası sərhədlərdə çıxarış əvəzinə
  aşkar tiplərə üstünlük verin.
- **Verilənlər bazası**: marşrutlarda və ya emalçılarda heç vaxt birbaşa SQL yazmayın — həmişə
  `src/lib/db/` modullarından istifadə edin. Heç vaxt barrel-idxaldan istifadə etməyin — konkret `src/lib/db/*` modullarını birbaşa istifadə edin.
- **DB obyekti tipləşdirməsi (#3512)**: DB cədvəlinin sətir strukturunu yazan və ya oxuyan funksiya,
  çağırış yerində `any` və ya daxili anonim tip deyil, həmin cədvəlin sütunlarını
  1:1 əks etdirən adlandırılmış TS interfeysini qəbul və ya qaytarmalıdır. İnterfeysi
  funksiyanın yanında yerləşdirin (məsələn, `saveRequestUsage` funksiyasının üzərindəki
  `src/lib/usage/usageHistory.ts` faylında `export interface UsageEntry`), müxtəlif
  yazıcılar sətri mərhələli şəkildə doldurduqda ayrı-ayrı sahələri qeyri-məcburi/nullable
  saxlayın və strukturu çağıranlar arasında dəyişən sahə üçün `any` əvəzinə `unknown`
  seçin (sahədə sənədləşdirilməlidir; məsələn, `UsageEntry.tokens` həm provayderin xam
  strukturundakı istifadə məlumatını, həm də normallaşdırılmış strukturu qəbul edir).
  Faylın `any` sayı bu üsulla sıfıra çatdıqda onu `check:any-budget:t11` icazə siyahısına
  (`scripts/check/check-t11-any-budget.mjs`, `maxAny: 0`) əlavə edin ki, geriləmə baş verməsin.
  Bu, ilkin hissə üçün konvensiyadır — daha geniş «anonim `any` olmasın» təmizlənməsi kod
  bazasının qalan hissəsində iterativ şəkildə aparılır.
- **Xətalar**: xüsusi xəta tipləri ilə try/catch istifadə edin, pino konteksti ilə jurnala yazın. SSE
  axınlarındakı xətaları heç vaxt səssizcə udmayın; təmizləmə üçün dayandırma siqnallarından istifadə edin.
- **Təhlükəsizlik**: heç vaxt `eval()` / `new Function()` / dolayı eval istifadə etməyin. Bütün
  girişləri Zod ilə doğrulayın. Giriş məlumatlarını saxlanma zamanı şifrələyin (AES-256-GCM).
  `src/shared/constants/upstreamHeaders.ts` qadağa siyahısını
  təmizləmə/doğrulama qatı ilə uyğun saxlayın.
- **Kommitlər**: Conventional Commits — `feat(scope): subject`. İcazə verilən əhatələr:
  `db`, `sse`, `oauth`, `dashboard`, `api`, `cli`, `docker`, `ci`, `mcp`,
  `a2a`, `memory`, `skills`.
- **Budaqlar**: prefikslər `feat/`, `fix/`, `refactor/`, `docs/`, `test/`,
  `chore/`. Heç vaxt birbaşa `main` budağına kommit etməyin.
- **Husky**: pre-commit zamanı `lint-staged` + `check:docs-sync` +
  `check:any-budget:t11`; pre-push zamanı isə `check:any-budget:t11` + `check:tracked-artifacts` işə salınır (sürətli yoxlamalar; `test:unit` daxil deyil).
