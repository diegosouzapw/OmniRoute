1. Mövcud tək açarlı semafor müqaviləsini və yeni atomik çox açarlı
   müqaviləni hədəflənmiş testlərlə sabitləyin: qismən rezervasiyaların olmaması,
   FIFO növbələnməsi, dayandırma, vaxt aşımı, növbənin dolması, idempotent
   buraxma, statistikalar və təmizləmə.
2. Mövcud hesab semaforunu yerində ümumiləşdirin. `acquire()` metodunu
   `acquireMany()` ətrafında uyğunluq örtüyü kimi saxlayın; ikinci planlaşdırıcı
   və ya asılılıq əlavə etməyin.
3. `chatCore` daxilində yalnız hesaba əsaslanan əldəetməni `withRateLimit`
   çağırışından dərhal əvvəl bir kumulyativ qlobal/provayder/hesab əldəetməsi ilə
   əvəz edin. Hesab rotasiyası bağlantını dəyişdikdə bütün dəsti yenidən əldə
   edin və buraxmanı axın tamamlanana qədər saxlayın.
4. Mövcud dayanıqlılıq parametrləri konveyerini (tiplər, standart dəyərlər,
   normallaşdırma, sxem, API cavabı, UI və tərcümələr) qlobal və provayder
   limitləri ilə genişləndirin. Köhnə Bottleneck paralellik idarəetməsini
   bağlantı/kvota əhatə dairəsi paralelliyi kimi yenidən adlandırın ki, onun
   həqiqi əhatə dairəsi aydın olsun.
5. Hədəflənmiş testləri, linti, tip yoxlamasını, statik yoxlamaları və tam test
   dəstini işə salın; davranış dəyişikliyini dəyişiklik jurnalında sənədləşdirin.

Qəsdən qorunan davranış: sıfır/null paralellik qapıdan yan keçir, yalnız hesab
üçün olan çağıranlar `acquire()` istifadə etməyə davam edir, bloklanmış hesab
idarəetmələri öz açar formatını və API-sini saxlayır və provayderin sürət limiti
növbəsinin davranışı dəyişməz qalır.
