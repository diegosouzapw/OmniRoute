OmniRoute OpenAI Codex-dən istifadə etmək üçün **iki** üsul təqdim edir:

| Provayder              | OpenAI ilə necə əlaqə qurur                                                                                                                                                                                                 | İstifadə ilə bağlı qeyd                                                  |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| **`codex`**            | ChatGPT/OpenAI OAuth tokeninizi birbaşa Responses API-yə təkrar ötürür                                                                                                                                                      | **Bəli** — rəsmi sessiyanın proksi/router istifadəsi üçün icazəsi yoxdur |
| **`codex-app-server`** | **Codex CLI-nin öz `codex app-server` xidmətini** JSON-RPC/WebSocket üzərindən idarə edir; CLI öz OAuth məlumatlarına (`~/.codex/auth.json`) interaktiv `codex` sessiyasında olduğu kimi sahib olur və onları özü yeniləyir | **Xeyr** — OmniRoute heç vaxt tokeni API-yə təkrar ötürmür               |

`codex-app-server` heç vaxt tokeni təkrar ötürmədiyi üçün ona
sessiyanın təkrar ötürülməsi ilə bağlı istifadə qeydi şamil edilmir. Bunun üçün
**konfiqurasiya edilmiş app-server URL-də əlçatan Codex CLI** tələb olunur və
həmin CLI-də **sessiya açılmış** olmalıdır.

---

## 1. Arxitektura

```
┌─ OmniRoute tətbiqi ──────────────┐        ┌─ codex-app-server köməkçi konteyneri ─┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                      │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456            │
│  (+ imkan tokeni)                │  JSON  │  --ws-auth capability-token            │
│                                  │  RPC   │  OpenAI OAuth-u özü idarə edir          │
└──────────────────────────────────┘        │  (~/.codex/auth.json, avtomatik yenilənmə) │
        │ paylaşır (compose volume-ları)     └────────────────────────────────────────┘
        ▼
  codex-appserver-token   → WS imkan tokeni (hər ikisi onu mount edir)
  codex-appserver-home    → ~/.codex (auth.json idarəetmə paneli tərəfindən yazılır,
                             köməkçi konteynerin codex app-server xidməti tərəfindən oxunur)
```

- Köməkçi konteyner imkan tokeni arxasında **yalnız** daxili compose şəbəkəsində
  (`ws://codex-app-server:1456`) dinləyir. O, hostda və ya internetdə **heç vaxt**
  yayımlanmır.
- Codex CLI `omniroute:base` daxilində əvvəlcədən yerləşdirilib, buna görə də
  köməkçi konteyneri işə salarkən hostda və ya istifadəçinin kompüterində codex
  quraşdırmağa ehtiyac yoxdur.

## 2. İşə salın

```bash
# Steki codex app-server köməkçi konteyner profili İLƏ başladın:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

Köməkçi konteyner ilk dəfə başladıqda öz WS imkan tokenini yaradır (paylaşılan
`codex-appserver-token` volume-unda) və tətbiq eyni tokeni
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE` vasitəsilə oxuyur. Tokeni əl ilə
əlaqələndirməyə ehtiyac yoxdur.

## 3. Qoşulun və sessiya açın

1. İdarəetmə panelində **OpenAI Codex (App-Server)** üçün bağlantı əlavə edin. API
   açarı və ya token tələb olunmur (bu, autentifikasiya tələb etməyən provayderdir
   — autentifikasiyanı köməkçi konteyner idarə edir).
2. Köməkçi konteynerin Codex CLI-sində **hələ sessiya açılmayıbsa**, bağlantının
   vəziyyət yoxlaması _"işləyir, lakin sessiya açılmayıb"_ mesajını göstərir
   (qırmızı autentifikasiya xətası deyil). **ChatGPT ilə daxil olun** seçimindən
   istifadə edin: bu, brauzerinizdə standart Codex cihaz OAuth prosesini işə
   salır və sonra **Autentifikasiya məlumatlarını tətbiq et** vasitəsilə
   `~/.codex/auth.json` faylını paylaşılan volume-a yazır (eyni giriş həm `codex`,
   həm də `codex-app-server` provayderlərinə xidmət edir).
3. Sessiya açıldıqdan sonra vəziyyət yoxlaması yaşıl olur (həm `/readyz`, **həm
   də** `account/read` yoxlanılır — yəni xidmət həm aktivdir, həm də
   autentifikasiya olunub) və işləməyə başlayır.

İdarəetmə paneli mövcud sağlam `~/.codex/auth.json` faylının üzərinə heç vaxt
yazmır — yalnız fayl mövcud olmadıqda və ya onun tokeni köhnəldikdə yazır
(həmişə ehtiyat nüsxə yaradılır).

## 4. Yerləşdirmə ssenariləri

- **Artıq autentifikasiya olunmuş Codex CLI-yə sahib operator** — hostunuzdakı
  `~/.codex` qovluğunu köməkçi konteynerə (`codex-appserver-home`) mount edin və
  sessiya açma addımını keçin.
- **İctimai istifadəçi, lokalda codex quraşdırılmayıb** — bunun əhəmiyyəti yoxdur:
  köməkçi konteynerdə CLI mövcuddur. İstifadəçi yalnız idarəetmə paneli vasitəsilə
  autentifikasiya olunur.
- **Bare-metal OmniRoute (köməkçi konteyner yoxdur, hostda codex var)** —
  `OMNIROUTE_CODEX_APPSERVER_WS` dəyişənini öz `codex app-server` xidmətinizə
  yönəldin və hostdakı codex sessiyasının açıq olduğuna əmin olun; binar fayl
  mövcud deyilsə, "codex quraşdırılmayıb" ipucu göstərilir.

## 5. Məişət / UDP çıxış trafiki (operator üçün əlavə, paketə daxil deyil)

Yuxarıdakı ümumi köməkçi konteyner çıxış trafikini konteynerin adi şəbəkəsi
üzərindən yönləndirir. Codex trafikini **məişət çıxış nöqtəsi** (məsələn, TCP +
UDP/QUIC daşıyan TUN tailscale köməkçi konteyneri) vasitəsilə yönləndirməli olan
operator bunu ayrıca compose override kimi işə salır; bu, bilərəkdən təqdim
edilən `codex-app-server` profilinə daxil edilməyib. Həmin quraşdırma üçün daxili
əməliyyat təlimatına baxın.
