## 1. Antigravity və Antigravity CLI (agy) müqayisəsi

Hər iki provayder **eyni Google server infrastrukturundan** istifadə edir — OAuth müştərisi, token yeniləməsi, son nöqtələr və Google hesabları eynidir. Fərq sizə hansı modellərin göstərilməsindədir.

> Google-un rəsmi müqayisəsi üçün [Antigravity CLI elanına](https://antigravity.google/blog/introducing-google-antigravity-cli) baxın.

| Aspekt                    | `antigravity` (IDE)                                             | `agy` (CLI)                                                               |
| ------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------- |
| **Google məhsulu**        | Antigravity 2.0 / Antigravity IDE                               | Antigravity CLI                                                           |
| **Server infrastrukturu** | Eyni Google Cloud Code API                                      | Eyni Google Cloud Code API                                                |
| **OAuth / Token**         | Eyni müştəri, eyni yeniləmə                                     | Eyni müştəri, eyni yeniləmə                                               |
| **Model kataloqu**        | Statik seçilmiş siyahı (OmniRoute daxilində sərt kodlaşdırılıb) | `:fetchAvailableModels` vasitəsilə Google-dan canlı sorğu ilə əldə edilir |
| **Claude modelləri**      | Sonnet 4.6, Opus 4.6 (hər birinin 4 variantı)                   | Sonnet 4.6, Opus 4.6 (hər birinin 4 variantı)                             |
| **Gemini adlandırması**   | Sadə etiketlər (Aşağı/Orta/Yüksək)                              | Yuxarı axın identifikatorları (extra-low/low/agent)                       |
| **Əlavə modellər**        | `gpt-oss-120b-medium`                                           | Google-dan əlavə modelləri ehtiva edə bilər                               |
| **Defolt istifadə halı**  | IDE inteqrasiyası (VS Code, JetBrains)                          | CLI / API girişi                                                          |
| **Kvota**                 | agy ilə paylaşılır (eyni Google hesabı)                         | antigravity ilə paylaşılır (eyni Google hesabı)                           |

**Mövcud modellər (təcrübə ilə təsdiqlənib, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (müxtəlif düşünmə səviyyələri)
- Claude: Sonnet 4.6, Opus 4.6 (hər biri defolt/aşağı/orta/yüksək variantlarla)
- Digər: GPT-OSS 120B Medium
- **Claude Sonnet 5 mövcud DEYİL** — yalnız 4.6 variantları dəstəklənir

**Model kataloqunun fərqlənmə səbəbi**: Google-un rəsmi bloquna əsasən, Google CLI “sürət və aşağı əlavə yük üçün optimallaşdırılıb” və “Gemini modelləri ilə birgə optimallaşdırılıb”. Veb/IDE məhsulu isə “əhatəlilik üçün optimallaşdırılıb”. CLI modelləri dinamik şəkildə aşkar etmək üçün `:fetchAvailableModels` istifadə edir, IDE isə statik seçilmiş siyahıdan istifadə edir.

**Praktikada**: Gemini modelləri üçün `agy/` prefiksindən istifadə edin (məsələn, `agy/gemini-3.7-flash-high`). Statik seçilmiş siyahı üçün `antigravity/` istifadə edin. Hər ikisi eyni Google server infrastrukturuna müraciət edir, lakin fərqli model adlandırmasını təqdim edir. Kvota paylaşılır — hər iki provayderdən istifadə eyni Google hesabının limitlərinə daxil edilir.

## 2. Google One AI Pro: Kvota Sistemi

> Rəsmi kvota təfərrüatları üçün [Antigravity Sənədləri: Planlar](https://antigravity.google/docs/plans), ən son qiymət yeniləmələri üçün isə [Antigravity Planlarında Dəyişikliklər](https://antigravity.google/blog/changes-to-antigravity-plans) səhifəsinə baxın.

Google Antigravity mesaj sayına deyil, "Görülən İş"ə (hesablama yükünə) əsaslanan **ikiqat kvota** sistemindən istifadə edir.

### İki Səviyyə

| Səviyyə            | Nədir                              | Yenilənmə dövrü                                                                             |
| ------------------ | ---------------------------------- | ------------------------------------------------------------------------------------------- |
| **5 saatlıq dövr** | Dərhal əlçatan "görülən iş" hovuzu | Sessiyadakı ilk sorğudan 5 saat sonra sıfırlanır                                            |
| **7 günlük baza**  | Həftəlik sərt limit                | Limitə çatdıqda 5 saatlıq yenilənməni üstələyir; növbəti 7 günlük dövrədək girişi bloklayır |

**"Görülən İş"in hesablanması**: Agentdən intensiv istifadə edən tapşırıqlar (məsələn, "Bütün bu repozitoriyanı refaktorinq et") kvotanı sadə tapşırıqlardan (məsələn, "Bu funksiyanı düzəlt") daha sürətlə sərf edir. İstehlakı göstərən real vaxt idarə paneli yoxdur.

### Plan Səviyyələri

| Plan         | Qiymət     | Kvota                                       | Həftəlik limit                                         |
| ------------ | ---------- | ------------------------------------------- | ------------------------------------------------------ |
| Pulsuz       | $0         | Əhəmiyyətli kvota, həftəlik yenilənir       | Bəli                                                   |
| AI Pro       | $19.99/ay  | Yüksək kvota, 5 saatlıq fasiləsiz yenilənmə | Bəli (limitə çatdıqda 5 saatlıq yenilənməni üstələyir) |
| AI Ultra 5x  | $99.99/ay  | Pro kvotasının 5 qatı                       | Həftəlik limit yoxdur                                  |
| AI Ultra 20x | $199.99/ay | Pro kvotasının 20 qatı                      | Həftəlik limit yoxdur                                  |

### Gemini və Qeyri-Gemini Modelləri

- **Gemini modelləri** (Flash + Pro): API qiymətinə əsasən sərf olunan vahid tezlik limitini paylaşır. Flash Pro-dan 8 dəfə ucuzdursa, 8 dəfə çox Flash tokeni əldə edirsiniz.
- **Qeyri-Gemini modelləri** (Claude, GPT-OSS): **Ayrı** tezlik limitlərinə malikdir. Gemini bloklandıqda belə əlçatan qala bilərlər.

### AI Kreditləri (Limit Aşımı)

> Kreditlərin necə işlədiyini öyrənmək üçün [Google One AI kreditləri](https://support.google.com/googleone/answer/14534406) səhifəsinə baxın.

Baza kvotası tükəndikdə:

- **Heç vaxt**: Kvotanın yenilənməsini gözləyir; "Baza model kvotasına çatıldı" mesajını göstərir
- **Həmişə**: AI kreditlərindən avtomatik istifadə edir; baza kvotası yeniləndikdə ona geri keçir

Kreditlər ayrıca alınır və standart API qiymətlərinə uyğun çıxılır.

### Əsas Təfərrüatlar

- Kvota **hesab səviyyəsində paylaşılır** — Antigravity IDE, CLI və OmniRoute daxilində eyni Google hesabı vahid kvota hovuzunu paylaşır
- Hər Google hesabının öz müstəqil kvotası var — bir neçə hesab = bir neçə kvota hovuzu
- AI Pro istifadəçiləri həftəlik baza limitinə çatdıqda 5 saatlıq sıfırlanma əvəzinə **7 günlük bloklanmalar** barədə məlumat veriblər (Google bunun yüksək tələbat üçün nəzərdə tutulmuş davranış olduğunu təsdiqləyib)

**Hesabınızın kvotası tükəndikdə**: OmniRoute kombinə edilmiş marşrutdakı növbəti əlçatan hesabla avtomatik olaraq yenidən cəhd edir. Əl ilə müdaxilə tələb olunmur.

## 3. projectId Necə Əldə Edilir

Hər antigravity/agy bağlantısı üçün Google Cloud Code `projectId` tələb olunur. O olmadıqda `/v1internal:models` son nöqtəsi 404 qaytarır.

### Metod A: Avtomatik (Tövsiyə olunur)

OmniRoute bunu avtomatik həyata keçirir. İdarə panelində OAuth vasitəsilə yeni Google hesabı əlavə etdikdə:

1. OmniRoute tokeni yeniləyir
2. projectId-ni aşkarlamaq üçün `loadCodeAssist` çağırır
3. Heç bir layihə mövcud deyilsə, layihə yaratmaq üçün `onboardUser` çağırır
4. Yeni yaradılmış projectId-ni əldə etmək üçün `loadCodeAssist` çağırışını təkrarlayır
5. Onu verilənlər bazasında saxlayır

**Bu, əksər hesablar üçün işləyir** — əl ilə addımlar tələb olunmur.

### Metod B: agy CLI Vasitəsilə Əl ilə

Avtomatik aşkarlama uğursuz olarsa (bunun nə vaxt baş verdiyi üçün Bölmə 5-ə baxın):

```bash
# agy CLI-ni quraşdırın (əgər artıq quraşdırılmayıbsa)
npm install -g @anthropic-ai/agy

# Google hesabınızla daxil olun
agy login

# Qeydiyyatdan keçirilməli olan hesabı seçin
# Bu, Cloud Code qeydiyyatını başladır və projectId təyin edir
```

`agy login` uğurla tamamlandıqdan sonra OmniRoute İdarə Panelində tokeni yeniləyin. projectId avtomatik aşkarlanacaq.

### Necə yoxlanılır

Verilənlər bazasını yoxlayın:

```bash
# OmniRoute konteynerinin daxilində
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Yaxud jurnalları yoxlayın:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. OAuth Yönləndirmə URI-si

### Problem

Google OAuth etibarlı yönləndirmə URI-si tələb edir. OmniRoute standart olaraq `http://127.0.0.1:20128/callback` (geri döngə) ünvanından istifadə edir. Bu, lokal yığımlar üçün işləyir, lakin **uzaq yerləşdirmələrdə uğursuz olur** (məsələn, LAN IP-si vasitəsilə əldə edilən serverdə).

Google aşağıdakı yönləndirmə URI-lərini rədd edir:

- IP ünvanlarından istifadə edənlər (sonu `.com`, `.org` və s. ilə bitən domen olmalıdır)
- OAuth müştəri konfiqurasiyasında qeydiyyatdan keçmiş yönləndirmə URI-ləri ilə uyğun gəlməyənlər

### Həll

**Seçim A: Daxili OAuth axınından istifadə edin (standart)**

- OmniRoute-a `localhost` və ya `127.0.0.1` vasitəsilə daxil olduğunuz zaman işləyir
- Heç bir konfiqurasiya tələb olunmur

**Seçim B: Fərdi OAuth identifikasiya məlumatları**

- Mühitinizdə `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` təyin edin
- Öz Google OAuth identifikasiya məlumatlarınızı təqdim edin:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Google Cloud Console-da `https://your-domain.com/callback` ünvanını səlahiyyətli yönləndirmə URI-si kimi qeydiyyatdan keçirin

**Seçim C: İlkin giriş üçün agy CLI-dan istifadə edin**

- OmniRoute-a daxil olacaq kompüterdə `agy login` əmrini icra edin
- OAuth axını lokal olaraq tamamlanır və tokenlər saxlanılır
- Bağlantını İdarəetmə paneli vasitəsilə OmniRoute-a idxal edin

### Məhdudiyyətlər

- Fərdi OAuth identifikasiya məlumatları domen adı tələb edir (Google IP ünvanlarını yönləndirmə URI-ləri kimi qəbul etmir)
- Domeniniz yoxdursa, bunun əvəzinə A və ya C Seçimindən istifadə edin

## 5. Problemlərin aradan qaldırılması: Avtomatik quraşdırma uğursuz olduqda

OmniRoute əksər hesablar üçün projectId aşkarlanmasını və ilkin qeydiyyatı avtomatik idarə edir. Proses uğursuz olduqda, əsas səbəb adətən aşağıdakılardan biri olur:

### Hesab regionu bloklanıb

**Əlamət**: `agy login` "Eligibility check failed: Your current account is not eligible for Antigravity, because it is not currently available in your location." xətasını qaytarır.

**Əsas səbəb**: Google hesablarında qeydiyyat zamanı təyin edilən daxili "Country Association" sahəsi var. agy CLI və Cloud Code API bu sahəni ciddi şəkildə yoxlayır — yalnız cari IP ünvanınızı yoxlayan veb Gemini-dən fərqli olaraq.

> Hesabınızla əlaqələndirilmiş regionu yoxlamaq və ya dəyişdirmək üçün [Google Ölkə Əlaqələndirmə Formasına](https://policies.google.com/country-association-form) daxil olun.

**Niyə veb Gemini işləyir, lakin agy işləmir**:

- Veb Gemini / Google One: yalnız cari IP-ni yoxlayır (proksi ilə işləyir)
- agy CLI / Cloud Code API: daxili Country Association sahəsini oxuyur (proksi kömək etmir)

**Həll**:

1. ABŞ IP ünvanından istifadə edərkən [Google Ölkə Əlaqələndirmə Formasına](https://policies.google.com/country-association-form) daxil olun
2. Regionun dəyişdirilməsi sorğusunu göndərin ("I live in a different country" seçimini seçin)
3. Google-un sorğunu emal etməsi və e-poçt bildirişi göndərməsi üçün 1–24 saat gözləyin
4. Bundan sonra `agy login` uğurla işləməlidir

### Hesabda Cloud Code layihəsi yoxdur

**Əlamət**: Jurnallarda `loadCodeAssist returned no project id` və `onboardUser failed (400)` göstərilir.

**Əsas səbəb**: Hesab heç vaxt Google Cloud Code-da qeydiyyatdan keçirilməyib və avtomatik ilkin qeydiyyat uğursuz olub.

**Həll**: Cloud Code qeydiyyatını başlatmaq üçün `agy login` əmrini əl ilə icra edin, sonra OmniRoute İdarəetmə panelində tokeni yeniləyin.

### Tokenin müddəti bitib və ya ləğv edilib

**Əlamət**: Jurnallarda 401 xətaları və ya "Token has expired" mesajları görünür.

**Həll**: İdarəetmə paneli → Provayderlər → agy bölməsinə keçin → yeniləmə nişanına klikləyin. Yeniləmə tokeninin özü ləğv edilibsə, OAuth vasitəsilə yenidən autentifikasiyadan keçməlisiniz.
