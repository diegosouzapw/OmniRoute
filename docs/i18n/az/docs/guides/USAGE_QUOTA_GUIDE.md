> **Qısa xülasə**: OmniRoute hər sorğunun token istifadəsini izləyir, xərci hesablayır, hər API açarı üzrə kvotanı tətbiq edir və analitik məlumatları idarəetmə panelində göstərir. Bu təlimat bütün bunların necə işlədiyini izah edir.

**Mənbələr:**

- `open-sse/services/usage.ts` (~70KB) — əsas istifadə izləmə xidməti
- `src/lib/usageAnalytics.ts` (~10KB) — idarəetmə paneli üçün aqreqasiya
- `src/lib/db/quotaSnapshots.ts` — tarixi kvota məlumatları
- `src/lib/db/usage*.ts` — istifadə ilə əlaqəli bir neçə DB modulu

## Ümumi baxış

OmniRoute üzərindən keçən hər sorğu aşağıdakı məlumatları əhatə edən **istifadə qeydi** yaradır:

- **İdentifikasiya**: hansı API açarı, provayder, model və kombinasiya
- **Tokenlər**: prompt tokenləri, tamamlama tokenləri, keşlənmiş tokenlər, ümumi say
- **Xərc**: USD məbləği (qiymət məlumatlarından hesablanır)
- **Vaxt göstəriciləri**: gecikmə, başlama/bitmə vaxt nişanları
- **Status**: uğurlu, xəta, sürət məhdudiyyətinə məruz qalmış və s.

Bu qeydlər **analitika** şəklində aqreqasiya olunur, **kvota anlıq görüntüləri** kimi saxlanılır və **hər açar üzrə büdcə limitlərini** tətbiq etmək üçün istifadə edilir.

```
Sorğu ──▶ chatCore ──▶ usage.record() ──▶ SQLite
                                  │
                          ┌───────┼───────┐
                          ▼       ▼       ▼
                    analitika  kvota   hesablaşma
                    (panel)    (tətbiq) (ixrac)
```

## Hansı Məlumatlar Qeydə Alınır

`usage.ts` xidməti hər sorğu üçün bir **istifadə hadisəsi** qeydə alır:

| Sahə               | Növ     | Mənbə                                                      |
| ------------------ | ------- | ---------------------------------------------------------- |
| `id`               | string  | Qeyd zamanı yaradılan UUID                                 |
| `apiKeyId`         | string  | Sorğunu başladan API açarı                                 |
| `provider`         | string  | Provayder ID-si (openai, anthropic və s.)                  |
| `model`            | string  | Model ID-si (gpt-5, claude-opus-4-6 və s.)                 |
| `comboId`          | string? | Kombinasiya vasitəsilə yönləndirilibsə, kombinasiya ID-si  |
| `promptTokens`     | number  | Yuxarı axın cavabından                                     |
| `completionTokens` | number  | Yuxarı axın cavabından                                     |
| `cachedTokens`     | number  | Keş uyğunluğu tokenləri (Anthropic prompt keşləməsi və s.) |
| `totalTokens`      | number  | prompt + tamamlama                                         |
| `costUsd`          | number  | Qiymət məlumatlarından hesablanır                          |
| `latencyMs`        | number  | Sorğunun başdan sona müddəti                               |
| `status`           | enum    | `success`, `error`, `rate_limited`, `timeout`, `cancelled` |
| `errorClass`       | string? | status != success olduqda xəta sinfi                       |
| `timestamp`        | string  | ISO 8601 UTC                                               |
| `metadata`         | object  | Plagin tərəfindən əlavə edilən xüsusi məlumatlar           |

### Tokenlər Haradan Gəlir

Tokenlər yuxarı axın provayderinin cavabından **cavab emalçısında** çıxarılır:

```ts
// open-sse/handlers/chatCore.ts faylından
const response = await providerExecutor.execute(provider, request);
const usage = response.usage || {
  prompt_tokens: 0,
  completion_tokens: 0,
  cached_tokens: 0,
};
```

İstifadə məlumatlarını qaytarmayan provayderlər üçün (bəzi veb-kuki provayderləri) OmniRoute tokenlərin sayını `hər token üçün ~4 simvol` evristikasından istifadə edərək **təxmin edir** (bax: `open-sse/services/autoCombo/pipelineRouter.ts`).

### Keşlənmiş Tokenlər

OmniRoute `cached_tokens` göstəricisini `prompt_tokens` göstəricisindən ayrı izləyir, çünki:

- Anthropic prompt keşləməsi keşlənmiş tokenlər üçün daha aşağı tarif tətbiq edir (normal tarifin 10%-i)
- Bəzi provayderlər fərqli qiymətləndirilməli olan `cache_read_input_tokens` qaytarır
- Analitika **keş uyğunluğu nisbətini** göstərə bilər = `cached_tokens / prompt_tokens`

## Xərcin Hesablanması

Xərclər LiteLLM-dən sinxronlaşdırılan **qiymət məlumatları** əsasında hesablanır (`src/lib/pricingSync.ts`):

| Model             | Giriş $/1M | Çıxış $/1M | Keşlənmiş $/1M |
| ----------------- | ---------- | ---------- | -------------- |
| gpt-5             | $2.50      | $10.00     | —              |
| claude-opus-4-6   | $15.00     | $75.00     | $1.50          |
| claude-sonnet-4-5 | $3.00      | $15.00     | $0.30          |
| gemini-2.5-pro    | $1.25      | $10.00     | —              |

Xərc düsturu (`src/lib/usage/costCalculator.ts`):

```ts
cost =
  (prompt_tokens - cached_tokens) * input_price +
  cached_tokens * cached_price +
  completion_tokens * output_price;
```

> **Keşlənmiş tokenlər niyə sorğudan çıxılır?** Keşlənmiş hissə ayrıca qiymətləndirilir; bütün sorğu üçün giriş qiymətinin tətbiq edilməsi xərcin artıq hesablanmasına səbəb olardı.

### Qiymətlərin Sinxronlaşdırılması

Qiymət məlumatları LiteLLM-dən `/api/pricing/sync` son nöqtəsi vasitəsilə avtomatik sinxronlaşdırılır (istifadəçiyə təqdim olunan mühit dəyişəni ilə deyil, daxili cron tapşırığı ilə başladılır):

```bash
# Əl ilə başladılma
curl -X POST http://localhost:20128/api/pricing/sync
```

Qiymət məlumatları olmayan modellər üçün OmniRoute daxili orta tariflərdən (LiteLLM-in qiymət məlumatlarından əldə edilən) istifadə edərək **xərci təxmini hesablayır**.

## Tarix Aralığı üzrə Aqreqasiya

`usageAnalytics.ts` modulu ilkin istifadə məlumatlarından idarəetmə paneli vidjetlərini hesablayır. O, 7 zaman aralığını dəstəkləyir:

| Aralıq   | Müddət                                     | İstifadə ssenarisi                        |
| -------- | ------------------------------------------ | ----------------------------------------- |
| `1d`     | Son 24 saat                                | Saatlıq xərc sıçrayışlarının aşkarlanması |
| `7d`     | Son 7 gün                                  | Həftəlik icmal                            |
| `30d`    | Son 30 gün                                 | Aylıq hesablaşma                          |
| `90d`    | Son 90 gün                                 | Rüblük təhlil                             |
| `ytd`    | Cari ilin 1 yanvarından etibarən           | İllik büdcənin izlənməsi                  |
| `all`    | Bütün dövr                                 | Ümumi statistika                          |
| `custom` | İstifadəçinin müəyyən etdiyi başlanğıc/son | Auditlər, xüsusi sorğular                 |

### Hesablanan İdarəetmə Paneli Vidjetləri

İstənilən tarix aralığı üçün analitika qatı aşağıdakıları hesablayır:

| Vidjet                                  | Təsvir                                                       |
| --------------------------------------- | ------------------------------------------------------------ |
| **Xülasə kartları**                     | Ümumi sorğular, ümumi xərc, ümumi tokenlər, uğur göstəricisi |
| **Gündəlik trend qrafiki**              | Model üzrə qruplaşdırılmış gündəlik xərc və tokenlər         |
| **Aktivlik istilik xəritəsi**           | Günün saatı × həftənin günü cədvəli, rəng = sorğu sayı       |
| **Model üzrə bölgü**                    | Model üzrə xərclərin dairəvi diaqramı                        |
| **Provayder üzrə bölgü**                | Provayder üzrə sorğuların sütun diaqramı                     |
| **Ən çox istifadə olunan API açarları** | Xərcə görə ilk 10 açarın cədvəli                             |
| **Xəta təhlili**                        | Zaman üzrə xəta göstəricisi, əsas xəta sinifləri             |

### Proqram Vasitəsilə Giriş

````ts
import { computeAnalytics } from "@/lib/usageAnalytics";

const analytics = await computeAnalytics(
  history,              // istifadə tarixçəsinin qeydləri
  "7d",                 // zaman aralığı: "1d" | "7d" | "30d" | "90d" | "ytd" | "all" | "custom"
  connectionMap,        // provayder bağlantı xəritəsi (connectionId → hesab adı)
  {
    startDate: "2025-01-01",  // ixtiyari: "custom" aralığı üçün
    endDate: "2025-06-01",   // ixtiyari: "custom" aralığı üçün
  }
);

console.log(analytics.summary.totalCost);   // 12.34 (sent)
console.log(analytics.byModel[0]);           // { model, cost, requests, promptTokens, completionTokens }

## Kvotanın Tətbiqi

Hər API açarı üzrə kvota iki yerdə tətbiq olunur:

1. **Yumşaq limit** (`quotaWarnAt`): istifadə həddi aşdıqda idarəetmə panelində xəbərdarlıq
2. **Sərt limit** (`quotaLimit`): limit aşıldıqda sorğu HTTP 429 kodu ilə rədd edilir

### Konfiqurasiya

```ts
// Hər API açarı üzrə
await updateApiKey(keyId, {
  quotaWarnAt: 5_00,    // $5.00 — xəbərdarlıq göstər
  quotaLimit: 10_00,    // $10.00 — sərt dayandırma
  quotaWindow: "month", // "day" | "week" | "month" | "all"
});
````

### Tətbiq Axını

```
Sorğu ──▶ quotaCheck()
              │
              ├── Limit daxilindədir?  ──▶ icazə ver
              │
              └── Limit aşılıb?  ──▶ 429 Həddindən Artıq Sorğu
                                   Retry-After başlığı ilə
```

### Kvota Anlıq Görüntüləri

`quotaSnapshots` cədvəli tendensiyaların təhlili üçün **tarixi kvota vəziyyətini** saxlayır:

| Sahə | Təsvir |
| ----------- | -------------------------------- | ------ | ------- |
| `apiKeyId` | İzlənilən açar |
| `window` | "day" | "week" | "month" |
| `used` | Bu pəncərədə istifadə olunan xərc (sentlə) |
| `limit` | Limit (sentlə) |
| `resetAt` | Pəncərənin sıfırlandığı vaxt |
| `createdAt` | Anlıq görüntünün alındığı vaxt |

Anlıq görüntülər dəyəri > 0 olan **hər sorğuda** alınır və aşağıdakılar üçün istifadə edilir:

- İdarəetmə panelində kvota irəliləyiş zolağını göstərmək
- 30 günlük kvota tendensiyası qrafiklərini göstərmək
- İstifadə limitə yaxınlaşdıqda xəbərdarlıqları işə salmaq

## Saxlama və Təmizləmə

İstifadə məlumatları hər sorğu üçün təxminən 1-10KB artır. Böyük miqyasda bu, əhəmiyyətli ola bilər.

### Saxlama Parametrləri

İstifadə tarixçəsinin saxlanması UI-dakı Database Settings vasitəsilə və ya `/api/settings/database` üzərindən konfiqurasiya edilir.

Standart olaraq istifadə tarixçəsi **90 gün** saxlanılır.

### Təmizləmə

Köhnə qeydlər `src/lib/db/cleanup.ts` tərəfindən təmizlənir:

- Arxa fon cron prosesi tərəfindən işə salınır
- Konfiqurasiya edilmiş `usageHistory` saxlama parametrindən daha köhnə qeydləri `usage_history` cədvəlindən silir

### Yaddaş Həcminin Təxmini Hesablanması

| Sorğu tezliyi     | 30 günlük yaddaş | 90 günlük yaddaş |
| ----------------- | ---------------- | ---------------- |
| 100 sorğu/gün     | ~3MB             | ~9MB             |
| 1,000 sorğu/gün   | ~30MB            | ~90MB            |
| 10,000 sorğu/gün  | ~300MB           | ~900MB           |
| 100,000 sorğu/gün | ~3GB             | ~9GB             |

Çox yüksək trafik üçün bunları nəzərdən keçirin:

- Database Settings vasitəsilə saxlama müddətini azaltmaq
- Xam qeydlərin əvəzinə `aggregated_metrics` istifadə etmək (yalnız analitika üçün)

## Xərclərin Optimallaşdırılması üzrə Məsləhətlər

### 1. Düzgün Modeldən İstifadə Edin

```bash
# Sürətli cavab — ucuz + sürətli modeldən istifadə edin
curl -d '{"model":"auto/fast","messages":[...]}'

# Mürəkkəb tapşırıq — keyfiyyətli modeldən istifadə edin
curl -d '{"model":"auto/smart","messages":[...]}'
```

### 2. Keşləməni Aktivləşdirin

Anthropic sorğu keşləməsi **təkrarlanan kontekst üzrə 90% qənaət edir**:

```ts
// Keşləmə avtomatikdir — sadəcə eyni böyük sistem sorğusunu daxil edin
const response = await openai.chat({
  model: "claude-sonnet-4-5",
  system: longSystemPrompt, // Avtomatik olaraq keşlənəcək
  messages: [{ role: "user", content: "..." }],
});
```

### 3. Sıxılmadan İstifadə Edin

RTK + Caveman sıxılması **alətlərdən intensiv istifadə edilən sessiyalarda 15-95% qənaət edir**:

```ts
const config = {
  compression: {
    engine: "rtk",
    intensity: "aggressive",
  },
};
```

### 4. Hər Açar üçün Kvotalar Təyin Edin

Nəzarətsiz xərclərin qarşısını almaq üçün həmişə `quotaLimit` təyin edin:

```ts
await updateApiKey(keyId, { quotaLimit: 10_00 }); // $10/ay limiti
```

### 5. Ən Çox İstehlak Edənləri Yoxlayın

API açarına görə qruplaşdırmaq və xərcə görə sıralamaq üçün idarəetmə panelindən və ya **`/api/usage/analytics`** ünvanından istifadə edin:

```bash
GET /api/usage/analytics?groupBy=apiKey
```

## Problemlərin Aradan Qaldırılması

### "Xərc gözləniləndən yüksəkdir"

1. **`/api/usage/analytics?groupBy=model`** ünvanını yoxlayın — bahalı modeli tapın
2. **`/api/usage/analytics?groupBy=apiKey`** ünvanını yoxlayın — çox istehlak edən istifadəçini tapın
3. Qiymət məlumatlarının aktual olduğunu yoxlayın: `POST /api/pricing/sync`

### "Qeydlər yoxdur"

- Dashboard → Database → Cleanup bölməsində DB saxlama parametrlərini yoxlayın — köhnə qeydlər dövri təmizləmə tapşırığı (`src/lib/db/cleanup.ts`) tərəfindən silinir
- `src/lib/db/usage*.ts` daxilində xətaları yoxlayın — DB-yə yazma xətaları jurnala qeyd olunur, lakin göstərilmir
- Sorğunun həqiqətən `chatCore`-a çatdığını yoxlayın — combo marşrutlaşdırmasını yoxlayın

### "Kvota tətbiq edilmir"

- Açarın `quotaLimit` parametrini yoxlayın
- `quotaWindow` parametrinin düzgün təyin edildiyini yoxlayın
- `quotaSnapshots` qeydlərini axtarın — onlar hər sorğuda yaradılmalıdır
