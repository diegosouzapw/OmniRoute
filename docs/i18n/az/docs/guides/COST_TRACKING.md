OmniRoute-un hər sorğunun xərcini necə təxmin etdiyi, qeydə aldığı və hesabatlaşdırdığı — və nə üçün
idarə panelindəki rəqəmin hesab deyil, **qənaət izləyicisi** olduğu.

Həmçinin baxın: [İstifadəçi təlimatı](./USER_GUIDE.md) · [Funksiyalar qalereyası](./FEATURES.md)

---

## Bu nədir (və nə deyil)

OmniRoute token saylarını modelin qiymət tariflərinə vuraraq hər tamamlanma üçün sorğu üzrə
USD xərcini hesablayır. Bu rəqəmlər **Xərclər** idarə panelində, `omniroute cost` /
`omniroute usage` CLI komandalarında, CSV/JSON ixraclarında və hər API açarı üzrə büdcələrdə
istifadə olunur.

> **İdarə panelindəki «xərc» hesab deyil, qənaət izləyicisidir.** OmniRoute sizdən heç vaxt
> ödəniş almır — o, sorğularınızı artıq qoşduğunuz provayderlərə (öz abunəliklərinizə,
> pulsuz tariflərə və API açarlarınıza) yönləndirir. Tamamilə pulsuz modellərdə yığılmış
> «$290 ümumi xərc» o deməkdir ki, ödənişli API-yə təxminən **$290 ödəməmisiniz**. Bu rəqəm
> eyni trafikin standart siyahı qiymətləri ilə nə qədər başa gələcəyinin _təxminidir_;
> beləliklə, istifadənizin harada cəmləşdiyini və daha ucuz/pulsuz provayderlərə
> yönləndirmənin sizə nə qədər qənaət etdirdiyini görə bilərsiniz.

Bu yanaşma layihənin [README](../../README.md) faylında birbaşa qeyd olunur («idarə
panelindəki 'xərc' hesab deyil, qənaət izləyicisidir»).

Bu rəqəm təxmini olduğuna görə:

- O, OmniRoute-un hər model üçün malik olduğu qiymət cədvəlindən asılıdır. Qiymət qeydi
  olmayan model `0` xərc hesablayır (araşdırıcıda «Köhnə / Pulsuz» sətri kimi göstərilir).
- Pulsuz tarif və abunəlik trafiki üçün də _təxmini_ xərc hesablanır — bu, borclu olduğunuz
  məbləğ deyil, qənaət etdiyiniz məbləğdir.

## Xərclər necə təxmin edilir

### Qiymət mənbəyi

Xərclər aşağıdakı üstünlük sırasına əsasən müəyyən edilən qiymət cədvəlindən götürülür
([`src/lib/pricingSync.ts`](../../src/lib/pricingSync.ts)):

1. **İstifadəçi əvəzləmələri** — idarə panelində / `PATCH /api/pricing` vasitəsilə təyin
   etdiyiniz qiymətlər.
2. **Sinxronlaşdırılmış xarici qiymətlər** — sinxronizasiya aktiv olduqda LiteLLM-in açıq
   `model_prices_and_context_window.json` faylından əldə edilir (əvəzləmələrinizi heç vaxt
   dəyişdirməməsi üçün ayrıca `pricing_synced` ad fəzasında saxlanılır).
3. **Sərt kodlaşdırılmış standart dəyərlər** — OmniRoute ilə birlikdə təqdim olunur.

Xarici qiymət sinxronizasiyası **seçim əsasında aktivləşdirilir** və standart olaraq
deaktivdir. Müvafiq mühit dəyişənləri
([`.env.example`](../../.env.example) faylına baxın):

| Mühit dəyişəni          | Standart  | Məqsəd                                                                   |
| ----------------------- | --------- | ------------------------------------------------------------------------ |
| `PRICING_SYNC_ENABLED`  | `false`   | Başlanğıcda LiteLLM qiymət sinxronizasiyasını fonda aktivləşdirir.       |
| `PRICING_SYNC_INTERVAL` | `86400`   | **Saniyə** ilə sinxronizasiya intervalı (standart olaraq gündəlik).      |
| `PRICING_SYNC_SOURCES`  | `litellm` | Vergüllə ayrılmış mənbə siyahısı (hazırda yalnız `litellm` dəstəklənir). |

### Xərc düsturu

Xərc hər sorğu üçün token saylarından və bir milyon token üzrə tariflərdən istifadə etməklə
[`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) faylında
(`computeCostFromPricing` / `calculateCost`) hesablanır:

- **Giriş tokenləri** (keş oxumaları və keş yaratma tokenləri çıxılmaqla) × `input` tarifi.
- **Keşdən oxunan tokenlər** × `cached` tarifi (olmadıqda giriş tarifindən istifadə edilir).
- **Keş yaratma tokenləri** × `cache_creation` tarifi (olmadıqda giriş tarifindən istifadə edilir).
- **Çıxış tokenləri** × `output` tarifi.
- **Mühakimə tokenləri** × `reasoning` tarifi (olmadıqda çıxış tarifindən istifadə edilir).

Bütün tariflər 1.000.000 token üçün USD kimi şərh olunur. Codex «fast»/«priority» və ya
«flex» xidmət səviyyəsi xərc əmsalı (`getCodexFastCostMultiplier`) tətbiq edir — məsələn,
flex tokenlərə 50% endirimlə hesablanır və idarə panelində **flex qənaəti** kimi göstərilir.

Əvvəlcə model adları normallaşdırılır (məsələn, `openai/` və ya
`accounts/fireworks/models/` kimi provayder yolu prefiksləri silinir) ki, tarixi sətirlər
hələ də qiymətlə uyğunlaşdırıla bilsin.

### Xərclər necə qeydə alınır

- Hər sorğu üzrə xərc cavabdan sonra hesablanır və müştəri üçün heç bir gecikmə
  yaratmaması məqsədilə nəticə gözlənilmədən qeydə alınır. Paylaşılan kvotanın istifadəsi
  növbəti hadisə dövrü addımında
  [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts) vasitəsilə
  planlaşdırılır.
- API açarı üzrə xərclər buferlənir və
  [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) tərəfindən paketlərlə yazılır
  (standart yazma intervalı 60 saniyə, bufer ölçüsü 1.000 qeyd). Aşağıdakılar vasitəsilə
  tənzimlənə bilər:

  | Mühit dəyişəni                      | Standart | Məqsəd                                       |
  | ----------------------------------- | -------- | -------------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000`  | Millisaniyə ilə buferi yazma intervalı.      |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`   | Yazmadan əvvəl buferdəki maksimum qeyd sayı. |

İdarə panelindəki xərc rəqəmləri hər sətir üçün saxlanılmış dollar məbləğindən **oxunmur** —
analitika son nöqtəsi hər dəfə işlədikdə onlar token sayları və cari qiymət cədvəli
əsasında yenidən hesablanır. Bu o deməkdir ki, səhv qiymətin düzəldilməsi (və yenidən
sinxronlaşdırılması) tarixi xərc təxminlərini geriyə dönük olaraq yeniləyir.

## İdarə paneli: Xərclər səhifəsi

**Xərclər** səhifəsi `/dashboard/costs` ünvanında yerləşir
(`src/app/(dashboard)/dashboard/costs/`).
Onun əsas görünüşü **Xərclərə ümumi baxış** tabıdır
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`);
bu tab bütün məlumatları `GET /api/usage/analytics` vasitəsilə yükləyir.

Göstərilənlər:

- **Xərc göstəriciləri** — _Bu gün (1d)_, _7d_, _30d_ və seçilmiş
  dövr üçün təxmini xərclər. Aralıq seçicisi: `7d`, `30d`, `90d`, `all`.
- **Əsas metrikalar** — dövr ərzindəki sorğular, aktiv provayderlər, aktiv modellər,
  hər sorğu üzrə orta xərc.
- **Xərc araşdırıcısı** — **provayder**, **model**,
  **API açarı**, **hesab** və ya **xidmət səviyyəsi** üzrə qruplaşdırılan, çeşidlənə və filtrlənə bilən cədvəl; xərc, sorğu sayı, token sayı,
  hər sorğu üzrə orta xərc və ümumi xərcdəki payı (%) göstərir.
- **Token istifadəsi** — ümumi / giriş / çıxış tokenləri və giriş:çıxış nisbəti.
- **Marşrutlaşdırma səmərəliliyi** — ehtiyat variantdan istifadə sayı, ehtiyat varianta keçid faizi və tələb olunan modelin əhatə səviyyəsi.
- **Aylıq proqnoz** — son gündəlik orta göstəriciyə əsasən ay sonundakı xərci proqnozlaşdırır.
- **Dövrlərin müqayisəsi** — dövrün birinci və ikinci yarısı arasındakı % dəyişiklik.
- **Diaqramlar** — gündəlik xərc tendensiyası, provayderlərin payı (dairəvi), ən çox istifadə olunan provayderlər, ən çox istifadə olunan modellər, API açarı
  üzrə xərc, hesab üzrə xərc, həftəlik istifadə sxemi və aktivlik istilik xəritəsi.
- **İxrac** — cari dövrün məlumatlarını **CSV** və ya **JSON** kimi endirin (düymələr
  xərc məlumatları sıfırdan böyük olduqda görünür).

Tarif tətbiq edilmiş trafik olmadıqda, qənaət izləyicisi modelini əks etdirmək üçün sətirlərdə `$0`
əvəzinə "Köhnə / Pulsuz" etiketi göstərilir.

### Xərclərlə əlaqəli alt səhifələr

Xərclər bölməsinə həmçinin aşağıdakılar daxildir (hamısı `/dashboard/costs/` altında yerləşir):

- **Qiymətqoyma** (`/dashboard/costs/pricing`) — modellər üzrə qiymətlərə baxın və onları əvəzləyin (ortaq
  Qiymətqoyma tabını göstərir).
- **Büdcə** (`/dashboard/costs/budget`) — əhatə dairəsi üzrə xərc limitləri təyin edin (ortaq
  Büdcə tabını göstərir).
- **Kvota paylaşımı** (`/dashboard/costs/quota-share`) — ortaq kvota hovuzları və istifadə sürəti
  görünüşləri.

## API son nöqtələri

Qeyd edilmədiyi halda, bunların hamısı idarəetmə autentifikasiyası tələb edir (loopback/JWT, `requireManagementAuth` vasitəsilə).

### İstifadə və xərc analitikası

| Metod | Son nöqtə                | Məqsəd                                                                                                                                                                    |
| ----- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET` | `/api/usage/analytics`   | Tam xərc/istifadə analitikası: xülasə, gündəlik tendensiya, provayder/model/API açarı/hesab/səviyyə üzrə. Sorğu: `range`, `startDate`, `endDate`, `apiKeyIds`, `presets`. |
| `GET` | `/api/usage/utilization` | Zaman ərzində hər provayder üzrə kvota istifadəsi. Sorğu: `range` (`1h`/`24h`/`7d`/`30d`), `provider`.                                                                    |
| `GET` | `/api/usage/history`     | Xam istifadə tarixçəsi sətirləri.                                                                                                                                         |
| `GET` | `/api/usage/call-logs`   | Hər sorğu üzrə çağırış jurnalları (model, tokenlər, xərc, gecikmə, status).                                                                                               |
| `GET` | `/api/usage/quota`       | Provayder kvotasının statusu.                                                                                                                                             |
| `GET` | `/api/usage/proxy-logs`  | Proksi sorğularının jurnalları.                                                                                                                                           |

### Büdcələr

| Metod  | Son nöqtə                | Məqsəd                                                                                        |
| ------ | ------------------------ | --------------------------------------------------------------------------------------------- |
| `GET`  | `/api/usage/budget`      | Bir API açarı üçün xərc xülasəsi + büdcə yoxlaması (`apiKeyId` sorğu parametri tələb olunur). |
| `POST` | `/api/usage/budget`      | API açarı üçün gündəlik/həftəlik/aylıq USD limitlərini və xəbərdarlıq həddini təyin edin.     |
| `GET`  | `/api/usage/budget/bulk` | API açarları üzrə toplu büdcə xülasələri.                                                     |

> Büdcə API-si hər **API açarı** (`apiKeyId`) üzrə əhatə dairəsinə malikdir.
> `GET /api/usage/budget` tərəfindən qaytarılan limitlərə `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`,
> `warningThreshold` və cari cəmlər (`totalCostToday`, `totalCostMonth`, …) daxildir.

### Qiymətqoyma

| Metod    | Son nöqtə               | Məqsəd                                                                                                                             |
| -------- | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/pricing`          | Cari birləşdirilmiş qiymətlər (istifadəçi + sinxronlaşdırılmış + standart). Hər qeyd üzrə mənbəni görmək üçün `?includeSources=1`. |
| `PATCH`  | `/api/pricing`          | `{ provider: { model: { input, output, cached, … } } }` üçün qiymətləri əvəz edin.                                                 |
| `DELETE` | `/api/pricing`          | Qiymətləri standart dəyərlərə sıfırlayın (istəyə görə `?provider=&model=` ilə məhdudlaşdırıla bilər).                              |
| `GET`    | `/api/pricing/defaults` | Hər 1M üzrə standart ehtiyat tariflərini göstərin.                                                                                 |
| `GET`    | `/api/pricing/models`   | Model üzrə indekslənmiş qiymətlər.                                                                                                 |
| `POST`   | `/api/pricing/sync`     | Xarici mənbələrdən (LiteLLM) əl ilə sinxronlaşdırmanı başladın.                                                                    |
| `GET`    | `/api/pricing/sync`     | Cari sinxronlaşdırma statusu.                                                                                                      |
| `DELETE` | `/api/pricing/sync`     | Bütün sinxronlaşdırılmış qiymət məlumatlarını silin.                                                                               |

### Xərclərlə əlaqəli digər son nöqtələr

| Metod | Son nöqtə                     | Məqsəd                                                                       |
| ----- | ----------------------------- | ---------------------------------------------------------------------------- |
| `GET` | `/api/free-tier/summary`      | Pulsuz model tokenlərinin cəmi, bu ay istifadə edilən və qalan pulsuz limit. |
| `GET` | `/api/quota/pools/[id]/usage` | Ortaq kvota hovuzu üçün istifadə göstəriciləri.                              |

## CLI

OmniRoute-un CLI interfeysi xərc, istifadə və qiymətləndirmə əmrlərini təqdim edir (əmrlər
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs) faylında qeydiyyatdan keçirilib).

### `omniroute cost`

`/api/usage/analytics` əsasında aqreqasiya edilmiş xərc hesabatı.

```bash
omniroute cost                          # son 30 gün, provayder üzrə qruplaşdırılıb
omniroute cost --period 7d              # son 7 gün
omniroute cost --group-by model         # provider | model | combo | api-key | day üzrə qruplaşdır
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

Sütunlar: qrup, sorğular, daxil olan/çıxan tokenlər, xərc (USD) və ümumi məbləğin faizi. Sonda
ümumi yekun sətri göstərilir (`--quiet` və ya `--output json` ilə gizlədilir).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # hər provayder üzrə xərc xülasəsi
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# Büdcələr
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` əmri `GET /api/pricing/defaults` ünvanından məlumatları oxuyur. Bunun əvəzinə ayrı-ayrı modellərin
> qiymətlərini redaktə etmək üçün idarəetmə panelindəki **Qiymətləndirmə** səhifəsindən və ya `PATCH /api/pricing` sorğusundan istifadə edin.

---

## Problemlərin həlli

- **Bütün xərclər $0 / "Legacy / Free" kimi göstərilir.** İstifadə edilən modellər üçün qiymət qeydi yoxdur.
  Xarici sinxronizasiyanı aktivləşdirin (`PRICING_SYNC_ENABLED=true`) və `omniroute pricing sync` əmrini icra edin və ya
  Qiymətləndirmə səhifəsi / `PATCH /api/pricing` vasitəsilə qiymətləri əl ilə təyin edin.
- **Tarixi modelin qiyməti yanlışdır.** Qiyməti düzəldin (üzərinə yazmaqla və ya yenidən sinxronizasiya etməklə) — xərc
  hər analitika oxunuşunda token saylarından yenidən hesablanır, buna görə təxminlər geriyə dönük şəkildə yenilənir.
- **Xərc məlumatları real vaxtdan geri qalır.** Hər açar üzrə xərclər paketlərlə işlənir; daha aktual rəqəmlərə ehtiyacınız varsa,
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` dəyərini azaldın.
