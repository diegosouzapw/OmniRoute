# Stealth Vodič

> **Izvor istine:** `open-sse/utils/tlsClient.ts`, `open-sse/services/{tlsClientBase,claudeTlsClient,perplexityTlsClient,grokTlsClient,notionTlsClient,lmarenaTlsClient,claudeCodeCCH,claudeCodeFingerprint,claudeCodeObfuscation,claudeCodeCompatible}.ts`, `open-sse/config/cliFingerprints.ts`, `src/mitm/`
> **Zadnje ažurirano:** 2026-09-02 — v3.8.51
> **Ciljna grupa:** Inženjeri koji održavaju stealth integracije specifične za provajdere.

OmniRoute se integriše sa provajderima čiji edge serveri aktivno vrše fingerprinting ne-zvaničnih klijenata (TLS JA3/JA4, redoslijed zaglavlja, oblik JSON tijela, integrity tokeni). Ova stranica dokumentuje stealth površine koje OmniRoute izlaže i gdje su one implementirane.

## Pravna i etička napomena

Stealth funkcionalnosti postoje kako bi OmniRoute mogao djelovati kao sloj kompatibilnosti između zvaničnih računa u vlasništvu korisnika (Claude Code CLI, Codex, Antigravity, Cursor, itd.) i OmniRoute-ovog jedinstvenog API-ja. Oni **nisu** namijenjeni za izbjegavanje detekcije prevara, dijeljenje kredencijala ili kršenje Uslova korištenja (ToS) provajdera. Održavatelji očekuju da operateri poštuju upstream ToS koji su potpisali prilikom kreiranja računa.

## TLS Fingerprinting sloj

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

Persistentne `wreq-js` sesije kreiraju se lijeno (lazily) po opsegu računa i razriješenom proxy-ju. `TlsClient` na nivou procesa grupiše najviše 128 sesija koje imitiraju **Chrome 124 na macOS-u** za upstream-ove iza Cloudflare-a. `TlsClient.fetch()` završava neuspjehom (fails closed) kada nativni runtime nije dostupan; pozivač može eksplicitno odabrati fallback izvan ovog omotača.

- Profil sesije: `browser: "chrome_124", os: "macos"`
- Razrješavanje proxy-ja (prioritet): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (također i mala slova)
- Timeout: `TLS_CLIENT_TIMEOUT_MS` (nasljeđuje iz `FETCH_TIMEOUT_MS`, default 600000)
- `wreq-js` Response je kompatibilan sa fetch-om (`headers`, `text()`, `json()`, `clone()`, `body`).
- First-byte watchdog (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656): `TlsClient.fetch()`
  se razrješava čim stignu upstream zaglavlja, tako da `TLS_CLIENT_TIMEOUT_MS` sam po sebi ne može ograničiti
  tijelo koje nikada ne isporuči prvi bajt. `guardTlsFirstByte()` utrkuje prvo `read()` tijela
  protiv `TLS_FIRST_BYTE_WATCHDOG_MS` (default `10000`, `0` ga onemogućava); zdravo tijelo
  ostaje nedodirnuto, dok tijelo koje je zastalo otkazuje wreq reader i dopušta postojećoj
  TLS-fallback logici `proxyFetch`-a da pređe na direktni/proxy dispatcher (zahtjev koji nije
  siguran za ponovni pokušaj, npr. POST sa tijelom, i dalje baca grešku umjesto da bude tiho ponovljen).

### Web-cookie provider transport — wreq-js 3.2.0

`open-sse/services/tlsClientBase.ts` je zajednički adapter za pet specijalizovanih
web-cookie transporta navedenih u nastavku. Svaki tanki omotač provajdera bira browser/OS profil. Adapter
koristi jedinstveni wreq runtime loader i transport pool u `open-sse/utils/tlsClient.ts`, indeksiran po
profilu + OS + razriješenom proxy-ju, dok svaki zahtjev koristi `cookieMode: "ephemeral"`. Računi i
zahtjevi stoga dijele konekcije na nivou transporta, ali nikada wreq sesiju ili cookie jar.

| Provajder  | Profil        | Emulirani OS | Politika Stream EOF                  |
| ---------- | ------------- | ------------ | ------------------------------------ |
| Claude     | `chrome_146`  | Linux        | uključi `[DONE]`                     |
| Perplexity | `firefox_148` | macOS        | uključi `event: end_of_stream`       |
| Grok       | `chrome_146`  | Linux        | isključi `[DONE]`                    |
| Notion     | `chrome_146`  | Windows      | uključi `[DONE]`                     |
| LMArena    | `chrome_146`  | Windows      | nema sentinel; zatvori na native EOF |

- Streaming direktno troši nativni response `ReadableStream`; ne kreiraju se privremene datoteke niti sidecar-i.
- Do 256 početnih bajtova se pregleda prije izlaganja stream-a. SSE provajderi baferuju non-SSE
  greške; Grok/LMArena mapiraju Cloudflare izazove na `403` i HTML intersticijale na `502`.
- Nativni timeout zahtjeva ostaje omotan apsolutnim JS hard deadline-om. Zastoj (hang) poništava
  i zatvara samo pogođeni transport profila/OS-a/proxy-ja prije nego što ga sljedeći zahtjev ponovo kreira.
- Prioritet razrješavanja proxy-ja je po pozivu `proxyUrl` → kontekst računa/dashboard-a u opsegu zahtjeva →
  `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (uključujući varijante malim slovima). Greške u razrješavanju
  završavaju neuspjehom (fail closed) umjesto curenja direktne konekcije. LMArena namjerno razrješava protiv `arena.ai`.
- `byteResponse` vraća content-typed `data:` URL bez UTF-8 korupcije.
- Greške su `TlsClientUnavailableError` (paket/addon nedostupan), `TlsClientHangError`
  (deadline prekoračen) i `WreqTransportCapacityError` (zajednički kod greške kapaciteta sesije)
  kada su svih 128 ograničenih slotova profila/OS-a/proxy-ja aktivni ili u procesu zatvaranja.

Generička `TlsClient` sesija iznad ostaje specijalizovana za persistentno stanje kolačića zasnovano na browseru. Oba puta ponovo koriste jedan keširani wreq module loader i hook za životni ciklus procesa; njihovi pool-ovi ostaju odvojeni jer su im životni vijekovi kolačića namjerno različiti.

Profili su podržani od strane fiksiranog paketa, ali stvarno WAF prihvatanje se može promijeniti nezavisno
od lokalnih contract testova. Validirajte promjene fingerprinta protiv eksplicitno ovlaštenog aktivnog računa
prije nego što potvrdite paritet sa upstream browserom.

## Claude Code Stealth Bundle

Kada je `cliCompatMode` uključen, OmniRoute preoblikuje odlazne Claude zahtjeve tako da budu neprepoznatljivi od `claude-cli` saobraćaja. Sarađuju tri modula:

### `claudeCodeFingerprint.ts`

Izračunava 3-karakterni `cc_version` otisak (fingerprint) ugrađen u billing zaglavlje:

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (hardkodirano; odgovara zvaničnom klijentu)
- Ulazi: karakteri na indeksima 4, 7, 20 teksta prve korisničke poruke + string verzije
- Izlaz: 3-karakterni hex prefiks

### `claudeCodeCCH.ts` (Client Content Hash)

Provjera integriteta na strani servera koju zvanični Claude Code CLI izračunava putem Bun/Zig. OmniRoute to ponovo implementira pomoću `xxhash-wasm`:

1. Serijalizacija tijela sa `cch=00000;` placeholderom
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. Zero-padded 5-karakterni lowercase hex
4. Zamjena `cch=00000;` izračunatim tokenom

Konstante:

- Seed: `0x6e52736ac806831e`
- Pattern: `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

Umetne Unicode **zero-width joiner** (`U+200D`) nakon prvog karaktera "osjetljivih" imena klijenata kako upstream filteri ne bi mogli pronaći njihove nazive putem grep-a. Podrazumijevana lista riječi:

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

Primjenjuje se na: `system` blokove, sve `messages[].content`, te `tools[].description` / `tools[].function.description`. Operator može nadjačati ovo putem `setSensitiveWords()`.

### `claudeCodeCompatible.ts` — `anthropic-compatible-cc-*` provajderi

Za third-party Anthropic releje koji prihvataju samo "pravi Claude Code" saobraćaj:

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.258 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"` po defaultu
- Prekidač "Enable redact-thinking beta" po konekciji dodaje `redact-thinking-2026-02-12` kada CC Compatible upstream specifično zahtijeva redacted thinking stream-ove
- Prekidač "Enable summarized thinking display" po konekciji sprema `providerSpecificData.requestDefaults.summarizeThinking` i dodaje `display: "summarized"` u CC Compatible thinking zahtjeve koji već nisu postavili display mod
- `CONTEXT_1M_BETA_HEADER = "context-1m-2025-08-07"` (Opus/Sonnet 4.x porodica)
- Podrazumijevana putanja: `/v1/messages?beta=true`

Srodni moduli u istom bundle-u:

- `claudeCodeConstraints.ts` — pravila za temperature + cache-control
- `claudeCodeToolRemapper.ts` — remapiranje imena alata (tools)
- `claudeCodeExtraRemap.ts` — dodatna normalizacija payload-a

## Antigravity Stealth

Antigravity zahtjevi čuvaju tekst pozivaoca bajt-po-bajt. OmniRoute ne umetne zero-width karaktere u promptove niti preimenuje/ubacuje alate kako bi imitirao IDE klijenta.

### `antigravityHeaderScrub.ts`

Uklanja Stainless SDK markere (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`) prije prosleđivanja.

### ⚠️ Rizik: `ANTIGRAVITY_CREDITS=always` (kritična tačka za banovanje naloga)

`ANTIGRAVITY_CREDITS=always` (koristi `open-sse/executors/antigravity.ts`) rutira **svaki** zahtjev kroz Antigravity AI Credit Overages (plaćeni Google krediti) umjesto da dopusti Google-ovom free-tier kvoti da ograničava pristup. Ovo je dokumentovano kao funkcionalnost, ali je **najčešći prijavljeni prekršaj ToS-a koji viđamo** — više Google Ultra naloga je banovano sa `403 / "service disabled for ToS violation" / insufficient_quota` nakon nekoliko sati rada sa `=always`.

Upstream primjena je na **Google-ovoj strani**, ne postoji ništa što OmniRoute može spriječiti. Naziv env varijable i postojeća dokumentacija čine da zvuči kao siguran prekidač; nije.

**Zašto ovo agresivnije aktivira detekciju zloupotrebe nego samo free-tier upotreba:**

- Kontinuirani automatizovani trošak na jednom Google nalogu signalizira drugačije nego kada free-tier dostigne kvotu i stane.
- Credit overages nemaju limit brzine (rate ceiling), tako da pogrešno konfigurisan klijent može potrošiti nekoliko stotina USD u minutima i izgledati kao preprodaja API ključeva ili bot saobraćaj.
- Više OmniRoute korisnika koji paralelno koriste overage kredite sa iste eksterne IP adrese pojačava ovaj signal.

**Preporučeni pristup:**

1. Zadržite default `ANTIGRAVITY_CREDITS=off` osim ako operator eksplicitno ne prihvata rizik plaćenih kredita i sankcionisanja naloga. `retry` prvo šalje normalan zahtjev i ubacuje kredite najviše jednom nakon kvalifikovanog quota 429; `always` ubacuje kredite već pri prvom zahtjevu.
2. **Rasporedite opterećenje kroz provajdere putem Auto-Combo** (`model: "auto"` ili `kr/glm/etc`-combo) umjesto zasićenja jednog Antigravity naloga.
3. **Postavite RPM limite po konekciji** na stranici za uređivanje Antigravity provajdera (Dashboard → Providers → Antigravity → connection → rate limit). 30–60 RPM je odbranjiva gornja granica za kontinuiranu upotrebu.
4. **Koristite stabilno, operatorom kontrolisano upstream mrežanje** i izbjegavajte dijeljenje jednog naloga između nepovezanih korisnika ili radnih opterećenja.
5. **Ako ste banovani**: podnesite žalbu putem `support.google.com` → "Restore Workspace/Account access" sa tačnim `quota_exceeded` / `service disabled` response tijelom koje je Google poslao. Vraćanje pristupa nije zagarantovano.

Referenca za okruženje dokumentuje implikacije na nalog i troškove za svaki mod kredita.

Kontaktne tačke:

- `open-sse/executors/antigravity.ts` — čita `process.env.ANTIGRAVITY_CREDITS`
- `src/lib/oauth/providers/antigravity.ts` — plumbing za kredencijale
- Originalni izvještaj o incidentu: Diskusija [#1183](https://github.com/diegosouzapw/OmniRoute/discussions/1183)

## CLI Fingerprint Registry — `open-sse/config/cliFingerprints.ts`

Tabela po provajderu koja fiksira **tačan** redoslijed zaglavlja (headers) i redoslijed polja u JSON tijelu, zabilježenih putem mitmproxy tragova zvaničnih CLI alata. Trenutno registrovani: `codex`, `claude`, plus profili izvedeni u runtime-u u `providerHeaderProfiles.ts` za `antigravity` i `github`.

```ts
interface CliFingerprint {
  headerOrder: string[]; // osjetljivo na velika i mala slova
  bodyFieldOrder: string[]; // JSON ključevi na vrhunskom nivou
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

Uključite/isključite po provajderu putem env varijabli (vidi ispod). Kada je onemogućeno, zaglavlja/ključevi tijela se pojavljuju u redoslijedu koji su odredili Node/JSON — što ih čini lakim za fingerprinting.

## MITM Proxy (Antigravity, Linux/macOS/Windows)

Za CLI alate čiji binarni fajlovi ne mogu biti preusmjereni putem `OPENAI_BASE_URL`, OmniRoute pokreće lokalni TLS-terminirajući proxy. Endpointi se nalaze pod `src/app/api/cli-tools/antigravity-mitm/`.

| Metoda | Endpoint                                | Svrha                                              |
| ------ | --------------------------------------- | -------------------------------------------------- |
| GET    | `/api/cli-tools/antigravity-mitm`       | Status — pokrenuto, pid, dnsConfigured, certExists |
| POST   | `/api/cli-tools/antigravity-mitm`       | Pokreni MITM (zahtijeva `apiKey` + `sudoPassword`) |
| DELETE | `/api/cli-tools/antigravity-mitm`       | Zaustavi MITM                                      |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | Lista aliasa modela                                |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | Sačuvaj aliase modela za alat                      |

Ciljni presretnuti host: **`daily-cloudcode-pa.googleapis.com`** (Antigravity upstream).

### Sekvenca pokretanja (`src/mitm/manager.ts::startMitm`)

1. Generisanje samopotpisnog certifikata putem `selfsigned` (RSA-2048, SHA-256, 1g) — `cert/generate.ts`
2. Instalacija certifikata u sistemski trust store — `cert/install.ts`
3. Dodavanje hosts zapisa `127.0.0.1 daily-cloudcode-pa.googleapis.com` — `dns/dnsConfig.ts`
4. Pokretanje `src/mitm/server.cjs` sa `ROUTER_API_KEY` + `MITM_LOCAL_PORT` (podrazumijevano `443`)
5. Trajno čuvanje PID-a u `<DATA_DIR>/mitm/.mitm.pid`

### Linux dinamička detekcija trust-store-a — `cert/install.ts`

`getLinuxCertConfig()` prolazi kroz listu prioriteta i bira prvi postojeći direktorij:

| Porodica distro-a        | Direktorij                                  | Komanda za ažuriranje    |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

Naziv certifikata: `omniroute-mitm.crt`. Podudaranje fingerprinta putem `getCertFingerprint()` (SHA-1 od DER).

Dodatno, `updateNssDatabases()` instalira certifikate u NSS baze podataka po korisniku kada je `certutil` dostupan: `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, svi Firefox profili (uključujući snap), pod nadimkom **`OmniRoute MITM Root CA`**.

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** povišeni PowerShell → `certutil -addstore Root`

### Autentifikacija

Svi MITM endpointi zahtijevaju administratorsku autentifikaciju (`requireCliToolsAuth`). Sudo lozinka je keširana u opsegu modula (nikada u `globalThis`) i briše se prilikom poziva `stopMitm()`.

Koristi `open-sse/executors/base.ts::buildHeaders()` putem dinamičkog pretraživanja. **Ažurirajte ove vrijednosti kada provajderi objave nove CLI verzije** — zastarjeli UA stringovi počinju biti odbijeni kao zastarjeli klijenti.

## Sanitizacija Dolaznih Zaglavlja (Inbound Header Sanitization)

OmniRoute čisti dolazna zaglavlja klijenta prije prosljeđivanja, tako da zahtjev koji dolazi iz Cursora ne otkrije `User-Agent: Cursor/X.Y.Z` Claude upstream-u. Pogledajte `src/shared/constants/upstreamHeaders.ts` za denylist, koji se održava u skladu sa Zod shemama i unit testovima.

## Ažuriranje Fingerprint-ova Kada Provajder Rotira

1. Zapišite zvanični CLI saobraćaj pomoću `mitmproxy` (TLS presretanje + dump)
2. Ekstrahujte JA3/JA4 i literalni redoslijed zaglavlja
3. Ažurirajte relevantni `CLI_FINGERPRINTS[...]` unos
4. Ažurirajte odgovarajući `*_USER_AGENT` default u `.env.example`
5. Ako se sam TLS handshake promijeni, ažurirajte relevantni wrapper provajdera ili wreq-js `browser:` opciju
6. Pokrenite TLS testove specifične za provajdera i ručni canary test protiv aktivnog provajdera
7. Objavite u patch verziji; dokumentujte u `CHANGELOG.md`
