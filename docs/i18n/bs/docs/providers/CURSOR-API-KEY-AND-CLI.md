# Cursor API provajder i Cursor CLI passthrough

Dva načina da postavite Cursor iza OmniRoute bez IDE sesije:

1. **`cursor-api` provajder** (kartica "Cursor API", alias `cua`): API-key provajder koji čuva Cursor korisnički API ključ (`crsr_…`, generisan na `https://cursor.com/dashboard/api`). Bilo koji OmniRoute klijent tada pristupa Cursor modelima kroz `/v1/chat/completions` kao `cursor-api/<model>` ili `cua/<model>`, uz uobičajene slojeve kvota, rezervnih opcija (fallback) i logovanja. IDE provajder (`cursor`, OAuth/IDE sesija) ostaje nepromijenjen.
2. **Cursor CLI passthrough**: usmjerite Cursor CLI (`agent`) ka OmniRoute tako da svaki RPC koji CLI napravi bude autentifikovan pomoću OmniRoute API ključa, proslijeđen Cursor-u sa akreditivima `cursor-api` konekcije i zabilježen na stranici Logs.

## Zašto se ključ razmjenjuje

`api2.cursor.sh` odbija sirovi `crsr_…` ključ kao Bearer token (401). Cursor CLI prvo šalje (POST) ključ na `/auth/exchange_user_api_key` i prima sesijski JWT koji ističe nakon jednog sata; vraćeni `refreshToken` nosi isti `exp`, tako da osvježavanje znači ponovnu razmjenu ključa.
`open-sse/services/cursorApiKeyAuth.ts` vrši tu razmjenu, kešira jedan sesijski token po ključu, ponovo vrši razmjenu pet minuta prije isteka i odbacuje keširani token kada Cursor odgovori sa 401. `CursorExecutor` ga poziva neposredno prije otvaranja upstream strima za `cursor-api` konekcije.

## `cursor-api` provajder

Registar: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, isti `format`, `baseUrl` i `models` kao `cursor`). Kataloška kartica:
`src/shared/constants/providers/apikey/specialty-media.ts`. Mapa izvršilaca (Executor map):
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

Dashboard: Providers → Cursor API → Add API key.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

Zatim:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

Napomene:

- Lista modela za `cursor-api` dolazi iz statičkog Cursor registra (ista lista na koju se IDE provajder oslanja kao rezervnu opciju); instalacija `cursor-agent` nije potrebna na OmniRoute hostu.
- `POST /api/providers/{id}/refresh-cursor` je samo za `cursor` IDE provajder; `cursor-api` konekcije nemaju IDE sesiju za obnavljanje.

## Cursor CLI passthrough

Ruta: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. Prefiks `/api/cursor-cli/` je registrovan u `src/shared/constants/publicApiRoutes.ts` jer handler sprovodi sopstvenu autentifikaciju:

| Putanja                                                                                                                         | Očekivana autentifikacija od CLI-ja | Šta OmniRoute radi                                                                                                                                             |
| ------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                              | `Bearer <OmniRoute API key>`        | Validira ključ, kreira 1h HS256 JWT (potpisan sa `JWT_SECRET`) i vraća ga                                                                                      |
| svaka druga putanja (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <taj JWT>`                  | Verifikuje izdavaoca/publiku/istek, bira aktivnu `cursor-api` konekciju, mijenja Authorization zaglavlje za razmijenjeni Cursor token i strimuje odgovor nazad |

CLI dekodira `exp` iz bilo kog tokena koji primi, pa mu davanje neprozirnog (opaque) tokena uzrokuje ponovnu razmjenu prije skoro svakog zahtjeva; kreirani JWT to izbjegava. 401 od OmniRoute-a uzrokuje da CLI ponovo izvrši razmjenu.

### Podešavanje

1. Kreirajte OmniRoute API ključ (Dashboard → API keys) i `cursor-api` konekciju.
2. Recite CLI-ju da koristi HTTP/1.1 za agent strim. U
   `~/.cursor/cli-config.json`:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   Bez ovoga, CLI otvara agent turn preko HTTP/2 ka zasebno konfigurisanom agent hostu i samo control-plane RPC-ovi prolaze kroz endpoint.

3. Pokrenite CLI protiv OmniRoute-a:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

Svaki hop završava u Logs kao provajder `cursor-api`, tip zahtjeva `cursor-cli`,
putanja `/api/cursor-cli/<rpc>`, pripisan OmniRoute API ključu i konekciji koja ga je opslužila.

### Scenariji grešaka

| Situacija                                         | Odgovor CLI-ju                                  |
| ------------------------------------------------- | ----------------------------------------------- |
| Nepoznat OmniRoute ključ i `REQUIRE_API_KEY=true` | 401 `unauthenticated` pri razmjeni              |
| `REQUIRE_API_KEY=false`                           | anonimna sesija (preslikava ponašanje `/v1/*`)  |
| Istekao / strani / izmijenjen sesijski JWT        | 401, CLI ponovo vrši razmjenu                   |
| OmniRoute API ključ opozvan nakon razmjene        | 401 pri sljedećem RPC-u                         |
| Nema aktivne `cursor-api` konekcije               | 503 `unavailable`                               |
| Cursor odbija ključ konekcije                     | 401 `unauthenticated`, keširana sesija odbačena |
| Upstream nedostupan                               | 502 `unavailable` (sanitizirana poruka)         |
| `JWT_SECRET` nije postavljen                      | 503 pri razmjeni                                |
