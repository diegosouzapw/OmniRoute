# Provajderi — ChatGPT Web (Codex)

`chatgpt-web-codex` (alias `cgpt-codex`) premošćuje Codex Responses turnove kroz autentifikovanu ChatGPT sesiju pretraživača. Nezavisan je od povučenog uobičajenog `chatgpt-web` provajdera i koristi implementaciju sa MIT licencom pod `open-sse/vendor/codex-chatgpt-web/`, osvježenu kroz upstream v4.0.7 commit `b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494`.

## Povlačenje uobičajenog provajdera

Bivši uobičajeni ID-ovi provajdera `chatgpt-web` i `cgpt-web` se više ne isporučuju jer se porijeklo njihove pre-key/proof-of-work implementacije nije moglo utvrditi. Eksplicitni zahtjevi prema bilo kojem ID-u, uključujući ID-ove modela sa prefiksom kose crte i sačuvane aliase, se odbijaju sa HTTP `410` i kodom **PROVIDER_RETIRED** prije bilo kakvog upstream zahtjeva.

Migracija `168_retire_chatgpt_web.sql` označava odgovarajuće konekcije provajdera kao nevažeće (tombstones) i poništava njihove aktivne zakupe sesija. Ona čuva historiju konekcija i liste dozvoljenih API ključeva; ne dodaje zamjenski pristup na listu dozvoljenih. Codex provajder i njegove konekcije nisu obuhvaćeni ovim povlačenjem.

## Preduslovi

- puni Cookie zaglavlje iz prijavljene ChatGPT sesije;
- Chrome ili Chromium plus grafička sesija ili Xvfb prikaz za npm, systemd i PM2 instalacije;
- sa Docker `web` profilom, interni Chromium servis iz `docker-compose.yml`;
- OpenAI `tunnel-client` v0.0.13 i ChatGPT prilagođeni konektor za lokalne Codex alate.

Tunel je potreban samo za turnove alata. Svaka navedena ruta, uključujući `pro`, može koristiti istu lokalnu mogućnost alata vezanu za turn kada su tunel i konektor konfigurisani.

## Podešavanje kontrolne table

1. Otvorite **ChatGPT Web (Codex)** provajder i dodajte konekciju.
2. Zalijepite puno ChatGPT Cookie zaglavlje, ID tunela, runtime ključ i naziv prilagođenog konektora. Nove postavke sa mogućnošću alata moraju koristiti novo kreirani konektor nazvan tačno `OmniRoute Codex v2`, sa Authentication postavljenim na None i Permissions postavljenim na Allow all actions.
3. Pokrenite provjeru konekcije. OmniRoute otvara Temporary Chat podržan pretraživačem i detektuje da li su Sol i Pro dostupni za nalog.
4. Sačuvajte konekciju. OmniRoute zamjenjuje zalijepljeni cookie sa verifikovanim Playwright stanjem skladišta i pohranjuje ga sa runtime ključem kroz apstrakciju šifrovanih akreditiva.

Sirovi cookie se ne zadržava nakon uspješnog čuvanja. Kada sesija istekne, otvorite konekciju, zalijepite svježe puno Cookie zaglavlje i ponovo pokrenite provjeru. Status doktora u dijalogu za uređivanje izvještava o pretraživaču, stanju skladišta, prijavi, Temporary Chat-u, tunelu, konektoru i povratnom putu alata zasebno.

> Nikada ne commit-ujte pravi cookie, runtime ključ, stanje skladišta ili token mogućnosti. Testne i dokumentacione vrijednosti moraju uvijek biti placeholderi.

## Modeli i kombinacije

Fiksne rute modela su:

- `chatgpt-web-codex/luna` — GPT-5.6 Luna, nizak napor
- `chatgpt-web-codex/think` — GPT-5.6 Luna, srednji napor
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

Dodajte jedan od njih u kombinaciju kao bilo koji drugi model. Codex aplikacija šalje naziv kombinacije kao `model` na regularni Responses endpoint, `/v1/responses`; ne postoji poseban Codex endpoint ili prekidač režima.

Free/Go nalozi izlažu Luna rute. Nalozi sa Sol mogućnostima izlažu Instant do High, a Pro nalozi dodatno izlažu Extra High i Pro. Svaka ruta ima fiksni backend model i napor zaključivanja; konfliktni eksplicitni Responses napor se odbija umjesto da tiho mijenja odabrani režim pretraživača.

Nemojte preimenovati ili ponovo koristiti stariji `Codex Native` ili `OmniRoute Codex` konektor. ChatGPT kešira javni MCP ugovor prema identitetu konektora, dok osvježeni most koristi novi direktni ugovor o turn-tokenu. Runtime odbacuje te naslijeđene identitete i zahtijeva novi `OmniRoute Codex v2` konektor.

## Sigurnosni model

- Izvorna putanja zahtijeva Responses zahtjev, prepoznatog Codex klijenta, te podudarajuće identitete niti i poteza.
- Radni prostor (workspace), sandbox, politika odobravanja i katalog alata dolaze iz izvorne Codex ljuske; slobodno oblikovani tekst upita nije autoritet za njih.
- ChatGPT prima samo kratkotrajnu mogućnost po potezu. MCP posrednik prihvaća samo alate koje je Codex ponudio u tom točnom potezu.
- Automatska potvrda **Allow once** samo vraća zahtjev za alatom natrag Codexu. Samo Codex odlučuje o odobrenju i izvršenju.
- Prije prvog izlaza, kombinacija se može vratiti na drugu kompatibilnu metu. Nakon što izlaz započne, pružatelj, model, veza i potez preglednika ostaju fiksirani dok se potez ne završi.
- Kolačići, runtime ključevi, stanje pohrane i tokeni mogućnosti ne pojavljuju se u odgovorima pružatelja ili zapisnicima zahtjeva.

## VPS bez zaslona i Docker

Za instalacije npm, systemd i PM2, OmniRoute detektira uobičajene putanje za Chrome i Chromium.
Alternativno, postavite `CHATGPT_WEB_CODEX_CHROME_PATH`. Runtime potezi namjerno koriste Chrome s grafičkim sučeljem (headed) jer ChatGPT odbija oblik preglednika bez grafičkog sučelja (true-headless). Host bez zaslona stoga mora pokrenuti OmniRoute s privatnim Xvfb zaslonom; samo postavljanje putanje Chromea to ne osigurava.

Docker `web` profil pokreće `chatgpt-web-codex-browser` na internoj Compose mreži. Sidecar pokreće Chrome s grafičkim sučeljem unutar Xvfb-a, tako da fizički zaslon nije potreban. Njegov CDP port nije objavljen na hostu. Volumen zaštićenog profila preglednika odvojen je od volumena podataka OmniRoute-a, a preglednik prima dovoljno dijeljene memorije. Interni CDP proxy sluša samo na portu `9223` unutar Compose mreže; Chrome ostaje vezan za loopback u sidecaru.

Zakup nadzornika pod `DATA_DIR` sprječava da više OmniRoute procesa posjeduje isti tunel i stanje posrednika. Sukob prijavljuje doctor.

## Interaktivni oporavak

Automatizirana Docker putanja nema prozor vidljiv hostu, ali sam Chrome radi s grafičkim sučeljem unutar privatnog Xvfb zaslona. Kada ChatGPT zahtijeva interaktivnu prijavu ili izazov, postojeća VNC infrastruktura preglednika može se koristiti za oporavak. Korisničko sučelje preglednika i CDP moraju ostati dostupni samo putem loopback-a, autentificirane upravljačke veze ili SSH tunela; noVNC ostaje onemogućen tijekom normalnog rada.

## WebSocket povratna opcija (fallback)

Kada kombinacija sadrži ChatGPT Web (Codex), Responses WebSocket most zahtijeva HTTP/SSE povratnu opciju (fallback) prije povezivanja uzvodno. Prijenos se tada odvija kroz `/v1/responses`.
