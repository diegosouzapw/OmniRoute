# Provajderi — Microsoft 365 Copilot (BizChat)

`copilot-m365-web` (alias `m365copilot`) šalje zahtjeve za ćaskanje u OpenAI formatu kroz autentifikovanu Microsoft 365 Copilot BizChat sesiju pretraživača na `m365.cloud.microsoft/chat`. Ovo je nezvanična integracija.

> **Novi ste u radu sa Web Cookie provajderima?**
>
> Pročitajte **`docs/getting-started/WEB-COOKIE-GUIDE.md`** za opšti proces podešavanja, smjernice za autentifikaciju, ograničenja i rješavanje problema prije nego što pratite ovaj vodič specifičan za provajdera.
>
> **Važno:** Akreditiv za ovog provajdera **nije kolačić (cookie)**. Nemojte kopirati kolačiće sa `m365.cloud.microsoft`. Akreditiv je parametar upita WebSocket URL-a i segment putanje, oba pročitana sa kartice DevTools Network.

## Preduslovi

- Microsoft 365 nalog sa pristupom BizChat-u na `m365.cloud.microsoft/chat`
- Pretraživač zasnovan na Chromium-u (Chrome, Edge) za inspekciju WebSocket-a putem DevTools-a
- M365 Copilot licenca (uključena u mnoge Microsoft 365 Business/Enterprise planove)

## Hvatanje akreditiva (WebSocket metod)

1. Prijavite se na `https://m365.cloud.microsoft/chat` i započnite razgovor.
2. Otvorite **DevTools → Network**.
3. Filtrirajte po **WS** (WebSocket).
4. Kliknite na Chathub WebSocket konekciju. Potražite URL koji počinje sa `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Iz njegovog **Request URL**-a, kopirajte:
   - Vrijednost parametra upita `access_token` (kratkotrajni JWT).
   - Segment putanje Chathub-a nakon `/Chathub/` (npr. `<oid>@<tenant>`).

Puni URL ima oblik:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. U OmniRoute-u, idite na **Providers → Add Provider**, izaberite **Microsoft 365 Copilot (BizChat)** i nalijepite akreditiv u formatu:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Kliknite na **Test Connection** i **Save**.

## Hvatanje akreditiva (HAR uvoz)

Umjesto ručnog kopiranja vrijednosti iz WebSocket URL-a, možete izvesti DevTools HAR datoteku:

1. Otvorite **DevTools → Network**.
2. Započnite ili nastavite BizChat razgovor (ovo pokreće WebSocket konekciju).
3. Kliknite desnim tasterom miša na Network panel i izaberite **Save all as HAR with content**.
4. U OmniRoute-u koristite dugme **Import .har file** u dijalogu za povezivanje provajdera.

OmniRoute skenira HAR u potrazi za Chathub WebSocket URL-om, ekstrahuje `access_token` i `chathubPath`, i automatski popunjava polja za akreditive. HAR uvoz dekodira JWT isteka i prikazuje preostalo vrijeme trajanja tokena.

> **Nikada ne commit-ujte pravi HAR izvoz, pristupni token ili token za osvježavanje.** Testne i dokumentacione vrijednosti moraju uvijek biti placeholderi.

## Životni vijek tokena i osvježavanje

`access_token` je kratkog vijeka (obično **~75 minuta**). Nakon isteka, provajder prijavljuje grešku u konekciji i morate ponovo uhvatiti akreditiv.

### Automatsko osvježavanje sa `refreshToken`

Da biste izbjegli ručno ponovno hvatanje, možete pohraniti Microsoft token za osvježavanje u **Advanced Settings → providerSpecificData** konekcije:

| Polje          | Opis                                                                         |
| -------------- | ---------------------------------------------------------------------------- |
| `refreshToken` | Microsoft OAuth token za osvježavanje za `substrate.office.com/sydney` opseg |
| `tier`         | `individual` (podrazumijevano), `edu`, ili `enterprise`                      |

Dobavite token za osvježavanje iz Microsoft device-code ili authorization-code toka sa opsegom `substrate.office.com/sydney`. Sa postavljenim `refreshToken`-om, OmniRoute vrši pre-flight osvježavanje `access_token`-a prije svakog zahtjeva, tako da ne morate ponovo hvatati akreditiv nakon svakog isteka od ~75 minuta.

Ako `refreshToken` nije postavljen, morate ručno ponovo uhvatiti WebSocket akreditiv nakon svakog isteka.

### Izbor nivoa (Tier)

| Nivo (Tier)  | Alias               | Površina (Surface)     |
| ------------ | ------------------- | ---------------------- |
| `individual` | _(podrazumijevano)_ | Consumer M365 Copilot  |
| `edu`        | `included`          | Education M365 Copilot |
| `enterprise` | `work`              | M365 Copilot for Work  |

Postavite nivo u **Advanced Settings → providerSpecificData → tier**. Nivo utiče na BizChat rutiranje i pristup modelu.

## Sigurnosni model

- **Nezvanična integracija.** Ovaj provajder vrši reverzni inženjering BizChat WebSocket protokola. Može prestati raditi bez najave kada Microsoft promijeni krajnju tačku (endpoint).
- Zastavica `subscriptionRisk: true` odražava činjenicu da se integracija oslanja na nedokumentovanu krajnju tačku. Ograničenja naloga su moguća, ali nisu potvrđena.
- Pristupni token je kratkotrajni JWT. Tretirajte ga kao lozinku: nemojte ga commit-ovati, logovati niti dijeliti.
- Token za osvježavanje (refresh token) omogućava dugoročni pristup BizChat interfejsu. Čuvajte ga sa istom pažnjom kao i API ključ.

## Rješavanje problema

### Autentifikacija odmah ne uspijeva

- Provjerite da li ste kopirali iz **WebSocket URL-a**, a ne iz XHR/Fetch zahtjeva. Akreditiv se nalazi u `access_token` parametru upita Chathub WebSocket konekcije — a ne u `Authorization: Bearer` zaglavlju.
- Osigurajte da `chathubPath` uključuje puni `<oid>@<tenant>` segment iz putanje URL-a.

### Token ističe nakon ~75 minuta

Ovo je očekivano. Bez `refreshToken`-a, pristupni token je kratkotrajan. Ili:

- Ponovo uhvatite akreditiv iz DevTools-a, ili
- Konfigurišite `refreshToken` u Naprednim postavkama (Advanced Settings) za automatsko osvježavanje.

### Test Connection prolazi, ali chat vraća 401

Token je možda istekao između validacije i prvog zahtjeva. Ponovo uhvatite svjež akreditiv.

### Copilot se ne pojavljuje na listi provajdera

Osigurajte da je `copilot-m365-web` omogućen u **Dashboard → Providers**. Provajder može biti sakriven po defaultu u nekim nivoima (tiers).
