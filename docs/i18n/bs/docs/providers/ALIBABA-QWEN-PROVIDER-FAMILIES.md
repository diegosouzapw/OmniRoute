# Alibaba i Qwen porodice provajdera

Ovaj dokument bilježi odluku o implementaciji za [Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854). Javni proizvodi su predstavljeni kao četiri porodice provajdera. Regija je podatak o konekciji, a ne poseban proizvod.

## Odluka

| Porodica provajdera                                 | OmniRoute ID            | Globalna regija | Kineska regija |
| --------------------------------------------------- | ----------------------- | --------------- | -------------- |
| Alibaba Cloud Model Studio (plaćanje po korištenju) | `alibaba`               | Singapur        | Peking         |
| Alibaba Cloud Token Plan                            | `bailian-coding-plan`   | Singapur        | Peking         |
| Qwen Cloud (plaćanje po korištenju)                 | `qwen-cloud`            | Globalno        | Peking         |
| Qwen Cloud Token Plan                               | `qwen-cloud-token-plan` | Singapur        | Peking         |

Postojeći `alibaba-cn` ID ostaje alias za kompatibilnost tokom izvršavanja za sačuvane konekcije, rute modela, kombinacije i historijsku upotrebu. Njegova kartica na kontrolnoj tabli je spojena u `alibaba`; nije potrebno prepisivanje baze podataka.

Qwen Cloud (plaćanje po korištenju) i Alibaba Cloud Model Studio trenutno dijele DashScope-kompatibilne runtime hostove, ali ostaju odvojeni identiteti provajdera jer korisnici dobijaju ključeve i upravljaju nalozima putem različitih sučelja proizvoda. Proizvodi Alibaba i Qwen Cloud Token Plan koriste različite porodice krajnjih tačaka (endpoint), tako da sva četiri proizvoda ostaju odvojeni ID-ovi provajdera.

## Matrica krajnjih tačaka

| Porodica provajdera     | `global-sg`                                                              | `china-beijing`                                                      | Format prenosa |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | -------------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI         |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic      |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI         |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI         |

API ključ i krajnja tačka moraju pripadati istom proizvodu i regiji. Odabir regije mijenja unaprijed postavljenu krajnju tačku koja se koristi za validaciju i normalne zahtjeve.

## Ugovor o konekciji

Nove konekcije pohranjuju ključ stabilne regije u `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

Dozvoljene vrijednosti su `global-sg` i `china-beijing`. Krajnja tačka se izvodi centralno iz ID-a provajdera i regije. `providerSpecificData.baseUrl` koji nije unaprijed postavljen ostaje eksplicitno nadjačavanje operatera i ima prioritet, dok se stari sačuvani unaprijed postavljeni URL-ovi normalizuju nazad u regionalnu matricu.

Ovo održava šemu konekcije proširivom: druga regija se može dodati u resolver bez kreiranja druge kartice provajdera ili promjene sačuvanih ID-ova provajdera.

## Kompatibilnost i uvođenje

1. Dodajte regionalni razrješivač krajnjih tačaka (endpoint resolver) i zadržite trenutne globalne zadane postavke.
2. Koristite otkrivanje putem regionalnog DashScope `/models` u realnom vremenu za `alibaba`, njegov `alibaba-cn` ID kompatibilnosti i `qwen-cloud`. Njihovi odgovori prvo prolaze kroz jedan filter za generisanje teksta jer generička krajnja tačka (endpoint) također vraća modele za slike, video, audio, ugradnju (embedding) i druge modele koji nisu za ćaskanje. `qwen-cloud` zatim primjenjuje održavanu listu dozvoljenih (allowlist) deklarisanu u svom registru provajdera. Alibaba Model Studio i Qwen Cloud zadržavaju odvojene kurirane kataloge iako trenutno dijele runtime hostove.
3. Registrujte `qwen-cloud-token-plan` sa trenutnom listom dozvoljenih (allowlist) tekstualnih modela Token Plana.
4. Dodajte tipizirani birač regiona u dijaloge za dodavanje/uređivanje konekcija.
5. Sakrijte duplikat kartice `alibaba-cn` i uključite njene postojeće konekcije na stranici provajdera `alibaba`.
6. Zadržite dostupnim prilagođene nadjačavanja krajnjih tačaka (endpoint overrides) za napredna i radna okruženja specifična za workspace.

Medijski modeli Token Plana ostaju izvan kataloga za ćaskanje jer koriste namjenske krajnje tačke (endpoints). `wan2.7-image` i `wan2.7-image-pro` su registrovani u `open-sse/config/imageRegistry.ts`; `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` i `happyhorse-1.1-r2v` su registrovani u `open-sse/config/videoRegistry.ts`. Oba registra ponovo koriste identitet konekcije `qwen-cloud-token-plan` i njene akreditive specifične za region.

Regularni Qwen Cloud ima odvojene kataloge za slike i video po principu plaćanja po upotrebi (pay-as-you-go) pod identitetom `qwen-cloud`. Njegovi modeli za slike su `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` i `z-image-turbo`. Njegovi video modeli su `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` i `wan2.7-videoedit`. Ovi modeli ponovo koriste samo regularnu `qwen-cloud` konekciju i regionalnu DashScope medijsku krajnju tačku (endpoint). Registri Token Plana i plaćanja po upotrebi ne nasljeđuju niti spajaju liste modela jedni drugih.

Identitet `bailian-coding-plan` također ima svoje liste dozvoljenih (allowlists) za medije: `wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` i `qwen-image-2.0-pro` za generisanje slika, plus `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` i `happyhorse-1.1-r2v` za generisanje videa. On koristi samo konekciju Bailian Coding Plan i regionalnu krajnju tačku (endpoint) Coding Plana. Njegovi registri slika i videa ne nasljeđuju niti se spajaju sa bilo kojim Qwen Cloud provajderom.

Regularni `alibaba` identitet ima odvojene liste dozvoljenih (allowlists) za slike i video. Njegovi modeli za slike su `qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`, `z-image-turbo` i `wan2.6-t2i`. Njegovi dodati video modeli su `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`, `wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`, `wan2.7-r2v-2026-06-12` i `wan2.7-videoedit`. Ovi modeli koriste samo konekciju Alibaba Model Studio i njenu odabranu regionalnu medijsku krajnju tačku (endpoint); oni se ne dodaju ni u jedan registar Coding Plana ili Qwen Clouda.

Katalog za ćaskanje Qwen Cloud Token Plana prati listu dozvoljenih (allowlist) tekstualnih nizova Individualnog plana: `qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` i `deepseek-v4-pro`. Wan i HappyHorse unosi pripadaju odvojenim API-jima za generisanje slika/videa.

Alibaba Token Plan izlaže istih šest trenutnih ID-ova modela za generisanje teksta putem svoje krajnje tačke (endpoint) kompatibilne sa Anthropicom. Njegova opcija za Singapur pohranjuje postojeći `global-sg` regionalni ključ; samo se oznaka okrenuta korisniku razlikuje od porodica provajdera koje taj region nazivaju Global.

Regularni Qwen Cloud katalog za ćaskanje je namjerno uži od punog odgovora teksta u realnom vremenu. Njegova održavana lista dozvoljenih (allowlist) nalazi se u `open-sse/config/providers/registry/qwen-cloud/index.ts`; otkrivanje u realnom vremenu vraća samo ID-ove koji su prisutni i u uzvodnom (upstream) odgovoru i u toj listi registra.

Alibaba Model Studio prati isto pravilo presjeka u realnom vremenu sa svojom nezavisno održavanom listom dozvoljenih (allowlist) u `open-sse/config/providers/registry/alibaba/index.ts`. Provajder kompatibilnosti `alibaba-cn` ponovo koristi taj katalog dok razrješava otkrivanje u odnosu na pekinšku krajnju tačku (endpoint).
