# Rješavanje problema sa relejima

Releji (Vercel, Deno, Cloudflare) prekidaju uzvodnu konekciju na serverless backendu tako da OmniRoute može ostvariti izlazni saobraćaj (egress) iz stabilnog regiona, dok se API ključ provajdera čuva na strani servera. Ovaj dokument pokriva dva režima greške na koje operateri nailaze u produkciji i puteve oporavka koje OmniRoute nudi za svaki od njih.

## Kako se pohranjuje auth releja

Kada rasporedite (deploy) relej iz **Settings → Proxy Pool → Deploy Relay**, proces raspoređivanja pohranjuje auth token releja u JSON polje `notes` proxy-ja:

- Ako je `STORAGE_ENCRYPTION_KEY` postavljen, token se zapisuje kao `relayAuthEnc` (AES-enkriptovan u stanju mirovanja).
- U suprotnom, zapisuje se kao plaintext `relayAuth`.

U trenutku zahtjeva, `extractRelayAuth(notes)` vraća onaj oblik koji je prisutan, tako da relej nastavlja raditi i nakon ponovnog pokretanja.

## Režim greške 1 — token koji se ne može dekriptovati nakon rotacije ključa

**Simptom:** releji koji su prethodno radili sada vraćaju uzvodne `401`/auth greške nakon rotacije `STORAGE_ENCRYPTION_KEY` u okruženju ili secret-manageru. Pohranjeni `relayAuthEnc` blob se više ne može dekriptovati, pa `extractRelayAuth` vraća prazan string i relej ne šalje nikakvu autentifikaciju.

**Oporavak — popravka na licu mjesta (bez ponovnog raspoređivanja):**

1. Otvorite **Settings → Proxy Pool**.
2. Redovi releja kojima nedostaje autentifikacija prikazuju žutu oznaku `auth missing` i dugme **Repair**.
3. Kliknite na **Repair**. OmniRoute poziva `POST /api/settings/proxies/[id]/repair-relay`, koji:
   - dekriptuje `relayAuthEnc` sa **trenutnim** ključem,
   - zapisuje plaintext `relayAuth` nazad u `notes`,
   - vraća `{ repaired: true, mode: "recovered" }`.

Relej nastavlja sa radom bez ponovnog unosa vjerodajnica za raspoređivanje.

Ovo radi samo ako trenutni `STORAGE_ENCRYPTION_KEY` još uvijek može dekriptovati blob. Ako ste rotirali ključ **bez** migracije, blob je nepopravljiv.

## Režim greške 2 — nepopravljiv token (ključ rotiran)

**Simptom:** kliknuli ste **Repair** i dobili `{ repaired: false, mode: "redeploy", status: 409 }`.

**Oporavak — ponovno raspoređivanje (redeploy):**

Pohranjeni token se ne može oporaviti sa trenutnim ključem. Ponovo rasporedite (re-deploy) relej iz istog modala koji ste prvobitno koristili (meni **Deploy Relay** → Vercel / Deno / Cloudflare). Proces raspoređivanja zapisuje novi token (enkriptovan trenutnim ključem) i oznaka `auth missing` u redu nestaje.

U korisničkom interfejsu, samo dugme **Repair** pokreće modal za ponovno raspoređivanje kada je token nepopravljiv, tako da ga nikada ne morate ručno tražiti.

## Režim greške 3 — relej dostupan, ali neispravan

**Simptom:** test proxy-ja (dugme `speed`) pokazuje da je relej aktivan, ali zahtjevi i dalje povremeno ne uspijevaju.

Provjerite zaglavlja za prepoznavanje releja (relay awareness headers) koja vraća OmniRoute auto-test sonda (pogledajte **Settings → Proxy Pool** i brojače `relayTested` / `relayAlive`):

- `x-relay-url` — koji relej backend je odgovorio.
- `x-relay-mode` — `ts` | `bifrost` | `auto` za taj zahtjev.
- `x-relay-attempts` — koliko pokušaja releja je napravljeno prije uspjeha.
- `x-relay-fallback` — `true` kada je zahtjev prešao sa preferiranog backenda na TypeScript relej.

Visoka stopa `x-relay-fallback` uz nizak `relayAlive` znači da je sidecar backend neispravan i trebali biste ga ili popraviti ili promijeniti strategiju backend-a releja na `ts` (pogledajte `RELAY_BACKEND_STRATEGY.md`).

## API referenca

| Metoda | Putanja                                   | Tijelo (Body)           | Uspjeh                                                                                                                                      | Greška                                                                                |
| ------ | ----------------------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `POST` | `/api/settings/proxies/[id]/repair-relay` | `{ "id": "<proxyId>" }` | `200 { repaired: true, mode: "recovered" }` kada je ponovo izvedeno; `200 { repaired: false, mode: "noop" }` kada je plaintext već prisutan | `409 { mode: "redeploy" }` nepopravljivo; `400` nije tip releja; `404` nije pronađeno |

Ruta za listanje `GET /api/settings/proxies` dodaje `relayInfo: { isRelay, authMissing, repairMode }` bez tajni svakoj stavci tako da kontrolna tabla može prikazati mogućnost popravke bez ikakvog izlaganja tokena.
