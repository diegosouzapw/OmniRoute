# Provajderi uklonjeni na zahtjev njihovog operatera

Neke usluge su bile integrisane u OmniRoute i kasnije uklonjene jer su ljudi koji njima upravljaju to tražili. Ova stranica je trajni zapis o tim uklanjanjima. Njena jedina svrha je da spriječi njihovo slučajno vraćanje: saradnik koji pronađe stari fork, keširani npm tarball, arhivirani issue ili zahtjev za "vraćanje provajdera X" treba jedno mjesto koje kaže **ne ponovo uvoditi**.

Ova stranica **nije** lista mrtvih ili ukinutih usluga. One se prate u [`FREE_TIERS.md`](FREE_TIERS.md) ("Uklonjeno / nema besplatnog nivoa") i mogu se vratiti ako se usluga vrati. Unosi ispod se mogu vratiti samo uz pismenu dozvolu operatera navedenog u zahtjevu, a ta dozvola mora biti povezana iz unosa.

## Politika

1. **Zahtjev za uklanjanje od strane operatera usluge se poštuje, o njemu se ne pregovara.** OmniRoute nije povezan ni sa jednom upstream uslugom. Kada operater usluge zatraži da se integracija ukloni, ona se uklanja, bez obzira da li je integracija koristila zvanični API ili ne.
2. **"Uklonjeno" znači svaka površina koju OmniRoute kontroliše.** Executor, unos u registru, id i alias provajdera, lista modela, krajnje tačke (endpoints), varijable okruženja, ikona, kartice na kontrolnoj tabli, generisana referenca provajdera, `FREE_TIERS.md`, referenca okruženja, README brojači, `llm.txt` ogledala, namjenski testovi i golden snapshots, komentari u kodu, CHANGELOG stavke (sa evidentiranim usklađivanjem, pogledajte `config/release/changelog-reconciliations.json`), GitHub Releases bilješke, wiki, te GitHub issues, diskusije i pull zahtjevi čija je tema bio taj provajder (issues i diskusije obrisani; pull zahtjevi preimenovani, njihov opis zamijenjen i nit zaključana, jer GitHub ne može brisati pull zahtjeve).
3. **Nikada ne vraćajte unos sa ove stranice bez pismene dozvole.** To uključuje vraćanje id-a ili aliasa u bilo koji katalog provajdera, dodavanje domena u executor, prihvatanje PR-a saradnika koji ga "vraća", dodavanje u katalog besplatnih modela, ili dokumentovanje ručnog načina za pristup putem OmniRoute-a. Zatvorite takve PR-ove i issues sa linkom ka ovoj stranici.
4. **Održavajte unos minimalnim.** Zabilježite samo ono što je recenzentu potrebno da prepozna ponovno uvođenje: identifikatore, domene, datume i pull zahtjev koji je izvršio uklanjanje. Ne opisujte kako je integracija radila.
5. **Zaštita od regresije je `tests/unit/removed-providers-blocklist.test.ts`.** Ona pada kada se bilo koji identifikator ili domen ispod ponovo pojavi u katalozima provajdera, mapi executora ili izvorima registra provajdera. Dodajte nove identifikatore u taj test u istom PR-u koji dodaje red ovdje.

## Dodavanje unosa

Kada stigne novi zahtjev za uklanjanje:

1. Potvrdite da zahtjev dolazi od operatera usluge (njihova adresa za podršku ili domen koji kontrolišu), i čuvajte poruku privatno.
2. Uklonite integraciju prateći kontrolnu listu u tački 2 politike. Koristite [#12440](https://github.com/diegosouzapw/OmniRoute/pull/12440) kao referencu za provajdera bez ključa i [#10210](https://github.com/diegosouzapw/OmniRoute/pull/10210) za provajdera sa API ključem sa sačuvanim konekcijama (dodajte migraciju).
3. Dodajte jedan red u tabelu iznad i identifikatore u `tests/unit/removed-providers-blocklist.test.ts`, u istom PR-u.
4. Odgovorite operateru kada PR bude spojen (merged), navodeći šta je uklonjeno i šta OmniRoute ne može promijeniti (već objavljene npm i Docker verzije, git istorija, fork-ovi trećih strana).
