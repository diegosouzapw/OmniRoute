# Format pravila kompresije

Pravila kompresije su JSON datoteke koje se učitavaju tokom izvršavanja (runtime). Namjerno su dizajnirana samo kao podaci kako bi se novi jezički paketi i filteri RTK komandi mogli pregledati bez izmjene koda engine-a.

> **Kanonicka šema (izvor istine):** [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) (JSON Schema draft 2020-12).
> Primjeri ispod su ilustrativni — ako ste u nedoumici, validirajte svoj paket prema `_schema.json`.

## Caveman paketi pravila

Caveman paketi pravila se nalaze u:

```txt
open-sse/services/compression/rules/<language>/<pack>.json
```

Svaki paket sadrži zamjene koje se primjenjuju na običan tekst nakon što se izoluju zaštićeni regioni.

```json
{
  "language": "en",
  "category": "filler",
  "rules": [
    {
      "name": "question_to_directive",
      "pattern": "\\b(?:Can you explain why|Could you show me how)\\b\\s*",
      "replacement": "Explain why ",
      "replacementMap": {
        "can you explain why": "Explain why ",
        "could you show me how": "Show how "
      },
      "flags": "gi",
      "context": "all",
      "category": "context",
      "minIntensity": "lite",
      "description": "Pretvaranje opširnih pitanja u direktne zahtjeve."
    }
  ]
}
```

### Caveman polja

| Polje                    | Obavezno | Opis                                                                                 |
| ------------------------ | -------- | ------------------------------------------------------------------------------------ |
| `language`               | da       | BCP-47 ključ jezika kao što je `en`, `pt-BR`, `es`                                   |
| `category`               | da       | Naziv datoteke/kategorija paketa, na primjer `filler` ili `dedup`                    |
| `rules`                  | da       | Niz regex pravila zamjene                                                            |
| `rules[].name`           | da       | Stabilan naziv pravila                                                               |
| `rules[].pattern`        | da       | Izvorni JavaScript regex                                                             |
| `rules[].flags`          | ne       | JavaScript regex zastavice; podrazumijevano `gi`                                     |
| `rules[].replacement`    | ne       | Zamjenski string ili rezervna opcija kada `replacementMap` ne pronađe podudaranje    |
| `rules[].replacementMap` | ne       | Zamjene specifične za podudaranje, ključirane prema normalizovanom podudarnom tekstu |
| `rules[].context`        | ne       | `all`, `user`, `assistant` ili `system`; podrazumijevano `all`                       |
| `rules[].category`       | ne       | `filler`, `context`, `structural`, `dedup`, `terse` ili `ultra`                      |
| `rules[].minIntensity`   | ne       | `lite`, `full` ili `ultra`; podrazumijevano `lite`                                   |
| `rules[].description`    | ne       | Čitljiv sažetak pravila                                                              |

Koristite `flags` kada je važno podudaranje osjetljivo na velika i mala slova, na primjer uklanjanje članova prije teksta malim slovima bez uklanjanja `the OpenAI API`. Koristite `replacementMap` kada jedan regex ima više alternativa koje zahtijevaju različite izlaze; ovo održava JSON pakete pravila samo kao podatke, uz očuvanje ponašanja bogatijih ugrađenih TypeScript funkcija za zamjenu.

## RTK paketi filtera

RTK filteri se nalaze u:

```txt
open-sse/services/compression/engines/rtk/filters/<filter>.json
```

Svaki filter opisuje kako prepoznati i komprimirati porodicu izlaza komandi.

```json
{
  "id": "test-vitest",
  "label": "Vitest izlaz",
  "category": "test",
  "priority": 92,
  "match": {
    "outputTypes": ["test-vitest"],
    "commands": ["vitest", "npm test", "npm run test"],
    "patterns": ["\\bFAIL\\b", "\\bPASS\\b", "\\bTest Files\\b"]
  },
  "rules": {
    "stripAnsi": true,
    "replace": [{ "pattern": "\\s+\\[[0-9]+ms\\]", "replacement": "" }],
    "matchOutput": [
      {
        "pattern": "All tests passed",
        "message": "vitest: ok",
        "unless": "FAIL|Error:"
      }
    ],
    "includePatterns": ["FAIL", "Error:", "Test Files", "Tests"],
    "dropPatterns": ["^\\s*$", "Duration\\s+\\d+"],
    "collapsePatterns": ["^\\s+at "],
    "deduplicate": true,
    "truncateLineAt": 240,
    "maxLines": 160,
    "headLines": 24,
    "tailLines": 40,
    "onEmpty": "vitest: ok",
    "filterStderr": false
  },
  "preserve": {
    "errorPatterns": ["FAIL", "Error:", "AssertionError"],
    "summaryPatterns": ["Test Files", "Tests", "Snapshots"]
  },
  "tests": [
    {
      "name": "zadržava neuspjele testove",
      "command": "vitest",
      "input": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed",
      "expected": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed"
    }
  ]
}
```

### RTK polja

| Polje                      | Obavezno | Opis                                                                              |
| -------------------------- | -------- | --------------------------------------------------------------------------------- |
| `id`                       | da       | Stabilni ID filtera                                                               |
| `label`                    | da       | Naziv čitljiv na kontrolnoj tabli                                                 |
| `category`                 | da       | Porodica filtera: git, test, build, shell, docker, package, infra, cloud, generic |
| `priority`                 | ne       | Veći prioritet pobjeđuje kada se podudara više filtera                            |
| `match.outputTypes`        | ne       | ID-ovi izlaza detektora koji biraju ovaj filter                                   |
| `match.commands`           | ne       | Tokeni komandi koji biraju ovaj filter                                            |
| `match.patterns`           | ne       | Regex uzorci koji biraju ovaj filter iz izlaznog teksta                           |
| `rules.stripAnsi`          | ne       | Ukloni ANSI escape sekvence prije regex faza                                      |
| `rules.replace`            | ne       | Uređene regex zamjene primijenjene liniju po liniju                               |
| `rules.matchOutput`        | ne       | Short-circuit pravila izlaza sa opcionom unless zaštitom                          |
| `rules.includePatterns`    | ne       | Linije koje treba preferirano sačuvati                                            |
| `rules.dropPatterns`       | ne       | Linije koje treba ukloniti kao šum                                                |
| `rules.collapsePatterns`   | ne       | Ponavljajuće podudarajuće linije koje se mogu sažeti                              |
| `rules.deduplicate`        | ne       | Sažmi duplikate normalizovanih linija                                             |
| `rules.truncateLineAt`     | ne       | Unicode-sigurno ograničenje znakova po liniji                                     |
| `rules.maxLines`           | ne       | Maksimalan broj zadržanih linija prije očuvanja kraja                             |
| `rules.headLines`          | ne       | Početne linije zadržane tokom skraćivanja                                         |
| `rules.tailLines`          | ne       | Završne linije zadržane za nedavni kontekst                                       |
| `rules.onEmpty`            | ne       | Rezervna poruka kada filtriranje ukloni sav sadržaj                               |
| `rules.filterStderr`       | ne       | Normalizuj uobičajene stderr prefikse prije kasnijih faza filtriranja             |
| `preserve.errorPatterns`   | ne       | Linije grešaka koje trebaju preživjeti skraćivanje                                |
| `preserve.summaryPatterns` | ne       | Linije sažetka koje trebaju preživjeti skraćivanje                                |
| `tests[]`                  | ne       | Uzorci za provjeru unutar koda koje koristi RTK verify gate                       |

RTK primjenjuje deklarativne faze ovim redoslijedom: `stripAnsi`, `filterStderr`, `replace`,
`matchOutput`, `dropPatterns`/`includePatterns`, `truncateLineAt`, `headLines`/`tailLines`,
`maxLines`, i `onEmpty`.

Prilagođeni filteri se mogu učitati iz:

1. Projektnih `.rtk/filters.json` datoteka samo nakon što je prisutan odgovarajući `.rtk/trust.json` hash ili je omogućena opcija `trustProjectFilters`.
2. Globalne `DATA_DIR/rtk/filters.json`.
3. Ugrađenih filtera.

Projektne/globalne prilagođene datoteke mogu sadržavati jedan objekt filtera ili niz objekata filtera. Neispravni
prilagođeni filteri se preskaču uz dijagnostiku; neispravni ugrađeni filteri ne prolaze validaciju.

Datoteka povjerenja projekta:

```json
{
  "filtersSha256": "0123456789abcdef..."
}
```

Promjenljiva okruženja `OMNIROUTE_RTK_TRUST_PROJECT_FILTERS=1` vjeruje projektnim filterima bez
hasha i treba je ograničiti na kontrolisani lokalni razvoj.

## Sigurnosna pravila

- Održavajte pravila idempotentnim: pokretanje istog filtera dvaput ne bi trebalo oštetiti izlaz.
- Zadržite tačan tekst greške, putanje datoteka, brojeve linija i sažetke komandi gdje je to moguće.
- Izbjegavajte pravila koja mijenjaju blokove koda, JSON payload-e, URL-ove ili tajne.
- Dodajte jediničnu pokrivenost za nove porodice komandi u testovima detektora/filtera.
- Dodajte `tests[]` uzorke svakom ugrađenom filteru i dijeljenim prilagođenim filterima.

## Validacija

Paketi pravila se validiraju prije upotrebe. Ugrađeni Caveman paketi i ugrađeni RTK filteri brzo padaju tokom validacije kako bi se neispravni resursi izdanja otkrili prije isporuke. Prilagođeni RTK filteri se preskaču uz dijagnostiku kada parsiranje ili validacija povjerenja ne uspije.

Fokusirana validacija:

```bash
node --import tsx/esm --test tests/unit/compression/rule-loader.test.ts tests/unit/compression/language-packs.test.ts
node --import tsx/esm --test tests/unit/compression/rtk-verify.test.ts tests/unit/compression/rtk-dsl-pipeline.test.ts
```
