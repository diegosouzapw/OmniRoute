# Ugrađeni servisi

> **Verzija:** v3.8.44
> **Posljednje ažurirano:** 2026-07-03
> **Publika:** Inženjeri koji dodaju, održavaju ili otklanjaju greške u ugrađenim servisima (9Router, CLIProxyAPI, Mux, Bifrost).

Ugrađeni servisi su lokalno instalirani procesni sidecar alati koje OmniRoute instalira, nadzire i izlaže kao prvoklasne mete usmjeravanja. Za razliku od vanjskih provajdera (kojima se pristupa putem interneta koristeći API ključeve), ugrađeni servisi rade na istoj mašini kao i OmniRoute i komuniciraju putem loopback-a.

## 1. Pregled

### Zašto ugrađeni servisi?

Pet servisa je ugrađeno:

| Servis          | npm paket                          | Zadani port | Svrha                                                                                                                                                                                                           |
| --------------- | ---------------------------------- | :---------: | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **9Router**     | `9router`                          |    20130    | AI ruter koji OmniRoute može koristiti kao pod-provajder. Modeli izloženi kao `9router/{sub}/{model}`                                                                                                           |
| **CLIProxyAPI** | GitHub release binary (`cliproxy`) |    8317     | Lokalni proxy adapter za Anthropic CLI tokove autentifikacije. Pruža rezervno usmjeravanje kada OAuth tokeni isteknu                                                                                            |
| **Mux**         | `mux` (headless `mux server`)      |    8322     | Lokalni demon za orkestraciju agenata (coder/mux). Upravlja se samo životnim ciklusom — nije meta usmjeravanja (nema LLM proxy-ja).                                                                             |
| **Bifrost**     | `@maximhq/bifrost`                 |    8080     | Go AI-gateway relay backend. Kada je pokrenut, automatski se bira putem relay rute (`/v1/relay/`)                                                                                                               |
| **Dario**       | `@askalf/dario`                    |    3456     | Claude-subscription proxy — alternativa/failover za CLIProxyAPI za saobraćaj tipa Claude-Code; injektirani ključ postaje `DARIO_ADMIN_TOKEN` koji ograničava pristup njegovom `/admin/*` OAuth kontrolnom planu |

Svih pet slijedi isti model nadzora:

- OmniRoute ih instalira pod `DATA_DIR/services/{name}/` (izolirano od OmniRoute-ovog vlastitog `package.json`)
- OmniRoute ih pokreće i nadzire kao podređene procese
- OmniRoute ubacuje efemerni API ključ u okruženje podređenog procesa i rotira ga bez prekida rada (gdje je primjenjivo)
- Sve rute za upravljanje (`/api/services/*`) su `LOCAL_ONLY` — dostupne samo sa loopback-a (strogo pravilo #17)

### Ključne odluke (iz plana dizajna)

| Odluka                                       | Vrijednost                                                                         |
| -------------------------------------------- | ---------------------------------------------------------------------------------- |
| Pristup 9Router izvornoj UI kontrolnoj tabli | Reverzni proxy na `/dashboard/providers/services/9router/embed/*`                  |
| Mehanizam instalacije                        | `npm install {package}` putem `execFile` (bez shell interpolacije)                 |
| Način potrošnje                              | Provajder registrovan kao `9router/{sub}/{model}` u mehanizmu za usmjeravanje      |
| Upravljanje API ključevima                   | OmniRoute generiše, šifrira u stanju mirovanja (AES-256-GCM) i ubacuje putem env-a |
| Lokacija kontrolne table                     | `/dashboard/providers/services` (tri kartice)                                      |
| Automatsko pokretanje                        | Prekidač po servisu, zadano ISKLJUČENO                                             |

## 3. Mašina stanja životnog ciklusa

```
                    install()
  ┌─────────────┐ ──────────► ┌─────────────┐
  │ not_installed│             │   stopped   │◄──────────────────┐
  └─────────────┘             └──────┬──────┘                   │
                                     │ start()                   │
                                     ▼                           │ stop()
                               ┌──────────┐                      │
                               │ starting │                      │
                               └────┬─────┘                     │
                  health probe ok   │         crash / SIGTERM    │
                               ┌────▼─────┐  (exit within 5s)   │
                               │ running  │──── crash ──────────►┤
                               └────┬─────┘                   ┌─▼────┐
                             stop() │                          │error │
                                    ▼                          └──────┘
                               ┌──────────┐
                               │ stopping │
                               └──────────┘
```

Stanja su pohranjena u `version_manager` DB tabeli (`status` kolona) i preslikana u `ServiceSupervisor` stanje u memoriji. Stanje u memoriji je mjerodavno za proces koji radi; stanje u bazi podataka je trajna rezerva pri pokretanju.

### Prijelazi stanja

| Iz              | Događaj                                         | U                      |
| --------------- | ----------------------------------------------- | ---------------------- |
| `not_installed` | `install()` uspijeva                            | `stopped`              |
| `stopped`       | `start()` pozvan                                | `starting`             |
| `starting`      | health probe vraća 200                          | `running`              |
| `starting`      | proces se završava prije nego što postane zdrav | `error`                |
| `running`       | `stop()` pozvan                                 | `stopping` → `stopped` |
| `running`       | proces se neočekivano završava (< 5 s)          | `error` (brzi pad)     |
| `running`       | proces se neočekivano završava (> 5 s)          | `error`                |
| `error`         | `start()` pozvan                                | `starting`             |
| bilo koje       | `stop()` dok je `stopping`                      | no-op                  |

### Zaključavanje operacije

`ServiceSupervisor` serijalizuje operacije životnog ciklusa kroz asinhrono zaključavanje operacije (`withLock()`). Istovremeni `start()` pozivi na istom supervizoru rezultiraju tačno jednim pokretanjem; drugi pozivalac čeka i vraća postojeći status. Ovo sprječava race condition kada, na primjer, auto-start i UI dugme budu aktivirani istovremeno.

## 4. API referenca

Sve rute pod `/api/services/` su **LOCAL_ONLY** (samo loopback, strogo pravilo #17). Zahtjevi koji nisu loopback primaju `403 LOCAL_ONLY` bez obzira na autorizacijski token.

### 4.1 9Router krajnje tačke (11 ruta)

#### `POST /api/services/9router/install`

Instalirajte 9Router iz npm-a. Kreira `DATA_DIR/services/9router/` sa sopstvenim `package.json` i `node_modules/`. Ne dolazi u sukob sa OmniRoute-ovim vlastitim zavisnostima.

**Tijelo zahtjeva** (sve opcionalno):

```json
{ "version": "latest" }
```

| Polje     | Tip      | Zadano     | Opis                                         |
| --------- | -------- | ---------- | -------------------------------------------- |
| `version` | `string` | `"latest"` | npm oznaka verzije ili semver za instalaciju |

**Odgovori:**

| Status | Opis                                                                          |
| ------ | ----------------------------------------------------------------------------- |
| `200`  | `{ ok: true, installedVersion: "x.y.z", path: "..." }`                        |
| `400`  | Neispravno tijelo zahtjeva (Zod greška validacije)                            |
| `409`  | Već se instalira (zaključavanje aktivno)                                      |
| `500`  | npm install nije uspio — pogledajte `message` za prijateljsku poruku o grešci |

**Napomene:** Koristi `execFile('npm', [...])` — bez shell-a, bez interpolacije (strogo pravilo #13). EACCES greške se prikazuju kao prijateljske poruke.

---

#### `POST /api/services/9router/start`

Pokrenite 9Router. Registruje supervizora ako već nije registrovan, a zatim poziva `supervisor.start()`. Idempotentno kada već radi.

**Tijelo zahtjeva:** nema

**Odgovori:**

| Status | Opis                                                              |
| ------ | ----------------------------------------------------------------- |
| `200`  | `ServiceStatus` objekat (pogledajte šemu ispod)                   |
| `409`  | 9Router nije instaliran (`status: "not_installed"`)               |
| `503`  | Pokretanje nije uspjelo (greška procesa — pogledajte `lastError`) |

**ServiceStatus šema:**

```json
{
  "tool": "9router",
  "state": "running",
  "pid": 12345,
  "port": 20130,
  "health": "healthy",
  "startedAt": "2026-05-25T10:00:00.000Z",
  "lastError": null
}
```

---

#### `POST /api/services/9router/stop`

Graciozno zaustavite 9Router. Šalje SIGTERM, čeka 15 s, zatim SIGKILL ako je još uvijek aktivan. Idempotentno kada je već zaustavljen.

**Tijelo zahtjeva:** nema

**Odgovori:**

| Status | Opis                                   |
| ------ | -------------------------------------- |
| `200`  | `ServiceStatus` (stanje: "stopped")    |
| `503`  | Zaustavljanje nije uspjelo neočekivano |

---

#### `POST /api/services/9router/restart`

Ekvivalentno `stop()` pa `start()` pod zaključavanjem operacije.

**Tijelo zahtjeva:** nema

**Odgovori:** isto kao `start` (vraća konačni `ServiceStatus`).

---

#### `POST /api/services/9router/update`

Ažurira 9Router na noviju npm verziju. Ako servis radi, prvo se zaustavlja, pokreće se npm install (instalirajući noviju verziju na istom mjestu), a zatim se servis ponovo pokreće.

**Tijelo zahtjeva** (sve opcionalno):

```json
{ "version": "latest" }
```

**Odgovori:**

| Status | Opis                                                            |
| ------ | --------------------------------------------------------------- |
| `200`  | `{ ok: true, previousVersion: "...", installedVersion: "..." }` |
| `400`  | Neispravno tijelo zahtjeva                                      |
| `500`  | npm update nije uspio                                           |

---

#### `POST /api/services/9router/rotate-key`

Generiše novi API ključ za 9Router, šifrira ga u stanju mirovanja (at-rest), i ponovo pokreće servis (ako je pokrenut) kako bi preuzeo novi ključ iz svog okruženja. Stari ključ se odmah poništava.

**Tijelo zahtjeva:** nema

**Odgovori:**

| Status | Opis                                       |
| ------ | ------------------------------------------ |
| `200`  | `{ keyRotated: true, restarted: boolean }` |
| `500`  | Rotacija nije uspjela                      |

**Sigurnost:** Novi ključ se nikada ne vraća u odgovoru (nema curenja vjerodajnica).
Pohranjuje se šifriran (AES-256-GCM) u tabeli `version_manager`.

- Prosleđuje zahtev na `http://127.0.0.1:{port}/{path}` (samo loopback)
- Uklanja dolazeće `cookie` i `authorization` zaglavlja (nema curenja OmniRoute sesije)

## 5. Sigurnost

### Sprovođenje LOCAL_ONLY (strogo pravilo #17)

Sve rute pod `/api/services/` i `/dashboard/providers/services/*/embed/` su klasifikovane kao LOCAL_ONLY u `src/server/authz/routeGuard.ts`. Provjera povratne petlje (loopback check) se izvršava bezuslovno prije bilo koje grane autentifikacije:

```
zahtjev stiže
  → isLocalOnlyPath(path)?
      → nije povratna petlja (non-loopback) → 403 LOCAL_ONLY (uvijek, prije provjere autentifikacije)
      → povratna petlja (loopback)    → prelazak na normalnu autentifikaciju
```

Ovo sprečava da procurjeli JWT (npr. putem tunela) pokrene `npm install` ili kreiranje procesa. Pogledajte `docs/security/ROUTE_GUARD_TIERS.md` za kompletnu matricu nivoa.

### Ubacivanje API ključa

9Router i Mux zahtijevaju API ključ/bearer token za svoje HTTP krajnje tačke. OmniRoute:

1. Generiše ključ putem `crypto.randomBytes(32).toString("base64url")` sa prefiksom specifičnim za servis (`nr_` za 9Router, `mx_` za Mux).
2. Šifruje ga u stanju mirovanja (at-rest) koristeći AES-256-GCM (isti šifrator koji se koristi za akreditive provajdera).
3. Dešifruje ga i ubacuje kao varijablu okruženja u trenutku pokretanja — `NINEROUTER_API_KEY` za 9Router, `MUX_SERVER_AUTH_TOKEN` za Mux (nikada kao CLI flag, tako da se token nikada ne pojavljuje u `ps`/listama procesa).
4. Nikada ne vraća ključ u čistom tekstu (plaintext) ni u jednom HTTP odgovoru.

CLIProxyAPI prima namjenski ključ ravni podataka (data-plane) ubačen pri pokretanju (`needsApiKey: true` — koristi se za sinhronizaciju modela sa adapterom).

### SSRF odbrana

Reverzni HTTP proxy (`/dashboard/.../embed/[...path]`) je hardkodiran da prosljeđuje samo na `http://127.0.0.1:{port}`. Nikada ne prati preusmjeravanja na destinacije koje nisu povratna petlja (non-loopback). Biblioteka `ssrf-req-filter` se koristi za odbijanje bilo kojeg uzvodnog (upstream) URL-a koji se razrješava izvan opsega povratne petlje.

### Sigurnost ljuske (strogo pravilo #13)

`npm install` se poziva putem `execFile('npm', ['install', pkg, '--prefix', dir])` — bez šablonskih literala, bez ljuske, bez interpolacije eksternih putanja u komandni niz. Vrijednosti tokom izvršavanja (portovi, API ključevi) se prosljeđuju putem `env` objekta podređenog procesa.

### Sanitizacija grešaka (strogo pravilo #12)

Svi odgovori o greškama sa `/api/services/*` prolaze kroz `buildErrorBody()` ili `sanitizeErrorMessage()`. Sirovi `err.stack` i `err.message` se nikada ne vraćaju doslovno pozivaocu.

## 7. Rješavanje problema

### Servis se ne pokreće

**Simptomi:** Dugme za pokretanje vraća 503, status ostaje `"error"` ili `"starting"`.

**Kontrolna lista:**

1. Provjerite `GET /api/services/{name}/logs` (ili panel Logs na kontrolnoj tabli). Potražite linije kao što su `Error: ENOENT`, `address already in use` ili `Cannot find module`.
2. Provjerite da li je `npm` u PATH-u: `which npm` sa istog korisničkog naloga koji pokreće OmniRoute.
3. Provjerite da li je servis instaliran: provjerite `GET /api/services/{name}/status` za `installedVersion`. Ako je `null`, prvo pokrenite instalaciju.
4. Provjerite da li `DATA_DIR/services/{name}/node_modules/` postoji i da nije prazan.
5. Provjerite polje `lastError` u odgovoru o statusu za očišćeni razlog izlaza.

---

### Hladno pokretanje je sporo (> 10 s do postizanja `running` statusa)

**Simptomi:** Status ostaje `"starting"` dugo vremena prije nego što pređe u `"running"` ili `"error"`.

**Objašnjenje:** Hladno pokretanje 9Router-a uključuje uvoz velikih stabala zavisnosti (DNS, tunel, MITM moduli). Podrazumijevani interval provjere ispravnosti je 2 s sa 3 pokušaja prije nego što supervizor proglasi istek vremena (ali nastavlja sa provjerom).

**Rješenje:** `healthIntervalMs` i `waitForHealthy` vremensko ograničenje (`healthIntervalMs * 3`) su podesivi u `bootstrap.ts`. Za servise sa dužim vremenom pokretanja, povećajte `healthIntervalMs` na 5000 i `stopTimeoutMs` na 30 000.

---

### Kolizija portova (`EADDRINUSE`)

**Simptomi:** Logovi pokazuju `address already in use :::20130`.

**Uzroci:**

- Drugi proces već koristi port 20130.
- Prethodni 9Router proces nije u potpunosti zaustavljen (zombi PID).

**Rješenje:**

1. Promijenite podrazumijevani port putem `NINEROUTER_PORT` varijable okruženja u `.env`.
2. Pronađite i prekinite proces koji pravi konflikt: `lsof -ti :20130 | xargs kill -9`.
3. Port je podesiv po servisu u `bootstrap.ts` putem polja `port`.

**Napomena:** 9Router podrazumijevano koristi port 20130 posebno da bi izbjegao koliziju sa OmniRoute-ovim podrazumijevanim portom 20128.

---

### Odbijena dozvola (`EACCES`) pri instalaciji

**Simptomi:** Instalacija vraća 500, logovi pokazuju `EACCES` ili `permission denied`.

**Uzroci:**

- `DATA_DIR` ili njegov nadređeni direktorij nije upisiv od strane OmniRoute procesa.
- Pokretanje unutar Docker-a bez root privilegija (rootless) bez prava upisa na mapirani volumen.

**Rješenje:**

1. Provjerite `DATA_DIR` (podrazumijevano: `~/.omniroute/`): `ls -la ~/.omniroute/`
2. Osigurajte da korisnik OmniRoute procesa posjeduje direktorij: `chown -R $USER ~/.omniroute/`
3. U Docker-u, osigurajte da mount volumena ima ispravne dozvole za korisnika kontejnera.

---

### Ažuriranje nije uspjelo (`npm install` istek vremena ili mrežna greška)

**Simptomi:** Ažuriranje vraća 500 sa `InstallError`, logovi pokazuju istek mrežnog vremena.

**Kontrolna lista:**

1. Potvrdite da je npm registar dostupan: `npm ping`.
2. Provjerite korporativni proxy: `npm config get proxy`, `npm config get https-proxy`.
3. Pokušajte ručno instalirati: `npm install {package}@latest --prefix ~/.omniroute/services/{name}/`.
4. Ako ste iza air-gap-a (izolirane mreže), prethodno preuzmite tarball i koristite `npm install /path/to/tarball.tgz`.

---

### Servis pokazuje `"error"` status odmah nakon pokretanja (brzi pad)

**Simptomi:** Status prelazi iz `"starting"` u `"error"` za manje od 5 sekundi. `lastError` pokazuje `"Fast crash (exited with code 1)"`.

**Kontrolna lista:**

1. Pročitajte cijeli kraj loga: `GET /api/services/{name}/logs?tail=500`.
2. Čest uzrok: nedostajuće varijable okruženja koje servis očekuje.
3. Za 9Router: provjerite da li su `NINEROUTER_DISABLE_MITM=true` i `NINEROUTER_DISABLE_TUNNEL=true` u env-u proslijeđenom pri pokretanju (pogledajte `installers/ninerouter.ts` `resolveSpawnArgs`).

## 8. Česta pitanja

**Q: Mogu li izložiti krajnje tačke (endpoints) ugrađenih servisa klijentima koji nisu na loopback adresi?**

Ne. LOCAL_ONLY nivo je namjeran (strogo pravilo #17). Rute koje mogu pozvati `npm install` ili pokrenuti `node` procese ne smiju biti dostupne iz saobraćaja koji nije loopback, jer bi procurjeli JWT putem tunela (Cloudflare, Ngrok, Tailscale) u suprotnom omogućio proizvoljno pokretanje procesa. Ne postoji izuzetak za `/api/services/` — za razliku od `/api/mcp/`, on je isključen sa liste zaobilaženja manage-scope-a. Pogledajte `docs/security/ROUTE_GUARD_TIERS.md`.

---

**Q: Hoće li 9Router i CLIProxyAPI biti dostupni u produkcijskim/cloud implementacijama?**

Da. Oba servisa prate isti model "lokalno-prvo" (local-first) kao i sam OmniRoute. Oni rade na istoj mašini i komuniciraju preko loopback-a. "Produkcija" ovdje znači VPS ili lokalni server na kojem je OmniRoute raspoređen, a ne udaljeni cloud provajder.

---

**Q: Kako da otklonim greške (debug) u supervisor-u?**

1. Pratite (tail) SSE log stream: `curl -N http://localhost:20128/api/services/9router/logs`.
2. Provjerite strukturirane logove u OmniRoute-ovom pino izlazu filtrirane po `service:supervisor` imenskom prostoru.
3. Pregledajte DB red: `sqlite3 ~/.omniroute/omniroute.db "SELECT * FROM version_manager WHERE tool='9router'"`.
4. Koristite `GET /api/services/9router/status` da vidite trenutno stanje uživo, PID, zdravlje (health) i `lastError` u jednom pozivu.

---

**Q: Supervisor prikazuje `health: "degraded"` ili `health: "unknown"`, ali je stanje `"running"`. Da li je to problem?**

`"degraded"` znači da je health probe vratio odgovor koji nije 200. `"unknown"` znači da nijedna provjera još nije završena (trka sa prvim anketiranjem). Oba su prolazna tokom pokretanja. Ako zdravlje ostane `"degraded"` duže od `healthIntervalMs * 3` ms nakon `"running"`, ugrađeni servis radi, ali njegov HTTP API ne odgovara. Provjerite da li je port ispravan u statusnom odgovoru i da li servis zaista sluša na tom portu.

---

**Q: Mogu li promijeniti 9Router API ključ bez potpunog ponovnog pokretanja?**

Ne. API ključ se prosljeđuje 9Router-u putem varijable okruženja u trenutku pokretanja. Varijable okruženja se ne mogu mijenjati u procesu koji radi. `POST .../rotate-key` automatski zaustavlja i ponovo pokreće servis kako bi se primijenio novi ključ. Rotacija ključa stupa na snagu unutar `stopTimeoutMs` servisa (podrazumijevano 15 s) plus njegovo vrijeme pokretanja.

---

**Q: Koje je ograničenje ring buffera i šta se dešava kada se popuni?**

Svaki servis ima namjenski 5 MB ring buffer. Kada se buffer popuni, najstarije linije logova se izbacuju kako bi se napravilo mjesta za nove. SSE `snapshot` događaj vraća najnovije linije unutar `tail` ograničenja. Logovi se ne čuvaju na disku osim ako `logsBufferPath` nije postavljen u DB redu.
