# AgentBridge

AgentBridge je OmniRoute-ov MITM (Man-in-the-Middle) proxy koji presreće HTTPS saobraćaj od IDE AI agenata i preusmjerava ga kroz OmniRoute-ov jedinstveni mehanizam za rutiranje. Podržava **10 IDE agenata** — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code i Trae (u fazi istraživanja) — čineći OmniRoute MITM proxyjem sa najširom pokrivenošću za AI asistente za kodiranje na tržištu.

**Lokacija kontrolne ploče (Dashboard):** `/dashboard/tools/agent-bridge`
**Grupa u bočnoj traci (Sidebar):** Tools (nakon Cloud Agents)
**Pogledajte također:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — nadgledajte sav presretnuti saobraćaj u realnom vremenu; `docs/security/MITM-TPROXY-DECRYPT.md` (git; nije kompajlirano u `/docs`) — Linux TPROXY transparentni-dešifrujući režim snimanja pokretan putem rute `/api/tools/agent-bridge/tproxy`.

---

## §1 Pregled

### Šta je AgentBridge?

Kada IDE agent (npr. GitHub Copilot, Cursor, Claude Code) napravi API poziv, on se direktno povezuje sa upstream AI provajderom (OpenAI, Anthropic, itd.). AgentBridge transparentno presreće tu konekciju na TLS nivou — bez potrebe za bilo kakvom promjenom konfiguracije agenta — i prepisuje zahtjev kroz OmniRoute.

To znači da možete:

- **Preusmjeriti bilo kojeg agenta na bilo kojeg provajdera**: Copilot komunicira sa OpenAI? Preusmjerite ga na Anthropic Claude, Gemini ili bilo kojeg od 352 OmniRoute provajdera.
- **Primijeniti mapiranja modela**: `gemini-3-flash` → `claude-sonnet-4.7` transparentno na nivou handlera.
- **Posmatrati sav saobraćaj agenta**: svaki presretnuti zahtjev se objavljuje u [Traffic Inspector](./TRAFFIC_INSPECTOR.md).
- **Primijeniti OmniRoute otpornost**: kombinovano rutiranje, circuit breakers, fallbacks i praćenje troškova rade i za saobraćaj IDE agenata.

## §2 Arhitektura

### 2.1 Pregled komponenti

```
IDE Agent (VS Code / Cursor / itd.)
    │  HTTPS (port 443)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← DNS preusmjeravanje
    │
    ▼
src/mitm/server.cjs  (port 443, CJS podproces)
    │  razrješava cilj putem Host zaglavlja SNI
    │  generiše TLS certifikat po SNI potpisan od strane AgentBridge CA
    ├── Podudaranje sa listom zaobilaženja? → TCP prolaz (bez dekripcije)
    ├── Podudaranje sa ciljem? → fetch → OmniRoute ruter (port 20128)
    │       └── handler.intercept() — TypeScript
    │               ├── maskSecrets() na tijelu zahtjeva/zaglavljima
    │               ├── TrafficBuffer.push() — objavljuje u Traffic Inspector
    │               └── fetchRouter() → /v1/chat/completions
    └── Nema podudaranja? → TCP prolaz (bez dekripcije)
```

### 2.2 MITM server (`src/mitm/server.cjs`)

Osnovni MITM server radi kao Node.js CJS podproces (kako bi se izbjeglo prepisivanje postojećeg CJS koda). On:

- Sluša na portu 443 (zahtijeva privilegije ili `authbind`/`setcap`)
- Prima CONNECT tunele od OS-a (putem `/etc/hosts` DNS preusmjeravanja)
- Generiše TLS certifikate po SNI potpisane od strane AgentBridge CA (`DATA_DIR/mitm/ca.crt`)
- Razrješava ciljni agent putem Host zaglavlja kroz `targets/index.ts` registar
- Prosljeđuje na TypeScript sloj rukovaoca putem HTTP-a na `http://127.0.0.1:20128`

`TARGET_HOSTS` se učitava iz `DATA_DIR/mitm/targets.json` (koji `targets/index.ts` upisuje pri pokretanju), omogućavajući dinamička ažuriranja bez ponovnog pokretanja CJS servera.

> **Root-CA model (#6684).** Gore navedeni opis certifikata po SNI potpisanog od strane CA je trajni root-CA model dodan u #6684 (`src/mitm/cert/rootCa.ts` + `src/mitm/_internal/rootCaShim.cjs`, ponovno koristeći CA/leaf kriptografiju koja je već provjerena za TPROXY u `src/mitm/tproxy/dynamicCert.ts`) — on zamjenjuje stariji pojedinačni statički samopotpisani leaf (`src/mitm/cert/generate.ts`, koji je još uvijek ograničen samo na antigravity hostove) na šta ukazuje običan `server.crt`/`server.key` par na disku. **Ponašanje pri migraciji**: svježa instalacija (bez prethodnog `server.crt`) automatski dobija root-CA model; instalacija koja je već vjerovala starom statičkom leaf-u nastavlja ga koristiti sve dok operater ne postavi `MITM_ROOT_CA_ENABLED=true` i ponovo pokrene bridge (`src/mitm/cert/migration.ts` je čista funkcija odlučivanja — pouzdani MITM CA koji može potpisati leaf za **bilo koji** host je materijalno moćniji od starog leaf-a sa fiksnim SAN-om, tako da prebacivanje nikada nije tiho za već pouzdanu instalaciju). CA certifikat se instalira u isti `omniroute-mitm.crt` slot skladišta povjerenja koji je koristio stari leaf (`cert/install.ts::installCaCert`) — nije potrebno čišćenje dvostrukog povjerenja.

### 2.3 Osnova rukovaoca (`src/mitm/handlers/base.ts`)

Svi rukovaoci agenata proširuju `MitmHandlerBase`:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // Zaštićeni pomoćnici: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

Svaki rukovalac poziva `hookBufferStart()` prije proksiranja i `hookBufferUpdate()` kada završi. Oni guraju `InterceptedRequest` unose u `globalTrafficBuffer` (pogledajte [Traffic Inspector](./TRAFFIC_INSPECTOR.md) §4).

### 2.4 Registar ciljeva (`src/mitm/targets/`)

Svaki agent ima deklarativnu datoteku cilja:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

Registar (`targets/index.ts`) izvozi `ALL_TARGETS` i emituje `DATA_DIR/mitm/targets.json` pri pokretanju.

### 2.5 Prolaz i lista zaobilaženja (`src/mitm/passthrough.ts`)

**Lista zaobilaženja** (provjerava se prva, sa prioritetom nad podudaranjem cilja):

- Zadani obrasci: bankarski hostovi, `.gov.`, OAuth/SSO provajderi (Okta, Auth0), itd.
- Korisnički obrasci: pohranjeni u DB tabeli `agent_bridge_bypass`
- Zaobiđeni hostovi primaju transparentni TCP tunel — TLS se **nikada ne dekriptuje**

**Zadani prolaz** (nema podudaranja cilja i nije u zaobilaženju):

- Također prima TCP tunel — veze se nikada ne prekidaju
- Sprečava AgentBridge da ometa opći sistemski HTTPS saobraćaj

Prioritet rutiranja:

```
lista zaobilaženja → podudaranje cilja → prolaz
```

### 2.6 Upstream CA certifikat (`src/mitm/upstreamTrust.ts`)

Za korporativna mrežna okruženja sa prilagođenim CA:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

Kada je postavljeno, konfiguriše `undici` globalni dispečer sa dodatnim CA certifikatom, omogućavajući AgentBridge-u da dosegne upstream provajdere kroz korporativne TLS terminacione proxyje.

### 2.7 Maskiranje tajni (`src/mitm/maskSecrets.ts`)

Nezavisni clean-room skener se primjenjuje na tijela zahtjeva i zaglavlja vjerodajnica **prije** nego što uđu u Traffic Inspector bafer ili bilo koji log. On izvodi jedan linearni prolaz:

- `sk-` / `ak-` / `pk-` prefiksirani tokeni (OpenAI/Anthropic stil)
- RFC 6750 `Authorization: Bearer <token>` vjerodajnice, sa prioritetom cijelog tokena
- Generički dugi neprozirni tokeni (≥40 znakova), uključujući tačkaste i popunjene oblike

`sanitizeHeaders()` pretvara zadržana imena u mala slova, spaja vrijednosti niza deterministički, odbacuje dijeljenu hop-by-hop/framing crnu listu (uključujući proxy autentifikaciju), potpuno rediguje `cookie` i `set-cookie`, i delegira vrijednosti vjerodajnica skeneru.

## §3 Postavljanje

### 3.1 Pokretanje/zaustavljanje MITM servera

Koristite karticu AgentBridge servera na `/dashboard/tools/agent-bridge`:

| Radnja                     | Opis                                                                               |
| -------------------------- | ---------------------------------------------------------------------------------- |
| Pokreni server             | Pokreće `src/mitm/server.cjs` na portu 443                                         |
| Zaustavi server            | Uredno zaustavlja podređeni proces                                                 |
| Ponovo pokreni server      | Zaustavlja i ponovo pokreće server (primjenjuje izmjene ciljeva)                   |
| Vjeruj certifikatu         | Instalira `DATA_DIR/mitm/ca.crt` u spremište pouzdanih certifikata OS-a            |
| Preuzmi certifikat         | Preuzima `ca.crt` radi ručne instalacije                                           |
| Ponovo generiši certifikat | Kreira novi par CA ključeva (svi postojeći certifikati po agentu postaju nevažeći) |

### 3.2 Postavljanje certifikata kao pouzdanog

AgentBridge CA certifikat mora biti označen kao pouzdan u OS-u prije nego što IDE-ovi prihvate MITM vezu.

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Privjesak ključeva):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

Ili koristite dugme "Vjeruj certifikatu" na kontrolnoj ploči (pokreće odgovarajuću naredbu za vaš OS, uz sudo upit ako je potreban).

#### IDE-ovi zasnovani na Electronu zanemaruju spremište pouzdanih certifikata OS-a (`NODE_EXTRA_CA_CERTS`)

Neki IDE-ovi — naročito **Antigravity IDE** i druge aplikacije izvedene iz Electrona / VS Codea — sadrže
vlastito Node.js izvršno okruženje koje **ne koristi spremište pouzdanih certifikata OS-a** za izlazne
`fetch`/HTTPS zahtjeve. Postavljanje CA certifikata kao pouzdanog na nivou OS-a/NSS-a dovoljno je za izvorni **pozadinski sistem**
IDE-a (npr. Go jezički server, koji koristi CA paket OS-a), ali će **Electronov korisnički interfejs**
i dalje prijavljivati TLS grešku — što se prikazuje kao da je korisnik _odjavljen_ ili kao _"greška veze"_,
iako MITM zapis pokazuje da inicijalni pozivi pozadinskog sistema vraćaju `200`. Potrebna su
dva koraka i oba su važna:

1. Izričito usmjerite izvršno okruženje na CA:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **Pokrenite IDE iz tog terminala.** Pokretanje putem ikone na radnoj površini / Docka / Start menija
   **ne** nasljeđuje varijable izvezene iz terminala, a `~/.config/environment.d/*.conf` primjenjuje se tek nakon
   nove grafičke prijave. Prvo potpuno zatvorite IDE — Electronovo zaključavanje jedne instance znači da drugo
   pokretanje samo prebacuje fokus na postojeći proces, dok se novo okruženje zanemaruje.

Prethodno navedeni korak postavljanja povjerenja na nivou OS-a + NSS-a i dalje je potreban (Chromiumov mrežni stek koji koriste neki
tokovi autentifikacije čita korisničko NSS spremište i ima vlastite statičke pinove za `*.googleapis.com` koje
lokalno pouzdani CA nadjačava). `NODE_EXTRA_CA_CERTS` dodatno pokriva Nodeovu `fetch` putanju.

### 3.3 DNS usmjeravanje

Za svakog agenta kojeg želite presretati njegovi API hostovi moraju se razrješavati na `127.0.0.1`. AgentBridge automatski upravlja unosima u `/etc/hosts` kada uključite ili isključite DNS za agenta u čarobnjaku za postavljanje.

Primjeri unosa u `/etc/hosts` za GitHub Copilot:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 Mapiranje modela

Koristite tabelu mapiranja modela na kartici svakog agenta kako biste definirali mapiranja izvora → cilja:

| Izvorni model (izvorni za agenta) | Ciljni model (OmniRoute) |
| --------------------------------- | ------------------------ |
| `gpt-4o`                          | `claude-sonnet-4.7`      |
| `*` (zamjenski znak)              | `claude-haiku-4.7`       |

Zamjenski znak `*` mapira svaki neprepoznati model na navedeni cilj. Trajno se pohranjuje u tabeli `agent_bridge_mappings`.

> **Savjet — otkrijte stvarne ID-ove modela agenta.** IDE može slati nazive modela koji se razlikuju od
> oznaka u njegovom korisničkom interfejsu i koji se mijenjaju između glavnih verzija. Naprimjer, **Antigravity 2** šalje
> `gemini-3.1-pro-low`, `gemini-pro-agent` i `gemini-3.1-flash-lite` putem mreže — a ne
> `gemini-2.5-pro` prikazan u starijoj dokumentaciji. Pošaljite jednu poruku bez odgovarajućeg mapiranja: MITM
> bilježi tačnu dolaznu vrijednost `model:` i prosljeđuje zahtjev. Mapirajte tu doslovnu vrijednost, a zatim
> će sljedeći zahtjev biti presretnut i usmjeren na vaš cilj.

### 3.5 Obavijest o riziku

AgentBridge presreće vjerodajnice (OAuth tokene, API ključeve) koje IDE koristi za autentifikaciju kod nadređenih pružalaca usluga. One su **maskirane prije zapisivanja** (pogledajte §2.7), ali su vidljive MITM sloju OmniRoutea. Pri prvom aktiviranju svakog agenta prikazuje se modalna obavijest o riziku koja se može zatvoriti.

### 3.6 Održavanje i dijagnostika

Kontrolna ploča sadrži karticu **Održavanje i dijagnostika** (`AgentBridgeMaintenanceCard`, u `src/app/(dashboard)/dashboard/tools/agent-bridge/components/`) koja prikazuje operativne MITM rute koje ranije nisu imale korisnički interfejs. Njen podnaslov glasi: _"Samostalno testirajte cjevovod za snimanje, poništite preostalo stanje sistema i prenesite svoju konfiguraciju između računara."_ Klijentske pomoćne funkcije kartice nalaze se u `src/lib/inspector/agentBridgeMaintenanceApi.ts`.

| Dugme                    | Ruta                                   | Šta radi                                                                                                                                                                                                         |
| ------------------------ | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Dijagnosticiraj**      | `GET /api/tools/agent-bridge/diagnose` | Pokreće samotestiranje cjevovoda za snimanje i prikazuje izvještaj za svaku provjeru (✓/✗ + savjet za otklanjanje problema).                                                                                     |
| **Popravi**              | `POST /api/tools/agent-bridge/repair`  | Poništava napušteno stanje MITM sistema (lažni DNS unosi, korijenski CA, sistemski proxy) preostalo nakon rušenja ili SIGKILL-a. Idempotentno — prijavljuje „Nema ništa za popraviti“ kada je stanje čisto.      |
| **Ukloni CA**            | `DELETE /api/tools/agent-bridge/cert`  | Ukida povjerenje i uklanja MITM korijenski CA iz OS spremišta pouzdanih certifikata (eksplicitno, idempotentno). Prikazuje se samo kada je CA trenutno pouzdan; zahtijeva potvrdu „Ukloniti CA?“ unutar prikaza. |
| **Izvezi konfiguraciju** | `GET /api/tools/agent-bridge/config`   | Preuzima prenosivi konfiguracijski JSON (pogledajte §3.7).                                                                                                                                                       |
| **Uvezi konfiguraciju**  | `POST /api/tools/agent-bridge/config`  | Učitava prethodno izvezeni konfiguracijski JSON (pogledajte §3.7).                                                                                                                                               |

Svaka kartica agenta također ima vlastito dugme **Vrati zadano** (`POST
/api/tools/agent-bridge/agents/{id}/reset`) — poništavanje jednim klikom za pojedinačnog agenta koje uklanja lažiranje samo za hostove tog
agenta, briše njegove sačuvane mape modela i vraća njegovo stanje `dns_enabled`/`setup_completed`
na početne vrijednosti, tako da IDE ponovo komunicira sa stvarnim nadređenim servisom nakon potpunog ponovnog pokretanja. Ono **ne** utiče na
dijeljeni MITM server ni korijenski CA (drugi agenti možda i dalje zavise od njih) — oni ostaju dostupni
putem kartice servera i gornje radnje **Ukloni CA**. Na Windowsu također, po principu najvećeg truda, pokreće
`ipconfig /flushdns`, jer Windows DNS klijent kešira unose iz datoteke hosts i inače neće ukloniti
upravo uklonjeno lažiranje.

**Dijagnostičke provjere** (`summarizeDiagnostics()` u `src/mitm/inspector/diagnostics.ts`). Ruta pokreće probu s efektima za svaku provjeru i prosljeđuje logičke vrijednosti čistom sažimaču; vraćaju se jedna procjena `healthy` i savjet za svaki neuspjeh:

| Naziv provjere     | Šta provjerava                                                    | Savjet u slučaju neuspjeha                                                                                                                           |
| ------------------ | ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server-running`   | Proces MITM servera je aktivan                                    | „MITM server nije pokrenut. Pokrenite ga s kartice AgentBridge.“                                                                                     |
| `server-reachable` | MITM server prihvata veze na svom portu (TCP proba)               | „MITM server ne prihvata veze na svom portu. Provjerite je li port slobodan i imate li ovlasti za njegovo povezivanje.“                              |
| `cert-exists`      | MITM certifikat je generisan na disku                             | „MITM certifikat još nije generisan. Generišite ga s kartice AgentBridge.“                                                                           |
| `cert-trusted`     | MITM korijenski CA nalazi se u OS spremištu pouzdanih certifikata | „OS spremište ne vjeruje MITM korijenskom CA-u, pa TLS presretanje neće uspjeti. Postavite certifikat kao pouzdan putem kartice AgentBridge.“        |
| `dns-configured`   | Ciljni nazivi hostova lažirani su u `/etc/hosts`                  | „Ciljni nazivi hostova nisu lažirani u /etc/hosts, pa saobraćaj nikada ne dolazi do proxyja. Omogućite DNS za agente čiji saobraćaj želite snimati.“ |

**Natpis o napuštenom stanju:** kada stranica otkrije stanje preostalo nakon rušenja (lažiranje DNS-a / CA / sistemski proxy), kartica prikazuje žuti natpis — _„Prethodna sesija ostavila je sistemsko stanje (lažiranje DNS-a, CA ili sistemski proxy). Pokrenite Popravi da biste ga očistili.“_ — i ističe dugme **Popravi**. `Repair` je ekvivalent ProxyBridgeove zastavice `--cleanup` na nivou aplikacije (delegira na `repairMitm()` u `src/mitm/manager.ts`).

> MITM korijenski CA ostaje instaliran između zaustavljanja i pokretanja kako bi se izbjegli ponovljeni sudo
> upiti (isto ponašanje kao kod mitmproxyja/Charlesa), pa je njegovo uklanjanje eksplicitna
> radnja **Ukloni CA**, umjesto nečega što se automatski događa pri zaustavljanju.

### 3.7 Uvoz/izvoz prenosive konfiguracije

AgentBridge može serijalizirati stanje koje **operater može podešavati** u verzionirani JSON objekt kako bi se postavke mogle replicirati na više računara. Serijalizator je `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`), a validira ga `AgentBridgeConfigSchema`.

Izvoz uključuje tačno tri stavke (ugrađene zadane vrijednosti namjerno se **NE** izvoze, tako da ih uvoz nikada ne duplicira niti dolazi u sukob s njima):

| Polje            | Izvor                                                              | Napomene                                                                  |
| ---------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| `bypassPatterns` | korisnički definirani obrasci zaobilaženja (`agent_bridge_bypass`) | zadani obrasci za banke/vladine stranice/Okta su isključeni               |
| `customHosts`    | prilagođeni hostovi Traffic Inspectora (`inspector_custom_hosts`)  | svaki: `{ host, kind: "llm"\|"app"\|"custom", label? }`                   |
| `agentMappings`  | mapiranja modela po agentu (`agent_bridge_mappings`)               | `{ [agentId]: [{ source, target }] }` za svakog agenta koji ima mapiranja |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**Ponašanje pri uvozu** (`POST /api/tools/agent-bridge/config`): obrasci zaobilaženja i mapiranja po agentu **zamjenjuju se u cijelosti**; prilagođeni hostovi dodaju se **idempotentno** (`INSERT OR IGNORE`). Odgovor navodi koliko je stavki svake vrste primijenjeno:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

Šta **NIJE** u konfiguraciji: stanje pokrenutosti servera, putanje certifikata, DNS stanje po agentu, putanja do nadređenog CA certifikata i TPROXY postavke — to je stanje hosta/izvršnog okruženja, a ne prenosive postavke.

### Lista zaobilaženja za osjetljive hostove

Lista zaobilaženja osigurava da se finansijske institucije, OAuth/SSO provajderi i drugi osjetljivi hostovi **nikada ne dekriptuju**. Njihov TLS saobraćaj prolazi kao transparentni TCP tunel — OmniRoute nikada ne vidi običan tekst (plaintext).

Podrazumijevani obrasci za zaobilaženje uključuju:

- `*.bank.*`, `*.gov.*` (finansijski/vladini)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/identitet)
- `*.apple.com`, `*.icloud.com` (Apple sistemski servisi)

Obrasci za zaobilaženje koje dodaju korisnici se čuvaju u tabeli `agent_bridge_bypass` i imaju prioritet nad svime ostalim.

### Maskiranje tajni

`maskSecrets()` iz `src/mitm/maskSecrets.ts` se primjenjuje:

- Na svako tijelo zahtjeva prije `TrafficBuffer.push()`
- Na svako zaglavlje prije logovanja ili emitovanja

Obrasci: tokeni sa prefiksom `sk-`/`ak-`/`pk-`, `Bearer` tokeni i generički tokeni ≥40 karaktera.

### Upstream CA certifikat

Kada je `AGENTBRIDGE_UPSTREAM_CA_CERT` postavljen, fajl se čita pri pokretanju. Ako putanja postoji, ali fajl nije čitljiv, AgentBridge loguje jasnu grešku i odbija da se pokrene (sprječava tihe TLS greške u korporativnim okruženjima).

### Poznata ograničenja

- **Port 443 zahtijeva privilegije**: Na Linuxu, AgentBridge treba `setcap 'cap_net_bind_service=+ep'` na Node binarnom fajlu, ili pokretanje putem `authbind`. Čarobnjak za podešavanje prikazuje uputstva specifična za OS.
- **Potrebno ponovno pokretanje IDE-a**: Nakon DNS preusmjeravanja, IDE se mora ponovo pokrenuti da bi nova rezolucija hosta stupila na snagu.
- **Hardkodirani OAuth tokeni**: Neki agenti (Kiro, Antigravity) čuvaju OAuth refresh tokene lokalno. Oni su transparentni za AgentBridge — on vidi `Bearer` token u svakom zahtjevu, koji se maskira prije logovanja.
- **Electron frontendi trebaju `NODE_EXTRA_CA_CERTS`**: IDE-ovi čiji frontend radi na ugrađenom Node/Electron runtime-u ignorišu OS/NSS trust store i moraju se pokrenuti iz shell-a sa postavljenim `NODE_EXTRA_CA_CERTS` (pogledajte §3.2). Simptom kada nedostaje: IDE backend se autentifikuje (MITM pokazuje `200`s), ali UI ostaje odjavljen.
- **Višestruke instalacije istog IDE-a su nezavisne**: sistemska instalacija (npr. `/usr/share/antigravity/antigravity`) i korisnička "Full" instalacija (npr. `~/AntigravityIDE_Full/antigravity-ide`) su odvojeni procesi sa sopstvenim runtime-ovima — svaki se mora ponovo pokrenuti sa injektovanim CA. Identifikujte koji je pokrenut prema njegovoj binarnoj putanji prije ponovnog pokretanja.
- **Identitet postavlja sistemski prompt agenta, a ne rutirani model**: kada remapirate model agenta na drugog provajdera, odgovor i dalje tvrdi da je to izvorni identitet agenta (npr. Antigravity odgovara "I am powered by Gemini") jer IDE to ubacuje u sistemski prompt. Potvrdite stvarni backend u `call_logs` / `proxy_logs` (`provider`, `model`, `target_format`), a ne pitajući model ko je on.

## §6 Rješavanje problema

### Konflikt porta 443

Ako neki drugi proces već sluša na portu 443 (web server, VPN, itd.):

```bash
lsof -i :443          # pronađi proces
sudo fuser -k 443/tcp  # prisilno zaustavi (koristi s oprezom)
```

Alternativno, konfigurišite neprivilegovani port u postavkama AgentBridge-a i podesite `iptables` / `pf` pravila preusmjeravanja.

### Certifikat nije pouzdan

Ako IDE prikazuje TLS greške nakon pokretanja AgentBridge-a:

1. Provjerite da li je certifikat instaliran: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) ili `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. Neke aplikacije održavaju vlastito skladište povjerenja (Firefox, Chrome na Linuxu). Ponovo pokrenite „Trust Cert“ i provjerite NSS/Firefox-specifično skladište certifikata.
3. Ponovo pokrenite IDE nakon dodavanja povjerenja — TLS sesije u toku koriste staro stanje povjerenja.

### IDE odjavljen / "greška u povezivanju" uprkos pouzdanom CA

Simptom: nakon preusmjeravanja DNS-a i dodavanja povjerenja CA, IDE zasnovan na Electronu (npr. Antigravity) se otvara **odjavljen** ili prikazuje grešku autentifikacije/povezivanja, iako MITM log pokazuje da bootstrap pozivi (`loadCodeAssist`, `fetchAvailableModels`, …) vraćaju `200`.

Uzrok: **ugrađeni Node/Electron runtime** IDE-a ignoriše skladište povjerenja operativnog sistema. Izvorni backend (Go jezički server) vjeruje OS CA i autentifikuje se, ali Electron frontend ne — pa UI vjeruje da je van mreže.

Rješenje (oba koraka): eksportujte `NODE_EXTRA_CA_CERTS=<ca.crt>` **i ponovo pokrenite IDE iz te ljuske (shell)**, a ne sa ikone na radnoj površini. Prvo potpuno zatvorite IDE — Electron-ovo zaključavanje singleton-a znači da drugo pokretanje samo fokusira postojeći proces i novo okruženje se ignoriše. Pogledajte §3.2. Ovo odražava otvoreni upstream izvještaj gdje samostalni agent radi kroz MITM, ali IDE varijanta ne uspijeva pod istim postavkama.

### DNS nije propagiran

Provjerite da li je `/etc/hosts` ažuriran:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

Ispraznite DNS keš:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### IDE nije detektovan

Automatska detekcija koristi uobičajene putanje instalacije. Ako detekcija ne uspije, a IDE je instaliran:

- Provjerite da li se IDE binarna datoteka nalazi na nestandardnoj lokaciji
- Čarobnjak za podešavanje (Setup Wizard) i dalje radi — neuspjeh detekcije samo znači da značka neće prikazati putanju instalacije

### Greške rukovaoca (upstream fetch ne uspijeva)

Ako AgentBridge presreće, ali svi zahtjevi ne uspijevaju:

1. Provjerite da li je barem jedan provajder povezan na `/dashboard/providers`
2. Provjerite logove OmniRoute servera: `APP_LOG_LEVEL=debug` u `.env`
3. Provjerite da li `OMNIROUTE_BASE_URL` pokazuje na ispravnu krajnju tačku rutera (podrazumijevano: `http://127.0.0.1:20128`)
