## 🎨 Kombo (Combos)

Kreirajte kombo ruting modela pomoću 19 javnih strategija: priority, weighted, round-robin, context-relay, fill-first, p2c (power-of-two choices), random, least-used, cost-optimized, reset-aware, reset-window, headroom, strict-random, auto, lkgp (last-known-good-provider), context-optimized, cache-optimized, **fusion** (distribucija na panel modela paralelno, a zatim sinteza jednog odgovora putem sudije), i **pipeline**. Svaki kombo povezuje više modela sa automatskim fallback-om i uključuje brze predloške (templates) i provjere spremnosti.

Nedavna poboljšanja komba:

- **Strukturirani builder komba** — kreirajte svaki korak odabirom provajdera, modela i tačnog naloga/konekcije
- **Podrška za ponovljene provajdere** — ponovo koristite isti provajder više puta u jednom kombu sve dok je `(provider, model, connection)` tuple jedinstven
- **Zdravlje cilja komba (Combo target health)** — analitika i status zdravlja sada razlikuju pojedinačne ciljeve/korake komba umjesto da sve spajaju u stringove modela
- **Redoslijed slojeva kompozita (Composite tier ordering)** — `defaultTier -> fallbackTier` sada utiče na redoslijed izvršavanja/fallback-a u runtime-u za korake komba na najvišem nivou
- **Predlošci sistemskih promptova** — combo `system_message` podržava na serverskoj strani
  `{{MODEL_ID}}`, `{{PROVIDER_ID}}`, `{{ACCOUNT}}` i `{{FINGERPRINT}}`
  placeholder-e, koji se proširuju iz stvarno rutingovanog cilja neposredno prije slanja.
  Dozvoljeni (allowlisted) i ne-rekurzivni; nepoznati placeholder-i ostaju literalni; prazne vrijednosti
  se proširuju u prazno; klijentski sistemski promptovi se nikada ne prepisuju. `{{FINGERPRINT}}`
  se razlučuje samo za besplatne provajdere bazirane na fingerprintu sa fiksiranim ili
  automatski rotiranim fingerprintom — na drugim mjestima se proširuje u prazno (npr.
  konekcije sa jednim fingerprintom, ne-fp provajderi). Proširivanje pokriva standardnu
  petlju slanja (dispatch loop), round-robin i sesije sa fiksiranim context-cache-om;
  fusion, chaos, pipeline i nested-execute strategije još ne proširuju
  placeholder-e.

## 🔗 Context Relay _(v3.5.5+)_

Kombinovana strategija koja čuva kontinuitet sesije kada dođe do rotacije računa usred konverzacije. Prije nego što se aktivni račun isprazni, OmniRoute u pozadini generiše strukturirani sažetak za prebacivanje (handoff summary). Nakon što sljedeći zahtjev bude usmjeren na drugačiji račun, sažetak se ubacuje kao sistemska poruka kako bi novi račun nastavio sa punim kontekstom.

Konfigurabilno putem postavki na nivou kombina ili globalno:

- **Handoff Threshold** — Procenat potrošnje kvote koji pokreće generisanje sažetka (podrazumijevano 85%)
- **Max Messages For Summary** — Koliko nedavne historije treba sažeti
- **Summary Model** — Opcionalni model za zamjenu prilikom generisanja sažetka za prebacivanje

Trenutno podržava rotaciju Codex računa. Pogledajte [Context Relay dokumentaciju](../architecture/ARCHITECTURE.md).

## 🗜️ Prompt Compression _(v3.7.9+)_

Context & Cache sada nudi namenske stranice za Caveman, RTK i Compression Combos:

- **Caveman** — paketi pravila prilagođeni jeziku, pregled, kontrole načina izlaza i analitika
- **RTK** — komandna kompresija za shell, git, test, build, package, Docker, infra, JSON i stack-trace izlaze
- **Compression Combos** — nazvane cijevi (pipelines) kao što je `rtk -> caveman` dodijeljene routing kombosima; podrazumijevana slojevita matematika dostiže prosjek od `~89%` i uštedu podobnog konteksta od `78-95%` kada se primijene oba engine-a
- **Raw-output recovery** — opcionalni redaction RTK sirovih pokazivača izlaza za otklanjanje grešaka kod kompresovanih neuspjeha

Pogledajte [Compression Guide](../compression/COMPRESSION_GUIDE.md), [RTK Compression](../compression/RTK_COMPRESSION.md) i [Compression Engines](../compression/COMPRESSION_ENGINES.md).

## 🛡️ Proxy Hardening _(v3.5.5+)_

Sveobuhvatno enforcement konfiguracije proxy-ja kroz cijeli pipeline zahtjeva:

- **Token Health Check** — Pozadinski OAuth refresh sada rješava proxy konfiguraciju po svakoj konekciji, sprječavajući neuspjehe u okruženjima koja zahtijevaju proxy
- **API Key Validation** — Validacija ključa provajdera (`POST /api/providers/validate`) prolazi kroz `runWithProxyContext`, poštujući postavke proxy-ja na nivou provajdera i globalno
- **undici Dispatcher Fix** — Proxy dispatcheri koriste undici-jevu vlastitu fetch implementaciju umjesto Node-ovog ugrađenog fetch-a, rješavajući `invalid onRequestStart method` greške na Node.js 22
- **Node.js Version Detection** — Stranica za prijavu proaktivno detektuje nekompatibilne Node.js verzije (24+) i prikazuje baner upozorenja sa uputama za korištenje Node 22 LTS

## 🖥️ Desktop aplikacija

Native Electron desktop aplikacija za Windows, macOS i Linux. Pokrenite OmniRoute kao samostalnu aplikaciju sa integracijom u sistemski tray, offline podrškom, automatskim ažuriranjem i instalacijom na jedan klik.

Ključne značajke:

- Polling spremnosti servera (nema praznog ekrana pri hladnom startu)
- System tray sa upravljanjem portovima
- Content Security Policy
- Single-instance lock
- Automatsko ažuriranje prilikom ponovnog pokretanja
- UI uslovljen platformom (macOS traffic lights, Windows/Linux default titlebar)
- Hardened Electron build packaging — symlinked `node_modules` u samostalnom paketu se detektuje i odbija prije pakovanja, sprječavajući runtime zavisnost od build mašine (v2.5.5+)
- **Graceful shutdown** — Electron `before-quit` čisto gasi Next.js, sprječavajući SQLite WAL zaključavanje baze podataka (v3.6.2+)

📖 Pogledajte [`electron/README.md`](../../electron/README.md) za punu dokumentaciju.

## 🌐 V1 WebSocket Bridge _(v3.6.6+)_

OmniRoute sada podržava **OpenAI-kompatibilne WebSocket klijente** putem `/v1/ws` upgrade endpointa. Prilagođeni `scripts/dev/v1-ws-bridge.mjs` server omotava Next.js i nadograđuje WS konekcije u pune sesije dvosmjernog strimovanja. Autentifikacija koristi isti API ključ ili session cookie kao i HTTP zahtjevi.

Ključna ponašanja:

- WS upgrade se validira putem `src/lib/ws/handshake.ts` prije nego što se konekcija uspostavi
- Strimovi se čisto terminiraju pri zatvaranju sesije ili upstream grešci
- Radi istovremeno uz postojeći HTTP+SSE strimovanje put

## 🔑 Sync Tokens & Config Bundle _(v3.6.6+)_

Pristup putem više uređaja i eksternih operatera sada je moguć putem **opsežnih (scoped) sync tokena**:

- **`POST /api/sync/tokens`** — Izdaje novi sync token (opsežan, sa opcionalnim istekom)
- **`DELETE /api/sync/tokens/:id`** — Opoziva token
- **`GET /api/sync/bundle`** — Preuzima verzionalni JSON snapshot svih neosjetljivih postavki (lozinke su sakrivene) sa ETag ključem

Config bundle kreira `src/lib/sync/bundle.ts`. Korisnici upoređuju `ETag` response header kako bi otkrili promjene bez ponovnog preuzimanja cijelog payload-a.

## 🛡️ Safe Outbound Fetch & SSRF Guard _(v3.6.6+)_

Svi pozivi za validaciju providera i otkrivanje modela sada prolaze kroz dvoslojni outbound guard:

1. **URL guard** (`src/shared/network/outboundUrlGuard.ts`) — Blokira privatne/loopback/link-local IP opsege prije nego što se socket otvori.
2. **Safe fetch wrapper** (`src/shared/network/safeOutboundFetch.ts`) — Primjenjuje URL guard, normalizuje timeout-e i ponavlja privremene greške uz exponential backoff.

Kršenja guard-a se pojavljuju kao HTTP 422 (`URL_GUARD_BLOCKED`) i zapisuju se u compliance audit log putem `providerAudit.ts`.

## 🔄 Cooldown-Aware Retries _(v3.6.6+)_

Chat zahtjevi sada **automatski pokušavaju ponovo** (retry) kada upstream provider vrati model-scoped cooldown. Konfigurišljivo putem `REQUEST_RETRY` (default: 2) i `MAX_RETRY_INTERVAL_SEC` (default: 30 s). Učenje rate-limit headera je poboljšano kroz `x-ratelimit-reset-requests`, `x-ratelimit-reset-tokens` i `Retry-After` — stanje cooldown-a po modelu je vidljivo u Resilience dashboardu.
