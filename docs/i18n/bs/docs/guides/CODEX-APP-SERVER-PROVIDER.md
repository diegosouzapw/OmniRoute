# OpenAI Codex — App-Server provajder (`codex-app-server`)

OmniRoute izlaže **dva** načina za korištenje OpenAI Codex-a:

| Provajder              | Kako komunicira sa OpenAI                                                                                                                                                                         | Ograničenje upotrebe                                                   |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| **`codex`**            | Direktno ponavlja vaš ChatGPT/OpenAI OAuth token ka Responses API-ju                                                                                                                              | **Da** — zvanična sesija nije autorizovana za upotrebu proxy-ja/rutera |
| **`codex-app-server`** | Pokreće **sopstveni `codex app-server` od Codex CLI-ja** putem JSON-RPC/WebSocket-a; CLI posjeduje i samostalno osvježava svoj OAuth (`~/.codex/auth.json`) baš kao i interaktivna `codex` sesija | **Ne** — OmniRoute nikada ne ponavlja token ka API-ju                  |

Budući da `codex-app-server` nikada ne ponavlja token, on ne nosi ograničenje upotrebe vezano za ponavljanje sesije (session-replay). Zahtijeva **Codex CLI dostupan na konfigurisanom URL-u aplikacijskog servera**, i taj CLI mora biti **prijavljen**.

---

## 1. Arhitektura

```
┌─ OmniRoute aplikacija ──────────┐        ┌─ codex-app-server sidecar ─────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ token sposobnosti)           │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  samostalno upravlja OpenAI OAuth-om│
└──────────────────────────────────┘        │  (~/.codex/auth.json, auto-osvježavanje) │
        │ dijeli (compose volumene)          └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → WS token sposobnosti (oboje ga montiraju)
  codex-appserver-home    → ~/.codex (auth.json upisuje dashboard,
                             čita ga sidecar-ov codex app-server)
```

- Sidecar osluškuje **samo** na internoj compose mreži (`ws://codex-app-server:1456`) iza tokena sposobnosti. **Nikada** se ne objavljuje na hostu ili internetu.
- Codex CLI je ugrađen u `omniroute:base`, tako da nije potrebna instalacija codex-a na hostu ili korisničkoj mašini kada pokrećete sidecar.

## 2. Pokretanje

```bash
# Pokrenite stack SA profilom codex app-server sidecar-a:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

Sidecar kreira svoj WS token sposobnosti pri prvom pokretanju (u dijeljeni `codex-appserver-token` volumen), a aplikacija čita isti token putem `OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE`. Nije potrebno ručno povezivanje tokena.

## 3. Povezivanje + prijava

1. Na dashboard-u dodajte konekciju za **OpenAI Codex (App-Server)**. Nije potreban API ključ ili token (to je provajder bez autentifikacije — sidecar posjeduje autentifikaciju).
2. Ako Codex CLI sidecar-a **još nije prijavljen**, provjera zdravlja konekcije prijavljuje _"running but not signed in"_ (nije crvena greška autentifikacije). Koristite **Sign in with ChatGPT**: ovo pokreće standardni Codex device-OAuth u vašem pretraživaču, a zatim upisuje `~/.codex/auth.json` u dijeljeni volumen putem **Apply auth** (ista prijava služi i za `codex` i za `codex-app-server` provajdere).
3. Jednom kada se prijavite, provjera zdravlja postaje zelena (verifikuje i `/readyz` **i** `account/read` — tj. pokrenut _i_ autentifikovan) i počinje sa radom.

Dashboard nikada ne prepisuje zdrav postojeći `~/.codex/auth.json` — upisuje samo kada datoteka nedostaje ili je njen token zastario (uvijek se pravi sigurnosna kopija).

## 4. Scenariji implementacije

- **Operator sa već autentifikovanim Codex CLI-jem** — montirajte vaš host `~/.codex` u sidecar (`codex-appserver-home`) i preskočite korak prijave.
- **Javni korisnik, codex nije instaliran lokalno** — irelevantno: sidecar ima CLI. Korisnik se autentifikuje samo putem dashboard-a.
- **Bare-metal OmniRoute (bez sidecar-a, host codex)** — usmjerite `OMNIROUTE_CODEX_APPSERVER_WS` na vaš sopstveni `codex app-server` i osigurajte da je host codex prijavljen; napomena "codex not installed" se pojavljuje ako binarni fajl nedostaje.

## 5. Rezidencijalni / UDP izlaz (operator dodatak, nije isporučen)

Generički sidecar iznad izlazi preko normalne mreže kontejnera. Operator koji treba da Codex saobraćaj izlazi preko **rezidencijalnog izlaza** (npr. TUN tailscale sidecar koji nosi TCP + UDP/QUIC) pokreće to kao zasebno compose nadjačavanje (override); to namjerno **nije** dio isporučenog `codex-app-server` profila. Pogledajte interni operativni priručnik (runbook) za to podešavanje.
