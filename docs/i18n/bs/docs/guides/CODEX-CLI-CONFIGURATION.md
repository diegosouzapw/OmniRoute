# Codex CLI — Konfiguracija sa OmniRoute

Kompletan vodič za korištenje Codex CLI usmjerenog na OmniRoute kao OpenAI-kompatibilni backend.

---

> **TOML je jedini efektivni format.** Moderni Codex čita isključivo `~/.codex/config.toml` (verifikovano u odnosu na codex-cli 0.147.0: `codex --help` dokumentuje da `-c/--config` nadjačava "učitano iz `~/.codex/config.toml`"). Stari `~/.codex/config.yaml` pripadao je naslijeđenom npm CLI-u i tiho se ignoriše. Generator kontrolne table (`/api/cli-tools/apply`, alat `codex`) piše TOML uz konzervativno spajanje — postojeći ključevi i blokovi drugih provajdera se čuvaju, API ključ ostaje u `OMNIROUTE_API_KEY` (nikada u datoteci), a zaostali naslijeđeni `config.yaml` se prijavljuje kao napomena o migraciji bez ikakvih izmjena.

## config.toml spreman za kopiranje

Zamijenite `<YOUR_HOST>` i `<YOUR_KEY>` vašim vrijednostima:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # ograničenje pohrane historije po pozivu alata

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc ili ~/.zshrc — stvarna vrijednost ključa, nikada u config.toml
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: Codex upakovan unutar ChatGPT aplikacije

Ako ste instalirali Codex putem ChatGPT desktop aplikacije, `codex` binarna datoteka možda postoji samo unutar paketa aplikacije i još uvijek nije na vašoj `PATH` putanji ljuske (shell). Dodajte direktorij resursa u datoteku za pokretanje vaše ljuske:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

Otvorite novu ljusku, a zatim provjerite:

```bash
command -v codex
codex --version
```

### Lokalni OmniRoute bez autentifikacije: placeholder ključ je dovoljan

Codex potvrđuje da varijabla okruženja imenovana sa `env_key` postoji **prije** nego što prvi zahtjev napusti CLI. Ako vaša **lokalna** OmniRoute instanca ne zahtijeva autentifikaciju, bilo koji placeholder koji nije prazan će raditi:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

Koristite pravi ključ umjesto toga kada je vaš OmniRoute server zaštićen ili udaljen.

> **Uobičajene opcije hosta**
>
> | Pristup       | URL                           |
> | ------------- | ----------------------------- |
> | Lokalna mreža | `http://192.168.0.1:20128/v1` |
> | Tailscale     | `http://100.x.x.x:20128/v1`   |
> | Loopback      | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — zašto radi za sve modele

Codex CLI je ukinuo `wire_api = "chat"` (Chat Completions) u februaru 2026. i sada **zahtijeva** `wire_api = "responses"` (OpenAI Responses API). Postavljanje `wire_api = "chat"` uzrokuje trenutni pad pri pokretanju od verzije v0.138.

Mnogi provajderi, uključujući GLM i Kimi, i dalje izlažu samo Chat Completions krajnju tačku (endpoint). DeepSeek V4 sada izlaže izvorni Responses API kao i Anthropic-kompatibilnu krajnju tačku; OmniRoute koristi Responses po defaultu i omogućava svakoj DeepSeek konekciji da odabere Anthropic kompatibilnost.

**OmniRoute ovo rješava transparentno:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute bira izvorni protokol provajdera i prevodi kada je potrebno
    → POST /responses (DeepSeek V4) ili /chat/completions (Mistral / GLM / Kimi / others)
```

Nikada vam nije potreban poseban prevodilački proxy kada koristite OmniRoute. **Svi modeli koriste `wire_api = "responses"`** — OmniRoute rješava ostalo.

> **`wire_api` je default** — polje je po defaultu `"responses"` i može se u potpunosti izostaviti iz `config.toml`. Postavljajte ga eksplicitno samo ako dokumentujete namjeru.

## Kontekstni prozor i sažimanje

### Polja za konfiguraciju tokena

| Polje                            | Opis                                                                                                                                                                                           |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model_context_window`           | Ukupni budžet tokena za aktivni model. Postavite na reklamirano ograničenje modela.                                                                                                            |
| `model_auto_compact_token_limit` | Prag koji pokreće automatsko sažimanje historije. **Maksimum: 90% od `model_context_window`** — vrijednosti iznad 90% se tiho zanemaruju.                                                      |
| `tool_output_token_limit`        | Ograničenje tokena pohranjenih po izlazu poziva alata u historiji. Sprječava da jedan veliki odgovor alata popuni prozor. **Ovo nije maksimalni izlaz** — to je ograničenje pohrane historije. |
| `compact_prompt`                 | Umetnuto nadjačavanje za sistemski upit koji se koristi tokom sažimanja (v0.138+).                                                                                                             |

> **Napomena o `model_max_output_tokens`**: Ovo polje **nije dio Codex CLI konfiguracijske sheme** (odsutno iz Codex Rust baze koda). Ako je postavljeno, tiho se zanemaruje. Nemojte se oslanjati na njega — koristite `tool_output_token_limit` za kontrolu količine izlaza alata pohranjenog u historiji.

## Napor rezonovanja

Kontroliše koliko model "razmišlja" pre odgovora.

| Vrijednost | Koristite za                                         |
| ---------- | ---------------------------------------------------- |
| `none`     | Bez rezonovanja — direktan odgovor                   |
| `low`      | Trivijalni zadaci (preimenovanje, formatiranje)      |
| `medium`   | **Podrazumevano na serveru** kada nije navedeno      |
| `high`     | Srednje složeni zadaci (refaktorisanje, debagovanje) |
| `xhigh`    | Arhitektura, dubinska analiza, složeni problemi      |

```bash
# Nadjačavanje po pozivu
codex -c model_reasoning_effort=low "rename variable x to count"
codex -c model_reasoning_effort=xhigh "design the auth module"
```

Takođe podesite **sažetak** rezonovanja kako bi Desktop mogao da renderuje tekst razmišljanja (a ne samo šifrovane blokove):

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # ili ultra kada je podržano
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### OmniRoute budžet za razmišljanje (podešavanje servera)

Na OmniRoute hostu, **Settings → AI → Thinking Budget** mora biti **`passthrough`** da bi Codex napor/sažetak stigli do upstream-a. Režim **`auto` uklanja** sva klijentska polja `reasoning` / `reasoning_effort` i isprazniće panele za razmišljanje čak i kada je Codex ispravno konfigurisan.

Kompletan vodič: [THINKING_BUDGET.md](./THINKING_BUDGET.md).

Kompresija i keširanje promptova su nezavisni i nastavljaju da rade pod `passthrough` režimom.

## Profili — imenovane konfiguracije po modelu/radnom toku

Profili vam omogućavaju da promenite model + kontekstualni prozor pomoću jedne zastavice. Svaki profil je ravan `~/.codex/<name>.config.toml` fajl koji se postavlja preko osnovnog `config.toml` fajla.

> **Pravilo imenovanja (Codex CLI v0.137+):** fajl mora biti `~/.codex/<name>.config.toml` — **bez `profile-` prefiksa**.
> CLI razrešava `-p kimi-k27` → `~/.codex/kimi-k27.config.toml`. Ako fajl nije pronađen, podrazumevana vrednost se primenjuje nečujno.

```bash
codex --profile kimi-k27 "analyze 10k lines of this codebase"
codex -p glm52 "architecture review"
codex --profile deepseek-flash "rename variable"   # brzo, jeftino
```

### Profili napora (isti model, različit napor)

```bash
codex -p low      # cx/gpt-5.5, effort=low
codex -p medium   # cx/gpt-5.5, effort=medium
codex -p high     # cx/gpt-5.5, effort=high
codex -p xhigh    # cx/gpt-5.5, effort=xhigh (podrazumevano)
codex -p chat     # cx/gpt-5.5, napor nije postavljen (podrazumevano na serveru)
```

## Automatsko generisanje profila pomoću `omniroute setup-codex`

Ako pokrećete OmniRoute na VPS-u, možete automatski generisati datoteke profila iz kataloga modela uživo:

```bash
# Sa VPS-a (koristi lokalni OmniRoute na portu 20128)
omniroute setup-codex

# Sa bilo koje mašine — usmjerite na svoj VPS
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# Pregled bez upisivanja datoteka
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# Generiši samo GLM i Kimi profile
omniroute setup-codex --only glm,kimi

# Upisivanje u prilagođeni direktorijum
omniroute setup-codex --codex-home /path/to/.codex
```

Komanda preuzima `/v1/models`, koristi podešene profile za poznate modele, vraća se na metapodatke kataloga za druge kompatibilne tekstualne modele i upisuje `~/.codex/<name>.config.toml` za svaki. Idempotentna — sigurna za ponovno pokretanje.

OmniRoute takođe može **automatski sinhronizovati** ove iste datoteke profila nakon što uspješno otkrivanje/uvoz modela provajdera promijeni katalog uživo. Ovo je **opciona funkcija i podrazumijevano je isključena**: uključite je sa **CLI Code kontrolne table** ("CLI profile auto-sync" → Codex), ili postavite `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` (takođe poštuje `CLI_ALLOW_CONFIG_WRITES`, što je podrazumijevano uključeno). Kada je omogućeno, samo upisuje zasebne `~/.codex/*.config.toml` datoteke profila; nikada ne mijenja aktivni/podrazumijevani `~/.codex/config.toml`, Codex-lb postavke, autentifikaciju ili izbor provajdera.

```bash
# Pokreni codex sa omniroute provajderom umetnutim putem -c zastavica (konfiguracija nije upisana)
omniroute run codex
```

## Dugotrajni zadaci

Dvije OmniRoute zadane postavke mogu tiho sabotirati višesatne Codex CLI sesije. Nijedna nije postavka Codex CLI-a — obje se nalaze na strani OmniRoute-a. Korisnici koji migriraju konfiguraciju sa uzvodnih (upstream) proxyja koji fiksiraju račune i onemogućavaju prekide zbog neaktivnosti često naiđu na oba problema i zaključe da OmniRoute „ne može održati dugu sesiju“.

| Simptom                                                                         | Vjerovatan uzrok                                                                            | Kontrola                 |
| ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- | ------------------------ |
| Sesija stalno mijenja račune / kontinuitet prompt-cache-a se gubi između poteza | TTL afiniteta sesije je `0` (onemogućeno)                                                   | `sessionAffinityTtlMs`   |
| Konekcija se prekida usred rezonovanja bez prompta okrenutog klijentu           | Watchdog za neaktivnost streama se aktivirao nakon 10 minuta bez uzvodnog (upstream) dijela | `STREAM_IDLE_TIMEOUT_MS` |

Povezane diskusije: [#7126](https://github.com/diegosouzapw/OmniRoute/discussions/7126) (prekidi dugih zadataka), [#5718](https://github.com/diegosouzapw/OmniRoute/discussions/5718) (zašto je afinitet po defaultu isključen). Praćenje: [#7287](https://github.com/diegosouzapw/OmniRoute/issues/7287).

### 1. Afinitet sesije — fiksirajte jedan razgovor za jedan račun

**Zadano:** `sessionAffinityTtlMs = 0` (onemogućeno).

**Gdje podesiti**

- Dashboard → **Postavke (Settings)** → **Rutiranje (Routing)** → **Afinitet sesije (Session affinity)** → **TTL afiniteta (sekunde)** (`ComboDefaultsTab`)
- Ili PATCH postavke sa `sessionAffinityTtlMs` u **milisekundama** (Zod opseg `0`–`86_400_000`, tj. do 24 sata)

> Preimenovano u #7274 iz Codex-only `codexSessionAffinityTtlMs`. Stari ključ je i dalje prihvaćen kao alias samo za čitanje; nove konfiguracije trebaju koristiti `sessionAffinityTtlMs`. Afinitet se sada primjenjuje na **bilo kojeg** provajdera kada je TTL iznad `0`, ne samo na Codex — pogledajte [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → Session affinity.

**Šta se kvari kada ostane na 0**

Svaki potez Codex razgovora sa više poteza se rutira nezavisno od strane aktivne combo strategije i može završiti na **drugom računu po potezu**. To prekida kontinuitet uzvodne (upstream) sesije / prompt-cache-a. OmniRoute konsultuje Codex zaglavlja sesije (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) i polja tijela kao što su `prompt_cache_key` / `session_id` samo kada je TTL veći od `0` (`extractSessionAffinityKey` u `src/sse/services/auth.ts`).

**Preporučeno za višesatni pojedinačni zadatak**

Postavite TTL **iznad očekivanog trajanja zadatka u realnom vremenu** (UI maksimum je **86400 sekundi** = 24 sata):

| Očekivano trajanje zadatka | TTL afiniteta (UI, sekunde) | `sessionAffinityTtlMs` |
| -------------------------- | --------------------------- | ---------------------- |
| Nekoliko sati              | `14400` (4h)                | `14400000`             |
| Preko noći / ~12h          | `43200` (12h)               | `43200000`             |
| Cijeli dan                 | `86400` (24h, maksimum)     | `86400000`             |

Opt-in je namjeran: onemogućavanje afiniteta favorizuje balansiranje opterećenja između računa; omogućavanje favorizuje kontinuitet za jednu dugu agentsku sesiju. Ovaj vodič **ne** mijenja zadane postavke — operateri koji pokreću duge Codex zadatke moraju se sami prijaviti (opt-in).

### 2. Timeout neaktivnosti streama — ne prekidajte tihe poteze rezonovanja

**Zadano:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 minuta). Nasljeđuje se od `REQUEST_TIMEOUT_MS` kada nije postavljeno; zajednička osnova je također 600000. Pogledajte [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → Timeouts.

**Šta se prekida pri zadanim postavkama**

Codex ciklus zaključivanja / alata koji ostaje neaktivan duže od 10 minuta bez **stvarnog uzvodnog (upstream) dijela (chunk)** biva prisilno zatvoren od strane SSE watchdog-a za neaktivnost (`open-sse/utils/stream.ts`). Klijent često vidi jednostavan prekid veze — što odgovara opisu „zaustavljeno automatski bez ikakve obavijesti.”

Kritičan detalj: OmniRoute-ov sintetički SSE **heartbeat ne resetuje** tajmer neaktivnosti (idle clock). Samo stvarni uzvodni dio tijela (upstream body chunk) ažurira `lastChunkTime`. Model koji je tih, a još uvijek „razmišlja”, izgleda identično kao zastoj uzvodno (stalled upstream) iz perspektive watchdog-a.

Povezana Undici neaktivnost tijela: `FETCH_BODY_TIMEOUT_MS` (također ima istu zadanu vrijednost od 10 minuta; `0` je onemogućava). Za streaming, `FETCH_TIMEOUT_MS` pokriva samo uspostavljanje veze / prva zaglavlja — kada je stream aktivan, zastoji su regulisani sa `STREAM_IDLE_TIMEOUT_MS` i `FETCH_BODY_TIMEOUT_MS`.

**Preporučeno za višesatni pojedinačni zadatak**

U okruženju OmniRoute procesa (`.env` / compose / systemd):

```bash
# Onemogućite prekide zbog neaktivnosti streama + neaktivnosti tijela za duge cikluse zaključivanja
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

Ili ih povećajte iznad najdužeg perioda tišine koji očekujete (vrijednosti su u milisekundama):

```bash
# Primjer: dozvolite do 2 sata tišine između uzvodnih dijelova (upstream chunks)
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

Ponovo pokrenite OmniRoute nakon promjene ovih varijabli okruženja.

### Konkretan recept — višesatni Codex zadatak

1. **Fiksirajte račun (Pin the account):** Dashboard → Settings → Routing → Session affinity → Affinity TTL = `43200` (12h) ili `86400` (maksimalno 24h).
2. **Povećajte / onemogućite prekide zbog neaktivnosti** u OmniRoute okruženju:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. Zadržite uobičajeni Codex `config.toml` (`wire_api = "responses"`, ispravan `base_url`, `OMNIROUTE_API_KEY`) — ne postoje Codex-strani parametri za afinitet/neaktivnost za ova dva ponašanja.
4. Ponovo pokrenite OmniRoute, a zatim započnite dugi Codex zadatak.

### Odluka o zadanim postavkama (#7287)

| Parametar                | Zadana vrijednost | Promjena u ovom vodiču?                                                                                  |
| ------------------------ | ----------------- | -------------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (isključeno)  | **Ne** — ostaje opcionalno (balansiranje opterećenja naspram kontinuiteta; pogledajte Diskusiju #5718)   |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 min) | **Ne** — ostaje 10 minuta za opći promet; operateri dugih Codex zadataka ga povećavaju ili onemogućavaju |

Globalna promjena bilo koje zadane vrijednosti promijenila bi ponašanje za svakog klijenta instance, ne samo za Codex. Dokumentirajte parametre; ostavite zadane vrijednosti kakve jesu dok operater eksplicitno ne odluči drugačije.

### Dijagnosticiranje prekida zbog neaktivnosti

Kada se aktivira watchdog za neaktivnost, OmniRoute bilježi liniju oblika:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

Pretražite (grep) za `Idle timeout: no data from` (ili kod `stream_idle_timeout` / naziv greške `StreamIdleTimeoutError`). Segment provajdera je ono što je OmniRoute koristio za taj zahtjev (`codex`, ID drugog provajdera, ili `provider` ako je nepoznat) — to nije uvijek doslovni string `codex`.

## Rješavanje problema

**`Greška: wire_api = "chat" više nije podržan`**
Uklonite `wire_api = "chat"` iz svoje konfiguracije. Postavite `wire_api = "responses"` ili izostavite polje (podrazumijeva `"responses"` od v0.138).

**`Greška: model nije pronađen`**
Provjerite postoji li model u OmniRoute-u s ispravnim prefiksom. Koristite `omniroute models list` ili otvorite `/dashboard/providers/<provider>`.

**`Greška pri autentifikaciji`**
Potvrdite da je `OMNIROUTE_API_KEY` eksportovan: `echo $OMNIROUTE_API_KEY`.

**`GREŠKA: Nedostaje varijabla okruženja: OMNIROUTE_API_KEY`**
Codex provjerava da li env var postoji prije slanja prvog zahtjeva. Eksportujte pravi ključ za zaštićene servere, ili placeholder koji nije prazan, kao što je `OMNIROUTE_API_KEY=local` kada vaša **lokalna** OmniRoute instanca ne zahtijeva autentifikaciju. Ponovo pokrenite shell ako ste ga dodali u `~/.bashrc` ili `~/.zshrc`.

**`Konekcija odbijena`**
Provjerite da li OmniRoute radi i da li su host/port za `base_url` ispravni za vašu mrežu (lokalna vs Tailscale vs VPS).

**Rušenje sesije blizu ograničenja konteksta**
Eksplicitno postavite `model_context_window` i `model_auto_compact_token_limit`. Pogledajte tabelu prozora konteksta iznad.

**Kompakcija se pokreće prekasno**
Smanjite `model_auto_compact_token_limit` na 80–85% prozora. Nikada ne postavljajte iznad 90%.

**Profil se ne učitava (`-p <name>` se tiho ignoriše)**
Potvrdite da datoteka postoji na `~/.codex/<name>.config.toml` (bez `profile-` prefiksa). Pokrenite `ls ~/.codex/*.config.toml`.

**Dugotrajni Codex zadatak se prekida usred izvršavanja / mijenja račune između poteza**
Pogledajte [Dugotrajni zadaci](#long-running-tasks). Omogućite afinitet sesije (TTL iznad dužine zadatka) i povećajte ili onemogućite `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS`. Pretražite (grep) OmniRoute logove za `Idle timeout: no data from`.
