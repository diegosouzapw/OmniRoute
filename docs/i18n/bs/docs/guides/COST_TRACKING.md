# Praćenje troškova i potrošnje

Kako OmniRoute procjenjuje, bilježi i izvještava o trošku svakog zahtjeva — i zašto je broj na kontrolnoj ploči **praćenje ušteda**, a ne račun.

Pogledajte također: [Korisnički vodič](./USER_GUIDE.md) · [Galerija funkcija](./FEATURES.md)

---

## Šta je to (a šta nije)

OmniRoute pripisuje USD trošak po zahtjevu svakom završetku (completion) množenjem broja tokena sa cijenama modela. Ovi brojevi pokreću kontrolnu ploču **Troškovi**, CLI komande `omniroute cost` / `omniroute usage`, CSV/JSON izvoze i budžete po API ključu.

> **"Trošak" na kontrolnoj ploči je praćenje ušteda, a ne račun.** OmniRoute vam nikada ne naplaćuje — on usmjerava vaše zahtjeve provajderima koje ste već povezali (vaše vlastite pretplate, besplatne nivoe i API ključeve). "Ukupan trošak od $290" akumuliran u potpunosti na besplatnim modelima znači otprilike **$290 koje niste platili** plaćenom API-ju. Ova brojka je _procjena_ onoga što bi isti saobraćaj koštao po standardnim cijenama sa liste, tako da možete vidjeti gdje je vaša upotreba koncentrisana i koliko vam usmjeravanje na jeftinije/besplatne provajdere štedi novac.

Ovo uokvirivanje je direktno navedeno u [README](../../README.md) projekta ("trošak na kontrolnoj ploči je praćenje ušteda, a ne račun").

Budući da je broj procjena:

- Zavisi od tabele cijena koju OmniRoute ima za svaki model. Model bez unosa cijene doprinosi `0` trošku (prikazuje se kao red "Legacy / Free" u istraživaču).
- Saobraćaj na besplatnom nivou i pretplati i dalje akumulira _procijenjeni_ trošak — to je iznos koji štedite, a ne iznos koji dugujete.

## Kako se procjenjuju troškovi

### Izvor cijena

Troškovi dolaze iz tabele cijena koja se rješava ovim redoslijedom prioriteta ([`src/lib/pricingSync.ts`](../../src/lib/pricingSync.ts)):

1. **Korisnička nadjačavanja (overrides)** — cijene koje postavite na kontrolnoj ploči / putem `PATCH /api/pricing`.
2. **Sinhronizovane vanjske cijene** — preuzete iz javnog `model_prices_and_context_window.json` datoteke LiteLLM-a kada je sinhronizacija omogućena (pohranjeno u zasebnom `pricing_synced` imenskom prostoru tako da nikada ne prebriše vaša nadjačavanja).
3. **Hardkodirane zadane vrijednosti** — isporučene uz OmniRoute.

Sinhronizacija vanjskih cijena je **opcionalna (opt-in)**, onemogućena po zadanim postavkama. Relevantne env varijable (pogledajte [`.env.example`](../../.env.example)):

| Env var                 | Default   | Purpose                                                              |
| ----------------------- | --------- | -------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`   | Omogućite pozadinsku sinhronizaciju cijena LiteLLM-a pri pokretanju. |
| `PRICING_SYNC_INTERVAL` | `86400`   | Interval sinhronizacije u **sekundama** (zadano dnevno).             |
| `PRICING_SYNC_SOURCES`  | `litellm` | Lista izvora odvojena zarezima (danas je podržan samo `litellm`).    |

### Formula troškova

Trošak se izračunava po zahtjevu iz broja tokena i stopa po milion tokena u [`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) (`computeCostFromPricing` / `calculateCost`):

- **Ulazni tokeni** (minus čitanja iz keša i tokeni za kreiranje keša) × `input` stopa.
- **Tokeni čitanja iz keša** × `cached` stopa (vraća se na ulaznu stopu ako nije dostupna).
- **Tokeni za kreiranje keša** × `cache_creation` stopa (vraća se na ulaznu stopu ako nije dostupna).
- **Izlazni tokeni** × `output` stopa.
- **Tokeni zaključivanja (reasoning)** × `reasoning` stopa (vraća se na izlaznu stopu ako nije dostupna).

Sve stope se tumače kao USD po 1.000.000 tokena. Codex "fast"/"priority" ili "flex" nivo usluge primjenjuje množitelj troškova (`getCodexFastCostMultiplier`) — npr. flex se naplaćuje uz popust od 50% na tokene, što se prikazuje kao **flex uštede** na kontrolnoj ploči.

Imena modela se prvo normalizuju (prefiksi putanje provajdera kao što su `openai/` ili `accounts/fireworks/models/` se uklanjaju) tako da se historijski redovi i dalje podudaraju sa cijenom.

### Kako se bilježi potrošnja

- Trošak po zahtjevu se izračunava nakon odgovora i bilježi metodom "fire-and-forget" (pusti i zaboravi) tako da nikada ne dodaje latenciju klijentu. Potrošnja zajedničke kvote se zakazuje na sljedećem otkucaju petlje događaja (event-loop tick) putem [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts).
- Potrošnja API ključa se baferuje i ispire (flush) u serijama od strane [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (zadano 60s interval ispiranja, bafer od 1.000 unosa). Podesivo putem:

  | Env var                             | Default | Purpose                                            |
  | ----------------------------------- | ------- | -------------------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000` | Interval ispiranja u milisekundama.                |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`  | Maksimalni broj baferovanih unosa prije ispiranja. |

Podaci o troškovima na kontrolnoj ploči se **ne** čitaju iz pohranjenog dolarskog iznosa po redu — oni se ponovo izračunavaju u hodu iz broja tokena i trenutne tabele cijena svaki put kada se pokrene analitički krajnja tačka (endpoint). To znači da ispravljanje pogrešne cijene (i ponovna sinhronizacija) retroaktivno ažurira historijske procjene troškova.

## Kontrolna tabla: stranica Troškovi

Stranica **Troškovi** (Costs) se nalazi na `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`).
Njen glavni prikaz je kartica **Pregled troškova** (Cost Overview)
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`),
koja učitava sve iz `GET /api/usage/analytics`.

Šta prikazuje:

- **Pločice potrošnje** — procijenjena potrošnja za _Danas (1d)_, _7d_, _30d_ i odabrani
  period. Birač raspona: `7d`, `30d`, `90d`, `all`.
- **Glavne metrike** — zahtjevi u periodu, aktivni provajderi, aktivni modeli, prosječni
  trošak po zahtjevu.
- **Istraživač troškova** (Cost Explorer) — tabela koja se može sortirati/filtrirati, grupisana po **provajderu**, **modelu**,
  **API ključu**, **nalogu** ili **nivou usluge**, sa troškovima, zahtjevima, tokenima, prosječnim
  troškom po zahtjevu i udjelom u ukupnom iznosu u %.
- **Upotreba tokena** — ukupni / ulazni / izlazni tokeni i odnos ulaz:izlaz.
- **Efikasnost rutiranja** — broj rezervnih opcija (fallback), stopa rezervnih opcija i pokrivenost traženih modela.
- **Mjesečna prognoza** — projektuje potrošnju na kraju mjeseca na osnovu nedavnog dnevnog prosjeka.
- **Poređenje perioda** — % promjene između prve i druge polovine perioda.
- **Grafikoni** — dnevni trend troškova, udio provajdera (kružni), top provajderi, top modeli, troškovi
  po API ključu, troškovi po nalogu, obrazac sedmične upotrebe i toplotna mapa aktivnosti.
- **Izvoz** — preuzimanje trenutnog perioda kao **CSV** ili **JSON** (dugmad se pojavljuju
  kada postoje podaci o troškovima koji nisu nula).

Kada nema naplativog saobraćaja, redovi se prikazuju kao oznaka "Legacy / Free" umjesto `$0`,
što odražava model praćenja ušteda.

### Povezane podstranice Troškova

Oblast Troškovi takođe sadrži (sve pod `/dashboard/costs/`):

- **Cijene** (Pricing) (`/dashboard/costs/pricing`) — pregled i nadjačavanje cijena po modelu (renderuje
  dijeljenu karticu Cijene).
- **Budžet** (Budget) (`/dashboard/costs/budget`) — postavljanje ograničenja potrošnje po opsegu (renderuje
  dijeljenu karticu Budžet).
- **Dijeljenje kvota** (Quota Share) (`/dashboard/costs/quota-share`) — bazeni dijeljenih kvota i prikazi
  stope potrošnje.

## API krajnje tačke

Sve ove zahtijevaju upravljačku autorizaciju (loopback/JWT, putem `requireManagementAuth`) osim
ako nije drugačije naznačeno.

### Analitika upotrebe i troškova

| Metoda | Krajnja tačka            | Svrha                                                                                                                                                                    |
| ------ | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET`  | `/api/usage/analytics`   | Potpuna analitika troškova/upotrebe: sažetak, dnevni trend, po provajderu/modelu/API ključu/nalogu/nivou. Upit: `range`, `startDate`, `endDate`, `apiKeyIds`, `presets`. |
| `GET`  | `/api/usage/utilization` | Iskorištenost kvota po provajderu tokom vremena. Upit: `range` (`1h`/`24h`/`7d`/`30d`), `provider`.                                                                      |
| `GET`  | `/api/usage/history`     | Sirovi redovi istorije upotrebe.                                                                                                                                         |
| `GET`  | `/api/usage/call-logs`   | Dnevnici poziva po zahtjevu (model, tokeni, trošak, latencija, status).                                                                                                  |
| `GET`  | `/api/usage/quota`       | Status kvote provajdera.                                                                                                                                                 |
| `GET`  | `/api/usage/proxy-logs`  | Dnevnici proxy zahtjeva.                                                                                                                                                 |

### Budžeti

| Metoda | Krajnja tačka            | Svrha                                                                                         |
| ------ | ------------------------ | --------------------------------------------------------------------------------------------- |
| `GET`  | `/api/usage/budget`      | Sažetak troškova + provjera budžeta za jedan API ključ (`apiKeyId` parametar upita potreban). |
| `POST` | `/api/usage/budget`      | Postavljanje dnevnih/sedmičnih/mjesečnih USD ograničenja + prag upozorenja za API ključ.      |
| `GET`  | `/api/usage/budget/bulk` | Masovni sažeci budžeta za više API ključeva.                                                  |

> API za budžet je ograničen na **API ključ** (`apiKeyId`). Ograničenja koja vraća
> `GET /api/usage/budget` uključuju `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`,
> `warningThreshold` i tekuće zbirove (`totalCostToday`, `totalCostMonth`, …).

### Cijene

| Metoda   | Krajnja tačka           | Svrha                                                                                                                       |
| -------- | ----------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/pricing`          | Trenutne objedinjene cijene (korisničke + sinhronizovane + podrazumijevane). `?includeSources=1` za prikaz izvora po unosu. |
| `PATCH`  | `/api/pricing`          | Nadjačavanje cijena za `{ provider: { model: { input, output, cached, … } } }`.                                             |
| `DELETE` | `/api/pricing`          | Resetovanje cijena na podrazumijevane (opciono ograničeno sa `?provider=&model=`).                                          |
| `GET`    | `/api/pricing/defaults` | Prikaz podrazumijevanih stopa rezervnih opcija na 1M.                                                                       |
| `GET`    | `/api/pricing/models`   | Cijene ključirane po modelu.                                                                                                |
| `POST`   | `/api/pricing/sync`     | Pokretanje ručne sinhronizacije iz vanjskih izvora (LiteLLM).                                                               |
| `GET`    | `/api/pricing/sync`     | Trenutni status sinhronizacije.                                                                                             |
| `DELETE` | `/api/pricing/sync`     | Brisanje svih sinhronizovanih podataka o cijenama.                                                                          |

### Ostale krajnje tačke relevantne za troškove

| Metoda | Endpoint                      | Svrha                                                                                       |
| ------ | ----------------------------- | ------------------------------------------------------------------------------------------- |
| `GET`  | `/api/free-tier/summary`      | Ukupni broj tokena besplatnog modela, iskorišteno ovog mjeseca i preostala besplatna kvota. |
| `GET`  | `/api/quota/pools/[id]/usage` | Korištenje za bazen zajedničke kvote.                                                       |

## CLI

CLI alata OmniRoute izlaže komande za troškove (cost), upotrebu (usage) i cijene (pricing) (registrovane u [`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)).

### `omniroute cost`

Izvještaj o troškovima agregiran iz `/api/usage/analytics`.

```bash
omniroute cost                          # zadnjih 30 dana, grupisano po provajderu
omniroute cost --period 7d              # zadnjih 7 dana
omniroute cost --group-by model         # grupiši po provajderu | modelu | kombinaciji | api-ključu | danu
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

Kolone: grupa, zahtjevi, tokeni ulaz/izlaz, trošak (USD) i % od ukupnog. Linija sa ukupnim zbirom se štampa na kraju (može se potisnuti sa `--quiet` ili `--output json`).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # sažetak troškova po provajderu
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# Budžeti
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` čita `GET /api/pricing/defaults`. Da biste umjesto toga uredili cijene pojedinačnih modela, koristite stranicu **Pricing** na kontrolnoj tabli ili `PATCH /api/pricing`.

## Rješavanje problema

- **Svi troškovi prikazuju $0 / "Legacy / Free".** Modeli koji se koriste nemaju unos cijene.
  Omogućite eksternu sinhronizaciju (`PRICING_SYNC_ENABLED=true`) i pokrenite `omniroute pricing sync`, ili
  ručno postavite cijene putem stranice Pricing / `PATCH /api/pricing`.
- **Historijski model ima pogrešnu cijenu.** Ispravite cijenu (prepišite ili ponovo sinhronizujte) — trošak se
  ponovo izračunava iz broja tokena pri svakom čitanju analitike, tako da se procjene ažuriraju retroaktivno.
- **Potrošnja kasni u odnosu na realno vrijeme.** Potrošnja po ključu se grupira (batch); smanjite
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` ako su vam potrebni svježiji podaci.
