# Zlatna staza doprinosa

Koristite ovaj vodič za odabir najmanje pouzdane razvojne petlje za pull request. Ovaj vodič ne zamjenjuje dokumente o arhitekturi i sigurnosti specifične za određena područja koji su povezani u nastavku; on povezuje svaku uobičajenu vrstu promjene s njenim ugovorima, fokusiranim provjerama i CI pokrivenošću.

## Putanja koju svaka promjena prati

1. **Odaberite osnovu prije uređivanja.** Pronađite najvišu aktivnu `release/v*` granu i kreirajte granu od njenog vrha. Ciljajte tu granu, a ne `main`. Ako je aktivno zamrzavanje izdanja (release freeze), nemojte ciljati zamrznutu granu; koristite sljedeći aktivni ciklus opisan u [Branching & Release Model](BRANCHING_MODEL.md).
2. **Imenujte ugovore.** Identificirajte svaki katalog, shemu, generirani artefakt, javni API ili korisničko sučelje na koje promjena utječe. Donja tablica daje minimalni početni skup.
3. **Napišite ili ažurirajte fokusirane testove.** Produkcijske promjene u `src/`, `open-sse/`, `electron/` ili `bin/` zahtijevaju automatizirani test u istom PR-u. Pokrenite najmanje testne datoteke koje dokazuju ponašanje, a zatim navedene fokusirane provjere.
4. **Pustite CI da pokrene široku matricu.** Kompletni unit shardovi, Vitest, coverage ratchet i produkcijska verzija (build) pokreću se na PR-u. Pokrenite široki paket (suite) lokalno samo kada fokusirani neuspjeh ukazuje na širi utjecaj ili kada promjena obuhvaća nekoliko podsustava.
5. **Uskladite prije pregleda.** Dohvatite aktivnu osnovu, pregledajte njene nove commitove i vaš diff u odnosu na nju, a zatim rebase-ujte ili merge-ujte osnovu prema tijeku rada za doprinositelje. Razriješite konflikte generiranih datoteka i kataloga iz njihovog izvora, ponovno ih generirajte, ponovno pokrenite fokusiranu petlju i potvrdite da PR i dalje cilja aktivnu granu izdanja.
6. **Zabilježite dokaze.** U predlošku PR-a navedite pokrenute naredbe, svaku dodanu ili promijenjenu testnu datoteku, migracije ili feature flagove, te bilo koju validaciju koja se vrši samo na CI-u, a koja je još uvijek na čekanju.

## Zlatne staze prema vrsti promjene

Naredbe u nastavku su minimalne fokusirane provjere, a ne dozvola za preskakanje testa koji izravno pokriva ponašanje koje ste promijenili.

### Provider

**Ugovori**

- Definicija providera u `src/shared/constants/providers/` i njegova kompozicija u `src/shared/constants/providers.ts`.
- Modeli i mogućnosti u `open-sse/config/providerRegistry.ts` ili njegovim izdvojenim datotekama registra.
- Odabir izvršitelja/prevoditelja, konfiguracija OAuth-a ili API ključa, resursi nadzorne ploče (dashboard assets) i generirana referenca providera kada je primjenjivo.
- Javne vjerodajnice (credentials) moraju koristiti `resolvePublicCred()`; odgovori na pogreške moraju koristiti dijeljene pomoćnike za sanitizaciju pogrešaka. Pogledajte `docs/security/PUBLIC_CREDS.md` (git; nije kompajlirano u `/docs`) i [Error Sanitization](../security/ERROR_SANITIZATION.md).

**Fokusirana petlja**

```bash
npm run check:provider-consistency
npm run check:provider-assets
node --import tsx/esm --test tests/unit/provider-translate-path-golden.test.ts
node --import tsx/esm --test tests/unit/<provider-or-executor>.test.ts
npm run gen:provider-reference   # kada se katalog promijeni; commit-ujte generirani diff
npm run lint
```

Također testirajte svaku pogođenu obitelj zahtjeva: chat, Responses, slike, embeddinge, audio ili video.
Pregledajte generirani katalog i golden diffove kao promjene ugovora; nemojte ih prihvaćati slijepo.

### Routing

**Ugovori**

- Vrijednosti javne strategije i UI metapodaci u `src/shared/constants/routingStrategies.ts`.
- Dispatch i redoslijed pod `open-sse/services/combo.ts` i `open-sse/services/combo/`.
- Combo sheme, perzistencija, stanje otpornosti (resilience state), mogućnosti modela i API/UI kontrole.
- [Auto-Combo Engine](../routing/AUTO-COMBO.md) i dokumentacija o otpornosti kada se ponašanje promijeni.

**Fokusirana petlja**

```bash
node --import tsx/esm --test tests/unit/combo-<behavior>.test.ts
npm run test:combo:matrix        # promjene strategije ili dispatcha
npm run check:known-symbols      # promjene registracije strategije
npm run lint
```

Lokalno koristite determinističke testove s mockanim upstreamom. Live combo smoke testovi zahtijevaju vjerodajnice i ručni su, nisu zamjena za CI.

### UI / UX

**Ugovori**

- Next.js ruta/stranica i granice dijeljenih komponenti pod `src/app/` i `src/shared/components/`.
- Oblici API odgovora, stanja učitavanja/prazno/pogreška, ponašanje tipkovnice i čitača zaslona, responsivni layout, teme i proširenje lokala.
- Engleski UI izvorni stringovi u `src/i18n/messages/en.json`; nemojte hardkodirati novi tekst namijenjen korisnicima.

**Fokusirana petlja**

```bash
node --import tsx --test tests/unit/dashboard/<feature>.test.ts
npx vitest run --config vitest.config.ts tests/unit/ui/<component>.test.tsx
npm run check:dashboard-typecheck
npm run lint
```

Pokrenite aplikaciju za interakcijske ili vizualne promjene i provjerite i uske i široke viewporte. CI pokreće produkcijski build i šire pakete; vizualno ponašanje i dalje treba fokusiranu komponentu, Playwright ili dokumentiranu ručnu provjeru prikladnu za promjenu.

### i18n

**Ugovori**

- `src/i18n/messages/en.json` je UI izvor; `config/i18n.json` je izvor lokala.
- CLI katalozi žive odvojeno pod `bin/cli/locales/`.
- Točno sačuvajte ICU rezervirana mjesta (placeholders) i oznake. Nemojte prevoditi nazive proizvoda/providera/modela, nazive protokola i zaglavlja, naredbe, kodne/JSON identifikatore, URL-ove, varijable okruženja ili zaštićene termine kao što su `OmniRoute`, `OAuth`, `MCP` i `A2A`. Trenutni izvorni popis je `scripts/i18n/glossary/protected-terms.json`.

**Fokusirana petlja**

```bash
npm run i18n:sync-ui:dry
npm run i18n:check-ui-coverage
npm run i18n:check-value-drift
npm run i18n:check-glossary
npm run check:cli-i18n          # kada se CLI stringovi/katalozi promijene
npm run lint
```

Ovo su smjernice za postojeći sustav, a ne poziv za proširenje njegovih alata ili ključnog modela. Neka i18n zakrpe budu kirurški precizne dok se dizajnira zamjenski sustav. Nemojte pokretati naredbe za prevođenje koje pozivaju vanjske usluge osim ako zadatak izričito ne zahtijeva generirane prijevode i ako niste pregledali rezultirajući diff.

### CLI

**Ugovori**

- Javne komande i flagovi u `bin/cli/`, generisane API komande, izlazni kodovi (exit codes), stdout/stderr i oblici JSON izlaza, ponašanje konfiguracije/okruženja i upakovane datoteke.
- Stringovi okrenuti korisniku u CLI-u moraju koristiti CLI i18n sloj i održavati `en`/`pt-BR` kataloge usklađenim.
- Zadržite Node kao podržano runtime okruženje i objavljeni binarni ugovor.

**Fokusirana petlja**

```bash
node --import tsx/esm --test tests/unit/cli/<command>.test.ts
npm run check:cli-i18n
npm run build:cli             # promjene generisanog/upakovanog CLI-a
npm run check:pack-policy     # promjene površine paketa
npm run lint
```

Koristite tačnu komandu u privremenom direktorijumu podataka kada ponašanje zavisi od parsiranja, datoteka ili statusa izlaza. CI vrši šire provjere artefakata paketa i ekosistema.

### Baza podataka

**Ugovori**

- Domenski moduli pod `src/lib/db/`; uvozite specifične module direktno (stari `localDb.ts` sloj za ponovni izvoz je uklonjen).
- Numerisane, idempotentne SQL migracije pod `src/lib/db/migrations/`, sigurnost transakcija, ponašanje nadogradnje, indeksi i svaki pozivalac na kojeg utiče šema.
- Rute i rukovaoci nikada ne izdaju sirovi SQL direktno.

**Fokusirana petlja**

```bash
npm run check:migration-numbering
npm run check:db-rules
node --import tsx/esm --test tests/unit/db/<domain>.test.ts
node --import tsx/esm --test tests/unit/db/migration-<number>.test.ts
npm run lint
```

Testirajte i svježu bazu podataka i nadogradnju sa prethodne šeme kada dodajete migraciju. Testovi baze podataka moraju zatvoriti handle-ove i pozvati `resetDbInstance()` tokom čišćenja. Pokrenite `npm run test:bun:db` samo kada se promijeni putanja Bun adaptera najboljeg napora; Node ostaje autoritativan.

### Izgradnja / raspoređivanje

**Ugovori**

- Korijenski i radni manifesti/lockfile, `scripts/build/`, Next.js samostalni sklop, sadržaj `dist/` paketa, metapodaci Electron platforme, CI radni tokovi i sentineli raspoređivanja.
- Podržani rasponi Node-a i dozvoljena upotreba Bun-a u `CLAUDE.md` moraju ostati netaknuti.
- Artefakti izgradnje ostaju nepraćeni; primjenjuju se politike zavisnosti, licenci, radnog toka i paketa.

**Fokusirana petlja**

```bash
node --import tsx/esm --test tests/unit/build/<behavior>.test.ts
npm run check:build-scope
npm run check:lockfile         # promjene zavisnosti ili lockfile-a
npm run check:pack-policy      # promjene površine objavljenog paketa
npm run lint
```

Koristite `npm run build` lokalno samo kada promjena utiče na kompilaciju, samostalni sklop, sredstva (assets) ili runtime bundle. Koristite `npm run build:release` samo za validaciju izdanja/raspoređivanja. CI izgradnja je konačni signal za više platformi; promjene specifične za Electron platformu trebaju odgovarajuću fokusiranu izgradnju ili dokaz o ispravnosti.

## Lokalna petlja naspram CI

| Pokretanje lokalno za svaku zakrpu                                                   | CI pruža širi signal                                                              |
| ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| Direktni testovi ponašanja i kategorijske kapije iznad                               | Podijeljeni potpuni paket jediničnih testova i serijski testovi                   |
| `npm run lint`                                                                       | Vitest paketi i mehanizmi ograničenja pokrivenosti/kvaliteta                      |
| Provjera tipova ili izgradnja samo kada to zahtijeva pogođeni ugovor                 | Produkcijska izgradnja, sigurnost, dokumentacija, zavisnosti i kapije PR-politike |
| Ručna interakcija/provjere uživo samo kada automatizacija ne može dokazati ponašanje | Integracija između poslova i provjere platforme konfigurisane putem radnog toka   |

Zelena fokusirana petlja je dokaz o promijenjenom ugovoru, a ne dokaz da će nepovezane CI provjere proći. Suprotno tome, nemojte čekati punu matricu repozitorija za svaku lokalnu izmjenu.

## Kontrolna lista za usklađivanje

Prije zahtjeva za pregled:

- Potvrdite da je baza PR-a i dalje najviša aktivna `release/v*` grana.
- Dohvatite tu bazu i pregledajte commit-e koji su dodani otkako ste kreirali granu.
- Pregledajte `git diff <active-base>...HEAD` radi slučajnih ili generisanih promjena.
- Razriješite konflikte kataloga i generisanih dokumenata ažuriranjem izvora i ponovnim generisanjem izlaza.
- Ponovo pokrenite svaki fokusirani test/kapiju navedenu u opisu PR-a nakon usklađivanja.
- Nikada ne slabite asertacije niti izbacujte potrebne testove samo da biste se uskladili sa pomjerenom bazom.

Za pravila zamrzavanja izdanja (release-freeze) i promjene cilja (retargeting), koristite [Branching & Release Model](BRANCHING_MODEL.md). Za kompletan CI inventar, koristite [Quality Gates Reference](../architecture/QUALITY_GATES.md).
