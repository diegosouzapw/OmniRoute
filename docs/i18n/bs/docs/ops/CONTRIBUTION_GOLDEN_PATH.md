Koristite ovaj vodič kako biste odabrali najmanju pouzdanu razvojnu petlju za pull request. On ne
zamjenjuje dokumente o arhitekturi i sigurnosti za određena područja, navedene u nastavku; povezuje
svaku uobičajenu vrstu izmjene s njenim ugovorima, ciljanim provjerama i CI pokrivenošću.

## Put koji slijedi svaka izmjena

1. **Odaberite osnovnu granu prije uređivanja.** Pronađite najvišu aktivnu granu `release/v*` i
   kreirajte granu iz njenog vrha. Kao cilj postavite tu granu, a ne `main`. Ako je aktivno
   zamrzavanje izdanja, nemojte kao cilj postaviti zamrznutu granu; koristite sljedeći aktivni ciklus
   opisan u dokumentu
   [Model grananja i izdanja](BRANCHING_MODEL.md).
2. **Navedite ugovore.** Identificirajte svaki katalog, shemu, generirani artefakt, javni API ili
   korisnički interfejs na koji izmjena utječe. Tabela u nastavku navodi minimalni početni skup.
3. **Napišite ili ažurirajte ciljane testove.** Izmjene produkcijskog koda u `src/`, `open-sse/`,
   `electron/` ili `bin/` zahtijevaju automatizirani test u istom PR-u. Pokrenite najmanji skup
   testnih datoteka koji dokazuje ponašanje, a zatim navedene ciljane provjere.
4. **Prepustite CI-u pokretanje široke matrice.** Potpuni segmenti jediničnih testova, Vitest,
   postepeno povećavanje pokrivenosti i produkcijska izgradnja pokreću se za PR. Širi skup testova
   pokrenite lokalno samo kada ciljani neuspjeh ukazuje na širi utjecaj ili kada izmjena obuhvata
   nekoliko podsistema.
5. **Uskladite izmjene prije pregleda.** Dohvatite aktivnu osnovnu granu, pregledajte njene nove
   commitove i svoj diff u odnosu na nju, a zatim izvršite rebase ili spojite osnovnu granu u skladu
   s radnim tokom za doprinositelje. Konflikte u generiranim datotekama i katalozima riješite u
   njihovom izvoru, ponovo ih generirajte, ponovo pokrenite ciljanu petlju i potvrdite da PR i dalje
   cilja aktivnu granu izdanja.
6. **Zabilježite dokaze.** U PR predlošku navedite pokrenute komande, svaku dodanu ili izmijenjenu
   testnu datoteku, migracije ili zastavice funkcionalnosti te sve provjere koje su još na čekanju i
   izvršavaju se samo u CI-u.

## Preporučeni putevi prema vrsti izmjene

Komande u nastavku predstavljaju minimalne ciljane provjere, a ne dopuštenje da preskočite test koji
direktno pokriva ponašanje koje ste izmijenili.

### Pružalac usluga

**Ugovori**

- Definicija pružaoca usluga u `src/shared/constants/providers/` i njeno sastavljanje u
  `src/shared/constants/providers.ts`.
- Modeli i mogućnosti u `open-sse/config/providerRegistry.ts` ili njegovim izdvojenim datotekama
  registra.
- Odabir izvršitelja/prevoditelja, OAuth ili API-key konfiguracija, resursi kontrolne ploče i
  generirana referenca pružaoca usluga, kada je primjenjivo.
- Javni pristupni podaci moraju koristiti `resolvePublicCred()`; odgovori o greškama moraju koristiti
  zajedničke pomoćne funkcije za sanitizaciju. Pogledajte `docs/security/PUBLIC_CREDS.md` (git; nije
  kompajlirano u `/docs`) i
  [Sanitizacija grešaka](../security/ERROR_SANITIZATION.md).

**Ciljana petlja**

```bash
npm run check:provider-consistency
npm run check:provider-assets
node --import tsx/esm --test tests/unit/provider-translate-path-golden.test.ts
node --import tsx/esm --test tests/unit/<provider-or-executor>.test.ts
npm run gen:provider-reference   # kada se katalog promijeni; commitujte generirani diff
npm run lint
```

Također testirajte svaku obuhvaćenu grupu zahtjeva: chat, Responses, slike, embeddings, zvuk ili
video. Pregledajte generirane diffove kataloga i referentnih rezultata kao izmjene ugovora; nemojte
ih prihvatati bez provjere.

### Usmjeravanje

**Ugovori**

- Javne vrijednosti strategije i metapodaci korisničkog interfejsa u
  `src/shared/constants/routingStrategies.ts`.
- Otpremanje i redoslijed unutar `open-sse/services/combo.ts` i `open-sse/services/combo/`.
- Combo sheme, trajna pohrana, stanje otpornosti, mogućnosti modela i API/UI kontrole.
- [Auto-Combo mehanizam](../routing/AUTO-COMBO.md) i dokumentacija o otpornosti kada se ponašanje
  promijeni.

**Ciljana petlja**

```bash
node --import tsx/esm --test tests/unit/combo-<behavior>.test.ts
npm run test:combo:matrix        # izmjene strategije ili otpremanja
npm run check:known-symbols      # izmjene registracije strategije
npm run lint
```

Lokalno koristite determinističke testove sa simuliranim upstream servisima. Aktivni combo dimni
testovi zahtijevaju pristupne podatke i izvode se ručno; oni nisu zamjena za CI.

### UI / UX

**Ugovori**

- Granice Next.js ruta/stranica i zajedničkih komponenti unutar `src/app/` i
  `src/shared/components/`.
- Oblici API odgovora, stanja učitavanja/praznog sadržaja/grešaka, ponašanje tastature i čitača
  ekrana, responzivni raspored, teme i proširenje lokalizacije.
- Engleski izvorni UI nizovi u `src/i18n/messages/en.json`; nemojte direktno upisivati novi tekst
  namijenjen korisnicima.

**Ciljana petlja**

```bash
node --import tsx --test tests/unit/dashboard/<feature>.test.ts
npx vitest run --config vitest.config.ts tests/unit/ui/<component>.test.tsx
npm run check:dashboard-typecheck
npm run lint
```

Pokrenite aplikaciju za izmjene interakcije ili vizuelnog prikaza i provjerite uske i široke prikaze.
CI pokreće produkcijsku izgradnju i šire skupove testova; vizuelno ponašanje i dalje zahtijeva
ciljanu komponentu, Playwright ili dokumentiranu ručnu provjeru primjerenu izmjeni.

### i18n

**Ugovori**

- `src/i18n/messages/en.json` je UI izvor; `config/i18n.json` je izvor lokalizacija.
- CLI katalozi nalaze se zasebno unutar `bin/cli/locales/`.
- Očuvajte ICU rezervirana mjesta i oznake u potpuno istom obliku. Nemojte prevoditi nazive
  proizvoda/pružalaca usluga/modela, nazive protokola i zaglavlja, komande, identifikatore
  koda/JSON-a, URL-ove, varijable okruženja ili zaštićene pojmove kao što su `OmniRoute`, `OAuth`,
  `MCP` i `A2A`. Trenutna izvorna lista nalazi se u
  `scripts/i18n/glossary/protected-terms.json`.

**Ciljana petlja**

```bash
npm run i18n:sync-ui:dry
npm run i18n:check-ui-coverage
npm run i18n:check-value-drift
npm run i18n:check-glossary
npm run check:cli-i18n          # kada se promijene CLI nizovi/katalozi
npm run lint
```

Ovo su smjernice za postojeći sistem, a ne poziv za proširenje njegovih alata ili modela ključeva.
Neka i18n zakrpe budu precizne i ograničene dok se osmišljava zamjenski sistem. Nemojte pokretati
komande za prevođenje koje pozivaju vanjske servise osim ako zadatak izričito zahtijeva generirane
prijevode i ako ste pregledali rezultirajući diff.

### CLI

**Ugovori**

- Javne komande i zastavice u `bin/cli/`, generisane API komande, izlazni kodovi, stdout/stderr i
  strukture JSON izlaza, ponašanje konfiguracije/okruženja i zapakovane datoteke.
- Tekstovi CLI-ja namijenjeni korisnicima moraju koristiti CLI i18n sloj, a katalozi `en`/`pt-BR` moraju ostati usklađeni.
- Zadržite Node kao podržano izvršno okruženje i ugovor objavljenih binarnih datoteka.

**Fokusirani ciklus**

```bash
node --import tsx/esm --test tests/unit/cli/<command>.test.ts
npm run check:cli-i18n
npm run build:cli             # promjene generisanog/pakovanog CLI-ja
npm run check:pack-policy     # promjene površine paketa
npm run lint
```

Koristite tačnu komandu u privremenom direktoriju podataka kada ponašanje zavisi od parsiranja, datoteka ili izlaznog
statusa. CI provodi šire provjere artefakata paketa i ekosistema.

### Baza podataka

**Ugovori**

- Domenski moduli nalaze se u `src/lib/db/`; direktno uvozite određene module (stari sloj za ponovni izvoz `localDb.ts` je uklonjen).
- Numerisane, idempotentne SQL migracije u `src/lib/db/migrations/`, sigurnost transakcija, ponašanje pri nadogradnji,
  indeksi i svaki pozivalac na kojeg utiče shema.
- Rute i rukovaoci nikada ne izvršavaju sirovi SQL direktno.

**Fokusirani ciklus**

```bash
npm run check:migration-numbering
npm run check:db-rules
node --import tsx/esm --test tests/unit/db/<domain>.test.ts
node --import tsx/esm --test tests/unit/db/migration-<number>.test.ts
npm run lint
```

Prilikom dodavanja migracije testirajte i novu bazu podataka i nadogradnju s prethodne sheme. Testovi baze podataka
moraju zatvoriti pristupne objekte i pozvati `resetDbInstance()` tokom čišćenja. Pokrenite `npm run test:bun:db` samo kada
se promijeni opcionalna putanja Bun adaptera; Node ostaje mjerodavan.

### Izgradnja / implementacija

**Ugovori**

- Korijenski i radni manifesti/datoteka zaključavanja, `scripts/build/`, Next.js samostalno sastavljanje, sadržaj
  paketa `dist/`, Electron metapodaci platforme, CI tokovi rada i kontrolne oznake implementacije.
- Podržani rasponi Node verzija i dozvoljena upotreba Bunu u `CLAUDE.md` moraju ostati nepromijenjeni.
- Artefakti izgradnje ne prate se u repozitoriju; primjenjuju se pravila za zavisnosti, licence, tokove rada i pakete.

**Fokusirani ciklus**

```bash
node --import tsx/esm --test tests/unit/build/<behavior>.test.ts
npm run check:build-scope
npm run check:lockfile         # promjene zavisnosti ili datoteke zaključavanja
npm run check:pack-policy      # promjene površine objavljenog paketa
npm run lint
```

Koristite `npm run build` lokalno samo kada promjena utiče na kompilaciju, samostalno sastavljanje, resurse
ili pakovanje izvršnog okruženja. Koristite `npm run build:release` samo za validaciju izdanja/implementacije. CI izgradnja je
konačni signal za različite platforme; promjene Electron-a specifične za platformu zahtijevaju odgovarajuću fokusiranu izgradnju
ili dokaz kroz osnovni test.

## Lokalna petlja kandidata

Testovi izvornog koda ne mogu dokazati da se zapakovani artefakt može pokrenuti: spiskovi za pakovanje, uklonjene zavisnosti i nativne binarne datoteke uzrokuju greške tek kada se tarball instalira i pokrene. `npm run dev:candidate` (`scripts/dev/candidate.mjs`) predstavlja lokalnu stranu toka izgradi-jednom / validiraj / promoviraj iz RFC-a #8084: izrađuje jednog kandidata, validira upravo taj artefakt, promovira ga preimenovanjem direktorija i vraća ga na prethodnu verziju kada promovirani slot ne prođe provjeru ispravnosti.

```bash
npm run dev:candidate -- run --dry-run --json  # ispiši plan, ne mijenjaj ništa
npm run dev:candidate -- run                   # izgradi + validiraj + promoviraj, automatski vrati prethodnu verziju
npm run dev:candidate -- build                 # npm pack + instalacija u _artifacts/candidate/<id>/
npm run dev:candidate -- validate --id <id>    # pokreni na slobodnom portu, /api/health + /v1/models
npm run dev:candidate -- promote --id <id>     # <id> → current, current → previous
npm run dev:candidate -- rollback              # zamijeni current i previous
npm run dev:candidate -- run --from-tarball <file.tgz>  # ponovo koristi tarball izrađen drugdje (CI)
```

- **Izgradi jednom.** `build` pakuje trenutno stablo (potreban mu je `dist/server.js`, stoga prvo pokrenite `npm run build:release`) ili kopira `--from-tarball`, a zatim instalira tarball u izolirani npm prefiks jer tarball ne sadrži `node_modules`. ID je skraćeni `HEAD` sha (`-dirty` kada stablo sadrži lokalne izmjene) ili `tgz-<sha256>` za tarball. Čisti ID koji je već izrađen ponovo se koristi umjesto ponovne izgradnje; proslijedite `--force` da biste ga ponovo izgradili.
- **Validirajte paket, a ne izvorni kod.** `validate` pokreće instalirani CLI (`serve --port <free port>`) sa svježim `DATA_DIR=<candidate>/data`, lažnim tajnama i uklonjenim operatorovim varijablama `OMNIROUTE_API_KEY`, `STORAGE_ENCRYPTION_KEY` i `INITIAL_PASSWORD` iz okruženja, čime provjerava ponašanje svježe instalacije bez ključeva na loopback interfejsu. Čeka da `GET /api/health` vrati 200, zahtijeva da `GET /v1/models` vrati 200, zaustavlja grupu procesa i bilježi rezultat u `validation.json` zajedno s hashom tarballa.
- **Promovirajte isti artefakt.** `promote` odbija kandidata bez uspješne validacije za njegov trenutni hash tarballa. Zadani aktivni slot je `_artifacts/candidate/current`; `--target <dir>` odabire drugi direktorij na istom datotečnom sistemu, a njegov prethodni slot je `<dir>.previous`. Svako preimenovanje je atomsko, a ako dođe do greške tokom postupka, poništavaju se već izvršena preimenovanja.
- **Vratite prethodnu verziju.** `run` ponovo validira promovirani slot i zamjenjuje `current` i `previous` ako ta provjera ne uspije. Kandidat koji ne prođe prvu validaciju nikada se ne promovira.

Sve se zapisuje unutar direktorija `_artifacts/candidate/` koji git ignorira; postojeća instalacija OmniRoutea i njen direktorij podataka nikada se ne mijenjaju. Promovirani CLI nalazi se na `_artifacts/candidate/current/prefix/bin/omniroute`; kada ga koristite, pokrenite ga s vlastitim `DATA_DIR`. Izlazni kodovi: `0` uspjeh, `1` neuspješna validacija ili promocija, `2` greška u korištenju ili nedostajuća izgradnja.

## Lokalna petlja naspram CI-ja

| Pokrenuti lokalno za svaku izmjenu                                                   | CI pruža širi signal                                                                     |
| ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| Direktni testovi ponašanja i gore navedene provjere kategorija                       | Podijeljeni puni skup jediničnih testova i serijski testovi                              |
| `npm run lint`                                                                       | Vitest skupovi testova i pragovi pokrivenosti/kvaliteta                                  |
| Provjera tipova ili izgradnja samo kada to zahtijeva izmijenjeni ugovor              | Produkcijska izgradnja te sigurnosne, dokumentacijske, zavisnosne i PR provjere          |
| Ručne provjere interakcije/uživo samo kada automatizacija ne može dokazati ponašanje | Integracijske provjere između zadataka i platformske provjere konfigurirane radnim tokom |

Uspješna fokusirana petlja dokaz je o izmijenjenom ugovoru, a ne dokaz da će nepovezane CI provjere
proći. S druge strane, nemojte činiti da svaka lokalna izmjena čeka punu matricu repozitorija.

## Kontrolna lista za usklađivanje

Prije nego što zatražite pregled:

- Potvrdite da je osnova PR-a i dalje najviša aktivna grana `release/v*`.
- Dohvatite tu osnovu i pregledajte commitove dodane otkako ste kreirali svoju granu.
- Pregledajte `git diff <active-base>...HEAD` radi slučajnih ili generiranih izmjena.
- Riješite konflikte u katalozima i generiranim dokumentima ažuriranjem izvora i ponovnim generiranjem izlaza.
- Nakon usklađivanja ponovo pokrenite svaki fokusirani test/provjeru navedenu u opisu PR-a.
- Nikada nemojte oslabiti provjere niti izostaviti obavezne testove samo da biste se uskladili s pomjerenom osnovom.

Za pravila o zamrzavanju izdanja i promjeni ciljne grane koristite
[Model grananja i izdanja](BRANCHING_MODEL.md). Za potpuni popis CI provjera koristite
[Referenca provjera kvaliteta](../architecture/QUALITY_GATES.md).
