## Pravila

- Ciljevi pokrivnosti se odnose na izvorne datoteke, ne na `tests/**`.
- `open-sse/**` je dio proizvoda i mora ostati u opsegu.
- Novi kod ne smije smanjiti pokrivnost u izmijenjenim oblastima.
- Preferirajte testiranje ponašanja i ishoda grana nad detaljima implementacije.
- Preferirajte privremene SQLite baze podataka i male fixture nad širokim mock-ovima za `src/lib/db/**`.

## Trenutni set komandi

- `npm run test:coverage`
  - Glavni prolaz za pokrivnost izvornog koda za set unit testova
  - Generiše `text-summary`, `html`, `json-summary` i `lcov`
- `npm run coverage:report`
  - Detaljan izvještaj po datotekama iz posljednjeg pokretanja
- `npm run test:coverage:legacy`
  - Samo za historijsko poređenje

## Ratchet polisa

Ažurirajte pragove za `npm run test:coverage` tek nakon što projekat premaši sljedeću prekretnicu sa komfornim bufferom.

**Trenutni gate:** `npm run test:coverage` nameće **60 statements / 60 lines / 60 functions / 60 branches** (metrika je rebasirana u Quality-Gates Fase 6A.1 — raniji baseline od 82.58% bio je naduvan jer je uključivao test fajlove i isključivao `open-sse`). Komanda `test:coverage:legacy` čuva staru metriku 50/50/50 za historijsko poređenje.

Za ad-hoc provjere pragova u odnosu na najnoviji izvještaj koristite:

```bash
node scripts/check/test-report-summary.mjs --threshold 75
```

Preporučeni ratchet redoslijed (redoslijed je `statements-lines / branches / functions`):

1. 55/60/55
2. 60/62/58
3. 65/64/62
4. 70/66/66
5. 75/70/72 <-- trenutni gate (75/70/75)
6. 80/75/78
7. 85/80/84
8. 90/85/88

Sljedeći ratchet cilj je `80/75/78` čim pokrivenost grana (branch coverage) ostane iznad 78% tokom dva uzastopna pokretanja.

## Poznata praznina

Trenutna komanda za pokrivenost mjeri glavni Node unit suite i uključuje izvore do kojih se dolazi iz njega, uključujući `open-sse`. Ona još uvijek ne spaja Vitest pokrivenost u jedan jedinstveni izvještaj. To spajanje vrijedi uraditi kasnije, ali nije blokada za početak uspona sa 60% na 80%.
