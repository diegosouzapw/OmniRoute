## Preduslovi

| Stavka     | Minimum                    | Preporučeno      |
| ---------- | -------------------------- | ---------------- |
| **CPU**    | 1 vCPU                     | 2 vCPU           |
| **RAM**    | 1 GB                       | 2 GB             |
| **Disk**   | 10 GB SSD                  | 25 GB SSD        |
| **OS**     | Ubuntu 22.04 LTS           | Ubuntu 24.04 LTS |
| **Domena** | Registrovana na Cloudflare | —                |
| **Docker** | Docker Engine 24+          | Docker 27+       |

**Testirani provajderi**: Akamai (Linode), DigitalOcean, Vultr, Hetzner, AWS Lightsail.

## 1. Konfigurišite VM

### 1.1 Kreirajte instancu

Kod vašeg preferiranog VPS provajdera:

- Odaberite Ubuntu 24.04 LTS
- Odaberite minimalni plan (1 vCPU / 1 GB RAM)
- Postavite jaku root lozinku ili konfigurišite SSH ključ
- Zabilježite **javnu IP adresu** (npr. `203.0.113.10`)

### 1.2 Povežite se putem SSH-a

```bash
ssh root@203.0.113.10
```

### 1.3 Ažurirajte sistem

```bash
apt update && apt upgrade -y
```

### 1.4 Instalirajte Docker

```bash
# Instalacija zavisnosti
apt install -y ca-certificates curl gnupg

# Dodavanje zvaničnog Docker repozitorija
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
chmod a+r /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $ (. /etc/os-release && echo "$VERSION_CODENAME") stable" | tee /etc/apt/sources.list.d/docker.list > /dev/null
apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

### 1.5 Instalirajte nginx

```bash
apt install -y nginx
```

### 1.6 Konfigurišite Firewall (UFW)

```bash
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp    # SSH
ufw allow 80/tcp    # HTTP (redirect)
ufw allow 443/tcp   # HTTPS
ufw enable
```

> **Savjet**: Za maksimalnu sigurnost, ograničite portove 80 i 443 samo na Cloudflare IP adrese. Pogledajte sekciju [Napredna sigurnost](#advanced-security).

## 2. Instalirajte OmniRoute

### 2.1 Kreirajte direktorij za konfiguraciju

```bash
mkdir -p /opt/omniroute
```

### 2.2 Kreirajte datoteku za environment varijable

```bash
cat > /opt/omniroute/.env << 'EOF'
# === Security ===
JWT_SECRET=CHANGE-TO-A-UNIQUE-64-CHAR-SECRET-KEY
INITIAL_PASSWORD=YourSecurePassword123!
API_KEY_SECRET=REPLACE-WITH-ANOTHER-SECRET-KEY
STORAGE_ENCRYPTION_KEY=REPLACE-WITH-THIRD-SECRET-KEY
STORAGE_ENCRYPTION_KEY_VERSION=v1
MACHINE_ID_SALT=CHANGE-TO-A-UNIQUE-SALT
OMNIROUTE_WS_BRIDGE_SECRET=REPLACE-WITH-WS-BRIDGE-SECRET  # OBAVEZNO u produkciji: koristi Codex Responses WS bridge

# === App ===
PORT=20128
NODE_ENV=production
HOSTNAME=0.0.0.0
DATA_DIR=/app/data
APP_LOG_TO_FILE=true
AUTH_COOKIE_SECURE=true
REQUIRE_API_KEY=false

# === URLs (promijenite na vašu domenu) ===
# Interni server-to-server osnovni URL za zakazane poslove / self-fetches.
BASE_URL=http://127.0.0.1:20128
# URL okrenut prema pregledniku koji se koristi za OAuth callback-ove, linkove za dashboard i generisane javne URL-ove.
NEXT_PUBLIC_BASE_URL=https://llms.vasadomena.com
# Opcionalno eksplicitno pregažanje javnog origina za generisane javne asset URL-ove.
# OMNIROUTE_PUBLIC_BASE_URL=https://llms.vasadomena.com

# === Cloud Sync (opcionalno) ===
# CLOUD_URL=https://cloud.omniroute.online
# NEXT_PUBLIC_CLOUD_URL=https://cloud.omniroute.online
EOF
```

> ⚠️ **VAŽNO**: Generišite jedinstvene tajne ključeve! Koristite `openssl rand -hex 32` za svaki ključ.

### 2.3 Pokrenite kontejner

```bash
docker pull diegosouzapw/omniroute:latest

docker run -d \
  --name omniroute \
  --restart unless-stopped \
  --env-file /opt/omniroute/.env \
  -p 20128:20128 \
  -v omniroute-data:/app/data \
  diegosouzapw/omniroute:latest
```

### 2.4 Provjerite da li radi

```bash
docker ps | grep omniroute
docker logs omniroute --tail 20
```

Trebalo bi prikazati: `[DB] SQLite database ready` i `listening on port 20128`.

## 3. Konfigurišite nginx (Reverse Proxy)

### 3.1 Generišite SSL certifikat (Cloudflare Origin)

U Cloudflare kontrolnoj ploči:

1. Idite na **SSL/TLS → Origin Server**
2. Kliknite na **Create Certificate**
3. Zadržite zadane vrijednosti (15 godina, \*.yourdomain.com)
4. Kopirajte **Origin Certificate** i **Private Key**

```bash
mkdir -p /etc/nginx/ssl

# Zalijepite certifikat
nano /etc/nginx/ssl/origin.crt

# Zalijepite privatni ključ
nano /etc/nginx/ssl/origin.key

chmod 600 /etc/nginx/ssl/origin.key
```

### 3.2 Nginx Konfiguracija

```bash
cat > /etc/nginx/sites-available/omniroute << 'NGINX'
# Default server — blokira direktan pristup putem IP adrese
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    listen 443 ssl default_server;
    listen [::]:443 ssl default_server;
    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    server_name _;
    return 444;
}

# OmniRoute — HTTPS
server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name llms.yourdomain.com;  # Promijenite u vašu domenu

    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    client_max_body_size 100M;

    location / {
        proxy_pass http://127.0.0.1:20128;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket podrška
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # SSE (Server-Sent Events) — streaming AI odgovora
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }
}

# HTTP → HTTPS preusmjeravanje
server {
    listen 80;
    listen [::]:80;
    server_name llms.yourdomain.com;
    return 301 https://$server_name$request_uri;
}
NGINX
```

Uskladite timeout vrijednosti reverse-proxy stream-a sa vašim OmniRoute timeout env varijablama. Ako povećate
`FETCH_TIMEOUT_MS` / `STREAM_IDLE_TIMEOUT_MS`, povećajte `proxy_read_timeout` / `proxy_send_timeout`
iznad istog praga.

OmniRoute koristi `NEXT_PUBLIC_BASE_URL` kao kanonski origin okrenut prema pregledniku za OAuth
callback-ove i generisane javne linkove. Autentifikovano pisanje u dashboard-u koristi same-origin zahtjeve
uz session-bound CSRF zaštitu, tako da im nije potreban statični javni bazni URL.
`X-Forwarded-*` zaglavlja iznad su i dalje korisni metapodaci za rutiranje, ali nisu zamjena
za postavljanje eksplicitnog javnog URL-a kada OAuth ili generisani linkovi za preglednik zahtijevaju isti. Omogućite
`OMNIROUTE_TRUST_PROXY` samo ako OmniRoute nije direktno dostupan klijentima i ako vaš proxy
uklanja/ponovo kreira dolazna forwarded zaglavlja.

### 3.3 Omogućite i Testirajte

```bash
# Uklonite default konfiguraciju
rm -f /etc/nginx/sites-enabled/default

# Omogućite OmniRoute
ln -sf /etc/nginx/sites-available/omniroute /etc/nginx/sites-enabled/omniroute

# Testirajte i ponovo učitajte
nginx -t && systemctl reload nginx
```

## 4. Konfiguracija Cloudflare DNS-a

### 4.1 Dodavanje DNS zapisa

U Cloudflare kontrolnoj ploči → DNS:

| Tip | Ime    | Sadržaj                | Proxy      |
| --- | ------ | ---------------------- | ---------- |

Pod **SSL/TLS → Overview**:

- Mode: **Full (Strict)**

Pod **SSL/TLS → Edge Certificates**:

- Always Use HTTPS: ✅ On
- Minimum TLS Version: TLS 1.2
- Automatic HTTPS Rewrites: ✅ On

### 4.3 Testiranje

```bash
curl -sI https://llms.seudominio.com/health
# Trebalo bi vratiti HTTP/2 200
```

## 5. Operacije i održavanje

### Nadogradnja na novu verziju

```bash
docker pull diegosouzapw/omniroute:latest
docker stop omniroute && docker rm omniroute
docker run -d --name omniroute --restart unless-stopped \
  --env-file /opt/omniroute/.env \
  -p 20128:20128 \
  -v omniroute-data:/app/data \
  diegosouzapw/omniroute:latest
```

### Pregled logova

```bash
docker logs -f omniroute          # Stream u stvarnom vremenu
docker logs omniroute --tail 50   # Posljednjih 50 linija
```

### Ručno pravljenje rezervne kopije baze podataka

```bash
# Kopiraj podatke iz volumena na host
docker cp omniroute:/app/data ./backup-$(date +%F)

# Ili komprimiraj cijeli volumen
docker run --rm -v omniroute-data:/data -v $(pwd):/backup \
  alpine tar czf /backup/omniroute-data-$(date +%F).tar.gz /data
```

### Vraćanje iz rezervne kopije

```bash
docker stop omniroute
docker run --rm -v omniroute-data:/data -v $(pwd):/backup \
  alpine sh -c "rm -rf /data/* && tar xzf /backup/omniroute-data-YYYY-MM-DD.tar.gz -C /"
docker start omniroute
```

set_real_ip_from 141.101.64.0/18;
set_real_ip_from 108.162.192.0/18;
set_real_ip_from 190.93.240.0/20;
set_real_ip_from 188.114.96.0/20;
set_real_ip_from 197.234.240.0/22;
set_real_ip_from 198.41.128.0/17;
set_real_ip_from 162.158.0.0/15;
set_real_ip_from 104.16.0.0/13;

## Optimizacija za malo memorije / mali VPS

Za implementacije na malim VPS instancama (1 GB RAM-a ili manje):

- **Onemogućite pozadinske servise** — postavite `OMNIROUTE_DISABLE_BACKGROUND_SERVICES=1` kako biste preskočili scheduler, MCP server i periodne zadatke održavanja. Pogledajte `docs/reference/ENVIRONMENT.md`.
- **Koristite SQLite WAL način rada** — omogućeno po defaultu, smanjuje vršnu potrošnju memorije tokom konkurentnog čitanja.
- **Ograničite V8 heap** — postavite `OMNIROUTE_MEMORY_MB` (npr. `512`) kako runtime ne bi kalibrisao limit veći od VM-a. Pogledajte `docs/reference/ENVIRONMENT.md`.
- **Teški zahtjevi se automatski skaliraju prema limitu heap-a** -- kada se `OMNIROUTE_MEMORY_MB` postavi kao gore navedeno, budžet bajtova za ingest (`OMNIROUTE_CHAT_MAX_INFLIGHT_BYTES`) se izvodi iz istog limita, tako da VM sa ograničenom memorijom već dobija manji budžet za konkurentne zahtjeve bez dodatnog podešavanja; višak zahtjeva dobija ponovljiv `503` sa `Retry-After` umjesto da se takmiče za memoriju. Postavite zastarjeli limit broja zahtjeva `OMNIROUTE_CHAT_MAX_HEAVY_IN_FLIGHT` samo ako vam je potreban strogi limit povrh toga.
- **Izbjegavajte `next build` na VPS-u** — build-ajte lokalno i implementirajte standalone izlaz (`.next/standalone/`).
- **Pratite stanje pomoću `top` / `free -m`** — OmniRoute obično koristi 200-400 MB RSS u stanju mirovanja na VM-u od 1 GB.
