1. Osigurajte postojeći single-key semaphore contract i novi atomic multi-key contract fokusiranim testovima: bez djelimičnih rezervacija, FIFO queueing, abort, timeout, queue-full, idempotent release, stats i cleanup.
2. Generalizujte postojeći account semaphore na licu mjesta. Zadržite `acquire()` kao compatibility wrapper oko `acquireMany()`; ne dodajte drugi scheduler niti zavisnost.
3. Zamijenite account-only acquisition u `chatCore` sa jednim kumulativnim global/provider/account acquisition neposredno prije `withRateLimit`. Ponovo izvršite reacquire cijelog seta kad god rotacija accounta promijeni konekciju, i zadržite release kroz završetak streaminga.
4. Proširite postojeći resilience settings pipeline (tipove, defaultove, normalizaciju, shemu, API response, UI i prijevode) sa globalnim i provider capovima. Preimenujte stari Bottleneck concurrency control u connection/quota-scope concurrency kako bi njegov stvarni opseg bio eksplicitan.
5. Pokrenite fokusirane testove, lint, typecheck, statičke provjere i puni test suite; dokumentujte promjenu ponašanja u changelogu.

Ponašanje je namjerno zadržano: zero/null concurrency zaobilazi gate, account-only pozivaoci nastavljaju koristiti `acquire()`, blocked-account kontroli zadržavaju svoj key format i API, a provider rate-limit queue ponašanje ostaje nepromijenjeno.
