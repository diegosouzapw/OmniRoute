> Kjøretidsveksler som endrer OmniRoutes oppførsel **uten en ny distribusjon**.
> Hvert flagg som er oppført her er definert i
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> — den eneste kilden til sannhet. Dashbordet og REST API-et leser begge fra
> den filen, så tabellen nedenfor er generert for å matche den 1:1.

---

## Hva funksjonsflagg er

Et funksjonsflagg er en navngitt veksler (boolsk eller enum) hvis verdi kan endres ved
kjøretid og lagres i databasen, uten at det kreves en ny prosessdistribusjon. Hvert
flagg er beskrevet av en `FeatureFlagDefinition` med en `key`, `label`,
`description`, `category`, `defaultValue`, `type`, og et `requiresRestart`-hint.

### Oppløsningsrekkefølge

Den **effektive verdien** av et flagg løses av
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) med denne
prioriteten (høyest vinner):

1. **DB-overstyring** — en verdi lagret i `key_value`-tabellen under
   `feature_flags`-navneområdet (angitt via dashbordet eller REST API-et).
2. **Miljøvariabel** — `process.env[<KEY>]`, hvis satt og ikke-tom.
3. **Definisjonsstandard** — `defaultValue` fra `featureFlagDefinitions.ts`.

Et boolsk flagg anses som **aktivert** når dets effektive verdi er `"true"`,
`"1"`, eller `"yes"` (se `isFeatureFlagEnabled()`).

> [!NOTE]
> De fleste flagg har også en matchende miljøvariabel med **samme navn**
> dokumentert i [`ENVIRONMENT.md`](./ENVIRONMENT.md). Flaggens DB-overstyring
> har forrang over den miljøvariabelen. Et flagg med
> `requiresRestart: true` lagres umiddelbart, men leses bare på nytt ved prosess
> oppstart — å veksle det viser en **"Start server på nytt"**-banner i dashbordet.

## Veksling av flagg

### Dashboard

Naviger til **Dashboard → Settings → Feature Flags**
(`/dashboard/settings/feature-flags`). Rutenettet
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
støtter:

- **Søk** etter nøkkel eller beskrivelse, og **filtrer** etter kategori (pluss en syntetisk
  **Requires Restart**-visning).
- En **veksler** for boolske flagg og en **nedtrekksmeny** for enum-flagg
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- Et **kilde-merke** per flagg — `DB`, `ENV`, eller `DEF` — som viser hvor den
  effektive verdien kom fra.
- En **Reset**-knapp (vises kun for `DB`-kilde-flagg) for å fjerne overstyringen,
  og en **Reset All Overrides**-knapp nederst.
- Et **Restart Server**-banner når et `requiresRestart`-flagg endres.

### REST API

Alle operasjoner går gjennom en enkelt rute:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Hver metode krever en autentisert dashboard-sesjon (`401` ellers).

#### `GET /api/settings/feature-flags`

Returnerer hvert flagg med dets effektive verdi, kilde og en oppsummering.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... all 77 flags
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Angi eller fjern en enkelt overstyring. Body: `{ key: string; value?: string }`.
Utelatelse av `value` fjerner overstyringen (gjenoppretter env / default).

```bash
# Set a DB override
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Remove the override (no "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Responsen gjenspeiler den nye `effectiveValue`/`source`, `previousValue`/
`previousSource`, og `requiresRestart`. Ukjente nøkler og enum-verdier utenfor
området avvises med `400`.

#### `DELETE /api/settings/feature-flags`

Sletter **alle** DB-overstyringer samtidig, og gjenoppretter hvert flagg til dets env / default
verdi. Returnerer `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> Flagg med `requiresRestart: true` trer i kraft først etter en prosessomlasting.
> Dashboardets omstartsprosess kaller `POST /api/restart` og poller deretter
> `GET /api/health/ping` til serveren er oppe igjen.

## Nød-budsjett-tilbakefall

`OMNIROUTE_EMERGENCY_FALLBACK` (kategori `runtime`, standard `true`) kontrollerer
nød-fri-tilbakefallsbanen i
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Når aktivert, rutes forespørsler som tømmer budsjettet sitt til en gratis tilbakefallsleverandør/modell
i stedet for å feile fullstendig. Sett den til `false` (eller `0`) — via
dashboard-veksleren, en DB-overstyring, eller `OMNIROUTE_EMERGENCY_FALLBACK`
miljøvariabelen — for å deaktivere oppførselen og la budsjett-tømte forespørsler feile.
(Fremhevet som en dashboard-veksler i PR #3741 / #3752.)
