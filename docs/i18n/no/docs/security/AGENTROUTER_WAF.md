`agentrouter`-oppstrømsgatewayen kjører et nøkkelordbasert innholdsfilter på
`messages[].content`. Filteret er delvis deterministisk (blokkerer alltid
bestemte fraser) og delvis probabilistisk (sensitivt for trafikkøkninger — blir
mer aggressivt etter raske forespørsler og normaliseres etter en nedkjølingsperiode).

Når WAF-en blokkerer en forespørsel, returnerer den:

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## Filterets omfang

WAF-en undersøker bare `messages[].content`. Den undersøker **ikke**:

- `system`-prompten
- Strukturerte innholdsblokker (`tool_result`, `tool_use`, `thinking`, `image`)
- Feltene `description` og `input_schema` for verktøy
- Forespørselsmetadata, headere eller modell-ID

## Mønstre som alltid blokkeres (uavhengig av store og små bokstaver)

| Mønster                         | Merknader                                                      |
| ------------------------------- | -------------------------------------------------------------- |
| Enhver variant av `Lorem ipsum` | Hele det latinske lorem-ordforrådet blokkeres                  |
| `language model` (alene)        | "the language model" og "large language model" slipper gjennom |
| `virtual assistant`             | "AI assistant" slipper gjennom                                 |
| `I'm here to help`              | "here to help" alene blokkeres også                            |
| `Claude, made by Anthropic`     | Bare hele frasen                                               |

## Mønstre som nesten alltid blokkeres

| Mønster                                                   | Merknader                                           |
| --------------------------------------------------------- | --------------------------------------------------- |
| `placeholder`                                             | Når det står alene (ikke som et parameternavn osv.) |
| `dummy data`                                              | Vanlig startfrase for testdata                      |
| `foo bar baz`                                             | Standardfrase for plassholdertekst                  |
| Gjentatte korte tokener (`AAA BBB CCC`, `test test test`) | Detektor for overbruk av nøkkelord                  |

## Atferd under belastning

Etter rundt 5 raske forespørsler i løpet av et kort tidsrom begynner WAF-en å blokkere innhold
som normalt ville sluppet gjennom. Begrensningen avtar etter rundt 5–10 sekunder uten
aktivitet. Dette er den samme IP- og nøkkelbundne hastighetsbegrenseren som forårsaker
sporadiske `400 content-blocked`-feil når Claude Code eller Codex CLI
foretar flere verktøybruk-/meldingskall i rask rekkefølge.

## Tiltak som allerede er implementert i OmniRoute

1. **`open-sse/services/wafRateLimit.ts`** — beskyttelse mot trafikkøkninger som håndhever et
   minimumsintervall på 500 ms mellom utgående forespørsler til enhver `agentrouter:*`-
   URL. Intervallet er godt under terskelen for menneskelig oppfatning av forsinkelse og forhindrer
   at WAF-en aktiveres ved normal trafikk.

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — når en oppstrømstjeneste returnerer
   `400 content-blocked`, prøver eksekutoren samme URL på nytt med
   eksponentiell tilbakeholdelse (1,5 s, 3,0 s, maksimalt 2 forsøk). Etter ventetiden
   har WAF-en vanligvis normalisert seg, og det nye forsøket lykkes.

3. **`tests/unit/compression/harness.test.ts`** — testfiksturen
   `longInput` ble endret fra `"lorem ipsum dolor sit amet ".repeat(40)`
   til `"example content for testing purposes ".repeat(40)`, slik at når
   Claude Code leser denne filen via `Read`-verktøyet, flyter ikke filinnholdet
   tilbake gjennom en `tool_result`-blokk og utløser WAF-en.

## Veiledning for prompter og verktøyutdata

Hvis en Claude Code- eller Codex CLI-økt gjentatte ganger møter
`400 content-blocked`, bør du kontrollere den nyeste brukermeldingen og det
nyeste verktøyresultatet for mønstrene ovenfor og omformulere innholdet. Vanlige
løsninger:

- Erstatt `Lorem ipsum …` med `example text …` eller det faktiske innholdet
  testen eller fiksturen prøver å modellere.
- Erstatt `placeholder` (når det står alene) med `example value`,
  `sample value` eller den virkelige verdien.
- Erstatt `language model` med `large language model` eller `the model`.
- Erstatt `dummy data` med `sample data` eller realistiske startverdier.
- Erstatt `I'm here to help` / `here to help` med en mer spesifikk
  innledning (f.eks. "I'll review the file you mentioned").

## Rapportering av falske positiver til oppstrømstjenesten

Det nåværende filteret er altfor aggressivt — det blokkerer "Lorem ipsum" i
`tool_result`-blokker selv om operatøren åpenbart ikke hadde til hensikt å
injisere en prompt. Operatører som ønsker at dette rettes ved kilden, bør
kontakte `agentrouter.org` for å rapportere de falske positivene. Blokkeringslisten
ovenfor er det empiriske resultatet av testing av oppstrømstjenesten per 2026-08-03.
