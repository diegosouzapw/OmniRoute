`devin-cli-agentic` lar den ekte Claude Code-kjøretiden bruke OmniRoutes lokale Anthropic
Messages-endepunkt, mens den offisielle Devin CLI-en leverer modellsvar over ACP stdio. Den
endrer ikke de eksisterende leverandørene for Anthropic, Claude OAuth, Claude Web eller `devin-cli`.

> **Gjeldende status: fastlåst til Claude Code `2.1.258`; frakoblet og direkte validering ble sist registrert
> på `2.1.220`.** Fastlåsingen til `2.1.220` fullførte tre isolerte scenarioer gjennom Devin CLI
> `3000.2.17` og modellen `swe-1-7-lightning`; den siste direkte kjøringen bekreftet klienteide `Read`-,
> `Edit`- og `Bash`-runder, vellykkede `npm test`-resultater, oppdagelse av prosjektkommandoer og
> ferdigheter, ruting utelukkende via Devin og ingen utgående trafikk til Claude. Fastlåsingen ble deretter hevet til `2.1.258`
> (CLI-generasjonen som OmniRoutes Claude-identitet utgir seg for å være, og den første serien som leveres
> med innebygd støtte for Fable 5.1-nivået). Med den nye fastlåsingen ble installasjonslaget og `claude --version`
> verifisert på det fastlåste basisavbildet, og broens enhetstestpakke, `compose config` og det
> statiske isolasjonsbeviset består — men det frakoblede mock-scenarioet og den direkte pakken med tre scenarioer
> er ennå ikke kjørt på nytt. Kjør dem på nytt (se «Oppdatering av fastlåste verktøy») før du tar
> broen i bruk med denne fastlåsingen.

## Arkitektur

```text
Claude Code 2.1.258 (isolert Linux-beholder uten root-tilgang)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-format, leverandør uten autentisering)
  -> devin acp --agent-type summarizer (offisiell ACP stdio, ingen Devin-verktøy)
  -> Devin-konto i det dedikerte devin-auth-volumet
```

Standard-ACP-agenten til den offisielle CLI-en kan kjøre sine egne verktøy, så denne broen bruker
den ikke. Den starter den faste ACP-agenten `summarizer`, hvis offisielle CLI-modus ikke har noen verktøy, og
rammer inn den serialiserte Anthropic-forespørselen som et kjøringsspor. Når en annen Claude-eid
handling er nødvendig, må svaret inneholde nøyaktig én klientverktøykonvolutt. Ethvert ACP-
`tool_call` eller `tool_call_update` avvises før et svar kan rapporteres som
vellykket.

Serialisatoren i `open-sse/executors/devin-agentic/serializer.ts` bevarer `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` og
verktøyene som leveres av Claude Code. Bilder og ukjente blokker feiler eksplisitt. Store verktøyresultater
bruker en synlig avkortingsmarkør.

Parseren godtar én frittstående `<tool>{...}</tool>`-konvolutt per modellrunde. Den kontrollerer
navnet mot forespørselens verktøyliste, validerer argumentene mot verktøyets JSON
Schema, avviser blandet narrativ/handlinger og tillater ett begrenset reparasjonsforsøk. Claude Code
kjører deretter den resulterende Anthropic-`tool_use` lokalt og sender `tool_result` tilbake gjennom
OmniRoute.

## Isolasjon og trusselmodell

Vertens Claude-installasjon, -konto og -konfigurasjon er utenfor omfanget og behandles som
forbudt. Compose-tjenestene:

- kjører som UID/GID `10001:10001`, med et skrivebeskyttet rotfilsystem, fjernede kapabiliteter og
  `no-new-privileges`;
- bruker en privat `/home/bridge`, et dedikert Claude-konfigurasjonsvolum, isolerte OmniRoute-data
  og et separat `devin-auth`-volum;
- monterer bare midlertidige `.sandbox`-arbeidsområder/-bevis;
- monterer ikke vertens hjemmekatalog, Keychain, SSH, skylegitimasjon eller Docker-socket;
- konstruerer eksplisitte miljøer og fjerner variabler for Anthropic API/OAuth/ruting;
- sender Claude Code-inferens bare til `http://omniroute:20128` med en nøkkel som kun gjelder lokalt.

Den frakoblede profilen bruker et internt nettverk. I den direkte profilen når OmniRoute de
offisielle Devin-endepunktene bare gjennom `network-guard`; urelaterte mål avvises.
Claude Code har en separat utgående sperre som avviser alt, og kan bare nå den lokale OmniRoute-
tjenesten gjennom `NO_PROXY`. Kontrollfiler for sperrene monteres bare av deres respektive sperreprosesser. Skriptene
verifiserer fileierskap, modus, antall lenker og hver beslutning før de eksporterer
tokenfrie bevis.

Kjør isolasjonsbeviset uavhengig:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

Det validerer topologi, navngitte monteringer, innstillinger for kjøring uten root og med skrivebeskyttelse, eksplisitt lokal ruting,
fravær av sensitive miljøvariabler, fravær av Docker-socket, blokkert tilgang til
`api.anthropic.com` og `claude.ai`, leverandørvalg som bare tillater Devin, og eksplisitt feil når
ACP-bakenden er utilgjengelig.

## Førstegangsoppsett og normal bruk

Bygg det versjonslåste imaget:

```bash
./scripts/devin-bridge/build
```

Autentiser bare det isolerte Devin-volumet:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

Innloggingskommandoen bruker den offisielle flyten med manuelt token, beregnet på eksterne miljøer og containermiljøer. Verdien angis direkte i CLI-ledeteksten. Den sendes ikke som et prosessargument, lagres i Git eller kopieres fra vertsmaskinen.

Start det isolerte Claude Code-kjøremiljøet:

```bash
./scripts/devin-bridge/launch
```

`launch` kontrollerer isolasjonen, Devin-autentiseringen og modelloppdagelsen på nytt før containerbasert Claude Code startes. Den kjører aldri vertsmaskinens Claude-programfil. Modellaliaser kan angis i `.env.devin-bridge`; alle konfigurerte verdier må beholde prefikset `devin-cli-agentic/`.

## Valideringskommandoer

Den reproduserbare frakoblede flyten krever ingen Devin-konto og har ingen Internett-tilgang under kjøring:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

Den autentiserte, eksplisitt aktiverte direkteflyten er:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

Direktekjøringen venter mellom scenarioene for å unngå å åpne ACP-økter i rask rekkefølge, og validerer strukturerte Claude-strømmehendelser i stedet for å stole på tekstlige påstander. De tre scenarioene bekrefter:

1. direkte lesing av prosjektet og feilanalyse;
2. en reell `Edit`, en klienteid `Bash`-kjøring av `npm test` og et terminalresultat;
3. `/bridge-check` samt oppdagelse av `bridge-proof`, lesing av prosjektet, nok en vellykket klienteid kjøring av `npm test` og fullføring uten ventende arbeid.

Den siste kontrollporten kontrollerer også Devin-nettverksrevisjonen og krever at Claude-utgående-revisjonen forblir tom.

## Oppdatering av versjonslåste verktøy

Imaget låser versjonene av Node, Claude Code og Devin CLI i `docker/devin-bridge/Dockerfile`. Slik oppdaterer du:

1. endre de eksplisitte versjonene;
2. erstatt kontrollsummene for Devin-arkivene for begge arkitekturer med verdier for den offisielle artefakten;
3. bygg på nytt og kjør alle frakoblede valideringskommandoer;
4. bekreft versjonene i imaget;
5. kjør den autentiserte direktepakken med tre scenarioer på nytt.

Ikke installer noen av CLI-verktøyene globalt på vertsmaskinen, og ikke erstatt kontrollsumverifisering med en ubekreftet nedlasting.

## Diagnostikk og opprydding

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  viser lokal ruting og rensede eksekveringsfeil.
- `.sandbox/evidence/mock-acp.jsonl` registrerer deterministiske simulerte ACP-handlinger.
- `.sandbox/evidence/claude-stream.jsonl` registrerer den virkelige frakoblede Claude Code-kjøringen.
- `.sandbox/evidence/live-*.jsonl` registrerer de tre validerte direktestrømmene.
- `.sandbox/evidence/egress.jsonl` og `.sandbox/evidence/claude-egress.jsonl` er validerte, tokenfrie kopier av sikkerhetskontrollenes revisjonslogger.

Stopp eide containere og nettverk, men behold innloggings- og konfigurasjonsvolumene:

```bash
./scripts/devin-bridge/clean
```

Fjern hele det broeide miljøet, inkludert navngitte volumer:

```bash
./scripts/devin-bridge/clean --all
```

## Begrensninger

- Broen er avhengig av den faste `summarizer`-rollen uten verktøy fordi Devin CLI `3000.2.17`
  ikke tilbyr en nøytral ACP-agent uten verktøy. Adapteren kompenserer for oppsummeringsformede
  mellomliggende svar, men ett avgrenset reparasjonsforsøk kan fortsatt mislykkes eksplisitt.
- Aktive ACP-kall kan returnere midlertidige `502`-/`504`-svar. Testverktøyet fordeler scenarioene
  over tid; vedvarende feil forblir lukket ved feil og velger aldri en annen leverandør.
- ACP-konteksten rekonstrueres fra hver Anthropic-forespørsel; det finnes ingen
  prosess-/sesjonstilhørighet.
- Ett verktøykall støttes per modellsvar; parallelle kall avvises.
- Bilder støttes eksplisitt ikke. Maskinsyn, resonneringsutdata, innsatskontroller og et
  kontekstvindu på 1M annonseres ikke.
- SSE bruker gyldige Anthropic-livssyklushendelser, men sendes først etter at den avgrensede
  ACP-runden er samlet inn; ACP-datablokker videresendes ikke fortløpende.
