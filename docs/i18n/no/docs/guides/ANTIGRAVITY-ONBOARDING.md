## 1. Antigravity kontra Antigravity CLI (agy)

Begge leverandørene bruker **den samme Google-backend-tjenesten** — identisk OAuth-klient, tokenoppdatering, endepunkter og Google-kontoer. Forskjellen er hvilke modeller du ser.

> Se [kunngjøringen av Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli) for Googles offisielle sammenligning.

| Aspekt                 | `antigravity` (IDE)                             | `agy` (CLI)                                           |
| ---------------------- | ----------------------------------------------- | ----------------------------------------------------- |
| **Google-produkt**     | Antigravity 2.0 / Antigravity IDE               | Antigravity CLI                                       |
| **Backend-tjeneste**   | Samme Google Cloud Code API                     | Samme Google Cloud Code API                           |
| **OAuth / token**      | Samme klient, samme oppdatering                 | Samme klient, samme oppdatering                       |
| **Modellkatalog**      | Statisk, kuratert liste (hardkodet i OmniRoute) | Hentes direkte fra Google via `:fetchAvailableModels` |
| **Claude-modeller**    | Sonnet 4.6, Opus 4.6 (4 varianter hver)         | Sonnet 4.6, Opus 4.6 (4 varianter hver)               |
| **Gemini-navngivning** | Tydelige etiketter (Low/Medium/High)            | Oppstrøms-ID-er (extra-low/low/agent)                 |
| **Ekstra modeller**    | `gpt-oss-120b-medium`                           | Kan inkludere flere modeller fra Google               |
| **Standardbruk**       | IDE-integrasjon (VS Code, JetBrains)            | CLI-/API-tilgang                                      |
| **Kvote**              | Delt med agy (samme Google-konto)               | Delt med antigravity (samme Google-konto)             |

**Tilgjengelige modeller (verifisert gjennom eksperiment, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (ulike resonneringsnivåer)
- Claude: Sonnet 4.6, Opus 4.6 (hver med variantene default/low/medium/high)
- Andre: GPT-OSS 120B Medium
- **Claude Sonnet 5 er IKKE tilgjengelig** — bare 4.6-variantene støttes

**Hvorfor modellkatalogen er forskjellig**: Googles CLI er «optimalisert for hastighet og lav ressursbruk» og «samoptimalisert med Gemini-modeller» (ifølge Googles offisielle blogg). Nett-/IDE-produktet er «optimalisert for helhetlig funksjonalitet». CLI-verktøyet bruker `:fetchAvailableModels` til å finne modeller dynamisk, mens IDE-produktet bruker en statisk, kuratert liste.

**I praksis**: Bruk prefikset `agy/` for Gemini-modeller (f.eks. `agy/gemini-3.7-flash-high`). Bruk `antigravity/` for den statiske, kuraterte listen. Begge bruker den samme Google-backend-tjenesten, men eksponerer ulik navngivning av modellene. Kvoten er delt — bruk av en av leverandørene teller mot grensene for den samme Google-kontoen.

## 2. Google One AI Pro: Kvotesystem

> Se [Antigravity-dokumentasjonen: Abonnementer](https://antigravity.google/docs/plans) for offisielle kvotedetaljer og [Endringer i Antigravity-abonnementer](https://antigravity.google/blog/changes-to-antigravity-plans) for de nyeste prisoppdateringene.

Google Antigravity bruker en **tolagskvote** basert på «Utført arbeid» (beregningsmessig belastning), ikke antall meldinger.

### De to lagene

| Lag                | Hva det er                        | Oppdateringssyklus                                                               |
| ------------------ | --------------------------------- | -------------------------------------------------------------------------------- |
| **5-timersøkt**    | Umiddelbar mengde «utført arbeid» | Tilbakestilles 5 timer etter den første forespørselen i en økt                   |
| **7-dagersgrense** | Ukentlig absolutt grense          | Overstyrer 5-timersoppdateringen hvis den nås; sperrer til neste 7-dagersperiode |

**Slik beregnes «Utført arbeid»**: Agentintensive oppgaver (f.eks. «Refaktorer hele dette repositoriet») bruker kvoten mye raskere enn enkle oppgaver (f.eks. «Rett denne funksjonen»). Det finnes ikke noe sanntidsdashbord som viser forbruket.

### Abonnementsnivåer

| Abonnement   | Pris         | Kvote                                     | Ukentlig grense                            |
| ------------ | ------------ | ----------------------------------------- | ------------------------------------------ |
| Free         | $0           | Betydelig kvote, oppdateres ukentlig      | Ja                                         |
| AI Pro       | $19.99/mnd.  | Høy kvote, rullerende 5-timersoppdatering | Ja (overstyrer 5-timersperioden hvis nådd) |
| AI Ultra 5x  | $99.99/mnd.  | 5x Pro-kvote                              | Ingen ukentlig grense                      |
| AI Ultra 20x | $199.99/mnd. | 20x Pro-kvote                             | Ingen ukentlig grense                      |

### Gemini- kontra ikke-Gemini-modeller

- **Gemini-modeller** (Flash + Pro): Deler én frekvensgrense, der forbruket beregnes ut fra API-priser. Hvis Flash er 8x billigere enn Pro, får du 8x flere Flash-tokener.
- **Ikke-Gemini-modeller** (Claude, GPT-OSS): Har **separate** frekvensgrenser. De kan fortsatt være tilgjengelige selv når Gemini er sperret.

### AI-kreditter (overforbruk)

> Se [Google One AI-kreditter](https://support.google.com/googleone/answer/14534406) for informasjon om hvordan kreditter fungerer.

Når grunnkvoten er brukt opp:

- **Aldri**: Vent til kvoten oppdateres; viser «Grunnkvoten for modellen er nådd»
- **Alltid**: Bruk AI-kreditter automatisk; bytter tilbake til grunnkvoten når den oppdateres

Kreditter kjøpes separat og trekkes etter standard API-priser.

### Viktige detaljer

- Kvoten **deles på kontonivå** — den samme Google-kontoen i Antigravity IDE, CLI og OmniRoute deler én kvotepott
- Hver Google-konto har sin egen uavhengige kvote — flere kontoer = flere kvotepotter
- AI Pro-brukere har rapportert **7-dagerssperrer** i stedet for tilbakestilling etter 5 timer når den ukentlige grunnkvoten nås (Google har bekreftet at dette er tilsiktet ved høy etterspørsel)

**Når kontoen din er tom for kvote**: OmniRoute prøver automatisk på nytt med den neste tilgjengelige kontoen i kombinasjonsruten. Ingen manuell inngripen er nødvendig.

## 3. Slik får du en projectId

Hver antigravity/agy-tilkobling trenger en Google Cloud Code-`projectId`. Uten denne returnerer endepunktet `/v1internal:models` 404.

### Metode A: Automatisk (anbefalt)

OmniRoute håndterer dette automatisk. Når du legger til en ny Google-konto via OAuth i dashbordet:

1. OmniRoute oppdaterer tokenet
2. Kaller `loadCodeAssist` for å finne projectId
3. Hvis det ikke finnes noe prosjekt, kalles `onboardUser` for å opprette et
4. Prøver `loadCodeAssist` på nytt for å hente den nyopprettede projectId
5. Lagrer den i databasen

**Dette fungerer for de fleste kontoer** — ingen manuelle trinn er nødvendige.

### Metode B: Manuelt via agy CLI

Hvis automatisk oppdagelse mislykkes (se del 5 for når dette skjer):

```bash
# Installer agy CLI (hvis den ikke allerede er installert)
npm install -g @anthropic-ai/agy

# Logg på med Google-kontoen din
agy login

# Velg kontoen som må registreres
# Dette utløser Cloud Code-registrering og tilordner en projectId
```

Når `agy login` er fullført, oppdaterer du tokenet i OmniRoute-dashbordet. projectId blir funnet automatisk.

### Slik bekrefter du det

Kontroller databasen:

```bash
# Inne i OmniRoute-containeren
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Eller kontroller loggene:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. OAuth-viderekoblings-URI

### Problemet

Google OAuth krever en gyldig viderekoblings-URI. OmniRoutes standardoppsett bruker `http://127.0.0.1:20128/callback` (tilbakekobling). Dette fungerer for lokale bygg, men **mislykkes ved eksterne distribusjoner** (f.eks. en server som åpnes via en LAN-IP).

Google avviser viderekoblings-URI-er som:

- Bruker IP-adresser (må være et domene som slutter på `.com`, `.org` osv.)
- Ikke samsvarer med de registrerte viderekoblings-URI-ene i OAuth-klientkonfigurasjonen

### Løsningen

**Alternativ A: Bruk den innebygde OAuth-flyten (standard)**

- Fungerer når du åpner OmniRoute fra `localhost` eller `127.0.0.1`
- Ingen konfigurasjon er nødvendig

**Alternativ B: Egendefinert OAuth-legitimasjon**

- Angi `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` i miljøet ditt
- Oppgi din egen Google OAuth-legitimasjon:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Registrer `https://your-domain.com/callback` som en autorisert viderekoblings-URI i Google Cloud Console

**Alternativ C: Bruk agy CLI for første innlogging**

- Kjør `agy login` på maskinen som skal få tilgang til OmniRoute
- OAuth-flyten fullføres lokalt, og tokenene lagres
- Importer tilkoblingen til OmniRoute via kontrollpanelet

### Begrensninger

- Egendefinert OAuth-legitimasjon krever et domenenavn (Google godtar ikke IP-adresser som viderekoblings-URI-er)
- Hvis du ikke har et domene, kan du bruke alternativ A eller C i stedet

## 5. Feilsøking: Når automatisk oppsett mislykkes

OmniRoute håndterer oppdagelse av projectId og innføring automatisk for de fleste kontoer. Når dette mislykkes, er grunnårsaken vanligvis én av følgende:

### Kontoregionen er blokkert

**Symptom**: `agy login` returnerer «Kvalifiseringskontrollen mislyktes: Den nåværende kontoen din er ikke kvalifisert for Antigravity fordi tjenesten for øyeblikket ikke er tilgjengelig der du befinner deg.»

**Grunnårsak**: Google-kontoer har et «Country Association»-felt i bakgrunnssystemet som angis ved registrering. agy CLI og Cloud Code API kontrollerer dette feltet strengt — i motsetning til Gemini på nettet, som bare kontrollerer den nåværende IP-adressen din.

> Gå til [Google-skjemaet for landstilknytning](https://policies.google.com/country-association-form) for å kontrollere eller endre regionen som er knyttet til kontoen din.

**Hvorfor Gemini på nettet fungerer, mens agy ikke gjør det**:

- Gemini på nettet / Google One: kontrollerer bare nåværende IP-adresse (proxy fungerer)
- agy CLI / Cloud Code API: leser «Country Association»-feltet i bakgrunnssystemet (proxy hjelper ikke)

**Løsning**:

1. Gå til [Google-skjemaet for landstilknytning](https://policies.google.com/country-association-form) mens du bruker en amerikansk IP-adresse
2. Send inn en forespørsel om regionendring (velg «Jeg bor i et annet land»)
3. Vent 1–24 timer mens Google behandler forespørselen og sender et e-postvarsel
4. Deretter skal `agy login` fungere

### Kontoen har ikke noe Cloud Code-prosjekt

**Symptom**: Loggene viser `loadCodeAssist returned no project id` og `onboardUser failed (400)`.

**Grunnårsak**: Kontoen har aldri blitt registrert med Google Cloud Code, og den automatiske innføringen mislyktes.

**Løsning**: Kjør `agy login` manuelt for å utløse Cloud Code-registrering, og oppdater deretter tokenet i OmniRoute-kontrollpanelet.

### Tokenet er utløpt eller tilbakekalt

**Symptom**: 401-feil i loggene eller meldinger om at «Tokenet er utløpt».

**Løsning**: Oppdater tokenet i Kontrollpanel → Leverandører → agy → Klikk på oppdateringsikonet. Hvis selve oppdateringstokenet er tilbakekalt, må du autentisere deg på nytt via OAuth.

## Beslutningsflytskjema

```
Fungerer ikke kontoen?
│
├─ Har den en projectId i databasen?
│  ├─ JA → Problemet ligger et annet sted (utløpt token, hastighetsbegrensning osv.)
│  └─ NEI ↓
│
├─ Er kontoens landtilknytning satt til en begrenset region?
│  ├─ JA → Endre region via Googles skjema for landtilknytning
│  │         (https://policies.google.com/country-association-form)
│  │         Vent i 1–24 timer, og prøv deretter på nytt
│  └─ NEI ↓
│
├─ Har kontoen et Google One AI Pro-abonnement?
│  ├─ NEI → Abonner først på one.google.com
│  └─ JA ↓
│
├─ Prøv automatisk oppdagelse (oppdater tokenet i kontrollpanelet)
│  ├─ Fungerer → Ferdig
│  └─ Mislykkes fortsatt ↓
│
└─ Manuelt: Kjør `agy login` på maskinen
   ├─ Fungerer → Oppdater tokenet i kontrollpanelet, projectId blir oppdaget
   └─ Mislykkes → Sjekk feilmeldingen; sannsynligvis et problem med region eller abonnement
```
