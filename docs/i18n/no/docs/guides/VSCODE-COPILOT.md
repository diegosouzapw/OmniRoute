**OmniCopilot** plasserer alle modellene som OmniRoute tilbyr, i den _innebygde_ modellvelgeren i GitHub Copilot Chat.
Ingen ekstra sidelinje, ikke noe separat chatgrensesnitt — Copilots agentmodus, verktøykall,
MCP-servere og egendefinerte instruksjoner fortsetter å fungere, bare med modellen du velger.

|                             |                                                                                                                                                 |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Installer (VS Code)**     | [Marketplace → `diegosouzapw.omnicopilot`](https://marketplace.visualstudio.com/items?itemName=diegosouzapw.omnicopilot)                        |
| **Installer (avledninger)** | [Open VSX](https://open-vsx.org/extension/diegosouzapw/omnicopilot) — Cursor, Windsurf, VSCodium, Theia, code-server, Gitpod, Antigravity, Kiro |
| **Kilde / problemer**       | [github.com/diegosouzapw/OmniCopilot](https://github.com/diegosouzapw/OmniCopilot) (MIT)                                                        |
| **Krever**                  | VS Code 1.104+                                                                                                                                  |

> **Krever ikke Copilot-abonnement.** Fra og med VS Code 1.122 fungerer en språkmodelltilbyder
> uten pålogging på GitHub og uten noen Copilot-plan. Innebygde kodeforslag og
> funksjoner basert på innebygginger ligger fortsatt utenfor provider-API-et og krever fortsatt Copilot.

## Oppsett

1. **Kjør OmniRoute** — `npm install -g omniroute && omniroute` (kontrollpanel på `http://localhost:20128`).
2. **Installer utvidelsen** — søk etter «OmniRoute» i utvidelsesvisningen.
3. **Velg en modell** — Copilot Chat → modellvelger → **Administrer modeller…** → **OmniRoute**, og merk deretter
   det du ønsker.

Ingenting må konfigureres når OmniRoute kjører på standardporten. For en ekstern instans åpner du
**OmniRoute-ikonet i aktivitetslinjen** (eller kjører `OmniRoute: Manage Connection`) og angir:

- **Server-URL** — serverroten, f.eks. `http://192.168.0.15:20128`. Suffikset `/v1`
  legges til av utvidelsen; ikke inkluder det.
- **API-nøkkel** — bare når serveren angir `REQUIRE_API_KEY`. Lagres i operativsystemets nøkkelring via VS
  Code SecretStorage, aldri i `settings.json`.

## Dette viser modellvelgeren

Utvidelsen viser ikke den ubehandlede nyttelasten fra `GET /v1/models` — den tilpasser den, og antallet du
ser, er lavere enn katalogstørrelsen av to bevisste grunner.

### Den ber om én ID per modell

`MODELS_CATALOG_PREFIX_MODE` bruker som standard **`dual`**, som annonserer hver modell to ganger — én gang
med det korte aliasprefikset og én gang med det kanoniske tilbyderprefikset — slik at eldre klientkonfigurasjoner
fortsatt kan slå opp begge formene:

```
cc/claude-sonnet-4-6        ← aliasprefiks
claude/claude-sonnet-4-6    ← kanonisk prefiks, samme modell
```

Utvidelsen sender en forespørsel til **`GET /v1/models?prefix=alias`**, slik at én ID mottas per modell, uten
å endre innstillingen for hele serveren for de andre klientene dine. På en referanseinstans reduserte dette
**2345 oppføringer til 1396 — 949 duplikater, ingen modeller gikk tapt.**

Hvis du heller vil løse dette på hele serveren for _alle_ klienter, setter du funksjonsflagget
`MODELS_CATALOG_PREFIX_MODE` til `alias` i kontrollpanelet. Se
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) for
spørringsparameteren og tabellen for hver modus.

### Den skjuler modeller som ikke kan brukes til chat

Katalogen viser også modeller for bilder, video, lyd, rerangering, innebygginger og moderering. Disse blir
uansett avvist ved en chatforespørsel:

```
HTTP 400 — Modellen '<id>' er en bildegenereringsmodell og kan ikke brukes på
/v1/chat/completions. Bruk POST /v1/images/generations i stedet.
```

Derfor filtreres de bort basert på `type`-feltet før de når modellvelgeren. **Responses-API-
modeller beholdes** — hver Codex- / GPT-5.x-oppføring annonserer `supported_endpoints: ["responses"]`,
og OmniRoute oversetter disse for `/v1/chat/completions`, slik at de kan brukes uten problemer.

### Tilbydere du aldri har konfigurert

Katalogen viser modeller fra tilbydere med en **aktiv tilkobling**, i tillegg til alle **noAuth**-
tilbydere — de nøkkelfrie tilbyderne som utgjør en stor del av gratisnivået. Dette er med hensikt. Hvis du vil skjule
dem, legger du dem til i `blockedProviders` i innstillingene i kontrollpanelet; ingenting endres i
utvidelsen.

## Kontrollpanel i en VS Code-fane

`omnicopilot.dashboardOpen: "editor"` viser OmniRoute-kontrollpanelet i en redigeringsfane via
Simple Browser i stedet for en ekstern nettleser. Innebygging er **valgfritt på serveren** gjennom
`DASHBOARD_ALLOW_EMBED=vscode`, som leverer HTML-sidene med
`frame-ancestors 'self' vscode-webview:` i stedet for standardinnstillingen `frame-ancestors 'none'` +
`X-Frame-Options: DENY`. API-grensesnittet (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) beholder de
strenge headerne uansett.

> ⚠️ **Dette er et byggtidsflagg, ikke et kjøretidsflagg.** Next.js kompilerer `headers()` inn i rute-
> manifestet, så `next.config.mjs` leser variabelen mens pakken bygges
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> Å eksportere den foran en server som allerede er bygd, endrer ingenting – headerne er bakt inn.

```bash
# variabelen må være tilgjengelig for BUILD-kommandoen
DASHBOARD_ALLOW_EMBED=vscode npm run build        # eller npm run build:release
npm start
```

| Slik installerte du        | Kan du aktivere innebygging?                                                                                                                            |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fra kildekode              | ✅ angi variabelen i byggkommandoen, som vist ovenfor                                                                                                   |
| `npm install -g omniroute` | ❌ den publiserte pakken leveres med en forhåndsbygd pakke – bygg fra kildekode i stedet                                                                |
| Docker-avbildning          | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` – den forhåndsbygde avbildningen på Docker Hub støtter ikke innebygging |

Uten en versjon som er bygd med støtte for innebygging, nekter siden å vises i en ramme. Utvidelsen
oppdager dette fra responsheaderne og går tilbake til den eksterne nettleseren – ingenting slutter å
virke, og den varsler om dette én gang. Se [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) og sak
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273).

## Konfigurere de andre verktøyene dine fra VS Code

**`OmniRoute: Configure Coding CLI`** bruker `omniroute`-CLI-et til å skrive bruksklare profiler
for Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code,
Kilo og Roo – de samme konfigurasjonene som er beskrevet i
[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md). API-nøkkelen sendes til CLI-et gjennom
miljøvariabelen `OMNIROUTE_API_KEY`, aldri på kommandolinjen.

## Feilsøking

| Symptom                                                          | Årsak/løsning                                                                                                                                                                                                                                                                |
| ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ingen OmniRoute-modeller i velgeren                              | Serveren kan ikke nås. Prikken på statuslinjen blir grå. Kjør `OmniRoute: Check Connection`. Oppdagelsen er bevisst lydløs og legger ikke til noen modeller i stedet for å vise en melding.                                                                                  |
| Hver modell vises to ganger                                      | Du bruker en OmniCopilot-versjon eldre enn 1.0.1 – oppdater. Utvidelsen ber nå om `?prefix=alias`.                                                                                                                                                                           |
| En bilde-/lydmodell som var oppført, er borte                    | Tilsiktet siden 1.0.1 – den kunne aldri svare på en chatforespørsel.                                                                                                                                                                                                         |
| Panelet mangler fra aktivitetslinjen                             | VS Code flytter ekstra visningsbeholdere til **"…"**-overløpsmenyen nederst på aktivitetslinjen, og en beholder som er skjult via høyreklikk, forblir skjult. Høyreklikk på aktivitetslinjen → merk av for **OmniRoute**, eller åpne den med `OmniRoute: Manage Connection`. |
| Kontrollpanelet åpnes i nettleseren til tross for `editor`-modus | Serveren ble ikke **bygd** med `DASHBOARD_ALLOW_EMBED=vscode` (se ovenfor) – å angi den ved oppstart for en forhåndsbygd installasjon har ingen effekt. Tilbakefallet er tilsiktet.                                                                                          |
| Modellisten er utdatert etter endring av leverandører            | `OmniRoute: Refresh Models`, eller ↻-lenken i panelet.                                                                                                                                                                                                                       |
