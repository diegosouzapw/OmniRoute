`@omniroute/opencode-plugin-v2` gjør hele OmniRoute-katalogen din — modeller, kombinasjoner og
automatiske kombinasjoner — tilgjengelig i modellvelgeren til OpenCode v2, med visningsnavn, priser og
budsjetter for gratisnivået.

Dette er en separat pakke fra `@omniroute/opencode-plugin` fordi OpenCode v1 og v2 laster inn
programtillegg gjennom ulike kontrakter. Velg den som samsvarer med hovedversjonen av OpenCode; ingenting
deles mellom dem, så en oppgradering av den ene fremtvinger aldri en oppgradering av den andre.

## Krav

- OpenCode v2.
- En tilgjengelig OmniRoute-gateway (`http://localhost:20128` som standard).
- Node.js 22 eller 24.

## Installasjon

Legg til programtillegget i `opencode.json`:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

Modellene vises deretter som `omniroute/<provider>/<model>`; `providerId` bestemmer dette prefikset og
ID-en til integrasjonen som OpenCode lagrer legitimasjonen under.

## Legitimasjon

Programtillegget ser etter en gateway-nøkkel på tre steder, i denne rekkefølgen:

1. **Legitimasjonen du koblet til i OpenCode.** Programtillegget registrerer en integrasjon, slik at
   OpenCodes egen autentiseringsflyt kan lagre nøkkelen. Ingenting havner i `opencode.json` — dette er å foretrekke.
2. `apiKey` i innstillingene for programtillegget, for en prosjektspesifikk overstyring. Dette legger nøkkelen i en fil du
   kanskje sjekker inn i versjonskontroll.
3. `OMNIROUTE_API_KEY` i miljøet.

Hvis ingen av de tre er angitt, er katalogen tom, og programtillegget opplyser om dette én gang ved oppstart i stedet for
å etterlate deg med en tom modellvelger uten noen forklaring.

### Administrasjonstokenet er en annen nøkkel

Kombinasjoner, leverandørstatus og berikelse (visningsnavn, priser og budsjetter for gratisnivået) kommer fra
gatewayens `/api/*`-endepunkter, som i de fleste distribusjoner er beskyttet av et **administrasjons**token
i stedet for inferensnøkkelen:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<administrasjonens lesetoken>"
}
```

Hvis `managementReadToken` ikke er angitt, brukes `apiKey` som reserve. Når en gateway avviser denne reserveløsningen,
publiseres katalogen fortsatt, men med rå modell-ID-er i stedet for visningsnavn, uten deduplisering av kanoniske
aliaser, priser eller kombinasjoner. Programtillegget advarer én gang per endepunkt når dette skjer,
og oppgir endepunktet og hva som gikk tapt — slik at en redusert modellvelger aldri er et mysterium.

## Alternativer

| Nøkkel                           | Standard                                             | Merknader                                                                                                    |
| -------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `providerId`                     | `"omniroute"`                                        | Leverandør-ID, integrasjons-ID og prefikset modellene vises under                                            |
| `baseURL`                        | påkrevd                                              | Gateway-rot, kun `http(s)`; suffikset `/v1` legges til der det er nødvendig                                  |
| `apiKey`                         | tilkoblet legitimasjon, deretter `OMNIROUTE_API_KEY` | Chat-nøkkel for `/v1/*`                                                                                      |
| `managementReadToken`            | bruker `apiKey` som reserve                          | Nøkkel for `/api/*` — vanligvis **ikke** den samme                                                           |
| `displayName`                    | `"OmniRoute"`                                        | Leverandørnavn i modellvelgeren                                                                              |
| `timeoutMs`                      | `10000`                                              | Tidsavbrudd per endepunkt for henting (automatiske kombinasjoner bruker 5 s)                                 |
| `modelCacheTtlMs`                | `300000`                                             | TTL for katalogbufferen; et øyeblikksbilde på disk gir raskere kaldstarter                                   |
| `timeouts`                       | bruker `timeoutMs` som reserve                       | Tidsbudsjetter per endepunkt i ms: `models`, `combos`, `autoCombos`, `enrichment`                            |
| `enrichment`                     | `true`                                               | Hent navn, priser og budsjetter for gratisnivået                                                             |
| `providerTag`                    | `true`                                               | Sett navnet på oppstrømsleverandøren som modellen rutes til, foran visningsnavnet                            |
| `usableOnly`                     | `false`                                              | Behold bare leverandører som gatewayen rapporterer som klargjort                                             |
| `visibleModels` / `hiddenModels` | `[]`                                                 | Tillatelseslister med nøyaktig samsvar eller suffikssamsvar; nektelse har forrang                            |
| `geminiSanitization`             | `true`                                               | Fjern JSON-Schema-nøkkelordene som Gemini avviser, fra verktøyskjemaer (`$ref`-verktøy videresendes uendret) |
| `apiFormat.allowAnthropic`       | `false`                                              | Rut ID-er på tillatelseslisten gjennom Anthropic API-blokken                                                 |
| `apiFormat.anthropicModels`      | `[]`                                                 | Fullstendige modell-ID-er som rutes til Anthropic                                                            |
| `logLevel` / `startupDebug`      | `warn` / `false`                                     | Detaljnivå for logging                                                                                       |

## Slik holdes katalogen oppdatert

Katalogen hentes ved behov og hurtigbufres i `modelCacheTtlMs`, og et diskøyeblikksbilde sørger for at den
sist kjente katalogen er tilgjengelig når gatewayen ikke kan nås — et driftsavbrudd koster deg bare
oppdatert informasjon. Modeller og kombinasjoner publiseres så snart de ankommer; automatiske kombinasjoner, leverandørlisten
og utvidelsesoverlegget flettes inn når de blir tilgjengelige, slik at ett tregt endepunkt ikke kan blokkere
hele velgeren.

Navnene inneholder det gatewayen vet: oppstrømsleverandøren som en modell rutes til, en `[Gratis]`-markør
og budsjettet som følger med — slik at to tilkoblinger som selger samme modell, fortsatt kan
skilles fra hverandre. Slå av prefikset med `"providerTag": false`.

Det finnes ingen kommando for manuell oppdatering: OpenCode v2-kommandoer er ledetekstmaler, ikke tilbakekall,
så en plugin kan ikke tilby en slik kommando. Oppdateringer følger TTL-en; verten blir bare bedt om å laste inn på nytt når
katalogen eller overlegget faktisk er endret, aldri én gang per oppdatering.

## Verktøykall i Gemini

Gemini avviser en hel forespørsel når verktøydeklarasjonene inneholder `$schema` eller
`additionalProperties`, og svarer med `400 INVALID_ARGUMENT`. Pluginen fjerner disse nøkkelordene fra
verktøyskjemaer som er ment for en Gemini-modell fra denne leverandøren, og lar alle andre forespørsler være urørt.
Et verktøy som inneholder en `$ref`, videresendes urørt i stedet for å bli renset, siden fjerning av
referansen ville utvidet skjemaet til å «godta hva som helst».
Angi `"geminiSanitization": false` for å slå det av.

## Feilsøking

| Symptom                                            | Årsak                                                                                                     |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Velgeren viser ingen OmniRoute-modell              | Ingen nøkkel ble funnet (sjekk oppstartsadvarselen), eller gatewayen kan ikke nås                         |
| Rå modell-ID-er, ingen kombinasjoner, ingen priser | Administrasjonsendepunktene avviste tokenet — angi `managementReadToken`                                  |
| En økt er festet til `opencode-<id>/…`             | v1-pluginen publiserte `opencode-<id>`; v2 publiserer kun `<id>`, så velg modellen på nytt under `<id>/…` |
