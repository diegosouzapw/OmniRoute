---

OmniRoute tilbyr **to** måter å bruke OpenAI Codex på:

| Leverandør             | Hvordan den kommuniserer med OpenAI                                                                                                                                                 | Forbehold om bruk                                                         |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| **`codex`**            | Videresender ChatGPT/OpenAI OAuth-tokenet ditt direkte til Responses API                                                                                                            | **Ja** — den offisielle økten er ikke autorisert for bruk via proxy/ruter |
| **`codex-app-server`** | Styrer **Codex CLI-ens egen `codex app-server`** over JSON-RPC/WebSocket; CLI-en eier og fornyer automatisk sin OAuth (`~/.codex/auth.json`), akkurat som en interaktiv `codex`-økt | **Nei** — OmniRoute videresender aldri et token til API-et                |

Fordi `codex-app-server` aldri videresender et token, gjelder ikke
bruksforbeholdet for videresending av økter. Den krever imidlertid en **Codex CLI
som er tilgjengelig på den konfigurerte app-server-URL-en**, og denne CLI-en må
være **logget inn**.

---

## 1. Arkitektur

```
┌─ OmniRoute-app ─────────────────┐        ┌─ codex-app-server-sidevogn ─────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ funksjonstoken)              │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  administrerer OpenAI OAuth selv    │
└──────────────────────────────────┘        │  (~/.codex/auth.json, autofornying) │
        │ deler (compose-volumer)            └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → WS-funksjonstokenet (begge monterer det)
  codex-appserver-home    → ~/.codex (auth.json skrives av kontrollpanelet,
                             leses av sidevognens codex app-server)
```

- Sidevognen lytter **bare** på det interne compose-nettverket
  (`ws://codex-app-server:1456`) bak et funksjonstoken. Den blir **aldri**
  eksponert mot verten eller internett.
- Codex CLI er innebygd i `omniroute:base`, så det er ikke nødvendig å installere
  codex på verten eller brukerens maskin når du kjører sidevognen.

## 2. Start den

```bash
# Start stakken MED sidevognprofilen for codex app-server:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

Sidevognen oppretter WS-funksjonstokenet sitt ved første oppstart (i det delte
`codex-appserver-token`-volumet), og appen leser det samme tokenet via
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE`. Ingen manuell konfigurering av token
er nødvendig.

## 3. Koble til + logg inn

1. Legg til en tilkobling for **OpenAI Codex (App-Server)** i kontrollpanelet.
   Ingen API-nøkkel eller token kreves (det er en leverandør uten autentisering
   — sidevognen håndterer autentiseringen).
2. Hvis sidevognens Codex CLI **ikke er logget inn ennå**, rapporterer
   helsesjekken for tilkoblingen _«kjører, men er ikke logget inn»_ (ikke en rød
   autentiseringsfeil). Bruk **Logg inn med ChatGPT**: Dette kjører Codex'
   standard enhets-OAuth i nettleseren din og skriver deretter
   `~/.codex/auth.json` til det delte volumet via **Bruk autentisering** (den
   samme innloggingen betjener både `codex`- og `codex-app-server`-leverandørene).
3. Når du er logget inn, blir helsesjekken grønn (den kontrollerer både `/readyz`
   **og** `account/read` — altså at tjenesten både kjører _og_ er autentisert), og
   tjenesten begynner å fungere.

Kontrollpanelet overskriver aldri en fungerende eksisterende
`~/.codex/auth.json` — det skriver bare når filen mangler eller tokenet er
utdatert (det tas alltid en sikkerhetskopi).

## 4. Distribusjonsscenarioer

- **Operatør med en allerede autentisert Codex CLI** — monter vertens
  `~/.codex` i sidevognen (`codex-appserver-home`), og hopp over
  innloggingstrinnet.
- **Offentlig bruker uten codex installert lokalt** — irrelevant: Sidevognen har
  CLI-en. Brukeren autentiserer seg bare gjennom kontrollpanelet.
- **OmniRoute direkte på maskinvaren (ingen sidevogn, codex på verten)** — pek
  `OMNIROUTE_CODEX_APPSERVER_WS` mot din egen `codex app-server`, og sørg for at
  codex på verten er logget inn. Hintet «codex er ikke installert» vises hvis den
  binære filen mangler.

## 5. Privatnett-/UDP-utgående trafikk (operatørtillegg, medfølger ikke)

Den generiske sidevognen ovenfor sender utgående trafikk over beholderens vanlige
nettverk. En operatør som trenger at Codex-trafikk går ut via en **utgang i et
privatnett** (f.eks. en TUN-tailscale-sidevogn som transporterer TCP + UDP/QUIC),
kjører dette som en separat compose-overstyring. Den er med hensikt **ikke** en
del av den medfølgende `codex-app-server`-profilen. Se den interne
driftshåndboken for dette oppsettet.
