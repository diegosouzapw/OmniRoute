Dette dokumentet beskriver implementeringsbeslutningen for
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854). De offentlige produktene er
representert som fire leverandørfamilier. Region er tilkoblingsdata, ikke et separat produkt.

## Beslutning

| Leverandørfamilie                             | OmniRoute-ID            | Global region | Kina-region |
| --------------------------------------------- | ----------------------- | ------------- | ----------- |
| Alibaba Cloud Model Studio (løpende betaling) | `alibaba`               | Singapore     | Beijing     |
| Alibaba Cloud Token Plan                      | `bailian-coding-plan`   | Singapore     | Beijing     |
| Qwen Cloud (løpende betaling)                 | `qwen-cloud`            | Global        | Beijing     |
| Qwen Cloud Token Plan                         | `qwen-cloud-token-plan` | Singapore     | Beijing     |

Den eksisterende ID-en `alibaba-cn` beholdes som et kompatibilitetsalias under kjøring for lagrede tilkoblinger, modellruter,
kombinasjoner og historisk bruk. Kortet i kontrollpanelet slås sammen med `alibaba`; ingen omskriving av
databasen er nødvendig.

Qwen Cloud med løpende betaling og Alibaba Cloud Model Studio deler for øyeblikket de DashScope-kompatible
vertene for kjøring, men de forblir separate leverandøridentiteter fordi brukerne henter nøkler og administrerer
kontoer gjennom ulike produktgrensesnitt. Produktene Alibaba og Qwen Cloud Token Plan bruker
ulike endepunktfamilier, så alle de fire produktene forblir separate leverandør-ID-er.

## Endepunktmatrise

| Leverandørfamilie       | `global-sg`                                                              | `china-beijing`                                                      | Dataformat |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ---------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI     |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic  |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI     |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI     |

API-nøkkelen og endepunktet må tilhøre samme produkt og region. Når en region velges, endres
det forhåndsinnstilte endepunktet som brukes ved validering og vanlige forespørsler.

## Tilkoblingskontrakt

Nye tilkoblinger lagrer den stabile regionnøkkelen i `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

Tillatte verdier er `global-sg` og `china-beijing`. Endepunktet utledes sentralt fra
leverandør-ID-en og regionen. En `providerSpecificData.baseUrl` som ikke er forhåndsinnstilt, forblir en eksplisitt
operatøroverstyring og har forrang, mens gamle lagrede forhåndsinnstilte URL-er normaliseres tilbake til den regionale
matrisen.

Dette gjør tilkoblingsskjemaet utvidbart: En ny region kan legges til i oppslagsmekanismen uten å
opprette et nytt leverandørkort eller endre lagrede leverandør-ID-er.

## Kompatibilitet og utrulling

1. Legg til den regionale endepunktløseren, og behold gjeldende globale standardverdier.
2. Bruk aktiv regional DashScope `/models`-oppdagelse for `alibaba`, kompatibilitets-ID-en
   `alibaba-cn` og `qwen-cloud`. Svarene deres sendes først gjennom ett filter for tekstgenerering
   fordi det generiske endepunktet også returnerer modeller for bilder, video, lyd, innebygginger
   og andre modeller som ikke er chatmodeller. `qwen-cloud` bruker deretter den vedlikeholdte
   tillatelseslisten som er deklarert i leverandørregisteret. Alibaba Model Studio og Qwen Cloud
   beholder separate kuraterte kataloger, selv om de for øyeblikket deler kjøretidsverter.
3. Registrer `qwen-cloud-token-plan` med den gjeldende tillatelseslisten for tekstmodeller i Token Plan.
4. Legg til en typet regionvelger i dialogene for å legge til og redigere tilkoblinger.
5. Skjul det dupliserte `alibaba-cn`-kortet, og inkluder de eksisterende tilkoblingene på
   leverandørsiden for `alibaba`.
6. Behold egendefinerte endepunktsoverstyringer for avanserte og arbeidsområdespesifikke utrullinger.

Mediemodeller i Token Plan forblir utenfor chatkatalogen fordi de bruker dedikerte endepunkter.
`wan2.7-image` og `wan2.7-image-pro` er registrert i `open-sse/config/imageRegistry.ts`;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` og `happyhorse-1.1-r2v` er registrert i
`open-sse/config/videoRegistry.ts`. Begge registrene gjenbruker tilkoblingsidentiteten
`qwen-cloud-token-plan` og dennes regionspesifikke legitimasjon.

Vanlig Qwen Cloud har separate bruksbaserte bilde- og videokataloger under identiteten
`qwen-cloud`. Bildemodellene er `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` og `z-image-turbo`. Videomodellene
er `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` og
`wan2.7-videoedit`. Disse modellene gjenbruker bare den vanlige `qwen-cloud`-tilkoblingen og det
regionale DashScope-medieendepunktet. Registrene for Token Plan og bruksbasert betaling arver eller
slår ikke sammen hverandres modellister.

Identiteten `bailian-coding-plan` har også egne tillatelseslister for medier:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` og `qwen-image-2.0-pro` for
bildegenerering, samt
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` og `happyhorse-1.1-r2v` for
videogenerering. Den bruker bare Bailian Coding Plan-tilkoblingen og det regionale Coding Plan-endepunktet.
Bilde- og videoregistrene arver ikke fra eller slås sammen med noen av Qwen Cloud-leverandørene.

Den vanlige `alibaba`-identiteten har separate tillatelseslister for bilder og video. Bildemodellene
er `qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` og `wan2.6-t2i`. De tilføyde videomodellene er `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` og `wan2.7-videoedit`. Disse modellene bruker bare Alibaba Model Studio-
tilkoblingen og det valgte regionale medieendepunktet; de legges ikke til i noe Coding Plan- eller
Qwen Cloud-register.

Chatkatalogen for Qwen Cloud Token Plan følger den eksakte teksttillatelseslisten for Individual-abonnementet:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` og
`deepseek-v4-pro`. Wan- og HappyHorse-oppføringer tilhører de separate API-ene for bilde-/videogenerering.

Alibaba Token Plan eksponerer de samme seks gjeldende modell-ID-ene for tekstgenerering gjennom sitt
Anthropic-kompatible endepunkt. Singapore-alternativet lagrer den eksisterende regionnøkkelen `global-sg`;
bare den brukervendte etiketten skiller seg fra leverandørfamilier som kaller regionen Global.

Den vanlige chatkatalogen for Qwen Cloud er med hensikt smalere enn hele den aktive tekstresponsen. Den
vedlikeholdte tillatelseslisten ligger i `open-sse/config/providers/registry/qwen-cloud/index.ts`; aktiv
oppdagelse returnerer bare ID-er som finnes både i oppstrømsresponsen og i denne registerlisten.

Alibaba Model Studio følger den samme regelen for aktivt snitt med sin uavhengig vedlikeholdte
tillatelsesliste i `open-sse/config/providers/registry/alibaba/index.ts`. Kompatibilitetsleverandøren
`alibaba-cn` gjenbruker denne katalogen, samtidig som oppdagelsen løses mot Beijing-endepunktet.
