> av verktøy og konfigurering av omfang finnes i `open-sse/mcp-server/server.ts`.

## Hva det er

OmniRoute kobler til et **Obsidian**-hvelv som en **kontekstkilde** — en lokal Markdown-
kunnskapsbase som agenter leser fra og skriver til gjennom den innebygde MCP-serveren.
Integrasjonen kommuniserer med fellesskapstillegget **Obsidian Local REST API**, som kjører
i skrivebordsappen, slik at agenter kan søke i notater, lese/skrive/oppdatere filer, vise
innholdet i hvelvet, arbeide med daglige/ukentlige periodiske notater, administrere
tagger, kjøre Obsidian-kommandoer og (valgfritt) koordinere toveis synkronisering av
hvelvet mellom skrivebord↔mobil.

Klienten (`src/lib/obsidian/api.ts`) kapsler inn Local REST API med:

- **Nye forsøk med eksponentiell ventetid** for midlertidige `5xx`-feil og **30 sekunders tidsavbrudd** via `AbortController`.
- **Typebasert feilklassifisering** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- Et **brukervennlig hint om at Obsidian ikke kan nås**, som fremhever den vanlige
  portfeilen (HTTP på `27123`, **ikke** MCP-endepunktet på `27124`) og Tailscale-formatet.
- **Banekoding** relativt til hvelvet, slik at notatbaner med mellomrom/skråstreker er trygge.

## Oppsett

Det finnes **ingen miljøvariabel** for Obsidian-tokenet eller basis-URL-en — begge lagres
i SQLite-tabellen `key_value` (navnerommet `obsidian`) via
`src/lib/db/obsidian.ts`. Tokenet er **kryptert ved lagring** (AES-256-GCM, med
bakoverkompatibel reserve for klartekst). Konfigurer fra fanen **Kontekstkilder** i
endepunktets kontrollpanel (`ObsidianSourceCard`), eller via REST-API-et for innstillinger.

> [!IMPORTANT]
> Tillegget **Obsidian Local REST API** må være installert og kjøre. REST-
> grensesnittet lytter på **HTTP `127.0.0.1:27123`** (standard basis-URL). Port `27124`
> er et _separat_ MCP/HTTPS-endepunkt og avvises uttrykkelig av innstillingsruten.
> Hvis du kobler til fra en annen enhet, bruker du `http://<tailscale-ip>:27123`.

### Konfigurasjonsnøkler (SQLite `key_value`, navnerommet `obsidian`)

| Nøkkel            | Formål                                                | Kryptert |
| ----------------- | ----------------------------------------------------- | -------- |
| `api_key`         | Bearer-token for Local REST API                       | ja       |
| `base_url`        | REST-basis-URL (standard `http://127.0.0.1:27123`)    | nei      |
| `vault_path`      | Absolutt bane til hvelvkatalogen (for synkronisering) | nei      |
| `webdav_username` | Generert WebDAV-brukernavn (hvelvsynkronisering)      | nei      |
| `webdav_password` | Generert WebDAV-passord (hvelvsynkronisering)         | ja       |
| `webdav_enabled`  | Om WebDAV-synkronisering av hvelvet er aktivert       | nei      |

### Konfigurer via REST

```bash
# Lagre og valider Local REST API-tokenet (POST validerer via en statuskontroll)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Kontroller tilkoblingsstatusen (returnerer connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# Koble fra (sletter det lagrede tokenet)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Alle metodene krever autentisering i kontrollpanelet. `POST` avviser alle URL-er på port
`27124` og validerer tokenet ved å kalle statusendepunktet til Local REST API før lagring.

### WebDAV-synkronisering av hvelv

`src/app/api/settings/obsidian/webdav/route.ts` administrerer en valgfri WebDAV-basert
synkronisering av hvelvet (drevet av `src/lib/obsidianSync.ts`). Når den aktiveres,
peker OmniRoute på en lokal hvelvkatalog og oppretter et tilfeldig WebDAV-brukernavn
og -passord:

```bash
# Aktiver WebDAV-synkronisering for en hvelvkatalog (oppretter brukernavn/passord)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# Hent status for WebDAV-synkronisering (legitimasjon returneres bare mens den er aktivert)
curl http://localhost:20128/api/settings/obsidian/webdav

# Deaktiver WebDAV-synkronisering (sletter legitimasjon og administrert .stignore)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Kontekstkilde per API-nøkkel (valgfritt)

Obsidian-konfigurasjonen kan avgrenses **per API-nøkkel** via tabellen
`api_key_context_sources` (`src/lib/db/apiKeyContextSources.ts`). Når et MCP-kall
inneholder en autentisert API-nøkkel-ID, foretrekker `getObsidianConfigForApiKey()`
nøkkelens eget token, basis-URL og hvelvbane (`source: "api_key"`), og bruker ellers
den globale konfigurasjonen som reserve (`source: "global"`).

## MCP-verktøy (22)

Definert i `open-sse/mcp-server/tools/obsidianTools.ts`. Tokenet og basis-URL-en løses
per kall (først per API-nøkkel, deretter globalt). Verktøy som bruker OmniRoute-**synkroniseringsserveren**
(de fire `obsidian_sync_*`-verktøyene), krever i tillegg autentiseringstokenet for synkronisering som er konfigurert
i OmniRoute-innstillingene.

### Leseverktøy (`read:obsidian`)

| Verktøy                      | Beskrivelse                                                                                           |
| ---------------------------- | ----------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Kontroller om det lokale REST-API-et er tilgjengelig og autentisert.                                  |
| `obsidian_search_simple`     | Fulltekstsøk i notatinnhold; returnerer utdrag med filbaner.                                          |
| `obsidian_search_structured` | Søk ved hjelp av et JSON Logic-uttrykk (and/or/regex/path-filtre).                                    |
| `obsidian_read_note`         | Les et notat etter hvelvrelativ bane; eventuelt en bestemt overskrift/blokk/frontmatter.              |
| `obsidian_list_vault`        | List opp filer og mapper i hvelvet (trestruktur med oppføringer).                                     |
| `obsidian_get_document_map`  | Hent notatets overskriftsstruktur som en tilordning av overskrifter → linjenumre.                     |
| `obsidian_get_note_metadata` | Hent frontmatter, tagger, lenker og antall tegn/ord uten hele innholdet.                              |
| `obsidian_get_active_file`   | Hent banen og innholdet til filen som er aktiv i Obsidian.                                            |
| `obsidian_get_periodic_note` | Hent det daglige/ukentlige/månedlige periodiske notatet for en dato (i dag hvis utelatt).             |
| `obsidian_get_tags`          | List opp alle tagger i hvelvet med forekomstfrekvens.                                                 |
| `obsidian_list_commands`     | List opp tilgjengelige Obsidian-kommando-ID-er (brukes med `obsidian_execute_command`).               |
| `obsidian_sync_status`       | Status for OmniRoute-synkroniseringsserveren: kjører, hvelvnavn, port, oppetid, siste synkronisering. |
| `obsidian_sync_conflicts`    | List opp uløste synkroniseringskonflikter (bane, konfliktbane, tidspunkt for oppdagelse).             |

### Skriveverktøy (`write:obsidian`)

| Verktøy                          | Beskrivelse                                                                                                     |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Opprett eller overskriv et notat med angitt Markdown-innhold.                                                   |
| `obsidian_append_note`           | Legg til innhold i et notat; eventuelt under en bestemt overskrift/blokk.                                       |
| `obsidian_patch_note`            | Legg presist til foran/bak eller erstatt ved en overskrift, blokk eller et frontmatter-felt.                    |
| `obsidian_delete_note`           | Slett et notat permanent fra hvelvet.                                                                           |
| `obsidian_move_note`             | Flytt eller gi nytt navn til et notat i hvelvet.                                                                |
| `obsidian_execute_command`       | Utfør en Obsidian-kommando ved hjelp av kommando-ID-en.                                                         |
| `obsidian_open_file`             | Åpne en fil i Obsidian (oppretter den hvis den ikke finnes).                                                    |
| `obsidian_sync_trigger`          | Utløs en umiddelbar toveis synkronisering av hvelvet mellom skrivebord↔mobil.                                   |
| `obsidian_sync_resolve_conflict` | Løs en synkroniseringskonflikt: behold `local` (mobil), `remote` (skrivebord) eller `keep-both` (behold begge). |

> [!NOTE]
> Mål for `obsidian_patch_note` godtar `targetType` med verdiene `heading | block | frontmatter`
> og `operation` med verdiene `append | prepend | replace`, med en valgfri
> `createTargetIfMissing`. De fire `obsidian_sync_*`-verktøyene kommuniserer med den lokale synkroniseringsserveren
> (`http://127.0.0.1:27781` som standard) og krever synkroniseringstokenet.

### Tilgangsområder

Leseverktøy krever `read:obsidian`; skriveverktøy krever `write:obsidian`. Håndhevingen
er identisk med Notion — håndteres av `withScopeEnforcement()` i
`open-sse/mcp-server/server.ts`, styres av `OMNIROUTE_MCP_ENFORCE_SCOPES=true`, med
tillatte tilgangsområder hentet fra `OMNIROUTE_MCP_SCOPES` eller API-nøkkelens tilgangskontekst. Se
[MCP-SERVER.md](./MCP-SERVER.md).

## Endepunkter

| Metode   | Bane                            | Formål                                                                |
| -------- | ------------------------------- | --------------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | Returnerer `{ connected, hasToken, baseUrl, vaultPath }`.             |
| `POST`   | `/api/settings/obsidian`        | Lagrer og validerer tokenet (avviser port `27124`).                   |
| `DELETE` | `/api/settings/obsidian`        | Kobler fra (sletter det lagrede tokenet).                             |
| `GET`    | `/api/settings/obsidian/webdav` | WebDAV-synkroniseringsstatus og påloggingsinformasjon (når aktivert). |
| `POST`   | `/api/settings/obsidian/webdav` | Aktiverer WebDAV-synkronisering for en hvelvmappe.                    |
| `DELETE` | `/api/settings/obsidian/webdav` | Deaktiverer WebDAV-synkronisering.                                    |

> Dette er innstillingsruter for kontrollpanelet. Selve hvelvet nås via Obsidians
> lokale REST-API (den konfigurerte `base_url`) og via MCP-verktøyene ovenfor — det finnes
> ikke noe offentlig `/v1`-proxyendepunkt for Obsidian.

## Bruksområder

- **Svar basert på hvelvet** — `obsidian_search_simple` / `obsidian_search_structured`
  og deretter `obsidian_read_note`, slik at en agent svarer basert på de faktiske notatene dine.
- **Oppretting av notater / journalføring** — `obsidian_write_note`, `obsidian_append_note` eller
  den presise `obsidian_patch_note` for å loggføre agentresultater, sammendrag eller daglige notater
  (`obsidian_get_periodic_note`) i hvelvet.
- **Navigering i hvelvet** — `obsidian_list_vault`, `obsidian_get_document_map` og
  `obsidian_get_tags` for å utforske strukturen før lesing/skriving.
- **Obsidian-automatisering** — `obsidian_list_commands` + `obsidian_execute_command` for å
  styre programtillegg/kommandoer fra en agent; `obsidian_open_file` for å vise et notat i brukergrensesnittet.
- **Mobilsynkronisering** — aktiver WebDAV-synkronisering, og bruk deretter `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  for å koordinere datamaskin↔mobil og løse konflikter.
