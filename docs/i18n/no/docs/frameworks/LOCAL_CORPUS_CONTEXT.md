## Hva det er

Local Corpus lar en operatør gjøre én eksplisitt godkjent katalog med tekstfiler tilgjengelig for
OmniRoutes MCP-server. Filene forblir i den opprinnelige katalogen: OmniRoute lagrer bare
den kanoniske rotbanen i SQLite og vedlikeholder en søkeindeks i minnet. Korpusinnhold
kopieres ikke til repositoriet eller databasen.

Indeksen oppdateres trinnvis. Uendrede filer gjenbrukes basert på størrelse og endringstid,
endrede filer leses på nytt og hashes med SHA-256, og slettede filer fjernes.
Søk oppdaterer en indeks som er eldre enn 30 sekunder. Kallere kan også be om en umiddelbar
oppdatering.

## Konfigurer kilden

Innstillingsruten krever samme administrasjonsautentisering som andre innstillings-API-er.
Den innsendte banen må allerede finnes og må være en absolutt katalogbane.

```bash
# Koble til en godkjent katalog
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# Kontroller konfigurasjon og indeksstatus
curl http://localhost:20128/api/settings/local-corpus

# Koble fra uten å endre kildefilene
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## MCP-verktøy

Alle tre verktøyene krever `read:local-corpus`. Verktøysvar viser relative baner og
navnet på rotkatalogen, aldri den absolutte banen.

| Verktøy               | Beskrivelse                                                                                 |
| :-------------------- | :------------------------------------------------------------------------------------------ |
| `local_corpus_status` | Rapporter konfigurasjonsstatus, indeksstørrelse, grenser og tidspunkt for siste oppdatering |
| `local_corpus_search` | Søk i indeksert tekst og returner avgrensede utdrag på linjenivå (opptil 20 resultater)     |
| `local_corpus_read`   | Les et avgrenset linjeområde fra én tillatt korpusrelativ fil                               |

Eksempler på MCP-inndata:

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## Sikkerhetsgrenser

- Tillatelseslisten er tekstorientert: `.cfg`, `.csv`, `.geojson`, `.htm`, `.html`, `.ini`,
  `.js`, `.json`, `.jsonl`, `.jsx`, `.log`, `.md`, `.mjs`, `.ps1`, `.py`, `.sh`,
  `.sql`, `.toml`, `.ts`, `.tsx`, `.txt`, `.xml`, `.yaml` og `.yml`.
- Symbolske lenker hoppes over. Lesebaner kanoniseres og må forbli innenfor den
  konfigurerte roten. Absolutte baner og forsøk på katalogtraversering avvises.
- Sensitive og genererte katalognavn utelukkes: `.build`, `.codex`, `.env`,
  `.git`, `.next`, `.omniroute`, `.ssh`, `coverage`, `dist`, `node_modules` og
  `secrets`.
- Standardgrensene er 5 000 filer, 1 MiB per fil, totalt 64 MiB indeksert innhold,
  omtrent 4 000 tegn per søkedel og 400 linjer per lesing.
- Filer som inneholder NUL, behandles som ikke-tekst og hoppes over eller avvises.

Binære dokumenter som PDF, DOCX, bilder og arkiver støttes med hensikt ikke.
Konverter dem til et godkjent tekstformat i den konfigurerte katalogen før indeksering.

## Driftsmerknader

- Endring eller sletting av den konfigurerte roten tømmer den delte indeksen i minnet.
- En omstart av prosessen forkaster indeksen. Det neste søket bygger den opp igjen fra den konfigurerte
  kilden.
- `local_corpus_status` fremtvinger ikke en skanning. Bruk `local_corpus_search` med
  `refresh: true` når en umiddelbar ny skanning er nødvendig.
- Skannings- og lesefeil telles eller returneres som rensede feilmeldinger. Kildefiler
  endres aldri.
