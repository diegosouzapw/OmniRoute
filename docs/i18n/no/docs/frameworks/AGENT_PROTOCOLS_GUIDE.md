> **Kilde:** `src/lib/{a2a,acp,cloudAgent}/`, `src/app/api/{a2a,acp,cloud}/`, `src/app/api/v1/agents/`
> **Sist oppdatert:** 2026-06-28 — v3.8.40

OmniRoute tilbyr tre forskjellige grensesnitt relatert til agenter. Ved første øyekast ser de like ut, men de løser forskjellige problemer. Bruk denne siden til å velge det riktige.

## Kort fortalt

| Grensesnitt                        | Best egnet for                                                                                                                                   | Transport                            | Standard              |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------ | --------------------- |
| **A2A — agent-til-agent**          | Samarbeid på tvers av agenter med andre agenter som støtter A2A-protokollen                                                                      | JSON-RPC 2.0 over HTTP               | A2A v0.3 (åpen spes.) |
| **ACP — register for CLI-agenter** | Oppdaging / registrering / oppstart av CLI-kodeagenter som er installert på brukerens maskin (Cursor, Cline, Codex CLI, Claude Code, Aider osv.) | HTTP REST                            | OmniRoute-spesifikk   |
| **Skyagenter**                     | Innsending av langvarige kodeoppgaver til eksterne skytjenester (Codex Cloud, Devin, Jules, Cursor Cloud)                                        | HTTP REST + databasebaserte oppgaver | OmniRoute-spesifikk   |

De tre er uavhengige av hverandre — velg hvilken som helst kombinasjon.

## Beslutningstre

```
Trenger du en skytjeneste til å utføre arbeid utenfor denne maskinen (Codex Cloud / Cursor Cloud / Devin / Jules)?
├─ JA → Skyagenter (POST /api/v1/agents/tasks)
└─ NEI → Fortsett
    │
    Har du en annen agent som støtter A2A og ønsker å samarbeide?
    ├─ JA → A2A (POST /a2a)
    └─ NEI → Fortsett
        │
        Trenger du å liste opp / konfigurere CLI-kodeagenter som er installert lokalt?
        ├─ JA → ACP (GET /api/acp/agents)
        └─ NEI → Bruk vanlig /v1/chat/completions
```

## 1. A2A — agent-til-agent

**Spesifikasjon:** [A2A v0.3](https://a2a-protocol.org)
**OmniRoute-endepunkt:** `POST /a2a` (JSON-RPC 2.0)
**Agentkort:** `GET /.well-known/agent.json`

### Når det bør brukes

- Når du bygger et multiagentsystem der OmniRoute er én av deltakerne
- Når du eksponerer OmniRoutes rutingsintelligens (smart-routing, quota-management osv.) for agenter i rammeverk som Google ADK eller generiske agentnettverk
- Når du legger OmniRoute bak et standardisert grensesnitt for oppdagelse og aktivering

### Metoder

- `message/send` — send inn en melding og motta et synkront svar
- `message/stream` — send inn en melding og motta SSE-strømmede fremdriftshendelser
- `tasks/get` — les en oppgave etter ID
- `tasks/cancel` — avbryt en oppgave som kjører

### Innebygde ferdigheter (6)

- `smart-routing` — rut en ledetekst gjennom den optimale kombinasjonen
- `quota-management` — rapporter kvotestatus per leverandør
- `provider-discovery` — list opp installerte leverandører med funksjonalitet
- `cost-analysis` — beregn kostnaden for en forespørsel/samtale
- `health-report` — sammenstill status for sikring/nedkjøling/utestenging per leverandør
- `list-capabilities` — list opp agentens tilgjengelige ferdigheter og metadata

### Fordypning

Se [A2A-SERVER.md](./A2A-SERVER.md) for transportdetaljer, agentkortets struktur, konfigurasjon av oppgavenes TTL og malen for å legge til nye ferdigheter.

## 2. ACP — register for CLI-agenter

**OmniRoute-endepunkt:** `GET /api/acp/agents`
**Kilde:** `src/lib/acp/{index,manager,registry}.ts`

### Hva det er

ACP er OmniRoutes **lokale oversikt over CLI-agenter**. Det oppdager hvilke kode-CLI-er som er installert på verten (Cursor, Cline, Claude Code, Codex CLI, Continue osv.), finner versjonene deres og gjør dem tilgjengelige i kontrollpanelet, slik at brukeren kan konfigurere hver CLI til å peke mot OmniRoute.

Dette er IKKE en ekstern protokoll — det er et internt register som driver brukergrensesnittet «CLI-verktøy» og sporing av CLI-fingeravtrykk (se [CLI-TOOLS.md](../reference/CLI-TOOLS.md)).

### Hva det gjør

- Undersøker verten etter installerte CLI-binærfiler (bruker `which` / `where` avhengig av operativsystem)
- Leser versjonen til hver CLI (kaller `<bin> --version`)
- Godtar eventuelt brukerdefinerte, tilpassede agenter (bane til binærfil + versjonskontroll + oppstartsargumenter)
- Lagrer tilpassede agenter i innstillingene
- Returnerer den samlede listen til kontrollpanelet

### REST-API

| Endepunkt         | Metode | Beskrivelse                                                           | Autentisering |
| ----------------- | ------ | --------------------------------------------------------------------- | ------------- |
| `/api/acp/agents` | GET    | Vis oppdagede + tilpassede agenter (antall installerte/totalt)        | API-nøkkel    |
| `/api/acp/agents` | POST   | Legg til/oppdater/fjern tilpasset agent (handlingsskille i innholdet) | API-nøkkel    |

Format på innholdet for POST (`customAgentBodySchema` i `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Brukstilfeller

- Siden «CLI-verktøy» i kontrollpanelet viser hva som er installert, og hjelper deg med å konfigurere hvert verktøy til å peke mot OmniRoute
- Tilpassede agenter lar avanserte brukere registrere interne/proprietære CLI-er som OmniRoute ikke kjenner til som standard
- Deteksjonsresultatet brukes i fingeravtrykksmatrisen for `cli-tools`

### Når ACP IKKE skal brukes

- ACP _kjører_ ikke oppgaver. Det oppdager og konfigurerer bare CLI-er. For å faktisk kalle en CLI må du starte den selv med miljøvariablene som OmniRoute oppgir (`OPENAI_BASE_URL`, `OPENAI_API_KEY` osv.).

## 3. Skyagenter

**OmniRoute-endepunkter:** `/api/v1/agents/tasks/*` (livssyklus) + `/api/cloud/*` (infrastruktur)
**Kilde:** `src/lib/cloudAgent/`

### Hva det er

Et enhetlig grensesnitt mot tredjeparts kodeagenter i skyen. Du sender inn en ledetekst + URL-adressen til et kodelager, og OmniRoute videresender oppgaven til riktig skyagent, sjekker status og returnerer resultatene.

### Støttede agenter (4, alle bekreftet i `src/lib/cloudAgent/agents/`)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### Livssyklus

```
POST /api/v1/agents/tasks
  → BaseAgent.createTask() per agentklasse
  → ekstern tjeneste starter arbeidet
  → oppgaverad opprettes i databasen (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → utsatt statussynkronisering fra leverandøren
  → returnerer gjeldende status + plan + aktivitetslogg
  ↓
POST /api/v1/agents/tasks/[id]   (handling: "approve" | "message" | "cancel")
  → videresender til leverandøren (eller markerer som avbrutt lokalt)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → lokal avbrytelse
```

### Autentisering

⚠️ **Alle endepunkter under `/api/v1/agents/tasks/*` krever administrasjonsautentisering** (commit `588a0333`). Kall som bare bruker bearer-autentisering, mottar 401 siden v3.8.0.

### Fordypning

Se [CLOUD_AGENT.md](./CLOUD_AGENT.md) for `CloudAgentBase`-kontrakten, agentspesifikke detaljer, skjemadetaljer og endepunkter for håndtering av påloggingsopplysninger.

## Sammenligning: A2A kontra skyagenter

Begge har «langvarige oppgaver», men på forskjellige lag:

| Aspekt               | A2A                                                                                         | Skyagenter                                 |
| -------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------ |
| Standard             | Åpen A2A v0.3                                                                               | OmniRoute-spesifikk                        |
| Hvor kjøringen skjer | Inne i OmniRoute (bruker konfigurerte kombinasjoner)                                        | Eksternt (Codex- / Devin- / Jules-servere) |
| Oppgavevarighet      | Standard TTL på 5 min (kan konfigureres i `TaskManager`)                                    | Minutter til timer                         |
| Repositoriebevisst   | Nei (videresender bare instruksjoner)                                                       | Ja (repo-URL + gren)                       |
| Bruksområde          | Samarbeid mellom agenter, smart ruting som en tjeneste                                      | Deleger «implementer funksjon X i repo Y»  |
| Autentisering        | Valgfri `OMNIROUTE_API_KEY` for `/a2a`; administrasjon for REST-hjelpere under `/api/a2a/*` | Alltid administrasjon                      |

## Integrasjonseksempler

### Oppdag OmniRoutes A2A-funksjoner

```bash
curl http://localhost:20128/.well-known/agent.json
```

Returnerer agentkortet med alle de seks ferdighetene, transportene og versjonen.

### Kall OmniRoute som en A2A-agent

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### Vis installerte CLI-agenter via ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Legg til en egendefinert CLI-agent

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### Send inn en skyagentoppgave

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### Kontroller statusen for en skyoppgave

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## Når du bør bruke hva

- **Chatbot-/copilot-grensesnitt** → `/v1/chat/completions` (OpenAI-kompatibelt – ikke en agentprotokoll)
- **Samarbeid mellom flere agenter** → A2A
- **Visning av lokale CLI-er i kontrollpanelet** → ACP
- **Delegering av langvarige kodeoppgaver til skytjenester** → skyagenter
