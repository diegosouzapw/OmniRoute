## Oversikt

Search Tools Studio forvandler `/dashboard/search-tools` fra en enkel sandkasse for søk til et
Studio med tre faner som samler nettsøk, nettskraping og sammenligning av leverandører side om side.

```
┌ Search Tools ──────────────────────────────────────────────────────────┐
│ [🔍 Søk] [📄 Skrap] [⚖ Sammenlign]              142ms · $0.001  </>    │
│ ⓘ [Modalitetsveiledning]                                               │
├──────────────────────────────────────────┬─────────────────────────────┤
│  {innhold i aktiv fane}                  │ ─ Konfigurasjon             │
│                                          │ Leverandør [auto ∨]         │
│                                          │   🟢 Serper  $0.001         │
│                                          │   🟢 Tavily  $0.008         │
│                                          │   🔥 Firecrawl (henting)    │
│                                          │ Type   [web | news]         │
│                                          │ Hele siden [ ] (skraping)   │
│                                          │ Format [md|text|html]       │
│                                          │ Rerankingsmodell [∨]        │
└──────────────────────────────────────────┴─────────────────────────────┘
```

---

## Faner

### Søkefane

Videreutvikler eksisterende `SearchForm` + `ResultsPanel` + `RerankPanel` til en fane:

- Spørring → resultater (tittel, URL, utdrag, relevanspoeng).
- Leverandørmetadata i konfigurasjonspanelet (kostnad, kvote, status).
- Rerankingsdel: Velg en rerankingsmodell, endre rekkefølgen på resultatene og vis `positionDelta`.
- Tom tilstand med handlingsoppfordring når ingen søkeleverandører er konfigurert.
- Søkehistorikk via `SearchHistory.tsx`.
- Kaller `POST /v1/search` (eksisterende endepunkt, ingen endringer).

### Skrapefane

Ny fane for uthenting av innhold fra en URL via `POST /v1/web/fetch` (opprettet i plan 05):

- Inndata: URL + bryter for hele siden + formatvelger (markdown / tekst / HTML).
- Send inn → hent → gjengi `ScrapeResult.tsx`.
- `ScrapeResult` gjengir en markdown-forhåndsvisning + bryter for rådata.
- Grense: Hvis responsinnholdet er større enn **256 KB**, viser brukergrensesnittet `(avkortet, vis rådata)` og åpner rådataene i en Monaco-dialogboks (D21).
- Metadatapanel: leverandør (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search), ventetid, kostnad, responsstørrelse, antall lenker.
- Bruker hooken `useScrapeFetch.ts`.

### Sammenligningsfane

Kjører samme spørring/URL parallelt hos opptil **4 leverandører** (D22):

- Kolonner side om side for hver leverandør.
- Måleverdier: ventetid, kostnad, antall resultater, responsstørrelse.
- Beregning av URL-overlapp for søk (antall delte URL-er sammenlignet med det opprinnelige resultatet).
- Kaller `POST /v1/search` (søk) eller `POST /v1/web/fetch` (skraping) for hver leverandør.

## Konfigurasjonspanel (felles)

`SearchToolsConfigPane.tsx` — alltid synlig, kan skjules.

| Felt             | Merknader                                                                    |
| ---------------- | ---------------------------------------------------------------------------- |
| Leverandør       | Nedtrekksliste med statusmerke (konfigurert / mangler / hastighetsbegrenset) |
| Type             | `web` eller `news` (kun søk)                                                 |
| Hele siden       | Bryter for skraping — henter hele siden kontra det første synlige innholdet  |
| Format           | `markdown`, `text` eller `html` (kun skraping)                               |
| Rerankingsmodell | Valgfri modell for rerangering etter søk                                     |
| Historikk        | Sammenleggbar del for søkehistorikk                                          |

---

## SearchConceptCard

`SearchConceptCard.tsx` — alltid synlig, sammenleggbart trekkspill. Forklarer:

| Konsept             | Kort forklaring                                                          |
| ------------------- | ------------------------------------------------------------------------ |
| **Søk**             | Henter en liste over nettresultater (tittel, URL, utdrag, relevanspoeng) |
| **Skraping**        | Trekker ut hele innholdet fra en URL (markdown, tekst eller HTML)        |
| **Sammenligning**   | Kjører det samme søket parallelt hos N leverandører                      |
| **Omrangering**     | Omorganiserer resultatene via LLM for å forbedre relevansen for søket    |
| **Auto (billigst)** | Velger automatisk den billigste tilgjengelige leverandøren               |

## Leverandørkatalog

`ProviderCatalog.tsx` viser hele leverandørlisten fra `GET /api/search/providers`
(utvidet i F4 til å inkludere henteleverandører):

| `kind` | `"search"` (20 leverandører) eller `"fetch"` (firecrawl, jina-reader, tavily-search, tinyfish, nimble-search, anysearch-search) |

Statusen **utledes på forespørselstidspunktet** ved å kontrollere om påloggingsinformasjon finnes, og om
alle nøkler for øyeblikket er i nedkjølingsperioden.

---

## Eksporter kode

`ExportCodeModal` (importert fra Playground Studio) + `codeExport.ts` genererer
curl-/Python-/TypeScript-kodeutdrag for kall til både `/v1/search` og `/v1/web/fetch`.
Plassholderen for API-nøkkelen er alltid `$OMNIROUTE_API_KEY` (D11, delt med Playground Studio).

---

## Endringer i backend

Bare én backend-endring var nødvendig for denne funksjonen:

### Utvidet `GET /api/search/providers`

`src/app/api/search/providers/route.ts` ble utvidet for å:

- Inkludere alle de 6 henteleverandørene (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`) i matrisen.
- Legge til `kind: "search" | "fetch"` for hvert element.
- Legge til `status: "configured" | "missing" | "rate_limited"` utledet fra gjeldende tilstand for påloggingsinformasjon.
- Opprettholde bakoverkompatibilitet — eksisterende felter (`id`, `name` osv.) er uendret.

## Feilsøking

| Symptom                                          | Årsak                                     | Løsning                                                                                                      |
| ------------------------------------------------ | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Scrape-fanen viser "endepunkt ikke tilgjengelig" | `/v1/web/fetch` er ikke koblet til        | Kontroller at plan 05 er slått sammen; sjekk at `src/app/api/v1/web/fetch/route.ts` finnes                   |
| Leverandørkatalogen viser alle som "mangler"     | Påloggingsinformasjon er ikke konfigurert | Legg til påloggingsinformasjon i `/dashboard/providers`                                                      |
| Scrape-innholdet er avkortet                     | Respons > grensen på 256 KB               | Forventet atferd (D21). Bruk knappen "vis rådata" for å se hele innholdet                                    |
| Sammenlign-fanen viser bare 2 leverandører       | Hastighetsbegrensning er aktiv            | To eller flere leverandører kan være i nedkjølingsperiode — sjekk leverandørstatusen i konfigurasjonspanelet |
| "Størrelse" vises som en rånøkkel i tabellen     | Manglende i18n-nøkkel                     | Kontroller at `search.size` finnes i lokalitetsfilen; bygg i18n på nytt                                      |
