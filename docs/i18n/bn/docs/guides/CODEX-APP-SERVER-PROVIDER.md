OmniRoute OpenAI Codex ব্যবহারের **দুটি** উপায় উন্মুক্ত করে:

| প্রোভাইডার             | এটি যেভাবে OpenAI-এর সঙ্গে যোগাযোগ করে                                                                                                                                                                             | ব্যবহারের সতর্কতা                                                     |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------- |
| **`codex`**            | আপনার ChatGPT/OpenAI OAuth টোকেন সরাসরি Responses API-তে পুনরায় ব্যবহার করে                                                                                                                                       | **হ্যাঁ** — অফিসিয়াল সেশনটি proxy/router ব্যবহারের জন্য অনুমোদিত নয় |
| **`codex-app-server`** | JSON-RPC/WebSocket-এর মাধ্যমে **Codex CLI-এর নিজস্ব `codex app-server`** পরিচালনা করে; একটি ইন্টার্যাক্টিভ `codex` সেশনের মতোই CLI তার OAuth (`~/.codex/auth.json`) নিজে নিয়ন্ত্রণ ও স্বয়ংক্রিয়ভাবে রিফ্রেশ করে | **না** — OmniRoute কখনোই API-তে কোনো টোকেন পুনরায় ব্যবহার করে না     |

যেহেতু `codex-app-server` কখনোই কোনো টোকেন পুনরায় ব্যবহার করে না, তাই এতে
সেশন-পুনর্ব্যবহারসংক্রান্ত সতর্কতা প্রযোজ্য নয়। তবে এর জন্য **কনফিগার করা
app-server URL-এ পৌঁছানো যায় এমন একটি Codex CLI** প্রয়োজন, এবং সেই CLI-তে
অবশ্যই **সাইন ইন করা থাকতে হবে**।

## 1. আর্কিটেকচার

```
┌─ OmniRoute অ্যাপ ────────────────┐        ┌─ codex-app-server সাইডকার ──────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ সক্ষমতা টোকেন)               │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  OpenAI OAuth নিজেই পরিচালনা করে    │
└──────────────────────────────────┘        │  (~/.codex/auth.json, স্বয়ংক্রিয় রিফ্রেশ) │
        │ শেয়ার করে (compose volumes)       └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → WS সক্ষমতা টোকেন (উভয়েই এটি mount করে)
  codex-appserver-home    → ~/.codex (dashboard দ্বারা লেখা auth.json,
                             সাইডকারের codex app-server দ্বারা পড়া হয়)
```

- সাইডকারটি সক্ষমতা টোকেনের আড়ালে **শুধু** অভ্যন্তরীণ compose নেটওয়ার্কে
  (`ws://codex-app-server:1456`) listen করে। এটি হোস্ট বা ইন্টারনেটে **কখনোই**
  প্রকাশ করা হয় না।
- Codex CLI `omniroute:base`-এর মধ্যে আগে থেকেই অন্তর্ভুক্ত থাকে, তাই সাইডকার
  চালানোর সময় হোস্ট বা ব্যবহারকারীর মেশিনে codex install করার প্রয়োজন নেই।

## 2. এটি চালু করুন

```bash
# codex app-server সাইডকার প্রোফাইলসহ স্ট্যাকটি চালু করুন:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

প্রথমবার boot করার সময় সাইডকারটি তার WS সক্ষমতা টোকেন তৈরি করে (শেয়ার করা
`codex-appserver-token` volume-এ), এবং অ্যাপটি
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE`-এর মাধ্যমে একই টোকেন পড়ে। ম্যানুয়ালি
টোকেন সংযুক্ত করার প্রয়োজন নেই।

## 3. সংযোগ + সাইন ইন

1. dashboard-এ **OpenAI Codex (App-Server)**-এর জন্য একটি সংযোগ যোগ করুন। কোনো API
   key বা token প্রয়োজন নেই (এটি একটি no-auth provider — auth সাইডকারের
   নিয়ন্ত্রণে থাকে)।
2. সাইডকারের Codex CLI-তে **এখনো সাইন ইন করা না থাকলে**, সংযোগের health
   check-এ _"চলছে, কিন্তু সাইন ইন করা নেই"_ দেখানো হয় (লাল auth error নয়)।
   **ChatGPT দিয়ে সাইন ইন করুন** ব্যবহার করুন: এটি আপনার browser-এ স্ট্যান্ডার্ড
   Codex device-OAuth চালায় এবং এরপর **Apply auth**-এর মাধ্যমে শেয়ার করা volume-এ
   `~/.codex/auth.json` লেখে (একই login `codex` এবং `codex-app-server` উভয়
   provider-এর জন্য ব্যবহৃত হয়)।
3. সাইন ইন হয়ে গেলে health check সবুজ হয় (এটি `/readyz` **এবং**
   `account/read`—অর্থাৎ চালু _এবং_ authenticated—দুটিই যাচাই করে) এবং কাজ শুরু
   করে।

dashboard কখনোই একটি সুস্থ বিদ্যমান `~/.codex/auth.json` ওভাররাইট করে না—এটি
শুধু তখনই লেখে, যখন ফাইলটি অনুপস্থিত থাকে বা এর token পুরোনো হয়ে যায় (সবসময়
একটি backup নেওয়া হয়)।

## 4. ডিপ্লয়মেন্ট পরিস্থিতি

- **আগে থেকেই authenticated Codex CLI-সহ অপারেটর** — আপনার হোস্টের
  `~/.codex` সাইডকারে (`codex-appserver-home`) mount করুন এবং sign-in ধাপটি
  এড়িয়ে যান।
- **পাবলিক ব্যবহারকারী, লোকালি codex install করা নেই** — এটি প্রাসঙ্গিক নয়:
  সাইডকারে CLI রয়েছে। ব্যবহারকারী শুধু dashboard-এর মাধ্যমে authenticate করেন।
- **Bare-metal OmniRoute (কোনো সাইডকার নেই, হোস্টে codex)** — আপনার নিজস্ব
  `codex app-server`-এর দিকে `OMNIROUTE_CODEX_APPSERVER_WS` নির্দেশ করুন এবং
  নিশ্চিত করুন যে হোস্টের codex-এ সাইন ইন করা আছে; binary অনুপস্থিত থাকলে
  "codex ইনস্টল করা নেই" ইঙ্গিতটি দেখানো হয়।

## 5. আবাসিক / UDP egress (অপারেটরের জন্য অতিরিক্ত, বিতরণ করা হয় না)

উপরের সাধারণ সাইডকারটি container-এর স্বাভাবিক network দিয়ে egress করে। যেসব
অপারেটরের Codex traffic একটি **আবাসিক exit**-এর মাধ্যমে egress করানো প্রয়োজন
(যেমন TCP + UDP/QUIC বহনকারী একটি TUN tailscale সাইডকার), তারা এটিকে আলাদা
compose override হিসেবে চালান; এটি ইচ্ছাকৃতভাবেই বিতরণ করা `codex-app-server`
profile-এর অংশ নয়। এই setup-এর জন্য অভ্যন্তরীণ operations runbook দেখুন।
