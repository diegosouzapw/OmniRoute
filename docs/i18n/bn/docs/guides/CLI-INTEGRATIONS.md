OmniRoute একটি `setup-*` কমান্ডসমষ্টি সরবরাহ করে, যা একটি কোডিং
CLI-কে (Codex, Claude Code, OpenCode, Cline, …) এর ব্যাকএন্ড হিসেবে OmniRoute ব্যবহার করার জন্য কনফিগার করে — ফলে
টুলটি **একটি** এন্ডপয়েন্টের সঙ্গে যোগাযোগ করে এবং OmniRoute স্বয়ংক্রিয় ফলব্যাকসহ সঠিক প্রোভাইডারের কাছে
অনুরোধ রাউট করে। প্রতিটি কমান্ড চলমান কোনো OmniRoute (লোকাল বা রিমোট) থেকে **লাইভ** মডেল ক্যাটালগ পড়ে
এবং **আপনার** মেশিনে টুলটির নিজস্ব কনফিগ ফাইল লেখে। টুলটি যেখানে সমর্থন করে, সেখানে API key-টি একটি environment variable-এর মাধ্যমে উল্লেখ করা হয়। যেসব কমান্ড টুল-লোকাল environment file স্থায়ীভাবে সংরক্ষণ করে, সেগুলো নিচে উল্লেখ করা হয়েছে।

এছাড়াও একটি সাধারণ লঞ্চার রয়েছে — `omniroute run <target>` — যা কোনো কনফিগ না লিখেই
সঠিক env ইনজেক্ট করে `claude`, `codex`, `aider`, `goose`, `opencode`, `qwen` বা `gemini`
চালু করে। টার্গেট ও সেগুলোর
alias ক্যানোনিক্যাল ম্যানিফেস্ট `bin/cli/cli-manifest.mjs` থেকে আসে
(`claude-code|cc|anthropic`, `codex-cli|openai-codex|openai`, `goose-cli`,
`open-code`, `qwen-code`, `gemini-cli`), এবং `omniroute completion` একই
ম্যানিফেস্ট-উৎপন্ন টার্গেট শব্দগুলো প্রদান করে। পুরোনো টুলভিত্তিক লঞ্চারগুলো —
`omniroute launch` (Claude Code) এবং `omniroute launch-codex` (Codex) — এখনও
উপলভ্য।

একই লোকাল/রিমোট কনটেক্সট থেকে প্রোভাইডার অনবোর্ডিংও করা যায়। নিচের
API-কেন্দ্রিক কমান্ডগুলো ম্যানেজমেন্ট authentication-কে প্রোভাইডার
credential থেকে আলাদা রাখে এবং structured output-এ কখনো কোনো credential প্রিন্ট করে না:

```bash
omniroute providers add glm --credential-env GLM_API_KEY --name work
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth openai
omniroute providers edit <connection-id> --default-model glm/glm-5.2
omniroute providers remove <connection-id> --yes
```

স্ক্রিপ্টের ক্ষেত্রে `--credential-stdin` বা `--credential-env` ব্যবহার করাই শ্রেয়; নিয়ন্ত্রিত লোকাল ব্যবহারের জন্য `--credential`
বজায় রাখা হয়েছে। non-interactive terminal-এ `providers remove` চালাতে `--yes` আবশ্যক,
এবং পাঁচটি কমান্ডই সক্রিয় কনটেক্সট অথবা গ্লোবাল `--base-url`/`--api-key` অপশন অনুসরণ করে।

সবচেয়ে সমৃদ্ধ দুটি ইন্টিগ্রেশনের এককালীন, হাতে-লেখা মৌলিক সেটআপের জন্য সংশ্লিষ্ট
টুলের বিস্তারিত নির্দেশিকা দেখুন:

- [Claude Code কনফিগারেশন](./CLAUDE-CODE-CONFIGURATION.md)
- [Codex CLI কনফিগারেশন](./CODEX-CLI-CONFIGURATION.md)
- [রিমোট মোড](./REMOTE-MODE.md) — আপনার ল্যাপটপ থেকে একটি রিমোট OmniRoute (VPS / Tailnet) নিয়ন্ত্রণ করুন
- [VS Code Copilot Chat](./VSCODE-COPILOT.md) — OmniCopilot এক্সটেনশন; এটি এডিটরের ভেতর থেকেই আপনার হয়ে এই
  `setup-*` কমান্ডগুলো চালাতে পারে

## প্রধান সারণি

প্রতিটি কমান্ড **সক্রিয় কনটেক্সট** অনুসরণ করে (`omniroute connect` দিয়ে সেট করা হয়,
[রিমোট মোড](./REMOTE-MODE.md) দেখুন) অথবা স্পষ্ট `--remote <url> --api-key <key>` ফ্ল্যাগ গ্রহণ করে।
নিচে "লোকাল বনাম রিমোট" বলতে বোঝায়: কোনো ফ্ল্যাগ না থাকলে এটি `http://localhost:20128`-কে লক্ষ্য করে;
`--remote` থাকলে (অথবা একটি সক্রিয় রিমোট কনটেক্সট থাকলে) এটি সেই
সার্ভার থেকে ক্যাটালগ সংগ্রহ করে এবং কনফিগটি লোকালি লেখে।

ফ্ল্যাগ-সংক্রান্ত নোট (কমান্ডের সোর্সে যাচাইকৃত):

- `--remote <url>` — একটি রিমোট OmniRoute থেকে ক্যাটালগ আনে (`--port`
  এবং সক্রিয় কনটেক্সটকে অগ্রাহ্য করে)। `--api-key <key>` ওই
  সার্ভারের জন্য ক্রেডেনশিয়াল সরবরাহ করে (ডিফল্ট হলো `OMNIROUTE_API_KEY` এনভায়রনমেন্ট ভ্যারিয়েবল, অথবা সক্রিয় কনটেক্সটের টোকেন)।
- `--only <patterns>` — কমা দিয়ে পৃথক করা সাবস্ট্রিং; শুধু মিলে যাওয়া মডেল ID-গুলো
  রাখে (যেমন `--only glm,kimi`)। `setup-codex`, `setup-claude`,
  `setup-opencode`, `setup-continue`, `setup-cursor`, `setup-crush`-এ উপলভ্য।
- `--dry-run` — ফাইলসিস্টেমে কোনো পরিবর্তন না করে ঠিক কী লেখা হতো তা প্রিন্ট
  করে। `setup-cursor` **ছাড়া** প্রতিটি `setup-*` কমান্ডে উপলভ্য
  (`setup-cursor` কখনো কোনো ফাইল লেখে না)।
- `--model <id>` — যেসব টুলে মডেল স্বয়ংক্রিয়ভাবে খুঁজে পাওয়ার সুবিধা নেই,
  সেগুলোর জন্য আবশ্যক (অথবা ইন্টার্যাক্টিভভাবে বেছে নেওয়া হয়): Cline, Kilo, Roo, Goose, Qwen, Aider, 5dive। ওই টুলগুলো
  নন-ইন্টার্যাক্টিভ রানের জন্য `--yes`-ও গ্রহণ করে (যার ক্ষেত্রে `--model` আবশ্যক)।
  `setup-opencode` ডিফল্ট টপ-লেভেল মডেল সেট করতে `--model` গ্রহণ করে।
- `omniroute run`-এ `--model <id>` ম্যানিফেস্টের প্রতি-টার্গেট সংযোগবিধি
  (`bin/cli/cli-manifest.mjs`) অনুসরণ করে: **aider** পায় `--model openai/<id>` এবং
  **opencode** পায় `--model omniroute/<id>` (id-তে প্রিফিক্সটি আগে থেকে না থাকলেই
  শুধু এটি যোগ করা হয়); **qwen** এবং **gemini** id-টি অপরিবর্তিতভাবে পায়;
  **claude** এটি `ANTHROPIC_MODEL`-এর মাধ্যমে, **goose** `GOOSE_MODEL`-এর মাধ্যমে এবং
  **codex** `-c model_providers.omniroute.*` আর্গুমেন্টের মাধ্যমে পায়। **Qwen-ই একমাত্র রান
  টার্গেট যেখানে `--model` কঠোরভাবে আবশ্যক** — এটি ছাড়া `omniroute run qwen`
  একটি স্পষ্ট ত্রুটিসহ `2` কোডে প্রস্থান করে।
- `--port <port>` — লোকাল OmniRoute পোর্ট (ডিফল্ট `20128`; `--remote`
  সেট করা থাকলে অগ্রাহ্য করা হয়)। সব `setup-*` এবং উভয় লঞ্চারে উপস্থিত।
- `omniroute run`-এর এক্সিট কোড: চাইল্ড CLI-এর নিজস্ব এক্সিট কোড অপরিবর্তিতভাবে
  প্রেরিত হয়; `2` = অবৈধ আর্গুমেন্ট (অসমর্থিত টার্গেট, আবশ্যক
  `--model` অনুপস্থিত, কনটেইনার গার্ড); `127` = টার্গেট বাইনারি `PATH`-এ নেই;
  `130`/`143`/`129` যখন লঞ্চটি `SIGINT`/`SIGTERM`/`SIGHUP` দ্বারা সমাপ্ত হয়;
  `1` = রানটাইমে লঞ্চের অন্য কোনো ব্যর্থতা।
- দুটি লঞ্চার (`launch`, `launch-codex`) `setup-claude` / `setup-codex` দ্বারা লেখা
  কোনো প্রোফাইল নির্বাচন করতে `--profile <name>` গ্রহণ করে, পাশাপাশি অন্তর্নিহিত
  `claude` / `codex` বাইনারির জন্য পাস-থ্রু আর্গুমেন্টও গ্রহণ করে।

ইন্টার্যাক্টিভ পিকারটিও সেটআপ রেসিপিগুলোর মধ্যে শেয়ার করা হয়:

```bash
# সক্রিয় লোকাল বা রিমোট মডেল ক্যাটালগ থেকে বেছে নিয়ে টার্গেট কনফিগার করুন।
omniroute configure claude
omniroute configure opencode --provider glm
omniroute configure qwen --model qwen/qwen3.8-max-preview --yes
```

`configure` বর্তমানে `codex`, `claude`,
`opencode`, `qwen`, `aider`, `goose`, `cline`, `continue`, `kilo`, এবং `5dive`-এর পরীক্ষিত রেসিপিগুলোতে কার্যভার অর্পণ করে।
শুধু-IDE,
MITM, এবং শুধু-গাইড ক্যাটালগ এন্ট্রিগুলো স্পষ্ট `setup-*`/ম্যানুয়াল প্রবাহ হিসেবেই থাকে এবং
লঞ্চযোগ্য টার্গেট হিসেবে উপস্থাপন করা হয় না।

> `setup-opencode` হলো **হালকা openai-compatible** OpenCode ইন্টিগ্রেশন।
> আরও সমৃদ্ধ একটি প্লাগইন ইন্টিগ্রেশনও রয়েছে — `omniroute setup opencode` — যা
> `@omniroute/opencode-plugin` ইনস্টল করে। এগুলো আলাদা কমান্ড; উপরের টেবিলে
> `setup-opencode` নথিভুক্ত করা হয়েছে।
>
> প্লাগইনটি দুটি প্যাকেজে আসে—OpenCode-এর প্রতিটি মেজর সংস্করণের জন্য একটি—কারণ দুটি
> লোডার ভিন্ন এন্ট্রিপয়েন্ট প্রত্যাশা করে:
> OpenCode v1-এর জন্য `@omniroute/opencode-plugin` এবং
> OpenCode v2-এর জন্য `@omniroute/opencode-plugin-v2`। v2 প্যাকেজটি নতুন
> (`0.1.0`) এবং এমন একটি হোস্ট কনট্র্যাক্ট অনুসরণ করে যা এখনও পরিবর্তনশীল, তাই এটি
> নিজে থেকে কোনো আকৃতি ধরে নেওয়ার বদলে ক্যাটালগ ড্রাফটে OpenCode যে আকৃতি প্রাথমিকভাবে যোগ করে সেটি পড়ে।
> `opencode.json`-এ একটি `plugins` এন্ট্রি যোগ করে এটি ইনস্টল করুন; `omniroute setup opencode`
> এখনও v1 প্যাকেজটিই ইনস্টল করে। অপশন এবং ক্রেডেনশিয়াল খোঁজার ক্রম
> প্যাকেজের README-তে রয়েছে।

## লোকাল ব্যবহার

OmniRoute যখন `localhost:20128`-এ চলছে, তখন শুধু আপনার টুলের জন্য সেটআপ কমান্ডটি চালান।
ক্যাটালগটি লোকাল সার্ভার থেকে আনা হয়।

```bash
# Codex: মিলে যাওয়া প্রতিটি মডেলের জন্য ~/.codex/-এ একটি প্রোফাইল লিখুন
omniroute setup-codex
codex --profile glm52            # তৈরি করা একটি প্রোফাইল ব্যবহার করুন

# Claude Code: প্রতিটি মডেলের জন্য প্রোফাইল লিখুন, তারপর একটি চালু করুন
omniroute setup-claude
omniroute launch --profile glm52

# OpenCode: ক্যাটালগের সব মডেলসহ openai-সামঞ্জস্যপূর্ণ প্রোভাইডারটি লিখুন
omniroute setup-opencode
export OMNIROUTE_API_KEY=sk-...  # {env:OMNIROUTE_API_KEY}-এর মাধ্যমে রেফারেন্স করা হয়, কখনোই ডিস্কে নয়
opencode -m omniroute/glm/glm-5.2 "..."

# স্বয়ংক্রিয় শনাক্তকরণ ছাড়া টুলগুলোর জন্য একটি সুস্পষ্ট মডেল প্রয়োজন:
omniroute setup-aider --model glm/glm-5.2
omniroute setup-qwen --model qwen/qwen3.8-max-preview

# কিছু না লিখেই প্রিভিউ করুন:
omniroute setup-continue --dry-run
```

কোনো কনফিগ না লিখেই চালু করুন (শুধু এনভায়রনমেন্ট ইনজেকশন):

```bash
omniroute launch                 # Claude Code → লোকাল OmniRoute
omniroute launch-codex           # Codex CLI → লোকাল OmniRoute
omniroute launch-codex --profile glm52
omniroute run claude --model openai/gpt-5.4
omniroute run codex --model openai/gpt-5.4 --dry-run --json
omniroute run aider --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"
omniroute run qwen --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "reply OK"

# সুস্পষ্ট কমান্ড পাথ: -- এর পরে যা আছে সব অপরিবর্তিতভাবে পাঠিয়ে দিন
omniroute run claude -- --print-system-prompt "review this diff"
```

## রিমোট ব্যবহার

`--remote` + `--api-key` দিয়ে যেকোনো সেটআপ কমান্ডকে একটি রিমোট OmniRoute-এর দিকে নির্দেশ করুন।
ক্যাটালগটি রিমোট থেকে আনা হয়; কনফিগটি আপনার লোকাল মেশিনে লেখা হয়।

```bash
# একটি রিমোট VPS-এর বিপরীতে OpenCode, শুধু glm/kimi মডেলগুলো রাখুন
omniroute setup-opencode --remote http://192.168.0.15:20128 --api-key oma_live_xxx \
  --only glm,kimi
opencode -m omniroute/glm/glm-5.2 "..."   # প্রথমে OMNIROUTE_API_KEY এক্সপোর্ট করুন

# একটি রিমোট ক্যাটালগ থেকে Codex প্রোফাইল
omniroute setup-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# CLI-টি সরাসরি রিমোটের বিপরীতে চালু করুন
omniroute launch       --remote http://192.168.0.15:20128 --api-key oma_live_xxx
omniroute launch-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx
```

প্রতিবার `--remote`/`--api-key` দেওয়ার বদলে, একবার লগ ইন করুন এবং
**সক্রিয় কনটেক্সটকে** সেগুলো স্বয়ংক্রিয়ভাবে সরবরাহ করতে দিন:

```bash
omniroute connect 192.168.0.15        # সীমিত-স্কোপের একটি টোকেন তৈরি করে, কনটেক্সট সংরক্ষণ করে
omniroute setup-codex                 # ← এখন রিমোট ক্যাটালগ ব্যবহার করে
omniroute setup-opencode              # ← একই
omniroute launch                      # ← রিমোটের বিপরীতে Claude Code
```

কনটেক্সট, স্কোপ এবং টোকেন ব্যবস্থাপনার জন্য [রিমোট মোড](./REMOTE-MODE.md) দেখুন।

## 5dive এজেন্ট ফ্লিট

[5dive](https://5dive.ai) দীর্ঘ সময় ধরে চলা কোডিং এজেন্টের একটি ফ্লিট চালায়, যেখানে প্রতিটি
এজেন্ট তার নিজস্ব Unix ব্যবহারকারীর অধীনে একটি systemd ইউনিট। এটি নিজে কোনো কোডিং CLI নয়,
তাই `omniroute run` দিয়ে চালু করার মতো কিছু নেই — `5dive` একটি **শুধু-কনফিগারেশন** টার্গেট।

```bash
omniroute configure 5dive --model failover-demo --yes
omniroute setup-5dive --model failover-demo --auth-profile omniroute --agent worker1
```

দুটি রূপই একটি 5dive **প্রমাণীকরণ প্রোফাইল** লেখে, এবং সেই প্রোফাইলের সঙ্গে যুক্ত প্রতিটি
`claude` সিট এরপর OmniRoute-এর সঙ্গে যোগাযোগ করে। এই টার্গেটের জন্য তিনটি বিষয় বিশেষভাবে প্রযোজ্য:

- **এটি ফ্লিট হোস্টে root হিসেবে চলে।** 5dive-এর ক্রিয়াগুলো লোকাল systemd ইউনিট
  এবং root-এর মালিকানাধীন স্টেট ডিরেক্টরিতে কাজ করে; কোনো রিমোট মোড নেই। এটি ইতিমধ্যে
  root হিসেবে না চললে রেসিপিটি `sudo`-এর মাধ্যমে পুনরায় এক্সিকিউট হয় (`--no-sudo` এটি
  বন্ধ করে এবং পরিবর্তে কমান্ডটি প্রিন্ট করে)।
- **লুপব্যাক না হলে এন্ডপয়েন্টটি অবশ্যই `https://` হতে হবে।** প্রতিটি অনুরোধে
  এজেন্টের API কী ওই URL-এর মাধ্যমে যায়, এবং 5dive অফ-বক্স প্লেইনটেক্সট এন্ডপয়েন্ট
  প্রত্যাখ্যান করে। প্রাইভেট LAN ঠিকানাও এর ব্যতিক্রম নয়।
- **প্রতিটি সিটের নিজস্ব মডেল পিন প্রোফাইলের চেয়ে অগ্রাধিকার পায়।** প্রোফাইলে
  `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL` থাকে, কিন্তু কোনো সিট যদি এখনও একটি স্টক
  মডেল আইডিতে পিন করা থাকে, তবে তার প্রথম টার্নটি _"নির্বাচিত মডেলটিতে একটি সমস্যা আছে"_
  বার্তাসহ ব্যর্থ হয়। সিটগুলোও পিন করতে `--agent <name>` দিন (একাধিকবার দেওয়া যায়);
  আপনি তা না করলে রেসিপিটি কমান্ডটি প্রিন্ট করে।

API কীটি 5dive-কে **stdin**-এর মাধ্যমে দেওয়া হয় (`--api-key=-`), তাই এটি কখনোই
`ps` আউটপুটে দেখা যায় না।

প্রোফাইলটিকে একটি একক মডেলের বদলে OmniRoute **কম্বো**-র দিকে নির্দেশ করলেই
ফ্লিটটি প্রোভাইডার ফেইলওভার পায়: [#11578](https://github.com/diegosouzapw/OmniRoute/issues/11578)-এ
রেকর্ড করা রানের মাঝপথে প্রাইমারি এন্ডপয়েন্ট সম্পূর্ণভাবে বন্ধ হয়ে গেলে, এজেন্টটি
ফলব্যাকে তার অবশিষ্ট ধাপগুলো সম্পন্ন করে এবং বিভ্রাটটি কখনোই প্রকাশ করেনি।

## আপডেটের সময় নেটিভ ডিপেন্ডেন্সি রাখা: `--include=optional`

আপনি `omniroute update` দিয়ে আপডেট করলে (নিশ্চিত করার পর অথবা `--apply` দিয়ে), OmniRoute ইনস্টল কমান্ডে আগে থেকেই `--include=optional` যুক্ত করে চালায়:

```bash
npm install -g omniroute@latest --include=optional
```

এটি **এমন কোনো ফ্ল্যাগ নয়** যা আপনাকে `omniroute update`-এ দিতে হবে — আপডেটার সর্বদা এটি প্রয়োগ করে। এটি নিশ্চিত করে যে `optionalDependencies` (`better-sqlite3`, `keytar`, `tls-client`, LLMLingua SLM স্ট্যাক) আপডেটের পরেও অক্ষত থাকে, এমনকি আপনার npm কনফিগে `omit=optional` সেট করা থাকলেও; অন্যথায় সেটি নীরবে নেটিভ SQLite ড্রাইভার এবং OS-keyring বাইন্ডিং বাদ দিত। প্রয়োগ না করে সঠিক কমান্ডটি প্রিভিউ করতে:

```bash
omniroute update --dry-run
# [DRY RUN] চালানো হতো: npm install -g omniroute@latest --include=optional
```

অন্যান্য `omniroute update` ফ্ল্যাগ (সোর্সে যাচাইকৃত): `--check` (পুরোনো হলে 1 দিয়ে এক্সিট), `--apply` (প্রম্পট না করে ইনস্টল), `--changelog`, `--no-backup`, `--yes`।

## `omniroute run gemini`-এর মাধ্যমে Google Gemini CLI

`@google/gemini-cli` 0.50.0-এর বিপরীতে কনট্র্যাক্ট যাচাই করা হয়েছে: CLI `GOOGLE_GEMINI_BASE_URL` মেনে চলে এবং এর বিপরীতে `POST /v1beta/models/<model>:generateContent` (এবং `:streamGenerateContent?alt=sse`) ইস্যু করে — যা ঠিক OmniRoute-এর নেটিভ Gemini সারফেস (`/v1beta`)। `omniroute run gemini` এটি স্বয়ংক্রিয়ভাবে সংযুক্ত করে:

- `GOOGLE_GEMINI_BASE_URL` → সক্রিয় OmniRoute বেস URL (রুট, `/v1` ছাড়া);
- `GEMINI_API_KEY` → নির্ধারিত OmniRoute ক্রেডেনশিয়াল (অপশন/env/context);
- একটি **অস্থায়ী ও বিচ্ছিন্ন `GEMINI_CLI_HOME`**, যার `.gemini/settings.json`-এ `gemini-api-key` অথ নির্বাচন করা থাকে, যাতে সংরক্ষিত Google OAuth সেশন (Code Assist) কখনো OmniRoute-নির্দেশিত লঞ্চকে ওভাররাইড না করে — এক্সিটের পর এটি সরিয়ে ফেলা হয়;
- **env পরিচ্ছন্নতা**: চাইল্ড env থেকে `GOOGLE_API_KEY`, `GOOGLE_GENAI_USE_VERTEXAI` এবং `GOOGLE_GENAI_USE_GCA` সরিয়ে ফেলা হয় (যেগুলো অথকে Vertex/Code Assist-এ রিডাইরেক্ট করত), এবং অতিরিক্ত সুরক্ষা হিসেবে `GEMINI_DEFAULT_AUTH_TYPE=gemini-api-key` সেট করা হয় — অন্যান্য `run` টার্গেটও তাদের নিজস্ব সাংঘর্ষিক ভেরিয়েবলের জন্য একই ব্যবস্থা পায়;
- `--provider`/`--model` থেকে `--model <id>` ইনজেকশন।

```bash
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "hello"
```

হেডলেস মোডেও Gemini-এর ওয়ার্কস্পেস-ট্রাস্ট গার্ড প্রযোজ্য থাকে — নিজে `--skip-trust` দিন (অথবা ইন্টার্যাক্টিভভাবে ডিরেক্টরিটিকে ট্রাস্ট করুন); লঞ্চারটি ইচ্ছাকৃতভাবে এটিকে বাইপাস করে না। এই লঞ্চারটি **ACP রেজিস্ট্রেশন** (`src/lib/acp/registry.ts`, `gemini --acp`) থেকে আলাদা, যা `/dashboard/acp-agents`-এর জন্য এজেন্ট-প্রোটোকল ইন্টিগ্রেশন হিসেবেই থাকে।

## বাস্তব স্মোক সুইপ (অপ্ট-ইন)

নির্ধারণযোগ্য লঞ্চ-প্ল্যান রিগ্রেশন CI-তে চলে (`tests/unit/cli/run-command.test.ts`,
`tests/unit/cli/run-execution.test.ts`)। একটি বাস্তব OmniRoute সার্ভারের বিপরীতে বাস্তব
বাইনারিগুলো যাচাই করার জন্য, একটি অপ্ট-ইন হারনেস রয়েছে
`tests/integration/upstream-cli-smoke.int.test.ts`-এ। এটি কখনোই স্বয়ংক্রিয়ভাবে চলে না
(`RUN_CLI_SMOKE=1` না হলে প্রতিটি সাব-টেস্ট এড়িয়ে যায়), env-var-এর মাধ্যমে ক্রেডেনশিয়ালের
NAME পাঠায় (কখনোই মান নয়), রেকর্ড করা যেকোনো আউটপুট থেকে কী-সদৃশ স্ট্রিং অপসারণ করে,
যেসব টার্গেটের বাইনারি ইনস্টল করা নেই সেগুলো এড়িয়ে যায় এবং ব্যর্থতাগুলোকে শুধু একটি
বুলিয়ান হিসেবে না দেখিয়ে auth / upstream / config হিসেবে শ্রেণিবদ্ধ করে:

```bash
RUN_CLI_SMOKE=1 \
OMNIROUTE_SMOKE_BASE_URL="http://localhost:20128" \
OMNIROUTE_SMOKE_MODEL="<provider/model>" \
OMNIROUTE_SMOKE_API_KEY_ENV="OMNIROUTE_API_KEY" \
node --import tsx/esm --test tests/integration/upstream-cli-smoke.int.test.ts
```

ঐচ্ছিক: `OMNIROUTE_SMOKE_TARGETS="codex,opencode,qwen"` সুইপটিকে সীমাবদ্ধ করে;
`OMNIROUTE_SMOKE_TIMEOUT_MS` প্রতি-টার্গেটের 120s টাইমআউট ওভাররাইড করে।
