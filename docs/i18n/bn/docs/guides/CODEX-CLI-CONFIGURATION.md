OmniRoute-কে OpenAI-সামঞ্জস্যপূর্ণ ব্যাকএন্ড হিসেবে নির্দেশ করে Codex CLI ব্যবহারের সম্পূর্ণ নির্দেশিকা।

---

> **TOML-ই একমাত্র কার্যকর ফরম্যাট।** আধুনিক Codex একচেটিয়াভাবে `~/.codex/config.toml`
> পড়ে (codex-cli 0.147.0-এর বিপরীতে যাচাই করা হয়েছে: `codex --help` অনুযায়ী
> `-c/--config` ওভাররাইডগুলো "`~/.codex/config.toml` থেকে লোড করা হয়")। পুরোনো
> `~/.codex/config.yaml` লিগ্যাসি npm CLI-এর অন্তর্ভুক্ত ছিল এবং কোনো বার্তা ছাড়াই উপেক্ষা করা হয়।
> ড্যাশবোর্ড জেনারেটরটি (`/api/cli-tools/apply`, টুল `codex`) সতর্কতামূলক মার্জসহ TOML লেখে —
> বিদ্যমান কী এবং অন্যান্য প্রোভাইডার ব্লক সংরক্ষিত থাকে, API কী `OMNIROUTE_API_KEY`-এ থাকে
> (কখনোই ফাইলে নয়), এবং অবশিষ্ট কোনো লিগ্যাসি `config.yaml` স্পর্শ না করেই সেটিকে
> মাইগ্রেশন নোট হিসেবে রিপোর্ট করা হয়।

## সরাসরি পেস্ট করার উপযোগী config.toml

`<YOUR_HOST>` এবং `<YOUR_KEY>`-এর জায়গায় আপনার মানগুলো বসান:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # প্রতিটি টুল কলের জন্য ইতিহাস সংরক্ষণের সীমা

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc অথবা ~/.zshrc — প্রকৃত কী-এর মান, কখনোই config.toml-এ নয়
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: ChatGPT অ্যাপের ভেতরে বান্ডেল করা Codex

আপনি যদি ChatGPT ডেস্কটপ অ্যাপের মাধ্যমে Codex ইনস্টল করে থাকেন, তাহলে `codex` বাইনারিটি
শুধু অ্যাপ বান্ডেলের ভেতরেই থাকতে পারে এবং এখনো আপনার শেলের `PATH`-এ নাও থাকতে পারে। আপনার
শেল স্টার্টআপ ফাইলে রিসোর্স ডিরেক্টরিটি যোগ করুন:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

একটি নতুন শেল খুলুন, তারপর যাচাই করুন:

```bash
command -v codex
codex --version
```

### স্থানীয় প্রমাণীকরণবিহীন OmniRoute: একটি প্লেসহোল্ডার কী-ই যথেষ্ট

CLI থেকে প্রথম অনুরোধ বের হওয়ার **আগেই** Codex যাচাই করে যে `env_key` দ্বারা নির্দিষ্ট
এনভায়রনমেন্ট ভেরিয়েবলটি বিদ্যমান কি না। আপনার **স্থানীয়** OmniRoute ইনস্ট্যান্সে
প্রমাণীকরণের প্রয়োজন না হলে, যেকোনো ফাঁকা নয় এমন প্লেসহোল্ডার কাজ করবে:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

আপনার OmniRoute সার্ভার সুরক্ষিত বা দূরবর্তী হলে এর পরিবর্তে একটি প্রকৃত কী ব্যবহার করুন।

> **প্রচলিত হোস্ট অপশন**
>
> | অ্যাক্সেস           | URL                           |
> | ------------------- | ----------------------------- |
> | স্থানীয় নেটওয়ার্ক | `http://192.168.0.1:20128/v1` |
> | Tailscale           | `http://100.x.x.x:20128/v1`   |
> | লুপব্যাক            | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — এটি কেন সব মডেলের জন্য কাজ করে

Codex CLI 2026 সালের ফেব্রুয়ারিতে `wire_api = "chat"` (Chat Completions) অবচিত করেছে এবং এখন **`wire_api = "responses"` আবশ্যক** (OpenAI Responses API)। v0.138 থেকে `wire_api = "chat"` সেট করলে স্টার্টআপের সঙ্গে সঙ্গেই ক্র্যাশ হয়।

GLM এবং Kimi-সহ অনেক প্রোভাইডার এখনো শুধু একটি Chat Completions এন্ডপয়েন্ট প্রকাশ করে। DeepSeek V4 এখন একটি নেটিভ Responses API-এর পাশাপাশি একটি Anthropic-সামঞ্জস্যপূর্ণ এন্ডপয়েন্টও প্রকাশ করে; OmniRoute ডিফল্টভাবে Responses ব্যবহার করে এবং প্রতিটি DeepSeek সংযোগকে Anthropic সামঞ্জস্য নির্বাচন করতে দেয়।

**OmniRoute স্বচ্ছভাবে এটি সমাধান করে:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute প্রোভাইডারের নেটিভ প্রোটোকল নির্বাচন করে এবং প্রয়োজন হলে রূপান্তর করে
    → POST /responses (DeepSeek V4) অথবা /chat/completions (Mistral / GLM / Kimi / অন্যান্য)
```

OmniRoute ব্যবহার করার সময় আপনার কখনোই আলাদা ট্রান্সলেশন প্রক্সির প্রয়োজন হয় না। **সব মডেল `wire_api = "responses"` ব্যবহার করে** — বাকি কাজ OmniRoute পরিচালনা করে।

> **`wire_api` হলো ডিফল্ট** — ফিল্ডটির ডিফল্ট মান `"responses"` এবং এটিকে `config.toml` থেকে সম্পূর্ণভাবে বাদ দেওয়া যায়। শুধু উদ্দেশ্য নথিভুক্ত করতে চাইলে এটিকে স্পষ্টভাবে সেট করুন।

## কনটেক্সট উইন্ডো এবং কম্প্যাকশন

### টোকেন কনফিগারেশন ফিল্ডসমূহ

| ফিল্ড                            | বিবরণ                                                                                                                                                                                        |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model_context_window`           | সক্রিয় মডেলের জন্য মোট টোকেন বাজেট। মডেলটির ঘোষিত সীমা অনুযায়ী সেট করুন।                                                                                                                   |
| `model_auto_compact_token_limit` | যে থ্রেশহোল্ডে পৌঁছালে স্বয়ংক্রিয় হিস্ট্রি কম্প্যাকশন শুরু হয়। **সর্বোচ্চ: `model_context_window`-এর 90%** — 90%-এর বেশি মান নীরবে উপেক্ষা করা হয়।                                       |
| `tool_output_token_limit`        | হিস্ট্রিতে প্রতিটি টুল কলের আউটপুটের জন্য সংরক্ষিত টোকেনের সীমা। এটি একটি বড় টুল রেসপন্সকে পুরো উইন্ডো পূর্ণ করা থেকে বিরত রাখে। **এটি সর্বোচ্চ আউটপুট নয়** — এটি হিস্ট্রি স্টোরেজের সীমা। |
| `compact_prompt`                 | কম্প্যাকশনের সময় ব্যবহৃত সিস্টেম প্রম্পটের ইনলাইন ওভাররাইড (v0.138+)।                                                                                                                       |

> **`model_max_output_tokens` সম্পর্কে নোট**: এই ফিল্ডটি **Codex CLI কনফিগ স্কিমার অংশ নয়** (Codex Rust কোডবেসে অনুপস্থিত)। সেট করা হলে এটি নীরবে উপেক্ষা করা হয়। এটির ওপর নির্ভর করবেন না — হিস্ট্রিতে কতটুকু টুল আউটপুট সংরক্ষিত হবে তা নিয়ন্ত্রণ করতে `tool_output_token_limit` ব্যবহার করুন।

## মডেল প্রিফিক্স: `cx/`

OmniRoute-এর সব Codex মডেল `cx/` প্রিফিক্স ব্যবহার করে:

| Codex CLI নাম           | OmniRoute মডেল        |
| ----------------------- | --------------------- |
| `cx/gpt-5.5`            | GPT-5.5 স্ট্যান্ডার্ড |
| `cx/gpt-5.4`            | GPT-5.4 স্ট্যান্ডার্ড |
| `cx/gpt-5.4-mini`       | GPT-5.4 মিনি          |
| `cx/gpt-5.1-codex-mini` | GPT-5.1 Codex মিনি    |

অন্যান্য প্রোভাইডার তাদের নিজস্ব প্রিফিক্স (`kmc/`, `glm/`, `ds/`, `ollamacloud/`, `opencode-go/`, `mistral/`) ব্যবহার করে — প্রিফিক্সটি OmniRoute প্রোভাইডার অ্যালিয়াসের সঙ্গে মিলে যায়।

## রিজনিং এফোর্ট

উত্তর দেওয়ার আগে মডেল কতটা "চিন্তা" করবে, তা নিয়ন্ত্রণ করে।

| মান      | যেখানে ব্যবহার করবেন                    |
| -------- | --------------------------------------- |
| `none`   | কোনো রিজনিং নয় — সরাসরি উত্তর          |
| `low`    | অতি সাধারণ কাজ (নাম পরিবর্তন, ফরম্যাট)  |
| `medium` | নির্দিষ্ট না থাকলে **সার্ভারের ডিফল্ট** |
| `high`   | মধ্যবর্তী কাজ (রিফ্যাক্টরিং, ডিবাগ)     |
| `xhigh`  | আর্কিটেকচার, গভীর বিশ্লেষণ, জটিল সমস্যা |

```bash
# প্রতিটি ইনভোকেশনের জন্য ওভাররাইড
codex -c model_reasoning_effort=low "rename variable x to count"
codex -c model_reasoning_effort=xhigh "design the auth module"
```

এছাড়াও একটি রিজনিং **সারাংশ** সেট করুন, যাতে Desktop চিন্তার টেক্সট রেন্ডার করতে পারে (শুধু এনক্রিপ্ট করা ব্লব নয়):

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # সমর্থিত হলে ultra-ও ব্যবহার করা যায়
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### OmniRoute থিংকিং বাজেট (সার্ভার সেটিং)

OmniRoute হোস্টে, Codex-এর এফোর্ট/সারাংশ আপস্ট্রিমে পৌঁছানোর জন্য **Settings → AI → Thinking Budget** অবশ্যই **`passthrough`** হতে হবে। **`auto` মোড** ক্লায়েন্টের সব `reasoning` / `reasoning_effort` ফিল্ড সরিয়ে দেয় এবং Codex সঠিকভাবে কনফিগার করা থাকলেও থিংকিং প্যানেল খালি রাখে।

সম্পূর্ণ নির্দেশিকা: [THINKING_BUDGET.md](./THINKING_BUDGET.md)।

কমপ্রেশন ও প্রম্পট ক্যাশ পরস্পর থেকে স্বাধীন এবং `passthrough`-এর অধীনেও কাজ করতে থাকে।

## প্রোফাইল — প্রতিটি মডেল/ওয়ার্কফ্লোর জন্য নামযুক্ত কনফিগারেশন

প্রোফাইলের মাধ্যমে একটি মাত্র ফ্ল্যাগ ব্যবহার করে মডেল + কনটেক্সট উইন্ডো পরিবর্তন করা যায়। প্রতিটি প্রোফাইল একটি ফ্ল্যাট
`~/.codex/<name>.config.toml` ফাইল, যা বেস `config.toml`-এর ওপর ওভারলে হয়।

> **নামকরণের নিয়ম (Codex CLI v0.137+):** ফাইলটি অবশ্যই `~/.codex/<name>.config.toml` হতে হবে — **কোনো `profile-` প্রিফিক্স নয়**।
> CLI এভাবে রিজলভ করে: `-p kimi-k27` → `~/.codex/kimi-k27.config.toml`। ফাইলটি পাওয়া না গেলে, কোনো বার্তা ছাড়াই ডিফল্ট প্রয়োগ করা হয়।

```bash
codex --profile kimi-k27 "analyze 10k lines of this codebase"
codex -p glm52 "architecture review"
codex --profile deepseek-flash "rename variable"   # দ্রুত, সাশ্রয়ী
```

## `omniroute setup-codex` দিয়ে স্বয়ংক্রিয়ভাবে প্রোফাইল তৈরি করা

আপনি যদি কোনো VPS-এ OmniRoute চালান, তাহলে লাইভ মডেল ক্যাটালগ থেকে স্বয়ংক্রিয়ভাবে প্রোফাইল ফাইল তৈরি করতে পারবেন:

```bash
# একটি VPS থেকে (পোর্ট 20128-এ স্থানীয় OmniRoute ব্যবহার করে)
omniroute setup-codex

# যেকোনো মেশিন থেকে — আপনার VPS নির্দেশ করুন
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# ফাইল না লিখে প্রিভিউ করুন
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# শুধু GLM এবং Kimi প্রোফাইল তৈরি করুন
omniroute setup-codex --only glm,kimi

# একটি কাস্টম ডিরেক্টরিতে লিখুন
omniroute setup-codex --codex-home /path/to/.codex
```

কমান্ডটি `/v1/models` থেকে তথ্য নিয়ে আসে, পরিচিত মডেলের জন্য টিউন করা প্রোফাইল ব্যবহার করে, অন্যান্য সামঞ্জস্যপূর্ণ টেক্সট মডেলের ক্ষেত্রে ক্যাটালগ মেটাডেটায় ফলব্যাক করে এবং প্রতিটির জন্য `~/.codex/<name>.config.toml` লেখে। এটি আইডেমপোটেন্ট—তাই নিরাপদে পুনরায় চালানো যায়।

সফল প্রোভাইডার মডেল ডিসকভারি/ইমপোর্টের ফলে লাইভ ক্যাটালগ পরিবর্তিত হওয়ার পর OmniRoute একই প্রোফাইল ফাইলগুলো **স্বয়ংক্রিয়ভাবে সিঙ্ক** করতেও পারে। এটি **অপ্ট-ইন এবং ডিফল্টভাবে বন্ধ**: **CLI Code dashboard** থেকে এটি টগল করুন ("CLI profile auto-sync" → Codex), অথবা `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` সেট করুন (এটি `CLI_ALLOW_CONFIG_WRITES`-কেও মান্য করে, যা ডিফল্টভাবে চালু থাকে)। সক্রিয় করা হলে এটি শুধু পৃথক `~/.codex/*.config.toml` প্রোফাইল ফাইল লেখে; এটি কখনোই সক্রিয়/ডিফল্ট `~/.codex/config.toml`, Codex-lb সেটিংস, প্রমাণীকরণ বা প্রোভাইডার নির্বাচন পরিবর্তন করে না।

## `omniroute launch-codex` দিয়ে Codex চালু করা

Codex চালু করার আগে আপনার OmniRoute ইনস্ট্যান্সের হেলথ-চেক করে:

```bash
# স্থানীয় OmniRoute-এর বিপরীতে চালু করুন (ডিফল্ট পোর্ট 20128)
omniroute launch-codex

# একটি নির্দিষ্ট প্রোফাইল দিয়ে চালু করুন
omniroute launch-codex --profile kimi-k27

# একটি রিমোট VPS-এর বিপরীতে চালু করুন
omniroute launch-codex --remote http://100.x.x.x:20128/v1 --api-key sk-xxx

# codex-এ অতিরিক্ত আর্গুমেন্ট পাঠান
omniroute launch-codex --profile glm52 -- --yolo "fix this bug"
```

Codex দুটি সাধারণ ম্যানিফেস্ট-চালিত এন্ট্রি পয়েন্টেরও একটি টার্গেট
(`bin/cli/cli-manifest.mjs`):

```bash
# ইন্টার্যাক্টিভ মডেল পিকার → ~/.codex/<name>.config.toml লেখে (TOML, env_key)
omniroute configure codex

# -c ফ্ল্যাগের মাধ্যমে omniroute প্রোভাইডার ইনজেক্ট করে codex চালু করুন (কোনো কনফিগ লেখা হয় না)
omniroute run codex
```

## দীর্ঘমেয়াদি কাজ

OmniRoute-এর দুটি ডিফল্ট নীরবে বহু ঘণ্টাব্যাপী Codex CLI সেশনকে ব্যাহত করতে পারে। কোনোটিই Codex CLI সেটিং নয় — দুটিই OmniRoute-এর দিকে থাকে। যেসব ব্যবহারকারী অ্যাকাউন্ট পিন করে এবং নিষ্ক্রিয়তার কাটঅফ বন্ধ রাখে এমন আপস্ট্রিম প্রক্সি থেকে কনফিগ স্থানান্তর করেন, তাঁরা প্রায়ই উভয় সমস্যার মুখোমুখি হন এবং সিদ্ধান্তে পৌঁছান যে OmniRoute “একটি দীর্ঘ সেশন চালিয়ে রাখতে পারে না।”

| উপসর্গ                                                                                    | সম্ভাব্য কারণ                                                                      | নিয়ন্ত্রণ               |
| ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------ |
| সেশন বারবার অ্যাকাউন্ট বদলায় / টার্নগুলোর মধ্যে প্রম্পট-ক্যাশের ধারাবাহিকতা হারিয়ে যায় | সেশন অ্যাফিনিটি TTL হলো `0` (নিষ্ক্রিয়)                                           | `sessionAffinityTtlMs`   |
| ক্লায়েন্টের কাছে দৃশ্যমান কোনো প্রম্পট ছাড়াই রিজনিংয়ের মাঝপথে সংযোগ বিচ্ছিন্ন হয়      | কোনো আপস্ট্রিম চাঙ্ক না আসায় ১০ মিনিট পর স্ট্রিম নিষ্ক্রিয়তা ওয়াচডগ চালু হয়েছে | `STREAM_IDLE_TIMEOUT_MS` |

সম্পর্কিত আলোচনা: [#7126](https://github.com/diegosouzapw/OmniRoute/discussions/7126) (দীর্ঘ কাজ বিচ্ছিন্ন হওয়া), [#5718](https://github.com/diegosouzapw/OmniRoute/discussions/5718) (কেন অ্যাফিনিটি ডিফল্টভাবে বন্ধ থাকে)। ট্র্যাকিং: [#7287](https://github.com/diegosouzapw/OmniRoute/issues/7287)।

### 1. সেশন অ্যাফিনিটি — একটি কথোপকথনকে একটি অ্যাকাউন্টে পিন করুন

**ডিফল্ট:** `sessionAffinityTtlMs = 0` (নিষ্ক্রিয়)।

**কোথায় সেট করবেন**

- ড্যাশবোর্ড → **সেটিংস → রাউটিং** → **সেশন অ্যাফিনিটি** → **অ্যাফিনিটি TTL (সেকেন্ড)** (`ComboDefaultsTab`)
- অথবা **মিলিসেকেন্ডে** `sessionAffinityTtlMs` দিয়ে সেটিংস PATCH করুন (Zod পরিসর `0`–`86_400_000`, অর্থাৎ সর্বোচ্চ ২৪ ঘণ্টা)

> #7274-এ শুধু Codex-এর জন্য ব্যবহৃত `codexSessionAffinityTtlMs` থেকে নাম পরিবর্তন করা হয়েছে। লিগ্যাসি কীটি এখনও শুধু-পঠন উপনাম হিসেবে গৃহীত হয়; নতুন কনফিগে `sessionAffinityTtlMs` ব্যবহার করা উচিত। TTL `0`-এর বেশি হলে অ্যাফিনিটি এখন শুধু Codex নয়, **যেকোনো** প্রদানকারীর ক্ষেত্রে প্রযোজ্য হয় — দেখুন [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → সেশন অ্যাফিনিটি।

**এটি 0-তেই থাকলে কী সমস্যা হয়**

একটি বহু-টার্নের Codex কথোপকথনের প্রতিটি টার্ন সক্রিয় কম্বো কৌশল অনুযায়ী স্বাধীনভাবে রাউট করা হয় এবং **প্রতি টার্নে ভিন্ন অ্যাকাউন্টে** যেতে পারে। এতে আপস্ট্রিম সেশন / প্রম্পট-ক্যাশের ধারাবাহিকতা নষ্ট হয়। কেবল TTL `0`-এর বেশি হলেই OmniRoute Codex সেশন হেডার (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) এবং `prompt_cache_key` / `session_id`-এর মতো বডি ফিল্ড বিবেচনা করে (`src/sse/services/auth.ts`-এ `extractSessionAffinityKey`)।

**বহু ঘণ্টাব্যাপী একটি একক কাজের জন্য সুপারিশ**

কাজটির প্রত্যাশিত বাস্তব সময়কালের **চেয়ে বেশি** TTL সেট করুন (UI-এর সর্বোচ্চ সীমা **86400 সেকেন্ড** = ২৪ ঘণ্টা):

| প্রত্যাশিত কাজের দৈর্ঘ্য | অ্যাফিনিটি TTL (UI, সেকেন্ড) | `sessionAffinityTtlMs` |
| ------------------------ | ---------------------------- | ---------------------- |
| কয়েক ঘণ্টা              | `14400` (৪ ঘণ্টা)            | `14400000`             |
| রাতভর / ~১২ ঘণ্টা        | `43200` (১২ ঘণ্টা)           | `43200000`             |
| পুরো দিন                 | `86400` (২৪ ঘণ্টা, সর্বোচ্চ) | `86400000`             |

অপ্ট-ইন ইচ্ছাকৃত: অ্যাফিনিটি নিষ্ক্রিয় করলে অ্যাকাউন্টগুলোর মধ্যে লোড-ব্যালান্সিং অগ্রাধিকার পায়; এটি সক্রিয় করলে একটি দীর্ঘ এজেন্ট সেশনের ধারাবাহিকতা অগ্রাধিকার পায়। এই নির্দেশিকা ডিফল্ট পরিবর্তন করে **না** — দীর্ঘ Codex কাজ চালানো অপারেটরদের অবশ্যই অপ্ট-ইন করতে হবে।

### 2. স্ট্রিম নিষ্ক্রিয়তার টাইমআউট — নীরব রিজনিং টার্ন বন্ধ করবেন না

**ডিফল্ট:** `STREAM_IDLE_TIMEOUT_MS = 600000` (১০ মিনিট)। সেট করা না থাকলে এটি `REQUEST_TIMEOUT_MS` থেকে মান গ্রহণ করে; শেয়ার করা বেসলাইনও 600000। দেখুন [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → টাইমআউটসমূহ।

**ডিফল্টে কী সমস্যা হয়**

Codex-এর কোনো reasoning / tool turn যদি **কোনো প্রকৃত upstream chunk ছাড়াই** 10 মিনিটের বেশি নীরব থাকে, তাহলে SSE idle watchdog (`open-sse/utils/stream.ts`) সেটিকে জোরপূর্বক বন্ধ করে দেয়। ক্লায়েন্ট প্রায়ই শুধু সংযোগ বিচ্ছিন্ন হতে দেখে—যা “কোনো বিজ্ঞপ্তি ছাড়াই স্বয়ংক্রিয়ভাবে বন্ধ হয়ে গেছে”-এর সঙ্গে মিলে যায়।

গুরুত্বপূর্ণ তথ্য: OmniRoute-এর কৃত্রিম SSE **heartbeat idle clock রিসেট করে না**। কেবল প্রকৃত upstream body chunk-ই `lastChunkTime` আপডেট করে। এখনও “চিন্তা করছে” এমন কোনো নীরব model-কে watchdog-এর দৃষ্টিকোণ থেকে আটকে যাওয়া upstream-এর মতোই দেখায়।

সংশ্লিষ্ট Undici body inactivity: `FETCH_BODY_TIMEOUT_MS` (এটিও একই 10-মিনিটের baseline-এ default হয়; `0` এটি নিষ্ক্রিয় করে)। Streaming-এর ক্ষেত্রে, `FETCH_TIMEOUT_MS` শুধু connection setup / প্রথম headers পর্যন্ত প্রযোজ্য—stream সক্রিয় হয়ে গেলে stall নিয়ন্ত্রিত হয় `STREAM_IDLE_TIMEOUT_MS` এবং `FETCH_BODY_TIMEOUT_MS` দ্বারা।

**একটি বহু-ঘণ্টার একক task-এর জন্য সুপারিশ**

OmniRoute process environment-এ (`.env` / compose / systemd):

```bash
# দীর্ঘ reasoning turn-এর জন্য stream idle + body inactivity cutoff নিষ্ক্রিয় করুন
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

অথবা আপনার প্রত্যাশিত দীর্ঘতম নীরব বিরতির চেয়ে বেশি মান নির্ধারণ করুন (মানগুলো milliseconds-এ):

```bash
# উদাহরণ: upstream chunk-গুলোর মধ্যে সর্বোচ্চ 2 ঘণ্টার নীরবতা অনুমোদন করুন
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

এই env vars পরিবর্তনের পর OmniRoute restart করুন।

### নির্দিষ্ট পদ্ধতি—বহু-ঘণ্টার Codex task

1. **Account pin করুন:** Dashboard → Settings → Routing → Session affinity → Affinity TTL = `43200` (12h) অথবা `86400` (সর্বোচ্চ 24h)।
2. OmniRoute-এর environment-এ **idle cutoff বাড়ান / নিষ্ক্রিয় করুন**:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. স্বাভাবিক Codex `config.toml` (`wire_api = "responses"`, সঠিক `base_url`, `OMNIROUTE_API_KEY`) বজায় রাখুন—এই দুটি behavior-এর জন্য Codex-এর দিকে কোনো affinity/idle knob নেই।
4. OmniRoute restart করুন, তারপর দীর্ঘ Codex task শুরু করুন।

### Default-সংক্রান্ত সিদ্ধান্ত (#7287)

| Knob                     | সরবরাহকৃত default | এই guide-এ পরিবর্তন করবেন?                                                                              |
| ------------------------ | ----------------- | ------------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (বন্ধ)        | **না**—opt-in হিসেবেই থাকবে (load-balancing বনাম continuity; Discussion #5718 দেখুন)                    |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 min) | **না**—সাধারণ traffic-এর জন্য 10 মিনিটই থাকবে; দীর্ঘ Codex-এর operator-রা এটি বাড়ান বা নিষ্ক্রিয় করেন |

যেকোনো একটি default বিশ্বব্যাপী পরিবর্তন করলে তা শুধু Codex নয়, একটি instance-এর প্রতিটি client-এর behavior পরিবর্তন করবে। Knob-গুলো document করুন; কোনো সুস্পষ্ট operator decision ভিন্ন কিছু না বলা পর্যন্ত default অপরিবর্তিত রাখুন।

### Idle cut নির্ণয় করা

Idle watchdog সক্রিয় হলে OmniRoute নিচের আকৃতির একটি line log করে:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

`Idle timeout: no data from` দিয়ে grep করুন (অথবা code `stream_idle_timeout` / error name `StreamIdleTimeoutError`)। Provider segment-টি হলো ওই request-এর জন্য OmniRoute যা ব্যবহার করেছে (`codex`, অন্য কোনো provider id, অথবা অজানা হলে `provider`)—এটি সব সময় আক্ষরিক string `codex` হয় না।

## সমস্যা সমাধান

**`Error: wire_api = "chat" is no longer supported`**
আপনার কনফিগ থেকে `wire_api = "chat"` সরিয়ে দিন। `wire_api = "responses"` সেট করুন অথবা ফিল্ডটি বাদ দিন (v0.138 থেকে ডিফল্ট হলো `"responses"`)।

**`Error: model not found`**
সঠিক প্রিফিক্সসহ মডেলটি OmniRoute-এ আছে কি না যাচাই করুন। `omniroute models list` ব্যবহার করুন অথবা `/dashboard/providers/<provider>` খুলুন।

**`Authentication error`**
`OMNIROUTE_API_KEY` এক্সপোর্ট করা হয়েছে কি না নিশ্চিত করুন: `echo $OMNIROUTE_API_KEY`।

**`ERROR: Missing environment variable: OMNIROUTE_API_KEY`**
প্রথম অনুরোধ করার আগে Codex env var-টি বিদ্যমান কি না যাচাই করে। সুরক্ষিত সার্ভারের জন্য
একটি আসল কী এক্সপোর্ট করুন, অথবা আপনার **লোকাল** OmniRoute ইনস্ট্যান্সে
auth প্রয়োজন না হলে `OMNIROUTE_API_KEY=local`-এর মতো একটি খালি নয় এমন প্লেসহোল্ডার ব্যবহার করুন।
আপনি এটি `~/.bashrc` বা `~/.zshrc`-এ যোগ করে থাকলে শেলটি পুনরায় চালু করুন।

**`Connection refused`**
OmniRoute চালু আছে এবং আপনার নেটওয়ার্কের (লোকাল বনাম Tailscale বনাম VPS) জন্য `base_url`-এর হোস্ট/পোর্ট সঠিক কি না যাচাই করুন।

**কনটেক্সট সীমার কাছাকাছি সেশন ক্র্যাশ করে**
`model_context_window` এবং `model_auto_compact_token_limit` স্পষ্টভাবে সেট করুন। উপরের কনটেক্সট উইন্ডো টেবিলটি দেখুন।

**কমপ্যাকশন খুব দেরিতে সক্রিয় হয়**
`model_auto_compact_token_limit` কমিয়ে উইন্ডোর 80–85% করুন। কখনোই 90%-এর বেশি সেট করবেন না।

**প্রোফাইল লোড হচ্ছে না (`-p <name>` নীরবে উপেক্ষিত হচ্ছে)**
ফাইলটি `~/.codex/<name>.config.toml`-এ আছে কি না নিশ্চিত করুন (`profile-` প্রিফিক্স ছাড়া)। `ls ~/.codex/*.config.toml` চালান।

**দীর্ঘ Codex টাস্ক চলার মাঝপথে সংযোগ বিচ্ছিন্ন হয় / টার্নগুলোর মধ্যে অ্যাকাউন্ট বদলে যায়**
[দীর্ঘমেয়াদি টাস্ক](#long-running-tasks) দেখুন। সেশন অ্যাফিনিটি সক্রিয় করুন (TTL টাস্কের সময়কালের চেয়ে বেশি রাখুন) এবং `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS` বাড়ান অথবা নিষ্ক্রিয় করুন। `Idle timeout: no data from` খুঁজতে OmniRoute লগে grep চালান।
