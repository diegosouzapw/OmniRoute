> **ড্যাশবোর্ড:** Settings → **AI** → Thinking Budget  
> **API:** `GET` / `PUT` `/api/settings/thinking-budget`  
> **সোর্স:** `open-sse/services/thinkingBudget.ts`

Thinking Budget নির্ধারণ করে যে OmniRoute প্রোভাইডারদের কাছে পাঠানোর সময় **ক্লায়েন্টের thinking/reasoning প্যারামিটার পুনর্লিখন করবে কি না**। এটি compression, routing বা prompt cache চালু কিংবা বন্ধ করে **না**।

## মোডসমূহ

| মোড                        | OmniRoute যা করে                                                                                                               | কখন ব্যবহার করবেন                                                                                                                                                                       |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`passthrough`** (ডিফল্ট) | ক্লায়েন্টের ফিল্ডগুলো অপরিবর্তিত রাখে (`reasoning`, `reasoning_effort`, Claude `thinking`, Gemini `thinking_config` ইত্যাদি)। | **Codex / Desktop / এমন যেকোনো ক্লায়েন্ট, যার effort + reasoning summary নিয়ন্ত্রণ করা উচিত।** ক্লায়েন্ট `reasoning.summary` অনুরোধ করলে দৃশ্যমান thinking panel-এর জন্য এটি আবশ্যক। |
| **`auto`**                 | upstream-এ পাঠানোর আগে request body থেকে thinking/reasoning-এর **সব ফিল্ড সরিয়ে দেয়**।                                       | কেবল তখনই, যখন আপনি ইচ্ছাকৃতভাবে চান যে **প্রোভাইডার** ডিফল্ট মান নির্ধারণ করুক এবং আপনার client-controlled thinking-এর প্রয়োজন নেই। এটি **“স্বয়ংক্রিয়ভাবে thinking দেখানো” নয়**।   |
| **`custom`**               | প্রতিটি request-কে একটি নির্দিষ্ট thinking token budget দিয়ে ওভাররাইট করে।                                                    | সব ট্রাফিকের thinking token-এর জন্য নির্দিষ্ট সর্বোচ্চ সীমা।                                                                                                                            |
| **`adaptive`**             | message-এর সংখ্যা, tool এবং prompt-এর দৈর্ঘ্য ব্যবহার করে একটি base effort থেকে budget সমন্বয় করে।                            | ক্লায়েন্টের অভিপ্রায় পুরোপুরি বাদ না দিয়ে নমনীয়ভাবে token নিয়ন্ত্রণের জন্য।                                                                                                        |

### `auto` যা সরিয়ে দেয়

মোড `auto` হলে, `stripThinkingConfig()` অন্যান্য ফিল্ডের সঙ্গে নিচের ফিল্ডগুলো মুছে দেয়:

- OpenAI / Responses: `reasoning`, `reasoning_effort`
- Claude: `thinking`, এবং উপস্থিত থাকলে `output_config.effort`
- Gemini: `generationConfig.thinking_config` / `thinkingConfig`

যদি কোনো ক্লায়েন্ট (যেমন Codex Desktop) `reasoning: { effort: "ultra", summary: "detailed" }` পাঠায়, তাহলে **auto সেই object-টি বাদ দেয়**। upstream তখনও কিছু reasoning token-এর জন্য বিল করতে পারে, তবে প্রায়ই **খালি অথবা শুধুই encrypted** reasoning item ফেরত দেয়—ফলে UI-তে কার্যকর কোনো thinking stream দেখা যায় না।

## এটি যা **নয়**

| ফিচার                                      | সম্পর্ক                                                                                                                         |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| **Compression** (Caveman, RTK, stacked, …) | আলাদা pipeline। প্রতিটি thinking-budget মোডেই কাজ করে।                                                                          |
| **Prompt / semantic cache**                | আলাদা। thinking-budget মোড দ্বারা প্রভাবিত হয় না।                                                                              |
| **Combo routing / fallbacks**              | আলাদা। প্রভাবিত হয় না।                                                                                                         |
| **API-key token limits / cost budgets**    | আলাদা। প্রভাবিত হয় না।                                                                                                         |
| **Reasoning replay cache**                 | কঠোর প্রোভাইডারগুলোর জন্য multi-turn re-inject (DeepSeek, Kimi, Qwen-thinking, …)। Desktop-এর “thinking দেখানো”-এর সমতুল্য নয়। |
| **`encrypted_content` ডিক্রিপ্ট করা**      | **অসম্ভব।** OpenAI/Codex-এর private reasoning blob অস্বচ্ছ। OmniRoute কখনো এগুলো ডিক্রিপ্ট করে না (#7095 / #7176 / #7304)।      |

## দৃশ্যমান চিন্তা (Codex / Responses ক্লায়েন্ট)

কোনো ক্লায়েন্টে চিন্তার টেক্সট দেখাতে আপনার **সবগুলোই** প্রয়োজন:

1. Thinking Budget mode = **`passthrough`** (অথবা এমন custom/adaptive, যা আপনার ব্যবহৃত পাথের জন্য summary অনুরোধ যথেষ্ট অক্ষত রাখে)।
2. ক্লায়েন্ট একটি summary চায়, যেমন Codex `model_reasoning_summary = "detailed"` / `auto` (`none` নয়)।
3. আপস্ট্রিম প্রকৃতপক্ষে `response.reasoning_summary_text.*` স্ট্রিম করে (অথবা আইটেমে একটি ফাঁকা নয় এমন `reasoning.summary` থাকে)।

আপনি যদি শুধু “encrypted private reasoning” পান, তাহলে হয়:

- mode ছিল **`auto`** (ক্লায়েন্টের অনুরোধ সরিয়ে দেওয়া হয়েছিল), অথবা
- আপস্ট্রিম summary টেক্সট ছাড়াই `encrypted_content` ফেরত দিয়েছে (প্রোভাইডারের সীমাবদ্ধতা; OmniRoute কেবল একটি placeholder দেখাতে পারে, plaintext নয়)।

## API উদাহরণ

```bash
# পড়ুন
curl -sS https://localhost:20128/api/settings/thinking-budget \
  -H "Authorization: Bearer $OMNIROUTE_TOKEN"

# Codex / Desktop-এ চিন্তার দৃশ্যমানতার জন্য প্রস্তাবিত
curl -sS -X PUT https://localhost:20128/api/settings/thinking-budget \
  -H "Authorization: Bearer $OMNIROUTE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"mode":"passthrough","customBudget":10240,"effortLevel":"medium"}'
```

Schema (`updateThinkingBudgetSchema`): `mode` ∈ `passthrough|auto|custom|adaptive`; ঐচ্ছিক `customBudget`, `effortLevel`, `baseBudget`, `complexityMultiplier`।

### স্থায়িত্ব / পুনরায় চালু করা

মানটি settings key `thinkingBudget`-এর অধীনে সংরক্ষিত হয় এবং process চালুর সময় hydrate করা হয় (`hydrateThinkingBudgetConfig`)। DB বা কিছু non-API পাথের মাধ্যমে পরিবর্তন করার পর, **OmniRoute process পুনরায় চালু করুন**, যাতে in-memory singleton ডিস্কের সঙ্গে মিলে যায়।

## অপারেটর চেকলিস্ট

- [ ] Codex / Desktop ব্যবহারকারী: mode = **passthrough**
- [ ] চিন্তা বাদ দিয়ে নয়, বরং **messages**-এ token সাশ্রয় করতে চাইলে compression চালু রাখুন
- [ ] `auto` “আরও বেশি চিন্তা দেখাবে”—এমনটি আশা করবেন না
- [ ] শুধুমাত্র encrypted summary হলো একটি **provider** আচরণ; passthrough সেগুলো decrypt করতে পারে না
