## 🎯 ব্যবহারের ক্ষেত্র

### ক্ষেত্র 1: "আমার Claude Pro সাবস্ক্রিপশন আছে"

**সমস্যা:** কোটা অব্যবহৃত অবস্থায় মেয়াদোত্তীর্ণ হয়ে যায়, নিবিড় কোডিংয়ের সময় রেট লিমিটে পৌঁছে যায়

```
কম্বো: "maximize-claude"
  1. cc/claude-opus-4-7        (সাবস্ক্রিপশন সম্পূর্ণভাবে ব্যবহার করুন)
  2. glm/glm-4.7               (কোটা শেষ হলে সাশ্রয়ী ব্যাকআপ)
  3. if/qwen3.8-max-preview       (জরুরি পরিস্থিতিতে বিনামূল্যের ফলব্যাক)

মাসিক খরচ: $20 (সাবস্ক্রিপশন) + ~$5 (ব্যাকআপ) = মোট $25
বনাম $20 + সীমায় পৌঁছানো = হতাশা
```

### ক্ষেত্র 2: "আমি শূন্য খরচ চাই"

**সমস্যা:** সাবস্ক্রিপশনের খরচ বহন করতে পারি না, নির্ভরযোগ্য AI কোডিং প্রয়োজন

```
কম্বো: "zero-cost"
  1. if/kimi-k2.7-code          (তালিকাভুক্ত বিনামূল্যের অ্যাক্সেস; রেট লিমিট প্রযোজ্য হতে পারে)
  2. kr/qwen3-coder-next        (Kiro-এর বিনামূল্যের ফলব্যাক)

মাসিক খরচ: $0
গুণমান: আপনার কাজের জন্য মডেল, সীমাবদ্ধতা, গোপনীয়তা এবং SLA যাচাই করুন
```

### ক্ষেত্র 3: "আমার কোনো বাধা ছাড়াই 24/7 কোডিং প্রয়োজন"

**সমস্যা:** সময়সীমা আছে, ডাউনটাইম বহন করা সম্ভব নয়

```
কম্বো: "always-on"
  1. cc/claude-opus-4-7        (সেরা গুণমান)
  2. cx/gpt-5.5                (দ্বিতীয় সাবস্ক্রিপশন)
  3. glm/glm-4.7               (সাশ্রয়ী, প্রতিদিন রিসেট হয়)
  4. minimax/MiniMax-M2.1      (সবচেয়ে সস্তা, 5 ঘণ্টায় রিসেট)
  5. if/deepseek-v4-flash       (তালিকাভুক্ত বিনামূল্যের অ্যাক্সেস; রেট লিমিট প্রযোজ্য হতে পারে)

ফলাফল: ফলব্যাকের 5টি স্তর সহনশীলতা বাড়ায়; আপস্ট্রিমের প্রাপ্যতা নিশ্চিত নয়
মাসিক খরচ: $20-200 (সাবস্ক্রিপশন) + $10-20 (ব্যাকআপ)
```

### ক্ষেত্র 4: "আমি OpenClaw-এ বিনামূল্যের AI চাই"

**সমস্যা:** মেসেজিং অ্যাপে সম্পূর্ণ বিনামূল্যের AI সহকারী প্রয়োজন

```
কম্বো: "openclaw-free"
  1. if/qwen3.8-max-preview     (তালিকাভুক্ত বিনামূল্যের অ্যাক্সেস; রেট লিমিট প্রযোজ্য হতে পারে)
  2. if/deepseek-v4-flash       (তালিকাভুক্ত বিনামূল্যের অ্যাক্সেস; রেট লিমিট প্রযোজ্য হতে পারে)
  3. if/kimi-k2.7-code          (তালিকাভুক্ত বিনামূল্যের অ্যাক্সেস; রেট লিমিট প্রযোজ্য হতে পারে)

মাসিক খরচ: $0
যেগুলোর মাধ্যমে অ্যাক্সেস করা যায়: WhatsApp, Telegram, Slack, Discord, iMessage, Signal...
```

## 🚀 ডিপ্লয়মেন্ট

### গ্লোবাল npm ইনস্টল (প্রস্তাবিত)

```bash
npm install -g omniroute

# কনফিগারেশন ডিরেক্টরি তৈরি করুন
mkdir -p ~/.omniroute

# .env ফাইল তৈরি করুন (.env.example দেখুন)
cp .env.example ~/.omniroute/.env

# সার্ভার চালু করুন
omniroute
# অথবা কাস্টম পোর্টসহ:
omniroute --port 3000
```

CLI স্বয়ংক্রিয়ভাবে `~/.omniroute/.env` অথবা `./.env` থেকে `.env` লোড করে।

### ট্রে মোড

সিস্টেম ট্রেতে OmniRoute চালু করুন:

```bash
omniroute serve --tray
```

সার্ভার ও ট্রে প্রস্তুত হওয়ার পর কমান্ডটি সমাপ্ত হয়।

টার্মিনাল ছাড়াই সার্ভারটি চলতে থাকে।

ট্রে মোড macOS, Windows এবং গ্রাফিক্যাল Linux সেশন সমর্থন করে। ট্রে মোড স্বয়ংক্রিয়ভাবে ড্যাশবোর্ড খোলে না।

নিচের কাজগুলোর জন্য ট্রে মেনু ব্যবহার করুন:

- ড্যাশবোর্ড খুলুন।
- `/dashboard/logs` খুলুন।
- স্বয়ংক্রিয়ভাবে চালু হওয়ার সেটিং পরিবর্তন করুন।
- OmniRoute বন্ধ করুন।

এই অপশনগুলোর সঙ্গে `--tray` ব্যবহার করবেন না:

- `--daemon`
- `--log`
- `--no-recovery`

এই মোডগুলোর জন্য ভিন্ন প্রক্রিয়া মালিকানা প্রয়োজন।

পরবর্তীবার মেশিনে লগইন করার সময় চালু হওয়া সক্রিয় করুন:

```bash
omniroute autostart enable
```

macOS, Windows এবং গ্রাফিক্যাল Linux সেশনে স্বয়ংক্রিয় চালু হওয়ার জন্য ট্রে মোড ব্যবহৃত হয়। হেডলেস Linux বিদ্যমান systemd ব্যবহারকারী পরিষেবা ব্যবহার করে।

লগইনের সময় চালু হওয়া নিষ্ক্রিয় করুন:

```bash
omniroute autostart disable
```

### আনইনস্টল করা

OmniRoute আর প্রয়োজন না হলে পরিচ্ছন্নভাবে অপসারণের জন্য আমরা দুটি দ্রুত স্ক্রিপ্ট প্রদান করি:

| কমান্ড                   | কাজ                                                                                            |
| ------------------------ | ---------------------------------------------------------------------------------------------- |
| `npm run uninstall`      | সিস্টেম অ্যাপটি অপসারণ করে, তবে `~/.omniroute`-এ থাকা **আপনার DB ও কনফিগারেশনগুলো রেখে দেয়**। |
| `npm run uninstall:full` | অ্যাপটি অপসারণ করে এবং স্থায়ীভাবে **সব কনফিগারেশন, কী ও ডেটাবেস মুছে দেয়**।                  |

> দ্রষ্টব্য: এই কমান্ডগুলো চালাতে OmniRoute প্রকল্প ফোল্ডারে যান (যদি আপনি এটি ক্লোন করে থাকেন) এবং সেখান থেকে চালান। বিকল্পভাবে, গ্লোবালি ইনস্টল করা থাকলে শুধু `npm uninstall -g omniroute` চালাতে পারেন।

## 🧩 উন্নত বৈশিষ্ট্যসমূহ

### কাস্টম মডেল

অ্যাপ আপডেটের জন্য অপেক্ষা না করেই যেকোনো প্রোভাইডারে যেকোনো মডেল ID যোগ করুন:

```bash
# API-এর মাধ্যমে
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# তালিকা: curl http://localhost:20128/api/provider-models?provider=openai
# অপসারণ: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

অথবা ড্যাশবোর্ড ব্যবহার করুন: **প্রোভাইডার → [প্রোভাইডার] → কাস্টম মডেল**।

নোট:

- OpenRouter এবং OpenAI/Anthropic-সামঞ্জস্যপূর্ণ প্রোভাইডারগুলো শুধুমাত্র **উপলভ্য মডেল** থেকে পরিচালিত হয়। ম্যানুয়াল যোগ, ইমপোর্ট এবং স্বয়ংক্রিয় সিঙ্ক—সবই একই উপলভ্য-মডেল তালিকায় যুক্ত হয়, তাই এসব প্রোভাইডারের জন্য আলাদা কাস্টম মডেল বিভাগ নেই।
- **কাস্টম মডেল** বিভাগটি এমন প্রোভাইডারগুলোর জন্য, যেগুলো পরিচালিত উপলভ্য-মডেল ইমপোর্ট প্রদান করে না।

### কাস্টম OpenAI-সামঞ্জস্যপূর্ণ প্রোভাইডার

OpenAI API ব্যবহার করে এমন যেকোনো গেটওয়ে (একটি স্ব-হোস্টেড প্রক্সি, vLLM, অথবা তৃতীয়-পক্ষের অ্যাগ্রিগেটর)
নিজস্ব প্রোভাইডার নোড হিসেবে যোগ করা যেতে পারে:

1. **প্রোভাইডার → OpenAI Compatible যোগ করুন**।
2. **নাম**: নোডটির জন্য প্রদর্শিত লেবেল।
3. **প্রিফিক্স**: রাউটিং নাম। ক্লায়েন্টরা `<prefix>/<model>` হিসেবে মডেল কল করে, তাই
   `mygw` প্রিফিক্সযুক্ত একটি নোড `mygw/gpt-4o-mini` পরিবেশন করে। আবশ্যক; অক্ষরসংক্রান্ত কোনো বিধিনিষেধ নেই।
4. **API ধরন**: গেটওয়েটি যে এন্ডপয়েন্ট পরিবার পরিবেশন করে (Chat Completions, Responses,
   Embeddings, অডিও, ছবি)।
5. **বেস URL**: `/v1`-সহ সেখান পর্যন্ত API রুট (উদাহরণস্বরূপ
   `https://gateway.example.com/v1`), সম্পূর্ণ `/chat/completions` পাথ নয়। অ-মানক
   পাথযুক্ত গেটওয়েগুলোর ক্ষেত্রে সেগুলো **উন্নত সেটিংস**-এর অধীনে সেট করুন (চ্যাট পাথ, মডেল পাথ)।
6. **API কী (পরীক্ষার জন্য)** ফিল্ডটি কেবল সংযোগ পরীক্ষা করে। নোড তৈরি করার পর,
   সেটি খুলুন এবং অনুরোধে ব্যবহৃত কী সংরক্ষণ করতে **সংযোগ যোগ করুন** ব্যবহার করুন।

নোডটি `openai-compatible-<apiType>-<uuid>` ফর্মের একটি অভ্যন্তরীণ id পায়; এটি কখনোই
টাইপ করার প্রয়োজন নেই, প্রিফিক্সই হলো সর্বজনীন নাম।

#### সংরক্ষিত প্রিফিক্স

কোনো প্রিফিক্স বিল্ট-ইন প্রোভাইডারের id বা alias (উদাহরণস্বরূপ `openai`, `cf`) কিংবা
অবসরপ্রাপ্ত প্রোভাইডারের id হতে পারবে না। মডেল রিজলভার কাস্টম নোডের আগে বিল্ট-ইন id ও alias
পরীক্ষা করে, তাই এসব প্রিফিক্সের কোনোটি ব্যবহারকারী নোড কখনো ট্রাফিক পাবে না:
`<prefix>/model` পরিবর্তে বিল্ট-ইন প্রোভাইডারে যাবে, অথবা সেই প্রোভাইডার অবসরপ্রাপ্ত হলে
নিরাপদভাবে ব্যর্থ হবে। এমন প্রিফিক্স দিয়ে নোড তৈরি বা সম্পাদনা করলে নিচের বার্তাসহ প্রত্যাখ্যান করা হয়:

```text
prefix: "<prefix>" is a reserved provider prefix — choose a different prefix (reserved ids/aliases cannot be used for custom nodes because requests like <prefix>/model route to a built-in provider or fail closed when retired)
```

একটি স্বতন্ত্র প্রিফিক্স (`mygw`, `acme-proxy`) বেছে নিন। কোনো কাস্টম নোডে অনুরোধ বিল্ট-ইন
প্রোভাইডার বা তার শংসাপত্রের নাম উল্লেখ করা ত্রুটিসহ ব্যর্থ হলে, নোডটির প্রিফিক্স
সংরক্ষিত কি না পরীক্ষা করুন: এই নিয়ম চালু হওয়ার আগে সংরক্ষিত নোডগুলো এখনো সংরক্ষিত আছে, কিন্তু তাদের প্রিফিক্স
বিল্ট-ইন প্রোভাইডারে রাউট করে। নোডটি সম্পাদনা করে একটি নতুন প্রিফিক্স দিন।

### OmniRoute পিয়ার চেইন করা

আরেকটি OmniRoute গেটওয়েকে **কাস্টম OpenAI-সামঞ্জস্যপূর্ণ** প্রোভাইডার হিসেবে যোগ করা যেতে পারে। পিয়ারের
`/v1` বেস URL এবং সেই পিয়ার থেকে ইস্যু করা একটি নিবেদিত, ন্যূনতম-সুবিধাযুক্ত API কী ব্যবহার করুন।

পারস্পরিক বা মাল্টি-হপ চেইনের জন্য প্রতিটি গেটওয়েতে অপ্ট-ইন লুপ গার্ড সক্রিয় করুন:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

শুধু স্পষ্টভাবে অনুমোদিত তালিকাভুক্ত পিয়ার URL-এ পাঠানো অনুরোধগুলো
`X-OmniRoute-Peer-Trace` হেডার পায়। পুনরাবৃত্ত instance ID অথবা নিঃশেষিত হপ
বাজেট পেলে একটি গেটওয়ে HTTP `508 Loop Detected` দিয়ে প্রত্যাখ্যান করে; সাধারণ আপস্ট্রিম প্রোভাইডারগুলো কোনো পিয়ার মেটাডেটা পায় না।

পিয়ার চেইনিং ডেটাবেস রেপ্লিকেশন বা হোস্ট ফেইলওভার নয়। প্রতিটি গেটওয়ে স্বাধীন
SQLite স্টেট, ক্যাশ, রেট কাউন্টার এবং সেশন বজায় রাখে। active/passive বা active/active প্রাপ্যতার জন্য
স্বাস্থ্য-পরীক্ষিত রিভার্স প্রক্সি অথবা ক্লায়েন্ট ফেইলওভার ব্যবহার করুন এবং কখনোই একটি SQLite ডেটাবেস
একাধিক চলমান OmniRoute ইনস্ট্যান্সে মাউন্ট করবেন না।

### নিবেদিত প্রোভাইডার রুট

মডেল যাচাইকরণসহ অনুরোধ সরাসরি একটি নির্দিষ্ট প্রোভাইডারে রাউট করুন:

```bash
POST http://localhost:20128/v1/providers/openai/chat/completions
POST http://localhost:20128/v1/providers/openai/embeddings
POST http://localhost:20128/v1/providers/fireworks/images/generations
```

প্রোভাইডার প্রিফিক্স অনুপস্থিত থাকলে স্বয়ংক্রিয়ভাবে যোগ করা হয়। অমিল মডেলগুলো `400` ফেরত দেয়।

### নেটওয়ার্ক প্রক্সি কনফিগারেশন

```bash
# গ্লোবাল প্রক্সি সেট করুন
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"global": {"type":"http","host":"proxy.example.com","port":"8080"}}'

# প্রতি-প্রোভাইডার প্রক্সি
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"providers": {"openai": {"type":"socks5","host":"proxy.example.com","port":"1080"}}}'

# প্রক্সি পরীক্ষা করুন
curl -X POST http://localhost:20128/api/settings/proxy/test \
  -d '{"proxy":{"type":"socks5","host":"proxy.example.com","port":"1080"}}'
```

**অগ্রাধিকারের ক্রম:** কী-নির্দিষ্ট → কম্বো-নির্দিষ্ট → প্রোভাইডার-নির্দিষ্ট → গ্লোবাল → এনভায়রনমেন্ট।

### মডেল ক্যাটালগ API

```bash
curl http://localhost:20128/api/models/catalog
```

ধরনসহ (`chat`, `embedding`, `image`) প্রোভাইডার অনুযায়ী গ্রুপ করা মডেল ফেরত দেয়।

### ক্লাউড সিঙ্ক

- ডিভাইসজুড়ে প্রোভাইডার, কম্বো এবং সেটিংস সিঙ্ক করুন
- টাইমআউট + দ্রুত-ব্যর্থতা সহ স্বয়ংক্রিয় ব্যাকগ্রাউন্ড সিঙ্ক
- প্রোডাকশনে সার্ভার-সাইড `NEXT_PUBLIC_BASE_URL`/`NEXT_PUBLIC_CLOUD_URL` অগ্রাধিকার দিন

### Cloudflare কুইক টানেল

- Docker এবং অন্যান্য স্ব-হোস্টেড ডিপ্লয়মেন্টের জন্য **ড্যাশবোর্ড → এন্ডপয়েন্টস**-এ উপলভ্য
- একটি অস্থায়ী `https://*.trycloudflare.com` URL তৈরি করে, যা আপনার বর্তমান OpenAI-সামঞ্জস্যপূর্ণ `/v1` এন্ডপয়েন্টে ফরওয়ার্ড করে
- প্রথমবার সক্রিয় করার সময় কেবল প্রয়োজন হলেই `cloudflared` ইনস্টল করা হয়; পরবর্তী রিস্টার্টগুলো একই পরিচালিত বাইনারি পুনরায় ব্যবহার করে
- OmniRoute বা কনটেইনার রিস্টার্টের পর Quick Tunnels স্বয়ংক্রিয়ভাবে পুনরুদ্ধার হয় না; প্রয়োজন হলে ড্যাশবোর্ড থেকে সেগুলো আবার সক্রিয় করুন
- টানেল URL অস্থায়ী এবং প্রতিবার টানেল বন্ধ/চালু করলে পরিবর্তিত হয়
- সীমাবদ্ধ কনটেইনারে বিরক্তিকর QUIC UDP বাফার সতর্কতা এড়াতে পরিচালিত Quick Tunnels ডিফল্টভাবে HTTP/2 ট্রান্সপোর্ট ব্যবহার করে
- পরিচালিত ট্রান্সপোর্টের নির্বাচন ওভাররাইড করতে চাইলে `CLOUDFLARED_PROTOCOL=quic` বা `auto` সেট করুন
- পরিচালিত ডাউনলোডের পরিবর্তে আগে থেকে ইনস্টল করা `cloudflared` বাইনারি ব্যবহার করতে চাইলে `CLOUDFLARED_BIN` সেট করুন
- Cloudflare Quick Tunnel, Tailscale Funnel এবং ngrok Tunnel প্যানেলগুলো **সেটিংস → অ্যাপিয়ারেন্স** থেকে দেখানো বা লুকানো যায়। কোনো প্যানেল লুকালে চলমান টানেল বন্ধ হয় না।

### LLM গেটওয়ে ইন্টেলিজেন্স (পর্যায় 9)

- **সেমান্টিক ক্যাশ** — নন-স্ট্রিমিং, temperature=0 রেসপন্স স্বয়ংক্রিয়ভাবে ক্যাশ করে (`X-OmniRoute-No-Cache: true` দিয়ে বাইপাস করুন)
- **রিকোয়েস্ট আইডেমপোটেন্সি** — `Idempotency-Key` বা `X-Request-Id` হেডারের মাধ্যমে 5s-এর মধ্যে আসা রিকোয়েস্টগুলো ডিডুপ্লিকেট করে
- **অগ্রগতি ট্র্যাকিং** — `X-OmniRoute-Progress: true` হেডারের মাধ্যমে অপ্ট-ইন SSE `event: progress` ইভেন্ট

### ট্রান্সলেটর প্লেগ্রাউন্ড

**ড্যাশবোর্ড → ট্রান্সলেটর** থেকে অ্যাক্সেস করুন। OmniRoute কীভাবে প্রোভাইডারগুলোর মধ্যে API রিকোয়েস্ট অনুবাদ করে, তা ডিবাগ ও ভিজুয়ালাইজ করুন।

| মোড               | উদ্দেশ্য                                                                                              |
| ----------------- | ----------------------------------------------------------------------------------------------------- |
| **প্লেগ্রাউন্ড**  | সোর্স/টার্গেট ফরম্যাট নির্বাচন করুন, একটি রিকোয়েস্ট পেস্ট করুন এবং অনূদিত আউটপুট তাৎক্ষণিকভাবে দেখুন |
| **চ্যাট টেস্টার** | প্রক্সির মাধ্যমে লাইভ চ্যাট মেসেজ পাঠান এবং সম্পূর্ণ রিকোয়েস্ট/রেসপন্স চক্র পরিদর্শন করুন            |
| **টেস্ট বেঞ্চ**   | অনুবাদের নির্ভুলতা যাচাই করতে একাধিক ফরম্যাটের সমন্বয়ে ব্যাচ টেস্ট চালান                             |
| **লাইভ মনিটর**    | প্রক্সির মধ্য দিয়ে রিকোয়েস্ট প্রবাহিত হওয়ার সময় রিয়েল-টাইম অনুবাদ দেখুন                          |

**ব্যবহারের ক্ষেত্র:**

- কোনো নির্দিষ্ট ক্লায়েন্ট/প্রোভাইডার সমন্বয় কেন ব্যর্থ হয় তা ডিবাগ করা
- থিংকিং ট্যাগ, টুল কল এবং সিস্টেম প্রম্পট সঠিকভাবে অনূদিত হচ্ছে কি না যাচাই করা
- OpenAI, Claude, Gemini এবং Responses API ফরম্যাটগুলোর মধ্যে পার্থক্য তুলনা করা

### রাউটিং কৌশল

**ড্যাশবোর্ড → সেটিংস → রাউটিং** থেকে কনফিগার করুন। ড্যাশবোর্ডে সবচেয়ে বেশি ব্যবহৃত ছয়টি কৌশল দেখানো হয়; কম্বো এবং অটো-রাউটার অভ্যন্তরীণভাবে আরও বিস্তৃত কৌশল সমর্থন করে।

**ড্যাশবোর্ডে দৃশ্যমান কৌশলসমূহ (অ্যাকাউন্ট-স্তরের রাউটিং):**

| কৌশল                           | বিবরণ                                                                                                                 |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| **আগে পূরণ**                   | অগ্রাধিকার অনুযায়ী অ্যাকাউন্ট ব্যবহার করে — প্রাথমিক অ্যাকাউন্ট অনুপলভ্য না হওয়া পর্যন্ত সব রিকোয়েস্ট পরিচালনা করে |
| **রাউন্ড রবিন**                | কনফিগারযোগ্য স্টিকি সীমাসহ সব অ্যাকাউন্ট পর্যায়ক্রমে ব্যবহার করে (ডিফল্ট: প্রতি অ্যাকাউন্টে 3টি কল)                  |
| **P2C (দুটি বিকল্পের ক্ষমতা)** | এলোমেলোভাবে 2টি অ্যাকাউন্ট বেছে নিয়ে স্বাস্থ্যকরটিতে রাউট করে — স্বাস্থ্য বিবেচনায় রেখে লোড ভারসাম্য করে            |
| **এলোমেলো**                    | Fisher-Yates shuffle ব্যবহার করে প্রতিটি রিকোয়েস্টের জন্য এলোমেলোভাবে একটি অ্যাকাউন্ট নির্বাচন করে                   |
| **সবচেয়ে কম ব্যবহৃত**         | সবচেয়ে পুরোনো `lastUsedAt` টাইমস্ট্যাম্পসহ অ্যাকাউন্টে রাউট করে, ফলে ট্রাফিক সমানভাবে বিতরণ হয়                      |
| **খরচ-অপ্টিমাইজড**             | সর্বনিম্ন অগ্রাধিকার মানসহ অ্যাকাউন্টে রাউট করে, সর্বনিম্ন খরচের প্রোভাইডারের জন্য অপ্টিমাইজ করে                      |

**উন্নত কম্বো এবং অটো কৌশলসমূহ** (প্রতি কম্বোতে বা `auto/*` প্রিফিক্সের মাধ্যমে কনফিগারযোগ্য — [AUTO-COMBO.md](../routing/AUTO-COMBO.md) দেখুন):

- `priority` — কঠোর ক্রম অনুসরণ করে, কখনো রাউন্ড-রবিন করে না
- `weighted` — প্রতি-মডেলের ওজন অনুযায়ী আনুপাতিক ট্রাফিক বণ্টন
- `fill-first` — সীমায় পৌঁছানো পর্যন্ত প্রথম মডেলটি ব্যবহার করে
- `round-robin` / `strict-random` / `random`
- `p2c` (দুটি বিকল্পের ক্ষমতা)
- `least-used` এবং `cost-optimized`
- `auto` — সব প্রার্থীর মধ্যে স্কোর-ভিত্তিক নির্বাচন
- `lkgp` (সর্বশেষ পরিচিত ভালো প্রোভাইডার) — সর্বশেষ সফল প্রোভাইডারে পিন করে, তারপর নিয়ম অনুযায়ী ফলব্যাক করে
- `context-optimized` — সবচেয়ে বড় খালি কনটেক্সট উইন্ডোসহ মডেলটি নির্বাচন করে
- `context-relay` — ফলো-আপ টার্নের জন্য দীর্ঘ-কনটেক্সট মডেলগুলোকে শৃঙ্খলিত করে

#### বাহ্যিক স্টিকি সেশন হেডার

বাহ্যিক সেশন অ্যাফিনিটির জন্য (উদাহরণস্বরূপ, রিভার্স প্রক্সির পেছনে থাকা Claude Code/Codex এজেন্ট), পাঠান:

```http
X-Session-Id: your-session-key
```

OmniRoute `x_session_id`-ও গ্রহণ করে এবং কার্যকর সেশন কী `X-OmniRoute-Session-Id`-এ ফেরত দেয়।

আপনি যদি Nginx ব্যবহার করেন এবং আন্ডারস্কোর-ফর্ম হেডার পাঠান, তাহলে সক্রিয় করুন:

```nginx
underscores_in_headers on;
```

#### ওয়াইল্ডকার্ড মডেল অ্যালিয়াস

মডেলের নাম রিম্যাপ করতে ওয়াইল্ডকার্ড প্যাটার্ন তৈরি করুন:

```
প্যাটার্ন: claude-sonnet-*     →  টার্গেট: cc/claude-sonnet-4-6
প্যাটার্ন: gpt-*               →  টার্গেট: gh/gpt-5.3-codex
```

ওয়াইল্ডকার্ডে `*` (যেকোনো অক্ষরসমষ্টি) এবং `?` (একটি অক্ষর) সমর্থিত।

#### ফলব্যাক চেইন

সব রিকোয়েস্টে প্রযোজ্য গ্লোবাল ফলব্যাক চেইন নির্ধারণ করুন:

```
চেইন: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### প্রচলিত প্রোভাইডার সমন্বয় ও রাউটিং প্যাটার্ন

OmniRoute-এ একাধিক প্রোভাইডার একত্রিত করা এবং তাদের মধ্যে রাউটিংয়ের কিছু উদাহরণ প্যাটার্ন নিচে দেওয়া হলো:

#### 1. কোডিং এজেন্ট কম্বো: খরচ/গতির ফলব্যাকসহ উচ্চমানের রিজনিং

কোডিং এজেন্টের (OpenCode, Claude Code, Cursor, Cline) জন্য আদর্শ। শুরুতে ফ্রন্টিয়ার রিজনিং মডেলে রাউট করে এবং কোটা শেষ হয়ে গেলে বা ত্রুটি ঘটলে দ্রুত কোডিং মডেলে ফলব্যাক করে।

- **ড্যাশবোর্ড**: কম্বো → নতুন কম্বো → নাম: `agent-coding` → কৌশল: `Priority`
- **মডেলসমূহ**:
  1. `claude/claude-sonnet-4-6` (প্রাথমিক কোডিং এজেন্ট)
  2. `openai/gpt-4o` (সেকেন্ডারি উচ্চ-ক্ষমতাসম্পন্ন ফলব্যাক)
  3. `deepseek/deepseek-v4-flash` (উচ্চ-দক্ষতাসম্পন্ন, সাশ্রয়ী ফলব্যাক)

```bash
# API-এর মাধ্যমে উদাহরণ
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "agent-coding",
    "strategy": "priority",
    "models": [
      { "model": "claude/claude-sonnet-4-6" },
      { "model": "openai/gpt-4o" },
      { "model": "deepseek/deepseek-v4-flash" }
    ]
  }'
```

#### 2. ফ্রি-টিয়ার স্বয়ংক্রিয় ফেইলওভার কম্বো

API খরচ ছাড়াই আপটাইম সর্বাধিক করতে একাধিক ফ্রি-টিয়ার ও কী-বিহীন প্রোভাইডারকে ধারাবাহিকভাবে সংযুক্ত করে।

- **কৌশল**: `Least Used` অথবা `Round Robin` (কোটাগুলোর মধ্যে লোড বণ্টন করে)
- **মডেলসমূহ**:
  1. `groq/llama-3.3-70b-versatile`
  2. `gemini/gemini-2.5-flash`
  3. `cerebras/gpt-oss-120b`

```bash
# CLI-এর মাধ্যমে উদাহরণ
omniroute combo create free-stack \
  --models "groq/llama-3.3-70b-versatile,gemini/gemini-2.5-flash,cerebras/gpt-oss-120b" \
  --strategy round-robin
```

#### 3. মাল্টিমোডাল / ভিশন ও টেক্সট পাইপলাইন

ছবি বোঝা ও কোড তৈরির সঙ্গে সংশ্লিষ্ট ওয়ার্কফ্লোর জন্য বিশেষায়িত ভিশন মডেলের সঙ্গে উচ্চগতির টেক্সট জেনারেশন যুক্ত করা।

- **প্যাটার্ন**: একটি `Priority` কম্বো, যেখানে প্রথমে ভিশন-সক্ষম মডেল এবং শেষে উচ্চ-থ্রুপুটের টেক্সট/কোড মডেল তালিকাভুক্ত থাকে।
- **মডেলসমূহ**:
  1. `gemini/gemini-2.5-pro` (ছবি/মাল্টিমোডাল বিষয়বস্তু বোঝার শক্তিশালী সক্ষমতা)
  2. `openai/gpt-4o` (ভিশন ও টুল ব্যবহারের সুষম সক্ষমতা)
  3. `deepseek/deepseek-v4-flash` (টেক্সট/কোড জেনারেশন)

### স্থিতিস্থাপকতা ও সার্কিট ব্রেকার

**ড্যাশবোর্ড → সেটিংস → স্থিতিস্থাপকতা** থেকে কনফিগার করুন।

OmniRoute পাঁচটি কম্পোনেন্টের মাধ্যমে প্রোভাইডার-স্তরের স্থিতিস্থাপকতা বাস্তবায়ন করে:

1. **রিকোয়েস্ট কিউ ও পেসিং** — সিস্টেম-স্তরের রিকোয়েস্ট শেপিং:
   - **প্রতি মিনিটে রিকোয়েস্ট (RPM)** — প্রতিটি অ্যাকাউন্টের জন্য প্রতি মিনিটে সর্বোচ্চ রিকোয়েস্ট
   - **রিকোয়েস্টগুলোর মধ্যে সর্বনিম্ন সময়** — রিকোয়েস্টগুলোর মধ্যে মিলিসেকেন্ডে সর্বনিম্ন ব্যবধান
   - **সর্বোচ্চ সমকালীন রিকোয়েস্ট** — প্রতিটি অ্যাকাউন্টের জন্য একযোগে সর্বোচ্চ রিকোয়েস্ট

2. **কানেকশন কুলডাউন** — পুনরায় চেষ্টা করা যায় এমন ব্যর্থতার পর একটি একক কানেকশনের জন্য প্রতি-অথ-টাইপ কনফিগারেশন:
   - **বেস কুলডাউন** — পুনরায় চেষ্টা করা যায় এমন আপস্ট্রিম ব্যর্থতার জন্য ডিফল্ট কুলডাউন সময়সীমা
   - **আপস্ট্রিম রিট্রাই হিন্ট ব্যবহার করুন** — প্রদান করা হলে নির্ভরযোগ্য `Retry-After` অথবা রিসেট হিন্ট মেনে চলে
   - **সর্বোচ্চ ব্যাকঅফ ধাপ** — বারবার ব্যর্থতার ক্ষেত্রে সর্বোচ্চ এক্সপোনেনশিয়াল ব্যাকঅফ স্তর

3. **প্রোভাইডার সার্কিট ব্রেকার** — প্রান্ত-থেকে-প্রান্ত প্রোভাইডার ব্যর্থতা ট্র্যাক করে, কনফিগার করা সতর্কতা থ্রেশহোল্ডে কোনো প্রোভাইডারকে অবনমিত হিসেবে চিহ্নিত করে এবং কনফিগার করা ব্যর্থতা থ্রেশহোল্ডে পৌঁছালে ব্রেকার খুলে দেয়:
   - **অবনমন থ্রেশহোল্ড** — `DEGRADED` অবস্থায় প্রবেশের আগে ধারাবাহিক প্রোভাইডার ব্যর্থতার সংখ্যা
   - **ব্যর্থতা থ্রেশহোল্ড** — `OPEN` অবস্থায় প্রবেশের আগে ধারাবাহিক প্রোভাইডার ব্যর্থতার সংখ্যা
   - **রিসেট টাইমআউট** — প্রোভাইডারকে আবার পরীক্ষা করার আগের সময়সীমা
   - **CLOSED** (সুস্থ) — রিকোয়েস্ট স্বাভাবিকভাবে প্রবাহিত হয়
   - **DEGRADED** — বেড়ে যাওয়া ব্যর্থতা ট্র্যাক করার সময়ও রিকোয়েস্ট প্রবাহিত হতে থাকে
   - **OPEN** — বারবার ব্যর্থতার পর প্রোভাইডারকে সাময়িকভাবে ব্লক করা হয়
   - **HALF_OPEN** — প্রোভাইডার পুনরুদ্ধার করেছে কি না তা পরীক্ষা করা হচ্ছে

   কানেকশন-স্কোপড `429` রেট লিমিট **কানেকশন কুলডাউনেই** থাকে এবং প্রোভাইডার ব্রেকারের গণনায় অন্তর্ভুক্ত হয় না।

   প্রোভাইডার ব্রেকারের রানটাইম অবস্থা শুধু **ড্যাশবোর্ড → স্বাস্থ্য**-এ দেখানো হয়।

4. **কুলডাউনের জন্য অপেক্ষা** — যদি প্রতিটি প্রার্থী কানেকশন ইতিমধ্যেই কুলডাউনে থাকে, OmniRoute সবচেয়ে আগে শেষ হওয়া কুলডাউনের জন্য অপেক্ষা করে একই ক্লায়েন্ট রিকোয়েস্ট স্বয়ংক্রিয়ভাবে আবার চেষ্টা করতে পারে।

5. **রেট লিমিট স্বয়ংক্রিয় শনাক্তকরণ** — আপস্ট্রিম প্রোভাইডারগুলো সুস্পষ্ট অপেক্ষার সময়সীমা ফেরত দিলে এবং সেটিংটি সক্রিয় থাকলে, সেই হিন্টগুলো স্থানীয় কানেকশন কুলডাউনকে ওভাররাইড করে।

**বিশেষ পরামর্শ:** কোনো বিভ্রাটের পর সক্রিয় প্রোভাইডার ব্রেকার পরিদর্শন ও রিসেট করতে **স্বাস্থ্য** পৃষ্ঠা ব্যবহার করুন। স্থিতিস্থাপকতা পৃষ্ঠা শুধু কনফিগারেশন পরিবর্তন করে।

### ডেটাবেস এক্সপোর্ট / ইমপোর্ট

**ড্যাশবোর্ড → সেটিংস → সিস্টেম ও স্টোরেজ** থেকে ডেটাবেস ব্যাকআপ পরিচালনা করুন।

| কার্যক্রম                       | বিবরণ                                                                                                                                                            |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ডেটাবেস এক্সপোর্ট করুন**      | বর্তমান SQLite ডেটাবেসকে একটি `.sqlite` ফাইল হিসেবে ডাউনলোড করে                                                                                                  |
| **সব এক্সপোর্ট করুন (.tar.gz)** | ডেটাবেস, সেটিংস, কম্বো, প্রোভাইডার কানেকশন (কোনো ক্রেডেনশিয়াল নয়) এবং API কী মেটাডেটাসহ একটি পূর্ণাঙ্গ ব্যাকআপ আর্কাইভ ডাউনলোড করে                             |
| **ডেটাবেস ইমপোর্ট করুন**        | বর্তমান ডেটাবেস প্রতিস্থাপন করতে একটি `.sqlite` ফাইল আপলোড করে। `DISABLE_SQLITE_AUTO_BACKUP=true` না থাকলে ইমপোর্টের আগের একটি ব্যাকআপ স্বয়ংক্রিয়ভাবে তৈরি হয় |

```bash
# API: ডেটাবেস এক্সপোর্ট করুন
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: সব এক্সপোর্ট করুন (পূর্ণাঙ্গ আর্কাইভ)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: ডেটাবেস ইমপোর্ট করুন
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**ইমপোর্ট যাচাইকরণ:** ইমপোর্ট করা ফাইলটির অখণ্ডতা (SQLite pragma পরীক্ষা), প্রয়োজনীয় টেবিল (`provider_connections`, `provider_nodes`, `combos`, `api_keys`) এবং আকার (সর্বোচ্চ 100MB) যাচাই করা হয়।

**ব্যবহারের ক্ষেত্রসমূহ:**

- এক মেশিন থেকে অন্য মেশিনে OmniRoute স্থানান্তর করা
- দুর্যোগ-পরবর্তী পুনরুদ্ধারের জন্য বাহ্যিক ব্যাকআপ তৈরি করা
- দলের সদস্যদের মধ্যে কনফিগারেশন শেয়ার করা (সব এক্সপোর্ট করুন → আর্কাইভ শেয়ার করুন)

### সেটিংস ড্যাশবোর্ড

সহজে নেভিগেট করার জন্য সেটিংস পৃষ্ঠাটি **7টি ট্যাবে** সাজানো হয়েছে:

| ট্যাব              | বিষয়বস্তু                                                                                                                                                                       |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **সাধারণ**         | সিস্টেম স্টোরেজ টুল, ডিফল্ট আচরণ, Endpoint টানেলের দৃশ্যমানতা                                                                                                                    |
| **চেহারা**         | থিম নিয়ন্ত্রণ (লাইট/ডার্ক/সিস্টেম), সাইডবারের দৃশ্যমানতা, Cloudflare/Tailscale/ngrok টানেল কার্ডের জন্য প্যানেল টগল                                                             |
| **AI**             | থিংকিং বাজেট (পাসথ্রু / স্বয়ংক্রিয়ভাবে বাদ দেওয়া / কাস্টম / অ্যাডাপটিভ — [THINKING_BUDGET.md](./THINKING_BUDGET.md) দেখুন), গ্লোবাল সিস্টেম প্রম্পট, প্রম্পট ক্যাশ পরিসংখ্যান |
| **নিরাপত্তা**      | লগইন/পাসওয়ার্ড সেটিংস, IP অ্যাক্সেস নিয়ন্ত্রণ, `/models`-এর জন্য API প্রমাণীকরণ, প্রোভাইডার ব্লকিং, প্রম্পট-ইনজেকশন সুরক্ষা                                                    |
| **রাউটিং**         | গ্লোবাল রাউটিং কৌশল (Fill First / Round Robin / P2C / Random / Least Used / Cost Optimized), ওয়াইল্ডকার্ড মডেল অ্যালিয়াস, ফলব্যাক চেইন, কম্বোর ডিফল্ট                          |
| **স্থিতিস্থাপকতা** | অনুরোধের সারি, সংযোগের কুলডাউন, প্রোভাইডার ব্রেকার কনফিগারেশন এবং কুলডাউনের জন্য অপেক্ষার আচরণ                                                                                   |
| **উন্নত**          | গ্লোবাল প্রক্সি কনফিগারেশন (HTTP/SOCKS5), প্রতিটি প্রোভাইডারের জন্য আলাদা প্রক্সি ওভাররাইড                                                                                       |

সাধারণ ট্যাবে এখন আর শুধু-পঠনযোগ্য লগিং ও ক্যাশ-সংক্রান্ত নোটের পুনরাবৃত্তি নেই। ডেটাবেসের সংরক্ষণকাল এবং
অপ্টিমাইজেশন সেটিংস `/api/settings/database`-এর মাধ্যমে সংরক্ষিত থাকে; ম্যানুয়ালি ক্যাশ পরিষ্কার করতে
`DELETE /api/cache` ব্যবহার করা হয়। অনুরোধ ও প্রক্সি লগের সারি-সীমা
`CALL_LOGS_TABLE_MAX_ROWS` এবং `PROXY_LOGS_TABLE_MAX_ROWS` দ্বারা নিয়ন্ত্রিত হয়।

### খরচ ও বাজেট ব্যবস্থাপনা

**ড্যাশবোর্ড → খরচ** থেকে অ্যাক্সেস করুন।

| ট্যাব             | উদ্দেশ্য                                                                                                    |
| ----------------- | ----------------------------------------------------------------------------------------------------------- |
| **বাজেট**         | দৈনিক/সাপ্তাহিক/মাসিক বাজেটসহ প্রতিটি API কী-এর জন্য ব্যয়সীমা নির্ধারণ এবং রিয়েল-টাইমে পর্যবেক্ষণ করুন    |
| **মূল্যনির্ধারণ** | মডেলের মূল্যনির্ধারণ এন্ট্রি দেখুন ও সম্পাদনা করুন — প্রতিটি প্রোভাইডারের প্রতি 1K ইনপুট/আউটপুট টোকেনের খরচ |

```bash
# API: একটি বাজেট নির্ধারণ করুন
curl -X POST http://localhost:20128/api/usage/budget \
  -H "Content-Type: application/json" \
  -d '{"keyId": "key-123", "limit": 50.00, "period": "monthly"}'

# API: বর্তমান বাজেটের স্থিতি দেখুন
curl http://localhost:20128/api/usage/budget
```

**খরচ পর্যবেক্ষণ:** প্রতিটি অনুরোধে টোকেন ব্যবহার লগ করা হয় এবং মূল্যনির্ধারণ টেবিল ব্যবহার করে খরচ গণনা করা হয়। প্রোভাইডার, মডেল এবং API কী অনুযায়ী বিস্তারিত হিসাব **ড্যাশবোর্ড → ব্যবহার**-এ দেখুন।

### অডিও ট্রান্সক্রিপশন

OmniRoute, OpenAI-সামঞ্জস্যপূর্ণ এন্ডপয়েন্টের মাধ্যমে অডিও ট্রান্সক্রিপশন সমর্থন করে:

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data

# curl ব্যবহারের উদাহরণ
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@audio.mp3" \
  -F "model=openai/whisper-1"
```

`deepgram/nova-3` হলো নেটিভ Deepgram রুট এবং এর জন্য একটি Deepgram API কী প্রয়োজন।
শুধু OpenRouter কনফিগার করা থাকলে `openrouter/deepgram/nova-3` ব্যবহার করুন।

- `assemblyai/`

- `qwen/`

**ড্যাশবোর্ড → কম্বো → তৈরি/সম্পাদনা → কৌশল** থেকে প্রতিটি কম্বোর ভারসাম্য কনফিগার করুন।

| কৌশল                  | বিবরণ                                                                          |
| --------------------- | ------------------------------------------------------------------------------ |
| **রাউন্ড-রবিন**       | মডেলগুলোর মধ্য দিয়ে ধারাবাহিকভাবে আবর্তন করে                                  |
| **অগ্রাধিকার**        | সবসময় প্রথম মডেলটি চেষ্টা করে; শুধু ত্রুটি ঘটলেই ফলব্যাক করে                  |
| **এলোমেলো**           | প্রতিটি অনুরোধের জন্য কম্বো থেকে এলোমেলোভাবে একটি মডেল বেছে নেয়               |
| **ওয়েটেড**           | প্রতিটি মডেলের জন্য নির্ধারিত ওজনের অনুপাতে রাউট করে                           |
| **সর্বনিম্ন-ব্যবহৃত** | সাম্প্রতিক অনুরোধ সবচেয়ে কম পাওয়া মডেলে রাউট করে (কম্বো মেট্রিক ব্যবহার করে) |
| **খরচ-অপ্টিমাইজড**    | উপলভ্য সবচেয়ে সস্তা মডেলে রাউট করে (মূল্যনির্ধারণ টেবিল ব্যবহার করে)          |

গ্লোবাল কম্বোর ডিফল্ট **ড্যাশবোর্ড → সেটিংস → রাউটিং → কম্বোর ডিফল্ট**-এ নির্ধারণ করা যায়।
কম্বো টার্গেটের টাইমআউট ডিফল্টভাবে বর্তমান অনুরোধের টাইমআউট থেকে উত্তরাধিকারসূত্রে পাওয়া যায়। শুধু তখনই কম্বোর ডিফল্ট বা কোনো পৃথক কম্বোতে **টার্গেট টাইমআউট
(সেকেন্ড)** ব্যবহার করুন, যখন প্রতিটি টার্গেটের জন্য কম সময়সীমা নির্ধারণ করে
দ্রুততর ফলব্যাক ট্রিগার করা দরকার।

শূন্য-বিলম্বের কম্বো অপ্টিমাইজেশনগুলো ব্যবহার করতে হলে স্পষ্টভাবে চালু করতে হবে। এসব বিলম্ব-সংক্রান্ত ফিচার যেন ফলব্যাক টার্গেটগুলোর সঙ্গে প্রতিযোগিতা না করে, TTFT
ইতিহাসের ভিত্তিতে টার্গেট এড়িয়ে না যায় বা ফলব্যাক অনুরোধ কম্প্রেস না করে, সে জন্য **শূন্য-বিলম্ব অপ্টিমাইজেশন** নিষ্ক্রিয় রাখুন; এটি সক্রিয় করলে কনফিগার করা হেজিং, পূর্বাভাসমূলক TTFT
স্কিপ এবং প্রোঅ্যাক্টিভ ফলব্যাক কম্প্রেশন কম টেইল ল্যাটেন্সির বিনিময়ে রাউটিং/অনুরোধের যথার্থতায় আপস করতে পারে।

আপস্ট্রিম প্রদানকারীদের কঠোর `max_tokens` / `maxOutputTokens` সীমা প্রয়োজন হলে **Reasoning token buffer** নিষ্ক্রিয় করুন। এটি সক্রিয় থাকলে, কম্বো রাউটিং শুধুমাত্র পরিচিত আউটপুট সীমাযুক্ত মডেলগুলোর জন্য রিজনিং-মডেলের অতিরিক্ত টোকেনের সুযোগ যোগ করে এবং নিরাপদ বাফারযুক্ত মানটি সেই সীমা অতিক্রম করলে ক্লায়েন্টের টোকেন সীমা অপরিবর্তিত রাখে। ক্লায়েন্টের সীমা আগে থেকেই কোনো পরিচিত সীমার বেশি হলে, আপস্ট্রিম অনুরোধ পাঠানোর আগে OmniRoute সেটিকে কমিয়ে সেই সীমায় নির্ধারণ করে।

## 🤖 স্বয়ংক্রিয় রাউটিং (শূন্য-কনফিগারেশন)

OmniRoute-এর সঙ্গে রয়েছে একটি **স্কোর-চালিত স্বয়ংক্রিয় রাউটার**, যা সংযুক্ত প্রতিটি প্রোভাইডারের মধ্য থেকে প্রতিটি অনুরোধের জন্য সেরা মডেলটি বেছে নেয় — রক্ষণাবেক্ষণের জন্য কোনো কম্বো প্রয়োজন নেই। শুধু `auto/*` প্রিফিক্সগুলোর একটি দিয়ে অনুরোধ পাঠান, আর OmniRoute তাৎক্ষণিকভাবে একটি ভার্চুয়াল কম্বো তৈরি করবে এবং ল্যাটেন্সি, খরচ, সফলতার হার, কনটেক্সটের সামঞ্জস্য, কাজটির জন্য মডেলের উপযুক্ততা, সাম্প্রতিক ব্যর্থতা, কোটা ও সার্কিট-ব্রেকারের অবস্থার ভিত্তিতে প্রার্থীদের স্কোর করবে।

| প্রিফিক্স      | যে বিষয়ের জন্য অপ্টিমাইজ করে                                                            |
| -------------- | ---------------------------------------------------------------------------------------- |
| `auto`         | ভারসাম্যপূর্ণ ডিফল্ট (ল্যাটেন্সি × খরচ × সফলতার হার)                                     |
| `auto/coding`  | কোডিংয়ের কাজ: Claude, GPT-5, GLM, Kimi, Qwen Coder ও DeepSeek কোডারকে অগ্রাধিকার দেয়   |
| `auto/cheap`   | সর্বনিম্ন $/token, বেশি ল্যাটেন্সি গ্রহণ করে                                             |
| `auto/fast`    | সর্বনিম্ন ল্যাটেন্সি, খরচ উপেক্ষা করে                                                    |
| `auto/offline` | শুধু স্থানীয় প্রোভাইডার (Ollama, vLLM, llama.cpp) — এয়ার-গ্যাপড সেটআপের জন্য উপযোগী    |
| `auto/smart`   | রিজনিংয়ের গুণমানকে সর্বোচ্চ অগ্রাধিকার দেয় (Opus, GPT-5 xhigh, R1, GLM 5.1 reasoning)  |
| `auto/lkgp`    | "সর্বশেষ কার্যকর প্রোভাইডার" — সর্বশেষ সফল প্রোভাইডারে স্থির থাকে, এরপর নিয়মে ফিরে যায় |

উদাহরণ:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "এই Python ফাংশনটি রিফ্যাক্টর করুন" }],
    "stream": true
  }'
```

স্কোরিংয়ের ওয়েট কীভাবে সামঞ্জস্য করতে হয়, প্রোভাইডারকে ব্ল্যাকলিস্ট করতে হয় এবং **ড্যাশবোর্ড → স্বয়ংক্রিয় কম্বো**-তে রাউটিংয়ের সিদ্ধান্ত পরিদর্শন করতে হয়—এসবসহ স্বয়ংক্রিয় রাউটারের সম্পূর্ণ বিবরণ [AUTO-COMBO.md](../routing/AUTO-COMBO.md)-এ রয়েছে।

## 🔌 MCP ও A2A ইন্টিগ্রেশন

OmniRoute একই সঙ্গে একটি **MCP সার্ভার** (Model Context Protocol) এবং একটি **A2A সার্ভার** (Agent-to-Agent JSON-RPC 2.0)। যেকোনো MCP-সামঞ্জস্যপূর্ণ IDE বা এজেন্ট হোস্ট সরাসরি OmniRoute-এর টুল কল করতে পারে — অতিরিক্ত কোনো র্যাপারের প্রয়োজন নেই।

### MCP ট্রান্সপোর্ট

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **স্ট্রিমযোগ্য HTTP**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (যেসব IDE প্লাগইন stdio পছন্দ করে তাদের জন্য)

### Claude Desktop সংযুক্ত করুন

macOS-এ `~/Library/Application Support/Claude/claude_desktop_config.json` অথবা Windows/Linux-এ সমতুল্য ফাইলটি সম্পাদনা করুন:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Cursor / Continue / VS Code MCP সংযুক্ত করুন

SSE URL `http://localhost:20128/api/mcp/sse` এবং **ড্যাশবোর্ড → API কীসমূহ**-এ তৈরি করা একটি Bearer API কী ব্যবহার করুন।

### স্কোপ

MCP বর্তমানে 32টি নামযুক্ত স্কোপ নির্ধারণ করে। প্রতিটি Bearer কীকে নির্দিষ্ট স্কোপে সীমাবদ্ধ করা যায় — প্রামাণ্য স্কোপ ও টুলের তালিকার জন্য [MCP-SERVER.md](../frameworks/MCP-SERVER.md) এবং JSON-RPC স্কিমার জন্য [A2A-SERVER.md](../frameworks/A2A-SERVER.md) দেখুন।

## 🧠 স্কিলস সিস্টেম

OmniRoute একটি সম্প্রসারণযোগ্য **স্কিল ফ্রেমওয়ার্ক** (`src/lib/skills/`) প্রদান করে, যার মাধ্যমে এজেন্ট এবং A2A এন্ডপয়েন্ট ডোমেইন-নির্দিষ্ট রুটিন চালাতে পারে (যেমন `code-review`, `summarize`, `extract-facts`, `web-research`)।

- **মার্কেটপ্লেস UI** — **ড্যাশবোর্ড → স্কিলস** থেকে স্কিল ব্রাউজ ও ইনস্টল করুন

- **কাস্টম স্কিল** — `src/lib/a2a/skills/`-এ একটি TypeScript ফাইল রাখুন, সেটি নিবন্ধন করুন, এবং তা সঙ্গে সঙ্গে A2A-এর মাধ্যমে ব্যবহারযোগ্য হয়ে যাবে

সম্পূর্ণ রেফারেন্স: [SKILLS.md](../frameworks/SKILLS.md)।

## 💾 মেমরি সিস্টেম

OmniRoute হাইব্রিড রিট্রিভালসহ **দীর্ঘমেয়াদি কথোপকথনের মেমরি** সংরক্ষণ করে:

- অতীতের কথোপকথনের টার্নগুলোতে কীওয়ার্ড অনুসন্ধানের জন্য **SQLite FTS5**
- শব্দার্থভিত্তিক স্মরণশক্তির জন্য **Qdrant vector store** (ঐচ্ছিক)
- **স্বয়ংক্রিয় তথ্য নিষ্কাশন** — প্রতিটি সেশনের পরে সত্তা, পছন্দ এবং সিদ্ধান্তগুলো সংক্ষেপিত হয়ে `memory_facts` টেবিলে সংরক্ষিত হয়
- মেমরিগুলো প্রতি API কী এবং প্রতি সেশন অনুযায়ী সীমাবদ্ধ থাকে

**ড্যাশবোর্ড → মেমরি** থেকে মেমরি পরিচালনা করুন (অনুসন্ধান, সম্পাদনা, এক্সপোর্ট, মুছে ফেলা)। HTTP ইন্টারফেস (`/api/memory/*`) এজেন্টদের প্রোগ্রামগতভাবে তথ্য পাঠানো ও অনুসন্ধান করার সুযোগ দেয় — দেখুন [MEMORY.md](../frameworks/MEMORY.md)।

## 🔔 ওয়েবহুক

রিয়েল-টাইম পর্যবেক্ষণ ও অটোমেশনের জন্য OmniRoute ইভেন্ট সাবস্ক্রাইব করুন।

- লক্ষ্য URL এবং HMAC স্বাক্ষর গোপন কী দিয়ে **ড্যাশবোর্ড → ওয়েবহুকস**-এ একটি ওয়েবহুক তৈরি করুন
- উপলভ্য ইভেন্ট: `request.completed`, `request.failed`, `provider.unavailable`, `budget.exceeded`, `combo.switched`, `circuit_breaker.opened`, `circuit_breaker.closed`
- যাচাইয়ের জন্য প্রতিটি পেলোডে `X-OmniRoute-Signature` (HMAC-SHA256) অন্তর্ভুক্ত থাকে
- পুনঃচেষ্টা: সূচকীয় ব্যাকঅফসহ 3 বার চেষ্টা, তারপর ডেড-লেটার কিউ

সম্পূর্ণ স্কিমা [WEBHOOKS.md](../frameworks/WEBHOOKS.md)-এ রয়েছে।

## ☁️ ক্লাউড এজেন্ট

OmniRoute ক্লাউড কোডিং এজেন্টের (**OpenAI Codex Cloud**, **Devin**, **Jules**, **Antigravity**) সঙ্গে সমন্বিত হয়, ফলে স্থানীয় রাউটিং পরিচালনাকারী একই ড্যাশবোর্ড থেকে দীর্ঘমেয়াদি কাজ পাঠাতে পারেন।

- **ড্যাশবোর্ড → ক্লাউড এজেন্টস** থেকে অথবা `POST /api/v1/agents/tasks`-এর মাধ্যমে কাজ তৈরি করুন
- প্রতিটি কাজের অবস্থা, লগ এবং আর্টিফ্যাক্ট ট্র্যাক করুন
- প্রতিটি প্রোভাইডারের জন্য নিজের API কী ব্যবহার করুন — ক্রেডেনশিয়াল কখনোই OmniRoute ইনস্ট্যান্সের বাইরে যায় না

সম্পূর্ণ রেফারেন্স: [CLOUD_AGENT.md](../frameworks/CLOUD_AGENT.md)।

## 🛠️ প্রোগ্রামগত ব্যবস্থাপনা

**`manage` স্কোপসহ একটি Bearer কী** ব্যবহার করে HTTP-এর মাধ্যমে OmniRoute-এর প্রতিটি রিসোর্স (প্রোভাইডার, কম্বো, কী, সেটিংস) পরিচালনা করতে পারেন।

**ড্যাশবোর্ড → API কীসমূহ → নতুন কী → স্কোপ: manage** থেকে কী তৈরি করুন, তারপর:

```bash
# প্রোভাইডারগুলোর তালিকা দেখুন
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# একটি প্রোভাইডার সংযোগ যোগ করুন
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# একটি কম্বো তৈরি করুন
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# API কীসমূহের তালিকা দেখুন/তৈরি করুন
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

সম্পূর্ণ এন্ডপয়েন্ট ক্যাটালগ এবং অনুরোধ/প্রতিক্রিয়া স্কিমার জন্য [API_REFERENCE.md](../reference/API_REFERENCE.md) দেখুন।

## 💻 অভ্যন্তরীণ CLI

সেটআপ, ডায়াগনস্টিকস এবং রানটাইম নিয়ন্ত্রণের জন্য OmniRoute-এর সঙ্গে একটি অভ্যন্তরীণ CLI (`omniroute …`) রয়েছে। এটি ড্যাশবোর্ডের **"CLI Tools" পৃষ্ঠা থেকে আলাদা**, যেখানে তৃতীয়-পক্ষের CLI-গুলোকে (Claude Code, Cursor, Codex, Cline, …) কনফিগার করা হয়, যাতে সেগুলো OmniRoute-এর সঙ্গে যোগাযোগ করতে পারে।

```bash
omniroute setup                    # ইন্টার্যাক্টিভ উইজার্ড (পাসওয়ার্ড, প্রোভাইডার, কম্বো)
omniroute setup --non-interactive  # CI-বান্ধব
omniroute doctor                   # স্বাস্থ্য ডায়াগনস্টিকস (ডেটা ডিরেক্টরি, DB, প্রোভাইডার, পোর্ট)
omniroute providers available      # সমর্থিত প্রোভাইডারগুলোর তালিকা দেখান
omniroute providers list           # কনফিগার করা সংযোগগুলোর তালিকা দেখান
omniroute providers test <id>      # কোনো প্রোভাইডার সংযোগের লাইভ পরীক্ষা করুন
omniroute combos list              # কম্বোগুলোর তালিকা দেখান
omniroute combos switch <name>     # ডিফল্ট কম্বো নির্ধারণ করুন
omniroute models                   # উপলভ্য মডেলগুলোর তালিকা দেখান (--json, --search)
omniroute keys add | list | remove # টার্মিনাল থেকে API কী পরিচালনা করুন
omniroute backup                   # কনফিগারেশন + DB-এর স্ন্যাপশট নিন
omniroute restore [<timestamp>]    # একটি স্ন্যাপশট থেকে পুনরুদ্ধার করুন
omniroute health                   # বিস্তারিত স্বাস্থ্যতথ্য (ব্রেকার, ক্যাশ, মেমরি)
omniroute quota                    # প্রোভাইডারের কোটা ব্যবহার
omniroute mcp status               # MCP সার্ভারের অবস্থা
omniroute a2a status               # A2A সার্ভারের অবস্থা
omniroute tunnel list|create|stop  # Cloudflare/Tailscale/ngrok টানেল
omniroute reset-password           # অ্যাডমিন পাসওয়ার্ড রিসেট করুন
omniroute --mcp                    # stdio-এর মাধ্যমে MCP সার্ভার চালু করুন
omniroute --port 3000              # কাস্টম পোর্টে সার্ভার চালু করুন
```

পরামর্শ: অস্বাস্থ্যকর প্রোভাইডার সংযোগ সম্পর্কে সতর্কতা পেতে আপনার মনিটরিং টুলের সঙ্গে `omniroute doctor --json` ব্যবহার করুন।

## 🖥️ ডেস্কটপ অ্যাপ্লিকেশন (Electron)

OmniRoute Windows, macOS এবং Linux-এর জন্য একটি নেটিভ ডেস্কটপ অ্যাপ্লিকেশন হিসেবে উপলভ্য।

### ইনস্টলেশন

```bash
# electron ডিরেক্টরি থেকে:
cd electron
npm install

# ডেভেলপমেন্ট মোড (চলমান Next.js ডেভ সার্ভারের সঙ্গে সংযোগ করে):
npm run dev

# প্রোডাকশন মোড (স্ট্যান্ডঅ্যালোন বিল্ড ব্যবহার করে):
npm start
```

### ইনস্টলার তৈরি

```bash
cd electron
npm run build          # বর্তমান প্ল্যাটফর্ম
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg universal)
npm run build:linux    # Linux (.AppImage)
```

আউটপুট → `electron/dist-electron/`
