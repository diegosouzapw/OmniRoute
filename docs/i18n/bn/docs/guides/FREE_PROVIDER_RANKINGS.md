> **সংক্ষেপে**: OmniRoute তার **বিনামূল্যের** প্রদানকারীদের মডেলের গুণমান অনুযায়ী ক্রম নির্ধারণ করতে **Arena AI
> (LMArena-শৈলীর) ELO স্কোর** ব্যবহার করে। আপনার কাজের জন্য কোন বিনামূল্যের প্রদানকারীরা সবচেয়ে শক্তিশালী মডেল দেয় তা দেখতে
> ড্যাশবোর্ডের **বিনামূল্যের প্রদানকারীদের র্যাঙ্কিং** পৃষ্ঠা খুলুন —
> সামগ্রিকভাবে অথবা বিভাগ অনুযায়ী ফিল্টার করে (কোডিং, পর্যালোচনা, ডকুমেন্টেশন, ডিবাগিং)।

## এটি কী

OmniRoute 329টি প্রদানকারী নিবন্ধন করে, যার মধ্যে 155টি ক্যাটালগ এন্ট্রি **বিনামূল্যের/প্রমাণীকরণ-বিহীন** হিসেবে চিহ্নিত
(প্রমাণীকরণ-বিহীন,
বিনামূল্যের-স্তরের OAuth অথবা বিনামূল্যের-স্তরের API কী — দেখুন
[বিনামূল্যের স্তরের নির্দেশিকা](../getting-started/FREE-TIERS-GUIDE.md) এবং সম্পূর্ণ
[বিনামূল্যের স্তরের ডিরেক্টরি](../reference/FREE_TIERS.md))। তবে সমস্যা হলো: বিনামূল্যের প্রদানকারীদের
মডেলের গুণমানে ব্যাপক পার্থক্য রয়েছে। একটি ফ্রন্টিয়ার মডেল সরবরাহকারী প্রমাণীকরণ-বিহীন প্রদানকারী,
একটি ছোট পুরোনো মডেল সরবরাহকারী প্রদানকারীর চেয়ে অনেক বেশি কার্যকর।

**বিনামূল্যের প্রদানকারীদের র্যাঙ্কিং** প্রতিটি বিনামূল্যের প্রদানকারীর ক্যাটালগকে
**Arena AI লিডারবোর্ডের** **ক্রাউড-সোর্সড গুণমান স্কোরের** সঙ্গে যুক্ত করে
"**কোন বিনামূল্যের প্রদানকারী আমাকে সেরা মডেল দেয়?**" প্রশ্নের উত্তর দেয় (মানব-পছন্দভিত্তিক ELO,
যা LMArena চ্যাটবট অ্যারেনার পেছনের ধারণার অনুরূপ)। এরপর প্রদানকারীদের তাদের
**সেরা বিনামূল্যের মডেলের** সক্ষমতা অনুযায়ী র্যাঙ্ক করা হয়।

র্যাঙ্কিংটি তিনটি বাস্তব উৎস থেকে গণনা করা হয়:

1. বিনামূল্যের প্রদানকারীদের তালিকা — `NOAUTH_PROVIDERS`, এবং `hasFree` হিসেবে চিহ্নিত
   `OAUTH_PROVIDERS` / `APIKEY_PROVIDERS` এন্ট্রি
   (`src/shared/constants/providers.ts`)।
2. প্রদানকারী রেজিস্ট্রি থেকে প্রতিটি প্রদানকারীর মডেল ক্যাটালগ
   (`open-sse/config/providerRegistry.ts`)।
3. Arena ELO সিঙ্ক ইঞ্জিন (`src/lib/arenaEloSync.ts`) দ্বারা `model_intelligence`
   DB টেবিলে সংরক্ষিত ELO-উদ্ভূত কাজের উপযোগিতা স্কোর।

সংযুক্তিকরণের লজিকটি `src/lib/freeProviderRankings.ts`-এ রয়েছে।

## কীভাবে অ্যাক্সেস করবেন

### ড্যাশবোর্ড পৃষ্ঠা

ড্যাশবোর্ড খুলে **খরচ → বিনামূল্যের প্রদানকারীদের র্যাঙ্কিং**-এ যান, অথবা সরাসরি এখানে নেভিগেট করুন:

```
/dashboard/free-provider-rankings
```

এই পৃষ্ঠায় (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) দেখা যায়:

- সেরা র্যাঙ্কপ্রাপ্ত বিনামূল্যের প্রদানকারীদের একটি **শীর্ষ-৩ পোডিয়াম** (🥇 🥈 🥉)।
- **র্যাঙ্ক**, **প্রদানকারী**, **শীর্ষ মডেল**,
  **স্কোর**, **গড় স্কোর**, **মডেল**, **ধরন** কলামসহ একটি পূর্ণাঙ্গ **র্যাঙ্কিং টেবিল**।
- **বিভাগ ফিল্টার বোতাম**: _সব বিভাগ_, _ডিফল্ট_, _কোডিং_, _পর্যালোচনা_,
  _ডকুমেন্টেশন_, _ডিবাগিং_।

প্রতিটি প্রদানকারীর **ধরন** ব্যাজ জানায় সেটি কীভাবে বিনামূল্যে পাওয়া যায়:

| ব্যাজ    | অর্থ                                              |
| -------- | ------------------------------------------------- |
| `NOAUTH` | সর্বদা বিনামূল্যে, কোনো পরিচয়পত্রের প্রয়োজন নেই |
| `OAUTH`  | বিনামূল্যের স্তরসহ OAuth প্রদানকারী (`hasFree`)   |
| `APIKEY` | বিনামূল্যের স্তরসহ API-কী প্রদানকারী (`hasFree`)  |

স্কোরগুলো অপরিশোধিত সংখ্যার পরিবর্তে মানুষের পাঠযোগ্য লেবেল হিসেবে দেখানো হয় (যেমন _অভিজাত_, _চমৎকার_, _খুব ভালো_,
_ভালো_, _গড়_), কারণ অন্তর্নিহিত মানটি একটি আপেক্ষিক
র্যাঙ্কিং-গুণমান, শতকরা হার নয়।

### API এন্ডপয়েন্ট

পৃষ্ঠাটি একটি সর্বজনীন রিড এন্ডপয়েন্ট দ্বারা পরিচালিত
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

কোয়েরি প্যারামিটারসমূহ (Zod দিয়ে যাচাই করা):

| প্যারামিটার | ধরন    | ডিফল্ট        | নোট                                                                                                                  |
| ----------- | ------ | ------------- | -------------------------------------------------------------------------------------------------------------------- |
| `category`  | string | (কোনোটিই নয়) | `default`, `coding`, `review`, `documentation`, `debugging`-এর যেকোনো একটি। সম্মিলিত র্যাঙ্কিংয়ের জন্য এটি বাদ দিন। |
| `limit`     | number | `50`          | `1–100` সীমার মধ্যে আবদ্ধ করা হয়।                                                                                   |

রেসপন্সের কাঠামো:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` হলো মূল Arena ELO মান; `score` হলো স্বাভাবিকীকৃত কাজের উপযোগিতা মান
(নিচে দেখুন)। স্কোরযুক্ত কোনো মডেল নেই এমন প্রদানকারীদের রেসপন্স থেকে বাদ দেওয়া হয়।

## স্কোর কীভাবে কাজ করে

### উৎস: Arena AI লিডারবোর্ড

Arena ELO সিঙ্ক ইঞ্জিন (`src/lib/arenaEloSync.ts`) Arena AI লিডারবোর্ড API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) থেকে দুটি লিডারবোর্ড — `text`
এবং `code` — নিয়ে আসে। প্রতিটি লিডারবোর্ড এন্ট্রিতে একটি মডেলের নাম, বিক্রেতা, ELO `score`,
কনফিডেন্স ইন্টারভ্যাল এবং ভোটের সংখ্যা থাকে।

লিডারবোর্ডের বিভাগগুলো OmniRoute-এর টাস্ক বিভাগের সঙ্গে এভাবে ম্যাপ করা হয়:

| Arena লিডারবোর্ড | OmniRoute টাস্ক বিভাগ                             |
| ---------------- | ------------------------------------------------- |
| `text`           | `default`, `review`, `documentation`, `debugging` |
| `code`           | `coding`                                          |

### স্বাভাবিকীকরণ (টাস্ক-ফিট স্কোর)

প্রতিটি লিডারবোর্ডের কাঁচা ELO স্কোরকে স্বাভাবিকীকরণ করে **`[0.4, 0.98]` সীমার মধ্যে একটি টাস্ক-ফিট মানে** রূপান্তর করা হয়:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

স্কোরটি কখনোই `0` বা `1`-এ পৌঁছায় না, ফলে ব্যবহারকারীর ওভাররাইডের জন্য কিছু পরিসর অবশিষ্ট থাকে।
এটিই API রেসপন্সে দেখা `score` ফিল্ড এবং ড্যাশবোর্ডে প্রদর্শিত লেবেল।

### কনফিডেন্স

Arena ভোটের সংখ্যার ভিত্তিতে প্রতিটি এন্ট্রিকে একটি কনফিডেন্স স্তর দেওয়া হয়:

| কনফিডেন্স | ভোট     |
| --------- | ------- |
| `high`    | ≥ 5,000 |
| `medium`  | ≥ 1,000 |
| `low`     | < 1,000 |

### সংরক্ষণ ও ডেটার সতেজতা

স্বাভাবিকীকৃত এন্ট্রিগুলো `source = "arena_elo"` সহ `model_intelligence` DB টেবিলে লেখা হয়
(`src/lib/db/modelIntelligence.ts`)। এন্ট্রিগুলোর মেয়াদ **7 দিন পরে শেষ হয়ে যায়**, ফলে কোনো
প্রোভাইডার সিঙ্ক করা বন্ধ করলে পুরোনো ডেটা পরিবেশন না করে শেষ পর্যন্ত তালিকা থেকে বাদ পড়ে যায়।

সিঙ্কটি **ডিফল্টভাবে চালু থাকে**:

- এটি সার্ভার চালু হওয়ার সময় একবার এবং এরপর নির্দিষ্ট সময় পরপর চলে
  (`src/lib/arenaEloSync.ts`, `src/instrumentation-node.ts` থেকে সংযুক্ত)।
- এটি **নন-ব্লকিং এবং কখনোই মারাত্মক ব্যর্থতার কারণ হয় না** — আপস্ট্রিম ফেচ ব্যর্থ হলে OmniRoute
  চলতে থাকে এবং র্যাঙ্কিংয়ে কেবল সর্বশেষ সফল ডেটা (অথবা একটি খালি অবস্থা) দেখানো হয়।

দুটি এনভায়রনমেন্ট ভেরিয়েবল এটি নিয়ন্ত্রণ করে ([`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)-এ
নথিভুক্ত):

| ভেরিয়েবল                 | ডিফল্ট        | উদ্দেশ্য                                        |
| ------------------------- | ------------- | ----------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | আউটবাউন্ড সিঙ্ক থেকে সরে আসতে `false` সেট করুন। |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | সেকেন্ডে সিঙ্কের ব্যবধান।                       |

### ম্যানুয়াল সিঙ্ক / স্ট্যাটাস / মুছে ফেলা

অপারেটরদের জন্য, একটি প্রমাণীকৃত ম্যানেজমেন্ট এন্ডপয়েন্ট ম্যানুয়াল নিয়ন্ত্রণের সুবিধা দেয়
(`src/app/api/intelligence/sync/route.ts` — ম্যানেজমেন্ট প্রমাণীকরণ প্রয়োজন):

```
GET    /api/intelligence/sync          # বর্তমান সিঙ্ক স্ট্যাটাস (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # একটি ম্যানুয়াল সিঙ্ক শুরু করুন; না লিখে প্রিভিউ দেখতে বডি: { "dryRun": true }
DELETE /api/intelligence/sync          # সিঙ্ক করা সব arena_elo ইন্টেলিজেন্স এন্ট্রি মুছে ফেলুন
```

র্যাঙ্কিং পৃষ্ঠা খালি থাকলে, একটি ম্যানুয়াল `POST /api/intelligence/sync` (অথবা শুধু
সার্ভার পুনরায় চালু করা) সেটি আবার পূরণ করে।

### লিডারবোর্ডের সঙ্গে মডেল মেলানো

রেজিস্ট্রির মডেল ID এবং Arena-এর মডেল নাম সবসময় হুবহু মেলে না। র্যাঙ্কিংটি নমনীয়
ম্যাচিং ব্যবহার করে (`src/lib/freeProviderRankings.ts`-এর `findMatchingIntelligence`):

1. স্বাভাবিকীকৃত মডেল ID-এর সঙ্গে হুবহু মিল।
2. শেষে থাকা সংস্করণ সাফিক্স বাদ দেওয়ার পর মিল (যেমন `kimi-k2.6` → `kimi-k2`)।
3. প্রিফিক্স মিল (লিডারবোর্ডের কোনো মডেল নাম রেজিস্ট্রি ID-এর প্রিফিক্স হলে)।

সিঙ্কের দিকে, পরিচিত বিক্রেতার প্রিফিক্সগুলো (`anthropic/`, `openai/`, `google/`, …)
বাদ দেওয়া হয় এবং একটি ছোট অ্যালিয়াস ম্যাপ ক্যানোনিক্যাল নামগুলোকে OmniRoute অভ্যন্তরীণভাবে
ব্যবহার করা ভ্যারিয়েন্টে প্রসারিত করে, ফলে যেকোনো নামেই মডেলগুলো খুঁজে পাওয়া যায়।

### কোনো প্রোভাইডারকে যেভাবে র্যাঙ্ক করা হয়

প্রতিটি বিনামূল্যের প্রোভাইডারের জন্য, ইঞ্জিনটি তার ক্যাটালগের প্রতিটি মডেলকে স্কোর করে, এরপর:

- **শীর্ষ মডেল** = প্রোভাইডারের সর্বোচ্চ স্কোরপ্রাপ্ত মডেল।
- **গড় স্কোর** = প্রোভাইডারের স্কোরপ্রাপ্ত সব মডেলের গড় স্কোর।
- **মডেল** = প্রোভাইডারের কতটি মডেলের Arena স্কোর ছিল।

প্রোভাইডারগুলোকে প্রথমে **শীর্ষ-মডেলের স্কোর** এবং এরপর গড় স্কোর অনুসারে সাজানো হয়। এতে অন্তত
একটি শক্তিশালী বিনামূল্যের মডেল সরবরাহকারী প্রোভাইডার পুরস্কৃত হয়।

## বিনামূল্যের প্রদানকারী বেছে নিতে এটি ব্যবহার করা

1. **সঠিক বিভাগটি বেছে নিন।** এজেন্টিক/কোড ওয়ার্কলোডের জন্য **Coding** ফিল্টার ব্যবহার করুন, অথবা
   সাধারণ চ্যাটের জন্য এটিকে **All Categories** / **Default**-এ রাখুন। একই প্রদানকারীর
   অবস্থান বিভিন্ন বিভাগে ভিন্ন হতে পারে, কারণ প্রতিটি লিডারবোর্ডে এর শীর্ষ মডেলটি আলাদা হয়।
2. **একবারেই সেটআপ করতে শীর্ষস্থানীয়গুলোকে অগ্রাধিকার দিন।** আপনি যদি শুধু একটি বা দুটি বিনামূল্যের
   প্রদানকারী সংযুক্ত করতে চান, তাহলে আপনার বিভাগের সর্বোচ্চ র্যাঙ্কেরগুলো দিয়ে শুরু করুন।
3. **Type ব্যাজ পরীক্ষা করুন।** `NOAUTH` প্রদানকারীগুলো সবচেয়ে দ্রুত সংযুক্ত করা যায় (কোনো
   পরিচয়পত্র লাগে না)। `OAUTH` / `APIKEY` বিনামূল্যের স্তরের জন্য দ্রুত সাইন-আপ করতে হয়, তবে এগুলো প্রায়ই
   আরও শক্তিশালী মডেল ব্যবহারের সুযোগ দেয়। সংযোগের ধাপগুলোর জন্য [বিনামূল্যের স্তর নির্দেশিকা](../getting-started/FREE-TIERS-GUIDE.md)
   দেখুন।
4. **একাধিক প্রদানকারী সংযুক্ত করুন এবং Auto-Combo-কে সিদ্ধান্ত নিতে দিন।** যে Arena ELO ডেটা
   এই পৃষ্ঠাটি পরিচালনা করে, সেটিই Auto-Combo স্কোরিং ইঞ্জিনের **টাস্ক-উপযোগিতা ফ্যাক্টর**-এও
   ব্যবহৃত হয় (`open-sse/services/autoCombo/taskFitness.ts`, নির্ধারণের ক্রম
   `user_override → arena_elo → models_dev_tier → static table`)। তাই শীর্ষ বিনামূল্যের প্রদানকারীগুলো সংযুক্ত করার পর
   `model: "auto"` (যেমন `auto/coding`) দিয়ে রাউটিং করলে প্রতিটি অনুরোধের জন্য
   স্বয়ংক্রিয়ভাবে উচ্চমানের বিনামূল্যের মডেলগুলোকে অগ্রাধিকার দেওয়া হবে। সম্পূর্ণ ১৬-ফ্যাক্টর স্কোরিংয়ের জন্য
   [Auto-Combo](../routing/AUTO-COMBO.md) দেখুন।
