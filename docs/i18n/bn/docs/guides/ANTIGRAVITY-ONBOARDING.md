## 1. Antigravity বনাম Antigravity CLI (agy)

উভয় প্রোভাইডার একই **Google ব্যাকএন্ড** ব্যবহার করে — অভিন্ন OAuth ক্লায়েন্ট, টোকেন রিফ্রেশ, এন্ডপয়েন্ট এবং Google অ্যাকাউন্ট। পার্থক্য হলো আপনি কোন মডেলগুলো দেখতে পান।

> Google-এর অফিশিয়াল তুলনার জন্য [Antigravity CLI ঘোষণাপত্র](https://antigravity.google/blog/introducing-google-antigravity-cli) দেখুন।

| দিক                          | `antigravity` (IDE)                                   | `agy` (CLI)                                                         |
| ---------------------------- | ----------------------------------------------------- | ------------------------------------------------------------------- |
| **Google পণ্য**              | Antigravity 2.0 / Antigravity IDE                     | Antigravity CLI                                                     |
| **ব্যাকএন্ড**                | একই Google Cloud Code API                             | একই Google Cloud Code API                                           |
| **OAuth / টোকেন**            | একই ক্লায়েন্ট, একই রিফ্রেশ                           | একই ক্লায়েন্ট, একই রিফ্রেশ                                         |
| **মডেল ক্যাটালগ**            | স্থিরভাবে বাছাই করা তালিকা (OmniRoute-এ হার্ডকোড করা) | Google থেকে `:fetchAvailableModels`-এর মাধ্যমে সরাসরি অনুসন্ধান করা |
| **Claude মডেলসমূহ**          | Sonnet 4.6, Opus 4.6 (প্রতিটির 4টি ভ্যারিয়েন্ট)      | Sonnet 4.6, Opus 4.6 (প্রতিটির 4টি ভ্যারিয়েন্ট)                    |
| **Gemini নামকরণ**            | পরিচ্ছন্ন লেবেল (Low/Medium/High)                     | আপস্ট্রিম ID (extra-low/low/agent)                                  |
| **অতিরিক্ত মডেল**            | `gpt-oss-120b-medium`                                 | Google থেকে অতিরিক্ত মডেল অন্তর্ভুক্ত থাকতে পারে                    |
| **ডিফল্ট ব্যবহারের ক্ষেত্র** | IDE ইন্টিগ্রেশন (VS Code, JetBrains)                  | CLI / API অ্যাক্সেস                                                 |
| **কোটা**                     | agy-এর সঙ্গে শেয়ার করা (একই Google অ্যাকাউন্ট)       | antigravity-এর সঙ্গে শেয়ার করা (একই Google অ্যাকাউন্ট)             |

**উপলভ্য মডেলসমূহ (পরীক্ষার মাধ্যমে যাচাইকৃত, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (বিভিন্ন চিন্তন স্তর)
- Claude: Sonnet 4.6, Opus 4.6 (প্রতিটির default/low/medium/high ভ্যারিয়েন্ট)
- অন্যান্য: GPT-OSS 120B Medium
- **Claude Sonnet 5 উপলভ্য নয়** — শুধুমাত্র 4.6 ভ্যারিয়েন্টগুলো সমর্থিত

**মডেল ক্যাটালগ ভিন্ন হওয়ার কারণ**: Google-এর অফিশিয়াল ব্লগ অনুযায়ী, Google-এর CLI-কে "গতি ও কম ওভারহেডের জন্য অপ্টিমাইজ করা হয়েছে" এবং এটি "Gemini মডেলের সঙ্গে যৌথভাবে অপ্টিমাইজ করা হয়েছে।" Web/IDE পণ্যটি "সার্বিকতার জন্য অপ্টিমাইজ করা হয়েছে।" CLI গতিশীলভাবে মডেল আবিষ্কারের জন্য `:fetchAvailableModels` ব্যবহার করে, অন্যদিকে IDE একটি স্থিরভাবে বাছাই করা তালিকা ব্যবহার করে।

**বাস্তবে**: Gemini মডেলের জন্য `agy/` প্রিফিক্স ব্যবহার করুন (যেমন `agy/gemini-3.7-flash-high`)। স্থিরভাবে বাছাই করা তালিকার জন্য `antigravity/` ব্যবহার করুন। উভয়ই একই Google ব্যাকএন্ডে অনুরোধ পাঠায়, তবে মডেলের নামকরণ ভিন্নভাবে প্রকাশ করে। কোটা শেয়ার করা হয় — যেকোনো প্রোভাইডার ব্যবহার করলেই তা একই Google অ্যাকাউন্টের সীমার বিপরীতে গণনা করা হয়।

## 2. Google One AI Pro: কোটা সিস্টেম

> অফিসিয়াল কোটার বিস্তারিত জানতে [Antigravity Docs: Plans](https://antigravity.google/docs/plans) এবং সর্বশেষ মূল্য পরিবর্তনের জন্য [Changes to Antigravity Plans](https://antigravity.google/blog/changes-to-antigravity-plans) দেখুন।

Google Antigravity বার্তার সংখ্যার পরিবর্তে "Work Done" (কম্পিউটেশনাল ওজন)-এর ওপর ভিত্তি করে একটি **দ্বি-স্তরবিশিষ্ট কোটা** ব্যবহার করে।

### দুটি স্তর

| স্তর                   | এটি কী                    | রিফ্রেশ চক্র                                                                          |
| ---------------------- | ------------------------- | ------------------------------------------------------------------------------------- |
| **৫-ঘণ্টার স্প্রিন্ট** | তাৎক্ষণিক "work done" পুল | একটি সেশনে প্রথম অনুরোধের ৫ ঘণ্টা পর রিসেট হয়                                        |
| **৭-দিনের বেসলাইন**    | সাপ্তাহিক সর্বোচ্চ সীমা   | সীমায় পৌঁছালে ৫-ঘণ্টার রিফ্রেশ অগ্রাহ্য করে; পরবর্তী ৭-দিনের সময়কাল পর্যন্ত লক থাকে |

**"Work Done" যেভাবে গণনা করা হয়**: এজেন্ট-নির্ভর ভারী কাজ (যেমন, "এই সম্পূর্ণ রিপোজিটরিটি রিফ্যাক্টর করুন") সাধারণ কাজের (যেমন, "এই ফাংশনটি ঠিক করুন") তুলনায় অনেক দ্রুত কোটা শেষ করে। ব্যবহার দেখানোর জন্য কোনো রিয়েল-টাইম ড্যাশবোর্ড নেই।

### Gemini বনাম Non-Gemini মডেল

- **Gemini মডেল** (Flash + Pro): API মূল্য অনুযায়ী ব্যবহৃত একটি অভিন্ন রেট লিমিট শেয়ার করে। Flash যদি Pro-এর তুলনায় 8x সস্তা হয়, তাহলে আপনি 8x বেশি Flash টোকেন পাবেন।
- **Non-Gemini মডেল** (Claude, GPT-OSS): এগুলোর **আলাদা** রেট লিমিট রয়েছে। Gemini লক হয়ে গেলেও এগুলো উপলভ্য থাকতে পারে।

### AI ক্রেডিট (অতিরিক্ত ব্যবহার)

> ক্রেডিট কীভাবে কাজ করে তা জানতে [Google One AI credits](https://support.google.com/googleone/answer/14534406) দেখুন।

বেসলাইন কোটা শেষ হয়ে গেলে:

- **কখনো নয়**: কোটা রিফ্রেশ হওয়া পর্যন্ত অপেক্ষা করে; "Baseline model quota reached" দেখায়
- **সবসময়**: স্বয়ংক্রিয়ভাবে AI ক্রেডিট ব্যবহার করে; বেসলাইন রিফ্রেশ হলে আবার তাতে ফিরে যায়

ক্রেডিট আলাদাভাবে কেনা হয় এবং স্ট্যান্ডার্ড API মূল্য অনুযায়ী কাটা হয়।

### গুরুত্বপূর্ণ বিবরণ

- কোটা **অ্যাকাউন্ট-স্তরে শেয়ার করা** — Antigravity IDE, CLI এবং OmniRoute-এ একই Google অ্যাকাউন্ট একটি অভিন্ন কোটা পুল শেয়ার করে
- প্রতিটি Google অ্যাকাউন্টের নিজস্ব স্বাধীন কোটা রয়েছে — একাধিক অ্যাকাউন্ট = একাধিক কোটা পুল
- AI Pro ব্যবহারকারীরা জানিয়েছেন, সাপ্তাহিক বেসলাইনের সীমায় পৌঁছালে ৫-ঘণ্টার রিসেটের পরিবর্তে **৭-দিনের লকআউট** ঘটে (Google নিশ্চিত করেছে যে উচ্চ চাহিদার ক্ষেত্রে এটি পরিকল্পিত আচরণ)

**আপনার অ্যাকাউন্টের কোটা শেষ হয়ে গেলে**: OmniRoute স্বয়ংক্রিয়ভাবে কম্বো রুটের পরবর্তী উপলভ্য অ্যাকাউন্ট দিয়ে পুনরায় চেষ্টা করে। কোনো ম্যানুয়াল হস্তক্ষেপের প্রয়োজন নেই।

## 3. যেভাবে একটি projectId পাবেন

প্রতিটি antigravity/agy সংযোগের জন্য একটি Google Cloud Code `projectId` প্রয়োজন। এটি ছাড়া `/v1internal:models` এন্ডপয়েন্ট 404 রিটার্ন করে।

### পদ্ধতি A: স্বয়ংক্রিয় (প্রস্তাবিত)

OmniRoute এটি স্বয়ংক্রিয়ভাবে পরিচালনা করে। Dashboard OAuth-এর মাধ্যমে নতুন Google অ্যাকাউন্ট যোগ করলে:

1. OmniRoute টোকেনটি রিফ্রেশ করে
2. projectId খুঁজে পেতে `loadCodeAssist` কল করে
3. কোনো প্রজেক্ট না থাকলে একটি তৈরি করতে `onboardUser` কল করে
4. নতুন তৈরি করা projectId পেতে `loadCodeAssist` পুনরায় চেষ্টা করে
5. এটি ডেটাবেজে সংরক্ষণ করে

**এটি অধিকাংশ অ্যাকাউন্টের ক্ষেত্রে কাজ করে** — কোনো ম্যানুয়াল ধাপের প্রয়োজন নেই।

### পদ্ধতি B: agy CLI-এর মাধ্যমে ম্যানুয়ালি

স্বয়ংক্রিয় অনুসন্ধান ব্যর্থ হলে (এটি কখন ঘটে তা জানতে অনুচ্ছেদ ৫ দেখুন):

```bash
# agy CLI ইনস্টল করুন (ইতিমধ্যে করা না থাকলে)
npm install -g @anthropic-ai/agy

# আপনার Google অ্যাকাউন্ট দিয়ে লগইন করুন
agy login

# যে অ্যাকাউন্টটির অনবোর্ডিং প্রয়োজন সেটি নির্বাচন করুন
# এটি Cloud Code রেজিস্ট্রেশন ট্রিগার করে এবং একটি projectId বরাদ্দ করে
```

`agy login` সফল হওয়ার পর OmniRoute Dashboard-এ টোকেনটি রিফ্রেশ করুন। projectId স্বয়ংক্রিয়ভাবে খুঁজে পাওয়া যাবে।

### যেভাবে যাচাই করবেন

ডেটাবেজ পরীক্ষা করুন:

```bash
# OmniRoute কনটেইনারের ভেতরে
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

অথবা লগ পরীক্ষা করুন:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. OAuth রিডাইরেক্ট URI

### সমস্যা

Google OAuth-এর জন্য একটি বৈধ রিডাইরেক্ট URI প্রয়োজন। OmniRoute-এর ডিফল্ট হিসেবে `http://127.0.0.1:20128/callback` (লুপব্যাক) ব্যবহৃত হয়। এটি লোকাল বিল্ডের ক্ষেত্রে কাজ করে, কিন্তু **রিমোট ডিপ্লয়মেন্টে ব্যর্থ হয়** (যেমন, LAN IP-এর মাধ্যমে অ্যাক্সেস করা কোনো সার্ভার)।

Google এমন রিডাইরেক্ট URI প্রত্যাখ্যান করে যেগুলো:

- IP অ্যাড্রেস ব্যবহার করে (এটি অবশ্যই `.com`, `.org` ইত্যাদি দিয়ে শেষ হওয়া একটি ডোমেইন হতে হবে)
- OAuth ক্লায়েন্ট কনফিগে নিবন্ধিত রিডাইরেক্ট URI-এর সঙ্গে মেলে না

### সমাধান

**বিকল্প A: বিল্ট-ইন OAuth ফ্লো ব্যবহার করুন (ডিফল্ট)**

- আপনি `localhost` বা `127.0.0.1` থেকে OmniRoute অ্যাক্সেস করলে এটি কাজ করে
- কোনো কনফিগারেশনের প্রয়োজন নেই

**বিকল্প B: কাস্টম OAuth ক্রেডেনশিয়াল**

- আপনার এনভায়রনমেন্টে `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` সেট করুন
- আপনার নিজস্ব Google OAuth ক্রেডেনশিয়াল প্রদান করুন:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Google Cloud Console-এ অনুমোদিত রিডাইরেক্ট URI হিসেবে `https://your-domain.com/callback` নিবন্ধন করুন

**বিকল্প C: প্রাথমিক লগইনের জন্য agy CLI ব্যবহার করুন**

- যে মেশিন থেকে OmniRoute অ্যাক্সেস করা হবে, সেখানে `agy login` চালান
- OAuth ফ্লোটি লোকালভাবে সম্পন্ন হবে এবং টোকেনগুলো সংরক্ষিত হবে
- Dashboard-এর মাধ্যমে সংযোগটি OmniRoute-এ ইমপোর্ট করুন

### সীমাবদ্ধতা

- কাস্টম OAuth ক্রেডেনশিয়ালের জন্য একটি ডোমেইন নাম প্রয়োজন (Google রিডাইরেক্ট URI হিসেবে IP অ্যাড্রেস গ্রহণ করে না)
- আপনার কোনো ডোমেইন না থাকলে এর পরিবর্তে বিকল্প A বা C ব্যবহার করুন

## 5. সমস্যা সমাধান: স্বয়ংক্রিয় সেটআপ ব্যর্থ হলে

বেশিরভাগ অ্যাকাউন্টের ক্ষেত্রে OmniRoute স্বয়ংক্রিয়ভাবে projectId শনাক্তকরণ এবং অনবোর্ডিং পরিচালনা করে। এটি ব্যর্থ হলে, মূল কারণটি সাধারণত নিচের যেকোনো একটি:

### অ্যাকাউন্টের অঞ্চল ব্লক করা হয়েছে

**লক্ষণ**: `agy login` চালালে "যোগ্যতা যাচাই ব্যর্থ হয়েছে: আপনার বর্তমান অ্যাকাউন্ট Antigravity-এর জন্য যোগ্য নয়, কারণ এটি বর্তমানে আপনার অবস্থানে উপলভ্য নয়।" বার্তাটি আসে।

**মূল কারণ**: Google অ্যাকাউন্টে নিবন্ধনের সময় সেট করা একটি ব্যাকএন্ড "Country Association" ফিল্ড থাকে। agy CLI এবং Cloud Code API এই ফিল্ডটি কঠোরভাবে যাচাই করে—অন্যদিকে ওয়েব Gemini কেবল আপনার বর্তমান IP যাচাই করে।

> আপনার অ্যাকাউন্টের সঙ্গে যুক্ত অঞ্চল যাচাই বা পরিবর্তন করতে [Google Country Association Form](https://policies.google.com/country-association-form) দেখুন।

**ওয়েব Gemini কাজ করলেও agy কাজ না করার কারণ**:

- ওয়েব Gemini / Google One: শুধু বর্তমান IP যাচাই করে (প্রক্সি ব্যবহার করলে কাজ করে)
- agy CLI / Cloud Code API: ব্যাকএন্ডের Country Association ফিল্ড পড়ে (প্রক্সি এতে সাহায্য করে না)

**সমাধান**:

1. US IP ব্যবহার করার সময় [Google Country Association Form](https://policies.google.com/country-association-form) দেখুন
2. অঞ্চল পরিবর্তনের অনুরোধ জমা দিন ("I live in a different country" নির্বাচন করুন)
3. Google-এর প্রক্রিয়াকরণ এবং ইমেইল নোটিফিকেশনের জন্য 1-24 ঘণ্টা অপেক্ষা করুন
4. এরপর `agy login` সফল হওয়ার কথা

### অ্যাকাউন্টে কোনো Cloud Code প্রজেক্ট নেই

**লক্ষণ**: লগে `loadCodeAssist returned no project id` এবং `onboardUser failed (400)` দেখা যায়।

**মূল কারণ**: অ্যাকাউন্টটি আগে কখনো Google Cloud Code-এর সঙ্গে নিবন্ধিত হয়নি এবং স্বয়ংক্রিয় অনবোর্ডিং ব্যর্থ হয়েছে।

**সমাধান**: Cloud Code নিবন্ধন ট্রিগার করতে ম্যানুয়ালি `agy login` চালান, তারপর OmniRoute Dashboard-এ টোকেনটি রিফ্রেশ করুন।

### টোকেনের মেয়াদ শেষ হয়েছে বা প্রত্যাহার করা হয়েছে

**লক্ষণ**: লগে 401 ত্রুটি বা "টোকেনের মেয়াদ শেষ হয়েছে" বার্তা দেখা যায়।

**সমাধান**: Dashboard → Providers → agy → রিফ্রেশ আইকনে ক্লিক করে টোকেনটি রিফ্রেশ করুন। রিফ্রেশ টোকেনটিও প্রত্যাহার করা হয়ে থাকলে, আপনাকে OAuth-এর মাধ্যমে পুনরায় প্রমাণীকরণ করতে হবে।
