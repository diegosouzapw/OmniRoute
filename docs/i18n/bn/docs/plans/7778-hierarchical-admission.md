1. বিদ্যমান একক-কী semaphore চুক্তি এবং নতুন atomic বহু-কী
   চুক্তি focused test দিয়ে নিশ্চিত করুন: কোনো আংশিক reservation নয়, FIFO queueing, abort,
   timeout, queue-full, idempotent release, stats, এবং cleanup।
2. বিদ্যমান account semaphore-টিকে একই জায়গায় সাধারণীকরণ করুন। `acquire()`-কে
   `acquireMany()`-এর একটি compatibility wrapper হিসেবে রাখুন; দ্বিতীয় কোনো scheduler
   বা dependency যোগ করবেন না।
3. `chatCore`-এ account-only acquisition-কে `withRateLimit`-এর ঠিক আগে একটি cumulative
   global/provider/account acquisition দিয়ে প্রতিস্থাপন করুন।
   account rotation-এর কারণে connection পরিবর্তিত হলে প্রতিবার সম্পূর্ণ set পুনরায় acquire করুন,
   এবং streaming সম্পন্ন হওয়া পর্যন্ত release ধরে রাখুন।
4. বিদ্যমান resilience settings pipeline-কে (types, defaults,
   normalization, schema, API response, UI, এবং translations) global
   এবং provider cap দিয়ে সম্প্রসারণ করুন। পুরোনো Bottleneck concurrency control-কে
   connection/quota-scope concurrency হিসেবে পুনরায় label করুন, যাতে এর প্রকৃত scope স্পষ্ট হয়।
5. focused test, lint, typecheck, static check, এবং সম্পূর্ণ test suite চালান;
   changelog-এ আচরণগত পরিবর্তনটি নথিভুক্ত করুন।

ইচ্ছাকৃতভাবে সংরক্ষিত আচরণ: শূন্য/null concurrency একটি gate bypass করে,
account-only caller-রা `acquire()` ব্যবহার করতে থাকে, blocked-account control-গুলো
তাদের key format এবং API বজায় রাখে, এবং provider rate-limit queue-এর আচরণ অপরিবর্তিত থাকে।
