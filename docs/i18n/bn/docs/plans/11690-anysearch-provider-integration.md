## 1. সার্ভিসের প্রকৃত তথ্য (অফিশিয়াল ডকুমেন্টেশন, ক্রস-চেক করা)

- বেস URL: `https://api.anysearch.com` (REST) + `POST /mcp` (MCP, JSON-RPC 2.0)।
- `POST /v1/search` - প্যারামিটার: `query` (আবশ্যক), `max_results` (1-10, ডিফল্ট 10), `tag` (`{domain}.{sub_domain}` ভার্টিক্যাল রাউটিং), `zone` (cn/intl), `language`, `params` (স্ট্রাকচার্ড ভার্টিক্যাল ফিল্ড), `format` (json/markdown)।
- `GET /v1/sub-domains?domain=...` - সক্ষমতার ক্যাটালগ, কোটা ব্যবহারের হিসাবে গণনা করা হয় না।
- `POST /v1/extract` - `{url, title, content}` ফেচ/এক্সট্র্যাক্ট করে; কঠোর JSON বডি, 16 KiB সীমা।
- `POST /v1/auth/email/register` - একক-কল রেজিস্ট্রেশন, একবার ব্যবহারযোগ্য প্লেইনটেক্সট কী `as_sk_...` ফেরত দেয়।
- অথেনটিকেশন: ঐচ্ছিক `Authorization: Bearer <as_sk_...>`; অ্যানোনিমাস ব্যবহার প্রতি-IP সীমায় অবনমিত হয় এবং দৈনিক ফ্রি কোটা ব্যবহার করে; অবৈধ কী কোনো নীরব অ্যানোনিমাস ফলব্যাক ছাড়াই 401/403 ফেরত দেয়।
- ফ্রি টিয়ার: প্রতিদিন 1000টি রিকোয়েস্ট, প্রতি কী-তে 20 QPS। পেইড টিয়ার: মূল্য অনির্ধারিত (শীঘ্রই আসছে)।
- রেসপন্স এনভেলপ: সফল হলে `{code: 0, message: "success", request_id, data}`; ব্যর্থ হলে `{code: -1, message}`। অথেনটিকেশন/কোটা ত্রুটিতে কোনো স্ট্রাকচার্ড `error_code` থাকে না (মেসেজের টেক্সটই সংকেত); এক্সট্র্যাক্ট-নির্দিষ্ট ত্রুটিতে `error_code` থাকে (`invalid_extract_url`, `extract_failed`)। 429-এর ক্ষেত্রে কোনো `Retry-After` হেডার নেই।

## ৩. সিদ্ধান্তসমূহ (সবগুলো 2026-08-26 তারিখে গৃহীত)

1. **রাউটিং অবস্থান: `fallbackOnly`।** যুক্তি: খরচ-0-এর কোনো বিনামূল্যের প্রোভাইডার কখনোই স্বয়ংক্রিয় খরচভিত্তিক রাউটিংয়ে প্রাধান্য পাবে না; স্পষ্ট নির্বাচন ও ফেইলওভার থেকে প্রত্যাবর্তন অপরিবর্তিত থাকবে। নজির: মার্জ করা xquik এন্ট্রি।
2. **পরিধি: v1-এ `POST /v1/extract`-এর মাধ্যমে webSearch + webFetch।** tavily/exa-এর দ্বৈত-সক্ষমতার মানসিক মডেলের সঙ্গে সামঞ্জস্যপূর্ণ। উল্লম্ব ক্ষেত্রগুলো (`tag`, `sub-domains`, `batch_search`) পরিধির বাইরে থাকবে—বর্তমানে উল্লম্ব প্যারামিটারের জন্য কোনো IR নেই।
3. **কোটা প্রদর্শন: `freeMonthlyQuota: 0`** (xquik-ধাঁচের রক্ষণশীল প্রদর্শন)। প্রকৃত বরাদ্দটি (প্রতিদিন 1000টি অনুরোধ, দৈনিক রিসেট) পরিবর্তে UI ক্যাটালগের `authHint` লেখায় উল্লেখ করা হবে। যুক্তি: কোটা প্রদর্শন অবশ্যই রিসেটের অর্থবোধের সঙ্গে সামঞ্জস্যপূর্ণ হতে হবে; দৈনিক সীমাকে মাসিক-সমতুল্য মানে (30000) রূপান্তর করা একটি মিথ্যা প্রতিশ্রুতি, যা UI পূরণ করতে পারে না।
4. **searchTypes: শুধু `["web"]`।** AnySearch API-তে news/images উল্লম্ব ক্ষেত্রের কোনো প্রকাশ্য প্রমাণ নেই; নথিভুক্ত উল্লম্ব ক্ষেত্র ছাড়া API ইন্টিগ্রেট করা গেটওয়েগুলো (যেমন Google Custom Search) নীরবে news -> web ম্যাপ করার পরিবর্তে শুধু web প্রকাশ করে।
5. **কী-সংক্রান্ত অবস্থান:** কী ছাড়াই কাজ করে; একটি অবৈধ কী 401/403 ফেরত দেয় এবং কখনোই নীরবে অ্যানোনিমাস মোডে নামিয়ে দেওয়া হয় না (আপস্ট্রিম চুক্তির অনুরূপ)।
6. **ইচ্ছাকৃতভাবে বাদ দেওয়া বিষয়সমূহ:** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (চ্যাট ইন্টারসেপশন firecrawl/jina/tavily-তেই থাকবে); `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (অ্যানোনিমাস রিমোট এন্ডপয়েন্টগুলো প্রতিটি ইগ্রেস IP-এর জন্য একটি IP-সীমিত পুল ভাগ করে, তাই কী-বিহীন extract অপ্ট-ইন, স্বয়ংক্রিয় রাউটিংয়ের প্রার্থী নয়); `QUOTA_STATUS_PROVIDERS` (AnySearch 402/403 স্ট্যাটাসের বদলে 429/এনভেলপের মাধ্যমে কোটা সংকেত দেয়)।
