`chatgpt-web-codex` (alias `cgpt-codex`) একটি প্রমাণীকৃত ChatGPT ব্রাউজার সেশনের মাধ্যমে Codex Responses টার্নগুলোর মধ্যে সেতুবন্ধন করে। এটি অবসরপ্রাপ্ত সাধারণ `chatgpt-web` প্রোভাইডার থেকে স্বতন্ত্র এবং `open-sse/vendor/codex-chatgpt-web/`-এর অধীনে থাকা MIT-নোটিশযুক্ত ইমপ্লিমেন্টেশন ব্যবহার করে, যা upstream v4.0.7 commit `b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494` পর্যন্ত হালনাগাদ করা হয়েছে।

## সাধারণ প্রোভাইডারের অবসর

পূর্ববর্তী সাধারণ প্রোভাইডার ID `chatgpt-web` এবং `cgpt-web` আর সরবরাহ করা হয় না, কারণ তাদের pre-key/proof-of-work ইমপ্লিমেন্টেশনের উৎসের স্বচ্ছতা নিশ্চিত করা যায়নি। slash-prefixed model ID এবং সংরক্ষিত alias-সহ যেকোনো একটি ID-এর জন্য স্পষ্ট অনুরোধ, কোনো upstream অনুরোধ পাঠানোর আগেই HTTP `410` এবং **PROVIDER_RETIRED** code সহ বন্ধ অবস্থায় ব্যর্থ হয়।

Migration `168_retire_chatgpt_web.sql` মিলে যাওয়া প্রোভাইডার সংযোগগুলোকে tombstone করে এবং তাদের সক্রিয় session lease অবৈধ করে। এটি সংযোগের ইতিহাস এবং API-key allowlist সংরক্ষণ করে; এটি কোনো allowlist-এ বিকল্প অ্যাক্সেস যোগ করে না। Codex প্রোভাইডার এবং এর সংযোগগুলো এই অবসর প্রক্রিয়ার আওতায় পড়ে না।

## পূর্বশর্ত

- সাইন-ইন করা ChatGPT সেশন থেকে একটি সম্পূর্ণ Cookie header;
- npm, systemd এবং PM2 ইনস্টলের জন্য Chrome বা Chromium-এর পাশাপাশি একটি graphical session বা Xvfb display;
- Docker `web` profile ব্যবহার করলে, `docker-compose.yml`-এর অভ্যন্তরীণ Chromium service;
- স্থানীয় Codex tool-এর জন্য OpenAI `tunnel-client` v0.0.13 এবং একটি ChatGPT custom connector।

tunnel শুধু tool turn-এর জন্য প্রয়োজন। tunnel এবং connector কনফিগার করা থাকলে `pro`-সহ তালিকাভুক্ত প্রতিটি route একই turn-bound স্থানীয় tool capability ব্যবহার করতে পারে।

## Dashboard সেটআপ

1. **ChatGPT Web (Codex)** প্রোভাইডার খুলুন এবং একটি সংযোগ যোগ করুন।
2. সম্পূর্ণ ChatGPT Cookie header, tunnel ID, runtime key এবং custom connector-এর নাম পেস্ট করুন। নতুন tool-capable সেটআপে অবশ্যই সদ্য তৈরি এমন একটি connector ব্যবহার করতে হবে, যার নাম ঠিক `OmniRoute Codex v2`, Authentication-এর মান None এবং Permissions-এর মান Allow all actions হিসেবে সেট করা আছে।
3. সংযোগ পরীক্ষা চালান। OmniRoute একটি browser-backed Temporary Chat খোলে এবং অ্যাকাউন্টটির জন্য Sol ও Pro উপলভ্য কি না শনাক্ত করে।
4. সংযোগটি সংরক্ষণ করুন। OmniRoute পেস্ট করা cookie-টি যাচাইকৃত Playwright storage state দিয়ে প্রতিস্থাপন করে এবং encrypted credential abstraction-এর মাধ্যমে runtime key-এর সঙ্গে সেটি সংরক্ষণ করে।

সফলভাবে সংরক্ষণের পর raw cookie রাখা হয় না। সেশনের মেয়াদ শেষ হলে সংযোগটি খুলুন, একটি নতুন সম্পূর্ণ Cookie header পেস্ট করুন এবং পুনরায় পরীক্ষা চালান। edit dialog-এর doctor status browser, storage state, sign-in, Temporary Chat, tunnel, connector এবং tool round-trip-এর অবস্থা আলাদাভাবে জানায়।

> কোনো আসল cookie, runtime key, storage state বা capability token কখনো commit করবেন না। পরীক্ষা ও
> ডকুমেন্টেশনের মানগুলো অবশ্যই সবসময় placeholder হতে হবে।

## Model এবং combo

নির্দিষ্ট model route-গুলো হলো:

- `chatgpt-web-codex/luna` — GPT-5.6 Luna, কম effort
- `chatgpt-web-codex/think` — GPT-5.6 Luna, মাঝারি effort
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

অন্য যেকোনো model-এর মতো এগুলোর যেকোনো একটিকে একটি combo-তে যোগ করুন। Codex app নিয়মিত Responses endpoint, `/v1/responses`-এ combo-টির নাম `model` হিসেবে পাঠায়; আলাদা কোনো Codex endpoint বা mode switch নেই।

Free/Go অ্যাকাউন্টগুলো Luna route প্রকাশ করে। Sol-capable অ্যাকাউন্টগুলো Instant থেকে High পর্যন্ত প্রকাশ করে এবং Pro-capable অ্যাকাউন্টগুলো অতিরিক্তভাবে Extra High ও Pro প্রকাশ করে। প্রতিটি route-এর একটি নির্দিষ্ট backend model এবং reasoning effort রয়েছে; পরস্পরবিরোধী কোনো স্পষ্ট Responses effort নীরবে নির্বাচিত browser mode পরিবর্তন করার বদলে বন্ধ অবস্থায় ব্যর্থ হয়।

পুরোনো কোনো `Codex Native` বা `OmniRoute Codex` connector-এর নাম পরিবর্তন বা সেটি পুনরায় ব্যবহার করবেন না। ChatGPT connector identity অনুযায়ী public MCP contract cache করে, অথচ হালনাগাদ bridge একটি নতুন direct turn-token contract ব্যবহার করে। runtime ওই legacy identity-গুলো প্রত্যাখ্যান করে এবং একটি নতুন `OmniRoute Codex v2` connector আবশ্যক করে।

## নিরাপত্তা মডেল

- নেটিভ পাথের জন্য একটি Responses অনুরোধ, একটি স্বীকৃত Codex ক্লায়েন্ট এবং মিলযুক্ত
  থ্রেড ও টার্ন পরিচয় প্রয়োজন।
- ওয়ার্কস্পেস, স্যান্ডবক্স, অনুমোদন নীতি এবং টুল ক্যাটালগ নেটিভ Codex শেল থেকে আসে;
  অবাধ প্রম্পট টেক্সট এগুলোর জন্য কর্তৃত্বপূর্ণ নয়।
- ChatGPT প্রতি টার্নে শুধু একটি স্বল্পমেয়াদি সক্ষমতা পায়। MCP ব্রোকার শুধু সেই
  নির্দিষ্ট টার্নে Codex-এর দেওয়া টুলগুলোই গ্রহণ করে।
- **Allow once** স্বয়ংক্রিয়ভাবে নিশ্চিত করলে শুধু টুল অনুরোধটি Codex-এ ফেরত যায়। অনুমোদন
  ও কার্যকরকরণের সিদ্ধান্ত শুধু Codex-ই নেয়।
- প্রথম আউটপুটের আগে, একটি কম্বো অন্য কোনো সামঞ্জস্যপূর্ণ টার্গেটে ফিরে যেতে পারে। আউটপুট
  শুরু হওয়ার পর, টার্নটি সম্পূর্ণ না হওয়া পর্যন্ত প্রোভাইডার, মডেল, সংযোগ এবং ব্রাউজার টার্ন পিন করা থাকে।
- কুকি, রানটাইম কী, স্টোরেজ স্টেট এবং সক্ষমতা টোকেন প্রোভাইডারের
  প্রতিক্রিয়া বা অনুরোধ লগে দেখা যায় না।

## ডিসপ্লেবিহীন VPS এবং Docker

npm, systemd এবং PM2 ইনস্টলের ক্ষেত্রে OmniRoute সাধারণ Chrome ও Chromium পাথ শনাক্ত করে।
বিকল্পভাবে, `CHATGPT_WEB_CODEX_CHROME_PATH` সেট করুন। রানটাইম টার্নগুলো ইচ্ছাকৃতভাবে হেডেড
Chrome ব্যবহার করে, কারণ ChatGPT প্রকৃত-হেডলেস ব্রাউজার বিন্যাস প্রত্যাখ্যান করে। তাই একটি ডিসপ্লেবিহীন হোস্টকে
একটি ব্যক্তিগত Xvfb ডিসপ্লে দিয়ে OmniRoute চালাতে হবে; শুধু Chrome পাথ সেট করলে ডিসপ্লে পাওয়া যায় না।

Docker-এর `web` প্রোফাইল অভ্যন্তরীণ Compose নেটওয়ার্কে
`chatgpt-web-codex-browser` চালু করে। সাইডকারটি Xvfb-এর ভেতরে হেডেড Chrome চালায়, তাই কোনো ফিজিক্যাল ডিসপ্লের প্রয়োজন হয় না। এর CDP
পোর্ট হোস্টে প্রকাশ করা হয় না। সুরক্ষিত ব্রাউজার প্রোফাইল ভলিউমটি
OmniRoute ডেটা ভলিউম থেকে পৃথক এবং ব্রাউজারটি পর্যাপ্ত শেয়ার্ড মেমরি পায়। অভ্যন্তরীণ CDP প্রক্সি
শুধু Compose নেটওয়ার্কের ভেতরে `9223` পোর্টে শোনে; সাইডকারে Chrome লুপব্যাকে আবদ্ধ থাকে।

`DATA_DIR`-এর অধীনে একটি সুপারভাইজার লিজ একাধিক OmniRoute প্রসেসকে একই
টানেল ও ব্রোকার স্টেটের মালিক হওয়া থেকে বিরত রাখে। কোনো দ্বন্দ্ব থাকলে তা doctor দ্বারা জানানো হয়।

## ইন্টার্যাক্টিভ পুনরুদ্ধার

স্বয়ংক্রিয় Docker পাথে হোস্টে দৃশ্যমান কোনো উইন্ডো নেই, তবে ব্যক্তিগত Xvfb
ডিসপ্লের ভেতরে Chrome নিজেই হেডেড অবস্থায় থাকে। ChatGPT-এর ইন্টার্যাক্টিভ সাইন-ইন বা চ্যালেঞ্জের প্রয়োজন হলে, বিদ্যমান VNC
ব্রাউজার অবকাঠামো পুনরুদ্ধারের জন্য ব্যবহার করা যায়। ব্রাউজার UI এবং CDP-কে অবশ্যই শুধু
লুপব্যাক, একটি প্রমাণীকৃত ব্যবস্থাপনা সংযোগ অথবা একটি SSH টানেলের মাধ্যমে অ্যাক্সেসযোগ্য রাখতে হবে; স্বাভাবিক কার্যক্রমের
সময় noVNC নিষ্ক্রিয় থাকে।

## WebSocket ফলব্যাক

যখন কোনো কম্বোতে ChatGPT Web (Codex) থাকে, তখন Responses WebSocket ব্রিজটি
আপস্ট্রিমে সংযোগ করার আগে HTTP/SSE ফলব্যাকের অনুরোধ করে। এরপর স্থানান্তরটি
`/v1/responses`-এর মাধ্যমে সম্পন্ন হয়।
