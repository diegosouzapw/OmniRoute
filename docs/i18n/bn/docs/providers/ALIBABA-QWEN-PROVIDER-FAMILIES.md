এই নথিতে
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854)-এর বাস্তবায়নসংক্রান্ত সিদ্ধান্ত লিপিবদ্ধ করা হয়েছে। সর্বজনীন পণ্যগুলোকে
চারটি প্রোভাইডার পরিবার হিসেবে উপস্থাপন করা হয়েছে। অঞ্চল হলো সংযোগের ডেটা, আলাদা কোনো পণ্য নয়।

## সিদ্ধান্ত

| প্রোভাইডার পরিবার                                          | OmniRoute ID            | বৈশ্বিক অঞ্চল | চীন অঞ্চল |
| ---------------------------------------------------------- | ----------------------- | ------------- | --------- |
| Alibaba Cloud Model Studio (ব্যবহার অনুযায়ী মূল্য পরিশোধ) | `alibaba`               | সিঙ্গাপুর     | বেইজিং    |
| Alibaba Cloud Token Plan                                   | `bailian-coding-plan`   | সিঙ্গাপুর     | বেইজিং    |
| Qwen Cloud (ব্যবহার অনুযায়ী মূল্য পরিশোধ)                 | `qwen-cloud`            | বৈশ্বিক       | বেইজিং    |
| Qwen Cloud Token Plan                                      | `qwen-cloud-token-plan` | সিঙ্গাপুর     | বেইজিং    |

বিদ্যমান `alibaba-cn` ID সংরক্ষিত সংযোগ, মডেল
রুট, কম্বো এবং ঐতিহাসিক ব্যবহারের জন্য রানটাইম সামঞ্জস্যের উপনাম হিসেবে বহাল থাকবে। এর ড্যাশবোর্ড কার্ডটি `alibaba`-এর মধ্যে একীভূত করা হয়েছে; কোনো ডেটাবেস
পুনর্লিখনের প্রয়োজন নেই।

Qwen Cloud-এর ব্যবহার অনুযায়ী মূল্য পরিশোধের পণ্য এবং Alibaba Cloud Model Studio বর্তমানে DashScope-সামঞ্জস্যপূর্ণ
রানটাইম হোস্টগুলো ভাগাভাগি করে, তবে এগুলো আলাদা প্রোভাইডার পরিচয় হিসেবেই থাকবে, কারণ ব্যবহারকারীরা ভিন্ন ভিন্ন পণ্য ইন্টারফেসের মাধ্যমে কী সংগ্রহ ও
অ্যাকাউন্ট পরিচালনা করেন। Alibaba এবং Qwen Cloud Token Plan পণ্যগুলো
ভিন্ন এন্ডপয়েন্ট পরিবার ব্যবহার করে, তাই চারটি পণ্যই আলাদা প্রোভাইডার ID হিসেবে থাকবে।

API কী এবং এন্ডপয়েন্ট অবশ্যই একই পণ্য ও অঞ্চলের হতে হবে। কোনো অঞ্চল নির্বাচন করলে
যাচাইকরণ এবং স্বাভাবিক অনুরোধের জন্য ব্যবহৃত পূর্বনির্ধারিত এন্ডপয়েন্ট পরিবর্তিত হয়।

## সংযোগ চুক্তি

নতুন সংযোগগুলো `providerSpecificData`-তে স্থিতিশীল অঞ্চল কী সংরক্ষণ করে:

```json
{
  "region": "global-sg"
}
```

অনুমোদিত মান হলো `global-sg` এবং `china-beijing`। প্রোভাইডার ID এবং অঞ্চলের ভিত্তিতে কেন্দ্রীয়ভাবে এন্ডপয়েন্ট
নির্ধারিত হয়। পূর্বনির্ধারিত নয় এমন `providerSpecificData.baseUrl` একটি সুস্পষ্ট অপারেটর
ওভাররাইড হিসেবে বহাল থাকে এবং অগ্রাধিকার পায়, অন্যদিকে পুরোনো সংরক্ষিত পূর্বনির্ধারিত URL-গুলোকে আবার আঞ্চলিক
ম্যাট্রিক্স অনুযায়ী স্বাভাবিকীকরণ করা হয়।

এটি সংযোগ স্কিমাকে সম্প্রসারণযোগ্য রাখে: আরেকটি প্রোভাইডার কার্ড তৈরি বা সংরক্ষিত প্রোভাইডার ID পরিবর্তন না করেই
রিজলভারে আরেকটি অঞ্চল যোগ করা যায়।

## সামঞ্জস্যতা এবং রোলআউট

1. আঞ্চলিক endpoint resolver যোগ করুন এবং বর্তমান global default-গুলো বজায় রাখুন।
2. `alibaba`, এর `alibaba-cn` compatibility ID এবং `qwen-cloud`-এর জন্য live আঞ্চলিক DashScope `/models` discovery ব্যবহার করুন। তাদের response প্রথমে একটি text-generation filter-এর মধ্য দিয়ে যায়, কারণ generic endpoint-টি image, video, audio, embedding এবং অন্যান্য non-chat model-ও ফেরত দেয়। এরপর `qwen-cloud` তার provider registry-তে ঘোষিত ও রক্ষণাবেক্ষণকৃত allowlist প্রয়োগ করে। বর্তমানে একই runtime host ব্যবহার করলেও Alibaba Model Studio এবং Qwen Cloud আলাদা curated catalog বজায় রাখে।
3. বর্তমান Token Plan text-model allowlist-সহ `qwen-cloud-token-plan` register করুন।
4. connection যোগ/সম্পাদনার dialog-গুলোতে typed region selector যোগ করুন।
5. সদৃশ `alibaba-cn` card-টি লুকিয়ে রাখুন এবং এর বিদ্যমান connection-গুলো `alibaba` provider page-এ অন্তর্ভুক্ত করুন।
6. উন্নত এবং workspace-নির্দিষ্ট deployment-এর জন্য custom endpoint override উপলভ্য রাখুন।

Token Plan media model-গুলো chat catalog-এর বাইরে থাকবে, কারণ এগুলো dedicated endpoint ব্যবহার করে।
`wan2.7-image` এবং `wan2.7-image-pro` `open-sse/config/imageRegistry.ts`-এ register করা আছে;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, এবং `happyhorse-1.1-r2v`
`open-sse/config/videoRegistry.ts`-এ register করা আছে। উভয় registry-ই
`qwen-cloud-token-plan` connection identity এবং এর region-specific credential পুনরায় ব্যবহার করে।

নিয়মিত Qwen Cloud-এর `qwen-cloud` identity-এর অধীনে আলাদা pay-as-you-go image এবং video catalog রয়েছে। এর image model-গুলো হলো `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03`, এবং `z-image-turbo`। এর video
model-গুলো হলো `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12`, এবং
`wan2.7-videoedit`। এই model-গুলো শুধুমাত্র নিয়মিত `qwen-cloud` connection এবং আঞ্চলিক
DashScope media endpoint পুনরায় ব্যবহার করে। Token Plan এবং pay-as-you-go registry-গুলো পরস্পরের model list inherit বা merge করে না।

`bailian-coding-plan` identity-এরও নিজস্ব media allowlist রয়েছে:
image generation-এর জন্য `wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0`, এবং `qwen-image-2.0-pro`,
এবং video generation-এর জন্য
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, ও `happyhorse-1.1-r2v`।
এটি শুধুমাত্র Bailian Coding Plan connection এবং আঞ্চলিক Coding Plan endpoint ব্যবহার করে।
এর image ও video registry-গুলো Qwen Cloud provider-এর কোনোটি থেকেই inherit করে না বা সেগুলোর সঙ্গে merge হয় না।

নিয়মিত `alibaba` identity-এর আলাদা image এবং video allowlist রয়েছে। এর image model-গুলো হলো
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo`, এবং `wan2.6-t2i`। এতে যোগ করা video model-গুলো হলো `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12`, এবং `wan2.7-videoedit`। এই model-গুলো শুধুমাত্র Alibaba Model Studio
connection এবং এর নির্বাচিত আঞ্চলিক media endpoint ব্যবহার করে; এগুলো কোনো Coding Plan বা Qwen
Cloud registry-তে যোগ করা হয় না।

Qwen Cloud Token Plan chat catalog Individual plan-এর exact-string text allowlist অনুসরণ করে:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2`, এবং
`deepseek-v4-pro`। Wan এবং HappyHorse entry-গুলো আলাদা image/video generation API-এর অন্তর্গত।

Alibaba Token Plan তার Anthropic-compatible endpoint-এর মাধ্যমে একই ছয়টি বর্তমান text-generation model ID প্রকাশ করে। এর Singapore option-এ বিদ্যমান `global-sg` region key সংরক্ষিত হয়;
শুধু user-facing label-টি সেই provider family-গুলো থেকে আলাদা, যেগুলো region-টিকে Global বলে।

নিয়মিত Qwen Cloud chat catalog ইচ্ছাকৃতভাবে সম্পূর্ণ live text response-এর তুলনায় সীমিত। এর
রক্ষণাবেক্ষণকৃত allowlist `open-sse/config/providers/registry/qwen-cloud/index.ts`-এ রয়েছে; live
discovery কেবল সেই ID-গুলোই ফেরত দেয়, যেগুলো upstream response এবং ওই registry list—উভয় স্থানেই উপস্থিত।

Alibaba Model Studio একই live-intersection নিয়ম অনুসরণ করে, যার স্বতন্ত্রভাবে রক্ষণাবেক্ষণকৃত
allowlist `open-sse/config/providers/registry/alibaba/index.ts`-এ রয়েছে। `alibaba-cn` compatibility
provider ওই catalog পুনরায় ব্যবহার করে, তবে discovery-র জন্য Beijing endpoint resolve করে।
