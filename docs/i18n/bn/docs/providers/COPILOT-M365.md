`copilot-m365-web` (ওরফে `m365copilot`) `m365.cloud.microsoft/chat`-এ একটি প্রমাণীকৃত Microsoft 365 Copilot BizChat ব্রাউজার সেশনের মাধ্যমে OpenAI-ফরম্যাটের চ্যাট অনুরোধ পাঠায়। এটি একটি অনানুষ্ঠানিক ইন্টিগ্রেশন।

> **Web Cookie প্রোভাইডারে নতুন?**
>
> এই প্রোভাইডার-নির্দিষ্ট নির্দেশিকা অনুসরণের আগে সাধারণ সেটআপ প্রক্রিয়া, প্রমাণীকরণ নির্দেশনা, সীমাবদ্ধতা এবং সমস্যা সমাধান সম্পর্কে জানতে **`docs/getting-started/WEB-COOKIE-GUIDE.md`** পড়ুন।
>
> **গুরুত্বপূর্ণ:** এই প্রোভাইডারের ক্রেডেনশিয়ালটি **কুকি নয়**। `m365.cloud.microsoft` থেকে কুকি কপি করবেন না। ক্রেডেনশিয়ালটি হলো একটি WebSocket URL-এর কোয়েরি প্যারামিটার এবং পাথ সেগমেন্ট, যেগুলো উভয়ই DevTools-এর Network ট্যাব থেকে নেওয়া হয়।

## পূর্বশর্ত

- `m365.cloud.microsoft/chat`-এ BizChat অ্যাক্সেসসহ একটি Microsoft 365 অ্যাকাউন্ট
- DevTools-এ WebSocket পরিদর্শনের জন্য একটি Chromium-ভিত্তিক ব্রাউজার (Chrome, Edge)
- একটি M365 Copilot লাইসেন্স (অনেক Microsoft 365 Business/Enterprise প্ল্যানে অন্তর্ভুক্ত)

## ক্রেডেনশিয়াল সংগ্রহ (WebSocket পদ্ধতি)

1. `https://m365.cloud.microsoft/chat`-এ সাইন ইন করে একটি কথোপকথন শুরু করুন।
2. **DevTools → Network** খুলুন।
3. **WS** (WebSocket) দিয়ে ফিল্টার করুন।
4. Chathub WebSocket সংযোগে ক্লিক করুন। `wss://substrate.office.com/m365Copilot/Chathub/` দিয়ে শুরু হওয়া একটি URL খুঁজুন।
5. এর **Request URL** থেকে কপি করুন:
   - `access_token` কোয়েরি প্যারামিটারের মান (একটি স্বল্পমেয়াদি JWT)।
   - `/Chathub/`-এর পরের Chathub পাথ সেগমেন্ট (যেমন `<oid>@<tenant>`)।

সম্পূর্ণ URL-এর বিন্যাস হলো:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute-এ **Providers → Add Provider**-এ যান, **Microsoft 365 Copilot
   (BizChat)** নির্বাচন করুন এবং নিচের বিন্যাসে ক্রেডেনশিয়ালটি পেস্ট করুন:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. **Test Connection** এবং **Save**-এ ক্লিক করুন।

## ক্রেডেনশিয়াল সংগ্রহ (HAR ইম্পোর্ট)

WebSocket URL থেকে মানগুলো ম্যানুয়ালি কপি করার পরিবর্তে আপনি একটি DevTools HAR ফাইল এক্সপোর্ট করতে পারেন:

1. **DevTools → Network** খুলুন।
2. একটি BizChat কথোপকথন শুরু করুন বা চালিয়ে যান (এটি WebSocket সংযোগটি ট্রিগার করে)।
3. Network প্যানেলে রাইট-ক্লিক করে **Save all as HAR with content** নির্বাচন করুন।
4. OmniRoute-এ প্রোভাইডার সংযোগ ডায়ালগের **Import .har file** বোতামটি ব্যবহার করুন।

OmniRoute, Chathub WebSocket URL-এর জন্য HAR স্ক্যান করে, `access_token` এবং `chathubPath` বের করে এবং স্বয়ংক্রিয়ভাবে ক্রেডেনশিয়াল ফিল্ডগুলো পূরণ করে। HAR ইম্পোর্ট JWT-এর মেয়াদ শেষ হওয়ার সময় ডিকোড করে এবং টোকেনের অবশিষ্ট মেয়াদ দেখায়।

> **কখনোই প্রকৃত HAR এক্সপোর্ট, অ্যাক্সেস টোকেন বা রিফ্রেশ টোকেন কমিট করবেন না।** পরীক্ষা ও ডকুমেন্টেশনের মানগুলো অবশ্যই সবসময় প্লেসহোল্ডার হতে হবে।

## টোকেনের মেয়াদ ও রিফ্রেশ

`access_token` স্বল্পমেয়াদি (সাধারণত **~75 মিনিট**)। মেয়াদ শেষ হওয়ার পরে প্রোভাইডার একটি সংযোগ ত্রুটি জানায় এবং আপনাকে ক্রেডেনশিয়ালটি আবার সংগ্রহ করতে হবে।

### `refreshToken` দিয়ে স্বয়ংক্রিয় রিফ্রেশ

ম্যানুয়ালি পুনরায় সংগ্রহ এড়াতে আপনি সংযোগের **Advanced Settings → providerSpecificData**-এ একটি Microsoft রিফ্রেশ টোকেন সংরক্ষণ করতে পারেন:

| ফিল্ড          | বিবরণ                                                                    |
| -------------- | ------------------------------------------------------------------------ |
| `refreshToken` | `substrate.office.com/sydney` স্কোপের জন্য Microsoft OAuth রিফ্রেশ টোকেন |
| `tier`         | `individual` (ডিফল্ট), `edu`, অথবা `enterprise`                          |

`substrate.office.com/sydney`-এ স্কোপ করা Microsoft device-code বা authorization-code ফ্লো থেকে রিফ্রেশ টোকেনটি সংগ্রহ করুন। `refreshToken` সেট করা থাকলে OmniRoute প্রতিটি অনুরোধের আগে `access_token` প্রি-ফ্লাইট-রিফ্রেশ করে, ফলে প্রতি ~75 মিনিটে মেয়াদ শেষ হওয়ার পর আপনাকে আবার সংগ্রহ করতে হয় না।

`refreshToken` সেট করা না থাকলে প্রতিবার মেয়াদ শেষ হওয়ার পর আপনাকে WebSocket ক্রেডেনশিয়ালটি ম্যানুয়ালি আবার সংগ্রহ করতে হবে।

### টিয়ার নির্বাচন

| টিয়ার       | ওরফে       | সারফেস                  |
| ------------ | ---------- | ----------------------- |
| `individual` | _(ডিফল্ট)_ | গ্রাহক M365 Copilot     |
| `edu`        | `included` | শিক্ষা M365 Copilot     |
| `enterprise` | `work`     | কাজের জন্য M365 Copilot |

**Advanced Settings → providerSpecificData → tier**-এ টিয়ার সেট করুন। টিয়ারটি BizChat রাউটিং এবং মডেল অ্যাক্সেসকে প্রভাবিত করে।

## নিরাপত্তা মডেল

- **অনানুষ্ঠানিক ইন্টিগ্রেশন।** এই প্রোভাইডারটি BizChat WebSocket
  প্রোটোকল রিভার্স-ইঞ্জিনিয়ার করে। Microsoft এন্ডপয়েন্ট পরিবর্তন করলে এটি কোনো পূর্বঘোষণা ছাড়াই অকার্যকর হতে পারে।
- `subscriptionRisk: true` ফ্ল্যাগটি নির্দেশ করে যে ইন্টিগ্রেশনটি একটি
  অনথিভুক্ত এন্ডপয়েন্টের ওপর নির্ভরশীল। অ্যাকাউন্টে বিধিনিষেধ আরোপিত হতে পারে, তবে তা নিশ্চিত নয়।
- অ্যাক্সেস টোকেনটি স্বল্পমেয়াদি JWT। এটিকে পাসওয়ার্ডের মতো বিবেচনা করুন: এটি কমিট,
  লগ বা শেয়ার করবেন না।
- রিফ্রেশ টোকেনটি BizChat সারফেসে দীর্ঘমেয়াদি অ্যাক্সেস প্রদান করে। এটিকে
  API কী-এর মতো একই সতর্কতার সঙ্গে সংরক্ষণ করুন।

## সমস্যা সমাধান

### প্রমাণীকরণ সঙ্গে সঙ্গেই ব্যর্থ হয়

- নিশ্চিত করুন যে আপনি **WebSocket URL** থেকে কপি করেছেন, কোনো XHR/Fetch অনুরোধ থেকে নয়। Chathub WebSocket
  সংযোগের `access_token` কোয়েরি প্যারামিটারে ক্রেডেনশিয়ালটি থাকে—
  কোনো `Authorization: Bearer` হেডারে নয়।
- নিশ্চিত করুন যে `chathubPath`-এ URL
  পাথের সম্পূর্ণ `<oid>@<tenant>` সেগমেন্টটি অন্তর্ভুক্ত রয়েছে।

### প্রায় ৭৫ মিনিট পর টোকেনের মেয়াদ শেষ হয়ে যায়

এটি প্রত্যাশিত আচরণ। `refreshToken` ছাড়া অ্যাক্সেস টোকেনটি স্বল্পমেয়াদি। নিচের যেকোনো একটি করুন:

- DevTools থেকে ক্রেডেনশিয়ালটি পুনরায় সংগ্রহ করুন, অথবা
- স্বয়ংক্রিয়ভাবে রিফ্রেশ করার জন্য Advanced Settings-এ একটি `refreshToken` কনফিগার করুন।

### Test Connection সফল হয়, কিন্তু চ্যাট 401 প্রদান করে

যাচাইকরণ এবং প্রথম অনুরোধের মধ্যবর্তী সময়ে টোকেনটির মেয়াদ শেষ হয়ে থাকতে পারে। একটি
নতুন ক্রেডেনশিয়াল পুনরায় সংগ্রহ করুন।

### প্রোভাইডার তালিকায় Copilot দেখা যায় না

**Dashboard → Providers**-এ `copilot-m365-web` সক্রিয় আছে কি না নিশ্চিত করুন। কিছু
টিয়ারে প্রোভাইডারটি ডিফল্টভাবে লুকানো থাকতে পারে।
