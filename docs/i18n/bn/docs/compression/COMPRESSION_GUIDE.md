## সংক্ষিপ্ত বিবরণ

OmniRoute একটি মডুলার প্রম্পট কম্প্রেশন পাইপলাইন বাস্তবায়ন করে, যা অনুরোধগুলো আপস্ট্রিম প্রোভাইডারের কাছে পৌঁছানোর **আগেই সক্রিয়ভাবে** চলে। অর্থাৎ, আপনার টোকেন সাশ্রয় স্বচ্ছভাবে ঘটে — আপনার কর্মপ্রবাহে কোনো পরিবর্তনের প্রয়োজন নেই।

```
ক্লায়েন্ট অনুরোধ
  → কম্প্রেশন কৌশল নির্বাচক
    → কম্বো ওভাররাইড? → কম্বো সেটিং ব্যবহার করুন
    → স্বয়ংক্রিয়-ট্রিগার থ্রেশহোল্ড? → স্বয়ংক্রিয় মোড ব্যবহার করুন
    → ডিফল্ট মোড? → গ্লোবাল সেটিং ব্যবহার করুন
    → বন্ধ? → কম্প্রেশন এড়িয়ে যান
  → নির্বাচিত কম্প্রেশন মোড
    → বন্ধ: কোনো কম্প্রেশন নয়
    → লাইট: নিরাপদ হোয়াইটস্পেস/ফরম্যাটিং পরিষ্কারকরণ (~15%)
    → স্ট্যান্ডার্ড: কেভম্যান-ধাঁচের অপ্রয়োজনীয় শব্দ অপসারণ (~30%)
    → অ্যাগ্রেসিভ: ইতিহাসের বয়সভিত্তিক সংকোচন + সারসংক্ষেপ (~50%)
    → আল্ট্রা: হিউরিস্টিক ছাঁটাই + কোড-ব্লক সংকোচন (~75%)
    → RTK: কমান্ড-সচেতন টার্মিনাল/টুল-আউটপুট ফিল্টারিং (আপস্ট্রিমে 60-90% পরিসর)
    → স্ট্যাকড: ক্রমানুসারী মাল্টি-ইঞ্জিন পাইপলাইন, সাধারণত প্রথমে RTK তারপর Caveman (উপযুক্ত ক্ষেত্রে 78-95% পরিসর)
  → সংকুচিত অনুরোধ → প্রোভাইডার
```

## কম্প্রেশন মোডসমূহ

### বন্ধ

কোনো কম্প্রেশন প্রয়োগ করা হয় না। সব বার্তা অপরিবর্তিত অবস্থায় পাঠানো হয়।

### লাইট মোড (~15% সাশ্রয়, <1ms লেটেন্সি)

সবচেয়ে নিরাপদ মোড — অর্থগত কোনো পরিবর্তন নেই, শুধু ফরম্যাটিং পরিষ্কার করা হয়:

| কৌশল                     | বিবরণ                                                 |
| ------------------------ | ----------------------------------------------------- |
| `collapseWhitespace`     | ধারাবাহিক ফাঁকা লাইন ও লাইনের শেষের স্পেস একত্রিত করে |
| `dedupSystemPrompt`      | সদৃশ সিস্টেম বার্তা সরিয়ে দেয়                       |
| `compressToolResults`    | অতিরিক্ত বিস্তারিত টুল/ফাংশন আউটপুট সংকুচিত করে       |
| `removeRedundantContent` | পুনরাবৃত্ত নির্দেশনা বাদ দেয়                         |
| `replaceImageUrls`       | base64 ইমেজ ডেটা URI সংক্ষিপ্ত করে                    |

**সবচেয়ে উপযোগী:** সর্বদা-সক্রিয় ব্যবহার এবং নিরাপত্তা-সংবেদনশীল কর্মপ্রবাহ।

### স্ট্যান্ডার্ড মোড (~30% সাশ্রয়)

[Caveman](https://github.com/JuliusBrussee/caveman) দ্বারা অনুপ্রাণিত — অর্থ অক্ষুণ্ণ রেখে অপ্রয়োজনীয় শব্দ ও অতিরিক্ত বাগাড়ম্বর সরিয়ে দেয়:

- অপ্রয়োজনীয় শব্দ ("please", "I think", "basically", "actually") সরিয়ে দেয়
- দীর্ঘ বাক্যাংশ সংক্ষিপ্ত করে ("in order to" → "to", "as a result of" → "because")
- বিনয়সূচক দ্বিধাপূর্ণ ভাষা ("Would you mind...", "If you could possibly...") বাদ দেয়
- কোডিং প্রম্পটের জন্য সূক্ষ্মভাবে সমন্বয় করা 30টির বেশি regex নিয়ম

**সবচেয়ে উপযোগী:** দৈনন্দিন কোডিং কর্মপ্রবাহ এবং খরচ-সচেতন দল।

### অ্যাগ্রেসিভ মোড (~50% সাশ্রয়)

দীর্ঘ সেশনের জন্য বুদ্ধিমান ইতিহাস ব্যবস্থাপনা:

- **বার্তার বয়সভিত্তিক সংকোচন** — পুরোনো বার্তাগুলো ধীরে ধীরে আরও সংকুচিত হয়
- **টুল ফলাফলের সারসংক্ষেপ** — দীর্ঘ টুল আউটপুট সারসংক্ষেপ দিয়ে প্রতিস্থাপিত হয়
- **কাঠামোগত অখণ্ডতা সুরক্ষা** — `tool_use` + `tool_result` জোড়াগুলো সামঞ্জস্যপূর্ণ থাকা নিশ্চিত করে
- **কনটেক্সট উইন্ডো সচেতনতা** — প্রতিটি মডেলের টোকেন সীমা মেনে চলে

**সবচেয়ে উপযোগী:** দীর্ঘ ডিবাগিং সেশন এবং বৃহৎ কোডবেস।

### আল্ট্রা মোড (~75% সাশ্রয়)

টোকেন-সংকটপূর্ণ পরিস্থিতির জন্য সর্বোচ্চ কম্প্রেশন:

- **হিউরিস্টিক ছাঁটাই** — প্রাসঙ্গিকতার থ্রেশহোল্ডের নিচে থাকা বার্তা সরিয়ে দেয়
- **কোড ব্লক সংকোচন** — পুনরাবৃত্তিমূলক কোড উদাহরণ সংকুচিত করে
- **বাইনারি সার্চ ট্রাঙ্কেশন** — কনটেক্সট উইন্ডোর জন্য সর্বোত্তম কর্তনবিন্দু নির্ধারণ করে
- অ্যাগ্রেসিভ মোডের সব বৈশিষ্ট্য অন্তর্ভুক্ত

**সবচেয়ে উপযোগী:** যখন আপনি বারবার কনটেক্সট সীমায় পৌঁছে যাচ্ছেন।

### RTK মোড (আপস্ট্রিমে 60-90% পরিসর)

RTK মোড কোডিং-এজেন্ট সেশনে দেখা যাওয়া অতিরিক্ত বিস্তারিত টুল আউটপুটের জন্য অপ্টিমাইজ করা হয়েছে:

- `git status`, `git diff`, `git log`, টেস্ট রানার, TypeScript/Vite/Webpack বিল্ড, ESLint/Biome/Prettier, npm audit/ইনস্টল, Docker লগ, ইনফ্রা আউটপুট এবং সাধারণ শেল আউটপুটের মতো কমান্ড/আউটপুট শ্রেণি শনাক্ত করে
- `open-sse/services/compression/engines/rtk/filters/` থেকে JSON ফিল্টার প্যাক প্রয়োগ করে
- ইনলাইন-টেস্ট যাচাইকরণ এবং প্রজেক্ট ফাইলের জন্য ট্রাস্ট-গেটিংসহ প্রজেক্ট বা গ্লোবাল `filters.toml` ফাইল থেকে RTK TOML schema v1 ফিল্টার ইমপোর্ট করে
- ইনলাইন যাচাইকরণ নমুনাসহ 49টি বিল্ট-ইন ফিল্টার সরবরাহ করে
- ANSI কন্ট্রোল সিকোয়েন্স, প্রগ্রেস বার, পুনরাবৃত্ত লাইন এবং কার্যকর নয় এমন অপ্রয়োজনীয় তথ্য সরিয়ে দেয়
- ব্যর্থতা, ত্রুটি, সতর্কতা, পরিবর্তিত ফাইল, সারসংক্ষেপ এবং দীর্ঘ আউটপুটের শেষাংশ সংরক্ষণ করে
- ট্রাস্ট-গেটেড প্রজেক্ট ফিল্টার, গ্লোবাল ফিল্টার এবং ঐচ্ছিকভাবে সংবেদনশীল তথ্য অপসারিত কাঁচা আউটপুট পুনরুদ্ধার সমর্থন করে

**সবচেয়ে উপযোগী:** শেল, বিল্ড, টেস্ট, git, grep এবং ফাইল-আউটপুট ট্রান্সক্রিপ্টসহ এজেন্ট সেশন।

### স্ট্যাকড মোড (উপযুক্ত ক্ষেত্রে 78-95% পরিসর)

স্ট্যাকড মোড নির্ধারিত ক্রমে একাধিক কম্প্রেশন ইঞ্জিন চালায়। ডিফল্ট পাইপলাইন হলো:

```txt
RTK -> Caveman
```

এই ক্রমে প্রথমে টার্মিনাল/টুল আউটপুট সংক্ষিপ্ত রাখা হয়, তারপর অবশিষ্ট স্বাভাবিক ভাষার প্রম্পটে Caveman-এর অর্থগত সংকোচন প্রয়োগ করা হয়। স্ট্যাকড পাইপলাইন গ্লোবালি অথবা রাউটিং কম্বোতে নির্ধারিত কম্প্রেশন কম্বোর মাধ্যমে কনফিগার করা যায়।

**সবচেয়ে উপযোগী:** বড় টুল লগের পাশাপাশি মানব নির্দেশনা বা অ্যাসিস্ট্যান্টের সারসংক্ষেপসহ মিশ্র কনটেক্সট।

## আপস্ট্রিম সাশ্রয়ের হিসাব

OmniRoute দুটি উৎস থেকে কম্প্রেশনজনিত সাশ্রয় নথিভুক্ত করে: আপস্ট্রিম প্রকল্পের বেঞ্চমার্ক এবং
OmniRoute-এর নিজস্ব ইঞ্জিন সমন্বয়।

| উৎস     | এখানে ব্যবহৃত আপস্ট্রিম README-এর সংখ্যা                                                                     |
| ------- | ------------------------------------------------------------------------------------------------------------ |
| Caveman | `~75%` কম আউটপুট টোকেন, বেঞ্চমার্কে গড় আউটপুট সাশ্রয় `65%`, পরিসর `22-87%`, এবং `~46%` ইনপুট কম্প্রেশন টুল |
| RTK     | কমান্ড-আউটপুটে `60-90%` সাশ্রয়; নমুনা সেশনে `~118,000 -> ~23,900` টোকেন, অর্থাৎ `79.7%` সাশ্রয় (`~80%`)    |

ওভারল্যাপ করা টুল/কনটেক্সট পেলোডের ক্ষেত্রে, ডিফল্ট OmniRoute কম্বো ইঞ্জিনগুলোকে ধারাবাহিকভাবে প্রয়োগ করে:

```txt
RTK -> Caveman
```

সম্মিলিত সাশ্রয় যোগাত্মক নয়, বরং গুণাত্মক:

```txt
combined = 1 - (1 - RTK savings) * (1 - Caveman input savings)
average  = 1 - (1 - 0.80) * (1 - 0.46) = 89.2%
range    = 1 - (1 - 0.60..0.90) * (1 - 0.46) = 78.4-94.6%
```

ওই `78-95%` সংখ্যাটি তখনই প্রযোজ্য, যখন RTK এবং Caveman উভয়ই একই ইনপুট/কনটেক্সট পেলোড কমাতে পারে।
Caveman-এর রেসপন্স আউটপুট মোড আলাদা: এটি সক্রিয় থাকলে Caveman-এর নিজস্ব আউটপুট সাশ্রয় ব্যবহার করুন (গড়ে `65%`,
প্রধানভাবে উল্লেখিত `~75%`, পরিসর `22-87%`)। মোট বিলিং সাশ্রয় আপনার প্রম্পট/আউটপুটের অনুপাতের ওপর নির্ভর করে।

### "যোগ্য" বলতে আসলে কী বোঝায়

প্রধানভাবে উল্লেখিত 15-95% পরিসরটি বাস্তব, তবে এটি শুধু **পুনরাবৃত্তিমূলক বা অতিরিক্ত বাগাড়ম্বরপূর্ণ** কনটেন্টের ক্ষেত্রে প্রযোজ্য—পুনরাবৃত্ত
এরর লাইন, একই সতর্কবার্তা বারবার দেখানো কোনো বিল্ড লগ, অতিরিক্ত বড় `grep`/ফাইল-পঠন ডাম্প। এর অর্থ এই
**নয়** যে প্রতিটি অনুরোধে এতটা সাশ্রয় হবে।

অভিজ্ঞতাভিত্তিকভাবে যাচাই করা হয়েছে (`tests/unit/compression/stacked-compression-tool-result-savings.test.ts`): 300টি অভিন্ন
এরর লাইন-সংবলিত Anthropic-আকৃতির একটি `tool_result` ব্লকের ওপর `stacked` (RTK + Caveman) রান চালিয়ে
**95.93% টোকেন সাশ্রয় / 96.26% ক্যারেক্টার সাশ্রয়** পাওয়া গেছে—যা প্রচারিত পরিসরের মধ্যেই পড়ে।
কিন্তু একই পাইপলাইন স্বাভাবিক, পুনরাবৃত্তিহীন টুল আউটপুটের ওপর চালালে (পরিচ্ছন্ন `grep` ম্যাচ তালিকা,
একটি ছোট ফাইল রিড, সাধারণ কথোপকথনের টেক্সট) সঠিকভাবেই **প্রায় শূন্য সাশ্রয়** হয়, কারণ
সরানোর মতো পুনরাবৃত্তিমূলক কিছুই থাকে না এবং `validateCompression()` (`validation.ts`) এমন কোনো
রিরাইট পাঠাতে অস্বীকৃতি জানায়, যা কোড ব্লক, URL, হেডিং, সংস্করণ, অথবা ALL-CAPS কনস্ট্যান্ট আইডেন্টিফায়ার বাদ দেবে বা পরিবর্তন করবে।

এটি প্রত্যাশিত ও নিরাপদ আচরণ, কোনো বাগ নয়: যে কোডিং সেশনে মূলত পরিচ্ছন্ন ফাইল পড়া/grep করা হয়,
সেখানে কম্প্রেশন সম্পূর্ণ সক্রিয় থাকা সত্ত্বেও মোট সাশ্রয় সীমিত হবে; অন্যদিকে ব্যর্থ হওয়া কোনো
লুপ বা অতিরিক্ত বার্তা দেওয়া লিন্টারের সম্মুখীন হওয়া সেশনে সেই ট্রাফিকের ওপর সম্পূর্ণ 78-95% পরিসরের সাশ্রয় দেখা যাবে। কম্প্রেশন ভুলভাবে কনফিগার করা হয়েছে—এমন প্রমাণ হিসেবে কোনো একক সেশনের
কম সামগ্রিক সাশ্রয় শতাংশ ব্যবহার করবেন না—প্রথমে যাচাই করুন, অন্তর্নিহিত টুল আউটপুটটি আসলেই পুনরাবৃত্তিমূলক ছিল কি না।

## কনফিগারেশন

### ড্যাশবোর্ড

`Dashboard → Context & Cache`-এ যান:

- **Caveman** — মোড নির্বাচন, ভাষা প্যাক, প্রিভিউ এবং গ্লোবাল ডিফল্ট
- **RTK** — কমান্ড-ফিল্টার প্রিভিউ, RTK নিরাপত্তা সেটিংস এবং ফিল্টার ক্যাটালগ
- **Compression Combos** — রাউটিং কম্বোগুলোর জন্য নির্ধারিত নামযুক্ত ইঞ্জিন পাইপলাইন
- **Auto-Trigger Threshold** — টোকেনের সংখ্যা থ্রেশহোল্ড অতিক্রম করলে স্বয়ংক্রিয়ভাবে কম্প্রেশন সক্রিয় করে

### প্রতি-কম্বো ওভাররাইড

`Dashboard → Context & Cache → Compression Combos`-এ একটি রাউটিং কম্বোর জন্য একটি কম্প্রেশন কম্বো নির্ধারণ করুন:

```txt
Combo: "free-tier-fallback"
  Compression Combo: "coding-agent-stack"
  Pipeline: RTK -> Caveman
  Targets:
    1. if/kimi-k2.7-code
    2. if/qwen3.8-max-preview
```

এর ফলে পেইড সাবস্ক্রিপশনগুলোতে লাইট মোড বজায় রেখে ফ্রি/কোডিং প্রোভাইডারগুলোতে স্ট্যাকড কম্প্রেশন ব্যবহার করতে পারবেন।

এই "Per-Combo Override" অ্যাসাইনমেন্টটি **routing-combo compression mode** ওভাররাইড (Default/Off/Lite/Standard/Aggressive/Ultra) থেকে আলাদা একটি নিয়ন্ত্রণ — ওই ওভাররাইড কোনো নামযুক্ত কম্প্রেশন-কম্বো পাইপলাইন নির্বাচন করে না; এটি কেবল `resolveCompressionPlan` দ্বারা বিবেচিত `compressionMode` ফিল্ডটি সেট করে। এটি কম্বো কার্ডে (`Dashboard → Combos`) অথবা #6760 থেকে `Dashboard → Context & Cache → Compression Combos`-এর "Assign to routing" তালিকায়, উপরে নথিভুক্ত পাইপলাইন-অ্যাসাইনমেন্ট চেকবক্সের ঠিক পাশেই, প্রতি রাউটিং কম্বোর জন্য সেট করা যায়। উভয় ইন্টারফেস একই `PUT /api/combos/{id}` এন্ডপয়েন্টের মাধ্যমে সংরক্ষিত হয়।

### প্রতি-রিকোয়েস্ট ওভাররাইড

একটি নির্দিষ্ট রিকোয়েস্টের জন্য কম্প্রেশন প্ল্যান ওভাররাইড করতে `x-omniroute-compression` রিকোয়েস্ট হেডার পাঠান। এটির অগ্রাধিকার সর্বোচ্চ — এটি রাউটিং-কম্বো ওভাররাইড, সক্রিয় প্রোফাইল, অটো-ট্রিগার এবং প্যানেলের Default-কে অগ্রাহ্য করে। অজানা মান উপেক্ষা করা হয় (রিকোয়েস্ট কখনো প্রত্যাখ্যাত হয় না), এবং গ্লোবাল মাস্টার সুইচ এখনও সবকিছু নিয়ন্ত্রণ করে: গ্লোবালি কম্প্রেশন বন্ধ থাকলে হেডারটি এটি চালু করতে পারে না। মানগুলো হলো:

| মান           | প্রভাব                                                                             |
| ------------- | ---------------------------------------------------------------------------------- |
| `off`         | এই রিকোয়েস্টের জন্য কোনো কম্প্রেশন নয়।                                           |
| `default`     | প্যানেল থেকে নির্ধারিত Default প্রোফাইল (সক্রিয় প্রোফাইল উপেক্ষা করে)।            |
| `engine:<id>` | সক্রিয় থাকলে একটি একক ইঞ্জিন, যেমন `engine:rtk`।                                  |
| `<combo>`     | একটি নামযুক্ত কম্বো, প্রথমে নাম দিয়ে (কেস-ইনসেনসিটিভ), তারপর id দিয়ে মিলানো হয়। |

প্রয়োগ করা প্ল্যানটি `X-OmniRoute-Compression: <mode>; source=<source>` রেসপন্স হেডারে ফেরত দেওয়া হয়, যেখানে `<source>` হলো `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default`, অথবা `off`-এর যেকোনো একটি।

### API

```bash
# কম্প্রেশন সেটিংস সংগ্রহ করুন
curl http://localhost:20128/api/settings/compression

# কম্প্রেশন সেটিংস আপডেট করুন
curl -X PUT http://localhost:20128/api/settings/compression \
  -H "Content-Type: application/json" \
  -d '{"defaultMode":"stacked","autoTriggerMode":"stacked","autoTriggerTokens":32000}'

# একটি নির্দিষ্ট RTK/stacked পেলোডের প্রিভিউ দেখুন
curl -X POST http://localhost:20128/api/compression/preview \
  -H "Content-Type: application/json" \
  -d '{"mode":"rtk","messages":[{"role":"tool","content":"npm test output here"}]}'

# RTK ফিল্টার প্যাকগুলোর তালিকা দেখুন
curl http://localhost:20128/api/context/rtk/filters

# ঐচ্ছিক কমান্ড মেটাডেটাসহ RTK সরাসরি পরীক্ষা করুন
curl -X POST http://localhost:20128/api/context/rtk/test \
  -H "Content-Type: application/json" \
  -d '{"command":"npm test","text":"FAIL tests/example.test.ts\nError: boom"}'
```

## কৃতজ্ঞতা

Standard মোডের কম্প্রেশন নিয়মগুলো **[JuliusBrussee](https://github.com/JuliusBrussee)**-এর **[Caveman](https://github.com/JuliusBrussee/caveman)** (⭐ 51K+) — ভাইরাল "অনেক টোকেন কেন ব্যবহার করবে, যখন অল্প টোকেনেই কাজ হয়" প্রকল্পটি থেকে অনুপ্রাণিত। Caveman-এর প্রতিবেদন অনুযায়ী, আউটপুট টোকেন `~75%` কম, বেঞ্চমার্কে গড় আউটপুট সাশ্রয় `65%`, আউটপুটের পরিসর `22-87%` এবং একটি `~46%` ইনপুট-কম্প্রেশন টুল রয়েছে।

RTK মোড **[RTK AI](https://github.com/rtk-ai)**-এর **[RTK - Rust Token Killer](https://github.com/rtk-ai/rtk)** — টার্মিনাল, বিল্ড, টেস্ট, git এবং টুল-আউটপুট ফিল্টারিংয়ের জন্য উচ্চ-কার্যক্ষমতার command-output কম্প্রেশন প্রকল্পটি থেকে অনুপ্রাণিত। RTK-এর প্রতিবেদন অনুযায়ী সাশ্রয় `60-90%`, এবং এর README-এর নমুনা সেশনে `~80%` সাশ্রয় দেখানো হয়েছে।

## উন্নত কম্প্রেশন সিস্টেম

৭টি স্ট্যান্ডার্ড মোডের পাশাপাশি, OmniRoute-এ বেশ কয়েকটি উন্নত কম্প্রেশন
সিস্টেম রয়েছে, যেগুলো কনটেক্সটের ভিত্তিতে স্বয়ংক্রিয়ভাবে কাজ করে।

### ক্যাশ-সচেতন কম্প্রেশন

কিছু প্রোভাইডার (যেমন prompt caching-সহ Anthropic) **prompt caching** সমর্থন করে,
যা খরচ ও ল্যাটেন্সি কমাতে তাদের প্রম্পটের কিছু অংশ ক্যাশ করতে দেয়। ক্যাশিং
সক্রিয় থাকলে aggressive কম্প্রেশন আসলে কর্মক্ষমতাকে **ক্ষতিগ্রস্ত** করতে পারে,
কারণ এটি ক্যাশ করা টোকেন পরিবর্তন করে এবং ক্যাশকে অকার্যকর করে দেয়।

`cachingAware.ts` মডিউলটি **ক্যাশিং কনটেক্সট শনাক্ত** করে এবং সেই অনুযায়ী
**কম্প্রেশন কৌশল সামঞ্জস্য** করে এই সমস্যার সমাধান করে।

#### এটি যেভাবে কাজ করে

1. **ক্যাশিং কনটেক্সট শনাক্ত করা** — `cache_control` মার্কারের জন্য অনুরোধের বডি স্ক্যান করে
2. **ক্যাশিং প্রোভাইডার শনাক্ত করা** — লক্ষ্য প্রোভাইডার ক্যাশিং সমর্থন করে কি না পরীক্ষা করে
3. **কৌশল সামঞ্জস্য করা** — ক্যাশিং প্রোভাইডারের ক্ষেত্রে `aggressive`/`ultra` থেকে `standard`-এ নামিয়ে আনে
4. **সিস্টেম প্রম্পট এড়িয়ে যাওয়া** — সিস্টেম প্রম্পট সাধারণত ক্যাশ করা থাকে, তাই সেগুলো কম্প্রেস করে না
5. **ডিটারমিনিস্টিক রূপান্তর ব্যবহার করা** — কেবল সামঞ্জস্যপূর্ণ আউটপুট তৈরি করে এমন রূপান্তর ব্যবহার করে

#### কোডের উদাহরণ

```ts
import {
  detectCachingContext,
  getCacheAwareStrategy,
} from "@omniroute/open-sse/services/compression/cachingAware";

const body = {
  model: "anthropic/claude-sonnet-4.5",
  messages: [{ role: "user", content: "Hello" }],
  cache_control: { type: "ephemeral" }, // ← ক্যাশ মার্কার
};

const ctx = detectCachingContext(body, { provider: "anthropic" });
// → { hasCacheControl: true, provider: "anthropic", isCachingProvider: true }

const strategy = getCacheAwareStrategy("aggressive", ctx);
// → { strategy: "standard", skipSystemPrompt: true, deterministicOnly: true }
```

#### কখন ব্যবহার করবেন

ক্যাশ-সচেতন কম্প্রেশন **সবসময় সক্রিয় থাকে** — কোনো কনফিগারেশনের প্রয়োজন নেই। এটি শুধু তখনই সক্রিয় হয়
যখন:

- অনুরোধে `cache_control` মার্কার থাকে
- লক্ষ্য প্রোভাইডার prompt caching সমর্থন করে (Anthropic, OpenAI ইত্যাদি)

### প্রগ্রেসিভ এজিং

দীর্ঘ কথোপকথনে অনেক মেসেজ টার্ন জমা হয়, কিন্তু পুরোনো টার্নগুলো ক্রমশ কম
প্রাসঙ্গিক হয়ে ওঠে। `progressiveAging.ts` মডিউলটি **টার্নের দূরত্ব অনুযায়ী মেসেজের বিস্তারিততা কমায়**:

- **সাম্প্রতিক টার্ন (0-3)**: হুবহু রাখা হয় (সম্পূর্ণ বিস্তারিত)
- **মাঝারি টার্ন (4-8)**: Lite কম্প্রেশন (হোয়াইটস্পেস, ফরম্যাটিং পরিষ্কার করা)
- **পুরোনো টার্ন (9+)**: Caveman কম্প্রেশন (অপ্রয়োজনীয় অংশ অপসারণ, সারসংক্ষেপ)
- **অত্যন্ত পুরোনো টার্ন (20+)**: ব্যাপকভাবে সংক্ষিপ্ত করা হয় অথবা বাদ দেওয়া হয়

#### কোডের উদাহরণ

```ts
import { applyAging } from "@omniroute/open-sse/services/compression/progressiveAging";

const messages = [
  { role: "system", content: "You are a helpful assistant" },
  { role: "user", content: "What is 2+2?" },
  { role: "assistant", content: "4" },
  // ... আরও ৫০টি টার্ন ...
];

const { messages: aged, saved } = applyAging(messages, {
  verbatim: 3, // প্রথম ৩টি টার্ন: হুবহু
  light: 8, // ৪-৮ নম্বর টার্ন: lite কম্প্রেশন
  moderate: 20, // ৯-২০ নম্বর টার্ন: caveman কম্প্রেশন
  // ২১ নম্বর এবং পরবর্তী টার্ন: ব্যাপক সারসংক্ষেপ
});

// saved = সাশ্রয় হওয়া টোকেনের সংখ্যা
```

#### কখন ব্যবহার করবেন

প্রগ্রেসিভ এজিং `aggressive` এবং `ultra` মোডে **সর্বদা চালু** থাকে। এটি
বিশেষভাবে কার্যকর:

- দীর্ঘ সময়ব্যাপী কোডিং সেশনে
- একাধিক দিনব্যাপী কথোপকথনে
- অনেক টুল কলসহ এজেন্টিক ওয়ার্কফ্লোতে

### কেভম্যান আউটপুট মোড

`outputMode.ts` মডিউলটি **সিস্টেম প্রম্পট নির্দেশনা** ইনজেক্ট করে, যাতে
মডেল নিজেই সংকুচিত, সংক্ষিপ্ত আউটপুট (একটি "কেভম্যান" স্টাইল) তৈরি করে।

#### এটি যেভাবে কাজ করে

ইনপুট সংকুচিত করার পরিবর্তে, এই মোডটি নিচের মতো একটি সিস্টেম প্রম্পট যোগ করে:

> "ন্যূনতম শব্দে উত্তর দিন। সৌজন্যমূলক কথা বাদ দিন। ছোট বাক্য ব্যবহার করুন।"

এটি বিশেষভাবে ভালো কাজ করে:

- কোড জেনারেশনে (আরও সংক্ষিপ্ত আউটপুট = কম টোকেন)
- দ্রুত প্রশ্নোত্তরে (বিস্তারিত ব্যাখ্যার প্রয়োজন নেই)
- ব্যাচ প্রসেসিংয়ে (থ্রুপুট সর্বাধিক করতে)

#### কখন ব্যবহার করবেন

কেভম্যান আউটপুট মোড **ঐচ্ছিক** — কম্বো কনফিগের মাধ্যমে এটি সেট করুন:

```json
{
  "strategy": "auto",
  "config": {
    "auto": {
      "outputMode": "caveman"
    }
  }
}
```

### আউটপুট স্টাইলসমূহ (ক্যাটালগ)

উপরের কেভম্যান আউটপুট মোডটি হলো **পুরোনো একক-স্টাইলের পাথ**। Phase 4 এটিকে
কম্পোজযোগ্য আউটপুট স্টাইলের একটি ক্যাটালগে সাধারণীকরণ করেছে: `OUTPUT_STYLE_CATALOG`, যা
`open-sse/services/compression/outputStyles/catalog.ts`-এ রয়েছে। প্রতিটি স্টাইল একটি সিস্টেম-প্রম্পট
নির্দেশনা, যা মডেলকে নিজেই কম ব্যয়বহুল আউটপুট তৈরি করতে বলে; স্টাইলগুলো একসঙ্গে সক্রিয়
করা যায় এবং ক্যাটালগের ক্রম অনুযায়ী ইনজেক্ট করা হয়।

| ------------------------------ | ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| সংক্ষিপ্ত গদ্য                 | `terse-prose` | অপ্রয়োজনীয় শব্দ/আর্টিকেল/দ্বিধাসূচক ভাষা বাদ দেয়; প্রযুক্তিগত বিষয়বস্তু নির্ভুল রাখে। পুরোনো কেভম্যান আউটপুট মোডের একই টেক্সট (রেফারেন্স করা হয়েছে, পুনরায় লেখা নয়)।                                                | en, pt-BR, es, de, fr, it, ru, zh, ja, id, vi                    |

প্রতিটি স্টাইলে তিনটি তীব্রতার স্তর থাকে — `lite`, `full`, `ultra` — এবং প্রতিটি স্তর
শেয়ার করা সীমারেখা ক্লজ দিয়ে শেষ হয়, যা কোড ব্লক, ফাইল পাথ, কমান্ড,
ত্রুটির স্ট্রিং, URL এবং আইডেন্টিফায়ার হুবহু রাখে।

#### ইনজেকশন যেভাবে কাজ করে

`applyOutputStyles()` (`open-sse/services/compression/outputStyles/apply.ts`) ক্যাটালগের
সঙ্গে নির্বাচনটি সমাধান করে (অজানা id এবং লোকেলের সঙ্গে না-মেলা স্টাইল বাদ দেওয়া হয়,
কখনোই ত্রুটি তৈরি হয় না), নির্বাচিত নির্দেশনাগুলো ক্যাটালগের ক্রমে সংযুক্ত করে,
সীমারেখা ক্লজটি **একবার** যোগ করে এবং একটি মাত্র আইডেমপোটেন্সি মার্কারের
(`[OmniRoute Output Styles]`) পরে ফলাফলটি সিস্টেম প্রম্পটের শুরুতে যোগ করে — পুনরায় প্রয়োগ
করলে কিছুই ঘটে না। শনাক্ত করা অনুরোধের ভাষার অনুবাদ থাকলে, ইংরেজির পরিবর্তে
স্থানীয়কৃত নির্দেশনা ইনজেক্ট করা হয়।

#### যেভাবে সক্রিয় করবেন

ড্যাশবোর্ডে: **Context → Settings → Compression** — প্রতিটি স্টাইলের জন্য একটি
চালু/বন্ধ টগল এবং একটি স্তর নির্বাচকসহ একটি সারি। প্রোগ্রামগতভাবে, কম্প্রেশন কনফিগ
নির্বাচনটি এভাবে সংরক্ষণ করে:

```json
{
  "outputStyles": [
    { "id": "i-have-adhd", "level": "full" },
    { "id": "less-code", "level": "lite" }
  ]
}
```

পশ্চাৎ-সামঞ্জস্য: পুরোনো `outputMode: "caveman"` কম্বো সেটিং এখনো কাজ করে এবং
`terse-prose`-এ ম্যাপ হয়, যা প্রতিটি পুরোনো ভাষায় আগের ইনজেকশনের সঙ্গে বাইট-অভিন্ন।

ভাষা নির্বাচন: `languageConfig.enabled` চালু থাকলে, `autoDetect` সর্বশেষ ব্যবহারকারী
বার্তার ভাষা বেছে নেয় (ইনপুট ইঞ্জিনগুলোর মতো একই ডিটেক্টর);
`autoDetect` বন্ধ করলে `defaultLanguage` স্থিরভাবে ব্যবহৃত হয়। বন্ধ → ইংরেজি।

স্টাইল × ভাষা ম্যাট্রিক্সটি
`tests/unit/compression/output-styles-i18n-matrix.test.ts` দ্বারা নির্ধারিত: অন্তত একটি
pt-BR অনুবাদ (অথবা স্পষ্টভাবে ট্র্যাক করা ব্যতিক্রম) ছাড়া কোনো নতুন স্টাইল প্রকাশ করা যায় না,
এবং বিদ্যমান কোনো স্টাইল নীরবে কোনো লোকেল হারাতে পারে না। স্টাইল যোগ করতে দেখুন
[EXTENDING_COMPRESSION.md](./EXTENDING_COMPRESSION.md#adding-an-output-style)।

### টুল ফলাফল কম্প্রেশন

`toolResultCompressor.ts` মডিউলটি টুলের ফলাফলের (ফাংশন কল, এজেন্ট আউটপুট,
সার্চ ফলাফল ইত্যাদি) জন্য **5টি বিশেষায়িত কম্প্রেশন কৌশল** প্রদান করে:

1. **সার্চ ফলাফল কম্প্রেশন** — অপ্রয়োজনীয় পুনরাবৃত্ত ফলাফল সরায়, শীর্ষ-N রাখে
2. **ফাইল রিড কম্প্রেশন** — বড় ফাইল ছেঁটে দেয়, হেডার/ইমপোর্ট সংরক্ষণ করে
3. **কোড এক্সিকিউশন কম্প্রেশন** — শুধু প্রয়োজনীয় stdout/stderr রাখে
4. **ডেটাবেস কোয়েরি কম্প্রেশন** — সারি সীমিত করে, অতিরিক্ত মেটাডেটা সরায়
5. **API রেসপন্স কম্প্রেশন** — null ফিল্ড বাদ দেয়, অ্যারে সংক্ষিপ্ত করে

#### কখন ব্যবহার করবেন

টুল কল উপস্থিত থাকলে টুল ফলাফল কম্প্রেশন **সর্বদা চালু** থাকে। কোনো
কনফিগারেশনের প্রয়োজন নেই।

### স্ট্যাকড পাইপলাইন

স্ট্যাকড মোড **একাধিক ইঞ্জিন ক্রমানুসারে** চালায় — সাধারণত প্রথমে RTK
(টুল আউটপুটে 60-90% সাশ্রয়), তারপর কেভম্যান (অবশিষ্ট টেক্সটে অতিরিক্ত 30%
সাশ্রয়)। এতে **মোট 78-95% সাশ্রয়** হয়।

#### এটি যেভাবে কাজ করে

```
ইনপুট (1000 টোকেন)
  → RTK (কমান্ড-সচেতন ফিল্টার) → 200 টোকেন
    → কেভম্যান (অপ্রয়োজনীয় শব্দ অপসারণ) → 140 টোকেন
  → আউটপুট (140 টোকেন, 86% সাশ্রয়)
```

#### কখন ব্যবহার করবেন

স্ট্যাকড মোড ব্যবহার করুন:

- টুল-নির্ভর ওয়ার্কফ্লোর জন্য (এজেন্টিক কোডিং, গবেষণা)
- ব্যয়-সংবেদনশীল ব্যাচ প্রসেসিংয়ের জন্য
- যখন আপনার সর্বাধিক টোকেন সাশ্রয় প্রয়োজন

কম্বোর মাধ্যমে কনফিগার করুন:

```json
{
  "strategy": "auto",
  "config": {
    "auto": {
      "modePack": "stacked"
    }
  }
}
```

## কম্প্রেশন কম্বো ওভাররাইড

বিভিন্ন ব্যবহারের ক্ষেত্রে আচরণ সূক্ষ্মভাবে নিয়ন্ত্রণ করতে আপনি **প্রতিটি কম্বোর জন্য** গ্লোবাল কম্প্রেশন মোড ওভাররাইড করতে পারেন:

```json
{
  "id": "coding-combo",
  "strategy": "priority",
  "config": {
    "auto": {
      "weights": { "taskFit": 0.5 },
      "modePack": "quality-first"
    }
  },
  "compressionOverride": {
    "mode": "aggressive",
    "stackedPipelines": ["rtk", "caveman"],
    "preserveToolDefinitions": true
  }
}
```

এটি যেসব ক্ষেত্রে উপযোগী:

- **কোডিং কম্বো**: দীর্ঘ সেশনের জন্য `aggressive` মোড ব্যবহার করুন
- **দ্রুত প্রশ্নোত্তর কম্বো**: দ্রুত প্রতিক্রিয়ার জন্য `lite` মোড ব্যবহার করুন
- **টুল-নির্ভর কম্বো**: সর্বোচ্চ সাশ্রয়ের জন্য `stacked` মোড ব্যবহার করুন
- **প্রোডাকশন কম্বো**: ক্যাশিং প্রদানকারীদের জন্য `cache-aware` মোড ব্যবহার করুন
