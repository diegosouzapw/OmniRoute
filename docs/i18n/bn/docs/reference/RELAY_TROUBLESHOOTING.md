রিলে (Vercel, Deno, Cloudflare) একটি সার্ভারলেস ব্যাকএন্ডে আপস্ট্রিম সংযোগ
সমাপ্ত করে, যাতে প্রোভাইডারের API কী সার্ভার-সাইডে রেখেই OmniRoute একটি স্থিতিশীল
অঞ্চল থেকে বহির্গামী ট্রাফিক পাঠাতে পারে। এই নথিতে অপারেটররা প্রোডাকশনে যে দুটি ব্যর্থতার
সম্মুখীন হন এবং প্রতিটির জন্য OmniRoute যে পুনরুদ্ধার পদ্ধতি সরবরাহ করে, তা আলোচনা করা হয়েছে।

## রিলে অথ কীভাবে সংরক্ষণ করা হয়

আপনি যখন **Settings → Proxy Pool → Deploy Relay** থেকে একটি রিলে ডিপ্লয় করেন,
তখন ডিপ্লয় প্রক্রিয়া প্রক্সির `notes` JSON ফিল্ডে রিলের অথ টোকেন সংরক্ষণ করে:

- `STORAGE_ENCRYPTION_KEY` সেট করা থাকলে, টোকেনটি `relayAuthEnc` হিসেবে লেখা হয়
  (সংরক্ষিত অবস্থায় AES-এনক্রিপ্টেড)।
- অন্যথায় এটি প্লেইনটেক্সট `relayAuth` হিসেবে লেখা হয়।

রিকোয়েস্টের সময় `extractRelayAuth(notes)` উপস্থিত ফর্মটি ফেরত দেয়,
তাই রিস্টার্টের পরেও রিলে কাজ করতে থাকে।

## ব্যর্থতার ধরন ১ — কী রোটেশনের পরে ডিক্রিপ্ট করা যায় না এমন টোকেন

**উপসর্গ:** আগে কাজ করা রিলেগুলো এখন
`STORAGE_ENCRYPTION_KEY`-এর এনভায়রনমেন্ট বা সিক্রেট-ম্যানেজার রোটেশনের পরে আপস্ট্রিম `401`/অথ
ত্রুটি ফেরত দেয়। সংরক্ষিত `relayAuthEnc` ব্লবটি আর ডিক্রিপ্ট করা যায় না,
তাই `extractRelayAuth` একটি খালি স্ট্রিং ফেরত দেয় এবং রিলে কোনো অথ
পাঠায় না।

**পুনরুদ্ধার — বর্তমান অবস্থাতেই মেরামত করুন (পুনরায় ডিপ্লয় নয়):**

1. **Settings → Proxy Pool** খুলুন।
2. যেসব রিলে সারিতে অথ অনুপস্থিত, সেখানে একটি হলুদ `auth missing` ব্যাজ এবং
   **Repair** বোতাম দেখা যায়।
3. **Repair**-এ ক্লিক করুন। OmniRoute
   `POST /api/settings/proxies/[id]/repair-relay` কল করে, যা:
   - **বর্তমান** কী দিয়ে `relayAuthEnc` ডিক্রিপ্ট করে,
   - প্লেইনটেক্সট `relayAuth` আবার `notes`-এ লেখে,
   - `{ repaired: true, mode: "recovered" }` ফেরত দেয়।

কোনো ডিপ্লয় ক্রেডেনশিয়াল পুনরায় প্রবেশ না করিয়েই রিলে আবার পরিষেবা দেওয়া শুরু করে।

এটি কেবল তখনই কাজ করে, যখন বর্তমান `STORAGE_ENCRYPTION_KEY` এখনও ব্লবটি
ডিক্রিপ্ট করতে পারে। আপনি যদি কোনো মাইগ্রেশন **ছাড়াই** কী রোটেট করে থাকেন, তবে ব্লবটি
পুনরুদ্ধার করা যাবে না।

## ব্যর্থতার ধরন ২ — পুনরুদ্ধার-অযোগ্য টোকেন (কী রোটেশনে হারিয়ে গেছে)

**উপসর্গ:** আপনি **Repair**-এ ক্লিক করেছেন এবং পেয়েছেন
`{ repaired: false, mode: "redeploy", status: 409 }`।

**পুনরুদ্ধার — পুনরায় ডিপ্লয় করুন:**

বর্তমান কী দিয়ে সংরক্ষিত টোকেনটি পুনরুদ্ধার করা যাবে না। আপনি প্রথমে যে
একই মডাল ব্যবহার করেছিলেন, সেখান থেকে রিলেটি পুনরায় ডিপ্লয় করুন (**Deploy Relay** মেনু → Vercel / Deno
/ Cloudflare)। ডিপ্লয় প্রক্রিয়া একটি নতুন টোকেন লেখে (বর্তমান
কী দিয়ে এনক্রিপ্ট করা) এবং সারিটির `auth missing` ব্যাজ সরে যায়।

UI-তে টোকেনটি পুনরুদ্ধার-অযোগ্য হলে **Repair** বোতামটিই পুনরায় ডিপ্লয়ের মডাল চালু করে,
তাই আপনাকে কখনোই এটি ম্যানুয়ালি খুঁজতে হয় না।

## ব্যর্থতার ধরন ৩ — রিলেতে পৌঁছানো যাচ্ছে, কিন্তু সেটি অস্বাস্থ্যকর

**উপসর্গ:** প্রক্সি পরীক্ষা (`speed` বোতাম) রিলেটিকে সচল দেখায়, কিন্তু রিকোয়েস্টগুলো
তবুও মাঝেমধ্যে ব্যর্থ হয়।

OmniRoute-এর স্বয়ংক্রিয় পরীক্ষা প্রোব থেকে ফেরত আসা রিলে-সচেতনতা হেডারগুলো পরীক্ষা করুন
(**Settings → Proxy Pool** এবং `relayTested` / `relayAlive` কাউন্টার দেখুন):

- `x-relay-url` — কোন রিলে ব্যাকএন্ড উত্তর দিয়েছে।
- `x-relay-mode` — ওই রিকোয়েস্টের জন্য `ts` | `bifrost` | `auto`।
- `x-relay-attempts` — সফল হওয়ার আগে কতটি রিলে হপ চেষ্টা করা হয়েছে।
- `x-relay-fallback` — পছন্দের ব্যাকএন্ড থেকে TypeScript রিলেতে রিকোয়েস্ট
  ফলব্যাক করলে `true`।

কম `relayAlive`-এর সঙ্গে `x-relay-fallback`-এর উচ্চ হার বোঝায় যে সাইডকার
ব্যাকএন্ডটি অস্বাস্থ্যকর এবং আপনার হয় এটি ঠিক করা উচিত, নয়তো রিলে ব্যাকএন্ড
কৌশল `ts`-এ পরিবর্তন করা উচিত (`RELAY_BACKEND_STRATEGY.md` দেখুন)।

## API রেফারেন্স

| মেথড   | পাথ                                       | বডি                     | সফলতা                                                                                                                                            | ব্যর্থতা                                                                                       |
| ------ | ----------------------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| `POST` | `/api/settings/proxies/[id]/repair-relay` | `{ "id": "<proxyId>" }` | পুনরায় নির্ণয় করা হলে `200 { repaired: true, mode: "recovered" }`; প্লেইনটেক্সট ইতিমধ্যে উপস্থিত থাকলে `200 { repaired: false, mode: "noop" }` | পুনরুদ্ধার-অযোগ্য হলে `409 { mode: "redeploy" }`; রিলে টাইপ না হলে `400`; পাওয়া না গেলে `404` |

লিস্ট রুট `GET /api/settings/proxies` প্রতিটি আইটেমে সিক্রেট-বিহীন
`relayInfo: { isRelay, authMissing, repairMode }` যুক্ত করে, যাতে ড্যাশবোর্ড
কখনো টোকেন প্রকাশ না করেই মেরামতের সুবিধাটি রেন্ডার করতে পারে।
