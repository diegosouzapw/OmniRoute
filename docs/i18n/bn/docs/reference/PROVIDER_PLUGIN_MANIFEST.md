`open-sse/config/providerPluginManifest.ts` JSON-নিরাপদ provider plugin চুক্তিটি সংজ্ঞায়িত করে।
`open-sse/config/providerPluginManifestRegistry.ts` সেই চুক্তিকে Bifrost,
CLIProxyAPI বা ভবিষ্যতের কোনো Go/Rust router-এর মতো sidecar-এর জন্য বর্তমান provider
registry-এর সঙ্গে যুক্ত করে। TypeScript registry-ই সত্যের উৎস হিসেবে বহাল থাকে,
তবে sidecar-গুলো executor code, OAuth default, header বা process environment state
import না করেই manifest ব্যবহার করতে পারে।

একই manifest HTTP-এর মাধ্যমেও
`GET /api/v1/provider-plugin-manifest`-এ পাওয়া যায়, যাতে out-of-process চলা sidecar-গুলো এটি ব্যবহার করতে পারে।

OmniRoute,
`X-OmniRoute-Provider-Manifest-Url` request header-এর মাধ্যমে Bifrost এবং CLIProxyAPI-কে ওই URL জানায়।
sidecar-এর local request origin-এর পরিবর্তে কোনো public বা container
network URL প্রয়োজন হলে `OMNIROUTE_PROVIDER_MANIFEST_URL` সেট করুন।

## Manifest রিফ্রেশ করা

HTTP endpointটি `Cache-Control: public, max-age=60` এবং একটি শক্তিশালী
`ETag` প্রদান করে। একটি sidecar-এর সর্বশেষ যাচাইকৃত manifest সংরক্ষণ করা উচিত এবং
রিফ্রেশ করার সময় `If-None-Match`-এ তার ETag পাঠানো উচিত। একটি `304 Not Modified`
response-এর কোনো body থাকে না; sidecar তার cached manifest ব্যবহার করতে থাকে।
যদি কোনো যাচাইকৃত cached manifest না থাকে, তবে `304` গ্রহণ করার পরিবর্তে sidecar-কে
অবশ্যই একটি unconditional request পাঠাতে হবে।

## লক্ষ্য

Provider metadata-কে একটি plugin চুক্তির দিকে নিয়ে যাওয়া, যাতে শেষ পর্যন্ত
কম latency-র কোনো sidecar hot request path-এর মালিকানা নিতে পারে, আর OmniRoute
TypeScript route-কে policy gate এবং fallback হিসেবে ধরে রাখে। Manifestটি additive:
এটি নিজে থেকে request routing পরিবর্তন করে না।

## চুক্তি

Manifest-এ রয়েছে:

- provider id এবং alias
- upstream format এবং executor name
- auth type, auth header এবং ঐচ্ছিক auth prefix
- static endpoint metadata
- sidecar eligibility এবং কোনো provider-এর TS-এ থেকে যাওয়া উচিত হলে তার সুস্পষ্ট কারণ
- JSON-নিরাপদ model metadata, যেমন context length, vision/reasoning flag এবং
  unsupported param
- `apikey`, `oauth`, `custom-executor`,
  `passthrough-models`, `responses`, `sidecar-candidate`, `usage-fetch` এবং `usage-supported`-সহ capability tag

Manifest থেকে ইচ্ছাকৃতভাবে বাদ দেওয়া হয়েছে:

- OAuth client secret এবং default secret value
- runtime environment resolution
- request header এবং public credential helper
- dynamic URL builder
- executor function
- session pool-এর অভ্যন্তরীণ বিষয়

## Capability Tag

`capabilities` হলো registry entry থেকে উদ্ভূত tag-এর একটি sorted array। Integrator-দের
TypeScript source আবার পড়ার পরিবর্তে, "এই provider কী করতে পারে"—এই প্রশ্নের
machine-readable উত্তর হিসেবে এটিকে বিবেচনা করা উচিত।

| Tag                  | অর্থ                                                                          |
| -------------------- | ----------------------------------------------------------------------------- |
| `apikey`             | একটি API key গ্রহণ করে (`authType` হলো `apikey` বা `optional`)।               |
| `oauth`              | একটি OAuth বা session flow ব্যবহার করে।                                       |
| `responses`          | একটি OpenAI Responses-API base URL প্রকাশ করে।                                |
| `passthrough-models` | static catalog-এর পরিবর্তে সরাসরি upstream থেকে model পরিবেশন করে।            |
| `custom-executor`    | non-default executor চালায়, তাই এটি TypeScript path-এ থাকে।                  |
| `sidecar-candidate`  | `sidecar.eligible` প্রতিফলিত করে — sidecar import-এর জন্য বিবেচনা করা নিরাপদ। |
| `usage-fetch`        | একটি সংযুক্ত usage বা quota fetcher (`getUsageForProvider`) রয়েছে।           |
| `usage-supported`    | usage API এই provider-কে গ্রহণ করে (`isSupportedUsageConnection`)।            |

`usage-fetch` শুধু discovery-এর জন্য। এটি জানায় যে OmniRoute কীভাবে provider-এর
usage পড়তে হয় তা জানে; এটি fetching সক্রিয় করে না, quota semantics পরিবর্তন করে না,
বা provider-এর জন্য Dashboard quota widget সক্রিয় আছে এমন ইঙ্গিত দেয় না — ওই widget
আলাদাভাবে `USAGE_SUPPORTED_PROVIDERS` দ্বারা gated। সত্যের উৎস হলো
`open-sse/services/usage/fetcherProviders.ts`-এর `USAGE_FETCHER_PROVIDERS`।

ওই list usage dispatcher যে string-গুলো গ্রহণ করে সেগুলো দিয়ে keyed, তাই এতে canonical id
এবং alias মিশ্রিত থাকে এবং এটি tagged provider-এর সংখ্যার চেয়ে সামান্য দীর্ঘ: manifest
registry-তে chat provider নয় এমন entry-গুলোর (যেমন `firecrawl` search provider
এবং `amazon-q` ACP provider) tag করার মতো কোনো manifest entry নেই।

`usage-supported` জানায় server এবং Dashboard usage route-গুলো provider-এর কোনো
connection গ্রহণ করে কি না। এটি `isSupportedUsageConnection()` (`src/lib/usage/providerLimits.ts`)
এবং `supportsProviderQuota()` (`src/shared/utils/providerQuotaVisibility.ts`) প্রতিফলিত করে,
যেগুলো উভয়ই `USAGE_SUPPORTED_PROVIDERS`
(`open-sse/services/usage/supportedProviders.ts`) দ্বারা gated। `usage-fetch`-এর বিপরীতে,
এটি শুধু provider id-তে নির্গত হয় — runtime guard কোনো alias resolution ছাড়াই
`USAGE_SUPPORTED_PROVIDERS.includes(providerId)` চালায়, তাই manifest-ও একই নিয়ম
বজায় রাখে। tag দুটির পরিধি আলাদা: 3টি provider-এ শুধু
`usage-fetch` (`opencode`, `opencode-zen`, `xai`) রয়েছে এবং 1টিতে শুধু
`usage-supported` (`xiaomi-mimo-token-plan`) রয়েছে, তাই একটি থেকে অন্যটি বোঝায় না।

## সাইডকারের ব্যবহার

সাইডকারগুলোর উচিত `sidecar.eligible`-কে শর্তহীন রাউটিং সিদ্ধান্ত হিসেবে নয়, বরং একটি রক্ষণশীল প্রার্থী সংকেত হিসেবে বিবেচনা করা। প্রথম ইমপোর্ট লক্ষ্য হওয়া উচিত ডিফল্ট এক্সিকিউটর ব্যবহারকারী API-key, স্ট্যাটিক-এন্ডপয়েন্ট প্রোভাইডারগুলো। কাস্টম ওয়েব এক্সিকিউটর, OAuth/সেশন ফ্লো, ডায়নামিক URL বিল্ডার অথবা পুল কনফিগসহ প্রোভাইডারগুলো TypeScript ফলব্যাক পাথে থাকবে, যতক্ষণ না কোনো সাইডকার সমতুল্য আচরণ বাস্তবায়ন করে এবং টেলিমেট্রি সমতা প্রমাণ করে।

প্রস্তাবিত মাইগ্রেশন পর্যায়সমূহ:

1. TS রেজিস্ট্রি থেকে প্রোভাইডার প্লাগইন ম্যানিফেস্ট তৈরি ও যাচাই করুন।
2. API-key/স্ট্যাটিক প্রোভাইডারগুলোর জন্য ম্যানিফেস্ট ইমপোর্ট করতে Bifrost বা CLIProxyAPI-কে সক্ষম করুন।
3. TS ফলব্যাক সক্রিয় রেখে `OMNIROUTE_RELAY_BACKEND`-এর আড়ালে যোগ্য প্রোভাইডারগুলোকে সাইডকারের মাধ্যমে রাউট করুন।
4. সফলতার হার, p99 ল্যাটেন্সি, স্ট্রিমিং আচরণ এবং অসমর্থিত প্যারামিটার পরিচালনা TS পাথের সঙ্গে মিলে গেলেই কেবল প্রোভাইডারগুলোকে উন্নীত করুন।
5. প্রতিবার একটি করে প্রোভাইডার পরিবারের কাস্টম এক্সিকিউটরের জন্য সাইডকার-নেটিভ প্লাগইন যোগ করুন।
