Traffic Inspector হলো OmniRoute-এর অন্তর্নির্মিত HTTPS ট্রাফিক ডিবাগার — Charles Proxy / mitmweb / HTTP Toolkit-এর মতো একটি টুল, যা **LLM-সচেতন** এবং **এজেন্ট-সচেতন**। এটি `/dashboard/tools/traffic-inspector`-এ অবস্থিত এবং একই সময়ে সর্বোচ্চ ৫টি ক্যাপচার উৎস থেকে লাইভ ট্রাফিক গ্রহণ করে।

**ড্যাশবোর্ডের অবস্থান:** `/dashboard/tools/traffic-inspector`
**সাইডবার গ্রুপ:** Tools (AgentBridge-এর পরে)
**আরও দেখুন:** [`AGENTBRIDGE.md`](./AGENTBRIDGE.md) — AgentBridge হলো ক্যাপচার মোড ১।

### এক অনুচ্ছেদে আর্কিটেকচার

`TrafficBuffer` (`src/mitm/inspector/buffer.ts`) হলো একটি শেয়ার করা ইন-মেমরি রিং বাফার (ডিফল্টভাবে ১০০০টি এন্ট্রি, `INSPECTOR_BUFFER_SIZE` দিয়ে কনফিগারযোগ্য)। সব ক্যাপচার উৎস `push()`-এর মাধ্যমে এতে ডেটা লেখে। বাফারটি `kindDetector.ts` ব্যবহার করে প্রতিটি এন্ট্রিকে শ্রেণিবদ্ধ করে (এটি কোনো LLM অনুরোধ কি না নির্ধারণ করে), একটি `contextKey` গণনা করে (সিস্টেম প্রম্পটের SHA-256 ফিঙ্গারপ্রিন্ট), এবং `globalTrafficBuffer.subscribe()`-এর মাধ্যমে সব WebSocket সাবস্ক্রাইবারের কাছে সম্প্রচার করে। ড্যাশবোর্ডটি `GET /api/tools/traffic-inspector/ws`-এর মাধ্যমে সংযুক্ত হয় এবং সংযোগের সময় একটি স্ন্যাপশট গ্রহণ করে, এরপর `new`/`update`/`clear` ইভেন্ট পায়।

## §2 ক্যাপচার মোডসমূহ

Traffic Inspector **5টি যুগপৎ ক্যাপচার উৎস** সমর্থন করে। প্রতিটি স্বাধীনভাবে চালু বা বন্ধ করা যায়। প্রতিটি `InterceptedRequest`-এর (`src/mitm/inspector/types.ts`) `source` ফিল্ডটি `"agent-bridge"`, `"custom-host"`, `"http-proxy"`, `"system-proxy"`, অথবা `"tproxy"`-এর মধ্যে একটি।

### মোড 1 — AgentBridge (ডিফল্ট, সর্বদা চালু)

**উৎস:** AgentBridge হ্যান্ডলারসমূহ (`src/mitm/handlers/base.ts`)
**কার্যপ্রণালি:** `MitmHandlerBase`-এর প্রতিটি `intercept()` কল ফরওয়ার্ড করার আগে `hookBufferStart()` এবং সম্পন্ন হওয়ার পর `hookBufferUpdate()` কল করে। কোনো অতিরিক্ত কনফিগারেশন নেই—AgentBridge চালু হলেই এটি কাজ করে।
**পরিধি:** AgentBridge-এ কনফিগার করা 9টি IDE এজেন্ট
**দ্রষ্টব্য:** `InterceptedRequest`-এর `source` ফিল্ড = `"agent-bridge"`

### মোড 2 — কাস্টম হোস্টসমূহ (DNS রিডাইরেক্ট)

**উৎস:** ব্যবহারকারী-সংজ্ঞায়িত হোস্ট তালিকা (`inspector_custom_hosts` টেবিল)
**কার্যপ্রণালি:** UI-এর মাধ্যমে একটি হোস্ট যোগ করলে `/etc/hosts`-এ `127.0.0.1 <host>` যোগ হয় (sudo প্রয়োজন)। বিদ্যমান AgentBridge MITM সার্ভারটি (পোর্ট 443) নতুন হোস্টের জন্য গতিশীলভাবে একটি SNI সার্টিফিকেট তৈরি করে।
**পরিধি:** যোগ করা হোস্ট ব্যবহারকারী যেকোনো অ্যাপ্লিকেশন—অ্যাপের কনফিগারেশন পরিবর্তনের প্রয়োজন নেই
**দ্রষ্টব্য:** `source` = `"custom-host"`

ব্যবহারের উদাহরণ:

- Python স্ক্রিপ্ট থেকে `api.openai.com` পর্যবেক্ষণ করা
- `my-internal-llm.company.com` ডিবাগ করা
- একই নেটওয়ার্কে থাকা মোবাইল ডিভাইসের ট্রাফিক ক্যাপচার করা (ARP স্পুফিংয়ের মাধ্যমে—উন্নত)

### মোড 3 — HTTP_PROXY লিসেনার (পোর্ট 8080)

**উৎস:** `HTTP_PROXY`/`HTTPS_PROXY` এনভায়রনমেন্ট ভেরিয়েবল ব্যবহারকারী অ্যাপ্লিকেশনসমূহ
**কার্যপ্রণালি:** পোর্ট 8080-এ একটি সেকেন্ডারি লিসেনার (`src/mitm/inspector/httpProxyServer.ts`), যা একটি আদর্শ সুস্পষ্ট HTTP/HTTPS প্রক্সি হিসেবে কাজ করে। এটি `CONNECT` টানেল (HTTPS) এবং সরাসরি HTTP অনুরোধ গ্রহণ করে।
**পরিধি:** `HTTP_PROXY` এনভায়রনমেন্ট ভেরিয়েবল অনুসরণকারী যেকোনো অ্যাপ্লিকেশন—DNS পরিবর্তন বা sudo-এর প্রয়োজন নেই
**দ্রষ্টব্য:** `source` = `"http-proxy"`

```bash
# একটি কমান্ডের জন্য দ্রুত ক্যাপচার:
HTTPS_PROXY=http://127.0.0.1:8080 curl https://api.openai.com/v1/models

# একটি শেল সেশনে স্থায়ী ক্যাপচার:
export HTTP_PROXY=http://127.0.0.1:8080
export HTTPS_PROXY=http://127.0.0.1:8080
```

**TLS সীমাবদ্ধতা:** HTTPS `CONNECT` টানেলগুলো কেবল মেটাডেটা হিসেবে ক্যাপচার করা হয় (হোস্ট, পোর্ট, সময়)—ডিফল্টভাবে TLS বডি ডিক্রিপ্ট করা হয় না। সম্পূর্ণ বডি পরিদর্শনের জন্য "প্রক্সি মোডে HTTPS ডিক্রিপ্ট করুন" টগলটি চালু করুন (অপ্ট-ইন; AgentBridge সার্টিফিকেটটি বিশ্বস্ত হতে হবে)।

**পোর্ট দ্বন্দ্ব:** পোর্ট 8080 ব্যবহৃত অবস্থায় থাকলে AgentBridge একটি কাঠামোবদ্ধ ত্রুটিসহ 409 ফেরত দেয়। `INSPECTOR_HTTP_PROXY_PORT` এনভায়রনমেন্ট ভেরিয়েবলের মাধ্যমে পোর্ট পরিবর্তন করুন।

### মোড 4 — সিস্টেমব্যাপী প্রক্সি (উন্নত, অপ্ট-ইন)

**উৎস:** OS-স্তরের প্রক্সি সেটিংস (মেশিনের সব অ্যাপে প্রযোজ্য)
**কার্যপ্রণালি:** HTTP_PROXY লিসেনারের মধ্য দিয়ে সব HTTP/HTTPS ট্রাফিক রিডাইরেক্ট করতে OS API ব্যবহার করে:

- **macOS:** `networksetup -setwebproxy / -setsecurewebproxy`
- **Linux:** `gsettings set org.gnome.system.proxy` + `/etc/environment`
- **Windows:** `netsh winhttp set proxy 127.0.0.1:8080`
  **পরিধি:** মেশিনের যেসব অ্যাপ্লিকেশন সিস্টেম প্রক্সি সেটিংস অনুসরণ করে, সেগুলোর সবকটি
  **দ্রষ্টব্য:** `source` = `"system-proxy"`

**নিরাপত্তা ব্যবস্থা:**

- স্বয়ংক্রিয়ভাবে নিষ্ক্রিয় করার টাইমার (ডিফল্ট 30 মিনিট, `INSPECTOR_SYSTEM_PROXY_GUARD_MINUTES`-এর মাধ্যমে কনফিগারযোগ্য)
- পূর্ববর্তী সিস্টেম প্রক্সি অবস্থা DB-তে সংরক্ষিত হয় এবং প্রত্যাবর্তনের সময় পুনরুদ্ধার করা হয়
- এটি সক্রিয় থাকা অবস্থায় ব্যবহারকারী অন্যত্র নেভিগেট করলে ড্যাশবোর্ডে "সিস্টেম প্রক্সি পূর্বাবস্থায় ফেরানো হচ্ছে" প্রম্পট দেখানো হয়
- UI-তে `⚠ উন্নত` ব্যাজ + সুস্পষ্ট নিশ্চিতকরণ চেকবক্স দেখানো হয়

### মোড 5 — TPROXY স্বচ্ছ ডিক্রিপশন (Linux, root, অপ্ট-ইন)

**উৎস:** কার্নেল TPROXY + পলিসি রাউটিং (`src/mitm/tproxy/`)
**কার্যপ্রণালি:** `mangle OUTPUT`-এ একটি লক্ষ্য পোর্টে (ডিফল্ট `443`) নতুন স্থানীয় আউটবাউন্ড TCP সংযোগগুলো চিহ্নিত করে, একটি `ip rule` চিহ্নিত প্যাকেটগুলোকে স্থানীয় ডেলিভারিতে পুনরায় রাউট করে এবং `mangle PREROUTING`-এর `TPROXY` টার্গেট সেগুলোকে একটি স্বচ্ছ (**IP_TRANSPARENT**) লিসেনারের (ডিফল্ট পোর্ট `8443`) কাছে পাঠায়। লিসেনারটি একটি ডায়নামিক CA দ্বারা **প্রয়োজন অনুযায়ী প্রতিটি SNI হোস্টনেমের জন্য** ইস্যু করা লিফ সার্টিফিকেট দিয়ে TLS সমাপ্ত করে, ডিক্রিপ্ট করা আদান-প্রদান ক্যাপচার করে এবং অনুরোধটি পুনরায় এনক্রিপ্ট করে মূল গন্তব্যে ফরওয়ার্ড করে।
**পরিধি:** লক্ষ্য পোর্টে **যেকোনো** গন্তব্য হোস্ট—কোনো `/etc/hosts` স্পুফ, `HTTP_PROXY` এনভায়রনমেন্ট ভেরিয়েবল বা সিস্টেমব্যাপী প্রক্সি পরিবর্তন নেই। ইন্টারসেপ্ট করা প্রসেসটির কোনো কনফিগারেশন পরিবর্তনের প্রয়োজন নেই, তবে সেটিকে ডায়নামিক CA-কে বিশ্বাস করতে হবে।
**দ্রষ্টব্য:** `source` = `"tproxy"`

**প্রয়োজনীয়তা:** শুধু Linux (**IP_TRANSPARENT** কেবল Linux-এ উপলভ্য), **CAP_NET_ADMIN** ক্যাপাবিলিটি (root) এবং একটি নেটিভ N-API অ্যাডঅন, যা একটি C টুলচেইন দিয়ে বিল্ড করতে হবে (`npm run build:native:tproxy`)। এটি উপলভ্য না থাকলে ড্যাশবোর্ডের টগলটি নিষ্ক্রিয় থাকে এবং "TPROXY ডিক্রিপ্টের জন্য Linux + root + নেটিভ অ্যাডঅন প্রয়োজন" টুলটিপ দেখায়। ফায়ারওয়াল নিয়মগুলো লেনদেনমূলকভাবে প্রয়োগ/প্রত্যাবর্তন করা হয় (ক্র্যাশ হলেও কখনো কোনো `mangle` নিয়ম থেকে যায় না) এবং রিবুটের সময় সেগুলো মুছে যায়। একটি SO_MARK-ভিত্তিক অ্যান্টি-লুপ প্রক্সির নিজস্ব পুনরায় এনক্রিপ্ট করা ফরওয়ার্ডকে পুনরায় ইন্টারসেপ্ট হওয়া থেকে রক্ষা করে।

এটি নিজস্ব নিবেদিত অপারেটর নির্দেশিকাসহ একটি উল্লেখযোগ্য সাবসিস্টেম—সম্পূর্ণ ফায়ারওয়াল রেসিপি, প্রতি-SNI ডায়নামিক CA + ট্রাস্ট-স্টোর ইনস্টলার, শুধু-স্থানীয় রুট, অ্যান্টি-লুপের বিস্তারিত এবং কনফিগারেশন স্কিমার জন্য `docs/security/MITM-TPROXY-DECRYPT.md` দেখুন (git; `/docs`-এ কম্পাইল করা হয়নি)। টগলটি `GET / POST / DELETE /api/tools/agent-bridge/tproxy` দ্বারা নিয়ন্ত্রিত হয় (দ্রষ্টব্য: রুটটি Traffic Inspector প্রিফিক্সের অধীনে নয়, AgentBridge প্রিফিক্সের অধীনে অবস্থিত)।

## §4 LLM-সচেতন বৈশিষ্ট্যসমূহ

### 4.1 ধরন শনাক্তকারী (`src/mitm/inspector/kindDetector.ts`)

৪টি সংকেত ব্যবহার করে প্রতিটি অনুরোধকে `"llm"`, `"app"`, বা `"unknown"` হিসেবে শ্রেণিবদ্ধ করে:

1. **হোস্ট রেজিস্ট্রি** — ~১৮টি পরিচিত LLM API হোস্টনেম (OpenAI, Anthropic, Gemini, Groq, Mistral, Together, Fireworks, Cohere, Perplexity, Hugging Face, OpenRouter, xAI, Moonshot, ইত্যাদি)
2. **পাথ প্যাটার্ন** — `/v1/chat/completions`, `/v1/messages`, `/generateContent`, `/v1/responses`, ইত্যাদি
3. **বডির গঠন** — `messages[]` (OpenAI/Claude), `contents[]` (Gemini), `prompt`, `input` ফিল্ড শনাক্ত করে
4. **ইউজার-এজেন্ট সংকেত** — UA স্ট্রিংয়ে `codex`, `claude`, `gemini`, `antigravity`, `kiro`, `copilot`, `cursor`

Mode 2-এর মাধ্যমে যোগ করা কাস্টম হোস্টগুলো ফর্ম ইনপুট থেকে তাদের `kind` গ্রহণ করে (ডিফল্ট হলো `"custom"`)।

[Gemini](https://ai.google.dev/api/generate-content#method:-models.streamgeneratecontent)
স্ট্রিমিং স্কিমা।

কাঁচা SSE ডেল্টা ইভেন্ট থেকে চূড়ান্ত অ্যাসিস্ট্যান্ট বার্তাটি পুনর্গঠন করে:

- **Anthropic**: ইনডেক্স অনুযায়ী `content_block_delta` সঞ্চয় করে; `text_delta`, `input_json_delta` (টুল কল), `thinking_delta` পরিচালনা করে
- **OpenAI**: Chat Completions-এর চয়েস/টুল কল এবং Responses API-এর আউটপুট আইটেম ইনডেক্স অনুযায়ী সঞ্চয় করে
- **Gemini**: `candidates[i].content.parts` সঞ্চয় করে
- **Unknown**: কাঁচা ইভেন্টগুলো অপরিবর্তিত অবস্থায় ফেরত দেয়

Response ট্যাবে একটি টগল দেখানো হয়: **"Raw events ↔ Merged"**।

### 4.3 কথোপকথন নর্মালাইজার (`src/mitm/inspector/conversationNormalizer.ts`)

**স্বতন্ত্র ক্লিন-রুম বাস্তবায়ন।** নর্মালাইজেশন স্থানীয় ব্ল্যাক-বক্স
কনট্র্যাক্ট এবং সর্বজনীন OpenAI, Anthropic ও Gemini মেসেজ স্কিমা দ্বারা সংজ্ঞায়িত; কোনো আপস্ট্রিম
বাস্তবায়নের সোর্স ব্যবহার করা হয়নি।

রেন্ডার করার আগে OpenAI, Anthropic, এবং Gemini মেসেজ ফরম্যাটকে একটি একক `NormalizedConversation`-এ রূপান্তর করে:

```ts
interface NormalizedConversation {
  request: NormalizedTurn[]; // অনুরোধের বডি থেকে messages / contents / prompt
  response: NormalizedTurn[]; // অ্যাসিস্ট্যান্টের প্রতিক্রিয়া (sseMerger-এর মাধ্যমে মার্জ করা)
  contextKey: string | null; // SHA-256 সিস্টেম-প্রম্পট ফিঙ্গারপ্রিন্ট
}
```

ব্লকের ধরন: `text`, `tool_use`, `tool_result`। প্রোভাইডার নির্বিশেষে Conversation ট্যাব এই গঠন ব্যবহার করে।

### 4.4 কনটেক্সট কী-এর রঙায়ন (`src/mitm/inspector/contextKey.ts`)

- সিস্টেম প্রম্পটের `SHA-256` গণনা করে (প্রথম `role:system` মেসেজ, অথবা `system` ফিল্ড, অথবা Gemini `systemInstruction`)
- ১২-অক্ষরের একটি হেক্স প্রিফিক্স ফেরত দেয় (`"a3f9c2..."`)
- বাম-বর্ডার বারের জন্য ফ্রন্টএন্ড কীটিকে একটি নির্ধারিত HSL রঙে ম্যাপ করে
- **"একই কনটেক্সট" ফিল্টার**: `ctx #a3f` চিপে ক্লিক করলে শুধুমাত্র একই ফিঙ্গারপ্রিন্টযুক্ত অনুরোধ দেখানোর জন্য একটি ফিল্টার যোগ হয়

এর ফলে একই এজেন্ট সেশনে চলমান বিভিন্ন "পারসোনা" বা কাজকে দৃশ্যত সহজে আলাদা করা যায়।

### 4.5 LLM মেটাডেটা নিষ্কাশন

LLM অনুরোধের ক্ষেত্রে, LLM Details ট্যাব যা নিষ্কাশন করে:

```ts
interface LlmMetadata {
  provider: string | null; // "openai" | "anthropic" | "gemini" | ...
  apiKind: string | null; // "chat.completions" | "messages" | "embeddings" | ...
  model: string | null; // অনুরোধের বডি বা প্রতিক্রিয়া থেকে
  messages: number; // টার্নের সংখ্যা
  tokensIn: number | null; // usage.prompt_tokens / usage.input_tokens
  tokensOut: number | null; // usage.completion_tokens / usage.output_tokens
  streamed: boolean; // SSE প্রতিক্রিয়া হলে true
  mappedTo: string | null; // x-omniroute-mapped হেডার
  costEstimateUsd: number | null; // OmniRoute-এর মূল্য নির্ধারণের ভিত্তিতে আনুমানিক খরচ
}
```

### 4.6 লাইভ চলমান অনুরোধের ফিল্টার

অনুরোধের `status` ফিল্ড হলো `number | "in-flight" | "error"` — অনুরোধ শুরু হওয়ার সঙ্গে সঙ্গেই একটি এন্ট্রি
`"in-flight"` হিসেবে যোগ করা হয় এবং প্রতিক্রিয়া (বা ত্রুটি) এলে সেটি **সেখানেই আপডেট করা হয়**।
টুলবারের **"Live"** টগল
(`liveOnly`, i18n কী `trafficInspector.liveOnly`) তালিকাটিকে শুধু সেইসব এন্ট্রিতে
সীমাবদ্ধ করে যেগুলোর `status === "in-flight"`, ফলে আপনি রিয়েল টাইমে খোলা কানেকশন পর্যবেক্ষণ করতে পারেন।

ফিল্টারটি
`src/lib/inspector/matchesTrafficFilter.ts`-এ থাকা একটি বিশুদ্ধ, ক্লায়েন্ট-সাইড প্রেডিকেট:

```ts
if (f.liveOnly && req.status !== "in-flight") return false;
```

টগলের অবস্থা `useTrafficFilters`-এ থাকে (ইন্সপেক্টর ড্যাশবোর্ড হুকসমূহ) এবং
অন্যান্য ফিল্টারের (প্রোফাইল, হোস্ট, এজেন্ট, সোর্স, স্ট্যাটাস, কনটেক্সট) সঙ্গে সমন্বিত হয়।

### 4.7 প্রসেস অ্যাট্রিবিউশন (Linux)

Linux-এ, প্রতিটি ইন্টারসেপ্ট করা অনুরোধকে **উৎস স্থানীয়
প্রসেসের** সঙ্গে সম্পর্কিত করা যায়। `InterceptedRequest`-এ দুটি ঐচ্ছিক ফিল্ড যোগ করা হয়েছে:

```ts
pid?: number;          // উৎস প্রসেস আইডি (শুধু Linux)
processName?: string;  // উৎস প্রসেসের নাম (শুধু Linux)
```

`src/mitm/inspector/processAttribution.ts` কানেকশনের _ক্লায়েন্ট_
এফিমেরাল পোর্টকে একটি PID + নামের সঙ্গে এভাবে ম্যাপ করে:

1. পোর্টটির সকেট inode খুঁজতে `/proc/net/tcp` এবং `/proc/net/tcp6` পড়ে
   (`parseProcNetTcpForInode`, একটি বিশুদ্ধ ফিক্সচার-পরীক্ষাযোগ্য পার্সার)।
2. `socket:[<inode>]`-এর প্রতি নির্দেশকারী একটি সিমলিংকের জন্য `/proc/<pid>/fd/` স্ক্যান করে।
3. `/proc/<pid>/comm` থেকে প্রসেসের নাম পড়ে।

১-সেকেন্ডের TTL ক্যাশ লোডের অধীনে procfs স্ক্যানের খরচ সীমিত রাখে। অ্যাট্রিবিউশন
**সর্বোচ্চ প্রচেষ্টাভিত্তিক** — যেকোনো ব্যর্থতায় ফলাফল `null` হয় এবং ক্যাপচার কখনো ব্লক করে না।
macOS/Windows-এ ফাংশনটি `null` ফেরত দেয় (স্টাব; `lsof`/`GetExtendedTcpTable`
সমর্থন ভবিষ্যতে যোগ করা হবে)।

## §5 সেশনসমূহ

### 5.1 একটি সেশন রেকর্ড করা

1. টুলবারে **"● সেশন রেকর্ড করুন"**-এ ক্লিক করুন → একটি নাম লিখুন (ঐচ্ছিক)
2. লাইভ টেইল স্বাভাবিকভাবে চলতে থাকে; একটি লাল স্পন্দিত সূচক দেখায় `◉ REC · <name> · 00:42 · 23টি অনুরোধ`
3. **"⏹ থামান"**-এ ক্লিক করুন → সেশন স্ন্যাপশটটি `inspector_sessions` + `inspector_session_requests`-এ সংরক্ষিত হয়

### 5.2 রেকর্ড করা সেশন দেখা

টুলবারের **সেশনসমূহ** ড্রপডাউনে সংরক্ষিত সেশনগুলোর তালিকা থাকে। একটি নির্বাচন করলে:

- সেশনটির স্ন্যাপশট লোড হয় (স্থির অবস্থা)
- একটি ব্যানারে দেখায়: `রেকর্ড করা সেশন "<name>" দেখা হচ্ছে — [লাইভে ফিরে যান]`
- Recharts-এর সমষ্টিগত উপাত্তসহ পরিসংখ্যান ট্যাবটি উপলভ্য হয়

### 5.3 এক্সপোর্ট ফরম্যাট

প্রতিটি সেশন নিম্নলিখিত ফরম্যাটে এক্সপোর্ট করা যায়:

| ফরম্যাট                    | ব্যবহার                                                                                         |
| -------------------------- | ----------------------------------------------------------------------------------------------- |
| **HAR** (HTTP Archive 1.2) | Chrome DevTools, Charles, Fiddler-এর সঙ্গে সামঞ্জস্যপূর্ণ — অফলাইন বিশ্লেষণের জন্য ইমপোর্ট করুন |
| **JSONL**                  | প্রতি লাইনে একটি `InterceptedRequest` — `llm-interceptor` ফরম্যাটের সঙ্গে সামঞ্জস্যপূর্ণ        |

`GET /api/tools/traffic-inspector/sessions/{id}/export.har` অথবা সেশনসমূহ ড্রপডাউনের ⬇ বোতামের মাধ্যমে এক্সপোর্ট করুন।

## §6 নিরাপত্তা

Traffic Inspector অনুমোদন হেডার ও অনুরোধের বডিসহ **ইন্টারসেপ্ট করা সব HTTPS ট্রাফিক** দেখায়। নিম্নলিখিত নিয়ন্ত্রণগুলো কার্যকর রয়েছে:

| নিয়ন্ত্রণ                              | বিস্তারিত                                                                                                                                                                             |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LOCAL_ONLY**                          | সব রুট ও WebSocket এন্ডপয়েন্ট কেবল লুপব্যাকে সীমাবদ্ধ (auth-এর আগে `routeGuard.ts`-এ প্রয়োগ করা হয়)                                                                                |
| **গোপন তথ্য মাস্কিং**                   | লিনিয়ার `maskSecret()` স্ক্যানার `TrafficBuffer.push()`-এর আগে RFC 6750 Bearer ক্রেডেনশিয়াল, প্রদানকারী-প্রিফিক্সযুক্ত কী এবং দীর্ঘ অস্বচ্ছ টোকেন অপসারণ করে                        |
| **বডির আকারসীমা**                       | `INSPECTOR_MAX_BODY_KB`-এর (ডিফল্ট 1024 KB) চেয়ে বড় বডিগুলো `"(কর্মক্ষমতার জন্য সংক্ষিপ্ত করা হয়েছে)"` বিজ্ঞপ্তিসহ সংক্ষিপ্ত করা হয়                                               |
| **হেডার স্যানিটাইজেশন**                 | নামগুলো ছোট হাতের অক্ষরে রূপান্তরিত হয়; ফ্রেমিং/হপ-বাই-হপ ও প্রক্সি-auth হেডার বাদ দেওয়া হয়; কুকি সম্পূর্ণ অপসারণ করা হয়; ক্রেডেনশিয়াল মানগুলো `maskSecret()`-এর কাছে ন্যস্ত হয় |
| **CSP**                                 | ইনজেক্ট করা রেসপন্স বডির মাধ্যমে XSS প্রতিরোধে Traffic Inspector পৃষ্ঠাগুলোতে কঠোর Content Security Policy                                                                            |
| **ডিফল্টভাবে কোনো স্থায়ী সংরক্ষণ নেই** | `TrafficBuffer` মেমরিতে থাকে এবং সার্ভার পুনরায় চালু হলে হারিয়ে যায়। সেশনগুলো কেবল স্পষ্টভাবে রেকর্ড করা হলেই স্থায়ীভাবে সংরক্ষিত হয়                                             |

### প্রয়োগ করা কঠোর নিয়ম

| নিয়ম                             | প্রয়োগ                                                                                 |
| --------------------------------- | --------------------------------------------------------------------------------------- |
| **#12** `sanitizeErrorMessage`    | Traffic Inspector রুটগুলো থেকে আসা সব HTTP ত্রুটি-রেসপন্স স্যানিটাইজ করা হয়            |

### পরিচিত সীমাবদ্ধতা

- **সিস্টেমব্যাপী প্রক্সি মোড** VPN ক্লায়েন্ট ও SSO-সহ মেশিনের সব অ্যাপ্লিকেশনকে প্রভাবিত করে। সবসময় স্বয়ংক্রিয়-নিষ্ক্রিয়করণ টাইমারের সঙ্গে ব্যবহার করুন। শেয়ার করা মেশিনে ব্যবহার করবেন না।
- **CONNECT টানেল HTTPS**: TLS ইন্টারসেপশন সক্রিয় না থাকলে মোড 3 (HTTP_PROXY) HTTPS গন্তব্যের জন্য কেবল টানেলের মেটাডেটা ধারণ করে। এটি পরিকল্পিত আচরণ — AgentBridge cert বিশ্বস্ত না হলে স্বচ্ছ ক্যাপচার ওই অ্যাপগুলোর TLS যাচাইকরণ ব্যাহত করবে।
- **কিছু কম্পোনেন্টে হার্ডকোড করা স্ট্রিং**: কিছু UI কম্পোনেন্টে (F7/F8) অল্প কয়েকটি হার্ডকোড করা স্ট্রিং রয়েছে, যেগুলো এখনো i18n কী দ্বারা অন্তর্ভুক্ত নয়। এগুলো i18n ব্যবধান প্রতিবেদনে পরিচিত সীমাবদ্ধতা হিসেবে নথিভুক্ত; পরবর্তী ধাপে এগুলো স্থানান্তর করা হবে। প্রভাবিত স্ট্রিংগুলো UI-এর অলংকারমূলক লেবেল, যেগুলোর কার্যকরী ব্যবহারের জন্য অনুবাদ প্রয়োজন হয় না।

## §7 সমস্যা সমাধান

### WebSocket সংযোগ বিচ্ছিন্ন হওয়া

লাইভ টেইলে "সংযোগ বিচ্ছিন্ন" দেখালে:

1. সার্ভারটি এখনও চলছে কি না পরীক্ষা করুন: `GET /api/tools/traffic-inspector/capture-modes`
2. পৃষ্ঠাটি পুনরায় লোড করুন — WebSocket পুনরায় সংযুক্ত হবে এবং একটি নতুন স্ন্যাপশট গ্রহণ করবে
3. সার্ভারটি পুনরায় চালু করা হয়ে থাকলে, ইন-মেমরি বাফার সাফ হয়ে গেছে — কোনো সেশন রেকর্ড করা না থাকলে পুরোনো এন্ট্রিগুলো আর পাওয়া যাবে না

### পোর্ট 8080-এর দ্বন্দ্ব

HTTP_PROXY মোড চালু হতে ব্যর্থ হলে:

```bash
lsof -i :8080    # প্রসেসটি খুঁজুন
```

পোর্ট পরিবর্তন করুন:

```bash
# .env
INSPECTOR_HTTP_PROXY_PORT=8888
```

### সিস্টেম প্রক্সি পূর্বাবস্থায় ফেরেনি

সিস্টেম-ব্যাপী প্রক্সি মোড সক্রিয় থাকা অবস্থায় OmniRoute ক্র্যাশ করলে:

**macOS:**

```bash
networksetup -setwebproxystate Wi-Fi off
networksetup -setsecurewebproxystate Wi-Fi off
```

**Linux (GNOME):**

```bash
gsettings set org.gnome.system.proxy mode 'none'
```

**Windows:**

```cmd
netsh winhttp reset proxy
```

পরবর্তীবার লোড হওয়ার সময় DB-এর অবস্থা থেকে প্রক্সি সক্রিয় ছিল বলে শনাক্ত করলে ড্যাশবোর্ডটি "সিস্টেম প্রক্সি পূর্বাবস্থায় ফেরান" বিকল্পও দেখাবে।

### বাফার পূর্ণ

বাফারটি `INSPECTOR_BUFFER_SIZE`-এ (ডিফল্ট 1000) পৌঁছালে, নতুন এন্ট্রি যোগ হওয়ার সঙ্গে সঙ্গে সবচেয়ে পুরোনো এন্ট্রিগুলো বাদ পড়ে। গুরুত্বপূর্ণ অনুরোধ হারিয়ে গেলে:

- `INSPECTOR_BUFFER_SIZE` বাড়ান (যেমন, 5000) — এতে বেশি সময় ধরে ডেটা রাখা যাবে, তবে বেশি মেমরি ব্যবহৃত হবে
- প্রাসঙ্গিক সময়সীমার ডেটা DB-তে সংরক্ষণ করতে একটি সেশন রেকর্ড করুন

## §8 API রেফারেন্স

সব রুটই `LOCAL_ONLY` (শুধু লুপব্যাক) এবং `SPAWN_CAPABLE` (সিস্টেম প্রক্সি কমান্ড)। `src/server/authz/routeGuard.ts` দেখুন।

বেস পাথ: `/api/tools/traffic-inspector/`

### অনুরোধ ব্যবস্থাপনা

| মেথড   | পাথ                         | বিবরণ                                                                                         |
| ------ | --------------------------- | --------------------------------------------------------------------------------------------- |
| GET    | `/requests`                 | অনুরোধের তালিকা দেখায় (ফিল্টারযোগ্য: `?profile=llm&host=&agent=&status=&source=&sessionId=`) |
| GET    | `/requests/{id}`            | একটি অনুরোধের বিস্তারিত তথ্য                                                                  |
| DELETE | `/requests`                 | ইন-মেমরি বাফার সাফ করে                                                                        |
| POST   | `/requests/{id}/replay`     | OmniRoute রাউটারের মাধ্যমে একই অনুরোধ পুনরায় কার্যকর করে                                     |
| PUT    | `/requests/{id}/annotation` | কোনো অনুরোধের নোট সংরক্ষণ বা হালনাগাদ করে                                                     |

| ------ | --------------- | ---------------------------------------------------------- |

### ক্যাপচার মোড

| মেথড | পাথ                            | বিবরণ                                                                                          |
| ---- | ------------------------------ | ---------------------------------------------------------------------------------------------- |
| GET  | `/capture-modes`               | AgentBridge / কাস্টম-হোস্ট / HTTP_PROXY / সিস্টেম-প্রক্সি মোড এবং `tls-intercept` টগলের অবস্থা |
| POST | `/capture-modes/http-proxy`    | HTTP_PROXY লিসেনার চালু/বন্ধ করে (`{action: "start"\|"stop"}`)                                 |
| POST | `/capture-modes/system-proxy`  | সিস্টেম-ব্যাপী প্রক্সি প্রয়োগ/পূর্বাবস্থায় ফেরায় (`{action: "apply"\|"revert"}`)            |
| POST | `/capture-modes/tls-intercept` | প্রক্সি মোডে HTTPS বডি ডিক্রিপশন টগল করে (`{enabled: boolean}`)                                |

> **TPROXY ডিক্রিপ্ট** (ক্যাপচার মোড 5) AgentBridge প্রিফিক্সের অধীনে একটি **আলাদা** রুট দ্বারা
> পরিচালিত হয় — `GET / POST / DELETE /api/tools/agent-bridge/tproxy` — এটি
> `/api/tools/traffic-inspector/`-এর অধীনে নয়। দেখুন
> `docs/security/MITM-TPROXY-DECRYPT.md` (git; `/docs`-এ কম্পাইল করা হয়নি)।
