## এটি কী

Local Corpus একজন অপারেটরকে টেক্সট ফাইলের একটি সুস্পষ্টভাবে অনুমোদিত ডিরেক্টরি
OmniRoute-এর MCP সার্ভারের কাছে উন্মুক্ত করতে দেয়। ফাইলগুলো তাদের মূল ডিরেক্টরিতেই থাকে:
OmniRoute শুধু ক্যানোনিক্যাল রুট পাথটি SQLite-এ সংরক্ষণ করে এবং একটি ইন-মেমরি সার্চ ইনডেক্স
রক্ষণাবেক্ষণ করে। এটি করপাসের কনটেন্ট রিপোজিটরি বা ডেটাবেসে কপি করে না।

ইনডেক্স রিফ্রেশ ক্রমবর্ধমানভাবে সম্পন্ন হয়। অপরিবর্তিত ফাইলগুলো আকার ও পরিবর্তনের
সময়ের ভিত্তিতে পুনঃব্যবহার করা হয়, পরিবর্তিত ফাইলগুলো পুনরায় পড়ে SHA-256 দিয়ে হ্যাশ
করা হয়, এবং মুছে ফেলা ফাইলগুলো সরিয়ে দেওয়া হয়। সার্চের সময় 30 সেকেন্ডের বেশি পুরোনো
ইনডেক্স রিফ্রেশ করা হয়; কলকারীরাও তাৎক্ষণিক রিফ্রেশের অনুরোধ করতে পারেন।

## উৎস কনফিগার করুন

সেটিংস রুটের জন্য অন্যান্য সেটিংস API-এর মতো একই ম্যানেজমেন্ট প্রমাণীকরণ প্রয়োজন।
জমা দেওয়া পাথটি আগে থেকেই বিদ্যমান হতে হবে এবং অবশ্যই একটি অ্যাবসোলিউট ডিরেক্টরি পাথ
হতে হবে।

```bash
# একটি অনুমোদিত ডিরেক্টরি সংযুক্ত করুন
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# কনফিগারেশন ও ইনডেক্সের স্থিতি পরীক্ষা করুন
curl http://localhost:20128/api/settings/local-corpus

# উৎস ফাইল পরিবর্তন না করে সংযোগ বিচ্ছিন্ন করুন
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## MCP টুল

তিনটি টুলের প্রতিটির জন্যই `read:local-corpus` প্রয়োজন। টুলের প্রতিক্রিয়ায় রিলেটিভ পাথ
এবং রুট ডিরেক্টরির basename প্রকাশ করা হয়, কখনোই এর অ্যাবসোলিউট পাথ নয়।

| টুল                   | বিবরণ                                                                                               |
| :-------------------- | :-------------------------------------------------------------------------------------------------- |
| `local_corpus_status` | কনফিগারেশনের অবস্থা, ইনডেক্সের আকার, সীমা এবং সর্বশেষ রিফ্রেশের সময় জানায়                         |
| `local_corpus_search` | ইনডেক্স করা টেক্সট অনুসন্ধান করে এবং সীমাবদ্ধ, লাইন-ভিত্তিক স্নিপেট ফেরত দেয় (সর্বোচ্চ 20টি ফলাফল) |
| `local_corpus_read`   | অনুমোদিত একটি করপাস-রিলেটিভ ফাইল থেকে সীমাবদ্ধ লাইন পরিসর পড়ে                                      |

MCP ইনপুটের উদাহরণ:

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## নিরাপত্তার সীমা

- অনুমোদন-তালিকাটি টেক্সট-কেন্দ্রিক: `.cfg`, `.csv`, `.geojson`, `.htm`, `.html`, `.ini`,
  `.js`, `.json`, `.jsonl`, `.jsx`, `.log`, `.md`, `.mjs`, `.ps1`, `.py`, `.sh`,
  `.sql`, `.toml`, `.ts`, `.tsx`, `.txt`, `.xml`, `.yaml`, এবং `.yml`।
- Symlink এড়িয়ে যাওয়া হয়। পড়ার পাথগুলো ক্যানোনিক্যালাইজ করা হয় এবং সেগুলোকে অবশ্যই
  কনফিগার করা রুটের ভেতরে থাকতে হবে; অ্যাবসোলিউট পাথ ও ট্রাভার্সাল প্রচেষ্টা প্রত্যাখ্যান করা হয়।
- সংবেদনশীল ও জেনারেট করা ডিরেক্টরির নামগুলো বাদ দেওয়া হয়: `.build`, `.codex`, `.env`,
  `.git`, `.next`, `.omniroute`, `.ssh`, `coverage`, `dist`, `node_modules`, এবং
  `secrets`।
- ডিফল্ট সীমা হলো 5,000টি ফাইল, প্রতি ফাইলে 1 MiB, মোট 64 MiB ইনডেক্স করা কনটেন্ট,
  প্রতি সার্চ চাঙ্কে আনুমানিক 4,000টি অক্ষর এবং প্রতি পঠনে 400টি লাইন।
- NUL-সম্বলিত ফাইলগুলোকে নন-টেক্সট হিসেবে গণ্য করে এড়িয়ে যাওয়া বা প্রত্যাখ্যান করা হয়।

PDF, DOCX, ছবি এবং আর্কাইভের মতো বাইনারি ডকুমেন্ট ইচ্ছাকৃতভাবে সমর্থিত নয়।
ইনডেক্স করার আগে কনফিগার করা ডিরেক্টরিতে এগুলোকে অনুমোদিত কোনো টেক্সট ফরম্যাটে রূপান্তর করুন।

## পরিচালনাসংক্রান্ত নোট

- কনফিগার করা রুট পরিবর্তন বা মুছে ফেললে শেয়ার করা ইন-মেমরি ইনডেক্স সাফ হয়ে যায়।
- কোনো প্রসেস পুনরায় চালু হলে ইনডেক্সটি বাতিল হয়ে যায়; পরবর্তী সার্চ কনফিগার করা
  উৎস থেকে এটি পুনর্নির্মাণ করে।
- `local_corpus_status` জোরপূর্বক স্ক্যান করায় না। তাৎক্ষণিক পুনঃস্ক্যানের প্রয়োজন হলে
  `refresh: true` সহ `local_corpus_search` ব্যবহার করুন।
- স্ক্যান ও পঠনের ব্যর্থতা গণনা করা হয় অথবা স্যানিটাইজ করা ত্রুটি হিসেবে ফেরত দেওয়া হয়;
  উৎস ফাইলগুলো কখনো পরিবর্তন করা হয় না।
