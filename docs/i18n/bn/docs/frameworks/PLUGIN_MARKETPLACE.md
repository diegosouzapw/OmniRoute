> **সত্যের উৎস:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/`, এবং
> `src/app/(dashboard)/dashboard/plugins/`
> **সর্বশেষ হালনাগাদ:** 2026-06-28 — v3.8.40

OmniRoute একটি WordPress-ধাঁচের প্লাগইন সিস্টেমসহ আসে। প্লাগইনগুলো স্বয়ংসম্পূর্ণ
ডিরেক্টরি — প্রতিটিতে একটি `plugin.json` ম্যানিফেস্ট এবং একটি এন্ট্রি ফাইল থাকে — যা
রিকোয়েস্ট পাইপলাইন (`onRequest` / `onResponse` / `onError`) এবং
লাইফসাইকেল ইভেন্টগুলোতে (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`)
হুক করে।

**Plugin Marketplace** হলো ওই সিস্টেমের ওপর নির্মিত ডিসকভারি স্তর। এটি
ইনস্টলযোগ্য প্লাগইনগুলোর একটি ব্রাউজযোগ্য ক্যাটালগ প্রকাশ করে। ডিফল্টভাবে ক্যাটালগটি
একটি ছোট বিল্ট-ইন সিড রেজিস্ট্রি; কোনো অপারেটর এটিকে একটি কাস্টম রিমোট
রেজিস্ট্রি URL-এর দিকে নির্দেশ করতে পারেন, সে ক্ষেত্রে ফেচটি DNS-রিজলভিং SSRF গার্ড
দ্বারা সুরক্ষিত করা হয় ([নিরাপত্তা](#security) দেখুন)।

প্রতিটি প্লাগইন রুট **শুধু লুপব্যাকের জন্য** (Tier 1 — `LOCAL_ONLY`): প্লাগইনগুলো
চাইল্ড প্রসেসে কোড লোড ও এক্সিকিউট করে, তাই অথ নির্বিশেষে নন-লুপব্যাক
অরিজিন থেকে রুটগুলোতে পৌঁছানো যায় না। দেখুন
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md)।

## এটি কীভাবে একসঙ্গে কাজ করে

```
ড্যাশবোর্ড (/dashboard/plugins)
  ├─ "ইনস্টল করা" ট্যাব → GET /api/plugins            (listPlugins)
  │                       POST /api/plugins/scan      (pluginManager.scan)
  │                       POST /api/plugins/{name}/activate|deactivate
  │                       DELETE /api/plugins/{name}   (আনইনস্টল)
  └─ "মার্কেটপ্লেস" ট্যাব → GET /api/plugins/marketplace
                             → listMarketplacePlugins()
                               ├─ কোনো কাস্টম URL নেই → বিল্ট-ইন SEED_REGISTRY
                               └─ কাস্টম URL → isSafeMarketplaceUrl() SSRF গার্ড
                                             → safeOutboundFetch(guard:"public-only")
```

- **রেজিস্ট্রি স্তর** — `src/lib/plugins/marketplace.ts`: ক্যাটালগ তালিকাভুক্ত /
  অনুসন্ধান করে এবং যেকোনো ব্যর্থতায় সিড রেজিস্ট্রিতে ফিরে যায়।
- **লাইফসাইকেল স্তর** — `src/lib/plugins/manager.ts` (`pluginManager` সিঙ্গেলটন):
  ইনস্টল, আপগ্রেড, সক্রিয়করণ, নিষ্ক্রিয়করণ, আনইনস্টল, স্ক্যান এবং স্টার্টআপে লোড।
- **ম্যানিফেস্ট স্তর** — `src/lib/plugins/manifest.ts`: `plugin.json`-এর জন্য
  Zod স্কিমা + ডিফল্ট।
- **স্ক্যানার** — `src/lib/plugins/scanner.ts`: প্লাগইন ডিরেক্টরির অধীনে
  ডিস্কে থাকা প্লাগইনগুলো শনাক্ত করে।
- **লোডার** — `src/lib/plugins/loader.ts`: প্রতিটি প্লাগইনকে একটি বিচ্ছিন্ন
  চাইল্ড প্রসেসে চালু করে এবং IPC-এর মাধ্যমে হুক কলগুলোর মধ্যস্থতা করে।

## মার্কেটপ্লেস ক্যাটালগ

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) `MarketplaceEntry`
অবজেক্টগুলোর একটি তালিকা ফেরত দেয়:

| ফিল্ড         | ধরন      | নোট                                     |
| ------------- | -------- | --------------------------------------- |
| `name`        | string   | kebab-case প্লাগইনের নাম                |
| `version`     | string   | semver                                  |
| `description` | string   | সংক্ষিপ্ত সারাংশ                        |
| `author`      | string   | লেখক / সংস্থা                           |
| `license`     | string   | SPDX-ধাঁচের লাইসেন্স আইডি               |
| `downloadUrl` | string   | সোর্স ডাউনলোড URL (খালি হতে পারে)       |
| `repository`  | string?  | ঐচ্ছিক রিপোজিটরি URL                    |
| `tags`        | string[] | অনুসন্ধান/ফিল্টারের ট্যাগ               |
| `downloads`   | number   | ডাউনলোডের সংখ্যা                        |
| `rating`      | number   | 0–5                                     |
| `verified`    | boolean  | এন্ট্রিটি যাচাইকৃত হিসেবে চিহ্নিত কি না |
| `lastUpdated` | string   | ISO-সদৃশ তারিখের স্ট্রিং                |

কোনো কাস্টম রেজিস্ট্রি URL কনফিগার করা না থাকলে, ক্যাটালগটি বিল্ট-ইন
`SEED_REGISTRY` (বর্তমানে `request-logger`, `rate-limiter`, `cost-tracker`, এবং
`theme-manager`) ব্যবহার করে। সিড রেজিস্ট্রি সর্বদা উপলভ্য — কনফিগার করা কোনো রিমোট
রেজিস্ট্রিতে পৌঁছানো না গেলে, সেটি নন-`200` স্ট্যাটাস ফেরত দিলে, অথবা অপরিচিত
বডি ফেরত দিলে, `listMarketplacePlugins()` একটি সতর্কতা লগ করে এবং সিড তালিকায়
ফিরে যায়।

> দ্রষ্টব্য: মার্কেটপ্লেস **ক্যাটালগ** (ব্রাউজ/অনুসন্ধান) শুরু থেকে শেষ পর্যন্ত সংযুক্ত,
> তবে ক্যাটালগ থেকে এক ক্লিকে মার্কেটপ্লেস **ইনস্টল** এখনো বাস্তবায়িত হয়নি —
> মার্কেটপ্লেস এন্ট্রিতে ড্যাশবোর্ডের "ইনস্টল" বোতামটি বর্তমানে একটি
> "শিগগিরই আসছে" বিজ্ঞপ্তি দেখায়। বর্তমানে ইনস্টলেশন লোকাল-পাথ ইনস্টল
> ফ্লো (`POST /api/plugins`) এবং অন-ডিস্ক ডিসকভারি (`POST /api/plugins/scan`)-এর
> মাধ্যমে সম্পন্ন হয়।

## REST API

সব endpoint-এর জন্য management auth (`requireManagementAuth`) **আবশ্যক** এবং এগুলো
শুধুমাত্র loopback থেকে অ্যাক্সেসযোগ্য — `/api/plugins` ও `/api/plugins/`
`LOCAL_ONLY_API_PREFIXES`-এ (`src/server/authz/routeGuard.ts`) তালিকাভুক্ত রয়েছে।

| Endpoint                         | Method | বিবরণ                                                             |
| -------------------------------- | ------ | ----------------------------------------------------------------- |
| `/api/plugins`                   | GET    | ইনস্টল করা plugin-এর তালিকা (ঐচ্ছিক `?status=` filter)            |
| `/api/plugins`                   | POST   | একটি absolute local path থেকে plugin ইনস্টল করা                   |
| `/api/plugins/scan`              | POST   | plugin directory scan করে নতুন plugin নিবন্ধন করা                 |
| `/api/plugins/marketplace`       | GET    | marketplace catalog entry-এর তালিকা                               |
| `/api/plugins/[name]`            | GET    | ইনস্টল করা plugin-এর বিস্তারিত তথ্য নেওয়া                        |
| `/api/plugins/[name]`            | DELETE | একটি plugin আনইনস্টল করা                                          |
| `/api/plugins/[name]/activate`   | POST   | সক্রিয় করা (load + hook নিবন্ধন)                                 |
| `/api/plugins/[name]/deactivate` | POST   | নিষ্ক্রিয় করা (`onDeactivate` চালানো, hook-এর নিবন্ধন বাতিল করা) |
| `/api/plugins/[name]/config`     | GET    | plugin config + config schema নেওয়া                              |
| `/api/plugins/[name]/config`     | PUT    | plugin config আপডেট করা (schema-এর বিপরীতে যাচাইকৃত)              |

`GET /api/plugins`-এর `status` filter নিচের যেকোনো একটি মান গ্রহণ করে:
`installed` / `active` / `inactive` / `error`। অবৈধ মান দিলে `400` ফেরত আসে।

### ইনস্টল করা plugin-এর তালিকা

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### একটি local path থেকে ইনস্টল করা

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` অবশ্যই **absolute** হতে হবে এবং এতে `..` traversal segment বা
null byte থাকতে পারবে না (Zod দ্বারা বলবৎ করা হয়)। source directory-তে অবশ্যই
একটি বৈধ `plugin.json` থাকতে হবে (অথবা directory-টি এমন একটির parent হতে হবে)।
সফল হলে response-এ ইনস্টল করা plugin row-সহ `201` ফেরত আসে।

### marketplace ব্রাউজ করা

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### plugin config আপডেট করা

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` plugin-এর `configSchema`-এর (manifest-এ ঘোষিত) বিপরীতে দেওয়া
প্রতিটি মান যাচাই করে: `number` field-গুলো `min`/`max` মেনে চলে এবং `select`
field-গুলো অবশ্যই ঘোষিত `enum`-এর সঙ্গে মিলতে হবে। schema-তে অনুপস্থিত key-গুলো
অনুমোদিত হয়।

## কনফিগারেশন

### Plugin directory

Plugin-গুলো OmniRoute data directory-এর অধীনে থাকে:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (অথবা manifest.main যে ফাইলকে নির্দেশ করে)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) তিনটি ধাপে ওই directory
নির্ধারণ করে:

1. **`OMNIROUTE_PLUGINS_DIR`**, সেট করা থাকলে — `HOME`-এর মান যা-ই হোক না কেন, এটি
   হুবহু ব্যবহার করা হয়। Docker/K8s-এর জন্য এটি সুস্পষ্ট নিয়ন্ত্রণব্যবস্থা, যেখানে
   plugin tree এমন একটি path-এ bind-mounted থাকে, যার সঙ্গে সাধারণত container-এর home
   directory-এর কোনো সম্পর্ক নেই (#11827)।
2. `<home>/.omniroute/plugins`, যেখানে `<home>` নেওয়া হয় `HOME` / `USERPROFILE`
   environment variable থেকে।
3. `/tmp/.omniroute/plugins`, যখন process থেকে কোনো home-ই export করা হয় না।

নির্ধারিত directory-টি startup-এর সময় একবার `scanner.dir_resolved` হিসেবে log করা
হয় এবং কোন input প্রাধান্য পেয়েছে (`OMNIROUTE_PLUGINS_DIR`, `home`, অথবা
`no-home-fallback`) তা উল্লেখ করা হয় — ফলে কোনো image নিঃশব্দে ধাপ 3-এ পৌঁছালে,
শুধু একটি খালি plugin list দেখানোর বদলে সেটি তা জানায়।
`POST /api/plugins/scan` সেখানে থাকা বৈধ `plugin.json`-সহ যেকোনো subdirectory
খুঁজে বের করে এবং সেটি নিবন্ধন করে; একই directory হলো সেই root যেখানে
`pluginManager.install()` plugin copy করে, ফলে override করলে discovery ও
installation উভয়ই একসঙ্গে স্থানান্তরিত হয়।

> **`OMNIROUTE_PLUGINS_DIR`, `OMNIROUTE_PLUGIN_PATH` নয়।** পরেরটি কেবল CLI
> command-plugin loader (`bin/cli/plugins.mjs`) পড়ে, যাতে `omniroute-cmd-*` npm
> package খুঁজে পাওয়া যায়, যেগুলো `omniroute` subcommand যোগ করে — এখানে বর্ণিত
> runtime scanner-এর ওপর এর কোনো প্রভাব নেই। ওই দিকটি সম্পর্কে জানতে
> [PLUGINS.md](./PLUGINS.md) দেখুন।

### Custom marketplace registry URL

Marketplace catalog-এর source `pluginMarketplaceUrl` setting থেকে পড়া হয়
(`src/lib/plugins/marketplace.ts`, `settings.pluginMarketplaceUrl` পড়ে)। এটি
একটি `http(s)` URL-এ সেট করা থাকলে `listMarketplacePlugins()` সেই URL fetch করে
এবং entry-এর top-level JSON array অথবা `plugins` array-সহ একটি object গ্রহণ করে;
string `name` ছাড়া entry-গুলো filter করে বাদ দেওয়া হয়। এটি সেট করা না থাকলে
(অথবা fetch SSRF guard-এ ব্যর্থ হলে / খারাপ response ফেরত দিলে), built-in seed
registry ব্যবহার করা হয়।

Dashboard-এর "Marketplace" tab-এ এই URL-এর জন্য একটি field রয়েছে (যা
`GET /api/settings` থেকে আবার পড়া হয়)।

> বাস্তবায়ন-সংক্রান্ত নোট: dashboard-এর "Save" action
> `pluginMarketplaceUrl`-কে `PATCH /api/settings`-এ পাঠায়। এই লেখা তৈরির সময়
> key-টি `updateSettingsSchema`-তে
> (`src/shared/validation/settingsSchemas.ts`) ঘোষিত নয়, তাই এর ওপর নির্ভর করার
> আগে আপনার release-এ persistence যাচাই করুন — settings store-এ key-টি উপস্থিত
> হয়ে গেলে **read** path (`getSettings()` → `listMarketplacePlugins()`) সেটি
> বিবেচনা করে।

**আগে** লুপব্যাক প্রয়োগ নিঃশর্তভাবে চলে, ফলে কোনো ফাঁস হওয়া ব্যবস্থাপনা টোকেন টানেলের
মাধ্যমে মেশিনে পৌঁছালেও তা কোনো প্লাগইন ইনস্টল, সক্রিয় বা আনইনস্টল করতে পারে না।
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) এবং
কঠোর নিয়ম #15 / #17 দেখুন।

### মার্কেটপ্লেস রেজিস্ট্রি SSRF সুরক্ষা

একটি কাস্টম রেজিস্ট্রি URL হলো আক্রমণকারীর দ্বারা প্রভাবিত হতে পারে এমন কনফিগারেশন, তাই
এটি ফেচ করার আগে `listMarketplacePlugins()` এটিকে দুটি স্তরের মধ্য দিয়ে চালায়:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - `http:` / `https:` নয় এমন সবকিছু প্রত্যাখ্যান করে।
   - ক্যানোনিক্যাল `isPrivateHost`
     (`src/shared/network/outboundUrlGuard.ts`) ব্যবহার করে সরাসরি লেখা প্রাইভেট/লুপব্যাক/লিংক-লোকাল/ULA হোস্ট (IPv4 **এবং** IPv6,
     IPv4-ম্যাপডসহ) প্রত্যাখ্যান করে।
   - **উভয়** `A` এবং `AAAA` রেকর্ড রিজলভ করে এবং রিজলভ হওয়া ঠিকানাগুলোর **যেকোনোটি**
     প্রাইভেট হলে প্রত্যাখ্যান করে — ফলে পাবলিক-হোস্টনেম → প্রাইভেট-IP বাইপাস বন্ধ হয়।
   - **ব্যর্থ হলে বন্ধ থাকে**: DNS রিজল্যুশন ব্যর্থ হলে URL প্রত্যাখ্যান করা হয়।
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`**
   (`src/shared/network/safeOutboundFetch.ts`): ফেচের সময় public-only URL
   সুরক্ষা পুনরায় প্রয়োগ করে এবং **রিডাইরেক্ট ব্লক করে** (কোনো পাবলিক → প্রাইভেট `30x`
   পিভট নয়)।

কোনো URL যেকোনো একটি স্তরে ব্যর্থ হলে অনুরোধটি বাতিল হয় না — মার্কেটপ্লেস
নীরবে বিল্ট-ইন সিড রেজিস্ট্রিতে ফিরে যায় এবং একটি সতর্কতা লগ করে।

> বিশেষভাবে A + AAAA রিজলভ করতে এবং শুধুমাত্র IPv4-ভিত্তিক যাচাইয়ের পরিবর্তে
> ক্যানোনিক্যাল `isPrivateHost` ব্যবহার করতে PR #3774-এ এই সুরক্ষা আরও শক্তিশালী করা হয়েছিল।

### প্লাগইন নির্বাহের বিচ্ছিন্নতা

- **প্রসেস বিচ্ছিন্নতা** — `loadPlugin()` (`src/lib/plugins/loader.ts`) প্রতিটি
  প্লাগইনকে একটি পৃথক Node.js চাইল্ড প্রসেসে চালু করে এবং IPC-এর মাধ্যমে যোগাযোগ করে।
  হুক কলগুলোর জন্য `SIGTERM` → `SIGKILL` ধাপে উন্নীতকরণসহ একটি টাইমআউট রয়েছে।
- **Env অনুমোদিত তালিকা** — চাইল্ডটি কেবল অনুমোদিত তালিকায় থাকা এনভায়রনমেন্ট
  ভ্যারিয়েবলগুলোর একটি সেট পায়; ম্যানিফেস্ট `env` অনুমতি চাইলেই কেবল বিস্তৃত সেটটি
  দেওয়া হয়।
- **পাথ সীমাবদ্ধতা** — ইনস্টল/আপগ্রেড/আনইনস্টলের ক্ষেত্রে যেকোনো কপি বা রিকার্সিভ
  ডিলিটের আগে নিশ্চিত করা হয় যে প্লাগইন ডিরেক্টরি এবং `manifest.main` পরিচালিত প্লাগইন
  রুটের **মধ্যে** রিজলভ হয় (বিকৃত DB পাথ এবং `manifest.main`-এ `../` ট্রাভার্সালের
  বিরুদ্ধে সুরক্ষা দেয়)। সক্রিয়করণের সময় `realpath` দিয়ে সিমলিংক রিজলভ করা হয় এবং
  প্লাগইন ডিরেক্টরির বাইরে চলে যাওয়া কোনো এন্ট্রি পয়েন্ট লোড করতে অস্বীকৃতি জানানো হয়।
- **ঐচ্ছিক ইন্টিগ্রিটি পিন** — একটি ম্যানিফেস্টে `integrity`
  (`sha256-<base64>`, SRI ফরম্যাট) ফিল্ড ঘোষণা করা যেতে পারে। এটি উপস্থিত থাকলে, লোডার
  লোডের সময় এন্ট্রি ফাইলের হ্যাশ যাচাই করে এবং অমিল হলে সক্রিয় করতে অস্বীকৃতি জানায়।
  এটি ঐচ্ছিক টেম্পার-শনাক্তকরণ, কোনো নিরাপত্তা সীমারেখা **নয়** — loopback-only রাউটিং
  এবং অনুমতি মডেলই প্রকৃত সীমারেখা।

## ম্যানিফেস্ট (`plugin.json`)

`PluginManifestSchema` (`src/lib/plugins/manifest.ts`) দ্বারা যাচাইকৃত:

| ফিল্ড              | ধরন       | টীকা                                                       |
| ------------------ | --------- | ---------------------------------------------------------- |
| `name`             | string    | আবশ্যক; kebab-case (`^[a-z0-9-]+$`), 1–100 অক্ষর           |
| `version`          | string    | আবশ্যক; semver (`MAJOR.MINOR.PATCH`)                       |
| `description`      | string?   | ≤ 500 অক্ষর                                                |
| `author`           | string?   | ≤ 200 অক্ষর                                                |
| `license`          | string?   | ডিফল্ট মান `MIT`                                           |
| `main`             | string?   | এন্ট্রি ফাইল; ডিফল্ট মান `index.js`                        |
| `source`           | enum?     | `local` \| `marketplace` (ডিফল্ট মান `local`)              |
| `tags`             | string[]? | অনুসন্ধান ট্যাগ                                            |
| `requires`         | object?   | `{ omniroute?, permissions[] }`                            |
| `hooks`            | object?   | প্লাগইনটি কোন হুক বাস্তবায়ন করে তা ঘোষণাকারী বুলিয়ান মান |
| `skills`           | object[]? | ঐচ্ছিক স্কিলের সংজ্ঞা                                      |
| `enabledByDefault` | boolean?  | ইনস্টলের সময় স্বয়ংক্রিয়ভাবে সক্রিয় হয়                 |
| `configSchema`     | object?   | কনফিগ ফিল্ডের ম্যাপ (`string`/`number`/`boolean`/`select`) |
| `integrity`        | string?   | ঐচ্ছিক `sha256-<base64>` এন্ট্রি-ফাইল পিন                  |

অনুমতিগুলো
`network` / `file-read` / `file-write` / `env` / `exec`
enum থেকে নেওয়া হয়।

## লাইফসাইকেল প্রবাহ

```
install (POST /api/plugins, path)
  → ম্যানিফেস্ট স্ক্যান/যাচাই → স্টেজিংয়ে কপি → main যে ডিরেক্টরির মধ্যে রয়েছে তা নিশ্চিত করা
  → ~/.omniroute/plugins/<name>-এ অ্যাটমিক রিনেম → DB সারি যোগ করা
  → onInstall চালানো → enabledByDefault হলে: সক্রিয় করা

activate (POST /api/plugins/{name}/activate)
  → realpath কনটেইনমেন্ট যাচাই → loadPlugin() (চাইল্ড প্রসেস চালু করা)
  → ঘোষিত হুক নিবন্ধন → status = "active" → onActivate চালানো

deactivate (POST /api/plugins/{name}/deactivate)
  → onDeactivate চালানো (নিবন্ধন বাতিলের আগে) → হুকগুলোর নিবন্ধন বাতিল
  → চাইল্ড প্রসেস বন্ধ করা → status = "inactive"

uninstall (DELETE /api/plugins/{name})
  → সক্রিয় থাকলে নিষ্ক্রিয় করা → onUninstall চালানো
  → কনটেইনমেন্ট-যাচাইকৃতভাবে প্লাগইন ডিরেক্টরি রিকার্সিভ মুছে ফেলা → DB সারি মুছে ফেলা
```

ইনস্টল করা সংস্করণের চেয়ে ম্যানিফেস্টের সংস্করণ **কঠোরভাবে
নতুন** এমন কোনো ডিরেক্টরিতে পুনরায় `install` চালালে স্বয়ংক্রিয়ভাবে আপগ্রেড হয় (পরিষ্কারভাবে পুনরায় ইনস্টল; কনফিগ ডিফল্টে রিসেট
হয়)। একই বা পুরোনো সংস্করণ প্রত্যাখ্যান করা হয়।

  সক্রিয়/নিষ্ক্রিয় করার টগল, আনইনস্টল বোতাম এবং "প্লাগইন স্ক্যান করুন"
  অ্যাকশন (`POST /api/plugins/scan`)।
- **মার্কেটপ্লেস** — `GET /api/plugins/marketplace` থেকে পাওয়া ক্যাটালগ দেখায় এবং
  কাস্টম রেজিস্ট্রি URL সেট করার জন্য একটি ফিল্ড প্রদান করে।

প্রতিটি প্লাগইনের জন্য আলাদা কনফিগ পেজ রয়েছে `/dashboard/plugins/[name]/config`-এ
(`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`)।
