AgentBridge হলো OmniRoute-এর MITM (Man-in-the-Middle) প্রক্সি, যা IDE AI এজেন্টগুলোর HTTPS ট্র্যাফিক ইন্টারসেপ্ট করে এবং OmniRoute-এর সমন্বিত রাউটিং ইঞ্জিনের মাধ্যমে পুনরায় রাউট করে। এটি **10টি IDE এজেন্ট** সমর্থন করে — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code এবং Trae (তদন্তাধীন) — ফলে OmniRoute বাজারে AI কোডিং সহকারীগুলোর জন্য সবচেয়ে বিস্তৃত কভারেজের MITM প্রক্সি।

**ড্যাশবোর্ডের অবস্থান:** `/dashboard/tools/agent-bridge`
**সাইডবার গ্রুপ:** Tools (Cloud Agents-এর পরে)
**আরও দেখুন:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — ইন্টারসেপ্ট করা সব ট্র্যাফিক রিয়েল-টাইমে পর্যবেক্ষণ করুন; `docs/security/MITM-TPROXY-DECRYPT.md` (git-এ রয়েছে; `/docs`-এ কম্পাইল করা হয়নি) — `/api/tools/agent-bridge/tproxy` রুট দ্বারা পরিচালিত Linux TPROXY ট্রান্সপারেন্ট-ডিক্রিপ্ট ক্যাপচার মোড।

## §1 সংক্ষিপ্ত বিবরণ

### AgentBridge কী?

যখন কোনো IDE এজেন্ট (যেমন, GitHub Copilot, Cursor, Claude Code) একটি API কল করে, তখন এটি সরাসরি আপস্ট্রিম AI প্রদানকারীর (OpenAI, Anthropic ইত্যাদি) সঙ্গে সংযুক্ত হয়। AgentBridge TLS স্তরে স্বচ্ছভাবে সেই সংযোগ ইন্টারসেপ্ট করে — এজেন্টের কনফিগারেশনে কোনো পরিবর্তনের প্রয়োজন ছাড়াই — এবং OmniRoute-এর মাধ্যমে অনুরোধটি পুনর্লিখন করে।

এর ফলে আপনি যা করতে পারেন:

- **যেকোনো এজেন্টকে যেকোনো প্রদানকারীর দিকে পুনরায় রাউট করা**: Copilot কি OpenAI-এর সঙ্গে যোগাযোগ করছে? এটিকে Anthropic Claude, Gemini অথবা OmniRoute-এর 352টি প্রদানকারীর যেকোনোটির দিকে পুনর্নির্দেশ করুন।
- **মডেল ম্যাপিং প্রয়োগ করা**: হ্যান্ডলার স্তরে স্বচ্ছভাবে `gemini-3-flash` → `claude-sonnet-4.7`।
- **এজেন্টের সব ট্র্যাফিক পর্যবেক্ষণ করা**: ইন্টারসেপ্ট করা প্রতিটি অনুরোধ [Traffic Inspector](./TRAFFIC_INSPECTOR.md)-এ প্রকাশ করা হয়।
- **OmniRoute-এর স্থিতিস্থাপকতা প্রয়োগ করা**: কম্বো রাউটিং, সার্কিট ব্রেকার, ফলব্যাক এবং খরচ ট্র্যাকিং IDE এজেন্টের ট্র্যাফিকের ক্ষেত্রেও কাজ করে।

## §2 আর্কিটেকচার

### 2.1 কম্পোনেন্টসমূহের সারসংক্ষেপ

```
IDE এজেন্ট (VS Code / Cursor / ইত্যাদি)
    │  HTTPS (পোর্ট 443)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← DNS রিডাইরেক্ট
    │
    ▼
src/mitm/server.cjs  (পোর্ট 443, CJS চাইল্ড প্রসেস)
    │  Host হেডারের SNI অনুযায়ী টার্গেট নির্ধারণ করে
    │  AgentBridge CA দ্বারা স্বাক্ষরিত প্রতি-SNI TLS সার্টিফিকেট তৈরি করে
    ├── বাইপাস তালিকায় মিলেছে? → TCP পাসথ্রু (ডিক্রিপ্ট নয়)
    ├── টার্গেট মিলেছে? → fetch → OmniRoute রাউটার (পোর্ট 20128)
    │       └── handler.intercept() — TypeScript
    │               ├── রিকোয়েস্ট বডি/হেডারে maskSecrets()
    │               ├── TrafficBuffer.push() — Traffic Inspector-এ প্রকাশ করে
    │               └── fetchRouter() → /v1/chat/completions
    └── কোনো মিল নেই? → TCP পাসথ্রু (ডিক্রিপ্ট নয়)
```

### 2.2 MITM সার্ভার (`src/mitm/server.cjs`)

মূল MITM সার্ভারটি একটি Node.js CJS চাইল্ড প্রসেস হিসেবে চলে (বিদ্যমান CJS কোডবেস পুনরায় লেখা এড়াতে)। এটি:

- পোর্ট 443-এ লিসেন করে (`authbind`/`setcap` অথবা উপযুক্ত বিশেষাধিকার প্রয়োজন)
- OS থেকে CONNECT টানেল গ্রহণ করে (`/etc/hosts` DNS রিডাইরেক্টের মাধ্যমে)
- AgentBridge CA (`DATA_DIR/mitm/ca.crt`) দ্বারা স্বাক্ষরিত প্রতি-SNI TLS সার্টিফিকেট তৈরি করে
- `targets/index.ts` রেজিস্ট্রির মাধ্যমে Host হেডার অনুযায়ী টার্গেট এজেন্ট নির্ধারণ করে
- HTTP-এর মাধ্যমে `http://127.0.0.1:20128`-এ TypeScript হ্যান্ডলার লেয়ারে পাঠায়

`TARGET_HOSTS`, `DATA_DIR/mitm/targets.json` থেকে লোড করা হয় (বুটের সময় `targets/index.ts` এটি লেখে), ফলে CJS সার্ভার পুনরায় চালু না করেই ডায়নামিক আপডেট করা যায়।

> **Root-CA মডেল (#6684)।** উপরে বর্ণিত CA দ্বারা স্বাক্ষরিত প্রতি-SNI সার্টিফিকেট
> হলো #6684-এ যোগ করা স্থায়ী root-CA মডেল (`src/mitm/cert/rootCa.ts` +
> `src/mitm/_internal/rootCaShim.cjs`, যা `src/mitm/tproxy/dynamicCert.ts`-এ TPROXY-এর জন্য
> ইতোমধ্যে প্রমাণিত CA/leaf ক্রিপ্টোগ্রাফি পুনঃব্যবহার করে) — এটি আগের একক স্ট্যাটিক
> স্ব-স্বাক্ষরিত leaf-কে (`src/mitm/cert/generate.ts`, যা এখনও শুধু antigravity হোস্টগুলোর
> মধ্যে সীমাবদ্ধ) প্রতিস্থাপন করে, যেটির উপস্থিতি ডিস্কে কেবল একটি `server.crt`/`server.key`
> জোড়া দ্বারা নির্দেশিত হয়। **মাইগ্রেশন আচরণ**: একটি নতুন ইনস্টলেশন (পূর্ববর্তী
> `server.crt` নেই) স্বয়ংক্রিয়ভাবে root-CA মডেল পায়; যে ইনস্টলেশন ইতোমধ্যে পুরোনো
> স্ট্যাটিক leaf-কে বিশ্বাস করে, সেটি অপারেটর `MITM_ROOT_CA_ENABLED=true` সেট করে
> ব্রিজ পুনরায় চালু না করা পর্যন্ত সেটিই ব্যবহার করতে থাকে (`src/mitm/cert/migration.ts`
> হলো বিশুদ্ধ সিদ্ধান্ত ফাংশন — একটি বিশ্বস্ত MITM CA, যা **যেকোনো** হোস্টের জন্য
> leaf স্বাক্ষর করতে পারে, পুরোনো স্থির-SAN leaf-এর তুলনায় বাস্তবিকভাবেই বেশি
> ক্ষমতাশালী; তাই ইতোমধ্যে বিশ্বস্ত কোনো ইনস্টলেশনের ক্ষেত্রে পরিবর্তনটি কখনোই
> নীরবে ঘটে না)। CA সার্টিফিকেটটি পুরোনো leaf-এর ব্যবহৃত একই `omniroute-mitm.crt`
> ট্রাস্ট-স্টোর স্লটে ইনস্টল হয় (`cert/install.ts::installCaCert`) — দ্বৈত-ট্রাস্ট
> পরিষ্কার করার প্রয়োজন নেই।

### 2.3 হ্যান্ডলার বেস (`src/mitm/handlers/base.ts`)

সব এজেন্ট হ্যান্ডলার `MitmHandlerBase` সম্প্রসারণ করে:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // সুরক্ষিত সহায়কসমূহ: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

প্রতিটি হ্যান্ডলার প্রক্সি করার আগে `hookBufferStart()` এবং সম্পন্ন হলে `hookBufferUpdate()` কল করে। এগুলো `globalTrafficBuffer`-এ `InterceptedRequest` এন্ট্রি পুশ করে ([Traffic Inspector](./TRAFFIC_INSPECTOR.md) §4 দেখুন)।

### 2.4 টার্গেট রেজিস্ট্রি (`src/mitm/targets/`)

প্রতিটি এজেন্টের একটি ঘোষণামূলক টার্গেট ফাইল রয়েছে:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

রেজিস্ট্রি (`targets/index.ts`) `ALL_TARGETS` এক্সপোর্ট করে এবং বুটের সময় `DATA_DIR/mitm/targets.json` তৈরি করে।

### 2.5 পাসথ্রু এবং বাইপাস তালিকা (`src/mitm/passthrough.ts`)

**বাইপাস তালিকা** (টার্গেট মিলের তুলনায় অগ্রাধিকার দিয়ে প্রথমে পরীক্ষা করা হয়):

- ডিফল্ট প্যাটার্ন: ব্যাংকিং হোস্ট, `.gov.`, OAuth/SSO প্রদানকারী (Okta, Auth0), ইত্যাদি
- ব্যবহারকারীর প্যাটার্ন: DB টেবিল `agent_bridge_bypass`-এ সংরক্ষিত
- বাইপাস করা হোস্টগুলো একটি স্বচ্ছ TCP টানেল পায় — TLS **কখনোই ডিক্রিপ্ট করা হয় না**

**পাসথ্রু ডিফল্ট** (টার্গেট মেলে না এবং বাইপাসেও নেই):

- এটিও একটি TCP টানেল পায় — সংযোগ কখনো বিচ্ছিন্ন করা হয় না
- AgentBridge-কে সাধারণ সিস্টেম HTTPS ট্রাফিক ব্যাহত করা থেকে বিরত রাখে

রাউটিং অগ্রাধিকার:

```
বাইপাস তালিকা → টার্গেট মিল → পাসথ্রু
```

### 2.6 আপস্ট্রিম CA সার্টিফিকেট (`src/mitm/upstreamTrust.ts`)

কাস্টম CA-সহ কর্পোরেট নেটওয়ার্ক পরিবেশের জন্য:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

এটি সেট করা হলে, অতিরিক্ত CA সার্টিফিকেটসহ `undici`-এর গ্লোবাল ডিসপ্যাচার কনফিগার করা হয়, ফলে AgentBridge কর্পোরেট TLS টার্মিনেশন প্রক্সির মাধ্যমে আপস্ট্রিম প্রদানকারীদের কাছে পৌঁছাতে পারে।

### 2.7 সিক্রেট মাস্কিং (`src/mitm/maskSecrets.ts`)

স্বতন্ত্র ক্লিন-রুম স্ক্যানারটি রিকোয়েস্ট বডি ও ক্রেডেনশিয়াল হেডারগুলো Traffic Inspector বাফার বা কোনো লগে প্রবেশের **আগে** প্রয়োগ করা হয়। এটি একবারের রৈখিক পাস সম্পাদন করে:

- `sk-` / `ak-` / `pk-` প্রিফিক্সযুক্ত টোকেন (OpenAI/Anthropic-ধাঁচের)
- RFC 6750 `Authorization: Bearer <token>` ক্রেডেনশিয়াল, যেখানে সম্পূর্ণ টোকেন অগ্রাধিকার পায়
- সাধারণ দীর্ঘ অস্বচ্ছ টোকেন (≥40 অক্ষর), ডটযুক্ত ও প্যাড করা ফর্মসহ

`sanitizeHeaders()` সংরক্ষিত নামগুলোকে লোয়ারকেসে রূপান্তর করে, অ্যারে মানগুলোকে নির্ধারিতভাবে যুক্ত করে, শেয়ার করা হপ-বাই-হপ/ফ্রেমিং ডিনাইলিস্ট (প্রক্সি প্রমাণীকরণসহ) বাদ দেয়, `cookie` এবং `set-cookie` সম্পূর্ণভাবে রেড্যাক্ট করে এবং ক্রেডেনশিয়াল মানগুলো স্ক্যানারের কাছে অর্পণ করে।

## §3 সেটআপ

### 3.1 MITM সার্ভার চালু/বন্ধ করা

`/dashboard/tools/agent-bridge`-এ থাকা AgentBridge সার্ভার কার্ড ব্যবহার করুন:

| অ্যাকশন                       | বিবরণ                                                                                |
| ----------------------------- | ------------------------------------------------------------------------------------ |
| সার্ভার চালু করুন             | পোর্ট 443-এ `src/mitm/server.cjs` চালু করে                                           |
| সার্ভার বন্ধ করুন             | চাইল্ড প্রসেসটি সুষ্ঠুভাবে বন্ধ করে                                                  |
| সার্ভার পুনরায় চালু করুন     | বন্ধ + চালু করে (টার্গেটের পরিবর্তনগুলো প্রয়োগ করে)                                 |
| সার্টিফিকেট বিশ্বাস করুন      | OS ট্রাস্ট স্টোরে `DATA_DIR/mitm/ca.crt` ইনস্টল করে                                  |
| সার্টিফিকেট ডাউনলোড করুন      | ম্যানুয়াল ইনস্টলেশনের জন্য `ca.crt` ডাউনলোড করে                                     |
| সার্টিফিকেট পুনরায় তৈরি করুন | একটি নতুন CA কী-পেয়ার তৈরি করে (এজেন্টপ্রতি বিদ্যমান সব সার্টিফিকেট অবৈধ হয়ে যায়) |

### 3.2 সার্টিফিকেটটি বিশ্বাসযোগ্য হিসেবে যোগ করা

IDE-গুলো MITM সংযোগ গ্রহণ করার আগে AgentBridge CA সার্টিফিকেটটি OS-এর কাছে বিশ্বাসযোগ্য হতে হবে।

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Keychain):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

অথবা ড্যাশবোর্ডের "সার্টিফিকেট বিশ্বাস করুন" বোতামটি ব্যবহার করুন (এটি আপনার OS-এর উপযুক্ত কমান্ড চালায় এবং প্রয়োজন হলে sudo প্রম্পট দেখায়)।

#### Electron-ভিত্তিক IDE-গুলো OS ট্রাস্ট স্টোর (`NODE_EXTRA_CA_CERTS`) উপেক্ষা করে

কিছু IDE — বিশেষত **Antigravity IDE** এবং অন্যান্য Electron / VS Code-ভিত্তিক অ্যাপ — নিজস্ব
Node.js রানটাইমের সঙ্গে আসে, যা বহির্গামী `fetch`/HTTPS-এর জন্য **OS ট্রাস্ট স্টোর ব্যবহার করে না**।
OS/NSS স্তরে CA-টিকে বিশ্বাস করা IDE-এর নেটিভ **ব্যাকএন্ডের** জন্য যথেষ্ট
(যেমন একটি Go ল্যাঙ্গুয়েজ সার্ভার, যা OS CA বান্ডল ব্যবহার করে), কিন্তু **Electron ফ্রন্টএন্ডে**
তারপরও TLS ব্যর্থ হবে — MITM লগে ব্যাকএন্ডের বুটস্ট্র্যাপ কলগুলো `200` ফেরত দেখালেও
অ্যাপটিতে এটি _লগ-আউট হয়ে যাওয়া_ বা _"সংযোগ ত্রুটি"_ দেখানোর মাধ্যমে প্রকাশ পায়।
দুটি ধাপ প্রয়োজন এবং দুটিই গুরুত্বপূর্ণ:

1. CA-টির দিকে রানটাইমকে স্পষ্টভাবে নির্দেশ করুন:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **সেই শেল থেকে IDE চালু করুন।** ডেস্কটপ আইকন / Dock / Start মেনু থেকে চালু করলে
   এটি শেলের export-গুলো **উত্তরাধিকারসূত্রে পায় না**, এবং `~/.config/environment.d/*.conf` কেবল
   নতুন করে গ্রাফিক্যাল লগইন করার পর প্রযোজ্য হয়। প্রথমে IDE সম্পূর্ণভাবে বন্ধ করুন — Electron-এর সিঙ্গলটন
   লকের কারণে দ্বিতীয়বার চালু করলে শুধু বিদ্যমান প্রসেসটিতে ফোকাস করা হয় এবং নতুন এনভায়রনমেন্ট উপেক্ষিত থাকে।

উপরের OS-trust + NSS ধাপটি এখনও প্রয়োজনীয় (কিছু অথেন্টিকেশন ফ্লোতে ব্যবহৃত Chromium নেটওয়ার্ক
স্ট্যাকটি ব্যবহারকারীপ্রতি NSS স্টোর পড়ে এবং `*.googleapis.com`-এর জন্য এর নিজস্ব স্ট্যাটিক পিন রয়েছে, যা
স্থানীয়ভাবে বিশ্বাসযোগ্য CA ওভাররাইড করে)। এর পাশাপাশি `NODE_EXTRA_CA_CERTS` Node-এর `fetch` পাথটি সামলায়।

### 3.3 DNS রাউটিং

আপনি যেসব এজেন্ট ইন্টারসেপ্ট করতে চান, সেগুলোর প্রতিটির API হোস্টকে অবশ্যই `127.0.0.1`-এ রিজলভ হতে হবে। সেটআপ উইজার্ডে কোনো এজেন্টের DNS টগল করলে AgentBridge স্বয়ংক্রিয়ভাবে `/etc/hosts` এন্ট্রি পরিচালনা করে।

GitHub Copilot-এর জন্য `/etc/hosts` এন্ট্রির উদাহরণ:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 মডেল ম্যাপিং

সোর্স → টার্গেট ম্যাপিং নির্ধারণ করতে প্রতিটি এজেন্ট কার্ডের মডেল ম্যাপিং টেবিল ব্যবহার করুন:

| সোর্স মডেল (এজেন্টের নেটিভ) | টার্গেট মডেল (OmniRoute) |
| --------------------------- | ------------------------ |
| `gpt-4o`                    | `claude-sonnet-4.7`      |
| `*` (ওয়াইল্ডকার্ড)         | `claude-haiku-4.7`       |

ওয়াইল্ডকার্ড `*` যেকোনো অপরিচিত মডেলকে নির্দিষ্ট টার্গেটে ম্যাপ করে। এটি `agent_bridge_mappings` টেবিলে সংরক্ষিত থাকে।

> **পরামর্শ — এজেন্টের প্রকৃত মডেল ID-গুলো খুঁজে বের করুন।** একটি IDE এমন মডেল নাম পাঠাতে পারে, যা
> এর UI লেবেল থেকে আলাদা এবং প্রধান সংস্করণগুলোর মধ্যে পরিবর্তিত হয়। উদাহরণস্বরূপ, **Antigravity 2**
> নেটওয়ার্কের মাধ্যমে `gemini-3.1-pro-low`, `gemini-pro-agent` এবং `gemini-3.1-flash-lite` পাঠায় —
> পুরোনো ডকুমেন্টেশনে দেখানো `gemini-2.5-pro` নয়। কোনো মিল থাকা ম্যাপিং ছাড়াই একটি চ্যাট পাঠান:
> MITM সঠিক আগত `model:` লগ করবে এবং অনুরোধটি সরাসরি পাঠিয়ে দেবে। সেই আক্ষরিক মানটি ম্যাপ করুন,
> এরপর পরবর্তী অনুরোধটি ইন্টারসেপ্ট হয়ে আপনার টার্গেটে রাউট হবে।

### 3.5 ঝুঁকি-সংক্রান্ত বিজ্ঞপ্তি

আপস্ট্রিম প্রদানকারীদের কাছে অথেন্টিকেট করার জন্য IDE যে ক্রেডেনশিয়ালগুলো (OAuth টোকেন, API কী) ব্যবহার করে, AgentBridge সেগুলো ইন্টারসেপ্ট করে। এগুলো **লগ করার আগে মাস্ক করা হয়** (§2.7 দেখুন), তবে OmniRoute-এর MITM স্তরে দৃশ্যমান থাকে। প্রতিটি এজেন্ট প্রথমবার সক্রিয় করার সময় বন্ধ করা যায় এমন একটি ঝুঁকি-সংক্রান্ত বিজ্ঞপ্তির মডাল দেখানো হয়।

### 3.6 রক্ষণাবেক্ষণ ও ডায়াগনস্টিকস

ড্যাশবোর্ডে একটি **রক্ষণাবেক্ষণ ও ডায়াগনস্টিকস** কার্ড (`AgentBridgeMaintenanceCard`, `src/app/(dashboard)/dashboard/tools/agent-bridge/components/`-এ) রয়েছে, যা আগে কোনো UI না থাকা অপারেশনাল MITM রুটগুলো প্রকাশ করে। এর উপশিরোনাম: _"ক্যাপচার পাইপলাইন স্বয়ং পরীক্ষা করুন, অবশিষ্ট সিস্টেম স্টেট পূর্বাবস্থায় ফিরিয়ে নিন এবং আপনার সেটআপটি এক মেশিন থেকে অন্য মেশিনে স্থানান্তর করুন।"_ কার্ডটির ক্লায়েন্ট হেল্পারগুলো `src/lib/inspector/agentBridgeMaintenanceApi.ts`-এ রয়েছে।

| বোতাম               | রুট                                    | এটি যা করে                                                                                                                                                                                                      |
| ------------------- | -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **নির্ণয়**         | `GET /api/tools/agent-bridge/diagnose` | ক্যাপচার-পাইপলাইনের স্ব-পরীক্ষা চালায় এবং প্রতিটি যাচাইয়ের প্রতিবেদন দেখায় (✓/✗ + প্রতিকারের ইঙ্গিত)।                                                                                                        |
| **মেরামত**          | `POST /api/tools/agent-bridge/repair`  | ক্র্যাশ বা SIGKILL-এর কারণে অবশিষ্ট থাকা অনাথ MITM সিস্টেম স্টেট (DNS স্পুফ এন্ট্রি, রুট CA, সিস্টেম প্রক্সি) পূর্বাবস্থায় ফিরিয়ে আনে। আইডেমপোটেন্ট — স্টেট পরিষ্কার থাকলে "মেরামত করার মতো কিছু নেই" জানায়। |
| **CA অপসারণ**       | `DELETE /api/tools/agent-bridge/cert`  | OS ট্রাস্ট স্টোর থেকে MITM রুট CA-এর আস্থা প্রত্যাহার করে এবং সেটি অপসারণ করে (স্পষ্ট, আইডেমপোটেন্ট)। কেবল CA বর্তমানে বিশ্বস্ত থাকলেই দেখানো হয়; একটি ইনলাইন "CA অপসারণ করবেন?" নিশ্চিতকরণ প্রয়োজন।          |
| **কনফিগ এক্সপোর্ট** | `GET /api/tools/agent-bridge/config`   | বহনযোগ্য কনফিগ JSON ডাউনলোড করে (§3.7 দেখুন)।                                                                                                                                                                   |
| **কনফিগ ইমপোর্ট**   | `POST /api/tools/agent-bridge/config`  | পূর্বে এক্সপোর্ট করা কনফিগ JSON আপলোড করে (§3.7 দেখুন)।                                                                                                                                                         |

**ডায়াগনস্টিক যাচাইসমূহ** (`src/mitm/inspector/diagnostics.ts`-এ `summarizeDiagnostics()`)। রুটটি প্রতিটির জন্য পার্শ্বপ্রতিক্রিয়াযুক্ত প্রোব চালায় এবং বুলিয়ান মানগুলো বিশুদ্ধ সারসংক্ষেপকারীতে সরবরাহ করে; একটি একক `healthy` সিদ্ধান্তের সঙ্গে প্রতিটি ব্যর্থতার জন্য একটি ইঙ্গিত ফেরত দেওয়া হয়:

| যাচাইয়ের নাম      | যা যাচাই করে                                          | ব্যর্থ হলে ইঙ্গিত                                                                                                                                                       |
| ------------------ | ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server-running`   | MITM সার্ভার প্রক্রিয়াটি সক্রিয় আছে                 | "MITM সার্ভারটি চলছে না। AgentBridge ট্যাব থেকে এটি চালু করুন।"                                                                                                         |
| `server-reachable` | MITM সার্ভারটি তার পোর্টে সংযোগ গ্রহণ করে (TCP প্রোব) | "MITM সার্ভারটি তার পোর্টে সংযোগ গ্রহণ করছে না। পোর্টটি খালি আছে কি না এবং সেটিতে বাইন্ড করার বিশেষাধিকার আপনার আছে কি না, তা পরীক্ষা করুন।"                            |
| `cert-exists`      | MITM সার্টিফিকেটটি ডিস্কে তৈরি করা হয়েছে             | "এখনও কোনো MITM সার্টিফিকেট তৈরি করা হয়নি। AgentBridge ট্যাব থেকে একটি তৈরি করুন।"                                                                                     |
| `cert-trusted`     | MITM রুট CA OS ট্রাস্ট স্টোরে রয়েছে                  | "MITM রুট CA-টি OS স্টোরের কাছে বিশ্বস্ত নয়, তাই TLS ইন্টারসেপশন ব্যর্থ হবে। AgentBridge ট্যাব থেকে সার্টিফিকেটটিকে বিশ্বস্ত হিসেবে চিহ্নিত করুন।"                     |
| `dns-configured`   | লক্ষ্য হোস্টনেমগুলো `/etc/hosts`-এ স্পুফ করা আছে      | "লক্ষ্য হোস্টনেমগুলো /etc/hosts-এ স্পুফ করা নেই, ফলে ট্রাফিক কখনোই প্রক্সিতে পৌঁছায় না। আপনি যে এজেন্টগুলোর ট্রাফিক ক্যাপচার করতে চান, সেগুলোর জন্য DNS সক্রিয় করুন।" |

**অনাথ-স্টেট ব্যানার:** পৃষ্ঠাটি যখন কোনো ক্র্যাশের কারণে অবশিষ্ট থাকা স্টেট (DNS স্পুফ / CA / সিস্টেম প্রক্সি) শনাক্ত করে, তখন কার্ডটি একটি অ্যাম্বার ব্যানার দেখায় — _"পূর্ববর্তী একটি সেশন সিস্টেম স্টেট (DNS স্পুফ, CA বা সিস্টেম প্রক্সি) অবশিষ্ট রেখে গেছে। এটি পরিষ্কার করতে মেরামত চালান।"_ — এবং **মেরামত** বোতামটি হাইলাইট করে। `Repair` হলো ProxyBridge-এর `--cleanup` ফ্ল্যাগের অ্যাপ্লিকেশন-স্তরের সমতুল্য (এটি `src/mitm/manager.ts`-এর `repairMitm()`-এ কাজটি অর্পণ করে)।

> বারবার sudo প্রম্পট এড়াতে MITM রুট CA বন্ধ/চালুর মধ্যেও ইনস্টল করা রাখা হয়
> (mitmproxy/Charles-এর মতো একই আচরণ), তাই বন্ধ করার সময় স্বয়ংক্রিয়ভাবে কিছু
> ঘটার পরিবর্তে এটি অপসারণ করতে স্পষ্ট **CA অপসারণ** অ্যাকশন প্রয়োজন।

### 3.7 বহনযোগ্য কনফিগ ইমপোর্ট/এক্সপোর্ট

AgentBridge **অপারেটর-কর্তৃক সামঞ্জস্যযোগ্য** স্টেটকে একটি সংস্করণযুক্ত JSON ব্লবে সিরিয়ালাইজ করতে পারে, যাতে একটি সেটআপ একাধিক মেশিনে প্রতিলিপি করা যায়। সিরিয়ালাইজারটি হলো `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`), যা `AgentBridgeConfigSchema` দ্বারা যাচাই করা হয়।

এক্সপোর্টে ঠিক তিনটি অংশ অন্তর্ভুক্ত থাকে (বিল্ট-ইন ডিফল্টগুলো ইচ্ছাকৃতভাবে এক্সপোর্ট করা হয় **না**, ফলে ইমপোর্ট করলে সেগুলো কখনো সদৃশ হয় না বা সেগুলোর সঙ্গে সংঘাত সৃষ্টি হয় না):

| ফিল্ড            | উৎস                                                             | নোট                                                                      |
| ---------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `bypassPatterns` | ব্যবহারকারী-সংজ্ঞায়িত বাইপাস প্যাটার্ন (`agent_bridge_bypass`) | ডিফল্ট bank/gov/okta প্যাটার্নগুলো বাদ দেওয়া হয়                        |
| `customHosts`    | Traffic Inspector-এর কাস্টম হোস্ট (`inspector_custom_hosts`)    | প্রতিটি: `{ host, kind: "llm"\|"app"\|"custom", label? }`                |
| `agentMappings`  | প্রতি-এজেন্ট মডেল ম্যাপিং (`agent_bridge_mappings`)             | ম্যাপিং থাকা প্রতিটি এজেন্টের জন্য `{ [agentId]: [{ source, target }] }` |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**ইমপোর্টের আচরণ** (`POST /api/tools/agent-bridge/config`): বাইপাস প্যাটার্ন এবং প্রতি-এজেন্ট ম্যাপিং **সম্পূর্ণভাবে প্রতিস্থাপিত হয়**; কাস্টম হোস্টগুলো **আইডেমপোটেন্টভাবে** যোগ করা হয় (`INSERT OR IGNORE`)। প্রতিটি থেকে কতটি প্রয়োগ করা হয়েছে তা প্রতিক্রিয়ায় জানানো হয়:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

কনফিগে যা **অন্তর্ভুক্ত নয়**: সার্ভার চালু থাকার অবস্থা, সার্টিফিকেটের পাথ, প্রতিটি এজেন্টের DNS অবস্থা, আপস্ট্রিম CA পাথ এবং TPROXY সেটিংস—এগুলো হোস্ট/রানটাইম অবস্থা, স্থানান্তরযোগ্য পছন্দ নয়।

### সংবেদনশীল হোস্টের বাইপাস তালিকা

বাইপাস তালিকা নিশ্চিত করে যে আর্থিক প্রতিষ্ঠান, OAuth/SSO প্রদানকারী এবং অন্যান্য সংবেদনশীল হোস্টের ট্রাফিক **কখনোই ডিক্রিপ্ট করা হবে না**। তাদের TLS ট্রাফিক একটি স্বচ্ছ TCP টানেলের মধ্য দিয়ে যায় — OmniRoute কখনোই প্লেইনটেক্সট দেখতে পায় না।

ডিফল্ট বাইপাস প্যাটার্নের মধ্যে রয়েছে:

- `*.bank.*`, `*.gov.*` (আর্থিক/সরকারি)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/পরিচয়)
- `*.apple.com`, `*.icloud.com` (Apple সিস্টেম পরিষেবা)

ব্যবহারকারীর যোগ করা বাইপাস প্যাটার্নগুলো `agent_bridge_bypass` টেবিলে সংরক্ষিত থাকে এবং অন্য সবকিছুর চেয়ে অগ্রাধিকার পায়।

### সিক্রেট মাস্কিং

`src/mitm/maskSecrets.ts` থেকে `maskSecrets()` প্রয়োগ করা হয়:

- `TrafficBuffer.push()`-এর আগে প্রতিটি রিকোয়েস্ট বডিতে
- লগিং বা ব্রডকাস্টিংয়ের আগে প্রতিটি হেডারে

প্যাটার্ন: `sk-`/`ak-`/`pk-` প্রিফিক্সযুক্ত টোকেন, `Bearer` টোকেন এবং ≥40 অক্ষরের সাধারণ টোকেন।

### আপস্ট্রিম CA সার্টিফিকেট

`AGENTBRIDGE_UPSTREAM_CA_CERT` সেট করা থাকলে, স্টার্টআপের সময় ফাইলটি পড়া হয়। পাথটি বিদ্যমান কিন্তু ফাইলটি পড়া না গেলে, AgentBridge একটি স্পষ্ট ত্রুটি লগ করে এবং চালু হতে অস্বীকৃতি জানায় (কর্পোরেট পরিবেশে নীরব TLS ব্যর্থতা প্রতিরোধ করে)।

### পরিচিত সীমাবদ্ধতা

- **Port 443-এর জন্য বিশেষাধিকার প্রয়োজন**: Linux-এ, AgentBridge-এর জন্য Node বাইনারিতে `setcap 'cap_net_bind_service=+ep'` প্রয়োজন, অথবা `authbind`-এর মাধ্যমে চালাতে হবে। Setup Wizard OS-নির্দিষ্ট নির্দেশনা দেখায়।
- **IDE পুনরায় চালু করা প্রয়োজন**: DNS রিডাইরেক্টের পর নতুন হোস্ট রেজোলিউশন কার্যকর করতে IDE পুনরায় চালু করতে হবে।
- **হার্ডকোড করা OAuth টোকেন**: কিছু এজেন্ট (Kiro, Antigravity) OAuth রিফ্রেশ টোকেন স্থানীয়ভাবে সংরক্ষণ করে। এগুলো AgentBridge-এর কাছে স্বচ্ছ — এটি প্রতিটি রিকোয়েস্টে Bearer টোকেন দেখতে পায়, যা লগিংয়ের আগে মাস্ক করা হয়।
- **Electron ফ্রন্টএন্ডে `NODE_EXTRA_CA_CERTS` প্রয়োজন**: যেসব IDE-এর ফ্রন্টএন্ড বান্ডল করা Node/Electron রানটাইমে চলে, সেগুলো OS/NSS ট্রাস্ট স্টোর উপেক্ষা করে এবং `NODE_EXTRA_CA_CERTS` সেট করা একটি শেল থেকে চালু করতে হয় (§3.2 দেখুন)। এটি অনুপস্থিত থাকার লক্ষণ: IDE ব্যাকএন্ড প্রমাণীকৃত হয় (MITM-এ `200` দেখা যায়), কিন্তু UI লগ-আউট অবস্থায় থাকে।
- **একই IDE-এর একাধিক ইনস্টলেশন স্বাধীন**: একটি সিস্টেম ইনস্টলেশন (যেমন `/usr/share/antigravity/antigravity`) এবং ব্যবহারকারী-স্থানীয় "Full" ইনস্টলেশন (যেমন `~/AntigravityIDE_Full/antigravity-ide`) নিজস্ব রানটাইমসহ পৃথক প্রক্রিয়া — প্রতিটিকেই CA ইনজেক্ট করে পুনরায় চালু করতে হবে। পুনরায় চালুর আগে কোনটি চলছে তা তার বাইনারি পাথ দিয়ে শনাক্ত করুন।
- **পরিচয় রাউট করা মডেল দিয়ে নয়, এজেন্টের সিস্টেম প্রম্পট দিয়ে নির্ধারিত হয়**: কোনো এজেন্টের মডেলকে অন্য প্রদানকারীতে রিম্যাপ করলে, উত্তরটি তবুও এজেন্টের নিজস্ব পরিচয় দাবি করে (যেমন Antigravity উত্তর দেয় "আমি Gemini দ্বারা চালিত") কারণ IDE সিস্টেম প্রম্পটে এটি ইনজেক্ট করে। মডেলটিকে তার পরিচয় জিজ্ঞাসা না করে `call_logs` / `proxy_logs`-এ (`provider`, `model`, `target_format`) প্রকৃত ব্যাকএন্ড নিশ্চিত করুন।

## §6 সমস্যা সমাধান

### পোর্ট 443-এর সংঘাত

যদি অন্য কোনো প্রসেস ইতিমধ্যেই পোর্ট 443-এ লিসেন করে থাকে (ওয়েব সার্ভার, VPN, ইত্যাদি):

```bash
lsof -i :443          # প্রসেসটি খুঁজুন
sudo fuser -k 443/tcp  # জোর করে বন্ধ করুন (সতর্কতার সঙ্গে ব্যবহার করুন)
```

বিকল্পভাবে, AgentBridge সেটিংসে একটি নন-প্রিভিলেজড পোর্ট কনফিগার করুন এবং `iptables` / `pf` রিডাইরেক্ট রুল সেট আপ করুন।

### সার্টিফিকেট বিশ্বস্ত নয়

AgentBridge চালু করার পরে IDE যদি TLS ত্রুটি দেখায়:

1. সার্টিফিকেটটি ইনস্টল করা হয়েছে কি না যাচাই করুন: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) অথবা `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. কিছু অ্যাপ নিজস্ব ট্রাস্ট স্টোর রক্ষণাবেক্ষণ করে (Firefox, Linux-এ Chrome)। আবার "Trust Cert" চালান এবং NSS/Firefox-নির্দিষ্ট সার্টিফিকেট স্টোর পরীক্ষা করুন।
3. বিশ্বাসযোগ্য হিসেবে চিহ্নিত করার পরে IDE পুনরায় চালু করুন — চলমান TLS সেশনগুলো পুরোনো ট্রাস্ট স্টেট ব্যবহার করে।

### বিশ্বস্ত CA থাকা সত্ত্বেও IDE লগ-আউট / "connection error"

লক্ষণ: DNS রিডাইরেক্ট এবং CA-কে বিশ্বাসযোগ্য হিসেবে চিহ্নিত করার পরে Electron-ভিত্তিক কোনো IDE (যেমন Antigravity)
**লগ-আউট অবস্থায়** খোলে অথবা একটি প্রমাণীকরণ/সংযোগ ত্রুটি দেখায়, অথচ MITM লগে
বুটস্ট্র্যাপ কলগুলো (`loadCodeAssist`, `fetchAvailableModels`, …) `200` রিটার্ন করতে দেখা যায়।

কারণ: IDE-এর **বান্ডেল করা Node/Electron রানটাইম OS-এর ট্রাস্ট স্টোর উপেক্ষা করে**। নেটিভ
ব্যাকএন্ড (একটি Go ল্যাঙ্গুয়েজ সার্ভার) OS CA-কে বিশ্বাস করে এবং প্রমাণীকরণ সম্পন্ন করে, কিন্তু Electron ফ্রন্টএন্ড
তা করে না — ফলে UI মনে করে এটি অফলাইন।

সমাধান (উভয় ধাপ): `NODE_EXTRA_CA_CERTS=<ca.crt>` এক্সপোর্ট করুন **এবং সেই
শেল থেকেই IDE পুনরায় চালু করুন**, ডেস্কটপ আইকন থেকে নয়। প্রথমে IDE সম্পূর্ণভাবে বন্ধ করুন — Electron-এর সিঙ্গেলটন লকের কারণে
দ্বিতীয়বার চালু করলে সেটি শুধু বিদ্যমান প্রসেসটিকে ফোকাস করে এবং নতুন এনভায়রনমেন্ট উপেক্ষিত হয়। §3.2 দেখুন।
এটি একটি উন্মুক্ত আপস্ট্রিম রিপোর্টের সঙ্গে সামঞ্জস্যপূর্ণ, যেখানে একটি স্বতন্ত্র এজেন্ট MITM-এর মাধ্যমে কাজ করে, কিন্তু একই
সেটআপে IDE ভ্যারিয়েন্টটি ব্যর্থ হয়।

### DNS প্রচারিত হয়নি

`/etc/hosts` আপডেট করা হয়েছে কি না পরীক্ষা করুন:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

DNS ক্যাশ ফ্লাশ করুন:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### IDE শনাক্ত হয়নি

স্বয়ংক্রিয় শনাক্তকরণ সাধারণ ইনস্টলেশন পাথ ব্যবহার করে। শনাক্তকরণ ব্যর্থ হলেও IDE ইনস্টল করা থাকলে:

- IDE বাইনারিটি কোনো অপ্রচলিত লোকেশনে আছে কি না পরীক্ষা করুন
- Setup Wizard তবুও কাজ করবে — শনাক্তকরণ ব্যর্থতার অর্থ শুধু ব্যাজে ইনস্টলেশন পাথ দেখানো হবে না

### হ্যান্ডলার ত্রুটি (আপস্ট্রিম ফেচ ব্যর্থ)

AgentBridge ইন্টারসেপ্ট করলেও যদি সব রিকোয়েস্ট ব্যর্থ হয়:

1. `/dashboard/providers`-এ অন্তত একটি প্রোভাইডার সংযুক্ত আছে কি না যাচাই করুন
2. OmniRoute সার্ভার লগ পরীক্ষা করুন: `.env`-এ `APP_LOG_LEVEL=debug`
3. `OMNIROUTE_BASE_URL` সঠিক রাউটার এন্ডপয়েন্ট নির্দেশ করছে কি না যাচাই করুন (ডিফল্ট: `http://127.0.0.1:20128`)

## §8 রোডম্যাপ

### Trae অনুসন্ধান

Trae একটি তুলনামূলকভাবে নতুন AI কোডিং সহকারী। একটি হ্যান্ডলার বাস্তবায়নের আগে:

1. VS Code / JetBrains মার্কেটপ্লেসে অথবা স্বতন্ত্র অ্যাপ হিসেবে বাইনারি/এক্সটেনশনটি শনাক্ত করুন
2. API হোস্ট ও এন্ডপয়েন্টের কাঠামো আবিষ্কার করতে mitmproxy দিয়ে ট্র্যাফিক ক্যাপচার করুন
3. প্রমাণীকরণ পদ্ধতি নির্ধারণ করুন
4. TOS এবং API আবিষ্কারযোগ্যতার ভিত্তিতে এগোনো/না-এগোনোর সিদ্ধান্ত নিন

অনুসন্ধান সম্পন্ন না হওয়া পর্যন্ত, ড্যাশবোর্ডে Trae কার্ডে একটি "অনুসন্ধানাধীন" ব্যাজ এবং "কার্যকারিতা প্রতিবেদন করুন" লিংক দেখানো হয়। `src/mitm/handlers/trae.ts`-এ থাকা হ্যান্ডলার স্টাবটি একটি কাঠামোবদ্ধ `এখনও বাস্তবায়িত হয়নি` ত্রুটি নিক্ষেপ করে।

### ব্যাকলগ এজেন্টসমূহ (MITM আবশ্যক — কাস্টম বেস URL সমর্থিত নয়)

নিম্নলিখিত টুলগুলো তাদের বর্তমান সংস্করণে কাস্টম বেস URL সমর্থন করে না, ফলে MITM-ই একমাত্র ইন্টারসেপশন পদ্ধতি। কার্যকারিতা মূল্যায়ন এখনও বাকি:

- **Windsurf** (Codeium/Cognition)
- **Amp** (Sourcegraph)
- **Amazon Q / Kiro CLI** (AWS Bedrock — Kiro IDE থেকে পৃথক)
- **Cowork** (Anthropic ডেস্কটপ)

দ্রষ্টব্য: GitHub Copilot CLI ≥v1.0.19 `COPILOT_PROVIDER_BASE_URL` সমর্থন করে — ওই টুলটির জন্য MITM-এর পরিবর্তে সরাসরি কনফিগারেশন ব্যবহার করুন।
