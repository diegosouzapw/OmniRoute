OmniRoute তৃতীয়-পক্ষের ক্লাউডে হোস্ট করা কোডিং এজেন্টগুলোকে (Codex Cloud, Cursor,
Devin, Jules) দীর্ঘমেয়াদি টাস্ক হিসেবে সমন্বয় করে। প্রতিটি এজেন্টকে একটি অভিন্ন ইন্টারফেসের
আড়ালে আবদ্ধ করা হয়েছে, যাতে ক্লায়েন্টরা প্রোভাইডার-নির্দিষ্ট API নিয়ে কাজ না করেই একটি
প্রম্পট + রিপোজিটরি URL জমা দিতে এবং ফলাফল পেতে পারে।

একটি Cloud Agent টাস্ক সাধারণ চ্যাট কমপ্লিশন **নয়**। এটি একটি স্থায়ী, বহু-ধাপের
কাজের একক, যা সম্পন্ন হতে কয়েক মিনিট থেকে কয়েক ঘণ্টা লাগতে পারে, আর্টিফ্যাক্ট হিসেবে
একটি Pull Request তৈরি করতে পারে এবং ফলো-আপ বার্তা ও (কিছু প্রোভাইডারের ক্ষেত্রে)
পরিকল্পনা অনুমোদনের ধাপ সমর্থন করে।

## আর্কিটেকচার

```
ক্লায়েন্ট (ড্যাশবোর্ড / CLI / API)
  → POST /api/v1/agents/tasks (ম্যানেজমেন্ট অথেনটিকেশন আবশ্যক)
    → CreateCloudAgentTaskSchema যাচাইকরণ (Zod)
    → registry.getAgent(providerId)
    → getCloudAgentCredentials(providerId)
      └─ getProviderConnections({ provider, isActive: true }) থেকে সংগ্রহ করে
         (প্রথমে apiKey, না পাওয়া গেলে accessToken)
    → agent.createTask({ prompt, source, options }, credentials)
      └─ আপস্ট্রিম প্রোভাইডার API-তে HTTP POST
      └─ অভ্যন্তরীণ id + externalId-সহ CloudAgentTask ফেরত দেয়
    → cloud_agent_tasks-এ insertCloudAgentTask(...) (SQLite)

পোলিং (পড়ার সময় অলস সিঙ্ক):
  GET /api/v1/agents/tasks/[id]
    → getCloudAgentTaskById(id)
    → agent.getStatus(externalId, credentials)  // স্ট্যাটাস + কার্যকলাপ হালনাগাদ করে
    → নতুন স্ট্যাটাস, ফলাফল, completed_at দিয়ে updateCloudAgentTask(...)
    → সিরিয়ালাইজ করা টাস্ক ফেরত দেয়

ইন্টার্যাকশন:
  POST /api/v1/agents/tasks/[id]  বডি: { action: "approve" | "message" | "cancel" }
    → agent.approvePlan(externalId, credentials)        "approve"-এর জন্য
    → agent.sendMessage(externalId, message, credentials) "message"-এর জন্য
    → স্ট্যাটাস "cancelled"-এ পরিবর্তিত হয়              "cancel"-এর জন্য (শুধু লোকাল)
```

সিঙ্ক **অলসভাবে** হয়: প্রতিবার `GET /tasks/[id]` অনুরোধে আপস্ট্রিম থেকে স্ট্যাটাস
হালনাগাদ করা হয়। কোনো ব্যাকগ্রাউন্ড পোলার নেই। যেসব ড্যাশবোর্ডে হালনাগাদ অবস্থা প্রয়োজন,
সেগুলোর উচিত যুক্তিসংগত বিরতিতে GET এন্ডপয়েন্টটি পোল করা।

## `CloudAgentBase` ইন্টারফেস

উৎস: `src/lib/cloudAgent/baseAgent.ts`

```typescript
export interface AgentCredentials {
  apiKey: string;
  baseUrl?: string;
}

export interface CreateTaskParams {
  prompt: string;
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
}

export interface GetStatusResult {
  status: CloudAgentStatus;
  externalId?: string;
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
}

export abstract class CloudAgentBase {
  abstract readonly providerId: string;
  abstract readonly baseUrl: string;

  abstract createTask(p: CreateTaskParams, c: AgentCredentials): Promise<CloudAgentTask>;
  abstract getStatus(externalId: string, c: AgentCredentials): Promise<GetStatusResult>;
  abstract approvePlan(externalId: string, c: AgentCredentials): Promise<void>;
  abstract sendMessage(
    externalId: string,
    message: string,
    c: AgentCredentials
  ): Promise<CloudAgentActivity>;
  abstract listSources(
    c: AgentCredentials
  ): Promise<{ name: string; url: string; branch?: string }[]>;

  protected mapStatus(raw: string): CloudAgentStatus; // হিউরিস্টিক আপস্ট্রিম-স্ট্রিং → enum
  protected generateTaskId(): string; // `task_<ts>_<rand>`
  protected generateActivityId(): string; // `act_<ts>_<rand>`
}
```

`CodexCloudAgent.approvePlan` ইচ্ছাকৃতভাবে ত্রুটি নিক্ষেপ করে — Codex Cloud স্বয়ংক্রিয়ভাবে পরিকল্পনা করে এবং এতে
কোনো অনুমোদন গেট নেই। `CodexCloudAgent.listSources` `[]` ফেরত দেয়।

`CursorCloudAgent`, Cursor-এর Background / Cloud Agents-কে এর অফিসিয়াল REST
API (`api.cursor.com/v0`)-এর মাধ্যমে **ব্যবহারকারী বা সার্ভিস-অ্যাকাউন্ট API key** দিয়ে পরিচালনা করে — এটি Cursor IDE-এর OAuth সেশন পুনরায় ব্যবহার করার তুলনায় নিরাপদ,
প্রথম-পক্ষীয় বিকল্প (প্রোভাইডার `cursor`,
যার সঙ্গে নিষিদ্ধ হওয়ার ঝুঁকির সতর্কতা রয়েছে)। এটি একটি সাধারণ REST অ্যাডাপ্টার (কোনো `@cursor/sdk` নেটিভ
ডিপেন্ডেন্সি নেই)। `approvePlan` ত্রুটি নিক্ষেপ করে (Cursor এজেন্টগুলো স্বায়ত্তশাসিতভাবে চলে); `listSources` ওই key দিয়ে
অ্যাক্সেসযোগ্য রিপোজিটরিগুলোর তালিকা দেয়। Cursor বড় হাতের অক্ষরে স্ট্যাটাস enum
(`CREATING`/`RUNNING`/`FINISHED`/`ERROR`) ফেরত দেয়, যেগুলো স্পষ্টভাবে শেয়ার করা
`CloudAgentStatus`-এ ম্যাপ করা হয়। প্রতিটি ক্রেডেনশিয়ালের জন্য `baseUrl` ওভাররাইড করা যায়, ফলে কোড পরিবর্তন না করেই
API সংস্করণ/পাথ সংশোধন করা যায়।

## ডোমেইন টাইপসমূহ

উৎস: `src/lib/cloudAgent/types.ts`

```typescript
export const CLOUD_AGENT_STATUS = {
  QUEUED: "queued",
  RUNNING: "running",
  AWAITING_APPROVAL: "awaiting_approval",
  COMPLETED: "completed",
  FAILED: "failed",
  CANCELLED: "cancelled",
} as const;

export interface CloudAgentSource {
  repoName: string;
  repoUrl: string; // অবশ্যই একটি বৈধ URL হতে হবে
  branch?: string;
}

export interface CloudAgentResult {
  prUrl?: string;
  prNumber?: number;
  commitMessage?: string;
  diffUrl?: string;
  summary?: string;
  duration?: number; // সেকেন্ড, ধনাত্মক পূর্ণসংখ্যা
  cost?: number; // ধনাত্মক ফ্লোট
}

export interface CloudAgentActivity {
  id: string;
  type: "plan" | "command" | "code_change" | "message" | "error" | "completion";
  content: string;
  timestamp: string; // ISO 8601
  metadata?: Record<string, unknown>;
}

export interface CloudAgentTask {
  id: string; // অভ্যন্তরীণ `task_...` id
  providerId: "jules" | "devin" | "codex-cloud" | "cursor-cloud";
  externalId?: string; // আপস্ট্রিম প্রোভাইডারের id
  status: CloudAgentStatus;
  prompt: string; // 1..10000 অক্ষর
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
  createdAt: string;
  updatedAt: string;
  completedAt?: string;
}
```

ভ্যালিডেশন স্কিমাগুলো (`CreateCloudAgentTaskSchema`, `UpdateCloudAgentTaskSchema`)
টাইপগুলোর পাশাপাশি এক্সপোর্ট করা হয় এবং রুট হ্যান্ডলারগুলো এগুলো ব্যবহার করে।

## ডেটাবেস

উৎস: `src/lib/cloudAgent/db.ts` — টেবিলটি `createCloudAgentTaskTable()`-এর মাধ্যমে প্রয়োজন অনুযায়ী অলসভাবে তৈরি করা হয় (`src/lib/cloudAgent/index.ts` থেকেও মডিউল ইমপোর্টের সময় কল করা হয়)।

```sql
CREATE TABLE IF NOT EXISTS cloud_agent_tasks (
  id           TEXT PRIMARY KEY,
  provider_id  TEXT NOT NULL,
  external_id  TEXT,
  status       TEXT NOT NULL DEFAULT 'queued',
  prompt       TEXT NOT NULL,
  source       TEXT NOT NULL,             -- JSON
  options      TEXT DEFAULT '{}',         -- JSON
  result       TEXT,                       -- JSON
  activities   TEXT DEFAULT '[]',          -- JSON
  error        TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_provider ON cloud_agent_tasks(provider_id);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_status   ON cloud_agent_tasks(status);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_created  ON cloud_agent_tasks(created_at DESC);
```

SQL injection প্রতিরোধ করতে `updateCloudAgentTask` একটি **কলাম অনুমোদন-তালিকা** প্রয়োগ করে:
`status`, `prompt`, `source`, `options`, `result`, `activities`, `error`,
`completed_at`। আংশিক আপডেটে থাকা অন্য যেকোনো key নীরবে বাদ দেওয়া হয়।

## REST API — টাস্কের জীবনচক্র

**প্রমাণীকরণ:** সব `/api/v1/agents/tasks*` endpoint-এর জন্য **ম্যানেজমেন্ট প্রমাণীকরণ**
প্রয়োজন (`requireCloudAgentManagementAuth`, `src/lib/api/requireManagementAuth`-এর
`requireManagementAuth`-কে wrap করে)। commit `588a0333`-এর পর থেকে এটি প্রয়োগ করা হচ্ছে
(_"fix(auth): agent ও cooldown API-এর জন্য management auth আবশ্যক করা"_).

| মেথড    | পাথ                           | উদ্দেশ্য                                                           |
| ------- | ----------------------------- | ------------------------------------------------------------------ |
| OPTIONS | `/api/v1/agents/tasks`        | CORS preflight                                                     |
| GET     | `/api/v1/agents/tasks`        | টাস্কের তালিকা দেখানো (ফিল্টার: `provider`, `status`, `limit≤500`) |
| POST    | `/api/v1/agents/tasks`        | টাস্ক তৈরি করা (upstream-এ পাঠায় + সংরক্ষণ করে)                   |
| DELETE  | `/api/v1/agents/tasks?id=...` | query `id` অনুযায়ী টাস্ক মুছে ফেলা (upstream বাতিল করে **না**)    |
| OPTIONS | `/api/v1/agents/tasks/[id]`   | CORS preflight                                                     |
| GET     | `/api/v1/agents/tasks/[id]`   | টাস্ক পড়া + upstream থেকে অলসভাবে status sync করা                 |
| POST    | `/api/v1/agents/tasks/[id]`   | অ্যাকশন: `approve` / `message` / `cancel`                          |
| DELETE  | `/api/v1/agents/tasks/[id]`   | path `id` অনুযায়ী টাস্ক মুছে ফেলা                                 |

### টাস্ক তৈরি করা

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{

    "prompt": "Fix the bug in src/foo.ts where the parser returns null",
    "source": {
      "repoName": "user/repo",

      "branch": "main"
    },

    }

```

```json

    "externalId": "session_xyz",
```

### একটি পরিকল্পনা অনুমোদন করা

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"action":"approve"}'
```

### একটি follow-up বার্তা পাঠানো

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"message","message":"Also add a unit test for the parser"}'
```

### বাতিল করা (শুধু স্থানীয় status)

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"cancel"}'
```

`cancel` স্থানীয় DB-তে `status`-কে `"cancelled"`-এ পরিবর্তন করে, কিন্তু upstream
provider-কে কল করে **না** — `CloudAgentBase`-এ কোনো abort RPC নেই। upstream-এ
billing বন্ধ করতে provider-এর নিজস্ব console থেকে টাস্কটি terminate করুন।

## REST API — Cloud Provider প্লাম্বিং

`src/app/api/cloud/`-এর অধীনে থাকা এই সহায়ক এন্ডপয়েন্টগুলো দূরবর্তী ক্লায়েন্ট
(CLI, Electron অ্যাপ বা sync worker) ব্যবহার করে provider সংযোগের metadata পড়তে
এবং model alias সমাধান করতে। এগুলো task endpoint-এ ব্যবহৃত management auth দিয়ে নয়,
বরং একটি **নিয়মিত API key** (`validateApiKey`-এর মাধ্যমে) দিয়ে প্রমাণীকৃত হয়।

| পদ্ধতি | পাথ                             | উদ্দেশ্য                                                                       |
| ------ | ------------------------------- | ------------------------------------------------------------------------------ |
| POST   | `/api/cloud/auth`               | API key যাচাই করে masked connection metadata + model alias ফেরত দেয়           |
| PUT    | `/api/cloud/credentials/update` | `accessToken` / `refreshToken` / `expiresAt` রিফ্রেশ করে                       |
| POST   | `/api/cloud/model/resolve`      | একটি model alias-কে `{ provider, model }`-এ সমাধান করে                         |
| GET    | `/api/cloud/models/alias`       | সব model alias তালিকাভুক্ত করে                                                 |
| PUT    | `/api/cloud/models/alias`       | একটি model alias সেট করে (এবং সক্রিয় থাকলে Cloud-এ স্বয়ংক্রিয়ভাবে sync করে) |

`/api/cloud/auth` কখনোই raw `apiKey` / `accessToken` / `refreshToken` ফেরত দেয় না। এটি
`hasApiKey`, `hasAccessToken`, `hasRefreshToken` এবং একটি masked preview
(`maskedApiKey`: প্রথম 4 + `****` + শেষ 4) ফেরত দেয়।

## Credential নির্ধারণ

`src/lib/cloudAgent/api.ts`-এর `getCloudAgentCredentials(providerId)`:

1. `getProviderConnections({ provider: providerId, isActive: true })`-এর মাধ্যমে সক্রিয় provider connection লোড করে।
2. প্রতিটি connection-এর ক্ষেত্রে `apiKey`-কে (trim করে) অগ্রাধিকার দেয়। না থাকলে `accessToken` ব্যবহার করে।
3. প্রথম non-empty token-টি `{ apiKey: token }` হিসেবে মোড়ানো অবস্থায় ফেরত দেয়।
4. ব্যবহারযোগ্য কোনো token পাওয়া না গেলে `null` ফেরত দেয় — API তখন `400` সহ
   `"No active credentials configured for cloud agent provider: <id>"` দেয়।

এর অর্থ হলো, Cloud Agent-গুলো নিয়মিত LLM provider-এর মতো একই Provider Connection table
পুনরায় ব্যবহার করে। Jules সক্রিয় করতে `provider: "jules"` এবং পূরণ করা `apiKey`-সহ
একটি সক্রিয় connection তৈরি করুন।

## A2A-এর সঙ্গে Integration

এমন একটি A2A skill register করে Cloud Agent-গুলোকে A2A skill হিসেবে প্রকাশ করা যায়, যা
তার `tasks/send` handler-কে `getAgent(...).createTask(...)`-এ delegate করে এবং A2A task
status event-গুলোকে JSON-RPC 2.0 protocol-এ রূপান্তর করে। [A2A-SERVER.md](./A2A-SERVER.md) দেখুন।

## নতুন Cloud Agent যোগ করা

1. `CloudAgentBase` extend করে `src/lib/cloudAgent/agents/<name>.ts` তৈরি করুন।
2. `createTask`, `getStatus`, `approvePlan` (অথবা প্রযোজ্য না হলে throw করুন),
   `sendMessage`, `listSources` implement করুন। status normalization-এর জন্য `this.mapStatus(...)` ব্যবহার করুন।
3. একটি স্থিতিশীল `providerId`-এর অধীনে `src/lib/cloudAgent/registry.ts`-এ register করুন।
4. `src/lib/cloudAgent/types.ts`-এর `providerId` literal union extend করুন
   (`CloudAgentTask.providerId` এবং `CreateCloudAgentTaskSchema`)।
5. provider-টির connection record প্রয়োজন হলে সেটিকে `src/shared/constants/providers.ts`-এ যোগ করুন।
   OAuth-ভিত্তিক provider-এর জন্য `src/lib/oauth/providers/`-ও প্রয়োজন।
6. `tests/unit/cloud-agent-*.test.ts`-এর অধীনে test যোগ করুন।
7. এই doc এবং dashboard-এর `CLOUD_AGENTS` constant আপডেট করুন।
