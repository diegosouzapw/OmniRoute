OmniRoute-এ একটি লোকাল-ফার্স্ট গেমিফিকেশন স্তর রয়েছে, যা প্ল্যাটফর্মের সঙ্গে
সম্পৃক্ত থাকার জন্য ব্যবহারকারীদের পুরস্কৃত করে — অনুরোধ করা, প্রদানকারী পরিবর্তন করা,
কম্বো তৈরি করা, টোকেন শেয়ার করা এবং কমিউনিটিতে অবদান রাখা। সমস্ত স্টেট
SQLite-এ থাকে; কমিউনিটি সার্ভারের সঙ্গে ফেডারেশন ঐচ্ছিক এবং পুশ-ভিত্তিক।

সিস্টেমটি এমনভাবে নকশা করা হয়েছে যেন **হট পাথে শূন্য ল্যাটেন্সি** থাকে — গেমিফিকেশন
ইভেন্টগুলো রিকোয়েস্ট পাইপলাইন থেকে ফায়ার-অ্যান্ড-ফরগেট পদ্ধতিতে পাঠানো হয় এবং কখনোই
কোনো LLM প্রতিক্রিয়াকে অবরুদ্ধ করে না।

## সংক্ষিপ্ত বিবরণ

### উদ্দেশ্য

দৃশ্যমান অগ্রগতি (XP, লেভেল, ব্যাজ), সামাজিক স্বীকৃতি (লিডারবোর্ড) এবং
অর্থনৈতিক প্রণোদনা (টোকেন শেয়ারিং, আমন্ত্রণ পুরস্কার) প্রদানের মাধ্যমে ব্যবহারকারীর
সম্পৃক্ততা ও ধরে রাখার হার বৃদ্ধি করা।

### পরিধি

| ফিচার            | বিবরণ                                                                   |
| ---------------- | ----------------------------------------------------------------------- |
| XP ও লেভেল       | প্রতিটি অ্যাকশনে XP অর্জন; একটি পলিনোমিয়াল কার্ভ অনুযায়ী লেভেল বৃদ্ধি |
| ব্যাজ            | ৪টি বিরলতার স্তরসহ ৫টি বিভাগে ২০টির বেশি অর্জন                          |
| স্ট্রিক          | বর্তমান/দীর্ঘতম স্ট্রিকসহ দৈনিক সক্রিয় ব্যবহারের ট্র্যাকিং             |
| লিডারবোর্ড       | গ্লোবাল, সাপ্তাহিক, মাসিক, টোকেন-শেয়ারিং এবং অবদানভিত্তিক স্কোপ        |
| টোকেন শেয়ারিং   | ডাবল-এন্ট্রি লেজারের মাধ্যমে ব্যবহারকারীদের মধ্যে ক্রেডিট স্থানান্তর    |
| আমন্ত্রণ ও রিডিম | SHA-256 হ্যাশ করা স্টোরেজসহ রেফারেল কোড                                 |
| কমিউনিটি সার্ভার | বহিরাগত OmniRoute ইনস্ট্যান্সের সঙ্গে ফেডারেশন                          |
| অ্যান্টি-চিট     | সার্ভার-সাইড স্কোরিং, রেট লিমিটিং, z-score অস্বাভাবিকতা শনাক্তকরণ       |

### নকশার মূলনীতি

1. **লোকাল-ফার্স্ট** — সমস্ত স্টেট SQLite-এ থাকে, কোনো বহিরাগত পরিষেবার প্রয়োজন নেই।
2. **নন-ব্লকিং** — ইভেন্টগুলো ফায়ার-অ্যান্ড-ফরগেট; গেমিফিকেশন লজিকের কারণে
   LLM প্রতিক্রিয়ার পথ কখনো বিলম্বিত হয় না।
3. **সার্ভার-অথরিটেটিভ** — XP কেবল সার্ভার-সাইডে গণনা করা হয়; ক্লায়েন্টরা
   স্কোর কৃত্রিমভাবে বাড়াতে পারে না।
4. **গোপনীয়তার প্রতি শ্রদ্ধাশীল** — লিডারবোর্ডে অংশগ্রহণ ঐচ্ছিক; ব্যবহারকারীরা
   তাঁদের প্রোফাইল লুকাতে পারেন।
5. **ফেডারেশন-প্রস্তুত** — কমিউনিটি সার্ভারগুলো স্বাক্ষরিত API-এর মাধ্যমে স্কোর পুশ করতে পারে;
   সিঙ্ক ওভাররাইট করে, যোগ করে না।

## আর্কিটেকচার

### উচ্চ-স্তরের প্রবাহ

```
ক্লায়েন্ট অনুরোধ
  → /v1/chat/completions
    → handleChatCore()                      [open-sse/handlers/chatCore.ts]
      → ... (বিদ্যমান পাইপলাইন) ...
      → আপস্ট্রিম প্রতিক্রিয়া ক্লায়েন্টের কাছে পাঠানো হয়েছে
      → setImmediate (ফায়ার-অ্যান্ড-ফরগেট):
        → emitGamificationEvent()           [src/lib/gamification/events.ts]
          → awardXp()                       [src/lib/gamification/xp.ts]
          → updateStreak()                  [src/lib/gamification/streaks.ts]
          → evaluateBadges()                [src/lib/gamification/badges.ts]
          → updateLeaderboard()             [src/lib/gamification/leaderboard.ts]
          → checkAnomalies()                [src/lib/gamification/antiCheat.ts]
```

ইভেন্ট এমিটারটি একমাত্র ইন্টিগ্রেশন পয়েন্ট। প্রতিক্রিয়া পাঠানোর পর `chatCore.ts`
`emitGamificationEvent()` কল করে; ইভেন্ট মডিউলটি XP, স্ট্রিক, ব্যাজ,
লিডারবোর্ড এবং অ্যান্টি-চিট সাবসিস্টেমে ইভেন্ট বিতরণ করে।

### ডোমেইন মডিউল: `src/lib/db/gamification.ts`

এটি আদর্শ OmniRoute প্যাটার্ন অনুসরণ করে — `core.ts` থেকে `getDbInstance()`
ইমপোর্ট করে এবং টাইপযুক্ত CRUD ফাংশন এক্সপোর্ট করে। রুট হ্যান্ডলারগুলোতে কোনো কাঁচা SQL নেই।

প্রধান ফাংশনসমূহ:

| ফাংশন                      | বিবরণ                                                           |
| -------------------------- | --------------------------------------------------------------- |
| `upsertLeaderboardEntry()` | (api_key_id, scope, period)-এর জন্য স্কোর যোগ বা হালনাগাদ করে   |
| `getLeaderboard()`         | প্রদত্ত scope/period-এর জন্য পৃষ্ঠাঙ্কিত র্যাঙ্কিং              |
| `getUserLevel()`           | ব্যবহারকারীর লেভেল রেকর্ড নিয়ে আসে বা তৈরি করে                 |
| `updateUserLevel()`        | XP, লেভেল এবং শিরোনাম পারমাণবিকভাবে সেট করে                     |
| `getBadgeDefinitions()`    | সব ব্যাজের সংজ্ঞা (ঐচ্ছিকভাবে ফিল্টার করা)                      |

### পুরস্কার প্রদানের প্রবাহ

```typescript
export async function awardXp(
  apiKeyId: string,
  action: XpAction,
  metadata?: Record<string, unknown>
): Promise<{ xp: number; level: number; title: string; levelUp: boolean }>;
```

1. XP-এর পরিমাণ পেতে `XP_REWARDS[action]`-এ খুঁজুন।
2. `checkRateLimit()`-এর মধ্য দিয়ে পাঠান (প্রতারণা প্রতিরোধ: প্রতি কী-এর জন্য সর্বোচ্চ 1000 XP/মিনিট)।
3. একটি ট্রানজ্যাকশন খুলুন:
   - বর্তমান `user_levels` সারিটি পড়ুন।
   - XP যোগ করুন; `levelFromXp(totalXp)` ব্যবহার করে লেভেল পুনরায় গণনা করুন।
   - লেভেল পরিবর্তিত হলে `levelUp = true` সেট করুন।
   - `user_levels` সারিটি আপডেট করুন।
   - `xp_audit_log`-এ ইনসার্ট করুন।
4. ফলাফল রিটার্ন করুন। কলার নোটিফিকেশন পরিচালনা করে।

### সহায়ক: `levelFromXp(totalXp)`

লেভেল 1..100 পর্যন্ত ইটারেট করে এবং ক্রমযোজিত XP `totalXp` অতিক্রম না করা পর্যন্ত `xp_for_level(n)` যোগ করে।
যে সর্বোচ্চ লেভেলের থ্রেশহোল্ড পূরণ হয়েছে, সেটি রিটার্ন করে।
এটি O(100) — গ্রহণযোগ্য, কারণ লেভেলের সর্বোচ্চ সীমা 100।

### মূল্যায়ন প্রবাহ

```

  → evaluateBadges(apiKeyId, event)
    → getBadgeDefinitions()           # সব সংজ্ঞা
    → getUserBadges(apiKeyId)         # ইতিমধ্যে অর্জিত (এড়িয়ে যান)
    → প্রতিটি অনর্জিত ব্যাজের জন্য:
       → matchesCriteria(badge, event, userState)
       → মিললে: awardBadge(apiKeyId, badgeId)
```

মূল্যায়নকে দ্রুত রাখে (অধিকাংশ ইভেন্টের জন্য < 5ms)।

## স্ট্রিক ট্র্যাকার

**ফাইল:** `src/lib/gamification/streaks.ts`

### ডেটা মডেল

স্ট্রিকগুলো নেমস্পেসযুক্ত কী-এর অধীনে `key_value` টেবিলে (শেয়ার্ড ইউটিলিটি টেবিল) সংরক্ষণ করা হয়:

| কী                            | মান                              | বিবরণ                  |
| ----------------------------- | -------------------------------- | ---------------------- |
| `gamification:streak:{keyId}` | `{current},{longest},{lastDate}` | সক্রিয় স্ট্রিকের ডেটা |

### লজিক

```typescript
export async function updateStreak(
  apiKeyId: string
): Promise<{ current: number; longest: number; milestone: boolean }>;
```

1. `key_value` থেকে স্ট্রিক রেকর্ড পড়ুন।
2. `{current}`, `{longest}`, `{lastDate}` (ISO তারিখের স্ট্রিং) পার্স করুন।
3. যদি `lastDate === today` হয় — কোনো পরিবর্তন নয় (আজ ইতিমধ্যেই গণনা করা হয়েছে)।
4. যদি `lastDate === yesterday` হয় — `current` বৃদ্ধি করুন; প্রয়োজন হলে `longest` আপডেট করুন।
5. যদি `lastDate < yesterday` হয় — `current = 1`-এ রিসেট করুন (স্ট্রিক ভেঙে গেছে)।
6. আপডেট করা রেকর্ড লিখুন।
7. মাইলস্টোন পরীক্ষা করুন: 7, 14, 30, 60, 90, 180, 365 দিন। অতিক্রম করলে
   `milestone = true` সেট করুন (কলকারী XP প্রদান করে এবং ব্যাজ পরীক্ষা করে)।

### বিশেষ পরিস্থিতি

- **টাইমজোন**: স্ট্রিকগুলো UTC তারিখ ব্যবহার করে (`new Date().toISOString().slice(0, 10)`)।
  এটি ইচ্ছাকৃত—একটি একক প্রামাণ্য টাইমজোন ব্যবহারের ফলে টাইমজোন পরিবর্তন করে
  সিস্টেমকে অপব্যবহার করা যায় না।
- **নতুন ব্যবহারকারী**: কোনো স্ট্রিক রেকর্ড থাকে না; প্রথম অনুরোধে
  `current=1, longest=1, lastDate=today` সহ এটি তৈরি করা হয়।
- **প্রতিদিন একাধিক অনুরোধ**: UTC দিনের কেবল প্রথম অনুরোধটিই
  স্ট্রিক বৃদ্ধি করে।

র্যাঙ্ক সংরক্ষণ করা হয় না, বরং **পড়ার সময় গণনা করা হয়**। এটি পুরোনো র্যাঙ্ক ডেটা এড়ায়
এবং পর্যায়ক্রমিক র্যাঙ্ক পুনর্গণনার জবের প্রয়োজন দূর করে।

```typescript
export async function getLeaderboard(
  scope: LeaderboardScope,
  period: string,
  limit: number,
  offset: number
): Promise<{ entries: LeaderboardEntry[]; total: number }>;
```

কোয়েরির ধরন:

```sql
SELECT api_key_id, score,
       RANK() OVER (ORDER BY score DESC) as rank
FROM leaderboard
WHERE scope = ? AND period = ?
ORDER BY score DESC
LIMIT ? OFFSET ?
```

## টোকেন শেয়ারিং

**ফাইল:** `src/lib/gamification/sharing.ts`

### ডাবল-এন্ট্রি লেজার

প্রতিটি ট্রান্সফার `token_ledger`-এ দুটি সারি তৈরি করে:

| সারি    | `from_key_id` | `to_key_id` | `amount` |
| ------- | ------------- | ----------- | -------- |
| ডেবিট   | প্রেরক        | প্রাপক      | +amount  |
| ক্রেডিট | প্রাপক        | প্রেরক      | -amount  |

অপেক্ষা করুন — প্রচলিত নিয়মটি হলো:

| সারি   | `from_key_id` | `to_key_id` | `amount` | অর্থ                 |
| ------ | ------------- | ----------- | -------- | -------------------- |
| প্রেরণ | প্রেরক        | প্রাপক      | +amount  | প্রেরকের বহিঃপ্রবাহ  |
| গ্রহণ  | প্রাপক        | প্রেরক      | +amount  | প্রাপকের অন্তঃপ্রবাহ |

ব্যালেন্স এভাবে গণনা করা হয়:

```sql
SELECT
  COALESCE(SUM(CASE WHEN to_key_id = ? THEN amount ELSE 0 END), 0)
  - COALESCE(SUM(CASE WHEN from_key_id = ? THEN amount ELSE 0 END), 0)
  AS balance
FROM token_ledger
WHERE from_key_id = ? OR to_key_id = ?
```

### ট্রান্সফার প্রবাহ

```typescript
export async function transferTokens(
  fromKeyId: string,
  toKeyId: string,
  amount: number,
  idempotencyKey: string
): Promise<{ success: boolean; balance: number }>;
```

1. **যাচাই**: `amount > 0`, `fromKeyId !== toKeyId`।
2. **আইডেমপোটেন্সি**: লেজারে `idempotency_key` ইতিমধ্যে বিদ্যমান কি না পরীক্ষা করুন।
   বিদ্যমান থাকলে, ক্যাশ করা ফলাফল ফেরত দিন।
3. **ট্রানজ্যাকশন** (একটি একক SQLite ট্রানজ্যাকশন):
   a. প্রেরকের ব্যালেন্স গণনা করুন।
   b. যদি `balance < amount` হয়, বাতিল করুন (পর্যাপ্ত তহবিল নেই)।
   c. প্রেরণ সারি ইনসার্ট করুন (`from=sender,` ফেরত দিন।

### রেট লিমিটিং

- প্রতি API কী-র জন্য প্রতি মিনিটে সর্বোচ্চ ১০টি ট্রান্সফার।
- একটি ট্রান্সফারে সর্বোচ্চ ১০,০০০ টোকেন।
- প্রতি API কী-র জন্য প্রতিদিন সর্বোচ্চ ১,০০,০০০ টোকেন ট্রান্সফার।

## টোকেন আমন্ত্রণ ও রিডিম করা

**ফাইল:** `src/lib/gamification/invites.ts`

### কোডের ফরম্যাট

- **কোড**: ৮-অক্ষরের আলফানিউমেরিক কোড (যেমন, `A3K9-X7M2`), সহজে পাঠযোগ্য,
  ব্যবহারকারীর কাছে প্রদর্শিত হয়।
- **টোকেন**: ৩২-বাইটের র্যান্ডম টোকেন, SHA-256 হ্যাশ হিসেবে সংরক্ষিত। প্রোগ্রামভিত্তিক
  রিডেম্পশনের জন্য ব্যবহৃত হয় (যেমন, URL লিংক)।

### সংরক্ষণ

| কলাম         | মান                            |
| ------------ | ------------------------------ |
| `code`       | `A3K9X7M2` (অনন্য, ইনডেক্সকৃত) |
| `token_hash` | SHA-256(raw_token)             |

তৈরির সময় র টোকেনটি ব্যবহারকারীকে ঠিক একবার ফেরত দেওয়া হয়। OmniRoute
এটি আর কখনও সংরক্ষণ বা প্রদর্শন করে না — কেবল হ্যাশটি সংরক্ষিত থাকে।

### স্ব-রেফারেল প্রতিরোধ

কোনো ব্যবহারকারী একটি কোড রিডিম করলে, সিস্টেম পরীক্ষা করে:

1. কোডটি ভিন্ন একটি `api_key_id`-এর অন্তর্গত।
2. রিডিমকারী ব্যবহারকারী একই রেফারারের কোনো কোড আগে রিডিম করেননি
   (`invite_tokens` + রিডেম্পশন লগে join ব্যবহার করে)।

যেকোনো একটি পরীক্ষা ব্যর্থ হলে, স্পষ্ট ত্রুটি বার্তাসহ রিডেম্পশনটি প্রত্যাখ্যান করা হয়।

### মেয়াদ ও সীমা

- ডিফল্ট `max_uses`: ১০ (তৈরির সময় কনফিগারযোগ্য)।
- ডিফল্ট `expires_at`: তৈরির সময় থেকে ৩০ দিন।
- মেয়াদোত্তীর্ণ বা ব্যবহারসীমা শেষ হওয়া কোড HTTP 410 Gone ফেরত দেয়।

## কমিউনিটি সার্ভার ফেডারেশন

**ফাইল:** `src/lib/gamification/servers.ts`

### সংযোগ

রিমোট সার্ভার থেকে ইস্যু করা একটি আমন্ত্রণ টোকেনের মাধ্যমে একটি কমিউনিটি সার্ভার নিবন্ধিত হয়। লোকাল ইনস্ট্যান্সটি:

1. আমন্ত্রণ টোকেনটি গ্রহণ করে (যেমন, ড্যাশবোর্ডে পেস্ট করা হয়)।
2. টোকেনটি যাচাই করতে এবং বর্তমান লিডারবোর্ড আনতে রিমোট সার্ভারে `POST /api/gamification/federation/leaderboard` কল করে।
3. `status: connected` সহ সার্ভার রেকর্ডটি সংরক্ষণ করে।

### সিঙ্ক মডেল

ফেডারেশন **ওভাররাইট সিঙ্ক** ব্যবহার করে, অ্যাডিটিভ সিঙ্ক নয়:

```
লোকাল ইনস্ট্যান্স               কমিউনিটি সার্ভার
     │                              │
     ├── স্কোর পুশ ────────────────►│  POST /federation/score
     │   { api_key_id, score }      │  (সার্ভার টোকেন হ্যাশ যাচাই করে)
     │                              │
     ├── লিডারবোর্ড পুল ──────────►│  GET /federation/leaderboard
     │◄── শীর্ষ-N এন্ট্রি ─────────┤  (লোকাল ক্যাশ ওভাররাইট করে)
     │                              │
     └── স্বাস্থ্য পরীক্ষা ────────►│  GET /federation/health
         (প্রতি 60s-এ, টাইমআউট 5s) │
```

### প্রমাণীকরণ

ফেডারেশন অনুরোধে অন্তর্ভুক্ত থাকে:

```
Authorization: Bearer <raw_token>
X-Federation-Version: 1
```

রিমোট সার্ভার টোকেনটি হ্যাশ করে এবং মিলে যাওয়া `community_servers` সারিটি খুঁজে বের করে। এটি সংরক্ষিত হ্যাশ প্রেরণ করা এড়ায়।

### স্বাস্থ্য পর্যবেক্ষণ

প্রতিটি সার্ভার রেকর্ডে নিম্নলিখিত তথ্য ট্র্যাক করা হয়:

| ফিল্ড       | বিবরণ                                  |
| ----------- | -------------------------------------- |
| `status`    | `connected`, `degraded`, `unreachable` |
| `last_sync` | সর্বশেষ সফল সিঙ্কের ISO টাইমস্ট্যাম্প  |
| `failures`  | পরপর ব্যর্থ স্বাস্থ্য পরীক্ষার সংখ্যা  |

পরপর 5টি ব্যর্থতার পর স্ট্যাটাস `unreachable`-এ পরিবর্তিত হয় এবং একটি ম্যানুয়াল স্বাস্থ্য পরীক্ষা সফল না হওয়া পর্যন্ত সিঙ্ক স্থগিত থাকে।

## প্রতারণা প্রতিরোধ

**ফাইল:** `src/lib/gamification/antiCheat.ts`

### সার্ভার-সাইড স্কোরিং

সব XP গণনা `src/lib/gamification/xp.ts`-এ সম্পন্ন হয়। ক্লায়েন্ট কখনো স্কোর জমা দেয় না—তারা অ্যাকশন জমা দেয় এবং সার্ভার XP গণনা করে। `leaderboard.score` কলামটি কেবল সার্ভার-সাইড কোড দ্বারা লেখার উপযোগী।

### রেট লিমিটিং

| সীমা                             | মান     | পরিধি            |
| -------------------------------- | ------- | ---------------- |
| প্রতি মিনিটে সর্বোচ্চ XP         | 1,000   | প্রতি API কী     |
| প্রতি মিনিটে সর্বোচ্চ ট্রান্সফার | 10      | প্রতি API কী     |
| সর্বোচ্চ ট্রান্সফারের পরিমাণ     | 10,000  | প্রতি ট্রান্সফার |
| সর্বোচ্চ দৈনিক ট্রান্সফার        | 100,000 | প্রতি API কী     |

রেট লিমিটে একটি ইন-মেমরি স্লাইডিং উইন্ডো ব্যবহার করা হয় (`open-sse/services/`-এর `RateLimitManager`-এর মতো একই প্যাটার্ন)। প্রসেস পুনরায় চালু হলে এটি SQLite-সমর্থিত কাউন্টার ব্যবহার করে।

### Z-স্কোর অ্যানোমালি শনাক্তকরণ

প্রতিটি API কীর জন্য সিস্টেমটি প্রতি ঘণ্টায় অর্জিত XP-এর একটি চলমান 7-দিনের উইন্ডো বজায় রাখে। প্রতিবার XP প্রদানের সময়:

1. ব্যবহারকারীর বর্তমান ঘণ্টাপ্রতি XP হার গণনা করে।
2. পপুলেশনের গড় এবং স্ট্যান্ডার্ড ডেভিয়েশন গণনা করে।
3. `z = (user_rate - mean) / stddev` গণনা করে।
4. `z > 3.0` (3 স্ট্যান্ডার্ড ডেভিয়েশন) হলে এটিকে অ্যানোমালি হিসেবে চিহ্নিত করে।

অ্যানোমালিগুলো `action = 'anomaly_detected'` সহ `xp_audit_log`-এ লগ করা হয় এবং অ্যাডমিন ড্যাশবোর্ডে প্রদর্শিত হয়।

### অডিট ট্রেইল

প্রতিটি XP প্রদান, ট্রান্সফার, ব্যাজ অর্জন এবং অ্যানোমালি শনাক্তকরণ নিম্নলিখিত তথ্যসহ `xp_audit_log`-এ লগ করা হয়:

| ফিল্ড        | বিবরণ                                             |
| ------------ | ------------------------------------------------- |
| `api_key_id` | কে                                                |
| `action`     | কী ঘটেছে (xp_award, transfer, anomaly, …)         |
| `xp_awarded` | পরিমাণ (XP-বহির্ভূত ইভেন্টের জন্য 0)              |
| `metadata`   | প্রাসঙ্গিক তথ্যসহ JSON (অ্যাকশনের ধরন, লক্ষ্য, …) |
| `created_at` | কখন (ISO 8601)                                    |

অ্যাডমিনরা `GET /api/gamification/anomalies`-এর মাধ্যমে সম্পূর্ণ অডিট ট্রেইল কোয়েরি করতে পারেন।

## ড্যাশবোর্ড পেজসমূহ

### `/dashboard/leaderboard`

- পোডিয়াম প্রদর্শন (শীর্ষ ৩ জনের অবতার ও XP সহ)।
- স্কোপ নির্বাচক: বিশ্বব্যাপী / সাপ্তাহিক / মাসিক / শেয়ার করা টোকেন / অবদান।
- র্যাঙ্ক, নাম, স্কোর, লেভেল ও টাইটেলসহ পৃষ্ঠাবিভক্ত টেবিল (প্রতি পৃষ্ঠায় ২৫টি)।
- SSE রিয়েল-টাইম আপডেট — র্যাঙ্কের পরিবর্তন অ্যানিমেশনের মাধ্যমে দেখানো হয়।
- টেবিলে বর্তমান ব্যবহারকারীকে একটি স্থির "আপনার র্যাঙ্ক" সারি দিয়ে হাইলাইট করা হয়।

### `/dashboard/profile`

- বর্তমান লেভেল ও পরবর্তী লেভেলের সীমাসহ XP অগ্রগতি বার।
- টাইটেল ব্যাজ সুস্পষ্টভাবে প্রদর্শিত হয়।
- ব্যাজ গ্যালারি — অর্জনের তারিখসহ অর্জিত ব্যাজ; অনর্জিত ব্যাজগুলো ধূসর দেখানো হয়
  (লুকানো ব্যাজ অর্জিত না হওয়া পর্যন্ত "???" দেখায়)।
- আগুনের আইকনসহ স্ট্রিক কাউন্টার; স্ট্রিক ক্যালেন্ডার (গত ৩০ দিন)।
- XP ইতিহাসের চার্ট (গত ৩০ দিনের দৈনিক XP)।

### `/dashboard/tokens`

- টোকেন ব্যালেন্স (সুস্পষ্টভাবে, পেজের শীর্ষে)।
- স্থানান্তর ফর্ম: প্রাপক, পরিমাণ, নিশ্চিতকরণ ডায়ালগ।
- ফিল্টারসহ স্থানান্তর ইতিহাসের টেবিল (পাঠানো/প্রাপ্ত/সব)।
- আমন্ত্রণ বিভাগ: সক্রিয় কোড, নতুন কোড তৈরি, শেয়ার লিংক।
- কমিউনিটি সার্ভার: স্বাস্থ্যস্থিতিসহ তালিকা, সংযোগ/বিচ্ছিন্নকরণ।

### `/dashboard/gamification/admin`

- তীব্রতা, ব্যবহারকারী, টাইমস্ট্যাম্প ও z-score-সহ অসংগতির তালিকা।
- ফিল্টারসহ অডিট লগ ভিউয়ার (অ্যাকশনের ধরন, ব্যবহারকারী, তারিখের পরিসর)।
- সিস্টেমের পরিসংখ্যান: মোট প্রদান করা XP, সক্রিয় ব্যবহারকারী, ব্যাজ অর্জনের হার।
- ফেডারেশন সার্ভারের স্বাস্থ্যস্থিতির সারসংক্ষেপ।

## পাইপলাইন ইন্টিগ্রেশন

### ইন্টিগ্রেশন পয়েন্ট

গ্যামিফিকেশন `open-sse/handlers/chatCore.ts`-এর একটি একক পয়েন্টে অনুরোধ
পাইপলাইনের সঙ্গে যুক্ত হয়:

```typescript
// ক্লায়েন্টকে প্রতিক্রিয়া পাঠানোর পর:
setImmediate(() => {
  emitGamificationEvent({
    type: "request.completed",
    apiKeyId,
    metadata: {
      provider: selectedProvider,
      model: selectedModel,
      comboId: resolvedCombo?.id,
      compressionUsed: compressionStats?.applied,
      skillUsed: skillExecution?.name,
    },
  }).catch(() => {
    // পাঠিয়ে ভুলে যাওয়া: লগ করুন, কিন্তু কখনোই ক্লায়েন্টে প্রচার করবেন না
  });
});
```

### ইভেন্টের ধরনসমূহ

| ইভেন্টের ধরন        | কখন নির্গত হয়                                        |
| ------------------- | ----------------------------------------------------- |
| `request.completed` | সফল LLM প্রতিক্রিয়া পাঠানো হলে                       |
| `provider.switch`   | প্রোভাইডার পরিবর্তিত হলে (কম্বো ফলব্যাক গণনা করা হয়) |
| `combo.created`     | নতুন কম্বো কনফিগারেশন সংরক্ষণ করা হলে                 |
| `combo.used`        | কম্বো টার্গেট সফলভাবে পূরণ হলে                        |
| `badge.earned`      | ব্যাজ মূল্যায়নে কোনো মিল পাওয়া গেলে                 |
| `streak.milestone`  | স্ট্রিকের সীমা অতিক্রম করলে                           |
| `transfer.sent`     | টোকেন স্থানান্তর সম্পন্ন হলে                          |
| `referral.redeemed` | আমন্ত্রণ কোড সফলভাবে রিডিম করা হলে                    |
| `compression.used`  | প্রম্পট কম্প্রেশন প্রয়োগ করা হলে                     |
| `skill.executed`    | স্কিল এক্সিকিউশন সম্পন্ন হলে                          |
| `model.first_use`   | মডেলটি গত ৭ দিনে ব্যবহার করা না হয়ে থাকলে            |

### নন-ব্লকিং নিশ্চয়তা

`setImmediate` + `.catch(() => {})` প্যাটার্নটি নিশ্চিত করে:

1. গ্যামিফিকেশন চালু হওয়ার আগে প্রতিক্রিয়াটি সম্পূর্ণভাবে পাঠানো হয়।
2. গ্যামিফিকেশনের ত্রুটি কখনোই ক্লায়েন্টের কাছে প্রকাশিত হয় না।
3. ইভেন্ট প্রসেসিং ইনলাইনে নয়, পরবর্তী মাইক্রোটাস্কে চলে।

| স্ব-রেফারেল              | রিডেম্পশনের সময় `api_key_id` ক্রস-চেক                             |
| লিডারবোর্ডে কারসাজি      | Z-score অ্যানোমালি শনাক্তকরণ; অ্যাডমিন অ্যানোমালি ড্যাশবোর্ড       |
| ফেডারেশন টোকেন চুরি      | SHA-256 হ্যাশ করা স্টোরেজ; কাঁচা টোকেন শুধু একবার দেখানো হয়       |
| ইনভাইট কোডে ব্রুট ফোর্স  | রিডেম্পশন এন্ডপয়েন্টে রেট লিমিটিং; ৮-অক্ষরের এনট্রপি              |
| প্রদর্শিত নামে XSS       | প্রদর্শিত নাম স্যানিটাইজ করা হয়; লিডারবোর্ড এন্ট্রি এসকেপ করা হয় |
| হ্যাশে টাইমিং আক্রমণ     | টোকেন হ্যাশ তুলনার জন্য `crypto.timingSafeEqual`                   |

### অথেন্টিকেশনের প্রয়োজনীয়তা

- **পাবলিক** (অথেন্টিকেশন নেই): `GET /leaderboard`, `GET /stream` (শুধু-পঠনযোগ্য
  লিডারবোর্ড)।
- **API key আবশ্যক**: সব রাইট অপারেশন, প্রোফাইল, ট্রান্সফার ও ইনভাইট।
- **শুধু অ্যাডমিন**: অ্যানোমালি ড্যাশবোর্ড, অডিট লগ ভিউয়ার।
- **ফেডারেশন**: `Authorization` হেডারে কাঁচা টোকেন ব্যবহার করে পৃথক অথেন্টিকেশন
  পাথ, যা সংরক্ষিত SHA-256 হ্যাশের বিপরীতে যাচাই করা হয়।
