Web Cookie প্রোভাইডারগুলো OmniRoute-কে API key-এর পরিবর্তে আপনার বিদ্যমান ব্রাউজার সেশন ব্যবহার করে কোনো AI পরিষেবা ব্যবহারের সুযোগ দেয়। যখন আপনি কোনো পরিষেবার ওয়েবসাইটের মাধ্যমে ইতিমধ্যে সেটিতে অ্যাক্সেস পান এবং চান যে OmniRoute একই প্রমাণীকৃত সেশন ব্যবহার করুক, তখন এগুলো কার্যকর।

API-key প্রোভাইডারের বিপরীতে, Web Cookie প্রোভাইডারগুলো ওয়েবসাইটে আপনার ব্রাউজার পাঠানো পরিচয়পত্র ব্যবহার করে প্রমাণীকরণ করে।

# শুরু করার আগে

> **গুরুত্বপূর্ণ:** পরিচয়পত্র সবসময় একটি **সক্রিয় নেটওয়ার্ক অনুরোধ** থেকে কপি করুন, আপনার ব্রাউজারের cookie storage থেকে **নয়**।

ভুল স্থান থেকে cookies কপি করার কারণে প্রমাণীকরণ-সংক্রান্ত অনেক সমস্যা ঘটে।

## Cookie Storage থেকে কপি করবেন না

অধিকাংশ ব্রাউজার সংরক্ষিত cookies নিচের মাধ্যমে দেখায়:

```
DevTools
→ Application (অথবা Storage)
→ Cookies
```

এই cookies সঠিক মনে হলেও, সেগুলো হতে পারে:

- মেয়াদোত্তীর্ণ
- অসম্পূর্ণ
- শুধু প্রমাণীকৃত অনুরোধে পাঠানো cookies-বিহীন

এই মানগুলো ব্যবহার করলে সেগুলো বৈধ মনে হলেও প্রমাণীকরণ ব্যর্থ হতে পারে।

## একটি সক্রিয় অনুরোধ থেকে কপি করুন

এর পরিবর্তে, একটি সফল অনুরোধের cookies ব্যবহার করুন:

```
DevTools
→ Network
→ পৃষ্ঠাটি রিফ্রেশ করুন
→ একটি chat অথবা conversation অনুরোধ খুলুন
→ Request Headers
→ Cookie
```

`Cookie` অনুরোধের header-এ আপনার ব্রাউজার সফলভাবে ব্যবহার করা সঠিক প্রমাণীকরণ তথ্য থাকে।

অধিকাংশ Web Cookie প্রোভাইডারের ক্ষেত্রে, এই মানটিই OmniRoute-এ পেস্ট করতে হবে।

# সাধারণ সেটআপ

অধিকাংশ Web Cookie প্রোভাইডারের সেটআপ প্রক্রিয়া একই।

1. প্রোভাইডারের ওয়েবসাইটে সাইন ইন করুন।
2. ব্রাউজারের Developer Tools খুলুন।
3. **Network** tab খুলুন।
4. পৃষ্ঠাটি রিফ্রেশ করুন।
5. একটি প্রমাণীকৃত chat অথবা conversation অনুরোধ খুলুন।
6. প্রয়োজনীয় প্রমাণীকরণ পরিচয়পত্র কপি করুন।
7. OmniRoute খুলুন।
8. **Providers → Add Provider**-এ যান।
9. আপনার Web Cookie প্রোভাইডার নির্বাচন করুন।
10. পরিচয়পত্র পেস্ট করুন।
11. **Test Connection**-এ ক্লিক করুন।
12. প্রোভাইডারটি সংরক্ষণ করুন।

কোন পরিচয়পত্রগুলো প্রয়োজন হবে, তা নির্দিষ্ট প্রোভাইডারের ওপর নির্ভর করে।

# প্রোভাইডারের পরিচয়পত্রের ফরম্যাট

বিভিন্ন ওয়েবসাইট প্রমাণীকরণের তথ্য বিভিন্নভাবে সংরক্ষণ করে। কিছু ওয়েবসাইটে শুধু cookies প্রয়োজন হয়, অন্যগুলোতে অতিরিক্ত headers অথবা tokens প্রয়োজন হতে পারে।

| প্রোভাইডার                      | পরিচয়পত্রের ফরম্যাট            | প্রোভাইডার নির্দেশিকা            |
| ------------------------------- | ------------------------------- | -------------------------------- |
| Claude Web                      | সম্পূর্ণ Cookie অনুরোধের header | `docs/providers/CLAUDE_WEB.md`   |
| ChatGPT Web (Codex)             | সম্পূর্ণ Cookie header          | `docs/providers/CHATGPT_WEB.md`  |
| Gemini Web                      | _(যাচাই করুন)_                  |                                  |
| Copilot Web                     | _(যাচাই করুন)_                  | `docs/providers/COPILOT-M365.md` |
| Microsoft 365 Copilot (BizChat) | WS access_token + chathubPath   | `docs/providers/COPILOT-M365.md` |
| Grok Web                        | _(যাচাই করুন)_                  |                                  |
| ...                             | ...                             | ...                              |

> নতুন Web Cookie প্রোভাইডার যোগ করা হলে অথবা বিদ্যমান প্রোভাইডারের প্রমাণীকরণ-সংক্রান্ত প্রয়োজনীয়তা পরিবর্তিত হলে এই টেবিলটি আপডেট করুন।

# Web Cookie প্রোভাইডার কী করতে পারে এবং কী করতে পারে না

Web Cookie প্রোভাইডারগুলো কোনো ওয়েবসাইটের chat interface পুনরায় ব্যবহার করে। এগুলো আনুষ্ঠানিক API-এর মতো একই সক্ষমতা প্রদান করে **না**।

## সমর্থিত

- আপনার বিদ্যমান ব্রাউজার সেশন ব্যবহার করে প্রমাণীকরণ
- আপনার account-এর মাধ্যমে উপলভ্য models-এ অ্যাক্সেস
- chat responses stream করা
- কোনো API key প্রয়োজন নেই

## সমর্থিত নয়

- Function calling
- Tool calling
- স্বয়ংক্রিয় file editing
- Agentic IDE workflows
- শুধু API-তে উপলভ্য বৈশিষ্ট্য

এটি প্রত্যাশিত আচরণ এবং **কোনো** bug নয়।

আপনার যদি tool execution, স্বয়ংক্রিয় file editing অথবা অন্যান্য agent workflows প্রয়োজন হয়, তাহলে Web Cookie প্রোভাইডারের পরিবর্তে একটি **API-key প্রোভাইডার** ব্যবহার করুন।

---

# Validation-সংক্রান্ত সতর্কতা

একটি সফল **Test Connection** অথবা cookie validation শুধু যাচাই করে যে সরবরাহ করা পরিচয়পত্রগুলো প্রত্যাশিত ফরম্যাটে আছে বলে মনে হচ্ছে।

Issue #7857 সমাধান না হওয়া পর্যন্ত, সফল validation প্রোভাইডারটি সফলভাবে প্রমাণীকৃত হবে—এর **নিশ্চয়তা দেয় না**।

প্রমাণীকরণ এরপরও ব্যর্থ হলে, নিশ্চিত করুন যে আপনি browser cookie storage-এর পরিবর্তে একটি সক্রিয় network request থেকে পরিচয়পত্র কপি করেছেন।

---

# সমস্যা সমাধান

## প্রমাণীকরণ ব্যর্থ হয়

পরিচয়পত্রগুলো নিচের স্থান থেকে কপি করা হয়েছে কি না যাচাই করুন:

```
Network
→ Request Headers
→ Cookie
```

এবং নিচের স্থান থেকে **নয়**:

```
Application
→ Cookies
```

---

## Cookie ব্রাউজারে কাজ করে, কিন্তু OmniRoute-এ করে না

কিছু প্রোভাইডার এমন cookies অন্তর্ভুক্ত করে, যেগুলো শুধু প্রমাণীকৃত অনুরোধের সময় পাঠানো হয়।

সফলভাবে একটি conversation খোলার পর নতুন network request থেকে পরিচয়পত্রগুলো আবার কপি করুন।

---

## সেশনের মেয়াদ শেষ হয়েছে

Web Cookie প্রোভাইডারগুলো আপনার বিদ্যমান browser session ব্যবহার করে।

আপনার browser session-এর মেয়াদ শেষ হলে অথবা আপনি sign out করলে, আপনাকে নতুন করে পরিচয়পত্র কপি করতে হবে।

---

## Test Connection সফল হয়, কিন্তু অনুরোধ ব্যর্থ হয়

Issue #7857 সমাধান না হওয়া পর্যন্ত, validation সফল হওয়া প্রমাণীকরণ অনুরোধ সফল হবে—এর নিশ্চয়তা দেয় না।

আরও সমস্যা সমাধানের আগে একটি নতুন প্রমাণীকৃত অনুরোধ থেকে আপনার পরিচয়পত্র আবার কপি করুন।

# প্রোভাইডারের উদাহরণ

সম্পূর্ণ প্রোভাইডার-নির্দিষ্ট ধাপে ধাপে নির্দেশনার জন্য দেখুন:

- **Claude Web** — `docs/providers/CLAUDE_WEB.md`

Claude Web নির্দেশিকায় একটি Web Cookie প্রোভাইডারের সম্পূর্ণ সেটআপ প্রক্রিয়া দেখানো হয়েছে এবং এটি reference implementation হিসেবে কাজ করে।

---

# সর্বোত্তম অনুশীলন

- একটি নতুন প্রমাণীকৃত অনুরোধ থেকে পরিচয়পত্র কপি করুন।
- পুরোনো cookies পুনরায় ব্যবহার করা এড়িয়ে চলুন।
- Web Cookie প্রোভাইডার ব্যবহার করার সময় আপনার browser session সক্রিয় রাখুন।
- কপি করা cookies-কে সংবেদনশীল পরিচয়পত্র হিসেবে বিবেচনা করুন।
- আপনার function calling অথবা agent workflows প্রয়োজন হলে API-key প্রোভাইডার ব্যবহার করুন।
