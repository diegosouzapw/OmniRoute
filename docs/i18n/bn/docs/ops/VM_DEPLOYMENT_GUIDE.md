## পূর্বশর্তসমূহ

| আইটেম      | ন্যূনতম               | প্রস্তাবিত       |
| ---------- | --------------------- | ---------------- |
| **CPU**    | 1 vCPU                | 2 vCPU           |
| **RAM**    | 1 GB                  | 2 GB             |
| **ডিস্ক**  | 10 GB SSD             | 25 GB SSD        |
| **OS**     | Ubuntu 22.04 LTS      | Ubuntu 24.04 LTS |
| **ডোমেইন** | Cloudflare-এ নিবন্ধিত | —                |
| **Docker** | Docker Engine 24+     | Docker 27+       |

**পরীক্ষিত প্রদানকারী**: Akamai (Linode), DigitalOcean, Vultr, Hetzner, AWS Lightsail।

## 1. VM কনফিগার করুন

### 1.1 ইনস্ট্যান্স তৈরি করুন

আপনার পছন্দের VPS প্রদানকারীতে:

- Ubuntu 24.04 LTS বেছে নিন
- ন্যূনতম প্ল্যানটি নির্বাচন করুন (1 vCPU / 1 GB RAM)
- একটি শক্তিশালী root পাসওয়ার্ড সেট করুন অথবা SSH key কনফিগার করুন
- **public IP** লিখে রাখুন (যেমন, `203.0.113.10`)

### 1.2 SSH-এর মাধ্যমে সংযোগ করুন

```bash
ssh root@203.0.113.10
```

### 1.3 সিস্টেম আপডেট করুন

```bash
apt update && apt upgrade -y
```

### 1.4 Docker ইনস্টল করুন

```bash
# ডিপেন্ডেন্সিগুলো ইনস্টল করুন
apt install -y ca-certificates curl gnupg

# অফিসিয়াল Docker রিপোজিটরি যোগ করুন
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
chmod a+r /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $ (. /etc/os-release && echo "$VERSION_CODENAME") stable" | tee /etc/apt/sources.list.d/docker.list > /dev/null
apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

### 1.5 nginx ইনস্টল করুন

```bash
apt install -y nginx
```

### 1.6 Firewall (UFW) কনফিগার করুন

```bash
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp    # SSH
ufw allow 80/tcp    # HTTP (রিডাইরেক্ট)
ufw allow 443/tcp   # HTTPS
ufw enable
```

> **পরামর্শ**: সর্বোচ্চ নিরাপত্তার জন্য, পোর্ট 80 এবং 443 কেবল Cloudflare IP-গুলোর জন্য উন্মুক্ত রাখুন। [উন্নত নিরাপত্তা](#advanced-security) বিভাগটি দেখুন।

## 2. OmniRoute ইনস্টল করুন

### 2.1 কনফিগারেশন ডিরেক্টরি তৈরি করুন

```bash
mkdir -p /opt/omniroute
```

### 2.2 এনভায়রনমেন্ট ভেরিয়েবল ফাইল তৈরি করুন

```bash
cat > /opt/omniroute/.env << 'EOF'
# === নিরাপত্তা ===
JWT_SECRET=CHANGE-TO-A-UNIQUE-64-CHAR-SECRET-KEY
INITIAL_PASSWORD=YourSecurePassword123!
API_KEY_SECRET=REPLACE-WITH-ANOTHER-SECRET-KEY
STORAGE_ENCRYPTION_KEY=REPLACE-WITH-THIRD-SECRET-KEY
STORAGE_ENCRYPTION_KEY_VERSION=v1
MACHINE_ID_SALT=CHANGE-TO-A-UNIQUE-SALT
OMNIROUTE_WS_BRIDGE_SECRET=REPLACE-WITH-WS-BRIDGE-SECRET  # প্রোডাকশনে আবশ্যক: Codex Responses WS bridge দ্বারা ব্যবহৃত

# === অ্যাপ ===
PORT=20128
NODE_ENV=production
HOSTNAME=0.0.0.0
DATA_DIR=/app/data
APP_LOG_TO_FILE=true
AUTH_COOKIE_SECURE=true
REQUIRE_API_KEY=false

# === URL-সমূহ (আপনার ডোমেইনে পরিবর্তন করুন) ===
# নির্ধারিত কাজ / স্বয়ংক্রিয় fetch-এর জন্য অভ্যন্তরীণ server-to-server বেস URL।
BASE_URL=http://127.0.0.1:20128
# OAuth callback, dashboard link এবং তৈরি করা public URL-এর জন্য ব্যবহৃত browser-facing URL।
NEXT_PUBLIC_BASE_URL=https://llms.seudominio.com
# তৈরি করা public asset URL-এর জন্য ঐচ্ছিক সুস্পষ্ট public origin override।
# OMNIROUTE_PUBLIC_BASE_URL=https://llms.seudominio.com

# === Cloud Sync (ঐচ্ছিক) ===
# CLOUD_URL=https://cloud.omniroute.online
# NEXT_PUBLIC_CLOUD_URL=https://cloud.omniroute.online
EOF
```

> ⚠️ **গুরুত্বপূর্ণ**: অনন্য secret key তৈরি করুন! প্রতিটি key-এর জন্য `openssl rand -hex 32` ব্যবহার করুন।

### 2.3 কনটেইনার চালু করুন

```bash
docker pull diegosouzapw/omniroute:latest

docker run -d \
  --name omniroute \
  --restart unless-stopped \
  --env-file /opt/omniroute/.env \
  -p 20128:20128 \
  -v omniroute-data:/app/data \
  diegosouzapw/omniroute:latest
```

### 2.4 এটি চলছে কি না যাচাই করুন

```bash
docker ps | grep omniroute
docker logs omniroute --tail 20
```

এতে `[DB] SQLite database ready` এবং `listening on port 20128` প্রদর্শিত হওয়া উচিত।

## 3. nginx কনফিগার করুন (রিভার্স প্রক্সি)

### 3.1 SSL সার্টিফিকেট তৈরি করুন (Cloudflare Origin)

Cloudflare ড্যাশবোর্ডে:

1. **SSL/TLS → Origin Server**-এ যান
2. **Create Certificate**-এ ক্লিক করুন
3. ডিফল্ট সেটিংস রাখুন (15 বছর, \*.yourdomain.com)
4. **Origin Certificate** এবং **Private Key** কপি করুন

```bash
mkdir -p /etc/nginx/ssl

# সার্টিফিকেটটি পেস্ট করুন
nano /etc/nginx/ssl/origin.crt

# প্রাইভেট কীটি পেস্ট করুন
nano /etc/nginx/ssl/origin.key

chmod 600 /etc/nginx/ssl/origin.key
```

### 3.2 Nginx কনফিগারেশন

```bash
cat > /etc/nginx/sites-available/omniroute << 'NGINX'
# ডিফল্ট সার্ভার — IP-এর মাধ্যমে সরাসরি অ্যাক্সেস ব্লক করে
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    listen 443 ssl default_server;
    listen [::]:443 ssl default_server;
    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    server_name _;
    return 444;
}

# OmniRoute — HTTPS
server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name llms.yourdomain.com;  # আপনার ডোমেইনে পরিবর্তন করুন

    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    client_max_body_size 100M;

    location / {
        proxy_pass http://127.0.0.1:20128;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket সমর্থন
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # SSE (Server-Sent Events) — AI প্রতিক্রিয়া স্ট্রিমিং
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }
}

# HTTP → HTTPS রিডাইরেক্ট
server {
    listen 80;
    listen [::]:80;
    server_name llms.yourdomain.com;
    return 301 https://$server_name$request_uri;
}
NGINX
```

রিভার্স-প্রক্সির স্ট্রিম টাইমআউটগুলো আপনার OmniRoute টাইমআউট এনভায়রনমেন্ট ভেরিয়েবলের সঙ্গে সামঞ্জস্যপূর্ণ রাখুন। আপনি যদি
`FETCH_TIMEOUT_MS` / `STREAM_IDLE_TIMEOUT_MS` বাড়ান, তাহলে `proxy_read_timeout` / `proxy_send_timeout`-ও
একই সীমার চেয়ে বেশি বাড়ান।

OAuth কলব্যাক এবং তৈরি করা পাবলিক লিংকের জন্য OmniRoute `NEXT_PUBLIC_BASE_URL`-কে ব্রাউজারে দৃশ্যমান ক্যানোনিক্যাল অরিজিন হিসেবে ব্যবহার করে। প্রমাণীকৃত ড্যাশবোর্ড রাইট অপারেশনগুলো একই-অরিজিন রিকোয়েস্টের পাশাপাশি সেশন-সংযুক্ত CSRF সুরক্ষা ব্যবহার করে, তাই এগুলোর জন্য একটি স্থির পাবলিক বেস URL প্রয়োজন হয় না। উপরের
`X-Forwarded-*` হেডারগুলো এখনও কার্যকর রাউটিং মেটাডেটা, তবে OAuth বা তৈরি করা ব্রাউজার লিংকের জন্য স্পষ্ট পাবলিক URL সেট করার বিকল্প নয়। কেবল তখনই
`OMNIROUTE_TRUST_PROXY` সক্রিয় করুন, যখন ক্লায়েন্টরা সরাসরি OmniRoute-এ পৌঁছাতে পারে না এবং আপনার প্রক্সি ইনকামিং ফরোয়ার্ডেড হেডারগুলো বাদ দিয়ে পুনর্নির্মাণ করে।

### 3.3 সক্রিয় করুন এবং পরীক্ষা করুন

```bash
# ডিফল্ট কনফিগারেশন সরান
rm -f /etc/nginx/sites-enabled/default

# OmniRoute সক্রিয় করুন
ln -sf /etc/nginx/sites-available/omniroute /etc/nginx/sites-enabled/omniroute

# পরীক্ষা করে পুনরায় লোড করুন
nginx -t && systemctl reload nginx
```

## কম-মেমোরি / ছোট VPS অপ্টিমাইজেশন

ছোট VPS ইনস্ট্যান্সে (1 GB RAM বা কম) ডিপ্লয়মেন্টের জন্য:

- **ব্যাকগ্রাউন্ড পরিষেবাগুলো নিষ্ক্রিয় করুন** — scheduler, MCP server এবং পর্যায়ক্রমিক রক্ষণাবেক্ষণের কাজগুলো এড়িয়ে যেতে `OMNIROUTE_DISABLE_BACKGROUND_SERVICES=1` সেট করুন। `docs/reference/ENVIRONMENT.md` দেখুন।
- **SQLite WAL মোড ব্যবহার করুন** — এটি ডিফল্টভাবে সক্রিয় থাকে এবং একই সময়ে একাধিক রিডের ক্ষেত্রে সর্বোচ্চ মেমোরি ব্যবহার কমায়।
- **V8 heap সীমাবদ্ধ করুন** — `OMNIROUTE_MEMORY_MB` (যেমন `512`) সেট করুন, যাতে runtime VM-এর চেয়ে বড় কোনো সর্বোচ্চ সীমা নির্ধারণ না করে। `docs/reference/ENVIRONMENT.md` দেখুন।
- **ভারী অনুরোধ গ্রহণ heap cap অনুযায়ী স্বয়ংক্রিয়ভাবে স্কেল হয়** -- উপরে `OMNIROUTE_MEMORY_MB` সেট করা হলে ingest byte budget (`OMNIROUTE_CHAT_MAX_INFLIGHT_BYTES`) একই সর্বোচ্চ সীমা থেকে স্বয়ংক্রিয়ভাবে নির্ধারিত হয়। ফলে মেমোরি-সীমাবদ্ধ VM কোনো অতিরিক্ত টিউনিং ছাড়াই একসঙ্গে চলা অনুরোধগুলোর জন্য একটি ছোট budget পায়; অতিরিক্ত অনুরোধগুলো মেমোরির জন্য প্রতিযোগিতা করার পরিবর্তে `Retry-After` সহ পুনরায় চেষ্টা করা যায় এমন `503` পায়। এর অতিরিক্ত একটি কঠোর সীমা প্রয়োজন হলেই কেবল পুরোনো `OMNIROUTE_CHAT_MAX_HEAVY_IN_FLIGHT` request-count cap সেট করুন।
- **VPS-এ `next build` এড়িয়ে চলুন** — লোকালভাবে build করুন এবং standalone output (`.next/standalone/`) ডিপ্লয় করুন।
- **`top` / `free -m` দিয়ে পর্যবেক্ষণ করুন** — একটি 1 GB VM-এ নিষ্ক্রিয় অবস্থায় OmniRoute সাধারণত 200-400 MB RSS ব্যবহার করে।
