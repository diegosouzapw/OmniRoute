> **পরিধি-সংক্রান্ত নোট:** `socket.yml` npm আর্টিফ্যাক্টের ওপর Socket.dev-এর রেজিস্ট্রি-পক্ষীয় প্রকাশনা-পরবর্তী স্ক্যান কনফিগার করে (প্যাকেজে অন্তর্ভুক্ত নয় এমন কনটেন্টের জন্য উপেক্ষিত পাথ, যেমন `tests/`, `docs/`, এবং বিল্ড রিপোর্ট)। এটি কোনো CI/PR মার্জ গেট সংযুক্ত করে না — `.github/workflows`-এ কোনো ওয়ার্কফ্লো, কোনো `package.json` স্ক্রিপ্ট, এবং কোনো `Makefile` টার্গেট Socket.dev-কে আহ্বান করে না।

এই নথিটি `omniroute@3.8.5`-এর বিরুদ্ধে উত্থাপিত ছয়টি
`AI-detected potential malware` শনাক্তকরণ এবং `omniroute@3.8.6`-এ প্রয়োগ করা
প্রশমনগুলোর জন্য রক্ষণাবেক্ষণকারীর-প্রণীত প্রত্যয়ন। এটি রাখা হয়েছে যাতে:

1. নিরাপত্তা-পাইপলাইন পরিচালনাকারীদের কাছে প্রকৃত সোর্সের বিপরীতে
   শনাক্তকরণগুলো মূল্যায়নের প্রয়োজন হলে উদ্ধৃত করার জন্য একটি একক রেফারেন্স থাকে।
2. ভবিষ্যতের AI স্ক্যানারগুলো রক্ষণাবেক্ষণকারী-স্বাক্ষরিত এই দাবিটি শনাক্ত করতে পারে যে প্রতিটি
   চিহ্নিত পাথ ইচ্ছাকৃত, অপ্ট-ইন এবং নথিভুক্ত।
3. প্রতিটি কল সাইট _কেন_ এভাবে গঠন করা হয়েছে, তার একটি লিখিত রেকর্ড আমাদের কাছে থাকে —
   যাতে ভবিষ্যতের কোনো রিফ্যাক্টর অসাবধানতাবশত এমন কোনো ফিঙ্গারপ্রিন্ট পুনরায় প্রবর্তন না করে,
   যা ইচ্ছাকৃতভাবে সরানো হয়েছিল।

আপনি যদি এমন কোনো স্ক্যানার পরিচালনা করেন, যা v3.8.6-এর প্রশমনগুলো প্রকাশিত হওয়ার পর নিচের
কোনো কল সাইটকে পুনরায় চিহ্নিত করে, তাহলে অনুগ্রহ করে স্ক্যান ট্রেসসহ একটি ইস্যু খুলুন এবং
আমরা এখানে প্রত্যয়নটি সম্প্রসারিত করব।

## §1 — MITM রুট-CA ইনস্টল (`77484.js`)

**সোর্স ফাইলগুলো**:

- `src/mitm/cert/install.ts` — পাবলিক `installCert()` / `uninstallCert()`,
  প্ল্যাটফর্মভিত্তিক `installCertWindows/Mac/Linux`।
- `src/mitm/systemCommands.ts` — ইনস্টল পাথগুলোতে ব্যবহৃত শেয়ার্ড `execFile` /
  `spawn` / PowerShell হেল্পার।

**ট্রিগার**: ব্যবহারকারী স্থানীয় ড্যাশবোর্ডের
`/dashboard/cli-tools/mitm`-এ "Enable MITM proxy"-তে ক্লিক করেন। রুটটি কেবল
লুপব্যাকের জন্য — `CLAUDE.md`-এর কঠোর নিয়ম #17 এবং
`src/server/authz/routeGuard.ts::isLocalOnlyPath()` দেখুন। কোনো টানেলের মাধ্যমে
প্রকাশিত ফাঁস হওয়া JWT এই কোড পাথটি **ট্রিগার করতে পারে না**।

**সম্পাদিত বিশেষাধিকারপ্রাপ্ত অপারেশনগুলো (প্ল্যাটফর্মভেদে)**:

| OS                     | কমান্ড(গুলো)                                                                                                      |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | UAC-এর মাধ্যমে `certutil -addstore Root <cert>`                                                                   |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | `certutil -d sql:<profile>`-এর মাধ্যমে প্রতি-প্রোফাইল NSS DB আপডেট                                                |

এগুলো `mitmproxy`, Charles Proxy, Fiddler এবং Caddy-তে ব্যবহৃত একই কমান্ড।
OmniRoute-এ এগুলোর উপস্থিতি `docs/security/STEALTH_GUIDE.md`-এ নথিভুক্ত আছে।

**v3.8.6 প্রশমন**:

- `runElevatedPowerShell()` এখন আর `-EncodedCommand <base64utf16le>` ব্যবহার
  করে না। উন্নীত বিশেষাধিকারসহ চালানোর পেলোডটি প্রতিটি কলের জন্য একটি অস্থায়ী
  `.ps1` ফাইলে (মোড 0o600, একটি ব্যক্তিগত `mkdtempSync` ডিরেক্টরির ভেতরে)
  লেখা হয় এবং `-File`-এর মাধ্যমে সেটি উল্লেখ করা হয়। `finally`-তে ফাইলটি
  আনলিঙ্ক করা হয়। এটি Socket.dev-এর AI ক্লাসিফায়ার দ্বারা চিহ্নিত প্রচলিত
  base64-elevation-via-PowerShell ফিঙ্গারপ্রিন্টটি সরিয়ে দেয়।
- `installCertWindows`-এ একটি ইনলাইন `SECURITY-AUDITOR-NOTE:` ব্লক রয়েছে,
  যা এখানে নির্দেশ করে।

**কেন আমরা এটি রাখছি**: MITM প্রক্সি একটি নথিভুক্ত ফিচার, যা
`docs/security/STEALTH_GUIDE.md` এবং `docs/frameworks/MITM-PROXY.md`-এ ব্যবহৃত
হয়েছে। এটি সরিয়ে দিলে agent-bridge ফিচার সেটটি ভেঙে যাবে।

## §2 — Zed ক্রেডেনশিয়াল ইমপোর্ট (`app/api/providers/zed/import/route.js`)

**সোর্স ফাইলসমূহ**:

- `src/app/api/providers/zed/discover/route.ts` _(v3.8.6-এ নতুন)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(v3.8.6-এ নতুন)_

**ট্রিগার**: ব্যবহারকারী লোকাল ড্যাশবোর্ডের Providers পেজে "Zed থেকে ইমপোর্ট করুন"-এ ক্লিক করেন। এন্ডপয়েন্টটি `requireManagementAuth` দ্বারা সুরক্ষিত। Zed এডিটর নিজেই নথিভুক্ত সার্ভিস নামের অধীনে OS keychain-এ তার প্রোভাইডার API key লেখে — দেখুন https://zed.dev/docs/ai/llm-providers।

**v3.8.5-এর আচরণ (যেটি Socket.dev ফ্ল্যাগ করেছিল)**:

`POST /import` ক্রেডেনশিয়ালগুলো খুঁজে বের করে একটি মাত্র রাউন্ড-ট্রিপে লোকাল SQLite স্টোরে স্বয়ংক্রিয়ভাবে সেভ করত। প্রতি-অ্যাকাউন্ট নিশ্চিতকরণ বা fingerprint কিছুই ছিল না, শুধু "Nটি token পাওয়া গেছে, সবগুলো ইমপোর্ট করা হয়েছে।"

**v3.8.6 প্রশমন — ২-ধাপের নিশ্চিতকরণ**:

1. **`POST /api/providers/zed/discover`** রিটার্ন করে
   `{ candidates: [{ provider, service, account, fingerprint }] }`। কাঁচা
   token **কখনোই** প্রেরণ করা হয় না। fingerprint হলো
   `sha256(service|account|token).slice(0,16)`।
2. ড্যাশবোর্ড candidate তালিকাটি রেন্ডার করে, অপারেটর কোনগুলো
   ইমপোর্ট করবেন তা নির্বাচন করেন এবং `{ confirmedAccounts: [{ service, account, fingerprint }] }`
   **`POST /api/providers/zed/import`**-এ পোস্ট করেন।
3. import এন্ডপয়েন্টটি **সার্ভারে keychain পুনরায় পড়ে** এবং
   `(service, account, fingerprint)` অনুযায়ী ফিল্টার করে। পরিবর্তিত বা replay করা discover
   response import এন্ডপয়েন্টকে কোনো সম্পর্কহীন token সেভ করতে প্ররোচিত করতে পারে না —
   discover-এর পর live token পরিবর্তিত হলে fingerprint আর
   মেলে না এবং ক্রেডেনশিয়ালটি বাদ দেওয়া হয়।

`OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` env flag সেই অপারেটরদের জন্য v3.8.5-এর
আচরণ বজায় রাখে, যারা এখনো তাদের automation আপডেট করেননি। এটি
v3.9-এ অপসারণ করা হবে।

**আমরা এটি কেন রাখি**: যেসব ব্যবহারকারী ইতিমধ্যেই Zed ব্যবহার করেন এবং পুনরায় paste না করে
তাদের provider key OmniRoute-এ প্রতিলিপি করতে চান, তাদের জন্য Zed import হলো সবচেয়ে সহজ onboarding পদ্ধতি।

## §3 — `execFile` / `spawn` / elevated PowerShell (`21843.js`)

**সোর্স ফাইলসমূহ**: `src/mitm/systemCommands.ts`।

**ফ্ল্যাগ করার কারণ**: chunk-টি `execFileWithPassword`,
`runElevatedPowerShell` এবং শেয়ার করা `quotePowerShell` helper পুনরায় export করে। Socket.dev-এর
AI classifier এগুলোকে একটি সাধারণ "host execution + privilege elevation
toolkit" হিসেবে দেখে। OmniRoute-এর মধ্যে এগুলো কেবল MITM cert install path
(§1) এবং `sudo` command execution-এর জন্য `execFileWithPassword` দ্বারা ব্যবহৃত হয়।

**v3.8.6 প্রশমন**:

- `runElevatedPowerShell` refactor (দেখুন §1)।
- `runElevatedPowerShell` এবং `execFileWithPassword` উভয় স্থানের inline
  `SECURITY-AUDITOR-NOTE:` block অনুমোদিত caller এবং নির্ধারিত executable
  তালিকা নথিভুক্ত করে।
- `execFileWithPassword`-এর `spawn()` call-এ একটি `nosemgrep` marker রয়েছে, যার সঙ্গে
  helper-টি যে executable-গুলো গ্রহণ করতে পারবে সেগুলোর allowlist দেওয়া আছে — ব্যবহারকারীর
  input থেকে `finalCommand`/`finalArgs`-এ যাওয়ার **কোনো path নেই**।

- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`।
- `src/lib/services/ServiceSupervisor.ts` — সাধারণ spawn / health-poll / log-buffer।

**ট্রিগার**: ব্যবহারকারী লোকাল ড্যাশবোর্ডের embedded services পেজে "Install" / "Start"-এ ক্লিক করেন।

**আগে থেকেই থাকা সুরক্ষাসমূহ**:

- `src/server/authz/routeGuard.ts` অনুযায়ী সব `/api/services/*` route হলো LOCAL_ONLY
  (কঠোর নিয়ম #17)। যেকোনো auth check-এর আগেই loopback enforcement
  কার্যকর হয় — ফাঁস হওয়া JWT এগুলোতে পৌঁছাতে পারে না।
- 9router DB row-টি `status='not_installed', auto_start=0` হিসেবে seed করা হয় (দেখুন
  `src/lib/db/migrations/071_services.sql:19`)। প্রথম launch-এ service-টি **শুরু হয় না**।
- `src/lib/services/installers/ninerouter.ts`-এর
  `resolveSpawnArgs(apiKey, PORT)` দ্বারা ফেরত দেওয়া binary path দিয়ে `spawn()` call করা হয়,
  যা সমর্থিত binary-গুলোর একটি নির্দিষ্ট allowlist।
- Stdout/stderr মেমরিতে buffer করা হয় (5 MB সীমা, দেখুন `_lib.ts`) — ব্যবহারকারী
  ড্যাশবোর্ড থেকে logging সক্রিয় না করলে on-disk write হয় না।

**v3.8.6 প্রশমন**: কার্যকরী কোনো পরিবর্তন নেই। যেসব ব্যবহারকারী bundle থেকে
privileged path-গুলো ভৌতভাবে সরিয়ে দিতে চান, তাদের জন্য minimal build profile
(`OMNIROUTE_BUILD_PROFILE=minimal`)
`src/lib/services/installers/ninerouter.ts`-কে একটি stub দিয়ে প্রতিস্থাপন করে।

**আমরা এটি কেন রাখি**: 9router হলো একটি ঐচ্ছিক, লোকালি install করা যায় এমন companion
service (ভাবুন: WordPress-ধাঁচের plugin) — কঠোরভাবে opt-in।

## §5 — OmniRoute Cloud Sync ক্রেডেনশিয়াল রাইট-ব্যাক (`api/keys/[id]/route.js`)

**সোর্স ফাইলসমূহ**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`।
- `src/app/api/keys/[id]/route.ts` — `syncKeysToCloudIfEnabled()` কল করে।

**ট্রিগার**: `isCloudEnabled()` `true` রিটার্ন করে (ড্যাশবোর্ড থেকে সেট করা) **এবং**
`CLOUD_URL` কনফিগার করা থাকে। উভয়ই বন্ধ থাকলে Cloud এন্ডপয়েন্টে কোনো বহির্মুখী নেটওয়ার্ক কল করা হয় না।

**v3.8.5-এর আচরণ (যে বাগটি Socket.dev সঠিকভাবে শনাক্ত করেছে)**:

`cloudUpdatedAt > localUpdatedAt` হলে `updateLocalTokens()` Cloud রেসপন্স থেকে
`accessToken`, `refreshToken`, এবং `providerSpecificData` ওভাররাইট করত।
কোনো HMAC, স্বাক্ষর বা চেকসাম ছিল না। ভুলভাবে কনফিগার করা বা ক্ষতিকর
`CLOUD_URL` (অথবা চ্যানেলে কোনো MITM) নীরবে প্রোভাইডারের OAuth টোকেন বদলে দিতে পারত।

**v3.8.6-এর প্রতিকার**:

1. **HMAC যাচাইকরণ**: `verifyCloudSignature(rawBody, sigHeader)` JSON পার্স করার আগে
   `X-Cloud-Sig` হেডার (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`) যাচাই করে। সিক্রেট সেট করা থাকলে স্বাক্ষর আবশ্যক।
   সেট করা না থাকলে (লিগ্যাসি মোড), একটি সতর্কতা লগ করা হয় এবং রেসপন্সটি
   গ্রহণ করা হয় — v3.9-এ সিক্রেট আবশ্যক হবে।
2. **সিক্রেট-ফিল্ড অপ্ট-ইন**: `accessToken` / `refreshToken` /
   `providerSpecificData` **শুধুমাত্র** তখনই ওভাররাইট করা হয়, যখন
   `OMNIROUTE_CLOUD_SYNC_SECRETS=true`। ডিফল্ট মোডে কেবল
   ক্রেডেনশিয়াল-বহির্ভূত মেটাডেটা (`expiresAt`, `status`, `lastError*`,
   `rateLimitedUntil`, `updatedAt`) সিঙ্ক করা হয়। যেসব ব্যবহারকারী
   রিমোট টোকেন সিঙ্কের ওপর নির্ভর করতেন, তাঁদের জন্য এটি একটি **ব্রেকিং পরিবর্তন** —
   তাঁদের স্পষ্টভাবে অপ্ট-ইন করতে হবে।

**কেন আমরা এটি রাখছি**: OmniRoute Cloud টেন্যান্টের জন্য টিমের ক্রেডেনশিয়াল
কেন্দ্রীভূত করার একমাত্র উপায় হলো Cloud Sync। এই সংশোধনটি থ্রেট মডেলকে স্বচ্ছ করে:
"সার্ভার স্বাক্ষর করে, ক্লায়েন্ট যাচাই করে, অপারেটর অপ্ট-ইন করে।"

## বিল্ড প্রোফাইল: `minimal`

যেসব ব্যবহারকারীর Socket-বান্ধব আর্টিফ্যাক্ট প্রয়োজন, তাঁরা এভাবে বিল্ড করুন:

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

webpack-এর `NormalModuleReplacementPlugin` চারটি মডিউলকে স্টাবের অ্যালিয়াস হিসেবে নির্ধারণ করে:

| মডিউল                                       | স্টাব                                            |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

প্রতিটি স্টাব একই সারফেস এক্সপোর্ট করে, কিন্তু রানটাইমে প্রতিটি ফাংশন
`featureDisabledError(name)` থ্রো করে। নিষ্ক্রিয় মডিউলের ওপর নির্ভরশীল রুটগুলো
সংবেদনশীল কোড পাথ সক্রিয় করার পরিবর্তে একটি স্পষ্ট বার্তাসহ HTTP 503 রিটার্ন করে।

ফলস্বরূপ বান্ডলটি `omniroute-secure` হিসেবে প্রকাশ করার উদ্দেশ্যে তৈরি।
প্রকাশনার নির্দেশাবলির জন্য `docs/ops/PUBLISHING_SECURE.md` দেখুন।
