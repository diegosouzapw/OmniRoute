OmniRoute এমন প্রোভাইডারগুলোর সঙ্গে ইন্টিগ্রেট করে, যাদের এজ সক্রিয়ভাবে অনানুষ্ঠানিক ক্লায়েন্টগুলোর ফিঙ্গারপ্রিন্ট শনাক্ত করে (TLS JA3/JA4, হেডারের ক্রম, JSON বডির গঠন, ইন্টেগ্রিটি টোকেন)। এই পৃষ্ঠায় OmniRoute-এর প্রকাশিত স্টেলথ সারফেস এবং সেগুলো কোথায় বাস্তবায়িত হয়েছে তা নথিভুক্ত করা হয়েছে।

## আইনি ও নৈতিক বিজ্ঞপ্তি

স্টেলথ ফিচারগুলোর উদ্দেশ্য হলো ব্যবহারকারীর মালিকানাধীন অফিসিয়াল অ্যাকাউন্ট (Claude Code CLI, Codex, Antigravity, Cursor ইত্যাদি) এবং OmniRoute-এর ইউনিফাইড API-এর মধ্যে OmniRoute-কে একটি কম্প্যাটিবিলিটি লেয়ার হিসেবে কাজ করতে দেওয়া। এগুলো জালিয়াতি শনাক্তকরণ এড়ানো, ক্রেডেনশিয়াল শেয়ার করা বা প্রোভাইডারের পরিষেবার শর্তাবলি লঙ্ঘনের জন্য **নয়**। রক্ষণাবেক্ষণকারীরা প্রত্যাশা করেন যে অপারেটররা অ্যাকাউন্ট তৈরির সময় সম্মত হওয়া আপস্ট্রিম ToS মেনে চলবেন।

## TLS ফিঙ্গারপ্রিন্টিং লেয়ার

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

প্রতি অ্যাকাউন্ট স্কোপ ও রিজলভ করা প্রক্সির জন্য স্থায়ী `wreq-js` সেশন প্রয়োজনমতো অলসভাবে তৈরি করা হয়। প্রসেস-ব্যাপী `TlsClient` সর্বাধিক 128টি সেশন পুল করে, যেগুলো Cloudflare-এর পেছনে থাকা আপস্ট্রিমগুলোর জন্য **macOS-এ Chrome 124**-এর ছদ্মবেশ ধারণ করে। নেটিভ রানটাইম অনুপলভ্য হলে `TlsClient.fetch()` ফলব্যাক না করে ব্যর্থ হয়; একজন কলার এই র্যাপারের বাইরে স্পষ্টভাবে একটি ফলব্যাক নির্বাচন করতে পারেন।

- সেশন প্রোফাইল: `browser: "chrome_124", os: "macos"`
- প্রক্সি রিজল্যুশন (অগ্রাধিকার): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (ছোট হাতের রূপগুলোও)
- টাইমআউট: `TLS_CLIENT_TIMEOUT_MS` (`FETCH_TIMEOUT_MS` থেকে উত্তরাধিকারসূত্রে প্রাপ্ত, ডিফল্ট 600000)
- `wreq-js` Response fetch-এর সঙ্গে সামঞ্জস্যপূর্ণ (`headers`, `text()`, `json()`, `clone()`, `body`)।
- ফার্স্ট-বাইট ওয়াচডগ (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656): আপস্ট্রিম হেডার আসামাত্র `TlsClient.fetch()` রিজলভ হয়, তাই কেবল `TLS_CLIENT_TIMEOUT_MS` কখনো প্রথম বাইট না দেওয়া কোনো বডির সময়সীমা বেঁধে দিতে পারে না। `guardTlsFirstByte()` বডির প্রথম `read()`-এর সঙ্গে `TLS_FIRST_BYTE_WATCHDOG_MS`-এর (ডিফল্ট `10000`, `0` এটি নিষ্ক্রিয় করে) প্রতিযোগিতা করায়; সুস্থ বডি এতে প্রভাবিত হয় না, আর স্থবির বডি wreq রিডার বাতিল করে এবং `proxyFetch`-এর বিদ্যমান TLS-ফলব্যাক লজিককে ডাইরেক্ট/প্রক্সি ডিসপ্যাচারে এগিয়ে যেতে দেয় (রিপ্লে-নিরাপদ নয় এমন অনুরোধ, যেমন বডিসহ POST, নীরবে পুনরায় চেষ্টা করার বদলে তখনও এরর নিক্ষেপ করে)।

### ওয়েব-কুকি প্রোভাইডার ট্রান্সপোর্ট — wreq-js 3.2.0

`open-sse/services/tlsClientBase.ts` নিচের পাঁচটি বিশেষায়িত ওয়েব-কুকি ট্রান্সপোর্টের শেয়ার করা অ্যাডাপ্টার। প্রতিটি পাতলা প্রোভাইডার র্যাপার একটি ব্রাউজার/OS প্রোফাইল নির্বাচন করে। অ্যাডাপ্টারটি `open-sse/utils/tlsClient.ts`-এ থাকা একক wreq রানটাইম লোডার ও ট্রান্সপোর্ট পুল ব্যবহার করে, যা প্রোফাইল + OS + রিজলভ করা প্রক্সি অনুযায়ী কী করা হয়; অন্যদিকে প্রতিটি অনুরোধ `cookieMode: "ephemeral"` ব্যবহার করে। ফলে অ্যাকাউন্ট ও অনুরোধগুলো ট্রান্সপোর্ট-স্তরের সংযোগ শেয়ার করে, কিন্তু কখনোই কোনো wreq সেশন বা কুকি জার শেয়ার করে না।

| প্রোভাইডার | প্রোফাইল      | এমুলেটেড OS | স্ট্রিম EOF নীতি                         |
| ---------- | ------------- | ----------- | ---------------------------------------- |
| Claude     | `chrome_146`  | Linux       | `[DONE]` অন্তর্ভুক্ত করুন                |
| Perplexity | `firefox_148` | macOS       | `event: end_of_stream` অন্তর্ভুক্ত করুন  |
| Grok       | `chrome_146`  | Linux       | `[DONE]` বাদ দিন                         |
| Notion     | `chrome_146`  | Windows     | `[DONE]` অন্তর্ভুক্ত করুন                |
| LMArena    | `chrome_146`  | Windows     | কোনো সেন্টিনেল নেই; নেটিভ EOF-এ বন্ধ হয় |

- স্ট্রিমিং সরাসরি নেটিভ রেসপন্সের `ReadableStream` ব্যবহার করে; কোনো অস্থায়ী ফাইল বা সাইডকার তৈরি করা হয় না।
- স্ট্রিম প্রকাশের আগে সর্বোচ্চ 256টি প্রাথমিক বাইট পরীক্ষা করা হয়। SSE প্রোভাইডারগুলো non-SSE এরর বাফার করে; Grok/LMArena Cloudflare চ্যালেঞ্জকে `403` এবং HTML ইন্টারস্টিশিয়ালকে `502`-এ ম্যাপ করে।
- নেটিভ অনুরোধের টাইমআউট একটি নিরঙ্কুশ JS হার্ড ডেডলাইন দ্বারা আবৃত থাকে। কোনো হ্যাং হলে শুধু প্রভাবিত প্রোফাইল/OS/প্রক্সি ট্রান্সপোর্টটি ইনভ্যালিডেট ও বন্ধ করা হয়, যাতে পরবর্তী অনুরোধের আগে সেটি পুনরায় তৈরি করা যায়।
- প্রক্সি রিজল্যুশনের অগ্রাধিকার হলো প্রতি-কল `proxyUrl` → অনুরোধ-স্কোপড অ্যাকাউন্ট/ড্যাশবোর্ড কনটেক্সট → `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (ছোট হাতের রূপগুলোসহ)। রিজল্যুশন এরর সরাসরি সংযোগ ফাঁস না করে ব্যর্থ হয়। LMArena ইচ্ছাকৃতভাবে `arena.ai`-এর বিপরীতে রিজলভ করে।
- `byteResponse` UTF-8 বিকৃতি ছাড়াই কনটেন্ট-টাইপযুক্ত `data:` URL ফেরত দেয়।
- এররগুলো হলো `TlsClientUnavailableError` (প্যাকেজ/অ্যাডঅন অনুপলভ্য), `TlsClientHangError` (ডেডলাইন অতিক্রান্ত), এবং `WreqTransportCapacityError` (শেয়ার করা সেশন-ক্যাপাসিটি এরর কোড), যখন সীমাবদ্ধ 128টি প্রোফাইল/OS/প্রক্সি স্লটের সবগুলো সক্রিয় বা বন্ধ হওয়ার প্রক্রিয়ায় থাকে।

উপরের জেনেরিক `TlsClient` সেশনটি স্থায়ী ব্রাউজার-সমর্থিত কুকি স্টেটের জন্য বিশেষায়িত থাকে। উভয় পাথ একটি ক্যাশ করা wreq মডিউল লোডার ও প্রসেস লাইফসাইকেল হুক পুনর্ব্যবহার করে; তাদের পুলগুলো আলাদা থাকে, কারণ তাদের কুকির আয়ুষ্কাল ইচ্ছাকৃতভাবে ভিন্ন।

পিন করা প্যাকেজটি প্রোফাইলগুলো সমর্থন করে, তবে বাস্তব WAF গ্রহণযোগ্যতা স্থানীয় কনট্র্যাক্ট টেস্ট থেকে স্বাধীনভাবে পরিবর্তিত হতে পারে। কোনো আপস্ট্রিম ব্রাউজারের সঙ্গে সমতা দাবি করার আগে স্পষ্টভাবে অনুমোদিত লাইভ অ্যাকাউন্টের বিপরীতে ফিঙ্গারপ্রিন্ট পরিবর্তনগুলো যাচাই করুন।

## Claude Code স্টেলথ বান্ডল

`cliCompatMode` চালু থাকলে, OmniRoute বহির্গামী Claude অনুরোধগুলোকে এমনভাবে পুনর্গঠন করে যাতে সেগুলো `claude-cli` ট্র্যাফিক থেকে আলাদা করা না যায়। তিনটি মডিউল একসঙ্গে কাজ করে:

### `claudeCodeFingerprint.ts`

বিলিং হেডারে এম্বেড করা ৩-অক্ষরের `cc_version` ফিঙ্গারপ্রিন্ট গণনা করে:

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (হার্ডকোড করা; অফিসিয়াল ক্লায়েন্টের সঙ্গে মেলে)
- ইনপুট: প্রথম ব্যবহারকারী বার্তার টেক্সটের ৪, ৭ ও ২০ নম্বর ইনডেক্সের অক্ষর + সংস্করণ স্ট্রিং
- আউটপুট: ৩-অক্ষরের হেক্স প্রিফিক্স

### `claudeCodeCCH.ts` (ক্লায়েন্ট কনটেন্ট হ্যাশ)

অফিসিয়াল Claude Code CLI Bun/Zig-এর মাধ্যমে যে সার্ভার-সাইড অখণ্ডতা যাচাই গণনা করে। OmniRoute `xxhash-wasm` দিয়ে এটি পুনরায় বাস্তবায়ন করে:

1. `cch=00000;` প্লেসহোল্ডারসহ বডি সিরিয়ালাইজ করুন
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. শূন্য দিয়ে প্যাড করা ৫-অক্ষরের ছোট হাতের হেক্স
4. `cch=00000;`-কে গণনা করা টোকেন দিয়ে প্রতিস্থাপন করুন

ধ্রুবক:

- সিড: `0x6e52736ac806831e`
- প্যাটার্ন: `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

“সংবেদনশীল” ক্লায়েন্ট নামের প্রথম অক্ষরের পরে একটি Unicode **zero-width joiner** (`U+200D`) সন্নিবেশ করে, যাতে আপস্ট্রিম ফিল্টারগুলো `grep` দিয়ে সেগুলো খুঁজে না পায়। ডিফল্ট শব্দতালিকা:

aider, continue.dev, copilot, avante, codecompanion

## Antigravity স্টেলথ

Antigravity অনুরোধগুলো কলারের টেক্সট বাইট-প্রতি-বাইট অপরিবর্তিত রাখে। কোনো IDE ক্লায়েন্টকে অনুকরণ করার জন্য OmniRoute প্রম্পটে zero-width অক্ষর সন্নিবেশ করে না বা টুলের নাম পরিবর্তন/ইনজেক্ট করে না।

### `antigravityHeaderScrub.ts`

ফরোয়ার্ড করার আগে Stainless SDK মার্কারগুলো (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`) সরিয়ে দেয়।

### ⚠️ ঝুঁকি: `ANTIGRAVITY_CREDITS=always` (অ্যাকাউন্ট নিষিদ্ধ হওয়ার হট স্পট)

`ANTIGRAVITY_CREDITS=always` (`open-sse/executors/antigravity.ts` দ্বারা ব্যবহৃত) Google-এর ফ্রি-টিয়ার কোটা দিয়ে অনুরোধ সীমাবদ্ধ হতে দেওয়ার পরিবর্তে **প্রতিটি** অনুরোধকে Antigravity AI Credit Overages-এর (পেইড Google ক্রেডিট) মাধ্যমে রাউট করে। এটিকে একটি ফিচার হিসেবে নথিভুক্ত করা হয়েছে, কিন্তু এটি **আমাদের দেখা ToS লঙ্ঘনের প্রতিবেদনের এককভাবে সবচেয়ে সাধারণ কারণ** — `=always` দিয়ে কয়েক ঘণ্টা চালানোর পর একাধিক Google Ultra অ্যাকাউন্ট `403 / "service disabled for ToS violation" / insufficient_quota` সহ নিষিদ্ধ হয়েছে।

আপস্ট্রিম প্রয়োগটি **Google-এর পক্ষ থেকে** হয়; OmniRoute এটি প্রতিরোধ করতে পারে না। এনভায়রনমেন্ট ভেরিয়েবলের নাম এবং বিদ্যমান ডকুমেন্টেশন দেখে এটিকে চালু করা নিরাপদ বলে মনে হতে পারে; কিন্তু তা নয়।

**কেন এটি শুধু ফ্রি-টিয়ার ব্যবহারের তুলনায় আরও আক্রমণাত্মকভাবে অপব্যবহার শনাক্তকরণ ট্রিগার করে:**

- একটি Google অ্যাকাউন্টে দীর্ঘস্থায়ী স্বয়ংক্রিয় ব্যয়, ফ্রি-টিয়ারের কোটা শেষ হয়ে থেমে যাওয়া অনুরোধের তুলনায় ভিন্নভাবে ফ্ল্যাগ হয়।
- ক্রেডিট ওভারেজে কোনো রেট সীমা নেই, তাই ভুলভাবে কনফিগার করা কোনো ক্লায়েন্ট কয়েক মিনিটেই কয়েকশ USD খরচ করে ফেলতে পারে এবং সেটিকে API-key পুনর্বিক্রয় বা বট ট্র্যাফিকের মতো দেখাতে পারে।
- একই বহিরাগত IP থেকে একাধিক OmniRoute ব্যবহারকারী সমান্তরালভাবে ওভারেজ ক্রেডিট ব্যবহার করলে সংকেতটি আরও শক্তিশালী হয়।

**প্রস্তাবিত অবস্থান:**

1. অপারেটর স্পষ্টভাবে পেইড-ক্রেডিট ও অ্যাকাউন্ট-এনফোর্সমেন্টের ঝুঁকি গ্রহণ না করলে ডিফল্ট `ANTIGRAVITY_CREDITS=off` রাখুন। `retry` প্রথমে স্বাভাবিক অনুরোধ পাঠায় এবং উপযুক্ত কোটা-সংক্রান্ত 429 পাওয়ার পরে সর্বোচ্চ একবার ক্রেডিট ইনজেক্ট করে; `always` প্রথম অনুরোধেই ক্রেডিট ইনজেক্ট করে।
2. একটি Antigravity অ্যাকাউন্ট সম্পৃক্ত করে ফেলার পরিবর্তে **Auto-Combo-এর মাধ্যমে প্রোভাইডারগুলোর মধ্যে লোড ছড়িয়ে দিন** (`model: "auto"` বা `kr/glm/etc`-combo)।
3. Antigravity প্রোভাইডারের সম্পাদনা পৃষ্ঠায় **প্রতি-সংযোগ RPM সীমা সেট করুন** (Dashboard → Providers → Antigravity → connection → rate limit)। টেকসই ব্যবহারের জন্য 30–60 RPM একটি যুক্তিসংগত সর্বোচ্চ সীমা।
4. **অপারেটর-নিয়ন্ত্রিত স্থিতিশীল আপস্ট্রিম নেটওয়ার্কিং ব্যবহার করুন** এবং সম্পর্কহীন ব্যবহারকারী বা ওয়ার্কলোডের মধ্যে একটি অ্যাকাউন্ট শেয়ার করা এড়িয়ে চলুন।
5. **নিষিদ্ধ হলে**: Google যে সঠিক `quota_exceeded` / `service disabled` রেসপন্স বডি পাঠিয়েছে, সেটিসহ `support.google.com` → “Restore Workspace/Account access”-এর মাধ্যমে আপিল করুন। পুনর্বহালের নিশ্চয়তা নেই।

এনভায়রনমেন্ট রেফারেন্সে প্রতিটি ক্রেডিট মোডের অ্যাকাউন্ট ও ব্যয়সংক্রান্ত প্রভাব নথিভুক্ত করা হয়েছে।

- `open-sse/executors/antigravity.ts` — `process.env.ANTIGRAVITY_CREDITS` পড়ে
- `src/lib/oauth/providers/antigravity.ts` — ক্রেডেনশিয়াল সংযোগব্যবস্থা

## CLI ফিঙ্গারপ্রিন্ট রেজিস্ট্রি — `open-sse/config/cliFingerprints.ts`

প্রতি-প্রোভাইডার টেবিল, যা অফিসিয়াল CLI-গুলোর mitmproxy ট্রেস থেকে ধারণ করা **সুনির্দিষ্ট** হেডার ক্রম এবং JSON বডি ফিল্ডের ক্রম নির্ধারণ করে। বর্তমানে নিবন্ধিত: `codex`, `claude`; পাশাপাশি `antigravity` এবং `github`-এর জন্য `providerHeaderProfiles.ts`-এ রানটাইম থেকে নির্ধারিত প্রোফাইল রয়েছে।

```ts
interface CliFingerprint {
  headerOrder: string[]; // কেস-সংবেদনশীল
  bodyFieldOrder: string[]; // শীর্ষ-স্তরের JSON কী
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

প্রতি প্রোভাইডারের জন্য env-এর মাধ্যমে টগল করুন (নিচে দেখুন)। নিষ্ক্রিয় থাকলে, হেডার/বডি কী Node/JSON যেভাবে দেয় সেভাবেই ক্রমানুসারে উপস্থিত হয় — সহজেই ফিঙ্গারপ্রিন্ট করা যায়।

## MITM প্রক্সি (Antigravity, Linux/macOS/Windows)

যেসব CLI-র বাইনারিকে `OPENAI_BASE_URL`-এর মাধ্যমে পুনর্নির্দেশ করা যায় না, সেগুলোর জন্য OmniRoute একটি স্থানীয় TLS-টার্মিনেটিং প্রক্সি চালায়। এন্ডপয়েন্টগুলো `src/app/api/cli-tools/antigravity-mitm/`-এর অধীনে রয়েছে।

| মেথড   | এন্ডপয়েন্ট                             | উদ্দেশ্য                                                 |
| ------ | --------------------------------------- | -------------------------------------------------------- |
| GET    | `/api/cli-tools/antigravity-mitm`       | স্ট্যাটাস — চলমান অবস্থা, pid, dnsConfigured, certExists |
| POST   | `/api/cli-tools/antigravity-mitm`       | MITM শুরু করুন (`apiKey` + `sudoPassword` আবশ্যক)        |
| DELETE | `/api/cli-tools/antigravity-mitm`       | MITM বন্ধ করুন                                           |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | মডেল অ্যালিয়াসের তালিকা দেখুন                           |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | একটি টুলের জন্য মডেল অ্যালিয়াস সংরক্ষণ করুন             |

ইন্টারসেপ্ট করা লক্ষ্য হোস্ট: **`daily-cloudcode-pa.googleapis.com`** (Antigravity-এর আপস্ট্রিম)।

### শুরুর ক্রম (`src/mitm/manager.ts::startMitm`)

1. `selfsigned`-এর মাধ্যমে স্ব-স্বাক্ষরিত সার্টিফিকেট তৈরি করুন (RSA-2048, SHA-256, 1y) — `cert/generate.ts`
2. সিস্টেম ট্রাস্ট স্টোরে সার্টিফিকেট ইনস্টল করুন — `cert/install.ts`
3. হোস্ট এন্ট্রি `127.0.0.1 daily-cloudcode-pa.googleapis.com` যোগ করুন — `dns/dnsConfig.ts`
4. `ROUTER_API_KEY` + `MITM_LOCAL_PORT` (ডিফল্ট `443`) সহ `src/mitm/server.cjs` স্পন করুন
5. PID-টি `<DATA_DIR>/mitm/.mitm.pid`-এ সংরক্ষণ করুন

### Linux-এর ডায়নামিক ট্রাস্ট-স্টোর শনাক্তকরণ — `cert/install.ts`

`getLinuxCertConfig()` অগ্রাধিকার তালিকা পর্যায়ক্রমে পরীক্ষা করে এবং বিদ্যমান প্রথম ডিরেক্টরিটি বেছে নেয়:

| ডিস্ট্রো পরিবার          | ডিরেক্টরি                                   | আপডেট কমান্ড             |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

সার্টিফিকেটের ফাইলনাম: `omniroute-mitm.crt`। `getCertFingerprint()`-এর মাধ্যমে ফিঙ্গারপ্রিন্ট মিলানো হয় (DER-এর SHA-1)।

এছাড়াও, `certutil` উপলভ্য থাকলে `updateNssDatabases()` প্রতি-ব্যবহারকারীর NSS DB-তে ইনস্টল করে: `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, সব Firefox প্রোফাইল (snap-সহ), **`OmniRoute MITM Root CA`** ডাকনামের অধীনে।

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** উন্নত অনুমতিসহ PowerShell → `certutil -addstore Root`

### অথেন্টিকেশন

সব MITM এন্ডপয়েন্টে ম্যানেজমেন্ট অথেন্টিকেশন (`requireCliToolsAuth`) আবশ্যক। sudo পাসওয়ার্ডটি মডিউল স্কোপে ক্যাশ করা হয় (কখনোই `globalThis`-এ নয়) এবং `stopMitm()`-এ মুছে ফেলা হয়।

## ইনবাউন্ড হেডার স্যানিটাইজেশন

OmniRoute ফরোয়ার্ড করার আগে ইনবাউন্ড ক্লায়েন্ট হেডারগুলো পরিষ্কার করে, যাতে Cursor থেকে আসা কোনো রিকোয়েস্ট Claude আপস্ট্রিমে `User-Agent: Cursor/X.Y.Z` ফাঁস না করে। ডিনাইলিস্টের জন্য `src/shared/constants/upstreamHeaders.ts` দেখুন, যা Zod স্কিমা ও ইউনিট টেস্টের সঙ্গে সমন্বিত রাখা হয়।

## কোনো প্রোভাইডার ফিঙ্গারপ্রিন্ট পরিবর্তন করলে তা আপডেট করা

1. `mitmproxy` দিয়ে অফিসিয়াল CLI ট্রাফিক ক্যাপচার করুন (TLS ইন্টারসেপশন + ডাম্প)
2. JA3/JA4 এবং হেডারের হুবহু ক্রম এক্সট্র্যাক্ট করুন
3. সংশ্লিষ্ট `CLI_FINGERPRINTS[...]` এন্ট্রি আপডেট করুন
4. `.env.example`-এ মিল থাকা `*_USER_AGENT` ডিফল্ট আপডেট করুন
5. TLS হ্যান্ডশেক নিজেই পরিবর্তিত হয়ে থাকলে সংশ্লিষ্ট প্রোভাইডার র্যাপার বা wreq-js-এর `browser:` অপশন আপডেট করুন
6. প্রোভাইডার-নির্দিষ্ট TLS টেস্ট এবং লাইভ প্রোভাইডারের বিরুদ্ধে একটি ম্যানুয়াল ক্যানারি চালান
7. একটি প্যাচ রিলিজে প্রকাশ করুন; `CHANGELOG.md`-এ নথিভুক্ত করুন
