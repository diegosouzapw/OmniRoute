OmniRoute npm + Docker আর্টিফ্যাক্ট প্রকাশ করে। এই গেটগুলি প্রোভেনেন্স, ইনভেন্টরি (SBOM) এবং CVE স্ক্যানিং প্রদান করে, যা সবই OSS এবং রিলিজ ওয়ার্কফ্লোতে সংযুক্ত।
**উপদেশ-প্রথম** অবস্থান — তারা এখন রিপোর্ট করে, প্রথম সবুজ রিলিজের পরে ব্লকিংয়ে উন্নীত করে।

| গেট                   | টুল                                            | কোথায়                        | ব্লক করে?                         | আউটপুট                                              |
| :-------------------- | :--------------------------------------------- | :---------------------------- | :-------------------------------- | :-------------------------------------------------- |
| SLSA provenance (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | শুধুমাত্র যদি প্রকাশ ব্যর্থ হয়   | ব্যাজ npmjs / `npm audit signatures`                |
| SBOM npm              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | শুধুমাত্র যদি জেনারেশন ব্যর্থ হয় | রিলিজ অ্যাসেট + আর্টিফ্যাক্ট                        |
| SBOM image            | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | উপদেশমূলক                         | CycloneDX আর্টিফ্যাক্ট                              |
| Trivy CVE (SARIF)     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | উপদেশমূলক                         | SARIF (HIGH+CRITICAL) → সিকিউরিটি ট্যাব             |
| Trivy CRITICAL gate   | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | **ব্লকিং**                        | `exit-code: '1'` যদি ঠিক করা যায় এমন CRITICAL থাকে |
| osv vulnCount         | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **ব্লকিং**                        | `metrics.vulnCount` র্যাচেট করে (দিক: নিচে)         |
| OpenSSF Scorecard     | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | উপদেশমূলক                         | SARIF → সিকিউরিটি + ব্যাজ                           |

ইমেজ CVE র্যাচেট `docker-publish.yml`-এ **দুটি ধাপ** ব্যবহার করে: SARIF ধাপ (`HIGH,CRITICAL`, `exit-code: 0`) HIGH+CRITICAL-কে সিকিউরিটি ট্যাবে ব্লকিং ছাড়াই দৃশ্যমান রাখে; _CRITICAL গেট_ ধাপ (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) একটি CRITICAL CVE-এর জন্য রিলিজ ব্যর্থ করে **যদি একটি ফিক্স উপলব্ধ থাকে**। `ignore-unfixed` একটি আপস্ট্রিম প্যাচ ছাড়া বেস-ইমেজ CVE-এর জন্য রিলিজ ব্লক করা প্রতিরোধ করে।

## ⚠️ CVE বৈচিত্র্য (osv/Trivy গেট ব্লক করা)

osv এবং Trivy CVE ডেটাবেসের বিরুদ্ধে নির্ভরতা তুলনা করে যা **ক্রমাগত বৃদ্ধি পায়**। একটি PR যা **কোনো নির্ভরতা স্পর্শ করে না** তা হঠাৎ লাল হয়ে যেতে পারে কারণ একটি বিদ্যমান নির্ভরতায় একটি নতুন CVE প্রকাশ করা হয়েছে (osv: পরিমাপকৃত `vulnCount` > বেসলাইন; Trivy: ইমেজে একটি নতুন ঠিক করা যায় এমন CRITICAL)। **এটি একটি ব্লকিং CVE গেটের প্রত্যাশিত অপারেশনাল আচরণ, কোনো পণ্যের রিগ্রেশন নয়।**

যখন একটি নতুন প্রকাশিত CVE-এর কারণে osv বা Trivy লাল হয়ে যায়, তখন প্রতিকার হল:

1.  **প্রভাবিত নির্ভরতা বাড়ান** (পছন্দনীয়) — `package.json` `overrides` (ট্রানজিটিভ নির্ভরতা) এর মাধ্যমে প্যাচ করা সংস্করণে আপগ্রেড করুন অথবা একটি প্যাচ করা বেসের উপর ইমেজটি পুনরায় তৈরি করুন।
2.  **যদি কোনো আপস্ট্রিম ফিক্স না থাকে:**
    - **osv:** `config/quality/quality-baseline.json`-এ `metrics.vulnCount` পুনরায় বেসলাইন করুন (`npm run quality:ratchet -- --update` ডেডিকেটেড গেটগুলি কভার করে না — মানটি হাতে সম্পাদনা করুন, `direction:down`) একটি ন্যায্যতা নোট + ট্র্যাকিং ইস্যু সহ।
    - **Trivy:** `.trivyignore`-এ (প্রতি লাইনে CVE-ID) একটি ন্যায্যতা মন্তব্য + ট্র্যাকিং ইস্যু সহ একটি এন্ট্রি যোগ করুন। `ignore-unfixed: true` স্বয়ংক্রিয়ভাবে প্যাচ ছাড়া CVE গুলিকে কভার করে।

উভয় গেটই **সুন্দরভাবে এড়িয়ে যায়** (exit 0) যখন টুলটি অনুপস্থিত থাকে বা পরিমাপ ব্যর্থ হয় (osv-scanner PATH-এ নেই, osv.dev/network পৌঁছানো যায় না, অবৈধ JSON) — একটি **পরিমাপ** ব্যর্থতা কখনও ব্লক করে না, শুধুমাত্র একটি **পরিমাপকৃত** রিগ্রেশন ব্লক করে।

## জ্ঞাত গৃহীত ঝুঁকি

### extract-zip 2.0.1 — GHSA-7pqw-9j4j-h8q3 / GHSA-jmr9-qjv8-65gv (#14482)

`extract-zip@2.0.1`-এ দুটি আনপ্যাচড উচ্চ-গুরুত্বের সিমলিঙ্ক-ট্র্যাভার্সাল অ্যাডভাইজরি রয়েছে। উপরের CVE ভ্যারিয়েন্স প্রতিকারের "নো আপস্ট্রিম ফিক্স" শাখার মতে, এটি একটি **গৃহীত ঝুঁকি**, কোনো আপগ্রেড নয়:

- **চেইন:** `promptfoo` (devDependency) → `@openai/codex-security` → `extract-zip@2.0.1`। `package-lock.json` এর মাধ্যমে নিশ্চিত করা হয়েছে — পুরো ডিপেন্ডেন্সি ট্রিতে (`@openai/codex-security`) ঠিক একটি প্যাকেজ `extract-zip` ঘোষণা করে, এবং ঠিক একটি প্যাকেজ (`promptfoo`) `@openai/codex-security` ঘোষণা করে।
- **চেইনের কোথাও কোনো ফিক্সড রিলিজ নেই।** `extract-zip@2.0.1` (২০২০ সালে প্রকাশিত) প্যাকেজটির চূড়ান্ত রিলিজ — এটি রক্ষণাবেক্ষণ করা হয় না। `@openai/codex-security`-এর বর্তমান npm-latest (`0.1.29`) এখনও `extract-zip@2.0.1` ব্যবহার করে।
- **প্রোডাকশন থেকে অপ্রাপ্য।** `promptfoo` শুধুমাত্র devDependency (কখনোই `dependencies`-এর অধীনে তালিকাভুক্ত নয়), এবং `src/`, `open-sse/`, বা `bin/`-এর অধীনে কোনো ফাইল `extract-zip` npm প্যাকেজটি ইম্পোর্ট করে না — OmniRoute-এর নিজস্ব `extractZip()` হেল্পার (`src/lib/versionManager/binaryManager.ts:93`) নেটিভ `unzip`/`tar` ব্যবহার করে এবং এটি সম্পর্কহীন। `@openai/codex-security` তার নিজস্ব সিমলিঙ্ক-ট্র্যাভার্সাল গার্ডও `extract-zip`-এর `onEntry` কলব্যাকের উপরে সরবরাহ করে।
- `package.json` `overrides`-এর মাধ্যমে `extract-zip` কে **উপনাম করবেন না** — একমাত্র কার্যকর ড্রপ-ইন প্রতিস্থাপনটি হল Electron-org-internal এবং `@openai/codex-security`-এর নিজস্ব `onEntry`/`defaultDirMode`/`defaultFileMode` চেকের সাথে API-অসামঞ্জস্যপূর্ণ; এটিকে ওভাররাইড করলে সেই প্যাকেজের নিরাপত্তা চেকগুলি নীরবে ভেঙে যাবে।
- **বেসলাইন:** পরিমাপকৃত osv `vulnCount` (3) ইতিমধ্যেই হিমায়িত `config/quality/quality-baseline.json` বেসলাইনের (27) অনেক নিচে — কোনো র্যাচেট পরিবর্তনের প্রয়োজন নেই।
- **রিগ্রেশন গার্ড:** `tests/unit/extract-zip-14482-exposure.test.ts` উপরের চেইন এবং নো-প্রোডাকশন-ইম্পোর্ট ইনভেরিয়েন্ট নিশ্চিত করে; যদি কোনোটি ভেঙে যায় (যেমন, ভবিষ্যতের একটি PR `extract-zip` কে প্রোডাকশন থেকে অ্যাক্সেসযোগ্য করে তোলে), তাহলে এটি CI ব্যর্থ করে।
- **ট্র্যাকিং:** ইস্যু #14482।
