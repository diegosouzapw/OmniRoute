OmniRoute npm + Docker আর্টিফ্যাক্ট প্রকাশ করে। এই গেটগুলো উৎসের প্রমাণ,
ইনভেন্টরি (SBOM) এবং CVE স্ক্যানিং প্রদান করে; সবগুলোই OSS এবং রিলিজ ওয়ার্কফ্লোর সঙ্গে সংযুক্ত।
**প্রথমে-অ্যাডভাইজরি** অবস্থান — এগুলো এখন রিপোর্ট করে এবং ১ম
সবুজ রিলিজের পরে ব্লকিং হিসেবে উন্নীত হবে।

| গেট                   | টুল                                            | কোথায়                        | ব্লক করে?                | আউটপুট                                           |
| --------------------- | ---------------------------------------------- | ----------------------------- | ------------------------ | ------------------------------------------------ |
| SLSA উৎস-প্রমাণ (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | শুধু প্রকাশ ব্যর্থ হলে   | npmjs ব্যাজ / `npm audit signatures`             |
| SBOM npm              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | শুধু জেনারেশন ব্যর্থ হলে | রিলিজ অ্যাসেট + আর্টিফ্যাক্ট                     |
| SBOM ইমেজ             | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (মার্জ)  | অ্যাডভাইজরি              | CycloneDX আর্টিফ্যাক্ট                           |
| Trivy CVE (SARIF)     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (মার্জ)  | অ্যাডভাইজরি              | SARIF (HIGH+CRITICAL) → Security ট্যাব           |
| Trivy CRITICAL গেট    | `aquasecurity/trivy-action`                    | `docker-publish.yml` (মার্জ)  | **ব্লকিং**               | সমাধানযোগ্য CRITICAL-এ `exit-code: '1'`          |
| osv vulnCount         | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **ব্লকিং**               | `metrics.vulnCount` র্যাচেট করে (দিক: নিম্নমুখী) |
| OpenSSF Scorecard     | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | অ্যাডভাইজরি              | SARIF → Security + ব্যাজ                         |

ইমেজ CVE র্যাচেটটি `docker-publish.yml`-এ **দুটি ধাপ** ব্যবহার করে: SARIF ধাপটি
(`HIGH,CRITICAL`, `exit-code: 0`) ব্লক না করেই Security ট্যাবে HIGH+CRITICAL দৃশ্যমান
রাখে; _CRITICAL গেট_ ধাপটি (`severity: CRITICAL`, `ignore-unfixed: true`,
`exit-code: 1`) **সমাধান উপলভ্য থাকা** কোনো CRITICAL CVE-এর ক্ষেত্রে রিলিজ ব্যর্থ করে। `ignore-unfixed`
কোনো আপস্ট্রিম প্যাচ ছাড়া বেস-ইমেজ CVE-এর কারণে রিলিজ ব্লক হওয়া প্রতিরোধ করে।

## ⚠️ CVE পরিবর্তনশীলতা (ব্লকিং osv/Trivy গেট)

osv এবং Trivy নির্ভরতাগুলোকে এমন CVE ডেটাবেসের সঙ্গে তুলনা করে যেগুলো **ক্রমাগত বৃদ্ধি পায়**। এমন একটি PR
যা **কোনো নির্ভরতা স্পর্শ করে না**, সেটিও হঠাৎ লাল হয়ে যেতে পারে, কারণ বিদ্যমান কোনো নির্ভরতায়
নতুন CVE প্রকাশিত হয়েছে (osv: পরিমাপ করা `vulnCount` > বেসলাইন; Trivy: ইমেজে নতুন
সমাধানযোগ্য CRITICAL)। **এটি একটি ব্লকিং CVE গেটের প্রত্যাশিত পরিচালনাগত আচরণ,
পণ্যের কোনো রিগ্রেশন নয়।**

নতুন প্রকাশিত কোনো CVE-এর কারণে osv বা Trivy লাল হলে, প্রতিকার হলো:

1. **প্রভাবিত নির্ভরতার সংস্করণ বাড়ান** (অগ্রাধিকারযোগ্য) — `package.json`
   `overrides` (পরোক্ষ নির্ভরতা) ব্যবহার করে প্যাচ করা সংস্করণে আপগ্রেড করুন অথবা প্যাচ করা বেসে ইমেজটি পুনর্নির্মাণ করুন।
2. **যদি কোনো আপস্ট্রিম সমাধান না থাকে:**
   - **osv:** `config/quality/quality-baseline.json`-এ `metrics.vulnCount` পুনরায় বেসলাইন করুন
     (`npm run quality:ratchet -- --update` নিবেদিত গেটগুলোকে অন্তর্ভুক্ত করে না — মানটি
     হাতে সম্পাদনা করুন, `direction:down`) এবং সঙ্গে একটি যৌক্তিকতার নোট + ট্র্যাকিং ইস্যু দিন।
   - **Trivy:** `.trivyignore`-এ একটি এন্ট্রি (প্রতি লাইনে CVE-ID) যোগ করুন, সঙ্গে একটি যৌক্তিকতার
     মন্তব্য + ট্র্যাকিং ইস্যু দিন। `ignore-unfixed: true` ইতোমধ্যেই প্যাচবিহীন
     CVE-গুলোকে স্বয়ংক্রিয়ভাবে অন্তর্ভুক্ত করে।

টুল অনুপস্থিত থাকলে বা পরিমাপ ব্যর্থ হলে উভয় গেটই **সুষ্ঠুভাবে SKIP করে** (exit 0)
(osv-scanner PATH-এ নেই, osv.dev/নেটওয়ার্কে পৌঁছানো যাচ্ছে না, অবৈধ JSON) — কোনো
**পরিমাপজনিত** ব্যর্থতা কখনো ব্লক করে না; শুধু একটি **পরিমাপ করা** রিগ্রেশন ব্লক করে।
