## 💰 నెలకు ~1.62B ఉచిత టోకెన్లు

</div>

> ఉచిత టియర్లను చేతితో కలిపి నిర్వహించడం కష్టసాధ్యం — డజన్ల కొద్దీ SDKలు, డజన్ల కొద్దీ రేట్ లిమిట్లు, వాస్తవానికి మీకు ఎంత అందుబాటులో ఉందో తెలియదు. OmniRoute **35 పునరావృత పూల్ కీలలోని 491 ఉచిత-టియర్ ఎంట్రీలను** జాబితా చేస్తుంది మరియు **ప్రచురించబడిన ధనాత్మక నెలవారీ బడ్జెట్ కలిగిన 17 పూల్స్తో పాటు ఒక్కో మోడల్కు ఐదు Groq పరిమితుల** ఆధారంగా టోకెన్ ప్రధాన సంఖ్యను లెక్కిస్తుంది; భాగస్వామ్య పూల్లను ఒకసారి మాత్రమే లెక్కిస్తుంది. ప్రాంతీయ గుర్తింపు తనిఖీ తర్వాత మాత్రమే అందుబాటులోకి వచ్చే కోటాలు (ప్రస్తుతం: ModelScope) విడిగా చూపబడతాయి, ప్రాంతీయ గుర్తింపు ధృవీకరణ వెనుక +~6Mగా ఉంటాయి మరియు ప్రధాన సంఖ్యలో ఎన్నడూ కలపబడవు. ఫలితం డ్యాష్బోర్డ్లో (`/dashboard/free-tiers`) కనిపిస్తూనే ఉంటుంది.

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="OmniRoute ఉచిత-టియర్ బడ్జెట్ కార్డ్: నెలకు స్థిరంగా ~1.62B ఉచిత టోకెన్లు, సైన్అప్ క్రెడిట్లతో మొదటి నెలలో ~2.22B వరకు, ఒకే ఎండ్పాయింట్ వెనుక జాబితా చేయబడిన 491 ఉచిత-టియర్ ఎంట్రీలను కవర్ చేసే 35 డాక్యుమెంట్ చేయబడిన పునరావృత పూల్ కీల నుంచి. నిజాయితీగల పూల్-డీడూప్ లెక్కింపు — ప్రచురించబడిన ధనాత్మక నెలవారీ టోకెన్ బడ్జెట్ కలిగిన 17 పునరావృత పూల్స్తో పాటు ఒక్కో మోడల్కు ఐదు Groq పరిమితులతో సహా, ప్రతి భాగస్వామ్య పూల్ను ఒక్కసారి మాత్రమే లెక్కిస్తుంది; మీరు నిర్ణయించుకునేందుకు నిబంధనల-ప్రమాద జాబితాలో 13 ప్రొవైడర్లు నివారించాల్సినవిగా గుర్తించబడ్డారు. బడ్జెట్ బార్లో Mistral 1B, Nara 210M, LLM7 150M, xKiro 150M, Groq 30M (ఒక్కో మోడల్కు ఐదు పరిమితులు) మరియు చిన్న పూల్స్ ఉన్నాయి; అదనంగా, ప్రధాన సంఖ్యను అవి ఎన్నడూ పెంచకుండా మొదటి నెల సైన్అప్ క్రెడిట్లు మరియు శాశ్వతంగా ఉచితమైన టోకెన్-పరిమితి-లేని ప్రొవైడర్లు విడిగా చూపబడతారు. /dashboard/free-tiersలో ప్రత్యక్షంగా ఉపయోగించినవి/మిగిలినవి."/>

> ప్రత్యక్ష `/dashboard/free-tiers` పేజీ యొక్క యానిమేటెడ్ సారాంశం. పూర్తి విధానం (పూల్ డీడూప్, క్రెడిట్ టియర్లు, ప్రొవైడర్ నిబంధనలు): **[docs/reference/FREE_TIERS.md](docs/reference/FREE_TIERS.md)**.
>
> <sub>ఈ గణాంకాలు ప్రతి రెండు వారాలకు ప్రత్యక్ష కేటలాగ్తో మళ్లీ ఆడిట్ చేయబడతాయి మరియు **రెండు దిశల్లోనూ మారుతాయి** — ఒక ప్రొవైడర్ ఉచిత టియర్ను ముగిస్తే సంఖ్య తగ్గుతుంది; కొత్తది చేరితే పెరుగుతుంది. కేటలాగ్ వాస్తవంగా లెక్కించిన దానినే మేము ప్రచురిస్తాము, పైకి రౌండ్ చేసిన అత్యుత్తమ సందర్భాన్ని ఎన్నడూ కాదు.</sub>

## 🆓 ఇన్స్టాల్ చేసిన వెంటనే పనిచేస్తుంది — కీలు లేవు, కాన్ఫిగరేషన్ లేదు

</div>

<img src="./docs/diagrams/works-zero-config.svg" width="100%" alt="ఇన్స్టాల్ చేసిన వెంటనే పనిచేస్తుంది — కాన్ఫిగరేషన్ అవసరం లేదు. మూడు దశలు: 1. ఇన్స్టాల్ చేయండి — npm i -g omniroute, సర్వర్ localhost:20128లో ప్రారంభమవుతుంది. 2. మీ సాధనాన్ని http://localhost:20128/v1 వైపు మళ్లించండి — ఏదైనా OpenAI-అనుకూల సాధనం (Claude Code, Cursor, Cline). 3. అది సమాధానమిస్తుంది — API కీ, నమోదు లేదా కాన్ఫిగరేషన్ లేకుండానే తక్షణ ప్రత్యుత్తరం కోసం auto మోడల్ను కాల్ చేయండి. కీ అవసరం లేని ప్రొవైడర్ OpenCode Free, auto కాంబోలో ముందుగానే అనుసంధానించబడి ఉంటుంది, కాబట్టి కొత్తగా ఇన్స్టాల్ చేసిన వెంటనే అది స్పందిస్తుంది."/>

```bash
# కొత్త ఇన్స్టాలేషన్, క్రెడెన్షియల్స్ అవసరం లేదు — `auto` ఇప్పటికే పనిచేస్తుంది:
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

<sub>నిర్దిష్టమైన ఉచిత బ్యాకెండ్ కావాలా? నేరుగా `oc/…` (OpenCode Free)ను కాల్ చేయండి. ఆ తర్వాత `auto`కు మారి, OmniRouteను ఎంపిక చేయనివ్వండి.</sub>

<sub>📦 **Python, Node.js, PHP మరియు cURL** కోసం కాపీ-పేస్ట్ క్విక్స్టార్ట్ స్క్రిప్ట్లు → [`examples/quickstart/`](examples/quickstart/)</sub>

### 🧱 స్థితిస్థాపకత అంతర్నిర్మితంగా ఉంటుంది (3 స్వతంత్ర లేయర్లు)

<img src="./docs/diagrams/resilience-layers.svg" width="100%" alt="OmniRoute స్థితిస్థాపకత — 3 స్వతంత్ర స్వీయ-పునరుద్ధరణ లేయర్లు, సరైన వైఫల్యానికి సరైన లేయర్. లేయర్ 1 ప్రొవైడర్ సర్క్యూట్ బ్రేకర్ (మొత్తం ప్రొవైడర్): 408/5xx వచ్చినప్పుడు మాత్రమే ట్రిప్ అవుతుంది, థ్రెషోల్డ్లు OAuth 8× / API-key 12× / local 2×, 60s/30s/15s తర్వాత HALF-OPEN ప్రోబ్కు రీసెట్ అవుతుంది, లేజీ రికవరీ; OPEN స్థితిలో ఉన్నప్పుడు కాంబో తదుపరి ప్రొవైడర్కు రీరూట్ చేస్తుంది. లేయర్ 2 కనెక్షన్ కూల్డౌన్ (ఒక కీ/అకౌంట్): బేస్ OAuthకు 5s / API-keyకు 3s, యాంటీ-థండరింగ్-హెర్డ్ గార్డ్తో ఎక్స్పోనెన్షియల్ ×2 బ్యాక్ఆఫ్, 429 వచ్చినప్పుడు Retry-Afterను పాటిస్తుంది, విజయం సాధించినప్పుడు మొత్తం ఎర్రర్ స్థితిని క్లియర్ చేస్తుంది; ఒక కూలింగ్ కీని దాటవేస్తూనే తోటి కీలు సేవలను కొనసాగిస్తాయి. లేయర్ 3 మోడల్ లాకౌట్ (ఒక మోడల్): ఒక్కో మోడల్కు సంబంధించిన 429, local 404 లేదా మోడ్ తిరస్కరణలు ఆ మోడల్ను మాత్రమే లాక్ చేస్తాయి — మొత్తం కనెక్షన్ను ఎప్పటికీ కాదు. టెర్మినల్ స్థితులు (నిషేధించబడినవి, గడువు ముగిసినవి, క్రెడిట్లు అయిపోయినవి) ఆపరేటర్ కోసం ఉద్దేశించినవి, కూల్డౌన్లు కావు."/>

## 📡 OmniRoute Radar

పైన డాక్యుమెంట్ చేయబడిన, పూల్-డీడూప్లికేట్ చేసిన కేటలాగ్ నుండి ప్రధాన ఉచిత-టియర్ ముఖ్యాంశం **~1.62B టోకెన్లు/నెల**గానే ఉంది. తాత్కాలిక ప్రొవైడర్ సైన్అప్ క్రెడిట్లు మొదటి నెల పరిమితిని విడిగా **~2.22B** వరకు పెంచగలవు. OmniRoute విడుదలల మధ్య మరింత తాజా ఉచిత-మోడల్ లభ్యతను కోరుకునే వారి కోసం Radar అనేది ఐచ్ఛికమైన, సంతకం చేసిన కేటలాగ్ ఓవర్లే; కమ్యూనిటీ కేటలాగ్ మరియు ఇప్పటికే ఉన్న ప్రతి ఉచిత ఫీచర్ ఉచితంగానే ఉంటాయి.

మద్దతుదారులు లైవ్ కేటలాగ్ను మరియు అదనపు ప్రొవైడర్ అవకాశాలను పొందవచ్చు. ప్రొవైడర్ లభ్యతను బట్టి, దీని ప్రత్యేకమైన, మార్పులకు లోనయ్యే గరిష్ఠ పరిమితి **అత్యధికంగా సుమారు 3B టోకెన్లు/నెల**. ఆ గరిష్ఠ పరిమితి హామీ కాదు: ప్రొవైడర్లు కోటాలు, అర్హత, మోడళ్లు లేదా ప్రాంతాలను ఎప్పుడైనా మార్చవచ్చు.

Radar ఐచ్ఛికం మరియు GET-మాత్రమే. OmniRoute క్లయింట్ ప్రాంప్ట్లు, ట్రాఫిక్, ప్రొవైడర్ కాన్ఫిగరేషన్, వినియోగ టెలిమెట్రీ లేదా స్థానిక ప్రకటన-తొలగింపు స్థితిని అప్లోడ్ చేయదు. అర్హత మరియు ప్రస్తుత కేటలాగ్ గురించి **[radar.omniroute.online/planos](https://radar.omniroute.online/planos)** వద్ద తెలుసుకోండి.

```bash
omniroute run claude   --model openai/gpt-5.4          # Claude Code
omniroute run codex    --model glm/glm-5.2             # OpenAI Codex CLI
omniroute run aider    --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose    --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"
omniroute run qwen     --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini   --model glm/glm-5.2 -- --skip-trust -p "reply OK"

# లేదా provider+modelను ఇంటరాక్టివ్గా ఎంచుకుని, సాధనానికి చెందిన స్వంత కాన్ఫిగరేషన్ను వ్రాయండి:
omniroute configure codex          # ఇవి కూడా: claude opencode qwen aider goose gemini cline continue kilo
```

ప్రతి కమాండ్ సక్రియ రిమోట్ కాంటెక్స్ట్ను (`omniroute connect <host>`) గౌరవిస్తుంది, `--dry-run`

### 🎩 కొత్తది: OmniRouteTray — మెనూ బార్లో ఉండే మీ గేట్వే

> `omniroute serve` ఎల్లప్పుడూ ఆన్లో ఉన్నప్పుడే అత్యుత్తమంగా పనిచేస్తుంది. **[OmniRouteTray](https://github.com/zoispag/omniroute-tray)**

> తర్వాత కూడా దాన్ని నడుస్తూ ఉంచుతుంది, అక్కడికక్కడే అప్డేట్ చేస్తుంది, అలాగే మీ లైవ్ టోకెన్ బడ్జెట్ను ఒక్క క్లిక్ దూరంలో ఉంచుతుంది — **తెరిచి ఉంచాల్సిన
> టెర్మినల్ విండో లేదు, పర్యవేక్షిస్తూ ఉండాల్సిన `npm install -g omniroute` లేదు.**

[Tauri v2](https://v2.tauri.app/)తో నిర్మించబడిన ఇది (రౌండింగ్ లోపం అంత పరిమాణంలో ఉండే Rust కోర్), తన
సొంత సంతకం చేసిన Node 24 రన్టైమ్తో వస్తుంది మరియు యాప్ యాజమాన్యంలోని OmniRoute ఇన్స్టాలేషన్ను నిర్వహిస్తుంది, కాబట్టి ఇది మీ
గ్లోబల్ `node`/`bun`తో ఎప్పుడూ విభేదించదు. ఇది **మీ ప్రస్తుత `~/.omniroute/` కాన్ఫిగ్ మరియు డేటాబేస్ను పంచుకుంటుంది** — కాబట్టి ఇది

## 🔌 సంపూర్ణ CLI + A2A & MCP

</div>

> సర్వర్కు మించి, OmniRoute అనేది **80+ కమాండ్లతో కూడిన సంపూర్ణ కమాండ్-లైన్ కాక్పిట్**; అదనంగా, ఒక AI ఏజెంట్ దాన్ని **స్వయంగా** నియంత్రించగలిగేలా ఓపెన్ ఏజెంట్ ప్రోటోకాల్లను అందిస్తుంది.

### ⌨️ నిజమైన CLI (కేవలం `start` మాత్రమే కాదు)

```bash
omniroute               # గేట్వే + డ్యాష్బోర్డ్ను అందించండి (పోర్ట్ 20128)
omniroute chat          # ఇంటరాక్టివ్ TUI చాట్ క్లయింట్ (స్లాష్: /model /combo /skill /memory)
omniroute setup         # మార్గనిర్దేశిత తొలి-వినియోగ విజార్డ్
omniroute doctor        # ప్రొవైడర్లు, పోర్ట్లు, నేటివ్ డిపెండెన్సీలను నిర్ధారించండి
```

### 🛰️ రిమోట్ మోడ్ — CLIని ఇక్కడ, OmniRouteని VPSలో నడపండి

OmniRoute సర్వర్లో ఉందా? **అదే CLI**తో మీ ల్యాప్టాప్ నుండి దాన్ని నియంత్రించండి. స్కోప్ చేసిన యాక్సెస్ టోకెన్తో ఒక్కసారి
లాగిన్ అవ్వండి; ఆ తర్వాత ప్రతి కమాండ్ రిమోట్ను లక్ష్యంగా చేసుకుంటుంది.

```bash
omniroute connect 192.168.0.15            # పాస్వర్డ్ → స్కోప్ చేసిన టోకెన్, కాంటెక్స్ట్గా సేవ్ చేయబడుతుంది
omniroute models list                     # ← రిమోట్ సర్వర్పై నడుస్తుంది
omniroute configure codex                 # ← రిమోట్ మోడల్ను ఎంచుకుని, స్థానిక Codex ప్రొఫైల్ను రాస్తుంది
omniroute tokens create --name ci --scope read   # ఇతర మెషీన్ల కోసం మరింత పరిమిత టోకెన్లను సృష్టించండి
omniroute contexts use default            # ← తిరిగి స్థానిక సర్వర్కు మారండి
```

టోకెన్లు `read` / `write` / `admin` స్కోప్లను కలిగి ఉంటాయి; ప్రాసెస్లను ప్రారంభించే రూట్లు లూప్బ్యాక్కు మాత్రమే పరిమితమై ఉంటాయి.

## 🗜️ 15–95% టోకెన్లను ఆదా చేయండి — స్వయంచాలకంగా

### 📖 ఇది ఎలా పనిచేస్తుంది — పైప్లైన్, ఆర్కిటెక్చర్ & ఆదా గణితం

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute కంప్రెషన్ పైప్లైన్: ఉదాహరణాత్మకమైన 10,000-టోకెన్ క్లయింట్ అభ్యర్థన 12 సమ్మిళిత ఇంజిన్ల గుండా వెళుతుంది — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra మరియు OmniGlyph — డాక్యుమెంట్ చేసిన స్టాక్డ్ ఉదాహరణలో సుమారు 1,080 టోకెన్లతో ప్రొవైడర్ను చేరగలదు. నిర్మిత కంటెంట్ ప్రిజర్వేషన్ గార్డ్లు మరియు ప్రతి దశలోని ఫిడెలిటీ గేట్ల ద్వారా రక్షించబడుతుంది; స్పష్టంగా పేర్కొన్న నష్టసహిత లేదా ప్రయోగాత్మక మోడ్లు అర్హమైన కంటెంట్ను మార్చవచ్చు."/>

డిఫాల్ట్ స్టాక్డ్ కాంబో `RTK → Caveman`ను అమలు చేస్తుంది. రెండూ ఒకే టూల్/కాంటెక్స్ట్ పేలోడ్పై పనిచేసినప్పుడు, ఆదా చక్రవడ్డీలా పెరుగుతుంది:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

కోడ్ బ్లాక్లు, URLలు, JSON మరియు నిర్మిత డేటా ప్రిజర్వేషన్ ఇంజిన్ ద్వారా **ఎల్లప్పుడూ రక్షించబడతాయి**.

> **కొద్ది టోకెన్లతో పని పూర్తయ్యేటప్పుడు ఎక్కువ టోకెన్లు ఎందుకు ఉపయోగించాలి?** ప్రతి అభ్యర్థన OmniRoute కంప్రెషన్ పైప్లైన్ గుండా **పారదర్శకంగా** వెళుతుంది — క్లయింట్ మార్పులు అవసరం లేదు. ఇప్పుడు ఇది క్రమానుసారంగా అమలయ్యే, ప్రతి రూటింగ్ కాంబోకు అవసరానుసారం కలిపి ఉపయోగించగల **12 సమ్మిళిత ఇంజిన్ల స్టాక్** — [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K+), [LLMLingua-2](https://github.com/microsoft/LLMLingua), మరియు [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR) ఆలోచనలపై నిర్మించబడింది.

### 🎚️ ఇంజిన్లకు మించి — అవుట్పుట్ శైలులు, అడాప్టివ్ డయల్ & ప్రతి అభ్యర్థనపై నియంత్రణ

పైన ఉన్న 12 ఇంజిన్లు లోపలికి వెళ్లేదాన్ని కుదిస్తాయి. మరో మూడు లేయర్లు **ఎలా**, **ఎప్పుడు**, మరియు బయటకు **ఏమి** వస్తుందో రూపొందిస్తాయి:

- **🪄 అవుట్పుట్ శైలులు** _(అవుట్పుట్-అక్ష నియంత్రణ)_ — నిర్దిష్టమైన, క్యాష్కు సురక్షితమైన ప్రతిస్పందన-రూపకల్పన సూచనలను చొప్పిస్తాయి; వీటిని కలిపి ఉపయోగించవచ్చు, ప్రతి ఒక్కటి `lite` / `full` / `ultra` తీవ్రతలో ఉంటుంది. ఒక శైలిని జోడించడానికి రిజిస్ట్రీలో ఒకే పంక్తి ఎంట్రీ సరిపోతుంది:
  - **సంక్షిప్త గద్యం** — అనవసర పదాలు / ఆర్టికల్లు / సందిగ్ధతను తొలగిస్తుంది; సాంకేతిక సారాన్ని ఖచ్చితంగా ఉంచుతుంది.
  - **తక్కువ కోడ్** — "సోమరి సీనియర్ డెవలపర్" YAGNI: పని చేసే అతి చిన్న మార్పు, అడగని స్కాఫోల్డింగ్ ఉండదు.
  - **పోనీటెయిల్ (సోమరి సీనియర్ డెవలపర్)** — YAGNI నిచ్చెనను ఎక్కి, మూల కారణాన్ని పరిష్కరించి, పని చేసే అతి చిన్న diffను అందిస్తుంది.
  - **నాకు ADHD ఉంది (చర్య-ముందు)** — తదుపరి చర్య ముందుగా వస్తుంది, దశలు సంఖ్యలతో ఉంటాయి, ఒక నిర్దిష్ట తదుపరి దశ ఉంటుంది, ఉపోద్ఘాతం ఉండదు.
  - **సంక్షిప్త CJK (文言)** — సాంప్రదాయ-చైనీస్ అత్యంత సంక్షిప్త శైలి (`zh` లోకేల్కు మాత్రమే పరిమితం).
- **🎯 అడాప్టివ్ కాంటెక్స్ట్-బడ్జెట్** _(డయల్)_ — ఒకే ఆన్/ఆఫ్ టోకెన్ థ్రెషోల్డ్కు బదులుగా, **మోడల్ కాంటెక్స్ట్ విండోలో సరిపడేందుకు** అవసరమైనంత వరకే అతి చవకైన, అత్యల్ప-నష్ట ఇంజిన్లను క్రమంగా వర్తింపజేస్తుంది. విధానం: `reserve-output` (డిఫాల్ట్, మోడల్-అవగాహనతో) · `percentage` · `absolute`. మోడ్: `floor` (సరిపోతుందని హామీ) · `replace-autotrigger` (మీ స్పష్టమైన ఎంపికకు ప్రాధాన్యం) · `off` (పాత థ్రెషోల్డ్).
- **🎛️ కంప్రెషన్ ఎక్కడ నిర్ణయించబడుతుంది** _(ప్రాధాన్య క్రమం, ఎక్కువ → తక్కువ)_ — ప్రతి అభ్యర్థనకు `x-omniroute-compression` హెడర్ › రౌటింగ్-కాంబో ఓవర్రైడ్ › సక్రియ నేమ్డ్ ప్రొఫైల్ › అడాప్టివ్ / ఆటో-ట్రిగర్ › ప్యానెల్ డిఫాల్ట్ › ఆఫ్. వర్తింపజేసిన ప్లాన్ `X-OmniRoute-Compression: <mode>; source=<source>` ప్రతిస్పందన హెడర్లో తిరిగి ప్రతిధ్వనిస్తుంది.

టోకెన్ థ్రెషోల్డ్ ద్వారా ఆటో-ట్రిగర్ చేయండి, అడాప్టివ్ డయల్ను ఆన్ చేయండి, నేమ్డ్ ప్రొఫైల్ను పిన్ చేయండి, ప్రతి అభ్యర్థనకు ఒకసారి మాత్రమే వర్తించే సెట్టింగ్ను నిర్దేశించండి, లేదా ప్రతి రౌటింగ్ కాంబోకు ఒక పైప్లైన్ను కేటాయించండి — పనిభారానికి ఏది సరిపోతే అది ఉపయోగించండి. మార్పును అమల్లోకి తీసుకురావడానికి ముందు, స్వచ్ఛందంగా ఉపయోగించగల ఆఫ్లైన్ **మూల్యాంకన హార్నెస్** (`npm run eval:compression`) పిన్ చేసిన కార్పస్పై నాణ్యత పరిరక్షణను ఆదాతో పోల్చి స్కోర్ చేస్తుంది.

```txt
OpenAI responses: http://localhost:20128/vscode/YOUR_KEY/responses
Ollama chat:      http://localhost:20128/vscode/YOUR_KEY/api/chat
Ollama tags:      http://localhost:20128/vscode/YOUR_KEY/api/tags
```

`Authorization: Bearer ...` జోడించలేని క్లయింట్ల కోసం మాత్రమే వీటిని ఉపయోగించండి. హెడర్ ప్రామాణీకరణే ప్రాధాన్య మోడ్గా కొనసాగుతుంది.

## 📦 మరిన్ని ఇన్స్టాలేషన్ పద్ధతులు — Docker, సోర్స్, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

`:latest` అత్యధికంగా **ప్రచురించబడిన** స్థిరమైన SemVerను అనుసరిస్తుంది. ఇది git `main`ను ట్రాక్ చేయదు. GitOps కోసం `:X.Y.Z`ను పిన్ చేయండి. [Docker విడుదల ఛానెల్లు](docs/guides/DOCKER_GUIDE.md#release-channels) చూడండి. ఇమేజ్లో **`OMNIROUTE_MEMORY_MB=1024`** పిన్ చేయబడింది. డ్యాష్బోర్డ్ మరియు తేలికపాటి చాట్ కోసం అది సరిపోతుంది. **కోడింగ్ ఏజెంట్లకు** (Claude Code, Codex, Grok, … నుండి `POST /v1/responses`) చాలా పెద్ద V8 హీప్ అవసరం; లేకపోతే ఒకదానితో ఒకటి ఓవర్ల్యాప్ అయ్యే రెండు దీర్ఘ కాంటెక్స్ట్ల కింద సుమారు 12 GiB వద్ద ప్రాసెస్ `FATAL ERROR`తో విఫలమవుతుంది. కంటైనర్ పరిమాణాన్ని హీప్ కంటే ఎక్కువగా సెట్ చేయండి (నేటివ్ బఫర్లు V8 వెలుపల ఉంటాయి):

| వర్క్లోడ్                            | హీప్ (`-e OMNIROUTE_MEMORY_MB`) | కంటైనర్ (`--memory`) |
| ------------------------------------ | ------------------------------- | -------------------- |
| డ్యాష్బోర్డ్ / తేలికపాటి చాట్        | `1024` (ఇమేజ్ డిఫాల్ట్)         | ≥2 g                 |
| ఒక కోడింగ్ ఏజెంట్                    | `8192`                          | ≥10 g                |
| ఏకకాలంలో రెండు దీర్ఘ `/v1/responses` | `10240`–`12288`                 | ≥12–16 g             |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

పూర్తి పట్టిక: [Docker గైడ్ — రన్టైమ్ RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

> **ప్రీ-రిలీజ్ Docker ఛానెల్:** `diegosouzapw/omniroute:next` మరియు
> `diegosouzapw/omniroute:next-web` ప్రస్తుత డిఫాల్ట్ `release/v*`
> బ్రాంచ్ను అనుసరిస్తాయి. ఈ మార్చగల ట్యాగ్లు విడుదల కాని పరిష్కారాలను పరీక్షించడానికి మాత్రమే
> ఉద్దేశించబడ్డాయి మరియు **ప్రొడక్షన్లో వినియోగానికి మద్దతు లేదు**. చూడండి:
> [Docker విడుదల ఛానెల్లు](docs/guides/DOCKER_GUIDE.md#release-channels).

**🥟 Bun**

Bun రన్టైమ్ గుర్తింపు ద్వారా ప్రామాణిక `bun install` మరియు గ్లోబల్ ఇన్స్టాలేషన్ (`bun install -g omniroute`)కు మద్దతు ఉంది:

- **అంతర్నిర్మిత `bun:sqlite`**: Bun కింద రన్ అవుతున్నప్పుడు OmniRoute, Bun యొక్క అంతర్నిర్మిత `bun:sqlite` డ్రైవర్ను ఉపయోగిస్తుంది; Node.jsలో `better-sqlite3`కు లేదా `sql.js`కు ఫాల్బ్యాక్ అవుతుంది.
- **డెవలప్మెంట్లో ఆటోమేటిక్ Webpack బండ్లర్ ఎంపిక**: నేటివ్ V8 బైండింగ్ అనుకూలత సమస్యలను నివారించడానికి, డెవలప్మెంట్ (`bun run dev`) స్వయంచాలకంగా Bunను గుర్తించి Turbopackను నిలిపివేసి Webpackను ఉపయోగిస్తుంది. ప్రొడక్షన్ బిల్డ్లు (`bun run build`) Nodeలో మాదిరిగానే `OMNIROUTE_USE_TURBOPACK`ను ఖచ్చితంగా అనుసరిస్తాయి: డిఫాల్ట్గా Turbopack, Webpackతో బిల్డ్ చేయడానికి `OMNIROUTE_USE_TURBOPACK=0` (`Dockerfile.bun` దీన్ని `--build-arg`గా అందుబాటులో ఉంచుతుంది).
- **ప్రత్యేక Bun Dockerfile**: నేటివ్ Bun ప్రొడక్షన్ డిప్లాయ్మెంట్ల కోసం మల్టీ-స్టేజ్ `Dockerfile.bun` (`docker build -f Dockerfile.bun -t omniroute:bun .`).

```bash
# Bunతో ఇన్స్టాల్ చేసి రన్ చేయండి
bun install
bun run dev
```

**⚡ వేగవంతమైన / తేలికైన ఇన్స్టాలేషన్ (నేటివ్ బిల్డ్ను దాటవేయండి)**

నేటివ్ SQLite ఇంజిన్ (`better-sqlite3`) ఒక **ఐచ్ఛిక** డిపెండెన్సీ, కాబట్టి గ్లోబల్
ఇన్స్టాలేషన్ ఎప్పుడూ సోర్స్ నుండి కంపైల్ కావడం కోసం నిలిచిపోదు: మీ ప్లాట్ఫారమ్/Nodeకు సరిపోయేది
ఉన్నప్పుడు ఇది ముందే బిల్డ్ చేసిన బైనరీని ఉపయోగిస్తుంది; లేకపోతే పారదర్శకంగా ప్యూర్-JS ఇంజిన్కు
ఫాల్బ్యాక్ అవుతుంది (Node 22+లో `node:sqlite`, లేకపోతే బండిల్ చేసిన `sql.js` WASM) — బిల్డ్ టూల్స్ అవసరం లేదు.

ఇన్స్టాలేషన్ తర్వాతి నేటివ్ వార్మ్-అప్ను పూర్తిగా దాటవేయడానికి (CI, హెడ్లెస్ లేదా నెమ్మదైన మెషీన్లు):

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 కూడా దీన్ని దాటవేస్తుంది
```

అత్యంత వేగవంతమైన ఇన్స్టాలేషన్ల కోసం **pnpm**ను ప్రాధాన్యంగా ఉపయోగించండి (కంటెంట్-అడ్రెస్డ్ స్టోర్ + హార్డ్ లింక్లు — పైన చూడండి).
డ్యాష్బోర్డ్ లేని హెడ్లెస్ రన్టైమ్ కోసం Docker `base` ప్రొఫైల్ను (పైన) లేదా
[Termux గైడ్ను](docs/guides/TERMUX_GUIDE.md) ఉపయోగించండి. CLI మరియు వెబ్ డ్యాష్బోర్డ్ ఒకే పోర్ట్పై ఒకే
ప్రాసెస్ ద్వారా అందించబడతాయి, కాబట్టి ప్రస్తుతం ప్రత్యేక CLI-మాత్రమే ప్యాకేజ్ లేదు.
