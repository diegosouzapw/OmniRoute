టెంప్లేట్: xquik #11370 (release/v3.8.51లో విలీనం చేయబడింది). విధానం: `fallbackOnly`.
అప్స్ట్రీమ్ ప్రతిపాదన: ఇష్యూ diegosouzapw/OmniRoute#11637.

## 1. సేవకు సంబంధించిన ప్రామాణిక వాస్తవాలు (అధికారిక డాక్యుమెంటేషన్, పరస్పర తనిఖీ చేయబడింది)

- బేస్ URL: `https://api.anysearch.com` (REST) + `POST /mcp` (MCP, JSON-RPC 2.0).
- `POST /v1/search` - పారామీటర్లు: `query` (తప్పనిసరి), `max_results` (1-10, డిఫాల్ట్ 10), `tag` (`{domain}.{sub_domain}` వర్టికల్ రూటింగ్), `zone` (cn/intl), `language`, `params` (నిర్మిత వర్టికల్ ఫీల్డ్లు), `format` (json/markdown).
- `GET /v1/sub-domains?domain=...` - సామర్థ్యాల కేటలాగ్, కోటాలో లెక్కించబడదు.
- `POST /v1/extract` - `{url, title, content}`ను పొందుతుంది/వెలికితీస్తుంది; కఠినమైన JSON బాడీ, 16 KiB పరిమితి.
- `POST /v1/auth/email/register` - ఒకే కాల్తో నమోదు, ఒక్కసారి మాత్రమే చూపబడే ప్లెయిన్టెక్స్ట్ కీ `as_sk_...`ని తిరిగి ఇస్తుంది.
- ప్రామాణీకరణ: ఐచ్ఛిక `Authorization: Bearer <as_sk_...>`; అనామక వినియోగం రోజువారీ ఉచిత కోటాను వినియోగించే ప్రతి-IP పరిమితులకు దిగజారుతుంది; చెల్లని కీ 401/403ను తిరిగి ఇస్తుంది, ఎటువంటి నిశ్శబ్ద అనామక ఫాల్బ్యాక్ ఉండదు.
- ఉచిత స్థాయి: రోజుకు 1000 అభ్యర్థనలు, ప్రతి కీకి 20 QPS. చెల్లింపు స్థాయి: ధర నిర్ణయించబడలేదు (త్వరలో అందుబాటులోకి వస్తుంది).
- ప్రతిస్పందన ఎన్వలప్: విజయం `{code: 0, message: "success", request_id, data}`; వైఫల్యం `{code: -1, message}`. ప్రామాణీకరణ/కోటా లోపాల్లో నిర్మిత `error_code` ఉండదు (సందేశ టెక్స్ట్నే సంకేతంగా ఉపయోగించాలి); ఎక్స్ట్రాక్ట్కు ప్రత్యేకమైన లోపాల్లో మాత్రం `error_code` ఉంటుంది (`invalid_extract_url`, `extract_failed`). 429పై `Retry-After` హెడర్ ఉండదు.

## 3. నిర్ణయాలు (అన్నీ 2026-08-26న తీసుకున్నవి)

1. **రూటింగ్ విధానం: `fallbackOnly`.** హేతువు: cost-0 ఉచిత ప్రొవైడర్ ఆటోమేటిక్ ఖర్చు-ఆధారిత రూటింగ్లో ఎప్పుడూ ఆధిపత్యం వహించకూడదు; స్పష్టమైన ఎంపిక మరియు ఫెయిల్ఓవర్ రిటర్న్పై ఎటువంటి ప్రభావం ఉండదు. పూర్వ ఉదాహరణ: విలీనం చేసిన xquik ఎంట్రీ.
2. **పరిధి: v1లో `POST /v1/extract` ద్వారా webSearch + webFetch.** ఇది tavily/exa ద్వంద్వ-సామర్థ్య మానసిక నమూనాకు అనుగుణంగా ఉంది. వర్టికల్ సర్ఫేస్లు (`tag`, `sub-domains`, `batch_search`) పరిధికి వెలుపలే ఉంటాయి — ప్రస్తుతం వర్టికల్ పారామీటర్ల కోసం ఎటువంటి IR లేదు.
3. **కోటా ప్రదర్శన: `freeMonthlyQuota: 0`** (xquik-శైలి సంప్రదాయవాద ప్రదర్శన). వాస్తవ పరిమితి (రోజుకు 1000 అభ్యర్థనలు, రోజువారీ రీసెట్) బదులుగా UI కేటలాగ్లోని `authHint` టెక్స్ట్లో పేర్కొనబడుతుంది. హేతువు: కోటా ప్రదర్శన రీసెట్ సెమాంటిక్స్కు సరిపోలాలి; రోజువారీ పరిమితిని నెలవారీ సమాన విలువగా (30000) మార్చడం, UI నెరవేర్చలేని తప్పుడు హామీ అవుతుంది.
4. **searchTypes: `["web"]` మాత్రమే.** AnySearch APIలో వార్తలు/చిత్రాల వర్టికల్కు సంబంధించి బహిరంగ ఆధారాలు లేవు; డాక్యుమెంట్ చేయబడిన వర్టికల్ లేని APIలను అనుసంధానించే గేట్వేలు (ఉదా. Google Custom Search), news -> webగా నిశ్శబ్దంగా మ్యాప్ చేయకుండా webను మాత్రమే అందుబాటులో ఉంచుతాయి.
5. **కీ విధానం:** కీ లేకుండానూ పని చేస్తుంది; చెల్లని కీ 401/403ను తిరిగి ఇస్తుంది మరియు దానిని ఎప్పుడూ నిశ్శబ్దంగా అనామక మోడ్కు డౌన్గ్రేడ్ చేయరు (అప్స్ట్రీమ్ ఒప్పందాన్ని ప్రతిబింబిస్తుంది).
6. **ఉద్దేశపూర్వక మినహాయింపులు:** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (చాట్ ఇంటర్సెప్షన్ firecrawl/jina/tavilyకే పరిమితమవుతుంది); `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (అనామక రిమోట్ ఎండ్పాయింట్లు ప్రతి ఎగ్రెస్ IPకి ఒకే IP-పరిమిత పూల్ను పంచుకుంటాయి, కాబట్టి కీ లేని extract అనేది ఆప్ట్-ఇన్ మాత్రమే, ఆటో-రూటింగ్ అభ్యర్థి కాదు); `QUOTA_STATUS_PROVIDERS` (AnySearch కోటాను 402/403 స్టేటస్ ద్వారా కాకుండా 429/ఎన్వలప్ ద్వారా సూచిస్తుంది).
