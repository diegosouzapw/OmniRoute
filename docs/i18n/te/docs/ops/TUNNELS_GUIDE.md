OmniRoute తన స్థానిక సర్వర్ను (`http://localhost:20128`) మూడు టన్నెల్ బ్యాకెండ్ల
ద్వారా పబ్లిక్ ఇంటర్నెట్కు అందుబాటులో ఉంచగలదు. ఇది క్రింది సందర్భాల్లో ఉపయోగపడుతుంది:

- పబ్లిక్గా చేరుకోగల రీడైరెక్ట్ URL అవసరమయ్యే క్లౌడ్ ప్రొవైడర్ల (Antigravity, Gemini, Cursor)
  నుండి వచ్చే OAuth కాల్బ్యాక్లు.
- VMను డిప్లాయ్ చేయకుండానే మీ స్థానిక ఇన్స్టాన్స్ను సహచరులతో పంచుకోవడం.
- మొబైల్, రిమోట్ లేదా క్రాస్-నెట్వర్క్ పరీక్ష.

మూడు బ్యాకెండ్లూ ప్రాసెస్లోనే నిర్వహించబడతాయి — OmniRoute డ్యాష్బోర్డ్ లేదా REST API
నుండి అంతర్లీన బైనరీ లేదా SDKని ప్రారంభిస్తుంది/నిలిపివేస్తుంది. రివర్స్-ప్రాక్సీ లేదా systemd
సెటప్ అవసరం లేదు.

| --------------------------- | ------------------------------------------------------------------------- | ---------------------------- | ----------------------------------------------------------------- |
| **Cloudflare Quick Tunnel** | తాత్కాలికం (ప్రతి పునఃప్రారంభంలో URL మారుతుంది)                           | ఉచితం                        | ఏమీ అవసరం లేదు — `cloudflared`ను స్వయంచాలకంగా ఇన్స్టాల్ చేస్తుంది |
| **ngrok**                   | చెల్లింపు ప్లాన్ లేదా స్థిర డొమైన్ కాన్ఫిగర్ చేసినంతవరకు స్థిరంగా ఉంటుంది | ఉచిత శ్రేణి + చెల్లింపు      | ngrok ఖాతా + authtoken అవసరం                                      |

అమలులు `src/lib/cloudflaredTunnel.ts`,
`src/lib/ngrokTunnel.ts`, మరియు `src/lib/tailscaleTunnel.ts`లో ఉన్నాయి. మూడూ
`phase`, `running`, `publicUrl`, `apiUrl`,
`targetUrl`, మరియు `lastError` ఫీల్డ్లతో ఒకే ఆకృతిగల `status` ఆబ్జెక్ట్ను అందిస్తాయి, తద్వారా డ్యాష్బోర్డ్ వాటిని ఏకరీతిగా రెండర్ చేయగలదు.

## 1. Cloudflare Tunnel (Quick Tunnel + Named Tunnel)

`src/lib/cloudflaredTunnel.ts`, `cloudflared`ను చైల్డ్ ప్రాసెస్గా అమలు చేస్తుంది. ఇది
నేమ్డ్-టన్నెల్ కాన్ఫిగ్ అందించబడిందా లేదా అనేదాని ఆధారంగా ఎంచుకోబడే రెండు మోడ్లకు మద్దతు ఇస్తుంది:

- **క్విక్ టన్నెల్ (డిఫాల్ట్).** `cloudflared tunnel --url
http://localhost:<apiPort>`ను అమలు చేసి, stdout నుండి కేటాయించబడిన `*.trycloudflare.com` URLను
  పార్స్ చేస్తుంది. URLలు తాత్కాలికమైనవి మరియు ప్రతి పునఃప్రారంభంలో మారతాయి.
- **నేమ్డ్ టన్నెల్ (ఐచ్ఛికం).** `CLOUDFLARED_CONFIG` స్థానికంగా నిర్వహించబడే
  cloudflared `config.yml`ను సూచించినప్పుడు, OmniRoute `cloudflared tunnel --no-autoupdate
--config <path> run`ను అమలు చేస్తుంది, తద్వారా మీకు **స్థిరమైన, పేరు కలిగిన హోస్ట్నేమ్** లభిస్తుంది. కాన్ఫిగ్
  టన్నెల్ UUID, `credentials-file`, మరియు `ingress` రూటింగ్ను అందిస్తుంది, కాబట్టి
  `--url` పంపబడదు మరియు Zero Trust డ్యాష్బోర్డ్ టోకెన్ అవసరం లేదు. `run`,
  కాన్ఫిగ్లోని సంపూర్ణ `credentials-file` పాత్ నుండి క్రెడెన్షియల్లను చదువుతుంది — `cert.pem`
  అవసరం లేదు (అది టన్నెల్ లైఫ్సైకిల్ నిర్వహణకు మాత్రమే ఉపయోగించబడుతుంది).

ముఖ్య ప్రవర్తనలు:

- **స్వయంచాలక ఇన్స్టాలేషన్.** మొదటిసారి ఉపయోగించినప్పుడు, OmniRoute అధికారిక GitHub విడుదలల
  నుండి తాజా `cloudflared` బైనరీని డౌన్లోడ్ చేస్తుంది (నిర్వహిత ఇన్స్టాలేషన్
  `DATA_DIR/cloudflared/` కింద ఉంటుంది). డౌన్లోడ్ చేసిన అసెట్ యొక్క SHA256ను అమలు చేయడానికి ముందు
  విడుదల మానిఫెస్ట్తో సరిపోల్చి ధృవీకరిస్తుంది.
- **ప్రాసెస్ పర్యవేక్షణ.** డ్యాష్బోర్డ్ రీలోడ్ల తర్వాత కూడా స్థితిని తిరిగి కొనసాగించగలిగేలా cloudflared PID మరియు పరిష్కరించబడిన URL
  `quick-tunnel-state.json`లో నిల్వ చేయబడతాయి.

### నేమ్డ్ టన్నెల్ సెటప్ (స్థిర హోస్ట్నేమ్)

1. cloudflared CLIతో స్థానికంగా నిర్వహించబడే టన్నెల్ను సృష్టించండి (ఒకసారి మాత్రమే):

   ```bash
   cloudflared tunnel login
   cloudflared tunnel create omniroute
   cloudflared tunnel route dns omniroute ai.example.com
   ```

2. మీ హోస్ట్నేమ్ను OmniRoute స్థానిక
   API పోర్ట్కు (డిఫాల్ట్ 20128) రూట్ చేసే `~/.cloudflared/config.yml`ను వ్రాయండి:

   ```yaml
   tunnel: <UUID-from-create>
   credentials-file: /home/you/.cloudflared/<UUID>.json
   ingress:
     - hostname: ai.example.com
       service: http://127.0.0.1:20128
     - service: http_status:404
   ```

3. OmniRouteను కాన్ఫిగ్కు సూచించి, టన్నెల్ను (పునః)ప్రారంభించండి:

   ```bash
   export CLOUDFLARED_CONFIG="/home/you/.cloudflared/config.yml"
   # ఐచ్ఛికం — OmniRoute నివేదించే హోస్ట్నేమ్ను ఓవర్రైడ్ చేస్తుంది; లేకపోతే
   # కాన్ఫిగ్లోని మొదటి ingress నియమం నుండి చదవబడుతుంది:
   # export CLOUDFLARED_HOSTNAME="ai.example.com"
   ```

   క్విక్ టన్నెల్ మాదిరిగానే టన్నెల్ను ప్రారంభించండి (క్రింద REST / డ్యాష్బోర్డ్ / CLI
   చూడండి). నేమ్డ్ టన్నెల్ స్క్రేప్ చేయడానికి ఎటువంటి పబ్లిక్ URLను విడుదల చేయదు, కాబట్టి cloudflared నమోదు చేసిన ఎడ్జ్ కనెక్షన్ ద్వారా
   సిద్ధత గుర్తించబడుతుంది, మరియు `publicUrl`/`apiUrl`లు
   `CLOUDFLARED_HOSTNAME` (లేదా కాన్ఫిగ్లోని మొదటి ingress హోస్ట్నేమ్) నుండి నివేదించబడతాయి.

### REST ద్వారా ప్రారంభించడం / నిలిపివేయడం

ఎండ్పాయింట్ వేర్వేరు `start`/`stop` పాత్లను కాకుండా
`{action: "enable" | "disable"}` బాడీని ఉపయోగిస్తుంది. నిర్వహణ ప్రామాణీకరణ (అడ్మిన్ సెషన్ లేదా అడ్మిన్ API కీ)
అవసరం.

```bash
# ప్రారంభించండి
curl -X POST http://localhost:20128/api/tunnels/cloudflared \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"enable"}'

# స్థితి
curl http://localhost:20128/api/tunnels/cloudflared \
  -H "Cookie: auth_token=..."

# నిలిపివేయండి
curl -X POST http://localhost:20128/api/tunnels/cloudflared \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"disable"}'
```

లేదా డ్యాష్బోర్డ్ ద్వారా: **Settings → Tunnels → Cloudflare**.

### ఐచ్ఛిక env vars

| వేరియబుల్                                            | ప్రయోజనం                                                                                                                                                                                           |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CLOUDFLARED_BIN`                                    | బైనరీ పాత్ను ఓవర్రైడ్ చేస్తుంది. ఇది సెట్ చేయబడి చెల్లుబాటులో ఉంటే, డౌన్లోడ్ చేయడానికి బదులుగా OmniRoute దీనిని ఉపయోగిస్తుంది.                                                                     |
| `CLOUDFLARED_PROTOCOL` / `TUNNEL_TRANSPORT_PROTOCOL` | ట్రాన్స్పోర్ట్ ప్రోటోకాల్ (డిఫాల్ట్ `http2`; `quic`, `auto` కూడా అందుబాటులో ఉన్నాయి).                                                                                                              |
| `CLOUDFLARED_CONFIG`                                 | స్థానికంగా నిర్వహించబడే cloudflared `config.yml` పాత్. ఇది సెట్ చేయబడినప్పుడు, క్విక్ టన్నెల్కు బదులుగా OmniRoute **నేమ్డ్/పర్సిస్టెంట్** టన్నెల్ను (`tunnel --config <path> run`) అమలు చేస్తుంది. |
| `CLOUDFLARED_HOSTNAME`                               | నేమ్డ్ టన్నెల్ నివేదించే పబ్లిక్ హోస్ట్నేమ్ను ఓవర్రైడ్ చేస్తుంది (ఉదా. `ai.example.com`). ఇది సెట్ చేయబడనప్పుడు, కాన్ఫిగ్లోని మొదటి `ingress` హోస్ట్నేమ్ నుండి చదవబడుతుంది.                        |

## 2. ngrok

`src/lib/ngrokTunnel.ts` **`@ngrok/ngrok` SDK**ని ఉపయోగిస్తుంది (ప్రాసెస్లోనే, CLI
సబ్ప్రాసెస్ లేకుండా). ముందే బిల్డ్ చేసిన బైనరీలు లేని ప్లాట్ఫారమ్లలో యాప్
బూట్ సమయంలో విఫలం కాకుండా, మొదటిసారి ప్రారంభించినప్పుడు మాత్రమే నేటివ్ మాడ్యూల్ దిగుమతి చేయబడుతుంది.

### ముందస్తు అవసరాలు

1. <https://ngrok.com>లో సైన్ అప్ చేయండి.
2. ngrok డ్యాష్బోర్డ్ నుండి మీ authtokenను కాపీ చేయండి.
3. దాన్ని కింది మార్గాల్లో ఏదో ఒకదాని ద్వారా అందించండి:
   - `.env`: `NGROK_AUTHTOKEN=<token>`, లేదా
   - డ్యాష్బోర్డ్: **Settings → Tunnels → ngrok**, లేదా
   - REST బాడీ (ఒక్కసారి మాత్రమే): `{"action":"enable","authToken":"<token>"}`.

ఏదీ కాన్ఫిగర్ చేయకపోతే, స్థితి `phase: "needs_auth"`ను తిరిగి ఇస్తుంది.

### REST ద్వారా ప్రారంభించడం / నిలిపివేయడం

```bash
# ప్రారంభించండి (env నుండి NGROK_AUTHTOKENను ఉపయోగిస్తుంది)
curl -X POST http://localhost:20128/api/tunnels/ngrok \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"enable"}'

# ఇన్లైన్ టోకెన్తో ప్రారంభించండి
curl -X POST http://localhost:20128/api/tunnels/ngrok \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"enable","authToken":"2abc..."}'

# స్థితి
curl http://localhost:20128/api/tunnels/ngrok \
  -H "Cookie: auth_token=..."

# నిలిపివేయండి
curl -X POST http://localhost:20128/api/tunnels/ngrok \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"disable"}'
```

ప్రతిస్పందనలో కేటాయించిన `publicUrl` ఉంటుంది (ఉదా.
`https://abcd-1234.ngrok-free.app`). కస్టమ్ డొమైన్లు, ప్రాంతాలు మరియు పాలసీ నియమాలను
ngrok డ్యాష్బోర్డ్లో కాన్ఫిగర్ చేయాలి — OmniRoute స్వయంగా స్థానిక లక్ష్య URLను
SDKకి మాత్రమే ఫార్వర్డ్ చేస్తుంది.

## 3. Tailscale Funnel

`src/lib/tailscaleTunnel.ts`, స్థానిక API పోర్ట్ను **Funnel** (serve కోసం Tailscale యొక్క
పబ్లిక్-ఇంటర్నెట్ ఎగ్రెస్) ద్వారా బహిర్గతం చేయడానికి సిస్టమ్ `tailscale` CLIని సమన్వయం చేస్తుంది.
ఇది పూర్తి జీవితచక్రానికి మద్దతిస్తుంది: ఇన్స్టాల్, లాగిన్, డీమన్ ప్రారంభం, ప్రారంభించడం, నిలిపివేయడం.

అమలు `tailscale funnel --bg <port>`ను (నేపథ్య మోడ్) అమలు చేస్తుంది.
పబ్లిక్ URL `https://<machine>.<tailnet>.ts.net/` ఆకారంలో ఉంటుంది.

### ముందస్తు అవసరాలు

1. Tailscaleను ఇన్స్టాల్ చేయండి (లేదా OmniRouteతో చేయించండి — దిగువన ఉన్న `install` ఎండ్పాయింట్ను చూడండి).
2. సైన్ ఇన్ చేయండి (`tailscale login` లేదా OmniRoute యొక్క `login` ఎండ్పాయింట్ ద్వారా).
3. Tailscale అడ్మిన్ కన్సోల్లో మీ tailnet కోసం Funnelను ప్రారంభించండి:
   <https://login.tailscale.com/admin/settings/features>.

Linux మరియు macOSలో డీమన్ను (`tailscaled`) నియంత్రించడానికి `sudo` అవసరం.
POST ఎండ్పాయింట్లు ఐచ్ఛిక `sudoPassword` ఫీల్డ్ను అంగీకరిస్తాయి; కాల్ వ్యవధి వరకు అది
OmniRoute యొక్క MITM పాస్వర్డ్ క్యాష్కు (`getCachedPassword` / `setCachedPassword`)
ఫార్వర్డ్ చేయబడుతుంది. Windowsలో `C:\Program Files\Tailscale\tailscale.exe` వద్ద ఉన్న
డిఫాల్ట్ సర్వీస్ ఇన్స్టాలేషన్ ఉపయోగించబడుతుంది.

### REST ఎండ్పాయింట్లు

ఇన్స్టాలేషన్, లాగిన్, డీమన్ మరియు టన్నెల్ వేర్వేరు అంశాలు కాబట్టి, ఇతర బ్యాకెండ్లతో
పోలిస్తే Tailscale మరింత విస్తృతమైన ఇంటర్ఫేస్ను కలిగి ఉంది.

| ఎండ్పాయింట్                           | పద్ధతి | ఉద్దేశ్యం                                                                            |
| ------------------------------------- | ------ | ------------------------------------------------------------------------------------ |
| `/api/tunnels/tailscale`              | `GET`  | సమగ్ర టన్నెల్ స్థితి (`phase`, `tunnelUrl`, `apiUrl` మొదలైనవి)                       |
| `/api/tunnels/tailscale/check`        | `GET`  | దిగువ-స్థాయి తనిఖీ: ఇన్స్టాల్ అయిందా? లాగిన్ అయ్యారా? డీమన్ నడుస్తోందా?              |
| `/api/tunnels/tailscale/install`      | `POST` | Tailscaleను ఇన్స్టాల్ చేయండి (SSE ద్వారా ప్రసారమయ్యే పురోగతి ఈవెంట్లు) — Linux/macOS |
| `/api/tunnels/tailscale/start-daemon` | `POST` | Linux/macOSలో `tailscaled`ను ప్రారంభించండి                                           |
| `/api/tunnels/tailscale/login`        | `POST` | లాగిన్ ప్రవాహాన్ని ప్రారంభించండి; బ్రౌజర్లో తెరవడానికి `authUrl`ను తిరిగి ఇస్తుంది   |
| `/api/tunnels/tailscale/enable`       | `POST` | API పోర్ట్ కోసం Funnelను ప్రారంభించండి                                               |
| `/api/tunnels/tailscale/disable`      | `POST` | Funnelను నిలిపివేయండి                                                                |

అన్ని Tailscale ఎండ్పాయింట్లకు నిర్వహణ ప్రామాణీకరణ అవసరం (`routeUtils.ts ::
requireTailscaleAuth` చూడండి).

ప్రారంభించే ఉదాహరణ:

```bash
curl -X POST http://localhost:20128/api/tunnels/tailscale/enable \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"sudoPassword":"<linux-pwd>","port":20128}'
```

అడ్మిన్ కన్సోల్లో Funnel ప్రారంభించబడకపోతే, ప్రతిస్పందనలో
`funnelNotEnabled: true`తో పాటు బ్రౌజర్లో తెరవడానికి ఒక `enableUrl` ఉంటుంది.

## OAuth కాల్బ్యాక్ పరిగణనలు

మీరు OmniRouteను టన్నెల్ ద్వారా అందుబాటులో ఉంచినప్పుడు, డ్యాష్బోర్డ్ మరియు OAuth ప్రవాహాలు
కాల్బ్యాక్ URLలను `localhost`కు కాకుండా **పబ్లిక్** హోస్ట్నేమ్కు అనుగుణంగా
రూపొందించాలి. లేకపోతే, OAuth ప్రొవైడర్ వినియోగదారుని దాని సర్వర్లు చేరుకోలేని URLకు
తిరిగి మళ్లిస్తుంది, దాంతో హ్యాండ్షేక్ విఫలమవుతుంది.

డ్యాష్బోర్డ్ సవరణలు మరియు సెట్టింగ్ల సేవ్ల కోసం టన్నెల్ హోస్ట్నేమ్ను
`NEXT_PUBLIC_BASE_URL`లో స్థిరపరచాల్సిన అవసరం లేదు. ప్రామాణీకరించిన డ్యాష్బోర్డ్,
సెషన్కు అనుసంధానించబడిన CSRF టోకెన్తో అదే మూలానికి చెందిన అసురక్షిత
అభ్యర్థనలను పంపుతుంది, కాబట్టి లాగిన్ అయిన తర్వాత సాధారణ UI నిర్వహణ కోసం తాత్కాలిక Cloudflare Quick Tunnel
హోస్ట్లను ఇప్పటికీ ఉపయోగించవచ్చు.

ఇలా సెట్ చేయండి:

```bash
NEXT_PUBLIC_BASE_URL=https://<your-tunnel-host>
```

మరియు OAuthను ప్రారంభించే ముందు OmniRouteను పునఃప్రారంభించండి. తాత్కాలిక Cloudflare Quick
Tunnels కోసం ప్రతి పునఃప్రారంభం తర్వాత URL మారుతుంది, కాబట్టి ప్రొడక్షన్ OAuth వినియోగానికి రిజర్వ్ చేసిన
డొమైన్తో ngrok లేదా Tailscale Funnelను ప్రాధాన్యంగా ఉపయోగించండి.

## హెల్త్ మరియు పర్యవేక్షణ

డ్యాష్బోర్డ్ టన్నెల్ స్థితిని **Settings → Tunnels** కింద చూపిస్తుంది:

- సక్రియ బ్యాకెండ్(లు) మరియు ప్రస్తుత `phase` (`stopped`, `starting`, `running`,
  `needs_auth`, `error`).
- ప్రస్తుత పబ్లిక్ URL మరియు దాని నుంచి రూపొందించిన API URL (`<publicUrl>/v1`).
- టన్నెల్ ఫార్వర్డ్ చేస్తున్న స్థానిక టార్గెట్ URL.
- ఏదైనా ఉంటే, చివరి ఎర్రర్ సందేశం.

ప్రోగ్రామేటిక్ పర్యవేక్షణ కోసం ప్రతి బ్యాకెండ్కు సంబంధించిన `GET` ఎండ్పాయింట్లను క్రమం తప్పకుండా పోల్ చేయండి. ఒకేసారి ఒకటి కంటే
ఎక్కువ బ్యాకెండ్లను అమలు చేయడానికి అనుమతి ఉంది; OmniRoute ప్రతి దానినీ
స్వతంత్రంగా ట్రాక్ చేస్తుంది.

## సమస్య పరిష్కారం

### "cloudflared బైనరీ కనుగొనబడలేదు"

మొదటిసారి ఉపయోగించినప్పుడు OmniRoute స్వయంచాలకంగా ఇన్స్టాల్ చేయడానికి ప్రయత్నిస్తుంది. ఇన్స్టాలేషన్ నిరోధించబడితే
(పరిమిత నెట్వర్క్, GitHub యాక్సెస్ లేకపోవడం), `cloudflared`ను
<https://github.com/cloudflare/cloudflared/releases> నుండి మాన్యువల్గా డౌన్లోడ్ చేసి,
`CLOUDFLARED_BIN=/path/to/cloudflared`ను సెట్ చేయండి.

### "ngrok: authtoken అవసరం"

`phase: "needs_auth"` అంటే authtoken కనుగొనబడలేదని అర్థం. `.env`లో
`NGROK_AUTHTOKEN`ను సెట్ చేయండి, డ్యాష్బోర్డ్ ద్వారా దాన్ని కాన్ఫిగర్ చేయండి, లేదా enable POST
బాడీలో `authToken`ను పంపండి.

### "tailscale: funnel ప్రారంభించబడలేదు"

enable రెస్పాన్స్లో `funnelNotEnabled: true` ఉంటే, మీ tailnet కోసం Funnel నిలిపివేయబడింది.
తిరిగి వచ్చిన `enableUrl`ను (లేదా అడ్మిన్ కన్సోల్ ఫీచర్
పేజీని) తెరిచి Funnelను ఆన్ చేయండి.

### టన్నెల్ URL మార్పులు OAuthను పనిచేయకుండా చేస్తాయి

రిజర్వ్ చేసిన డొమైన్తో ngrok లేదా Tailscale Funnelను ఉపయోగించండి (రెండూ ప్రతి నోడ్కు స్థిరంగా ఉంటాయి).
Cloudflare Quick Tunnels రూపకల్పన ప్రకారమే తాత్కాలికమైనవి, దీర్ఘకాలిక
OAuth కాల్బ్యాక్ల కోసం సిఫార్సు చేయబడవు.

### Tailscale కోసం Linux/macOSలో అనుమతి నిరాకరించబడింది

`tailscaled`కు root అవసరం. సంబంధిత POST ఎండ్పాయింట్కు `sudoPassword`ను అందించండి,
లేదా డీమన్ను మీరే అమలు చేయండి (`sudo systemctl start tailscaled`).
