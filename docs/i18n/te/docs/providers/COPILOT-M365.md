`copilot-m365-web` (alias `m365copilot`) ప్రామాణీకరించబడిన Microsoft 365 Copilot BizChat బ్రౌజర్ సెషన్ ద్వారా
`m365.cloud.microsoft/chat` వద్ద OpenAI-ఫార్మాట్ చాట్ అభ్యర్థనలను పంపుతుంది.
ఇది అధికారికం కాని ఇంటిగ్రేషన్.

> **Web Cookie ప్రొవైడర్లకు కొత్తా?**
>
> ఈ ప్రొవైడర్కు నిర్దిష్టమైన మార్గదర్శిని అనుసరించే ముందు, సాధారణ సెటప్ ప్రక్రియ, ప్రామాణీకరణ మార్గదర్శకాలు, పరిమితులు మరియు సమస్య పరిష్కారం కోసం **`docs/getting-started/WEB-COOKIE-GUIDE.md`** చదవండి.
>
> **ముఖ్యమైనది:** ఈ ప్రొవైడర్కు అవసరమైన క్రెడెన్షియల్ **cookie కాదు**. `m365.cloud.microsoft` నుండి
> cookiesను కాపీ చేయవద్దు. క్రెడెన్షియల్ అనేది WebSocket URL క్వెరీ
> పారామీటర్ మరియు పాత్ సెగ్మెంట్; ఈ రెండూ DevTools Network ట్యాబ్ నుండి చదవబడతాయి.

## ముందస్తు అవసరాలు

- `m365.cloud.microsoft/chat` వద్ద BizChat యాక్సెస్ ఉన్న Microsoft 365 ఖాతా
- DevTools WebSocket తనిఖీ కోసం Chromium-ఆధారిత బ్రౌజర్ (Chrome, Edge)
- M365 Copilot లైసెన్స్ (అనేక Microsoft 365 Business/Enterprise ప్లాన్లలో చేర్చబడింది)

## క్రెడెన్షియల్ను సంగ్రహించడం (WebSocket పద్ధతి)

1. `https://m365.cloud.microsoft/chat` వద్ద సైన్ ఇన్ చేసి సంభాషణను ప్రారంభించండి.
2. **DevTools → Network** తెరవండి.
3. **WS** (WebSocket) ద్వారా ఫిల్టర్ చేయండి.
4. Chathub WebSocket కనెక్షన్పై క్లిక్ చేయండి. కింది దానితో ప్రారంభమయ్యే URL కోసం చూడండి:
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. దాని **Request URL** నుండి, వీటిని కాపీ చేయండి:
   - `access_token` క్వెరీ పారామీటర్ విలువ (స్వల్పకాలిక JWT).
   - `/Chathub/` తర్వాత ఉన్న Chathub పాత్ సెగ్మెంట్ (ఉదా. `<oid>@<tenant>`).

పూర్తి URL ఈ రూపంలో ఉంటుంది:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRouteలో, **Providers → Add Provider**కు వెళ్లి, **Microsoft 365 Copilot
   (BizChat)**ను ఎంచుకుని, క్రెడెన్షియల్ను కింది ఫార్మాట్లో అతికించండి:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. **Test Connection** మరియు **Save**పై క్లిక్ చేయండి.

## క్రెడెన్షియల్ను సంగ్రహించడం (HAR దిగుమతి)

WebSocket URL నుండి విలువలను మాన్యువల్గా కాపీ చేయడానికి బదులుగా, మీరు DevTools HAR
ఫైల్ను ఎగుమతి చేయవచ్చు:

1. **DevTools → Network** తెరవండి.
2. BizChat సంభాషణను ప్రారంభించండి లేదా కొనసాగించండి (ఇది WebSocket కనెక్షన్ను ట్రిగ్గర్ చేస్తుంది).
3. Network ప్యానెల్లో రైట్-క్లిక్ చేసి, **Save all as HAR with content** ఎంచుకోండి.
4. OmniRouteలో, ప్రొవైడర్ కనెక్షన్ డైలాగ్లోని **Import .har file** బటన్ను ఉపయోగించండి.

OmniRoute, Chathub WebSocket URL కోసం HARను స్కాన్ చేసి,
`access_token` మరియు `chathubPath`ను వెలికితీసి, క్రెడెన్షియల్ ఫీల్డ్లను స్వయంచాలకంగా నింపుతుంది.
HAR దిగుమతి JWT గడువు ముగింపు సమయాన్ని డీకోడ్ చేసి, మిగిలిన టోకెన్ జీవితకాలాన్ని చూపుతుంది.

> **నిజమైన HAR ఎగుమతి, యాక్సెస్ టోకెన్ లేదా రిఫ్రెష్ టోకెన్ను ఎప్పుడూ commit చేయవద్దు.** పరీక్ష మరియు
> డాక్యుమెంటేషన్ విలువలు ఎల్లప్పుడూ ప్లేస్హోల్డర్లుగా ఉండాలి.

## టోకెన్ జీవితకాలం మరియు రిఫ్రెష్

`access_token` స్వల్పకాలికమైనది (సాధారణంగా **~75 నిమిషాలు**). గడువు ముగిసిన తర్వాత, ప్రొవైడర్
కనెక్షన్ లోపాన్ని నివేదిస్తుంది మరియు మీరు క్రెడెన్షియల్ను మళ్లీ సంగ్రహించాలి.

### `refreshToken`తో స్వయంచాలక రిఫ్రెష్

మాన్యువల్గా మళ్లీ సంగ్రహించాల్సిన అవసరాన్ని నివారించడానికి, కనెక్షన్లోని
**Advanced Settings → providerSpecificData**లో Microsoft రిఫ్రెష్ టోకెన్ను నిల్వ చేయవచ్చు:

| ఫీల్డ్         | వివరణ                                                                     |
| -------------- | ------------------------------------------------------------------------- |
| `refreshToken` | `substrate.office.com/sydney` స్కోప్ కోసం Microsoft OAuth రిఫ్రెష్ టోకెన్ |
| `tier`         | `individual` (డిఫాల్ట్), `edu`, లేదా `enterprise`                         |

`substrate.office.com/sydney`కు స్కోప్ చేయబడిన Microsoft device-code లేదా authorization-code ఫ్లో
నుండి రిఫ్రెష్ టోకెన్ను పొందండి. `refreshToken` సెట్ చేసినప్పుడు, ప్రతి అభ్యర్థనకు ముందు OmniRoute
`access_token`ను ముందస్తుగా రిఫ్రెష్ చేస్తుంది, కాబట్టి ప్రతి ~75-నిమిషాల గడువు ముగిసిన తర్వాత
మీరు మళ్లీ సంగ్రహించాల్సిన అవసరం లేదు.

`refreshToken` సెట్ చేయకపోతే, ప్రతి గడువు ముగిసిన తర్వాత మీరు WebSocket క్రెడెన్షియల్ను మాన్యువల్గా
మళ్లీ సంగ్రహించాలి.

### టైర్ ఎంపిక

| టైర్         | అలియాస్      | సర్ఫేస్                  |
| ------------ | ------------ | ------------------------ |
| `individual` | _(డిఫాల్ట్)_ | వినియోగదారు M365 Copilot |
| `edu`        | `included`   | విద్యా M365 Copilot      |
| `enterprise` | `work`       | పని కోసం M365 Copilot    |

**Advanced Settings → providerSpecificData → tier**లో టైర్ను సెట్ చేయండి. టైర్
BizChat రూటింగ్ మరియు మోడల్ యాక్సెస్ను ప్రభావితం చేస్తుంది.

## భద్రతా నమూనా

- **అనధికారిక ఇంటిగ్రేషన్.** ఈ ప్రొవైడర్ BizChat WebSocket
  ప్రోటోకాల్ను రివర్స్-ఇంజినీర్ చేస్తుంది. Microsoft ఎండ్పాయింట్ను మార్చినప్పుడు ఇది ముందస్తు నోటీసు లేకుండా పనిచేయడం ఆగిపోవచ్చు.
- `subscriptionRisk: true` ఫ్లాగ్, ఈ ఇంటిగ్రేషన్ డాక్యుమెంట్ చేయని
  ఎండ్పాయింట్పై ఆధారపడుతుందని సూచిస్తుంది. ఖాతాపై పరిమితులు విధించే అవకాశం ఉంది, కానీ అది నిర్ధారించబడలేదు.
- యాక్సెస్ టోకెన్ స్వల్పకాలిక JWT. దాన్ని పాస్వర్డ్లా పరిగణించండి: దాన్ని కమిట్ చేయవద్దు,
  లాగ్ చేయవద్దు లేదా ఇతరులతో పంచుకోవద్దు.
- రిఫ్రెష్ టోకెన్ BizChat ఉపరితలానికి దీర్ఘకాలిక యాక్సెస్ను అందిస్తుంది. దాన్ని
  API కీకి ఇచ్చేంత జాగ్రత్తతో నిల్వ చేయండి.

## సమస్య పరిష్కారం

### ప్రామాణీకరణ వెంటనే విఫలమవుతుంది

- మీరు XHR/Fetch అభ్యర్థన నుంచి కాకుండా, **WebSocket URL** నుంచి కాపీ చేశారని నిర్ధారించుకోండి.
  క్రెడెన్షియల్ Chathub WebSocket కనెక్షన్లోని `access_token` క్వెరీ పారామీటర్లో ఉంటుంది
  — `Authorization: Bearer` హెడర్లో కాదు.
- URL పాత్లోని పూర్తి `<oid>@<tenant>` సెగ్మెంట్ను `chathubPath` కలిగి ఉందని
  నిర్ధారించుకోండి.

### టోకెన్ ~75 నిమిషాల తర్వాత గడువు ముగుస్తుంది

ఇది ఊహించిన ప్రవర్తనే. `refreshToken` లేకుండా యాక్సెస్ టోకెన్ స్వల్పకాలికంగా ఉంటుంది. కింది వాటిలో ఏదో ఒకటి చేయండి:

- DevTools నుంచి క్రెడెన్షియల్ను మళ్లీ క్యాప్చర్ చేయండి, లేదా
- ఆటోమేటిక్ రిఫ్రెష్ కోసం Advanced Settingsలో `refreshToken`ను కాన్ఫిగర్ చేయండి.

### Test Connection విజయవంతమవుతుంది, కానీ చాట్ 401ను తిరిగి ఇస్తుంది

ధ్రువీకరణకు, మొదటి అభ్యర్థనకు మధ్య టోకెన్ గడువు ముగిసి ఉండవచ్చు. తాజా
క్రెడెన్షియల్ను మళ్లీ క్యాప్చర్ చేయండి.

### ప్రొవైడర్ జాబితాలో Copilot కనిపించదు

**Dashboard → Providers**లో `copilot-m365-web` ప్రారంభించబడిందని నిర్ధారించుకోండి. కొన్ని
టియర్లలో ప్రొవైడర్ డిఫాల్ట్గా దాచబడి ఉండవచ్చు.
