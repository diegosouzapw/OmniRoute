ఈ పత్రం [Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854) కోసం తీసుకున్న అమలు నిర్ణయాన్ని నమోదు చేస్తుంది. పబ్లిక్ ఉత్పత్తులు నాలుగు ప్రొవైడర్ కుటుంబాలుగా సూచించబడతాయి. ప్రాంతం అనేది కనెక్షన్ డేటా, ప్రత్యేక ఉత్పత్తి కాదు.

## నిర్ణయం

| ప్రొవైడర్ కుటుంబం                                  | OmniRoute ID            | గ్లోబల్ ప్రాంతం | చైనా ప్రాంతం |
| -------------------------------------------------- | ----------------------- | --------------- | ------------ |
| Alibaba Cloud Model Studio (వాడిన మేరకు చెల్లింపు) | `alibaba`               | Singapore       | Beijing      |
| Alibaba Cloud Token Plan                           | `bailian-coding-plan`   | Singapore       | Beijing      |
| Qwen Cloud (వాడిన మేరకు చెల్లింపు)                 | `qwen-cloud`            | Global          | Beijing      |
| Qwen Cloud Token Plan                              | `qwen-cloud-token-plan` | Singapore       | Beijing      |

ఇప్పటికే ఉన్న `alibaba-cn` ID, సేవ్ చేసిన కనెక్షన్లు, మోడల్ రూట్లు, కాంబోలు మరియు చారిత్రక వినియోగం కోసం రన్టైమ్ అనుకూలత అలియాస్గా కొనసాగుతుంది. దాని డ్యాష్బోర్డ్ కార్డ్ `alibaba`లో విలీనం చేయబడుతుంది; డేటాబేస్ను తిరిగి రాయాల్సిన అవసరం లేదు.

Qwen Cloud వాడిన మేరకు చెల్లింపు ఉత్పత్తి మరియు Alibaba Cloud Model Studio ప్రస్తుతం DashScope-అనుకూల రన్టైమ్ హోస్ట్లను పంచుకుంటాయి, కానీ వినియోగదారులు వేర్వేరు ఉత్పత్తి ఇంటర్ఫేస్ల ద్వారా కీలు పొందడం మరియు ఖాతాలను నిర్వహించడం వల్ల అవి వేర్వేరు ప్రొవైడర్ గుర్తింపులుగానే ఉంటాయి. Alibaba మరియు Qwen Cloud Token Plan ఉత్పత్తులు వేర్వేరు ఎండ్పాయింట్ కుటుంబాలను ఉపయోగిస్తాయి, కాబట్టి నాలుగు ఉత్పత్తులూ వేర్వేరు ప్రొవైడర్ IDలుగానే ఉంటాయి.

## కనెక్షన్ ఒప్పందం

కొత్త కనెక్షన్లు స్థిరమైన ప్రాంత కీని `providerSpecificData`లో నిల్వ చేస్తాయి:

```json
{
  "region": "global-sg"
}
```

అనుమతించబడిన విలువలు `global-sg` మరియు `china-beijing`. ఎండ్పాయింట్ ప్రొవైడర్ ID మరియు ప్రాంతం ఆధారంగా కేంద్రీయంగా ఉత్పన్నమవుతుంది. ప్రీసెట్ కాని `providerSpecificData.baseUrl` స్పష్టమైన ఆపరేటర్ ఓవర్రైడ్గా కొనసాగి ప్రాధాన్యత పొందుతుంది, అయితే పాత సేవ్ చేసిన ప్రీసెట్ URLలు తిరిగి ప్రాంతీయ మ్యాట్రిక్స్కు సాధారణీకరించబడతాయి.

ఇది కనెక్షన్ స్కీమాను విస్తరించగలిగేలా ఉంచుతుంది: మరొక ప్రొవైడర్ కార్డ్ను సృష్టించకుండా లేదా సేవ్ చేసిన ప్రొవైడర్ IDలను మార్చకుండా రిజాల్వర్కు మరొక ప్రాంతాన్ని జోడించవచ్చు.

## అనుకూలత మరియు అమలు

1. ప్రాంతీయ endpoint resolverను జోడించి, ప్రస్తుత global defaultsను అలాగే ఉంచండి.
2. `alibaba`, దాని `alibaba-cn` అనుకూలత ID, మరియు `qwen-cloud` కోసం ప్రత్యక్ష ప్రాంతీయ DashScope `/models` ఆవిష్కరణను ఉపయోగించండి. సాధారణ endpoint చిత్రం, వీడియో, ఆడియో, embedding మరియు ఇతర chat-యేతర మోడళ్లను కూడా అందిస్తుంది కాబట్టి, వాటి ప్రతిస్పందనలు ముందుగా ఒక text-generation filter ద్వారా వెళ్తాయి. ఆ తర్వాత `qwen-cloud`, దాని provider registryలో ప్రకటించిన నిర్వహిత allowlistను వర్తింపజేస్తుంది. ప్రస్తుతం అవి ఒకే runtime hostsను పంచుకుంటున్నప్పటికీ, Alibaba Model Studio మరియు Qwen Cloud వేర్వేరు ఎంపికచేసిన catalogsను నిర్వహిస్తాయి.
3. ప్రస్తుత Token Plan text-model allowlistతో `qwen-cloud-token-plan`ను నమోదు చేయండి.
4. connectionలను జోడించే/సవరించే dialogsకు typed region selectorను జోడించండి.
5. నకిలీ `alibaba-cn` cardను దాచిపెట్టి, దాని ప్రస్తుత connectionలను `alibaba` provider పేజీలో చేర్చండి.
6. అధునాతన మరియు workspace-నిర్దిష్ట deployments కోసం custom endpoint overridesను అందుబాటులో ఉంచండి.

Token Plan media models ప్రత్యేక endpointsను ఉపయోగిస్తాయి కాబట్టి అవి chat catalogకు వెలుపలే ఉంటాయి.
