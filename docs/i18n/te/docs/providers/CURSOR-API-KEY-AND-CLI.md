IDE సెషన్ లేకుండా Cursorను OmniRoute వెనుక ఉంచడానికి రెండు మార్గాలు:

1. **`cursor-api` ప్రొవైడర్** (కార్డ్ "Cursor API", అలియాస్ `cua`): Cursor వినియోగదారు API కీని (`crsr_…`, `https://cursor.com/dashboard/api` వద్ద రూపొందించబడుతుంది) కలిగి ఉండే API-కీ ప్రొవైడర్. ఆ తర్వాత ఏ OmniRoute క్లయింట్ అయినా సాధారణ కోటా, ఫాల్బ్యాక్ మరియు లాగింగ్ లేయర్లతో `/v1/chat/completions` ద్వారా `cursor-api/<model>` లేదా `cua/<model>`గా Cursor మోడల్లను యాక్సెస్ చేస్తుంది. IDE ప్రొవైడర్ (`cursor`, OAuth/IDE సెషన్) మారదు.
2. **Cursor CLI పాస్త్రూ**: Cursor CLI (`agent`)ని OmniRoute వైపు మళ్లించండి, తద్వారా CLI చేసే ప్రతి RPC OmniRoute API కీతో ప్రామాణీకరించబడి, `cursor-api` కనెక్షన్ క్రెడెన్షియల్తో Cursorకు ఫార్వర్డ్ చేయబడుతుంది మరియు Logs పేజీలో రికార్డ్ అవుతుంది.

## కీ ఎందుకు మార్పిడి చేయబడుతుంది

`api2.cursor.sh` ముడి `crsr_…` కీని Bearer టోకెన్గా తిరస్కరిస్తుంది (401). Cursor CLI మొదట కీని `/auth/exchange_user_api_key`కు POST చేసి, ఒక గంట తర్వాత గడువు ముగిసే సెషన్ JWTని పొందుతుంది; తిరిగి వచ్చిన `refreshToken` కూడా అదే `exp`ను కలిగి ఉంటుంది, కాబట్టి రిఫ్రెష్ చేయడం అంటే కీని మళ్లీ మార్పిడి చేయడమే.
`open-sse/services/cursorApiKeyAuth.ts` ఆ మార్పిడిని నిర్వహిస్తుంది, ప్రతి కీకి ఒక సెషన్ టోకెన్ను క్యాష్ చేస్తుంది, గడువు ముగియడానికి ఐదు నిమిషాల ముందు మళ్లీ మార్పిడి చేస్తుంది మరియు Cursor 401తో స్పందించినప్పుడు క్యాష్ చేసిన టోకెన్ను తొలగిస్తుంది. `cursor-api` కనెక్షన్ల కోసం అప్స్ట్రీమ్ స్ట్రీమ్ను తెరవడానికి సరిగ్గా ముందు `CursorExecutor` దాన్ని కాల్ చేస్తుంది.

## `cursor-api` ప్రొవైడర్

రిజిస్ట్రీ: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, `cursor`లో ఉన్నట్లే అదే `format`, `baseUrl` మరియు `models`). కేటలాగ్ కార్డ్:
`src/shared/constants/providers/apikey/specialty-media.ts`. ఎగ్జిక్యూటర్ మ్యాప్:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

డ్యాష్బోర్డ్: Providers → Cursor API → Add API key.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

ఆ తర్వాత:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

గమనికలు:

- `cursor-api` కోసం మోడల్ జాబితా స్థిరమైన Cursor రిజిస్ట్రీ నుండి వస్తుంది (IDE ప్రొవైడర్ ఫాల్బ్యాక్గా ఉపయోగించే అదే జాబితా); OmniRoute హోస్ట్లో `cursor-agent` ఇన్స్టాల్ చేయాల్సిన అవసరం లేదు.
- `POST /api/providers/{id}/refresh-cursor` అనేది `cursor` IDE ప్రొవైడర్కు మాత్రమే; `cursor-api` కనెక్షన్లకు పునరుద్ధరించాల్సిన IDE సెషన్ ఉండదు.

## Cursor CLI పాస్త్రూ

రూట్: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. `/api/cursor-cli/` ప్రిఫిక్స్ `src/shared/constants/publicApiRoutes.ts`లో నమోదు చేయబడింది, ఎందుకంటే హ్యాండ్లర్ తన స్వంత ప్రామాణీకరణను అమలు చేస్తుంది:

| మార్గం                                                                                                                       | CLI నుండి ఆశించే ప్రామాణీకరణ | OmniRoute చేసే పని                                                                                                                                                                                |
| ---------------------------------------------------------------------------------------------------------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                           | `Bearer <OmniRoute API key>` | కీని ధృవీకరిస్తుంది, 1h HS256 JWTని (`JWT_SECRET`తో సంతకం చేయబడినది) రూపొందించి తిరిగి అందిస్తుంది                                                                                                |
| ప్రతి ఇతర మార్గం (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`          | ఇష్యువర్/ఆడియన్స్/గడువును ధృవీకరిస్తుంది, క్రియాశీల `cursor-api` కనెక్షన్ను ఎంచుకుంటుంది, Authorization హెడర్ను మార్పిడి చేసిన Cursor టోకెన్తో భర్తీ చేసి ప్రతిస్పందనను తిరిగి స్ట్రీమ్ చేస్తుంది |

CLI తాను అందుకున్న ఏ టోకెన్ నుండైనా `exp`ను డీకోడ్ చేస్తుంది, కాబట్టి దానికి ఒక అస్పష్టమైన టోకెన్ను ఇస్తే దాదాపు ప్రతి అభ్యర్థనకు ముందు అది మళ్లీ మార్పిడి చేస్తుంది; రూపొందించిన JWT దాన్ని నివారిస్తుంది. OmniRoute నుండి వచ్చే 401 కారణంగా CLI మళ్లీ మార్పిడి చేస్తుంది.

### సెటప్

1. ఒక OmniRoute API కీని (Dashboard → API keys) మరియు ఒక `cursor-api` కనెక్షన్ను సృష్టించండి.
2. ఏజెంట్ స్ట్రీమ్ కోసం HTTP/1.1ను ఉపయోగించమని CLIకి సూచించండి. `~/.cursor/cli-config.json`లో:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   ఇది లేకపోతే, CLI ఏజెంట్ టర్న్ను విడిగా కాన్ఫిగర్ చేసిన ఏజెంట్ హోస్ట్కు HTTP/2 ద్వారా తెరుస్తుంది మరియు కంట్రోల్-ప్లేన్ RPCలు మాత్రమే ఎండ్పాయింట్ ద్వారా వెళ్తాయి.

3. OmniRouteకు వ్యతిరేకంగా CLIని అమలు చేయండి:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

ప్రతి హాప్ Logsలో ప్రొవైడర్ `cursor-api`, అభ్యర్థన రకం `cursor-cli`, మార్గం `/api/cursor-cli/<rpc>`గా నమోదు అవుతుంది మరియు దానికి OmniRoute API కీతో పాటు దాన్ని అందించిన కనెక్షన్ కూడా ఆపాదించబడుతుంది.

### వైఫల్య పరిస్థితులు

| పరిస్థితి                                                       | CLIకి ప్రతిస్పందన                                       |
| --------------------------------------------------------------- | ------------------------------------------------------- |
| తెలియని OmniRoute కీ మరియు `REQUIRE_API_KEY=true`               | ఎక్స్చేంజ్ సమయంలో 401 `unauthenticated`                 |
| `REQUIRE_API_KEY=false`                                         | అనామక సెషన్ (`/v1/*` ప్రవర్తనను ప్రతిబింబిస్తుంది)      |
| గడువు ముగిసిన / ఇతర వ్యవస్థకు చెందిన / తారుమారు చేసిన సెషన్ JWT | 401, CLI మళ్లీ ఎక్స్చేంజ్ చేస్తుంది                     |
| ఎక్స్చేంజ్ తర్వాత OmniRoute API కీ రద్దు చేయబడింది              | తదుపరి RPCలో 401                                        |
| సక్రియ `cursor-api` కనెక్షన్ లేదు                               | 503 `unavailable`                                       |
| కనెక్షన్ కీని Cursor తిరస్కరిస్తుంది                            | 401 `unauthenticated`, కాష్ చేసిన సెషన్ తొలగించబడుతుంది |
| అప్స్ట్రీమ్ను చేరుకోలేకపోవడం                                    | 502 `unavailable` (శుద్ధి చేసిన సందేశం)                 |
| `JWT_SECRET` సెట్ చేయబడలేదు                                     | ఎక్స్చేంజ్ సమయంలో 503                                   |
