Web Cookie ప్రొవైడర్లు API keyకు బదులుగా మీ ప్రస్తుత బ్రౌజర్ సెషన్ ద్వారా AI సేవను ఉపయోగించడానికి OmniRouteను అనుమతిస్తాయి. మీరు ఇప్పటికే ఒక సేవకు దాని వెబ్సైట్ ద్వారా యాక్సెస్ కలిగి ఉండి, అదే ప్రామాణీకరించిన సెషన్ను OmniRoute ఉపయోగించాలని కోరుకున్నప్పుడు ఇవి ఉపయోగకరంగా ఉంటాయి.

API-key ప్రొవైడర్లకు భిన్నంగా, Web Cookie ప్రొవైడర్లు మీ బ్రౌజర్ వెబ్సైట్కు పంపే క్రెడెన్షియల్స్ను ఉపయోగించి ప్రామాణీకరిస్తాయి.

# ప్రారంభించడానికి ముందు

> **ముఖ్యమైనది:** క్రెడెన్షియల్స్ను ఎల్లప్పుడూ **ప్రత్యక్ష నెట్వర్క్ అభ్యర్థన** నుండి కాపీ చేయండి, మీ బ్రౌజర్ cookie storage నుండి **కాదు**.

Cookiesను తప్పు ప్రదేశం నుండి కాపీ చేయడం వల్ల అనేక ప్రామాణీకరణ సమస్యలు ఏర్పడతాయి.

## Cookie Storage నుండి కాపీ చేయవద్దు

చాలా బ్రౌజర్లు నిల్వ చేసిన cookiesను దీని ద్వారా చూపిస్తాయి:

```
DevTools
→ Application (లేదా Storage)
→ Cookies
```

ఈ cookies సరైనవిగా కనిపించినప్పటికీ, అవి:

- కాలం చెల్లినవి కావచ్చు
- అసంపూర్ణంగా ఉండవచ్చు
- ప్రామాణీకరించిన అభ్యర్థనలపై మాత్రమే పంపే cookiesను కలిగి ఉండకపోవచ్చు

ఈ విలువలు చెల్లుబాటు అయ్యేవిగా కనిపించినప్పటికీ, వాటిని ఉపయోగించడం వల్ల ప్రామాణీకరణ వైఫల్యాలు సంభవించవచ్చు.

## ప్రత్యక్ష అభ్యర్థన నుండి కాపీ చేయండి

దానికి బదులుగా, విజయవంతమైన అభ్యర్థనలోని cookiesను ఉపయోగించండి:

```
DevTools
→ Network
→ పేజీని రిఫ్రెష్ చేయండి
→ chat లేదా conversation అభ్యర్థనను తెరవండి
→ Request Headers
→ Cookie
```

`Cookie` request headerలో మీ బ్రౌజర్ విజయవంతంగా ఉపయోగించిన ఖచ్చితమైన ప్రామాణీకరణ సమాచారం ఉంటుంది.

చాలా Web Cookie ప్రొవైడర్ల కోసం, OmniRouteలో పేస్ట్ చేయాల్సిన విలువ ఇదే.

# సాధారణ సెటప్

చాలా Web Cookie ప్రొవైడర్లకు సెటప్ ప్రక్రియ ఒకే విధంగా ఉంటుంది.

1. ప్రొవైడర్ వెబ్సైట్కు సైన్ ఇన్ చేయండి.
2. బ్రౌజర్ Developer Toolsను తెరవండి.
3. **Network** ట్యాబ్ను తెరవండి.
4. పేజీని రిఫ్రెష్ చేయండి.
5. ప్రామాణీకరించిన chat లేదా conversation అభ్యర్థనను తెరవండి.
6. అవసరమైన ప్రామాణీకరణ క్రెడెన్షియల్స్ను కాపీ చేయండి.
7. OmniRouteను తెరవండి.
8. **Providers → Add Provider**కు వెళ్లండి.
9. మీ Web Cookie ప్రొవైడర్ను ఎంచుకోండి.
10. క్రెడెన్షియల్స్ను పేస్ట్ చేయండి.
11. **Test Connection**ను క్లిక్ చేయండి.
12. ప్రొవైడర్ను సేవ్ చేయండి.

అవసరమైన ఖచ్చితమైన క్రెడెన్షియల్స్ ప్రొవైడర్పై ఆధారపడి ఉంటాయి.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) అనేది సైన్ అప్ అవసరం లేని ఉచిత వినియోగదారు చాట్ ప్లాట్ఫారమ్ — మొదటిసారి సందర్శించినప్పుడు సెషన్ అనామకంగా సృష్టించబడుతుంది మరియు మూడు కుకీల ద్వారా కొనసాగుతుంది: `uid`, `si_usr_id`, మరియు `si_ses_id`. OmniRoute అదే `/api/dispatch` ఎండ్పాయింట్ను ఒకే మోడల్ id (`notrack-c`, అలియాస్ `ntw`) ద్వారా ప్రాక్సీ చేస్తుంది.

### కనెక్ట్ చేయడానికి దశలు

1. మీ బ్రౌజర్లో [notrack.ai](https://notrack.ai) తెరిచి, అనామక సెషన్ కుకీ సెట్ అయ్యేలా చేయండి.
2. **DevTools → Network** తెరిచి, పేజీని రిఫ్రెష్ చేసి, ఏదైనా `/api` అభ్యర్థనపై క్లిక్ చేయండి.
3. **Request Headers**లో, పూర్తి `Cookie` హెడర్ విలువను కాపీ చేయండి.
4. OmniRouteలో, **Providers → Add Provider → NoTrack Web (Free)**కు వెళ్లండి.
5. కుకీ స్ట్రింగ్ను `apiKey` ఫీల్డ్లో పేస్ట్ చేసి, **Save** చేయండి.

OmniRoute పేస్ట్ చేసిన స్ట్రింగ్ నుండి `uid`, `si_usr_id`, మరియు `si_ses_id`ను సంగ్రహించి, ఆ జతలతో మాత్రమే శుభ్రమైన `Cookie` హెడర్ను పునర్నిర్మిస్తుంది — అలాగే `nt_session` (లాగిన్ చేసిన ఖాతాల కోసం సెట్ అయ్యే `ntk_…` టోకెన్) ఉన్నప్పుడు దానిని కూడా జోడిస్తుంది. ఈ మూడింటిలో ఏదైనా లేకపోతే, ప్రత్యామ్నాయ రూపాలతో ఆపరేటర్లు ప్రయోగాలు చేయగలిగేలా పేస్ట్ చేసిన ముడి స్ట్రింగ్ ఎలాంటి మార్పు లేకుండా ఫార్వర్డ్ చేయబడుతుంది.

### మోడల్ idలు

| మోడల్ id    | ప్రదర్శన పేరు | గమనికలు                                                 |
| ----------- | ------------- | ------------------------------------------------------- |
| `notrack-c` | NoTrack C     | డిఫాల్ట్ — అప్స్ట్రీమ్ డిస్పాచ్ మోడల్ `C`.              |
| `C`         | NoTrack C     | `notrack-c`కు అలియాస్ (ముడి అప్స్ట్రీమ్ డిస్పాచ్ కోడ్). |
| `notrack`   | NoTrack C     | `notrack-c`కు అలియాస్.                                  |
| `ntw`       | NoTrack C     | `notrack-c`కు సంక్షిప్త అలియాస్.                        |

నాలుగు మోడల్ idలు ఒకే అప్స్ట్రీమ్ డిస్పాచ్ మోడల్కు (`C`) మ్యాప్ అవుతాయి.

### అభ్యర్థన ఎంపికలు

ఎగ్జిక్యూటర్ అభ్యర్థన బాడీలో ఈ ఐచ్ఛిక ఫీల్డ్లను అంగీకరిస్తుంది:

| బాడీ ఫీల్డ్           | డిఫాల్ట్ | ప్రయోజనం                                                                              |
| --------------------- | -------- | ------------------------------------------------------------------------------------- |
| `notrack_mode`        | `usual`  | డిస్పాచ్ మోడ్ (స్వేచ్ఛా-రూప స్ట్రింగ్; అప్స్ట్రీమ్ `usual`, …ను అంగీకరిస్తుంది)       |
| `notrack_max_turns`   | `6`      | సమాధానం ఇచ్చే ముందు అప్స్ట్రీమ్ తీసుకోగల అంతర్గత టర్న్ల సంఖ్య.                        |
| `notrack_chat_id`     | `null`   | ఇప్పటికే ఉన్న అప్స్ట్రీమ్ చాట్ను కొనసాగించండి (కొత్త చాట్ కోసం దీనిని వదిలివేయండి).   |
| `notrack_attachments` | `[]`     | అప్స్ట్రీమ్ అటాచ్మెంట్ డిస్క్రిప్టర్ల పాస్-త్రూ అర్రే.                                |
| `notrack_regenerate`  | `false`  | మునుపటి టర్న్కు సమాధానాన్ని మళ్లీ రూపొందించమని అభ్యర్థించడానికి `true`గా సెట్ చేయండి. |

### సామర్థ్యాలు

- **స్ట్రీమింగ్ మరియు నాన్-స్ట్రీమింగ్** చాట్ కంప్లీషన్లు.
- **టూల్ కాలింగ్** — అభ్యర్థనలో `tools: [...]`ను సెట్ చేయండి; ఎగ్జిక్యూటర్ వాటిని టూల్-కాల్ ఎన్వలప్ కాంట్రాక్ట్గా సీరియలైజ్ చేసి, మోడల్ ప్రతిస్పందనలను తిరిగి OpenAI `tool_calls`గా పార్స్ చేస్తుంది.
- **`response_format`** — `json_object` మరియు `json_schema`కు మద్దతు ఉంది. ఎగ్జిక్యూటర్ మోడల్ సమాధానం నుండి మొదటి JSON ఆబ్జెక్ట్ను సంగ్రహించి, తిరిగి ఇచ్చే ముందు దాన్ని స్ట్రింగ్గా మారుస్తుంది.
- **రీజనింగ్ సూచన** — అప్స్ట్రీమ్ `thinking` ఈవెంట్ను పంపినప్పుడు, ఎగ్జిక్యూటర్ `reasoning` డెల్టాను విడుదల చేస్తుంది.

### పరిమితులు

- అప్స్ట్రీమ్ అనామక వినియోగ కోటాలను అమలు చేస్తుంది — అవి మించిపోయినప్పుడు, ఎగ్జిక్యూటర్ స్నేహపూర్వక సందేశంతో 429ను చూపుతుంది.
- అన్ని మోడల్ idలు ఒకే అప్స్ట్రీమ్ డిస్పాచ్ మోడల్కు పరిష్కరించబడతాయి; ఒక్కో మోడల్కు ప్రత్యేక స్విచ్ లేదు.
- ఎగ్జిక్యూటర్ అప్స్ట్రీమ్ `/api/chats` ఎండ్పాయింట్ను కాల్ చేయదు, కాబట్టి చాట్ చరిత్ర / సెషన్లు స్వయంచాలకంగా నిర్వహించబడవు. ఇప్పటికే ఉన్న అప్స్ట్రీమ్ చాట్ను కొనసాగించడానికి `notrack_chat_id`ను ఉపయోగించండి.

# వెబ్ కుకీ ప్రొవైడర్లు చేయగలిగేవి మరియు చేయలేనివి

వెబ్ కుకీ ప్రొవైడర్లు వెబ్సైట్ చాట్ ఇంటర్ఫేస్ను తిరిగి ఉపయోగిస్తాయి. అవి అధికారిక APIలతో సమానమైన సామర్థ్యాలను **అందించవు**.

## మద్దతు ఉన్నవి

- మీ ప్రస్తుత బ్రౌజర్ సెషన్ను ఉపయోగించి ప్రమాణీకరించడం
- మీ ఖాతా ద్వారా అందుబాటులో ఉన్న మోడల్లను యాక్సెస్ చేయడం
- చాట్ ప్రతిస్పందనలను స్ట్రీమ్ చేయడం
- API కీ అవసరం లేదు

## మద్దతు లేనివి

- ఫంక్షన్ కాలింగ్
- టూల్ కాలింగ్
- ఆటోమేటిక్ ఫైల్ ఎడిటింగ్
- ఏజెంటిక్ IDE వర్క్ఫ్లోలు
- APIలో మాత్రమే అందుబాటులో ఉండే ఫీచర్లు

ఇది ఊహించిన ప్రవర్తనే మరియు ఇది **బగ్ కాదు**.

మీకు టూల్ అమలు, ఆటోమేటిక్ ఫైల్ ఎడిటింగ్ లేదా ఇతర ఏజెంట్ వర్క్ఫ్లోలు అవసరమైతే, Web Cookie ప్రొవైడర్కు బదులుగా **API-key ప్రొవైడర్ను** ఉపయోగించండి.

# ధ్రువీకరణ పరిమితి

విజయవంతమైన **Test Connection** లేదా కుకీ ధ్రువీకరణ, అందించిన ప్రమాణపత్రాలు ఊహించిన ఫార్మాట్లో ఉన్నట్లు కనిపిస్తున్నాయని మాత్రమే నిర్ధారిస్తుంది.

Issue #7857 పరిష్కరించబడే వరకు, విజయవంతమైన ధ్రువీకరణ ప్రొవైడర్ విజయవంతంగా ప్రమాణీకరిస్తుందని **హామీ ఇవ్వదు**.

ప్రమాణీకరణ ఇప్పటికీ విఫలమైతే, మీరు ప్రమాణపత్రాలను బ్రౌజర్ కుకీ స్టోరేజ్ నుండి కాకుండా, ప్రత్యక్ష నెట్వర్క్ రిక్వెస్ట్ నుండి కాపీ చేశారని నిర్ధారించుకోండి.

# సమస్య పరిష్కారం

## ప్రమాణీకరణ విఫలమవుతుంది

ప్రమాణపత్రాలు ఇక్కడి నుండి కాపీ చేయబడ్డాయని నిర్ధారించుకోండి:

```
Network
→ Request Headers
→ Cookie
```

మరియు ఇక్కడి నుండి **కాదని** నిర్ధారించుకోండి:

```
Application
→ Cookies
```

## సెషన్ గడువు ముగిసింది

Web Cookie ప్రొవైడర్లు మీ ప్రస్తుత బ్రౌజర్ సెషన్ను ఉపయోగిస్తాయి.

మీ బ్రౌజర్ సెషన్ గడువు ముగిసినా లేదా మీరు సైన్ అవుట్ చేసినా, మీరు కొత్త ప్రమాణపత్రాల సమితిని కాపీ చేయాలి. మద్దతు ఉన్న వెబ్ ప్రొవైడర్ల కోసం కుకీ పునరుద్ధరణను ఆటోమేట్ చేయడానికి, అనుబంధ సాధనమైన [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md)ను చూడండి.

# ఉత్తమ పద్ధతులు

- తాజా ప్రమాణీకరించిన రిక్వెస్ట్ నుండి ప్రమాణపత్రాలను కాపీ చేయండి.
- పాత కుకీలను మళ్లీ ఉపయోగించవద్దు.
- Web Cookie ప్రొవైడర్లను ఉపయోగిస్తున్నప్పుడు మీ బ్రౌజర్ సెషన్ను యాక్టివ్గా ఉంచండి.
- కాపీ చేసిన కుకీలను సున్నితమైన ప్రమాణపత్రాలుగా పరిగణించండి.
- మీకు ఫంక్షన్ కాలింగ్ లేదా ఏజెంట్ వర్క్ఫ్లోలు అవసరమైనప్పుడు API-key ప్రొవైడర్లను ఉపయోగించండి.
