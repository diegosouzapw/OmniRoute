ఈ పత్రం `omniroute@3.8.5`పై లేవనెత్తిన ఆరు
`AI-detected potential malware` నిర్ధారణలకు మరియు `omniroute@3.8.6`లో
అమలు చేసిన ఉపశమనాలకు సంబంధించి నిర్వహణదారు రచించిన ధృవీకరణ. దీని ఉద్దేశాలు:

1. భద్రతా పైప్లైన్ నిర్వాహకులు నిర్ధారణలను వాస్తవ సోర్స్తో పోల్చి
   మూల్యాంకనం చేయాల్సి వచ్చినప్పుడు ఉదహరించడానికి ఒకే సూచనను కలిగి ఉండటం.
2. ఫ్లాగ్ చేయబడిన ప్రతి పాత్ ఉద్దేశపూర్వకమైనది, ఆప్ట్-ఇన్ ప్రాతిపదికన
   పనిచేసేది మరియు డాక్యుమెంట్ చేయబడినది అనే నిర్వహణదారు సంతకం చేసిన
   ప్రకటనను భవిష్యత్తు AI స్కానర్లు గుర్తించగలగడం.
3. ప్రతి కాల్ సైట్ను ఆ విధంగా ఎందుకు రూపొందించామో తెలిపే లిఖితపూర్వక రికార్డు
   మనకు ఉండటం — తద్వారా భవిష్యత్తు రీఫ్యాక్టర్ ఉద్దేశపూర్వకంగా తొలగించిన
   ఫింగర్ప్రింట్ను అనుకోకుండా తిరిగి ప్రవేశపెట్టకుండా ఉండటం.

v3.8.6 ఉపశమనాలు విడుదలైన తర్వాత దిగువన ఉన్న కాల్ సైట్లలో దేనినైనా మీ
స్కానర్ మళ్లీ ఫ్లాగ్ చేస్తే, దయచేసి స్కాన్ ట్రేస్తో ఒక ఇష్యూను తెరవండి;
మేము ఇక్కడి ధృవీకరణను విస్తరిస్తాము.

## §1 — MITM రూట్-CA ఇన్స్టాల్ (`77484.js`)

**సోర్స్ ఫైళ్లు**:

- `src/mitm/cert/install.ts` — పబ్లిక్ `installCert()` / `uninstallCert()`,
  ప్రతి ప్లాట్ఫారమ్కు సంబంధించిన `installCertWindows/Mac/Linux`.
- `src/mitm/systemCommands.ts` — ఇన్స్టాల్ పాత్లు ఉపయోగించే ఉమ్మడి
  `execFile` / `spawn` / PowerShell సహాయకాలు.

**ట్రిగ్గర్**: వినియోగదారు స్థానిక డ్యాష్బోర్డ్లోని
`/dashboard/cli-tools/mitm` వద్ద "MITM ప్రాక్సీని ప్రారంభించు"పై క్లిక్ చేస్తారు.
ఈ రూట్ లూప్బ్యాక్కు మాత్రమే పరిమితం — `CLAUDE.md`లోని కఠిన నియమం #17 మరియు
`src/server/authz/routeGuard.ts::isLocalOnlyPath()` చూడండి. టన్నెల్ ద్వారా
బహిర్గతమైన JWT ఈ కోడ్ పాత్ను **ట్రిగ్గర్ చేయలేదు**.

**నిర్వహించే ప్రత్యేకాధికార ఆపరేషన్లు (ప్రతి ప్లాట్ఫారమ్కు)**:

| OS                     | కమాండ్(లు)                                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | UAC ద్వారా `certutil -addstore Root <cert>`                                                                       |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | ప్రతి ప్రొఫైల్కు NSS DB నవీకరణ కోసం `certutil -d sql:<profile>`                                                   |

ఇవి `mitmproxy`, Charles Proxy, Fiddler మరియు Caddy ఉపయోగించే కమాండ్లే.
అవి OmniRouteలో ఉన్నాయనే విషయం
`docs/security/STEALTH_GUIDE.md`లో డాక్యుమెంట్ చేయబడింది.

**v3.8.6 ఉపశమనం**:

- `runElevatedPowerShell()` ఇకపై `-EncodedCommand <base64utf16le>`ను ఉపయోగించదు.
  ఎలివేటెడ్ పేలోడ్ ప్రతి కాల్కు ప్రత్యేకమైన తాత్కాలిక `.ps1` ఫైల్లో
  (mode 0o600, ప్రైవేట్ `mkdtempSync` డైరెక్టరీ లోపల) వ్రాయబడి, `-File`
  ద్వారా సూచించబడుతుంది. `finally`లో ఫైల్ అన్లింక్ చేయబడుతుంది. ఇది
  Socket.dev యొక్క AI క్లాసిఫయర్ ఫ్లాగ్ చేసిన సుపరిచితమైన
  base64-elevation-via-PowerShell ఫింగర్ప్రింట్ను తొలగిస్తుంది.
- `installCertWindows` ఇక్కడికి సూచించే ఇన్లైన్ `SECURITY-AUDITOR-NOTE:`
  బ్లాక్ను కలిగి ఉంటుంది.

**దీనిని ఎందుకు కొనసాగిస్తున్నాం**: MITM ప్రాక్సీ అనేది
`docs/security/STEALTH_GUIDE.md` మరియు `docs/frameworks/MITM-PROXY.md`
ఉపయోగించే, డాక్యుమెంట్ చేయబడిన ఫీచర్. దాన్ని తొలగిస్తే agent-bridge ఫీచర్
సమితి పనిచేయదు.

## §2 — Zed క్రెడెన్షియల్ దిగుమతి (`app/api/providers/zed/import/route.js`)

**సోర్స్ ఫైళ్లు**:

- `src/app/api/providers/zed/discover/route.ts` _(v3.8.6లో కొత్తది)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(v3.8.6లో కొత్తది)_

**ట్రిగ్గర్**: స్థానిక డ్యాష్బోర్డ్లోని Providers పేజీలో వినియోగదారు "Zed నుండి దిగుమతి చేయి"ని క్లిక్ చేస్తారు. ఈ ఎండ్పాయింట్ `requireManagementAuth` ద్వారా నియంత్రించబడుతుంది. Zed ఎడిటర్ తన ప్రొవైడర్ API కీలను డాక్యుమెంట్ చేయబడిన సర్వీస్ పేర్ల కింద OS కీచైన్లో రాస్తుంది — https://zed.dev/docs/ai/llm-providers చూడండి.

**v3.8.5 ప్రవర్తన (Socket.dev ఫ్లాగ్ చేసినది)**:

`POST /import` క్రెడెన్షియల్లను కనుగొని, ఒకే రౌండ్-ట్రిప్లో వాటిని స్థానిక SQLite స్టోర్కు స్వయంచాలకంగా సేవ్ చేసింది. ప్రతి ఖాతాకు ప్రత్యేక నిర్ధారణ లేదు, ఫింగర్ప్రింట్ లేదు; కేవలం "N టోకెన్లు కనుగొనబడ్డాయి, అన్నీ దిగుమతి చేయబడ్డాయి."

**v3.8.6 ఉపశమనం — 2-దశల నిర్ధారణ**:

1. **`POST /api/providers/zed/discover`**
   `{ candidates: [{ provider, service, account, fingerprint }] }`ను తిరిగి ఇస్తుంది. అసలు
   టోకెన్ **ఎప్పటికీ** ప్రసారం చేయబడదు. ఫింగర్ప్రింట్
   `sha256(service|account|token).slice(0,16)`.
2. డ్యాష్బోర్డ్ అభ్యర్థుల జాబితాను ప్రదర్శిస్తుంది, ఆపరేటర్ దిగుమతి చేయాల్సిన వాటిని
   ఎంచుకుని, `{ confirmedAccounts: [{ service, account, fingerprint }] }`ను
   **`POST /api/providers/zed/import`**కు పోస్ట్ చేస్తారు.
3. దిగుమతి ఎండ్పాయింట్ **సర్వర్లో కీచైన్ను మళ్లీ చదివి**,
   `(service, account, fingerprint)` ఆధారంగా ఫిల్టర్ చేస్తుంది. మార్చబడిన లేదా రీప్లే చేయబడిన discover
   ప్రతిస్పందన, సంబంధం లేని టోకెన్ను సేవ్ చేసేలా దిగుమతి ఎండ్పాయింట్ను మోసగించలేదు —
   discover తర్వాత లైవ్ టోకెన్ మారితే, ఫింగర్ప్రింట్ ఇక సరిపోలదు
   మరియు ఆ క్రెడెన్షియల్ దాటవేయబడుతుంది.

`OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` env ఫ్లాగ్, ఇంకా తమ ఆటోమేషన్ను నవీకరించని ఆపరేటర్ల కోసం v3.8.5 ప్రవర్తనను కొనసాగిస్తుంది. ఇది v3.9లో తొలగించబడుతుంది.

**దీన్ని ఎందుకు కొనసాగిస్తున్నాం**: ఇప్పటికే Zedను ఉపయోగిస్తూ, తమ ప్రొవైడర్ కీలను మళ్లీ పేస్ట్ చేయకుండా OmniRouteలో ప్రతిబింబించాలని కోరుకునే వినియోగదారులకు Zed దిగుమతి అత్యంత సులభమైన ఆన్బోర్డింగ్ మార్గం.

## §3 — `execFile` / `spawn` / ఎలివేటెడ్ PowerShell (`21843.js`)

**సోర్స్ ఫైళ్లు**: `src/mitm/systemCommands.ts`.

**ఫ్లాగ్ చేయడానికి కారణం**: ఈ చంక్ `execFileWithPassword`,
`runElevatedPowerShell`, మరియు షేర్డ్ `quotePowerShell` హెల్పర్ను మళ్లీ ఎక్స్పోర్ట్ చేస్తుంది. Socket.dev యొక్క
AI క్లాసిఫయర్ వాటిని సాధారణ "హోస్ట్ ఎగ్జిక్యూషన్ + ప్రివిలేజ్ ఎలివేషన్
టూల్కిట్"గా గుర్తిస్తుంది. OmniRouteలో అవి MITM సర్టిఫికేట్ ఇన్స్టాలేషన్ మార్గం
(§1) ద్వారా, అలాగే `sudo` కమాండ్ అమలు కోసం `execFileWithPassword` ద్వారా మాత్రమే ఉపయోగించబడతాయి.

**v3.8.6 ఉపశమనం**:

- `runElevatedPowerShell` రీఫ్యాక్టర్ (§1 చూడండి).
- `runElevatedPowerShell` మరియు `execFileWithPassword` రెండింటి వద్ద ఉన్న ఇన్లైన్
  `SECURITY-AUDITOR-NOTE:` బ్లాక్, అనుమతించబడిన కాలర్లను మరియు స్థిరీకరించిన ఎగ్జిక్యూటబుల్ జాబితాను
  డాక్యుమెంట్ చేస్తుంది.
- `execFileWithPassword`లోని `spawn()` కాల్, హెల్పర్ స్వీకరించడానికి అనుమతించబడిన
  ఎగ్జిక్యూటబుల్ల అలౌలిస్ట్తో కూడిన `nosemgrep` మార్కర్ను కలిగి ఉంటుంది —
  వినియోగదారు ఇన్పుట్ నుండి `finalCommand`/`finalArgs`కు **ఎలాంటి మార్గమూ లేదు**.

## §4 / §6 — 9router సర్వీస్ సూపర్వైజర్ (`api/services/9router/{start,restart}/route.js`)

**సోర్స్ ఫైళ్లు**:

- `src/app/api/services/9router/_lib.ts` — సూపర్వైజర్ ఫ్యాక్టరీ.
- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`.
- `src/lib/services/ServiceSupervisor.ts` — సాధారణ spawn / హెల్త్-పోల్ / లాగ్-బఫర్.

**ట్రిగ్గర్**: స్థానిక డ్యాష్బోర్డ్లోని ఎంబెడెడ్ సర్వీసుల పేజీలో వినియోగదారు "Install" / "Start"ను క్లిక్ చేస్తారు.

**ఇప్పటికే అమల్లో ఉన్న రక్షణలు**:

- `src/server/authz/routeGuard.ts` ప్రకారం అన్ని `/api/services/*` రూట్లు LOCAL_ONLY
  (కఠిన నియమం #17). ఏదైనా ఆథ్ తనిఖీకి ముందే లూప్బ్యాక్ అమలు జరుగుతుంది —
  లీక్ అయిన JWT కూడా వాటిని చేరుకోలేదు.
- 9router DB రో `status='not_installed', auto_start=0`గా సీడ్ చేయబడుతుంది
  (`src/lib/db/migrations/071_services.sql:19` చూడండి). మొదటిసారి ప్రారంభించినప్పుడు సర్వీస్
  **ప్రారంభం కాదు**.
- `src/lib/services/installers/ninerouter.ts`లోని
  `resolveSpawnArgs(apiKey, PORT)` తిరిగి ఇచ్చే బైనరీ పాత్తో `spawn()` కాల్ చేయబడుతుంది;
  ఇది మద్దతు ఉన్న బైనరీల స్థిరమైన అలౌలిస్ట్.
- Stdout/stderr మెమరీలో బఫర్ చేయబడుతుంది (5 MB పరిమితి, `_lib.ts` చూడండి) —
  వినియోగదారు డ్యాష్బోర్డ్ నుండి లాగింగ్ను ప్రారంభించకపోతే డిస్క్పై ఏమీ రాయబడదు.

**v3.8.6 ఉపశమనం**: ఫంక్షనల్ మార్పు లేదు. ప్రివిలేజ్డ్ మార్గాలను బండిల్ నుండి భౌతికంగా తొలగించాలని కోరుకునే వినియోగదారుల కోసం, మినిమల్ బిల్డ్ ప్రొఫైల్
(`OMNIROUTE_BUILD_PROFILE=minimal`)
`src/lib/services/installers/ninerouter.ts`ను స్టబ్తో భర్తీ చేస్తుంది.

**దీన్ని ఎందుకు కొనసాగిస్తున్నాం**: 9router అనేది ఐచ్ఛికంగా స్థానికంగా ఇన్స్టాల్ చేయగల కంపానియన్
సర్వీస్ (WordPress-శైలి ప్లగిన్గా భావించండి) — పూర్తిగా స్పష్టమైన ఎంపికతో మాత్రమే ప్రారంభమవుతుంది.

## §5 — OmniRoute Cloud Sync క్రెడెన్షియల్ రైట్-బ్యాక్ (`api/keys/[id]/route.js`)

**సోర్స్ ఫైళ్లు**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`.
- `src/app/api/keys/[id]/route.ts` — `syncKeysToCloudIfEnabled()`ను అమలు చేస్తుంది.

**ట్రిగ్గర్**: `isCloudEnabled()` `true`ను తిరిగి ఇస్తుంది (డ్యాష్బోర్డ్ నుండి సెట్ చేయబడుతుంది) **మరియు**
`CLOUD_URL` కాన్ఫిగర్ చేయబడి ఉంటుంది. రెండూ ఆఫ్లో ఉంటే, Cloud ఎండ్పాయింట్కు
అవుట్బౌండ్ నెట్వర్క్ కాల్ చేయబడదు.

**v3.8.5 ప్రవర్తన (Socket.dev సరిగ్గా గుర్తించిన బగ్)**:

`cloudUpdatedAt > localUpdatedAt` అయినప్పుడు, Cloud ప్రతిస్పందనలోని
`accessToken`, `refreshToken`, మరియు `providerSpecificData`తో
`updateLocalTokens()` స్థానిక విలువలను ఓవర్రైట్ చేసింది. HMAC లేదు, సంతకం లేదు,
చెక్సమ్ లేదు. తప్పుగా కాన్ఫిగర్ చేయబడిన లేదా హానికరమైన `CLOUD_URL` (లేదా
ఛానల్లోని MITM) ప్రొవైడర్ OAuth టోకెన్లను నిశ్శబ్దంగా మార్చగలదు.

**v3.8.6 ఉపశమన చర్యలు**:

1. **HMAC ధృవీకరణ**: JSONను పార్స్ చేయడానికి ముందు `verifyCloudSignature(rawBody, sigHeader)`
   `X-Cloud-Sig` హెడర్ను (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`) తనిఖీ చేస్తుంది. సీక్రెట్ సెట్ చేయబడి ఉంటే, సంతకం తప్పనిసరి.
   లేకపోతే (లెగసీ మోడ్), హెచ్చరిక లాగ్ చేయబడి, ప్రతిస్పందన
   ఆమోదించబడుతుంది — v3.9లో సీక్రెట్ తప్పనిసరి అవుతుంది.
2. **సీక్రెట్-ఫీల్డ్ ఆప్ట్-ఇన్**: `OMNIROUTE_CLOUD_SYNC_SECRETS=true`గా ఉన్నప్పుడు
   **మాత్రమే** `accessToken` / `refreshToken` / `providerSpecificData`
   ఓవర్రైట్ చేయబడతాయి. డిఫాల్ట్ మోడ్ క్రెడెన్షియల్ కాని మెటాడేటాను మాత్రమే
   (`expiresAt`, `status`, `lastError*`, `rateLimitedUntil`, `updatedAt`)
   సింక్ చేస్తుంది. రిమోట్ టోకెన్ సింక్పై ఆధారపడిన వినియోగదారులకు ఇది ఒక
   **బ్రేకింగ్ మార్పు** — వారు స్పష్టంగా ఆప్ట్-ఇన్ చేయాలి.

**దీన్ని ఎందుకు కొనసాగిస్తున్నాం**: OmniRoute Cloud టెనెంట్ తమ బృందపు
క్రెడెన్షియల్లను కేంద్రీకరించడానికి Cloud Sync ఒక్కటే మార్గం. ఈ పరిష్కారం
థ్రెట్ మోడల్ను స్పష్టంగా చేస్తుంది:
"సర్వర్ సంతకం చేస్తుంది, క్లయింట్ ధృవీకరిస్తుంది, ఆపరేటర్ ఆప్ట్-ఇన్ చేస్తారు."

## బిల్డ్ ప్రొఫైల్: `minimal`

Socketకు అనుకూలమైన ఆర్టిఫ్యాక్ట్ అవసరమైన వినియోగదారులు దీనితో బిల్డ్ చేయండి:

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

webpack `NormalModuleReplacementPlugin` నాలుగు మాడ్యూల్లను స్టబ్లకు అలియాస్ చేస్తుంది:

| మాడ్యూల్                                    | స్టబ్                                            |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

ప్రతి స్టబ్ అదే ఇంటర్ఫేస్ను ఎక్స్పోర్ట్ చేస్తుంది, కానీ ప్రతి ఫంక్షన్ రన్టైమ్లో
`featureDisabledError(name)`ను త్రో చేస్తుంది. నిలిపివేయబడిన మాడ్యూల్పై ఆధారపడే
రూట్లు సున్నితమైన కోడ్ పాత్ను యాక్టివేట్ చేయకుండా, స్పష్టమైన సందేశంతో HTTP 503ను
తిరిగి ఇస్తాయి.

ఫలితంగా వచ్చే బండిల్ను `omniroute-secure`గా ప్రచురించడానికి ఉద్దేశించారు.
ప్రచురణ విధానం కోసం `docs/ops/PUBLISHING_SECURE.md`ను చూడండి.
