`agentrouter` అప్స్ట్రీమ్ గేట్వే `messages[].content`పై కీవర్డ్-ఆధారిత కంటెంట్ ఫిల్టర్ను అమలు చేస్తుంది. ఈ ఫిల్టర్ కొంతవరకు నిర్ధారితమైనది (కొన్ని నిర్దిష్ట పదబంధాలను ఎల్లప్పుడూ బ్లాక్ చేస్తుంది), మరికొంతవరకు సంభావ్యత-ఆధారితమైనది (బర్స్ట్కు సున్నితమైనది — వేగంగా వరుస అభ్యర్థనలు వచ్చిన తర్వాత మరింత కఠినంగా మారి, కూల్డౌన్ తర్వాత తిరిగి సాధారణ స్థితికి వస్తుంది).

WAF ఒక అభ్యర్థనను బ్లాక్ చేసినప్పుడు ఇది ఇలా ప్రతిస్పందిస్తుంది:

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## ఫిల్టర్ పరిధి

WAF కేవలం `messages[].content`ను మాత్రమే పరిశీలిస్తుంది. ఇది కింది వాటిని పరిశీలించదు:

- `system` ప్రాంప్ట్
- నిర్మిత కంటెంట్ బ్లాక్లు (`tool_result`, `tool_use`, `thinking`, `image`)
- టూల్ `description` మరియు `input_schema` ఫీల్డ్లు
- అభ్యర్థన మెటాడేటా, హెడర్లు లేదా మోడల్ id

## ఎల్లప్పుడూ బ్లాక్ అయ్యే నమూనాలు (అక్షరాల కేసుతో సంబంధం లేకుండా)

| నమూనా                        | గమనికలు                                                          |
| ---------------------------- | ---------------------------------------------------------------- |
| ఏదైనా `Lorem ipsum` వేరియంట్ | పూర్తి లాటిన్ lorem పదజాలం బ్లాక్ అవుతుంది                       |
| `language model` (ఒంటరిగా)   | "the language model" మరియు "large language model" అనుమతించబడతాయి |
| `virtual assistant`          | "AI assistant" అనుమతించబడుతుంది                                  |
| `I'm here to help`           | "here to help" మాత్రమే ఉన్నా కూడా బ్లాక్ అవుతుంది                |
| `Claude, made by Anthropic`  | పూర్తి పదబంధం మాత్రమే                                            |

## దాదాపు ఎల్లప్పుడూ బ్లాక్ అయ్యే నమూనాలు

| నమూనా                                                          | గమనికలు                                                       |
| -------------------------------------------------------------- | ------------------------------------------------------------- |
| `placeholder`                                                  | ఇది ఒంటరిగా ఉన్నప్పుడు (పారామీటర్ పేరు మొదలైన వాటిలో కాకుండా) |
| `dummy data`                                                   | ఫిక్చర్ల కోసం సాధారణ సీడ్ పదబంధం                              |
| `foo bar baz`                                                  | ప్రామాణిక ప్లేస్హోల్డర్ పదబంధం                                |
| పునరావృతమయ్యే చిన్న టోకెన్లు (`AAA BBB CCC`, `test test test`) | కీవర్డ్ స్టఫింగ్ను గుర్తించే డిటెక్టర్                        |

## లోడ్లో ఉన్నప్పుడు ప్రవర్తన

తక్కువ వ్యవధిలో సుమారు 5 వేగవంతమైన అభ్యర్థనలు వచ్చిన తర్వాత, సాధారణంగా అనుమతించబడే కంటెంట్ను కూడా WAF బ్లాక్ చేయడం ప్రారంభిస్తుంది. సుమారు 5–10 సెకన్ల పాటు ఎలాంటి అభ్యర్థనలు లేకపోతే బకెట్ సడలుతుంది. Claude Code లేదా Codex CLI వేగంగా వరుసగా అనేక టూల్-వినియోగ / సందేశ-పంపిణీ కాల్లు చేసినప్పుడు అప్పుడప్పుడు `400 content-blocked` ఎర్రర్లు రావడానికి కారణమయ్యే IP-మరియు-key-ఆధారిత రేట్ లిమిటర్ కూడా ఇదే.

## OmniRouteలో ఇప్పటికే అమలు చేసిన నివారణలు

1. **`open-sse/services/wafRateLimit.ts`** — ఏదైనా `agentrouter:*` URLకు పంపే అవుట్బౌండ్ అభ్యర్థనల మధ్య కనీసం 500 ms విరామాన్ని అమలు చేసే బర్స్ట్ గార్డ్. ఈ విరామం మానవులు గుర్తించగల లేటెన్సీ కంటే చాలా తక్కువగా ఉండి, సాధారణ ట్రాఫిక్లో WAF యాక్టివేట్ కాకుండా నిరోధిస్తుంది.

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — అప్స్ట్రీమ్ `400 content-blocked`ను తిరిగి పంపినప్పుడు, ఎగ్జిక్యూటర్ అదే URLను ఎక్స్పోనెన్షియల్ బ్యాక్ఆఫ్తో (1.5 s, 3.0 s, గరిష్ఠంగా 2 ప్రయత్నాలు) మళ్లీ ప్రయత్నిస్తుంది. బ్యాక్ఆఫ్ తర్వాత WAF సాధారణంగా సడలుతుంది, తద్వారా పునఃప్రయత్నం విజయవంతమవుతుంది.

3. **`tests/unit/compression/harness.test.ts`** — Claude Code ఈ ఫైల్ను `Read` టూల్ ద్వారా చదివినప్పుడు, ఫైల్ కంటెంట్ `tool_result` బ్లాక్ ద్వారా తిరిగి ప్రవహించి WAFను ట్రిగ్గర్ చేయకుండా ఉండేందుకు, టెస్ట్ ఫిక్చర్ `longInput`ను `"lorem ipsum dolor sit amet ".repeat(40)` నుండి `"example content for testing purposes ".repeat(40)`కు మార్చారు.

## ప్రాంప్ట్లు మరియు టూల్ అవుట్పుట్కు మార్గదర్శకాలు

Claude Code లేదా Codex CLI సెషన్లో పదేపదే `400 content-blocked` వస్తుంటే, అత్యంత ఇటీవలి యూజర్ సందేశం మరియు అత్యంత ఇటీవలి టూల్ ఫలితంలో పైన పేర్కొన్న నమూనాలు ఏవైనా ఉన్నాయేమో తనిఖీ చేసి, వాటిని మరో విధంగా వ్రాయండి. సాధారణ ప్రత్యామ్నాయ మార్గాలు:

- `Lorem ipsum …`ను `example text …`తో లేదా టెస్ట్ లేదా ఫిక్చర్ నమూనాగా చూపించడానికి ప్రయత్నిస్తున్న వాస్తవ కంటెంట్తో భర్తీ చేయండి.
- `placeholder` (ఒంటరిగా ఉన్నప్పుడు)ను `example value`, `sample value` లేదా వాస్తవ విలువతో భర్తీ చేయండి.
- `language model`ను `large language model` లేదా `the model`తో భర్తీ చేయండి.
- `dummy data`ను `sample data` లేదా వాస్తవిక సీడ్ విలువలతో భర్తీ చేయండి.
- `I'm here to help` / `here to help`ను మరింత నిర్దిష్టమైన ప్రారంభ వాక్యంతో భర్తీ చేయండి (ఉదా. "I'll review the file you mentioned").

## తప్పుడు పాజిటివ్లను అప్స్ట్రీమ్కు నివేదించడం

ప్రస్తుత ఫిల్టర్ అతిగా కఠినంగా ఉంది — ఆపరేటర్ స్పష్టంగా ప్రాంప్ట్ను ఇంజెక్ట్ చేయాలని ఉద్దేశించనప్పటికీ, ఇది `tool_result` బ్లాక్లలోని "Lorem ipsum"ను బ్లాక్ చేస్తుంది. దీనిని మూలస్థాయిలో పరిష్కరించాలని కోరుకునే ఆపరేటర్లు తప్పుడు పాజిటివ్లను నివేదించడానికి `agentrouter.org`ను సంప్రదించాలి. పై బ్లాక్లిస్ట్ 2026-08-03 నాటికి అప్స్ట్రీమ్ను పరీక్షించడం ద్వారా పొందిన అనుభవాధారిత ఫలితం.
