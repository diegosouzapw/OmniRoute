OmniRoute npm + Docker ఆర్టిఫాక్ట్లను ప్రచురిస్తుంది. ఈ గేట్లు మూలాధార ధృవీకరణను,
ఇన్వెంటరీని (SBOM), CVE స్కానింగ్ను అందిస్తాయి; ఇవన్నీ OSS సాధనాలు మరియు విడుదల వర్క్ఫ్లోలలో అనుసంధానించబడ్డాయి.
**ముందుగా-హెచ్చరిక** విధానం — ప్రస్తుతం ఇవి నివేదిస్తాయి; 1వ విజయవంతమైన
విడుదల తర్వాత బ్లాకింగ్గా మార్చబడతాయి.

| గేట్                       | సాధనం                                          | ఎక్కడ                         | బ్లాక్ చేస్తుందా?        | అవుట్పుట్                                                 |
| -------------------------- | ---------------------------------------------- | ----------------------------- | ------------------------ | --------------------------------------------------------- |
| SLSA మూలాధార ధృవీకరణ (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | ప్రచురణ విఫలమైతే మాత్రమే | npmjs బ్యాడ్జ్ / `npm audit signatures`                   |
| SBOM npm                   | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | జనరేషన్ విఫలమైతే మాత్రమే | విడుదల అసెట్ + ఆర్టిఫాక్ట్                                |
| SBOM ఇమేజ్                 | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (విలీనం) | హెచ్చరిక మాత్రమే         | CycloneDX ఆర్టిఫాక్ట్                                     |
| Trivy CVE (SARIF)          | `aquasecurity/trivy-action`                    | `docker-publish.yml` (విలీనం) | హెచ్చరిక మాత్రమే         | SARIF (HIGH+CRITICAL) → Security ట్యాబ్                   |
| Trivy CRITICAL గేట్        | `aquasecurity/trivy-action`                    | `docker-publish.yml` (విలీనం) | **బ్లాకింగ్**            | పరిష్కరించగల CRITICALపై `exit-code: '1'`                  |
| osv vulnCount              | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **బ్లాకింగ్**            | `metrics.vulnCount`ను రాట్చెట్ చేస్తుంది (direction:down) |
| OpenSSF Scorecard          | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | హెచ్చరిక మాత్రమే         | SARIF → Security + బ్యాడ్జ్                               |

ఇమేజ్ CVE రాట్చెట్ `docker-publish.yml`లో **రెండు దశలను** ఉపయోగిస్తుంది: SARIF దశ
(`HIGH,CRITICAL`, `exit-code: 0`) బ్లాక్ చేయకుండానే Security ట్యాబ్లో HIGH+CRITICALను
కనిపించేలా ఉంచుతుంది; _CRITICAL గేట్_ దశ (`severity: CRITICAL`, `ignore-unfixed: true`,
`exit-code: 1`) **పరిష్కారం అందుబాటులో ఉన్న** CRITICAL CVE కారణంగా విడుదలను విఫలం చేస్తుంది. `ignore-unfixed`
అప్స్ట్రీమ్ ప్యాచ్ లేని బేస్-ఇమేజ్ CVE కారణంగా విడుదల బ్లాక్ కాకుండా నిరోధిస్తుంది.

## ⚠️ CVE వైవిధ్యం (బ్లాకింగ్ osv/Trivy గేట్లు)

osv మరియు Trivy డిపెండెన్సీలను **నిరంతరం పెరుగుతున్న** CVE డేటాబేస్లతో పోలుస్తాయి. ఎలాంటి
డిపెండెన్సీలను **మార్చని** PR కూడా, ఇప్పటికే ఉన్న డిపెండెన్సీలో కొత్త CVE
వెల్లడించబడినందున అకస్మాత్తుగా ఎరుపుగా మారవచ్చు (osv: కొలిచిన `vulnCount` > బేస్లైన్; Trivy: ఇమేజ్లో కొత్తగా
పరిష్కరించగల CRITICAL). **ఇది బ్లాకింగ్ CVE గేట్కు సంబంధించి ఊహించిన కార్యాచరణ ప్రవర్తనే,
ఉత్పత్తిలో తిరోగమనం కాదు.**

కొత్తగా వెల్లడైన CVE కారణంగా osv లేదా Trivy ఎరుపుగా మారినప్పుడు, పరిష్కారం:

1. **ప్రభావిత డిపెండెన్సీని బంప్ చేయండి** (ప్రాధాన్య ఎంపిక) — `package.json`
   `overrides` (ట్రాన్సిటివ్ డిపెండెన్సీలు) ద్వారా ప్యాచ్ చేసిన వెర్షన్కు అప్గ్రేడ్ చేయండి లేదా ప్యాచ్ చేసిన బేస్పై ఇమేజ్ను మళ్లీ బిల్డ్ చేయండి.
2. **అప్స్ట్రీమ్ పరిష్కారం లేకపోతే:**
   - **osv:** `config/quality/quality-baseline.json`లో `metrics.vulnCount`ను మళ్లీ బేస్లైన్ చేయండి
     (`npm run quality:ratchet -- --update` ప్రత్యేక గేట్లను కవర్ చేయదు — సమర్థన గమనిక + ట్రాకింగ్ ఇష్యూతో
     విలువను మాన్యువల్గా సవరించండి, `direction:down`).
   - **Trivy:** సమర్థన
     కామెంట్ + ట్రాకింగ్ ఇష్యూతో `.trivyignore`లో ఒక ఎంట్రీని జోడించండి (ఒక్కో లైన్కు CVE-ID). ప్యాచ్లు లేని
     CVEలను `ignore-unfixed: true` ఇప్పటికే ఆటోమేటిక్గా కవర్ చేస్తుంది.

సాధనం అందుబాటులో లేనప్పుడు లేదా కొలత
విఫలమైనప్పుడు (osv-scanner PATHలో లేకపోవడం, osv.dev/నెట్వర్క్ అందుబాటులో లేకపోవడం, చెల్లని JSON) రెండు గేట్లు **సజావుగా SKIP** అవుతాయి (exit 0) — ఒక
**కొలత** వైఫల్యం ఎన్నడూ బ్లాక్ చేయదు; **కొలిచిన** తిరోగమనం మాత్రమే బ్లాక్ చేస్తుంది.
