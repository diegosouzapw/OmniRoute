OmniRoute npm + Docker ఆర్టిఫాక్ట్లను ప్రచురిస్తుంది. ఈ గేట్లు ప్రొవెనెన్స్, ఇన్వెంటరీ (SBOM) మరియు CVE స్కానింగ్ను అందిస్తాయి, ఇవన్నీ OSS, రిలీజ్ వర్క్ఫ్లోలలో ప్లగ్ చేయబడ్డాయి.
**అడ్వైజరీ-ఫస్ట్** వైఖరి — అవి ఇప్పుడు నివేదిస్తాయి, 1వ గ్రీన్ రిలీజ్ తర్వాత బ్లాకింగ్కు ప్రమోట్ చేస్తాయి.

| గేట్                    | టూల్                                           | ఎక్కడ                         | బ్లాక్ చేస్తుందా?        | అవుట్పుట్                                            |
| ----------------------- | ---------------------------------------------- | ----------------------------- | ------------------------ | ---------------------------------------------------- |
| SLSA ప్రొవెనెన్స్ (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | పబ్లిష్ విఫలమైతే మాత్రమే | బ్యాడ్జ్ npmjs / `npm audit signatures`              |
| SBOM npm                | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | జనరేషన్ విఫలమైతే మాత్రమే | రిలీజ్ అసెట్ + ఆర్టిఫాక్ట్                           |
| SBOM ఇమేజ్              | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | సలహా                     | CycloneDX ఆర్టిఫాక్ట్                                |
| Trivy CVE (SARIF)       | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | సలహా                     | SARIF (HIGH+CRITICAL) → సెక్యూరిటీ ట్యాబ్            |
| Trivy CRITICAL గేట్     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | **బ్లాకింగ్**            | పరిష్కరించదగిన CRITICAL పై `exit-code: '1'`          |
| osv vulnCount           | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **బ్లాకింగ్**            | `metrics.vulnCount` (దిశ:కిందికి)ని రాచెట్ చేస్తుంది |
| OpenSSF Scorecard       | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | సలహా                     | SARIF → సెక్యూరిటీ + బ్యాడ్జ్                        |

ఇమేజ్ CVE రాచెట్ `docker-publish.yml`లో **రెండు దశలను** ఉపయోగిస్తుంది: SARIF దశ (`HIGH,CRITICAL`, `exit-code: 0`) HIGH+CRITICALని సెక్యూరిటీ ట్యాబ్లో బ్లాక్ చేయకుండా కనిపించేలా ఉంచుతుంది; _CRITICAL గేట్_ దశ (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) **పరిష్కారం అందుబాటులో ఉన్న** CRITICAL CVE పై రిలీజ్ను విఫలం చేస్తుంది. `ignore-unfixed` అప్స్ట్రీమ్ ప్యాచ్ లేని బేస్-ఇమేజ్ CVE కోసం రిలీజ్ను బ్లాక్ చేయకుండా నిరోధిస్తుంది.

## ⚠️ CVE వేరియెన్స్ (osv/Trivy గేట్లను బ్లాక్ చేయడం)

osv మరియు Trivy డిపెండెన్సీలను **నిరంతరం పెరుగుతున్న** CVE డేటాబేస్లతో పోలుస్తాయి. **ఎటువంటి డిపెండెన్సీలను తాకని** ఒక PR, ఇప్పటికే ఉన్న డిపెండెన్సీలో కొత్త CVE వెల్లడి కావడంతో అకస్మాత్తుగా ఎరుపు రంగులోకి మారవచ్చు (osv: కొలవబడిన `vulnCount` > బేస్లైన్; Trivy: ఇమేజ్లో కొత్తగా పరిష్కరించదగిన CRITICAL). **ఇది బ్లాకింగ్ CVE గేట్ యొక్క ఆశించిన కార్యాచరణ ప్రవర్తన, ఉత్పత్తి రిగ్రెషన్ కాదు.**

కొత్తగా వెల్లడైన CVE కారణంగా osv లేదా Trivy ఎరుపు రంగులోకి మారినప్పుడు, నివారణ మార్గం:

1.  **ప్రభావితమైన డిపెండెన్సీని బంప్ చేయండి** (ప్రాధాన్యత) — `package.json` `overrides` (ట్రాన్సిటివ్ డిపెండెన్సీలు) ద్వారా ప్యాచ్ చేయబడిన వెర్షన్కు అప్గ్రేడ్ చేయండి లేదా ప్యాచ్ చేయబడిన బేస్ పై ఇమేజ్ను తిరిగి నిర్మించండి.
2.  **అప్స్ట్రీమ్ పరిష్కారం లేకపోతే:**
    - **osv:** `config/quality/quality-baseline.json`లో `metrics.vulnCount`ను తిరిగి బేస్లైన్ చేయండి (`npm run quality:ratchet -- --update` అంకితమైన గేట్లను కవర్ చేయదు — విలువను చేతితో సవరించండి, `direction:down`) సమర్థన నోట్ + ట్రాకింగ్ ఇష్యూతో.
    - **Trivy:** `.trivyignore`లో (ప్రతి లైన్కు CVE-ID) సమర్థన వ్యాఖ్య + ట్రాకింగ్ ఇష్యూతో ఒక ఎంట్రీని జోడించండి. `ignore-unfixed: true` ఇప్పటికే ప్యాచ్లు లేని CVEలను స్వయంచాలకంగా కవర్ చేస్తుంది.

టూల్ లేనప్పుడు లేదా కొలత విఫలమైనప్పుడు (osv-scanner PATHలో లేదు, osv.dev/network అందుబాటులో లేదు, చెల్లని JSON) రెండు గేట్లు **సౌకర్యవంతంగా SKIP** (exit 0) అవుతాయి — **కొలత** వైఫల్యం ఎప్పుడూ బ్లాక్ చేయదు, **కొలవబడిన** రిగ్రెషన్ మాత్రమే బ్లాక్ చేస్తుంది.

### extract-zip 2.0.1 — GHSA-7pqw-9j4j-h8q3 / GHSA-jmr9-qjv8-65gv (#14482)

`extract-zip@2.0.1` రెండు ప్యాచ్ చేయని అధిక-తీవ్రత సిమ్లింక్-ట్రావెర్సల్ సలహాలను కలిగి ఉంది.

**ఆమోదించబడిన ప్రమాదం**, బంప్ కాదు:

- **చైన్:** `promptfoo` (devDependency) → `@openai/codex-security` → `extract-zip@2.0.1`.
  `package-lock.json` ద్వారా నిర్ధారించబడింది — మొత్తం డిపెండెన్సీలో సరిగ్గా ఒక ప్యాకేజీ
  ట్రీ (`@openai/codex-security`) `extract-zip`ని ప్రకటిస్తుంది, మరియు సరిగ్గా ఒక ప్యాకేజీ
  (`promptfoo`) `@openai/codex-security`ని ప్రకటిస్తుంది.
- **చైన్లో ఎక్కడా స్థిరమైన విడుదల లేదు.** `extract-zip@2.0.1` (2020లో ప్రచురించబడింది) ప్యాకేజీ యొక్క చివరి విడుదల — ఇది నిర్వహించబడదు. `@openai/codex-security` యొక్క
  ప్రస్తుత npm-latest (`0.1.29`) ఇప్పటికీ `extract-zip@2.0.1`ని లాగుతుంది.

  `extract-zip` npm ప్యాకేజీని దిగుమతి చేయదు — OmniRoute యొక్క స్వంత `extractZip()` హెల్పర్
  (`src/lib/versionManager/binaryManager.ts:93`) స్థానిక `unzip`/`tar`కి షెల్స్ చేస్తుంది
