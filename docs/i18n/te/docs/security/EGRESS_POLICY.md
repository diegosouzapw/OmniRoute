> **ప్రతి ప్రాక్సీకి అవుట్బౌండ్ ట్రాఫిక్ను ఒకే IP ఫ్యామిలీకి — `auto`, `ipv4`, లేదా `ipv6` — పరిమితం చేయండి, తద్వారా IPv6-మాత్రమే ఉన్న ఎగ్రెస్ ఎప్పటికీ నిశ్శబ్దంగా IPv4కు తిరిగి లీక్ అవదు.**

> **ప్రామాణిక మూలం:** `open-sse/utils/proxyFamily.ts`, `open-sse/utils/proxyDispatcher.ts`, `open-sse/utils/proxyFetch.ts`, `open-sse/utils/socksConnectorWithFamily.ts`, `open-sse/utils/proxyFamilyResolve.ts`, `src/shared/validation/schemas.ts`, `src/lib/db/proxies.ts`, `src/lib/db/upstreamProxy.ts`, `src/lib/db/migrations/099_proxy_family.sql`

OmniRoute ప్రతి ప్రాక్సీకి ఒక **అడ్రస్-ఫ్యామిలీ ఎగ్రెస్ నిర్దేశాన్ని** కలిగి ఉండే వీలు కల్పిస్తుంది. డిఫాల్ట్గా OS IPv4 లేదా IPv6ను ఎంచుకుంటుంది (డ్యూయల్-స్టాక్, "Happy Eyeballs"). మీరు నిర్దేశాన్ని `ipv4` లేదా `ipv6`కు సెట్ చేసినప్పుడు, OmniRoute ఆ ప్రాక్సీ ద్వారా జరిగే ప్రతి కనెక్షన్ను ఎంచుకున్న ఫ్యామిలీకి పరిమితం చేస్తుంది మరియు ఇతర ఫ్యామిలీకి ఫాల్బ్యాక్ కాకుండా **విఫలమైనప్పుడు మూసివేస్తుంది**.

ఈ పేజీ ఆ నిర్దేశం ఏమిటి, అది ఎందుకు ఉంది, దాన్ని ఎక్కడ కాన్ఫిగర్ చేయాలి, మరియు రన్టైమ్ దాన్ని ఎలా పరిష్కరిస్తుంది అనే విషయాలను వివరిస్తుంది.

## ఇది ఏమిటి

రిజిస్ట్రీలోని ప్రతి ప్రాక్సీకి మూడు సాధ్యమైన విలువలతో కూడిన `family` ఫీల్డ్ ఉంటుంది, ఇది Zod enum ద్వారా ధృవీకరించబడుతుంది:

```ts
// src/shared/validation/schemas.ts
family: z.enum(["auto", "ipv4", "ipv6"]).optional().default("auto"),
```

ఈ ఫీల్డ్ డిఫాల్ట్గా `"auto"`ను ఉపయోగిస్తుంది, ఇది మునుపటి డ్యూయల్-స్టాక్ ప్రవర్తనను అలాగే ఉంచుతుంది. దాన్ని `ipv4` లేదా `ipv6`కు సెట్ చేయడం ద్వారా ఆ ప్రాక్సీకి కనెక్ట్ ఫ్యామిలీ పరిమితం చేయబడుతుంది.

ఏదైనా తెలియని విలువ `auto`గా మారేలా, ఈ నిర్దేశం ప్రతిచోటా ఒకే సహాయక ఫంక్షన్ ద్వారా సాధారణీకరించబడుతుంది:

```ts
// open-sse/utils/proxyFamily.ts
export type ProxyFamily = "auto" | "ipv4" | "ipv6";

export function parseProxyFamily(value: unknown): ProxyFamily {
  return value === "ipv4" || value === "ipv6" ? value : "auto";
}
```

## ఇది ఎందుకు ఉంది

PR [#3777](https://github.com/diegosouzapw/OmniRoute/pull/3777)లో ప్రవేశపెట్టబడింది. దీన్ని ప్రవేశపెట్టడానికి కారణమైన సమస్యలు:

| సమస్య                                           | నిర్దేశం పరిష్కరించేది                                                                                                                                                                                                                                                                                                                            |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **IPv6-మాత్రమే ఉన్న ఎగ్రెస్ IPv4కు లీక్ కావడం** | ఒక ప్రాక్సీ హోస్ట్కు A మరియు AAAA రికార్డులు రెండూ ఉన్నప్పుడు (లేదా OS IPv4కు ప్రాధాన్యత ఇచ్చినప్పుడు), మీరు IPv6-మాత్రమే ఉన్న మార్గాన్ని ఉద్దేశించినప్పటికీ Happy Eyeballs IPv4 ద్వారా బయటకు కనెక్ట్ కావచ్చు. `ipv6`కు పరిమితం చేయడం ఆ లీక్ను తొలగిస్తుంది.                                                                                      |
| **భాగస్వామ్య-ఎగ్రెస్ అసాధారణత కారణంగా రద్దు**   | అనేక ఖాతాలు అధిక పరిమాణంలో **ఒకే** IP ద్వారా ఎగ్రెస్ అయినప్పుడు, రొటేటింగ్ ప్రొవైడర్లు (codex/openai) టోకెన్లను రద్దు చేస్తారు. ఖాతాలను వేర్వేరు, ఊహించదగిన ఎగ్రెస్ మార్గాల్లో ఉంచడంలో ఎగ్రెస్ ఫ్యామిలీని నియంత్రించడం ఒక భాగం (దీనితో జతగా ఉపయోగించే ఎగ్రెస్-IP నిర్ధారణల కోసం [`src/lib/proxyEgress.ts`](../../src/lib/proxyEgress.ts) చూడండి). |
| **అనుగుణ్యత/పరీక్ష కోసం నిర్దిష్ట ఎగ్రెస్**     | ట్రాఫిక్ నిర్దిష్ట ఫ్యామిలీ ద్వారా బయటకు వెళ్తుందని మీరు హామీ ఇవ్వాల్సినప్పుడు, `auto` సరిపోదు.                                                                                                                                                                                                                                                   |

ఈ నిర్దేశం ఉద్దేశపూర్వకంగా గ్లోబల్గా కాకుండా **ప్రతి-ప్రాక్సీకి** వర్తిస్తుంది — మీ పూల్లోని వేర్వేరు ప్రాక్సీలు వేర్వేరు విధానాలను కలిగి ఉండవచ్చు.

## దీన్ని ఎలా కాన్ఫిగర్ చేయాలి

### డాష్బోర్డ్

సెలెక్టర్ **ప్రాక్సీ పూల్** ట్యాబ్లోని ప్రాక్సీ ఫారమ్లో ఉంటుంది:

1. **డాష్బోర్డ్ → సెట్టింగ్లు → ప్రాక్సీ → ప్రాక్సీ పూల్** తెరవండి
2. ఒక ప్రాక్సీని జోడించండి లేదా సవరించండి
3. **IP ఫ్యామిలీ** డ్రాప్డౌన్ను `స్వయంచాలకం (డ్యూయల్-స్టాక్)`, `IPv4 మాత్రమే`, లేదా `IPv6 మాత్రమే`గా సెట్ చేయండి
4. సేవ్ చేయండి

ఈ కంట్రోల్ను `ProxyRegistryManager.tsx` రెండర్ చేస్తుంది (`proxy/ProxyPoolTab.tsx`లో మౌంట్ చేయబడింది).

### API

`family` ఫీల్డ్ ప్రాక్సీ రిజిస్ట్రీ సృష్టి/నవీకరణ పేలోడ్లలో భాగంగా ఉంటుంది, దీనిని `createProxyRegistrySchema` / `updateProxyRegistrySchema` (`src/shared/validation/schemas.ts`) ధృవీకరిస్తాయి మరియు `POST` / `PATCH /api/v1/management/proxies` నిర్వహిస్తాయి:

```bash
# IPv6-మాత్రమే ప్రాక్సీని సృష్టించండి
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "IPv6 egress",
    "type": "socks5",
    "host": "proxy.example.com",
    "port": 1080,
    "family": "ipv6"
  }'

# ఇప్పటికే ఉన్న ప్రాక్సీని IPv4-మాత్రమేగా మార్చండి
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{ "id": "proxy-uuid-here", "family": "ipv4" }'
```

అప్స్ట్రీమ్-ప్రాక్సీ ఎంట్రీల కోసం ఉపయోగించే ఇన్లైన్ ప్రాక్సీ కాన్ఫిగ్ ఆబ్జెక్ట్ కూడా ఇదే ఫీల్డ్ను అంగీకరిస్తుంది (`upstream_proxy_config.family`, [డేటా మోడల్](#data-model) చూడండి).

మిగిలిన ప్రాక్సీ CRUD/అసైన్మెంట్ API కోసం, [PROXY_GUIDE.md](../ops/PROXY_GUIDE.md) చూడండి.

## `auto` ఎలా పరిష్కరించబడుతుంది

`family` విలువ `auto`గా ఉన్నప్పుడు, OmniRoute ఎలాంటి డైరెక్టివ్నూ జోడించదు — ప్రాక్సీ URL యథాతథంగా ఉపయోగించబడుతుంది మరియు కనెక్ట్ ఫ్యామిలీ అంతర్గతంగా నిర్ణయించబడుతుంది.

URL-బిల్డ్ సమయంలో (`open-sse/utils/proxyDispatcher.ts`లోని `proxyConfigToUrl` / `normalizeProxyUrl`), `auto` ప్రాక్సీ ఎలాంటి మార్కర్ లేని సాధారణ URLను అందిస్తుంది:

```ts
// open-sse/utils/proxyDispatcher.ts
const fam = parseProxyFamily(config.family);
const normalized = normalizeProxyUrl(proxyUrlStr, "context proxy", {
  allowSocks5,
});
return fam === "auto" ? normalized : `${normalized}?family=${fam}`;
```

డిస్పాచ్ సమయంలో (`resolveDispatcherFamily`), `auto` అనేది IP-లిటరల్ హోస్ట్ యొక్క అంతర్గత ఫ్యామిలీగా పరిష్కరించబడుతుంది లేదా హోస్ట్నేమ్ విషయంలో `null`గా (OS నిర్ణయించనివ్వడం) పరిష్కరించబడుతుంది:

```ts
// open-sse/utils/proxyDispatcher.ts
function resolveDispatcherFamily(parsed: URL): 4 | 6 | null {
  const directive = parseProxyFamily(parsed.searchParams.get("family") ?? undefined);
  const literal = detectIpLiteralFamily(parsed.hostname);
  if (directive === "auto") return literal; // హోస్ట్నేమ్కు null → OS ఎంచుకుంటుంది
  // ...
}
```

కాబట్టి:

- `auto` + IP-లిటరల్ హోస్ట్ (`192.0.2.1` / `[2001:db8::1]`) → ఆ లిటరల్ యొక్క ఫ్యామిలీ.
- `auto` + హోస్ట్నేమ్ → `null` → ప్రామాణిక డ్యూయల్-స్టాక్ OS రిజల్యూషన్.

## `ipv4` / `ipv6` ఎలా అమలు చేయబడతాయి

`auto` కాని డైరెక్టివ్, సాధారణీకరించిన ప్రాక్సీ URLకు ఒకసారి జోడించబడిన ఒకే సింథటిక్ క్వెరీ మార్కర్గా — `?family=ipv4` లేదా `?family=ipv6` — ప్రయాణిస్తుంది. పోర్ట్ పార్సింగ్ను అది ఎప్పటికీ పాడుచేయకుండా ఉండేలా, ఈ మార్కర్ను ఖచ్చితంగా ఒక్కసారి తొలగించి తిరిగి జోడించడంలో `normalizeProxyUrl` జాగ్రత్త వహిస్తుంది.

డిస్పాచర్ నిర్మించబడినప్పుడు, మార్కర్ చదవబడి నిర్దిష్ట కనెక్ట్ ఫ్యామిలీగా మార్చబడుతుంది. హోస్ట్ **వ్యతిరేక** ఫ్యామిలీకి చెందిన IP లిటరల్ అయితే, OmniRoute ఎర్రర్ను విసురుతుంది (వైరుధ్యం ఏర్పడితే fail-closed అవుతుంది):

```ts
// open-sse/utils/proxyDispatcher.ts
const want = directive === "ipv6" ? 6 : 4;
if (literal !== null && literal !== want) {
  throw new Error(
    `[ProxyDispatcher] Proxy family directive ${directive} contradicts ${literal === 6 ? "IPv6" : "IPv4"} literal host`
  );
}
```

ఆపై నిర్దిష్ట ఫ్యామిలీ కనెక్టర్పై స్థిరపరచబడుతుంది:

- **HTTP/HTTPS ప్రాక్సీలు** (`ProxyAgent`): `proxyTls: { family, autoSelectFamily: false }` — Happy Eyeballsను నిలిపివేస్తుంది, తద్వారా ఎంచుకున్న ఫ్యామిలీకి మాత్రమే డయల్ చేయబడుతుంది.
- **SOCKS5 ప్రాక్సీలు**: కస్టమ్ కనెక్టర్, SOCKS క్లయింట్లోకి `socket_options: { family, autoSelectFamily: false }`ను పంపిస్తుంది ([SOCKS5 అనుకూలత](#socks5-compatibility) చూడండి).

## SOCKS5 అనుకూలత

ఫ్యామిలీ పిన్ SOCKS5 ప్రాక్సీలతో పనిచేస్తుంది, కానీ ప్రాక్సీ హాప్ ఫ్యామిలీని పిన్ చేయడానికి అవసరమైన సాకెట్ ఎంపికలను ప్రామాణిక `fetch-socks` బహిర్గతం చేయదు. దాని కోసం OmniRoute తన సొంత కనెక్టర్ను అందిస్తుంది:

```ts
// open-sse/utils/socksConnectorWithFamily.ts
export function buildSocksFamilySocketOptions(family: 4 | 6 | null): Record<string, unknown> {
  if (family === 6) return { family: 6, autoSelectFamily: false };
  if (family === 4) return { family: 4, autoSelectFamily: false };
  return {};
}
```

`family`తో సంబంధం లేకుండా (`null` / హోస్ట్నేమ్పై `auto`తో సహా), అన్ని SOCKS5 డిస్పాచ్లు `createSocksDispatcherWithFamily` ద్వారా వెళ్తాయి: `buildSocksFamilySocketOptions(null)` `{}`ను అందిస్తుంది, అలాగే `socket_options` పిన్నింగ్తో అదే `SocksClient.createConnection` + TLS `buildConnector` మార్గం ఉపయోగించబడుతుంది; అందువల్ల IPv6-మాత్రమే అనుమతించే ఎగ్రెస్ విధానం కోసం Happy Eyeballs IPv4ను ఎంచుకోలేదు.

SOCKS5 మద్దతు డిఫాల్ట్గా ప్రారంభించబడి ఉంటుంది (`ENABLE_SOCKS5_PROXY=false` ద్వారా నిలిపివేయవచ్చు); [PROXY_GUIDE.md → ఎన్విరాన్మెంట్ వేరియబుల్స్](../ops/PROXY_GUIDE.md#environment-variables) చూడండి.

## Fail-Closed ప్రవర్తన

తప్పు ఫ్యామిలీకి నిశ్శబ్దంగా ఫాల్బ్యాక్ కావడానికి బదులుగా దానిని **తిరస్కరించడమే** ఈ డైరెక్టివ్ యొక్క మొత్తం ఉద్దేశ్యం. రెండు గార్డ్లు దీనిని అమలు చేస్తాయి:

1. **లిటరల్ వైరుధ్యం** — IP-లిటరల్ హోస్ట్తో విరుద్ధంగా ఉన్న డైరెక్టివ్, డిస్పాచర్ నిర్మాణ సమయంలో ఎర్రర్ను విసురుతుంది (పైన చూపిన `resolveDispatcherFamily`).

2. **హోస్ట్నేమ్ ప్రీ-ఫ్లైట్ DNS తనిఖీ** — పిన్ చేయబడిన ఫ్యామిలీ ఉన్న హోస్ట్నేమ్ ప్రాక్సీ విషయంలో, ఎగ్రెస్కు **ముందే**, అవసరమైన ఫ్యామిలీలో ఆ హోస్ట్నేమ్కు వాస్తవంగా రికార్డ్ ఉందో లేదో `proxyFetch.ts`, `assertHostnameSupportsFamily` ద్వారా ధృవీకరిస్తుంది:

   ```ts
   // open-sse/utils/proxyFamilyResolve.ts
   const hasFamily = records.some((r) => r.family === family);
   if (!hasFamily) {
     throw new Error(
       `[ProxyFamily] Proxy host ${host} has no ${family === 6 ? "IPv6 (AAAA)" : "IPv4 (A)"} record; ` +
         `refusing ${family === 6 ? "IPv6" : "IPv4"}-only egress (fail-closed)`
     );
   }
   ```

   విఫలమైనప్పుడు, `proxyFetch.ts` ఎర్రర్కు `code = "PROXY_FAMILY_UNAVAILABLE"` మరియు `statusCode = 503` ట్యాగ్లను జోడిస్తుంది. DNS రిజల్యూషన్ వైఫల్యం కూడా అదే విధంగా fail-closedగా పరిగణించబడుతుంది (ఎగ్రెస్ను తిరస్కరిస్తుంది).

DNS ప్రీ-ఫ్లైట్ విషయంలో IP-లిటరల్ హోస్ట్లపై ఎలాంటి చర్య ఉండదు — వాటి ఫ్యామిలీ అంతర్గతంగా నిర్ణయించబడి ఉంటుంది మరియు లుకప్ అవసరం లేదు.

## డేటా మోడల్

`099_proxy_family.sql` మైగ్రేషన్ ద్వారా `family` కాలమ్ **రెండు** పట్టికలకు జోడించబడింది:

```sql
-- src/lib/db/migrations/099_proxy_family.sql
ALTER TABLE proxy_registry ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
ALTER TABLE upstream_proxy_config ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
```

- `proxy_registry.family` — రిజిస్ట్రీ ఎంట్రీల కోసం ప్రతి-ప్రాక్సీ నిర్దేశం (`src/lib/db/proxies.ts`). రిజల్యూషన్ క్వెరీలు ఇతర ప్రాక్సీ కాలమ్లతో పాటు `family`ని ఎంచుకుంటాయి; విలువ లేకపోయినా లేదా స్ట్రింగ్ కాకపోయినా, అది `"auto"`గా మార్చబడుతుంది.
- `upstream_proxy_config.family` — అప్స్ట్రీమ్-ప్రాక్సీ ఎంట్రీల కోసం నిర్దేశం (`src/lib/db/upstreamProxy.ts`), ఇదే `"auto"` డిఫాల్ట్తో ఉంటుంది.

రిజాల్వ్ చేయబడిన ప్రాక్సీ ఆబ్జెక్ట్లో `auto` కాని `family` ఉంటే, ఆ పిన్ డిస్పాచర్ వరకు కొనసాగేందుకు `proxyConfigToUrl`, `?family=` మార్కర్ను జోడిస్తుంది.
