అధికారికం కాని క్లయింట్లను క్రియాశీలంగా ఫింగర్ప్రింట్ చేసే ఎడ్జ్లను కలిగిన ప్రొవైడర్లతో OmniRoute అనుసంధానమవుతుంది (TLS JA3/JA4, హెడర్ క్రమం, JSON బాడీ ఆకృతి, సమగ్రత టోకెన్లు). OmniRoute అందుబాటులో ఉంచే స్టెల్త్ ఉపరితలాలను, అవి ఎక్కడ అమలు చేయబడ్డాయో ఈ పేజీ డాక్యుమెంట్ చేస్తుంది.

## చట్టపరమైన మరియు నైతిక గమనిక

వినియోగదారుల స్వంత అధికారిక ఖాతాలు (Claude Code CLI, Codex, Antigravity, Cursor మొదలైనవి) మరియు OmniRoute ఏకీకృత API మధ్య OmniRoute ఒక అనుకూలత లేయర్గా పనిచేయడానికి స్టెల్త్ ఫీచర్లు ఉన్నాయి. అవి మోసాన్ని గుర్తించే వ్యవస్థలను తప్పించుకోవడం, క్రెడెన్షియల్లను పంచుకోవడం లేదా ప్రొవైడర్ సేవా నిబంధనలను ఉల్లంఘించడం కోసం **కావు**. ఖాతాలను సృష్టించేటప్పుడు అంగీకరించిన అప్స్ట్రీమ్ ToSను ఆపరేటర్లు పాటించాలని నిర్వహణకర్తలు ఆశిస్తున్నారు.

## TLS ఫింగర్ప్రింటింగ్ లేయర్

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

ప్రతి ఖాతా స్కోప్ మరియు పరిష్కరించబడిన ప్రాక్సీ కోసం స్థిరమైన `wreq-js` సెషన్లు అవసరమైనప్పుడు మాత్రమే సృష్టించబడతాయి. ప్రాసెస్-వ్యాప్త `TlsClient`, Cloudflare వెనుక ఉన్న అప్స్ట్రీమ్ల కోసం **macOSపై Chrome 124** వలె వ్యవహరించే గరిష్ఠంగా 128 సెషన్లను పూల్ చేస్తుంది. స్థానిక రన్టైమ్ అందుబాటులో లేనప్పుడు `TlsClient.fetch()` ఫెయిల్-క్లోజ్డ్ అవుతుంది; కాలర్ ఈ ర్యాపర్ వెలుపల ఫాల్బ్యాక్ను స్పష్టంగా ఎంచుకోవచ్చు.

- సెషన్ ప్రొఫైల్: `browser: "chrome_124", os: "macos"`
- ప్రాక్సీ పరిష్కార క్రమం (ప్రాధాన్యత): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (చిన్న అక్షరాల రూపాలు కూడా)
- కాలపరిమితి: `TLS_CLIENT_TIMEOUT_MS` (`FETCH_TIMEOUT_MS` నుండి సంక్రమిస్తుంది, డిఫాల్ట్ 600000)
- `wreq-js` Response అనేది fetch-అనుకూలమైనది (`headers`, `text()`, `json()`, `clone()`, `body`).
- మొదటి-బైట్ వాచ్డాగ్ (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656): అప్స్ట్రీమ్ హెడర్లు వచ్చిన వెంటనే `TlsClient.fetch()` పరిష్కరించబడుతుంది, కాబట్టి ఎప్పటికీ మొదటి బైట్ను అందించని బాడీని `TLS_CLIENT_TIMEOUT_MS` ఒక్కటే పరిమితం చేయలేదు. `guardTlsFirstByte()`, బాడీ యొక్క మొదటి `read()`ను `TLS_FIRST_BYTE_WATCHDOG_MS`తో పోటీకి ఉంచుతుంది (డిఫాల్ట్ `10000`, `0` దాన్ని నిలిపివేస్తుంది); ఆరోగ్యకరమైన బాడీపై ప్రభావం ఉండదు, అయితే నిలిచిపోయిన బాడీ wreq రీడర్ను రద్దు చేసి, `proxyFetch`లో ఇప్పటికే ఉన్న TLS-ఫాల్బ్యాక్ లాజిక్ నేరుగా/ప్రాక్సీ డిస్పాచర్కు కొనసాగేందుకు అనుమతిస్తుంది (రీప్లే చేయడం సురక్షితం కాని అభ్యర్థన, ఉదాహరణకు బాడీతో కూడిన POST, నిశ్శబ్దంగా మళ్లీ ప్రయత్నించబడకుండా ఇప్పటికీ ఎర్రర్ను విసురుతుంది).

### వెబ్-కుకీ ప్రొవైడర్ ట్రాన్స్పోర్ట్ — wreq-js 3.2.0

క్రింద ఉన్న ఐదు ప్రత్యేకీకరించిన వెబ్-కుకీ ట్రాన్స్పోర్ట్లకు `open-sse/services/tlsClientBase.ts` ఉమ్మడి అడాప్టర్. ప్రతి సన్నని ప్రొవైడర్ ర్యాపర్ ఒక బ్రౌజర్/OS ప్రొఫైల్ను ఎంచుకుంటుంది. ప్రొఫైల్ + OS + పరిష్కరించబడిన ప్రాక్సీ ఆధారంగా కీ చేయబడిన `open-sse/utils/tlsClient.ts`లోని ఒకే wreq రన్టైమ్ లోడర్ మరియు ట్రాన్స్పోర్ట్ పూల్ను అడాప్టర్ ఉపయోగిస్తుంది; అదే సమయంలో ప్రతి అభ్యర్థన `cookieMode: "ephemeral"`ను ఉపయోగిస్తుంది. కాబట్టి ఖాతాలు మరియు అభ్యర్థనలు ట్రాన్స్పోర్ట్-స్థాయి కనెక్షన్లను పంచుకుంటాయి, కానీ wreq సెషన్ లేదా కుకీ జార్ను ఎప్పటికీ పంచుకోవు.

| ప్రొవైడర్  | ప్రొఫైల్      | అనుకరించిన OS | స్ట్రీమ్ EOF విధానం                         |
| ---------- | ------------- | ------------- | ------------------------------------------- |
| Claude     | `chrome_146`  | Linux         | `[DONE]`ను చేర్చాలి                         |
| Perplexity | `firefox_148` | macOS         | `event: end_of_stream`ను చేర్చాలి           |
| Grok       | `chrome_146`  | Linux         | `[DONE]`ను మినహాయించాలి                     |
| Notion     | `chrome_146`  | Windows       | `[DONE]`ను చేర్చాలి                         |
| LMArena    | `chrome_146`  | Windows       | సెంటినెల్ లేదు; స్థానిక EOF వద్ద మూసివేయాలి |

- స్ట్రీమింగ్ స్థానిక ప్రతిస్పందన `ReadableStream`ను నేరుగా వినియోగిస్తుంది; తాత్కాలిక ఫైల్ లేదా సైడ్కార్ సృష్టించబడదు.
- స్ట్రీమ్ను అందుబాటులో ఉంచడానికి ముందు ప్రారంభంలోని గరిష్ఠంగా 256 బైట్లు పరిశీలించబడతాయి. SSE ప్రొవైడర్లు SSE కాని ఎర్రర్లను బఫర్ చేస్తాయి; Grok/LMArena Cloudflare ఛాలెంజ్లను `403`కు మరియు HTML ఇంటర్స్టీషియల్లను `502`కు మ్యాప్ చేస్తాయి.
- స్థానిక అభ్యర్థన కాలపరిమితి ఒక సంపూర్ణ JS హార్డ్ డెడ్లైన్తో ర్యాప్ చేయబడి ఉంటుంది. హ్యాంగ్ సంభవిస్తే, తదుపరి అభ్యర్థన దాన్ని మళ్లీ సృష్టించే ముందు ప్రభావితమైన ప్రొఫైల్/OS/ప్రాక్సీ ట్రాన్స్పోర్ట్ మాత్రమే చెల్లనిదిగా చేసి మూసివేయబడుతుంది.
- ప్రాక్సీ పరిష్కార ప్రాధాన్యత ప్రతి కాల్కు `proxyUrl` → అభ్యర్థన-స్కోప్డ్ ఖాతా/డ్యాష్బోర్డ్ కాంటెక్స్ట్ → `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (చిన్న అక్షరాల రూపాలతో సహా). నేరుగా కనెక్షన్ లీక్ కాకుండా పరిష్కార ఎర్రర్లు ఫెయిల్-క్లోజ్డ్ అవుతాయి. LMArena ఉద్దేశపూర్వకంగా `arena.ai`కు అనుగుణంగా పరిష్కరిస్తుంది.
- `byteResponse`, UTF-8 కరప్షన్ లేకుండా కంటెంట్-టైప్ చేయబడిన `data:` URLను తిరిగి ఇస్తుంది.
- మొత్తం 128 పరిమిత ప్రొఫైల్/OS/ప్రాక్సీ స్లాట్లు సక్రియంగా లేదా మూసివేయబడుతున్న స్థితిలో ఉన్నప్పుడు, ఎర్రర్లు `TlsClientUnavailableError` (ప్యాకేజీ/యాడ్ఆన్ అందుబాటులో లేదు), `TlsClientHangError` (డెడ్లైన్ మించిపోయింది), మరియు `WreqTransportCapacityError` (ఉమ్మడి సెషన్-సామర్థ్య ఎర్రర్ కోడ్)గా ఉంటాయి.

పైన ఉన్న సాధారణ `TlsClient` సెషన్, స్థిరమైన బ్రౌజర్-ఆధారిత కుకీ స్థితి కోసం ప్రత్యేకీకరించబడే ఉంటుంది. రెండు మార్గాలు ఒకే క్యాష్ చేయబడిన wreq మాడ్యూల్ లోడర్ మరియు ప్రాసెస్ లైఫ్సైకిల్ హుక్ను తిరిగి ఉపయోగిస్తాయి; వాటి కుకీ జీవితకాలాలు ఉద్దేశపూర్వకంగా భిన్నంగా ఉన్నందున వాటి పూల్లు వేరుగా ఉంటాయి.

పిన్ చేసిన ప్యాకేజీ ఈ ప్రొఫైల్లకు మద్దతు ఇస్తుంది, కానీ వాస్తవ WAF ఆమోదం స్థానిక కాంట్రాక్ట్ పరీక్షలతో సంబంధం లేకుండా మారవచ్చు. అప్స్ట్రీమ్ బ్రౌజర్తో సమానత్వం ఉందని ప్రకటించే ముందు, స్పష్టంగా అధికారం పొందిన లైవ్ ఖాతాతో ఫింగర్ప్రింట్ మార్పులను ధృవీకరించండి.

## Claude Code స్టెల్త్ బండిల్

`cliCompatMode` ఆన్లో ఉన్నప్పుడు, అవి `claude-cli` ట్రాఫిక్ నుండి వేరు చేసి గుర్తించలేని విధంగా OmniRoute అవుట్గోయింగ్ Claude అభ్యర్థనలను పునర్రూపకల్పన చేస్తుంది. మూడు మాడ్యూల్లు కలిసి పనిచేస్తాయి:

### `claudeCodeFingerprint.ts`

బిల్లింగ్ హెడర్లో పొందుపరిచిన 3-అక్షరాల `cc_version` ఫింగర్ప్రింట్ను గణిస్తుంది:

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (హార్డ్కోడ్ చేయబడింది; అధికారిక క్లయింట్తో సరిపోలుతుంది)
- ఇన్పుట్లు: మొదటి వినియోగదారు సందేశంలోని టెక్స్ట్లో ఇండెక్స్ 4, 7, 20 వద్ద ఉన్న అక్షరాలు + వెర్షన్ స్ట్రింగ్
- అవుట్పుట్: 3-అక్షరాల హెక్స్ ప్రిఫిక్స్

### `claudeCodeCCH.ts` (క్లయింట్ కంటెంట్ హ్యాష్)

అధికారిక Claude Code CLI, Bun/Zig ద్వారా గణించే సర్వర్-సైడ్ సమగ్రత తనిఖీ. OmniRoute దీన్ని `xxhash-wasm`తో తిరిగి అమలు చేస్తుంది:

1. బాడీని `cch=00000;` ప్లేస్హోల్డర్తో సీరియలైజ్ చేయండి
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. సున్నాలతో ప్యాడ్ చేసిన 5-అక్షరాల లోయర్కేస్ హెక్స్
4. `cch=00000;`ను గణించిన టోకెన్తో భర్తీ చేయండి

స్థిరాంకాలు:

- సీడ్: `0x6e52736ac806831e`
- ప్యాటర్న్: `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

అప్స్ట్రీమ్ ఫిల్టర్లు వాటిని grep చేయకుండా ఉండేందుకు, "సున్నితమైన" క్లయింట్ పేర్లలోని మొదటి అక్షరం తర్వాత Unicode **zero-width joiner** (`U+200D`)ను చొప్పిస్తుంది. డిఫాల్ట్ పదాల జాబితా:

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

వర్తించే చోటులు: `system` బ్లాక్లు, అన్ని `messages[].content`, అలాగే `tools[].description` / `tools[].function.description`. ఆపరేటర్ `setSensitiveWords()` ద్వారా దీన్ని ఓవర్రైడ్ చేయవచ్చు.

### `claudeCodeCompatible.ts` — `anthropic-compatible-cc-*` ప్రొవైడర్లు

"నిజమైన Claude Code" ట్రాఫిక్ను మాత్రమే అంగీకరించే థర్డ్-పార్టీ Anthropic రిలేల కోసం:

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.258 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- డిఫాల్ట్గా `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"`
- ప్రతి కనెక్షన్కు ఉన్న "Enable redact-thinking beta" టాగుల్, ఒక CC Compatible అప్స్ట్రీమ్కు ప్రత్యేకంగా రీడాక్ట్ చేసిన థింకింగ్ స్ట్రీమ్లు అవసరమైనప్పుడు `redact-thinking-2026-02-12`ను జోడిస్తుంది
- ప్రతి కనెక్షన్కు ఉన్న "Enable summarized thinking display" టాగుల్ `providerSpecificData.requestDefaults.summarizeThinking`ను నిల్వ చేస్తుంది మరియు ఇప్పటికే డిస్ప్లే మోడ్ సెట్ చేయని CC Compatible థింకింగ్ అభ్యర్థనలకు `display: "summarized"`ను జోడిస్తుంది
- `CONTEXT_1M_BETA_HEADER = "context-1m-2025-08-07"` (Opus/Sonnet 4.x కుటుంబం)
- డిఫాల్ట్ పాత్: `/v1/messages?beta=true`

అదే బండిల్లోని అనుబంధ మాడ్యూల్లు:

- `claudeCodeConstraints.ts` — టెంపరేచర్ + cache-control నియమాలు
- `claudeCodeToolRemapper.ts` — టూల్ పేరు రీమ్యాపింగ్
- `claudeCodeExtraRemap.ts` — అదనపు పేలోడ్ సాధారణీకరణ

## Antigravity స్టెల్త్

Antigravity అభ్యర్థనలు కాలర్ టెక్స్ట్ను బైట్-ఫర్-బైట్ యథాతథంగా ఉంచుతాయి. ఒక IDE క్లయింట్ను అనుకరించడానికి OmniRoute ప్రాంప్ట్లలో zero-width అక్షరాలను చొప్పించదు లేదా టూల్ల పేర్లు మార్చదు/వాటిని ఇంజెక్ట్ చేయదు.

### `antigravityHeaderScrub.ts`

ఫార్వర్డ్ చేసే ముందు Stainless SDK మార్కర్లను (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`) తొలగిస్తుంది.

### ⚠️ ప్రమాదం: `ANTIGRAVITY_CREDITS=always` (ఖాతా నిషేధానికి ప్రధాన ప్రమాద స్థానం)

Google ఉచిత-స్థాయి కోటా అభ్యర్థనలను నియంత్రించనివ్వడానికి బదులుగా, `ANTIGRAVITY_CREDITS=always` (`open-sse/executors/antigravity.ts` ద్వారా వినియోగించబడుతుంది) **ప్రతి** అభ్యర్థనను Antigravity AI Credit Overages (చెల్లింపు Google క్రెడిట్లు) ద్వారా రూట్ చేస్తుంది. ఇది ఒక ఫీచర్గా డాక్యుమెంట్ చేయబడింది, కానీ ఇది **మేము చూసే ToS ఉల్లంఘన నివేదికల్లో అత్యంత సాధారణమైన ఏకైక కారణం** — `=always`తో కొన్ని గంటలు రన్ చేసిన తర్వాత అనేక Google Ultra ఖాతాలు `403 / "service disabled for ToS violation" / insufficient_quota`తో నిషేధించబడ్డాయి.

అప్స్ట్రీమ్ అమలు **Google వైపున** జరుగుతుంది, దీన్ని OmniRoute ఏ విధంగానూ నిరోధించలేదు. ఎన్విరాన్మెంట్ వేరియబుల్ పేరు మరియు ప్రస్తుత డాక్యుమెంటేషన్ దీన్ని ఆన్ చేయడం సురక్షితమైన సెట్టింగ్లా అనిపించేలా చేస్తాయి; కానీ అది సురక్షితం కాదు.

**ఇది ఉచిత-స్థాయి-మాత్రమే వినియోగం కంటే దుర్వినియోగ గుర్తింపును మరింత తీవ్రంగా ఎందుకు ప్రేరేపిస్తుంది:**

- ఒకే Google ఖాతాలో నిరంతర ఆటోమేటెడ్ ఖర్చు, ఉచిత-స్థాయి కోటాను చేరుకొని ఆగిపోవడం కంటే భిన్నంగా ఫ్లాగ్ చేయబడుతుంది.
- క్రెడిట్ ఓవరేజ్లకు రేట్ పరిమితి లేదు, కాబట్టి తప్పుగా కాన్ఫిగర్ చేసిన క్లయింట్ నిమిషాల్లోనే అనేక వందల USD ఖర్చు చేసి, API-key పునర్విక్రయం లేదా బాట్ ట్రాఫిక్లా కనిపించవచ్చు.
- ఒకే బాహ్య IP నుంచి సమాంతరంగా ఓవరేజ్ క్రెడిట్లను వినియోగించే అనేక OmniRoute వినియోగదారులు ఈ సంకేతాన్ని మరింత బలపరుస్తారు.

**సిఫార్సు చేసిన విధానం:**

1. ఆపరేటర్ చెల్లింపు-క్రెడిట్ మరియు ఖాతా-అమలు ప్రమాదాన్ని స్పష్టంగా అంగీకరిస్తే తప్ప, డిఫాల్ట్ `ANTIGRAVITY_CREDITS=off`ను అలాగే ఉంచండి. `retry` మొదట సాధారణ అభ్యర్థనను పంపి, అర్హతగల కోటా 429 వచ్చిన తర్వాత గరిష్ఠంగా ఒక్కసారి మాత్రమే క్రెడిట్లను ఇంజెక్ట్ చేస్తుంది; `always` మొదటి అభ్యర్థనలోనే క్రెడిట్లను ఇంజెక్ట్ చేస్తుంది.
2. ఒకే Antigravity ఖాతాను పూర్తిగా వినియోగించడానికి బదులుగా, **Auto-Combo ద్వారా ప్రొవైడర్ల మధ్య లోడ్ను విస్తరించండి** (`model: "auto"` లేదా `kr/glm/etc`-combo).
3. Antigravity ప్రొవైడర్ ఎడిట్ పేజీలో **ప్రతి కనెక్షన్కు RPM పరిమితులను సెట్ చేయండి** (Dashboard → Providers → Antigravity → కనెక్షన్ → రేట్ పరిమితి). నిరంతర వినియోగానికి 30–60 RPM సమర్థించదగిన గరిష్ఠ పరిమితి.
4. **స్థిరమైన, ఆపరేటర్-నియంత్రిత అప్స్ట్రీమ్ నెట్వర్కింగ్ను ఉపయోగించండి** మరియు సంబంధం లేని వినియోగదారులు లేదా వర్క్లోడ్ల మధ్య ఒకే ఖాతాను పంచుకోవడం నివారించండి.
5. **నిషేధించబడితే**: Google పంపిన ఖచ్చితమైన `quota_exceeded` / `service disabled` ప్రతిస్పందన బాడీతో `support.google.com` → "Restore Workspace/Account access" ద్వారా అప్పీల్ చేయండి. పునరుద్ధరణకు హామీ లేదు.

ఎన్విరాన్మెంట్ రిఫరెన్స్ ప్రతి క్రెడిట్స్ మోడ్కు సంబంధించిన ఖాతా మరియు ఖర్చు ప్రభావాలను డాక్యుమెంట్ చేస్తుంది.

సంబంధిత స్థానాలు:

- `open-sse/executors/antigravity.ts` — `process.env.ANTIGRAVITY_CREDITS`ను చదువుతుంది
- `src/lib/oauth/providers/antigravity.ts` — క్రెడెన్షియల్ ప్లంబింగ్

## CLI ఫింగర్ప్రింట్ రిజిస్ట్రీ — `open-sse/config/cliFingerprints.ts`

అధికారిక CLIల mitmproxy ట్రేస్ల నుండి సంగ్రహించిన **ఖచ్చితమైన** హెడర్ క్రమాన్ని మరియు JSON బాడీ ఫీల్డ్ క్రమాన్ని స్థిరపరిచే ప్రతి-ప్రొవైడర్ పట్టిక. ప్రస్తుతం నమోదు చేసినవి: `codex`, `claude`, అలాగే `antigravity` మరియు `github` కోసం `providerHeaderProfiles.ts`లో రన్టైమ్ నుండి ఉత్పన్నమైన ప్రొఫైల్లు.

```ts
interface CliFingerprint {
  headerOrder: string[]; // కేస్-సెన్సిటివ్
  bodyFieldOrder: string[]; // అగ్ర-స్థాయి JSON కీలు
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

env ద్వారా ప్రతి ప్రొవైడర్కు టాగుల్ చేయండి (క్రింద చూడండి). నిలిపివేసినప్పుడు, హెడర్లు/బాడీ కీలు Node/JSON అందించిన క్రమంలోనే కనిపిస్తాయి — సులభంగా ఫింగర్ప్రింట్ చేయవచ్చు.

## MITM ప్రాక్సీ (Antigravity, Linux/macOS/Windows)

`OPENAI_BASE_URL` ద్వారా బైనరీలను రీడైరెక్ట్ చేయలేని CLIల కోసం, OmniRoute స్థానిక TLS-టెర్మినేటింగ్ ప్రాక్సీని అమలు చేస్తుంది. ఎండ్పాయింట్లు `src/app/api/cli-tools/antigravity-mitm/` కింద ఉంటాయి.

| పద్ధతి | ఎండ్పాయింట్                             | ఉద్దేశ్యం                                              |
| ------ | --------------------------------------- | ------------------------------------------------------ |
| GET    | `/api/cli-tools/antigravity-mitm`       | స్థితి — అమలవుతోందా, pid, dnsConfigured, certExists    |
| POST   | `/api/cli-tools/antigravity-mitm`       | MITMను ప్రారంభించండి (`apiKey` + `sudoPassword` అవసరం) |
| DELETE | `/api/cli-tools/antigravity-mitm`       | MITMను ఆపండి                                           |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | మోడల్ అలియాస్లను జాబితా చేయండి                         |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | ఒక సాధనం కోసం మోడల్ అలియాస్లను సేవ్ చేయండి             |

ఇంటర్సెప్ట్ చేయబడే లక్ష్య హోస్ట్: **`daily-cloudcode-pa.googleapis.com`** (Antigravity యొక్క అప్స్ట్రీమ్).

### ప్రారంభ క్రమం (`src/mitm/manager.ts::startMitm`)

1. `selfsigned` ద్వారా స్వీయ-సంతకం చేసిన సర్టిఫికేట్ను రూపొందించండి (RSA-2048, SHA-256, 1y) — `cert/generate.ts`
2. సిస్టమ్ ట్రస్ట్ స్టోర్లో సర్టిఫికేట్ను ఇన్స్టాల్ చేయండి — `cert/install.ts`
3. `127.0.0.1 daily-cloudcode-pa.googleapis.com` hosts ఎంట్రీని జోడించండి — `dns/dnsConfig.ts`
4. `ROUTER_API_KEY` + `MITM_LOCAL_PORT` (డిఫాల్ట్ `443`)తో `src/mitm/server.cjs`ను ప్రారంభించండి
5. PIDను `<DATA_DIR>/mitm/.mitm.pid`లో నిల్వ చేయండి

### Linux డైనమిక్ ట్రస్ట్-స్టోర్ గుర్తింపు — `cert/install.ts`

`getLinuxCertConfig()` ప్రాధాన్యత జాబితాను పరిశీలించి, ఉనికిలో ఉన్న మొదటి డైరెక్టరీని ఎంచుకుంటుంది:

| డిస్ట్రో కుటుంబం         | డైరెక్టరీ                                   | నవీకరణ కమాండ్            |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

సర్టిఫికేట్ ఫైల్ పేరు: `omniroute-mitm.crt`. `getCertFingerprint()` ద్వారా ఫింగర్ప్రింట్ సరిపోలిక (DER యొక్క SHA-1).

అదనంగా, `certutil` అందుబాటులో ఉన్నప్పుడు `updateNssDatabases()` ప్రతి-వినియోగదారు NSS DBలలో ఇన్స్టాల్ చేస్తుంది: `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, అన్ని Firefox ప్రొఫైల్లు (snapతో సహా), **`OmniRoute MITM Root CA`** అనే ముద్దుపేరు కింద.

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** ఎలివేటెడ్ PowerShell → `certutil -addstore Root`

### ప్రామాణీకరణ

అన్ని MITM ఎండ్పాయింట్లకు నిర్వహణ ప్రామాణీకరణ (`requireCliToolsAuth`) అవసరం. sudo పాస్వర్డ్ మాడ్యూల్ స్కోప్లో క్యాష్ చేయబడుతుంది (`globalThis`లో ఎప్పుడూ కాదు) మరియు `stopMitm()` సమయంలో క్లియర్ చేయబడుతుంది.

Cursor నుండి వచ్చే అభ్యర్థనలోని `User-Agent: Cursor/X.Y.Z`, Claude అప్స్ట్రీమ్కు లీక్ కాకుండా ఫార్వర్డ్ చేయడానికి ముందు OmniRoute ఇన్బౌండ్ క్లయింట్ హెడర్లను తొలగిస్తుంది. Zod స్కీమాలు మరియు యూనిట్ టెస్ట్లతో సమకాలీకరించి ఉంచే డినైలిస్ట్ కోసం `src/shared/constants/upstreamHeaders.ts` చూడండి.

## ప్రొవైడర్ మార్చినప్పుడు ఫింగర్ప్రింట్లను నవీకరించడం

1. `mitmproxy`తో అధికారిక CLI ట్రాఫిక్ను క్యాప్చర్ చేయండి (TLS ఇంటర్సెప్షన్ + డంప్)
2. JA3/JA4 మరియు హెడర్ల యథాతథ క్రమాన్ని వెలికితీయండి
3. సంబంధిత `CLI_FINGERPRINTS[...]` ఎంట్రీని నవీకరించండి
4. `.env.example`లో సరిపోలే `*_USER_AGENT` డిఫాల్ట్ను పెంచండి
5. TLS హ్యాండ్షేక్ కూడా మారితే, సంబంధిత ప్రొవైడర్ ర్యాపర్ లేదా wreq-js `browser:` ఎంపికను నవీకరించండి
6. ప్రొవైడర్కు నిర్దిష్టమైన TLS టెస్ట్లను మరియు లైవ్ ప్రొవైడర్పై మాన్యువల్ కానరీని అమలు చేయండి
7. ప్యాచ్ విడుదలలో షిప్ చేయండి; `CHANGELOG.md`లో డాక్యుమెంట్ చేయండి
