OmniRoute, ప్లాట్ఫారమ్తో పరస్పర చర్య చేసినందుకు వినియోగదారులకు రివార్డ్లను అందించే లోకల్-ఫస్ట్ గేమిఫికేషన్ లేయర్ను కలిగి ఉంది — అభ్యర్థనలు చేయడం, ప్రొవైడర్లను మార్చడం, కాంబోలను సృష్టించడం, టోకెన్లను పంచుకోవడం మరియు కమ్యూనిటీకి సహకరించడం వంటివి ఇందులో ఉన్నాయి. స్థితి మొత్తం SQLiteలో ఉంటుంది; కమ్యూనిటీ సర్వర్లతో ఫెడరేషన్ ఐచ్ఛికం మరియు పుష్-ఆధారితమైనది.

ఈ సిస్టమ్ **హాట్ పాత్లో జీరో-లేటెన్సీ** ఉండేలా రూపొందించబడింది — గేమిఫికేషన్ ఈవెంట్లు అభ్యర్థన పైప్లైన్ నుండి ఫైర్-అండ్-ఫర్గెట్ పద్ధతిలో పంపబడతాయి మరియు LLM ప్రతిస్పందనను ఎప్పుడూ నిరోధించవు.

## అవలోకనం

### ఉద్దేశ్యం

కనిపించే పురోగతి (XP, లెవెల్లు, బ్యాడ్జ్లు), సామాజిక ప్రమాణం (లీడర్బోర్డ్లు) మరియు ఆర్థిక ప్రోత్సాహకాలు (టోకెన్ షేరింగ్, ఆహ్వాన రివార్డ్లు) అందించడం ద్వారా వినియోగదారుల భాగస్వామ్యాన్ని మరియు నిలుపుదలను పెంచడం.

### పరిధి

| ఫీచర్              | వివరణ                                                                    |
| ------------------ | ------------------------------------------------------------------------ |
| XP & లెవెల్లు      | ప్రతి చర్యకు XP సంపాదించండి; పాలినోమియల్ కర్వ్ ప్రకారం లెవెల్ పెంచుకోండి |
| బ్యాడ్జ్లు         | 4 అరుదుదన స్థాయిలతో 5 వర్గాలలో 20+ విజయాలు                               |
| స్ట్రీక్లు         | ప్రస్తుత/అత్యధిక స్ట్రీక్తో రోజువారీ సక్రియ వినియోగ ట్రాకింగ్            |
| లీడర్బోర్డ్లు      | గ్లోబల్, వారపు, నెలవారీ, టోకెన్-షేరింగ్ మరియు కాంట్రిబ్యూషన్ స్కోప్లు    |
| టోకెన్ షేరింగ్     | డబుల్-ఎంట్రీ లెడ్జర్ ద్వారా వినియోగదారుల మధ్య క్రెడిట్లను బదిలీ చేయడం    |
| ఆహ్వానం & రీడీమ్   | SHA-256 హ్యాష్ చేసిన స్టోరేజ్తో రెఫరల్ కోడ్లు                            |
| కమ్యూనిటీ సర్వర్లు | బాహ్య OmniRoute ఇన్స్టాన్స్లతో ఫెడరేట్ అవడం                              |
| యాంటీ-చీట్         | సర్వర్-సైడ్ స్కోరింగ్, రేట్ లిమిటింగ్, z-score అసాధారణత గుర్తింపు        |

### రూపకల్పన సూత్రాలు

1. **లోకల్-ఫస్ట్** — స్థితి మొత్తం SQLiteలో ఉంటుంది, బాహ్య సేవలు అవసరం లేదు.
2. **నాన్-బ్లాకింగ్** — ఈవెంట్లు ఫైర్-అండ్-ఫర్గెట్ పద్ధతిలో ఉంటాయి; LLM ప్రతిస్పందన పాత్ గేమిఫికేషన్ లాజిక్ కారణంగా
   ఎప్పుడూ ఆలస్యం కాదు.
3. **సర్వర్-అథారిటేటివ్** — XP సర్వర్-సైడ్లో మాత్రమే లెక్కించబడుతుంది; క్లయింట్లు
   స్కోర్లను కృత్రిమంగా పెంచలేరు.
4. **గోప్యతను గౌరవించేది** — లీడర్బోర్డ్లో పాల్గొనడం ఐచ్ఛికం; వినియోగదారులు
   తమ ప్రొఫైల్ను దాచవచ్చు.
5. **ఫెడరేషన్కు సిద్ధం** — కమ్యూనిటీ సర్వర్లు సంతకం చేసిన API ద్వారా స్కోర్లను పుష్ చేయగలవు;
   సింక్ అనేది ఓవర్రైట్ పద్ధతిలో జరుగుతుంది, అదనంగా కలపడం కాదు.

## ఆర్కిటెక్చర్

### ఉన్నత-స్థాయి ప్రవాహం

```
క్లయింట్ అభ్యర్థన
  → /v1/chat/completions
    → handleChatCore()                      [open-sse/handlers/chatCore.ts]
      → ... (ఇప్పటికే ఉన్న పైప్లైన్) ...
      → అప్స్ట్రీమ్ ప్రతిస్పందన క్లయింట్కు పంపబడుతుంది
      → setImmediate (ఫైర్-అండ్-ఫర్గెట్):
        → emitGamificationEvent()           [src/lib/gamification/events.ts]
          → awardXp()                       [src/lib/gamification/xp.ts]
          → updateStreak()                  [src/lib/gamification/streaks.ts]
          → evaluateBadges()                [src/lib/gamification/badges.ts]
          → updateLeaderboard()             [src/lib/gamification/leaderboard.ts]
          → checkAnomalies()                [src/lib/gamification/antiCheat.ts]
```

ఈవెంట్ ఎమిటర్ ఏకైక ఇంటిగ్రేషన్ పాయింట్. ప్రతిస్పందన పంపబడిన తర్వాత `chatCore.ts`,
`emitGamificationEvent()`ను కాల్ చేస్తుంది; ఈవెంట్ మాడ్యూల్ దానిని
XP, స్ట్రీక్, బ్యాడ్జ్, లీడర్బోర్డ్ మరియు యాంటీ-చీట్ సబ్సిస్టమ్లకు పంపిణీ చేస్తుంది.

```
xp_for_level(n) = floor(100 * n^1.5)
```

### ప్రదాన ప్రక్రియ

```typescript
export async function awardXp(
  apiKeyId: string,
  action: XpAction,
  metadata?: Record<string, unknown>
): Promise<{ xp: number; level: number; title: string; levelUp: boolean }>;
```

1. XP మొత్తాన్ని పొందడానికి `XP_REWARDS[action]`ను చూడండి.
2. `checkRateLimit()` ద్వారా పంపండి (మోస నిరోధం: ఒక్కో కీకి నిమిషానికి గరిష్ఠంగా 1000 XP).
3. ఒక ట్రాన్సాక్షన్ను తెరవండి:
   - ప్రస్తుత `user_levels` వరుసను చదవండి.
   - XPని జోడించండి; `levelFromXp(totalXp)` ద్వారా లెవల్ను మళ్లీ లెక్కించండి.
   - లెవల్ మారితే, `levelUp = true`గా సెట్ చేయండి.
   - `user_levels` వరుసను అప్డేట్ చేయండి.
   - `xp_audit_log`లో చేర్చండి.
4. ఫలితాన్ని తిరిగి ఇవ్వండి. కాలర్ నోటిఫికేషన్లను నిర్వహిస్తుంది.

### సహాయక ఫంక్షన్: `levelFromXp(totalXp)`

సంచిత XP `totalXp`ను మించే వరకు `xp_for_level(n)`ను కూడుతూ, 1..100 లెవల్లపై పునరావృతం చేస్తుంది. థ్రెషోల్డ్ను చేరుకున్న అత్యధిక లెవల్ను తిరిగి ఇస్తుంది.
లెవల్లు 100 వద్ద పరిమితం అవుతాయి కాబట్టి ఇది O(100) — ఆమోదయోగ్యమైనది.

### మూల్యాంకన ప్రక్రియ

```
emitGamificationEvent(event)
  → evaluateBadges(apiKeyId, event)
    → getBadgeDefinitions()           # అన్ని నిర్వచనాలు
    → getUserBadges(apiKeyId)         # ఇప్పటికే సంపాదించినవి (దాటవేయండి)
    → సంపాదించని ప్రతి బ్యాడ్జ్ కోసం:
       → matchesCriteria(badge, event, userState)
       → సరిపోలితే: awardBadge(apiKeyId, badgeId)
         → నోటిఫికేషన్ పేలోడ్ను తిరిగి ఇవ్వండి
```

మూల్యాంకనం **ఈవెంట్ ఆధారితమైనది** — ఇది ప్రతి గేమిఫికేషన్ ఈవెంట్ తర్వాత రన్ అవుతుంది, కానీ ఈవెంట్ చర్యతో `criteria.type` సరిపోలే బ్యాడ్జ్లను మాత్రమే తనిఖీ చేస్తుంది. ఇది చాలా ఈవెంట్లకు మూల్యాంకనాన్ని వేగంగా (< 5ms) ఉంచుతుంది.

## స్ట్రీక్ ట్రాకర్

**ఫైల్:** `src/lib/gamification/streaks.ts`

### డేటా మోడల్

స్ట్రీక్లు `key_value` పట్టికలో (భాగస్వామ్య యుటిలిటీ పట్టిక), నేమ్స్పేస్ చేయబడిన కీల కింద నిల్వ చేయబడతాయి:

| కీ                            | విలువ                            | వివరణ                |
| ----------------------------- | -------------------------------- | -------------------- |
| `gamification:streak:{keyId}` | `{current},{longest},{lastDate}` | సక్రియ స్ట్రీక్ డేటా |

### లాజిక్

```typescript
export async function updateStreak(
  apiKeyId: string
): Promise<{ current: number; longest: number; milestone: boolean }>;
```

1. `key_value` నుండి స్ట్రీక్ రికార్డును చదవండి.
2. `{current}`, `{longest}`, `{lastDate}` (ISO తేదీ స్ట్రింగ్)ను పార్స్ చేయండి.
3. `lastDate === today` అయితే — ఎలాంటి మార్పూ లేదు (ఈరోజు ఇప్పటికే లెక్కించబడింది).
4. `lastDate === yesterday` అయితే — `current`ను పెంచండి; అవసరమైతే `longest`ను నవీకరించండి.
5. `lastDate < yesterday` అయితే — `current = 1`కు రీసెట్ చేయండి (స్ట్రీక్ తెగిపోయింది).
6. నవీకరించిన రికార్డును వ్రాయండి.
7. మైలురాళ్లను తనిఖీ చేయండి: 7, 14, 30, 60, 90, 180, 365 రోజులు. ఏదైనా దాటితే,
   `milestone = true`గా సెట్ చేయండి (కాలర్ XPని ప్రదానం చేసి బ్యాడ్జ్లను తనిఖీ చేస్తుంది).

### ప్రత్యేక సందర్భాలు

- **టైమ్జోన్**: స్ట్రీక్లు UTC తేదీలను ఉపయోగిస్తాయి (`new Date().toISOString().slice(0, 10)`).
  ఇది ఉద్దేశపూర్వకమే — ఒకే ప్రామాణిక టైమ్జోన్, టైమ్జోన్ల మధ్య మారడం ద్వారా
  వ్యవస్థను దుర్వినియోగం చేయడాన్ని నివారిస్తుంది.
- **కొత్త వినియోగదారులు**: స్ట్రీక్ రికార్డు ఉండదు; మొదటి అభ్యర్థన దానిని
  `current=1, longest=1, lastDate=today`తో సృష్టిస్తుంది.
- **రోజుకు అనేక అభ్యర్థనలు**: UTC రోజులోని మొదటి అభ్యర్థన మాత్రమే
  స్ట్రీక్ను పెంచుతుంది.

### ర్యాంక్ గణన

ర్యాంక్లు నిల్వ చేయబడవు, వాటిని **చదివే సమయంలో గణిస్తారు**. ఇది కాలం చెల్లిన ర్యాంక్ డేటాను నివారించి,
కాలానుగుణ ర్యాంక్ పునఃగణన జాబ్ల అవసరాన్ని తొలగిస్తుంది.

```typescript
export async function getLeaderboard(
  scope: LeaderboardScope,
  period: string,
  limit: number,
  offset: number
): Promise<{ entries: LeaderboardEntry[]; total: number }>;
```

క్వెరీ నమూనా:

```sql
SELECT api_key_id, score,
       RANK() OVER (ORDER BY score DESC) as rank
FROM leaderboard
WHERE scope = ? AND period = ?
ORDER BY score DESC
LIMIT ? OFFSET ?
```

## టోకెన్ భాగస్వామ్యం

**ఫైల్:** `src/lib/gamification/sharing.ts`

### డబుల్-ఎంట్రీ లెడ్జర్

ప్రతి బదిలీ `token_ledger`లో రెండు వరుసలను సృష్టిస్తుంది:

| వరుస     | `from_key_id` | `to_key_id` | `amount` |
| -------- | ------------- | ----------- | -------- |
| డెబిట్   | పంపినవారు     | స్వీకర్త    | +మొత్తం  |
| క్రెడిట్ | స్వీకర్త      | పంపినవారు   | -మొత్తం  |

ఆగండి — అనుసరించే పద్ధతి ఇది:

| వరుస        | `from_key_id` | `to_key_id` | `amount` | అర్థం                               |
| ----------- | ------------- | ----------- | -------- | ----------------------------------- |
| పంపడం       | పంపినవారు     | స్వీకర్త    | +మొత్తం  | పంపినవారి నుండి బయటకు వెళ్లే మొత్తం |
| స్వీకరించడం | స్వీకర్త      | పంపినవారు   | +మొత్తం  | స్వీకర్తకు లోపలికి వచ్చే మొత్తం     |

బ్యాలెన్స్ ఇలా లెక్కించబడుతుంది:

```sql
SELECT
  COALESCE(SUM(CASE WHEN to_key_id = ? THEN amount ELSE 0 END), 0)
  - COALESCE(SUM(CASE WHEN from_key_id = ? THEN amount ELSE 0 END), 0)
  AS balance
FROM token_ledger
WHERE from_key_id = ? OR to_key_id = ?
```

### బదిలీ ప్రక్రియ

```typescript
export async function transferTokens(
  fromKeyId: string,
  toKeyId: string,
  amount: number,
  idempotencyKey: string
): Promise<{ success: boolean; balance: number }>;
```

1. **ధ్రువీకరణ**: `amount > 0`, `fromKeyId !== toKeyId`.
2. **ఐడెంపొటెన్సీ**: లెడ్జర్లో `idempotency_key` ఇప్పటికే ఉందో లేదో తనిఖీ చేయండి.
   ఉంటే, క్యాష్ చేసిన ఫలితాన్ని తిరిగి ఇవ్వండి.
3. **ట్రాన్సాక్షన్** (ఒకే SQLite ట్రాన్సాక్షన్):
   a. పంపినవారి బ్యాలెన్స్ను లెక్కించండి.
   b. `balance < amount` అయితే, రద్దు చేయండి (తగినంత నిధులు లేవు).
   c. పంపే వరుసను చొప్పించండి (`from=sender,`ను తిరిగి ఇవ్వండి.

### రేట్ పరిమితి

- ప్రతి API కీకి నిమిషానికి గరిష్ఠంగా 10 బదిలీలు.
- ఒక్క బదిలీకి గరిష్ఠంగా 10,000 టోకెన్లు.
- ప్రతి API కీకి రోజుకు గరిష్ఠంగా 100,000 టోకెన్ల బదిలీ.

## ఆహ్వాన & రిడీమ్ టోకెన్లు

**ఫైల్:** `src/lib/gamification/invites.ts`

### కోడ్ ఫార్మాట్

- **కోడ్**: 8-అక్షరాల ఆల్ఫాన్యూమరిక్ కోడ్ (ఉదా., `A3K9-X7M2`), మనుషులు సులభంగా చదవగలిగేది,
  వినియోగదారుకు ప్రదర్శించబడుతుంది.
- **టోకెన్**: 32-బైట్ యాదృచ్ఛిక టోకెన్, SHA-256 హ్యాష్గా నిల్వ చేయబడుతుంది.
  ప్రోగ్రామాటిక్ రిడెంప్షన్ కోసం ఉపయోగించబడుతుంది (ఉదా., URL లింకులు).

### నిల్వ

| కాలమ్        | విలువ                                      |
| ------------ | ------------------------------------------ |
| `code`       | `A3K9X7M2` (ప్రత్యేకం, ఇండెక్స్ చేయబడినది) |
| `token_hash` | SHA-256(raw_token)                         |

ముడి టోకెన్ సృష్టించే సమయంలో సరిగ్గా ఒక్కసారి మాత్రమే వినియోగదారుకు తిరిగి ఇవ్వబడుతుంది. OmniRoute
దాన్ని మళ్లీ ఎప్పుడూ నిల్వ చేయదు లేదా ప్రదర్శించదు — హ్యాష్ మాత్రమే కొనసాగుతుంది.

### స్వీయ-రిఫరల్ నివారణ

ఒక వినియోగదారు కోడ్ను రిడీమ్ చేసినప్పుడు, సిస్టమ్ వీటిని తనిఖీ చేస్తుంది:

1. కోడ్ వేరే `api_key_id`కు చెందినది.
2. రిడీమ్ చేస్తున్న వినియోగదారు అదే రిఫరర్ నుండి ఇంతకు ముందు ఏ కోడ్నూ
   రిడీమ్ చేయలేదు (`invite_tokens` + రిడెంప్షన్ లాగ్పై జాయిన్ చేస్తుంది).

ఈ తనిఖీలలో ఏదైనా విఫలమైతే, స్పష్టమైన దోష సందేశంతో రిడెంప్షన్ తిరస్కరించబడుతుంది.

- డిఫాల్ట్ `max_uses`: 10 (సృష్టించే సమయంలో కాన్ఫిగర్ చేయవచ్చు).
- డిఫాల్ట్ `expires_at`: సృష్టించిన తేదీ నుండి 30 రోజులు.
- గడువు ముగిసిన లేదా వినియోగ పరిమితి పూర్తయిన కోడ్లు HTTP 410 Goneను తిరిగి ఇస్తాయి.

## కమ్యూనిటీ సర్వర్ ఫెడరేషన్

**ఫైల్:** `src/lib/gamification/servers.ts`

### కనెక్ట్ చేయడం

రిమోట్ సర్వర్ జారీ చేసిన ఆహ్వాన టోకెన్ ద్వారా కమ్యూనిటీ సర్వర్ నమోదు చేయబడుతుంది. లోకల్ ఇన్స్టాన్స్:

1. ఆహ్వాన టోకెన్ను స్వీకరిస్తుంది (ఉదా., డ్యాష్బోర్డ్లో పేస్ట్ చేసినది).
2. టోకెన్ను ధృవీకరించి, ప్రస్తుత లీడర్బోర్డ్ను పొందడానికి రిమోట్ సర్వర్లోని `POST /api/gamification/federation/leaderboard`ను కాల్ చేస్తుంది.
3. సర్వర్ రికార్డును `status: connected`తో నిల్వ చేస్తుంది.

### సింక్ మోడల్

ఫెడరేషన్ **ఓవర్రైట్ సింక్**ను ఉపయోగిస్తుంది, అడిటివ్ సింక్ను కాదు:

```
లోకల్ ఇన్స్టాన్స్                కమ్యూనిటీ సర్వర్
     │                              │
     ├── స్కోర్ను పుష్ చేయి ─────►│  POST /federation/score
     │   { api_key_id, score }      │  (సర్వర్ టోకెన్ హాష్ను ధృవీకరిస్తుంది)
     │                              │
     ├── లీడర్బోర్డ్ను పుల్ చేయి ►│  GET /federation/leaderboard
     │◄── అగ్ర-N ఎంట్రీలు ─────────┤  (లోకల్ క్యాష్ను ఓవర్రైట్ చేస్తుంది)
     │                              │
     └── హెల్త్ చెక్ ──────────────►│  GET /federation/health
         (ప్రతి 60sకు, టైమ్అవుట్ 5s)│
```

### ప్రమాణీకరణ

ఫెడరేషన్ అభ్యర్థనల్లో ఇవి ఉంటాయి:

```
Authorization: Bearer <raw_token>
X-Federation-Version: 1
```

రిమోట్ సర్వర్ టోకెన్ను హాష్ చేసి, సరిపోలే `community_servers` రోను వెతుకుతుంది. దీని వల్ల నిల్వ చేసిన హాష్ను ప్రసారం చేయాల్సిన అవసరం ఉండదు.

### హెల్త్ మానిటరింగ్

ప్రతి సర్వర్ రికార్డు వీటిని ట్రాక్ చేస్తుంది:

| ఫీల్డ్      | వివరణ                                          |
| ----------- | ---------------------------------------------- |
| `status`    | `connected`, `degraded`, `unreachable`         |
| `last_sync` | చివరిగా విజయవంతమైన సింక్ యొక్క ISO టైమ్స్టాంప్ |
| `failures`  | వరుసగా విఫలమైన హెల్త్ చెక్లు                   |

వరుసగా 5 వైఫల్యాల తర్వాత, స్థితి `unreachable`కు మారుతుంది మరియు మాన్యువల్ హెల్త్ చెక్ విజయవంతమయ్యే వరకు సింక్ పాజ్ చేయబడుతుంది.

## మోస నిరోధం

**ఫైల్:** `src/lib/gamification/antiCheat.ts`

### సర్వర్-సైడ్ స్కోరింగ్

అన్ని XP లెక్కింపులు `src/lib/gamification/xp.ts`లో జరుగుతాయి. క్లయింట్లు ఎప్పుడూ స్కోర్ను సమర్పించరు — వారు చర్యలను సమర్పిస్తారు, సర్వర్ XPని లెక్కిస్తుంది. `leaderboard.score` కాలమ్ను సర్వర్-సైడ్ కోడ్ మాత్రమే రాయగలదు.

### రేట్ లిమిటింగ్

| పరిమితి                   | విలువ   | పరిధి          |
| ------------------------- | ------- | -------------- |
| నిమిషానికి గరిష్ఠ XP      | 1,000   | ప్రతి API కీకి |
| నిమిషానికి గరిష్ఠ బదిలీలు | 10      | ప్రతి API కీకి |
| గరిష్ఠ బదిలీ మొత్తం       | 10,000  | ప్రతి బదిలీకి  |
| గరిష్ఠ రోజువారీ బదిలీలు   | 100,000 | ప్రతి API కీకి |

రేట్ లిమిట్లు ఇన్-మెమరీ స్లైడింగ్ విండోను ఉపయోగిస్తాయి (`open-sse/services/`లోని `RateLimitManager` మాదిరిగానే). ప్రాసెస్ రీస్టార్ట్ అయితే SQLite-ఆధారిత కౌంటర్లను ప్రత్యామ్నాయంగా ఉపయోగిస్తుంది.

### Z-స్కోర్ అసాధారణత గుర్తింపు

ప్రతి API కీ కోసం, గంటకు సంపాదించిన XP యొక్క రోలింగ్ 7-రోజుల విండోను సిస్టమ్ నిర్వహిస్తుంది. ప్రతి XP ప్రదానం సమయంలో:

1. యూజర్ యొక్క ప్రస్తుత గంటవారీ XP రేటును లెక్కించండి.
2. పాప్యులేషన్ సగటు మరియు ప్రామాణిక విచలనాన్ని లెక్కించండి.
3. `z = (user_rate - mean) / stddev`ను లెక్కించండి.
4. `z > 3.0` (3 ప్రామాణిక విచలనాలు) అయితే, దాన్ని అసాధారణతగా ఫ్లాగ్ చేయండి.

అసాధారణతలు `action = 'anomaly_detected'`తో `xp_audit_log`లో లాగ్ చేయబడతాయి మరియు అడ్మిన్ డ్యాష్బోర్డ్లో చూపబడతాయి.

### ఆడిట్ ట్రైల్

ప్రతి XP ప్రదానం, బదిలీ, బ్యాడ్జ్ సంపాదన మరియు అసాధారణత గుర్తింపు `xp_audit_log`లో ఈ వివరాలతో లాగ్ చేయబడుతుంది:

| ఫీల్డ్       | వివరణ                                         |
| ------------ | --------------------------------------------- |
| `api_key_id` | ఎవరు                                          |
| `action`     | ఏమి జరిగింది (xp_award, transfer, anomaly, …) |
| `xp_awarded` | మొత్తం (XP-యేతర ఈవెంట్లకు 0)                  |
| `metadata`   | సందర్భంతో కూడిన JSON (చర్య రకం, లక్ష్యం, …)   |
| `created_at` | ఎప్పుడు (ISO 8601)                            |

అడ్మిన్లు `GET /api/gamification/anomalies` ద్వారా పూర్తి ఆడిట్ ట్రైల్ను క్వెరీ చేయవచ్చు.

## డ్యాష్బోర్డ్ పేజీలు

### `/dashboard/leaderboard`

- పోడియం ప్రదర్శన (అవతార్లు మరియు XPతో అగ్రస్థానంలోని 3 మంది).
- పరిధి ఎంపిక: గ్లోబల్ / వారంవారీ / నెలవారీ / షేర్ చేసిన టోకెన్లు / సహకారాలు.
- ర్యాంక్, పేరు, స్కోర్, స్థాయి, బిరుదుతో పేజీకి 25 అంశాలు ఉండే పేజినేట్ చేసిన పట్టిక.
- SSE రియల్-టైమ్ అప్డేట్లు — ర్యాంక్ మార్పులు యానిమేషన్తో కనిపిస్తాయి.
- పట్టికలో ప్రస్తుత వినియోగదారు "మీ ర్యాంక్" అనే స్థిర వరుసతో హైలైట్ చేయబడతారు.

### `/dashboard/profile`

- ప్రస్తుత స్థాయి మరియు తదుపరి స్థాయి థ్రెషోల్డ్తో XP పురోగతి పట్టీ.
- బిరుదు బ్యాడ్జ్ ప్రముఖంగా ప్రదర్శించబడుతుంది.
- బ్యాడ్జ్ గ్యాలరీ — సాధించిన తేదీతో సాధించిన బ్యాడ్జ్లు, సాధించని బ్యాడ్జ్లు బూడిద రంగులో
  (దాచిన బ్యాడ్జ్లు సాధించే వరకు "???"గా కనిపిస్తాయి).
- మంట చిహ్నంతో స్ట్రీక్ కౌంటర్; స్ట్రీక్ క్యాలెండర్ (గత 30 రోజులు).
- XP చరిత్ర చార్ట్ (గత 30 రోజుల రోజువారీ XP).

### `/dashboard/tokens`

- టోకెన్ బ్యాలెన్స్ (ప్రముఖంగా, పేజీ ఎగువన).
- బదిలీ ఫారమ్: గ్రహీత, మొత్తం, నిర్ధారణ డైలాగ్.
- ఫిల్టర్లతో బదిలీ చరిత్ర పట్టిక (పంపినవి/అందుకున్నవి/అన్నీ).
- ఆహ్వాన విభాగం: క్రియాశీల కోడ్లు, కొత్తదాన్ని రూపొందించడం, లింక్ను షేర్ చేయడం.
- కమ్యూనిటీ సర్వర్లు: ఆరోగ్య స్థితితో జాబితా, కనెక్ట్/డిస్కనెక్ట్.

### `/dashboard/gamification/admin`

- తీవ్రత, వినియోగదారు, టైమ్స్టాంప్, z-స్కోర్తో అసాధారణతల జాబితా.
- ఫిల్టర్లతో ఆడిట్ లాగ్ వ్యూయర్ (చర్య రకం, వినియోగదారు, తేదీ పరిధి).
- సిస్టమ్ గణాంకాలు: ప్రదానం చేసిన మొత్తం XP, క్రియాశీల వినియోగదారులు, బ్యాడ్జ్ సాధన రేట్లు.
- ఫెడరేషన్ సర్వర్ ఆరోగ్య స్థితి సమగ్ర అవలోకనం.

## పైప్లైన్ ఇంటిగ్రేషన్

### ఇంటిగ్రేషన్ పాయింట్

గేమిఫికేషన్ `open-sse/handlers/chatCore.ts`లోని ఒకే పాయింట్ వద్ద అభ్యర్థన పైప్లైన్లో
అనుసంధానమవుతుంది:

```typescript
// ప్రతిస్పందనను క్లయింట్కు పంపిన తర్వాత:
setImmediate(() => {
  emitGamificationEvent({
    type: "request.completed",
    apiKeyId,
    metadata: {
      provider: selectedProvider,
      model: selectedModel,
      comboId: resolvedCombo?.id,
      compressionUsed: compressionStats?.applied,
      skillUsed: skillExecution?.name,
    },
  }).catch(() => {
    // అమలు చేసి వదిలేయండి: లాగ్ చేయండి, కానీ క్లయింట్కు ఎప్పుడూ పంపవద్దు
  });
});
```

### ఈవెంట్ రకాలు

| ఈవెంట్ రకం          | ఎప్పుడు విడుదల చేయబడుతుంది                                |
| ------------------- | --------------------------------------------------------- |
| `request.completed` | విజయవంతమైన LLM ప్రతిస్పందన పంపబడినప్పుడు                  |
| `provider.switch`   | ప్రొవైడర్ మారినప్పుడు (కాంబో ఫాల్బ్యాక్లు లెక్కించబడతాయి) |
| `combo.created`     | కొత్త కాంబో కాన్ఫిగరేషన్ సేవ్ చేయబడినప్పుడు               |
| `combo.used`        | కాంబో లక్ష్యం విజయవంతంగా చేరుకున్నప్పుడు                  |
| `badge.earned`      | బ్యాడ్జ్ మూల్యాంకనం సరిపోలికను కనుగొన్నప్పుడు             |
| `streak.milestone`  | స్ట్రీక్ థ్రెషోల్డ్ దాటినప్పుడు                           |
| `transfer.sent`     | టోకెన్ బదిలీ పూర్తయినప్పుడు                               |
| `referral.redeemed` | ఆహ్వాన కోడ్ విజయవంతంగా రిడీమ్ చేయబడినప్పుడు               |
| `compression.used`  | ప్రాంప్ట్ కంప్రెషన్ వర్తింపజేసినప్పుడు                    |
| `skill.executed`    | నైపుణ్య అమలు పూర్తయినప్పుడు                               |
| `model.first_use`   | గత 7 రోజుల్లో మోడల్ ఉపయోగించబడనప్పుడు                     |

### నాన్-బ్లాకింగ్ హామీ

`setImmediate` + `.catch(() => {})` నమూనా వీటిని నిర్ధారిస్తుంది:

1. గేమిఫికేషన్ అమలయ్యే ముందు ప్రతిస్పందన పూర్తిగా పంపబడుతుంది.
2. గేమిఫికేషన్ లోపాలు ఎప్పుడూ క్లయింట్కు చేరవు.
3. ఈవెంట్ ప్రాసెసింగ్ ఇన్లైన్లో కాకుండా తదుపరి మైక్రోటాస్క్లో నడుస్తుంది.

## భవిష్యత్ పరిశీలనలు

- **సీజనల్ ఈవెంట్లు**: పరిమిత కాల బ్యాడ్జ్ సెట్లు మరియు లీడర్బోర్డ్ సీజన్లు.
- **టీమ్ లీడర్బోర్డ్లు**: సంస్థ లేదా కాంబో ఆధారంగా వినియోగదారులను సమూహపరచడం.
- **XP మల్టిప్లయర్లు**: ప్రచార వ్యవధుల్లో XPని పెంచడం.
- **అచీవ్మెంట్ షేరింగ్**: షేర్ చేయగల బ్యాడ్జ్ కార్డ్లను (OpenGraph చిత్రాలు) రూపొందించడం.
- **మొబైల్ పుష్**: బ్యాడ్జ్/లెవల్ ఈవెంట్ల కోసం webhook-ఆధారిత నోటిఫికేషన్లు.
- **లీడర్బోర్డ్ API**: మూడవ పక్ష ఇంటిగ్రేషన్ల కోసం పబ్లిక్ API.
