> **అధికారిక మూలం:** `src/lib/skills/` మరియు `src/app/api/skills/`
> **చివరిగా నవీకరించబడింది:** 2026-06-28 — v3.8.40

ఫైల్సిస్టమ్ రీడ్లు మరియు HTTP అభ్యర్థనల నుంచి శాండ్బాక్స్డ్ కోడ్ అమలు, ఎంపిక చేసిన మార్కెట్ప్లేస్ స్కిల్స్ వరకు — పునర్వినియోగించగల సామర్థ్యాలను లాంగ్వేజ్ మోడళ్లు (మరియు ఆపరేటర్లు) సమ్మిళితం చేయడానికి వీలు కల్పించే విస్తరించదగిన Skills ఫ్రేమ్వర్క్ను OmniRoute అందిస్తుంది.

స్కిల్ అనేది వెర్షన్ చేయబడిన, స్కీమా ద్వారా నిర్వచించబడిన పని యూనిట్. OmniRoute అవుట్బౌండ్ అభ్యర్థనల్లో స్కిల్స్ను టూల్ నిర్వచనాలుగా చేర్చగలదు, మోడల్ నుంచి తిరిగి వచ్చే టూల్ కాల్లను అడ్డుకుని, సరిపోలే హ్యాండ్లర్ను అమలు చేసి, సంభాషణ కొనసాగేందుకు ఫలితాన్ని తిరిగి మోడల్కు అందించగలదు. మోడల్కు అమలు విధానం ఎప్పుడూ కనిపించదు — టూల్ ఇంటర్ఫేస్ మాత్రమే కనిపిస్తుంది.

## Agent Skills వర్సెస్ Omni Skills

OmniRouteలో వేర్వేరుగా ఉన్నప్పటికీ పరస్పరం అనుబంధమైన రెండు స్కిల్ సిస్టమ్లు ఉన్నాయి:

| అంశం                     | **Omni Skills** (ఈ డాక్యుమెంట్)                                        | **Agent Skills**                                                                             |
| :----------------------- | :--------------------------------------------------------------------- | :------------------------------------------------------------------------------------------- |
| ఉద్దేశ్యం                | LLM టూల్ ఇంజెక్షన్ + శాండ్బాక్స్డ్ అమలు                                | బాహ్య ఏజెంట్లు కనుగొని ఉపయోగించడానికి SKILL.md కేటలాగ్                                       |
| అధికారిక మూలం            | `src/lib/skills/` + మార్కెట్ప్లేస్                                     | `src/lib/agentSkills/` + `skills/` డైరెక్టరీ                                                 |
| రన్టైమ్ మోడ్             | అవుట్బౌండ్ అభ్యర్థనల్లో చేర్చబడి, టూల్-కాల్ ఈవెంట్లపై అమలు చేయబడుతుంది | స్థిరమైన మార్క్డౌన్ కేటలాగ్ + REST/MCP/A2A డిస్కవరీ ఎండ్పాయింట్లు                            |
| దీన్ని ఎవరు ఉపయోగిస్తారు | OmniRoute స్వయంగా (కాంబో రూటింగ్, ఇన్బౌండ్ LLM కాల్లు)                 | బాహ్య ఏజెంట్లు, MCP క్లయింట్లు, A2A ఆర్కెస్ట్రేటర్లు                                         |
| సంఖ్య                    | మారవచ్చు (మార్కెట్ప్లేస్ ఆధారితం)                                      | 45 కేటలాగ్ ఎంట్రీలు (23 API + 21 CLI + 1 కాన్ఫిగ్)                                           |
| ఫార్మాట్                 | టూల్ స్కీమా + హ్యాండ్లర్తో కూడిన `SkillDefinition`                     | `SKILL.md` ఫ్రంట్మ్యాటర్ + మార్క్డౌన్ బాడీ                                                   |
| డిస్కవరీ                 | `/api/skills/*` REST + `omniroute_skills_*` MCP టూల్స్                 | `/api/agent-skills/*` REST + `omniroute_agent_skills_*` MCP టూల్స్ + A2A `list-capabilities` |

**Omni Skills** అమలు ఇంజిన్ — ఒక LLM టూల్ను ఇన్వోక్ చేసినప్పుడు OmniRoute _ఏం చేయగలదో_ అవి నిర్వచిస్తాయి.

**Agent Skills** డాక్యుమెంటేషన్ కేటలాగ్ — ఏజెంట్ ప్రాంప్ట్లలో నేరుగా అందించగల నిర్మిత SKILL.md ఫైళ్లతో, OmniRoute యొక్క REST API మరియు CLIని _ఎలా ఉపయోగించాలో_ అవి బాహ్య ఏజెంట్లకు వివరిస్తాయి.

Agent Skills కేటలాగ్, జనరేటర్, MCP టూల్స్ మరియు A2A స్కిల్ కోసం [docs/frameworks/AGENT-SKILLS.md](./AGENT-SKILLS.md) చూడండి.

## భావనలు

### స్కిల్ మూలాలు

ఒకే రిజిస్ట్రీలో మూడు స్కిల్ మూలాలు సహజీవనం చేస్తాయి:

1. **అంతర్నిర్మిత స్కిల్స్** (`src/lib/skills/builtins.ts`) — OmniRouteతో పాటు అందించబడతాయి. సాధారణ వినియోగ సందర్భాలను కవర్ చేస్తాయి:
   - `file_read`, `file_write` — `<DATA_DIR>/skills/workspaces/<hashed-key>/` కింద ప్రతి API కీకి ప్రత్యేకమైన శాండ్బాక్స్ వర్క్స్పేస్
   - `http_request` — `guard: "public-only"`తో `safeOutboundFetch` ద్వారా అవుట్బౌండ్ HTTP
   - `web_search` — క్యాషింగ్తో ప్లగ్ చేయగల సెర్చ్ ప్రొవైడర్ (`executeWebSearch`)
   - `eval_code` — Dockerలో శాండ్బాక్స్ చేయబడిన `node` లేదా `python` అమలు
   - `execute_command` — Dockerలో శాండ్బాక్స్ చేయబడిన షెల్ కమాండ్
   - `browser` — Playwright ఆధారిత స్కాఫోల్డింగ్, డిఫాల్ట్గా నిలిపివేయబడింది (`builtin/browser.ts`)
2. **SkillsMP** (OmniRoute మార్కెట్ప్లేస్) — `https://skillsmp.com/api/v1/skills/search` నుంచి పొందబడతాయి. Settingsలో `skillsmpApiKey` అవసరం.
3. **SkillsSH** (`skills.sh` కమ్యూనిటీ కేటలాగ్) — `https://skills.sh/api/search` నుంచి పొందబడతాయి. ప్రామాణీకరణ అవసరం లేదు; SKILL.md కంటెంట్ GitHub raw నుంచి తీసుకోబడుతుంది.

డాష్బోర్డ్ ఏ కేటలాగ్ నుంచి ఇన్స్టాల్ చేస్తుందో ఒకే "యాక్టివ్ ప్రొవైడర్" నియంత్రిస్తుంది (`src/lib/skills/providerSettings.ts`). దీన్ని **Settings → Memory & Skills** కింద మార్చండి. డిఫాల్ట్: `skillsmp`.

### స్కిల్ గుర్తింపు

ఇన్-మెమరీ రిజిస్ట్రీలో (`src/lib/skills/registry.ts`) స్కిల్స్ `name@version` ద్వారా కీ చేయబడతాయి. వెర్షన్ తప్పనిసరిగా semver (`^\d+\.\d+\.\d+$`) అయి ఉండాలి. `resolveVersion()`కు `^`, `~`, `>`, `>=`, `<`, `<=`, `==` మరియు ఖచ్చిత-సరిపోలిక పరిమితులు అర్థమవుతాయి.

### స్కిల్ మోడ్

ప్రతి స్కిల్ ఎప్పుడు ఇంజెక్ట్ చేయబడాలో నియంత్రించే రన్టైమ్ మోడ్ను కలిగి ఉంటుంది:

| మోడ్   | ప్రవర్తన                                                                                                                  |
| ------ | ------------------------------------------------------------------------------------------------------------------------- |
| `on`   | ఎల్లప్పుడూ టూల్ నిర్వచనంగా ఇంజెక్ట్ చేయబడుతుంది                                                                           |
| `off`  | ఎప్పుడూ ఇంజెక్ట్ చేయబడదు, ఎప్పుడూ అమలు చేయబడదు                                                                            |
| `auto` | ఇన్కమింగ్ అభ్యర్థనతో పోల్చి స్కోర్ చేయబడుతుంది; స్కోర్ ≥ `AUTO_MIN_SCORE` (డిఫాల్ట్ 3) అయితే మాత్రమే ఇంజెక్ట్ చేయబడుతుంది |

మార్కెట్ప్లేస్ నుంచి ఇన్స్టాల్ చేసిన స్కిల్స్కు `auto` డిఫాల్ట్. `enabled=true` మరియు `mode="off"` కలిపి ఉంటే "రిజిస్టర్ చేయబడింది కానీ యాక్టివ్గా లేదు" అని అర్థం — లెగసీ కాలమ్ ద్వారా `enabled`ను టాగుల్ చేసినప్పుడు, పాత కోడ్పాత్లు కూడా స్థిరంగా ఉండేందుకు `mode` కూడా మార్చబడుతుంది (`src/app/api/skills/[id]/route.ts`).

### స్థితి (అమలులు)

స్కిల్ అమలులు క్రింది స్థితులతో `skill_executions` పట్టికలో ట్రాక్ చేయబడతాయి (`src/lib/skills/types.ts`):

```ts
enum SkillStatus {
  PENDING = "pending",
  RUNNING = "running",
  SUCCESS = "success",
  ERROR = "error",
  TIMEOUT = "timeout",
}
```

### రిజిస్ట్రీ క్యాష్

`SkillRegistry` అనేది 60-సెకన్ల TTL క్యాష్తో కూడిన సింగిల్టన్ (`registry.ts:14`). `loadFromDatabase()` ఐడెంపోటెంట్గా ఉంటుంది మరియు `pendingLoad` ద్వారా సమాంతర కాల్లలోని నకళ్లను తొలగిస్తుంది. ఏదైనా రైట్ (`register`/`unregister`/`unregisterById`) క్యాష్ను చెల్లనిదిగా చేస్తుంది. `getSkillVersions(name)` మరియు `resolveVersion(name, constraint)` ద్వారా వెర్షన్లను వెతకండి.

### ప్రొవైడర్-అవేర్ ఇంజెక్షన్

`src/lib/skills/injection.ts`లోని `injectSkills()` రిజిస్టర్ చేసిన స్కిల్స్ను ప్రొవైడర్కు ప్రత్యేకమైన టూల్ నిర్వచనాలుగా మార్చే ఎంట్రీ పాయింట్:

- **OpenAI** — `{ type: "function", function: { name, description, parameters } }`
- **Anthropic** — `{ name, description, input_schema }`
- **Google (Gemini)** — `{ name, description, parameters }`

మోడల్ తిరిగి కాల్ చేసినప్పుడు హ్యాండ్లర్ సరైన వెర్షన్ను ఎంచుకునేలా టూల్ పేరు `name@version` రూపంలో ఎన్కోడ్ చేయబడుతుంది.

### AUTO స్కోరింగ్

`mode="auto"` అయినప్పుడు, ప్రతి అభ్యర్థి స్కిల్ అభ్యర్థన సందర్భంతో పోల్చి స్కోర్ చేయబడుతుంది (`injection.ts`లోని `scoreAutoSkill()`):

| సంకేతం                                                       | పాయింట్లు         |
| ------------------------------------------------------------ | ----------------- |
| స్కిల్ పేరు సందర్భంలో యథాతథంగా కనిపిస్తుంది                  | +6                |

`score >= AUTO_MIN_SCORE = 3` ఉన్న వాటిలో అత్యధిక స్కోర్ పొందిన `AUTO_MAX_SKILLS = 5` స్కిల్స్ ఇంజెక్ట్ చేయబడతాయి. సమాన స్కోర్లు ఉంటే ముందుగా `installCount` (అవరోహణ క్రమం), ఆ తర్వాత పేరును అక్షర క్రమంలో పరిగణించి నిర్ణయిస్తారు (`injection.ts:225-235`).

### టూల్ కాల్ ఇంటర్సెప్షన్

అప్స్ట్రీమ్ టూల్-కాలింగ్ ప్రతిస్పందనను ఇచ్చిన తర్వాత, చాట్ హ్యాండ్లర్ ద్వారా `src/lib/skills/interception.ts`లోని `handleToolCallExecution()` ఇన్వోక్ చేయబడుతుంది:

1. `extractToolCalls()` ప్రొవైడర్కు నిర్దిష్టమైన ఆకృతులను చదువుతుంది (OpenAI `tool_calls` / Responses `function_call`, Anthropic `tool_use`, Gemini `functionCalls`).
2. బిల్ట్-ఇన్ టూల్ అలియాస్లు (ఉదా. `omniroute_web_search` → `web_search`) మొదట పరిష్కరించబడతాయి. బిల్ట్-ఇన్ హ్యాండ్లర్లు ఇన్లైన్లో రన్ అవుతాయి.
3. మిగతావన్నీ `skillExecutor.execute(name@version, args, { apiKeyId, sessionId })` ద్వారా రూట్ చేయబడతాయి.
4. ఫలితాలు తగిన విధంగా ప్రతిస్పందనలోకి చేర్చబడతాయి — `tool_results`, `function_call_output` ఐటెమ్లు లేదా Anthropic `tool_result` బ్లాక్లు.

ఎగ్జిక్యూషన్ సందర్భంలోని `customSkillExecutionEnabled`ను `false`గా సెట్ చేసి, బిల్ట్-ఇన్ ఇంటర్సెప్షన్ను మాత్రమే అనుమతించవచ్చు (వినియోగదారు నిర్వచించిన హ్యాండ్లర్లను స్పష్టంగా నిలిపివేసే అభ్యర్థన మార్గాల్లో ఇది ఉపయోగించబడుతుంది).

## Docker శాండ్బాక్స్

అంతర్నిర్మితం కాని కోడ్ పాత్లు (`eval_code`, `execute_command`) `SandboxRunner` (`src/lib/skills/sandbox.ts`) ద్వారా Docker లోపల అమలవుతాయి. ప్రతి కంటైనర్ కింది వాటితో ప్రారంభించబడుతుంది:

```
--rm --network none|bridge --cap-drop ALL
--security-opt no-new-privileges --pids-limit 100
--cpus <cpuLimit/1000> --memory <memoryLimit>m
--tmpfs /tmp:rw,noexec,nosuid,size=64m
--tmpfs /workspace:rw,noexec,nosuid,size=64m
--read-only (readOnly=true అయినప్పుడు)
```

డిఫాల్ట్లు (`SandboxRunner.DEFAULT_CONFIG`):

| ఫీల్డ్           | డిఫాల్ట్        | గమనికలు                                               |
| ---------------- | --------------- | ----------------------------------------------------- |
| `cpuLimit`       | 100 (= 0.1 CPU) | `--cpus`కు పంపే ముందు 1000తో భాగించబడుతుంది           |
| `memoryLimit`    | 256 MB          | కఠిన పరిమితి                                          |
| `timeout`        | 30000 ms        | `SIGTERM` + `docker kill` ద్వారా సాఫ్ట్ కిల్          |
| `networkEnabled` | `false`         | `--network none`గా మారుతుంది                          |
| `readOnly`       | `true`          | రూట్ FS రీడ్-ఓన్లీ; `/tmp` మరియు `/workspace` tmpfsలు |

షట్డౌన్ కోసం `SandboxRunner.kill(id)` మరియు `killAll()` అందుబాటులో ఉంచబడ్డాయి; అమలవుతున్న కంటైనర్లు `runningContainers: Map<string, ChildProcess>`లో ట్రాక్ చేయబడతాయి.

### శాండ్బాక్స్ ఎన్విరాన్మెంట్ వేరియబుల్స్

`src/lib/skills/builtins.ts`లో `process.env` ద్వారా కాన్ఫిగర్ చేయబడతాయి:

| ఎన్విరాన్మెంట్ వేరియబుల్          | డిఫాల్ట్         | ప్రయోజనం                                                                                         |
| --------------------------------- | ---------------- | ------------------------------------------------------------------------------------------------ |
| `SKILLS_MAX_FILE_BYTES`           | `1048576` (1 MB) | `file_read` మరియు `file_write` కోసం పరిమితి                                                      |
| `SKILLS_MAX_HTTP_RESPONSE_BYTES`  | `256000`         | `http_request` ప్రతిస్పందన బాడీ కోసం పరిమితి                                                     |
| `SKILLS_MAX_SANDBOX_OUTPUT_CHARS` | `100000`         | కాలర్కు తిరిగి ఇచ్చే stdout/stderr కోసం పరిమితి                                                  |
| `SKILLS_SANDBOX_TIMEOUT_MS`       | `10000`          | శాండ్బాక్స్ చేసిన కమాండ్లకు డిఫాల్ట్ టైమ్అవుట్; గరిష్ఠంగా 60 sకు పరిమితం                         |
| `SKILLS_SANDBOX_NETWORK_ENABLED`  | `false`          | ఎగ్రెస్కు ప్రధాన నియంత్రణ. ప్రతి కాల్కు ఆప్ట్-ఇన్ను అనుమతించడానికి `1` లేదా `true`గా సెట్ చేయండి |
| `SKILLS_ALLOWED_SANDBOX_IMAGES`   | (క్రింద చూడండి)  | Docker ఇమేజ్ల కామాతో వేరు చేసిన అనుమతి జాబితా                                                    |

డిఫాల్ట్గా అనుమతించబడిన ఇమేజ్లు: `alpine:3.20`, `node:22-alpine`, `python:3.12-alpine`. `SKILLS_ALLOWED_SANDBOX_IMAGES` ద్వారా చేసే ఏవైనా చేర్పులు డిఫాల్ట్లతో విలీనం చేయబడతాయి; తెలియని ఇమేజ్లను `normalizeImage()` తిరస్కరిస్తుంది.

> గమనిక: ప్రత్యేక `SKILLS_EXECUTION_TIMEOUT_MS` ఎన్విరాన్మెంట్ వేరియబుల్ లేదు. శాండ్బాక్స్ కాని హ్యాండ్లర్ టైమ్అవుట్ `SkillExecutor` (`executor.ts:13`)లో 30 sకు హార్డ్-కోడ్ చేయబడింది, కానీ రన్టైమ్లో `skillExecutor.setTimeout(ms)` ద్వారా దాన్ని ఓవర్రైడ్ చేయవచ్చు.

### వర్క్స్పేస్ ఐసోలేషన్

`file_read` మరియు `file_write` ప్రతి పాత్ను `<DATA_DIR>/skills/workspaces/<sha256(apiKeyId).slice(0,24)>/` వద్ద ఉన్న ప్రతి-API-కీ వర్క్స్పేస్కు సాపేక్షంగా పరిష్కరిస్తాయి. ఏదైనా డిస్క్ I/Oకు ముందు పాత్ ట్రావర్సల్ (`..`) మరియు నిషేధిత సెగ్మెంట్లు (`.env`, `.git`, `.ssh`, `.omniroute`, `.codex`, `secrets`) తిరస్కరించబడతాయి.

### HTTP పటిష్ఠీకరణ

`http_request` (`builtins.ts:257`):

- మెథడ్ అనుమతి జాబితా: `GET, HEAD, POST, PUT, PATCH, DELETE`
- బ్లాక్ చేయబడిన అవుట్బౌండ్ హెడర్లు: `host, connection, content-length, cookie, set-cookie, authorization, proxy-authorization`
- రీడైరెక్ట్లు నిలిపివేయబడ్డాయి (`allowRedirect: false`)
- `guard: "public-only"`తో `safeOutboundFetch` ద్వారా రూట్ చేయబడుతుంది (ప్రైవేట్/లూప్బ్యాక్ పరిధులు బ్లాక్ చేయబడతాయి)
- ప్రతిస్పందన `SKILLS_MAX_HTTP_RESPONSE_BYTES` వద్ద కుదించబడుతుంది; క్లయింట్కు `truncated: true` కనిపిస్తుంది

## హైబ్రిడ్ ఎగ్జిక్యూటర్ (ప్రివ్యూ)

`src/lib/skills/hybrid.ts` ప్రతి కాల్కు `direct` (ప్రాసెస్లోనే) మరియు `sandbox` అమలులో దేనిని ఉపయోగించాలో నిర్ణయించే `HybridExecutor`ను నిర్వచిస్తుంది. టైమ్అవుట్/మెమరీ లోపాలు సంభవించినప్పుడు `autoUpgrade` ద్వారా మళ్లీ ప్రయత్నించే మార్గం కూడా ఉంటుంది. అనుసంధానించబడిన `directExecutor` / `sandboxRunner` అమలులు స్టబ్లు (`executeDirect`, `executeInSandbox` ప్లేస్హోల్డర్ ఆబ్జెక్ట్లను తిరిగి ఇస్తాయి) — ఈ మాడ్యూల్ను నిర్మాణంలో ఉన్న ఒప్పందంగా పరిగణించండి. వాస్తవ అమలు ఇప్పటికీ `skillExecutor` + `SandboxRunner` ద్వారానే జరుగుతుంది.

## REST API

అన్ని ఎండ్పాయింట్లు `src/app/api/skills/` కింద ఉంటాయి. నిర్వహణ ఎండ్పాయింట్లకు (`/api/skills`, `/api/skills/[id]`, `/api/skills/install`) `requireManagementAuth()` ద్వారా **నిర్వహణ ప్రామాణీకరణ** అవసరం. మార్కెట్ప్లేస్/ఇన్స్టాల్ ప్రవాహాలు తేలికపాటి `isAuthenticated()`ను (సెషన్ లేదా API కీ) ఉపయోగిస్తాయి.

| ఎండ్పాయింట్ | పద్ధతి | ఉద్దేశ్యం |
| --------------------------------- | ------ | ------------------------------------------------------------------------ | --- | ------------------------ | -------- | ------------------ |
| `/api/skills` | GET | నమోదైన స్కిల్లను జాబితా చేస్తుంది. `?q=`, `?mode=on                        | off | auto`, `?source=skillsmp | skillssh | local`, పేజినేషన్కు మద్దతు ఇస్తుంది |
| `/api/skills/[id]` | PUT | `enabled` లేదా `mode`ను నవీకరిస్తుంది |

| `/api/skills/skillssh/install` | POST | skills.sh స్కిల్ను ఇన్స్టాల్ చేస్తుంది (సక్రియ ప్రొవైడర్ = `skillssh` కావాలి) |

`settings.skillsEnabled === false` అయినప్పుడు `POST /api/skills/executions` ఎండ్పాయింట్ `{ error: "Skills execution is disabled..." }`తో HTTP `503`ను తిరిగి ఇస్తుంది (`executor.ts:42-45`). ఆపరేటర్లు **Settings → AI** నుండి మాస్టర్ స్విచ్ను మార్చవచ్చు.

```bash
  }'
```

`handlerCode` స్ట్రింగ్ అనేది **హ్యాండ్లర్ పేరు కోసం లుకప్** — అమలు చేయగల కోడ్ కాదు. ఎగ్జిక్యూటర్ దాన్ని `skillExecutor.registerHandler(name, fn)` ద్వారా మ్యాప్ చేస్తుంది (`executor.ts:25`). మార్కెట్ప్లేస్ ఇన్స్టాలేషన్లు డాక్యుమెంటేషన్గా SKILL.md టెక్స్ట్ను ఈ ఫీల్డ్లో నిల్వ చేస్తాయి మరియు మోడల్ రూపొందించిన టూల్ కాల్ల ద్వారా అమలును రూట్ చేస్తాయి. వినియోగదారు స్వేచ్ఛగా అందించిన సోర్స్పై eval అమలు చేయబడదు.

## కొత్త అంతర్నిర్మిత Skillను జోడించడం

1. **handlerను నిర్వచించండి** — `src/lib/skills/builtins.ts`లో (లేదా `src/lib/skills/builtin/` కింద ఉన్న అనుబంధ ఫైల్లో). Signature: `(input, { apiKeyId, sessionId }) => Promise<output>`.
2. **Sandboxed code path?** `sandboxRunner.run(image, command, env, sandboxConfig({...}))`ను కాల్ చేయండి. allowlistకు అనుగుణంగా `normalizeImage()`ను ఉపయోగించండి.
3. **Filesystem path?** diskను యాక్సెస్ చేయడానికి ముందు ఎల్లప్పుడూ `resolveWorkspacePath(input, context)` ద్వారా పంపండి.
4. **Network call?** `guard: "public-only"`తో `safeOutboundFetch`ను ఉపయోగించండి; `sanitizeHeaders()` ద్వారా headersను శుభ్రపరచండి.
5. **నమోదు చేయండి** — entryని `builtinSkills`కు జోడించండి (లేదా boot సమయంలో `registerBrowserSkill(executor)` తరహాలో కాల్ చేయండి).
6. upstream model వేరే పేరును విడుదల చేస్తే, `BUILTIN_TOOL_ALIASES` (`interception.ts:23`)లో **అంతర్నిర్మిత tool aliasesను అనుసంధానించండి** (ఐచ్ఛికం).
7. `src/lib/skills/__tests__/`లో **పరీక్షలు** (Vitest).

## నిర్వహణ చిట్కాలు

- **ప్రధాన switch:** `settings.skillsEnabled = false` అన్ని అమలులను నిరోధిస్తుంది మరియు `/api/skills/executions`పై HTTP `503`ను తిరిగి ఇస్తుంది. registry లోడ్ అవుతూనే ఉంటుంది.
- **Egressను నిరోధించండి:** పూర్తిగా air-gapped sandboxing కోసం `SKILLS_SANDBOX_NETWORK_ENABLED`ను సెట్ చేయకుండా ఉంచండి (డిఫాల్ట్). ప్రతి callకు `networkEnabled: true` ఇచ్చినా, master gate అనుమతి అవసరమే.
- **నిర్దిష్ట imagesను అనుమతించండి:** allowlistను విస్తరించడానికి `SKILLS_ALLOWED_SANDBOX_IMAGES="myorg/sandbox:1.0,node:22-alpine"`ను సెట్ చేయండి.
- **అమలులను audit చేయండి:** `/dashboard/skills/executions` మరియు `omniroute_skills_executions` రెండూ `skill_executions`ను query చేస్తాయి. విజయవంతమైన runsలో `durationMs` ఉంటుంది; విఫలమైన వాటిలో `errorMessage` ఉంటుంది.
- **Cache invalidation:** మాన్యువల్ DB సవరణల తర్వాత `skillRegistry.invalidateCache()`ను కాల్ చేయండి; లేకపోతే 60 s వేచి ఉండండి.
- **Anonymous workspace:** `apiKeyId` ఖాళీగా ఉన్నప్పుడు, అన్ని calls ఒకే `"anonymous"` workspaceకు hash అవుతాయి — share-aware code ఎల్లప్పుడూ నిజమైన keyని పంపాలి.

## అమలు జీవనచక్రం (v3.8.16+)

`SkillExecutor` (`src/lib/skills/executor.ts`) అనేది ప్రతి స్కిల్ ఆహ్వానాన్ని నిర్వహించే **సింగిల్టన్**. టైమ్అవుట్లు, పునఃప్రయత్నాలు మరియు అమలు స్థితిని డీబగ్ చేయడానికి దాని జీవనచక్రాన్ని అర్థం చేసుకోవడం అత్యంత ముఖ్యం.

### 5-దశల జీవనచక్రం

```
   execute() కాల్ చేయబడింది
        │
        ▼
  ┌─────────────┐
  │  PENDING    │  ← క్యూలో ఉంది, ఇంకా ప్రారంభం కాలేదు (DB వరుస సృష్టించబడింది)
  └──────┬──────┘
         │ హ్యాండ్లర్ను ప్రారంభించండి
         ▼
  ┌─────────────┐
  │  RUNNING    │  ← టైమ్అవుట్తో హ్యాండ్లర్ ఆహ్వానించబడింది
  └──────┬──────┘
         │
    ┌────┴────┬──────────┬──────────┐
    │         │          │          │
    ▼         ▼          ▼          ▼
  SUCCESS   ERROR     TIMEOUT   (ఇతర మార్గం లేదు — పేరెంట్ ద్వారా నిలిపివేయబడింది)
    │         │          │
    └────┬────┴──────────┘
         │
         ▼
   స్థితి, అవుట్పుట్, durationMsతో DB వరుస నవీకరించబడింది
```

### డిఫాల్ట్ కాన్ఫిగరేషన్

| సెట్టింగ్    | డిఫాల్ట్       | దీని ద్వారా కాన్ఫిగర్ చేయవచ్చు       |
| ------------ | -------------- | ------------------------------------ |
| `timeout`    | `30000` (30సె) | `skillExecutor.setTimeout(ms)`       |
| `maxRetries` | `3`            | `skillExecutor.setMaxRetries(count)` |

> **ముఖ్యమైనది**: ఎగ్జిక్యూటర్ ఒక సింగిల్టన్ — `setTimeout()`ను కాల్ చేయడం తదుపరి అన్ని ఆహ్వానాలను గ్లోబల్గా ప్రభావితం చేస్తుంది. ప్రస్తుతం ఒక్కో స్కిల్కు ప్రత్యేక టైమ్అవుట్లకు మద్దతు లేదు; ఒక్కో స్కిల్కు వేర్వేరు టైమ్అవుట్లు అవసరమైతే, వేర్వేరు ప్రాసెస్లను సమర్పించండి లేదా ఎగ్జిక్యూటర్ను ఫోర్క్ చేయండి.

### స్థితి విలువలు

`src/lib/skills/types.ts` నుండి:

```ts
enum SkillStatus {
  PENDING = "pending", // క్యూలో ఉంది, ఇంకా ప్రారంభం కాలేదు
  RUNNING = "running", // హ్యాండ్లర్ ఆహ్వానించబడింది
  SUCCESS = "success", // హ్యాండ్లర్ చెల్లుబాటు అయ్యే అవుట్పుట్ను తిరిగి ఇచ్చింది
  ERROR = "error", // హ్యాండ్లర్ ఒక మినహాయింపును విసిరింది
  TIMEOUT = "timeout", // ఎగ్జిక్యూటర్ టైమ్అవుట్ను మించిపోయింది
}
```

> **గమనిక**: `TIMEOUT` స్థితి enumలో నిర్వచించబడింది, కానీ ప్రస్తుత ఎగ్జిక్యూటర్ అమలు ద్వారా ఇది **వాస్తవంగా DBలో వ్రాయబడదు** — టైమ్అవుట్లు `"Skill execution timed out"` సందేశంతో `ERROR`గా కనిపిస్తాయి. ఈ స్థితి enum భవిష్యత్ వినియోగం కోసం రిజర్వ్ చేయబడింది.

### అమలులను పరిశీలించడం

```ts
import { skillExecutor } from "omniroute/skills/executor";

// ID ద్వారా నిర్దిష్ట అమలును పొందండి
const exec = skillExecutor.getExecution("exec-uuid-123");
if (exec) {
  console.log(`${exec.skillName}: ${exec.status} in ${exec.durationMs}ms`);
}

// API కీ కోసం ఇటీవలి అమలులను జాబితా చేయండి
const recent = skillExecutor.listExecutions("api-key-id", 50, 0);
for (const e of recent) {
  console.log(`${e.skillName} → ${e.status} (${e.durationMs}ms)`);
}

// మొత్తం అమలుల సంఖ్యను లెక్కించండి
const total = skillExecutor.countExecutions("api-key-id");
```

### పునఃప్రయత్న ప్రవర్తన

`maxRetries` సెట్టింగ్ నిల్వ చేయబడుతుంది, కానీ ఎగ్జిక్యూటర్ యొక్క `execute()` పద్ధతి ద్వారా **ప్రస్తుతం ఉపయోగించబడదు** — ఇది ఒకే ప్రయత్నాన్ని మాత్రమే నిర్వహిస్తుంది. `maxRetries` విలువ భవిష్యత్ అమలు కోసం మరియు దానిని చదవాలనుకునే హుక్ల కోసం అందుబాటులో ఉంచబడింది.

ప్రస్తుతానికి, పునఃప్రయత్నాలను స్కిల్ హ్యాండ్లర్లోనే అమలు చేయాలి. అంతర్నిర్మిత
స్కిల్లు ఎగ్జిక్యూటర్తో నమోదు చేయబడతాయి (ఉదా. `registerBuiltinSkills(executor)`
/ `src/lib/skills/builtin/`లోని `registerBrowserSkill(executor)`); మీరు నమోదు చేసే ఏ హ్యాండ్లర్ అయినా
దాని స్వంత పునఃప్రయత్న లూప్ను చుట్టవచ్చు:

```ts
// స్కిల్ హ్యాండ్లర్ లోపల
async function handler(input, ctx) {
  const maxRetries = 3;
  let lastError: Error | null = null;

  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      return await fetchSomething(input);
    } catch (err) {
      lastError = err as Error;
      if (attempt < maxRetries) {
        await new Promise((r) => setTimeout(r, 1000 * attempt));
      }
    }
  }
  throw lastError;
}
```

## SkillMode వివరంగా

`SkillMode` enum (`src/lib/skills/types.ts`) నైపుణ్యాలు **ఎప్పుడు మరియు ఎలా** అమలు చేయబడతాయో నియంత్రిస్తుంది:

```ts
enum SkillMode {
  AUTO = "auto", // నైపుణ్యాన్ని ఎప్పుడు కాల్ చేయాలో LLM నిర్ణయిస్తుంది
  MANUAL = "manual", // స్పష్టమైన వినియోగదారు అభ్యర్థన ద్వారా మాత్రమే అమలు చేయబడుతుంది
  HYBRID = "hybrid", // AUTO స్కోరింగ్ + మాన్యువల్ ఓవర్రైడ్
}
```

> **గమనిక**: కోడ్బేస్ `SkillMode` (AUTO/MANUAL/HYBRID)ని నిర్వచిస్తుంది, అయితే `Skill.mode` ఫీల్డ్ వేరొక ఆకృతిని (`"on" | "off" | "auto"`) ఉపయోగిస్తుంది. అవి పరస్పరం సంబంధితమైనవి, కానీ ఒకేలా ఉండవు — `SkillMode` అనేది ఎగ్జిక్యూటర్ విధానం కోసం, `Skill.mode` అనేది ప్రతి నైపుణ్యాన్ని ప్రారంభించడం లేదా నిలిపివేయడం కోసం.

| -------- | ---------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| `AUTO`   | అవసరమని భావించినప్పుడు LLM నైపుణ్యాన్ని కాల్ చేయగలదు                                           | సాధారణ-ప్రయోజన నైపుణ్యాలు (ఫైల్ రీడ్లు, HTTP అభ్యర్థనలు) |
| `MANUAL` | LLM నైపుణ్యాన్ని కాల్ చేయలేదు; స్పష్టమైన `executeSkill` API కాల్ మాత్రమే దాన్ని అమలు చేస్తుంది | సున్నితమైన కార్యకలాపాలు (డేటాబేస్ రైట్లు, చెల్లింపులు)   |
| `HYBRID` | LLM నైపుణ్యాన్ని సూచించగలదు; వినియోగదారు తప్పనిసరిగా నిర్ధారించాలి                             | దుష్ప్రభావాలు ఉన్నప్పటికీ ప్రమాదకరం కాని నైపుణ్యాలు      |

### AUTO స్కోరింగ్

`AUTO` మోడ్ సక్రియంగా ఉన్నప్పుడు, ప్రతి అభ్యర్థి నైపుణ్యం అభ్యర్థన
సందర్భంతో పోల్చి `src/lib/skills/injection.ts`లోని `scoreAutoSkill()` ద్వారా స్కోర్ చేయబడుతుంది — ఇది కూడిక
పూర్ణాంక పాయింట్ల వ్యవస్థ (నైపుణ్య-పేరు సరిపోలిక, పేరు/ట్యాగ్/వివరణ టోకెన్ సారూప్యత,
నేపథ్య-కారణ సూచనలు, ప్రొవైడర్-సూచన బోనస్/పెనాల్టీ). అత్యధిక స్కోర్ కలిగిన
`AUTO_MAX_SKILLS = 5` నైపుణ్యాల్లో `score >= AUTO_MIN_SCORE = 3` ఉన్నవి కాల్ చేయగల
టూల్స్గా ఇంజెక్ట్ చేయబడతాయి; సమాన స్కోర్లను ముందుగా `installCount`, ఆపై పేరు ఆధారంగా నిర్ణయిస్తారు. పూర్తి పాయింట్ల పట్టిక కోసం ఈ
డాక్యుమెంట్లో ముందుగా ఉన్న [**టూల్ స్కీమా జనరేషన్ → AUTO స్కోరింగ్**](#auto-scoring) చూడండి;
ఫ్లోట్ `0.6`-శైలి థ్రెషోల్డ్ లేదు మరియు `registry.ts` స్కోరింగ్ కూడా లేదు.

## అంతర్నిర్మిత నైపుణ్యాల కేటలాగ్

OmniRouteలో `src/lib/skills/builtin/`లో ఎంపిక చేసి రూపొందించిన అంతర్నిర్మిత నైపుణ్యాల సమితి ఉంటుంది. అత్యంత సాధారణమైనవి:

### బ్రౌజర్ ఆటోమేషన్ నైపుణ్యం

బ్రౌజర్ నైపుణ్యం (`src/lib/skills/builtin/browser.ts`) Playwright/Puppeteer ద్వారా హెడ్లెస్ బ్రౌజర్ ఆటోమేషన్ను అందిస్తుంది. **ఇది అమలు చేయబడింది, కానీ డిఫాల్ట్ నైపుణ్యాల కేటలాగ్లో లేదు** — దీన్ని ఉపయోగించడానికి, బ్రౌజర్ ఎక్స్టెన్షన్ ప్లగిన్ను విడిగా ఇన్స్టాల్ చేయండి.

```ts
// మీ కాన్ఫిగ్లో ప్రారంభించండి
const config: SkillConfig = {
  enabled: true,
  mode: SkillMode.MANUAL, // ఎల్లప్పుడూ స్పష్టమైన అమలును కోరండి
  allowedSkills: ["browser"],
  timeout: 60000, // పేజీ లోడ్ల కోసం 60సె
  maxRetries: 1,
};
```

### ఇతర అంతర్నిర్మిత వర్గాలు

| వర్గం     | నైపుణ్యాలు                                    | మోడ్   |
| --------- | --------------------------------------------- | ------ |
| ఫైల్ I/O  | `file_read`, `file_write`                     | AUTO   |
| HTTP      | `http_request`                                | AUTO   |
| శోధన      | `web_search`                                  | AUTO   |
| కోడ్ అమలు | `eval_code` (శాండ్బాక్స్డ్ JavaScript/Python) | HYBRID |
| సిస్టమ్   | `execute_command` (శాండ్బాక్స్డ్ CLI అమలు)    | MANUAL |

### అనుకూల నైపుణ్యాన్ని జోడించడం

ప్లగిన్ సిస్టమ్ ద్వారా అనుకూల నైపుణ్యాన్ని ఎలా జోడించాలో తెలుసుకోవడానికి [ప్లగిన్ SDK & నైపుణ్యాల ఇంటిగ్రేషన్](./PLUGIN_SDK.md) చూడండి.
