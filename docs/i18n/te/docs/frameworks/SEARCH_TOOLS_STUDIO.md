## అవలోకనం

## ట్యాబ్లు

### శోధన ట్యాబ్

ఇప్పటికే ఉన్న `SearchForm` + `ResultsPanel` + `RerankPanel`ను ఒక ట్యాబ్గా అభివృద్ధి చేస్తుంది:

- క్వెరీ → ఫలితాలు (శీర్షిక, URL, స్నిపెట్, సంబంధితత స్కోర్).
- కాన్ఫిగరేషన్ పేన్లో ప్రొవైడర్ మెటాడేటా (ఖర్చు, కోటా, స్థితి).
- రీర్యాంక్ విభాగం: ఒక రీర్యాంక్ మోడల్ను ఎంచుకుని, ఫలితాలను తిరిగి క్రమబద్ధీకరించి, `positionDelta`ను చూపుతుంది.
- శోధన ప్రొవైడర్లు ఏవీ కాన్ఫిగర్ చేయబడనప్పుడు CTAతో కూడిన ఖాళీ స్థితి.
- `SearchHistory.tsx` ద్వారా శోధన చరిత్ర.
- `POST /v1/search`ను కాల్ చేస్తుంది (ఇప్పటికే ఉన్న ఎండ్పాయింట్, మార్పులు లేవు).

### స్క్రేప్ ట్యాబ్

`POST /v1/web/fetch` ద్వారా URL నుండి కంటెంట్ను సంగ్రహించడానికి కొత్త ట్యాబ్ (ప్లాన్ 05లో సృష్టించబడింది):

- ఇన్పుట్: URL + పూర్తి-పేజీ టాగుల్ + ఫార్మాట్ సెలెక్టర్ (markdown / text / HTML).
- సమర్పించండి → ఫెచ్ చేయండి → `ScrapeResult.tsx`ను రెండర్ చేయండి.
- `ScrapeResult` markdown ప్రివ్యూ + ముడి కంటెంట్ టాగుల్ను రెండర్ చేస్తుంది.
- పరిమితి: ప్రతిస్పందన బాడీ **256 KB** కంటే ఎక్కువగా ఉంటే, UI `(కుదించబడింది, ముడి కంటెంట్ను వీక్షించండి)` అని చూపించి, ముడి కంటెంట్ను Monaco మోడల్లో తెరుస్తుంది (D21).
- మెటాడేటా ప్యానెల్: ప్రొవైడర్ (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search), లేటెన్సీ, ఖర్చు, ప్రతిస్పందన పరిమాణం, లింకుల సంఖ్య.
- `useScrapeFetch.ts` హుక్ను ఉపయోగిస్తుంది.

### పోలిక ట్యాబ్

ఒకే క్వెరీ/URLను గరిష్ఠంగా **4 ప్రొవైడర్లలో సమాంతరంగా** అమలు చేస్తుంది (D22):

- ప్రతి ప్రొవైడర్ కోసం పక్కపక్కన నిలువు వరుసలు.
- మెట్రిక్లు: లేటెన్సీ, ఖర్చు, ఫలితాల సంఖ్య, ప్రతిస్పందన పరిమాణం.
- శోధన కోసం URL ఓవర్ల్యాప్ లెక్కింపు (ప్రారంభ ఫలితంతో పోలిస్తే ఉమ్మడి URLల సంఖ్య).
- ప్రతి ప్రొవైడర్ కోసం `POST /v1/search` (శోధన) లేదా `POST /v1/web/fetch` (స్క్రేప్)ను కాల్ చేస్తుంది.

## ప్రొవైడర్ కేటలాగ్

`ProviderCatalog.tsx`, `GET /api/search/providers` నుండి పూర్తి ప్రొవైడర్ జాబితాను అందిస్తుంది
(fetch ప్రొవైడర్లను చేర్చడానికి F4లో విస్తరించబడింది):

| `kind` | `"search"` (20 ప్రొవైడర్లు) లేదా `"fetch"` (firecrawl, jina-reader, tavily-search, tinyfish, nimble-search, anysearch-search) |

క్రెడెన్షియల్స్ ఉన్నాయో లేదో, అలాగే అన్ని కీలు ప్రస్తుతం కూల్డౌన్లో ఉన్నాయో లేదో తనిఖీ చేయడం ద్వారా
అభ్యర్థన సమయంలో **స్థితి నిర్ధారించబడుతుంది**.

## కోడ్ ఎగుమతి

`ExportCodeModal` (Playground Studio నుండి దిగుమతి చేయబడింది) + `codeExport.ts`, `/v1/search` మరియు `/v1/web/fetch` కాల్స్ రెండింటికీ
curl / Python / TypeScript స్నిపెట్లను రూపొందిస్తాయి.
API కీ ప్లేస్హోల్డర్ ఎల్లప్పుడూ `$OMNIROUTE_API_KEY` (D11, Playground Studioతో భాగస్వామ్యం చేయబడింది).

## బ్యాకెండ్ మార్పులు

ఈ ఫీచర్ కోసం ఒకే ఒక్క బ్యాకెండ్ మార్పు అవసరమైంది:

### విస్తరించబడిన `GET /api/search/providers`

`src/app/api/search/providers/route.ts` ఈ విధంగా విస్తరించబడింది:

- మొత్తం 6 fetch ప్రొవైడర్లను (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`) అర్రేలో చేర్చడం.
- ప్రతి ఐటమ్కు `kind: "search" | "fetch"` జోడించడం.
- ప్రత్యక్ష క్రెడెన్షియల్ స్థితి నుండి నిర్ధారించబడిన `status: "configured" | "missing" | "rate_limited"` జోడించడం.
- బ్యాక్వర్డ్ కంపాటిబిలిటీని కొనసాగించడం — ఇప్పటికే ఉన్న ఫీల్డ్లు (`id`, `name`, మొదలైనవి) మారవు.
