## ఇది ఏమిటి

OmniRoute ఒక **Obsidian** వాల్ట్కు **సందర్భ మూలం**గా కనెక్ట్ అవుతుంది — ఇది అంతర్నిర్మిత
MCP సర్వర్ ద్వారా ఏజెంట్లు చదివే మరియు వ్రాసే స్థానిక Markdown జ్ఞాన భాండాగారం.
ఈ ఇంటిగ్రేషన్ డెస్క్టాప్ యాప్లో నడుస్తున్న **Obsidian Local REST API** కమ్యూనిటీ
ప్లగిన్తో కమ్యూనికేట్ చేస్తుంది. అందువల్ల ఏజెంట్లు నోట్లను శోధించడం, ఫైళ్లను
చదవడం/వ్రాయడం/ప్యాచ్ చేయడం, వాల్ట్ను జాబితా చేయడం, రోజువారీ/వారపు పీరియాడిక్
నోట్లతో పని చేయడం, ట్యాగ్లను నిర్వహించడం, Obsidian కమాండ్లను అమలు చేయడం, అలాగే
(ఐచ్ఛికంగా) ద్విదిశాత్మక డెస్క్టాప్↔మొబైల్ వాల్ట్ సింక్ను సమన్వయం చేయడం చేయగలరు.

క్లయింట్ (`src/lib/obsidian/api.ts`) Local REST APIని కింది సౌకర్యాలతో ర్యాప్ చేస్తుంది:

- తాత్కాలిక `5xx` లోపాల కోసం **బ్యాక్ఆఫ్తో పునఃప్రయత్నం**, `AbortController` ద్వారా **30-సెకన్ల గడువు**.
- **టైప్డ్ లోప వర్గీకరణ** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- సాధారణంగా జరిగే పోర్ట్ పొరపాటును సూచించే, సులభంగా అర్థమయ్యే **"Obsidianను చేరుకోలేకపోయింది" సూచన**
  (HTTP కోసం `27123`, `27124`లోని MCP ఎండ్పాయింట్ **కాదు**) మరియు Tailscale రూపం.
- స్పేస్లు/స్లాష్లు ఉన్న నోట్ పాత్లు సురక్షితంగా ఉండేలా వాల్ట్కు సంబంధిత **పాత్ ఎన్కోడింగ్**.

## సెటప్

Obsidian టోకెన్ లేదా బేస్ URL కోసం **ఎలాంటి ఎన్విరాన్మెంట్ వేరియబుల్ లేదు** — రెండూ
`src/lib/db/obsidian.ts` ద్వారా SQLite `key_value` పట్టికలో (`obsidian` నేమ్స్పేస్)
నిల్వ చేయబడతాయి. టోకెన్ **నిల్వలో ఉన్నప్పుడు ఎన్క్రిప్ట్ చేయబడుతుంది** (AES-256-GCM,
ప్లెయిన్టెక్స్ట్ బ్యాక్వర్డ్-కంపాటిబిలిటీ ఫాల్బ్యాక్తో). Endpoint డ్యాష్బోర్డ్లోని
**Context Sources** ట్యాబ్ (`ObsidianSourceCard`) నుంచి లేదా సెట్టింగ్స్ REST API ద్వారా కాన్ఫిగర్ చేయండి.

> [!IMPORTANT]
> **Obsidian Local REST API** ప్లగిన్ తప్పనిసరిగా ఇన్స్టాల్ చేయబడి, నడుస్తూ ఉండాలి. దాని REST
> ఇంటర్ఫేస్ **HTTP `127.0.0.1:27123`**లో వింటుంది (డిఫాల్ట్ బేస్ URL). పోర్ట్ `27124`
> ఒక _ప్రత్యేక_ MCP/HTTPS ఎండ్పాయింట్ మరియు సెట్టింగ్స్ రూట్ దాన్ని స్పష్టంగా తిరస్కరిస్తుంది.
> మరొక పరికరం నుంచి కనెక్ట్ అవుతున్నట్లయితే, `http://<tailscale-ip>:27123` ఉపయోగించండి.

### కాన్ఫిగరేషన్ కీలు (SQLite `key_value`, నేమ్స్పేస్ `obsidian`)

| కీ                | ప్రయోజనం                                             | ఎన్క్రిప్ట్ చేయబడిందా |
| ----------------- | ---------------------------------------------------- | --------------------- |
| `api_key`         | Local REST API బేరర్ టోకెన్                          | అవును                 |
| `base_url`        | REST బేస్ URL (డిఫాల్ట్ `http://127.0.0.1:27123`)    | కాదు                  |
| `vault_path`      | వాల్ట్ డైరెక్టరీకి సంపూర్ణ పాత్ (సింక్ కోసం)         | కాదు                  |
| `webdav_username` | రూపొందించబడిన WebDAV వినియోగదారు పేరు (వాల్ట్ సింక్) | కాదు                  |
| `webdav_password` | రూపొందించబడిన WebDAV పాస్వర్డ్ (వాల్ట్ సింక్)        | అవును                 |
| `webdav_enabled`  | WebDAV వాల్ట్ సింక్ ప్రారంభించబడిందా                 | కాదు                  |

### REST ద్వారా కాన్ఫిగర్ చేయడం

```bash
# Local REST API టోకెన్ను సేవ్ చేసి ధ్రువీకరించండి (POST స్థితి తనిఖీ ద్వారా ధ్రువీకరిస్తుంది)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# కనెక్షన్ స్థితిని తనిఖీ చేయండి (connected, hasToken, baseUrl, vaultPathను తిరిగి ఇస్తుంది)
curl http://localhost:20128/api/settings/obsidian

# డిస్కనెక్ట్ చేయండి (నిల్వ చేసిన టోకెన్ను తొలగిస్తుంది)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

అన్ని మెథడ్లకు డ్యాష్బోర్డ్ ప్రామాణీకరణ అవసరం. `POST`, పోర్ట్ `27124`లోని ఏ URLనైనా
తిరస్కరిస్తుంది మరియు నిల్వ చేయడానికి ముందు Local REST API స్థితి ఎండ్పాయింట్ను కాల్ చేసి టోకెన్ను ధ్రువీకరిస్తుంది.

### WebDAV వాల్ట్ సింక్

`src/app/api/settings/obsidian/webdav/route.ts`, ఐచ్ఛిక WebDAV-ఆధారిత
వాల్ట్ సింక్ను నిర్వహిస్తుంది (`src/lib/obsidianSync.ts` ద్వారా నడపబడుతుంది). దీన్ని ప్రారంభించడం వల్ల
OmniRoute ఒక స్థానిక వాల్ట్ డైరెక్టరీని ఉపయోగించేలా చేసి, యాదృచ్ఛిక WebDAV వినియోగదారు పేరు/పాస్వర్డ్ జోడీని సృష్టిస్తుంది:

```bash
# వాల్ట్ డైరెక్టరీ కోసం WebDAV సింక్ను ప్రారంభించండి (వినియోగదారు పేరు/పాస్వర్డ్ను సృష్టిస్తుంది)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# WebDAV సింక్ స్థితిని పొందండి (ప్రారంభించబడి ఉన్నప్పుడు మాత్రమే ఆధారాలు తిరిగి ఇవ్వబడతాయి)
curl http://localhost:20128/api/settings/obsidian/webdav

# WebDAV సింక్ను నిలిపివేయండి (ఆధారాలు + నిర్వహిత .stignoreను తొలగిస్తుంది)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### ప్రతి-API-కీ సందర్భ మూలం (ఐచ్ఛికం)

`api_key_context_sources` పట్టిక ద్వారా Obsidian కాన్ఫిగరేషన్ను **ప్రతి API కీకి**
స్కోప్ చేయవచ్చు (`src/lib/db/apiKeyContextSources.ts`). ఒక MCP కాల్ ప్రామాణీకరించబడిన API
కీ idని కలిగి ఉన్నప్పుడు, `getObsidianConfigForApiKey()` ఆ కీకి చెందిన స్వంత టోకెన్/బేస్-URL/వాల్ట్-పాత్కు
(`source: "api_key"`) ప్రాధాన్యం ఇస్తుంది; అవి లేకపోతే గ్లోబల్ కాన్ఫిగరేషన్కు (`source: "global"`) ఫాల్బ్యాక్ అవుతుంది.

## MCP సాధనాలు (22)

`open-sse/mcp-server/tools/obsidianTools.ts`లో నిర్వచించబడ్డాయి. token/base-URL ప్రతి కాల్కు పరిష్కరించబడతాయి (మొదట ప్రతి API కీకి సంబంధించినవి, ఆపై గ్లోబల్). OmniRoute **sync server**ను యాక్సెస్ చేసే సాధనాలకు (నాలుగు `obsidian_sync_*` సాధనాలు) అదనంగా OmniRoute సెట్టింగ్లలో కాన్ఫిగర్ చేసిన sync auth token అవసరం.

| `obsidian_search_structured` | JSON Logic ఎక్స్ప్రెషన్ను (and/or/regex/path ఫిల్టర్లు) ఉపయోగించి శోధిస్తుంది.                            |
| `obsidian_read_note`         | vault-relative path ద్వారా నోట్ను చదువుతుంది; ఐచ్ఛికంగా నిర్దిష్ట heading/block/frontmatterను చదువుతుంది. |
| `obsidian_list_vault`        | vaultలోని ఫైల్లు మరియు డైరెక్టరీలను (ఎంట్రీల ట్రీగా) జాబితా చేస్తుంది.                                    |
| `obsidian_get_document_map`  | నోట్ heading నిర్మాణాన్ని headings → line numbers మ్యాప్గా పొందుతుంది.                                    |
| `obsidian_get_note_metadata` | పూర్తి కంటెంట్ లేకుండా frontmatter, ట్యాగ్లు, లింక్లు, అక్షర/పదాల సంఖ్యను పొందుతుంది.                     |
| `obsidian_get_active_file`   | Obsidianలో ప్రస్తుతం యాక్టివ్గా ఉన్న ఫైల్ path + contentను పొందుతుంది.                                    |
| `obsidian_get_periodic_note` | ఒక తేదీకి సంబంధించిన రోజువారీ/వారపు/నెలవారీ periodic noteను పొందుతుంది (వదిలివేస్తే నేటిది).              |
| `obsidian_get_tags`          | అన్ని vault ట్యాగ్లను వాటి పునరావృత సంఖ్యలతో జాబితా చేస్తుంది.                                            |
| `obsidian_list_commands`     | అందుబాటులో ఉన్న Obsidian command IDలను జాబితా చేస్తుంది (`obsidian_execute_command`తో ఉపయోగించండి).       |
| `obsidian_sync_status`       | OmniRoute sync server స్థితి: రన్ అవుతోందా, vault పేరు, port, uptime, చివరి sync.                         |
| `obsidian_sync_conflicts`    | పరిష్కరించని sync conflictsను (path, conflict path, గుర్తించిన సమయం) జాబితా చేస్తుంది.                    |

### రైట్ సాధనాలు (`write:obsidian`)

| సాధనం                            | వివరణ                                                                                              |
| -------------------------------- | -------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | ఇచ్చిన Markdown కంటెంట్తో నోట్ను సృష్టిస్తుంది లేదా ఓవర్రైట్ చేస్తుంది.                            |
| `obsidian_append_note`           | నోట్కు కంటెంట్ను జోడిస్తుంది; ఐచ్ఛికంగా నిర్దిష్ట heading/blockకు జోడిస్తుంది.                     |
| `obsidian_patch_note`            | heading, block లేదా frontmatter field వద్ద ఖచ్చితంగా append/prepend/replace చేస్తుంది.             |
| `obsidian_delete_note`           | vault నుండి నోట్ను శాశ్వతంగా తొలగిస్తుంది.                                                         |
| `obsidian_move_note`             | vaultలో నోట్ను తరలిస్తుంది లేదా పేరు మారుస్తుంది.                                                  |
| `obsidian_execute_command`       | Obsidian commandను దాని command ID ద్వారా అమలు చేస్తుంది.                                          |
| `obsidian_open_file`             | Obsidianలో ఫైల్ను తెరుస్తుంది (అది లేకపోతే సృష్టిస్తుంది).                                         |
| `obsidian_sync_trigger`          | తక్షణ ద్విదిశాత్మక desktop↔mobile vault syncను ట్రిగ్గర్ చేస్తుంది.                                |
| `obsidian_sync_resolve_conflict` | sync conflictను పరిష్కరిస్తుంది: `local` (mobile), `remote` (desktop), లేదా `keep-both` ఉంచుతుంది. |

> [!NOTE]
> `obsidian_patch_note` targets, `heading | block | frontmatter`లో ఒకదాన్ని `targetType`గా,
> అలాగే `append | prepend | replace`లో ఒకదాన్ని `operation`గా, ఐచ్ఛిక
> `createTargetIfMissing`తో అంగీకరిస్తాయి. నాలుగు `obsidian_sync_*` సాధనాలు స్థానిక sync
> serverతో (డిఫాల్ట్గా `http://127.0.0.1:27781`) కమ్యూనికేట్ చేస్తాయి మరియు వాటికి sync token అవసరం.

### స్కోప్లు

రీడ్ సాధనాలకు `read:obsidian` అవసరం; రైట్ సాధనాలకు `write:obsidian` అవసరం. అమలు విధానం
Notionతో సమానంగా ఉంటుంది — ఇది `open-sse/mcp-server/server.ts`లోని
`withScopeEnforcement()` ద్వారా నిర్వహించబడుతుంది, `OMNIROUTE_MCP_ENFORCE_SCOPES=true`పై
గేట్ చేయబడుతుంది, అలాగే అనుమతించబడిన స్కోప్లు `OMNIROUTE_MCP_SCOPES` లేదా API కీ scope context
నుండి తీసుకోబడతాయి. [MCP-SERVER.md](./MCP-SERVER.md) చూడండి.

## ఎండ్పాయింట్లు

| పద్ధతి   | పాత్                            | ఉద్దేశ్యం                                                               |
| -------- | ------------------------------- | ----------------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | `{ connected, hasToken, baseUrl, vaultPath }`ను తిరిగి ఇస్తుంది.        |
| `POST`   | `/api/settings/obsidian`        | టోకెన్ను సేవ్ చేసి ధ్రువీకరిస్తుంది (`27124` పోర్ట్ను తిరస్కరిస్తుంది). |
| `DELETE` | `/api/settings/obsidian`        | డిస్కనెక్ట్ చేస్తుంది (నిల్వ చేసిన టోకెన్ను తొలగిస్తుంది).              |
| `GET`    | `/api/settings/obsidian/webdav` | WebDAV సింక్ స్థితి + క్రెడెన్షియల్స్ (ప్రారంభించబడి ఉన్నప్పుడు).       |
| `POST`   | `/api/settings/obsidian/webdav` | వాల్ట్ డైరెక్టరీ కోసం WebDAV సింక్ను ప్రారంభిస్తుంది.                   |
| `DELETE` | `/api/settings/obsidian/webdav` | WebDAV సింక్ను నిలిపివేస్తుంది.                                         |

> ఇవి డ్యాష్బోర్డ్ సెట్టింగ్స్ రూట్లు. వాల్ట్ను Obsidian
> Local REST API (కాన్ఫిగర్ చేసిన `base_url`) ద్వారా మరియు పైన పేర్కొన్న MCP సాధనాల ద్వారా యాక్సెస్ చేస్తారు —
> పబ్లిక్ `/v1` Obsidian ప్రాక్సీ ఎండ్పాయింట్ లేదు.

## వినియోగ సందర్భాలు

- **వాల్ట్ ఆధారిత సమాధానాలు** — ముందుగా `obsidian_search_simple` / `obsidian_search_structured`,
  ఆపై `obsidian_read_note`ను ఉపయోగించడం ద్వారా ఏజెంట్ మీ వాస్తవ నోట్స్ ఆధారంగా సమాధానమిస్తుంది.
- **నోట్స్ రచన / జర్నలింగ్** — ఏజెంట్ అవుట్పుట్, సారాంశాలు లేదా రోజువారీ నోట్స్ను
  (`obsidian_get_periodic_note`) వాల్ట్లో లాగ్ చేయడానికి `obsidian_write_note`, `obsidian_append_note` లేదా
  ఖచ్చితమైన మార్పుల కోసం `obsidian_patch_note`ను ఉపయోగించండి.
- **వాల్ట్ నావిగేషన్** — చదవడానికి/వ్రాయడానికి ముందు నిర్మాణాన్ని అన్వేషించేందుకు
  `obsidian_list_vault`, `obsidian_get_document_map` మరియు `obsidian_get_tags`ను ఉపయోగించండి.
- **Obsidian ఆటోమేషన్** — ఏజెంట్ ద్వారా ప్లగిన్లు/కమాండ్లను నడపడానికి
  `obsidian_list_commands` + `obsidian_execute_command`; UIలో నోట్ను చూపించడానికి `obsidian_open_file`.
- **మొబైల్ సింక్** — WebDAV సింక్ను ప్రారంభించి, ఆపై డెస్క్టాప్↔మొబైల్ను సమన్వయం చేయడానికి మరియు వైరుధ్యాలను పరిష్కరించడానికి
  `obsidian_sync_trigger` / `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  ఉపయోగించండి.
