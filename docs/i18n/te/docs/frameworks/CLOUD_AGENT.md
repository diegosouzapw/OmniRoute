OmniRoute మూడవ పక్షం క్లౌడ్-హోస్ట్ చేసిన కోడింగ్ ఏజెంట్లను (Codex Cloud, Cursor,
Devin, Jules) దీర్ఘకాలం అమలయ్యే టాస్క్లుగా సమన్వయం చేస్తుంది. ప్రతి ఏజెంట్ను ఏకరీతి ఇంటర్ఫేస్ వెనుక ఉంచుతారు, తద్వారా
క్లయింట్లు ప్రొవైడర్-నిర్దిష్ట APIలతో వ్యవహరించాల్సిన అవసరం లేకుండా ప్రాంప్ట్ + రిపో URLను సమర్పించి ఫలితాలను పొందగలరు.

Cloud Agent టాస్క్ సాధారణ చాట్ కంప్లీషన్ **కాదు**. ఇది నిమిషాల నుంచి గంటల వరకు పట్టగల,
Pull Requestను తన ఆర్టిఫాక్ట్గా రూపొందించగల, తదుపరి సందేశాలకు మరియు (కొన్ని ప్రొవైడర్లలో)
ప్లాన్ ఆమోద దశలకు మద్దతిచ్చే, నిలకడైన బహుళ-దశల పని యూనిట్.

రిజిస్ట్రీ: `src/lib/cloudAgent/registry.ts` — `getAgent(providerId)`,
`getAvailableAgents()`, మరియు `isCloudAgentProvider(providerId)`లను ఎక్స్పోర్ట్ చేస్తుంది. రిజిస్ట్రీ అనేది
మాడ్యూల్ లోడ్ సమయంలో నింపబడే సాధారణ ఇన్-మెమరీ `Record<string, CloudAgentBase>`.

## ఆర్కిటెక్చర్

```
క్లయింట్ (డ్యాష్బోర్డ్ / CLI / API)
  → POST /api/v1/agents/tasks (మేనేజ్మెంట్ ప్రామాణీకరణ అవసరం)
    → CreateCloudAgentTaskSchema ధ్రువీకరణ (Zod)
    → registry.getAgent(providerId)
    → getCloudAgentCredentials(providerId)
      └─ getProviderConnections({ provider, isActive: true }) నుంచి పొందుతుంది
         (మొదట apiKey, అందుబాటులో లేకపోతే accessToken)
    → agent.createTask({ prompt, source, options }, credentials)
      └─ అప్స్ట్రీమ్ ప్రొవైడర్ APIకి HTTP POST
      └─ అంతర్గత id + externalIdతో CloudAgentTaskను అందిస్తుంది
    → cloud_agent_tasks (SQLite)లోకి insertCloudAgentTask(...)

పోలింగ్ (చదివేటప్పుడు లేజీ సింక్):
  GET /api/v1/agents/tasks/[id]
    → getCloudAgentTaskById(id)
    → agent.getStatus(externalId, credentials)  // స్థితి + కార్యకలాపాలను రిఫ్రెష్ చేస్తుంది
    → కొత్త స్థితి, ఫలితం, completed_atతో updateCloudAgentTask(...)
    → సీరియలైజ్ చేసిన టాస్క్ను అందిస్తుంది

పరస్పర చర్యలు:
  POST /api/v1/agents/tasks/[id]  బాడీ: { action: "approve" | "message" | "cancel" }
    → agent.approvePlan(externalId, credentials)        "approve" కోసం
    → agent.sendMessage(externalId, message, credentials) "message" కోసం
    → స్థితి "cancelled"కు మారుతుంది                    "cancel" కోసం (లోకల్లో మాత్రమే)
```

సింక్ **లేజీ**గా జరుగుతుంది: ప్రతి `GET /tasks/[id]` అభ్యర్థనపై స్థితి అప్స్ట్రీమ్ నుంచి రిఫ్రెష్ చేయబడుతుంది.
బ్యాక్గ్రౌండ్ పోలర్ లేదు. తాజా స్థితి అవసరమైన డ్యాష్బోర్డ్లు సముచిత వ్యవధిలో GET
ఎండ్పాయింట్ను పోల్ చేయాలి.

## `CloudAgentBase` ఇంటర్ఫేస్

మూలం: `src/lib/cloudAgent/baseAgent.ts`

```typescript
export interface AgentCredentials {
  apiKey: string;
  baseUrl?: string;
}

export interface CreateTaskParams {
  prompt: string;
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
}

export interface GetStatusResult {
  status: CloudAgentStatus;
  externalId?: string;
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
}

export abstract class CloudAgentBase {
  abstract readonly providerId: string;
  abstract readonly baseUrl: string;

  abstract createTask(p: CreateTaskParams, c: AgentCredentials): Promise<CloudAgentTask>;
  abstract getStatus(externalId: string, c: AgentCredentials): Promise<GetStatusResult>;
  abstract approvePlan(externalId: string, c: AgentCredentials): Promise<void>;
  abstract sendMessage(
    externalId: string,
    message: string,
    c: AgentCredentials
  ): Promise<CloudAgentActivity>;
  abstract listSources(
    c: AgentCredentials
  ): Promise<{ name: string; url: string; branch?: string }[]>;

  protected mapStatus(raw: string): CloudAgentStatus; // హ్యూరిస్టిక్ అప్స్ట్రీమ్-స్ట్రింగ్ → enum
  protected generateTaskId(): string; // `task_<ts>_<rand>`
  protected generateActivityId(): string; // `act_<ts>_<rand>`
}
```

`CodexCloudAgent.approvePlan` ఉద్దేశపూర్వకంగా ఎర్రర్ను విసురుతుంది — Codex Cloud స్వయంచాలకంగా ప్లాన్ చేస్తుంది మరియు
దీనికి ఆమోద గేట్ లేదు. `CodexCloudAgent.listSources` `[]`ను తిరిగి ఇస్తుంది.

`CursorCloudAgent`, Cursor యొక్క Background / Cloud Agentsను దాని అధికారిక REST
API (`api.cursor.com/v0`) ద్వారా **వినియోగదారు లేదా సేవా-ఖాతా API కీ**తో నడుపుతుంది — ఇది Cursor IDE యొక్క OAuth సెషన్ను తిరిగి ఉపయోగించడం కంటే సురక్షితమైన,
ఫస్ట్-పార్టీ ప్రత్యామ్నాయం (నిషేధానికి గురయ్యే ప్రమాద హెచ్చరికను కలిగి ఉన్న ప్రొవైడర్ `cursor`).
ఇది సాధారణ REST అడాప్టర్ (`@cursor/sdk` స్థానిక డిపెండెన్సీ లేదు).
`approvePlan` ఎర్రర్ను విసురుతుంది (Cursor ఏజెంట్లు స్వయంప్రతిపత్తితో నడుస్తాయి); `listSources` ఆ కీ ద్వారా
యాక్సెస్ చేయగల రిపోజిటరీలను జాబితా చేస్తుంది. Cursor UPPERCASE స్థితి enumsను
(`CREATING`/`RUNNING`/`FINISHED`/`ERROR`) తిరిగి ఇస్తుంది, ఇవి భాగస్వామ్య
`CloudAgentStatus`కు స్పష్టంగా మ్యాప్ చేయబడతాయి. కోడ్ మార్పు లేకుండానే API వెర్షన్/పాత్ను
సరిచేయగలిగేలా ప్రతి క్రెడెన్షియల్కు `baseUrl`ను ఓవర్రైడ్ చేయవచ్చు.

## డొమైన్ రకాలు

మూలం: `src/lib/cloudAgent/types.ts`

```typescript
export const CLOUD_AGENT_STATUS = {
  QUEUED: "queued",
  RUNNING: "running",
  AWAITING_APPROVAL: "awaiting_approval",
  COMPLETED: "completed",
  FAILED: "failed",
  CANCELLED: "cancelled",
} as const;

export interface CloudAgentSource {
  repoName: string;
  repoUrl: string; // తప్పనిసరిగా చెల్లుబాటు అయ్యే URL అయి ఉండాలి
  branch?: string;
}

export interface CloudAgentResult {
  prUrl?: string;
  prNumber?: number;
  commitMessage?: string;
  diffUrl?: string;
  summary?: string;
  duration?: number; // సెకన్లు, ధన పూర్ణసంఖ్య
  cost?: number; // ధన దశాంశ సంఖ్య
}

export interface CloudAgentActivity {
  id: string;
  type: "plan" | "command" | "code_change" | "message" | "error" | "completion";
  content: string;
  timestamp: string; // ISO 8601
  metadata?: Record<string, unknown>;
}

export interface CloudAgentTask {
  id: string; // అంతర్గత `task_...` id
  providerId: "jules" | "devin" | "codex-cloud" | "cursor-cloud";
  externalId?: string; // అప్స్ట్రీమ్ ప్రొవైడర్ యొక్క id
  status: CloudAgentStatus;
  prompt: string; // 1..10000 అక్షరాలు
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
  createdAt: string;
  updatedAt: string;
  completedAt?: string;
}
```

ధృవీకరణ స్కీమాలు (`CreateCloudAgentTaskSchema`, `UpdateCloudAgentTaskSchema`) రకాలతో
పాటు ఎగుమతి చేయబడతాయి మరియు రూట్ హ్యాండ్లర్ల ద్వారా ఉపయోగించబడతాయి.

## డేటాబేస్

మూలం: `src/lib/cloudAgent/db.ts` — పట్టిక `createCloudAgentTaskTable()` ద్వారా అవసరమైనప్పుడు సృష్టించబడుతుంది (`src/lib/cloudAgent/index.ts`లో మాడ్యూల్ దిగుమతి సమయంలో కూడా ఇది కాల్ చేయబడుతుంది).

```sql
CREATE TABLE IF NOT EXISTS cloud_agent_tasks (
  id           TEXT PRIMARY KEY,
  provider_id  TEXT NOT NULL,
  external_id  TEXT,
  status       TEXT NOT NULL DEFAULT 'queued',
  prompt       TEXT NOT NULL,
  source       TEXT NOT NULL,             -- JSON
  options      TEXT DEFAULT '{}',         -- JSON
  result       TEXT,                       -- JSON
  activities   TEXT DEFAULT '[]',          -- JSON
  error        TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_provider ON cloud_agent_tasks(provider_id);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_status   ON cloud_agent_tasks(status);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_created  ON cloud_agent_tasks(created_at DESC);
```

SQL ఇంజెక్షన్ను నిరోధించడానికి `updateCloudAgentTask` ఒక **కాలమ్ అనుమతి జాబితా**ను అమలు చేస్తుంది:
`status`, `prompt`, `source`, `options`, `result`, `activities`, `error`,
`completed_at`. పాక్షిక నవీకరణలోని ఇతర ఏ కీ అయినా నిశ్శబ్దంగా తొలగించబడుతుంది.

`requireManagementAuth`ను ర్యాప్ చేస్తుంది). కమిట్ `588a0333`

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Fix the bug in src/foo.ts where the parser returns null",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    },
    "options": {
      "autoCreatePr": true,
      "planApprovalRequired": false
    }
  }'
```

  "data": {

### రద్దు చేయడం (స్థానిక స్థితి మాత్రమే)

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"cancel"}'
```

`cancel` స్థానిక DBలోని `status`ను `"cancelled"`కు మారుస్తుంది, కానీ అప్స్ట్రీమ్ ప్రొవైడర్ను
కాల్ **చేయదు** — `CloudAgentBase`లో నిలిపివేత RPC లేదు. అప్స్ట్రీమ్ బిల్లింగ్ను ఆపడానికి,
ప్రొవైడర్కు చెందిన కన్సోల్లో టాస్క్ను ముగించండి.

## REST API — క్లౌడ్ ప్రొవైడర్ ప్లంబింగ్

`src/app/api/cloud/` కింద ఉన్న ఈ సహాయక ఎండ్పాయింట్లు, ప్రొవైడర్ కనెక్షన్ మెటాడేటాను చదవడానికి మరియు మోడల్ అలియాస్లను పరిష్కరించడానికి రిమోట్ క్లయింట్లు
(CLI, Electron యాప్ లేదా సింక్ వర్కర్లు) ఉపయోగిస్తాయి. టాస్క్ ఎండ్పాయింట్లు ఉపయోగించే మేనేజ్మెంట్ ఆథ్తో కాకుండా, ఇవి **సాధారణ API కీ**
ద్వారా (`validateApiKey` ఉపయోగించి) ప్రామాణీకరించబడతాయి.

| పద్ధతి | పాత్                            | ఉద్దేశ్యం                                                                            |
| ------ | ------------------------------- | ------------------------------------------------------------------------------------ |
| POST   | `/api/cloud/auth`               | API కీని ధృవీకరించి, మాస్క్ చేసిన కనెక్షన్ మెటాడేటా + మోడల్ అలియాస్లను తిరిగి ఇవ్వడం |
| PUT    | `/api/cloud/credentials/update` | `accessToken` / `refreshToken` / `expiresAt`లను రీఫ్రెష్ చేయడం                       |
| POST   | `/api/cloud/model/resolve`      | మోడల్ అలియాస్ను `{ provider, model }`గా పరిష్కరించడం                                 |
| GET    | `/api/cloud/models/alias`       | అన్ని మోడల్ అలియాస్లను జాబితా చేయడం                                                  |
| PUT    | `/api/cloud/models/alias`       | మోడల్ అలియాస్ను సెట్ చేయడం (ప్రారంభించబడి ఉంటే Cloudకు ఆటో-సింక్ చేయడం)              |

`/api/cloud/auth` ముడి `apiKey` / `accessToken` / `refreshToken`లను ఎప్పుడూ తిరిగి ఇవ్వదు. ఇది
`hasApiKey`, `hasAccessToken`, `hasRefreshToken` మరియు మాస్క్ చేసిన ప్రివ్యూను
(`maskedApiKey`: మొదటి 4 + `****` + చివరి 4) తిరిగి ఇస్తుంది.

## క్రెడెన్షియల్స్ పరిష్కారం

`src/lib/cloudAgent/api.ts`లోని `getCloudAgentCredentials(providerId)`:

1. `getProviderConnections({ provider: providerId, isActive: true })` ద్వారా యాక్టివ్ ప్రొవైడర్ కనెక్షన్లను లోడ్ చేస్తుంది.
2. ప్రతి కనెక్షన్కు, `apiKey`కు (ట్రిమ్ చేసినది) ప్రాధాన్యత ఇస్తుంది. అది లేకపోతే `accessToken`ను ఉపయోగిస్తుంది.
3. ఖాళీగా లేని మొదటి టోకెన్ను `{ apiKey: token }` రూపంలో చుట్టి తిరిగి ఇస్తుంది.
4. ఉపయోగించగల టోకెన్ ఏదీ కనుగొనబడకపోతే `null`ను తిరిగి ఇస్తుంది — API `400`తో
   `"క్లౌడ్ ఏజెంట్ ప్రొవైడర్ కోసం యాక్టివ్ క్రెడెన్షియల్స్ ఏవీ కాన్ఫిగర్ చేయబడలేదు: <id>"` అని ప్రతిస్పందిస్తుంది.

అంటే Cloud Agents కూడా సాధారణ LLM ప్రొవైడర్లు ఉపయోగించే అదే Provider Connection పట్టికను తిరిగి ఉపయోగిస్తాయి.
Julesను ప్రారంభించడానికి, `provider: "jules"`తో మరియు విలువ ఉన్న `apiKey`తో ఒక యాక్టివ్ కనెక్షన్ను సృష్టించండి.

## డ్యాష్బోర్డ్

సోర్స్: `src/app/(dashboard)/dashboard/cloud-agents/page.tsx`

ఇది ఒక `"use client"` React పేజీ:

- టాస్క్లను జాబితా చేస్తుంది (`GET /api/v1/agents/tasks` ద్వారా పోలింగ్ చేయబడతాయి).
- `CreateCloudAgentTaskSchema`కు మ్యాప్ అయ్యే ఫారమ్ ద్వారా కొత్త టాస్క్లను సమర్పిస్తుంది.
- స్థితి బ్యాడ్జ్లను (`queued`, `running`, `awaiting_approval`, `completed`,
  `failed`, `cancelled`) చూపిస్తుంది మరియు `activities[]` టైమ్లైన్ను రెండర్ చేస్తుంది.
- `status === "completed"` అయినప్పుడు `result.prUrl` / `commitMessage` / `summary`ను చూపిస్తుంది.

## A2Aతో ఇంటిగ్రేషన్

`tasks/send` హ్యాండ్లర్ను `getAgent(...).createTask(...)`కు అప్పగించే A2A స్కిల్ను రిజిస్టర్ చేయడం ద్వారా మరియు A2A టాస్క్
స్థితి ఈవెంట్లను JSON-RPC 2.0 ప్రోటోకాల్కు అనువదించడం ద్వారా Cloud Agentsను A2A స్కిల్స్గా అందుబాటులో ఉంచవచ్చు. [A2A-SERVER.md](./A2A-SERVER.md) చూడండి.

## కొత్త Cloud Agentను జోడించడం

1. `CloudAgentBase`ను విస్తరించే `src/lib/cloudAgent/agents/<name>.ts`ను సృష్టించండి.
2. `createTask`, `getStatus`, `approvePlan`లను (లేదా వర్తించకపోతే ఎర్రర్ను త్రో చేయండి),
   అలాగే `sendMessage`, `listSources`ను అమలు చేయండి. స్థితి సాధారణీకరణ కోసం `this.mapStatus(...)`ను ఉపయోగించండి.
3. స్థిరమైన `providerId` కింద `src/lib/cloudAgent/registry.ts`లో రిజిస్టర్ చేయండి.
4. `src/lib/cloudAgent/types.ts`లోని `providerId` లిటరల్ యూనియన్ను
   (`CloudAgentTask.providerId` మరియు `CreateCloudAgentTaskSchema`) విస్తరించండి.
5. దానికి కనెక్షన్ రికార్డ్ అవసరమైతే ప్రొవైడర్ను `src/shared/constants/providers.ts`కు జోడించండి.
   OAuth-ఆధారిత ప్రొవైడర్లకు `src/lib/oauth/providers/` కూడా అవసరం.
6. `tests/unit/cloud-agent-*.test.ts` కింద టెస్ట్లను జోడించండి.
7. ఈ డాక్యుమెంట్ను మరియు డ్యాష్బోర్డ్లోని `CLOUD_AGENTS` స్థిరాంకాన్ని అప్డేట్ చేయండి.
