| ఇంటర్ఫేస్                        | దీనికి అత్యుత్తమం                                                                                                                                          | రవాణా విధానం                   | ప్రమాణం                 |

## నిర్ణయ వృక్షం

```
ఈ మెషీన్ వెలుపల పని చేయడానికి మీకు క్లౌడ్ సేవ అవసరమా (Codex Cloud / Cursor Cloud / Devin / Jules)?
├─ అవును → క్లౌడ్ ఏజెంట్లు (POST /api/v1/agents/tasks)
└─ కాదు → కొనసాగండి
    │
    మీతో సహకరించాలనుకునే, A2A ఉపయోగించే పీర్ ఏజెంట్ మీకు ఉందా?
    ├─ అవును → A2A (POST /a2a)
    └─ కాదు → కొనసాగండి
        │
        స్థానికంగా ఇన్స్టాల్ చేసిన CLI కోడింగ్ ఏజెంట్లను జాబితా చేయడం / కాన్ఫిగర్ చేయడం మీకు అవసరమా?
        ├─ అవును → ACP (GET /api/acp/agents)
        └─ కాదు → సాధారణ /v1/chat/completions ఉపయోగించండి
```

## 1. A2A — ఏజెంట్-టు-ఏజెంట్

**స్పెక్:** [A2A v0.3](https://a2a-protocol.org)
**OmniRoute ఎండ్పాయింట్:** `POST /a2a` (JSON-RPC 2.0)
**ఏజెంట్ కార్డ్:** `GET /.well-known/agent.json`

### ఎప్పుడు ఉపయోగించాలి

- పీర్లలో OmniRoute కూడా ఒకటిగా ఉండే బహుళ-ఏజెంట్ సిస్టమ్ను నిర్మించేటప్పుడు
- Google ADK వంటి ఫ్రేమ్వర్క్లలోని ఏజెంట్లకు లేదా సాధారణ ఏజెంట్ మెష్లకు OmniRoute యొక్క రూటింగ్ మేధస్సును (smart-routing, quota-management మొదలైనవి) అందుబాటులో ఉంచేటప్పుడు
- ప్రామాణిక డిస్కవరీ + ఇన్వొకేషన్ ఇంటర్ఫేస్ వెనుక OmniRouteను ర్యాప్ చేసేటప్పుడు

### మెథడ్లు

- `message/send` — సందేశాన్ని సమర్పించి, సింక్ ప్రతిస్పందనను స్వీకరించండి
- `message/stream` — సమర్పించి + SSE ద్వారా స్ట్రీమ్ చేయబడిన పురోగతి ఈవెంట్లను స్వీకరించండి
- `tasks/get` — ID ద్వారా టాస్క్ను చదవండి
- `tasks/cancel` — నడుస్తున్న టాస్క్ను రద్దు చేయండి

### అంతర్నిర్మిత నైపుణ్యాలు (6)

- `smart-routing` — ప్రాంప్ట్ను అత్యుత్తమ కాంబో ద్వారా రూట్ చేయండి
- `quota-management` — ప్రతి ప్రొవైడర్కు సంబంధించిన కోటా స్థితిని నివేదించండి
- `provider-discovery` — సామర్థ్యాలతో సహా ఇన్స్టాల్ చేసిన ప్రొవైడర్లను జాబితా చేయండి
- `cost-analysis` — అభ్యర్థన/సంభాషణ వ్యయాన్ని అంచనా వేయండి
- `health-report` — ప్రతి ప్రొవైడర్కు సంబంధించిన బ్రేకర్/కూల్డౌన్/లాకౌట్ స్థితిని సమగ్రపరచండి
- `list-capabilities` — ఏజెంట్కు అందుబాటులో ఉన్న నైపుణ్యాలు మరియు మెటాడేటాను జాబితా చేయండి

### సమగ్ర వివరణ

రవాణా వివరాలు, ఏజెంట్ కార్డ్ నిర్మాణం, టాస్క్ TTL కాన్ఫిగరేషన్ మరియు కొత్త నైపుణ్యాలను జోడించే టెంప్లేట్ కోసం [A2A-SERVER.md](./A2A-SERVER.md) చూడండి.

## 2. ACP — CLI ఏజెంట్ల రిజిస్ట్రీ

**OmniRoute ఎండ్పాయింట్:** `GET /api/acp/agents`
**మూలం:** `src/lib/acp/{index,manager,registry}.ts`

### ఇది ఏమిటి

ACP అనేది OmniRoute యొక్క **స్థానిక CLI ఏజెంట్ జాబితా**. ఇది హోస్ట్లో ఏ కోడింగ్ CLIలు ఇన్స్టాల్ చేయబడ్డాయో (Cursor, Cline, Claude Code, Codex CLI, Continue మొదలైనవి) గుర్తించి, వాటి వెర్షన్లను నిర్ధారించి, ప్రతి CLIని OmniRoute వైపు మళ్లించేలా వినియోగదారు కాన్ఫిగర్ చేసేందుకు వాటిని డ్యాష్బోర్డ్లో ప్రదర్శిస్తుంది.

ఇది బాహ్య ప్రోటోకాల్ కాదు — ఇది "CLI Tools" UIకి మరియు CLI ఫింగర్ప్రింట్ ట్రాకింగ్కు శక్తినిచ్చే అంతర్గత రిజిస్ట్రీ ([CLI-TOOLS.md](../reference/CLI-TOOLS.md) చూడండి).

### ఇది ఏమి చేస్తుంది

- ఇన్స్టాల్ చేసిన CLI బైనరీల కోసం హోస్ట్ను పరిశీలిస్తుంది (OSను బట్టి `which` / `where` ఉపయోగిస్తుంది)
- ప్రతి CLI వెర్షన్ను చదువుతుంది (`<bin> --version`ను కాల్ చేస్తుంది)
- ఐచ్ఛికంగా వినియోగదారు నిర్వచించిన కస్టమ్ ఏజెంట్లను అంగీకరిస్తుంది (బైనరీ పాత్ + వెర్షన్ ప్రోబ్ + స్పాన్ ఆర్గ్యుమెంట్లు)
- కస్టమ్ ఏజెంట్లను సెట్టింగ్లలో నిల్వ చేస్తుంది
- ఏకీకృత జాబితాను డ్యాష్బోర్డ్కు అందిస్తుంది

### REST API

| ఎండ్పాయింట్       | మెథడ్ | వివరణ                                                                          | ప్రామాణీకరణ |
| ----------------- | ----- | ------------------------------------------------------------------------------ | ----------- |
| `/api/acp/agents` | GET   | గుర్తించిన + కస్టమ్ ఏజెంట్ల జాబితా (ఇన్స్టాల్ చేసినవి/మొత్తం సంఖ్యలు)          | API కీ      |
| `/api/acp/agents` | POST  | కస్టమ్ ఏజెంట్ను జోడించడం/నవీకరించడం/తొలగించడం (బాడీలో యాక్షన్ డిస్క్రిమినేటర్) | API కీ      |

POST కోసం బాడీ ఆకృతి (`src/app/api/acp/agents/route.ts`లోని `customAgentBodySchema`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### వినియోగ సందర్భాలు

- డ్యాష్బోర్డ్లోని "CLI Tools" పేజీ ఇన్స్టాల్ చేసిన వాటిని జాబితా చేసి, ప్రతి దానినీ OmniRoute వైపు మళ్లించడంలో మీకు సహాయపడుతుంది
- OmniRouteకు డిఫాల్ట్గా తెలియని అంతర్గత/యాజమాన్య CLIలను నిపుణ వినియోగదారులు నమోదు చేసేందుకు కస్టమ్ ఏజెంట్లు వీలు కల్పిస్తాయి
- గుర్తింపు ఫలితం `cli-tools` ఫింగర్ప్రింట్ మ్యాట్రిక్స్కు డేటాను అందిస్తుంది

### ACPని ఎప్పుడు ఉపయోగించకూడదు

- ACP టాస్క్లను _అమలు చేయదు_. ఇది CLIలను గుర్తించి + కాన్ఫిగర్ మాత్రమే చేస్తుంది. వాస్తవంగా ఒక CLIని అమలు చేయడానికి, OmniRoute అందించే ఎన్విరాన్మెంట్ వేరియబుల్లతో (`OPENAI_BASE_URL`, `OPENAI_API_KEY` మొదలైనవి) దాన్ని మీరే ప్రారంభించాలి.

## 3. క్లౌడ్ ఏజెంట్లు

**OmniRoute ఎండ్పాయింట్లు:** `/api/v1/agents/tasks/*` (లైఫ్సైకిల్) + `/api/cloud/*` (అంతర్గత అనుసంధానం)
**మూలం:** `src/lib/cloudAgent/`

### ఇది ఏమిటి

మూడవ-పక్ష క్లౌడ్ కోడింగ్ ఏజెంట్లపై ఒక ఏకరీతి ఇంటర్ఫేస్. మీరు ఒక ప్రాంప్ట్ + రిపో URLను సమర్పిస్తారు, OmniRoute దాన్ని సరైన క్లౌడ్ ఏజెంట్కు పంపించి, స్థితిని పోలింగ్ చేసి, ఫలితాలను తిరిగి అందిస్తుంది.

### మద్దతు ఉన్న ఏజెంట్లు (4, అన్నీ `src/lib/cloudAgent/agents/`లో నిర్ధారించబడ్డాయి)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### లైఫ్సైకిల్

```
POST /api/v1/agents/tasks
  → ప్రతి ఏజెంట్ క్లాస్కు BaseAgent.createTask()
  → బాహ్య సేవ పనిని ప్రారంభిస్తుంది
  → DBలో టాస్క్ రో సృష్టించబడుతుంది (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → ప్రొవైడర్ నుండి అవసరమైనప్పుడు స్థితి సింక్
  → ప్రస్తుత స్థితి + ప్రణాళిక + యాక్టివిటీ లాగ్ను అందిస్తుంది
  ↓
POST /api/v1/agents/tasks/[id]   (యాక్షన్: "approve" | "message" | "cancel")
  → ప్రొవైడర్కు ఫార్వర్డ్ చేస్తుంది (లేదా స్థానికంగా రద్దయినట్లు గుర్తిస్తుంది)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → స్థానికంగా రద్దు చేస్తుంది
```

### ప్రామాణీకరణ

⚠️ **అన్ని `/api/v1/agents/tasks/*` ఎండ్పాయింట్లకు మేనేజ్మెంట్ ప్రామాణీకరణ అవసరం** (కమిట్ `588a0333`). v3.8.0 నుండి కేవలం Bearerతో కాల్ చేసేవారికి 401 ప్రతిస్పందన అందుతుంది.

### సమగ్ర వివరణ

`CloudAgentBase` కాంట్రాక్ట్, ప్రతి ఏజెంట్కు సంబంధించిన ప్రత్యేక వివరాలు, స్కీమా వివరాలు మరియు క్రెడెన్షియల్ అనుసంధాన ఎండ్పాయింట్ల కోసం [CLOUD_AGENT.md](./CLOUD_AGENT.md) చూడండి.

## పోలిక: A2A vs Cloud Agents

రెండింటిలోనూ "దీర్ఘకాలం నడిచే టాస్క్లు" ఉంటాయి, కానీ వేర్వేరు లేయర్లలో:

| అంశం                | A2A                                                                                | Cloud Agents                                  |
| ------------------- | ---------------------------------------------------------------------------------- | --------------------------------------------- |
| ప్రమాణం             | Open A2A v0.3                                                                      | OmniRoute-నిర్దిష్టం                          |
| కంప్యూట్ జరిగే చోటు | OmniRoute లోపల (కాన్ఫిగర్ చేసిన కాంబోలను ఉపయోగిస్తుంది)                            | బాహ్యంగా (Codex / Devin / Jules సర్వర్లు)     |
| టాస్క్ వ్యవధి       | డిఫాల్ట్ TTL 5 నిమి (`TaskManager`లో కాన్ఫిగర్ చేయవచ్చు)                           | నిమిషాల నుండి గంటల వరకు                       |
| రెపో-అవగాహన         | లేదు (ప్రాంప్ట్లను మాత్రమే పంపుతుంది)                                              | ఉంది (రెపో URL + బ్రాంచ్)                     |
| వినియోగ సందర్భం     | క్రాస్-ఏజెంట్ సహకారం, సేవగా స్మార్ట్ రౌటింగ్                                       | "రెపో Yలో ఫీచర్ Xను అమలు చేయి" అని అప్పగించడం |
| ప్రామాణీకరణ         | `/a2a` కోసం ఐచ్ఛిక `OMNIROUTE_API_KEY`; `/api/a2a/*` REST సహాయకాల కోసం మేనేజ్మెంట్ | ఎల్లప్పుడూ మేనేజ్మెంట్                        |

## ఇంటిగ్రేషన్ ఉదాహరణలు

### OmniRoute యొక్క A2A సామర్థ్యాలను కనుగొనండి

```bash
curl http://localhost:20128/.well-known/agent.json
```

మొత్తం 6 స్కిల్స్, ట్రాన్స్పోర్ట్లు, వెర్షన్తో కూడిన Agent Cardను తిరిగి ఇస్తుంది.

### OmniRouteను A2A ఏజెంట్గా కాల్ చేయండి

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### ACP ద్వారా ఇన్స్టాల్ చేసిన CLI ఏజెంట్లను జాబితా చేయండి

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### కస్టమ్ CLI ఏజెంట్ను జోడించండి

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### Cloud Agent టాస్క్ను సమర్పించండి

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### క్లౌడ్ టాస్క్ స్థితిని పోల్ చేయండి

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## దేనిని ఎప్పుడు ఉపయోగించాలి

- **Chatbot / copilot ఫ్రంటెండ్** → `/v1/chat/completions` (OpenAI-అనుకూలం — ఇది ఏజెంట్ ప్రోటోకాల్ కాదు)
- **మల్టీ-ఏజెంట్ సహకారం** → A2A
- **డ్యాష్బోర్డ్లో స్థానిక CLIలను జాబితా చేయడం** → ACP
- **దీర్ఘకాలం నడిచే కోడింగ్ టాస్క్లను క్లౌడ్ సేవలకు అప్పగించడం** → Cloud Agents
