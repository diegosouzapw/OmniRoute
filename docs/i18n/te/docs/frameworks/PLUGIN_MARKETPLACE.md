> **ప్రామాణిక మూలం:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/`, మరియు
> `src/app/(dashboard)/dashboard/plugins/`
> **చివరిగా నవీకరించబడింది:** 2026-06-28 — v3.8.40

OmniRoute, WordPress-శైలి ప్లగిన్ వ్యవస్థతో అందించబడుతుంది. ప్లగిన్లు స్వయం-సమగ్ర
డైరెక్టరీలు — ప్రతి దానిలో ఒక `plugin.json` మానిఫెస్ట్ మరియు ఒక ఎంట్రీ ఫైల్ ఉంటాయి — ఇవి
అభ్యర్థన పైప్లైన్లో (`onRequest` / `onResponse` / `onError`) మరియు
లైఫ్సైకిల్ ఈవెంట్లలో (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`)
హుక్ అవుతాయి.

**ప్లగిన్ మార్కెట్ప్లేస్** అనేది ఆ వ్యవస్థపై ఉండే డిస్కవరీ లేయర్. ఇది
ఇన్స్టాల్ చేయగల ప్లగిన్లను బ్రౌజ్ చేయగల కేటలాగ్గా అందిస్తుంది. డిఫాల్ట్గా ఈ కేటలాగ్
ఒక చిన్న అంతర్నిర్మిత సీడ్ రిజిస్ట్రీగా ఉంటుంది; ఆపరేటర్ దీన్ని అనుకూల రిమోట్
రిజిస్ట్రీ URLకు నిర్దేశించవచ్చు. అటువంటి సందర్భంలో ఫెచ్ను DNS-రిజాల్వింగ్ SSRF గార్డ్
ద్వారా పటిష్ఠం చేస్తారు ([భద్రత](#security) చూడండి).

ప్రతి ప్లగిన్ రూట్ **లూప్బ్యాక్కు మాత్రమే పరిమితం** (టియర్ 1 — `LOCAL_ONLY`):
ప్లగిన్లు చైల్డ్ ప్రాసెస్లలో కోడ్ను లోడ్ చేసి అమలు చేస్తాయి, కాబట్టి ఆథెంటికేషన్తో
సంబంధం లేకుండా లూప్బ్యాక్ కాని మూలం నుండి ఈ రూట్లను చేరుకోలేరు.
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) చూడండి.

## ఇది ఎలా కలిసి పనిచేస్తుంది

```
డాష్బోర్డ్ (/dashboard/plugins)
  ├─ "ఇన్స్టాల్ చేసినవి" ట్యాబ్ → GET /api/plugins            (listPlugins)
  │                              POST /api/plugins/scan      (pluginManager.scan)
  │                              POST /api/plugins/{name}/activate|deactivate
  │                              DELETE /api/plugins/{name}   (అన్ఇన్స్టాల్)
  └─ "మార్కెట్ప్లేస్" ట్యాబ్    → GET /api/plugins/marketplace
                                   → listMarketplacePlugins()
                                     ├─ అనుకూల URL లేదు → అంతర్నిర్మిత SEED_REGISTRY
                                     └─ అనుకూల URL → isSafeMarketplaceUrl() SSRF గార్డ్
                                                   → safeOutboundFetch(guard:"public-only")
```

- **రిజిస్ట్రీ లేయర్** — `src/lib/plugins/marketplace.ts`: కేటలాగ్ను జాబితా చేస్తుంది /
  శోధిస్తుంది; ఏదైనా వైఫల్యం సంభవిస్తే సీడ్ రిజిస్ట్రీకి తిరిగి వెళ్తుంది.
- **లైఫ్సైకిల్ లేయర్** — `src/lib/plugins/manager.ts` (`pluginManager` సింగిల్టన్):
  ఇన్స్టాల్, అప్గ్రేడ్, యాక్టివేట్, డీయాక్టివేట్, అన్ఇన్స్టాల్, స్కాన్, స్టార్టప్ లోడ్.
- **మానిఫెస్ట్ లేయర్** — `src/lib/plugins/manifest.ts`: `plugin.json` కోసం Zod స్కీమా +
  డిఫాల్ట్లు.
- **స్కానర్** — `src/lib/plugins/scanner.ts`: ప్లగిన్ డైరెక్టరీ కింద డిస్క్పై ఉన్న
  ప్లగిన్లను గుర్తిస్తుంది.
- **లోడర్** — `src/lib/plugins/loader.ts`: ప్రతి ప్లగిన్ను వేరుచేసిన
  చైల్డ్ ప్రాసెస్లో ప్రారంభించి, IPC ద్వారా హుక్ కాల్లను మధ్యవర్తిత్వం చేస్తుంది.

## మార్కెట్ప్లేస్ కేటలాగ్

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) `MarketplaceEntry`
ఆబ్జెక్ట్ల జాబితాను తిరిగి ఇస్తుంది:

| ఫీల్డ్        | రకం      | గమనికలు                                 |
| ------------- | -------- | --------------------------------------- |
| `name`        | string   | kebab-case ప్లగిన్ పేరు                 |
| `version`     | string   | semver                                  |
| `description` | string   | సంక్షిప్త సారాంశం                       |
| `author`      | string   | రచయిత / సంస్థ                           |
| `license`     | string   | SPDX-శైలి లైసెన్స్ id                   |
| `downloadUrl` | string   | సోర్స్ డౌన్లోడ్ URL (ఖాళీగా ఉండవచ్చు)   |
| `repository`  | string?  | ఐచ్ఛిక రిపోజిటరీ URL                    |
| `tags`        | string[] | శోధన/ఫిల్టర్ ట్యాగ్లు                   |
| `downloads`   | number   | డౌన్లోడ్ల సంఖ్య                         |
| `rating`      | number   | 0–5                                     |
| `verified`    | boolean  | ఎంట్రీ ధృవీకరించబడినదిగా గుర్తించబడిందా |
| `lastUpdated` | string   | ISO-తరహా తేదీ స్ట్రింగ్                 |

అనుకూల రిజిస్ట్రీ URL ఏదీ కాన్ఫిగర్ చేయనప్పుడు, కేటలాగ్ అంతర్నిర్మిత
`SEED_REGISTRY`గా ఉంటుంది (ప్రస్తుతం `request-logger`, `rate-limiter`, `cost-tracker`,
మరియు `theme-manager`). సీడ్ రిజిస్ట్రీ ఎల్లప్పుడూ అందుబాటులో ఉంటుంది — కాన్ఫిగర్ చేసిన
రిమోట్ రిజిస్ట్రీని చేరుకోలేకపోయినా, అది `200` కాని స్టేటస్ను తిరిగి ఇచ్చినా లేదా
గుర్తించలేని బాడీని తిరిగి ఇచ్చినా, `listMarketplacePlugins()` హెచ్చరికను లాగ్ చేసి
సీడ్ జాబితాకు తిరిగి వెళ్తుంది.

> గమనిక: మార్కెట్ప్లేస్ **కేటలాగ్** (బ్రౌజ్/శోధన) మొదటి నుంచి చివరి వరకు అనుసంధానించబడింది,
> కానీ కేటలాగ్ నుండి ఒకే క్లిక్తో మార్కెట్ప్లేస్ **ఇన్స్టాల్** చేయడం ఇంకా అమలు కాలేదు —
> మార్కెట్ప్లేస్ ఎంట్రీపై ఉన్న డాష్బోర్డ్ "ఇన్స్టాల్" బటన్ ప్రస్తుతం
> "త్వరలో అందుబాటులోకి వస్తుంది" అనే నోటీసును చూపుతుంది. ప్రస్తుతం ఇన్స్టాలేషన్
> స్థానిక-పాత్ ఇన్స్టాల్ ఫ్లో (`POST /api/plugins`) మరియు డిస్క్పై డిస్కవరీ
> (`POST /api/plugins/scan`) ద్వారా జరుగుతుంది.

## REST API

అన్ని ఎండ్పాయింట్లకు నిర్వహణ ప్రమాణీకరణ (`requireManagementAuth`) అవసరం **మరియు** అవి
లూప్బ్యాక్కు మాత్రమే పరిమితం — `/api/plugins` మరియు `/api/plugins/` అనేవి
`LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`)లో జాబితా చేయబడ్డాయి.

| ఎండ్పాయింట్                      | పద్ధతి | వివరణ                                                                    |
| -------------------------------- | ------ | ------------------------------------------------------------------------ |
| `/api/plugins`                   | GET    | ఇన్స్టాల్ చేసిన ప్లగిన్లను జాబితా చేయండి (ఐచ్ఛిక `?status=` ఫిల్టర్)     |
| `/api/plugins`                   | POST   | సంపూర్ణ స్థానిక పాత్ నుండి ప్లగిన్ను ఇన్స్టాల్ చేయండి                    |
| `/api/plugins/scan`              | POST   | ప్లగిన్ డైరెక్టరీని స్కాన్ చేసి కొత్త ప్లగిన్లను నమోదు చేయండి            |
| `/api/plugins/marketplace`       | GET    | మార్కెట్ప్లేస్ కేటలాగ్ ఎంట్రీలను జాబితా చేయండి                           |
| `/api/plugins/[name]`            | GET    | ఇన్స్టాల్ చేసిన ప్లగిన్ వివరాలను పొందండి                                 |
| `/api/plugins/[name]`            | DELETE | ప్లగిన్ను అన్ఇన్స్టాల్ చేయండి                                            |
| `/api/plugins/[name]/activate`   | POST   | సక్రియం చేయండి (లోడ్ చేయడం + హుక్లను నమోదు చేయడం)                        |
| `/api/plugins/[name]/deactivate` | POST   | నిష్క్రియం చేయండి (`onDeactivate`ను అమలు చేయడం, హుక్ల నమోదును తొలగించడం) |
| `/api/plugins/[name]/config`     | GET    | ప్లగిన్ కాన్ఫిగ్ + కాన్ఫిగ్ స్కీమాను పొందండి                             |
| `/api/plugins/[name]/config`     | PUT    | ప్లగిన్ కాన్ఫిగ్ను నవీకరించండి (స్కీమాకు వ్యతిరేకంగా ధృవీకరించబడుతుంది)  |

`GET /api/plugins`లోని `status` ఫిల్టర్
`installed` / `active` / `inactive` / `error`లో ఒకదాన్ని అంగీకరిస్తుంది. చెల్లని విలువ `400`ను తిరిగి ఇస్తుంది.

### ఇన్స్టాల్ చేసిన ప్లగిన్లను జాబితా చేయడం

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### స్థానిక పాత్ నుండి ఇన్స్టాల్ చేయడం

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` తప్పనిసరిగా **సంపూర్ణమైనది** అయి ఉండాలి మరియు అందులో `..` ట్రావర్సల్ సెగ్మెంట్లు లేదా
నల్ బైట్లు ఉండకూడదు (Zod ద్వారా అమలు చేయబడుతుంది). సోర్స్ డైరెక్టరీలో చెల్లుబాటు అయ్యే
`plugin.json` ఉండాలి (లేదా అది ఉన్న డైరెక్టరీకి పేరెంట్ అయి ఉండాలి). విజయవంతమైతే, ప్రతిస్పందన
ఇన్స్టాల్ చేసిన ప్లగిన్ వరుసతో `201`గా ఉంటుంది.

### మార్కెట్ప్లేస్ను బ్రౌజ్ చేయడం

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### ప్లగిన్ కాన్ఫిగ్ను నవీకరించడం

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` అందించిన ప్రతి విలువను ప్లగిన్ యొక్క
`configSchema`కు వ్యతిరేకంగా ధృవీకరిస్తుంది (మానిఫెస్ట్లో ప్రకటించబడింది): `number` ఫీల్డ్లు `min`/`max`ను
గౌరవిస్తాయి, `select` ఫీల్డ్లు ప్రకటించిన `enum`తో సరిపోలాలి. స్కీమాలో లేని కీలు
అనుమతించబడతాయి.

## కాన్ఫిగరేషన్

### ప్లగిన్ డైరెక్టరీ

ప్లగిన్లు OmniRoute డేటా డైరెక్టరీ కింద ఉంటాయి:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (లేదా manifest.main సూచించే ఏదైనా)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) ఆ డైరెక్టరీని
మూడు దశల్లో పరిష్కరిస్తుంది:

1. **`OMNIROUTE_PLUGINS_DIR`**, సెట్ చేసినప్పుడు — `HOME`లో ఏది ఉన్నా, యథాతథంగా ఉపయోగించబడుతుంది. ఇది
   Docker/K8s కోసం స్పష్టమైన నియంత్రణ; అక్కడ ప్లగిన్ ట్రీ సాధారణంగా కంటైనర్ హోమ్ డైరెక్టరీతో
   ఎలాంటి సంబంధం లేని పాత్లో బైండ్-మౌంట్ చేయబడుతుంది (#11827).
2. `<home>/.omniroute/plugins`, ఇక్కడ `<home>` అనేది `HOME` / `USERPROFILE`
   ఎన్విరాన్మెంట్ వేరియబుల్స్ నుండి వస్తుంది.
3. `/tmp/.omniroute/plugins`, ప్రాసెస్ ఎలాంటి హోమ్ను ఎగుమతి చేయనప్పుడు.

పరిష్కరించిన డైరెక్టరీ స్టార్టప్ సమయంలో `scanner.dir_resolved`గా ఒకసారి లాగ్ చేయబడుతుంది; అందులో
ఎంచుకోబడిన ఇన్పుట్ (`OMNIROUTE_PLUGINS_DIR`, `home`, లేదా `no-home-fallback`) పేర్కొనబడుతుంది — అందువల్ల
నిశ్శబ్దంగా 3వ దశకు చేరే ఇమేజ్, కేవలం ఖాళీ ప్లగిన్ జాబితాను నివేదించడానికి బదులుగా, ఆ విషయాన్ని తెలియజేస్తుంది.
`POST /api/plugins/scan` అక్కడ చెల్లుబాటు అయ్యే `plugin.json`ను కలిగి ఉన్న ఏ సబ్డైరెక్టరీనైనా
కనుగొని నమోదు చేస్తుంది; అదే డైరెక్టరీలోకి `pluginManager.install()` ప్లగిన్లను కాపీ చేస్తుంది,
కాబట్టి ఓవర్రైడ్ డిస్కవరీ మరియు ఇన్స్టాలేషన్ రెండింటినీ కలిపి తరలిస్తుంది.

> **`OMNIROUTE_PLUGINS_DIR` అనేది `OMNIROUTE_PLUGIN_PATH` కాదు.** రెండవది
> `omniroute` సబ్కమాండ్లను జోడించే `omniroute-cmd-*` npm ప్యాకేజీలను కనుగొనడానికి
> CLI కమాండ్-ప్లగిన్ లోడర్ (`bin/cli/plugins.mjs`) ద్వారా మాత్రమే చదవబడుతుంది — ఇక్కడ వివరించిన
> రన్టైమ్ స్కానర్పై దానికి ఎలాంటి ప్రభావం లేదు. ఆ అంశం కోసం [PLUGINS.md](./PLUGINS.md) చూడండి.

### అనుకూల మార్కెట్ప్లేస్ రిజిస్ట్రీ URL

మార్కెట్ప్లేస్ కేటలాగ్ మూలం `pluginMarketplaceUrl` సెట్టింగ్ నుండి చదవబడుతుంది
(`src/lib/plugins/marketplace.ts` అనేది `settings.pluginMarketplaceUrl`ను చదువుతుంది). దాన్ని
`http(s)` URLకు సెట్ చేసినప్పుడు, `listMarketplacePlugins()` ఆ URLను ఫెచ్ చేసి,
ఎంట్రీల టాప్-లెవల్ JSON అర్రేను లేదా `plugins` అర్రే కలిగిన ఆబ్జెక్ట్ను అంగీకరిస్తుంది;
స్ట్రింగ్ `name` లేని ఎంట్రీలు ఫిల్టర్ చేయబడతాయి. సెట్ చేయనప్పుడు (లేదా ఫెచ్
SSRF గార్డ్లో విఫలమైనప్పుడు / చెల్లని ప్రతిస్పందనను ఇచ్చినప్పుడు), అంతర్నిర్మిత సీడ్ రిజిస్ట్రీ
ఉపయోగించబడుతుంది.

డాష్బోర్డ్లోని "Marketplace" ట్యాబ్ ఈ URL కోసం ఒక ఫీల్డ్ను అందిస్తుంది (ఇది
`GET /api/settings` నుండి తిరిగి చదవబడుతుంది).

> అమలు గమనిక: డాష్బోర్డ్లోని "Save" చర్య
> `pluginMarketplaceUrl`ను `PATCH /api/settings`కు పంపుతుంది. ఇది రాస్తున్న సమయానికి,
> ఈ కీ `updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`)లో ప్రకటించబడలేదు, కాబట్టి దానిపై ఆధారపడే ముందు
> మీ విడుదలలో నిల్వ కొనసాగుతుందో లేదో ధృవీకరించండి — సెట్టింగ్ల స్టోర్లో కీ ఉన్న తర్వాత
> **రీడ్** పాత్ (`getSettings()` →
> `listMarketplacePlugins()`) దానిని గౌరవిస్తుంది.

## భద్రత

### రూట్ స్థాయి — లూప్బ్యాక్ మాత్రమే

ప్లగిన్లు సృష్టించబడిన చైల్డ్ ప్రాసెస్లలో కోడ్ను అమలు చేస్తాయి, కాబట్టి మొత్తం `/api/plugins`
ఉపరితలం `LOCAL_ONLY` (స్థాయి 1)గా వర్గీకరించబడింది. ఏదైనా ప్రామాణీకరణ తనిఖీకి
**ముందే** లూప్బ్యాక్ అమలు బేషరతుగా జరుగుతుంది, కాబట్టి టన్నెల్ ద్వారా
మెషీన్కు చేరుకున్న లీకైన నిర్వహణ టోకెన్ కూడా ప్లగిన్ను ఇన్స్టాల్ చేయడం,
సక్రియం చేయడం లేదా అన్ఇన్స్టాల్ చేయడం సాధ్యం కాదు.
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) మరియు
కఠిన నియమాలు #15 / #17 చూడండి.

### మార్కెట్ప్లేస్ రిజిస్ట్రీ SSRF రక్షణ

అనుకూల రిజిస్ట్రీ URL అనేది దాడి చేసేవారు ప్రభావితం చేయగల కాన్ఫిగరేషన్, కాబట్టి
దాన్ని పొందడానికి ముందు `listMarketplacePlugins()` రెండు స్థాయిల ద్వారా పంపుతుంది:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - `http:` / `https:` కానిదేదైనా తిరస్కరిస్తుంది.
   - కానానికల్ `isPrivateHost`
     (`src/shared/network/outboundUrlGuard.ts`) ద్వారా లిటరల్ ప్రైవేట్/లూప్బ్యాక్/లింక్-లోకల్/ULA హోస్ట్లను
     (IPv4-మ్యాప్ చేసిన వాటితో సహా IPv4 **మరియు** IPv6) తిరస్కరిస్తుంది.
   - **`A` మరియు `AAAA` రెండింటి** రికార్డులను పరిష్కరిస్తుంది; పరిష్కరించబడిన
     చిరునామాల్లో **ఏదైనా** ప్రైవేట్ అయితే తిరస్కరిస్తుంది — తద్వారా పబ్లిక్-హోస్ట్నేమ్ → ప్రైవేట్-IP బైపాస్ను మూసివేస్తుంది.
   - **విఫలమైతే మూసివేస్తుంది**: DNS పరిష్కరణ వైఫల్యం URLను తిరస్కరిస్తుంది.
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`**
   (`src/shared/network/safeOutboundFetch.ts`): ఫెచ్ సమయంలో పబ్లిక్-మాత్రమే URL
   రక్షణను మళ్లీ వర్తింపజేస్తుంది మరియు **రీడైరెక్ట్లను నిరోధిస్తుంది** (పబ్లిక్ → ప్రైవేట్ `30x`
   పివట్ ఉండదు).

ఏ స్థాయిలోనైనా విఫలమైన URL అభ్యర్థనను నిలిపివేయదు — మార్కెట్ప్లేస్
నిశ్శబ్దంగా అంతర్నిర్మిత సీడ్ రిజిస్ట్రీకి తిరిగి వెళ్లి హెచ్చరికను లాగ్ చేస్తుంది.

> ప్రత్యేకంగా A + AAAAను పరిష్కరించడానికి మరియు IPv4-మాత్రమే తనిఖీకి బదులుగా
> కానానికల్ `isPrivateHost`ను ఉపయోగించడానికి ఈ రక్షణ PR #3774లో పటిష్ఠం చేయబడింది.

### ప్లగిన్ అమలు వేర్పాటు

- **ప్రాసెస్ వేర్పాటు** — `loadPlugin()` (`src/lib/plugins/loader.ts`) ప్రతి
  ప్లగిన్ను ప్రత్యేక Node.js చైల్డ్ ప్రాసెస్లో సృష్టించి, IPC ద్వారా కమ్యూనికేట్ చేస్తుంది.
  హుక్ కాల్లకు `SIGTERM` → `SIGKILL` ఎస్కలేషన్తో కూడిన గడువు ఉంటుంది.
- **Env అనుమతి జాబితా** — చైల్డ్కు అనుమతి జాబితాలోని ఎన్విరాన్మెంట్
  వేరియబుల్ల సమితి మాత్రమే అందుతుంది; మానిఫెస్ట్ `env` అనుమతిని అభ్యర్థించినప్పుడు
  మాత్రమే విస్తృత సమితి మంజూరు చేయబడుతుంది.
- **పాత్ నిర్బంధం** — కాపీ చేయడానికి లేదా పునరావృతంగా తొలగించడానికి ముందు,
  ప్లగిన్ డైరెక్టరీ మరియు `manifest.main` నిర్వహిత ప్లగిన్ రూట్కు **లోపలే**
  పరిష్కరించబడతాయని ఇన్స్టాల్/అప్గ్రేడ్/అన్ఇన్స్టాల్ నిర్ధారిస్తాయి (తారుమారు
  చేయబడిన DB పాత్లు మరియు `manifest.main`లో `../` ట్రావర్సల్కు వ్యతిరేకంగా
  రక్షణ కల్పిస్తాయి). సక్రియీకరణ `realpath` ద్వారా సింబాలిక్ లింక్లను
  పరిష్కరిస్తుంది మరియు ప్లగిన్ డైరెక్టరీ వెలుపలికి వెళ్లే ఎంట్రీ పాయింట్ను
  లోడ్ చేయడానికి నిరాకరిస్తుంది.
- **ఐచ్ఛిక సమగ్రత పిన్** — మానిఫెస్ట్ ఒక `integrity`
  (`sha256-<base64>`, SRI ఫార్మాట్) ఫీల్డ్ను ప్రకటించవచ్చు. అది ఉన్నప్పుడు,
  లోడర్ లోడ్ సమయంలో ఎంట్రీ ఫైల్ హాష్ను ధృవీకరిస్తుంది మరియు సరిపోలకపోతే
  సక్రియం చేయడానికి నిరాకరిస్తుంది. ఇది ఐచ్ఛిక తారుమారు-గుర్తింపు మాత్రమే,
  భద్రతా సరిహద్దు **కాదు** — లూప్బ్యాక్-మాత్రమే రూటింగ్ మరియు అనుమతి నమూనానే
  నిజమైన సరిహద్దులు.

## మానిఫెస్ట్ (`plugin.json`)

`PluginManifestSchema` (`src/lib/plugins/manifest.ts`) ద్వారా ధృవీకరించబడుతుంది:

| ఫీల్డ్             | రకం       | గమనికలు                                                        |
| ------------------ | --------- | -------------------------------------------------------------- |
| `name`             | string    | తప్పనిసరి; kebab-case (`^[a-z0-9-]+$`), 1–100 అక్షరాలు         |
| `version`          | string    | తప్పనిసరి; semver (`MAJOR.MINOR.PATCH`)                        |
| `description`      | string?   | ≤ 500 అక్షరాలు                                                 |
| `author`           | string?   | ≤ 200 అక్షరాలు                                                 |
| `license`          | string?   | డిఫాల్ట్గా `MIT`                                               |
| `main`             | string?   | ఎంట్రీ ఫైల్; డిఫాల్ట్గా `index.js`                             |
| `source`           | enum?     | `local` \| `marketplace` (డిఫాల్ట్గా `local`)                  |
| `tags`             | string[]? | శోధన ట్యాగ్లు                                                  |
| `requires`         | object?   | `{ omniroute?, permissions[] }`                                |
| `hooks`            | object?   | ప్లగిన్ ఏ హుక్లను అమలు చేస్తుందో ప్రకటించే బూలియన్లు           |
| `skills`           | object[]? | ఐచ్ఛిక నైపుణ్య నిర్వచనాలు                                      |
| `enabledByDefault` | boolean?  | ఇన్స్టాల్ చేసినప్పుడు స్వయంచాలకంగా సక్రియం చేయండి              |
| `configSchema`     | object?   | కాన్ఫిగ్ ఫీల్డ్ల మ్యాప్ (`string`/`number`/`boolean`/`select`) |
| `integrity`        | string?   | ఐచ్ఛిక `sha256-<base64>` ఎంట్రీ-ఫైల్ పిన్                      |

అనుమతులు
`network` / `file-read` / `file-write` / `env` / `exec` enum నుండి తీసుకోబడతాయి.

## జీవనచక్ర ప్రవాహం

```
ఇన్స్టాల్ (POST /api/plugins, పాత్)
  → మానిఫెస్ట్ను స్కాన్/ధృవీకరించడం → స్టేజింగ్కు కాపీ చేయడం → ప్రధాన ఫైల్ డైరెక్టరీలోనే ఉందని నిర్ధారించడం
  → ~/.omniroute/plugins/<name> లోకి అటామిక్ రీనేమ్ చేయడం → DB వరుసను చేర్చడం
  → onInstallను అమలు చేయడం → enabledByDefault అయితే: యాక్టివేట్ చేయడం

యాక్టివేట్ (POST /api/plugins/{name}/activate)
  → realpath కంటైన్మెంట్ తనిఖీ → loadPlugin() (చైల్డ్ ప్రాసెస్ను ప్రారంభించడం)
  → ప్రకటించిన హుక్స్ను నమోదు చేయడం → status = "active" → onActivateను అమలు చేయడం

డియాక్టివేట్ (POST /api/plugins/{name}/deactivate)
  → onDeactivateను అమలు చేయడం (నమోదు తొలగించే ముందు) → హుక్స్ నమోదును తొలగించడం
  → చైల్డ్ ప్రాసెస్ను నిలిపివేయడం → status = "inactive"

అన్ఇన్స్టాల్ (DELETE /api/plugins/{name})
  → యాక్టివ్గా ఉంటే డియాక్టివేట్ చేయడం → onUninstallను అమలు చేయడం
  → కంటైన్మెంట్ తనిఖీతో ప్లగిన్ డైరెక్టరీని రికర్సివ్గా తొలగించడం → DB వరుసను తొలగించడం
```

ఇన్స్టాల్ చేసిన వెర్షన్ కంటే మానిఫెస్ట్ వెర్షన్ **ఖచ్చితంగా
కొత్తది**గా ఉన్న డైరెక్టరీపై `install`ను మళ్లీ అమలు చేస్తే స్వయంచాలకంగా అప్గ్రేడ్ అవుతుంది (క్లీన్ రీఇన్స్టాల్; కాన్ఫిగరేషన్ డిఫాల్ట్లకు రీసెట్ అవుతుంది).
అదే లేదా అంతకంటే పాత వెర్షన్ తిరస్కరించబడుతుంది.

| `main`          | TEXT    | ప్రవేశ ఫైల్; డిఫాల్ట్ `index.js`                 |

## డ్యాష్బోర్డ్

`/dashboard/plugins` వద్ద ఉన్న డ్యాష్బోర్డ్ పేజీ
(`src/app/(dashboard)/dashboard/plugins/page.tsx`) రెండు ట్యాబ్లను అందిస్తుంది:

- **ఇన్స్టాల్ చేసినవి** — ఇన్స్టాల్ చేసిన ప్లగిన్లను వాటి ప్రకటిత హుక్స్తో పాటు జాబితా చేస్తుంది, అలాగే
  యాక్టివేట్/డియాక్టివేట్ టాగుల్, అన్ఇన్స్టాల్ బటన్ మరియు "ప్లగిన్ల కోసం స్కాన్ చేయండి"
  చర్యను (`POST /api/plugins/scan`) అందిస్తుంది.
- **మార్కెట్ప్లేస్** — `GET /api/plugins/marketplace` నుండి కేటలాగ్ను, అలాగే
  కస్టమ్ రిజిస్ట్రీ URLను సెట్ చేయడానికి ఒక ఫీల్డ్ను చూపుతుంది.

ప్రతి ప్లగిన్కు సంబంధించిన కాన్ఫిగరేషన్ పేజీ `/dashboard/plugins/[name]/config`
(`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`) వద్ద ఉంటుంది.
