## అవలోకనం

Playground Studio, `/dashboard/playground`ను సాధారణ Monaco-ఆధారిత ఎడిటర్ నుండి
పూర్తి ఫీచర్లతో కూడిన పరీక్షా వర్క్స్పేస్గా మారుస్తుంది. ఇది పాత `page.tsx` స్థానంలో నాలుగు ట్యాబ్లు మరియు ఉమ్మడి కాన్ఫిగరేషన్ పేన్ను రెండర్ చేసే `PlaygroundStudio`
షెల్ను ఉపయోగిస్తుంది.

```
┌ Playground ──────────────────────────────────────────────────────────┐
│ [💬 చాట్] [⚖ పోలిక] [{} API] [🔧 బిల్డ్]      142↑ 38↓ · $0.002 </>│
├──────────────────────────────────────────┬───────────────────────────┤
│  {యాక్టివ్ ట్యాబ్ కంటెంట్}               │ ─ కాన్ఫిగరేషన్           │
```

## ట్యాబ్లు

### చాట్ ట్యాబ్

`ChatPlayground.tsx`ను బహుళ-టర్న్ స్ట్రీమింగ్ వర్క్బెంచ్గా అభివృద్ధి చేస్తుంది:

- `MarkdownMessage.tsx` ద్వారా పూర్తి markdown రెండరింగ్ (కోడ్ బ్లాక్లు, పట్టికలు, జాబితాలు, లింక్లు).
- ఉమ్మడి కాన్ఫిగరేషన్ పేన్ నుండి సిస్టమ్ ప్రాంప్ట్ను పొందుతుంది.
- ప్రతి సందేశానికి టోకెన్లు/ఖర్చు (ప్రాంప్ట్ + కంప్లీషన్ టోకెన్లు).
- చివరి ప్రతిస్పందనను మళ్లీ రూపొందించడం.
- SSE స్ట్రీమింగ్తో `POST /v1/chat/completions`కు పంపుతుంది.

### పోలిక ట్యాబ్

ప్రాక్సీకి కీలక ప్రత్యేకత: ఒక ప్రాంప్ట్ను గరిష్ఠంగా **4 మోడళ్లలో సమాంతరంగా** అమలు చేయడం.

- గరిష్ఠంగా 4 కాలమ్లు; ప్రతి ఒక్కటీ `/v1/chat/completions` నుండి స్వతంత్రంగా స్ట్రీమ్ అవుతుంది.
- కాలమ్లను జోడించడానికి `+ మోడల్ను జోడించు` బటన్ (Cmd+K షార్ట్కట్).
- `అన్నింటినీ అమలు చేయి ▶`, `Promise.all` + ప్రతి కాలమ్కు ఒక `AbortController` ద్వారా అన్ని స్ట్రీమ్లను ఏకకాలంలో ప్రారంభిస్తుంది.
- గ్లోబల్ **అన్నింటినీ రద్దు చేయి** ప్రస్తుతం కొనసాగుతున్న ప్రతి స్ట్రీమ్ను నిలిపివేస్తుంది.
- ప్రతి కాలమ్లోని `ProviderMetrics`, TTFT, TPS, టోకెన్లు మరియు అంచనా ఖర్చును నిజ సమయంలో చూపుతుంది.
- మెట్రిక్లకు **"క్లయింట్-సైడ్ అంచనా"** (D12) అనే లేబుల్ ఉంటుంది — మొదటి SSE చంక్ నుండి కొలుస్తారు.

### API ట్యాబ్

నైపుణ్యం కలిగిన వినియోగదారుల కోసం అసలు Monaco ఎడిటర్ను 100% యథాతథంగా ఉంచుతుంది (D14):

- 10 ఎండ్పాయింట్లు: చాట్ కంప్లీషన్లు, కంప్లీషన్లు, ఎంబెడింగ్లు, చిత్రాలు, ఆడియో, స్పీచ్, ట్రాన్స్క్రిప్షన్లు, మోడరేషన్లు, రీర్యాంక్, సెర్చ్.
- మల్టీమోడల్ ఫైల్ అప్లోడ్.
- నిజ-సమయ అవుట్పుట్తో SSE స్ట్రీమింగ్.
- `ApiTab.tsx`గా ర్యాప్ చేయబడింది (లేజీ-లోడ్ చేయబడుతుంది, `ssr: false`).

### బిల్డ్ ట్యాబ్

టూల్స్/ఫంక్షన్ కాలింగ్ మరియు నిర్మిత అవుట్పుట్ UI:

- `ToolsBuilder.tsx` — ప్రతి టూల్కు JSON స్కీమా ఎడిటర్తో `tools[]`ను జోడించడం/సవరించడం/తొలగించడం.
  `ToolDefinitionSchema` (Zod) ద్వారా పారామీటర్లను ధ్రువీకరిస్తుంది.
- `StructuredOutputEditor.tsx` — JSON మోడ్ టాగుల్ + JSON స్కీమా ఎడిటర్.
  `StructuredOutputSchema` (Zod) ద్వారా స్కీమాకు అనుగుణంగా ప్రతిస్పందనను ధ్రువీకరిస్తుంది.
- `tools[]` మరియు/లేదా `response_format`తో అభ్యర్థనను `/v1/chat/completions`కు పంపుతుంది.

## కాన్ఫిగ్ పేన్ (భాగస్వామ్యమైనది)

`StudioConfigPane.tsx` — ఎల్లప్పుడూ కనిపిస్తుంది, కుదించవచ్చు.

| ఫీల్డ్                  | కాంపోనెంట్            | గమనికలు                                                                         |
| ----------------------- | --------------------- | ------------------------------------------------------------------------------- |
| ఎండ్పాయింట్             | `<select>`            | `PlaygroundEndpoint`కు సరిపోలే 10 ఎంపికలు                                       |
| మోడల్                   | `<input>`             | స్వేచ్ఛా టెక్స్ట్, ఉదా. `openai/gpt-4o`                                         |
| సిస్టమ్ ప్రాంప్ట్       | `<textarea>`          | అన్ని ట్యాబ్లకు అందించబడుతుంది                                                  |
| పారామీటర్లు             | `ParamSliders`        | temperature, max_tokens, top_p, presence/frequency penalty, seed, stop          |
| ప్రీసెట్లు              | `PresetPicker`        | పేరుతో ఉన్న కాన్ఫిగ్ స్నాప్షాట్లను లోడ్/సేవ్ చేస్తుంది (DBలో నిల్వ చేయబడతాయి)   |
| ప్రాంప్ట్ను మెరుగుపరచడం | `ImprovePromptButton` | కోటా-హెచ్చరిక మోడల్ను తెరిచి, `/api/playground/improve-prompt`ను కాల్ చేస్తుంది |

స్థితి `PlaygroundStudio.tsx`కు ఎత్తబడుతుంది మరియు అన్ని ట్యాబ్లకు పంపబడుతుంది. ట్యాబ్లను
మార్చినప్పుడు కాన్ఫిగ్ స్థితి అలాగే ఉంటుంది.

## ప్రాంప్ట్ మెరుగుపరిచే సాధనం

`ImprovePromptButton.tsx` → `useImprovePrompt.ts` → `POST /api/playground/improve-prompt`:

1. "కోటాను వినియోగిస్తుంది" అని మోడల్ హెచ్చరిస్తుంది.
2. నిర్ధారించినప్పుడు, రూట్కు `{ system, prompt, model, tone }`ను పంపుతుంది.
3. రూట్ అంతర్గతంగా `promptImprover.META_SYSTEM_PROMPT`తో `/v1/chat/completions`ను కాల్ చేస్తుంది.
4. `{ improvedSystem?, improvedPrompt?, tokensIn, tokensOut }`ను తిరిగి ఇస్తుంది.
5. UI, కాన్ఫిగ్ పేన్ సిస్టమ్ ప్రాంప్ట్ను మరియు చాట్ ట్యాబ్ వినియోగదారు ప్రాంప్ట్ను ప్యాచ్ చేస్తుంది.

## ప్రీసెట్లు

`PresetPicker.tsx` → `usePresets.ts` → `/api/playground/presets/*`:

- `playground_presets` SQLite పట్టికలో నిల్వ చేయబడతాయి (మైగ్రేషన్ `084_playground_presets.sql`).
- ప్రతి ప్రీసెట్ వీటిని నిల్వ చేస్తుంది: `name`, `endpoint`, `model`, `system`, `params_json`, `created_at`.
- CRUD: `GET` జాబితా, `POST` సృష్టి, `GET /:id`, `PUT /:id`, `DELETE /:id`.

## స్ట్రీమ్ మెట్రిక్లు

`useStreamMetrics.ts` + `streamMetrics.ts` (ప్యూర్ ఫంక్షన్):

- `start()` — రిక్వెస్ట్ ప్రారంభ సమయాన్ని రికార్డ్ చేస్తుంది.
- `onFirstChunk()` — TTFTను రికార్డ్ చేస్తుంది.
- `onChunk(n)` — కంప్లీషన్ టోకెన్ల సంఖ్యను కూడబెడుతుంది.
- `finish(usage?)` — తుది మెట్రిక్లను గణిస్తుంది: `ttftMs`, `totalMs`, `tps`, `tokensIn`, `tokensOut`, `costUsd`.
- `src/lib/playground/types.ts`లోని స్టాటిక్ పట్టిక నుంచి ధర వివరాలు ("అంచనా" అని లేబుల్ చేయబడింది — D13).

| `POST`   | `/api/playground/presets`        | ప్రీసెట్ను సృష్టిస్తుంది; `PlaygroundPresetCreateSchema`ను ధృవీకరిస్తుంది                                      |
| `GET`    | `/api/playground/presets/:id`    | ఒక ప్రీసెట్ను లేదా 404ను తిరిగి ఇస్తుంది                                                                       |
| `PUT`    | `/api/playground/presets/:id`    | పాక్షిక నవీకరణ                                                                                                 |
| `DELETE` | `/api/playground/presets/:id`    | 204                                                                                                            |

ప్రమాణీకరణ: ఐచ్ఛికం (`REQUIRE_API_KEY`). లోపాలు `buildErrorBody()` ద్వారా నిర్వహించబడతాయి (కఠిన నియమం #12).
