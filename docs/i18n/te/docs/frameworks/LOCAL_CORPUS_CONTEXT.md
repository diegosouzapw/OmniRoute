## ఇది ఏమిటి

Local Corpus ద్వారా, ఒక ఆపరేటర్ స్పష్టంగా ఆమోదించిన ఒక టెక్స్ట్ ఫైళ్ల డైరెక్టరీని
OmniRoute యొక్క MCP సర్వర్కు అందుబాటులో ఉంచవచ్చు. ఫైళ్లు వాటి అసలు డైరెక్టరీలోనే ఉంటాయి:
OmniRoute కేవలం కానానికల్ రూట్ పాత్ను SQLiteలో నిల్వ చేసి, ఇన్-మెమరీ సెర్చ్ ఇండెక్స్ను
నిర్వహిస్తుంది. ఇది కార్పస్ కంటెంట్ను రిపోజిటరీలోకి లేదా డేటాబేస్లోకి కాపీ చేయదు.

ఇండెక్స్ రిఫ్రెష్ ఇంక్రిమెంటల్గా జరుగుతుంది. మార్పులేని ఫైళ్లు పరిమాణం మరియు సవరించిన
సమయం ఆధారంగా తిరిగి ఉపయోగించబడతాయి, మారిన ఫైళ్లు మళ్లీ చదవబడి SHA-256తో హ్యాష్
చేయబడతాయి, అలాగే తొలగించిన ఫైళ్లు తీసివేయబడతాయి. 30 సెకన్ల కంటే పాత ఇండెక్స్ను
సెర్చ్ రిఫ్రెష్ చేస్తుంది; కాలర్లు తక్షణ రిఫ్రెష్ను కూడా అభ్యర్థించవచ్చు.

## సోర్స్ను కాన్ఫిగర్ చేయడం

ఇతర సెట్టింగ్స్ APIల మాదిరిగానే, సెట్టింగ్స్ రూట్కు కూడా అదే మేనేజ్మెంట్
ఆథెంటికేషన్ అవసరం. సమర్పించిన పాత్ ఇప్పటికే ఉనికిలో ఉండాలి మరియు అది ఒక అబ్సల్యూట్
డైరెక్టరీ పాత్ అయి ఉండాలి.

```bash
# ఆమోదించిన డైరెక్టరీని కనెక్ట్ చేయండి
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# కాన్ఫిగరేషన్ మరియు ఇండెక్స్ స్థితిని తనిఖీ చేయండి
curl http://localhost:20128/api/settings/local-corpus

# సోర్స్ ఫైళ్లను మార్చకుండా డిస్కనెక్ట్ చేయండి
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## MCP టూల్స్

మూడు టూల్స్కూ `read:local-corpus` అవసరం. టూల్ రెస్పాన్స్లు రిలేటివ్ పాత్లను మరియు
రూట్ డైరెక్టరీ యొక్క బేస్నేమ్ను చూపుతాయి, కానీ దాని అబ్సల్యూట్ పాత్ను ఎప్పుడూ
చూపవు.

| టూల్                  | వివరణ                                                                                                         |
| :-------------------- | :------------------------------------------------------------------------------------------------------------ |
| `local_corpus_status` | కాన్ఫిగరేషన్ స్థితి, ఇండెక్స్ పరిమాణం, పరిమితులు మరియు చివరి రిఫ్రెష్ సమయాన్ని నివేదిస్తుంది                  |
| `local_corpus_search` | ఇండెక్స్ చేసిన టెక్స్ట్ను వెతికి, పరిమితమైన, లైన్-స్కోప్డ్ స్నిపెట్లను తిరిగి ఇస్తుంది (గరిష్ఠంగా 20 ఫలితాలు) |
| `local_corpus_read`   | అనుమతించబడిన ఒక కార్పస్-రిలేటివ్ ఫైల్ నుంచి పరిమిత లైన్ పరిధిని చదువుతుంది                                    |

MCP ఇన్పుట్ల ఉదాహరణలు:

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## భద్రతా హద్దులు

- అనుమతి జాబితా టెక్స్ట్-ఆధారితమైనది: `.cfg`, `.csv`, `.geojson`, `.htm`, `.html`, `.ini`,
  `.js`, `.json`, `.jsonl`, `.jsx`, `.log`, `.md`, `.mjs`, `.ps1`, `.py`, `.sh`,
  `.sql`, `.toml`, `.ts`, `.tsx`, `.txt`, `.xml`, `.yaml`, మరియు `.yml`.
- సింబాలిక్ లింక్లు దాటవేయబడతాయి. రీడ్ పాత్లు కానానికలైజ్ చేయబడతాయి మరియు అవి
  కాన్ఫిగర్ చేసిన రూట్లోనే ఉండాలి; అబ్సల్యూట్ పాత్లు మరియు ట్రావర్సల్ ప్రయత్నాలు తిరస్కరించబడతాయి.
- సున్నితమైన మరియు జనరేట్ చేసిన డైరెక్టరీ పేర్లు మినహాయించబడతాయి: `.build`, `.codex`, `.env`,
  `.git`, `.next`, `.omniroute`, `.ssh`, `coverage`, `dist`, `node_modules`, మరియు
  `secrets`.
- డిఫాల్ట్ పరిమితులు: 5,000 ఫైళ్లు, ప్రతి ఫైల్కు 1 MiB, మొత్తం ఇండెక్స్ చేసిన కంటెంట్కు
  64 MiB, ప్రతి సెర్చ్ చంక్కు సుమారు 4,000 అక్షరాలు, మరియు ప్రతి రీడ్కు 400 లైన్లు.
- NUL కలిగిన ఫైళ్లు టెక్స్ట్ కానివిగా పరిగణించబడి, దాటవేయబడతాయి లేదా తిరస్కరించబడతాయి.

PDF, DOCX, చిత్రాలు మరియు ఆర్కైవ్ల వంటి బైనరీ డాక్యుమెంట్లకు ఉద్దేశపూర్వకంగానే
మద్దతు లేదు. ఇండెక్సింగ్కు ముందు వాటిని కాన్ఫిగర్ చేసిన డైరెక్టరీలో ఆమోదించబడిన
టెక్స్ట్ ఫార్మాట్కు మార్చండి.

## నిర్వహణ గమనికలు

- కాన్ఫిగర్ చేసిన రూట్ను మార్చడం లేదా తొలగించడం వల్ల షేర్డ్ ఇన్-మెమరీ ఇండెక్స్ క్లియర్ అవుతుంది.
- ప్రాసెస్ను రీస్టార్ట్ చేస్తే ఇండెక్స్ తొలగిపోతుంది; తదుపరి సెర్చ్ దాన్ని కాన్ఫిగర్ చేసిన
  సోర్స్ నుంచి మళ్లీ నిర్మిస్తుంది.
- `local_corpus_status` బలవంతంగా స్కాన్ చేయదు. తక్షణ రీస్కాన్ అవసరమైనప్పుడు
  `refresh: true`తో `local_corpus_search`ను ఉపయోగించండి.
- స్కాన్ మరియు రీడ్ వైఫల్యాలు లెక్కించబడతాయి లేదా శానిటైజ్ చేసిన ఎర్రర్లుగా తిరిగి
  ఇవ్వబడతాయి; సోర్స్ ఫైళ్లు ఎప్పుడూ సవరించబడవు.
