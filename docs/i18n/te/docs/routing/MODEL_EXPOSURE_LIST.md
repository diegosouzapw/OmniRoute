> ఆప్ట్-ఇన్, డిఫాల్ట్గా ఆఫ్లో ఉంటుంది (`modelVisibilityAllowlist`/`modelVisibilityDenylist` రెండూ ఖాళీగా ఉంటే
> `/v1/models` కేటలాగ్ మరియు ప్రతి `auto/*` అభ్యర్థి పూల్ బైట్-టు-బైట్ ఒకేలా ఉంటాయి). ఖర్చుతో ఎలాంటి
> సంబంధం లేని కారణాల కోసం క్యురేట్ చేసిన మోడల్ జాబితాను కోరుకునే ఆపరేటర్ల కోసం
> `hidePaidModels`/`hideAutoCombos` (`src/lib/db/settings.ts`)కు సహోదర సెట్టింగ్.

## ఇది ఎందుకు ఉంది

`hidePaidModels` అనేది "ఈ మోడల్ ఉచితమా?" అనే ప్రశ్నకు, `hideAutoCombos` అనేది "`auto/*`
వర్చువల్ idలను అసలు ప్రచారం చేయాలా?" అనే ప్రశ్నకు సమాధానమిస్తాయి — కానీ ఏదీ మోడళ్లలో
ఏదైనా నిర్దిష్ట ఉపసమితిని ఆపరేటర్ క్యురేట్ చేసేందుకు అనుమతించదు (ఉదా. ధరతో సంబంధం లేకుండా,
నిర్దిష్ట Claude Code / OpenCode క్లయింట్ చూడాల్సిన మోడళ్లను మాత్రమే ఖచ్చితంగా చూపించడం).
#11481 దీన్ని రెండు స్వతంత్ర, ఆప్ట్-ఇన్ స్ట్రింగ్-అరే సెట్టింగ్లుగా జోడిస్తుంది.

## సెట్టింగ్లు

| కీ                         | రకం        | డిఫాల్ట్ | అర్థం                                                                    |
| -------------------------- | ---------- | -------- | ------------------------------------------------------------------------ |
| `modelVisibilityDenylist`  | `string[]` | `[]`     | అభ్యర్థితో సరిపోలే ఎంట్రీలు దాన్ని కేటలాగ్/అభ్యర్థి పూల్ నుండి దాచుతాయి. |
| `modelVisibilityAllowlist` | `string[]` | `[]`     | ఖాళీగా లేనప్పుడు, అభ్యర్థితో సరిపోలే ఎంట్రీలు మాత్రమే కనిపించేలా ఉంటాయి. |

రెండూ ఒక్కోటి గరిష్ఠంగా 200 అక్షరాలు కలిగిన 500 ఎంట్రీల వరకు అనుమతిస్తాయి
(`src/shared/validation/settingsSchemas.ts`లో Zod ద్వారా ధ్రువీకరించబడతాయి). ఒక ఎంట్రీ వీటిలో ఒకటి:

- ఖచ్చితమైన కేటలాగ్ id — `"gpt-4o"` (ప్రొవైడర్ ప్రిఫిక్స్ లేని మోడల్ id) లేదా `"openai/gpt-4o"` (ప్రొవైడర్ ప్రిఫిక్స్తో), లేదా
- `*`/`?`ను ఉపయోగించే గ్లోబ్ నమూనా — ఉదా. `"openai/gpt-4*"` లేదా `"anthropic/*"` — ఇప్పటికే
  `ModelRoutingSection` యొక్క ప్రతి-మోడల్ కాంబో మ్యాపింగ్లు మరియు
  `freeModels.ts::matchesOnlyPaidModels` ఉపయోగిస్తున్న అదే భాగస్వామ్య `globToRegex()` మ్యాచర్
  (`src/shared/utils/globPattern.ts`) ద్వారా పరిష్కరించబడుతుంది.

ప్రాధాన్యత: డినైలిస్ట్ మొదట తనిఖీ చేయబడుతుంది (తిరస్కరించబడిన ఎంట్రీ అలవ్లిస్ట్తో కూడా
సరిపోలినా ఎల్లప్పుడూ దాచబడుతుంది); అలవ్లిస్ట్ ఖాళీగా లేనప్పుడు, దానితో సరిపోలే ఎంట్రీలు మాత్రమే మిగులుతాయి.

## ఒకటి కాదు, రెండు చోక్పాయింట్లు

#6512 నుండి నేర్చుకున్న పాఠం (`hidePaidModels`-మాత్రమే ఉన్న కేటలాగ్ ఫిల్టర్, కాంబో అభ్యర్థి పూల్
స్వతంత్రంగా నిర్మించబడినందున, `auto/*`ను ఇప్పటికీ చెల్లింపు మోడల్కు రూట్ చేయనిచ్చింది) ఇక్కడ కూడా
అదే విధంగా వర్తిస్తుంది. సరిపోలిక ప్రెడికేట్ `isModelExposureAllowed()`
(`src/shared/utils/modelExposureList.ts`) ఈ రెండింటి నుండీ కాల్ చేయబడుతుంది:

- `src/app/api/v1/models/catalog.ts` — `/v1/models` జాబితా, ఇప్పటికే `shouldHidePaid()` గేట్ చేసే
  ప్రతి సోర్స్కు సంబంధించిన అదే 5 చోక్పాయింట్ల వద్ద (స్టాటిక్ `PROVIDER_MODELS`, సింక్ చేసిన
  ప్రొవైడర్ రోలు, కస్టమ్ రోలు, అలియాస్-ఆధారిత రోలు, మేనేజ్డ్-ఫాల్బ్యాక్ రోలు).
- `open-sse/services/autoCombo/modelExposureFilter.ts::filterModelExposureCandidates()` — సమానమైన
  `filterPaidOnlyCandidates()` కాల్ చేసిన వెంటనే `virtualFactory.ts::buildPreparedPool` నుండి
  కాల్ చేయబడుతుంది, కాబట్టి తిరస్కరించబడిన మోడల్ను `auto/*` అభ్యర్థి పూల్లోకి కూడా ఎప్పటికీ
  ఎంచుకోలేరు.

## ఏవి ఫిల్టర్ చేయబడవు

`hideAutoCombos` యొక్క ప్రస్తుత ప్రవర్తనను ప్రతిబింబిస్తుంది: **స్పష్టంగా** పంపిన మోడల్ id (`auto/*`
ద్వారా కాకుండా, కేటలాగ్ జాబితా ద్వారా కనుగొనబడకుండా) డిస్పాచ్ సమయంలో ఎప్పటికీ బ్లాక్ చేయబడదు —
ప్రచారం/అభ్యర్థి-పూల్ సభ్యత్వం మాత్రమే ఫిల్టర్ చేయబడుతుంది. ఇది `hidePaidModels` నుండి స్వతంత్రం;
ఖర్చుతో ఎలాంటి సంబంధం లేని కారణాల కోసం ఆపరేటర్ క్యురేట్ చేసిన సమితిని కోరుకోవచ్చు, కాబట్టి
`catalog.ts`లో ఇప్పటికే ఉన్న బహుళ-ఫ్లాగ్ కూర్పు మాదిరిగానే, రెండు సెట్టింగ్లు స్వతంత్రంగా AND
చేయబడిన ఫిల్టర్లుగా కలిసి పనిచేస్తాయి.

సెట్టింగ్ల ఎక్స్పోర్ట్ (`GET /api/settings/export-json`) ఏ ఇతర సెట్టింగ్ ఫీల్డ్ మాదిరిగానే రెండు
అరేలను యథాతథంగా కలిగి ఉంటుంది — `hidePaidModels` యొక్క కాంబో-స్టెప్ ఎక్స్పోర్ట్ ఫిల్టర్కు భిన్నంగా,
ఇక్కడ రీ-హైడ్రేషన్ ప్రమాదం లేదు: ఎక్స్పోర్ట్ చేసిన కాంబో స్టెప్లో పొందుపరిచిన తిరస్కరించబడిన id
ఆపరేటర్ స్వయంగా చేసిన స్పష్టమైన రూటింగ్ ఎంపిక; దాన్ని ఎక్స్పోర్ట్ సరిహద్దు తొలగించాల్సిన అవసరం లేదు.
