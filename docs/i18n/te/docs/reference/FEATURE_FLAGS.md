> మళ్లీ డిప్లాయ్ చేయకుండానే OmniRoute ప్రవర్తనను మార్చే రన్టైమ్ టాగిళ్లు.
> ఇక్కడ జాబితా చేసిన ప్రతి ఫ్లాగ్
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> లో నిర్వచించబడింది — ఇదే ఏకైక ప్రామాణిక మూలం. డ్యాష్బోర్డ్ మరియు REST API రెండూ
> ఆ ఫైల్ నుంచే చదువుతాయి, కాబట్టి దిగువ పట్టిక దానితో 1:1 సరిపోలేలా రూపొందించబడింది.

## ఫీచర్ ఫ్లాగ్లు అంటే ఏమిటి

ఫీచర్ ఫ్లాగ్ అనేది పేరు కలిగిన టాగిల్ (boolean లేదా enum); దాని విలువను
రన్టైమ్లో మార్చి, డేటాబేస్లో నిల్వ చేయవచ్చు, ఇందుకు ప్రాసెస్ను మళ్లీ డిప్లాయ్ చేయాల్సిన అవసరం లేదు. ప్రతి
ఫ్లాగ్ను `key`, `label`, `description`, `category`, `defaultValue`, `type`,
మరియు `requiresRestart` సూచన కలిగిన `FeatureFlagDefinition` వివరిస్తుంది.

### పరిష్కార ప్రాధాన్యత క్రమం

ఫ్లాగ్ యొక్క **ప్రభావవంతమైన విలువ**ను
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) ఈ
ప్రాధాన్యత క్రమంలో పరిష్కరిస్తుంది (అత్యధిక ప్రాధాన్యత గలది అమలవుతుంది):

1. **DB ఓవర్రైడ్** — `feature_flags` నేమ్స్పేస్ కింద `key_value` పట్టికలో
   నిల్వ చేయబడిన విలువ (డ్యాష్బోర్డ్ లేదా REST API ద్వారా సెట్ చేయబడుతుంది).
2. **ఎన్విరాన్మెంట్ వేరియబుల్** — సెట్ చేయబడి, ఖాళీగా లేకపోతే `process.env[<KEY>]`.
3. **నిర్వచన డిఫాల్ట్** — `featureFlagDefinitions.ts` నుంచి తీసుకున్న `defaultValue`.

boolean ఫ్లాగ్ ప్రభావవంతమైన విలువ `"true"`,
`"1"`, లేదా `"yes"` అయినప్పుడు అది **ప్రారంభించబడినట్లు** పరిగణించబడుతుంది
(`isFeatureFlagEnabled()` చూడండి).

> [!NOTE]
> చాలా ఫ్లాగ్లకు [`ENVIRONMENT.md`](./ENVIRONMENT.md)లో డాక్యుమెంట్ చేయబడిన
> **అదే పేరు** గల సంబంధిత ఎన్విరాన్మెంట్ వేరియబుల్ కూడా ఉంటుంది. ఫ్లాగ్ యొక్క DB ఓవర్రైడ్కు
> ఆ ఎన్విరాన్మెంట్ వేరియబుల్ కంటే అధిక ప్రాధాన్యత ఉంటుంది. `requiresRestart: true`
> గల ఫ్లాగ్ వెంటనే నిల్వ చేయబడుతుంది, కానీ ప్రాసెస్ ప్రారంభ సమయంలో మాత్రమే మళ్లీ చదవబడుతుంది
> — దాన్ని టాగిల్ చేసినప్పుడు డ్యాష్బోర్డ్లో **"సర్వర్ను పునఃప్రారంభించండి"** బ్యానర్ కనిపిస్తుంది.

## ఫ్లాగ్లను టాగుల్ చేయడం

### డ్యాష్బోర్డ్

**Dashboard → Settings → Feature Flags**కు వెళ్లండి
(`/dashboard/settings/feature-flags`). గ్రిడ్
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
కింది వాటికి మద్దతు ఇస్తుంది:

- కీ లేదా వివరణ ఆధారంగా **శోధన**, అలాగే వర్గం ఆధారంగా **ఫిల్టర్** (అదనంగా ఒక సింథటిక్
  **Requires Restart** వీక్షణ).
- బూలియన్ ఫ్లాగ్ల కోసం ఒక **టాగుల్**, enum ఫ్లాగ్ల కోసం ఒక **డ్రాప్డౌన్**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- ప్రతి ఫ్లాగ్కు ఒక **సోర్స్ బ్యాడ్జ్** — `DB`, `ENV`, లేదా `DEF` — ఇది అమల్లో ఉన్న
  విలువ ఎక్కడి నుంచి వచ్చిందో చూపిస్తుంది.
- ఓవర్రైడ్ను తొలగించడానికి ఒక **Reset** బటన్ (`DB` మూలం గల ఫ్లాగ్లకు మాత్రమే చూపబడుతుంది),
  అలాగే దిగువన ఒక **Reset All Overrides** బటన్.
- `requiresRestart` ఫ్లాగ్ మార్చబడినప్పుడు ఒక **Restart Server** బ్యానర్.

### REST API

అన్ని ఆపరేషన్లు ఒకే రూట్ ద్వారా జరుగుతాయి:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
ప్రతి మెథడ్కు ప్రామాణీకరించబడిన డ్యాష్బోర్డ్ సెషన్ అవసరం (లేకపోతే `401`).

#### `GET /api/settings/feature-flags`

అమల్లో ఉన్న విలువ, మూలం, సారాంశంతో సహా ప్రతి ఫ్లాగ్ను అందిస్తుంది.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... మొత్తం 75 ఫ్లాగ్లు
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

ఒకే ఓవర్రైడ్ను సెట్ చేయండి లేదా తొలగించండి. బాడీ: `{ key: string; value?: string }`.
`value`ను చేర్చకపోతే ఓవర్రైడ్ తొలగించబడుతుంది (env / default పునరుద్ధరించబడుతుంది).

```bash
# DB ఓవర్రైడ్ను సెట్ చేయండి
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# ఓవర్రైడ్ను తొలగించండి ("value" లేకుండా)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

రెస్పాన్స్ కొత్త `effectiveValue`/`source`, `previousValue`/
`previousSource`, అలాగే `requiresRestart`ను తిరిగి అందిస్తుంది. తెలియని కీలు మరియు అనుమతించిన పరిధికి వెలుపల ఉన్న enum
విలువలు `400`తో తిరస్కరించబడతాయి.

#### `DELETE /api/settings/feature-flags`

అన్ని DB ఓవర్రైడ్లను ఒకేసారి తొలగించి, ప్రతి ఫ్లాగ్ను దాని env / default
విలువకు పునరుద్ధరిస్తుంది. `{ cleared: <count>, message: "..." }`ను అందిస్తుంది.

> [!NOTE]
> `requiresRestart: true` ఉన్న ఫ్లాగ్లు ప్రాసెస్ రీలోడ్ తర్వాత మాత్రమే అమల్లోకి వస్తాయి.
> డ్యాష్బోర్డ్ రీస్టార్ట్ ప్రక్రియ `POST /api/restart`ను కాల్ చేసి, ఆపై సర్వర్ తిరిగి ప్రారంభమయ్యే వరకు
> `GET /api/health/ping`ను పోల్ చేస్తుంది.

## అత్యవసర బడ్జెట్ ఫాల్బ్యాక్

`OMNIROUTE_EMERGENCY_FALLBACK` (వర్గం `runtime`, డిఫాల్ట్ `true`) అనేది
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)లోని
అత్యవసర ఉచిత-ఫాల్బ్యాక్ మార్గాన్ని నియంత్రిస్తుంది.
ఇది ప్రారంభించబడి ఉన్నప్పుడు, తమ బడ్జెట్ను పూర్తిగా వినియోగించిన అభ్యర్థనలు పూర్తిగా విఫలం కావడానికి బదులుగా ఉచిత ఫాల్బ్యాక్
ప్రొవైడర్/మోడల్కు రూట్ చేయబడతాయి. ఈ ప్రవర్తనను నిలిపివేసి, బడ్జెట్ అయిపోయిన అభ్యర్థనలు
విఫలం కావడానికి దీన్ని `false` (లేదా `0`)కు సెట్ చేయండి — డ్యాష్బోర్డ్
టాగుల్, DB ఓవర్రైడ్ లేదా `OMNIROUTE_EMERGENCY_FALLBACK`
ఎన్విరాన్మెంట్ వేరియబుల్ ద్వారా. (PRలు #3741 / #3752లో డ్యాష్బోర్డ్ టాగుల్గా అందుబాటులోకి తీసుకురాబడింది.)
