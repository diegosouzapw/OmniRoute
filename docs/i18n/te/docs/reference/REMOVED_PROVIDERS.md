కొన్ని సేవలు OmniRouteలో సమీకరించబడి, తరువాత వాటిని నిర్వహించే వ్యక్తులు
కోరినందున తొలగించబడ్డాయి. ఈ తొలగింపులకు ఈ పేజీ శాశ్వత రికార్డు. అవి పొరపాటున
మళ్లీ చేర్చబడకుండా నిరోధించడమే దీని ఏకైక ఉద్దేశ్యం: పాత ఫోర్క్, క్యాష్ చేసిన npm
టార్బాల్, ఆర్కైవ్ చేసిన ఇష్యూ లేదా "ప్రొవైడర్ Xను పునరుద్ధరించండి" అనే అభ్యర్థనను కనుగొన్న కంట్రిబ్యూటర్కు **మళ్లీ
ప్రవేశపెట్టవద్దు** అని చెప్పే ఒకే స్థలం అవసరం.

ఈ పేజీ నిలిచిపోయిన లేదా రద్దు చేయబడిన సేవల జాబితా **కాదు**. అవి
[`FREE_TIERS.md`](FREE_TIERS.md)లో ("తొలగించబడినవి / ఉచిత టైర్ లేదు") ట్రాక్ చేయబడతాయి మరియు సేవ
తిరిగి వస్తే అవి కూడా తిరిగి రావచ్చు. దిగువ ఎంట్రీలు అభ్యర్థనలో పేర్కొన్న ఆపరేటర్ నుండి
లిఖితపూర్వక అనుమతి ఉంటే మాత్రమే తిరిగి రావచ్చు, అలాగే ఆ అనుమతికి సంబంధించిన లింక్ను ఎంట్రీలో తప్పనిసరిగా చేర్చాలి.

## విధానం

1. **సేవా ఆపరేటర్ నుండి వచ్చిన తొలగింపు అభ్యర్థనను గౌరవించాలి, దానిపై బేరసారాలు చేయకూడదు.** OmniRouteకు
   ఏ అప్స్ట్రీమ్ సేవతోనూ అనుబంధం లేదు. ఏదైనా సేవా ఆపరేటర్ ఆ సమీకరణను
   తొలగించమని కోరితే, అది అధికారిక APIని ఉపయోగించినా లేదా ఉపయోగించకపోయినా తొలగించబడుతుంది.
2. **"తొలగించబడింది" అంటే OmniRoute నియంత్రించే ప్రతి ఉపరితలం నుండి తొలగించబడిందని అర్థం.** ఎగ్జిక్యూటర్, రిజిస్ట్రీ ఎంట్రీ, ప్రొవైడర్
   id మరియు అలియాస్, మోడల్ జాబితా, ఎండ్పాయింట్లు, ఎన్విరాన్మెంట్ వేరియబుల్స్, ఐకాన్, డ్యాష్బోర్డ్ కార్డులు,
   రూపొందించిన ప్రొవైడర్ రిఫరెన్స్, `FREE_TIERS.md`, ఎన్విరాన్మెంట్ రిఫరెన్స్, README గణనలు,
   `llm.txt` మిర్రర్లు, ప్రత్యేక పరీక్షలు మరియు గోల్డెన్ స్నాప్షాట్లు, కోడ్ కామెంట్లు, CHANGELOG బులెట్లు
   (లెడ్జర్లో నమోదు చేసిన సయోధ్యతో, `config/release/changelog-reconciliations.json` చూడండి),
   GitHub Releases నోట్లు, వికీ మరియు ఆ ప్రొవైడర్నే అంశంగా కలిగిన GitHub ఇష్యూలు, చర్చలు మరియు పుల్ రిక్వెస్ట్లు
   (ఇష్యూలు మరియు చర్చలు తొలగించబడతాయి; GitHub పుల్ రిక్వెస్ట్లను తొలగించలేనందున పుల్ రిక్వెస్ట్లకు కొత్త శీర్షికలు పెట్టి, వాటి
   వివరణను భర్తీ చేసి, థ్రెడ్ను లాక్ చేస్తారు).
3. **లిఖితపూర్వక అనుమతి లేకుండా ఈ పేజీలోని ఎంట్రీని ఎప్పటికీ మళ్లీ ప్రవేశపెట్టవద్దు.** ఇందులో
   ఏదైనా ప్రొవైడర్ కేటలాగ్కు id లేదా అలియాస్ను తిరిగి జోడించడం, డొమైన్లను ఎగ్జిక్యూటర్కు జోడించడం,
   దాన్ని "పునరుద్ధరించే" కంట్రిబ్యూటర్ PRను ఆమోదించడం, ఉచిత-మోడల్ కేటలాగ్కు దాన్ని జోడించడం లేదా
   OmniRoute ద్వారా దాన్ని మాన్యువల్గా చేరుకునే విధానాన్ని డాక్యుమెంట్ చేయడం కూడా ఉన్నాయి. అటువంటి PRలు మరియు ఇష్యూలను ఈ
   పేజీకి లింక్తో మూసివేయండి.
4. **ఎంట్రీని కనిష్ఠంగా ఉంచండి.** మళ్లీ ప్రవేశపెట్టడాన్ని గుర్తించడానికి రివ్యూయర్కు అవసరమైన వాటిని మాత్రమే నమోదు చేయండి:
   ఐడెంటిఫయర్లు, డొమైన్లు, తేదీలు మరియు తొలగింపును చేసిన పుల్ రిక్వెస్ట్.
   సమీకరణ ఎలా పనిచేసిందో వివరించవద్దు.
5. **రిగ్రెషన్ గార్డ్ `tests/unit/removed-providers-blocklist.test.ts`.** దిగువ ఉన్న ఏదైనా
   ఐడెంటిఫయర్ లేదా డొమైన్ ప్రొవైడర్ కేటలాగ్లు, ఎగ్జిక్యూటర్ మ్యాప్ లేదా ప్రొవైడర్ రిజిస్ట్రీ సోర్స్లలో
   మళ్లీ కనిపిస్తే ఇది విఫలమవుతుంది. ఇక్కడ వరుసను జోడించే అదే PRలో కొత్త ఐడెంటిఫయర్లను ఆ పరీక్షకు
   జోడించండి.

## ఎంట్రీని జోడించడం

1. అభ్యర్థన సేవా ఆపరేటర్ నుండే వచ్చిందని (వారి సపోర్ట్ అడ్రస్ లేదా వారు నియంత్రించే
   డొమైన్ ద్వారా) నిర్ధారించుకొని, సందేశాన్ని ప్రైవేట్గా ఉంచండి.
2. విధానంలోని అంశం 2లో ఉన్న చెక్లిస్ట్ను అనుసరించి సమీకరణను తొలగించండి. కీ అవసరం లేని
   ప్రొవైడర్ కోసం [#12440](https://github.com/diegosouzapw/OmniRoute/pull/12440)ను, నిల్వ చేసిన కనెక్షన్లు కలిగిన
   API-key ప్రొవైడర్ కోసం [#10210](https://github.com/diegosouzapw/OmniRoute/pull/10210)ను రిఫరెన్స్గా ఉపయోగించండి
   (ఒక మైగ్రేషన్ను జోడించండి).
3. అదే PRలో, పై పట్టికకు ఒక వరుసను మరియు
   `tests/unit/removed-providers-blocklist.test.ts`కు ఐడెంటిఫయర్లను జోడించండి.
4. PR మెర్జ్ అయిన తరువాత ఆపరేటర్కు ప్రతిస్పందించి, ఏమేమి తొలగించబడ్డాయో మరియు OmniRoute
   మార్చలేని వాటిని (ఇప్పటికే ప్రచురించబడిన npm మరియు Docker వెర్షన్లు, git హిస్టరీ, థర్డ్-పార్టీ ఫోర్క్లు) జాబితా చేయండి.
