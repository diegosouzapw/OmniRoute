`devin-cli-agentic`, అధికారిక Devin CLI ACP stdio ద్వారా మోడల్ ప్రతిస్పందనలను అందిస్తుండగా,
నిజమైన Claude Code రన్టైమ్ను OmniRoute యొక్క స్థానిక Anthropic Messages ఎండ్పాయింట్ను
ఉపయోగించడానికి అనుమతిస్తుంది. ఇది ఇప్పటికే ఉన్న Anthropic, Claude OAuth, Claude Web లేదా
`devin-cli` ప్రొవైడర్లను సవరించదు.

> **ప్రస్తుత స్థితి: Claude Code `2.1.258`కు పిన్ చేయబడింది; చివరిగా నమోదు చేసిన ఆఫ్లైన్
> మరియు లైవ్ ధ్రువీకరణ `2.1.220`పై జరిగింది.** `2.1.220` పిన్, Devin CLI
> `3000.2.17` మరియు `swe-1-7-lightning` మోడల్ ద్వారా మూడు వేరు చేసిన సందర్భాలను పూర్తి చేసింది;
> ఆ చివరి లైవ్ రన్ క్లయింట్ ఆధీనంలోని `Read`, `Edit`, మరియు `Bash` టర్న్లు, విజయవంతమైన
> `npm test` ఫలితాలు, ప్రాజెక్ట్ కమాండ్ మరియు స్కిల్ గుర్తింపు, Devin-మాత్రమే రౌటింగ్,
> అలాగే Claude వైపు సున్నా ఎగ్రెస్ను నిరూపించింది. అనంతరం పిన్ `2.1.258`కు పెంచబడింది
> (OmniRoute యొక్క Claude గుర్తింపు అనుకరించే CLI తరం, అలాగే Fable 5.1 టియర్ను స్థానికంగా
> అందించే మొదటి లైన్). కొత్త పిన్పై, పిన్ చేసిన బేస్ ఇమేజ్లో ఇన్స్టాల్ లేయర్ మరియు
> `claude --version` ధ్రువీకరించబడ్డాయి; అలాగే బ్రిడ్జ్ యూనిట్ సూట్, `compose config` మరియు
> స్థిర ఐసోలేషన్ రుజువు విజయవంతమయ్యాయి — కానీ ఆఫ్లైన్ మాక్ సందర్భం మరియు లైవ్ మూడు-సందర్భాల
> సూట్ ఇంకా మళ్లీ అమలు చేయబడలేదు. ఈ పిన్తో బ్రిడ్జ్పై ఆధారపడే ముందు వాటిని మళ్లీ అమలు
> చేయండి ("పిన్ చేసిన సాధనాలను నవీకరించడం" చూడండి).

## ఆర్కిటెక్చర్

```text
Claude Code 2.1.258 (వేరు చేసిన non-root Linux కంటైనర్)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-ఫార్మాట్, no-auth ప్రొవైడర్)
  -> devin acp --agent-type summarizer (అధికారిక ACP stdio, Devin సాధనాలు లేవు)
  -> ప్రత్యేక devin-auth వాల్యూమ్లోని Devin ఖాతా
```

అధికారిక CLI యొక్క డిఫాల్ట్ ACP ఏజెంట్ తన స్వంత సాధనాలను అమలు చేయగలదు, కాబట్టి ఈ బ్రిడ్జ్
దానిని ఉపయోగించదు. ఇది సాధనాలు లేని అధికారిక CLI మోడ్ను కలిగిన స్థిర `summarizer` ACP
ఏజెంట్ను ప్రారంభించి, సీరియలైజ్ చేసిన Anthropic అభ్యర్థనను ఎగ్జిక్యూషన్ ట్రేస్గా
ఫ్రేమ్ చేస్తుంది. Claude ఆధీనంలోని మరొక చర్య అవసరమైనప్పుడు, ప్రతిస్పందనలో ఖచ్చితంగా ఒక
క్లయింట్ టూల్ ఎన్వలప్ ఉండాలి. ప్రతిస్పందన విజయవంతమైందని నివేదించడానికి ముందు ఏదైనా ACP
`tool_call` లేదా `tool_call_update` తిరస్కరించబడుతుంది.

`open-sse/executors/devin-agentic/serializer.ts`లోని సీరియలైజర్ `system`, `text`,
`tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice`, మరియు Claude Code
అందించిన సాధనాలను యథాతథంగా ఉంచుతుంది. చిత్రాలు మరియు తెలియని బ్లాక్లు స్పష్టంగా
విఫలమవుతాయి. పెద్ద టూల్ ఫలితాలు కనిపించే ట్రంకేషన్ మార్కర్ను ఉపయోగిస్తాయి.

పార్సర్ ప్రతి మోడల్ టర్న్కు ఒక స్వతంత్ర `<tool>{...}</tool>` ఎన్వలప్ను అంగీకరిస్తుంది.
ఇది అభ్యర్థనలోని టూల్ జాబితాతో పేరును తనిఖీ చేస్తుంది, ఆ టూల్ యొక్క JSON Schema ప్రకారం
ఆర్గ్యుమెంట్లను ధ్రువీకరిస్తుంది, వివరణాత్మక వచనం/చర్యల మిశ్రమాన్ని తిరస్కరిస్తుంది, మరియు
ఒక పరిమిత రిపేర్ను అనుమతిస్తుంది. ఆపై Claude Code ఫలితంగా వచ్చిన Anthropic `tool_use`ను
స్థానికంగా అమలు చేసి, `tool_result`ను OmniRoute ద్వారా తిరిగి పంపుతుంది.

## ఐసోలేషన్ మరియు ముప్పు నమూనా

హోస్ట్లోని Claude ఇన్స్టాలేషన్, ఖాతా, మరియు కాన్ఫిగరేషన్ పరిధికి వెలుపలివిగా మరియు
నిషేధితమైనవిగా పరిగణించబడతాయి. Compose సేవలు:

- UID/GID `10001:10001`గా, రీడ్-ఓన్లీ రూట్ ఫైల్సిస్టమ్, తొలగించిన సామర్థ్యాలు, మరియు
  `no-new-privileges`తో అమలవుతాయి;
- ప్రైవేట్ `/home/bridge`, ప్రత్యేక Claude కాన్ఫిగరేషన్ వాల్యూమ్, వేరుచేసిన OmniRoute డేటా,
  మరియు ప్రత్యేక `devin-auth` వాల్యూమ్ను ఉపయోగిస్తాయి;
- తాత్కాలిక `.sandbox` వర్క్స్పేస్లు/ఆధారాలను మాత్రమే మౌంట్ చేస్తాయి;
- హోస్ట్ హోమ్, Keychain, SSH, క్లౌడ్ క్రెడెన్షియల్లు లేదా Docker సాకెట్ను మౌంట్ చేయవు;
- స్పష్టమైన ఎన్విరాన్మెంట్లను నిర్మించి, Anthropic API/OAuth/రౌటింగ్ వేరియబుల్లను
  తొలగిస్తాయి;
- స్థానిక-మాత్రమే కీతో Claude Code ఇన్ఫరెన్స్ను `http://omniroute:20128`కు మాత్రమే
  మళ్లిస్తాయి.

ఆఫ్లైన్ ప్రొఫైల్ అంతర్గత నెట్వర్క్ను ఉపయోగిస్తుంది. లైవ్ ప్రొఫైల్లో, OmniRoute
అధికారిక Devin ఎండ్పాయింట్లను `network-guard` ద్వారా మాత్రమే చేరుకుంటుంది; సంబంధంలేని
గమ్యస్థానాలు నిరాకరించబడతాయి. Claude Codeకు ప్రత్యేక deny-all ఎగ్రెస్ గార్డ్ ఉంటుంది మరియు
`NO_PROXY` ద్వారా స్థానిక OmniRoute సేవను మాత్రమే చేరుకోగలదు. గార్డ్ ఆడిట్ ఫైల్లు వాటి
గార్డ్ ప్రాసెస్ ద్వారా మాత్రమే మౌంట్ చేయబడతాయి. టోకెన్-రహిత ఆధారాలను ఎగుమతి చేయడానికి ముందు
స్క్రిప్ట్లు ఫైల్ యాజమాన్యం, మోడ్, లింక్ కౌంట్, మరియు ప్రతి నిర్ణయాన్ని ధ్రువీకరిస్తాయి.

ఐసోలేషన్ రుజువును స్వతంత్రంగా అమలు చేయండి:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

ఇది టోపాలజీ, నేమ్డ్ మౌంట్లు, non-root/రీడ్-ఓన్లీ సెట్టింగ్లు, స్పష్టమైన స్థానిక రౌటింగ్,
సున్నితమైన ఎన్విరాన్మెంట్ వేరియబుల్లు లేకపోవడం, Docker సాకెట్ లేకపోవడం,
`api.anthropic.com` మరియు `claude.ai`కు నిరోధించబడిన యాక్సెస్, Devin-మాత్రమే ప్రొవైడర్
ఎంపిక, మరియు ACP బ్యాకెండ్ అందుబాటులో లేనప్పుడు స్పష్టమైన వైఫల్యాన్ని ధ్రువీకరిస్తుంది.

## మొదటిసారి సెటప్ మరియు సాధారణ వినియోగం

పిన్ చేసిన ఇమేజ్ను బిల్డ్ చేయండి:

```bash
./scripts/devin-bridge/build
```

వేరుచేసిన Devin వాల్యూమ్ను మాత్రమే ప్రమాణీకరించండి:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

లాగిన్ కమాండ్ రిమోట్/కంటైనర్ పరిసరాల కోసం ఉద్దేశించిన అధికారిక మాన్యువల్-టోకెన్ విధానాన్ని ఉపయోగిస్తుంది. విలువ నేరుగా CLI ప్రాంప్ట్లో నమోదు చేయబడుతుంది; అది ప్రాసెస్ ఆర్గ్యుమెంట్గా పంపబడదు, Gitలో వ్రాయబడదు లేదా హోస్ట్ నుండి కాపీ చేయబడదు.

వేరుచేసిన Claude Code రన్టైమ్ను ప్రారంభించండి:

```bash
./scripts/devin-bridge/launch
```

కంటైనరైజ్ చేసిన Claude Codeను ప్రారంభించే ముందు `launch`, వేరుచేయడం, Devin ప్రమాణీకరణ మరియు మోడల్ డిస్కవరీని మళ్లీ తనిఖీ చేస్తుంది. ఇది హోస్ట్లోని Claude ఎగ్జిక్యూటబుల్ను ఎన్నడూ అమలు చేయదు. మోడల్ అలియాస్లను `.env.devin-bridge`లో సెట్ చేయవచ్చు; కాన్ఫిగర్ చేసిన ప్రతి విలువ తప్పనిసరిగా `devin-cli-agentic/` ప్రిఫిక్స్ను కలిగి ఉండాలి.

## ధ్రువీకరణ కమాండ్లు

పునరుత్పాదక ఆఫ్లైన్ మార్గానికి Devin ఖాతా అవసరం లేదు మరియు రన్టైమ్లో ఇంటర్నెట్ ఉండదు:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

ప్రమాణీకరించిన, ఎంపిక చేసుకుని అమలు చేసే లైవ్ మార్గం:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

ACP సెషన్లను ఒకేసారి పెద్ద సంఖ్యలో తెరవకుండా ఉండేందుకు లైవ్ రన్నర్ దృశ్యాల మధ్య వేచి ఉంటుంది మరియు వచనపరమైన క్లెయిమ్లను విశ్వసించడానికి బదులుగా నిర్మిత Claude స్ట్రీమ్ ఈవెంట్లను ధ్రువీకరిస్తుంది. దాని మూడు దృశ్యాలు వీటిని నిరూపిస్తాయి:

1. నేరుగా ప్రాజెక్ట్ రీడ్లు మరియు లోప విశ్లేషణ;
2. నిజమైన `Edit`, క్లయింట్ అధీనంలోని `Bash` `npm test` మరియు టెర్మినల్ ఫలితం;
3. `/bridge-check`తో పాటు `bridge-proof` డిస్కవరీ, ప్రాజెక్ట్ రీడ్లు, విజయవంతమైన మరొక క్లయింట్ అధీనంలోని `npm test` మరియు పెండింగ్ పని లేకుండా పూర్తి కావడం.

చివరి గేట్ Devin నెట్వర్క్ ఆడిట్ను కూడా తనిఖీ చేస్తుంది మరియు Claude ఎగ్రెస్ ఆడిట్ ఖాళీగా ఉండాలని నిర్దేశిస్తుంది.

## పిన్ చేసిన టూల్లను అప్డేట్ చేయడం

ఇమేజ్లో Node, Claude Code మరియు Devin CLIలను `docker/devin-bridge/Dockerfile`లో పిన్ చేస్తారు. అప్డేట్ చేయడానికి:

1. స్పష్టంగా పేర్కొన్న వెర్షన్లను మార్చండి;
2. రెండు ఆర్కిటెక్చర్-నిర్దిష్ట Devin ఆర్కైవ్ చెక్సమ్లను అధికారిక ఆర్టిఫాక్ట్కు సంబంధించిన విలువలతో భర్తీ చేయండి;
3. మళ్లీ బిల్డ్ చేసి, ప్రతి ఆఫ్లైన్ ధ్రువీకరణ కమాండ్ను అమలు చేయండి;
4. ఇమేజ్లోని వెర్షన్లను నిర్ధారించండి;
5. ప్రమాణీకరించిన మూడు-దృశ్యాల లైవ్ సూట్ను మళ్లీ అమలు చేయండి.

ఏ CLIని కూడా హోస్ట్లో గ్లోబల్గా ఇన్స్టాల్ చేయవద్దు లేదా చెక్సమ్ ధ్రువీకరణను ధ్రువీకరించని డౌన్లోడ్తో భర్తీ చేయవద్దు.

## నిర్ధారణ మరియు క్లీన్అప్

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  స్థానిక రూటింగ్ మరియు శుద్ధీకరించిన ఎగ్జిక్యూటర్ ఎర్రర్లను చూపుతుంది.
- `.sandbox/evidence/mock-acp.jsonl` నిర్ధారిత మాక్ ACP చర్యలను రికార్డ్ చేస్తుంది.
- `.sandbox/evidence/claude-stream.jsonl` నిజమైన Claude Code ఆఫ్లైన్ రన్ను రికార్డ్ చేస్తుంది.
- `.sandbox/evidence/live-*.jsonl` ధ్రువీకరించిన మూడు లైవ్ స్ట్రీమ్లను రికార్డ్ చేస్తుంది.
- `.sandbox/evidence/egress.jsonl` మరియు `.sandbox/evidence/claude-egress.jsonl` అనేవి గార్డ్ ఆడిట్ల యొక్క ధ్రువీకరించిన, టోకెన్-రహిత కాపీలు.

లాగిన్/కాన్ఫిగ్ వాల్యూమ్లను భద్రపరుస్తూ, అధీనంలోని కంటైనర్లు మరియు నెట్వర్క్లను నిలిపివేయండి:

```bash
./scripts/devin-bridge/clean
```

పేరు పెట్టిన వాల్యూమ్లతో సహా, పూర్తిగా బ్రిడ్జ్ అధీనంలోని పరిసరాన్ని తొలగించండి:

```bash
./scripts/devin-bridge/clean --all
```

## పరిమితులు

- Devin CLI `3000.2.17` తటస్థమైన, సాధనాలు లేని ACP ఏజెంట్ను అందుబాటులో ఉంచనందున, బ్రిడ్జ్ స్థిరమైన సాధనాలు లేని `summarizer` పాత్రపై ఆధారపడుతుంది. సారాంశం-ఆకారంలో ఉండే మధ్యంతర ప్రతిస్పందనలను అడాప్టర్ సరిచేస్తుంది, అయినప్పటికీ పరిమితమైన ఒక మరమ్మతు ప్రయత్నం స్పష్టంగా విఫలం కావచ్చు.
- ప్రత్యక్ష ACP కాల్లు తాత్కాలిక `502`/`504` ప్రతిస్పందనలను తిరిగి ఇవ్వవచ్చు. హార్నెస్ సన్నివేశాల మధ్య విరామం ఉంచుతుంది; నిరంతర వైఫల్యం ఫెయిల్-క్లోజ్డ్గానే ఉంటుంది మరియు మరొక ప్రొవైడర్ను ఎన్నుకోదు.
- ప్రతి Anthropic అభ్యర్థన నుండి ACP సందర్భం పునర్నిర్మించబడుతుంది; ప్రాసెస్/సెషన్ అనుబంధం ఉండదు.
- ప్రతి మోడల్ ప్రతిస్పందనకు ఒక సాధన కాల్కు మద్దతు ఉంది; సమాంతర కాల్లు తిరస్కరించబడతాయి.
- చిత్రాలకు స్పష్టంగా మద్దతు లేదు. విజన్, థింకింగ్ అవుట్పుట్, ఎఫర్ట్ నియంత్రణలు మరియు 1M సందర్భ విండో ప్రకటించబడవు.
- SSE చెల్లుబాటు అయ్యే Anthropic లైఫ్సైకిల్ ఈవెంట్లను ఉపయోగిస్తుంది, కానీ పరిమిత ACP టర్న్ సేకరించబడిన తర్వాతే విడుదల చేయబడుతుంది; ACP భాగాలు క్రమానుగతంగా ఫార్వర్డ్ చేయబడవు.
