ఈ మార్గదర్శిని OmniRouteకు Kiro (AWS ద్వారా హోస్ట్ చేయబడిన AI కోడింగ్ సహాయకం) ఖాతాలను జోడించడం గురించి వివరిస్తుంది,
ప్రత్యేకించి సెషన్ వైరుధ్యాలు లేకుండా ఒకేసారి అనేక ఖాతాలను అమలు చేయడంపై దృష్టి పెడుతుంది.

---

## నేపథ్యం: Kiro ఖాతాల మధ్య వైరుధ్యం ఎందుకు ఏర్పడవచ్చు

సక్రియ సెషన్లను ట్రాక్ చేయడానికి Kiro బ్యాకెండ్ AWS SSO OIDC క్లయింట్ నమోదులను ఉపయోగిస్తుంది.
ముఖ్యమైన పరిమితి: **ప్రతి OIDC క్లయింట్ నమోదు ఒక సమయంలో ఒక సక్రియ
సెషన్కు మాత్రమే మద్దతు ఇస్తుంది**. అదే నమోదిత క్లయింట్ను ఉపయోగించి రెండవ పరికరం లేదా వినియోగదారు
ప్రమాణీకరించినప్పుడు, బ్యాకెండ్ మొదటి ఖాతా యొక్క రిఫ్రెష్ టోకెన్ను చెల్లనిదిగా చేస్తుంది.

మరొక Kiro ఖాతా ఇప్పటికే సైన్ ఇన్ చేసి ఉన్న మెషీన్లో `kiro-cli login`
అమలు చేసినప్పుడు సమస్యలు కలిగించేది కూడా ఇదే విధానం — కొత్త లాగిన్
మొదటి ఖాతా టోకెన్ను రద్దు చేస్తుంది.

## OmniRoute దీనిని ఎలా పరిష్కరిస్తుంది (v3.8.0+)

v3.8.0 నుండి, ప్రతి Kiro కనెక్షన్ దిగుమతి సమయంలో OmniRoute
`registerClient()` (AWS SSO OIDC)ను కాల్ చేస్తుంది. దీనివల్ల ప్రతి OmniRoute కనెక్షన్కు దానికే
ప్రత్యేకమైన OIDC క్లయింట్ నమోదు లభిస్తుంది. ప్రతి క్లయింట్ నమోదు స్వతంత్రంగా ఉండటం వల్ల, ఒక ఖాతాను
రిఫ్రెష్ చేయడం లేదా మళ్లీ ప్రమాణీకరించడం మరే ఇతర ఖాతా రిఫ్రెష్ టోకెన్పై ప్రభావం చూపదు.

ఈ వేర్పాటు రిఫ్రెష్-టోకెన్ దిగుమతి పద్ధతులకు వర్తిస్తుంది, అలాగే API-కీ ప్రమాణీకరణ
OIDC రిఫ్రెష్ సెషన్లను పూర్తిగా నివారిస్తుంది:

| దిగుమతి పద్ధతి                                                           | వేర్పాటు స్థితి                                                                                                  |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| AWS Builder ID / IDC పరికర-కోడ్ ప్రవాహం                                  | పరికర-కోడ్ ప్రవాహం ప్రవేశపెట్టినప్పటి నుండి వేరుచేయబడింది                                                        |
| **టోకెన్ను దిగుమతి చేయండి** (రిఫ్రెష్ టోకెన్ను మాన్యువల్గా పేస్ట్ చేయడం) | v3.8.0 నుండి వేరుచేయబడింది                                                                                       |
| **Google / GitHub సామాజిక లాగిన్**                                       | v3.8.0 నుండి వేరుచేయబడింది                                                                                       |
| **స్వయంచాలక దిగుమతి** (kiro-cli SQLite)                                  | v3.8.0 నుండి వేరుచేయబడింది (SQLite పాత్ ఇప్పటికే వేరుచేయబడింది; SSO-cache ఫాల్బ్యాక్ ఇప్పుడు కూడా వేరుచేయబడింది) |
| **API కీ** (దీర్ఘకాలిక CodeWhisperer కీ)                                 | రిఫ్రెష్ సెషన్ ఉండదు; కీ ధ్రువీకరించబడి బేరర్ క్రెడెన్షియల్గా నిల్వ చేయబడుతుంది                                  |

## v3.8.0కు ముందు సృష్టించిన కనెక్షన్ల కోసం మైగ్రేషన్ గమనిక

v3.8.0కు ముందు దిగుమతి చేసిన కనెక్షన్లకు `providerSpecificData`లో ప్రత్యేక OIDC క్లయింట్ నమోదు
నిల్వ చేయబడి ఉండదు. ఈ కనెక్షన్లు పని చేస్తూనే ఉంటాయి, కానీ పంచుకున్న
సామాజిక-ప్రమాణీకరణ రిఫ్రెష్ ఎండ్పాయింట్ను ఉపయోగిస్తాయి; అంటే అలాంటి రెండు కనెక్షన్లు ఇప్పటికీ ఒకదానిని మరొకటి
చెల్లనిదిగా చేయగలవు.

**వేర్పాటును పొందడానికి:** **డ్యాష్బోర్డ్ → ప్రొవైడర్లు** నుండి పాత కనెక్షన్ను తొలగించి,
మద్దతు ఉన్న ఏదైనా దిగుమతి ప్రవాహాన్ని ఉపయోగించి దానిని మళ్లీ దిగుమతి చేయండి. కొత్తగా సృష్టించిన అన్ని కనెక్షన్లు
స్వయంచాలకంగా వాటికంటూ ప్రత్యేకమైన క్లయింట్ నమోదును పొందుతాయి.

## రెండు Kiro ఖాతాలను పక్కపక్కనే జోడించడం

### ముందస్తు అవసరాలు

- OmniRoute v3.8.0 లేదా తర్వాతి వెర్షన్.
- పనిచేసే Kiro ఖాతా (ఇమెయిల్ + పాస్వర్డ్, Google లేదా GitHub లాగిన్).
- ఐచ్ఛికంగా రెండవ Kiro ఖాతా.

### దశ 1: మొదటి ఖాతాను దిగుమతి చేయండి

1. **డ్యాష్బోర్డ్ → ప్రొవైడర్లు → ప్రొవైడర్ను జోడించండి → Kiro** తెరవండి.
2. కింది వాటిలో ఒకదాన్ని ఎంచుకోండి:
   - **టోకెన్ను దిగుమతి చేయండి** — `aorAAAAAG`తో ప్రారంభమయ్యే రిఫ్రెష్ టోకెన్ను పేస్ట్ చేయండి.
   - **API కీ** — దీర్ఘకాలిక Kiro / CodeWhisperer API కీని పేస్ట్ చేయండి.
   - **Google / GitHub లాగిన్** — బ్రౌజర్లో OAuth ప్రవాహాన్ని పూర్తి చేయండి.
   - **స్వయంచాలక దిగుమతి** — బటన్ను క్లిక్ చేయండి; OmniRoute స్థానిక
     kiro-cli డేటాబేస్ లేదా `~/.aws/sso/cache` నుండి క్రెడెన్షియల్లను చదువుతుంది.
3. కనెక్షన్ సేవ్ చేయబడుతుంది. రిఫ్రెష్-టోకెన్ ప్రవాహాలు స్వయంచాలకంగా ప్రత్యేకమైన
   OIDC క్లయింట్ను నమోదు చేస్తాయి. API-కీ ప్రవాహాలు AWSతో కీని ధ్రువీకరిస్తాయి మరియు రిఫ్రెష్ టోకెన్ను నిల్వ చేయవు.

### దశ 2: రెండవ ఖాతాను దిగుమతి చేయండి

రెండవ ఖాతా కోసం దశ 1ను పునరావృతం చేయండి. ప్రతి దిగుమతి ప్రత్యేక OIDC
క్లయింట్ నమోదును సృష్టిస్తుంది కాబట్టి, రెండు కనెక్షన్లు పూర్తిగా వేరుచేయబడతాయి.

### దశ 3: రెండు కనెక్షన్లు సక్రియంగా ఉన్నాయని ధ్రువీకరించండి

1. **డ్యాష్బోర్డ్ → ప్రొవైడర్లు** — రెండు Kiro కనెక్షన్లు **సక్రియం** స్థితిని చూపాలి.
2. **డ్యాష్బోర్డ్ → ఆరోగ్యం** — రెండు కనెక్షన్లు వాటి టోకెన్ ఆరోగ్య తనిఖీలో ఉత్తీర్ణం కావాలి.

### దశ 4: ఖాతాల మధ్య రూట్ చేయడానికి కాంబోను ఉపయోగించండి

లోడ్ను సమతుల్యం చేయడానికి లేదా ఒకటి విఫలమైతే మరొకదానికి మారడానికి రెండు కనెక్షన్లను లక్ష్యాలుగా ఉంచి ఒక కాంబోను సృష్టించండి:

```
kiro/kiro-dev → kiro/kiro-pro
```

కాంబో కాన్ఫిగరేషన్ కోసం [FEATURES.md](./FEATURES.md) మరియు రూటింగ్ డాక్యుమెంటేషన్ను చూడండి.

## ఎంటర్ప్రైజ్ / IDC వినియోగదారులు

AWS IAM Identity Center (IDC) ఖాతాల కోసం, **డాష్బోర్డ్ → ప్రొవైడర్లు → Kiro → డివైస్ కోడ్** లోని **AWS Builder ID / IDC డివైస్-కోడ్**
ప్రవాహాన్ని ఉపయోగించండి. డివైస్-కోడ్ ప్రవాహం ఎల్లప్పుడూ పూర్తిగా వేరుగా ఉంచబడింది. ఈ కనెక్షన్లను మళ్లీ దిగుమతి చేయాల్సిన అవసరం లేదు.

డిఫాల్ట్ కాని AWS రీజియన్లో పనిచేసే ఎంటర్ప్రైజ్ వినియోగదారులు, Import Token API ద్వారా
దిగుమతి చేసేటప్పుడు రీజియన్ను పేర్కొనవచ్చు:

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/import \
  -H "Content-Type: application/json" \
  -d '{"refreshToken": "aorAAAAAG...", "region": "eu-west-1"}'
```

`region` ఫీల్డ్ను పేర్కొనకపోతే దాని డిఫాల్ట్ విలువ `us-east-1`.

## API-కీ దిగుమతి ప్రవాహం

API-కీ ప్రమాణీకరణ దీర్ఘకాలం చెల్లుబాటయ్యే Kiro / AWS CodeWhisperer బేరర్ క్రెడెన్షియల్ల కోసం ఉద్దేశించబడింది. ఇది
OAuth రిఫ్రెష్ను ఉపయోగించదు, కాబట్టి షేర్ చేయబడిన OIDC సెషన్ చెల్లుబాటు రద్దు కావడాన్ని నివారిస్తుంది.

### డాష్బోర్డ్

1. **డాష్బోర్డ్ -> ప్రొవైడర్లు -> Kiro** తెరవండి.
2. **API కీ**ని ఎంచుకోండి.
3. API కీని మరియు ఐచ్ఛిక AWS రీజియన్ను (డిఫాల్ట్గా `us-east-1`) అతికించండి.
4. OmniRoute కీని ధృవీకరించి, కనెక్షన్ను సేవ్ చేస్తుంది.

### API

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/api-key \
  -H "Content-Type: application/json" \
  -d '{"apiKey": "kiro_or_codewhisperer_key", "region": "us-east-1"}'
```

### అంతర్గత ఒప్పందం

API రూట్ `KiroService.validateApiKey()`ను కాల్ చేయడం ద్వారా కీని ధృవీకరిస్తుంది; ఇది
రీజియన్కు సరిపోలే CodeWhisperer/Amazon Q ఎండ్పాయింట్పై `ListAvailableProfiles`ను
ఉపయోగించి, ఒక `profileArn`ను పరిష్కరిస్తుంది.

సేవ్ చేసిన కనెక్షన్ దీనిని ఉపయోగిస్తుంది:

```json
{
  "authType": "apikey",
  "providerSpecificData": {
    "authMethod": "api_key",
    "region": "us-east-1",
    "profileArn": "arn:aws:codewhisperer:..."
  }
}
```

రన్టైమ్లో, `KiroExecutor.buildHeaders()` కీని
`Authorization: Bearer <key>` రూపంలో పంపి, `tokentype: API_KEY`ను జోడిస్తుంది. కోటా/ప్రొఫైల్ కాల్లు
కూడా ఇదే మార్కర్ను ఉపయోగిస్తాయి, తద్వారా AWS ఆ బేరర్ను OIDC లేదా సోషల్ యాక్సెస్ టోకెన్గా కాకుండా
దీర్ఘకాలం చెల్లుబాటయ్యే API కీగా పరిగణిస్తుంది.

## OIDC క్లయింట్ గడువు ముగింపు

AWS SSO OIDC పబ్లిక్ క్లయింట్ల గడువు సాధారణంగా 90 రోజుల తర్వాత ముగుస్తుంది
(`clientSecretExpiresAt`). పరిశీలన సౌలభ్యం కోసం OmniRoute ఈ టైమ్స్టాంప్ను `providerSpecificData`లో
నిల్వ చేస్తుంది. ఒక కనెక్షన్ సుమారు 90 రోజుల తర్వాత రిఫ్రెష్ అవడం ఆగిపోతే, కొత్త OIDC క్లయింట్ రిజిస్ట్రేషన్ను
పొందడానికి కనెక్షన్ను మళ్లీ దిగుమతి చేయండి. గడువు ముగిసినప్పుడు ఆటోమేటిక్గా మళ్లీ రిజిస్టర్ చేయడం
భవిష్యత్ మెరుగుదలగా ట్రాక్ చేయబడుతోంది.

API-కీ కనెక్షన్లు AWS SSO OIDC ద్వారా రిఫ్రెష్ కావు కాబట్టి, వాటికి OIDC క్లయింట్ గడువు ముగింపు ఉండదు.

## సమస్య పరిష్కారం

### రెండవ ఖాతా పదేపదే లాగ్ అవుట్ అవుతోంది

- **డాష్బోర్డ్ → ప్రొవైడర్లు**లో రెండు కనెక్షన్లను తనిఖీ చేసి, ప్రతి దాని రా JSONలో (సమాచార చిహ్నం ద్వారా కనిపిస్తుంది)
  శూన్యం కాని `clientId` ఉందని నిర్ధారించండి. ఏదైనా కనెక్షన్లో `clientId` లేకపోతే,
  అది v3.8.0కు ముందు దిగుమతి చేయబడింది — దాన్ని మళ్లీ దిగుమతి చేయండి.

### "Token validation failed"తో దిగుమతి విఫలమవుతోంది

- రిఫ్రెష్ టోకెన్ `aorAAAAAG`తో ప్రారంభమవుతుందని నిర్ధారించండి.
- OmniRoute `https://oidc.us-east-1.amazonaws.com`ను (లేదా కాన్ఫిగర్ చేసిన
  రీజియన్ను) చేరుకోగలదని నిర్ధారించండి. మీరు కార్పొరేట్ ప్రాక్సీ వెనుక ఉంటే,
  **డాష్బోర్డ్ → సెట్టింగ్లు → ప్రాక్సీలు**లో ప్రొవైడర్-స్థాయి ప్రాక్సీని సెట్ చేయండి.

### API-కీ దిగుమతి విఫలమవుతోంది

- కీ ఒక Kiro / CodeWhisperer API కీ అని, రిఫ్రెష్ టోకెన్ కాదని నిర్ధారించండి.
- AWS రీజియన్ కీ/ఖాతాతో సరిపోలుతుందని నిర్ధారించండి. డిఫాల్ట్ `us-east-1`.
- కీ తప్పనిసరిగా `ListAvailableProfiles`ను కాల్ చేయగలగాలి; లేకపోతే OmniRoute అవసరమైన
  `profileArn`ను పరిష్కరించలేదు.

ఇతర సమస్యల కోసం, ప్రధాన [TROUBLESHOOTING.md](./TROUBLESHOOTING.md)ను చూడండి.
