OmniRoute, OpenAI Codexను ఉపయోగించడానికి **రెండు** మార్గాలను అందిస్తుంది:

| ప్రొవైడర్              | ఇది OpenAIతో ఎలా కమ్యూనికేట్ చేస్తుంది                                                                                                                                                               | వినియోగానికి సంబంధించిన హెచ్చరిక                                      |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| **`codex`**            | మీ ChatGPT/OpenAI OAuth టోకెన్ను నేరుగా Responses APIకి రీప్లే చేస్తుంది                                                                                                                             | **అవును** — అధికారిక సెషన్కు ప్రాక్సీ/రౌటర్ వినియోగం కోసం అనుమతి లేదు |
| **`codex-app-server`** | JSON-RPC/WebSocket ద్వారా **Codex CLIకి చెందిన స్వంత `codex app-server`**ను నడిపిస్తుంది; ఇంటరాక్టివ్ `codex` సెషన్లాగే CLI తన OAuth (`~/.codex/auth.json`)ను స్వయంగా నిర్వహించి, రీఫ్రెష్ చేస్తుంది | **లేదు** — OmniRoute ఎప్పుడూ APIకి టోకెన్ను రీప్లే చేయదు              |

`codex-app-server` ఎప్పుడూ టోకెన్ను రీప్లే చేయదు కాబట్టి, దీనికి
సెషన్-రీప్లే వినియోగ హెచ్చరిక వర్తించదు. అయితే, కాన్ఫిగర్ చేసిన
app-server URL వద్ద **అందుబాటులో ఉండే Codex CLI** అవసరం, అలాగే ఆ CLIలో
**సైన్ ఇన్ చేసి ఉండాలి**.

## 1. ఆర్కిటెక్చర్

```
┌─ OmniRoute యాప్ ────────────────┐        ┌─ codex-app-server సైడ్కార్ ─────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ సామర్థ్య టోకెన్)              │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  OpenAI OAuthను స్వయంగా నిర్వహిస్తుంది │
└──────────────────────────────────┘        │  (~/.codex/auth.json, ఆటో-రీఫ్రెష్) │
        │ భాగస్వామ్యం చేస్తుంది (compose వాల్యూమ్లు) └──────────────────────────────┘
        ▼
  codex-appserver-token   → WS సామర్థ్య టోకెన్ (రెండూ దీన్ని మౌంట్ చేస్తాయి)
  codex-appserver-home    → ~/.codex (డ్యాష్బోర్డ్ ద్వారా auth.json వ్రాయబడుతుంది,
                             సైడ్కార్లోని codex app-server ద్వారా చదవబడుతుంది)
```

- సైడ్కార్ సామర్థ్య టోకెన్ వెనుక ఉన్న అంతర్గత compose నెట్వర్క్
  (`ws://codex-app-server:1456`)లో **మాత్రమే** లిసన్ చేస్తుంది. ఇది హోస్ట్కు లేదా
  ఇంటర్నెట్కు **ఎప్పుడూ** పబ్లిష్ చేయబడదు.
- Codex CLI అనేది `omniroute:base`లోనే బేక్ చేయబడింది, కాబట్టి సైడ్కార్ను
  అమలు చేసేటప్పుడు హోస్ట్లో లేదా వినియోగదారు మెషీన్లో codexను ఇన్స్టాల్ చేయాల్సిన
  అవసరం లేదు.

## 2. దీన్ని ప్రారంభించడం

```bash
# codex app-server సైడ్కార్ ప్రొఫైల్తో స్టాక్ను ప్రారంభించండి:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

సైడ్కార్ మొదటిసారి బూట్ అయినప్పుడు తన WS సామర్థ్య టోకెన్ను సృష్టిస్తుంది
(భాగస్వామ్య `codex-appserver-token` వాల్యూమ్లోకి), అలాగే యాప్
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE` ద్వారా అదే టోకెన్ను చదువుతుంది.
టోకెన్ను మాన్యువల్గా అనుసంధానించాల్సిన అవసరం లేదు.

## 3. కనెక్ట్ చేయడం + సైన్ ఇన్ చేయడం

1. డ్యాష్బోర్డ్లో **OpenAI Codex (App-Server)** కోసం ఒక కనెక్షన్ను జోడించండి.
   API కీ లేదా టోకెన్ అవసరం లేదు (ఇది no-auth ప్రొవైడర్ — ఆథెంటికేషన్ను
   సైడ్కార్ నిర్వహిస్తుంది).
2. సైడ్కార్లోని Codex CLIలో **ఇంకా సైన్ ఇన్ చేయకపోతే**, కనెక్షన్ హెల్త్
   చెక్ _"నడుస్తోంది, కానీ సైన్ ఇన్ చేయలేదు"_ అని నివేదిస్తుంది (ఎరుపు రంగు
   ఆథెంటికేషన్ లోపంగా కాదు). **Sign in with ChatGPT**ని ఉపయోగించండి: ఇది మీ
   బ్రౌజర్లో ప్రామాణిక Codex device-OAuthను అమలు చేసి, ఆపై **Apply auth** ద్వారా
   భాగస్వామ్య వాల్యూమ్లోకి `~/.codex/auth.json`ను వ్రాస్తుంది (ఒకే లాగిన్
   `codex` మరియు `codex-app-server` ప్రొవైడర్లు రెండింటికీ ఉపయోగపడుతుంది).
3. సైన్ ఇన్ చేసిన తర్వాత, హెల్త్ చెక్ ఆకుపచ్చగా మారి (`/readyz` **మరియు**
   `account/read` రెండింటినీ ఇది ధృవీకరిస్తుంది — అంటే సర్వర్ అందుబాటులో ఉండటంతో
   పాటు ఆథెంటికేట్ కూడా అయి ఉంటుంది) పని చేయడం ప్రారంభిస్తుంది.

డ్యాష్బోర్డ్ ఇప్పటికే ఆరోగ్యకరంగా ఉన్న `~/.codex/auth.json`ను ఎప్పుడూ
ఓవర్రైట్ చేయదు — ఫైల్ లేనప్పుడు లేదా దాని టోకెన్ పాతబడినప్పుడు మాత్రమే
వ్రాస్తుంది (ఎల్లప్పుడూ బ్యాకప్ తీసుకోబడుతుంది).

## 4. డిప్లాయ్మెంట్ సందర్భాలు

- **ఇప్పటికే ఆథెంటికేట్ చేసిన Codex CLI కలిగిన ఆపరేటర్** — మీ హోస్ట్లోని
  `~/.codex`ను సైడ్కార్లోకి (`codex-appserver-home`) మౌంట్ చేసి, సైన్-ఇన్
  దశను దాటవేయండి.
- **పబ్లిక్ వినియోగదారు, స్థానికంగా codex ఇన్స్టాల్ చేయలేదు** — ఇది సంబంధం
  లేని విషయం: సైడ్కార్లో CLI ఉంది. వినియోగదారు డ్యాష్బోర్డ్ ద్వారా మాత్రమే
  ఆథెంటికేట్ చేస్తారు.
- **బేర్-మెటల్ OmniRoute (సైడ్కార్ లేదు, హోస్ట్ codex)** — మీ స్వంత
  `codex app-server` వైపు `OMNIROUTE_CODEX_APPSERVER_WS`ను సూచించేలా చేసి,
  హోస్ట్ codexలో సైన్ ఇన్ చేసి ఉందని నిర్ధారించుకోండి; బైనరీ లేకపోతే
  "codex ఇన్స్టాల్ చేయబడలేదు" అనే సూచన కనిపిస్తుంది.

## 5. రెసిడెన్షియల్ / UDP ఎగ్రెస్ (ఆపరేటర్ అదనపు ఏర్పాటు, దీనితో అందించబడదు)

పైన ఉన్న సాధారణ సైడ్కార్, కంటైనర్ సాధారణ నెట్వర్క్ ద్వారా ఎగ్రెస్ అవుతుంది.
Codex ట్రాఫిక్ను **రెసిడెన్షియల్ ఎగ్జిట్** ద్వారా ఎగ్రెస్ చేయాల్సిన ఆపరేటర్
(ఉదా. TCP + UDP/QUICను మోసుకెళ్లే TUN tailscale సైడ్కార్) దాన్ని ప్రత్యేక
compose ఓవర్రైడ్గా అమలు చేస్తారు; ఉద్దేశపూర్వకంగానే అది అందించబడే
`codex-app-server` ప్రొఫైల్లో భాగం కాదు. ఆ సెటప్ కోసం అంతర్గత ఆపరేషన్స్
రన్బుక్ను చూడండి.
