OmniRoute ప్రతి అభ్యర్థన ఖర్చును ఎలా అంచనా వేస్తుంది, నమోదు చేస్తుంది మరియు నివేదిస్తుంది — అలాగే
డ్యాష్బోర్డ్లోని సంఖ్య బిల్లు కాకుండా **పొదుపుల ట్రాకర్** ఎందుకు అవుతుంది.

ఇవి కూడా చూడండి: [వినియోగదారు మార్గదర్శిని](./USER_GUIDE.md) · [ఫీచర్ల గ్యాలరీ](./FEATURES.md)

## ఇది ఏమిటి (మరియు ఏమి కాదు)

OmniRoute టోకెన్ సంఖ్యలను మోడల్ ధరల రేట్లతో గుణించడం ద్వారా ప్రతి కంప్లీషన్కు
ఒక్కో అభ్యర్థన USD ఖర్చును కేటాయిస్తుంది. ఈ సంఖ్యలు **ఖర్చులు** డ్యాష్బోర్డ్,
`omniroute cost` / `omniroute usage` CLI, CSV/JSON ఎగుమతులు మరియు ఒక్కో API కీ బడ్జెట్లకు
ఆధారంగా ఉంటాయి.

> **డ్యాష్బోర్డ్లోని "ఖర్చు" ఒక పొదుపుల ట్రాకర్, బిల్లు కాదు.** OmniRoute మీ నుండి ఎప్పుడూ
> రుసుము వసూలు చేయదు — మీరు ఇప్పటికే అనుసంధానించిన ప్రొవైడర్లకు (మీ స్వంత
> సబ్స్క్రిప్షన్లు, ఉచిత టైర్లు మరియు API కీలు) మీ అభ్యర్థనలను రూట్ చేస్తుంది. పూర్తిగా ఉచిత
> మోడల్లపై నమోదైన "$290 మొత్తం ఖర్చు" అంటే, చెల్లింపు APIకి మీరు సుమారుగా
> **$290 చెల్లించలేదని** అర్థం. అదే ట్రాఫిక్కు ప్రామాణిక జాబితా ధరల ప్రకారం ఎంత ఖర్చయ్యేదో
> ఈ సంఖ్య ఒక _అంచనా_; తద్వారా మీ వినియోగం ఎక్కడ కేంద్రీకృతమైందో, తక్కువ ధర/ఉచిత
> ప్రొవైడర్లకు రూటింగ్ చేయడం వల్ల మీరు ఎంత ఆదా చేస్తున్నారో చూడవచ్చు.

ఈ వివరణ ప్రాజెక్ట్ [README](../../README.md)లో నేరుగా పేర్కొనబడింది ("డ్యాష్బోర్డ్లోని
'ఖర్చు' ఒక పొదుపుల ట్రాకర్, బిల్లు కాదు").

ఈ సంఖ్య ఒక అంచనా కాబట్టి:

- ప్రతి మోడల్కు OmniRoute వద్ద ఉన్న ధరల పట్టికపై ఇది ఆధారపడి ఉంటుంది. ధర నమోదు లేని
  మోడల్ `0` ఖర్చును జోడిస్తుంది (ఎక్స్ప్లోరర్లో అది "లెగసీ / ఉచితం" వరుసగా కనిపిస్తుంది).
- ఉచిత-టైర్ మరియు సబ్స్క్రిప్షన్ ట్రాఫిక్కు కూడా _అంచనా_ ఖర్చు నమోదవుతుంది — అది
  మీరు ఆదా చేస్తున్న మొత్తం, చెల్లించాల్సిన మొత్తం కాదు.

## ఖర్చులు ఎలా అంచనా వేయబడతాయి

### ధరల మూలం

ఈ ప్రాధాన్యత క్రమంలో నిర్ణయించబడే ధరల పట్టిక నుండి ఖర్చులు వస్తాయి
([`src/lib/pricingSync.ts`](../../src/lib/pricingSync.ts)):

1. **వినియోగదారు ఓవర్రైడ్లు** — డ్యాష్బోర్డ్లో / `PATCH /api/pricing` ద్వారా మీరు సెట్ చేసిన ధరలు.
2. **సింక్ చేసిన బాహ్య ధరలు** — సింక్ ప్రారంభించబడినప్పుడు LiteLLM పబ్లిక్
   `model_prices_and_context_window.json` నుండి పొందబడతాయి (మీ ఓవర్రైడ్లను ఎప్పటికీ
   భర్తీ చేయకుండా ఉండేందుకు ప్రత్యేక `pricing_synced` నేమ్స్పేస్లో నిల్వ చేయబడతాయి).
3. **హార్డ్కోడ్ చేసిన డిఫాల్ట్లు** — OmniRouteతో పాటు అందించబడతాయి.

బాహ్య ధరల సింక్ **ఐచ్ఛికం**, డిఫాల్ట్గా నిలిపివేయబడి ఉంటుంది. సంబంధిత env vars
([`.env.example`](../../.env.example) చూడండి):

| Env var                 | డిఫాల్ట్  | ప్రయోజనం                                                                     |
| ----------------------- | --------- | ---------------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`   | స్టార్టప్ సమయంలో బ్యాక్గ్రౌండ్ LiteLLM ధరల సింక్ను ప్రారంభిస్తుంది.          |
| `PRICING_SYNC_INTERVAL` | `86400`   | **సెకన్లలో** సింక్ వ్యవధి (డిఫాల్ట్గా రోజుకు ఒకసారి).                        |
| `PRICING_SYNC_SOURCES`  | `litellm` | కామాలతో వేరు చేసిన మూలాల జాబితా (ప్రస్తుతం `litellm`కు మాత్రమే మద్దతు ఉంది). |

### ఖర్చు సూత్రం

[`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts)లోని
(`computeCostFromPricing` / `calculateCost`) టోకెన్ సంఖ్యలు మరియు ప్రతి మిలియన్ టోకెన్కు
వర్తించే రేట్ల ఆధారంగా ప్రతి అభ్యర్థన ఖర్చు లెక్కించబడుతుంది:

- **ఇన్పుట్ టోకెన్లు** (క్యాష్ రీడ్లు మరియు క్యాష్-క్రియేషన్ టోకెన్లను తీసివేసి) × `input` రేటు.
- **క్యాష్-రీడ్ టోకెన్లు** × `cached` రేటు (అది లేకపోతే ఇన్పుట్ రేటును ఉపయోగిస్తుంది).
- **క్యాష్-క్రియేషన్ టోకెన్లు** × `cache_creation` రేటు (అది లేకపోతే ఇన్పుట్ రేటును ఉపయోగిస్తుంది).
- **అవుట్పుట్ టోకెన్లు** × `output` రేటు.
- **రీజనింగ్ టోకెన్లు** × `reasoning` రేటు (అది లేకపోతే అవుట్పుట్ రేటును ఉపయోగిస్తుంది).

అన్ని రేట్లు 1,000,000 టోకెన్లకు USDగా పరిగణించబడతాయి. Codex "fast"/"priority" లేదా
"flex" సర్వీస్ టైర్ ఖర్చు గుణకాన్ని (`getCodexFastCostMultiplier`) వర్తింపజేస్తుంది — ఉదాహరణకు,
flexకు టోకెన్ ధరపై 50% తగ్గింపు వర్తిస్తుంది; ఇది డ్యాష్బోర్డ్లో **flex పొదుపులు**గా చూపబడుతుంది.

చారిత్రక వరుసలు కూడా ధరతో సరిపోలేలా మోడల్ పేర్లు ముందుగా సాధారణీకరించబడతాయి
(`openai/` లేదా `accounts/fireworks/models/` వంటి ప్రొవైడర్-పాత్ ప్రిఫిక్స్లు
తొలగించబడతాయి).

### ఖర్చు ఎలా నమోదు చేయబడుతుంది

- ప్రతి అభ్యర్థన ఖర్చు ప్రతిస్పందన తర్వాత లెక్కించబడి, క్లయింట్కు ఎలాంటి ఆలస్యాన్ని
  కలిగించకుండా fire-and-forget పద్ధతిలో నమోదు చేయబడుతుంది. షేర్డ్-కోటా వినియోగం తదుపరి
  ఈవెంట్-లూప్ టిక్లో [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts)
  ద్వారా షెడ్యూల్ చేయబడుతుంది.
- API కీ వ్యయం బఫర్ చేయబడి,
  [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) ద్వారా బ్యాచ్లుగా ఫ్లష్ చేయబడుతుంది
  (డిఫాల్ట్గా 60s ఫ్లష్ వ్యవధి, 1,000-ఎంట్రీ బఫర్). వీటి ద్వారా సర్దుబాటు చేయవచ్చు:

  | Env var                             | డిఫాల్ట్ | ప్రయోజనం                                    |
  | ----------------------------------- | -------- | ------------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000`  | మిల్లీసెకన్లలో ఫ్లష్ వ్యవధి.                |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`   | ఫ్లష్కు ముందు గరిష్ఠంగా బఫర్ చేసే ఎంట్రీలు. |

డ్యాష్బోర్డ్లోని ఖర్చు సంఖ్యలు నిల్వ చేసిన ఒక్కో వరుస డాలర్ మొత్తం నుండి **చదవబడవు** —
అనలిటిక్స్ ఎండ్పాయింట్ అమలయ్యే ప్రతిసారీ టోకెన్ సంఖ్యలు మరియు ప్రస్తుత ధరల పట్టిక నుండి
అవి వెంటనే మళ్లీ లెక్కించబడతాయి. అంటే, తప్పు ధరను సరిచేయడం (మరియు మళ్లీ సింక్ చేయడం)
చారిత్రక ఖర్చు అంచనాలను గత డేటాకు కూడా వర్తించేలా నవీకరిస్తుంది.

## డ్యాష్బోర్డ్: ఖర్చుల పేజీ

**ఖర్చులు** పేజీ `/dashboard/costs` వద్ద ఉంటుంది
(`src/app/(dashboard)/dashboard/costs/`).
దీని ప్రధాన వీక్షణ **ఖర్చుల అవలోకనం** ట్యాబ్
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`),
ఇది `GET /api/usage/analytics` నుండి మొత్తం డేటాను లోడ్ చేస్తుంది.

ఇది చూపించేవి:

- **వ్యయ టైల్స్** — _ఈ రోజు (1d)_, _7d_, _30d_, అలాగే ఎంచుకున్న
  వ్యవధికి అంచనా వ్యయం. వ్యవధి ఎంపిక సాధనం: `7d`, `30d`, `90d`, `all`.
- **ప్రధాన మెట్రిక్లు** — వ్యవధిలోని అభ్యర్థనలు, సక్రియ ప్రొవైడర్లు, సక్రియ మోడళ్లు, ఒక్కో
  అభ్యర్థనకు సగటు ఖర్చు.
- **ఖర్చుల ఎక్స్ప్లోరర్** — **ప్రొవైడర్**, **మోడల్**,
  **API కీ**, **ఖాతా** లేదా **సేవా స్థాయి** ఆధారంగా సమూహపరచగల, క్రమబద్ధీకరించగల/ఫిల్టర్ చేయగల పట్టిక; ఇందులో ఖర్చు, అభ్యర్థనలు, టోకెన్లు, సగటు
  ఖర్చు/అభ్యర్థన, అలాగే మొత్తం ఖర్చులో వాటా % ఉంటాయి.
- **టోకెన్ వినియోగం** — మొత్తం / ఇన్పుట్ / అవుట్పుట్ టోకెన్లు మరియు ఇన్పుట్:అవుట్పుట్ నిష్పత్తి.
- **రూటింగ్ సామర్థ్యం** — ఫాల్బ్యాక్ల సంఖ్య, ఫాల్బ్యాక్ రేటు, అలాగే అభ్యర్థించిన-మోడల్ కవరేజ్.
- **నెలవారీ అంచనా** — ఇటీవలి రోజువారీ సగటు ఆధారంగా నెలాఖరు వ్యయాన్ని అంచనా వేస్తుంది.
- **వ్యవధి పోలిక** — వ్యవధిలోని మొదటి, రెండవ భాగాల మధ్య % మార్పు.
- **చార్ట్లు** — రోజువారీ ఖర్చు ధోరణి, ప్రొవైడర్ వాటా (పై), అగ్ర ప్రొవైడర్లు, అగ్ర మోడళ్లు, API కీ
  వారీగా ఖర్చు, ఖాతా వారీగా ఖర్చు, వారపు వినియోగ నమూనా, అలాగే కార్యాచరణ హీట్మ్యాప్.
- **ఎగుమతి** — ప్రస్తుత వ్యవధిని **CSV** లేదా **JSON** రూపంలో డౌన్లోడ్ చేయండి (సున్నా కంటే ఎక్కువ ఖర్చు డేటా
  ఉన్నప్పుడు బటన్లు కనిపిస్తాయి).

ధర నిర్ణయించబడిన ట్రాఫిక్ లేనప్పుడు, వరుసలు `$0`కు బదులుగా "లెగసీ / ఉచితం" లేబుల్ను చూపిస్తాయి,
ఇది పొదుపు-ట్రాకర్ నమూనాను ప్రతిబింబిస్తుంది.

### సంబంధిత ఖర్చుల ఉప-పేజీలు

ఖర్చుల విభాగంలో ఇవి కూడా ఉంటాయి (అన్నీ `/dashboard/costs/` కింద):

- **ధరలు** (`/dashboard/costs/pricing`) — ఒక్కో మోడల్ ధరలను వీక్షించి, ఓవర్రైడ్ చేయండి (భాగస్వామ్య
  ధరల ట్యాబ్ను రెండర్ చేస్తుంది).
- **బడ్జెట్** (`/dashboard/costs/budget`) — ఒక్కో స్కోప్కు వ్యయ పరిమితులను సెట్ చేయండి (భాగస్వామ్య
  బడ్జెట్ ట్యాబ్ను రెండర్ చేస్తుంది).
- **కోటా భాగస్వామ్యం** (`/dashboard/costs/quota-share`) — భాగస్వామ్య-కోటా పూల్లు మరియు వినియోగ-రేటు
  వీక్షణలు.

## API ఎండ్పాయింట్లు

వేరుగా పేర్కొనని పక్షంలో, వీటన్నింటికీ నిర్వహణ ప్రమాణీకరణ (లూప్బ్యాక్/JWT, `requireManagementAuth` ద్వారా)
అవసరం.

### వినియోగం & ఖర్చు విశ్లేషణ

| పద్ధతి | ఎండ్పాయింట్              | ప్రయోజనం                                                                                                                                                            |
| ------ | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`  | `/api/usage/analytics`   | పూర్తి ఖర్చు/వినియోగ విశ్లేషణ: సారాంశం, రోజువారీ ధోరణి, ప్రొవైడర్/మోడల్/API కీ/ఖాతా/స్థాయి వారీగా. క్వెరీ: `range`, `startDate`, `endDate`, `apiKeyIds`, `presets`. |
| `GET`  | `/api/usage/utilization` | కాలక్రమంలో ఒక్కో ప్రొవైడర్ కోటా వినియోగం. క్వెరీ: `range` (`1h`/`24h`/`7d`/`30d`), `provider`.                                                                      |
| `GET`  | `/api/usage/history`     | ముడి వినియోగ చరిత్ర వరుసలు.                                                                                                                                         |
| `GET`  | `/api/usage/call-logs`   | ఒక్కో అభ్యర్థన కాల్ లాగ్లు (మోడల్, టోకెన్లు, ఖర్చు, లేటెన్సీ, స్థితి).                                                                                              |
| `GET`  | `/api/usage/quota`       | ప్రొవైడర్ కోటా స్థితి.                                                                                                                                              |
| `GET`  | `/api/usage/proxy-logs`  | ప్రాక్సీ అభ్యర్థన లాగ్లు.                                                                                                                                           |

### బడ్జెట్లు

| పద్ధతి | ఎండ్పాయింట్              | ప్రయోజనం                                                                                 |
| ------ | ------------------------ | ---------------------------------------------------------------------------------------- |
| `GET`  | `/api/usage/budget`      | ఒక API కీ కోసం ఖర్చు సారాంశం + బడ్జెట్ తనిఖీ (`apiKeyId` క్వెరీ పారామీటర్ అవసరం).        |
| `POST` | `/api/usage/budget`      | ఒక API కీ కోసం రోజువారీ/వారపు/నెలవారీ USD పరిమితులు + హెచ్చరిక థ్రెషోల్డ్ను సెట్ చేయండి. |
| `GET`  | `/api/usage/budget/bulk` | API కీలన్నింటిలో సమూహ బడ్జెట్ సారాంశాలు.                                                 |

> బడ్జెట్ API ఒక్కో **API కీ** (`apiKeyId`) పరిధికి వర్తిస్తుంది. దీని ద్వారా తిరిగి వచ్చే పరిమితుల్లో
> `GET /api/usage/budget` ద్వారా `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`,
> ఒక `warningThreshold`, అలాగే కొనసాగుతున్న మొత్తాలు (`totalCostToday`, `totalCostMonth`, …) ఉంటాయి.

## CLI

OmniRoute యొక్క CLI, ఖర్చు, వినియోగం మరియు ధరల కమాండ్లను అందిస్తుంది (ఇవి
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)లో నమోదు చేయబడ్డాయి).

### `omniroute cost`

`/api/usage/analytics` నుండి సమగ్రపరచిన ఖర్చు నివేదిక.

```bash
omniroute cost                          # గత 30 రోజులు, ప్రొవైడర్ వారీగా సమూహీకరించబడుతుంది
omniroute cost --period 7d              # గత 7 రోజులు
omniroute cost --group-by model         # provider | model | combo | api-key | day ఆధారంగా సమూహీకరించండి
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

నిలువు వరుసలు: సమూహం, అభ్యర్థనలు, ఇన్పుట్/అవుట్పుట్ టోకెన్లు, ఖర్చు (USD) మరియు మొత్తం శాతం. చివరలో
సర్వమొత్తం పంక్తి ప్రదర్శించబడుతుంది (`--quiet` లేదా `--output json`తో ఇది అణచివేయబడుతుంది).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # ప్రతి ప్రొవైడర్కు ఖర్చు సారాంశం
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# బడ్జెట్లు
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show`, `GET /api/pricing/defaults` నుండి చదువుతుంది. దానికి బదులుగా వ్యక్తిగత మోడల్
> ధరలను సవరించడానికి, **Pricing** డ్యాష్బోర్డ్ పేజీని లేదా `PATCH /api/pricing`ను ఉపయోగించండి.

## సమస్య పరిష్కారం

- **అన్ని ఖర్చులు $0 / "Legacy / Free"గా కనిపిస్తున్నాయి.** ఉపయోగంలో ఉన్న మోడల్లకు ధర నమోదు లేదు.
  బాహ్య సమకాలీకరణను ప్రారంభించి (`PRICING_SYNC_ENABLED=true`), `omniroute pricing sync`ను అమలు చేయండి లేదా
  Pricing పేజీ / `PATCH /api/pricing` ద్వారా ధరలను మాన్యువల్గా సెట్ చేయండి.
- **చారిత్రక మోడల్కు తప్పుగా ధర నిర్ణయించబడింది.** ధరను సరిచేయండి (ఓవర్రైడ్ చేయండి లేదా మళ్లీ సమకాలీకరించండి) — ప్రతి అనలిటిక్స్ రీడ్లోనూ టోకెన్ల సంఖ్య నుండి ఖర్చు
  మళ్లీ లెక్కించబడుతుంది, కాబట్టి అంచనాలు గత కాలానికి కూడా నవీకరించబడతాయి.
- **ఖర్చు నిజ సమయం కంటే ఆలస్యంగా కనిపిస్తోంది.** ప్రతి కీకి సంబంధించిన ఖర్చు బ్యాచ్లుగా ప్రాసెస్ చేయబడుతుంది; మరింత తాజా సంఖ్యలు అవసరమైతే
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS`ను తగ్గించండి.
