## 1. Antigravity మరియు Antigravity CLI (agy) మధ్య వ్యత్యాసం

రెండు ప్రొవైడర్లూ **ఒకే Google బ్యాకెండ్ను** పంచుకుంటాయి — ఒకే విధమైన OAuth క్లయింట్, టోకెన్ రిఫ్రెష్, ఎండ్పాయింట్లు మరియు Google ఖాతాలు. మీకు కనిపించే మోడళ్లలోనే తేడా ఉంటుంది.

> Google అధికారిక పోలిక కోసం [Antigravity CLI ప్రకటన](https://antigravity.google/blog/introducing-google-antigravity-cli) చూడండి.

| అంశం                         | `antigravity` (IDE)                                            | `agy` (CLI)                                                                |
| ---------------------------- | -------------------------------------------------------------- | -------------------------------------------------------------------------- |
| **Google ఉత్పత్తి**          | Antigravity 2.0 / Antigravity IDE                              | Antigravity CLI                                                            |
| **బ్యాకెండ్**                | అదే Google Cloud Code API                                      | అదే Google Cloud Code API                                                  |
| **OAuth / టోకెన్**           | అదే క్లయింట్, అదే రిఫ్రెష్                                     | అదే క్లయింట్, అదే రిఫ్రెష్                                                 |
| **మోడల్ కేటలాగ్**            | స్థిరంగా ఎంపిక చేసిన జాబితా (OmniRouteలో హార్డ్కోడ్ చేయబడింది) | `:fetchAvailableModels` ద్వారా Google నుండి ప్రత్యక్షంగా పరిశీలించబడుతుంది |
| **Claude మోడళ్లు**           | Sonnet 4.6, Opus 4.6 (ఒక్కోదానికి 4 వేరియంట్లు)                | Sonnet 4.6, Opus 4.6 (ఒక్కోదానికి 4 వేరియంట్లు)                            |
| **Gemini పేర్లు**            | స్పష్టమైన లేబుళ్లు (Low/Medium/High)                           | అప్స్ట్రీమ్ IDలు (extra-low/low/agent)                                     |
| **అదనపు మోడళ్లు**            | `gpt-oss-120b-medium`                                          | Google నుండి అదనపు మోడళ్లు ఉండవచ్చు                                        |
| **డిఫాల్ట్ వినియోగ సందర్భం** | IDE ఇంటిగ్రేషన్ (VS Code, JetBrains)                           | CLI / API యాక్సెస్                                                         |
| **కోటా**                     | agyతో పంచుకోబడుతుంది (అదే Google ఖాతా)                         | antigravityతో పంచుకోబడుతుంది (అదే Google ఖాతా)                             |

**అందుబాటులో ఉన్న మోడళ్లు (ప్రయోగం ద్వారా ధృవీకరించబడినవి, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (వివిధ థింకింగ్ స్థాయిలు)
- Claude: Sonnet 4.6, Opus 4.6 (ఒక్కోదానికి default/low/medium/high వేరియంట్లు)
- ఇతరాలు: GPT-OSS 120B Medium
- **Claude Sonnet 5 అందుబాటులో లేదు** — 4.6 వేరియంట్లకు మాత్రమే మద్దతు ఉంది

**మోడల్ కేటలాగ్ ఎందుకు భిన్నంగా ఉంటుంది**: Google అధికారిక బ్లాగ్ ప్రకారం, Google CLI "వేగం మరియు తక్కువ ఓవర్హెడ్ కోసం ఆప్టిమైజ్ చేయబడింది" మరియు "Gemini మోడళ్లతో కలిసి ఆప్టిమైజ్ చేయబడింది." Web/IDE ఉత్పత్తి "సమగ్రత కోసం ఆప్టిమైజ్ చేయబడింది." మోడళ్లను డైనమిక్గా కనుగొనడానికి CLI `:fetchAvailableModels`ను ఉపయోగిస్తే, IDE స్థిరంగా ఎంపిక చేసిన జాబితాను ఉపయోగిస్తుంది.

**ఆచరణలో**: Gemini మోడళ్ల కోసం `agy/` ప్రిఫిక్స్ను ఉపయోగించండి (ఉదా. `agy/gemini-3.7-flash-high`). స్థిరంగా ఎంపిక చేసిన జాబితా కోసం `antigravity/`ను ఉపయోగించండి. రెండూ ఒకే Google బ్యాకెండ్ను ఉపయోగిస్తాయి, కానీ వేర్వేరు మోడల్ పేర్లను అందుబాటులో ఉంచుతాయి. కోటా పంచుకోబడుతుంది — ఏ ప్రొవైడర్ను ఉపయోగించినా అదే Google ఖాతా పరిమితుల్లో లెక్కించబడుతుంది.

## 2. Google One AI Pro: కోటా వ్యవస్థ

> అధికారిక కోటా వివరాల కోసం [Antigravity Docs: Plans](https://antigravity.google/docs/plans)ను, తాజా ధరల నవీకరణల కోసం [Changes to Antigravity Plans](https://antigravity.google/blog/changes-to-antigravity-plans)ను చూడండి.

Google Antigravity సందేశాల సంఖ్యపై కాకుండా, "పూర్తయిన పని" (గణనాత్మక భారం) ఆధారంగా **ద్వి-స్థాయి కోటా**ను ఉపయోగిస్తుంది.

### రెండు స్థాయిలు

| స్థాయి               | అది ఏమిటి                 | రీఫ్రెష్ చక్రం                                                                                |
| -------------------- | ------------------------- | --------------------------------------------------------------------------------------------- |
| **5-గంటల స్ప్రింట్** | తక్షణ "పూర్తయిన పని" పూల్ | ఒక సెషన్లో మొదటి అభ్యర్థన తర్వాత 5 గంటలకు రీసెట్ అవుతుంది                                     |

**"పూర్తయిన పని" ఎలా లెక్కించబడుతుంది**: ఏజెంట్ను ఎక్కువగా ఉపయోగించే పనులు (ఉదా. "ఈ రిపోజిటరీ మొత్తాన్ని రీఫ్యాక్టర్ చేయండి") సాధారణ పనుల (ఉదా. "ఈ ఫంక్షన్ను సరిచేయండి") కంటే కోటాను చాలా వేగంగా వినియోగిస్తాయి. వినియోగాన్ని చూపించే రియల్-టైమ్ డ్యాష్బోర్డ్ ఏదీ లేదు.

### Gemini మరియు Gemini-యేతర మోడళ్లు

- **Gemini మోడళ్లు** (Flash + Pro): API ధరల ఆధారంగా తగ్గించబడే ఒకే రేట్ పరిమితిని పంచుకుంటాయి. Flash ధర Pro కంటే 8x తక్కువైతే, మీకు 8x ఎక్కువ Flash టోకెన్లు లభిస్తాయి.
- **Gemini-యేతర మోడళ్లు** (Claude, GPT-OSS): **వేర్వేరు** రేట్ పరిమితులను కలిగి ఉంటాయి. Gemini లాక్ అయినప్పటికీ ఇవి అందుబాటులో ఉండవచ్చు.

### AI క్రెడిట్లు (అదనపు వినియోగం)

> క్రెడిట్లు ఎలా పనిచేస్తాయో తెలుసుకోవడానికి [Google One AI credits](https://support.google.com/googleone/answer/14534406)ను చూడండి.

బేస్లైన్ కోటా పూర్తిగా వినియోగించబడినప్పుడు:

- **ఎప్పటికీ వద్దు**: కోటా రీఫ్రెష్ అయ్యే వరకు వేచి ఉంటుంది; "Baseline model quota reached" అని చూపిస్తుంది
- **ఎల్లప్పుడూ**: AI క్రెడిట్లను స్వయంచాలకంగా ఉపయోగిస్తుంది; బేస్లైన్ రీఫ్రెష్ అయినప్పుడు తిరిగి దానికి మారుతుంది

క్రెడిట్లు విడిగా కొనుగోలు చేయబడతాయి మరియు ప్రామాణిక API ధరల ప్రకారం తగ్గించబడతాయి.

### ముఖ్యమైన వివరాలు

- కోటా **ఖాతా స్థాయిలో పంచుకోబడుతుంది** — Antigravity IDE, CLI మరియు OmniRouteలోని ఒకే Google ఖాతా ఒకే కోటా పూల్ను పంచుకుంటుంది
- ప్రతి Google ఖాతాకు దాని స్వంత స్వతంత్ర కోటా ఉంటుంది — బహుళ ఖాతాలు = బహుళ కోటా పూల్లు
- AI Pro వినియోగదారులు వారపు బేస్లైన్ను చేరుకున్నప్పుడు 5-గంటల రీసెట్లకు బదులుగా **7-రోజుల లాక్అవుట్లు** ఎదురైనట్లు నివేదించారు (అధిక డిమాండ్ను దృష్టిలో ఉంచుకుని ఇది ఉద్దేశపూర్వకంగానే రూపొందించబడిందని Google ధృవీకరించింది)

**మీ ఖాతా కోటా పూర్తిగా వినియోగించబడినప్పుడు**: కాంబో రూట్లో అందుబాటులో ఉన్న తదుపరి ఖాతాతో OmniRoute స్వయంచాలకంగా మళ్లీ ప్రయత్నిస్తుంది. మాన్యువల్ జోక్యం అవసరం లేదు.

## 3. projectIdను ఎలా పొందాలి

ప్రతి antigravity/agy కనెక్షన్కు Google Cloud Code `projectId` అవసరం. అది లేకపోతే, `/v1internal:models` ఎండ్పాయింట్ 404ను అందిస్తుంది.

### పద్ధతి A: స్వయంచాలకం (సిఫార్సు చేయబడింది)

OmniRoute దీన్ని స్వయంచాలకంగా నిర్వహిస్తుంది. మీరు Dashboard OAuth ద్వారా కొత్త Google ఖాతాను జోడించినప్పుడు:

1. OmniRoute టోకెన్ను రీఫ్రెష్ చేస్తుంది
2. projectIdను కనుగొనడానికి `loadCodeAssist`ను కాల్ చేస్తుంది
3. ప్రాజెక్ట్ ఏదీ లేకపోతే, ఒకదాన్ని సృష్టించడానికి `onboardUser`ను కాల్ చేస్తుంది
4. కొత్తగా సృష్టించిన projectIdను పొందడానికి `loadCodeAssist`ను మళ్లీ ప్రయత్నిస్తుంది
5. దాన్ని డేటాబేస్లో సేవ్ చేస్తుంది

**ఇది చాలా ఖాతాలకు పనిచేస్తుంది** — మాన్యువల్ దశలు అవసరం లేదు.

### పద్ధతి B: agy CLI ద్వారా మాన్యువల్గా

స్వయంచాలక గుర్తింపు విఫలమైతే (ఇది ఎప్పుడు జరుగుతుందో తెలుసుకోవడానికి విభాగం 5 చూడండి):

```bash
# agy CLIని ఇన్స్టాల్ చేయండి (ఇప్పటికే చేయకపోతే)
npm install -g @anthropic-ai/agy

# మీ Google ఖాతాతో లాగిన్ చేయండి

# ఆన్బోర్డింగ్ అవసరమైన ఖాతాను ఎంచుకోండి
# ఇది Cloud Code నమోదును ప్రారంభించి, ఒక projectIdను కేటాయిస్తుంది

## 4. OAuth రీడైరెక్ట్ URI

### సమస్య

Google OAuthకు చెల్లుబాటు అయ్యే రీడైరెక్ట్ URI అవసరం. OmniRoute డిఫాల్ట్గా `http://127.0.0.1:20128/callback` (లూప్బ్యాక్)ను ఉపయోగిస్తుంది. ఇది లోకల్ బిల్డ్లకు పని చేస్తుంది, కానీ **రిమోట్ డిప్లాయ్మెంట్లలో విఫలమవుతుంది** (ఉదా., LAN IP ద్వారా యాక్సెస్ చేసే సర్వర్).

Google కింది రీడైరెక్ట్ URIలను తిరస్కరిస్తుంది:

- IP చిరునామాలను ఉపయోగించేవి (`.com`, `.org` మొదలైన వాటితో ముగిసే డొమైన్ అయి ఉండాలి)
- OAuth క్లయింట్ కాన్ఫిగరేషన్లో నమోదైన రీడైరెక్ట్ URIలతో సరిపోలనివి

### పరిష్కారం

**ఎంపిక A: అంతర్నిర్మిత OAuth ఫ్లోను ఉపయోగించండి (డిఫాల్ట్)**

- మీరు OmniRouteను `localhost` లేదా `127.0.0.1` నుంచి యాక్సెస్ చేసినప్పుడు పని చేస్తుంది
- ఎలాంటి కాన్ఫిగరేషన్ అవసరం లేదు

**ఎంపిక B: అనుకూల OAuth క్రెడెన్షియల్స్**

- మీ ఎన్విరాన్మెంట్లో `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web`ను సెట్ చేయండి
- మీ స్వంత Google OAuth క్రెడెన్షియల్స్ను అందించండి:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Google Cloud Consoleలో `https://your-domain.com/callback`ను అధీకృత రీడైరెక్ట్ URIగా నమోదు చేయండి

**ఎంపిక C: ప్రారంభ లాగిన్ కోసం agy CLIని ఉపయోగించండి**

- OmniRouteను యాక్సెస్ చేయబోయే మెషీన్లో `agy login`ను అమలు చేయండి
- OAuth ఫ్లో లోకల్గా పూర్తవుతుంది, టోకెన్లు నిల్వ చేయబడతాయి
- Dashboard ద్వారా కనెక్షన్ను OmniRouteలోకి ఇంపోర్ట్ చేయండి

### పరిమితులు

- అనుకూల OAuth క్రెడెన్షియల్స్కు డొమైన్ పేరు అవసరం (రీడైరెక్ట్ URIలుగా IP చిరునామాలను Google అంగీకరించదు)
- మీకు డొమైన్ లేకపోతే, బదులుగా ఎంపిక A లేదా Cను ఉపయోగించండి

## 5. సమస్య పరిష్కారం: ఆటోమేటిక్ సెటప్ విఫలమైనప్పుడు

చాలా ఖాతాల కోసం projectId గుర్తింపు మరియు ఆన్బోర్డింగ్ను OmniRoute ఆటోమేటిక్గా నిర్వహిస్తుంది. ఇది విఫలమైనప్పుడు, సాధారణంగా కింది వాటిలో ఒకటి మూల కారణంగా ఉంటుంది:

### ఖాతా ప్రాంతం బ్లాక్ చేయబడింది

**లక్షణం**: `agy login` "అర్హత తనిఖీ విఫలమైంది: Antigravity ప్రస్తుతం మీ ప్రాంతంలో అందుబాటులో లేనందున, మీ ప్రస్తుత ఖాతా దీనికి అర్హమైనది కాదు." అని చూపిస్తుంది.

**మూల కారణం**: Google ఖాతాలలో నమోదు సమయంలో సెట్ చేయబడే బ్యాకెండ్ "దేశ అనుబంధం" ఫీల్డ్ ఉంటుంది. మీ ప్రస్తుత IPని మాత్రమే తనిఖీ చేసే వెబ్ Geminiకి భిన్నంగా, agy CLI మరియు Cloud Code API ఈ ఫీల్డ్ను కఠినంగా తనిఖీ చేస్తాయి.

> మీ ఖాతాకు అనుబంధించబడిన ప్రాంతాన్ని తనిఖీ చేయడానికి లేదా మార్చడానికి, [Google దేశ అనుబంధ ఫారమ్](https://policies.google.com/country-association-form)ను సందర్శించండి.

**వెబ్ Gemini పని చేసినా agy ఎందుకు పని చేయదు**:

- వెబ్ Gemini / Google One: ప్రస్తుత IPని మాత్రమే తనిఖీ చేస్తుంది (ప్రాక్సీతో పని చేస్తుంది)
- agy CLI / Cloud Code API: బ్యాకెండ్ దేశ అనుబంధ ఫీల్డ్ను చదువుతుంది (ప్రాక్సీ సహాయపడదు)

**పరిష్కారం**:

1. US IPలో ఉన్నప్పుడు [Google దేశ అనుబంధ ఫారమ్](https://policies.google.com/country-association-form)ను సందర్శించండి
2. ప్రాంత మార్పు అభ్యర్థనను సమర్పించండి ("నేను వేరే దేశంలో నివసిస్తున్నాను"ని ఎంచుకోండి)
3. Google ప్రాసెస్ చేసి + ఇమెయిల్ నోటిఫికేషన్ పంపడానికి 1-24 గంటలు వేచి ఉండండి
4. ఆ తర్వాత `agy login` విజయవంతం కావాలి

### ఖాతాకు Cloud Code ప్రాజెక్ట్ లేదు

**లక్షణం**: లాగ్లలో `loadCodeAssist ప్రాజెక్ట్ idని తిరిగి ఇవ్వలేదు` మరియు `onboardUser విఫలమైంది (400)` అని కనిపిస్తుంది.

**మూల కారణం**: ఖాతా Google Cloud Codeతో ఎన్నడూ నమోదు చేయబడలేదు, అలాగే ఆటోమేటిక్ ఆన్బోర్డింగ్ విఫలమైంది.

**పరిష్కారం**: Cloud Code నమోదును ప్రారంభించడానికి `agy login`ను మాన్యువల్గా అమలు చేసి, ఆపై OmniRoute Dashboardలో టోకెన్ను రిఫ్రెష్ చేయండి.

### టోకెన్ గడువు ముగిసింది లేదా రద్దు చేయబడింది

**లక్షణం**: లాగ్లలో 401 ఎర్రర్లు లేదా "టోకెన్ గడువు ముగిసింది" సందేశాలు కనిపిస్తాయి.

**పరిష్కారం**: Dashboard → Providers → agy → రిఫ్రెష్ ఐకాన్ను క్లిక్ చేయండి వద్ద టోకెన్ను రిఫ్రెష్ చేయండి. రిఫ్రెష్ టోకెన్ కూడా రద్దు చేయబడితే, మీరు OAuth ద్వారా మళ్లీ ప్రామాణీకరించాల్సి ఉంటుంది.

   └─ విఫలమవుతుంది → దోష సందేశాన్ని తనిఖీ చేయండి; ఇది ప్రాంతం లేదా సబ్స్క్రిప్షన్ సమస్య కావచ్చు
```
