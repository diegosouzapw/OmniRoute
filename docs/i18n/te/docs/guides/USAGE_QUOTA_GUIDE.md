> **TL;DR**: OmniRoute ప్రతి అభ్యర్థన యొక్క టోకెన్ వినియోగాన్ని ట్రాక్ చేస్తుంది, ఖర్చును లెక్కిస్తుంది, ప్రతి API కీకి కోటాను అమలు చేస్తుంది మరియు డ్యాష్బోర్డ్లో విశ్లేషణలను ప్రదర్శిస్తుంది. ఇవన్నీ ఎలా పనిచేస్తాయో ఈ మార్గదర్శిని వివరిస్తుంది.

**మూలాలు:**

- `open-sse/services/usage.ts` (~70KB) — ప్రధాన వినియోగ ట్రాకింగ్
- `src/lib/usageAnalytics.ts` (~10KB) — డ్యాష్బోర్డ్ కోసం సమీకరణ
- `src/lib/db/quotaSnapshots.ts` — చారిత్రక కోటా డేటా
- `src/lib/db/usage*.ts` — వినియోగానికి సంబంధించిన అనేక DB మాడ్యూళ్లు

## అవలోకనం

OmniRoute ద్వారా ప్రవహించే ప్రతి అభ్యర్థన కింది వివరాలను సంగ్రహించే **వినియోగ రికార్డ్**ను రూపొందిస్తుంది:

- **గుర్తింపు**: ఏ API కీ, ప్రొవైడర్, మోడల్, కాంబో
- **టోకెన్లు**: ప్రాంప్ట్ టోకెన్లు, కంప్లీషన్ టోకెన్లు, క్యాష్ చేసిన టోకెన్లు, మొత్తం
- **ఖర్చు**: USD మొత్తం (ధరల డేటా నుండి లెక్కించబడుతుంది)
- **సమయ వివరాలు**: లేటెన్సీ, ప్రారంభ/ముగింపు టైమ్స్టాంప్లు
- **స్థితి**: విజయవంతం, లోపం, రేట్-లిమిట్ చేయబడింది మొదలైనవి

ఈ రికార్డ్లు **విశ్లేషణలు**గా సమీకరించబడతాయి, **కోటా స్నాప్షాట్లు**గా నిల్వ చేయబడతాయి మరియు **ప్రతి కీకి బడ్జెట్ పరిమితులను** అమలు చేయడానికి ఉపయోగించబడతాయి.

```
అభ్యర్థన ──▶ chatCore ──▶ usage.record() ──▶ SQLite
                                  │
                          ┌───────┼───────┐
                          ▼       ▼       ▼
                    విశ్లేషణలు  కోటా   బిల్లింగ్
                    (డ్యాష్బోర్డ్) (అమలు) (ఎగుమతి)
```

## ఏవి రికార్డ్ చేయబడతాయి

`usage.ts` సర్వీస్ ప్రతి అభ్యర్థనకు ఒక **వినియోగ ఈవెంట్**ను సంగ్రహిస్తుంది:

| ఫీల్డ్             | రకం     | మూలం                                                          |
| ------------------ | ------- | ------------------------------------------------------------- |
| `id`               | string  | రికార్డ్ చేసేటప్పుడు రూపొందించబడిన UUID                       |
| `apiKeyId`         | string  | అభ్యర్థనను ప్రారంభించిన API కీ                                |
| `provider`         | string  | ప్రొవైడర్ ID (openai, anthropic మొదలైనవి)                     |
| `model`            | string  | మోడల్ ID (gpt-5, claude-opus-4-6 మొదలైనవి)                    |
| `comboId`          | string? | కాంబో ద్వారా రూట్ చేయబడితే కాంబో ID                           |
| `promptTokens`     | number  | అప్స్ట్రీమ్ ప్రతిస్పందన నుండి                                 |
| `completionTokens` | number  | అప్స్ట్రీమ్ ప్రతిస్పందన నుండి                                 |
| `cachedTokens`     | number  | క్యాష్ హిట్ టోకెన్లు (Anthropic ప్రాంప్ట్ క్యాషింగ్ మొదలైనవి) |
| `totalTokens`      | number  | ప్రాంప్ట్ + కంప్లీషన్                                         |
| `costUsd`          | number  | ధరల డేటా నుండి లెక్కించబడింది                                 |
| `latencyMs`        | number  | ఎండ్-టు-ఎండ్ అభ్యర్థన వ్యవధి                                  |
| `status`           | enum    | `success`, `error`, `rate_limited`, `timeout`, `cancelled`    |
| `errorClass`       | string? | స్థితి `success` కాకపోతే లోపం క్లాస్                          |
| `timestamp`        | string  | ISO 8601 UTC                                                  |
| `metadata`         | object  | ప్లగిన్ ద్వారా చేర్చబడిన అనుకూల డేటా                          |

### టోకెన్లు ఎక్కడి నుండి వస్తాయి

**రెస్పాన్స్ హ్యాండ్లర్**లో అప్స్ట్రీమ్ ప్రొవైడర్ ప్రతిస్పందన నుండి టోకెన్లు సంగ్రహించబడతాయి:

```ts
// open-sse/handlers/chatCore.ts నుండి
const response = await providerExecutor.execute(provider, request);
const usage = response.usage || {
  prompt_tokens: 0,
  completion_tokens: 0,
  cached_tokens: 0,
};
```

వినియోగ వివరాలను అందించని ప్రొవైడర్ల కోసం (కొన్ని వెబ్-కుకీ ప్రొవైడర్లు), OmniRoute `~4 chars per token` హ్యూరిస్టిక్ను ఉపయోగించి టోకెన్లను **అంచనా వేస్తుంది** (`open-sse/services/autoCombo/pipelineRouter.ts` చూడండి).

### క్యాష్ చేసిన టోకెన్లు

OmniRoute `cached_tokens`ను `prompt_tokens` నుండి విడిగా ట్రాక్ చేస్తుంది, ఎందుకంటే:

- Anthropic ప్రాంప్ట్ క్యాషింగ్ క్యాష్ చేసిన టోకెన్లకు తక్కువ రేటును వసూలు చేస్తుంది (సాధారణ రేటులో 10%)
- కొంతమంది ప్రొవైడర్లు భిన్నంగా ధర నిర్ణయించాల్సిన `cache_read_input_tokens`ను అందిస్తారు
- విశ్లేషణలు **క్యాష్ హిట్ రేటు** = `cached_tokens / prompt_tokens`ను చూపగలవు

## ఖర్చు గణన

ఖర్చులు LiteLLM నుండి సమకాలీకరించబడిన **ధరల డేటా** ఆధారంగా గణించబడతాయి (`src/lib/pricingSync.ts`):

| మోడల్             | ఇన్పుట్ $/1M | అవుట్పుట్ $/1M | కాష్డ్ $/1M |
| ----------------- | ------------ | -------------- | ----------- |
| gpt-5             | $2.50        | $10.00         | —           |
| claude-opus-4-6   | $15.00       | $75.00         | $1.50       |
| claude-sonnet-4-5 | $3.00        | $15.00         | $0.30       |
| gemini-2.5-pro    | $1.25        | $10.00         | —           |

ఖర్చు సూత్రం (`src/lib/usage/costCalculator.ts`):

```ts
cost =
  (prompt_tokens - cached_tokens) * input_price +
  cached_tokens * cached_price +
  completion_tokens * output_price;
```

> **ప్రాంప్ట్ నుండి కాష్డ్ టోకెన్లను ఎందుకు తీసివేయాలి?** కాష్డ్ భాగానికి విడిగా ధర నిర్ణయించబడుతుంది; మొత్తం ప్రాంప్ట్పై ఇన్పుట్ ధరను వర్తింపజేస్తే ఖర్చు అధికంగా లెక్కించబడుతుంది.

### ధరల సమకాలీకరణ

అంతర్నిర్మిత cron టాస్క్ ద్వారా ట్రిగ్గర్ చేయబడే `/api/pricing/sync` ఎండ్పాయింట్ ద్వారా ధరల డేటా LiteLLM నుండి స్వయంచాలకంగా సమకాలీకరించబడుతుంది (ఇది వినియోగదారులకు అందుబాటులో ఉండే env var కాదు):

```bash
# మాన్యువల్ ట్రిగ్గర్
curl -X POST http://localhost:20128/api/pricing/sync
```

ధరల డేటా లేని మోడల్ల కోసం, OmniRoute అంతర్గత సగటు రేట్లను ఉపయోగించి **ఖర్చును అంచనా వేస్తుంది** (ఇవి LiteLLM ధరల డేటా నుండి సేకరించబడతాయి).

## తేదీ పరిధి అగ్రిగేషన్

`usageAnalytics.ts` మాడ్యూల్ ముడి వినియోగ డేటా నుండి డ్యాష్బోర్డ్ విడ్జెట్లను గణిస్తుంది. ఇది 7 కాల పరిధులకు మద్దతు ఇస్తుంది:

| పరిధి    | కాల వ్యవధి                               | ఉపయోగ సందర్భం                    |
| -------- | ---------------------------------------- | -------------------------------- |
| `1d`     | గత 24 గంటలు                              | గంటవారీ ఖర్చు పెరుగుదల గుర్తింపు |
| `7d`     | గత 7 రోజులు                              | వారపు సమీక్ష                     |
| `30d`    | గత 30 రోజులు                             | నెలవారీ బిల్లింగ్                |
| `90d`    | గత 90 రోజులు                             | త్రైమాసిక విశ్లేషణ               |
| `ytd`    | ప్రస్తుత సంవత్సరం Jan 1 నుండి            | వార్షిక బడ్జెట్ ట్రాకింగ్        |
| `all`    | మొత్తం కాలం                              | జీవితకాల గణాంకాలు                |
| `custom` | వినియోగదారు నిర్వచించిన ప్రారంభం/ముగింపు | ఆడిట్లు, తాత్కాలిక క్వెరీలు      |

### గణించబడే డ్యాష్బోర్డ్ విడ్జెట్లు

ఏ తేదీ పరిధికైనా, అనలిటిక్స్ లేయర్ కింది వాటిని గణిస్తుంది:

| విడ్జెట్                    | వివరణ                                                       |
| --------------------------- | ----------------------------------------------------------- |
| **సారాంశ కార్డ్లు**         | మొత్తం అభ్యర్థనలు, మొత్తం ఖర్చు, మొత్తం టోకెన్లు, విజయ రేటు |
| **రోజువారీ ట్రెండ్ చార్ట్** | రోజుకు ఖర్చు + టోకెన్లు, మోడల్ ఆధారంగా స్టాక్ చేయబడినవి     |
| **యాక్టివిటీ హీట్మ్యాప్**   | రోజులోని గంట × వారంలోని రోజు గ్రిడ్, రంగు = అభ్యర్థనల సంఖ్య |
| **మోడల్ విభజన**             | మోడల్ వారీ ఖర్చు పై చార్ట్                                  |
| **ప్రొవైడర్ విభజన**         | ప్రొవైడర్ వారీ అభ్యర్థనల బార్ చార్ట్                        |
| **అగ్ర API కీలు**           | ఖర్చు ఆధారంగా అగ్ర 10 కీల పట్టిక                            |
| **లోప విశ్లేషణ**            | కాలక్రమంలో లోప రేటు, అగ్ర లోప తరగతులు                       |

### ప్రోగ్రామాటిక్ యాక్సెస్

````ts
import { computeAnalytics } from "@/lib/usageAnalytics";

const analytics = await computeAnalytics(
  history,              // వినియోగ చరిత్ర రికార్డులు
  "7d",                 // కాల పరిధి: "1d" | "7d" | "30d" | "90d" | "ytd" | "all" | "custom"
  connectionMap,        // ప్రొవైడర్ కనెక్షన్ మ్యాప్ (connectionId → ఖాతా పేరు)
  {
    startDate: "2025-01-01",  // ఐచ్ఛికం: "custom" పరిధి కోసం
    endDate: "2025-06-01",   // ఐచ్ఛికం: "custom" పరిధి కోసం
  }
);

console.log(analytics.summary.totalCost);   // 12.34 (సెంట్లు)
console.log(analytics.byModel[0]);           // { model, cost, requests, promptTokens, completionTokens }

## కోటా అమలు

ఒక్కో API కీకి సంబంధించిన కోటా రెండు చోట్ల అమలు చేయబడుతుంది:

1. **సాఫ్ట్ పరిమితి** (`quotaWarnAt`): వినియోగం పరిమితిని మించినప్పుడు డ్యాష్బోర్డ్ హెచ్చరిక
2. **హార్డ్ పరిమితి** (`quotaLimit`): పరిమితిని మించినప్పుడు అభ్యర్థన HTTP 429తో తిరస్కరించబడుతుంది

### కాన్ఫిగరేషన్

```ts
// ఒక్కో API కీకి
await updateApiKey(keyId, {
  quotaWarnAt: 5_00,    // $5.00 — హెచ్చరికను చూపించు
  quotaLimit: 10_00,    // $10.00 — పూర్తిగా నిలిపివేయి
  quotaWindow: "month", // "day" | "week" | "month" | "all"
});
````

### అమలు ప్రవాహం

```
అభ్యర్థన ──▶ quotaCheck()
              │
              ├── పరిమితిలో ఉందా?  ──▶ అనుమతించు
              │
              └── పరిమితిని మించిందా?  ──▶ 429 చాలా ఎక్కువ అభ్యర్థనలు
                                             Retry-After హెడర్తో
```

### కోటా స్నాప్షాట్లు

ట్రెండ్ విశ్లేషణ కోసం `quotaSnapshots` పట్టిక **చారిత్రక కోటా స్థితిని** నిల్వ చేస్తుంది:

| ఫీల్డ్ | వివరణ |
| ----------- | -------------------------------- | ------ | ------- |
| `apiKeyId` | ట్రాక్ చేయబడుతున్న కీ |
| `window` | "day" | "week" | "month" |
| `used` | ఈ విండోలో ఉపయోగించిన ఖర్చు (సెంట్లు) |
| `limit` | పరిమితి (సెంట్లు) |
| `resetAt` | విండో రీసెట్ అయ్యే సమయం |
| `createdAt` | స్నాప్షాట్ తీసుకున్న సమయం |

> 0 ఖర్చును ఉపయోగించే **ప్రతి అభ్యర్థనకు** స్నాప్షాట్లు తీసుకోబడతాయి, మరియు వీటిని కింది వాటికి ఉపయోగిస్తారు:

- డ్యాష్బోర్డ్లో కోటా పురోగతి పట్టీని రెండర్ చేయడానికి
- 30-రోజుల కోటా ట్రెండ్ చార్ట్లను చూపించడానికి
- వినియోగం పరిమితికి చేరువైనప్పుడు హెచ్చరికలను ట్రిగ్గర్ చేయడానికి

- **`/api/usage/history`** — అభ్యర్థన చరిత్ర లాగ్లు

## నిల్వ వ్యవధి మరియు క్లీనప్

ప్రతి అభ్యర్థనకు వినియోగ డేటా ~1-10KB మేర పెరుగుతుంది. పెద్ద స్థాయిలో ఇది గణనీయంగా ఉండవచ్చు.

### నిల్వ వ్యవధి సెట్టింగ్లు

వినియోగ చరిత్ర నిల్వ వ్యవధిని UIలోని Database Settings ద్వారా లేదా `/api/settings/database` ద్వారా కాన్ఫిగర్ చేయవచ్చు.

డిఫాల్ట్గా, వినియోగ చరిత్ర **90 రోజుల** పాటు నిల్వ చేయబడుతుంది.

### క్లీనప్

పాత రికార్డులను `src/lib/db/cleanup.ts` ద్వారా తొలగిస్తారు:

- బ్యాక్గ్రౌండ్ cron ప్రాసెస్ ద్వారా ట్రిగ్గర్ చేయబడుతుంది
- కాన్ఫిగర్ చేసిన `usageHistory` నిల్వ వ్యవధి సెట్టింగ్ కంటే పాత `usage_history` రికార్డులను తొలగిస్తుంది

### స్టోరేజ్ అంచనా

| అభ్యర్థన రేటు             | 30-రోజుల స్టోరేజ్ | 90-రోజుల స్టోరేజ్ |
| ------------------------- | ----------------- | ----------------- |
| రోజుకు 100 అభ్యర్థనలు     | ~3MB              | ~9MB              |
| రోజుకు 1,000 అభ్యర్థనలు   | ~30MB             | ~90MB             |
| రోజుకు 10,000 అభ్యర్థనలు  | ~300MB            | ~900MB            |
| రోజుకు 100,000 అభ్యర్థనలు | ~3GB              | ~9GB              |

చాలా అధిక ట్రాఫిక్ కోసం, వీటిని పరిగణించండి:

- Database Settings ద్వారా నిల్వ వ్యవధిని తగ్గించడం
- ముడి రికార్డులకు బదులుగా `aggregated_metrics` ఉపయోగించడం (విశ్లేషణల కోసం మాత్రమే)

## ఖర్చు ఆప్టిమైజేషన్ చిట్కాలు

### 1. సరైన మోడల్ను ఉపయోగించండి

```bash
# త్వరిత సమాధానం — చౌకైన + వేగవంతమైనదాన్ని ఉపయోగించండి
curl -d '{"model":"auto/fast","messages":[...]}'

# సంక్లిష్టమైన పని — నాణ్యతకు ప్రాధాన్యం ఇవ్వండి
curl -d '{"model":"auto/smart","messages":[...]}'
```

### 2. క్యాషింగ్ను ప్రారంభించండి

Anthropic prompt caching పునరావృతమయ్యే కాంటెక్స్ట్పై **90% ఆదా చేస్తుంది**:

```ts
// క్యాషింగ్ ఆటోమేటిక్గా జరుగుతుంది — అదే పెద్ద system promptను చేర్చండి
const response = await openai.chat({
  model: "claude-sonnet-4-5",
  system: longSystemPrompt, // ఆటోమేటిక్గా క్యాష్ చేయబడుతుంది
  messages: [{ role: "user", content: "..." }],
});
```

### 3. కంప్రెషన్ను ఉపయోగించండి

RTK + Caveman కంప్రెషన్, టూల్స్ను ఎక్కువగా ఉపయోగించే సెషన్లలో **15-95% ఆదా చేస్తుంది**:

```ts
const config = {
  compression: {
    engine: "rtk",
    intensity: "aggressive",
  },
};
```

### 4. ప్రతి కీకి కోటాలను సెట్ చేయండి

నియంత్రణ లేని ఖర్చులను నివారించడానికి ఎల్లప్పుడూ `quotaLimit`ను సెట్ చేయండి:

```ts
await updateApiKey(keyId, { quotaLimit: 10_00 }); // నెలకు $10 పరిమితి
```

### 5. అత్యధిక వినియోగదారులను ఆడిట్ చేయండి

API కీ ఆధారంగా గ్రూప్ చేసి, ఖర్చు ప్రకారం క్రమబద్ధీకరించడానికి డ్యాష్బోర్డ్ లేదా **`/api/usage/analytics`** ఉపయోగించండి:

```bash
GET /api/usage/analytics?groupBy=apiKey
```

## సమస్య పరిష్కారం

### "ఖర్చు ఊహించిన దానికంటే ఎక్కువగా ఉంది"

1. **`/api/usage/analytics?groupBy=model`** తనిఖీ చేయండి — ఖరీదైన మోడల్ను కనుగొనండి
2. **`/api/usage/analytics?groupBy=apiKey`** తనిఖీ చేయండి — అధికంగా వినియోగిస్తున్న వినియోగదారును కనుగొనండి
3. ధరల డేటా తాజాగా ఉందని ధృవీకరించండి: `POST /api/pricing/sync`

### "రికార్డులు కనిపించడం లేదు"

- Dashboard → Database → Cleanup కింద DB నిల్వ వ్యవధి సెట్టింగ్లను తనిఖీ చేయండి — పాత రికార్డులు ఆవర్తన క్లీనప్ టాస్క్ (`src/lib/db/cleanup.ts`) ద్వారా తొలగించబడతాయి
- `src/lib/db/usage*.ts`లో ఎర్రర్ల కోసం తనిఖీ చేయండి — DB రైట్ వైఫల్యాలు లాగ్ చేయబడతాయి, కానీ బయటకు చూపబడవు
- అభ్యర్థన నిజంగా `chatCore`కు చేరిందని ధృవీకరించండి — combo routingను తనిఖీ చేయండి

### "కోటా అమలు కావడం లేదు"

- కీ యొక్క `quotaLimit` సెట్టింగ్ను తనిఖీ చేయండి
- `quotaWindow` సరిగ్గా సెట్ చేయబడిందని ధృవీకరించండి
- `quotaSnapshots` రికార్డుల కోసం చూడండి — ప్రతి అభ్యర్థనపై అవి సృష్టించబడాలి
