`@omniroute/opencode-plugin-v2` మీ పూర్తి OmniRoute కేటలాగ్ను — మోడల్లు, కాంబోలు మరియు
ఆటో-కాంబోలు — ప్రదర్శన పేర్లు, ధరలు మరియు ఉచిత-స్థాయి బడ్జెట్లతో సహా OpenCode v2 మోడల్ పికర్లో ఉంచుతుంది.

ఇది `@omniroute/opencode-plugin` నుండి వేరైన ప్యాకేజీ, ఎందుకంటే OpenCode v1 మరియు v2 ప్లగిన్లను
వేర్వేరు కాంట్రాక్ట్ల ద్వారా లోడ్ చేస్తాయి. మీ OpenCode ప్రధాన వెర్షన్కు సరిపోయేదాన్ని ఎంచుకోండి; వాటి మధ్య
ఏదీ భాగస్వామ్యం చేయబడదు, కాబట్టి ఒకదాన్ని అప్గ్రేడ్ చేయడం వల్ల మరొకదాన్ని అప్గ్రేడ్ చేయాల్సిన అవసరం ఎప్పుడూ ఉండదు.

## అవసరాలు

- OpenCode v2.
- అందుబాటులో ఉండే OmniRoute గేట్వే (డిఫాల్ట్గా `http://localhost:20128`).
- Node.js 22 లేదా 24.

## ఇన్స్టాల్ చేయడం

ప్లగిన్ను `opencode.json`కు జోడించండి:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

తర్వాత మోడల్లు `omniroute/<provider>/<model>` రూపంలో కనిపిస్తాయి; ఆ ప్రిఫిక్స్ను మరియు
OpenCode క్రెడెన్షియల్ను నిల్వ చేసే ఇంటిగ్రేషన్ idని `providerId` నిర్ణయిస్తుంది.

## క్రెడెన్షియల్లు

ప్లగిన్ గేట్వే కీ కోసం ఈ క్రమంలో మూడు చోట్ల వెతుకుతుంది:

1. **మీరు OpenCodeలో కనెక్ట్ చేసిన క్రెడెన్షియల్.** ప్లగిన్ ఒక ఇంటిగ్రేషన్ను నమోదు చేస్తుంది, కాబట్టి
   OpenCode స్వంత ప్రమాణీకరణ ప్రక్రియ కీని నిల్వ చేయగలదు. `opencode.json`లో ఏదీ చేరదు — దీనికే ప్రాధాన్యం ఇవ్వండి.
2. ఒక్కో ప్రాజెక్ట్కు ప్రత్యేక ఓవర్రైడ్ కోసం ప్లగిన్ ఎంపికలలోని `apiKey`. ఇది మీరు
   కమిట్ చేసే అవకాశం ఉన్న ఫైల్లో కీని ఉంచుతుంది.
3. ఎన్విరాన్మెంట్లోని `OMNIROUTE_API_KEY`.

ఈ మూడింటిలో ఏదీ లేకపోతే, కేటలాగ్ ఖాళీగా ఉంటుంది మరియు నిశ్శబ్దంగా ఖాళీ పికర్ను
వదిలివేయడానికి బదులుగా ప్లగిన్ స్టార్టప్ సమయంలో ఒక్కసారి ఆ విషయాన్ని తెలియజేస్తుంది.

### నిర్వహణ టోకెన్ వేరే కీ

కాంబోలు, ప్రొవైడర్ ఆరోగ్యం మరియు మెరుగుదల సమాచారం (ప్రదర్శన పేర్లు, ధరలు, ఉచిత-స్థాయి బడ్జెట్లు)
గేట్వే `/api/*` ఎండ్పాయింట్ల నుండి వస్తాయి. చాలా డిప్లాయ్మెంట్లు వీటిని ఇన్ఫరెన్స్ కీకి బదులుగా
**నిర్వహణ** టోకెన్తో రక్షిస్తాయి:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<management read token>"
}
```

`managementReadToken`ను సెట్ చేయకుండా వదిలేస్తే, అది `apiKey`ను ఫాల్బ్యాక్గా ఉపయోగిస్తుంది. గేట్వే ఆ ఫాల్బ్యాక్ను
తిరస్కరించినప్పుడు కూడా కేటలాగ్ ప్రచురించబడుతుంది, కానీ ప్రదర్శన పేర్లకు బదులుగా ముడి మోడల్ idలతో,
కానానికల్ అలియాస్ డీడూప్ లేకుండా, ధరలు లేకుండా మరియు కాంబోలు లేకుండా ఉంటుంది. అలా జరిగినప్పుడు ప్లగిన్ ఒక్కో ఎండ్పాయింట్కు
ఒక్కసారి హెచ్చరిస్తూ, ఎండ్పాయింట్ను మరియు ఏది కోల్పోయిందో పేర్కొంటుంది — కాబట్టి పరిమితమైన పికర్ ఎప్పుడూ అంతుచిక్కని విషయం కాదు.

## ఎంపికలు

| కీ                               | డిఫాల్ట్                                                | గమనికలు                                                                                                                      |
| -------------------------------- | ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `providerId`                     | `"omniroute"`                                           | ప్రొవైడర్ id, ఇంటిగ్రేషన్ id మరియు మోడల్లు కనిపించే ప్రిఫిక్స్                                                               |
| `baseURL`                        | తప్పనిసరి                                               | గేట్వే రూట్, `http(s)` మాత్రమే; అవసరమైన చోట `/v1` సఫిక్స్ జోడించబడుతుంది                                                     |
| `apiKey`                         | కనెక్ట్ చేసిన క్రెడెన్షియల్, తర్వాత `OMNIROUTE_API_KEY` | `/v1/*` కోసం చాట్ కీ                                                                                                         |
| `managementReadToken`            | `apiKey`కు ఫాల్బ్యాక్ అవుతుంది                          | `/api/*` కోసం కీ — సాధారణంగా **అదే కీ కాదు**                                                                                 |
| `displayName`                    | `"OmniRoute"`                                           | పికర్లో ప్రొవైడర్ పేరు                                                                                                       |
| `timeoutMs`                      | `10000`                                                 | ఒక్కో ఎండ్పాయింట్ ఫెచ్ టైమ్అవుట్ (ఆటో-కాంబోలు 5s ఉపయోగిస్తాయి)                                                               |
| `modelCacheTtlMs`                | `300000`                                                | కేటలాగ్ క్యాష్ TTL; డిస్క్ స్నాప్షాట్ కోల్డ్ స్టార్ట్లను వేగవంతం చేస్తుంది                                                   |
| `timeouts`                       | `timeoutMs`కు ఫాల్బ్యాక్ అవుతుంది                       | msలో ఒక్కో ఎండ్పాయింట్ బడ్జెట్లు: `models`, `combos`, `autoCombos`, `enrichment`                                             |
| `enrichment`                     | `true`                                                  | పేర్లు, ధరలు మరియు ఉచిత-స్థాయి బడ్జెట్లను పొందుతుంది                                                                         |
| `providerTag`                    | `true`                                                  | ప్రదర్శన పేరుకు అది రూట్ చేసే అప్స్ట్రీమ్ ప్రొవైడర్ను ప్రిఫిక్స్గా జోడిస్తుంది                                               |
| `usableOnly`                     | `false`                                                 | గేట్వే ప్రొవిజన్ చేయబడినవిగా నివేదించే ప్రొవైడర్లను మాత్రమే ఉంచుతుంది                                                        |
| `visibleModels` / `hiddenModels` | `[]`                                                    | ఖచ్చితమైన-లేదా-సఫిక్స్ అనుమతి జాబితాలు; నిరాకరణకే ప్రాధాన్యం                                                                 |
| `geminiSanitization`             | `true`                                                  | టూల్ స్కీమాల నుండి Gemini తిరస్కరించే JSON-Schema కీవర్డ్లను తొలగిస్తుంది (`$ref` టూల్లు మార్పు లేకుండా ఫార్వర్డ్ చేయబడతాయి) |
| `apiFormat.allowAnthropic`       | `false`                                                 | అనుమతి జాబితాలోని idలను Anthropic API బ్లాక్ ద్వారా రూట్ చేస్తుంది                                                           |
| `apiFormat.anthropicModels`      | `[]`                                                    | Anthropicకు రూట్ చేయబడే పూర్తి మోడల్ idలు                                                                                    |
| `logLevel` / `startupDebug`      | `warn` / `false`                                        | లాగర్ వివరాల స్థాయి                                                                                                          |

## కాటలాగ్ తాజాగా ఎలా ఉంటుంది

కాటలాగ్ అవసరమైనప్పుడు మాత్రమే పొందబడుతుంది మరియు `modelCacheTtlMs` వ్యవధి వరకు క్యాష్ చేయబడుతుంది. గేట్వేను చేరుకోలేనప్పుడు చివరిగా తెలిసిన కాటలాగ్ అందుబాటులో ఉండేలా ఒక డిస్క్ స్నాప్షాట్ ఉంచుతుంది — అంతరాయం వల్ల తాజాదనం తప్ప మరేమీ కోల్పోరు. మోడళ్లు మరియు కాంబోలు అందిన వెంటనే ప్రచురించబడతాయి; ఆటో-కాంబోలు, ప్రొవైడర్ జాబితా మరియు ఎన్రిచ్మెంట్ ఓవర్లే అందినప్పుడు విలీనం అవుతాయి. అందువల్ల నెమ్మదిగా స్పందించే ఒక ఎండ్పాయింట్ మొత్తం పికర్ను నిలిపివేయలేదు.

గేట్వేకు తెలిసిన వివరాలను పేర్లు కలిగి ఉంటాయి: ఒక మోడల్ రూట్ అయ్యే అప్స్ట్రీమ్ ప్రొవైడర్, ఒక `[Free]` గుర్తు మరియు దానితో లభించే బడ్జెట్ — తద్వారా ఒకే మోడల్ను అందించే రెండు కనెక్షన్లను వేరుగా గుర్తించవచ్చు. `"providerTag": false`తో ప్రిఫిక్స్ను నిలిపివేయండి.

మాన్యువల్ రిఫ్రెష్ కమాండ్ లేదు: OpenCode v2 కమాండ్లు ప్రాంప్ట్ టెంప్లేట్లు, కాల్బ్యాక్లు కావు, కాబట్టి ప్లగిన్ అలాంటి కమాండ్ను అందించలేదు. రిఫ్రెష్లు TTLను అనుసరిస్తాయి; కాటలాగ్ లేదా ఓవర్లే నిజంగా మారినప్పుడు మాత్రమే హోస్ట్ను రీలోడ్ చేయమని అడుగుతుంది, ప్రతి రిఫ్రెష్కు కాదు.

## Geminiలో టూల్ కాలింగ్

టూల్ డిక్లరేషన్లలో `$schema` లేదా `additionalProperties` ఉంటే Gemini మొత్తం అభ్యర్థనను తిరస్కరించి, `400 INVALID_ARGUMENT`తో స్పందిస్తుంది. ఈ ప్రొవైడర్కు చెందిన Gemini మోడల్కు పంపే టూల్ స్కీమాల నుంచి ప్లగిన్ ఆ కీవర్డ్లను తొలగిస్తుంది మరియు ఇతర ప్రతి అభ్యర్థనను మార్చకుండా ఉంచుతుంది. `$ref` ఉన్న టూల్ను తొలగింపులు చేయకుండా యథాతథంగా ఫార్వర్డ్ చేస్తుంది, ఎందుకంటే ఆ రెఫరెన్స్ను తొలగిస్తే స్కీమా "దేనినైనా ఆమోదించేలా" విస్తరిస్తుంది.
దీన్ని నిలిపివేయడానికి `"geminiSanitization": false`ను సెట్ చేయండి.
