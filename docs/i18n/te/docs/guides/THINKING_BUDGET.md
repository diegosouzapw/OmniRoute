> **డ్యాష్బోర్డ్:** సెట్టింగ్లు → **AI** → థింకింగ్ బడ్జెట్  
> **API:** `GET` / `PUT` `/api/settings/thinking-budget`  
> **సోర్స్:** `open-sse/services/thinkingBudget.ts`

ప్రొవైడర్లకు పంపే క్రమంలో OmniRoute **క్లయింట్ థింకింగ్/రీజనింగ్ పారామీటర్లను తిరిగి రాయాలా వద్దా** అనేది థింకింగ్ బడ్జెట్ నియంత్రిస్తుంది. ఇది కంప్రెషన్, రూటింగ్ లేదా ప్రాంప్ట్ క్యాష్ను ఆన్ లేదా ఆఫ్ **చేయదు**.

## మోడ్లు

| మోడ్                         | OmniRoute చేసే పని                                                                                                               | ఎప్పుడు ఉపయోగించాలి                                                                                                                                                                     |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`passthrough`** (డిఫాల్ట్) | క్లయింట్ ఫీల్డ్లను మార్చకుండా ఉంచుతుంది (`reasoning`, `reasoning_effort`, Claude `thinking`, Gemini `thinking_config` మొదలైనవి). | **Codex / Desktop / ఎఫర్ట్ + రీజనింగ్ సారాంశాలను నియంత్రించాల్సిన ఏ క్లయింట్కైనా.** క్లయింట్ `reasoning.summary`ని అభ్యర్థించినప్పుడు కనిపించే థింకింగ్ ప్యానెల్లకు ఇది అవసరం.          |
| **`auto`**                   | అప్స్ట్రీమ్కు పంపే ముందు రిక్వెస్ట్ బాడీ నుండి అన్ని థింకింగ్/రీజనింగ్ ఫీల్డ్లను **తొలగిస్తుంది**.                               | మీరు ఉద్దేశపూర్వకంగా **ప్రొవైడర్** డిఫాల్ట్లను నిర్ణయించాలని కోరుకున్నప్పుడు మరియు క్లయింట్-నియంత్రిత థింకింగ్ అవసరం లేనప్పుడు మాత్రమే. ఇది “థింకింగ్ను ఆటోమేటిక్గా చూపించడం” **కాదు**. |
| **`custom`**                 | ప్రతి రిక్వెస్ట్ను స్థిరమైన థింకింగ్ టోకెన్ బడ్జెట్తో ఓవర్రైట్ చేస్తుంది.                                                        | మొత్తం ట్రాఫిక్లో థింకింగ్ టోకెన్లకు కఠిన పరిమితి.                                                                                                                                      |
| **`adaptive`**               | మెసేజ్ల సంఖ్య, టూల్లు మరియు ప్రాంప్ట్ పొడవు ఆధారంగా బేస్ ఎఫర్ట్ నుండి బడ్జెట్ను స్కేల్ చేస్తుంది.                                | క్లయింట్ ఉద్దేశాన్ని పూర్తిగా తొలగించకుండా సాఫ్ట్ టోకెన్ నియంత్రణ.                                                                                                                      |

### `auto` ఏమి తొలగిస్తుంది

మోడ్ `auto`గా ఉన్నప్పుడు, `stripThinkingConfig()` వీటితో సహా పలు అంశాలను తొలగిస్తుంది:

- OpenAI / Responses: `reasoning`, `reasoning_effort`
- Claude: `thinking`, అలాగే ఉన్నప్పుడు `output_config.effort`
- Gemini: `generationConfig.thinking_config` / `thinkingConfig`

ఒక క్లయింట్ (ఉదా. Codex Desktop) `reasoning: { effort: "ultra", summary: "detailed" }`ను పంపితే, **auto ఆ ఆబ్జెక్ట్ను తొలగిస్తుంది**. అప్స్ట్రీమ్ ఇప్పటికీ కొన్ని రీజనింగ్ టోకెన్లకు బిల్లు విధించవచ్చు, కానీ తరచుగా **ఖాళీ లేదా ఎన్క్రిప్ట్ చేసినవి మాత్రమే** ఉన్న రీజనింగ్ ఐటమ్లను తిరిగి పంపుతుంది — అందువల్ల UIలో ఉపయోగకరమైన థింకింగ్ స్ట్రీమ్ కనిపించదు.

## ఇది **ఏమి కాదు**

| ఫీచర్                                        | సంబంధం                                                                                                                                  |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| **కంప్రెషన్** (Caveman, RTK, stacked, …)     | ప్రత్యేక పైప్లైన్. ప్రతి థింకింగ్-బడ్జెట్ మోడ్లో పనిచేస్తుంది.                                                                          |
| **ప్రాంప్ట్ / సెమాంటిక్ క్యాష్**             | ప్రత్యేకమైనది. థింకింగ్-బడ్జెట్ మోడ్ దీనిపై ప్రభావం చూపదు.                                                                              |
| **కాంబో రూటింగ్ / ఫాల్బ్యాక్లు**             | ప్రత్యేకమైనవి. ప్రభావితం కావు.                                                                                                          |
| **API-కీ టోకెన్ పరిమితులు / వ్యయ బడ్జెట్లు** | ప్రత్యేకమైనవి. ప్రభావితం కావు.                                                                                                          |
| **రీజనింగ్ రీప్లే క్యాష్**                   | కఠినమైన ప్రొవైడర్ల కోసం మల్టీ-టర్న్ రీ-ఇంజెక్ట్ (DeepSeek, Kimi, Qwen-thinking, …). ఇది Desktop “థింకింగ్ను చూపించడం”తో సమానం కాదు.     |
| **`encrypted_content`ను డీక్రిప్ట్ చేయడం**   | **అసాధ్యం.** OpenAI/Codex ప్రైవేట్ రీజనింగ్ బ్లాబ్లు అపారదర్శకమైనవి. OmniRoute వాటిని ఎప్పుడూ డీక్రిప్ట్ చేయదు (#7095 / #7176 / #7304). |

## కనిపించే ఆలోచనా ప్రక్రియ (Codex / Responses క్లయింట్లు)

ఒక క్లయింట్ ఆలోచనా ప్రక్రియ టెక్స్ట్ను చూపించాలంటే, కింది **అన్ని** అవసరం:

1. Thinking Budget మోడ్ = **`passthrough`** (లేదా మీరు ఉపయోగించే మార్గానికి సంబంధించిన సారాంశ అభ్యర్థనలను తగినంత యథాతథంగా ఉంచే custom/adaptive).
2. క్లయింట్ సారాంశాన్ని అభ్యర్థించాలి, ఉదా. Codex `model_reasoning_summary = "detailed"` / `auto` (`none` కాదు).
3. అప్స్ట్రీమ్ వాస్తవంగా `response.reasoning_summary_text.*`ను స్ట్రీమ్ చేయాలి (లేదా ఐటెమ్లో ఖాళీ కాని `reasoning.summary` ఉండాలి).

మీకు “ఎన్క్రిప్ట్ చేసిన ప్రైవేట్ ఆలోచనా ప్రక్రియ” మాత్రమే లభిస్తే, కారణం వీటిలో ఒకటి:

- మోడ్ **`auto`**గా ఉంది (క్లయింట్ అభ్యర్థన తొలగించబడింది), లేదా
- అప్స్ట్రీమ్ సారాంశ టెక్స్ట్ లేకుండా `encrypted_content`ను తిరిగి ఇచ్చింది (ప్రొవైడర్ పరిమితి; OmniRoute ప్లేస్హోల్డర్ను మాత్రమే చూపించగలదు, ప్లెయిన్టెక్స్ట్ను కాదు).

## API ఉదాహరణలు

```bash
# చదవండి
curl -sS https://localhost:20128/api/settings/thinking-budget \
  -H "Authorization: Bearer $OMNIROUTE_TOKEN"

# Codex / Desktopలో ఆలోచనా ప్రక్రియ కనిపించడానికి సిఫార్సు చేయబడింది
curl -sS -X PUT https://localhost:20128/api/settings/thinking-budget \
  -H "Authorization: Bearer $OMNIROUTE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"mode":"passthrough","customBudget":10240,"effortLevel":"medium"}'
```

స్కీమా (`updateThinkingBudgetSchema`): `mode` ∈ `passthrough|auto|custom|adaptive`; ఐచ్ఛికంగా `customBudget`, `effortLevel`, `baseBudget`, `complexityMultiplier`.

### నిల్వ / పునఃప్రారంభం

విలువ సెట్టింగ్ల కీ `thinkingBudget` కింద నిల్వ చేయబడుతుంది మరియు ప్రాసెస్ ప్రారంభంలో (`hydrateThinkingBudgetConfig`) లోడ్ చేయబడుతుంది. DB లేదా కొన్ని API-యేతర మార్గాల ద్వారా మార్చిన తర్వాత, ఇన్-మెమరీ సింగిల్టన్ డిస్క్తో సరిపోలేలా **OmniRoute ప్రాసెస్ను పునఃప్రారంభించండి**.

## ఆపరేటర్ చెక్లిస్ట్

- [ ] Codex / Desktop వినియోగదారులు: మోడ్ = **passthrough**
- [ ] ఆలోచనా ప్రక్రియను తొలగించడం ద్వారా కాకుండా, **సందేశాలపై** టోకెన్లను ఆదా చేయాలనుకుంటే కంప్రెషన్ను ప్రారంభంగానే ఉంచండి
- [ ] `auto` “మరింత ఆలోచనా ప్రక్రియను చూపిస్తుంది” అని ఆశించవద్దు
- [ ] ఎన్క్రిప్ట్ చేసిన సారాంశాలు మాత్రమే రావడం అనేది **ప్రొవైడర్** ప్రవర్తన; passthrough వాటిని డీక్రిప్ట్ చేయలేదు
