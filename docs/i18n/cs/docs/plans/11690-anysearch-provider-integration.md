## 1. Skutečný stav služby (oficiální dokumentace, křížově ověřeno)

- Základní URL: `https://api.anysearch.com` (REST) + `POST /mcp` (MCP, JSON-RPC 2.0).
- `POST /v1/search` – parametry: `query` (povinný), `max_results` (1–10, výchozí 10), `tag` (vertikální směrování `{domain}.{sub_domain}`), `zone` (cn/intl), `language`, `params` (strukturovaná pole vertikály), `format` (json/markdown).
- `GET /v1/sub-domains?domain=...` – katalog funkcí, NEZAPOČÍTÁVÁ se do kvóty.
- `POST /v1/extract` – načte/extrahuje `{url, title, content}`; striktní tělo JSON, limit 16 KiB.
- `POST /v1/auth/email/register` – registrace jediným voláním, vrací jednorázový klíč v prostém textu `as_sk_...`.
- Autentizace: volitelná pomocí `Authorization: Bearer <as_sk_...>`; anonymní přístup je omezen limity pro jednotlivé IP adresy a čerpá denní bezplatnou kvótu; neplatný klíč vrací 401/403 BEZ tichého přepnutí na anonymní přístup.
- Bezplatná úroveň: 1000 požadavků/den, 20 QPS na klíč. Placená úroveň: cena nestanovena (již brzy).
- Obálka odpovědi: úspěch `{code: 0, message: "success", request_id, data}`; selhání `{code: -1, message}`. Chyby autentizace/kvóty neobsahují strukturovaný `error_code` (signálem je text zprávy); chyby specifické pro extrakci `error_code` obsahují (`invalid_extract_url`, `extract_failed`). Odpověď 429 neobsahuje hlavičku `Retry-After`.

## 3. Rozhodnutí (všechna přijata 2026-08-26)

1. **Strategie směrování: `fallbackOnly`.** Odůvodnění: bezplatný poskytovatel s náklady 0 nesmí nikdy dominovat automatickému směrování podle nákladů; explicitní výběr a návrat při převzetí služeb při selhání zůstávají beze změny. Precedent: začleněná položka xquik.
2. **Rozsah: webSearch + webFetch prostřednictvím `POST /v1/extract` ve v1.** V souladu s mentálním modelem dvojí funkcionality tavily/exa. Vertikální rozhraní (`tag`, `sub-domains`, `batch_search`) zůstávají mimo rozsah — pro vertikální parametry dnes neexistuje žádná IR.
3. **Zobrazení kvóty: `freeMonthlyQuota: 0`** (konzervativní zobrazení ve stylu xquik). Skutečný limit (1000 požadavků/den, denní obnovení) je místo toho uveden v textu `authHint` katalogu uživatelského rozhraní. Odůvodnění: zobrazení kvóty musí odpovídat způsobu jejího obnovování; převod denního limitu na měsíční ekvivalent (30000) je falešný příslib, který uživatelské rozhraní nemůže dodržet.
4. **searchTypes: pouze `["web"]`.** Neexistují žádné veřejné důkazy o vertikále pro zprávy/obrázky v API AnySearch; brány integrující API bez zdokumentované vertikály (např. Google Custom Search) zpřístupňují pouze web namísto tichého mapování news -> web.
5. **Strategie klíčů:** provoz bez klíče funguje; neplatný klíč vrátí 401/403 a nikdy není bez upozornění nahrazen anonymním přístupem (odpovídá kontraktu upstreamu).
6. **Záměrně vynecháno:** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (zachytávání chatu nadále využívá firecrawl/jina/tavily); `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (anonymní vzdálené koncové body sdílejí jeden fond omezený podle IP adresy pro každou výstupní IP adresu, takže extrakce bez klíče je volitelná, nikoli kandidát pro automatické směrování); `QUOTA_STATUS_PROVIDERS` (AnySearch signalizuje kvótu prostřednictvím 429/obálky, nikoli stavem 402/403).
