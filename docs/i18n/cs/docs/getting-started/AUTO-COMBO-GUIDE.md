> **TL;DR**: Nastavte svůj model na `auto` a OmniRoute automaticky vybere nejlepšího poskytovatele AI pro každý požadavek. Není nutná žádná konfigurace.

---

## Co to dělá

Místo výběru konkrétního modelu AI (například GPT-4o nebo Claude) můžete nechat OmniRoute, aby pro každý požadavek **automaticky vybral ten nejlepší**. Zohledňuje:

- **Stav** — Funguje poskytovatel právě teď?
- **Rychlost** — Jak je rychlý?
- **Cena** — Kolik stojí?
- **Kvalita** — Je vhodný pro tento typ úlohy?
- **Kapacita** — Zbývá mu dostupná kvóta?

OmniRoute ohodnotí všechny vaše připojené poskytovatele a vybere toho nejlepšího. Pokud požadavek selže, automaticky vyzkouší dalšího.

---

## Rychlý začátek

**Krok 1**: Nastavte svůj model na `auto` ve svém IDE nebo CLI:

```
model: "auto"
```

**Krok 2**: To je vše! O zbytek se postará OmniRoute.

**Krok 3** (volitelné): Pro konkrétní úlohy použijte variantu:

```
model: "auto/coding"    # Nejlepší pro kód
model: "auto/fast"      # Nejrychlejší odpověď
model: "auto/cheap"     # Nejlevnější možnost
```

---

## Které „auto“ mám použít?

| Pokud chcete...          | Použijte       | Nejvhodnější pro                 | Jak to funguje                              |
| ------------------------ | -------------- | -------------------------------- | ------------------------------------------- |
| **Celkově nejlepší**     | `auto`         | Obecné otázky, chat              | Vyvažuje rychlost, cenu a kvalitu           |
| **Nejlepší kód**         | `auto/coding`  | Psaní kódu, ladění               | Vybírá modely vhodné pro programovací úlohy |
| **Nejrychlejší odpověď** | `auto/fast`    | Rychlé odpovědi, nízká latence   | Upřednostňuje rychlost před vším ostatním   |
| **Nejlevnější možnost**  | `auto/cheap`   | Úsporu peněz                     | Vybírá nejlevnějšího poskytovatele          |
| **Nejchytřejší model**   | `auto/smart`   | Složité úlohy                    | Upřednostňuje kvalitu + zkoumá nové modely  |
| **Nejdostupnější**       | `auto/offline` | Když jsou poskytovatelé vytížení | Vybírá poskytovatele s největší kapacitou   |

### Příklady

```bash
# Obecný chat — vyvážený
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Ahoj!"}]}'

# Generování kódu — důraz na kvalitu
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/coding","messages":[{"role":"user","content":"Napiš funkci v Pythonu"}]}'

# Rychlá odpověď — důraz na rychlost
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/fast","messages":[{"role":"user","content":"Kolik je 2+2?"}]}'
```

## Jak to funguje (jednoduchá verze)

Když odešlete požadavek s `model: "auto"`, OmniRoute:

1. **Projde všechny vaše připojené poskytovatele** — Každého poskytovatele, kterého jste přidali (OpenAI, Anthropic, Google atd.)
2. **Každého ohodnotí**, přičemž mimo jiné zvažuje:
   - Funguje? (stav)
   - Má dostupnou kapacitu? (kvóta)
   - Kolik stojí? (cena)
   - Jak je rychlý? (rychlost)
   - Je vhodný pro tuto úlohu? (kvalita)
3. **Vybere toho nejlepšího** — Poskytovatel s nejvyšším skóre obdrží váš požadavek
4. **Automaticky se zotaví** — Pokud požadavek selže, OmniRoute automaticky vyzkouší dalšího

### Systém hodnocení

Každý poskytovatel získá skóre od 0 do 1. Čím vyšší je skóre, tím je vhodnější.

| Faktor             | Váha | Co znamená                                   |
| ------------------ | ---- | -------------------------------------------- |
| Stav               | 20%  | Funguje poskytovatel? (stav jističe)         |
| Kvóta              | 15%  | Zbývá mu dostupná kapacita?                  |
| Cena               | 15%  | Jak je drahý? (levnější = vyšší skóre)       |
| Rychlost           | 12%  | Jak je rychlý? (nižší latence = vyšší skóre) |
| Vhodnost pro úlohu | 8%   | Je vhodný pro tento typ úlohy?               |
| Stabilita          | 5%   | Je konzistentní? (nízká míra chybovosti)     |
| Úroveň             | 5%   | Úroveň účtu (Ultra > Pro > Free)             |
| Ostatní            | 20%  | Afinita kontextu, hustota připojení atd.     |

### Jak varianty mění hodnocení

Každá varianta používá jiné váhy:

| Varianta       | Upřednostňuje     | Klíčové váhy                    |
| -------------- | ----------------- | ------------------------------- |
| `auto`         | Vyváženost        | health=20%, quota=15%, cost=15% |
| `auto/coding`  | Kvalitu           | taskFit=37%, stability=15%      |
| `auto/fast`    | Rychlost          | latency=32%, health=28%         |
| `auto/cheap`   | Cenu              | cost=37%                        |
| `auto/smart`   | Kvalitu + průzkum | taskFit=37%, exploration=10%    |
| `auto/offline` | Kapacitu          | quota=37%, health=28%           |

## Jak řeší selhání

OmniRoute má **tři vrstvy ochrany**:

### 1. Automatický přechod na záložního poskytovatele

Pokud nejlepší poskytovatel selže, OmniRoute automaticky vyzkouší dalšího. Nemusíte dělat nic.

### 2. Automatické zotavení

Pokud poskytovatel opakovaně selhává:

- **Skóre < 0.2** → Vyloučen na 5 minut
- **Jistič je otevřený** → Automaticky vyloučen
- **Více než 50 % poskytovatelů je nedostupných** → Režim incidentu (bez průzkumu)

### 3. Nouzový záložní poskytovatel

Pokud selžou všichni poskytovatelé, OmniRoute jako poslední možnost přesměruje požadavky ke stabilním bezplatným poskytovatelům (například Kiro nebo Qoder).

---

## Podpora více účtů

Pokud máte více účtů u stejného poskytovatele (např. dva klíče OpenAI), OmniRoute považuje každý z nich za **samostatného kandidáta**. To znamená:

- Účet A má zbývající kvótu → použít jej
- Účet B má omezenou frekvenci požadavků → přeskočit jej
- Účet C je levnější → upřednostnit jej

Každý účet je hodnocen nezávisle podle vlastní dostupnosti, kvóty a rychlosti.

---

## Průzkum pomocí algoritmu bandit

OmniRoute občas **prozkoumává** nové poskytovatele, aby našel lepší možnosti:

- **Výchozí nastavení**: 5 % požadavků směřuje k náhodným poskytovatelům
- **Auto/smart**: 10% míra průzkumu
- **Vypnuto**, pokud je více než 50 % poskytovatelů v nevyhovujícím stavu

OmniRoute se tak může učit, kteří poskytovatelé nejlépe vyhovují vašim způsobům používání.

## Časté otázky

### „Vybere vždy nejdražší model?“

**Ne.** Cena ve výchozím nastavení představuje pouze 15 % skóre. Levný, rychlý a spolehlivý poskytovatel může překonat dražšího. Pokud chcete náklady upřednostnit ještě více, použijte `auto/cheap`.

### „Co když dojde k výpadku poskytovatele?“

OmniRoute jej automaticky přeskočí a vyzkouší dalšího. Pokud poskytovatel opakovaně selhává, je dočasně vyloučen (na 5–30 minut). Nemusíte dělat nic.

### „Mohu zjistit, který poskytovatel byl použit?“

Zkontrolujte hlavičky odpovědi — OmniRoute v každé odpovědi uvádí použitého poskytovatele a model.

### „Učí se z mého používání?“

Ano! Systém hodnocení využívá historická data (latenci, míru chybovosti a úspěšnosti), aby se postupem času rozhodoval lépe.

### „Jaký je rozdíl mezi `auto` a `auto/smart`?“

- `auto` — Vyvážené nastavení, 5% průzkum
- `auto/smart` — Důraz na kvalitu (stejné váhy jako u `auto/coding`), 10% průzkum

Použijte `auto/smart`, pokud chcete nejlepší kvalitu a nevadí vám občasný průzkum.

### „Mohu vynutit konkrétního poskytovatele?“

Ano! Místo `auto` použijte kombinaci se strategií `priority` a poté odešlete **přesný název** kombinace v poli `model` (např. `model: "my-combo"` — nikoli `auto`). Podrobnosti najdete v [technické referenci](../routing/AUTO-COMBO.md).

### „Jak se to liší od cyklického přidělování?“

Cyklické přidělování prochází poskytovatele v daném pořadí. Automatická kombinace **ohodnotí každého poskytovatele** a vybere toho nejlepšího. Je chytřejší — zohledňuje dostupnost, rychlost, cenu a kvalitu.
