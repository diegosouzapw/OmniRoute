> **Zdroj:** `src/lib/{a2a,acp,cloudAgent}/`, `src/app/api/{a2a,acp,cloud}/`, `src/app/api/v1/agents/`
> **Poslední aktualizace:** 2026-06-28 — v3.8.40

OmniRoute nabízí tři různá rozhraní související s agenty. Na první pohled vypadají podobně, ale řeší odlišné problémy. Tato stránka vám pomůže vybrat to správné.

## Stručně

| Rozhraní                     | Nejvhodnější použití                                                                                                                                      | Transport                      | Standard                        |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------ | ------------------------------- |
| **A2A — Agent-to-Agent**     | Spolupráce mezi agenty s partnerskými agenty, kteří používají protokol A2A                                                                                | JSON-RPC 2.0 přes HTTP         | A2A v0.3 (otevřená specifikace) |
| **ACP — registr CLI agentů** | Zjišťování / registrace / spouštění CLI agentů pro programování nainstalovaných na počítači uživatele (Cursor, Cline, Codex CLI, Claude Code, Aider atd.) | HTTP REST                      | Specifické pro OmniRoute        |
| **Cloudoví agenti**          | Zadávání dlouhotrvajících programovacích úloh externím cloudovým službám (Codex Cloud, Devin, Jules, Cursor Cloud)                                        | HTTP REST + úlohy uložené v DB | Specifické pro OmniRoute        |

Všechna tři rozhraní jsou nezávislá — můžete si vybrat libovolnou podmnožinu.

## Rozhodovací strom

```
Potřebujete, aby cloudová služba vykonávala práci mimo tento počítač (Codex Cloud / Cursor Cloud / Devin / Jules)?
├─ ANO → Cloudoví agenti (POST /api/v1/agents/tasks)
└─ NE → Pokračujte
    │
    Máte partnerského agenta, který používá A2A a chce spolupracovat?
    ├─ ANO → A2A (POST /a2a)
    └─ NE → Pokračujte
        │
        Potřebujete vypsat / nakonfigurovat lokálně nainstalované CLI agenty pro programování?
        ├─ ANO → ACP (GET /api/acp/agents)
        └─ NE → Použijte běžné /v1/chat/completions
```

## 1. A2A — Agent-to-Agent

**Specifikace:** [A2A v0.3](https://a2a-protocol.org)
**Koncový bod OmniRoute:** `POST /a2a` (JSON-RPC 2.0)
**Karta agenta:** `GET /.well-known/agent.json`

### Kdy použít

- Při vytváření systému s více agenty, ve kterém je OmniRoute jedním z partnerských agentů
- Při zpřístupnění směrovací inteligence OmniRoute (inteligentní směrování, správa kvót atd.) agentům ve frameworkách, jako je Google ADK, nebo v obecných sítích agentů
- Při zapouzdření OmniRoute za standardním rozhraním pro zjišťování a vyvolávání

### Metody

- `message/send` — odešle zprávu a přijme synchronní odpověď
- `message/stream` — odešle zprávu a přijímá události průběhu streamované přes SSE
- `tasks/get` — načte úlohu podle ID
- `tasks/cancel` — zruší spuštěnou úlohu

### Vestavěné dovednosti (6)

- `smart-routing` — směruje prompt přes optimální kombinaci
- `quota-management` — hlásí stav kvót jednotlivých poskytovatelů
- `provider-discovery` — vypíše nainstalované poskytovatele a jejich možnosti
- `cost-analysis` — odhadne náklady na požadavek nebo konverzaci
- `health-report` — agreguje stav jističe, doby vychladnutí a uzamčení pro jednotlivé poskytovatele
- `list-capabilities` — vypíše dostupné dovednosti agenta a metadata

### Podrobnosti

Podrobnosti o transportu, struktuře karty agenta, konfiguraci TTL úloh a šabloně pro přidávání nových dovedností najdete v dokumentu [A2A-SERVER.md](./A2A-SERVER.md).

## 2. ACP — registr agentů CLI

**Endpoint OmniRoute:** `GET /api/acp/agents`
**Zdroj:** `src/lib/acp/{index,manager,registry}.ts`

### Co to je

ACP je **místní inventář agentů CLI** v OmniRoute. Zjišťuje, která programátorská CLI jsou na hostiteli nainstalována (Cursor, Cline, Claude Code, Codex CLI, Continue atd.), zjišťuje jejich verze a zpřístupňuje je řídicímu panelu, aby uživatel mohl každé CLI nastavit tak, aby směřovalo na OmniRoute.

NEJDE o externí protokol — je to interní registr, který zajišťuje fungování uživatelského rozhraní „Nástroje CLI“ a sledování otisků CLI (viz [CLI-TOOLS.md](../reference/CLI-TOOLS.md)).

### Co dělá

- Vyhledává na hostiteli nainstalované binární soubory CLI (používá `which` / `where` podle operačního systému)
- Zjišťuje verzi každého CLI (volá `<bin> --version`)
- Volitelně přijímá uživatelsky definované vlastní agenty (cesta k binárnímu souboru + příkaz pro zjištění verze + argumenty spuštění)
- Ukládá vlastní agenty v nastavení
- Vrací sjednocený seznam řídicímu panelu

### REST API

| Endpoint          | Metoda | Popis                                                           | Ověření  |
| ----------------- | ------ | --------------------------------------------------------------- | -------- |
| `/api/acp/agents` | GET    | Vypíše zjištěné + vlastní agenty (počty nainstalovaných/celkem) | Klíč API |
| `/api/acp/agents` | POST   | Přidá/aktualizuje/odebere vlastního agenta (akce určená v těle) | Klíč API |

Struktura těla požadavku POST (`customAgentBodySchema` v `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Případy použití

- Stránka „Nástroje CLI“ v řídicím panelu zobrazuje nainstalované nástroje a pomáhá každý z nich nasměrovat na OmniRoute
- Vlastní agenti umožňují pokročilým uživatelům registrovat interní/proprietární CLI, která OmniRoute ve výchozím nastavení nezná
- Výsledek detekce slouží jako zdroj pro matici otisků `cli-tools`

### Kdy ACP NEPOUŽÍVAT

- ACP úlohy _nespouští_. Pouze zjišťuje a konfiguruje CLI. Chcete-li CLI skutečně vyvolat, spusťte jej sami s proměnnými prostředí poskytovanými OmniRoute (`OPENAI_BASE_URL`, `OPENAI_API_KEY` atd.).

## 3. Cloudoví agenti

**Endpointy OmniRoute:** `/api/v1/agents/tasks/*` (životní cyklus) + `/api/cloud/*` (podpůrná infrastruktura)
**Zdroj:** `src/lib/cloudAgent/`

### Co to je

Jednotné rozhraní nad cloudovými programátorskými agenty třetích stran. Odešlete zadání + URL repozitáře, OmniRoute požadavek předá správnému cloudovému agentovi, průběžně zjišťuje stav a vrátí výsledky.

### Podporovaní agenti (3, všichni potvrzeni v `src/lib/cloudAgent/agents/`)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### Životní cyklus

```
POST /api/v1/agents/tasks
  → BaseAgent.createTask() pro každou třídu agenta
  → externí služba zahájí práci
  → v databázi se vytvoří řádek úlohy (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → odložená synchronizace stavu od poskytovatele
  → vrátí aktuální stav + plán + protokol aktivit
  ↓
POST /api/v1/agents/tasks/[id]   (akce: "approve" | "message" | "cancel")
  → předá požadavek poskytovateli (nebo úlohu místně označí jako zrušenou)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → místní zrušení
```

### Ověření

⚠️ **Všechny endpointy `/api/v1/agents/tasks/*` vyžadují ověření pro správu** (commit `588a0333`). Volající používající pouze token Bearer dostávají od verze v3.8.0 odpověď 401.

### Podrobnosti

Podrobnosti o kontraktu `CloudAgentBase`, specifikách jednotlivých agentů, schématech a endpointech pro předávání přihlašovacích údajů najdete v dokumentu [CLOUD_AGENT.md](./CLOUD_AGENT.md).

## Srovnání: A2A vs. cloudoví agenti

Obě řešení podporují „dlouhotrvající úlohy“, ale na různých vrstvách:

| Aspekt                | A2A                                                                                                     | Cloudoví agenti                                   |
| --------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| Standard              | Otevřený standard A2A v0.3                                                                              | Specifické pro OmniRoute                          |
| Kde probíhají výpočty | Uvnitř OmniRoute (používá nakonfigurované kombinace)                                                    | Externě (servery Codex / Devin / Jules)           |
| Doba trvání úlohy     | Výchozí TTL 5 min (lze nakonfigurovat v `TaskManager`)                                                  | Minuty až hodiny                                  |
| Zohlednění repozitáře | Ne (předává pouze prompty)                                                                              | Ano (URL repozitáře + větev)                      |
| Případ použití        | Spolupráce mezi agenty, inteligentní směrování jako služba                                              | Delegování „implementace funkce X v repozitáři Y“ |
| Ověřování             | Volitelný `OMNIROUTE_API_KEY` pro `/a2a`; správcovské ověřování pro pomocné REST endpointy `/api/a2a/*` | Vždy správcovské ověřování                        |

## Příklady integrace

### Zjištění možností A2A systému OmniRoute

```bash
curl http://localhost:20128/.well-known/agent.json
```

Vrátí kartu agenta se všemi 6 dovednostmi, transporty a verzí.

### Volání OmniRoute jako agenta A2A

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### Výpis nainstalovaných CLI agentů prostřednictvím ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Přidání vlastního CLI agenta

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### Odeslání úlohy cloudového agenta

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### Pravidelné zjišťování stavu cloudové úlohy

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## Kdy co použít

- **Frontend chatbota / kopilota** → `/v1/chat/completions` (kompatibilní s OpenAI — nejde o protokol agenta)
- **Spolupráce více agentů** → A2A
- **Výpis místních CLI v řídicím panelu** → ACP
- **Delegování dlouhotrvajících programátorských úloh cloudovým službám** → cloudoví agenti

```
                ┌─────────────────────┐
                │   Jádro OmniRoute   │
                └─────────────────────┘
                  ↑       ↑        ↑
        ┌─────────┘       │        └─────────┐

    ┌───────┐        ┌─────────┐       ┌────────────┐

                                        Devin, Jules
```
