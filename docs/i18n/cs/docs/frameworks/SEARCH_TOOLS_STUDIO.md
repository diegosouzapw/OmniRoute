## Přehled

Search Tools Studio transformuje `/dashboard/search-tools` ze základního prostředí pro experimentování s vyhledáváním na
Studio se třemi kartami, které sjednocuje webové vyhledávání, extrakci webového obsahu a porovnávání poskytovatelů vedle sebe.

```
┌ Nástroje vyhledávání ──────────────────────────────────────────────────┐
│ [🔍 Hledat] [📄 Extrahovat] [⚖ Porovnat]         142ms · $0.001  </>    │
│ ⓘ [Průvodce modalitami]                                                │
├──────────────────────────────────────────┬─────────────────────────────┤
│  {obsah aktivní karty}                   │ ─ Konfigurace               │
│                                          │ Poskytovatel [auto ∨]       │
│                                          │   🟢 Serper  $0.001         │
│                                          │   🟢 Tavily  $0.008         │
│                                          │   🔥 Firecrawl (načtení)    │
│                                          │ Typ    [web | news]         │
│                                          │ Celá stránka [ ] (extrakce) │
│                                          │ Formát [md|text|html]       │
│                                          │ Model přerazení [∨]         │
└──────────────────────────────────────────┴─────────────────────────────┘
```

## Karty

### Karta vyhledávání

Rozšiřuje stávající `SearchForm` + `ResultsPanel` + `RerankPanel` do podoby karty:

- Dotaz → výsledky (název, URL, úryvek, skóre relevance).
- Metadata poskytovatele v panelu Konfigurace (náklady, kvóta, stav).
- Sekce přerazení: výběr modelu pro přerazení, změna pořadí výsledků, zobrazení `positionDelta`.
- Prázdný stav s výzvou k akci, pokud nejsou nakonfigurováni žádní poskytovatelé vyhledávání.
- Historie vyhledávání prostřednictvím `SearchHistory.tsx`.
- Volá `POST /v1/search` (stávající koncový bod, beze změn).

### Karta extrakce

Nová karta pro extrakci obsahu z URL prostřednictvím `POST /v1/web/fetch` (vytvořeného v plánu 05):

- Vstup: URL + přepínač celé stránky + výběr formátu (markdown / text / HTML).
- Odeslání → načtení → vykreslení `ScrapeResult.tsx`.
- `ScrapeResult` vykresluje náhled markdownu + přepínač nezpracovaného obsahu.
- Limit: pokud je tělo odpovědi větší než **256 KB**, uživatelské rozhraní zobrazí `(zkráceno, zobrazit nezpracované)` a otevře nezpracovaný obsah v modálním okně Monaco (D21).
- Panel metadat: poskytovatel (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search), latence, náklady, velikost odpovědi, počet odkazů.
- Používá hook `useScrapeFetch.ts`.

### Karta porovnání

Spouští stejný dotaz/URL paralelně až u **4 poskytovatelů** (D22):

- Sloupce vedle sebe pro jednotlivé poskytovatele.
- Metriky: latence, náklady, počet výsledků, velikost odpovědi.
- Výpočet překryvu URL pro vyhledávání (počet sdílených URL oproti původnímu výsledku).
- Volá `POST /v1/search` (vyhledávání) nebo `POST /v1/web/fetch` (extrakce) pro každého poskytovatele.

## Panel konfigurace (sdílený)

`SearchToolsConfigPane.tsx` — vždy viditelný, sbalitelný.

| Pole            | Poznámky                                                                       |
| --------------- | ------------------------------------------------------------------------------ |
| Poskytovatel    | Rozbalovací seznam se stavovým odznakem (nakonfigurován / chybí / omezen)      |
| Typ             | `web` nebo `news` (pouze vyhledávání)                                          |
| Celá stránka    | Přepínač pro extrakci — načte celou stránku namísto prvního viditelného obsahu |
| Formát          | `markdown`, `text` nebo `html` (pouze extrakce)                                |
| Model přerazení | Volitelný model pro přerazení po vyhledávání                                   |
| Historie        | Sbalitelná sekce historie vyhledávání                                          |

## SearchConceptCard

`SearchConceptCard.tsx` — vždy viditelný sbalitelný akordeon. Vysvětluje:

| Koncept                       | Stručný popis                                                            |
| ----------------------------- | ------------------------------------------------------------------------ |
| **Vyhledávání**               | Načte seznam webových výsledků (název, URL, úryvek, skóre relevance)     |
| **Extrakce**                  | Extrahuje úplný obsah z URL (markdown, text nebo HTML)                   |
| **Porovnání**                 | Spustí stejný dotaz souběžně u N poskytovatelů                           |
| **Přeřazení**                 | Změní pořadí výsledků pomocí LLM pro zvýšení relevance vzhledem k dotazu |
| **Automaticky (nejlevnější)** | Automaticky vybere nejlevnějšího dostupného poskytovatele                |

## Katalog poskytovatelů

`ProviderCatalog.tsx` zpřístupňuje úplný seznam poskytovatelů z `GET /api/search/providers`
(rozšířený ve F4 o poskytovatele načítání):

| `kind` | `"search"` (20 poskytovatelů) nebo `"fetch"` (firecrawl, jina-reader, tavily-search, tinyfish, nimble-search, anysearch-search) |

Stav je **odvozen v okamžiku požadavku** na základě kontroly, zda existují přihlašovací údaje a zda
jsou všechny klíče právě ve fázi cooldownu.

## Export kódu

`ExportCodeModal` (importovaný z Playground Studio) + `codeExport.ts` generují
ukázky pro curl / Python / TypeScript pro volání `/v1/search` i `/v1/web/fetch`.
Zástupný symbol klíče API je vždy `$OMNIROUTE_API_KEY` (D11, sdílený s Playground Studio).

## Změny backendu

Pro tuto funkci byla potřeba pouze jedna změna backendu:

### Rozšířený endpoint `GET /api/search/providers`

Soubor `src/app/api/search/providers/route.ts` byl rozšířen tak, aby:

- Zahrnoval do pole všech 6 poskytovatelů načítání (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`).
- Přidal `kind: "search" | "fetch"` ke každé položce.
- Přidal `status: "configured" | "missing" | "rate_limited"` odvozený z aktuálního stavu přihlašovacích údajů.
- Zachoval zpětnou kompatibilitu — stávající pole (`id`, `name` atd.) zůstávají beze změny.

## Řešení problémů

| Příznak                                                  | Příčina                                   | Řešení                                                                                                |
| -------------------------------------------------------- | ----------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Karta Scrape zobrazuje „endpoint není dostupný“          | `/v1/web/fetch` není propojen             | Ověřte, že je plán 05 sloučen; zkontrolujte, zda existuje `src/app/api/v1/web/fetch/route.ts`         |
| Katalog poskytovatelů zobrazuje všechny jako „chybějící“ | Přihlašovací údaje nejsou nakonfigurovány | Přidejte přihlašovací údaje v `/dashboard/providers`                                                  |
| Obsah Scrape je zkrácen                                  | Odpověď překračuje limit 256 KB           | Očekávané chování (D21). Pro zobrazení celého obsahu použijte tlačítko „zobrazit nezpracovaný obsah“  |
| Karta Compare zobrazuje pouze 2 poskytovatele            | Je aktivní omezení frekvence požadavků    | Dva nebo více poskytovatelů může být ve fázi čekání — zkontrolujte stav poskytovatelů v panelu Config |
| „Size“ se v tabulce zobrazuje jako nezpracovaný klíč     | Chybějící klíč i18n                       | Ověřte, že v souboru lokalizace existuje `search.size`; znovu sestavte i18n                           |
