Kompletní průvodce instalací a konfigurací OmniRoute na virtuálním počítači (VPS) s doménou spravovanou prostřednictvím Cloudflare.

## Předpoklady

| Položka    | Minimum                   | Doporučeno       |
| ---------- | ------------------------- | ---------------- |
| **CPU**    | 1 vCPU                    | 2 vCPU           |
| **RAM**    | 1 GB                      | 2 GB             |
| **Disk**   | 10 GB SSD                 | 25 GB SSD        |
| **OS**     | Ubuntu 22.04 LTS          | Ubuntu 24.04 LTS |
| **Doména** | Registrovaná u Cloudflare | —                |
| **Docker** | Docker Engine 24+         | Docker 27+       |

**Testovaní poskytovatelé**: Akamai (Linode), DigitalOcean, Vultr, Hetzner, AWS Lightsail.

## 1. Konfigurace virtuálního počítače

### 1.1 Vytvoření instance

U preferovaného poskytovatele VPS:

- Zvolte Ubuntu 24.04 LTS
- Vyberte minimální tarif (1 vCPU / 1 GB RAM)
- Nastavte silné heslo uživatele root nebo nakonfigurujte SSH klíč
- Poznamenejte si **veřejnou IP adresu** (např. `203.0.113.10`)

### 1.2 Připojení přes SSH

```bash
ssh root@203.0.113.10
```

### 1.3 Aktualizace systému

```bash
apt update && apt upgrade -y
```

### 1.4 Instalace Dockeru

```bash
# Instalace závislostí
apt install -y ca-certificates curl gnupg

# Přidání oficiálního repozitáře Dockeru
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
chmod a+r /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $ (. /etc/os-release && echo "$VERSION_CODENAME") stable" | tee /etc/apt/sources.list.d/docker.list > /dev/null
apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

### 1.5 Instalace nginx

```bash
apt install -y nginx
```

### 1.6 Konfigurace firewallu (UFW)

```bash
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp    # SSH
ufw allow 80/tcp    # HTTP (přesměrování)
ufw allow 443/tcp   # HTTPS
ufw enable
```

> **Tip**: Pro maximální zabezpečení omezte porty 80 a 443 pouze na IP adresy Cloudflare. Viz část [Pokročilé zabezpečení](#advanced-security).

## 2. Instalace OmniRoute

### 2.1 Vytvoření konfiguračního adresáře

```bash
mkdir -p /opt/omniroute
```

### 2.2 Vytvoření souboru s proměnnými prostředí

```bash
cat > /opt/omniroute/.env << 'EOF'
# === Zabezpečení ===
JWT_SECRET=CHANGE-TO-A-UNIQUE-64-CHAR-SECRET-KEY
INITIAL_PASSWORD=YourSecurePassword123!
API_KEY_SECRET=REPLACE-WITH-ANOTHER-SECRET-KEY
STORAGE_ENCRYPTION_KEY=REPLACE-WITH-THIRD-SECRET-KEY
STORAGE_ENCRYPTION_KEY_VERSION=v1
MACHINE_ID_SALT=CHANGE-TO-A-UNIQUE-SALT
OMNIROUTE_WS_BRIDGE_SECRET=REPLACE-WITH-WS-BRIDGE-SECRET  # V produkčním prostředí POVINNÉ: používá jej WS bridge Codex Responses

# === Aplikace ===
PORT=20128
NODE_ENV=production
HOSTNAME=0.0.0.0
DATA_DIR=/app/data
APP_LOG_TO_FILE=true
AUTH_COOKIE_SECURE=true
REQUIRE_API_KEY=false

# === URL (změňte na svou doménu) ===
# Interní základní URL pro komunikaci mezi servery, plánované úlohy a požadavky na vlastní server.
BASE_URL=http://127.0.0.1:20128
# URL určená pro prohlížeč, používaná pro zpětná volání OAuth, odkazy na řídicí panel a generované veřejné URL.
NEXT_PUBLIC_BASE_URL=https://llms.seudominio.com
# Volitelné explicitní přepsání veřejného původu pro generované veřejné URL prostředků.
# OMNIROUTE_PUBLIC_BASE_URL=https://llms.seudominio.com

# === Cloudová synchronizace (volitelné) ===
# CLOUD_URL=https://cloud.omniroute.online
# NEXT_PUBLIC_CLOUD_URL=https://cloud.omniroute.online
EOF
```

> ⚠️ **DŮLEŽITÉ**: Vygenerujte jedinečné tajné klíče! Pro každý klíč použijte `openssl rand -hex 32`.

### 2.3 Spuštění kontejneru

```bash
docker pull diegosouzapw/omniroute:latest

docker run -d \
  --name omniroute \
  --restart unless-stopped \
  --env-file /opt/omniroute/.env \
  -p 20128:20128 \
  -v omniroute-data:/app/data \
  diegosouzapw/omniroute:latest
```

### 2.4 Ověření, že je kontejner spuštěný

```bash
docker ps | grep omniroute
docker logs omniroute --tail 20
```

Mělo by se zobrazit: `[DB] SQLite database ready` a `listening on port 20128`.

## 3. Konfigurace nginx (reverzní proxy)

### 3.1 Vygenerování SSL certifikátu (Cloudflare Origin)

V ovládacím panelu Cloudflare:

1. Přejděte do **SSL/TLS → Origin Server**
2. Klikněte na **Create Certificate**
3. Ponechte výchozí nastavení (15 let, \*.yourdomain.com)
4. Zkopírujte **Origin Certificate** a **Private Key**

```bash
mkdir -p /etc/nginx/ssl

# Vložte certifikát
nano /etc/nginx/ssl/origin.crt

# Vložte soukromý klíč
nano /etc/nginx/ssl/origin.key

chmod 600 /etc/nginx/ssl/origin.key
```

### 3.2 Konfigurace nginx

```bash
cat > /etc/nginx/sites-available/omniroute << 'NGINX'
# Výchozí server — blokuje přímý přístup přes IP adresu
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    listen 443 ssl default_server;
    listen [::]:443 ssl default_server;
    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    server_name _;
    return 444;
}

# OmniRoute — HTTPS
server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name llms.yourdomain.com;  # Změňte na svou doménu

    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    client_max_body_size 100M;

    location / {
        proxy_pass http://127.0.0.1:20128;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Podpora WebSocket
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # SSE (Server-Sent Events) — streamování odpovědí AI
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }
}

# Přesměrování HTTP → HTTPS
server {
    listen 80;
    listen [::]:80;
    server_name llms.yourdomain.com;
    return 301 https://$server_name$request_uri;
}
NGINX
```

Udržujte časové limity streamování reverzní proxy v souladu s proměnnými prostředí pro časové limity OmniRoute. Pokud zvýšíte
`FETCH_TIMEOUT_MS` / `STREAM_IDLE_TIMEOUT_MS`, zvyšte `proxy_read_timeout` / `proxy_send_timeout`
nad stejnou prahovou hodnotu.

OmniRoute používá `NEXT_PUBLIC_BASE_URL` jako kanonický veřejný počátek URL prohlížeče pro zpětná volání OAuth
a generované veřejné odkazy. Autentizované zápisy z ovládacího panelu používají požadavky stejného původu
spolu s ochranou CSRF vázanou na relaci, takže nevyžadují statickou veřejnou základní URL. Výše uvedené
hlavičky `X-Forwarded-*` jsou stále užitečnými metadaty směrování, ale nenahrazují
nastavení explicitní veřejné URL, pokud ji OAuth nebo generované odkazy pro prohlížeč potřebují. Proměnnou
`OMNIROUTE_TRUST_PROXY` povolte pouze v případě, že OmniRoute není přímo dostupný klientům a vaše proxy
odstraňuje a znovu sestavuje příchozí přeposílané hlavičky.

### 3.3 Povolení a otestování

```bash
# Odstraňte výchozí konfiguraci
rm -f /etc/nginx/sites-enabled/default

# Povolte OmniRoute
ln -sf /etc/nginx/sites-available/omniroute /etc/nginx/sites-enabled/omniroute

# Otestujte konfiguraci a znovu ji načtěte
nginx -t && systemctl reload nginx
```

## 4. Konfigurace DNS Cloudflare

### 4.1 Přidání záznamu DNS

V ovládacím panelu Cloudflare → DNS:

| Typ | Název  | Obsah                                    | Proxy         |
| --- | ------ | ---------------------------------------- | ------------- |
| A   | `llms` | `203.0.113.10` (IP virtuálního počítače) | ✅ Aktivováno |

### 4.2 Konfigurace SSL

V části **SSL/TLS → Overview**:

- Režim: **Full (Strict)**

V části **SSL/TLS → Edge Certificates**:

- Always Use HTTPS: ✅ Zapnuto
- Minimální verze TLS: TLS 1.2
- Automatic HTTPS Rewrites: ✅ Zapnuto

### 4.3 Testování

```bash
curl -sI https://llms.seudominio.com/health
# Mělo by vrátit HTTP/2 200
```

## Optimalizace pro nízkou paměť / malý VPS

Pro nasazení na malých instancích VPS (1 GB RAM nebo méně):

- **Vypněte služby na pozadí** — nastavením `OMNIROUTE_DISABLE_BACKGROUND_SERVICES=1` přeskočíte plánovač, server MCP a pravidelné úlohy údržby. Viz `docs/reference/ENVIRONMENT.md`.
- **Používejte režim WAL databáze SQLite** — ve výchozím nastavení je zapnutý a snižuje špičkovou spotřebu paměti při souběžném čtení.
- **Omezte haldu V8** — nastavte `OMNIROUTE_MEMORY_MB` (např. `512`), aby běhové prostředí nenastavilo limit vyšší, než umožňuje virtuální stroj. Viz `docs/reference/ENVIRONMENT.md`.
- **Řízení přijímání náročných požadavků se automaticky škáluje podle limitu haldy** -- po nastavení výše uvedené proměnné `OMNIROUTE_MEMORY_MB` se rozpočet bajtů pro příjem (`OMNIROUTE_CHAT_MAX_INFLIGHT_BYTES`) odvodí ze stejného limitu, takže virtuální stroj s omezenou pamětí automaticky získá nižší rozpočet pro souběžné požadavky bez dalšího ladění; nadbytečné požadavky obdrží opakovatelnou chybu `503` s hlavičkou `Retry-After`, místo aby soupeřily o paměť. Starší limit počtu požadavků `OMNIROUTE_CHAT_MAX_HEAVY_IN_FLIGHT` nastavte pouze v případě, že nad rámec tohoto mechanismu potřebujete pevný strop.
- **Nespouštějte `next build` na VPS** — sestavení proveďte lokálně a nasaďte samostatný výstup (`.next/standalone/`).
- **Monitorujte pomocí `top` / `free -m`** — OmniRoute na virtuálním stroji s 1 GB paměti obvykle v nečinnosti využívá 200–400 MB RSS.
