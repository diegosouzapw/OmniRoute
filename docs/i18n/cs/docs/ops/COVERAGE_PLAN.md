## Výchozí stav

| Diagnostická            | Pouze zdrojové soubory, bez testů a bez `open-sse`    |         68.16 % | 63.55 % | 64.06 % | Užitečné pouze k izolaci `src/**`                                 |

Doporučený výchozí stav je hodnota, kterou je třeba optimalizovat.

## Pravidla

- Cíle pokrytí se vztahují na zdrojové soubory, nikoli na `tests/**`.
- `open-sse/**` je součástí produktu a musí zůstat zahrnutý.
- Nový kód by neměl snižovat pokrytí v dotčených oblastech.
- Upřednostňujte testování chování a výsledků větví před detaily implementace.
- Pro `src/lib/db/**` upřednostňujte dočasné databáze SQLite a malé testovací datové sady před rozsáhlými mocky.

## Aktuální sada příkazů

- `npm run test:coverage`
  - Hlavní kontrola pokrytí zdrojového kódu pro sadu jednotkových testů
  - Generuje `text-summary`, `html`, `json-summary` a `lcov`
- `npm run coverage:report`
  - Podrobný report po jednotlivých souborech z posledního spuštění
- `npm run test:coverage:legacy`
  - Pouze pro historické porovnání

## Zásady postupného zpřísňování

Prahové hodnoty `npm run test:coverage` aktualizujte teprve poté, co projekt skutečně překročí další milník s dostatečnou rezervou.

**Aktuální limit:** `npm run test:coverage` vynucuje **60 příkazů / 60 řádků / 60 funkcí / 60 větví** (metrika byla nově nastavena ve fázi Quality-Gates 6A.1 — dřívější výchozí hodnota 82.58 % byla nadhodnocená, protože započítávala testovací soubory a nezahrnovala `open-sse`). Příkaz `test:coverage:legacy` zachovává pro historické porovnání původní metriku 50/50/50.

Pro jednorázové kontroly prahové hodnoty vůči nejnovější zprávě použijte:

```bash
node scripts/check/test-report-summary.mjs --threshold 75
```

Doporučená posloupnost zpřísňování (pořadí je `příkazy-řádky / větve / funkce`):

1. 55/60/55
2. 60/62/58
3. 65/64/62
4. 70/66/66
5. 75/70/72 <-- aktuální limit (75/70/75)
6. 80/75/78

Dalším cílem zpřísnění je `80/75/78`, jakmile se pokrytí větví udrží nad 78 % ve dvou po sobě jdoucích spuštěních.

## Známý nedostatek

Aktuální příkaz pro pokrytí měří hlavní sadu jednotkových testů pro Node a zahrnuje zdrojový kód, ke kterému se z ní přistupuje, včetně `open-sse`. Pokrytí z Vitestu zatím neslučuje do jediné sjednocené zprávy. Toto sloučení má smysl provést později, ale není překážkou pro zahájení růstu z 60 % na 80 %.
