Tento dokument zaznamenává implementační rozhodnutí pro
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854). Veřejné produkty jsou
reprezentovány jako čtyři rodiny poskytovatelů. Region je údaj připojení, nikoli samostatný produkt.

## Rozhodnutí

| Rodina poskytovatele                           | OmniRoute ID            | Globální region | Region Čína |
| ---------------------------------------------- | ----------------------- | --------------- | ----------- |
| Alibaba Cloud Model Studio (platba za využití) | `alibaba`               | Singapur        | Peking      |
| Alibaba Cloud Token Plan                       | `bailian-coding-plan`   | Singapur        | Peking      |
| Qwen Cloud (platba za využití)                 | `qwen-cloud`            | Globální        | Peking      |
| Qwen Cloud Token Plan                          | `qwen-cloud-token-plan` | Singapur        | Peking      |

Stávající ID `alibaba-cn` zůstává aliasem pro kompatibilitu za běhu pro uložená připojení, trasy
modelů, kombinace a historické využití. Jeho karta na řídicím panelu je sloučena s `alibaba`;
není vyžadován žádný přepis databáze.

Qwen Cloud s platbou za využití a Alibaba Cloud Model Studio v současnosti sdílejí běhové hostitele
kompatibilní s DashScope, zůstávají však samostatnými identitami poskytovatelů, protože uživatelé
získávají klíče a spravují účty prostřednictvím odlišných produktových rozhraní. Produkty Alibaba
a Qwen Cloud Token Plan používají odlišné rodiny koncových bodů, takže všechny čtyři produkty
zůstávají samostatnými ID poskytovatelů.

## Matice koncových bodů

| Rodina poskytovatele    | `global-sg`                                                              | `china-beijing`                                                      | Formát přenosu |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | -------------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI         |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic      |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI         |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI         |

Klíč API a koncový bod musí patřit ke stejnému produktu a regionu. Výběr regionu změní
přednastavený koncový bod používaný při ověřování i běžných požadavcích.

## Smlouva připojení

Nová připojení ukládají stabilní klíč regionu do `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

Povolené hodnoty jsou `global-sg` a `china-beijing`. Koncový bod je centrálně odvozen z ID
poskytovatele a regionu. Nepřednastavená hodnota `providerSpecificData.baseUrl` zůstává explicitním
přepsáním nastaveným operátorem a má přednost, zatímco staré uložené přednastavené adresy URL jsou
normalizovány zpět podle regionální matice.

Tím zůstává schéma připojení rozšiřitelné: do resolveru lze přidat další region, aniž by bylo nutné
vytvářet další kartu poskytovatele nebo měnit uložená ID poskytovatelů.

## Kompatibilita a postupné nasazení

1. Přidejte resolver regionálních endpointů a zachovejte aktuální globální výchozí hodnoty.
2. Použijte živé regionální zjišťování `/models` služby DashScope pro `alibaba`, jeho kompatibilní
   ID `alibaba-cn` a `qwen-cloud`. Jejich odpovědi nejprve projdou filtrem pro generování textu,
   protože obecný endpoint vrací také modely pro obrázky, video, zvuk, embeddingy a další modely,
   které nejsou určeny pro chat. `qwen-cloud` následně použije udržovaný seznam povolených modelů
   deklarovaný ve svém registru poskytovatelů. Alibaba Model Studio a Qwen Cloud si zachovávají
   samostatné spravované katalogy, přestože aktuálně sdílejí runtime hostitele.
3. Zaregistrujte `qwen-cloud-token-plan` s aktuálním seznamem povolených textových modelů plánu Token Plan.
4. Přidejte typovaný výběr regionu do dialogových oken pro přidání a úpravu připojení.
5. Skryjte duplicitní kartu `alibaba-cn` a zahrňte její existující připojení na stránku poskytovatele
   `alibaba`.
6. Zachovejte možnost vlastního přepsání endpointů pro pokročilá nasazení a nasazení specifická pro
   pracovní prostory.

Mediální modely plánu Token Plan zůstávají mimo katalog chatu, protože používají vyhrazené endpointy.
`wan2.7-image` a `wan2.7-image-pro` jsou registrovány v `open-sse/config/imageRegistry.ts`;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` a `happyhorse-1.1-r2v` jsou registrovány v
`open-sse/config/videoRegistry.ts`. Oba registry znovu používají identitu připojení
`qwen-cloud-token-plan` a její přihlašovací údaje specifické pro daný region.

Běžný Qwen Cloud má pod identitou `qwen-cloud` samostatné katalogy obrázků a videí s průběžnými
platbami podle využití. Jeho obrazové modely jsou `wan2.7-image-pro`, `wan2.7-image`,
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` a
`z-image-turbo`. Jeho video modely jsou `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`,
`happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`,
`wan2.7-r2v-2026-06-12` a `wan2.7-videoedit`. Tyto modely znovu používají pouze běžné připojení
`qwen-cloud` a regionální mediální endpoint DashScope. Registry plánu Token Plan a plateb podle
využití nedědí ani neslučují seznamy modelů toho druhého.

Identita `bailian-coding-plan` má také své vlastní seznamy povolených mediálních modelů:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` a `qwen-image-2.0-pro` pro generování
obrázků a dále
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` a `happyhorse-1.1-r2v` pro generování videa.
Používá pouze připojení Bailian Coding Plan a regionální endpoint Coding Plan. Její registry
obrázků a videí nedědí ani se neslučují s žádným z poskytovatelů Qwen Cloud.

Běžná identita `alibaba` má samostatné seznamy povolených obrazových a video modelů. Její obrazové
modely jsou `qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` a `wan2.6-t2i`. Její přidané video modely jsou `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` a `wan2.7-videoedit`. Tyto modely používají pouze připojení Alibaba Model
Studio a jeho vybraný regionální mediální endpoint; nejsou přidány do žádného registru Coding Plan
ani Qwen Cloud.

Katalog chatu Qwen Cloud Token Plan se řídí seznamem povolených textových modelů plánu Individual
s přesnou shodou řetězců:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` a
`deepseek-v4-pro`. Položky Wan a HappyHorse patří do samostatných API pro generování obrázků a videa.

Alibaba Token Plan zpřístupňuje stejných šest aktuálních ID modelů pro generování textu prostřednictvím
endpointu kompatibilního s Anthropic. Jeho možnost Singapur ukládá existující klíč regionu
`global-sg`; od rodin poskytovatelů, které region označují jako globální, se liší pouze popisek
zobrazený uživateli.

Běžný katalog chatu Qwen Cloud je záměrně užší než úplná živá odpověď s textovými modely. Jeho
udržovaný seznam povolených modelů se nachází v
`open-sse/config/providers/registry/qwen-cloud/index.ts`; živé zjišťování vrací pouze ID přítomná
jak v odpovědi upstreamu, tak v tomto seznamu registru.

Alibaba Model Studio používá stejné pravidlo živého průniku se svým nezávisle udržovaným seznamem
povolených modelů v `open-sse/config/providers/registry/alibaba/index.ts`. Kompatibilní poskytovatel
`alibaba-cn` tento katalog znovu používá, přičemž zjišťování směruje na pekingský endpoint.
