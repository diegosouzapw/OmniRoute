`copilot-m365-web` (alias `m365copilot`) odesílá chatovací požadavky ve formátu OpenAI prostřednictvím
ověřené relace Microsoft 365 Copilot BizChat v prohlížeči na adrese
`m365.cloud.microsoft/chat`. Jedná se o neoficiální integraci.

> **Začínáte s poskytovateli využívajícími webové cookies?**
>
> Než budete pokračovat podle tohoto průvodce pro konkrétního poskytovatele, přečtěte si **`docs/getting-started/WEB-COOKIE-GUIDE.md`**, kde najdete obecný postup nastavení, pokyny k ověřování, omezení a řešení problémů.
>
> **Důležité:** Přihlašovací údaj pro tohoto poskytovatele **není cookie**. Nekopírujte
> cookies z `m365.cloud.microsoft`. Přihlašovací údaj tvoří parametr dotazu URL WebSocketu
> a segment cesty, které lze získat na kartě Network ve vývojářských nástrojích.

## Předpoklady

- Účet Microsoft 365 s přístupem k BizChat na adrese `m365.cloud.microsoft/chat`
- Prohlížeč založený na Chromiu (Chrome, Edge) pro kontrolu WebSocketu ve vývojářských nástrojích
- Licence M365 Copilot (součást mnoha tarifů Microsoft 365 Business/Enterprise)

## Získání přihlašovacího údaje (metoda WebSocket)

1. Přihlaste se na adrese `https://m365.cloud.microsoft/chat` a zahajte konverzaci.
2. Otevřete **DevTools → Network**.
3. Filtrujte podle **WS** (WebSocket).
4. Klikněte na připojení Chathub WebSocket. Vyhledejte URL začínající na
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Z jeho **Request URL** zkopírujte:
   - Hodnotu parametru dotazu `access_token` (JWT s krátkou dobou platnosti).
   - Segment cesty Chathub za `/Chathub/` (např. `<oid>@<tenant>`).

Úplná URL má následující formát:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. V OmniRoute přejděte na **Providers → Add Provider**, vyberte **Microsoft 365 Copilot
   (BizChat)** a vložte přihlašovací údaj v následujícím formátu:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Klikněte na **Test Connection** a **Save**.

## Získání přihlašovacího údaje (import HAR)

Místo ručního kopírování hodnot z URL WebSocketu můžete exportovat soubor HAR
z vývojářských nástrojů:

1. Otevřete **DevTools → Network**.
2. Zahajte konverzaci v BizChat nebo v ní pokračujte (tím se aktivuje připojení WebSocket).
3. Klikněte pravým tlačítkem v panelu Network a vyberte **Save all as HAR with content**.
4. V dialogovém okně připojení poskytovatele v OmniRoute použijte tlačítko **Import .har file**.

OmniRoute prohledá soubor HAR, vyhledá URL Chathub WebSocketu, extrahuje
`access_token` a `chathubPath` a automaticky vyplní pole přihlašovacích údajů. Při
importu HAR se dekóduje doba vypršení platnosti JWT a zobrazí se zbývající doba platnosti tokenu.

> **Nikdy neukládejte skutečný export HAR, přístupový token ani obnovovací token do repozitáře.** Testovací
> a dokumentační hodnoty musí být vždy zástupné.

## Doba platnosti a obnovení tokenu

`access_token` má krátkou dobu platnosti (obvykle **~75 minut**). Po vypršení platnosti poskytovatel
ohlásí chybu připojení a přihlašovací údaj musíte získat znovu.

### Automatické obnovení pomocí `refreshToken`

Abyste nemuseli přihlašovací údaj získávat znovu ručně, můžete uložit obnovovací token Microsoftu v části
**Advanced Settings → providerSpecificData** daného připojení:

| Pole           | Popis                                                                     |
| -------------- | ------------------------------------------------------------------------- |
| `refreshToken` | Obnovovací token Microsoft OAuth pro rozsah `substrate.office.com/sydney` |
| `tier`         | `individual` (výchozí), `edu` nebo `enterprise`                           |

Obnovovací token získejte prostřednictvím toku s kódem zařízení Microsoftu nebo toku s autorizačním kódem
s rozsahem `substrate.office.com/sydney`. Pokud je nastaven `refreshToken`, OmniRoute
preventivně obnoví `access_token` před každým požadavkem, takže jej po každém vypršení platnosti přibližně po 75 minutách
nemusíte získávat znovu.

Pokud `refreshToken` není nastaven, musíte po každém vypršení platnosti přihlašovací údaj WebSocketu
získat znovu ručně.

### Výběr úrovně

| Úroveň       | Alias       | Varianta                    |
| ------------ | ----------- | --------------------------- |
| `individual` | _(výchozí)_ | Spotřebitelský M365 Copilot |
| `edu`        | `included`  | M365 Copilot pro vzdělávání |
| `enterprise` | `work`      | M365 Copilot pro práci      |

Nastavte úroveň v části **Advanced Settings → providerSpecificData → tier**. Úroveň ovlivňuje
směrování BizChat a přístup k modelům.

## Bezpečnostní model

- **Neoficiální integrace.** Tento poskytovatel využívá reverzní inženýrství protokolu
  BizChat WebSocket. Pokud Microsoft změní koncový bod, může integrace bez upozornění přestat fungovat.
- Příznak `subscriptionRisk: true` vyjadřuje, že integrace závisí na
  nezdokumentovaném koncovém bodu. Omezení účtu jsou možná, ale nebyla potvrzena.
- Přístupový token je JWT s krátkou platností. Zacházejte s ním jako s heslem:
  neukládejte jej do repozitáře, nezaznamenávejte jej do protokolů ani jej nesdílejte.
- Obnovovací token poskytuje dlouhodobý přístup k rozhraní BizChat. Uchovávejte jej
  se stejnou obezřetností jako klíč API.

## Řešení problémů

### Ověření selže okamžitě

- Ověřte, že jste údaj zkopírovali z **adresy URL WebSocketu**, nikoli z požadavku XHR/Fetch.
  Přihlašovací údaj se nachází v parametru dotazu `access_token` připojení Chathub WebSocket
  — nikoli v hlavičce `Authorization: Bearer`.
- Ujistěte se, že `chathubPath` obsahuje celý segment `<oid>@<tenant>` z cesty
  adresy URL.

### Platnost tokenu vyprší přibližně po 75 minutách

Jedná se o očekávané chování. Bez `refreshToken` má přístupový token krátkou platnost. Buď:

- Získejte přihlašovací údaj znovu pomocí DevTools, nebo
- Nakonfigurujte `refreshToken` v Rozšířených nastaveních pro automatické obnovení.

### Test připojení projde, ale chat vrací chybu 401

Platnost tokenu mohla vypršet mezi ověřením a prvním požadavkem. Získejte znovu
aktuální přihlašovací údaj.

### Copilot se nezobrazuje v seznamu poskytovatelů

Ujistěte se, že je `copilot-m365-web` povolen v části **Řídicí panel → Poskytovatelé**. Poskytovatel může
být v některých úrovních ve výchozím nastavení skrytý.
