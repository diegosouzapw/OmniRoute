`chatgpt-web-codex` (alias `cgpt-codex`) zprostředkovává tahy Codex Responses prostřednictvím
ověřené relace ChatGPT v prohlížeči. Je nezávislý na vyřazeném společném
poskytovateli `chatgpt-web` a používá implementaci s upozorněním na licenci MIT v
`open-sse/vendor/codex-chatgpt-web/`, aktualizovanou podle upstreamového commitu v4.0.7
`b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494`.

## Vyřazení společného poskytovatele

Dřívější ID společného poskytovatele `chatgpt-web` a `cgpt-web` již nejsou součástí distribuce, protože
nebylo možné ověřit původ jejich implementace pre-key/proof-of-work. Explicitní
požadavky na kterékoli z těchto ID, včetně ID modelů s úvodním lomítkem a uložených aliasů,
jsou před jakýmkoli upstreamovým požadavkem bezpečně odmítnuty s HTTP `410` a kódem **PROVIDER_RETIRED**.

Migrace `168_retire_chatgpt_web.sql` označí odpovídající připojení poskytovatele jako odstraněná a
zneplatní jejich aktivní pronájmy relací. Zachová historii připojení a seznamy povolených
API klíčů; nepřidá do seznamu povolených přístup k náhradě. Toto vyřazení se netýká poskytovatele Codex
ani jeho připojení.

## Předpoklady

- úplná hlavička Cookie z přihlášené relace ChatGPT;
- Chrome nebo Chromium spolu s grafickou relací či displejem Xvfb pro instalace npm, systemd a PM2;
- při použití profilu Dockeru `web` interní služba Chromium z
  `docker-compose.yml`;
- OpenAI `tunnel-client` v0.0.13 a vlastní konektor ChatGPT pro místní nástroje Codex.

Tunel je potřeba pouze pro tahy s nástroji. Každá uvedená trasa, včetně `pro`, může používat
stejnou místní funkci nástrojů vázanou na tah, pokud jsou tunel a konektor nakonfigurovány.

## Nastavení na řídicím panelu

1. Otevřete poskytovatele **ChatGPT Web (Codex)** a přidejte připojení.
2. Vložte úplnou hlavičku Cookie služby ChatGPT, ID tunelu, runtime klíč a název vlastního konektoru.
   Nová nastavení podporující nástroje musí používat nově vytvořený konektor s přesným názvem
   `OmniRoute Codex v2`, s položkou Authentication nastavenou na None a položkou Permissions nastavenou na Allow all
   actions.
3. Spusťte kontrolu připojení. OmniRoute otevře prohlížečem zprostředkovaný Temporary Chat a zjistí,
   zda jsou pro daný účet dostupné režimy Sol a Pro.
4. Uložte připojení. OmniRoute nahradí vloženou cookie ověřeným
   stavem úložiště Playwright a uloží jej spolu s runtime klíčem prostřednictvím abstrakce
   šifrovaných přihlašovacích údajů.

Nezpracovaná cookie se po úspěšném uložení neuchovává. Jakmile platnost relace vyprší, otevřete
připojení, vložte novou úplnou hlavičku Cookie a spusťte kontrolu znovu. Stav diagnostiky
v dialogu úprav samostatně uvádí prohlížeč, stav úložiště, přihlášení, Temporary Chat, tunel,
konektor a obousměrnou komunikaci s nástrojem.

> Nikdy neukládejte skutečnou cookie, runtime klíč, stav úložiště ani token funkce do repozitáře. Hodnoty pro testy a
> dokumentaci musí být vždy zástupné.

## Modely a kombinace

Pevné trasy modelů jsou:

- `chatgpt-web-codex/luna` — GPT-5.6 Luna, nízká úroveň úsilí
- `chatgpt-web-codex/think` — GPT-5.6 Luna, střední úroveň úsilí
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

Přidejte jednu z nich do kombinace stejně jako kterýkoli jiný model. Aplikace Codex odesílá název kombinace jako
`model` do standardního koncového bodu Responses, `/v1/responses`; neexistuje žádný samostatný koncový bod Codex
ani přepínač režimu.

Účty Free/Go zpřístupňují trasy Luna. Účty s podporou Sol zpřístupňují trasy Instant až
High a účty s podporou Pro navíc zpřístupňují Extra High a Pro. Každá trasa má
pevně daný backendový model a úroveň úsilí při uvažování; konfliktní explicitní nastavení úsilí Responses je
bezpečně odmítnuto namísto tiché změny vybraného režimu prohlížeče.

Nepřejmenovávejte ani znovu nepoužívejte starší konektor `Codex Native` nebo `OmniRoute Codex`. ChatGPT
ukládá veřejný kontrakt MCP do mezipaměti podle identity konektoru, zatímco aktualizovaný bridge používá
nový přímý kontrakt tokenu tahu. Runtime tyto zastaralé identity odmítá a vyžaduje
nový konektor `OmniRoute Codex v2`.

## Bezpečnostní model

- Nativní cesta vyžaduje požadavek Responses, rozpoznaného klienta Codex a shodné
  identity vlákna a tahu.
- Pracovní prostor, sandbox, zásady schvalování a katalog nástrojů pocházejí z nativního shellu Codex;
  volně formulovaný text výzvy pro ně není autoritou.
- ChatGPT obdrží pro každý tah pouze krátkodobě platnou způsobilost. Broker MCP přijímá pouze
  nástroje, které Codex nabídl přesně v daném tahu.
- Automatické potvrzení **Povolit jednou** pouze vrátí požadavek na nástroj systému Codex. Pouze Codex
  rozhoduje o schválení a spuštění.
- Před prvním výstupem může kombinace přejít na jiný kompatibilní cíl. Jakmile
  výstup začne, poskytovatel, model, připojení a tah prohlížeče zůstanou pevně nastavené až do
  dokončení tahu.
- Soubory cookie, běhové klíče, stav úložiště a tokeny způsobilostí se nezobrazují v odpovědích
  poskytovatele ani v protokolech požadavků.

## VPS bez displeje a Docker

Při instalacích pomocí npm, systemd a PM2 OmniRoute detekuje běžné cesty k Chrome a Chromium.
Případně nastavte `CHATGPT_WEB_CODEX_CHROME_PATH`. Běhové tahy záměrně používají Chrome
s grafickým rozhraním, protože ChatGPT odmítá charakteristiku skutečně bezhlavého prohlížeče. Hostitel bez displeje proto musí
spouštět OmniRoute se soukromým displejem Xvfb; samotné nastavení cesty k Chrome jej neposkytne.

Profil Dockeru `web` spustí `chatgpt-web-codex-browser` v interní síti
Compose. Sidecar spouští Chrome s grafickým rozhraním uvnitř Xvfb, takže není vyžadován žádný fyzický displej. Jeho port CDP
není publikován na hostiteli. Svazek chráněného profilu prohlížeče je oddělen od
datového svazku OmniRoute a prohlížeč dostává dostatek sdílené paměti. Interní proxy CDP
naslouchá pouze na portu `9223` uvnitř sítě Compose; Chrome zůstává v sidecaru navázán na loopback.

Pronájem správce pod `DATA_DIR` brání tomu, aby více procesů OmniRoute vlastnilo
stejný stav tunelu a brokeru. Konflikt nahlásí diagnostický nástroj.

## Interaktivní obnovení

Automatizovaná cesta Dockeru nemá okno viditelné na hostiteli, ale samotný Chrome běží s grafickým rozhraním uvnitř
soukromého displeje Xvfb. Když ChatGPT vyžaduje interaktivní přihlášení nebo ověření, lze k obnovení
použít stávající infrastrukturu prohlížeče VNC. Uživatelské rozhraní prohlížeče a CDP musí zůstat dostupné pouze
přes loopback, ověřené připojení pro správu nebo tunel SSH; noVNC zůstává během
běžného provozu zakázáno.

## Záložní varianta WebSocket

Pokud kombinace obsahuje ChatGPT Web (Codex), most Responses WebSocket před připojením
k upstreamu vyžádá záložní variantu HTTP/SSE. Přenos poté probíhá přes
`/v1/responses`.
