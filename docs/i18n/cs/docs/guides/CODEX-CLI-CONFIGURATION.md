> **TOML je jediný funkční formát.** Moderní Codex čte výhradně
> `~/.codex/config.toml` (ověřeno s codex-cli 0.147.0: `codex --help` uvádí,
> že přepínače `-c/--config` přepisují konfiguraci „načtenou z `~/.codex/config.toml`“).
> Starý soubor `~/.codex/config.yaml` patřil k původnímu npm CLI a je bez upozornění
> ignorován. Generátor na řídicím panelu (`/api/cli-tools/apply`, nástroj `codex`)
> zapisuje TOML pomocí konzervativního sloučení — existující klíče a bloky ostatních
> poskytovatelů zůstanou zachovány, API klíč zůstane v `OMNIROUTE_API_KEY`
> (nikdy v souboru) a případný starý soubor `config.yaml` je uveden v poznámce
> k migraci, aniž by byl změněn.

## config.toml připravený ke vložení

Nahraďte `<YOUR_HOST>` a `<YOUR_KEY>` vlastními hodnotami:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # limit ukládání historie pro každé volání nástroje

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc nebo ~/.zshrc — skutečná hodnota klíče, nikdy v config.toml
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: Codex obsažený v aplikaci ChatGPT

Pokud jste Codex nainstalovali prostřednictvím desktopové aplikace ChatGPT, binární
soubor `codex` může existovat pouze uvnitř balíčku aplikace a ještě nemusí být
součástí proměnné `PATH` vašeho shellu. Přidejte adresář prostředků do spouštěcího
souboru svého shellu:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

Otevřete nový shell a poté vše ověřte:

```bash
command -v codex
codex --version
```

### Lokální OmniRoute bez ověřování: stačí zástupný klíč

Codex ověřuje, že proměnná prostředí určená pomocí `env_key` existuje,
**ještě předtím**, než CLI odešle první požadavek. Pokud vaše **lokální**
instance OmniRoute nevyžaduje ověřování, postačí libovolná neprázdná zástupná
hodnota:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

Pokud je váš server OmniRoute chráněný nebo vzdálený, použijte skutečný klíč.

> **Běžné možnosti hostitele**
>
> | Přístup       | URL                           |
> | ------------- | ----------------------------- |
> | Místní síť    | `http://192.168.0.1:20128/v1` |
> | Tailscale     | `http://100.x.x.x:20128/v1`   |
> | Zpětná smyčka | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — proč funguje pro všechny modely

Codex CLI v únoru 2026 označilo `wire_api = "chat"` (Chat Completions) za zastaralé a nyní **vyžaduje** `wire_api = "responses"` (OpenAI Responses API). Nastavení `wire_api = "chat"` způsobuje od verze v0.138 okamžitý pád při spuštění.

Mnoho poskytovatelů, včetně GLM a Kimi, stále zpřístupňuje pouze koncový bod Chat Completions. DeepSeek V4 nyní zpřístupňuje také nativní Responses API a koncový bod kompatibilní s Anthropic; OmniRoute ve výchozím nastavení používá Responses a umožňuje u každého připojení DeepSeek zvolit kompatibilitu s Anthropic.

**OmniRoute to řeší transparentně:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute vybere nativní protokol poskytovatele a v případě potřeby provede převod
    → POST /responses (DeepSeek V4) nebo /chat/completions (Mistral / GLM / Kimi / ostatní)
```

Při používání OmniRoute nikdy nepotřebujete samostatný překladový proxy server. **Všechny modely používají `wire_api = "responses"`** — o zbytek se postará OmniRoute.

> **`wire_api` je výchozí nastavení** — výchozí hodnotou tohoto pole je `"responses"` a z `config.toml` jej lze zcela vynechat. Nastavujte jej explicitně pouze tehdy, když chcete zdokumentovat záměr.

## Kontextové okno a komprimace

### Pole konfigurace tokenů

| Pole                             | Popis                                                                                                                                                                                                              |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `model_context_window`           | Celkový rozpočet tokenů pro aktivní model. Nastavte na limit uváděný pro daný model.                                                                                                                               |
| `model_auto_compact_token_limit` | Prahová hodnota, která spustí automatickou komprimaci historie. **Maximum: 90 % hodnoty `model_context_window`** — hodnoty nad 90 % jsou bez upozornění ignorovány.                                                |
| `tool_output_token_limit`        | Limit počtu tokenů uložených v historii pro výstup jednotlivého volání nástroje. Zabraňuje tomu, aby jediná rozsáhlá odpověď nástroje zaplnila okno. **Nejde o maximální výstup** — je to limit úložiště historie. |
| `compact_prompt`                 | Vložené přepsání systémového promptu používaného během komprimace (v0.138+).                                                                                                                                       |

> **Poznámka k `model_max_output_tokens`**: Toto pole **není součástí konfiguračního schématu Codex CLI** (v kódové základně Codex Rust chybí). Pokud je nastaveno, je bez upozornění ignorováno. Nespoléhejte na něj — pomocí `tool_output_token_limit` určete, jak velká část výstupu nástroje se uloží do historie.

## Prefix modelu: `cx/`

Všechny modely Codex v OmniRoute používají prefix `cx/`:

| Název v Codex CLI       | Model OmniRoute    |
| ----------------------- | ------------------ |
| `cx/gpt-5.5`            | GPT-5.5 standardní |
| `cx/gpt-5.4`            | GPT-5.4 standardní |
| `cx/gpt-5.4-mini`       | GPT-5.4 mini       |
| `cx/gpt-5.1-codex-mini` | GPT-5.1 Codex mini |

Ostatní poskytovatelé používají vlastní prefix (`kmc/`, `glm/`, `ds/`, `ollamacloud/`, `opencode-go/`, `mistral/`) — prefix odpovídá aliasu poskytovatele v OmniRoute.

## Úsilí při uvažování

Určuje, jak intenzivně model před odpovědí „přemýšlí“.

| Hodnota  | Použití pro                                       |
| -------- | ------------------------------------------------- |
| `none`   | Bez uvažování — přímá odpověď                     |
| `low`    | Triviální úlohy (přejmenování, formátování)       |
| `medium` | **Výchozí nastavení serveru**, pokud není uvedeno |
| `high`   | Středně náročné úlohy (refaktoring, ladění)       |
| `xhigh`  | Architektura, hloubková analýza, složité problémy |

```bash
# Přepsání nastavení pro jednotlivé spuštění
codex -c model_reasoning_effort=low "rename variable x to count"
codex -c model_reasoning_effort=xhigh "design the auth module"
```

Nastavte také **shrnutí** uvažování, aby Desktop mohl zobrazovat text přemýšlení (nejen šifrované bloky):

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # nebo ultra, pokud je podporováno
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### Rozpočet na uvažování v OmniRoute (nastavení serveru)

Na hostiteli OmniRoute musí být **Settings → AI → Thinking Budget** nastaveno na **`passthrough`**, aby se nastavení úsilí/shrnutí z Codexu dostalo k nadřazenému poskytovateli. Režim **`auto` odstraňuje** všechna klientská pole `reasoning` / `reasoning_effort` a panely uvažování proto zůstanou prázdné, i když je Codex nakonfigurován správně.

Kompletní průvodce: [THINKING_BUDGET.md](./THINKING_BUDGET.md).

Komprese a mezipaměť promptů jsou nezávislé a v režimu `passthrough` nadále fungují.

## Profily — pojmenované konfigurace pro jednotlivé modely/pracovní postupy

Profily umožňují přepínat model a kontextové okno jediným příznakem. Každý profil je samostatný
soubor `~/.codex/<name>.config.toml`, který se aplikuje přes základní soubor `config.toml`.

> **Pravidlo pojmenování (Codex CLI v0.137+):** soubor musí mít název `~/.codex/<name>.config.toml` — **bez prefixu `profile-`**.
> CLI převede `-p kimi-k27` na `~/.codex/kimi-k27.config.toml`. Pokud soubor nenajde, bez upozornění se použije výchozí nastavení.

```bash
codex --profile kimi-k27 "analyze 10k lines of this codebase"
codex -p glm52 "architecture review"
codex --profile deepseek-flash "rename variable"   # rychlé, levné
```

### Profily úsilí (stejný model, různé úsilí)

```bash
codex -p low      # cx/gpt-5.5, úsilí=low
codex -p medium   # cx/gpt-5.5, úsilí=medium
codex -p high     # cx/gpt-5.5, úsilí=high
codex -p xhigh    # cx/gpt-5.5, úsilí=xhigh (výchozí)
codex -p chat     # cx/gpt-5.5, úsilí nenastaveno (výchozí nastavení serveru)
```

## Automatické generování profilů pomocí `omniroute setup-codex`

Pokud OmniRoute provozujete na VPS, můžete automaticky generovat soubory profilů z aktuálního katalogu modelů:

```bash
# Z VPS (používá místní OmniRoute na portu 20128)
omniroute setup-codex

# Z libovolného počítače — nasměrujte jej na svůj VPS
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# Náhled bez zápisu souborů
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# Generovat pouze profily GLM a Kimi
omniroute setup-codex --only glm,kimi

# Zápis do vlastního adresáře
omniroute setup-codex --codex-home /path/to/.codex
```

Příkaz načte `/v1/models`, použije vyladěné profily pro známé modely, pro ostatní kompatibilní textové modely použije jako záložní řešení metadata katalogu a pro každý z nich zapíše `~/.codex/<name>.config.toml`. Je idempotentní — lze jej bezpečně spustit opakovaně.

OmniRoute také může tyto stejné soubory profilů **automaticky synchronizovat** poté, co úspěšné zjištění/import modelů poskytovatele změní aktuální katalog. Tato funkce je **volitelná a ve výchozím nastavení vypnutá**: zapněte ji na **řídicím panelu CLI Code** („Automatická synchronizace profilů CLI“ → Codex) nebo nastavte `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` (respektuje také `CLI_ALLOW_CONFIG_WRITES`, které je ve výchozím nastavení zapnuté). Je-li funkce povolena, zapisuje pouze samostatné soubory profilů `~/.codex/*.config.toml`; nikdy nemění aktivní/výchozí soubor `~/.codex/config.toml`, nastavení Codex-lb, ověřování ani výběr poskytovatele.

## Dlouhotrvající úlohy

Dvě výchozí hodnoty OmniRoute mohou nenápadně narušit několikahodinové relace Codex CLI. Ani jedna není nastavením Codex CLI — obě se nacházejí na straně OmniRoute. Uživatelé, kteří migrují konfiguraci z upstream proxy serverů, jež připínají účty a vypínají limity nečinnosti, často narazí na oba problémy a dojdou k závěru, že OmniRoute „nedokáže udržet dlouhou relaci“.

| Příznak                                                                          | Pravděpodobná příčina                                                  | Nastavení                |
| -------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------ |
| Relace neustále přepíná účty / mezi tahy se ztrácí kontinuita mezipaměti promptů | TTL afinity relace je `0` (vypnuto)                                    | `sessionAffinityTtlMs`   |
| Připojení se přeruší během uvažování bez upozornění zobrazeného klientovi        | Hlídač nečinnosti streamu se spustil po 10 minutách bez upstream části | `STREAM_IDLE_TIMEOUT_MS` |

Související diskuse: [#7126](https://github.com/diegosouzapw/OmniRoute/discussions/7126) (výpadky dlouhých úloh), [#5718](https://github.com/diegosouzapw/OmniRoute/discussions/5718) (proč je afinita ve výchozím nastavení vypnutá). Sledování: [#7287](https://github.com/diegosouzapw/OmniRoute/issues/7287).

### 1. Afinita relace — připnutí jedné konverzace k jednomu účtu

**Výchozí hodnota:** `sessionAffinityTtlMs = 0` (vypnuto).

**Kde ji nastavit**

- Řídicí panel → **Nastavení → Směrování** → **Afinita relace** → **TTL afinity (sekundy)** (`ComboDefaultsTab`)
- Nebo aktualizujte nastavení metodou PATCH s `sessionAffinityTtlMs` v **milisekundách** (rozsah Zod `0`–`86_400_000`, tj. až 24 hodin)

> V #7274 přejmenováno z `codexSessionAffinityTtlMs`, které bylo určeno pouze pro Codex. Původní klíč je stále přijímán jako alias pouze pro čtení; nové konfigurace by měly používat `sessionAffinityTtlMs`. Afinita se nyní vztahuje na **libovolného** poskytovatele, jakmile je TTL vyšší než `0`, nejen na Codex — viz [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → Afinita relace.

**Co přestane fungovat, když hodnota zůstane 0**

Každý tah vícekolové konverzace Codex je směrován nezávisle podle aktivní kombinované strategie a při každém tahu může skončit na **jiném účtu**. Tím se naruší kontinuita upstream relace / mezipaměti promptů. OmniRoute kontroluje hlavičky relace Codex (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) a pole těla, například `prompt_cache_key` / `session_id`, pouze tehdy, když je TTL větší než `0` (`extractSessionAffinityKey` v `src/sse/services/auth.ts`).

**Doporučení pro několikahodinovou samostatnou úlohu**

Nastavte TTL **nad očekávanou dobu trvání úlohy podle hodin** (maximum v uživatelském rozhraní je **86400 sekund** = 24 hodin):

| Očekávaná délka úlohy | TTL afinity (UI, sekundy) | `sessionAffinityTtlMs` |
| --------------------- | ------------------------- | ---------------------- |
| Několik hodin         | `14400` (4 h)             | `14400000`             |
| Přes noc / ~12 h      | `43200` (12 h)            | `43200000`             |
| Celý den              | `86400` (24 h, maximum)   | `86400000`             |

Výslovné povolení je záměrné: vypnutí afinity upřednostňuje vyvažování zátěže mezi účty; její zapnutí upřednostňuje kontinuitu jedné dlouhé relace agenta. Tato příručka výchozí hodnotu **nemění** — provozovatelé spouštějící dlouhé úlohy Codex musí tuto funkci výslovně povolit.

### 2. Časový limit nečinnosti streamu — neukončujte tiché tahy uvažování

**Výchozí hodnota:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 minut). Pokud není nastavena, dědí hodnotu z `REQUEST_TIMEOUT_MS`; sdílená výchozí hodnota je rovněž 600000. Viz [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → Časové limity.

**Co přestane fungovat při výchozí hodnotě**

Tah uvažování / nástroje Codexu, který zůstane potichu déle než 10 minut a nepřijde během něj **žádný skutečný datový blok z upstreamu**, je násilně ukončen hlídačem nečinnosti SSE (`open-sse/utils/stream.ts`). Klient často zaznamená pouze náhlé přerušení připojení — což odpovídá hlášení „automaticky se zastavilo bez jakéhokoli upozornění“.

Kritický detail: syntetický SSE **heartbeat OmniRoute časovač nečinnosti neresetuje**. Hodnotu `lastChunkTime` aktualizuje pouze skutečný blok těla odpovědi z upstreamu. Tichý model, který stále „přemýšlí“, vypadá z pohledu hlídače stejně jako zablokovaný upstream.

Související nečinnost těla odpovědi Undici: `FETCH_BODY_TIMEOUT_MS` (ve výchozím nastavení používá stejný základ 10 minut; hodnota `0` ji vypne). U streamování pokrývá `FETCH_TIMEOUT_MS` pouze navázání připojení / první hlavičky — po aktivaci streamu se prodlevy řídí pomocí `STREAM_IDLE_TIMEOUT_MS` a `FETCH_BODY_TIMEOUT_MS`.

**Doporučení pro jednu několikahodinovou úlohu**

V prostředí procesu OmniRoute (`.env` / compose / systemd):

```bash
# Vypnutí limitů nečinnosti streamu a těla odpovědi pro dlouhé tahy uvažování
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

Nebo je zvyšte nad nejdelší očekávanou dobu bez aktivity (hodnoty jsou v milisekundách):

```bash
# Příklad: povolit až 2 hodiny bez aktivity mezi bloky z upstreamu
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

Po změně těchto proměnných prostředí OmniRoute restartujte.

### Konkrétní postup — několikahodinová úloha Codexu

1. **Připněte účet:** Dashboard → Settings → Routing → Session affinity → Affinity TTL = `43200` (12 h) nebo `86400` (maximum 24 h).
2. **Zvyšte / vypněte limity nečinnosti** v prostředí OmniRoute:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. Zachovejte obvyklý soubor `config.toml` Codexu (`wire_api = "responses"`, správná hodnota `base_url`, `OMNIROUTE_API_KEY`) — pro tato dvě chování neexistují na straně Codexu žádná nastavení afinity ani nečinnosti.
4. Restartujte OmniRoute a poté spusťte dlouhou úlohu Codexu.

### Rozhodnutí o výchozích hodnotách (#7287)

| Nastavení                | Dodávaná výchozí hodnota | Změnit v tomto průvodci?                                                                             |
| ------------------------ | ------------------------ | ---------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (vypnuto)            | **Ne** — zůstává volitelné (vyvažování zátěže vs. kontinuita; viz Discussion #5718)                  |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 min)        | **Ne** — pro běžný provoz zůstává 10 minut; provozovatelé dlouhých úloh Codexu jej zvýší nebo vypnou |

Globální změna kterékoli výchozí hodnoty by změnila chování pro každého klienta dané instance, nejen pro Codex. Nastavení zdokumentujte; výchozí hodnoty ponechte beze změny, dokud explicitní rozhodnutí provozovatele neurčí jinak.

### Diagnostika ukončení kvůli nečinnosti

Když se aktivuje hlídač nečinnosti, OmniRoute zaznamená řádek v následujícím tvaru:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

Vyhledejte pomocí grep řetězec `Idle timeout: no data from` (nebo kód `stream_idle_timeout` / název chyby `StreamIdleTimeoutError`). Segment poskytovatele odpovídá tomu, co OmniRoute použil pro daný požadavek (`codex`, ID jiného poskytovatele nebo `provider`, pokud není znám) — nejde vždy doslova o řetězec `codex`.

## Řešení problémů

**`Error: wire_api = "chat" is no longer supported`**
Odstraňte z konfigurace `wire_api = "chat"`. Nastavte `wire_api = "responses"` nebo toto pole vynechte (od verze v0.138 je výchozí hodnotou `"responses"`).

**`Error: model not found`**
Ověřte, že model v OmniRoute existuje a má správnou předponu. Použijte `omniroute models list` nebo otevřete `/dashboard/providers/<provider>`.

**`Authentication error`**
Ověřte, že je proměnná `OMNIROUTE_API_KEY` exportována: `echo $OMNIROUTE_API_KEY`.

**`ERROR: Missing environment variable: OMNIROUTE_API_KEY`**
Codex před odesláním prvního požadavku ověřuje, zda proměnná prostředí existuje. Pro chráněné servery exportujte skutečný klíč. Pokud vaše **lokální** instance OmniRoute nevyžaduje ověření, použijte neprázdnou zástupnou hodnotu, například `OMNIROUTE_API_KEY=local`. Pokud jste proměnnou přidali do `~/.bashrc` nebo `~/.zshrc`, restartujte shell.

**`Connection refused`**
Ověřte, že OmniRoute běží a hostitel i port v `base_url` jsou pro vaši síť správné (lokální síť vs. Tailscale vs. VPS).

**Relace selhává poblíž limitu kontextu**
Nastavte explicitně `model_context_window` a `model_auto_compact_token_limit`. Viz tabulka kontextových oken výše.

**Komprimace se spouští příliš pozdě**
Snižte `model_auto_compact_token_limit` na 80–85 % okna. Nikdy jej nenastavujte nad 90 %.

**Profil se nenačítá (`-p <name>` je bez upozornění ignorováno)**
Ověřte, že soubor existuje v umístění `~/.codex/<name>.config.toml` (bez předpony `profile-`). Spusťte `ls ~/.codex/*.config.toml`.

**Dlouhá úloha Codexu se během provádění přeruší / mezi jednotlivými kroky přepíná účty**
Viz [Dlouhotrvající úlohy](#long-running-tasks). Zapněte afinitu relace (s TTL delším než doba trvání úlohy) a zvyšte nebo deaktivujte `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS`. V protokolech OmniRoute vyhledejte pomocí grep řetězec `Idle timeout: no data from`.
