**OmniCopilot** přidává každý model poskytovaný službou OmniRoute do _nativního_ výběru modelů v GitHub Copilot Chat. Žádný druhý postranní panel, žádné samostatné chatovací rozhraní — režim agenta Copilotu, volání nástrojů, servery MCP i vlastní instrukce nadále fungují, pouze běží na modelu, který si vyberete.

|                             |                                                                                                                                                 |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Instalace (VS Code)**     | [Marketplace → `diegosouzapw.omnicopilot`](https://marketplace.visualstudio.com/items?itemName=diegosouzapw.omnicopilot)                        |
| **Instalace (forky)**       | [Open VSX](https://open-vsx.org/extension/diegosouzapw/omnicopilot) — Cursor, Windsurf, VSCodium, Theia, code-server, Gitpod, Antigravity, Kiro |
| **Zdrojový kód / problémy** | [github.com/diegosouzapw/OmniCopilot](https://github.com/diegosouzapw/OmniCopilot) (MIT)                                                        |
| **Požadavky**               | VS Code 1.104+                                                                                                                                  |

> **Předplatné Copilotu není potřeba.** Od verze VS Code 1.122 funguje poskytovatel jazykových modelů
> bez přihlášení ke GitHubu a bez jakéhokoli tarifu Copilot. Doplňování přímo v editoru a
> funkce založené na embeddings zůstávají mimo API poskytovatele a stále vyžadují Copilot.

## Nastavení

1. **Spusťte OmniRoute** — `npm install -g omniroute && omniroute` (dashboard na adrese `http://localhost:20128`).
2. **Nainstalujte rozšíření** — ve zobrazení Rozšíření vyhledejte „OmniRoute“.
3. **Vyberte model** — Copilot Chat → výběr modelu → **Manage Models…** → **OmniRoute** a poté zaškrtněte
   požadované modely.

Pokud OmniRoute běží na výchozím portu, není třeba nic nastavovat. Pro vzdálenou instanci otevřete
**ikonu OmniRoute na panelu aktivit** (nebo spusťte `OmniRoute: Manage Connection`) a nastavte:

- **Adresa URL serveru** — kořenová adresa serveru, např. `http://192.168.0.15:20128`. Příponu `/v1`
  přidá rozšíření; neuvádějte ji.
- **Klíč API** — pouze pokud je na serveru nastavena proměnná `REQUIRE_API_KEY`. Ukládá se do systémové klíčenky prostřednictvím
  VS Code SecretStorage, nikdy do `settings.json`.

## Co se zobrazí ve výběru

Rozšíření nezobrazuje nezpracovaný obsah odpovědi `GET /v1/models` — upravuje jej, a počet zobrazených
položek je nižší než velikost katalogu ze dvou záměrných důvodů.

### Vyžaduje jedno id pro každý model

Výchozí hodnota `MODELS_CATALOG_PREFIX_MODE` je **`dual`**, což znamená, že každý model je inzerován dvakrát — jednou
s krátkým prefixem aliasu a jednou s kanonickým prefixem poskytovatele — aby starší konfigurace
klientů nadále dokázaly rozpoznat obě podoby:

```
cc/claude-sonnet-4-6        ← prefix aliasu
claude/claude-sonnet-4-6    ← kanonický prefix, stejný model
```

Rozšíření odesílá požadavek **`GET /v1/models?prefix=alias`**, takže pro každý model obdrží jedno id, aniž by
měnilo celoserverové nastavení pro ostatní klienty. Na referenční instanci se tím počet snížil
z **2345 položek na 1396 — 949 duplicit, žádné ztracené modely.**

Pokud to chcete opravit na úrovni serveru pro _každého_ klienta, nastavte na dashboardu
příznak funkce `MODELS_CATALOG_PREFIX_MODE` na hodnotu `alias`. Informace o parametru
dotazu a tabulku pro jednotlivé režimy najdete v části
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix).

### Skrývá modely, které nepodporují chat

Katalog obsahuje také modely pro obrázky, video, zvuk, změnu pořadí, embeddings a moderování. Ty by
byly při chatovacím požadavku stejně odmítnuty:

```
HTTP 400 — Model '<id>' je model pro generování obrázků a nelze jej použít pro
/v1/chat/completions. Místo toho použijte POST /v1/images/generations.
```

proto jsou před zobrazením ve výběru odfiltrovány podle svého pole `type`. **Modely Responses API
zůstávají zachovány** — každá položka Codex / GPT-5.x uvádí `supported_endpoints: ["responses"]`
a OmniRoute je překládá pro `/v1/chat/completions`, takže jsou plně použitelné.

### Poskytovatelé, které jste nikdy nenakonfigurovali

Katalog uvádí modely od poskytovatelů s **aktivním připojením** a také od všech poskytovatelů **noAuth**
— tedy těch bez klíče, kteří tvoří velkou část bezplatné úrovně. Je to záměrné. Chcete-li
je skrýt, přidejte je v nastavení dashboardu do `blockedProviders`; v rozšíření není třeba
nic měnit.

## Řídicí panel na kartě VS Code

`omnicopilot.dashboardOpen: "editor"` vykreslí řídicí panel OmniRoute na kartě editoru prostřednictvím
Simple Browser namísto externího prohlížeče. Vkládání je **nutné výslovně povolit na serveru** pomocí
`DASHBOARD_ALLOW_EMBED=vscode`, což zajistí, že se HTML stránky budou poskytovat s
`frame-ancestors 'self' vscode-webview:` namísto výchozího `frame-ancestors 'none'` +
`X-Frame-Options: DENY`. Rozhraní API (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) si v obou
případech zachovává striktní hlavičky.

> ⚠️ **Jde o příznak při sestavení, nikoli za běhu.** Next.js zkompiluje `headers()` do manifestu
> tras, takže `next.config.mjs` načítá proměnnou během sestavování balíčku
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> Její exportování před spuštěním již sestaveného serveru nic nezmění — hlavičky jsou pevnou součástí sestavení.

```bash
# proměnná musí být nastavena pro příkaz SESTAVENÍ
DASHBOARD_ALLOW_EMBED=vscode npm run build        # nebo npm run build:release
npm start
```

| Způsob instalace           | Lze povolit vkládání?                                                                                                                       |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Ze zdrojového kódu         | ✅ nastavte proměnnou pro příkaz sestavení, jak je uvedeno výše                                                                             |
| `npm install -g omniroute` | ❌ publikovaný balíček obsahuje předem sestavený balíček — místo toho proveďte sestavení ze zdrojového kódu                                 |
| Obraz Dockeru              | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — předem sestavený obraz na Docker Hub vkládání nepodporuje |

Bez sestavení s povoleným vkládáním stránka odmítne zobrazení v rámci, rozšíření to zjistí z
hlaviček odpovědi a přepne se na externí prohlížeč — nic se tím nenaruší a jednorázově vás o tom informuje.
Viz [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) a problém
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273).

## Konfigurace ostatních nástrojů přímo z VS Code

**`OmniRoute: Configure Coding CLI`** používá rozhraní `omniroute` CLI k zápisu připravených profilů
pro Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code,
Kilo a Roo — jde o stejné konfigurace, které jsou popsány v
[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md). Klíč API se rozhraní CLI předává prostřednictvím
proměnné prostředí `OMNIROUTE_API_KEY`, nikdy na příkazovém řádku.

## Řešení potíží

| Příznak                                                      | Příčina / řešení                                                                                                                                                                                                                                                                         |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ve výběru nejsou žádné modely OmniRoute                      | Server je nedostupný. Tečka na stavovém řádku zešedne; spusťte `OmniRoute: Check Connection`. Zjišťování je záměrně tiché a namísto zobrazování výzvy neposkytne žádné modely.                                                                                                           |
| Každý model se zobrazuje dvakrát                             | Používáte OmniCopilot starší než 1.0.1 — aktualizujte jej. Rozšíření nyní požaduje `?prefix=alias`.                                                                                                                                                                                      |
| Dříve zobrazený model pro obrázky/zvuk zmizel                | Od verze 1.0.1 je to záměrné — takový model nikdy nedokázal odpovědět na požadavek chatu.                                                                                                                                                                                                |
| Na panelu aktivit chybí panel                                | VS Code přesouvá další kontejnery zobrazení do nabídky **„…“** v dolní části panelu aktivit a kontejner skrytý kliknutím pravým tlačítkem zůstane skrytý. Klikněte pravým tlačítkem na panel aktivit → zaškrtněte **OmniRoute** nebo jej otevřete pomocí `OmniRoute: Manage Connection`. |
| Řídicí panel se navzdory režimu `editor` otevře v prohlížeči | Server nebyl **sestaven** s `DASHBOARD_ALLOW_EMBED=vscode` (viz výše) — jeho nastavení při spuštění předem sestavené instalace nic nezmění. Přepnutí na externí prohlížeč je záměrné.                                                                                                    |
| Seznam modelů je po změně poskytovatelů zastaralý            | Použijte `OmniRoute: Refresh Models` nebo odkaz ↻ na panelu.                                                                                                                                                                                                                             |
