---

OmniRoute nabízí **dva** způsoby použití OpenAI Codex:

| Poskytovatel           | Jak komunikuje s OpenAI                                                                                                                                                                         | Omezení použití                                                            |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| **`codex`**            | Předává váš OAuth token ChatGPT/OpenAI přímo rozhraní Responses API                                                                                                                             | **Ano** — oficiální relace není autorizována pro použití přes proxy/router |
| **`codex-app-server`** | Ovládá **vlastní `codex app-server` nástroje Codex CLI** přes JSON-RPC/WebSocket; CLI spravuje a automaticky obnovuje svůj OAuth (`~/.codex/auth.json`) přesně jako interaktivní relace `codex` | **Ne** — OmniRoute nikdy nepředává token rozhraní API                      |

Protože `codex-app-server` nikdy nepředává token, nevztahuje se na něj
omezení použití týkající se opakovaného přehrávání relace. Vyžaduje však
**Codex CLI dostupné na nakonfigurované URL app-serveru** a toto CLI musí být
**přihlášené**.

---

## 1. Architektura

```
┌─ Aplikace OmniRoute ─────────────┐        ┌─ Sidecar codex-app-server ─────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ token schopností)             │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  samostatně spravuje OpenAI OAuth   │
└──────────────────────────────────┘        │  (~/.codex/auth.json, automatická   │
        │ sdílí (svazky compose)            │   obnova)                            │
        ▼                                   └─────────────────────────────────────┘
  codex-appserver-token   → token schopností WS (připojují jej oba)
  codex-appserver-home    → ~/.codex (auth.json zapisovaný řídicím panelem,
                             čtený procesem codex app-server v sidecaru)
```

- Sidecar naslouchá **pouze** v interní síti compose
  (`ws://codex-app-server:1456`) a je chráněn tokenem schopností. **Nikdy** není
  zpřístupněn hostiteli ani internetu.
- Codex CLI je součástí obrazu `omniroute:base`, takže při spuštění sidecaru
  není nutné instalovat codex na hostiteli ani na počítači uživatele.

## 2. Spuštění

```bash
# Spusťte celý stack VČETNĚ profilu sidecaru codex app-server:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

Sidecar při prvním spuštění vygeneruje svůj token schopností WS (do sdíleného
svazku `codex-appserver-token`) a aplikace načte stejný token prostřednictvím
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE`. Žádné ruční nastavování tokenu není
potřeba.

## 3. Připojení a přihlášení

1. V řídicím panelu přidejte připojení pro **OpenAI Codex (App-Server)**. Není
   vyžadován žádný klíč API ani token (jde o poskytovatele bez ověřování —
   ověřování vlastní sidecar).
2. Pokud Codex CLI sidecaru **ještě není přihlášené**, kontrola stavu připojení
   zobrazí _„spuštěno, ale nepřihlášeno“_ (nikoli červenou chybu ověřování).
   Použijte **Přihlásit se pomocí ChatGPT**: tím se v prohlížeči spustí
   standardní ověření Codex prostřednictvím device-OAuth a následně se pomocí
   možnosti **Použít přihlašovací údaje** zapíše `~/.codex/auth.json` do
   sdíleného svazku (jedno přihlášení slouží poskytovatelům `codex` i
   `codex-app-server`).
3. Po přihlášení se kontrola stavu zobrazí zeleně (ověřuje jak `/readyz`, **tak**
   `account/read` — tedy že je služba spuštěná _a_ ověřená) a vše začne
   fungovat.

Řídicí panel nikdy nepřepíše funkční existující soubor `~/.codex/auth.json` —
zapisuje pouze tehdy, když soubor chybí nebo je jeho token zastaralý (vždy se
vytvoří záloha).

## 4. Scénáře nasazení

- **Provozovatel s již ověřeným Codex CLI** — připojte hostitelský adresář
  `~/.codex` do sidecaru (`codex-appserver-home`) a krok přihlášení přeskočte.
- **Veřejný uživatel bez lokálně nainstalovaného codexu** — na tom nezáleží:
  sidecar obsahuje CLI. Uživatel se pouze ověří prostřednictvím řídicího panelu.
- **OmniRoute přímo na serveru (bez sidecaru, codex na hostiteli)** — nastavte
  `OMNIROUTE_CODEX_APPSERVER_WS` na svůj vlastní `codex app-server` a zajistěte,
  aby byl codex na hostiteli přihlášený; pokud binární soubor chybí, zobrazí se
  upozornění „codex není nainstalován“.

## 5. Rezidenční / UDP odchozí připojení (volitelné pro provozovatele, není součástí distribuce)

Výše uvedený obecný sidecar směruje odchozí provoz přes běžnou síť kontejneru.
Provozovatel, který potřebuje, aby provoz Codex odcházel přes **rezidenční
výstupní uzel** (např. sidecar tailscale v režimu TUN přenášející TCP +
UDP/QUIC), jej spustí jako samostatné překrytí compose; záměrně **není** součástí
dodávaného profilu `codex-app-server`. Pokyny k tomuto nastavení naleznete
v interní provozní příručce.
