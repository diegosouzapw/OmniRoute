## 1. Antigravity vs. Antigravity CLI (agy)

Oba poskytovatelé sdílejí **stejný backend Google** — identického klienta OAuth, obnovování tokenů, koncové body a účty Google. Rozdíl spočívá v tom, které modely se zobrazují.

> Oficiální porovnání od Googlu najdete v [oznámení Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli).

| Aspekt                     | `antigravity` (IDE)                                | `agy` (CLI)                                                 |
| -------------------------- | -------------------------------------------------- | ----------------------------------------------------------- |
| **Produkt Google**         | Antigravity 2.0 / Antigravity IDE                  | Antigravity CLI                                             |
| **Backend**                | Stejné API Google Cloud Code                       | Stejné API Google Cloud Code                                |
| **OAuth / Token**          | Stejný klient, stejné obnovování                   | Stejný klient, stejné obnovování                            |
| **Katalog modelů**         | Statický kurátorovaný seznam (napevno v OmniRoute) | Dynamicky zjišťovaný od Googlu přes `:fetchAvailableModels` |
| **Modely Claude**          | Sonnet 4.6, Opus 4.6 (každý ve 4 variantách)       | Sonnet 4.6, Opus 4.6 (každý ve 4 variantách)                |
| **Pojmenování Gemini**     | Přehledné názvy (Low/Medium/High)                  | Nadřazené identifikátory (extra-low/low/agent)              |
| **Další modely**           | `gpt-oss-120b-medium`                              | Může zahrnovat další modely od Googlu                       |
| **Výchozí způsob použití** | Integrace s IDE (VS Code, JetBrains)               | Přístup přes CLI / API                                      |
| **Kvóta**                  | Sdílená s agy (stejný účet Google)                 | Sdílená s antigravity (stejný účet Google)                  |

**Dostupné modely (ověřeno experimentálně, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (různé úrovně uvažování)
- Claude: Sonnet 4.6, Opus 4.6 (každý ve variantách default/low/medium/high)
- Ostatní: GPT-OSS 120B Medium
- **Claude Sonnet 5 NENÍ k dispozici** — podporovány jsou pouze varianty 4.6

**Proč se katalog modelů liší**: CLI od Googlu je podle oficiálního blogu Googlu „optimalizováno pro rychlost a nízkou režii“ a „společně optimalizováno s modely Gemini“. Webový produkt / produkt pro IDE je „optimalizován pro komplexnost“. CLI používá `:fetchAvailableModels` k dynamickému zjišťování modelů, zatímco IDE používá statický kurátorovaný seznam.

**V praxi**: Pro modely Gemini používejte prefix `agy/` (např. `agy/gemini-3.7-flash-high`). Pro statický kurátorovaný seznam používejte `antigravity/`. Oba využívají stejný backend Google, ale používají odlišné pojmenování modelů. Kvóta je sdílená — používání kteréhokoli poskytovatele se započítává do limitů stejného účtu Google.

## 2. Google One AI Pro: Systém kvót

> Oficiální podrobnosti o kvótách najdete v [dokumentaci Antigravity: Tarify](https://antigravity.google/docs/plans) a nejnovější informace o cenách v článku [Změny tarifů Antigravity](https://antigravity.google/blog/changes-to-antigravity-plans).

Google Antigravity používá **dvouvrstvou kvótu** založenou na „vykonané práci“ (výpočetní náročnosti), nikoli na počtu zpráv.

### Dvě vrstvy

| Vrstva             | Co představuje                   | Cyklus obnovení                                                                      |
| ------------------ | -------------------------------- | ------------------------------------------------------------------------------------ |
| **5hodinový úsek** | Okamžitá zásoba „vykonané práce“ | Obnoví se 5 hodin po prvním požadavku v relaci                                       |
| **7denní základ**  | Pevný týdenní limit              | Po dosažení přepíše 5hodinové obnovení; zablokuje přístup do dalšího 7denního období |

**Jak se počítá „vykonaná práce“**: Úlohy s vysokým zapojením agenta (např. „Refaktoruj celý tento repozitář“) spotřebovávají kvótu mnohem rychleji než jednoduché úlohy (např. „Oprav tuto funkci“). Neexistuje žádný řídicí panel zobrazující spotřebu v reálném čase.

### Úrovně tarifů

| Tarif        | Cena         | Kvóta                                     | Týdenní limit                             |
| ------------ | ------------ | ----------------------------------------- | ----------------------------------------- |
| Free         | $0           | Smysluplná kvóta obnovovaná týdně         | Ano                                       |
| AI Pro       | $19.99/měs.  | Vysoká kvóta, průběžné 5hodinové obnovení | Ano (po dosažení přepíše 5hodinový limit) |
| AI Ultra 5x  | $99.99/měs.  | 5násobek kvóty Pro                        | Bez týdenního limitu                      |
| AI Ultra 20x | $199.99/měs. | 20násobek kvóty Pro                       | Bez týdenního limitu                      |

### Modely Gemini oproti ostatním modelům

- **Modely Gemini** (Flash + Pro): Sdílejí jeden limit využití, který se čerpá podle cen API. Pokud je Flash 8x levnější než Pro, získáte 8x více tokenů Flash.
- **Modely jiné než Gemini** (Claude, GPT-OSS): Mají **samostatné** limity využití. Mohou zůstat dostupné, i když je přístup k Gemini zablokován.

### Kredity AI (nadlimitní využití)

> Informace o fungování kreditů najdete na stránce [Kredity Google One AI](https://support.google.com/googleone/answer/14534406).

Po vyčerpání základní kvóty:

- **Nikdy**: Čeká na obnovení kvóty; zobrazí se „Dosažena základní kvóta modelu“
- **Vždy**: Automaticky používá kredity AI; po obnovení základní kvóty se na ni přepne zpět

Kredity se nakupují samostatně a odečítají se podle standardních cen API.

### Klíčové podrobnosti

- Kvóta je **sdílena na úrovni účtu** — stejný účet Google v Antigravity IDE, CLI a OmniRoute sdílí jednu zásobu kvóty
- Každý účet Google má vlastní nezávislou kvótu — více účtů = více zásob kvóty
- Uživatelé AI Pro hlásili **7denní blokace** namísto 5hodinových obnovení po dosažení týdenního základu (Google potvrdil, že je to záměrné chování při vysoké poptávce)

**Když je kvóta vašeho účtu vyčerpána**: OmniRoute automaticky zopakuje pokus s dalším dostupným účtem v kombinované trase. Není nutný žádný ruční zásah.

## 3. Jak získat projectId

Každé připojení antigravity/agy potřebuje `projectId` služby Google Cloud Code. Bez něj koncový bod `/v1internal:models` vrací chybu 404.

### Metoda A: Automaticky (doporučeno)

OmniRoute to zajišťuje automaticky. Když přidáte nový účet Google prostřednictvím OAuth na řídicím panelu:

1. OmniRoute obnoví token
2. Zavolá `loadCodeAssist`, aby zjistil projectId
3. Pokud žádný projekt neexistuje, zavolá `onboardUser`, aby jej vytvořil
4. Znovu zavolá `loadCodeAssist`, aby získal nově vytvořené projectId
5. Uloží jej do databáze

**Funguje to pro většinu účtů** — nejsou potřeba žádné ruční kroky.

### Metoda B: Ručně prostřednictvím agy CLI

Pokud automatické zjištění selže (případy, kdy k tomu dochází, najdete v části 5):

```bash
# Nainstalujte agy CLI (pokud ještě není nainstalováno)
npm install -g @anthropic-ai/agy

# Přihlaste se pomocí svého účtu Google
agy login

# Vyberte účet, který je třeba zaregistrovat
# Tím se spustí registrace služby Cloud Code a přiřadí se projectId
```

Po úspěšném dokončení `agy login` obnovte token na řídicím panelu OmniRoute. projectId bude zjištěno automaticky.

### Jak ověřit

Zkontrolujte databázi:

```bash
# Uvnitř kontejneru OmniRoute
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Nebo zkontrolujte protokoly:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. URI pro přesměrování OAuth

### Problém

Google OAuth vyžaduje platný identifikátor URI pro přesměrování. OmniRoute ve výchozím nastavení používá `http://127.0.0.1:20128/callback` (loopback). To funguje pro lokální sestavení, ale **selhává u vzdálených nasazení** (např. u serveru přístupného přes IP adresu v síti LAN).

Google odmítá identifikátory URI pro přesměrování, které:

- Používají IP adresy (musí jít o doménu končící na `.com`, `.org` atd.)
- Se neshodují s registrovanými identifikátory URI pro přesměrování v konfiguraci klienta OAuth

### Řešení

**Možnost A: Použít vestavěný tok OAuth (výchozí)**

- Funguje, když k OmniRoute přistupujete z `localhost` nebo `127.0.0.1`
- Není nutná žádná konfigurace

**Možnost B: Vlastní přihlašovací údaje OAuth**

- Nastavte ve svém prostředí `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web`
- Zadejte vlastní přihlašovací údaje Google OAuth:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Zaregistrujte `https://your-domain.com/callback` jako autorizovaný identifikátor URI pro přesměrování v Google Cloud Console

**Možnost C: Použít agy CLI pro počáteční přihlášení**

- Spusťte `agy login` na počítači, který bude přistupovat k OmniRoute
- Tok OAuth se dokončí lokálně a tokeny se uloží
- Importujte připojení do OmniRoute prostřednictvím řídicího panelu

### Omezení

- Vlastní přihlašovací údaje OAuth vyžadují název domény (Google nepřijímá IP adresy jako identifikátory URI pro přesměrování)
- Pokud doménu nemáte, použijte místo toho možnost A nebo C

## 5. Řešení problémů: Když automatické nastavení selže

OmniRoute u většiny účtů zajišťuje zjištění projectId a úvodní registraci automaticky. Pokud proces selže, hlavní příčinou je obvykle jedna z následujících možností:

### Oblast účtu je blokována

**Příznak**: `agy login` vrátí zprávu „Kontrola způsobilosti selhala: Váš aktuální účet není způsobilý pro Antigravity, protože tato služba momentálně není ve vaší lokalitě dostupná.“

**Hlavní příčina**: Účty Google mají na backendu pole „Přiřazení země“, které se nastavuje při registraci. agy CLI a Cloud Code API toto pole striktně kontrolují — na rozdíl od webové verze Gemini, která kontroluje pouze vaši aktuální IP adresu.

> Chcete-li zkontrolovat nebo změnit oblast přiřazenou k vašemu účtu, navštivte [formulář Google pro přiřazení země](https://policies.google.com/country-association-form).

**Proč webová verze Gemini funguje, ale agy ne**:

- Webová verze Gemini / Google One: kontroluje pouze aktuální IP adresu (proxy stačí)
- agy CLI / Cloud Code API: čte pole Přiřazení země na backendu (proxy nepomůže)

**Náprava**:

1. Navštivte [formulář Google pro přiřazení země](https://policies.google.com/country-association-form), zatímco používáte IP adresu z USA
2. Odešlete žádost o změnu oblasti (vyberte možnost „Žiji v jiné zemi“)
3. Počkejte 1–24 hodin, než Google žádost zpracuje a odešle e-mailové oznámení
4. Poté by měl příkaz `agy login` uspět

### Účet nemá projekt Cloud Code

**Příznak**: Protokoly obsahují `loadCodeAssist returned no project id` a `onboardUser failed (400)`.

**Hlavní příčina**: Účet nebyl nikdy zaregistrován ve službě Google Cloud Code a automatická úvodní registrace selhala.

**Náprava**: Ručním spuštěním `agy login` aktivujte registraci do Cloud Code a poté obnovte token v řídicím panelu OmniRoute.

### Platnost tokenu vypršela nebo byl odvolán

**Příznak**: Chyby 401 v protokolech nebo zprávy „Platnost tokenu vypršela“.

**Náprava**: Obnovte token v části Řídicí panel → Poskytovatelé → agy → Klikněte na ikonu obnovení. Pokud byl odvolán samotný obnovovací token, budete se muset znovu ověřit prostřednictvím OAuth.
