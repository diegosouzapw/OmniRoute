Relaye (Vercel, Deno, Cloudflare) ukončují upstreamové připojení na
serverless backendu, takže OmniRoute může směrovat odchozí provoz ze stabilní oblasti a zároveň
uchovávat API klíč poskytovatele na straně serveru. Tento dokument popisuje dva režimy selhání,
se kterými se provozovatelé setkávají v produkci, a postupy obnovení, které OmniRoute
pro každý z nich nabízí.

## Jak se ukládá ověřování relayů

Když nasadíte relay přes **Nastavení → Fond proxy serverů → Nasadit relay**,
proces nasazení uloží ověřovací token relaye do JSON pole `notes` dané proxy:

- Pokud je nastaveno `STORAGE_ENCRYPTION_KEY`, token se uloží jako `relayAuthEnc`
  (v úložišti zašifrovaný pomocí AES).
- V opačném případě se uloží jako prostý text `relayAuth`.

Při zpracování požadavku vrátí `extractRelayAuth(notes)` kteroukoli přítomnou
formu, takže relay funguje i po restartech.

## Režim selhání 1 — token nelze po rotaci klíče dešifrovat

**Příznak:** relaye, které dříve fungovaly, nyní vracejí upstreamové chyby
`401`/ověřování po rotaci `STORAGE_ENCRYPTION_KEY` v prostředí nebo správci
tajných údajů. Uložený blob `relayAuthEnc` již nelze dešifrovat, takže
`extractRelayAuth` vrátí prázdný řetězec a relay neodešle žádné ověřovací
údaje.

**Obnovení — oprava na místě (bez opětovného nasazení):**

1. Otevřete **Nastavení → Fond proxy serverů**.
2. Řádky relayů, kterým chybí ověřovací údaje, zobrazují žlutý štítek
   `chybí ověření` a tlačítko **Opravit**.
3. Klikněte na **Opravit**. OmniRoute zavolá
   `POST /api/settings/proxies/[id]/repair-relay`, který:
   - dešifruje `relayAuthEnc` pomocí **aktuálního** klíče,
   - zapíše `relayAuth` v prostém textu zpět do `notes`,
   - vrátí `{ repaired: true, mode: "recovered" }`.

Relay obnoví obsluhu bez nutnosti znovu zadávat přihlašovací údaje pro nasazení.

Tento postup funguje pouze tehdy, pokud aktuální `STORAGE_ENCRYPTION_KEY` stále
dokáže blob dešifrovat. Pokud jste klíč zrotovali **bez** migrace, blob nelze
obnovit.

## Režim selhání 2 — neobnovitelný token (původní klíč již není dostupný)

**Příznak:** klikli jste na **Opravit** a obdrželi jste
`{ repaired: false, mode: "redeploy", status: 409 }`.

**Obnovení — opětovné nasazení:**

Uložený token nelze pomocí aktuálního klíče obnovit. Nasaďte relay znovu
ze stejného dialogového okna, které jste použili původně (nabídka **Nasadit relay** → Vercel / Deno
/ Cloudflare). Proces nasazení zapíše nový token (zašifrovaný aktuálním
klíčem) a štítek `chybí ověření` u daného řádku zmizí.

Pokud token nelze obnovit, tlačítko **Opravit** v uživatelském rozhraní samo
otevře dialogové okno opětovného nasazení, takže jej nemusíte ručně hledat.

## Režim selhání 3 — relay je dostupný, ale není v pořádku

**Příznak:** test proxy (tlačítko `rychlost`) ukazuje, že je relay v provozu,
ale požadavky přesto občas selhávají.

Zkontrolujte hlavičky informující o relayi, které vrací automatický testovací
požadavek OmniRoute (viz **Nastavení → Fond proxy serverů** a počítadla
`relayTested` / `relayAlive`):

- `x-relay-url` — který backend relaye odpověděl.
- `x-relay-mode` — `ts` | `bifrost` | `auto` pro daný požadavek.
- `x-relay-attempts` — kolik přeskoků přes relaye bylo před úspěchem vyzkoušeno.
- `x-relay-fallback` — `true`, pokud požadavek přešel z preferovaného
  backendu na TypeScriptový relay.

Vysoký podíl `x-relay-fallback` společně s nízkou hodnotou `relayAlive`
znamená, že backend sidecaru není v pořádku. Měli byste jej buď opravit, nebo
přepnout strategii backendu relaye na `ts` (viz `RELAY_BACKEND_STRATEGY.md`).

## Referenční dokumentace API

| Metoda | Cesta                                     | Tělo                    | Úspěch                                                                                                                                      | Selhání                                                                              |
| ------ | ----------------------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `POST` | `/api/settings/proxies/[id]/repair-relay` | `{ "id": "<proxyId>" }` | `200 { repaired: true, mode: "recovered" }` při opětovném odvození; `200 { repaired: false, mode: "noop" }`, pokud již existuje prostý text | `409 { mode: "redeploy" }` nelze obnovit; `400` nejde o typ relaye; `404` nenalezeno |

Seznamová trasa `GET /api/settings/proxies` připojuje ke každé položce
objekt `relayInfo: { isRelay, authMissing, repairMode }` bez tajných údajů,
aby dashboard mohl zobrazit možnost opravy, aniž by kdy došlo k odhalení tokenu.
