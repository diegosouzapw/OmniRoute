> **مصدر الحقيقة:** `src/lib/cloudAgent/` و`src/app/api/v1/agents/tasks/`
> **آخر تحديث:** 2026-06-28 — v3.8.40 (تحديث frontmatter؛ 4 وكلاء بما في ذلك cursor-cloud)

ينسّق OmniRoute وكلاء البرمجة المستضافين سحابيًا من جهات خارجية (Codex Cloud وCursor
وDevin وJules) على هيئة مهام طويلة الأمد. يُغلَّف كل وكيل خلف واجهة موحّدة بحيث
يمكن للعملاء إرسال مطالبة + عنوان URL لمستودع وتلقّي النتائج دون التعامل مع
واجهات API الخاصة بكل مزوّد.

مهمة وكيل السحابة **ليست** عملية إكمال محادثة عادية. بل هي وحدة عمل دائمة ومتعددة الخطوات
قد تستغرق من دقائق إلى ساعات، ويمكنها إنتاج طلب سحب بوصفه
ناتجًا لها، كما تدعم رسائل المتابعة وبوابات الموافقة على الخطة (لدى بعض المزوّدين).

## الوكلاء المدعومون

| معرّف المزوّد  | الفئة              | المصدر                                | عنوان URL الأساسي للخدمة الأصلية        | الموافقة على الخطة |
| -------------- | ------------------ | ------------------------------------- | --------------------------------------- | ------------------ |
| `jules`        | `JulesAgent`       | `src/lib/cloudAgent/agents/jules.ts`  | `https://jules.googleapis.com/v1alpha`  | نعم                |
| `devin`        | `DevinAgent`       | `src/lib/cloudAgent/agents/devin.ts`  | `https://api.devin.ai/v1`               | نعم                |
| `codex-cloud`  | `CodexCloudAgent`  | `src/lib/cloudAgent/agents/codex.ts`  | `https://api.openai.com/v1/codex/cloud` | لا (تلقائيًا)      |
| `cursor-cloud` | `CursorCloudAgent` | `src/lib/cloudAgent/agents/cursor.ts` | `https://api.cursor.com/v0`             | لا (تلقائيًا)      |

السجل: `src/lib/cloudAgent/registry.ts` — يصدّر `getAgent(providerId)` و
`getAvailableAgents()` و`isCloudAgentProvider(providerId)`. السجل عبارة عن
`Record<string, CloudAgentBase>` بسيط داخل الذاكرة يُملأ عند تحميل الوحدة.

## البنية

```
العميل (لوحة المعلومات / CLI / API)
  → POST /api/v1/agents/tasks (مصادقة الإدارة مطلوبة)
    → التحقق باستخدام CreateCloudAgentTaskSchema (Zod)
    → registry.getAgent(providerId)
    → getCloudAgentCredentials(providerId)
      └─ يجلب من getProviderConnections({ provider, isActive: true })
         (apiKey أولًا، ثم الرجوع إلى accessToken)
    → agent.createTask({ prompt, source, options }, credentials)
      └─ طلب HTTP POST إلى واجهة API الأصلية للمزوّد
      └─ يعيد CloudAgentTask بمعرّف داخلي + externalId
    → إدراج insertCloudAgentTask(...) في cloud_agent_tasks (SQLite)

الاستقصاء (مزامنة كسولة عند القراءة):
  GET /api/v1/agents/tasks/[id]
    → getCloudAgentTaskById(id)
    → agent.getStatus(externalId, credentials)  // يحدّث الحالة + الأنشطة
    → updateCloudAgentTask(...) بالحالة والنتيجة وcompleted_at الجديدة
    → إعادة المهمة بعد تسلسلها

التفاعلات:
  POST /api/v1/agents/tasks/[id]  المتن: { action: "approve" | "message" | "cancel" }
    → agent.approvePlan(externalId, credentials)          للإجراء "approve"
    → agent.sendMessage(externalId, message, credentials) للإجراء "message"
    → تتغير الحالة إلى "cancelled"                       للإجراء "cancel" (محلي فقط)
```

المزامنة **كسولة**: تُحدَّث الحالة من الخدمة الأصلية عند كل طلب `GET /tasks/[id]`.
لا توجد أداة استقصاء تعمل في الخلفية. ينبغي للوحات المعلومات التي تحتاج إلى حالة حديثة استقصاء نقطة نهاية GET
بفاصل زمني معقول.

## واجهة `CloudAgentBase`

المصدر: `src/lib/cloudAgent/baseAgent.ts`

```typescript
export interface AgentCredentials {
  apiKey: string;
  baseUrl?: string;
}

export interface CreateTaskParams {
  prompt: string;
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
}

export interface GetStatusResult {
  status: CloudAgentStatus;
  externalId?: string;
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
}

export abstract class CloudAgentBase {
  abstract readonly providerId: string;
  abstract readonly baseUrl: string;

  abstract createTask(p: CreateTaskParams, c: AgentCredentials): Promise<CloudAgentTask>;
  abstract getStatus(externalId: string, c: AgentCredentials): Promise<GetStatusResult>;
  abstract approvePlan(externalId: string, c: AgentCredentials): Promise<void>;
  abstract sendMessage(
    externalId: string,
    message: string,
    c: AgentCredentials
  ): Promise<CloudAgentActivity>;
  abstract listSources(
    c: AgentCredentials
  ): Promise<{ name: string; url: string; branch?: string }[]>;

  protected mapStatus(raw: string): CloudAgentStatus; // تحويل استدلالي من سلسلة المنبع إلى التعداد
  protected generateTaskId(): string; // `task_<ts>_<rand>`
  protected generateActivityId(): string; // `act_<ts>_<rand>`
}
```

تطرح `CodexCloudAgent.approvePlan` استثناءً عمدًا — إذ تُنشئ Codex Cloud الخطط تلقائيًا ولا تحتوي على بوابة موافقة. تُرجع `CodexCloudAgent.listSources` القيمة `[]`.

تُشغّل `CursorCloudAgent` وكلاء Cursor في الخلفية / السحابة عبر واجهة REST API الرسمية الخاصة بها (`api.cursor.com/v0`) باستخدام **مفتاح API لمستخدم أو لحساب خدمة** — وهو البديل الأكثر أمانًا ومن الطرف الأول لإعادة استخدام جلسة OAuth الخاصة ببيئة Cursor IDE (المزوّد `cursor`، الذي يتضمن تحذيرًا من خطر الحظر). وهي محوّل REST عادي (من دون اعتماد أصلي على `@cursor/sdk`). تطرح `approvePlan` استثناءً (يعمل وكلاء Cursor بصورة مستقلة)؛ وتسرد `listSources` المستودعات التي يمكن للمفتاح الوصول إليها. تُرجع Cursor تعدادات حالة بأحرف كبيرة (`CREATING`/`RUNNING`/`FINISHED`/`ERROR`)، وتُربط صراحةً بـ `CloudAgentStatus` المشترك. يمكن تجاوز `baseUrl` لكل بيانات اعتماد، بحيث يمكن تصحيح إصدار/مسار API من دون تغيير الشيفرة.

## أنواع المجال

المصدر: `src/lib/cloudAgent/types.ts`

```typescript
export const CLOUD_AGENT_STATUS = {
  QUEUED: "queued",
  RUNNING: "running",
  AWAITING_APPROVAL: "awaiting_approval",
  COMPLETED: "completed",
  FAILED: "failed",
  CANCELLED: "cancelled",
} as const;

export interface CloudAgentSource {
  repoName: string;
  repoUrl: string; // يجب أن يكون عنوان URL صالحًا
  branch?: string;
}

export interface CloudAgentResult {
  prUrl?: string;
  prNumber?: number;
  commitMessage?: string;
  diffUrl?: string;
  summary?: string;
  duration?: number; // بالثواني، عدد صحيح موجب
  cost?: number; // عدد عشري موجب
}

export interface CloudAgentActivity {
  id: string;
  type: "plan" | "command" | "code_change" | "message" | "error" | "completion";
  content: string;
  timestamp: string; // ISO 8601
  metadata?: Record<string, unknown>;
}

export interface CloudAgentTask {
  id: string; // معرّف `task_...` داخلي
  providerId: "jules" | "devin" | "codex-cloud" | "cursor-cloud";
  externalId?: string; // معرّف المزوّد في المنبع
  status: CloudAgentStatus;
  prompt: string; // من 1 إلى 10000 محرف
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
  createdAt: string;
  updatedAt: string;
  completedAt?: string;
}
```

## قاعدة البيانات

المصدر: `src/lib/cloudAgent/db.ts` — يُنشأ الجدول عند الحاجة عبر
`createCloudAgentTaskTable()` (ويُستدعى أيضًا من `src/lib/cloudAgent/index.ts` عند
استيراد الوحدة).

```sql
CREATE TABLE IF NOT EXISTS cloud_agent_tasks (
  id           TEXT PRIMARY KEY,
  provider_id  TEXT NOT NULL,
  external_id  TEXT,
  status       TEXT NOT NULL DEFAULT 'queued',
  prompt       TEXT NOT NULL,
  source       TEXT NOT NULL,             -- JSON
  options      TEXT DEFAULT '{}',         -- JSON
  result       TEXT,                       -- JSON
  activities   TEXT DEFAULT '[]',          -- JSON
  error        TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_provider ON cloud_agent_tasks(provider_id);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_status   ON cloud_agent_tasks(status);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_created  ON cloud_agent_tasks(created_at DESC);
```

يفرض `updateCloudAgentTask` **قائمة سماح للأعمدة** لمنع حقن SQL:
`status`، و`prompt`، و`source`، و`options`، و`result`، و`activities`، و`error`،
و`completed_at`. ويُتجاهل بصمت أي مفتاح آخر في التحديث الجزئي.

## REST API — دورة حياة المهمة

**المصادقة:** تتطلب جميع نقاط النهاية `/api/v1/agents/tasks*` **مصادقة الإدارة**
(`requireCloudAgentManagementAuth` يغلّف `requireManagementAuth` من
`src/lib/api/requireManagementAuth`). ويُطبَّق ذلك بعد الالتزام `588a0333`
(_"الإصلاح(auth): اشتراط مصادقة الإدارة لواجهات API الخاصة بالوكيل وفترة الانتظار"_).

| الطريقة | المسار                        | الغرض                                                       |
| ------- | ----------------------------- | ----------------------------------------------------------- |
| OPTIONS | `/api/v1/agents/tasks`        | طلب CORS التمهيدي                                           |
| GET     | `/api/v1/agents/tasks`        | سرد المهام (التصفية: `provider`، و`status`، و`limit≤500`)   |
| POST    | `/api/v1/agents/tasks`        | إنشاء مهمة (يرسلها إلى المزوّد الخارجي ويحفظها)             |
| DELETE  | `/api/v1/agents/tasks?id=...` | حذف المهمة حسب معرّف الاستعلام (لا **يلغي** المهمة خارجيًا) |
| OPTIONS | `/api/v1/agents/tasks/[id]`   | طلب CORS التمهيدي                                           |
| GET     | `/api/v1/agents/tasks/[id]`   | قراءة المهمة + مزامنة حالتها عند الحاجة من المزوّد الخارجي  |
| POST    | `/api/v1/agents/tasks/[id]`   | الإجراء: `approve` / `message` / `cancel`                   |
| DELETE  | `/api/v1/agents/tasks/[id]`   | حذف المهمة حسب معرّف المسار                                 |

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{

    "prompt": "Fix the bug in src/foo.ts where the parser returns null",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"

    "options": {
      "autoCreatePr": true,
      "planApprovalRequired": false
    }

```


### الإلغاء (الحالة المحلية فقط)

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \

```

يغيّر `cancel` قيمة `status` إلى `"cancelled"` في قاعدة البيانات المحلية، لكنه لا
يستدعي المزوّد الخارجي — إذ لا توجد عملية RPC للإيقاف في `CloudAgentBase`. لإيقاف
الفوترة لدى المزوّد الخارجي، أنهِ المهمة من وحدة التحكم الخاصة بالمزوّد.

## واجهة REST API — البنية التحتية لمزوّد الخدمات السحابية

تُستخدم نقاط النهاية المساعدة هذه ضمن `src/app/api/cloud/` بواسطة العملاء البعيدين
(واجهة CLI، أو تطبيق Electron، أو عمال المزامنة) لقراءة البيانات الوصفية لاتصال المزوّد
وحل الأسماء المستعارة للنماذج. وتتم مصادقتها باستخدام **مفتاح API عادي**
(عبر `validateApiKey`)، وليس مصادقة الإدارة المستخدمة بواسطة نقاط نهاية المهام.

| الطريقة | المسار                          | الغرض                                                                           |
| ------- | ------------------------------- | ------------------------------------------------------------------------------- |
| POST    | `/api/cloud/auth`               | التحقق من مفتاح API، وإرجاع بيانات اتصال وصفية محجوبة + أسماء النماذج المستعارة |
| PUT     | `/api/cloud/credentials/update` | تحديث `accessToken` / `refreshToken` / `expiresAt`                              |
| POST    | `/api/cloud/model/resolve`      | تحويل اسم نموذج مستعار إلى `{ provider, model }`                                |
| GET     | `/api/cloud/models/alias`       | عرض جميع الأسماء المستعارة للنماذج                                              |
| PUT     | `/api/cloud/models/alias`       | تعيين اسم مستعار لنموذج (ومزامنته تلقائيًا مع Cloud إذا كانت مفعّلة)            |

لا تُرجع `/api/cloud/auth` مطلقًا القيم الخام لـ `apiKey` / `accessToken` / `refreshToken`.
بل تُرجع `hasApiKey`، و`hasAccessToken`، و`hasRefreshToken`، ومعاينة محجوبة
(`maskedApiKey`: أول 4 أحرف + `****` + آخر 4 أحرف).

## تحديد بيانات الاعتماد

تقوم `getCloudAgentCredentials(providerId)` في `src/lib/cloudAgent/api.ts` بما يلي:

1. تحميل اتصالات المزوّد النشطة عبر `getProviderConnections({ provider: providerId, isActive: true })`.
2. تفضيل `apiKey` (بعد إزالة المسافات الزائدة) لكل اتصال، والرجوع إلى `accessToken` عند عدم توفره.
3. إرجاع أول رمز غير فارغ مغلفًا على النحو `{ apiKey: token }`.
4. إرجاع `null` إذا لم يُعثر على رمز صالح للاستخدام — وتستجيب واجهة API بالحالة `400` مع
   `"No active credentials configured for cloud agent provider: <id>"`.

يعني هذا أن وكلاء Cloud Agents يعيدون استخدام جدول Provider Connection نفسه الذي تستخدمه
مزوّدات LLM العادية. لتفعيل Jules، أنشئ اتصالًا نشطًا يحتوي على `provider: "jules"`
وقيمة معبأة في `apiKey`.

## لوحة المعلومات

المصدر: `src/app/(dashboard)/dashboard/cloud-agents/page.tsx`

صفحة React تستخدم `"use client"` وتقوم بما يلي:

- عرض المهام (مع الاستقصاء الدوري عبر `GET /api/v1/agents/tasks`).
- إرسال مهام جديدة عبر نموذج يتوافق مع `CreateCloudAgentTaskSchema`.
- عرض شارات الحالة (`queued`، و`running`، و`awaiting_approval`، و`completed`،
  و`failed`، و`cancelled`) وتصيير المخطط الزمني `activities[]`.
- إظهار `result.prUrl` / `commitMessage` / `summary` عندما تكون `status === "completed"`.

## التكامل مع A2A

يمكن عرض وكلاء Cloud Agents بوصفهم مهارات A2A من خلال تسجيل مهارة A2A تفوّض
معالج `tasks/send` الخاص بها إلى `getAgent(...).createTask(...)`، وتحويل أحداث حالة
مهام A2A إلى بروتوكول JSON-RPC 2.0. راجع [A2A-SERVER.md](./A2A-SERVER.md).

## إضافة وكيل Cloud Agent جديد

1. أنشئ `src/lib/cloudAgent/agents/<name>.ts` مع توسيع `CloudAgentBase`.
2. نفّذ `createTask`، و`getStatus`، و`approvePlan` (أو اطرح استثناءً إذا لم يكن منطبقًا)،
   و`sendMessage`، و`listSources`. استخدم `this.mapStatus(...)` لتوحيد الحالات.
3. سجّله في `src/lib/cloudAgent/registry.ts` ضمن `providerId` ثابت.
4. وسّع اتحاد القيم الحرفية لـ `providerId` في `src/lib/cloudAgent/types.ts`
   (`CloudAgentTask.providerId` و`CreateCloudAgentTaskSchema`).
5. أضف المزوّد إلى `src/shared/constants/providers.ts` إذا كان يحتاج إلى سجل اتصال.
   تحتاج المزوّدات المعتمدة على OAuth أيضًا إلى `src/lib/oauth/providers/`.
6. أضف اختبارات ضمن `tests/unit/cloud-agent-*.test.ts`.
7. حدّث هذا المستند وثابت `CLOUD_AGENTS` في لوحة المعلومات.

## الإعداد

| متغير البيئة     | الغرض                                                       |
| ---------------- | ----------------------------------------------------------- |
| `DATA_DIR`       | موقع قاعدة بيانات SQLite التي تحتوي على `cloud_agent_tasks` |
| `JWT_SECRET`     | مطلوب لمصادقة الإدارة على نقاط نهاية المهام                 |
| `API_KEY_SECRET` | مطلوب لتشفير بيانات اعتماد اتصال المزوّد عند تخزينها        |

لا توجد حاليًا متغيرات بيئة خاصة بـ Cloud-Agent — إذ تُخزَّن جميع الأسرار في
جدول `provider_connections`.
