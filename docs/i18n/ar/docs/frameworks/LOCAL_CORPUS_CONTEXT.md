## ما هي هذه الميزة

تتيح Local Corpus للمشغّل إتاحة دليل واحد معتمد صراحةً من الملفات النصية لخادم MCP الخاص بـ
OmniRoute. تبقى الملفات في دليلها الأصلي: لا يخزّن OmniRoute سوى مسار الجذر القياسي في SQLite،
ويحتفظ بفهرس بحث في الذاكرة. ولا ينسخ محتوى مجموعة النصوص إلى المستودع أو قاعدة البيانات.

يُحدَّث الفهرس تدريجيًا. يُعاد استخدام الملفات التي لم تتغير بناءً على الحجم ووقت التعديل،
بينما تُعاد قراءة الملفات المتغيرة وتُحسب تجزئتها باستخدام SHA-256، وتُزال الملفات المحذوفة.
يُحدِّث البحث أي فهرس مضى عليه أكثر من 30 ثانية؛ ويمكن للجهات المستدعية أيضًا طلب تحديث فوري.

## تهيئة المصدر

يتطلب مسار الإعدادات مصادقة الإدارة نفسها التي تتطلبها واجهات API الأخرى للإعدادات.
يجب أن يكون المسار المُرسل موجودًا بالفعل، وأن يكون مسار دليل مطلقًا.

```bash
# ربط دليل معتمد
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# التحقق من التهيئة وحالة الفهرس
curl http://localhost:20128/api/settings/local-corpus

# قطع الاتصال دون تغيير ملفات المصدر
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## أدوات MCP

تتطلب الأدوات الثلاث جميعها `read:local-corpus`. تعرض استجابات الأدوات المسارات النسبية
والاسم الأساسي للدليل الجذر، ولا تعرض مساره المطلق أبدًا.

| الأداة                | الوصف                                                                              |
| :-------------------- | :--------------------------------------------------------------------------------- |
| `local_corpus_status` | الإبلاغ عن حالة التهيئة، وحجم الفهرس، والحدود، ووقت آخر تحديث                      |
| `local_corpus_search` | البحث في النص المفهرس وإرجاع مقتطفات محدودة النطاق على مستوى الأسطر (حتى 20 نتيجة) |
| `local_corpus_read`   | قراءة نطاق محدود من الأسطر من ملف واحد مسموح به ذي مسار نسبي إلى مجموعة النصوص     |

أمثلة على مُدخلات MCP:

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## حدود الأمان

- تتمحور قائمة السماح حول النصوص: `.cfg`، و`.csv`، و`.geojson`، و`.htm`، و`.html`، و`.ini`،
  و`.js`، و`.json`، و`.jsonl`، و`.jsx`، و`.log`، و`.md`، و`.mjs`، و`.ps1`، و`.py`، و`.sh`،
  و`.sql`، و`.toml`، و`.ts`، و`.tsx`، و`.txt`، و`.xml`، و`.yaml`، و`.yml`.
- يجري تخطي الروابط الرمزية. تُحوَّل مسارات القراءة إلى صيغتها القياسية ويجب أن تبقى داخل
  الجذر المُهيأ؛ وتُرفض المسارات المطلقة ومحاولات اجتياز المسارات.
- تُستبعد أسماء الأدلة الحساسة والمُنشأة: `.build`، و`.codex`، و`.env`،
  و`.git`، و`.next`، و`.omniroute`، و`.ssh`، و`coverage`، و`dist`، و`node_modules`، و
  `secrets`.
- الحدود الافتراضية هي 5,000 ملف، و1 MiB لكل ملف، و64 MiB من إجمالي المحتوى المفهرس،
  ونحو 4,000 حرف لكل مقطع بحث، و400 سطر لكل عملية قراءة.
- تُعامل الملفات التي تحتوي على NUL على أنها غير نصية، ويجري تخطيها أو رفضها.

المستندات الثنائية، مثل PDF وDOCX والصور والأرشيفات، غير مدعومة عمدًا.
حوّلها إلى تنسيق نصي معتمد داخل الدليل المُهيأ قبل الفهرسة.

## ملاحظات تشغيلية

- يؤدي تغيير الجذر المُهيأ أو حذفه إلى مسح الفهرس المشترك الموجود في الذاكرة.
- تؤدي إعادة تشغيل العملية إلى التخلص من الفهرس؛ وتعيد عملية البحث التالية بناءه من المصدر
  المُهيأ.
- لا تفرض `local_corpus_status` إجراء فحص. استخدم `local_corpus_search` مع
  `refresh: true` عند الحاجة إلى إعادة فحص فورية.
- تُحتسب حالات فشل الفحص والقراءة أو تُعاد كأخطاء منقّحة؛ ولا تُعدَّل ملفات المصدر
  أبدًا.
