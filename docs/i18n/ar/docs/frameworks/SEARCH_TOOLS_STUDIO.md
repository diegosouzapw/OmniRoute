## نظرة عامة

تحوّل Search Tools Studio المسار `/dashboard/search-tools` من بيئة تجريبية بسيطة للبحث إلى
استوديو من ثلاث علامات تبويب يوحّد البحث في الويب، واستخلاص محتوى الويب، والمقارنة المتجاورة بين المزوّدين.

```
┌ أدوات البحث ───────────────────────────────────────────────────────────┐
│ [🔍 بحث] [📄 استخلاص] [⚖ مقارنة]                142ms · $0.001  </>    │
│ ⓘ [دليل الأنماط]                                                        │
├──────────────────────────────────────────┬─────────────────────────────┤
│  {محتوى علامة التبويب النشطة}            │ ─ الإعدادات                 │
│                                          │ المزوّد [تلقائي ∨]          │
│                                          │   🟢 Serper  $0.001         │
│                                          │   🟢 Tavily  $0.008         │
│                                          │   🔥 Firecrawl (جلب)        │
│                                          │ النوع [ويب | أخبار]         │
│                                          │ الصفحة كاملة [ ] (استخلاص) │
│                                          │ التنسيق [md|نص|html]        │
│                                          │ نموذج إعادة الترتيب [∨]     │
└──────────────────────────────────────────┴─────────────────────────────┘
```

## علامات التبويب

### علامة تبويب البحث

تطوّر المكوّنات الحالية `SearchForm` + `ResultsPanel` + `RerankPanel` إلى علامة تبويب:

- الاستعلام ← النتائج (العنوان، عنوان URL، المقتطف، درجة الصلة).
- بيانات المزوّد الوصفية في لوحة الإعدادات (التكلفة، الحصة، الحالة).
- قسم إعادة الترتيب: اختيار نموذج لإعادة الترتيب، وإعادة ترتيب النتائج، وعرض `positionDelta`.
- حالة فارغة تتضمن دعوة لاتخاذ إجراء عند عدم إعداد أي مزوّدي بحث.
- سجل البحث عبر `SearchHistory.tsx`.
- تستدعي `POST /v1/search` (نقطة النهاية الحالية، من دون تغييرات).

### علامة تبويب الاستخلاص

علامة تبويب جديدة لاستخراج المحتوى من عنوان URL عبر `POST /v1/web/fetch` (أُنشئت في الخطة 05):

- الإدخال: عنوان URL + مفتاح تبديل الصفحة الكاملة + محدد التنسيق (Markdown / نص / HTML).
- الإرسال ← الجلب ← عرض `ScrapeResult.tsx`.
- يعرض `ScrapeResult` معاينة Markdown + مفتاح تبديل العرض الخام.
- الحد الأقصى: إذا تجاوز نص الاستجابة **256 KB**، تعرض واجهة المستخدم `(مقتطع، عرض الخام)` وتفتح المحتوى الخام في نافذة Monaco منبثقة (D21).
- لوحة البيانات الوصفية: المزوّد (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search)، وزمن الاستجابة، والتكلفة، وحجم الاستجابة، وعدد الروابط.
- تستخدم الخطّاف `useScrapeFetch.ts`.

### علامة تبويب المقارنة

تشغّل الاستعلام/عنوان URL نفسه عبر ما يصل إلى **4 مزوّدين بالتوازي** (D22):

- أعمدة متجاورة لكل مزوّد.
- المقاييس: زمن الاستجابة، والتكلفة، وعدد النتائج، وحجم الاستجابة.
- حساب تداخل عناوين URL للبحث (عدد عناوين URL المشتركة مقارنةً بالنتيجة الأولية).
- تستدعي `POST /v1/search` (للبحث) أو `POST /v1/web/fetch` (للاستخلاص) لكل مزوّد.

## لوحة الإعدادات (مشتركة)

`SearchToolsConfigPane.tsx` — مرئية دائمًا وقابلة للطي.

| الحقل               | الملاحظات                                                         |
| ------------------- | ----------------------------------------------------------------- |
| المزوّد             | قائمة منسدلة مع شارة حالة (مُعدّ / مفقود / مقيّد المعدّل)         |
| النوع               | `web` أو `news` (للبحث فقط)                                       |
| الصفحة كاملة        | مفتاح تبديل للاستخلاص — يجلب الصفحة كاملة بدلًا من أول محتوى ظاهر |
| التنسيق             | `markdown` أو `text` أو `html` (للاستخلاص فقط)                    |
| نموذج إعادة الترتيب | نموذج اختياري لإعادة ترتيب النتائج بعد البحث                      |
| السجل               | قسم قابل للطي لسجل البحث                                          |

## SearchConceptCard

`SearchConceptCard.tsx` — ظاهر دائمًا، وأكورديون قابل للطي. يوضّح:

| المفهوم             | وصف مختصر                                                              |
| ------------------- | ---------------------------------------------------------------------- |
| **البحث**           | يجلب قائمة من نتائج الويب (العنوان، وعنوان URL، والمقتطف، ودرجة الصلة) |
| **الاستخراج**       | يستخرج المحتوى الكامل لعنوان URL (markdown أو نص أو HTML)              |
| **المقارنة**        | يشغّل الاستعلام نفسه في N من المزوّدين جنبًا إلى جنب                   |
| **إعادة الترتيب**   | يعيد ترتيب النتائج عبر LLM لتحسين مدى صلتها بالاستعلام                 |
| **تلقائي (الأرخص)** | يختار تلقائيًا أرخص مزوّد متاح                                         |

## كتالوج المزوّدين

يعرض `ProviderCatalog.tsx` قائمة المزوّدين الكاملة من `GET /api/search/providers`
(موسّعة في F4 لتشمل مزوّدي الجلب):

| `kind` | `"search"` (20 مزوّدًا) أو `"fetch"` (firecrawl، jina-reader، tavily-search، tinyfish، nimble-search، anysearch-search) |

تُشتق الحالة **وقت الطلب** من خلال التحقق من وجود بيانات الاعتماد وما إذا كانت
جميع المفاتيح في فترة تهدئة حاليًا.

## تصدير الكود

تقوم `ExportCodeModal` (المستوردة من Playground Studio) و`codeExport.ts` بإنشاء
مقتطفات curl / Python / TypeScript لكل من استدعاءات `/v1/search` و`/v1/web/fetch`.
يكون العنصر النائب لمفتاح API دائمًا `$OMNIROUTE_API_KEY` (D11، مشترك مع Playground Studio).

## تغييرات الواجهة الخلفية

كان يلزم تغيير واحد فقط في الواجهة الخلفية لهذه الميزة:

### توسيع `GET /api/search/providers`

تم توسيع `src/app/api/search/providers/route.ts` من أجل:

- تضمين مزوّدي الجلب الستة جميعًا (`firecrawl`، `jina-reader`، `tavily-search`، `tinyfish`، `nimble-search`، `anysearch-search`) في المصفوفة.
- إضافة `kind: "search" | "fetch"` إلى كل عنصر.
- إضافة `status: "configured" | "missing" | "rate_limited"`، مشتقة من حالة بيانات الاعتماد الحالية.
- الحفاظ على التوافق مع الإصدارات السابقة — تظل الحقول الموجودة (`id`، `name`، وما إلى ذلك) دون تغيير.
