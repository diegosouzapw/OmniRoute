> **مصدر الحقيقة:** `src/lib/plugins/` (`marketplace.ts`، `manager.ts`، `manifest.ts`،
> `scanner.ts`، `loader.ts`)، و`src/app/api/plugins/`، و
> `src/app/(dashboard)/dashboard/plugins/`
> **آخر تحديث:** 2026-06-28 — v3.8.40

يأتي OmniRoute مزودًا بنظام إضافات على غرار WordPress. الإضافات هي أدلة
مستقلة بذاتها — يحتوي كل منها على ملف بيان `plugin.json` وملف دخول — وترتبط
بمسار معالجة الطلبات (`onRequest` / `onResponse` / `onError`) وبأحداث
دورة الحياة (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`).

يمثّل **سوق الإضافات** طبقة الاكتشاف المبنية فوق ذلك النظام. وهو يوفّر
كتالوجًا قابلًا للتصفح للإضافات المتاحة للتثبيت. يستخدم الكتالوج افتراضيًا
سجلًا أوليًا مدمجًا صغيرًا؛ ويمكن للمشغّل توجيهه إلى عنوان URL لسجل بعيد
مخصص، وفي هذه الحالة تُحصّن عملية الجلب بواسطة آلية حماية من SSRF تحلّ أسماء
DNS (راجع [الأمان](#security)).

جميع مسارات الإضافات **مقصورة على واجهة الاسترجاع** (المستوى 1 — `LOCAL_ONLY`):
تحمّل الإضافات الشيفرة وتنفذها في عمليات فرعية، ولذلك يتعذر الوصول إلى
المسارات من أي مصدر غير واجهة الاسترجاع، بصرف النظر عن المصادقة. راجع
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md).

## كيفية ترابط المكونات

```
لوحة المعلومات (/dashboard/plugins)
  ├─ علامة تبويب "المثبّتة"  → GET /api/plugins            (listPlugins)
  │                            POST /api/plugins/scan      (pluginManager.scan)
  │                            POST /api/plugins/{name}/activate|deactivate
  │                            DELETE /api/plugins/{name}   (إلغاء التثبيت)
  └─ علامة تبويب "السوق"      → GET /api/plugins/marketplace
                                 → listMarketplacePlugins()
                                   ├─ لا يوجد عنوان URL مخصص → SEED_REGISTRY المدمج
                                   └─ عنوان URL مخصص → آلية حماية SSRF ‏isSafeMarketplaceUrl()
                                                       → safeOutboundFetch(guard:"public-only")
```

- **طبقة السجل** — `src/lib/plugins/marketplace.ts`: تسرد الكتالوج / تبحث فيه،
  مع الرجوع إلى السجل الأولي عند حدوث أي فشل.
- **طبقة دورة الحياة** — `src/lib/plugins/manager.ts` (الكائن المفرد `pluginManager`):
  التثبيت، والترقية، والتفعيل، وإلغاء التفعيل، وإلغاء التثبيت، والفحص، والتحميل عند بدء التشغيل.
- **طبقة البيان** — `src/lib/plugins/manifest.ts`: مخطط Zod + القيم الافتراضية
  لملف `plugin.json`.
- **الماسح** — `src/lib/plugins/scanner.ts`: يكتشف الإضافات الموجودة على القرص ضمن
  دليل الإضافات.
- **المحمّل** — `src/lib/plugins/loader.ts`: يشغّل كل إضافة في عملية فرعية
  معزولة ويتوسط في استدعاءات نقاط الارتباط عبر IPC.

## كتالوج السوق

تعيد `listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) قائمة من
كائنات `MarketplaceEntry`:

| الحقل         | النوع    | ملاحظات                                  |
| ------------- | -------- | ---------------------------------------- |
| `name`        | string   | اسم الإضافة بصيغة kebab-case             |
| `version`     | string   | semver                                   |
| `description` | string   | ملخص قصير                                |
| `author`      | string   | المؤلف / المؤسسة                         |
| `license`     | string   | معرّف ترخيص بنمط SPDX                    |
| `downloadUrl` | string   | عنوان URL لتنزيل المصدر (قد يكون فارغًا) |
| `repository`  | string?  | عنوان URL اختياري للمستودع               |
| `tags`        | string[] | وسوم البحث/التصفية                       |
| `downloads`   | number   | عدد التنزيلات                            |
| `rating`      | number   | 0–5                                      |
| `verified`    | boolean  | ما إذا كان الإدخال معلّمًا على أنه موثّق |
| `lastUpdated` | string   | سلسلة تاريخ بصيغة شبيهة بـ ISO           |

عند عدم تكوين عنوان URL لسجل مخصص، يكون الكتالوج هو `SEED_REGISTRY` المدمج
(ويتضمن حاليًا `request-logger` و`rate-limiter` و`cost-tracker`
و`theme-manager`). يظل السجل الأولي متاحًا دائمًا — فإذا تعذر الوصول إلى سجل
بعيد مُكوّن، أو أعاد حالة غير `200`، أو أعاد محتوى غير معروف، تسجّل
`listMarketplacePlugins()` تحذيرًا وتعود إلى القائمة الأولية.

> ملاحظة: **كتالوج** السوق (التصفح/البحث) موصول بالكامل من البداية إلى النهاية،
> لكن **التثبيت** بنقرة واحدة من السوق عبر الكتالوج لم يُنفذ بعد — إذ يعرض زر
> "تثبيت" في لوحة المعلومات ضمن إدخال السوق حاليًا إشعارًا يفيد بأنه
> "قريبًا". يتم التثبيت حاليًا من خلال مسار التثبيت من مسار محلي
> (`POST /api/plugins`) والاكتشاف على القرص (`POST /api/plugins/scan`).

## واجهة REST API

تتطلب جميع نقاط النهاية مصادقة إدارية (`requireManagementAuth`) **كما أنها**
متاحة عبر واجهة loopback فقط — إذ إن `/api/plugins` و`/api/plugins/` مدرجتان في
`LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`).

| نقطة النهاية                     | الطريقة | الوصف                                                       |
| -------------------------------- | ------- | ----------------------------------------------------------- |
| `/api/plugins`                   | GET     | عرض الإضافات المثبتة (مع عامل تصفية اختياري `?status=`)     |
| `/api/plugins`                   | POST    | تثبيت إضافة من مسار محلي مطلق                               |
| `/api/plugins/scan`              | POST    | فحص دليل الإضافات وتسجيل الإضافات الجديدة                   |
| `/api/plugins/marketplace`       | GET     | عرض إدخالات كتالوج السوق                                    |
| `/api/plugins/[name]`            | GET     | الحصول على تفاصيل إضافة مثبتة                               |
| `/api/plugins/[name]`            | DELETE  | إلغاء تثبيت إضافة                                           |
| `/api/plugins/[name]/activate`   | POST    | التفعيل (التحميل + تسجيل الخطافات)                          |
| `/api/plugins/[name]/deactivate` | POST    | إلغاء التفعيل (تشغيل `onDeactivate`، وإلغاء تسجيل الخطافات) |
| `/api/plugins/[name]/config`     | GET     | الحصول على إعدادات الإضافة + مخطط الإعدادات                 |
| `/api/plugins/[name]/config`     | PUT     | تحديث إعدادات الإضافة (مع التحقق منها مقابل المخطط)         |

يقبل عامل التصفية `status` في `GET /api/plugins` إحدى القيم
`installed` / `active` / `inactive` / `error`. تؤدي القيمة غير الصالحة إلى إرجاع `400`.

### عرض الإضافات المثبتة

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### التثبيت من مسار محلي

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

يجب أن يكون `path` **مطلقًا**، ولا يجوز أن يحتوي على مقاطع اجتياز `..` أو
بايتات فارغة (يفرض ذلك Zod). يجب أن يحتوي دليل المصدر على ملف
`plugin.json` صالح (أو أن يكون دليلًا أبًا لملف كهذا). عند النجاح، تكون الاستجابة `201` مع
صف الإضافة المثبتة.

### تصفح السوق

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### تحديث إعدادات الإضافة

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

يتحقق `PUT .../config` من كل قيمة مقدمة مقابل `configSchema` الخاص بالإضافة
(المعلن في ملف البيان): تراعي حقول `number` القيمتين `min`/`max`،
ويجب أن تتطابق حقول `select` مع `enum` المعلن. يُسمح بتمرير المفاتيح غير الموجودة
في المخطط.

## الإعدادات

### دليل الإضافات

توجد الإضافات ضمن دليل بيانات OmniRoute:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (أو أي ملف يشير إليه manifest.main)
```

تحدد `getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) ذلك الدليل عبر
ثلاث خطوات:

1. **`OMNIROUTE_PLUGINS_DIR`**، عند تعيينه — يُستخدم حرفيًا، بصرف النظر عن قيمة `HOME`. هذا هو
   الخيار الصريح لـ Docker/K8s، حيث تُربط شجرة الإضافات بمسار
   لا تكون له عادةً أي صلة بدليل المنزل الخاص بالحاوية (#11827).
2. `<home>/.omniroute/plugins`، حيث تأتي `<home>` من متغيري البيئة `HOME` / `USERPROFILE`.
3. `/tmp/.omniroute/plugins`، عندما لا تصدّر العملية أي دليل منزل على الإطلاق.

يُسجَّل الدليل المحدد مرة واحدة عند بدء التشغيل باسم `scanner.dir_resolved`، مع ذكر
المدخل الذي تم اختياره (`OMNIROUTE_PLUGINS_DIR` أو `home` أو `no-home-fallback`) — ولذلك فإن الصورة
التي تنتقل بصمت إلى الخطوة 3 توضح ذلك، بدلًا من الاكتفاء بالإبلاغ عن قائمة إضافات فارغة.
يكتشف `POST /api/plugins/scan` أي دليل فرعي هناك يحتوي على ملف
`plugin.json` صالح ويسجله؛ والدليل نفسه هو الجذر الذي تنسخ
`pluginManager.install()` الإضافات إليه، ولذلك ينقل التجاوز الاكتشاف
والتثبيت معًا.

> **`OMNIROUTE_PLUGINS_DIR` ليس `OMNIROUTE_PLUGIN_PATH`.** لا يقرأ الأخير سوى
> محمّل إضافات الأوامر في CLI (`bin/cli/plugins.mjs`) للعثور على حزم npm من النمط `omniroute-cmd-*`
> التي تضيف أوامر فرعية إلى `omniroute` — ولا يؤثر في الماسح وقت التشغيل
> الموصوف هنا. راجع [PLUGINS.md](./PLUGINS.md) لمعرفة تفاصيل ذلك الجانب.

### عنوان URL مخصص لسجل السوق

يُقرأ مصدر كتالوج السوق من الإعداد `pluginMarketplaceUrl`
(`src/lib/plugins/marketplace.ts` يقرأ `settings.pluginMarketplaceUrl`). عند
تعيينه إلى عنوان URL من نوع `http(s)`، تجلب `listMarketplacePlugins()` ذلك العنوان وتقبل
إما مصفوفة JSON من الإدخالات في المستوى الأعلى أو كائنًا يحتوي على مصفوفة `plugins`؛
وتُستبعد الإدخالات التي لا تحتوي على `name` من نوع سلسلة نصية. عند عدم تعيينه (أو عندما يفشل الجلب
في اجتياز حماية SSRF / يعيد استجابة غير صالحة)، يُستخدم سجل البذور المضمّن.

تعرض علامة تبويب "السوق" في لوحة المعلومات حقلًا لعنوان URL هذا (تُقرأ قيمته مجددًا من
`GET /api/settings`).

> ملاحظة تنفيذية: يرسل إجراء "حفظ" في لوحة المعلومات
> `pluginMarketplaceUrl` إلى `PATCH /api/settings`. وقت كتابة هذا النص، لم يكن هذا
> المفتاح معلنًا في `updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`)، لذا تحقّق من استمرارية تخزينه في
> إصدارك قبل الاعتماد عليه — إذ يحترم مسار **القراءة** (`getSettings()` →
> `listMarketplacePlugins()`) المفتاح بمجرد وجوده في مخزن الإعدادات.

## الأمان

### مستوى المسار — الاسترجاع المحلي فقط

تنفّذ الإضافات تعليمات برمجية في عمليات فرعية مُنشأة، لذا يُصنَّف نطاق `/api/plugins`
بأكمله على أنه `LOCAL_ONLY` (المستوى 1). يُطبَّق التحقق من الاسترجاع المحلي
دائمًا **قبل** أي تحقق من المصادقة، ولذلك حتى رمز إدارة مُسرَّب يصل
إلى الجهاز عبر نفق لا يمكنه تثبيت إضافة أو تفعيلها أو إلغاء تثبيتها.
راجع [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md)
والقاعدتين الصارمتين #15 / #17.

### حارس SSRF لسجل السوق

عنوان URL المخصّص للسجل هو إعداد يمكن للمهاجم التأثير فيه، لذلك قبل
جلبه تمرّره `listMarketplacePlugins()` عبر طبقتين:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - يرفض أي شيء لا يستخدم `http:` / `https:`.
   - يرفض المضيفين الحرفيين الخاصين/ذوي الاسترجاع المحلي/المحليين للوصلة/ULA ‏(IPv4 **و** IPv6،
     بما في ذلك عناوين IPv4 المضمّنة) عبر `isPrivateHost` القياسية
     (`src/shared/network/outboundUrlGuard.ts`).
   - يحل سجلات **كل من** `A` و`AAAA` ويرفض الطلب إذا كان **أي** عنوان
     محلول خاصًا — ما يسد مسار التجاوز من اسم مضيف عام ← إلى عنوان IP خاص.
   - **يفشل بشكل مغلق**: يؤدي فشل حل DNS إلى رفض عنوان URL.
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`**
   (`src/shared/network/safeOutboundFetch.ts`): يعيد تطبيق حارس URL العام فقط
   وقت الجلب، كما **يحظر عمليات إعادة التوجيه** (لمنع التحول من عنوان عام ← إلى عنوان خاص عبر `30x`).

لا يؤدي فشل عنوان URL في أي من الطبقتين إلى إلغاء الطلب — إذ يعود السوق
بصمت إلى سجل البذور المضمّن ويسجّل تحذيرًا.

> جرى تعزيز هذا الحارس في PR #3774 خصيصًا لحل سجلات A + AAAA واستخدام

### عزل تنفيذ الإضافات

- **عزل العمليات** — تنشئ `loadPlugin()` (`src/lib/plugins/loader.ts`)
  كل إضافة في عملية Node.js فرعية منفصلة وتتواصل معها عبر IPC.
  تخضع استدعاءات الخطافات لمهلة زمنية مع تصعيد من `SIGTERM` ← إلى `SIGKILL`.
- **قائمة السماح لمتغيرات البيئة** — لا تتلقى العملية الفرعية إلا مجموعة مدرجة في قائمة السماح من متغيرات
  البيئة؛ ولا تُمنح المجموعة الأوسع إلا عندما يطلب البيان
  إذن `env`.
- **احتواء المسار** — تتحقق عمليات التثبيت/الترقية/إلغاء التثبيت من أن دليل الإضافة
  و`manifest.main` يُحلّان **داخل** جذر الإضافات المُدار
  قبل أي نسخ أو حذف تكراري (للحماية من مسارات قاعدة البيانات المتلاعب بها
  واجتياز `../` في `manifest.main`). يحل التفعيل الروابط الرمزية عبر
  `realpath` ويرفض تحميل نقطة دخول تتجاوز دليل الإضافة.
- **تثبيت اختياري للتكامل** — يجوز للبيان تعريف حقل `integrity`
  (`sha256-<base64>`، بتنسيق SRI). عند وجوده، يتحقق المُحمِّل من تجزئة
  ملف الدخول وقت التحميل ويرفض التفعيل عند عدم التطابق. وهذه آلية اختيارية
  لاكتشاف العبث، **وليست** حدًا أمنيًا — فالتوجيه المقصور على الاسترجاع المحلي
  ونموذج الأذونات هما الحدود الفعلية.

## البيان (`plugin.json`)

يجري التحقق منه بواسطة `PluginManifestSchema` (`src/lib/plugins/manifest.ts`):

| الحقل              | النوع     | ملاحظات                                                     |
| ------------------ | --------- | ----------------------------------------------------------- |
| `name`             | string    | مطلوب؛ بصيغة kebab-case ‏(`^[a-z0-9-]+$`)، من 1 إلى 100 حرف |
| `version`          | string    | مطلوب؛ بصيغة semver ‏(`MAJOR.MINOR.PATCH`)                  |
| `description`      | string?   | ≤ 500 حرف                                                   |
| `author`           | string?   | ≤ 200 حرف                                                   |
| `license`          | string?   | القيمة الافتراضية `MIT`                                     |
| `main`             | string?   | ملف الدخول؛ القيمة الافتراضية `index.js`                    |
| `source`           | enum?     | `local` \| `marketplace` (القيمة الافتراضية `local`)        |
| `tags`             | string[]? | وسوم البحث                                                  |
| `requires`         | object?   | `{ omniroute?, permissions[] }`                             |
| `hooks`            | object?   | قيم منطقية تحدد الخطافات التي تنفذها الإضافة                |
| `skills`           | object[]? | تعريفات اختيارية للمهارات                                   |
| `enabledByDefault` | boolean?  | التفعيل تلقائيًا عند التثبيت                                |
| `configSchema`     | object?   | خريطة حقول الإعداد (`string`/`number`/`boolean`/`select`)   |
| `integrity`        | string?   | تثبيت اختياري لملف الدخول بصيغة `sha256-<base64>`           |

تُختار الأذونات من التعداد
`network` / `file-read` / `file-write` / `env` / `exec`.

## تدفق دورة الحياة

```
install (POST /api/plugins، المسار)
  → فحص/التحقق من ملف البيان → النسخ إلى منطقة التجهيز → التأكد من وجود main داخل الدليل
  → إعادة تسمية ذرّية إلى ~/.omniroute/plugins/<name> → إدراج صف في قاعدة البيانات
  → تشغيل onInstall → إذا كان enabledByDefault: التفعيل

activate (POST /api/plugins/{name}/activate)
  → التحقق من الاحتواء باستخدام realpath → loadPlugin() (إنشاء عملية فرعية)
  → تسجيل الخطافات المعلنة → status = "active" → تشغيل onActivate

deactivate (POST /api/plugins/{name}/deactivate)
  → تشغيل onDeactivate (قبل إلغاء التسجيل) → إلغاء تسجيل الخطافات
  → إنهاء العملية الفرعية → status = "inactive"

uninstall (DELETE /api/plugins/{name})
  → إلغاء التفعيل إذا كانت الإضافة نشطة → تشغيل onUninstall
  → حذف متكرر لدليل الإضافة بعد التحقق من الاحتواء → حذف صف قاعدة البيانات
```

تؤدي إعادة تشغيل `install` على دليل يحتوي ملف بيان بإصدار **أحدث بشكل صارم**
من الإصدار المثبّت إلى ترقية تلقائية (إعادة تثبيت نظيفة؛ تُعاد التهيئة إلى
القيم الافتراضية). ويُرفض الإصدار المطابق أو الأقدم.

## قاعدة البيانات

الجدول `plugins` (الترحيل `076_create_plugins.sql`):

| العمود          | النوع   | ملاحظات                                             |
| --------------- | ------- | --------------------------------------------------- |
| `id`            | TEXT PK | UUID                                                |
| `name`          | TEXT    | فريد                                                |
| `version`       | TEXT    | semver؛ القيمة الافتراضية `1.0.0`                   |
| `description`   | TEXT    | اختياري                                             |
| `author`        | TEXT    | اختياري                                             |
| `license`       | TEXT    | القيمة الافتراضية `MIT`                             |
| `main`          | TEXT    | ملف نقطة الدخول؛ القيمة الافتراضية `index.js`       |
| `source`        | TEXT    | القيمة الافتراضية `local`                           |
| `tags`          | TEXT    | مصفوفة JSON؛ القيمة الافتراضية `[]`                 |
| `status`        | TEXT    | `installed` \| `active` \| `inactive` \| `error`    |
| `enabled`       | INT     | 0/1؛ القيمة الافتراضية 0                            |
| `manifest`      | TEXT    | ملف البيان الكامل بصيغة JSON                        |
| `config`        | TEXT    | JSON؛ القيمة الافتراضية `{}`                        |
| `config_schema` | TEXT    | JSON؛ القيمة الافتراضية `{}`                        |
| `hooks`         | TEXT    | مصفوفة JSON لأسماء الخطافات المعلنة؛ الافتراضي `[]` |
| `permissions`   | TEXT    | مصفوفة JSON؛ القيمة الافتراضية `[]`                 |
| `plugin_dir`    | TEXT    | دليل التثبيت المطلق                                 |
| `error_message` | TEXT    | يُعيّن عندما تكون `status = "error"`                |
| `installed_at`  | TEXT    | `datetime('now')`                                   |
| `updated_at`    | TEXT    | `datetime('now')`                                   |
| `activated_at`  | TEXT    | يُعيّن عند التفعيل                                  |

تُتتبّع مقاييس الإضافات وتحليلاتها في جداول إضافية
(`090_plugin_metrics.sql`، `091_plugin_analytics.sql`).

## لوحة المعلومات

توفر صفحة لوحة المعلومات في `/dashboard/plugins`
(`src/app/(dashboard)/dashboard/plugins/page.tsx`) علامتي تبويب:

- **المثبّتة** — تعرض الإضافات المثبّتة مع الخطافات المعلنة الخاصة بها، ومفتاح
  تبديل للتفعيل/إلغاء التفعيل، وزر لإلغاء التثبيت، وإجراء "البحث عن إضافات"
  (`POST /api/plugins/scan`).
- **السوق** — تعرض الكتالوج من `GET /api/plugins/marketplace` مع حقل
  لتعيين عنوان URL المخصص للسجل.

توجد صفحة إعدادات خاصة بكل إضافة في `/dashboard/plugins/[name]/config`
(`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`).
