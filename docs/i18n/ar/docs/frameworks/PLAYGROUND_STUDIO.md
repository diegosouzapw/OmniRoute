## نظرة عامة

يحوّل Playground Studio المسار `/dashboard/playground` من محرر بسيط قائم على Monaco إلى
مساحة عمل اختبار متكاملة الميزات. ويستبدل الملف القديم `page.tsx` بهيكل `PlaygroundStudio`
يعرض أربع علامات تبويب ولوحة إعدادات مشتركة.

```
┌ Playground ──────────────────────────────────────────────────────────┐
│ [💬 الدردشة] [⚖ المقارنة] [{} API] [🔧 الإنشاء]  142↑ 38↓ · $0.002 </>│
├──────────────────────────────────────────┬───────────────────────────┤
│  {محتوى علامة التبويب النشطة}           │ ─ الإعدادات               │
│                                          │ نقطة النهاية [chat ∨]     │
│                                          │ النموذج [gpt-5.4 ∨]       │
│                                          │ النظام [منطقة نص]         │
│                                          │ الحرارة ▕▕▔▔ 0.7          │
│                                          │ الإعدادات المسبقة          │
│                                          │ [▾ تحميل][حفظ]             │
│                                          │ [✨ تحسين المطالبة]         │
└──────────────────────────────────────────┴───────────────────────────┘
```

## علامات التبويب

### علامة تبويب الدردشة

تطوّر `ChatPlayground.tsx` إلى بيئة عمل متعددة الجولات تدعم التدفق:

- عرض Markdown بالكامل عبر `MarkdownMessage.tsx` (كتل التعليمات البرمجية، والجداول، والقوائم، والروابط).
- تُستمد مطالبة النظام من لوحة الإعدادات المشتركة.
- عدد الرموز/التكلفة لكل رسالة (رموز المطالبة + رموز الإكمال).
- إعادة توليد الرد الأخير.
- الإرسال إلى `POST /v1/chat/completions` مع تدفق SSE.

### علامة تبويب المقارنة

عامل التميّز الرئيسي للوكيل: تشغيل مطالبة واحدة عبر ما يصل إلى **4 نماذج بالتوازي**.

- ما يصل إلى 4 أعمدة، يتدفق كل منها بصورة مستقلة من `/v1/chat/completions`.
- زر `+ إضافة نموذج` (اختصار Cmd+K) لإضافة أعمدة.
- يؤدي `تشغيل الكل ▶` إلى تشغيل جميع التدفقات في الوقت نفسه عبر `Promise.all` مع `AbortController` خاص بكل عمود.
- يؤدي أمر **إلغاء الكل** العام إلى إيقاف كل التدفقات الجارية.
- يعرض `ProviderMetrics` لكل عمود كلاً من TTFT وTPS والرموز والتكلفة التقديرية في الوقت الفعلي.
- تحمل المقاييس تسمية **"تقدير من جانب العميل"** (D12) — وتُقاس بدءاً من أول جزء SSE.

### علامة تبويب API

تحافظ على محرر Monaco الأصلي بنسبة 100% للمستخدمين المتقدمين (D14):

- 10 نقاط نهاية: إكمالات الدردشة، والإكمالات، والتضمينات، والصور، والصوت، والكلام، والنسخ، والإشراف، وإعادة الترتيب، والبحث.
- رفع ملفات متعددة الوسائط.
- تدفق SSE مع مخرجات في الوقت الفعلي.
- مغلّفة باسم `ApiTab.tsx` (تُحمّل عند الطلب، `ssr: false`).

### علامة تبويب الإنشاء

واجهة مستخدم للأدوات/استدعاء الدوال والمخرجات المنظّمة:

- `ToolsBuilder.tsx` — إضافة/تحرير/إزالة `tools[]` باستخدام محرر مخطط JSON لكل أداة.
  تتحقق من صحة المعاملات عبر `ToolDefinitionSchema` (Zod).
- `StructuredOutputEditor.tsx` — تبديل وضع JSON + محرر مخطط JSON.
  يتحقق من صحة الاستجابة وفقاً للمخطط عبر `StructuredOutputSchema` (Zod).
- إرسال الطلب إلى `/v1/chat/completions` باستخدام `tools[]` و/أو `response_format`.

## جزء الإعدادات (مشترك)

`StudioConfigPane.tsx` — ظاهر دائمًا وقابل للطي.

| الحقل             | المكوّن               | ملاحظات                                                                |
| ----------------- | --------------------- | ---------------------------------------------------------------------- |
| نقطة النهاية      | `<select>`            | 10 خيارات مطابقة لـ `PlaygroundEndpoint`                               |
| النموذج           | `<input>`             | نص حر، مثل `openai/gpt-4o`                                             |
| موجّه النظام      | `<textarea>`          | يُمرَّر إلى جميع علامات التبويب                                        |
| المعلمات          | `ParamSliders`        | temperature، max_tokens، top_p، presence/frequency penalty، seed، stop |
| الإعدادات المسبقة | `PresetPicker`        | تحميل/حفظ لقطات إعدادات مسماة (محفوظة في قاعدة البيانات)               |
| تحسين الموجّه     | `ImprovePromptButton` | يفتح نافذة تحذير الحصة، ويستدعي `/api/playground/improve-prompt`       |

تُرفع الحالة إلى `PlaygroundStudio.tsx` وتُمرَّر إلى جميع علامات التبويب. يحافظ التبديل بين علامات التبويب
على حالة الإعدادات.

## مُحسِّن الموجّه

`ImprovePromptButton.tsx` → `useImprovePrompt.ts` → `POST /api/playground/improve-prompt`:

1. تحذّر النافذة بأن العملية "ستستهلك من الحصة".
2. عند التأكيد، ترسل `{ system, prompt, model, tone }` إلى المسار.
3. يستدعي المسار `/v1/chat/completions` داخليًا باستخدام `promptImprover.META_SYSTEM_PROMPT`.
4. يُرجع `{ improvedSystem?, improvedPrompt?, tokensIn, tokensOut }`.
5. تُحدّث واجهة المستخدم موجّه النظام في جزء الإعدادات وموجّه المستخدم في علامة تبويب الدردشة.

## الإعدادات المسبقة

`PresetPicker.tsx` → `usePresets.ts` → `/api/playground/presets/*`:

- تُخزَّن في جدول SQLite المسمى `playground_presets` (الترحيل `084_playground_presets.sql`).
- يخزّن كل إعداد مسبق: `name`، و`endpoint`، و`model`، و`system`، و`params_json`، و`created_at`.
- عمليات CRUD: سرد عبر `GET`، وإنشاء عبر `POST`، و`GET /:id`، و`PUT /:id`، و`DELETE /:id`.

## مقاييس البث

`useStreamMetrics.ts` + `streamMetrics.ts` (دالة نقية):

- `start()` — يسجّل وقت بدء الطلب.
- `onFirstChunk()` — يسجّل TTFT.
- `onChunk(n)` — يجمع عدد رموز الإكمال.
- `finish(usage?)` — يحسب المقاييس النهائية: `ttftMs`، و`totalMs`، و`tps`، و`tokensIn`، و`tokensOut`، و`costUsd`.
- التسعير مأخوذ من الجدول الثابت في `src/lib/playground/types.ts` (موسوم بأنه "تقديري" — D13).

## مسارات الواجهة الخلفية

| الطريقة  | المسار                           | المعالج                                                                                                    |
| -------- | -------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `POST`   | `/api/playground/improve-prompt` | يتحقق باستخدام Zod من `ImprovePromptRequestSchema`؛ ويستدعي `/v1/chat/completions` باستخدام الموجّه الوصفي |
| `GET`    | `/api/playground/presets`        | يُرجع `{ presets: PlaygroundPresetListItem[] }`                                                            |
| `POST`   | `/api/playground/presets`        | ينشئ إعدادًا مسبقًا؛ ويتحقق من `PlaygroundPresetCreateSchema`                                              |
| `GET`    | `/api/playground/presets/:id`    | يُرجع إعدادًا مسبقًا واحدًا أو 404                                                                         |
| `PUT`    | `/api/playground/presets/:id`    | تحديث جزئي                                                                                                 |
| `DELETE` | `/api/playground/presets/:id`    | 204                                                                                                        |

المصادقة: اختيارية (`REQUIRE_API_KEY`). تُعالَج الأخطاء عبر `buildErrorBody()` (القاعدة الصارمة رقم 12).

## استكشاف الأخطاء وإصلاحها

| العَرَض                                   | السبب                           | الحل                                                                                  |
| ----------------------------------------- | ------------------------------- | ------------------------------------------------------------------------------------- |
| محرر Monaco لا يظهر في علامة تبويب API    | حمّل SSR محرر Monaco            | تحقق من أن `ApiTab` يستخدم `dynamic(..., { ssr: false })`                             |
| تبدأ تدفقات المقارنة بالتتابع             | استخدام خاطئ لـ `Promise.all`   | يجب إرسال جميع عمليات بدء التدفقات في استدعاء واحد لـ `Promise.all`                   |
| تعرض المقاييس قيمة `null` لـ TTFT         | معالج الجزء الأول غير موصول     | تحقق من استدعاء `useStreamMetrics.onFirstChunk()` داخل حلقة قارئ SSE                  |
| الإعداد المسبق لا يستمر                   | لم يُشغَّل ترحيل قاعدة البيانات | شغّل `npm run db:migrate` أو أعد تشغيل الخادم (يعمل الترحيل تلقائيًا عند بدء التشغيل) |
| تُرجع ميزة تحسين الموجّه 502              | لم يُحدَّد النموذج في الإعدادات | يجب على المستخدم إدخال اسم نموذج في لوحة الإعدادات قبل إجراء التحسين                  |
| تعرض الشيفرة المُصدَّرة `MISSING_API_KEY` | لم يُدرج العنصر النائب          | يستخدم `codeExport.ts` دائمًا `API_KEY_PLACEHOLDER = "$OMNIROUTE_API_KEY"`            |
