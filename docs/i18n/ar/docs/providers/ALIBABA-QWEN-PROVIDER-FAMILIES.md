يوثّق هذا المستند قرار التنفيذ الخاص بـ
[المشكلة رقم #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854). تُمثَّل المنتجات العامة
بأربع عائلات من المزوّدين. المنطقة هي بيانات اتصال وليست منتجًا منفصلًا.

## القرار

| عائلة المزوّد                                    | معرّف OmniRoute         | المنطقة العالمية | منطقة الصين |
| ------------------------------------------------ | ----------------------- | ---------------- | ----------- |
| Alibaba Cloud Model Studio (الدفع حسب الاستخدام) | `alibaba`               | سنغافورة         | بكين        |
| Alibaba Cloud Token Plan                         | `bailian-coding-plan`   | سنغافورة         | بكين        |
| Qwen Cloud (الدفع حسب الاستخدام)                 | `qwen-cloud`            | عالمي            | بكين        |
| Qwen Cloud Token Plan                            | `qwen-cloud-token-plan` | سنغافورة         | بكين        |

يظل المعرّف الحالي `alibaba-cn` اسمًا مستعارًا للتوافق وقت التشغيل للاتصالات المحفوظة ومسارات
النماذج والتركيبات والاستخدام السابق. تُدمج بطاقة لوحة التحكم الخاصة به ضمن `alibaba`؛ ولا
يلزم إعادة كتابة قاعدة البيانات.

تستخدم خدمة Qwen Cloud بنظام الدفع حسب الاستخدام وAlibaba Cloud Model Studio حاليًا مضيفات وقت تشغيل
متوافقة مع DashScope، لكنهما تظلان هويتين منفصلتين للمزوّد لأن المستخدمين يحصلون على المفاتيح ويديرون
الحسابات عبر واجهات منتجات مختلفة. تستخدم منتجات Alibaba وQwen Cloud Token Plan عائلات مختلفة
من نقاط النهاية، ولذلك تظل المنتجات الأربعة معرّفات منفصلة للمزوّدين.

## مصفوفة نقاط النهاية

| عائلة المزوّد           | `global-sg`                                                              | `china-beijing`                                                      | تنسيق النقل |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ----------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI      |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic   |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI      |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI      |

يجب أن ينتمي مفتاح API ونقطة النهاية إلى المنتج والمنطقة نفسيهما. يؤدي تحديد منطقة إلى تغيير
نقطة النهاية المضبوطة مسبقًا التي يستخدمها التحقق والطلبات العادية.

## عقد الاتصال

تخزّن الاتصالات الجديدة مفتاح المنطقة الثابت في `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

القيم المسموح بها هي `global-sg` و`china-beijing`. تُشتق نقطة النهاية مركزيًا من
معرّف المزوّد والمنطقة. يظل `providerSpecificData.baseUrl` غير المضبوط مسبقًا تجاوزًا صريحًا
من المشغّل وله الأولوية، بينما تُطبَّع عناوين URL القديمة المحفوظة والمضبوطة مسبقًا لتعود إلى
المصفوفة الإقليمية.

يحافظ هذا على قابلية توسيع مخطط الاتصال: يمكن إضافة منطقة أخرى إلى المحلّل دون
إنشاء بطاقة مزوّد أخرى أو تغيير معرّفات المزوّدين المحفوظة.

## التوافق والطرح

1. أضف محلّل نقاط النهاية الإقليمية مع الاحتفاظ بالإعدادات الافتراضية العامة الحالية.
2. استخدم الاكتشاف المباشر عبر `/models` الإقليمي في DashScope لكل من `alibaba` ومعرّف التوافق
   `alibaba-cn` الخاص به و`qwen-cloud`. تمر استجاباتها أولًا عبر مرشّح واحد لنماذج توليد النصوص، لأن
   نقطة النهاية العامة تُرجع أيضًا نماذج الصور والفيديو والصوت والتضمين وغيرها من النماذج غير المخصصة للدردشة. بعد ذلك، يطبّق `qwen-cloud`
   قائمة السماح المُدارة والمعلنة في سجل موفّده. يحتفظ Alibaba Model Studio
   وQwen Cloud بكتالوجين منسّقين منفصلين رغم أنهما يتشاركان حاليًا مضيفي وقت التشغيل.
3. سجّل `qwen-cloud-token-plan` باستخدام قائمة السماح الحالية للنماذج النصية في Token Plan.
4. أضف محدِّد منطقة ذي نوع محدد إلى مربعات حوار إضافة الاتصالات وتحريرها.
5. أخفِ بطاقة `alibaba-cn` المكررة، وأدرج اتصالاتها الحالية في صفحة موفّر `alibaba`.
6. أبقِ تجاوزات نقاط النهاية المخصصة متاحة لعمليات النشر المتقدمة والخاصة بمساحات العمل.

تظل نماذج الوسائط في Token Plan خارج كتالوج الدردشة لأنها تستخدم نقاط نهاية مخصصة.
النموذجان `wan2.7-image` و`wan2.7-image-pro` مسجلان في `open-sse/config/imageRegistry.ts`؛
والنماذج `happyhorse-1.1-i2v` و`happyhorse-1.1-t2v` و`happyhorse-1.1-r2v` مسجلة في
`open-sse/config/videoRegistry.ts`. يعيد كلا السجلين استخدام هوية اتصال `qwen-cloud-token-plan`
وبيانات اعتمادها الخاصة بكل منطقة.

لدى Qwen Cloud العادي كتالوجات منفصلة للصور والفيديو بنظام الدفع حسب الاستخدام ضمن هوية `qwen-cloud`.
نماذج الصور الخاصة به هي `wan2.7-image-pro` و`wan2.7-image` و`qwen-image-3.0-pro`
و`qwen-image-2.0-pro-2026-06-22` و`qwen-image-2.0-2026-03-03` و`z-image-turbo`. أما نماذج
الفيديو الخاصة به فهي `happyhorse-1.1-i2v` و`happyhorse-1.1-t2v` و`happyhorse-1.1-r2v`
و`happyhorse-1.0-video-edit` و`wan2.7-t2v` و`wan2.7-i2v` و`wan2.7-r2v-2026-06-12` و
`wan2.7-videoedit`. تعيد هذه النماذج استخدام اتصال `qwen-cloud` العادي فقط ونقطة نهاية الوسائط
الإقليمية في DashScope. لا ترث سجلات Token Plan والدفع حسب الاستخدام قوائم نماذج بعضها بعضًا ولا
تدمجها.

لدى هوية `bailian-coding-plan` أيضًا قوائم سماح خاصة بها للوسائط:
`wan2.7-image` و`wan2.7-image-pro` و`qwen-image-2.0` و`qwen-image-2.0-pro` لتوليد
الصور، بالإضافة إلى
`happyhorse-1.1-i2v` و`happyhorse-1.1-t2v` و`happyhorse-1.1-r2v` لتوليد
الفيديو. وهي تستخدم اتصال Bailian Coding Plan فقط ونقطة نهاية Coding Plan الإقليمية.
لا ترث سجلات الصور والفيديو الخاصة بها من أي من موفّري Qwen Cloud ولا تندمج معهما.

لدى هوية `alibaba` العادية قوائم سماح منفصلة للصور والفيديو. نماذج الصور الخاصة بها هي
`qwen-image-3.0-pro` و`qwen-image-2.0-pro-2026-06-22` و`qwen-image-2.0`
و`z-image-turbo` و`wan2.6-t2i`. أما نماذج الفيديو المضافة إليها فهي `happyhorse-1.1-i2v`
و`happyhorse-1.1-t2v` و`happyhorse-1.1-r2v` و`happyhorse-1.0-video-edit`
و`wan2.7-i2v-2026-04-25` و`wan2.6-i2v-flash` و`wan2.7-t2v-2026-06-12`
و`wan2.7-r2v-2026-06-12` و`wan2.7-videoedit`. تستخدم هذه النماذج اتصال Alibaba Model Studio
فقط ونقطة نهاية الوسائط الإقليمية المحددة له؛ ولا تُضاف إلى أي سجل لـ Coding Plan أو Qwen
Cloud.

يتبع كتالوج دردشة Qwen Cloud Token Plan قائمة السماح النصية ذات المطابقة التامة لخطة Individual:
`qwen3.8-max-preview` و`qwen3.7-max` و`qwen3.7-plus` و`qwen3.6-flash` و`glm-5.2` و
`deepseek-v4-pro`. تنتمي إدخالات Wan وHappyHorse إلى واجهات API المنفصلة لتوليد الصور والفيديو.

يتيح Alibaba Token Plan معرّفات نماذج توليد النصوص الستة الحالية نفسها عبر نقطة النهاية
المتوافقة مع Anthropic. يخزّن خيار سنغافورة مفتاح المنطقة الحالي `global-sg`؛
ولا يختلف سوى التصنيف الظاهر للمستخدم عن عائلات الموفّرين التي تسمّي المنطقة Global.

صُمّم كتالوج دردشة Qwen Cloud العادي ليكون أضيق نطاقًا من استجابة النصوص المباشرة الكاملة. توجد
قائمة السماح المُدارة الخاصة به في `open-sse/config/providers/registry/qwen-cloud/index.ts`؛ ولا يعيد
الاكتشاف المباشر سوى المعرّفات الموجودة في كل من الاستجابة الواردة من المصدر وقائمة السجل تلك.

يتبع Alibaba Model Studio قاعدة التقاطع المباشر نفسها باستخدام قائمة السماح المُدارة بصورة مستقلة
في `open-sse/config/providers/registry/alibaba/index.ts`. يعيد موفّر التوافق `alibaba-cn`
استخدام ذلك الكتالوج، مع توجيه الاكتشاف إلى نقطة نهاية بكين.
