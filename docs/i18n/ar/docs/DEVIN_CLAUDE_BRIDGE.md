يتيح `devin-cli-agentic` لبيئة تشغيل Claude Code الفعلية استخدام نقطة نهاية Anthropic Messages المحلية الخاصة بـ OmniRoute، بينما توفّر واجهة Devin CLI الرسمية استجابات النموذج عبر ACP stdio. ولا يعدّل موفّري Anthropic أو Claude OAuth أو Claude Web أو `devin-cli` الحاليين.

> **الحالة الحالية: تم تثبيت Claude Code على الإصدار `2.1.258`؛ وآخر تحقق مسجّل دون اتصال ومباشر
> كان على الإصدار `2.1.220`.** أكمل الإصدار المثبّت `2.1.220` ثلاثة سيناريوهات معزولة عبر Devin CLI
> `3000.2.17` والنموذج `swe-1-7-lightning`؛ وقد أثبت ذلك التشغيل المباشر النهائي تنفيذ دورات `Read`
> و`Edit` و`Bash` المملوكة للعميل، ونجاح نتائج `npm test`، واكتشاف أوامر المشروع ومهاراته،
> والتوجيه الحصري إلى Devin، وعدم وجود أي حركة صادرة إلى Claude. ثم رُفع الإصدار المثبّت إلى `2.1.258`
> (وهو جيل واجهة CLI الذي تنتحل هوية Claude الخاصة بـ OmniRoute صفته، وأول خط إصدار يضم
> فئة Fable 5.1 بصورة أصلية). في الإصدار المثبّت الجديد، تم التحقق من طبقة التثبيت و`claude --version`
> على الصورة الأساسية المثبّتة، كما تنجح حزمة اختبارات الوحدة للجسر و`compose config`
> وإثبات العزل الثابت — لكن لم يُعَد بعد تشغيل سيناريو المحاكاة دون اتصال ولا حزمة
> السيناريوهات الثلاثة المباشرة. أعِد تشغيلها (راجع "تحديث الأدوات المثبّتة") قبل الاعتماد على
> الجسر مع هذا الإصدار المثبّت.

## البنية

```text
Claude Code 2.1.258 (حاوية Linux معزولة لا تعمل بصلاحيات الجذر)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (بتنسيق Claude، موفّر بلا مصادقة)
  -> devin acp --agent-type summarizer (واجهة ACP stdio الرسمية، بلا أدوات Devin)
  -> حساب Devin في وحدة تخزين devin-auth المخصصة
```

يمكن لوكيل ACP الافتراضي في واجهة CLI الرسمية تنفيذ أدواته الخاصة، لذا لا يستخدمه هذا الجسر. بل يشغّل وكيل ACP الثابت `summarizer`، الذي لا يتضمن وضع CLI الرسمي الخاص به أي أدوات، ويؤطّر طلب Anthropic المتسلسل على هيئة تتبّع تنفيذ. عندما يلزم إجراء آخر مملوك لـ Claude، يجب أن تحتوي الاستجابة على مغلف واحد بالضبط لأداة العميل. ويُرفض أي `tool_call` أو `tool_call_update` صادر من ACP قبل إمكان الإبلاغ عن نجاح الاستجابة.

يحافظ المُسلسِل في `open-sse/executors/devin-agentic/serializer.ts` على `system` و`text` و`tool_use` و`tool_result` و`thinking` و`redacted_thinking` و`tool_choice` والأدوات التي يوفّرها Claude Code. وتفشل الصور والكتل غير المعروفة صراحةً. أما نتائج الأدوات الكبيرة فتستخدم علامة اقتطاع مرئية.

يقبل المحلّل مغلفًا مستقلاً واحدًا من نوع `<tool>{...}</tool>` في كل دورة للنموذج. ويتحقق من الاسم مقابل قائمة أدوات الطلب، ويتحقق من صحة الوسائط وفق JSON Schema الخاص بتلك الأداة، ويرفض المزج بين السرد والإجراءات، ويسمح بمحاولة إصلاح واحدة محدودة. ثم ينفّذ Claude Code ناتج Anthropic `tool_use` محليًا ويرسل `tool_result` مجددًا عبر OmniRoute.

## العزل ونموذج التهديدات

يُعد تثبيت Claude على المضيف وحسابه وإعداداته خارج النطاق وتُعامل باعتبارها محظورة. خدمات Compose:

- تعمل باستخدام UID/GID `10001:10001`، مع نظام ملفات جذري للقراءة فقط، وإسقاط الإمكانات، و
  `no-new-privileges`؛
- تستخدم `/home/bridge` خاصًا، ووحدة تخزين مخصصة لإعدادات Claude، وبيانات OmniRoute معزولة،
  ووحدة تخزين `devin-auth` منفصلة؛
- تربط فقط مساحات عمل/أدلة `.sandbox` القابلة للتخلص منها؛
- لا تربط المجلد الرئيسي للمضيف أو Keychain أو SSH أو بيانات اعتماد الخدمات السحابية أو مقبس Docker؛
- تنشئ بيئات صريحة وتزيل متغيرات Anthropic الخاصة بواجهة API وOAuth والتوجيه؛
- توجّه استدلال Claude Code فقط إلى `http://omniroute:20128` باستخدام مفتاح محلي فقط.

يستخدم ملف التعريف دون اتصال شبكة داخلية. وفي ملف التعريف المباشر، لا يصل OmniRoute إلى
نقاط نهاية Devin الرسمية إلا عبر `network-guard`؛ وتُرفض الوجهات غير ذات الصلة.
يمتلك Claude Code حارسًا منفصلاً يمنع جميع الاتصالات الصادرة، ولا يمكنه الوصول إلا إلى خدمة OmniRoute
المحلية عبر `NO_PROXY`. ولا تُربط ملفات تدقيق الحارس إلا بعملية الحارس الخاصة بها. تتحقق
البرامج النصية من ملكية الملفات ووضعها وعدد روابطها وكل قرار قبل تصدير
أدلة خالية من الرموز المميزة.

شغّل إثبات العزل بصورة مستقلة:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

يتحقق هذا من البنية، وعمليات الربط المسماة، وإعدادات التشغيل دون صلاحيات الجذر/للقراءة فقط، والتوجيه المحلي الصريح،
وغياب متغيرات البيئة الحساسة، وغياب مقبس Docker، وحظر الوصول إلى
`api.anthropic.com` و`claude.ai`، واختيار موفّر Devin حصرًا، والفشل الصريح عند
عدم توفر واجهة ACP الخلفية.

## الإعداد لأول مرة والاستخدام العادي

أنشئ الصورة ذات الإصدارات المثبتة:

```bash
./scripts/devin-bridge/build
```

صادِق على وحدة تخزين Devin المعزولة فقط:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

يستخدم أمر تسجيل الدخول مسار الرمز اليدوي الرسمي المخصص لبيئات الحاويات/البيئات البعيدة. تُدخَل القيمة مباشرةً في مطالبة واجهة سطر الأوامر؛ ولا تُمرَّر كوسيطة للعملية، أو تُكتب إلى Git، أو تُنسخ من المضيف.

شغّل بيئة تشغيل Claude Code المعزولة:

```bash
./scripts/devin-bridge/launch
```

يعيد `launch` التحقق من العزل ومصادقة Devin واكتشاف النموذج قبل بدء Claude Code داخل الحاوية. ولا يشغّل أبدًا ملف Claude التنفيذي الخاص بالمضيف. يمكن تعيين الأسماء المستعارة للنماذج في `.env.devin-bridge`؛ ويجب أن تحتفظ كل قيمة مُعدَّة بالبادئة `devin-cli-agentic/`.

## أوامر التحقق

لا يتطلب المسار القابل لإعادة الإنتاج دون اتصال حساب Devin، ولا يتوفر له اتصال بالإنترنت في وقت التشغيل:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

مسار الاختبار الفعلي الاختياري الذي يتطلب المصادقة هو:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

ينتظر مشغّل الاختبارات الفعلية بين السيناريوهات لتجنب فتح جلسات ACP على دفعات، ويتحقق من أحداث دفق Claude المهيكلة بدلًا من الوثوق بالادعاءات النصية. وتثبت سيناريوهاته الثلاثة ما يلي:

1. القراءة المباشرة للمشروع وتحليل العيوب؛
2. تنفيذ `Edit` فعلي، وتشغيل `npm test` عبر `Bash` مملوك للعميل، والحصول على نتيجة نهائية؛
3. اكتشاف `/bridge-check` و`bridge-proof`، وقراءة المشروع، وتشغيل ناجح آخر لـ `npm test` مملوك للعميل، والإكمال دون عمل معلّق.

تتحقق البوابة النهائية أيضًا من تدقيق شبكة Devin، وتشترط بقاء تدقيق حركة الخروج الخاصة بـ Claude فارغًا.

## تحديث الأدوات ذات الإصدارات المثبتة

تُثبّت الصورة إصدارات Node وClaude Code وDevin CLI في `docker/devin-bridge/Dockerfile`. للتحديث:

1. غيّر الإصدارات المحددة صراحةً؛
2. استبدل المجموعين الاختباريين لأرشيف Devin الخاصين بكلتا المعماريتين بقيم الأداة الرسمية؛
3. أعد البناء وشغّل جميع أوامر التحقق دون اتصال؛
4. تأكد من الإصدارات داخل الصورة؛
5. أعد تشغيل مجموعة الاختبارات الفعلية ذات السيناريوهات الثلاثة بعد المصادقة.

لا تثبّت أيًا من واجهتي سطر الأوامر بشكل عام على المضيف، ولا تستبدل التحقق بالمجموع الاختباري بتنزيل غير متحقق منه.

## التشخيص والتنظيف

- يعرض `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute` معلومات التوجيه المحلي وأخطاء المنفّذ المنقّحة.
- يسجّل `.sandbox/evidence/mock-acp.jsonl` إجراءات ACP الوهمية الحتمية.
- يسجّل `.sandbox/evidence/claude-stream.jsonl` تشغيل Claude Code الفعلي دون اتصال.
- تسجّل `.sandbox/evidence/live-*.jsonl` التدفقات الفعلية الثلاثة التي تم التحقق منها.
- يُعدّ `.sandbox/evidence/egress.jsonl` و`.sandbox/evidence/claude-egress.jsonl` نسختين متحققًا منهما وخاليتين من الرموز المميزة لعمليات تدقيق الحماية.

أوقف الحاويات والشبكات المملوكة مع الحفاظ على وحدات تخزين تسجيل الدخول/الإعدادات:

```bash
./scripts/devin-bridge/clean
```

أزل البيئة الكاملة المملوكة للجسر، بما في ذلك وحدات التخزين المسماة:

```bash
./scripts/devin-bridge/clean --all
```

## القيود

- يعتمد الجسر على دور `summarizer` الثابت الذي لا يستخدم أدوات، لأن Devin CLI `3000.2.17` لا يوفّر وكيل ACP محايدًا من دون أدوات. يعوّض المحوّل الاستجابات الوسيطة المصاغة على هيئة ملخص، لكن قد تظل محاولة الإصلاح المحدودة الوحيدة تفشل بشكل صريح.
- يمكن لاستدعاءات ACP المباشرة أن تُرجع استجابات `502`/`504` عابرة. يباعد إطار الاختبار بين السيناريوهات؛ ويظل الفشل المستمر مغلقًا بأمان ولا يختار مزوّدًا آخر مطلقًا.
- يُعاد إنشاء سياق ACP من كل طلب Anthropic؛ ولا يوجد ارتباط بالعملية/الجلسة.
- يُدعم استدعاء أداة واحد لكل استجابة من النموذج؛ وتُرفض الاستدعاءات المتوازية.
- الصور غير مدعومة صراحةً. ولا يتم الإعلان عن دعم الرؤية أو مخرجات التفكير أو عناصر التحكم في الجهد أو نافذة سياق بسعة 1M.
- يستخدم SSE أحداث دورة حياة Anthropic صالحة، لكنه يُرسَل بعد جمع دورة ACP المحدودة؛ ولا تُمرَّر أجزاء ACP تدريجيًا.
