> **ملاحظة حول النطاق:** يضبط `socket.yml` فحص Socket.dev الذي يُجرى من جانب السجل بعد نشر حزمة npm (مع تجاهل مسارات المحتوى غير المضمّن في الحزمة المنشورة، مثل `tests/` و`docs/` وتقارير البناء). ولا ينشئ بوابة دمج ضمن CI/PR — فلا يوجد سير عمل في `.github/workflows`، ولا برنامج نصي في `package.json`، ولا هدف في `Makefile` يستدعي Socket.dev.

هذه الوثيقة هي إفادة أعدّها المشرف بشأن نتائج
`برمجيات ضارة محتملة مكتشفة بواسطة الذكاء الاصطناعي` الست التي أُثيرت حول `omniroute@3.8.5`
والإجراءات التخفيفية المطبقة في `omniroute@3.8.6`. وهي موجودة لكي:

1. يتوفر لمشغّلي مسار الأمان مرجع واحد يمكنهم الاستشهاد به عندما يحتاجون
   إلى تقييم النتائج بالرجوع إلى الشيفرة المصدرية الفعلية.
2. تتمكن أدوات الفحص المستقبلية المعتمدة على الذكاء الاصطناعي من التقاط إفادة المشرف الموقعة التي تؤكد أن كل
   مسار جرى الإبلاغ عنه مقصود، ويتطلب تمكينًا صريحًا، وموثق.
3. يكون لدينا سجل مكتوب يوضح _سبب_ تصميم كل موضع استدعاء على النحو الحالي —
   حتى لا تؤدي إعادة هيكلة مستقبلية، دون قصد، إلى إعادة إدخال بصمة
   أُزيلت عمدًا.

إذا كنتم تشغّلون أداة فحص تعيد الإبلاغ عن أي من مواضع الاستدعاء أدناه بعد
إصدار الإجراءات التخفيفية في v3.8.6، فيُرجى فتح مشكلة وإرفاق سجل تتبع الفحص،
وسنوسّع الإفادة هنا.

## §1 — تثبيت مرجع مصادقة جذري لاعتراض الاتصال (`77484.js`)

**ملفات المصدر**:

- `src/mitm/cert/install.ts` — الدالتان العامتان `installCert()` / `uninstallCert()`،
  والدوال الخاصة بكل منصة `installCertWindows/Mac/Linux`.
- `src/mitm/systemCommands.ts` — الأدوات المساعدة المشتركة لـ `execFile` / `spawn` / PowerShell
  التي تستخدمها مسارات التثبيت.

**المشغّل**: ينقر المستخدم على "تمكين وكيل اعتراض الاتصال" في لوحة المعلومات المحلية عند
`/dashboard/cli-tools/mitm`. المسار متاح فقط عبر واجهة الاسترجاع المحلية — راجع القاعدة الصارمة رقم 17 في
`CLAUDE.md` و`src/server/authz/routeGuard.ts::isLocalOnlyPath()`. **لا يمكن** لرمز
JWT مسرّب ومكشوف عبر نفق تشغيل مسار الشيفرة هذا.

**العمليات ذات الامتيازات التي تُنفّذ (بحسب المنصة)**:

| نظام التشغيل           | الأمر (الأوامر)                                                                                                   |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | `certutil -addstore Root <cert>` عبر UAC                                                                          |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | تحديث قاعدة بيانات NSS لكل ملف تعريف عبر `certutil -d sql:<profile>`                                              |

هذه هي الأوامر نفسها التي تستخدمها `mitmproxy` وCharles Proxy وFiddler
وCaddy. حقيقة وجودها في OmniRoute موثّقة في
`docs/security/STEALTH_GUIDE.md`.

**إجراءات التخفيف في v3.8.6**:

- لم تعد `runElevatedPowerShell()` تستخدم `-EncodedCommand <base64utf16le>`.
  تُكتب الحمولة ذات الامتيازات المرتفعة إلى ملف `.ps1` مؤقت خاص بكل استدعاء (بالوضع 0o600،
  داخل دليل `mkdtempSync` خاص)، ويُشار إليها عبر `-File`. يُحذف
  الملف في `finally`. يؤدي هذا إلى إزالة البصمة النمطية المعروفة
  للترميز باستخدام base64 ورفع الامتيازات عبر PowerShell، التي صنّفها مصنّف الذكاء الاصطناعي لدى Socket.dev.
- تتضمن `installCertWindows` كتلة مضمنة باسم `SECURITY-AUDITOR-NOTE:`
  تشير إلى هذا المستند.

**سبب احتفاظنا بها**: وكيل اعتراض الاتصال ميزة موثّقة تستخدمها
`docs/security/STEALTH_GUIDE.md` و`docs/frameworks/MITM-PROXY.md`. ستؤدي
إزالتها إلى تعطيل مجموعة ميزات جسر الوكيل.

## §2 — استيراد بيانات اعتماد Zed (`app/api/providers/zed/import/route.js`)

**ملفات المصدر**:

- `src/app/api/providers/zed/discover/route.ts` _(جديد في v3.8.6)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(جديد في v3.8.6)_

**المُشغِّل**: ينقر المستخدم على "استيراد من Zed" في صفحة الموفّرين ضمن لوحة
التحكم المحلية. تخضع نقطة النهاية لحماية `requireManagementAuth`. يكتب محرر Zed نفسه
مفاتيح API الخاصة بالموفّرين في سلسلة مفاتيح نظام التشغيل تحت أسماء خدمات
موثقة — راجع https://zed.dev/docs/ai/llm-providers.

**سلوك v3.8.5 (الذي أبلغ عنه Socket.dev)**:

كانت `POST /import` تكتشف بيانات الاعتماد وتحفظها تلقائيًا في مخزن SQLite المحلي
ضمن رحلة طلب واحدة. لم يكن هناك تأكيد لكل حساب ولا بصمة، بل مجرد
"تم العثور على N من الرموز، وتم استيرادها جميعًا."

**معالجة v3.8.6 — تأكيد من خطوتين**:

1. تعيد **`POST /api/providers/zed/discover`**
   `{ candidates: [{ provider, service, account, fingerprint }] }`. لا يتم نقل
   الرمز الخام **مطلقًا**. وتكون البصمة
   `sha256(service|account|token).slice(0,16)`.
2. تعرض لوحة التحكم قائمة العناصر المرشحة، ويحدد المشغّل العناصر المطلوب
   استيرادها، ثم يرسل `{ confirmedAccounts: [{ service, account, fingerprint }] }`
   إلى **`POST /api/providers/zed/import`**.
3. تعيد نقطة نهاية الاستيراد **قراءة سلسلة المفاتيح على الخادم** وتُرشّح بحسب
   `(service, account, fingerprint)`. لا يمكن لاستجابة اكتشاف جرى العبث بها
   أو إعادة تشغيلها أن تخدع نقطة نهاية الاستيراد لحفظ رمز غير ذي صلة —
   فإذا تغير الرمز الفعلي منذ الاكتشاف، فلن تعود البصمة متطابقة
   وسيتم تخطي بيانات الاعتماد.

يحافظ متغير البيئة `OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` على سلوك v3.8.5
للمشغّلين الذين لم يحدّثوا عمليات الأتمتة لديهم بعد. وستتم إزالته
في v3.9.

**لماذا نحتفظ به**: يُعد استيراد Zed أسهل مسار إعداد أولي للمستخدمين
الذين يستخدمون Zed بالفعل ويريدون نسخ مفاتيح موفّريهم إلى OmniRoute
من دون إعادة لصقها.

## §3 — `execFile` / `spawn` / PowerShell بصلاحيات مرتفعة (`21843.js`)

**ملفات المصدر**: `src/mitm/systemCommands.ts`.

**سبب الإبلاغ**: تعيد الحزمة تصدير `execFileWithPassword`
و`runElevatedPowerShell` وأداة `quotePowerShell` المساعدة المشتركة. يصنفها
مصنّف الذكاء الاصطناعي الخاص بـ Socket.dev باعتبارها "مجموعة أدوات عامة لتنفيذ
الأوامر على المضيف + رفع الصلاحيات." وضمن OmniRoute، لا تُستخدم إلا في مسار
تثبيت شهادة MITM (§1)، وكذلك بواسطة `execFileWithPassword` لتنفيذ أوامر `sudo`.

**معالجة v3.8.6**:

- إعادة هيكلة `runElevatedPowerShell` (راجع §1).
- توثّق كتلة `SECURITY-AUDITOR-NOTE:` المضمّنة عند كل من
  `runElevatedPowerShell` و`execFileWithPassword` المستدعين المدرجين في القائمة
  المسموح بها، وقائمة الملفات التنفيذية المثبتة.
- يتضمن استدعاء `spawn()` في `execFileWithPassword` علامة `nosemgrep` مع
  قائمة الملفات التنفيذية المسموح للأداة المساعدة باستلامها — ولا يوجد
  **أي مسار من إدخال المستخدم إلى `finalCommand`/`finalArgs`**.

## §4 / §6 — مشرف خدمة 9router (`api/services/9router/{start,restart}/route.js`)

**ملفات المصدر**:

- `src/app/api/services/9router/_lib.ts` — مصنع المشرف.
- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`.
- `src/lib/services/ServiceSupervisor.ts` — تشغيل عام / استقصاء حالة السلامة / مخزن سجلات مؤقت.

**المُشغِّل**: ينقر المستخدم على "تثبيت" / "بدء" في صفحة الخدمات المضمّنة ضمن
لوحة التحكم المحلية.

**وسائل الحماية الموجودة بالفعل**:

- جميع مسارات `/api/services/*` هي LOCAL_ONLY وفقًا للملف
  `src/server/authz/routeGuard.ts` (القاعدة الصارمة رقم 17). يجري فرض الاتصال
  عبر واجهة الاسترجاع قبل أي تحقق من المصادقة — ولا يمكن لرمز JWT مسرّب الوصول إليها.
- يُنشأ صف 9router في قاعدة البيانات بالقيم `status='not_installed', auto_start=0` (راجع
  `src/lib/db/migrations/071_services.sql:19`). **لا** تبدأ الخدمة
  عند التشغيل الأول.
- يُستدعى `spawn()` باستخدام مسار الملف التنفيذي الذي تعيده
  `resolveSpawnArgs(apiKey, PORT)` في `src/lib/services/installers/ninerouter.ts`،
  وهي قائمة ثابتة بالملفات التنفيذية المدعومة والمسموح بها.
- يجري تخزين stdout/stderr مؤقتًا في الذاكرة (بحد أقصى 5 MB، راجع `_lib.ts`) — ولا
  تتم الكتابة على القرص إلا إذا فعّل المستخدم التسجيل من لوحة التحكم.

**معالجة v3.8.6**: لا يوجد تغيير وظيفي. يستبدل ملف تعريف البناء الأدنى
(`OMNIROUTE_BUILD_PROFILE=minimal`)
الملف `src/lib/services/installers/ninerouter.ts` بتنفيذ بديل فارغ للمستخدمين الذين يريدون
إزالة المسارات ذات الصلاحيات المرتفعة فعليًا من الحزمة.

**لماذا نحتفظ به**: 9router خدمة مرافقة اختيارية يمكن تثبيتها محليًا
(على غرار: إضافة WordPress) — ولا تُفعّل إلا باشتراك صريح.

## §5 — إعادة كتابة بيانات اعتماد مزامنة OmniRoute Cloud (`api/keys/[id]/route.js`)

**ملفات المصدر**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`.
- `src/app/api/keys/[id]/route.ts` — يستدعي `syncKeysToCloudIfEnabled()`.

**المُشغِّل**: تُرجع `isCloudEnabled()` القيمة `true` (يُضبط ذلك من لوحة المعلومات) **و**
يكون `CLOUD_URL` مُهيّأً. عند تعطيل كليهما، لا تُجرى أي مكالمة شبكة صادرة إلى
نقطة نهاية Cloud.

**سلوك v3.8.5 (الخلل الذي اكتشفه Socket.dev على نحو صحيح)**:

كانت `updateLocalTokens()` تستبدل `accessToken` و`refreshToken` و
`providerSpecificData` من استجابة Cloud عندما
تكون `cloudUpdatedAt > localUpdatedAt`. لم يكن هناك HMAC أو توقيع أو مجموع تدقيق. كان بإمكان
قيمة `CLOUD_URL` مُهيّأة بشكل خاطئ أو عدائية (أو هجوم MITM على القناة) تبديل
رموز OAuth الخاصة بموفّر الخدمة بصمت.

**التخفيف في v3.8.6**:

1. **التحقق من HMAC**: تتحقق `verifyCloudSignature(rawBody, sigHeader)` من
   ترويسة `X-Cloud-Sig` (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`) قبل تحليل JSON. إذا كان السر مضبوطًا، يكون التوقيع
   مطلوبًا. وإن لم يكن مضبوطًا (الوضع القديم)، يُسجَّل تحذير وتُقبل
   الاستجابة — سيصبح السر مطلوبًا في v3.9.
2. **الاشتراك الصريح في مزامنة الحقول السرية**: لا تُستبدل `accessToken` / `refreshToken` /
   `providerSpecificData` **إلا** عندما تكون
   `OMNIROUTE_CLOUD_SYNC_SECRETS=true`. يزامن الوضع الافتراضي فقط
   بيانات التعريف غير المرتبطة ببيانات الاعتماد (`expiresAt` و`status` و`lastError*` و
   `rateLimitedUntil` و`updatedAt`). هذا **تغيير كاسر للتوافق** للمستخدمين
   الذين اعتمدوا على مزامنة الرموز عن بُعد — ويجب عليهم الاشتراك فيها صراحةً.

**سبب الإبقاء عليها**: تُعد Cloud Sync الوسيلة الوحيدة التي تمكّن مستأجر OmniRoute Cloud
من مركزة بيانات اعتماد الفريق. يجعل الإصلاح نموذج التهديد صريحًا:
"يوقّع الخادم، ويتحقق العميل، ويشترك المشغّل."

للمستخدمين الذين يحتاجون إلى ناتج بناء ملائم لـ Socket، نفّذوا البناء باستخدام:

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

ينشئ `NormalModuleReplacementPlugin` في webpack أسماءً بديلة لأربع وحدات تشير إلى وحدات بديلة وهمية:

| الوحدة                                      | الوحدة البديلة الوهمية                           |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
