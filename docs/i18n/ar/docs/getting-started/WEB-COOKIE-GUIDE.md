تتيح موفّرات ملفات تعريف الارتباط للويب لـ OmniRoute استخدام خدمة ذكاء اصطناعي من خلال جلسة المتصفح الحالية بدلًا من مفتاح API. وهي مفيدة عندما يكون لديك بالفعل وصول إلى خدمة عبر موقعها الإلكتروني، وتريد أن يستخدم OmniRoute الجلسة الموثَّقة نفسها.

على خلاف الموفّرات التي تستخدم مفتاح API، تجري موفّرات ملفات تعريف الارتباط للويب المصادقة باستخدام بيانات الاعتماد التي يرسلها متصفحك إلى الموقع الإلكتروني.

---

# قبل أن تبدأ

> **مهم:** انسخ بيانات الاعتماد دائمًا من **طلب شبكة مباشر**، **وليس** من مخزن ملفات تعريف الارتباط في متصفحك.

تنجم العديد من مشكلات المصادقة عن نسخ ملفات تعريف الارتباط من المكان الخطأ.

## لا تنسخ من مخزن ملفات تعريف الارتباط

تتيح معظم المتصفحات الوصول إلى ملفات تعريف الارتباط المخزّنة من خلال:

```
DevTools
→ Application (أو Storage)
→ Cookies
```

على الرغم من أن ملفات تعريف الارتباط هذه تبدو صحيحة، فقد تكون:

- قديمة
- غير مكتملة
- تفتقد ملفات تعريف ارتباط لا تُرسل إلا مع الطلبات الموثَّقة

قد يؤدي استخدام هذه القيم إلى فشل المصادقة، حتى لو بدت صالحة.

## انسخ من طلب مباشر

بدلًا من ذلك، استخدم ملفات تعريف الارتباط من طلب ناجح:

```
DevTools
→ Network
→ حدّث الصفحة
→ افتح طلب دردشة أو محادثة
→ Request Headers
→ Cookie
```

يحتوي ترويسة الطلب `Cookie` على معلومات المصادقة الدقيقة التي استخدمها متصفحك بنجاح.

بالنسبة إلى معظم موفّرات ملفات تعريف الارتباط للويب، هذه هي القيمة التي ينبغي لصقها في OmniRoute.

---

# الإعداد العام

تتشابه عملية الإعداد لدى معظم موفّرات ملفات تعريف الارتباط للويب.

1. سجّل الدخول إلى الموقع الإلكتروني للموفّر.
2. افتح أدوات المطوّرين في المتصفح.
3. افتح علامة التبويب **Network**.
4. حدّث الصفحة.
5. افتح طلب دردشة أو محادثة موثَّقًا.
6. انسخ بيانات اعتماد المصادقة المطلوبة.
7. افتح OmniRoute.
8. انتقل إلى **Providers → Add Provider**.
9. حدّد موفّر ملفات تعريف الارتباط للويب.
10. الصق بيانات الاعتماد.
11. انقر على **Test Connection**.
12. احفظ الموفّر.

تعتمد بيانات الاعتماد المطلوبة تحديدًا على الموفّر.

## NoTrack (notrack-web)

NoTrack ‏([notrack.ai](https://notrack.ai)) هي منصة دردشة مجانية للمستهلكين لا تتطلب التسجيل — تُنشأ الجلسة بشكل مجهول عند الزيارة الأولى وتستمر عبر ثلاث ملفات تعريف ارتباط: `uid` و`si_usr_id` و`si_ses_id`. يمرّر OmniRoute نقطة النهاية نفسها `/api/dispatch` عبر معرّف نموذج واحد (`notrack-c`، والاسم المستعار `ntw`).

### خطوات الاتصال

1. افتح [notrack.ai](https://notrack.ai) في متصفحك وانتظر حتى يُعيَّن ملف تعريف ارتباط الجلسة المجهولة.
2. افتح **أدوات المطور → الشبكة**، وحدّث الصفحة، ثم انقر على أي طلب `/api`.
3. في **ترويسات الطلب**، انسخ القيمة الكاملة لترويسة `Cookie`.
4. في OmniRoute، انتقل إلى **المزوّدون → إضافة مزوّد → NoTrack Web (مجاني)**.
5. الصق سلسلة ملفات تعريف الارتباط في الحقل `apiKey` ثم انقر على **حفظ**.

يستخرج OmniRoute القيم `uid` و`si_usr_id` و`si_ses_id` من السلسلة الملصقة، ثم يعيد إنشاء ترويسة `Cookie` نظيفة لا تحتوي إلا على هذه الأزواج — بالإضافة إلى `nt_session` (رمز `ntk_…` المعيّن للحسابات المسجّلة الدخول) عند وجوده. إذا كانت أي من القيم الثلاث مفقودة، فتُمرَّر السلسلة الخام الملصقة دون تغيير حتى يتمكن المشغّلون من تجربة تنسيقات بديلة.

### معرّفات النماذج

| معرّف النموذج | اسم العرض | ملاحظات                                                 |
| ------------- | --------- | ------------------------------------------------------- |
| `notrack-c`   | NoTrack C | الافتراضي — نموذج الإرسال في المنبع `C`.                |
| `C`           | NoTrack C | اسم مستعار لـ`notrack-c` (رمز الإرسال الخام في المنبع). |
| `notrack`     | NoTrack C | اسم مستعار لـ`notrack-c`.                               |
| `ntw`         | NoTrack C | اسم مستعار مختصر لـ`notrack-c`.                         |

تُربط معرّفات النماذج الأربعة بنموذج الإرسال نفسه في المنبع (`C`).

### خيارات الطلب

يقبل المنفّذ الحقول الاختيارية التالية في نص الطلب:

| حقل النص              | القيمة الافتراضية | الغرض                                                      |
| --------------------- | ----------------- | ---------------------------------------------------------- |
| `notrack_mode`        | `usual`           | وضع الإرسال (سلسلة حرة؛ يقبل المنبع `usual`، …)            |
| `notrack_max_turns`   | `6`               | عدد الأدوار الداخلية التي يمكن للمنبع تنفيذها قبل الإجابة. |
| `notrack_chat_id`     | `null`            | استئناف دردشة حالية في المنبع (احذفه لبدء دردشة جديدة).    |
| `notrack_attachments` | `[]`              | مصفوفة تمرير مباشر لواصفات المرفقات في المنبع.             |
| `notrack_regenerate`  | `false`           | عيّنه إلى `true` لطلب إعادة توليد إجابة الدور السابق.      |

### الإمكانات

- إكمالات دردشة **متدفقة وغير متدفقة**.
- **استدعاء الأدوات** — عيّن `tools: [...]` في الطلب؛ يتولى المنفّذ إجراء تسلسل لها ضمن عقد مغلّف لاستدعاء الأدوات، ثم يحلّل استجابات النموذج ويعيدها إلى `tool_calls` بتنسيق OpenAI.
- **`response_format`** — التنسيقان `json_object` و`json_schema` مدعومان. يستخرج المنفّذ أول كائن JSON من رد النموذج ويحوّله إلى سلسلة نصية قبل إرجاعه.
- **تلميح الاستدلال** — يصدر المنفّذ جزء `reasoning` عندما يرسل المنبع حدث `thinking`.

### القيود

- يفرض المنبع حصص استخدام مجهولة — وعند تجاوزها، يعرض المنفّذ خطأ 429 مع رسالة سهلة الفهم.
- تُحل جميع معرّفات النماذج إلى نموذج الإرسال نفسه في المنبع؛ ولا يوجد تبديل منفصل لكل نموذج.
- لا يستدعي المنفّذ نقطة النهاية `/api/chats` الخاصة بالمنبع، ولذلك لا تُدار سجلات الدردشة أو الجلسات تلقائيًا. استخدم `notrack_chat_id` لاستئناف دردشة حالية في المنبع.

# ما الذي يستطيع مزوّدو ملفات تعريف ارتباط الويب فعله وما الذي لا يستطيعون فعله

يعيد مزوّدو ملفات تعريف ارتباط الويب استخدام واجهة الدردشة الخاصة بموقع ويب. وهم **لا** يوفّرون الإمكانات نفسها التي توفّرها واجهات API الرسمية.

## الميزات المدعومة

- المصادقة باستخدام جلسة المتصفح الحالية
- الوصول إلى النماذج المتاحة من خلال حسابك
- بث استجابات الدردشة
- لا يلزم مفتاح API

## الميزات غير المدعومة

- استدعاء الدوال
- استدعاء الأدوات
- التحرير التلقائي للملفات
- سير العمل الوكيلي في بيئات التطوير المتكاملة
- الميزات المتاحة عبر API فقط

هذا سلوك متوقع و**ليس** خطأً برمجيًا.

إذا كنت بحاجة إلى تنفيذ الأدوات أو التحرير التلقائي للملفات أو غير ذلك من مهام سير العمل الوكيلية، فاستخدم **موفّرًا يعتمد على مفتاح API** بدلًا من موفّر Web Cookie.

# تنبيه بشأن التحقق

لا يعني نجاح **اختبار الاتصال** أو التحقق من ملفات تعريف الارتباط سوى أن بيانات الاعتماد المقدّمة تبدو بالتنسيق المتوقع.

إلى أن تُحل المشكلة #7857، فإن نجاح التحقق **لا يضمن** نجاح مصادقة الموفّر.

إذا استمرت المصادقة في الفشل، فتحقق من أنك نسخت بيانات الاعتماد من طلب شبكة مباشر بدلًا من مخزن ملفات تعريف الارتباط في المتصفح.

---

# استكشاف الأخطاء وإصلاحها

## فشل المصادقة

تحقق من نسخ بيانات الاعتماد من:

```
الشبكة
→ ترويسات الطلب
→ ملف تعريف الارتباط
```

و**ليس** من:

```
التطبيق
→ ملفات تعريف الارتباط
```

---

## يعمل ملف تعريف الارتباط في المتصفح ولكن ليس في OmniRoute

تتضمن بعض الجهات الموفّرة ملفات تعريف ارتباط لا تُرسل إلا أثناء الطلبات المصادَق عليها.

أعِد نسخ بيانات الاعتماد من طلب شبكة جديد بعد فتح محادثة بنجاح.

---

## انتهاء صلاحية الجلسة

تستخدم الجهات الموفّرة عبر Web Cookie جلسة المتصفح الحالية.

إذا انتهت صلاحية جلسة المتصفح أو سجّلت الخروج، فيجب عليك نسخ مجموعة جديدة من بيانات الاعتماد. لأتمتة تجديد ملفات تعريف الارتباط لموفّري الويب المدعومين، راجع الأداة المصاحبة [ملحق مزامنة جلسة المتصفح](../guides/SESSION-SYNC-EXTENSION.md).

---

## نجاح اختبار الاتصال مع فشل الطلبات

إلى أن تُحل المشكلة #7857، فإن اجتياز التحقق لا يضمن نجاح طلب المصادقة.

أعِد نسخ بيانات اعتمادك من طلب مصادَق عليه حديث قبل متابعة استكشاف الأخطاء وإصلاحها.

# أفضل الممارسات

- انسخ بيانات الاعتماد من طلب مصادَق عليه حديث.
- تجنّب إعادة استخدام ملفات تعريف الارتباط القديمة.
- أبقِ جلسة المتصفح نشطة أثناء استخدام موفّري Web Cookie.
- تعامل مع ملفات تعريف الارتباط المنسوخة باعتبارها بيانات اعتماد حساسة.
- استخدم الموفّرين المعتمدين على مفتاح API عندما تحتاج إلى استدعاء الدوال أو مهام سير العمل الوكيلية.
