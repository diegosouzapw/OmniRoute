توسّع قواعد توجيه الاستدلال آليات توجيه النماذج والمجموعات الحالية. عندما لا تتطابق أي قاعدة نشطة،
يظل سلوك التفكير واللاحقة والإعداد الافتراضي للاتصال وترجمة المزوّد الحالي
دون تغيير.

## الإدارة

تتوفر إدارة القواعد ضمن **الإعدادات ← التوجيه العام**. وتوفر أداة تحرير مفتاح API
واجهة الإدارة نفسها بعد تصفيتها وفقًا للمفتاح المحدد.

تُتاح واجهة API للإدارة عبر المسارات التالية:

- `GET` و`POST` على `/api/settings/reasoning-routing-rules`
- `GET` و`PATCH` و`DELETE` على `/api/settings/reasoning-routing-rules/[id]`
- `POST` على `/api/settings/reasoning-routing-rules/simulate`

تستخدم جميع المسارات `requireManagementAuth`. ويجري التحقق من صحة المدخلات باستخدام المخططات الموجودة في
`src/shared/validation/schemas/reasoningRouting.ts`. لا يجري المحاكي أي استدعاء إلى جهة خارجية.

## حلّ القواعد

يحدد التقييم المبكر قاعدة واحدة فقط. ويجري التحقق من النطاقات بالترتيب التالي:

1. `apiKey`
2. `combo`
3. `model`
4. `global`

ضمن النطاق، تكون الأولوية أولًا للقيمة الأعلى من `priority`، يليها تطابق النموذج الدقيق بدلًا من نمط glob،
ثم الترتيب الثابت حسب `createdAt` و`id`. تُقرأ `requestTags` حصريًا من `metadata.tags`
وتدعم المطابقة باستخدام `any` أو `all`.

لا تُقيَّم قاعدة `connection` إلا عندما لا تفوز أي قاعدة مبكرة ويكون قد جرى بالفعل تحديد اتصال فعلي
بالمزوّد. ولا يمكنها سوى تغيير مستوى الجهد والميزانية.

## الجهد والميزانية

تقبل `sourceEffort` القيم `any` و`missing` و`none` و`low` و`medium` و`high` و`xhigh` و`max`
و`ultra`. تعني `missing` أن الطلب لا يحتوي على مستوى جهد منفصل، ولا مفتاح تبديل للتفكير،
ولا ميزانية للتفكير. ولذلك لا تتطابق الإشارة التي تحتوي على ميزانية فقط إلا مع `any`.

لدى `effortMode` ثلاثة أنواع:

- يحافظ `inherit` على جهد العميل مع السماح بتغيير النموذج أو المجموعة.
- يعيّن `default` القيمة `targetEffort` فقط عند عدم وجود إشارة استدلال صريحة.
- يستبدل `force` مستوى الجهد المنفصل بالقيمة `targetEffort`.

وبشكل مستقل، يمكن أن تكون قيمة `budgetAction` هي `preserve` أو `remove` أو `set`. يؤدي استخدام `force` مع `none` إلى إزالة
جميع حقول الجهد والميزانية المعروفة. ويُعد استخدام `none` مع `set` غير صالح.

تُرفض الطلبات التي تستهدف نماذج معروفة بعدم التوافق قبل إجراء الاستدعاء الخارجي. وبالنسبة إلى أهداف
المجموعات، تُزال الإدخالات غير المتوافقة؛ وإذا لم يتبقَّ أي إدخال، يُرجع الطلب الحالة `400`.
تنتج بيانات الإمكانات غير المعروفة تحذيرًا وتُبقي القاعدة نشطة.

## الأمان ووسائل النقل

يظل النموذج المصدر والمستهدف، أو المجموعة المصدر والمستهدفة، خاضعًا لسياسة مفتاح API
الحالية. لا توسّع قاعدة الاستدلال أبدًا أذونات النموذج أو المجموعة أو الحصة.

دُمج المحرك في Chat Completions وResponses وAnthropic Messages ومسار
Codex WebSocket الداخلي. لا يقبل مسار WebSocket إلا نماذج Codex المستهدفة؛ ولا يمكن
تنفيذ أهداف المجموعات من خلاله. يُخزَّن قرار القاعدة في تتبع المسار الحالي دون أي أسرار.

## الاستمرارية

ينشئ ترحيل قاعدة البيانات `src/lib/db/migrations/126_reasoning_routing_rules.sql`
جدول `reasoning_routing_rules`. تشير القواعد إلى مفاتيح API والمجموعات واتصالات المزوّد المخزّنة.
تؤدي عمليات الحذف إلى تنظيف القواعد المرتبطة. وتحافظ طبقة الوصول إلى قاعدة البيانات في
`src/lib/db/reasoningRoutingRules.ts` على ذاكرة تخزين مؤقت قابلة للإبطال لمسار الطلب.

تُضمَّن القواعد في نُسخ SQLite الاحتياطية، وتصدير قاعدة البيانات بالكامل، وحزمة مزامنة الإعدادات.
تعطّل `reconcileReasoningRulesForSync` القواعد المستوردة ذات المراجع المفقودة وتُبلغ عن تلك
التعارضات.
