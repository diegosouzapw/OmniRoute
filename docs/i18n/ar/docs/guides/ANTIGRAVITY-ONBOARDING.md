## 1. مقارنة Antigravity وAntigravity CLI ‏(agy)

يستخدم كلا المزوّدين **واجهة Google الخلفية نفسها** — عميل OAuth نفسه، وتحديث الرمز المميز نفسه، ونقاط النهاية نفسها، وحسابات Google نفسها. يكمن الاختلاف في النماذج التي تظهر لك.

> راجع [الإعلان عن Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli) للاطلاع على مقارنة Google الرسمية.

| الجانب                        | `antigravity` ‏(IDE)                             | `agy` ‏(CLI)                                          |
| ----------------------------- | ------------------------------------------------ | ----------------------------------------------------- |
| **منتج Google**               | Antigravity 2.0 / Antigravity IDE                | Antigravity CLI                                       |
| **الواجهة الخلفية**           | واجهة Google Cloud Code API نفسها                | واجهة Google Cloud Code API نفسها                     |
| **OAuth / الرمز المميز**      | العميل نفسه، والتحديث نفسه                       | العميل نفسه، والتحديث نفسه                            |
| **كتالوج النماذج**            | قائمة منتقاة ثابتة (مضمّنة مباشرةً في OmniRoute) | تُستعلم مباشرةً من Google عبر `:fetchAvailableModels` |
| **نماذج Claude**              | Sonnet 4.6، وOpus 4.6 (أربعة متغيرات لكل منهما)  | Sonnet 4.6، وOpus 4.6 (أربعة متغيرات لكل منهما)       |
| **تسمية Gemini**              | تسميات واضحة (Low/Medium/High)                   | معرّفات المصدر (extra-low/low/agent)                  |
| **نماذج إضافية**              | `gpt-oss-120b-medium`                            | قد تتضمن نماذج إضافية من Google                       |
| **حالة الاستخدام الافتراضية** | التكامل مع IDE ‏(VS Code وJetBrains)             | الوصول عبر CLI / API                                  |
| **الحصة**                     | مشتركة مع agy (حساب Google نفسه)                 | مشتركة مع antigravity (حساب Google نفسه)              |

**النماذج المتاحة (تم التحقق منها تجريبيًا، 2026-07-29)**:

- Gemini: ‏3.6 Flash، و3.5 Flash، و3.1 Pro، و3 Flash، و2.5 Flash (بمستويات تفكير مختلفة)
- Claude: ‏Sonnet 4.6، وOpus 4.6 (لكل منهما متغيرات default/low/medium/high)
- أخرى: GPT-OSS 120B Medium
- **Claude Sonnet 5 غير متاح** — لا تُدعم سوى متغيرات 4.6

**سبب اختلاف كتالوج النماذج**: واجهة CLI من Google «محسّنة للسرعة وتقليل الأعباء» و«محسّنة بالتكامل مع نماذج Gemini» (وفقًا لمدونة Google الرسمية). أما منتج الويب/IDE فهو «محسّن للشمولية». تستخدم CLI الأمر `:fetchAvailableModels` لاكتشاف النماذج ديناميكيًا، بينما يستخدم IDE قائمة منتقاة ثابتة.

**عمليًا**: استخدم البادئة `agy/` لنماذج Gemini (مثل `agy/gemini-3.7-flash-high`). واستخدم `antigravity/` للقائمة المنتقاة الثابتة. يصل كلاهما إلى واجهة Google الخلفية نفسها، لكنهما يعرضان تسميات مختلفة للنماذج. الحصة مشتركة — يُحتسب استخدام أيّ من المزوّدين ضمن حدود حساب Google نفسه.

## 2. Google One AI Pro: نظام الحصص

> راجع [مستندات Antigravity: الخطط](https://antigravity.google/docs/plans) للاطلاع على تفاصيل الحصص الرسمية، و[التغييرات على خطط Antigravity](https://antigravity.google/blog/changes-to-antigravity-plans) للاطلاع على أحدث تحديثات الأسعار.

يستخدم Google Antigravity **نظام حصص ثنائي الطبقات** يعتمد على «العمل المنجَز» (الوزن الحسابي)، وليس على عدد الرسائل.

### الطبقتان

| الطبقة                       | ماهيتها                      | دورة التحديث                                                                  |
| ---------------------------- | ---------------------------- | ----------------------------------------------------------------------------- |
| **فترة 5 ساعات**             | رصيد فوري من «العمل المنجَز» | يُعاد تعيينه بعد 5 ساعات من أول طلب في الجلسة                                 |
| **الحد الأساسي لمدة 7 أيام** | حد أقصى أسبوعي صارم          | يتجاوز تحديث الـ5 ساعات عند بلوغه؛ ويمنع الاستخدام حتى فترة الـ7 أيام التالية |

**كيفية احتساب «العمل المنجَز»**: تستنزف المهام التي تعتمد بكثافة على الوكلاء (مثل «أعِد هيكلة هذا المستودع بالكامل») الحصة بسرعة أكبر بكثير من المهام البسيطة (مثل «أصلح هذه الدالة»). لا توجد لوحة معلومات فورية تعرض الاستهلاك.

### مستويات الخطط

| الخطة        | السعر       | الحصة                                 | الحد الأسبوعي                           |
| ------------ | ----------- | ------------------------------------- | --------------------------------------- |
| المجانية     | $0          | حصة مجدية، تُحدَّث أسبوعيًا           | نعم                                     |
| AI Pro       | $19.99/شهر  | حصة مرتفعة، مع تحديث متجدد كل 5 ساعات | نعم (يتجاوز تحديث الـ5 ساعات عند بلوغه) |
| AI Ultra 5x  | $99.99/شهر  | 5 أضعاف حصة Pro                       | لا يوجد حد أسبوعي                       |
| AI Ultra 20x | $199.99/شهر | 20 ضعف حصة Pro                        | لا يوجد حد أسبوعي                       |

### نماذج Gemini مقابل النماذج الأخرى

- **نماذج Gemini** (Flash + Pro): تشترك في حد معدل واحد يُحتسب وفق تسعير API. إذا كان Flash أرخص من Pro بمقدار 8 أضعاف، فستحصل على عدد أكبر من رموز Flash بمقدار 8 أضعاف.
- **النماذج غير التابعة لـGemini** (Claude، GPT-OSS): لها حدود معدل **منفصلة**. وقد تظل متاحة حتى عند حظر Gemini.

### أرصدة AI (الاستخدام الإضافي)

> راجع [أرصدة Google One AI](https://support.google.com/googleone/answer/14534406) لمعرفة كيفية عمل الأرصدة.

عند استنفاد الحصة الأساسية:

- **أبدًا**: انتظر حتى تتجدد الحصة؛ ويظهر التنبيه "Baseline model quota reached"
- **دائمًا**: استخدم أرصدة AI تلقائيًا؛ ثم عُد إلى الحصة الأساسية عند تجددها

تُشترى الأرصدة بشكل منفصل وتُخصم وفق تسعير API القياسي.

### تفاصيل أساسية

- الحصة **مشتركة على مستوى الحساب** — إذ يستخدم حساب Google نفسه في Antigravity IDE وCLI وOmniRoute رصيد حصة واحدًا مشتركًا
- لكل حساب Google حصة مستقلة خاصة به — حسابات متعددة = أرصدة حصص متعددة
- أفاد مستخدمو AI Pro بحدوث **حظر لمدة 7 أيام** بدلًا من إعادة التعيين بعد 5 ساعات عند بلوغ الحد الأساسي الأسبوعي (أكدت Google أن هذا السلوك مقصود في حالات الطلب المرتفع)

**عند استنفاد حصة حسابك**: يعيد OmniRoute المحاولة تلقائيًا باستخدام الحساب التالي المتاح في المسار المجمّع. لا يلزم أي تدخل يدوي.

## 3. كيفية الحصول على projectId

يحتاج كل اتصال antigravity/agy إلى `projectId` خاص بـGoogle Cloud Code. وبدونه، تُرجع نقطة النهاية `/v1internal:models` الخطأ 404.

### الطريقة A: تلقائيًا (موصى بها)

يتولى OmniRoute ذلك تلقائيًا. عند إضافة حساب Google جديد عبر OAuth في لوحة المعلومات:

1. يجدّد OmniRoute الرمز المميز
2. يستدعي `loadCodeAssist` لاكتشاف projectId
3. إذا لم يكن هناك مشروع، يستدعي `onboardUser` لإنشاء مشروع
4. يعيد محاولة `loadCodeAssist` للحصول على projectId الذي أُنشئ حديثًا
5. يحفظه في قاعدة البيانات

**ينجح هذا مع معظم الحسابات** — ولا يلزم تنفيذ أي خطوات يدوية.

### الطريقة B: يدويًا عبر agy CLI

إذا فشل الاكتشاف التلقائي (راجع القسم 5 لمعرفة الحالات التي يحدث فيها ذلك):

```bash
# ثبّت agy CLI (إذا لم يكن مثبّتًا بالفعل)
npm install -g @anthropic-ai/agy

# سجّل الدخول باستخدام حساب Google الخاص بك
agy login

# حدّد الحساب الذي يحتاج إلى الإعداد
# يؤدي ذلك إلى تسجيل Cloud Code وتعيين projectId
```

بعد نجاح `agy login`، حدّث الرمز المميز في لوحة معلومات OmniRoute. سيُكتشف projectId تلقائيًا.

### كيفية التحقق

تحقق من قاعدة البيانات:

```bash
# داخل حاوية OmniRoute
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

أو تحقق من السجلات:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. عنوان URI لإعادة توجيه OAuth

### المشكلة

يتطلب Google OAuth عنوان URI صالحًا لإعادة التوجيه. يستخدم OmniRoute افتراضيًا `http://127.0.0.1:20128/callback` (عنوان loopback). يعمل هذا مع عمليات البناء المحلية، لكنه **يفشل في عمليات النشر عن بُعد** (مثل خادم يتم الوصول إليه عبر عنوان IP على الشبكة المحلية LAN).

يرفض Google عناوين URI لإعادة التوجيه التي:

- تستخدم عناوين IP (يجب أن تكون نطاقًا ينتهي بـ `.com` أو `.org` وما إلى ذلك)
- لا تتطابق مع عناوين URI لإعادة التوجيه المسجّلة في إعدادات عميل OAuth

### الحل

**الخيار A: استخدام تدفق OAuth المضمّن (الافتراضي)**

- يعمل عند الوصول إلى OmniRoute من `localhost` أو `127.0.0.1`
- لا يتطلب أي إعداد

**الخيار B: بيانات اعتماد OAuth مخصّصة**

- عيّن `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` في بيئتك
- وفّر بيانات اعتماد Google OAuth الخاصة بك:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- سجّل `https://your-domain.com/callback` بوصفه عنوان URI معتمدًا لإعادة التوجيه في Google Cloud Console

**الخيار C: استخدام agy CLI لتسجيل الدخول الأولي**

- شغّل `agy login` على الجهاز الذي سيصل إلى OmniRoute
- يكتمل تدفق OAuth محليًا، وتُخزّن الرموز المميزة
- استورد الاتصال إلى OmniRoute عبر لوحة التحكم

### القيود

- تتطلب بيانات اعتماد OAuth المخصّصة اسم نطاق (لا يقبل Google عناوين IP بوصفها عناوين URI لإعادة التوجيه)
- إذا لم يكن لديك نطاق، فاستخدم الخيار A أو C بدلًا من ذلك

## 5. استكشاف الأخطاء وإصلاحها: عند فشل الإعداد التلقائي

يتولى OmniRoute تلقائيًا اكتشاف projectId وتهيئة معظم الحسابات. وعند فشل ذلك، يكون السبب الجذري عادةً واحدًا مما يلي:

### منطقة الحساب محظورة

**العَرَض**: يعرض `agy login` الرسالة "فشل التحقق من الأهلية: حسابك الحالي غير مؤهل لاستخدام Antigravity، لأنه غير متاح حاليًا في موقعك."

**السبب الجذري**: تحتوي حسابات Google على حقل "ارتباط البلد" في الواجهة الخلفية، ويُعيَّن عند التسجيل. تتحقق agy CLI وCloud Code API من هذا الحقل بصرامة — بخلاف Gemini على الويب، الذي يتحقق فقط من عنوان IP الحالي.

> للتحقق من المنطقة المرتبطة بحسابك أو تغييرها، تفضّل بزيارة [نموذج ارتباط البلد من Google](https://policies.google.com/country-association-form).

**لماذا يعمل Gemini على الويب بينما لا تعمل agy**:

- Gemini على الويب / Google One: يتحقق من عنوان IP الحالي فقط (يمر الاتصال عبر الوكيل بنجاح)
- agy CLI / Cloud Code API: يقرأ حقل ارتباط البلد من الواجهة الخلفية (الوكيل لا يفيد)

**الإصلاح**:

1. تفضّل بزيارة [نموذج ارتباط البلد من Google](https://policies.google.com/country-association-form) أثناء استخدام عنوان IP أمريكي
2. أرسل طلب تغيير المنطقة (حدّد "أعيش في بلد مختلف")
3. انتظر من 1 إلى 24 ساعة حتى تعالج Google الطلب وترسل إشعارًا عبر البريد الإلكتروني
4. بعد ذلك، يُفترض أن ينجح `agy login`

### لا يحتوي الحساب على مشروع Cloud Code

**العَرَض**: تعرض السجلات `loadCodeAssist returned no project id` و`onboardUser failed (400)`.

**السبب الجذري**: لم يُسجَّل الحساب من قبل في Google Cloud Code، وفشلت عملية التهيئة التلقائية.

**الإصلاح**: شغّل `agy login` يدويًا لبدء تسجيل Cloud Code، ثم حدّث الرمز المميز في لوحة تحكم OmniRoute.

### انتهت صلاحية الرمز المميز أو تم إلغاؤه

**العَرَض**: أخطاء 401 في السجلات، أو رسائل "انتهت صلاحية الرمز المميز".

**الإصلاح**: حدّث الرمز المميز من لوحة التحكم → موفّرو الخدمة → agy → انقر على أيقونة التحديث. إذا تم إلغاء رمز التحديث نفسه، فستحتاج إلى إعادة المصادقة عبر OAuth.

## مخطط اتخاذ القرار

```
هل الحساب لا يعمل؟
│
├─ هل يحتوي على projectId في قاعدة البيانات؟
│  ├─ نعم → المشكلة في مكان آخر (انتهت صلاحية الرمز، أو تم بلوغ حد المعدل، إلخ.)
│  └─ لا ↓
│
├─ هل تم تعيين «ارتباط البلد» الخاص بالحساب إلى منطقة محظورة؟
│  ├─ نعم → غيّر المنطقة عبر نموذج ارتباط البلد من Google
│  │         (https://policies.google.com/country-association-form)
│  │         انتظر من ساعة إلى 24 ساعة، ثم أعد المحاولة
│  └─ لا ↓
│
├─ هل لدى الحساب اشتراك Google One AI Pro؟
│  ├─ لا → اشترك أولًا عبر one.google.com
│  └─ نعم ↓
│
├─ جرّب الاكتشاف التلقائي (حدّث الرمز في لوحة التحكم)
│  ├─ نجح → تم
│  └─ ما زال يفشل ↓
│
└─ يدويًا: شغّل `agy login` على الجهاز
   ├─ نجح → حدّث الرمز في لوحة التحكم، وسيتم اكتشاف projectId
   └─ فشل → تحقّق من رسالة الخطأ؛ يُرجّح وجود مشكلة في المنطقة أو الاشتراك
```

## مرجع سريع

| المهمة                                | الأمر / عنوان URL                                                                    |
| ------------------------------------- | ------------------------------------------------------------------------------------ |
| تغيير منطقة الحساب                    | [نموذج ارتباط البلد من Google](https://policies.google.com/country-association-form) |
| تسجيل الدخول إلى agy CLI              | `agy login`                                                                          |
| التحقق من projectId في قاعدة البيانات | `SELECT email,project_id FROM provider_connections WHERE provider='agy'`             |
| التحقق من السجلات                     | `podman logs omniroute 2>&1 \| grep projectId`                                       |
| تحديث الرمز                           | لوحة التحكم → المزوّدون → agy → انقر على أيقونة التحديث                              |
