> **باختصار**: يصنّف OmniRoute مزوّديه **المجانيين** حسب جودة النماذج باستخدام **درجات ELO الخاصة بـ Arena AI
> (على غرار LMArena)**. افتح صفحة **تصنيفات المزوّدين المجانيين** في
> لوحة المعلومات لمعرفة المزوّدين المجانيين الذين يوفّرون أقوى النماذج لمهمتك —
> إجمالًا، أو بعد التصفية حسب الفئة (البرمجة، المراجعة، التوثيق، تصحيح الأخطاء).

---

## ما هي

يسجّل OmniRoute عددًا قدره 329 مزوّدًا، من بينهم 155 إدخالًا في الكتالوج معلَّمًا بأنه **مجاني/لا يتطلب مصادقة**
(من دون مصادقة،
أو OAuth ضمن الفئة المجانية، أو مفتاح API ضمن الفئة المجانية — راجع
[دليل الفئات المجانية](../getting-started/FREE-TIERS-GUIDE.md) ودليل
[الفئات المجانية الكامل](../reference/FREE_TIERS.md)). لكن المشكلة تكمن في أن المزوّدين المجانيين يتفاوتون
بشكل كبير في جودة النماذج. فالمزوّد الذي لا يتطلب مصادقة ويقدّم نموذجًا متطورًا أكثر فائدة بكثير
من مزوّد يقدّم نموذجًا قديمًا صغيرًا.

تجيب **تصنيفات المزوّدين المجانيين** عن سؤال "**أي مزوّد مجاني يمنحني أفضل نموذج؟**" من خلال
ربط كتالوج كل مزوّد مجاني بـ **درجات جودة مستمدة من الجمهور** من
**لوحة صدارة Arena AI** (درجات ELO المستندة إلى التفضيلات البشرية، وهي الفكرة نفسها وراء ساحة
روبوتات المحادثة في LMArena). ثم يُصنَّف المزوّدون حسب قوة **أفضل نموذج مجاني** لديهم.

يُحتسب التصنيف من ثلاثة مصادر فعلية:

1. قوائم المزوّدين المجانيين — `NOAUTH_PROVIDERS`، بالإضافة إلى إدخالات `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` المعلَّمة بـ `hasFree`
   (`src/shared/constants/providers.ts`).
2. كتالوج نماذج كل مزوّد من سجل المزوّدين
   (`open-sse/config/providerRegistry.ts`).
3. درجات ملاءمة المهام المستمدة من ELO والمخزّنة في جدول قاعدة البيانات `model_intelligence` بواسطة
   محرك مزامنة Arena ELO ‏(`src/lib/arenaEloSync.ts`).

يوجد منطق الربط في `src/lib/freeProviderRankings.ts`.

## كيفية الوصول

### صفحة لوحة المعلومات

افتح لوحة المعلومات وانتقل إلى **التكاليف ← تصنيفات المزوّدين المجانيين**، أو انتقل مباشرةً إلى:

```
/dashboard/free-provider-rankings
```

تعرض الصفحة (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) ما يلي:

- **منصة لأفضل 3 مزوّدين** (🥇 🥈 🥉) من المزوّدين المجانيين الأعلى تصنيفًا.
- **جدول تصنيف** كاملًا بالأعمدة: **الترتيب**، **المزوّد**، **أفضل نموذج**،
  **الدرجة**، **متوسط الدرجة**، **النماذج**، **النوع**.
- **أزرار تصفية الفئات**: _كل الفئات_، _الافتراضي_، _البرمجة_، _المراجعة_،
  _التوثيق_، _تصحيح الأخطاء_.

توضّح شارة **النوع** الخاصة بكل مزوّد كيفية إتاحته مجانًا:

| الشارة   | المعنى                                             |
| -------- | -------------------------------------------------- |
| `NOAUTH` | مجاني دائمًا، ولا يتطلب بيانات اعتماد              |
| `OAUTH`  | مزوّد OAuth لديه فئة مجانية (`hasFree`)            |
| `APIKEY` | مزوّد يعتمد مفتاح API ولديه فئة مجانية (`hasFree`) |

تُعرض الدرجات في صورة تسميات سهلة القراءة (مثل _نخبوي_، _ممتاز_، _جيد جدًا_،
_جيد_، _متوسط_) بدلًا من أرقام أولية، لأن القيمة الأساسية تعبّر عن جودة
تصنيف نسبية، وليست نسبة مئوية.

### نقطة نهاية API

تعتمد الصفحة على نقطة نهاية عامة للقراءة
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

معاملات الاستعلام (يتم التحقق منها باستخدام Zod):

| المعامل    | النوع  | الافتراضي | ملاحظات                                                                                                   |
| ---------- | ------ | --------- | --------------------------------------------------------------------------------------------------------- |
| `category` | string | (لا يوجد) | إحدى القيم `default`، `coding`، `review`، `documentation`، `debugging`. احذفه للحصول على التصنيف الموحّد. |
| `limit`    | number | `50`      | تُقيَّد قيمته بالنطاق `1–100`.                                                                            |

بنية الاستجابة:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

تمثّل `eloRaw` قيمة Arena ELO الأصلية؛ أما `score` فهي قيمة ملاءمة المهمة المطبّعة
(انظر أدناه). ويُستبعد من الاستجابة أي مزوّد لا يملك نماذج حاصلة على درجات.

## كيفية عمل الدرجات

### المصدر: لوحة صدارة Arena AI

يجلب محرك مزامنة Arena ELO (`src/lib/arenaEloSync.ts`) لوحتي صدارة — `text`
و`code` — من واجهة API الخاصة بلوحة صدارة Arena AI
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`). يتضمن كل إدخال في لوحة الصدارة
اسم النموذج، والمورّد، و`score` ‏ELO، وفاصل الثقة، وعدد الأصوات.

تُربط فئات لوحة الصدارة بفئات مهام OmniRoute كما يلي:

| لوحة صدارة Arena | فئات مهام OmniRoute                               |
| ---------------- | ------------------------------------------------- |
| `text`           | `default`، `review`، `documentation`، `debugging` |
| `code`           | `coding`                                          |

### التطبيع (درجة ملاءمة المهمة)

تُطبَّع درجات ELO الخام لكل لوحة صدارة إلى **قيمة ملاءمة للمهمة ضمن `[0.4, 0.98]`**:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

لا تصل الدرجة مطلقًا إلى `0` أو `1`، مما يترك هامشًا لتجاوزات المستخدم. وهذا هو حقل
`score` الذي تراه في استجابة API والتسمية المعروضة في لوحة المعلومات.

### الثقة

يحصل كل إدخال على مستوى ثقة استنادًا إلى عدد الأصوات في Arena:

| الثقة    | الأصوات |
| -------- | ------- |
| `high`   | ≥ 5,000 |
| `medium` | ≥ 1,000 |
| `low`    | < 1,000 |

### التخزين وحداثة البيانات

تُكتب الإدخالات المطبَّعة في جدول قاعدة البيانات `model_intelligence` مع
`source = "arena_elo"` (`src/lib/db/modelIntelligence.ts`). **تنتهي صلاحية الإدخالات بعد
7 أيام**، ولذلك يُزال في النهاية أي مزوّد يتوقف عن المزامنة بدلًا من عرض
بيانات قديمة.

تعمل المزامنة **افتراضيًا**:

- تعمل مرة واحدة عند بدء تشغيل الخادم، ثم وفق مؤقت دوري
  (`src/lib/arenaEloSync.ts`، مع ربطها من `src/instrumentation-node.ts`).
- هي **غير حاجبة ولا تتسبب مطلقًا في فشل فادح** — إذا فشل الجلب من المصدر الخارجي، يواصل OmniRoute
  العمل، وتعرض التصنيفات ببساطة آخر بيانات صالحة (أو حالة فارغة).

يتحكم فيها متغيرا بيئة (موثّقان في
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)):

| المتغير                   | القيمة الافتراضية | الغرض                                                   |
| ------------------------- | ----------------- | ------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`            | اضبطه على `false` لإلغاء الاشتراك في المزامنة الخارجية. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h)     | الفاصل الزمني للمزامنة، بالثواني.                       |

### المزامنة اليدوية / الحالة / المسح

بالنسبة للمشغّلين، تتيح نقطة نهاية إدارة مصادقًا عليها تحكمًا يدويًا
(`src/app/api/intelligence/sync/route.ts` — تتطلب مصادقة الإدارة):

```
GET    /api/intelligence/sync          # حالة المزامنة الحالية (enabled، lastSync، nextSync، intervalMs)
POST   /api/intelligence/sync          # تشغيل مزامنة يدوية؛ النص: { "dryRun": true } للمعاينة دون كتابة
DELETE /api/intelligence/sync          # مسح جميع إدخالات معلومات arena_elo المتزامنة
```

إذا كانت صفحة التصنيفات فارغة، فإن طلب `POST /api/intelligence/sync` يدويًا (أو مجرد
إعادة تشغيل الخادم) يعيد ملأها.

### مطابقة النماذج مع لوحة الصدارة

لا تتطابق معرّفات نماذج السجل وأسماء نماذج Arena دائمًا بصورة تامة. يستخدم التصنيف
مطابقة مرنة (`findMatchingIntelligence` في `src/lib/freeProviderRankings.ts`):

1. مطابقة تامة لمعرّف النموذج المطبَّع.
2. المطابقة بعد إزالة لاحقة إصدار في النهاية (مثلًا `kimi-k2.6` ← `kimi-k2`).
3. مطابقة البادئة (يكون اسم نموذج لوحة الصدارة بادئة لمعرّف السجل).

على جانب المزامنة، تُزال بادئات المورّدين المعروفة (`anthropic/`، و`openai/`، و`google/`، …)
وتوسّع خريطة أسماء مستعارة صغيرة الأسماء القياسية إلى الصيغ التي يستخدمها OmniRoute
داخليًا، بحيث تظل النماذج قابلة للعثور عليها تحت أي اسم.

### كيفية تصنيف المزوّد

لكل مزوّد مجاني، يحسب المحرك درجة كل نموذج في كتالوجه، ثم:

- **أفضل نموذج** = نموذج المزوّد الحاصل على أعلى درجة.
- **متوسط الدرجة** = متوسط الدرجات لجميع نماذج ذلك المزوّد التي حُسبت درجاتها.
- **النماذج** = عدد نماذج المزوّد التي كانت لها درجة في Arena.

يُرتّب المزوّدون حسب **درجة أفضل نموذج** أولًا، ثم حسب متوسط الدرجة. ويكافئ ذلك
المزوّد الذي يوفّر نموذجًا مجانيًا قويًا واحدًا على الأقل.

## استخدامه لاختيار المزوّدين المجانيين

1. **اختر الفئة المناسبة.** استخدم عامل التصفية **البرمجة** لأعباء عمل الوكلاء/البرمجة، أو
   اتركه على **جميع الفئات** / **الافتراضي** للدردشة العامة. قد يختلف ترتيب المزوّد نفسه
   بين الفئات لأن نموذجه الأفضل يختلف باختلاف لوحة الصدارة.
2. **فضّل المراكز الثلاثة الأولى للإعدادات أحادية المحاولة.** إذا كنت تريد الاتصال بمزوّد
   مجاني واحد أو اثنين فقط، فابدأ بالمزوّدين الأعلى ترتيبًا في فئتك.
3. **تحقّق من شارة النوع.** مزوّدو `NOAUTH` هم الأسرع في الاتصال (من دون
   بيانات اعتماد). تتطلب المستويات المجانية من `OAUTH` / `APIKEY` تسجيلًا سريعًا، لكنها غالبًا ما تتيح
   نماذج أقوى. راجع [دليل المستويات المجانية](../getting-started/FREE-TIERS-GUIDE.md) للاطلاع على
   خطوات الاتصال.
4. **اتصل بعدة مزوّدين ودع Auto-Combo يقرر.** إن بيانات Arena ELO نفسها التي تشغّل
   هذه الصفحة تغذّي أيضًا **عامل الملاءمة للمهمة** في محرك تسجيل النقاط Auto-Combo
   (`open-sse/services/autoCombo/taskFitness.ts`، ترتيب الحل
   `user_override → arena_elo → models_dev_tier → static table`). لذا، بعد الاتصال
   بأفضل المزوّدين المجانيين، سيؤدي التوجيه باستخدام `model: "auto"` (مثل `auto/coding`) إلى
   تفضيل النماذج المجانية الأعلى جودة تلقائيًا لكل طلب. راجع
   [Auto-Combo](../routing/AUTO-COMBO.md) للاطلاع على نظام التسجيل الكامل ذي العوامل الستة عشر.
