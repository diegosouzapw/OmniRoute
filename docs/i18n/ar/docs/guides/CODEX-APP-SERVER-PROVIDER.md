يتيح OmniRoute طريقتين **اثنتين** لاستخدام OpenAI Codex:

| المزوّد                | كيفية اتصاله بـ OpenAI                                                                                                                                                                    | محاذير الاستخدام                                             |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| **`codex`**            | يعيد إرسال رمز OAuth الخاص بـ ChatGPT/OpenAI مباشرةً إلى Responses API                                                                                                                    | **نعم** — الجلسة الرسمية غير مصرّح باستخدامها عبر وكيل/موجّه |
| **`codex-app-server`** | يشغّل **أمر `codex app-server` الخاص بـ Codex CLI نفسه** عبر JSON-RPC/WebSocket؛ وتتولى CLI ملكية OAuth الخاص بها وتحديثه تلقائيًا (`~/.codex/auth.json`) تمامًا مثل جلسة `codex` تفاعلية | **لا** — لا يعيد OmniRoute إرسال أي رمز إلى API مطلقًا       |

نظرًا إلى أن `codex-app-server` لا يعيد إرسال أي رمز مطلقًا، فإنه لا يخضع
لمحاذير استخدام إعادة إرسال الجلسة. لكنه يتطلب وجود **Codex CLI يمكن الوصول
إليها عبر عنوان URL المهيأ لـ app-server**، ويجب أن تكون CLI هذه **مسجّلة الدخول**.

## 1. البنية

```
┌─ تطبيق OmniRoute ────────────────┐        ┌─ الحاوية المرافقة codex-app-server ─┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ رمز الإمكانية)               │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  يدير OpenAI OAuth ذاتيًا           │
└──────────────────────────────────┘        │  (~/.codex/auth.json، تحديث تلقائي) │
        │ مشاركة (وحدات تخزين compose)      └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → رمز إمكانية WS (يتم تركيبه لدى كليهما)
  codex-appserver-home    → ~/.codex (يكتب auth.json عبر لوحة المعلومات،
                             ويقرأه codex app-server في الحاوية المرافقة)
```

- تستمع الحاوية المرافقة **فقط** على شبكة compose الداخلية
  (`ws://codex-app-server:1456`) خلف رمز إمكانية. ولا يتم **مطلقًا** نشرها
  على المضيف أو الإنترنت.
- تكون Codex CLI مضمنة في `omniroute:base`، ولذلك لا يلزم تثبيت codex على
  المضيف أو جهاز المستخدم عند تشغيل الحاوية المرافقة.

## 2. تشغيله

```bash
# شغّل الحزمة مع ملف تعريف الحاوية المرافقة codex app-server:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

تنشئ الحاوية المرافقة رمز إمكانية WS الخاص بها عند أول تشغيل (داخل وحدة التخزين
المشتركة `codex-appserver-token`)، ويقرأ التطبيق الرمز نفسه عبر
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE`. لا حاجة إلى ربط الرمز يدويًا.

## 3. الاتصال + تسجيل الدخول

1. أضف اتصالًا في لوحة المعلومات لـ **OpenAI Codex (App-Server)**. لا يلزم مفتاح
   API أو رمز (فهو مزوّد لا يتطلب مصادقة — تتولى الحاوية المرافقة المصادقة).
2. إذا لم تكن Codex CLI الخاصة بالحاوية المرافقة **مسجّلة الدخول بعد**، فسيعرض
   فحص سلامة الاتصال _"قيد التشغيل ولكن لم يُسجّل الدخول"_ (وليس خطأ مصادقة
   أحمر). استخدم **تسجيل الدخول باستخدام ChatGPT**: يؤدي ذلك إلى تشغيل مصادقة
   OAuth القياسية للأجهزة الخاصة بـ Codex في متصفحك، ثم كتابة
   `~/.codex/auth.json` إلى وحدة التخزين المشتركة عبر **تطبيق المصادقة**
   (وتخدم عملية تسجيل الدخول الواحدة نفسها مزوّدي `codex` و
   `codex-app-server`).
3. بعد تسجيل الدخول، يتحول فحص السلامة إلى اللون الأخضر (إذ يتحقق من كلٍ من
   `/readyz` **و** `account/read` — أي إنه يعمل _وتمت مصادقته_) ويبدأ العمل.

لا تستبدل لوحة المعلومات مطلقًا ملف `~/.codex/auth.json` سليمًا وموجودًا — فهي
لا تكتب إلا عندما يكون الملف غير موجود أو يكون رمزه قديمًا (ويتم دائمًا إنشاء
نسخة احتياطية).

## 4. سيناريوهات النشر

- **مشغّل لديه Codex CLI تمت مصادقتها مسبقًا** — اركب دليل المضيف
  `~/.codex` داخل الحاوية المرافقة (`codex-appserver-home`) وتخطَّ خطوة تسجيل الدخول.
- **مستخدم عام، من دون تثبيت codex محليًا** — لا أهمية لذلك: تحتوي الحاوية
  المرافقة على CLI. ولا يحتاج المستخدم إلا إلى المصادقة عبر لوحة المعلومات.
- **OmniRoute على جهاز فعلي (من دون حاوية مرافقة، وcodex على المضيف)** — وجّه
  `OMNIROUTE_CODEX_APPSERVER_WS` إلى `codex app-server` الخاص بك وتأكد من تسجيل
  دخول codex على المضيف؛ ويظهر تلميح "codex غير مثبت" إذا كان الملف التنفيذي
  مفقودًا.

## 5. خروج عبر اتصال سكني / UDP (إضافة للمشغّل، غير مضمّنة)

تخرج حركة مرور الحاوية المرافقة العامة أعلاه عبر الشبكة العادية للحاوية. ويمكن
للمشغّل الذي يحتاج إلى خروج حركة مرور Codex عبر **منفذ خروج سكني** (مثل حاوية
مرافقة TUN tailscale تنقل TCP + UDP/QUIC) تشغيل ذلك كتجاوز compose منفصل؛ وهو
**ليس** جزءًا من ملف التعريف `codex-app-server` المضمّن عمدًا. راجع دليل تشغيل
العمليات الداخلي لإعداد ذلك.
