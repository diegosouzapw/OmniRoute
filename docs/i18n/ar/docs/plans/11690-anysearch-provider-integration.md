## 1. الحقائق الأساسية للخدمة (الوثائق الرسمية، بعد التحقق المتقاطع)

- عنوان URL الأساسي: `https://api.anysearch.com` ‏(REST) + ‏`POST /mcp` ‏(MCP، ‏JSON-RPC 2.0).
- `POST /v1/search` - المعاملات: `query` (مطلوب)، `max_results` ‏(1-10، القيمة الافتراضية 10)، `tag` ‏(التوجيه العمودي وفق `{domain}.{sub_domain}`)، `zone` ‏(cn/intl)، `language`، `params` (حقول عمودية منظّمة)، `format` ‏(json/markdown).
- `GET /v1/sub-domains?domain=...` - كتالوج الإمكانات، ولا يُحتسب ضمن الحصة.
- `POST /v1/extract` - جلب/استخراج `{url, title, content}`؛ نص طلب JSON صارم، بحد أقصى 16 KiB.
- `POST /v1/auth/email/register` - تسجيل باستدعاء واحد، يُرجع مفتاحًا نصيًا صالحًا للاستخدام مرة واحدة `as_sk_...`.
- المصادقة: ترويسة `Authorization: Bearer <as_sk_...>` اختيارية؛ يؤدي الاستخدام المجهول إلى تطبيق حدود لكل عنوان IP مع استهلاك الحصة اليومية المجانية؛ ويُرجع المفتاح غير الصالح 401/403 من دون رجوع صامت إلى الوضع المجهول.
- الخطة المجانية: 1000 طلب/يوم، و20 QPS لكل مفتاح. الخطة المدفوعة: لم يُحدَّد سعرها (قريبًا).
- غلاف الاستجابة: النجاح `{code: 0, message: "success", request_id, data}`؛ والفشل `{code: -1, message}`. لا تحتوي أخطاء المصادقة/الحصة على `error_code` منظّم (نص الرسالة هو الإشارة)؛ بينما تحتوي الأخطاء الخاصة بالاستخراج على `error_code` ‏(`invalid_extract_url`، `extract_failed`). لا توجد ترويسة `Retry-After` مع 429.

## 3. القرارات (تم التوصل إليها جميعًا في 2026-08-26)

1. **نهج التوجيه: `fallbackOnly`.** المبرر: يجب ألا يهيمن موفّر مجاني بتكلفة 0 مطلقًا على التوجيه التلقائي حسب التكلفة؛ ولا يتأثر الاختيار الصريح ولا الرجوع عند تجاوز الفشل. السابقة: إدخال xquik المدمج.
2. **النطاق: webSearch + webFetch عبر `POST /v1/extract` في الإصدار v1.** يتوافق ذلك مع النموذج الذهني مزدوج الإمكانات لـ tavily/exa. وتظل الواجهات المتخصصة (`tag` و`sub-domains` و`batch_search`) خارج النطاق — إذ لا يوجد حاليًا تمثيل وسيط (IR) للمعلمات المتخصصة.
3. **عرض الحصة: `freeMonthlyQuota: 0`** (عرض متحفظ بأسلوب xquik). ويُذكر الحد الفعلي (1000 طلب/يوم، مع إعادة تعيين يومية) بدلًا من ذلك في نص `authHint` ضمن كتالوج واجهة المستخدم. المبرر: يجب أن يتطابق عرض الحصة مع دلالات إعادة التعيين؛ فتحويل الحد اليومي إلى مكافئ شهري (30000) هو وعد زائف لا تستطيع واجهة المستخدم الوفاء به.
4. **searchTypes: ‏`["web"]` فقط.** لا يوجد دليل علني على وجود واجهة متخصصة للأخبار/الصور في AnySearch API؛ وتعرض البوابات التي تدمج واجهات API من دون واجهة متخصصة موثّقة (مثل Google Custom Search) الويب فقط، بدلًا من تحويل الأخبار ضمنيًا إلى الويب.
5. **نهج المفتاح:** يعمل من دون مفتاح؛ ويؤدي المفتاح غير الصالح إلى إرجاع 401/403، ولا يتم أبدًا خفضه ضمنيًا إلى وصول مجهول (بما يعكس عقد الخدمة الأصلية).
6. **الاستبعادات المتعمدة:** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (يبقى اعتراض المحادثة محصورًا في firecrawl/jina/tavily)؛ و`ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (تتشارك نقاط النهاية البعيدة المجهولة مجموعة واحدة محدودة حسب عنوان IP لكل عنوان IP للخروج، لذا فإن الاستخراج من دون مفتاح يتطلب اشتراكًا صريحًا، وليس مرشحًا للتوجيه التلقائي)؛ و`QUOTA_STATUS_PROVIDERS` (تشير AnySearch إلى الحصة عبر 429/الغلاف، وليس عبر حالة 402/403).

## 4. المراجع

- قالب xquik: الالتزام a0ceccc، وPR #11370 (مضمّن في الشجرة عند release/v3.8.51).
- الوثائق الرسمية لـ AnySearch: https://anysearch.com/docs، وhttps://anysearch.com/pricing؛ وكتالوج MCP ‏mcpservers.org/servers/anysearch-ai/anysearch-mcp-server؛ ومستودع المهارة github.com/anysearch-ai/anysearch-skill.
- النموذج الذهني المتبع في الصناعة: وثائق البحث في LiteLLM (سجل + ‏search() موحّدة + تمثيل وسيط وفق مواصفات Perplexity)، والبحث عبر الويب في open-webui (موفّرون مضمّنون وأداتان مزدوجتان search_web/fetch_url)، ونمط المكوّن الإضافي للأدوات في Dify؛ وسُلّم الرجوع حسب التكلفة: مستضاف ذاتيًا -> حصة مجانية -> مدفوع.
