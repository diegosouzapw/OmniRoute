يمكن لضغط Caveman تحميل حزم قواعد خاصة بكل لغة بالإضافة إلى القواعد الإنجليزية المضمّنة.
يحافظ هذا على استقرار المحرك الأساسي، مع السماح لحزم اللغات البرتغالية والإسبانية والألمانية والفرنسية والإيطالية واليابانية،
وحزم اللغات المستقبلية بالتطور بصورة مستقلة.

## الموقع

توجد حزم اللغات ضمن:

```txt
open-sse/services/compression/rules/<language>/
```

الحزم المتوفرة حاليًا (تم التحقق منها مقابل محتويات دليل `rules/`):

| اللغة                 | الدليل         | فئات القواعد المتوفرة                               |
| --------------------- | -------------- | --------------------------------------------------- |
| الإنجليزية            | `rules/en/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| الإسبانية             | `rules/es/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| البرتغالية (البرازيل) | `rules/pt-BR/` | `context`, `dedup`, `filler`, `structural`, `ultra` |
| الإندونيسية           | `rules/id/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| الإيطالية             | `rules/it/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| الألمانية             | `rules/de/`    | `context`, `filler`, `structural`                   |
| الفرنسية              | `rules/fr/`    | `context`, `filler`, `structural`                   |
| اليابانية             | `rules/ja/`    | `context`, `filler`, `structural`                   |

> **ملاحظة حول التكافؤ:** تحتوي حزم `en` و`es` و`pt-BR` و`id` و`it` على الفئات الخمس كاملة؛ بينما تتضمن حزم `de` و`fr` و`ja` ثلاث فئات. وتعود فئتا `dedup` و`ultra` المفقودتان تلقائيًا إلى القواعد الإنجليزية المضمّنة دون إصدار أي تنبيه. نرحب بالمساهمات لإضافة `dedup.json` و`ultra.json` إلى الحزم الأصغر.
>
> تستند حزمة `pt-BR` إلى **[Troglodita](https://github.com/leninejunior/troglodita)** من تطوير Lenine Júnior — وهو نظام ضغط مصمم من الصفر لقواعد البرتغالية البرازيلية (تقليل الحشو البلاغي، وإزالة كلمات الحشو في PT-BR، والاختصارات التقنية لمجتمع المطورين البرازيلي).
>
> توجد القائمة المرجعية للفئات ومخطط كل فئة في [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) (مسودة JSON Schema 2020-12).

## اكتشاف اللغة

يستخدم `languageDetector.ts` أساليب استدلال خفيفة لاستخلاص اللغة من نص المطالبة. ويظل إعداد اللغة الافتراضية
المكوّن محترمًا، كما يمكن تعطيل الاكتشاف من خلال الإعدادات عند الحاجة إلى تحكم دقيق.

تُستخدم نتيجة الاكتشاف لاختيار حزم القواعد فقط. ولا تغيّر توجيه المزوّد أو اختيار الإعدادات المحلية
أو لغة واجهة المستخدم.

## بنية الإعدادات

يمكن أن تتضمن إعدادات الضغط ما يلي:

```json
{
  "languageConfig": {
    "enabled": true,
    "defaultLanguage": "en",
    "autoDetect": true,
    "enabledPacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  },
  "cavemanConfig": {
    "language": "en",
    "autoDetectLanguage": true,
    "enabledLanguagePacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  }
}
```

يتحكم `languageConfig` في الإعدادات الافتراضية للوحة المعلومات والمعاينة. أما `cavemanConfig` فهو إعداد محرك وقت التشغيل
المستخدم عندما يضغط Caveman نص الرسالة.

## إضافة حزمة لغة

1. أنشئ `open-sse/services/compression/rules/<language>/<pack>.json`.
2. استخدم تنسيق قواعد Caveman الموضّح في `docs/compression/COMPRESSION_RULES_FORMAT.md`.
3. اجعل عمليات الاستبدال متحفظة وتجنب تغيير الشيفرة أو المعرّفات أو عناوين URL أو JSON.
4. أضف اختبارات لسلوك اختيار اللغة والاستبدال أو حدّثها.
5. أضف تسميات جديدة للوحة المعلومات/i18n إذا كانت اللغة تظهر في محددات واجهة المستخدم.

## واجهة API

يمكن الاستعلام عن الحزم المتاحة باستخدام:

```bash
curl http://localhost:20128/api/compression/language-packs
```

تقبل نقطة نهاية المعاينة تجاوزات إعدادات اللغة:

```bash
curl -X POST http://localhost:20128/api/compression/preview \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "standard",
    "text": "Por favor, eu gostaria que voce basicamente resumisse isso.",
    "config": {
      "languageConfig": {
        "defaultLanguage": "pt-BR",
        "autoDetect": true
      }
    }
  }'
```

## SHARED_BOUNDARIES (v3.8.0)

تلقت حزم اللغات الست جميعها عبارة `SHARED_BOUNDARIES` في v3.8.0، وتُطبَّق عند كل
مستوى كثافة لـ Caveman‏ (LITE وFULL وULTRA). وهي توجّه المحرك إلى الحفاظ على هذه الأنماط حرفيًا،
بغض النظر عن إزالة الحشو المحيط بها:

| نوع النمط                      | مثال                                   |
| ------------------------------ | -------------------------------------- |
| كتل الشيفرة المسيّجة           | ` ```python\n...\n``` `                |
| الشيفرة المضمنة                | `` `my_var` ``                         |
| عناوين URL                     | `https://example.com/path`             |
| مسارات الملفات (مطلقة + نسبية) | `/etc/hosts`, `./src/index.ts`         |
| ترويسات الأخطاء                | `Error:`, `TypeError:`, `SyntaxError:` |
| أسطر تتبع المكدس               | `  at functionName (file.ts:12:3)`     |

تُدرج هذه الأنماط في `DEFAULT_CAVEMAN_CONFIG.preservePatterns` (وكانت سابقًا `[]`). يوجد
الثابت في `open-sse/services/compression/types.ts`.

### سبب أهمية ذلك

من دون SHARED_BOUNDARIES، قد تزيل أوضاع Caveman الصارمة محتوى يبدو كنص نثري متكرر،
لكنه في الواقع مقتطف شيفرة أو مسار ملف أو مكدس أخطاء. تعمل SHARED_BOUNDARIES كشبكة أمان
مستقلة عن اللغة، وتُطبَّق قبل تشغيل قواعد الحشو.

### تخصيص preservePatterns

يمكن إضافة أنماط أخرى في وقت التشغيل عبر إعدادات الضغط:

````json
{
  "cavemanConfig": {
    "preservePatterns": [
      "```[\\s\\S]*?```",
      "`[^`]+`",
      "https?://\\S+",
      "(?:/|\\./)[^\\s]+",
      "\\b(?:Error|TypeError|SyntaxError|RangeError):",
      "\\s+at\\s+\\S+\\s+\\(\\S+:\\d+:\\d+\\)"
    ]
  }
}
````

توسّع الأنماط المخصصة الأنماط الافتراضية الستة (ولا تستبدلها).

## ملاحظات تشغيلية

- تظل القواعد الإنجليزية المضمنة هي الخيار الاحتياطي عند غياب حزمة لغة.
- تفشل حزم JSON المضمنة غير الصالحة في التحقق، كي لا تتدهور أصول الإصدار بصمت.
- حزم القواعد مخصصة للبيانات فقط، ويجب ألا تستورد شيفرة أو تشغّل منطقًا عشوائيًا.
- تسجّل طبقة تحليلات الضغط الوضع والمحرك المحددين، وليس النص الكامل للمطالبة.
