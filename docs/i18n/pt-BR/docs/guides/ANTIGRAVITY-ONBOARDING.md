## 1. Antigravity vs. Antigravity CLI (agy)

Ambos os provedores compartilham o **mesmo backend do Google** — cliente OAuth, atualização de token, endpoints e contas do Google idênticos. A diferença está nos modelos exibidos.

> Consulte o [anúncio da CLI do Antigravity](https://antigravity.google/blog/introducing-google-antigravity-cli) para ver a comparação oficial do Google.

| Aspecto                    | `antigravity` (IDE)                            | `agy` (CLI)                                                    |
| -------------------------- | ---------------------------------------------- | -------------------------------------------------------------- |
| **Produto do Google**      | Antigravity 2.0 / Antigravity IDE              | Antigravity CLI                                                |
| **Backend**                | Mesma API Google Cloud Code                    | Mesma API Google Cloud Code                                    |
| **OAuth / Token**          | Mesmo cliente, mesma atualização               | Mesmo cliente, mesma atualização                               |
| **Catálogo de modelos**    | Lista estática selecionada (fixa no OmniRoute) | Consultado em tempo real no Google via `:fetchAvailableModels` |
| **Modelos Claude**         | Sonnet 4.6, Opus 4.6 (4 variantes de cada)     | Sonnet 4.6, Opus 4.6 (4 variantes de cada)                     |
| **Nomenclatura do Gemini** | Rótulos simples (Low/Medium/High)              | IDs do upstream (extra-low/low/agent)                          |
| **Modelos extras**         | `gpt-oss-120b-medium`                          | Pode incluir modelos adicionais do Google                      |
| **Caso de uso padrão**     | Integração com IDE (VS Code, JetBrains)        | Acesso via CLI / API                                           |
| **Cota**                   | Compartilhada com agy (mesma conta do Google)  | Compartilhada com antigravity (mesma conta do Google)          |

**Modelos disponíveis (verificados por meio de experimento, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (vários níveis de raciocínio)
- Claude: Sonnet 4.6, Opus 4.6 (cada um com variantes default/low/medium/high)
- Outros: GPT-OSS 120B Medium
- **Claude Sonnet 5 NÃO está disponível** — somente as variantes 4.6 são compatíveis

**Por que o catálogo de modelos é diferente**: A CLI do Google é “otimizada para velocidade e baixo overhead” e “otimizada em conjunto com os modelos Gemini” (segundo o blog oficial do Google). O produto Web/IDE é “otimizado para abrangência”. A CLI usa `:fetchAvailableModels` para descobrir modelos dinamicamente, enquanto a IDE usa uma lista estática selecionada.

**Na prática**: Use o prefixo `agy/` para modelos Gemini (por exemplo, `agy/gemini-3.7-flash-high`). Use `antigravity/` para a lista estática selecionada. Ambos acessam o mesmo backend do Google, mas apresentam nomenclaturas de modelos diferentes. A cota é compartilhada — o uso de qualquer um dos provedores é contabilizado nos mesmos limites da conta do Google.

## 2. Google One AI Pro: Sistema de cotas

> Consulte [Documentação do Antigravity: Planos](https://antigravity.google/docs/plans) para obter detalhes oficiais sobre as cotas e [Alterações nos planos do Antigravity](https://antigravity.google/blog/changes-to-antigravity-plans) para conferir as últimas atualizações de preços.

O Google Antigravity usa uma **cota de duas camadas** baseada em "Trabalho Realizado" (peso computacional), e não na quantidade de mensagens.

### As duas camadas

| Camada                 | O que é                                  | Ciclo de renovação                                                                     |
| ---------------------- | ---------------------------------------- | -------------------------------------------------------------------------------------- |
| **Período de 5 horas** | Reserva imediata de "trabalho realizado" | É redefinida 5 horas após a primeira solicitação em uma sessão                         |
| **Base de 7 dias**     | Limite máximo semanal                    | Substitui a renovação de 5 horas se atingido; bloqueia até o próximo período de 7 dias |

**Como o "Trabalho Realizado" é calculado**: tarefas que exigem uso intensivo de agentes (por exemplo, "Refatore este repositório inteiro") consomem a cota muito mais rapidamente do que tarefas simples (por exemplo, "Corrija esta função"). Não há um painel em tempo real que mostre o consumo.

### Níveis dos planos

| Plano        | Preço       | Cota                                      | Limite semanal                                   |
| ------------ | ----------- | ----------------------------------------- | ------------------------------------------------ |
| Gratuito     | $0          | Cota significativa, renovada semanalmente | Sim                                              |
| AI Pro       | $19.99/mês  | Cota alta, renovação contínua de 5 horas  | Sim (substitui o período de 5 horas se atingido) |
| AI Ultra 5x  | $99.99/mês  | 5x a cota do Pro                          | Sem limite semanal                               |
| AI Ultra 20x | $199.99/mês | 20x a cota do Pro                         | Sem limite semanal                               |

### Modelos Gemini versus não Gemini

- **Modelos Gemini** (Flash + Pro): compartilham um único limite de uso, consumido de acordo com os preços da API. Se o Flash for 8x mais barato que o Pro, você receberá 8x mais tokens do Flash.
- **Modelos não Gemini** (Claude, GPT-OSS): têm limites de uso **separados**. Podem continuar disponíveis mesmo quando o Gemini estiver bloqueado.

### Créditos de IA (uso excedente)

> Consulte [Créditos de IA do Google One](https://support.google.com/googleone/answer/14534406) para saber como os créditos funcionam.

Quando a cota de base é esgotada:

- **Nunca**: aguarda a renovação da cota; exibe "Cota do modelo de base atingida"
- **Sempre**: usa automaticamente os créditos de IA; retorna à cota de base quando ela é renovada

Os créditos são comprados separadamente e deduzidos conforme os preços padrão da API.

### Detalhes importantes

- A cota é **compartilhada no nível da conta** — a mesma conta do Google no Antigravity IDE, CLI e OmniRoute compartilha uma única reserva de cota
- Cada conta do Google tem sua própria cota independente — várias contas = várias reservas de cota
- Usuários do AI Pro relataram **bloqueios de 7 dias** em vez de redefinições após 5 horas quando a base semanal é atingida (o Google confirmou que esse comportamento é intencional durante períodos de alta demanda)

**Quando a cota da sua conta é esgotada**: o OmniRoute tenta novamente de forma automática usando a próxima conta disponível na rota combinada. Nenhuma intervenção manual é necessária.

## 3. Como obter um projectId

Toda conexão antigravity/agy precisa de um `projectId` do Google Cloud Code. Sem ele, o endpoint `/v1internal:models` retorna 404.

### Método A: automático (recomendado)

O OmniRoute cuida disso automaticamente. Quando você adiciona uma nova conta do Google por meio do OAuth no Dashboard:

1. O OmniRoute renova o token
2. Chama `loadCodeAssist` para descobrir o projectId
3. Se nenhum projeto existir, chama `onboardUser` para criar um
4. Tenta executar `loadCodeAssist` novamente para obter o projectId recém-criado
5. Salva-o no banco de dados

**Isso funciona para a maioria das contas** — nenhuma etapa manual é necessária.

### Método B: manual por meio da CLI agy

Se a descoberta automática falhar (consulte a Seção 5 para saber quando isso acontece):

```bash
# Instale a CLI agy (caso ainda não esteja instalada)
npm install -g @anthropic-ai/agy

# Faça login com sua conta do Google
agy login

# Selecione a conta que precisa de integração
# Isso aciona o registro no Cloud Code e atribui um projectId
```

Após a execução bem-sucedida de `agy login`, renove o token no Dashboard do OmniRoute. O projectId será descoberto automaticamente.

### Como verificar

Verifique o banco de dados:

```bash
# Dentro do contêiner do OmniRoute
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Ou verifique os logs:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. URI de redirecionamento do OAuth

### O problema

O Google OAuth exige uma URI de redirecionamento válida. Por padrão, o OmniRoute usa `http://127.0.0.1:20128/callback` (loopback). Isso funciona para builds locais, mas **falha em implantações remotas** (por exemplo, um servidor acessado por meio de um IP da LAN).

O Google rejeita URIs de redirecionamento que:

- Usam endereços IP (deve ser um domínio terminado em `.com`, `.org` etc.)
- Não correspondem às URIs de redirecionamento registradas na configuração do cliente OAuth

### A solução

**Opção A: usar o fluxo OAuth integrado (padrão)**

- Funciona quando você acessa o OmniRoute por `localhost` ou `127.0.0.1`
- Nenhuma configuração é necessária

**Opção B: credenciais OAuth personalizadas**

- Defina `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` no seu ambiente
- Forneça suas próprias credenciais do Google OAuth:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Registre `https://your-domain.com/callback` como uma URI de redirecionamento autorizada no Google Cloud Console

**Opção C: usar a CLI agy para o login inicial**

- Execute `agy login` na máquina que acessará o OmniRoute
- O fluxo OAuth é concluído localmente e os tokens são armazenados
- Importe a conexão para o OmniRoute pelo Dashboard

### Limitações

- Credenciais OAuth personalizadas exigem um nome de domínio (o Google não aceita endereços IP como URIs de redirecionamento)
- Se você não tiver um domínio, use a Opção A ou C

## 5. Solução de problemas: quando a configuração automática falha

O OmniRoute realiza automaticamente a descoberta do projectId e o onboarding para a maioria das contas. Quando isso falha, a causa raiz geralmente é uma destas:

### A região da conta está bloqueada

**Sintoma**: `agy login` retorna "Falha na verificação de elegibilidade: sua conta atual não é elegível para o Antigravity porque ele não está disponível no momento em sua localização."

**Causa raiz**: as contas do Google têm um campo de backend chamado "Country Association", definido no momento do cadastro. A CLI agy e a API Cloud Code verificam esse campo rigorosamente — ao contrário do Gemini na web, que verifica apenas seu IP atual.

> Para verificar ou alterar a região associada à sua conta, acesse o [Formulário de associação de país do Google](https://policies.google.com/country-association-form).

**Por que o Gemini na web funciona, mas o agy não**:

- Gemini na web / Google One: verifica apenas o IP atual (o proxy funciona)
- CLI agy / API Cloud Code: lê o campo de backend Country Association (o proxy não ajuda)

**Correção**:

1. Acesse o [Formulário de associação de país do Google](https://policies.google.com/country-association-form) enquanto estiver usando um IP dos EUA
2. Envie uma solicitação de alteração de região (selecione "Moro em outro país")
3. Aguarde de 1 a 24 horas para o processamento pelo Google e a notificação por e-mail
4. Depois disso, `agy login` deverá funcionar

### A conta não tem um projeto do Cloud Code

**Sintoma**: os logs mostram `loadCodeAssist returned no project id` e `onboardUser failed (400)`.

**Causa raiz**: a conta nunca foi registrada no Google Cloud Code, e o onboarding automático falhou.

**Correção**: execute `agy login` manualmente para iniciar o registro no Cloud Code e, em seguida, atualize o token no Dashboard do OmniRoute.

### O token expirou ou foi revogado

**Sintoma**: erros 401 nos logs ou mensagens "O token expirou".

**Correção**: atualize o token em Dashboard → Providers → agy → clique no ícone de atualização. Se o próprio token de atualização tiver sido revogado, você precisará se autenticar novamente por meio do OAuth.

## Fluxograma de Decisão

```
A conta não está funcionando?
│
├─ Ela possui um projectId no banco de dados?
│  ├─ SIM → O problema está em outro lugar (token expirado, limite de requisições etc.)
│  └─ NÃO ↓
│
├─ A Associação de País da conta está definida como uma região restrita?
│  ├─ SIM → Altere a região no Formulário de Associação de País do Google
│  │         (https://policies.google.com/country-association-form)
│  │         Aguarde de 1 a 24 horas e tente novamente
│  └─ NÃO ↓
│
├─ A conta possui uma assinatura do Google One AI Pro?
│  ├─ NÃO → Primeiro, assine em one.google.com
│  └─ SIM ↓
│
├─ Tente a descoberta automática (atualize o token no Dashboard)
│  ├─ Funciona → Concluído
│  └─ Ainda falha ↓
│
└─ Manual: execute `agy login` na máquina
   ├─ Funciona → Atualize o token no Dashboard; o projectId será descoberto
   └─ Falha → Verifique a mensagem de erro; provavelmente é um problema de região ou assinatura
```
