**OmniCopilot** coloca todos os modelos disponibilizados pelo OmniRoute no seletor de modelos
_nativo_ do GitHub Copilot Chat. Sem uma segunda barra lateral, sem uma interface de chat separada —
o modo agente do Copilot, as chamadas de ferramentas, os servidores MCP e as instruções
personalizadas continuam funcionando, apenas executados no modelo que você escolher.

|                           |                                                                                                                                                 |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Instalar (VS Code)**    | [Marketplace → `diegosouzapw.omnicopilot`](https://marketplace.visualstudio.com/items?itemName=diegosouzapw.omnicopilot)                        |
| **Instalar (forks)**      | [Open VSX](https://open-vsx.org/extension/diegosouzapw/omnicopilot) — Cursor, Windsurf, VSCodium, Theia, code-server, Gitpod, Antigravity, Kiro |
| **Código-fonte / issues** | [github.com/diegosouzapw/OmniCopilot](https://github.com/diegosouzapw/OmniCopilot) (MIT)                                                        |
| **Requer**                | VS Code 1.104+                                                                                                                                  |

> **Não é necessária uma assinatura do Copilot.** Desde o VS Code 1.122, um provedor de modelos
> de linguagem funciona sem login no GitHub e sem qualquer plano do Copilot. Os preenchimentos
> inline e os recursos baseados em embeddings permanecem fora da API do provedor e ainda exigem
> o Copilot.

## Configuração

1. **Execute o OmniRoute** — `npm install -g omniroute && omniroute` (painel em `http://localhost:20128`).
2. **Instale a extensão** — pesquise por "OmniRoute" na visualização Extensions.
3. **Escolha um modelo** — Copilot Chat → seletor de modelos → **Manage Models…** → **OmniRoute** e, em seguida, marque
   os modelos desejados.

Não é necessário configurar nada quando o OmniRoute é executado na porta padrão. Para uma instância remota, abra o
**ícone do OmniRoute na Activity Bar** (ou execute `OmniRoute: Manage Connection`) e defina:

- **URL do servidor** — a raiz do servidor, por exemplo, `http://192.168.0.15:20128`. O sufixo `/v1` é
  adicionado pela extensão; não o inclua.
- **Chave de API** — somente quando o servidor define `REQUIRE_API_KEY`. Armazenada no chaveiro do sistema operacional por meio do
  SecretStorage do VS Code, nunca em `settings.json`.

## O que o seletor exibirá

A extensão não exibe a resposta bruta de `GET /v1/models` — ela a formata, e a quantidade que você
vê é menor que o tamanho do catálogo por dois motivos intencionais.

### Ela solicita um id por modelo

`MODELS_CATALOG_PREFIX_MODE` usa **`dual`** como padrão, o que anuncia cada modelo duas vezes — uma
com o prefixo curto do alias e outra com o prefixo canônico do provedor — para que configurações de
clientes mais antigos continuem resolvendo ambas as formas:

```
cc/claude-sonnet-4-6        ← prefixo do alias
claude/claude-sonnet-4-6    ← prefixo canônico, mesmo modelo
```

A extensão solicita **`GET /v1/models?prefix=alias`** para que seja retornado um id por modelo, sem
alterar a configuração global do servidor para seus outros clientes. Em uma instância de referência,
isso reduziu **2345 entradas para 1396 — 949 duplicatas, nenhum modelo perdido.**

Se você preferir corrigir isso no servidor para _todos_ os clientes, defina a feature flag
`MODELS_CATALOG_PREFIX_MODE` como `alias` no painel. Consulte
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) para ver o
parâmetro de consulta e a tabela de cada modo.

### Ela oculta modelos que não podem ser usados em chats

O catálogo também lista modelos de imagem, vídeo, áudio, rerank, embedding e moderação. Eles
seriam rejeitados de qualquer forma em uma solicitação de chat:

```
HTTP 400 — O modelo '<id>' é um modelo de geração de imagens e não pode ser usado em
/v1/chat/completions. Em vez disso, use POST /v1/images/generations.
```

por isso, eles são filtrados pelo campo `type` antes de chegarem ao seletor. **Os modelos da
Responses API são mantidos** — cada entrada Codex / GPT-5.x anuncia `supported_endpoints: ["responses"]`,
e o OmniRoute faz a tradução para `/v1/chat/completions`, portanto eles podem ser usados normalmente.

### Provedores que você nunca configurou

O catálogo lista modelos de provedores com uma **conexão ativa**, além de todos os provedores
**noAuth** — aqueles que não exigem chave e que compõem grande parte do nível gratuito. Isso é
intencional. Para ocultá-los, adicione-os a `blockedProviders` nas configurações do painel; nada
muda na extensão.

## Dashboard em uma aba do VS Code

`omnicopilot.dashboardOpen: "editor"` renderiza o dashboard do OmniRoute em uma aba do editor por meio do
Simple Browser, em vez de em um navegador externo. A incorporação é **habilitada explicitamente no servidor** por meio de
`DASHBOARD_ALLOW_EMBED=vscode`, que fornece as páginas HTML com
`frame-ancestors 'self' vscode-webview:` em vez do padrão `frame-ancestors 'none'` +
`X-Frame-Options: DENY`. A superfície da API (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) mantém os
cabeçalhos restritivos em ambos os casos.

> ⚠️ **Essa é uma opção de tempo de build, não de runtime.** O Next.js compila `headers()` no manifesto de
> rotas, portanto, `next.config.mjs` lê a variável enquanto o bundle é criado
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> Exportá-la antes de iniciar um servidor já compilado não altera nada — os cabeçalhos ficam incorporados.

```bash
# a variável precisa estar presente no comando de BUILD
DASHBOARD_ALLOW_EMBED=vscode npm run build        # ou npm run build:release
npm start
```

| Como você instalou         | É possível habilitar a incorporação?                                                                                                            |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| A partir do código-fonte   | ✅ defina a variável no comando de build, como mostrado acima                                                                                   |
| `npm install -g omniroute` | ❌ o pacote publicado inclui um bundle pré-compilado — em vez disso, faça o build a partir do código-fonte                                      |
| Imagem Docker              | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — a imagem pré-compilada no Docker Hub não permite incorporação |

Sem um build com incorporação habilitada, a página recusa ser exibida em um frame; a extensão detecta isso pelos
cabeçalhos da resposta e recorre ao navegador externo — nada para de funcionar, e ela informa isso uma vez.
Consulte [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) e a issue
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273).

## Configurando suas outras ferramentas pelo VS Code

**`OmniRoute: Configure Coding CLI`** usa a CLI `omniroute` para gravar perfis prontos para uso
para Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code,
Kilo e Roo — as mesmas configurações descritas em
[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md). A chave de API é fornecida à CLI por meio da variável de ambiente
`OMNIROUTE_API_KEY`, nunca pela linha de comando.

## Solução de problemas

| Sintoma                                                          | Causa / correção                                                                                                                                                                                                                                                                                                                  |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Nenhum modelo do OmniRoute no seletor                            | O servidor está inacessível. O ponto da barra de status fica cinza; execute `OmniRoute: Check Connection`. A descoberta é silenciosa por design e não fornece nenhum modelo, em vez de exibir uma solicitação.                                                                                                                    |
| Todos os modelos aparecem duas vezes                             | Você está usando uma versão do OmniCopilot anterior à 1.0.1 — atualize. Agora, a extensão solicita `?prefix=alias`.                                                                                                                                                                                                               |
| Um modelo de imagem/áudio que aparecia não está mais listado     | Intencional desde a versão 1.0.1 — ele nunca poderia responder a uma solicitação de chat.                                                                                                                                                                                                                                         |
| Painel ausente na Barra de Atividades                            | O VS Code move os contêineres de visualização adicionais para o menu excedente **"…"** na parte inferior da Barra de Atividades, e um contêiner ocultado pelo clique com o botão direito permanece oculto. Clique com o botão direito na Barra de Atividades → marque **OmniRoute** ou abra-o com `OmniRoute: Manage Connection`. |
| O dashboard abre no navegador apesar do modo `editor`            | O servidor não foi **compilado** com `DASHBOARD_ALLOW_EMBED=vscode` (veja acima) — defini-la na inicialização de uma instalação pré-compilada não altera nada. O fallback é intencional.                                                                                                                                          |
| A lista de modelos está desatualizada após alterar os provedores | Execute `OmniRoute: Refresh Models` ou use o link ↻ no painel.                                                                                                                                                                                                                                                                    |
