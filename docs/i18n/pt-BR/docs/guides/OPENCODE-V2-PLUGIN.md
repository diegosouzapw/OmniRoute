`@omniroute/opencode-plugin-v2` disponibiliza todo o seu catálogo do OmniRoute — modelos, combos e
auto-combos — no seletor de modelos do OpenCode v2, com nomes de exibição, preços e limites
do nível gratuito.

Ele é um pacote separado de `@omniroute/opencode-plugin` porque o OpenCode v1 e o v2 carregam
plugins por meio de contratos diferentes. Escolha aquele que corresponde à versão principal do seu OpenCode; nada é
compartilhado entre eles, portanto atualizar um nunca força a atualização do outro.

## Requisitos

- OpenCode v2.
- Um gateway OmniRoute acessível (`http://localhost:20128` por padrão).
- Node.js 22 ou 24.

## Instalação

Adicione o plugin ao `opencode.json`:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

Os modelos aparecerão como `omniroute/<provider>/<model>`; `providerId` define esse prefixo e
o id da integração sob a qual o OpenCode armazena a credencial.

## Credenciais

O plugin procura uma chave do gateway em três locais, nesta ordem:

1. **A credencial que você conectou no OpenCode.** O plugin registra uma integração, portanto
   o próprio fluxo de autenticação do OpenCode pode armazenar a chave. Nada é gravado no `opencode.json` — prefira esta opção.
2. `apiKey` nas opções do plugin, para uma substituição específica por projeto. Isso coloca a chave em um arquivo que
   você pode estar enviando ao repositório.
3. `OMNIROUTE_API_KEY` no ambiente.

Sem nenhuma das três, o catálogo fica vazio, e o plugin informa isso uma vez na inicialização, em vez de
deixar você com um seletor vazio sem qualquer aviso.

### O token de gerenciamento é uma chave diferente

Combos, integridade dos provedores e enriquecimento (nomes de exibição, preços e limites do nível gratuito) vêm
dos endpoints `/api/*` do gateway, que na maioria das implantações são protegidos por um token de
**gerenciamento**, em vez da chave de inferência:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<token de leitura de gerenciamento>"
}
```

Quando não definido, `managementReadToken` usa `apiKey` como alternativa. Quando um gateway rejeita essa alternativa,
o catálogo ainda é publicado, mas com ids de modelo brutos em vez de nomes de exibição, sem
desduplicação de aliases canônicos, sem preços e sem combos. O plugin emite um aviso uma vez por endpoint quando isso acontece,
indicando o endpoint e o que foi perdido — assim, um seletor degradado nunca é um mistério.

## Opções

| Chave                            | Padrão                                           | Observações                                                                                                                                         |
| -------------------------------- | ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `providerId`                     | `"omniroute"`                                    | Id do provedor, id da integração e o prefixo sob o qual os modelos aparecem                                                                         |
| `baseURL`                        | obrigatório                                      | Raiz do gateway, somente `http(s)`; o sufixo `/v1` é adicionado quando necessário                                                                   |
| `apiKey`                         | credencial conectada, depois `OMNIROUTE_API_KEY` | Chave de chat para `/v1/*`                                                                                                                          |
| `managementReadToken`            | usa `apiKey` como alternativa                    | Chave para `/api/*` — geralmente **não** é a mesma                                                                                                  |
| `displayName`                    | `"OmniRoute"`                                    | Nome do provedor no seletor                                                                                                                         |
| `timeoutMs`                      | `10000`                                          | Tempo limite de busca por endpoint (auto-combos usam 5s)                                                                                            |
| `modelCacheTtlMs`                | `300000`                                         | TTL do cache do catálogo; um snapshot em disco agiliza inicializações a frio                                                                        |
| `timeouts`                       | usa `timeoutMs` como alternativa                 | Limites por endpoint em ms: `models`, `combos`, `autoCombos`, `enrichment`                                                                          |
| `enrichment`                     | `true`                                           | Busca nomes, preços e limites do nível gratuito                                                                                                     |
| `providerTag`                    | `true`                                           | Adiciona ao nome de exibição o prefixo do provedor upstream para o qual ele roteia                                                                  |
| `usableOnly`                     | `false`                                          | Mantém apenas os provedores que o gateway informa como provisionados                                                                                |
| `visibleModels` / `hiddenModels` | `[]`                                             | Listas de permissão por correspondência exata ou de sufixo; a negação prevalece                                                                     |
| `geminiSanitization`             | `true`                                           | Remove dos esquemas de ferramentas as palavras-chave de JSON Schema rejeitadas pelo Gemini (ferramentas com `$ref` são encaminhadas sem alterações) |
| `apiFormat.allowAnthropic`       | `false`                                          | Encaminha ids incluídos na lista de permissão pelo bloco da API da Anthropic                                                                        |
| `apiFormat.anthropicModels`      | `[]`                                             | IDs completos de modelos encaminhados para a Anthropic                                                                                              |
| `logLevel` / `startupDebug`      | `warn` / `false`                                 | Nível de detalhamento do logger                                                                                                                     |

## Como o catálogo se mantém atualizado

O catálogo é buscado sob demanda e armazenado em cache por `modelCacheTtlMs`, e um snapshot em disco mantém o
último catálogo conhecido disponível quando o gateway está inacessível — uma indisponibilidade não custa nada além de
atualização. Modelos e combos são publicados assim que chegam; combos automáticos, a lista de provedores
e a camada de enriquecimento são incorporados quando ficam disponíveis, portanto um endpoint lento não consegue manter
todo o seletor bloqueado.

Os nomes incluem o que o gateway conhece: o provedor upstream para o qual um modelo é roteado, um marcador `[Free]`
e o orçamento que o acompanha — assim, duas conexões que oferecem o mesmo modelo continuam
distinguíveis. Desative o prefixo com `"providerTag": false`.

Não há comando de atualização manual: os comandos do OpenCode v2 são templates de prompt, não callbacks,
portanto um plugin não pode disponibilizar um. As atualizações seguem o TTL; o host só é solicitado a recarregar quando
o catálogo ou a camada realmente mudam, nunca uma vez por atualização.

## Chamada de ferramentas no Gemini

O Gemini rejeita uma solicitação inteira quando suas declarações de ferramentas contêm `$schema` ou
`additionalProperties`, respondendo com `400 INVALID_ARGUMENT`. O plugin remove essas palavras-chave dos
schemas de ferramentas destinados a um modelo Gemini deste provedor e mantém todas as outras solicitações inalteradas.
Uma ferramenta que contém um `$ref` é encaminhada sem alterações, em vez de ter palavras-chave removidas, pois remover a
referência ampliaria o schema para "aceitar qualquer coisa".
Defina `"geminiSanitization": false` para desativar esse comportamento.

## Solução de problemas

| Sintoma                                      | Causa                                                                                                                |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| O seletor não mostra nenhum modelo OmniRoute | Nenhuma chave foi resolvida (verifique o aviso de inicialização), ou o gateway está inacessível                      |
| IDs de modelo brutos, sem combos nem preços  | Os endpoints de gerenciamento recusaram o token — defina `managementReadToken`                                       |
| Uma sessão fixada em `opencode-<id>/…`       | O plugin v1 publicava `opencode-<id>`; a v2 publica apenas `<id>`, portanto selecione novamente o modelo em `<id>/…` |
