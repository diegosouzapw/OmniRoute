> **Fonte da verdade:** `src/lib/obsidian/api.ts` (cliente REST + sincronização),
> `src/lib/db/obsidian.ts` (persistência de token / URL base / WebDAV),
> `src/lib/obsidianSync.ts` (sincronização do cofre via WebDAV), `open-sse/mcp-server/tools/obsidianTools.ts`
> (22 ferramentas MCP), `src/app/api/settings/obsidian/route.ts` +
> `src/app/api/settings/obsidian/webdav/route.ts` (APIs de configurações). O registro
> de ferramentas e a configuração de escopos ficam em `open-sse/mcp-server/server.ts`.

## O que é

O OmniRoute conecta-se a um cofre do **Obsidian** como uma **fonte de contexto** — uma
base de conhecimento local em Markdown que os agentes leem e gravam por meio do servidor
MCP integrado. A integração se comunica com o plugin da comunidade **Obsidian Local REST API**
em execução dentro do aplicativo para desktop, permitindo que os agentes pesquisem notas,
leiam/gravem/apliquem patches em arquivos, listem o cofre, trabalhem com notas periódicas
diárias/semanais, gerenciem tags, executem comandos do Obsidian e (opcionalmente) coordenem
uma sincronização bidirecional do cofre entre desktop↔dispositivo móvel.

O cliente (`src/lib/obsidian/api.ts`) encapsula a Local REST API com:

- **Novas tentativas com backoff** para erros `5xx` transitórios e **timeout de 30 segundos** via `AbortController`.
- **Classificação tipada de erros** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- Uma **dica amigável de "não foi possível acessar o Obsidian"** que destaca o erro comum
  de porta (HTTP em `27123`, **não** o endpoint MCP em `27124`) e o formato do Tailscale.
- **Codificação de caminhos** relativos ao cofre, garantindo a segurança de caminhos de notas com espaços/barras.

## Configuração

Não há **nenhuma variável de ambiente** para o token ou a URL base do Obsidian — ambos são
armazenados na tabela `key_value` do SQLite (namespace `obsidian`) por meio de
`src/lib/db/obsidian.ts`. O token é **criptografado em repouso** (AES-256-GCM, com
fallback de compatibilidade retroativa para texto simples). Configure pela aba **Fontes de contexto**
do painel do Endpoint (`ObsidianSourceCard`) ou pela API REST de configurações.

> [!IMPORTANT]
> O plugin **Obsidian Local REST API** deve estar instalado e em execução. Sua interface
> REST escuta em **HTTP `127.0.0.1:27123`** (a URL base padrão). A porta `27124`
> é um endpoint MCP/HTTPS _separado_ e é rejeitada explicitamente pela rota de configurações.
> Ao se conectar de outro dispositivo, use `http://<tailscale-ip>:27123`.

### Chaves de configuração (SQLite `key_value`, namespace `obsidian`)

| Chave             | Finalidade                                                  | Criptografada |
| ----------------- | ----------------------------------------------------------- | ------------- |
| `api_key`         | Token bearer da Local REST API                              | sim           |
| `base_url`        | URL base REST (padrão `http://127.0.0.1:27123`)             | não           |
| `vault_path`      | Caminho absoluto do diretório do cofre (para sincronização) | não           |
| `webdav_username` | Nome de usuário WebDAV gerado (sincronização do cofre)      | não           |
| `webdav_password` | Senha WebDAV gerada (sincronização do cofre)                | sim           |
| `webdav_enabled`  | Se a sincronização do cofre via WebDAV está habilitada      | não           |

### Configurar via REST

```bash
# Salva e valida o token da Local REST API (POST valida por meio de uma verificação de status)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Verifica o status da conexão (retorna connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# Desconecta (remove o token armazenado)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Todos os métodos exigem autenticação no painel. `POST` rejeita qualquer URL na porta `27124`
e valida o token chamando o endpoint de status da Local REST API antes de persistir os dados.

### Sincronização do cofre via WebDAV

`src/app/api/settings/obsidian/webdav/route.ts` gerencia uma sincronização opcional
do cofre baseada em WebDAV (controlada por `src/lib/obsidianSync.ts`). Ao habilitá-la,
o OmniRoute é direcionado a um diretório de cofre local e gera um par aleatório de
nome de usuário/senha WebDAV:

```bash
# Habilita a sincronização via WebDAV para um diretório de cofre (gera nome de usuário/senha)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# Obtém o status da sincronização via WebDAV (as credenciais são retornadas somente enquanto estiver habilitada)
curl http://localhost:20128/api/settings/obsidian/webdav

# Desabilita a sincronização via WebDAV (remove as credenciais + o .stignore gerenciado)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Fonte de contexto por chave de API (opcional)

A configuração do Obsidian pode ter um escopo **por chave de API** por meio da tabela
`api_key_context_sources` (`src/lib/db/apiKeyContextSources.ts`). Quando uma chamada MCP
inclui um id de chave de API autenticado, `getObsidianConfigForApiKey()` dá preferência
ao token/URL base/caminho do cofre da própria chave (`source: "api_key"`) e, caso contrário,
faz fallback para a configuração global (`source: "global"`).

## Ferramentas MCP (22)

Definidas em `open-sse/mcp-server/tools/obsidianTools.ts`. O token e a URL base são resolvidos
a cada chamada (primeiro por chave de API, depois globalmente). As ferramentas que acessam o **servidor de sincronização**
do OmniRoute (as quatro ferramentas `obsidian_sync_*`) também exigem o token de autenticação de sincronização configurado
nas configurações do OmniRoute.

### Ferramentas de leitura (`read:obsidian`)

| Ferramenta                   | Descrição                                                                                                                       |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Verifica se a API REST local está acessível e autenticada.                                                                      |
| `obsidian_search_simple`     | Pesquisa de texto completo no conteúdo das notas; retorna trechos com caminhos de arquivos.                                     |
| `obsidian_search_structured` | Pesquisa usando uma expressão JSON Logic (filtros and/or/regex/path).                                                           |
| `obsidian_read_note`         | Lê uma nota pelo caminho relativo ao vault; opcionalmente, um título/bloco/frontmatter específico.                              |
| `obsidian_list_vault`        | Lista arquivos e diretórios no vault (árvore de entradas).                                                                      |
| `obsidian_get_document_map`  | Obtém a estrutura de títulos da nota como um mapa de títulos → números de linha.                                                |
| `obsidian_get_note_metadata` | Obtém frontmatter, tags, links e contagem de caracteres/palavras sem o conteúdo completo.                                       |
| `obsidian_get_active_file`   | Obtém o caminho e o conteúdo do arquivo atualmente ativo no Obsidian.                                                           |
| `obsidian_get_periodic_note` | Obtém a nota periódica diária/semanal/mensal para uma data (hoje, se omitida).                                                  |
| `obsidian_get_tags`          | Lista todas as tags do vault com suas frequências.                                                                              |
| `obsidian_list_commands`     | Lista os IDs de comandos disponíveis do Obsidian (use com `obsidian_execute_command`).                                          |
| `obsidian_sync_status`       | Status do servidor de sincronização do OmniRoute: em execução, nome do vault, porta, tempo de atividade e última sincronização. |
| `obsidian_sync_conflicts`    | Lista conflitos de sincronização não resolvidos (caminho, caminho do conflito e momento da detecção).                           |

### Ferramentas de escrita (`write:obsidian`)

| Ferramenta                       | Descrição                                                                                                    |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `obsidian_write_note`            | Cria ou sobrescreve uma nota com o conteúdo Markdown fornecido.                                              |
| `obsidian_append_note`           | Acrescenta conteúdo a uma nota; opcionalmente, a um título/bloco específico.                                 |
| `obsidian_patch_note`            | Acrescenta, insere no início ou substitui de forma precisa em um título, bloco ou campo de frontmatter.      |
| `obsidian_delete_note`           | Exclui permanentemente uma nota do vault.                                                                    |
| `obsidian_move_note`             | Move ou renomeia uma nota dentro do vault.                                                                   |
| `obsidian_execute_command`       | Executa um comando do Obsidian pelo respectivo ID.                                                           |
| `obsidian_open_file`             | Abre um arquivo no Obsidian (cria-o caso ele não exista).                                                    |
| `obsidian_sync_trigger`          | Aciona uma sincronização bidirecional imediata do vault entre desktop e dispositivo móvel.                   |
| `obsidian_sync_resolve_conflict` | Resolve um conflito de sincronização: mantém `local` (dispositivo móvel), `remote` (desktop) ou `keep-both`. |

> [!NOTE]
> Os destinos de `obsidian_patch_note` aceitam `targetType` como `heading | block | frontmatter`
> e `operation` como `append | prepend | replace`, com um
> `createTargetIfMissing` opcional. As quatro ferramentas `obsidian_sync_*` se comunicam com o servidor de sincronização
> local (`http://127.0.0.1:27781` por padrão) e exigem o token de sincronização.

### Escopos

As ferramentas de leitura exigem `read:obsidian`; as ferramentas de escrita exigem `write:obsidian`. A aplicação
é idêntica à do Notion — tratada por `withScopeEnforcement()` em
`open-sse/mcp-server/server.ts`, condicionada a `OMNIROUTE_MCP_ENFORCE_SCOPES=true`, com
os escopos permitidos obtidos de `OMNIROUTE_MCP_SCOPES` ou do contexto de escopos da chave de API. Consulte
[MCP-SERVER.md](./MCP-SERVER.md).

## Endpoints

| Método   | Caminho                         | Finalidade                                                   |
| -------- | ------------------------------- | ------------------------------------------------------------ |
| `GET`    | `/api/settings/obsidian`        | Retorna `{ connected, hasToken, baseUrl, vaultPath }`.       |
| `POST`   | `/api/settings/obsidian`        | Salva e valida o token (rejeita a porta `27124`).            |
| `DELETE` | `/api/settings/obsidian`        | Desconecta (limpa o token armazenado).                       |
| `GET`    | `/api/settings/obsidian/webdav` | Status da sincronização WebDAV + credenciais (quando ativa). |
| `POST`   | `/api/settings/obsidian/webdav` | Ativa a sincronização WebDAV para um diretório do cofre.     |
| `DELETE` | `/api/settings/obsidian/webdav` | Desativa a sincronização WebDAV.                             |

> Estas são rotas de configurações do painel. O próprio cofre é acessado pela API REST
> local do Obsidian (a `base_url` configurada) e pelas ferramentas MCP acima — não há
> nenhum endpoint de proxy público `/v1` do Obsidian.

## Casos de uso

- **Respostas fundamentadas no cofre** — `obsidian_search_simple` / `obsidian_search_structured`
  e depois `obsidian_read_note`, para que um agente responda com base em suas anotações reais.
- **Criação de notas / diário** — `obsidian_write_note`, `obsidian_append_note` ou
  o preciso `obsidian_patch_note` para registrar no cofre a saída do agente, resumos ou notas diárias
  (`obsidian_get_periodic_note`).
- **Navegação pelo cofre** — `obsidian_list_vault`, `obsidian_get_document_map` e
  `obsidian_get_tags` para explorar a estrutura antes de ler/gravar.
- **Automação do Obsidian** — `obsidian_list_commands` + `obsidian_execute_command` para
  controlar plugins/comandos por meio de um agente; `obsidian_open_file` para exibir uma nota na interface.
- **Sincronização móvel** — ative a sincronização WebDAV e, em seguida, use `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  para coordenar a sincronização entre desktop e dispositivo móvel e resolver conflitos.
