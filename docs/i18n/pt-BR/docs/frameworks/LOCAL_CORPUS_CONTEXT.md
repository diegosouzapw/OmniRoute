> `src/lib/localCorpus/configured.ts` (runtime configurado),
> `src/lib/db/localCorpus.ts` (persistência do caminho raiz),

> `src/app/api/settings/local-corpus/route.ts` (API de configurações).

## O que é

O Local Corpus permite que um operador disponibilize um diretório explicitamente aprovado de arquivos de texto para o servidor MCP do OmniRoute. Os arquivos permanecem no diretório original: o OmniRoute armazena apenas o caminho raiz canônico no SQLite e mantém um índice de pesquisa em memória. Ele não copia o conteúdo do corpus para o repositório nem para o banco de dados.

A atualização do índice é incremental. Arquivos inalterados são reutilizados com base no tamanho e na data de modificação, arquivos alterados são relidos e recebem um hash SHA-256, e arquivos excluídos são removidos. A pesquisa atualiza um índice com mais de 30 segundos; os chamadores também podem solicitar uma atualização imediata.

## Configurar a origem

A rota de configurações exige a mesma autenticação de gerenciamento que as outras APIs de configurações. O caminho enviado já deve existir e deve ser um caminho absoluto de diretório.

```bash
# Conectar um diretório aprovado
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# Verificar a configuração e o status do índice
curl http://localhost:20128/api/settings/local-corpus

# Desconectar sem alterar os arquivos de origem
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## Ferramentas MCP

Todas as três ferramentas exigem `read:local-corpus`. As respostas das ferramentas expõem caminhos relativos e o nome-base do diretório raiz, nunca o caminho absoluto.

| Ferramenta            | Descrição                                                                                        |
| :-------------------- | :----------------------------------------------------------------------------------------------- |
| `local_corpus_status` | Informa o estado da configuração, o tamanho do índice, os limites e a hora da última atualização |
| `local_corpus_search` | Pesquisa o texto indexado e retorna trechos limitados e restritos por linha (até 20 resultados)  |
| `local_corpus_read`   | Lê um intervalo limitado de linhas de um arquivo permitido relativo ao corpus                    |

Exemplos de entradas MCP:

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## Limites de segurança

- A lista de permissões é voltada para texto: `.cfg`, `.csv`, `.geojson`, `.htm`, `.html`, `.ini`,
  `.js`, `.json`, `.jsonl`, `.jsx`, `.log`, `.md`, `.mjs`, `.ps1`, `.py`, `.sh`,
  `.sql`, `.toml`, `.ts`, `.tsx`, `.txt`, `.xml`, `.yaml` e `.yml`.
- Links simbólicos são ignorados. Os caminhos de leitura são canonicalizados e devem permanecer dentro da
  raiz configurada; caminhos absolutos e tentativas de travessia são rejeitados.
- Nomes de diretórios sensíveis e gerados são excluídos: `.build`, `.codex`, `.env`,
  `.git`, `.next`, `.omniroute`, `.ssh`, `coverage`, `dist`, `node_modules` e
  `secrets`.
- Os limites padrão são 5.000 arquivos, 1 MiB por arquivo, 64 MiB de conteúdo total indexado,
  aproximadamente 4.000 caracteres por trecho de pesquisa e 400 linhas por leitura.
- Arquivos que contêm NUL são tratados como não textuais e ignorados ou rejeitados.

Documentos binários, como PDF, DOCX, imagens e arquivos compactados, não são intencionalmente compatíveis. Converta-os para um formato de texto aprovado no diretório configurado antes da indexação.

## Observações operacionais

- Alterar ou excluir a raiz configurada limpa o índice compartilhado em memória.
- A reinicialização do processo descarta o índice; a próxima pesquisa o recria a partir da origem
  configurada.
- `local_corpus_status` não força uma varredura. Use `local_corpus_search` com
  `refresh: true` quando uma nova varredura imediata for necessária.
- Falhas de varredura e leitura são contabilizadas ou retornadas como erros sanitizados; os arquivos de origem
  nunca são modificados.
