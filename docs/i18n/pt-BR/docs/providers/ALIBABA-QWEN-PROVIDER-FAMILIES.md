Este documento registra a decisão de implementação para a
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854). Os produtos públicos são
representados como quatro famílias de provedores. A região é um dado de conexão, não um produto separado.

## Decisão

| Família de provedores                          | ID do OmniRoute         | Região global | Região da China |
| ---------------------------------------------- | ----------------------- | ------------- | --------------- |
| Alibaba Cloud Model Studio (pagamento por uso) | `alibaba`               | Singapura     | Pequim          |
| Alibaba Cloud Token Plan                       | `bailian-coding-plan`   | Singapura     | Pequim          |
| Qwen Cloud (pagamento por uso)                 | `qwen-cloud`            | Global        | Pequim          |
| Qwen Cloud Token Plan                          | `qwen-cloud-token-plan` | Singapura     | Pequim          |

O ID existente `alibaba-cn` permanece como um alias de compatibilidade em tempo de execução para conexões
salvas, rotas de modelos, combinações e uso histórico. Seu cartão no painel é incorporado ao `alibaba`;
nenhuma reescrita do banco de dados é necessária.

O Qwen Cloud com pagamento por uso e o Alibaba Cloud Model Studio atualmente compartilham os hosts de
tempo de execução compatíveis com o DashScope, mas permanecem como identidades de provedor separadas porque
os usuários obtêm chaves e gerenciam contas por meio de interfaces de produto diferentes. Os produtos
Alibaba e Qwen Cloud Token Plan usam famílias de endpoints diferentes, portanto, os quatro produtos
permanecem como IDs de provedor separados.

## Matriz de endpoints

| Família de provedores   | `global-sg`                                                              | `china-beijing`                                                      | Formato de transmissão |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ---------------------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI                 |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic              |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI                 |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI                 |

A chave de API e o endpoint devem pertencer ao mesmo produto e à mesma região. Selecionar uma região altera
o endpoint predefinido usado pela validação e pelas solicitações normais.

## Contrato de conexão

As novas conexões armazenam a chave de região estável em `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

Os valores permitidos são `global-sg` e `china-beijing`. O endpoint é derivado centralmente do
ID do provedor e da região. Um `providerSpecificData.baseUrl` não predefinido permanece como uma
substituição explícita definida pelo operador e tem precedência, enquanto URLs predefinidas salvas
anteriormente são normalizadas de volta para a matriz regional.

Isso mantém o esquema de conexão extensível: outra região pode ser adicionada ao resolvedor sem
criar outro cartão de provedor nem alterar os IDs de provedor salvos.

## Compatibilidade e implantação

1. Adicione o resolvedor de endpoint regional e mantenha os padrões globais atuais.
2. Use a descoberta dinâmica regional do `/models` do DashScope para `alibaba`, seu ID de compatibilidade
   `alibaba-cn` e `qwen-cloud`. As respostas passam primeiro por um filtro de geração de texto porque o
   endpoint genérico também retorna modelos de imagem, vídeo, áudio, embedding e outros modelos que não são de chat. Em seguida, `qwen-cloud`
   aplica a lista de permissões mantida e declarada em seu registro de provedor. O Alibaba Model Studio
   e o Qwen Cloud mantêm catálogos selecionados separados, embora atualmente compartilhem hosts de runtime.
3. Registre `qwen-cloud-token-plan` com a lista de permissões atual de modelos de texto do Token Plan.
4. Adicione um seletor de região tipado às caixas de diálogo para adicionar/editar conexões.
5. Oculte o cartão duplicado `alibaba-cn` e inclua suas conexões existentes na página do provedor
   `alibaba`.
6. Mantenha disponíveis as substituições personalizadas de endpoint para implantações avançadas e específicas de workspace.

Os modelos de mídia do Token Plan permanecem fora do catálogo de chat porque usam endpoints dedicados.
`wan2.7-image` e `wan2.7-image-pro` estão registrados em `open-sse/config/imageRegistry.ts`;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` e `happyhorse-1.1-r2v` estão registrados em
`open-sse/config/videoRegistry.ts`. Ambos os registros reutilizam a identidade de conexão
`qwen-cloud-token-plan` e suas credenciais específicas da região.

O Qwen Cloud regular possui catálogos separados de imagem e vídeo com pagamento conforme o uso sob a identidade
`qwen-cloud`. Seus modelos de imagem são `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` e `z-image-turbo`. Seus modelos de vídeo
são `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` e
`wan2.7-videoedit`. Esses modelos reutilizam apenas a conexão regular `qwen-cloud` e o endpoint regional
de mídia do DashScope. Os registros do Token Plan e de pagamento conforme o uso não herdam nem mesclam
as listas de modelos um do outro.

A identidade `bailian-coding-plan` também possui suas próprias listas de permissões de mídia:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` e `qwen-image-2.0-pro` para geração
de imagens, além de
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` e `happyhorse-1.1-r2v` para geração
de vídeos. Ela usa apenas a conexão do Bailian Coding Plan e o endpoint regional do Coding Plan.
Seus registros de imagem e vídeo não herdam nem são mesclados com nenhum dos provedores do Qwen Cloud.

A identidade regular `alibaba` possui listas de permissões separadas para imagem e vídeo. Seus modelos de imagem são
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` e `wan2.6-t2i`. Seus modelos de vídeo adicionados são `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` e `wan2.7-videoedit`. Esses modelos usam apenas a conexão do Alibaba Model Studio
e o endpoint regional de mídia selecionado; eles não são adicionados a nenhum registro do Coding Plan ou do Qwen
Cloud.

O catálogo de chat do Qwen Cloud Token Plan segue a lista de permissões de texto por correspondência exata de strings do plano Individual:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` e
`deepseek-v4-pro`. As entradas Wan e HappyHorse pertencem às APIs separadas de geração de imagem/vídeo.

O Alibaba Token Plan expõe os mesmos seis IDs atuais de modelos de geração de texto por meio de seu
endpoint compatível com a Anthropic. Sua opção de Singapura armazena a chave de região existente `global-sg`;
apenas o rótulo exibido ao usuário difere das famílias de provedores que chamam a região de Global.

O catálogo regular de chat do Qwen Cloud é intencionalmente mais restrito do que a resposta dinâmica completa de texto. Sua
lista de permissões mantida está em `open-sse/config/providers/registry/qwen-cloud/index.ts`; a descoberta
dinâmica retorna apenas IDs presentes tanto na resposta upstream quanto nessa lista do registro.

O Alibaba Model Studio segue a mesma regra de interseção dinâmica com sua lista de permissões mantida de forma independente
em `open-sse/config/providers/registry/alibaba/index.ts`. O provedor de compatibilidade `alibaba-cn`
reutiliza esse catálogo enquanto resolve a descoberta no endpoint de Pequim.
