`copilot-m365-web` (alias `m365copilot`) envia solicitações de chat no formato OpenAI por meio de uma
sessão autenticada do Microsoft 365 Copilot BizChat no navegador em
`m365.cloud.microsoft/chat`. Esta é uma integração não oficial.

> **É a primeira vez que você usa provedores de cookies da Web?**
>
> Leia **`docs/getting-started/WEB-COOKIE-GUIDE.md`** para conhecer o processo geral de configuração, as orientações de autenticação, as limitações e a solução de problemas antes de seguir este guia específico do provedor.
>
> **Importante:** A credencial deste provedor **não é um cookie**. Não copie
> cookies de `m365.cloud.microsoft`. A credencial consiste em um parâmetro de consulta
> da URL do WebSocket e um segmento de caminho, ambos obtidos na guia Network do DevTools.

## Pré-requisitos

- Uma conta do Microsoft 365 com acesso ao BizChat em `m365.cloud.microsoft/chat`
- Um navegador baseado em Chromium (Chrome, Edge) para inspecionar o WebSocket no DevTools
- Uma licença do M365 Copilot (incluída em muitos planos Microsoft 365 Business/Enterprise)

## Captura da credencial (método WebSocket)

1. Entre em `https://m365.cloud.microsoft/chat` e inicie uma conversa.
2. Abra **DevTools → Network**.
3. Filtre por **WS** (WebSocket).
4. Clique na conexão WebSocket do Chathub. Procure uma URL que comece com
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Na **Request URL**, copie:
   - O valor do parâmetro de consulta `access_token` (um JWT de curta duração).
   - O segmento de caminho do Chathub após `/Chathub/` (por exemplo, `<oid>@<tenant>`).

A URL completa tem o seguinte formato:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. No OmniRoute, acesse **Providers → Add Provider**, selecione **Microsoft 365 Copilot
   (BizChat)** e cole a credencial no seguinte formato:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Clique em **Test Connection** e **Save**.

## Captura da credencial (importação de HAR)

Em vez de copiar manualmente os valores da URL do WebSocket, você pode exportar um arquivo
HAR do DevTools:

1. Abra **DevTools → Network**.
2. Inicie ou continue uma conversa no BizChat (isso aciona a conexão WebSocket).
3. Clique com o botão direito no painel Network e selecione **Save all as HAR with content**.
4. No OmniRoute, use o botão **Import .har file** na caixa de diálogo de conexão do provedor.

O OmniRoute verifica o HAR em busca da URL do WebSocket do Chathub, extrai
`access_token` e `chathubPath` e preenche automaticamente os campos da credencial. A
importação do HAR decodifica a expiração do JWT e mostra o tempo restante de validade do token.

> **Nunca faça commit de uma exportação HAR real, de um token de acesso ou de um token de atualização.** Os valores de teste e de
> documentação devem sempre ser espaços reservados.

## Duração e atualização do token

O `access_token` tem curta duração (normalmente **~75 minutos**). Após a expiração, o provedor
informa um erro de conexão e você precisa capturar novamente a credencial.

### Atualização automática com `refreshToken`

Para evitar a recaptura manual, você pode armazenar um token de atualização da Microsoft nas
**Advanced Settings → providerSpecificData** da conexão:

| Campo          | Descrição                                                                           |
| -------------- | ----------------------------------------------------------------------------------- |
| `refreshToken` | Token de atualização OAuth da Microsoft para o escopo `substrate.office.com/sydney` |
| `tier`         | `individual` (padrão), `edu` ou `enterprise`                                        |

Obtenha o token de atualização por meio de um fluxo de código de dispositivo ou de código de autorização da Microsoft
com o escopo `substrate.office.com/sydney`. Com `refreshToken` definido, o OmniRoute
atualiza preventivamente o `access_token` antes de cada solicitação, portanto, você não precisa
capturá-lo novamente após cada expiração de aproximadamente 75 minutos.

Se `refreshToken` não estiver definido, você precisará capturar novamente a credencial do WebSocket manualmente
após cada expiração.

### Seleção do nível

| Nível        | Alias      | Interface                      |
| ------------ | ---------- | ------------------------------ |
| `individual` | _(padrão)_ | M365 Copilot para consumidores |
| `edu`        | `included` | M365 Copilot para educação     |
| `enterprise` | `work`     | M365 Copilot para o trabalho   |

Defina o nível em **Advanced Settings → providerSpecificData → tier**. O nível afeta
o roteamento do BizChat e o acesso aos modelos.

## Modelo de segurança

- **Integração não oficial.** Este provedor utiliza engenharia reversa no protocolo
  WebSocket do BizChat. Ele pode parar de funcionar sem aviso prévio quando a Microsoft alterar o endpoint.
- O sinalizador `subscriptionRisk: true` indica que a integração depende de um
  endpoint não documentado. Restrições à conta são possíveis, mas não foram confirmadas.
- O token de acesso é um JWT de curta duração. Trate-o como uma senha: não faça commit,
  não registre em logs nem o compartilhe.
- O token de atualização concede acesso de longo prazo à interface do BizChat. Armazene-o com o
  mesmo cuidado que uma chave de API.

## Solução de problemas

### A autenticação falha imediatamente

- Verifique se você copiou da **URL do WebSocket**, e não de uma solicitação XHR/Fetch. A
  credencial está no parâmetro de consulta `access_token` da conexão WebSocket do Chathub
  — e não em um cabeçalho `Authorization: Bearer`.
- Certifique-se de que `chathubPath` inclua o segmento `<oid>@<tenant>` completo do caminho
  da URL.

### O token expira após aproximadamente 75 minutos

Isso é esperado. Sem um `refreshToken`, o token de acesso tem curta duração. Você pode:

- Capturar novamente a credencial no DevTools ou
- Configurar um `refreshToken` nas Configurações avançadas para atualização automática.

### O teste de conexão é aprovado, mas o chat retorna 401

O token pode ter expirado entre a validação e a primeira solicitação. Capture novamente uma
credencial válida.

### O Copilot não aparece na lista de provedores

Certifique-se de que `copilot-m365-web` esteja habilitado em **Painel → Provedores**. O provedor pode
estar oculto por padrão em alguns níveis.
