O gateway upstream `agentrouter` executa um filtro de conteúdo baseado em palavras-chave em
`messages[].content`. O filtro é parcialmente determinístico (sempre bloqueia
determinadas frases) e parcialmente probabilístico (sensível a rajadas — torna-se
mais agressivo após requisições rápidas e se recupera após um período de espera).

Quando o WAF bloqueia uma requisição, ele retorna:

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## Escopo do filtro

O WAF inspeciona apenas `messages[].content`. Ele **não** inspeciona:

- O prompt `system`
- Blocos de conteúdo estruturado (`tool_result`, `tool_use`, `thinking`, `image`)
- Os campos `description` e `input_schema` das ferramentas
- Metadados da requisição, cabeçalhos ou ID do modelo

## Padrões sempre bloqueados (sem diferenciação entre maiúsculas e minúsculas)

| Padrão                             | Observações                                                  |
| ---------------------------------- | ------------------------------------------------------------ |
| Qualquer variante de `Lorem ipsum` | Todo o vocabulário latino lorem é bloqueado                  |
| `language model` (isoladamente)    | "the language model" e "large language model" são permitidos |
| `virtual assistant`                | "AI assistant" é permitido                                   |
| `I'm here to help`                 | "here to help" isoladamente também é bloqueado               |
| `Claude, made by Anthropic`        | Somente a frase completa                                     |

## Padrões quase sempre bloqueados

| Padrão                                                    | Observações                                                   |
| --------------------------------------------------------- | ------------------------------------------------------------- |
| `placeholder`                                             | Quando aparece isoladamente (não como nome de parâmetro etc.) |
| `dummy data`                                              | Frase inicial comum para fixtures                             |
| `foo bar baz`                                             | Frase de placeholder canônica                                 |
| Tokens curtos repetidos (`AAA BBB CCC`, `test test test`) | Detector de excesso de palavras-chave                         |

## Comportamento sob carga

Após aproximadamente 5 requisições rápidas em um curto intervalo, o WAF começa a bloquear conteúdo
que normalmente seria permitido. O bucket relaxa após aproximadamente 5–10 segundos de
inatividade. Esse é o mesmo limitador de taxa vinculado ao IP e à chave que causa
erros intermitentes `400 content-blocked` quando o Claude Code ou o Codex CLI
faz várias chamadas de uso de ferramenta/envio de mensagem em rápida sucessão.

## Mitigações já aplicadas no OmniRoute

1. **`open-sse/services/wafRateLimit.ts`** — proteção contra rajadas que impõe um
   intervalo mínimo de 500 ms entre requisições de saída para qualquer URL
   `agentrouter:*`. O intervalo está muito abaixo do limiar humano de percepção de latência e impede
   que o WAF seja ativado pelo tráfego normal.

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — quando um upstream retorna
   `400 content-blocked`, o executor tenta novamente a mesma URL com
   backoff exponencial (1,5 s, 3,0 s, no máximo 2 tentativas). Após o backoff,
   o WAF geralmente relaxa e a nova tentativa é bem-sucedida.

3. **`tests/unit/compression/harness.test.ts`** — a fixture de teste
   `longInput` foi alterada de `"lorem ipsum dolor sit amet ".repeat(40)`
   para `"example content for testing purposes ".repeat(40)` para que, quando
   o Claude Code leia esse arquivo por meio da ferramenta `Read`, o conteúdo do arquivo
   não retorne por um bloco `tool_result` e acione o WAF.

## Orientações para prompts e saída de ferramentas

Se uma sessão do Claude Code ou Codex CLI encontrar repetidamente
`400 content-blocked`, verifique a mensagem de usuário mais recente e o resultado de ferramenta mais
recente em busca de qualquer um dos padrões acima e reformule o texto. Soluções alternativas
comuns:

- Substitua `Lorem ipsum …` por `example text …` ou pelo conteúdo real
  que o teste ou a fixture está tentando representar.
- Substitua `placeholder` (quando estiver isolado) por `example value`,
  `sample value` ou pelo valor real.
- Substitua `language model` por `large language model` ou `the model`.
- Substitua `dummy data` por `sample data` ou por valores iniciais realistas.
- Substitua `I'm here to help` / `here to help` por uma abertura mais específica
  (por exemplo, "I'll review the file you mentioned").

## Como relatar os falsos positivos ao upstream

O filtro atual é excessivamente agressivo — ele bloqueia "Lorem ipsum" em
blocos `tool_result`, embora o operador claramente não tivesse a intenção de
injetar um prompt. Os operadores que desejarem que isso seja corrigido na origem devem
entrar em contato com `agentrouter.org` para relatar os falsos positivos. A lista de bloqueio
acima é o resultado empírico de testes do upstream em 2026-08-03.
