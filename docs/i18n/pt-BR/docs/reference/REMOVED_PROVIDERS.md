Alguns serviços foram integrados ao OmniRoute e posteriormente removidos porque as pessoas que os gerenciam solicitaram. Esta página é o registro duradouro dessas remoções. Seu único propósito é evitar que eles retornem acidentalmente: um colaborador que encontra um fork antigo, um tarball npm em cache, um problema arquivado ou uma solicitação de "restaurar provedor X" precisa de um único lugar que diga **não reintroduzir**.

Esta página **não** é uma lista de serviços mortos ou descontinuados. Esses são rastreados em [`FREE_TIERS.md`](FREE_TIERS.md) ("Removido / sem camada gratuita") e podem retornar se o serviço o fizer. As entradas abaixo só podem retornar com permissão por escrito do operador nomeado na solicitação, e essa permissão deve ser vinculada à entrada.

## Política

1.  **Uma solicitação de remoção de um operador de serviço é atendida, não negociada.** O OmniRoute não é afiliado a nenhum serviço upstream. Quando o operador de um serviço pede para a integração ser removida, ela é removida, independentemente de a integração ter usado uma API oficial ou não.
2.  **"Removido" significa todas as superfícies que o OmniRoute controla.** Executor, entrada de registro, ID e alias do provedor, lista de modelos, endpoints, variáveis de ambiente, ícone, cartões do painel, a referência do provedor gerada, `FREE_TIERS.md`, a referência de ambiente, contagens do README, espelhos de `llm.txt`, testes dedicados e snapshots dourados, comentários de código, itens do CHANGELOG (com uma reconciliação contábil, veja `config/release/changelog-reconciliations.json`), notas de lançamento do GitHub, a wiki, e os issues, discussões e pull requests do GitHub cujo assunto era aquele provedor (issues e discussões excluídos; pull requests renomeados, suas descrições substituídas e o tópico bloqueado, porque o GitHub não pode excluir pull requests).
3.  **Nunca reintroduza uma entrada nesta página sem permissão por escrito.** Isso inclui adicionar o ID ou alias de volta a qualquer catálogo de provedores, adicionar os domínios a um executor, aceitar um PR de colaborador que o "restaura", adicioná-lo ao catálogo de modelos gratuitos ou documentar uma maneira manual de alcançá-lo através do OmniRoute. Feche tais PRs e issues com um link para esta página.
4.  **Mantenha a entrada mínima.** Registre apenas o que um revisor precisa para reconhecer uma reintrodução: identificadores, domínios, datas e o pull request que fez a remoção. Não descreva como a integração funcionou.
5.  **O guarda de regressão é `tests/unit/removed-providers-blocklist.test.ts`.** Ele falha quando qualquer identificador ou domínio abaixo aparece novamente nos catálogos de provedores, no mapa do executor ou nas fontes do registro de provedores. Adicione os novos identificadores a esse teste no mesmo PR que adiciona uma linha aqui.

## Adicionando uma entrada

Quando uma nova solicitação de remoção chega:

1.  Confirme que a solicitação vem do operador do serviço (seu endereço de suporte ou um domínio que ele controla) e mantenha a mensagem privada.
2.  Remova a integração seguindo a lista de verificação no item 2 da política. Use [#12440](https://github.com/diegosouzapw/OmniRoute/pull/12440) como referência para um provedor sem chave e [#10210](https://github.com/diegosouzapw/OmniRoute/pull/10210) para um provedor de chave de API com conexões armazenadas (adicione uma migração).
3.  Adicione uma linha à tabela acima e os identificadores a `tests/unit/removed-providers-blocklist.test.ts`, no mesmo PR.
4.  Responda ao operador assim que o PR for mesclado, listando o que foi removido e o que o OmniRoute não pode alterar (versões npm e Docker já publicadas, histórico do git, forks de terceiros).
