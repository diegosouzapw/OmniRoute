Alguns serviços foram integrados ao OmniRoute e posteriormente removidos porque as pessoas que os operam solicitaram isso. Esta página é o registro permanente dessas remoções. Seu único objetivo é impedir que eles voltem por acidente: um colaborador que encontre um fork antigo, um tarball do npm em cache, uma issue arquivada ou uma solicitação para “restaurar o provedor X” precisa de um lugar que diga **não reintroduza**.

Esta página **não** é uma lista de serviços inativos ou descontinuados. Esses serviços são registrados em [`FREE_TIERS.md`](FREE_TIERS.md) (“Removidos / sem nível gratuito”) e podem voltar caso o serviço também volte. As entradas abaixo só podem voltar mediante permissão por escrito do operador mencionado na solicitação, e essa permissão deve ser vinculada a partir da entrada.

## Política

1. **Uma solicitação de remoção feita pelo operador de um serviço é atendida, não negociada.** O OmniRoute não é afiliado a nenhum serviço externo. Quando o operador de um serviço solicita que a integração seja removida, ela é removida, independentemente de usar ou não uma API oficial.
2. **“Removido” significa todas as superfícies controladas pelo OmniRoute.** Executor, entrada do registro, ID e alias do provedor, lista de modelos, endpoints, variáveis de ambiente, ícone, cartões do painel, referência gerada do provedor, `FREE_TIERS.md`, referência de ambiente, contagens no README, espelhos de `llm.txt`, testes dedicados e snapshots de referência, comentários no código, itens do CHANGELOG (com uma reconciliação registrada; consulte `config/release/changelog-reconciliations.json`), notas do GitHub Releases, wiki e issues, discussões e pull requests do GitHub cujo assunto era esse provedor (issues e discussões excluídas; pull requests renomeados, com a descrição substituída e a conversa bloqueada, pois o GitHub não permite excluir pull requests).
3. **Nunca reintroduza uma entrada desta página sem permissão por escrito.** Isso inclui adicionar novamente o ID ou alias a qualquer catálogo de provedores, adicionar os domínios a um executor, aceitar um PR de colaborador que o “restaure”, adicioná-lo ao catálogo de modelos gratuitos ou documentar uma forma manual de acessá-lo por meio do OmniRoute. Encerre esses PRs e issues com um link para esta página.
4. **Mantenha a entrada mínima.** Registre apenas o que um revisor precisa para reconhecer uma reintrodução: identificadores, domínios, datas e o pull request que realizou a remoção. Não descreva como a integração funcionava.
5. **A proteção contra regressões é `tests/unit/removed-providers-blocklist.test.ts`.** Ela falha quando qualquer identificador ou domínio abaixo reaparece nos catálogos de provedores, no mapa de executores ou nos arquivos-fonte do registro de provedores. Adicione os novos identificadores a esse teste no mesmo PR que adicionar uma linha aqui.

## Como adicionar uma entrada

Quando uma nova solicitação de remoção chegar:

1. Confirme que a solicitação vem do operador do serviço (do endereço de suporte dele ou de um domínio sob seu controle) e mantenha a mensagem em sigilo.
2. Remova a integração seguindo a lista de verificação do item 2 da política. Use [#12440](https://github.com/diegosouzapw/OmniRoute/pull/12440) como referência para um provedor sem chave e [#10210](https://github.com/diegosouzapw/OmniRoute/pull/10210) para um provedor com chave de API e conexões armazenadas (adicione uma migração).
3. Adicione uma linha à tabela acima e os identificadores a `tests/unit/removed-providers-blocklist.test.ts`, no mesmo PR.
4. Responda ao operador depois que o PR for mesclado, listando o que foi removido e o que o OmniRoute não pode alterar (versões do npm e Docker já publicadas, histórico do git e forks de terceiros).
