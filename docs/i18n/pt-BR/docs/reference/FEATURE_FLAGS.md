> Alternâncias em tempo de execução que alteram o comportamento do OmniRoute **sem uma nova implantação**.
> Todas as flags listadas aqui estão definidas em
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> — a única fonte da verdade. Tanto o painel quanto a API REST leem
> esse arquivo, portanto a tabela abaixo é gerada para corresponder a ele na proporção de 1:1.

---

## O que são feature flags

Uma feature flag é uma alternância nomeada (booleana ou enum) cujo valor pode ser alterado em
tempo de execução e persistido no banco de dados, sem exigir uma nova implantação do processo. Cada
flag é descrita por uma `FeatureFlagDefinition` com uma `key`, `label`,
`description`, `category`, `defaultValue`, `type` e uma indicação `requiresRestart`.

### Ordem de resolução

O **valor efetivo** de uma flag é resolvido por
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) com esta
precedência (a mais alta prevalece):

1. **Substituição no banco de dados** — um valor armazenado na tabela `key_value` sob o
   namespace `feature_flags` (definido pelo painel ou pela API REST).
2. **Variável de ambiente** — `process.env[<KEY>]`, caso esteja definida e não esteja vazia.
3. **Valor padrão da definição** — o `defaultValue` de `featureFlagDefinitions.ts`.

Uma flag booleana é considerada **habilitada** quando seu valor efetivo é `"true"`,
`"1"` ou `"yes"` (consulte `isFeatureFlagEnabled()`).

> [!NOTE]
> A maioria das flags também possui uma variável de ambiente correspondente com o **mesmo nome**,
> documentada em [`ENVIRONMENT.md`](./ENVIRONMENT.md). A substituição da flag no banco de dados
> tem precedência sobre essa variável de ambiente. Uma flag com
> `requiresRestart: true` é persistida imediatamente, mas só é lida novamente na inicialização
> do processo — alterná-la exibe um banner **"Reiniciar servidor"** no painel.

usado quando não há uma substituição no banco de dados nem uma variável de ambiente presente.

## Alternando Flags

### Dashboard

Navegue até **Dashboard → Settings → Feature Flags**
(`/dashboard/settings/feature-flags`). A grade
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
oferece suporte a:

- **Pesquisa** por chave ou descrição e **filtro** por categoria (além de uma
  visualização sintética **Requires Restart**).
- Um **botão de alternância** para flags booleanas e uma **lista suspensa** para flags enum
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- Um **selo de origem** por flag — `DB`, `ENV` ou `DEF` — mostrando de onde veio o
  valor efetivo.
- Um botão **Reset** (exibido apenas para flags provenientes de `DB`) para remover a substituição
  e um botão **Reset All Overrides** na parte inferior.
- Um banner **Restart Server** quando uma flag `requiresRestart` é alterada.

### API REST

Todas as operações passam por uma única rota:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Cada método exige uma sessão autenticada no dashboard (caso contrário, retorna `401`).

#### `GET /api/settings/feature-flags`

Retorna todas as flags com seus valores efetivos, origens e um resumo.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... todas as 72 flags
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Define ou remove uma única substituição. Corpo: `{ key: string; value?: string }`.
Omitir `value` remove a substituição (restaurando o valor de env / padrão).

```bash
# Define uma substituição no DB
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Remove a substituição (sem "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

A resposta retorna o novo `effectiveValue`/`source`, o `previousValue`/
`previousSource` e `requiresRestart`. Chaves desconhecidas e valores enum fora do intervalo
são rejeitados com `400`.

#### `DELETE /api/settings/feature-flags`

Remove **todas** as substituições do DB de uma só vez, restaurando cada flag para seu valor de env / padrão.
Retorna `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> Flags com `requiresRestart: true` só entram em vigor após o processo ser recarregado.
> O fluxo de reinicialização do dashboard chama `POST /api/restart` e depois consulta repetidamente
> `GET /api/health/ping` até que o servidor volte a funcionar.

## Fallback Emergencial de Orçamento

`OMNIROUTE_EMERGENCY_FALLBACK` (categoria `runtime`, padrão `true`) controla o
caminho de fallback gratuito emergencial em
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Quando habilitado, as solicitações que esgotam seu orçamento são encaminhadas para um
provedor/modelo de fallback gratuito em vez de falharem imediatamente. Defina-o como `false` (ou `0`) — por meio
do botão de alternância no dashboard, de uma substituição no DB ou da variável de ambiente
`OMNIROUTE_EMERGENCY_FALLBACK` — para desabilitar o comportamento e permitir que solicitações cujo orçamento
foi esgotado falhem. (Disponibilizado como um botão de alternância no dashboard nos PRs #3741 / #3752.)
