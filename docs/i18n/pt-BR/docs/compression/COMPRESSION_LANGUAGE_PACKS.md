A compressão Caveman pode carregar pacotes de regras específicos de cada idioma, além das regras integradas em inglês.
Isso mantém o mecanismo principal estável e permite que os pacotes de português, espanhol, alemão, francês, italiano, japonês e
de futuros idiomas evoluam de forma independente.

## Localização

Os pacotes de idiomas ficam em:

```txt
open-sse/services/compression/rules/<language>/
```

Pacotes distribuídos atualmente (verificados em relação ao conteúdo do diretório `rules/`):

| Idioma             | Diretório      | Categorias de regras presentes                      |
| ------------------ | -------------- | --------------------------------------------------- |
| Inglês             | `rules/en/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Espanhol           | `rules/es/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Português (Brasil) | `rules/pt-BR/` | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Indonésio          | `rules/id/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Italiano           | `rules/it/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Alemão             | `rules/de/`    | `context`, `filler`, `structural`                   |
| Francês            | `rules/fr/`    | `context`, `filler`, `structural`                   |
| Japonês            | `rules/ja/`    | `context`, `filler`, `structural`                   |

> **Nota de paridade:** os pacotes `en`, `es`, `pt-BR`, `id` e `it` têm todas as 5 categorias; `de`, `fr` e `ja` incluem 3 categorias. As categorias `dedup` e `ultra` ausentes usam silenciosamente como alternativa as regras integradas em inglês. Contribuições para adicionar `dedup.json` e `ultra.json` aos pacotes menores são bem-vindas.
>
> O pacote `pt-BR` é baseado no **[Troglodita](https://github.com/leninejunior/troglodita)**, de Lenine Júnior — um sistema de compressão projetado do zero para a gramática do português brasileiro (redução de pleonasmos, remoção de termos de preenchimento em PT-BR e abreviações técnicas para a comunidade brasileira de desenvolvimento).
>
> A lista canônica de categorias e o esquema de cada categoria estão em [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) (JSON Schema, rascunho 2020-12).

## Detecção de idioma

`languageDetector.ts` usa heurísticas leves para inferir o idioma com base no texto do prompt. O
idioma padrão configurado continua sendo respeitado, e a detecção pode ser desabilitada pela configuração quando um controle
preciso for necessário.

A saída da detecção é usada apenas para escolher os pacotes de regras. Ela não altera o roteamento de provedores, a seleção
de localidade nem o idioma da interface.

## Formato da configuração

As configurações de compressão podem incluir:

```json
{
  "languageConfig": {
    "enabled": true,
    "defaultLanguage": "en",
    "autoDetect": true,
    "enabledPacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  },
  "cavemanConfig": {
    "language": "en",
    "autoDetectLanguage": true,
    "enabledLanguagePacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  }
}
```

`languageConfig` controla os valores padrão do dashboard e da pré-visualização. `cavemanConfig` é a configuração do mecanismo em tempo de execução
usada quando o Caveman comprime o texto das mensagens.

## Adicionando um Pacote de Idioma

1. Crie `open-sse/services/compression/rules/<language>/<pack>.json`.
2. Use o formato de regras do Caveman descrito em `docs/compression/COMPRESSION_RULES_FORMAT.md`.
3. Mantenha as substituições conservadoras e evite alterar código, identificadores, URLs ou JSON.
4. Adicione ou atualize testes para a seleção de idioma e o comportamento das substituições.
5. Disponibilize novos rótulos do painel/i18n se o idioma aparecer nos seletores da interface.

## API

Os pacotes disponíveis podem ser consultados com:

```bash
curl http://localhost:20128/api/compression/language-packs
```

O endpoint de pré-visualização aceita substituições da configuração de idioma:

```bash
curl -X POST http://localhost:20128/api/compression/preview \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "standard",
    "text": "Por favor, eu gostaria que voce basicamente resumisse isso.",
    "config": {
      "languageConfig": {
        "defaultLanguage": "pt-BR",
        "autoDetect": true
      }
    }
  }'
```

## SHARED_BOUNDARIES (v3.8.0)

Todos os 6 pacotes de idioma receberam uma cláusula `SHARED_BOUNDARIES` na v3.8.0, aplicada em todas
as intensidades do Caveman (LITE, FULL, ULTRA). Ela instrui o mecanismo a preservar literalmente estes padrões,
independentemente da remoção de conteúdo supérfluo ao redor:

| Tipo de padrão                              | Exemplo                                |
| ------------------------------------------- | -------------------------------------- |
| Blocos de código delimitados                | ` ```python\n...\n``` `                |
| Código inline                               | `` `my_var` ``                         |
| URLs                                        | `https://example.com/path`             |
| Caminhos de arquivo (absolutos + relativos) | `/etc/hosts`, `./src/index.ts`         |
| Cabeçalhos de erro                          | `Error:`, `TypeError:`, `SyntaxError:` |
| Linhas de rastreamento de pilha             | `  at functionName (file.ts:12:3)`     |

Esses padrões são preenchidos em `DEFAULT_CAVEMAN_CONFIG.preservePatterns` (anteriormente `[]`). A
constante está localizada em `open-sse/services/compression/types.ts`.

### Por que isso é importante

Sem `SHARED_BOUNDARIES`, os modos agressivos do Caveman poderiam remover conteúdo que parecesse texto
repetitivo, mas que na verdade fosse um trecho de código, caminho de arquivo ou pilha de erros. `SHARED_BOUNDARIES` atua como uma
rede de segurança independente de idioma, aplicada antes da execução das regras de remoção de conteúdo supérfluo.

### Personalizando preservePatterns

Padrões adicionais podem ser adicionados em tempo de execução por meio das configurações de compactação:

````json
{
  "cavemanConfig": {
    "preservePatterns": [
      "```[\\s\\S]*?```",
      "`[^`]+`",
      "https?://\\S+",
      "(?:/|\\./)[^\\s]+",
      "\\b(?:Error|TypeError|SyntaxError|RangeError):",
      "\\s+at\\s+\\S+\\s+\\(\\S+:\\d+:\\d+\\)"
    ]
  }
}
````

Os padrões personalizados estendem (não substituem) os 6 padrões padrão.

## Notas Operacionais

- As regras integradas em inglês continuam sendo a alternativa quando um pacote de idioma está ausente.
- Pacotes JSON integrados inválidos falham na validação para que os artefatos de lançamento não sofram degradação silenciosa.
- Os pacotes de regras contêm apenas dados e não devem importar código nem executar lógica arbitrária.
- A camada de análise de compactação registra o modo e o mecanismo selecionados, não o texto completo do prompt.
