## 1. Fonte oficial do serviço (documentação oficial, verificada de forma cruzada)

- URL base: `https://api.anysearch.com` (REST) + `POST /mcp` (MCP, JSON-RPC 2.0).
- `POST /v1/search` - parâmetros: `query` (obrigatório), `max_results` (1-10, padrão 10), `tag` (`{domain}.{sub_domain}` para roteamento vertical), `zone` (cn/intl), `language`, `params` (campos verticais estruturados), `format` (json/markdown).
- `GET /v1/sub-domains?domain=...` - catálogo de recursos, NÃO é contabilizado na cota.
- `POST /v1/extract` - busca/extrai `{url, title, content}`; corpo JSON estrito, limite de 16 KiB.
- `POST /v1/auth/email/register` - cadastro em uma única chamada, retorna uma chave em texto simples de uso único `as_sk_...`.
- Autenticação: `Authorization: Bearer <as_sk_...>` opcional; o acesso anônimo é rebaixado para limites por IP, consumindo a cota gratuita diária; uma chave inválida retorna 401/403 SEM fallback anônimo silencioso.
- Plano gratuito: 1000 solicitações/dia, 20 QPS por chave. Plano pago: sem preço definido (Em breve).
- Envelope da resposta: sucesso `{code: 0, message: "success", request_id, data}`; falha `{code: -1, message}`. Erros de autenticação/cota não incluem um `error_code` estruturado (o texto da mensagem é o sinal); erros específicos de extração incluem `error_code` (`invalid_extract_url`, `extract_failed`). Não há cabeçalho `Retry-After` em respostas 429.

## 3. Decisões (todas tomadas em 2026-08-26)

1. **Postura de roteamento: `fallbackOnly`.** Justificativa: um provedor gratuito de custo 0 nunca deve dominar o roteamento automático por custo; a seleção explícita e o retorno de failover não são afetados. Precedente: entrada xquik já mesclada.
2. **Escopo: webSearch + webFetch via `POST /v1/extract` na v1.** Alinhado ao modelo mental de dupla capacidade tavily/exa. Superfícies verticais (`tag`, `sub-domains`, `batch_search`) permanecem fora do escopo — atualmente não há IR para parâmetros verticais.
3. **Exibição da cota: `freeMonthlyQuota: 0`** (exibição conservadora no estilo xquik). A franquia real (1000 requisições/dia, com redefinição diária) é informada no texto de `authHint` do catálogo da interface. Justificativa: a exibição da cota deve corresponder à semântica de redefinição; converter um limite diário em um equivalente mensal (30000) é uma promessa falsa que a interface não pode cumprir.
4. **searchTypes: `["web"]` somente.** Não há evidência pública de uma vertical de notícias/imagens na API do AnySearch; gateways que integram APIs sem uma vertical documentada (por exemplo, Google Custom Search) expõem apenas a web, em vez de mapear silenciosamente notícias -> web.
5. **Postura quanto à chave:** funciona sem chave; uma chave inválida retorna 401/403 e nunca é silenciosamente rebaixada para acesso anônimo (reflete o contrato do serviço upstream).
6. **Exclusões deliberadas:** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (a interceptação de chat permanece com firecrawl/jina/tavily); `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (endpoints remotos anônimos compartilham um único pool limitado por IP para cada IP de saída, portanto a extração sem chave é opcional, e não uma candidata ao roteamento automático); `QUOTA_STATUS_PROVIDERS` (o AnySearch sinaliza a cota via 429/envelope, não pelo status 402/403).
