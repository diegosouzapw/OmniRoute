Há vários números de cobertura, dependendo de como o relatório é calculado. Para fins de planejamento, apenas um deles é útil.

A linha de base recomendada é o número que deve ser otimizado.

## Regras

- As metas de cobertura se aplicam aos arquivos de código-fonte, não a `tests/**`.
- `open-sse/**` faz parte do produto e deve permanecer no escopo.
- Código novo não deve reduzir a cobertura nas áreas alteradas.
- Prefira testar o comportamento e os resultados das ramificações em vez dos detalhes de implementação.
- Prefira bancos de dados SQLite temporários e fixtures pequenas em vez de mocks abrangentes para `src/lib/db/**`.

## Conjunto atual de comandos

- `npm run test:coverage`
  - Verificação principal de cobertura do código-fonte para a suíte de testes unitários
  - Gera `text-summary`, `html`, `json-summary` e `lcov`
- `npm run coverage:report`
  - Relatório detalhado, arquivo por arquivo, da execução mais recente
- `npm run test:coverage:legacy`
  - Somente para comparação histórica

## Política de ratchet

Atualize os limites de `npm run test:coverage` somente depois que o projeto realmente superar o próximo marco com uma margem confortável.

**Limite atual:** `npm run test:coverage` exige **60 statements / 60 lines / 60 functions / 60 branches** (a métrica teve sua linha de base redefinida na Quality-Gates Fase 6A.1 — a linha de base anterior de 82,58% estava inflada porque contabilizava arquivos de teste e excluía `open-sse`). O comando `test:coverage:legacy` preserva a métrica antiga de 50/50/50 para comparação histórica.

Para verificações pontuais de limites no relatório mais recente, use:

```bash
node scripts/check/test-report-summary.mjs --threshold 75
```

Sequência de ratchet recomendada (a ordem é `statements-lines / branches / functions`):

1. 55/60/55
2. 60/62/58
3. 65/64/62
4. 70/66/66
5. 75/70/72 <-- limite atual (75/70/75)
6. 80/75/78
7. 85/80/84
8. 90/85/88

O próximo objetivo do ratchet é `80/75/78`, assim que a cobertura de branches permanecer acima de 78% por duas execuções consecutivas.

## Lacuna conhecida

O comando de cobertura atual mede a suíte principal de testes unitários do Node e inclui o código-fonte alcançado por ela, incluindo `open-sse`. Ele ainda não combina a cobertura do Vitest em um único relatório consolidado. Vale a pena fazer essa consolidação posteriormente, mas ela não é um impedimento para iniciar a progressão de 60% -> 80%.
