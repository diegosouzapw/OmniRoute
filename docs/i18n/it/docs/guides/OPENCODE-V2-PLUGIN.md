`@omniroute/opencode-plugin-v2` rende disponibile l'intero catalogo OmniRoute — modelli, combo e
auto-combo — nel selettore di modelli di OpenCode v2, con nomi visualizzati, prezzi e budget
del piano gratuito.

È un pacchetto separato da `@omniroute/opencode-plugin` perché OpenCode v1 e v2 caricano
i plugin tramite contratti differenti. Scegli quello corrispondente alla versione principale di OpenCode in uso; non vi è
nulla di condiviso tra i due, quindi l'aggiornamento dell'uno non impone mai quello dell'altro.

## Requisiti

- OpenCode v2.
- Un gateway OmniRoute raggiungibile (`http://localhost:20128` per impostazione predefinita).
- Node.js 22 o 24.

## Installazione

Aggiungi il plugin a `opencode.json`:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

I modelli vengono quindi visualizzati come `omniroute/<provider>/<model>`; `providerId` determina tale prefisso e
l'id dell'integrazione sotto cui OpenCode memorizza la credenziale.

## Credenziali

Il plugin cerca una chiave del gateway in tre posizioni, nel seguente ordine:

1. **La credenziale collegata in OpenCode.** Il plugin registra un'integrazione, consentendo
   al flusso di autenticazione di OpenCode di memorizzare la chiave. Nulla viene salvato in `opencode.json`: questa è l'opzione consigliata.
2. `apiKey` nelle opzioni del plugin, per una sostituzione specifica del progetto. In questo modo la chiave viene inserita in un file che
   potrebbe essere incluso nei commit.
3. `OMNIROUTE_API_KEY` nell'ambiente.

Se nessuna delle tre è presente, il catalogo è vuoto e il plugin lo segnala una volta all'avvio, anziché
lasciare un selettore vuoto senza alcuna spiegazione.

### Il token di gestione è una chiave diversa

Le combo, lo stato dei provider e l'arricchimento (nomi visualizzati, prezzi e budget del piano gratuito) provengono
dagli endpoint `/api/*` del gateway, che nella maggior parte delle distribuzioni sono protetti da un token di **gestione**
anziché dalla chiave di inferenza:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<token di lettura per la gestione>"
}
```

Se non è impostato, `managementReadToken` utilizza come ripiego `apiKey`. Quando un gateway rifiuta tale ripiego,
il catalogo viene comunque pubblicato, ma con gli id grezzi dei modelli anziché i nomi visualizzati, senza
deduplicazione degli alias canonici, senza prezzi e senza combo. Il plugin emette un avviso una volta per ciascun endpoint quando ciò accade,
indicando il nome dell'endpoint e ciò che è andato perso, affinché un selettore degradato non rimanga mai inspiegabile.

## Opzioni

| Chiave                           | Valore predefinito                                | Note                                                                                                                                           |
| -------------------------------- | ------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `providerId`                     | `"omniroute"`                                     | Id del provider, id dell'integrazione e prefisso sotto cui vengono visualizzati i modelli                                                      |
| `baseURL`                        | obbligatorio                                      | Radice del gateway, solo `http(s)`; il suffisso `/v1` viene aggiunto dove necessario                                                           |
| `apiKey`                         | credenziale collegata, quindi `OMNIROUTE_API_KEY` | Chiave per la chat per `/v1/*`                                                                                                                 |
| `managementReadToken`            | utilizza `apiKey` come ripiego                    | Chiave per `/api/*` — solitamente **non** è la stessa                                                                                          |
| `displayName`                    | `"OmniRoute"`                                     | Nome del provider nel selettore                                                                                                                |
| `timeoutMs`                      | `10000`                                           | Timeout di recupero per endpoint (le auto-combo utilizzano 5 s)                                                                                |
| `modelCacheTtlMs`                | `300000`                                          | TTL della cache del catalogo; un'istantanea su disco accelera gli avvii a freddo                                                               |
| `timeouts`                       | utilizza `timeoutMs` come ripiego                 | Limiti per endpoint in ms: `models`, `combos`, `autoCombos`, `enrichment`                                                                      |
| `enrichment`                     | `true`                                            | Recupera nomi, prezzi e budget del piano gratuito                                                                                              |
| `providerTag`                    | `true`                                            | Anteporre al nome visualizzato il provider upstream verso cui viene effettuato l'instradamento                                                 |
| `usableOnly`                     | `false`                                           | Mantiene solo i provider che il gateway segnala come configurati                                                                               |
| `visibleModels` / `hiddenModels` | `[]`                                              | Liste consentite per corrispondenza esatta o suffisso; l'esclusione ha la precedenza                                                           |
| `geminiSanitization`             | `true`                                            | Rimuove dagli schemi degli strumenti le parole chiave JSON Schema rifiutate da Gemini (gli strumenti `$ref` vengono inoltrati senza modifiche) |
| `apiFormat.allowAnthropic`       | `false`                                           | Instrada gli id presenti nella lista consentita tramite il blocco API di Anthropic                                                             |
| `apiFormat.anthropicModels`      | `[]`                                              | Id completi dei modelli instradati ad Anthropic                                                                                                |
| `logLevel` / `startupDebug`      | `warn` / `false`                                  | Livello di dettaglio dei log                                                                                                                   |

## Come mantenere aggiornato il catalogo

Il catalogo viene recuperato in modo lazy e memorizzato nella cache per `modelCacheTtlMs`; inoltre, uno snapshot su disco mantiene disponibile l'ultimo catalogo noto quando il gateway non è raggiungibile: un'interruzione comporta soltanto una perdita di aggiornamento. I modelli e le combo vengono pubblicati non appena arrivano; le combo automatiche, l'elenco dei provider e l'overlay di arricchimento vengono integrati quando sono disponibili, in modo che un singolo endpoint lento non possa bloccare l'intero selettore.

I nomi includono le informazioni note al gateway: il provider upstream verso cui viene instradato un modello, un indicatore `[Free]` e il relativo budget, così due connessioni che offrono lo stesso modello restano distinguibili. Disattiva il prefisso con `"providerTag": false`.

Non esiste un comando di aggiornamento manuale: i comandi di OpenCode v2 sono modelli di prompt, non callback, quindi un plugin non può esporne uno. Gli aggiornamenti seguono il TTL; all'host viene richiesto di ricaricare solo quando il catalogo o l'overlay sono effettivamente cambiati, mai a ogni aggiornamento.

## Chiamata degli strumenti su Gemini

Gemini rifiuta un'intera richiesta le cui dichiarazioni degli strumenti contengono `$schema` o `additionalProperties`, rispondendo con `400 INVALID_ARGUMENT`. Il plugin rimuove queste parole chiave dagli schemi degli strumenti destinati a un modello Gemini di questo provider e lascia inalterate tutte le altre richieste. Uno strumento contenente un `$ref` viene inoltrato senza modifiche anziché essere ripulito, poiché la rimozione del riferimento amplierebbe lo schema facendogli «accettare qualsiasi cosa».
Imposta `"geminiSanitization": false` per disattivare questa funzionalità.

## Risoluzione dei problemi

| Sintomo                                         | Causa                                                                                                                        |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Il selettore non mostra alcun modello OmniRoute | Non è stata trovata alcuna chiave (controlla l'avviso all'avvio), oppure il gateway non è raggiungibile                      |
| ID modello grezzi, nessuna combo, nessun prezzo | Gli endpoint di gestione hanno rifiutato il token: imposta `managementReadToken`                                             |
| Una sessione è vincolata a `opencode-<id>/…`    | Il plugin v1 pubblicava `opencode-<id>`; v2 pubblica direttamente `<id>`, quindi seleziona nuovamente il modello in `<id>/…` |
