**OmniCopilot** aggiunge tutti i modelli forniti da OmniRoute al selettore modelli _nativo_ di GitHub Copilot Chat.
Nessuna seconda barra laterale, nessuna interfaccia di chat separata: la modalità agente di Copilot, le chiamate agli strumenti,
i server MCP e le istruzioni personalizzate continuano a funzionare, semplicemente utilizzando il modello selezionato.

|                                    |                                                                                                                                                 |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Installazione (VS Code)**        | [Marketplace → `diegosouzapw.omnicopilot`](https://marketplace.visualstudio.com/items?itemName=diegosouzapw.omnicopilot)                        |
| **Installazione (fork)**           | [Open VSX](https://open-vsx.org/extension/diegosouzapw/omnicopilot) — Cursor, Windsurf, VSCodium, Theia, code-server, Gitpod, Antigravity, Kiro |
| **Codice sorgente / segnalazioni** | [github.com/diegosouzapw/OmniCopilot](https://github.com/diegosouzapw/OmniCopilot) (MIT)                                                        |
| **Requisiti**                      | VS Code 1.104+                                                                                                                                  |

> **Non è necessario un abbonamento a Copilot.** A partire da VS Code 1.122, un provider di modelli linguistici funziona
> senza accedere a GitHub e senza alcun piano Copilot. I completamenti inline e
> le funzionalità basate sugli embedding non rientrano nell'API del provider e richiedono comunque Copilot.

## Configurazione

1. **Avvia OmniRoute** — `npm install -g omniroute && omniroute` (dashboard su `http://localhost:20128`).
2. **Installa l'estensione** — cerca "OmniRoute" nella vista Estensioni.
3. **Scegli un modello** — Copilot Chat → selettore modelli → **Gestisci modelli…** → **OmniRoute**, quindi seleziona
   quelli che desideri.

Non è necessario configurare nulla quando OmniRoute viene eseguito sulla porta predefinita. Per un'istanza remota, apri
l'**icona OmniRoute nella barra attività** (oppure esegui `OmniRoute: Manage Connection`) e imposta:

- **URL del server** — la radice del server, ad esempio `http://192.168.0.15:20128`. Il suffisso `/v1` viene
  aggiunto dall'estensione; non includerlo.
- **Chiave API** — solo quando il server imposta `REQUIRE_API_KEY`. Viene archiviata nel portachiavi del sistema operativo tramite
  SecretStorage di VS Code, mai in `settings.json`.

## Cosa mostrerà il selettore

L'estensione non mostra il payload grezzo di `GET /v1/models`: lo rielabora, e il numero visualizzato
è inferiore alle dimensioni del catalogo per due motivi ben precisi.

### Richiede un solo id per modello

Il valore predefinito di `MODELS_CATALOG_PREFIX_MODE` è **`dual`**, che pubblicizza ogni modello due volte: una volta
con il prefisso alias breve e una volta con il prefisso canonico del provider, in modo che le configurazioni dei client
meno recenti continuino a risolvere entrambe le forme:

```
cc/claude-sonnet-4-6        ← prefisso alias
claude/claude-sonnet-4-6    ← prefisso canonico, stesso modello
```

L'estensione richiede **`GET /v1/models?prefix=alias`**, così viene restituito un solo id per modello, senza
modificare l'impostazione globale del server per gli altri client. Su un'istanza di riferimento, ciò ha ridotto
**2345 voci a 1396: 949 duplicati, zero modelli persi.**

Se preferisci applicare la correzione a livello di server per _ogni_ client, imposta il flag di funzionalità
`MODELS_CATALOG_PREFIX_MODE` su `alias` nella dashboard. Consulta
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) per il
parametro di query e la tabella relativa a ciascuna modalità.

### Nasconde i modelli che non supportano la chat

Il catalogo elenca anche modelli per immagini, video, audio, reranking, embedding e moderazione. Questi vengono
comunque rifiutati nelle richieste di chat:

```
HTTP 400 — Il modello '<id>' è un modello di generazione di immagini e non può essere utilizzato su
/v1/chat/completions. Utilizza invece POST /v1/images/generations.
```

pertanto vengono filtrati in base al campo `type` prima di raggiungere il selettore. **I modelli Responses-API
vengono mantenuti**: ogni voce Codex / GPT-5.x dichiara `supported_endpoints: ["responses"]`
e OmniRoute le traduce per `/v1/chat/completions`, quindi sono perfettamente utilizzabili.

### Provider mai configurati

Il catalogo elenca i modelli dei provider con una **connessione attiva**, oltre a tutti i provider **noAuth**:
quelli senza chiave che costituiscono gran parte del piano gratuito. È intenzionale. Per nasconderli,
aggiungili a `blockedProviders` nelle impostazioni della dashboard; non è necessario modificare nulla
nell'estensione.

## Dashboard all'interno di una scheda di VS Code

`omnicopilot.dashboardOpen: "editor"` visualizza la dashboard di OmniRoute in una scheda dell'editor tramite
Simple Browser anziché in un browser esterno. L'incorporamento è **facoltativo sul server** tramite
`DASHBOARD_ALLOW_EMBED=vscode`, che serve le pagine HTML con
`frame-ancestors 'self' vscode-webview:` anziché con le impostazioni predefinite `frame-ancestors 'none'` +
`X-Frame-Options: DENY`. La superficie API (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) mantiene in
ogni caso gli header restrittivi.

> ⚠️ **È un flag di fase di build, non di runtime.** Next.js compila `headers()` nel manifesto delle route,
> quindi `next.config.mjs` legge la variabile durante la creazione del bundle
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> Esportarla prima di avviare un server già compilato non cambia nulla: gli header sono incorporati nella build.

```bash
# la variabile deve essere presente nel comando di BUILD
DASHBOARD_ALLOW_EMBED=vscode npm run build        # oppure npm run build:release
npm start
```

| Metodo di installazione    | È possibile abilitare l'incorporamento?                                                                                                              |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dal codice sorgente        | ✅ imposta la variabile nel comando di build, come indicato sopra                                                                                    |
| `npm install -g omniroute` | ❌ il pacchetto pubblicato include un bundle precompilato: esegui invece la build dal codice sorgente                                                |
| Immagine Docker            | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — l'immagine precompilata su Docker Hub non abilita l'incorporamento |

Senza una build che consenta l'incorporamento, la pagina rifiuta di essere visualizzata in un frame; l'estensione lo rileva dagli
header della risposta e torna al browser esterno: non si verifica alcun malfunzionamento e viene mostrato un solo avviso.
Consulta [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) e l'issue
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273).

## Risoluzione dei problemi

| Sintomo                                                               | Causa / soluzione                                                                                                                                                                                                                                                                                                               |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Nessun modello OmniRoute nel selettore                                | Il server non è raggiungibile. Il punto nella barra di stato diventa grigio; esegui `OmniRoute: Check Connection`. Il rilevamento è intenzionalmente silenzioso e non aggiunge alcun modello anziché mostrare una richiesta.                                                                                                    |
| Ogni modello appare due volte                                         | Stai usando una versione di OmniCopilot precedente alla 1.0.1: aggiornala. Ora l'estensione richiede `?prefix=alias`.                                                                                                                                                                                                           |
| Un modello di immagini/audio prima presente è scomparso               | Comportamento intenzionale dalla versione 1.0.1: non avrebbe mai potuto rispondere a una richiesta di chat.                                                                                                                                                                                                                     |
| Il pannello non è presente nella barra attività                       | VS Code sposta i contenitori di viste aggiuntivi nel menu di overflow **"…"** nella parte inferiore della barra attività, mentre un contenitore nascosto tramite clic destro rimane nascosto. Fai clic con il pulsante destro sulla barra attività → seleziona **OmniRoute**, oppure aprilo con `OmniRoute: Manage Connection`. |
| La dashboard si apre nel browser nonostante la modalità `editor`      | Il server non è stato **compilato** con `DASHBOARD_ALLOW_EMBED=vscode` (vedi sopra): impostarla all'avvio di un'installazione precompilata non produce alcun effetto. Il fallback è intenzionale.                                                                                                                               |
| L'elenco dei modelli non è aggiornato dopo aver modificato i provider | Esegui `OmniRoute: Refresh Models` oppure usa il collegamento ↻ nel pannello.                                                                                                                                                                                                                                                   |
