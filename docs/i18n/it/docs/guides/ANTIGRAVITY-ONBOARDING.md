## 1. Antigravity vs Antigravity CLI (agy)

Entrambi i provider condividono lo **stesso backend Google**: client OAuth, aggiornamento dei token, endpoint e account Google identici. La differenza riguarda i modelli visualizzati.

> Consulta l'[annuncio della CLI di Antigravity](https://antigravity.google/blog/introducing-google-antigravity-cli) per il confronto ufficiale di Google.

| Aspetto                    | `antigravity` (IDE)                                 | `agy` (CLI)                                                       |
| -------------------------- | --------------------------------------------------- | ----------------------------------------------------------------- |
| **Prodotto Google**        | Antigravity 2.0 / Antigravity IDE                   | Antigravity CLI                                                   |
| **Backend**                | Stessa API Google Cloud Code                        | Stessa API Google Cloud Code                                      |
| **OAuth / Token**          | Stesso client, stesso aggiornamento                 | Stesso client, stesso aggiornamento                               |
| **Catalogo dei modelli**   | Elenco statico selezionato (integrato in OmniRoute) | Rilevato in tempo reale da Google tramite `:fetchAvailableModels` |
| **Modelli Claude**         | Sonnet 4.6, Opus 4.6 (4 varianti ciascuno)          | Sonnet 4.6, Opus 4.6 (4 varianti ciascuno)                        |
| **Nomenclatura Gemini**    | Etichette chiare (Low/Medium/High)                  | ID upstream (extra-low/low/agent)                                 |
| **Modelli aggiuntivi**     | `gpt-oss-120b-medium`                               | Può includere modelli aggiuntivi di Google                        |
| **Caso d'uso predefinito** | Integrazione con IDE (VS Code, JetBrains)           | Accesso tramite CLI / API                                         |
| **Quota**                  | Condivisa con agy (stesso account Google)           | Condivisa con antigravity (stesso account Google)                 |

**Modelli disponibili (verificati sperimentalmente, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (vari livelli di ragionamento)
- Claude: Sonnet 4.6, Opus 4.6 (ciascuno con varianti default/low/medium/high)
- Altro: GPT-OSS 120B Medium
- **Claude Sonnet 5 NON è disponibile**: sono supportate solo le varianti 4.6

**Perché il catalogo dei modelli è diverso**: la CLI di Google è «ottimizzata per velocità e basso overhead» e «co-ottimizzata con i modelli Gemini» (secondo il blog ufficiale di Google). Il prodotto Web/IDE è «ottimizzato per la completezza». La CLI utilizza `:fetchAvailableModels` per individuare dinamicamente i modelli, mentre l'IDE utilizza un elenco statico selezionato.

**In pratica**: usa il prefisso `agy/` per i modelli Gemini (ad esempio, `agy/gemini-3.7-flash-high`). Usa `antigravity/` per l'elenco statico selezionato. Entrambi accedono allo stesso backend Google, ma espongono nomenclature diverse per i modelli. La quota è condivisa: l'utilizzo di uno dei due provider viene conteggiato rispetto agli stessi limiti dell'account Google.

## 2. Google One AI Pro: sistema di quote

> Consulta [Documentazione di Antigravity: piani](https://antigravity.google/docs/plans) per i dettagli ufficiali sulle quote e [Modifiche ai piani Antigravity](https://antigravity.google/blog/changes-to-antigravity-plans) per gli ultimi aggiornamenti sui prezzi.

Google Antigravity utilizza una **quota a due livelli** basata sul "Lavoro svolto" (peso computazionale), non sul numero di messaggi.

### I due livelli

| Livello                     | Che cos'è                          | Ciclo di rinnovo                                                                          |
| --------------------------- | ---------------------------------- | ----------------------------------------------------------------------------------------- |
| **Sessione di 5 ore**       | Quota immediata di "lavoro svolto" | Si reimposta 5 ore dopo la prima richiesta di una sessione                                |
| **Soglia base di 7 giorni** | Limite massimo settimanale         | Se raggiunto, prevale sul rinnovo di 5 ore; blocca fino al periodo di 7 giorni successivo |

**Come viene calcolato il "Lavoro svolto"**: le attività che fanno un uso intensivo degli agenti (ad es. "Esegui il refactoring dell'intero repository") consumano la quota molto più rapidamente rispetto alle attività semplici (ad es. "Correggi questa funzione"). Non è disponibile una dashboard in tempo reale che mostri il consumo.

### Livelli dei piani

| Piano        | Prezzo     | Quota                                         | Limite settimanale                             |
| ------------ | ---------- | --------------------------------------------- | ---------------------------------------------- |
| Free         | $0         | Quota significativa, rinnovata ogni settimana | Sì                                             |
| AI Pro       | $19.99/mo  | Quota elevata, rinnovo continuo ogni 5 ore    | Sì (se raggiunto, prevale sul limite di 5 ore) |
| AI Ultra 5x  | $99.99/mo  | Quota 5x rispetto a Pro                       | Nessun limite settimanale                      |
| AI Ultra 20x | $199.99/mo | Quota 20x rispetto a Pro                      | Nessun limite settimanale                      |

### Modelli Gemini e non Gemini

- **Modelli Gemini** (Flash + Pro): condividono un unico limite di utilizzo, il cui consumo è calcolato in base ai prezzi delle API. Se Flash costa 8x meno di Pro, si ottengono 8x più token Flash.
- **Modelli non Gemini** (Claude, GPT-OSS): dispongono di limiti di utilizzo **separati**. Potrebbero rimanere disponibili anche quando Gemini è bloccato.

### Crediti AI (utilizzo eccedente)

> Consulta [Crediti AI di Google One](https://support.google.com/googleone/answer/14534406) per informazioni sul funzionamento dei crediti.

Quando la quota di base è esaurita:

- **Mai**: attende il rinnovo della quota; mostra "Quota del modello di base raggiunta"
- **Sempre**: utilizza automaticamente i crediti AI; torna alla quota di base quando viene rinnovata

I crediti vengono acquistati separatamente e detratti in base ai prezzi standard delle API.

### Dettagli principali

- La quota è **condivisa a livello di account**: lo stesso account Google utilizzato nell'IDE Antigravity, nella CLI e in OmniRoute condivide un unico pool di quote
- Ogni account Google dispone di una quota indipendente: più account = più pool di quote
- Gli utenti di AI Pro hanno segnalato **blocchi di 7 giorni** anziché rinnovi dopo 5 ore quando viene raggiunta la soglia base settimanale (Google ha confermato che questo comportamento è intenzionale nei periodi di forte domanda)

**Quando la quota del tuo account è esaurita**: OmniRoute riprova automaticamente con l'account disponibile successivo nella route combinata. Non è necessario alcun intervento manuale.

## 3. Come ottenere un projectId

Ogni connessione antigravity/agy richiede un `projectId` di Google Cloud Code. Senza di esso, l'endpoint `/v1internal:models` restituisce un errore 404.

### Metodo A: automatico (consigliato)

OmniRoute gestisce automaticamente questa operazione. Quando aggiungi un nuovo account Google tramite OAuth nella Dashboard:

1. OmniRoute aggiorna il token
2. Chiama `loadCodeAssist` per individuare il projectId
3. Se non esiste alcun progetto, chiama `onboardUser` per crearne uno
4. Riprova a chiamare `loadCodeAssist` per ottenere il projectId appena creato
5. Lo salva nel database

**Questo metodo funziona per la maggior parte degli account**: non sono necessari passaggi manuali.

### Metodo B: manuale tramite la CLI agy

Se l'individuazione automatica non riesce (consulta la Sezione 5 per sapere quando accade):

```bash
# Installa la CLI agy (se non è già installata)
npm install -g @anthropic-ai/agy

# Accedi con il tuo account Google
agy login

# Seleziona l'account che deve completare l'onboarding
# Questa operazione avvia la registrazione a Cloud Code e assegna un projectId
```

Dopo il completamento di `agy login`, aggiorna il token nella Dashboard di OmniRoute. Il projectId verrà individuato automaticamente.

### Come verificare

Controlla il database:

```bash
# All'interno del container OmniRoute
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Oppure controlla i log:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. URI di reindirizzamento OAuth

### Il problema

Google OAuth richiede un URI di reindirizzamento valido. La configurazione predefinita di OmniRoute utilizza `http://127.0.0.1:20128/callback` (loopback). Questa configurazione funziona per le build locali, ma **non funziona per le distribuzioni remote** (ad esempio, un server a cui si accede tramite un indirizzo IP LAN).

Google rifiuta gli URI di reindirizzamento che:

- Utilizzano indirizzi IP (è necessario un dominio che termini con `.com`, `.org`, ecc.)
- Non corrispondono agli URI di reindirizzamento registrati nella configurazione del client OAuth

### La soluzione

**Opzione A: utilizzare il flusso OAuth integrato (predefinito)**

- Funziona quando accedi a OmniRoute da `localhost` o `127.0.0.1`
- Non è necessaria alcuna configurazione

**Opzione B: credenziali OAuth personalizzate**

- Imposta `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` nel tuo ambiente
- Fornisci le tue credenziali Google OAuth:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Registra `https://your-domain.com/callback` come URI di reindirizzamento autorizzato nella Google Cloud Console

**Opzione C: utilizzare la CLI agy per l'accesso iniziale**

- Esegui `agy login` sulla macchina che accederà a OmniRoute
- Il flusso OAuth viene completato localmente e i token vengono memorizzati
- Importa la connessione in OmniRoute tramite la Dashboard

### Limitazioni

- Le credenziali OAuth personalizzate richiedono un nome di dominio (Google non accetta indirizzi IP come URI di reindirizzamento)
- Se non disponi di un dominio, utilizza invece l'opzione A o C

## 5. Risoluzione dei problemi: quando la configurazione automatica non riesce

OmniRoute gestisce automaticamente l'individuazione di projectId e l'onboarding per la maggior parte degli account. Quando il processo non riesce, la causa principale è generalmente una delle seguenti:

### La regione dell'account è bloccata

**Sintomo**: `agy login` restituisce "Eligibility check failed: Your current account is not eligible for Antigravity, because it is not currently available in your location."

**Causa principale**: gli account Google dispongono di un campo backend "Country Association", impostato al momento della registrazione. La CLI agy e l'API Cloud Code verificano rigorosamente questo campo, a differenza di Gemini sul web, che controlla soltanto il tuo IP corrente.

> Per controllare o modificare la regione associata al tuo account, visita il [modulo di associazione del Paese di Google](https://policies.google.com/country-association-form).

**Perché Gemini sul web funziona, mentre agy no**:

- Gemini sul web / Google One: controlla soltanto l'IP corrente (il proxy funziona)
- CLI agy / API Cloud Code: legge il campo backend Country Association (il proxy non è d'aiuto)

**Soluzione**:

1. Visita il [modulo di associazione del Paese di Google](https://policies.google.com/country-association-form) mentre utilizzi un IP statunitense
2. Invia una richiesta di modifica della regione (seleziona "I live in a different country")
3. Attendi da 1 a 24 ore affinché Google elabori la richiesta e invii la notifica via email
4. A questo punto, `agy login` dovrebbe riuscire

### L'account non dispone di un progetto Cloud Code

**Sintomo**: i log mostrano `loadCodeAssist returned no project id` e `onboardUser failed (400)`.

**Causa principale**: l'account non è mai stato registrato con Google Cloud Code e l'onboarding automatico non è riuscito.

**Soluzione**: esegui manualmente `agy login` per avviare la registrazione a Cloud Code, quindi aggiorna il token nella Dashboard di OmniRoute.

### Token scaduto o revocato

**Sintomo**: errori 401 nei log o messaggi "Token has expired".

**Soluzione**: aggiorna il token in Dashboard → Providers → agy → fai clic sull'icona di aggiornamento. Se il token di aggiornamento è stato revocato, dovrai autenticarti nuovamente tramite OAuth.

## Diagramma di flusso decisionale

```
L'account non funziona?
│
├─ Ha un projectId nel database?
│  ├─ SÌ → Il problema è altrove (token scaduto, limite di richieste, ecc.)
│  └─ NO ↓
│
├─ L'associazione del Paese dell'account è impostata su un'area geografica soggetta a restrizioni?
│  ├─ SÌ → Modifica l'area geografica nel modulo per l'associazione del Paese di Google
│  │         (https://policies.google.com/country-association-form)
│  │         Attendi da 1 a 24 ore, quindi riprova
│  └─ NO ↓
│
├─ L'account dispone di un abbonamento Google One AI Pro?
│  ├─ NO → Prima abbonati su one.google.com
│  └─ SÌ ↓
│
├─ Prova il rilevamento automatico (aggiorna il token nella Dashboard)
│  ├─ Funziona → Fatto
│  └─ Non funziona ancora ↓
│
└─ Procedura manuale: esegui `agy login` sul computer
   ├─ Funziona → Aggiorna il token nella Dashboard; projectId verrà rilevato
   └─ Non funziona → Controlla il messaggio di errore: probabilmente è un problema relativo all'area geografica o all'abbonamento
```
