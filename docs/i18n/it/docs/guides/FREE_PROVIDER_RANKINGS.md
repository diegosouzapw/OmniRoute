> **TL;DR**: OmniRoute classifica i suoi provider **gratuiti** in base alla qualità dei modelli utilizzando i **punteggi ELO di Arena AI
> (in stile LMArena)**. Apri la pagina **Classifica dei provider gratuiti** nella
> dashboard per vedere quali provider gratuiti offrono i modelli migliori per la tua attività —
> complessivamente oppure filtrati per categoria (programmazione, revisione, documentazione, debugging).

---

## Che cos'è

OmniRoute registra 329 provider, incluse 155 voci del catalogo contrassegnate come **gratuite/senza autenticazione**
(senza autenticazione,
OAuth con piano gratuito o chiave API con piano gratuito — consulta la
[Guida ai piani gratuiti](../getting-started/FREE-TIERS-GUIDE.md) e la
[Directory completa dei piani gratuiti](../reference/FREE_TIERS.md)). Il problema è che la qualità
dei modelli dei provider gratuiti varia enormemente. Un provider senza autenticazione che offre un
modello all'avanguardia è molto più utile di uno che offre un piccolo modello legacy.

**Classifica dei provider gratuiti** risponde alla domanda "**quale provider gratuito mi offre il modello migliore?**"
combinando il catalogo di ciascun provider gratuito con i **punteggi di qualità raccolti dalla community**
della **classifica di Arena AI** (ELO basato sulle preferenze umane, lo stesso concetto alla base
della chatbot arena di LMArena). I provider vengono quindi classificati in base alla qualità del loro
**miglior modello gratuito**.

La classifica viene calcolata a partire da tre fonti reali:

1. Gli elenchi dei provider gratuiti — `NOAUTH_PROVIDERS`, più le voci
   `OAUTH_PROVIDERS` / `APIKEY_PROVIDERS` contrassegnate con `hasFree`
   (`src/shared/constants/providers.ts`).
2. Il catalogo dei modelli di ciascun provider dal registro dei provider
   (`open-sse/config/providerRegistry.ts`).
3. I punteggi di idoneità alle attività derivati dall'ELO e archiviati nella tabella DB
   `model_intelligence` dal motore di sincronizzazione ELO di Arena (`src/lib/arenaEloSync.ts`).

La logica di combinazione si trova in `src/lib/freeProviderRankings.ts`.

## Come accedere

### Pagina della dashboard

Apri la dashboard e vai a **Costi → Classifica dei provider gratuiti**, oppure accedi direttamente a:

```
/dashboard/free-provider-rankings
```

La pagina (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) mostra:

- Un **podio dei primi 3** (🥇 🥈 🥉) provider gratuiti con il punteggio più alto.
- Una **tabella di classifica** completa con le colonne: **Posizione**, **Provider**, **Modello migliore**,
  **Punteggio**, **Punteggio medio**, **Modelli**, **Tipo**.
- **Pulsanti per filtrare per categoria**: _Tutte le categorie_, _Predefinita_, _Programmazione_, _Revisione_,
  _Documentazione_, _Debugging_.

Il badge **Tipo** di ciascun provider indica in che modo è gratuito:

| Badge    | Significato                                          |
| -------- | ---------------------------------------------------- |
| `NOAUTH` | Sempre gratuito, non sono necessarie credenziali     |
| `OAUTH`  | Provider OAuth con un piano gratuito (`hasFree`)     |
| `APIKEY` | Provider con chiave API e piano gratuito (`hasFree`) |

I punteggi vengono mostrati sotto forma di etichette leggibili (ad esempio _Élite_, _Eccellente_, _Molto buono_,
_Buono_, _Nella media_) anziché come numeri grezzi, perché il valore sottostante rappresenta
una qualità relativa della classifica, non una percentuale.

### Endpoint API

La pagina è supportata da un endpoint pubblico di lettura
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

Parametri della query (convalidati con Zod):

| Parametro  | Tipo   | Predefinito | Note                                                                                                       |
| ---------- | ------ | ----------- | ---------------------------------------------------------------------------------------------------------- |
| `category` | string | (nessuno)   | Uno tra `default`, `coding`, `review`, `documentation`, `debugging`. Omettilo per la classifica combinata. |
| `limit`    | number | `50`        | Limitato all'intervallo `1–100`.                                                                           |

Struttura della risposta:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` è il valore ELO originale di Arena; `score` è il valore normalizzato di idoneità
all'attività (vedi sotto). I provider privi di modelli con punteggio vengono omessi dalla risposta.

## Come funzionano i punteggi

### Fonte: classifica Arena AI

Il motore di sincronizzazione ELO di Arena (`src/lib/arenaEloSync.ts`) recupera due classifiche — `text`
e `code` — dall'API della classifica Arena AI
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`). Ogni voce della classifica
include il nome del modello, il fornitore, il `score` ELO, l'intervallo di confidenza e il numero di voti.

Le categorie della classifica sono associate alle categorie di attività di OmniRoute:

| Classifica Arena | Categorie di attività OmniRoute                   |
| ---------------- | ------------------------------------------------- |
| `text`           | `default`, `review`, `documentation`, `debugging` |
| `code`           | `coding`                                          |

### Normalizzazione (punteggio di idoneità all'attività)

I punteggi ELO grezzi vengono normalizzati per ciascuna classifica in un **valore di idoneità all'attività nell'intervallo `[0.4, 0.98]`**:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

Il punteggio non raggiunge mai `0` o `1`, lasciando margine per le personalizzazioni dell'utente. Questo è il
campo `score` visualizzato nella risposta dell'API e l'etichetta mostrata nella dashboard.

### Confidenza

A ogni voce viene assegnato un livello di confidenza in base al numero di voti su Arena:

| Confidenza | Voti    |
| ---------- | ------- |
| `high`     | ≥ 5.000 |
| `medium`   | ≥ 1.000 |
| `low`      | < 1.000 |

### Archiviazione e aggiornamento dei dati

Le voci normalizzate vengono scritte nella tabella DB `model_intelligence` con
`source = "arena_elo"` (`src/lib/db/modelIntelligence.ts`). Le voci **scadono dopo
7 giorni**, quindi un fornitore che interrompe la sincronizzazione viene infine rimosso anziché continuare a fornire
dati obsoleti.

La sincronizzazione è **attiva per impostazione predefinita**:

- Viene eseguita una volta all'avvio del server e successivamente tramite un timer periodico
  (`src/lib/arenaEloSync.ts`, collegato da `src/instrumentation-node.ts`).
- È **non bloccante e mai fatale**: se il recupero dei dati dal servizio upstream non riesce, OmniRoute continua
  a funzionare e le classifiche mostrano semplicemente gli ultimi dati validi (oppure uno stato vuoto).

Due variabili di ambiente ne controllano il funzionamento (documentate in
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)):

| Variabile                 | Valore predefinito | Scopo                                                               |
| ------------------------- | ------------------ | ------------------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`             | Impostare su `false` per disattivare la sincronizzazione in uscita. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h)      | Intervallo di sincronizzazione, in secondi.                         |

### Sincronizzazione manuale / stato / cancellazione

Per gli operatori, un endpoint di gestione autenticato consente il controllo manuale
(`src/app/api/intelligence/sync/route.ts` — richiede l'autenticazione di gestione):

```
GET    /api/intelligence/sync          # stato corrente della sincronizzazione (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # avvia una sincronizzazione manuale; corpo: { "dryRun": true } per visualizzare un'anteprima senza scrivere
DELETE /api/intelligence/sync          # cancella tutte le voci di intelligence arena_elo sincronizzate
```

Se la pagina delle classifiche è vuota, un `POST /api/intelligence/sync` manuale (o semplicemente
il riavvio del server) la ripopola.

### Associazione dei modelli alla classifica

Gli ID dei modelli nel registro e i nomi dei modelli Arena non sempre corrispondono esattamente. La classifica utilizza
un'associazione flessibile (`findMatchingIntelligence` in `src/lib/freeProviderRankings.ts`):

1. Corrispondenza esatta con l'ID normalizzato del modello.
2. Corrispondenza dopo la rimozione di un suffisso di versione finale (ad es. `kimi-k2.6` → `kimi-k2`).
3. Corrispondenza per prefisso (il nome di un modello nella classifica è un prefisso dell'ID nel registro).

Durante la sincronizzazione, i prefissi dei fornitori noti (`anthropic/`, `openai/`, `google/`, …) vengono
rimossi e una piccola mappa di alias espande i nomi canonici nelle varianti utilizzate internamente da OmniRoute,
così i modelli restano individuabili con qualsiasi nome.

### Come viene classificato un fornitore

Per ogni fornitore gratuito, il motore assegna un punteggio a ciascun modello del suo catalogo, quindi:

- **Modello migliore** = il modello del fornitore con il punteggio più alto.
- **Punteggio medio** = la media dei punteggi di tutti i modelli valutati del fornitore.
- **Modelli** = il numero di modelli del fornitore che disponevano di un punteggio Arena.

I fornitori vengono ordinati prima in base al **punteggio del modello migliore**, quindi in base al punteggio medio. Questo premia un
fornitore che offre almeno un modello gratuito valido.

## Come usarlo per scegliere i provider gratuiti

1. **Scegli la categoria corretta.** Usa il filtro **Coding** per i carichi di lavoro agentici/di programmazione oppure
   lascia selezionato **All Categories** / **Default** per la chat generica. Lo stesso provider può
   avere una posizione diversa a seconda della categoria, perché il suo modello migliore varia in base alla classifica.
2. **Dai la priorità al podio per le configurazioni singole.** Se vuoi connettere soltanto uno o due provider
   gratuiti, inizia da quelli con la posizione più alta nella tua categoria.
3. **Controlla il badge Type.** I provider `NOAUTH` sono i più rapidi da connettere (non richiedono
   credenziali). I piani gratuiti `OAUTH` / `APIKEY` richiedono una breve registrazione, ma spesso offrono
   modelli più potenti. Consulta la [Guida ai piani gratuiti](../getting-started/FREE-TIERS-GUIDE.md) per i
   passaggi di connessione.
4. **Connettine diversi e lascia decidere ad Auto-Combo.** Gli stessi dati Arena ELO su cui si basa
   questa pagina alimentano anche il **fattore di idoneità al compito** del motore di valutazione Auto-Combo
   (`open-sse/services/autoCombo/taskFitness.ts`, ordine di risoluzione
   `user_override → arena_elo → models_dev_tier → static table`). Quindi, dopo aver connesso
   i migliori provider gratuiti, l'instradamento con `model: "auto"` (ad es. `auto/coding`) darà
   automaticamente la priorità ai modelli gratuiti di qualità superiore per ogni richiesta. Consulta
   [Auto-Combo](../routing/AUTO-COMBO.md) per il sistema completo di valutazione a 16 fattori.
