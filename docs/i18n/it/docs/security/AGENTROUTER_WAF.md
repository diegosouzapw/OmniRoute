Il gateway upstream `agentrouter` esegue un filtro dei contenuti basato su parole chiave su
`messages[].content`. Il filtro è parzialmente deterministico (blocca sempre
determinate frasi) e parzialmente probabilistico (sensibile alle raffiche: diventa
più aggressivo dopo richieste rapide e torna alla normalità dopo un periodo di attesa).

Quando il WAF blocca una richiesta, restituisce:

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## Ambito del filtro

Il WAF esamina soltanto `messages[].content`. **Non** esamina:

- Il prompt `system`
- I blocchi di contenuto strutturati (`tool_result`, `tool_use`, `thinking`, `image`)
- I campi `description` e `input_schema` degli strumenti
- I metadati della richiesta, gli header o l'id del modello

## Pattern sempre bloccati (senza distinzione tra maiuscole e minuscole)

| Pattern                             | Note                                                          |
| ----------------------------------- | ------------------------------------------------------------- |
| Qualsiasi variante di `Lorem ipsum` | L'intero vocabolario latino lorem è bloccato                  |
| `language model` (da solo)          | "the language model" e "large language model" sono consentiti |
| `virtual assistant`                 | "AI assistant" è consentito                                   |
| `I'm here to help`                  | Anche "here to help" da solo viene bloccato                   |
| `Claude, made by Anthropic`         | Solo la frase completa                                        |

## Pattern bloccati quasi sempre

| Pattern                                                | Note                                                      |
| ------------------------------------------------------ | --------------------------------------------------------- |
| `placeholder`                                          | Quando compare da solo (non come nome di parametro, ecc.) |
| `dummy data`                                           | Frase seed comune per le fixture                          |
| `foo bar baz`                                          | Frase segnaposto canonica                                 |
| Token brevi ripetuti (`AAA BBB CCC`, `test test test`) | Rilevatore di keyword stuffing                            |

## Comportamento sotto carico

Dopo circa 5 richieste rapide in un breve intervallo, il WAF inizia a bloccare contenuti
che normalmente verrebbero consentiti. Il bucket si rilassa dopo circa 5–10 secondi
di inattività. Si tratta dello stesso rate limiter associato a IP e chiave che causa
errori intermittenti `400 content-blocked` quando Claude Code o Codex CLI
effettuano più chiamate di utilizzo degli strumenti o invio di messaggi in rapida successione.

## Mitigazioni già applicate in OmniRoute

1. **`open-sse/services/wafRateLimit.ts`** — protezione dalle raffiche che impone un
   intervallo minimo di 500 ms tra le richieste in uscita verso qualsiasi URL
   `agentrouter:*`. L'intervallo è ben al di sotto della soglia di percezione umana
   della latenza e impedisce al WAF di attivarsi con il traffico normale.

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — quando un upstream restituisce
   `400 content-blocked`, l'esecutore riprova lo stesso URL con
   backoff esponenziale (1,5 s, 3,0 s, massimo 2 tentativi). Dopo il backoff,
   il WAF solitamente si rilassa e il nuovo tentativo riesce.

3. **`tests/unit/compression/harness.test.ts`** — la fixture di test
   `longInput` è stata modificata da `"lorem ipsum dolor sit amet ".repeat(40)`
   a `"example content for testing purposes ".repeat(40)`, in modo che, quando
   Claude Code legge questo file tramite lo strumento `Read`, il contenuto del file
   non venga reinviato attraverso un blocco `tool_result` facendo scattare il WAF.

## Indicazioni per i prompt e l'output degli strumenti

Se una sessione di Claude Code o Codex CLI riceve ripetutamente
`400 content-blocked`, controllare il messaggio utente più recente e il risultato
dello strumento più recente per verificare la presenza di uno dei pattern sopra
indicati e riformularlo. Soluzioni alternative comuni:

- Sostituire `Lorem ipsum …` con `example text …` o con il contenuto effettivo
  che il test o la fixture sta cercando di rappresentare.
- Sostituire `placeholder` (quando compare da solo) con `example value`,
  `sample value` o con il valore reale.
- Sostituire `language model` con `large language model` o `the model`.
- Sostituire `dummy data` con `sample data` o con valori seed realistici.
- Sostituire `I'm here to help` / `here to help` con un'apertura più specifica
  (ad es. "I'll review the file you mentioned").

## Segnalazione dei falsi positivi all'upstream

Il filtro attuale è eccessivamente aggressivo: blocca "Lorem ipsum" nei
blocchi `tool_result`, anche se è evidente che l'operatore non intendeva
iniettare un prompt. Gli operatori che desiderano risolvere il problema alla fonte
devono contattare `agentrouter.org` per segnalare i falsi positivi. La blocklist
sopra riportata è il risultato empirico dei test effettuati sull'upstream al 2026-08-03.
