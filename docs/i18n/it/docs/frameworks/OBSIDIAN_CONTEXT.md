> **Fonte di riferimento:** `src/lib/obsidian/api.ts` (client REST + sincronizzazione),
> `src/lib/db/obsidian.ts` (persistenza di token / URL di base / WebDAV),
> `src/lib/obsidianSync.ts` (sincronizzazione del vault tramite WebDAV), `open-sse/mcp-server/tools/obsidianTools.ts`
> (22 strumenti MCP), `src/app/api/settings/obsidian/route.ts` +
> `src/app/api/settings/obsidian/webdav/route.ts` (API delle impostazioni). La registrazione
> degli strumenti e la configurazione degli ambiti si trovano in `open-sse/mcp-server/server.ts`.

## Cos'è

OmniRoute si connette a un vault **Obsidian** come **sorgente di contesto** — una base
di conoscenza Markdown locale che gli agenti leggono e modificano tramite il server MCP
integrato. L'integrazione comunica con il plugin della community **Obsidian Local REST API**
in esecuzione all'interno dell'app desktop, consentendo agli agenti di cercare note,
leggere/scrivere/applicare patch ai file, elencare il contenuto del vault, lavorare con
note periodiche giornaliere/settimanali, gestire tag, eseguire comandi Obsidian e,
facoltativamente, coordinare una sincronizzazione bidirezionale del vault tra desktop
e dispositivi mobili.

Il client (`src/lib/obsidian/api.ts`) incapsula la Local REST API con:

- **Nuovi tentativi con backoff** per errori transitori `5xx` e **timeout di 30 secondi** tramite `AbortController`.
- **Classificazione tipizzata degli errori** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- Un **suggerimento intuitivo per l'errore "impossibile raggiungere Obsidian"** che evidenzia
  il comune errore relativo alla porta (HTTP su `27123`, **non** l'endpoint MCP su `27124`)
  e il formato Tailscale.
- **Codifica dei percorsi** relativi al vault, affinché i percorsi delle note contenenti
  spazi/barre siano sicuri.

## Configurazione

Non esiste **alcuna variabile d'ambiente** per il token o l'URL di base di Obsidian:
entrambi vengono archiviati nella tabella SQLite `key_value` (namespace `obsidian`) tramite
`src/lib/db/obsidian.ts`. Il token è **crittografato a riposo** (AES-256-GCM, con
fallback di compatibilità all'indietro in testo non crittografato). Esegui la configurazione
dalla scheda **Sorgenti di contesto** della dashboard degli endpoint (`ObsidianSourceCard`)
oppure tramite l'API REST delle impostazioni.

> [!IMPORTANT]
> Il plugin **Obsidian Local REST API** deve essere installato e in esecuzione. La sua
> interfaccia REST è in ascolto su **HTTP `127.0.0.1:27123`** (l'URL di base predefinito).
> La porta `27124` è un endpoint MCP/HTTPS _separato_ ed è esplicitamente rifiutata dalla
> route delle impostazioni. Per connettersi da un altro dispositivo, usa
> `http://<tailscale-ip>:27123`.

### Chiavi di configurazione (SQLite `key_value`, namespace `obsidian`)

| Chiave            | Scopo                                                                 | Crittografato |
| ----------------- | --------------------------------------------------------------------- | ------------- |
| `api_key`         | Token bearer della Local REST API                                     | sì            |
| `base_url`        | URL di base REST (predefinito `http://127.0.0.1:27123`)               | no            |
| `vault_path`      | Percorso assoluto della directory del vault (per la sincronizzazione) | no            |
| `webdav_username` | Nome utente WebDAV generato (sincronizzazione del vault)              | no            |
| `webdav_password` | Password WebDAV generata (sincronizzazione del vault)                 | sì            |
| `webdav_enabled`  | Indica se la sincronizzazione WebDAV del vault è abilitata            | no            |

### Configurazione tramite REST

```bash
# Salva e convalida il token della Local REST API (POST esegue la convalida tramite un controllo dello stato)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Controlla lo stato della connessione (restituisce connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# Disconnetti (cancella il token archiviato)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Tutti i metodi richiedono l'autenticazione alla dashboard. `POST` rifiuta qualsiasi URL
sulla porta `27124` e convalida il token chiamando l'endpoint di stato della Local REST API
prima di salvarlo.

### Sincronizzazione WebDAV del vault

`src/app/api/settings/obsidian/webdav/route.ts` gestisce una sincronizzazione opzionale
del vault basata su WebDAV (orchestrata da `src/lib/obsidianSync.ts`). L'abilitazione
configura OmniRoute affinché utilizzi una directory locale del vault e genera una coppia
casuale di nome utente/password WebDAV:

```bash
# Abilita la sincronizzazione WebDAV per una directory del vault (genera nome utente/password)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# Ottieni lo stato della sincronizzazione WebDAV (le credenziali vengono restituite solo quando è abilitata)
curl http://localhost:20128/api/settings/obsidian/webdav

# Disabilita la sincronizzazione WebDAV (cancella le credenziali + il file .stignore gestito)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Sorgente di contesto per chiave API (opzionale)

La configurazione di Obsidian può essere definita **per ciascuna chiave API** tramite la
tabella `api_key_context_sources` (`src/lib/db/apiKeyContextSources.ts`). Quando una
chiamata MCP include l'id di una chiave API autenticata, `getObsidianConfigForApiKey()`
preferisce il token, l'URL di base e il percorso del vault specifici di quella chiave
(`source: "api_key"`); in caso contrario, ricorre alla configurazione globale
(`source: "global"`).

## Strumenti MCP (22)

Definiti in `open-sse/mcp-server/tools/obsidianTools.ts`. Il token e l'URL di base vengono risolti
per ogni chiamata (prima per chiave API, poi a livello globale). Gli strumenti che contattano il **server di sincronizzazione**
OmniRoute (i quattro strumenti `obsidian_sync_*`) richiedono inoltre il token di autenticazione per la sincronizzazione configurato
nelle impostazioni di OmniRoute.

### Strumenti di lettura (`read:obsidian`)

| Strumento                    | Descrizione                                                                                                                       |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Verifica se la Local REST API è raggiungibile e autenticata.                                                                      |
| `obsidian_search_simple`     | Ricerca full-text nel contenuto delle note; restituisce estratti con i percorsi dei file.                                         |
| `obsidian_search_structured` | Esegue ricerche usando un'espressione JSON Logic (filtri and/or/regex/path).                                                      |
| `obsidian_read_note`         | Legge una nota tramite il percorso relativo al vault; facoltativamente un titolo/blocco/frontmatter specifico.                    |
| `obsidian_list_vault`        | Elenca file e directory nel vault (albero di voci).                                                                               |
| `obsidian_get_document_map`  | Ottiene la struttura dei titoli della nota come mappa di titoli → numeri di riga.                                                 |
| `obsidian_get_note_metadata` | Ottiene frontmatter, tag, link e conteggio di caratteri/parole senza il contenuto completo.                                       |
| `obsidian_get_active_file`   | Ottiene il percorso e il contenuto del file attualmente attivo in Obsidian.                                                       |
| `obsidian_get_periodic_note` | Ottiene la nota periodica giornaliera/settimanale/mensile per una data (oggi, se omessa).                                         |
| `obsidian_get_tags`          | Elenca tutti i tag del vault con le relative frequenze.                                                                           |
| `obsidian_list_commands`     | Elenca gli ID dei comandi Obsidian disponibili (da usare con `obsidian_execute_command`).                                         |
| `obsidian_sync_status`       | Stato del server di sincronizzazione OmniRoute: in esecuzione, nome del vault, porta, tempo di attività, ultima sincronizzazione. |
| `obsidian_sync_conflicts`    | Elenca i conflitti di sincronizzazione irrisolti (percorso, percorso del conflitto, data di rilevamento).                         |

### Strumenti di scrittura (`write:obsidian`)

| Strumento                        | Descrizione                                                                                                 |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Crea o sovrascrive una nota con il contenuto Markdown specificato.                                          |
| `obsidian_append_note`           | Aggiunge contenuto a una nota; facoltativamente a un titolo/blocco specifico.                               |
| `obsidian_patch_note`            | Aggiunge, antepone o sostituisce in modo mirato in corrispondenza di un titolo, blocco o campo frontmatter. |
| `obsidian_delete_note`           | Elimina definitivamente una nota dal vault.                                                                 |
| `obsidian_move_note`             | Sposta o rinomina una nota all'interno del vault.                                                           |
| `obsidian_execute_command`       | Esegue un comando Obsidian tramite il relativo ID.                                                          |
| `obsidian_open_file`             | Apre un file in Obsidian (lo crea se non esiste).                                                           |
| `obsidian_sync_trigger`          | Avvia una sincronizzazione bidirezionale immediata del vault desktop↔mobile.                                |
| `obsidian_sync_resolve_conflict` | Risolve un conflitto di sincronizzazione: mantiene `local` (mobile), `remote` (desktop) oppure `keep-both`. |

> [!NOTE]
> Le destinazioni di `obsidian_patch_note` accettano un `targetType` pari a `heading | block | frontmatter`
> e un'`operation` pari a `append | prepend | replace`, con un valore facoltativo
> `createTargetIfMissing`. I quattro strumenti `obsidian_sync_*` comunicano con il server di sincronizzazione
> locale (`http://127.0.0.1:27781` per impostazione predefinita) e richiedono il token di sincronizzazione.

### Ambiti

Gli strumenti di lettura richiedono `read:obsidian`; quelli di scrittura richiedono `write:obsidian`. L'applicazione
è identica a quella di Notion: viene gestita da `withScopeEnforcement()` in
`open-sse/mcp-server/server.ts`, subordinata a `OMNIROUTE_MCP_ENFORCE_SCOPES=true`, con
gli ambiti consentiti ricavati da `OMNIROUTE_MCP_SCOPES` o dal contesto degli ambiti della chiave API. Vedere
[MCP-SERVER.md](./MCP-SERVER.md).

## Endpoint

| Metodo   | Percorso                        | Scopo                                                                 |
| -------- | ------------------------------- | --------------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | Restituisce `{ connected, hasToken, baseUrl, vaultPath }`.            |
| `POST`   | `/api/settings/obsidian`        | Salva e convalida il token (rifiuta la porta `27124`).                |
| `DELETE` | `/api/settings/obsidian`        | Disconnette (cancella il token memorizzato).                          |
| `GET`    | `/api/settings/obsidian/webdav` | Stato della sincronizzazione WebDAV e credenziali (quando abilitata). |
| `POST`   | `/api/settings/obsidian/webdav` | Abilita la sincronizzazione WebDAV per una directory del vault.       |
| `DELETE` | `/api/settings/obsidian/webdav` | Disabilita la sincronizzazione WebDAV.                                |

> Queste sono route delle impostazioni della dashboard. Il vault stesso è raggiungibile tramite
> l'API REST locale di Obsidian (il `base_url` configurato) e tramite gli strumenti MCP indicati sopra:
> non esiste alcun endpoint proxy Obsidian `/v1` pubblico.

## Casi d'uso

- **Risposte basate sul vault** — `obsidian_search_simple` / `obsidian_search_structured`
  e poi `obsidian_read_note`, affinché un agente risponda sulla base delle tue note reali.
- **Creazione di note / journaling** — `obsidian_write_note`, `obsidian_append_note` oppure
  il preciso `obsidian_patch_note` per registrare nel vault l'output dell'agente, riepiloghi o note giornaliere
  (`obsidian_get_periodic_note`).
- **Navigazione nel vault** — `obsidian_list_vault`, `obsidian_get_document_map` e
  `obsidian_get_tags` per esplorare la struttura prima di leggere o scrivere.
- **Automazione di Obsidian** — `obsidian_list_commands` + `obsidian_execute_command` per
  eseguire plugin/comandi tramite un agente; `obsidian_open_file` per visualizzare una nota nell'interfaccia utente.
- **Sincronizzazione mobile** — abilita la sincronizzazione WebDAV, quindi usa `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  per coordinare desktop↔mobile e risolvere i conflitti.
