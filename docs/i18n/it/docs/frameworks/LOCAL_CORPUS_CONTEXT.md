## Che cos'è

Local Corpus consente a un operatore di rendere disponibile al server MCP di OmniRoute una directory di file di testo approvata esplicitamente. I file rimangono nella loro directory originale: OmniRoute memorizza in SQLite soltanto il percorso radice canonico e mantiene un indice di ricerca in memoria. Il contenuto del corpus non viene copiato nel repository né nel database.

L'aggiornamento dell'indice è incrementale. I file invariati vengono riutilizzati in base alle dimensioni e all'ora di modifica, quelli modificati vengono riletti e sottoposti a hashing con SHA-256, mentre quelli eliminati vengono rimossi. La ricerca aggiorna gli indici più vecchi di 30 secondi; i chiamanti possono inoltre richiedere un aggiornamento immediato.

## Configurare l'origine

La route delle impostazioni richiede la stessa autenticazione di gestione delle altre API delle impostazioni. Il percorso inviato deve già esistere e deve essere un percorso assoluto di una directory.

```bash
# Collega una directory approvata
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# Verifica la configurazione e lo stato dell'indice
curl http://localhost:20128/api/settings/local-corpus

# Disconnetti senza modificare i file di origine
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## Strumenti MCP

Tutti e tre gli strumenti richiedono `read:local-corpus`. Le risposte degli strumenti espongono i percorsi relativi e il nome di base della directory radice, mai il suo percorso assoluto.

| Strumento             | Descrizione                                                                                                       |
| :-------------------- | :---------------------------------------------------------------------------------------------------------------- |
| `local_corpus_status` | Riporta lo stato della configurazione, le dimensioni dell'indice, i limiti e l'ora dell'ultimo aggiornamento      |
| `local_corpus_search` | Cerca nel testo indicizzato e restituisce estratti con limiti e riferiti a righe specifiche (fino a 20 risultati) |
| `local_corpus_read`   | Legge un intervallo limitato di righe da un file consentito il cui percorso è relativo al corpus                  |

Esempi di input MCP:

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## Limiti di sicurezza

- L'elenco delle estensioni consentite è orientato al testo: `.cfg`, `.csv`, `.geojson`, `.htm`, `.html`, `.ini`,
  `.js`, `.json`, `.jsonl`, `.jsx`, `.log`, `.md`, `.mjs`, `.ps1`, `.py`, `.sh`,
  `.sql`, `.toml`, `.ts`, `.tsx`, `.txt`, `.xml`, `.yaml` e `.yml`.
- I collegamenti simbolici vengono ignorati. I percorsi di lettura vengono canonicalizzati e devono rimanere all'interno della
  radice configurata; i percorsi assoluti e i tentativi di attraversamento delle directory vengono rifiutati.
- I nomi di directory sensibili e generati vengono esclusi: `.build`, `.codex`, `.env`,
  `.git`, `.next`, `.omniroute`, `.ssh`, `coverage`, `dist`, `node_modules` e
  `secrets`.
- I limiti predefiniti sono 5.000 file, 1 MiB per file, 64 MiB complessivi di contenuto indicizzato,
  circa 4.000 caratteri per blocco di ricerca e 400 righe per lettura.
- I file contenenti caratteri NUL vengono considerati non testuali e ignorati o rifiutati.

I documenti binari, come PDF, DOCX, immagini e archivi, non sono intenzionalmente supportati.
Prima dell'indicizzazione, convertili in un formato di testo approvato all'interno della directory configurata.

## Note operative

- La modifica o l'eliminazione della radice configurata svuota l'indice condiviso in memoria.
- Il riavvio del processo elimina l'indice; la ricerca successiva lo ricostruisce a partire dall'origine
  configurata.
- `local_corpus_status` non forza una scansione. Usa `local_corpus_search` con
  `refresh: true` quando è necessaria una nuova scansione immediata.
- Gli errori di scansione e lettura vengono conteggiati o restituiti come errori sanificati; i file di origine non vengono
  mai modificati.
