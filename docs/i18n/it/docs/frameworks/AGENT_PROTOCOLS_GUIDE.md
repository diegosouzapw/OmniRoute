OmniRoute espone tre diverse interfacce relative agli agenti. A prima vista sembrano simili, ma risolvono problemi differenti. Usa questa pagina per scegliere quella giusta.

## In breve

| Interfaccia                   | Ideale per                                                                                                                                                   | Trasporto                          | Standard                    |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------- | --------------------------- |
| **A2A — Da agente ad agente** | Collaborazione tra agenti con agenti peer che supportano il protocollo A2A                                                                                   | JSON-RPC 2.0 tramite HTTP          | A2A v0.3 (specifica aperta) |
| **ACP — Registro agenti CLI** | Rilevamento / registrazione / avvio di agenti CLI di programmazione installati sul computer dell'utente (Cursor, Cline, Codex CLI, Claude Code, Aider, ecc.) | HTTP REST                          | Specifico di OmniRoute      |
| **Agenti cloud**              | Invio di attività di programmazione di lunga durata a servizi cloud esterni (Codex Cloud, Devin, Jules, Cursor Cloud)                                        | HTTP REST + attività salvate in DB | Specifico di OmniRoute      |

Le tre interfacce sono indipendenti: puoi sceglierne qualsiasi combinazione.

## Albero decisionale

```
Hai bisogno di un servizio cloud che svolga del lavoro al di fuori di questo computer (Codex Cloud / Cursor Cloud / Devin / Jules)?
├─ SÌ → Agenti cloud (POST /api/v1/agents/tasks)
└─ NO → Continua
    │
    Hai un agente peer che supporta A2A e vuole collaborare?
    ├─ SÌ → A2A (POST /a2a)
    └─ NO → Continua
        │
        Devi elencare / configurare gli agenti CLI di programmazione installati localmente?
        ├─ SÌ → ACP (GET /api/acp/agents)
        └─ NO → Usa semplicemente /v1/chat/completions
```

## 1. A2A — Da agente ad agente

**Specifica:** [A2A v0.3](https://a2a-protocol.org)
**Endpoint OmniRoute:** `POST /a2a` (JSON-RPC 2.0)
**Scheda agente:** `GET /.well-known/agent.json`

### Quando usarlo

- Creazione di un sistema multi-agente in cui OmniRoute è uno dei peer
- Esposizione dell'intelligenza di routing di OmniRoute (routing intelligente, gestione delle quote, ecc.) ad agenti in framework come Google ADK o in reti generiche di agenti
- Integrazione di OmniRoute dietro un'interfaccia standard di rilevamento e invocazione

### Metodi

- `message/send` — invia un messaggio e riceve una risposta sincrona
- `message/stream` — invia un messaggio e riceve eventi di avanzamento tramite streaming SSE
- `tasks/get` — legge un'attività tramite ID
- `tasks/cancel` — annulla un'attività in esecuzione

### Funzionalità integrate (6)

- `smart-routing` — instrada un prompt tramite la combinazione ottimale
- `quota-management` — segnala lo stato delle quote per ciascun provider
- `provider-discovery` — elenca i provider installati e le relative funzionalità
- `cost-analysis` — stima il costo di una richiesta/conversazione
- `health-report` — aggrega lo stato di breaker/cooldown/lockout per ciascun provider
- `list-capabilities` — elenca le funzionalità disponibili dell'agente e i relativi metadati

### Approfondimento

Consulta [A2A-SERVER.md](./A2A-SERVER.md) per i dettagli sul trasporto, la struttura della scheda agente, la configurazione del TTL delle attività e il modello per aggiungere nuove funzionalità.

## 2. ACP — Registro degli agenti CLI

**Endpoint OmniRoute:** `GET /api/acp/agents`
**Origine:** `src/lib/acp/{index,manager,registry}.ts`

### Che cos'è

ACP è l'**inventario locale degli agenti CLI** di OmniRoute. Rileva quali CLI di programmazione sono installate sull'host (Cursor, Cline, Claude Code, Codex CLI, Continue, ecc.), ne determina le versioni e le rende disponibili nella dashboard, in modo che l'utente possa configurare ciascuna CLI affinché punti a OmniRoute.

Questo NON è un protocollo esterno: è un registro interno che alimenta l'interfaccia utente "CLI Tools" e il monitoraggio delle impronte digitali delle CLI (vedere [CLI-TOOLS.md](../reference/CLI-TOOLS.md)).

### Cosa fa

- Esamina l'host alla ricerca dei binari CLI installati (utilizza `which` / `where` a seconda del sistema operativo)
- Legge la versione di ciascuna CLI (esegue `<bin> --version`)
- Accetta facoltativamente agenti personalizzati definiti dall'utente (percorso del binario + verifica della versione + argomenti di avvio)
- Salva gli agenti personalizzati nelle impostazioni
- Restituisce l'elenco unificato alla dashboard

### API REST

| Endpoint          | Metodo | Descrizione                                                                       | Autenticazione |
| ----------------- | ------ | --------------------------------------------------------------------------------- | -------------- |
| `/api/acp/agents` | GET    | Elenca gli agenti rilevati + personalizzati (conteggi installati/totali)          | Chiave API     |
| `/api/acp/agents` | POST   | Aggiunge/aggiorna/rimuove un agente personalizzato (azione specificata nel corpo) | Chiave API     |

Struttura del corpo per POST (`customAgentBodySchema` in `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Casi d'uso

- La pagina "CLI Tools" della dashboard elenca ciò che è installato e aiuta a configurare ogni strumento affinché punti a OmniRoute
- Gli agenti personalizzati consentono agli utenti esperti di registrare CLI interne/proprietarie che OmniRoute non riconosce per impostazione predefinita
- Il risultato del rilevamento alimenta la matrice delle impronte digitali `cli-tools`

### Quando NON utilizzare ACP

- ACP non _esegue_ attività. Rileva e configura soltanto le CLI. Per richiamare effettivamente una CLI, è necessario avviarla autonomamente con le variabili d'ambiente fornite da OmniRoute (`OPENAI_BASE_URL`, `OPENAI_API_KEY`, ecc.).

## 3. Agenti cloud

**Endpoint OmniRoute:** `/api/v1/agents/tasks/*` (ciclo di vita) + `/api/cloud/*` (infrastruttura)
**Origine:** `src/lib/cloudAgent/`

### Che cos'è

Un'interfaccia uniforme per agenti di programmazione cloud di terze parti. Si inviano un prompt + l'URL di un repository; OmniRoute inoltra la richiesta all'agente cloud appropriato, verifica periodicamente lo stato e restituisce i risultati.

### Agenti supportati (4, tutti confermati in `src/lib/cloudAgent/agents/`)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### Ciclo di vita

```
POST /api/v1/agents/tasks
  → BaseAgent.createTask() per ciascuna classe di agente
  → il servizio esterno avvia il lavoro
  → viene creata una riga dell'attività nel DB (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → sincronizzazione differita dello stato dal provider
  → restituisce lo stato corrente + il piano + il registro delle attività
  ↓
POST /api/v1/agents/tasks/[id]   (azione: "approve" | "message" | "cancel")
  → inoltra al provider (oppure contrassegna localmente come annullata)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → annullamento locale
```

### Autenticazione

⚠️ **Tutti gli endpoint `/api/v1/agents/tasks/*` richiedono l'autenticazione di gestione** (commit `588a0333`). I client che utilizzano solo Bearer ricevono un errore 401 a partire dalla versione v3.8.0.

### Approfondimento

Consultare [CLOUD_AGENT.md](./CLOUD_AGENT.md) per il contratto `CloudAgentBase`, i dettagli specifici di ciascun agente, i dettagli dello schema e gli endpoint per la gestione delle credenziali.

## Confronto: A2A vs Cloud Agents

Entrambi prevedono "attività di lunga durata", ma a livelli diversi:

| Aspetto                       | A2A                                                                                 | Cloud Agents                                             |
| ----------------------------- | ----------------------------------------------------------------------------------- | -------------------------------------------------------- |
| Standard                      | Open A2A v0.3                                                                       | Specifico di OmniRoute                                   |
| Dove avviene l'elaborazione   | All'interno di OmniRoute (utilizza le combinazioni configurate)                     | All'esterno (server Codex / Devin / Jules)               |
| Durata dell'attività          | TTL predefinito di 5 min (configurabile in `TaskManager`)                           | Da minuti a ore                                          |
| Consapevolezza del repository | No (passa solo i prompt)                                                            | Sì (URL del repository + branch)                         |
| Caso d'uso                    | Collaborazione tra agenti, routing intelligente come servizio                       | Delegare "implementa la funzionalità X nel repository Y" |
| Autenticazione                | `OMNIROUTE_API_KEY` opzionale per `/a2a`; gestione per gli helper REST `/api/a2a/*` | Sempre tramite gestione                                  |

## Esempi di integrazione

### Scoprire le funzionalità A2A di OmniRoute

```bash
curl http://localhost:20128/.well-known/agent.json
```

Restituisce la scheda dell'agente con tutte e 6 le skill, i trasporti e la versione.

### Chiamare OmniRoute come agente A2A

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Instrada questo prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### Elencare gli agenti CLI installati tramite ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Aggiungere un agente CLI personalizzato

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### Inviare un'attività a Cloud Agent

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### Verificare lo stato dell'attività cloud

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## Quale usare e quando

- **Frontend per chatbot / copilot** → `/v1/chat/completions` (compatibile con OpenAI — non è un protocollo per agenti)
- **Collaborazione multi-agente** → A2A
- **Elenco delle CLI locali nella dashboard** → ACP
- **Delega di attività di programmazione di lunga durata a servizi cloud** → Cloud Agents
