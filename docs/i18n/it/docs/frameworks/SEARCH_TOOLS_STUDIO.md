## Panoramica

Search Tools Studio trasforma `/dashboard/search-tools` da un semplice ambiente di prova per la ricerca in uno
Studio a tre schede che unifica ricerca web, web scraping e confronto affiancato tra provider.

```
┌ Strumenti di ricerca ──────────────────────────────────────────────────┐
│ [🔍 Ricerca] [📄 Scraping] [⚖ Confronto]        142ms · $0.001  </>    │
│ ⓘ [Guida alle modalità]                                                │
├──────────────────────────────────────────┬─────────────────────────────┤
│  {contenuto della scheda attiva}         │ ─ Configurazione            │
│                                          │ Provider [auto ∨]           │
│                                          │   🟢 Serper  $0.001         │
│                                          │   🟢 Tavily  $0.008         │
│                                          │   🔥 Firecrawl (recupero)   │
│                                          │ Tipo   [web | notizie]      │
│                                          │ Pagina intera [ ] (scraping)│
│                                          │ Formato [md|testo|html]     │
│                                          │ Modello rerank [∨]          │
└──────────────────────────────────────────┴─────────────────────────────┘
```

## Schede

### Scheda Ricerca

Trasforma gli attuali `SearchForm` + `ResultsPanel` + `RerankPanel` in una scheda:

- Query → risultati (titolo, URL, snippet, punteggio di rilevanza).
- Metadati del provider nel pannello Configurazione (costo, quota, stato).
- Sezione di rerank: selezione di un modello di rerank, riordinamento dei risultati, visualizzazione di `positionDelta`.
- Stato vuoto con CTA quando non è configurato alcun provider di ricerca.
- Cronologia delle ricerche tramite `SearchHistory.tsx`.
- Chiama `POST /v1/search` (endpoint esistente, nessuna modifica).

### Scheda Scraping

Nuova scheda per estrarre contenuti da un URL tramite `POST /v1/web/fetch` (creato nel piano 05):

- Input: URL + interruttore per la pagina intera + selettore del formato (markdown / testo / HTML).
- Invio → recupero → rendering di `ScrapeResult.tsx`.
- `ScrapeResult` mostra l'anteprima markdown e un interruttore per i dati grezzi.
- Limite: se il corpo della risposta supera **256 KB**, l'interfaccia mostra `(troncato, visualizza dati grezzi)` e apre i dati grezzi in una finestra modale Monaco (D21).
- Pannello dei metadati: provider (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search), latenza, costo, dimensione della risposta, numero di link.
- Utilizza l'hook `useScrapeFetch.ts`.

### Scheda Confronto

Esegue la stessa query o lo stesso URL su un massimo di **4 provider in parallelo** (D22):

- Colonne affiancate per ciascun provider.
- Metriche: latenza, costo, numero di risultati, dimensione della risposta.
- Calcolo della sovrapposizione degli URL per la ricerca (numero di URL condivisi rispetto al risultato iniziale).
- Chiama `POST /v1/search` (ricerca) o `POST /v1/web/fetch` (scraping) per ciascun provider.

## Pannello Configurazione (condiviso)

`SearchToolsConfigPane.tsx` — sempre visibile e comprimibile.

| Campo          | Note                                                                                             |
| -------------- | ------------------------------------------------------------------------------------------------ |
| Provider       | Menu a discesa con badge di stato (configurato / mancante / limite raggiunto)                    |
| Tipo           | `web` o `news` (solo ricerca)                                                                    |
| Pagina intera  | Interruttore per lo scraping — recupera l'intera pagina anziché solo il primo contenuto visibile |
| Formato        | `markdown`, `text` o `html` (solo scraping)                                                      |
| Modello rerank | Modello facoltativo per il reranking successivo alla ricerca                                     |
| Cronologia     | Sezione comprimibile della cronologia delle ricerche                                             |

---

## SearchConceptCard

`SearchConceptCard.tsx` — sempre visibile, pannello a fisarmonica comprimibile. Spiega:

| Concetto                       | Descrizione breve                                                                   |
| ------------------------------ | ----------------------------------------------------------------------------------- |
| **Ricerca**                    | Recupera un elenco di risultati web (titolo, URL, estratto, punteggio di rilevanza) |
| **Scraping**                   | Estrae il contenuto completo di un URL (markdown, testo o HTML)                     |
| **Confronto**                  | Esegue la stessa query su N provider affiancati                                     |
| **Riordinamento**              | Riordina i risultati tramite LLM per migliorare la rilevanza rispetto alla query    |
| **Automatico (più economico)** | Seleziona automaticamente il provider disponibile più economico                     |

## Catalogo dei provider

`ProviderCatalog.tsx` espone l'elenco completo dei provider da `GET /api/search/providers`
(esteso in F4 per includere i provider di recupero):

| `kind` | `"search"` (20 provider) o `"fetch"` (firecrawl, jina-reader, tavily-search, tinyfish, nimble-search, anysearch-search) |

Lo stato viene **derivato al momento della richiesta** verificando se esistono credenziali e se
tutte le chiavi sono attualmente in cooldown.

## Esportazione del codice

`ExportCodeModal` (importato da Playground Studio) + `codeExport.ts` generano
snippet curl / Python / TypeScript per le chiamate sia a `/v1/search` sia a `/v1/web/fetch`.
Il segnaposto della chiave API è sempre `$OMNIROUTE_API_KEY` (D11, condiviso con Playground Studio).

---

## Modifiche al backend

Per questa funzionalità è stata necessaria una sola modifica al backend:

### Estensione di `GET /api/search/providers`

`src/app/api/search/providers/route.ts` è stato esteso per:

- Includere nell'array tutti e 6 i provider di recupero (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`).
- Aggiungere `kind: "search" | "fetch"` a ogni elemento.
- Aggiungere `status: "configured" | "missing" | "rate_limited"`, derivato dallo stato corrente delle credenziali.
- Mantenere la compatibilità con le versioni precedenti — i campi esistenti (`id`, `name`, ecc.) rimangono invariati.

## Risoluzione dei problemi

| Sintomo                                                                 | Causa                         | Soluzione                                                                                                                |
| ----------------------------------------------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| La scheda Scrape mostra "endpoint non disponibile"                      | `/v1/web/fetch` non collegato | Verificare che il piano 05 sia stato integrato; controllare che `src/app/api/v1/web/fetch/route.ts` esista               |
| Il catalogo dei provider li mostra tutti come "mancanti"                | Credenziali non configurate   | Aggiungere le credenziali in `/dashboard/providers`                                                                      |
| Il contenuto dello scraping è troncato                                  | Risposta > limite di 256 KB   | Comportamento previsto (D21). Usare il pulsante "visualizza dati grezzi" per il contenuto completo                       |
| La scheda Confronta mostra solo 2 provider                              | Limite di richieste attivo    | Due o più provider potrebbero essere in pausa temporanea — controllare lo stato dei provider nel pannello Configurazione |
| "Dimensione" viene visualizzato come chiave non elaborata nella tabella | Chiave i18n mancante          | Verificare che `search.size` esista nel file delle impostazioni locali; ricompilare i18n                                 |
