## Passaggio 1: installa OmniRoute

Scegli il metodo che preferisci:

### Opzione A: npm (consigliata)

```bash
npm install -g omniroute
```

### Opzione B: Docker

```bash
docker run -d --name omniroute -p 20128:20128 diegosouzapw/omniroute:latest
```

`:latest` corrisponde alla versione stabile SemVer **pubblicata** più recente. **Non** segue il branch git `main`. Per GitOps, fissa la versione con `diegosouzapw/omniroute:X.Y.Z`. Consulta [Tag delle immagini / Canali di rilascio](../guides/DOCKER_GUIDE.md#release-channels).

### Opzione C: dal codice sorgente

```bash
git clone https://github.com/diegosouzapw/OmniRoute.git
cd OmniRoute
npm install
npm run dev
```

---

## Passaggio 2: avvia OmniRoute

```bash
omniroute
```

OmniRoute si avvia all'indirizzo `http://localhost:20128`. La dashboard si apre automaticamente.

---

## Passaggio 3: connetti un provider gratuito

Puoi usare OmniRoute **senza pagare nulla** connettendo un provider gratuito.

### Opzione A: Kiro (Claude gratuito — nessuna carta di credito)

1. Apri la dashboard all'indirizzo `http://localhost:20128`
2. Vai su **Provider** → **Aggiungi provider**
3. Seleziona **Kiro AI**
4. Fai clic su **Connetti** (non è necessaria alcuna chiave API!)
5. Fatto! Ora hai accesso gratuito ai modelli Claude.

### Opzione B: OpenCode Free (nessuna autenticazione)

1. Apri la dashboard all'indirizzo `http://localhost:20128`
2. Vai su **Provider** → **Aggiungi provider**
3. Seleziona **OpenCode Free**
4. Fai clic su **Connetti** (non è necessaria alcuna chiave API!)
5. Fatto! Ora hai accesso gratuito a più modelli.

### Opzione C: Pollinations (nessuna chiave necessaria)

1. Apri la dashboard all'indirizzo `http://localhost:20128`
2. Vai su **Provider** → **Aggiungi provider**
3. Seleziona **Pollinations**
4. Fai clic su **Connetti** (non è necessaria alcuna chiave API!)
5. Fatto! Ora hai accesso gratuito a GPT-5, Claude, Gemini e altri modelli.

## Passaggio 4: verifica che funzioni

Da [Chiavi API](http://localhost:20128/dashboard/api-manager), crea una nuova chiave. Conservala, perché non verrà mostrata di nuovo. Tieni presente che questa chiave serve agli strumenti per accedere a OmniRoute, non per accedere ai provider upstream.

```bash
curl http://localhost:20128/v1/models -H "Authorization: Bearer YOUR_KEY"
```

Dovresti vedere l'elenco dei modelli connessi.

## Passaggio 5: configura il tuo IDE o strumento CLI affinché usi OmniRoute

Nel tuo IDE o strumento CLI, imposta:

```
URL di base: http://localhost:20128/v1
Chiave API:  [copia dalla Dashboard → Endpoint]
Modello:     auto
```

Ecco fatto! Ora il tuo IDE utilizza OmniRoute con la selezione automatica del provider.

### Esempio per IDE: VSCode/Continue.dev

1. In VSCode, installa l'estensione [Continue.dev](https://marketplace.visualstudio.com/items?itemName=Continue.continue).
2. Aggiorna `~/.continue/config.yaml` aggiungendo le seguenti righe:

```
  - name: OmniRoute - Auto
    provider: openai
    model: auto
    apiBase: http://localhost:20128/v1
    apiKey: <YOUR_KEY>
```

3. Nel pannello di chat di Continue.dev, seleziona `OmniRoute - Auto` per inviare richieste a OmniRoute.
4. (Facoltativo) Esercizio per il lettore: chiedi al tuo IDE di aggiornare `config.yaml` con tutte le altre configurazioni predefinite 😊

### Esempio CLI: Codex CLI

1. Nel tuo sistema operativo, imposta la variabile d'ambiente in modo permanente.
   Per macOS/Linux (aggiungila a `~/.bashrc` o `~/.zshrc`):

```bash
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

Per Windows (Prompt dei comandi):

```
setx OMNIROUTE_API_KEY <YOUR_KEY>
```

2. Ora avviamo Codex configurato per OmniRoute. Esegui:

```
omniroute launch-codex --model auto
```

Puoi farlo manualmente tramite `codex` e i parametri della riga di comando per specificare l'endpoint e la chiave API, ma con il comando precedente OmniRoute si occupa di tutto al posto tuo.

La stessa modalità di avvio con un solo comando funziona per altre CLI tramite il launcher generico: `omniroute run <target>` supporta `claude`, `codex`, `aider`, `goose`, `opencode`, `qwen` e `gemini` (consulta [Integrazioni CLI](../guides/CLI-INTEGRATIONS.md)).

3. Ora la CLI dovrebbe inviare le richieste a OmniRoute.

### Verifica che il tuo strumento instradi le richieste verso OmniRoute

Puoi visualizzare i dettagli della richiesta facendo clic su [Monitoraggio/Log](http://localhost:20128/dashboard/logs) nella barra laterale sinistra. Facendo clic sui vari elementi puoi visualizzare ulteriori dettagli. Come nota a margine, puoi vedere quali informazioni vengono inviate dal tuo harness preferito. Ciò è utile a scopo didattico e di debug.

## Domande frequenti

### "Ho bisogno di una chiave API?"

**No!** Puoi usare provider gratuiti (Kiro, OpenCode Free, Pollinations) senza alcuna chiave API. Ti basta connetterli dalla dashboard.

### "Che cos'è `auto`?"

`auto` indica a OmniRoute di scegliere automaticamente il provider migliore per ogni richiesta. Tiene conto di velocità, costo, qualità e disponibilità. Per maggiori dettagli, consulta la [Guida ad Auto-Combo](./AUTO-COMBO-GUIDE.md).

### "Quanto costa?"

OmniRoute è **gratuito e open source**. Paghi solo per i provider che utilizzi. Molti provider dispongono di piani gratuiti: consulta la [Guida ai piani gratuiti](./FREE-TIERS-GUIDE.md).

### "Posso usarlo con Claude Code / Cursor / Copilot?"

**Sì!** OmniRoute funziona con qualsiasi strumento che supporti il formato OpenAI. È sufficiente impostare l'URL di base su `http://localhost:20128/v1`. Per istruzioni specifiche sulla configurazione, consulta la [Guida agli strumenti CLI](../reference/CLI-TOOLS.md).

### "Cosa succede se un provider non è disponibile?"

OmniRoute ignora automaticamente i provider che non funzionano e prova quello successivo. Non devi fare nulla. Per maggiori dettagli, consulta la [Guida ad Auto-Combo](./AUTO-COMBO-GUIDE.md).
