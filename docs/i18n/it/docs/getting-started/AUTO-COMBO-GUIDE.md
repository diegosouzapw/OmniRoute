---

## Cosa fa

Invece di scegliere uno specifico modello di IA (come GPT-4o o Claude), puoi lasciare che OmniRoute **scelga automaticamente quello migliore** per ogni richiesta. Prende in considerazione:

- **Stato operativo** — Il provider funziona in questo momento?
- **Velocità** — Quanto è veloce?
- **Costo** — Quanto costa?
- **Qualità** — È adatto a questo tipo di attività?
- **Capacità** — Ha ancora quota disponibile?

OmniRoute assegna un punteggio a tutti i provider connessi e sceglie quello migliore. Se non funziona, prova automaticamente quello successivo.

---

## Avvio rapido

**Passaggio 1**: Imposta il modello su `auto` nel tuo IDE o nella tua CLI:

```
model: "auto"
```

**Passaggio 2**: Tutto qui! OmniRoute si occupa del resto.

**Passaggio 3** (facoltativo): Usa una variante per attività specifiche:

```
model: "auto/coding"    # Ideale per il codice
model: "auto/fast"      # Risposta più rapida
model: "auto/cheap"     # Opzione più economica
```

## Quale "auto" dovrei usare?

| Se desideri...                  | Usa questo     | Ideale per                           | Come funziona                                  |
| ------------------------------- | -------------- | ------------------------------------ | ---------------------------------------------- |
| **Il migliore in generale**     | `auto`         | Domande generiche, chat              | Bilancia velocità, costo e qualità             |
| **Il migliore per il codice**   | `auto/coding`  | Scrittura di codice, debug           | Sceglie modelli adatti alle attività di coding |
| **La risposta più rapida**      | `auto/fast`    | Risposte rapide, bassa latenza       | Dà priorità assoluta alla velocità             |
| **L'opzione più economica**     | `auto/cheap`   | Risparmiare                          | Sceglie il provider più economico              |
| **Il modello più intelligente** | `auto/smart`   | Attività complesse                   | Privilegia la qualità + esplora nuovi modelli  |
| **La massima disponibilità**    | `auto/offline` | Quando i provider sono sovraccarichi | Sceglie i provider con maggiore capacità       |

### Esempi

```bash
# Chat generica — bilanciata
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'

# Generazione di codice — priorità alla qualità
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/coding","messages":[{"role":"user","content":"Write a Python function"}]}'

# Risposta rapida — priorità alla velocità
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/fast","messages":[{"role":"user","content":"What is 2+2?"}]}'
```

## Come funziona (versione semplificata)

Quando invii una richiesta con `model: "auto"`, OmniRoute:

1. **Esamina tutti i provider connessi** — Ogni provider che hai aggiunto (OpenAI, Anthropic, Google, ecc.)
2. **Assegna un punteggio a ciascuno**, valutando, tra le altre cose:
   - Funziona? (stato operativo)
   - Ha capacità disponibile? (quota)
   - Quanto costa? (prezzo)
   - Quanto è veloce? (velocità)
   - È adatto a questa attività? (qualità)
3. **Sceglie quello migliore** — Il provider con il punteggio più alto riceve la tua richiesta
4. **Esegue il ripristino automatico** — Se non funziona, OmniRoute prova automaticamente quello successivo

### Il sistema di punteggio

Ogni provider riceve un punteggio da 0 a 1. Più alto è il punteggio, più il provider è adatto.

| Fattore               | Peso | Cosa significa                                         |
| --------------------- | ---- | ------------------------------------------------------ |
| Stato operativo       | 20%  | Il provider funziona? (stato del circuit breaker)      |
| Quota                 | 15%  | Ha ancora capacità disponibile?                        |
| Costo                 | 15%  | Quanto è costoso? (più economico = punteggio più alto) |
| Velocità              | 12%  | Quanto è veloce? (minore latenza = punteggio più alto) |
| Idoneità all'attività | 8%   | È adatto a questo tipo di attività?                    |
| Stabilità             | 5%   | È affidabile? (basso tasso di errore)                  |
| Livello               | 5%   | Livello dell'account (Ultra > Pro > Free)              |
| Altro                 | 20%  | Affinità di contesto, densità delle connessioni, ecc.  |

### Come le varianti modificano il punteggio

Ogni variante utilizza pesi diversi:

| Variante       | Dà priorità a          | Pesi principali                 |
| -------------- | ---------------------- | ------------------------------- |
| `auto`         | Bilanciamento          | health=20%, quota=15%, cost=15% |
| `auto/coding`  | Qualità                | taskFit=37%, stability=15%      |
| `auto/fast`    | Velocità               | latency=32%, health=28%         |
| `auto/cheap`   | Costo                  | cost=37%                        |
| `auto/smart`   | Qualità + esplorazione | taskFit=37%, exploration=10%    |
| `auto/offline` | Capacità               | quota=37%, health=28%           |

## Come gestisce gli errori

OmniRoute dispone di **tre livelli di protezione**:

### 1. Fallback automatico

Se il provider migliore non risponde, OmniRoute prova automaticamente quello successivo. Non devi fare nulla.

### 2. Ripristino automatico

Se un provider continua a non rispondere:

- **Punteggio < 0.2** → Escluso per 5 minuti
- **Circuit breaker aperto** → Escluso automaticamente
- **Più del 50% dei provider non disponibili** → Modalità incidente (nessuna esplorazione)

### 3. Fallback di emergenza

Se tutti i provider non rispondono, come ultima risorsa OmniRoute instrada le richieste verso provider gratuiti e stabili, come Kiro o Qoder.

---

## Supporto multi-account

Se disponi di più account per lo stesso provider (ad esempio, due chiavi OpenAI), OmniRoute considera ciascuno di essi come un **candidato separato**. Ciò significa:

- L'account A dispone ancora di quota → usalo
- L'account B è soggetto a limitazione della frequenza → ignoralo
- L'account C è più economico → preferiscilo

Ogni account riceve un punteggio indipendente in base al proprio stato, alla quota e alla velocità.

---

## Esplorazione bandit

Occasionalmente OmniRoute **esplora** nuovi provider per individuare opzioni migliori:

- **Predefinita**: il 5% delle richieste viene inviato a provider casuali
- **Auto/smart**: tasso di esplorazione del 10%
- **Disabilitata** quando più del 50% dei provider presenta problemi

Questo consente a OmniRoute di determinare quali provider funzionano meglio per i tuoi modelli di utilizzo.

## Domande frequenti

### "Sceglierà sempre il modello più costoso?"

**No.** Per impostazione predefinita, il costo rappresenta solo il 15% del punteggio. Un provider economico, veloce e affidabile può superarne uno costoso. Usa `auto/cheap` se vuoi dare ancora più priorità al costo.

### "Cosa succede se un provider non è disponibile?"

OmniRoute lo ignora automaticamente e prova quello successivo. Se un provider continua a non rispondere, viene escluso temporaneamente (per 5-30 minuti). Non devi fare nulla.

### "Posso vedere quale provider è stato utilizzato?"

Controlla gli header della risposta: OmniRoute include in ogni risposta il provider e il modello utilizzati.

### "Impara dal mio utilizzo?"

Sì! Il sistema di assegnazione del punteggio usa i dati storici (latenza, tassi di errore e percentuali di successo) per prendere decisioni migliori nel tempo.

### "Qual è la differenza tra `auto` e `auto/smart`?"

- `auto` — Bilanciato, 5% di esplorazione
- `auto/smart` — Priorità alla qualità (stessi pesi di `auto/coding`), 10% di esplorazione

Usa `auto/smart` quando desideri la qualità migliore e accetti esplorazioni occasionali.

### "Posso imporre un provider specifico?"

Sì! Usa una combinazione con strategia `priority` anziché `auto`, quindi invia il **nome esatto** della combinazione come campo `model` (ad esempio, `model: "my-combo"` — non `auto`). Per maggiori dettagli, consulta il [Riferimento tecnico](../routing/AUTO-COMBO.md).

### "In cosa differisce dal round-robin?"

Il round-robin alterna ciclicamente i provider in ordine. Auto-combo **assegna un punteggio a ogni provider** e sceglie quello migliore. È più intelligente: considera stato, velocità, costo e qualità.
