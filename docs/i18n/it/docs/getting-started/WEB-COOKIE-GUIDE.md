I provider Web Cookie consentono a OmniRoute di utilizzare un servizio di IA tramite la sessione esistente del browser anziché tramite una chiave API. Sono utili quando disponi già dell'accesso a un servizio attraverso il relativo sito web e vuoi che OmniRoute utilizzi la stessa sessione autenticata.

A differenza dei provider con chiave API, i provider Web Cookie eseguono l'autenticazione utilizzando le credenziali che il browser invia al sito web.

---

# Prima di iniziare

> **Importante:** copia sempre le credenziali da una **richiesta di rete attiva**, **non** dall'archivio dei cookie del browser.

Molti problemi di autenticazione sono causati dalla copia dei cookie dalla posizione sbagliata.

## NON copiare dall'archivio dei cookie

La maggior parte dei browser espone i cookie memorizzati tramite:

```
Strumenti per sviluppatori
→ Applicazione (o Archiviazione)
→ Cookie
```

Anche se questi cookie sembrano corretti, potrebbero essere:

- obsoleti
- incompleti
- privi di cookie inviati solo nelle richieste autenticate

L'utilizzo di questi valori può causare errori di autenticazione anche se sembrano validi.

## Copiare da una richiesta attiva

Utilizza invece i cookie di una richiesta completata correttamente:

```
Strumenti per sviluppatori
→ Rete
→ Aggiorna la pagina
→ Apri una richiesta di chat o conversazione
→ Header della richiesta
→ Cookie
```

L'header della richiesta `Cookie` contiene le informazioni di autenticazione esatte utilizzate correttamente dal browser.

Per la maggior parte dei provider Web Cookie, questo è il valore da incollare in OmniRoute.

---

# Configurazione generale

Il processo di configurazione è lo stesso per la maggior parte dei provider Web Cookie.

1. Accedi al sito web del provider.
2. Apri gli Strumenti per sviluppatori del browser.
3. Apri la scheda **Rete**.
4. Aggiorna la pagina.
5. Apri una richiesta autenticata di chat o conversazione.
6. Copia le credenziali di autenticazione richieste.
7. Apri OmniRoute.
8. Vai a **Provider → Aggiungi provider**.
9. Seleziona il tuo provider Web Cookie.
10. Incolla le credenziali.
11. Fai clic su **Verifica connessione**.
12. Salva il provider.

Le credenziali esatte richieste dipendono dal provider.

# Cosa possono e non possono fare i provider Web Cookie

I provider Web Cookie riutilizzano l'interfaccia di chat di un sito web. **Non** offrono le stesse funzionalità delle API ufficiali.

## Funzionalità supportate

- Autenticazione tramite la sessione esistente del browser
- Accesso ai modelli disponibili tramite il tuo account
- Streaming delle risposte della chat
- Nessuna chiave API richiesta

## Funzionalità non supportate

- Chiamata di funzioni
- Chiamata di strumenti
- Modifica automatica dei file
- Flussi di lavoro agentici negli IDE
- Funzionalità disponibili solo tramite API

Questo è il comportamento previsto e **non** è un bug.

Se hai bisogno dell'esecuzione di strumenti, della modifica automatica dei file o di altri flussi di lavoro basati su agenti, utilizza un **provider con chiave API** anziché un provider Web Cookie.

---

# Avvertenza sulla convalida

Il completamento corretto di **Verifica connessione** o della convalida dei cookie verifica soltanto che le credenziali fornite sembrino essere nel formato previsto.

Finché il problema #7857 non sarà risolto, una convalida completata correttamente **non garantisce** che il provider riesca ad autenticarsi.

Se l'autenticazione continua a non riuscire, verifica di aver copiato le credenziali da una richiesta di rete attiva anziché dall'archivio dei cookie del browser.

---

# Risoluzione dei problemi

## Autenticazione non riuscita

Verifica che le credenziali siano state copiate da:

```
Rete
→ Header della richiesta
→ Cookie
```

e **non** da:

```
Applicazione
→ Cookie
```

---

## Il cookie funziona nel browser ma non in OmniRoute

Alcuni provider includono cookie che vengono inviati solo durante le richieste autenticate.

Copia nuovamente le credenziali da una nuova richiesta di rete dopo aver aperto correttamente una conversazione.

---

## Sessione scaduta

I provider Web Cookie utilizzano la sessione esistente del browser.

Se la sessione del browser scade o esegui la disconnessione, devi copiare un nuovo set di credenziali.

---

## Verifica connessione riesce, ma le richieste non vanno a buon fine

Finché il problema #7857 non sarà risolto, il superamento della convalida non garantisce che la richiesta di autenticazione vada a buon fine.

Prima di proseguire con la risoluzione dei problemi, copia nuovamente le credenziali da una nuova richiesta autenticata.

# Procedure consigliate

- Copia le credenziali da una nuova richiesta autenticata.
- Evita di riutilizzare cookie obsoleti.
- Mantieni attiva la sessione del browser mentre utilizzi i provider Web Cookie.
- Tratta i cookie copiati come credenziali sensibili.
- Utilizza provider con chiave API quando hai bisogno della chiamata di funzioni o di flussi di lavoro basati su agenti.
