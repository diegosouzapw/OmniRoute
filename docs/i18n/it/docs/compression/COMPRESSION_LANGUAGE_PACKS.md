La compressione Caveman può caricare pacchetti di regole specifici per lingua oltre alle regole inglesi integrate.
Ciò mantiene stabile il motore principale, consentendo al contempo ai pacchetti per portoghese, spagnolo, tedesco, francese, italiano, giapponese e
per le lingue future di evolversi in modo indipendente.

## Posizione

I pacchetti linguistici si trovano in:

```txt
open-sse/services/compression/rules/<language>/
```

Pacchetti attualmente distribuiti (verificati rispetto al contenuto della directory `rules/`):

| Lingua               | Directory      | Categorie di regole presenti                        |
| -------------------- | -------------- | --------------------------------------------------- |
| Inglese              | `rules/en/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Spagnolo             | `rules/es/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Portoghese (Brasile) | `rules/pt-BR/` | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Indonesiano          | `rules/id/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Italiano             | `rules/it/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Tedesco              | `rules/de/`    | `context`, `filler`, `structural`                   |
| Francese             | `rules/fr/`    | `context`, `filler`, `structural`                   |
| Giapponese           | `rules/ja/`    | `context`, `filler`, `structural`                   |

> **Nota sulla parità:** i pacchetti `en`, `es`, `pt-BR`, `id` e `it` includono tutte e 5 le categorie; `de`, `fr` e `ja` ne distribuiscono 3. Per le categorie `dedup` e `ultra` mancanti vengono utilizzate automaticamente le regole inglesi integrate. I contributi per aggiungere `dedup.json` e `ultra.json` ai pacchetti più piccoli sono benvenuti.
>
> Il pacchetto `pt-BR` si basa su **[Troglodita](https://github.com/leninejunior/troglodita)** di Lenine Júnior, un sistema di compressione progettato da zero per la grammatica del portoghese brasiliano (riduzione dei pleonasmi, rimozione dei riempitivi PT-BR, abbreviazioni tecniche per la comunità brasiliana di sviluppatori).
>
> L'elenco canonico delle categorie e lo schema di ciascuna categoria si trovano in [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) (JSON Schema bozza 2020-12).

## Rilevamento della lingua

`languageDetector.ts` utilizza euristiche leggere per dedurre la lingua dal testo del prompt. La
lingua predefinita configurata viene comunque rispettata e il rilevamento può essere disabilitato tramite la configurazione quando è richiesto un
controllo preciso.

Il risultato del rilevamento viene utilizzato esclusivamente per scegliere i pacchetti di regole. Non modifica l'instradamento verso i provider, la
selezione delle impostazioni locali o la lingua dell'interfaccia utente.

## Struttura della configurazione

Le impostazioni di compressione possono includere:

```json
{
  "languageConfig": {
    "enabled": true,
    "defaultLanguage": "en",
    "autoDetect": true,
    "enabledPacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  },
  "cavemanConfig": {
    "language": "en",
    "autoDetectLanguage": true,
    "enabledLanguagePacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  }
}
```

`languageConfig` controlla le impostazioni predefinite della dashboard e dell'anteprima. `cavemanConfig` è la configurazione del motore in fase di esecuzione
utilizzata quando Caveman comprime il testo dei messaggi.

## Aggiunta di un pacchetto lingua

1. Crea `open-sse/services/compression/rules/<language>/<pack>.json`.
2. Usa il formato delle regole Caveman descritto in `docs/compression/COMPRESSION_RULES_FORMAT.md`.
3. Mantieni le sostituzioni conservative ed evita di modificare codice, identificatori, URL o JSON.
4. Aggiungi o aggiorna i test per la selezione della lingua e il comportamento delle sostituzioni.
5. Esponi le nuove etichette della dashboard/i18n se la lingua compare nei selettori dell'interfaccia utente.

## API

I pacchetti disponibili possono essere interrogati con:

```bash
curl http://localhost:20128/api/compression/language-packs
```

L'endpoint di anteprima accetta sostituzioni della configurazione della lingua:

```bash
curl -X POST http://localhost:20128/api/compression/preview \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "standard",
    "text": "Por favor, eu gostaria que voce basicamente resumisse isso.",
    "config": {
      "languageConfig": {
        "defaultLanguage": "pt-BR",
        "autoDetect": true
      }
    }
  }'
```

## SHARED_BOUNDARIES (v3.8.0)

Tutti e 6 i pacchetti lingua hanno ricevuto una clausola `SHARED_BOUNDARIES` nella versione v3.8.0, applicata a ogni
livello di intensità Caveman (LITE, FULL, ULTRA). Questa indica al motore di preservare tali pattern alla lettera,
indipendentemente dalla rimozione del testo superfluo circostante:

| Tipo di pattern                        | Esempio                                |
| -------------------------------------- | -------------------------------------- |
| Blocchi di codice delimitati           | ` ```python\n...\n``` `                |
| Codice inline                          | `` `my_var` ``                         |
| URL                                    | `https://example.com/path`             |
| Percorsi di file (assoluti + relativi) | `/etc/hosts`, `./src/index.ts`         |
| Intestazioni degli errori              | `Error:`, `TypeError:`, `SyntaxError:` |
| Righe dello stack trace                | `  at functionName (file.ts:12:3)`     |

Questi pattern sono inclusi in `DEFAULT_CAVEMAN_CONFIG.preservePatterns` (in precedenza `[]`). La
costante si trova in `open-sse/services/compression/types.ts`.

### Perché è importante

Senza SHARED_BOUNDARIES, le modalità Caveman aggressive potrebbero rimuovere contenuti che sembravano testo
ripetitivo, ma che in realtà erano uno snippet di codice, un percorso di file o uno stack di errori. SHARED_BOUNDARIES funge da
rete di sicurezza indipendente dalla lingua, applicata prima dell'esecuzione delle regole per la rimozione del testo superfluo.

### Personalizzazione di preservePatterns

È possibile aggiungere pattern supplementari in fase di esecuzione tramite le impostazioni di compressione:

````json
{
  "cavemanConfig": {
    "preservePatterns": [
      "```[\\s\\S]*?```",
      "`[^`]+`",
      "https?://\\S+",
      "(?:/|\\./)[^\\s]+",
      "\\b(?:Error|TypeError|SyntaxError|RangeError):",
      "\\s+at\\s+\\S+\\s+\\(\\S+:\\d+:\\d+\\)"
    ]
  }
}
````

I pattern personalizzati estendono (non sostituiscono) i 6 valori predefiniti.

## Note operative

- Le regole integrate per l'inglese rimangono l'alternativa predefinita quando manca un pacchetto lingua.
- I pacchetti JSON integrati non validi non superano la convalida, in modo che gli asset delle release non subiscano un degrado silenzioso.
- I pacchetti di regole contengono esclusivamente dati e non devono importare codice né eseguire logica arbitraria.
- Il livello di analisi della compressione registra la modalità e il motore selezionati, non il testo completo del prompt.
