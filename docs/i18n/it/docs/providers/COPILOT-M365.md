`copilot-m365-web` (alias `m365copilot`) invia richieste di chat in formato OpenAI tramite una
sessione browser Microsoft 365 Copilot BizChat autenticata su
`m365.cloud.microsoft/chat`. Questa è un'integrazione non ufficiale.

> **Non hai mai usato i provider Web Cookie?**
>
> Leggi **`docs/getting-started/WEB-COOKIE-GUIDE.md`** per conoscere la procedura generale di configurazione, le indicazioni sull'autenticazione, le limitazioni e la risoluzione dei problemi prima di seguire questa guida specifica per il provider.
>
> **Importante:** la credenziale per questo provider **non è un cookie**. Non copiare
> i cookie da `m365.cloud.microsoft`. La credenziale è costituita da un parametro di query
> dell'URL WebSocket e da un segmento del percorso, entrambi reperibili nella scheda Network di DevTools.

## Prerequisiti

- Un account Microsoft 365 con accesso a BizChat su `m365.cloud.microsoft/chat`
- Un browser basato su Chromium (Chrome, Edge) per l'ispezione WebSocket tramite DevTools
- Una licenza M365 Copilot (inclusa in molti piani Microsoft 365 Business/Enterprise)

## Acquisizione della credenziale (metodo WebSocket)

1. Accedi a `https://m365.cloud.microsoft/chat` e avvia una conversazione.
2. Apri **DevTools → Network**.
3. Filtra per **WS** (WebSocket).
4. Fai clic sulla connessione WebSocket Chathub. Cerca un URL che inizi con
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Dal relativo **Request URL**, copia:
   - Il valore del parametro di query `access_token` (un JWT di breve durata).
   - Il segmento del percorso Chathub dopo `/Chathub/` (ad es. `<oid>@<tenant>`).

L'URL completo ha il seguente formato:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. In OmniRoute, vai su **Providers → Add Provider**, seleziona **Microsoft 365 Copilot
   (BizChat)** e incolla la credenziale nel seguente formato:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Fai clic su **Test Connection** e **Save**.

## Acquisizione della credenziale (importazione HAR)

Anziché copiare manualmente i valori dall'URL WebSocket, puoi esportare un file HAR da DevTools:

1. Apri **DevTools → Network**.
2. Avvia o continua una conversazione BizChat (questa operazione attiva la connessione WebSocket).
3. Fai clic con il pulsante destro del mouse nel pannello Network e seleziona **Save all as HAR with content**.
4. In OmniRoute, usa il pulsante **Import .har file** nella finestra di dialogo della connessione del provider.

OmniRoute analizza il file HAR alla ricerca dell'URL WebSocket Chathub, estrae
`access_token` e `chathubPath` e compila automaticamente i campi delle credenziali. L'importazione
HAR decodifica la scadenza del JWT e mostra il tempo di validità rimanente del token.

> **Non eseguire mai il commit di un'esportazione HAR reale, di un token di accesso o di un token di aggiornamento.** I valori usati nei test e
> nella documentazione devono sempre essere segnaposto.

## Durata e aggiornamento del token

L'`access_token` ha una durata limitata (in genere **~75 minuti**). Dopo la scadenza, il provider
segnala un errore di connessione ed è necessario acquisire nuovamente la credenziale.

### Aggiornamento automatico con `refreshToken`

Per evitare di dover acquisire nuovamente la credenziale manualmente, puoi memorizzare un token di aggiornamento Microsoft nelle
**Advanced Settings → providerSpecificData** della connessione:

| Campo          | Descrizione                                                                       |
| -------------- | --------------------------------------------------------------------------------- |
| `refreshToken` | Token di aggiornamento OAuth Microsoft per l'ambito `substrate.office.com/sydney` |
| `tier`         | `individual` (predefinito), `edu` o `enterprise`                                  |

Ottieni il token di aggiornamento da un flusso Microsoft con codice dispositivo o codice di autorizzazione
limitato all'ambito `substrate.office.com/sydney`. Se `refreshToken` è impostato, OmniRoute
aggiorna preventivamente l'`access_token` prima di ogni richiesta, evitando di doverlo
acquisire nuovamente dopo ogni scadenza di ~75 minuti.

Se `refreshToken` non è impostato, devi acquisire nuovamente e manualmente la credenziale WebSocket
dopo ogni scadenza.

### Selezione del livello

| Livello      | Alias           | Interfaccia                     |
| ------------ | --------------- | ------------------------------- |
| `individual` | _(predefinito)_ | M365 Copilot per utenti privati |
| `edu`        | `included`      | M365 Copilot per l'istruzione   |
| `enterprise` | `work`          | M365 Copilot per il lavoro      |

Imposta il livello in **Advanced Settings → providerSpecificData → tier**. Il livello influisce
sull'instradamento di BizChat e sull'accesso ai modelli.

## Modello di sicurezza

- **Integrazione non ufficiale.** Questo provider utilizza il reverse engineering del protocollo
  WebSocket di BizChat. Potrebbe smettere di funzionare senza preavviso quando Microsoft modifica l'endpoint.
- Il flag `subscriptionRisk: true` indica che l'integrazione si basa su un
  endpoint non documentato. Sono possibili restrizioni dell'account, ma non sono confermate.
- Il token di accesso è un JWT di breve durata. Trattalo come una password: non eseguirne il commit,
  non registrarlo nei log e non condividerlo.
- Il token di aggiornamento garantisce un accesso a lungo termine all'interfaccia BizChat. Conservalo con la
  stessa attenzione riservata a una chiave API.

## Risoluzione dei problemi

### L'autenticazione non riesce immediatamente

- Verifica di aver copiato il valore dall'**URL WebSocket**, non da una richiesta XHR/Fetch. La
  credenziale si trova nel parametro di query `access_token` della connessione WebSocket
  Chathub, non in un'intestazione `Authorization: Bearer`.
- Assicurati che `chathubPath` includa il segmento `<oid>@<tenant>` completo del percorso
  dell'URL.

### Il token scade dopo circa 75 minuti

Questo comportamento è previsto. Senza un `refreshToken`, il token di accesso ha una durata limitata. Puoi:

- Acquisire nuovamente la credenziale da DevTools oppure
- Configurare un `refreshToken` nelle Impostazioni avanzate per l'aggiornamento automatico.

### Il test della connessione riesce, ma la chat restituisce 401

Il token potrebbe essere scaduto tra la convalida e la prima richiesta. Acquisisci nuovamente una
credenziale aggiornata.

### Copilot non viene visualizzato nell'elenco dei provider

Assicurati che `copilot-m365-web` sia abilitato in **Dashboard → Provider**. Il provider potrebbe
essere nascosto per impostazione predefinita in alcuni livelli.
