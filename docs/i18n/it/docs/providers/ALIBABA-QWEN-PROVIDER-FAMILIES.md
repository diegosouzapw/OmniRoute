Questo documento registra la decisione di implementazione relativa alla
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854). I prodotti pubblici sono
rappresentati come quattro famiglie di provider. La regione è un dato della connessione, non un prodotto separato.

## Decisione

| Famiglia di provider                   | ID OmniRoute            | Regione globale | Regione Cina |
| -------------------------------------- | ----------------------- | --------------- | ------------ |
| Alibaba Cloud Model Studio (a consumo) | `alibaba`               | Singapore       | Pechino      |
| Alibaba Cloud Token Plan               | `bailian-coding-plan`   | Singapore       | Pechino      |
| Qwen Cloud (a consumo)                 | `qwen-cloud`            | Globale         | Pechino      |
| Qwen Cloud Token Plan                  | `qwen-cloud-token-plan` | Singapore       | Pechino      |

L'ID esistente `alibaba-cn` rimane un alias di compatibilità in fase di esecuzione per le connessioni salvate, le route dei
modelli, le combinazioni e l'utilizzo storico. La relativa scheda nella dashboard viene incorporata in `alibaba`; non è necessaria
alcuna riscrittura del database.

Qwen Cloud a consumo e Alibaba Cloud Model Studio condividono attualmente gli host di runtime compatibili con
DashScope, ma rimangono identità di provider separate perché gli utenti ottengono le chiavi e gestiscono
gli account attraverso interfacce di prodotto differenti. I prodotti Alibaba e Qwen Cloud Token Plan utilizzano
famiglie di endpoint differenti, pertanto tutti e quattro i prodotti rimangono ID di provider separati.

## Matrice degli endpoint

| Famiglia di provider    | `global-sg`                                                              | `china-beijing`                                                      | Formato di trasmissione |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ----------------------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI                  |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic               |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI                  |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI                  |

La chiave API e l'endpoint devono appartenere allo stesso prodotto e alla stessa regione. La selezione di una regione modifica
l'endpoint preimpostato utilizzato dalla convalida e dalle richieste normali.

## Contratto di connessione

Le nuove connessioni memorizzano la chiave stabile della regione in `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

I valori consentiti sono `global-sg` e `china-beijing`. L'endpoint viene derivato centralmente dall'ID del
provider e dalla regione. Un valore `providerSpecificData.baseUrl` non preimpostato rimane una sostituzione esplicita definita dall'operatore
e ha la precedenza, mentre i vecchi URL preimpostati salvati vengono normalizzati in base alla matrice
regionale.

Ciò mantiene estensibile lo schema della connessione: è possibile aggiungere un'altra regione al resolver senza
creare un'altra scheda provider né modificare gli ID provider salvati.

## Compatibilità e distribuzione

1. Aggiungere il resolver degli endpoint regionali e mantenere le impostazioni predefinite globali correnti.
2. Utilizzare il rilevamento live regionale di DashScope `/models` per `alibaba`, il relativo ID di compatibilità `alibaba-cn` e `qwen-cloud`. Le relative risposte vengono prima sottoposte a un filtro per la generazione di testo, poiché l'endpoint generico restituisce anche modelli per immagini, video, audio, embedding e altri modelli non destinati alla chat. `qwen-cloud` applica quindi l'allowlist gestita dichiarata nel proprio registro del provider. Alibaba Model Studio e Qwen Cloud mantengono cataloghi curati separati, anche se attualmente condividono gli host di runtime.
3. Registrare `qwen-cloud-token-plan` con l'allowlist corrente dei modelli di testo del Token Plan.
4. Aggiungere un selettore di regione tipizzato alle finestre di dialogo per l'aggiunta e la modifica delle connessioni.
5. Nascondere la scheda duplicata `alibaba-cn` e includere le relative connessioni esistenti nella pagina del provider `alibaba`.
6. Mantenere disponibili le sostituzioni personalizzate degli endpoint per le distribuzioni avanzate e specifiche dell'area di lavoro.

I modelli multimediali del Token Plan rimangono esclusi dal catalogo della chat perché utilizzano endpoint dedicati.
`wan2.7-image` e `wan2.7-image-pro` sono registrati in `open-sse/config/imageRegistry.ts`;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` e `happyhorse-1.1-r2v` sono registrati in
`open-sse/config/videoRegistry.ts`. Entrambi i registri riutilizzano l'identità di connessione
`qwen-cloud-token-plan` e le relative credenziali specifiche della regione.

Qwen Cloud standard dispone di cataloghi separati di immagini e video con pagamento in base al consumo sotto l'identità `qwen-cloud`. I suoi modelli di immagini sono `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` e `z-image-turbo`. I suoi modelli video
sono `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` e
`wan2.7-videoedit`. Questi modelli riutilizzano esclusivamente la connessione standard `qwen-cloud` e l'endpoint multimediale regionale di DashScope. I registri del Token Plan e quelli con pagamento in base al consumo non ereditano né uniscono gli elenchi di modelli reciproci.

Anche l'identità `bailian-coding-plan` dispone di allowlist multimediali proprie:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` e `qwen-image-2.0-pro` per la generazione di immagini, oltre a
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` e `happyhorse-1.1-r2v` per la generazione di video. Utilizza esclusivamente la connessione Bailian Coding Plan e l'endpoint regionale del Coding Plan. I suoi registri di immagini e video non ereditano né si uniscono a quelli di alcun provider Qwen Cloud.

L'identità standard `alibaba` dispone di allowlist separate per immagini e video. I suoi modelli di immagini sono
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` e `wan2.6-t2i`. I modelli video aggiunti sono `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` e `wan2.7-videoedit`. Questi modelli utilizzano esclusivamente la connessione Alibaba Model Studio e il relativo endpoint multimediale regionale selezionato; non vengono aggiunti ad alcun registro Coding Plan o Qwen Cloud.

Il catalogo della chat del Qwen Cloud Token Plan segue l'allowlist testuale con corrispondenza esatta del piano Individual:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` e
`deepseek-v4-pro`. Le voci Wan e HappyHorse appartengono alle API separate per la generazione di immagini e video.

Alibaba Token Plan espone gli stessi sei ID correnti dei modelli di generazione di testo tramite il proprio endpoint compatibile con Anthropic. L'opzione Singapore memorizza la chiave di regione esistente `global-sg`; differisce solo l'etichetta mostrata all'utente rispetto alle famiglie di provider che chiamano la regione Global.

Il catalogo della chat standard di Qwen Cloud è intenzionalmente più ristretto rispetto alla risposta testuale live completa. La relativa allowlist gestita si trova in `open-sse/config/providers/registry/qwen-cloud/index.ts`; il rilevamento live restituisce solo gli ID presenti sia nella risposta upstream sia nell'elenco del registro.

Alibaba Model Studio segue la stessa regola di intersezione live con la propria allowlist gestita in modo indipendente in `open-sse/config/providers/registry/alibaba/index.ts`. Il provider di compatibilità `alibaba-cn` riutilizza tale catalogo, indirizzando il rilevamento verso l'endpoint di Pechino.
