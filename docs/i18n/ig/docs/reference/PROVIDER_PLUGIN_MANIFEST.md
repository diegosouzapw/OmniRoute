`open-sse/config/providerPluginManifest.ts` na-akọwapụta nkwekọrịta ngwa mgbakwunye onye na-eweta
nke dị nchebe maka JSON. `open-sse/config/providerPluginManifestRegistry.ts` na-ejikọta
nkwekọrịta ahụ na ndekọ ndị na-eweta dị ugbu a maka sidecar dịka Bifrost,
CLIProxyAPI, ma ọ bụ router Go/Rust nke ga-abịa n'ọdịnihu. Ndebanye TypeScript ka bụ
isi mmalite nke eziokwu, mana sidecar nwere ike iji manifest ahụ na-enweghị ibubata
koodu executor, ntọala ndabara OAuth, header, ma ọ bụ ọnọdụ environment nke process.

Manifest ahụ dịkwa site na HTTP na
`GET /api/v1/provider-plugin-manifest` maka sidecar ndị na-agba ọsọ n'èzí process.

OmniRoute na-ezisa URL ahụ nye Bifrost na CLIProxyAPI site na header arịrịọ
`X-OmniRoute-Provider-Manifest-Url`. Tọọ
`OMNIROUTE_PROVIDER_MANIFEST_URL` mgbe sidecar chọrọ URL netwọkụ ọha ma ọ bụ nke container
kama origin arịrịọ mpaghara.

## Imelite Manifest

Endpoint HTTP ahụ na-eweghachi `Cache-Control: public, max-age=60` na
`ETag` siri ike. Sidecar kwesịrị idowe manifest ikpeazụ e nyochara ma ziga ETag ya
n'ime `If-None-Match` mgbe ọ na-emelite. Nzaghachi `304 Not Modified` enweghị body;
sidecar ga-edobe manifest dị na cache ya. Ọ bụrụ na ọ nweghị manifest cache e nyochara,
sidecar ga-ezipụ arịrịọ na-enweghị condition kama ịnakwere `304`.

## Ebumnuche

Bugharịa metadata onye na-eweta ka ọ bụrụ nkwekọrịta ngwa mgbakwunye ka sidecar nwere
latency dị ala nwee ike ijikwa ụzọ arịrịọ a na-ejikarị eme ihe n'ọdịnihu, ebe OmniRoute
na-edobe route TypeScript dịka ọnụ ụzọ amụma na fallback. Manifest ahụ bụ mgbakwunye:
ọ naghị agbanwe routing arịrịọ n'onwe ya.

## Nkwekọrịta

Manifest ahụ nwere:

- id na alias onye na-eweta
- format upstream na aha executor
- ụdị auth, header auth, na prefix auth nhọrọ
- metadata endpoint na-adịghị agbanwe agbanwe
- ntozu sidecar na ihe kpatara doro anya mgbe onye na-eweta kwesịrị ịnọ na TS
- metadata model dị nchebe maka JSON dịka ogologo context, flag vision/reasoning, na
  param ndị anaghị akwado
- mkpado ikike gụnyere `apikey`, `oauth`, `custom-executor`,
  `passthrough-models`, `responses`, `sidecar-candidate`, `usage-fetch`, na `usage-supported`

Manifest ahụ kpachaara anya wepu:

- ihe nzuzo client OAuth na uru nzuzo ndabara
- mkpebi environment n'oge runtime
- header arịrịọ na helper credential ọha
- builder URL dynamic
- function executor
- ihe ime session pool

## Mkpado Ikike

`capabilities` bụ array mkpado a haziri n'usoro nke sitere na entry dị na registry. Ndị na-eme
integration kwesịrị ile ya anya dịka azịza igwe nwere ike ịgụ nye “gịnị ka onye na-eweta a nwere ike ime,” kama
ịgụgharị source TypeScript.

| Mkpado               | Ihe ọ pụtara                                                                  |
| -------------------- | ----------------------------------------------------------------------------- |
| `apikey`             | Na-anabata API key (`authType` bụ `apikey` ma ọ bụ `optional`).               |
| `oauth`              | Na-eji usoro OAuth ma ọ bụ session.                                           |
| `responses`          | Na-ekpughe base URL OpenAI Responses-API.                                     |
| `passthrough-models` | Na-enye model ozugbo site na upstream kama catalog na-adịghị agbanwe agbanwe. |
| `custom-executor`    | Na-agba executor na-abụghị nke ndabara, ya mere ọ na-anọ na ụzọ TypeScript.   |
| `sidecar-candidate`  | Na-egosipụta `sidecar.eligible` — ọ dị nchebe ịtụle maka import sidecar.      |
| `usage-fetch`        | Nwere fetcher usage ma ọ bụ quota ejikọrọ (`getUsageForProvider`).            |
| `usage-supported`    | API usage na-anabata onye na-eweta a (`isSupportedUsageConnection`).          |

`usage-fetch` bụ naanị maka nchọpụta. Ọ na-egosi na OmniRoute maara otu esi agụ usage maka
onye na-eweta; ọ naghị eme ka fetching rụọ ọrụ, gbanwee semantics quota, ma ọ bụ gosi na
widget quota Dashboard agbanyere maka onye na-eweta — a na-achịkwa widget ahụ iche site na
`USAGE_SUPPORTED_PROVIDERS`. Isi mmalite nke eziokwu bụ `USAGE_FETCHER_PROVIDERS` dị na
`open-sse/services/usage/fetcherProviders.ts`.

A na-eji string ndị usage dispatcher na-anabata dị ka key nke ndepụta ahụ, ya mere ọ na-agwakọta id canonical
na alias ma dịtụ ogologo karịa ọnụọgụ ndị na-eweta nwere mkpado: entry ndị na-abụghị
ndị na-eweta chat n'ime registry manifest (dịka ọmụmaatụ onye na-eweta search `firecrawl`
na onye na-eweta ACP `amazon-q`) enweghị entry manifest a ga-etinye mkpado.

`usage-supported` na-aza ma route usage nke server na Dashboard na-anabata connection
maka onye na-eweta. Ọ na-egosipụta `isSupportedUsageConnection()` (`src/lib/usage/providerLimits.ts`)
na `supportsProviderQuota()` (`src/shared/utils/providerQuotaVisibility.ts`), nke abụọ bụ
`USAGE_SUPPORTED_PROVIDERS` (`open-sse/services/usage/supportedProviders.ts`) na-achịkwa. N'adịghị ka
`usage-fetch`, a na-ewepụta ya naanị na id onye na-eweta — guard runtime na-eme
`USAGE_SUPPORTED_PROVIDERS.includes(providerId)` na-enweghị mkpebi alias, ya mere manifest
na-edobe otu iwu ahụ. Mkpado abụọ ahụ nwere ókè dị iche: ndị na-eweta 3 nwere naanị
`usage-fetch` (`opencode`, `opencode-zen`, `xai`) ma 1 nwere naanị
`usage-supported` (`xiaomi-mimo-token-plan`), ya mere otu anaghị apụta na nke ọzọ dị.

## Ojiji Sidecar

Sidecar kwesịrị iwere `sidecar.eligible` dị ka akara nke na-egosi naanị onye nwere ike iru eru n'ụzọ akpachapụ anya, ọ bụghị dị ka mkpebi routing na-enweghị ọnọdụ. Ihe mbụ e kwesịrị ibubata kwesịrị ịbụ ndị provider na-eji API-key na static-endpoint site na default executor. Ndị provider nwere custom web executors, usoro OAuth/session, dynamic URL builders, ma ọ bụ pool config ga-anọgide na ụzọ fallback nke TypeScript ruo mgbe sidecar mepụtara omume hà nhata, telemetry egosikwa na ha kwekọrọ.

Usoro mbugharị a tụrụ aro:

1. Mepụta ma nyochaa provider plugin manifest site na TS registry.
2. Kụziere Bifrost ma ọ bụ CLIProxyAPI otu esi ebubata manifest maka ndị provider na-eji API-key/static.
3. Zipụ ndị provider ruru eru site na sidecar n'azụ `OMNIROUTE_RELAY_BACKEND` ma hapụ TS fallback ka ọ ka na-arụ ọrụ.
4. Bulie ndị provider naanị mgbe success rate, p99 latency, streaming behavior, na unsupported-param handling kwekọrọ na ụzọ TS.
5. Tinye plugins nke sidecar n'onwe ya maka custom executors, otu ezinụlọ provider n'otu oge.

## Ihe Mere A Na-ekwesịghị Itinye Ndị Provider Kpọmkwem N'ime Next

Frontend Next ekwesịghị ijikwa mmezu nke provider. O kwesịrị ịkpọ API boundary. Backend nwere ike ikpebi ma ọ ga-eji TypeScript executor, Bifrost, CLIProxyAPI, ma ọ bụ sidecar native nke ga-abịa n'ọdịnihu. Nke a na-eme ka request signing, allowlist checks, DB policy, na fallback behavior nọgide n'otu ebe tupu e nyefee ọrụ ọ bụla n'aka sidecar.
