`agentrouter` അപ്സ്ട്രീം ഗേറ്റ്വേ `messages[].content`-ൽ കീവേഡ് അധിഷ്ഠിതമായ ഒരു ഉള്ളടക്ക ഫിൽട്ടർ പ്രവർത്തിപ്പിക്കുന്നു.
ഫിൽട്ടർ ഭാഗികമായി നിർണായകമാണ് (ചില പ്രയോഗങ്ങളെ എല്ലായ്പ്പോഴും തടയുന്നു),
ഭാഗികമായി സാധ്യതാധിഷ്ഠിതവുമാണ് (ബർസ്റ്റ്-സെൻസിറ്റീവ് — അതിവേഗ അഭ്യർത്ഥനകൾക്കുശേഷം
കൂടുതൽ കർശനമാകുകയും ഒരു കൂൾഡൗണിനുശേഷം സാധാരണ നിലയിലാകുകയും ചെയ്യുന്നു).

WAF ഒരു അഭ്യർത്ഥന തടയുമ്പോൾ ഇത് തിരികെ നൽകുന്നു:

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## ഫിൽട്ടറിന്റെ പരിധി

WAF `messages[].content` മാത്രം പരിശോധിക്കുന്നു. ഇത് ഇനിപ്പറയുന്നവ പരിശോധിക്കില്ല:

- `system` പ്രോംപ്റ്റ്
- ഘടനാബദ്ധമായ ഉള്ളടക്ക ബ്ലോക്കുകൾ (`tool_result`, `tool_use`, `thinking`, `image`)
- ടൂളിന്റെ `description`, `input_schema` ഫീൽഡുകൾ
- അഭ്യർത്ഥനയുടെ മെറ്റാഡാറ്റ, ഹെഡറുകൾ, അല്ലെങ്കിൽ മോഡൽ id

## എല്ലായ്പ്പോഴും തടയപ്പെടുന്ന പാറ്റേണുകൾ (കേസ് പരിഗണിക്കാതെ)

| പാറ്റേൺ                         | കുറിപ്പുകൾ                                                      |
| ------------------------------- | --------------------------------------------------------------- |
| ഏതെങ്കിലും `Lorem ipsum` വകഭേദം | സമ്പൂർണ്ണ ലാറ്റിൻ lorem പദസഞ്ചയം തടയപ്പെടുന്നു                  |
| `language model` (ഒറ്റയ്ക്ക്)   | "the language model", "large language model" എന്നിവ കടന്നുപോകും |
| `virtual assistant`             | "AI assistant" കടന്നുപോകും                                      |
| `I'm here to help`              | "here to help" മാത്രം വന്നാലും തടയപ്പെടും                       |
| `Claude, made by Anthropic`     | പൂർണ്ണ പ്രയോഗം മാത്രം                                           |

## മിക്കവാറും എല്ലായ്പ്പോഴും തടയപ്പെടുന്ന പാറ്റേണുകൾ

| പാറ്റേൺ                                                          | കുറിപ്പുകൾ                                                     |
| ---------------------------------------------------------------- | -------------------------------------------------------------- |
| `placeholder`                                                    | ഇത് ഒറ്റയ്ക്ക് വരുമ്പോൾ (ഒരു പാരാമീറ്റർ നാമമായോ മറ്റോ അല്ലാതെ) |
| `dummy data`                                                     | ഫിക്ചറുകൾക്കുള്ള സാധാരണ സീഡ് പ്രയോഗം                           |
| `foo bar baz`                                                    | പ്രാമാണികമായ പ്ലേസ്ഹോൾഡർ പ്രയോഗം                               |
| ആവർത്തിക്കുന്ന ചെറിയ ടോക്കണുകൾ (`AAA BBB CCC`, `test test test`) | കീവേഡ് നിറച്ചുകുത്തൽ കണ്ടെത്താനുള്ള ഡിറ്റക്ടർ                  |

## ലോഡിന് കീഴിലെ പെരുമാറ്റം

ഒരു ചെറിയ സമയപരിധിക്കുള്ളിൽ ഏകദേശം 5 അതിവേഗ അഭ്യർത്ഥനകൾക്കുശേഷം, സാധാരണയായി
കടന്നുപോകുന്ന ഉള്ളടക്കവും WAF തടയാൻ തുടങ്ങും. ഏകദേശം 5–10 സെക്കൻഡ് നിഷ്ക്രിയമായി
കഴിഞ്ഞാൽ ബക്കറ്റ് അയയും. Claude Code അല്ലെങ്കിൽ Codex CLI അതിവേഗം തുടർച്ചയായി
ഒന്നിലധികം ടൂൾ-ഉപയോഗ / സന്ദേശ-അയയ്ക്കൽ കോളുകൾ നടത്തുമ്പോൾ ഇടയ്ക്കിടെ
`400 content-blocked` പിശകുകൾക്ക് കാരണമാകുന്നതും ഇതേ IP-യും കീയും അടിസ്ഥാനമാക്കിയുള്ള
റേറ്റ് ലിമിറ്ററാണ്.

## OmniRoute-ൽ ഇതിനകം പ്രയോഗിച്ച പരിഹാരങ്ങൾ

1. **`open-sse/services/wafRateLimit.ts`** — ഏതെങ്കിലും `agentrouter:*`
   URL-ലേക്കുള്ള ഔട്ട്ബൗണ്ട് അഭ്യർത്ഥനകൾക്കിടയിൽ കുറഞ്ഞത് 500 ms ഇടവേള
   നിർബന്ധമാക്കുന്ന ബർസ്റ്റ് ഗാർഡ്. ഈ ഇടവേള മനുഷ്യന് അനുഭവപ്പെടുന്ന ലേറ്റൻസിയേക്കാൾ
   വളരെ താഴെയാണ്, കൂടാതെ സാധാരണ ട്രാഫിക്കിൽ WAF സജീവമാകുന്നത് ഇത് തടയുന്നു.

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — ഒരു അപ്സ്ട്രീം
   `400 content-blocked` തിരികെ നൽകുമ്പോൾ, എക്സിക്യൂട്ടർ അതേ URL എക്സ്പോണൻഷ്യൽ
   ബാക്ക്ഓഫോടെ വീണ്ടും ശ്രമിക്കുന്നു (1.5 s, 3.0 s, പരമാവധി 2 ശ്രമങ്ങൾ). ബാക്ക്ഓഫിനുശേഷം
   WAF സാധാരണയായി അയയുകയും പുനഃശ്രമം വിജയിക്കുകയും ചെയ്യും.

3. **`tests/unit/compression/harness.test.ts`** — ടെസ്റ്റ് ഫിക്ചറായ
   `longInput`, `"lorem ipsum dolor sit amet ".repeat(40)` എന്നതിൽനിന്ന്
   `"example content for testing purposes ".repeat(40)` എന്നതിലേക്ക് മാറ്റി. അതിനാൽ
   Claude Code ഈ ഫയൽ `Read` ടൂൾ വഴി വായിക്കുമ്പോൾ, ഫയലിലെ ഉള്ളടക്കം
   `tool_result` ബ്ലോക്കിലൂടെ തിരികെ ഒഴുകി WAF പ്രവർത്തനക്ഷമമാക്കില്ല.

## പ്രോംപ്റ്റുകൾക്കും ടൂൾ ഔട്ട്പുട്ടിനുമുള്ള മാർഗ്ഗനിർദ്ദേശം

ഒരു Claude Code അല്ലെങ്കിൽ Codex CLI സെഷൻ ആവർത്തിച്ച്
`400 content-blocked` നേരിടുകയാണെങ്കിൽ, ഏറ്റവും പുതിയ ഉപയോക്തൃ സന്ദേശത്തിലും ഏറ്റവും
പുതിയ ടൂൾ ഫലത്തിലും മുകളിലുള്ള ഏതെങ്കിലും പാറ്റേൺ ഉണ്ടോയെന്ന് പരിശോധിച്ച് മറ്റൊരു രീതിയിൽ
എഴുതുക. സാധാരണ പരിഹാരങ്ങൾ:

- `Lorem ipsum …` എന്നത് `example text …` അല്ലെങ്കിൽ ടെസ്റ്റ് അതോ ഫിക്ചർ
  മാതൃകയാക്കാൻ ശ്രമിക്കുന്ന യഥാർഥ ഉള്ളടക്കം ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുക.
- `placeholder` (ഒറ്റയ്ക്ക് വരുമ്പോൾ) എന്നത് `example value`,
  `sample value`, അല്ലെങ്കിൽ യഥാർഥ മൂല്യം ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുക.
- `language model` എന്നത് `large language model` അല്ലെങ്കിൽ `the model` ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുക.
- `dummy data` എന്നത് `sample data` അല്ലെങ്കിൽ യാഥാർഥ്യസമാനമായ സീഡ് മൂല്യങ്ങൾ ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുക.
- `I'm here to help` / `here to help` എന്നത് കൂടുതൽ വ്യക്തമായ ഒരു
  തുടക്കവാചകം ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുക (ഉദാ. "I'll review the file you mentioned").

## തെറ്റായ പോസിറ്റീവുകൾ അപ്സ്ട്രീമിലേക്ക് റിപ്പോർട്ട് ചെയ്യൽ

നിലവിലെ ഫിൽട്ടർ അതിരുകടന്ന കർശനതയുള്ളതാണ് — ഓപ്പറേറ്റർക്ക് ഒരു പ്രോംപ്റ്റ്
ഇൻജക്റ്റ് ചെയ്യാനുള്ള ഉദ്ദേശ്യമില്ലെന്ന് വ്യക്തമായിരിക്കുമ്പോഴും ഇത് `tool_result`
ബ്ലോക്കുകളിലെ "Lorem ipsum" തടയുന്നു. ഇത് ഉറവിടത്തിൽത്തന്നെ പരിഹരിക്കാൻ ആഗ്രഹിക്കുന്ന
ഓപ്പറേറ്റർമാർ തെറ്റായ പോസിറ്റീവുകൾ റിപ്പോർട്ട് ചെയ്യാൻ `agentrouter.org`-നെ
ബന്ധപ്പെടണം. മുകളിലുള്ള ബ്ലോക്ക്ലിസ്റ്റ് 2026-08-03-ലെ അപ്സ്ട്രീം പരിശോധനയിൽനിന്നുള്ള
അനുഭവാധിഷ്ഠിത ഫലമാണ്.
