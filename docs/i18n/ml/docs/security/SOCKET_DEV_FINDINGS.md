ഈ പ്രമാണം `omniroute@3.8.5`-നെതിരെ ഉന്നയിക്കപ്പെട്ട ആറ്
`AI-detected potential malware` കണ്ടെത്തലുകളെയും `omniroute@3.8.6`-ൽ
പ്രയോഗിച്ച ലഘൂകരണങ്ങളെയും സംബന്ധിച്ച് പരിപാലകൻ തയ്യാറാക്കിയ സാക്ഷ്യപത്രമാണ്. ഇതിന്റെ ഉദ്ദേശ്യങ്ങൾ:

1. കണ്ടെത്തലുകളെ യഥാർത്ഥ സോഴ്സുമായി താരതമ്യം ചെയ്ത് വിലയിരുത്തേണ്ടപ്പോൾ ഉദ്ധരിക്കാൻ
   സുരക്ഷാ-പൈപ്പ്ലൈൻ ഓപ്പറേറ്റർമാർക്ക് ഒരൊറ്റ റഫറൻസ് ലഭ്യമാക്കുക.
2. ഫ്ലാഗ് ചെയ്ത ഓരോ പാത്തും മനഃപൂർവമുള്ളതും, ഓപ്റ്റ്-ഇൻ സ്വഭാവമുള്ളതും,
   രേഖപ്പെടുത്തിയതുമാണെന്ന പരിപാലകൻ ഒപ്പിട്ട അവകാശവാദം ഭാവിയിലെ AI സ്കാനറുകൾക്ക് തിരിച്ചറിയാൻ സഹായിക്കുക.
3. ഓരോ കോൾ സൈറ്റും _എന്തുകൊണ്ട്_ ആ രീതിയിൽ രൂപപ്പെടുത്തിയിരിക്കുന്നു എന്നതിന്റെ രേഖാമൂലമുള്ള ചരിത്രം സൂക്ഷിക്കുക —
   അങ്ങനെ ഭാവിയിലെ ഒരു റീഫാക്ടറിംഗ് മനഃപൂർവം നീക്കം ചെയ്ത ഫിംഗർപ്രിന്റ്
   അബദ്ധത്തിൽ വീണ്ടും അവതരിപ്പിക്കാതിരിക്കും.

v3.8.6 ലഘൂകരണങ്ങൾ പുറത്തിറങ്ങിയതിനുശേഷം താഴെയുള്ള ഏതെങ്കിലും കോൾ സൈറ്റ് നിങ്ങളുടെ സ്കാനർ
വീണ്ടും ഫ്ലാഗ് ചെയ്യുന്നുവെങ്കിൽ, സ്കാൻ ട്രേസിനൊപ്പം ഒരു ഇഷ്യൂ തുറക്കുക;
ഞങ്ങൾ ഈ സാക്ഷ്യപത്രം ഇവിടെ വിപുലീകരിക്കും.

## §1 — MITM റൂട്ട്-CA ഇൻസ്റ്റാളേഷൻ (`77484.js`)

**സോഴ്സ് ഫയലുകൾ**:

- `src/mitm/cert/install.ts` — പബ്ലിക് `installCert()` / `uninstallCert()`,
  ഓരോ പ്ലാറ്റ്ഫോമിനുമുള്ള `installCertWindows/Mac/Linux`.
- `src/mitm/systemCommands.ts` — ഇൻസ്റ്റാളേഷൻ പാത്തുകൾ ഉപയോഗിക്കുന്ന പങ്കിട്ട `execFile` / `spawn` / PowerShell
  ഹെൽപ്പറുകൾ.

**ട്രിഗർ**: ഉപയോക്താവ് `/dashboard/cli-tools/mitm` എന്ന ലോക്കൽ ഡാഷ്ബോർഡിൽ
"MITM പ്രോക്സി പ്രവർത്തനക്ഷമമാക്കുക" ക്ലിക്ക് ചെയ്യുന്നു. ഈ റൂട്ട് ലൂപ്പ്ബാക്കിൽ മാത്രം ലഭ്യമാണ് — `CLAUDE.md`-ലെ
കർശന നിയമം #17-ഉം `src/server/authz/routeGuard.ts::isLocalOnlyPath()`-ഉം കാണുക. ഒരു ടണലിലൂടെ വെളിപ്പെട്ട
JWT-ക്ക് ഈ കോഡ് പാത്ത് ട്രിഗർ ചെയ്യാൻ **കഴിയില്ല**.

**നടത്തുന്ന പ്രിവിലേജ്ഡ് പ്രവർത്തനങ്ങൾ (ഓരോ പ്ലാറ്റ്ഫോമിലും)**:

| OS                     | കമാൻഡ്(കൾ)                                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | UAC വഴി `certutil -addstore Root <cert>`                                                                          |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | `certutil -d sql:<profile>` വഴി ഓരോ പ്രൊഫൈലിനുമുള്ള NSS DB അപ്ഡേറ്റ്                                              |

ഇവ `mitmproxy`, Charles Proxy, Fiddler, Caddy എന്നിവ ഉപയോഗിക്കുന്ന അതേ കമാൻഡുകളാണ്.
OmniRoute-ൽ ഇവ നിലവിലുണ്ടെന്ന വസ്തുത
`docs/security/STEALTH_GUIDE.md`-ൽ രേഖപ്പെടുത്തിയിട്ടുണ്ട്.

**v3.8.6 ലഘൂകരണം**:

- `runElevatedPowerShell()` ഇനി `-EncodedCommand <base64utf16le>` ഉപയോഗിക്കുന്നില്ല.
  എലിവേറ്റഡ് പേലോഡ് ഓരോ കോളിനുമുള്ള താൽക്കാലിക `.ps1` ഫയലിലേക്ക് എഴുതുന്നു (മോഡ് 0o600,
  ഒരു സ്വകാര്യ `mkdtempSync` ഡയറക്ടറിക്കുള്ളിൽ), തുടർന്ന് `-File` വഴി അതിനെ റഫർ ചെയ്യുന്നു.
  `finally`-ൽ ഫയൽ അൺലിങ്ക് ചെയ്യുന്നു. ഇത് Socket.dev-ന്റെ AI
  ക്ലാസിഫയർ ഫ്ലാഗ് ചെയ്ത, പാഠപുസ്തക മാതൃകയിലുള്ള
  PowerShell-വഴിയുള്ള-base64-എലിവേഷൻ ഫിംഗർപ്രിന്റ് നീക്കം ചെയ്യുന്നു.
- `installCertWindows` ഇവിടെ ചൂണ്ടിക്കാണിക്കുന്ന ഒരു ഇൻലൈൻ `SECURITY-AUDITOR-NOTE:` ബ്ലോക്ക്
  ഉൾക്കൊള്ളുന്നു.

**ഞങ്ങൾ ഇത് നിലനിർത്തുന്നതിന്റെ കാരണം**: MITM പ്രോക്സി
`docs/security/STEALTH_GUIDE.md`, `docs/frameworks/MITM-PROXY.md` എന്നിവയിൽ രേഖപ്പെടുത്തിയ ഒരു സവിശേഷതയാണ്.
ഇത് നീക്കം ചെയ്യുന്നത് ഏജന്റ്-ബ്രിഡ്ജ് സവിശേഷതാസമുച്ചയം പ്രവർത്തനരഹിതമാക്കും.

## §2 — Zed ക്രെഡൻഷ്യൽ ഇമ്പോർട്ട് (`app/api/providers/zed/import/route.js`)

**സോഴ്സ് ഫയലുകൾ**:

- `src/app/api/providers/zed/discover/route.ts` _(v3.8.6-ൽ പുതിയത്)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(v3.8.6-ൽ പുതിയത്)_

**ട്രിഗർ**: ലോക്കൽ ഡാഷ്ബോർഡിലെ Providers പേജിൽ ഉപയോക്താവ് "Zed-ൽ നിന്ന് ഇമ്പോർട്ട് ചെയ്യുക" ക്ലിക്ക് ചെയ്യുന്നു. എൻഡ്പോയിന്റ് `requireManagementAuth` വഴി നിയന്ത്രിച്ചിരിക്കുന്നു. രേഖപ്പെടുത്തിയിട്ടുള്ള സർവീസ് പേരുകൾക്ക് കീഴിൽ Zed എഡിറ്റർ തന്നെ അതിന്റെ പ്രൊവൈഡർ API കീകൾ OS കീചെയിനിലേക്ക് എഴുതുന്നു — https://zed.dev/docs/ai/llm-providers കാണുക.

**v3.8.5-ലെ പ്രവർത്തനം (Socket.dev ഫ്ലാഗ് ചെയ്തത്)**:

`POST /import` ക്രെഡൻഷ്യലുകൾ കണ്ടെത്തുകയും ഒറ്റ റൗണ്ട്-ട്രിപ്പിൽ അവയെ ലോക്കൽ SQLite സ്റ്റോറിലേക്ക് സ്വയമേവ സേവ് ചെയ്യുകയും ചെയ്തിരുന്നു. ഓരോ അക്കൗണ്ടിനും പ്രത്യേകം സ്ഥിരീകരണമോ ഫിംഗർപ്രിന്റോ ഉണ്ടായിരുന്നില്ല; "N ടോക്കണുകൾ കണ്ടെത്തി, എല്ലാം ഇമ്പോർട്ട് ചെയ്തു" എന്നത് മാത്രമായിരുന്നു.

**v3.8.6 ലഘൂകരണം — 2-ഘട്ട സ്ഥിരീകരണം**:

1. **`POST /api/providers/zed/discover`**
   `{ candidates: [{ provider, service, account, fingerprint }] }` മടക്കിനൽകുന്നു. അസംസ്കൃത ടോക്കൺ **ഒരിക്കലും** കൈമാറപ്പെടുന്നില്ല. ഫിംഗർപ്രിന്റ്
   `sha256(service|account|token).slice(0,16)` ആണ്.
2. ഡാഷ്ബോർഡ് കാൻഡിഡേറ്റ് ലിസ്റ്റ് പ്രദർശിപ്പിക്കുന്നു; ഓപ്പറേറ്റർ ഇമ്പോർട്ട് ചെയ്യേണ്ടവ തിരഞ്ഞെടുക്കുകയും `{ confirmedAccounts: [{ service, account, fingerprint }] }`
   **`POST /api/providers/zed/import`**-ലേക്ക് പോസ്റ്റ് ചെയ്യുകയും ചെയ്യുന്നു.
3. ഇമ്പോർട്ട് എൻഡ്പോയിന്റ് **സെർവറിൽ കീചെയിൻ വീണ്ടും വായിക്കുകയും**
   `(service, account, fingerprint)` അനുസരിച്ച് ഫിൽട്ടർ ചെയ്യുകയും ചെയ്യുന്നു. കൈകടത്തിയതോ വീണ്ടും പ്ലേ ചെയ്തതോ ആയ discover റെസ്പോൺസിന്, ബന്ധമില്ലാത്ത ഒരു ടോക്കൺ സേവ് ചെയ്യാൻ ഇമ്പോർട്ട് എൻഡ്പോയിന്റിനെ കബളിപ്പിക്കാനാവില്ല — discover നടത്തിയതിന് ശേഷം ലൈവ് ടോക്കൺ മാറിയിട്ടുണ്ടെങ്കിൽ, ഫിംഗർപ്രിന്റ് ഇനി പൊരുത്തപ്പെടില്ല, ക്രെഡൻഷ്യൽ ഒഴിവാക്കപ്പെടും.

ഇതുവരെ ഓട്ടോമേഷൻ അപ്ഡേറ്റ് ചെയ്തിട്ടില്ലാത്ത ഓപ്പറേറ്റർമാർക്കായി `OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` env ഫ്ലാഗ് v3.8.5-ലെ പ്രവർത്തനം നിലനിർത്തുന്നു. v3.9-ൽ ഇത് നീക്കംചെയ്യും.

**ഞങ്ങൾ ഇത് നിലനിർത്തുന്നതിന്റെ കാരണം**: ഇതിനകം Zed ഉപയോഗിക്കുന്നവർക്കും തങ്ങളുടെ പ്രൊവൈഡർ കീകൾ വീണ്ടും പേസ്റ്റ് ചെയ്യാതെ OmniRoute-ലേക്ക് പകർത്താൻ ആഗ്രഹിക്കുന്നവർക്കും ഏറ്റവും സൗഹൃദപരമായ ഓൺബോർഡിംഗ് മാർഗമാണ് Zed ഇമ്പോർട്ട്.

## §3 — `execFile` / `spawn` / ഉയർന്ന അധികാരമുള്ള PowerShell (`21843.js`)

**സോഴ്സ് ഫയലുകൾ**: `src/mitm/systemCommands.ts`.

**ഫ്ലാഗ് ചെയ്തതിന്റെ കാരണം**: ഈ ചങ്ക് `execFileWithPassword`,
`runElevatedPowerShell`, പങ്കിട്ട `quotePowerShell` ഹെൽപ്പർ എന്നിവ വീണ്ടും എക്സ്പോർട്ട് ചെയ്യുന്നു. Socket.dev-ന്റെ AI ക്ലാസിഫയർ അവയെ പൊതുവായ ഒരു "ഹോസ്റ്റ് എക്സിക്യൂഷൻ + പ്രിവിലേജ് എലിവേഷൻ ടൂൾകിറ്റ്" ആയി കാണുന്നു. OmniRoute-നുള്ളിൽ അവ MITM സർട്ടിഫിക്കറ്റ് ഇൻസ്റ്റാൾ പാത്ത് (§1), `sudo` കമാൻഡ് എക്സിക്യൂഷനുവേണ്ടിയുള്ള `execFileWithPassword` എന്നിവയിൽ മാത്രമാണ് ഉപയോഗിക്കുന്നത്.

**v3.8.6 ലഘൂകരണം**:

- `runElevatedPowerShell` റീഫാക്ടർ (§1 കാണുക).
- `runElevatedPowerShell`, `execFileWithPassword` എന്നിവയുടെ രണ്ടിടത്തുമുള്ള ഇൻലൈൻ `SECURITY-AUDITOR-NOTE:` ബ്ലോക്ക്, അനുവദനീയ ലിസ്റ്റിലുള്ള കോളർമാരെയും നിശ്ചയിച്ച എക്സിക്യൂട്ടബിൾ ലിസ്റ്റിനെയും രേഖപ്പെടുത്തുന്നു.
- `execFileWithPassword`-ലെ `spawn()` കോൾ, ഹെൽപ്പറിന് സ്വീകരിക്കാൻ അനുമതിയുള്ള എക്സിക്യൂട്ടബിളുകളുടെ അനുവദനീയ ലിസ്റ്റിനൊപ്പം ഒരു `nosemgrep` മാർക്കർ ഉൾക്കൊള്ളുന്നു — ഉപയോക്തൃ ഇൻപുട്ടിൽ നിന്ന് `finalCommand`/`finalArgs`-ലേക്ക് **യാതൊരു പാത്തും ഇല്ല**.

## §4 / §6 — 9router സർവീസ് സൂപ്പർവൈസർ (`api/services/9router/{start,restart}/route.js`)

**സോഴ്സ് ഫയലുകൾ**:

- `src/app/api/services/9router/_lib.ts` — സൂപ്പർവൈസർ ഫാക്ടറി.
- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`.
- `src/lib/services/ServiceSupervisor.ts` — പൊതുവായ spawn / ഹെൽത്ത്-പോൾ / ലോഗ്-ബഫർ.

**ട്രിഗർ**: ലോക്കൽ ഡാഷ്ബോർഡിലെ എംബെഡഡ് സർവീസസ് പേജിൽ ഉപയോക്താവ് "ഇൻസ്റ്റാൾ ചെയ്യുക" / "ആരംഭിക്കുക" ക്ലിക്ക് ചെയ്യുന്നു.

**നിലവിൽത്തന്നെയുള്ള സംരക്ഷണങ്ങൾ**:

- `src/server/authz/routeGuard.ts` അനുസരിച്ച് എല്ലാ `/api/services/*` റൂട്ടുകളും LOCAL_ONLY ആണ് (കർശന നിയമം #17). ഏതൊരു auth പരിശോധനയ്ക്കും മുമ്പ് ലൂപ്പ്ബാക്ക് നിർബന്ധമാക്കുന്നു — ചോർന്ന JWT ഉപയോഗിച്ചുപോലും അവയിലെത്താനാവില്ല.
- 9router DB വരി `status='not_installed', auto_start=0` ആയി സീഡ് ചെയ്തിരിക്കുന്നു (`src/lib/db/migrations/071_services.sql:19` കാണുക). ആദ്യ ലോഞ്ചിൽ സർവീസ് **ആരംഭിക്കില്ല**.
- `src/lib/services/installers/ninerouter.ts`-ലെ `resolveSpawnArgs(apiKey, PORT)` മടക്കിനൽകുന്ന ബൈനറി പാത്ത് ഉപയോഗിച്ചാണ് `spawn()` വിളിക്കുന്നത്; ഇത് പിന്തുണയ്ക്കുന്ന ബൈനറികളുടെ ഒരു സ്ഥിരമായ അനുവദനീയ ലിസ്റ്റാണ്.
- Stdout/stderr മെമ്മറിയിൽ ബഫർ ചെയ്യുന്നു (5 MB പരിധി, `_lib.ts` കാണുക) — ഡാഷ്ബോർഡിൽ നിന്ന് ഉപയോക്താവ് ലോഗിംഗ് പ്രവർത്തനക്ഷമമാക്കാത്തിടത്തോളം ഡിസ്കിലേക്ക് എഴുതില്ല.

**v3.8.6 ലഘൂകരണം**: പ്രവർത്തനപരമായ മാറ്റമില്ല. പ്രിവിലേജ്ഡ് പാത്തുകൾ ബണ്ടിലിൽ നിന്ന് ഭൗതികമായി നീക്കംചെയ്യാൻ ആഗ്രഹിക്കുന്ന ഉപയോക്താക്കൾക്കായി മിനിമൽ ബിൽഡ് പ്രൊഫൈൽ (`OMNIROUTE_BUILD_PROFILE=minimal`), `src/lib/services/installers/ninerouter.ts`-നെ ഒരു സ്റ്റബ് ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു.

**ഞങ്ങൾ ഇത് നിലനിർത്തുന്നതിന്റെ കാരണം**: 9router, ഓപ്ഷണലായി ലോക്കലിൽ ഇൻസ്റ്റാൾ ചെയ്യാവുന്ന ഒരു അനുബന്ധ സർവീസാണ് (WordPress-ശൈലിയിലുള്ള പ്ലഗിൻ എന്ന് കരുതുക) — കർശനമായ opt-in.

## §5 — OmniRoute Cloud Sync ക്രെഡൻഷ്യൽ റൈറ്റ്-ബാക്ക് (`api/keys/[id]/route.js`)

**സോഴ്സ് ഫയലുകൾ**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`.
- `src/app/api/keys/[id]/route.ts` — `syncKeysToCloudIfEnabled()` അഭ്യർത്ഥിക്കുന്നു.

**ട്രിഗർ**: `isCloudEnabled()` `true` നൽകുന്നു (ഡാഷ്ബോർഡിൽ നിന്ന് സജ്ജീകരിച്ചത്) **കൂടാതെ**
`CLOUD_URL` കോൺഫിഗർ ചെയ്തിരിക്കുന്നു. ഇവ രണ്ടും പ്രവർത്തനരഹിതമാണെങ്കിൽ, Cloud
എൻഡ്പോയിന്റിലേക്ക് ഔട്ട്ബൗണ്ട് നെറ്റ്വർക്ക് കോൾ നടത്തില്ല.

**v3.8.5-ലെ പ്രവർത്തനം (Socket.dev ശരിയായ രീതിയിൽ കണ്ടെത്തിയ ബഗ്)**:

`cloudUpdatedAt > localUpdatedAt` ആയിരിക്കുമ്പോൾ, Cloud പ്രതികരണത്തിൽ നിന്നുള്ള
`accessToken`, `refreshToken`, `providerSpecificData` എന്നിവ ഉപയോഗിച്ച്
`updateLocalTokens()` നിലവിലുള്ള മൂല്യങ്ങൾ പുനഃരേഖപ്പെടുത്തി. HMAC ഇല്ല,
സിഗ്നേച്ചർ ഇല്ല, ചെക്ക്സം ഇല്ല. തെറ്റായി കോൺഫിഗർ ചെയ്തതോ ദോഷകരമായതോ ആയ
`CLOUD_URL`-ന് (അല്ലെങ്കിൽ ചാനലിലെ ഒരു MITM-ന്) പ്രൊവൈഡർ OAuth ടോക്കണുകൾ
നിശ്ശബ്ദമായി മാറ്റിസ്ഥാപിക്കാമായിരുന്നു.

**v3.8.6-ലെ പ്രതിവിധി**:

1. **HMAC പരിശോധന**: JSON പാഴ്സ് ചെയ്യുന്നതിന് മുമ്പ് `verifyCloudSignature(rawBody, sigHeader)`
   `X-Cloud-Sig` ഹെഡർ (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`) പരിശോധിക്കുന്നു. സീക്രട്ട് സജ്ജീകരിച്ചിട്ടുണ്ടെങ്കിൽ, സിഗ്നേച്ചർ
   നിർബന്ധമാണ്. ഇല്ലെങ്കിൽ (ലെഗസി മോഡ്), ഒരു മുന്നറിയിപ്പ് ലോഗ് ചെയ്യുകയും
   പ്രതികരണം സ്വീകരിക്കുകയും ചെയ്യും — v3.9 മുതൽ സീക്രട്ട് നിർബന്ധമാകും.
2. **രഹസ്യ ഫീൽഡുകൾക്കുള്ള ഓപ്റ്റ്-ഇൻ**: `OMNIROUTE_CLOUD_SYNC_SECRETS=true`
   ആയിരിക്കുമ്പോൾ **മാത്രമേ** `accessToken` / `refreshToken` /
   `providerSpecificData` എന്നിവ പുനഃരേഖപ്പെടുത്തുകയുള്ളൂ. ഡിഫോൾട്ട് മോഡ്
   ക്രെഡൻഷ്യൽ അല്ലാത്ത മെറ്റാഡാറ്റ (`expiresAt`, `status`, `lastError*`,
   `rateLimitedUntil`, `updatedAt`) മാത്രം സിങ്ക് ചെയ്യുന്നു. റിമോട്ട് ടോക്കൺ
   സിങ്കിനെ ആശ്രയിച്ചിരുന്ന ഉപയോക്താക്കൾക്ക് ഇത് ഒരു **ബ്രേക്കിംഗ് മാറ്റമാണ്**
   — അവർ വ്യക്തമായി ഓപ്റ്റ്-ഇൻ ചെയ്യണം.

**ഞങ്ങൾ ഇത് നിലനിർത്തുന്നതിന്റെ കാരണം**: ഒരു OmniRoute Cloud ടെനന്റിന് ടീം
ക്രെഡൻഷ്യലുകൾ കേന്ദ്രീകരിക്കാനുള്ള ഏക മാർഗമാണ് Cloud Sync. ഈ പരിഹാരം ഭീഷണി
മാതൃകയെ സുതാര്യമാക്കുന്നു: "സെർവർ ഒപ്പിടുന്നു, ക്ലയന്റ് പരിശോധിക്കുന്നു,
ഓപ്പറേറ്റർ ഓപ്റ്റ്-ഇൻ ചെയ്യുന്നു."

## ബിൽഡ് പ്രൊഫൈൽ: `minimal`

Socket-സൗഹൃദ ആർട്ടിഫാക്റ്റ് ആവശ്യമുള്ള ഉപയോക്താക്കൾ ഇങ്ങനെ ബിൽഡ് ചെയ്യുക:

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

webpack `NormalModuleReplacementPlugin` നാല് മൊഡ്യൂളുകളെ സ്റ്റബുകളിലേക്ക്
അലിയാസ് ചെയ്യുന്നു:

| മൊഡ്യൂൾ                                     | സ്റ്റബ്                                          |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

ഓരോ സ്റ്റബും അതേ ഇന്റർഫേസ് എക്സ്പോർട്ട് ചെയ്യുന്നു, എന്നാൽ റൺടൈമിൽ ഓരോ
ഫങ്ഷനും `featureDisabledError(name)` ത്രോ ചെയ്യുന്നു. പ്രവർത്തനരഹിതമാക്കിയ
മൊഡ്യൂളിനെ ആശ്രയിക്കുന്ന റൂട്ടുകൾ, സെൻസിറ്റീവ് കോഡ് പാത്ത് സജീവമാക്കുന്നതിന്
പകരം വ്യക്തമായ സന്ദേശത്തോടുകൂടി HTTP 503 നൽകുന്നു.

തത്ഫലമായുണ്ടാകുന്ന ബണ്ടിൽ `omniroute-secure` ആയി പ്രസിദ്ധീകരിക്കാനാണ്
ഉദ്ദേശിച്ചിരിക്കുന്നത്. പ്രസിദ്ധീകരണ നടപടിക്രമത്തിനായി
`docs/ops/PUBLISHING_SECURE.md` കാണുക.
