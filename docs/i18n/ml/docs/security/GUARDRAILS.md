> **അവസാനം അപ്ഡേറ്റ് ചെയ്തത്:** 2026-08-29 — v3.8.51 (വീഡിയോ ബ്രിഡ്ജ് ട്രാൻസ്ക്രിപ്റ്റ് പ്രൂവനെൻസ് കോളർ-പ്രഖ്യാപിച്ചതാണ്,
> ഇതുവരെ സെർവർ-പരിശോധിച്ചിട്ടില്ല — #11661 അനുസരിച്ച് വ്യക്തമാക്കിയത്)

OmniRoute-നും അപ്സ്ട്രീം പ്രൊവൈഡർമാർക്കും ഇടയിലുള്ള അതിർത്തിയിൽ സുരക്ഷ, നയം, ഉള്ളടക്ക പരിവർത്തനങ്ങൾ എന്നിവ ഗാർഡ്റെയിലുകൾ നടപ്പിലാക്കുന്നു. ഓരോ ഗാർഡ്റെയിലിനും അഭ്യർത്ഥന പേലോഡുകളും (`preCall`) അപ്സ്ട്രീം പ്രതികരണങ്ങളും (`postCall`) പരിശോധിക്കാൻ (ഓപ്ഷണലായി നിരസിക്കുകയോ, രൂപാന്തരപ്പെടുത്തുകയോ, വ്യാഖ്യാനിക്കുകയോ ചെയ്യാം) കഴിയും.

സിസ്റ്റം **ഫെയിൽ-ഓപ്പൺ** ആണ്: ഒരു ഗാർഡ്റെയിൽ പ്രവർത്തിക്കുമ്പോൾ പിശക് സംഭവിച്ചാൽ, രജിസ്ട്രി പിശക് രേഖപ്പെടുത്തുകയും അഭ്യർത്ഥന പരാജയപ്പെടുത്തുന്നതിന് പകരം അടുത്ത ഗാർഡ്റെയിലുമായി മുന്നോട്ട് പോകുകയും ചെയ്യുന്നു. തടയുന്നത് ഒരു വ്യക്തമായ തീരുമാനമാണ് (`block: true`), ഒരിക്കലും ഒരു അപകടമല്ല.

## ബിൽറ്റ്-ഇൻ ഗാർഡ്റെയിലുകൾ

ഇംപോർട്ട് ചെയ്യുമ്പോൾ രജിസ്ട്രി ആറ് ഗാർഡ്റെയിലുകൾ മുൻഗണനാ ക്രമത്തിൽ സ്വയമേവ ലോഡ് ചെയ്യുന്നു
(കാണുക `registry.ts` → `registerDefaultGuardrails()`):

| മുൻഗണന | പേര്                | ഘട്ടം(ങ്ങൾ)    | ഫയൽ                   |
| ------ | ------------------- | -------------- | --------------------- |
| `5`    | `vision-bridge`     | `preCall`      | `visionBridge.ts`     |
| `6`    | `audio-bridge`      | `preCall`      | `audioBridge.ts`      |
| `7`    | `video-bridge`      | `preCall`      | `videoBridge.ts`      |
| `10`   | `pii-masker`        | `pre` + `post` | `piiMasker.ts`        |
| `20`   | `prompt-injection`  | `preCall`      | `promptInjection.ts`  |
| `95`   | `credential-masker` | `pre` + `post` | `credentialMasker.ts` |

കുറഞ്ഞ മുൻഗണനാ നമ്പറുകൾ **ആദ്യം** പ്രവർത്തിക്കുന്നു.

### വിഷൻ ബ്രിഡ്ജ് (`visionBridge.ts`) — മോഡാലിറ്റി ബ്രിഡ്ജ് PR-1

**നോൺ-വിഷൻ മോഡലുകളെ** ലക്ഷ്യമിട്ടുള്ള ഇമേജ് അടങ്ങിയ അഭ്യർത്ഥനകളെ തടസ്സപ്പെടുത്തുകയും, ഒന്നുകിൽ മുഴുവൻ അഭ്യർത്ഥനയും വിഷൻ ശേഷിയുള്ള ഒരു മോഡലിലേക്ക് റീറൂട്ട് ചെയ്യുകയോ അല്ലെങ്കിൽ അപ്സ്ട്രീം കോളിന് മുമ്പ് കോൺഫിഗർ ചെയ്യാവുന്ന ഒരു വിഷൻ മോഡൽ നിർമ്മിച്ച ടെക്സ്റ്റ് വിവരണങ്ങൾ ഉപയോഗിച്ച് ഇമേജ് ഭാഗങ്ങൾ മാറ്റിസ്ഥാപിക്കുകയോ ചെയ്യുന്നു. ഇത് ടെക്സ്റ്റ്-മാത്രം പ്രൊവൈഡർമാർക്ക് മൾട്ടിമോഡൽ പേലോഡുകൾ സുതാര്യമായി കൈകാര്യം ചെയ്യാൻ അനുവദിക്കുന്നു.

പ്രവാഹം:

1. ടാർഗെറ്റ് മോഡൽ ഇതിനകം വിഷൻ പിന്തുണയ്ക്കുന്നുണ്ടെങ്കിൽ ഒഴിവാക്കുക (നിർബന്ധിത-ബ്രിഡ്ജ് ലിസ്റ്റിൽ `isVisionBridgeForcedModel` ഉണ്ടെങ്കിൽ ഒഴികെ).
2. `extractImageParts(messages)` (`visionBridgeHelpers.ts`) വഴി ഇമേജ് ഭാഗങ്ങൾ വേർതിരിച്ചെടുക്കുക, ഇത് `open-sse/utils/mediaParts.ts` എന്നതിലെ **യൂണിഫൈഡ് മീഡിയ ഡിറ്റക്ടർ** `detectMediaParts()`-ലേക്ക് കൈമാറുന്നു — കോംബോ കോംപാറ്റിബിലിറ്റി ഫിൽട്ടറുമായി പങ്കിടുന്ന ഒരൊറ്റ സത്യത്തിന്റെ ഉറവിടം. `replaceImageParts` തിരികെ ചേർക്കാൻ കഴിയുന്ന രൂപങ്ങളുടെ ടോപ്പ്-ലെവൽ ഭാഗങ്ങളിലേക്ക് എക്സ്ട്രാക്ഷൻ അനുവദിച്ചിരിക്കുന്നു (എക്സ്ട്രാക്റ്റ്↔റീപ്ലേസ് കരാർ): OpenAI `image_url`, Anthropic base64 `source.type:"base64"`, Anthropic URL `source.type:"url"`, കൂടാതെ Responses API `input_image`. നെസ്റ്റഡ് ഹിറ്റുകളും ഇൻഡിക്കേറ്റർ-മാത്രം രൂപങ്ങളും കോംബോ-ഫിൽട്ടർ മെറ്റീരിയലാണ്, അവ ഒരിക്കലും വേർതിരിച്ചെടുക്കില്ല. ഒന്നും കണ്ടെത്തിയില്ലെങ്കിൽ ഒഴിവാക്കുക.
3. `resolveVisionBridgeRuntimeSettings()` (`src/shared/constants/modalityBridgeDefaults.ts`) വഴി റൺടൈം കോൺഫിഗറേഷൻ പരിഹരിക്കുക: പുതിയ `modalityBridge*` ക്രമീകരണ കീകളാണ് വിജയിക്കുന്നത്; പഴയ `visionBridge*` കീകളാണ് **ഒരു സൈക്കിൾ ഫാൾബാക്ക്** (റോൾബാക്ക് വിൻഡോ). ബ്രിഡ്ജ് പ്രവർത്തനരഹിതമാകുമ്പോൾ ഏതെങ്കിലും മീഡിയ ട്രാവേഴ്സലിന് മുമ്പ് ഒഴിവാക്കുക.
4. മോഡ് സെലക്ടർ (`modalityBridgeVisionMode`, താഴെയുള്ള പട്ടിക കാണുക) റീറൂട്ട് ചെയ്യണോ വിവരിക്കണോ എന്ന് തീരുമാനിക്കുന്നു. റീറൂട്ട് ചെയ്യുന്നത് `model` മാത്രം മാറ്റിസ്ഥാപിച്ച `modifiedPayload` തിരികെ നൽകുന്നു, കൂടാതെ മെറ്റാ `{ rerouted, fromModel, toModel, imagesKept }` ഉം.
5. വിവരണ പാത: `maxImages` എന്നതിൽ ചിത്രങ്ങൾ പരിമിതപ്പെടുത്തുക, ടാസ്ക്-അവബോധമുള്ള പ്രോംപ്റ്റ് രചിക്കുക, വിവരണ കാഷെ പരിശോധിക്കുക, വിഷൻ മോഡലിനെ **സമാന്തരമായി** വിളിക്കുക (`Promise.allSettled`), കൂടാതെ `[Image N]: <description>` ടെക്സ്റ്റ് ഭാഗങ്ങൾ അവയുടെ സ്ഥാനത്ത് ചേർക്കുക. ഒരു പരാജയപ്പെട്ട വിവരണം `null` നൽകുന്നു, യഥാർത്ഥ ഇമേജ് ഭാഗം **സംരക്ഷിക്കപ്പെടുന്നു** (#4012) — ഓരോ വിവരണവും പരാജയപ്പെട്ട കോംബോ വിവരണ പാതയിൽ ഒഴികെ, അവിടെ സ്ഥിരീകരിച്ച നോൺ-വിഷൻ അപ്സ്ട്രീമിന് പകരം `(ലഭ്യമല്ല — വിഷൻ ശേഷിയുള്ള പ്രൊവൈഡർ കണക്ട് ചെയ്തിട്ടില്ല)` എന്ന സ്റ്റബ് ലഭിക്കുന്നു (#8430).
6. `modifiedPayload` + മെറ്റാ (`imagesProcessed`, `descriptions`, `processingTimeMs`, `visionModel`) തിരികെ നൽകുക.

| `reroute`  |           | റീറൂട്ട് നിർബന്ധമാക്കുക: ക്രെഡൻഷ്യൽ ചെയ്ത മോഡൽ സംരക്ഷിക്കുന്ന ഗാർഡ് ഒഴിവാക്കുന്നു. റീറൂട്ട്-**ടാർഗെറ്റ്** ക്രെഡൻഷ്യൽ ഗാർഡ് ഇപ്പോഴും ബാധകമാണ് — ഉപയോഗിക്കാവുന്ന വിഷൻ ടാർഗെറ്റ് ഇല്ലെങ്കിൽ, അഭ്യർത്ഥന വിവരണത്തിലേക്ക് പോകുന്നു, അതിനാൽ അസംസ്കൃത ചിത്രങ്ങൾ ടെക്സ്റ്റ്-മാത്രം ബാക്കെൻഡിൽ എത്തുകയില്ല (#8430). |

ഫോഴ്സ്ഡ് മോഡുകൾ ഓട്ടോ ഹ്യൂറിസ്റ്റിക് പ്രവർത്തിക്കുന്നതിന് **മുമ്പ്** ഷോർട്ട്-സർക്യൂട്ട് ചെയ്യുന്നു; `auto` സ്വഭാവം PR-1 ന് മുമ്പുള്ള ഗാർഡ്റെയിലിന് സമാനമാണ്.

#### ടാസ്ക്-അവബോധമുള്ള വിവരണ പ്രോംപ്റ്റ് (`modalityBridgeVisionTaskAware`)

ഡിഫോൾട്ട് **true**. `composeVisionPrompt()` (`visionBridgeHelpers.ts`) **അവസാന ഉപയോക്തൃ സന്ദേശത്തിന്റെ** ടെക്സ്റ്റ് (500 പ്രതീകങ്ങളായി ചുരുക്കിയത്) അടിസ്ഥാന വിവരണ പ്രോംപ്റ്റിലേക്ക് ചേർക്കുന്നു, ഇത് ഉപയോക്താവ് യഥാർത്ഥത്തിൽ ചോദിച്ച കാര്യങ്ങളിലേക്ക് വിവരണം നയിക്കുകയും (codex-vision-proxy പാറ്റേൺ) ദൃശ്യമായ ടെക്സ്റ്റ് ട്രാൻസ്ക്രൈബ് ചെയ്യാൻ വിഷൻ മോഡലിനോട് ആവശ്യപ്പെടുകയും ചെയ്യുന്നു. ഫ്ലാഗ് ഓഫാണെങ്കിൽ — അല്ലെങ്കിൽ ഉപയോക്തൃ ടെക്സ്റ്റ് ഇല്ലെങ്കിൽ — അടിസ്ഥാന പ്രോംപ്റ്റ് മാറ്റമില്ലാതെ ഉപയോഗിക്കുന്നു.

സെൽഫ്-ലൂപ്പിന്റെ സ്വന്തം OpenAI-അനുയോജ്യമായ അഭ്യർത്ഥന (`callVisionModelSingle()`
`visionBridgeHelpers.ts`-ൽ) എല്ലായ്പ്പോഴും `image_url.detail: "high"` എന്ന് അഭ്യർത്ഥിക്കുന്നു —
യാതൊരു വ്യവസ്ഥയുമില്ലാതെ, എല്ലാ കോളർ/പ്രൊവൈഡർമാർക്കും, ഒരു ക്ലയിന്റ് സിഗ്നലിലും ഇത് ഗേറ്റ് ചെയ്തിട്ടില്ല.
കുറഞ്ഞ-വിശദാംശങ്ങളുള്ള സാമ്പിൾ ചെയ്യുന്നത് OCR കൃത്യതയെ ഈ പ്രോംപ്റ്റ് ആവശ്യപ്പെടുന്ന ടെക്സ്റ്റ്-ട്രാൻസ്ക്രിപ്ഷൻ
ടാസ്ക്കിന് കൃത്യമായി കുറയ്ക്കുന്നു, അതിനാൽ യഥാർത്ഥ ഇൻബൗണ്ട് അഭ്യർത്ഥന ഉപയോഗിച്ച വിശദാംശങ്ങളുടെ നിലവാരം പരിഗണിക്കാതെ തന്നെ
വിവരണ കോൾ എല്ലായ്പ്പോഴും ഉയർന്ന വിശദാംശങ്ങൾ ആവശ്യപ്പെടുന്നു. ഇത് ആന്തരിക വിവരണ അഭ്യർത്ഥന ബോഡിയെ മാത്രമേ ബാധിക്കുകയുള്ളൂ;
OmniRoute കോളറുടെ സ്വന്തം `image_url.detail` പ്രാഥമിക അഭ്യർത്ഥനയിൽ എങ്ങനെ ഫോർവേഡ് ചെയ്യുന്നു എന്നതിനെ ഇത് മാറ്റുന്നില്ല —
ആ ഡിഫോൾട്ട് പ്രത്യേകം പ്രയോഗിക്കുന്നു, കൂടാതെ കണ്ടെത്തിയ OpenCode ക്ലയിന്റുകൾക്ക് മാത്രം,
`defaultImageDetail()` (`open-sse/handlers/chatCore/upstreamBody.ts`) എന്നതിൽ.
വിവരണ സെൽഫ്-ലൂപ്പിന്റെ Anthropic വയർ-ഫോർമാറ്റ് ബ്രാഞ്ചിന് `detail` ഫീൽഡ് ഇല്ല,
രണ്ട് ഡിഫോൾട്ടുകളും ഇതിനെ ബാധിക്കുന്നില്ല.

#### ഔട്ട്പുട്ട് ക്യാപ് വിവരിക്കുക (`modalityBridgeVisionMaxChars`)

| കീ                             | ഡിഫോൾട്ട് | ശ്രേണി                   |
| ------------------------------ | --------- | ------------------------ |
| `modalityBridgeVisionMaxChars` | `0`       | `0` അല്ലെങ്കിൽ 100–50000 |

`0` (ഡിഫോൾട്ട്) എന്നാൽ **ക്യാപ് ഇല്ല** — `callVisionModel()` നൽകുന്ന വിവരണം മാറ്റങ്ങളില്ലാതെ കൈമാറുന്നു,
നിലവിലുള്ള സ്വഭാവം നിലനിർത്തുന്നു. 100–50000 ശ്രേണിയിലെ ഏതൊരു മൂല്യവും വിവരണത്തെ
`…` സഫിക്സ് ഉപയോഗിച്ച് ചെറുതാക്കുന്നു, അത് `[Image N]: <description>`
(`VisionBridgeGuardrail.preCall()` `src/lib/guardrails/visionBridge.ts`-ൽ) ആയി തിരികെ ചേർക്കുന്നതിന് മുമ്പ്.
ഡൗൺസ്ട്രീം മോഡലിന് പൂർണ്ണമായ ട്രാൻസ്ക്രിപ്ഷൻ ആവശ്യമുള്ള വിശദാംശങ്ങൾ നിറഞ്ഞ OCR ടാസ്ക്കുകൾക്കായി ഇത് വർദ്ധിപ്പിക്കുക;
ചാറ്റി വിഷൻ മോഡലുകളിൽ ടോക്കൺ ഉപയോഗം പരിമിതപ്പെടുത്താൻ ഇത് കുറയ്ക്കുക.
ഡാഷ്ബോർഡ് ഫീൽഡ് വിഷൻ ടാബിന്റെ അഡ്വാൻസ്ഡ് പാനലിൽ സ്ഥിതിചെയ്യുന്നു
(`modality-bridge-max-chars` `ModalityBridgeVisionTab.tsx`-ൽ) കൂടാതെ 1-നും 99-നും ഇടയിലുള്ള ഏതൊരു മൂല്യവും
100 ഫ്ലോറിലേക്ക് ക്ലാംപ് ചെയ്യുന്നു, അതേസമയം ഒരു വ്യക്തമായ `0` മാറ്റമില്ലാതെ വിടുന്നു —
`0` എന്നത് അതിൻ്റേതായ ഒരു സാധുവായ Zod മൂല്യമാണ്
(`z.union([z.literal(0), z.number().int().min(100).max(50000)])`),
വെറും "സെറ്റ് ചെയ്യാത്ത" ഡിഫോൾട്ട് മാത്രമല്ല.

#### കാഷെ വിവരിക്കുക (`modalityBridge/bridgeCache.ts`)

വിവരണ ഔട്ട്പുട്ടുകൾക്കായുള്ള ഇൻ-മെമ്മറി LRU + TTL കാഷെ, പ്രോസസ്സ്-വൈഡ് പങ്കിടുന്നു.
കീ = `sha256(imageRef + composedPrompt + configuredBridgeModel)`
ലെങ്ത്-പ്രിഫിക്സ് ഫ്രെയിമിംഗ് സഹിതം (ഫീൽഡ്-ബൗണ്ടറി കൂട്ടിയിടികൾ ഇല്ല).
മോഡൽ ഘടകം **കോൺഫിഗർ ചെയ്ത** ബ്രിഡ്ജ് മോഡലാണ്, യഥാർത്ഥത്തിൽ ഉത്തരം നൽകിയ മോഡലല്ല —
`callVisionModel` ആന്തരികമായി തിരികെ പോകാം, കൂടാതെ ഓരോ ശ്രമത്തിനും കീ ചെയ്യുന്നത് കാഷെയെ വിഭജിക്കും.
പരാജയപ്പെട്ട വിവരണങ്ങൾ ഒരിക്കലും കാഷെ ചെയ്യുന്നില്ല. ക്രമീകരണങ്ങൾ:

| കീ                              | ഡിഫോൾട്ട് | ശ്രേണി  |
| ------------------------------- | --------- | ------- |
| `modalityBridgeCacheEnabled`    | `true`    | —       |
| `modalityBridgeCacheTtlMinutes` | `60`      | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`     | 10–5000 |

#### റിമോട്ട് ഇമേജ് നോർമലൈസേഷൻ (സെൽഫ്-ലൂപ്പ് വിവരിക്കുക/base64 ഫെച്ച്)

ബ്രിഡ്ജ് ഒരു **റിമോട്ട്** ചിത്രം സ്വയം ഫെച്ച് ചെയ്യുമ്പോൾ — Anthropic വിവരണ സെൽഫ്-കോൾ
കൂടാതെ claude-wire-format base64 പരിവർത്തനം (`ensureBase64ImagesForClaudeWire`),
രണ്ടും `visionBridgeHelpers.ts`-ലെ `fetchRemoteImageAsDataUri()` വഴി —
ലഭിക്കുന്ന ഡാറ്റ URI `normalizeDataUri()`
(`open-sse/utils/imageNormalize.ts`) വഴി കടന്നുപോകുന്നു, അതിനുശേഷം വിഷൻ-മോഡൽ
അഭ്യർത്ഥനയിൽ ഉൾച്ചേർക്കുന്നു. വലുപ്പമുള്ള ചിത്രങ്ങൾ **2048px നീളമുള്ള അരികിലേക്ക്**
ചെറുതാക്കുന്നു (OpenAI/Anthropic ഇതിനകം സെർവർ-സൈഡിൽ പ്രയോഗിക്കുന്ന വലുപ്പം മാറ്റുന്ന ക്യാപ്പുമായി പൊരുത്തപ്പെടുന്നു),
ഇത് വിഷൻ മോഡൽ കാണുന്നതിനെ മാറ്റാതെ അപ്ലോഡ് ബൈറ്റുകൾ/ലേറ്റൻസി കുറയ്ക്കുന്നു.
വലുപ്പം മാറ്റാൻ `sharp` ഉപയോഗിക്കുന്നു, ഡൈനാമിക് ഇംപോർട്ട് വഴി ലോഡ് ചെയ്യുന്നു:
അതിൻ്റെ നേറ്റീവ് ബൈനറി ലോഡ് ചെയ്യാൻ കഴിയാത്ത ഒരു പ്ലാറ്റ്ഫോമിൽ, `normalizeDataUri()`
**ഒരിക്കലും പിശക് വരുത്തുന്നില്ല** — അത് യഥാർത്ഥ ബൈറ്റുകളുടെ ഒരു പാസ്ത്രൂവിലേക്ക് തിരികെ പോകുന്നു,
അതിനാൽ വിവരണ/base64-പരിവർത്തന പാത എല്ലായ്പ്പോഴും പ്രവർത്തിക്കുന്നു.
ചിത്രമല്ലാത്ത ബൈറ്റുകൾ (ഡീകോഡ് ചെയ്യാൻ കഴിയുന്ന ഒരു ചിത്രം തിരികെ നൽകാത്ത ഒരു ഫെച്ച്)
മാറ്റങ്ങളില്ലാതെ കൈമാറുന്നു. ഈ നോർമലൈസേഷൻ ബ്രിഡ്ജ് അതിൻ്റെ സ്വന്തം സെൽഫ്-കോളിനായി ഫെച്ച് ചെയ്യുന്ന ചിത്രങ്ങളിലേക്ക്
പരിമിതപ്പെടുത്തിയിരിക്കുന്നു — കോളറുടെ റോ പാസ്ത്രൂ പേലോഡിൽ ഇത് ഒരിക്കലും പ്രയോഗിക്കുന്നില്ല,
ഓപ്റ്റ്-ഇൻ-മാത്രം മ്യൂട്ടേഷൻ തത്വവുമായി പൊരുത്തപ്പെടുന്നു (ഹാർഡ് റൂൾ #20).

കൂടാതെ ഓഡിയോ ബ്രിഡ്ജ് ഉപയോഗിക്കുന്ന `modalityBridgeAudio*` ഗ്രൂപ്പ്.
മൈഗ്രേഷൻ `141_modality_bridge_settings.sql` നിലവിലുള്ള ലെഗസി
`visionBridge*` മൂല്യങ്ങൾ പൊരുത്തപ്പെടുന്ന പുതിയ കീകളിലേക്ക് പകർത്തുന്നു
(ഇഡെംപോട്ടന്റ്, ഒരു ഓപ്പറേറ്റർ-സെറ്റ് `modalityBridge*` മൂല്യം ഒരിക്കലും ഓവർറൈറ്റ് ചെയ്യുന്നില്ല);
ലെഗസി കീകൾ ഒരു റിലീസ് സൈക്കിളിനായി ഒരു റീഡ് ഫാൾബാക്കായി സ്വീകരിക്കുന്നു.

#### ട്രാൻസ്പാരൻസി ഹെഡർ + സ്റ്റാറ്റസ്

വിവരണം-രൂപാന്തരപ്പെടുത്തിയ പ്രതികരണങ്ങളിൽ
`x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>`
( `modalityBridge/bridgeStats.ts`-ലെ `buildModalityBridgeHeader()` നിർമ്മിച്ചത്,
`src/sse/handlers/chatHelpers.ts`-ലെ `withModalityBridgeHeader()` സ്റ്റാമ്പ് ചെയ്തത്) അടങ്ങിയിരിക്കുന്നു.
റീറൂട്ട് ചെയ്ത അഭ്യർത്ഥനകൾക്ക് ഹെഡർ **ഇല്ല** — പേലോഡ് മാറ്റങ്ങളില്ലാതെയായിരുന്നു,
മോഡൽ സ്വാപ്പ് പ്രതികരണ ബോഡിയുടെ `model` ഫീൽഡിൽ ഇതിനകം ദൃശ്യമാണ്.

`GET /api/modality-bridge/stats` (മാനേജ്മെന്റ് ഓത്ത്, `GET /api/settings` എന്നതിന് സമാനമായ തലം)
`vision`, `audio`, `video` എന്നിവയ്ക്കായുള്ള ഇൻ-മെമ്മറി പെർ-മോഡാലിറ്റി കൗണ്ടറുകൾ
`{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs,
latencySamples, averageLatencyMs, lastUsedAt }` തിരികെ നൽകുന്നു.
`averageLatencyMs` അതിൻ്റെ ഡെനോമിനേറ്ററായി `latencySamples` ഉപയോഗിക്കുന്നു, എല്ലാ ശ്രമങ്ങളുമല്ല;
സമയമില്ലാത്ത ഒരു പ്രവർത്തനം പൂജ്യം-മില്ലിസെക്കൻഡ് സാമ്പിൾ ഉണ്ടാക്കുന്നില്ല.
`bridged` വിജയകരമായ പരിവർത്തനങ്ങൾക്കുള്ള ബാക്ക്വേർഡ്-കോംപാറ്റിബിൾ അലിയാസായി തുടരുന്നു;
പരാജയപ്പെട്ട ശ്രമങ്ങൾ ഇത് വർദ്ധിപ്പിക്കുന്നില്ല.
പ്രോസസ്സ് പുനരാരംഭിക്കുമ്പോൾ കൗണ്ടറുകൾ പുനഃസജ്ജമാക്കുന്നു
(ടെലിമെട്രി, അക്കൗണ്ടിംഗ് അല്ല).

#### ഡാഷ്ബോർഡ് കോൺഫിഗറേഷൻ

സമർപ്പിതമായ ഡാഷ്ബോർഡ് പേജ് `/dashboard/settings/modality-bridge` ആണ്. ഇതിലെ URL-അഡ്രസ്സബിൾ ആയ `Vision`, `Audio`, `Video` ടാബുകൾ `tab` മൂല്യം മാറ്റുമ്പോൾ ക്വറി പാരാമീറ്ററുകൾ നിലനിർത്തുന്നു. വിഷൻ ടാബ് പ്രവർത്തനക്ഷമത, മോഡ്, മോഡൽ തിരഞ്ഞെടുക്കൽ (ഓട്ടോമാറ്റിക് ഡിഫോൾട്ട് ഉൾപ്പെടെ), ടാസ്ക്-അവെയർ പ്രോംപ്റ്റിംഗ്, അഡ്വാൻസ്ഡ് ടൈംഔട്ട്/ഇമേജ്/ഡിസ്ക്രിപ്ഷൻ-ലെങ്ത്/കാഷെ പരിധികൾ, റൺടൈം കൗണ്ടറുകൾ, ഒരു ഗാർഡഡ് സാമ്പിൾ അഭ്യർത്ഥന എന്നിവ നൽകുന്നു. ഓഡിയോ ടാബും ലൈവ് ആണ്: ഇത് പ്രവർത്തനക്ഷമത, ഓട്ടോ ഉള്ള ഒരു STT-മാത്രം മോഡൽ പിക്കർ, ടൈംഔട്ട്/മാക്സ്-ക്ലിപ്പ് പരിധികൾ, ഓഡിയോ കൗണ്ടറുകൾ, ഒരു `input_audio` സാമ്പിൾ ടെസ്റ്റ് എന്നിവ നൽകുന്നു. വീഡിയോ ടാബ് പ്രവർത്തനക്ഷമമാണ്: ഇത് FFmpeg/ffprobe റൺടൈം സ്റ്റേറ്റ് റിപ്പോർട്ട് ചെയ്യുന്നു — നാല് വ്യക്തമായ UI സ്റ്റേറ്റുകളിൽ ഒന്ന് (`unknown` പ്രോബ് പ്രവർത്തിക്കുമ്പോഴോ പൂർത്തിയാക്കാൻ കഴിയാതിരിക്കുമ്പോഴോ, `restricted` ഒരു നോൺ-ലൂപ്പ്ബാക്ക് ഡാഷ്ബോർഡ് ഹോസ്റ്റിൽ പ്രോബ് ക്ലയിന്റ്-സൈഡിൽ ഒഴിവാക്കുമ്പോൾ, `unavailable` പ്രോബ് ചെയ്ത ശേഷം ലഭ്യമല്ലെന്ന് സ്ഥിരീകരിക്കുമ്പോൾ, അല്ലെങ്കിൽ FFmpeg/ffprobe പതിപ്പുകൾ സഹിതം `available`) — പ്രവർത്തനക്ഷമമാക്കൽ/മോഡൽ/ഫ്രെയിം/വീഡിയോ/ടൈംഔട്ട് പരിധികൾ നിലനിർത്തുന്നു, വിഷൻ-ശേഷിയുള്ള മോഡലുകളിലേക്ക് മോഡൽ പിക്കർ ഫിൽട്ടർ ചെയ്യുന്നു, കൂടാതെ വീഡിയോ കൗണ്ടറുകൾ നൽകുന്നു.

AI ക്രമീകരണങ്ങൾക്ക് കീഴിലുള്ള മുൻ വിഷൻ ബ്രിഡ്ജ് കാർഡ് പുതിയ പേജിലേക്കുള്ള ഒരു കോംപാറ്റിബിലിറ്റി ലിങ്കാണ്; ഇതിന് ഇനി ഫോമിന്റെ രണ്ടാമത്തെ പകർപ്പ് സ്വന്തമായില്ല. മീഡിയ പ്രൊവൈഡർമാർ നിലവിലുള്ള സ്പീച്ച്-ടു-ടെക്സ്റ്റ് പ്ലേഗ്രൗണ്ട് നീക്കം ചെയ്യാതെ തന്നെ ഇമേജ്-ടു-ടെക്സ്റ്റ്, സ്പീച്ച്-ടു-ടെക്സ്റ്റ് വർക്ക്ഫ്ലോകളെ അനുബന്ധ മോഡാലിറ്റി ബ്രിഡ്ജ് ടാബുകളിലേക്ക് ലിങ്ക് ചെയ്യുന്നു.

**സെൽഫ്-ലൂപ്പ് അഡ്മിഷൻ ബൈപാസ്:** ഡിസ്ക്രൈബ് കോൾ OmniRoute-ന്റെ സ്വന്തം `/v1` സെൽഫ്-ലൂപ്പിലൂടെ (നോൺ-സ്റ്റാൻഡേർഡ് പ്രൊവൈഡർ മോഡൽ) റൂട്ട് ചെയ്യുമ്പോൾ, സബ്-റിക്വസ്റ്റ് `x-omniroute-admission-bypass: internal` അയയ്ക്കുകയും പരിഹരിച്ച സെൽഫ്-ലൂപ്പ് ക്രെഡൻഷ്യൽ ഉപയോഗിച്ച് ആധികാരികമാക്കുകയും ചെയ്യുന്നു — ലോക്കൽ മോഡിൽ ലോക്കൽ `sk_omniroute` സെന്റിനൽ, അല്ലെങ്കിൽ ഓപ്പറേറ്റർ കോൺഫിഗർ ചെയ്ത `OMNIROUTE_API_KEY` / `ROUTER_API_KEY` എൻവയോൺമെന്റ് കീ (#1350) വഴി `REQUIRE_API_KEY=true` ഡിപ്ലോയ്മെന്റുകൾക്ക് ഇപ്പോഴും ഡിസ്ക്രൈബ് കോൾ പ്രവർത്തിപ്പിക്കാൻ കഴിയും. ഈ കൃത്യമായ ക്രെഡൻഷ്യലുകൾക്ക് മാത്രമേ ബൈപാസ് അംഗീകരിക്കപ്പെടുകയുള്ളൂ, അതിനാൽ ബാഹ്യ ക്ലയിന്റുകൾക്ക് അഡ്മിഷൻ ഒഴിവാക്കാൻ ഈ ഹെഡർ ഉപയോഗിക്കാൻ കഴിയില്ല.

ലെഗസി ഡിഫോൾട്ടുകൾ `src/shared/constants/visionBridgeDefaults.ts` എന്ന ഫയലിൽ ഉണ്ട്; പുതിയ മോഡ്/ടാസ്ക്-അവെയർ/കാഷെ ഡിഫോൾട്ടുകളും ക്രമീകരണ റിസോൾവറും `src/shared/constants/modalityBridgeDefaults.ts` എന്ന ഫയലിൽ ഉണ്ട്. ഗാർഡ്റെയിൽ ഒരു `deps` കൺസ്ട്രക്ടർ ഓപ്ഷൻ നൽകുന്നു, അതിനാൽ ടെസ്റ്റുകൾക്ക് വ്യാജ `getSettings`, `callVisionModel` ഇംപ്ലിമെന്റേഷനുകൾ ഇൻജക്റ്റ് ചെയ്യാൻ കഴിയും.

### ഓഡിയോ ബ്രിഡ്ജ് (`audioBridge.ts`) — മോഡാലിറ്റി ബ്രിഡ്ജ് PR-3

ഓഡിയോ ഇൻപുട്ട് സ്വീകരിക്കാൻ അറിയാത്ത ഒരു ടാർഗെറ്റിൽ എത്തുന്നതിന് മുമ്പ് ഓഡിയോ അടങ്ങിയ ചാറ്റ് അഭ്യർത്ഥനകളെ ഇത് തടസ്സപ്പെടുത്തുന്നു. ഇത് ചാറ്റ് അഭ്യർത്ഥനയെ ഒരിക്കലും റീറൂട്ട് ചെയ്യുന്നില്ല: ഓഡിയോ ഭാഗങ്ങൾ നിലവിലുള്ള OpenAI-കോംപാറ്റിബിൾ മൾട്ടിപാർട്ട് എൻഡ്പോയിന്റ് വഴി ട്രാൻസ്ക്രൈബ് ചെയ്യുകയും തിരഞ്ഞെടുത്ത ചാറ്റ് മോഡൽ ടെക്സ്റ്റ് ട്രാൻസ്ക്രിപ്റ്റുകളുമായി തുടരുകയും ചെയ്യുന്നു.

പ്രവർത്തനരീതി:

1.  `getResolvedModelCapabilities()` വഴി `supportsAudio` പരിഹരിക്കുക. വ്യക്തമായ പ്രൊവൈഡർ-രജിസ്ട്രി മെറ്റാഡാറ്റയ്ക്ക് മുൻഗണന, തുടർന്ന് സ്റ്റാറ്റിക് മോഡൽ മെറ്റാഡാറ്റ, തുടർന്ന് സിങ്ക് ചെയ്ത `modalities_input`. `audio` ഇല്ലാത്ത ഒരു ഡിക്ലയർ ചെയ്ത ഇൻപുട്ട് ലിസ്റ്റ് `false` ആണ്; കഴിവ് തെളിവുകളൊന്നും ഇല്ലെങ്കിൽ `null` ആയി തുടരും. `false`, `null` എന്നിവ കൺസർവേറ്റീവ് ബ്രിഡ്ജിനെ സജീവമാക്കുമ്പോൾ, `true` അതിനെ ബൈപാസ് ചെയ്യുന്നു.
2.  `modalityBridgeAudio*` ക്രമീകരണങ്ങൾ പരിഹരിക്കുകയും പങ്കിട്ട `detectMediaParts()` ഡിറ്റക്ടർ വഴി ഓരോ സന്ദേശത്തിൽ നിന്നും സ്പ്ലൈസ് ചെയ്യാവുന്ന ടോപ്പ്-ലെവൽ ഓഡിയോ ഭാഗങ്ങൾ വേർതിരിച്ചെടുക്കുകയും ചെയ്യുക. പിന്തുണയ്ക്കുന്ന വയർ ഷേപ്പുകൾ OpenAI `input_audio`, `audio_url`, `source.media_type: "audio/*"` എന്നിവയാണ്. നെസ്റ്റഡ് ഓഡിയോ റൂട്ടിംഗിനായി കണ്ടെത്തുന്നു, പക്ഷേ സ്പ്ലൈസ് പാത്ത് വഴി നീക്കം ചെയ്യുന്നില്ല. `modalityBridgeAudioMaxClips` വഴി പ്രവർത്തനം പരിമിതപ്പെടുത്തിയിരിക്കുന്നു; പിന്നീടുള്ള ഭാഗങ്ങൾ മാറ്റമില്ലാതെ തുടരുന്നു.
3.  കോൺഫിഗർ ചെയ്ത `provider/model` അംഗീകരിക്കുക, അല്ലെങ്കിൽ `selectAudioBridgeModel()` നെ `AUDIO_TRANSCRIPTION_PROVIDERS` നെ സ്റ്റേബിൾ കാറ്റലോഗ് ക്രമത്തിൽ പരിശോധിച്ച് ഉപയോഗിക്കാവുന്ന സജീവ പ്രൊവൈഡർ ക്രെഡൻഷ്യൽ ഉള്ള ആദ്യത്തെ മോഡൽ തിരഞ്ഞെടുക്കാൻ അനുവദിക്കുക.
4.  `callAudioTranscription()` base64/data-URI ഓഡിയോയെ ഒരു മൾട്ടിപാർട്ട് `file` ആക്കി മാറ്റുന്നു, അല്ലെങ്കിൽ ഒരു റിമോട്ട് `audio_url` നെ പബ്ലിക്-മാത്രം ഔട്ട്ബൗണ്ട് ഗാർഡ് വഴി DNS പിന്നിംഗും 25 MB പരിധിയും ഉപയോഗിച്ച് ഡൗൺലോഡ് ചെയ്യുന്നു. തുടർന്ന് ഇത് ഫയലും തിരഞ്ഞെടുത്ത മോഡലും ലോക്കൽ `/v1/audio/transcriptions` സെൽഫ്-ലൂപ്പിലേക്ക് `POST` ചെയ്യുന്നു, `resolveSelfLoopBearer()` ഉപയോഗിച്ച് ആധികാരികമാക്കുന്നു. നിലവിലുള്ള ട്രാൻസ്ക്രിപ്ഷൻ റൂട്ട് സാധാരണ ക്രെഡൻഷ്യൽ ലുക്കപ്പ്, കൂൾഡൗൺ/റേറ്റ്-ലിമിറ്റ് കൈകാര്യം ചെയ്യൽ, പ്രൊവൈഡർ ഡിസ്പാച്ച് എന്നിവ നടത്തുന്നു.
5.  വിജയകരമായ കോളുകൾ അവയുടെ ഭാഗങ്ങളെ `[Audio N]: <transcript>` എന്ന് മാറ്റുന്നു. കോളുകൾ `Promise.allSettled` ഉപയോഗിച്ച് പ്രവർത്തിക്കുന്നു: ഒരു വ്യക്തിഗത പരാജയം ആ യഥാർത്ഥ ഓഡിയോ ഭാഗം നിലനിർത്തുന്നു (#4012 കരാർ). എല്ലാ കോളുകളും പരാജയപ്പെടുകയും ടാർഗെറ്റ് `supportsAudio === false` എന്ന് തെളിയിക്കപ്പെടുകയും ചെയ്താൽ, ഭാഗങ്ങൾ `[Audio N]: (unavailable — no STT provider connected)` എന്ന് മാറുന്നു (#8430 കരാർ). അറിയപ്പെടാത്ത ഒരു ടാർഗെറ്റിന് (`null`), എല്ലാ പരാജയ ഫലവും മാറ്റമില്ലാതെ തുടരുന്നു. ഉപയോഗിക്കാവുന്ന STT ക്രെഡൻഷ്യൽ ഇല്ലാത്ത ഒരു ടെക്സ്റ്റ്-മാത്രം ടാർഗെറ്റിന് ഒരു നെറ്റ്വർക്ക് കോൾ ഇഷ്യൂ ചെയ്യാതെ തന്നെ അതേ വ്യക്തമായ സ്റ്റബ് ലഭിക്കുന്നു.

വിജയകരമായ ട്രാൻസ്ക്രിപ്റ്റുകൾ പ്രോസസ്സ്-വൈഡ് മോഡാലിറ്റി ബ്രിഡ്ജ് LRU/TTL കാഷെ ഉപയോഗിക്കുന്നു. ഓഡിയോ റഫറൻസ്, സ്റ്റേബിൾ `audio-transcription` ഓപ്പറേഷൻ ലേബൽ, തിരഞ്ഞെടുത്ത STT മോഡൽ എന്നിവ ചേർന്നതാണ് കീ; പരാജയങ്ങൾ ഒരിക്കലും കാഷെ ചെയ്യുന്നില്ല. ഓഡിയോ ശ്രമങ്ങൾ പങ്കിട്ട `bridged`, `cacheHits`, `failures`, `lastUsedAt` കൗണ്ടറുകൾ അപ്ഡേറ്റ് ചെയ്യുന്നു. രൂപാന്തരപ്പെട്ട പ്രതികരണങ്ങളിൽ `x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>` അടങ്ങിയിരിക്കുന്നു; മാറ്റമില്ലാത്ത അഭ്യർത്ഥനകൾക്ക് ഒരു ഓഡിയോ ബ്രിഡ്ജ് സെഗ്മെന്റ് ലഭിക്കുന്നില്ല.

റൺടൈം ക്രമീകരണങ്ങൾ DB-ബാക്ക്ഡ് ആണ്, കൂടാതെ Zod-വാലിഡേറ്റഡ് ആണ്:

| Key                           | Default | Range          |
| ----------------------------- | ------- | -------------- |
| `modalityBridgeAudioEnabled`  | `true`  | —              |
| `modalityBridgeAudioModel`    | `""`    | Auto or STT ID |
| `modalityBridgeAudioTimeout`  | `60000` | 1000–300000    |
| `modalityBridgeAudioMaxClips` | `3`     | 1–10           |

പങ്കിട്ട കാഷെ `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, `modalityBridgeCacheMaxEntries` എന്നിവയാൽ നിയന്ത്രിക്കപ്പെടുന്നു.

### വീഡിയോ ബ്രിഡ്ജ് (`videoBridge.ts`, `videoBridgePipeline.ts`)

ഡെസിഡേർഡ് നേറ്റീവ് വീഡിയോ പിന്തുണയില്ലാത്ത ലക്ഷ്യസ്ഥാനം വിളിക്കുന്നതിന് തൊട്ടുമുമ്പ് ചാറ്റ് കംപ്ലീഷൻസ് `messages`-ലെയും റെസ്പോൺസസ് API `input`-ലെയും ടോപ്പ് ലെവൽ വീഡിയോ ഭാഗങ്ങളെ `VideoBridgeGuardrail.preCall` തടസ്സപ്പെടുത്തുന്നു. പിന്തുണയ്ക്കുന്ന രൂപങ്ങൾ `input_video`, `video_url`, `video_source`, HTTPS URL-കൾ, കൂടാതെ `data:video/*;base64,...` ഡാറ്റ യു.ആർ.ഐ.-കളുമാണ്. ടെക്സ്റ്റിലെ ലളിതമായ ഫയൽനാമങ്ങൾ വീഡിയോ ആയി കണക്കാക്കില്ല.

`VideoBridgeGuardrail.preCall` (`videoBridge.ts`) അഭ്യർത്ഥന ട്രാവേഴ്സൽ, ശേഷി/പോളിസി പരിശോധന, പ്രതി-അഭ്യർത്ഥന അഗ്രഗേഷൻ, റെസ്പോൺസ് പേലോഡ് എന്നിവ നിയന്ത്രിക്കുന്നു. ഓരോ വീഡിയോയ്ക്കും വേണ്ടിയുള്ള ജോലികൾ — ഏറ്റെടുക്കൽ, പൂർണ്ണ-ഫല കാഷെ, ഒരു ഫ്രെയിം സീക്വൻസ് വിവരിക്കൽ (ഏത് കോളർ പ്രഖ്യാപിച്ച ഓഡിയോ ട്രാൻസ്ക്രിപ്റ്റും സമന്വയിപ്പിക്കുന്നു), ഒപ്പം ഓരോ ശ്രമത്തിനുമുള്ള മെട്രിക്സ്/അബോർട്ട്/ക്ലീനപ്പ് — `preCall`-ന്റെ ലൂപ്പിനുള്ളിൽ ഓരോ വീഡിയോ ഭാഗത്തിനും ഒരിക്കൽ വീതം വിളിക്കപ്പെടുന്ന `videoBridgePipeline.ts`-ലെ `processVideoPart`-ന് പിന്നിൽ മറഞ്ഞിരിക്കുന്നു. ആ മൊഡ്യൂൾ വ്യക്തമായ പോർട്ട് അതിർത്തികളായ `VideoMediaBrokerPort` (ബൈറ്റുകൾ ഏറ്റെടുക്കുകയും സാമ്പിൾ ചെയ്ത ഫ്രെയിമുകൾ എക്സ്ട്രാക്റ്റ് ചെയ്യുകയും ചെയ്യുന്നു), `VideoAudioTranscriptionPort` (കോളർ പ്രഖ്യാപിച്ച ഓഡിയോ ട്രാൻസ്ക്രിപ്റ്റും സാമ്പിൾ ചെയ്ത ക്യാപ്ഷനുകളും സമന്വയിപ്പിക്കുന്നു), ഒപ്പം `VideoDrilldownPort` (ഫ്രെയിം ഡ്രിൽ-ഡൗൺ പെർസിസ്റ്റൻസ് അതിർത്തി; ഇതുവരെ `processVideoPart`-ൽ കണക്ട് ചെയ്തിട്ടില്ല — ഇന്നത്തെ പ്രത്യേക `/api/modality-bridge/video/drilldown` റൂട്ട് മാത്രമാണ് ഡ്രിൽ-ഡൗൺ എൻട്രികൾ എഴുതുന്നത്) എന്നിവയും നിർവ്വചിക്കുന്നു.

പൊതു `/v1` അഭ്യർത്ഥന പാത ഒരിക്കലും ഒരു സബ്പ്രോസസ്സ് ഇമ്പോർട്ട് ചെയ്യുകയോ വിളിക്കുകയോ ഇല്ല. റിമോട്ട് വീഡിയോകൾ 50 MiB പരിധിക്കുള്ളിൽ ഡൗൺലോഡ് ചെയ്യപ്പെടുന്നു; ഇൻലൈൻ ബേസ്64 വീഡിയോകൾക്ക് വീഡിയോ ഒന്നിന് കൺസർവേറ്റീവ് ആയ 36 MiB ഡീകോഡ് ചെയ്ത പരിധിയുണ്ട്, അതുവഴി മോഡൽ/സന്ദേശങ്ങൾ/ഫ്രെയിമിംഗ് എൻവലപ്പ് എന്നിവയ്ക്ക് പബ്ലിക് JSON അഭ്യർത്ഥന അഡ്മിഷൻ പരിധിയായ 50 MiB-ൽ തുടരാനാകും. അലോക്കേഷന് മുമ്പ് ഇൻലൈൻ നീളവും ഡീകോഡ് ചെയ്ത വലിപ്പത്തിന്റെ എസ്റ്റിമേറ്റുകളും പരിശോധിക്കപ്പെടുന്നു. DNS പിന്നിംഗിനൊപ്പം നിലവിലുള്ള പബ്ലിക്-മാത്രം ഔട്ട്ബൗണ്ട് ഗാർഡ് ഉപയോഗിച്ച് പ്രാരംഭ റിമോട്ട് URL-ലും ഓരോ റീഡയറക്റ്റിലും HTTPS നിർബന്ധമാണ്. ബൈറ്റുകൾ കൃത്യമായ ആന്തരിക `POST /api/modality-bridge/video/extract` ബ്രോക്കർ അതിർത്തി കടക്കുന്നു. ആ റൂട്ട് `LOCAL_ONLY`, `SPAWN_CAPABLE` എന്നിവയാണ്, പ്രോസസ്സ്-അധിഷ്ഠിതമായി ആധികാരികത ഉറപ്പാക്കിയ, വിശ്വസനീയമായ ലൂപ്പ്ബാക്ക് അഭ്യർത്ഥനകൾ മാത്രം സ്വീകരിക്കുന്നു, കൂടാതെ ഒരിക്കലും ഒരു URL, ഫയൽസിസ്റ്റം പാത്ത്, എക്സിക്യൂട്ടബിൾ അല്ലെങ്കിൽ ആർഗ്യുമെന്റ് ലിസ്റ്റ് എന്നിവ സ്വീകരിക്കുന്നില്ല. API ബോഡി-സൈസ് പൈപ്പ്ലൈനും ഹാൻഡ്ലറുടെ ഇൻക്രിമെന്റൽ ബോഡി റീഡറും സ്വതന്ത്രമായി 50 MiB ബ്രോക്കർ ഇൻപുട്ട് പരിധി നടപ്പിലാക്കുന്നു. അതിൻ്റെ ബൗണ്ടഡ് ക്യൂ ഒരേസമയം ഒരു എക്സ്ട്രാക്ഷൻ വീതം പ്രവർത്തിപ്പിക്കുന്നു, നാല് പെൻഡിംഗ് ജോലികൾ അനുവദിക്കുന്നു, കൂടാതെ പെൻഡിംഗ് ഇൻപുട്ട് 100 MiB ആയി പരിമിതപ്പെടുത്തുന്നു.

ബ്രോക്കറിനുള്ളിൽ, `ffprobe` ഒരു സ്വകാര്യ ലോക്കൽ ഫയൽ വായിക്കുന്നു; ഫിക്സഡ് ഫോർമാറ്റ് വൈറ്റ്ലിസ്റ്റ് പ്ലേലിസ്റ്റ്, മാനിഫെസ്റ്റ് ഫോർമാറ്റുകളെ ഒഴിവാക്കുന്നു. അനുവദനീയമായ MOV-ഫാമിലി കണ്ടെയ്നറുകൾക്കായി, ബാഹ്യ MOV ഡാറ്റ റഫറൻസുകൾ ഡിഫോൾട്ടായി പ്രവർത്തനരഹിതമായി തുടരുന്നു, കൂടാതെ ഫിക്സഡ് കമാൻഡ് അവയിലേക്ക് ഒപ്റ്റ് ഇൻ ചെയ്യുന്നില്ല. `ffprobe`, `ffmpeg` രണ്ടും `file`-മാത്രം പ്രോട്ടോക്കോൾ വൈറ്റ്ലിസ്റ്റ്, ഒരു തീഡ്, ഫിക്സഡ് ആർഗ്യുമെന്റ് അറേകൾ, ഷെൽ ഇല്ല, ഒപ്പം `PATH`-ൽ നിന്ന് റിസോൾവ് ചെയ്ത എക്സിക്യൂട്ടബിളുകൾ എന്നിവ ഉപയോഗിക്കുന്നു. അറ്റാച്ച്ഡ്-പിക്ചർ കവർ സ്ട്രീമുകൾ പ്ലേ ചെയ്യാൻ സാധിക്കുന്ന സ്ഥാനാർത്ഥികളല്ല. പ്ലേ ചെയ്യാൻ കഴിയുന്ന എല്ലാ സ്ട്രീമുകളും പരിധികൾ പാലിക്കണം, കൂടാതെ ഡിറ്റർമിനിസ്റ്റിക് ഏറ്റവും കുറഞ്ഞ ഇൻഡക്സ് ഫോളോബാക്കിന് മുമ്പ് വ്യക്തമായ ഡിഫോൾട്ട് സ്ട്രീം മുൻഗണന നൽകുന്നു. വീഡിയോകൾ 600 സെക്കൻഡ്, ഒരു അളവിന് 8,192 പിക്സലുകൾ, 33,554,432 സോഴ്സ് പിക്സലുകൾ എന്നിവയായി പരിമിതപ്പെടുത്തിയിരിക്കുന്നു. FFmpeg 1–16 മിഡ്പോയിന്റ് JPEG ഫ്രെയിമുകൾ സാമ്പിൾ ചെയ്യുന്നു, ചെറിയ ഇൻപുട്ടുകൾ വലുതാക്കാതെ നീളമുള്ള എഡ്ജ് പരമാവധി 1,024 പിക്സലുകളായി സ്കെയിൽ ചെയ്യുന്നു, കൂടാതെ ഒരിക്കലും ഒരു URL സ്വീകരിക്കുന്നില്ല. സാമ്പിൾ ചെയ്യൽ ഡിഫോൾട്ടായി `uniform` ആണ്. ഓപ്ഷണൽ ആയ `scene_aware`, എക്സ്പിരിമെന്റൽ `segment_aware` പോളിസികൾ ഇതിനകം സാധുതയുള്ള ലോക്കൽ സ്ട്രീമിൽ ഒരു അധിക ഫിക്സഡ് FFmpeg പാസ് കൂടി നടത്തുന്നു, ബൗണ്ടഡ് ആയ `showinfo` സീൻ ടൈംസ്റ്റാമ്പുകൾ തിരഞ്ഞെടുക്കുന്നു, കൂടാതെ ഡിറ്റക്ടർ പരാജയം, ടൈംഔട്ട്, തെറ്റായ ഔട്ട്പുട്ട്, അല്ലെങ്കിൽ ശൂന്യമായ കാൻഡിഡേറ്റ് സെറ്റ് എന്നിവ ഉണ്ടായാൽ അതേ യൂണിഫോം മിഡ്പോയിന്റുകളിലേക്ക് ഡിറ്റർമിനിസ്റ്റിക് ആയി ഫാൾ ബാക്ക് ചെയ്യുന്നു. സെഗ്മെന്റ്-അവെയർ മോഡ് സാധുതയുള്ള സീൻ ഇടവേളകൾക്ക് അനുപാതികമായി മിഡ്പോയിന്റ് സാമ്പിളുകൾ അലോക്കേറ്റ് ചെയ്യുന്നു; സെഗ്മെന്റ്-അവെയർ എവിഡൻസും ഫാൾബാക്ക് സ്വഭാവവും താഴെ വിശദീകരിച്ചിരിക്കുന്നു. ഓരോ പോളിസിയിലും തിരഞ്ഞെടുപ്പിന് ശേഷമാണ് ഹാർഡ് 16-ഫ്രെയിം ക്യാപ് പ്രയോഗിക്കുന്നത്. ഒരു സീൻ-അവെയർ അഭ്യർത്ഥനയ്ക്ക് ഒരു ഫ്രെയിം ബജറ്റ് മാത്രമുള്ളപ്പോൾ, അത് സജീവമായ ഫുൾ-വീഡിയോ അല്ലെങ്കിൽ ഫോക്കസ് വിൻഡോയുടെ യൂണിഫോം മിഡ്പോയിന്റ് ഉപയോഗിക്കുകയും `policyEffective: uniform` എന്ന് റിപ്പോർട്ട് ചെയ്യുകയും ചെയ്യുന്നു: തിരഞ്ഞെടുത്ത ഒരൊറ്റ സീൻ ഫ്രെയിമിന് രണ്ട് ടെമ്പറൽ അറ്റങ്ങളും സംരക്ഷിക്കാൻ കഴിയില്ല. ഒരു കോളർ ഓപ്ഷണലായി ഒരു ഫൈനറ്റ് ഫോക്കസ് വിൻഡോ (`start`/`end` സെക്കൻഡുകൾ) നൽകാം; ബൗണ്ടുകൾ മീഡിയ ദൈർഘ്യത്തിലേക്ക് ക്ലമ്പ് ചെയ്യപ്പെടുന്നു, റിവേഴ്സ് ചെയ്തതോ ഫൈനറ്റ് അല്ലാത്തതോ ആയ വിൻഡോകൾ നിരസിക്കപ്പെടുന്നു, കൂടാതെ എല്ലാ സാമ്പിളിംഗ് പോളിസികളും നോർമലൈസ്ഡ് ഇടവേളയ്ക്കുള്ളിൽ മാത്രം നിർവഹിക്കപ്പെടുന്നു. ഫലമായുണ്ടാവുന്ന വിൻഡോ സാമ്പിളിംഗ് മെറ്റാഡാറ്റയിലും അൺട്രസ്റ്റഡ് ഡിസ്ക്രിപ്ഷൻ പ്രിഫിക്സിലും ഉൾപ്പെടുത്തിയിരിക്കുന്നു, അതുവഴി ഡൗൺസ്ട്രീം മോഡലുകൾക്ക് ഫുൾ ടൈംലൈനിൽ നിന്ന് ഫോക്കസ് ചെയ്ത എക്സെർപ്റ്റ് വേർതിരിച്ചറിയാൻ കഴിയും.

സെമാന്റിക് ക്യാപ്ഷൻ ഫോക്കസ് വേറിട്ടതും വ്യക്തവുമായ ഒരു ക്രമീകരണമാണ്. ഡിഫോൾട്ട് ആയ `full` അനാലിസിസ് മോഡ് നിലവിലുള്ള ഫ്രെയിം പ്രോംപ്റ്റ് സംരക്ഷിക്കുകയും ഒരിക്കലും അഭ്യർത്ഥന ടെക്സ്റ്റ് ക്യാപ്ഷൻ മോഡലിലേക്ക് ഫോർവേഡ് ചെയ്യുകയും ഇല്ല. `focused` മോഡിൽ, ബ്രിഡ്ജ് അതേ ചാറ്റ് അല്ലെങ്കിൽ റെസ്പോൺസസ് കണ്ടെയ്നറിൽ നിന്നുള്ള ഏറ്റവും പുതിയ നോൺ-എംപ്റ്റി ആയ യൂസർ-ഓതേർഡ് `text`/`input_text` മാത്രം വായിക്കുന്നു, അതിനെ NFC-യിലേക്ക് നോർമലൈസ് ചെയ്യുന്നു, കൺട്രോൾ ക്യാരക്ടറുകളും വൈറ്റ്സ്പെയ്സുകളും ചുരുക്കുന്നു, കൂടാതെ അതിനെ 500 യൂണികോഡ് കോഡ് പോയിന്റുകളായി പരിമിതപ്പെടുത്തുന്നു. ശൂന്യമായ ഫലം കൃത്യമായ `full` പ്രോംപ്റ്റിലേക്ക് ഫാൾ ബാക്ക് ചെയ്യുന്നു. ഉപയോഗയോഗ്യമായ ഒരു സൂചന ഒരു പ്രത്യേക അൺട്രസ്റ്റഡ്-യൂസർ-കോൺടെക്സ്റ്റ് ബ്ലോക്കിൽ JSON ആയി സീരിയലൈസ് ചെയ്യപ്പെടുന്നു കൂടാതെ നിരീക്ഷിക്കാവുന്ന വിശദാംശങ്ങൾക്ക് മുൻഗണന നൽകാം; മീഡിയയിൽ ദൃശ്യമാകുന്നതോ കേൾക്കാവുന്നതോ ആയ നിർദ്ദേശങ്ങൾ പാലിക്കുന്നതിനെതിരെയുള്ള പ്രത്യേക മുന്നറിയിപ്പിനെ അതിന് അസാധുവാക്കാൻ കഴിയില്ല. ടെക്സ്റ്റുഅൽ ഫോക്കസ് ഒരിക്കലും `start`/`end` അനുമാനിക്കുകയോ ടെമ്പറൽ സാമ്പ്ലർ മാറ്റുകയോ ഇല്ല.

#### FU-07 ഘടനാപരമായ സെഗ്മെന്റ് തെളിവുകൾ

ഇതിനകം സാധുതയുള്ള ലോക്കൽ വീഡിയോ സ്ട്രീമിൽ `segment_aware` പരിമിതമായ ഒരു പ്രീ-അനാലിസിസ് പാസ് ഉപയോഗിക്കുന്നു. ഫിക്സഡ് ഫിൽട്ടർ ചെയിൻ ആദ്യം പരമാവധി 320 പിക്സൽ വീതിയിലേക്ക് സ്കെയിൽ ചെയ്യുന്നു, സീൻ മാറ്റങ്ങളും ഫ്രോസൺ ഇടവേളകളും കണ്ടെത്തുന്നു, തുടർന്ന് ബ്ലർ, ശരാശരി ലുമ, സ്പേഷ്യൽ/ടെമ്പറൽ വിവരങ്ങൾ എന്നിവയ്ക്കായി സെക്കൻഡിൽ 1 ഫ്രെയിം വീതം സാമ്പിൾ ചെയ്യുന്നു. പാസ് 600 ഘടനാപരമായ സാമ്പിളുകൾ, ഒരു FFmpeg/ഫിൽട്ടർ തിരെഡ്, അതേ `file`-മാത്രം പ്രോട്ടോക്കോൾ, കണ്ടെയ്നർ വൈറ്റ്ലിസ്റ്റുകൾ, 1 MiB പ്രോസസ്സ്-ഔട്ട്പുട്ട് പരിധി, കൂടാതെ ബ്രോക്കറുടെ പങ്കിട്ട അബോർട്ട്/ഡെഡ്ലൈനിനുള്ളിൽ പരമാവധി 30 സെക്കൻഡ് എന്നിവയിലേക്ക് പരിമിതപ്പെടുത്തിയിരിക്കുന്നു. ഇത് ഒരിക്കലും അഭ്യർത്ഥനയിൽ നിന്നുള്ള ഒരു കമാൻഡ്, ഫിൽട്ടർ, പാത്ത് അല്ലെങ്കിൽ URL സ്വീകരിക്കുന്നില്ല.

ഘടനപരമായ മൂല്യങ്ങൾ നിർണ്ണായകമായ സാമ്പിൾ തെളിവുകളാണ്, അല്ലാതെ സെമാന്റിക് വീഡിയോ മനസ്സിലാക്കലല്ല. അവ വിഷയങ്ങൾ, പ്രവർത്തനങ്ങൾ, അടിക്കുറിപ്പുകൾ, സംഭാഷണം, അല്ലെങ്കിൽ ഉപയോക്തൃ ഉദ്ദേശ്യം എന്നിവ അനുമാനിക്കുന്നില്ല. രംഗവും ഫ്രീസ് അതിരുകളും സെഗ്മെന്റുകൾ രൂപപ്പെടുത്തുന്നു; ഫ്രീസ് കവറേജ്, ബ്ലർ, എക്സ്പോഷർ, സ്പേഷ്യൽ വിശദാംശങ്ങൾ, താൽക്കാലിക മാറ്റം എന്നിവ നിലവിലുള്ള 1-16 ഫ്രെയിം ബഡ്ജറ്റ് എങ്ങനെയാണ് വിനിയോഗിക്കുന്നത് എന്ന് മാത്രമേ സ്വാധീനിക്കൂ. പൂർണ്ണമായി ഫ്രീസ് ചെയ്ത ഒരു സെഗ്മെന്റ് ഒരു ഫ്രെയിമിൽ പരിമിതപ്പെടുത്തിയിരിക്കുന്നു, അതേസമയം ഫ്രീസ് ചെയ്യാത്ത സെഗ്മെന്റുകൾ ശേഷിക്കുന്ന ബഡ്ജറ്റിനായി മത്സരിക്കുന്നു. അതിരുകൾ ഫ്രെയിമുകളേക്കാൾ കൂടുതലാകുമ്പോൾ, ഏകീകൃത ടൈംലൈൻ കവറേജ് നിലനിർത്തുന്നു, അതിനാൽ വേഗത്തിലുള്ള ആദ്യകാല കട്ടുകൾക്ക് ഒരു നീണ്ട പിൻഭാഗത്തെ സെഗ്മെന്റിനെ മറയ്ക്കാൻ കഴിയില്ല. ഒരു ഫ്രീസ് അതിർത്തിയുടെ 1-സെക്കൻഡ് വിശകലന റെസല്യൂഷനിലുള്ള രംഗ അതിരുകൾ സംയോജിപ്പിക്കുന്നു.

ഫിൽട്ടറുകൾ ഇല്ലാത്തത്, തെറ്റായ/ഒഴിഞ്ഞ തെളിവുകൾ, ഒരു ഡിറ്റക്ടർ പിശക്, അല്ലെങ്കിൽ ബൗണ്ടഡ് പ്രീ-അനാലിസിസ് ടൈംഔട്ട് എന്നിവ കൃത്യമായ ഏകീകൃത മധ്യബിന്ദു നയത്തിലേക്ക് തുറക്കുന്നു. ഒരു കോളർ അബോർട്ട് അല്ലെങ്കിൽ ബ്രോക്കർ ഡെഡ്ലൈൻ തുറക്കുന്നില്ല: അത് ഇൻ-ഫ്ലൈറ്റ് സബ്പ്രോസസ് അവസാനിപ്പിക്കുന്നു, പിന്നീട് ഫ്രെയിം എക്സ്ട്രാക്ഷൻ തടയുന്നു, കൂടാതെ സ്വകാര്യ താൽക്കാലിക ട്രീ `finally` എന്നതിൽ നീക്കംചെയ്യുന്നു.

`scripts/perf/video-bridge-fu07-eval.ts` പോസ്റ്റ്-ഡെഡ്യൂപ്പ് ക്യാപ്ഷൻ-കോൾ ലാഭങ്ങൾ, ഡെൻസ്-മോഷൻ ബഡ്ജറ്റ് അലോക്കേഷൻ, ബ്ലർ/എക്സ്പോഷർ/SI-TI തെളിവുകൾ, ഒരു നീണ്ട വാലോടുകൂടിയ റാപ്പിഡ് കട്ടുകൾ, ക്രമാനുഗതമായ ഫേഡ് തെറ്റായ പോസിറ്റീവുകൾ എന്നിവയ്ക്കായി നിർണ്ണായകമായ യഥാർത്ഥ FFmpeg ഫിക്സ്ചറുകൾ സൃഷ്ടിക്കുന്നു. ഇത് പ്രീ-അനാലിസിസ് വാൾ ടൈം രേഖപ്പെടുത്തുന്നു, കൂടാതെ `/usr/bin/time` ലഭ്യമാണെങ്കിൽ, ചൈൽഡ് CPU-യും പീക്ക് RSS-ഉം രേഖപ്പെടുത്തുന്നു. ഇതിന്റെ ഗുണനിലവാര പരിശോധനകൾ ഘടനാപരമായ ഓറക്കിളുകൾ മാത്രമാണ്. യഥാർത്ഥ ക്യാപ്ഷൻ-മോഡൽ ഗുണനിലവാരം `HOLD` ആയി തുടരുന്നു, കാരണം ഈ ഹാർനെസിന് അംഗീകൃത എൻഡ്പോയിന്റോ ഫ്രോസൺ ജഡ്ജോ ഇല്ല. `--caption-cost-per-call-usd` ഒരു വ്യക്തമായ പോസിറ്റീവ് പെർ-കോൾ എസ്റ്റിമേറ്റ് നൽകുന്നില്ലെങ്കിൽ സാമ്പത്തിക ലാഭവും `HOLD` ആയി തുടരുന്നു; സ്ക്രിപ്റ്റ് ഒരു ഫലവും നിർമ്മിക്കുന്നില്ല.

ഓരോ ഫ്രെയിമും 4 MiB ആയി പരിമിതപ്പെടുത്തിയിരിക്കുന്നു, എല്ലാ റോ ഫ്രെയിമുകളും ഒരുമിച്ച് 23 MiB ആയി, കൂടാതെ സീരിയലൈസ് ചെയ്ത ബ്രോക്കർ പ്രതികരണം 32 MiB ആയി. ഒരു സ്വകാര്യ താൽക്കാലിക ഡയറക്ടറി `finally` എന്നതിൽ നീക്കംചെയ്യുന്നു. OmniRoute FFmpeg ബണ്ടിൽ ചെയ്യുന്നില്ല, കൂടാതെ ഒരു കസ്റ്റം എക്സിക്യൂട്ടബിൾ പാത്ത് സ്വീകരിക്കുന്നില്ല. ക്യാപ്ഷൻ ചെയ്യുന്നതിന് മുമ്പ്, ബ്രിഡ്ജ് ഒരു യാഥാസ്ഥിതിക വിഷ്വൽ ഡെഡ്യൂപ്ലിക്കേഷൻ പാസ് പ്രയോഗിക്കുന്നു: ഓരോ JPEG-യും ഒരു 16×16 ഗ്രേസ്കെയിൽ ബഫറായി കുറയ്ക്കുകയും നിലനിർത്തിയ അവസാന ഫ്രെയിമുമായി മാത്രം താരതമ്യം ചെയ്യുകയും ചെയ്യുന്നു. ഒരു ഫ്രെയിമിന് മുകളിലുള്ള അഭ്യർത്ഥിച്ച ക്യാപ്ഷൻ ബഡ്ജറ്റിനായി, എക്സ്ട്രാക്ഷൻ ആ ബഡ്ജറ്റിന്റെ ഇരട്ടി വരെയും 16 ഫ്രെയിമുകളിൽ കൂടാതെയും ഒരു ബൗണ്ടഡ് കാൻഡിഡേറ്റ് പൂൾ നൽകുന്നു. അഭ്യർത്ഥിച്ച പരിധി ഡെഡ്യൂപ്ലിക്കേഷന് ശേഷം മാത്രമേ പ്രയോഗിക്കൂ, ബഡ്ജറ്റ് കുറഞ്ഞത് രണ്ടായിരിക്കുമ്പോൾ ആദ്യത്തെയും അവസാനത്തെയും തിരഞ്ഞെടുത്ത കാൻഡിഡേറ്റുകൾ അന്തിമ തിന്നിംഗിൽ സംരക്ഷിക്കപ്പെടുന്നു. പതിപ്പുള്ള `grayscale-16x16-mean-cells-v2` പോളിസി മീൻ ലൂമ ഡെൽറ്റയുടെയും നോർമലൈസ് ചെയ്ത ഡെൽറ്റ കുറഞ്ഞത് 0.05 ആയ തംബ്നെയിൽ സെല്ലുകളുടെ അനുപാതത്തിന്റെയും വലിയ മൂല്യം ഉപയോഗിക്കുന്നു. ഡ്യൂപ്ലിക്കേറ്റ് ത്രെഷോൾഡ് 0.04 എന്ന സ്ഥിരമായ മൂല്യമാണ്, ഇത് റൺടൈം ക്രമീകരണമായി വെളിപ്പെടുത്തുന്നതിന് പകരം പ്രവചനാത്മകതയ്ക്കായി തിരഞ്ഞെടുത്തതാണ്. ഈ ദ്വിതീയ ഹൈ-കോൺട്രാസ്റ്റ് സിഗ്നൽ ചെറിയ ചലനങ്ങളും ദൃശ്യമായ-ടെക്സ്റ്റ് മാറ്റങ്ങളും സംരക്ഷിക്കുന്നു, അത് ഒരു മീൻ-മാത്രം താരതമ്യത്തിന് മറയ്ക്കാൻ കഴിയും. താരതമ്യപ്പെടുത്തൽ അല്ലെങ്കിൽ ഡീകോഡർ പിശകുകൾ തുറക്കുകയും കവറേജ് നിലനിർത്തുകയും ചെയ്യുന്നു. ഔട്ട്പുട്ട് മെറ്റാഡാറ്റ വേർതിരിച്ചെടുത്ത കാൻഡിഡേറ്റുകൾ, വിജയകരമായി ഉപയോഗിച്ച ഫ്രെയിമുകൾ, ഒഴിവാക്കിയ വിഷ്വൽ ഡ്യൂപ്ലിക്കേറ്റുകൾ എന്നിവ വേർതിരിക്കുന്നു.

വ്യക്തമായി അടയാളപ്പെടുത്തിയ ഒരു വീഡിയോ ഭാഗം ഒരു ടൈംസ്റ്റാമ്പ് ചെയ്ത കോൺടാക്റ്റ് ഷീറ്റ് അഭ്യർത്ഥിച്ചേക്കാം. ബ്രിഡ്ജ് പരമാവധി 4-കോളം, 16-ഫ്രെയിം JPEG ഗ്രിഡ് നിർമ്മിക്കുന്നു. ഓരോ 512-പിക്സൽ സെല്ലും അതിന്റെ സോഴ്സ് ടൈംസ്റ്റാമ്പ് ഒരു ഹൈ-കോൺട്രാസ്റ്റ് താഴത്തെ ബാൻഡിലേക്ക് ബേൺ ചെയ്യുന്നു, അതേസമയം അതേ ടൈംസ്റ്റാമ്പുകൾ ഡൗൺസ്ട്രീം അസോസിയേഷനും ഓഡിറ്റിനുമായി ടെക്സ്റ്റ്വൽ മെറ്റാഡാറ്റയിൽ നിലനിൽക്കുന്നു. പൂർണ്ണമായ JPEG 32 MiB-യിൽ പരിമിതപ്പെടുത്തിയിരിക്കുന്നു. `sharp` ഗ്രിഡ് ഡീകോഡ് ചെയ്യാനോ കമ്പോസ് ചെയ്യാനോ കഴിയുന്നില്ലെങ്കിൽ, ബ്രിഡ്ജ് വ്യക്തിഗത JPEG ഫ്രെയിമുകളിലേക്ക് തിരിയുന്നു; ഒരു ക്ലയിന്റ് അബോർട്ട് ഷീറ്റ് ഓപ്പറേഷനിലൂടെയും പ്രചരിക്കുന്നു.

പ്രൊമോഷൻ തെളിവുകൾ സിന്തറ്റിക് കോമ്പോസിഷൻ മൈക്രോബെഞ്ച്മാർക്കിൽ നിന്ന് മനഃപൂർവ്വം വേർതിരിച്ചിരിക്കുന്നു. `scripts/perf/video-bridge-contact-sheet-eval.ts` യഥാർത്ഥ OpenAI-അനുയോജ്യമായ വിഷൻ മോഡലുകൾക്കായി ഒരു സ്കീമ-പതിപ്പുള്ള A/B ഹാർനെസ് നിർവചിക്കുന്നു. ഇത് പ്രൊവൈഡർ-റിപ്പോർട്ട് ചെയ്ത ടോക്കണുകൾ, എൻഡ്-ടു-എൻഡ് വാൾ ലേറ്റൻസി (ഷീറ്റ് കോമ്പോസിഷൻ ഉൾപ്പെടെ), മോഡൽ-കോൾ കൗണ്ട്, മാനിഫെസ്റ്റ്-നിർവചിച്ച വസ്തുത നിലനിർത്തൽ എന്നിവ അളക്കുന്നു. റോ മോഡൽ പ്രതികരണങ്ങൾ റിപ്പോർട്ടിൽ എഴുതുന്നില്ല; SHA-256 ഡൈജസ്റ്റുകളും പൊരുത്തപ്പെട്ട വസ്തുത ഐഡികളും മാത്രമേ നിലനിർത്തുന്നുള്ളൂ. `--execute-real` പാസ്സാക്കുകയും `--model`, `OMNIROUTE_BASE_URL`, `OMNIROUTE_API_KEY` എന്നിവ കോൺഫിഗർ ചെയ്യുകയും ചെയ്തില്ലെങ്കിൽ ഹാർനെസ് നെറ്റ്വർക്കോ പണമടച്ചുള്ള മോഡൽ കോളോ ചെയ്യുന്നില്ല. ആ വ്യക്തമായ യഥാർത്ഥ റൺ ഇല്ലാതെ, അതിന്റെ മെഷീൻ-റീഡബിൾ വിധി `HOLD` ആയി തുടരുന്നു; സിന്തറ്റിക് പേലോഡ്/കോൾ-കൗണ്ട് അളവുകൾ മാത്രം പ്രൊമോഷൻ തെളിവുകളല്ല.

കോളർമാർക്ക് ഇതിനകം വിന്യസിച്ച ടെക്സ്റ്റ് ഉള്ളപ്പോൾ പിന്തുണയ്ക്കുന്ന ഒരു വീഡിയോ ഭാഗത്തിലേക്ക് ഒരു ഓപ്ഷണൽ `transcript.cues` അറേ അറ്റാച്ചുചെയ്യാവുന്നതാണ്. ഓരോ ക്യൂവും `text`, പ്രോബ് ചെയ്ത ദൈർഘ്യത്തിനുള്ളിൽ ഒരു പരിമിതമായ `start`/`end` ഇടവേള, ഒരു വൈറ്റ്ലിസ്റ്റ് ചെയ്ത `source` (`client`, `embedded`, അല്ലെങ്കിൽ `audio-bridge`) എന്നിവ വഹിക്കണം; `confidence` സ്ഥിരസ്ഥിതിയായി `1` ആണ്, കൂടാതെ `0` നും `1` നും ഇടയിൽ ആയിരിക്കണം. കൃത്യമായ ഡ്യൂപ്ലിക്കേറ്റ് ക്യൂകൾ ചുരുക്കുന്നു. OmniRoute ഈ മെറ്റാഡാറ്റയിൽ നിന്ന് ട്രാൻസ്ക്രിപ്ഷൻ ആരംഭിക്കുന്നില്ല: സാധുവായ ക്യൂകൾ സോഴ്സ്, കോൺഫിഡൻസ്, ഇടവേള എന്നിവയോടൊപ്പം വിവരിച്ച ഫലത്തിലേക്ക് പകർത്തുന്നു, കൂടാതെ ഫ്രെയിം ക്യാപ്ഷനുകൾക്കൊപ്പം വിശ്വസനീയമല്ലാത്ത നിരീക്ഷണങ്ങളായി റെൻഡർ ചെയ്യുന്നു. അസാധുവായ, പരിധിക്ക് പുറത്തുള്ള, അല്ലെങ്കിൽ പ്രോവനൻസ്-രഹിതമായ ടെക്സ്റ്റ് ക്യാപ്ഷൻ സ്ട്രീമിലേക്ക് കലർത്തുന്നതിന് പകരം നിരസിക്കപ്പെടുന്നു. `source` ഫീൽഡ് നിലവിൽ കോളർ-പ്രഖ്യാപിതമാണ്, സെർവർ-പരിശോധിച്ചതല്ല: OmniRoute അനുവദനീയമായ മൂന്ന് സ്ട്രിംഗുകളിൽ ഒന്നാണ് മൂല്യം എന്ന് നിർബന്ധമാക്കുന്നു, പക്ഷേ ഒരു `embedded` അല്ലെങ്കിൽ `audio-bridge` ലേബൽ യഥാർത്ഥത്തിൽ ഒരു സെർവർ-ഉടമസ്ഥതയിലുള്ള എക്സ്ട്രാക്ഷനിൽ നിന്നാണ് വന്നതെന്ന് ക്രിപ്റ്റോഗ്രാഫിക്കായി സ്ഥിരീകരിക്കുന്നില്ല. ആ പരിശോധന വരുന്നതുവരെ `source` ഒരു വിശ്വസനീയമല്ലാത്ത സൂചനയായി കണക്കാക്കുക; അതിനെ അടിസ്ഥാനമാക്കി അംഗീകാര തീരുമാനങ്ങൾ എടുക്കരുത്.

ഒരു അഡ്വാൻസ്ഡ് കോളർക്ക് അതേ വീഡിയോയ്ക്കായി ഇതിനകം അംഗീകൃതമായ `audioTranscript` ട്രാക്ക് നൽകാൻ കഴിഞ്ഞേക്കും. ഫ്യൂഷൻ സീം വിഷ്വൽ, ഓഡിയോ നിരീക്ഷണങ്ങളെ ഒരു ഡെഡ്ലൈനിനും അബോർട്ട് സിഗ്നലിനും കീഴിൽ പ്രവർത്തിപ്പിക്കുന്നു, അവയെ ഒരു പൊതു ടൈംലൈനിൽ ക്രമീകരിക്കുന്നു, കൃത്യമായ ഡ്യൂപ്ലിക്കേറ്റുകൾ ഇല്ലാതാക്കുന്നു, കൂടാതെ ഒരു ഭാഗം മാത്രം വിജയിക്കുമ്പോൾ ഒരു ഭാഗിക ഫലം റിപ്പോർട്ട് ചെയ്യുന്നു. ഒരു അസാധുവായ `audioTranscript` ആ ഭാഗിക ഫലത്തിലേക്ക് തരംതാഴ്ത്തുന്നു — വിഷ്വൽ വിവരണം നിലനിർത്തുകയും ഓഡിയോ ബ്രാഞ്ച് ഒരു സാനിറ്റൈസ്ഡ് പരാജയ കോഡ് രേഖപ്പെടുത്തുകയും ചെയ്യുന്നു — മുഴുവൻ വീഡിയോയും പരാജയപ്പെടുന്നതിന് പകരം. ഓരോ ബ്രാഞ്ചിന്റെയും ലഭ്യത, ഭാഗിക ഫ്ലാഗ്, സാനിറ്റൈസ്ഡ് പരാജയ കോഡുകൾ എന്നിവ വിവരിച്ച ഫലത്തിലും, ഗാർഡ്റെയിൽ മെറ്റാഡാറ്റയിലും (`audioFusionRuns`/`audioFusionPartials`/`audioFusionFailureCodes`), റിസൾട്ട്-കാഷെ മെറ്റാഡാറ്റയിലും, ബ്രിഡ്ജ് ഫ്യൂഷൻ കൗണ്ടറുകളിലും സംരക്ഷിക്കപ്പെടുന്നു. ഡിഫോൾട്ട് വീഡിയോ ബ്രിഡ്ജ് പാത സ്പീച്ച്-ടു-ടെക്സ്റ്റ് ഉപയോഗിക്കുകയോ രണ്ടാമത്തെ മീഡിയ കോപ്പി ഡൗൺലോഡ് ചെയ്യുകയോ ചെയ്യുന്നില്ല; ആ വ്യക്തമായ ട്രാക്ക് ഇല്ലാതെ, അത് വീഡിയോ-മാത്രം ആയി തുടരുന്നു.

**ട്രാൻസ്ക്രിപ്റ്റ് നിലനിർത്തൽ (#12150 P1).** വീഡിയോ ബ്രിഡ്ജ് (സ്വയം ഓപ്റ്റ്-ഇൻ) ഒരു ട്രാൻസ്ക്രിപ്റ്റ് ക്യൂ റെൻഡർ ചെയ്യുമ്പോൾ ഇത് സ്വയമേവ ബാധകമാകും — പ്രത്യേക നിലനിർത്തൽ ഫ്ലാഗ് ഇല്ല. ഒരു അഭ്യർത്ഥന ഏതെങ്കിലും ട്രാൻസ്ക്രിപ്റ്റ് ക്യൂ റെൻഡർ ചെയ്യുമ്പോൾ (ഒരു കോളർ-പ്രഖ്യാപിത `transcript` അല്ലെങ്കിൽ ഒരു ഫ്യൂസ്ഡ് `audioTranscript`), ഗാർഡ്റെയിൽ അതിനെ `videoBridgeObserved` എന്ന് അടയാളപ്പെടുത്തുകയും വീഡിയോ വിവരണത്തിന്റെ ഒരു റെഡാക്ട് ചെയ്ത നിഴൽ നിർമ്മിക്കുകയും ചെയ്യുന്നു — ഓരോ ക്യൂവിന്റെയും ഫ്രീ-ടെക്സ്റ്റ് ബോഡി `[redacted-video-transcript]` എന്ന് മാറ്റിസ്ഥാപിക്കുന്ന ഒരു സമാന റെൻഡറിംഗ്, സ്ട്രിംഗ് അസംബിൾ ചെയ്യുന്നതിന് മുമ്പ് സ്ട്രക്ചർഡ് ക്യൂ ഫീൽഡ് മാറ്റിസ്ഥാപിച്ച് നിർമ്മിച്ചത് (ഫ്ലാറ്റ് ചെയ്ത ടെക്സ്റ്റ് പാഴ്സ് ചെയ്തുകൊണ്ടല്ല, അതിനാൽ ക്യൂ ഉള്ളടക്കം — പ്രതികൂലമോ സാധാരണയോ, `]` അടങ്ങിയ ബോഡികൾ ഉൾപ്പെടെ `[inaudible]`/`[music]` പോലുള്ളവ — നിലനിൽക്കില്ല). നിലനിർത്തിയ കോൾ-ലോഗ് അഭ്യർത്ഥന ബോഡി ഓരോ വീഡിയോ-ഡെറിവ്ഡ് ടെക്സ്റ്റ് ഭാഗവും ഉള്ളടക്ക സമത്വം അനുസരിച്ച് പൊരുത്തപ്പെടുന്ന ആ റെഡാക്ട് ചെയ്ത നിഴലിനായി മാറ്റുന്നു; `fullText` ആങ്കർ പൂർത്തിയാക്കിയ പ്രീ-കോൾ ഗാർഡ്റെയിൽ പേലോഡിൽ നിന്ന് വീണ്ടും വായിക്കുന്നു, അതിനാൽ പിന്നീടുള്ള ചെയിൻ ഗാർഡ്റെയിലുകൾ (PII, ക്രെഡൻഷ്യൽ മാസ്കറുകൾ, മുൻഗണനകൾ 10/95) വിവരണ ടെക്സ്റ്റ് മാറ്റിയെഴുതിയ ശേഷവും സിസ്റ്റം-പ്രോംപ്റ്റ്/ഹാൻഡ്ഓഫ്/മെമ്മറി ഇൻജക്ഷൻ മെസ്സേജ് അറേയെ മാറ്റിയെഴുതിയ ശേഷവും പൊരുത്തം വിജയിക്കുന്നു. മോഡലിലേക്ക് അപ്സ്ട്രീം അയച്ച ബോഡി മാറ്റമില്ലാതെ തുടരുന്നു. നിരീക്ഷിച്ച ഒരു അഭ്യർത്ഥന നിലനിൽക്കുന്ന മെമ്മറിയിൽ ഒന്നും ചേർക്കുന്നില്ല (അഭ്യർത്ഥനയിൽ നിന്നും പ്രതികരണത്തിൽ നിന്നും ലഭിക്കുന്ന എക്സ്ട്രാക്ഷൻ ഒഴിവാക്കുന്നു), അതിനാൽ മോഡലിന്റെ സ്വന്തം മറുപടിക്ക് ട്രാൻസ്ക്രിപ്റ്റ് ടെക്സ്റ്റ് മെമ്മറിയിലേക്ക് പ്രതിധ്വനിക്കാൻ കഴിയില്ല.

അധികമായി നിലനിർത്തിയ പകർപ്പുകൾ അതേ നിരീക്ഷിച്ച-അഭ്യർത്ഥന സിഗ്നൽ ഉപയോഗിക്കുന്നു. റോ പ്രീ-ഗാർഡ്റെയിൽ ക്ലയിന്റ്-അഭ്യർത്ഥന സ്നാപ്പ്ഷോട്ട്, ഇൻ-മെമ്മറി പെൻഡിംഗ് അഭ്യർത്ഥന, നേരത്തെ നിരസിച്ച-അഭ്യർത്ഥന ലോഗ് എന്നിവ വീഡിയോ ഭാഗങ്ങളിലെ ട്രാൻസ്ക്രിപ്റ്റ് ഫീൽഡുകൾ ഘടനാപരമായി മാറ്റിസ്ഥാപിക്കുന്നു; പൈപ്പ്ലൈൻ ഘട്ടങ്ങളും കോൺടെക്സ്റ്റ് ഹാൻഡ്ഓഫും വഴി സമന്വയിപ്പിച്ച സ്ട്രിംഗ് പ്രോംപ്റ്റുകൾ നിലനിർത്തിയ-അഭ്യർത്ഥന-ബോഡി സിങ്കിൽ റെഡാക്ട് ചെയ്യപ്പെടുന്നു. നിലനിർത്തിയ `video_content_removed` മാർക്കർ `previous_response_id` തുടർച്ചയെ അടഞ്ഞ നിലയിൽ പരാജയപ്പെടുത്തുന്നു, അല്ലാതെ മനഃപൂർവം ഉപേക്ഷിച്ച ടെക്സ്റ്റ് പുനർനിർമ്മിക്കുന്നില്ല. നിരീക്ഷിച്ച ഒരു അഭ്യർത്ഥന ലോഗിംഗിന് മുമ്പ് അതിന്റെ ഓരോ ഭാഗത്തെയും റെഡാക്ഷൻ ഷാഡോ നഷ്ടപ്പെടുകയാണെങ്കിൽ, അല്ലെങ്കിൽ പിന്നീടുള്ള അഭ്യർത്ഥന മ്യൂട്ടേഷനുകൾക്ക് ശേഷം നിരവധി വീഡിയോ ഷാഡോകളിൽ ഒന്ന് പൊരുത്തപ്പെടുന്നില്ലെങ്കിൽ, നിലനിർത്തിയ അഭ്യർത്ഥന ബോഡി ഭാഗികമായി റെഡാക്ട് ചെയ്ത ട്രാൻസ്ക്രിപ്റ്റ് നിലനിർത്തുന്നതിന് പകരം പൂർണ്ണമായും ഒഴിവാക്കപ്പെടുന്നു.

നിരീക്ഷിച്ച ഒരു അഭ്യർത്ഥനയ്ക്കായി, ഒരു മോഡൽ പ്രതികരണം ഒരു സ്ട്രക്ചർഡ് ക്യൂ അതിരില്ലാതെ ട്രാൻസ്ക്രിപ്റ്റിന്റെ ഏതെങ്കിലും ഭാഗം ഉദ്ധരിച്ചേക്കാം. അതിനാൽ അതിന്റെ നിലനിർത്തിയ കോൾ-ലോഗ് `responseBody` ഒരു ഒഴിവാക്കൽ മാർക്കർ ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു; വിശദമായ പൈപ്പ്ലൈൻ ആർട്ടിഫാക്റ്റ് (അപ്സ്ട്രീം/ക്ലയിന്റ് ബോഡികളും സ്ട്രീം ചങ്കുകളും ഉൾപ്പെടാം) നിലനിർത്തുന്നില്ല. സെമാന്റിക്, ഐഡംപൊട്ടൻസി, റീസണിംഗ്-റീപ്ലേ കാഷെകൾ ആ അഭ്യർത്ഥനയ്ക്കായുള്ള റീഡുകളും റൈറ്റുകളും ഒഴിവാക്കുന്നു. പ്രൊവൈഡർ അഭ്യർത്ഥനയും ക്ലയിന്റ്-ദൃശ്യമായ പ്രതികരണവും മാറ്റമില്ലാതെ തുടരുന്നു. വിശദമായ ആർട്ടിഫാക്റ്റ് ഒഴിവാക്കുമ്പോൾ താൽക്കാലിക ബഫറിൽ നിന്ന് നേരത്തെയുള്ള കീപലൈവ് ബൈറ്റുകൾ ഒഴുകിപ്പോകുന്നു. കിറോയുടെ തെറ്റായ EventStream മുന്നറിയിപ്പ് പേലോഡ് ബൈറ്റ് കൗണ്ട് മാത്രം റിപ്പോർട്ട് ചെയ്യുന്നു, അതിന്റെ ഉള്ളടക്കങ്ങളോ JSON പാഴ്സറിന്റെ റോ എററോ ഒരിക്കലും റിപ്പോർട്ട് ചെയ്യുന്നില്ല.
ബന്ധമില്ലാത്ത ഓരോ പ്രൊവൈഡർ/പ്ലഗിൻ ഡയഗ്നോസ്റ്റിക്സും ഓഡിറ്റ് ചെയ്തിട്ടുണ്ടെന്ന് ഇത് അവകാശപ്പെടുന്നില്ല; വിശാലമായ നിലനിർത്തിയ-സിങ്ക് സ്വീപ്പ് #11658-ൽ ട്രാക്ക് ചെയ്യുന്നു.

ആന്തരിക `/api/modality-bridge/video/drilldown` ലൈഫ്സൈക്കിൾ ഒരു പ്രത്യേക, ലൂപ്പ്ബാക്ക്/ടോക്കൺ-ഓതന്റിക്കേറ്റഡ് കാഷെ സബ്സ്ട്രേറ്റാണ്. ഓരോ പ്രവർത്തനത്തിനും ഒരു കാനോനിക്കൽ ഒപാക് പ്രിൻസിപ്പൽ ഐഡിയും ആവശ്യമാണ്. ഒരു പ്രൊഡക്ഷൻ കോളർ പ്രവർത്തനക്ഷമമാക്കുന്നതിന് മുമ്പ്, അത് ഓതന്റിക്കേറ്റഡ് ടെനന്റിൽ നിന്ന് ആ ഐഡി നേടുകയും ക്ലയിന്റ് തിരഞ്ഞെടുത്ത മൂല്യം ഒരിക്കലും കൈമാറുകയും ചെയ്യരുത്. കാഷെ കീകൾ ആ പ്രിൻസിപ്പലിനെ കാനോനിക്കൽ സെഷൻ, വീഡിയോ-റെഫറൻസ് ഐഡികളുമായി ബന്ധിപ്പിക്കുന്നു, അവയുടെ SHA-256-ൽ നിന്ന് ലഭിച്ച കീകൾ മാത്രം സംഭരിക്കുന്നു, കൂടാതെ റീഡുകളും ഡിലീഷനും അതേ പ്രിൻസിപ്പലിലേക്ക് പരിമിതപ്പെടുത്തുന്നു. കാഷെ ഓരോ എൻട്രിക്കും പരമാവധി 16 ഡെറിവ്ഡ് JPEG ഫ്രെയിമുകൾ സംഭരിക്കുന്നു, പത്ത് മിനിറ്റിന് ശേഷം അവയുടെ കാലാവധി തീരുന്നു, കൂടാതെ ബൗണ്ടഡ് `start`/`end` റീഡുകളോ വ്യക്തമായ സെഷൻ ഡിലീഷനോ പിന്തുണയ്ക്കുന്നു.

ഓരോ പ്രിൻസിപ്പലിനും 16 എൻട്രികളും 64 MiB കാനോനിക്കൽ JPEG ഡാറ്റയും പരിമിതപ്പെടുത്തിയിരിക്കുന്നു. ആ പരിധികൾ ആഗോള 64-എൻട്രി/256 MiB പരിധിയിൽ നിന്ന് സ്വതന്ത്രമാണ്: ആഗോള LRU ഒഴിവാക്കൽ പരിഗണിക്കുന്നതിന് മുമ്പ് പ്രിൻസിപ്പൽ ക്വാട്ട സമ്മർദ്ദം ആ പ്രിൻസിപ്പലിന്റെ ഏറ്റവും കുറഞ്ഞ ഉപയോഗത്തിലുള്ള എൻട്രികളെ മാത്രം ഒഴിവാക്കുന്നു. കാലാവധി കഴിഞ്ഞ എൻട്രികൾ കാഷെ പ്രവർത്തനത്തിൽ പ്രിൻസിപ്പൽ, ആഗോള അക്കൗണ്ടിംഗ് എന്നിവയിൽ നിന്ന് നീക്കംചെയ്യുന്നു, അതേസമയം റദ്ദാക്കലും വാലിഡേഷൻ പരാജയവും ഭാഗികമായ മാറ്റിവയ്ക്കൽ ചെയ്യുന്നില്ല.

നോൺ-കാനോനിക്കൽ Base64, അധിക പാഡിംഗ്, നോൺ-JPEG മീഡിയ, തെറ്റായതോ മുറിഞ്ഞതോ ആയ JPEG-കൾ, ഒരു ബൗണ്ടഡ് ഫുൾ-ഇമേജ് `sharp` ഡീകോഡ് ചെയ്യുമ്പോൾ മുന്നറിയിപ്പ് നൽകുന്ന JPEG-കൾ എന്നിവ കാഷെ നിരസിക്കുന്നു. ഇത് ഓരോ സ്വീകരിച്ച ചിത്രത്തെയും ഒരു കാനോനിക്കൽ JPEG ആയി വീണ്ടും എൻകോഡ് ചെയ്യുന്നു, കോളർ ഫീൽഡുകളെ വിശ്വസിക്കുന്നതിന് പകരം ഡീകോഡ് ചെയ്ത ബൈറ്റുകളിൽ നിന്ന് വീതിയും ഉയരവും നേടുന്നു, കൂടാതെ ഏതെങ്കിലും ട്രെയിലിംഗ് പോളിഗ്ലോട്ട് ബൈറ്റുകൾ നിലനിർത്തുന്നതിന് പകരം ഉപേക്ഷിക്കുന്നു. ബൗണ്ടഡ് കാനോനിക്കൽ കംപ്രസ്ഡ് ബഫർ മാത്രമാണ് രണ്ട് ക്വാട്ടകളിലും ഈടാക്കുന്നത്. JSON വയർ പരിധിയിൽ 32 MiB ഡീകോഡ് ചെയ്ത-ഇൻപുട്ട് പരിധിക്കുള്ള Base64 ഓവർഹെഡ് ഉൾപ്പെടുന്നു. ഓരോ സംഭരിച്ച ഡെറിവേഷനും അതിന്റെ വാലിഡേറ്റ് ചെയ്ത JPEG ഫോർമാറ്റ്/റെസല്യൂഷൻ, സാമ്പിൾ പോളിസി, ഡെറിവേഷൻ പതിപ്പ്, സൃഷ്ടിച്ച സമയം, സെർവർ-കണക്കാക്കിയ ഉള്ളടക്ക ഹാഷ്, ഹാഷ് ചെയ്ത പാരന്റ് റെഫറൻസ് എന്നിവയും വിശ്വസനീയമായ കോളറുടെ പാരന്റ്-ഉള്ളടക്ക ഹാഷും രേഖപ്പെടുത്തുന്നു. അറ്റോമിക് കാഷെ കമ്മിറ്റിന് മുമ്പ് അസിൻക്രണസ് ഡീകോഡ്/ഹാഷ് ഘട്ടങ്ങൾക്കിടയിൽ റദ്ദാക്കൽ പരിശോധിക്കുന്നു.

ഈ ട്രാൻഷെറ്റ് ഇതുവരെ ഒരു പ്രൊഡക്ഷൻ പ്രൊഡ്യൂസറെ റൂട്ടിലേക്ക് ബന്ധിപ്പിക്കുന്നില്ല, കൂടാതെ മൾട്ടി-റെസല്യൂഷൻ വേരിയൻ്റ് തിരഞ്ഞെടുക്കൽ നൽകുന്നുമില്ല. അതിനാൽ, സുതാര്യമായ വീഡിയോ ബ്രിഡ്ജ് അഭ്യർത്ഥന പാതയ്ക്ക് അധിക ജോലിഭാരം വരുന്നില്ല, അതേസമയം ടെനൻ്റ്-ബൗണ്ട് പ്രിൻസിപ്പൽ ഡെറിവേഷനും പൂർണ്ണമായ FU-08 മൾട്ടി-റെസല്യൂഷൻ ലൈഫ്സൈക്കിളും പൂർണ്ണമായ സ്വഭാവമായി രേഖപ്പെടുത്തുന്നതിന് പകരം വ്യക്തമായ തുടർപ്രവർത്തനങ്ങളായി തുടരുന്നു.

കോൺഫിഗർ ചെയ്ത വീഡിയോ മോഡൽ ഉപയോഗിച്ച് ഫ്രെയിമുകൾ ക്രമമായി അടിക്കുറിപ്പ് നൽകുന്നു. ഒരു ശൂന്യമായ വീഡിയോ ഓവർറൈഡ് വിഷൻ ക്രമീകരണം സ്വീകരിക്കുന്നു; രണ്ടും ശൂന്യമാണെങ്കിൽ, വിഷൻ ഓട്ടോ-റൂട്ടർ ഫലപ്രദമായ വിഷൻ-ശേഷിയുള്ള മോഡൽ തിരഞ്ഞെടുക്കുന്നു. വിജയകരമായ അടിക്കുറിപ്പുകൾ യഥാർത്ഥ ഭാഗത്തെ ഒരു സ്ഥിരമായ `[Video description:` പ്രിഫിക്സ് ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു, ഇത് ടെക്സ്റ്റിനെ വിശ്വസനീയമല്ലാത്ത മീഡിയയിൽ നിന്ന് ലഭിച്ച നിരീക്ഷണമായി അടയാളപ്പെടുത്തുകയും മീഡിയയിൽ കാണുന്ന നിർദ്ദേശങ്ങൾ പാലിക്കരുതെന്ന് ഡൗൺസ്ട്രീം മോഡലുകളോട് പറയുകയും ചെയ്യുന്നു. ഫ്രെയിം-അടിക്കുറിപ്പ് കാഷെ കീകൾ JPEG ബൈറ്റുകൾ, പ്രോംപ്റ്റ്, ടൈംസ്റ്റാമ്പ്, ഫലപ്രദമായ മോഡൽ എന്നിവ ഉൾക്കൊള്ളുന്നു; വിജയകരമായ അടിക്കുറിപ്പുകൾ മാത്രമേ കാഷെ ചെയ്യപ്പെടുന്നുള്ളൂ. കാഷെ എൻട്രികൾ യഥാർത്ഥ വിജയകരമായ പ്രൊഡ്യൂസർ മോഡൽ നിലനിർത്തുന്നു, ഒരു ഫാൾബാക്ക് മോഡൽ ഉൾപ്പെടെ; വ്യത്യസ്ത മോഡലുകൾ വ്യത്യസ്ത ഫ്രെയിമുകൾ നിർമ്മിക്കുമ്പോൾ ബ്രിഡ്ജ് `mixed` എന്ന് റിപ്പോർട്ട് ചെയ്യുന്നു. ഒരു കാഷെ ഹിറ്റ്, അഭ്യർത്ഥിച്ച റൂട്ടിംഗ് പ്ലാനായി വീണ്ടും ലേബൽ ചെയ്യുന്നതിന് പകരം ആ പ്രൊഡ്യൂസർ ഐഡൻ്റിറ്റി വീണ്ടും ഉപയോഗിക്കുന്നു. മുഴുവൻ വീഡിയോയുടെയും ഫല കാഷെ, ഔട്ട്പുട്ട് മാറ്റുന്ന ഓരോ ഇൻപുട്ടിലും കീ ചെയ്തിരിക്കുന്നു — പ്രോംപ്റ്റ്, ഫലപ്രദമായ മോഡൽ, സാമ്പിൾ പോളിസി, ഫ്രെയിം കൗണ്ട്, സെമാൻ്റിക് അനാലിസിസ് മോഡ്, നോർമലൈസ് ചെയ്ത ഫോക്കസ് സൂചനയുടെ SHA-256 ഫിംഗർപ്രിൻ്റ്, ഫോക്കസ് വിൻഡോ, `transcript`, `audioTranscript`, കോൺടാക്റ്റ്-ഷീറ്റ് ഫ്ലാഗ് എന്നിവ — അതിനാൽ ഈ അളവുകളിൽ ഏതെങ്കിലും മാറ്റുന്നത് ഒരു കാഷെ മിസ് ആണ്, ഒരിക്കലും പഴയ ഡാറ്റയുടെ പുനരുപയോഗമല്ല. വിഷ്വൽ ഡെഡ്യൂപ്പ് പോളിസി പതിപ്പ്, ത്രെഷോൾഡ്, ബൗണ്ടഡ് കാൻഡിഡേറ്റ്-ഫ്രെയിം കൗണ്ട് എന്നിവയും റിസൾട്ട്-കാഷെ കീയിലും മെറ്റാഡാറ്റയിലും വ്യക്തമാണ്; അതിനാൽ ഒരു പോളിസി മാറ്റത്തിന് പഴയ മുഴുവൻ വീഡിയോ വിവരണവും വീണ്ടും ഉപയോഗിക്കാൻ കഴിയില്ല. റിസൾട്ട്-കാഷെ v4 മെറ്റാഡാറ്റ മോഡും ഫിംഗർപ്രിൻ്റും നിലനിർത്തുന്നു, അസംസ്കൃത ഉപയോക്തൃ ടാസ്ക് ഒരിക്കലുമില്ല. ഗാർഡ്റെയിൽ മെറ്റാഡാറ്റ അഭ്യർത്ഥിച്ചതും ഫലപ്രദവുമായ വിശകലന മോഡുകൾ റിപ്പോർട്ട് ചെയ്യുന്നു; ഉപയോഗയോഗ്യമായ ഉപയോക്തൃ ടെക്സ്റ്റ് ഇല്ലാത്ത അഭ്യർത്ഥിച്ച `focused` മോഡ് ഫലപ്രദമായി `full` എന്ന് റിപ്പോർട്ട് ചെയ്യപ്പെടുന്നു.

ഗാർഡ്റെയിൽ പിന്തുണയ്ക്കുന്ന എല്ലാ വീഡിയോ ഭാഗങ്ങളും എക്സ്ട്രാക്റ്റ് ചെയ്യുന്നു, എന്നാൽ `modalityBridgeVideoMaxVideos` എന്നതിനേക്കാൾ കൂടുതൽ വിവരിക്കുന്നില്ല. `supportsVideo === false` എന്ന് തെളിയിക്കപ്പെട്ട ഒരു ടാർഗെറ്റിനായി, പരാജയപ്പെട്ടതും പരിധി കവിഞ്ഞതുമായ വീഡിയോകൾ വ്യക്തമായ സുരക്ഷിത ടെക്സ്റ്റ് മാർക്കറുകളായി മാറുന്നു, അതിനാൽ അസംസ്കൃത വീഡിയോ നിലനിൽക്കില്ല. കഴിവ് അജ്ഞാതമായിരിക്കുമ്പോൾ, ആ ഭാഗങ്ങൾ സ്പർശിക്കാതെ നിലനിൽക്കുന്നു. `supportsVideo === true` ഉള്ള ടാർഗെറ്റുകൾ ബ്രിഡ്ജിനെ മറികടക്കുന്നു. ക്ലയിൻ്റ് അഭ്യർത്ഥനയുടെ അബോർട്ട് സിഗ്നൽ ഡൗൺലോഡ്, ബ്രോക്കർ ക്യൂ, സബ്പ്രോസസ്സുകൾ, അടിക്കുറിപ്പ് കോളുകൾ എന്നിവയിലൂടെ വ്യാപിക്കുന്നു; അബോർട്ടുകൾ വീഡിയോകൾക്കിടയിൽ നിർത്തുന്നു, അസംസ്കൃത മീഡിയയിലേക്ക് തുറന്ന് പരാജയപ്പെടുന്നില്ല.

റൺടൈം ക്രമീകരണങ്ങൾ DB-ബാക്ക്ഡ് ആണ്, Zod-വാലിഡേറ്റഡ് ആണ്:

| :---------------------------------- | :---------- | :-------------------------------------------------------------------------------------------------------------------------------- |

120 സെക്കൻഡിന് മുകളിലുള്ള ലെഗസി പെർസിസ്റ്റഡ് വീഡിയോ ടൈംഔട്ട് മൂല്യങ്ങൾ ബ്രോക്കർ ഡെഡ്ലൈനിലേക്ക് ക്ലാംപ് ചെയ്യപ്പെടുന്നു; ആ പരിധിക്ക് മുകളിലുള്ള പുതിയ ക്രമീകരണ എഴുത്തുകൾ നിരസിക്കപ്പെടുന്നു. `GET /api/modality-bridge/video/runtime` പ്രാമാണീകരണത്തിനോ റൺടൈം പ്രോബിംഗിനോ മുമ്പ് വിശ്വസനീയമായ സ്റ്റാമ്പ് ചെയ്ത ലൂപ്പ്ബാക്ക് ലോക്കാലിറ്റി ആവശ്യപ്പെടുന്നു, തുടർന്ന് മാനേജ്മെൻ്റ് ഓത്ത് ആവശ്യപ്പെടുന്നു. ഇത് `available`, സാനിറ്റൈസ് ചെയ്ത FFmpeg/ffprobe പതിപ്പുകൾ, റൺടൈം ലഭ്യമല്ലാത്തപ്പോൾ ഒരു നിശ്ചിത കാരണം എന്നിവ മാത്രമേ തിരികെ നൽകുന്നുള്ളൂ. ആന്തരിക എക്സ്ട്രാക്ഷൻ എൻഡ്പോയിൻ്റ് ഒരു പൊതു അപ്ലോഡ് API അല്ല: ക്യൂ സാച്ചുറേഷൻ `503` ഉം `Retry-After` ഉം തിരികെ നൽകുന്നു, ഒരു കോളർ വിച്ഛേദിക്കൽ `499` തിരികെ നൽകുന്നു, നിശ്ചിത ബ്രോക്കർ ഡെഡ്ലൈൻ `504` തിരികെ നൽകുന്നു. പരിവർത്തനം ചെയ്ത പ്രതികരണങ്ങൾ വിഷൻ അല്ലെങ്കിൽ ഓഡിയോ സെഗ്മെൻ്റുകൾ നീക്കം ചെയ്യാതെ `video->text;model=<visionModel>;parts=<videos>` എന്നത് കേന്ദ്ര `x-omniroute-modality-bridge` ഹെഡറിലേക്ക് ചേർക്കുന്നു.

### PII മാസ്കർ (`piiMasker.ts`)

**രണ്ട്** ഘട്ടങ്ങളിലും പ്രവർത്തിക്കുന്നു.

- **`preCall`** പേലോഡ് ക്ലോൺ ചെയ്യുന്നു, `system`, `messages`, `input`, `prompt` (പ്ലെയിൻ സ്ട്രിംഗ് ഇനങ്ങൾ ഉൾപ്പെടെ) എന്നിവയിലൂടെ സഞ്ചരിക്കുന്നു, കൂടാതെ സ്ട്രിംഗ് `content`/`text` ഫീൽഡുകളിൽ `processPII()` ( `@/shared/utils/inputSanitizer` ൽ നിന്ന്) പ്രയോഗിക്കുന്നു. `PII_REDACTION_ENABLED=true` ആയിരിക്കുമ്പോൾ, കണ്ടെത്തിയ PII ഔട്ട്ബൗണ്ട് പേലോഡിൽ റെഡാക്ട് ചെയ്യപ്പെടുന്നു. ഇത് `INPUT_SANITIZER_MODE` (ഇത് പ്രോംപ്റ്റ്-ഇൻജക്ഷൻ പോളിസി മാത്രം നിയന്ത്രിക്കുന്നു) എന്നതിൽ നിന്ന് സ്വതന്ത്രമാണ്. റെഡാക്ഷൻ ഓഫായിരിക്കുമ്പോൾ, കോൾ ഉള്ളടക്കം മാറ്റിയെഴുതാതെ കണ്ടെത്തൽ എണ്ണം രേഖപ്പെടുത്തുന്നു.
- **`postCall`** പ്രതികരണം ഡീപ്-ക്ലോൺ ചെയ്യുന്നു, `sanitizePIIResponse()` ഉം റെസ്പോൺസസ്-API-ഷേപ്പ് മാസ്കറും (`maskResponsesOutput` — `output_text`, `output[].content[].text` എന്നിവ ഉൾക്കൊള്ളുന്നു) പ്രവർത്തിപ്പിക്കുന്നു. ഏതെങ്കിലും റെഡാക്ഷൻ സംഭവിക്കുകയാണെങ്കിൽ, പരിഷ്കരിച്ച പ്രതികരണം യഥാർത്ഥത്തെ മാറ്റിസ്ഥാപിക്കുന്നു.

ഗാർഡ്റെയിൽ ഒരിക്കലും തടസ്സപ്പെടുത്തുന്നില്ല; അത് അടയാളപ്പെടുത്തുകയോ (`meta.detections`, `meta.redacted`) അല്ലെങ്കിൽ മാറ്റിയെഴുതുകയോ മാത്രം ചെയ്യുന്നു.

### പ്രോംപ്റ്റ് ഇൻജക്ഷൻ (`promptInjection.ts`)

ഉപയോക്താവ് നൽകുന്ന ഉള്ളടക്കത്തിലെ പ്രതികൂല ഘടനകൾ കണ്ടെത്തുകയും കോൺഫിഗർ ചെയ്ത പോളിസി നടപ്പിലാക്കുകയും ചെയ്യുന്നു. പരിസ്ഥിതി വേരിയബിളുകളും കൺസ്ട്രക്ടർ ഓപ്ഷനുകളും വഴിയാണ് പ്രവർത്തനം നിയന്ത്രിക്കുന്നത്:

| ക്രമീകരണം          | Env var                                                                                               | ഡിഫോൾട്ട് | ഫലം                                                                                                                                                                                                                                     |
| ------------------ | ----------------------------------------------------------------------------------------------------- | --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| പ്രവർത്തനക്ഷമം     | `INPUT_SANITIZER_ENABLED`                                                                             | `true`    | `false` ആയിരിക്കുമ്പോൾ, ഗാർഡ്റെയിൽ ഷോർട്ട്-സർക്യൂട്ട് ചെയ്യുന്നു.                                                                                                                                                                       |
| മോഡ്               | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                       | `warn`    | ഇൻജക്ഷൻ പോളിസി: `block`, `warn`, അല്ലെങ്കിൽ `log`. (`redact` പിന്നോട്ട്-അനുയോജ്യതയ്ക്കായി സ്വീകാര്യമാണ്, പക്ഷേ ഇത് ഇൻജക്ഷൻ ടെക്സ്റ്റ് നീക്കം ചെയ്യുന്നില്ല; PII മാറ്റിയെഴുതാനുള്ള അഭ്യർത്ഥന `PII_REDACTION_ENABLED` നിയന്ത്രിക്കുന്നു.) |
| ബ്ലോക്ക് ത്രെഷോൾഡ് | `blockThreshold` option / `INPUT_SANITIZER_BLOCK_THRESHOLD` (alias `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`    | ബ്ലോക്ക് ചെയ്യാൻ ആവശ്യമായ ഏറ്റവും കുറഞ്ഞ തീവ്രത. ഡിഫോൾട്ടായി മീഡിയം നിരീക്ഷിക്കാൻ മാത്രമുള്ളതാണ്.                                                                                                                                       |

**മോഡ് മുൻഗണന** (`getMode`): കോളർ `options.mode` →
`INJECTION_GUARD_MODE` **DB ഫീച്ചർ-ഫ്ലാഗ് ഓവർറൈഡ്** (ഡാഷ്ബോർഡ് → ക്രമീകരണങ്ങൾ →
ഫീച്ചർ ഫ്ലാഗുകൾ) → `INJECTION_GUARD_MODE` env → `INPUT_SANITIZER_MODE` env →
`warn`. അതിനാൽ ഒരു ഡാഷ്ബോർഡ് ഓവർറൈഡ് എൻവയോൺമെന്റ് വേരിയബിളുകളെക്കാൾ മുൻഗണന നേടുന്നു, അതുവഴി ഫീച്ചർ
ഫ്ലാഗ്സ് UI പ്രവർത്തിക്കുന്ന ഗാർഡിനെ തത്സമയം നിയന്ത്രിക്കുന്നു (റീസ്റ്റാർട്ട് ആവശ്യമില്ല). DB റീഡ് ഫെയിൽ-സേഫ് ആണ്:
പിശക് സംഭവിക്കുകയാണെങ്കിൽ, ഗാർഡ് env-അധിഷ്ഠിത സ്വഭാവത്തിലേക്ക് മടങ്ങുന്നു, കൂടാതെ ഓവർറൈഡ് ഒന്നും സജ്ജീകരിച്ചിട്ടില്ലെങ്കിൽ,
env-മാത്രം റെസല്യൂഷന് സമാനമായിരിക്കും സ്വഭാവം.

കണ്ടെത്തൽ ഉറവിടങ്ങൾ:

1.  `@/shared/utils/inputSanitizer`-ൽ നിന്നുള്ള `sanitizeRequest()` (പൈപ്പ്ലൈനിലെ മറ്റ് സ്ഥലങ്ങളിൽ ഉപയോഗിക്കുന്ന പങ്കിട്ട ഡിറ്റക്ടർ സെറ്റ്).
2.  ബിൽറ്റ്-ഇൻ `DEFAULT_GUARD_PATTERNS` (നിലവിൽ `system_override_inline`, `markdown_system_block` എന്നിവ, രണ്ടും `high` തീവ്രതയുള്ളവ).
3.  കൺസ്ട്രക്ടർ ഓപ്ഷനുകളിലൂടെ കൈമാറുന്ന ഓപ്ഷണൽ `customPatterns` (സ്ട്രിംഗുകൾ, റെഗുലർ എക്സ്പ്രഷനുകൾ,
    അല്ലെങ്കിൽ `{ name, pattern, severity }` റെക്കോർഡുകൾ).

`mode === "block"` ആയിരിക്കുകയും കുറഞ്ഞത് ഒരു കണ്ടെത്തലെങ്കിലും തീവ്രത പരിധിയിൽ എത്തുകയും ചെയ്യുമ്പോൾ,
`preCall` `{ block: true, message: "Request rejected: suspicious content detected" }` എന്ന് തിരികെ നൽകുന്നു.
`warn`/`log` മോഡുകളിൽ ഗാർഡ്റെയിൽ ലോഗ് ചെയ്യുകയും എന്നാൽ കോളിന് അനുമതി നൽകുകയും ചെയ്യുന്നു.
രജിസ്ട്രിയിലൂടെ കടന്നുപോകാതെ പ്രോംപ്റ്റുകൾ വിലയിരുത്തേണ്ട കോളറുകൾക്കായി പങ്കിട്ട സഹായിയായ `evaluatePromptInjection()` എക്സ്പോർട്ട് ചെയ്തിട്ടുണ്ട്.

**സ്കാൻ പരിധി (v3.8.20):** ഡിറ്റക്ടർ src/shared/utils/inputSanitizer.ts-ലെ
`MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 ബൈറ്റുകൾ) എന്ന ജോയിൻ ചെയ്ത പ്രോംപ്റ്റ് ടെക്സ്റ്റിന്റെ
ആദ്യത്തെ **16 KB** മാത്രമേ പരിശോധിക്കുന്നുള്ളൂ. `detectInjection()` ഉം
`evaluatePromptInjection()` ഉം പാറ്റേൺ ലൂപ്പ് പ്രവർത്തിപ്പിക്കുന്നതിന് മുമ്പ് `slice(0, MAX_INJECTION_SCAN_BYTES)` ചെയ്യുന്നു.
ഇൻജക്ഷൻ നിർദ്ദേശങ്ങൾ ഒരു ഇൻപുട്ടിന്റെ മുകൾ ഭാഗത്തായിരിക്കും, അതിനാൽ ഇത് നൂറുകണക്കിന് KB പേലോഡുകളിൽ
റെഗുലർ എക്സ്പ്രഷൻ CPU/GC എന്നിവയെ പരിമിതപ്പെടുത്തുന്നു, കണ്ടെത്തലിനെ ദുർബലപ്പെടുത്താതെ (cf. #3932, #4041).

### ക്രെഡൻഷ്യൽ മാസ്കർ (`credentialMasker.ts`)

രണ്ട് ഘട്ടങ്ങളിലും പ്രവർത്തിക്കുന്നു, ഡിഫോൾട്ട് ശൃംഖലയിൽ അവസാനത്തേത് (മുൻഗണന `95`).
ഔട്ട്ബൗണ്ട് പേലോഡിൽ (സന്ദേശ ഉള്ളടക്കം, ടൂൾ-കോൾ ആർഗ്യുമെന്റുകൾ, ടൂൾ ഫലങ്ങൾ) നിന്നും പ്രൊവൈഡർ പ്രതികരണത്തിൽ നിന്നും
അറിയപ്പെടുന്ന API-കീ / രഹസ്യ-ടോക്കൺ പാറ്റേണുകൾ ഇത് നീക്കം ചെയ്യുന്നു, അതിനാൽ ഒരു പ്രോംപ്റ്റിലേക്ക് ഒട്ടിച്ച
(അല്ലെങ്കിൽ ഒരു ടൂൾ ഫലം തിരികെ നൽകിയ) ഒരു ക്രെഡൻഷ്യൽ അപ്സ്ട്രീം പ്രൊവൈഡർക്കോ ക്ലയന്റിനോ ചോർത്തപ്പെടുന്നില്ല.

- ഓപ്റ്റ്-ഇൻ മാത്രം, PII റിഡാക്ഷന്റെ അതേ കൺവെൻഷൻ (ഹാർഡ് റൂൾ #20-നോട് ചേർന്നുള്ളത്):
  `settings.credentialRedactionEnabled === true` അല്ലെങ്കിൽ `CREDENTIAL_REDACTION_ENABLED=true` അല്ലെങ്കിൽ ഇത് പ്രവർത്തനരഹിതമാക്കും.
  ഇത് ഓഫായിരിക്കുമ്പോൾ, ഗാർഡ്റെയിൽ ഒരു നോ-ഓപ് ആണ് — ഇത് ഒരിക്കലും ബ്ലോക്ക് ചെയ്യുകയോ മാറ്റിയെഴുതുകയോ ചെയ്യുന്നില്ല.
- `redactCredentials()` പൂർണ്ണമായ പേലോഡ്/പ്രതികരണ ട്രീയിലൂടെ (`walkValue()`, പ്രോട്ടോടൈപ്പ്-പൊല്യൂഷൻ-സേഫ്,
  `WeakSet` വഴി സൈക്കിൾ-സേഫ്) സഞ്ചരിക്കുകയും പൊരുത്തപ്പെടുന്നവയെ `[REDACTED:<type>]` പ്ലേസ്ഹോൾഡർ ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുകയും ചെയ്യുന്നു,
  യഥാർത്ഥത്തിൽ മാറിയ ബ്രാഞ്ചുകൾ മാത്രം ക്ലോൺ ചെയ്യുന്നു.
- `CREDENTIAL_PATTERNS` LLM പ്രൊവൈഡർ കീകൾ (OpenAI, OpenAI-proj, Anthropic, Google, Hugging Face, Replicate),
  VCS/SaaS ടോക്കണുകൾ (GitHub, Slack, Linear, Notion, npm, Postman, Discord), പേയ്മെന്റ് കീകൾ (Stripe, Square),
  ക്ലൗഡ് കീകൾ (AWS access key, Twilio, SendGrid, Mailgun), പ്രൈവറ്റ് കീകൾ / JWT-കൾ,
  ക്രെഡൻഷ്യൽ അടങ്ങിയ കണക്ഷൻ സ്ട്രിംഗുകൾ (`mongodb://user:pass@...`, തുടങ്ങിയവ), കൂടാതെ ഒരു പൊതുവായ
  `Authorization`/`x-api-key`/`api-key`/`apikey` ഹെഡർ-വാല്യൂ പാറ്റേൺ എന്നിവ ഉൾക്കൊള്ളുന്നു.
  ഹെഡർ ആകൃതിയിലുള്ള കീകൾ (`authorization`, `x-api-key`, `api-key`, `apikey`) ഘടനാപരമായി (വാല്യൂ മാത്രം,
  `Bearer `/`Basic ` പോലുള്ള സ്കീം പ്രിഫിക്സ് നിലനിർത്തിക്കൊണ്ട്) നീക്കംചെയ്യുന്നു, അല്ലാതെ പൊതുവായ ടെക്സ്റ്റ് റെഗുലർ എക്സ്പ്രഷൻ വഴിയല്ല.
- ഗാർഡ്റെയിൽ ഒരിക്കലും ബ്ലോക്ക് ചെയ്യുന്നില്ല; ഇത് മാറ്റിയെഴുതുകയും (`modifiedPayload` / `modifiedResponse`)
  അടയാളപ്പെടുത്തുകയും (`meta.credentialsRedacted`, `meta.count`) മാത്രം ചെയ്യുന്നു.

റിഗ്രഷൻ ഗാർഡ്: `tests/unit/credential-masker-guardrail.test.ts`.

## അടിസ്ഥാന കരാർ (base.ts)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true short-circuits the chain
  message?: string; // തടയുമ്പോൾ ഇത് ദൃശ്യമാകും
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // അഭ്യർത്ഥന മാറ്റിയെഴുതാൻ preCall തിരികെ നൽകുന്നത്
  modifiedResponse?: TValue; // പ്രതികരണം മാറ്റിയെഴുതാൻ postCall തിരികെ നൽകുന്നത്
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

ഒരു ഗാർഡ്റെയിൽ "മാറ്റമില്ല" എന്ന് സൂചിപ്പിക്കുന്നത് ``void`, `{}`, അല്ലെങ്കിൽ `{ block: false }`തിരികെ നൽകിക്കൊണ്ടാണ്.`modifiedPayload`/`modifiedResponse`തിരികെ നൽകുന്നത്, താഴെയുള്ള ഗാർഡ്റെയിലുകൾക്കായി ചെയിനിലൂടെ ഒഴുകുന്ന മൂല്യത്തെ മാറ്റിസ്ഥാപിക്കുന്നു.`signal?: AbortSignal` കോളർ ലൈഫ്സൈക്കിളിനെ ഗാർഡ്റെയിലുകളിലേക്ക് എത്തിക്കുന്നു. ഒരു അഭ്യർത്ഥന റദ്ദാക്കൽ എന്നത് മനഃപൂർവമായ ഒരു ഫെയിൽ-ഓപ്പൺ അപവാദമാണ്: മീഡിയ ബ്രിഡ്ജുകൾ പ്രവർത്തിക്കുന്നത് നിർത്തുകയും, അസംസ്കൃത മീഡിയയെ പിന്തുണയ്ക്കാത്ത ഒരു ലക്ഷ്യസ്ഥാനത്തേക്ക് പുനഃസ്ഥാപിക്കാതെ വൃത്തിയാക്കുകയും ചെയ്യുന്നു.

## രജിസ്ട്രി (registry.ts)

സിംഗിൾട്ടൺ `guardrailRegistry` താഴെ പറയുന്നവ നൽകുന്നു:

- `register(guardrail)` — ഒരു ഗാർഡ്റെയിൽ ചേർക്കുന്നു (അല്ലെങ്കിൽ സാധാരണമാക്കിയ പേര് ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു) കൂടാതെ ആരോഹണ ക്രമത്തിൽ `priority` അനുസരിച്ച് വീണ്ടും ക്രമീകരിക്കുന്നു.
- `clear()` / `list()` — അഡ്മിനിസ്ട്രേറ്റീവ് സഹായികൾ.
- `runPreCallHooks(payload, context)` — സജീവ ഗാർഡ്റെയിലുകളിലൂടെ ആവർത്തിക്കുന്നു, `modifiedPayload` വഴി പേലോഡിനെ കടത്തിവിടുന്നു, കൂടാതെ ആദ്യത്തെ `block: true` വരുമ്പോൾ നിർത്തുന്നു.
- `runPostCallHooks(response, context)` — പ്രതികരണ ഭാഗത്തും ഇതേ പ്രവാഹം.
- `resetGuardrailsForTests({ registerDefaults })` — നിലവിലെ അവസ്ഥ മായ്ക്കുന്നു കൂടാതെ വൃത്തിയുള്ള ടെസ്റ്റ് ഐസൊലേഷനായി ഡിഫോൾട്ടുകൾ ഓപ്ഷണലായി വീണ്ടും രജിസ്റ്റർ ചെയ്യുന്നു.

രണ്ട് റണ്ണറുകളും `{ blocked, payload|response, results, guardrail?, message? }` തിരികെ നൽകുന്നു, ഇവിടെ `results` എന്നത് `GuardrailExecutionResult` റെക്കോർഡുകളുടെ ഒരു നിരയാണ്, അതിൽ ഓരോ ഗാർഡ്റെയിലിനുമുള്ള `blocked`, `skipped`, `modified`, `error`, `meta` ഫീൽഡുകൾ ഉൾപ്പെടുന്നു, ഇത് ട്രേസിംഗിന് ഉപയോഗപ്രദമാണ്.

### ഓരോ അഭ്യർത്ഥനയ്ക്കും ഗാർഡ്റെയിലുകൾ പ്രവർത്തനരഹിതമാക്കുന്നു

`resolveDisabledGuardrails({ apiKeyInfo, body, headers })` നിലവിലെ അഭ്യർത്ഥനയ്ക്കായി ഒഴിവാക്കേണ്ട ഗാർഡ്റെയിൽ പേരുകളുടെ ഡ്യൂപ്ലിക്കേഷൻ ഒഴിവാക്കിയ ഒരു ലിസ്റ്റ് ശേഖരിക്കുന്നു. ഉറവിടങ്ങൾ (എല്ലാം ഓപ്ഷണൽ, എല്ലാം ലയിപ്പിച്ചത്):

- `apiKeyInfo.disabledGuardrails`
- അഭ്യർത്ഥന ബോഡി `disabledGuardrails` (ടോപ്പ്-ലെവൽ)
- അഭ്യർത്ഥന ബോഡി `metadata.disabledGuardrails`
- ഹെഡർ `x-omniroute-disabled-guardrails` (അല്ലെങ്കിൽ പഴയ `x-disabled-guardrails`)

മൂല്യങ്ങൾ സ്ട്രിംഗുകളുടെ നിരകളോ കോമയാൽ വേർതിരിച്ച സ്ട്രിംഗോ ആകാം; പേരുകൾ ലോവർകേസ് കെബാബ്-കേസിലേക്ക് സാധാരണമാക്കുന്നു (`pii_masker` → `pii-masker`). ഫലം `context.disabledGuardrails` വഴി രജിസ്ട്രിയിലേക്ക് കൈമാറുന്നു, ഇത് പൊരുത്തപ്പെടുന്ന ഗാർഡ്റെയിലുകളെ ഒഴിവാക്കുന്നു (`results`-ൽ `skipped: true`).

## എക്സിക്യൂഷൻ ഓർഡർ

`src/sse/handlers/chat.ts`, `open-sse/handlers/chatCore.ts` എന്നിവയിലൂടെ ഒഴുകുന്ന ഓരോ അഭ്യർത്ഥനയ്ക്കും:

1. `resolveDisabledGuardrails(...)` API കീ, ബോഡി, ഹെഡറുകൾ എന്നിവയിൽ നിന്ന് സ്കിപ്പ് ലിസ്റ്റ് നിർമ്മിക്കുന്നു.
2. `guardrailRegistry.runPreCallHooks(body, ctx)` ഗാർഡ്റെയിലുകൾ ആരോഹണ മുൻഗണനാ ക്രമത്തിൽ പ്രവർത്തിപ്പിക്കുന്നു:
   - പ്രവർത്തനരഹിതമാക്കിയ ഗാർഡ്റെയിലുകൾ `skipped` എന്ന് രേഖപ്പെടുത്തുന്നു.
   - ഓരോ ഗാർഡ്റെയിലിന്റെയും `preCall` `modifiedPayload` വഴി പേലോഡ് മാറ്റിയെഴുതിയേക്കാം.
   - ആദ്യത്തെ `block: true` ചെയിൻ ചുരുക്കുകയും ഹാൻഡ്ലർ ഒരു ഗാർഡ്റെയിൽ നിരസിക്കൽ പ്രതികരണം നൽകുകയും ചെയ്യുന്നു.
3. (സാധ്യതയുള്ള മാറ്റിയെഴുതിയ) പേലോഡ് കോംബോ റൂട്ടിംഗിലേക്കും അപ്സ്ട്രീം ഡിസ്പാച്ചിലേക്കും ഒഴുകുന്നു.
4. പ്രതികരണം കൂട്ടിച്ചേർത്ത ശേഷം, `guardrailRegistry.runPostCallHooks(...)` പ്രതികരണത്തിൽ അതേ ചെയിൻ പ്രവർത്തിപ്പിക്കുന്നു. ഇവിടെ `block: true` അപ്സ്ട്രീം പ്രതികരണം ഒഴിവാക്കുന്നു.

തെറ്റ് വരുത്തുന്ന ഗാർഡ്റെയിലുകൾ `error: <message>` എന്ന് രേഖപ്പെടുത്തുകയും `logger.warn` വഴി ലോഗ് ചെയ്യുകയും ചെയ്യുന്നു, പക്ഷേ ചെയിൻ തുടരുന്നു — രൂപകൽപ്പന പ്രകാരം ഫെയിൽ-ഓപ്പൺ.

## കോൺഫിഗറേഷൻ

ബിൽറ്റ്-ഇൻ ഗാർഡ്റെയിലുകൾ വായിക്കുന്ന എൻവയോൺമെന്റ് വേരിയബിളുകൾ:

| വേരിയബിൾ                              | ഉപയോഗിക്കുന്നത്           | പ്രഭാവം                                                                                                             |
| ------------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `INPUT_SANITIZER_ENABLED`             | `prompt-injection`        | കണ്ടെത്തൽ പൂർണ്ണമായും പ്രവർത്തനരഹിതമാക്കാൻ `false` എന്ന് സജ്ജമാക്കുക.                                               |
| `INPUT_SANITIZER_MODE`                | `prompt-injection`        | ഇൻജക്ഷൻ പോളിസി: `warn`, `block`, അല്ലെങ്കിൽ `log`. പഴയ മൂല്യം `redact` ഇൻജക്ഷൻ ടെക്സ്റ്റ് മാറ്റിയെഴുതുന്നില്ല.      |
| `INJECTION_GUARD_MODE`                | `prompt-injection`        | ഇൻജക്ഷൻ ഗാർഡിനായുള്ള മോഡ്; എൻവയോൺമെന്റ് വേരിയബിളുകളെ **അസാധുവാക്കുന്ന** ഒരു DB ഫീച്ചർ ഫ്ലാഗ് കൂടിയാണിത് (DB > ENV). |
| `INPUT_SANITIZER_BLOCK_THRESHOLD`     | `prompt-injection`        | `MODE=block` നിരസിക്കുന്ന ഏറ്റവും കുറഞ്ഞ തീവ്രത: `high` (സ്ഥിരസ്ഥിതി), `medium`, അല്ലെങ്കിൽ `low`.                  |
| `INJECTION_GUARD_BLOCK_THRESHOLD`     | `prompt-injection`        | `INPUT_SANITIZER_BLOCK_THRESHOLD` എന്നതിന്റെ പഴയ പേര്.                                                              |
| `PII_REDACTION_ENABLED`               | `pii-masker`              | `true` ആയിരിക്കുമ്പോൾ, അഭ്യർത്ഥന PII റെഡാക്ട് ചെയ്യപ്പെടുന്നു (ഇൻജക്ഷൻ മോഡിൽ നിന്ന് സ്വതന്ത്രമായി).                 |
| `PII_RESPONSE_SANITIZATION` / `_MODE` | `pii-masker` (ഡൗൺസ്ട്രീം) | പ്രതികരണ-വശത്തുള്ള മാസ്കർ സ്വഭാവം നിയന്ത്രിക്കുന്നു.                                                                |

മോഡാലിറ്റി ബ്രിഡ്ജ് ഗാർഡ്റെയിലുകൾ DB-ബാക്ക്ഡ് സെറ്റിംഗ്സ് സ്റ്റോറിൽ നിന്ന് (`getSettings()`) റൺടൈം കോൺഫിഗറേഷൻ വായിക്കുന്നു, എൻവയോൺമെന്റ് വേരിയബിളുകളിൽ നിന്നല്ല. വിഷന്റെ പ്രാഥമിക കീകൾ `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, `modalityBridgeCacheMaxEntries` എന്നിവയാണ്. പഴയ `visionBridge*` കീകൾ ഡോക്യുമെന്റ് ചെയ്ത വൺ-സൈക്കിൾ റീഡ് ഫാൾബാക്കായി മാത്രമേ സ്വീകരിക്കുകയുള്ളൂ; ഡാഷ്ബോർഡ് റൈറ്റുകൾ പ്രാഥമിക കീകൾ ഉപയോഗിക്കുന്നു. സ്ഥിരസ്ഥിതികളും ഫാൾബാക്ക് റെസല്യൂവറും `src/shared/constants/modalityBridgeDefaults.ts` എന്നതിലാണ്, പഴയ സ്ഥിരാങ്കങ്ങൾ `src/shared/constants/visionBridgeDefaults.ts` എന്നതിൽ നിലനിർത്തുന്നു.

ഓഡിയോ `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`, `modalityBridgeAudioTimeout`, `modalityBridgeAudioMaxClips` എന്നിവയും പങ്കിട്ട `modalityBridgeCache*` ക്രമീകരണങ്ങളും ഉപയോഗിക്കുന്നു. മോഡാലിറ്റി ബ്രിഡ്ജ് സ്കീമയോടൊപ്പം ഈ കീകൾ അവതരിപ്പിച്ചതിനാൽ ഓഡിയോയ്ക്ക് പഴയ-കീ ഫാൾബാക്ക് ഇല്ല.

വീഡിയോ `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`, `modalityBridgeVideoModel`, `modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`, `modalityBridgeVideoMaxVideos`, `modalityBridgeVideoTimeout` എന്നിവയും പങ്കിട്ട `modalityBridgeCache*` ക്രമീകരണങ്ങളും ഉപയോഗിക്കുന്നു. FFmpeg/ffprobe ഓപ്ഷണൽ ഓപ്പറേഷണൽ ഡിപൻഡൻസികളും ഫ്രെയിം ക്യാപ്ഷനിംഗ് ലേറ്റൻസിയും മോഡൽ ചെലവും വർദ്ധിപ്പിക്കുന്നതിനാൽ ഇത് സ്ഥിരസ്ഥിതിയായി പ്രവർത്തനരഹിതമാക്കിയിരിക്കുന്നു.

## കസ്റ്റം ഗാർഡ്റെയിലുകൾ

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

ഘട്ടങ്ങൾ:

1.  `BaseGuardrail` വികസിപ്പിച്ച് `src/lib/guardrails/myGuardrail.ts` ഉണ്ടാക്കുക.
2.  `preCall`, `postCall` എന്നിവ നടപ്പിലാക്കുക.
3.  ഇറക്കുമതി ചെയ്യുന്ന സമയത്ത് ( `registerDefaultGuardrails` ൽ നിന്ന് പുഷ് ചെയ്യുക) അല്ലെങ്കിൽ റൺടൈമിൽ `guardrailRegistry.register(...)` വിളിക്കുക — രജിസ്ട്രി, അതേ സാധാരണവൽക്കരിച്ച പേരുള്ള മുൻ ഗാർഡ്റെയിലിനെ മാറ്റിസ്ഥാപിക്കും.
4.  `tests/unit/` ന് കീഴിൽ ടെസ്റ്റുകൾ ചേർക്കുക (നിലവിലുള്ള ഉദാഹരണങ്ങൾ: `tests/unit/guardrails-registry.test.ts`, `tests/unit/prompt-injection-guard.test.ts`, `tests/unit/guardrails/visionBridge.test.ts`).

## പരിശോധന

അറിയപ്പെടുന്ന അവസ്ഥയിൽ നിന്ന് ആരംഭിക്കാൻ ടെസ്റ്റുകൾക്കിടയിൽ `resetGuardrailsForTests()` ഉപയോഗിക്കുക. ശൂന്യമായ ഒരു രജിസ്ട്രിയിൽ നിന്ന് ആരംഭിച്ച്, പരിശോധനയിലുള്ള ഗാർഡ്റെയിലുകൾ മാത്രം രജിസ്റ്റർ ചെയ്യാൻ `{ registerDefaults: false }` നൽകുക. വിഷൻ ബ്രിഡ്ജ് ഡിപൻഡൻസി ഇൻജക്ഷൻ (`deps.getSettings`, `deps.callVisionModel`) സ്വീകരിക്കുന്നു; ഓഡിയോ ബ്രിഡ്ജ് ക്രമീകരണങ്ങൾ, കഴിവുകൾ, STT മോഡൽ തിരഞ്ഞെടുക്കൽ, ക്രെഡൻഷ്യൽ പരിശോധനകൾ, ട്രാൻസ്ക്രിപ്ഷൻ എന്നിവയ്ക്കായി സമാനമായ സീമുകൾ നൽകുന്നു. അതിനാൽ, ഡാറ്റാബേസ് അല്ലെങ്കിൽ നെറ്റ്വർക്ക് ആക്സസ് ഇല്ലാതെ തന്നെ ടെസ്റ്റുകൾക്ക് രണ്ട് ഫ്ലോകളും പ്രവർത്തിപ്പിക്കാൻ കഴിയും.

## ഇൻജക്ഷൻ-ഗാർഡ് റൂട്ട് കവറേജ് & റെഡ്-ടീം (ഘട്ടം 8 · ബ്ലോക്ക് D)

ഇൻജക്ഷൻ-ഗാർഡ് (`createInjectionGuard` / `withInjectionGuard`) ഉപയോക്തൃ പ്രോംപ്റ്റുകൾ സ്വീകരിക്കുന്ന എല്ലാ റൂട്ടുകളെയും ഉൾക്കൊള്ളുന്നു. ഇത് `INJECTION_GUARD_MODE` നെ മാനിക്കുന്നു (സ്ഥിരസ്ഥിതി `warn` = ലോഗ് മാത്രം; `block` = HTTP 400 `SECURITY_001` തിരികെ നൽകുന്നു).

| തരം             | റൂട്ടുകൾ                                                                                                                                      | സ്ഥിരസ്ഥിതി മോഡ് |
| :-------------- | :-------------------------------------------------------------------------------------------------------------------------------------------- | :--------------- |
| Text (existing) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                       | warn             |
| Generative      | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn             |
| Data            | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                               | warn             |

ടെക്സ്റ്റ് എക്സ്ട്രാക്ഷൻ (`extractMessageContents`) `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` എന്നിവയെ ഉൾക്കൊള്ളുന്നു.

**റെഡ്-ടീം (രാത്രികാല, `nightly-llm-security.yml`):** `INJECTION_GUARD_MODE=block` ആയിരിക്കുമ്പോൾ ഓരോ റൂട്ടും OWASP-LLM കോർപ്പസിനെ തടയുന്നുവെന്ന് promptfoo സാധൂകരിക്കുന്നു; garak പ്രോബുകൾ പ്രവർത്തിപ്പിക്കുന്നു (രഹസ്യമില്ലാതെ ഒഴിവാക്കുന്നു). സ്ഥിരതയ്ക്കായി `moderations` ഉൾപ്പെടുത്തിയിട്ടുണ്ട് — ബ്ലോക്ക്-മോഡിലുള്ള ഓപ്പറേറ്റർമാർക്ക് `resolveDisabledGuardrails` വഴി ഇതിനെ ഒഴിവാക്കാം.

രാത്രികാല വർക്ക്ഫ്ലോ (`.github/workflows/nightly-llm-security.yml`, cron + മാനുവൽ ഡിസ്പാച്ച്) ന് രണ്ട് ജോലികളുണ്ട്:

- **`promptfoo-guard` (തടയുന്നത്)** — `INJECTION_GUARD_MODE=block` ഉപയോഗിച്ച് `promptfoo eval -c promptfooconfig.yaml` പ്രവർത്തിപ്പിക്കുന്നു. ഓരോ പ്രതികൂല സാഹചര്യവും (ഉദാഹരണത്തിന്, "മുമ്പത്തെ എല്ലാ നിർദ്ദേശങ്ങളും അവഗണിക്കുക...", DAN-ശൈലിയിലുള്ള ജയിൽബ്രേക്കുകൾ) പ്രതികരണത്തിൽ `error.code === "SECURITY_001"` ഉണ്ടെന്ന് ഉറപ്പാക്കുന്നു, അതായത് ഗാർഡ് യഥാർത്ഥത്തിൽ അഭ്യർത്ഥന നിരസിച്ചു.
- **`garak` (ഉപദേശക)** — ഒരു പ്രാദേശിക OmniRoute ഇൻസ്റ്റൻസിനെതിരെ (`http://localhost:20128/v1`) garak `--probes promptinject,dan,leakreplay` പ്രവർത്തിപ്പിക്കുന്നു. ഒരു പ്രൊവൈഡർ രഹസ്യം (`PROMPTFOO_PROVIDER_KEY`) വഴി നിയന്ത്രിക്കപ്പെടുന്നു; ഇത് ഭംഗിയായി ഒഴിവാക്കുകയും `|| true` എന്ന് ചേർക്കുകയും ചെയ്യുന്നു, അതിനാൽ CI പരാജയപ്പെടാതെ റിപ്പോർട്ട് ചെയ്യുന്നു.

ഗാർഡ് ഹെൽപ്പറിന്റെ (`createInjectionGuard` / `withInjectionGuard`) കവറേജ് എല്ലാ പ്രോംപ്റ്റ്-ഉൾക്കൊള്ളുന്ന `/v1` റൂട്ടുകളിലും വ്യാപിക്കുന്നു; പ്രോംപ്റ്റ് ടെക്സ്റ്റ് `src/shared/utils/inputSanitizer.ts` ലെ `extractMessageContents()` വഴി `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` എന്നിവയിൽ നിന്ന് വലിച്ചെടുക്കുന്നു.
