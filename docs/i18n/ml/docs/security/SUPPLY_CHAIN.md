OmniRoute npm + Docker ആർട്ടിഫാക്റ്റുകൾ പ്രസിദ്ധീകരിക്കുന്നു. ഈ ഗേറ്റുകൾ ഉറവിടസാക്ഷ്യം,
ഇൻവെന്ററി (SBOM), CVE സ്കാനിംഗ് എന്നിവ നൽകുന്നു; ഇവയെല്ലാം OSS ആണ്, കൂടാതെ release workflow-കളുമായി സംയോജിപ്പിച്ചിരിക്കുന്നു.
**ആദ്യം advisory** എന്ന സമീപനം — ഇപ്പോൾ അവ റിപ്പോർട്ട് ചെയ്യുന്നു; ആദ്യത്തെ
വിജയകരമായ release-ന് ശേഷം blocking ആയി ഉയർത്തും.

| ഗേറ്റ്                   | ടൂൾ                                            | എവിടെ                         | തടയുമോ?                             | ഔട്ട്പുട്ട്                                                |
| ------------------------ | ---------------------------------------------- | ----------------------------- | ----------------------------------- | ---------------------------------------------------------- |
| SLSA ഉറവിടസാക്ഷ്യം (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | പ്രസിദ്ധീകരണം പരാജയപ്പെട്ടാൽ മാത്രം | npmjs badge / `npm audit signatures`                       |
| npm SBOM                 | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | സൃഷ്ടിക്കൽ പരാജയപ്പെട്ടാൽ മാത്രം    | Release asset + artifact                                   |
| image SBOM               | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | advisory                            | CycloneDX artifact                                         |
| Trivy CVE (SARIF)        | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | advisory                            | SARIF (HIGH+CRITICAL) → Security tab                       |
| Trivy CRITICAL ഗേറ്റ്    | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | **blocking**                        | പരിഹരിക്കാവുന്ന CRITICAL-ൽ `exit-code: '1'`                |
| osv vulnCount            | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **blocking**                        | `metrics.vulnCount`-നെ ratchet ചെയ്യുന്നു (direction:down) |
| OpenSSF Scorecard        | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | advisory                            | SARIF → Security + badge                                   |

image CVE ratchet `docker-publish.yml`-ൽ **രണ്ട് ഘട്ടങ്ങൾ** ഉപയോഗിക്കുന്നു: SARIF ഘട്ടം
(`HIGH,CRITICAL`, `exit-code: 0`) തടയാതെ തന്നെ HIGH+CRITICAL-നെ Security tab-ൽ
ദൃശ്യമാക്കി നിലനിർത്തുന്നു; _CRITICAL ഗേറ്റ്_ ഘട്ടം (`severity: CRITICAL`, `ignore-unfixed: true`,
`exit-code: 1`) **പരിഹാരം ലഭ്യമായ** ഒരു CRITICAL CVE ഉണ്ടെങ്കിൽ release പരാജയപ്പെടുത്തുന്നു. upstream patch ഇല്ലാത്ത
base-image CVE കാരണം release തടയുന്നത് `ignore-unfixed`
ഒഴിവാക്കുന്നു.

## ⚠️ CVE വ്യതിയാനം (blocking osv/Trivy ഗേറ്റുകൾ)

osv, Trivy എന്നിവ dependency-കളെ **തുടർച്ചയായി വളരുന്ന** CVE database-ുകളുമായി താരതമ്യം ചെയ്യുന്നു.
**dependency-കളൊന്നും മാറ്റാത്ത** ഒരു PR പോലും നിലവിലുള്ള dependency-യിൽ ഒരു പുതിയ CVE
വെളിപ്പെടുത്തിയതിനാൽ പെട്ടെന്ന് red ആകാം (osv: അളന്ന `vulnCount` > baseline; Trivy: image-ൽ
പരിഹരിക്കാവുന്ന ഒരു പുതിയ CRITICAL). **ഇത് blocking CVE ഗേറ്റിന്റെ പ്രതീക്ഷിത പ്രവർത്തനരീതിയാണ്,
product regression അല്ല.**

പുതുതായി വെളിപ്പെടുത്തിയ CVE കാരണം osv അല്ലെങ്കിൽ Trivy red ആകുമ്പോൾ, പരിഹാരം:

1. **ബാധിച്ച dependency-യുടെ version ഉയർത്തുക** (അഭികാമ്യം) — `package.json`
   `overrides` (transitive dependency-കൾ) വഴി patched version-ലേക്ക് upgrade ചെയ്യുക, അല്ലെങ്കിൽ patched base ഉപയോഗിച്ച് image വീണ്ടും build ചെയ്യുക.
2. **upstream പരിഹാരം ഇല്ലെങ്കിൽ:**
   - **osv:** `config/quality/quality-baseline.json`-ലെ `metrics.vulnCount` വീണ്ടും baseline ആക്കുക
     (`npm run quality:ratchet -- --update` dedicated gate-കളെ ഉൾക്കൊള്ളുന്നില്ല — ന്യായീകരണ കുറിപ്പ് + tracking issue സഹിതം
     value കൈകൊണ്ട് തിരുത്തുക, `direction:down`).
   - **Trivy:** ന്യായീകരണ comment + tracking issue സഹിതം `.trivyignore`-ൽ ഒരു entry
     ചേർക്കുക (ഓരോ വരിയിലും CVE-ID). patch ഇല്ലാത്ത CVE-കളെ `ignore-unfixed: true`
     ഇതിനകം സ്വയമേവ കൈകാര്യം ചെയ്യുന്നു.

ടൂൾ ഇല്ലാതിരിക്കുമ്പോഴോ measurement പരാജയപ്പെടുമ്പോഴോ രണ്ട് ഗേറ്റുകളും **സുരക്ഷിതമായി SKIP**
ചെയ്യുന്നു (exit 0) (osv-scanner PATH-ൽ ഇല്ല, osv.dev/network ലഭ്യമല്ല, അസാധുവായ JSON) —
ഒരു **measurement** പരാജയം ഒരിക്കലും തടയില്ല; **അളക്കപ്പെട്ട** regression മാത്രമേ തടയൂ.

## Backlog: Scorecard advisory → blocking

Scorecard reporting സഹിതമുള്ള ആദ്യത്തെ വിജയകരമായ release-ന് ശേഷം:

- Scorecard: score ratchet (അളന്ന score സ്ഥിരപ്പെടുത്തുന്നു; അത് കുറയാൻ പാടില്ല).

Phase 7 ഗേറ്റുകളെ (osv-scanner, gitleaks, actionlint+zizmor) ഇത് പൂരകമാക്കുന്നു: zizmor
workflow-കളെത്തന്നെ audit ചെയ്യുന്നു; Scorecard repo-യുടെ മൊത്തത്തിലുള്ള posture അളക്കുന്നു.
