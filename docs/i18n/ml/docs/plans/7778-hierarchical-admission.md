1. നിലവിലുള്ള single-key semaphore കരാറും പുതിയ atomic multi-key കരാറും കേന്ദ്രീകൃത ടെസ്റ്റുകൾ ഉപയോഗിച്ച് ഉറപ്പിക്കുക: ഭാഗികമായ reservations ഇല്ലാതിരിക്കുക, FIFO queueing, abort, timeout, queue-full, idempotent release, stats, cleanup എന്നിവ ഉൾപ്പെടുത്തുക.
2. നിലവിലുള്ള account semaphore-നെ അതേ സ്ഥാനത്ത് പൊതുവൽക്കരിക്കുക. `acquire()`-നെ `acquireMany()`-നെ പൊതിയുന്ന compatibility wrapper ആയി നിലനിർത്തുക; രണ്ടാമത്തെ scheduler-ഓ dependency-ഓ ചേർക്കരുത്.
3. `chatCore`-ലെ account-only acquisition-ന് പകരം, `withRateLimit`-ന് തൊട്ടുമുമ്പായി ഒരു cumulative global/provider/account acquisition ഉപയോഗിക്കുക. account rotation മൂലം connection മാറുമ്പോഴെല്ലാം മുഴുവൻ set-ഉം വീണ്ടും acquire ചെയ്യുക; streaming പൂർത്തിയാകുന്നതുവരെ release നിലനിർത്തുക.
4. നിലവിലുള്ള resilience settings pipeline-നെ (types, defaults, normalization, schema, API response, UI, translations) global, provider caps ഉൾപ്പെടുത്തി വിപുലീകരിക്കുക. പഴയ Bottleneck concurrency control-ന്റെ യഥാർത്ഥ scope വ്യക്തമാക്കുന്നതിനായി അതിനെ connection/quota-scope concurrency എന്ന് പുനർനാമകരണം ചെയ്യുക.
5. കേന്ദ്രീകൃത ടെസ്റ്റുകൾ, lint, typecheck, static checks, പൂർണ്ണ test suite എന്നിവ പ്രവർത്തിപ്പിക്കുക; behavioral change changelog-ൽ രേഖപ്പെടുത്തുക.

മനഃപൂർവം മാറ്റമില്ലാതെ നിലനിർത്തുന്ന പെരുമാറ്റം: zero/null concurrency ഒരു gate-നെ bypass ചെയ്യുന്നു, account-only callers `acquire()` ഉപയോഗിക്കുന്നത് തുടരുന്നു, blocked-account controls അവയുടെ key format-ഉം API-യും നിലനിർത്തുന്നു, provider rate-limit queue-ന്റെ പെരുമാറ്റം മാറ്റമില്ലാതെ തുടരുന്നു.
