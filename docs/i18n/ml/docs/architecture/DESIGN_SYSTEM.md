> **നില:** റഫറൻസ് — ഇവിടെ വിവരിച്ചിരിക്കുന്ന സ്റ്റാൻഡേർഡൈസേഷൻ **നടപ്പിലാക്കിയിട്ടുണ്ട്** (ഘട്ടങ്ങൾ 1–6: ഗ്രിഡ് വാൾപേപ്പർ, പ്രിമിറ്റീവുകൾ, സ്റ്റാറ്റസ്-കളർ കേന്ദ്രീകരണം, മോണോ ടോക്കൺ, DataTable ടോക്കൺ മൈഗ്രേഷൻ, focus-ring → accent, Checkbox/Textarea പ്രിമിറ്റീവുകൾ, `cn()` → tailwind-merge, ഓരോ സ്വതന്ത്ര സ്ക്രീനിലും ഗ്രിഡ്, ഫ്ലൂയിഡ് 4K കണ്ടന്റ് ഷെൽ, അതാര്യമായ ഡാറ്റാ-ടേബിൾ സർഫേസുകൾ). ഡാഷ്ബോർഡിന്റെ ഡിസൈൻ ടോക്കണുകൾ, ഘടകങ്ങൾ, കൺവെൻഷനുകൾ എന്നിവയുടെ ആധികാരിക വിവരണമാണ് ഈ ഡോക്യുമെന്റ്; ഓരോ തീരുമാനത്തിന്റെയും യുക്തി വ്യക്തമാക്കുന്നതിനായി താഴെയുള്ള ഘട്ടാധിഷ്ഠിത ഘടന നിലനിർത്തിയിരിക്കുന്നു.
> **പരിധി:** OmniRoute ഡാഷ്ബോർഡും (`src/`) മാർക്കറ്റിംഗ് സൈറ്റും (`_mono_repo/omnirouteSite/`) **ഒരേ വിഷ്വൽ ഐഡന്റിറ്റി** പങ്കിടുന്നു — ഒരേ ഗ്രാഫ്-പേപ്പർ ഗ്രിഡ് പശ്ചാത്തലം (32px), ഒരേ കളർ ടോക്കണുകൾ, സ്റ്റാൻഡേർഡൈസ് ചെയ്ത ഘടകങ്ങൾ.
>
> പരിപാലകർക്കുള്ള പ്രായോഗിക കുറിപ്പുകൾ:
>
> - അവശേഷിക്കുന്ന ചില ഹാർഡ്കോഡ് ചെയ്ത hex മൂല്യങ്ങൾ **മനഃപൂർവമുള്ളവയാണ്** (എപ്പോഴും ഇരുണ്ട കൺസോൾ ടെർമിനൽ, ReactFlow SVG സ്ട്രോക്കുകൾ), അവ ടോക്കണുകളിലേക്ക് മാറ്റാൻ **പാടില്ല**.
> - പ്രവർത്തിക്കുന്ന ഒരു ഇൻസ്റ്റൻസിൽ കാണുന്ന "വലിയ" ഗ്രിഡ് പഴയ ബിൽഡിന്റെ ഫലമാണ്, കോഡിന്റേതല്ല — ഗ്രിഡ് വലുപ്പം 32px ആണ്, സൈറ്റിലേതിന് സമാനം.
> - ഡാർക്ക്-തീമിലെ `--table-*` മൂല്യങ്ങൾ മൈഗ്രേഷനുമുമ്പുള്ള ഹാർഡ്കോഡ് ചെയ്ത rgba മൂല്യങ്ങളുമായി ബൈറ്റ്-തലത്തിൽ സമാനമാണ്; ലൈറ്റ് തീം പരിഹരിച്ചിട്ടുണ്ട് (പ്രവർത്തനരഹിതമായ `var()` ഫാൾബാക്കുകൾ കാരണം അത് തെറ്റായി എല്ലായ്പ്പോഴും ഇരുണ്ടതായിരുന്നു).

## 1. ഉദ്ദേശ്യം

മാർക്കറ്റിംഗ് സൈറ്റും (`viral.omniroute.online`, `why.omniroute.online`, `omniroute.online`) ഉൽപ്പന്ന ഡാഷ്ബോർഡും **ഒരേ ഉൽപ്പന്നം** പോലെ കാണപ്പെടണം. സൈറ്റ് ഇതിനകം തന്നെ ഡാഷ്ബോർഡിൽനിന്ന് അതിന്റെ പാലറ്റ് സ്വീകരിച്ചിട്ടുണ്ട് — അതിന്റെ `css/tokens.css`-ൽ _"പാലറ്റ് OmniRoute ഡാഷ്ബോർഡിനെ പ്രതിഫലിപ്പിക്കുന്നു (src/app/globals.css)"_ എന്നു പോലും പറയുന്നു. അതിനാൽ കളർ തലത്തിൽ ഇവ രണ്ടും ഇതിനകം ~80% ഏകീകരിച്ചിരിക്കുന്നു. ഡാഷ്ബോർഡിൽ ഇല്ലാത്തത്:

1. ഓരോ പേജിലും സൈറ്റ് ഉപയോഗിക്കുന്ന **ഗ്രാഫ്-പേപ്പർ ഗ്രിഡ് വാൾപേപ്പർ**.
2. സൈറ്റിലുള്ളതും ഡാഷ്ബോർഡിൽ ഇല്ലാത്തതുമായ ഏതാനും **പങ്കിട്ട ഡിസൈൻ ടോക്കണുകൾ** (റേഡിയസ് സ്കെയിൽ, ബ്രാൻഡ് ഗ്രേഡിയന്റ്, `surface-2`, മോണോ ഫോണ്ട്).
3. **ഘടകതലത്തിലുള്ള സ്ഥിരത** — നിരവധി ഡാഷ്ബോർഡ് ഘടകങ്ങൾ ഹാർഡ്കോഡ് ചെയ്ത hex/rgba ഉപയോഗിച്ച് തീം ടോക്കണുകളെ മറികടക്കുന്നു.

ഈ ഡോക്യുമെന്റ് വിശകലനവും പദ്ധതിയുമാണ്.

## 2. തത്വങ്ങൾ

- **സത്യത്തിന്റെ ഏക ഉറവിടം = `src/app/globals.css`.** സൈറ്റ് ഡാഷ്ബോർഡിനെ പ്രതിഫലിപ്പിക്കുന്നു; ഒരിക്കലും മറിച്ചല്ല. പുതിയ ടോക്കണുകൾ ആദ്യം `globals.css`-ലാണ് ചേർക്കേണ്ടത്.
- **ലിറ്ററലുകളല്ല, ടോക്കണുകൾ.** ഘടകങ്ങൾ അസംസ്കൃത `#hex` മൂല്യങ്ങൾക്ക് പകരം സെമാന്റിക് ടോക്കണുകൾ (`bg-surface`, `text-primary`, `border-border`) ഉപയോഗിക്കണം.
- **സൂക്ഷ്മമായിരിക്കണം, പ്രകടമായിരിക്കരുത്.** ഉള്ളടക്കത്തിന് പിന്നിൽ നിലകൊള്ളുന്ന മങ്ങിയ വാൾപേപ്പറാണ് ഗ്രിഡ് — അത് ഒരിക്കലും ടെക്സ്റ്റ് കോൺട്രാസ്റ്റ് കുറയ്ക്കുകയോ UI-യുമായി മത്സരിക്കുകയോ ചെയ്യരുത്.
- **തീമിനനുസൃതം.** എല്ലാം `.dark`-ലും (ഉൽപ്പന്നത്തിന്റെ സവിശേഷ രൂപം) ലൈറ്റ് തീമിലും പ്രവർത്തിക്കണം.
- **കൃത്യമായ ഘട്ടംഘട്ടമായ വിന്യാസം.** ആദ്യം ഗ്രിഡും ടോക്കണുകളും പുറത്തിറക്കുക (കുറഞ്ഞ അപകടസാധ്യത, ഉയർന്ന ദൃശ്യപ്രഭാവം), തുടർന്ന് ഘടക ശുചീകരണങ്ങൾ ഘട്ടങ്ങളായി നടപ്പിലാക്കുക.

### 3.3 തീമിംഗ് പ്രവർത്തനരീതി (ഒന്നും തകരാതിരിക്കാൻ)

- **Tailwind v4, CSS-first** (`tailwind.config.*` ഇല്ല). ടോക്കണുകൾ `:root`/`.dark`-ൽ നിർവചിക്കുകയും `@theme inline` വഴി യൂട്ടിലിറ്റികൾക്ക് ലഭ്യമാക്കുകയും ചെയ്യുന്നു (`globals.css:130-179`).
- **`<html>`-ലെ `.dark` ക്ലാസ് വഴിയുള്ള ഡാർക്ക് മോഡ്** (`globals.css:22`-ൽ `@custom-variant dark`), ഒരു കസ്റ്റം Zustand സ്റ്റോർ (`src/store/themeStore.ts`) വഴി ടോഗിൾ ചെയ്യുന്നു; ഡിഫോൾട്ട് തീം = `system` (`src/shared/constants/appConfig.ts:11`). പകരം സൈറ്റ് `html[data-theme="light"]` ഉപയോഗിക്കുന്നു — **പ്രവർത്തനരീതികൾ വ്യത്യസ്തമാണെങ്കിലും അവ ഒരിക്കലും കൂട്ടിമുട്ടുന്നില്ല** (വ്യത്യസ്ത ഒറിജിനുകൾ), അതിനാൽ വൈരുദ്ധ്യമില്ല. ഡാഷ്ബോർഡിന്റെ `.dark` പ്രവർത്തനരീതി ഞങ്ങൾ നിലനിർത്തുന്നു.
- **റൺടൈം പ്രൈമറി ഓവർറൈഡ്** നിലവിലുണ്ട് (`themeStore.ts:85-97`, `COLOR_THEMES`-ലെ പ്രീസെറ്റുകൾ) — ഉപയോക്താക്കൾക്ക് `--color-primary` മാറ്റാനാകും. `--color-primary`-യെ റഫറൻസ് ചെയ്യുന്ന ഏത് പുതിയ ടോക്കണും (ഗ്രേഡിയന്റ് മുതലായവ) ആ ഓവർറൈഡുകൾ അധിക പ്രവർത്തനമില്ലാതെ പാരമ്പര്യമായി സ്വീകരിക്കും. ✅
- **Tailwind v4-ലെ റിസർവ് ചെയ്ത റേഡിയസ് പേരുകൾ:** `--radius-sm/md/lg/...` ആണ് `rounded-*` യൂട്ടിലിറ്റികളുടെ അടിസ്ഥാനമാകുന്നത്. അവ പുനർനിർവചിക്കുന്നത് നിലവിലുള്ള എല്ലാ `rounded-*`-കളെയും മുൻകാലപ്രാബല്യത്തോടെ മാറ്റും (ഉദാ. `rounded-sm` 12 ഫയലുകളിൽ ഉപയോഗിക്കുന്നു). അതിനാൽ ചെറിയ റേഡിയസ് മൂല്യവും ഘടകങ്ങളുടെ പുനഃസൂചനയും, ഉപയോഗിക്കുന്നവയും ഒരുമിച്ച് മാറുന്ന ഘട്ടം 2-ലേക്ക് മനഃപൂർവം മാറ്റിവെച്ചിരിക്കുന്നു.

## 4. ഭാഗം A — ഗ്രാഫ്-പേപ്പർ ഗ്രിഡ് പശ്ചാത്തലം (പ്രധാന ആവശ്യം) — നടപ്പിലാക്കി (ഘട്ടം 1)

### 4.1 ഇത് എന്താണ്

സൈറ്റിൽ നിന്നുള്ള കൃത്യമായ രീതി (`_mono_repo/omnirouteSite/css/base.css`): രണ്ട് 1px ലൈൻ ഗ്രേഡിയന്റുകൾ വരയ്ക്കുന്ന, എല്ലാ ഉള്ളടക്കത്തിനും പിന്നിൽ `z-index:-1`-ൽ സ്ഥിതിചെയ്യുന്ന ഒരു **സ്ഥിരമായ, പൂർണ്ണ-വ്യൂപോർട്ട് സ്യൂഡോ-എലമെന്റ്**.

```css
body::before {
  content: "";
  position: fixed;
  inset: 0;
  z-index: -1;
  pointer-events: none;
  background-image:
    linear-gradient(to right, var(--grid-line) 1px, transparent 1px),
    linear-gradient(to bottom, var(--grid-line) 1px, transparent 1px);
  background-size: var(--grid-size) var(--grid-size);
}
```

**`body`-ക്ക് അതാര്യമായ `background-color` ഉണ്ടെങ്കിലും ഇത് പ്രവർത്തിക്കുന്നത് എന്തുകൊണ്ട്:** `z-index:-1` ഉള്ള ഒരു `::before`, എലമെന്റിന്റെ സ്വന്തം പശ്ചാത്തലത്തിന് _മുകളിൽ_, എന്നാൽ അതിന്റെ ഇൻ-ഫ്ലോ ഉള്ളടക്കത്തിന് _താഴെ_ വരയ്ക്കപ്പെടുന്നു. അതിനാൽ `--color-bg` അടിസ്ഥാന നിറപ്പൂരിപ്പാണ്, ഗ്രിഡ് അതിന് മുകളിൽ ലെയർ ചെയ്യപ്പെടുന്നു, ആപ്പ് ഗ്രിഡിന് മുകളിൽ റെൻഡർ ചെയ്യപ്പെടുന്നു.

### 4.2 കോഡ്ബേസിൽ ഇതിനകം നിലവിലുള്ള മാതൃക

`src/app/landing/page.tsx:16-26` **ഇതിനകം ഇതേ ഗ്രിഡ് ഓരോ പേജിലും നടപ്പിലാക്കുന്നു** — എന്നാൽ **ചുവപ്പ്** ലൈനുകളോടെ (`#E54D5E`, അതാര്യത `0.06`), **50px**-ൽ, കൂടാതെ ആനിമേറ്റഡ് ഓർബുകളും. അതിനാൽ ഈ പാറ്റേൺ ഉൽപ്പന്നത്തിൽ തെളിയിക്കപ്പെട്ടതാണ്; ഈ പ്രവർത്തനം അതിനെ **ആഗോളവും തീം-അവബോധമുള്ളതുമായ** വാൾപേപ്പറായി ഉയർത്തുന്നു.

`landing/page.tsx` അതിന്റെ കൂടുതൽ സമ്പന്നമായ ആനിമേറ്റഡ് പശ്ചാത്തലം (ഓർബുകൾ + വിഗ്നെറ്റ്) നിലനിർത്തുന്നു — അതിന്റെ സ്വന്തം മാർക്കറ്റിംഗ് സ്പ്ലാഷ് (തീരുമാനം D5 = മാറ്റമില്ലാതെ നിലനിർത്തുക).

## 7. റോൾഔട്ട് പ്ലാൻ

- **ഘട്ടം 1 — ഗ്രിഡ് + ഐഡന്റിറ്റി ടോക്കണുകൾ (ഈ PR).** `globals.css` ഗ്രിഡ് + `--surface-2`/`--grad-brand`/`--radius` ടോക്കണുകൾ; `body::before` വാൾപേപ്പർ; `bg-bg` ബ്ലോക്കർ നീക്കംചെയ്യുക; സ്റ്റാറ്റിക് ഗാർഡ് ടെസ്റ്റ്. കുറഞ്ഞ അപകടസാധ്യത, ഒരൊറ്റ കമ്മിറ്റിൽ പഴയപടിയാക്കാനാകും.
- **ഘട്ടം 2 — പ്രിമിറ്റീവുകൾ (C1, C2, C5) — ഈ PR-ൽ പൂർത്തിയായി.** സെമാന്റിക് റേഡിയസ് യൂട്ടിലിറ്റികളായ `rounded-card` (14px) / `rounded-control` (9px) എന്നിവ `@theme` വഴി ചേർത്തു (ഇഷ്ടാനുസൃത പേരുകളായതിനാൽ ഡിഫോൾട്ട് `rounded-sm/md/lg/xl` മാറ്റമില്ലാതെ തുടരും — 400 ഫയലുകളിലേക്കുള്ള വ്യാപകമായ മാറ്റമില്ല); Card/Modal → 14px, Button/Input/Select → 9px; Button primary → `--grad-brand` (ചുവപ്പ്→വയലറ്റ്) + പുതിയ `accent` വേരിയന്റ്; Card ബോർഡറുകൾ → `border-border` ടോക്കൺ (0.08). **മാറ്റിവെച്ചത്:** `cn()`→tailwind-merge (C9)-ന് പുതിയ ഡിപെൻഡൻസികൾ ആവശ്യമാണ്; ഉപരിതലത്തിന്റെ ഭൂരിഭാഗവും പ്രിമിറ്റീവുകൾ കൈകാര്യം ചെയ്യുന്നതിനാൽ താൽക്കാലികമായി ചേർത്ത `rounded-lg`-കളുടെ സമഗ്ര മാറ്റം (326 ഫയലുകൾ) അതേപടി വിട്ടിരിക്കുന്നു.
- **ഘട്ടം 3 — സ്റ്റാറ്റസ് നിറങ്ങൾ + പട്ടികകൾ (C3, C4) — ഈ PR-ൽ പൂർത്തിയായി.** ✅ **C4** (`src/shared/constants/statusColors.ts` — `STATUS_HEX` ഏക ഉറവിടം; `flow/edgeStyles.ts` + `TokenHealthBadge` ഇതിലേക്ക് തിരിച്ചുവിട്ടു, കൃത്യമായി അതേ hex). ✅ **`--font-mono`** ടോക്കൺ. ✅ **C3 (DataTable)** — എല്ലാ ഇൻലൈൻ rgba-കളും പ്രവർത്തനരഹിതമായ `var(--bg-table-header)` / `var(--text-secondary)` ഫാൾബാക്കുകളും `--table-*` ടോക്കൺ സെറ്റ് (`--table-header-bg/-row-zebra/-row-hover/-cell-border/-row-selected`) ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിച്ചു; ഇതിന്റെ **ഡാർക്ക് മൂല്യങ്ങൾ പഴയ ഹാർഡ്കോഡ് ചെയ്ത rgba-യുമായി കൃത്യമായി തുല്യമാണ്** (ഡാർക്ക് ബൈറ്റ്-ഐഡന്റിക്കൽ), ലൈറ്റ് മൂല്യങ്ങൾ മുമ്പ് എല്ലായ്പ്പോഴും ഡാർക്കായിരുന്ന ലൈറ്റ് തീം ശരിയാക്കുന്നു. Header ബോർഡർ → `--color-border`, സെക്കൻഡറി ടെക്സ്റ്റ് → `--color-text-muted`. **മെർജ് ചെയ്യുന്നതിന് മുമ്പ് ഒരു വിഷ്വൽ പരിശോധന വേണം.** (സ്പർശിക്കാത്തവ: `logTableStyles.ts`, പഴയ Ant `.ant-table` നിയമങ്ങൾ — ഇവ വേറിട്ടതും കുറഞ്ഞ മുൻഗണനയുള്ളതുമാണ്.)
- **ഘട്ടം 4 — ക്ലീനപ്പ് (C6, C7, C9 പൂർത്തിയായി; C8 ബാക്കി).** ✅ **C9** `cn()` → `twMerge(clsx(...))` (clsx + tailwind-merge ഡിപെൻഡൻസികളായി ചേർത്തു) — ഒരു കോളറുടെ `className`, ഇനി ഒരു പ്രിമിറ്റീവിലെ വൈരുധ്യമുള്ള ക്ലാസുമായി അടുക്കുന്നതിന് പകരം അതിനെ ശരിയായി _മാറ്റിസ്ഥാപിക്കുന്നു_. ✅ **C7** പുതിയ `Checkbox` + `Textarea` പ്രിമിറ്റീവുകൾ (ടോക്കൺ അധിഷ്ഠിതം, ബാരലിൽ നിന്ന് എക്സ്പോർട്ട് ചെയ്തവ; അഡിറ്റീവ് — 32 റോ ചെക്ക്ബോക്സുകളും / 41 റോ ടെക്സ്റ്റ് ഏരിയകളും ക്രമാനുഗതമായി സ്വീകരിക്കാം). ✅ **C6** ഫോക്കസ്-റിങ് അനുരൂപീകരണം — ഗ്ലോബൽ `--focus-ring`-മായി പൊരുത്തപ്പെടാനും ചുവന്ന എറർ റിങ്ങുമായി കൂട്ടിയിടിക്കുന്നത് ഒഴിവാക്കാനും ഫോം കൺട്രോളുകൾ (`Input`/`Select`/`Textarea`/`Toggle`/`Checkbox`) ഇപ്പോൾ **accent (വയലറ്റ്)** റിങ്ങിൽ ഫോക്കസ് ചെയ്യുന്നു; ചുവന്ന എറർ സ്റ്റേറ്റിൽ മാറ്റമില്ല. ⏳ **C8 hex-sweep ഒരു അന്ധമായ find/replace അല്ല** — _മനഃപൂർവമുള്ളതും_ അതേപടി തുടരേണ്ടതുമായ സ്ഥിരീകരിച്ച ഘടകങ്ങൾ: `ConsoleLogViewer.tsx:240` (എല്ലായ്പ്പോഴും ഡാർക്കായ ടെർമിനൽ), `TokenHealthBadge` പോപ്പോവർ, ReactFlow SVG സ്ട്രോക്കുകൾ. യഥാർത്ഥത്തിൽ തീം അനുസരിച്ച് മാറേണ്ട hex മാത്രം മൈഗ്രേറ്റ് ചെയ്യുക.

## 8. തീരുമാനിക്കാനുള്ള കാര്യങ്ങൾ (ശുപാർശകൾ)

- **D1 — Button primary:** ചുവപ്പ്→ചുവപ്പ് നിലനിർത്തണോ, അതോ **ചുവപ്പ്→വയലറ്റ് `--grad-brand`**-ലേക്ക് മാറണോ? ശുപാർശ: **ചുവപ്പ്→വയലറ്റ്** (ഘട്ടം 2).

- **D3 — ക്രോം വൈബ്രൻസി:** sidebar/header **സോളിഡ്** — തിരഞ്ഞെടുത്തു.

- **D6 — ഉൽപ്പന്നമൊട്ടാകെ Radius 14/9:** ശുപാർശ: അതെ (ഘട്ടം 2).
- **D7 — ഘട്ടം 1 ആദ്യം ഷിപ്പ് ചെയ്യുക:** തിരഞ്ഞെടുത്തു.
- **D8 — ലേഔട്ട് വീതി (ഘട്ടം 5):** ഡാഷ്ബോർഡ് കണ്ടന്റ് ഷെൽ `max-w-7xl` (1280px)-ൽ പരിമിതപ്പെടുത്തിയിരുന്നതിനാൽ വലിയ മോണിറ്ററുകളിൽ ഇരുവശത്തും വീതിയേറിയ ഒഴിഞ്ഞ ഗട്ടറുകളോടെ മധ്യഭാഗത്തായി നിന്നിരുന്നു. ✅ **പൂർത്തിയായി** — ഫ്ലൂയിഡ് `max-w-[3840px]` (യഥാർത്ഥ 4K) ആയി ഉയർത്തി: ഇപ്പോൾ കണ്ടന്റ് ~4K വരെ വ്യൂപോർട്ടിനെ പിന്തുടരുകയും അതിന് അപ്പുറം മാത്രമേ മധ്യഭാഗത്താക്കപ്പെടുകയുള്ളൂ (`DashboardLayout.tsx`). മനഃപൂർവം വീതി കുറച്ച പേജുകൾ ഡിസൈൻപ്രകാരം വീതി കുറഞ്ഞതായി തന്നെ തുടരും (`ProviderOnboardingWizard` max-w-5xl, `Rtk`/`CavemanContextPageClient` max-w-6xl).
- **D9 — Opaque ഡാറ്റാ പട്ടികകൾ (ഘട്ടം 6):** ഡാഷ്ബോർഡ് കണ്ടന്റ് ഏരിയ ഇപ്പോൾ ട്രാൻസ്പാരന്റായതിനാൽ (ഗ്രിഡ് വാൾപേപ്പർ അതിലൂടെ കാണാൻ, ഘട്ടം 5), opaque surface അല്ലാത്ത കണ്ടെയ്നറുകളിലെ ഡാറ്റാ പട്ടികകളുടെ ട്രാൻസ്പാരന്റ് ഇരട്ട വരികളിലൂടെയും / കുറഞ്ഞ-ആൽഫ സീബ്രയിലൂടെയും ഗ്രിഡ് പുറത്തുകാണുന്നുണ്ടായിരുന്നു. ✅ **പൂർത്തിയായി** — Card ഇല്ലാത്ത എല്ലാ പട്ടികകളും ഇപ്പോൾ `bg-surface` പെയിന്റ് ചെയ്യുന്നു (അല്ലെങ്കിൽ `<DataTable>` പ്രിമിറ്റീവിന്റെ കാര്യത്തിൽ, അതിന്റെ സ്ക്രോൾ കണ്ടെയ്നറിൽ `background: var(--color-surface)`). പരിഹരിച്ചവ: `DataTable` (പ്രിമിറ്റീവ്), `ProxyLogger`/`RequestLoggerV2` (അവയുടെ `<Card>`-ലെ `bg-black/5 dark:bg-black/20` ടിന്റ് tailwind-merge വഴി Card-ന്റെ `bg-surface`-നെ മറികടക്കുകയായിരുന്നു → ~95% ട്രാൻസ്പാരന്റ്), `BatchListTab`/`FilesListTab`/`CacheEntriesTab`/`ReasoningCacheTab`/`cache page`/`FreePoolTab`/`ModelMappingTable`/`HeaderTable`, കൂടാതെ cache വ്യൂകളിലെ രണ്ട് CSS-grid "പട്ടികകൾ" (`bg-surface/35` → `bg-surface`). ഇതിനകം ഒരു `<Card>`/Modal-നുള്ളിലുള്ള പട്ടികകൾ opaque ആണെന്ന് സ്ഥിരീകരിച്ച് മനഃപൂർവം മാറ്റമില്ലാതെ വിട്ടു (അവിടെ bg-surface ആവർത്തനപരവും ഫലമില്ലാത്തതുമാണ്). ഗ്രിഡിന് തന്നെ **ഒരു മാറ്റവും ആവശ്യമില്ലായിരുന്നു** — ഡാഷ്ബോർഡ് `body::before` സൈറ്റിലേതുമായി ബൈറ്റ്-ഐഡന്റിക്കൽ ആണ് (`--grid-size: 32px`); പ്രവർത്തിക്കുന്ന ഒരു ഇൻസ്റ്റൻസിൽ കാണുന്ന ഏതെങ്കിലും "വലിയ ഗ്രിഡ്", കോഡിന്റെ ഫലമല്ല, പഴയ pre-`#4143` ബിൽഡ് ശേഷിച്ചിരിക്കുന്നതാണ്. `tests/unit/design-grid-background.test.ts` ഉപയോഗിച്ച് ഗാർഡ് ചെയ്തിരിക്കുന്നു (ഘട്ടം 6 ബ്ലോക്ക്).

## 9. പരിധിക്ക് പുറത്തുള്ളവ / അപകടസാധ്യതകൾ

- **വർണ്ണപ്പട്ടികയിൽ മാറ്റമില്ല** — നിറങ്ങൾ ഇതിനകം പൊരുത്തപ്പെടുന്നു; നഷ്ടമായ ടോക്കണുകൾ മാത്രമാണ് ചേർക്കുന്നത്. ഉൽപ്പന്നത്തിന്റെ നിറങ്ങൾ മാറാനുള്ള അപകടസാധ്യത ശൂന്യമാണ്.
- **തീം എഞ്ചിനിൽ മാറ്റമില്ല** — `.dark` + Zustand സ്റ്റോർ നിലനിർത്തുക.
- **റേഡിയസ് മാറ്റം (ഘട്ടം 2) വ്യാപകമാണ്** — എല്ലാ കാർഡ്/ബട്ടൺ/ഇൻപുട്ടുകളെയും ബാധിക്കുന്നു; ലയിപ്പിക്കുന്നതിന് മുമ്പ് തിരക്കേറിയ സ്ക്രീനുകൾ (പട്ടികകൾ, മോഡലുകൾ) ദൃശ്യപരമായി പരിശോധിക്കുക.
- **പട്ടികകളിൽ (C3)** ഏറ്റവും കൂടുതൽ ഹാർഡ്കോഡ് ചെയ്ത സ്റ്റൈലിംഗും ഏറ്റവും ഉയർന്ന റിഗ്രഷൻ സാധ്യതയുമുണ്ട് — അവയെ പ്രത്യേക PR-ൽ വേർതിരിക്കുക.
