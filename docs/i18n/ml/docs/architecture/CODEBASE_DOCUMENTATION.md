### 3.1 `src/app/` — App Router

App Router ഡാഷ്ബോർഡ് UI-യും പൊതു/മാനേജ്മെന്റ് HTTP API-യും ലഭ്യമാക്കുന്നു.
**ഗ്ലോബൽ മിഡിൽവെയർ ഇല്ല** — ഓരോ റൂട്ടിലും പ്രത്യേകം ഇന്റർസെപ്ഷൻ നടത്തുന്നു.

`src/app/` എന്നതിന് കീഴിലുള്ള ഉന്നത-തല സെഗ്മെന്റുകൾ:

| പാത                                                                           | ഉദ്ദേശ്യം                                           |
| ----------------------------------------------------------------------------- | --------------------------------------------------- |
| `api/`                                                                        | എല്ലാ HTTP API റൂട്ടുകളും (താഴെയുള്ള വിഭജനം കാണുക)  |
| `a2a/`                                                                        | A2A JSON-RPC 2.0 എൻഡ്പോയിന്റ് (`POST /a2a`)         |
| `.well-known/agent.json/`                                                     | A2A Agent Card കണ്ടെത്തൽ ഡോക്യുമെന്റ്               |
| `(dashboard)/`                                                                | ഡാഷ്ബോർഡ് UI (റൂട്ട് ഗ്രൂപ്പ്, URL പ്രിഫിക്സ് ഇല്ല) |
| `auth/`, `login/`, `forgot-password/`, `callback/`                            | ഓതന്റിക്കേഷൻ ഫ്ലോകൾ                                 |
| `landing/`                                                                    | മാർക്കറ്റിംഗ്/ലാൻഡിംഗ് പേജ്                         |
| `docs/`                                                                       | എംബെഡ് ചെയ്ത API ഡോക്സ് വ്യൂവർ                      |
| `status/`, `maintenance/`, `offline/`                                         | പ്രവർത്തനസംബന്ധിയായ പേജുകൾ                          |
| `privacy/`, `terms/`                                                          | നിയമപരമായ പേജുകൾ                                    |
| `400/`, `401/`, `403/`, `408/`, `429/`, `500/`, `502/`, `503/`                | സ്റ്റാറ്റിക് പിശക് പേജുകൾ                           |
| `error.tsx`, `global-error.tsx`, `not-found.tsx`, `forbidden/`, `loading.tsx` | ഫ്രെയിംവർക്ക് പിശക്/ലോഡിംഗ് അതിരുകൾ                 |
| `layout.tsx`, `page.tsx`, `globals.css`, `manifest.ts`                        | റൂട്ട് ഷെൽ                                          |

#### 3.1.2a `src/app/api/services/` — എംബെഡ് ചെയ്ത സർവീസുകളുടെ മാനേജ്മെന്റ്

     കാഷെ പരിശോധന (സെമാന്റിക് + റീഡ് കാഷെ)
     നിരക്ക് പരിധി (rateLimitManager, accountSemaphore)
     കോംബോ റൂട്ടിങ് (മോഡൽ ഒരു കോംബോയിലേക്ക് പരിഹരിക്കപ്പെടുന്നുവെങ്കിൽ)
       comboResolver → ഓരോ ലക്ഷ്യത്തിനും ലൂപ്പ് → handleSingleModel()
     translateRequest()  (open-sse/translator/request/*)
     getExecutor(providerId).execute()  (open-sse/executors/*)
       അപ്സ്ട്രീമിൽനിന്ന് ഫെച്ച് ചെയ്യുക → accountFallback വഴി വീണ്ടും ശ്രമിക്കൽ/ബാക്ക്ഓഫ്
     translateResponse() (open-sse/translator/response/*)
     SSE സ്ട്രീം അല്ലെങ്കിൽ JSON പ്രതികരണം
     Responses API ആണെങ്കിൽ: open-sse/transformer/responsesTransformer.ts വഴിയുള്ള TransformStream
  → കംപ്ലയൻസ് ഓഡിറ്റ് (src/lib/compliance/)
  → ക്ലയന്റിലേക്കുള്ള പ്രതികരണം

## 10. എങ്ങനെ സംഭാവന ചെയ്യാം

### ഒരു പുതിയ പ്രൊവൈഡർ ചേർക്കുക

1. `src/shared/constants/providers.ts`-ൽ രജിസ്റ്റർ ചെയ്യുക (ലോഡ് ചെയ്യുമ്പോൾ Zod ഉപയോഗിച്ച് സാധൂകരിക്കുന്നു).

   (`BaseExecutor` വിപുലീകരിക്കുക).
3. അത് OpenAI ഫോർമാറ്റ് ഉപയോഗിക്കുന്നില്ലെങ്കിൽ `open-sse/translator/`-ൽ ഒരു ട്രാൻസ്ലേറ്റർ ചേർക്കുക.
4. OAuth അടിസ്ഥാനമാക്കിയുള്ളതാണെങ്കിൽ, `src/lib/oauth/providers/`-നും
   `src/lib/oauth/services/`-നും കീഴിൽ കോൺഫിഗറേഷൻ ചേർക്കുക.
5. `open-sse/config/providerRegistry.ts`-ൽ (അല്ലെങ്കിൽ `open-sse/config/`-ന് കീഴിലുള്ള
   ഫോർമാറ്റ്-നിർദ്ദിഷ്ട രജിസ്ട്രിയിൽ) മോഡലുകൾ രജിസ്റ്റർ ചെയ്യുക.
6. `tests/unit/`-ന് കീഴിൽ ടെസ്റ്റുകൾ എഴുതുക.

### ഒരു പുതിയ API റൂട്ട് ചേർക്കുക

1. `src/app/api/your-route/route.ts` സൃഷ്ടിക്കുക.

3. പുതിയ അഭ്യർത്ഥനാ ഘടനയാണെങ്കിൽ: `src/shared/validation/schemas.ts`-ൽ Zod സ്കീമ ചേർക്കുക.

6. `docs/reference/API_REFERENCE.md`-ഉം `docs/openapi.yaml`-ഉം പുതുക്കുക.

## 11. കൺവെൻഷനുകൾ

- **കോഡ് ശൈലി**: 2-സ്പേസ് ഇൻഡന്റ്, ഡബിൾ ക്വോട്ടുകൾ, 100 പ്രതീക വീതി, സെമിക്കോളനുകൾ,
  `es5` ട്രെയിലിംഗ് കോമകൾ — `lint-staged` മുഖേന Prettier ഇത് നിർബന്ധമാക്കുന്നു.
- **ഇംപോർട്ടുകൾ**: എക്സ്റ്റേണൽ → ഇന്റേണൽ (`@/`, `@omniroute/open-sse`) → റിലേറ്റീവ്.
- **നാമകരണം**: ഫയലുകൾ `camelCase` അല്ലെങ്കിൽ `kebab-case`, ഘടകങ്ങൾ `PascalCase`,
  കോൺസ്റ്റന്റുകൾ `UPPER_SNAKE`.
- **ESLint**: എല്ലായിടത്തും `no-eval`, `no-implied-eval`, `no-new-func` = `error`;
  `open-sse/`-ലും `tests/`-ലും `no-explicit-any` = `warn`, മറ്റിടങ്ങളിൽ `error`.
- **TypeScript**: `strict: false` (ലെഗസി നിലപാട്). മൊഡ്യൂളുകൾക്കിടയിലെ അതിരുകളിൽ
  ഇൻഫറൻസിനേക്കാൾ വ്യക്തമായ ടൈപ്പുകൾക്ക് മുൻഗണന നൽകുക.
- **ഡാറ്റാബേസ്**: റൂട്ടുകളിലോ ഹാൻഡ്ലറുകളിലോ ഒരിക്കലും റോ SQL എഴുതരുത് — എല്ലായ്പ്പോഴും
  `src/lib/db/` മൊഡ്യൂളുകളിലൂടെ പ്രവർത്തിക്കുക. ഒരിക്കലും ബാരൽ-ഇംപോർട്ട് ചെയ്യരുത് — നിർദ്ദിഷ്ട `src/lib/db/*` മൊഡ്യൂളുകൾ നേരിട്ട് ഉപയോഗിക്കുക.
- **DB-എന്റിറ്റി ടൈപ്പിംഗ് (#3512)**: ഒരു DB പട്ടികയുടെ റോ ഘടന എഴുതുകയോ വായിക്കുകയോ
  ചെയ്യുന്ന ഫംഗ്ഷൻ, കോൾ സൈറ്റിൽ `any` അല്ലെങ്കിൽ ഇൻലൈൻ അനോനിമസ് ടൈപ്പ് ഉപയോഗിക്കുന്നതിന് പകരം,
  ആ പട്ടികയുടെ കോളങ്ങളെ 1:1 ആയി പ്രതിഫലിപ്പിക്കുന്ന പേരുള്ള TS ഇന്റർഫേസ് സ്വീകരിക്കുകയോ മടക്കിനൽകുകയോ വേണം. ഇന്റർഫേസ്
  ഫംഗ്ഷനോടടുത്ത് സ്ഥാപിക്കുക (ഉദാ. `saveRequestUsage`-ന് മുകളിലുള്ള
  `src/lib/usage/usageHistory.ts`-ലെ `export interface UsageEntry`), വ്യത്യസ്ത റൈറ്ററുകൾ റോ
  ക്രമേണ പൂരിപ്പിക്കുമ്പോൾ ഓരോ ഫീൽഡും ഓപ്ഷണൽ/നല്ലബിൾ ആയി നിലനിർത്തുക,
  കോൾ ചെയ്യുന്നവർക്കനുസരിച്ച് ഘടന മാറുന്ന ഫീൽഡിനായി `any`-നേക്കാൾ `unknown`-ന് മുൻഗണന നൽകുക
  (ഫീൽഡിൽ ഇത് രേഖപ്പെടുത്തുക, ഉദാ. `UsageEntry.tokens`
  റോ പ്രൊവൈഡർ-ഘടനയിലുള്ള ഉപയോഗവും നോർമലൈസ് ചെയ്ത ഘടനയും സ്വീകരിക്കുന്നു). ഈ രീതിയിൽ ഒരു
  ഫയലിലെ `any` എണ്ണം പൂജ്യത്തിലെത്തിയാൽ, റിഗ്രഷൻ ഉണ്ടാകാതിരിക്കാൻ അതിനെ
  `check:any-budget:t11` അലൗലിസ്റ്റിൽ (`scripts/check/check-t11-any-budget.mjs`,
  `maxAny: 0`) ചേർക്കുക. ഇത് ആദ്യ ഘട്ടത്തിനുള്ള കൺവെൻഷനാണ് — വിശാലമായ "അനോനിമസ് `any` പാടില്ല"
  ക്ലീനപ്പ് ശേഷിക്കുന്ന കോഡ്ബേസിലുടനീളം ആവർത്തനാത്മകമായി നടപ്പാക്കുന്നതാണ്.
- **പിശകുകൾ**: നിർദ്ദിഷ്ട എറർ ടൈപ്പുകളോടൊപ്പം try/catch ഉപയോഗിക്കുക, pino കോൺടെക്സ്റ്റോടെ ലോഗ് ചെയ്യുക. SSE സ്ട്രീമുകളിലെ

2. ഒരിക്കലും barrel-import ചെയ്യരുത് — നിർദ്ദിഷ്ട `src/lib/db/*` മൊഡ്യൂളുകൾ നേരിട്ട് ഉപയോഗിക്കുക.
3. `eval()` / `new Function()` / പരോക്ഷ eval എന്നിവ ഒരിക്കലും ഉപയോഗിക്കരുത്.
4. `main`-ലേക്ക് ഒരിക്കലും നേരിട്ട് commit ചെയ്യരുത്.
5. routes-ൽ ഒരിക്കലും raw SQL എഴുതരുത് — എല്ലായ്പ്പോഴും `src/lib/db/` മൊഡ്യൂളുകളിലൂടെ മാത്രം ഉപയോഗിക്കുക.
6. SSE streams-ൽ പിശകുകൾ ഒരിക്കലും നിശ്ശബ്ദമായി അവഗണിക്കരുത്.
7. ഇൻപുട്ടുകൾ എല്ലായ്പ്പോഴും Zod schemas ഉപയോഗിച്ച് സാധൂകരിക്കുക.
8. production code മാറ്റുമ്പോൾ എല്ലായ്പ്പോഴും tests ഉൾപ്പെടുത്തുക.
9. Coverage ≥ 60% ആയി നിലനിർത്തണം (statements, lines, functions, branches).
