ഈ രേഖ [Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854)-നുള്ള നടപ്പാക്കൽ തീരുമാനം രേഖപ്പെടുത്തുന്നു. പൊതുവായി ലഭ്യമായ ഉൽപ്പന്നങ്ങളെ നാല് പ്രൊവൈഡർ കുടുംബങ്ങളായി പ്രതിനിധീകരിക്കുന്നു. റീജിയൻ എന്നത് കണക്ഷൻ ഡാറ്റയാണ്, പ്രത്യേക ഉൽപ്പന്നമല്ല.

## തീരുമാനം

| പ്രൊവൈഡർ കുടുംബം                                            | OmniRoute ID            | ഗ്ലോബൽ റീജിയൻ | ചൈന റീജിയൻ |
| ----------------------------------------------------------- | ----------------------- | ------------- | ---------- |
| Alibaba Cloud Model Studio (ഉപയോഗത്തിനനുസരിച്ച് പണമടയ്ക്കൽ) | `alibaba`               | സിംഗപ്പൂർ     | ബെയ്ജിങ്   |
| Alibaba Cloud Token Plan                                    | `bailian-coding-plan`   | സിംഗപ്പൂർ     | ബെയ്ജിങ്   |
| Qwen Cloud (ഉപയോഗത്തിനനുസരിച്ച് പണമടയ്ക്കൽ)                 | `qwen-cloud`            | ഗ്ലോബൽ        | ബെയ്ജിങ്   |
| Qwen Cloud Token Plan                                       | `qwen-cloud-token-plan` | സിംഗപ്പൂർ     | ബെയ്ജിങ്   |

നിലവിലുള്ള `alibaba-cn` ID, സേവ് ചെയ്ത കണക്ഷനുകൾ, മോഡൽ റൂട്ടുകൾ, കോംബോകൾ, ചരിത്രപരമായ ഉപയോഗം എന്നിവയ്ക്കായുള്ള റൺടൈം അനുയോജ്യതാ അപരനാമമായി തുടരും. അതിന്റെ ഡാഷ്ബോർഡ് കാർഡ് `alibaba`-ലേക്ക് സംയോജിപ്പിച്ചിരിക്കുന്നു; ഡാറ്റാബേസ് റീറൈറ്റ് ആവശ്യമില്ല.

Qwen Cloud-ന്റെ ഉപയോഗത്തിനനുസരിച്ച് പണമടയ്ക്കുന്ന ഉൽപ്പന്നവും Alibaba Cloud Model Studio-യും നിലവിൽ DashScope-അനുയോജ്യമായ റൺടൈം ഹോസ്റ്റുകൾ പങ്കിടുന്നു. എന്നാൽ ഉപയോക്താക്കൾ വ്യത്യസ്ത ഉൽപ്പന്ന ഇന്റർഫേസുകളിലൂടെയാണ് കീകൾ നേടുന്നതും അക്കൗണ്ടുകൾ കൈകാര്യം ചെയ്യുന്നതും എന്നതിനാൽ അവ പ്രത്യേക പ്രൊവൈഡർ ഐഡന്റിറ്റികളായി തുടരുന്നു. Alibaba, Qwen Cloud Token Plan ഉൽപ്പന്നങ്ങൾ വ്യത്യസ്ത എൻഡ്പോയിന്റ് കുടുംബങ്ങൾ ഉപയോഗിക്കുന്നതിനാൽ, നാല് ഉൽപ്പന്നങ്ങളും പ്രത്യേക പ്രൊവൈഡർ ID-കളായി തുടരുന്നു.

## കണക്ഷൻ കരാർ

പുതിയ കണക്ഷനുകൾ സ്ഥിരമായ റീജിയൻ കീ `providerSpecificData`-യിൽ സംഭരിക്കുന്നു:

```json
{
  "region": "global-sg"
}
```

അനുവദനീയമായ മൂല്യങ്ങൾ `global-sg`, `china-beijing` എന്നിവയാണ്. പ്രൊവൈഡർ ID, റീജിയൻ എന്നിവയിൽനിന്ന് എൻഡ്പോയിന്റ് കേന്ദ്രീകൃതമായി നിർണ്ണയിക്കുന്നു. മുൻനിശ്ചയിച്ചതല്ലാത്ത `providerSpecificData.baseUrl`, ഓപ്പറേറ്റർ വ്യക്തമായി നൽകിയ ഓവർറൈഡായി തുടർന്നും മുൻഗണന നേടുന്നു; അതേസമയം, പഴയതായി സേവ് ചെയ്ത മുൻനിശ്ചയിച്ച URL-കൾ റീജിയണൽ മാട്രിക്സിലേക്ക് വീണ്ടും നോർമലൈസ് ചെയ്യപ്പെടുന്നു.

ഇത് കണക്ഷൻ സ്കീമ വിപുലീകരിക്കാവുന്നതായി നിലനിർത്തുന്നു: മറ്റൊരു പ്രൊവൈഡർ കാർഡ് സൃഷ്ടിക്കാതെയും സേവ് ചെയ്ത പ്രൊവൈഡർ ID-കൾ മാറ്റാതെയും റിസോൾവറിലേക്ക് മറ്റൊരു റീജിയൻ ചേർക്കാനാകും.

## അനുയോജ്യതയും പുറത്തിറക്കലും

1. പ്രാദേശിക endpoint resolver ചേർക്കുകയും നിലവിലെ global defaults നിലനിർത്തുകയും ചെയ്യുക.
2. `alibaba`, അതിന്റെ `alibaba-cn` compatibility ID, കൂടാതെ `qwen-cloud` എന്നിവയ്ക്കായി തത്സമയ പ്രാദേശിക DashScope `/models` discovery ഉപയോഗിക്കുക. generic endpoint image, video, audio, embedding, മറ്റ് non-chat models എന്നിവയും മടക്കിനൽകുന്നതിനാൽ, അവയുടെ responses ആദ്യം ഒരു text-generation filter-ലൂടെ കടന്നുപോകുന്നു. തുടർന്ന് `qwen-cloud`, അതിന്റെ provider registry-യിൽ പ്രഖ്യാപിച്ചിട്ടുള്ള പരിപാലിത allowlist പ്രയോഗിക്കുന്നു. നിലവിൽ ഒരേ runtime hosts പങ്കിടുന്നുണ്ടെങ്കിലും Alibaba Model Studio-യും Qwen Cloud-ഉം വെവ്വേറെ curated catalogs നിലനിർത്തുന്നു.
3. നിലവിലെ Token Plan text-model allowlist ഉപയോഗിച്ച് `qwen-cloud-token-plan` രജിസ്റ്റർ ചെയ്യുക.
4. connection ചേർക്കുന്നതിനും തിരുത്തുന്നതിനുമുള്ള dialogs-ൽ typed region selector ചേർക്കുക.
5. duplicate ആയ `alibaba-cn` card മറയ്ക്കുകയും അതിന്റെ നിലവിലുള്ള connections `alibaba` provider page-ൽ ഉൾപ്പെടുത്തുകയും ചെയ്യുക.
6. വിപുലമായതും workspace-specific ആയതുമായ deployments-നായി custom endpoint overrides തുടർന്നും ലഭ്യമാക്കുക.

Token Plan media models സമർപ്പിത endpoints ഉപയോഗിക്കുന്നതിനാൽ അവ chat catalog-ന് പുറത്തുതന്നെ തുടരുന്നു.
`wan2.7-image`, `wan2.7-image-pro` എന്നിവ `open-sse/config/imageRegistry.ts`-ൽ രജിസ്റ്റർ ചെയ്തിരിക്കുന്നു;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v` എന്നിവ
`open-sse/config/videoRegistry.ts`-ൽ രജിസ്റ്റർ ചെയ്തിരിക്കുന്നു. രണ്ട് registries-ഉം `qwen-cloud-token-plan` connection
identity-യും അതിന്റെ region-specific credentials-ഉം വീണ്ടും ഉപയോഗിക്കുന്നു.

സാധാരണ Qwen Cloud-ന് `qwen-cloud` identity-യുടെ കീഴിൽ വെവ്വേറെ pay-as-you-go image, video catalogs ഉണ്ട്.
അതിന്റെ image models: `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03`, `z-image-turbo`. അതിന്റെ video
models: `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12`,
`wan2.7-videoedit`. ഈ models സാധാരണ `qwen-cloud` connection-ഉം പ്രാദേശിക
DashScope media endpoint-ഉം മാത്രം വീണ്ടും ഉപയോഗിക്കുന്നു. Token Plan, pay-as-you-go registries എന്നിവ പരസ്പരം
മറ്റൊന്നിന്റെ model lists പാരമ്പര്യമായി സ്വീകരിക്കുകയോ ലയിപ്പിക്കുകയോ ചെയ്യുന്നില്ല.

`bailian-coding-plan` identity-ക്കും അതിന്റേതായ media allowlists ഉണ്ട്:
image generation-നായി `wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0`, `qwen-image-2.0-pro`,
കൂടാതെ video generation-നായി
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`.
ഇത് Bailian Coding Plan connection-ഉം പ്രാദേശിക Coding Plan endpoint-ഉം മാത്രം ഉപയോഗിക്കുന്നു.
അതിന്റെ image, video registries ഏതെങ്കിലും Qwen Cloud provider-ൽ നിന്ന് പാരമ്പര്യമായി സ്വീകരിക്കുകയോ അവയുമായി ലയിക്കുകയോ ചെയ്യുന്നില്ല.

സാധാരണ `alibaba` identity-ക്ക് വെവ്വേറെ image, video allowlists ഉണ്ട്. അതിന്റെ image models:
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo`, `wan2.6-t2i`. പുതുതായി ചേർത്ത video models: `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12`, `wan2.7-videoedit`. ഈ models Alibaba Model Studio
connection-ഉം അതിൽ തിരഞ്ഞെടുത്ത പ്രാദേശിക media endpoint-ഉം മാത്രം ഉപയോഗിക്കുന്നു; ഇവ ഏതെങ്കിലും Coding Plan അല്ലെങ്കിൽ Qwen
Cloud registry-യിലേക്ക് ചേർക്കപ്പെടുന്നില്ല.

Qwen Cloud Token Plan chat catalog, Individual plan-ന്റെ exact-string text allowlist പിന്തുടരുന്നു:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2`,
`deepseek-v4-pro`. Wan, HappyHorse entries വെവ്വേറെയുള്ള image/video generation APIs-ലാണ് ഉൾപ്പെടുന്നത്.

Alibaba Token Plan, അതിന്റെ Anthropic-compatible endpoint വഴി നിലവിലുള്ള അതേ ആറ് text-generation model IDs ലഭ്യമാക്കുന്നു.
അതിന്റെ Singapore option നിലവിലുള്ള `global-sg` region key സൂക്ഷിക്കുന്നു;
region-നെ Global എന്ന് വിളിക്കുന്ന provider families-ൽ നിന്ന് വ്യത്യസ്തമാകുന്നത് ഉപയോക്താവിന് ദൃശ്യമാകുന്ന label മാത്രമാണ്.

സാധാരണ Qwen Cloud chat catalog, പൂർണ്ണമായ തത്സമയ text response-നേക്കാൾ ഉദ്ദേശപൂർവം പരിമിതമാണ്. അതിന്റെ
പരിപാലിത allowlist `open-sse/config/providers/registry/qwen-cloud/index.ts`-ലാണ്; live
discovery upstream response-ലും ആ registry list-ലും ഉള്ള IDs മാത്രം മടക്കിനൽകുന്നു.

Alibaba Model Studio, `open-sse/config/providers/registry/alibaba/index.ts`-ൽ സ്വതന്ത്രമായി പരിപാലിക്കുന്ന
allowlist ഉപയോഗിച്ച് ഇതേ live-intersection rule പിന്തുടരുന്നു. `alibaba-cn` compatibility
provider, Beijing endpoint-നെതിരെ discovery resolve ചെയ്യുമ്പോൾ ആ catalog വീണ്ടും ഉപയോഗിക്കുന്നു.
