## `claude-web`

`claude-web`, പ്രാമാണീകരിച്ച ഒരു `claude.ai` ബ്രൗസർ സെഷനിലൂടെ OpenAI-ഫോർമാറ്റിലുള്ള ചാറ്റ് അഭ്യർത്ഥനകൾ അയയ്ക്കുന്നു. എക്സിക്യൂട്ടർ നൽകിയ കുക്കിയെ നോർമലൈസ് ചെയ്യുകയും, പ്രാമാണീകരിച്ച ഒരു ഓർഗനൈസേഷൻ കണ്ടെത്തുകയും, സംഭാഷണാവസ്ഥ തയ്യാറാക്കുകയും, ഡയറക്ട് അല്ലെങ്കിൽ ബ്രൗസർ ട്രാൻസ്പോർട്ട് തിരഞ്ഞെടുക്കുകയും, അപ്സ്ട്രീം SSE പ്രതികരണത്തെ കർശനമായി പരിവർത്തനം ചെയ്യുകയും ചെയ്യുന്നു. ഓർക്കസ്ട്രേഷൻ `open-sse/executors/claude-web.ts:320`-ലാണ്.

> **Web Cookie പ്രൊവൈഡറുകൾ ആദ്യമായാണോ ഉപയോഗിക്കുന്നത്?**
>
> ഈ പ്രൊവൈഡർ-നിർദ്ദിഷ്ട ഗൈഡ് പിന്തുടരുന്നതിന് മുമ്പ് പൊതുവായ സജ്ജീകരണ പ്രക്രിയ, പ്രാമാണീകരണ മാർഗ്ഗനിർദ്ദേശം, പരിമിതികൾ, പ്രശ്നപരിഹാരം എന്നിവയ്ക്കായി **`docs/getting-started/WEB-COOKIE-GUIDE.md`** വായിക്കുക.

പ്രൊവൈഡർ രജിസ്ട്രി നിലവിൽ താഴെപ്പറയുന്ന കൃത്യമായ ഏഴ് സ്റ്റാറ്റിക് മോഡൽ ID-കൾ ലഭ്യമാക്കുന്നു
(`open-sse/config/providers/registry/claude/web/index.ts:11`):

| മോഡൽ ID                     | പ്രദർശന നാമം             |
| --------------------------- | ------------------------ |
| `claude-fable-5`            | Claude Fable 5 (വെബ്)    |
| `claude-opus-4-8`           | Claude Opus 4.8 (വെബ്)   |

| `claude-opus-4-7`           | Claude Opus 4.7 (വെബ്)   |

ഈ പ്രൊവൈഡറിനായി ഡൈനാമിക് മോഡൽ കണ്ടെത്തൽ നടപ്പിലാക്കിയിട്ടില്ല. മുകളിലുള്ള പട്ടികയാണ് റൺടൈം കാറ്റലോഗ്.

### ക്രെഡൻഷ്യലുകളും ഓർഗനൈസേഷൻ കണ്ടെത്തലും

പൂർണ്ണമായ `claude.ai` Cookie ഹെഡറോ ഒരു സെഷൻ മൂല്യമാത്രമോ നൽകുക. സെഷൻ മൂല്യങ്ങൾ മാത്രം നൽകിയാൽ അവ `sessionKey` ആയി നോർമലൈസ് ചെയ്യപ്പെടും; മറ്റ് കുക്കികൾ നൽകിയിട്ടുണ്ടെങ്കിൽ അവ നിലനിർത്തും. എക്സിക്യൂട്ടർ `cookie` അല്ലെങ്കിൽ `apiKey` വഴി കുക്കി സ്വീകരിക്കുകയും കണക്ഷൻ ഡാറ്റയിൽനിന്ന് ഐച്ഛികമായ `deviceId`, `orgId` മൂല്യങ്ങൾ വായിക്കുകയും ചെയ്യുന്നു
(`open-sse/executors/claude-web.ts:72`).

`orgId` ഇല്ലെങ്കിൽ, എക്സിക്യൂട്ടർ `GET https://claude.ai/api/organizations` കോൾ ചെയ്യുകയും പ്രാമാണീകരിച്ച Claude Web സെഷൻ മടക്കിനൽകുന്ന ആദ്യ ഓർഗനൈസേഷൻ ഉപയോഗിക്കുകയും ചെയ്യുന്നു
(`open-sse/executors/claude-web.ts:141`). സാധുവായ ഓർഗനൈസേഷനൊന്നും ലഭിക്കാത്തപ്പോൾ ഇത് സുരക്ഷിതമായി പരാജയപ്പെടുന്നു, നിരസിക്കപ്പെട്ട സെഷൻ ഓതറൈസേഷൻ 401 ആയി റിപ്പോർട്ട് ചെയ്യുന്നു, കൂടാതെ Cloudflare ചലഞ്ചിനെ പ്രാമാണീകരണ പരാജയത്തിൽനിന്ന് വേർതിരിച്ചറിയുന്നു.

### സംഭാഷണ പ്രവർത്തനങ്ങൾ

ഐച്ഛികമായ ടോപ്പ്-ലെവൽ `claude_web` ഒബ്ജക്റ്റ് കർശനമാണ്. അജ്ഞാത ഫീൽഡുകൾ നിരസിക്കപ്പെടും. അത് സ്വീകരിക്കുന്ന ഫീൽഡുകൾ `open-sse/executors/claude-web/session.ts:50`-ൽ നിർവചിച്ചിരിക്കുന്നു:

| ഫീൽഡ്                 | അർത്ഥം                                                                            |
| --------------------- | --------------------------------------------------------------------------------- |
| `operation`           | ഡിഫോൾട്ടായി `completion`; വീണ്ടും ശ്രമിക്കുന്ന ടേണിന് `retry` ഉപയോഗിക്കുക         |
| `conversation_id`     | നിലവിലുള്ള സംഭാഷണത്തിനായുള്ള വ്യക്തമായ UUID                                       |
| `parent_message_uuid` | പാരന്റ് അസിസ്റ്റന്റ് സന്ദേശത്തിനായുള്ള വ്യക്തമായ UUID                             |
| `timezone`            | സാധുവായ IANA സമയമേഖലാ നാമം                                                        |
| `locale`              | ഘടനാപരമായി സാധുവായ ലോക്കേൽ                                                        |
| `tool_states`         | ഐച്ഛിക അക്കൗണ്ട് ടൂൾ-സ്റ്റേറ്റ് അറേ; 128 എൻട്രികളായി പരിമിതപ്പെടുത്തിയിരിക്കുന്നു |

തയ്യാറാക്കിയ അഭ്യർത്ഥനകൾ രണ്ട് അപ്സ്ട്രീം എൻഡ്പോയിന്റുകളിൽ ഒന്ന് ഉപയോഗിക്കുന്നു
(`open-sse/executors/claude-web.ts:203`):

- പുതിയതോ തുടർനടപടിയായതോ ആയ ടേൺ
  `POST https://claude.ai/api/organizations/{orgId}/chat_conversations/{conversationId}/completion`-ലേക്ക് പോസ്റ്റ് ചെയ്യുന്നു.
- വീണ്ടും ശ്രമിക്കുന്നത്
  `POST https://claude.ai/api/organizations/{orgId}/chat_conversations/{conversationId}/retry_completion`-ലേക്ക് പോസ്റ്റ് ചെയ്യുന്നു.

ഒരു പുതിയ ടേണിൽ `create_conversation_params` ഉൾപ്പെടുന്നു. കാഷ് ചെയ്തതോ വ്യക്തമായി ലിങ്ക് ചെയ്തതോ ആയ തുടർനടപടിയിൽ `parent_message_uuid` ഉൾപ്പെടുകയും `create_conversation_params` ഒഴിവാക്കുകയും ചെയ്യുന്നു. വീണ്ടും ശ്രമിക്കുന്നതിന് സംഭാഷണാവസ്ഥയും പാരന്റ്-സന്ദേശാവസ്ഥയും ആവശ്യമാണ്; അതിൽ പ്രോംപ്റ്റ് അയയ്ക്കില്ല
(`open-sse/executors/claude-web/session.ts:254`). പുതിയ സംഭാഷണങ്ങൾ പ്രാമാണീകരിച്ച UI `/new`-ൽ തുറക്കുന്നു; കാഷ് ചെയ്തതോ വ്യക്തമായി ലിങ്ക് ചെയ്തതോ ആയ തുടർനടപടികൾ കൃത്യമായ സംഭാഷണ പേജ് തുറക്കുന്നു
(`open-sse/executors/claude-web/session.ts:324`).

SHA-256 അക്കൗണ്ട് സ്കോപ്പും കാനോണിക്കൽ കോളർ ട്രാൻസ്ക്രിപ്റ്റും കീ ആയി ഉപയോഗിക്കുന്ന ഇൻ-മെമ്മറി കാഷാണ് സംഭാഷണാവസ്ഥ. എൻട്രികൾ 30 മിനിറ്റിന് ശേഷം കാലഹരണപ്പെടുകയും കാഷ് 5,000 എൻട്രികളായി പരിമിതപ്പെടുത്തുകയും ചെയ്യുന്നു
(`open-sse/executors/claude-web/session.ts:12`). കർശനമായ സ്ട്രീം പാർസർ `message_stop` നിരീക്ഷിച്ചതിനുശേഷം മാത്രമേ അവസ്ഥ കമ്മിറ്റ് ചെയ്യൂ; പ്രോസസ്സ് പുനരാരംഭിക്കുമ്പോൾ അത് ഉപേക്ഷിക്കപ്പെടും. കാഷ് മിസ് സംഭവിക്കുമ്പോൾ, മുൻ സന്ദേശങ്ങൾ നിശ്ശബ്ദമായി ഒഴിവാക്കുന്നതിനുപകരം ഒന്നിലധികം സന്ദേശങ്ങളുള്ള അഭ്യർത്ഥന ഒരൊറ്റ റിക്കവറി പ്രോംപ്റ്റായി സീരിയലൈസ് ചെയ്യപ്പെടുന്നു.

ലോക്കേലും സമയമേഖലയും ഈ മുൻഗണനാക്രമം ഉപയോഗിക്കുന്നു: അഭ്യർത്ഥനയിലെ `claude_web` മൂല്യം, കണക്ഷൻ മൂല്യം, റൺടൈം മൂല്യം, തുടർന്ന് ലോക്കേലിനായി `en-US` അല്ലെങ്കിൽ സമയമേഖലയ്ക്കായി `UTC`
(`open-sse/executors/claude-web/session.ts:218`).

### ടൂളുകളും അഭ്യർത്ഥന പേലോഡുകളും

ഡയറക്ട് അഭ്യർത്ഥനകൾ കോളർ നൽകുന്ന, ഘടനാപരമായി സാധുവായ OpenAI ഫങ്ഷൻ ടൂളുകൾ മാത്രം പരിവർത്തനം ചെയ്യുന്നു. കൃത്രിമമായി സൃഷ്ടിച്ച സ്റ്റാറ്റിക് ഡിഫോൾട്ട് ടൂൾ ലിസ്റ്റ് ഇല്ല
(`open-sse/executors/claude-web/payload.ts:102`).

പകരം ബ്രൗസർ അഭ്യർത്ഥനകൾ പ്രാമാണീകരിച്ച UI അഭ്യർത്ഥന ക്യാപ്ചർ ചെയ്യുകയും അതിലെ അക്കൗണ്ട് ടൂളുകൾ, ടൂൾ സ്റ്റേറ്റുകൾ, വ്യക്തിപരമാക്കിയ ശൈലികൾ എന്നിവ നിലനിർത്തുകയും ചെയ്യുന്നു. തയ്യാറാക്കിയ സംഭാഷണം, മോഡൽ, റീസണിങ്, പ്രോംപ്റ്റ്, സന്ദേശ UUID ഫീൽഡുകൾ എന്നിവ ക്യാപ്ചർ ചെയ്ത അഭ്യർത്ഥനയെ തുടർന്നും ഓവർറൈഡ് ചെയ്യുന്നു
(`open-sse/executors/claude-web/browserTransport.ts:175`). അക്കൗണ്ട്, ഓർഗനൈസേഷൻ, കുക്കി, ലോക്കേൽ, സമയമേഖല എന്നിവയുടെ ഹാഷ് അനുസരിച്ചാണ് ബ്രൗസർ ടെംപ്ലേറ്റുകളുടെ സ്കോപ്പ് നിർണ്ണയിക്കുന്നത്; അവ 30 മിനിറ്റിന് ശേഷം കാലഹരണപ്പെടുന്നു
(`open-sse/executors/claude-web/browserTransport.ts:11`,
`open-sse/executors/claude-web/browserTransport.ts:158`). ഒരു ഡയറക്ട് അഭ്യർത്ഥനയിൽ കോളർ ടൂളുകൾ ഇല്ലെങ്കിൽ, അതിന് ആ സ്കോപ്പ് ചെയ്ത ടെംപ്ലേറ്റ് വീണ്ടും ഉപയോഗിക്കാം; വ്യക്തമായി നൽകിയ കോളർ ടൂളുകൾക്കാണ് മുൻഗണന
(`open-sse/executors/claude-web/browserTransport.ts:214`).

### ട്രാൻസ്പോർട്ട് തിരഞ്ഞെടുപ്പ്

ഡിഫോൾട്ട് പാത `sendClaudeWebDirect()` ആണ്; ഇത് കോൺഫിഗർ ചെയ്ത Chrome 146 പ്രൊഫൈലും നൽകിയ കുക്കിയും ഉപയോഗിച്ച് `tlsFetchClaude()` കോൾ ചെയ്യുന്നു (`open-sse/services/claudeTlsClient.ts:23`). ഇത് ഒരു സോൾവർ ലോഞ്ച് ചെയ്യുകയോ പകരം ഉപയോഗിക്കാനുള്ള കുക്കി നിർമ്മിക്കുകയോ ചെയ്യുന്നില്ല.

അക്കൗണ്ട് പരിധിയിലുള്ള browser adapter-നെ പ്രാഥമിക transport ആക്കാൻ `WEB_COOKIE_USE_BROWSER` എന്നത് `1`, `true`, അല്ലെങ്കിൽ `on` ആയി സജ്ജീകരിക്കുക. തിരിച്ചറിഞ്ഞ Cloudflare 403 challenge ഉണ്ടാകുമ്പോൾ direct transport-ൽ നിന്ന് browser adapter-ലേക്ക് fallback അനുവദിക്കാൻ `OMNIROUTE_BROWSER_POOL` എന്നതും ഇതേ മൂല്യങ്ങളിൽ ഒന്നായി സജ്ജീകരിക്കുക (`open-sse/executors/claude-web.ts:195`). മറ്റ് HTTP പരാജയങ്ങൾ ആ fallback പ്രവർത്തനക്ഷമമാക്കില്ല.

Browser adapter cookies-നെ അതേ pooled Playwright context-നുള്ളിൽ സൂക്ഷിക്കുകയും, മുകളിൽ വിവരിച്ച scoped hashed key ഉപയോഗിക്കുകയും, ആ context-ൽ നിന്ന് completion അയയ്ക്കുകയും ചെയ്യുന്നു (`open-sse/executors/claude-web/browserTransport.ts:444`). Browser പരിഹരിച്ച cookie-യെ ഇത് ഒരിക്കലും direct TLS client-ലേക്ക് export ചെയ്യില്ല. Browser retry-കൾക്ക് അതേ യഥാർഥ Playwright context-മായി ബന്ധിപ്പിച്ചിട്ടുള്ള, കാലഹരണപ്പെടാത്ത UI template ആവശ്യമാണ് (`open-sse/executors/claude-web/browserTransport.ts:467`). Browser response വായനകൾ authenticated page-ൽ incremental ആയി പ്രവർത്തിക്കുകയും, request cancellation മാനിക്കുകയും, 16 MiB കവിഞ്ഞ ഉടൻ upstream body cancel ചെയ്യുകയും ചെയ്യുന്നു (`open-sse/executors/claude-web/browserTransport.ts:259`).

Executor, പങ്കിട്ട request logger-ലേക്ക് redacted audit projection നൽകുന്നു: organization, conversation, message UUID-കൾ, prompt text, tool definitions, cookies, device identifiers എന്നിവ ഒഴിവാക്കപ്പെടുന്നു (`open-sse/executors/claude-web.ts:237`,
`open-sse/executors/claude-web.ts:252`). Transport exception-കളും thrown message-ന് പകരം ഒരു പൊതുവായ connection error ആണ് നൽകുന്നത്.

### SSE പെരുമാറ്റം

`createClaudeWebResponse()` LF അല്ലെങ്കിൽ CRLF framing-ഉം multiline `data:` field-ുകളും കൈകാര്യം ചെയ്യുന്നു. ഇത് text delta-കളെ `content`-ലേക്കും, thinking delta-കളെ `reasoning_content`-ലേക്കും, അറിയപ്പെടുന്ന metadata event-ുകളെ `claude_web` response extension-ലേക്കും map ചെയ്യുന്നു. ഓരോ metadata event-ഉം അതിന്റേതായ field allowlist വഴി project ചെയ്യപ്പെടുന്നു (`open-sse/executors/claude-web/stream.ts:37`). Conversation, parent-message, assistant-message, operation metadata എന്നിവ `X-OmniRoute-Claude-Web-*` header-ുകളിലും നൽകപ്പെടുന്നു (`open-sse/executors/claude-web/stream.ts:364`).

വികലമായ JSON, upstream `error` event-ുകൾ, അറിയപ്പെടാത്ത event type-ുകൾ, അസാധുവായ ordering, content-block പൊരുത്തക്കേടുകൾ, അല്ലെങ്കിൽ `message_stop`-ന് മുമ്പുള്ള EOF എന്നിവ ഉണ്ടായാൽ parser സുരക്ഷിതമായി പരാജയപ്പെടുന്നു. Streaming output ഒരു finish chunk-ഉം ഒരു `[DONE]`-ഉം പുറപ്പെടുവിക്കുന്നു; buffered output ഇതേ parser ഉപയോഗിക്കുന്നു. Parser `message_stop`-നെ ഉടൻ terminal ആയി കണക്കാക്കുകയും, തുടർന്നുവരുന്ന upstream data cancel ചെയ്യുകയും, downstream cancellation upstream reader-ലേക്ക് propagate ചെയ്യുകയും ചെയ്യുന്നു (`open-sse/executors/claude-web/stream.ts:461`,
`open-sse/executors/claude-web/stream.ts:563`). അവസാനിപ്പിക്കാത്ത SSE line-ുകളും ശേഖരിച്ച event-ുകളും പരമാവധി 1 MiB ആയി നിയന്ത്രിച്ചിരിക്കുന്നു (`open-sse/executors/claude-web/stream.ts:17`,
`open-sse/executors/claude-web/stream.ts:62`).
