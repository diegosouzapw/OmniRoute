`chatgpt-web-codex` (`cgpt-codex` എന്ന അപരനാമം) പ്രാമാണീകരിച്ച ChatGPT ബ്രൗസർ സെഷനിലൂടെ Codex Responses ടേണുകളെ ബന്ധിപ്പിക്കുന്നു. വിരമിച്ച പൊതുവായ `chatgpt-web` പ്രൊവൈഡറിൽനിന്ന് ഇത് സ്വതന്ത്രമാണ്; കൂടാതെ upstream v4.0.7 commit `b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494` വഴി പുതുക്കിയ, `open-sse/vendor/codex-chatgpt-web/` എന്നതിലെ MIT അറിയിപ്പോടുകൂടിയ ഇംപ്ലിമെന്റേഷനാണ് ഇത് ഉപയോഗിക്കുന്നത്.

## പൊതുവായ പ്രൊവൈഡറിന്റെ വിരമിക്കൽ

മുൻ പൊതുവായ പ്രൊവൈഡർ ID-കളായ `chatgpt-web`, `cgpt-web` എന്നിവയുടെ pre-key/proof-of-work ഇംപ്ലിമെന്റേഷന്റെ ഉത്ഭവം സ്ഥിരീകരിക്കാൻ കഴിഞ്ഞില്ലാത്തതിനാൽ അവ ഇനി വിതരണം ചെയ്യുന്നില്ല. slash-prefixed മോഡൽ ID-കളും നിലനിർത്തിയ അപരനാമങ്ങളും ഉൾപ്പെടെ, ഈ ID-കളിൽ ഏതെങ്കിലും ഒന്നിലേക്കുള്ള വ്യക്തമായ അഭ്യർത്ഥനകൾ ഏതെങ്കിലും upstream അഭ്യർത്ഥനയ്ക്ക് മുമ്പ് HTTP `410`, **PROVIDER_RETIRED** കോഡ് എന്നിവയോടെ അടച്ച നിലയിൽ പരാജയപ്പെടും.

Migration `168_retire_chatgpt_web.sql`, പൊരുത്തപ്പെടുന്ന പ്രൊവൈഡർ കണക്ഷനുകളെ tombstone ചെയ്യുകയും അവയുടെ സജീവ സെഷൻ lease-കൾ അസാധുവാക്കുകയും ചെയ്യുന്നു. ഇത് കണക്ഷൻ ചരിത്രവും API-key allowlist-കളും നിലനിർത്തുന്നു; പകരംവയ്ക്കുന്ന ആക്സസ് ഒരു allowlist-ലേക്കും ചേർക്കുന്നില്ല. Codex പ്രൊവൈഡറും അതിന്റെ കണക്ഷനുകളും ഈ വിരമിക്കലിൽ പൊരുത്തപ്പെടുത്തപ്പെടുന്നില്ല.

## മുൻവ്യവസ്ഥകൾ

- സൈൻ ഇൻ ചെയ്ത ChatGPT സെഷനിൽനിന്നുള്ള പൂർണ്ണ Cookie header;
- npm, systemd, PM2 ഇൻസ്റ്റാളേഷനുകൾക്കായി Chrome അല്ലെങ്കിൽ Chromium-ഉം ഒരു ഗ്രാഫിക്കൽ സെഷൻ അല്ലെങ്കിൽ Xvfb display-യും;
- Docker `web` പ്രൊഫൈലിനൊപ്പം, `docker-compose.yml`-ൽനിന്നുള്ള ആന്തരിക Chromium സേവനം;
- പ്രാദേശിക Codex ടൂളുകൾക്കായി OpenAI `tunnel-client` v0.0.13-ഉം ഒരു ChatGPT custom connector-ഉം.

ടൂൾ ടേണുകൾക്കായി മാത്രമാണ് tunnel ആവശ്യമായത്. tunnel-ഉം connector-ഉം കോൺഫിഗർ ചെയ്തിരിക്കുമ്പോൾ, `pro` ഉൾപ്പെടെ പട്ടികപ്പെടുത്തിയിരിക്കുന്ന എല്ലാ route-കൾക്കും അതേ turn-bound പ്രാദേശിക ടൂൾ ശേഷി ഉപയോഗിക്കാനാകും.

## Dashboard സജ്ജീകരണം

1. **ChatGPT Web (Codex)** പ്രൊവൈഡർ തുറന്ന് ഒരു കണക്ഷൻ ചേർക്കുക.
2. പൂർണ്ണ ChatGPT Cookie header, tunnel ID, runtime key, custom connector-ന്റെ പേര് എന്നിവ ഒട്ടിക്കുക. പുതിയ ടൂൾ-ശേഷിയുള്ള സജ്ജീകരണങ്ങൾ, കൃത്യമായി `OmniRoute Codex v2` എന്ന് പേരിട്ട പുതുതായി സൃഷ്ടിച്ച connector ഉപയോഗിക്കണം; അതിൽ Authentication എന്നത് None ആയും Permissions എന്നത് Allow all actions ആയും സജ്ജീകരിച്ചിരിക്കണം.
3. കണക്ഷൻ പരിശോധന പ്രവർത്തിപ്പിക്കുക. OmniRoute, ബ്രൗസർ പിന്തുണയുള്ള Temporary Chat തുറന്ന് അക്കൗണ്ടിന് Sol, Pro എന്നിവ ലഭ്യമാണോ എന്ന് കണ്ടെത്തുന്നു.
4. കണക്ഷൻ സംരക്ഷിക്കുക. OmniRoute, ഒട്ടിച്ച cookie-യെ സ്ഥിരീകരിച്ച Playwright storage state ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുകയും encrypted credential abstraction വഴി runtime key-നൊപ്പം അത് സംഭരിക്കുകയും ചെയ്യുന്നു.

വിജയകരമായി സംരക്ഷിച്ചതിന് ശേഷം അസംസ്കൃത cookie നിലനിർത്തില്ല. സെഷൻ കാലഹരണപ്പെടുമ്പോൾ, കണക്ഷൻ തുറന്ന് പുതിയ പൂർണ്ണ Cookie header ഒട്ടിക്കുകയും പരിശോധന വീണ്ടും പ്രവർത്തിപ്പിക്കുകയും ചെയ്യുക. എഡിറ്റ് ഡയലോഗിലെ doctor status, browser, storage state, sign-in, Temporary Chat, tunnel, connector, tool round-trip എന്നിവയുടെ നില പ്രത്യേകം റിപ്പോർട്ട് ചെയ്യുന്നു.

> യഥാർഥ cookie, runtime key, storage state, capability token എന്നിവ ഒരിക്കലും commit ചെയ്യരുത്. പരിശോധനയിലും
> ഡോക്യുമെന്റേഷനിലും ഉപയോഗിക്കുന്ന മൂല്യങ്ങൾ എല്ലായ്പ്പോഴും placeholder-കൾ ആയിരിക്കണം.

## മോഡലുകളും combo-കളും

സ്ഥിരമായ model route-കൾ ഇവയാണ്:

- `chatgpt-web-codex/luna` — GPT-5.6 Luna, കുറഞ്ഞ effort
- `chatgpt-web-codex/think` — GPT-5.6 Luna, ഇടത്തരം effort
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

മറ്റേതൊരു മോഡലിനെയും പോലെ ഇവയിൽ ഒന്ന് ഒരു combo-യിലേക്ക് ചേർക്കുക. Codex ആപ്പ്, സാധാരണ Responses endpoint ആയ `/v1/responses`-ലേക്ക് combo-യുടെ പേര് `model` ആയി അയയ്ക്കുന്നു; പ്രത്യേക Codex endpoint-ഓ mode switch-ഓ ഇല്ല.

Free/Go അക്കൗണ്ടുകൾ Luna route-കൾ ലഭ്യമാക്കുന്നു. Sol-ശേഷിയുള്ള അക്കൗണ്ടുകൾ Instant മുതൽ High വരെയുള്ളവ ലഭ്യമാക്കുന്നു; Pro-ശേഷിയുള്ള അക്കൗണ്ടുകൾ കൂടാതെ Extra High, Pro എന്നിവയും ലഭ്യമാക്കുന്നു. ഓരോ route-നും സ്ഥിരമായ backend model-ഉം reasoning effort-ഉം ഉണ്ട്; വൈരുദ്ധ്യമുള്ള വ്യക്തമായ Responses effort, തിരഞ്ഞെടുത്ത browser mode നിശ്ശബ്ദമായി മാറ്റുന്നതിനുപകരം അടച്ച നിലയിൽ പരാജയപ്പെടുന്നു.

പഴയ `Codex Native` അല്ലെങ്കിൽ `OmniRoute Codex` connector-ന്റെ പേര് മാറ്റുകയോ അത് വീണ്ടും ഉപയോഗിക്കുകയോ ചെയ്യരുത്. ChatGPT, connector identity അനുസരിച്ച് പൊതു MCP contract cache ചെയ്യുന്നു; അതേസമയം പുതുക്കിയ bridge ഒരു പുതിയ direct turn-token contract ആണ് ഉപയോഗിക്കുന്നത്. runtime ആ legacy identity-കളെ നിരസിക്കുകയും പുതിയ `OmniRoute Codex v2` connector ആവശ്യപ്പെടുകയും ചെയ്യുന്നു.

  നിർവഹണവും Codex മാത്രമാണ് തീരുമാനിക്കുന്നത്.
- ആദ്യ ഔട്ട്പുട്ടിന് മുമ്പ്, ഒരു കോംബോയ്ക്ക് അനുയോജ്യമായ മറ്റൊരു ടാർഗെറ്റിലേക്ക് ഫാൾബാക്ക് ചെയ്യാം. ഔട്ട്പുട്ട്
  ആരംഭിച്ചതിന് ശേഷം, ടേൺ പൂർത്തിയാകുന്നതുവരെ പ്രൊവൈഡർ, മോഡൽ, കണക്ഷൻ, ബ്രൗസർ ടേൺ എന്നിവ പിൻ ചെയ്ത നിലയിൽ തുടരും.
- കുക്കികൾ, റൺടൈം കീകൾ, സ്റ്റോറേജ് സ്റ്റേറ്റ്, ശേഷി ടോക്കണുകൾ എന്നിവ പ്രൊവൈഡർ
  പ്രതികരണങ്ങളിലോ അഭ്യർത്ഥന ലോഗുകളിലോ പ്രത്യക്ഷപ്പെടില്ല.

## ഡിസ്പ്ലേയില്ലാത്ത VPS-ഉം Docker-ഉം

npm, systemd, PM2 ഇൻസ്റ്റാളേഷനുകൾക്കായി, സാധാരണ Chrome, Chromium പാതകൾ OmniRoute കണ്ടെത്തുന്നു.
പകരമായി, `CHATGPT_WEB_CODEX_CHROME_PATH` സജ്ജമാക്കുക. ChatGPT യഥാർഥ-ഹെഡ്ലെസ് ബ്രൗസർ രൂപം നിരസിക്കുന്നതിനാൽ,
റൺടൈം ടേണുകൾ മനഃപൂർവം ഹെഡഡ് Chrome ഉപയോഗിക്കുന്നു. അതിനാൽ ഡിസ്പ്ലേയില്ലാത്ത ഒരു ഹോസ്റ്റ്,
ഒരു സ്വകാര്യ Xvfb ഡിസ്പ്ലേയോടൊപ്പം OmniRoute പ്രവർത്തിപ്പിക്കണം; Chrome പാത മാത്രം സജ്ജമാക്കുന്നത് ഒരു ഡിസ്പ്ലേ നൽകില്ല.

Docker `web` പ്രൊഫൈൽ, ആന്തരിക Compose നെറ്റ്വർക്കിൽ `chatgpt-web-codex-browser`
ആരംഭിക്കുന്നു. സൈഡ്കാർ Xvfb-യ്ക്കുള്ളിൽ ഹെഡഡ് Chrome പ്രവർത്തിപ്പിക്കുന്നതിനാൽ, ഭൗതിക ഡിസ്പ്ലേ ആവശ്യമില്ല. അതിന്റെ CDP
പോർട്ട് ഹോസ്റ്റിൽ പ്രസിദ്ധീകരിക്കപ്പെടുന്നില്ല. സംരക്ഷിത ബ്രൗസർ പ്രൊഫൈൽ വോള്യം
OmniRoute ഡാറ്റ വോള്യത്തിൽ നിന്ന് വേറിട്ടതാണ്, കൂടാതെ ബ്രൗസറിന് മതിയായ പങ്കിട്ട മെമ്മറി ലഭിക്കുന്നു. ആന്തരിക CDP പ്രോക്സി,
Compose നെറ്റ്വർക്കിനുള്ളിലെ `9223` പോർട്ടിൽ മാത്രം ലിസൺ ചെയ്യുന്നു; സൈഡ്കാറിൽ Chrome ലൂപ്പ്ബാക്കുമായി ബന്ധിപ്പിച്ച നിലയിൽ തുടരുന്നു.

`DATA_DIR`-ന് കീഴിലുള്ള ഒരു സൂപ്പർവൈസർ ലീസ്, ഒന്നിലധികം OmniRoute പ്രോസസ്സുകൾ
ഒരേ ടണലിന്റെയും ബ്രോക്കർ സ്റ്റേറ്റിന്റെയും ഉടമസ്ഥത ഏറ്റെടുക്കുന്നത് തടയുന്നു. ഒരു വൈരുദ്ധ്യം ഡോക്ടർ റിപ്പോർട്ട് ചെയ്യും.

## ഇന്ററാക്ടീവ് വീണ്ടെടുക്കൽ

ഓട്ടോമേറ്റഡ് Docker പാതയ്ക്ക് ഹോസ്റ്റിൽ ദൃശ്യമാകുന്ന വിൻഡോ ഇല്ലെങ്കിലും, സ്വകാര്യ Xvfb
ഡിസ്പ്ലേയ്ക്കുള്ളിൽ Chrome തന്നെ ഹെഡഡ് മോഡിലാണ്. ChatGPT-യ്ക്ക് ഇന്ററാക്ടീവ് സൈൻ-ഇൻ അല്ലെങ്കിൽ ചലഞ്ച് ആവശ്യമായി വരുമ്പോൾ, നിലവിലുള്ള VNC
ബ്രൗസർ ഇൻഫ്രാസ്ട്രക്ചർ വീണ്ടെടുക്കലിനായി ഉപയോഗിക്കാം. ബ്രൗസർ UI-യും CDP-യും ലൂപ്പ്ബാക്ക്,
ആധികാരികത പരിശോധിച്ച മാനേജ്മെന്റ് കണക്ഷൻ, അല്ലെങ്കിൽ SSH ടണൽ എന്നിവയിലൂടെ മാത്രം പ്രാപ്യമാകണം; സാധാരണ പ്രവർത്തന സമയത്ത് noVNC പ്രവർത്തനരഹിതമായി തുടരും.

## WebSocket ഫാൾബാക്ക്

ഒരു കോംബോയിൽ ChatGPT Web (Codex) ഉൾപ്പെടുമ്പോൾ, അപ്സ്ട്രീമിലേക്ക് കണക്റ്റ് ചെയ്യുന്നതിന് മുമ്പ് Responses WebSocket ബ്രിഡ്ജ്
HTTP/SSE ഫാൾബാക്ക് അഭ്യർത്ഥിക്കുന്നു. തുടർന്ന് കൈമാറ്റം
`/v1/responses` വഴി നടക്കുന്നു.
