IDE സെഷൻ ഇല്ലാതെ Cursor-നെ OmniRoute-ന് പിന്നിൽ സ്ഥാപിക്കാൻ രണ്ട് മാർഗങ്ങൾ:

1. **`cursor-api` പ്രൊവൈഡർ** (കാർഡ് "Cursor API", അപരനാമം `cua`): Cursor ഉപയോക്തൃ API കീ (`crsr_…`, `https://cursor.com/dashboard/api`-ൽ സൃഷ്ടിച്ചത്) സൂക്ഷിക്കുന്ന ഒരു API-key പ്രൊവൈഡർ. തുടർന്ന് ഏത് OmniRoute ക്ലയന്റിനും സാധാരണ ക്വാട്ട, ഫാൾബാക്ക്, ലോഗിംഗ് ലെയറുകളോടെ `/v1/chat/completions` വഴി `cursor-api/<model>` അല്ലെങ്കിൽ `cua/<model>` ആയി Cursor മോഡലുകൾ ആക്സസ് ചെയ്യാം. IDE പ്രൊവൈഡറിൽ (`cursor`, OAuth/IDE സെഷൻ) മാറ്റമില്ല.
2. **Cursor CLI പാസ്ത്രൂ**: Cursor CLI (`agent`)-യെ OmniRoute-ലേക്ക് പോയിന്റ് ചെയ്യുക. അങ്ങനെ CLI നടത്തുന്ന ഓരോ RPC-യും ഒരു OmniRoute API കീ ഉപയോഗിച്ച് പ്രാമാണീകരിക്കപ്പെടുകയും, ഒരു `cursor-api` കണക്ഷന്റെ ക്രെഡൻഷ്യൽ ഉപയോഗിച്ച് Cursor-ലേക്ക് ഫോർവേഡ് ചെയ്യപ്പെടുകയും, Logs പേജിൽ രേഖപ്പെടുത്തപ്പെടുകയും ചെയ്യും.

## കീ കൈമാറ്റം ചെയ്യുന്നതിന്റെ കാരണം

ഒരു അസംസ്കൃത `crsr_…` കീയെ Bearer ടോക്കണായി നൽകിയാൽ `api2.cursor.sh` അത് നിരസിക്കുന്നു (401). Cursor CLI ആദ്യം കീയെ `/auth/exchange_user_api_key`-ലേക്ക് POST ചെയ്യുകയും ഒരു മണിക്കൂറിന് ശേഷം കാലഹരണപ്പെടുന്ന സെഷൻ JWT സ്വീകരിക്കുകയും ചെയ്യുന്നു; തിരികെ ലഭിക്കുന്ന `refreshToken`-ലും അതേ `exp` ഉള്ളതിനാൽ, പുതുക്കൽ എന്നത് കീ വീണ്ടും കൈമാറ്റം ചെയ്യുക എന്നതാണ്.
`open-sse/services/cursorApiKeyAuth.ts` ആ കൈമാറ്റം നടത്തുകയും, ഓരോ കീയ്ക്കും ഒരു സെഷൻ ടോക്കൺ കാഷെ ചെയ്യുകയും, കാലഹരണപ്പെടുന്നതിന് അഞ്ച് മിനിറ്റ് മുമ്പ് വീണ്ടും കൈമാറ്റം നടത്തുകയും, Cursor 401 നൽകി പ്രതികരിക്കുമ്പോൾ കാഷെ ചെയ്ത ടോക്കൺ നീക്കം ചെയ്യുകയും ചെയ്യുന്നു. `cursor-api` കണക്ഷനുകൾക്കായി അപ്സ്ട്രീം സ്ട്രീം തുറക്കുന്നതിന് തൊട്ടുമുമ്പ് `CursorExecutor` ഇതിനെ വിളിക്കുന്നു.

## `cursor-api` പ്രൊവൈഡർ

റെജിസ്ട്രി: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, `cursor`-ലേതിന് സമാനമായ `format`, `baseUrl`, `models`). കാറ്റലോഗ് കാർഡ്:
`src/shared/constants/providers/apikey/specialty-media.ts`. എക്സിക്യൂട്ടർ മാപ്പ്:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

ഡാഷ്ബോർഡ്: Providers → Cursor API → Add API key.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

തുടർന്ന്:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

കുറിപ്പുകൾ:

- `cursor-api`-ക്കുള്ള മോഡൽ ലിസ്റ്റിംഗ് സ്റ്റാറ്റിക് Cursor റെജിസ്ട്രിയിൽ നിന്നാണ് ലഭിക്കുന്നത് (IDE പ്രൊവൈഡർ ഫാൾബാക്ക് ചെയ്യുന്ന അതേ ലിസ്റ്റ്); OmniRoute ഹോസ്റ്റിൽ `cursor-agent` ഇൻസ്റ്റാൾ ചെയ്യേണ്ടതില്ല.
- `POST /api/providers/{id}/refresh-cursor` എന്നത് `cursor` IDE പ്രൊവൈഡറിനായി മാത്രമുള്ളതാണ്; `cursor-api` കണക്ഷനുകൾക്ക് പുതുക്കേണ്ട IDE സെഷനില്ല.

## Cursor CLI പാസ്ത്രൂ

റൂട്ട്: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. ഹാൻഡ്ലർ സ്വന്തം പ്രാമാണീകരണം നടപ്പിലാക്കുന്നതിനാൽ `/api/cursor-cli/` പ്രിഫിക്സ് `src/shared/constants/publicApiRoutes.ts`-ൽ രജിസ്റ്റർ ചെയ്തിരിക്കുന്നു:

| പാത്ത്                                                                                                                           | CLI-യിൽ നിന്ന് പ്രതീക്ഷിക്കുന്ന പ്രാമാണീകരണം | OmniRoute ചെയ്യുന്നത്                                                                                                                                                                                     |
| -------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                               | `Bearer <OmniRoute API key>`                 | കീ സാധൂകരിക്കുകയും, 1h HS256 JWT (`JWT_SECRET` ഉപയോഗിച്ച് സൈൻ ചെയ്തത്) സൃഷ്ടിക്കുകയും, അത് തിരികെ നൽകുകയും ചെയ്യുന്നു                                                                                     |
| മറ്റെല്ലാ പാത്തുകളും (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`                          | ഇഷ്യൂവർ/ഓഡിയൻസ്/കാലാവധി പരിശോധിക്കുകയും, സജീവമായ ഒരു `cursor-api` കണക്ഷൻ തിരഞ്ഞെടുക്കുകയും, Authorization ഹെഡറിന് പകരം കൈമാറ്റം ചെയ്ത Cursor ടോക്കൺ നൽകുകയും, മറുപടി തിരികെ സ്ട്രീം ചെയ്യുകയും ചെയ്യുന്നു |

CLI-ക്ക് ലഭിക്കുന്ന ഏത് ടോക്കണിൽ നിന്നുമുള്ള `exp` അത് ഡീകോഡ് ചെയ്യുന്നതിനാൽ, ഒരു അപാരദർശക ടോക്കൺ നൽകിയാൽ മിക്കവാറും എല്ലാ അഭ്യർത്ഥനകൾക്കും മുമ്പ് അത് വീണ്ടും കൈമാറ്റം ചെയ്യും; സൃഷ്ടിച്ച JWT അത് ഒഴിവാക്കുന്നു. OmniRoute-ൽ നിന്നുള്ള 401, CLI-യെ വീണ്ടും കൈമാറ്റം നടത്താൻ പ്രേരിപ്പിക്കുന്നു.

### സജ്ജീകരണം

1. ഒരു OmniRoute API കീ (Dashboard → API keys), ഒരു `cursor-api` കണക്ഷൻ എന്നിവ സൃഷ്ടിക്കുക.
2. ഏജന്റ് സ്ട്രീമിനായി HTTP/1.1 ഉപയോഗിക്കാൻ CLI-യോട് നിർദേശിക്കുക. `~/.cursor/cli-config.json`-ൽ:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   ഇത് ഇല്ലെങ്കിൽ, പ്രത്യേകം കോൺഫിഗർ ചെയ്ത ഏജന്റ് ഹോസ്റ്റിലേക്ക് HTTP/2 വഴി CLI ഏജന്റ് ടേൺ തുറക്കുകയും കൺട്രോൾ-പ്ലെയ്ൻ RPC-കൾ മാത്രം എൻഡ്പോയിന്റിലൂടെ കടന്നുപോകുകയും ചെയ്യും.

3. OmniRoute-ന് എതിരായി CLI പ്രവർത്തിപ്പിക്കുക:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

ഓരോ ഹോപ്പും പ്രൊവൈഡർ `cursor-api`, അഭ്യർത്ഥനാ തരം `cursor-cli`, പാത്ത് `/api/cursor-cli/<rpc>` എന്നിവയായി Logs-ൽ എത്തുകയും, OmniRoute API കീക്കും അത് കൈകാര്യം ചെയ്ത കണക്ഷനും ബന്ധപ്പെടുത്തപ്പെടുകയും ചെയ്യുന്നു.

### പരാജയ സാഹചര്യങ്ങൾ

| സാഹചര്യം                                          | CLI-യിലേക്കുള്ള പ്രതികരണം                               |
| ------------------------------------------------- | ------------------------------------------------------- |
| അജ്ഞാത OmniRoute കീയും `REQUIRE_API_KEY=true`-ഉം  | എക്സ്ചേഞ്ചിൽ 401 `unauthenticated`                      |
| `REQUIRE_API_KEY=false`                           | അജ്ഞാത സെഷൻ (`/v1/*` പെരുമാറ്റത്തെ അനുകരിക്കുന്നു)      |
| കാലഹരണപ്പെട്ട / അന്യമായ / തിരുത്തപ്പെട്ട സെഷൻ JWT | 401, CLI വീണ്ടും എക്സ്ചേഞ്ച് നടത്തുന്നു                 |
| എക്സ്ചേഞ്ചിന് ശേഷം OmniRoute API കീ പിൻവലിച്ചു    | അടുത്ത RPC-യിൽ 401                                      |
