നിങ്ങളുടെ നിലവിലുള്ള ബ്രൗസർ സെഷനിലൂടെ API key-യ്ക്ക് പകരം ഒരു AI സേവനം ഉപയോഗിക്കാൻ OmniRoute-നെ Web Cookie providers അനുവദിക്കുന്നു. ഒരു സേവനത്തിന്റെ വെബ്സൈറ്റ് വഴി നിങ്ങൾക്ക് ഇതിനകം ആക്സസ് ഉണ്ടായിരിക്കുകയും, അതേ പ്രാമാണീകരിച്ച സെഷൻ OmniRoute ഉപയോഗിക്കണമെന്ന് ആഗ്രഹിക്കുകയും ചെയ്യുമ്പോൾ ഇവ പ്രയോജനകരമാണ്.

API-key providers-ൽ നിന്ന് വ്യത്യസ്തമായി, നിങ്ങളുടെ ബ്രൗസർ വെബ്സൈറ്റിലേക്ക് അയയ്ക്കുന്ന ക്രെഡൻഷ്യലുകൾ ഉപയോഗിച്ചാണ് Web Cookie providers പ്രാമാണീകരിക്കുന്നത്.

# ആരംഭിക്കുന്നതിന് മുമ്പ്

> **പ്രധാനം:** ക്രെഡൻഷ്യലുകൾ എല്ലായ്പ്പോഴും ഒരു **തത്സമയ നെറ്റ്വർക്ക് അഭ്യർത്ഥനയിൽ** നിന്നാണ് പകർത്തേണ്ടത്, നിങ്ങളുടെ ബ്രൗസറിന്റെ cookie storage-ൽ നിന്നല്ല.

തെറ്റായ സ്ഥലത്തുനിന്ന് cookies പകർത്തുന്നതാണ് പല പ്രാമാണീകരണ പ്രശ്നങ്ങൾക്കും കാരണം.

## Cookie Storage-ൽ നിന്ന് പകർത്തരുത്

മിക്ക ബ്രൗസറുകളും സംഭരിച്ച cookies ഇനിപ്പറയുന്നിടത്ത് ലഭ്യമാക്കുന്നു:

```
DevTools
→ Application (അല്ലെങ്കിൽ Storage)
→ Cookies
```

ഈ cookies ശരിയാണെന്ന് തോന്നുമെങ്കിലും, അവ:

- കാലഹരണപ്പെട്ടതായിരിക്കാം
- അപൂർണ്ണമായിരിക്കാം
- പ്രാമാണീകരിച്ച അഭ്യർത്ഥനകളിൽ മാത്രം അയയ്ക്കുന്ന cookies ഇല്ലാത്തവയായിരിക്കാം

ഈ മൂല്യങ്ങൾ സാധുവാണെന്ന് തോന്നിയാലും അവ ഉപയോഗിക്കുന്നത് പ്രാമാണീകരണ പരാജയങ്ങൾക്ക് കാരണമായേക്കാം.

## ഒരു തത്സമയ അഭ്യർത്ഥനയിൽ നിന്ന് പകർത്തുക

പകരം, വിജയകരമായ ഒരു അഭ്യർത്ഥനയിൽ നിന്നുള്ള cookies ഉപയോഗിക്കുക:

```
DevTools
→ Network
→ പേജ് പുതുക്കുക
→ ഒരു chat അല്ലെങ്കിൽ conversation അഭ്യർത്ഥന തുറക്കുക
→ Request Headers
→ Cookie
```

നിങ്ങളുടെ ബ്രൗസർ വിജയകരമായി ഉപയോഗിച്ച കൃത്യമായ പ്രാമാണീകരണ വിവരങ്ങൾ `Cookie` request header-ൽ അടങ്ങിയിരിക്കുന്നു.

മിക്ക Web Cookie providers-നും OmniRoute-ൽ ഒട്ടിക്കേണ്ട മൂല്യം ഇതാണ്.

# പൊതുവായ സജ്ജീകരണം

മിക്ക Web Cookie providers-നും സജ്ജീകരണ പ്രക്രിയ ഒരുപോലെയാണ്.

1. provider-ന്റെ വെബ്സൈറ്റിൽ സൈൻ ഇൻ ചെയ്യുക.
2. ബ്രൗസറിന്റെ Developer Tools തുറക്കുക.
3. **Network** tab തുറക്കുക.
4. പേജ് പുതുക്കുക.
5. പ്രാമാണീകരിച്ച ഒരു chat അല്ലെങ്കിൽ conversation അഭ്യർത്ഥന തുറക്കുക.
6. ആവശ്യമായ പ്രാമാണീകരണ ക്രെഡൻഷ്യലുകൾ പകർത്തുക.
7. OmniRoute തുറക്കുക.
8. **Providers → Add Provider** എന്നതിലേക്ക് പോകുക.
9. നിങ്ങളുടെ Web Cookie provider തിരഞ്ഞെടുക്കുക.
10. ക്രെഡൻഷ്യലുകൾ ഒട്ടിക്കുക.
11. **Test Connection** ക്ലിക്ക് ചെയ്യുക.
12. provider സംരക്ഷിക്കുക.

ആവശ്യമായ കൃത്യമായ ക്രെഡൻഷ്യലുകൾ provider-നെ ആശ്രയിച്ചിരിക്കുന്നു.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) സൈൻ അപ്പ് ആവശ്യമില്ലാത്ത ഒരു സൗജന്യ ഉപഭോക്തൃ ചാറ്റ് പ്ലാറ്റ്ഫോമാണ് — ആദ്യ സന്ദർശനത്തിൽ സെഷൻ അജ്ഞാതമായി സൃഷ്ടിക്കപ്പെടുകയും `uid`, `si_usr_id`, `si_ses_id` എന്നീ മൂന്ന് കുക്കികളിലൂടെ നിലനിൽക്കുകയും ചെയ്യുന്നു. OmniRoute അതേ `/api/dispatch` എൻഡ്പോയിന്റിനെ ഒരൊറ്റ മോഡൽ ഐഡി (`notrack-c`, അപരനാമം `ntw`) വഴി പ്രോക്സി ചെയ്യുന്നു.

### കണക്റ്റ് ചെയ്യാനുള്ള ഘട്ടങ്ങൾ

1. നിങ്ങളുടെ ബ്രൗസറിൽ [notrack.ai](https://notrack.ai) തുറന്ന് അജ്ഞാത സെഷൻ കുക്കി സജ്ജമാകാൻ അനുവദിക്കുക.
2. **DevTools → Network** തുറന്ന് പേജ് പുതുക്കിയശേഷം ഏതെങ്കിലും `/api` അഭ്യർത്ഥനയിൽ ക്ലിക്ക് ചെയ്യുക.
3. **Request Headers** എന്നതിൽ നിന്ന് പൂർണ്ണമായ `Cookie` ഹെഡർ മൂല്യം പകർത്തുക.
4. OmniRoute-ൽ **Providers → Add Provider → NoTrack Web (Free)** എന്നതിലേക്ക് പോകുക.
5. കുക്കി സ്ട്രിംഗ് `apiKey` ഫീൽഡിൽ ഒട്ടിച്ച് **Save** ചെയ്യുക.

ഒട്ടിച്ച സ്ട്രിംഗിൽ നിന്ന് OmniRoute `uid`, `si_usr_id`, `si_ses_id` എന്നിവ വേർതിരിച്ചെടുക്കുകയും ആ ജോടികൾ മാത്രം ഉൾപ്പെടുത്തി ശുദ്ധമായ ഒരു `Cookie` ഹെഡർ പുനർനിർമ്മിക്കുകയും ചെയ്യുന്നു — കൂടാതെ, ലഭ്യമാണെങ്കിൽ `nt_session`-ഉം (ലോഗിൻ ചെയ്ത അക്കൗണ്ടുകൾക്കായി സജ്ജമാക്കിയ `ntk_…` ടോക്കൺ) ഉൾപ്പെടുത്തുന്നു. ഈ മൂന്നിൽ ഏതെങ്കിലും ഒന്ന് ഇല്ലെങ്കിൽ, ഓപ്പറേറ്റർമാർക്ക് ബദൽ ഘടനകൾ പരീക്ഷിക്കാൻ കഴിയുന്നതിനായി ഒട്ടിച്ച അസംസ്കൃത സ്ട്രിംഗ് മാറ്റമില്ലാതെ ഫോർവേഡ് ചെയ്യപ്പെടുന്നു.

### മോഡൽ ഐഡികൾ

| മോഡൽ ഐഡി    | പ്രദർശന നാമം | കുറിപ്പുകൾ                                                      |
| ----------- | ------------ | --------------------------------------------------------------- |
| `notrack-c` | NoTrack C    | ഡിഫോൾട്ട് — അപ്സ്ട്രീം ഡിസ്പാച്ച് മോഡൽ `C`.                     |
| `C`         | NoTrack C    | `notrack-c`-ന്റെ അപരനാമം (അസംസ്കൃത അപ്സ്ട്രീം ഡിസ്പാച്ച് കോഡ്). |
| `notrack`   | NoTrack C    | `notrack-c`-ന്റെ അപരനാമം.                                       |
| `ntw`       | NoTrack C    | `notrack-c`-ന്റെ ഹ്രസ്വ അപരനാമം.                                |

നാല് മോഡൽ ഐഡികളും ഒരേ അപ്സ്ട്രീം ഡിസ്പാച്ച് മോഡലിലേക്കാണ് (`C`) മാപ്പ് ചെയ്യുന്നത്.

### അഭ്യർത്ഥനാ ഓപ്ഷനുകൾ

അഭ്യർത്ഥനാ ബോഡിയിൽ എക്സിക്യൂട്ടർ ഇനിപ്പറയുന്ന ഐച്ഛിക ഫീൽഡുകൾ സ്വീകരിക്കുന്നു:

| ബോഡി ഫീൽഡ്            | ഡിഫോൾട്ട് | ഉദ്ദേശ്യം                                                                                        |
| --------------------- | --------- | ------------------------------------------------------------------------------------------------ |
| `notrack_mode`        | `usual`   | ഡിസ്പാച്ച് മോഡ് (സ്വതന്ത്ര രൂപത്തിലുള്ള സ്ട്രിംഗ്; അപ്സ്ട്രീം `usual`, … എന്നിവ സ്വീകരിക്കുന്നു) |
| `notrack_max_turns`   | `6`       | മറുപടി നൽകുന്നതിന് മുമ്പ് അപ്സ്ട്രീമിന് നടത്താവുന്ന ആന്തരിക ടേണുകളുടെ എണ്ണം.                     |
| `notrack_chat_id`     | `null`    | നിലവിലുള്ള ഒരു അപ്സ്ട്രീം ചാറ്റ് പുനരാരംഭിക്കുക (പുതിയ ചാറ്റിനായി ഒഴിവാക്കുക).                   |
| `notrack_attachments` | `[]`      | അപ്സ്ട്രീം അറ്റാച്ച്മെന്റ് ഡിസ്ക്രിപ്റ്ററുകളുടെ പാസ്-ത്രൂ അറേ.                                   |
| `notrack_regenerate`  | `false`   | മുമ്പത്തെ ടേണിന് പുനഃസൃഷ്ടിച്ച മറുപടി അഭ്യർത്ഥിക്കാൻ `true` ആയി സജ്ജമാക്കുക.                     |

### ശേഷികൾ

- **സ്ട്രീമിംഗും നോൺ-സ്ട്രീമിംഗും** ആയ ചാറ്റ് കംപ്ലീഷനുകൾ.
- **ടൂൾ കോളിംഗ്** — അഭ്യർത്ഥനയിൽ `tools: [...]` സജ്ജമാക്കുക; എക്സിക്യൂട്ടർ അവയെ ഒരു ടൂൾ-കോൾ എൻവലപ്പ് കോൺട്രാക്റ്റിലേക്ക് സീരിയലൈസ് ചെയ്യുകയും മോഡലിന്റെ പ്രതികരണങ്ങൾ വീണ്ടും OpenAI `tool_calls` ആയി പാർസ് ചെയ്യുകയും ചെയ്യുന്നു.
- **`response_format`** — `json_object`, `json_schema` എന്നിവ പിന്തുണയ്ക്കുന്നു. എക്സിക്യൂട്ടർ മോഡലിന്റെ മറുപടിയിൽ നിന്ന് ആദ്യത്തെ JSON ഒബ്ജക്റ്റ് വേർതിരിച്ചെടുത്ത് തിരികെ നൽകുന്നതിന് മുമ്പ് അതിനെ സ്ട്രിംഗാക്കി മാറ്റുന്നു.
- **റീസണിംഗ് സൂചന** — അപ്സ്ട്രീം ഒരു `thinking` ഇവന്റ് അയയ്ക്കുമ്പോൾ എക്സിക്യൂട്ടർ ഒരു `reasoning` ഡെൽറ്റ പുറപ്പെടുവിക്കുന്നു.

### പരിമിതികൾ

- അപ്സ്ട്രീം അജ്ഞാത ഉപയോഗ ക്വാട്ടകൾ നിർബന്ധമാക്കുന്നു — പരിധി കടക്കുമ്പോൾ, സൗഹൃദപരമായ ഒരു സന്ദേശത്തോടൊപ്പം എക്സിക്യൂട്ടർ 429 പിശക് പ്രദർശിപ്പിക്കുന്നു.
- എല്ലാ മോഡൽ ഐഡികളും ഒരേ അപ്സ്ട്രീം ഡിസ്പാച്ച് മോഡലിലേക്കാണ് പരിഹരിക്കപ്പെടുന്നത്; ഓരോ മോഡലിനും പ്രത്യേകം സ്വിച്ച് ഇല്ല.
- എക്സിക്യൂട്ടർ അപ്സ്ട്രീമിന്റെ `/api/chats` എൻഡ്പോയിന്റ് വിളിക്കാത്തതിനാൽ, ചാറ്റ് ചരിത്രം / സെഷനുകൾ സ്വയമേവ മാനേജ് ചെയ്യപ്പെടുന്നില്ല. നിലവിലുള്ള ഒരു അപ്സ്ട്രീം ചാറ്റ് പുനരാരംഭിക്കാൻ `notrack_chat_id` ഉപയോഗിക്കുക.

# വെബ് കുക്കി പ്രൊവൈഡർമാർക്ക് ചെയ്യാൻ കഴിയുന്നതും കഴിയാത്തതും

വെബ് കുക്കി പ്രൊവൈഡർമാർ ഒരു വെബ്സൈറ്റിന്റെ ചാറ്റ് ഇന്റർഫേസ് പുനരുപയോഗിക്കുന്നു. അവ ഔദ്യോഗിക API-കളുടെ അതേ ശേഷികൾ നൽകുന്നില്ല.

## പിന്തുണയ്ക്കുന്നവ

- നിലവിലുള്ള ബ്രൗസർ സെഷൻ ഉപയോഗിച്ച് പ്രാമാണീകരിക്കുക
- നിങ്ങളുടെ അക്കൗണ്ടിലൂടെ ലഭ്യമായ മോഡലുകൾ ആക്സസ് ചെയ്യുക
- ചാറ്റ് പ്രതികരണങ്ങൾ സ്ട്രീം ചെയ്യുക
- API കീ ആവശ്യമില്ല

## പിന്തുണയ്ക്കാത്തവ

- ഫങ്ഷൻ കോളിംഗ്
- ടൂൾ കോളിംഗ്
- സ്വയമേവയുള്ള ഫയൽ എഡിറ്റിംഗ്
- ഏജന്റിക് IDE വർക്ക്ഫ്ലോകൾ
- API-യിൽ മാത്രം ലഭ്യമായ സവിശേഷതകൾ

ഇത് പ്രതീക്ഷിക്കുന്ന പെരുമാറ്റമാണ്, ഇത് ഒരു ബഗ് **അല്ല**.

ടൂൾ എക്സിക്യൂഷൻ, സ്വയമേവയുള്ള ഫയൽ എഡിറ്റിംഗ്, അല്ലെങ്കിൽ മറ്റ് ഏജന്റ് വർക്ക്ഫ്ലോകൾ ആവശ്യമാണെങ്കിൽ, Web Cookie ദാതാവിന് പകരം ഒരു **API-key provider** ഉപയോഗിക്കുക.

# സാധൂകരണ മുന്നറിയിപ്പ്

വിജയകരമായ **Test Connection** അല്ലെങ്കിൽ കുക്കി സാധൂകരണം, നൽകിയ ക്രെഡൻഷ്യലുകൾ പ്രതീക്ഷിച്ച ഫോർമാറ്റിലാണെന്ന് തോന്നുന്നു എന്നത് മാത്രമാണ് സ്ഥിരീകരിക്കുന്നത്.

Issue #7857 പരിഹരിക്കപ്പെടുന്നതുവരെ, വിജയകരമായ സാധൂകരണം ദാതാവിന് വിജയകരമായി പ്രാമാണീകരിക്കാൻ കഴിയുമെന്ന് **ഉറപ്പുനൽകുന്നില്ല**.

പ്രാമാണീകരണം തുടർന്നും പരാജയപ്പെടുകയാണെങ്കിൽ, ബ്രൗസറിലെ കുക്കി സ്റ്റോറേജിൽ നിന്നല്ല, സജീവമായ ഒരു നെറ്റ്വർക്ക് അഭ്യർത്ഥനയിൽ നിന്നാണ് ക്രെഡൻഷ്യലുകൾ പകർത്തിയതെന്ന് ഉറപ്പാക്കുക.

# പ്രശ്നപരിഹാരം

## പ്രാമാണീകരണം പരാജയപ്പെടുന്നു

ക്രെഡൻഷ്യലുകൾ ഇനിപ്പറയുന്നിടത്തുനിന്നാണ് പകർത്തിയതെന്ന് ഉറപ്പാക്കുക:

```
Network
→ Request Headers
→ Cookie
```

ഇനിപ്പറയുന്നിടത്തുനിന്ന് **അല്ല**:

```
Application
→ Cookies
```

## കുക്കി ബ്രൗസറിൽ പ്രവർത്തിക്കുന്നു, പക്ഷേ OmniRoute-ൽ പ്രവർത്തിക്കുന്നില്ല

ചില ദാതാക്കൾ പ്രാമാണീകരിച്ച അഭ്യർത്ഥനകളിൽ മാത്രം അയയ്ക്കുന്ന കുക്കികൾ ഉൾപ്പെടുത്തുന്നു.

ഒരു സംഭാഷണം വിജയകരമായി തുറന്നതിന് ശേഷം പുതിയൊരു നെറ്റ്വർക്ക് അഭ്യർത്ഥനയിൽനിന്ന് ക്രെഡൻഷ്യലുകൾ വീണ്ടും പകർത്തുക.

## സെഷൻ കാലഹരണപ്പെട്ടു

Web Cookie ദാതാക്കൾ നിങ്ങളുടെ നിലവിലുള്ള ബ്രൗസർ സെഷൻ ഉപയോഗിക്കുന്നു.

നിങ്ങളുടെ ബ്രൗസർ സെഷൻ കാലഹരണപ്പെടുകയോ നിങ്ങൾ സൈൻ ഔട്ട് ചെയ്യുകയോ ചെയ്താൽ, പുതിയൊരു സെറ്റ് ക്രെഡൻഷ്യലുകൾ പകർത്തണം. പിന്തുണയ്ക്കുന്ന വെബ് ദാതാക്കൾക്കായി കുക്കി പുതുക്കൽ സ്വയമേവ നടത്തുന്നതിന്, [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md) അനുബന്ധ ടൂൾ കാണുക.

# മികച്ച രീതികൾ

- പുതിയൊരു പ്രാമാണീകരിച്ച അഭ്യർത്ഥനയിൽനിന്ന് ക്രെഡൻഷ്യലുകൾ പകർത്തുക.

- Web Cookie ദാതാക്കളെ ഉപയോഗിക്കുമ്പോൾ നിങ്ങളുടെ ബ്രൗസർ സെഷൻ സജീവമായി നിലനിർത്തുക.
- പകർത്തിയ കുക്കികളെ അതീവ രഹസ്യമായ ക്രെഡൻഷ്യലുകളായി പരിഗണിക്കുക.
- ഫങ്ഷൻ കോളിംഗ് അല്ലെങ്കിൽ ഏജന്റ് വർക്ക്ഫ്ലോകൾ ആവശ്യമുള്ളപ്പോൾ API-key ദാതാക്കളെ ഉപയോഗിക്കുക.
