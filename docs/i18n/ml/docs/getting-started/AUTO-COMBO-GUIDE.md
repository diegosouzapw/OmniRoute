> **TL;DR**: നിങ്ങളുടെ മോഡൽ `auto` ആയി സജ്ജീകരിക്കുക; ഓരോ അഭ്യർത്ഥനയ്ക്കും ഏറ്റവും അനുയോജ്യമായ AI ദാതാവിനെ OmniRoute സ്വയമേവ തിരഞ്ഞെടുക്കും. കോൺഫിഗറേഷൻ ആവശ്യമില്ല.

---

## ഇത് എന്താണ് ചെയ്യുന്നത്

ഒരു നിർദ്ദിഷ്ട AI മോഡൽ (GPT-4o അല്ലെങ്കിൽ Claude പോലുള്ളത്) തിരഞ്ഞെടുക്കുന്നതിനുപകരം, ഓരോ അഭ്യർത്ഥനയ്ക്കും **ഏറ്റവും മികച്ചത് സ്വയമേവ തിരഞ്ഞെടുക്കാൻ** OmniRoute-നെ അനുവദിക്കാം. ഇത് പരിഗണിക്കുന്ന ഘടകങ്ങൾ:

- **പ്രവർത്തനക്ഷമത** — ദാതാവ് ഇപ്പോൾ പ്രവർത്തിക്കുന്നുണ്ടോ?
- **വേഗത** — ഇത് എത്ര വേഗത്തിലാണ്?
- **ചെലവ്** — ഇതിന് എത്ര ചെലവാകും?
- **ഗുണനിലവാരം** — ഈ തരത്തിലുള്ള ടാസ്കിൽ ഇത് മികച്ചതാണോ?
- **ശേഷി** — ഇതിന് ശേഷിക്കുന്ന ക്വോട്ടയുണ്ടോ?

നിങ്ങൾ ബന്ധിപ്പിച്ചിട്ടുള്ള എല്ലാ ദാതാക്കൾക്കും OmniRoute സ്കോർ നൽകുകയും ഏറ്റവും മികച്ചത് തിരഞ്ഞെടുക്കുകയും ചെയ്യുന്നു. അത് പരാജയപ്പെട്ടാൽ, അടുത്തത് സ്വയമേവ പരീക്ഷിക്കും.

## വേഗത്തിൽ ആരംഭിക്കുക

**ഘട്ടം 1**: നിങ്ങളുടെ IDE അല്ലെങ്കിൽ CLI-യിൽ മോഡൽ `auto` ആയി സജ്ജീകരിക്കുക:

```
model: "auto"
```

**ഘട്ടം 2**: അത്ര മാത്രം! ബാക്കിയുള്ളതെല്ലാം OmniRoute കൈകാര്യം ചെയ്യും.

**ഘട്ടം 3** (ഐച്ഛികം): നിർദ്ദിഷ്ട ടാസ്കുകൾക്കായി ഒരു വേരിയന്റ് ഉപയോഗിക്കുക:

```
model: "auto/coding"    # കോഡിന് ഏറ്റവും മികച്ചത്
model: "auto/fast"      # ഏറ്റവും വേഗത്തിലുള്ള പ്രതികരണം
model: "auto/cheap"     # ഏറ്റവും ചെലവ് കുറഞ്ഞ ഓപ്ഷൻ
```

## ഏത് "auto" ആണ് ഞാൻ ഉപയോഗിക്കേണ്ടത്?

| നിങ്ങൾക്ക് വേണ്ടത്...              | ഇത് ഉപയോഗിക്കുക | ഏറ്റവും അനുയോജ്യം                        | ഇത് എങ്ങനെ പ്രവർത്തിക്കുന്നു                           |
| ---------------------------------- | --------------- | ---------------------------------------- | ------------------------------------------------------ |
| **മൊത്തത്തിൽ ഏറ്റവും മികച്ചത്**    | `auto`          | പൊതുവായ ചോദ്യങ്ങൾ, ചാറ്റ്                | വേഗത, ചെലവ്, ഗുണനിലവാരം എന്നിവ സന്തുലിതമാക്കുന്നു      |
| **കോഡിന് ഏറ്റവും മികച്ചത്**        | `auto/coding`   | കോഡ് എഴുതൽ, ഡീബഗ്ഗിങ്                    | കോഡിങ് ടാസ്കുകളിൽ മികച്ച മോഡലുകൾ തിരഞ്ഞെടുക്കുന്നു     |
| **ഏറ്റവും വേഗത്തിലുള്ള പ്രതികരണം** | `auto/fast`     | പെട്ടെന്നുള്ള ഉത്തരങ്ങൾ, കുറഞ്ഞ ലേറ്റൻസി | മറ്റെല്ലാറ്റിനേക്കാളും വേഗതയ്ക്ക് മുൻഗണന നൽകുന്നു      |
| **ഏറ്റവും ചെലവ് കുറഞ്ഞ ഓപ്ഷൻ**     | `auto/cheap`    | പണം ലാഭിക്കൽ                             | ഏറ്റവും ചെലവ് കുറഞ്ഞ ദാതാവിനെ തിരഞ്ഞെടുക്കുന്നു        |
| **ഏറ്റവും ബുദ്ധിശാലിയായ മോഡൽ**     | `auto/smart`    | സങ്കീർണ്ണമായ ടാസ്കുകൾ                    | ഗുണനിലവാരത്തിന് മുൻഗണന + പുതിയ മോഡലുകൾ പരീക്ഷിക്കുന്നു |
| **ഏറ്റവും ലഭ്യമായത്**              | `auto/offline`  | ദാതാക്കൾ തിരക്കിലായിരിക്കുമ്പോൾ          | ഏറ്റവും കൂടുതൽ ശേഷിയുള്ള ദാതാക്കളെ തിരഞ്ഞെടുക്കുന്നു   |

## ഇത് എങ്ങനെ പ്രവർത്തിക്കുന്നു (ലളിതമായ പതിപ്പ്)

`model: "auto"` ഉപയോഗിച്ച് നിങ്ങൾ ഒരു അഭ്യർത്ഥന അയയ്ക്കുമ്പോൾ, OmniRoute:

1. **നിങ്ങൾ ബന്ധിപ്പിച്ചിട്ടുള്ള എല്ലാ ദാതാക്കളെയും പരിശോധിക്കുന്നു** — നിങ്ങൾ ചേർത്തിട്ടുള്ള ഓരോ ദാതാവും (OpenAI, Anthropic, Google തുടങ്ങിയവ)
2. **ഓരോന്നിനും സ്കോർ നൽകുന്നു**, മറ്റ് കാര്യങ്ങൾക്കൊപ്പം ഇനിപ്പറയുന്നവയ്ക്കും പ്രാധാന്യം നൽകുന്നു:
   - ഇത് പ്രവർത്തിക്കുന്നുണ്ടോ? (പ്രവർത്തനക്ഷമത)
   - ഇതിന് ശേഷിയുണ്ടോ? (ക്വോട്ട)
   - ഇതിന് എത്ര ചെലവാകും? (വില)
   - ഇത് എത്ര വേഗത്തിലാണ്? (വേഗത)
   - ഈ ടാസ്കിൽ ഇത് മികച്ചതാണോ? (ഗുണനിലവാരം)
3. **ഏറ്റവും മികച്ചത് തിരഞ്ഞെടുക്കുന്നു** — ഏറ്റവും ഉയർന്ന സ്കോറുള്ള ദാതാവിന് നിങ്ങളുടെ അഭ്യർത്ഥന ലഭിക്കുന്നു
4. **സ്വയമേവ വീണ്ടെടുക്കുന്നു** — അത് പരാജയപ്പെട്ടാൽ, OmniRoute അടുത്തത് സ്വയമേവ പരീക്ഷിക്കുന്നു

### സ്കോറിങ് സംവിധാനം

ഓരോ ദാതാവിനും 0 മുതൽ 1 വരെ ഒരു സ്കോർ ലഭിക്കുന്നു. സ്കോർ ഉയരുന്തോറും അനുയോജ്യതയും മെച്ചപ്പെടുന്നു.

| ഘടകം             | പ്രാധാന്യം | അതിന്റെ അർത്ഥം                                            |
| ---------------- | ---------- | --------------------------------------------------------- |
| പ്രവർത്തനക്ഷമത   | 20%        | ദാതാവ് പ്രവർത്തിക്കുന്നുണ്ടോ? (സർക്യൂട്ട് ബ്രേക്കർ അവസ്ഥ) |
| ക്വോട്ട          | 15%        | ഇതിന് ശേഷിക്കുന്ന ശേഷിയുണ്ടോ?                             |
| ചെലവ്            | 15%        | ഇതിന് എത്ര ചെലവാകും? (ചെലവ് കുറയുമ്പോൾ സ്കോർ ഉയരും)       |
| വേഗത             | 12%        | ഇത് എത്ര വേഗത്തിലാണ്? (ലേറ്റൻസി കുറയുമ്പോൾ സ്കോർ ഉയരും)   |
| ടാസ്ക് അനുയോജ്യത | 8%         | ഈ തരത്തിലുള്ള ടാസ്കിൽ ഇത് മികച്ചതാണോ?                     |
| സ്ഥിരത           | 5%         | ഇത് സ്ഥിരതയുള്ളതാണോ? (കുറഞ്ഞ പിശക് നിരക്ക്)               |
| ടയർ              | 5%         | അക്കൗണ്ട് ടയർ (Ultra > Pro > Free)                        |
| മറ്റുള്ളവ        | 20%        | കോൺടെക്സ്റ്റ് അഫിനിറ്റി, കണക്ഷൻ സാന്ദ്രത തുടങ്ങിയവ        |

| `auto/offline` | ശേഷി                     | quota=37%, health=28%           |

## പരാജയങ്ങൾ എങ്ങനെ കൈകാര്യം ചെയ്യുന്നു

OmniRoute-ന് **മൂന്ന് തലത്തിലുള്ള പരിരക്ഷയുണ്ട്**:

### 1. സ്വയമേവയുള്ള ഫാൾബാക്ക്

മികച്ച പ്രൊവൈഡർ പരാജയപ്പെട്ടാൽ, OmniRoute സ്വയമേവ അടുത്ത പ്രൊവൈഡറെ പരീക്ഷിക്കുന്നു. നിങ്ങൾ ഒന്നും ചെയ്യേണ്ടതില്ല.

### 2. സ്വയം പരിഹരിക്കൽ

ഒരു പ്രൊവൈഡർ തുടർച്ചയായി പരാജയപ്പെടുകയാണെങ്കിൽ:

- **സ്കോർ < 0.2** → 5 മിനിറ്റ് നേരത്തേക്ക് ഒഴിവാക്കും
- **സർക്യൂട്ട് ബ്രേക്കർ തുറന്നിരിക്കുന്നു** → സ്വയമേവ ഒഴിവാക്കും
- **50%-ത്തിലധികം പ്രൊവൈഡർമാർ പ്രവർത്തനരഹിതം** → ഇൻസിഡന്റ് മോഡ് (പര്യവേക്ഷണമില്ല)

### 3. അടിയന്തര ഫാൾബാക്ക്

എല്ലാ പ്രൊവൈഡർമാരും പരാജയപ്പെട്ടാൽ, അവസാന ആശ്രയമായി OmniRoute അഭ്യർത്ഥനകളെ സ്ഥിരതയുള്ള സൗജന്യ പ്രൊവൈഡർമാരിലേക്ക് (Kiro അല്ലെങ്കിൽ Qoder പോലുള്ളവ) റൂട്ട് ചെയ്യുന്നു.

## ഒന്നിലധികം അക്കൗണ്ടുകൾക്കുള്ള പിന്തുണ

ഒരേ പ്രൊവൈഡറിനായി നിങ്ങൾക്ക് ഒന്നിലധികം അക്കൗണ്ടുകളുണ്ടെങ്കിൽ (ഉദാ., രണ്ട് OpenAI കീകൾ), OmniRoute ഓരോന്നിനെയും **വ്യത്യസ്ത കാൻഡിഡേറ്റായി** പരിഗണിക്കുന്നു. അതായത്:

- Account A-യിൽ ക്വാട്ട ശേഷിക്കുന്നു → അത് ഉപയോഗിക്കുക
- Account B നിരക്ക്-പരിമിതമാണ് → അത് ഒഴിവാക്കുക
- Account C ചെലവ് കുറഞ്ഞതാണ് → അതിന് മുൻഗണന നൽകുക

ഓരോ അക്കൗണ്ടിന്റെയും ആരോഗ്യം, ക്വാട്ട, വേഗത എന്നിവയെ അടിസ്ഥാനമാക്കി അവയ്ക്ക് പ്രത്യേകം സ്കോർ നൽകുന്നു.

---

## ബാൻഡിറ്റ് പര്യവേക്ഷണം

കൂടുതൽ മികച്ച ഓപ്ഷനുകൾ കണ്ടെത്താൻ OmniRoute ഇടയ്ക്കിടെ പുതിയ പ്രൊവൈഡർമാരെ **പര്യവേക്ഷണം ചെയ്യുന്നു**:

- **ഡിഫോൾട്ട്**: അഭ്യർത്ഥനകളിൽ 5% ക്രമരഹിത പ്രൊവൈഡർമാരിലേക്ക് പോകുന്നു
- **Auto/smart**: 10% പര്യവേക്ഷണ നിരക്ക്
- **പ്രവർത്തനരഹിതമാക്കും**: 50%-ത്തിലധികം പ്രൊവൈഡർമാർ അനാരോഗ്യകരമായിരിക്കുമ്പോൾ

നിങ്ങളുടെ ഉപയോഗരീതികൾക്ക് ഏറ്റവും നന്നായി പ്രവർത്തിക്കുന്ന പ്രൊവൈഡർമാർ ഏതൊക്കെയെന്ന് മനസ്സിലാക്കാൻ ഇത് OmniRoute-നെ സഹായിക്കുന്നു.

## സാധാരണ ചോദ്യങ്ങൾ

### "ഇത് എല്ലായ്പ്പോഴും ഏറ്റവും ചെലവേറിയ മോഡൽ തിരഞ്ഞെടുക്കുമോ?"

**ഇല്ല.** ഡിഫോൾട്ടായി ചെലവ് സ്കോറിന്റെ 15% മാത്രമാണ്. ചെലവ് കുറഞ്ഞതും വേഗതയുള്ളതും ആരോഗ്യകരവുമായ ഒരു പ്രൊവൈഡർക്ക് ചെലവേറിയ ഒന്നിനെ മറികടക്കാനാകും. ചെലവിന് കൂടുതൽ മുൻഗണന നൽകണമെങ്കിൽ `auto/cheap` ഉപയോഗിക്കുക.

### "ഒരു പ്രൊവൈഡർ പ്രവർത്തനരഹിതമായാൽ എന്ത് സംഭവിക്കും?"

OmniRoute സ്വയമേവ അതിനെ ഒഴിവാക്കി അടുത്തത് പരീക്ഷിക്കുന്നു. ഒരു പ്രൊവൈഡർ തുടർച്ചയായി പരാജയപ്പെടുകയാണെങ്കിൽ, അതിനെ താൽക്കാലികമായി (5-30 മിനിറ്റ്) ഒഴിവാക്കും. നിങ്ങൾ ഒന്നും ചെയ്യേണ്ടതില്ല.

### "ഏത് പ്രൊവൈഡറാണ് ഉപയോഗിച്ചതെന്ന് എനിക്ക് കാണാനാകുമോ?"

റെസ്പോൺസ് ഹെഡറുകൾ പരിശോധിക്കുക — ഓരോ പ്രതികരണത്തിലും ഉപയോഗിച്ച പ്രൊവൈഡറും മോഡലും OmniRoute ഉൾപ്പെടുത്തുന്നു.

### "ഇത് എന്റെ ഉപയോഗത്തിൽനിന്ന് പഠിക്കുമോ?"

അതെ! കാലക്രമേണ കൂടുതൽ മികച്ച തീരുമാനങ്ങളെടുക്കാൻ സ്കോറിംഗ് സിസ്റ്റം ചരിത്രപരമായ ഡാറ്റ (ലേറ്റൻസി, പിശക് നിരക്കുകൾ, വിജയ നിരക്കുകൾ) ഉപയോഗിക്കുന്നു.

### "`auto`-യും `auto/smart`-യും തമ്മിലുള്ള വ്യത്യാസമെന്താണ്?"

- `auto` — സന്തുലിതം, 5% പര്യവേക്ഷണം
- `auto/smart` — ഗുണനിലവാരത്തിന് പ്രഥമ പരിഗണന (`auto/coding`-ന്റെ അതേ വെയ്റ്റുകൾ), 10% പര്യവേക്ഷണം

നിങ്ങൾക്ക് മികച്ച ഗുണനിലവാരം വേണമെങ്കിൽ, ഇടയ്ക്കിടെയുള്ള പര്യവേക്ഷണം പ്രശ്നമല്ലെങ്കിൽ `auto/smart` ഉപയോഗിക്കുക.

### "ഒരു പ്രത്യേക പ്രൊവൈഡറെ നിർബന്ധമായി ഉപയോഗിക്കാനാകുമോ?"

അതെ! `auto`-യ്ക്ക് പകരം `priority` സ്ട്രാറ്റജിയുള്ള ഒരു കോംബോ ഉപയോഗിക്കുക, തുടർന്ന് കോംബോയുടെ **കൃത്യമായ പേര്** `model` ഫീൽഡായി അയയ്ക്കുക (ഉദാ. `model: "my-combo"` — `auto` അല്ല). വിശദാംശങ്ങൾക്ക് [സാങ്കേതിക റഫറൻസ്](../routing/AUTO-COMBO.md) കാണുക.

### "റൗണ്ട്-റോബിനിൽനിന്ന് ഇത് എങ്ങനെ വ്യത്യസ്തമാണ്?"

റൗണ്ട്-റോബിൻ ക്രമത്തിൽ പ്രൊവൈഡർമാരിലൂടെ ആവർത്തിച്ച് സഞ്ചരിക്കുന്നു. Auto-combo **ഓരോ പ്രൊവൈഡർക്കും സ്കോർ നൽകുകയും** ഏറ്റവും മികച്ചത് തിരഞ്ഞെടുക്കുകയും ചെയ്യുന്നു. ഇത് കൂടുതൽ ബുദ്ധിപരമാണ് — ആരോഗ്യം, വേഗത, ചെലവ്, ഗുണനിലവാരം എന്നിവ പരിഗണിക്കുന്നു.
