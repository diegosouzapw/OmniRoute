> **ചുരുക്കത്തിൽ**: ഒരു പ്രൊവൈഡർ എന്നത് ഒരു AI സേവനത്തിലേക്കുള്ള (OpenAI, Anthropic, Google എന്നിവ പോലുള്ള) കണക്ഷനാണ്. OmniRoute ഉപയോഗിക്കാൻ നിങ്ങൾക്ക് കുറഞ്ഞത് ഒരു പ്രൊവൈഡറെങ്കിലും ആവശ്യമാണ്.

## എന്താണ് ഒരു പ്രൊവൈഡർ?

ഒരു പ്രൊവൈഡറെ ഒരു **ഫോൺ കാരിയർ** പോലെ കരുതുക. കോളുകൾ ചെയ്യാൻ ഒരു ഫോൺ കാരിയർ ആവശ്യമായതുപോലെ, AI മോഡലുകൾ ഉപയോഗിക്കാൻ ഒരു AI പ്രൊവൈഡർ ആവശ്യമാണ്. **എല്ലാ കാരിയറുകളുമായും** പ്രവർത്തിക്കുന്ന ഒരു ഫോൺ പോലെയാണ് OmniRoute — അവയ്ക്കിടയിൽ നിങ്ങൾക്ക് സ്വയമേവ മാറാനാകും.

പൊതുവായ സജ്ജീകരണ നിർദ്ദേശങ്ങൾ, പരിമിതികൾ, പ്രശ്നപരിഹാരം, പ്രൊവൈഡർ-നിർദ്ദിഷ്ട പ്രാമാണീകരണ മാർഗ്ഗനിർദ്ദേശങ്ങൾ എന്നിവയ്ക്കായി **[WEB-COOKIE-GUIDE.md](./WEB-COOKIE-GUIDE.md)** കാണുക.

## ദ്രുതാരംഭം: നിങ്ങളുടെ ആദ്യ പ്രൊവൈഡറെ ബന്ധിപ്പിക്കുക

### ആദ്യ പ്രവർത്തനത്തിലെ ഐച്ഛിക സൗജന്യ-പ്രൊവൈഡർ സജ്ജീകരണം

ആദ്യ പ്രവർത്തന വിസാർഡ് വ്യക്തമായ ഒരു **സൗജന്യ പ്രൊവൈഡറുകൾ സജ്ജീകരിക്കുക** കാർഡ് നൽകുന്നു. OmniRoute-ന്റെ പ്രാമാണീകരണം ആവശ്യമില്ലാത്ത പ്രൊവൈഡർ രജിസ്ട്രിയിൽനിന്ന് നിലവിൽ യോഗ്യമായവയുടെ പട്ടിക ഇത് കണ്ടെത്തുന്നു; തുടർന്ന് സ്ഥിരീകരിക്കുന്നതിന് മുമ്പ് ഓരോ പ്രൊവൈഡറെയും അവലോകനം ചെയ്യാനും തിരഞ്ഞെടുപ്പ് ഒഴിവാക്കാനും നിങ്ങളെ അനുവദിക്കുന്നു. മൂന്നാം കക്ഷി നിബന്ധനകൾ, സ്വകാര്യത, ലഭ്യത, നിരക്ക് പരിധികൾ എന്നിവ ആദ്യം അവലോകനം ചെയ്യുന്നതിനായി OmniRoute പ്രൊവൈഡറുടെ ജാഗ്രതാ അറിയിപ്പും അതിന്റെ സൈറ്റിലേക്കുള്ള ലിങ്കും പ്രദർശിപ്പിക്കുന്നു.

ഈ നടപടി ഐച്ഛികമാണ്: വിസാർഡ് പൂർത്തിയാക്കുന്നത് ഒരിക്കലും നിശ്ശബ്ദമായി സൗജന്യ-പ്രൊവൈഡർ കണക്ഷനുകൾ സൃഷ്ടിക്കില്ല. ഇപ്പോഴും ഇല്ലാത്ത പ്രൊവൈഡറുകൾ മാത്രമാണ് ഇത് സൃഷ്ടിക്കുന്നത്, നിലവിലുള്ള ഇഷ്ടാനുസൃത കണക്ഷനുകൾ മാറ്റമില്ലാതെ നിലനിർത്തുന്നു, കൂടാതെ സൃഷ്ടിച്ചവ, ഇതിനകം കോൺഫിഗർ ചെയ്തവ, പരാജയപ്പെട്ടവ എന്നിവ ഓരോന്നായി റിപ്പോർട്ട് ചെയ്യുന്നു. ഭാഗിക ഫലത്തിനുശേഷം പരാജയപ്പെട്ടവ മാത്രം നിങ്ങൾക്ക് സുരക്ഷിതമായി വീണ്ടും ശ്രമിക്കാം.

### ഓപ്ഷൻ A: സൗജന്യ പ്രൊവൈഡർ (ക്രെഡിറ്റ് കാർഡ് ആവശ്യമില്ല)

1. `http://localhost:20128`-ൽ ഡാഷ്ബോർഡ് തുറക്കുക
2. **പ്രൊവൈഡറുകൾ** → **പ്രൊവൈഡർ ചേർക്കുക** എന്നതിലേക്ക് പോകുക
3. ഈ സൗജന്യ പ്രൊവൈഡറുകളിൽ ഒന്ന് തിരഞ്ഞെടുക്കുക:
   - **Kiro AI** — സൗജന്യ Claude മോഡലുകൾ (പ്രാമാണീകരണം ആവശ്യമില്ല)
   - **OpenCode Free** — സൗജന്യ GPT മോഡലുകൾ (പ്രാമാണീകരണം ആവശ്യമില്ല)
   - **Pollinations** — സൗജന്യ GPT-5, Claude, Gemini (കീ ആവശ്യമില്ല)
   - **LongCat** — 10M ടോക്കണുകൾ സൗജന്യം (ഒറ്റത്തവണ ഗ്രാന്റ്, അക്കൗണ്ടും KYC-യും ആവശ്യമാണ്)
   - **Cloudflare AI** — 50+ മോഡലുകൾ, പ്രതിദിനം 10K ന്യൂറോണുകൾ
   - **MLX Gemma 26B** — ലോക്കൽ Apple Silicon മോഡൽ (~38.5 tok/s, ~15.9GB RAM)
   - **MLX Qwen 3.8 27B** — ലോക്കൽ Apple Silicon മോഡൽ (~9.1 tok/s, ~13.1GB RAM)
4. **ബന്ധിപ്പിക്കുക** ക്ലിക്ക് ചെയ്യുക
5. പൂർത്തിയായി! ഇപ്പോൾ നിങ്ങൾക്ക് സൗജന്യ AI ആക്സസ് ലഭ്യമാണ്.

### ഓപ്ഷൻ B: API കീ പ്രൊവൈഡർ (പണമടയ്ക്കേണ്ടത്)

7. പൂർത്തിയായി! ഇപ്പോൾ നിങ്ങൾക്ക് ആ പ്രൊവൈഡറുടെ മോഡലുകളിലേക്കുള്ള ആക്സസ് ലഭ്യമാണ്.

### ഓപ്ഷൻ C: OAuth പ്രൊവൈഡർ (സബ്സ്ക്രിപ്ഷൻ)

### ഓപ്ഷൻ D: ലോക്കൽ MLX മോഡലുകൾ (Apple Silicon)

ഏകീകൃത മെമ്മറിയുള്ള Apple Silicon Mac-കൾക്കായി, `mlx-lm.server` വഴി പ്രവർത്തിക്കുന്ന ലോക്കൽ MLX മോഡലുകളെ സാധാരണ OpenAI-അനുയോജ്യ ലോക്കൽ പ്രൊവൈഡറുകളായി ബന്ധിപ്പിക്കുന്നതിനെ OmniRoute പിന്തുണയ്ക്കുന്നു.

#### മുൻവ്യവസ്ഥകൾ

- 24GB+ ഏകീകൃത മെമ്മറിയുള്ള **Apple Silicon Mac** (M1/M2/M3/M4) ശുപാർശ ചെയ്യുന്നു
- **uv** പാക്കേജ് മാനേജർ: `curl -LsSf https://astral.sh/uv/install.sh | sh`
- **mlx-lm**: `uv pip install mlx-lm`

#### ദ്രുതാരംഭം

1. **ഡിപെൻഡൻസികൾ ഇൻസ്റ്റാൾ ചെയ്യുക**:

   ```bash
   # ഇതിനകം ഇൻസ്റ്റാൾ ചെയ്തിട്ടില്ലെങ്കിൽ uv ഇൻസ്റ്റാൾ ചെയ്യുക
   curl -LsSf https://astral.sh/uv/install.sh | sh

   # mlx-lm ഇൻസ്റ്റാൾ ചെയ്യുക
   uv pip install mlx-lm
   ```

2. **MLX സെർവറുകൾ മാനുവലായി ആരംഭിക്കുക** (വ്യത്യസ്ത ടെർമിനലുകളിൽ):

   ```bash
   # ടെർമിനൽ 1: Gemma 4 26B A4B IT-QAT (പോർട്ട് 11435)
   uv run mlx_lm.server --model mlx-community/gemma-4-26B-A4B-it-qat-q4_0-mlx-aligned --port 11435 --host 127.0.0.1

   # ടെർമിനൽ 2: Qwen 3.8 27B MLX Mixed (പോർട്ട് 11436)
   uv run mlx_lm.server --model maglun/Qwen3.8-27B-MLX-Mixed-3.80bpw --port 11436 --host 127.0.0.1
   ```

3. **OmniRoute ഡാഷ്ബോർഡിൽ ബന്ധിപ്പിക്കുക**:
   - **പ്രൊവൈഡറുകൾ** → **പ്രൊവൈഡർ ചേർക്കുക** എന്നതിലേക്ക് പോകുക
   - **MLX Gemma 26B** അല്ലെങ്കിൽ **MLX Qwen 3.8 27B** തിരഞ്ഞെടുക്കുക
   - **ബന്ധിപ്പിക്കുക** ക്ലിക്ക് ചെയ്യുക (API കീ ആവശ്യമില്ല)

4. **OpenCode-നൊപ്പം ഉപയോഗിക്കുക**:
   ```bash
   # OmniRoute ഉപയോഗിക്കാൻ OpenCode കോൺഫിഗർ ചെയ്യുക
   opencode config set api.base_url http://localhost:20128/v1
   opencode config set api.key <your-omniroute-api-key>

   # MLX മോഡലുകൾ ഉപയോഗിക്കുക
   opencode run --model mlx-gemma/gemma-4-26b
   opencode run --model mlx-qwen/qwen3.8-27b
   ```

#### മെമ്മറി മാനേജ്മെന്റ്

**പ്രധാനം**: 24GB ഏകീകൃത മെമ്മറിയിൽ, ഒരേസമയം **ഒരു വലിയ MLX മോഡൽ മാത്രമേ പ്രവർത്തിപ്പിക്കാനാകൂ**.

- Gemma 26B: ~15.9GB പരമാവധി മെമ്മറി
- Qwen 3.8 27B: ~13.1GB പരമാവധി മെമ്മറി

നിങ്ങൾ ഇത് മാനുവലായി നിയന്ത്രിക്കണം:

- ഒരേസമയം ഒരു MLX സെർവർ മാത്രം പ്രവർത്തിപ്പിക്കുക, അല്ലെങ്കിൽ
- രണ്ടും വ്യത്യസ്ത മെഷീനുകളിൽ പ്രവർത്തിപ്പിക്കുക, അല്ലെങ്കിൽ
- മറ്റൊന്ന് ആരംഭിക്കുന്നതിന് മുമ്പ് ഒന്ന് നിർത്തുക

OmniRoute MLX സെർവർ പ്രോസസ്സുകളെ സ്വയമേവ നിയന്ത്രിക്കുന്നില്ല — നിങ്ങൾ കോൺഫിഗർ ചെയ്യുന്ന OpenAI-അനുയോജ്യ എൻഡ്പോയിന്റുകളിലേക്ക് അഭ്യർത്ഥനകൾ റൂട്ട് ചെയ്യുക മാത്രമാണ് അത് ചെയ്യുന്നത്.

#### ടൂൾ കോളിംഗ് പിന്തുണ

രണ്ട് മോഡലുകളും OpenAI-അനുയോജ്യമായ ടൂൾ കോളിംഗ് പിന്തുണയ്ക്കുന്നു. ഇതുപയോഗിച്ച് പരിശോധിക്കുക:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "mlx-gemma/gemma-4-26b",
    "messages": [{"role": "user", "content": "What is 2+2? Use the calculator tool."}],
    "tools": [{"type": "function", "function": {"name": "calculator", "description": "Calculate", "parameters": {"type": "object", "properties": {"expression": {"type": "string"}}, "required": ["expression"]}}}]
  }'
```

## ഒരു ദാതാവിനെ എങ്ങനെ കണക്റ്റ് ചെയ്യാം (ഘട്ടം ഘട്ടമായി)

### ഘട്ടം 1: ഡാഷ്ബോർഡ് തുറക്കുക

നിങ്ങളുടെ ബ്രൗസറിൽ `http://localhost:20128` എന്നതിലേക്ക് പോകുക.

### ഘട്ടം 2: ദാതാക്കൾ എന്നതിലേക്ക് പോകുക

സൈഡ്ബാറിലെ **ദാതാക്കൾ** ക്ലിക്ക് ചെയ്യുക.

### ഘട്ടം 3: ദാതാവിനെ ചേർക്കുക ക്ലിക്ക് ചെയ്യുക

**+ ദാതാവിനെ ചേർക്കുക** ബട്ടൺ ക്ലിക്ക് ചെയ്യുക.

### ഘട്ടം 4: നിങ്ങളുടെ ദാതാവിനെ തിരഞ്ഞെടുക്കുക

പട്ടിക പരിശോധിക്കുകയോ നിങ്ങളുടെ ദാതാവിനായി തിരയുകയോ ചെയ്യുക. അതിൽ ക്ലിക്ക് ചെയ്യുക.

### ഘട്ടം 5: ക്രെഡൻഷ്യലുകൾ നൽകുക

- **സൗജന്യ ദാതാക്കൾ**: ക്രെഡൻഷ്യലുകൾ ആവശ്യമില്ല — **കണക്റ്റ് ചെയ്യുക** ക്ലിക്ക് ചെയ്താൽ മതി
- **API കീ ദാതാക്കൾ**: നിങ്ങളുടെ API കീ ഒട്ടിക്കുക
- **OAuth ദാതാക്കൾ**: **OAuth ഉപയോഗിച്ച് കണക്റ്റ് ചെയ്യുക** ക്ലിക്ക് ചെയ്ത് ലോഗിൻ ചെയ്യുക

### ഘട്ടം 6: കണക്ഷൻ പരിശോധിക്കുക

പ്രവർത്തിക്കുന്നുണ്ടെന്ന് സ്ഥിരീകരിക്കാൻ **കണക്ഷൻ പരിശോധിക്കുക** ക്ലിക്ക് ചെയ്യുക.

### ഘട്ടം 7: പൂർത്തിയായി!

നിങ്ങളുടെ ദാതാവ് ഇപ്പോൾ കണക്റ്റ് ചെയ്തിരിക്കുന്നു. `model: "auto"` ഉപയോഗിച്ചോ ദാതാവിനെ നേരിട്ട് വ്യക്തമാക്കിയോ നിങ്ങൾക്ക് ഇത് ഉപയോഗിക്കാം.

- **സ്വയമേവയുള്ള ഫാൾബാക്ക്** — ഒരു ദാതാവ് പരാജയപ്പെട്ടാൽ, OmniRoute അടുത്ത ദാതാവിനെ പരീക്ഷിക്കും
- **ചെലവ് ഒപ്റ്റിമൈസേഷൻ** — ഓരോ അഭ്യർത്ഥനയ്ക്കും ഏറ്റവും ചെലവ് കുറഞ്ഞ ദാതാവിനെ OmniRoute തിരഞ്ഞെടുക്കും
- **വേഗത ഒപ്റ്റിമൈസേഷൻ** — ഓരോ അഭ്യർത്ഥനയ്ക്കും ഏറ്റവും വേഗതയുള്ള ദാതാവിനെ OmniRoute തിരഞ്ഞെടുക്കും
- **ഗുണനിലവാര ഒപ്റ്റിമൈസേഷൻ** — ഓരോ ടാസ്കിനും ഏറ്റവും മികച്ച ദാതാവിനെ OmniRoute തിരഞ്ഞെടുക്കും

### Qoder: ക്രെഡൻഷ്യൽ ട്രാൻസ്പോർട്ട് തിരഞ്ഞെടുക്കുക

Qoder-ന് ക്രെഡൻഷ്യലുകൾ ആവശ്യമാണ്. അതിന്റെ രണ്ട് ട്രാൻസ്പോർട്ടുകൾക്കും വ്യത്യസ്ത ശേഷികളാണുള്ളത്; ഒരു മോഡൽ നാമം
മാത്രം ഉപയോഗിച്ച് ഒരു പ്രത്യേക കണക്ഷന് എന്തെല്ലാം ചെയ്യാനാകുമെന്ന് തിരിച്ചറിയാനാവില്ല.

| ക്രെഡൻഷ്യൽ                                   | OmniRoute ട്രാൻസ്പോർട്ട്                       | കോളർ ടൂൾ കോളിംഗ്                                                 | സ്ട്രീമിംഗ്                                                              |
| -------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `pt-` എന്നതിൽ ആരംഭിക്കുന്ന PAT               | OmniRoute ഹോസ്റ്റിലെ ലോക്കൽ `qodercli` പ്രോസസ് | പിന്തുണയ്ക്കുന്നില്ല                                             | ബഫർ ചെയ്തത്: CLI പൂർണ്ണ മറുപടി നൽകിയതിനുശേഷം മാത്രമേ SSE പുറപ്പെടുവിക്കൂ |
| PAT അല്ലാത്ത ആക്സസ് ടോക്കൺ അല്ലെങ്കിൽ API കീ | DashScope OpenAI-അനുയോജ്യമായ HTTP എൻഡ്പോയിന്റ് | അപ്സ്ട്രീം മോഡൽ/കീയുടെ വ്യവസ്ഥകൾക്ക് വിധേയമായി അതേപടി കൈമാറുന്നു | അപ്സ്ട്രീം HTTP/SSE പാത                                                  |

ഒരു PAT-യ്ക്കായി, OmniRoute പ്രവർത്തിക്കുന്ന അതേ ഹോസ്റ്റിലോ കണ്ടെയ്നറിലോ Qoder CLI ഇൻസ്റ്റാൾ ചെയ്യുക. എക്സിക്യൂട്ടബിൾ
`qodercli` ആയി കണ്ടെത്താനാകണം, അല്ലെങ്കിൽ അതിന്റെ എക്സിക്യൂട്ടബിൾ പാതയായി `CLI_QODER_BIN` സജ്ജമാക്കുക. Docker ഹോസ്റ്റിൽ
മാത്രം ഇൻസ്റ്റാൾ ചെയ്ത CLI കണ്ടെയ്നറിൽ സ്വയമേവ ലഭ്യമാകില്ല. ബൈനറികൾ ലഭ്യമല്ലെങ്കിൽ,
ഇൻസ്റ്റാളേഷനിലേക്കോ പാതാ ക്രമീകരണത്തിലേക്കോ നിങ്ങളെ നയിക്കുന്ന വ്യക്തമായ ഒരു പിശക് ലഭിക്കും.

PAT ചാറ്റ് പാതയ്ക്ക് 45 സെക്കൻഡ് പ്രോസസ് സമയപരിധിയുണ്ട്. ഇത് സംഭാഷണത്തെ ഒരു
പ്രോംപ്റ്റാക്കി ഏകീകരിച്ച്, സ്ട്രീമിംഗ് അല്ലാത്ത പ്രിന്റ് മോഡിൽ CLI പ്രവർത്തിപ്പിക്കുന്നു. `stream: true` അഭ്യർത്ഥിക്കുന്നത്
പ്രതികരണ എൻവലപ്പ് SSE ആക്കി മാറ്റുന്നു; ഇത് അപ്സ്ട്രീം ടോക്കണുകളുടെ ഘട്ടംഘട്ടമായ ഡെലിവറി നൽകുന്നില്ല.
CLI സാധൂകരണം/മോഡൽ ലിസ്റ്റിംഗ് വേറിട്ട 20 സെക്കൻഡ് സമയപരിധിയാണ് ഉപയോഗിക്കുന്നത്. ഇവ നിലവിലെ കോഡ്
സ്ഥിരസ്ഥിതികളാണ്, കോൺഫിഗർ ചെയ്യാവുന്ന ഡാഷ്ബോർഡ് ക്രമീകരണങ്ങളല്ല.

സാധാരണ ചാറ്റിനായി PAT കണക്ഷനുകൾ ഉപയോഗിക്കുക. `tools` അല്ലെങ്കിൽ പഴയ `functions`
ഉൾക്കൊള്ളുന്ന ഏജന്റ് അഭ്യർത്ഥനകൾ, പിൻ ചെയ്ത കോംബോ ടാർഗെറ്റുകൾ ഉൾപ്പെടെ, ക്രെഡൻഷ്യൽ തിരഞ്ഞെടുക്കുമ്പോൾ PAT അക്കൗണ്ടുകളെ
ഒഴിവാക്കുന്നു. സമ്മിശ്ര Qoder പൂളിന് ഇപ്പോഴും അതിന്റെ HTTP അക്കൗണ്ട് തിരഞ്ഞെടുക്കാനാകും. PAT എക്സിക്യൂട്ടറിലേക്കുള്ള നേരിട്ടുള്ള കോളുകളും
ടൂൾ നിർവചനങ്ങൾ നിശ്ശബ്ദമായി ഒഴിവാക്കുന്നതിന് പകരം CLI പ്രവർത്തിപ്പിക്കുന്നതിന് മുമ്പ് വ്യക്തമായി പരാജയപ്പെടും. ഈ
നിയന്ത്രണം API കോളർ നൽകുന്ന ടൂളുകളെയാണ് ബാധിക്കുന്നത്, Qoder
CLI തന്നെ ആന്തരികമായി ഉപയോഗിച്ചേക്കാവുന്ന ടൂളുകളെയല്ല. ഒരു HTTP കീ എല്ലാ മോഡലുകളും ടൂളുകളെ പിന്തുണയ്ക്കുമെന്ന് ഉറപ്പുനൽകുന്നില്ല; സാധാരണ
മോഡൽ ശേഷി പരിശോധനകൾ തുടർന്നും ബാധകമാണ്.

അഡ്മിനിസ്ട്രേറ്റർ അഞ്ച് ക്രമീകരണങ്ങളും കോൺഫിഗർ ചെയ്യുമ്പോൾ മാത്രമേ ബ്രൗസർ OAuth ലഭ്യമാകൂ:
`QODER_OAUTH_AUTHORIZE_URL`, `QODER_OAUTH_TOKEN_URL`, `QODER_OAUTH_USERINFO_URL`,
`QODER_OAUTH_CLIENT_ID`, കൂടാതെ `QODER_OAUTH_CLIENT_SECRET`. അവയുടെ സ്ഥിരസ്ഥിതി ശൂന്യമാണ്; കോൺഫിഗർ ചെയ്യാത്ത
ഇൻസ്റ്റാളേഷൻ, ബ്രൗസർ സൈൻ-ഇൻ പ്രവാഹം തയ്യാറാണെന്ന് അനുമാനിക്കുന്നതിന് പകരം പിന്തുണയ്ക്കുന്ന ഒരു ക്രെഡൻഷ്യൽ ഇമ്പോർട്ട് ഉപയോഗിക്കണം.

നിർവഹണ റഫറൻസുകൾ: [Qoder എക്സിക്യൂട്ടർ](../../open-sse/executors/qoder.ts),
[CLI റൺടൈം](../../open-sse/services/qoderCli.ts), കൂടാതെ
[OAuth കോൺഫിഗറേഷൻ](../../src/lib/oauth/constants/oauth.ts). ഘട്ടംഘട്ടമായ PAT സ്ട്രീമിംഗും
കോൺഫിഗർ ചെയ്യാവുന്ന സമയപരിധിയും വേറിട്ട മെച്ചപ്പെടുത്തലുകളാണ്; ഈ പ്രവർത്തനം അവ വാഗ്ദാനം ചെയ്യുന്നില്ല.

## പൊതുവായ ചോദ്യങ്ങൾ

### "OmniRoute ഉപയോഗിക്കാൻ ഞാൻ പണം നൽകേണ്ടതുണ്ടോ?"

**ഇല്ല!** OmniRoute സൗജന്യവും ഓപ്പൺ സോഴ്സുമാണ്. ഒന്നും പണം നൽകാതെ നിങ്ങൾക്ക് സൗജന്യ പ്രൊവൈഡറുകൾ (Kiro, OpenCode Free, Pollinations) ഉപയോഗിക്കാം. പണമടച്ചുള്ള പ്രൊവൈഡറുകൾ ഉപയോഗിക്കാൻ നിങ്ങൾ തീരുമാനിച്ചാൽ മാത്രമേ പണം നൽകേണ്ടതുള്ളൂ.

### "ഏത് പ്രൊവൈഡർ ഉപയോഗിച്ചാണ് ഞാൻ തുടങ്ങേണ്ടത്?"

**Kiro AI** ഉപയോഗിച്ച് തുടങ്ങുക — ഇത് സൗജന്യമാണ്, API കീ ആവശ്യമില്ല, കൂടാതെ Claude മോഡലുകളിലേക്ക് നിങ്ങൾക്ക് ആക്സസ് നൽകുന്നു. തുടർന്ന് ആവശ്യാനുസരണം കൂടുതൽ പ്രൊവൈഡറുകളെ ചേർക്കുക.

### "ഒരേസമയം ഒന്നിലധികം പ്രൊവൈഡറുകൾ ഉപയോഗിക്കാനാകുമോ?"

**അതെ!** അതാണ് OmniRoute-ന്റെ മുഴുവൻ ഉദ്ദേശ്യം. ഒന്നിലധികം പ്രൊവൈഡറുകളെ കണക്റ്റ് ചെയ്ത് ഓരോ അഭ്യർത്ഥനയ്ക്കും ഏറ്റവും മികച്ചത് തിരഞ്ഞെടുക്കാൻ OmniRoute-നെ അനുവദിക്കുന്നതിന് `model: "auto"` ഉപയോഗിക്കുക.

### "ഒരു പ്രൊവൈഡർ പ്രവർത്തനരഹിതമായാൽ എന്ത് സംഭവിക്കും?"

പരാജയപ്പെട്ട പ്രൊവൈഡറുകളെ OmniRoute സ്വയമേവ ഒഴിവാക്കി അടുത്തത് പരീക്ഷിക്കുന്നു. നിങ്ങൾ ഒന്നും ചെയ്യേണ്ടതില്ല.

### "ഒരു പ്രൊവൈഡറെ എങ്ങനെ വിച്ഛേദിക്കാം?"

പ്രൊവൈഡറുകൾ എന്നതിലേക്ക് പോകുക → പ്രൊവൈഡറിൽ ക്ലിക്ക് ചെയ്യുക → **വിച്ഛേദിക്കുക** എന്നതിൽ ക്ലിക്ക് ചെയ്യുക.

### "എന്റെ നിലവിലുള്ള API കീകൾ ഉപയോഗിക്കാനാകുമോ?"

**അതെ!** OpenAI, Anthropic, Google തുടങ്ങിയവയ്ക്കുള്ള API കീകൾ ഇതിനകം നിങ്ങളുടെ പക്കലുണ്ടെങ്കിൽ, അവ OmniRoute-ൽ ഉപയോഗിക്കാം. പ്രൊവൈഡറെ കണക്റ്റ് ചെയ്യുമ്പോൾ അവ പേസ്റ്റ് ചെയ്താൽ മതി.
