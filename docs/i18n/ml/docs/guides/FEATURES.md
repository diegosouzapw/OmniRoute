## ✨ v3.8.0 പ്രധാന സവിശേഷതകൾ

v3.7.x → v3.8.0 കാലയളവിൽ സീറോ-കോൺഫിഗ് ഓട്ടോ റൂട്ടിംഗ്, പുതിയ പ്രൊവൈഡറുകൾ, OAuth ഫ്ലോകൾ, കൂടുതൽ ആഴത്തിലുള്ള പ്രതിരോധശേഷി, ഏറെ സമ്പന്നമായ CLI അനുഭവം എന്നിവ ചേർത്തു. പ്രധാന സവിശേഷതകൾ താഴെ നൽകിയിരിക്കുന്നു — പൂർണ്ണ വിവരങ്ങൾ ഈ പ്രമാണത്തിൽ തുടർന്നും ലിങ്ക് ചെയ്തിരിക്കുന്ന സ്പെസിഫിക്കേഷനുകളിലും ലഭ്യമാണ്.

- 🤖 **ഓട്ടോ കോംബോ / സീറോ-കോൺഫിഗ് ഓട്ടോ-റൂട്ടിംഗ്** — `auto/coding`, `auto/fast`, `auto/cheap`, `auto/offline`, `auto/smart`, `auto/lkgp`, `auto/chaos` എന്നീ പ്രിഫിക്സുകൾ ഉപയോഗിക്കുക. 16-ഘടക സ്കോറിംഗ് എൻജിനും പ്രത്യേകം തയ്യാറാക്കിയ 6 **മോഡ് പാക്കുകളും** (ship-fast, cost-saver, quality-first, offline-friendly, reliability-first, chaos-mode) ഇതിന് പിന്തുണ നൽകുന്നു
- 🆕 **Command Code പ്രൊവൈഡർ** (#2199) — മോഡൽ കാറ്റലോഗും ക്വോട്ട ട്രാക്കിംഗും ഉൾപ്പെടുന്ന പൂർണ്ണ പിന്തുണയുള്ള രജിസ്ട്രേഷൻ
- 🆕 **Z.AI പ്രൊവൈഡർ** — ക്വോട്ട ലേബലുകളോടുകൂടിയ പുതിയ സൗജന്യ-ടയർ പ്രൊവൈഡർ
- 🎬 **KIE മീഡിയ വിപുലീകരണം** — വീഡിയോ ജനറേഷൻ മോഡലുകൾ ഉൾപ്പെടുന്ന വിപുലീകരിച്ച കാറ്റലോഗ്
- 🔐 **Devin ഓതന്റിക്കേഷൻ** — Desktop നിലവിലുള്ള Devin API കീ ഇമ്പോർട്ട് ചെയ്യുന്നു; CLI ലോക്കൽ `devin auth login` ക്രെഡൻഷ്യലുകൾ ഉപയോഗിക്കുന്നു
- 🆓 **8 പുതിയ സൗജന്യ പ്രൊവൈഡറുകൾ** — LLM7, Lepton, UncloseAI, BazaarLink, Completions, Enally, FreeTheAi, Command Code
- 🎯 **മാനിഫെസ്റ്റ്-അവബോധമുള്ള W1–W4 ടയർ റൂട്ടിംഗ്** — പ്രൊവൈഡർ മാനിഫെസ്റ്റുകൾ ഭാരിത ടയർ തിരഞ്ഞെടുപ്പിനെ നിയന്ത്രിക്കുന്നു
- 🎨 **Cursor-ന് പൂർണ്ണ OpenAI തുല്യത** — ടൂൾ കോളുകൾ, സ്ട്രീമിംഗ്, സെഷൻ മാനേജ്മെന്റ് എന്നിവയ്ക്ക് എൻഡ്-ടു-എൻഡ് പിന്തുണ
- 📊 **Cursor Pro പ്ലാൻ ഉപയോഗം** — ക്വോട്ടയും സൈക്കിൾ ഡാറ്റയും പ്രൊവൈഡർ-ലിമിറ്റ്സ് ഡാഷ്ബോർഡിൽ പ്രദർശിപ്പിക്കുന്നു

## 🎨 കോംബോകൾ

19 പൊതു സ്ട്രാറ്റജികൾ ഉപയോഗിച്ച് മോഡൽ റൂട്ടിംഗ് കോംബോകൾ സൃഷ്ടിക്കുക: priority, weighted, round-robin, context-relay, fill-first, p2c (power-of-two choices), random, least-used, cost-optimized, reset-aware, reset-window, headroom, strict-random, auto, lkgp (last-known-good-provider), context-optimized, cache-optimized, **fusion** (മോഡലുകളുടെ ഒരു പാനലിലേക്ക് സമാന്തരമായി അഭ്യർത്ഥനകൾ അയച്ച്, തുടർന്ന് ഒരു ജഡ്ജ് വഴി ഒറ്റ ഉത്തരം സമന്വയിപ്പിക്കുന്നു), കൂടാതെ **pipeline**. ഓരോ കോംബോയും സ്വയമേവയുള്ള fallback ഉപയോഗിച്ച് ഒന്നിലധികം മോഡലുകളെ ശൃംഖലയാക്കുകയും ദ്രുത ടെംപ്ലേറ്റുകളും സന്നദ്ധതാ പരിശോധനകളും ഉൾപ്പെടുത്തുകയും ചെയ്യുന്നു.

സമീപകാല കോംബോ മെച്ചപ്പെടുത്തലുകൾ:

- **ഘടനാപരമായ കോംബോ ബിൽഡർ** — പ്രൊവൈഡർ, മോഡൽ, കൃത്യമായ അക്കൗണ്ട്/കണക്ഷൻ എന്നിവ തിരഞ്ഞെടുത്ത് ഓരോ ഘട്ടവും സൃഷ്ടിക്കുക
- **ആവർത്തിച്ചുള്ള പ്രൊവൈഡർ പിന്തുണ** — `(provider, model, connection)` ട്യൂപ്പിൾ സവിശേഷമായിരിക്കുന്നിടത്തോളം, ഒരേ പ്രൊവൈഡറെ ഒരു കോംബോയിൽ പലതവണ വീണ്ടും ഉപയോഗിക്കുക
- **കോംബോ ടാർഗറ്റ് ഹെൽത്ത്** — എല്ലാം മോഡൽ സ്ട്രിങ്ങുകളായി ഒന്നിപ്പിക്കുന്നതിനുപകരം, അനലിറ്റിക്സും ഹെൽത്ത് പ്രതലങ്ങളും ഇപ്പോൾ ഓരോ കോംബോ ടാർഗറ്റിനെയും/ഘട്ടത്തെയും വേർതിരിച്ചറിയുന്നു
- **കോംപോസിറ്റ് ടയർ ക്രമീകരണം** — ടോപ്പ്-ലെവൽ കോംബോ ഘട്ടങ്ങളുടെ റൺടൈം നിർവഹണ/fallback ക്രമത്തെ ഇപ്പോൾ `defaultTier -> fallbackTier` സ്വാധീനിക്കുന്നു
- **സിസ്റ്റം പ്രോംപ്റ്റ് ടെംപ്ലേറ്റുകൾ** — കോംബോ `system_message`, സെർവർ-സൈഡ്
  `{{MODEL_ID}}`, `{{PROVIDER_ID}}`, `{{ACCOUNT}}`, `{{FINGERPRINT}}`
  പ്ലേസ്ഹോൾഡറുകളെ പിന്തുണയ്ക്കുന്നു; ഡിസ്പാച്ചിന് തൊട്ടുമുമ്പ് യഥാർത്ഥത്തിൽ റൂട്ട് ചെയ്ത ടാർഗറ്റിൽനിന്ന് ഇവ വികസിപ്പിക്കപ്പെടുന്നു.
  അനുവദനീയ പട്ടികയിലുള്ളവ മാത്രം, കൂടാതെ റിക്കർഷൻ ഇല്ല; അജ്ഞാത പ്ലേസ്ഹോൾഡറുകൾ മാറ്റമില്ലാതെ നിലനിൽക്കും; ശൂന്യമായ മൂല്യങ്ങൾ
  ശൂന്യമായി വികസിക്കും; ക്ലയന്റ് സിസ്റ്റം പ്രോംപ്റ്റുകൾ ഒരിക്കലും മാറ്റിയെഴുതില്ല. `{{FINGERPRINT}}`
  എന്നത് പിൻ ചെയ്തതോ സ്വയം റൊട്ടേറ്റ് ചെയ്യുന്നതോ ആയ fingerprint ഉള്ള fingerprint-അധിഷ്ഠിത സൗജന്യ പ്രൊവൈഡറുകൾക്ക് മാത്രമേ
  പരിഹരിക്കപ്പെടുകയുള്ളൂ — മറ്റിടങ്ങളിൽ ഇത് ശൂന്യമായി വികസിക്കും (ഉദാ.
  single-fingerprint കണക്ഷനുകൾ, non-fp പ്രൊവൈഡറുകൾ). വികസനം
  സ്റ്റാൻഡേർഡ് ഡിസ്പാച്ച് ലൂപ്പ്, round-robin, പിൻ ചെയ്ത context-cache സെഷനുകൾ എന്നിവ ഉൾക്കൊള്ളുന്നു;
  fusion, chaos, pipeline, nested-execute സ്ട്രാറ്റജികൾ ഇതുവരെ
  പ്ലേസ്ഹോൾഡറുകൾ വികസിപ്പിക്കുന്നില്ല.

- **രൂപഭാവം** — തീം സെലക്ടർ (ഡാർക്ക്/ലൈറ്റ്/സിസ്റ്റം), വർണ്ണ തീം പ്രീസെറ്റുകളും ഇഷ്ടാനുസൃത നിറങ്ങളും, ഹെൽത്ത് ലോഗ് ദൃശ്യത, സൈഡ്ബാർ ഇനങ്ങളുടെയും ഗ്രൂപ്പ് സെപ്പറേറ്ററുകളുടെയും ദൃശ്യതാ നിയന്ത്രണങ്ങൾ, എൻഡ്പോയിന്റ് ടണൽ ദൃശ്യതാ നിയന്ത്രണങ്ങൾ
- **AI** — AI അസിസ്റ്റന്റ് സവിശേഷതകൾ, ഡിഫോൾട്ട് റൂട്ടിങ് പ്രീസെറ്റുകൾ (Auto Combo `auto/coding`, `auto/fast`, `auto/cheap`, `auto/smart`), റീസണിങ് റീപ്ലേ കാഷ്, സ്കിൽ/മെമ്മറി ടോഗിളുകൾ
- **സുരക്ഷ** — API എൻഡ്പോയിന്റ് സംരക്ഷണം, ഇഷ്ടാനുസൃത പ്രൊവൈഡർ ബ്ലോക്കിങ്, IP ഫിൽട്ടറിങ്, സെഷൻ വിവരങ്ങൾ
- **റൂട്ടിങ്** — മോഡൽ അപരനാമങ്ങൾ, പശ്ചാത്തല ടാസ്ക് ഡീഗ്രഡേഷൻ, മാനിഫെസ്റ്റ് അധിഷ്ഠിത ടിയർ റൂട്ടിങ് (W1–W4), `fallbackDelayMs`, ഓരോ സെഷനുമുള്ള സ്റ്റിക്കി റൂട്ടിങ്
- **പ്രതിരോധശേഷി** — നിരക്ക് പരിധി നിലനിർത്തൽ, സർക്യൂട്ട് ബ്രേക്കർ ട്യൂണിങ്, നിരോധിക്കപ്പെട്ട അക്കൗണ്ടുകൾ സ്വയമേവ പ്രവർത്തനരഹിതമാക്കൽ, പ്രൊവൈഡർ കാലഹരണപ്പെടൽ നിരീക്ഷണം, **Context Relay** കൈമാറ്റ ത്രെഷോൾഡും സംഗ്രഹ മോഡൽ കോൺഫിഗറേഷനും, ഓരോ പ്രൊവൈഡറിനുമുള്ള 429 വർഗ്ഗീകരണവും `useUpstream429BreakerHints` ടോഗിളും, മോഡൽ കൂൾഡൗണുകൾ
- **വിപുലമായവ** — കോൺഫിഗറേഷൻ ഓവർറൈഡുകൾ, കോൺഫിഗറേഷൻ ഓഡിറ്റ് ട്രെയിൽ, ഫാൾബാക്ക് ഡീഗ്രഡേഷൻ മോഡ്, Responses API-യ്ക്കുള്ള പശ്ചാത്തല മോഡ് ഡീഗ്രഡേഷൻ

## 🌐 V1 WebSocket ബ്രിഡ്ജ് _(v3.6.6+)_

OmniRoute ഇപ്പോൾ `/v1/ws` അപ്ഗ്രേഡ് എൻഡ്പോയിന്റ് വഴി **OpenAI-അനുയോജ്യമായ WebSocket ക്ലയന്റുകളെ** പിന്തുണയ്ക്കുന്നു. ഇഷ്ടാനുസൃത `scripts/dev/v1-ws-bridge.mjs` സെർവർ Next.js-നെ പൊതിഞ്ഞ്, WS കണക്ഷനുകളെ പൂർണ്ണമായ ദ്വിദിശാ സ്ട്രീമിംഗ് സെഷനുകളിലേക്ക് അപ്ഗ്രേഡ് ചെയ്യുന്നു. പ്രാമാണീകരണത്തിനായി HTTP അഭ്യർത്ഥനകളിലെ അതേ API കീയോ സെഷൻ കുക്കിയോ ഉപയോഗിക്കുന്നു.

പ്രധാന പ്രവർത്തനരീതികൾ:

- കണക്ഷൻ സ്ഥാപിക്കുന്നതിന് മുമ്പ് `src/lib/ws/handshake.ts` ഉപയോഗിച്ച് WS അപ്ഗ്രേഡ് സാധൂകരിക്കുന്നു
- സെഷൻ അടയ്ക്കുമ്പോഴോ അപ്സ്ട്രീം പിശക് സംഭവിക്കുമ്പോഴോ സ്ട്രീമുകൾ വൃത്തിയായി അവസാനിപ്പിക്കുന്നു
- നിലവിലുള്ള HTTP+SSE സ്ട്രീമിംഗ് പാതയ്ക്കൊപ്പം ഒരേസമയം പ്രവർത്തിക്കുന്നു

## 🔑 സിങ്ക് ടോക്കണുകളും കോൺഫിഗ് ബണ്ടിലും _(v3.6.6+)_

ഒന്നിലധികം ഉപകരണങ്ങളിൽനിന്നും ബാഹ്യ ഓപ്പറേറ്റർമാർക്കും ഇപ്പോൾ **പരിധി നിർണ്ണയിച്ച സിങ്ക് ടോക്കണുകൾ** വഴി ആക്സസ് സാധ്യമാണ്:

- **`POST /api/sync/tokens`** — ഒരു പുതിയ സിങ്ക് ടോക്കൺ നൽകുക (പരിധി നിർണ്ണയിച്ചത്, ഐച്ഛിക കാലാവധിയോടെ)
- **`DELETE /api/sync/tokens/:id`** — ഒരു ടോക്കൺ അസാധുവാക്കുക
- **`GET /api/sync/bundle`** — രഹസ്യസ്വഭാവമില്ലാത്ത എല്ലാ ക്രമീകരണങ്ങളുടെയും പതിപ്പ് നിർണ്ണയിച്ചതും ETag അടിസ്ഥാനമാക്കിയുള്ളതുമായ JSON സ്നാപ്പ്ഷോട്ട് ഡൗൺലോഡ് ചെയ്യുക (പാസ്വേഡുകൾ മറച്ചിരിക്കും)

കോൺഫിഗ് ബണ്ടിൽ `src/lib/sync/bundle.ts` ആണ് നിർമ്മിക്കുന്നത്. മുഴുവൻ പേലോഡും വീണ്ടും ഡൗൺലോഡ് ചെയ്യാതെ മാറ്റങ്ങൾ കണ്ടെത്താൻ ഉപഭോക്താക്കൾ `ETag` പ്രതികരണ ഹെഡർ താരതമ്യം ചെയ്യുന്നു.

## 🛡️ സുരക്ഷിത ഔട്ട്ബൗണ്ട് ഫെച്ചും SSRF ഗാർഡും _(v3.6.6+)_

എല്ലാ പ്രൊവൈഡർ സാധൂകരണവും മോഡൽ കണ്ടെത്തൽ കോളുകളും ഇപ്പോൾ രണ്ട്-തല ഔട്ട്ബൗണ്ട് ഗാർഡിലൂടെയാണ് കടന്നുപോകുന്നത്:

1. **URL ഗാർഡ്** (`src/shared/network/outboundUrlGuard.ts`) — സോക്കറ്റ് തുറക്കുന്നതിന് മുമ്പ് സ്വകാര്യ/ലൂപ്പ്ബാക്ക്/ലിങ്ക്-ലോക്കൽ IP ശ്രേണികളെ തടയുന്നു.
2. **സുരക്ഷിത ഫെച്ച് റാപ്പർ** (`src/shared/network/safeOutboundFetch.ts`) — URL ഗാർഡ് പ്രയോഗിക്കുകയും ടൈംഔട്ടുകൾ ഏകീകരിക്കുകയും താൽക്കാലിക പിശകുകൾക്ക് എക്സ്പോണൻഷ്യൽ ബാക്ക്ഓഫോടെ വീണ്ടും ശ്രമിക്കുകയും ചെയ്യുന്നു.

ഗാർഡ് ലംഘനങ്ങൾ HTTP 422 (`URL_GUARD_BLOCKED`) ആയി ദൃശ്യമാകുകയും `providerAudit.ts` വഴി കംപ്ലയൻസ് ഓഡിറ്റ് ലോഗിൽ രേഖപ്പെടുത്തുകയും ചെയ്യുന്നു.

ഒരു അപ്സ്ട്രീം പ്രൊവൈഡർ മോഡൽ-നിർദ്ദിഷ്ട കൂൾഡൗൺ മടക്കി നൽകുമ്പോൾ ചാറ്റ് അഭ്യർത്ഥനകൾ ഇപ്പോൾ **സ്വയമേവ വീണ്ടും ശ്രമിക്കുന്നു**. `REQUEST_RETRY` (ഡിഫോൾട്ട്: 2), `MAX_RETRY_INTERVAL_SEC` (ഡിഫോൾട്ട്: 30 s) എന്നിവ വഴി ഇത് ക്രമീകരിക്കാം. `x-ratelimit-reset-requests`, `x-ratelimit-reset-tokens`, `Retry-After` എന്നിവയിലുടനീളം റേറ്റ്-ലിമിറ്റ് ഹെഡർ ലേണിങ് മെച്ചപ്പെടുത്തിയിട്ടുണ്ട് — ഓരോ മോഡലിന്റെയും കൂൾഡൗൺ നില Resilience ഡാഷ്ബോർഡിൽ കാണാം.

## 📋 കംപ്ലയൻസ് ഓഡിറ്റ് v2 _(v3.6.6+)_

കർസർ അടിസ്ഥാനമാക്കിയുള്ള പേജിനേഷൻ, അഭ്യർത്ഥനാ സന്ദർഭ സമ്പുഷ്ടീകരണം (അഭ്യർത്ഥന ID, യൂസർ ഏജന്റ്, IP), ഘടനാബദ്ധമായ ഓതന്റിക്കേഷൻ ഇവന്റുകൾ, വ്യത്യാസ സന്ദർഭത്തോടുകൂടിയ പ്രൊവൈഡർ CRUD ഇവന്റുകൾ, SSRF തടഞ്ഞ സാധൂകരണ ലോഗിങ് എന്നിവ ഉൾപ്പെടുത്തി ഓഡിറ്റ് ലോഗ് വിപുലീകരിച്ചിട്ടുണ്ട്. പുതിയ ഇവന്റുകൾ `src/lib/compliance/providerAudit.ts` പുറപ്പെടുവിക്കുന്നു.
