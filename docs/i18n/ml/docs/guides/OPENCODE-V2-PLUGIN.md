`@omniroute/opencode-plugin-v2` നിങ്ങളുടെ മുഴുവൻ OmniRoute കാറ്റലോഗും — മോഡലുകൾ, കോംബോകൾ,
ഓട്ടോ-കോംബോകൾ എന്നിവ — പ്രദർശന നാമങ്ങൾ, നിരക്കുകൾ, സൗജന്യ-ടയർ പരിധികൾ എന്നിവയോടെ
OpenCode v2-ന്റെ മോഡൽ പിക്കറിൽ ലഭ്യമാക്കുന്നു.

OpenCode v1, v2 എന്നിവ വ്യത്യസ്ത കോൺട്രാക്ടുകളിലൂടെയാണ് പ്ലഗിനുകൾ ലോഡ് ചെയ്യുന്നത് എന്നതിനാൽ,
ഇത് `@omniroute/opencode-plugin`-ൽ നിന്ന് വേറിട്ട ഒരു പാക്കേജാണ്. നിങ്ങളുടെ OpenCode മേജർ
പതിപ്പുമായി പൊരുത്തപ്പെടുന്നത് തിരഞ്ഞെടുക്കുക; അവയ്ക്കിടയിൽ ഒന്നും പങ്കിടുന്നില്ല, അതിനാൽ
ഒന്ന് അപ്ഗ്രേഡ് ചെയ്യുന്നത് മറ്റൊന്നിനെ ഒരിക്കലും നിർബന്ധിതമായി ബാധിക്കില്ല.

## ആവശ്യകതകൾ

- OpenCode v2.
- ആക്സസ് ചെയ്യാനാകുന്ന ഒരു OmniRoute ഗേറ്റ്വേ (സ്ഥിരസ്ഥിതിയായി `http://localhost:20128`).
- Node.js 22 അല്ലെങ്കിൽ 24.

## ഇൻസ്റ്റാൾ ചെയ്യുക

`opencode.json`-ലേക്ക് പ്ലഗിൻ ചേർക്കുക:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

തുടർന്ന് മോഡലുകൾ `omniroute/<provider>/<model>` എന്ന രൂപത്തിൽ ദൃശ്യമാകും; ആ പ്രിഫിക്സും
OpenCode ക്രെഡൻഷ്യൽ സൂക്ഷിക്കുന്ന ഇന്റഗ്രേഷന്റെ ഐഡിയും `providerId` നിർണ്ണയിക്കുന്നു.

## ക്രെഡൻഷ്യലുകൾ

പ്ലഗിൻ ഒരു ഗേറ്റ്വേ കീക്കായി താഴെ പറയുന്ന മൂന്ന് സ്ഥലങ്ങളിൽ, ഈ ക്രമത്തിൽ, തിരയുന്നു:

1. **OpenCode-ൽ നിങ്ങൾ കണക്റ്റ് ചെയ്ത ക്രെഡൻഷ്യൽ.** പ്ലഗിൻ ഒരു ഇന്റഗ്രേഷൻ രജിസ്റ്റർ ചെയ്യുന്നതിനാൽ,
   OpenCode-ന്റെ സ്വന്തം ഓത്ത് ഫ്ലോയ്ക്ക് കീ സൂക്ഷിക്കാനാകും. `opencode.json`-ൽ ഒന്നും ചേർക്കപ്പെടുന്നില്ല
   — ഈ രീതി തിരഞ്ഞെടുക്കുന്നതാണ് ഉചിതം.
2. ഓരോ പ്രോജക്റ്റിനുമുള്ള ഓവർറൈഡിനായി പ്ലഗിൻ ഓപ്ഷനുകളിലെ `apiKey`. ഇത് നിങ്ങൾ
   കമ്മിറ്റ് ചെയ്യാനിടയുള്ള ഒരു ഫയലിൽ കീ ഉൾപ്പെടുത്തുന്നു.
3. എൻവയൺമെന്റിലെ `OMNIROUTE_API_KEY`.

ഈ മൂന്നിൽ ഒന്നുമില്ലെങ്കിൽ, കാറ്റലോഗ് ശൂന്യമായിരിക്കും; നിശ്ശബ്ദമായി ശൂന്യമായ ഒരു പിക്കർ
നൽകുന്നതിനുപകരം പ്ലഗിൻ സ്റ്റാർട്ടപ്പിൽ ഒരിക്കൽ അത് അറിയിക്കും.

### മാനേജ്മെന്റ് ടോക്കൺ മറ്റൊരു കീയാണ്

കോംബോകൾ, പ്രൊവൈഡർ ഹെൽത്ത്, സമ്പുഷ്ടീകരണം (പ്രദർശന നാമങ്ങൾ, നിരക്കുകൾ, സൗജന്യ-ടയർ പരിധികൾ)
എന്നിവ ഗേറ്റ്വേയുടെ `/api/*` എൻഡ്പോയിന്റുകളിൽ നിന്നാണ് ലഭിക്കുന്നത്. മിക്ക ഡിപ്ലോയ്മെന്റുകളിലും
ഇൻഫറൻസ് കീക്ക് പകരം ഒരു **മാനേജ്മെന്റ്** ടോക്കൺ ഉപയോഗിച്ചാണ് ഇവ പരിരക്ഷിക്കുന്നത്:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<management read token>"
}
```

`managementReadToken` സജ്ജീകരിക്കാതെ വിട്ടാൽ, അത് `apiKey`-ലേക്ക് ഫാൾബാക്ക് ചെയ്യും. ഒരു ഗേറ്റ്വേ
ആ ഫാൾബാക്ക് നിരസിച്ചാലും കാറ്റലോഗ് പ്രസിദ്ധീകരിക്കും; എന്നാൽ പ്രദർശന നാമങ്ങൾക്ക് പകരം അസംസ്കൃത മോഡൽ
ഐഡികളായിരിക്കും, കൂടാതെ കാനോനിക്കൽ അപരനാമ ഡിഡ്യൂപ്പ്ലിക്കേഷൻ, നിരക്കുകൾ, കോംബോകൾ എന്നിവ ലഭ്യമാകില്ല.
അങ്ങനെ സംഭവിക്കുമ്പോൾ ഓരോ എൻഡ്പോയിന്റിനും ഒരിക്കൽ പ്ലഗിൻ മുന്നറിയിപ്പ് നൽകുകയും എൻഡ്പോയിന്റിന്റെ
പേരും നഷ്ടപ്പെട്ട കാര്യങ്ങളും വ്യക്തമാക്കുകയും ചെയ്യും — അതിനാൽ പരിമിതമായ ഒരു പിക്കർ ഒരിക്കലും
ദുരൂഹമായിരിക്കില്ല.

| `logLevel` / `startupDebug`      | `warn` / `false`                                        | ലോഗറിന്റെ വിശദാംശനില                                                                                                      |

## കാറ്റലോഗ് എങ്ങനെ പുതുമയോടെ നിലനിൽക്കുന്നു

കാറ്റലോഗ് ആവശ്യാനുസരണം മാത്രം ലഭ്യമാക്കുകയും `modelCacheTtlMs` സമയത്തേക്ക് കാഷ് ചെയ്യുകയും ചെയ്യുന്നു. ഗേറ്റ്വേയിൽ എത്തിച്ചേരാനാകാത്തപ്പോൾ അവസാനം അറിയപ്പെട്ടിരുന്ന കാറ്റലോഗ് ലഭ്യമായി നിലനിർത്താൻ ഒരു ഡിസ്ക് സ്നാപ്പ്ഷോട്ട് സഹായിക്കുന്നു — സേവനതടസ്സം മൂലം നിങ്ങൾക്ക് നഷ്ടമാകുന്നത് പുതുമ മാത്രമാണ്. മോഡലുകളും കോംബോകളും ലഭിച്ചയുടൻ പ്രസിദ്ധീകരിക്കുന്നു; ഓട്ടോ-കോംബോകൾ, പ്രൊവൈഡർ ലിസ്റ്റ്, എൻറിച്ച്മെന്റ് ഓവർലേ എന്നിവ ലഭ്യമാകുന്ന മുറയ്ക്ക് ഉൾച്ചേരുന്നതിനാൽ, വേഗം കുറഞ്ഞ ഒരു എൻഡ്പോയിന്റിന് മുഴുവൻ പിക്കറെയും തടഞ്ഞുനിർത്താനാകില്ല.

പേരുകളിൽ ഗേറ്റ്വേയ്ക്ക് അറിയാവുന്ന വിവരങ്ങൾ ഉൾപ്പെടുന്നു: ഒരു മോഡൽ റൂട്ട് ചെയ്യപ്പെടുന്ന അപ്സ്ട്രീം പ്രൊവൈഡർ, ഒരു `[Free]` അടയാളം, അതിനോടൊപ്പം ലഭിക്കുന്ന ബജറ്റ് എന്നിവ — അതിനാൽ ഒരേ മോഡൽ വിൽക്കുന്ന രണ്ട് കണക്ഷനുകൾ വേർതിരിച്ചറിയാൻ കഴിയും. `"providerTag": false` ഉപയോഗിച്ച് പ്രിഫിക്സ് ഓഫാക്കാം.

മാനുവൽ റിഫ്രഷ് കമാൻഡ് ഇല്ല: OpenCode v2 കമാൻഡുകൾ പ്രോംപ്റ്റ് ടെംപ്ലേറ്റുകളാണ്, കോൾബാക്കുകളല്ല; അതിനാൽ ഒരു പ്ലഗിന് അത്തരമൊരു കമാൻഡ് ലഭ്യമാക്കാനാകില്ല. റിഫ്രഷുകൾ TTL അനുസരിച്ചാണ് നടക്കുന്നത്; കാറ്റലോഗോ ഓവർലേയോ യഥാർത്ഥത്തിൽ മാറുമ്പോൾ മാത്രമേ ഹോസ്റ്റിനോട് റീലോഡ് ചെയ്യാൻ ആവശ്യപ്പെടുകയുള്ളൂ, ഓരോ റിഫ്രഷിലും അല്ല.

## Gemini-യിൽ ടൂൾ കോളിംഗ്

ടൂൾ ഡിക്ലറേഷനുകളിൽ `$schema` അല്ലെങ്കിൽ `additionalProperties` ഉൾപ്പെട്ടിട്ടുള്ള ഒരു മുഴുവൻ അഭ്യർത്ഥനയും Gemini നിരസിക്കുകയും `400 INVALID_ARGUMENT` എന്ന് മറുപടി നൽകുകയും ചെയ്യുന്നു. ഈ പ്രൊവൈഡറിന്റെ Gemini മോഡലിലേക്ക് അയയ്ക്കുന്ന ടൂൾ സ്കീമകളിൽനിന്ന് പ്ലഗിൻ ആ കീവേഡുകൾ നീക്കം ചെയ്യുകയും മറ്റെല്ലാ അഭ്യർത്ഥനകളും മാറ്റമില്ലാതെ നിലനിർത്തുകയും ചെയ്യുന്നു. `$ref` ഉൾക്കൊള്ളുന്ന ഒരു ടൂൾ മാറ്റമില്ലാതെ ഫോർവേഡ് ചെയ്യുന്നു; കാരണം റഫറൻസ് നീക്കം ചെയ്താൽ സ്കീമയുടെ പരിധി "എന്തും സ്വീകരിക്കുക" എന്നതിലേക്ക് വികസിക്കും.
ഇത് ഓഫാക്കാൻ `"geminiSanitization": false` സജ്ജീകരിക്കുക.
