## 1. Antigravity vs Antigravity CLI (agy)

രണ്ട് പ്രൊവൈഡർമാരും **ഒരേ Google ബാക്കെൻഡ്** പങ്കിടുന്നു — ഒരേ OAuth ക്ലയന്റ്, ടോക്കൺ പുതുക്കൽ, എൻഡ്പോയിന്റുകൾ, Google അക്കൗണ്ടുകൾ. നിങ്ങൾക്ക് ഏതൊക്കെ മോഡലുകൾ കാണാം എന്നതാണ് വ്യത്യാസം.

> Google-ന്റെ ഔദ്യോഗിക താരതമ്യത്തിനായി [Antigravity CLI പ്രഖ്യാപനം](https://antigravity.google/blog/introducing-google-antigravity-cli) കാണുക.

| വശം                          | `antigravity` (IDE)                                         | `agy` (CLI)                                                     |
| ---------------------------- | ----------------------------------------------------------- | --------------------------------------------------------------- |
| **Google ഉൽപ്പന്നം**         | Antigravity 2.0 / Antigravity IDE                           | Antigravity CLI                                                 |
| **ബാക്കെൻഡ്**                | ഒരേ Google Cloud Code API                                   | ഒരേ Google Cloud Code API                                       |
| **OAuth / ടോക്കൺ**           | ഒരേ ക്ലയന്റ്, ഒരേ പുതുക്കൽ                                  | ഒരേ ക്ലയന്റ്, ഒരേ പുതുക്കൽ                                      |
| **മോഡൽ കാറ്റലോഗ്**           | സ്ഥിരമായ ക്യൂറേറ്റഡ് പട്ടിക (OmniRoute-ൽ ഹാർഡ്കോഡ് ചെയ്തത്) | `:fetchAvailableModels` വഴി Google-ൽനിന്ന് തത്സമയം പരിശോധിച്ചത് |
| **Claude മോഡലുകൾ**           | Sonnet 4.6, Opus 4.6 (ഓരോന്നിനും 4 വേരിയന്റുകൾ)             | Sonnet 4.6, Opus 4.6 (ഓരോന്നിനും 4 വേരിയന്റുകൾ)                 |
| **Gemini നാമകരണം**           | ലളിതമായ ലേബലുകൾ (Low/Medium/High)                           | അപ്സ്ട്രീം ID-കൾ (extra-low/low/agent)                          |
| **അധിക മോഡലുകൾ**             | `gpt-oss-120b-medium`                                       | Google-ൽനിന്നുള്ള അധിക മോഡലുകൾ ഉൾപ്പെട്ടേക്കാം                  |
| **ഡിഫോൾട്ട് ഉപയോഗ സാഹചര്യം** | IDE സംയോജനം (VS Code, JetBrains)                            | CLI / API ആക്സസ്                                                |
| **ക്വോട്ട**                  | agy-യുമായി പങ്കിടുന്നു (ഒരേ Google അക്കൗണ്ട്)               | antigravity-യുമായി പങ്കിടുന്നു (ഒരേ Google അക്കൗണ്ട്)           |

**ലഭ്യമായ മോഡലുകൾ (പരീക്ഷണത്തിലൂടെ സ്ഥിരീകരിച്ചത്, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (വിവിധ ചിന്താ തലങ്ങൾ)
- Claude: Sonnet 4.6, Opus 4.6 (ഓരോന്നിനും default/low/medium/high വേരിയന്റുകൾ)
- മറ്റുള്ളവ: GPT-OSS 120B Medium
- **Claude Sonnet 5 ലഭ്യമല്ല** — 4.6 വേരിയന്റുകൾ മാത്രമാണ് പിന്തുണയ്ക്കുന്നത്

**മോഡൽ കാറ്റലോഗ് വ്യത്യസ്തമാകുന്നത് എന്തുകൊണ്ട്**: Google-ന്റെ ഔദ്യോഗിക ബ്ലോഗ് പ്രകാരം, Google-ന്റെ CLI "വേഗതയ്ക്കും കുറഞ്ഞ ഓവർഹെഡിനുമായി ഒപ്റ്റിമൈസ് ചെയ്തതും" "Gemini മോഡലുകൾക്കൊപ്പം സംയുക്തമായി ഒപ്റ്റിമൈസ് ചെയ്തതുമാണ്." Web/IDE ഉൽപ്പന്നം "സമഗ്രതയ്ക്കായി ഒപ്റ്റിമൈസ് ചെയ്തതാണ്." മോഡലുകൾ ഡൈനാമിക്കായി കണ്ടെത്താൻ CLI `:fetchAvailableModels` ഉപയോഗിക്കുമ്പോൾ, IDE സ്ഥിരമായ ഒരു ക്യൂറേറ്റഡ് പട്ടിക ഉപയോഗിക്കുന്നു.

**പ്രായോഗികമായി**: Gemini മോഡലുകൾക്കായി `agy/` പ്രിഫിക്സ് ഉപയോഗിക്കുക (ഉദാ. `agy/gemini-3.7-flash-high`). സ്ഥിരമായ ക്യൂറേറ്റഡ് പട്ടികയ്ക്കായി `antigravity/` ഉപയോഗിക്കുക. രണ്ടും ഒരേ Google ബാക്കെൻഡിലേക്കാണ് അഭ്യർത്ഥനകൾ അയയ്ക്കുന്നത്, എന്നാൽ വ്യത്യസ്ത മോഡൽ നാമകരണമാണ് ലഭ്യമാക്കുന്നത്. ക്വോട്ട പങ്കിടപ്പെടുന്നു — ഏതെങ്കിലും പ്രൊവൈഡർ ഉപയോഗിക്കുന്നത് അതേ Google അക്കൗണ്ടിന്റെ പരിധികളിൽ കണക്കാക്കപ്പെടും.

## 2. Google One AI Pro: ക്വോട്ട സംവിധാനം

> ഔദ്യോഗിക ക്വോട്ട വിശദാംശങ്ങൾക്ക് [Antigravity Docs: Plans](https://antigravity.google/docs/plans) കാണുക; ഏറ്റവും പുതിയ വിലനിർണ്ണയ അപ്ഡേറ്റുകൾക്ക് [Changes to Antigravity Plans](https://antigravity.google/blog/changes-to-antigravity-plans) കാണുക.

സന്ദേശങ്ങളുടെ എണ്ണത്തെ അടിസ്ഥാനമാക്കിയല്ല, മറിച്ച് "Work Done" (കമ്പ്യൂട്ടേഷണൽ ഭാരം) അടിസ്ഥാനമാക്കിയുള്ള ഒരു **ദ്വിതല ക്വോട്ട** ആണ് Google Antigravity ഉപയോഗിക്കുന്നത്.

### രണ്ട് തലങ്ങൾ

| തലം                          | എന്താണിത്                            | പുതുക്കൽ ചക്രം                                                                                     |
| ---------------------------- | ------------------------------------ | -------------------------------------------------------------------------------------------------- |
| **5 മണിക്കൂർ സ്പ്രിന്റ്**    | "ചെയ്ത ജോലിയുടെ" ഉടനടി ലഭ്യമായ ശേഖരം | ഒരു സെഷനിലെ ആദ്യ അഭ്യർത്ഥനയ്ക്ക് 5 മണിക്കൂറിന് ശേഷം പുനഃസജ്ജമാകും                                  |
| **7 ദിവസത്തെ അടിസ്ഥാനപരിധി** | പ്രതിവാര കർശന പരിധി                  | ഈ പരിധിയിലെത്തിയാൽ 5 മണിക്കൂർ പുതുക്കലിനെ മറികടക്കും; അടുത്ത 7 ദിവസത്തെ കാലയളവ് വരെ ലോക്ക് ചെയ്യും |

**"Work Done" കണക്കാക്കുന്ന വിധം**: ഏജന്റിനെ കൂടുതലായി ഉപയോഗിക്കുന്ന ജോലികൾ (ഉദാ. "ഈ മുഴുവൻ റെപ്പോസിറ്ററിയും റീഫാക്ടർ ചെയ്യുക") ലളിതമായ ജോലികളേക്കാൾ (ഉദാ. "ഈ ഫങ്ഷൻ ശരിയാക്കുക") വളരെ വേഗത്തിൽ ക്വോട്ട ഉപയോഗിച്ചുതീർക്കും. ഉപയോഗം കാണിക്കുന്ന തത്സമയ ഡാഷ്ബോർഡ് ലഭ്യമല്ല.

### Gemini മോഡലുകളും Non-Gemini മോഡലുകളും

- **Gemini മോഡലുകൾ** (Flash + Pro): API വിലനിർണ്ണയം അനുസരിച്ച് ഉപയോഗം കുറയുന്ന ഒരൊറ്റ നിരക്ക് പരിധി പങ്കിടുന്നു. Flash-ന് Pro-യേക്കാൾ 8x വിലക്കുറവാണെങ്കിൽ, നിങ്ങൾക്ക് 8x കൂടുതൽ Flash ടോക്കണുകൾ ലഭിക്കും.
- **Non-Gemini മോഡലുകൾ** (Claude, GPT-OSS): ഇവയ്ക്ക് **വെവ്വേറെ** നിരക്ക് പരിധികളുണ്ട്. Gemini ലോക്ക് ചെയ്തിരിക്കുമ്പോഴും ഇവ ലഭ്യമായി തുടരാം.

### AI ക്രെഡിറ്റുകൾ (അധിക ഉപയോഗം)

> ക്രെഡിറ്റുകൾ എങ്ങനെ പ്രവർത്തിക്കുന്നുവെന്ന് അറിയാൻ [Google One AI credits](https://support.google.com/googleone/answer/14534406) കാണുക.

അടിസ്ഥാന ക്വോട്ട തീർന്നാൽ:

- **ഒരിക്കലുമില്ല**: ക്വോട്ട പുതുക്കുന്നതുവരെ കാത്തിരിക്കുക; "Baseline model quota reached" എന്ന് കാണിക്കും
- **എപ്പോഴും**: AI ക്രെഡിറ്റുകൾ സ്വയമേവ ഉപയോഗിക്കുക; അടിസ്ഥാന ക്വോട്ട പുതുക്കുമ്പോൾ അതിലേക്ക് തിരികെ മാറും

ക്രെഡിറ്റുകൾ പ്രത്യേകം വാങ്ങേണ്ടതാണ്; സ്റ്റാൻഡേർഡ് API വിലനിർണ്ണയമനുസരിച്ച് അവ കുറയ്ക്കപ്പെടും.

### പ്രധാന വിശദാംശങ്ങൾ

- ക്വോട്ട **അക്കൗണ്ട് തലത്തിൽ പങ്കിടുന്നതാണ്** — Antigravity IDE, CLI, OmniRoute എന്നിവയിൽ ഒരേ Google അക്കൗണ്ട് ഉപയോഗിക്കുമ്പോൾ ഒരൊറ്റ ക്വോട്ട ശേഖരം പങ്കിടും
- ഓരോ Google അക്കൗണ്ടിനും അതിന്റേതായ സ്വതന്ത്ര ക്വോട്ടയുണ്ട് — ഒന്നിലധികം അക്കൗണ്ടുകൾ = ഒന്നിലധികം ക്വോട്ട ശേഖരങ്ങൾ
- പ്രതിവാര അടിസ്ഥാനപരിധിയിലെത്തുമ്പോൾ 5 മണിക്കൂർ പുനഃസജ്ജീകരണത്തിന് പകരം **7 ദിവസത്തെ ലോക്കൗട്ടുകൾ** ലഭിക്കുന്നതായി AI Pro ഉപയോക്താക്കൾ റിപ്പോർട്ട് ചെയ്തിട്ടുണ്ട് (ഉയർന്ന ഡിമാൻഡ് കൈകാര്യം ചെയ്യുന്നതിനുള്ള രൂപകൽപ്പനയുടെ ഭാഗമാണിതെന്ന് Google സ്ഥിരീകരിച്ചിട്ടുണ്ട്)

**നിങ്ങളുടെ അക്കൗണ്ടിന്റെ ക്വോട്ട തീർന്നാൽ**: കോംബോ റൂട്ടിൽ അടുത്തതായി ലഭ്യമായ അക്കൗണ്ട് ഉപയോഗിച്ച് OmniRoute സ്വയമേവ വീണ്ടും ശ്രമിക്കും. മാനുവൽ ഇടപെടൽ ആവശ്യമില്ല.

## 3. ഒരു projectId എങ്ങനെ നേടാം

ഓരോ antigravity/agy കണക്ഷനും ഒരു Google Cloud Code `projectId` ആവശ്യമാണ്. അതില്ലെങ്കിൽ, `/v1internal:models` എൻഡ്പോയിന്റ് 404 നൽകും.

### രീതി A: സ്വയമേവ (ശുപാർശ ചെയ്യുന്നത്)

OmniRoute ഇത് സ്വയമേവ കൈകാര്യം ചെയ്യുന്നു. Dashboard OAuth വഴി നിങ്ങൾ ഒരു പുതിയ Google അക്കൗണ്ട് ചേർക്കുമ്പോൾ:

1. OmniRoute ടോക്കൺ പുതുക്കുന്നു
2. projectId കണ്ടെത്താൻ `loadCodeAssist` വിളിക്കുന്നു
3. പ്രോജക്റ്റ് നിലവിലില്ലെങ്കിൽ, ഒരെണ്ണം സൃഷ്ടിക്കാൻ `onboardUser` വിളിക്കുന്നു
4. പുതുതായി സൃഷ്ടിച്ച projectId ലഭിക്കാൻ `loadCodeAssist` വീണ്ടും ശ്രമിക്കുന്നു
5. അത് ഡാറ്റാബേസിൽ സംരക്ഷിക്കുന്നു

**മിക്ക അക്കൗണ്ടുകൾക്കും ഇത് പ്രവർത്തിക്കും** — മാനുവൽ നടപടികൾ ആവശ്യമില്ല.

### രീതി B: agy CLI വഴി മാനുവലായി

സ്വയമേവയുള്ള കണ്ടെത്തൽ പരാജയപ്പെട്ടാൽ (ഇത് എപ്പോൾ സംഭവിക്കുമെന്നതിന് വിഭാഗം 5 കാണുക):

```bash
# agy CLI ഇൻസ്റ്റാൾ ചെയ്യുക (ഇതിനകം ചെയ്തിട്ടില്ലെങ്കിൽ)
npm install -g @anthropic-ai/agy

# നിങ്ങളുടെ Google അക്കൗണ്ട് ഉപയോഗിച്ച് ലോഗിൻ ചെയ്യുക
agy login

# ഓൺബോർഡിങ് ആവശ്യമായ അക്കൗണ്ട് തിരഞ്ഞെടുക്കുക
# ഇത് Cloud Code രജിസ്ട്രേഷൻ ആരംഭിക്കുകയും ഒരു projectId നൽകുകയും ചെയ്യുന്നു
```

`agy login` വിജയിച്ച ശേഷം, OmniRoute Dashboard-ൽ ടോക്കൺ പുതുക്കുക. projectId സ്വയമേവ കണ്ടെത്തപ്പെടും.

### പരിശോധിക്കുന്ന വിധം

ഡാറ്റാബേസ് പരിശോധിക്കുക:

## 4. OAuth റീഡയറക്ട് URI

### പ്രശ്നം

Google OAuth-ന് സാധുവായ ഒരു റീഡയറക്ട് URI ആവശ്യമാണ്. OmniRoute-ന്റെ ഡിഫോൾട്ട് `http://127.0.0.1:20128/callback` (ലൂപ്പ്ബാക്ക്) ഉപയോഗിക്കുന്നു. ഇത് ലോക്കൽ ബിൽഡുകളിൽ പ്രവർത്തിക്കുമെങ്കിലും **റിമോട്ട് ഡിപ്ലോയ്മെന്റുകളിൽ പരാജയപ്പെടും** (ഉദാ., LAN IP വഴി ആക്സസ് ചെയ്യുന്ന ഒരു സെർവർ).

ഇനിപ്പറയുന്ന തരത്തിലുള്ള റീഡയറക്ട് URI-കൾ Google നിരസിക്കുന്നു:

- IP വിലാസങ്ങൾ ഉപയോഗിക്കുന്നവ (`.com`, `.org` തുടങ്ങിയവയിൽ അവസാനിക്കുന്ന ഒരു ഡൊമെയ്ൻ ആയിരിക്കണം)
- OAuth ക്ലയന്റ് കോൺഫിഗിൽ രജിസ്റ്റർ ചെയ്ത റീഡയറക്ട് URI-കളുമായി പൊരുത്തപ്പെടാത്തവ

### പരിഹാരം

**ഓപ്ഷൻ A: ബിൽറ്റ്-ഇൻ OAuth ഫ്ലോ ഉപയോഗിക്കുക (ഡിഫോൾട്ട്)**

- `localhost` അല്ലെങ്കിൽ `127.0.0.1` വഴി OmniRoute ആക്സസ് ചെയ്യുമ്പോൾ പ്രവർത്തിക്കുന്നു
- കോൺഫിഗറേഷൻ ആവശ്യമില്ല

**ഓപ്ഷൻ B: കസ്റ്റം OAuth ക്രെഡൻഷ്യലുകൾ**

- നിങ്ങളുടെ എൻവയോൺമെന്റിൽ `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` സജ്ജമാക്കുക
- നിങ്ങളുടെ സ്വന്തം Google OAuth ക്രെഡൻഷ്യലുകൾ നൽകുക:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Google Cloud Console-ൽ `https://your-domain.com/callback` ഒരു അംഗീകൃത റീഡയറക്ട് URI ആയി രജിസ്റ്റർ ചെയ്യുക

**ഓപ്ഷൻ C: പ്രാരംഭ ലോഗിനിനായി agy CLI ഉപയോഗിക്കുക**

- OmniRoute ആക്സസ് ചെയ്യുന്ന മെഷീനിൽ `agy login` പ്രവർത്തിപ്പിക്കുക
- OAuth ഫ്ലോ ലോക്കലായി പൂർത്തിയാകുകയും ടോക്കണുകൾ സംഭരിക്കപ്പെടുകയും ചെയ്യും
- Dashboard വഴി കണക്ഷൻ OmniRoute-ലേക്ക് ഇമ്പോർട്ട് ചെയ്യുക

### പരിമിതികൾ

- കസ്റ്റം OAuth ക്രെഡൻഷ്യലുകൾക്ക് ഒരു ഡൊമെയ്ൻ നാമം ആവശ്യമാണ് (റീഡയറക്ട് URI-കളായി IP വിലാസങ്ങൾ Google അംഗീകരിക്കുന്നില്ല)
- നിങ്ങൾക്ക് ഒരു ഡൊമെയ്ൻ ഇല്ലെങ്കിൽ, പകരം ഓപ്ഷൻ A അല്ലെങ്കിൽ C ഉപയോഗിക്കുക

## 5. ട്രബിൾഷൂട്ടിംഗ്: ഓട്ടോമാറ്റിക് സജ്ജീകരണം പരാജയപ്പെടുമ്പോൾ

മിക്ക അക്കൗണ്ടുകൾക്കും projectId കണ്ടെത്തലും ഓൺബോർഡിംഗും OmniRoute സ്വയമേവ കൈകാര്യം ചെയ്യുന്നു. അത് പരാജയപ്പെടുമ്പോൾ, സാധാരണയായി താഴെ പറയുന്നവയിൽ ഒന്നായിരിക്കും അടിസ്ഥാന കാരണം:

### അക്കൗണ്ട് മേഖല ബ്ലോക്ക് ചെയ്തിരിക്കുന്നു

**ലക്ഷണം**: `agy login` "Eligibility check failed: Your current account is not eligible for Antigravity, because it is not currently available in your location." എന്ന് നൽകുന്നു.

**അടിസ്ഥാന കാരണം**: രജിസ്ട്രേഷൻ സമയത്ത് സജ്ജമാക്കുന്ന ഒരു ബാക്കെൻഡ് "Country Association" ഫീൽഡ് Google അക്കൗണ്ടുകൾക്കുണ്ട്. നിങ്ങളുടെ നിലവിലെ IP മാത്രം പരിശോധിക്കുന്ന വെബ് Gemini-യിൽ നിന്ന് വ്യത്യസ്തമായി, agy CLI-യും Cloud Code API-യും ഈ ഫീൽഡ് കർശനമായി പരിശോധിക്കുന്നു.

> നിങ്ങളുടെ അക്കൗണ്ടുമായി ബന്ധപ്പെടുത്തിയിരിക്കുന്ന മേഖല പരിശോധിക്കാനോ മാറ്റാനോ [Google Country Association Form](https://policies.google.com/country-association-form) സന്ദർശിക്കുക.

**വെബ് Gemini പ്രവർത്തിക്കുകയും agy പ്രവർത്തിക്കാതിരിക്കുകയും ചെയ്യുന്നതിന്റെ കാരണം**:

- വെബ് Gemini / Google One: നിലവിലെ IP മാത്രം പരിശോധിക്കുന്നു (പ്രോക്സി ഉപയോഗിച്ചാൽ കടന്നുപോകും)
- agy CLI / Cloud Code API: ബാക്കെൻഡ് Country Association ഫീൽഡ് വായിക്കുന്നു (പ്രോക്സി സഹായിക്കില്ല)

**പരിഹാരം**:

1. ഒരു US IP ഉപയോഗിക്കുമ്പോൾ [Google Country Association Form](https://policies.google.com/country-association-form) സന്ദർശിക്കുക
2. മേഖല മാറ്റാനുള്ള അഭ്യർത്ഥന സമർപ്പിക്കുക ("I live in a different country" തിരഞ്ഞെടുക്കുക)
3. Google അത് പ്രോസസ്സ് ചെയ്ത് ഇമെയിൽ അറിയിപ്പ് അയയ്ക്കുന്നതിനായി 1-24 മണിക്കൂർ കാത്തിരിക്കുക
4. തുടർന്ന് `agy login` വിജയിക്കണം

### അക്കൗണ്ടിന് Cloud Code പ്രോജക്റ്റ് ഇല്ല

**ലക്ഷണം**: ലോഗുകളിൽ `loadCodeAssist returned no project id`, `onboardUser failed (400)` എന്നിവ കാണിക്കുന്നു.

**അടിസ്ഥാന കാരണം**: അക്കൗണ്ട് മുമ്പൊരിക്കലും Google Cloud Code-ൽ രജിസ്റ്റർ ചെയ്തിട്ടില്ല, കൂടാതെ ഓട്ടോമാറ്റിക് ഓൺബോർഡിംഗ് പരാജയപ്പെട്ടു.

**പരിഹാരം**: Cloud Code രജിസ്ട്രേഷൻ ആരംഭിക്കുന്നതിന് `agy login` മാനുവലായി പ്രവർത്തിപ്പിക്കുക, തുടർന്ന് OmniRoute Dashboard-ൽ ടോക്കൺ പുതുക്കുക.

### ടോക്കൺ കാലഹരണപ്പെട്ടു അല്ലെങ്കിൽ അസാധുവാക്കി

**ലക്ഷണം**: ലോഗുകളിൽ 401 പിശകുകൾ അല്ലെങ്കിൽ "Token has expired" സന്ദേശങ്ങൾ കാണുന്നു.

**പരിഹാരം**: Dashboard → Providers → agy → പുതുക്കൽ ഐക്കൺ ക്ലിക്ക് ചെയ്യുക എന്ന ക്രമത്തിൽ ടോക്കൺ പുതുക്കുക. റിഫ്രഷ് ടോക്കൺ തന്നെ അസാധുവാക്കിയിട്ടുണ്ടെങ്കിൽ, OAuth വഴി വീണ്ടും പ്രാമാണീകരിക്കേണ്ടിവരും.

│

│  │         1-24 മണിക്കൂർ കാത്തിരുന്ന ശേഷം വീണ്ടും ശ്രമിക്കുക
│  └─ ഇല്ല ↓
│
├─ അക്കൗണ്ടിന് Google One AI Pro സബ്സ്ക്രിപ്ഷൻ ഉണ്ടോ?
│  ├─ ഇല്ല → ആദ്യം one.google.com-ൽ സബ്സ്ക്രൈബ് ചെയ്യുക
│  └─ ഉണ്ട് ↓
│
├─ സ്വയമേവയുള്ള കണ്ടെത്തൽ ശ്രമിക്കുക (Dashboard-ൽ ടോക്കൺ പുതുക്കുക)
│  ├─ പ്രവർത്തിക്കുന്നു → പൂർത്തിയായി

   ├─ പ്രവർത്തിക്കുന്നു → Dashboard-ൽ ടോക്കൺ പുതുക്കുക, projectId കണ്ടെത്തും
   └─ പരാജയപ്പെടുന്നു → പിശക് സന്ദേശം പരിശോധിക്കുക; മിക്കവാറും മേഖല അല്ലെങ്കിൽ സബ്സ്ക്രിപ്ഷൻ പ്രശ്നമായിരിക്കും
