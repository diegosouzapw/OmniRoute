**Claude Code** CLI (`claude`)യെ OmniRoute-ലേക്ക് — ലോക്കലായോ റിമോട്ട് VPS-ലേക്കോ —
ഓരോ മോഡലിനുമുള്ള പ്രൊഫൈലുകളോടെ, Codex സജ്ജീകരണത്തിന് സമാനമായി ബന്ധിപ്പിക്കുക.

---

## ദ്രുതാരംഭം

```bash
# ലോക്കൽ OmniRoute-നെതിരെ Claude Code സമാരംഭിക്കുക (സജീവ context സ്വയമേവ കണ്ടെത്തുന്നു)
omniroute launch

# റിമോട്ട് OmniRoute-നെതിരെ (`omniroute connect <host>`-ന് ശേഷം ഇത് സ്വയമേവ നടക്കും)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# ഓരോ മോഡലിനുമുള്ള പ്രൊഫൈലുകൾ സൃഷ്ടിച്ച ശേഷം ഒരെണ്ണം സമാരംഭിക്കുക
omniroute setup-claude            # ~/.claude/profiles/<name>/settings.json-ലേക്ക് എഴുതുന്നു
omniroute launch --profile glm52  # OmniRoute വഴി glm/glm-5.2 ഉപയോഗിക്കുന്ന Claude Code
```

## Claude Code ഒരു ഗേറ്റ്വേയിലേക്ക് എങ്ങനെ ബന്ധിപ്പിക്കുന്നു

Claude Code **Anthropic Messages API** ഉപയോഗിച്ചാണ് ആശയവിനിമയം നടത്തുന്നത്, കൂടാതെ പരിസ്ഥിതി വേരിയബിളുകൾ ഉപയോഗിച്ച് ഒരു ഇഷ്ടാനുസൃത
എൻഡ്പോയിന്റിലേക്ക് അതിനെ നയിക്കുന്നു (ഇതിന് `--base-url` ഫ്ലാഗ് ഇല്ല):

| വേരിയബിൾ                                     | ഉദ്ദേശ്യം                                                                                                               |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `ANTHROPIC_BASE_URL`                         | ഗേറ്റ്വേ റൂട്ട് URL (Claude Code `/v1/messages` ചേർക്കുന്നു). **`/v1` പ്രത്യയം പാടില്ല.**                               |
| `ANTHROPIC_AUTH_TOKEN`                       | `Authorization: Bearer …` ആയി അയയ്ക്കുന്നു — നിങ്ങളുടെ OmniRoute ആക്സസ് ടോക്കൺ / API കീ ഉപയോഗിക്കുക                     |
| `ANTHROPIC_API_KEY`                          | മറ്റൊരു മാർഗം: `x-api-key` ആയി അയയ്ക്കുന്നു. രണ്ടും സജ്ജീകരിച്ചിട്ടുണ്ടെങ്കിൽ `ANTHROPIC_AUTH_TOKEN`-ന് മുൻഗണന ലഭിക്കും |
| `ANTHROPIC_MODEL`                            | ഒരു നിർദ്ദിഷ്ട മോഡൽ നിർബന്ധിതമാക്കുന്നു (`/model` പിക്കറിന്റെ ഡിഫോൾട്ടിനെ മറികടക്കുന്നു)                                |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` → നേറ്റീവ് `/model` പിക്കർ `/v1/models`-ൽ നിന്നുള്ള `claude*`/`anthropic*` മോഡലുകൾ പട്ടികപ്പെടുത്തുന്നു             |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`              | ഓരോ പ്രതികരണത്തിനുമുള്ള ഔട്ട്പുട്ട് ടോക്കണുകൾ പരിമിതപ്പെടുത്തുന്നു (ഉദാ. `65536`)                                       |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`            | സ്വയമേവയുള്ള കോംപാക്ഷനുള്ള ടോക്കൺ പരിധി                                                                                 |

> പരിസ്ഥിതി വേരിയബിളുകൾ **സ്റ്റാർട്ടപ്പിൽ ഒരിക്കൽ മാത്രം** വായിക്കുന്നു — അവ മാറ്റിയ ശേഷം Claude Code പുനരാരംഭിക്കുക.

`omniroute launch` ഇവയെല്ലാം നിങ്ങൾക്കായി സജ്ജീകരിക്കുന്നു: സജീവ context-ൽ നിന്ന് ബേസ് URL + ടോക്കൺ
കണ്ടെത്തുന്നു (അതിനാൽ `omniroute connect <vps>` ചെയ്ത ശേഷം `omniroute launch`
പ്രവർത്തിക്കും), സെർവറിന്റെ ആരോഗ്യപരിശോധന നടത്തുന്നു, തുടർന്ന് `claude` എക്സിക്യൂട്ട് ചെയ്യുന്നു.

## ഡിസ്കവറി അപരനാമങ്ങൾ — Claude അല്ലാത്ത മോഡലുകൾ `/model` പിക്കറിൽ ദൃശ്യമാക്കുക

Claude Code-ന്റെ ഗേറ്റ്വേ മോഡൽ ഡിസ്കവറി, `claude` അല്ലെങ്കിൽ `anthropic` എന്നതിൽ തുടങ്ങുന്ന id-കൾ മാത്രമേ പട്ടികപ്പെടുത്തൂ.
അതിനാൽ `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` ഉപയോഗിക്കുമ്പോൾ നേറ്റീവ്
`/model` പിക്കർ സാധാരണയായി OmniRoute-ന്റെ Claude/Anthropic മോഡലുകൾ **മാത്രം** കാണിക്കുന്നു —
`kimi/kimi-k2.6` അല്ലെങ്കിൽ `glm/glm-5.2` ശരിയായി റൂട്ട് ചെയ്യപ്പെടുന്നുണ്ടെങ്കിലും ഒരിക്കലും ദൃശ്യമാകില്ല.

പ്രവർത്തനക്ഷമമാക്കിയ ഏത് മോഡലിനെയും (combo-യെയും) OmniRoute-ന് ഒരു `claude/…` id-യുടെ കീഴിൽ മിറർ ചെയ്യാനാകും, അതുവഴി അത്
ആ ഫിൽട്ടർ കടന്ന് പിക്കറിൽ ദൃശ്യമാകും:

```
kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<combo "custo-otimizado"> →  claude/combo/custo-otimizado
```

Claude Code-ൽ ഇവയിലൊന്ന് തിരഞ്ഞെടുക്കുമ്പോൾ, റൂട്ട് ചെയ്യുന്നതിന് മുമ്പ് OmniRoute `claude/` റാപ്പർ
നീക്കം ചെയ്ത് യഥാർഥ id ആക്കുന്നു — യഥാർഥ Claude OAuth പ്രൊവൈഡറായ ഒരു യഥാർഥ `claude/<real-claude-model>` id
എപ്പോഴും മാറ്റമില്ലാതെ നിലനിർത്തപ്പെടും.

**ഇത് ഡിഫോൾട്ടായി ഓഫാണ്**, കൂടാതെ മൂന്ന് തലങ്ങളുള്ള ഒരു ഗേറ്റ് ഉപയോഗിച്ചാണ് നിയന്ത്രിക്കുന്നത് (ഏറ്റവും നിർദ്ദിഷ്ടമായതിന്
മുൻഗണന ലഭിക്കും). അതിനാൽ Claude Code ഉപയോഗിക്കാത്ത ക്ലയന്റുകൾക്കായി ഒരു സാധാരണ OmniRoute ഒരിക്കലും അതിന്റെ കാറ്റലോഗ്
ഇരട്ടിയാക്കില്ല:

| തലം      | എവിടെ                                                                            |
| -------- | -------------------------------------------------------------------------------- |
| മോഡൽ     | പ്രൊവൈഡർ വിശദാംശ പേജ് → ഓരോ മോഡലിനുമുള്ള "Expose in Claude Code" ടോഗിൾ           |
| പ്രൊവൈഡർ | പ്രൊവൈഡർ വിശദാംശ പേജ് → പ്രൊവൈഡർ-തല ടോഗിൾ (അതിന്റെ എല്ലാ മോഡലുകളും ഉൾപ്പെടുന്നു) |
| ഗ്ലോബൽ   | Settings → Feature Flags → `EXPOSE_CC_DISCOVERY_ALIASES` (ഡിഫോൾട്ടായി ഓഫ്)       |

`EXPOSE_CC_DISCOVERY_ALIASES` പരിസ്ഥിതി വേരിയബിൾ ഗ്ലോബൽ തലത്തെ നിർബന്ധിതമായി ഓൺ ചെയ്യുകയും
ഡാഷ്ബോർഡ് ഓവർറൈഡിനെക്കാൾ മുൻഗണന നേടുകയും ചെയ്യുന്നു (അങ്ങനെ സംഭവിക്കുമ്പോൾ Feature Flags സ്ക്രീൻ
"active via environment variable" എന്ന കുറിപ്പ് കാണിക്കുന്നു). ഓരോ പ്രൊവൈഡറിനും ഓരോ മോഡലിനുമുള്ള
ടോഗിളുകൾ അവിടെനിന്ന് കൂടുതൽ കൃത്യമായി നിയന്ത്രിക്കുന്നു — ഉദാ. ഗ്ലോബൽ ഓഫ് + Kimi പ്രൊവൈഡർ ഓൺ ആണെങ്കിൽ
Kimi-യുടെ മോഡലുകൾ മാത്രം ദൃശ്യമാകും.

> ⚠️ **Claude അല്ലാത്ത മോഡലുകളിലെ വിൻഡോ പൊരുത്തക്കേട്.** Claude Code തിരിച്ചറിയാത്ത ഏത് id-ക്കും
> 200K context വിൻഡോ ഉണ്ടെന്ന് കരുതുന്നു (`/v1/models`-ൽ നിന്ന് യഥാർഥ വിൻഡോ വായിക്കാൻ അതിന് കഴിയില്ല).
> കൂടുതൽ വലിയ വിൻഡോയുള്ള ഒരു മോഡലിന് (ഉദാ. Kimi K2-ന്റെ 256K), മോഡലിന്റെ യഥാർഥ വിൻഡോയേക്കാൾ കുറഞ്ഞ ഒരു മൂല്യമായി
> `CLAUDE_CODE_AUTO_COMPACT_WINDOW` സജ്ജീകരിക്കുക, അതുവഴി സ്വയമേവയുള്ള കോംപാക്ഷൻ സമയത്തിന് മുമ്പ്
> പ്രവർത്തിക്കാതിരിക്കും. മുകളിൽ സൃഷ്ടിച്ച പ്രൊഫൈലുകൾ ഓരോ മോഡലിനും ഇത് ഇതിനകം ചെയ്യുന്നു.

## ഡാഷ്ബോർഡിലെ ഓൺബോർഡിംഗ് ബ്ലോക്ക്

Claude ടൂൾ കാർഡ് (**Dashboard → CLI Code**), ഡിസ്കവറി-അലിയാസ് വിവര ബട്ടണിന് സമീപം, കോപ്പി ബട്ടണോടുകൂടി ഈ ഇൻസ്റ്റൻസിനുള്ള കൃത്യമായ `settings.json` ഫ്രാഗ്മെന്റ് റെൻഡർ ചെയ്യുന്നു:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}
```

കാർഡ് കണ്ടെത്തിയ ബേസ് URL ആണ് ഉപയോഗിക്കുന്നത് (നിങ്ങൾ നൽകിയ കസ്റ്റം ഓവർറൈഡ് ഉൾപ്പെടെ); അത് ഇതിനകം നോർമലൈസ് ചെയ്തതാണ് — `/v1` സഫിക്സോ അവസാനിക്കുന്ന സ്ലാഷോ ഇല്ല. **കീ ഒരിക്കലും റെൻഡർ ചെയ്യില്ല**: ബ്ലോക്കിൽ ഒരു പ്ലേസ്ഹോൾഡറാണ് നൽകുന്നത്, അതിനാൽ സ്ക്രീൻഷോട്ടിലൂടെയോ പേസ്റ്റ് ചെയ്ത സ്നിപ്പറ്റിലൂടെയോ കീ ചോരുകയില്ല. അതിനുമുകളിൽ നിങ്ങളുടെ കീ പേസ്റ്റ് ചെയ്യുക.

യഥാർഥ കോൺടെക്സ്റ്റ് വിൻഡോ 200K അല്ലാത്ത ഏതൊരു മോഡലിനും അതേ `env` ബ്ലോക്കിന് കീഴിൽ `CLAUDE_CODE_AUTO_COMPACT_WINDOW` ചേർക്കുക — തിരിച്ചറിയാൻ കഴിയാത്ത എല്ലാ id-കൾക്കും Claude Code 200K ആണെന്ന് അനുമാനിക്കുന്നതിനാൽ, ഇല്ലെങ്കിൽ ഓട്ടോ-കോംപാക്ഷൻ തെറ്റായ ഘട്ടത്തിൽ പ്രവർത്തിക്കും (മുൻ വിഭാഗത്തിലെ മുന്നറിയിപ്പ് കാണുക). സ്നിപ്പറ്റ് ബിൽഡർ ഈ മൂല്യവും സ്വീകരിക്കുന്നു, അതിനാൽ ലക്ഷ്യ മോഡലിന്റെ വിൻഡോ അറിയുന്ന കോളറിന് അത് നേരിട്ട് എമിറ്റ് ചെയ്യാനാകും.

സോഴ്സ്: `src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet` (`ClaudeGatewayOnboardingBlock` റെൻഡർ ചെയ്യുന്ന പ്യൂർ ബിൽഡർ, യൂണിറ്റ്-ടെസ്റ്റ് ചെയ്തത്).

## പ്രൊഫൈലുകൾ (`CLAUDE_CONFIG_DIR`)

Claude Code-ന് **നേറ്റീവ് പ്രൊഫൈൽ ഫയലുകളില്ല** (Codex-ന്റെ `~/.codex/<name>.config.toml` പോലെയല്ല). ഓരോ പ്രൊഫൈലിനും പ്രത്യേക കോൺഫിഗ് ഡയറക്ടറി നൽകുന്ന `CLAUDE_CONFIG_DIR` ആണ് സ്വാഭാവിക സംവിധാനം; ഓരോന്നിനും അതിന്റേതായ `settings.json`, ക്രെഡൻഷ്യലുകൾ, ഹിസ്റ്ററി, കാഷ് എന്നിവ ഉണ്ടായിരിക്കും.

`omniroute setup-claude`, നിലവിലെ `/v1/models` കാറ്റലോഗ് ലഭ്യമാക്കി ഓരോ മോഡലിനും `~/.claude/profiles/<name>/settings.json` എന്നതിൽ ഓരോ പ്രൊഫൈൽ വീതം എഴുതുന്നു. ഇത് **`setup-codex` ഉപയോഗിക്കുന്ന അതേ പേരുകൾ** (`glm52`, `kimi-k27`, `deepseek-pro`, …) പുനരുപയോഗിക്കുന്നു:

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}
```

> **ഓത്ത് ടോക്കൺ ഒരിക്കലും പ്രൊഫൈലിലേക്ക് എഴുതില്ല.** `omniroute launch --profile <name>` ഉപയോഗിച്ച് ലോഞ്ച് ചെയ്യുക (ഇത് ആക്റ്റീവ് കോൺടെക്സ്റ്റിൽ നിന്ന് `ANTHROPIC_AUTH_TOKEN` ഇൻജക്റ്റ് ചെയ്യുന്നു), അല്ലെങ്കിൽ `ANTHROPIC_AUTH_TOKEN` സ്വയം എക്സ്പോർട്ട് ചെയ്തശേഷം
> `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude` റൺ ചെയ്യുക.

**മോഡൽ ഡിസ്കവറിക്കുശേഷമുള്ള ഓട്ടോ-സിങ്ക് (ഓപ്റ്റ്-ഇൻ).** ഒരു പ്രൊവൈഡർ മോഡൽ സിങ്ക് നിലവിലെ കാറ്റലോഗിൽ മാറ്റം വരുത്തുമ്പോഴെല്ലാം, ഇതേ `~/.claude/profiles/<name>/settings.json` ഫയലുകൾ OmniRoute-ന് സ്വയമേവ വീണ്ടും സൃഷ്ടിക്കാനാകും — അതിനാൽ കമാൻഡ് വീണ്ടും റൺ ചെയ്യാതെതന്നെ പുതിയതോ പുനർനാമകരണം ചെയ്തതോ ആയ മോഡലുകൾക്ക് പ്രൊഫൈലുകൾ ലഭിക്കും. ഇത് **ഡിഫോൾട്ടായി ഓഫാണ്**: **CLI Code dashboard**-ൽ നിന്ന് ("CLI profile auto-sync" → Claude Code) ഇത് ടോഗിൾ ചെയ്യുക, അല്ലെങ്കിൽ `OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true` സജ്ജമാക്കുക (ഡിഫോൾട്ടായി ഓണായിരിക്കുന്ന `CLI_ALLOW_CONFIG_WRITES`-നെയും ഇത് മാനിക്കുന്നു). പ്രവർത്തനക്ഷമമാക്കിയാൽ ഇത് പ്രൊഫൈൽ ഫയലുകൾ മാത്രമേ എഴുതുകയുള്ളൂ; നിങ്ങളുടെ ആക്റ്റീവ്/ഡിഫോൾട്ട് Claude കോൺഫിഗ്, ഓത്ത്, അല്ലെങ്കിൽ `~/.claude/settings.json` എന്നിവയിൽ ഒരിക്കലും മാറ്റം വരുത്തില്ല.

### പ്രൊഫൈലുകൾ സൃഷ്ടിക്കലും ഉപയോഗിക്കലും

```bash
# ലോക്കൽ OmniRoute
omniroute setup-claude

# റിമോട്ട് VPS (ഓരോ പ്രൊഫൈലിലും VPS URL ഉൾപ്പെടുത്തുന്നു)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# ചില പ്രൊവൈഡറുകൾ മാത്രം
omniroute setup-claude --only glm,kimi

# എഴുതാതെ പ്രിവ്യൂ ചെയ്യുക
omniroute setup-claude --dry-run

# ഒരു പ്രൊഫൈൽ ലോഞ്ച് ചെയ്യുക
omniroute launch --profile kimi-k27
```

## മോഡൽ ടിയറുകൾ (ഐച്ഛികം)

Claude Code ശേഷിയുടെ ടിയറുകളിലേക്ക് റൂട്ട് ചെയ്യുന്നു. ഓരോ ടിയറിനും വ്യത്യസ്ത പ്രൊവൈഡറുകൾ വേണമെങ്കിൽ env /
ക്രമീകരണങ്ങൾ വഴി ഓരോന്നും ഒരു OmniRoute മോഡലിലേക്ക് മാപ്പ് ചെയ്യുക:

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm/glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="kmc/kimi-k2.6"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="glm/glm-4.7-flash"
```

അല്ലെങ്കിൽ, എല്ലാത്തിനും ഒരൊറ്റ `ANTHROPIC_MODEL` (പ്രൊഫൈലുകൾ സജ്ജമാക്കുന്നത്) ഉപയോഗിക്കും.

## റിമോട്ട് മോഡ്

`omniroute connect <host>` പ്രവർത്തിപ്പിച്ചുകഴിഞ്ഞാൽ ([റിമോട്ട് മോഡ്](./REMOTE-MODE.md)
കാണുക), `omniroute launch`, `omniroute setup-claude` എന്നിവ സ്വയമേവ ആ റിമോട്ട്
സെർവറിനെ ലക്ഷ്യമാക്കി അതിന്റെ സ്കോപ്പ് ചെയ്ത ആക്സസ് ടോക്കൺ ഉപയോഗിക്കും — അധിക
ഫ്ലാഗുകളൊന്നും ആവശ്യമില്ല. ഓരോ ഇൻവൊക്കേഷനിലും `--remote` / `--api-key` ഉപയോഗിച്ച്
ഇത് ഓവർറൈഡ് ചെയ്യാം.

## പ്രശ്നപരിഹാരം

**Claude Code ഗേറ്റ്വേ അവഗണിക്കുന്നു** — `ANTHROPIC_BASE_URL`-ൽ **`/v1`
ഇല്ലെന്ന്** സ്ഥിരീകരിച്ച് `claude` പുനരാരംഭിക്കുക (ആരംഭിക്കുമ്പോൾ env ഒരിക്കൽ മാത്രമാണ്
വായിക്കുന്നത്). `omniroute launch` ഇത് നിങ്ങൾക്കായി കൈകാര്യം ചെയ്യുന്നു.

**`/model` പിക്കർ ശൂന്യമാണ് / ഗേറ്റ്വേ മോഡലുകൾ കാണുന്നില്ല** — Claude Code
v2.1.219+ ഉം `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` ഉം ആവശ്യമാണ്. `claude*` /
`anthropic*` മോഡൽ ID-കൾ മാത്രമേ പിക്കറിൽ ദൃശ്യമാകൂ; മറ്റേതെങ്കിലും മോഡൽ
`ANTHROPIC_MODEL=<id>` ഉപയോഗിച്ച് നിർബന്ധിതമായി തിരഞ്ഞെടുക്കുക (പ്രൊഫൈലുകൾ ചെയ്യുന്നത് ഇതാണ്).

**`400 Ambiguous model 'claude-…'`** — Claude Code എല്ലായ്പ്പോഴും **പ്രിഫിക്സ് ഇല്ലാത്ത**
മോഡൽ ID-കളാണ് അയയ്ക്കുന്നത് (ഉദാ. `claude-opus-4-8`), അതിനാൽ Claude Code (`cc/…`),
Claude (`claude/…`) പ്രൊവൈഡറുകൾ രണ്ടും കണക്റ്റ് ചെയ്തിരിക്കുമ്പോൾ പ്രിഫിക്സ് ഇല്ലാത്ത id രണ്ട്
റൂട്ടുകളുമായി പൊരുത്തപ്പെടുകയും OmniRoute ഊഹിക്കാൻ വിസമ്മതിക്കുകയും ചെയ്യും. ഇത് ഏതെങ്കിലും
രീതിയിൽ പരിഹരിക്കാം: `ANTHROPIC_MODEL=cc/claude-opus-4-8` ഉപയോഗിച്ച് പ്രിഫിക്സ് ചേർത്ത id
പിൻ ചെയ്യുക, അല്ലെങ്കിൽ **പ്രിഫിക്സ് ഇല്ലാത്ത Claude മോഡലുകൾക്ക് Claude Code മുൻഗണന നൽകുക**
എന്നത് പ്രവർത്തനക്ഷമമാക്കുക — Claude പ്രൊവൈഡർ പേജിലെ ടോഗിൾ, അല്ലെങ്കിൽ
`OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true` (സ്ഥിരസ്ഥിതിയിൽ ഓഫ്;
[പരിസ്ഥിതി](../reference/ENVIRONMENT.md) കാണുക) — ഇത് പ്രിഫിക്സ് ഇല്ലാത്ത `claude-*`
ID-കളെ പകരം Claude Code-ലേക്ക് റൂട്ട് ചെയ്യുന്നു. വ്യക്തമായ പ്രൊവൈഡർ പ്രിഫിക്സുകൾക്ക്
എപ്പോഴും മുൻഗണന ലഭിക്കും.

**ഓതന്റിക്കേഷൻ പിശകുകൾ** — പ്രൊഫൈലിൽ ടോക്കൺ ഇല്ല. `omniroute launch --profile`
ഉപയോഗിക്കുക (അത് ടോക്കൺ ഇൻജക്റ്റ് ചെയ്യും), അല്ലെങ്കിൽ `ANTHROPIC_AUTH_TOKEN` എക്സ്പോർട്ട് ചെയ്യുക.

**പ്രൊഫൈലുകൾ വേർതിരിക്കപ്പെടുന്നില്ല** — ഓരോ പ്രൊഫൈലും വ്യത്യസ്തമായ ഒരു
`CLAUDE_CONFIG_DIR` ആണ്; സെഷനിൽ `echo $CLAUDE_CONFIG_DIR` പ്രവർത്തിപ്പിച്ച് അത്
`~/.claude/profiles/<name>`-ലേക്കാണ് പോയിന്റ് ചെയ്യുന്നതെന്ന് സ്ഥിരീകരിക്കുക.
