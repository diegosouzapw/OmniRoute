ഈ ഗൈഡ് OmniRoute-ലേക്ക് Kiro (AWS ഹോസ്റ്റ് ചെയ്യുന്ന AI കോഡിംഗ് അസിസ്റ്റന്റ്) അക്കൗണ്ടുകൾ ചേർക്കുന്നതിനെക്കുറിച്ച് വിശദീകരിക്കുന്നു,
സെഷൻ വൈരുദ്ധ്യങ്ങളില്ലാതെ ഒന്നിലധികം അക്കൗണ്ടുകൾ ഒരേസമയം പ്രവർത്തിപ്പിക്കുന്നതിലാണ് ശ്രദ്ധ കേന്ദ്രീകരിക്കുന്നത്.

## പശ്ചാത്തലം: Kiro അക്കൗണ്ടുകൾ തമ്മിൽ വൈരുദ്ധ്യമുണ്ടാകുന്നത് എന്തുകൊണ്ട്

സജീവ സെഷനുകൾ ട്രാക്ക് ചെയ്യുന്നതിന് Kiro-യുടെ ബാക്ക്എൻഡ് AWS SSO OIDC ക്ലയന്റ് രജിസ്ട്രേഷനുകൾ ഉപയോഗിക്കുന്നു.
നിർണായകമായ പരിമിതി: **ഓരോ OIDC ക്ലയന്റ് രജിസ്ട്രേഷനും ഒരു സമയം ഒരു സജീവ
സെഷൻ മാത്രമേ പിന്തുണയ്ക്കൂ**. അതേ രജിസ്റ്റർ ചെയ്ത ക്ലയന്റ് ഉപയോഗിച്ച് രണ്ടാമത്തെ ഉപകരണമോ ഉപയോക്താവോ
ആധികാരികത ഉറപ്പാക്കുമ്പോൾ, ബാക്ക്എൻഡ് ആദ്യ അക്കൗണ്ടിന്റെ റിഫ്രഷ് ടോക്കൺ അസാധുവാക്കുന്നു.

മറ്റൊരു Kiro അക്കൗണ്ട് ഇതിനകം സൈൻ ഇൻ ചെയ്തിരിക്കുന്ന ഒരു മെഷീനിൽ `kiro-cli login`
പ്രവർത്തിപ്പിക്കുമ്പോൾ പ്രശ്നങ്ങളുണ്ടാക്കുന്നതും ഇതേ സംവിധാനമാണ് — പുതിയ ലോഗിൻ
ആദ്യ അക്കൗണ്ടിന്റെ ടോക്കൺ പിൻവലിക്കുന്നു.

## OmniRoute ഇത് എങ്ങനെ പരിഹരിക്കുന്നു (v3.8.0+)

v3.8.0 മുതൽ, ഓരോ Kiro കണക്ഷൻ ഇംപോർട്ടിനിടയിലും OmniRoute `registerClient()` (AWS SSO OIDC)
വിളിക്കുന്നു. ഇത് ഓരോ OmniRoute കണക്ഷനും അതിന്റേതായ സമർപ്പിത OIDC ക്ലയന്റ് രജിസ്ട്രേഷൻ
നൽകുന്നു. ഓരോ ക്ലയന്റ് രജിസ്ട്രേഷനും സ്വതന്ത്രമായതിനാൽ, ഒരു അക്കൗണ്ട് റിഫ്രഷ് ചെയ്യുന്നതോ
വീണ്ടും ആധികാരികത ഉറപ്പാക്കുന്നതോ മറ്റേതെങ്കിലും അക്കൗണ്ടിന്റെ റിഫ്രഷ് ടോക്കണിനെ ബാധിക്കില്ല.

ഈ ഒറ്റപ്പെടുത്തൽ റിഫ്രഷ്-ടോക്കൺ ഇംപോർട്ട് രീതികൾക്ക് ബാധകമാണ്; API-key ആധികാരികത
OIDC റിഫ്രഷ് സെഷനുകൾ പൂർണ്ണമായും ഒഴിവാക്കുന്നു:

| ഇംപോർട്ട് രീതി                                                         | ഒറ്റപ്പെടുത്തൽ നില                                                                                                                        |
| ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| AWS Builder ID / IDC ഡിവൈസ്-കോഡ് ഫ്ലോ                                  | ഡിവൈസ്-കോഡ് ഫ്ലോ അവതരിപ്പിച്ചതുമുതൽ ഒറ്റപ്പെടുത്തിയിരിക്കുന്നു                                                                            |
| **ടോക്കൺ ഇംപോർട്ട് ചെയ്യുക** (റിഫ്രഷ് ടോക്കൺ നേരിട്ട് പേസ്റ്റ് ചെയ്യൽ) | v3.8.0 മുതൽ ഒറ്റപ്പെടുത്തിയിരിക്കുന്നു                                                                                                    |
| **Google / GitHub സോഷ്യൽ ലോഗിൻ**                                       | v3.8.0 മുതൽ ഒറ്റപ്പെടുത്തിയിരിക്കുന്നു                                                                                                    |
| **ഓട്ടോ-ഇംപോർട്ട്** (kiro-cli SQLite)                                  | v3.8.0 മുതൽ ഒറ്റപ്പെടുത്തിയിരിക്കുന്നു (SQLite പാത ഇതിനകം ഒറ്റപ്പെടുത്തിയിരുന്നു; SSO-cache ഫാൾബാക്കും ഇപ്പോൾ ഒറ്റപ്പെടുത്തിയിരിക്കുന്നു) |
| **API Key** (ദീർഘകാല CodeWhisperer കീ)                                 | റിഫ്രഷ് സെഷനില്ല; കീ സാധൂകരിച്ച് ബെയറർ ക്രെഡൻഷ്യലായി സംഭരിക്കുന്നു                                                                        |

## v3.8.0-ന് മുമ്പ് സൃഷ്ടിച്ച കണക്ഷനുകൾക്കുള്ള മൈഗ്രേഷൻ കുറിപ്പ്

v3.8.0-ന് മുമ്പ് ഇംപോർട്ട് ചെയ്ത കണക്ഷനുകളിൽ `providerSpecificData`-യിൽ സംഭരിച്ച
സമർപ്പിത OIDC ക്ലയന്റ് രജിസ്ട്രേഷൻ ഉണ്ടായിരിക്കില്ല. ഈ കണക്ഷനുകൾ തുടർന്നും പ്രവർത്തിക്കുമെങ്കിലും,
പങ്കിട്ട സോഷ്യൽ-ഓത്ത് റിഫ്രഷ് എൻഡ്പോയിന്റാണ് ഉപയോഗിക്കുന്നത്; അതിനാൽ അത്തരത്തിലുള്ള രണ്ട് കണക്ഷനുകൾക്ക്
ഇപ്പോഴും പരസ്പരം അസാധുവാക്കാനാകും.

**ഒറ്റപ്പെടുത്തൽ ലഭിക്കാൻ:** **Dashboard → Providers**-ൽ നിന്ന് പഴയ കണക്ഷൻ ഇല്ലാതാക്കി,
പിന്തുണയ്ക്കുന്ന ഏതെങ്കിലും ഇംപോർട്ട് ഫ്ലോ ഉപയോഗിച്ച് അത് വീണ്ടും ഇംപോർട്ട് ചെയ്യുക. പുതുതായി സൃഷ്ടിക്കുന്ന എല്ലാ കണക്ഷനുകൾക്കും
അവയുടേതായ ക്ലയന്റ് രജിസ്ട്രേഷൻ സ്വയമേവ ലഭിക്കും.

## രണ്ട് Kiro അക്കൗണ്ടുകൾ ഒരുമിച്ച് ചേർക്കുന്നത്

### മുൻവ്യവസ്ഥകൾ

- OmniRoute v3.8.0 അല്ലെങ്കിൽ അതിന് ശേഷമുള്ള പതിപ്പ്.
- പ്രവർത്തിക്കുന്ന ഒരു Kiro അക്കൗണ്ട് (ഇമെയിൽ + പാസ്വേഡ്, Google, അല്ലെങ്കിൽ GitHub ലോഗിൻ).
- ഐച്ഛികമായി രണ്ടാമത്തെ Kiro അക്കൗണ്ട്.

### ഘട്ടം 1: ആദ്യ അക്കൗണ്ട് ഇംപോർട്ട് ചെയ്യുക

1. **Dashboard → Providers → Add Provider → Kiro** തുറക്കുക.
2. ഇനിപ്പറയുന്നവയിൽ ഒന്ന് തിരഞ്ഞെടുക്കുക:
   - **ടോക്കൺ ഇംപോർട്ട് ചെയ്യുക** — `aorAAAAAG`-ൽ ആരംഭിക്കുന്ന ഒരു റിഫ്രഷ് ടോക്കൺ പേസ്റ്റ് ചെയ്യുക.
   - **API Key** — ദീർഘകാല Kiro / CodeWhisperer API കീ പേസ്റ്റ് ചെയ്യുക.
   - **Google / GitHub ലോഗിൻ** — ബ്രൗസറിൽ OAuth ഫ്ലോ പൂർത്തിയാക്കുക.
   - **ഓട്ടോ-ഇംപോർട്ട്** — ബട്ടണിൽ ക്ലിക്ക് ചെയ്യുക; പ്രാദേശിക kiro-cli ഡാറ്റാബേസിൽ നിന്നോ
     `~/.aws/sso/cache`-ൽ നിന്നോ OmniRoute ക്രെഡൻഷ്യലുകൾ വായിക്കും.
3. കണക്ഷൻ സംരക്ഷിക്കപ്പെടും. റിഫ്രഷ്-ടോക്കൺ ഫ്ലോകൾ സ്വയമേവ ഒരു സമർപ്പിത
   OIDC ക്ലയന്റ് രജിസ്റ്റർ ചെയ്യും. API-key ഫ്ലോകൾ AWS ഉപയോഗിച്ച് കീ സാധൂകരിക്കുകയും റിഫ്രഷ് ടോക്കൺ സംഭരിക്കാതിരിക്കുകയും ചെയ്യും.

### ഘട്ടം 2: രണ്ടാമത്തെ അക്കൗണ്ട് ഇംപോർട്ട് ചെയ്യുക

രണ്ടാമത്തെ അക്കൗണ്ടിനായി ഘട്ടം 1 ആവർത്തിക്കുക. ഓരോ ഇംപോർട്ടും പ്രത്യേക OIDC
ക്ലയന്റ് രജിസ്ട്രേഷൻ സൃഷ്ടിക്കുന്നതിനാൽ, രണ്ട് കണക്ഷനുകളും പൂർണ്ണമായി ഒറ്റപ്പെട്ടിരിക്കും.

### ഘട്ടം 3: രണ്ട് കണക്ഷനുകളും സജീവമാണെന്ന് പരിശോധിക്കുക

1. **Dashboard → Providers** — രണ്ട് Kiro കണക്ഷനുകളും **സജീവം** എന്ന നില കാണിക്കണം.
2. **Dashboard → Health** — രണ്ട് കണക്ഷനുകളും അവയുടെ ടോക്കൺ ആരോഗ്യ പരിശോധന വിജയിക്കണം.

### ഘട്ടം 4: അക്കൗണ്ടുകൾക്കിടയിൽ റൂട്ട് ചെയ്യാൻ ഒരു കോംബോ ഉപയോഗിക്കുക

ലോഡ് ബാലൻസ് ചെയ്യുന്നതിനോ അവയ്ക്കിടയിൽ ഫാൾബാക്ക് ചെയ്യുന്നതിനോ രണ്ട് കണക്ഷനുകളും ലക്ഷ്യങ്ങളാക്കി ഒരു കോംബോ സൃഷ്ടിക്കുക:

```
kiro/kiro-dev → kiro/kiro-pro
```

കോംബോ കോൺഫിഗറേഷനായി [FEATURES.md](./FEATURES.md)-യും റൂട്ടിംഗ് ഡോക്യുമെന്റേഷനും കാണുക.

## എന്റർപ്രൈസ് / IDC ഉപയോക്താക്കൾ

AWS IAM Identity Center (IDC) അക്കൗണ്ടുകൾക്കായി, **Dashboard → Providers → Kiro → Device Code** എന്നതിൽ നിന്നുള്ള **AWS Builder ID / IDC device-code**
ഫ്ലോ ഉപയോഗിക്കുക. device-code ഫ്ലോ എല്ലായ്പ്പോഴും പൂർണ്ണമായി വേർതിരിച്ചാണ് പ്രവർത്തിച്ചിട്ടുള്ളത്. ഈ കണക്ഷനുകൾക്കായി
വീണ്ടും ഇംപോർട്ട് ചെയ്യേണ്ടതില്ല.

ഡിഫോൾട്ട് അല്ലാത്ത AWS റീജിയനിൽ പ്രവർത്തിക്കുന്ന എന്റർപ്രൈസ് ഉപയോക്താക്കൾക്ക് Import Token API വഴി
ഇംപോർട്ട് ചെയ്യുമ്പോൾ റീജിയൻ വ്യക്തമാക്കാം:

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/import \
  -H "Content-Type: application/json" \
  -d '{"refreshToken": "aorAAAAAG...", "region": "eu-west-1"}'
```

`region` ഫീൽഡ് ഒഴിവാക്കിയാൽ അതിന്റെ ഡിഫോൾട്ട് മൂല്യം `us-east-1` ആയിരിക്കും.

## API-Key ഇംപോർട്ട് ഫ്ലോ

API-key ഓതന്റിക്കേഷൻ ദീർഘകാലത്തേക്ക് ഉപയോഗിക്കാവുന്ന Kiro / AWS CodeWhisperer bearer ക്രെഡൻഷ്യലുകൾക്കായുള്ളതാണ്. ഇത്
OAuth റിഫ്രഷ് ഉപയോഗിക്കുന്നില്ല, അതിനാൽ പങ്കിട്ട OIDC സെഷൻ അസാധുവാകുന്നത് ഒഴിവാക്കുന്നു.

### ഡാഷ്ബോർഡ്

1. **Dashboard -> Providers -> Kiro** തുറക്കുക.
2. **API Key** തിരഞ്ഞെടുക്കുക.
3. API key-യും ഐച്ഛികമായ AWS റീജിയനും ഒട്ടിക്കുക (ഡിഫോൾട്ടായി `us-east-1`).
4. OmniRoute കീ സാധൂകരിക്കുകയും കണക്ഷൻ സംരക്ഷിക്കുകയും ചെയ്യും.

### API

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/api-key \
  -H "Content-Type: application/json" \
  -d '{"apiKey": "kiro_or_codewhisperer_key", "region": "us-east-1"}'
```

### ആന്തരിക കരാർ

API റൂട്ട് `KiroService.validateApiKey()` വിളിച്ച് കീ സാധൂകരിക്കുന്നു; ഇത്
റീജിയനുമായി പൊരുത്തപ്പെടുന്ന CodeWhisperer/Amazon Q എൻഡ്പോയിന്റിനെതിരെ `ListAvailableProfiles` ഉപയോഗിക്കുകയും ഒരു `profileArn` കണ്ടെത്തുകയും ചെയ്യുന്നു.

സംരക്ഷിച്ച കണക്ഷൻ ഇനിപ്പറയുന്നത് ഉപയോഗിക്കുന്നു:

```json
{
  "authType": "apikey",
  "providerSpecificData": {
    "authMethod": "api_key",
    "region": "us-east-1",
    "profileArn": "arn:aws:codewhisperer:..."
  }
}
```

റൺടൈമിൽ, `KiroExecutor.buildHeaders()` കീ
`Authorization: Bearer <key>` ആയി അയയ്ക്കുകയും `tokentype: API_KEY` ചേർക്കുകയും ചെയ്യുന്നു. ക്വോട്ട/പ്രൊഫൈൽ കോളുകളും
ഇതേ മാർക്കർ ഉപയോഗിക്കുന്നതിനാൽ, AWS ഈ bearer-നെ ഒരു OIDC അല്ലെങ്കിൽ സോഷ്യൽ ആക്സസ് ടോക്കൺ എന്നതിനു പകരം
ദീർഘകാല API key ആയി പരിഗണിക്കുന്നു.

## OIDC ക്ലയന്റ് കാലഹരണപ്പെടൽ

AWS SSO OIDC പബ്ലിക് ക്ലയന്റുകൾ സാധാരണയായി 90 ദിവസത്തിനു ശേഷം
കാലഹരണപ്പെടുന്നു (`clientSecretExpiresAt`). നിരീക്ഷണക്ഷമതയ്ക്കായി OmniRoute ഈ ടൈംസ്റ്റാമ്പ് `providerSpecificData`-യിൽ
സംഭരിക്കുന്നു. ഏകദേശം 90 ദിവസത്തിനു ശേഷം ഒരു കണക്ഷൻ റിഫ്രഷ് ചെയ്യുന്നത് നിർത്തുകയാണെങ്കിൽ, പുതിയൊരു OIDC ക്ലയന്റ് രജിസ്ട്രേഷൻ ലഭിക്കാൻ
കണക്ഷൻ വീണ്ടും ഇംപോർട്ട് ചെയ്യുക. കാലഹരണപ്പെടുമ്പോഴുള്ള സ്വയമേവയുള്ള പുനർരജിസ്ട്രേഷൻ ഭാവിയിലെ മെച്ചപ്പെടുത്തലായി
ട്രാക്ക് ചെയ്തിരിക്കുന്നു.

API-key കണക്ഷനുകൾ AWS SSO OIDC വഴി റിഫ്രഷ് ചെയ്യാത്തതിനാൽ അവയ്ക്ക് OIDC ക്ലയന്റ് കാലഹരണപ്പെടൽ
ബാധകമല്ല.

## പ്രശ്നപരിഹാരം

### രണ്ടാമത്തെ അക്കൗണ്ട് തുടർച്ചയായി ലോഗ് ഔട്ട് ചെയ്യപ്പെടുന്നു

- **Dashboard → Providers** എന്നതിലെ രണ്ട് കണക്ഷനുകളും പരിശോധിച്ച്, അവയുടെ raw JSON-ൽ (വിവര ഐക്കൺ വഴി കാണാം) ഓരോന്നിലും null അല്ലാത്ത
  `clientId` കാണിക്കുന്നുവെന്ന് സ്ഥിരീകരിക്കുക. ഏതെങ്കിലും കണക്ഷനിൽ
  `clientId` ഇല്ലെങ്കിൽ, അത് v3.8.0-ന് മുമ്പ് ഇംപോർട്ട് ചെയ്തതാണ് — അത് വീണ്ടും ഇംപോർട്ട് ചെയ്യുക.

### "Token validation failed" എന്ന പിശകോടെ ഇംപോർട്ട് പരാജയപ്പെടുന്നു

- റിഫ്രഷ് ടോക്കൺ `aorAAAAAG` എന്നതിൽ ആരംഭിക്കുന്നുവെന്ന് ഉറപ്പാക്കുക.
- OmniRoute-ന് `https://oidc.us-east-1.amazonaws.com`-ലേക്ക് (അല്ലെങ്കിൽ കോൺഫിഗർ ചെയ്ത
  റീജിയനിലേക്ക്) എത്താനാകുമെന്ന് ഉറപ്പാക്കുക. നിങ്ങൾ ഒരു കോർപ്പറേറ്റ് പ്രോക്സിക്ക് പിന്നിലാണെങ്കിൽ,
  **Dashboard → Settings → Proxies** എന്നതിൽ പ്രൊവൈഡർ-തലത്തിലുള്ള പ്രോക്സി സജ്ജീകരിക്കുക.

### API-key ഇംപോർട്ട് പരാജയപ്പെടുന്നു

- കീ ഒരു റിഫ്രഷ് ടോക്കൺ അല്ലെന്നും Kiro / CodeWhisperer API key ആണെന്നും സ്ഥിരീകരിക്കുക.
- AWS റീജിയൻ കീ/അക്കൗണ്ടുമായി പൊരുത്തപ്പെടുന്നുവെന്ന് സ്ഥിരീകരിക്കുക. `us-east-1` ആണ് ഡിഫോൾട്ട്.
- കീയ്ക്ക് `ListAvailableProfiles` വിളിക്കാൻ കഴിയണം; അല്ലെങ്കിൽ ആവശ്യമായ `profileArn`
  കണ്ടെത്താൻ OmniRoute-ന് കഴിയില്ല.
