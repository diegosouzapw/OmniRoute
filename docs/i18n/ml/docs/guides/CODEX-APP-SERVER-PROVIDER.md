OmniRoute, OpenAI Codex ഉപയോഗിക്കാൻ **രണ്ട്** മാർഗങ്ങൾ ലഭ്യമാക്കുന്നു:

| പ്രൊവൈഡർ               | ഇത് OpenAI-യുമായി ആശയവിനിമയം നടത്തുന്ന വിധം                                                                                                                                                                                          | ഉപയോഗത്തിലെ മുന്നറിയിപ്പ്                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| **`codex`**            | നിങ്ങളുടെ ChatGPT/OpenAI OAuth ടോക്കൺ നേരിട്ട് Responses API-യിലേക്ക് വീണ്ടും അയയ്ക്കുന്നു                                                                                                                                           | **ഉണ്ട്** — ഔദ്യോഗിക സെഷന് proxy/router ഉപയോഗത്തിനുള്ള അനുമതിയില്ല         |
| **`codex-app-server`** | JSON-RPC/WebSocket വഴി **Codex CLI-യുടെ സ്വന്തം `codex app-server`** പ്രവർത്തിപ്പിക്കുന്നു; ഒരു ഇന്ററാക്ടീവ് `codex` സെഷനിലെന്നപോലെ CLI തന്നെ അതിന്റെ OAuth (`~/.codex/auth.json`) കൈകാര്യം ചെയ്യുകയും സ്വയം പുതുക്കുകയും ചെയ്യുന്നു | **ഇല്ല** — OmniRoute ഒരിക്കലും API-യിലേക്ക് ടോക്കൺ വീണ്ടും അയയ്ക്കുന്നില്ല |

`codex-app-server` ഒരിക്കലും ടോക്കൺ വീണ്ടും അയയ്ക്കാത്തതിനാൽ, അതിന്
സെഷൻ-റീപ്ലേ ഉപയോഗ മുന്നറിയിപ്പ് ബാധകമല്ല. എന്നാൽ, **കോൺഫിഗർ ചെയ്തിരിക്കുന്ന
app-server URL-ൽ ലഭ്യമായ ഒരു Codex CLI** ആവശ്യമാണ്; ആ CLI-യിൽ **സൈൻ ഇൻ
ചെയ്തിരിക്കണം**.

## 1. ആർക്കിടെക്ചർ

```
┌─ OmniRoute ആപ്പ് ────────────────┐        ┌─ codex-app-server സൈഡ്കാർ ─────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ ശേഷി ടോക്കൺ)                 │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  OpenAI OAuth സ്വയം കൈകാര്യം ചെയ്യുന്നു │
└──────────────────────────────────┘        │  (~/.codex/auth.json, സ്വയം പുതുക്കൽ) │
        │ പങ്കിടുന്നു (compose വോള്യങ്ങൾ)      └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → WS ശേഷി ടോക്കൺ (രണ്ടും ഇത് മൗണ്ട് ചെയ്യുന്നു)
  codex-appserver-home    → ~/.codex (ഡാഷ്ബോർഡ് എഴുതുന്ന auth.json,
                             സൈഡ്കാറിന്റെ codex app-server വായിക്കുന്നു)
```

- ശേഷി ടോക്കൺ ഉപയോഗിച്ച് സംരക്ഷിച്ചിട്ടുള്ള ആന്തരിക compose നെറ്റ്വർക്കിൽ
  (`ws://codex-app-server:1456`) **മാത്രമാണ്** സൈഡ്കാർ ലിസൺ ചെയ്യുന്നത്. ഇത്
  ഹോസ്റ്റിലേക്കോ ഇന്റർനെറ്റിലേക്കോ **ഒരിക്കലും** പബ്ലിഷ് ചെയ്യപ്പെടുന്നില്ല.
- Codex CLI, `omniroute:base`-ൽ ഉൾപ്പെടുത്തിയിട്ടുണ്ട്; അതിനാൽ സൈഡ്കാർ
  പ്രവർത്തിപ്പിക്കുമ്പോൾ ഹോസ്റ്റിലോ ഉപയോക്താവിന്റെ മെഷീനിലോ codex ഇൻസ്റ്റാൾ
  ചെയ്യേണ്ടതില്ല.

## 2. പ്രവർത്തിപ്പിക്കുക

```bash
# codex app-server സൈഡ്കാർ പ്രൊഫൈൽ ഉൾപ്പെടുത്തി സ്റ്റാക്ക് ആരംഭിക്കുക:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

ആദ്യ ബൂട്ടിൽ സൈഡ്കാർ അതിന്റെ WS ശേഷി ടോക്കൺ സൃഷ്ടിക്കുന്നു (പങ്കിട്ട
`codex-appserver-token` വോള്യത്തിലേക്ക്); ആപ്പ് അതേ ടോക്കൺ
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE` വഴി വായിക്കുന്നു. ടോക്കൺ മാനുവലായി
ബന്ധിപ്പിക്കേണ്ടതില്ല.

## 3. കണക്റ്റ് ചെയ്യുക + സൈൻ ഇൻ ചെയ്യുക

1. ഡാഷ്ബോർഡിൽ, **OpenAI Codex (App-Server)**-നായി ഒരു കണക്ഷൻ ചേർക്കുക. API
   കീയോ ടോക്കണോ ആവശ്യമില്ല (ഇത് auth ആവശ്യമില്ലാത്ത പ്രൊവൈഡറാണ് — സൈഡ്കാർ
   auth കൈകാര്യം ചെയ്യുന്നു).
2. സൈഡ്കാറിന്റെ Codex CLI-യിൽ **ഇതുവരെ സൈൻ ഇൻ ചെയ്തിട്ടില്ലെങ്കിൽ**, കണക്ഷൻ
   ഹെൽത്ത് ചെക്ക് _"പ്രവർത്തിക്കുന്നു, പക്ഷേ സൈൻ ഇൻ ചെയ്തിട്ടില്ല"_ എന്ന്
   റിപ്പോർട്ട് ചെയ്യും (ചുവന്ന auth പിശകല്ല). **Sign in with ChatGPT**
   ഉപയോഗിക്കുക: ഇത് നിങ്ങളുടെ ബ്രൗസറിൽ സാധാരണ Codex device-OAuth
   പ്രവർത്തിപ്പിക്കുകയും തുടർന്ന് **Apply auth** വഴി പങ്കിട്ട വോള്യത്തിലേക്ക്
   `~/.codex/auth.json` എഴുതുകയും ചെയ്യുന്നു (ഒരേ ലോഗിൻ `codex`,
   `codex-app-server` എന്നീ രണ്ട് പ്രൊവൈഡറുകൾക്കും ഉപയോഗിക്കുന്നു).
3. സൈൻ ഇൻ ചെയ്തുകഴിഞ്ഞാൽ, ഹെൽത്ത് ചെക്ക് പച്ചയാകും (ഇത് `/readyz` **ഉം**
   `account/read` **ഉം** പരിശോധിക്കുന്നു — അതായത് പ്രവർത്തനക്ഷമമാണെന്നും
   ഓതന്റിക്കേറ്റ് ചെയ്തിട്ടുണ്ടെന്നും സ്ഥിരീകരിക്കുന്നു), തുടർന്ന് പ്രവർത്തനം
   ആരംഭിക്കുന്നു.

നിലവിലുള്ള ആരോഗ്യകരമായ `~/.codex/auth.json` ഡാഷ്ബോർഡ് ഒരിക്കലും
തിരുത്തിയെഴുതില്ല — ഫയൽ ഇല്ലാത്തപ്പോഴോ അതിലെ ടോക്കൺ കാലഹരണപ്പെട്ടിരിക്കുമ്പോഴോ
മാത്രമാണ് അത് എഴുതുന്നത് (എല്ലായ്പ്പോഴും ഒരു ബാക്കപ്പ് എടുക്കുന്നു).

## 4. വിന്യാസ സാഹചര്യങ്ങൾ

- **ഇതിനകം ഓതന്റിക്കേറ്റ് ചെയ്ത Codex CLI ഉള്ള ഓപ്പറേറ്റർ** — നിങ്ങളുടെ ഹോസ്റ്റിലെ
  `~/.codex`, സൈഡ്കാറിലേക്ക് (`codex-appserver-home`) മൗണ്ട് ചെയ്ത് സൈൻ-ഇൻ ഘട്ടം
  ഒഴിവാക്കുക.
- **പൊതു ഉപയോക്താവ്, ലോക്കലായി codex ഇൻസ്റ്റാൾ ചെയ്തിട്ടില്ല** — ഇത്
  പ്രശ്നമല്ല: സൈഡ്കാറിൽ CLI ഉണ്ട്. ഉപയോക്താവ് ഡാഷ്ബോർഡ് വഴി മാത്രം
  ഓതന്റിക്കേറ്റ് ചെയ്താൽ മതി.
- **ബെയർ-മെറ്റൽ OmniRoute (സൈഡ്കാർ ഇല്ല, ഹോസ്റ്റ് codex)** — നിങ്ങളുടെ സ്വന്തം
  `codex app-server`-ലേക്ക് `OMNIROUTE_CODEX_APPSERVER_WS` ചൂണ്ടിക്കാണിക്കുകയും
  ഹോസ്റ്റിലെ codex-ൽ സൈൻ ഇൻ ചെയ്തിട്ടുണ്ടെന്ന് ഉറപ്പാക്കുകയും ചെയ്യുക; ബൈനറി
  ഇല്ലെങ്കിൽ "codex ഇൻസ്റ്റാൾ ചെയ്തിട്ടില്ല" എന്ന സൂചന ദൃശ്യമാകും.

## 5. റെസിഡൻഷ്യൽ / UDP എഗ്രസ് (ഓപ്പറേറ്റർക്കുള്ള അധിക സൗകര്യം, വിതരണത്തിൽ ഉൾപ്പെടുത്തിയിട്ടില്ല)

മുകളിലുള്ള ജനറിക് സൈഡ്കാർ, കണ്ടെയ്നറിന്റെ സാധാരണ നെറ്റ്വർക്ക് വഴിയാണ് എഗ്രസ്
ചെയ്യുന്നത്. Codex ട്രാഫിക് ഒരു **റെസിഡൻഷ്യൽ എക്സിറ്റ്** വഴി എഗ്രസ് ചെയ്യേണ്ട
ഓപ്പറേറ്റർ (ഉദാ. TCP + UDP/QUIC വഹിക്കുന്ന ഒരു TUN tailscale സൈഡ്കാർ) അത്
പ്രത്യേക compose override ആയി പ്രവർത്തിപ്പിക്കണം; ഇത് മനഃപൂർവം വിതരണം ചെയ്യുന്ന
`codex-app-server` പ്രൊഫൈലിന്റെ ഭാഗമാക്കിയിട്ടില്ല. ആ സജ്ജീകരണത്തിനായി ആന്തരിക
ഓപ്പറേഷൻസ് റൺബുക്ക് കാണുക.
