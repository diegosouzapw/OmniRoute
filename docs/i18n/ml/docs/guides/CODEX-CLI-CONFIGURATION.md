OpenAI-അനുയോജ്യമായ ബാക്ക്എൻഡായി OmniRoute-ലേക്ക് ചൂണ്ടുന്ന Codex CLI ഉപയോഗിക്കുന്നതിനുള്ള സമ്പൂർണ്ണ മാർഗ്ഗനിർദ്ദേശം.

---

> **TOML മാത്രമാണ് ഫലപ്രദമായ ഫോർമാറ്റ്.** ആധുനിക Codex, `~/.codex/config.toml`
> മാത്രമാണ് വായിക്കുന്നത് (codex-cli 0.147.0 ഉപയോഗിച്ച് സ്ഥിരീകരിച്ചത്: `codex --help`,
> `~/.codex/config.toml`-ൽ നിന്ന് ലോഡ് ചെയ്ത ക്രമീകരണങ്ങളെ `-c/--config`
> അസാധുവാക്കുമെന്ന് രേഖപ്പെടുത്തുന്നു). പഴയ `~/.codex/config.yaml`, ലെഗസി npm CLI-യുടേതായിരുന്നു,
> അത് യാതൊരു അറിയിപ്പുമില്ലാതെ അവഗണിക്കപ്പെടുന്നു.
> ഡാഷ്ബോർഡ് ജനറേറ്റർ (`/api/cli-tools/apply`, ടൂൾ `codex`) സൂക്ഷ്മമായ ഒരു
> ലയനത്തിലൂടെ TOML എഴുതുന്നു — നിലവിലുള്ള കീകളും മറ്റ് പ്രൊവൈഡർ ബ്ലോക്കുകളും നിലനിർത്തപ്പെടും,
> API കീ `OMNIROUTE_API_KEY`-ൽ തന്നെ തുടരും (ഫയലിൽ ഒരിക്കലും സൂക്ഷിക്കില്ല), കൂടാതെ ശേഷിക്കുന്ന ലെഗസി
> `config.yaml`-നെ സ്പർശിക്കാതെ ഒരു മൈഗ്രേഷൻ കുറിപ്പായി റിപ്പോർട്ട് ചെയ്യും.

## നേരിട്ട് ഒട്ടിക്കാൻ തയ്യാറായ config.toml

`<YOUR_HOST>`, `<YOUR_KEY>` എന്നിവ നിങ്ങളുടെ മൂല്യങ്ങൾ ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുക:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # ഓരോ ടൂൾ കോളിനുമുള്ള ഹിസ്റ്ററി സംഭരണ പരിധി

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc അല്ലെങ്കിൽ ~/.zshrc — യഥാർത്ഥ കീ മൂല്യം, config.toml-ൽ ഒരിക്കലും സൂക്ഷിക്കരുത്
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: ChatGPT ആപ്പിനുള്ളിൽ ഉൾപ്പെടുത്തിയിരിക്കുന്ന Codex

ChatGPT ഡെസ്ക്ടോപ്പ് ആപ്പ് വഴി നിങ്ങൾ Codex ഇൻസ്റ്റാൾ ചെയ്തിട്ടുണ്ടെങ്കിൽ, `codex` ബൈനറി
ആപ്പ് ബണ്ടിലിനുള്ളിൽ മാത്രം ഉണ്ടായിരിക്കാം; നിങ്ങളുടെ ഷെൽ `PATH`-ൽ ഇതുവരെ ഉണ്ടായിരിക്കണമെന്നില്ല. നിങ്ങളുടെ
ഷെൽ സ്റ്റാർട്ടപ്പ് ഫയലിലേക്ക് റിസോഴ്സസ് ഡയറക്ടറി ചേർക്കുക:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

ഒരു പുതിയ ഷെൽ തുറന്ന ശേഷം പരിശോധിക്കുക:

```bash
command -v codex
codex --version
```

### പ്രാദേശികമായി പ്രാമാണീകരണം ആവശ്യമില്ലാത്ത OmniRoute: ഒരു പ്ലേസ്ഹോൾഡർ കീ മതി

ആദ്യ അഭ്യർത്ഥന CLI-യിൽ നിന്ന് പുറത്തുപോകുന്നതിന് **മുമ്പ്**, `env_key` സൂചിപ്പിക്കുന്ന
എൻവയോൺമെന്റ് വേരിയബിൾ നിലവിലുണ്ടെന്ന് Codex സാധൂകരിക്കുന്നു. നിങ്ങളുടെ **പ്രാദേശിക**
OmniRoute ഇൻസ്റ്റൻസിന് പ്രാമാണീകരണം ആവശ്യമില്ലെങ്കിൽ, ശൂന്യമല്ലാത്ത ഏതൊരു പ്ലേസ്ഹോൾഡറും മതിയാകും:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

നിങ്ങളുടെ OmniRoute സെർവർ സംരക്ഷിതമോ റിമോട്ടോ ആണെങ്കിൽ, പകരം യഥാർത്ഥ കീ ഉപയോഗിക്കുക.

> **സാധാരണ ഹോസ്റ്റ് ഓപ്ഷനുകൾ**
>
> | ആക്സസ്                 | URL                           |
> | ---------------------- | ----------------------------- |
> | പ്രാദേശിക നെറ്റ്വർക്ക് | `http://192.168.0.1:20128/v1` |
> | Tailscale              | `http://100.x.x.x:20128/v1`   |
> | ലൂപ്പ്ബാക്ക്           | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — എല്ലാ മോഡലുകൾക്കും ഇത് പ്രവർത്തിക്കുന്നതിന്റെ കാരണം

2026 ഫെബ്രുവരിയിൽ Codex CLI, `wire_api = "chat"` (Chat Completions) ഉപയോഗശൂന്യമാക്കി; ഇപ്പോൾ **നിർബന്ധമായും** `wire_api = "responses"` (OpenAI Responses API) ആവശ്യമാണ്. v0.138 മുതൽ `wire_api = "chat"` സജ്ജമാക്കുന്നത് സ്റ്റാർട്ടപ്പിൽ ഉടനടി ക്രാഷ് ഉണ്ടാക്കുന്നു.

GLM, Kimi എന്നിവ ഉൾപ്പെടെ നിരവധി പ്രൊവൈഡർമാർ ഇപ്പോഴും Chat Completions എൻഡ്പോയിന്റ് മാത്രമാണ് ലഭ്യമാക്കുന്നത്. DeepSeek V4 ഇപ്പോൾ ഒരു നേറ്റീവ് Responses API-യും Anthropic-അനുയോജ്യമായ ഒരു എൻഡ്പോയിന്റും ലഭ്യമാക്കുന്നു; OmniRoute സ്ഥിരസ്ഥിതിയായി Responses ഉപയോഗിക്കുകയും ഓരോ DeepSeek കണക്ഷനും Anthropic അനുയോജ്യത തിരഞ്ഞെടുക്കാൻ അനുവദിക്കുകയും ചെയ്യുന്നു.

**OmniRoute ഇത് സുതാര്യമായി പരിഹരിക്കുന്നു:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute പ്രൊവൈഡറുടെ നേറ്റീവ് പ്രോട്ടോക്കോൾ തിരഞ്ഞെടുക്കുകയും ആവശ്യമുള്ളപ്പോൾ പരിവർത്തനം നടത്തുകയും ചെയ്യുന്നു
    → POST /responses (DeepSeek V4) അല്ലെങ്കിൽ /chat/completions (Mistral / GLM / Kimi / മറ്റുള്ളവ)
```

OmniRoute ഉപയോഗിക്കുമ്പോൾ നിങ്ങൾക്ക് ഒരിക്കലും പ്രത്യേകമായൊരു ട്രാൻസ്ലേഷൻ പ്രോക്സി ആവശ്യമില്ല. **എല്ലാ മോഡലുകളും `wire_api = "responses"` ഉപയോഗിക്കുന്നു** — ശേഷിക്കുന്നതെല്ലാം OmniRoute കൈകാര്യം ചെയ്യും.

> **`wire_api` ആണ് സ്ഥിരസ്ഥിതി** — ഈ ഫീൽഡിന്റെ സ്ഥിരസ്ഥിതി മൂല്യം `"responses"` ആണ്, അതിനാൽ `config.toml`-ൽ നിന്ന് ഇത് പൂർണ്ണമായും ഒഴിവാക്കാം. ഉദ്ദേശ്യം രേഖപ്പെടുത്തണമെങ്കിൽ മാത്രം ഇത് വ്യക്തമായി സജ്ജമാക്കുക.

## കോൺടെക്സ്റ്റ് വിൻഡോയും കോംപാക്ഷനും

### ടോക്കൺ കോൺഫിഗറേഷൻ ഫീൽഡുകൾ

| ഫീൽഡ്                            | വിവരണം                                                                                                                                                                                                                         |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `model_context_window`           | സജീവ മോഡലിനുള്ള ആകെ ടോക്കൺ ബജറ്റ്. മോഡൽ പ്രസിദ്ധീകരിച്ചിരിക്കുന്ന പരിധിയായി സജ്ജീകരിക്കുക.                                                                                                                                     |
| `model_auto_compact_token_limit` | ഓട്ടോമാറ്റിക് ഹിസ്റ്ററി കോംപാക്ഷൻ ട്രിഗർ ചെയ്യുന്ന പരിധി. **പരമാവധി: `model_context_window`-ന്റെ 90%** — 90%-ന് മുകളിലുള്ള മൂല്യങ്ങൾ അറിയിപ്പില്ലാതെ അവഗണിക്കപ്പെടും.                                                          |
| `tool_output_token_limit`        | ഓരോ ടൂൾ കോളിന്റെയും ഔട്ട്പുട്ടിൽ നിന്ന് ഹിസ്റ്ററിയിൽ സംഭരിക്കുന്ന ടോക്കണുകളുടെ പരമാവധി പരിധി. ഒരു വലിയ ടൂൾ പ്രതികരണം മാത്രം വിൻഡോ നിറയ്ക്കുന്നത് തടയുന്നു. **ഇത് പരമാവധി ഔട്ട്പുട്ട് അല്ല** — ഇതൊരു ഹിസ്റ്ററി സംഭരണ പരിധിയാണ്. |
| `compact_prompt`                 | കോംപാക്ഷൻ സമയത്ത് ഉപയോഗിക്കുന്ന സിസ്റ്റം പ്രോംപ്റ്റിനുള്ള ഇൻലൈൻ ഓവർറൈഡ് (v0.138+).                                                                                                                                             |

> **`model_max_output_tokens` സംബന്ധിച്ച കുറിപ്പ്**: ഈ ഫീൽഡ് **Codex CLI കോൺഫിഗ് സ്കീമയുടെ ഭാഗമല്ല** (Codex Rust കോഡ്ബേസിൽ ഇത് ഇല്ല). ഇത് സജ്ജീകരിച്ചാൽ അറിയിപ്പില്ലാതെ അവഗണിക്കപ്പെടും. ഇതിനെ ആശ്രയിക്കരുത് — ഹിസ്റ്ററിയിൽ എത്ര ടൂൾ ഔട്ട്പുട്ട് സംഭരിക്കണമെന്ന് നിയന്ത്രിക്കാൻ `tool_output_token_limit` ഉപയോഗിക്കുക.

## റീസണിംഗ് ശ്രമം

പ്രതികരിക്കുന്നതിന് മുമ്പ് മോഡൽ എത്രത്തോളം "ചിന്തിക്കുന്നു" എന്നത് നിയന്ത്രിക്കുന്നു.

| മൂല്യം   | ഉപയോഗിക്കേണ്ടത്                                            |
| -------- | ---------------------------------------------------------- |
| `none`   | റീസണിംഗ് ഇല്ല — നേരിട്ടുള്ള പ്രതികരണം                      |
| `low`    | നിസ്സാര ടാസ്കുകൾ (പേരുമാറ്റൽ, ഫോർമാറ്റ് ചെയ്യൽ)            |
| `medium` | വ്യക്തമാക്കിയിട്ടില്ലെങ്കിൽ **സെർവർ ഡിഫോൾട്ട്**            |
| `high`   | ഇടത്തരം ടാസ്കുകൾ (റീഫാക്ടറിംഗ്, ഡീബഗ്)                     |
| `xhigh`  | ആർക്കിടെക്ചർ, ആഴത്തിലുള്ള വിശകലനം, സങ്കീർണ്ണമായ പ്രശ്നങ്ങൾ |

```bash
# ഓരോ ഇൻവൊക്കേഷനിലെയും ഓവർറൈഡ്
codex -c model_reasoning_effort=low "rename variable x to count"
codex -c model_reasoning_effort=xhigh "design the auth module"
```

Desktop-ന് ചിന്താ വാചകം റെൻഡർ ചെയ്യാൻ കഴിയുന്നതിന് (എൻക്രിപ്റ്റ് ചെയ്ത ബ്ലോബുകൾ മാത്രമല്ല), ഒരു റീസണിംഗ് **സംഗ്രഹവും** സജ്ജീകരിക്കുക:

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # പിന്തുണയ്ക്കുമ്പോൾ ultra എന്നും നൽകാം
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### OmniRoute ചിന്താ ബജറ്റ് (സെർവർ ക്രമീകരണം)

OmniRoute ഹോസ്റ്റിൽ, Codex ശ്രമം/സംഗ്രഹം അപ്സ്ട്രീമിൽ എത്തുന്നതിന് **Settings → AI → Thinking Budget** എന്നത് **`passthrough`** ആയിരിക്കണം. **`auto` മോഡ്** എല്ലാ ക്ലയന്റ് `reasoning` / `reasoning_effort` ഫീൽഡുകളും നീക്കംചെയ്യുകയും, Codex ശരിയായി കോൺഫിഗർ ചെയ്തിട്ടുണ്ടെങ്കിലും ചിന്താ പാനലുകൾ ശൂന്യമാക്കുകയും ചെയ്യും.

പൂർണ്ണ ഗൈഡ്: [THINKING_BUDGET.md](./THINKING_BUDGET.md).

കംപ്രഷനും പ്രോംപ്റ്റ് കാഷും സ്വതന്ത്രമാണ്, കൂടാതെ `passthrough`-ന് കീഴിലും പ്രവർത്തിച്ചുകൊണ്ടിരിക്കും.

## പ്രൊഫൈലുകൾ — ഓരോ മോഡലിനും/വർക്ക്ഫ്ലോയ്ക്കും പേരുനൽകിയ കോൺഫിഗറേഷനുകൾ

ഒരൊറ്റ ഫ്ലാഗ് ഉപയോഗിച്ച് മോഡലും കോൺടെക്സ്റ്റ് വിൻഡോയും മാറ്റാൻ പ്രൊഫൈലുകൾ നിങ്ങളെ അനുവദിക്കുന്നു. ഓരോ പ്രൊഫൈലും അടിസ്ഥാന `config.toml`-ന്റെ മുകളിൽ ഓവർലേ ചെയ്യുന്ന ഒരു ഫ്ലാറ്റ്
`~/.codex/<name>.config.toml` ആണ്.

> **പേരിടൽ നിയമം (Codex CLI v0.137+):** ഫയൽ `~/.codex/<name>.config.toml` ആയിരിക്കണം — **`profile-` പ്രിഫിക്സ് പാടില്ല**.
> CLI, `-p kimi-k27` → `~/.codex/kimi-k27.config.toml` ആയി പരിഹരിക്കുന്നു. ഫയൽ കണ്ടെത്തിയില്ലെങ്കിൽ, ഡിഫോൾട്ട് നിശ്ശബ്ദമായി പ്രയോഗിക്കപ്പെടും.

```bash
codex --profile kimi-k27 "analyze 10k lines of this codebase"
codex -p glm52 "architecture review"
codex --profile deepseek-flash "rename variable"   # വേഗതയേറിയത്, ചെലവ് കുറഞ്ഞത്
```

## `omniroute setup-codex` ഉപയോഗിച്ച് പ്രൊഫൈലുകൾ സ്വയമേവ സൃഷ്ടിക്കൽ

നിങ്ങൾ ഒരു VPS-ൽ OmniRoute പ്രവർത്തിപ്പിക്കുന്നുവെങ്കിൽ, നിലവിലെ മോഡൽ കാറ്റലോഗിൽ നിന്ന് പ്രൊഫൈൽ ഫയലുകൾ സ്വയമേവ സൃഷ്ടിക്കാം:

```bash
# ഒരു VPS-ൽ നിന്ന് (പോർട്ട് 20128-ലെ ലോക്കൽ OmniRoute ഉപയോഗിക്കുന്നു)
omniroute setup-codex

# ഏത് മെഷീനിൽ നിന്നും — നിങ്ങളുടെ VPS ചൂണ്ടിക്കാണിക്കുക
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# ഫയലുകൾ എഴുതാതെ പ്രിവ്യൂ ചെയ്യുക
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# GLM, Kimi പ്രൊഫൈലുകൾ മാത്രം സൃഷ്ടിക്കുക
omniroute setup-codex --only glm,kimi

# ഒരു ഇഷ്ടാനുസൃത ഡയറക്ടറിയിലേക്ക് എഴുതുക
omniroute setup-codex --codex-home /path/to/.codex
```

ഈ കമാൻഡ് `/v1/models` ലഭ്യമാക്കുകയും, അറിയപ്പെടുന്ന മോഡലുകൾക്കായി ട്യൂൺ ചെയ്ത പ്രൊഫൈലുകൾ ഉപയോഗിക്കുകയും, അനുയോജ്യമായ മറ്റ് ടെക്സ്റ്റ് മോഡലുകൾക്കായി കാറ്റലോഗ് മെറ്റാഡാറ്റയിലേക്ക് മടങ്ങുകയും, ഓരോന്നിനുമായി `~/.codex/<name>.config.toml` എഴുതുകയും ചെയ്യുന്നു. ഇത് ഐഡംപൊട്ടന്റ് ആണ് — വീണ്ടും പ്രവർത്തിപ്പിക്കുന്നത് സുരക്ഷിതമാണ്.

വിജയകരമായ പ്രൊവൈഡർ മോഡൽ കണ്ടെത്തൽ/ഇംപോർട്ട് നിലവിലെ കാറ്റലോഗിൽ മാറ്റം വരുത്തിയതിന് ശേഷം, ഇതേ പ്രൊഫൈൽ ഫയലുകൾ OmniRoute-ന് **സ്വയമേവ സമന്വയിപ്പിക്കാനും** കഴിയും. ഇത് **ഓപ്റ്റ്-ഇൻ ആണ്, ഡിഫോൾട്ടായി ഓഫാണ്**: **CLI Code dashboard**-ൽ നിന്ന് ഇത് ടോഗിൾ ചെയ്യുക ("CLI profile auto-sync" → Codex), അല്ലെങ്കിൽ `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` സജ്ജമാക്കുക (`CLI_ALLOW_CONFIG_WRITES`-നെയും ഇത് മാനിക്കുന്നു; ഡിഫോൾട്ടായി ഓൺ). പ്രവർത്തനക്ഷമമാക്കിയാൽ, ഇത് വേർതിരിച്ച `~/.codex/*.config.toml` പ്രൊഫൈൽ ഫയലുകൾ മാത്രമേ എഴുതൂ; സജീവ/ഡിഫോൾട്ട് `~/.codex/config.toml`, Codex-lb ക്രമീകരണങ്ങൾ, ഓതന്റിക്കേഷൻ, അല്ലെങ്കിൽ പ്രൊവൈഡർ തിരഞ്ഞെടുപ്പ് എന്നിവ ഒരിക്കലും മാറ്റില്ല.

## `omniroute launch-codex` ഉപയോഗിച്ച് Codex ആരംഭിക്കൽ

Codex ആരംഭിക്കുന്നതിന് മുമ്പ് നിങ്ങളുടെ OmniRoute ഇൻസ്റ്റൻസിന്റെ ആരോഗ്യനില പരിശോധിക്കുന്നു:

```bash
# ലോക്കൽ OmniRoute ഉപയോഗിച്ച് ആരംഭിക്കുക (ഡിഫോൾട്ട് പോർട്ട് 20128)
omniroute launch-codex

# ഒരു നിർദ്ദിഷ്ട പ്രൊഫൈൽ ഉപയോഗിച്ച് ആരംഭിക്കുക
omniroute launch-codex --profile kimi-k27

# ഒരു റിമോട്ട് VPS ഉപയോഗിച്ച് ആരംഭിക്കുക
omniroute launch-codex --remote http://100.x.x.x:20128/v1 --api-key sk-xxx

# അധിക ആർഗ്യുമെന്റുകൾ codex-ലേക്ക് കൈമാറുക
omniroute launch-codex --profile glm52 -- --yolo "fix this bug"
```

മാനിഫെസ്റ്റ് നിയന്ത്രിക്കുന്ന രണ്ട് പൊതുവായ എൻട്രി പോയിന്റുകളുടെയും ലക്ഷ്യമാണ് Codex
(`bin/cli/cli-manifest.mjs`):

```bash
# ഇന്ററാക്ടീവ് മോഡൽ പിക്കർ → ~/.codex/<name>.config.toml എഴുതുന്നു (TOML, env_key)
omniroute configure codex

# -c ഫ്ലാഗുകൾ വഴി omniroute പ്രൊവൈഡർ ഇൻജക്റ്റ് ചെയ്ത് codex ആരംഭിക്കുക (കോൺഫിഗറേഷൻ എഴുതില്ല)
omniroute run codex
```

## ദീർഘനേരം പ്രവർത്തിക്കുന്ന ടാസ്കുകൾ

രണ്ട് OmniRoute ഡിഫോൾട്ടുകൾക്ക് മണിക്കൂറുകളോളം നീളുന്ന Codex CLI സെഷനുകളെ നിശ്ശബ്ദമായി തകരാറിലാക്കാൻ കഴിയും. ഇവ രണ്ടും Codex CLI ക്രമീകരണങ്ങളല്ല — രണ്ടും OmniRoute ഭാഗത്താണ്. അക്കൗണ്ടുകൾ പിൻ ചെയ്യുകയും ഐഡിൽ കട്ട്ഓഫുകൾ പ്രവർത്തനരഹിതമാക്കുകയും ചെയ്യുന്ന അപ്സ്ട്രീം പ്രോക്സികളിൽനിന്ന് ഒരു കോൺഫിഗ് മൈഗ്രേറ്റ് ചെയ്യുന്ന ഉപയോക്താക്കൾ പലപ്പോഴും ഈ രണ്ട് പ്രശ്നങ്ങളും നേരിടുകയും OmniRoute-ന് “ഒരു ദീർഘ സെഷൻ നിലനിർത്താൻ കഴിയില്ല” എന്ന് നിഗമനം ചെയ്യുകയും ചെയ്യുന്നു.

| ലക്ഷണം                                                                                           | സാധ്യതയുള്ള കാരണം                                                                      | നിയന്ത്രണം               |
| ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- | ------------------------ |
| സെഷൻ അക്കൗണ്ടുകൾ മാറിക്കൊണ്ടിരിക്കുന്നു / ടേണുകൾക്കിടയിൽ പ്രോംപ്റ്റ്-കാഷ് തുടർച്ച നഷ്ടപ്പെടുന്നു | സെഷൻ അഫിനിറ്റി TTL `0` ആണ് (പ്രവർത്തനരഹിതം)                                            | `sessionAffinityTtlMs`   |

ബന്ധപ്പെട്ട ചർച്ചകൾ: [#7126](https://github.com/diegosouzapw/OmniRoute/discussions/7126) (ദീർഘ ടാസ്കുകൾ ഡ്രോപ്പ് ആകുന്നത്), [#5718](https://github.com/diegosouzapw/OmniRoute/discussions/5718) (അഫിനിറ്റി ഡിഫോൾട്ടായി പ്രവർത്തനരഹിതമായിരിക്കുന്നത് എന്തുകൊണ്ട്). ട്രാക്കിങ്: [#7287](https://github.com/diegosouzapw/OmniRoute/issues/7287).

### 1. സെഷൻ അഫിനിറ്റി — ഒരു സംഭാഷണം ഒരു അക്കൗണ്ടിലേക്ക് പിൻ ചെയ്യുക

**ഡിഫോൾട്ട്:** `sessionAffinityTtlMs = 0` (പ്രവർത്തനരഹിതം).

**ഇത് എവിടെ സജ്ജീകരിക്കണം**

- ഡാഷ്ബോർഡ് → **ക്രമീകരണങ്ങൾ → റൂട്ടിങ്** → **സെഷൻ അഫിനിറ്റി** → **അഫിനിറ്റി TTL (സെക്കൻഡുകൾ)** (`ComboDefaultsTab`)
- അല്ലെങ്കിൽ **മില്ലിസെക്കൻഡുകളിൽ** `sessionAffinityTtlMs` ഉപയോഗിച്ച് ക്രമീകരണങ്ങൾ PATCH ചെയ്യുക (Zod പരിധി `0`–`86_400_000`, അതായത് പരമാവധി 24 മണിക്കൂർ)

> #7274-ൽ Codex-ന് മാത്രമായിരുന്ന `codexSessionAffinityTtlMs` എന്നതിൽനിന്ന് പേര് മാറ്റി. ലെഗസി കീ ഇപ്പോഴും റീഡ്-ഒൺലി അപരനാമമായി സ്വീകരിക്കുന്നു; പുതിയ കോൺഫിഗുകൾ `sessionAffinityTtlMs` ഉപയോഗിക്കണം. TTL `0`-ന് മുകളിലായാൽ ഇപ്പോൾ അഫിനിറ്റി Codex-ന് മാത്രമല്ല, **ഏത്** പ്രൊവൈഡർക്കും ബാധകമാണ് — [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → സെഷൻ അഫിനിറ്റി കാണുക.

**ഇത് 0 ആയി തുടരുമ്പോൾ എന്താണ് തകരുന്നത്**

ഒന്നിലധികം ടേണുകളുള്ള Codex സംഭാഷണത്തിലെ ഓരോ ടേണും സജീവമായ കോംബോ സ്ട്രാറ്റജി ഉപയോഗിച്ച് സ്വതന്ത്രമായി റൂട്ട് ചെയ്യപ്പെടുകയും **ഓരോ ടേണിലും വ്യത്യസ്ത അക്കൗണ്ടിൽ** എത്തുകയും ചെയ്യാം. ഇത് അപ്സ്ട്രീം സെഷൻ / പ്രോംപ്റ്റ്-കാഷ് തുടർച്ചയെ തകർക്കുന്നു. TTL `0`-ന് മുകളിലായിരിക്കുമ്പോൾ മാത്രമാണ് OmniRoute, Codex സെഷൻ ഹെഡറുകളും (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) `prompt_cache_key` / `session_id` പോലുള്ള ബോഡി ഫീൽഡുകളും പരിശോധിക്കുന്നത് (`src/sse/services/auth.ts`-ലെ `extractSessionAffinityKey`).

**മണിക്കൂറുകളോളം നീളുന്ന ഒരൊറ്റ ടാസ്കിനായി ശുപാർശ ചെയ്യുന്നത്**

ടാസ്കിന്റെ പ്രതീക്ഷിക്കുന്ന യഥാർഥ സമയദൈർഘ്യത്തിന് **മുകളിലായി TTL** സജ്ജീകരിക്കുക (UI പരമാവധി **86400 സെക്കൻഡുകൾ** = 24 മണിക്കൂർ):

| പ്രതീക്ഷിക്കുന്ന ടാസ്ക് ദൈർഘ്യം | അഫിനിറ്റി TTL (UI, സെക്കൻഡുകൾ) | `sessionAffinityTtlMs` |
| ------------------------------- | ------------------------------ | ---------------------- |
| ഏതാനും മണിക്കൂറുകൾ              | `14400` (4 മണിക്കൂർ)           | `14400000`             |
| രാത്രി മുഴുവൻ / ~12 മണിക്കൂർ    | `43200` (12 മണിക്കൂർ)          | `43200000`             |
| ഒരു ദിവസം മുഴുവൻ                | `86400` (24 മണിക്കൂർ, പരമാവധി) | `86400000`             |

ഓപ്റ്റ്-ഇൻ ചെയ്യുന്നത് മനഃപൂർവമാണ്: അഫിനിറ്റി പ്രവർത്തനരഹിതമാക്കുന്നത് അക്കൗണ്ടുകൾക്കിടയിലെ ലോഡ്-ബാലൻസിങ്ങിന് മുൻഗണന നൽകുന്നു; അത് പ്രവർത്തനക്ഷമമാക്കുന്നത് ഒരു ദീർഘ ഏജന്റ് സെഷന്റെ തുടർച്ചയ്ക്ക് മുൻഗണന നൽകുന്നു. ഈ ഗൈഡ് ഡിഫോൾട്ട് **മാറ്റുന്നില്ല** — ദീർഘമായ Codex ടാസ്കുകൾ പ്രവർത്തിപ്പിക്കുന്ന ഓപ്പറേറ്റർമാർ ഓപ്റ്റ്-ഇൻ ചെയ്യണം.

### 2. സ്ട്രീം ഐഡിൽ ടൈംഔട്ട് — നിശ്ശബ്ദമായ റീസണിങ് ടേണുകൾ അവസാനിപ്പിക്കരുത്

**ഡിഫോൾട്ട്:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 മിനിറ്റ്). ഇത് സജ്ജീകരിച്ചിട്ടില്ലെങ്കിൽ `REQUEST_TIMEOUT_MS`-ൽനിന്ന് മൂല്യം സ്വീകരിക്കുന്നു; പങ്കിട്ട അടിസ്ഥാന മൂല്യവും 600000 ആണ്. [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → ടൈംഔട്ടുകൾ കാണുക.

**ഡിഫോൾട്ടിൽ എന്താണ് തകരുന്നത്**

**യഥാർത്ഥ upstream chunk ഒന്നുമില്ലാതെ** 10 മിനിറ്റിലധികം നിശ്ശബ്ദമായി തുടരുന്ന Codex reasoning / tool turn, SSE idle watchdog (`open-sse/utils/stream.ts`) നിർബന്ധിതമായി അവസാനിപ്പിക്കും. ക്ലയന്റിന് പലപ്പോഴും യാതൊരു വിശദീകരണവുമില്ലാതെ കണക്ഷൻ വിച്ഛേദിക്കപ്പെടുന്നതായി മാത്രമേ കാണൂ — ഇത് “അറിയിപ്പൊന്നുമില്ലാതെ സ്വയമേവ നിലച്ചു” എന്നതിനോട് യോജിക്കുന്നു.

നിർണായകമായ വിശദാംശം: OmniRoute-ന്റെ കൃത്രിമ SSE **heartbeat idle clock പുനഃസജ്ജമാക്കുന്നില്ല**. യഥാർത്ഥ upstream body chunk ലഭിക്കുമ്പോൾ മാത്രമാണ് `lastChunkTime` അപ്ഡേറ്റ് ചെയ്യപ്പെടുന്നത്. ഇപ്പോഴും “ചിന്തിച്ചുകൊണ്ടിരിക്കുന്ന” നിശ്ശബ്ദ മോഡലും സ്തംഭിച്ച upstream-ഉം watchdog-ന്റെ കാഴ്ചപ്പാടിൽ ഒരുപോലെയാണ്.

അനുബന്ധ Undici body inactivity: `FETCH_BODY_TIMEOUT_MS` (ഇതിന്റെയും ഡിഫോൾട്ട് അതേ 10-മിനിറ്റ് അടിസ്ഥാനപരിധിയാണ്; `0` നൽകിയാൽ ഇത് പ്രവർത്തനരഹിതമാകും). Streaming-ൽ, `FETCH_TIMEOUT_MS` കണക്ഷൻ സജ്ജീകരണം / ആദ്യ headers എന്നിവയെ മാത്രമാണ് ബാധിക്കുന്നത് — stream സജീവമായിക്കഴിഞ്ഞാൽ, സ്തംഭനങ്ങളെ നിയന്ത്രിക്കുന്നത് `STREAM_IDLE_TIMEOUT_MS`, `FETCH_BODY_TIMEOUT_MS` എന്നിവയാണ്.

**മണിക്കൂറുകൾ നീളുന്ന ഒറ്റ task-ിന് ശുപാർശ ചെയ്യുന്നത്**

OmniRoute process environment-ൽ (`.env` / compose / systemd):

```bash
# ദീർഘമായ reasoning turns-നായി stream idle + body inactivity cutoffs പ്രവർത്തനരഹിതമാക്കുക
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

അല്ലെങ്കിൽ നിങ്ങൾ പ്രതീക്ഷിക്കുന്ന ഏറ്റവും ദൈർഘ്യമേറിയ നിശ്ശബ്ദ ഇടവേളയേക്കാൾ ഉയർന്ന മൂല്യങ്ങളിലേക്ക് അവ വർധിപ്പിക്കുക (മൂല്യങ്ങൾ milliseconds-ലാണ്):

```bash
# ഉദാഹരണം: upstream chunks-ക്കിടയിൽ പരമാവധി 2 മണിക്കൂർ നിശ്ശബ്ദത അനുവദിക്കുക
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

ഈ env vars മാറ്റിയ ശേഷം OmniRoute പുനരാരംഭിക്കുക.

### കൃത്യമായ നടപടിക്രമം — മണിക്കൂറുകൾ നീളുന്ന Codex task

1. **Account pin ചെയ്യുക:** Dashboard → Settings → Routing → Session affinity → Affinity TTL = `43200` (12h) അല്ലെങ്കിൽ `86400` (പരമാവധി 24h).
2. OmniRoute-ന്റെ environment-ൽ **idle cutoffs വർധിപ്പിക്കുക / പ്രവർത്തനരഹിതമാക്കുക**:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. സാധാരണ Codex `config.toml` (`wire_api = "responses"`, ശരിയായ `base_url`, `OMNIROUTE_API_KEY`) നിലനിർത്തുക — ഈ രണ്ട് പ്രവർത്തനരീതികൾക്കായി Codex ഭാഗത്ത് affinity/idle ക്രമീകരണങ്ങളൊന്നും നിലവിലില്ല.
4. OmniRoute പുനരാരംഭിച്ച ശേഷം ദീർഘമായ Codex task ആരംഭിക്കുക.

### Defaults തീരുമാനം (#7287)

| ക്രമീകരണം                | വിതരണം ചെയ്യുന്ന ഡിഫോൾട്ട് | ഈ guide-ൽ മാറ്റണോ?                                                                                                                         |
| ------------------------ | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `sessionAffinityTtlMs`   | `0` (off)                  | **ഇല്ല** — opt-in ആയി തുടരും (load-balancing vs continuity; Discussion #5718 കാണുക)                                                        |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 min)          | **ഇല്ല** — പൊതുവായ traffic-നായി 10 മിനിറ്റായി തുടരും; ദീർഘമായ Codex പ്രവർത്തിപ്പിക്കുന്നവർ ഇത് വർധിപ്പിക്കുകയോ പ്രവർത്തനരഹിതമാക്കുകയോ വേണം |

ഏതെങ്കിലും ഒരു ഡിഫോൾട്ട് ആഗോളമായി മാറ്റുന്നത് Codex-നെ മാത്രമല്ല, ഒരു instance-ന്റെ എല്ലാ clients-ന്റെയും പ്രവർത്തനരീതി മാറ്റും. ക്രമീകരണങ്ങൾ രേഖപ്പെടുത്തുക; വ്യക്തമായ operator തീരുമാനം മറ്റൊരു നിർദേശം നൽകുന്നതുവരെ ഡിഫോൾട്ടുകൾ മാറ്റാതെ വയ്ക്കുക.

### Idle cuts നിർണയിക്കൽ

Idle watchdog പ്രവർത്തിക്കുമ്പോൾ, OmniRoute ഏകദേശം ഇത്തരത്തിലുള്ള ഒരു line log ചെയ്യും:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

`Idle timeout: no data from` എന്നതിനായി grep ചെയ്യുക (അല്ലെങ്കിൽ `stream_idle_timeout` എന്ന code / `StreamIdleTimeoutError` എന്ന error name). Provider segment എന്നത് ആ request-നായി OmniRoute ഉപയോഗിച്ചതാണ് (`codex`, മറ്റൊരു provider id, അല്ലെങ്കിൽ അജ്ഞാതമാണെങ്കിൽ `provider`) — അത് എല്ലായ്പ്പോഴും അക്ഷരാർത്ഥത്തിൽ `codex` എന്ന string ആയിരിക്കണമെന്നില്ല.

നിങ്ങളുടെ കോൺഫിഗിൽ നിന്ന് `wire_api = "chat"` നീക്കം ചെയ്യുക. `wire_api = "responses"` ആയി സജ്ജീകരിക്കുകയോ ഫീൽഡ് ഒഴിവാക്കുകയോ ചെയ്യുക (v0.138 മുതൽ സ്വതവേയുള്ള മൂല്യം `"responses"` ആണ്).

**`Error: model not found`**
ശരിയായ പ്രിഫിക്സോടെ മോഡൽ OmniRoute-ൽ നിലവിലുണ്ടെന്ന് ഉറപ്പാക്കുക. `omniroute models list` ഉപയോഗിക്കുകയോ `/dashboard/providers/<provider>` തുറക്കുകയോ ചെയ്യുക.

**`Authentication error`**
`OMNIROUTE_API_KEY` എക്സ്പോർട്ട് ചെയ്തിട്ടുണ്ടെന്ന് ഉറപ്പാക്കുക: `echo $OMNIROUTE_API_KEY`.

**`ERROR: Missing environment variable: OMNIROUTE_API_KEY`**
ആദ്യ അഭ്യർത്ഥന നടത്തുന്നതിന് മുമ്പ് env var നിലവിലുണ്ടെന്ന് Codex സാധൂകരിക്കുന്നു. പരിരക്ഷിത സെർവറുകൾക്കായി ഒരു യഥാർഥ കീ എക്സ്പോർട്ട് ചെയ്യുക; അല്ലെങ്കിൽ നിങ്ങളുടെ **ലോക്കൽ** OmniRoute ഇൻസ്റ്റൻസിന് പ്രാമാണീകരണം ആവശ്യമില്ലെങ്കിൽ `OMNIROUTE_API_KEY=local` പോലുള്ള ശൂന്യമല്ലാത്ത ഒരു പ്ലേസ്ഹോൾഡർ ഉപയോഗിക്കുക. നിങ്ങൾ അത് `~/.bashrc` അല്ലെങ്കിൽ `~/.zshrc`-ൽ ചേർത്തിട്ടുണ്ടെങ്കിൽ ഷെൽ പുനരാരംഭിക്കുക.

**`Connection refused`**
OmniRoute പ്രവർത്തിക്കുന്നുണ്ടെന്നും `base_url`-ലെ ഹോസ്റ്റ്/പോർട്ട് നിങ്ങളുടെ നെറ്റ്വർക്കിന് (ലോക്കൽ, Tailscale, അല്ലെങ്കിൽ VPS) അനുയോജ്യമാണെന്നും ഉറപ്പാക്കുക.

**കോൺടെക്സ്റ്റ് പരിധിക്ക് സമീപം സെഷൻ ക്രാഷ് ആകുന്നു**
`model_context_window`, `model_auto_compact_token_limit` എന്നിവ വ്യക്തമായി സജ്ജീകരിക്കുക. മുകളിലുള്ള കോൺടെക്സ്റ്റ് വിൻഡോ പട്ടിക കാണുക.

**കോംപാക്ഷൻ വളരെ വൈകി പ്രവർത്തിക്കുന്നു**
`model_auto_compact_token_limit` വിൻഡോയുടെ 80–85% ആയി കുറയ്ക്കുക. ഒരിക്കലും 90%-ന് മുകളിൽ സജ്ജീകരിക്കരുത്.

**പ്രൊഫൈൽ ലോഡ് ആകുന്നില്ല (`-p <name>` നിശ്ശബ്ദമായി അവഗണിക്കപ്പെടുന്നു)**
ഫയൽ `~/.codex/<name>.config.toml`-ൽ നിലവിലുണ്ടെന്ന് ഉറപ്പാക്കുക (`profile-` പ്രിഫിക്സ് പാടില്ല). `ls ~/.codex/*.config.toml` പ്രവർത്തിപ്പിക്കുക.

**ദീർഘനേരം പ്രവർത്തിക്കുന്ന Codex ടാസ്ക് ഇടയിൽ നിലയ്ക്കുന്നു / ടേണുകൾക്കിടയിൽ അക്കൗണ്ടുകൾ മാറുന്നു**
[ദീർഘനേരം പ്രവർത്തിക്കുന്ന ടാസ്കുകൾ](#long-running-tasks) കാണുക. സെഷൻ അഫിനിറ്റി പ്രവർത്തനക്ഷമമാക്കുക (TTL ടാസ്കിന്റെ ദൈർഘ്യത്തേക്കാൾ കൂടുതലാക്കുക), കൂടാതെ `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS` വർധിപ്പിക്കുകയോ പ്രവർത്തനരഹിതമാക്കുകയോ ചെയ്യുക. `Idle timeout: no data from` എന്നതിനായി OmniRoute ലോഗുകളിൽ grep ചെയ്യുക.
