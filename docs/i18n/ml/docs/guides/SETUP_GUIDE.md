## ഇൻസ്റ്റാളേഷൻ രീതികൾ

### npm (ശുപാർശ ചെയ്യുന്നത്)

```bash
npm install -g omniroute
omniroute
```

ഡാഷ്ബോർഡ് `http://localhost:20128`-ൽ തുറക്കും, API അടിസ്ഥാന URL `http://localhost:20128/v1` ആയിരിക്കും.

### pnpm

```bash
pnpm add -g omniroute@latest --allow-build=better-sqlite3 --allow-build=@swc/core
omniroute
```

> **pnpm ഉപയോക്താക്കൾ:** `better-sqlite3`, `@swc/core` എന്നിവയ്ക്കായുള്ള നേറ്റീവ് ബിൽഡ് സ്ക്രിപ്റ്റുകൾ പ്രവർത്തനക്ഷമമാക്കാൻ `--allow-build` ഫ്ലാഗ് ആവശ്യമാണ്. pnpm v11-ലെ ഗ്ലോബൽ ഇൻസ്റ്റാളേഷനുകൾക്ക് `pnpm approve-builds -g` കമാൻഡ് പിന്തുണയ്ക്കുന്നില്ല.

### Arch Linux (AUR)

```bash
yay -S omniroute-bin
systemctl --user enable --now omniroute.service
```

[AUR പാക്കേജ്](https://aur.archlinux.org/packages/omniroute-bin) OmniRoute ഇൻസ്റ്റാൾ ചെയ്യുകയും ഒരു systemd ഉപയോക്തൃ സർവീസ് നൽകുകയും ചെയ്യുന്നു.

### സോഴ്സിൽ നിന്ന്

```bash
npm install
PORT=20128 DASHBOARD_PORT=20129 NEXT_PUBLIC_BASE_URL=http://localhost:20129 npm run dev
```

> **Windows കുറിപ്പ്:** ലെഗസി `%USERPROFILE%\.omniroute` ഡയറക്ടറി നിലവിലില്ലെങ്കിൽ, ഡിഫോൾട്ടായി OmniRoute `%APPDATA%\omniroute` ഉപയോഗിക്കുന്നു. മറ്റൊരു ഡാറ്റാ-ഡയറക്ടറി ലൊക്കേഷൻ തിരഞ്ഞെടുക്കാൻ `DATA_DIR` സജ്ജമാക്കുക.

> **കുറിപ്പ്:** ആദ്യമായി പ്രവർത്തിപ്പിക്കുമ്പോൾ `npm install`, `.env.example`-ൽ നിന്ന് `.env` സ്വയമേവ സൃഷ്ടിക്കുന്നു. തുടർന്നുള്ള ഇൻസ്റ്റാളേഷനുകൾ നിലവിലുള്ള `.env` തിരുത്തിയെഴുതില്ല, അതിനാൽ ഇഷ്ടാനുസൃത മാറ്റങ്ങൾ നിലനിർത്തപ്പെടും. വീണ്ടും പ്രാരംഭ മൂല്യങ്ങൾ നൽകാൻ, വീണ്ടും പ്രവർത്തിപ്പിക്കുന്നതിന് മുമ്പ് `.env` ഇല്ലാതാക്കുക.

### Docker

Compose പ്രൊഫൈലുകളും Caddy HTTPS-ഉം ഉൾപ്പെടെയുള്ള സമ്പൂർണ്ണ Docker സജ്ജീകരണത്തിനായി [Docker ഗൈഡ്](./DOCKER_GUIDE.md) കാണുക.

### ഡെസ്ക്ടോപ്പ് ആപ്പ് (Electron)

Electron 41 + electron-builder 26.10 അടിസ്ഥാനമാക്കി നിർമ്മിച്ച ഒരു ഡെസ്ക്ടോപ്പ് റാപ്പറോടെയാണ് OmniRoute വിതരണം ചെയ്യുന്നത്. ലഭ്യമായ സ്ക്രിപ്റ്റുകൾ (വർക്ക്സ്പേസ് റൂട്ട്):

```bash
npm run electron:dev          # ഹോട്ട്-റീലോഡോടെ ഡെസ്ക്ടോപ്പ് പ്രവർത്തിപ്പിക്കുക
npm run electron:build        # നിലവിലെ OS-നായി ബിൽഡ് ചെയ്യുക (സ്വയമേവ കണ്ടെത്തുന്നു)
npm run electron:build:win    # Windows ഇൻസ്റ്റാളർ (NSIS + പോർട്ടബിൾ)
npm run electron:build:mac    # macOS (dmg + zip, arm64+x64)
npm run electron:build:linux  # Linux (AppImage + deb + rpm)
npm run electron:smoke:packaged  # പാക്കേജ് ചെയ്ത ബിൽഡ് സ്മോക്ക്-ടെസ്റ്റ് ചെയ്യുക
```

ഡെസ്ക്ടോപ്പ് ഇൻസ്റ്റാളറുകളുടെ റിലീസുകൾ GitHub Releases-ൽ അറ്റാച്ച് ചെയ്തിട്ടുണ്ട്. Electron-നെക്കുറിച്ചുള്ള സമഗ്ര വിശദീകരണത്തിനായി (സൈനിംഗ്, IPC ബ്രിഡ്ജ്, ഡിസ്ട്രോകൾ), [`ELECTRON_GUIDE.md`](./ELECTRON_GUIDE.md) കാണുക _(പിന്നീടുള്ള ഘട്ടത്തിൽ സൃഷ്ടിച്ചത്)_.

### ഹെഡ്ലെസ് സെർവർ (CI/ഓട്ടോമേഷൻ)

മേൽനോട്ടമില്ലാത്ത സജ്ജീകരണങ്ങൾക്ക് (Docker, Kubernetes, CI), ഇവ ഉപയോഗിക്കുക:

```bash
omniroute setup --non-interactive
omniroute providers test-batch
```

എൻവയോൺമെന്റ് വേരിയബിളുകളുമായി (`INITIAL_PASSWORD`, `OMNIROUTE_WS_BRIDGE_SECRET` തുടങ്ങിയവ) സംയോജിപ്പിക്കുമ്പോൾ, പൂർണ്ണമായും സ്ക്രിപ്റ്റ് ചെയ്യാവുന്ന രീതിയിൽ ഒരു OmniRoute ഇൻസ്റ്റൻസ് ആരംഭിക്കാൻ ഇത് നിങ്ങളെ അനുവദിക്കുന്നു.

### CLI ഓപ്ഷനുകൾ

| കമാൻഡ്                  | വിവരണം                                                                                                              |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `omniroute`             | സെർവർ ആരംഭിക്കുക (`PORT=20128`, API-യും ഡാഷ്ബോർഡും ഒരേ പോർട്ടിൽ)                                                    |
| `omniroute setup`       | പാസ്വേഡിനും ആദ്യ പ്രൊവൈഡറിനുമുള്ള മാർഗനിർദേശത്തോടെയുള്ള CLI ഓൺബോർഡിംഗ്                                              |
| `omniroute doctor`      | സെർവർ ആരംഭിക്കാതെ ലോക്കൽ ആരോഗ്യ പരിശോധനകൾ പ്രവർത്തിപ്പിക്കുക                                                        |
| `omniroute providers`   | CLI-യിൽ നിന്ന് പ്രൊവൈഡറുകളെ കണ്ടെത്തുക, പട്ടികപ്പെടുത്തുക, സാധൂകരിക്കുക, പരിശോധിക്കുക                               |
| `omniroute config`      | CLI ടൂൾ കോൺഫിഗറേഷൻ — കോൺഫിഗുകൾ പട്ടികപ്പെടുത്തുക, നേടുക, സജ്ജമാക്കുക, സാധൂകരിക്കുക                                  |
| `omniroute status`      | ഓഫ്ലൈൻ സ്റ്റാറ്റസ് ഡാഷ്ബോർഡ് — പതിപ്പ്, DB, ടൂളുകൾ, കോൺഫിഗ്                                                         |
| `omniroute logs`        | API-യിൽ നിന്നുള്ള ഉപയോഗ ലോഗുകൾ സ്ട്രീം ചെയ്യുക (`--follow` പിന്തുണയ്ക്കുന്നു)                                       |
| `omniroute update`      | OmniRoute അപ്ഡേറ്റുകൾ പരിശോധിക്കുകയോ പ്രയോഗിക്കുകയോ ചെയ്യുക                                                         |
| `omniroute provider`    | പ്രൊവൈഡർ കണക്ഷനുകൾ നിയന്ത്രിക്കുക — ചേർക്കുക, പട്ടികപ്പെടുത്തുക, നീക്കംചെയ്യുക, പരിശോധിക്കുക, ഡിഫോൾട്ട് സജ്ജമാക്കുക |
| `omniroute --port 3000` | കാനോണിക്കൽ/API പോർട്ട് 3000 ആയി സജ്ജമാക്കുക                                                                         |
| `omniroute --mcp`       | MCP സെർവർ ആരംഭിക്കുക (stdio ട്രാൻസ്പോർട്ട്)                                                                         |
| `omniroute --no-open`   | ബ്രൗസർ സ്വയമേവ തുറക്കാതിരിക്കുക                                                                                     |
| `omniroute --help`      | സഹായം കാണിക്കുക                                                                                                     |

ഫ്ലാഗുകളോ എൻവയോൺമെന്റ് വേരിയബിളുകളോ ഉപയോഗിച്ച് ഹെഡ്ലെസ് സജ്ജീകരണം സ്ക്രിപ്റ്റ് ചെയ്യാം:

```bash
omniroute setup --non-interactive --password "$OMNIROUTE_PASSWORD"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY" --test-provider
```

ഡാഷ്ബോർഡ് തുറക്കാതെ ലോക്കൽ ഡയഗ്നോസ്റ്റിക്സ് പ്രവർത്തിപ്പിക്കുക:

```bash
omniroute doctor
omniroute doctor --json
omniroute doctor --no-liveness
```

ഡാഷ്ബോർഡ് തുറക്കാതെ SSH-യിൽ നിന്നോ സ്ക്രിപ്റ്റുകളിൽ നിന്നോ പ്രൊവൈഡറുകളെ നിയന്ത്രിക്കുക:

```bash
omniroute providers available
omniroute providers available --search openai
omniroute providers available --category api-key
omniroute providers list
omniroute providers test <id-or-name>
omniroute providers test-all
omniroute providers validate
```

## CLI ടൂൾ കോൺഫിഗറേഷൻ

### 1) പ്രൊവൈഡറുകളെ ബന്ധിപ്പിച്ച് API കീ സൃഷ്ടിക്കുക

1. Dashboard → `Providers` തുറന്ന് കുറഞ്ഞത് ഒരു പ്രൊവൈഡറെങ്കിലും ബന്ധിപ്പിക്കുക (OAuth അല്ലെങ്കിൽ API കീ).
2. Dashboard → `Endpoints` തുറന്ന് ഒരു API കീ സൃഷ്ടിക്കുക.
3. (ഐച്ഛികം) Dashboard → `Combos` തുറന്ന് നിങ്ങളുടെ ഫാൾബാക്ക് ചെയിൻ സജ്ജീകരിക്കുക.

### 2) നിങ്ങളുടെ കോഡിംഗ് ടൂൾ സജ്ജീകരിക്കുക

```txt
അടിസ്ഥാന URL: http://localhost:20128/v1
API കീ:       [Endpoint പേജിൽനിന്ന് പകർത്തുക]
മോഡൽ:        if/qwen3.8-max-preview (അല്ലെങ്കിൽ ഏതെങ്കിലും പ്രൊവൈഡർ/മോഡൽ പ്രിഫിക്സ്)
```

നിങ്ങളുടെ എഡിറ്ററിന് `Authorization: Bearer ...` അയയ്ക്കാൻ കഴിയുന്നില്ലെങ്കിൽ, പകരം ടോക്കൺ ഉൾപ്പെടുത്തിയ കോംപാറ്റിബിലിറ്റി ബേസ് ഉപയോഗിക്കുക:

```txt
അടിസ്ഥാന URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/
മോഡലുകളുടെ URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/models
ചാറ്റ് URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/chat/completions
Ollama ടാഗുകളുടെ URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/api/tags
```

Claude Code, Codex CLI, Cursor, Cline, OpenClaw, OpenCode, OpenAI-അനുയോജ്യ SDK-കൾ എന്നിവയ്ക്കൊപ്പം പ്രവർത്തിക്കുന്നു.

#### `setup-*` ഉപയോഗിച്ച് സ്വയമേവ കോൺഫിഗർ ചെയ്യുക

അടിസ്ഥാന URL-ഉം കീയും കൈകൊണ്ട് ഒട്ടിക്കുന്നതിന് പകരം, തത്സമയ മോഡൽ കാറ്റലോഗിൽനിന്ന് ഓരോ ടൂളിന്റെയും
സ്വന്തം കോൺഫിഗറേഷൻ എഴുതാൻ OmniRoute-നെ അനുവദിക്കുക. ഓരോ ടൂളിനും ഓരോ കമാൻഡ്:

```bash
omniroute setup-codex        # ~/.codex/<name>.config.toml പ്രൊഫൈലുകൾ
omniroute setup-claude       # ~/.claude/profiles/<name>/settings.json
omniroute setup-opencode     # ~/.config/opencode/opencode.json (openai-അനുയോജ്യം)
omniroute setup-cline        # Cline CLI + VS Code എക്സ്റ്റൻഷൻ ക്രമീകരണങ്ങൾ
omniroute setup-kilo         # Kilo Code
omniroute setup-continue     # ~/.continue/config.yaml (Continue / cn)
omniroute setup-cursor       # Cursor-ന്റെ ആപ്പിനുള്ളിലെ ഘട്ടങ്ങൾ പ്രിന്റ് ചെയ്യുന്നു
omniroute setup-roo          # Roo Code ഇംപോർട്ട് + autoImport പോയിന്റർ
omniroute setup-crush        # ~/.config/crush/crush.json
omniroute setup-goose        # ~/.config/goose/config.yaml
omniroute setup-aider        # ~/.aider.conf.yml
omniroute setup-qwen         # ~/.qwen/settings.json + ~/.qwen/.env
```

ഒരു ലോക്കൽ ടൂൾ **റിമോട്ട്** OmniRoute-നായി കോൺഫിഗർ ചെയ്യാൻ ഓരോന്നും `--remote <url> --api-key <key>` സ്വീകരിക്കുന്നു; പ്രിവ്യൂ ചെയ്യാൻ `--dry-run`-ഉം സ്വീകരിക്കുന്നു. ശരിയായ
env ഉൾപ്പെടുത്തി, യാതൊരു കോൺഫിഗറേഷനും എഴുതാതെ ഒരു CLI ആരംഭിക്കാൻ പൊതുവായ ലോഞ്ചറായ
`omniroute run <target>` (claude, codex, aider, goose, opencode, qwen, gemini) ഉപയോഗിക്കുക;
പഴയ ഓരോ-ടൂൾ ലോഞ്ചറുകളായ `omniroute launch` (Claude Code),
`omniroute launch-codex` (Codex) എന്നിവയും തുടർന്നും ലഭ്യമാണ്.

പൂർണ്ണ പട്ടികയ്ക്കായി (ഓരോ കമാൻഡും എന്താണ് എഴുതുന്നത്, എല്ലാ ഫ്ലാഗുകളും, ലോക്കൽ vs റിമോട്ട്, അടിസ്ഥാന-URL
`/v1` കൺവെൻഷനുകൾ), **[CLI ഇന്റഗ്രേഷനുകൾ](./CLI-INTEGRATIONS.md)** കാണുക.

ഓരോ ടൂളിനുമുള്ള വിശദമായ കോൺഫിഗറേഷനായി (Claude Code, Codex CLI, Cursor, Cline, OpenClaw, Kilo Code, Copilot എന്നിവയും അതിലധികവും), സമർപ്പിതമായ **[CLI ടൂൾസ് ഗൈഡ്](../reference/CLI-TOOLS.md)** കാണുക.

stdio മോഡിൽ MCP ട്രാൻസ്പോർട്ട് ആരംഭിക്കുക:

ശുപാർശ ചെയ്യുന്ന പരിശോധനാ പ്രവാഹം:

```bash
# 1. MCP സെർവർ ആരംഭിക്കുക
omniroute --mcp

# 2. നിങ്ങളുടെ MCP ക്ലയന്റിൽനിന്ന് വിളിക്കുക:
omniroute_get_health        # സിസ്റ്റത്തിന്റെ ആരോഗ്യനില തിരികെ നൽകണം
omniroute_list_combos       # സജീവ കോമ്പോകൾ തിരികെ നൽകണം

# 3. അല്ലെങ്കിൽ പൂർണ്ണ E2E സ്യൂട്ട് പ്രവർത്തിപ്പിക്കുക:
npm run test:protocols:e2e
```

## ടൈംഔട്ട് കോൺഫിഗറേഷൻ

### അടിസ്ഥാന ടൈംഔട്ടുകൾ

മിക്ക ഡിപ്ലോയ്മെന്റുകൾക്കും, ഈ രണ്ട് വേരിയബിളുകൾ മാത്രം മതി:

| വേരിയബിൾ                 | ഡിഫോൾട്ട്                                 | ഉദ്ദേശ്യം                                                                                                                                                                                                |
| ------------------------ | ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `REQUEST_TIMEOUT_MS`     | `600000`                                  | അപ്സ്ട്രീം പ്രതികരണം ആരംഭിക്കുന്നതിനുള്ള ടൈംഔട്ട്, മറഞ്ഞിരിക്കുന്ന Undici ടൈംഔട്ടുകൾ, TLS ഫിംഗർപ്രിന്റ് അഭ്യർത്ഥനകൾ, API ബ്രിഡ്ജ് അഭ്യർത്ഥന/പ്രോക്സി ടൈംഔട്ടുകൾ എന്നിവയ്ക്കുള്ള പങ്കിട്ട അടിസ്ഥാന മൂല്യം |
| `STREAM_IDLE_TIMEOUT_MS` | `REQUEST_TIMEOUT_MS`-ൽ നിന്ന് ലഭിക്കുന്നു | OmniRoute SSE സ്ട്രീം നിർത്തുന്നതിന് മുമ്പ് സ്ട്രീമിംഗ് ചങ്കുകൾക്കിടയിൽ അനുവദനീയമായ പരമാവധി ഇടവേള                                                                                                        |

പിന്നോട്ടുള്ള അനുയോജ്യത നിലനിർത്തിയിട്ടുണ്ട്: നിലവിലുള്ള `FETCH_TIMEOUT_MS`, `API_BRIDGE_PROXY_TIMEOUT_MS`, മറ്റ് ഓരോ ലെയറിനുമുള്ള ടൈംഔട്ട് വേരിയബിളുകൾ എന്നിവ തുടർന്നും പ്രവർത്തിക്കുകയും പങ്കിട്ട അടിസ്ഥാന മൂല്യത്തെ അസാധുവാക്കുകയും ചെയ്യും.

### പ്രൊവൈഡർ-നിർദ്ദിഷ്ട കുറിപ്പുകൾ

Claude Code-ന് അനുയോജ്യമായ അപ്സ്ട്രീമുകൾക്കായി (`anthropic-compatible-cc-*`), പ്രൊവൈഡർ ഭാഗത്തെ റീഡ് ടൈംഔട്ടുകൾ നിങ്ങളുടെ env കോൺഫിഗറേഷനുമായി ഒത്തുചേരുന്നതിനായി പരിഹരിച്ച ഫെച്ച് ടൈംഔട്ടിൽ നിന്ന് ഔട്ട്ബൗണ്ട് `X-Stainless-Timeout` ഹെഡർ OmniRoute നിർണ്ണയിക്കുന്നു.

മൂന്നാം കക്ഷി Claude Code-ന് അനുയോജ്യമായ റിവേഴ്സ് പ്രോക്സികൾക്കായി, OmniRoute ഡിഫോൾട്ട് `anthropic-beta` സെറ്റ് പരിമിതമായി നിലനിർത്തുന്നു; കൂടാതെ `Client Cache Control` `Auto` ആയി നിലനിർത്തുമ്പോൾ, ക്ലയന്റ് നൽകിയ `cache_control` മാർക്കറുകൾ മാത്രം ഫോർവേഡ് ചെയ്യുന്നു. അപ്സ്ട്രീമിന് റീഡാക്റ്റ് ചെയ്ത Claude തിങ്കിംഗ് സ്ട്രീമുകൾ പ്രത്യേകമായി ആവശ്യമായിരിക്കുമ്പോൾ മാത്രം ഓരോ കണക്ഷനിലുമുള്ള "റീഡാക്റ്റ്-തിങ്കിംഗ് ബീറ്റ പ്രവർത്തനക്ഷമമാക്കുക" ടോഗിൾ പ്രവർത്തനക്ഷമമാക്കുക.

### വിപുലമായ ടൈംഔട്ട് ഓവർറൈഡുകൾ

| വേരിയബിൾ                                 | ഡിഫോൾട്ട്                                                     | ഉദ്ദേശ്യം                                                                                        |
| ---------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `FETCH_TIMEOUT_MS`                       | `REQUEST_TIMEOUT_MS`-ൽ നിന്ന് ലഭിക്കുന്നു                     | പ്രതികരണ ഹെഡറുകൾ ലഭിക്കുന്നതുവരെ ഉപയോഗിക്കുന്ന അപ്സ്ട്രീം പ്രതികരണം ആരംഭിക്കുന്നതിനുള്ള ടൈംഔട്ട് |
| `FETCH_HEADERS_TIMEOUT_MS`               | `FETCH_TIMEOUT_MS`-ൽ നിന്ന് ലഭിക്കുന്നു                       | അപ്സ്ട്രീം പ്രതികരണ ഹെഡറുകൾ സ്വീകരിക്കുന്നതിനുള്ള Undici സമയപരിധി                                |
| `FETCH_BODY_TIMEOUT_MS`                  | `FETCH_TIMEOUT_MS`-ൽ നിന്ന് ലഭിക്കുന്നു                       | അപ്സ്ട്രീം ബോഡി ചങ്കുകൾക്കിടയിലുള്ള Undici സമയപരിധി (`0` ഇത് പ്രവർത്തനരഹിതമാക്കുന്നു)            |
| `FETCH_CONNECT_TIMEOUT_MS`               | `30000`                                                       | Undici TCP കണക്ഷൻ ടൈംഔട്ട്                                                                       |
| `FETCH_KEEPALIVE_TIMEOUT_MS`             | `4000`                                                        | Undici നിഷ്ക്രിയ keep-alive സോക്കറ്റ് ടൈംഔട്ട്                                                   |
| `TLS_CLIENT_TIMEOUT_MS`                  | `FETCH_TIMEOUT_MS`-ൽ നിന്ന് ലഭിക്കുന്നു                       | `wreq-js` വഴി നടത്തുന്ന TLS ഫിംഗർപ്രിന്റ് അഭ്യർത്ഥനകൾക്കുള്ള ടൈംഔട്ട്                            |
| `API_BRIDGE_PROXY_TIMEOUT_MS`            | `REQUEST_TIMEOUT_MS`-ൽ നിന്ന് ലഭിക്കുന്നു അല്ലെങ്കിൽ `600000` | API പോർട്ടിൽ നിന്ന് ഡാഷ്ബോർഡ് പോർട്ടിലേക്കുള്ള `/v1` പ്രോക്സി ഫോർവേഡിംഗിനുള്ള ടൈംഔട്ട്           |
| `API_BRIDGE_SERVER_REQUEST_TIMEOUT_MS`   | `max(API_BRIDGE_PROXY_TIMEOUT_MS, 300000)`                    | API ബ്രിഡ്ജ് സെർവറിലെ ഇൻകമിംഗ് അഭ്യർത്ഥനാ ടൈംഔട്ട്                                               |
| `API_BRIDGE_SERVER_HEADERS_TIMEOUT_MS`   | `60000`                                                       | API ബ്രിഡ്ജ് സെർവറിലെ ഇൻകമിംഗ് ഹെഡർ ടൈംഔട്ട്                                                     |
| `API_BRIDGE_SERVER_KEEPALIVE_TIMEOUT_MS` | `5000`                                                        | API ബ്രിഡ്ജ് സെർവറിലെ keep-alive ടൈംഔട്ട്                                                        |
| `API_BRIDGE_SERVER_SOCKET_TIMEOUT_MS`    | `0`                                                           | API ബ്രിഡ്ജ് സെർവറിലെ സോക്കറ്റ് നിഷ്ക്രിയതാ ടൈംഔട്ട് (`0` ഇത് പ്രവർത്തനരഹിതമാക്കുന്നു)           |

> **കുറിപ്പ്:** സ്ട്രീമിംഗ് അഭ്യർത്ഥനകൾക്കായി, `FETCH_TIMEOUT_MS` കണക്ഷൻ സജ്ജീകരണം / ആദ്യ അപ്സ്ട്രീം പ്രതികരണത്തിനായുള്ള കാത്തിരിപ്പ് എന്നിവ മാത്രം ഉൾക്കൊള്ളുന്നു. സ്ട്രീം സജീവമായിക്കഴിഞ്ഞാൽ, യഥാർത്ഥമായൊരു തടസ്സം (`STREAM_IDLE_TIMEOUT_MS`) അല്ലെങ്കിൽ Undici ബോഡി നിഷ്ക്രിയത (`FETCH_BODY_TIMEOUT_MS`) ഉണ്ടായാൽ മാത്രമേ OmniRoute അത് നിർത്തുകയുള്ളൂ.

### റിവേഴ്സ് പ്രോക്സി അനുയോജ്യത

Nginx, Caddy, Cloudflare അല്ലെങ്കിൽ മറ്റൊരു റിവേഴ്സ് പ്രോക്സിക്ക് പിന്നിലാണ് നിങ്ങൾ OmniRoute പ്രവർത്തിപ്പിക്കുന്നതെങ്കിൽ, പ്രോക്സി ടൈംഔട്ടുകളും നിങ്ങളുടെ OmniRoute സ്ട്രീം/ഫെച്ച് ടൈംഔട്ടുകളേക്കാൾ കൂടുതലാണെന്ന് ഉറപ്പാക്കുക.

## സ്പ്ലിറ്റ്-പോർട്ട് മോഡ്

വിപുലമായ സാഹചര്യങ്ങൾക്കായി (റിവേഴ്സ് പ്രോക്സി, കണ്ടെയ്നർ നെറ്റ്വർക്കിംഗ്) API-യും Dashboard-ഉം വ്യത്യസ്ത പോർട്ടുകളിൽ പ്രവർത്തിപ്പിക്കുക:

```bash
PORT=20128 DASHBOARD_PORT=20129 omniroute
# API:       http://localhost:20128/v1
# Dashboard: http://localhost:20129
```

## Void Linux (`xbps-src`) ടെംപ്ലേറ്റ്

Void Linux ഉപയോക്താക്കൾക്ക് `xbps-src` ഉപയോഗിച്ച് ഒരു നേറ്റീവ് പാക്കേജ് ബിൽഡ് ചെയ്യാം. ഈ ബ്ലോക്ക് `srcpkgs/omniroute/template` ആയി സേവ് ചെയ്യുക:

```bash
# 'omniroute'-നുള്ള ടെംപ്ലേറ്റ് ഫയൽ
pkgname=omniroute
version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"
maintainer="zenobit <zenobit@disroot.org>"
license="MIT"
homepage="https://github.com/diegosouzapw/OmniRoute"
distfiles="https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz"
# ഓരോ റിലീസിനും ചെക്ക്സം വീണ്ടും സൃഷ്ടിക്കാൻ:
#   curl -L -o /tmp/omniroute.tar.gz "https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz" && sha256sum /tmp/omniroute.tar.gz
checksum=PLACEHOLDER_REGENERATE_PER_RELEASE
system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	NODE_ENV=development npm ci --ignore-scripts
	npm run build
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	rm -rf .next/standalone/node_modules/@img

	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
		touch "${DESTDIR}/usr/lib/omniroute/${_d}/.keep"
	done

	cat > "${WRKDIR}/omniroute" <<'EOF'
#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"
mkdir -p "${DATA_DIR}"
exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```

## അൺഇൻസ്റ്റാൾ ചെയ്യൽ

| കമാൻഡ്                   | പ്രവർത്തനം                                                                                                        |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| `npm run uninstall`      | സിസ്റ്റം ആപ്പ് നീക്കംചെയ്യുന്നു, എന്നാൽ `~/.omniroute`-ലുള്ള **നിങ്ങളുടെ DB-യും കോൺഫിഗറേഷനുകളും നിലനിർത്തുന്നു**. |
| `npm run uninstall:full` | ആപ്പ് നീക്കംചെയ്യുകയും **എല്ലാ കോൺഫിഗറേഷനുകളും കീകളും ഡാറ്റാബേസുകളും ശാശ്വതമായി മായ്ക്കുകയും ചെയ്യുന്നു**.        |

> എല്ലാ രീതികളിലുമുള്ള വിശദമായ അൺഇൻസ്റ്റാൾ നിർദ്ദേശങ്ങൾക്കായി [UNINSTALL.md](./UNINSTALL.md) കാണുക.
