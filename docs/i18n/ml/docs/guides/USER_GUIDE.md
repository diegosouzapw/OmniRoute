## 🎯 ഉപയോഗ സാഹചര്യങ്ങൾ

### സാഹചര്യം 1: "എനിക്ക് Claude Pro സബ്സ്ക്രിപ്ഷൻ ഉണ്ട്"

**പ്രശ്നം:** ഉപയോഗിക്കാത്ത ക്വാട്ട കാലഹരണപ്പെടുന്നു, തീവ്രമായ കോഡിംഗിനിടെ നിരക്ക് പരിധികൾ നേരിടുന്നു

```
കോംബോ: "maximize-claude"
  1. cc/claude-opus-4-7        (സബ്സ്ക്രിപ്ഷൻ പൂർണ്ണമായി ഉപയോഗിക്കുക)
  2. glm/glm-4.7               (ക്വാട്ട തീരുമ്പോൾ ചെലവുകുറഞ്ഞ ബാക്കപ്പ്)
  3. if/qwen3.8-max-preview       (അടിയന്തര സാഹചര്യത്തിനുള്ള സൗജന്യ ഫാൾബാക്ക്)

പ്രതിമാസ ചെലവ്: $20 (സബ്സ്ക്രിപ്ഷൻ) + ~$5 (ബാക്കപ്പ്) = ആകെ $25
$20 നൽകുകയും പരിധികളിൽ എത്തുകയും ചെയ്യുന്നതുമായി താരതമ്യപ്പെടുത്തുമ്പോൾ = നിരാശ
```

### സാഹചര്യം 2: "എനിക്ക് ചെലവൊന്നും വേണ്ട"

**പ്രശ്നം:** സബ്സ്ക്രിപ്ഷനുകൾ താങ്ങാനാകുന്നില്ല, വിശ്വസനീയമായ AI കോഡിംഗ് ആവശ്യമാണ്

```
കോംബോ: "zero-cost"
  1. if/kimi-k2.7-code          (സൗജന്യ ആക്സസ് പട്ടികപ്പെടുത്തിയിരിക്കുന്നു; നിരക്ക് പരിധികൾ ബാധകമായേക്കാം)
  2. kr/qwen3-coder-next        (Kiro സൗജന്യ ഫാൾബാക്ക്)

പ്രതിമാസ ചെലവ്: $0
ഗുണനിലവാരം: നിങ്ങളുടെ വർക്ക്ലോഡിനായി മോഡൽ, പരിധികൾ, സ്വകാര്യത, SLA എന്നിവ പരിശോധിക്കുക
```

### സാഹചര്യം 3: "തടസ്സങ്ങളില്ലാതെ 24/7 കോഡിംഗ് വേണം"

**പ്രശ്നം:** സമയപരിധികൾ അടുത്തിരിക്കുന്നു, പ്രവർത്തനരഹിതമായ സമയം താങ്ങാനാകില്ല

### ആഗോള npm ഇൻസ്റ്റാളേഷൻ (ശുപാർശ ചെയ്യുന്നത്)

```bash
npm install -g omniroute

# കോൺഫിഗറേഷൻ ഡയറക്ടറി സൃഷ്ടിക്കുക
mkdir -p ~/.omniroute

# .env ഫയൽ സൃഷ്ടിക്കുക (.env.example കാണുക)
cp .env.example ~/.omniroute/.env

# സെർവർ ആരംഭിക്കുക
omniroute
# അല്ലെങ്കിൽ ഇഷ്ടാനുസൃത പോർട്ടോടെ:
omniroute --port 3000
```

CLI സ്വയമേവ `~/.omniroute/.env` അല്ലെങ്കിൽ `./.env` എന്നതിൽ നിന്ന് `.env` ലോഡ് ചെയ്യുന്നു.

### ട്രേ മോഡ്

സിസ്റ്റം ട്രേയിൽ OmniRoute ആരംഭിക്കുക:

```bash
omniroute serve --tray
```

സെർവറും ട്രേയും തയ്യാറായ ശേഷം കമാൻഡ് അവസാനിക്കുന്നു.

ടെർമിനൽ ഇല്ലാതെയും സെർവർ പ്രവർത്തനം തുടരുന്നു.

ട്രേ മോഡ് macOS, Windows, ഗ്രാഫിക്കൽ Linux സെഷനുകൾ എന്നിവ പിന്തുണയ്ക്കുന്നു. ട്രേ മോഡ് ഡാഷ്ബോർഡ് സ്വയമേവ തുറക്കില്ല.

ഈ പ്രവർത്തനങ്ങൾക്കായി ട്രേ മെനു ഉപയോഗിക്കുക:

- ഡാഷ്ബോർഡ് തുറക്കുക.
- `/dashboard/logs` തുറക്കുക.
- സ്വയമേവ ആരംഭിക്കൽ മാറ്റുക.
- OmniRoute നിർത്തുക.

ഈ ഓപ്ഷനുകൾക്കൊപ്പം `--tray` ഉപയോഗിക്കരുത്:

- `--daemon`
- `--log`
- `--no-recovery`

ഈ മോഡുകൾക്ക് വ്യത്യസ്ത പ്രോസസ് ഉടമസ്ഥത ആവശ്യമാണ്.

അടുത്ത മെഷീൻ ലോഗിനിൽ സ്റ്റാർട്ടപ്പ് പ്രവർത്തനക്ഷമമാക്കുക:

```bash
omniroute autostart enable
```

macOS, Windows, ഗ്രാഫിക്കൽ Linux സെഷനുകൾ എന്നിവയിൽ സ്വയമേവ ആരംഭിക്കൽ ട്രേ മോഡ് ഉപയോഗിക്കുന്നു. ഹെഡ്ലെസ് Linux നിലവിലുള്ള systemd യൂസർ സർവീസ് ഉപയോഗിക്കുന്നു.

ലോഗിൻ സമയത്തെ സ്റ്റാർട്ടപ്പ് പ്രവർത്തനരഹിതമാക്കുക:

```bash
omniroute autostart disable
```

### അൺഇൻസ്റ്റാൾ ചെയ്യൽ

OmniRoute ഇനി ആവശ്യമില്ലാത്തപ്പോൾ, പൂർണ്ണമായി നീക്കം ചെയ്യുന്നതിനായി ഞങ്ങൾ രണ്ട് ദ്രുത സ്ക്രിപ്റ്റുകൾ നൽകുന്നു:

| കമാൻഡ്                   | പ്രവർത്തനം                                                                                                     |
| ------------------------ | -------------------------------------------------------------------------------------------------------------- |
| `npm run uninstall`      | സിസ്റ്റം ആപ്പ് നീക്കംചെയ്യുന്നു, എന്നാൽ `~/.omniroute`-ലെ **നിങ്ങളുടെ DB-യും കോൺഫിഗറേഷനുകളും നിലനിർത്തുന്നു**. |
| `npm run uninstall:full` | ആപ്പ് നീക്കംചെയ്യുന്നതിനൊപ്പം **എല്ലാ കോൺഫിഗറേഷനുകളും കീകളും ഡാറ്റാബേസുകളും ശാശ്വതമായി മായ്ക്കുന്നു**.         |

> കുറിപ്പ്: ഈ കമാൻഡുകൾ പ്രവർത്തിപ്പിക്കാൻ, OmniRoute പ്രോജക്റ്റ് ഫോൾഡറിലേക്ക് പോകുക (നിങ്ങൾ അത് ക്ലോൺ ചെയ്തിട്ടുണ്ടെങ്കിൽ) തുടർന്ന് അവ പ്രവർത്തിപ്പിക്കുക. പകരമായി, ആഗോളമായി ഇൻസ്റ്റാൾ ചെയ്തിട്ടുണ്ടെങ്കിൽ, `npm uninstall -g omniroute` പ്രവർത്തിപ്പിച്ചാൽ മതി.

### VPS വിന്യാസം

```bash
git clone https://github.com/diegosouzapw/OmniRoute.git
cd OmniRoute && npm install && npm run build

export JWT_SECRET="your-secure-secret-change-this"
export INITIAL_PASSWORD="your-password"

export HOSTNAME="0.0.0.0"

npm run start
# അല്ലെങ്കിൽ: pm2 start npm --name omniroute -- start
```

### PM2 വിന്യാസം (കുറഞ്ഞ മെമ്മറി)

പരിമിതമായ RAM ഉള്ള സെർവറുകൾക്ക്, മെമ്മറി പരിധി ഓപ്ഷൻ ഉപയോഗിക്കുക:

```bash
# 512MB പരിധിയോടെ (ഡിഫോൾട്ട്)
pm2 start npm --name omniroute -- start

# അല്ലെങ്കിൽ ഇഷ്ടാനുസൃത മെമ്മറി പരിധിയോടെ
OMNIROUTE_MEMORY_MB=512 pm2 start npm --name omniroute -- start

# അല്ലെങ്കിൽ ecosystem.config.js ഉപയോഗിച്ച്
pm2 start ecosystem.config.js
```

`ecosystem.config.js` സൃഷ്ടിക്കുക:

```javascript
module.exports = {
  apps: [
    {
      name: "omniroute",
      script: "npm",
      args: "start",
      env: {
        NODE_ENV: "production",
        OMNIROUTE_MEMORY_MB: "512",
        JWT_SECRET: "your-secret",
        INITIAL_PASSWORD: "your-password",
      },
      node_args: "--max-old-space-size=512",
      max_memory_restart: "300M",
    },
  ],
};
```

### Docker

```bash
# ഇമേജ് ബിൽഡ് ചെയ്യുക (ഡിഫോൾട്ട് = codex/claude/droid മുൻകൂട്ടി ഇൻസ്റ്റാൾ ചെയ്ത runner-cli)
docker build -t omniroute:cli .

# പോർട്ടബിൾ മോഡ് (ശുപാർശ ചെയ്യുന്നത്)
```

### Void Linux (xbps-src)

Void Linux ഉപയോക്താക്കൾക്ക് `xbps-src` ക്രോസ്-കംപൈലേഷൻ ഫ്രെയിംവർക്ക് ഉപയോഗിച്ച് OmniRoute നേറ്റീവായി പാക്കേജ് ചെയ്ത് ഇൻസ്റ്റാൾ ചെയ്യാം. ആവശ്യമായ `better-sqlite3` നേറ്റീവ് ബൈൻഡിങ്ങുകൾക്കൊപ്പം Node.js സ്റ്റാൻഡ്എലോൺ ബിൽഡും ഇത് സ്വയമേവ നിർവഹിക്കുന്നു.

<details>
<summary><b>xbps-src ടെംപ്ലേറ്റ് കാണുക</b></summary>

```bash
# 'omniroute'-നുള്ള ടെംപ്ലേറ്റ് ഫയൽ
pkgname=omniroute
version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"
maintainer="zenobit <zenobit@disroot.org>"
license="MIT"
homepage="https://github.com/diegosouzapw/OmniRoute"
distfiles="https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz"
checksum=009400afee90a9f32599d8fe734145cfd84098140b7287990183dde45ae2245b
system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	# node-gyp-നുള്ള ലക്ഷ്യ CPU ആർക്കിടെക്ചർ നിർണ്ണയിക്കുക
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	# 1) എല്ലാ ഡിപ്പൻഡൻസികളും ഇൻസ്റ്റാൾ ചെയ്യുക – സ്ക്രിപ്റ്റുകൾ ഒഴിവാക്കുക
	NODE_ENV=development npm ci --ignore-scripts

	# 2) Next.js സ്റ്റാൻഡ്എലോൺ ബണ്ടിൽ ബിൽഡ് ചെയ്യുക
	npm run build

	# 3) സ്റ്റാറ്റിക് അസറ്റുകൾ സ്റ്റാൻഡ്എലോണിലേക്ക് പകർത്തുക
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	# 4) better-sqlite3 നേറ്റീവ് ബൈൻഡിങ് കംപൈൽ ചെയ്യുക
	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	# 5) കംപൈൽ ചെയ്ത ബൈൻഡിങ് സ്റ്റാൻഡ്എലോൺ ബണ്ടിലിൽ സ്ഥാപിക്കുക
	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	# 6) ആർക്കിടെക്ചർ-നിർദ്ദിഷ്ട sharp ബണ്ടിലുകൾ നീക്കംചെയ്യുക
	rm -rf .next/standalone/node_modules/@img

	# 7) Next.js സ്റ്റാറ്റിക് വിശകലനം ഒഴിവാക്കിയ pino റൺടൈം ഡിപ്പൻഡൻസികൾ പകർത്തുക:
	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	# പോസ്റ്റ്-ഇൻസ്റ്റാൾ ഹുക്ക് ശൂന്യമായ Next.js ആപ്പ് റൂട്ടർ ഡയറക്ടറികൾ നീക്കംചെയ്യുന്നത് തടയുക
	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
		touch "${DESTDIR}/usr/lib/omniroute/${_d}/.keep"
	done

	cat > "${WRKDIR}/omniroute" <<'EOF'
#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"
mkdir -p "${DATA_DIR}"
exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```

### എൻവയോൺമെന്റ് വേരിയബിളുകൾ

| വേരിയബിൾ                                | ഡിഫോൾട്ട്                            | വിവരണം                                                                                                                                                   |
| --------------------------------------- | ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `JWT_SECRET`                            | `omniroute-default-secret-change-me` | JWT സൈനിംഗ് രഹസ്യം (**പ്രൊഡക്ഷനിൽ മാറ്റുക**)                                                                                                             |
| `INITIAL_PASSWORD`                      | `CHANGEME`                           | ആദ്യ ലോഗിൻ പാസ്വേഡ്                                                                                                                                      |
| `DATA_DIR`                              | `~/.omniroute`                       | ഡാറ്റ ഡയറക്ടറി (db, ഉപയോഗം, ലോഗുകൾ)                                                                                                                      |
| `PORT`                                  | ഫ്രെയിംവർക്ക് ഡിഫോൾട്ട്              | സർവീസ് പോർട്ട് (ഉദാഹരണങ്ങളിൽ `20128`)                                                                                                                    |
| `HOSTNAME`                              | ഫ്രെയിംവർക്ക് ഡിഫോൾട്ട്              | ബൈൻഡ് ഹോസ്റ്റ് (Docker-ൽ ഡിഫോൾട്ടായി `0.0.0.0`)                                                                                                          |
| `NODE_ENV`                              | റൺടൈം ഡിഫോൾട്ട്                      | വിന്യാസത്തിനായി `production` ആയി സജ്ജമാക്കുക                                                                                                             |
| `NEXT_PUBLIC_BASE_URL`                  | `http://localhost:20128`             | ഡാഷ്ബോർഡിൽ പ്രദർശിപ്പിക്കുകയും സെർവറിന് ലഭ്യമാക്കുകയും ചെയ്യുന്ന പൊതു അടിസ്ഥാന URL (പഴയ `BASE_URL`-നെ മാറ്റിസ്ഥാപിക്കുന്നു)                              |
| `NEXT_PUBLIC_CLOUD_URL`                 | `https://omniroute.dev`              | ക്ലൗഡ് സിങ്ക് എൻഡ്പോയിന്റിന്റെ അടിസ്ഥാന URL (പഴയ `CLOUD_URL`-നെ മാറ്റിസ്ഥാപിക്കുന്നു)                                                                    |
| `API_KEY_SECRET`                        | `endpoint-proxy-api-key-secret`      | സൃഷ്ടിക്കുന്ന API കീകൾക്കായുള്ള HMAC രഹസ്യം                                                                                                              |
| `REQUIRE_API_KEY`                       | `false`                              | `/v1/*`-ൽ Bearer API കീ നിർബന്ധമാക്കുക                                                                                                                   |
| `ALLOW_API_KEY_REVEAL`                  | `false`                              | പ്രാമാണീകരിച്ച ഡാഷ്ബോർഡ് ഉപയോക്താക്കൾക്ക് ആവശ്യാനുസരണം സംഭരിച്ചിരിക്കുന്ന API കീയുടെ പൂർണ്ണ മൂല്യങ്ങൾ വെളിപ്പെടുത്താൻ അനുവദിക്കുക                        |
| `PROVIDER_LIMITS_SYNC_INTERVAL_MINUTES` | `70`                                 | കാഷ് ചെയ്ത Provider Limits ഡാറ്റയ്ക്കുള്ള സെർവർ-സൈഡ് പുതുക്കൽ ഇടവേള; UI പുതുക്കൽ ബട്ടണുകൾ തുടർന്നും മാനുവൽ സിങ്ക് പ്രവർത്തിപ്പിക്കും                     |

### ഇഷ്ടാനുസൃത മോഡലുകൾ

ആപ്പ് അപ്ഡേറ്റിനായി കാത്തിരിക്കാതെ ഏത് പ്രൊവൈഡറിലേക്കും ഏത് മോഡൽ ID-യും ചേർക്കുക:

```bash
# API വഴി
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# പട്ടിക: curl http://localhost:20128/api/provider-models?provider=openai
# നീക്കംചെയ്യുക: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

അല്ലെങ്കിൽ Dashboard ഉപയോഗിക്കുക: **Providers → [Provider] → Custom Models**.

കുറിപ്പുകൾ:

- OpenRouter, OpenAI/Anthropic-അനുയോജ്യ പ്രൊവൈഡറുകൾ എന്നിവ **Available Models**-ൽനിന്ന് മാത്രമാണ് നിയന്ത്രിക്കുന്നത്. മാനുവൽ ചേർക്കൽ, ഇംപോർട്ട്, ഓട്ടോ-സിങ്ക് എന്നിവയെല്ലാം ഒരേ ലഭ്യമായ-മോഡൽ പട്ടികയിലാണ് എത്തുന്നത്, അതിനാൽ ആ പ്രൊവൈഡറുകൾക്കായി പ്രത്യേക Custom Models വിഭാഗമില്ല.
- നിയന്ത്രിത ലഭ്യമായ-മോഡൽ ഇംപോർട്ടുകൾ നൽകാത്ത പ്രൊവൈഡറുകൾക്കായാണ് **Custom Models** വിഭാഗം ഉദ്ദേശിച്ചിരിക്കുന്നത്.

### OmniRoute പിയറുകളെ ശൃംഖലയാക്കൽ

മറ്റൊരു OmniRoute ഗേറ്റ്വേയെ **Custom OpenAI-compatible** പ്രൊവൈഡറായി ചേർക്കാം. പിയറിന്റെ
`/v1` അടിസ്ഥാന URL-ഉം ആ പിയർ നൽകിയ, പ്രത്യേകം സജ്ജീകരിച്ച, ഏറ്റവും കുറഞ്ഞ പ്രത്യേകാവകാശമുള്ള API കീയും ഉപയോഗിക്കുക.

പരസ്പര അല്ലെങ്കിൽ മൾട്ടി-ഹോപ്പ് ശൃംഖലകൾക്കായി, എല്ലാ ഗേറ്റ്വേയിലും ഓപ്റ്റ്-ഇൻ ലൂപ്പ് ഗാർഡ് പ്രവർത്തനക്ഷമമാക്കുക:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

വ്യക്തമായി അനുവദനീയ പട്ടികയിൽ ചേർത്ത പിയർ URL-ലേക്ക് അയയ്ക്കുന്ന അഭ്യർത്ഥനകൾക്ക് മാത്രമാണ്
`X-OmniRoute-Peer-Trace` ഹെഡർ ലഭിക്കുക. ആവർത്തിക്കുന്ന instance ID-യോ തീർന്നുപോയ ഹോപ്പ്
ബജറ്റോ ഗേറ്റ്വേ HTTP `508 Loop Detected` ഉപയോഗിച്ച് നിരസിക്കും; സാധാരണ അപ്സ്ട്രീം പ്രൊവൈഡറുകൾക്ക് പിയർ മെറ്റാഡാറ്റയൊന്നും ലഭിക്കില്ല.

പിയർ ശൃംഖലപ്പെടുത്തൽ ഡാറ്റാബേസ് റെപ്ലിക്കേഷനോ ഹോസ്റ്റ് ഫെയിൽഓവറോ അല്ല. ഓരോ ഗേറ്റ്വേയും സ്വതന്ത്രമായ
SQLite സ്റ്റേറ്റ്, കാഷുകൾ, നിരക്ക് കൗണ്ടറുകൾ, സെഷനുകൾ എന്നിവ നിലനിർത്തുന്നു. active/passive അല്ലെങ്കിൽ active/active ലഭ്യതയ്ക്കായി ആരോഗ്യ പരിശോധനയുള്ള റിവേഴ്സ് പ്രോക്സിയോ ക്ലയന്റ്
ഫെയിൽഓവറോ ഉപയോഗിക്കുക; ഒരേ SQLite ഡാറ്റാബേസ് പ്രവർത്തിച്ചുകൊണ്ടിരിക്കുന്ന ഒന്നിലധികം OmniRoute ഇൻസ്റ്റൻസുകളിൽ ഒരിക്കലും മൗണ്ട് ചെയ്യരുത്.

### സമർപ്പിത പ്രൊവൈഡർ റൂട്ടുകൾ

മോഡൽ സാധൂകരണത്തോടെ അഭ്യർത്ഥനകൾ ഒരു നിർദ്ദിഷ്ട പ്രൊവൈഡറിലേക്ക് നേരിട്ട് റൂട്ട് ചെയ്യുക:

```bash
POST http://localhost:20128/v1/providers/openai/chat/completions
POST http://localhost:20128/v1/providers/openai/embeddings
POST http://localhost:20128/v1/providers/fireworks/images/generations
```

പ്രൊവൈഡർ പ്രിഫിക്സ് ഇല്ലെങ്കിൽ അത് സ്വയമേവ ചേർക്കും. പൊരുത്തമില്ലാത്ത മോഡലുകൾ `400` തിരികെ നൽകും.

### നെറ്റ്വർക്ക് പ്രോക്സി കോൺഫിഗറേഷൻ

```bash
# ഗ്ലോബൽ പ്രോക്സി സജ്ജീകരിക്കുക
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"global": {"type":"http","host":"proxy.example.com","port":"8080"}}'

# ഓരോ പ്രൊവൈഡറിനുമുള്ള പ്രോക്സി
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"providers": {"openai": {"type":"socks5","host":"proxy.example.com","port":"1080"}}}'

# പ്രോക്സി പരിശോധിക്കുക
curl -X POST http://localhost:20128/api/settings/proxy/test \
  -d '{"proxy":{"type":"socks5","host":"proxy.example.com","port":"1080"}}'
```

**മുൻഗണനാക്രമം:** കീ-നിർദ്ദിഷ്ടം → കോംബോ-നിർദ്ദിഷ്ടം → പ്രൊവൈഡർ-നിർദ്ദിഷ്ടം → ഗ്ലോബൽ → എൻവയോൺമെന്റ്.

### മോഡൽ കാറ്റലോഗ് API

```bash
curl http://localhost:20128/api/models/catalog
```

തരങ്ങളോടുകൂടി (`chat`, `embedding`, `image`) പ്രൊവൈഡർ അനുസരിച്ച് ഗ്രൂപ്പുചെയ്ത മോഡലുകൾ തിരികെ നൽകുന്നു.

### ക്ലൗഡ് സിങ്ക്

- ഉപകരണങ്ങളിലുടനീളം പ്രൊവൈഡറുകൾ, കോംബോകൾ, ക്രമീകരണങ്ങൾ എന്നിവ സിങ്ക് ചെയ്യുക
- ടൈംഔട്ട് + fail-fast സഹിതമുള്ള സ്വയമേവയുള്ള പശ്ചാത്തല സിങ്ക്
- പ്രൊഡക്ഷനിൽ സെർവർ-സൈഡ് `NEXT_PUBLIC_BASE_URL`/`NEXT_PUBLIC_CLOUD_URL` തിരഞ്ഞെടുക്കുക

### Cloudflare Quick Tunnel

- Docker-നും മറ്റ് സ്വയം ഹോസ്റ്റ് ചെയ്ത വിന്യാസങ്ങൾക്കുമായി **Dashboard → Endpoints**-ൽ ലഭ്യമാണ്
- നിങ്ങളുടെ നിലവിലെ OpenAI-അനുയോജ്യമായ `/v1` എൻഡ്പോയിന്റിലേക്ക് ഫോർവേഡ് ചെയ്യുന്ന താൽക്കാലിക `https://*.trycloudflare.com` URL സൃഷ്ടിക്കുന്നു
- ആദ്യം പ്രവർത്തനക്ഷമമാക്കുമ്പോൾ ആവശ്യമുണ്ടെങ്കിൽ മാത്രം `cloudflared` ഇൻസ്റ്റാൾ ചെയ്യുന്നു; പിന്നീടുള്ള പുനരാരംഭങ്ങളിൽ അതേ നിയന്ത്രിത ബൈനറി വീണ്ടും ഉപയോഗിക്കുന്നു
- OmniRoute അല്ലെങ്കിൽ കണ്ടെയ്നർ പുനരാരംഭിച്ചതിനുശേഷം Quick Tunnels സ്വയമേവ പുനഃസ്ഥാപിക്കില്ല; ആവശ്യമുള്ളപ്പോൾ ഡാഷ്ബോർഡിൽനിന്ന് വീണ്ടും പ്രവർത്തനക്ഷമമാക്കുക
- ടണൽ URL-കൾ താൽക്കാലികമാണ്; ടണൽ നിർത്തി/ആരംഭിക്കുന്ന ഓരോ തവണയും അവ മാറും
- നിയന്ത്രിത കണ്ടെയ്നറുകളിലെ ശബ്ദമേറിയ QUIC UDP ബഫർ മുന്നറിയിപ്പുകൾ ഒഴിവാക്കാൻ, നിയന്ത്രിത Quick Tunnels ഡിഫോൾട്ടായി HTTP/2 ട്രാൻസ്പോർട്ട് ഉപയോഗിക്കുന്നു
- നിയന്ത്രിത ട്രാൻസ്പോർട്ട് തിരഞ്ഞെടുപ്പ് അസാധുവാക്കണമെങ്കിൽ `CLOUDFLARED_PROTOCOL=quic` അല്ലെങ്കിൽ `auto` സജ്ജീകരിക്കുക
- നിയന്ത്രിത ഡൗൺലോഡിന് പകരം മുൻകൂട്ടി ഇൻസ്റ്റാൾ ചെയ്ത `cloudflared` ബൈനറി ഉപയോഗിക്കാനാണ് താൽപ്പര്യമെങ്കിൽ `CLOUDFLARED_BIN` സജ്ജീകരിക്കുക
- Cloudflare Quick Tunnel, Tailscale Funnel, ngrok Tunnel പാനലുകൾ **Settings → Appearance**-ൽ കാണിക്കാനോ മറയ്ക്കാനോ കഴിയും. ഒരു പാനൽ മറയ്ക്കുന്നത് പ്രവർത്തിക്കുന്ന ടണൽ നിർത്തുകയില്ല.

### LLM ഗേറ്റ്വേ ഇന്റലിജൻസ് (ഘട്ടം 9)

- **സെമാന്റിക് കാഷ്** — സ്ട്രീമിംഗ് അല്ലാത്ത, temperature=0 പ്രതികരണങ്ങൾ സ്വയമേവ കാഷ് ചെയ്യുന്നു (`X-OmniRoute-No-Cache: true` ഉപയോഗിച്ച് മറികടക്കാം)
- **അഭ്യർത്ഥന ഐഡംപൊട്ടൻസി** — `Idempotency-Key` അല്ലെങ്കിൽ `X-Request-Id` ഹെഡർ വഴി 5s-നുള്ളിലെ അഭ്യർത്ഥനകളുടെ പകർപ്പുകൾ നീക്കംചെയ്യുന്നു
- **പുരോഗതി ട്രാക്കിംഗ്** — `X-OmniRoute-Progress: true` ഹെഡർ വഴി ഓപ്റ്റ്-ഇൻ SSE `event: progress` ഇവന്റുകൾ

### റൂട്ടിംഗ് തന്ത്രങ്ങൾ

**Dashboard → Settings → Routing** വഴി കോൺഫിഗർ ചെയ്യുക. ഏറ്റവും കൂടുതൽ ഉപയോഗിക്കുന്ന ആറ് തന്ത്രങ്ങൾ ഡാഷ്ബോർഡ് പ്രദർശിപ്പിക്കുന്നു; കോംബോകളും ഓട്ടോ-റൂട്ടറും ആന്തരികമായി കൂടുതൽ വിപുലമായ ഒരു സെറ്റിനെ പിന്തുണയ്ക്കുന്നു.

**ഡാഷ്ബോർഡിൽ ദൃശ്യമാകുന്ന തന്ത്രങ്ങൾ (അക്കൗണ്ട്-തല റൂട്ടിംഗ്):**

| തന്ത്രം                        | വിവരണം                                                                                                                               |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| **Fill First**                 | മുൻഗണനാക്രമത്തിൽ അക്കൗണ്ടുകൾ ഉപയോഗിക്കുന്നു — ലഭ്യമല്ലാതാകുന്നതുവരെ പ്രാഥമിക അക്കൗണ്ട് എല്ലാ അഭ്യർത്ഥനകളും കൈകാര്യം ചെയ്യും          |
| **Round Robin**                | കോൺഫിഗർ ചെയ്യാവുന്ന സ്റ്റിക്കി പരിധിയോടെ എല്ലാ അക്കൗണ്ടുകളിലൂടെയും ക്രമമായി മാറുന്നു (ഡിഫോൾട്ട്: ഓരോ അക്കൗണ്ടിനും 3 കോളുകൾ)          |
| **P2C (Power of Two Choices)** | ക്രമരഹിതമായി 2 അക്കൗണ്ടുകൾ തിരഞ്ഞെടുത്ത് കൂടുതൽ ആരോഗ്യമുള്ളതിലേക്ക് റൂട്ട് ചെയ്യുന്നു — ആരോഗ്യനില പരിഗണിച്ച് ലോഡ് സന്തുലിതമാക്കുന്നു |
| **Random**                     | Fisher-Yates ഷഫിൾ ഉപയോഗിച്ച് ഓരോ അഭ്യർത്ഥനയ്ക്കും ക്രമരഹിതമായി ഒരു അക്കൗണ്ട് തിരഞ്ഞെടുക്കുന്നു                                       |
| **Least Used**                 | ഏറ്റവും പഴയ `lastUsedAt` ടൈംസ്റ്റാമ്പുള്ള അക്കൗണ്ടിലേക്ക് റൂട്ട് ചെയ്ത് ട്രാഫിക് തുല്യമായി വിതരണം ചെയ്യുന്നു                         |
| **Cost Optimized**             | ഏറ്റവും കുറഞ്ഞ മുൻഗണനാ മൂല്യമുള്ള അക്കൗണ്ടിലേക്ക് റൂട്ട് ചെയ്ത് ഏറ്റവും കുറഞ്ഞ ചെലവുള്ള പ്രൊവൈഡറുകൾക്കായി ഒപ്റ്റിമൈസ് ചെയ്യുന്നു     |

**വിപുലമായ കോംബോ, ഓട്ടോ തന്ത്രങ്ങൾ** (ഓരോ കോംബോയ്ക്കും അല്ലെങ്കിൽ `auto/*` പ്രിഫിക്സുകൾ വഴി കോൺഫിഗർ ചെയ്യാവുന്നത് — [AUTO-COMBO.md](../routing/AUTO-COMBO.md) കാണുക):

- `priority` — കർശനമായ ക്രമം, ഒരിക്കലും round-robin ചെയ്യില്ല
- `weighted` — ഓരോ മോഡലിനുമുള്ള വെയിറ്റുകൾ അനുസരിച്ചുള്ള ആനുപാതിക ട്രാഫിക് വിഭജനം
- `fill-first` — പരിധിയിൽ എത്തുന്നതുവരെ ആദ്യ മോഡൽ ഉപയോഗിക്കുക
- `round-robin` / `strict-random` / `random`
- `p2c` (Power of Two Choices)
- `least-used`, `cost-optimized`
- `auto` — എല്ലാ കാൻഡിഡേറ്റുകളിലുമായി സ്കോർ-അധിഷ്ഠിതം
- `lkgp` (Last Known Good Provider) — അവസാനം വിജയിച്ച പ്രൊവൈഡറിലേക്ക് പിൻ ചെയ്യുന്നു, തുടർന്ന് നിയമങ്ങളിലേക്ക് ഫാൾബാക്ക് ചെയ്യുന്നു
- `context-optimized` — ഏറ്റവും വലിയ ഒഴിവുള്ള കോൺടെക്സ്റ്റ് വിൻഡോയുള്ള മോഡൽ തിരഞ്ഞെടുക്കുന്നു
- `context-relay` — തുടർ ടേണുകൾക്കായി ദീർഘ-കോൺടെക്സ്റ്റ് മോഡലുകളെ ശൃംഖലയാക്കുന്നു

#### ബാഹ്യ സ്റ്റിക്കി സെഷൻ ഹെഡർ

ബാഹ്യ സെഷൻ അഫിനിറ്റിക്കായി (ഉദാഹരണത്തിന്, റിവേഴ്സ് പ്രോക്സികൾക്ക് പിന്നിലുള്ള Claude Code/Codex ഏജന്റുകൾ), ഇങ്ങനെ അയയ്ക്കുക:

```http
X-Session-Id: your-session-key
```

OmniRoute `x_session_id`-യും സ്വീകരിക്കുകയും പ്രാബല്യത്തിലുള്ള സെഷൻ കീ `X-OmniRoute-Session-Id`-ൽ തിരികെ നൽകുകയും ചെയ്യുന്നു.

Nginx ഉപയോഗിക്കുകയും അണ്ടർസ്കോർ-രൂപത്തിലുള്ള ഹെഡറുകൾ അയയ്ക്കുകയും ചെയ്യുന്നെങ്കിൽ, ഇത് പ്രവർത്തനക്ഷമമാക്കുക:

```nginx
underscores_in_headers on;
```

#### വൈൽഡ്കാർഡ് മോഡൽ അപരനാമങ്ങൾ

മോഡൽ പേരുകൾ റീമാപ്പ് ചെയ്യാൻ വൈൽഡ്കാർഡ് പാറ്റേണുകൾ സൃഷ്ടിക്കുക:

```
പാറ്റേൺ: claude-sonnet-*     →  ലക്ഷ്യം: cc/claude-sonnet-4-6
പാറ്റേൺ: gpt-*               →  ലക്ഷ്യം: gh/gpt-5.3-codex
```

വൈൽഡ്കാർഡുകൾ `*` (ഏത് പ്രതീകങ്ങളും), `?` (ഒറ്റ പ്രതീകം) എന്നിവ പിന്തുണയ്ക്കുന്നു.

#### ഫാൾബാക്ക് ശൃംഖലകൾ

എല്ലാ അഭ്യർത്ഥനകൾക്കും ബാധകമായ ഗ്ലോബൽ ഫാൾബാക്ക് ശൃംഖലകൾ നിർവചിക്കുക:

```
ശൃംഖല: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### പ്രതിരോധശേഷിയും സർക്യൂട്ട് ബ്രേക്കറുകളും

**Dashboard → Settings → Resilience** വഴി കോൺഫിഗർ ചെയ്യുക.

OmniRoute അഞ്ച് ഘടകങ്ങളോടെ പ്രൊവൈഡർ-തല പ്രതിരോധശേഷി നടപ്പിലാക്കുന്നു:

1. **അഭ്യർത്ഥന ക്യൂവും പേസിംഗും** — സിസ്റ്റം-തല അഭ്യർത്ഥന രൂപപ്പെടുത്തൽ:
   - **മിനിറ്റിലെ അഭ്യർത്ഥനകൾ (RPM)** — ഓരോ അക്കൗണ്ടിനും മിനിറ്റിലെ പരമാവധി അഭ്യർത്ഥനകൾ
   - **അഭ്യർത്ഥനകൾക്കിടയിലെ ഏറ്റവും കുറഞ്ഞ സമയം** — അഭ്യർത്ഥനകൾക്കിടയിലെ മില്ലിസെക്കൻഡിലുള്ള ഏറ്റവും കുറഞ്ഞ ഇടവേള
   - **പരമാവധി സമകാലിക അഭ്യർത്ഥനകൾ** — ഓരോ അക്കൗണ്ടിനുമുള്ള പരമാവധി ഒരേസമയം നടക്കുന്ന അഭ്യർത്ഥനകൾ

2. **കണക്ഷൻ കൂൾഡൗൺ** — വീണ്ടും ശ്രമിക്കാവുന്ന പരാജയങ്ങൾക്ക് ശേഷം ഒരൊറ്റ കണക്ഷനുവേണ്ടി ഓരോ auth-type-നുമുള്ള കോൺഫിഗറേഷൻ:
   - **അടിസ്ഥാന കൂൾഡൗൺ** — വീണ്ടും ശ്രമിക്കാവുന്ന അപ്സ്ട്രീം പരാജയങ്ങൾക്കുള്ള ഡിഫോൾട്ട് കൂൾഡൗൺ കാലയളവ്
   - **അപ്സ്ട്രീം റീട്രൈ സൂചനകൾ ഉപയോഗിക്കുക** — നൽകിയിട്ടുണ്ടെങ്കിൽ ആധികാരികമായ `Retry-After` അല്ലെങ്കിൽ റീസെറ്റ് സൂചനകൾ മാനിക്കുന്നു
   - **പരമാവധി ബാക്ക്ഓഫ് ഘട്ടങ്ങൾ** — ആവർത്തിച്ചുള്ള പരാജയങ്ങൾക്കുള്ള പരമാവധി എക്സ്പോണൻഷ്യൽ ബാക്ക്ഓഫ് നില

3. **പ്രൊവൈഡർ സർക്യൂട്ട് ബ്രേക്കർ** — എൻഡ്-ടു-എൻഡ് പ്രൊവൈഡർ പരാജയങ്ങൾ ട്രാക്ക് ചെയ്യുന്നു, കോൺഫിഗർ ചെയ്ത മുന്നറിയിപ്പ് പരിധിയിൽ ഒരു പ്രൊവൈഡറെ ദുർബലമായതായി അടയാളപ്പെടുത്തുന്നു, കോൺഫിഗർ ചെയ്ത പരാജയ പരിധിയിലെത്തുമ്പോൾ ബ്രേക്കർ തുറക്കുന്നു:
   - **ദുർബലാവസ്ഥാ പരിധി** — `DEGRADED`-ലേക്ക് പ്രവേശിക്കുന്നതിന് മുമ്പുള്ള തുടർച്ചയായ പ്രൊവൈഡർ പരാജയങ്ങൾ
   - **പരാജയ പരിധി** — `OPEN`-ലേക്ക് പ്രവേശിക്കുന്നതിന് മുമ്പുള്ള തുടർച്ചയായ പ്രൊവൈഡർ പരാജയങ്ങൾ
   - **റീസെറ്റ് ടൈംഔട്ട്** — പ്രൊവൈഡറെ വീണ്ടും പരിശോധിക്കുന്നതിന് മുമ്പുള്ള സമയപരിധി
   - **CLOSED** (ആരോഗ്യകരം) — അഭ്യർത്ഥനകൾ സാധാരണപോലെ ഒഴുകുന്നു
   - **DEGRADED** — ഉയർന്ന പരാജയങ്ങൾ ട്രാക്ക് ചെയ്യുന്നതിനിടെ അഭ്യർത്ഥനകൾ തുടർന്നും ഒഴുകുന്നു
   - **OPEN** — ആവർത്തിച്ചുള്ള പരാജയങ്ങൾക്ക് ശേഷം പ്രൊവൈഡറെ താൽക്കാലികമായി തടയുന്നു
   - **HALF_OPEN** — പ്രൊവൈഡർ വീണ്ടെടുത്തോയെന്ന് പരിശോധിക്കുന്നു

   കണക്ഷൻ-സ്കോപ്പിലുള്ള `429` നിരക്ക് പരിധികൾ **Connection Cooldown**-ൽ തന്നെ തുടരുന്നു; അവ പ്രൊവൈഡർ ബ്രേക്കറിലേക്ക് കണക്കാക്കില്ല.

   പ്രൊവൈഡർ ബ്രേക്കറിന്റെ റൺടൈം സ്റ്റേറ്റ് **Dashboard → Health**-ൽ മാത്രമാണ് കാണിക്കുന്നത്.

4. **കൂൾഡൗണിനായി കാത്തിരിക്കുക** — എല്ലാ കാൻഡിഡേറ്റ് കണക്ഷനുകളും ഇതിനകം കൂൾഡൗണിലാണെങ്കിൽ, OmniRoute-ന് ഏറ്റവും നേരത്തെ അവസാനിക്കുന്ന കൂൾഡൗണിനായി കാത്തിരുന്ന് അതേ ക്ലയന്റ് അഭ്യർത്ഥന സ്വയമേവ വീണ്ടും ശ്രമിക്കാം.

5. **നിരക്ക് പരിധി സ്വയം കണ്ടെത്തൽ** — അപ്സ്ട്രീം പ്രൊവൈഡറുകൾ വ്യക്തമായ കാത്തിരിപ്പ് കാലയളവുകൾ തിരികെ നൽകുമ്പോൾ, ക്രമീകരണം പ്രവർത്തനക്ഷമമാണെങ്കിൽ ആ സൂചനകൾ ലോക്കൽ കണക്ഷൻ കൂൾഡൗണിനെ അസാധുവാക്കും.

**പ്രൊ ടിപ്പ്:** ഒരു ഔട്ടേജിനുശേഷം തത്സമയ പ്രൊവൈഡർ ബ്രേക്കറുകൾ പരിശോധിക്കാനും റീസെറ്റ് ചെയ്യാനും **Health** പേജ് ഉപയോഗിക്കുക. Resilience പേജ് കോൺഫിഗറേഷൻ മാത്രമാണ് മാറ്റുന്നത്.

### ഡാറ്റാബേസ് എക്സ്പോർട്ട് / ഇംപോർട്ട്

**Dashboard → Settings → System & Storage**-ൽ ഡാറ്റാബേസ് ബാക്കപ്പുകൾ നിയന്ത്രിക്കുക.

| പ്രവർത്തനം                                | വിവരണം                                                                                                                                                                          |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ഡാറ്റാബേസ് എക്സ്പോർട്ട് ചെയ്യുക**       | നിലവിലെ SQLite ഡാറ്റാബേസ് ഒരു `.sqlite` ഫയലായി ഡൗൺലോഡ് ചെയ്യുന്നു                                                                                                               |
| **എല്ലാം എക്സ്പോർട്ട് ചെയ്യുക (.tar.gz)** | ഡാറ്റാബേസ്, ക്രമീകരണങ്ങൾ, കോംബോകൾ, പ്രൊവൈഡർ കണക്ഷനുകൾ (ക്രെഡൻഷ്യലുകൾ ഇല്ല), API കീ മെറ്റാഡാറ്റ എന്നിവ ഉൾപ്പെടുന്ന പൂർണ്ണ ബാക്കപ്പ് ആർക്കൈവ് ഡൗൺലോഡ് ചെയ്യുന്നു                  |
| **ഡാറ്റാബേസ് ഇംപോർട്ട് ചെയ്യുക**          | നിലവിലെ ഡാറ്റാബേസ് മാറ്റിസ്ഥാപിക്കാൻ ഒരു `.sqlite` ഫയൽ അപ്ലോഡ് ചെയ്യുന്നു. `DISABLE_SQLITE_AUTO_BACKUP=true` അല്ലാത്ത പക്ഷം ഇംപോർട്ടിന് മുമ്പുള്ള ബാക്കപ്പ് സ്വയമേവ സൃഷ്ടിക്കും |

```bash
# API: ഡാറ്റാബേസ് എക്സ്പോർട്ട് ചെയ്യുക
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: എല്ലാം എക്സ്പോർട്ട് ചെയ്യുക (പൂർണ്ണ ആർക്കൈവ്)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: ഡാറ്റാബേസ് ഇംപോർട്ട് ചെയ്യുക
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**ഇംപോർട്ട് സാധൂകരണം:** ഇംപോർട്ട് ചെയ്ത ഫയലിന്റെ സമഗ്രത (SQLite pragma പരിശോധന), ആവശ്യമായ പട്ടികകൾ (`provider_connections`, `provider_nodes`, `combos`, `api_keys`), വലുപ്പം (പരമാവധി 100MB) എന്നിവ സാധൂകരിക്കുന്നു.

**ഉപയോഗ സാഹചര്യങ്ങൾ:**

- മെഷീനുകൾക്കിടയിൽ OmniRoute മൈഗ്രേറ്റ് ചെയ്യുക
- ദുരന്ത വീണ്ടെടുപ്പിനായി ബാഹ്യ ബാക്കപ്പുകൾ സൃഷ്ടിക്കുക
- ടീം അംഗങ്ങൾക്കിടയിൽ കോൺഫിഗറേഷനുകൾ പങ്കിടുക (എല്ലാം എക്സ്പോർട്ട് ചെയ്യുക → ആർക്കൈവ് പങ്കിടുക)

| **General**    | സിസ്റ്റം സ്റ്റോറേജ് ഉപകരണങ്ങൾ, ഡിഫോൾട്ട് പെരുമാറ്റം, എൻഡ്പോയിന്റ് ടണൽ ദൃശ്യത                                                                                                        |
| **Appearance** | തീം നിയന്ത്രണങ്ങൾ (ലൈറ്റ്/ഡാർക്ക്/സിസ്റ്റം), സൈഡ്ബാർ ദൃശ്യത, Cloudflare/Tailscale/ngrok ടണൽ കാർഡുകൾക്കുള്ള പാനൽ ടോഗിളുകൾ                                                            |
| **AI**         | ചിന്താ ബജറ്റ് (passthrough / auto-strip / custom / adaptive — [THINKING_BUDGET.md](./THINKING_BUDGET.md) കാണുക), ഗ്ലോബൽ സിസ്റ്റം പ്രോംപ്റ്റ്, പ്രോംപ്റ്റ് കാഷ് സ്ഥിതിവിവരക്കണക്കുകൾ |
| **Security**   | ലോഗിൻ/പാസ്വേഡ് ക്രമീകരണങ്ങൾ, IP ആക്സസ് നിയന്ത്രണം, `/models`-നുള്ള API auth, പ്രൊവൈഡർ തടയൽ, പ്രോംപ്റ്റ്-ഇൻജക്ഷൻ ഗാർഡ്                                                               |
| **Routing**    | ഗ്ലോബൽ റൂട്ടിംഗ് തന്ത്രം (Fill First / Round Robin / P2C / Random / Least Used / Cost Optimized), വൈൽഡ്കാർഡ് മോഡൽ അപരനാമങ്ങൾ, ഫാൾബാക്ക് ശൃംഖലകൾ, കോംബോ ഡിഫോൾട്ടുകൾ                  |
| **Resilience** | അഭ്യർത്ഥന ക്യൂ, കണക്ഷൻ കൂൾഡൗൺ, പ്രൊവൈഡർ ബ്രേക്കർ കോൺഫിഗറേഷൻ, കൂൾഡൗണിനായി കാത്തിരിക്കുന്ന പെരുമാറ്റം                                                                                 |
| **Advanced**   | ഗ്ലോബൽ പ്രോക്സി കോൺഫിഗറേഷൻ (HTTP/SOCKS5), ഓരോ പ്രൊവൈഡറിനുമുള്ള പ്രോക്സി ഓവർറൈഡുകൾ                                                                                                   |

General ഇനി വായിക്കാൻ മാത്രം കഴിയുന്ന ലോഗിംഗ്, കാഷ് കുറിപ്പുകൾ തനിപ്പകർപ്പാക്കുന്നില്ല. ഡാറ്റാബേസ് നിലനിർത്തൽ,
ഒപ്റ്റിമൈസേഷൻ ക്രമീകരണങ്ങൾ `/api/settings/database` വഴി സ്ഥിരമായി സൂക്ഷിക്കുന്നു; മാനുവൽ കാഷ് നീക്കംചെയ്യൽ
`DELETE /api/cache` ഉപയോഗിക്കുന്നു. അഭ്യർത്ഥന, പ്രോക്സി ലോഗ് വരികളുടെ പരമാവധി എണ്ണം
`CALL_LOGS_TABLE_MAX_ROWS`, `PROXY_LOGS_TABLE_MAX_ROWS` എന്നിവ നിയന്ത്രിക്കുന്നു.

### ഓഡിയോ ട്രാൻസ്ക്രിപ്ഷൻ

OpenAI-അനുയോജ്യമായ എൻഡ്പോയിന്റ് വഴി OmniRoute ഓഡിയോ ട്രാൻസ്ക്രിപ്ഷൻ പിന്തുണയ്ക്കുന്നു:

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data

# curl ഉപയോഗിച്ചുള്ള ഉദാഹരണം
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@audio.mp3" \
  -F "model=openai/whisper-1"
```

`deepgram/nova-3` നേറ്റീവ് Deepgram റൂട്ടാണ്; അതിന് ഒരു Deepgram API കീ ആവശ്യമാണ്.
OpenRouter മാത്രമാണ് കോൺഫിഗർ ചെയ്തിരിക്കുന്നതെങ്കിൽ, `openrouter/deepgram/nova-3` ഉപയോഗിക്കുക.

**ശബ്ദത്തിൽനിന്ന് ടെക്സ്റ്റിലേക്ക് (ട്രാൻസ്ക്രിപ്ഷൻ)** പ്രൊവൈഡറുകൾ:

### കോംബോ ബാലൻസിംഗ് തന്ത്രങ്ങൾ

**Dashboard → Combos → Create/Edit → Strategy**-ൽ ഓരോ കോംബോയ്ക്കുമുള്ള ബാലൻസിംഗ് കോൺഫിഗർ ചെയ്യുക.

| തന്ത്രം            | വിവരണം                                                                                                        |
| ------------------ | ------------------------------------------------------------------------------------------------------------- |
| **Round-Robin**    | മോഡലുകളിലൂടെ ക്രമാനുഗതമായി മാറുന്നു                                                                           |
| **Priority**       | എല്ലായ്പ്പോഴും ആദ്യ മോഡൽ പരീക്ഷിക്കുന്നു; പിശക് ഉണ്ടായാൽ മാത്രം ഫാൾബാക്ക് ചെയ്യുന്നു                          |
| **Random**         | ഓരോ അഭ്യർത്ഥനയ്ക്കും കോംബോയിൽനിന്ന് ഒരു ക്രമരഹിത മോഡൽ തിരഞ്ഞെടുക്കുന്നു                                       |
| **Weighted**       | ഓരോ മോഡലിനും നൽകിയ വെയിറ്റുകൾ അടിസ്ഥാനമാക്കി ആനുപാതികമായി റൂട്ട് ചെയ്യുന്നു                                   |
| **Least-Used**     | സമീപകാലത്ത് ഏറ്റവും കുറച്ച് അഭ്യർത്ഥനകളുള്ള മോഡലിലേക്ക് റൂട്ട് ചെയ്യുന്നു (കോംബോ മെട്രിക്കുകൾ ഉപയോഗിക്കുന്നു) |
| **Cost-Optimized** | ലഭ്യമായതിൽ ഏറ്റവും ചെലവ് കുറഞ്ഞ മോഡലിലേക്ക് റൂട്ട് ചെയ്യുന്നു (വിലനിർണ്ണയ പട്ടിക ഉപയോഗിക്കുന്നു)              |

ഗ്ലോബൽ കോംബോ ഡിഫോൾട്ടുകൾ **Dashboard → Settings → Routing → Combo Defaults**-ൽ സജ്ജീകരിക്കാം.
കോംബോ ടാർഗറ്റ് ടൈംഔട്ടുകൾ ഡിഫോൾട്ടായി നിലവിലെ അഭ്യർത്ഥനാ ടൈംഔട്ട് പാരമ്പര്യമായി സ്വീകരിക്കുന്നു. കുറഞ്ഞ ഓരോ-ടാർഗറ്റ് പരിധി
വേഗത്തിലുള്ള ഫാൾബാക്ക് ട്രിഗർ ചെയ്യേണ്ടപ്പോൾ മാത്രം കോംബോ ഡിഫോൾട്ടുകളിലോ വ്യക്തിഗത കോംബോയിലോ **Target timeout
(seconds)** ഉപയോഗിക്കുക.

സീറോ-ലേറ്റൻസി കോംബോ ഒപ്റ്റിമൈസേഷനുകൾ ഓപ്റ്റ്-ഇൻ ആണ്. ഈ ലേറ്റൻസി സവിശേഷതകൾ ഫാൾബാക്ക് ടാർഗറ്റുകളുമായി മത്സരിക്കുന്നത്, TTFT
ചരിത്രം അടിസ്ഥാനമാക്കി ടാർഗറ്റുകൾ ഒഴിവാക്കുന്നത്, അല്ലെങ്കിൽ ഫാൾബാക്ക് അഭ്യർത്ഥനകൾ കംപ്രസ് ചെയ്യുന്നത് തടയാൻ **Zero-latency optimizations** പ്രവർത്തനരഹിതമായി
വിടുക; ഇത് പ്രവർത്തനക്ഷമമാക്കുന്നത് കോൺഫിഗർ ചെയ്ത ഹെഡ്ജിംഗ്, പ്രവചനാത്മക TTFT
സ്കിപ്പുകൾ, മുൻകരുതൽ ഫാൾബാക്ക് കംപ്രഷൻ എന്നിവ ഉപയോഗിച്ച് റൂട്ടിംഗ്/അഭ്യർത്ഥന വിശ്വസ്തതയ്ക്ക് പകരമായി കുറഞ്ഞ ടെയിൽ
ലേറ്റൻസി നേടാൻ അനുവദിക്കുന്നു.

അപ്സ്ട്രീം പ്രൊവൈഡറുകൾക്ക് കർശനമായ `max_tokens` / `maxOutputTokens` പരിധികൾ ആവശ്യമായിരിക്കുമ്പോൾ
**Reasoning token buffer** പ്രവർത്തനരഹിതമാക്കുക. ഇത് പ്രവർത്തനക്ഷമമായിരിക്കുമ്പോൾ, അറിയാവുന്ന ഔട്ട്പുട്ട് പരിധിയുള്ള മോഡലുകൾക്ക് മാത്രമേ കോംബോ റൂട്ടിംഗ്
റീസണിംഗ്-മോഡൽ ഹെഡ്റൂം ചേർക്കുകയുള്ളൂ; സുരക്ഷിതമായ ബഫർ ചെയ്ത മൂല്യം ആ പരിധി കവിയുമെങ്കിൽ ക്ലയന്റ് ടോക്കൺ പരിധി മാറ്റമില്ലാതെ നിലനിർത്തും. ക്ലയന്റ് പരിധി ഇതിനകം അറിയാവുന്ന ഒരു പരിധിക്ക് മുകളിലാണെങ്കിൽ,
അപ്സ്ട്രീം അഭ്യർത്ഥന അയയ്ക്കുന്നതിന് മുമ്പ് OmniRoute അത് ആ പരിധിയിലേക്ക് കുറയ്ക്കുന്നു.

### ആരോഗ്യ ഡാഷ്ബോർഡ്

**Dashboard → Health** വഴി ആക്സസ് ചെയ്യുക. 6 കാർഡുകളുള്ള തത്സമയ സിസ്റ്റം ആരോഗ്യ അവലോകനം:

| കാർഡ്                 | കാണിക്കുന്നത്                                                              |
| --------------------- | -------------------------------------------------------------------------- |
| **System Status**     | പ്രവർത്തനസമയം, പതിപ്പ്, മെമ്മറി ഉപയോഗം, ഡാറ്റ ഡയറക്ടറി                     |
| **Provider Health**   | ഗ്ലോബൽ പ്രൊവൈഡർ സർക്യൂട്ട് ബ്രേക്കർ റൺടൈം സ്റ്റേറ്റ്                       |
| **Rate Limits**       | ശേഷിക്കുന്ന സമയത്തോടുകൂടി ഓരോ അക്കൗണ്ടിലുമുള്ള സജീവ കണക്ഷൻ കൂൾഡൗണുകൾ       |
| **Active Lockouts**   | സജീവ മോഡൽ-സ്കോപ്പിലുള്ള ലോക്കൗട്ടുകളും താൽക്കാലിക ഒഴിവാക്കലുകളും           |
| **Signature Cache**   | പകർപ്പ് നീക്കംചെയ്യൽ കാഷ് സ്ഥിതിവിവരക്കണക്കുകൾ (സജീവ കീകൾ, ഹിറ്റ് നിരക്ക്) |
| **Latency Telemetry** | ഓരോ പ്രൊവൈഡറിനുമുള്ള p50/p95/p99 ലേറ്റൻസി അഗ്രിഗേഷൻ                        |

**പ്രൊ ടിപ്പ്:** Health പേജ് ഓരോ 10 സെക്കൻഡിലും സ്വയമേവ പുതുക്കുന്നു. ഏത് പ്രൊവൈഡറുകൾക്കാണ് പ്രശ്നങ്ങൾ നേരിടുന്നതെന്ന് തിരിച്ചറിയാൻ സർക്യൂട്ട് ബ്രേക്കർ കാർഡ് ഉപയോഗിക്കുക.

## 🤖 സ്വയമേവയുള്ള റൂട്ടിംഗ് (ക്രമീകരണം ആവശ്യമില്ല)

ബന്ധിപ്പിച്ചിരിക്കുന്ന എല്ലാ പ്രൊവൈഡറുകളിൽ നിന്നും ഓരോ അഭ്യർത്ഥനയ്ക്കും ഏറ്റവും അനുയോജ്യമായ മോഡൽ തിരഞ്ഞെടുക്കുന്ന ഒരു **സ്കോർ അധിഷ്ഠിത ഓട്ടോ-റൂട്ടറുമായാണ്** OmniRoute എത്തുന്നത് — പരിപാലിക്കേണ്ട കോംബോകളൊന്നുമില്ല. `auto/*` പ്രിഫിക്സുകളിലൊന്ന് ഉപയോഗിച്ച് അഭ്യർത്ഥന അയച്ചാൽ മാത്രം മതി; ലേറ്റൻസി, ചെലവ്, വിജയനിരക്ക്, കോൺടെക്സ്റ്റുമായുള്ള പൊരുത്തം, ടാസ്കിനോടുള്ള മോഡലിന്റെ അനുയോജ്യത, സമീപകാല പരാജയങ്ങൾ, ക്വോട്ട, സർക്യൂട്ട്-ബ്രേക്കർ നില എന്നിവയുടെ അടിസ്ഥാനത്തിൽ കാൻഡിഡേറ്റുകൾക്ക് സ്കോർ നൽകി OmniRoute തത്സമയം ഒരു വെർച്വൽ കോംബോ സജ്ജീകരിക്കും.

## 🔌 MCP & A2A സംയോജനം

OmniRoute ഒരു **MCP സെർവറും** (Model Context Protocol) ഒരു **A2A സെർവറും** (Agent-to-Agent JSON-RPC 2.0) ആണ്. MCP-യുമായി പൊരുത്തപ്പെടുന്ന ഏത് IDE-യ്ക്കോ ഏജന്റ് ഹോസ്റ്റിനോ OmniRoute ടൂളുകൾ നേരിട്ട് കോൾ ചെയ്യാനാകും — അധിക റാപ്പർ ആവശ്യമില്ല.

### MCP ട്രാൻസ്പോർട്ടുകൾ

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **സ്ട്രീം ചെയ്യാവുന്ന HTTP**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (stdio തിരഞ്ഞെടുക്കുന്ന IDE പ്ലഗിനുകൾക്കായി)

### Claude Desktop ബന്ധിപ്പിക്കുക

macOS-ൽ `~/Library/Application Support/Claude/claude_desktop_config.json` അല്ലെങ്കിൽ Windows/Linux-ലെ തത്തുല്യമായ ഫയൽ എഡിറ്റ് ചെയ്യുക:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Cursor / Continue / VS Code MCP ബന്ധിപ്പിക്കുക

SSE URL ആയ `http://localhost:20128/api/mcp/sse`-ഉം **Dashboard → API Keys** എന്നതിൽ സൃഷ്ടിച്ച ഒരു Bearer API കീയും ഉപയോഗിക്കുക.

### സ്കോപ്പുകൾ

MCP നിലവിൽ പേരിട്ട 32 സ്കോപ്പുകൾ നിർവചിക്കുന്നു. ഓരോ Bearer കീയും നിർദിഷ്ട സ്കോപ്പുകളിലേക്ക് പരിമിതപ്പെടുത്താനാകും — ആധികാരികമായ സ്കോപ്പ്, ടൂൾ ഇൻവെന്ററികൾക്കായി [MCP-SERVER.md](../frameworks/MCP-SERVER.md)-ഉം JSON-RPC സ്കീമയ്ക്കായി [A2A-SERVER.md](../frameworks/A2A-SERVER.md)-ഉം കാണുക.

- **ഇഷ്ടാനുസൃത കഴിവുകൾ** — `src/lib/a2a/skills/` എന്നതിൽ ഒരു TypeScript ഫയൽ ചേർത്ത് അത് രജിസ്റ്റർ ചെയ്യുക; ഉടൻതന്നെ A2A വഴി അത് പ്രവർത്തിപ്പിക്കാനാകും

## 💾 മെമ്മറി സംവിധാനം

ഹൈബ്രിഡ് റിട്രീവലോടുകൂടിയ **ദീർഘകാല സംഭാഷണ മെമ്മറി** OmniRoute നിലനിർത്തുന്നു:

- കഴിഞ്ഞ സംഭാഷണങ്ങളിലുടനീളമുള്ള കീവേഡ് തിരയലിനായി **SQLite FTS5**
- അർത്ഥാധിഷ്ഠിത ഓർമ്മപ്പെടുത്തലിനായി **Qdrant വെക്റ്റർ സ്റ്റോർ** (ഐച്ഛികം)
- **സ്വയമേവയുള്ള വസ്തുതാ വേർതിരിച്ചെടുക്കൽ** — ഓരോ സെഷനുശേഷവും എന്റിറ്റികൾ, മുൻഗണനകൾ, തീരുമാനങ്ങൾ എന്നിവ സംഗ്രഹിച്ച് `memory_facts` പട്ടികയിൽ സംഭരിക്കുന്നു
- ഓരോ API കീയ്ക്കും ഓരോ സെഷനും അനുസരിച്ച് മെമ്മറികൾക്ക് സ്കോപ്പ് നിശ്ചയിച്ചിരിക്കുന്നു

**ഡാഷ്ബോർഡ് → മെമ്മറി** എന്നതിൽ മെമ്മറികൾ കൈകാര്യം ചെയ്യുക (തിരയുക, എഡിറ്റ് ചെയ്യുക, എക്സ്പോർട്ട് ചെയ്യുക, പൂർണ്ണമായി നീക്കം ചെയ്യുക). HTTP ഇന്റർഫേസ് (`/api/memory/*`) ഉപയോഗിച്ച് ഏജന്റുകൾക്ക് പ്രോഗ്രാമാറ്റിക്കായി വസ്തുതകൾ നൽകാനും അന്വേഷിക്കാനും കഴിയും — [MEMORY.md](../frameworks/MEMORY.md) കാണുക.

## 🔔 വെബ്ഹുക്കുകൾ

തത്സമയ നിരീക്ഷണത്തിനും ഓട്ടോമേഷനുമായി OmniRoute ഇവന്റുകൾ സബ്സ്ക്രൈബ് ചെയ്യുക.

- ലക്ഷ്യ URL-ഉം HMAC സൈനിംഗ് സീക്രട്ടും ഉപയോഗിച്ച് **ഡാഷ്ബോർഡ് → വെബ്ഹുക്കുകൾ** എന്നതിൽ ഒരു വെബ്ഹുക്ക് സൃഷ്ടിക്കുക
- ലഭ്യമായ ഇവന്റുകൾ: `request.completed`, `request.failed`, `provider.unavailable`, `budget.exceeded`, `combo.switched`, `circuit_breaker.opened`, `circuit_breaker.closed`
- സ്ഥിരീകരണത്തിനായി ഓരോ പേലോഡിലും `X-OmniRoute-Signature` (HMAC-SHA256) ഉൾപ്പെടുന്നു
- വീണ്ടും ശ്രമിക്കൽ: എക്സ്പോണൻഷ്യൽ ബാക്ക്ഓഫോടെ 3 ശ്രമങ്ങൾ, തുടർന്ന് ഡെഡ്-ലെറ്റർ ക്യൂ

പൂർണ്ണ സ്കീമ [WEBHOOKS.md](../frameworks/WEBHOOKS.md) എന്നതിൽ ലഭ്യമാണ്.

- ഓരോ പ്രൊവൈഡർക്കും നിങ്ങളുടെ സ്വന്തം API കീ ഉപയോഗിക്കുക — ക്രെഡൻഷ്യലുകൾ ഒരിക്കലും OmniRoute ഇൻസ്റ്റൻസിൽ നിന്ന് പുറത്തുപോകില്ല

## 🛠️ പ്രോഗ്രാമാറ്റിക് മാനേജ്മെന്റ്

**`manage` സ്കോപ്പുള്ള ഒരു Bearer കീ** ഉപയോഗിച്ച് HTTP വഴി എല്ലാ OmniRoute റിസോഴ്സുകളും (പ്രൊവൈഡറുകൾ, കോംബോകൾ, കീകൾ, ക്രമീകരണങ്ങൾ) കൈകാര്യം ചെയ്യാം.

**ഡാഷ്ബോർഡ് → API കീകൾ → പുതിയ കീ → സ്കോപ്പ്: manage** എന്നതിൽ കീ സൃഷ്ടിച്ച ശേഷം:

```bash
# പ്രൊവൈഡറുകളുടെ പട്ടിക കാണിക്കുക
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
```

## 💻 ആന്തരിക CLI

സജ്ജീകരണം, ഡയഗ്നോസ്റ്റിക്സ്, റൺടൈം നിയന്ത്രണം എന്നിവയ്ക്കായി OmniRoute ഒരു ആന്തരിക CLI (`omniroute …`) സഹിതമാണ് ലഭിക്കുന്നത്. ഇത് മൂന്നാം കക്ഷി CLI-കൾക്ക് (Claude Code, Cursor, Codex, Cline, …) OmniRoute-മായി ആശയവിനിമയം നടത്താൻ കഴിയുന്ന വിധത്തിൽ അവയെ കോൺഫിഗർ ചെയ്യുന്ന ഡാഷ്ബോർഡിലെ **"CLI Tools" പേജിൽ നിന്ന് വ്യത്യസ്തമാണ്**.

```bash
omniroute setup                    # ഇന്ററാക്ടീവ് വിസാർഡ് (പാസ്വേഡ്, പ്രൊവൈഡറുകൾ, കോമ്പോകൾ)
omniroute setup --non-interactive  # CI-ക്ക് അനുയോജ്യം
omniroute doctor                   # ആരോഗ്യനില ഡയഗ്നോസ്റ്റിക്സ് (ഡാറ്റ ഡയറക്ടറി, DB, പ്രൊവൈഡറുകൾ, പോർട്ടുകൾ)
omniroute providers available      # പിന്തുണയ്ക്കുന്ന പ്രൊവൈഡറുകളെ പട്ടികപ്പെടുത്തുക
omniroute providers list           # കോൺഫിഗർ ചെയ്ത കണക്ഷനുകളെ പട്ടികപ്പെടുത്തുക
omniroute providers test <id>      # ഒരു പ്രൊവൈഡർ കണക്ഷൻ തത്സമയം പരിശോധിക്കുക
omniroute combos list              # കോമ്പോകളെ പട്ടികപ്പെടുത്തുക
omniroute combos switch <name>     # ഡിഫോൾട്ട് കോമ്പോ സജ്ജമാക്കുക
omniroute models                   # ലഭ്യമായ മോഡലുകളെ പട്ടികപ്പെടുത്തുക (--json, --search)
omniroute keys add | list | remove # ടെർമിനലിൽ നിന്ന് API കീകൾ കൈകാര്യം ചെയ്യുക
omniroute backup                   # കോൺഫിഗറേഷന്റെയും DB-യുടെയും സ്നാപ്പ്ഷോട്ട് എടുക്കുക
omniroute restore [<timestamp>]    # ഒരു സ്നാപ്പ്ഷോട്ടിൽ നിന്ന് പുനഃസ്ഥാപിക്കുക
omniroute health                   # വിശദമായ ആരോഗ്യനില (ബ്രേക്കറുകൾ, കാഷ്, മെമ്മറി)
omniroute quota                    # പ്രൊവൈഡർ ക്വോട്ട ഉപയോഗം
omniroute mcp status               # MCP സെർവർ നില
omniroute a2a status               # A2A സെർവർ നില
omniroute tunnel list|create|stop  # Cloudflare/Tailscale/ngrok ടണലുകൾ
omniroute reset-password           # അഡ്മിൻ പാസ്വേഡ് പുനഃസജ്ജമാക്കുക
omniroute --mcp                    # stdio വഴി MCP സെർവർ ആരംഭിക്കുക
omniroute --port 3000              # ഇഷ്ടാനുസൃത പോർട്ടിൽ സെർവർ ആരംഭിക്കുക
```

നുറുങ്ങ്: ആരോഗ്യകരമല്ലാത്ത പ്രൊവൈഡർ കണക്ഷനുകളെക്കുറിച്ച് മുന്നറിയിപ്പ് ലഭിക്കാൻ `omniroute doctor --json` നിങ്ങളുടെ മോണിറ്ററിംഗ് ടൂളുമായി ചേർത്ത് ഉപയോഗിക്കുക.

## 🖥️ ഡെസ്ക്ടോപ്പ് ആപ്ലിക്കേഷൻ (Electron)

Windows, macOS, Linux എന്നിവയ്ക്കായി ഒരു നേറ്റീവ് ഡെസ്ക്ടോപ്പ് ആപ്ലിക്കേഷനായി OmniRoute ലഭ്യമാണ്.

### ഇൻസ്റ്റാളേഷൻ

```bash
# electron ഡയറക്ടറിയിൽ നിന്ന്:
cd electron
npm install

# ഡെവലപ്മെന്റ് മോഡ് (പ്രവർത്തിച്ചുകൊണ്ടിരിക്കുന്ന Next.js ഡെവ് സെർവറുമായി കണക്റ്റ് ചെയ്യുന്നു):
npm run dev

# പ്രൊഡക്ഷൻ മോഡ് (സ്റ്റാൻഡ്അലോൺ ബിൽഡ് ഉപയോഗിക്കുന്നു):
npm start
```

### ഇൻസ്റ്റാളറുകൾ ബിൽഡ് ചെയ്യൽ

```bash
cd electron
npm run build          # നിലവിലെ പ്ലാറ്റ്ഫോം
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg യൂണിവേഴ്സൽ)
npm run build:linux    # Linux (.AppImage)
```

ഔട്ട്പുട്ട് → `electron/dist-electron/`
