## ഇത് എന്താണ്

ടെക്സ്റ്റ് ഫയലുകളുള്ള, വ്യക്തമായി അംഗീകരിച്ച ഒരു ഡയറക്ടറി OmniRoute-ന്റെ MCP സെർവറിന് ലഭ്യമാക്കാൻ Local Corpus ഒരു ഓപ്പറേറ്ററെ അനുവദിക്കുന്നു. ഫയലുകൾ അവയുടെ യഥാർത്ഥ ഡയറക്ടറിയിൽ തന്നെ തുടരുന്നു: OmniRoute കാനോനിക്കൽ റൂട്ട് പാത്ത് മാത്രമാണ് SQLite-ൽ സംഭരിക്കുന്നത്, കൂടാതെ ഒരു ഇൻ-മെമ്മറി സെർച്ച് ഇൻഡക്സ് പരിപാലിക്കുകയും ചെയ്യുന്നു. കോർപ്പസ് ഉള്ളടക്കം റിപ്പോസിറ്ററിയിലേക്കോ ഡാറ്റാബേസിലേക്കോ ഇത് പകർത്തുന്നില്ല.

ഇൻഡക്സ് പുതുക്കൽ ഇൻക്രിമെന്റൽ രീതിയിലാണ് നടക്കുന്നത്. വലുപ്പവും പരിഷ്കരിച്ച സമയവും അടിസ്ഥാനമാക്കി മാറ്റമില്ലാത്ത ഫയലുകൾ വീണ്ടും ഉപയോഗിക്കുന്നു, മാറ്റം വന്ന ഫയലുകൾ വീണ്ടും വായിച്ച് SHA-256 ഉപയോഗിച്ച് ഹാഷ് ചെയ്യുന്നു, ഇല്ലാതാക്കിയ ഫയലുകൾ നീക്കം ചെയ്യുന്നു. 30 സെക്കൻഡിൽ കൂടുതൽ പഴക്കമുള്ള ഇൻഡക്സ് സെർച്ച് പുതുക്കും; കോളർമാർക്ക് ഉടനടി പുതുക്കലും അഭ്യർത്ഥിക്കാം.

## ഉറവിടം കോൺഫിഗർ ചെയ്യുക

മറ്റ് സെറ്റിങ്സ് API-കളിലേതുപോലെ തന്നെ മാനേജ്മെന്റ് ഓതന്റിക്കേഷൻ സെറ്റിങ്സ് റൂട്ടിനും ആവശ്യമാണ്. സമർപ്പിക്കുന്ന പാത്ത് നിലവിൽ ഉണ്ടായിരിക്കണം, കൂടാതെ അത് ഒരു അബ്സല്യൂട്ട് ഡയറക്ടറി പാത്ത് ആയിരിക്കണം.

```bash
# അംഗീകരിച്ച ഒരു ഡയറക്ടറി ബന്ധിപ്പിക്കുക
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# കോൺഫിഗറേഷനും ഇൻഡക്സ് നിലയും പരിശോധിക്കുക
curl http://localhost:20128/api/settings/local-corpus

# ഉറവിട ഫയലുകളിൽ മാറ്റം വരുത്താതെ ബന്ധം വിച്ഛേദിക്കുക
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## MCP ടൂളുകൾ

മൂന്ന് ടൂളുകൾക്കും `read:local-corpus` ആവശ്യമാണ്. ടൂൾ പ്രതികരണങ്ങൾ റിലേറ്റീവ് പാത്തുകളും റൂട്ട് ഡയറക്ടറിയുടെ ബേസ് നെയിമും മാത്രമേ വെളിപ്പെടുത്തൂ; അതിന്റെ അബ്സല്യൂട്ട് പാത്ത് ഒരിക്കലും വെളിപ്പെടുത്തില്ല.

| ടൂൾ                   | വിവരണം                                                                                                         |
| :-------------------- | :------------------------------------------------------------------------------------------------------------- |
| `local_corpus_status` | കോൺഫിഗറേഷൻ നില, ഇൻഡക്സ് വലുപ്പം, പരിധികൾ, അവസാനമായി പുതുക്കിയ സമയം എന്നിവ റിപ്പോർട്ട് ചെയ്യുന്നു               |
| `local_corpus_search` | ഇൻഡക്സ് ചെയ്ത ടെക്സ്റ്റിൽ തിരഞ്ഞ്, പരിധിയുള്ളതും വരി-അധിഷ്ഠിതവുമായ സ്നിപ്പെറ്റുകൾ നൽകുന്നു (പരമാവധി 20 ഫലങ്ങൾ) |
| `local_corpus_read`   | അനുമതിയുള്ള ഒരു കോർപ്പസ്-റിലേറ്റീവ് ഫയലിൽനിന്ന് പരിധിയുള്ള വരിശ്രേണി വായിക്കുന്നു                              |

MCP ഇൻപുട്ട് ഉദാഹരണങ്ങൾ:

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## സുരക്ഷാ അതിരുകൾ

- അലൗലിസ്റ്റ് ടെക്സ്റ്റ് അധിഷ്ഠിതമാണ്: `.cfg`, `.csv`, `.geojson`, `.htm`, `.html`, `.ini`,
  `.js`, `.json`, `.jsonl`, `.jsx`, `.log`, `.md`, `.mjs`, `.ps1`, `.py`, `.sh`,
  `.sql`, `.toml`, `.ts`, `.tsx`, `.txt`, `.xml`, `.yaml`, കൂടാതെ `.yml`.
- സിംലിങ്കുകൾ ഒഴിവാക്കുന്നു. റീഡ് പാത്തുകൾ കാനോനിക്കലൈസ് ചെയ്യുകയും അവ കോൺഫിഗർ ചെയ്ത റൂട്ടിനുള്ളിൽ തന്നെ തുടരണമെന്ന് ഉറപ്പാക്കുകയും ചെയ്യുന്നു; അബ്സല്യൂട്ട് പാത്തുകളും ട്രാവേഴ്സൽ ശ്രമങ്ങളും നിരസിക്കുന്നു.
- സെൻസിറ്റീവും ജനറേറ്റ് ചെയ്തതുമായ ഡയറക്ടറി പേരുകൾ ഒഴിവാക്കുന്നു: `.build`, `.codex`, `.env`,
  `.git`, `.next`, `.omniroute`, `.ssh`, `coverage`, `dist`, `node_modules`, കൂടാതെ
  `secrets`.
- ഡിഫോൾട്ട് പരിധികൾ: 5,000 ഫയലുകൾ, ഓരോ ഫയലിനും 1 MiB, ഇൻഡക്സ് ചെയ്ത മൊത്തം ഉള്ളടക്കത്തിന് 64 MiB, ഓരോ സെർച്ച് ചങ്കിനും ഏകദേശം 4,000 പ്രതീകങ്ങൾ, ഓരോ റീഡിനും 400 വരികൾ.
- NUL അടങ്ങിയ ഫയലുകളെ ടെക്സ്റ്റ് അല്ലാത്തവയായി കണക്കാക്കി ഒഴിവാക്കുകയോ നിരസിക്കുകയോ ചെയ്യുന്നു.

PDF, DOCX, ചിത്രങ്ങൾ, ആർക്കൈവുകൾ തുടങ്ങിയ ബൈനറി ഡോക്യുമെന്റുകൾക്ക് മനഃപൂർവം പിന്തുണ നൽകുന്നില്ല. ഇൻഡക്സ് ചെയ്യുന്നതിന് മുമ്പ് കോൺഫിഗർ ചെയ്ത ഡയറക്ടറിയിൽ അവയെ അംഗീകരിച്ച ഒരു ടെക്സ്റ്റ് ഫോർമാറ്റിലേക്ക് പരിവർത്തനം ചെയ്യുക.

## പ്രവർത്തന കുറിപ്പുകൾ

- കോൺഫിഗർ ചെയ്ത റൂട്ട് മാറ്റുകയോ ഇല്ലാതാക്കുകയോ ചെയ്യുന്നത് പങ്കിട്ട ഇൻ-മെമ്മറി ഇൻഡക്സ് മായ്ക്കും.
- ഒരു പ്രോസസ് റീസ്റ്റാർട്ട് ഇൻഡക്സ് ഉപേക്ഷിക്കും; അടുത്ത സെർച്ച് കോൺഫിഗർ ചെയ്ത ഉറവിടത്തിൽനിന്ന് അത് വീണ്ടും നിർമ്മിക്കും.
- `local_corpus_status` നിർബന്ധിത സ്കാൻ നടത്തില്ല. ഉടനടി വീണ്ടും സ്കാൻ ചെയ്യേണ്ടപ്പോൾ `refresh: true` സഹിതം `local_corpus_search` ഉപയോഗിക്കുക.
- സ്കാൻ, റീഡ് പരാജയങ്ങൾ എണ്ണുകയോ ശുദ്ധീകരിച്ച പിശകുകളായി നൽകുകയോ ചെയ്യുന്നു; ഉറവിട ഫയലുകളിൽ ഒരിക്കലും മാറ്റം വരുത്തുന്നില്ല.
