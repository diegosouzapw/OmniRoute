Traffic Inspector എന്നത് OmniRoute-ൽ ഉൾപ്പെടുത്തിയിരിക്കുന്ന HTTPS ട്രാഫിക് ഡീബഗറാണ് — **LLM-aware**-ഉം **agent-aware**-ഉം ആയ Charles Proxy / mitmweb / HTTP Toolkit പോലുള്ള ഒരു ഉപകരണം. ഇത് `/dashboard/tools/traffic-inspector` എന്നതിൽ ലഭ്യമാണ്, കൂടാതെ ഒരേസമയം പരമാവധി 5 ക്യാപ്ചർ സ്രോതസ്സുകളിൽ നിന്ന് തത്സമയ ട്രാഫിക് സ്വീകരിക്കുന്നു.

**ഡാഷ്ബോർഡ് സ്ഥാനം:** `/dashboard/tools/traffic-inspector`
**സൈഡ്ബാർ ഗ്രൂപ്പ്:** Tools (AgentBridge-ന് ശേഷം)
**ഇതും കാണുക:** [`AGENTBRIDGE.md`](./AGENTBRIDGE.md) — AgentBridge ക്യാപ്ചർ മോഡ് 1 ആണ്.

### ഒറ്റ ഖണ്ഡികയിൽ ആർക്കിടെക്ചർ

`TrafficBuffer` (`src/mitm/inspector/buffer.ts`) എന്നത് പങ്കിടുന്ന ഇൻ-മെമ്മറി റിങ് ബഫറാണ് (സ്ഥിരസ്ഥിതിയിൽ 1000 എൻട്രികൾ; `INSPECTOR_BUFFER_SIZE` വഴി ക്രമീകരിക്കാം). എല്ലാ ക്യാപ്ചർ സ്രോതസ്സുകളും `push()` വഴി ഇതിലേക്ക് എഴുതുന്നു. `kindDetector.ts` ഉപയോഗിച്ച് ബഫർ ഓരോ എൻട്രിയും വർഗീകരിക്കുന്നു (അതൊരു LLM അഭ്യർത്ഥനയാണോ എന്ന് നിർണ്ണയിക്കുന്നു), ഒരു `contextKey` കണക്കാക്കുന്നു (സിസ്റ്റം പ്രോംപ്റ്റിന്റെ SHA-256 ഫിംഗർപ്രിന്റ്), കൂടാതെ `globalTrafficBuffer.subscribe()` വഴി എല്ലാ WebSocket സബ്സ്ക്രൈബർമാർക്കും ബ്രോഡ്കാസ്റ്റ് ചെയ്യുന്നു. ഡാഷ്ബോർഡ് `GET /api/tools/traffic-inspector/ws` വഴി കണക്റ്റ് ചെയ്യുകയും, കണക്ഷൻ സ്ഥാപിക്കുമ്പോൾ ഒരു സ്നാപ്ഷോട്ട് സ്വീകരിക്കുകയും, തുടർന്ന് `new`/`update`/`clear` ഇവന്റുകൾ സ്വീകരിക്കുകയും ചെയ്യുന്നു.

## §2 ക്യാപ്ചർ മോഡുകൾ

Traffic Inspector **ഒരേസമയം 5 ക്യാപ്ചർ ഉറവിടങ്ങളെ** പിന്തുണയ്ക്കുന്നു. ഓരോന്നും സ്വതന്ത്രമായി ഓൺ/ഓഫ് ചെയ്യാം. ഓരോ `InterceptedRequest`-ലെയും (`src/mitm/inspector/types.ts`) `source` ഫീൽഡ് `"agent-bridge"`, `"custom-host"`, `"http-proxy"`, `"system-proxy"`, അല്ലെങ്കിൽ `"tproxy"` എന്നിവയിൽ ഒന്നായിരിക്കും.

### മോഡ് 1 — AgentBridge (ഡിഫോൾട്ട്, എപ്പോഴും ഓൺ)

**ഉറവിടം:** AgentBridge ഹാൻഡ്ലറുകൾ (`src/mitm/handlers/base.ts`)
**പ്രവർത്തനരീതി:** `MitmHandlerBase`-ലെ ഓരോ `intercept()` കോളും ഫോർവേഡ് ചെയ്യുന്നതിന് മുമ്പ് `hookBufferStart()`-ഉം പൂർത്തിയാകുമ്പോൾ `hookBufferUpdate()`-ഉം വിളിക്കുന്നു. അധിക കോൺഫിഗറേഷൻ ഒന്നും ആവശ്യമില്ല — AgentBridge പ്രവർത്തനം ആരംഭിച്ചാലുടൻ ഇത് പ്രവർത്തിക്കും.
**പരിധി:** AgentBridge-ൽ കോൺഫിഗർ ചെയ്തിട്ടുള്ള 9 IDE ഏജന്റുകൾ
**കുറിപ്പ്:** `InterceptedRequest`-ലെ `source` ഫീൽഡ് = `"agent-bridge"`

### മോഡ് 2 — ഇഷ്ടാനുസൃത ഹോസ്റ്റുകൾ (DNS റീഡയറക്ട്)

**ഉറവിടം:** ഉപയോക്താവ് നിർവചിച്ച ഹോസ്റ്റ് ലിസ്റ്റ് (`inspector_custom_hosts` ടേബിൾ)
**പ്രവർത്തനരീതി:** UI വഴി ഒരു ഹോസ്റ്റ് ചേർക്കുമ്പോൾ `/etc/hosts`-ലേക്ക് `127.0.0.1 <host>` ചേർക്കുന്നു (sudo ആവശ്യമാണ്). നിലവിലുള്ള AgentBridge MITM സെർവർ (പോർട്ട് 443) പുതിയ ഹോസ്റ്റിനായി ഡൈനാമിക്കായി ഒരു SNI സർട്ടിഫിക്കറ്റ് സൃഷ്ടിക്കുന്നു.
**പരിധി:** ചേർത്ത ഹോസ്റ്റ് ഉപയോഗിക്കുന്ന ഏതൊരു ആപ്ലിക്കേഷനും — ആപ്പ് കോൺഫിഗറേഷനിൽ മാറ്റമൊന്നും ആവശ്യമില്ല
**കുറിപ്പ്:** `source` = `"custom-host"`

ഉപയോഗ ഉദാഹരണങ്ങൾ:

- Python സ്ക്രിപ്റ്റുകളിൽ നിന്നുള്ള `api.openai.com` നിരീക്ഷിക്കുക
- `my-internal-llm.company.com` ഡീബഗ് ചെയ്യുക
- ഒരേ നെറ്റ്വർക്കിലുള്ള മൊബൈൽ ഉപകരണങ്ങളിൽ നിന്നുള്ള ട്രാഫിക് ക്യാപ്ചർ ചെയ്യുക (ARP spoofing വഴി — വിപുലമായ ഉപയോഗം)

### മോഡ് 3 — HTTP_PROXY ലിസണർ (പോർട്ട് 8080)

**ഉറവിടം:** `HTTP_PROXY`/`HTTPS_PROXY` എൻവയോൺമെന്റ് വേരിയബിളുകൾ ഉപയോഗിക്കുന്ന ആപ്ലിക്കേഷനുകൾ
**പ്രവർത്തനരീതി:** പോർട്ട് 8080-ലെ (`src/mitm/inspector/httpProxyServer.ts`) സെക്കൻഡറി ലിസണർ ഒരു സ്റ്റാൻഡേർഡ് എക്സ്പ്ലിസിറ്റ് HTTP/HTTPS പ്രോക്സിയായി പ്രവർത്തിക്കുന്നു. `CONNECT` ടണലുകളും (HTTPS) നേരിട്ടുള്ള HTTP അഭ്യർത്ഥനകളും സ്വീകരിക്കുന്നു.
**പരിധി:** `HTTP_PROXY` എൻവയോൺമെന്റ് വേരിയബിൾ മാനിക്കുന്ന ഏതൊരു ആപ്ലിക്കേഷനും — DNS മാറ്റമോ sudo-യോ ആവശ്യമില്ല
**കുറിപ്പ്:** `source` = `"http-proxy"`

```bash
# ഒരൊറ്റ കമാൻഡിനായി ദ്രുത ക്യാപ്ചർ:
HTTPS_PROXY=http://127.0.0.1:8080 curl https://api.openai.com/v1/models

# ഒരു ഷെൽ സെഷനിലുടനീളം സ്ഥിരമായ ക്യാപ്ചർ:
export HTTP_PROXY=http://127.0.0.1:8080
export HTTPS_PROXY=http://127.0.0.1:8080
```

**TLS പരിമിതി:** HTTPS `CONNECT` ടണലുകൾ മെറ്റാഡാറ്റയായി മാത്രം ക്യാപ്ചർ ചെയ്യപ്പെടുന്നു (ഹോസ്റ്റ്, പോർട്ട്, ടൈമിങ്) — ഡിഫോൾട്ടായി TLS ബോഡി ഡീക്രിപ്റ്റ് ചെയ്യപ്പെടുന്നില്ല. ബോഡി പൂർണ്ണമായി പരിശോധിക്കാൻ "പ്രോക്സി മോഡിൽ HTTPS ഡീക്രിപ്റ്റ് ചെയ്യുക" ടോഗിൾ പ്രവർത്തനക്ഷമമാക്കുക (ഐച്ഛികമാണ്; AgentBridge സർട്ടിഫിക്കറ്റ് വിശ്വസനീയമാക്കിയിരിക്കണം).

**പോർട്ട് വൈരുദ്ധ്യം:** പോർട്ട് 8080 ഉപയോഗത്തിലാണെങ്കിൽ, ഘടനാബദ്ധമായ ഒരു പിശകിനൊപ്പം AgentBridge 409 തിരികെ നൽകും. `INSPECTOR_HTTP_PROXY_PORT` എൻവയോൺമെന്റ് വേരിയബിൾ വഴി പോർട്ട് മാറ്റുക.

### മോഡ് 4 — സിസ്റ്റം-വ്യാപക പ്രോക്സി (വിപുലമായ ഉപയോഗം, ഐച്ഛികം)

**ഉറവിടം:** OS-തല പ്രോക്സി ക്രമീകരണങ്ങൾ (മെഷീനിലെ എല്ലാ ആപ്പുകൾക്കും ബാധകം)
**പ്രവർത്തനരീതി:** HTTP_PROXY ലിസണറിലൂടെ എല്ലാ HTTP/HTTPS ട്രാഫിക്കും റീഡയറക്ട് ചെയ്യാൻ OS API-കൾ ഉപയോഗിക്കുന്നു:

- **macOS:** `networksetup -setwebproxy / -setsecurewebproxy`
- **Linux:** `gsettings set org.gnome.system.proxy` + `/etc/environment`
- **Windows:** `netsh winhttp set proxy 127.0.0.1:8080`
  **പരിധി:** സിസ്റ്റം പ്രോക്സി ക്രമീകരണങ്ങൾ മാനിക്കുന്ന, മെഷീനിലെ എല്ലാ ആപ്ലിക്കേഷനുകളും
  **കുറിപ്പ്:** `source` = `"system-proxy"`

**സുരക്ഷാ സംവിധാനങ്ങൾ:**

- സ്വയമേവ പ്രവർത്തനരഹിതമാക്കുന്ന ടൈമർ (ഡിഫോൾട്ട് 30 മിനിറ്റ്; `INSPECTOR_SYSTEM_PROXY_GUARD_MINUTES` വഴി കോൺഫിഗർ ചെയ്യാം)
- മുമ്പത്തെ സിസ്റ്റം പ്രോക്സി നില DB-യിൽ സംരക്ഷിക്കുകയും റിവർട്ട് ചെയ്യുമ്പോൾ പുനഃസ്ഥാപിക്കുകയും ചെയ്യുന്നു
- ഇത് സജീവമായിരിക്കുമ്പോൾ ഉപയോക്താവ് പേജ് വിട്ടുപോകുകയാണെങ്കിൽ, ഡാഷ്ബോർഡ് "സിസ്റ്റം പ്രോക്സി റിവർട്ട് ചെയ്യുന്നു" എന്ന പ്രോംപ്റ്റ് കാണിക്കുന്നു
- UI-യിൽ `⚠ വിപുലമായത്` ബാഡ്ജും വ്യക്തമായ സ്ഥിരീകരണ ചെക്ക്ബോക്സും കാണിക്കുന്നു

### മോഡ് 5 — TPROXY സുതാര്യ ഡീക്രിപ്ഷൻ (Linux, root, ഐച്ഛികം)

**ഉറവിടം:** കേർണൽ TPROXY + പോളിസി റൂട്ടിങ് (`src/mitm/tproxy/`)
**പ്രവർത്തനരീതി:** ഒരു ലക്ഷ്യ പോർട്ടിലേക്കുള്ള (ഡിഫോൾട്ട് `443`) പുതിയ ലോക്കൽ ഔട്ട്ബൗണ്ട് TCP കണക്ഷനുകൾ `mangle OUTPUT`-ൽ മാർക്ക് ചെയ്യുന്നു; ഒരു `ip rule` മാർക്ക് ചെയ്ത പാക്കറ്റുകളെ ലോക്കൽ ഡെലിവറിയിലേക്ക് റീറൂട്ട് ചെയ്യുന്നു; തുടർന്ന് `mangle PREROUTING`-ന്റെ `TPROXY` ടാർഗറ്റ് അവയെ ഒരു സുതാര്യ (**IP_TRANSPARENT**) ലിസണറിന് (ഡിഫോൾട്ട് പോർട്ട് `8443`) കൈമാറുന്നു. ഒരു ഡൈനാമിക് CA ആവശ്യാനുസരണം **ഓരോ SNI ഹോസ്റ്റ്നെയിമിനും** നൽകുന്ന ലീഫ് സർട്ടിഫിക്കറ്റ് ഉപയോഗിച്ച് ലിസണർ TLS അവസാനിപ്പിക്കുകയും, ഡീക്രിപ്റ്റ് ചെയ്ത എക്സ്ചേഞ്ച് ക്യാപ്ചർ ചെയ്യുകയും, അഭ്യർത്ഥന വീണ്ടും എൻക്രിപ്റ്റ് ചെയ്ത് യഥാർത്ഥ ലക്ഷ്യസ്ഥാനത്തേക്ക് ഫോർവേഡ് ചെയ്യുകയും ചെയ്യുന്നു.
**പരിധി:** ലക്ഷ്യ പോർട്ടിലെ **ഏത്** ഡെസ്റ്റിനേഷൻ ഹോസ്റ്റുകളും — `/etc/hosts` സ്പൂഫ് ആവശ്യമില്ല, `HTTP_PROXY` എൻവയോൺമെന്റ് വേരിയബിൾ ആവശ്യമില്ല, സിസ്റ്റം-വ്യാപക പ്രോക്സി മാറ്റവും ആവശ്യമില്ല. ഇന്റർസെപ്റ്റ് ചെയ്യപ്പെടുന്ന പ്രോസസിൽ കോൺഫിഗറേഷൻ മാറ്റമൊന്നും ആവശ്യമില്ലെങ്കിലും, അത് ഡൈനാമിക് CA-യെ വിശ്വസിക്കണം.
**കുറിപ്പ്:** `source` = `"tproxy"`

**ആവശ്യകതകൾ:** Linux മാത്രം (**IP_TRANSPARENT** Linux-ൽ മാത്രമേ ലഭ്യമാകൂ), **CAP_NET_ADMIN** ശേഷി (root), കൂടാതെ C ടൂൾചെയിൻ ഉപയോഗിച്ച് ബിൽഡ് ചെയ്യേണ്ട ഒരു നേറ്റീവ് N-API ആഡോൺ (`npm run build:native:tproxy`). ഇത് ലഭ്യമല്ലാത്തപ്പോൾ, "TPROXY ഡീക്രിപ്ഷന് Linux + root + നേറ്റീവ് ആഡോൺ ആവശ്യമാണ്" എന്ന ടൂൾടിപ്പോടെ ഡാഷ്ബോർഡ് ടോഗിൾ പ്രവർത്തനരഹിതമാക്കപ്പെടും. ഫയർവാൾ നിയമങ്ങൾ ട്രാൻസാക്ഷണലായി പ്രയോഗിക്കുകയും റിവർട്ട് ചെയ്യുകയും ചെയ്യുന്നു (ഒരു ക്രാഷും `mangle` നിയമം ശേഷിപ്പിക്കില്ല), കൂടാതെ റീബൂട്ട് ചെയ്യുമ്പോൾ അവ നീക്കം ചെയ്യപ്പെടും. SO_MARK അടിസ്ഥാനമാക്കിയ ആന്റി-ലൂപ്പ്, പ്രോക്സി തന്നെ വീണ്ടും എൻക്രിപ്റ്റ് ചെയ്ത് ഫോർവേഡ് ചെയ്യുന്ന ട്രാഫിക് വീണ്ടും ഇന്റർസെപ്റ്റ് ചെയ്യപ്പെടുന്നത് തടയുന്നു.

ഇത് സ്വന്തം സമർപ്പിത ഓപ്പറേറ്റർ ഗൈഡുള്ള വിപുലമായ ഒരു സബ്സിസ്റ്റമാണ് — പൂർണ്ണമായ ഫയർവാൾ റെസിപ്പി, ഓരോ SNI-ക്കുമുള്ള ഡൈനാമിക് CA + ട്രസ്റ്റ്-സ്റ്റോർ ഇൻസ്റ്റാളർ, ലോക്കൽ-ഒൺലി റൂട്ട്, ആന്റി-ലൂപ്പ് വിശദാംശങ്ങൾ, കോൺഫിഗറേഷൻ സ്കീമ എന്നിവയ്ക്കായി `docs/security/MITM-TPROXY-DECRYPT.md` കാണുക (git; `/docs`-ലേക്ക് കംപൈൽ ചെയ്തിട്ടില്ല). `GET / POST / DELETE /api/tools/agent-bridge/tproxy` ആണ് ടോഗിളിനെ നിയന്ത്രിക്കുന്നത് (ശ്രദ്ധിക്കുക: റൂട്ട് Traffic Inspector പ്രിഫിക്സിന് കീഴിലല്ല, AgentBridge പ്രിഫിക്സിന് കീഴിലാണ്).

### 3.2 അഭ്യർത്ഥനാ പട്ടിക (ഇടത് പാനൽ)

- **വിർച്വലൈസ് ചെയ്തത്** (`useVirtualList` + `ResizeObserver`): ഫ്രീസ് ആകാതെ 1000 ഇനങ്ങൾ കൈകാര്യം ചെയ്യുന്നു

- **നിറംകൊണ്ട് സൂചിപ്പിച്ച സ്റ്റാറ്റസ്**: പച്ച (2xx), മഞ്ഞ (3xx), ചുവപ്പ് (4xx/5xx), ചാരനിറം (പുരോഗതിയിലുള്ളത്)
- **ഏജന്റ് ഇമോജി**: 🔵 Antigravity, 🟢 Copilot, 🟠 Kiro, 🟣 Codex, 🔷 Cursor, 🟤 Zed, 🟡 Claude Code, ⚫ Open Code, 🌐 ഇഷ്ടാനുസൃത ഹോസ്റ്റ്
- **കോൺടെക്സ്റ്റ് വർണ്ണ ബാർ**: `contextKey` അനുസരിച്ച് നിറം നൽകിയ 1px ഇടത് ബോർഡർ (സിസ്റ്റം പ്രോംപ്റ്റിന്റെ SHA-256) — ബന്ധപ്പെട്ട സംഭാഷണങ്ങളെ ദൃശ്യപരമായി ഗ്രൂപ്പുചെയ്യുന്നു
- **ലേസി ബോഡി**: തിരഞ്ഞെടുത്ത അഭ്യർത്ഥനയുടെ ബോഡി മാത്രം വിശദാംശ ടാബുകളിൽ മെറ്റീരിയലൈസ് ചെയ്യുന്നു (1000 × 1MB ബോഡികൾ റെൻഡർ ചെയ്യുന്നത് ഒഴിവാക്കുന്നു)

## §4 LLM-അവബോധമുള്ള സവിശേഷതകൾ

### 4.1 തരം കണ്ടെത്തൽ (`src/mitm/inspector/kindDetector.ts`)

4 സൂചനകൾ ഉപയോഗിച്ച് ഓരോ അഭ്യർത്ഥനയെയും `"llm"`, `"app"`, അല്ലെങ്കിൽ `"unknown"` എന്ന് വർഗ്ഗീകരിക്കുന്നു:

1. **ഹോസ്റ്റ് രജിസ്ട്രി** — അറിയപ്പെടുന്ന ~18 LLM API ഹോസ്റ്റ് നാമങ്ങൾ (OpenAI, Anthropic, Gemini, Groq, Mistral, Together, Fireworks, Cohere, Perplexity, Hugging Face, OpenRouter, xAI, Moonshot തുടങ്ങിയവ)
2. **പാത്ത് പാറ്റേണുകൾ** — `/v1/chat/completions`, `/v1/messages`, `/generateContent`, `/v1/responses` തുടങ്ങിയവ
3. **ബോഡി ഘടന** — `messages[]` (OpenAI/Claude), `contents[]` (Gemini), `prompt`, `input` ഫീൽഡുകൾ കണ്ടെത്തുന്നു
4. **യൂസർ-ഏജന്റ് സൂചനകൾ** — UA സ്ട്രിങ്ങിലെ `codex`, `claude`, `gemini`, `antigravity`, `kiro`, `copilot`, `cursor`

Mode 2 വഴി ചേർക്കുന്ന ഇഷ്ടാനുസൃത ഹോസ്റ്റുകൾക്ക് ഫോം ഇൻപുട്ടിൽനിന്ന് അവയുടെ `kind` ലഭിക്കുന്നു (ഡിഫോൾട്ട് `"custom"`).

### 4.2 SSE ലയനം (`src/mitm/inspector/sseMerger.ts`)

**സ്വതന്ത്രമായ ക്ലീൻ-റൂം ഇംപ്ലിമെന്റേഷൻ.** ഇവന്റ് പാർസിങ്
[WHATWG സെർവർ-സെന്റ് ഇവന്റ്സ് അൽഗോരിതം](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream)
പിന്തുടരുന്നു; പുനർനിർമാണം പൊതുവായി ലഭ്യമായ [OpenAI](https://platform.openai.com/docs/api-reference/chat/create),
[Anthropic](https://platform.claude.com/docs/en/build-with-claude/streaming), [Gemini](https://ai.google.dev/api/generate-content#method:-models.streamgeneratecontent)
സ്ട്രീമിങ് സ്കീമകൾ പിന്തുടരുന്നു.

അസംസ്കൃത SSE ഡെൽറ്റ ഇവന്റുകളിൽനിന്ന് അന്തിമ അസിസ്റ്റന്റ് സന്ദേശം പുനർനിർമിക്കുന്നു:

- **Anthropic**: ഇൻഡക്സ് അനുസരിച്ച് `content_block_delta` സമാഹരിക്കുന്നു; `text_delta`, `input_json_delta` (ടൂൾ കോളുകൾ), `thinking_delta` എന്നിവ കൈകാര്യം ചെയ്യുന്നു
- **OpenAI**: Chat Completions ചോയ്സുകൾ/ടൂൾ കോളുകൾ, Responses API ഔട്ട്പുട്ട് ഇനങ്ങൾ എന്നിവ ഇൻഡക്സ് അനുസരിച്ച് സമാഹരിക്കുന്നു
- **Gemini**: `candidates[i].content.parts` സമാഹരിക്കുന്നു
- **Unknown**: അസംസ്കൃത ഇവന്റുകൾ അതേപടി തിരികെ നൽകുന്നു

Response ടാബ് ഒരു ടോഗിൾ കാണിക്കുന്നു: **"അസംസ്കൃത ഇവന്റുകൾ ↔ ലയിപ്പിച്ചത്"**.

### 4.3 സംഭാഷണ നോർമലൈസർ (`src/mitm/inspector/conversationNormalizer.ts`)

**സ്വതന്ത്രമായ ക്ലീൻ-റൂം ഇംപ്ലിമെന്റേഷൻ.** നോർമലൈസേഷൻ നിർവചിക്കുന്നത് പ്രാദേശിക ബ്ലാക്ക്-ബോക്സ്
കരാറുകളും പൊതുവായി ലഭ്യമായ OpenAI, Anthropic, Gemini സന്ദേശ സ്കീമകളും ഉപയോഗിച്ചാണ്; അപ്സ്ട്രീം
ഇംപ്ലിമെന്റേഷൻ സോഴ്സുകളൊന്നും ഉപയോഗിക്കുന്നില്ല.

റെൻഡർ ചെയ്യുന്നതിന് മുമ്പ് OpenAI, Anthropic, Gemini സന്ദേശ ഫോർമാറ്റുകളെ ഒരൊറ്റ `NormalizedConversation`-ലേക്ക് പരിവർത്തനം ചെയ്യുന്നു:

```ts
interface NormalizedConversation {
  request: NormalizedTurn[]; // അഭ്യർത്ഥനാ ബോഡിയിലെ സന്ദേശങ്ങൾ / ഉള്ളടക്കങ്ങൾ / പ്രോംപ്റ്റ്
  response: NormalizedTurn[]; // അസിസ്റ്റന്റ് പ്രതികരണം (sseMerger വഴി ലയിപ്പിച്ചത്)
  contextKey: string | null; // SHA-256 സിസ്റ്റം-പ്രോംപ്റ്റ് ഫിംഗർപ്രിന്റ്
}
```

ബ്ലോക്ക് തരങ്ങൾ: `text`, `tool_use`, `tool_result`. പ്രൊവൈഡർ ഏതായാലും Conversation ടാബ് ഈ ഘടന ഉപയോഗിക്കുന്നു.

### 4.4 കോൺടെക്സ്റ്റ് കീ കളറൈസേഷൻ (`src/mitm/inspector/contextKey.ts`)

- സിസ്റ്റം പ്രോംപ്റ്റിന്റെ `SHA-256` കണക്കാക്കുന്നു (ആദ്യത്തെ `role:system` സന്ദേശം, അല്ലെങ്കിൽ `system` ഫീൽഡ്, അല്ലെങ്കിൽ Gemini `systemInstruction`)
- 12 പ്രതീകങ്ങളുള്ള ഒരു ഹെക്സ് പ്രിഫിക്സ് (`"a3f9c2..."`) തിരികെ നൽകുന്നു
- ഇടത് ബോർഡർ ബാറിനായി ഫ്രണ്ട്എൻഡ് കീയെ നിർണിതമായ ഒരു HSL നിറത്തിലേക്ക് മാപ്പ് ചെയ്യുന്നു
- **"ഒരേ കോൺടെക്സ്റ്റ്" ഫിൽട്ടർ**: `ctx #a3f` ചിപ്പിൽ ക്ലിക്ക് ചെയ്യുമ്പോൾ ഒരേ ഫിംഗർപ്രിന്റുള്ള അഭ്യർത്ഥനകൾ മാത്രം കാണിക്കുന്നതിനുള്ള ഒരു ഫിൽട്ടർ ചേർക്കുന്നു

ഒരേ ഏജന്റ് സെഷനിൽ പ്രവർത്തിക്കുന്ന വ്യത്യസ്ത "വ്യക്തിത്വങ്ങൾ" അല്ലെങ്കിൽ ടാസ്ക്കുകൾ ദൃശ്യപരമായി വേർതിരിച്ചറിയാൻ ഇത് സഹായിക്കുന്നു.

### 4.5 LLM മെറ്റാഡാറ്റ എക്സ്ട്രാക്ഷൻ

LLM അഭ്യർത്ഥനകൾക്കായി, LLM Details ടാബ് ഇനിപ്പറയുന്നവ എക്സ്ട്രാക്റ്റ് ചെയ്യുന്നു:

```ts
interface LlmMetadata {
  provider: string | null; // "openai" | "anthropic" | "gemini" | ...
  apiKind: string | null; // "chat.completions" | "messages" | "embeddings" | ...
  model: string | null; // അഭ്യർത്ഥനാ ബോഡിയിൽനിന്നോ പ്രതികരണത്തിൽനിന്നോ
  messages: number; // ടേണുകളുടെ എണ്ണം
  tokensIn: number | null; // usage.prompt_tokens / usage.input_tokens
  tokensOut: number | null; // usage.completion_tokens / usage.output_tokens
  streamed: boolean; // SSE പ്രതികരണമാണെങ്കിൽ true
  mappedTo: string | null; // x-omniroute-mapped ഹെഡർ
  costEstimateUsd: number | null; // OmniRoute നിരക്കുകളെ അടിസ്ഥാനമാക്കിയുള്ള കണക്കാക്കിയ ചെലവ്
}
```

### 4.6 തത്സമയ ഇൻ-ഫ്ലൈറ്റ് അഭ്യർത്ഥനാ ഫിൽട്ടർ

അഭ്യർത്ഥനയുടെ `status` ഫീൽഡ് `number | "in-flight" | "error"` ആണ് — അഭ്യർത്ഥന ആരംഭിക്കുന്ന നിമിഷംതന്നെ ഒരു എൻട്രി
`"in-flight"` ആയി ചേർക്കുകയും പ്രതികരണം (അല്ലെങ്കിൽ പിശക്) എത്തുമ്പോൾ അത് **അതേ സ്ഥാനത്ത് അപ്ഡേറ്റ്**
ചെയ്യുകയും ചെയ്യുന്നു. ടൂൾബാറിലെ **"തത്സമയം"** ടോഗിൾ
(`liveOnly`, i18n കീ `trafficInspector.liveOnly`) `status === "in-flight"` ആയ എൻട്രികൾ മാത്രമായി
ലിസ്റ്റിനെ പരിമിതപ്പെടുത്തുന്നു; ഇതുവഴി തുറന്ന കണക്ഷനുകൾ തത്സമയം നിരീക്ഷിക്കാനാകും.

ഫിൽട്ടർ `src/lib/inspector/matchesTrafficFilter.ts`-ലെ പൂർണ്ണമായും ക്ലയന്റ്-സൈഡ് പ്രെഡിക്കേറ്റാണ്:

```ts
if (f.liveOnly && req.status !== "in-flight") return false;
```

ടോഗിൾ നില `useTrafficFilters`-ലാണ് (ഇൻസ്പെക്ടർ ഡാഷ്ബോർഡ് ഹുക്കുകൾ) സൂക്ഷിക്കുന്നത്; ഇത് മറ്റ് ഫിൽട്ടറുകളുമായി (പ്രൊഫൈൽ, ഹോസ്റ്റ്, ഏജന്റ്, സോഴ്സ്, സ്റ്റാറ്റസ്, കോൺടെക്സ്റ്റ്) സംയോജിക്കുന്നു.

### 4.7 പ്രോസസ് ആട്രിബ്യൂഷൻ (Linux)

Linux-ൽ, ഇന്റർസെപ്റ്റ് ചെയ്യുന്ന ഓരോ അഭ്യർത്ഥനയും അതിന്റെ **ഉത്ഭവ പ്രാദേശിക
പ്രോസസുമായി** ബന്ധപ്പെടുത്താനാകും. `InterceptedRequest`-ലേക്ക് രണ്ട് ഓപ്ഷണൽ ഫീൽഡുകൾ ചേർക്കുന്നു:

```ts
pid?: number;          // ഉത്ഭവ പ്രോസസ് ഐഡി (Linux-ൽ മാത്രം)
processName?: string;  // ഉത്ഭവ പ്രോസസിന്റെ പേര് (Linux-ൽ മാത്രം)
```

`src/mitm/inspector/processAttribution.ts` കണക്ഷന്റെ _ക്ലയന്റ്_
എഫെമറൽ പോർട്ടിനെ ഒരു PID + പേരിലേക്ക് ഇനിപ്പറയുന്ന രീതിയിൽ മാപ്പ് ചെയ്യുന്നു:

1. പോർട്ടിന്റെ സോക്കറ്റ് inode കണ്ടെത്തുന്നതിനായി `/proc/net/tcp`, `/proc/net/tcp6` എന്നിവ വായിക്കുന്നു
   (`parseProcNetTcpForInode`, ഫിക്സ്ചർ ഉപയോഗിച്ച് പരിശോധിക്കാവുന്ന ഒരു പ്യുവർ പാർസർ).
2. `socket:[<inode>]`-ലേക്കുള്ള സിംലിങ്കിനായി `/proc/<pid>/fd/` സ്കാൻ ചെയ്യുന്നു.
3. `/proc/<pid>/comm`-ൽനിന്ന് പ്രോസസിന്റെ പേര് വായിക്കുന്നു.

ലോഡിന് കീഴിലുള്ള procfs സ്കാൻ ചെലവ് 1-സെക്കൻഡ് TTL കാഷ് ഉപയോഗിച്ച് നിയന്ത്രിക്കുന്നു. ആട്രിബ്യൂഷൻ
**പരമാവധി ശ്രമത്തിന്റെ അടിസ്ഥാനത്തിലാണ്** — ഏത് പരാജയവും `null` ആയി പരിഹരിക്കപ്പെടുന്നു, ക്യാപ്ചർ ഒരിക്കലും തടയുന്നില്ല.
macOS/Windows-ൽ ഫങ്ഷൻ `null` തിരികെ നൽകുന്നു (സ്റ്റബ്; `lsof`/`GetExtendedTcpTable`
പിന്തുണ തുടർനടപടിയാണ്).

## §5 സെഷനുകൾ

### 5.1 ഒരു സെഷൻ റെക്കോർഡ് ചെയ്യൽ

1. ടൂൾബാറിലെ **"● സെഷൻ റെക്കോർഡ് ചെയ്യുക"** ക്ലിക്ക് ചെയ്യുക → ഒരു പേര് നൽകുക (ഐച്ഛികം)
2. തത്സമയ ടെയിൽ സാധാരണപോലെ തുടരുന്നു; ചുവന്ന മിന്നുന്ന സൂചകം `◉ REC · <name> · 00:42 · 23 അഭ്യർത്ഥനകൾ` എന്ന് കാണിക്കുന്നു
3. **"⏹ നിർത്തുക"** ക്ലിക്ക് ചെയ്യുക → സെഷൻ സ്നാപ്പ്ഷോട്ട് `inspector_sessions` + `inspector_session_requests` എന്നിവയിൽ സംരക്ഷിക്കപ്പെടുന്നു

### 5.2 റെക്കോർഡ് ചെയ്ത സെഷൻ കാണൽ

ടൂൾബാറിലെ **സെഷനുകൾ** ഡ്രോപ്പ്ഡൗൺ സംരക്ഷിച്ച സെഷനുകൾ പട്ടികപ്പെടുത്തുന്നു. ഒരെണ്ണം തിരഞ്ഞെടുക്കുമ്പോൾ:

- സെഷന്റെ സ്നാപ്പ്ഷോട്ട് ലോഡ് ചെയ്യുന്നു (ഫ്രീസ് ചെയ്ത അവസ്ഥ)
- ഒരു ബാനർ ഇങ്ങനെ കാണിക്കുന്നു: `റെക്കോർഡ് ചെയ്ത സെഷൻ "<name>" കാണുന്നു — [തത്സമയ കാഴ്ചയിലേക്ക് മടങ്ങുക]`
- Recharts അഗ്രിഗേറ്റുകളോടുകൂടിയ സ്ഥിതിവിവരക്കണക്ക് ടാബ് ലഭ്യമാകുന്നു

### 5.3 എക്സ്പോർട്ട് ഫോർമാറ്റുകൾ

ഓരോ സെഷനും ഇനിപ്പറയുന്ന ഫോർമാറ്റുകളിൽ എക്സ്പോർട്ട് ചെയ്യാം:

| ഫോർമാറ്റ്                  | ഉപയോഗം                                                                                                      |
| -------------------------- | ----------------------------------------------------------------------------------------------------------- |
| **HAR** (HTTP Archive 1.2) | Chrome DevTools, Charles, Fiddler എന്നിവയുമായി പൊരുത്തപ്പെടുന്നു — ഓഫ്ലൈൻ വിശകലനത്തിനായി ഇമ്പോർട്ട് ചെയ്യുക |
| **JSONL**                  | ഓരോ വരിയിലും ഒരു `InterceptedRequest` — `llm-interceptor` ഫോർമാറ്റുമായി പൊരുത്തപ്പെടുന്നു                   |

`GET /api/tools/traffic-inspector/sessions/{id}/export.har` വഴിയോ സെഷനുകൾ ഡ്രോപ്പ്ഡൗണിലെ ⬇ ബട്ടൺ വഴിയോ എക്സ്പോർട്ട് ചെയ്യുക.

## §6 സുരക്ഷ

ട്രാഫിക് ഇൻസ്പെക്ടർ ഓതറൈസേഷൻ ഹെഡറുകളും അഭ്യർത്ഥന ബോഡികളും ഉൾപ്പെടെ **ഇന്റർസെപ്റ്റ് ചെയ്ത എല്ലാ HTTPS ട്രാഫിക്കും** കാണിക്കുന്നു. ഇനിപ്പറയുന്ന നിയന്ത്രണങ്ങൾ നിലവിലുണ്ട്:

| നിയന്ത്രണം                         | വിശദാംശങ്ങൾ                                                                                                                                                                                 |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LOCAL_ONLY**                     | എല്ലാ റൂട്ടുകളും WebSocket എൻഡ്പോയിന്റും ലൂപ്പ്ബാക്കിൽ മാത്രം ലഭ്യമാണ് (ഓതന്റിക്കേഷനു മുമ്പ് `routeGuard.ts`-ൽ ഇത് നിർബന്ധിതമാക്കുന്നു)                                                     |

| **CSP**                            | ഇൻജക്റ്റ് ചെയ്ത പ്രതികരണ ബോഡികൾ വഴിയുള്ള XSS തടയാൻ ട്രാഫിക് ഇൻസ്പെക്ടർ പേജുകളിൽ കർശനമായ Content Security Policy പ്രയോഗിക്കുന്നു                                                             |

### അറിയപ്പെടുന്ന പരിമിതികൾ

- **സിസ്റ്റം-വ്യാപക പ്രോക്സി മോഡ്** VPN ക്ലയന്റുകളും SSO-യും ഉൾപ്പെടെ മെഷീനിലെ എല്ലാ ആപ്ലിക്കേഷനുകളെയും ബാധിക്കുന്നു. എല്ലായ്പ്പോഴും ഓട്ടോ-ഡിസേബിൾ ടൈമറോടൊപ്പം ഉപയോഗിക്കുക. പങ്കിടുന്ന മെഷീനുകളിൽ ഉപയോഗിക്കരുത്.
- **CONNECT ടണൽ HTTPS**: TLS ഇന്റർസെപ്ഷൻ പ്രവർത്തനക്ഷമമാക്കിയിട്ടില്ലെങ്കിൽ, മോഡ് 3 (HTTP_PROXY) HTTPS ലക്ഷ്യസ്ഥാനങ്ങൾക്കായി ടണൽ മെറ്റാഡാറ്റ മാത്രം ക്യാപ്ചർ ചെയ്യുന്നു. ഇത് രൂപകൽപ്പനാപരമാണ് — AgentBridge സർട്ടിഫിക്കറ്റ് വിശ്വസനീയമാക്കിയിട്ടില്ലാതെ സുതാര്യമായ ക്യാപ്ചർ നടത്തുന്നത് ആ ആപ്പുകളുടെ TLS പരിശോധന തകരാറിലാക്കും.
- **ചില ഘടകങ്ങളിലെ ഹാർഡ്കോഡ് ചെയ്ത സ്ട്രിങ്ങുകൾ**: ചില UI ഘടകങ്ങളിൽ (F7/F8) ഇതുവരെ i18n കീകളിൽ ഉൾപ്പെടുത്തിയിട്ടില്ലാത്ത കുറച്ച് ഹാർഡ്കോഡ് ചെയ്ത സ്ട്രിങ്ങുകളുണ്ട്. i18n വിടവ് റിപ്പോർട്ടിൽ ഇവ അറിയപ്പെടുന്ന പരിമിതിയായി രേഖപ്പെടുത്തിയിട്ടുണ്ട്; തുടർ പാസിൽ ഇവ മൈഗ്രേറ്റ് ചെയ്യും. പ്രവർത്തനപരമായ ഉപയോഗത്തിന് വിവർത്തനം ആവശ്യമില്ലാത്ത UI അലങ്കാര ലേബലുകളാണ് ബാധിക്കപ്പെട്ട സ്ട്രിങ്ങുകൾ.

## §7 പ്രശ്നപരിഹാരം

### WebSocket വിച്ഛേദിക്കൽ

ലൈവ് ടെയിലിൽ "വിച്ഛേദിച്ചു" എന്ന് കാണിക്കുന്നുവെങ്കിൽ:

1. സെർവർ ഇപ്പോഴും പ്രവർത്തിക്കുന്നുണ്ടെന്ന് പരിശോധിക്കുക: `GET /api/tools/traffic-inspector/capture-modes`
2. പേജ് വീണ്ടും ലോഡ് ചെയ്യുക — WebSocket വീണ്ടും കണക്റ്റ് ചെയ്ത് ഒരു പുതിയ സ്നാപ്പ്ഷോട്ട് സ്വീകരിക്കും
3. സെർവർ പുനരാരംഭിച്ചിട്ടുണ്ടെങ്കിൽ, ഇൻ-മെമ്മറി ബഫർ മായ്ക്കപ്പെട്ടിരിക്കും — ഒരു സെഷൻ റെക്കോർഡ് ചെയ്തിട്ടില്ലെങ്കിൽ പഴയ എൻട്രികൾ നഷ്ടമായിരിക്കും

### പോർട്ട് 8080 വൈരുദ്ധ്യം

HTTP_PROXY മോഡ് ആരംഭിക്കുന്നതിൽ പരാജയപ്പെടുന്നുവെങ്കിൽ:

```bash
lsof -i :8080    # പ്രോസസ് കണ്ടെത്തുക
```

പോർട്ട് മാറ്റുക:

```bash
# .env
INSPECTOR_HTTP_PROXY_PORT=8888
```

### സിസ്റ്റം പ്രോക്സി പഴയ നിലയിലേക്ക് മാറ്റിയിട്ടില്ല

സിസ്റ്റം-വ്യാപക പ്രോക്സി മോഡ് സജീവമായിരിക്കുമ്പോൾ OmniRoute ക്രാഷ് ആകുന്നുവെങ്കിൽ:

**macOS:**

```bash
networksetup -setwebproxystate Wi-Fi off
networksetup -setsecurewebproxystate Wi-Fi off
```

**Linux (GNOME):**

```bash
gsettings set org.gnome.system.proxy mode 'none'
```

**Windows:**

```cmd
netsh winhttp reset proxy
```

പ്രോക്സി സജീവമായിരുന്നുവെന്ന് DB നില സൂചിപ്പിക്കുന്നതായി കണ്ടെത്തിയാൽ, അടുത്ത തവണ ലോഡ് ചെയ്യുമ്പോൾ ഡാഷ്ബോർഡ് "സിസ്റ്റം പ്രോക്സി പഴയ നിലയിലേക്ക് മാറ്റുക" എന്ന ഓപ്ഷനും നൽകും.

### ബഫർ നിറഞ്ഞു

ബഫർ `INSPECTOR_BUFFER_SIZE`-ൽ (ഡിഫോൾട്ട് 1000) എത്തുമ്പോൾ, പുതിയ എൻട്രികൾ ഏറ്റവും പഴയവയെ ഒഴിവാക്കും. പ്രധാനപ്പെട്ട അഭ്യർത്ഥനകൾ നഷ്ടപ്പെടുന്നുവെങ്കിൽ:

- `INSPECTOR_BUFFER_SIZE` വർധിപ്പിക്കുക (ഉദാ., 5000) — കൂടുതൽ സമയം നിലനിർത്തുന്നതിനായി കൂടുതൽ മെമ്മറി ഉപയോഗിക്കും
- പ്രസക്തമായ സമയപരിധിയിലെ ഡാറ്റ DB-യിൽ സ്ഥിരമായി സൂക്ഷിക്കാൻ ഒരു സെഷൻ റെക്കോർഡ് ചെയ്യുക

## §8 API റഫറൻസ്

എല്ലാ റൂട്ടുകളും `LOCAL_ONLY` (ലൂപ്പ്ബാക്കിൽ മാത്രം), `SPAWN_CAPABLE` (സിസ്റ്റം പ്രോക്സി കമാൻഡുകൾ) എന്നിവയാണ്. `src/server/authz/routeGuard.ts` കാണുക.

അടിസ്ഥാന പാത: `/api/tools/traffic-inspector/`

### അഭ്യർത്ഥന മാനേജ്മെന്റ്

| രീതി   | പാത                         | വിവരണം                                                                                                       |

| GET    | `/requests/{id}`            | ഒറ്റ അഭ്യർത്ഥനയുടെ വിശദാംശങ്ങൾ                                                                               |

| POST   | `/requests/{id}/replay`     | അതേ അഭ്യർത്ഥന OmniRoute റൂട്ടറിലൂടെ വീണ്ടും എക്സിക്യൂട്ട് ചെയ്യുക                                            |
| PUT    | `/requests/{id}/annotation` | ഒരു അഭ്യർത്ഥനയിലെ കുറിപ്പ് സേവ് ചെയ്യുകയോ അപ്ഡേറ്റ് ചെയ്യുകയോ ചെയ്യുക                                        |
