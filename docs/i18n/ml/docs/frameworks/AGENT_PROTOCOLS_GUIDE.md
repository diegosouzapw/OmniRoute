OmniRoute ഏജന്റുകളുമായി ബന്ധപ്പെട്ട മൂന്ന് വ്യത്യസ്ത ഇന്റർഫേസുകൾ ലഭ്യമാക്കുന്നു. ഒറ്റനോട്ടത്തിൽ അവ സമാനമായി തോന്നുമെങ്കിലും, വ്യത്യസ്ത പ്രശ്നങ്ങളാണ് പരിഹരിക്കുന്നത്. അനുയോജ്യമായത് തിരഞ്ഞെടുക്കാൻ ഈ പേജ് ഉപയോഗിക്കുക.

## 1. A2A — ഏജന്റ്-ടു-ഏജന്റ്

**സ്പെക്:** [A2A v0.3](https://a2a-protocol.org)
**OmniRoute എൻഡ്പോയിന്റ്:** `POST /a2a` (JSON-RPC 2.0)
**ഏജന്റ് കാർഡ്:** `GET /.well-known/agent.json`

### എപ്പോൾ ഉപയോഗിക്കണം

- OmniRoute പിയറുകളിൽ ഒന്നായ ഒരു മൾട്ടി-ഏജന്റ് സിസ്റ്റം നിർമ്മിക്കുമ്പോൾ
- Google ADK പോലുള്ള ഫ്രെയിംവർക്കുകളിലോ പൊതുവായ ഏജന്റ് മെഷുകളിലോ ഉള്ള ഏജന്റുകൾക്ക് OmniRoute-ന്റെ റൂട്ടിങ് ഇന്റലിജൻസ് (സ്മാർട്ട് റൂട്ടിങ്, ക്വാട്ട മാനേജ്മെന്റ് മുതലായവ) ലഭ്യമാക്കുമ്പോൾ
- ഒരു സ്റ്റാൻഡേർഡ് ഡിസ്കവറി + ഇൻവൊക്കേഷൻ ഇന്റർഫേസിന് പിന്നിൽ OmniRoute ഉൾപ്പെടുത്തുമ്പോൾ

### രീതികൾ

- `message/send` — ഒരു സന്ദേശം സമർപ്പിച്ച് സമകാലിക പ്രതികരണം സ്വീകരിക്കുക
- `message/stream` — സമർപ്പിച്ച് SSE-സ്ട്രീം ചെയ്ത പുരോഗതി ഇവന്റുകൾ സ്വീകരിക്കുക
- `tasks/get` — ID ഉപയോഗിച്ച് ടാസ്ക് വായിക്കുക
- `tasks/cancel` — പ്രവർത്തിച്ചുകൊണ്ടിരിക്കുന്ന ഒരു ടാസ്ക് റദ്ദാക്കുക

### ബിൽറ്റ്-ഇൻ സ്കില്ലുകൾ (6)

- `smart-routing` — ഒരു പ്രോംപ്റ്റിനെ ഏറ്റവും അനുയോജ്യമായ കോംബോയിലൂടെ റൂട്ട് ചെയ്യുക
- `quota-management` — ഓരോ പ്രൊവൈഡറിന്റെയും ക്വാട്ട നില റിപ്പോർട്ട് ചെയ്യുക
- `provider-discovery` — ശേഷികളോടൊപ്പം ഇൻസ്റ്റാൾ ചെയ്ത പ്രൊവൈഡറുകളെ പട്ടികപ്പെടുത്തുക
- `cost-analysis` — ഒരു അഭ്യർത്ഥനയുടെ/സംഭാഷണത്തിന്റെ ചെലവ് കണക്കാക്കുക
- `health-report` — ഓരോ പ്രൊവൈഡറിന്റെയും ബ്രേക്കർ/കൂൾഡൗൺ/ലോക്കൗട്ട് നില സംഗ്രഹിക്കുക
- `list-capabilities` — ഏജന്റിന്റെ ലഭ്യമായ സ്കില്ലുകളും മെറ്റാഡാറ്റയും എണ്ണിപ്പറയുക

### വിശദമായ അവലോകനം

ട്രാൻസ്പോർട്ട് വിശദാംശങ്ങൾ, ഏജന്റ് കാർഡ് ഘടന, ടാസ്ക് TTL കോൺഫിഗറേഷൻ, പുതിയ സ്കില്ലുകൾ ചേർക്കുന്നതിനുള്ള ടെംപ്ലേറ്റ് എന്നിവയ്ക്കായി [A2A-SERVER.md](./A2A-SERVER.md) കാണുക.

## 2. ACP — CLI ഏജന്റുകളുടെ രജിസ്ട്രി

**OmniRoute എൻഡ്പോയിന്റ്:** `GET /api/acp/agents`
**സോഴ്സ്:** `src/lib/acp/{index,manager,registry}.ts`

### ഇത് എന്താണ്

ACP എന്നത് OmniRoute-ന്റെ **ലോക്കൽ CLI ഏജന്റ് ഇൻവെന്ററിയാണ്**. ഹോസ്റ്റിൽ ഏതെല്ലാം കോഡിംഗ് CLI-കൾ ഇൻസ്റ്റാൾ ചെയ്തിട്ടുണ്ടെന്ന് (Cursor, Cline, Claude Code, Codex CLI, Continue തുടങ്ങിയവ) ഇത് കണ്ടെത്തുകയും അവയുടെ പതിപ്പുകൾ നിർണ്ണയിക്കുകയും ഡാഷ്ബോർഡിൽ പ്രദർശിപ്പിക്കുകയും ചെയ്യുന്നു. അതുവഴി ഓരോ CLI-യും OmniRoute-ലേക്ക് ചൂണ്ടിക്കാണിക്കുന്ന വിധത്തിൽ ഉപയോക്താവിന് ക്രമീകരിക്കാനാകും.

ഇത് ഒരു ബാഹ്യ പ്രോട്ടോക്കോൾ അല്ല — "CLI Tools" UI-യെയും CLI ഫിംഗർപ്രിന്റ് ട്രാക്കിംഗിനെയും പ്രവർത്തിപ്പിക്കുന്ന ഒരു ആന്തരിക രജിസ്ട്രിയാണ് (കാണുക [CLI-TOOLS.md](../reference/CLI-TOOLS.md)).

### ഇത് ചെയ്യുന്നത്

- ഇൻസ്റ്റാൾ ചെയ്ത CLI ബൈനറികൾക്കായി ഹോസ്റ്റ് പരിശോധിക്കുന്നു (OS അനുസരിച്ച് `which` / `where` ഉപയോഗിക്കുന്നു)
- ഓരോ CLI-യുടെയും പതിപ്പ് വായിക്കുന്നു (`<bin> --version` വിളിക്കുന്നു)
- ഉപയോക്താവ് നിർവചിച്ച കസ്റ്റം ഏജന്റുകളെ ഐച്ഛികമായി സ്വീകരിക്കുന്നു (ബൈനറി പാത്ത് + പതിപ്പ് പരിശോധന + spawn ആർഗ്യുമെന്റുകൾ)
- കസ്റ്റം ഏജന്റുകളെ ക്രമീകരണങ്ങളിൽ സ്ഥിരമായി സൂക്ഷിക്കുന്നു
- ഏകീകരിച്ച ലിസ്റ്റ് ഡാഷ്ബോർഡിലേക്ക് നൽകുന്നു

| ----------------- | ------- | ----------------------------------------------------------------------------------------------------- | ------ |
| `/api/acp/agents` | GET     | കണ്ടെത്തിയ + കസ്റ്റം ഏജന്റുകളെ പട്ടികപ്പെടുത്തുന്നു (ഇൻസ്റ്റാൾ ചെയ്തവ/ആകെ എണ്ണം)                      | API കീ |
| `/api/acp/agents` | POST    | കസ്റ്റം ഏജന്റിനെ ചേർക്കുന്നു/അപ്ഡേറ്റ് ചെയ്യുന്നു/നീക്കം ചെയ്യുന്നു (ബോഡിയിലെ ആക്ഷൻ ഡിസ്ക്രിമിനേറ്റർ) | API കീ |

POST-നുള്ള ബോഡി ഘടന (`src/app/api/acp/agents/route.ts`-ലെ `customAgentBodySchema`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### ഉപയോഗ സാഹചര്യങ്ങൾ

- ഡാഷ്ബോർഡിലെ "CLI Tools" പേജ് ഇൻസ്റ്റാൾ ചെയ്തിരിക്കുന്നവ പട്ടികപ്പെടുത്തുകയും ഓരോന്നിനെയും OmniRoute-ലേക്ക് ചൂണ്ടിക്കാണിക്കാൻ സഹായിക്കുകയും ചെയ്യുന്നു
- OmniRoute സ്ഥിരസ്ഥിതിയായി തിരിച്ചറിയാത്ത ആന്തരിക/പ്രൊപ്രൈറ്ററി CLI-കൾ രജിസ്റ്റർ ചെയ്യാൻ കസ്റ്റം ഏജന്റുകൾ പ്രഗത്ഭ ഉപയോക്താക്കളെ അനുവദിക്കുന്നു
- കണ്ടെത്തൽ ഫലം `cli-tools` ഫിംഗർപ്രിന്റ് മാട്രിക്സിന് ഡാറ്റ നൽകുന്നു

### ACP ഉപയോഗിക്കരുതാത്ത സാഹചര്യങ്ങൾ

- ACP ടാസ്ക്കുകൾ _പ്രവർത്തിപ്പിക്കുന്നില്ല_. ഇത് CLI-കളെ കണ്ടെത്തുകയും കോൺഫിഗർ ചെയ്യുകയും മാത്രമാണ് ചെയ്യുന്നത്. ഒരു CLI യഥാർത്ഥത്തിൽ പ്രവർത്തിപ്പിക്കാൻ, OmniRoute നൽകുന്ന env വേരിയബിളുകൾ (`OPENAI_BASE_URL`, `OPENAI_API_KEY` തുടങ്ങിയവ) ഉപയോഗിച്ച് നിങ്ങൾ തന്നെ അത് ലോഞ്ച് ചെയ്യണം.

## 3. ക്ലൗഡ് ഏജന്റുകൾ

**OmniRoute എൻഡ്പോയിന്റുകൾ:** `/api/v1/agents/tasks/*` (ലൈഫ്സൈക്കിൾ) + `/api/cloud/*` (പ്ലംബിംഗ്)
**സോഴ്സ്:** `src/lib/cloudAgent/`

### ഇത് എന്താണ്

മൂന്നാം കക്ഷി ക്ലൗഡ് കോഡിംഗ് ഏജന്റുകൾക്കായുള്ള ഏകീകൃത ഇന്റർഫേസ്. നിങ്ങൾ ഒരു പ്രോംപ്റ്റും + റിപ്പോ URL-ഉം സമർപ്പിക്കുമ്പോൾ, OmniRoute അത് ശരിയായ ക്ലൗഡ് ഏജന്റിലേക്ക് അയയ്ക്കുകയും സ്റ്റാറ്റസ് പോൾ ചെയ്യുകയും ഫലങ്ങൾ തിരികെ നൽകുകയും ചെയ്യുന്നു.

### പിന്തുണയ്ക്കുന്ന ഏജന്റുകൾ (4, എല്ലാം `src/lib/cloudAgent/agents/`-ൽ സ്ഥിരീകരിച്ചവ)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### ലൈഫ്സൈക്കിൾ

```
POST /api/v1/agents/tasks
  → ഓരോ ഏജന്റ് ക്ലാസിനും BaseAgent.createTask()
  → ബാഹ്യ സേവനം പ്രവർത്തനം ആരംഭിക്കുന്നു
  → DB-യിൽ ടാസ്ക് റോ സൃഷ്ടിക്കുന്നു (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → പ്രൊവൈഡറിൽ നിന്നുള്ള ലേസി സ്റ്റാറ്റസ് സമന്വയം
  → നിലവിലെ സ്റ്റാറ്റസ് + പ്ലാൻ + ആക്റ്റിവിറ്റി ലോഗ് നൽകുന്നു
  ↓
POST /api/v1/agents/tasks/[id]   (ആക്ഷൻ: "approve" | "message" | "cancel")
  → പ്രൊവൈഡറിലേക്ക് കൈമാറുന്നു (അല്ലെങ്കിൽ ലോക്കലായി റദ്ദാക്കിയതായി അടയാളപ്പെടുത്തുന്നു)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → ലോക്കൽ റദ്ദാക്കൽ
```

### ഓത്ത്

⚠️ **എല്ലാ `/api/v1/agents/tasks/*` എൻഡ്പോയിന്റുകൾക്കും മാനേജ്മെന്റ് ഓത്ത് ആവശ്യമാണ്** (കമ്മിറ്റ് `588a0333`). v3.8.0 മുതൽ Bearer മാത്രം ഉപയോഗിക്കുന്ന കോളർമാർക്ക് 401 ലഭിക്കും.

### വിശദമായ അവലോകനം

`CloudAgentBase` കോൺട്രാക്ട്, ഓരോ ഏജന്റിന്റെയും പ്രത്യേകതകൾ, സ്കീമ വിശദാംശങ്ങൾ, ക്രെഡൻഷ്യൽ പ്ലംബിംഗ് എൻഡ്പോയിന്റുകൾ എന്നിവയ്ക്കായി [CLOUD_AGENT.md](./CLOUD_AGENT.md) കാണുക.

## താരതമ്യം: A2A vs Cloud Agents

രണ്ടിലും "ദീർഘനേരം പ്രവർത്തിക്കുന്ന ടാസ്കുകൾ" ഉണ്ടെങ്കിലും അവ വ്യത്യസ്ത ലെയറുകളിലാണ്:

| വശം                    | A2A                                                                                       | Cloud Agents                                         |
| ---------------------- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| സ്റ്റാൻഡേർഡ്           | Open A2A v0.3                                                                             | OmniRoute-നു മാത്രമായുള്ളത്                          |
| കംപ്യൂട്ട് നടക്കുന്നത് | OmniRoute-നുള്ളിൽ (കോൺഫിഗർ ചെയ്ത കോംബോകൾ ഉപയോഗിക്കുന്നു)                                  | ബാഹ്യമായി (Codex / Devin / Jules സെർവറുകൾ)           |
| ടാസ്കിന്റെ ദൈർഘ്യം     | ഡിഫോൾട്ട് TTL 5 മിനിറ്റ് (`TaskManager`-ൽ കോൺഫിഗർ ചെയ്യാം)                                | മിനിറ്റുകൾ മുതൽ മണിക്കൂറുകൾ വരെ                      |
| റിപ്പോ-അവബോധം          | ഇല്ല (പ്രോംപ്റ്റുകൾ മാത്രം കൈമാറുന്നു)                                                    | ഉണ്ട് (റിപ്പോ URL + ബ്രാഞ്ച്)                        |
| ഉപയോഗ സാഹചര്യം         | ഏജന്റുകൾ തമ്മിലുള്ള സഹകരണം, ഒരു സേവനമായുള്ള സ്മാർട്ട് റൂട്ടിംഗ്                           | "റിപ്പോ Y-ൽ ഫീച്ചർ X നടപ്പിലാക്കുക" എന്ന് ഏൽപ്പിക്കൽ |
| ഓത്ത്                  | `/a2a`-യ്ക്കായി ഓപ്ഷണൽ `OMNIROUTE_API_KEY`; `/api/a2a/*` REST ഹെൽപ്പറുകൾക്ക് മാനേജ്മെന്റ് | എപ്പോഴും മാനേജ്മെന്റ്                                |

## ഇന്റഗ്രേഷൻ ഉദാഹരണങ്ങൾ

### OmniRoute-ന്റെ A2A ശേഷികൾ കണ്ടെത്തുക

```bash
curl http://localhost:20128/.well-known/agent.json
```

എല്ലാ 6 സ്കില്ലുകളും ട്രാൻസ്പോർട്ടുകളും പതിപ്പും ഉൾപ്പെടുന്ന Agent Card തിരികെ നൽകുന്നു.

### OmniRoute-നെ ഒരു A2A ഏജന്റായി വിളിക്കുക

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### ACP വഴി ഇൻസ്റ്റാൾ ചെയ്ത CLI ഏജന്റുകളെ ലിസ്റ്റ് ചെയ്യുക

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### ഒരു കസ്റ്റം CLI ഏജന്റ് ചേർക്കുക

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### ഒരു Cloud Agent ടാസ്ക് സമർപ്പിക്കുക

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### ക്ലൗഡ് ടാസ്കിന്റെ നില പോൾ ചെയ്യുക

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```
