OmniRoute പ്രാദേശികമായി ഇൻസ്റ്റാൾ ചെയ്യുകയും മേൽനോട്ടം വഹിക്കുകയും പ്രഥമ-ശ്രേണി റൂട്ടിംഗ് ലക്ഷ്യങ്ങളായി
ലഭ്യമാക്കുകയും ചെയ്യുന്ന പ്രോസസ് സൈഡ്കാർ ടൂളുകളാണ് എംബെഡഡ് സേവനങ്ങൾ. API കീകൾ വഴി ഇന്റർനെറ്റിലൂടെ
ആക്സസ് ചെയ്യുന്ന ബാഹ്യ ദാതാക്കളിൽനിന്ന് വ്യത്യസ്തമായി, എംബെഡഡ് സേവനങ്ങൾ OmniRoute പ്രവർത്തിക്കുന്ന അതേ മെഷീനിൽ പ്രവർത്തിക്കുകയും ലൂപ്പ്ബാക്കിലൂടെ ആശയവിനിമയം നടത്തുകയും ചെയ്യുന്നു.

| സേവനം           | npm പാക്കേജ്                     | ഡിഫോൾട്ട് പോർട്ട് | ഉദ്ദേശ്യം                                                                                                                                                                                                                                                                                                                                                                                  |
| --------------- | -------------------------------- | :---------------: | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

ഏഴ് സേവനങ്ങളും ഒരേ സൂപ്പർവൈസറി മാതൃക പിന്തുടരുന്നു:

- OmniRoute അവയെ `DATA_DIR/services/{name}/` എന്നതിന് കീഴിൽ ഇൻസ്റ്റാൾ ചെയ്യുന്നു (OmniRoute-ന്റെ സ്വന്തം `package.json`-ൽ നിന്ന് വേർതിരിച്ച്)
- OmniRoute അവയെ ചൈൽഡ് പ്രോസസുകളായി സ്പോൺ ചെയ്ത് നിരീക്ഷിക്കുന്നു
- OmniRoute ചൈൽഡിന്റെ എൻവയോൺമെന്റിലേക്ക് ഒരു താൽക്കാലിക API കീ ഇൻജക്റ്റ് ചെയ്യുകയും പ്രവർത്തനത്തടസ്സമില്ലാതെ അത് റൊട്ടേറ്റ് ചെയ്യുകയും ചെയ്യുന്നു (ബാധകമായിടത്ത്)
- എല്ലാ മാനേജ്മെന്റ് റൂട്ടുകളും (`/api/services/*`) **LOCAL_ONLY** ആണ് — ലൂപ്പ്ബാക്കിൽ നിന്ന് മാത്രം ആക്സസ് ചെയ്യാനാകും (കർശന നിയമം #17)

### പ്രധാന തീരുമാനങ്ങൾ (ഡിസൈൻ പ്ലാനിൽ നിന്ന്)

| തീരുമാനം                                         | മൂല്യം                                                                                                                  |

| ഇൻസ്റ്റലേഷൻ സംവിധാനം                             | `execFile` വഴി `npm install {package}` (ഷെൽ ഇന്റർപൊളേഷൻ ഇല്ല)                                                           |
| ഉപയോഗ രീതി                                       | റൂട്ടിങ് എൻജിനിൽ `9router/{sub}/{model}` ആയി രജിസ്റ്റർ ചെയ്ത പ്രൊവൈഡർ                                                   |
| API കീ മാനേജ്മെന്റ്                              | OmniRoute സൃഷ്ടിക്കുകയും, അറ്റ്-റെസ്റ്റ് എൻക്രിപ്റ്റ് ചെയ്യുകയും (AES-256-GCM), env വഴി ഇൻജക്റ്റ് ചെയ്യുകയും ചെയ്യുന്നു |
| ഡാഷ്ബോർഡ് സ്ഥാനം                                 | `/dashboard/providers/services` (മൂന്ന് ടാബുകൾ)                                                                         |
| സ്വയമേവ ആരംഭിക്കൽ                                | ഓരോ സേവനത്തിനും പ്രത്യേകം ടോഗിൾ, ഡിഫോൾട്ടായി OFF                                                                        |

## 3. ലൈഫ്സൈക്കിൾ സ്റ്റേറ്റ് മെഷീൻ

```
                    install()
  ┌─────────────┐ ──────────► ┌─────────────┐
  │ not_installed│             │   stopped   │◄──────────────────┐
  └─────────────┘             └──────┬──────┘                   │
                                     │ start()                   │
                                     ▼                           │ stop()
                               ┌──────────┐                      │
                               │ starting │                      │
                               └────┬─────┘                     │
             ഹെൽത്ത് പ്രോബ് വിജയിച്ചു │         ക്രാഷ് / SIGTERM    │
                               ┌────▼─────┐  (5s-നുള്ളിൽ എക്സിറ്റ്) │
                               │ running  │──── ക്രാഷ് ─────────►┤
                               └────┬─────┘                   ┌─▼────┐
                             stop() │                          │error │
                                    ▼                          └──────┘
                               ┌──────────┐
                               │ stopping │
                               └──────────┘
```

സ്റ്റേറ്റുകൾ `version_manager` DB ടേബിളിൽ (`status` കോളം) സംഭരിക്കുകയും
`ServiceSupervisor`-ന്റെ ഇൻ-മെമ്മറി സ്റ്റേറ്റിൽ പ്രതിഫലിപ്പിക്കുകയും ചെയ്യുന്നു. പ്രവർത്തിച്ചുകൊണ്ടിരിക്കുന്ന
ഒരു പ്രോസസിന്റെ കാര്യത്തിൽ ഇൻ-മെമ്മറി സ്റ്റേറ്റാണ് ആധികാരികം; ബൂട്ട് സമയത്തെ സ്ഥിരമായ ഫാൾബാക്കാണ് DB സ്റ്റേറ്റ്.

### സ്റ്റേറ്റ് ട്രാൻസിഷനുകൾ

| ഇതിൽ നിന്ന്     | ഇവന്റ്                                                  | ഇതിലേക്ക്                     |
| --------------- | ------------------------------------------------------- | ----------------------------- |
| `not_installed` | `install()` വിജയിക്കുന്നു                               | `stopped`                     |
| `stopped`       | `start()` വിളിക്കുന്നു                                  | `starting`                    |
| `starting`      | ഹെൽത്ത് പ്രോബ് 200 നൽകുന്നു                             | `running`                     |
| `starting`      | ആരോഗ്യകരമാകുന്നതിന് മുമ്പ് പ്രോസസ് എക്സിറ്റ് ചെയ്യുന്നു | `error`                       |
| `running`       | `stop()` വിളിക്കുന്നു                                   | `stopping` → `stopped`        |
| `running`       | പ്രോസസ് അപ്രതീക്ഷിതമായി എക്സിറ്റ് ചെയ്യുന്നു (< 5 s)    | `error` (വേഗത്തിലുള്ള ക്രാഷ്) |
| `running`       | പ്രോസസ് അപ്രതീക്ഷിതമായി എക്സിറ്റ് ചെയ്യുന്നു (> 5 s)    | `error`                       |
| `error`         | `start()` വിളിക്കുന്നു                                  | `starting`                    |
| ഏതെങ്കിലും      | `stopping` സമയത്ത് `stop()`                             | പ്രവർത്തനമില്ല                |

### ഓപ്പറേഷൻ ലോക്ക്

`ServiceSupervisor`, ഒരു അസിങ്ക് ഓപ്പറേഷൻ ലോക്കിലൂടെ
(`withLock()`) ലൈഫ്സൈക്കിൾ പ്രവർത്തനങ്ങൾ ക്രമാനുസൃതമായി നടപ്പാക്കുന്നു. ഒരേ സൂപ്പർവൈസറിലെ സമകാലിക
`start()` കോളുകൾ കൃത്യമായി ഒരു പ്രോസസ് മാത്രമേ സ്പോൺ ചെയ്യൂ; രണ്ടാമത്തെ കോളർ കാത്തിരുന്ന ശേഷം നിലവിലുള്ള
സ്റ്റാറ്റസ് തിരികെ നൽകുന്നു. ഉദാഹരണത്തിന്, ഓട്ടോ-സ്റ്റാർട്ടും ഒരു UI ബട്ടണും ഒരേസമയം
പ്രവർത്തിക്കുമ്പോൾ ഉണ്ടാകാവുന്ന റേസ് കണ്ടീഷനുകൾ ഇത് തടയുന്നു.

## 4. API റഫറൻസ്

`/api/services/`-ന് കീഴിലുള്ള എല്ലാ റൂട്ടുകളും **LOCAL_ONLY** ആണ് (loopback മാത്രം, കർശന നിയമം #17).
auth token പരിഗണിക്കാതെ, loopback അല്ലാത്ത അഭ്യർത്ഥനകൾക്ക് `403 LOCAL_ONLY` ലഭിക്കും.

### 4.1 9Router എൻഡ്പോയിന്റുകൾ (11 റൂട്ടുകൾ)

#### `POST /api/services/9router/install`

npm-ൽ നിന്ന് 9Router ഇൻസ്റ്റാൾ ചെയ്യുന്നു. സ്വന്തം `package.json`, `node_modules/`
എന്നിവയോടുകൂടിയ `DATA_DIR/services/9router/` സൃഷ്ടിക്കുന്നു. OmniRoute-ന്റെ സ്വന്തം dependencies-മായി വൈരുധ്യമുണ്ടാകില്ല.

**അഭ്യർത്ഥനാ ബോഡി** (എല്ലാം ഐച്ഛികം):

```json
{ "version": "latest" }
```

| ഫീൽഡ്     | തരം      | ഡിഫോൾട്ട്  | വിവരണം                                                |
| --------- | -------- | ---------- | ----------------------------------------------------- |
| `version` | `string` | `"latest"` | ഇൻസ്റ്റാൾ ചെയ്യേണ്ട npm version tag അല്ലെങ്കിൽ semver |

**പ്രതികരണങ്ങൾ:**

| സ്റ്റാറ്റസ് | വിവരണം                                                                    |
| ----------- | ------------------------------------------------------------------------- |
| `200`       | `{ ok: true, installedVersion: "x.y.z", path: "..." }`                    |
| `400`       | അസാധുവായ അഭ്യർത്ഥനാ ബോഡി (Zod validation പരാജയം)                          |
| `409`       | ഇതിനകം ഇൻസ്റ്റാൾ ചെയ്യുന്നു (lock കൈവശമുണ്ട്)                             |
| `500`       | npm install പരാജയപ്പെട്ടു — സൗഹൃദപരമായ പിശക് സന്ദേശത്തിന് `message` കാണുക |

**കുറിപ്പുകൾ:** `execFile('npm', [...])` ഉപയോഗിക്കുന്നു — shell ഇല്ല, interpolation ഇല്ല (കർശന നിയമം #13).
EACCES പിശകുകൾ സൗഹൃദപരമായ സന്ദേശങ്ങളായി പ്രദർശിപ്പിക്കുന്നു.

#### `POST /api/services/9router/start`

9Router ആരംഭിക്കുന്നു. ഇതിനകം രജിസ്റ്റർ ചെയ്തിട്ടില്ലെങ്കിൽ ഒരു supervisor രജിസ്റ്റർ ചെയ്യുകയും തുടർന്ന്
`supervisor.start()` വിളിക്കുകയും ചെയ്യുന്നു. ഇതിനകം പ്രവർത്തിക്കുമ്പോൾ ആവർത്തിച്ച് വിളിച്ചാലും ഫലം മാറില്ല.

**അഭ്യർത്ഥനാ ബോഡി:** ഒന്നുമില്ല

**പ്രതികരണങ്ങൾ:**

| സ്റ്റാറ്റസ് | വിവരണം                                                      |
| ----------- | ----------------------------------------------------------- |
| `200`       | `ServiceStatus` ഒബ്ജക്റ്റ് (താഴെയുള്ള schema കാണുക)         |
| `409`       | 9Router ഇൻസ്റ്റാൾ ചെയ്തിട്ടില്ല (`status: "not_installed"`) |
| `503`       | ആരംഭിക്കൽ പരാജയപ്പെട്ടു (process പിശക് — `lastError` കാണുക) |

**ServiceStatus schema:**

```json
{
  "tool": "9router",
  "state": "running",
  "pid": 12345,
  "port": 20130,
  "health": "healthy",
  "startedAt": "2026-05-25T10:00:00.000Z",
  "lastError": null
}
```

#### `POST /api/services/9router/stop`

9Router ക്രമമായി നിർത്തുന്നു. SIGTERM അയയ്ക്കുകയും 15 s കാത്തിരിക്കുകയും, തുടർന്ന് ഇപ്പോഴും പ്രവർത്തിക്കുന്നുണ്ടെങ്കിൽ SIGKILL അയയ്ക്കുകയും ചെയ്യുന്നു.
ഇതിനകം നിർത്തിയിരിക്കുമ്പോൾ ആവർത്തിച്ച് വിളിച്ചാലും ഫലം മാറില്ല.

**അഭ്യർത്ഥനാ ബോഡി:** ഒന്നുമില്ല

**പ്രതികരണങ്ങൾ:**

| സ്റ്റാറ്റസ് | വിവരണം                                |
| ----------- | ------------------------------------- |
| `200`       | `ServiceStatus` (state: "stopped")    |
| `503`       | നിർത്തൽ അപ്രതീക്ഷിതമായി പരാജയപ്പെട്ടു |

---

#### `POST /api/services/9router/restart`

operation lock-ന് കീഴിൽ `stop()` തുടർന്ന് `start()` ചെയ്യുന്നതിന് തുല്യമാണ്.

**അഭ്യർത്ഥനാ ബോഡി:** ഒന്നുമില്ല

**പ്രതികരണങ്ങൾ:** `start`-ന് സമാനം (അന്തിമ `ServiceStatus` തിരികെ നൽകുന്നു).

#### `POST /api/services/9router/update`

9Router-നെ പുതിയൊരു npm version-ലേക്ക് അപ്ഡേറ്റ് ചെയ്യുന്നു. service പ്രവർത്തിക്കുന്നുണ്ടെങ്കിൽ ആദ്യം അത്
നിർത്തുകയും npm install പ്രവർത്തിപ്പിക്കുകയും (പുതിയ version അതേ സ്ഥാനത്ത് ഇൻസ്റ്റാൾ ചെയ്യുന്നു), തുടർന്ന്
service പുനരാരംഭിക്കുകയും ചെയ്യുന്നു.

**അഭ്യർത്ഥനാ ബോഡി** (എല്ലാം ഐച്ഛികം):

```json
{ "version": "latest" }
```

**പ്രതികരണങ്ങൾ:**

| സ്റ്റാറ്റസ് | വിവരണം                                                          |
| ----------- | --------------------------------------------------------------- |
| `200`       | `{ ok: true, previousVersion: "...", installedVersion: "..." }` |
| `400`       | അസാധുവായ ബോഡി                                                   |
| `500`       | npm update പരാജയപ്പെട്ടു                                        |

#### `POST /api/services/9router/rotate-key`

9Router-നായി ഒരു പുതിയ API key സൃഷ്ടിക്കുകയും, സംഭരണത്തിലുള്ളപ്പോൾ അത് encrypt ചെയ്യുകയും, service
പ്രവർത്തിക്കുന്നുണ്ടെങ്കിൽ പുനരാരംഭിക്കുകയും ചെയ്യുന്നു; അങ്ങനെ അതിന്റെ environment-ൽ നിന്ന് പുതിയ key ലഭിക്കും. പഴയ key
ഉടൻ അസാധുവാക്കപ്പെടുന്നു.

**അഭ്യർത്ഥനാ ബോഡി:** ഒന്നുമില്ല

**പ്രതികരണങ്ങൾ:**

| സ്റ്റാറ്റസ് | വിവരണം                                     |
| ----------- | ------------------------------------------ |
| `200`       | `{ keyRotated: true, restarted: boolean }` |
| `500`       | key rotation പരാജയപ്പെട്ടു                 |

**സുരക്ഷ:** പുതിയ key ഒരിക്കലും പ്രതികരണത്തിൽ തിരികെ നൽകുന്നില്ല (credential ചോർച്ചയില്ല).
അത് `version_manager` table-ൽ encrypt ചെയ്ത് (AES-256-GCM) സംഭരിക്കുന്നു.

#### `GET /api/services/9router/logs`

9Router-ന്റെ stdout/stderr ring buffer-ൽ നിന്നുള്ള തത്സമയ logs-ന്റെ SSE stream.

**Query parameters:**

| പാരാമീറ്റർ | തരം       | ഡിഫോൾട്ട്  | വിവരണം                                                                              |
| ---------- | --------- | ---------- | ----------------------------------------------------------------------------------- |
| `tail`     | `integer` | 200        | ആദ്യം അയയ്ക്കേണ്ട ചരിത്രപരമായ വരികളുടെ എണ്ണം (പരമാവധി 1000)                         |
| `filter`   | `string`  | ഒന്നുമില്ല | അക്ഷരവലുപ്പം പരിഗണിക്കാത്ത substring filter (regex ഇല്ല — ReDoS-ൽ നിന്ന് സുരക്ഷിതം) |

**SSE events:**

| Event       | Data        | വിവരണം                   |
| ----------- | ----------- | ------------------------ |
| `snapshot`  | `LogLine[]` | പ്രാരംഭ ചരിത്രപരമായ tail |
| `log`       | `LogLine`   | തത്സമയ log വരി           |
| `heartbeat` | `{}`        | ഓരോ 15 s-ലും keep-alive  |

**LogLine schema:**

```json
{
  "ts": 1716633600000,
  "stream": "stdout",
  "line": "[9router] Listening on :20130"
}
```

**പ്രതികരണങ്ങൾ:**

| നില   | വിവരണം                                                      |
| ----- | ----------------------------------------------------------- |
| `200` | `text/event-stream`                                         |
| `400` | `filter` പാരാമീറ്റർ വളരെ ദൈർഘ്യമേറിയതാണ് (> 200 പ്രതീകങ്ങൾ) |
| `404` | സേവനം കണ്ടെത്തിയില്ല (supervisor രജിസ്റ്റർ ചെയ്തിട്ടില്ല)   |

### 4.2 CLIProxyAPI എൻഡ്പോയിന്റുകൾ (10 റൂട്ടുകൾ)

CLIProxyAPI-ക്ക് `rotate-key` ഒഴികെ 9Router-ന്റെ അതേ എൻഡ്പോയിന്റ് ഘടനയാണുള്ളത്; കൂടാതെ
`accounts`, `provider-expose`, `auto-restart-adopted` എന്നിവയും ഉൾപ്പെടുന്നു. ഇപ്പോൾ spawn സമയത്ത്
ഇതിനായി ഒരു സമർപ്പിത data-plane API കീ ഇൻജക്റ്റ് ചെയ്യപ്പെടുന്നു (`bootstrap.ts`-ൽ
`needsApiKey: true`, മോഡൽ സമന്വയത്തിനായി ഉപയോഗിക്കുന്നു); `status`-ൽ കുറച്ച് ഫീൽഡുകൾ മാത്രമേ ഉൾപ്പെടുന്നുള്ളൂ.

| ------ | ----------------------------------- | ------------------------------------------ |
| `POST` | `/api/services/cliproxy/install`    | npm-ൽ നിന്ന് CLIProxyAPI ഇൻസ്റ്റാൾ ചെയ്യുക |
| `POST` | `/api/services/cliproxy/start`      | CLIProxyAPI ആരംഭിക്കുക                     |
| `POST` | `/api/services/cliproxy/stop`       | CLIProxyAPI നിർത്തുക                       |
| `POST` | `/api/services/cliproxy/restart`    | CLIProxyAPI പുനരാരംഭിക്കുക                 |
| `POST` | `/api/services/cliproxy/update`     | പുതിയ പതിപ്പിലേക്ക് അപ്ഡേറ്റ് ചെയ്യുക      |
| `GET`  | `/api/services/cliproxy/status`     | തത്സമയ + DB നില (`apiKeyMasked` ഇല്ല)      |

സെഗ്മെന്റ് ഉപയോഗിച്ച് നാല് സേവനങ്ങൾക്കും പ്രവർത്തിക്കുന്നു.

### 4.3 Mux എൻഡ്പോയിന്റുകൾ (8 റൂട്ടുകൾ)

റൂട്ട് ഇല്ല (bearer token, 9Router-ലേതിന് സമാനമായി `getOrCreateApiKey("mux")` വഴി
സൃഷ്ടിക്കുകയും `MUX_SERVER_AUTH_TOKEN` env var വഴി ഇൻജക്റ്റ് ചെയ്യുകയും ചെയ്യുന്നു, എന്നാൽ
ഇതുവരെ സമർപ്പിത rotation എൻഡ്പോയിന്റ് ഇല്ല). Mux-ന്റെ lifecycle മാത്രമാണ് മാനേജ് ചെയ്യുന്നത്:
9Router-ൽ നിന്ന് വ്യത്യസ്തമായി, ഇതിന് Layer 4 executor ഇല്ല; routing provider ആയി ഒരിക്കലും
രജിസ്റ്റർ ചെയ്യപ്പെടുന്നുമില്ല.

| രീതി   | പാത                            | വിവരണം                                           |

| `POST` | `/api/services/mux/install`    | npm-ൽ നിന്ന് Mux ഇൻസ്റ്റാൾ ചെയ്യുക (`npm i mux`) |
| `POST` | `/api/services/mux/start`      | Mux ആരംഭിക്കുക (`mux server`)                    |
| `POST` | `/api/services/mux/stop`       | Mux നിർത്തുക                                     |
| `POST` | `/api/services/mux/restart`    | Mux പുനരാരംഭിക്കുക                               |
| `POST` | `/api/services/mux/update`     | പുതിയ npm പതിപ്പിലേക്ക് അപ്ഡേറ്റ് ചെയ്യുക        |
| `GET`  | `/api/services/mux/status`     | തത്സമയ + DB നില                                  |
| `POST` | `/api/services/mux/auto-start` | സ്വയമേവ ആരംഭിക്കൽ ടോഗിൾ ചെയ്യുക                  |

**API കീ:** `WA_KEY` ആയി ഇൻജക്റ്റ് ചെയ്യുന്നു — open-wa-യുടെ പൊതുവായ `WA_*`-പ്രിഫിക്സ് ചെയ്ത env

(`dist/cli/setup.js::envArgs()`, ഇൻസ്റ്റാൾ ചെയ്ത 4.76.0
പാക്കേജിനെതിരെ സ്ഥിരീകരിച്ചത്). `generateServiceApiKey()` ഉപയോഗിച്ച് സൃഷ്ടിക്കുമ്പോൾ `ow_` പ്രിഫിക്സ് ചെയ്യുന്നു. open-wa
ഒരു `key`/`api_key` HTTP ഹെഡറിൽ നിന്നാണ് കീ തിരികെ വായിക്കുന്നത് (`Authorization:
Bearer` അല്ല); പരിശോധനയിൽ നിന്ന് `/api-docs*` വ്യക്തമായി ഒഴിവാക്കിയിരിക്കുന്നു
(`dist/cli/server.js`-ലെ `setupAuthenticationLayer`), അതിനാൽ ഹെൽത്ത് പ്രോബിന്
auth ഹെഡർ ആവശ്യമില്ല.

**പെയറിംഗ്:** open-wa ഔദ്യോഗികമല്ല, WhatsApp-മായി അഫിലിയേറ്റ് ചെയ്തിട്ടുമില്ല —
കണക്റ്റ് ചെയ്ത നമ്പറിന് WhatsApp-ന്റെ സ്വന്തം ഓട്ടോമേഷൻ കണ്ടെത്തൽ കാരണം നിരോധനസാധ്യതയുണ്ട്.
ആദ്യം ആരംഭിക്കുമ്പോൾ, പെയറിംഗ് QR കോഡ് stdout-ലേക്ക് പ്രിന്റ് ചെയ്യുകയും നിലവിലുള്ള
ലോഗ്സ് പാനൽ/SSE സ്ട്രീം വഴി ലഭ്യമാക്കുകയും ചെയ്യുന്നു — ഈ ഇന്റഗ്രേഷനിൽ ഇതുവരെ
പ്രത്യേക QR-ഇമേജ് എൻഡ്പോയിന്റ് ഇല്ല.

### 4.8 റിവേഴ്സ് പ്രോക്സി (9Router ഡാഷ്ബോർഡ് എംബെഡ്)

ഡാഷ്ബോർഡ്, താഴെപ്പറയുന്ന ഇന്റേണൽ റിവേഴ്സ്
പ്രോക്സി വഴി ഒരു iframe-നുള്ളിൽ 9Router വെബ് UI എംബെഡ് ചെയ്യുന്നു:

```
GET|POST|... /dashboard/providers/services/9router/embed/[...path]
```

ഈ പ്രോക്സി:

- റിക്വസ്റ്റ് `http://127.0.0.1:{port}/{path}`-ലേക്ക് ഫോർവേഡ് ചെയ്യുന്നു (ലൂപ്പ്ബാക്ക് മാത്രം)
- ഇൻകമിംഗ് `cookie`, `authorization` ഹെഡറുകൾ നീക്കം ചെയ്യുന്നു (OmniRoute സെഷൻ ചോരാതിരിക്കാൻ)
- 9Router ഓതന്റിക്കേഷനായി `Authorization: Bearer {apiKey}` ഇൻജക്റ്റ് ചെയ്യുന്നു
- പ്രതികരണത്തിൽ നിന്ന് `set-cookie`, `content-security-policy`, `x-frame-options`, `cross-origin-*` എന്നിവ നീക്കം ചെയ്യുന്നു
- `<base href>` ഇൻജക്റ്റ് ചെയ്യുന്നതിനും അബ്സല്യൂട്ട് പാതകൾ നോർമലൈസ് ചെയ്യുന്നതിനുമായി HTML പ്രതികരണങ്ങൾ റീറൈറ്റ് ചെയ്യുന്നു (`/foo` → `/dashboard/.../embed/foo`)

എംബെഡ് ചെയ്ത ഡാഷ്ബോർഡിനായുള്ള WebSocket അപ്ഗ്രേഡുകൾ ഒരു
സമർപ്പിത port-ലെ കമ്പാനിയൻ സെർവർ കൈകാര്യം ചെയ്യുന്നു (`src/lib/services/embedWsProxy.ts` കാണുക).

**സുരക്ഷ:** എംബെഡ് പ്രോക്സി റൂട്ടുകളെ `LOCAL_ONLY_API_PREFIXES`-ന്റെ കീഴിൽ
വർഗ്ഗീകരിച്ചിരിക്കുന്നു, കൂടാതെ ലൂപ്പ്ബാക്കിൽ നിന്ന് മാത്രമേ അവ ആക്സസ് ചെയ്യാനാകൂ. ഒരു
Cloudflare/Ngrok ടണൽ വഴി JWT നേടുന്ന ആക്രമണകാരിക്ക് എംബെഡ് ചെയ്ത സർവീസുകളിലേക്ക് പ്രോക്സി ചെയ്യാനാകില്ല.

## 5. സുരക്ഷ

### LOCAL_ONLY നടപ്പാക്കൽ (കർശന നിയമം #17)

`/api/services/`-ന് കീഴിലെയും `/dashboard/providers/services/*/embed/`-ന് കീഴിലെയും എല്ലാ റൂട്ടുകളും
`src/server/authz/routeGuard.ts`-ൽ LOCAL_ONLY ആയി വർഗ്ഗീകരിച്ചിരിക്കുന്നു. ഏതൊരു auth ശാഖയ്ക്കും മുമ്പായി
loopback പരിശോധന നിർബന്ധമായും പ്രവർത്തിക്കുന്നു:

```
അഭ്യർത്ഥന എത്തുന്നു
  → isLocalOnlyPath(path)?
      → loopback അല്ല → 403 LOCAL_ONLY (എല്ലായ്പ്പോഴും, auth പരിശോധനയ്ക്ക് മുമ്പ്)
      → loopback ആണ് → സാധാരണ auth-ലേക്ക് തുടരുക
```

ചോർന്നുപോയ ഒരു JWT (ഉദാ., ഒരു tunnel വഴി) `npm install` അല്ലെങ്കിൽ
process spawning പ്രവർത്തനക്ഷമമാക്കുന്നതിൽ നിന്ന് ഇത് തടയുന്നു. പൂർണ്ണ tier
matrix-നായി `docs/security/ROUTE_GUARD_TIERS.md` കാണുക.

### API key ഉൾപ്പെടുത്തൽ

9Router-നും Mux-നും അവയുടെ സ്വന്തം HTTP endpoints-നായി ഒരു API key/bearer token ആവശ്യമാണ്.
OmniRoute:

1. സേവനത്തിന് പ്രത്യേകമായ prefix (`nr_` 9Router-ന്, `mx_` Mux-ന്) ഉപയോഗിച്ച്
   `crypto.randomBytes(32).toString("base64url")` വഴി ഒരു key സൃഷ്ടിക്കുന്നു.
2. AES-256-GCM ഉപയോഗിച്ച് അതിനെ നിശ്ചലാവസ്ഥയിൽ encrypt ചെയ്യുന്നു (provider credentials-ന് ഉപയോഗിക്കുന്ന അതേ cipher).
3. spawn സമയത്ത് അതിനെ decrypt ചെയ്ത് ഒരു environment variable ആയി ഉൾപ്പെടുത്തുന്നു —
   9Router-ന് `NINEROUTER_API_KEY`, Mux-ന് `MUX_SERVER_AUTH_TOKEN` (ഒരിക്കലും CLI
   flag ആയി അല്ല; അതിനാൽ token ഒരിക്കലും `ps`/process listings-ൽ ദൃശ്യമാകില്ല).
4. ഏതെങ്കിലും HTTP response-ൽ plaintext key ഒരിക്കലും മടക്കി നൽകുന്നില്ല.

CLIProxyAPI-ക്ക് spawn സമയത്ത് ഉൾപ്പെടുത്തുന്ന ഒരു സമർപ്പിത data-plane key ലഭിക്കുന്നു
(`needsApiKey: true` — adapter-നെതിരെയുള്ള model sync-നായി ഉപയോഗിക്കുന്നു).

### SSRF പ്രതിരോധം

reverse HTTP proxy (`/dashboard/.../embed/[...path]`) അഭ്യർത്ഥനകൾ
`http://127.0.0.1:{port}`-ലേക്ക് മാത്രം forward ചെയ്യുന്നതിനായി hardcode ചെയ്തിരിക്കുന്നു. non-loopback
ലക്ഷ്യസ്ഥാനങ്ങളിലേക്കുള്ള redirects അത് ഒരിക്കലും പിന്തുടരുന്നില്ല. loopback പരിധിക്ക് പുറത്തേക്ക്
resolve ചെയ്യുന്ന ഏതൊരു upstream URL-ഉം നിരസിക്കാൻ `ssrf-req-filter` library ഉപയോഗിക്കുന്നു.

### Shell സുരക്ഷ (കർശന നിയമം #13)

`npm install`, `execFile('npm', ['install', pkg, '--prefix', dir])` വഴി invoke ചെയ്യുന്നു —
template literals ഇല്ല, shell ഇല്ല, external paths command
string-ലേക്ക് interpolate ചെയ്യുന്നില്ല. Runtime values (ports, API keys) child-ന്റെ `env` object വഴി കൈമാറുന്നു.

### Error ശുദ്ധീകരണം (കർശന നിയമം #12)

`/api/services/*`-ൽ നിന്നുള്ള എല്ലാ error responses-ഉം `buildErrorBody()` അല്ലെങ്കിൽ
`sanitizeErrorMessage()` വഴി കടന്നുപോകുന്നു. അസംസ്കൃതമായ `err.stack`, `err.message` എന്നിവ caller-ന്
അതേപടി ഒരിക്കലും മടക്കി നൽകുന്നില്ല.

## 6. ഒരു പുതിയ embedded service ചേർക്കൽ

ഈ 8 ഘട്ടങ്ങൾ പിന്തുടരുക. ആധികാരിക reference ആയി `src/lib/services/installers/`-ലെയും
`src/app/api/services/`-ലെയും നിലവിലുള്ള implementations വായിക്കുക.

### ഘട്ടം 1 — installer സൃഷ്ടിക്കുക

`ninerouter.ts` മാതൃകയാക്കി `src/lib/services/installers/{name}.ts` സൃഷ്ടിക്കുക:

```typescript
export const NAME_PACKAGE = "your-npm-package";
export const NAME_DEFAULT_PORT = 20132; // ലഭ്യമായ ഒരു port തിരഞ്ഞെടുക്കുക

export async function install(version = "latest"): Promise<InstallResult> { ... }
export async function update(version = "latest"): Promise<InstallResult> { ... }
export async function uninstall(): Promise<void> { ... }
export function resolveSpawnArgs(apiKey: string, port: number): SpawnArgs { ... }
export async function getInstalledVersion(): Promise<string | null> { ... }
export async function getLatestVersion(): Promise<string | null> { ... }
```

`installers/utils.ts`-ൽ നിന്നുള്ള `runNpm(['install', NAME_PACKAGE, '--prefix', dir])`
ഉപയോഗിക്കുക — `execSync` അല്ലെങ്കിൽ shell interpolation ഒരിക്കലും ഉപയോഗിക്കരുത്.

### ഘട്ടം 2 — bootstrap-ൽ register ചെയ്യുക

`src/lib/services/bootstrap.ts`-ലെ `SERVICES` array-യിലേക്ക് ഒരു `ServiceEntry` ചേർക്കുക:

```typescript
{
  tool: "myservice",
  port: NAME_DEFAULT_PORT,
  healthPath: "/health",
  healthIntervalMs: 5_000,
  stopTimeoutMs: 15_000,
  logsBufferBytes: 5_242_880,
  needsApiKey: true, // API key ആവശ്യമില്ലെങ്കിൽ false
}
```

`cfg.tool === "myservice"` കൈകാര്യം ചെയ്യുന്നതിനായി `buildSpawnArgsFactory()` വിപുലീകരിക്കുക.

#### ഘടിപ്പിക്കാവുന്ന provider-plugin contract (Phase 1, #7333)

ഒരേ backend-ന്റെ ഘടന ബന്ധമില്ലാത്ത രണ്ട് വ്യത്യസ്ത files-ൽ പ്രത്യേകം നിർവചിക്കുന്നതിനുപകരം,
ഒരു backend-ന്റെ `bootstrap.ts`-ലെ `ServiceEntry` fields-ഉം `serviceBackends.ts`-ലെ
manifest-template fields-ഉം ഒരൊറ്റ object-ലേക്ക് package ചെയ്യുന്ന ഒരു `ServiceProviderPlugin`
contract, `src/lib/services/providerPlugins/` അവതരിപ്പിക്കുന്നു. ഇത് എഴുതുന്ന സമയത്ത് **`9router`
മാത്രമാണ് migrate ചെയ്തിരിക്കുന്നത്** — `getServiceProviderPlugin("9router")`
(`src/lib/services/providerPlugins/registry.ts`) ഉപയോഗിച്ച് `bootstrap.ts` അതിന്റെ `SERVICES[]`
entry derive ചെയ്യുന്നു; plugin എപ്പോഴെങ്കിലും ഇല്ലെങ്കിൽ startup error throw ചെയ്യും. `cliproxy`,
`mux`, `bifrost` എന്നിവ മാറ്റമില്ലാതെ മുമ്പ് നിലവിലുണ്ടായിരുന്ന inline `SERVICES[]` literals-ൽ തുടരുന്നു.

ഒരു `SERVICE_BACKEND_MANIFEST_TEMPLATE` entry-യിൽ നിന്ന് ശരിയായ ഘടനയുള്ള
`ProviderPluginManifestEntry` നിർമ്മിക്കുന്ന additive ആയ
`createServiceBackendManifestEntry(pluginId, template)` helper-ഉം
`open-sse/config/providerPluginManifest.ts`-ൽ ചേർത്തിട്ടുണ്ട് — ഇത് ഇതുവരെ ഏതെങ്കിലും live request
path-ലേക്ക് wire ചെയ്തിട്ടില്ല (`generateProviderPluginManifestFromRegistry()`-ലേക്കോ
`/v1/providers/[provider]/models`-ലേക്കോ ഇല്ല); രണ്ടാമത്തെ backend-നായി contract തെളിയിച്ചുകഴിഞ്ഞാൽ
ചെയ്യേണ്ട follow-up ആയി അത് തുടരുന്നു.

issue #7333-ന് കീഴിൽ track ചെയ്യുന്ന follow-up PRs-ലേക്ക് മാറ്റിവെച്ചവ: അതേ registry വഴി
`cliproxyapi` migrate ചെയ്യുക, `mux`/`bifrost` എന്നിവയെ `ServiceBackendPluginId` union-ലേക്ക്
generalize ചെയ്യുക, executor-routing special-casing (`open-sse/executors/index.ts`,
`open-sse/handlers/chatCore/executorProxy.ts`) plugin contract-ലേക്ക് ഉൾപ്പെടുത്തുക, കൂടാതെ
`createServiceBackendManifestEntry()` ഒരു live manifest/models code path-ലേക്ക് wire ചെയ്യുക.

## 7. പ്രശ്നപരിഹാരം

### സേവനം ആരംഭിക്കുന്നില്ല

**ലക്ഷണങ്ങൾ:** Start ബട്ടൺ 503 നൽകുന്നു, നില `"error"` അല്ലെങ്കിൽ `"starting"` ആയി തുടരുന്നു.

**പരിശോധനപ്പട്ടിക:**

1. `GET /api/services/{name}/logs` പരിശോധിക്കുക (അല്ലെങ്കിൽ ഡാഷ്ബോർഡിലെ Logs പാനൽ). `Error: ENOENT`, `address already in use`, അല്ലെങ്കിൽ `Cannot find module` പോലുള്ള വരികൾ തിരയുക.
2. `npm` PATH-ൽ ഉണ്ടെന്ന് ഉറപ്പാക്കുക: OmniRoute പ്രവർത്തിപ്പിക്കുന്ന അതേ ഉപയോക്തൃ അക്കൗണ്ടിൽ നിന്ന് `which npm` പ്രവർത്തിപ്പിക്കുക.
3. സേവനം ഇൻസ്റ്റാൾ ചെയ്തിട്ടുണ്ടെന്ന് ഉറപ്പാക്കുക: `installedVersion` അറിയാൻ `GET /api/services/{name}/status` പരിശോധിക്കുക. അത് `null` ആണെങ്കിൽ, ആദ്യം ഇൻസ്റ്റാൾ ചെയ്യുക.
4. `DATA_DIR/services/{name}/node_modules/` നിലവിലുണ്ടെന്നും ശൂന്യമല്ലെന്നും പരിശോധിക്കുക.
5. ശുദ്ധീകരിച്ച എക്സിറ്റ് കാരണം അറിയാൻ സ്റ്റാറ്റസ് പ്രതികരണത്തിലെ `lastError` ഫീൽഡ് പരിശോധിക്കുക.

### കോൾഡ് സ്റ്റാർട്ട് മന്ദഗതിയിലാണ് (`running` നിലയിലെത്താൻ > 10 s)

**ലക്ഷണങ്ങൾ:** `"running"` അല്ലെങ്കിൽ `"error"` എന്നതിലേക്ക് മാറുന്നതിന് മുമ്പ് നില വളരെ നേരം `"starting"` ആയി തുടരുന്നു.

**വിശദീകരണം:** 9Router-ന്റെ കോൾഡ് സ്റ്റാർട്ടിൽ വലിയ ഡിപെൻഡൻസി ട്രീകൾ (DNS, tunnel, MITM മൊഡ്യൂളുകൾ) ഇമ്പോർട്ട് ചെയ്യുന്നത് ഉൾപ്പെടുന്നു. ഡിഫോൾട്ട് ഹെൽത്ത് ഇടവേള 2 s ആണ്; സൂപ്പർവൈസർ ടൈംഔട്ട് പ്രഖ്യാപിക്കുന്നതിന് മുമ്പ് 3 ശ്രമങ്ങൾ നടത്തുന്നു (എന്നാൽ പോളിങ് തുടരുന്നു).

**പരിഹാരം:** `healthIntervalMs`, `waitForHealthy` ടൈംഔട്ട് (`healthIntervalMs * 3`) എന്നിവ `bootstrap.ts`-ൽ കോൺഫിഗർ ചെയ്യാവുന്നതാണ്. കൂടുതൽ സ്റ്റാർട്ടപ്പ് സമയം ആവശ്യമായ സേവനങ്ങൾക്ക് `healthIntervalMs` 5000 ആയും `stopTimeoutMs` 30 000 ആയും വർധിപ്പിക്കുക.

### പോർട്ട് കൂട്ടിയിടി (`EADDRINUSE`)

**ലക്ഷണങ്ങൾ:** ലോഗുകളിൽ `address already in use :::20130` കാണിക്കുന്നു.

**കാരണങ്ങൾ:**

- മറ്റൊരു പ്രോസസ് ഇതിനകം പോർട്ട് 20130 ഉപയോഗിക്കുന്നു.
- മുമ്പത്തെ ഒരു 9Router പ്രോസസ് പൂർണ്ണമായി നിർത്തിയിട്ടില്ല (സോംബി PID).

**പരിഹാരം:**

1. `.env`-ലെ `NINEROUTER_PORT` എൻവയോൺമെന്റ് വേരിയബിൾ വഴി ഡിഫോൾട്ട് പോർട്ട് മാറ്റുക.
2. വൈരുദ്ധ്യമുണ്ടാക്കുന്ന പ്രോസസ് കണ്ടെത്തി അവസാനിപ്പിക്കുക: `lsof -ti :20130 | xargs kill -9`.
3. `bootstrap.ts`-ലെ `port` ഫീൽഡ് വഴി ഓരോ സേവനത്തിനും പോർട്ട് കോൺഫിഗർ ചെയ്യാം.

**കുറിപ്പ്:** OmniRoute-ന്റെ ഡിഫോൾട്ട് പോർട്ടായ 20128-മായി കൂട്ടിയിടിക്കുന്നത് ഒഴിവാക്കാനാണ് 9Router പ്രത്യേകമായി പോർട്ട് 20130 ഡിഫോൾട്ടായി ഉപയോഗിക്കുന്നത്.

### ഇൻസ്റ്റാളിൽ അനുമതി നിഷേധിച്ചു (EACCES)

**ലക്ഷണങ്ങൾ:** ഇൻസ്റ്റാൾ 500 നൽകുന്നു, ലോഗുകളിൽ `EACCES` അല്ലെങ്കിൽ `permission denied` കാണിക്കുന്നു.

**കാരണങ്ങൾ:**

- `DATA_DIR`-ലോ അതിന്റെ പാരന്റ് ഡയറക്ടറിയിലോ OmniRoute പ്രോസസിന് എഴുതാനുള്ള അനുമതിയില്ല.
- മാപ്പ് ചെയ്ത വോളിയത്തിലേക്ക് റൈറ്റ് ആക്സസ് ഇല്ലാതെ Docker rootless-ൽ പ്രവർത്തിക്കുന്നു.

**പരിഹാരം:**

1. `DATA_DIR` പരിശോധിക്കുക (ഡിഫോൾട്ട്: `~/.omniroute/`): `ls -la ~/.omniroute/`
2. ഡയറക്ടറിയുടെ ഉടമ OmniRoute പ്രോസസ് ഉപയോക്താവാണെന്ന് ഉറപ്പാക്കുക: `chown -R $USER ~/.omniroute/`
3. Docker-ൽ, വോളിയം മൗണ്ടിന് കണ്ടെയ്നർ ഉപയോക്താവിനുള്ള ശരിയായ അനുമതികൾ ഉണ്ടെന്ന് ഉറപ്പാക്കുക.

---

### അപ്ഡേറ്റ് പരാജയപ്പെടുന്നു (`npm install` ടൈംഔട്ട് അല്ലെങ്കിൽ നെറ്റ്വർക്ക് പിശക്)

**ലക്ഷണങ്ങൾ:** അപ്ഡേറ്റ് `InstallError` സഹിതം 500 നൽകുന്നു, ലോഗുകളിൽ നെറ്റ്വർക്ക് ടൈംഔട്ട് കാണിക്കുന്നു.

**പരിശോധനപ്പട്ടിക:**

1. npm registry ലഭ്യമാണെന്ന് സ്ഥിരീകരിക്കുക: `npm ping`.
2. കോർപ്പറേറ്റ് പ്രോക്സി ഉണ്ടോയെന്ന് പരിശോധിക്കുക: `npm config get proxy`, `npm config get https-proxy`.
3. ഇൻസ്റ്റാൾ മാനുവലായി ശ്രമിക്കുക: `npm install {package}@latest --prefix ~/.omniroute/services/{name}/`.
4. എയർ-ഗ്യാപ്പിന് പിന്നിലാണെങ്കിൽ, ടാർബോൾ മുൻകൂട്ടി ഡൗൺലോഡ് ചെയ്ത് `npm install /path/to/tarball.tgz` ഉപയോഗിക്കുക.

---

### ആരംഭിച്ച ഉടൻ സേവനം `"error"` നില കാണിക്കുന്നു (വേഗത്തിലുള്ള ക്രാഷ്)

**ലക്ഷണങ്ങൾ:** 5 സെക്കൻഡിനുള്ളിൽ നില `"starting"` എന്നതിൽ നിന്ന് `"error"` എന്നതിലേക്ക് മാറുന്നു. `lastError` `"Fast crash (exited with code 1)"` കാണിക്കുന്നു.

**പരിശോധനപ്പട്ടിക:**

1. പൂർണ്ണമായ ലോഗ് ടെയിൽ വായിക്കുക: `GET /api/services/{name}/logs?tail=500`.
2. സാധാരണ കാരണം: സേവനം പ്രതീക്ഷിക്കുന്ന എൻവയോൺമെന്റ് വേരിയബിളുകൾ ലഭ്യമല്ല.
3. 9Router-നായി: സ്പോൺ ചെയ്യുമ്പോൾ കൈമാറുന്ന env-ൽ `NINEROUTER_DISABLE_MITM=true`, `NINEROUTER_DISABLE_TUNNEL=true` എന്നിവ ഉണ്ടെന്ന് ഉറപ്പാക്കുക (`installers/ninerouter.ts`-ലെ `resolveSpawnArgs` കാണുക).

## 8. പതിവുചോദ്യങ്ങൾ

**ചോ: ഉൾച്ചേർത്ത സേവനങ്ങളുടെ എൻഡ്പോയിന്റുകൾ നോൺ-ലൂപ്പ്ബാക്ക് ക്ലയന്റുകൾക്ക് ലഭ്യമാക്കാനാകുമോ?**

ഇല്ല. LOCAL_ONLY ടയർ മനഃപൂർവം ഏർപ്പെടുത്തിയതാണ് (കർശന നിയമം #17). `npm install`
പ്രവർത്തിപ്പിക്കാനോ `node` പ്രോസസുകൾ സൃഷ്ടിക്കാനോ കഴിയുന്ന റൂട്ടുകൾ നോൺ-ലൂപ്പ്ബാക്ക്
ട്രാഫിക്കിൽ നിന്ന് ആക്സസ് ചെയ്യാൻ കഴിയരുത്. അല്ലാത്തപക്ഷം, ഒരു ടണലിലൂടെ (Cloudflare,
Ngrok, Tailscale) JWT ചോർന്നാൽ, അനിയന്ത്രിതമായി പ്രോസസുകൾ സൃഷ്ടിക്കാൻ സാധിക്കും.
`/api/services/`-ന് ഇതിൽ നിന്ന് ഒഴിവാകാനുള്ള വ്യവസ്ഥയില്ല — `/api/mcp/`-ൽ നിന്ന് വ്യത്യസ്തമായി,
ഇത് manage-scope ബൈപാസ് പട്ടികയിൽ ഉൾപ്പെടുത്തിയിട്ടില്ല. `docs/security/ROUTE_GUARD_TIERS.md`
കാണുക.

---

**ചോ: പ്രൊഡക്ഷൻ/ക്ലൗഡ് വിന്യാസങ്ങളിൽ 9Router, CLIProxyAPI എന്നിവ ലഭ്യമാകുമോ?**

അതെ. രണ്ട് സേവനങ്ങളും OmniRoute പിന്തുടരുന്ന അതേ local-first മാതൃകയാണ് പിന്തുടരുന്നത്.
അവ ഒരേ മെഷീനിൽ പ്രവർത്തിക്കുകയും ലൂപ്പ്ബാക്ക് വഴി ആശയവിനിമയം നടത്തുകയും ചെയ്യുന്നു.
ഇവിടെ "പ്രൊഡക്ഷൻ" എന്നത് OmniRoute വിന്യസിച്ചിരിക്കുന്ന VPS അല്ലെങ്കിൽ ലോക്കൽ സെർവറിനെയാണ്
സൂചിപ്പിക്കുന്നത്, ഒരു റിമോട്ട് ക്ലൗഡ് പ്രൊവൈഡറെയല്ല.

---

**ചോ: സൂപ്പർവൈസർ എങ്ങനെ ഡീബഗ് ചെയ്യാം?**

1. SSE ലോഗ് സ്ട്രീം പിന്തുടരുക: `curl -N http://localhost:20128/api/services/9router/logs`.
2. `service:supervisor` നെയിംസ്പേസ് ഉപയോഗിച്ച് ഫിൽട്ടർ ചെയ്ത OmniRoute-ന്റെ pino ഔട്ട്പുട്ടിലെ
   ഘടനാബദ്ധമായ ലോഗുകൾ പരിശോധിക്കുക.
3. DB റോ പരിശോധിക്കുക: `sqlite3 ~/.omniroute/omniroute.db "SELECT * FROM version_manager WHERE tool='9router'"`.
4. നിലവിലെ തത്സമയ സ്റ്റേറ്റ്, PID, ഹെൽത്ത്, `lastError` എന്നിവ ഒരൊറ്റ കോളിൽ കാണാൻ
   `GET /api/services/9router/status` ഉപയോഗിക്കുക.

---

**ചോ: സൂപ്പർവൈസർ `health: "degraded"` അല്ലെങ്കിൽ `health: "unknown"` കാണിക്കുന്നു, എന്നാൽ സ്റ്റേറ്റ് `"running"` ആണ്. അതൊരു പ്രശ്നമാണോ?**

`"degraded"` എന്നത് ഹെൽത്ത് പ്രോബ് 200 അല്ലാത്ത പ്രതികരണം നൽകി എന്നാണ് അർത്ഥമാക്കുന്നത്.
`"unknown"` എന്നത് ഇതുവരെ ഒരു പ്രോബും പൂർത്തിയായിട്ടില്ല എന്നാണ് അർത്ഥമാക്കുന്നത്
(ആദ്യ പോളുമായുള്ള റേസ്). സ്റ്റാർട്ടപ്പ് സമയത്ത് ഇവ രണ്ടും താൽക്കാലികമാണ്.
`"running"` ആയതിന് ശേഷം `healthIntervalMs * 3` ms-ൽ കൂടുതൽ സമയം ഹെൽത്ത്
`"degraded"` ആയി തുടരുകയാണെങ്കിൽ, ഉൾച്ചേർത്ത സേവനം പ്രവർത്തിക്കുന്നുണ്ടെങ്കിലും അതിന്റെ
HTTP API പ്രതികരിക്കുന്നില്ല. സ്റ്റാറ്റസ് പ്രതികരണത്തിലെ പോർട്ട് ശരിയാണോയെന്നും സേവനം
യഥാർത്ഥത്തിൽ ആ പോർട്ടിൽ ലിസൺ ചെയ്യുന്നുണ്ടോയെന്നും പരിശോധിക്കുക.

---

**ചോ: പൂർണ്ണമായി റീസ്റ്റാർട്ട് ചെയ്യാതെ 9Router API കീ മാറ്റാനാകുമോ?**

ഇല്ല. സ്പോൺ ചെയ്യുന്ന സമയത്ത് ഒരു എൻവയോൺമെന്റ് വേരിയബിൾ വഴിയാണ് API കീ 9Router-ന്
നൽകുന്നത്. പ്രവർത്തിച്ചുകൊണ്ടിരിക്കുന്ന ഒരു പ്രോസസിലെ എൻവയോൺമെന്റ് വേരിയബിളുകൾ
മാറ്റാനാകില്ല. പുതിയ കീ പ്രയോഗിക്കുന്നതിന് `POST .../rotate-key` സേവനം സ്വയമേവ
നിർത്തുകയും പുനരാരംഭിക്കുകയും ചെയ്യുന്നു. സേവനത്തിന്റെ `stopTimeoutMs` (സ്ഥിരസ്ഥിതിയിൽ
15 s) കൂടാതെ അതിന്റെ സ്റ്റാർട്ടപ്പ് സമയത്തിനുള്ളിൽ കീ റൊട്ടേഷൻ പ്രാബല്യത്തിൽ വരും.

---

**ചോ: റിങ് ബഫർ പരിധി എത്രയാണ്, അത് നിറഞ്ഞാൽ എന്ത് സംഭവിക്കും?**

ഓരോ സേവനത്തിനും പ്രത്യേകം 5 MB റിങ് ബഫർ ഉണ്ട്. ബഫർ നിറയുമ്പോൾ, പുതിയവയ്ക്കായി
ഇടം സൃഷ്ടിക്കുന്നതിന് ഏറ്റവും പഴയ ലോഗ് വരികൾ നീക്കംചെയ്യപ്പെടും. `tail` പരിധിക്കുള്ളിലെ
ഏറ്റവും പുതിയ വരികൾ SSE `snapshot` ഇവന്റ് തിരികെ നൽകുന്നു. DB റോയിൽ
`logsBufferPath` സജ്ജീകരിച്ചിട്ടില്ലെങ്കിൽ ലോഗുകൾ ഡിസ്കിൽ നിലനിറുത്തുകയില്ല.
