> **ആധികാരിക ഉറവിടം:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/`, കൂടാതെ
> `src/app/(dashboard)/dashboard/plugins/`
> **അവസാനം പുതുക്കിയത്:** 2026-06-28 — v3.8.40

OmniRoute-ൽ WordPress മാതൃകയിലുള്ള ഒരു പ്ലഗിൻ സിസ്റ്റം ഉൾപ്പെടുത്തിയിട്ടുണ്ട്. പ്ലഗിനുകൾ സ്വയംപര്യാപ്തമായ
ഡയറക്ടറികളാണ് — ഓരോന്നിലും ഒരു `plugin.json` മാനിഫെസ്റ്റും ഒരു എൻട്രി ഫയലും ഉണ്ടായിരിക്കും — അവ
റിക്വസ്റ്റ് പൈപ്പ്ലൈനിലേക്കും (`onRequest` / `onResponse` / `onError`)
ലൈഫ്സൈക്കിൾ ഇവന്റുകളിലേക്കും (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`)
ഹുക്ക് ചെയ്യുന്നു.

**പ്ലഗിൻ മാർക്കറ്റ്പ്ലേസ്** ആ സിസ്റ്റത്തിന് മുകളിലുള്ള കണ്ടെത്തൽ ലെയറാണ്. ഇൻസ്റ്റാൾ ചെയ്യാവുന്ന
പ്ലഗിനുകളുടെ ബ്രൗസ് ചെയ്യാവുന്ന ഒരു കാറ്റലോഗ് ഇത് ലഭ്യമാക്കുന്നു. ഡിഫോൾട്ടായി, കാറ്റലോഗ്
ചെറിയൊരു ബിൽറ്റ്-ഇൻ സീഡ് രജിസ്ട്രിയാണ്; ഒരു ഓപ്പറേറ്റർക്ക് അതിനെ ഇഷ്ടാനുസൃത റിമോട്ട്
രജിസ്ട്രി URL-ലേക്ക് ചൂണ്ടിക്കാണിക്കാനാകും. അത്തരം സാഹചര്യത്തിൽ DNS റിസോൾവ് ചെയ്യുന്ന SSRF ഗാർഡ് ഉപയോഗിച്ച്
ഫെച്ച് കൂടുതൽ സുരക്ഷിതമാക്കുന്നു ([സുരക്ഷ](#security) കാണുക).

എല്ലാ പ്ലഗിൻ റൂട്ടുകളും **ലൂപ്പ്ബാക്കിൽ മാത്രം ലഭ്യമാണ്** (ടയർ 1 — `LOCAL_ONLY`): പ്ലഗിനുകൾ ചൈൽഡ്
പ്രോസസുകളിൽ കോഡ് ലോഡ് ചെയ്ത് എക്സിക്യൂട്ട് ചെയ്യുന്നതിനാൽ, ഓതന്റിക്കേഷൻ പരിഗണിക്കാതെ തന്നെ
ലൂപ്പ്ബാക്ക് അല്ലാത്ത ഒറിജിനുകളിൽ നിന്ന് റൂട്ടുകൾ ആക്സസ് ചെയ്യാനാവില്ല.
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) കാണുക.

## ഘടകങ്ങൾ എങ്ങനെ ഒരുമിച്ച് പ്രവർത്തിക്കുന്നു

```
ഡാഷ്ബോർഡ് (/dashboard/plugins)
  ├─ "ഇൻസ്റ്റാൾ ചെയ്തവ" ടാബ് → GET /api/plugins            (listPlugins)
  │                           POST /api/plugins/scan      (pluginManager.scan)
  │                           POST /api/plugins/{name}/activate|deactivate
  │                           DELETE /api/plugins/{name}   (അൺഇൻസ്റ്റാൾ)
  └─ "മാർക്കറ്റ്പ്ലേസ്" ടാബ് → GET /api/plugins/marketplace
                                → listMarketplacePlugins()
                                  ├─ ഇഷ്ടാനുസൃത URL ഇല്ല → ബിൽറ്റ്-ഇൻ SEED_REGISTRY
                                  └─ ഇഷ്ടാനുസൃത URL → isSafeMarketplaceUrl() SSRF ഗാർഡ്
                                                       → safeOutboundFetch(guard:"public-only")
```

- **രജിസ്ട്രി ലെയർ** — `src/lib/plugins/marketplace.ts`: കാറ്റലോഗ് ലിസ്റ്റ് ചെയ്യുകയും / തിരയുകയും
  ചെയ്യുന്നു; എന്തെങ്കിലും പരാജയം സംഭവിച്ചാൽ സീഡ് രജിസ്ട്രിയിലേക്ക് മടങ്ങുന്നു.
- **ലൈഫ്സൈക്കിൾ ലെയർ** — `src/lib/plugins/manager.ts` (`pluginManager` സിംഗിൾട്ടൺ):
  ഇൻസ്റ്റാൾ, അപ്ഗ്രേഡ്, ആക്ടിവേറ്റ്, ഡീആക്ടിവേറ്റ്, അൺഇൻസ്റ്റാൾ, സ്കാൻ, സ്റ്റാർട്ടപ്പ് ലോഡ്.
- **മാനിഫെസ്റ്റ് ലെയർ** — `src/lib/plugins/manifest.ts`: `plugin.json`-നുള്ള
  Zod സ്കീമയും ഡിഫോൾട്ടുകളും.
- **സ്കാനർ** — `src/lib/plugins/scanner.ts`: പ്ലഗിൻ ഡയറക്ടറിക്ക് കീഴിൽ ഡിസ്കിലുള്ള
  പ്ലഗിനുകൾ കണ്ടെത്തുന്നു.
- **ലോഡർ** — `src/lib/plugins/loader.ts`: ഓരോ പ്ലഗിനെയും ഒറ്റപ്പെട്ട
  ചൈൽഡ് പ്രോസസിൽ ആരംഭിക്കുകയും IPC വഴി ഹുക്ക് കോളുകൾക്ക് ഇടനില വഹിക്കുകയും ചെയ്യുന്നു.

## മാർക്കറ്റ്പ്ലേസ് കാറ്റലോഗ്

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`)
`MarketplaceEntry` ഒബ്ജക്റ്റുകളുടെ ഒരു ലിസ്റ്റ് നൽകുന്നു:

| ഫീൽഡ്         | തരം      | കുറിപ്പുകൾ                                        |
| ------------- | -------- | ------------------------------------------------- |
| `name`        | string   | kebab-case പ്ലഗിൻ നാമം                            |
| `version`     | string   | semver                                            |
| `description` | string   | ഹ്രസ്വ സംഗ്രഹം                                    |
| `author`      | string   | രചയിതാവ് / സ്ഥാപനം                                |
| `license`     | string   | SPDX മാതൃകയിലുള്ള ലൈസൻസ് ഐഡി                      |
| `downloadUrl` | string   | സോഴ്സ് ഡൗൺലോഡ് URL (ശൂന്യമാകാം)                   |
| `repository`  | string?  | ഐച്ഛിക റെപ്പോസിറ്ററി URL                          |
| `tags`        | string[] | തിരയൽ/ഫിൽട്ടർ ടാഗുകൾ                              |
| `downloads`   | number   | ഡൗൺലോഡ് എണ്ണം                                     |
| `rating`      | number   | 0–5                                               |
| `verified`    | boolean  | എൻട്രി സ്ഥിരീകരിച്ചതായി അടയാളപ്പെടുത്തിയിട്ടുണ്ടോ |
| `lastUpdated` | string   | ISO മാതൃകയിലുള്ള തീയതി സ്ട്രിംഗ്                  |

ഇഷ്ടാനുസൃത രജിസ്ട്രി URL കോൺഫിഗർ ചെയ്തിട്ടില്ലെങ്കിൽ, കാറ്റലോഗ് ബിൽറ്റ്-ഇൻ
`SEED_REGISTRY` ആയിരിക്കും (നിലവിൽ `request-logger`, `rate-limiter`, `cost-tracker`,
കൂടാതെ `theme-manager`). സീഡ് രജിസ്ട്രി എല്ലായ്പ്പോഴും ലഭ്യമാണ് — കോൺഫിഗർ ചെയ്ത റിമോട്ട്
രജിസ്ട്രി ലഭ്യമല്ലെങ്കിലോ, `200` അല്ലാത്ത സ്റ്റാറ്റസ് നൽകിയാലോ, തിരിച്ചറിയാനാകാത്ത
ബോഡി നൽകിയാലോ, `listMarketplacePlugins()` ഒരു മുന്നറിയിപ്പ് ലോഗ് ചെയ്ത് സീഡ് ലിസ്റ്റിലേക്ക് മടങ്ങും.

> കുറിപ്പ്: മാർക്കറ്റ്പ്ലേസ് **കാറ്റലോഗ്** (ബ്രൗസ്/തിരയൽ) പൂർണമായി ബന്ധിപ്പിച്ചിട്ടുണ്ടെങ്കിലും,
> കാറ്റലോഗിൽ നിന്നുള്ള ഒറ്റ-ക്ലിക്ക് മാർക്കറ്റ്പ്ലേസ് **ഇൻസ്റ്റാൾ** ഇതുവരെ നടപ്പിലാക്കിയിട്ടില്ല —
> ഒരു മാർക്കറ്റ്പ്ലേസ് എൻട്രിയിലെ ഡാഷ്ബോർഡിന്റെ "ഇൻസ്റ്റാൾ" ബട്ടൺ നിലവിൽ
> "ഉടൻ വരുന്നു" എന്ന അറിയിപ്പ് കാണിക്കുന്നു. ഇപ്പോൾ ഇൻസ്റ്റലേഷൻ ലോക്കൽ-പാത്ത് ഇൻസ്റ്റാൾ
> ഫ്ലോ (`POST /api/plugins`) വഴിയും ഡിസ്കിലെ കണ്ടെത്തൽ (`POST /api/plugins/scan`) വഴിയുമാണ് നടക്കുന്നത്.

## REST API

എല്ലാ എൻഡ്പോയിന്റുകൾക്കും മാനേജ്മെന്റ് ഓത്ത് (`requireManagementAuth`) ആവശ്യമാണ്, കൂടാതെ അവ
ലൂപ്പ്ബാക്കിൽ മാത്രമേ ലഭ്യമാകൂ — `/api/plugins`, `/api/plugins/` എന്നിവ
`LOCAL_ONLY_API_PREFIXES`-ൽ (`src/server/authz/routeGuard.ts`) ഉൾപ്പെടുത്തിയിരിക്കുന്നു.

| എൻഡ്പോയിന്റ്                     | രീതി   | വിവരണം                                                                               |
| -------------------------------- | ------ | ------------------------------------------------------------------------------------ |
| `/api/plugins`                   | GET    | ഇൻസ്റ്റാൾ ചെയ്ത പ്ലഗിനുകൾ പട്ടികപ്പെടുത്തുക (ഐച്ഛികമായ `?status=` ഫിൽട്ടർ)           |
| `/api/plugins`                   | POST   | ഒരു സമ്പൂർണ്ണ ലോക്കൽ പാത്തിൽനിന്ന് പ്ലഗിൻ ഇൻസ്റ്റാൾ ചെയ്യുക                          |
| `/api/plugins/scan`              | POST   | പ്ലഗിൻ ഡയറക്ടറി സ്കാൻ ചെയ്ത് പുതിയ പ്ലഗിനുകൾ രജിസ്റ്റർ ചെയ്യുക                       |
| `/api/plugins/marketplace`       | GET    | മാർക്കറ്റ്പ്ലേസ് കാറ്റലോഗ് എൻട്രികൾ പട്ടികപ്പെടുത്തുക                                |
| `/api/plugins/[name]`            | GET    | ഇൻസ്റ്റാൾ ചെയ്ത പ്ലഗിന്റെ വിശദാംശങ്ങൾ നേടുക                                          |
| `/api/plugins/[name]`            | DELETE | ഒരു പ്ലഗിൻ അൺഇൻസ്റ്റാൾ ചെയ്യുക                                                       |
| `/api/plugins/[name]/activate`   | POST   | സജീവമാക്കുക (ലോഡ് ചെയ്യുക + ഹുക്കുകൾ രജിസ്റ്റർ ചെയ്യുക)                              |
| `/api/plugins/[name]/deactivate` | POST   | നിർജ്ജീവമാക്കുക (`onDeactivate` പ്രവർത്തിപ്പിക്കുക, ഹുക്കുകളുടെ രജിസ്ട്രേഷൻ നീക്കുക) |
| `/api/plugins/[name]/config`     | GET    | പ്ലഗിൻ കോൺഫിഗും കോൺഫിഗ് സ്കീമയും നേടുക                                               |
| `/api/plugins/[name]/config`     | PUT    | പ്ലഗിൻ കോൺഫിഗ് അപ്ഡേറ്റ് ചെയ്യുക (സ്കീമയ്ക്കെതിരെ സാധൂകരിച്ചത്)                      |

`GET /api/plugins`-ലെ `status` ഫിൽട്ടർ
`installed` / `active` / `inactive` / `error` എന്നിവയിൽ ഒന്ന് സ്വീകരിക്കുന്നു. അസാധുവായ മൂല്യം നൽകിയാൽ `400` തിരികെ നൽകും.

### ഇൻസ്റ്റാൾ ചെയ്ത പ്ലഗിനുകൾ പട്ടികപ്പെടുത്തുക

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### ഒരു ലോക്കൽ പാത്തിൽനിന്ന് ഇൻസ്റ്റാൾ ചെയ്യുക

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` **സമ്പൂർണ്ണമായിരിക്കണം**, കൂടാതെ അതിൽ `..` ട്രാവേഴ്സൽ സെഗ്മെന്റുകളോ
നൾ ബൈറ്റുകളോ ഉണ്ടാകരുത് (Zod ഇത് നിർബന്ധമാക്കുന്നു). സോഴ്സ് ഡയറക്ടറിയിൽ സാധുവായ
`plugin.json` ഉണ്ടായിരിക്കണം (അല്ലെങ്കിൽ അത്തരമൊന്നിന്റെ പാരന്റ് ഡയറക്ടറിയായിരിക്കണം). വിജയിച്ചാൽ,
ഇൻസ്റ്റാൾ ചെയ്ത പ്ലഗിൻ റോയ്ക്കൊപ്പം `201` പ്രതികരണമായി ലഭിക്കും.

### മാർക്കറ്റ്പ്ലേസ് ബ്രൗസ് ചെയ്യുക

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### പ്ലഗിൻ കോൺഫിഗ് അപ്ഡേറ്റ് ചെയ്യുക

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

നൽകിയ ഓരോ മൂല്യവും പ്ലഗിന്റെ `configSchema`-യ്ക്കെതിരെ (`manifest`-ൽ പ്രഖ്യാപിച്ചത്)
`PUT .../config` സാധൂകരിക്കുന്നു: `number` ഫീൽഡുകൾ `min`/`max` പാലിക്കുന്നു,
`select` ഫീൽഡുകൾ പ്രഖ്യാപിച്ച `enum`-മായി പൊരുത്തപ്പെടണം. സ്കീമയിൽ ഇല്ലാത്ത കീകളും
അനുവദിക്കും.

## കോൺഫിഗറേഷൻ

### പ്ലഗിൻ ഡയറക്ടറി

പ്ലഗിനുകൾ OmniRoute ഡാറ്റാ ഡയറക്ടറിക്കു കീഴിലാണ് സ്ഥിതിചെയ്യുന്നത്:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (അല്ലെങ്കിൽ manifest.main ചൂണ്ടിക്കാണിക്കുന്ന മറ്റെന്തെങ്കിലും)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) ആ ഡയറക്ടറി മൂന്ന്
ഘട്ടങ്ങളിലായി നിർണ്ണയിക്കുന്നു:

1. **`OMNIROUTE_PLUGINS_DIR`**, സജ്ജീകരിച്ചിട്ടുണ്ടെങ്കിൽ — `HOME` എന്ത് പറഞ്ഞാലും, നൽകിയതുപോലെതന്നെ ഉപയോഗിക്കും. സാധാരണയായി കണ്ടെയ്നറിന്റെ ഹോം ഡയറക്ടറിയുമായി യാതൊരു ബന്ധവുമില്ലാത്ത ഒരു പാത്തിൽ പ്ലഗിൻ ട്രീ ബൈൻഡ്-മൗണ്ട് ചെയ്യുന്ന Docker/K8s-നുള്ള വ്യക്തമായ ക്രമീകരണമാണിത് (#11827).
2. `<home>/.omniroute/plugins`, ഇവിടെ `<home>` എന്നത് `HOME` / `USERPROFILE`
   എൻവയോൺമെന്റ് വേരിയബിളുകളിൽനിന്ന് ലഭിക്കുന്നു.
3. പ്രോസസ് ഹോം ഒന്നും എക്സ്പോർട്ട് ചെയ്യുന്നില്ലെങ്കിൽ `/tmp/.omniroute/plugins`.

ഏത് ഇൻപുട്ടാണ് പ്രാബല്യത്തിൽ വന്നതെന്ന് (`OMNIROUTE_PLUGINS_DIR`, `home`, അല്ലെങ്കിൽ `no-home-fallback`) വ്യക്തമാക്കിക്കൊണ്ട്, നിർണ്ണയിച്ച ഡയറക്ടറി സ്റ്റാർട്ടപ്പിൽ ഒരിക്കൽ `scanner.dir_resolved` ആയി ലോഗ് ചെയ്യപ്പെടുന്നു — അതിനാൽ, നിശ്ശബ്ദമായി ഘട്ടം 3-ൽ എത്തുന്ന ഒരു ഇമേജ് ശൂന്യമായ പ്ലഗിൻ ലിസ്റ്റ് മാത്രം റിപ്പോർട്ട് ചെയ്യാതെ അക്കാര്യം വ്യക്തമാക്കുകയും ചെയ്യും.
അവിടെ സാധുവായ `plugin.json` ഉൾക്കൊള്ളുന്ന ഏതൊരു സബ്ഡയറക്ടറിയെയും `POST /api/plugins/scan` കണ്ടെത്തി രജിസ്റ്റർ ചെയ്യും; `pluginManager.install()` പ്ലഗിനുകൾ പകർത്തുന്നതിന്റെ റൂട്ടും ഇതേ ഡയറക്ടറിയാണ്, അതിനാൽ ഒരു ഓവർറൈഡ് ഡിസ്കവറിയെയും ഇൻസ്റ്റാളേഷനെയും ഒരുമിച്ച് മാറ്റുന്നു.

> **`OMNIROUTE_PLUGINS_DIR` എന്നത് `OMNIROUTE_PLUGIN_PATH` അല്ല.** `omniroute`
> സബ്കമാൻഡുകൾ ചേർക്കുന്ന `omniroute-cmd-*` npm പാക്കേജുകൾ കണ്ടെത്താൻ CLI കമാൻഡ്-പ്ലഗിൻ ലോഡർ
> (`bin/cli/plugins.mjs`) മാത്രമാണ് രണ്ടാമത്തേത് വായിക്കുന്നത് — ഇവിടെ വിവരിച്ചിരിക്കുന്ന റൺടൈം സ്കാനറിൽ
> അതിന് യാതൊരു സ്വാധീനവുമില്ല. അതിനെക്കുറിച്ച് അറിയാൻ [PLUGINS.md](./PLUGINS.md) കാണുക.

### ഇഷ്ടാനുസൃത മാർക്കറ്റ്പ്ലേസ് രജിസ്ട്രി URL

മാർക്കറ്റ്പ്ലേസ് കാറ്റലോഗിന്റെ സോഴ്സ് `pluginMarketplaceUrl` ക്രമീകരണത്തിൽനിന്നാണ് വായിക്കുന്നത്
(`src/lib/plugins/marketplace.ts`, `settings.pluginMarketplaceUrl` വായിക്കുന്നു). ഒരു
`http(s)` URL ആയി സജ്ജീകരിക്കുമ്പോൾ, `listMarketplacePlugins()` ആ URL ഫെച്ച് ചെയ്യുകയും,
എൻട്രികളുടെ ടോപ്പ്-ലെവൽ JSON അറേയോ `plugins` അറേയുള്ള ഒരു ഒബ്ജക്റ്റോ സ്വീകരിക്കുകയും ചെയ്യും;
സ്ട്രിംഗ് `name` ഇല്ലാത്ത എൻട്രികൾ ഫിൽട്ടർ ചെയ്ത് നീക്കും. ഇത് സജ്ജീകരിച്ചിട്ടില്ലെങ്കിൽ (അല്ലെങ്കിൽ ഫെച്ച്
SSRF ഗാർഡിൽ പരാജയപ്പെടുകയോ മോശം പ്രതികരണം ലഭിക്കുകയോ ചെയ്താൽ), ബിൽറ്റ്-ഇൻ സീഡ് രജിസ്ട്രിയാണ്
ഉപയോഗിക്കുന്നത്.

ഡാഷ്ബോർഡിലെ "Marketplace" ടാബ് ഈ URL-നായി ഒരു ഫീൽഡ് നൽകുന്നു (`GET /api/settings`-ൽനിന്ന്
തിരികെ വായിക്കുന്നു).

> ഇംപ്ലിമെന്റേഷൻ കുറിപ്പ്: ഡാഷ്ബോർഡിലെ "Save" പ്രവർത്തനം
> `pluginMarketplaceUrl` എന്നത് `PATCH /api/settings`-ലേക്ക് അയയ്ക്കുന്നു. ഇത് എഴുതുന്ന സമയത്ത്,
> ഈ കീ `updateSettingsSchema`-യിൽ
> (`src/shared/validation/settingsSchemas.ts`) പ്രഖ്യാപിച്ചിട്ടില്ല; അതിനാൽ ഇതിനെ ആശ്രയിക്കുന്നതിന് മുമ്പ്
> നിങ്ങളുടെ റിലീസിൽ പെർസിസ്റ്റൻസ് പരിശോധിക്കുക — ക്രമീകരണ സ്റ്റോറിൽ കീ നിലവിലുണ്ടായാൽ **റീഡ്**
> പാത്ത് (`getSettings()` → `listMarketplacePlugins()`) അതിനെ മാനിക്കും.

## സുരക്ഷ

### റൂട്ട് ടിയർ — ലൂപ്പ്ബാക്ക് മാത്രം

പ്ലഗിനുകൾ സ്പോൺ ചെയ്ത ചൈൽഡ് പ്രോസസുകളിൽ കോഡ് പ്രവർത്തിപ്പിക്കുന്നതിനാൽ, മുഴുവൻ `/api/plugins`
ഉപരിതലവും `LOCAL_ONLY` (ടിയർ 1) ആയി വർഗ്ഗീകരിച്ചിരിക്കുന്നു. ഏതൊരു ഓത്ത് പരിശോധനയ്ക്കും
**മുമ്പ്** ലൂപ്പ്ബാക്ക് എൻഫോഴ്സ്മെന്റ് നിരുപാധികമായി പ്രവർത്തിക്കുന്നു. അതിനാൽ ഒരു ടണൽ വഴി
മെഷീനിലെത്തുന്ന ചോർന്ന മാനേജ്മെന്റ് ടോക്കണിനുപോലും ഒരു പ്ലഗിൻ ഇൻസ്റ്റാൾ ചെയ്യാനോ,
സജീവമാക്കാനോ, അൺഇൻസ്റ്റാൾ ചെയ്യാനോ കഴിയില്ല.
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md), കൂടാതെ
കർശന നിയമങ്ങൾ #15 / #17 കാണുക.

### മാർക്കറ്റ്പ്ലേസ് രജിസ്ട്രി SSRF ഗാർഡ്

ഒരു ഇഷ്ടാനുസൃത രജിസ്ട്രി URL ആക്രമണകാരിക്ക് സ്വാധീനിക്കാവുന്ന കോൺഫിഗറേഷനായതിനാൽ,
അത് ഫെച്ച് ചെയ്യുന്നതിന് മുമ്പ് `listMarketplacePlugins()` അതിനെ രണ്ട് പാളികളിലൂടെ
കടത്തിവിടുന്നു:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - `http:` / `https:` അല്ലാത്ത എന്തും നിരസിക്കുന്നു.
   - കാനോണിക്കൽ `isPrivateHost`
     (`src/shared/network/outboundUrlGuard.ts`) ഉപയോഗിച്ച് ലിറ്ററൽ സ്വകാര്യ/ലൂപ്പ്ബാക്ക്/ലിങ്ക്-ലോക്കൽ/ULA ഹോസ്റ്റുകൾ
     (IPv4-മാപ്പ് ചെയ്തവ ഉൾപ്പെടെ IPv4-ഉം IPv6-ഉം) നിരസിക്കുന്നു.
   - **`A`**, **`AAAA`** റെക്കോർഡുകൾ രണ്ടും റിസോൾവ് ചെയ്യുകയും റിസോൾവ് ചെയ്ത
     വിലാസങ്ങളിൽ **ഏതെങ്കിലും ഒന്ന്** സ്വകാര്യമാണെങ്കിൽ നിരസിക്കുകയും ചെയ്യുന്നു — ഇതിലൂടെ
     പൊതു-ഹോസ്റ്റ്നെയിം → സ്വകാര്യ-IP ബൈപാസ് തടയുന്നു.
   - **ഫെയിൽസ് ക്ലോസ്ഡ്**: DNS റിസല്യൂഷൻ പരാജയപ്പെട്ടാൽ URL നിരസിക്കുന്നു.
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`**
   (`src/shared/network/safeOutboundFetch.ts`): ഫെച്ച് ചെയ്യുന്ന സമയത്ത് പൊതു-മാത്രം URL
   ഗാർഡ് വീണ്ടും പ്രയോഗിക്കുകയും **റീഡയറക്ടുകൾ തടയുകയും** ചെയ്യുന്നു (പൊതു → സ്വകാര്യ `30x`
   പിവറ്റ് അനുവദിക്കില്ല).

ഏതെങ്കിലും പാളിയിൽ പരാജയപ്പെടുന്ന URL അഭ്യർത്ഥനയെ അബോർട്ട് ചെയ്യില്ല — മാർക്കറ്റ്പ്ലേസ്
നിശ്ശബ്ദമായി ബിൽറ്റ്-ഇൻ സീഡ് രജിസ്ട്രിയിലേക്ക് ഫാൾബാക്ക് ചെയ്യുകയും ഒരു മുന്നറിയിപ്പ് ലോഗ്
ചെയ്യുകയും ചെയ്യും.

> A + AAAA റിസോൾവ് ചെയ്യുന്നതിനും IPv4-മാത്രം പരിശോധനയ്ക്കു പകരം കാനോണിക്കൽ
> `isPrivateHost` ഉപയോഗിക്കുന്നതിനുമായി ഈ ഗാർഡ് PR #3774-ൽ പ്രത്യേകം ശക്തിപ്പെടുത്തിയതാണ്.

### പ്ലഗിൻ നിർവഹണ ഐസൊലേഷൻ

- **പ്രോസസ് ഐസൊലേഷൻ** — `loadPlugin()` (`src/lib/plugins/loader.ts`) ഓരോ
  പ്ലഗിനും പ്രത്യേക Node.js ചൈൽഡ് പ്രോസസിൽ സ്പോൺ ചെയ്യുകയും IPC വഴി ആശയവിനിമയം
  നടത്തുകയും ചെയ്യുന്നു. ഹുക്ക് കോളുകൾക്ക് `SIGTERM` → `SIGKILL` എസ്കലേഷനോടുകൂടിയ
  ടൈംഔട്ട് ഉണ്ട്.
- **എൻവ് അലൗലിസ്റ്റ്** — ചൈൽഡിന് അലൗലിസ്റ്റിൽ ഉൾപ്പെട്ട എൻവയോൺമെന്റ്
  വേരിയബിളുകളുടെ സെറ്റ് മാത്രമേ ലഭിക്കൂ; മാനിഫെസ്റ്റ് `env` അനുമതി അഭ്യർത്ഥിക്കുമ്പോൾ
  മാത്രമാണ് കൂടുതൽ വിപുലമായ സെറ്റ് അനുവദിക്കുന്നത്.
- **പാത്ത് കണ്ടെയ്ൻമെന്റ്** — പകർത്തലിനോ റിക്കഴ്സീവ് ഡിലീഷനോ മുമ്പ്, പ്ലഗിൻ
  ഡയറക്ടറിയും `manifest.main`-ഉം മാനേജ് ചെയ്യുന്ന പ്ലഗിൻ റൂട്ടിന്റെ **ഉള്ളിൽത്തന്നെ**
  റിസോൾവ് ചെയ്യുന്നുവെന്ന് ഇൻസ്റ്റാൾ/അപ്ഗ്രേഡ്/അൺഇൻസ്റ്റാൾ പ്രവർത്തനങ്ങൾ ഉറപ്പാക്കുന്നു
  (കൃത്രിമം നടത്തിയ DB പാത്തുകളിൽനിന്നും `manifest.main`-ലെ `../` ട്രാവേഴ്സലിൽനിന്നും
  സംരക്ഷിക്കുന്നു). ആക്ടിവേഷൻ `realpath` വഴി സിംലിങ്കുകൾ റിസോൾവ് ചെയ്യുകയും പ്ലഗിൻ
  ഡയറക്ടറിയിൽനിന്ന് പുറത്തുകടക്കുന്ന എൻട്രി പോയിന്റ് ലോഡ് ചെയ്യാൻ വിസമ്മതിക്കുകയും ചെയ്യുന്നു.
- **ഓപ്ഷണൽ ഇന്റഗ്രിറ്റി പിൻ** — ഒരു മാനിഫെസ്റ്റിന് `integrity`
  (`sha256-<base64>`, SRI ഫോർമാറ്റ്) ഫീൽഡ് പ്രഖ്യാപിക്കാം. അത് നൽകിയിട്ടുണ്ടെങ്കിൽ,
  ലോഡ് ചെയ്യുന്ന സമയത്ത് ലോഡർ എൻട്രി ഫയലിന്റെ ഹാഷ് പരിശോധിക്കുകയും പൊരുത്തക്കേടുണ്ടെങ്കിൽ
  സജീവമാക്കാൻ വിസമ്മതിക്കുകയും ചെയ്യുന്നു. ഇത് ഓപ്റ്റ്-ഇൻ ടാംപർ-ഡിറ്റക്ഷനാണ്,
  ഒരു സുരക്ഷാ അതിർത്തി **അല്ല** — ലൂപ്പ്ബാക്ക്-മാത്രം റൂട്ടിംഗും അനുമതി മോഡലുമാണ്
  യഥാർത്ഥ അതിർത്തികൾ.

## മാനിഫെസ്റ്റ് (`plugin.json`)

`PluginManifestSchema` (`src/lib/plugins/manifest.ts`) ഉപയോഗിച്ച് സാധൂകരിക്കുന്നു:

| ഫീൽഡ്              | തരം       | കുറിപ്പുകൾ                                                             |
| ------------------ | --------- | ---------------------------------------------------------------------- |
| `name`             | string    | നിർബന്ധം; kebab-case (`^[a-z0-9-]+$`), 1–100 പ്രതീകങ്ങൾ                |
| `version`          | string    | നിർബന്ധം; semver (`MAJOR.MINOR.PATCH`)                                 |
| `description`      | string?   | ≤ 500 പ്രതീകങ്ങൾ                                                       |
| `author`           | string?   | ≤ 200 പ്രതീകങ്ങൾ                                                       |
| `license`          | string?   | ഡിഫോൾട്ട് `MIT`                                                        |
| `main`             | string?   | എൻട്രി ഫയൽ; ഡിഫോൾട്ട് `index.js`                                       |
| `source`           | enum?     | `local` \| `marketplace` (ഡിഫോൾട്ട് `local`)                           |
| `tags`             | string[]? | തിരയൽ ടാഗുകൾ                                                           |
| `requires`         | object?   | `{ omniroute?, permissions[] }`                                        |
| `hooks`            | object?   | പ്ലഗിൻ നടപ്പാക്കുന്ന ഹുക്കുകൾ ഏതൊക്കെയെന്ന് പ്രഖ്യാപിക്കുന്ന ബൂളിയനുകൾ |
| `skills`           | object[]? | ഓപ്ഷണൽ സ്കിൽ നിർവചനങ്ങൾ                                                |
| `enabledByDefault` | boolean?  | ഇൻസ്റ്റാൾ ചെയ്യുമ്പോൾ സ്വയമേവ സജീവമാക്കുക                              |
| `configSchema`     | object?   | കോൺഫിഗ് ഫീൽഡുകളുടെ മാപ്പ് (`string`/`number`/`boolean`/`select`)       |
| `integrity`        | string?   | ഓപ്ഷണൽ `sha256-<base64>` എൻട്രി-ഫയൽ പിൻ                                |

അനുമതികൾ
`network` / `file-read` / `file-write` / `env` / `exec` എന്ന enum-ൽ നിന്നാണ് എടുക്കുന്നത്.

## ലൈഫ്സൈക്കിൾ പ്രവാഹം

```
install (POST /api/plugins, പാത്ത്)
  → മാനിഫെസ്റ്റ് സ്കാൻ/സാധൂകരിക്കുക → സ്റ്റേജിങ്ങിലേക്ക് പകർത്തുക → main ഡയറക്ടറിക്കുള്ളിലാണെന്ന് ഉറപ്പാക്കുക
  → ~/.omniroute/plugins/<name>-ലേക്ക് ആറ്റോമിക് ആയി പേരുമാറ്റുക → DB വരി ചേർക്കുക
  → onInstall പ്രവർത്തിപ്പിക്കുക → enabledByDefault ആണെങ്കിൽ: activate

activate (POST /api/plugins/{name}/activate)
  → realpath കണ്ടെയ്ൻമെന്റ് പരിശോധന → loadPlugin() (ചൈൽഡ് പ്രോസസ് ആരംഭിക്കുക)
  → പ്രഖ്യാപിച്ച ഹുക്കുകൾ രജിസ്റ്റർ ചെയ്യുക → status = "active" → onActivate പ്രവർത്തിപ്പിക്കുക

deactivate (POST /api/plugins/{name}/deactivate)
  → onDeactivate പ്രവർത്തിപ്പിക്കുക (രജിസ്ട്രേഷൻ നീക്കുന്നതിന് മുമ്പ്) → ഹുക്കുകളുടെ രജിസ്ട്രേഷൻ നീക്കുക
  → ചൈൽഡ് പ്രോസസ് അവസാനിപ്പിക്കുക → status = "inactive"

uninstall (DELETE /api/plugins/{name})
  → സജീവമാണെങ്കിൽ deactivate ചെയ്യുക → onUninstall പ്രവർത്തിപ്പിക്കുക
  → കണ്ടെയ്ൻമെന്റ് പരിശോധിച്ച് പ്ലഗിൻ ഡയറക്ടറി ആവർത്തിതമായി ഇല്ലാതാക്കുക → DB വരി ഇല്ലാതാക്കുക
```

ഇൻസ്റ്റാൾ ചെയ്ത പതിപ്പിനേക്കാൾ **കർശനമായി പുതിയ** മാനിഫെസ്റ്റ് പതിപ്പുള്ള ഒരു
ഡയറക്ടറിയിൽ `install` വീണ്ടും പ്രവർത്തിപ്പിക്കുന്നത് സ്വയമേവ അപ്ഗ്രേഡ് ചെയ്യും
(ശുദ്ധമായ പുനഃസ്ഥാപനം; കോൺഫിഗറേഷൻ ഡിഫോൾട്ട് മൂല്യങ്ങളിലേക്ക് പുനഃസജ്ജമാകും).
അതേ പതിപ്പോ അതിലും പഴയ പതിപ്പോ നിരസിക്കപ്പെടും.

## ഡാഷ്ബോർഡ്

`/dashboard/plugins`-ലെ ഡാഷ്ബോർഡ് പേജ്
(`src/app/(dashboard)/dashboard/plugins/page.tsx`) രണ്ട് ടാബുകൾ നൽകുന്നു:

- **ഇൻസ്റ്റാൾ ചെയ്തവ** — ഇൻസ്റ്റാൾ ചെയ്ത പ്ലഗിനുകൾ, അവ പ്രഖ്യാപിച്ച ഹുക്കുകൾ,
  activate/deactivate ടോഗിൾ, uninstall ബട്ടൺ, "പ്ലഗിനുകൾക്കായി സ്കാൻ ചെയ്യുക"
  പ്രവർത്തനം (`POST /api/plugins/scan`) എന്നിവ പ്രദർശിപ്പിക്കുന്നു.
- **മാർക്കറ്റ്പ്ലേസ്** — കസ്റ്റം രജിസ്ട്രി URL സജ്ജീകരിക്കാനുള്ള ഒരു ഫീൽഡിനൊപ്പം
  `GET /api/plugins/marketplace`-ൽ നിന്നുള്ള കാറ്റലോഗ് പ്രദർശിപ്പിക്കുന്നു.

ഓരോ പ്ലഗിനുമുള്ള കോൺഫിഗറേഷൻ പേജ് `/dashboard/plugins/[name]/config`-ൽ ലഭ്യമാണ്
(`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`).
