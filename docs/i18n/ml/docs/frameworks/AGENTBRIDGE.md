AgentBridge എന്നത് IDE AI ഏജന്റുകളിൽ നിന്നുള്ള HTTPS ട്രാഫിക് തടഞ്ഞുപിടിച്ച് OmniRoute-ന്റെ ഏകീകൃത റൂട്ടിംഗ് എഞ്ചിനിലൂടെ തിരിച്ചുവിടുന്ന OmniRoute-ന്റെ MITM (Man-in-the-Middle) പ്രോക്സിയാണ്. ഇത് **10 IDE ഏജന്റുകളെ** പിന്തുണയ്ക്കുന്നു — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code, കൂടാതെ Trae (പരിശോധനയിലാണ്) — ഇതിലൂടെ വിപണിയിലെ AI കോഡിംഗ് അസിസ്റ്റന്റുകൾക്കായുള്ള ഏറ്റവും വിപുലമായ കവറേജുള്ള MITM പ്രോക്സിയായി OmniRoute മാറുന്നു.

**ഡാഷ്ബോർഡ് സ്ഥാനം:** `/dashboard/tools/agent-bridge`
**സൈഡ്ബാർ ഗ്രൂപ്പ്:** ഉപകരണങ്ങൾ (Cloud Agents-ന് ശേഷം)
**ഇതും കാണുക:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — തടഞ്ഞുപിടിച്ച എല്ലാ ട്രാഫിക്കും തത്സമയം നിരീക്ഷിക്കുക; `docs/security/MITM-TPROXY-DECRYPT.md` (git; `/docs`-ലേക്ക് കംപൈൽ ചെയ്തിട്ടില്ല) — `/api/tools/agent-bridge/tproxy` റൂട്ട് നിയന്ത്രിക്കുന്ന Linux TPROXY സുതാര്യ-ഡീക്രിപ്റ്റ് ക്യാപ്ചർ മോഡ്.

## §1 അവലോകനം

### എന്താണ് AgentBridge?

ഒരു IDE ഏജന്റ് (ഉദാ., GitHub Copilot, Cursor, Claude Code) ഒരു API കോൾ നടത്തുമ്പോൾ, അത് അപ്സ്ട്രീം AI ദാതാവുമായി (OpenAI, Anthropic മുതലായവ) നേരിട്ട് ബന്ധപ്പെടുന്നു. TLS തലത്തിൽ AgentBridge ആ കണക്ഷൻ സുതാര്യമായി തടഞ്ഞുപിടിക്കുകയും — ഏജന്റിന്റെ കോൺഫിഗറേഷനിൽ ഒരു മാറ്റവും ആവശ്യമില്ലാതെ — OmniRoute വഴി അഭ്യർത്ഥന മാറ്റിയെഴുതുകയും ചെയ്യുന്നു.

ഇതിലൂടെ നിങ്ങൾക്ക്:

- **ഏത് ഏജന്റിനെയും ഏത് ദാതാവിലേക്കും തിരിച്ചുവിടാം**: Copilot OpenAI-യുമായി ആശയവിനിമയം നടത്തുന്നുണ്ടോ? അത് Anthropic Claude, Gemini, അല്ലെങ്കിൽ OmniRoute-ന്റെ 352 ദാതാക്കളിൽ ഏതിലേക്കും തിരിച്ചുവിടാം.
- **മോഡൽ മാപ്പിംഗുകൾ പ്രയോഗിക്കാം**: ഹാൻഡ്ലർ തലത്തിൽ സുതാര്യമായി `gemini-3-flash` → `claude-sonnet-4.7`.
- **എല്ലാ ഏജന്റ് ട്രാഫിക്കും നിരീക്ഷിക്കാം**: തടഞ്ഞുപിടിക്കുന്ന ഓരോ അഭ്യർത്ഥനയും [Traffic Inspector](./TRAFFIC_INSPECTOR.md)-ലേക്ക് പ്രസിദ്ധീകരിക്കുന്നു.
- **OmniRoute-ന്റെ പ്രതിരോധശേഷി പ്രയോഗിക്കാം**: കോംബോ റൂട്ടിംഗ്, സർക്യൂട്ട് ബ്രേക്കറുകൾ, ഫാൾബാക്കുകൾ, ചെലവ് ട്രാക്കിംഗ് എന്നിവ IDE ഏജന്റ് ട്രാഫിക്കിനും പ്രവർത്തിക്കുന്നു.

### 2.2 MITM സെർവർ (`src/mitm/server.cjs`)

പ്രധാന MITM സെർവർ ഒരു Node.js CJS ചൈൽഡ് പ്രോസസായി പ്രവർത്തിക്കുന്നു (നിലവിലുള്ള CJS കോഡ്ബേസ് പുനരാലേഖനം ചെയ്യുന്നത് ഒഴിവാക്കാൻ). ഇത്:

- പോർട്ട് 443-ൽ ലിസൺ ചെയ്യുന്നു (പ്രിവിലേജ് അല്ലെങ്കിൽ `authbind`/`setcap` ആവശ്യമാണ്)
- OS-ൽ നിന്ന് CONNECT ടണലുകൾ സ്വീകരിക്കുന്നു (`/etc/hosts` DNS റീഡയറക്ട് വഴി)
- AgentBridge CA (`DATA_DIR/mitm/ca.crt`) ഒപ്പിട്ട ഓരോ SNI-യ്ക്കുമുള്ള TLS സർട്ടിഫിക്കറ്റുകൾ സൃഷ്ടിക്കുന്നു
- `targets/index.ts` രജിസ്ട്രി വഴി Host ഹെഡർ ഉപയോഗിച്ച് ടാർഗറ്റ് ഏജന്റിനെ കണ്ടെത്തുന്നു
- HTTP വഴി `http://127.0.0.1:20128`-ലെ TypeScript ഹാൻഡ്ലർ ലെയറിലേക്ക് അയയ്ക്കുന്നു

`TARGET_HOSTS`, `DATA_DIR/mitm/targets.json`-ൽ നിന്ന് ലോഡ് ചെയ്യുന്നു (ബൂട്ട് സമയത്ത് `targets/index.ts` എഴുതുന്നത്); ഇത് CJS സെർവർ പുനരാരംഭിക്കാതെ ഡൈനാമിക് അപ്ഡേറ്റുകൾ അനുവദിക്കുന്നു.

> **റൂട്ട്-CA മോഡൽ (#6684).** മുകളിൽ വിവരിച്ച ഓരോ SNI-യ്ക്കുമുള്ള-CA-ഒപ്പിട്ട-സർട്ടിഫിക്കറ്റ്
> രീതി #6684-ൽ ചേർത്ത, സ്ഥിരമായി സൂക്ഷിക്കപ്പെടുന്ന റൂട്ട്-CA മോഡലാണ് (`src/mitm/cert/rootCa.ts` +
> `src/mitm/_internal/rootCaShim.cjs`; `src/mitm/tproxy/dynamicCert.ts`-ൽ TPROXY-ക്കായി
> ഇതിനകം തെളിയിക്കപ്പെട്ട CA/ലീഫ് ക്രിപ്റ്റോ പുനരുപയോഗിക്കുന്നു) — ഡിസ്കിലെ ഒരു സാധാരണ
> `server.crt`/`server.key` ജോടി സൂചിപ്പിക്കുന്ന, പഴയ ഒറ്റ സ്റ്റാറ്റിക് സ്വയം ഒപ്പിട്ട ലീഫിനെ
> (`src/mitm/cert/generate.ts`, ഇപ്പോഴും antigravity ഹോസ്റ്റുകൾക്ക് മാത്രമായി പരിമിതപ്പെടുത്തിയിരിക്കുന്നു)
> ഇത് മാറ്റിസ്ഥാപിക്കുന്നു. **മൈഗ്രേഷൻ രീതി**: പുതിയ ഇൻസ്റ്റാളിന് (മുമ്പുണ്ടായിരുന്ന

> പുനരാരംഭിക്കുന്നതുവരെ അതുതന്നെ ഉപയോഗിക്കുന്നത് തുടരും (`src/mitm/cert/migration.ts`
> ശുദ്ധമായ തീരുമാന ഫങ്ഷനാണ് — **ഏത്** ഹോസ്റ്റിനും ലീഫ് ഒപ്പിടാൻ കഴിയുന്ന വിശ്വസനീയമായ
> MITM CA, പഴയ സ്ഥിര-SAN ലീഫിനേക്കാൾ ഗണ്യമായി കൂടുതൽ ശക്തമാണ്; അതിനാൽ ഇതിനകം വിശ്വസിക്കപ്പെട്ട
> ഇൻസ്റ്റാളിൽ ഈ മാറ്റം ഒരിക്കലും നിശ്ശബ്ദമായി നടക്കില്ല). പഴയ ലീഫ് ഉപയോഗിച്ചിരുന്ന അതേ
> `omniroute-mitm.crt` ട്രസ്റ്റ്-സ്റ്റോർ സ്ലോട്ടിലേക്കാണ് CA സർട്ടിഫിക്കറ്റ് ഇൻസ്റ്റാൾ ചെയ്യുന്നത്
> (`cert/install.ts::installCaCert`) — ഇരട്ട-ട്രസ്റ്റ് ക്ലീനപ്പ് ആവശ്യമില്ല.

### 2.3 ഹാൻഡ്ലർ ബേസ് (`src/mitm/handlers/base.ts`)

എല്ലാ ഏജന്റ് ഹാൻഡ്ലറുകളും `MitmHandlerBase` വിപുലീകരിക്കുന്നു:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // സംരക്ഷിത ഹെൽപ്പറുകൾ: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

ഓരോ ഹാൻഡ്ലറും പ്രോക്സി ചെയ്യുന്നതിന് മുമ്പ് `hookBufferStart()`-ഉം പൂർത്തിയാകുമ്പോൾ `hookBufferUpdate()`-ഉം വിളിക്കുന്നു. ഇവ `InterceptedRequest` എൻട്രികൾ `globalTrafficBuffer`-ലേക്ക് പുഷ് ചെയ്യുന്നു ([Traffic Inspector](./TRAFFIC_INSPECTOR.md) §4 കാണുക).

### 2.4 ടാർഗറ്റ് രജിസ്ട്രി (`src/mitm/targets/`)

ഓരോ ഏജന്റിനും ഒരു ഡിക്ലറേറ്റീവ് ടാർഗറ്റ് ഫയൽ ഉണ്ട്:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

രജിസ്ട്രി (`targets/index.ts`), `ALL_TARGETS` എക്സ്പോർട്ട് ചെയ്യുകയും ബൂട്ട് സമയത്ത് `DATA_DIR/mitm/targets.json` സൃഷ്ടിക്കുകയും ചെയ്യുന്നു.

### 2.5 പാസ്ത്രൂവും ബൈപാസ് ലിസ്റ്റും (`src/mitm/passthrough.ts`)

**ബൈപാസ് ലിസ്റ്റ്** (ടാർഗറ്റ് പൊരുത്തത്തേക്കാൾ മുൻഗണന നൽകി ആദ്യം പരിശോധിക്കുന്നു):

- ഡിഫോൾട്ട് പാറ്റേണുകൾ: ബാങ്കിങ് ഹോസ്റ്റുകൾ, `.gov.`, OAuth/SSO ദാതാക്കൾ (Okta, Auth0), മുതലായവ
- ഉപയോക്തൃ പാറ്റേണുകൾ: `agent_bridge_bypass` DB ടേബിളിൽ സംഭരിക്കുന്നു
- ബൈപാസ് ചെയ്ത ഹോസ്റ്റുകൾക്ക് സുതാര്യമായ TCP ടണൽ ലഭിക്കുന്നു — TLS **ഒരിക്കലും ഡീക്രിപ്റ്റ് ചെയ്യപ്പെടുന്നില്ല**

**ഡിഫോൾട്ട് പാസ്ത്രൂ** (ടാർഗറ്റ് പൊരുത്തമില്ലാത്തതും ബൈപാസിൽ ഇല്ലാത്തതും):

- ഇതിലും ഒരു TCP ടണൽ ലഭിക്കുന്നു — കണക്ഷനുകൾ ഒരിക്കലും വിച്ഛേദിക്കപ്പെടുന്നില്ല
- പൊതുവായ സിസ്റ്റം HTTPS ട്രാഫിക്കിനെ AgentBridge തടസ്സപ്പെടുത്തുന്നത് ഒഴിവാക്കുന്നു

റൂട്ടിങ് മുൻഗണന:

```
ബൈപാസ് ലിസ്റ്റ് → ടാർഗറ്റ് പൊരുത്തം → പാസ്ത്രൂ
```

### 2.6 അപ്സ്ട്രീം CA സർട്ടിഫിക്കറ്റ് (`src/mitm/upstreamTrust.ts`)

കസ്റ്റം CA ഉള്ള കോർപ്പറേറ്റ് നെറ്റ്വർക്ക് പരിതസ്ഥിതികൾക്കായി:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

ഇത് സജ്ജീകരിക്കുമ്പോൾ, അധിക CA സർട്ടിഫിക്കറ്റ് ഉപയോഗിച്ച് `undici`-യുടെ ഗ്ലോബൽ ഡിസ്പാച്ചർ കോൺഫിഗർ ചെയ്യുന്നു; ഇതിലൂടെ കോർപ്പറേറ്റ് TLS ടെർമിനേഷൻ പ്രോക്സികൾ വഴി അപ്സ്ട്രീം ദാതാക്കളുമായി ബന്ധപ്പെടാൻ AgentBridge-ന് സാധിക്കുന്നു.

### 2.7 രഹസ്യങ്ങൾ മറയ്ക്കൽ (`src/mitm/maskSecrets.ts`)

സ്വതന്ത്രമായ ക്ലീൻ-റൂം സ്കാനർ, അഭ്യർത്ഥനാ ബോഡികളിലും ക്രെഡൻഷ്യൽ ഹെഡറുകളിലും
അവ Traffic Inspector ബഫറിലേക്കോ ഏതെങ്കിലും ലോഗിലേക്കോ പ്രവേശിക്കുന്നതിന് **മുമ്പ്** പ്രയോഗിക്കുന്നു. ഇത് ഒറ്റ ലീനിയർ പാസ് നടത്തുന്നു:

- `sk-` / `ak-` / `pk-` പ്രിഫിക്സുള്ള ടോക്കണുകൾ (OpenAI/Anthropic ശൈലി)
- RFC 6750 `Authorization: Bearer <token>` ക്രെഡൻഷ്യലുകൾ, പൂർണ്ണ ടോക്കണിന് മുൻഗണന നൽകി
- പൊതുവായ നീളമുള്ള അപാരദർശക ടോക്കണുകൾ (≥40 പ്രതീകങ്ങൾ), ഡോട്ടുകളും പാഡിങ്ങും ഉള്ള രൂപങ്ങൾ ഉൾപ്പെടെ

`sanitizeHeaders()` നിലനിർത്തുന്ന പേരുകൾ ലോവർകേസിലാക്കുന്നു, അറേ മൂല്യങ്ങൾ നിർണായകമായ രീതിയിൽ ചേർക്കുന്നു,
പങ്കിടുന്ന ഹോപ്പ്-ബൈ-ഹോപ്പ്/ഫ്രെയിമിങ് ഡിനൈലിസ്റ്റ് (പ്രോക്സി ഓതന്റിക്കേഷൻ ഉൾപ്പെടെ) ഒഴിവാക്കുന്നു, `cookie`,
`set-cookie` എന്നിവ പൂർണ്ണമായി മറയ്ക്കുന്നു, കൂടാതെ ക്രെഡൻഷ്യൽ മൂല്യങ്ങൾ സ്കാനറിന് കൈമാറുന്നു.

### 3.2 സർട്ടിഫിക്കറ്റിനെ വിശ്വസിക്കുക

IDE-കൾ MITM കണക്ഷൻ സ്വീകരിക്കുന്നതിന് മുമ്പ് AgentBridge CA സർട്ടിഫിക്കറ്റ് OS വിശ്വസിച്ചിരിക്കണം.

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Keychain):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

അല്ലെങ്കിൽ ഡാഷ്ബോർഡിലെ "Trust Cert" ബട്ടൺ ഉപയോഗിക്കുക (നിങ്ങളുടെ OS-ന് അനുയോജ്യമായ കമാൻഡ് പ്രവർത്തിപ്പിക്കുന്നു; ആവശ്യമെങ്കിൽ sudo പ്രോംപ്റ്റ് കാണിക്കും).

#### Electron അധിഷ്ഠിത IDE-കൾ OS ട്രസ്റ്റ് സ്റ്റോർ അവഗണിക്കുന്നു (`NODE_EXTRA_CA_CERTS`)

ചില IDE-കൾ — പ്രത്യേകിച്ച് **Antigravity IDE**, കൂടാതെ Electron / VS Code-ൽ നിന്ന് ഉരുത്തിരിഞ്ഞ മറ്റ് ആപ്പുകൾ — ഔട്ട്ബൗണ്ട്
`fetch`/HTTPS-നായി **OS ട്രസ്റ്റ് സ്റ്റോർ പരിശോധിക്കാത്ത** സ്വന്തം Node.js റൺടൈം ഉൾക്കൊള്ളുന്നു.
OS/NSS തലത്തിൽ CA-യെ വിശ്വസിക്കുന്നത് IDE-യുടെ നേറ്റീവ് **ബാക്കെൻഡിന്**
(ഉദാ. OS CA ബണ്ടിൽ ഉപയോഗിക്കുന്ന ഒരു Go ലാംഗ്വേജ് സെർവർ) മതിയാകും, എന്നാൽ **Electron ഫ്രണ്ടെൻഡിൽ**
TLS അപ്പോഴും പരാജയപ്പെടും — ആപ്പ് _ലോഗ് ഔട്ട് ആയതായി_ കാണിക്കുകയോ _"connection error"_
കാണിക്കുകയോ ചെയ്യുന്നതായിരിക്കും ഇതിന്റെ ലക്ഷണം; അതേസമയം MITM ലോഗിൽ ബാക്കെൻഡിന്റെ ബൂട്ട്സ്ട്രാപ്പ് കോളുകൾ `200` തിരികെ നൽകുന്നതായി കാണാം. രണ്ട് ഘട്ടങ്ങൾ
ആവശ്യമാണ്, രണ്ടും പ്രധാനമാണ്:

1. റൺടൈമിന് CA വ്യക്തമായി നിർദ്ദേശിക്കുക:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **ആ ഷെല്ലിൽ നിന്ന് IDE ആരംഭിക്കുക.** ഡെസ്ക്ടോപ്പ് ഐക്കൺ / Dock / Start menu എന്നിവയിൽ നിന്ന് ആരംഭിച്ചാൽ
   ഷെൽ എക്സ്പോർട്ടുകൾ പാരമ്പര്യമായി ലഭിക്കില്ല; പുതിയൊരു ഗ്രാഫിക്കൽ ലോഗിൻ നടത്തിയതിനുശേഷം മാത്രമേ `~/.config/environment.d/*.conf`
   ബാധകമാകൂ. ആദ്യം IDE പൂർണ്ണമായി അടയ്ക്കുക — Electron-ന്റെ സിംഗിൾടൺ ലോക്ക് കാരണം രണ്ടാമതൊരു
   തവണ ആരംഭിക്കുന്നത് നിലവിലുള്ള പ്രോസസിലേക്ക് മാത്രം ഫോക്കസ് ചെയ്യുകയും പുതിയ എൻവയോൺമെന്റ് അവഗണിക്കപ്പെടുകയും ചെയ്യും.

മുകളിലുള്ള OS ട്രസ്റ്റ് + NSS ഘട്ടം തുടർന്നും ആവശ്യമാണ് (ചില ഓത്ത്
ഫ്ലോകൾ ഉപയോഗിക്കുന്ന Chromium നെറ്റ്വർക്ക് സ്റ്റാക്ക് ഓരോ ഉപയോക്താവിന്റെയും NSS സ്റ്റോർ വായിക്കുന്നു; കൂടാതെ പ്രാദേശികമായി വിശ്വസിക്കപ്പെട്ട ഒരു CA മറികടക്കുന്ന `*.googleapis.com`-നുള്ള സ്വന്തം സ്റ്റാറ്റിക് പിന്നുകളും അതിനുണ്ട്).
ഇതിനുപുറമേയുള്ള Node `fetch` പാത `NODE_EXTRA_CA_CERTS` കൈകാര്യം ചെയ്യുന്നു.

### 3.3 DNS റൂട്ടിങ്

നിങ്ങൾ ഇന്റർസെപ്റ്റ് ചെയ്യാൻ ആഗ്രഹിക്കുന്ന ഓരോ ഏജന്റിന്റെയും API ഹോസ്റ്റ്(കൾ) `127.0.0.1`-ലേക്ക് റിസോൾവ് ചെയ്യണം. Setup Wizard-ൽ ഒരു ഏജന്റിനായി DNS ടോഗിൾ ചെയ്യുമ്പോൾ AgentBridge `/etc/hosts` എൻട്രികൾ സ്വയമേവ കൈകാര്യം ചെയ്യുന്നു.

GitHub Copilot-നുള്ള `/etc/hosts` എൻട്രികളുടെ ഉദാഹരണം:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 മോഡൽ മാപ്പിങ്

സോഴ്സ് → ടാർഗറ്റ് മാപ്പിങ്ങുകൾ നിർവചിക്കാൻ ഓരോ ഏജന്റ് കാർഡിലെയും Model Mapping Table ഉപയോഗിക്കുക:

| സോഴ്സ് മോഡൽ (ഏജന്റിന്റെ നേറ്റീവ്) | ടാർഗറ്റ് മോഡൽ (OmniRoute) |
| --------------------------------- | ------------------------- |
| `gpt-4o`                          | `claude-sonnet-4.7`       |
| `*` (വൈൽഡ്കാർഡ്)                  | `claude-haiku-4.7`        |

വൈൽഡ്കാർഡ് `*` തിരിച്ചറിയപ്പെടാത്ത ഏത് മോഡലിനെയും നിർദ്ദിഷ്ട ടാർഗറ്റിലേക്ക് മാപ്പ് ചെയ്യുന്നു. `agent_bridge_mappings` പട്ടികയിൽ സ്ഥിരമായി സംഭരിക്കുന്നു.

> **നുറുങ്ങ് — ഏജന്റിന്റെ യഥാർത്ഥ മോഡൽ ID-കൾ കണ്ടെത്തുക.** ഒരു IDE അതിന്റെ UI ലേബലുകളിൽ നിന്ന് വ്യത്യസ്തമായതും
> പ്രധാന പതിപ്പുകൾക്കിടയിൽ മാറുന്നതുമായ മോഡൽ പേരുകൾ അയച്ചേക്കാം. ഉദാഹരണത്തിന്, **Antigravity 2**
> നെറ്റ്വർക്കിലൂടെ `gemini-3.1-pro-low`, `gemini-pro-agent`, `gemini-3.1-flash-lite` എന്നിവയാണ് അയയ്ക്കുന്നത് —
> പഴയ ഡോക്യുമെന്റുകളിൽ കാണിച്ചിരിക്കുന്ന `gemini-2.5-pro` അല്ല. പൊരുത്തപ്പെടുന്ന മാപ്പിങ് ഇല്ലാതെ ഒരു ചാറ്റ് അയയ്ക്കുക: MITM
> കൃത്യമായി ലഭിച്ച `model:` ലോഗ് ചെയ്യുകയും അഭ്യർത്ഥന കടത്തിവിടുകയും ചെയ്യും. ആ ലിറ്ററൽ മൂല്യം മാപ്പ് ചെയ്യുക; തുടർന്ന്
> അടുത്ത അഭ്യർത്ഥന ഇന്റർസെപ്റ്റ് ചെയ്ത് നിങ്ങളുടെ ടാർഗറ്റിലേക്ക് റൂട്ട് ചെയ്യപ്പെടും.

### 3.5 അപകടസാധ്യതാ അറിയിപ്പ്

അപ്സ്ട്രീം പ്രൊവൈഡർമാരുമായി ഓതന്റിക്കേറ്റ് ചെയ്യാൻ IDE ഉപയോഗിക്കുന്ന ക്രെഡൻഷ്യലുകൾ (OAuth ടോക്കണുകൾ, API കീകൾ) AgentBridge ഇന്റർസെപ്റ്റ് ചെയ്യുന്നു. ഇവ **ലോഗ് ചെയ്യുന്നതിന് മുമ്പ് മറയ്ക്കപ്പെടുന്നു** (§2.7 കാണുക), എന്നാൽ OmniRoute-ന്റെ MITM ലെയറിന് ദൃശ്യമാണ്. ഓരോ ഏജന്റിന്റെയും ആദ്യ ആക്ടിവേഷനിൽ ഒഴിവാക്കാവുന്ന ഒരു അപകടസാധ്യതാ അറിയിപ്പ് മോഡൽ കാണിക്കും.

### 3.6 പരിപാലനവും ഡയഗ്നോസ്റ്റിക്സും

മുമ്പ് UI ഇല്ലാതിരുന്ന പ്രവർത്തനസംബന്ധിയായ MITM റൂട്ടുകൾ പ്രദർശിപ്പിക്കുന്ന ഒരു **Maintenance & Diagnostics** കാർഡ് (`AgentBridgeMaintenanceCard`, `src/app/(dashboard)/dashboard/tools/agent-bridge/components/`-ൽ) ഡാഷ്ബോർഡ് ലഭ്യമാക്കുന്നു. അതിന്റെ ഉപശീർഷകം: _"ക്യാപ്ചർ പൈപ്പ്ലൈൻ സ്വയം പരിശോധിക്കുക, ശേഷിച്ചിരിക്കുന്ന സിസ്റ്റം നില പഴയപടിയാക്കുക, നിങ്ങളുടെ സജ്ജീകരണം മെഷീനുകൾക്കിടയിൽ മാറ്റുക."_ കാർഡ് ക്ലയന്റ് ഹെൽപ്പറുകൾ `src/lib/inspector/agentBridgeMaintenanceApi.ts`-ലാണ്.

**അനാഥ-അവസ്ഥ ബാനർ:** ക്രാഷ് കാരണം ശേഷിച്ച അവസ്ഥ (DNS സ്പൂഫ് / CA / സിസ്റ്റം പ്രോക്സി) പേജ് കണ്ടെത്തുമ്പോൾ, കാർഡ് ഒരു ആംബർ ബാനർ കാണിക്കുന്നു — _"മുമ്പത്തെ ഒരു സെഷൻ സിസ്റ്റം അവസ്ഥ ശേഷിപ്പിച്ചു (DNS സ്പൂഫ്, CA, അല്ലെങ്കിൽ സിസ്റ്റം പ്രോക്സി). അത് വൃത്തിയാക്കാൻ നന്നാക്കൽ പ്രവർത്തിപ്പിക്കുക."_ — കൂടാതെ **നന്നാക്കുക** ബട്ടൺ ഹൈലൈറ്റ് ചെയ്യുന്നു. `Repair`, ProxyBridge-ന്റെ `--cleanup` ഫ്ലാഗിന്റെ ആപ്ലിക്കേഷൻ-ലെയർ സമാനരൂപമാണ് (ഇത് `src/mitm/manager.ts`-ലെ `repairMitm()`-ലേക്ക് ചുമതല കൈമാറുന്നു).

> ആവർത്തിച്ചുള്ള sudo പ്രോംപ്റ്റുകൾ ഒഴിവാക്കാൻ MITM റൂട്ട് CA നിർത്തൽ/ആരംഭിക്കൽ എന്നിവയ്ക്കിടയിലും ഇൻസ്റ്റാൾ ചെയ്ത നിലയിൽ സൂക്ഷിക്കുന്നു
> (mitmproxy/Charles-ന്റെ അതേ സ്വഭാവം), അതിനാൽ നിർത്തുമ്പോൾ സ്വയമേവ സംഭവിക്കുന്ന ഒന്നിന് പകരം
> അത് നീക്കംചെയ്യുന്നത് വ്യക്തമായ **CA നീക്കംചെയ്യുക** നടപടിയാണ്.

### 3.7 പോർട്ടബിൾ കോൺഫിഗ് ഇമ്പോർട്ട്/എക്സ്പോർട്ട്

ഒരു സജ്ജീകരണം വ്യത്യസ്ത മെഷീനുകളിൽ പുനഃസൃഷ്ടിക്കാൻ കഴിയുന്ന വിധത്തിൽ AgentBridge-ന് **ഓപ്പറേറ്റർക്ക് ക്രമീകരിക്കാവുന്ന** അവസ്ഥയെ പതിപ്പുള്ള JSON ബ്ലോബായി സീരിയലൈസ് ചെയ്യാനാകും. സീരിയലൈസർ `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`) ആണ്; ഇത് `AgentBridgeConfigSchema` ഉപയോഗിച്ച് സാധൂകരിക്കുന്നു.

എക്സ്പോർട്ടിൽ കൃത്യമായി മൂന്ന് ഭാഗങ്ങൾ ഉൾപ്പെടുന്നു (ബിൽറ്റ്-ഇൻ ഡിഫോൾട്ടുകൾ മനഃപൂർവം എക്സ്പോർട്ട് ചെയ്യുന്നില്ല, അതിനാൽ ഇമ്പോർട്ട് ചെയ്യുന്നത് ഒരിക്കലും അവയുടെ പകർപ്പുകൾ സൃഷ്ടിക്കുകയോ അവയുമായി വൈരുധ്യമുണ്ടാക്കുകയോ ചെയ്യില്ല):

| ഫീൽഡ്            | ഉറവിടം                                                             | കുറിപ്പുകൾ                                                           |
| ---------------- | ------------------------------------------------------------------ | -------------------------------------------------------------------- |
| `bypassPatterns` | ഉപയോക്താവ് നിർവചിച്ച ബൈപാസ് പാറ്റേണുകൾ (`agent_bridge_bypass`)     | ഡിഫോൾട്ട് bank/gov/okta പാറ്റേണുകൾ ഒഴിവാക്കപ്പെടുന്നു                |
| `customHosts`    | Traffic Inspector ഇഷ്ടാനുസൃത ഹോസ്റ്റുകൾ (`inspector_custom_hosts`) | ഓരോന്നും: `{ host, kind: "llm"\|"app"\|"custom", label? }`           |
| `agentMappings`  | ഓരോ ഏജന്റിനുമുള്ള മോഡൽ മാപ്പിങ്ങുകൾ (`agent_bridge_mappings`)      | മാപ്പിങ്ങുകളുള്ള ഓരോ ഏജന്റിനും `{ [agentId]: [{ source, target }] }` |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**ഇമ്പോർട്ട് സ്വഭാവം** (`POST /api/tools/agent-bridge/config`): ബൈപാസ് പാറ്റേണുകളും ഓരോ ഏജന്റിനുമുള്ള മാപ്പിങ്ങുകളും **പൂർണമായി മാറ്റിസ്ഥാപിക്കുന്നു**; ഇഷ്ടാനുസൃത ഹോസ്റ്റുകൾ **ഐഡംപൊട്ടന്റായി** ചേർക്കുന്നു (`INSERT OR IGNORE`). ഓരോ വിഭാഗത്തിലും എത്രയെണ്ണം പ്രയോഗിച്ചുവെന്ന് പ്രതികരണം റിപ്പോർട്ട് ചെയ്യുന്നു:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

കോൺഫിഗിൽ **ഉൾപ്പെടാത്തവ**: സെർവർ പ്രവർത്തിക്കുന്ന അവസ്ഥ, സർട്ടിഫിക്കറ്റ് പാത്തുകൾ, ഓരോ ഏജന്റിന്റെയും DNS അവസ്ഥ, അപ്സ്ട്രീം CA പാത്ത്, TPROXY ക്രമീകരണങ്ങൾ — ഇവ പോർട്ടബിൾ മുൻഗണനകളല്ല, മറിച്ച് ഹോസ്റ്റ്/റൺടൈം അവസ്ഥയാണ്.

### സജ്ജീകരണ വിസാർഡ് ഘട്ടങ്ങൾ (ഓരോ ഏജന്റിനും)

ഓരോ ഏജന്റ് കാർഡിലും 3-ഘട്ട സജ്ജീകരണ വിസാർഡ് ഉണ്ട്:

1. **മുൻവ്യവസ്ഥകൾ പരിശോധിക്കുക** — സെർവർ പ്രവർത്തിക്കുന്നുണ്ടോ? സർട്ടിഫിക്കറ്റ് വിശ്വസനീയമാണോ? IDE ഇൻസ്റ്റാൾ ചെയ്തിട്ടുണ്ടോ (സ്വയമേവ കണ്ടെത്തിയോ)?
2. **DNS പ്രവർത്തനക്ഷമമാക്കുക** — `/etc/hosts` എൻട്രികൾ ചേർക്കുന്നു (sudo ആവശ്യമാണ്). ചേർക്കുന്ന വരികൾ ഏതൊക്കെയെന്ന് കൃത്യമായി കാണിക്കുന്നു.
3. **മോഡലുകൾ മാപ്പ് ചെയ്യുക** — ഐച്ഛിക മോഡൽ മാപ്പിംഗ് പട്ടിക. വൈൽഡ്കാർഡുകൾ സ്വീകരിക്കും.

### ഏജന്റ് കണ്ടെത്തൽ

1–8 വരെയുള്ള ഏജന്റുകൾക്കായി, IDE ഇൻസ്റ്റാളേഷൻ സ്വയമേവ കണ്ടെത്താൻ AgentBridge ശ്രമിക്കുന്നു:

```ts
export async function detectAgent(agentId: AgentId): Promise<DetectionResult>;
// നൽകുന്നത്: { installed: boolean, version?: string, path?: string }
```

കണ്ടെത്തലിനായി OS-നിർദ്ദിഷ്ട പാത്തുകളും ബൈനറി പരിശോധനകളും ഉപയോഗിക്കുന്നു (ഉദാ., Copilot-നായി `code --list-extensions | grep github.copilot`, Antigravity-ക്കായി `~/.config/antigravity/`).

### സെൻസിറ്റീവ് ഹോസ്റ്റുകൾക്കുള്ള ബൈപാസ് പട്ടിക

സാമ്പത്തിക സ്ഥാപനങ്ങൾ, OAuth/SSO ദാതാക്കൾ, മറ്റ് സെൻസിറ്റീവ് ഹോസ്റ്റുകൾ എന്നിവ **ഒരിക്കലും ഡീക്രിപ്റ്റ് ചെയ്യപ്പെടുന്നില്ലെന്ന്** ബൈപാസ് പട്ടിക ഉറപ്പാക്കുന്നു. അവയുടെ TLS ട്രാഫിക് സുതാര്യമായ TCP ടണലിലൂടെ കടന്നുപോകുന്നു — OmniRoute-ന് ഒരിക്കലും പ്ലെയിൻടെക്സ്റ്റ് കാണാനാവില്ല.

ഡിഫോൾട്ട് ബൈപാസ് പാറ്റേണുകളിൽ ഉൾപ്പെടുന്നവ:

- `*.bank.*`, `*.gov.*` (സാമ്പത്തികം/സർക്കാർ)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/ഐഡന്റിറ്റി)
- `*.apple.com`, `*.icloud.com` (Apple സിസ്റ്റം സേവനങ്ങൾ)

ഉപയോക്താവ് ചേർത്ത ബൈപാസ് പാറ്റേണുകൾ `agent_bridge_bypass` പട്ടികയിൽ സംഭരിക്കപ്പെടുകയും മറ്റെല്ലാറ്റിനേക്കാളും മുൻഗണന നേടുകയും ചെയ്യുന്നു.

### രഹസ്യ വിവരങ്ങളുടെ മാസ്കിങ്

`src/mitm/maskSecrets.ts`-ൽ നിന്നുള്ള `maskSecrets()` പ്രയോഗിക്കുന്നത്:

- `TrafficBuffer.push()`-നു മുമ്പ് ഓരോ റിക്വസ്റ്റ് ബോഡിയിലും
- ലോഗ് ചെയ്യുന്നതിനോ ബ്രോഡ്കാസ്റ്റ് ചെയ്യുന്നതിനോ മുമ്പ് ഓരോ ഹെഡറിലും

പാറ്റേണുകൾ: `sk-`/`ak-`/`pk-` പ്രിഫിക്സ് ടോക്കണുകൾ, `Bearer` ടോക്കണുകൾ, 40-ഓ അതിലധികമോ പ്രതീകങ്ങളുള്ള പൊതുവായ ടോക്കണുകൾ.

### അപ്സ്ട്രീം CA സർട്ടിഫിക്കറ്റ്

`AGENTBRIDGE_UPSTREAM_CA_CERT` സജ്ജമാക്കിയിരിക്കുമ്പോൾ, സ്റ്റാർട്ടപ്പിൽ ഫയൽ വായിക്കുന്നു. പാത്ത് നിലവിലുണ്ടെങ്കിലും ഫയൽ വായിക്കാൻ കഴിയുന്നില്ലെങ്കിൽ, AgentBridge വ്യക്തമായ ഒരു പിശക് ലോഗ് ചെയ്യുകയും ആരംഭിക്കാൻ വിസമ്മതിക്കുകയും ചെയ്യുന്നു (കോർപ്പറേറ്റ് പരിതസ്ഥിതികളിലെ നിശ്ശബ്ദ TLS പരാജയങ്ങൾ തടയുന്നു).

### അറിയപ്പെടുന്ന പരിമിതികൾ

- **Port 443-ന് പ്രത്യേക അനുമതി ആവശ്യമാണ്**: Linux-ൽ, Node ബൈനറിയിൽ AgentBridge-ന് `setcap 'cap_net_bind_service=+ep'` ആവശ്യമാണ്, അല്ലെങ്കിൽ `authbind` വഴി പ്രവർത്തിപ്പിക്കണം. സജ്ജീകരണ വിസാർഡ് OS-നിർദ്ദിഷ്ട നിർദ്ദേശങ്ങൾ പ്രദർശിപ്പിക്കുന്നു.
- **IDE പുനരാരംഭിക്കേണ്ടതുണ്ട്**: DNS റീഡയറക്ടിന് ശേഷം, പുതിയ ഹോസ്റ്റ് റെസല്യൂഷൻ പ്രാബല്യത്തിൽ വരാൻ IDE പുനരാരംഭിക്കണം.
- **ഹാർഡ്കോഡ് ചെയ്ത OAuth ടോക്കണുകൾ**: ചില ഏജന്റുകൾ (Kiro, Antigravity) OAuth റിഫ്രഷ് ടോക്കണുകൾ ലോക്കലായി സംഭരിക്കുന്നു. AgentBridge-നെ സംബന്ധിച്ചിടത്തോളം ഇവ സുതാര്യമാണ് — ഓരോ റിക്വസ്റ്റിലും അത് Bearer ടോക്കൺ കാണുന്നു; ലോഗ് ചെയ്യുന്നതിന് മുമ്പ് അത് മാസ്ക് ചെയ്യപ്പെടുന്നു.
- **Electron ഫ്രണ്ട്എൻഡുകൾക്ക് `NODE_EXTRA_CA_CERTS` ആവശ്യമാണ്**: ബണ്ടിൽ ചെയ്ത Node/Electron റൺടൈമിൽ ഫ്രണ്ട്എൻഡ് പ്രവർത്തിക്കുന്ന IDE-കൾ OS/NSS ട്രസ്റ്റ് സ്റ്റോർ അവഗണിക്കുന്നു; അതിനാൽ `NODE_EXTRA_CA_CERTS` സജ്ജമാക്കിയ ഷെല്ലിൽനിന്ന് അവ ലോഞ്ച് ചെയ്യണം (§3.2 കാണുക). ഇത് ഇല്ലാത്തപ്പോഴുള്ള ലക്ഷണം: IDE ബാക്ക്എൻഡ് ആധികാരികത ഉറപ്പാക്കുന്നു (MITM-ൽ `200`-കൾ കാണാം), എന്നാൽ UI ലോഗ് ഔട്ട് ആയിത്തന്നെ തുടരുന്നു.
- **ഒരേ IDE-യുടെ ഒന്നിലധികം ഇൻസ്റ്റാളേഷനുകൾ സ്വതന്ത്രമാണ്**: ഒരു സിസ്റ്റം ഇൻസ്റ്റാളും (ഉദാ. `/usr/share/antigravity/antigravity`) ഉപയോക്തൃ-ലോക്കൽ "Full" ഇൻസ്റ്റാളും (ഉദാ. `~/AntigravityIDE_Full/antigravity-ide`) സ്വന്തം റൺടൈമുകളുള്ള വ്യത്യസ്ത പ്രോസസ്സുകളാണ് — ഓരോന്നും CA ഇൻജക്റ്റ് ചെയ്ത് വീണ്ടും ലോഞ്ച് ചെയ്യണം. വീണ്ടും ലോഞ്ച് ചെയ്യുന്നതിനുമുമ്പ്, പ്രവർത്തിക്കുന്നത് ഏതാണെന്ന് അതിന്റെ ബൈനറി പാത്ത് ഉപയോഗിച്ച് തിരിച്ചറിയുക.
- **ഐഡന്റിറ്റി നിർണ്ണയിക്കുന്നത് ഏജന്റിന്റെ സിസ്റ്റം പ്രോംപ്റ്റാണ്, റൂട്ട് ചെയ്ത മോഡലല്ല**: ഒരു ഏജന്റിന്റെ മോഡൽ മറ്റൊരു ദാതാവിലേക്ക് റീമാപ്പ് ചെയ്യുമ്പോൾ, മറുപടി തുടർന്നും ഏജന്റിന്റെ നേറ്റീവ് ഐഡന്റിറ്റി അവകാശപ്പെടുന്നു (ഉദാ. Antigravity "I am powered by Gemini" എന്ന് മറുപടി നൽകുന്നു), കാരണം IDE അത് സിസ്റ്റം പ്രോംപ്റ്റിലേക്ക് ഇൻജക്റ്റ് ചെയ്യുന്നു. മോഡലിനോട് അത് ആരാണെന്ന് ചോദിക്കുന്നതിനുപകരം, യഥാർത്ഥ ബാക്ക്എൻഡ് `call_logs` / `proxy_logs` (`provider`, `model`, `target_format`) എന്നിവയിൽ സ്ഥിരീകരിക്കുക.

## §6 പ്രശ്നപരിഹാരം

### പോർട്ട് 443 വൈരുദ്ധ്യം

മറ്റൊരു പ്രോസസ് ഇതിനകം പോർട്ട് 443-ൽ ലിസൺ ചെയ്യുന്നുണ്ടെങ്കിൽ (വെബ് സെർവർ, VPN മുതലായവ):

```bash
lsof -i :443          # പ്രോസസ് കണ്ടെത്തുക
sudo fuser -k 443/tcp  # നിർബന്ധിച്ച് നിർത്തുക (ശ്രദ്ധയോടെ ഉപയോഗിക്കുക)
```

പകരമായി, AgentBridge ക്രമീകരണങ്ങളിൽ ഒരു പ്രിവിലേജ് ആവശ്യമില്ലാത്ത പോർട്ട് കോൺഫിഗർ ചെയ്ത് `iptables` / `pf` റീഡയറക്ട് നിയമങ്ങൾ സജ്ജീകരിക്കുക.

### സർട്ടിഫിക്കറ്റ് വിശ്വസനീയമല്ല

AgentBridge ആരംഭിച്ചതിന് ശേഷം IDE TLS പിശകുകൾ കാണിക്കുന്നുവെങ്കിൽ:

1. സർട്ടിഫിക്കറ്റ് ഇൻസ്റ്റാൾ ചെയ്തിട്ടുണ്ടെന്ന് സ്ഥിരീകരിക്കുക: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) അല്ലെങ്കിൽ `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. ചില ആപ്പുകൾ അവയുടെ സ്വന്തം ട്രസ്റ്റ് സ്റ്റോർ പരിപാലിക്കുന്നു (Firefox, Linux-ലെ Chrome). "Trust Cert" വീണ്ടും പ്രവർത്തിപ്പിച്ച് NSS/Firefox-നിർദ്ദിഷ്ട സർട്ടിഫിക്കറ്റ് സ്റ്റോർ പരിശോധിക്കുക.
3. വിശ്വസനീയമാക്കിയ ശേഷം IDE പുനരാരംഭിക്കുക — നിലവിൽ നടന്നുകൊണ്ടിരിക്കുന്ന TLS സെഷനുകൾ പഴയ ട്രസ്റ്റ് നിലയാണ് ഉപയോഗിക്കുന്നത്.

### വിശ്വസനീയമായ CA ഉണ്ടായിട്ടും IDE-യിൽ നിന്ന് ലോഗ് ഔട്ട് ആയി / "connection error"

ലക്ഷണം: DNS റീഡയറക്ട് ചെയ്ത് CA വിശ്വസനീയമാക്കിയ ശേഷം, Electron അടിസ്ഥാനമാക്കിയുള്ള ഒരു IDE (ഉദാ. Antigravity)
**ലോഗ് ഔട്ട് ചെയ്ത നിലയിൽ** തുറക്കുകയോ ഓതന്റിക്കേഷൻ/കണക്ഷൻ പിശക് കാണിക്കുകയോ ചെയ്യുന്നു; എന്നാൽ MITM ലോഗിൽ
ബൂട്ട്സ്ട്രാപ്പ് കോളുകൾ (`loadCodeAssist`, `fetchAvailableModels`, …) `200` മടക്കുന്നതായി കാണുന്നു.

കാരണം: IDE-യുടെ **ബണ്ടിൽ ചെയ്ത Node/Electron റൺടൈം OS ട്രസ്റ്റ് സ്റ്റോറിനെ അവഗണിക്കുന്നു**. നേറ്റീവ്
ബാക്കെൻഡ് (ഒരു Go ലാംഗ്വേജ് സെർവർ) OS CA-യെ വിശ്വസിക്കുകയും ഓതന്റിക്കേറ്റ് ചെയ്യുകയും ചെയ്യുന്നു, എന്നാൽ Electron ഫ്രണ്ട്എൻഡ്
അങ്ങനെ ചെയ്യുന്നില്ല — അതിനാൽ UI ഓഫ്ലൈനാണെന്ന് കരുതുന്നു.

പരിഹാരം (രണ്ട് ഘട്ടങ്ങളും): `NODE_EXTRA_CA_CERTS=<ca.crt>` എക്സ്പോർട്ട് ചെയ്യുകയും ഡെസ്ക്ടോപ്പ് ഐക്കണിൽ നിന്നല്ല,
**ആ ഷെല്ലിൽ നിന്ന് IDE വീണ്ടും ആരംഭിക്കുകയും** ചെയ്യുക. ആദ്യം IDE പൂർണ്ണമായി ക്വിറ്റ് ചെയ്യുക — Electron-ന്റെ സിംഗിൾടൺ ലോക്ക് കാരണം
രണ്ടാമത്തെ ലോഞ്ച് നിലവിലുള്ള പ്രോസസിലേക്ക് മാത്രം ഫോക്കസ് ചെയ്യുകയും പുതിയ എൻവയോൺമെന്റ് അവഗണിക്കപ്പെടുകയും ചെയ്യും. §3.2 കാണുക.
ഒരു സ്വതന്ത്ര ഏജന്റ് MITM വഴി പ്രവർത്തിക്കുന്നുവെങ്കിലും അതേ സജ്ജീകരണത്തിൽ IDE
വേരിയന്റ് പരാജയപ്പെടുന്നുവെന്ന് പറയുന്ന നിലവിലുള്ള ഒരു അപ്സ്ട്രീം റിപ്പോർട്ടുമായി ഇത് പൊരുത്തപ്പെടുന്നു.

### DNS പ്രചരിച്ചിട്ടില്ല

`/etc/hosts` അപ്ഡേറ്റ് ചെയ്തിട്ടുണ്ടോയെന്ന് പരിശോധിക്കുക:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

DNS കാഷെ ഫ്ലഷ് ചെയ്യുക:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### IDE കണ്ടെത്തിയില്ല

സ്വയമേവ കണ്ടെത്തൽ സാധാരണ ഇൻസ്റ്റലേഷൻ പാത്തുകൾ ഉപയോഗിക്കുന്നു. കണ്ടെത്തൽ പരാജയപ്പെട്ടെങ്കിലും IDE ഇൻസ്റ്റാൾ ചെയ്തിട്ടുണ്ടെങ്കിൽ:

- IDE ബൈനറി നിലവാരമില്ലാത്ത ഒരു ലൊക്കേഷനിലാണോയെന്ന് പരിശോധിക്കുക
- Setup Wizard തുടർന്നും പ്രവർത്തിക്കും — കണ്ടെത്തൽ പരാജയപ്പെട്ടാൽ ബാഡ്ജിൽ ഇൻസ്റ്റാൾ പാത്ത് കാണിക്കില്ല എന്നുമാത്രം

### ഹാൻഡ്ലർ പിശകുകൾ (അപ്സ്ട്രീം ഫെച്ച് പരാജയപ്പെടുന്നു)

AgentBridge ഇന്റർസെപ്റ്റ് ചെയ്യുന്നുണ്ടെങ്കിലും എല്ലാ അഭ്യർത്ഥനകളും പരാജയപ്പെടുന്നുവെങ്കിൽ:

1. `/dashboard/providers`-ൽ കുറഞ്ഞത് ഒരു പ്രൊവൈഡറെങ്കിലും കണക്റ്റ് ചെയ്തിട്ടുണ്ടെന്ന് സ്ഥിരീകരിക്കുക
2. OmniRoute സെർവർ ലോഗുകൾ പരിശോധിക്കുക: `.env`-ൽ `APP_LOG_LEVEL=debug`
3. `OMNIROUTE_BASE_URL` ശരിയായ റൗട്ടർ എൻഡ്പോയിന്റിലേക്കാണ് ചൂണ്ടുന്നതെന്ന് സ്ഥിരീകരിക്കുക (ഡിഫോൾട്ട്: `http://127.0.0.1:20128`)

## §8 റോഡ്മാപ്പ്

### Trae അന്വേഷണം

Trae താരതമ്യേന പുതിയൊരു AI കോഡിംഗ് അസിസ്റ്റന്റാണ്. ഒരു ഹാൻഡ്ലർ നടപ്പിലാക്കുന്നതിനുമുമ്പ്:

1. VS Code / JetBrains മാർക്കറ്റ്പ്ലേസുകളിലോ ഒരു സ്വതന്ത്ര ആപ്പായോ ബൈനറി/എക്സ്റ്റൻഷൻ തിരിച്ചറിയുക
2. API ഹോസ്റ്റുകളും എൻഡ്പോയിന്റ് ഘടനകളും കണ്ടെത്താൻ mitmproxy ഉപയോഗിച്ച് ട്രാഫിക് ക്യാപ്ചർ ചെയ്യുക
3. ഓതന്റിക്കേഷൻ സംവിധാനം നിർണ്ണയിക്കുക
4. TOS-ഉം API കണ്ടെത്താനാകുന്ന ശേഷിയും അടിസ്ഥാനമാക്കി മുന്നോട്ടുപോകണോ വേണ്ടയോ എന്ന് വിലയിരുത്തുക

അന്വേഷണം പൂർത്തിയാകുന്നതുവരെ, ഡാഷ്ബോർഡിലെ Trae കാർഡിൽ "സാധ്യത റിപ്പോർട്ട് ചെയ്യുക" എന്ന ലിങ്കിനൊപ്പം "അന്വേഷണത്തിലാണ്" എന്ന ബാഡ്ജ് കാണിക്കും. `src/mitm/handlers/trae.ts`-ലെ ഹാൻഡ്ലർ സ്റ്റബ് ഘടനാബദ്ധമായ `ഇതുവരെ നടപ്പിലാക്കിയിട്ടില്ല` പിശക് എറിയുന്നു.

### ബാക്ക്ലോഗ് ഏജന്റുകൾ (MITM ആവശ്യമാണ് — ഇഷ്ടാനുസൃത base URL പിന്തുണയില്ല)

താഴെപ്പറയുന്ന ടൂളുകൾ അവയുടെ നിലവിലെ പതിപ്പുകളിൽ ഇഷ്ടാനുസൃത base URL-കൾ പിന്തുണയ്ക്കുന്നില്ല; അതിനാൽ MITM മാത്രമാണ് ഇന്റർസെപ്ഷനുള്ള ഏക മാർഗം. പ്രായോഗികതാ വിലയിരുത്തൽ തീർപ്പാകാതെ കിടക്കുന്നു:

- **Windsurf** (Codeium/Cognition)
- **Amp** (Sourcegraph)
- **Amazon Q / Kiro CLI** (AWS Bedrock — Kiro IDE-യിൽ നിന്ന് വേറിട്ടത്)
- **Cowork** (Anthropic ഡെസ്ക്ടോപ്പ്)

കുറിപ്പ്: GitHub Copilot CLI ≥v1.0.19 `COPILOT_PROVIDER_BASE_URL` പിന്തുണയ്ക്കുന്നു — ആ ടൂളിനായി MITM-ന് പകരം നേരിട്ടുള്ള കോൺഫിഗറേഷൻ ഉപയോഗിക്കുക.
