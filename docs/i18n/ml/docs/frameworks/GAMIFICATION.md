പ്ലാറ്റ്ഫോമുമായി ഇടപഴകുന്നതിന് ഉപയോക്താക്കൾക്ക് പ്രതിഫലം നൽകുന്ന, ലോക്കൽ-ഫസ്റ്റ് ഗെയിമിഫിക്കേഷൻ പാളി OmniRoute-ൽ ഉൾപ്പെടുന്നു — അഭ്യർത്ഥനകൾ നടത്തുക, പ്രൊവൈഡറുകൾ മാറുക, കോമ്പോകൾ സൃഷ്ടിക്കുക, ടോക്കണുകൾ പങ്കിടുക, കമ്മ്യൂണിറ്റിയിലേക്ക് സംഭാവന ചെയ്യുക എന്നിവയ്ക്ക്. എല്ലാ സ്റ്റേറ്റും
SQLite-ലാണ് നിലനിൽക്കുന്നത്; കമ്മ്യൂണിറ്റി സെർവറുകളുമായുള്ള ഫെഡറേഷൻ ഓപ്റ്റ്-ഇൻ അടിസ്ഥാനത്തിലുള്ളതും പുഷ് അധിഷ്ഠിതവുമാണ്.

**ഹോട്ട് പാത്തിൽ ഒട്ടും ലേറ്റൻസി ഇല്ലാത്ത** രീതിയിലാണ് സിസ്റ്റം രൂപകൽപ്പന ചെയ്തിരിക്കുന്നത് — ഗെയിമിഫിക്കേഷൻ
ഇവന്റുകൾ റിക്വസ്റ്റ് പൈപ്പ്ലൈനിൽ നിന്ന് ഫയർ-ആൻഡ്-ഫോർഗെറ്റ് രീതിയിൽ ഡിസ്പാച്ച് ചെയ്യപ്പെടുന്നു, കൂടാതെ അവ ഒരിക്കലും
LLM റെസ്പോൺസിനെ തടയുന്നില്ല.

## അവലോകനം

### ഉദ്ദേശ്യം

ദൃശ്യമായ പുരോഗതി (XP,
ലെവലുകൾ, ബാഡ്ജുകൾ), സോഷ്യൽ പ്രൂഫ് (ലീഡർബോർഡുകൾ), സാമ്പത്തിക പ്രോത്സാഹനങ്ങൾ (ടോക്കൺ
പങ്കിടൽ, ഇൻവൈറ്റ് പ്രതിഫലങ്ങൾ) എന്നിവ നൽകിക്കൊണ്ട് ഉപയോക്തൃ ഇടപഴകലും നിലനിർത്തലും വർധിപ്പിക്കുക.

### വ്യാപ്തി

### രൂപകൽപ്പനാ തത്വങ്ങൾ

1. **ലോക്കൽ-ഫസ്റ്റ്** — എല്ലാ സ്റ്റേറ്റും SQLite-ൽ; ബാഹ്യ സേവനങ്ങളൊന്നും ആവശ്യമില്ല.
2. **നോൺ-ബ്ലോക്കിങ്** — ഇവന്റുകൾ ഫയർ-ആൻഡ്-ഫോർഗെറ്റ് രീതിയിലാണ്; ഗെയിമിഫിക്കേഷൻ ലോജിക് കാരണം LLM റെസ്പോൺസ് പാത്ത്
   ഒരിക്കലും വൈകില്ല.
3. **സെർവർ-ഓതറിറ്റേറ്റീവ്** — XP സെർവർ-സൈഡിൽ മാത്രമാണ് കണക്കാക്കുന്നത്; ക്ലയന്റുകൾക്ക്
   സ്കോറുകൾ കൃത്രിമമായി വർധിപ്പിക്കാൻ കഴിയില്ല.
4. **സ്വകാര്യതയെ മാനിക്കുന്നത്** — ലീഡർബോർഡ് പങ്കാളിത്തം ഓപ്റ്റ്-ഇൻ ആണ്; ഉപയോക്താക്കൾക്ക്
   അവരുടെ പ്രൊഫൈൽ മറയ്ക്കാം.
5. **ഫെഡറേഷൻ-റെഡി** — കമ്മ്യൂണിറ്റി സെർവറുകൾക്ക് സൈൻ ചെയ്ത API വഴി സ്കോറുകൾ പുഷ് ചെയ്യാം;
   സിങ്ക് ഓവർറൈറ്റ് രീതിയിലാണ്, അഡിറ്റീവ് അല്ല.

### റിവാർഡ് നൽകുന്ന പ്രവാഹം

```typescript
export async function awardXp(
  apiKeyId: string,
  action: XpAction,
  metadata?: Record<string, unknown>
): Promise<{ xp: number; level: number; title: string; levelUp: boolean }>;
```

1. XP തുക ലഭിക്കാൻ `XP_REWARDS[action]` പരിശോധിക്കുക.
2. `checkRateLimit()`-ലൂടെ കടത്തിവിടുക (ചതി തടയൽ: ഓരോ കീയ്ക്കും പരമാവധി 1000 XP/മിനിറ്റ്).
3. ഒരു ട്രാൻസാക്ഷൻ തുറക്കുക:
   - നിലവിലെ `user_levels` റോ വായിക്കുക.
   - XP ചേർക്കുക; `levelFromXp(totalXp)` വഴി ലെവൽ വീണ്ടും കണക്കാക്കുക.
   - ലെവൽ മാറിയെങ്കിൽ, `levelUp = true` ആയി സജ്ജമാക്കുക.
   - `user_levels` റോ അപ്ഡേറ്റ് ചെയ്യുക.
   - `xp_audit_log`-ലേക്ക് ചേർക്കുക.
4. ഫലം മടക്കിനൽകുക. കോളർ അറിയിപ്പുകൾ കൈകാര്യം ചെയ്യുന്നു.

### സഹായി: `levelFromXp(totalXp)`

ആകെ XP `totalXp`-യെ കവിയുന്നതുവരെ `xp_for_level(n)` കൂട്ടിക്കൊണ്ട് 1..100 ലെവലുകളിലൂടെ ആവർത്തിക്കുന്നു.
പരിധി കൈവരിച്ചിട്ടുള്ളതിൽ ഏറ്റവും ഉയർന്ന ലെവൽ മടക്കിനൽകുന്നു.
ഇത് O(100) ആണ് — ലെവലുകളുടെ പരമാവധി 100 ആയതിനാൽ സ്വീകാര്യമാണ്.

### വിലയിരുത്തൽ പ്രവാഹം

```
emitGamificationEvent(event)
  → evaluateBadges(apiKeyId, event)
    → getBadgeDefinitions()           # എല്ലാ നിർവചനങ്ങളും
    → getUserBadges(apiKeyId)         # ഇതിനകം നേടിയവ (ഒഴിവാക്കുക)
    → നേടാത്ത ഓരോ ബാഡ്ജിനും:
       → matchesCriteria(badge, event, userState)
       → പൊരുത്തമുണ്ടെങ്കിൽ: awardBadge(apiKeyId, badgeId)
         → അറിയിപ്പ് പേലോഡ് മടക്കിനൽകുക
```

വിലയിരുത്തൽ **ഇവന്റ്-ഡ്രിവൺ** ആണ് — ഓരോ ഗെയിമിഫിക്കേഷൻ ഇവന്റിന് ശേഷവും ഇത് പ്രവർത്തിക്കുന്നു, എന്നാൽ ഇവന്റ് പ്രവർത്തനവുമായി `criteria.type` പൊരുത്തപ്പെടുന്ന ബാഡ്ജുകൾ മാത്രമേ പരിശോധിക്കൂ. ഇത് വിലയിരുത്തൽ വേഗത്തിലാക്കുന്നു (മിക്ക ഇവന്റുകൾക്കും < 5ms).

### `matchesCriteria(badge, event, userState)`

| മാനദണ്ഡ തരം    | പരിശോധന                                                         |
| -------------- | --------------------------------------------------------------- |
| `action_count` | `getActionCount(apiKeyId, action) >= count`                     |
| `streak`       | `getCurrentStreak(apiKeyId) >= days`                            |
| `unique_count` | `getUniqueCount(apiKeyId, field) >= n`                          |
| `rank`         | `getRank(apiKeyId, scope) <= n`                                 |

## സ്ട്രീക്ക് ട്രാക്കർ

**ഫയൽ:** `src/lib/gamification/streaks.ts`

### ഡാറ്റാ മോഡൽ

സ്ട്രീക്കുകൾ `key_value` പട്ടികയിൽ (പങ്കിട്ട യൂട്ടിലിറ്റി പട്ടിക) നെയിംസ്പേസ് ചെയ്ത കീകൾക്ക് കീഴിൽ സംഭരിക്കുന്നു:

| കീ                            | മൂല്യം                           | വിവരണം                |
| ----------------------------- | -------------------------------- | --------------------- |
| `gamification:streak:{keyId}` | `{current},{longest},{lastDate}` | സജീവ സ്ട്രീക്ക് ഡാറ്റ |

### ലോജിക്

```typescript
export async function updateStreak(
  apiKeyId: string
): Promise<{ current: number; longest: number; milestone: boolean }>;
```

1. `key_value`-ൽ നിന്ന് സ്ട്രീക്ക് റെക്കോർഡ് വായിക്കുക.
2. `{current}`, `{longest}`, `{lastDate}` (ISO തീയതി സ്ട്രിംഗ്) എന്നിവ പാർസ് ചെയ്യുക.
3. `lastDate === today` ആണെങ്കിൽ — മാറ്റമില്ല (ഇന്ന് ഇതിനകം കണക്കാക്കിയിട്ടുണ്ട്).
4. `lastDate === yesterday` ആണെങ്കിൽ — `current` വർധിപ്പിക്കുക; ആവശ്യമെങ്കിൽ `longest` അപ്ഡേറ്റ് ചെയ്യുക.
5. `lastDate < yesterday` ആണെങ്കിൽ — `current = 1` ആയി പുനഃസജ്ജമാക്കുക (സ്ട്രീക്ക് മുറിഞ്ഞു).
6. അപ്ഡേറ്റ് ചെയ്ത റെക്കോർഡ് എഴുതുക.
7. നാഴികക്കല്ലുകൾ പരിശോധിക്കുക: 7, 14, 30, 60, 90, 180, 365 ദിവസങ്ങൾ. ഏതെങ്കിലും കടന്നിട്ടുണ്ടെങ്കിൽ,
   `milestone = true` ആയി സജ്ജമാക്കുക (കോളർ XP നൽകുകയും ബാഡ്ജുകൾ പരിശോധിക്കുകയും ചെയ്യും).

### പ്രത്യേക സാഹചര്യങ്ങൾ

- **സമയമേഖല**: സ്ട്രീക്കുകൾ UTC തീയതികൾ ഉപയോഗിക്കുന്നു (`new Date().toISOString().slice(0, 10)`).
  ഇത് മനഃപൂർവമാണ് — ഒരൊറ്റ കാനോനിക്കൽ സമയമേഖല ഉപയോഗിക്കുന്നത് സമയമേഖലകൾ മാറിമാറി ഉപയോഗിച്ചുള്ള
  ദുരുപയോഗം തടയുന്നു.
- **പുതിയ ഉപയോക്താക്കൾ**: സ്ട്രീക്ക് റെക്കോർഡ് നിലവിലില്ല; ആദ്യ അഭ്യർത്ഥന
  `current=1, longest=1, lastDate=today` മൂല്യങ്ങളോടെ അത് സൃഷ്ടിക്കുന്നു.
- **ഒരു ദിവസത്തെ ഒന്നിലധികം അഭ്യർത്ഥനകൾ**: UTC ദിവസത്തിലെ ആദ്യ അഭ്യർത്ഥന മാത്രമാണ്
  സ്ട്രീക്ക് വർധിപ്പിക്കുന്നത്.

## ടോക്കൺ പങ്കിടൽ

**ഫയൽ:** `src/lib/gamification/sharing.ts`

### ഡബിൾ-എൻട്രി ലെഡ്ജർ

ഓരോ കൈമാറ്റവും `token_ledger`-ൽ രണ്ട് വരികൾ സൃഷ്ടിക്കുന്നു:

| വരി        | `from_key_id`     | `to_key_id`       | `amount` |
| ---------- | ----------------- | ----------------- | -------- |
| ഡെബിറ്റ്   | അയച്ചയാൾ          | സ്വീകരിക്കുന്നയാൾ | +amount  |
| ക്രെഡിറ്റ് | സ്വീകരിക്കുന്നയാൾ | അയച്ചയാൾ          | -amount  |

കാത്തിരിക്കൂ — പിന്തുടരുന്ന രീതി ഇതാണ്:

| വരി         | `from_key_id`     | `to_key_id`       | `amount` | അർത്ഥം                                            |
| ----------- | ----------------- | ----------------- | -------- | ------------------------------------------------- |
| അയയ്ക്കൽ    | അയച്ചയാൾ          | സ്വീകരിക്കുന്നയാൾ | +amount  | അയച്ചയാളിൽ നിന്നുള്ള പുറത്തേക്കുള്ള ഒഴുക്ക്       |
| സ്വീകരിക്കൽ | സ്വീകരിക്കുന്നയാൾ | അയച്ചയാൾ          | +amount  | സ്വീകരിക്കുന്നയാളിലേക്കുള്ള അകത്തേക്കുള്ള ഒഴുക്ക് |

ബാലൻസ് ഇങ്ങനെ കണക്കാക്കുന്നു:

```sql
SELECT
  COALESCE(SUM(CASE WHEN to_key_id = ? THEN amount ELSE 0 END), 0)
  - COALESCE(SUM(CASE WHEN from_key_id = ? THEN amount ELSE 0 END), 0)
  AS balance
FROM token_ledger
WHERE from_key_id = ? OR to_key_id = ?
```

### കൈമാറ്റ പ്രവാഹം

```typescript
export async function transferTokens(
  fromKeyId: string,
  toKeyId: string,
  amount: number,
  idempotencyKey: string
): Promise<{ success: boolean; balance: number }>;
```

1. **സാധൂകരിക്കുക**: `amount > 0`, `fromKeyId !== toKeyId`.
2. **ഐഡംപൊട്ടൻസി**: ലെഡ്ജറിൽ `idempotency_key` ഇതിനകം നിലവിലുണ്ടോയെന്ന് പരിശോധിക്കുക.
   ഉണ്ടെങ്കിൽ, കാഷ് ചെയ്ത ഫലം മടക്കിനൽകുക.
3. **ട്രാൻസാക്ഷൻ** (ഒരൊറ്റ SQLite ട്രാൻസാക്ഷൻ):
   a. അയച്ചയാളുടെ ബാലൻസ് കണക്കാക്കുക.
   b. `balance < amount` ആണെങ്കിൽ, നിർത്തലാക്കുക (മതിയായ ഫണ്ട് ഇല്ല).
   c. അയയ്ക്കൽ വരി ചേർക്കുക (`from=sender,` മടക്കിനൽകുക.

### നിരക്ക് പരിമിതപ്പെടുത്തൽ

- ഓരോ API കീയിലും മിനിറ്റിൽ പരമാവധി 10 കൈമാറ്റങ്ങൾ.
- ഒരൊറ്റ കൈമാറ്റത്തിൽ പരമാവധി 10,000 ടോക്കണുകൾ.
- ഓരോ API കീയിലും പ്രതിദിനം പരമാവധി 100,000 ടോക്കണുകൾ കൈമാറാം.

## ക്ഷണിക്കൽ & ടോക്കണുകൾ റിഡീം ചെയ്യൽ

**ഫയൽ:** `src/lib/gamification/invites.ts`

### കോഡ് ഫോർമാറ്റ്

- **കോഡ്**: 8 പ്രതീകങ്ങളുള്ള ആൽഫാന്യൂമെറിക് കോഡ് (ഉദാ., `A3K9-X7M2`), മനുഷ്യർക്ക് വായിക്കാവുന്നത്,
  ഉപയോക്താവിന് പ്രദർശിപ്പിക്കുന്നു.
- **ടോക്കൺ**: 32-ബൈറ്റ് റാൻഡം ടോക്കൺ, SHA-256 ഹാഷായി സംഭരിക്കുന്നു.
  പ്രോഗ്രാമാറ്റിക് റിഡംപ്ഷനായി ഉപയോഗിക്കുന്നു (ഉദാ., URL ലിങ്കുകൾ).

### സംഭരണം

| കോളം         | മൂല്യം                                |
| ------------ | ------------------------------------- |
| `code`       | `A3K9X7M2` (അതുല്യം, ഇൻഡക്സ് ചെയ്തത്) |
| `token_hash` | SHA-256(raw_token)                    |

സൃഷ്ടിക്കുന്ന സമയത്ത് റോ ടോക്കൺ കൃത്യമായി ഒരിക്കൽ മാത്രം ഉപയോക്താവിന് മടക്കിനൽകുന്നു. OmniRoute
അത് പിന്നീട് ഒരിക്കലും സംഭരിക്കുകയോ പ്രദർശിപ്പിക്കുകയോ ചെയ്യുന്നില്ല — ഹാഷ് മാത്രമാണ് നിലനിൽക്കുന്നത്.

### സ്വയം-റഫറൽ തടയൽ

ഒരു ഉപയോക്താവ് ഒരു കോഡ് റിഡീം ചെയ്യുമ്പോൾ, സിസ്റ്റം ഇനിപ്പറയുന്നവ പരിശോധിക്കുന്നു:

1. കോഡ് മറ്റൊരു `api_key_id`-യുടേതാണ്.
2. റിഡീം ചെയ്യുന്ന ഉപയോക്താവ് ഇതേ
   റഫററിൽ നിന്നുള്ള ഏതെങ്കിലും കോഡ് മുമ്പ് റിഡീം ചെയ്തിട്ടില്ല (`invite_tokens` + റിഡംപ്ഷൻ ലോഗിൽ ജോയിൻ ചെയ്യുന്നു).

ഏതെങ്കിലും പരിശോധന പരാജയപ്പെട്ടാൽ, വ്യക്തമായ ഒരു പിശക് സന്ദേശത്തോടെ റിഡംപ്ഷൻ നിരസിക്കുന്നു.

### കാലഹരണപ്പെടലും പരിധികളും

- ഡിഫോൾട്ട് `max_uses`: 10 (സൃഷ്ടിക്കുമ്പോൾ കോൺഫിഗർ ചെയ്യാവുന്നത്).
- ഡിഫോൾട്ട് `expires_at`: സൃഷ്ടിച്ചതിന് ശേഷം 30 ദിവസം.
- കാലഹരണപ്പെട്ടതോ ഉപയോഗപരിധി എത്തിയതോ ആയ കോഡുകൾ HTTP 410 Gone മടക്കിനൽകുന്നു.

## കമ്മ്യൂണിറ്റി സെർവർ ഫെഡറേഷൻ

**ഫയൽ:** `src/lib/gamification/servers.ts`

### കണക്റ്റ് ചെയ്യൽ

റിമോട്ട് സെർവർ നൽകുന്ന ഒരു ഇൻവൈറ്റ് ടോക്കൺ വഴിയാണ് കമ്മ്യൂണിറ്റി സെർവർ രജിസ്റ്റർ ചെയ്യുന്നത്. ലോക്കൽ ഇൻസ്റ്റൻസ്:

1. ഇൻവൈറ്റ് ടോക്കൺ സ്വീകരിക്കുന്നു (ഉദാ., ഡാഷ്ബോർഡിൽ പേസ്റ്റ് ചെയ്തത്).
2. ടോക്കൺ സാധൂകരിക്കാനും നിലവിലെ ലീഡർബോർഡ് ലഭ്യമാക്കാനും റിമോട്ട് സെർവറിലെ `POST /api/gamification/federation/leaderboard` കോൾ ചെയ്യുന്നു.
3. `status: connected` സഹിതം സെർവർ റെക്കോർഡ് സംഭരിക്കുന്നു.

### സമന്വയ മാതൃക

ഫെഡറേഷൻ അഡിറ്റീവ് സമന്വയമല്ല, **ഓവർറൈറ്റ് സമന്വയമാണ്** ഉപയോഗിക്കുന്നത്:

```
ലോക്കൽ ഇൻസ്റ്റൻസ്                കമ്മ്യൂണിറ്റി സെർവർ
     │                              │
     ├── സ്കോർ പുഷ് ചെയ്യുക ───────►│  POST /federation/score
     │   { api_key_id, score }      │  (സെർവർ ടോക്കൺ ഹാഷ് സാധൂകരിക്കുന്നു)
     │                              │
     ├── ലീഡർബോർഡ് പുൾ ചെയ്യുക ───►│  GET /federation/leaderboard
     │◄── മികച്ച-N എൻട്രികൾ ────────┤  (ലോക്കൽ കാഷ് ഓവർറൈറ്റ് ചെയ്യുന്നു)
     │                              │
     └── ഹെൽത്ത് പരിശോധന ─────────►│  GET /federation/health
         (ഓരോ 60s-ലും, സമയപരിധി 5s) │
```

### പ്രാമാണീകരണം

ഫെഡറേഷൻ അഭ്യർത്ഥനകളിൽ ഇവ ഉൾപ്പെടുന്നു:

```
Authorization: Bearer <raw_token>
X-Federation-Version: 1
```

റിമോട്ട് സെർവർ ടോക്കൺ ഹാഷ് ചെയ്യുകയും അതുമായി പൊരുത്തപ്പെടുന്ന `community_servers` വരി കണ്ടെത്തുകയും ചെയ്യുന്നു. സംഭരിച്ച ഹാഷ് കൈമാറുന്നത് ഇത് ഒഴിവാക്കുന്നു.

### ഹെൽത്ത് നിരീക്ഷണം

ഓരോ സെർവർ റെക്കോർഡും ഇവ ട്രാക്ക് ചെയ്യുന്നു:

| ഫീൽഡ്       | വിവരണം                                           |
| ----------- | ------------------------------------------------ |
| `status`    | `connected`, `degraded`, `unreachable`           |
| `last_sync` | അവസാനം വിജയിച്ച സമന്വയത്തിന്റെ ISO ടൈംസ്റ്റാമ്പ് |
| `failures`  | തുടർച്ചയായ ഹെൽത്ത് പരിശോധനാ പരാജയങ്ങൾ            |

തുടർച്ചയായ 5 പരാജയങ്ങൾക്കുശേഷം സ്റ്റാറ്റസ് `unreachable` എന്നതിലേക്ക് മാറുകയും, മാനുവൽ ഹെൽത്ത് പരിശോധന വിജയിക്കുന്നതുവരെ സമന്വയം താൽക്കാലികമായി നിർത്തുകയും ചെയ്യുന്നു.

## തട്ടിപ്പ്-പ്രതിരോധം

**ഫയൽ:** `src/lib/gamification/antiCheat.ts`

### സെർവർ-സൈഡ് സ്കോറിംഗ്

എല്ലാ XP കണക്കുകൂട്ടലുകളും `src/lib/gamification/xp.ts`-ലാണ് നടക്കുന്നത്. ക്ലയന്റുകൾ ഒരിക്കലും സ്കോർ സമർപ്പിക്കുന്നില്ല — അവർ പ്രവർത്തനങ്ങൾ സമർപ്പിക്കുകയും സെർവർ XP കണക്കാക്കുകയും ചെയ്യുന്നു. `leaderboard.score` കോളത്തിൽ സെർവർ-സൈഡ് കോഡിന് മാത്രമേ എഴുതാൻ കഴിയൂ.

### നിരക്ക് പരിമിതപ്പെടുത്തൽ

| പരിധി                           | മൂല്യം  | വ്യാപ്തി          |
| ------------------------------- | ------- | ----------------- |
| മിനിറ്റിലെ പരമാവധി XP           | 1,000   | ഓരോ API കീക്കും   |
| മിനിറ്റിലെ പരമാവധി ട്രാൻസ്ഫറുകൾ | 10      | ഓരോ API കീക്കും   |
| പരമാവധി ട്രാൻസ്ഫർ തുക           | 10,000  | ഓരോ ട്രാൻസ്ഫറിനും |
| പരമാവധി പ്രതിദിന ട്രാൻസ്ഫറുകൾ   | 100,000 | ഓരോ API കീക്കും   |

നിരക്ക് പരിധികൾ ഇൻ-മെമ്മറി സ്ലൈഡിംഗ് വിൻഡോ ഉപയോഗിക്കുന്നു (`open-sse/services/`-ലെ `RateLimitManager`-ന്റെ അതേ പാറ്റേൺ). പ്രോസസ്സ് പുനരാരംഭിക്കുകയാണെങ്കിൽ SQLite പിന്തുണയുള്ള കൗണ്ടറുകളിലേക്ക് ഫാൾബാക്ക് ചെയ്യുന്നു.

### Z-സ്കോർ അസാധാരണത്വ കണ്ടെത്തൽ

ഓരോ API കീക്കുമായി, മണിക്കൂറിൽ നേടിയ XP-യുടെ റോളിംഗ് 7-ദിവസ വിൻഡോ സിസ്റ്റം പരിപാലിക്കുന്നു. ഓരോ XP അവാർഡിലും:

1. ഉപയോക്താവിന്റെ നിലവിലെ മണിക്കൂർ XP നിരക്ക് കണക്കാക്കുക.
2. പോപ്പുലേഷൻ ശരാശരിയും സ്റ്റാൻഡേർഡ് ഡീവിയേഷനും കണക്കാക്കുക.
3. `z = (user_rate - mean) / stddev` കണക്കാക്കുക.
4. `z > 3.0` (3 സ്റ്റാൻഡേർഡ് ഡീവിയേഷനുകൾ) ആണെങ്കിൽ, അസാധാരണത്വമായി ഫ്ലാഗ് ചെയ്യുക.

അസാധാരണത്വങ്ങൾ `action = 'anomaly_detected'` സഹിതം `xp_audit_log`-ൽ ലോഗ് ചെയ്യുകയും അഡ്മിൻ ഡാഷ്ബോർഡിൽ പ്രദർശിപ്പിക്കുകയും ചെയ്യുന്നു.

### ഓഡിറ്റ് ട്രെയിൽ

ഓരോ XP അവാർഡും, ട്രാൻസ്ഫറും, ബാഡ്ജ് നേട്ടവും, അസാധാരണത്വ കണ്ടെത്തലും താഴെപ്പറയുന്നവ സഹിതം `xp_audit_log`-ൽ ലോഗ് ചെയ്യുന്നു:

| ഫീൽഡ്        | വിവരണം                                                 |
| ------------ | ------------------------------------------------------ |
| `api_key_id` | ആര്                                                    |
| `action`     | എന്താണ് സംഭവിച്ചത് (xp_award, transfer, anomaly, …)    |
| `xp_awarded` | തുക (XP ഇതര ഇവന്റുകൾക്ക് 0)                            |
| `metadata`   | സന്ദർഭം ഉൾക്കൊള്ളുന്ന JSON (പ്രവർത്തന തരം, ലക്ഷ്യം, …) |
| `created_at` | എപ്പോൾ (ISO 8601)                                      |

അഡ്മിൻമാർക്ക് `GET /api/gamification/anomalies` വഴി പൂർണ്ണ ഓഡിറ്റ് ട്രെയിൽ ക്വറി ചെയ്യാൻ കഴിയും.

## API റൂട്ടുകൾ

എല്ലാ റൂട്ടുകളും സ്റ്റാൻഡേർഡ് OmniRoute മാതൃക പിന്തുടരുന്നു:

```
റൂട്ട് → CORS പ്രീഫ്ലൈറ്റ് → ബോഡി സാധൂകരണം (Zod) → പ്രാമാണീകരണം (extractApiKey)
  → ഹാൻഡ്ലർ
```

### എൻഡ്പോയിന്റുകൾ

| രീതി   | പാത്ത്                                     | വിവരണം                                          | പ്രാമാണീകരണം |
| ------ | ------------------------------------------ | ----------------------------------------------- | ------------ |
| GET    | `/api/gamification/leaderboard`            | ലീഡർബോർഡ് നേടുക (വ്യാപ്തി, കാലയളവ്, പേജിനേഷൻ)   | ഐച്ഛികം      |
| POST   | `/api/gamification/leaderboard`            | ലീഡർബോർഡ് കാഷ് നിർബന്ധമായി പുതുക്കുക            | ആവശ്യമാണ്    |
| GET    | `/api/gamification/stream`                 | SSE തത്സമയ ലീഡർബോർഡ് അപ്ഡേറ്റുകൾ                | ഐച്ഛികം      |

## പൈപ്പ്ലൈൻ സംയോജനം

### സംയോജന പോയിന്റ്

`open-sse/handlers/chatCore.ts`-ലെ റിക്വസ്റ്റ് പൈപ്പ്ലൈനിലെ ഒരൊറ്റ പോയിന്റിൽ
ഗെയിമിഫിക്കേഷൻ ഹുക്ക് ചെയ്യുന്നു:

```typescript
// പ്രതികരണം ക്ലയന്റിലേക്ക് അയച്ചതിനുശേഷം:
setImmediate(() => {
  emitGamificationEvent({
    type: "request.completed",
    apiKeyId,
    metadata: {
      provider: selectedProvider,
      model: selectedModel,
      comboId: resolvedCombo?.id,
      compressionUsed: compressionStats?.applied,
      skillUsed: skillExecution?.name,
    },
  }).catch(() => {
    // ഫയർ-ആൻഡ്-ഫോർഗെറ്റ്: ലോഗ് ചെയ്യുക, എന്നാൽ ഒരിക്കലും ക്ലയന്റിലേക്ക് പ്രചരിപ്പിക്കരുത്
  });
});
```

### ഇവന്റ് തരങ്ങൾ

| ഇവന്റ് തരം          | എപ്പോൾ എമിറ്റ് ചെയ്യുന്നു                               |
| ------------------- | ------------------------------------------------------- |

| `provider.switch`   | പ്രൊവൈഡർ മാറിയപ്പോൾ (കോംബോ ഫോൾബാക്കും കണക്കാക്കും)      |

| `model.first_use`   | കഴിഞ്ഞ 7 ദിവസത്തിനിടെ ഉപയോഗിക്കാത്ത മോഡൽ ഉപയോഗിച്ചപ്പോൾ |

### നോൺ-ബ്ലോക്കിംഗ് ഉറപ്പ്

`setImmediate` + `.catch(() => {})` പാറ്റേൺ ഇനിപ്പറയുന്നവ ഉറപ്പാക്കുന്നു:

1. ഗെയിമിഫിക്കേഷൻ പ്രവർത്തിക്കുന്നതിന് മുമ്പ് പ്രതികരണം പൂർണ്ണമായി അയച്ചിരിക്കും.
2. ഗെയിമിഫിക്കേഷൻ പിശകുകൾ ഒരിക്കലും ക്ലയന്റിന് ദൃശ്യമാകില്ല.
3. ഇവന്റ് പ്രോസസ്സിംഗ് ഇൻലൈനായല്ല, അടുത്ത മൈക്രോടാസ്കിൽ പ്രവർത്തിക്കും.

### പ്രാമാണീകരണ ആവശ്യകതകൾ

- **പൊതുവായത്** (പ്രാമാണീകരണം ആവശ്യമില്ല): `GET /leaderboard`, `GET /stream` (വായിക്കാൻ മാത്രം കഴിയുന്ന
  ലീഡർബോർഡുകൾ).
- **API കീ ആവശ്യമാണ്**: എല്ലാ എഴുത്ത് പ്രവർത്തനങ്ങൾക്കും, പ്രൊഫൈലിനും, കൈമാറ്റങ്ങൾക്കും, ക്ഷണങ്ങൾക്കും.
- **അഡ്മിന് മാത്രം**: അനോമലി ഡാഷ്ബോർഡ്, ഓഡിറ്റ് ലോഗ് വ്യൂവർ.
- **ഫെഡറേഷൻ**: `Authorization`
  ഹെഡറിൽ റോ ടോക്കൺ ഉപയോഗിക്കുന്ന പ്രത്യേക പ്രാമാണീകരണ പാത; സംഭരിച്ചിരിക്കുന്ന SHA-256 ഹാഷുമായി താരതമ്യം ചെയ്ത് സാധുത പരിശോധിക്കുന്നു.
