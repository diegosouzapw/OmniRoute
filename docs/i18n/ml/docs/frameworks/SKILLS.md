> **അവസാനം പുതുക്കിയത്:** 2026-06-28 — v3.8.40

ഫയൽസിസ്റ്റം വായനയും HTTP അഭ്യർത്ഥനകളും മുതൽ സാൻഡ്ബോക്സ് ചെയ്ത കോഡ് നിർവഹണവും ശ്രദ്ധാപൂർവം തിരഞ്ഞെടുത്ത മാർക്കറ്റ്പ്ലേസ് സ്കില്ലുകളും വരെയുള്ള പുനരുപയോഗിക്കാവുന്ന ശേഷികൾ സംയോജിപ്പിക്കാൻ ഭാഷാ മോഡലുകളെയും (ഓപ്പറേറ്റർമാരെയും) അനുവദിക്കുന്ന, വിപുലീകരിക്കാവുന്ന ഒരു Skills ഫ്രെയിംവർക്ക് OmniRoute ലഭ്യമാക്കുന്നു.

ഒരു സ്കിൽ എന്നത് പതിപ്പുള്ളതും സ്കീമ നിർവചിച്ചതുമായ ഒരു പ്രവൃത്തി യൂണിറ്റാണ്. ഔട്ട്ബൗണ്ട് അഭ്യർത്ഥനകളിലേക്ക് ടൂൾ നിർവചനങ്ങളായി സ്കില്ലുകൾ ഇൻജെക്റ്റ് ചെയ്യാനും, മോഡലിൽനിന്ന് മടങ്ങിവരുന്ന ടൂൾ കോളുകൾ ഇന്റർസെപ്റ്റ് ചെയ്യാനും, പൊരുത്തപ്പെടുന്ന ഹാൻഡ്ലർ പ്രവർത്തിപ്പിക്കാനും, സംഭാഷണം തുടരാൻ കഴിയുന്നവിധം ഫലം മോഡലിലേക്ക് തിരികെ നൽകാനും OmniRoute-ന് കഴിയും. മോഡൽ ഒരിക്കലും ഇംപ്ലിമെന്റേഷൻ കാണുന്നില്ല — ടൂൾ ഇന്റർഫേസ് മാത്രമാണ് കാണുന്നത്.

## Agent Skills-ഉം Omni Skills-ഉം

OmniRoute-ന് വ്യത്യസ്തവും അതേസമയം പരസ്പരപൂരകവുമായ രണ്ട് സ്കിൽ സിസ്റ്റങ്ങളുണ്ട്:

| മാനം                  | **Omni Skills** (ഈ ഡോക്യുമെന്റ്)                                                                  | **Agent Skills**                                                                             |
| :-------------------- | :------------------------------------------------------------------------------------------------ | :------------------------------------------------------------------------------------------- |
| ഉദ്ദേശ്യം             | LLM ടൂൾ ഇൻജെക്ഷൻ + സാൻഡ്ബോക്സ് ചെയ്ത നിർവഹണം                                                      | ബാഹ്യ ഏജന്റുകൾക്ക് കണ്ടെത്താനും ഉപയോഗിക്കാനുമുള്ള SKILL.md കാറ്റലോഗ്                         |
| ആധികാരിക ഉറവിടം       | `src/lib/skills/` + മാർക്കറ്റ്പ്ലേസ്                                                              | `src/lib/agentSkills/` + `skills/` ഡയറക്ടറി                                                  |
| റൺടൈം മോഡ്            | ഔട്ട്ബൗണ്ട് അഭ്യർത്ഥനകളിലേക്ക് ഇൻജെക്റ്റ് ചെയ്യുകയും ടൂൾ-കോൾ ഇവന്റുകളിൽ നിർവഹിക്കുകയും ചെയ്യുന്നു | സ്റ്റാറ്റിക് മാർക്ക്ഡൗൺ കാറ്റലോഗ് + REST/MCP/A2A ഡിസ്കവറി എൻഡ്പോയിന്റുകൾ                     |
| ആരാണ് ഉപയോഗിക്കുന്നത് | OmniRoute തന്നെ (കോംബോ റൂട്ടിങ്, ഇൻബൗണ്ട് LLM കോളുകൾ)                                             | ബാഹ്യ ഏജന്റുകൾ, MCP ക്ലയന്റുകൾ, A2A ഓർക്കസ്ട്രേറ്ററുകൾ                                       |
| എണ്ണം                 | വ്യത്യാസപ്പെടുന്നത് (മാർക്കറ്റ്പ്ലേസ് അടിസ്ഥാനമാക്കി)                                             | 45 കാറ്റലോഗ് എൻട്രികൾ (23 API + 21 CLI + 1 കോൺഫിഗ്)                                          |
| ഫോർമാറ്റ്             | ടൂൾ സ്കീമയും ഹാൻഡ്ലറും ഉൾപ്പെട്ട `SkillDefinition`                                                | `SKILL.md` ഫ്രണ്ട്മാറ്റർ + മാർക്ക്ഡൗൺ ഉള്ളടക്കം                                              |
| കണ്ടെത്തൽ             | `/api/skills/*` REST + `omniroute_skills_*` MCP ടൂളുകൾ                                            | `/api/agent-skills/*` REST + `omniroute_agent_skills_*` MCP ടൂളുകൾ + A2A `list-capabilities` |

**Omni Skills** ആണ് എക്സിക്യൂഷൻ എൻജിൻ — ഒരു LLM ടൂൾ അഭ്യർത്ഥിക്കുമ്പോൾ OmniRoute-ന് _എന്ത് ചെയ്യാൻ കഴിയും_ എന്ന് അവ നിർവചിക്കുന്നു.

**Agent Skills** ആണ് ഡോക്യുമെന്റേഷൻ കാറ്റലോഗ് — ഏജന്റ് പ്രോംപ്റ്റുകളിലേക്ക് നേരിട്ട് നൽകാവുന്ന ഘടനാബദ്ധമായ SKILL.md ഫയലുകൾ ഉപയോഗിച്ച് OmniRoute-ന്റെ REST API-യും CLI-യും _എങ്ങനെ ഉപയോഗിക്കാം_ എന്ന് അവ ബാഹ്യ ഏജന്റുകളോട് വിശദീകരിക്കുന്നു.

Agent Skills കാറ്റലോഗ്, ജനറേറ്റർ, MCP ടൂളുകൾ, A2A സ്കിൽ എന്നിവയെക്കുറിച്ച് അറിയാൻ [docs/frameworks/AGENT-SKILLS.md](./AGENT-SKILLS.md) കാണുക.

## ആശയങ്ങൾ

### സ്കിൽ ഉറവിടങ്ങൾ

സ്കില്ലുകളുടെ മൂന്ന് ഉറവിടങ്ങൾ ഒരേ രജിസ്ട്രിയിൽ സഹവർത്തിക്കുന്നു:

1. **ബിൽറ്റ്-ഇൻ സ്കില്ലുകൾ** (`src/lib/skills/builtins.ts`) — OmniRoute-നൊപ്പം ലഭ്യമാക്കുന്നവ. പൊതുവായ ഉപയോഗസാഹചര്യങ്ങൾ ഉൾക്കൊള്ളുന്നു:
   - `file_read`, `file_write` — `<DATA_DIR>/skills/workspaces/<hashed-key>/` എന്നതിന് കീഴിലുള്ള ഓരോ API കീയ്ക്കും പ്രത്യേകമായ സാൻഡ്ബോക്സ് വർക്ക്സ്പേസ്
   - `http_request` — `guard: "public-only"` സഹിതം `safeOutboundFetch` വഴിയുള്ള ഔട്ട്ബൗണ്ട് HTTP
   - `web_search` — കാഷിങ് സഹിതമുള്ള, മാറ്റിവെക്കാവുന്ന സെർച്ച് പ്രൊവൈഡർ (`executeWebSearch`)
   - `eval_code` — Docker-ൽ സാൻഡ്ബോക്സ് ചെയ്ത `node` അല്ലെങ്കിൽ `python` നിർവഹണം
   - `execute_command` — Docker-ൽ സാൻഡ്ബോക്സ് ചെയ്ത ഷെൽ കമാൻഡ്
   - `browser` — Playwright പിന്തുണയുള്ള സ്കാഫോൾഡിങ്, ഡിഫോൾട്ടായി പ്രവർത്തനരഹിതം (`builtin/browser.ts`)
2. **SkillsMP** (OmniRoute മാർക്കറ്റ്പ്ലേസ്) — `https://skillsmp.com/api/v1/skills/search` എന്നതിൽനിന്ന് ലഭ്യമാക്കുന്നു. Settings-ൽ `skillsmpApiKey` ആവശ്യമാണ്.
3. **SkillsSH** (`skills.sh` കമ്മ്യൂണിറ്റി കാറ്റലോഗ്) — `https://skills.sh/api/search` എന്നതിൽനിന്ന് ലഭ്യമാക്കുന്നു. ഓതന്റിക്കേഷൻ ആവശ്യമില്ല; SKILL.md ഉള്ളടക്കം GitHub raw-ൽനിന്ന് എടുക്കുന്നു.

ഡാഷ്ബോർഡ് ഏത് കാറ്റലോഗിൽനിന്നാണ് ഇൻസ്റ്റാൾ ചെയ്യുന്നതെന്ന് ഒരൊറ്റ "സജീവ പ്രൊവൈഡർ" നിയന്ത്രിക്കുന്നു (`src/lib/skills/providerSettings.ts`). **Settings → Memory & Skills** എന്നതിൽ ഇത് മാറ്റുക. ഡിഫോൾട്ട്: `skillsmp`.

### സ്കിൽ ഐഡന്റിറ്റി

ഇൻ-മെമ്മറി രജിസ്ട്രിയിൽ (`src/lib/skills/registry.ts`) സ്കില്ലുകൾ `name@version` ഉപയോഗിച്ചാണ് കീ ചെയ്യുന്നത്. പതിപ്പ് semver (`^\d+\.\d+\.\d+$`) ആയിരിക്കണം. `resolveVersion()`-ന് `^`, `~`, `>`, `>=`, `<`, `<=`, `==`, കൃത്യമായ പൊരുത്ത നിയന്ത്രണങ്ങൾ എന്നിവ മനസ്സിലാക്കാം.

### സ്കിൽ മോഡ്

ഓരോ സ്കില്ലിനും അത് എപ്പോൾ ഇൻജെക്റ്റ് ചെയ്യണമെന്ന് നിയന്ത്രിക്കുന്ന ഒരു റൺടൈം മോഡ് ഉണ്ട്:

| മോഡ്   | പ്രവർത്തനം                                                                                                                           |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| `on`   | എപ്പോഴും ഒരു ടൂൾ നിർവചനമായി ഇൻജെക്റ്റ് ചെയ്യുന്നു                                                                                    |
| `off`  | ഒരിക്കലും ഇൻജെക്റ്റ് ചെയ്യുന്നില്ല, നിർവഹിക്കാനും കഴിയില്ല                                                                           |
| `auto` | ഇൻകമിങ് അഭ്യർത്ഥനയുമായി താരതമ്യം ചെയ്ത് സ്കോർ നൽകുന്നു; സ്കോർ ≥ `AUTO_MIN_SCORE` (ഡിഫോൾട്ട് 3) ആണെങ്കിൽ മാത്രം ഇൻജെക്റ്റ് ചെയ്യുന്നു |

മാർക്കറ്റ്പ്ലേസിൽനിന്ന് ഇൻസ്റ്റാൾ ചെയ്യുന്ന സ്കില്ലുകളുടെ ഡിഫോൾട്ട് `auto` ആണ്. `enabled=true`, `mode="off"` എന്നിവ ഒരുമിച്ച് വരുമ്പോൾ "രജിസ്റ്റർ ചെയ്തെങ്കിലും സജീവമല്ല" എന്നാണ് അർത്ഥം — ലെഗസി കോളം വഴി `enabled` ടോഗിൾ ചെയ്യുന്നത് `mode`-ഉം മാറ്റുന്നു, അതിനാൽ പഴയ കോഡ് പാതകൾ സ്ഥിരതയോടെ തുടരുന്നു (`src/app/api/skills/[id]/route.ts`).

### സ്റ്റാറ്റസ് (നിർവഹണങ്ങൾ)

സ്കിൽ നിർവഹണങ്ങൾ ഇനിപ്പറയുന്ന സ്റ്റാറ്റസുകളോടെ `skill_executions` പട്ടികയിൽ ട്രാക്ക് ചെയ്യുന്നു (`src/lib/skills/types.ts`):

```ts
enum SkillStatus {
  PENDING = "pending",
  RUNNING = "running",
  SUCCESS = "success",
  ERROR = "error",
  TIMEOUT = "timeout",
}
```

### രജിസ്ട്രി കാഷ്

`SkillRegistry` എന്നത് 60-സെക്കൻഡ് TTL കാഷുള്ള ഒരു സിംഗിൾട്ടൺ ആണ് (`registry.ts:14`). `loadFromDatabase()` ഐഡംപൊട്ടന്റ് ആണ്; `pendingLoad` വഴി ഒരേസമയം നടക്കുന്ന കോളുകളുടെ ഡ്യൂപ്ലിക്കേറ്റുകൾ നീക്കംചെയ്യുന്നു. ഏതൊരു റൈറ്റ് പ്രവർത്തനവും (`register`/`unregister`/`unregisterById`) കാഷ് അസാധുവാക്കുന്നു. പതിപ്പുകൾ കണ്ടെത്താൻ `getSkillVersions(name)` ഉം `resolveVersion(name, constraint)` ഉം ഉപയോഗിക്കുക.

### പ്രൊവൈഡർ-അവബോധമുള്ള ഇൻജെക്ഷൻ

`src/lib/skills/injection.ts`-ലെ `injectSkills()` ആണ് രജിസ്റ്റർ ചെയ്ത സ്കില്ലുകളെ പ്രൊവൈഡർ-നിർദ്ദിഷ്ട ടൂൾ നിർവചനങ്ങളാക്കി മാറ്റുന്ന എൻട്രി പോയിന്റ്:

- **OpenAI** — `{ type: "function", function: { name, description, parameters } }`
- **Anthropic** — `{ name, description, input_schema }`
- **Google (Gemini)** — `{ name, description, parameters }`

മോഡൽ തിരികെ വിളിക്കുമ്പോൾ ഹാൻഡ്ലറിന് ശരിയായ പതിപ്പ് തിരഞ്ഞെടുക്കാനാകുന്നതിനായി ടൂളിന്റെ പേര് `name@version` എന്ന രീതിയിൽ എൻകോഡ് ചെയ്തിരിക്കുന്നു.

### AUTO സ്കോറിംഗ്

`mode="auto"` ആയിരിക്കുമ്പോൾ, ഓരോ കാൻഡിഡേറ്റ് സ്കില്ലിനും അഭ്യർത്ഥനാ കോൺടെക്സ്റ്റിനെ അടിസ്ഥാനമാക്കി സ്കോർ നൽകുന്നു (`injection.ts`-ലെ `scoreAutoSkill()`):

| സിഗ്നൽ                                                                | പോയിന്റുകൾ        |
| --------------------------------------------------------------------- | ----------------- |
| സ്കില്ലിന്റെ പേര് കോൺടെക്സ്റ്റിൽ അതേപടി പ്രത്യക്ഷപ്പെടുന്നു           | +6                |
| ഓരോ പേര് ടോക്കണും ഒരു കോൺടെക്സ്റ്റ് ടോക്കണുമായി പൊരുത്തപ്പെടുന്നു     | +2                |
| ഓരോ ടാഗ് സബ്സ്ട്രിങ്ങും കോൺടെക്സ്റ്റുമായി പൊരുത്തപ്പെടുന്നു           | +3                |
| ഓരോ വിവരണ ടോക്കണും കോൺടെക്സ്റ്റുമായി പൊരുത്തപ്പെടുന്നു                | +1                |
| പശ്ചാത്തല കാരണം ഒരു പേര് ടോക്കണുമായി പൊരുത്തപ്പെടുന്നു                | ഓരോ ടോക്കണിനും +2 |
| പശ്ചാത്തല കാരണം ഒരു ടാഗുമായി പൊരുത്തപ്പെടുന്നു                        | ഓരോ ടോക്കണിനും +2 |
| ടാഗുകളിലെ പ്രൊവൈഡർ സൂചന അഭ്യർത്ഥനയിലെ പ്രൊവൈഡറുമായി പൊരുത്തപ്പെടുന്നു | +2 / −2           |

`score >= AUTO_MIN_SCORE = 3` ഉള്ള മികച്ച `AUTO_MAX_SKILLS = 5` സ്കില്ലുകൾ ഇൻജക്റ്റ് ചെയ്യപ്പെടുന്നു. തുല്യ സ്കോറുകൾ `installCount` (അവരോഹണക്രമം), തുടർന്ന് അക്ഷരമാലാക്രമത്തിലുള്ള പേര് എന്നിവ അടിസ്ഥാനമാക്കി വേർതിരിക്കുന്നു (`injection.ts:225-235`).

### ടൂൾ കോൾ ഇന്റർസെപ്ഷൻ

അപ്സ്ട്രീം ഒരു ടൂൾ-കോളിംഗ് പ്രതികരണം നൽകിയതിന് ശേഷം ചാറ്റ് ഹാൻഡ്ലർ `src/lib/skills/interception.ts`-ലെ `handleToolCallExecution()` വിളിക്കുന്നു:

1. `extractToolCalls()` പ്രൊവൈഡർ-നിർദ്ദിഷ്ട ഘടനകൾ വായിക്കുന്നു (OpenAI `tool_calls` / Responses `function_call`, Anthropic `tool_use`, Gemini `functionCalls`).
2. ബിൽറ്റ്-ഇൻ ടൂൾ അപരനാമങ്ങൾ (ഉദാ. `omniroute_web_search` → `web_search`) ആദ്യം റിസോൾവ് ചെയ്യുന്നു. ബിൽറ്റ്-ഇൻ ഹാൻഡ്ലറുകൾ ഇൻലൈനായി പ്രവർത്തിക്കുന്നു.
3. മറ്റെല്ലാം `skillExecutor.execute(name@version, args, { apiKeyId, sessionId })` വഴി റൂട്ട് ചെയ്യുന്നു.
4. ഫലങ്ങൾ പ്രതികരണത്തിലേക്ക് തിരികെ ചേർക്കുന്നു — അനുയോജ്യമായ രീതിയിൽ `tool_results`, `function_call_output` ഇനങ്ങൾ, അല്ലെങ്കിൽ Anthropic `tool_result` ബ്ലോക്കുകൾ ആയി.

ഉപയോക്താവ് നിർവചിച്ച ഹാൻഡ്ലറുകൾ വ്യക്തമായി പ്രവർത്തനരഹിതമാക്കുന്ന അഭ്യർത്ഥനാ പാതകളിൽ, ബിൽറ്റ്-ഇൻ ഇന്റർസെപ്ഷൻ മാത്രം അനുവദിക്കുന്നതിനായി എക്സിക്യൂഷൻ കോൺടെക്സ്റ്റിലെ `customSkillExecutionEnabled` എന്നത് `false` ആയി സജ്ജീകരിക്കാം.

## Docker സാൻഡ്ബോക്സ്

ബിൽറ്റ്-ഇൻ അല്ലാത്ത കോഡ് പാതകൾ (`eval_code`, `execute_command`) `SandboxRunner` (`src/lib/skills/sandbox.ts`) വഴി Docker-നുള്ളിൽ പ്രവർത്തിക്കുന്നു. ഓരോ കണ്ടെയ്നറും ഇനിപ്പറയുന്നവ ഉപയോഗിച്ചാണ് ആരംഭിക്കുന്നത്:

```
--rm --network none|bridge --cap-drop ALL
--security-opt no-new-privileges --pids-limit 100
--cpus <cpuLimit/1000> --memory <memoryLimit>m
--tmpfs /tmp:rw,noexec,nosuid,size=64m
--tmpfs /workspace:rw,noexec,nosuid,size=64m
--read-only (readOnly=true ആയിരിക്കുമ്പോൾ)
```

സ്ഥിരസ്ഥിതി മൂല്യങ്ങൾ (`SandboxRunner.DEFAULT_CONFIG`):

| ഫീൽഡ്            | സ്ഥിരസ്ഥിതി     | കുറിപ്പുകൾ                                                   |
| ---------------- | --------------- | ------------------------------------------------------------ |
| `cpuLimit`       | 100 (= 0.1 CPU) | `--cpus`-ലേക്ക് കൈമാറുന്നതിന് മുമ്പ് 1000 കൊണ്ട് ഹരിക്കുന്നു |
| `memoryLimit`    | 256 MB          | കർശനമായ പരിധി                                                |
| `timeout`        | 30000 ms        | `SIGTERM` + `docker kill` വഴിയുള്ള സോഫ്റ്റ് കിൽ              |
| `networkEnabled` | `false`         | `--network none` ആയി മാറുന്നു                                |
| `readOnly`       | `true`          | റൂട്ട് FS റീഡ്-ഒൺലി; `/tmp`, `/workspace` എന്നിവ tmpfs ആണ്   |

ഷട്ട്ഡൗണിനായി `SandboxRunner.kill(id)`, `killAll()` എന്നിവ ലഭ്യമാക്കിയിരിക്കുന്നു; പ്രവർത്തിക്കുന്ന കണ്ടെയ്നറുകൾ `runningContainers: Map<string, ChildProcess>`-ൽ ട്രാക്ക് ചെയ്യുന്നു.

### സാൻഡ്ബോക്സ് പരിസ്ഥിതി വേരിയബിളുകൾ

`src/lib/skills/builtins.ts`-ൽ `process.env` വഴി കോൺഫിഗർ ചെയ്യുന്നു:

| പരിസ്ഥിതി വേരിയബിൾ                | സ്ഥിരസ്ഥിതി      | ഉദ്ദേശ്യം                                                                                                         |
| --------------------------------- | ---------------- | ----------------------------------------------------------------------------------------------------------------- |
| `SKILLS_MAX_FILE_BYTES`           | `1048576` (1 MB) | `file_read`, `file_write` എന്നിവയ്ക്കുള്ള പരിധി                                                                   |
| `SKILLS_MAX_HTTP_RESPONSE_BYTES`  | `256000`         | `http_request` പ്രതികരണ ബോഡിക്കുള്ള പരിധി                                                                         |
| `SKILLS_MAX_SANDBOX_OUTPUT_CHARS` | `100000`         | കോളറിന് തിരികെ നൽകുന്ന stdout/stderr-നുള്ള പരിധി                                                                  |
| `SKILLS_SANDBOX_TIMEOUT_MS`       | `10000`          | സാൻഡ്ബോക്സ് ചെയ്ത കമാൻഡുകൾക്കുള്ള സ്ഥിരസ്ഥിതി ടൈംഔട്ട്; പരമാവധി 60 s                                              |
| `SKILLS_SANDBOX_NETWORK_ENABLED`  | `false`          | എഗ്രസ് നിയന്ത്രിക്കുന്ന മാസ്റ്റർ ഗേറ്റ്. ഓരോ കോളിലും ഓപ്റ്റ്-ഇൻ അനുവദിക്കാൻ `1` അല്ലെങ്കിൽ `true` ആയി സജ്ജമാക്കുക |
| `SKILLS_ALLOWED_SANDBOX_IMAGES`   | (താഴെ കാണുക)     | കോമ ഉപയോഗിച്ച് വേർതിരിച്ച Docker ഇമേജുകളുടെ അനുവദനീയ പട്ടിക                                                       |

സ്ഥിരസ്ഥിതിയായി അനുവദിച്ചിരിക്കുന്ന ഇമേജുകൾ: `alpine:3.20`, `node:22-alpine`, `python:3.12-alpine`. `SKILLS_ALLOWED_SANDBOX_IMAGES` വഴി ചേർക്കുന്നവ സ്ഥിരസ്ഥിതി പട്ടികയുമായി ലയിപ്പിക്കുന്നു; തിരിച്ചറിയാത്ത ഇമേജുകൾ `normalizeImage()` നിരസിക്കുന്നു.

> കുറിപ്പ്: വേറിട്ട `SKILLS_EXECUTION_TIMEOUT_MS` പരിസ്ഥിതി വേരിയബിൾ ഇല്ല. സാൻഡ്ബോക്സ് അല്ലാത്ത ഹാൻഡ്ലർ ടൈംഔട്ട് `SkillExecutor`-ൽ (`executor.ts:13`) 30 s ആയി ഹാർഡ്-കോഡ് ചെയ്തിട്ടുണ്ട്, എന്നാൽ റൺടൈമിൽ `skillExecutor.setTimeout(ms)` വഴി അത് അസാധുവാക്കി മറ്റൊരു മൂല്യം നൽകാം.

### വർക്ക്സ്പേസ് ഐസൊലേഷൻ

`file_read`, `file_write` എന്നിവ ഓരോ പാതയും `<DATA_DIR>/skills/workspaces/<sha256(apiKeyId).slice(0,24)>/` എന്നിടത്തുള്ള ഓരോ API കീയ്ക്കുമായുള്ള വർക്ക്സ്പേസിനെ ആപേക്ഷികമായി പരിഹരിക്കുന്നു. ഏതെങ്കിലും ഡിസ്ക് I/O നടക്കുന്നതിന് മുമ്പ് പാതാ ട്രാവേഴ്സൽ (`..`), നിരോധിത സെഗ്മെന്റുകൾ (`.env`, `.git`, `.ssh`, `.omniroute`, `.codex`, `secrets`) എന്നിവ നിരസിക്കുന്നു.

### HTTP ഹാർഡനിംഗ്

`http_request` (`builtins.ts:257`):

- മെത്തഡ് അനുവദനീയ പട്ടിക: `GET, HEAD, POST, PUT, PATCH, DELETE`
- ബ്ലോക്ക് ചെയ്ത ഔട്ട്ബൗണ്ട് ഹെഡറുകൾ: `host, connection, content-length, cookie, set-cookie, authorization, proxy-authorization`
- റീഡയറക്ടുകൾ പ്രവർത്തനരഹിതമാക്കി (`allowRedirect: false`)
- `guard: "public-only"` ഉപയോഗിച്ച് `safeOutboundFetch` വഴി റൂട്ട് ചെയ്യുന്നു (സ്വകാര്യ/ലൂപ്പ്ബാക്ക് ശ്രേണികൾ ബ്ലോക്ക് ചെയ്യുന്നു)
- പ്രതികരണം `SKILLS_MAX_HTTP_RESPONSE_BYTES`-ൽ വെട്ടിച്ചുരുക്കുന്നു; ക്ലയന്റിന് `truncated: true` ലഭിക്കുന്നു

## ഹൈബ്രിഡ് എക്സിക്യൂട്ടർ (പ്രിവ്യൂ)

`src/lib/skills/hybrid.ts` ഓരോ കോളിലും `direct` (പ്രോസസ്സിനുള്ളിൽ) നിർവഹണമോ `sandbox` നിർവഹണമോ വേണമെന്ന് തീരുമാനിക്കുന്ന ഒരു `HybridExecutor` നിർവചിക്കുന്നു; ടൈംഔട്ട്/മെമ്മറി പിശകുകൾ സംഭവിക്കുമ്പോൾ `autoUpgrade` പുനഃശ്രമ പാതയും ഇതിലുണ്ട്. വയർ ചെയ്തിരിക്കുന്ന `directExecutor` / `sandboxRunner` ഇംപ്ലിമെന്റേഷനുകൾ സ്റ്റബുകളാണ് (`executeDirect`, `executeInSandbox` എന്നിവ പ്ലേസ്ഹോൾഡർ ഒബ്ജക്റ്റുകൾ മടക്കിനൽകുന്നു) — ഈ മൊഡ്യൂളിനെ നിർമാണത്തിലിരിക്കുന്ന ഒരു കോൺട്രാക്ടായി പരിഗണിക്കുക. യഥാർത്ഥ നിർവഹണം ഇപ്പോഴും `skillExecutor` + `SandboxRunner` വഴിയാണ് നടക്കുന്നത്.

## REST API

എല്ലാ എൻഡ്പോയിന്റുകളും `src/app/api/skills/`-ന് കീഴിലാണ്. മാനേജ്മെന്റ് എൻഡ്പോയിന്റുകൾക്ക് (`/api/skills`, `/api/skills/[id]`, `/api/skills/install`) `requireManagementAuth()` മുഖേനയുള്ള **മാനേജ്മെന്റ് ഓതന്റിക്കേഷൻ** ആവശ്യമാണ്. മാർക്കറ്റ്പ്ലേസ്/ഇൻസ്റ്റാൾ ഫ്ലോകൾ കൂടുതൽ ലളിതമായ `isAuthenticated()` (സെഷൻ അല്ലെങ്കിൽ API കീ) ഉപയോഗിക്കുന്നു.

| എൻഡ്പോയിന്റ് | മെത്തേഡ് | ഉദ്ദേശ്യം |
| --------------------------------- | ------ | ------------------------------------------------------------------------ | --- | ------------------------ | -------- | ------------------ |
| `/api/skills` | GET | രജിസ്റ്റർ ചെയ്ത സ്കില്ലുകൾ ലിസ്റ്റ് ചെയ്യുന്നു. `?q=`, `?mode=on                        | off | auto`, `?source=skillsmp | skillssh | local`, പേജിനേഷൻ എന്നിവ പിന്തുണയ്ക്കുന്നു |
| `/api/skills/[id]` | PUT | `enabled` അല്ലെങ്കിൽ `mode` അപ്ഡേറ്റ് ചെയ്യുന്നു |
| `/api/skills/[id]` | DELETE | id ഉപയോഗിച്ച് രജിസ്ട്രേഷൻ റദ്ദാക്കുന്നു |
| `/api/skills/install` | POST | ഒരു കസ്റ്റം സ്കിൽ ഇൻസ്റ്റാൾ ചെയ്യുന്നു (ഹാൻഡ്ലർ കോഡ് + സ്കീമ) |
| `/api/skills/marketplace` | GET | SkillsMP കാറ്റലോഗിൽ തിരയുന്നു (`q` ശൂന്യമായിരിക്കുമ്പോൾ ജനപ്രിയ ഡിഫോൾട്ടുകൾ മടക്കിനൽകുന്നു) |
| `/api/skills/marketplace/install` | POST | ഒരു SkillsMP സ്കിൽ ഇൻസ്റ്റാൾ ചെയ്യുന്നു (സജീവ പ്രൊവൈഡർ = `skillsmp` ആയിരിക്കണം) |
| `/api/skills/skillssh` | GET | skills.sh കാറ്റലോഗിൽ തിരയുന്നു (`?q=&limit=`, പരമാവധി 100) |
| `/api/skills/skillssh/install` | POST | ഒരു skills.sh സ്കിൽ ഇൻസ്റ്റാൾ ചെയ്യുന്നു (സജീവ പ്രൊവൈഡർ = `skillssh` ആയിരിക്കണം) |
| `/api/skills/executions` | GET | പേജിനേറ്റ് ചെയ്ത നിർവഹണ ചരിത്രം (`?apiKeyId=`) |
| `/api/skills/executions` | POST | രജിസ്റ്റർ ചെയ്ത ഒരു സ്കിൽ തത്സമയം നിർവഹിക്കുന്നു |

`settings.skillsEnabled === false` ആയിരിക്കുമ്പോൾ `POST /api/skills/executions` എൻഡ്പോയിന്റ് `{ error: "Skills execution is disabled..." }` സഹിതം HTTP `503` മടക്കിനൽകുന്നു (`executor.ts:42-45`). ഓപ്പറേറ്റർമാർക്ക് **Settings → AI** എന്നതിൽ നിന്ന് മാസ്റ്റർ സ്വിച്ച് മാറ്റാനാകും.

### ഉദാഹരണം: ഒരു കസ്റ്റം സ്കിൽ ഇൻസ്റ്റാൾ ചെയ്യുക

```bash
curl -X POST http://localhost:20128/api/skills/install \
  -H "Authorization: Bearer $OMNIROUTE_MGMT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "reverse-text",
    "version": "1.0.0",
    "description": "Reverses a string",
    "schema": {
      "input":  { "type": "object", "properties": { "text": { "type": "string" } }, "required": ["text"] },
      "output": { "type": "object", "properties": { "reversed": { "type": "string" } } }
    },
    "handlerCode": "echo-handler",
    "apiKeyId": "your-api-key-id"
  }'
```

`handlerCode` സ്ട്രിംഗ് ഒരു **ഹാൻഡ്ലർ നെയിം ലുക്കപ്പ്** ആണ് — നിർവഹിക്കാവുന്ന കോഡല്ല. എക്സിക്യൂട്ടർ അതിനെ `skillExecutor.registerHandler(name, fn)` (`executor.ts:25`) മുഖേന മാപ്പ് ചെയ്യുന്നു. മാർക്കറ്റ്പ്ലേസ് ഇൻസ്റ്റാളുകൾ SKILL.md ടെക്സ്റ്റ് ഡോക്യുമെന്റേഷനായി ഈ ഫീൽഡിൽ സംഭരിക്കുകയും മോഡൽ സൃഷ്ടിച്ച ടൂൾ കോളുകൾ വഴി നിർവഹണം റൂട്ട് ചെയ്യുകയും ചെയ്യുന്നു. ഉപയോക്താവ് നൽകുന്ന ഏതെങ്കിലും സോഴ്സ് ഏകപക്ഷീയമായി eval ചെയ്യപ്പെടുന്നില്ല.

## MCP ടൂളുകൾ

നാല് MCP ടൂളുകൾ സ്കിൽസ് സർഫേസിനെ പൊതിയുന്നു (`open-sse/mcp-server/tools/skillTools.ts`). MCP സർവർ ബൂട്ട് ചെയ്യുമ്പോൾ അവ സ്വയമേവ രജിസ്റ്റർ ചെയ്യപ്പെടുന്നു.

| ടൂൾ                           | വിവരണം                                                                            |
| ----------------------------- | --------------------------------------------------------------------------------- |
| `omniroute_skills_list`       | സ്കില്ലുകൾ പട്ടികപ്പെടുത്തുന്നു; ഐച്ഛിക ഫിൽട്ടറുകൾ: `apiKeyId`, `name`, `enabled` |
| `omniroute_skills_enable`     | `skillId` ഉപയോഗിച്ച് ഒരു സ്കിൽ പ്രവർത്തനക്ഷമമാക്കുക/പ്രവർത്തനരഹിതമാക്കുക          |
| `omniroute_skills_execute`    | ഇൻപുട്ട് പേലോഡ് ഉപയോഗിച്ച് ഒരു സ്കിൽ നിർവഹിക്കുക                                  |
| `omniroute_skills_executions` | സമീപകാല നിർവഹണ ചരിത്രം (സ്ഥിരസ്ഥിതി 50, പരമാവധി 100)                              |

ട്രാൻസ്പോർട്ട് സജ്ജീകരണത്തിനും സ്കോപ്പ് അസൈൻമെന്റുകൾക്കുമായി [MCP-SERVER.md](./MCP-SERVER.md) കാണുക.

## പുതിയൊരു ബിൽറ്റ്-ഇൻ സ്കിൽ ചേർക്കൽ

1. **ഹാൻഡ്ലർ നിർവചിക്കുക** `src/lib/skills/builtins.ts`-ൽ (അല്ലെങ്കിൽ `src/lib/skills/builtin/`-ന് കീഴിലുള്ള മറ്റൊരു ഫയലിൽ). സിഗ്നേച്ചർ: `(input, { apiKeyId, sessionId }) => Promise<output>`.
2. **സാൻഡ്ബോക്സ് ചെയ്ത കോഡ് പാതയാണോ?** `sandboxRunner.run(image, command, env, sandboxConfig({...}))` കോൾ ചെയ്യുക. അനുവദനീയ പട്ടികയ്ക്കെതിരെ `normalizeImage()` ഉപയോഗിക്കുക.
3. **ഫയൽസിസ്റ്റം പാതയാണോ?** ഡിസ്ക് ആക്സസ് ചെയ്യുന്നതിന് മുമ്പ് എല്ലായ്പ്പോഴും `resolveWorkspacePath(input, context)` വഴി കടത്തിവിടുക.
4. **നെറ്റ്വർക്ക് കോൾ ആണോ?** `guard: "public-only"` സഹിതം `safeOutboundFetch` ഉപയോഗിക്കുക; `sanitizeHeaders()` വഴി ഹെഡറുകൾ ശുദ്ധീകരിക്കുക.
5. **രജിസ്റ്റർ ചെയ്യുക** `builtinSkills`-ലേക്ക് എൻട്രി ചേർത്തുകൊണ്ട് (അല്ലെങ്കിൽ ബൂട്ട് സമയത്ത് `registerBrowserSkill(executor)` ശൈലിയിൽ കോൾ ചെയ്തുകൊണ്ട്).
6. അപ്സ്ട്രീം മോഡൽ മറ്റൊരു പേര് പുറപ്പെടുവിക്കുന്നുവെങ്കിൽ, `BUILTIN_TOOL_ALIASES` (`interception.ts:23`)-ൽ **ബിൽറ്റ്-ഇൻ ടൂൾ അപരനാമങ്ങൾ ബന്ധിപ്പിക്കുക** (ഐച്ഛികം).
7. **ടെസ്റ്റുകൾ** `src/lib/skills/__tests__/`-ൽ (Vitest).

## ഇഷ്ടാനുസൃത (ബിൽറ്റ്-ഇൻ അല്ലാത്ത) സ്കിൽ ചേർക്കൽ

1. പ്രോസസ് ആരംഭിക്കുമ്പോൾ ഹാൻഡ്ലർ രജിസ്റ്റർ ചെയ്യുക:
   ```ts
   skillExecutor.registerHandler("my-handler", async (input, ctx) => { ... });
   ```
2. `POST /api/skills/install` വഴി സ്കിൽ ചേർക്കുക (`handlerCode` ഫീൽഡ് രജിസ്റ്റർ ചെയ്ത ഹാൻഡ്ലർ പേരുമായി പൊരുത്തപ്പെടണം).
3. `PUT /api/skills/[id]` വഴി `mode`, `on` അല്ലെങ്കിൽ `auto` ആയി മാറ്റുക.

## പ്രവർത്തനപരമായ നിർദ്ദേശങ്ങൾ

- **മാസ്റ്റർ സ്വിച്ച്:** `settings.skillsEnabled = false` എല്ലാ നിർവഹണവും തടയുകയും `/api/skills/executions`-ൽ HTTP `503` തിരികെ നൽകുകയും ചെയ്യുന്നു. രജിസ്ട്രി ലോഡ് ചെയ്യുന്നത് തുടരുന്നു.
- **ഔട്ട്ബൗണ്ട് ട്രാഫിക് നിയന്ത്രിക്കുക:** പൂർണ്ണമായി എയർ-ഗ്യാപ് ചെയ്ത സാൻഡ്ബോക്സിങ്ങിനായി `SKILLS_SANDBOX_NETWORK_ENABLED` സജ്ജീകരിക്കാതെ സൂക്ഷിക്കുക (സ്ഥിരസ്ഥിതി). ഓരോ കോളിലുമുള്ള `networkEnabled: true`-നും മാസ്റ്റർ ഗേറ്റ് ആവശ്യമാണ്.
- **നിർദ്ദിഷ്ട ഇമേജുകൾ അനുവദിക്കുക:** അനുവദനീയ പട്ടിക വിപുലീകരിക്കാൻ `SKILLS_ALLOWED_SANDBOX_IMAGES="myorg/sandbox:1.0,node:22-alpine"` സജ്ജീകരിക്കുക.
- **നിർവഹണങ്ങൾ ഓഡിറ്റ് ചെയ്യുക:** `/dashboard/skills/executions`-ഉം `omniroute_skills_executions`-ഉം `skill_executions` ക്വറി ചെയ്യുന്നു. വിജയകരമായ റണ്ണുകളിൽ `durationMs` ഉൾപ്പെടുന്നു; പരാജയങ്ങളിൽ `errorMessage` ഉൾപ്പെടുന്നു.
- **കാഷ് അസാധുവാക്കൽ:** മാനുവൽ DB എഡിറ്റുകൾക്ക് ശേഷം `skillRegistry.invalidateCache()` കോൾ ചെയ്യുക; അല്ലെങ്കിൽ 60 s കാത്തിരിക്കുക.
- **അജ്ഞാത വർക്ക്സ്പേസ്:** `apiKeyId` ശൂന്യമായിരിക്കുമ്പോൾ, എല്ലാ കോളുകളും ഒരേ `"anonymous"` വർക്ക്സ്പേസിലേക്ക് ഹാഷ് ചെയ്യപ്പെടുന്നു — പങ്കിടൽ പരിഗണിക്കുന്ന കോഡ് എല്ലായ്പ്പോഴും യഥാർത്ഥ കീ നൽകണം.

## നിർവഹണ ലൈഫ്സൈക്കിൾ (v3.8.16+)

ഓരോ സ്കിൽ അഭ്യർത്ഥനയും കൈകാര്യം ചെയ്യുന്ന ഒരു **സിംഗിൾട്ടൺ** ആണ് `SkillExecutor` (`src/lib/skills/executor.ts`). ടൈംഔട്ടുകൾ, പുനഃശ്രമങ്ങൾ, നിർവഹണ നില എന്നിവ ഡീബഗ് ചെയ്യുന്നതിന് അതിന്റെ ലൈഫ്സൈക്കിൾ മനസ്സിലാക്കുന്നത് നിർണായകമാണ്.

### 5-ഘട്ട ലൈഫ്സൈക്കിൾ

```
   execute() വിളിച്ചു
        │
        ▼
  ┌─────────────┐
  │  PENDING    │  ← ക്യൂവിൽ ചേർത്തു, ഇതുവരെ ആരംഭിച്ചിട്ടില്ല (DB വരി സൃഷ്ടിച്ചു)
  └──────┬──────┘
         │ ഹാൻഡ്ലർ ആരംഭിക്കുക
         ▼
  ┌─────────────┐
  │  RUNNING    │  ← ടൈംഔട്ടോടെ ഹാൻഡ്ലർ വിളിച്ചു
  └──────┬──────┘
         │
    ┌────┴────┬──────────┬──────────┐
    │         │          │          │
    ▼         ▼          ▼          ▼
  SUCCESS   ERROR     TIMEOUT   (മറ്റൊരു പാതയുമില്ല — പാരന്റ് അവസാനിപ്പിച്ചു)
    │         │          │
    └────┬────┴──────────┘
         │
         ▼
   നില, ഔട്ട്പുട്ട്, durationMs എന്നിവ ഉപയോഗിച്ച് DB വരി അപ്ഡേറ്റ് ചെയ്തു
```

### ഡിഫോൾട്ട് കോൺഫിഗറേഷൻ

| ക്രമീകരണം    | ഡിഫോൾട്ട്     | ഇതിലൂടെ കോൺഫിഗർ ചെയ്യാം              |
| ------------ | ------------- | ------------------------------------ |
| `timeout`    | `30000` (30s) | `skillExecutor.setTimeout(ms)`       |
| `maxRetries` | `3`           | `skillExecutor.setMaxRetries(count)` |

> **പ്രധാനം**: എക്സിക്യൂട്ടർ ഒരു സിംഗിൾട്ടൺ ആണ് — `setTimeout()` വിളിക്കുന്നത് തുടർന്നുള്ള എല്ലാ അഭ്യർത്ഥനകളെയും ആഗോളമായി ബാധിക്കും. ഓരോ സ്കില്ലിനും വെവ്വേറെ ടൈംഔട്ടുകൾ നിലവിൽ പിന്തുണയ്ക്കുന്നില്ല; ഓരോ സ്കില്ലിനും വ്യത്യസ്ത ടൈംഔട്ടുകൾ ആവശ്യമാണെങ്കിൽ, പ്രത്യേക പ്രോസസ്സുകൾ സമർപ്പിക്കുകയോ എക്സിക്യൂട്ടർ ഫോർക്ക് ചെയ്യുകയോ ചെയ്യുക.

### സ്റ്റാറ്റസ് മൂല്യങ്ങൾ

`src/lib/skills/types.ts`-ൽ നിന്ന്:

```ts
enum SkillStatus {
  PENDING = "pending", // ക്യൂവിൽ ചേർത്തു, ഇതുവരെ ആരംഭിച്ചിട്ടില്ല
  RUNNING = "running", // ഹാൻഡ്ലർ വിളിച്ചു
  SUCCESS = "success", // ഹാൻഡ്ലർ സാധുവായ ഔട്ട്പുട്ട് തിരികെ നൽകി
  ERROR = "error", // ഹാൻഡ്ലർ ഒരു എക്സെപ്ഷൻ എറിഞ്ഞു
  TIMEOUT = "timeout", // എക്സിക്യൂട്ടറിന്റെ ടൈംഔട്ട് പരിധി കവിഞ്ഞു
}
```

> **കുറിപ്പ്**: `TIMEOUT` സ്റ്റാറ്റസ് enum-ൽ നിർവചിച്ചിട്ടുണ്ടെങ്കിലും, നിലവിലെ എക്സിക്യൂട്ടർ ഇംപ്ലിമെന്റേഷൻ അത് **യഥാർത്ഥത്തിൽ DB-യിലേക്ക് എഴുതുന്നില്ല** — ടൈംഔട്ടുകൾ `"Skill execution timed out"` എന്ന സന്ദേശത്തോടുകൂടിയ `ERROR` ആയി പ്രത്യക്ഷപ്പെടുന്നു. ഈ സ്റ്റാറ്റസ് enum ഭാവിയിലെ ഉപയോഗത്തിനായി മാറ്റിവെച്ചിരിക്കുന്നു.

### നിർവഹണങ്ങൾ പരിശോധിക്കൽ

```ts
import { skillExecutor } from "omniroute/skills/executor";

// ID ഉപയോഗിച്ച് ഒരു നിർദ്ദിഷ്ട നിർവഹണം നേടുക
const exec = skillExecutor.getExecution("exec-uuid-123");
if (exec) {
  console.log(`${exec.skillName}: ${exec.status} in ${exec.durationMs}ms`);
}

// ഒരു API കീയുടെ സമീപകാല നിർവഹണങ്ങൾ ലിസ്റ്റ് ചെയ്യുക
const recent = skillExecutor.listExecutions("api-key-id", 50, 0);
for (const e of recent) {
  console.log(`${e.skillName} → ${e.status} (${e.durationMs}ms)`);
}

// നിർവഹണങ്ങളുടെ ആകെ എണ്ണം കണക്കാക്കുക
const total = skillExecutor.countExecutions("api-key-id");
```

### പുനഃശ്രമ രീതി

`maxRetries` ക്രമീകരണം സംഭരിക്കപ്പെടുന്നുണ്ടെങ്കിലും എക്സിക്യൂട്ടറിന്റെ `execute()` മെത്തഡ് അത് **നിലവിൽ ഉപയോഗിക്കുന്നില്ല** — അത് ഒരൊറ്റ ശ്രമം മാത്രമാണ് നടത്തുന്നത്. ഭാവിയിലെ ഇംപ്ലിമെന്റേഷനും അത് വായിക്കേണ്ട ഹുക്കുകൾക്കുമായി `maxRetries` മൂല്യം ലഭ്യമാക്കിയിരിക്കുന്നു.

നിലവിൽ, പുനഃശ്രമങ്ങൾ സ്കിൽ ഹാൻഡ്ലറിനുള്ളിൽ തന്നെ ഇംപ്ലിമെന്റ് ചെയ്യണം. ബിൽറ്റ്-ഇൻ
സ്കില്ലുകൾ എക്സിക്യൂട്ടറിൽ രജിസ്റ്റർ ചെയ്യപ്പെടുന്നു (ഉദാ. `registerBuiltinSkills(executor)`
/ `src/lib/skills/builtin/`-ലെ `registerBrowserSkill(executor)`); നിങ്ങൾ രജിസ്റ്റർ ചെയ്യുന്ന ഏത് ഹാൻഡ്ലറിനും
സ്വന്തം പുനഃശ്രമ ലൂപ്പ് ഉൾപ്പെടുത്താം:

```ts
// ഒരു സ്കിൽ ഹാൻഡ്ലറിനുള്ളിൽ
async function handler(input, ctx) {
  const maxRetries = 3;
  let lastError: Error | null = null;

  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      return await fetchSomething(input);
    } catch (err) {
      lastError = err as Error;
      if (attempt < maxRetries) {
        await new Promise((r) => setTimeout(r, 1000 * attempt));
      }
    }
  }
  throw lastError;
}
```

## SkillMode വിശദമായി

`SkillMode` enum (`src/lib/skills/types.ts`) സ്കില്ലുകൾ **എപ്പോൾ, എങ്ങനെ** ആഹ്വാനം ചെയ്യപ്പെടണമെന്ന് നിയന്ത്രിക്കുന്നു:

```ts
enum SkillMode {
  AUTO = "auto", // സ്കിൽ എപ്പോൾ വിളിക്കണമെന്ന് LLM തീരുമാനിക്കുന്നു
  MANUAL = "manual", // ഉപയോക്താവിന്റെ വ്യക്തമായ അഭ്യർത്ഥനയിലൂടെ മാത്രം ആഹ്വാനം ചെയ്യപ്പെടുന്നു
  HYBRID = "hybrid", // AUTO സ്കോറിംഗ് + മാനുവൽ ഓവർറൈഡ്
}
```

> **കുറിപ്പ്**: കോഡ്ബേസ് `SkillMode` (AUTO/MANUAL/HYBRID) നിർവചിക്കുന്നു, എന്നാൽ `Skill.mode` ഫീൽഡ് മറ്റൊരു ഘടന (`"on" | "off" | "auto"`) ഉപയോഗിക്കുന്നു. അവ പരസ്പരം ബന്ധപ്പെട്ടവയാണെങ്കിലും ഒരേ കാര്യമല്ല — `SkillMode` എക്സിക്യൂട്ടർ നയത്തിനും `Skill.mode` ഓരോ സ്കില്ലും പ്രവർത്തനക്ഷമമാക്കുന്നതിനുമാണ്.

### ഓരോ മോഡും എപ്പോൾ ഉപയോഗിക്കണം

| മോഡ്     | LLM-ന്റെ പെരുമാറ്റം                                                                       | ഉപയോഗസാഹചര്യം                                                      |
| -------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `AUTO`   | ആവശ്യമാണെന്ന് തോന്നുമ്പോൾ LLM-ന് സ്കിൽ വിളിക്കാം                                          | പൊതുവായ ആവശ്യങ്ങൾക്കുള്ള സ്കില്ലുകൾ (ഫയൽ വായനകൾ, HTTP അഭ്യർത്ഥനകൾ) |
| `MANUAL` | LLM-ന് സ്കിൽ വിളിക്കാനാകില്ല; വ്യക്തമായ `executeSkill` API കോൾ മാത്രമേ അത് ആഹ്വാനം ചെയ്യൂ | സൂക്ഷ്മമായ പ്രവർത്തനങ്ങൾ (ഡാറ്റാബേസ് എഴുത്തുകൾ, പേയ്മെന്റുകൾ)      |
| `HYBRID` | LLM-ന് സ്കിൽ നിർദ്ദേശിക്കാം; ഉപയോക്താവ് സ്ഥിരീകരിക്കണം                                    | പാർശ്വഫലങ്ങളുള്ളതും എന്നാൽ അപകടകരമല്ലാത്തതുമായ സ്കില്ലുകൾ          |

### AUTO സ്കോറിംഗ്

`AUTO` മോഡ് സജീവമായിരിക്കുമ്പോൾ, ഓരോ കാൻഡിഡേറ്റ് സ്കില്ലിനും അഭ്യർത്ഥനയുടെ
സന്ദർഭവുമായി താരതമ്യം ചെയ്ത് `src/lib/skills/injection.ts`-ലെ `scoreAutoSkill()` വഴി സ്കോർ നൽകുന്നു — ഇത് ഒരു അഡിറ്റീവ്,
പൂർണ്ണസംഖ്യാ പോയിന്റ് സംവിധാനമാണ് (സ്കിൽ-പേര് പൊരുത്തം, പേര്/ടാഗ്/വിവരണം ടോക്കൺ ഓവർലാപ്പ്,
പശ്ചാത്തല-കാരണ സൂചനകൾ, പ്രൊവൈഡർ-സൂചന ബോണസ്/പിഴ). `score >= AUTO_MIN_SCORE = 3` ഉള്ളതിൽ ഏറ്റവും ഉയർന്ന സ്കോർ നേടിയ
`AUTO_MAX_SKILLS = 5` സ്കില്ലുകൾ വിളിക്കാവുന്ന ടൂളുകളായി ഇൻജക്റ്റ് ചെയ്യപ്പെടുന്നു;
തുല്യ സ്കോറുകൾ ആദ്യം `installCount` ഉപയോഗിച്ചും തുടർന്ന് പേര് ഉപയോഗിച്ചും വേർതിരിക്കുന്നു. ഈ ഡോക്യുമെന്റിൽ നേരത്തെ നൽകിയിരിക്കുന്ന
[**ടൂൾ സ്കീമ സൃഷ്ടിക്കൽ → AUTO സ്കോറിംഗ്**](#auto-scoring) എന്നതിൽ പൂർണ്ണ പോയിന്റ് പട്ടിക കാണുക;
ഫ്ലോട്ട് `0.6`-ശൈലിയിലുള്ള ത്രെഷോൾഡോ `registry.ts` സ്കോറിംഗോ ഇല്ല.

## ബിൽറ്റ്-ഇൻ സ്കില്ലുകളുടെ കാറ്റലോഗ്

`src/lib/skills/builtin/`-ൽ ശ്രദ്ധാപൂർവം തിരഞ്ഞെടുത്ത ഒരു കൂട്ടം ബിൽറ്റ്-ഇൻ സ്കില്ലുകളോടെയാണ് OmniRoute ലഭ്യമാകുന്നത്. ഏറ്റവും സാധാരണമായവ:

### ബ്രൗസർ ഓട്ടോമേഷൻ സ്കിൽ

ബ്രൗസർ സ്കിൽ (`src/lib/skills/builtin/browser.ts`) Playwright/Puppeteer വഴി ഹെഡ്ലെസ് ബ്രൗസർ ഓട്ടോമേഷൻ നൽകുന്നു. **ഇത് നടപ്പിലാക്കിയിട്ടുണ്ടെങ്കിലും ഡിഫോൾട്ട് സ്കിൽ കാറ്റലോഗിൽ ഉൾപ്പെടുത്തിയിട്ടില്ല** — ഇത് ഉപയോഗിക്കാൻ ബ്രൗസർ എക്സ്റ്റൻഷൻ പ്ലഗിൻ പ്രത്യേകം ഇൻസ്റ്റാൾ ചെയ്യുക.

```ts
// നിങ്ങളുടെ കോൺഫിഗിൽ പ്രവർത്തനക്ഷമമാക്കുക
const config: SkillConfig = {
  enabled: true,
  mode: SkillMode.MANUAL, // എല്ലായ്പ്പോഴും വ്യക്തമായ ആഹ്വാനം ആവശ്യപ്പെടുക
  allowedSkills: ["browser"],
  timeout: 60000, // പേജ് ലോഡുകൾക്ക് 60 സെക്കൻഡ്
  maxRetries: 1,
};
```
