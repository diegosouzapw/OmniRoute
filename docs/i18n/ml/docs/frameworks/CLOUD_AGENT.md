> **അവസാനം പുതുക്കിയത്:** 2026-06-28 — v3.8.40 (frontmatter പുതുക്കൽ; cursor-cloud ഉൾപ്പെടെ 4 ഏജന്റുകൾ)

മൂന്നാം കക്ഷി ക്ലൗഡ്-ഹോസ്റ്റഡ് കോഡിംഗ് ഏജന്റുകളെ (Codex Cloud, Cursor,
Devin, Jules) ദീർഘകാലം പ്രവർത്തിക്കുന്ന ടാസ്കുകളായി OmniRoute ഏകോപിപ്പിക്കുന്നു. ഓരോ ഏജന്റിനെയും ഒരേ രീതിയിലുള്ള ഇന്റർഫേസിന് പിന്നിൽ പൊതിഞ്ഞിരിക്കുന്നതിനാൽ,
ദാതാവിനനുസരിച്ചുള്ള API-കൾ കൈകാര്യം ചെയ്യാതെ തന്നെ ക്ലയന്റുകൾക്ക് ഒരു പ്രോംപ്റ്റും + റിപ്പോ URL-ഉം സമർപ്പിച്ച് ഫലങ്ങൾ സ്വീകരിക്കാം.

ഒരു Cloud Agent ടാസ്ക് സാധാരണ ചാറ്റ് കംപ്ലീഷൻ **അല്ല**. ഇത് മിനിറ്റുകൾ മുതൽ മണിക്കൂറുകൾ വരെ എടുത്തേക്കാവുന്ന, നിലനിൽക്കുന്ന, ഒന്നിലധികം ഘട്ടങ്ങളുള്ള
ഒരു പ്രവർത്തന യൂണിറ്റാണ്; ഇതിന് അതിന്റെ ആർട്ടിഫാക്റ്റായി ഒരു Pull Request സൃഷ്ടിക്കാനും,
തുടർ സന്ദേശങ്ങളെയും (ചില ദാതാക്കളിൽ) പ്ലാൻ അംഗീകാര ഗേറ്റുകളെയും പിന്തുണയ്ക്കാനും കഴിയും.

## പിന്തുണയ്ക്കുന്ന ഏജന്റുകൾ

| ദാതാവിന്റെ ID  | ക്ലാസ്             | ഉറവിടം                                | അപ്സ്ട്രീം അടിസ്ഥാന URL                 | പ്ലാൻ അംഗീകാരം |
| -------------- | ------------------ | ------------------------------------- | --------------------------------------- | -------------- |
| `jules`        | `JulesAgent`       | `src/lib/cloudAgent/agents/jules.ts`  | `https://jules.googleapis.com/v1alpha`  | ഉണ്ട്          |
| `devin`        | `DevinAgent`       | `src/lib/cloudAgent/agents/devin.ts`  | `https://api.devin.ai/v1`               | ഉണ്ട്          |
| `codex-cloud`  | `CodexCloudAgent`  | `src/lib/cloudAgent/agents/codex.ts`  | `https://api.openai.com/v1/codex/cloud` | ഇല്ല (സ്വയമേവ) |
| `cursor-cloud` | `CursorCloudAgent` | `src/lib/cloudAgent/agents/cursor.ts` | `https://api.cursor.com/v0`             | ഇല്ല (സ്വയമേവ) |

രജിസ്ട്രി: `src/lib/cloudAgent/registry.ts` — `getAgent(providerId)`,
`getAvailableAgents()`, `isCloudAgentProvider(providerId)` എന്നിവ എക്സ്പോർട്ട് ചെയ്യുന്നു. മൊഡ്യൂൾ ലോഡ് ചെയ്യുമ്പോൾ പോപ്പുലേറ്റ് ചെയ്യപ്പെടുന്ന
ഒരു സാധാരണ ഇൻ-മെമ്മറി `Record<string, CloudAgentBase>` ആണ് രജിസ്ട്രി.

## ആർക്കിടെക്ചർ

```
ക്ലയന്റ് (ഡാഷ്ബോർഡ് / CLI / API)
  → POST /api/v1/agents/tasks (മാനേജ്മെന്റ് ഓതന്റിക്കേഷൻ ആവശ്യമാണ്)
    → CreateCloudAgentTaskSchema സാധൂകരണം (Zod)
    → registry.getAgent(providerId)
    → getCloudAgentCredentials(providerId)
      └─ getProviderConnections({ provider, isActive: true })-ൽ നിന്ന് ലഭ്യമാക്കുന്നു
         (ആദ്യം apiKey, ലഭ്യമല്ലെങ്കിൽ accessToken ഉപയോഗിക്കുന്നു)
    → agent.createTask({ prompt, source, options }, credentials)
      └─ അപ്സ്ട്രീം ദാതാവിന്റെ API-യിലേക്കുള്ള HTTP POST
      └─ ആന്തരിക id + externalId സഹിതമുള്ള CloudAgentTask തിരികെ നൽകുന്നു
    → cloud_agent_tasks-ലേക്ക് (SQLite) insertCloudAgentTask(...)

പോളിംഗ് (വായിക്കുമ്പോഴുള്ള lazy sync):
  GET /api/v1/agents/tasks/[id]
    → getCloudAgentTaskById(id)
    → agent.getStatus(externalId, credentials)  // സ്റ്റാറ്റസും പ്രവർത്തനങ്ങളും പുതുക്കുന്നു
    → പുതിയ സ്റ്റാറ്റസ്, ഫലം, completed_at എന്നിവ ഉപയോഗിച്ച് updateCloudAgentTask(...)
    → സീരിയലൈസ് ചെയ്ത ടാസ്ക് തിരികെ നൽകുന്നു

ഇടപെടലുകൾ:
  POST /api/v1/agents/tasks/[id]  body: { action: "approve" | "message" | "cancel" }
    → "approve"-നായി agent.approvePlan(externalId, credentials)
    → "message"-നായി agent.sendMessage(externalId, message, credentials)
    → "cancel"-നായി സ്റ്റാറ്റസ് "cancelled" ആയി മാറുന്നു (ലോക്കലായി മാത്രം)
```

സമന്വയം **lazy** ആണ്: ഓരോ `GET /tasks/[id]` അഭ്യർത്ഥനയിലും അപ്സ്ട്രീമിൽ നിന്ന് സ്റ്റാറ്റസ് പുതുക്കുന്നു.
പശ്ചാത്തല പോളർ ഇല്ല. പുതിയ നില ആവശ്യമുള്ള ഡാഷ്ബോർഡുകൾ യുക്തിസഹമായ ഇടവേളകളിൽ GET
എൻഡ്പോയിന്റ് പോൾ ചെയ്യണം.

## `CloudAgentBase` ഇന്റർഫേസ്

ഉറവിടം: `src/lib/cloudAgent/baseAgent.ts`

```typescript
export interface AgentCredentials {
  apiKey: string;
  baseUrl?: string;
}

export interface CreateTaskParams {
  prompt: string;
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
}

export interface GetStatusResult {
  status: CloudAgentStatus;
  externalId?: string;
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
}

export abstract class CloudAgentBase {
  abstract readonly providerId: string;
  abstract readonly baseUrl: string;

  abstract createTask(p: CreateTaskParams, c: AgentCredentials): Promise<CloudAgentTask>;
  abstract getStatus(externalId: string, c: AgentCredentials): Promise<GetStatusResult>;
  abstract approvePlan(externalId: string, c: AgentCredentials): Promise<void>;
  abstract sendMessage(
    externalId: string,
    message: string,
    c: AgentCredentials
  ): Promise<CloudAgentActivity>;
  abstract listSources(
    c: AgentCredentials
  ): Promise<{ name: string; url: string; branch?: string }[]>;

  protected mapStatus(raw: string): CloudAgentStatus; // ഹ്യൂറിസ്റ്റിക് അപ്സ്ട്രീം സ്ട്രിങ് → enum
  protected generateTaskId(): string; // `task_<ts>_<rand>`
  protected generateActivityId(): string; // `act_<ts>_<rand>`
}
```

`CodexCloudAgent.approvePlan` മനഃപൂർവം എറർ ത്രോ ചെയ്യുന്നു — Codex Cloud സ്വയമേവ പ്ലാൻ ചെയ്യുന്നതിനാൽ
അതിന് അംഗീകാര ഗേറ്റ് ഇല്ല. `CodexCloudAgent.listSources`, `[]` റിട്ടേൺ ചെയ്യുന്നു.

`CursorCloudAgent`, അതിന്റെ ഔദ്യോഗിക REST API (`api.cursor.com/v0`) വഴി Cursor-ന്റെ
Background / Cloud Agents പ്രവർത്തിപ്പിക്കുന്നു; ഇതിനായി **ഉപയോക്തൃ അല്ലെങ്കിൽ സർവീസ്-അക്കൗണ്ട് API കീ** ഉപയോഗിക്കുന്നു — വിലക്ക് ലഭിക്കാനുള്ള സാധ്യതയെക്കുറിച്ചുള്ള മുന്നറിയിപ്പുള്ള `cursor`
പ്രൊവൈഡറായ Cursor IDE-യുടെ OAuth സെഷൻ വീണ്ടും ഉപയോഗിക്കുന്നതിനേക്കാൾ സുരക്ഷിതമായ,
ഔദ്യോഗിക ബദലാണിത്. ഇത് ഒരു സാധാരണ REST അഡാപ്റ്ററാണ് (`@cursor/sdk` നേറ്റീവ്
ഡിപ്പൻഡൻസി ഇല്ല). `approvePlan` എറർ ത്രോ ചെയ്യുന്നു (Cursor ഏജന്റുകൾ സ്വയംഭരണപരമായി പ്രവർത്തിക്കുന്നു); `listSources`,
കീയിലൂടെ ആക്സസ് ചെയ്യാവുന്ന റിപ്പോസിറ്ററികൾ ലിസ്റ്റ് ചെയ്യുന്നു. Cursor വലിയക്ഷരത്തിലുള്ള സ്റ്റാറ്റസ് enum-കൾ
(`CREATING`/`RUNNING`/`FINISHED`/`ERROR`) റിട്ടേൺ ചെയ്യുന്നു; അവ പങ്കിട്ടിരിക്കുന്ന
`CloudAgentStatus`-ലേക്ക് വ്യക്തമായി മാപ്പ് ചെയ്യപ്പെടുന്നു. കോഡ് മാറ്റമില്ലാതെ API വേർഷൻ/പാത്ത്
തിരുത്താൻ കഴിയുന്നവിധം ഓരോ ക്രെഡൻഷ്യലിനും `baseUrl` ഓവർറൈഡ് ചെയ്യാം.

## ഡൊമെയ്ൻ ടൈപ്പുകൾ

ഉറവിടം: `src/lib/cloudAgent/types.ts`

```typescript
export const CLOUD_AGENT_STATUS = {
  QUEUED: "queued",
  RUNNING: "running",
  AWAITING_APPROVAL: "awaiting_approval",
  COMPLETED: "completed",
  FAILED: "failed",
  CANCELLED: "cancelled",
} as const;

export interface CloudAgentSource {
  repoName: string;
  repoUrl: string; // സാധുവായ URL ആയിരിക്കണം
  branch?: string;
}

export interface CloudAgentResult {
  prUrl?: string;
  prNumber?: number;
  commitMessage?: string;
  diffUrl?: string;
  summary?: string;
  duration?: number; // സെക്കൻഡുകൾ, പോസിറ്റീവ് int
  cost?: number; // പോസിറ്റീവ് float
}

export interface CloudAgentActivity {
  id: string;
  type: "plan" | "command" | "code_change" | "message" | "error" | "completion";
  content: string;
  timestamp: string; // ISO 8601
  metadata?: Record<string, unknown>;
}

export interface CloudAgentTask {
  id: string; // ആന്തരിക `task_...` id
  providerId: "jules" | "devin" | "codex-cloud" | "cursor-cloud";
  externalId?: string; // അപ്സ്ട്രീം പ്രൊവൈഡറിന്റെ id
  status: CloudAgentStatus;
  prompt: string; // 1..10000 പ്രതീകങ്ങൾ
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
  createdAt: string;
  updatedAt: string;
  completedAt?: string;
}
```

വാലിഡേഷൻ സ്കീമകൾ (`CreateCloudAgentTaskSchema`, `UpdateCloudAgentTaskSchema`) ടൈപ്പുകൾക്കൊപ്പം
എക്സ്പോർട്ട് ചെയ്യപ്പെടുകയും റൂട്ട് ഹാൻഡ്ലറുകൾ ഉപയോഗിക്കുകയും ചെയ്യുന്നു.

## ഡാറ്റാബേസ്

ഉറവിടം: `src/lib/cloudAgent/db.ts` — `createCloudAgentTaskTable()` വഴി പട്ടിക ആവശ്യാനുസരണം സൃഷ്ടിക്കപ്പെടുന്നു (`src/lib/cloudAgent/index.ts`-ൽ മൊഡ്യൂൾ ഇംപോർട്ട് ചെയ്യുമ്പോഴും ഇത് വിളിക്കപ്പെടുന്നു).

```sql
CREATE TABLE IF NOT EXISTS cloud_agent_tasks (
  id           TEXT PRIMARY KEY,
  provider_id  TEXT NOT NULL,
  external_id  TEXT,
  status       TEXT NOT NULL DEFAULT 'queued',
  prompt       TEXT NOT NULL,
  source       TEXT NOT NULL,             -- JSON
  options      TEXT DEFAULT '{}',         -- JSON
  result       TEXT,                       -- JSON
  activities   TEXT DEFAULT '[]',          -- JSON
  error        TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_provider ON cloud_agent_tasks(provider_id);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_status   ON cloud_agent_tasks(status);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_created  ON cloud_agent_tasks(created_at DESC);
```

SQL ഇൻജെക്ഷൻ തടയുന്നതിനായി `updateCloudAgentTask` ഒരു **കോളം അനുവദനീയപട്ടിക** നിർബന്ധമാക്കുന്നു:
`status`, `prompt`, `source`, `options`, `result`, `activities`, `error`,
`completed_at`. ഭാഗിക അപ്ഡേറ്റിലുള്ള മറ്റേതെങ്കിലും കീ നിശ്ശബ്ദമായി ഒഴിവാക്കപ്പെടും.

## REST API — ടാസ്ക് ജീവിതചക്രം

**ഓതന്റിക്കേഷൻ:** എല്ലാ `/api/v1/agents/tasks*` എൻഡ്പോയിന്റുകൾക്കും **മാനേജ്മെന്റ് ഓതന്റിക്കേഷൻ** ആവശ്യമാണ് (`requireCloudAgentManagementAuth`, `src/lib/api/requireManagementAuth`-ൽ നിന്നുള്ള `requireManagementAuth`-നെ പൊതിയുന്നു). `588a0333`
(_"fix(auth): require management auth for agent and cooldown APIs"_) കമ്മിറ്റിന് ശേഷം ഇത് നിർബന്ധമാക്കിയിരിക്കുന്നു.

| രീതി    | പാത                           | ഉദ്ദേശ്യം                                                                        |
| ------- | ----------------------------- | -------------------------------------------------------------------------------- |
| OPTIONS | `/api/v1/agents/tasks`        | CORS പ്രീഫ്ലൈറ്റ്                                                                |
| GET     | `/api/v1/agents/tasks`        | ടാസ്കുകൾ പട്ടികപ്പെടുത്തുക (ഫിൽട്ടർ: `provider`, `status`, `limit≤500`)          |
| POST    | `/api/v1/agents/tasks`        | ടാസ്ക് സൃഷ്ടിക്കുക (അപ്സ്ട്രീമിലേക്ക് അയയ്ക്കുകയും നിലനിർത്തുകയും ചെയ്യുന്നു)    |
| DELETE  | `/api/v1/agents/tasks?id=...` | ക്വറി id ഉപയോഗിച്ച് ടാസ്ക് ഇല്ലാതാക്കുക (അപ്സ്ട്രീമിൽ റദ്ദാക്കുന്നില്ല)          |
| OPTIONS | `/api/v1/agents/tasks/[id]`   | CORS പ്രീഫ്ലൈറ്റ്                                                                |
| GET     | `/api/v1/agents/tasks/[id]`   | ടാസ്ക് വായിക്കുക + അപ്സ്ട്രീമിൽ നിന്ന് ആവശ്യാനുസരണം സ്റ്റാറ്റസ് സമന്വയിപ്പിക്കുക |
| POST    | `/api/v1/agents/tasks/[id]`   | പ്രവർത്തനം: `approve` / `message` / `cancel`                                     |
| DELETE  | `/api/v1/agents/tasks/[id]`   | പാത്തിലെ id ഉപയോഗിച്ച് ടാസ്ക് ഇല്ലാതാക്കുക                                       |

### ടാസ്ക് സൃഷ്ടിക്കുക

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Fix the bug in src/foo.ts where the parser returns null",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    },
    "options": {
      "autoCreatePr": true,
      "planApprovalRequired": false
    }
  }'
```

പ്രതികരണം `201`:

```json
{
  "data": {
    "id": "task_1731512345678_abc123def",
    "providerId": "devin",
    "externalId": "session_xyz",
    "status": "queued",
    "prompt": "...",
    "source": { "repoName": "user/repo", "repoUrl": "...", "branch": "main" },
    "options": { "autoCreatePr": true },
    "createdAt": "2026-05-13T12:34:56.789Z"
  }
}
```

### ഒരു പ്ലാൻ അംഗീകരിക്കുക

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"action":"approve"}'
```

### ഒരു തുടർസന്ദേശം അയയ്ക്കുക

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"message","message":"Also add a unit test for the parser"}'
```

### റദ്ദാക്കുക (ലോക്കൽ സ്റ്റാറ്റസ് മാത്രം)

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"cancel"}'
```

`cancel`, ലോക്കൽ DB-യിലെ `status`-നെ `"cancelled"` എന്നതിലേക്ക് മാറ്റുന്നു, എന്നാൽ അപ്സ്ട്രീം പ്രൊവൈഡറെ വിളിക്കുന്നില്ല — `CloudAgentBase`-ൽ അബോർട്ട് RPC ഇല്ല. അപ്സ്ട്രീം ബില്ലിംഗ് നിർത്താൻ, പ്രൊവൈഡറുടെ സ്വന്തം കൺസോളിൽ ടാസ്ക് അവസാനിപ്പിക്കുക.

## REST API — Cloud Provider പ്ലംബിംഗ്

`src/app/api/cloud/`-ന് കീഴിലുള്ള ഈ സഹായക എൻഡ്പോയിന്റുകൾ റിമോട്ട് ക്ലയന്റുകൾക്ക്
(CLI, Electron ആപ്പ്, അല്ലെങ്കിൽ സമന്വയ വർക്കറുകൾ) പ്രൊവൈഡർ കണക്ഷൻ മെറ്റാഡാറ്റ വായിക്കാനും
മോഡൽ അപരനാമങ്ങൾ പരിഹരിക്കാനും ഉപയോഗിക്കുന്നു. ടാസ്ക് എൻഡ്പോയിന്റുകൾ ഉപയോഗിക്കുന്ന മാനേജ്മെന്റ്
ഓതന്റിക്കേഷൻ അല്ല, മറിച്ച് (`validateApiKey` വഴി) ഒരു **സാധാരണ API കീ** ഉപയോഗിച്ചാണ് ഇവയുടെ ഓതന്റിക്കേഷൻ നടത്തുന്നത്.

| രീതി | പാത്ത്                          | ഉദ്ദേശ്യം                                                                                                            |
| ---- | ------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| POST | `/api/cloud/auth`               | API കീ സാധൂകരിച്ച്, മാസ്ക് ചെയ്ത കണക്ഷൻ മെറ്റാഡാറ്റയും മോഡൽ അപരനാമങ്ങളും തിരികെ നൽകുക                                |
| PUT  | `/api/cloud/credentials/update` | `accessToken` / `refreshToken` / `expiresAt` പുതുക്കുക                                                               |
| POST | `/api/cloud/model/resolve`      | ഒരു മോഡൽ അപരനാമത്തെ `{ provider, model }` ആയി പരിഹരിക്കുക                                                            |
| GET  | `/api/cloud/models/alias`       | എല്ലാ മോഡൽ അപരനാമങ്ങളും പട്ടികപ്പെടുത്തുക                                                                            |
| PUT  | `/api/cloud/models/alias`       | ഒരു മോഡൽ അപരനാമം സജ്ജീകരിക്കുക (പ്രവർത്തനക്ഷമമാക്കിയിട്ടുണ്ടെങ്കിൽ Cloud-ലേക്ക് സ്വയമേവ സമന്വയിപ്പിക്കുകയും ചെയ്യുക) |

`/api/cloud/auth` അസംസ്കൃതമായ `apiKey` / `accessToken` / `refreshToken` ഒരിക്കലും തിരികെ നൽകില്ല. ഇത്
`hasApiKey`, `hasAccessToken`, `hasRefreshToken` എന്നിവയും മാസ്ക് ചെയ്ത ഒരു പ്രിവ്യൂവും
(`maskedApiKey`: ആദ്യത്തെ 4 + `****` + അവസാനത്തെ 4) തിരികെ നൽകുന്നു.

## ക്രെഡൻഷ്യലുകളുടെ പരിഹാരം

`src/lib/cloudAgent/api.ts`-ലെ `getCloudAgentCredentials(providerId)`:

1. `getProviderConnections({ provider: providerId, isActive: true })` വഴി സജീവമായ പ്രൊവൈഡർ കണക്ഷനുകൾ ലോഡ് ചെയ്യുന്നു.
2. ഓരോ കണക്ഷനും, ആദ്യം `apiKey`-ന് (ട്രിം ചെയ്തത്) മുൻഗണന നൽകുന്നു. അതില്ലെങ്കിൽ `accessToken` ഉപയോഗിക്കുന്നു.
3. ശൂന്യമല്ലാത്ത ആദ്യ ടോക്കൺ `{ apiKey: token }` ആയി പൊതിഞ്ഞ് തിരികെ നൽകുന്നു.
4. ഉപയോഗിക്കാവുന്ന ടോക്കൺ കണ്ടെത്തിയില്ലെങ്കിൽ `null` തിരികെ നൽകുന്നു — API `400` എന്നതിനൊപ്പം
   `"No active credentials configured for cloud agent provider: <id>"` എന്ന് പ്രതികരിക്കുന്നു.

ഇതിനർത്ഥം, സാധാരണ LLM പ്രൊവൈഡറുകൾ ഉപയോഗിക്കുന്ന അതേ Provider Connection പട്ടിക തന്നെയാണ് Cloud Agents വീണ്ടും
ഉപയോഗിക്കുന്നത് എന്നാണ്. Jules പ്രവർത്തനക്ഷമമാക്കാൻ, `provider: "jules"` എന്നതും പൂരിപ്പിച്ച `apiKey`-ഉം ഉള്ള ഒരു സജീവ കണക്ഷൻ സൃഷ്ടിക്കുക.

## ഡാഷ്ബോർഡ്

ഉറവിടം: `src/app/(dashboard)/dashboard/cloud-agents/page.tsx`

ഇനിപ്പറയുന്ന കാര്യങ്ങൾ ചെയ്യുന്ന ഒരു `"use client"` React പേജ്:

- ടാസ്കുകൾ പട്ടികപ്പെടുത്തുന്നു (`GET /api/v1/agents/tasks` വഴി പോൾ ചെയ്യുന്നു).
- `CreateCloudAgentTaskSchema`-യിലേക്ക് മാപ്പ് ചെയ്യുന്ന ഒരു ഫോം വഴി പുതിയ ടാസ്കുകൾ സമർപ്പിക്കുന്നു.
- സ്റ്റാറ്റസ് ബാഡ്ജുകൾ (`queued`, `running`, `awaiting_approval`, `completed`,
  `failed`, `cancelled`) കാണിക്കുകയും `activities[]` ടൈംലൈൻ റെൻഡർ ചെയ്യുകയും ചെയ്യുന്നു.
- `status === "completed"` ആകുമ്പോൾ `result.prUrl` / `commitMessage` / `summary` പ്രദർശിപ്പിക്കുന്നു.

## A2A-യുമായുള്ള സംയോജനം

ഒരു A2A സ്കില്ലിന്റെ `tasks/send` ഹാൻഡ്ലർ `getAgent(...).createTask(...)`-ലേക്ക് ചുമതലപ്പെടുത്തുകയും A2A ടാസ്ക്
സ്റ്റാറ്റസ് ഇവന്റുകളെ JSON-RPC 2.0 പ്രോട്ടോക്കോളിലേക്ക് പരിവർത്തനം ചെയ്യുകയും ചെയ്യുന്ന വിധത്തിൽ ആ സ്കിൽ രജിസ്റ്റർ ചെയ്ത് Cloud Agents-നെ A2A സ്കില്ലുകളായി ലഭ്യമാക്കാം.
[A2A-SERVER.md](./A2A-SERVER.md) കാണുക.

## പുതിയൊരു Cloud Agent ചേർക്കൽ

1. `CloudAgentBase` വിപുലീകരിക്കുന്ന `src/lib/cloudAgent/agents/<name>.ts` സൃഷ്ടിക്കുക.
2. `createTask`, `getStatus`, `approvePlan` (അല്ലെങ്കിൽ ബാധകമല്ലെങ്കിൽ ഒരു പിശക് ത്രോ ചെയ്യുക),
   `sendMessage`, `listSources` എന്നിവ നടപ്പിലാക്കുക. സ്റ്റാറ്റസ് സാധാരണവൽക്കരണത്തിനായി `this.mapStatus(...)` ഉപയോഗിക്കുക.
3. സ്ഥിരതയുള്ള ഒരു `providerId`-ന് കീഴിൽ `src/lib/cloudAgent/registry.ts`-ൽ രജിസ്റ്റർ ചെയ്യുക.
4. `src/lib/cloudAgent/types.ts`-ലെ `providerId` ലിറ്ററൽ യൂണിയൻ വിപുലീകരിക്കുക
   (`CloudAgentTask.providerId`, `CreateCloudAgentTaskSchema` എന്നിവ).
5. ഒരു കണക്ഷൻ റെക്കോർഡ് ആവശ്യമാണെങ്കിൽ പ്രൊവൈഡറെ `src/shared/constants/providers.ts`-ലേക്ക് ചേർക്കുക.
   OAuth അടിസ്ഥാനമാക്കിയുള്ള പ്രൊവൈഡറുകൾക്ക് `src/lib/oauth/providers/`-ഉം ആവശ്യമാണ്.
6. `tests/unit/cloud-agent-*.test.ts`-ന് കീഴിൽ ടെസ്റ്റുകൾ ചേർക്കുക.
7. ഈ ഡോക്യുമെന്റും ഡാഷ്ബോർഡിന്റെ `CLOUD_AGENTS` സ്ഥിരാങ്കവും അപ്ഡേറ്റ് ചെയ്യുക.
