`devin-cli-agentic`, യഥാർത്ഥ Claude Code റൺടൈമിനെ OmniRoute-ന്റെ ലോക്കൽ Anthropic
Messages എൻഡ്പോയിന്റ് ഉപയോഗിക്കാൻ അനുവദിക്കുന്നു; അതേസമയം ഔദ്യോഗിക Devin CLI, ACP stdio വഴി മോഡൽ പ്രതികരണങ്ങൾ നൽകുന്നു. ഇത്
നിലവിലുള്ള Anthropic, Claude OAuth, Claude Web, അല്ലെങ്കിൽ `devin-cli` പ്രൊവൈഡറുകളിൽ മാറ്റം വരുത്തുന്നില്ല.

> **നിലവിലെ സ്ഥിതി: Claude Code `2.1.258`-ലേക്ക് പിൻ ചെയ്തിരിക്കുന്നു; ഓഫ്ലൈൻ, ലൈവ് സാധൂകരണം അവസാനമായി രേഖപ്പെടുത്തിയത്
> `2.1.220`-ലാണ്.** `2.1.220` പിൻ, Devin CLI
> `3000.2.17`, മോഡൽ `swe-1-7-lightning` എന്നിവയിലൂടെ മൂന്ന് ഒറ്റപ്പെട്ട സാഹചര്യങ്ങൾ പൂർത്തിയാക്കി; ആ അന്തിമ ലൈവ് റൺ ക്ലയന്റ് നിയന്ത്രിത `Read`,
> `Edit`, `Bash` ടേണുകൾ, വിജയകരമായ `npm test` ഫലങ്ങൾ, പ്രോജക്റ്റ് കമാൻഡ്, സ്കിൽ
> കണ്ടെത്തൽ, Devin-മാത്രമുള്ള റൂട്ടിംഗ്, Claude-ലേക്കുള്ള ഔട്ട്ബൗണ്ട് ട്രാഫിക് പൂർണ്ണമായും ഇല്ലാത്തത് എന്നിവ തെളിയിച്ചു. തുടർന്ന് പിൻ `2.1.258`-ലേക്ക് ഉയർത്തി
> (OmniRoute-ന്റെ Claude ഐഡന്റിറ്റി അനുകരിക്കുന്ന CLI തലമുറയും, Fable 5.1 ടയർ നേറ്റീവ് ആയി ഉൾപ്പെടുത്തുന്ന
> ആദ്യ പതിപ്പും). പുതിയ പിന്നിൽ, പിൻ ചെയ്ത ബേസ് ഇമേജിൽ ഇൻസ്റ്റാൾ ലെയറും `claude --version`-ഉം
> പരിശോധിച്ചു; കൂടാതെ ബ്രിഡ്ജ് യൂണിറ്റ് സ്യൂട്ട്, `compose config`, സ്റ്റാറ്റിക്
> ഐസൊലേഷൻ പ്രൂഫ് എന്നിവ വിജയിക്കുന്നു — എന്നാൽ ഓഫ്ലൈൻ മോക്ക് സാഹചര്യവും ലൈവ് മൂന്ന്-സാഹചര്യ
> സ്യൂട്ടും ഇതുവരെ വീണ്ടും റൺ ചെയ്തിട്ടില്ല. ഈ പിൻ ഉപയോഗിച്ച് ബ്രിഡ്ജിനെ ആശ്രയിക്കുന്നതിന് മുമ്പ് അവ വീണ്ടും റൺ ചെയ്യുക ("പിൻ ചെയ്ത ടൂളുകൾ അപ്ഡേറ്റ് ചെയ്യൽ" കാണുക).

## ആർക്കിടെക്ചർ

```text
Claude Code 2.1.258 (ഒറ്റപ്പെടുത്തിയ നോൺ-റൂട്ട് Linux കണ്ടെയ്നർ)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-ഫോർമാറ്റ്, ഓതന്റിക്കേഷൻ ആവശ്യമില്ലാത്ത പ്രൊവൈഡർ)
  -> devin acp --agent-type summarizer (ഔദ്യോഗിക ACP stdio, Devin ടൂളുകളില്ല)
  -> സമർപ്പിത devin-auth വോളിയത്തിലുള്ള Devin അക്കൗണ്ട്
```

ഔദ്യോഗിക CLI-യുടെ ഡിഫോൾട്ട് ACP ഏജന്റിന് സ്വന്തം ടൂളുകൾ പ്രവർത്തിപ്പിക്കാൻ കഴിയുന്നതിനാൽ, ഈ ബ്രിഡ്ജ്
അത് ഉപയോഗിക്കുന്നില്ല. ടൂളുകളൊന്നുമില്ലാത്ത ഔദ്യോഗിക CLI മോഡിലുള്ള സ്ഥിരനിശ്ചിത `summarizer` ACP ഏജന്റിനെ ഇത് ആരംഭിക്കുകയും
സീരിയലൈസ് ചെയ്ത Anthropic അഭ്യർത്ഥനയെ ഒരു എക്സിക്യൂഷൻ ട്രേസായി ഫ്രെയിം ചെയ്യുകയും ചെയ്യുന്നു. Claude നിയന്ത്രിക്കുന്ന മറ്റൊരു
പ്രവർത്തനം ആവശ്യമായി വരുമ്പോൾ, പ്രതികരണത്തിൽ കൃത്യമായി ഒരു ക്ലയന്റ് ടൂൾ എൻവലപ്പ് ഉണ്ടായിരിക്കണം. ഏതെങ്കിലും ACP
`tool_call` അല്ലെങ്കിൽ `tool_call_update`, പ്രതികരണം വിജയകരമാണെന്ന് റിപ്പോർട്ട് ചെയ്യുന്നതിന് മുമ്പ് നിരസിക്കപ്പെടും.

`open-sse/executors/devin-agentic/serializer.ts`-ലെ സീരിയലൈസർ, `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice`, കൂടാതെ
Claude Code നൽകുന്ന ടൂളുകൾ എന്നിവ നിലനിർത്തുന്നു. ചിത്രങ്ങളും തിരിച്ചറിയാത്ത ബ്ലോക്കുകളും വ്യക്തമായ പരാജയത്തിലേക്ക് നയിക്കും. വലിയ ടൂൾ ഫലങ്ങളിൽ
ദൃശ്യമാകുന്ന ഒരു ട്രങ്കേഷൻ മാർക്കർ ഉപയോഗിക്കുന്നു.

ഓരോ മോഡൽ ടേണിലും സ്വതന്ത്രമായ ഒരു `<tool>{...}</tool>` എൻവലപ്പ് പാർസർ സ്വീകരിക്കുന്നു. അഭ്യർത്ഥനയിലെ ടൂൾ ലിസ്റ്റുമായി
പേര് പൊരുത്തപ്പെടുന്നുണ്ടോ എന്ന് ഇത് പരിശോധിക്കുന്നു, ആ ടൂളിന്റെ JSON
Schema അനുസരിച്ച് ആർഗ്യുമെന്റുകൾ സാധൂകരിക്കുന്നു, വിവരണവും പ്രവർത്തനങ്ങളും കലർത്തിയത് നിരസിക്കുന്നു, കൂടാതെ പരിധിയുള്ള ഒരു പരിഹാരശ്രമം അനുവദിക്കുന്നു. തുടർന്ന് Claude Code
ലഭിച്ച Anthropic `tool_use` ലോക്കലായി പ്രവർത്തിപ്പിക്കുകയും `tool_result` OmniRoute വഴി
തിരികെ അയയ്ക്കുകയും ചെയ്യുന്നു.

## ഐസൊലേഷനും ഭീഷണി മോഡലും

ഹോസ്റ്റിലെ Claude ഇൻസ്റ്റലേഷൻ, അക്കൗണ്ട്, കോൺഫിഗറേഷൻ എന്നിവ പരിധിക്ക് പുറത്തുള്ളവയും
വിലക്കപ്പെട്ടവയുമായി കണക്കാക്കപ്പെടുന്നു. Compose സർവീസുകൾ:

- UID/GID `10001:10001` ആയി, റീഡ്-ഒൺലി റൂട്ട് ഫയൽസിസ്റ്റം, നീക്കം ചെയ്ത ക്യാപബിലിറ്റികൾ, കൂടാതെ
  `no-new-privileges` ഉപയോഗിച്ച് പ്രവർത്തിക്കുന്നു;
- സ്വകാര്യ `/home/bridge`, സമർപ്പിത Claude കോൺഫിഗറേഷൻ വോളിയം, ഒറ്റപ്പെടുത്തിയ OmniRoute ഡാറ്റ,
  കൂടാതെ പ്രത്യേക `devin-auth` വോളിയം എന്നിവ ഉപയോഗിക്കുന്നു;
- താൽക്കാലിക `.sandbox` വർക്ക്സ്പേസുകൾ/തെളിവുകൾ മാത്രം മൗണ്ട് ചെയ്യുന്നു;
- ഹോസ്റ്റ് ഹോം, Keychain, SSH, ക്ലൗഡ് ക്രെഡൻഷ്യലുകൾ, അല്ലെങ്കിൽ Docker സോക്കറ്റ് എന്നിവ മൗണ്ട് ചെയ്യുന്നില്ല;
- വ്യക്തമായ എൻവയോൺമെന്റുകൾ നിർമിക്കുകയും Anthropic API/OAuth/റൂട്ടിംഗ് വേരിയബിളുകൾ നീക്കം ചെയ്യുകയും ചെയ്യുന്നു;
- ലോക്കൽ-മാത്രം ഉപയോഗിക്കുന്ന ഒരു കീ ഉപയോഗിച്ച് Claude Code ഇൻഫറൻസിനെ `http://omniroute:20128`-ലേക്ക് മാത്രം നയിക്കുന്നു.

ഓഫ്ലൈൻ പ്രൊഫൈൽ ഒരു ഇന്റേണൽ നെറ്റ്വർക്ക് ഉപയോഗിക്കുന്നു. ലൈവ് പ്രൊഫൈലിൽ, OmniRoute ഔദ്യോഗിക
Devin എൻഡ്പോയിന്റുകളിലേക്ക് `network-guard` വഴി മാത്രം എത്തുന്നു; ബന്ധമില്ലാത്ത ലക്ഷ്യസ്ഥാനങ്ങൾ നിരസിക്കപ്പെടുന്നു.
Claude Code-ന് പ്രത്യേകമായി എല്ലാ എഗ്രസും നിരസിക്കുന്ന ഗാർഡ് ഉണ്ട്; `NO_PROXY` വഴി ലോക്കൽ OmniRoute
സർവീസിലേക്ക് മാത്രമേ അതിന് എത്താനാകൂ. ഗാർഡ് ഓഡിറ്റ് ഫയലുകൾ അവയുടെ ഗാർഡ് പ്രോസസ് മാത്രം മൗണ്ട് ചെയ്യുന്നു. സ്ക്രിപ്റ്റുകൾ
ടോക്കൺ രഹിത തെളിവുകൾ എക്സ്പോർട്ട് ചെയ്യുന്നതിന് മുമ്പ് ഫയൽ ഉടമസ്ഥത, മോഡ്, ലിങ്ക് എണ്ണം, ഓരോ തീരുമാനവും പരിശോധിക്കുന്നു.

ഐസൊലേഷൻ പ്രൂഫ് സ്വതന്ത്രമായി റൺ ചെയ്യുക:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

ഇത് ടോപ്പോളജി, നാമകരണം ചെയ്ത മൗണ്ടുകൾ, നോൺ-റൂട്ട്/റീഡ്-ഒൺലി ക്രമീകരണങ്ങൾ, വ്യക്തമായ ലോക്കൽ റൂട്ടിംഗ്,
സെൻസിറ്റീവ് എൻവയോൺമെന്റ് വേരിയബിളുകളുടെ അഭാവം, Docker സോക്കറ്റിന്റെ അഭാവം, `api.anthropic.com`, `claude.ai` എന്നിവയിലേക്കുള്ള
തടഞ്ഞ ആക്സസ്, Devin-മാത്രമുള്ള പ്രൊവൈഡർ തിരഞ്ഞെടുപ്പ്, ACP ബാക്ക്എൻഡ് ലഭ്യമല്ലാത്തപ്പോൾ വ്യക്തമായ പരാജയം
എന്നിവ സാധൂകരിക്കുന്നു.

## ആദ്യ സജ്ജീകരണവും സാധാരണ ഉപയോഗവും

പിൻ ചെയ്ത ഇമേജ് ബിൽഡ് ചെയ്യുക:

```bash
./scripts/devin-bridge/build
```

ഒറ്റപ്പെടുത്തിയ Devin വോളിയം മാത്രം പ്രാമാണീകരിക്കുക:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

റിമോട്ട്/കണ്ടെയ്നർ പരിതസ്ഥിതികൾക്കായി ഉദ്ദേശിച്ചിട്ടുള്ള ഔദ്യോഗിക മാനുവൽ-ടോക്കൺ രീതിയാണ് ലോഗിൻ കമാൻഡ് ഉപയോഗിക്കുന്നത്. മൂല്യം CLI പ്രോംപ്റ്റിൽ നേരിട്ട് നൽകുന്നു; അത് പ്രോസസ് ആർഗ്യുമെന്റായി കൈമാറുകയോ Git-ലേക്ക് എഴുതുകയോ ഹോസ്റ്റിൽ നിന്ന് പകർത്തുകയോ ചെയ്യുന്നില്ല.

ഒറ്റപ്പെടുത്തിയ Claude Code റൺടൈം ആരംഭിക്കുക:

```bash
./scripts/devin-bridge/launch
```

കണ്ടെയ്നറൈസ് ചെയ്ത Claude Code ആരംഭിക്കുന്നതിന് മുമ്പ് `launch`, ഐസൊലേഷൻ, Devin പ്രാമാണീകരണം, മോഡൽ കണ്ടെത്തൽ എന്നിവ വീണ്ടും പരിശോധിക്കുന്നു. ഇത് ഒരിക്കലും ഹോസ്റ്റിലെ Claude എക്സിക്യൂട്ടബിൾ പ്രവർത്തിപ്പിക്കില്ല. മോഡൽ അപരനാമങ്ങൾ `.env.devin-bridge`-ൽ സജ്ജീകരിക്കാം; കോൺഫിഗർ ചെയ്ത എല്ലാ മൂല്യങ്ങളിലും `devin-cli-agentic/` പ്രിഫിക്സ് നിലനിർത്തണം.

## സാധൂകരണ കമാൻഡുകൾ

പുനരാവർത്തിക്കാവുന്ന ഓഫ്ലൈൻ പാതയ്ക്ക് Devin അക്കൗണ്ട് ആവശ്യമില്ല, കൂടാതെ റൺടൈം ഇന്റർനെറ്റ് ആക്സസും ഇല്ല:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

പ്രാമാണീകരിച്ച, തിരഞ്ഞെടുക്കാവുന്ന ലൈവ് പാത:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

ACP സെഷനുകൾ ഒരുമിച്ച് തുറക്കുന്നത് ഒഴിവാക്കാൻ ലൈവ് റണ്ണർ ഓരോ സാഹചര്യത്തിനിടയിലും കാത്തിരിക്കുകയും വാചകരൂപത്തിലുള്ള അവകാശവാദങ്ങൾ വിശ്വസിക്കുന്നതിനുപകരം ഘടനാബദ്ധമായ Claude സ്ട്രീം ഇവന്റുകൾ സാധൂകരിക്കുകയും ചെയ്യുന്നു. അതിന്റെ മൂന്ന് സാഹചര്യങ്ങൾ ഇനിപ്പറയുന്നവ തെളിയിക്കുന്നു:

1. നേരിട്ടുള്ള പ്രോജക്റ്റ് വായനയും തകരാർ വിശകലനവും;
2. ഒരു യഥാർത്ഥ `Edit`, ക്ലയന്റ് നിയന്ത്രിക്കുന്ന `Bash` `npm test`, ഒരു അന്തിമ ഫലം;
3. `/bridge-check`, `bridge-proof` കണ്ടെത്തൽ, പ്രോജക്റ്റ് വായനകൾ, ക്ലയന്റ് നിയന്ത്രിക്കുന്ന മറ്റൊരു വിജയകരമായ `npm test`, തീർപ്പാക്കാത്ത ജോലികളില്ലാതെയുള്ള പൂർത്തീകരണം.

അവസാന ഗേറ്റ് Devin നെറ്റ്വർക്ക് ഓഡിറ്റും പരിശോധിക്കുകയും Claude എഗ്രസ് ഓഡിറ്റ് ശൂന്യമായി തുടരണമെന്ന് ആവശ്യപ്പെടുകയും ചെയ്യുന്നു.

## പിൻ ചെയ്ത ടൂളുകൾ അപ്ഡേറ്റ് ചെയ്യൽ

`docker/devin-bridge/Dockerfile`-ൽ ഇമേജ് Node, Claude Code, Devin CLI എന്നിവ പിൻ ചെയ്യുന്നു. അപ്ഡേറ്റ് ചെയ്യാൻ:

1. വ്യക്തമായി നൽകിയിരിക്കുന്ന പതിപ്പുകൾ മാറ്റുക;
2. ഔദ്യോഗിക ആർട്ടിഫാക്റ്റിന്റെ മൂല്യങ്ങൾ ഉപയോഗിച്ച് ആർക്കിടെക്ചർ-നിർദ്ദിഷ്ടമായ രണ്ട് Devin ആർക്കൈവ് ചെക്ക്സങ്ങളും മാറ്റിസ്ഥാപിക്കുക;
3. വീണ്ടും ബിൽഡ് ചെയ്ത് എല്ലാ ഓഫ്ലൈൻ സാധൂകരണ കമാൻഡുകളും പ്രവർത്തിപ്പിക്കുക;
4. ഇമേജിനുള്ളിലെ പതിപ്പുകൾ സ്ഥിരീകരിക്കുക;
5. പ്രാമാണീകരിച്ച മൂന്ന്-സാഹചര്യ ലൈവ് സ്യൂട്ട് വീണ്ടും പ്രവർത്തിപ്പിക്കുക.

ഹോസ്റ്റിൽ ഒരു CLI-യും ഗ്ലോബലായി ഇൻസ്റ്റാൾ ചെയ്യരുത്; ചെക്ക്സം സ്ഥിരീകരണത്തിന് പകരം സ്ഥിരീകരിക്കാത്ത ഡൗൺലോഡ് ഉപയോഗിക്കരുത്.

## രോഗനിർണയവും വൃത്തിയാക്കലും

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  ലോക്കൽ റൂട്ടിംഗും ശുദ്ധീകരിച്ച എക്സിക്യൂട്ടർ പിശകുകളും കാണിക്കുന്നു.
- `.sandbox/evidence/mock-acp.jsonl` നിർണായകമായ മോക്ക് ACP പ്രവർത്തനങ്ങൾ രേഖപ്പെടുത്തുന്നു.
- `.sandbox/evidence/claude-stream.jsonl` യഥാർത്ഥ Claude Code ഓഫ്ലൈൻ റൺ രേഖപ്പെടുത്തുന്നു.
- `.sandbox/evidence/live-*.jsonl` സാധൂകരിച്ച മൂന്ന് ലൈവ് സ്ട്രീമുകൾ രേഖപ്പെടുത്തുന്നു.
- `.sandbox/evidence/egress.jsonl`, `.sandbox/evidence/claude-egress.jsonl` എന്നിവ ഗാർഡ് ഓഡിറ്റുകളുടെ സാധൂകരിച്ച, ടോക്കൺ-രഹിത പകർപ്പുകളാണ്.

ലോഗിൻ/കോൺഫിഗ് വോളിയങ്ങൾ നിലനിർത്തിക്കൊണ്ട് ഉടമസ്ഥതയിലുള്ള കണ്ടെയ്നറുകളും നെറ്റ്വർക്കുകളും നിർത്തുക:

```bash
./scripts/devin-bridge/clean
```

നെയിംഡ് വോളിയങ്ങൾ ഉൾപ്പെടെ ബ്രിഡ്ജിന്റെ ഉടമസ്ഥതയിലുള്ള മുഴുവൻ പരിതസ്ഥിതിയും നീക്കം ചെയ്യുക:

```bash
./scripts/devin-bridge/clean --all
```

## പരിമിതികൾ

- Devin CLI `3000.2.17` ഒരു നിഷ്പക്ഷമായ, ടൂളുകളില്ലാത്ത ACP ഏജന്റിനെ ലഭ്യമാക്കാത്തതിനാൽ, ബ്രിഡ്ജ് ടൂളുകളില്ലാത്ത സ്ഥിരമായ `summarizer` റോളിനെ ആശ്രയിക്കുന്നു. സംഗ്രഹ-രൂപത്തിലുള്ള ഇടക്കാല പ്രതികരണങ്ങളെ അഡാപ്റ്റർ പരിഹരിക്കുന്നുണ്ടെങ്കിലും, പരിധിബദ്ധമായ ഒരു അറ്റകുറ്റപ്പണി ശ്രമം ഇപ്പോഴും വ്യക്തമായി പരാജയപ്പെടാം.
- തത്സമയ ACP കോളുകൾക്ക് താൽക്കാലികമായ `502`/`504` പ്രതികരണങ്ങൾ ലഭിക്കാം. ഹാർനെസ് സാഹചര്യങ്ങൾക്കിടയിൽ ഇടവേള നൽകുന്നു; തുടർച്ചയായ പരാജയമുണ്ടായാൽ fail-closed നില തുടരുകയും മറ്റൊരു പ്രൊവൈഡറെ ഒരിക്കലും തിരഞ്ഞെടുക്കാതിരിക്കുകയും ചെയ്യും.
- ഓരോ Anthropic അഭ്യർത്ഥനയിൽനിന്നും ACP സന്ദർഭം പുനർനിർമ്മിക്കപ്പെടുന്നു; പ്രോസസ്/സെഷൻ അഫിനിറ്റി ഇല്ല.
- ഓരോ മോഡൽ പ്രതികരണത്തിലും ഒരു ടൂൾ കോൾ പിന്തുണയ്ക്കുന്നു; സമാന്തര കോളുകൾ നിരസിക്കപ്പെടുന്നു.
- ചിത്രങ്ങൾക്ക് വ്യക്തമായി പിന്തുണയില്ല. വിഷൻ, തിങ്കിങ് ഔട്ട്പുട്ട്, എഫർട്ട് നിയന്ത്രണങ്ങൾ, 1M സന്ദർഭ വിൻഡോ എന്നിവ പരസ്യപ്പെടുത്തുന്നില്ല.
- SSE സാധുവായ Anthropic ലൈഫ്സൈക്കിൾ ഇവന്റുകൾ ഉപയോഗിക്കുന്നു, എന്നാൽ പരിധിബദ്ധമായ ACP ടേൺ ശേഖരിച്ചതിന് ശേഷമാണ് അത് എമിറ്റ് ചെയ്യപ്പെടുന്നത്; ACP ചങ്കുകൾ ക്രമാനുഗതമായി ഫോർവേഡ് ചെയ്യപ്പെടുന്നില്ല.
