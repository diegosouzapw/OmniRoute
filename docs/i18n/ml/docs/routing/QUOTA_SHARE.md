## അവലോകനം

Quota Sharing Engine, ഒരേ കണക്ഷൻ പങ്കിടുന്ന ഒന്നിലധികം API കീകൾക്കിടയിൽ ഒരു പ്രൊവൈഡറുടെ സമയാധിഷ്ഠിത ക്വോട്ട (ഉദാ. Codex
5-മണിക്കൂർ വിൻഡോ, Kimi 1500 req/h) ന്യായമായി വിതരണം ചെയ്യുന്നു.

**ഇത് പരിഹരിക്കുന്ന പ്രശ്നം:** OmniRoute, ഒരേ അപ്സ്ട്രീം പ്രൊവൈഡർ അക്കൗണ്ടിനെതിരെ നിരവധി API കീകൾ പ്രോക്സി ചെയ്യുന്നു.
പങ്കിടൽ ലോജിക് ഇല്ലെങ്കിൽ, കീ A-യിൽ നിന്നുള്ള പെട്ടെന്നുള്ള അഭ്യർത്ഥനാവർധന ആ മണിക്കൂറിലേക്കുള്ള
പ്രൊവൈഡർ ക്വോട്ട മുഴുവൻ ഉപയോഗിച്ചുതീർക്കാം; വിൻഡോ റീസെറ്റ് ചെയ്യുന്നതുവരെ കീകൾ B, C എന്നിവ ബ്ലോക്ക് ചെയ്യപ്പെടും.
എഞ്ചിൻ ഇത് തടയുന്നത് ഇപ്രകാരമാണ്:

1. ഓരോ ഡൈമെൻഷനിലും (%, അഭ്യർത്ഥനകൾ, ടോക്കണുകൾ, $) ഓരോ കീയുടെയും റോളിംഗ് ഉപഭോഗം ട്രാക്ക് ചെയ്യുന്നു.
2. വർക്കിനെ സംരക്ഷിക്കുന്ന ഫെയർ-ഷെയർ അൽഗോരിതം പ്രയോഗിക്കുന്നു: ഗ്ലോബൽ പൂൾ സാച്ചുറേറ്റ് ആയിട്ടില്ലെങ്കിൽ ഒരു കീക്ക് ഉപയോഗത്തിലില്ലാത്ത
   ഷെയറുകളിൽനിന്ന് കടമെടുക്കാം.
3. അഭ്യർത്ഥന അപ്സ്ട്രീം എക്സിക്യൂട്ടറിൽ എത്തുന്നതിനുമുമ്പ് ഹോട്ട് പാത്തിൽ (`chatCore.ts`) ഫലം നടപ്പിലാക്കുന്നു.

## അൽഗോരിതം: വർക്കിനെ സംരക്ഷിക്കുന്ന ഫെയർ-ഷെയർ

`src/lib/quota/fairShare.ts`-ൽ നടപ്പിലാക്കിയിരിക്കുന്നു.

### മോഡുകൾ

| വ്യവസ്ഥ                                    | മോഡ്          | പെരുമാറ്റം                                                       |
| ------------------------------------------ | ------------- | ---------------------------------------------------------------- |
| `globalUsedPercent < saturationThreshold`  | **ഉദാരമായത്** | ഉപയോഗിച്ച ആകെ അളവ് കുറച്ചുള്ള ഗ്ലോബൽ പരിധിവരെ കീക്ക് കടമെടുക്കാം |
| `globalUsedPercent >= saturationThreshold` | **കർശനമായത്** | വ്യക്തിഗത ന്യായമായ വിഹിതം കർശനമായി നടപ്പിലാക്കുക                 |

ഡിഫോൾട്ട് `saturationThreshold = 0.5` (env `QUOTA_SATURATION_THRESHOLD`).

### ഓരോ ഡൈമെൻഷനിലുമുള്ള തീരുമാനം

പൂളിലെ ഓരോ സജീവ ഡൈമെൻഷനും എഞ്ചിൻ ഇനിപ്പറയുന്നവ കണക്കാക്കുന്നു:

```
fairShareAllowed = poolLimit × (allocationWeight / 100)
consumed        = ഈ കീയുടെ നിലവിലെ റോളിംഗ് മൂല്യം (QuotaStore.peek-ൽനിന്ന്)
remaining       = fairShareAllowed - consumed
```

തുടർന്ന്:

- **`policy = hard`**: `consumed > fairShareAllowed` ആയിരിക്കുകയും മോഡ് കർശനമായിരിക്കുകയും ചെയ്താൽ → **ബ്ലോക്ക് ചെയ്യുക**.
- **`policy = soft`**: `consumed > fairShareAllowed` ആയിരിക്കുകയും മോഡ് കർശനമായിരിക്കുകയും ചെയ്താൽ → **പിഴ ചുമത്തുക** (കോംബോയിൽ മുൻഗണന കുറയ്ക്കുക; ഒരിക്കലും ഹാർഡ്-ബ്ലോക്ക് ചെയ്യരുത്).
- **`policy = burst`**: ന്യായമായ വിഹിതം പരിഗണിക്കാതെ, ഗ്ലോബൽ ശേഷി ലഭ്യമായിരിക്കുന്നിടത്തോളം അനുവദിക്കുക.

### സമ്പൂർണ്ണ പരിധി

ഒരു അലോക്കേഷനിലെ `capValue` + `capUnit`, മോഡിൽനിന്നോ
പോളിസിയിൽനിന്നോ സ്വതന്ത്രമായ ഹാർഡ് പരിധിയാണ്. `consumed >= capValue` ആയ ഏതൊരു ഡൈമെൻഷനും എല്ലായ്പ്പോഴും അഭ്യർത്ഥനയെ **ബ്ലോക്ക് ചെയ്യുന്നു**.

### മൾട്ടി-ഡൈമെൻഷൻ പരിശോധന

പൂളിലെ **ഏതെങ്കിലും** ഡൈമെൻഷൻ അഭ്യർത്ഥനയെ ബ്ലോക്ക് ചെയ്യുമെങ്കിൽ, അത് ബ്ലോക്ക് ചെയ്യപ്പെടും. ഡൈമെൻഷനുകൾ
സ്വതന്ത്രമാണ് — 5h% തീർന്നുപോകുന്നത് weekly% ഡൈമെൻഷനെ ബാധിക്കില്ല.

### കടമെടുക്കൽ

ഉദാരമായ മോഡിൽ, അലോക്കേഷൻ പൂർണ്ണമായി ഉപയോഗിക്കാത്ത ഒരു കീക്ക് മറ്റ് കീകളുടെ
അലോക്കേറ്റ് ചെയ്യാത്ത വിഹിതങ്ങളിൽനിന്നുള്ള മിച്ചം ഉപയോഗിക്കാം. ഫോർമുല:

```
maxAllowed = globalLimit - consumedByOtherKeys
```

ഇവിടെ `consumedByOtherKeys = consumedTotal - consumedByThisKey`. ഗ്ലോബൽ പരിധി
(ആ ഡൈമെൻഷനുള്ള പൂളിന്റെ `limit`) എല്ലായ്പ്പോഴും ഹാർഡ് പരിധിയാണ്.

## സ്ലൈഡിംഗ് വിൻഡോ കൗണ്ടർ

`src/lib/quota/sqliteQuotaStore.ts`, `redisQuotaStore.ts` എന്നിവയിൽ നടപ്പിലാക്കിയിരിക്കുന്നു.

ഓരോ `(apiKeyId, dimensionKey)`-നും രണ്ട് ബക്കറ്റുകൾ:

- `curr`: നിലവിലെ ബക്കറ്റ് (`floor(nowMs / windowMs)`)
- `prev`: മുമ്പത്തെ ബക്കറ്റ് (`curr - 1`)

ഫലപ്രദമായ റോളിംഗ് മൂല്യം:

```
effectiveBucketIndex = floor(nowMs / windowMs)
bucketStartMs        = effectiveBucketIndex × windowMs
elapsed              = nowMs - bucketStartMs
weight               = 1 - elapsed / windowMs

effective = prev × weight + curr
```

**കൃത്യത**: ~99% കൃത്യം. ബക്കറ്റുകൾക്കിടയിലെ അതിർത്തിയിൽ പിശക് വിൻഡോ വലുപ്പത്തിന്റെ പരമാവധി 1% മാത്രമാണ്
(2-ബക്കറ്റ് ഏകദേശീകരണത്തിന്റെ അന്തർലീനമായ സവിശേഷത).

### കൺകറൻസി

SQLite ഡ്രൈവർ: ഓരോ `(apiKeyId | dimensionKey)` കീയ്ക്കുമുള്ള ഇൻ-മെമ്മറി മ്യൂട്ടക്സ്
read-modify-write റേസ് തടയുന്നു. ഈ പാറ്റേൺ `src/sse/services/auth.ts`-ലെ anti-thundering-herd മാതൃക പിന്തുടരുന്നു.

Redis ഡ്രൈവർ: അറ്റോമിക് ഇൻക്രിമെന്റിനുള്ള Lua EVAL സ്ക്രിപ്റ്റ് — ഒറ്റ Redis കമാൻഡായി പ്രവർത്തിക്കുന്നു.

## ഡ്രൈവറുകൾ

### SQLite (ഡിഫോൾട്ട്, ഇൻസ്റ്റാളേഷൻ ആവശ്യമില്ല)

- പട്ടിക: `quota_consumption` (മൈഗ്രേഷൻ `073_quota_pools.sql` / `074_quota_consumption.sql` കാണുക).
- ഒറ്റ ഇൻസ്റ്റൻസ് വിന്യാസങ്ങൾക്ക് ഏറ്റവും അനുയോജ്യം.
- എല്ലാ സ്ഥിരസംഭരണവും നിലവിലുള്ള OmniRoute SQLite DB-യിലാണ് (`DATA_DIR/storage.sqlite`).

### Redis (ഐച്ഛികം, മൾട്ടി-ഇൻസ്റ്റൻസ്)

- `ioredis` npm പാക്കേജ് ആവശ്യമാണ്.
- കൗണ്ടറുകൾ Redis-ൽ സംഭരിക്കുന്നു; മെറ്റാഡാറ്റ (പൂളുകൾ/അലോക്കേഷനുകൾ) തുടർന്നും SQLite-ൽ സൂക്ഷിക്കുന്നു.
- കൗണ്ടറുകൾ പങ്കിടേണ്ട മൾട്ടി-റെപ്ലിക്ക വിന്യാസങ്ങൾക്ക് ഏറ്റവും അനുയോജ്യം.

### ഡ്രൈവറുകൾ മാറുന്നത്

ക്രമീകരണ UI (`/dashboard/settings` → Quota Store) വഴിയോ env vars വഴിയോ:

```bash
QUOTA_STORE_DRIVER=redis
QUOTA_STORE_REDIS_URL=redis://localhost:6379
```

env-നേക്കാൾ DB ക്രമീകരണത്തിനാണ് മുൻഗണന. `driver=redis` ആയിരിക്കെ URL ഇല്ലെങ്കിലോ
`ioredis` ഇൻസ്റ്റാൾ ചെയ്തിട്ടില്ലെങ്കിലോ, ഫാക്ടറി SQLite-ലേക്ക് തിരികെ മാറുകയും ഒരു മുന്നറിയിപ്പ് ലോഗ് ചെയ്യുകയും ചെയ്യും.

ഡ്രൈവർ തിരഞ്ഞെടുക്കുന്ന ക്രമം:

1. DB ക്രമീകരണം `quotaStore.driver`
2. Env `QUOTA_STORE_DRIVER`
3. ഡിഫോൾട്ട്: `sqlite`

## ബഹു-ഡൈമെൻഷൻ

ഒരു പൂളിന് ഒന്നിലധികം ഡൈമെൻഷനുകൾ ഉണ്ടായിരിക്കാം. ഓരോ ഡൈമെൻഷനും സ്വതന്ത്രമാണ്:

```ts
QuotaDimension {
  unit: "percent" | "requests" | "tokens" | "usd",
  window: "5h" | "hourly" | "daily" | "weekly" | "monthly",
  limit: number,  // ഈ ഡൈമെൻഷനുള്ള ഗ്ലോബൽ പൂളിന്റെ പരമാവധി പരിധി
}
```

**ഉദാഹരണം: Codex പ്ലാൻ** (5h% + weekly%):

```json
[
  { "unit": "percent", "window": "5h", "limit": 100 },
  { "unit": "percent", "window": "weekly", "limit": 100 }
]
```

അനുവദിക്കപ്പെടാൻ ഒരു അഭ്യർത്ഥന എല്ലാ ഡൈമെൻഷനുകളും പാലിക്കണം.

## പൈപ്പ്ലൈൻ സംയോജനം

### PRE ഹുക്ക് (`open-sse/handlers/chatCore.ts`)

ഓതന്റിക്കേഷനും പോളിസി പരിശോധനകൾക്കും ശേഷം, അപ്സ്ട്രീം എക്സിക്യൂട്ടറിന് മുമ്പായി പ്രവർത്തിക്കുന്നു:

```
resolveComboTargets / handleSingleModel
  → enforceQuotaShare(apiKeyId, connectionId, provider, estimatedCost)
      → ഓരോ ഡൈമെൻഷനും getQuotaStore().peek()
      → fairShare.decideFairShare()
      → ബ്ലോക്ക് ചെയ്യുകയാണെങ്കിൽ → 429 മടക്കുക (buildErrorBody, Hard Rule #12)
      → അനുവദിക്കുകയും + മുൻഗണന കുറയ്ക്കുകയും ചെയ്താൽ → കാൻഡിഡേറ്റിൽ quotaSoftPenalty=true സജ്ജമാക്കുക
  → executor.execute()
```

**ഫെയിൽ-ഓപ്പൺ**: `enforceQuotaShare` എറർ എറിഞ്ഞാൽ, ഒരു `pino.warn` ലോഗോടെ
അഭ്യർത്ഥന അനുവദിക്കും. ക്വാട്ട എഞ്ചിനിലെ ഒരു ബഗ് എല്ലാ ട്രാഫിക്കും തടയുന്നത് ഇത് ഒഴിവാക്കുന്നു.

### POST ഹുക്ക് (ഉപഭോഗം രേഖപ്പെടുത്തുക)

വിജയകരമായ ഒരു റെസ്പോൺസിന് ശേഷം:

```
executor വിജയം മടക്കുന്നു
  → spendRecorder.recordConsumption(apiKeyId, connectionId, provider, actualCost)
      → ഓരോ ഡൈമെൻഷനും getQuotaStore().consume()
      → ഫെയിൽ-ഓപ്പൺ: എററുകൾ pino.warn ആയി ലോഗ് ചെയ്യുന്നു, ക്ലയന്റിലേക്ക് ഒരിക്കലും പ്രചരിപ്പിക്കില്ല
```

**ഡ്രിഫ്റ്റ് കുറിപ്പ്**: റെസ്പോൺസിന് ശേഷം `consume` പരാജയപ്പെട്ടാൽ, റോളിംഗ് കൗണ്ടർ യഥാർഥത്തേക്കാൾ കുറച്ച് എണ്ണും.
പ്രൊവൈഡറിൽനിന്നുള്ള സാച്ചുറേഷൻ സിഗ്നൽ (ഉദാ. `anthropic-ratelimit-unified-5h-utilization`)
അടുത്ത അഭ്യർത്ഥനയിൽ ഗ്ലോബൽ എസ്റ്റിമേറ്റ് തിരുത്തുന്നു.

### കോംബോ സോഫ്റ്റ് പെനാൽറ്റി (`open-sse/services/combo.ts`)

`decision.deprioritize === true` ആയിരിക്കുമ്പോൾ:

```ts
if (candidate.quotaSoftPenalty) {
  score *= QUOTA_SOFT_DEPRIORITIZE_FACTOR; // ഡിഫോൾട്ട് 0.7
}
```

മറ്റെല്ലാ സ്കോറിംഗ് ഘടകങ്ങൾക്കും ശേഷമാണ് പെനാൽറ്റി പ്രയോഗിക്കുന്നത്. ഇത് സാച്ചുറേറ്റഡ് ആയ ഒരു കീ ഹാർഡ്-ബ്ലോക്ക് ചെയ്യാതെ തന്നെ
അതിനെ തിരഞ്ഞെടുക്കാനുള്ള ഓട്ടോ-കോംബോ സാധ്യത കുറയ്ക്കുന്നു.

## പ്രശ്നപരിഹാരം

### Redis കോൺഫിഗർ ചെയ്തിട്ടുണ്ടെങ്കിലും കണക്റ്റ് ചെയ്യുന്നില്ല

`ioredis` ഇൻസ്റ്റാൾ ചെയ്തിട്ടുണ്ടെന്നും (`npm ls ioredis`) `QUOTA_STORE_REDIS_URL`
ആക്സസ് ചെയ്യാനാകുമെന്നും പരിശോധിക്കുക. കണക്ഷൻ പരാജയപ്പെട്ടാൽ ഫാക്ടറി SQLite-ലേക്ക് ഫാൾബാക്ക് ചെയ്യുന്നു
(`warn`-ൽ ലോഗ് ചെയ്യുന്നു).

### `peek` പഴയ ഡാറ്റ നൽകുന്നു / ഫെയിൽ-ഓപ്പൺ ചെയ്യുന്നു

`peek` എറർ നൽകിയാൽ, `enforceQuotaShare` ഫലത്തെ "അനുവദിക്കുക" (ഫെയിൽ-ഓപ്പൺ) ആയി കണക്കാക്കുന്നു.
മൂലകാരണം തിരിച്ചറിയാൻ `quota:enforce`, `quota:factory` എൻട്രികൾക്കായി `pino` ലോഗുകൾ
പരിശോധിക്കുക.

### ഉപഭോഗ കൗണ്ടറിലെ വ്യതിയാനം

യഥാർഥ പ്രൊവൈഡർ ഉപയോഗം കൗണ്ടറുകളിൽ നിന്ന് വ്യത്യസ്തമാണെങ്കിൽ അത് പ്രതീക്ഷിക്കാവുന്നതാണ് —
2-ബക്കറ്റ് സ്ലൈഡിങ് വിൻഡോയ്ക്ക് വിൻഡോ അതിരുകളിൽ ~1% പിശകുണ്ട്, കൂടാതെ `consume`
റെസ്പോൺസിന് ശേഷം ഫയർ-ആൻഡ്-ഫോർഗെറ്റ് രീതിയിലാണ്. സാച്ചുറേഷൻ സിഗ്നൽ (`saturationSignals.ts`)
30 സെക്കൻഡ് TTL ഉപയോഗിച്ച് യഥാർഥ പ്രൊവൈഡർ ഉപയോഗനില വായിക്കുകയും അതനുസരിച്ച് `globalUsedPercent`
ക്രമീകരിക്കുകയും ചെയ്യുന്നു.

### ബേൺ റേറ്റിനായി പൂൾ "ഡാറ്റയില്ല" എന്ന് കാണിക്കുന്നു

`computeBurnRate`-ന് കുറഞ്ഞത് 2 ചരിത്ര സാമ്പിളുകളെങ്കിലും ആവശ്യമാണ്. മുമ്പ്
`consume` കോളുകൾ ഇല്ലാത്ത പുതിയ പൂളുകൾ `tokensPerSecond: 0`, `timeToExhaustionMs: null` എന്നിവ കാണിക്കും.

## localStorage-ൽ നിന്നുള്ള മൈഗ്രേഷൻ

`/dashboard/costs/quota-share` ആദ്യമായി ലോഡ് ചെയ്യുമ്പോൾ, `useLocalStoragePoolMigration`
ഹുക്ക് ഇനിപ്പറയുന്നവ പരിശോധിക്കുന്നു:

1. `localStorage.getItem("omniroute:quota-share:pools")` ശൂന്യമല്ല.
2. `GET /api/quota/pools` `[]` മടക്കിനൽകുന്നു (DB ശൂന്യമാണ്).

രണ്ടും ശരിയാണെങ്കിൽ, ഓരോ ലെഗസി പൂളും ബാച്ചായി `POST /api/quota/pools`-ലേക്ക് പോസ്റ്റ് ചെയ്യുകയും,
തുടർന്ന് localStorage കീ നീക്കം ചെയ്യുകയും ചെയ്യുന്നു. മൈഗ്രേഷൻ ഐഡംപൊട്ടന്റാണ്: വ്യവസ്ഥ 2
വീണ്ടും മൈഗ്രേറ്റ് ചെയ്യുന്നത് തടയുന്നു.

## ആന്തരിക സ്ട്രാറ്റജി വർഗ്ഗീകരണം

`quota-share` ഒരു **ആന്തരിക ഉപയോഗത്തിന് മാത്രമുള്ള** റൂട്ടിംഗ് സ്ട്രാറ്റജിയാണ് (`src/shared/constants/routingStrategies.ts`-ലെ
`INTERNAL_ROUTING_STRATEGY_VALUES`). ഇത് സിസ്റ്റം സൃഷ്ടിച്ച
`qtSd/` പൂൾ കോംബോകൾ മാത്രം ഉപയോഗിക്കുന്നു. UI-യിലോ API-യിലോ ഉപയോക്താവിന് തിരഞ്ഞെടുക്കാവുന്ന ഓപ്ഷനായി ഒരിക്കലും
ദൃശ്യമാകാതിരിക്കാൻ ഇത് ഉദ്ദേശപൂർവം `ROUTING_STRATEGY_VALUES`-ൽ നിന്ന് ഒഴിവാക്കിയിരിക്കുന്നു.

## DB സ്കീമ സംഗ്രഹം

`078`, `079`, `085` മൈഗ്രേഷനുകൾ ചേർത്ത മൂന്ന് പട്ടികകൾ:

- `quota_pools` + `quota_allocations` — പൂൾ നിർവചനങ്ങളും ഓരോ കീയ്ക്കുമുള്ള അലോക്കേഷനുകളും.
- `quota_consumption` — ഓരോ `(apiKeyId, dimensionKey)`-നുമുള്ള റോളിംഗ് 2-ബക്കറ്റ് കൗണ്ടറുകൾ.
- `provider_plans` — മാനുവൽ പ്രൊവൈഡർ പ്ലാൻ ഓവർറൈഡുകൾ (ഓരോ connectionId-നുമുള്ള dimensions JSON).

എല്ലാ പട്ടികകളും ഐഡംപൊട്ടന്റ് `CREATE TABLE IF NOT EXISTS` മൈഗ്രേഷനുകൾ വഴിയാണ് ചേർത്തത്.
