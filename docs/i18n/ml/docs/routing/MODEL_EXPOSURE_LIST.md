> തിരഞ്ഞെടുക്കുകയാണെങ്കിൽ മാത്രം പ്രവർത്തനക്ഷമമാകുന്നത്, ഡിഫോൾട്ടായി പ്രവർത്തനരഹിതം (`modelVisibilityAllowlist`/`modelVisibilityDenylist` രണ്ടും ശൂന്യമാണെങ്കിൽ
> `/v1/models` കാറ്റലോഗും എല്ലാ `auto/*` കാൻഡിഡേറ്റ് പൂളുകളും ബൈറ്റ്-തലത്തിൽ സമാനമായി തുടരും). ചെലവുമായി യാതൊരു ബന്ധവുമില്ലാത്ത
> കാരണങ്ങളാൽ ക്രമീകരിച്ച മോഡൽ ലിസ്റ്റ് ആവശ്യമുള്ള ഓപ്പറേറ്റർമാർക്കായി
> `hidePaidModels`/`hideAutoCombos` (`src/lib/db/settings.ts`) എന്നിവയുടെ സമാനതലത്തിലുള്ള ഒരു ക്രമീകരണം.

## ഇത് നിലനിൽക്കുന്നതിന്റെ കാരണം

`hidePaidModels` "ഈ മോഡൽ സൗജന്യമാണോ?" എന്ന ചോദ്യത്തിനും `hideAutoCombos` "`auto/*`
വെർച്വൽ id-കൾ പരസ്യപ്പെടുത്തണോ?" എന്ന ചോദ്യത്തിനും ഉത്തരം നൽകുന്നു — എന്നാൽ ഒരു ഓപ്പറേറ്റർക്ക്
മോഡലുകളുടെ ഏതെങ്കിലും ഉപഗണം ഇഷ്ടാനുസൃതമായി ക്രമീകരിക്കാൻ ഇവയൊന്നും അനുവദിക്കുന്നില്ല (ഉദാ. വിലനിർണ്ണയത്തിൽനിന്ന് സ്വതന്ത്രമായി,
ഒരു നിർദ്ദിഷ്ട Claude Code / OpenCode ക്ലയന്റ് കാണേണ്ട മോഡലുകൾ കൃത്യമായി അവതരിപ്പിക്കുന്നത്).
#11481 ഇത് സ്വതന്ത്രമായ, തിരഞ്ഞെടുക്കുകയാണെങ്കിൽ മാത്രം പ്രവർത്തനക്ഷമമാകുന്ന രണ്ട് സ്ട്രിംഗ്-അറേ ക്രമീകരണങ്ങളായി ചേർക്കുന്നു.

## ക്രമീകരണങ്ങൾ

| കീ                         | തരം        | ഡിഫോൾട്ട് | അർത്ഥം                                                                                                       |
| -------------------------- | ---------- | --------- | ------------------------------------------------------------------------------------------------------------ |
| `modelVisibilityDenylist`  | `string[]` | `[]`      | ഒരു കാൻഡിഡേറ്റുമായി പൊരുത്തപ്പെടുന്ന എൻട്രികൾ അതിനെ കാറ്റലോഗിൽനിന്നും കാൻഡിഡേറ്റ് പൂളിൽനിന്നും മറയ്ക്കുന്നു. |
| `modelVisibilityAllowlist` | `string[]` | `[]`      | ശൂന്യമല്ലാത്തപ്പോൾ, ഒരു കാൻഡിഡേറ്റുമായി പൊരുത്തപ്പെടുന്ന എൻട്രികൾ മാത്രം ദൃശ്യമാക്കി നിലനിർത്തുന്നു.         |

രണ്ടിലും പരമാവധി 200 പ്രതീകങ്ങൾ വീതമുള്ള 500 എൻട്രികൾ വരെ സ്വീകരിക്കാം
(`src/shared/validation/settingsSchemas.ts`-ൽ Zod ഉപയോഗിച്ച് സാധൂകരിക്കുന്നു). ഒരു എൻട്രി ഇനിപ്പറയുന്നവയിൽ ഒന്നാണ്:

- കൃത്യമായ ഒരു കാറ്റലോഗ് id — `"gpt-4o"` (പ്രൊവൈഡർ പ്രിഫിക്സ് ഇല്ലാത്ത മോഡൽ id) അല്ലെങ്കിൽ `"openai/gpt-4o"` (പ്രൊവൈഡർ പ്രിഫിക്സോടുകൂടിയത്), അല്ലെങ്കിൽ
- `*`/`?` ഉപയോഗിക്കുന്ന ഒരു ഗ്ലോബ് പാറ്റേൺ — ഉദാ. `"openai/gpt-4*"` അല്ലെങ്കിൽ `"anthropic/*"` — ഇത്
  `ModelRoutingSection`-ന്റെ ഓരോ മോഡലിനുമുള്ള കോംബോ മാപ്പിങ്ങുകളിലും `freeModels.ts::matchesOnlyPaidModels`-ലും ഇതിനകം ഉപയോഗിക്കുന്ന
  അതേ പങ്കിട്ട `globToRegex()` മാച്ചർ (`src/shared/utils/globPattern.ts`) വഴി പരിഹരിക്കുന്നു.

മുൻഗണന: ഡിനൈലിസ്റ്റാണ് ആദ്യം പരിശോധിക്കുന്നത് (നിരസിക്കപ്പെട്ട ഒരു എൻട്രി അലൗലിസ്റ്റുമായും
പൊരുത്തപ്പെട്ടാലും എല്ലായ്പ്പോഴും മറച്ചിരിക്കും); അലൗലിസ്റ്റ് ശൂന്യമല്ലാത്തപ്പോൾ, അതുമായി പൊരുത്തപ്പെടുന്ന എൻട്രികൾ മാത്രമേ ശേഷിക്കൂ.

## ഒന്നല്ല, രണ്ട് ചോക്ക്പോയിന്റുകൾ

#6512-ൽനിന്നുള്ള പാഠം (ഒരു `hidePaidModels`-മാത്രമുള്ള കാറ്റലോഗ് ഫിൽട്ടർ, കോംബോ കാൻഡിഡേറ്റ് പൂൾ
സ്വതന്ത്രമായി നിർമ്മിച്ചതിനാൽ, ഒരു പണമടയ്ക്കേണ്ട മോഡലിലേക്ക് റൂട്ട് ചെയ്യാൻ `auto/*`-നെ അപ്പോഴും അനുവദിച്ചിരുന്നു) ഇവിടെയും അതേപടി ബാധകമാണ്.
പൊരുത്തപ്പെടുത്തൽ പ്രെഡിക്കേറ്റ് ആയ `isModelExposureAllowed()` (`src/shared/utils/modelExposureList.ts`)
താഴെപ്പറയുന്ന രണ്ടിടത്തുനിന്നും വിളിക്കുന്നു:

- `src/app/api/v1/models/catalog.ts` — `/v1/models` ലിസ്റ്റിങ് തന്നെ; `shouldHidePaid()` ഇതിനകം നിയന്ത്രിക്കുന്ന,
  ഓരോ സ്രോതസ്സിനുമുള്ള അതേ 5 ചോക്ക്പോയിന്റുകളിൽ (സ്റ്റാറ്റിക് `PROVIDER_MODELS`, സമന്വയിപ്പിച്ച പ്രൊവൈഡർ റോകൾ,
  ഇഷ്ടാനുസൃത റോകൾ, അലിയാസ് പിന്തുണയുള്ള റോകൾ, മാനേജ്ഡ്-ഫാൾബാക്ക് റോകൾ).
- `open-sse/services/autoCombo/modelExposureFilter.ts::filterModelExposureCandidates()` — സമാനമായ
  `filterPaidOnlyCandidates()` കോളിന് തൊട്ടുപിന്നാലെ `virtualFactory.ts::buildPreparedPool`-ൽനിന്ന് വിളിക്കുന്നു;
  അതിനാൽ നിരസിക്കപ്പെട്ട ഒരു മോഡലിനെയും ഒരു `auto/*` കാൻഡിഡേറ്റ് പൂളിലേക്ക് ഒരിക്കലും തിരഞ്ഞെടുക്കാനാവില്ല.

## ഫിൽട്ടർ ചെയ്യാത്തവ

`hideAutoCombos`-ന്റെ നിലവിലുള്ള പെരുമാറ്റത്തെ അനുകരിക്കുന്നു: **വ്യക്തമായി** അയച്ച ഒരു മോഡൽ id (`auto/*` വഴിയല്ലാതെയും
കാറ്റലോഗ് ലിസ്റ്റിങ്ങിലൂടെ കണ്ടെത്തിയതല്ലാതെയും) ഡിസ്പാച്ച് സമയത്ത് ഒരിക്കലും തടയപ്പെടില്ല — പരസ്യപ്പെടുത്തൽ/കാൻഡിഡേറ്റ്-പൂൾ അംഗത്വം
മാത്രമാണ് ഫിൽട്ടർ ചെയ്യുന്നത്. ഇത് `hidePaidModels`-ൽനിന്ന് സ്വതന്ത്രമാണ്;
ചെലവുമായി യാതൊരു ബന്ധവുമില്ലാത്ത കാരണങ്ങളാൽ ഒരു ഓപ്പറേറ്റർക്ക് ക്രമീകരിച്ച ഒരു ഗണം ആവശ്യമായേക്കാം, അതിനാൽ
`catalog.ts`-ലെ നിലവിലുള്ള മൾട്ടി-ഫ്ലാഗ് സംയോജനത്തിലെന്നപോലെ, രണ്ട് ക്രമീകരണങ്ങളും സ്വതന്ത്രമായ AND-ചെയ്ത ഫിൽട്ടറുകളായി സംയോജിക്കുന്നു.

ക്രമീകരണ എക്സ്പോർട്ടിൽ (`GET /api/settings/export-json`) മറ്റേതൊരു ക്രമീകരണ ഫീൽഡിലെയും പോലെ രണ്ട് അറേകളും അതേപടി ഉൾപ്പെടുന്നു
— `hidePaidModels`-ന്റെ കോംബോ-സ്റ്റെപ്പ് എക്സ്പോർട്ട് ഫിൽട്ടറിൽനിന്ന് വ്യത്യസ്തമായി, ഇവിടെ വീണ്ടും ഹൈഡ്രേറ്റ് ചെയ്യപ്പെടാനുള്ള
അപകടസാധ്യതയില്ല: എക്സ്പോർട്ട് ചെയ്ത കോംബോ സ്റ്റെപ്പിൽ ഉൾച്ചേർത്ത ഒരു നിരസിക്കപ്പെട്ട id എന്നത് ഓപ്പറേറ്ററുടെ സ്വന്തം വ്യക്തമായ റൂട്ടിങ്
തിരഞ്ഞെടുപ്പാണ്; എക്സ്പോർട്ട് അതിർത്തി നീക്കംചെയ്യേണ്ട ഒന്നല്ല അത്.
