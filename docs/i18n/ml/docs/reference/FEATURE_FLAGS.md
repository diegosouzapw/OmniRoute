> പുനർവിന്യാസം നടത്താതെ തന്നെ OmniRoute-ന്റെ പ്രവർത്തനം മാറ്റുന്ന റൺടൈം ടോഗിളുകൾ.
> ഇവിടെ പട്ടികപ്പെടുത്തിയിരിക്കുന്ന ഓരോ ഫ്ലാഗും
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> എന്നതിൽ നിർവചിച്ചിരിക്കുന്നു — ഇതാണ് ഏക ആധികാരിക ഉറവിടം. ഡാഷ്ബോർഡും REST API-യും
> ആ ഫയലിൽ നിന്നാണ് വായിക്കുന്നത്, അതിനാൽ താഴെയുള്ള പട്ടിക അതുമായി 1:1 ആയി പൊരുത്തപ്പെടുന്ന രീതിയിൽ സൃഷ്ടിച്ചിരിക്കുന്നു.

## ഫീച്ചർ ഫ്ലാഗുകൾ എന്താണ്

ഫീച്ചർ ഫ്ലാഗ് എന്നത് പേര് നൽകിയിട്ടുള്ള ഒരു ടോഗിളാണ് (boolean അല്ലെങ്കിൽ enum). അതിന്റെ മൂല്യം
റൺടൈമിൽ മാറ്റാനും ഡാറ്റാബേസിൽ നിലനിർത്താനും കഴിയും; പ്രോസസ്സ് പുനർവിന്യസിക്കേണ്ട ആവശ്യമില്ല. ഓരോ
ഫ്ലാഗും `key`, `label`, `description`, `category`, `defaultValue`, `type`,
എന്നിവയും `requiresRestart` സൂചനയും ഉൾക്കൊള്ളുന്ന ഒരു `FeatureFlagDefinition` ഉപയോഗിച്ചാണ് വിവരിക്കുന്നത്.

### നിർണ്ണയ മുൻഗണനാക്രമം

ഒരു ഫ്ലാഗിന്റെ **പ്രാബല്യത്തിലുള്ള മൂല്യം**
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) ഉപയോഗിച്ച് ഇനിപ്പറയുന്ന
മുൻഗണനാക്രമത്തിൽ നിർണ്ണയിക്കപ്പെടുന്നു (ഏറ്റവും ഉയർന്ന മുൻഗണനയുള്ളത് പ്രാബല്യത്തിൽ വരും):

1. **DB ഓവർറൈഡ്** — `feature_flags` നെയിംസ്പേസിന് കീഴിലുള്ള `key_value`
   പട്ടികയിൽ സംഭരിച്ചിരിക്കുന്ന മൂല്യം (ഡാഷ്ബോർഡ് അല്ലെങ്കിൽ REST API വഴി സജ്ജീകരിച്ചത്).
2. **പരിസ്ഥിതി വേരിയബിൾ** — സജ്ജീകരിച്ചിട്ടുള്ളതും ശൂന്യമല്ലാത്തതുമാണെങ്കിൽ `process.env[<KEY>]`.
3. **നിർവചനത്തിലെ ഡിഫോൾട്ട്** — `featureFlagDefinitions.ts`-ൽ നിന്നുള്ള `defaultValue`.

ഒരു boolean ഫ്ലാഗിന്റെ പ്രാബല്യത്തിലുള്ള മൂല്യം `"true"`, `"1"`, അല്ലെങ്കിൽ `"yes"`
ആയിരിക്കുമ്പോൾ അത് **പ്രവർത്തനക്ഷമമാക്കിയതായി** കണക്കാക്കുന്നു (`isFeatureFlagEnabled()` കാണുക).

> [!NOTE]
> ഭൂരിഭാഗം ഫ്ലാഗുകൾക്കും [`ENVIRONMENT.md`](./ENVIRONMENT.md)-ൽ രേഖപ്പെടുത്തിയിട്ടുള്ള,
> **അതേ പേരിലുള്ള** ഒരു പൊരുത്തപ്പെടുന്ന പരിസ്ഥിതി വേരിയബിളും ഉണ്ട്. ഫ്ലാഗിന്റെ DB ഓവർറൈഡിന്
> ആ പരിസ്ഥിതി വേരിയബിളിനെക്കാൾ മുൻഗണനയുണ്ട്. `requiresRestart: true` ഉള്ള ഒരു ഫ്ലാഗ്
> ഉടൻതന്നെ നിലനിർത്തപ്പെടുമെങ്കിലും പ്രോസസ്സ് ആരംഭിക്കുമ്പോൾ മാത്രമേ വീണ്ടും വായിക്കപ്പെടുകയുള്ളൂ
> — അത് ടോഗിൾ ചെയ്യുമ്പോൾ ഡാഷ്ബോർഡിൽ **"സെർവർ പുനരാരംഭിക്കുക"** എന്ന ബാനർ ദൃശ്യമാകും.

## ഫ്ലാഗ് കാറ്റലോഗ്

> `INJECTION_GUARD_BLOCK_THRESHOLD`-ഉം `INJECTION_GUARD_MODE`-ന്റെ `block`
> മോഡ് ക്രമീകരിക്കുന്നു, എന്നാൽ അവ
> [`src/shared/utils/injectionSeverity.ts`](../../src/shared/utils/injectionSeverity.ts)
> വായിക്കുന്ന സാധാരണ എൻവയോൺമെന്റ് വേരിയബിളുകളാണ്, ഫീച്ചർ ഫ്ലാഗുകളല്ല: അവയ്ക്ക് DB
> ഓവർറൈഡോ ഡാഷ്ബോർഡ് ടോഗിളോ ഇല്ല. കാണുക:
> [`ENVIRONMENT.md`](./ENVIRONMENT.md#4-security--authentication).

> [!NOTE]
> `Restart` കോളം `requiresRestart: true` ഉള്ള ഫ്ലാഗുകളെ അടയാളപ്പെടുത്തുന്നു — മൂല്യം
> തൽക്ഷണം നിലനിർത്തപ്പെടുമെങ്കിലും പ്രോസസ് വീണ്ടും ലോഡ് ചെയ്തതിനുശേഷം മാത്രമേ പ്രാബല്യത്തിൽ വരൂ. Enum
> ഫ്ലാഗുകൾ അവയുടെ അനുവദനീയമായ സെറ്റിന് പുറത്തുള്ള ഏത് മൂല്യവും നിരസിക്കുന്നു (`setFeatureFlagOverride()`-ലും
> REST `PUT` ഹാൻഡ്ലറിലും സെർവർ-സൈഡിൽ സാധൂകരിക്കുന്നു).

## ഫ്ലാഗുകൾ ടോഗിൾ ചെയ്യൽ

### ഡാഷ്ബോർഡ്

**Dashboard → Settings → Feature Flags** എന്നതിലേക്ക് നാവിഗേറ്റ് ചെയ്യുക
(`/dashboard/settings/feature-flags`). ഗ്രിഡ്
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
ഇനിപ്പറയുന്നവ പിന്തുണയ്ക്കുന്നു:

- കീ അല്ലെങ്കിൽ വിവരണം ഉപയോഗിച്ചുള്ള **തിരയൽ**, വിഭാഗം അനുസരിച്ചുള്ള **ഫിൽട്ടർ** (കൂടാതെ കൃത്രിമമായ
  **Requires Restart** കാഴ്ച).
- ബൂളിയൻ ഫ്ലാഗുകൾക്കായി ഒരു **ടോഗിളും**, enum ഫ്ലാഗുകൾക്കായി ഒരു **ഡ്രോപ്പ്ഡൗണും**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- ഓരോ ഫ്ലാഗിനും ഒരു **ഉറവിട ബാഡ്ജ്** — `DB`, `ENV`, അല്ലെങ്കിൽ `DEF` — പ്രാബല്യത്തിലുള്ള
  മൂല്യം എവിടെനിന്നാണ് ലഭിച്ചതെന്ന് ഇത് കാണിക്കുന്നു.
- ഓവർറൈഡ് നീക്കം ചെയ്യുന്നതിനുള്ള ഒരു **Reset** ബട്ടണും (`DB` ഉറവിടമായ ഫ്ലാഗുകൾക്ക് മാത്രം കാണിക്കുന്നു),
  താഴെയായി ഒരു **Reset All Overrides** ബട്ടണും.
- `requiresRestart` ഫ്ലാഗ് മാറ്റുമ്പോൾ ഒരു **Restart Server** ബാനർ.

### REST API

എല്ലാ പ്രവർത്തനങ്ങളും ഒരൊറ്റ റൂട്ടിലൂടെയാണ് നടക്കുന്നത്:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
ഓരോ മെത്തഡിനും പ്രാമാണീകരിച്ച ഡാഷ്ബോർഡ് സെഷൻ ആവശ്യമാണ് (അല്ലെങ്കിൽ `401`).

#### `GET /api/settings/feature-flags`

ഓരോ ഫ്ലാഗിന്റെയും പ്രാബല്യത്തിലുള്ള മൂല്യം, ഉറവിടം, സംഗ്രഹം എന്നിവ തിരികെ നൽകുന്നു.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... എല്ലാ 75 ഫ്ലാഗുകളും
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

ഒരൊറ്റ ഓവർറൈഡ് സജ്ജീകരിക്കുകയോ നീക്കം ചെയ്യുകയോ ചെയ്യുന്നു. ബോഡി: `{ key: string; value?: string }`.
`value` ഒഴിവാക്കുന്നത് ഓവർറൈഡ് നീക്കം ചെയ്യുന്നു (env / default പുനഃസ്ഥാപിക്കുന്നു).

```bash
# ഒരു DB ഓവർറൈഡ് സജ്ജീകരിക്കുക
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# ഓവർറൈഡ് നീക്കം ചെയ്യുക ("value" ഇല്ലാതെ)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

പ്രതികരണം പുതിയ `effectiveValue`/`source`, `previousValue`/
`previousSource`, `requiresRestart` എന്നിവ പ്രതിധ്വനിപ്പിക്കുന്നു. അറിയാത്ത കീകളും പരിധിക്ക് പുറത്തുള്ള enum
മൂല്യങ്ങളും `400` ഉപയോഗിച്ച് നിരസിക്കപ്പെടുന്നു.

#### `DELETE /api/settings/feature-flags`

എല്ലാ DB ഓവർറൈഡുകളും ഒരേസമയം മായ്ച്ച്, ഓരോ ഫ്ലാഗിനെയും അതിന്റെ env / default
മൂല്യത്തിലേക്ക് പുനഃസ്ഥാപിക്കുന്നു. `{ cleared: <count>, message: "..." }` തിരികെ നൽകുന്നു.

> [!NOTE]
> `requiresRestart: true` ഉള്ള ഫ്ലാഗുകൾ ഒരു പ്രോസസ് റീലോഡിന് ശേഷം മാത്രമേ പ്രാബല്യത്തിൽ വരൂ.
> ഡാഷ്ബോർഡിന്റെ റീസ്റ്റാർട്ട് ഫ്ലോ `POST /api/restart` വിളിക്കുകയും തുടർന്ന് സെർവർ വീണ്ടും പ്രവർത്തനക്ഷമമാകുന്നതുവരെ
> `GET /api/health/ping` പോൾ ചെയ്യുകയും ചെയ്യുന്നു.

## അടിയന്തര ബജറ്റ് ഫാൾബാക്ക്

`OMNIROUTE_EMERGENCY_FALLBACK` (`runtime` വിഭാഗം, ഡിഫോൾട്ട് `true`) എന്നത്
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)-ലെ
അടിയന്തര സൗജന്യ ഫാൾബാക്ക് പാതയെ നിയന്ത്രിക്കുന്നു.
ഇത് പ്രവർത്തനക്ഷമമാക്കിയിരിക്കുമ്പോൾ, ബജറ്റ് തീർന്ന അഭ്യർത്ഥനകൾ പൂർണ്ണമായും പരാജയപ്പെടുന്നതിനുപകരം
ഒരു സൗജന്യ ഫാൾബാക്ക് പ്രൊവൈഡർ/മോഡലിലേക്ക് റൂട്ട് ചെയ്യപ്പെടും. ഈ പ്രവർത്തനം പ്രവർത്തനരഹിതമാക്കാനും ബജറ്റ് തീർന്ന അഭ്യർത്ഥനകൾ
പരാജയപ്പെടാൻ അനുവദിക്കാനും — ഡാഷ്ബോർഡ് ടോഗിൾ, ഒരു DB ഓവർറൈഡ്, അല്ലെങ്കിൽ `OMNIROUTE_EMERGENCY_FALLBACK`
എൻവയോൺമെന്റ് വേരിയബിൾ വഴി — ഇത് `false` (അല്ലെങ്കിൽ `0`) ആയി സജ്ജമാക്കുക.
(PR-കൾ #3741 / #3752-ൽ ഡാഷ്ബോർഡ് ടോഗിളായി ലഭ്യമാക്കി.)
