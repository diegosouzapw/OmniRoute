ഡെലിഗേറ്റ് ചെയ്ത **കോൺടെക്സ്റ്റ് എഡിറ്റിംഗ്** എന്നത് Claude-ൽ മാത്രം ലഭ്യമായ ഒരു കോൺടെക്സ്റ്റ്-മാനേജ്മെന്റ് സവിശേഷതയാണ്. OmniRoute-ന്റെ ലോക്കൽ
കംപ്രഷൻ എൻജിനുകളിൽ (Caveman, RTK, LLMLingua, സ്റ്റാക്ക്ഡ് പൈപ്പ്ലൈനുകൾ) നിന്ന് വ്യത്യസ്തമായി — അവ അഭ്യർത്ഥനാ ബോഡി
പ്രോക്സിയിൽ നിന്ന് പുറത്തുപോകുന്നതിന് _മുമ്പ്_ തിരുത്തിയെഴുതുന്നു — കോൺടെക്സ്റ്റ് എഡിറ്റിംഗ്, അതിന്റെ തന്നെ പ്രവർത്തിച്ചുകൊണ്ടിരിക്കുന്ന കോൺടെക്സ്റ്റ് വിൻഡോയിൽ നിന്ന് പഴകിയ
ടൂൾ-യൂസ് / ടൂൾ-റിസൾട്ട് ബ്ലോക്കുകൾ നീക്കം ചെയ്യാൻ **പ്രൊവൈഡറോട്** ആവശ്യപ്പെടുന്നു. OmniRoute ഒരു ബോഡി
പാരാമീറ്റർ (`context_management.edits[]`) മാത്രമാണ് ചേർക്കുന്നത്; Claude അതിന്റെ സ്വന്തം ടോക്കണൈസർ അടിസ്ഥാനമാക്കി യഥാർത്ഥ നീക്കംചെയ്യൽ നിർവഹിക്കുന്നു.

ഇത് സ്വഭാവപരമായി ഒരു ഡെലിഗേറ്റ് ചെയ്ത ശേഷിയാണ്: മറ്റ് പ്രൊവൈഡർമാർ ഈ പാരാമീറ്റർ നിരസിക്കുന്നതിനാൽ, OmniRoute ഇത്
Claude-ലേക്കും Claude-Code-അനുയോജ്യമായ റിലേകളിലേക്കും മാത്രമായി കർശനമായി പരിമിതപ്പെടുത്തുന്നു.

ആധികാരിക ഉറവിടം: `open-sse/config/contextEditing.ts` (സ്ട്രാറ്റജി ഐഡികൾ, ബോഡി ഇൻജക്ഷൻ, ടെലിമെട്രി
എക്സ്ട്രാക്ഷൻ), `open-sse/executors/base.ts` (ഇൻജക്ഷൻ ഗേറ്റ് + 400-ഫാൾബാക്ക്), കൂടാതെ
`open-sse/services/compression/types.ts` (കോൺഫിഗ് ഘടന + ഡിഫോൾട്ട്).

## `clear_tool_uses` എന്താണ് ചെയ്യുന്നത്

ഔട്ട്ബൗണ്ട് Anthropic Messages ബോഡിയിലേക്ക് OmniRoute ഒരൊറ്റ എഡിറ്റ് ഇൻജക്റ്റ് ചെയ്യുന്നു:

```json
{
  "context_management": {
    "edits": [
      {
        "type": "clear_tool_uses_20250919",
        "trigger": { "type": "input_tokens", "value": 100000 },
        "keep": { "type": "tool_uses", "value": 3 }
      }
    ]
  }
}
```

- `type: "clear_tool_uses_20250919"` — തീയതി ഉൾപ്പെടുത്തിയ Anthropic സ്ട്രാറ്റജി ഐഡി (`CLEAR_TOOL_USES_STRATEGY`).
- `trigger.value: 100000` — അഭ്യർത്ഥനയുടെ ഇൻപുട്ട് ടോക്കണുകൾ ഈ പരിധി കടന്നാൽ, Claude പഴയ
  ടൂൾ-യൂസ്/റിസൾട്ട് ജോടികൾ നീക്കം ചെയ്യാൻ തുടങ്ങുന്നു (`CONTEXT_EDITING_DEFAULT_TRIGGER_TOKENS`, Anthropic-ന്റെ ഡിഫോൾട്ട്).
- `keep.value: 3` — ഏറ്റവും പുതിയ N ടൂൾ-യൂസ്/റിസൾട്ട് ജോടികൾ മാറ്റമില്ലാതെ നിലനിർത്തുന്നു
  (`CONTEXT_EDITING_DEFAULT_KEEP_TOOL_USES`).

`anthropic-beta: context-management-2025-06-27` ഹെഡർ മുഖേന ബീറ്റയെ അറിയിക്കുന്നു; Claude അഭ്യർത്ഥനകളിൽ
OmniRoute ഇതിനകം തന്നെ ഈ ഹെഡർ അയയ്ക്കുന്നുണ്ട്.

ഇൻജക്ഷൻ നിർവഹിക്കുന്നത് `applyContextEditingToBody()` ആണ്, കൂടാതെ ഇത് **ഐഡംപൊട്ടന്റ്** ആണ്: ബോഡിയിൽ ഇതിനകം ഒരു `clear_tool_uses`
എഡിറ്റ് നിലവിലുണ്ടെങ്കിൽ (മുമ്പത്തെ ഒരു കോൾ ചേർത്തതോ ക്ലയന്റ് നൽകിയതോ), ബോഡി
അതേപടി നിലനിർത്തുന്നു. ഒരു `clear_thinking_20251015` എഡിറ്റും നിലവിലുണ്ടെങ്കിൽ, OmniRoute
`clear_thinking` എഡിറ്റിനെ മുൻവശത്തേക്ക് സ്റ്റേബിൾ-സോർട്ട് ചെയ്യുന്നു, കാരണം `edits[]` അറേയിൽ
`clear_thinking`, `clear_tool_uses`-ന് മുമ്പായി വരണമെന്ന് Anthropic ആവശ്യപ്പെടുന്നു.

## ഓരോ കോംബോയ്ക്കുമുള്ള പ്രവർത്തനക്ഷമമാക്കൽ ടോഗിൾ

കോൺടെക്സ്റ്റ് എഡിറ്റിംഗ് **ഡിഫോൾട്ടായി ഓഫാണ്**, അത് ഓപ്റ്റ്-ഇൻ രീതിയിലാണ്. കംപ്രഷൻ കോൺഫിഗിൽ ഉൾക്കൊള്ളുന്ന ഒരൊറ്റ ബൂളിയനാണ് ഈ ടോഗിൾ:

- ക്രമീകരണ കീ: `contextEditing.enabled` (camelCase — `context_editing` / `context-editing` **അല്ല**).
- തരം: `open-sse/services/compression/types.ts`-ലെ `ContextEditingConfig { enabled: boolean }`.
- ഡിഫോൾട്ട്: `DEFAULT_CONTEXT_EDITING_CONFIG = { enabled: false }`.
- Zod സ്കീമ: `src/shared/validation/compressionConfigSchemas.ts`-ലെ `contextEditingConfigSchema`.
- സംഭരണം: ശേഷിക്കുന്ന കംപ്രഷൻ ക്രമീകരണങ്ങളോടൊപ്പം നിലനിർത്തുന്നു
  (`src/lib/db/compression.ts`-ൽ നോർമലൈസ് ചെയ്യുന്നു).

ഡാഷ്ബോർഡിൽ ഈ ടോഗിൾ കംപ്രഷൻ ഹബ്ബിലാണ്
(`src/app/(dashboard)/dashboard/context/combos/CompressionHub.tsx`), കൂടാതെ `saveSettings()` വഴി
`{ contextEditing: { enabled: … } }` തിരികെ എഴുതുന്നു. ഇത് കംപ്രഷൻ-ക്രമീകരണ ഒബ്ജക്റ്റിന്റെ ഭാഗമായതിനാൽ,
പൂർണ്ണമായും സ്വതന്ത്രമായ ഒരു സർഫേസ് ആയിരിക്കുന്നതിന് പകരം ഓരോ കോംബോയുടെയും കംപ്രഷൻ പ്രൊഫൈലുമായി ഇത് സംയോജിച്ച് പ്രവർത്തിക്കുന്നു — കോൺഫിഗിൽ ഓൺ/ഓഫ് ഫ്ലാഗ് മാത്രമേ ഉൾപ്പെടുന്നുള്ളൂ; എല്ലാ പരിധികളും (`trigger`,
`keep`) മുകളിൽ രേഖപ്പെടുത്തിയ കോൺസ്റ്റന്റുകളാണ്.

## Claude-ന് മാത്രമുള്ള ഗേറ്റിംഗ്

യഥാർത്ഥ Claude അല്ലെങ്കിൽ Claude-Code-അനുയോജ്യമായ റിലേകൾക്ക് മാത്രമാണ് ഇൻജെക്ഷൻ സംഭവിക്കുന്നത്. `open-sse/executors/base.ts`-ലെ ഗേറ്റ് ഇതാണ്:

```ts
if (
  (this.provider === "claude" || isClaudeCodeCompatible(this.provider)) &&
  contextEditing?.enabled &&
  !contextEditingDisabled
) {
  applyContextEditingToBody(transformedBody, { enabled: true });
}
```

- `this.provider === "claude"` — യഥാർത്ഥ Anthropic കീ/OAuth.
- `isClaudeCodeCompatible(this.provider)` — `anthropic-compatible-cc-` പ്രിഫിക്സിൽ ആരംഭിക്കുന്ന പ്രൊവൈഡർ ഐഡിയുള്ള റിലേകൾ (അവ Claude Code അനുയോജ്യത പരസ്യപ്പെടുത്തുന്നതിനാൽ, ബീറ്റ സ്വീകരിക്കാൻ ഏറ്റവും സാധ്യതയുള്ള റിലേകൾ ഇവയാണ്). `open-sse/services/provider.ts` കാണുക.

മനഃപൂർവം **ഒഴിവാക്കിയവ**:

- `claude-web` — `context_management` ഒരിക്കലും കാണാത്ത `create_conversation_params` അഭ്യർത്ഥനാ ഘടനയുള്ള ഒരു ബ്രൗസർ റിലേ.
- പൊതുവായ `anthropic-compatible-*` റിലേകൾ (`-cc-` പ്രിഫിക്സ് ഇല്ലാത്തവ) — ബീറ്റ പിന്തുണ അനിശ്ചിതമായ മൂന്നാം കക്ഷി എൻഡ്പോയിന്റുകൾ.

ടോഗിൾ ഓണായിരിക്കുമ്പോഴും Claude അല്ലാത്ത പ്രൊവൈഡർമാർക്ക് `context_management` പാരാമീറ്റർ ഒരിക്കലും ലഭിക്കില്ല.

## 400-ഫാൾബാക്ക് / റിലേ കവറേജ്

Claude-അനുയോജ്യമായ ഒരു റിലേ ബീറ്റ പരസ്യപ്പെടുത്തിയേക്കാം, എന്നാൽ എന്നിട്ടും HTTP 400 നൽകി `context_management` പാരാമീറ്റർ നിരസിച്ചേക്കാം. അഭ്യർത്ഥന പരാജയപ്പെടുത്തുന്നതിന് പകരം ക്രമാനുഗതമായി നിലവാരം കുറയ്ക്കുന്നതിനായി, എക്സിക്യൂട്ടർ പാരാമീറ്റർ നീക്കംചെയ്ത് അതേ URL **ഒരിക്കൽ** വീണ്ടും ശ്രമിക്കുന്നു:

```ts
if (
  response.status === HTTP_STATUS.BAD_REQUEST &&
  contextEditing?.enabled &&
  !contextEditingDisabled &&
  transformedBody?.context_management !== undefined
) {
  const errText = await response
    .clone()
    .text()
    .catch(() => "");
  if (/context[_-]management|context editing/i.test(errText)) {
    contextEditingDisabled = true;
    delete transformedBody.context_management;
    let retryBody = JSON.stringify(transformedBody);
    if (isClaudeCodeCompatible(this.provider) || this.provider === "claude") {
      retryBody = await signRequestBody(retryBody);
    }
    response = await fetch(url, { ...fetchOptions, body: retryBody });
  }
}
```

പെരുമാറ്റം:

1. കോൺടെക്സ്റ്റ് എഡിറ്റിംഗ് പ്രവർത്തനക്ഷമമായിരിക്കുകയും ബോഡിയിൽ യഥാർത്ഥത്തിൽ `context_management` ഉണ്ടായിരിക്കുകയും ചെയ്യുന്ന സാഹചര്യത്തിലെ `400`-ൽ മാത്രമേ ഇത് പ്രവർത്തിക്കൂ.
2. പൊരുത്തപ്പെടാത്ത പാതയ്ക്കായി യഥാർത്ഥ റെസ്പോൺസ് മാറ്റമില്ലാതെ നിലനിർത്തുന്നതിന്, 400 ബോഡി ഒരു `clone()` വഴി വായിക്കുന്നു.
3. പിശക് ടെക്സ്റ്റ് `/context[_-]management|context editing/i`-നോട് പൊരുത്തപ്പെടണം — ബന്ധമില്ലാത്ത ഒരു 400 (ഉദാ. `max_tokens must be >= 1`) ഫാൾബാക്ക് ട്രിഗർ **ചെയ്യില്ല**; യഥാർത്ഥ പിശക് തുടർന്നും പ്രചരിക്കും.
4. പൊരുത്തം കണ്ടെത്തുമ്പോൾ ഇത് `contextEditingDisabled = true` സജ്ജീകരിക്കുന്നു (പിന്നീട് ഒരു റീട്രൈ/ഫാൾബാക്ക് URL-നായി പുതിയ `transformedBody` നിർമിക്കുകയാണെങ്കിൽ വീണ്ടും ഇൻജെക്റ്റ് ചെയ്യുന്നത് ഇത് തടയുന്നു), `context_management` ഇല്ലാതാക്കുന്നു, Claude / Claude-Code-അനുയോജ്യമായ റിലേകൾക്കായി ബോഡി വീണ്ടും സൈൻ ചെയ്യുന്നു (`signRequestBody`), തുടർന്ന് അതേ URL ഒരിക്കൽ വീണ്ടും ശ്രമിക്കുന്നു.

യഥാർത്ഥ Claude ബീറ്റയെ `ANTHROPIC_BETA_BASE`-ൽ ഉൾക്കൊള്ളുന്നതിനാൽ ഈ ഫാൾബാക്ക് പാതയിൽ എത്തില്ല.

## `applied_edits` ടെലിമെട്രി

ഒരു Claude റെസ്പോൺസിന് ശേഷം, പ്രൊവൈഡർ യഥാർത്ഥത്തിൽ എത്ര കോൺടെക്സ്റ്റ് നീക്കംചെയ്തുവെന്ന് OmniRoute രേഖപ്പെടുത്തുന്നു. ഇത് **സ്ട്രീം ചെയ്യപ്പെടുന്നില്ല** — സ്ട്രീമിംഗ് അല്ലാത്ത റെസ്പോൺസ് ബോഡിയിൽ നിന്ന് സാധ്യമായത്ര മികച്ച രീതിയിൽ ഇത് എക്സ്ട്രാക്റ്റ് ചെയ്യുന്നു, മാത്രമല്ല ഇത് ഒരിക്കലും റെസ്പോൺസിനെ ബാധിക്കുകയുമില്ല (ടെലിമെട്രി പരാജയങ്ങൾ അവഗണിക്കുന്നു).

- എക്സ്ട്രാക്ഷൻ: `open-sse/config/contextEditing.ts`-ലെ `extractContextEditingTelemetry(responseBody)`.
  റെസ്പോൺസ് ഘടനയിലെ വ്യത്യാസങ്ങളെ പ്രതിരോധിക്കുന്നതിനായി ഇത് മൂന്ന് സ്ഥാനങ്ങളിൽ `applied_edits` പരിശോധിക്കുന്നു:
  - `context_management.applied_edits`
  - `usage.context_management.applied_edits`
  - `usage.applied_edits`
- ഓരോ എൻട്രിയിൽ നിന്നും വായിക്കുന്ന എഡിറ്റ് ഫീൽഡുകൾ: `cleared_input_tokens`, `cleared_tool_uses`
  (snake_case, Anthropic-ന്റെ നേറ്റീവ് രൂപം), കൂടാതെ ഫാൾബാക്കുകളായി `clearedInputTokens` / `clearedToolUses` camelCase രൂപങ്ങൾ.
- `applied_edits` അറേ കണ്ടെത്താനാകാത്തപ്പോഴോ യഥാർത്ഥത്തിൽ ഒന്നും നീക്കംചെയ്തിട്ടില്ലെങ്കിലോ `null` മടക്കിനൽകുന്നു.

റെസീറ്റ് ഘടന `ContextEditingTelemetry { editCount, clearedInputTokens, clearedToolUses }` ആണ്. `recordContextEditingTelemetry()` (`src/lib/db/compressionAnalytics.ts`) വഴി `open-sse/handlers/chatCore.ts`-ലാണ് റെക്കോർഡിംഗ് നടക്കുന്നത് (`provider === "claude"` എന്ന വ്യവസ്ഥയ്ക്ക് വിധേയമായി); ഇത് താഴെപ്പറയുന്ന ടാഗുകളുള്ള ഒരു കംപ്രഷൻ അനലിറ്റിക്സ് റോ എഴുതുന്നു:

- `mode: "context-editing"`
- `engine: "context-editing"`
- `tokens_saved` / `original_tokens` = നീക്കംചെയ്ത ഇൻപുട്ട്-ടോക്കണുകളുടെ എണ്ണം
- `request_id`-ന് `::context-editing` സഫിക്സ് ചേർക്കുന്നു

അതുകൊണ്ട്, ഏൽപ്പിക്കപ്പെട്ട ക്ലിയറിംഗ് പ്രാദേശിക എഞ്ചിനുകൾക്കൊപ്പം കംപ്രഷൻ അനലിറ്റിക്സിൽ `context-editing` എഞ്ചിൻ ലേബലിന് കീഴിൽ ദൃശ്യമാകുകയും RTK/Caveman/LLMLingua ലാഭങ്ങളിൽ നിന്ന് വേർതിരിച്ചറിയാൻ കഴിയുകയും ചെയ്യുന്നു.

## ലോക്കൽ കംപ്രഷൻ എഞ്ചിനുകളുമായുള്ള ബന്ധം

| വശം                    | ലോക്കൽ എഞ്ചിനുകൾ (Caveman / RTK / LLMLingua / stacked)            | ഡെലിഗേറ്റഡ് കോൺടെക്സ്റ്റ് എഡിറ്റിംഗ്                              |
| ---------------------- | ----------------------------------------------------------------- | ----------------------------------------------------------------- |
| പ്രവർത്തിക്കുന്ന സ്ഥലം | അഭ്യർത്ഥന പ്രോക്സിയിൽനിന്ന് പുറത്തുപോകുന്നതിന് മുമ്പ് OmniRoute-ൽ | പ്രൊവൈഡറിൽ (Claude), സെർവർ-സൈഡിൽ                                  |
| എഡിറ്റ് ചെയ്യുന്നത്    | പ്രോംപ്റ്റ് / കോൺടെക്സ്റ്റ് / ടൂൾ-റിസൾട്ട് ടെക്സ്റ്റ്             | പഴയ ടൂൾ-യൂസ് / ടൂൾ-റിസൾട്ട് ബ്ലോക്കുകൾ                            |
| പ്രൊവൈഡർ പരിധി         | എല്ലാ പ്രൊവൈഡർമാരും                                               | `claude` + `anthropic-compatible-cc-*` മാത്രം                     |
| ടോഗിൾ                  | കംപ്രഷൻ മോഡ് ക്രമീകരണങ്ങൾ                                         | `contextEditing.enabled`                                          |
| പരാജയ രീതി             | ഫെയിൽ-ഓപ്പൺ (യഥാർഥ ടെക്സ്റ്റ്)                                    | 400-ഫോൾബാക്ക്: പാരാമീറ്റർ നീക്കംചെയ്ത് ഒരിക്കൽ വീണ്ടും ശ്രമിക്കുക |

ഇവ രണ്ടും പരസ്പരപൂരകമാണ്: OmniRoute അയയ്ക്കുന്ന ബൈറ്റുകൾ ലോക്കൽ എഞ്ചിനുകൾ കംപ്രസ് ചെയ്യുന്നു; ഓരോ ടേണിലും തുടരുന്ന കോൺടെക്സ്റ്റ് വെട്ടിച്ചുരുക്കാൻ Context Editing Claude-നെ അനുവദിക്കുന്നു. ഇവ രണ്ടും ഒരുമിച്ച് പ്രവർത്തനക്ഷമമാക്കാം.
