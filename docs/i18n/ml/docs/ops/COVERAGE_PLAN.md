## നിയമങ്ങൾ

- കവറേജ് ലക്ഷ്യങ്ങൾ `tests/**`-ന് അല്ല, സോഴ്സ് ഫയലുകൾക്കാണ് ബാധകമാകുന്നത്.
- `open-sse/**` ഉൽപ്പന്നത്തിന്റെ ഭാഗമാണ്, അത് പരിധിയിൽ തുടരണം.
- പുതിയ കോഡ് മാറ്റം വരുത്തിയ മേഖലകളിലെ കവറേജ് കുറയ്ക്കരുത്.
- നടപ്പാക്കൽ വിശദാംശങ്ങൾ പരിശോധിക്കുന്നതിനെക്കാൾ പെരുമാറ്റവും ബ്രാഞ്ച് ഫലങ്ങളും പരിശോധിക്കുന്നതിന് മുൻഗണന നൽകുക.
- `src/lib/db/**`-ന് വിപുലമായ മോക്കുകളെക്കാൾ താൽക്കാലിക SQLite ഡാറ്റാബേസുകളും ചെറിയ ഫിക്ചറുകളും ഉപയോഗിക്കുന്നതിന് മുൻഗണന നൽകുക.

## നിലവിലെ കമാൻഡ് സെറ്റ്

- `npm run test:coverage`
  - യൂണിറ്റ് ടെസ്റ്റ് സ്യൂട്ടിനുള്ള പ്രധാന സോഴ്സ് കവറേജ് ഗേറ്റ്
  - `text-summary`, `html`, `json-summary`, `lcov` എന്നിവ സൃഷ്ടിക്കുന്നു
- `npm run coverage:report`
  - ഏറ്റവും പുതിയ റണ്ണിൽ നിന്നുള്ള വിശദമായ ഫയൽ-തിരിച്ചുള്ള റിപ്പോർട്ട്
- `npm run test:coverage:legacy`
  - ചരിത്രപരമായ താരതമ്യത്തിന് മാത്രം

## അറിയപ്പെടുന്ന വിടവ്

നിലവിലെ കവറേജ് കമാൻഡ് പ്രധാന Node യൂണിറ്റ് സ്യൂട്ട് അളക്കുകയും അതിൽനിന്ന് എക്സിക്യൂട്ട് ചെയ്യപ്പെടുന്ന `open-sse` ഉൾപ്പെടെയുള്ള സോഴ്സ് ഉൾപ്പെടുത്തുകയും ചെയ്യുന്നു. ഇത് ഇതുവരെ Vitest കവറേജ് ഒരൊറ്റ ഏകീകൃത റിപ്പോർട്ടിലേക്ക് ലയിപ്പിക്കുന്നില്ല. ആ ലയനം പിന്നീട് ചെയ്യുന്നത് പ്രയോജനകരമാണ്, എന്നാൽ 60% -> 80% വർധന ആരംഭിക്കുന്നതിന് അതൊരു തടസ്സമല്ല.
