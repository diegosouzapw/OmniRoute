ഈ ഡോക്യുമെന്റ് Fly.io-യിൽ OmniRoute വിന്യസിക്കുന്നതിനുള്ള യഥാർത്ഥ പ്രക്രിയ വിവരിക്കുന്നു. ഇതിൽ ഇനിപ്പറയുന്ന സാഹചര്യങ്ങൾ ഉൾപ്പെടുന്നു:

- നിലവിലെ പ്രോജക്റ്റ് ആദ്യമായി Fly.io-യിൽ വിന്യസിക്കൽ
- തുടർന്നുള്ള കോഡ് അപ്ഡേറ്റുകൾ പ്രസിദ്ധീകരിക്കൽ
- ഇതേ വിന്യാസ വർക്ക്ഫ്ലോ പിന്തുടരുന്ന പുതിയ പ്രോജക്റ്റുകൾ

നിലവിലെ പ്രോജക്റ്റിനായി പരിശോധിച്ച് പ്രവർത്തനക്ഷമമാണെന്ന് ഉറപ്പാക്കിയ കോൺഫിഗറേഷനെ അടിസ്ഥാനമാക്കിയുള്ളതാണ് ഈ ഗൈഡ്. ആപ്ലിക്കേഷന്റെ പേര് `omniroute` എന്നാണ്.

---

## 1. വിന്യാസ ലക്ഷ്യങ്ങൾ

- പ്ലാറ്റ്ഫോം: Fly.io
- വിന്യാസ രീതി: ലോക്കൽ `flyctl` നേരിട്ടുള്ള പ്രസിദ്ധീകരണം
- റൺടൈം: റിപ്പോസിറ്ററിയിലുള്ള നിലവിലെ `Dockerfile`, `fly.toml` എന്നിവ ഉപയോഗിക്കുന്നു
- ഡാറ്റാ സ്ഥിരസംഭരണം: `/data`-യിലേക്ക് മൗണ്ട് ചെയ്ത Fly Volume
- ആക്സസ് URL: `https://omniroute.fly.dev/`

---

## 2. നിലവിലെ പ്രോജക്റ്റിന്റെ പ്രധാന കോൺഫിഗറേഷൻ

നിലവിലെ റിപ്പോസിറ്ററിയിലുള്ള `fly.toml`-ൽ ഇനിപ്പറയുന്ന പ്രധാന ഇനങ്ങൾ അടങ്ങിയിട്ടുണ്ടെന്ന് സ്ഥിരീകരിച്ചിട്ടുണ്ട്:

```toml
app = 'omniroute'
primary_region = 'sin'

[[mounts]]
  source = 'data'
  destination = '/data'

[processes]
  app = 'node run-standalone.mjs'

[http_service]
  internal_port = 20128

[env]
  TZ = "Asia/Shanghai"
  HOST = "0.0.0.0"
  HOSTNAME = "0.0.0.0"
  BIND = "0.0.0.0"
```

കുറിപ്പുകൾ:

- വിന്യാസം ഏത് Fly ആപ്ലിക്കേഷനെയാണ് ലക്ഷ്യമിടുന്നതെന്ന് `app = 'omniroute'` നിർണ്ണയിക്കുന്നു
- സ്ഥിരസംഭരണ വോളിയം മൗണ്ട് ചെയ്യേണ്ട ഡയറക്ടറി `destination = '/data'` നിർണ്ണയിക്കുന്നു
- ഈ പ്രോജക്റ്റിൽ `DATA_DIR=/data` സജ്ജീകരിക്കേണ്ടതാണ്; അല്ലാത്തപക്ഷം ഡാറ്റാബേസും കീകളും കണ്ടെയ്നറിന്റെ താൽക്കാലിക ഡയറക്ടറിയിലേക്ക് എഴുതപ്പെടും

## 3. മുൻവ്യവസ്ഥകൾ

### 3.1 Fly CLI ഇൻസ്റ്റാൾ ചെയ്യൽ

Windows PowerShell:

```powershell
pwsh -Command "iwr https://fly.io/install.ps1 -useb | iex"
```

നിങ്ങളുടെ പരിതസ്ഥിതിയിൽ ഇൻസ്റ്റാളേഷൻ സ്ക്രിപ്റ്റ് പരാജയപ്പെടുകയാണെങ്കിൽ, `flyctl` ബൈനറി മാനുവലായി ഡൗൺലോഡ് ചെയ്ത് നിങ്ങളുടെ `PATH`-ലേക്ക് ചേർക്കാവുന്നതാണ്.

### 3.2 നിങ്ങളുടെ Fly അക്കൗണ്ടിലേക്ക് ലോഗിൻ ചെയ്യൽ

```powershell
flyctl auth login
```

### 3.3 ലോഗിൻ നില പരിശോധിക്കൽ

```powershell
flyctl auth whoami
flyctl version
```

## 4. നിലവിലെ പ്രോജക്റ്റിന്റെ ആദ്യ വിന്യാസം

### 4.1 കോഡ് ക്ലോൺ ചെയ്ത് ഡയറക്ടറിയിൽ പ്രവേശിക്കുക

```powershell
git clone https://github.com/diegosouzapw/OmniRoute.git
cd OmniRoute
```

### 4.2 ആപ്ലിക്കേഷന്റെ പേര് സ്ഥിരീകരിക്കുക

`fly.toml` തുറന്ന് ഇനിപ്പറയുന്ന വരി പരിശോധിക്കുക:

```toml
app = 'omniroute'
```

നിങ്ങളുടെ സ്വന്തം പുതിയ ആപ്ലിക്കേഷനിലേക്കാണ് വിന്യസിക്കുന്നതെങ്കിൽ, ആഗോളതലത്തിൽ തനതായ ഒരു പേരിലേക്ക് ഇത് മാറ്റാവുന്നതാണ്, ഉദാഹരണത്തിന്:

```toml
app = 'omniroute-yourname'
```

കുറിപ്പ്:

- കൺസോളിൽ കാണുന്ന ആപ്ലിക്കേഷൻ `fly.toml`-ലെ `app` മൂല്യവുമായി പൊരുത്തപ്പെടുന്നുവെന്ന് ഉറപ്പാക്കുക
- നിങ്ങൾ മുമ്പ് `oroute` പോലുള്ള മറ്റൊരു പേര് ഉപയോഗിച്ചിട്ടുണ്ടെങ്കിൽ, അത് `omniroute`-മായി ആശയക്കുഴപ്പത്തിലാക്കരുത്

### 4.3 ആപ്ലിക്കേഷൻ സൃഷ്ടിക്കുക

ആപ്ലിക്കേഷൻ ഇതുവരെ നിലവിലില്ലെങ്കിൽ:

```powershell
flyctl apps create omniroute
```

നിങ്ങൾ ആപ്ലിക്കേഷന്റെ പേര് മാറ്റിയിട്ടുണ്ടെങ്കിൽ, `omniroute`-ന് പകരം നിങ്ങൾ തിരഞ്ഞെടുത്ത പേര് ഉപയോഗിക്കുക.

### 4.4 ആദ്യ വിന്യാസം

```powershell
flyctl deploy
```

## 5. ആവശ്യമായ പാരാമീറ്ററുകൾ

Fly.io-യിൽ കുറഞ്ഞത് ഇനിപ്പറയുന്ന പാരാമീറ്ററുകളെങ്കിലും കോൺഫിഗർ ചെയ്യാൻ ഈ പ്രോജക്റ്റ് ശുപാർശ ചെയ്യുന്നു.

### 5.1 പരിശോധിച്ചുറപ്പിച്ച പാരാമീറ്ററുകൾ

നിലവിലെ `omniroute` ആപ്ലിക്കേഷന്റെ യഥാർത്ഥ വിന്യാസങ്ങളിൽ ഈ പാരാമീറ്ററുകൾ ഉപയോഗിച്ചിട്ടുണ്ട്:

- `API_KEY_SECRET`
- `DATA_DIR`
- `JWT_SECRET`
- `MACHINE_ID_SALT`
- `NEXT_PUBLIC_BASE_URL`
- `OMNIROUTE_WS_BRIDGE_SECRET` (പ്രൊഡക്ഷനിൽ ആവശ്യമാണ് — WebSocket ബ്രിഡ്ജ് പ്രാമാണീകരണത്തിനായി ഉപയോഗിക്കുന്നു)
- `STORAGE_ENCRYPTION_KEY`

### 5.2 `INITIAL_PASSWORD`-നെക്കുറിച്ച്

ഈ വിന്യാസത്തിന് അത് ആവശ്യമില്ലാത്തതിനാൽ നിലവിലെ പ്രോജക്റ്റിൽ `INITIAL_PASSWORD` സജ്ജീകരിച്ചിട്ടില്ല.

ഇത് സജ്ജീകരിച്ചിട്ടില്ലെങ്കിൽ:

- ഡിഫോൾട്ട് പാസ്വേഡ് `CHANGEME` ആണെന്ന് സ്റ്റാർട്ടപ്പ് ലോഗ് സൂചിപ്പിക്കും
- വിന്യാസത്തിനുശേഷം കഴിയുന്നത്ര വേഗത്തിൽ സിസ്റ്റം ക്രമീകരണങ്ങളിൽ ലോഗിൻ പാസ്വേഡ് മാറ്റണം

മാനുവൽ ഇടപെടലില്ലാതെ ബാക്കെൻഡ് പാസ്വേഡ് ഇനിഷ്യലൈസ് ചെയ്യണമെങ്കിൽ, ഇത് പിന്നീട് ചേർക്കാവുന്നതാണ്:

- `INITIAL_PASSWORD`

## 6. ശുപാർശ ചെയ്യുന്ന പാരാമീറ്ററുകൾ

### 6.1 രഹസ്യങ്ങളുടെ കോൺഫിഗറേഷൻ

Fly Secrets-നായി ഇനിപ്പറയുന്ന വേരിയബിളുകൾ ശുപാർശ ചെയ്യുന്നു:

| വേരിയബിൾ                         | ശുപാർശ                     | വിവരണം                                                                 |
| -------------------------------- | -------------------------- | ---------------------------------------------------------------------- |
| `API_KEY_SECRET`                 | ആവശ്യമാണ്                  | API Key സൃഷ്ടിക്കുന്നതിനും സാധൂകരിക്കുന്നതിനും ഉപയോഗിക്കുന്നു          |
| `JWT_SECRET`                     | ആവശ്യമാണ്                  | ലോഗിൻ സെഷനുകൾക്കും JWT സൈനിംഗിനും ഉപയോഗിക്കുന്നു                       |
| `OMNIROUTE_WS_BRIDGE_SECRET`     | പ്രൊഡക്ഷനിൽ ആവശ്യമാണ്      | WebSocket ബ്രിഡ്ജ് ഓതന്റിക്കേഷൻ രഹസ്യം                                 |
| `STORAGE_ENCRYPTION_KEY`         | ശക്തമായി ശുപാർശ ചെയ്യുന്നു | സംഭരിച്ചിരിക്കുന്ന സെൻസിറ്റീവ് കണക്ഷൻ വിവരങ്ങൾ എൻക്രിപ്റ്റ് ചെയ്യുന്നു |
| `MACHINE_ID_SALT`                | ശുപാർശ ചെയ്യുന്നു          | സ്ഥിരതയുള്ള മെഷീൻ ഐഡന്റിഫയർ സൃഷ്ടിക്കുന്നു                             |
| `INITIAL_PASSWORD`               | ഐച്ഛികം                    | ആദ്യ ഡിപ്ലോയ്മെന്റിൽ പ്രാരംഭ ബാക്കെൻഡ് പാസ്വേഡ് സജ്ജീകരിക്കുന്നു       |
| OAuth/API സ്വകാര്യ ക്രെഡൻഷ്യലുകൾ | ആവശ്യാനുസരണം               | ബാഹ്യ പ്ലാറ്റ്ഫോം ഓതന്റിക്കേഷൻ കോൺഫിഗറേഷൻ                              |

### 6.2 നിലവിലെ പ്രോജക്റ്റിനായി ശുപാർശ ചെയ്യുന്ന മൂല്യങ്ങൾ

| വേരിയബിൾ               | ശുപാർശ ചെയ്യുന്ന മൂല്യം     |
| ---------------------- | --------------------------- |
| `DATA_DIR`             | `/data`                     |
| `NEXT_PUBLIC_BASE_URL` | `https://omniroute.fly.dev` |

കുറിപ്പുകൾ:

- `DATA_DIR=/data` നിർണായകമാണ്, കൂടാതെ അത് Fly Volume മൗണ്ട് പോയിന്റുമായി പൊരുത്തപ്പെടണം
- `NEXT_PUBLIC_BASE_URL` ഷെഡ്യൂളർ, ഫ്രണ്ട്എൻഡ് കോൾബാക്കുകൾ, സമാന സാഹചര്യങ്ങൾ എന്നിവയിൽ ഉപയോഗിക്കുന്നു

### 6.3 OAuth കോൾബാക്ക് URL കോൺഫിഗറേഷൻ

Fly.io ഡിപ്ലോയ്മെന്റിൽ OAuth അടിസ്ഥാനമാക്കിയുള്ള പ്രൊവൈഡറുകൾ (ഉദാ. Antigravity, Gemini, Cursor) പ്രവർത്തനക്ഷമമാക്കണമെങ്കിൽ, ഇനിപ്പറയുന്ന രണ്ട് കാര്യങ്ങൾ ഉറപ്പാക്കുക:

1. **`NEXT_PUBLIC_BASE_URL` നിങ്ങളുടെ പൊതു HTTPS ഡൊമെയ്നായി സജ്ജീകരിക്കുക**

   ```powershell
   flyctl secrets set NEXT_PUBLIC_BASE_URL=https://omniroute.fly.dev -a omniroute
   ```

   നിങ്ങൾ ഒരു കസ്റ്റം ഡൊമെയ്ൻ ഉപയോഗിക്കുന്നുണ്ടെങ്കിൽ, അതിന് അനുയോജ്യമായ ഡൊമെയ്ൻ ഉപയോഗിച്ച് ഇത് മാറ്റിസ്ഥാപിക്കുക (ഉദാ. `https://omniroute.yourdomain.com`).

2. **പ്രൊവൈഡർ കൺസോളിൽ കോൾബാക്ക് URL കോൺഫിഗർ ചെയ്യുക**

   എല്ലാ OAuth പ്രൊവൈഡറുകളും ഒരേയൊരു കോൾബാക്ക് പാതയായ `/callback` പങ്കിടുന്നു — ഓരോ പ്രൊവൈഡറിനും പ്രത്യേക കോൾബാക്ക് റൂട്ട് ഇല്ല:

   ```text
   <NEXT_PUBLIC_BASE_URL>/callback
   ```

   ഉദാഹരണത്തിന്, Gemini, Antigravity, Cursor, അല്ലെങ്കിൽ GitLab Duo ഏതായാലും:
   - `https://omniroute.fly.dev/callback`

   `NEXT_PUBLIC_BASE_URL` പ്രൊവൈഡറിൽ രജിസ്റ്റർ ചെയ്തിട്ടുള്ള കോൾബാക്ക് URL-മായി പൊരുത്തപ്പെടുന്നില്ലെങ്കിൽ, ബ്രൗസർ റീഡയറക്ട് ഘട്ടത്തിൽ OAuth ഫ്ലോ പരാജയപ്പെടും.

## 7. ഒറ്റ കമാൻഡിലുള്ള രഹസ്യ സജ്ജീകരണം

ഇനിപ്പറയുന്ന കമാൻഡുകൾ സുരക്ഷിതമായ റാൻഡം മൂല്യങ്ങൾ സൃഷ്ടിക്കുകയും നിലവിലെ പ്രോജക്റ്റിന് ആവശ്യമായ എല്ലാ പാരാമീറ്ററുകളും ഒറ്റ ഘട്ടത്തിൽ Fly Secrets-ലേക്ക് എഴുതുകയും ചെയ്യുന്നു.

കുറിപ്പുകൾ:

- `INITIAL_PASSWORD` ഉൾപ്പെടുത്തിയിട്ടില്ല
- നിലവിലെ `omniroute` പ്രോജക്റ്റിനായി ഉദ്ദേശിച്ചുള്ളതാണ്

```powershell
$apiKeySecret = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$jwtSecret = [Convert]::ToHexString((1..64 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$machineIdSalt = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$storageKey = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$wsBridgeSecret = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()

flyctl secrets set `
  API_KEY_SECRET=$apiKeySecret `
  JWT_SECRET=$jwtSecret `
  MACHINE_ID_SALT=$machineIdSalt `
  STORAGE_ENCRYPTION_KEY=$storageKey `
  OMNIROUTE_WS_BRIDGE_SECRET=$wsBridgeSecret `
  DATA_DIR=/data `
  NEXT_PUBLIC_BASE_URL=https://omniroute.fly.dev `
  -a omniroute
```

Linux / macOS-ൽ, നിങ്ങൾക്ക് `openssl rand -hex 32` ഉപയോഗിക്കാനും കഴിയും:

```bash
flyctl secrets set OMNIROUTE_WS_BRIDGE_SECRET=$(openssl rand -hex 32) -a omniroute
```

കുറിപ്പുകൾ:

- പ്രൊഡക്ഷനിൽ `OMNIROUTE_WS_BRIDGE_SECRET` ആവശ്യമാണ്; ഇത് ഇല്ലെങ്കിൽ WebSocket ബ്രിഡ്ജ് ഹാൻഡ്ഷേക്ക് പ്രവർത്തിക്കില്ല

നിങ്ങൾക്ക് ഒരു പ്രാരംഭ പാസ്വേഡും സജ്ജീകരിക്കണമെങ്കിൽ:

```powershell
flyctl secrets set INITIAL_PASSWORD=your-strong-password -a omniroute
```

## 9. തുടർന്നുള്ള അപ്ഡേറ്റുകളും റിലീസുകളും

കോഡ് അപ്ഡേറ്റുകൾക്കുശേഷം, റിലീസ് പ്രക്രിയ ലളിതമാണ്:

```powershell
git pull
flyctl deploy
```

കോഡിൽ മാറ്റം വരുത്താതെ പാരാമീറ്ററുകൾ മാത്രം അപ്ഡേറ്റ് ചെയ്യണമെങ്കിൽ:

```powershell
flyctl secrets set KEY=value -a omniroute
```

Fly മെഷീനുകളിൽ സ്വയമേവ ഒരു റോളിംഗ് അപ്ഡേറ്റ് നടത്തും.

### 9.1 നിങ്ങളുടെ ഫോർക്കിന്റെ `fly.toml` നിലനിർത്തിക്കൊണ്ട് അപ്സ്ട്രീം റിപ്പോസിറ്ററി അപ്ഡേറ്റുകൾ പിന്തുടരൽ

നിലവിലെ റിപ്പോസിറ്ററി ഒരു ഫോർക്ക് ആണെങ്കിൽ, അപ്സ്ട്രീം `https://github.com/diegosouzapw/OmniRoute`-ൽ നിന്നുള്ള അപ്ഡേറ്റുകൾ സമന്വയിപ്പിക്കാൻ നിങ്ങൾ ആഗ്രഹിക്കുന്നുവെങ്കിൽ, താഴെയുള്ള പ്രവർത്തനക്രമം പിന്തുടരുക.

ആദ്യം, നിങ്ങളുടെ റിമോട്ടുകൾ പരിശോധിക്കുക:

```powershell
git remote -v
```

കുറഞ്ഞത് ഇനിപ്പറയുന്നവയെങ്കിലും നിങ്ങൾ കാണണം:

- നിങ്ങളുടെ സ്വന്തം ഫോർക്കിലേക്ക് ചൂണ്ടുന്ന `origin`
- യഥാർത്ഥ റിപ്പോസിറ്ററിയിലേക്ക് ചൂണ്ടുന്ന `upstream`

`upstream` കോൺഫിഗർ ചെയ്തിട്ടില്ലെങ്കിൽ, അത് ചേർക്കുക:

```powershell
git remote add upstream https://github.com/diegosouzapw/OmniRoute.git
```

അപ്സ്ട്രീമുമായി സമന്വയിപ്പിക്കുന്നതിന് മുമ്പ്, ഏറ്റവും പുതിയ കമ്മിറ്റുകളും ടാഗുകളും ലഭ്യമാക്കുക:

```powershell
git fetch upstream --tags
```

നിലവിലെ പതിപ്പും അപ്സ്ട്രീം ടാഗുകളും പരിശോധിക്കുക:

```powershell
git describe --tags --always
git show --no-patch --oneline v3.4.7
```

> കുറിപ്പ്: നിലവിലെ പ്രോജക്റ്റ് പതിപ്പ് `v3.8.0` ആണ്. താഴെയുള്ള `v3.4.7` പരാമർശങ്ങൾ ചരിത്രപരമായ ഉദാഹരണങ്ങളായി മാത്രം നിലനിർത്തിയിരിക്കുന്നു. യഥാർത്ഥ റിലീസുകൾക്കായി `:latest` അല്ലെങ്കിൽ നിലവിലെ പതിപ്പ് ടാഗ് (ഉദാ. `:v3.8.0`) ഉപയോഗിക്കുക.

നിങ്ങളുടെ ഫോർക്കിലെ `fly.toml` നിർബന്ധമായും നിലനിർത്തിക്കൊണ്ട് ഏറ്റവും പുതിയ അപ്സ്ട്രീം `main` ലയിപ്പിക്കാൻ നിങ്ങൾ ആഗ്രഹിക്കുന്നുവെങ്കിൽ, ഈ പ്രവർത്തനക്രമം പിന്തുടരുക:

```powershell
git merge upstream/main
git checkout HEAD~1 -- fly.toml
git add -- fly.toml
git commit -m "chore(deploy): keep fork fly.toml"
git push origin main
```

കുറിപ്പുകൾ:

- `git merge upstream/main` യഥാർത്ഥ റിപ്പോസിറ്ററിയിൽ നിന്നുള്ള ഏറ്റവും പുതിയ കോഡ് സമന്വയിപ്പിക്കുന്നു
- `git checkout HEAD~1 -- fly.toml` ലയനത്തിന് മുമ്പുണ്ടായിരുന്ന നിങ്ങളുടെ ഫോർക്കിന്റെ സ്വന്തം `fly.toml` പുനഃസ്ഥാപിക്കുന്നു
- അപ്സ്ട്രീം `fly.toml` പരിഷ്കരിച്ചിട്ടില്ലെങ്കിൽ, ഈ ഘട്ടം വ്യത്യാസങ്ങളൊന്നും സൃഷ്ടിക്കില്ല
- അപ്സ്ട്രീം `fly.toml` പരിഷ്കരിച്ചിട്ടുണ്ടെങ്കിൽ, നിങ്ങളുടെ Fly ആപ്ലിക്കേഷൻ നാമം, വോള്യം മൗണ്ട്, റീജിയൻ, ഫോർക്കിന് മാത്രമായുള്ള മറ്റ് ഡിപ്ലോയ്മെന്റ് കോൺഫിഗറേഷനുകൾ എന്നിവ പുനരാലേഖനം ചെയ്യപ്പെടുന്നില്ലെന്ന് ഈ ഘട്ടം ഉറപ്പാക്കുന്നു

ഒരു നിർദിഷ്ട റിലീസ് ടാഗുമായി (ഉദാ. `v3.4.7`) വിന്യസിക്കാൻ നിങ്ങൾ ആഗ്രഹിക്കുന്നുവെങ്കിൽ, ആ ടാഗ് ഇതിനകം `upstream/main`-ൽ ഉൾപ്പെടുത്തിയിട്ടുണ്ടെന്ന് ആദ്യം പരിശോധിക്കുക:

```powershell
git merge-base --is-ancestor v3.4.7 upstream/main
```

വിജയകരമായ ഫലം ലഭിച്ചാൽ, `upstream/main`-ൽ ആ പതിപ്പ് ഇതിനകം ഉൾപ്പെട്ടിട്ടുണ്ടെന്നാണ് അർത്ഥം; നിങ്ങൾക്ക് `upstream/main` ലളിതമായി ലയിപ്പിക്കാം.

### 9.2 അപ്സ്ട്രീം സമന്വയിപ്പിച്ചതിനുശേഷമുള്ള സ്റ്റാൻഡേർഡ് റിലീസ് ക്രമം

യഥാർത്ഥ റിപ്പോസിറ്ററിയുമായി സമന്വയിപ്പിച്ചതിനുശേഷം, ശുപാർശ ചെയ്യുന്ന ഈ റിലീസ് ക്രമം പിന്തുടരുക:

1. `git fetch upstream --tags`
2. `git merge upstream/main`
3. ഫോർക്കിന്റെ `fly.toml` പുനഃസ്ഥാപിക്കുക
4. `git push origin main`
5. `flyctl deploy`
6. `flyctl status -a omniroute`
7. `flyctl logs --no-tail -a omniroute`

നിലവിലെ പ്രോജക്റ്റ് `v3.4.7`-ലേക്ക് അപ്ഗ്രേഡ് ചെയ്തപ്പോൾ ഉപയോഗിച്ച യഥാർത്ഥ പ്രവർത്തനക്രമം ഇതാണ് (ഈ ഉദാഹരണം ഒരു ചരിത്രപരമായ പതിപ്പിനെയാണ് സൂചിപ്പിക്കുന്നത്; നിലവിലെ യഥാർത്ഥ പതിപ്പ് `v3.8.0` ആണ്).

## 10. വിന്യാസാനന്തര പരിശോധനകൾ

### 10.1 ആപ്ലിക്കേഷൻ നില പരിശോധിക്കുക

```powershell
flyctl status -a omniroute
```

### 10.2 സ്റ്റാർട്ടപ്പ് ലോഗുകൾ കാണുക

```powershell
flyctl logs --no-tail -a omniroute
```

### 10.3 സൈറ്റിന്റെ ലഭ്യത സ്ഥിരീകരിക്കുക

```powershell
try {
  (Invoke-WebRequest -Uri "https://omniroute.fly.dev" -MaximumRedirection 5 -UseBasicParsing).StatusCode
} catch {
  if ($_.Exception.Response) {
    $_.Exception.Response.StatusCode.value__
  } else {
    throw
  }
}
```

`200` എന്ന റിട്ടേൺ മൂല്യം സൈറ്റ് സാധാരണയായി പ്രതികരിക്കുന്നുവെന്ന് സൂചിപ്പിക്കുന്നു.

## 11. വിജയസൂചകങ്ങൾ

വിജയകരമായ വിന്യാസത്തിനുശേഷം, ലോഗുകളിൽ ഇനിപ്പറയുന്നതിന് സമാനമായ ഉള്ളടക്കം കാണണം:

```text
[bootstrap] Secrets persisted to: /data/server.env
[DB] SQLite database ready: /data/storage.sqlite
```

ഈ രണ്ട് കാര്യങ്ങൾ നിർണായകമാണ്:

- `/data/server.env` റൺടൈം രഹസ്യങ്ങൾ സ്ഥിരമായ വോള്യത്തിലേക്ക് എഴുതിയിട്ടുണ്ടെന്ന് സ്ഥിരീകരിക്കുന്നു
- `/data/storage.sqlite` ഡാറ്റാബേസ് സ്ഥിരമായ വോള്യത്തിലേക്ക് എഴുതിയിട്ടുണ്ടെന്ന് സ്ഥിരീകരിക്കുന്നു

പകരം `/app/data/...` കാണുകയാണെങ്കിൽ, `DATA_DIR` തെറ്റായി കോൺഫിഗർ ചെയ്തിരിക്കുന്നു; അത് ഉടൻ തിരുത്തണം.

## 12. സാധാരണ പ്രശ്നങ്ങൾ

### 12.1 `Secrets` പേജ് ശൂന്യമാണ്

സാധാരണയായി രണ്ട് കാരണങ്ങളാണുള്ളത്:

- നിങ്ങൾ ഇതുവരെ `flyctl secrets set` പ്രവർത്തിപ്പിച്ചിട്ടില്ല
- നിങ്ങൾ മറ്റൊരു ആപ്ലിക്കേഷനാണ് കാണുന്നത് (ഉദാ. `omniroute` എന്നതിനുപകരം `oroute`)

### 12.2 `flyctl deploy`, `app not found` എന്ന് റിപ്പോർട്ട് ചെയ്യുന്നു

ആദ്യം ആപ്ലിക്കേഷൻ സൃഷ്ടിക്കുക:

```powershell
flyctl apps create omniroute
```

### 12.3 `fly.toml` പാർസിംഗ് പരാജയപ്പെടുന്നു

ഇനിപ്പറയുന്നവ പരിശോധിക്കുക:

- കമന്റുകളിൽ വികലമായ അക്ഷരങ്ങൾ ഉണ്ടോ എന്ന്
- TOML ഉദ്ധരണികളും ഇൻഡന്റേഷനും ശരിയാണോ എന്ന്

### 12.4 ഡാറ്റ സ്ഥിരമായി നിലനിൽക്കുന്നില്ല

ഇനിപ്പറയുന്ന രണ്ടും സ്ഥിരീകരിക്കുക:

- `fly.toml`-ൽ `destination = '/data'` ഉൾപ്പെട്ടിട്ടുണ്ട്
- `DATA_DIR`, `/data` ആയി സജ്ജീകരിച്ചിരിക്കുന്നു

### 12.5 `INITIAL_PASSWORD` ഇല്ലാതെ ഇത് പ്രവർത്തിക്കുമോ?

അതെ, പ്രവർത്തിക്കും. ഇത് ഡിഫോൾട്ട് `CHANGEME` പാസ്വേഡിലേക്ക് മടങ്ങും. പ്രൊഡക്ഷനിൽ ബാക്കെൻഡ് പാസ്വേഡ് എത്രയും വേഗം മാറ്റാൻ ശുപാർശ ചെയ്യുന്നു.

## 13. പുതിയ പ്രോജക്റ്റുകൾക്കായി പുനരുപയോഗിക്കൽ

ഈ പ്രമാണം പിന്തുടർന്ന് നിങ്ങൾ ഒരു പുതിയ പ്രോജക്റ്റ് വിന്യസിക്കുകയാണെങ്കിൽ, ഈ ഇനങ്ങൾ മാത്രം മാറ്റിയാൽ മതി:

1. `fly.toml`-ലെ `app` മൂല്യം മാറ്റുക
2. `NEXT_PUBLIC_BASE_URL` മാറ്റുക
3. `DATA_DIR=/data` അതേപടി നിലനിർത്തുക
4. `API_KEY_SECRET`, `JWT_SECRET`, `MACHINE_ID_SALT`, `STORAGE_ENCRYPTION_KEY` എന്നിവ വീണ്ടും സൃഷ്ടിക്കുക
5. ആദ്യ വിന്യാസത്തിനുശേഷം, ലോഗുകൾ `/data`-യിലേക്ക് എഴുതപ്പെടുന്നുണ്ടെന്ന് സ്ഥിരീകരിക്കുക

മുൻ പ്രോജക്റ്റിലെ കീകൾ പുനരുപയോഗിക്കരുത്.

## 14. നിലവിലെ പ്രോജക്റ്റിനായുള്ള ഏറ്റവും ചുരുങ്ങിയ റിലീസ് ചെക്ക്ലിസ്റ്റ്

തുടർന്നുള്ള റിലീസുകൾക്കായി ഏറ്റവും സാധാരണമായി ഉപയോഗിക്കുന്ന കമാൻഡുകൾ:

```powershell
flyctl auth whoami
flyctl status -a omniroute
flyctl secrets list -a omniroute
flyctl deploy
flyctl logs --no-tail -a omniroute
```

ഒരു സാധാരണ റിലീസിനുള്ള പ്രധാന കമാൻഡ് ഇത്രമാത്രമാണ്:

```powershell
flyctl deploy
```

ഒരു പുതിയ പരിതസ്ഥിതിയിലെ ആദ്യ വിന്യാസത്തിനുള്ള പ്രധാന ഘട്ടങ്ങൾ:

1. `flyctl auth login`
2. `flyctl apps create omniroute`
3. `flyctl secrets set ... -a omniroute`
4. `flyctl deploy`
5. `flyctl logs --no-tail -a omniroute`
