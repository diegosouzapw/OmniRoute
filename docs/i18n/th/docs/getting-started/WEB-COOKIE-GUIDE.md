ผู้ให้บริการ Web Cookie ช่วยให้ OmniRoute สามารถใช้บริการ AI ผ่านเซสชันเบราว์เซอร์ที่มีอยู่ของคุณแทน API key ได้ ซึ่งมีประโยชน์เมื่อคุณสามารถเข้าถึงบริการผ่านเว็บไซต์ของบริการนั้นอยู่แล้ว และต้องการให้ OmniRoute ใช้เซสชันที่ผ่านการยืนยันตัวตนเดียวกัน

ต่างจากผู้ให้บริการที่ใช้ API key ผู้ให้บริการ Web Cookie จะยืนยันตัวตนโดยใช้ข้อมูลรับรองที่เบราว์เซอร์ของคุณส่งไปยังเว็บไซต์

# ก่อนเริ่มต้น

> **สำคัญ:** คัดลอกข้อมูลรับรองจาก **คำขอเครือข่ายแบบสด** เสมอ **อย่า** คัดลอกจากพื้นที่จัดเก็บคุกกี้ของเบราว์เซอร์

ปัญหาการยืนยันตัวตนจำนวนมากเกิดจากการคัดลอกคุกกี้จากตำแหน่งที่ไม่ถูกต้อง

## อย่าคัดลอกจากพื้นที่จัดเก็บคุกกี้

เบราว์เซอร์ส่วนใหญ่แสดงคุกกี้ที่จัดเก็บไว้ผ่าน:

```
DevTools
→ Application (หรือ Storage)
→ Cookies
```

แม้ว่าคุกกี้เหล่านี้จะดูถูกต้อง แต่อาจ:

- ล้าสมัย
- ไม่ครบถ้วน
- ขาดคุกกี้ที่ส่งเฉพาะในคำขอที่ผ่านการยืนยันตัวตนเท่านั้น

การใช้ค่าเหล่านี้อาจทำให้การยืนยันตัวตนล้มเหลว แม้ว่าค่าดังกล่าวจะดูเหมือนใช้งานได้ก็ตาม

## คัดลอกจากคำขอแบบสด

ให้ใช้คุกกี้จากคำขอที่สำเร็จแทน:

```
DevTools
→ Network
→ รีเฟรชหน้า
→ เปิดคำขอแชทหรือการสนทนา
→ Request Headers
→ Cookie
```

ส่วนหัวคำขอ `Cookie` มีข้อมูลการยืนยันตัวตนที่ตรงกับข้อมูลที่เบราว์เซอร์ของคุณใช้สำเร็จทุกประการ

สำหรับผู้ให้บริการ Web Cookie ส่วนใหญ่ ค่านี้คือค่าที่ควรวางลงใน OmniRoute

# การตั้งค่าทั่วไป

กระบวนการตั้งค่าจะเหมือนกันสำหรับผู้ให้บริการ Web Cookie ส่วนใหญ่

1. ลงชื่อเข้าใช้เว็บไซต์ของผู้ให้บริการ
2. เปิดเครื่องมือสำหรับนักพัฒนาของเบราว์เซอร์
3. เปิดแท็บ **Network**
4. รีเฟรชหน้า
5. เปิดคำขอแชทหรือการสนทนาที่ผ่านการยืนยันตัวตน
6. คัดลอกข้อมูลรับรองสำหรับการยืนยันตัวตนที่จำเป็น
7. เปิด OmniRoute
8. ไปที่ **Providers → Add Provider**
9. เลือกผู้ให้บริการ Web Cookie ของคุณ
10. วางข้อมูลรับรอง
11. คลิก **Test Connection**
12. บันทึกผู้ให้บริการ

ข้อมูลรับรองที่จำเป็นจะแตกต่างกันไปตามผู้ให้บริการ

> อัปเดตตารางนี้เมื่อมีการเพิ่มผู้ให้บริการ Web Cookie รายใหม่ หรือเมื่อผู้ให้บริการที่มีอยู่เปลี่ยนแปลงข้อกำหนดในการยืนยันตัวตน

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) เป็นแพลตฟอร์มแชตสำหรับผู้ใช้ฟรีที่ไม่ต้องสมัครบัญชี — เซสชันจะถูกสร้างโดยไม่ระบุตัวตนเมื่อเข้าชมครั้งแรก และคงอยู่ผ่านคุกกี้สามรายการ ได้แก่ `uid`, `si_usr_id` และ `si_ses_id` OmniRoute ทำพร็อกซีเอนด์พอยต์ `/api/dispatch` เดียวกันผ่านรหัสโมเดลเดียว (`notrack-c` และมีนามแฝงเป็น `ntw`)

### ขั้นตอนการเชื่อมต่อ

1. เปิด [notrack.ai](https://notrack.ai) ในเบราว์เซอร์ของคุณ และรอให้ระบบตั้งค่าคุกกี้ของเซสชันแบบไม่ระบุตัวตน
2. เปิด **DevTools → Network** รีเฟรชหน้า แล้วคลิกคำขอ `/api` ใดก็ได้
3. ใน **Request Headers** ให้คัดลอกค่าทั้งหมดของส่วนหัว `Cookie`
4. ใน OmniRoute ไปที่ **Providers → Add Provider → NoTrack Web (Free)**
5. วางสตริงคุกกี้ลงในช่อง `apiKey` แล้วกด **Save**

OmniRoute จะแยก `uid`, `si_usr_id` และ `si_ses_id` ออกจากสตริงที่วาง และสร้างส่วนหัว `Cookie` ใหม่แบบสะอาดซึ่งมีเฉพาะคู่ค่าเหล่านั้น — รวมถึง `nt_session` (โทเค็น `ntk_…` ที่ตั้งค่าไว้สำหรับบัญชีที่เข้าสู่ระบบ) หากมีอยู่ หากขาดรายการใดรายการหนึ่งในสามรายการนี้ สตริงดิบที่วางจะถูกส่งต่อโดยไม่มีการแก้ไข เพื่อให้ผู้ดูแลระบบสามารถทดลองใช้รูปแบบอื่นได้

### รหัสโมเดล

| รหัสโมเดล   | ชื่อที่แสดง | หมายเหตุ                                       |
| ----------- | ----------- | ---------------------------------------------- |
| `notrack-c` | NoTrack C   | ค่าเริ่มต้น — โมเดลการจัดส่งต้นทาง `C`         |
| `C`         | NoTrack C   | นามแฝงของ `notrack-c` (รหัสการจัดส่งต้นทางดิบ) |
| `notrack`   | NoTrack C   | นามแฝงของ `notrack-c`                          |
| `ntw`       | NoTrack C   | นามแฝงแบบสั้นของ `notrack-c`                   |

รหัสโมเดลทั้งสี่รายการจะถูกแมปไปยังโมเดลการจัดส่งต้นทางเดียวกัน (`C`)

### ตัวเลือกคำขอ

ตัวดำเนินการรองรับฟิลด์ทางเลือกต่อไปนี้ในเนื้อหาคำขอ:

| ฟิลด์ในเนื้อหา        | ค่าเริ่มต้น | วัตถุประสงค์                                                    |
| --------------------- | ----------- | --------------------------------------------------------------- |
| `notrack_mode`        | `usual`     | โหมดการจัดส่ง (สตริงรูปแบบอิสระ โดยระบบต้นทางรองรับ `usual`, …) |
| `notrack_max_turns`   | `6`         | จำนวนรอบภายในที่ระบบต้นทางสามารถดำเนินการได้ก่อนตอบกลับ         |
| `notrack_chat_id`     | `null`      | ดำเนินการแชตต้นทางที่มีอยู่ต่อ (ละเว้นเพื่อเริ่มแชตใหม่)        |
| `notrack_attachments` | `[]`        | อาร์เรย์ตัวอธิบายไฟล์แนบต้นทางที่ส่งผ่านโดยตรง                  |
| `notrack_regenerate`  | `false`     | ตั้งค่าเป็น `true` เพื่อขอให้สร้างคำตอบใหม่สำหรับรอบก่อนหน้า    |

### ความสามารถ

- รองรับการเติมเต็มแชตทั้งแบบ **สตรีมมิงและไม่ใช่สตรีมมิง**
- **การเรียกใช้เครื่องมือ** — ตั้งค่า `tools: [...]` ในคำขอ ตัวดำเนินการจะแปลงเป็นอนุกรมตามสัญญาเอนเวโลปการเรียกใช้เครื่องมือ และแยกวิเคราะห์การตอบกลับของโมเดลกลับเป็น `tool_calls` ของ OpenAI
- **`response_format`** — รองรับ `json_object` และ `json_schema` ตัวดำเนินการจะแยกออบเจ็กต์ JSON แรกจากคำตอบของโมเดล แล้วแปลงเป็นสตริงก่อนส่งคืน
- **คำใบ้การให้เหตุผล** — ตัวดำเนินการจะปล่อยเดลตา `reasoning` เมื่อระบบต้นทางส่งเหตุการณ์ `thinking`

### ข้อจำกัด

- ระบบต้นทางบังคับใช้โควตาการใช้งานแบบไม่ระบุตัวตน — เมื่อถึงขีดจำกัด ตัวดำเนินการจะแสดงข้อผิดพลาด 429 พร้อมข้อความที่เข้าใจง่าย
- รหัสโมเดลทั้งหมดจะถูกแก้ไขไปยังโมเดลการจัดส่งต้นทางเดียวกัน โดยไม่มีการสลับแยกตามโมเดล
- ตัวดำเนินการไม่เรียกเอนด์พอยต์ `/api/chats` ของระบบต้นทาง ดังนั้นประวัติแชต/เซสชันจะไม่ได้รับการจัดการโดยอัตโนมัติ ใช้ `notrack_chat_id` เพื่อดำเนินการแชตต้นทางที่มีอยู่ต่อ

# สิ่งที่ผู้ให้บริการ Web Cookie ทำได้และทำไม่ได้

ผู้ให้บริการ Web Cookie นำอินเทอร์เฟซแชตของเว็บไซต์กลับมาใช้ใหม่ โดย **ไม่ได้** มอบความสามารถเช่นเดียวกับ API อย่างเป็นทางการ

## รองรับ

- ยืนยันตัวตนโดยใช้เซสชันเบราว์เซอร์ที่มีอยู่
- เข้าถึงโมเดลที่พร้อมใช้งานผ่านบัญชีของคุณ
- สตรีมการตอบกลับจากแชต
- ไม่ต้องใช้คีย์ API

## ไม่รองรับ

- การเรียกใช้ฟังก์ชัน
- การเรียกใช้เครื่องมือ
- การแก้ไขไฟล์โดยอัตโนมัติ
- เวิร์กโฟลว์ IDE แบบเอเจนต์
- ฟีเจอร์ที่ใช้งานได้ผ่าน API เท่านั้น

นี่เป็นพฤติกรรมที่คาดไว้และ **ไม่ใช่** บั๊ก

หากคุณต้องการเรียกใช้เครื่องมือ แก้ไขไฟล์โดยอัตโนมัติ หรือใช้เวิร์กโฟลว์แบบเอเจนต์อื่นๆ ให้ใช้ **ผู้ให้บริการที่ใช้คีย์ API** แทนผู้ให้บริการ Web Cookie

# ข้อควรระวังเกี่ยวกับการตรวจสอบความถูกต้อง

การ **Test Connection** สำเร็จหรือการตรวจสอบคุกกี้ผ่าน เป็นเพียงการยืนยันว่าข้อมูลประจำตัวที่ระบุดูเหมือนจะอยู่ในรูปแบบที่คาดไว้เท่านั้น

จนกว่า Issue #7857 จะได้รับการแก้ไข การตรวจสอบที่สำเร็จ **ไม่ได้รับประกัน** ว่าผู้ให้บริการจะยืนยันตัวตนได้สำเร็จ

หากการยืนยันตัวตนยังคงล้มเหลว ให้ตรวจสอบว่าคุณคัดลอกข้อมูลประจำตัวจากคำขอเครือข่ายที่กำลังใช้งานอยู่ ไม่ใช่จากพื้นที่จัดเก็บคุกกี้ของเบราว์เซอร์

---

# การแก้ไขปัญหา

## การยืนยันตัวตนล้มเหลว

ตรวจสอบว่าคัดลอกข้อมูลประจำตัวมาจาก:

```
Network
→ Request Headers
→ Cookie
```

และ **ไม่ใช่** จาก:

```
Application
→ Cookies
```

---

## คุกกี้ทำงานในเบราว์เซอร์แต่ไม่ทำงานใน OmniRoute

ผู้ให้บริการบางรายมีคุกกี้ที่จะถูกส่งเฉพาะระหว่างคำขอที่ผ่านการยืนยันตัวตนแล้วเท่านั้น

คัดลอกข้อมูลประจำตัวอีกครั้งจากคำขอเครือข่ายใหม่ หลังจากเปิดการสนทนาได้สำเร็จ

---

## เซสชันหมดอายุ

ผู้ให้บริการ Web Cookie ใช้เซสชันเบราว์เซอร์ที่มีอยู่ของคุณ

หากเซสชันเบราว์เซอร์หมดอายุหรือคุณออกจากระบบ คุณต้องคัดลอกข้อมูลประจำตัวชุดใหม่ หากต้องการดำเนินการต่ออายุคุกกี้โดยอัตโนมัติสำหรับผู้ให้บริการเว็บที่รองรับ โปรดดูเครื่องมือเสริม [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md)

---

## Test Connection ผ่านแต่คำขอล้มเหลว

จนกว่า Issue #7857 จะได้รับการแก้ไข การผ่านการตรวจสอบไม่ได้รับประกันว่าคำขอยืนยันตัวตนจะสำเร็จ

คัดลอกข้อมูลประจำตัวอีกครั้งจากคำขอใหม่ที่ผ่านการยืนยันตัวตนแล้ว ก่อนดำเนินการแก้ไขปัญหาเพิ่มเติม

---

# ตัวอย่างผู้ให้บริการ

สำหรับคำแนะนำแบบทีละขั้นตอนที่ครบถ้วนสำหรับผู้ให้บริการรายใดรายหนึ่ง โปรดดู:

- **Claude Web** — `docs/providers/CLAUDE_WEB.md`

คู่มือ Claude Web สาธิตกระบวนการตั้งค่าที่ครบถ้วนสำหรับผู้ให้บริการ Web Cookie และใช้เป็นการใช้งานอ้างอิง

---

# แนวทางปฏิบัติที่ดีที่สุด

- คัดลอกข้อมูลประจำตัวจากคำขอใหม่ที่ผ่านการยืนยันตัวตนแล้ว
- หลีกเลี่ยงการนำคุกกี้เก่ากลับมาใช้ซ้ำ
- รักษาเซสชันเบราว์เซอร์ให้ทำงานอยู่ขณะใช้ผู้ให้บริการ Web Cookie
- ปฏิบัติต่อคุกกี้ที่คัดลอกมาเสมือนเป็นข้อมูลประจำตัวที่ละเอียดอ่อน
- ใช้ผู้ให้บริการที่ใช้คีย์ API เมื่อคุณต้องการการเรียกใช้ฟังก์ชันหรือเวิร์กโฟลว์แบบเอเจนต์
