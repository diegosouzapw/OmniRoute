ผู้ให้บริการ Web Cookie ช่วยให้ OmniRoute สามารถใช้บริการ AI ผ่านเซสชันเบราว์เซอร์ที่มีอยู่ของคุณแทน API key ได้ ซึ่งมีประโยชน์เมื่อคุณมีสิทธิ์เข้าถึงบริการผ่านเว็บไซต์อยู่แล้ว และต้องการให้ OmniRoute ใช้เซสชันที่ผ่านการยืนยันตัวตนเดียวกัน

ผู้ให้บริการ Web Cookie แตกต่างจากผู้ให้บริการแบบ API key ตรงที่ใช้ข้อมูลรับรองที่เบราว์เซอร์ส่งไปยังเว็บไซต์เพื่อยืนยันตัวตน

# ก่อนเริ่มต้น

> **สำคัญ:** คัดลอกข้อมูลรับรองจาก **คำขอเครือข่ายที่กำลังใช้งานจริง** เสมอ และ **อย่า** คัดลอกจากพื้นที่จัดเก็บคุกกี้ของเบราว์เซอร์

ปัญหาการยืนยันตัวตนจำนวนมากเกิดจากการคัดลอกคุกกี้มาจากตำแหน่งที่ไม่ถูกต้อง

## อย่าคัดลอกจากพื้นที่จัดเก็บคุกกี้

เบราว์เซอร์ส่วนใหญ่แสดงคุกกี้ที่จัดเก็บไว้ผ่าน:

```
DevTools
→ Application (หรือ Storage)
→ Cookies
```

แม้ว่าคุกกี้เหล่านี้จะดูถูกต้อง แต่คุกกี้อาจ:

- หมดอายุหรือไม่เป็นปัจจุบัน
- ไม่ครบถ้วน
- ขาดคุกกี้ที่ส่งเฉพาะในคำขอที่ผ่านการยืนยันตัวตนเท่านั้น

การใช้ค่าเหล่านี้อาจทำให้การยืนยันตัวตนล้มเหลว แม้ว่าค่าจะดูเหมือนใช้ได้ก็ตาม

## คัดลอกจากคำขอที่กำลังใช้งานจริง

ให้ใช้คุกกี้จากคำขอที่สำเร็จแทน:

```
DevTools
→ Network
→ รีเฟรชหน้า
→ เปิดคำขอแชตหรือการสนทนา
→ Request Headers
→ Cookie
```

ส่วนหัวคำขอ `Cookie` มีข้อมูลการยืนยันตัวตนที่ตรงกับข้อมูลที่เบราว์เซอร์ของคุณใช้สำเร็จทุกประการ

สำหรับผู้ให้บริการ Web Cookie ส่วนใหญ่ ค่านี้คือค่าที่ควรวางลงใน OmniRoute

# การตั้งค่าทั่วไป

ขั้นตอนการตั้งค่าจะเหมือนกันสำหรับผู้ให้บริการ Web Cookie ส่วนใหญ่

1. ลงชื่อเข้าใช้เว็บไซต์ของผู้ให้บริการ
2. เปิดเครื่องมือสำหรับนักพัฒนาของเบราว์เซอร์
3. เปิดแท็บ **Network**
4. รีเฟรชหน้า
5. เปิดคำขอแชตหรือการสนทนาที่ผ่านการยืนยันตัวตน
6. คัดลอกข้อมูลรับรองที่จำเป็น
7. เปิด OmniRoute
8. ไปที่ **Providers → Add Provider**
9. เลือกผู้ให้บริการ Web Cookie ของคุณ
10. วางข้อมูลรับรอง
11. คลิก **Test Connection**
12. บันทึกผู้ให้บริการ

ข้อมูลรับรองที่จำเป็นจะแตกต่างกันไปตามผู้ให้บริการ

# สิ่งที่ผู้ให้บริการ Web Cookie ทำได้และทำไม่ได้

ผู้ให้บริการ Web Cookie ใช้อินเทอร์เฟซแชตของเว็บไซต์ซ้ำ ซึ่ง **ไม่ได้** มอบความสามารถในระดับเดียวกับ API อย่างเป็นทางการ

## รองรับ

- ยืนยันตัวตนโดยใช้เซสชันเบราว์เซอร์ที่มีอยู่ของคุณ
- เข้าถึงโมเดลที่บัญชีของคุณสามารถใช้งานได้
- สตรีมการตอบกลับของแชต
- ไม่ต้องใช้ API key

## ไม่รองรับ

- การเรียกใช้ฟังก์ชัน
- การเรียกใช้เครื่องมือ
- การแก้ไขไฟล์โดยอัตโนมัติ
- เวิร์กโฟลว์ IDE แบบเอเจนต์
- ฟีเจอร์ที่มีเฉพาะใน API

นี่เป็นพฤติกรรมที่คาดไว้และ **ไม่ใช่** ข้อบกพร่อง

หากคุณต้องการเรียกใช้เครื่องมือ แก้ไขไฟล์โดยอัตโนมัติ หรือใช้เวิร์กโฟลว์แบบเอเจนต์อื่นๆ ให้ใช้ **ผู้ให้บริการแบบ API key** แทนผู้ให้บริการ Web Cookie

# ข้อควรระวังเกี่ยวกับการตรวจสอบความถูกต้อง

การที่ **Test Connection** หรือการตรวจสอบคุกกี้สำเร็จ เป็นเพียงการยืนยันว่าข้อมูลรับรองที่ระบุดูเหมือนจะอยู่ในรูปแบบที่คาดไว้

จนกว่า Issue #7857 จะได้รับการแก้ไข การตรวจสอบที่สำเร็จ **ไม่ได้รับประกัน** ว่าผู้ให้บริการจะยืนยันตัวตนได้สำเร็จ

หากการยืนยันตัวตนยังคงล้มเหลว ให้ตรวจสอบว่าคุณคัดลอกข้อมูลรับรองจากคำขอเครือข่ายที่กำลังใช้งานจริง ไม่ใช่จากพื้นที่จัดเก็บคุกกี้ของเบราว์เซอร์

---

# การแก้ไขปัญหา

## การยืนยันตัวตนล้มเหลว

ตรวจสอบว่าข้อมูลรับรองถูกคัดลอกจาก:

```
Network
→ Request Headers
→ Cookie
```

และ **ไม่ได้** คัดลอกจาก:

```
Application
→ Cookies
```

---

## คุกกี้ใช้ได้ในเบราว์เซอร์ แต่ใช้ไม่ได้ใน OmniRoute

ผู้ให้บริการบางรายมีคุกกี้ที่ส่งเฉพาะระหว่างคำขอที่ผ่านการยืนยันตัวตนเท่านั้น

คัดลอกข้อมูลรับรองอีกครั้งจากคำขอเครือข่ายใหม่ หลังจากเปิดการสนทนาสำเร็จแล้ว

---

## เซสชันหมดอายุ

ผู้ให้บริการ Web Cookie ใช้เซสชันเบราว์เซอร์ที่มีอยู่ของคุณ

หากเซสชันเบราว์เซอร์หมดอายุหรือคุณลงชื่อออก คุณต้องคัดลอกข้อมูลรับรองชุดใหม่

---

## Test Connection ผ่าน แต่คำขอล้มเหลว

จนกว่า Issue #7857 จะได้รับการแก้ไข การผ่านการตรวจสอบไม่ได้รับประกันว่าคำขอยืนยันตัวตนจะสำเร็จ

คัดลอกข้อมูลรับรองของคุณอีกครั้งจากคำขอใหม่ที่ผ่านการยืนยันตัวตน ก่อนดำเนินการแก้ไขปัญหาเพิ่มเติม

---

# ตัวอย่างผู้ให้บริการ

สำหรับคำแนะนำแบบทีละขั้นตอนที่ครบถ้วนสำหรับผู้ให้บริการรายใดรายหนึ่ง โปรดดู:

- **Claude Web** — `docs/providers/CLAUDE_WEB.md`

คู่มือ Claude Web แสดงขั้นตอนการตั้งค่าที่ครบถ้วนสำหรับผู้ให้บริการ Web Cookie และใช้เป็นการติดตั้งใช้งานอ้างอิง

---

# แนวทางปฏิบัติที่ดีที่สุด

- คัดลอกข้อมูลรับรองจากคำขอใหม่ที่ผ่านการยืนยันตัวตน
- หลีกเลี่ยงการนำคุกกี้เก่ากลับมาใช้
- รักษาเซสชันเบราว์เซอร์ให้ทำงานอยู่ขณะใช้ผู้ให้บริการ Web Cookie
- ปฏิบัติต่อคุกกี้ที่คัดลอกมาเสมือนเป็นข้อมูลรับรองที่ละเอียดอ่อน
- ใช้ผู้ให้บริการแบบ API key เมื่อคุณต้องการเรียกใช้ฟังก์ชันหรือเวิร์กโฟลว์แบบเอเจนต์
