## การทำงาน

แทนที่จะเลือกโมเดล AI เฉพาะเจาะจง (เช่น GPT-4o หรือ Claude) คุณสามารถให้ OmniRoute **เลือกโมเดลที่ดีที่สุดโดยอัตโนมัติ** สำหรับแต่ละคำขอ โดยจะพิจารณาปัจจัยต่อไปนี้:

- **สถานะการทำงาน** — ผู้ให้บริการทำงานอยู่ในขณะนี้หรือไม่?
- **ความเร็ว** — ทำงานเร็วเพียงใด?
- **ค่าใช้จ่าย** — มีค่าใช้จ่ายเท่าใด?
- **คุณภาพ** — เหมาะกับงานประเภทนี้หรือไม่?
- **ความจุ** — มีโควตาเหลืออยู่หรือไม่?

OmniRoute จะให้คะแนนผู้ให้บริการทั้งหมดที่คุณเชื่อมต่อไว้และเลือกตัวเลือกที่ดีที่สุด หากตัวเลือกนั้นล้มเหลว ระบบจะลองใช้ตัวเลือกถัดไปโดยอัตโนมัติ

---

## เริ่มต้นใช้งานอย่างรวดเร็ว

**ขั้นตอนที่ 1**: ตั้งค่าโมเดลเป็น `auto` ใน IDE หรือ CLI ของคุณ:

```
model: "auto"
```

**ขั้นตอนที่ 2**: เพียงเท่านี้! OmniRoute จะจัดการส่วนที่เหลือให้เอง

**ขั้นตอนที่ 3** (ไม่บังคับ): ใช้ตัวเลือกย่อยสำหรับงานเฉพาะ:

```
model: "auto/coding"    # เหมาะที่สุดสำหรับโค้ด
model: "auto/fast"      # ตอบกลับเร็วที่สุด
model: "auto/cheap"     # ตัวเลือกที่ถูกที่สุด
```

## วิธีการทำงาน (ฉบับเข้าใจง่าย)

เมื่อคุณส่งคำขอโดยใช้ `model: "auto"` OmniRoute จะ:

1. **ตรวจสอบผู้ให้บริการทั้งหมดที่คุณเชื่อมต่อไว้** — ผู้ให้บริการทุกรายที่คุณเพิ่มไว้ (OpenAI, Anthropic, Google เป็นต้น)
2. **ให้คะแนนผู้ให้บริการแต่ละราย** โดยพิจารณาปัจจัยต่าง ๆ ซึ่งรวมถึง:
   - ใช้งานได้หรือไม่? (สถานะการทำงาน)
   - มีความจุเหลือหรือไม่? (โควตา)
   - มีค่าใช้จ่ายเท่าใด? (ราคา)
   - ทำงานเร็วเพียงใด? (ความเร็ว)
   - เหมาะกับงานนี้หรือไม่? (คุณภาพ)
3. **เลือกตัวเลือกที่ดีที่สุด** — ผู้ให้บริการที่ได้คะแนนสูงสุดจะได้รับคำขอของคุณ
4. **กู้คืนโดยอัตโนมัติ** — หากล้มเหลว OmniRoute จะลองใช้ตัวเลือกถัดไปโดยอัตโนมัติ

### ระบบการให้คะแนน

ผู้ให้บริการแต่ละรายจะได้รับคะแนนตั้งแต่ 0 ถึง 1 ยิ่งคะแนนสูง ก็ยิ่งเหมาะสมมากขึ้น

| ปัจจัย            | น้ำหนัก | ความหมาย                                                 |
| ----------------- | ------- | -------------------------------------------------------- |
| สถานะการทำงาน     | 20%     | ผู้ให้บริการทำงานอยู่หรือไม่? (สถานะ circuit breaker)    |
| โควตา             | 15%     | มีความจุเหลืออยู่หรือไม่?                                |
| ค่าใช้จ่าย        | 15%     | มีราคาแพงเพียงใด? (ยิ่งถูก = คะแนนยิ่งสูง)               |
| ความเร็ว          | 12%     | ทำงานเร็วเพียงใด? (เวลาแฝงยิ่งต่ำ = คะแนนยิ่งสูง)        |
| ความเหมาะสมกับงาน | 8%      | เหมาะกับงานประเภทนี้หรือไม่?                             |
| ความเสถียร        | 5%      | ทำงานสม่ำเสมอหรือไม่? (อัตราข้อผิดพลาดต่ำ)               |
| ระดับบัญชี        | 5%      | ระดับบัญชี (Ultra > Pro > Free)                          |
| อื่น ๆ            | 20%     | ความสอดคล้องกับบริบท, ความหนาแน่นของการเชื่อมต่อ เป็นต้น |

### ตัวเลือกย่อยเปลี่ยนการให้คะแนนอย่างไร

ตัวเลือกย่อยแต่ละแบบใช้น้ำหนักที่แตกต่างกัน:

| ตัวเลือกย่อย   | ให้ความสำคัญกับ   | น้ำหนักหลัก                     |
| -------------- | ----------------- | ------------------------------- |
| `auto`         | ความสมดุล         | health=20%, quota=15%, cost=15% |
| `auto/coding`  | คุณภาพ            | taskFit=37%, stability=15%      |
| `auto/fast`    | ความเร็ว          | latency=32%, health=28%         |
| `auto/cheap`   | ค่าใช้จ่าย        | cost=37%                        |
| `auto/smart`   | คุณภาพ + การสำรวจ | taskFit=37%, exploration=10%    |
| `auto/offline` | ความจุ            | quota=37%, health=28%           |

## วิธีจัดการกับความล้มเหลว

OmniRoute มี **การป้องกันสามชั้น**:

### 1. การสลับไปใช้ตัวเลือกสำรองโดยอัตโนมัติ

หากผู้ให้บริการที่ดีที่สุดล้มเหลว OmniRoute จะลองใช้ผู้ให้บริการรายถัดไปโดยอัตโนมัติ คุณไม่จำเป็นต้องดำเนินการใดๆ

### 2. การกู้คืนตัวเอง

หากผู้ให้บริการล้มเหลวอย่างต่อเนื่อง:

- **คะแนน < 0.2** → ถูกระงับการใช้งานเป็นเวลา 5 นาที
- **Circuit breaker เปิดอยู่** → ถูกระงับการใช้งานโดยอัตโนมัติ
- **ผู้ให้บริการใช้งานไม่ได้มากกว่า 50%** → โหมดเหตุขัดข้อง (ไม่มีการสำรวจ)

### 3. ตัวเลือกสำรองฉุกเฉิน

หากผู้ให้บริการทั้งหมดล้มเหลว OmniRoute จะกำหนดเส้นทางไปยังผู้ให้บริการฟรีที่เสถียร (เช่น Kiro หรือ Qoder) เป็นทางเลือกสุดท้าย

## การรองรับหลายบัญชี

หากคุณมีหลายบัญชีสำหรับผู้ให้บริการรายเดียวกัน (เช่น คีย์ OpenAI สองคีย์) OmniRoute จะถือว่าแต่ละบัญชีเป็น **ตัวเลือกแยกกัน** ซึ่งหมายความว่า:

- บัญชี A ยังมีโควตาเหลืออยู่ → ใช้งานบัญชีนี้
- บัญชี B ถูกจำกัดอัตราการใช้งาน → ข้ามบัญชีนี้
- บัญชี C มีราคาถูกกว่า → เลือกบัญชีนี้ก่อน

แต่ละบัญชีจะได้รับการให้คะแนนอย่างอิสระตามสถานะการทำงาน โควตา และความเร็วของบัญชีนั้นๆ

---

## การสำรวจด้วย Bandit

OmniRoute จะ **สำรวจ** ผู้ให้บริการรายใหม่เป็นครั้งคราวเพื่อค้นหาตัวเลือกที่ดีกว่า:

- **ค่าเริ่มต้น**: 5% ของคำขอจะถูกส่งไปยังผู้ให้บริการแบบสุ่ม
- **Auto/smart**: อัตราการสำรวจ 10%
- **ปิดใช้งาน** เมื่อผู้ให้บริการมากกว่า 50% มีสถานะผิดปกติ

วิธีนี้ช่วยให้ OmniRoute เรียนรู้ว่าผู้ให้บริการรายใดทำงานได้ดีที่สุดสำหรับรูปแบบการใช้งานของคุณ

## คำถามที่พบบ่อย

### "ระบบจะเลือกโมเดลที่แพงที่สุดเสมอหรือไม่?"

**ไม่** โดยค่าเริ่มต้น ค่าใช้จ่ายมีสัดส่วนเพียง 15% ของคะแนน ผู้ให้บริการที่ราคาถูก รวดเร็ว และมีสถานะปกติสามารถทำคะแนนได้ดีกว่าผู้ให้บริการที่มีราคาแพง ใช้ `auto/cheap` หากคุณต้องการให้ความสำคัญกับค่าใช้จ่ายมากยิ่งขึ้น

### "หากผู้ให้บริการใช้งานไม่ได้จะเกิดอะไรขึ้น?"

OmniRoute จะข้ามผู้ให้บริการรายนั้นโดยอัตโนมัติและลองใช้รายถัดไป หากผู้ให้บริการล้มเหลวอย่างต่อเนื่อง ระบบจะระงับการใช้งานชั่วคราว (5-30 นาที) คุณไม่จำเป็นต้องดำเนินการใดๆ

### "ฉันสามารถดูได้หรือไม่ว่ามีการใช้ผู้ให้บริการรายใด?"

ตรวจสอบส่วนหัวของการตอบกลับ — OmniRoute จะระบุผู้ให้บริการและโมเดลที่ใช้ในการตอบกลับแต่ละครั้ง

### "ระบบเรียนรู้จากการใช้งานของฉันหรือไม่?"

ใช่! ระบบการให้คะแนนใช้ข้อมูลย้อนหลัง (เวลาแฝง อัตราข้อผิดพลาด และอัตราความสำเร็จ) เพื่อทำการตัดสินใจที่ดีขึ้นเมื่อเวลาผ่านไป

### "`auto` และ `auto/smart` แตกต่างกันอย่างไร?"

- `auto` — สมดุล พร้อมอัตราการสำรวจ 5%
- `auto/smart` — ให้ความสำคัญกับคุณภาพเป็นอันดับแรก (ใช้น้ำหนักเดียวกับ `auto/coding`) พร้อมอัตราการสำรวจ 10%

ใช้ `auto/smart` เมื่อคุณต้องการคุณภาพที่ดีที่สุดและยอมรับการสำรวจเป็นครั้งคราวได้

### "ฉันสามารถบังคับให้ใช้ผู้ให้บริการรายใดรายหนึ่งได้หรือไม่?"

ได้! ใช้คอมโบที่มีกลยุทธ์ `priority` แทน `auto` จากนั้นส่ง **ชื่อที่ตรงกันทุกประการ** ของคอมโบเป็นฟิลด์ `model` (เช่น `model: "my-combo"` — ไม่ใช่ `auto`) ดูรายละเอียดได้ใน[เอกสารอ้างอิงทางเทคนิค](../routing/AUTO-COMBO.md)

### "วิธีนี้แตกต่างจาก round-robin อย่างไร?"

Round-robin จะวนใช้ผู้ให้บริการตามลำดับ ส่วน Auto-combo จะ **ให้คะแนนผู้ให้บริการแต่ละราย** และเลือกผู้ให้บริการที่ดีที่สุด วิธีนี้ฉลาดกว่า เพราะพิจารณาสถานะการทำงาน ความเร็ว ค่าใช้จ่าย และคุณภาพ
