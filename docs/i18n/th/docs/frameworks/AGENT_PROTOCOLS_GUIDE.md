OmniRoute มีช่องทางที่เกี่ยวข้องกับเอเจนต์อยู่สามรูปแบบ แม้ในตอนแรกจะดูคล้ายกัน แต่แต่ละรูปแบบใช้แก้ปัญหาที่แตกต่างกัน ใช้หน้านี้เพื่อเลือกรูปแบบที่เหมาะสม

## สรุปโดยย่อ

| ช่องทาง                       | เหมาะที่สุดสำหรับ                                                                                                                             | การรับส่งข้อมูล                      | มาตรฐาน                    |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ | -------------------------- |
| **A2A — เอเจนต์ถึงเอเจนต์**   | การทำงานร่วมกันข้ามเอเจนต์กับเอเจนต์อื่นที่รองรับโปรโตคอล A2A                                                                                 | JSON-RPC 2.0 ผ่าน HTTP               | A2A v0.3 (ข้อกำหนดแบบเปิด) |
| **ACP — รีจิสทรีเอเจนต์ CLI** | การตรวจหา / ลงทะเบียน / เปิดใช้งานเอเจนต์เขียนโค้ดแบบ CLI ที่ติดตั้งอยู่บนเครื่องของผู้ใช้ (Cursor, Cline, Codex CLI, Claude Code, Aider ฯลฯ) | HTTP REST                            | เฉพาะ OmniRoute            |
| **Cloud Agents**              | การส่งงานเขียนโค้ดที่ใช้เวลานานไปยังบริการคลาวด์ภายนอก (Codex Cloud, Devin, Jules, Cursor Cloud)                                              | HTTP REST + งานที่จัดเก็บในฐานข้อมูล | เฉพาะ OmniRoute            |

ทั้งสามรูปแบบทำงานแยกจากกัน — เลือกใช้ชุดใดก็ได้

## แผนผังการตัดสินใจ

```
คุณต้องการให้บริการคลาวด์ทำงานภายนอกเครื่องนี้หรือไม่ (Codex Cloud / Cursor Cloud / Devin / Jules)?
├─ ใช่ → Cloud Agents (POST /api/v1/agents/tasks)
└─ ไม่ใช่ → ดำเนินการต่อ
    │
    คุณมีเอเจนต์อื่นที่รองรับ A2A และต้องการทำงานร่วมกันหรือไม่?
    ├─ ใช่ → A2A (POST /a2a)
    └─ ไม่ใช่ → ดำเนินการต่อ
        │
        คุณต้องการแสดงรายการ / กำหนดค่าเอเจนต์เขียนโค้ดแบบ CLI ที่ติดตั้งในเครื่องหรือไม่?
        ├─ ใช่ → ACP (GET /api/acp/agents)
        └─ ไม่ใช่ → ใช้ /v1/chat/completions แบบปกติ
```

## 1. A2A — เอเจนต์ถึงเอเจนต์

**ข้อกำหนด:** [A2A v0.3](https://a2a-protocol.org)
**เอนด์พอยต์ของ OmniRoute:** `POST /a2a` (JSON-RPC 2.0)
**การ์ดเอเจนต์:** `GET /.well-known/agent.json`

### ควรใช้เมื่อใด

- สร้างระบบหลายเอเจนต์ที่มี OmniRoute เป็นหนึ่งในเอเจนต์ที่ทำงานร่วมกัน
- เปิดให้เอเจนต์ในเฟรมเวิร์กอย่าง Google ADK หรือเครือข่ายเอเจนต์ทั่วไปสามารถใช้ความสามารถด้านการกำหนดเส้นทางอัจฉริยะของ OmniRoute (smart-routing, quota-management ฯลฯ)
- ครอบ OmniRoute ไว้เบื้องหลังช่องทางมาตรฐานสำหรับการค้นหาและการเรียกใช้งาน

### เมธอด

- `message/send` — ส่งข้อความและรับการตอบกลับแบบซิงโครนัส
- `message/stream` — ส่งข้อความและรับเหตุการณ์ความคืบหน้าแบบสตรีมผ่าน SSE
- `tasks/get` — อ่านงานตาม ID
- `tasks/cancel` — ยกเลิกงานที่กำลังทำงานอยู่

### ทักษะในตัว (6)

- `smart-routing` — กำหนดเส้นทางพรอมต์ผ่านชุดการทำงานที่เหมาะสมที่สุด
- `quota-management` — รายงานสถานะโควตาของผู้ให้บริการแต่ละราย
- `provider-discovery` — แสดงรายการผู้ให้บริการที่ติดตั้งไว้พร้อมความสามารถ
- `cost-analysis` — ประเมินค่าใช้จ่ายของคำขอ/การสนทนา
- `health-report` — รวบรวมสถานะ breaker/cooldown/lockout ของผู้ให้บริการแต่ละราย
- `list-capabilities` — แจกแจงทักษะและข้อมูลเมตาที่เอเจนต์มีให้ใช้งาน

### เจาะลึก

ดูรายละเอียดการรับส่งข้อมูล โครงสร้างการ์ดเอเจนต์ การกำหนดค่า TTL ของงาน และเทมเพลตสำหรับเพิ่มทักษะใหม่ได้ที่ [A2A-SERVER.md](./A2A-SERVER.md)

## 2. ACP — รีจิสทรีเอเจนต์ CLI

**เอนด์พอยต์ OmniRoute:** `GET /api/acp/agents`
**ซอร์ส:** `src/lib/acp/{index,manager,registry}.ts`

### คืออะไร

ACP คือ **คลังรายการเอเจนต์ CLI ภายในเครื่อง** ของ OmniRoute โดยจะตรวจหา CLI สำหรับเขียนโค้ดที่ติดตั้งอยู่บนโฮสต์ (Cursor, Cline, Claude Code, Codex CLI, Continue ฯลฯ) ตรวจสอบเวอร์ชัน และแสดงข้อมูลเหล่านั้นบนแดชบอร์ด เพื่อให้ผู้ใช้กำหนดค่า CLI แต่ละตัวให้ชี้ไปยัง OmniRoute ได้

นี่ไม่ใช่โปรโตคอลภายนอก แต่เป็นรีจิสทรีภายในที่ขับเคลื่อน UI "CLI Tools" และการติดตามลายนิ้วมือของ CLI (ดู [CLI-TOOLS.md](../reference/CLI-TOOLS.md))

### ทำอะไรบ้าง

- ตรวจสอบไบนารี CLI ที่ติดตั้งอยู่บนโฮสต์ (ใช้ `which` / `where` ตามระบบปฏิบัติการ)
- อ่านเวอร์ชันของ CLI แต่ละตัว (เรียกใช้ `<bin> --version`)
- รองรับเอเจนต์แบบกำหนดเองที่ผู้ใช้ระบุได้ (พาธไบนารี + คำสั่งตรวจสอบเวอร์ชัน + อาร์กิวเมนต์สำหรับเรียกใช้)
- บันทึกเอเจนต์แบบกำหนดเองไว้ในการตั้งค่า
- ส่งคืนรายการแบบรวมให้แดชบอร์ด

### REST API

| เอนด์พอยต์        | เมธอด | คำอธิบาย                                                                  | การยืนยันตัวตน |
| ----------------- | ----- | ------------------------------------------------------------------------- | -------------- |
| `/api/acp/agents` | GET   | แสดงรายการเอเจนต์ที่ตรวจพบและเอเจนต์แบบกำหนดเอง (จำนวนที่ติดตั้ง/ทั้งหมด) | คีย์ API       |
| `/api/acp/agents` | POST  | เพิ่ม/อัปเดต/ลบเอเจนต์แบบกำหนดเอง (ตัวจำแนกการดำเนินการอยู่ในเนื้อหาคำขอ) | คีย์ API       |

รูปแบบเนื้อหาสำหรับ POST (`customAgentBodySchema` ใน `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### กรณีการใช้งาน

- หน้า "CLI Tools" บนแดชบอร์ดแสดงรายการเครื่องมือที่ติดตั้งอยู่ และช่วยให้คุณกำหนดค่าแต่ละเครื่องมือให้ชี้ไปยัง OmniRoute
- เอเจนต์แบบกำหนดเองช่วยให้ผู้ใช้ขั้นสูงลงทะเบียน CLI ภายในองค์กรหรือ CLI ที่เป็นกรรมสิทธิ์ ซึ่ง OmniRoute ไม่รู้จักโดยค่าเริ่มต้นได้
- ผลการตรวจจับจะใช้เป็นข้อมูลสำหรับเมทริกซ์ลายนิ้วมือ `cli-tools`

### เมื่อใดที่ไม่ควรใช้ ACP

- ACP ไม่ได้ _เรียกใช้งาน_ งานต่าง ๆ แต่ทำหน้าที่เพียงตรวจหาและกำหนดค่า CLI เท่านั้น หากต้องการเรียกใช้ CLI จริง คุณต้องเปิดใช้งานด้วยตนเองโดยใช้ตัวแปรสภาพแวดล้อมที่ OmniRoute จัดเตรียมไว้ (`OPENAI_BASE_URL`, `OPENAI_API_KEY` ฯลฯ)

## 3. เอเจนต์คลาวด์

**เอนด์พอยต์ OmniRoute:** `/api/v1/agents/tasks/*` (วงจรการทำงาน) + `/api/cloud/*` (โครงสร้างการเชื่อมต่อ)
**ซอร์ส:** `src/lib/cloudAgent/`

### คืออะไร

อินเทอร์เฟซแบบ统一สำหรับเอเจนต์เขียนโค้ดบนคลาวด์ของบุคคลที่สาม คุณส่งพรอมต์และ URL ของรีโพซิทอรี จากนั้น OmniRoute จะส่งงานไปยังเอเจนต์คลาวด์ที่เหมาะสม ตรวจสอบสถานะเป็นระยะ และส่งผลลัพธ์กลับมา

### เอเจนต์ที่รองรับ (3 รายการ ซึ่งทั้งหมดได้รับการยืนยันใน `src/lib/cloudAgent/agents/`)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### วงจรการทำงาน

```
POST /api/v1/agents/tasks
  → BaseAgent.createTask() ตามคลาสของเอเจนต์แต่ละตัว
  → บริการภายนอกเริ่มทำงาน
  → สร้างแถวของงานใน DB (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → ซิงค์สถานะจากผู้ให้บริการแบบ lazy
  → ส่งคืนสถานะปัจจุบัน + แผน + บันทึกกิจกรรม
  ↓
POST /api/v1/agents/tasks/[id]   (action: "approve" | "message" | "cancel")
  → ส่งต่อไปยังผู้ให้บริการ (หรือทำเครื่องหมายว่ายกเลิกภายในระบบ)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → ยกเลิกภายในระบบ
```

### การยืนยันตัวตน

⚠️ **เอนด์พอยต์ `/api/v1/agents/tasks/*` ทั้งหมดต้องใช้การยืนยันตัวตนสำหรับการจัดการ** (คอมมิต `588a0333`) ผู้เรียกที่ใช้เฉพาะ Bearer จะได้รับสถานะ 401 ตั้งแต่ v3.8.0 เป็นต้นมา

### เจาะลึก

ดู [CLOUD_AGENT.md](./CLOUD_AGENT.md) สำหรับข้อกำหนด `CloudAgentBase` รายละเอียดเฉพาะของแต่ละเอเจนต์ รายละเอียดสคีมา และเอนด์พอยต์สำหรับโครงสร้างการเชื่อมต่อข้อมูลรับรอง

## การเปรียบเทียบ: A2A กับ Cloud Agents

ทั้งสองรองรับ "งานที่ใช้เวลานาน" แต่ทำงานอยู่คนละชั้น:

| แง่มุม             | A2A                                                                                               | Cloud Agents                               |
| ------------------ | ------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| มาตรฐาน            | Open A2A v0.3                                                                                     | เฉพาะ OmniRoute                            |
| ตำแหน่งที่ประมวลผล | ภายใน OmniRoute (ใช้ชุดการกำหนดค่าที่ตั้งไว้)                                                     | ภายนอก (เซิร์ฟเวอร์ Codex / Devin / Jules) |
| ระยะเวลาของงาน     | TTL เริ่มต้น 5 นาที (กำหนดค่าได้ใน `TaskManager`)                                                 | หลายนาทีถึงหลายชั่วโมง                     |
| รับรู้บริบทของรีโพ | ไม่ (ส่งผ่านเฉพาะพรอมต์)                                                                          | ใช่ (URL ของรีโพ + แบรนช์)                 |
| กรณีใช้งาน         | การทำงานร่วมกันข้ามเอเจนต์, การกำหนดเส้นทางอัจฉริยะในรูปแบบบริการ                                 | มอบหมายงาน "พัฒนาฟีเจอร์ X ในรีโพ Y"       |
| การยืนยันตัวตน     | เลือกใช้ `OMNIROUTE_API_KEY` สำหรับ `/a2a`; ใช้สิทธิ์การจัดการสำหรับตัวช่วย REST ที่ `/api/a2a/*` | ใช้สิทธิ์การจัดการเสมอ                     |

## ตัวอย่างการเชื่อมต่อ

### ค้นหาความสามารถ A2A ของ OmniRoute

```bash
curl http://localhost:20128/.well-known/agent.json
```

ส่งคืน Agent Card พร้อมทักษะทั้ง 6 รายการ รูปแบบการรับส่งข้อมูล และเวอร์ชัน

### เรียกใช้ OmniRoute ในฐานะเอเจนต์ A2A

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### แสดงรายการเอเจนต์ CLI ที่ติดตั้งผ่าน ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### เพิ่มเอเจนต์ CLI แบบกำหนดเอง

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### ส่งงานไปยัง Cloud Agent

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### ตรวจสอบสถานะงานบนคลาวด์เป็นระยะ

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## ควรใช้อะไรเมื่อใด

- **ฟรอนต์เอนด์แชตบอต / ผู้ช่วยร่วมงาน** → `/v1/chat/completions` (เข้ากันได้กับ OpenAI — ไม่ใช่โปรโตคอลเอเจนต์)
- **การทำงานร่วมกันของหลายเอเจนต์** → A2A
- **การแสดงรายการ CLI ภายในเครื่องบนแดชบอร์ด** → ACP
- **การมอบหมายงานเขียนโค้ดที่ใช้เวลานานให้บริการคลาวด์** → Cloud Agents
