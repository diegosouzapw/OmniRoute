## คืออะไร

OmniRoute เชื่อมต่อกับ vault ของ **Obsidian** ในฐานะ **แหล่งบริบท** — ฐานความรู้ Markdown
ภายในเครื่องที่เอเจนต์อ่านและเขียนผ่านเซิร์ฟเวอร์ MCP ในตัว การผสานรวมนี้สื่อสารกับปลั๊กอินชุมชน
**Obsidian Local REST API** ที่ทำงานอยู่ภายในแอปเดสก์ท็อป เพื่อให้เอเจนต์สามารถค้นหาโน้ต,
อ่าน/เขียน/แก้ไขไฟล์บางส่วน, แสดงรายการภายใน vault, ทำงานกับโน้ตประจำวัน/ประจำสัปดาห์,
จัดการแท็ก, เรียกใช้คำสั่ง Obsidian และ (หากเลือกเปิดใช้) ประสานการซิงค์ vault แบบสองทิศทาง
ระหว่างเดสก์ท็อป↔มือถือ

ไคลเอนต์ (`src/lib/obsidian/api.ts`) ครอบ Local REST API พร้อมด้วย:

- **การลองใหม่โดยเพิ่มระยะเวลารอ** สำหรับข้อผิดพลาดชั่วคราว `5xx`, **หมดเวลาหลัง 30 วินาที** ผ่าน `AbortController`
- **การจำแนกข้อผิดพลาดแบบมีชนิด** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`
- **คำแนะนำที่เข้าใจง่ายเมื่อ "ไม่สามารถเข้าถึง Obsidian"** ซึ่งชี้ให้เห็นข้อผิดพลาดเรื่องพอร์ตที่พบบ่อย
  (HTTP บน `27123` **ไม่ใช่** endpoint MCP บน `27124`) และรูปแบบสำหรับ Tailscale
- **การเข้ารหัสพาธ** แบบอ้างอิงจากรากของ vault เพื่อให้พาธของโน้ตที่มีช่องว่าง/เครื่องหมายทับใช้งานได้อย่างปลอดภัย

## การตั้งค่า

ไม่มี **environment variable** สำหรับโทเค็นหรือ base URL ของ Obsidian — ทั้งสองค่าถูก
จัดเก็บไว้ในตาราง `key_value` ของ SQLite (namespace `obsidian`) ผ่าน
`src/lib/db/obsidian.ts` โทเค็นถูก **เข้ารหัสขณะจัดเก็บ** (AES-256-GCM พร้อมกลไกสำรองเพื่อความเข้ากันได้ย้อนหลัง
กับข้อความธรรมดา) กำหนดค่าได้จากแท็บ **Context Sources** ของแดชบอร์ด
Endpoint (`ObsidianSourceCard`) หรือผ่าน REST API สำหรับการตั้งค่า

> [!IMPORTANT]
> ต้องติดตั้งและเปิดใช้งานปลั๊กอิน **Obsidian Local REST API** อินเทอร์เฟซ REST
> ของปลั๊กอินรับฟังอยู่ที่ **HTTP `127.0.0.1:27123`** (base URL เริ่มต้น) พอร์ต `27124`
> เป็น endpoint MCP/HTTPS ที่_แยกต่างหาก_ และ route การตั้งค่าจะปฏิเสธพอร์ตนี้โดยชัดแจ้ง
> หากเชื่อมต่อจากอุปกรณ์อื่น ให้ใช้ `http://<tailscale-ip>:27123`

### คีย์การกำหนดค่า (SQLite `key_value`, namespace `obsidian`)

| คีย์              | วัตถุประสงค์                                         | เข้ารหัส |
| ----------------- | ---------------------------------------------------- | -------- |
| `api_key`         | bearer token ของ Local REST API                      | ใช่      |
| `base_url`        | REST base URL (ค่าเริ่มต้น `http://127.0.0.1:27123`) | ไม่      |
| `vault_path`      | พาธแบบสัมบูรณ์ไปยังไดเรกทอรี vault (สำหรับการซิงค์)  | ไม่      |
| `webdav_username` | ชื่อผู้ใช้ WebDAV ที่สร้างขึ้น (การซิงค์ vault)      | ไม่      |
| `webdav_password` | รหัสผ่าน WebDAV ที่สร้างขึ้น (การซิงค์ vault)        | ใช่      |
| `webdav_enabled`  | ระบุว่าเปิดใช้งานการซิงค์ vault ผ่าน WebDAV หรือไม่  | ไม่      |

### กำหนดค่าผ่าน REST

```bash
# บันทึก + ตรวจสอบโทเค็น Local REST API (POST ตรวจสอบผ่านการเช็กสถานะ)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# ตรวจสอบสถานะการเชื่อมต่อ (ส่งคืน connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# ยกเลิกการเชื่อมต่อ (ล้างโทเค็นที่จัดเก็บไว้)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

ทุกเมธอดต้องมีการยืนยันตัวตนกับแดชบอร์ด `POST` จะปฏิเสธ URL ใดก็ตามที่ใช้พอร์ต `27124`
และตรวจสอบโทเค็นโดยเรียก endpoint สถานะของ Local REST API ก่อนจัดเก็บ

### การซิงค์ vault ผ่าน WebDAV

`src/app/api/settings/obsidian/webdav/route.ts` จัดการการซิงค์ vault ที่มี WebDAV
เป็นแบ็กเอนด์แบบเลือกเปิดใช้ได้ (ขับเคลื่อนโดย `src/lib/obsidianSync.ts`) การเปิดใช้งานจะกำหนดให้ OmniRoute ใช้
ไดเรกทอรี vault ภายในเครื่อง และสร้างคู่ชื่อผู้ใช้/รหัสผ่าน WebDAV แบบสุ่ม:

```bash
# เปิดใช้งานการซิงค์ WebDAV สำหรับไดเรกทอรี vault (สร้างชื่อผู้ใช้/รหัสผ่าน)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# รับสถานะการซิงค์ WebDAV (ส่งคืนข้อมูลรับรองเฉพาะขณะที่เปิดใช้งานอยู่)
curl http://localhost:20128/api/settings/obsidian/webdav

# ปิดใช้งานการซิงค์ WebDAV (ล้างข้อมูลรับรอง + .stignore ที่มีการจัดการ)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### แหล่งบริบทต่อ API key (เลือกใช้ได้)

การกำหนดค่า Obsidian สามารถจำกัดขอบเขต **แยกตาม API key** ผ่านตาราง `api_key_context_sources`
(`src/lib/db/apiKeyContextSources.ts`) เมื่อการเรียก MCP มี id ของ API key ที่ผ่านการยืนยันตัวตนแล้ว
`getObsidianConfigForApiKey()` จะให้ความสำคัญกับโทเค็น/base-URL/vault-path ของคีย์นั้นเอง
(`source: "api_key"`) และหากไม่มีจึงใช้การกำหนดค่าส่วนกลางแทน (`source: "global"`)

## เครื่องมือ MCP (22)

กำหนดไว้ใน `open-sse/mcp-server/tools/obsidianTools.ts` โดย token/base-URL จะถูกกำหนด
แยกสำหรับแต่ละการเรียก (ใช้ค่าของ API key ก่อน แล้วจึงใช้ค่าส่วนกลาง) เครื่องมือที่เรียกใช้ **sync server**
ของ OmniRoute (เครื่องมือ `obsidian_sync_*` ทั้งสี่รายการ) จำเป็นต้องใช้ sync auth token ที่กำหนดค่าไว้
ในการตั้งค่า OmniRoute เพิ่มเติมด้วย

### เครื่องมืออ่าน (`read:obsidian`)

| เครื่องมือ                   | คำอธิบาย                                                                              |
| ---------------------------- | ------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | ตรวจสอบว่าสามารถเข้าถึง Local REST API และผ่านการยืนยันตัวตนได้หรือไม่                |
| `obsidian_search_simple`     | ค้นหาข้อความแบบเต็มในเนื้อหาโน้ต โดยส่งคืนส่วนย่อยพร้อมพาธไฟล์                        |
| `obsidian_search_structured` | ค้นหาโดยใช้นิพจน์ JSON Logic (ตัวกรอง and/or/regex/path)                              |
| `obsidian_read_note`         | อ่านโน้ตตามพาธที่สัมพันธ์กับ vault โดยเลือกเฉพาะ heading/block/frontmatter ได้        |
| `obsidian_list_vault`        | แสดงรายการไฟล์และไดเรกทอรีใน vault (โครงสร้างแบบต้นไม้ของรายการ)                      |
| `obsidian_get_document_map`  | รับโครงสร้าง heading ของโน้ตในรูปแบบแผนที่ heading → หมายเลขบรรทัด                    |
| `obsidian_get_note_metadata` | รับ frontmatter, แท็ก, ลิงก์ และจำนวนอักขระ/คำโดยไม่ต้องดึงเนื้อหาทั้งหมด             |
| `obsidian_get_active_file`   | รับพาธและเนื้อหาของไฟล์ที่กำลังใช้งานอยู่ใน Obsidian                                  |
| `obsidian_get_periodic_note` | รับโน้ตรายวัน/รายสัปดาห์/รายเดือนสำหรับวันที่ระบุ (ใช้วันนี้หากไม่ระบุ)               |
| `obsidian_get_tags`          | แสดงแท็กทั้งหมดใน vault พร้อมความถี่ในการปรากฏ                                        |
| `obsidian_list_commands`     | แสดง ID คำสั่ง Obsidian ที่พร้อมใช้งาน (ใช้กับ `obsidian_execute_command`)            |
| `obsidian_sync_status`       | สถานะ sync server ของ OmniRoute: การทำงาน, ชื่อ vault, พอร์ต, uptime, การ sync ล่าสุด |
| `obsidian_sync_conflicts`    | แสดงข้อขัดแย้งในการ sync ที่ยังไม่ได้แก้ไข (พาธ, พาธข้อขัดแย้ง, เวลาที่ตรวจพบ)        |

### เครื่องมือเขียน (`write:obsidian`)

| เครื่องมือ                       | คำอธิบาย                                                                                |
| -------------------------------- | --------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | สร้างหรือเขียนทับโน้ตด้วยเนื้อหา Markdown ที่กำหนด                                      |
| `obsidian_append_note`           | เพิ่มเนื้อหาต่อท้ายโน้ต โดยเลือกเพิ่มที่ heading/block ที่ระบุได้                       |
| `obsidian_patch_note`            | เพิ่มต่อท้าย/เพิ่มไว้ข้างหน้า/แทนที่อย่างเจาะจงที่ heading, block หรือฟิลด์ frontmatter |
| `obsidian_delete_note`           | ลบโน้ตออกจาก vault อย่างถาวร                                                            |
| `obsidian_move_note`             | ย้ายหรือเปลี่ยนชื่อโน้ตภายใน vault                                                      |
| `obsidian_execute_command`       | เรียกใช้คำสั่ง Obsidian ตาม command ID                                                  |
| `obsidian_open_file`             | เปิดไฟล์ใน Obsidian (สร้างไฟล์หากยังไม่มี)                                              |
| `obsidian_sync_trigger`          | เรียกใช้การ sync vault แบบสองทิศทางระหว่างเดสก์ท็อป↔มือถือทันที                         |
| `obsidian_sync_resolve_conflict` | แก้ไขข้อขัดแย้งในการ sync: เก็บ `local` (มือถือ), `remote` (เดสก์ท็อป) หรือ `keep-both` |

> [!NOTE]
> เป้าหมายของ `obsidian_patch_note` รองรับ `targetType` เป็น `heading | block | frontmatter`
> และ `operation` เป็น `append | prepend | replace` พร้อมตัวเลือก
> `createTargetIfMissing` เครื่องมือ `obsidian_sync_*` ทั้งสี่รายการสื่อสารกับ sync
> server ภายในเครื่อง (`http://127.0.0.1:27781` โดยค่าเริ่มต้น) และจำเป็นต้องใช้ sync token

### Scope

เครื่องมืออ่านจำเป็นต้องมี `read:obsidian` ส่วนเครื่องมือเขียนจำเป็นต้องมี `write:obsidian` การบังคับใช้
เหมือนกับ Notion โดยจัดการผ่าน `withScopeEnforcement()` ใน
`open-sse/mcp-server/server.ts` ซึ่งควบคุมด้วย `OMNIROUTE_MCP_ENFORCE_SCOPES=true` และ
scope ที่อนุญาตมาจาก `OMNIROUTE_MCP_SCOPES` หรือบริบท scope ของ API key ดู
[MCP-SERVER.md](./MCP-SERVER.md)

## เอนด์พอยต์

| เมธอด    | พาธ                             | วัตถุประสงค์                                           |
| -------- | ------------------------------- | ------------------------------------------------------ |
| `GET`    | `/api/settings/obsidian`        | ส่งคืน `{ connected, hasToken, baseUrl, vaultPath }`   |
| `POST`   | `/api/settings/obsidian`        | บันทึกและตรวจสอบโทเค็น (ปฏิเสธพอร์ต `27124`)           |
| `DELETE` | `/api/settings/obsidian`        | ยกเลิกการเชื่อมต่อ (ล้างโทเค็นที่จัดเก็บไว้)           |
| `GET`    | `/api/settings/obsidian/webdav` | สถานะการซิงค์ WebDAV และข้อมูลประจำตัว (ขณะเปิดใช้งาน) |
| `POST`   | `/api/settings/obsidian/webdav` | เปิดใช้งานการซิงค์ WebDAV สำหรับไดเรกทอรีของ vault     |
| `DELETE` | `/api/settings/obsidian/webdav` | ปิดใช้งานการซิงค์ WebDAV                               |

> เส้นทางเหล่านี้ใช้สำหรับการตั้งค่าแดชบอร์ด ส่วนตัว vault เข้าถึงได้ผ่าน Obsidian
> Local REST API (`base_url` ที่กำหนดค่าไว้) และผ่านเครื่องมือ MCP ข้างต้น —
> ไม่มีเอนด์พอยต์พร็อกซี Obsidian `/v1` สาธารณะ

## กรณีการใช้งาน

- **คำตอบที่อ้างอิงข้อมูลจาก vault** — ใช้ `obsidian_search_simple` / `obsidian_search_structured`
  แล้วตามด้วย `obsidian_read_note` เพื่อให้เอเจนต์ตอบจากบันทึกจริงของคุณ
- **การเขียนบันทึก / บันทึกประจำวัน** — ใช้ `obsidian_write_note`, `obsidian_append_note` หรือ
  `obsidian_patch_note` สำหรับแก้ไขเฉพาะจุด เพื่อบันทึกเอาต์พุตของเอเจนต์ บทสรุป หรือบันทึกประจำวัน
  (`obsidian_get_periodic_note`) ลงใน vault
- **การนำทางใน vault** — ใช้ `obsidian_list_vault`, `obsidian_get_document_map` และ
  `obsidian_get_tags` เพื่อสำรวจโครงสร้างก่อนอ่าน/เขียน
- **ระบบอัตโนมัติของ Obsidian** — ใช้ `obsidian_list_commands` + `obsidian_execute_command` เพื่อ
  ควบคุมปลั๊กอิน/คำสั่งจากเอเจนต์ และใช้ `obsidian_open_file` เพื่อแสดงบันทึกใน UI
- **การซิงค์กับอุปกรณ์เคลื่อนที่** — เปิดใช้งานการซิงค์ WebDAV แล้วใช้ `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  เพื่อประสานการซิงค์เดสก์ท็อป↔อุปกรณ์เคลื่อนที่และแก้ไขข้อขัดแย้ง
