OmniRoute แยก **การค้นหา CLI**, **Agent Client Protocol แบบเนทีฟ** และ
**อะแดปเตอร์ stdio แบบเดิม** ออกจากกัน การพบไบนารีที่ติดตั้งแล้วไม่ได้พิสูจน์ว่า
มีการยืนยันตัวตน ความเข้ากันได้ของโมเดล หรือความพร้อมในการจัดการพรอมต์

แดชบอร์ดใช้ `GET /api/acp/agents` และ `POST /api/acp/agents` สำหรับคลังรายการ
และการลงทะเบียนเอเจนต์แบบกำหนดเอง เส้นทางเหล่านี้เป็นเส้นทางการจัดการเฉพาะภายในเครื่อง ไม่ใช่
API สาธารณะสำหรับสร้างโปรเซสหรือส่งพรอมต์ `AcpManager` ภายใน
จะไม่กลายเป็นทางเลือกสำรองของผู้ให้บริการ HTTP โดยอัตโนมัติ

## สัญญาที่ลงทะเบียนไว้

`config/cli-tools-manifest.json` เป็นแหล่งข้อมูลหลักที่เชื่อถือได้สำหรับไบนารีที่ใช้เรียกใช้งาน
อาร์กิวเมนต์ และโหมดแบ็กเอนด์ในตัว รีจิสทรีสร้างคำนิยามต่าง ๆ
จากแมนิเฟสต์ดังกล่าว ผลการตรวจหาจะถูกแคชไว้ 60 วินาที

- `acp`: สัญญา Gemini เรียกใช้ `gemini --experimental-acp` และสื่อสารด้วย
  ACP JSON-RPC ที่คั่นด้วยบรรทัดใหม่ผ่าน SDK อย่างเป็นทางการสำหรับ TypeScript
- `stdio-adapter`: สัญญาอื่น ๆ ที่ลงทะเบียนไว้ยังคงใช้อะแดปเตอร์แบบเดิมที่รับอินพุต
  แบบคั่นด้วยบรรทัดใหม่และส่งเอาต์พุตผ่าน stdout โดยช่วงที่ไม่มีเอาต์พุตเป็นเวลาสองวินาที
  จะถือว่าการตอบกลับสิ้นสุดลง อะแดปเตอร์นี้ **ไม่ได้** รับรองการรองรับ ACP แบบเนทีฟสำหรับ CLI เหล่านั้น

Gemini ระบุแฟล็กสำหรับการเรียกใช้งานไว้ใน [เอกสารอ้างอิง CLI](https://geminicli.com/docs/cli/cli-reference/)
ไคลเอนต์ใช้ [ACP SDK อย่างเป็นทางการ](https://github.com/agentclientprotocol/typescript-sdk)
สำหรับการเริ่มต้น การสร้างเซสชัน คำขอพรอมต์ การแจ้งเตือน และการยกเลิก

คำนิยามเอเจนต์แบบกำหนดเองยังคงเป็นสัญญาการเรียกใช้งานที่ควบคุมโดยผู้ดูแลระบบ
การลงทะเบียนไบนารีและอาร์กิวเมนต์จะมอบสิทธิ์การเรียกใช้ภายในเครื่องของผู้ใช้เซิร์ฟเวอร์
ให้แก่โปรเซสนั้น การลงทะเบียนไม่ใช่แซนด์บ็อกซ์ การตรวจสอบเวอร์ชันจะยอมรับ
เฉพาะไฟล์ปฏิบัติการที่ลงทะเบียนไว้และแฟล็กเวอร์ชันที่รู้จักเท่านั้น

## API การเรียกใช้งานภายใน

```typescript
import { acpManager } from "@/lib/acp";

const session = acpManager.spawn("gemini", {
  cwd: process.cwd(),
  // ส่งผ่านเฉพาะตัวแปรของผู้ให้บริการที่กำหนดให้กับเอเจนต์นี้โดยเจตนาเท่านั้น
  env: {
    GEMINI_API_KEY: process.env.GEMINI_API_KEY,
  },
});

try {
  const response = await acpManager.sendPrompt(session.id, "Explain this project", 120_000);
  // นำการตอบกลับไปใช้ในแอปพลิเคชันที่เรียก
} finally {
  acpManager.kill(session.id);
}
```

`spawn(agentId, options)` จะหาไฟล์ปฏิบัติการและอาร์กิวเมนต์จาก
คำนิยามที่ลงทะเบียนไว้ ตัวเลือกเดียวที่ผู้เรียกใช้ระบุได้คือ `cwd` และ `env`; รูปแบบเดิม
`spawn(agentId, binary, args, env)` และการเขียนทับไฟล์ปฏิบัติการ
จะถูกปฏิเสธ ตัวจัดการนี้ไม่รองรับสัญญาการเรียกใช้งานผ่าน HTTP

โปรเซสลูกจะสืบทอดรายการที่อนุญาตของระบบปฏิบัติการ เทอร์มินัล โลเคล และใบรับรอง
เช่นเดียวกับตัวเรียกใช้ CLI ความลับของเซิร์ฟเวอร์/ผู้ให้บริการจะไม่ถูกคัดลอกจาก
สภาพแวดล้อมของโปรเซสแม่ ข้อมูลประจำตัวที่ CLI ที่เลือกต้องใช้จะต้องถูกส่งผ่าน
อย่างชัดเจน หรือจัดเตรียมผ่านการยืนยันตัวตนภายในเครื่องของ CLI นั้นเอง โปรเซสลูก
ยังคงมีสิทธิ์เข้าถึงระบบไฟล์ของผู้ใช้ภายในเครื่องและอาจอ่านการกำหนดค่าของตนเองได้

## วงจรการทำงานแบบเนทีฟและข้อจำกัด

1. สร้างโปรเซสจากไบนารีที่ลงทะเบียนไว้ เริ่มต้น ACP และสร้างเซสชันที่มีรากอยู่ที่
   ไดเรกทอรีทำงานที่เลือก การเริ่มต้นมีขีดจำกัดสิบวินาที
2. ส่งพรอมต์และรวบรวมการแจ้งเตือนข้อความสำหรับเซสชันนั้นเท่านั้น
   การเสร็จสิ้นพิจารณาจากการตอบกลับ RPC ของพรอมต์ ไม่ใช่ช่วงที่ stdout ไม่มีข้อมูล
3. ใช้กำหนดเวลาสิ้นสุดของพรอมต์เพียงค่าเดียว ซึ่งรวมถึงการเริ่มต้นที่ยังไม่เสร็จสิ้นด้วย ค่าเริ่มต้น
   คือ 120 วินาที พรอมต์ที่ทำงานพร้อมกันในโปรเซสเดียวกันจะถูกปฏิเสธ
4. เมื่อหมดเวลาสำหรับโหมดเนทีฟ ให้พยายามเรียก `session/cancel` และยุติโปรเซส
   หน้าต่างเวลาจำกัด 100 ms เปิดโอกาสให้ส่งการแจ้งเตือนที่ค้างอยู่ก่อนยุติโปรเซส
5. ปิดสถานะการขนส่งและนำเซสชันออกเมื่อการเริ่มต้นล้มเหลว
   การเชื่อมต่อปิดลง โปรเซสสิ้นสุด หรือผู้เรียกใช้ยุติเซสชัน

คำขอสิทธิ์ใช้เครื่องมือจะถูกปฏิเสธ ไม่มีการประกาศความสามารถของไคลเอนต์
ด้านระบบไฟล์หรือเทอร์มินัล ข้อจำกัดเหล่านี้ไม่ได้แซนด์บ็อกซ์ตัวไบนารีของโปรเซสลูก
หรือใช้แทนการตั้งค่าการอนุญาตของ CLI เอง

ทั้งข้อความแบบเนทีฟและ stdout/stderr แบบเดิมจะเก็บอักขระไว้ได้สูงสุด 1 MiB
โดยเก็บเอาต์พุตส่วนล่าสุดพร้อมข้อความแจ้งการตัดทอน เฟรมข้อมูลแบบเนทีฟแต่ละเฟรม
ถูกจำกัดไว้ที่ 2 MiB ก่อนที่ SDK จะแยกวิเคราะห์ บัฟเฟอร์จะถูกรีเซ็ตสำหรับแต่ละพรอมต์

`kill(sessionId)` จะส่ง SIGTERM จากนั้นส่ง SIGKILL หลังจากห้าวินาที หากโปรเซส
ยังไม่สิ้นสุด การหมดเวลาของพรอมต์แบบเดิมจะปล่อยลิสเทนเนอร์และตัวจับเวลา แต่ยังคง
เปิดให้ใช้เซสชันกับพรอมต์อื่นได้ ผู้เรียกใช้ยังคงมีหน้าที่เรียก
`kill()` หรือ `killAll()` เมื่อใช้งานเสร็จ

## เหตุการณ์และการตรวจสอบ

ตัวจัดการจะปล่อยเหตุการณ์ `stdout`, `stderr` และ `exit` โดยแต่ละเหตุการณ์มี `sessionId`
`sessionError` ใช้รายงานข้อผิดพลาดของการขนส่งที่ผ่านการตัดข้อมูลละเอียดอ่อนออกแล้ว เหตุการณ์ `error`
เพื่อความเข้ากันได้จะถูกปล่อยเฉพาะเมื่อมีผู้สมัครรับเท่านั้น ดังนั้นไบนารีที่หายไป
จึงไม่สามารถก่อให้เกิดข้อผิดพลาด EventEmitter ที่ไม่ได้รับการจัดการ

- `getSession(sessionId)` ส่งคืนเซสชันที่จัดการอยู่ หรือ `undefined`
- `getActiveSessions()` ไม่รวมเซสชันที่หยุดแล้วหรือกำลังหยุด
- `sendInput(sessionId, input)` ใช้ได้เฉพาะกับอะแดปเตอร์แบบเดิมที่กำลังทำงานอยู่
  ACP แบบเนทีฟจะปฏิเสธอินพุตดิบเพื่อปกป้องสตรีม JSON-RPC
- `killAll()` ยุติทุกเซสชันที่จัดการโดยอินสแตนซ์นั้น

## ขอบเขตการตรวจสอบความถูกต้อง

ฟิกซ์เจอร์แบบกำหนดผลลัพธ์แน่นอนครอบคลุมการจับมือแบบเนทีฟ เอาต์พุตข้อความ การปฏิเสธ
สิทธิ์ การยกเลิก พรอมต์ที่ทำงานพร้อมกัน การเริ่มต้นที่ล้มเหลว การสิ้นสุดของโปรเซส
ขีดจำกัดเอาต์พุต และการแยกความลับออกจากกัน รวมถึงยังครอบคลุมกรณีถดถอยเดิม
ของบัฟเฟอร์/ลิสเทนเนอร์ การทดสอบเหล่านี้ไม่ได้แสดงให้เห็นถึงการเข้าสู่ระบบ Gemini จริง
หรือการอนุมานผ่านผู้ให้บริการที่สำเร็จ ซึ่งต้องใช้การทดสอบแบบ smoke test ที่ได้รับอนุญาต
แยกต่างหากในสภาพแวดล้อมเป้าหมาย
