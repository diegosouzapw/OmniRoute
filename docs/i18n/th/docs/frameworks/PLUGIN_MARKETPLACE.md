> **แหล่งข้อมูลหลัก:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/` และ
> `src/app/(dashboard)/dashboard/plugins/`
> **อัปเดตล่าสุด:** 2026-06-28 — v3.8.40

OmniRoute มาพร้อมระบบปลั๊กอินแบบ WordPress ปลั๊กอินแต่ละตัวเป็นไดเรกทอรีที่แยกเป็นอิสระ
โดยแต่ละไดเรกทอรีมีไฟล์แมนิเฟสต์ `plugin.json` และไฟล์เริ่มต้น ซึ่งเชื่อมต่อ
เข้ากับไปป์ไลน์คำขอ (`onRequest` / `onResponse` / `onError`) และ
เหตุการณ์วงจรชีวิต (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`)

**ตลาดปลั๊กอิน** เป็นเลเยอร์สำหรับการค้นหาและสำรวจที่อยู่บนระบบดังกล่าว
โดยนำเสนอแค็ตตาล็อกปลั๊กอินที่สามารถเรียกดูและติดตั้งได้ ตามค่าเริ่มต้น แค็ตตาล็อกจะเป็น
รีจิสทรีเริ่มต้นขนาดเล็กที่มีมาให้ในตัว ผู้ดูแลระบบสามารถกำหนดให้ใช้ URL ของรีจิสทรีระยะไกล
แบบกำหนดเองได้ ซึ่งในกรณีนี้ การดึงข้อมูลจะได้รับการป้องกันอย่างเข้มงวดด้วยตัวป้องกัน SSRF
ที่ตรวจสอบ DNS (ดู[ความปลอดภัย](#security))

ทุกเส้นทางของปลั๊กอินเป็นแบบ **เข้าถึงได้จากลูปแบ็กเท่านั้น** (ระดับ 1 — `LOCAL_ONLY`):
ปลั๊กอินจะโหลดและเรียกใช้โค้ดในโปรเซสลูก ดังนั้นเส้นทางเหล่านี้จึงไม่สามารถเข้าถึงได้
จากต้นทางที่ไม่ใช่ลูปแบ็ก ไม่ว่าการยืนยันตัวตนจะเป็นอย่างไรก็ตาม ดู
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md)

## การทำงานร่วมกันขององค์ประกอบต่าง ๆ

```
แดชบอร์ด (/dashboard/plugins)
  ├─ แท็บ "ติดตั้งแล้ว"  → GET /api/plugins            (listPlugins)
  │                        POST /api/plugins/scan      (pluginManager.scan)
  │                        POST /api/plugins/{name}/activate|deactivate
  │                        DELETE /api/plugins/{name}   (ถอนการติดตั้ง)
  └─ แท็บ "ตลาดปลั๊กอิน" → GET /api/plugins/marketplace
                             → listMarketplacePlugins()
                               ├─ ไม่มี URL แบบกำหนดเอง → SEED_REGISTRY ที่มีมาให้ในตัว
                               └─ URL แบบกำหนดเอง → ตัวป้องกัน SSRF isSafeMarketplaceUrl()
                                                    → safeOutboundFetch(guard:"public-only")
```

- **เลเยอร์รีจิสทรี** — `src/lib/plugins/marketplace.ts`: แสดงรายการ / ค้นหา
  แค็ตตาล็อก และกลับไปใช้รีจิสทรีเริ่มต้นเมื่อเกิดความล้มเหลวใด ๆ
- **เลเยอร์วงจรชีวิต** — `src/lib/plugins/manager.ts` (ซิงเกิลตัน `pluginManager`):
  ติดตั้ง อัปเกรด เปิดใช้งาน ปิดใช้งาน ถอนการติดตั้ง สแกน และโหลดเมื่อเริ่มต้นระบบ
- **เลเยอร์แมนิเฟสต์** — `src/lib/plugins/manifest.ts`: สคีมา Zod + ค่าเริ่มต้นสำหรับ
  `plugin.json`
- **ตัวสแกน** — `src/lib/plugins/scanner.ts`: ค้นหาปลั๊กอินบนดิสก์ภายใต้
  ไดเรกทอรีปลั๊กอิน
- **ตัวโหลด** — `src/lib/plugins/loader.ts`: เริ่มต้นปลั๊กอินแต่ละตัวใน
  โปรเซสลูกที่แยกออกจากกัน และเป็นตัวกลางในการเรียกฮุกผ่าน IPC

## แค็ตตาล็อกตลาดปลั๊กอิน

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) ส่งคืนรายการออบเจ็กต์
`MarketplaceEntry`:

| ฟิลด์         | ชนิด     | หมายเหตุ                                                |
| ------------- | -------- | ------------------------------------------------------- |
| `name`        | string   | ชื่อปลั๊กอินแบบ kebab-case                              |
| `version`     | string   | semver                                                  |
| `description` | string   | ข้อมูลสรุปสั้น ๆ                                        |
| `author`      | string   | ผู้เขียน / องค์กร                                       |
| `license`     | string   | รหัสสัญญาอนุญาตแบบ SPDX                                 |
| `downloadUrl` | string   | URL สำหรับดาวน์โหลดซอร์ส (อาจว่างเปล่า)                 |
| `repository`  | string?  | URL ของรีโพซิทอรีซึ่งระบุหรือไม่ก็ได้                   |
| `tags`        | string[] | แท็กสำหรับค้นหา/กรอง                                    |
| `downloads`   | number   | จำนวนการดาวน์โหลด                                       |
| `rating`      | number   | 0–5                                                     |
| `verified`    | boolean  | ระบุว่ารายการได้รับการทำเครื่องหมายว่ายืนยันแล้วหรือไม่ |
| `lastUpdated` | string   | สตริงวันที่ในรูปแบบคล้าย ISO                            |

เมื่อไม่ได้กำหนด URL ของรีจิสทรีแบบกำหนดเอง แค็ตตาล็อกจะใช้
`SEED_REGISTRY` ที่มีมาให้ในตัว (ปัจจุบันประกอบด้วย `request-logger`, `rate-limiter`,
`cost-tracker` และ `theme-manager`) รีจิสทรีเริ่มต้นพร้อมใช้งานเสมอ หากรีจิสทรีระยะไกล
ที่กำหนดค่าไว้ไม่สามารถเข้าถึงได้ ส่งคืนสถานะที่ไม่ใช่ `200` หรือส่งคืนเนื้อหา
ที่ระบบไม่รู้จัก `listMarketplacePlugins()` จะบันทึกคำเตือนและกลับไปใช้รายการเริ่มต้น

> หมายเหตุ: **แค็ตตาล็อก** ตลาดปลั๊กอิน (เรียกดู/ค้นหา) เชื่อมต่อการทำงานครบถ้วนตั้งแต่ต้นจนจบแล้ว แต่
> การ**ติดตั้ง**จากแค็ตตาล็อกด้วยคลิกเดียวยังไม่ได้รับการพัฒนา ปุ่ม "ติดตั้ง"
> บนรายการในตลาดปลั๊กอินของแดชบอร์ดจะแสดงข้อความว่า "เร็ว ๆ นี้" ในขณะนี้
> การติดตั้งปัจจุบันดำเนินการผ่านโฟลว์การติดตั้งจากพาธภายในเครื่อง
> (`POST /api/plugins`) และการค้นหาบนดิสก์ (`POST /api/plugins/scan`)

## REST API

ทุก endpoint ต้องใช้การยืนยันตัวตนระดับการจัดการ (`requireManagementAuth`) **และ**
อนุญาตให้เข้าถึงได้จาก loopback เท่านั้น — `/api/plugins` และ `/api/plugins/` ถูกระบุไว้ใน
`LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`)

| Endpoint                         | Method | คำอธิบาย                                                           |
| -------------------------------- | ------ | ------------------------------------------------------------------ |
| `/api/plugins`                   | GET    | แสดงรายการปลั๊กอินที่ติดตั้งแล้ว (ตัวกรอง `?status=` เป็นตัวเลือก) |
| `/api/plugins`                   | POST   | ติดตั้งปลั๊กอินจากพาธภายในเครื่องแบบ absolute                      |
| `/api/plugins/scan`              | POST   | สแกนไดเรกทอรีปลั๊กอินและลงทะเบียนปลั๊กอินใหม่                      |
| `/api/plugins/marketplace`       | GET    | แสดงรายการในแค็ตตาล็อก marketplace                                 |
| `/api/plugins/[name]`            | GET    | รับรายละเอียดปลั๊กอินที่ติดตั้งแล้ว                                |
| `/api/plugins/[name]`            | DELETE | ถอนการติดตั้งปลั๊กอิน                                              |
| `/api/plugins/[name]/activate`   | POST   | เปิดใช้งาน (โหลด + ลงทะเบียน hooks)                                |
| `/api/plugins/[name]/deactivate` | POST   | ปิดใช้งาน (เรียก `onDeactivate`, ยกเลิกการลงทะเบียน hooks)         |
| `/api/plugins/[name]/config`     | GET    | รับการกำหนดค่าปลั๊กอิน + schema การกำหนดค่า                        |
| `/api/plugins/[name]/config`     | PUT    | อัปเดตการกำหนดค่าปลั๊กอิน (ตรวจสอบกับ schema)                      |

ตัวกรอง `status` ของ `GET /api/plugins` ยอมรับค่าใดค่าหนึ่งต่อไปนี้:
`installed` / `active` / `inactive` / `error` ค่าที่ไม่ถูกต้องจะส่งคืน `400`

### แสดงรายการปลั๊กอินที่ติดตั้งแล้ว

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### ติดตั้งจากพาธภายในเครื่อง

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` ต้องเป็นพาธแบบ **absolute** และต้องไม่มีเซกเมนต์ `..` สำหรับไล่ย้อนพาธหรือ
null byte (บังคับใช้โดย Zod) ไดเรกทอรีต้นทางต้องมี
`plugin.json` ที่ถูกต้อง (หรือเป็นไดเรกทอรีแม่ของไดเรกทอรีที่มีไฟล์ดังกล่าว) เมื่อสำเร็จ การตอบกลับจะเป็น `201` พร้อมแถวข้อมูลของ
ปลั๊กอินที่ติดตั้งแล้ว

### เรียกดู marketplace

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### อัปเดตการกำหนดค่าปลั๊กอิน

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` จะตรวจสอบแต่ละค่าที่ระบุกับ
`configSchema` ของปลั๊กอิน (ประกาศใน manifest): ฟิลด์ `number` จะใช้ข้อกำหนด `min`/`max`
ส่วนฟิลด์ `select` ต้องตรงกับ `enum` ที่ประกาศไว้ คีย์ที่ไม่มีอยู่ใน schema
จะได้รับอนุญาตให้ผ่านได้

## การกำหนดค่า

### ไดเรกทอรีปลั๊กอิน

ปลั๊กอินอยู่ภายใต้ไดเรกทอรีข้อมูลของ OmniRoute:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (หรือไฟล์ใดก็ตามที่ manifest.main ชี้ไป)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) จะกำหนดไดเรกทอรีดังกล่าวตาม
สามขั้นตอน:

1. **`OMNIROUTE_PLUGINS_DIR`** เมื่อมีการตั้งค่า — ใช้ค่าตามที่ระบุโดยตรง ไม่ว่า `HOME` จะเป็นค่าใด นี่คือ
   ตัวเลือกที่กำหนดอย่างชัดเจนสำหรับ Docker/K8s ซึ่งโครงสร้างปลั๊กอินจะถูก bind mount ไว้ที่พาธ
   ซึ่งโดยปกติไม่เกี่ยวข้องกับไดเรกทอรี home ของคอนเทนเนอร์ (#11827)
2. `<home>/.omniroute/plugins` โดย `<home>` มาจากตัวแปรสภาพแวดล้อม `HOME` / `USERPROFILE`
3. `/tmp/.omniroute/plugins` เมื่อโปรเซสไม่ได้ export ค่า home ใดๆ เลย

ไดเรกทอรีที่กำหนดได้จะถูกบันทึกใน log หนึ่งครั้งเมื่อเริ่มต้นระบบในชื่อ `scanner.dir_resolved` โดยระบุ
อินพุตที่ถูกเลือก (`OMNIROUTE_PLUGINS_DIR`, `home` หรือ `no-home-fallback`) — ดังนั้น image
ที่ไปใช้ขั้นตอนที่ 3 โดยไม่มีการแจ้งเตือนจะแสดงข้อมูลดังกล่าว แทนที่จะรายงานเพียงว่ารายการปลั๊กอินว่างเปล่า
`POST /api/plugins/scan` จะค้นหาไดเรกทอรีย่อยทั้งหมดในตำแหน่งนั้นซึ่งมี
`plugin.json` ที่ถูกต้องและลงทะเบียนไดเรกทอรีเหล่านั้น ไดเรกทอรีเดียวกันนี้ยังเป็น root ที่
`pluginManager.install()` ใช้คัดลอกปลั๊กอินเข้าไป ดังนั้นการ override จะย้ายทั้งตำแหน่งการค้นหาและ
การติดตั้งไปด้วยกัน

> **`OMNIROUTE_PLUGINS_DIR` ไม่ใช่ `OMNIROUTE_PLUGIN_PATH`** ตัวแปรหลังจะถูกอ่านเฉพาะโดย
> ตัวโหลด command-plugin ของ CLI (`bin/cli/plugins.mjs`) เพื่อค้นหาแพ็กเกจ npm `omniroute-cmd-*`
> ที่เพิ่มคำสั่งย่อยให้กับ `omniroute` — ตัวแปรนี้ไม่มีผลต่อ runtime scanner
> ที่อธิบายไว้ที่นี่ โปรดดู [PLUGINS.md](./PLUGINS.md) สำหรับส่วนนั้น

### URL ของรีจิสทรี marketplace แบบกำหนดเอง

แหล่งข้อมูลแค็ตตาล็อก marketplace จะถูกอ่านจากการตั้งค่า `pluginMarketplaceUrl`
(`src/lib/plugins/marketplace.ts` อ่าน `settings.pluginMarketplaceUrl`) เมื่อ
ตั้งค่าเป็น URL แบบ `http(s)` แล้ว `listMarketplacePlugins()` จะดึงข้อมูลจาก URL นั้นและยอมรับ
ทั้งอาร์เรย์ JSON ระดับบนสุดของรายการ หรืออ็อบเจ็กต์ที่มีอาร์เรย์ `plugins`;
รายการที่ไม่มี `name` ชนิด string จะถูกกรองออก เมื่อไม่ได้ตั้งค่า (หรือเมื่อการดึงข้อมูล
ไม่ผ่านการป้องกัน SSRF / ส่งคืนการตอบกลับที่ไม่ถูกต้อง) ระบบจะใช้รีจิสทรีเริ่มต้นที่มีมาให้

แท็บ "Marketplace" บนแดชบอร์ดมีฟิลด์สำหรับ URL นี้ (อ่านค่ากลับจาก
`GET /api/settings`)

> หมายเหตุเกี่ยวกับการนำไปใช้: การดำเนินการ "Save" บนแดชบอร์ดจะส่ง
> `pluginMarketplaceUrl` ไปยัง `PATCH /api/settings` ณ เวลาที่เขียนนี้
> คีย์ดังกล่าวยังไม่ได้รับการประกาศใน `updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`) ดังนั้นควรตรวจสอบการบันทึกค่าใน
> release ของคุณก่อนใช้งานจริง — เส้นทางการ **อ่าน** (`getSettings()` →
> `listMarketplacePlugins()`) จะรองรับคีย์นี้เมื่อมีอยู่ใน settings
> store แล้ว

## ความปลอดภัย

### ระดับของเส้นทาง — เฉพาะลูปแบ็ก

ปลั๊กอินเรียกใช้โค้ดในโพรเซสลูกที่ถูกสร้างขึ้น ดังนั้นพื้นผิว `/api/plugins`
ทั้งหมดจึงถูกจัดประเภทเป็น `LOCAL_ONLY` (ระดับ 1) การบังคับใช้ลูปแบ็กจะทำงาน
โดยไม่มีเงื่อนไข **ก่อน** การตรวจสอบสิทธิ์ใดๆ ดังนั้นแม้โทเค็นการจัดการที่รั่วไหลจะเข้าถึง
เครื่องผ่านทันเนล ก็ยังไม่สามารถติดตั้ง เปิดใช้งาน หรือถอนการติดตั้งปลั๊กอินได้
ดู [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) และ
กฎบังคับ #15 / #17

### การป้องกัน SSRF ของรีจิสทรีมาร์เก็ตเพลส

URL ของรีจิสทรีแบบกำหนดเองเป็นการกำหนดค่าที่ผู้โจมตีอาจมีอิทธิพลได้ ดังนั้นก่อน
ดึงข้อมูล `listMarketplacePlugins()` จะตรวจสอบ URL ผ่านการป้องกันสองชั้น:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - ปฏิเสธทุกอย่างที่ไม่ใช่ `http:` / `https:`
   - ปฏิเสธโฮสต์ส่วนตัว/ลูปแบ็ก/ลิงก์โลคัล/ULA ที่ระบุโดยตรง (ทั้ง IPv4 **และ** IPv6
     รวมถึง IPv4-mapped) ผ่าน `isPrivateHost` มาตรฐาน
     (`src/shared/network/outboundUrlGuard.ts`)
   - แปลงระเบียน **ทั้ง** `A` และ `AAAA` และปฏิเสธหากที่อยู่ที่แปลงได้
     **รายการใดก็ตาม** เป็นที่อยู่ส่วนตัว ซึ่งปิดช่องทางเลี่ยงแบบชื่อโฮสต์สาธารณะ → IP ส่วนตัว
   - **ปฏิเสธเมื่อเกิดข้อผิดพลาด**: หากการแปลง DNS ล้มเหลว URL จะถูกปฏิเสธ
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`**
   (`src/shared/network/safeOutboundFetch.ts`): ใช้การป้องกัน URL แบบสาธารณะเท่านั้น
   อีกครั้งในขณะดึงข้อมูล และ **บล็อกการเปลี่ยนเส้นทาง** (ไม่มีช่องทางเปลี่ยนจากสาธารณะ → ส่วนตัว
   ผ่าน `30x`)

URL ที่ไม่ผ่านการป้องกันชั้นใดชั้นหนึ่งจะไม่ทำให้คำขอล้มเหลว แต่มาร์เก็ตเพลส
จะย้อนกลับไปใช้รีจิสทรีเริ่มต้นในตัวโดยไม่มีการแจ้งเตือนต่อผู้ใช้ และบันทึกคำเตือนไว้ในล็อก

> การป้องกันนี้ได้รับการเสริมความแข็งแกร่งใน PR #3774 โดยเฉพาะเพื่อแปลงทั้ง A + AAAA และใช้
> `isPrivateHost` มาตรฐานแทนการตรวจสอบเฉพาะ IPv4

### การแยกการทำงานของปลั๊กอิน

- **การแยกโพรเซส** — `loadPlugin()` (`src/lib/plugins/loader.ts`) สร้าง
  ปลั๊กอินแต่ละตัวในโพรเซสลูก Node.js แยกต่างหากและสื่อสารผ่าน IPC
  การเรียกฮุกมีการหมดเวลาพร้อมการยกระดับจาก `SIGTERM` → `SIGKILL`
- **รายการอนุญาตของตัวแปรสภาพแวดล้อม** — โพรเซสลูกจะได้รับเฉพาะชุดตัวแปรสภาพแวดล้อม
  ที่อยู่ในรายการอนุญาตเท่านั้น โดยจะได้รับชุดที่กว้างขึ้นเฉพาะเมื่อแมนิเฟสต์ร้องขอสิทธิ์
  `env`
- **การจำกัดเส้นทาง** — การติดตั้ง/อัปเกรด/ถอนการติดตั้งจะตรวจยืนยันว่าไดเรกทอรี
  ของปลั๊กอินและ `manifest.main` ถูกแปลงเป็นเส้นทางที่อยู่ **ภายใน** รากปลั๊กอินที่จัดการอยู่
  ก่อนการคัดลอกหรือการลบแบบเรียกซ้ำทุกครั้ง (ป้องกันเส้นทาง DB ที่ถูกดัดแปลงและ
  การท่องเส้นทางด้วย `../` ใน `manifest.main`) การเปิดใช้งานจะแปลง symlink ผ่าน
  `realpath` และปฏิเสธการโหลดจุดเข้าใช้งานที่หลุดออกจากไดเรกทอรี
  ของปลั๊กอิน
- **การตรึงความถูกต้องแบบไม่บังคับ** — แมนิเฟสต์อาจประกาศฟิลด์ `integrity`
  (`sha256-<base64>` รูปแบบ SRI) เมื่อมีฟิลด์นี้ ตัวโหลดจะตรวจสอบแฮชของ
  ไฟล์จุดเข้าใช้งานขณะโหลด และปฏิเสธการเปิดใช้งานหากไม่ตรงกัน นี่คือ
  การตรวจจับการดัดแปลงที่เลือกใช้ได้ **ไม่ใช่** ขอบเขตความปลอดภัย — การกำหนดเส้นทาง
  แบบลูปแบ็กเท่านั้นและโมเดลสิทธิ์คือขอบเขตที่แท้จริง

## แมนิเฟสต์ (`plugin.json`)

ตรวจสอบความถูกต้องโดย `PluginManifestSchema` (`src/lib/plugins/manifest.ts`):

| ฟิลด์              | ชนิดข้อมูล | หมายเหตุ                                                      |
| ------------------ | ---------- | ------------------------------------------------------------- |

| `author`           | string?    | ≤ 200 อักขระ                                                  |
| `license`          | string?    | ค่าเริ่มต้นคือ `MIT`                                          |
| `main`             | string?    | ไฟล์จุดเข้าใช้งาน; ค่าเริ่มต้นคือ `index.js`                  |
| `source`           | enum?      | `local` \| `marketplace` (ค่าเริ่มต้นคือ `local`)             |
| `tags`             | string[]?  | แท็กสำหรับค้นหา                                               |
| `requires`         | object?    | `{ omniroute?, permissions[] }`                               |
| `hooks`            | object?    | ค่าบูลีนที่ประกาศว่าปลั๊กอินใช้ฮุกใดบ้าง                      |
| `skills`           | object[]?  | ข้อกำหนดทักษะแบบไม่บังคับ                                     |
| `enabledByDefault` | boolean?   | เปิดใช้งานโดยอัตโนมัติเมื่อติดตั้ง                            |
| `configSchema`     | object?    | แมปของฟิลด์การกำหนดค่า (`string`/`number`/`boolean`/`select`) |
| `integrity`        | string?    | การตรึงไฟล์จุดเข้าใช้งานด้วย `sha256-<base64>` แบบไม่บังคับ   |

สิทธิ์จะเลือกจาก enum
`network` / `file-read` / `file-write` / `env` / `exec`

## ลำดับวงจรชีวิต

```
install (POST /api/plugins, path)
  → สแกน/ตรวจสอบ manifest → คัดลอกไปยัง staging → ยืนยันว่า main อยู่ภายในไดเรกทอรี
  → เปลี่ยนชื่อแบบ atomic ไปยัง ~/.omniroute/plugins/<name> → เพิ่มแถวในฐานข้อมูล
  → เรียกใช้ onInstall → หาก enabledByDefault: activate

activate (POST /api/plugins/{name}/activate)
  → ตรวจสอบการอยู่ภายในขอบเขตด้วย realpath → loadPlugin() (สร้าง child process)
  → ลงทะเบียน hooks ที่ประกาศไว้ → status = "active" → เรียกใช้ onActivate

deactivate (POST /api/plugins/{name}/deactivate)
  → เรียกใช้ onDeactivate (ก่อนยกเลิกการลงทะเบียน) → ยกเลิกการลงทะเบียน hooks
  → ปิด child process → status = "inactive"

uninstall (DELETE /api/plugins/{name})
  → deactivate หาก active → เรียกใช้ onUninstall
  → ลบไดเรกทอรีปลั๊กอินแบบ recursive โดยตรวจสอบขอบเขต → ลบแถวในฐานข้อมูล
```

การเรียกใช้ `install` ซ้ำกับไดเรกทอรีที่มีเวอร์ชันใน manifest **ใหม่กว่าอย่างเคร่งครัด**
เมื่อเทียบกับเวอร์ชันที่ติดตั้งไว้ จะอัปเกรดโดยอัตโนมัติ (ติดตั้งใหม่ทั้งหมด โดยรีเซ็ต config
เป็นค่าเริ่มต้น) เวอร์ชันที่เท่ากันหรือเก่ากว่าจะถูกปฏิเสธ

## แดชบอร์ด

หน้าแดชบอร์ดที่ `/dashboard/plugins`
(`src/app/(dashboard)/dashboard/plugins/page.tsx`) มีสองแท็บ:

- **ติดตั้งแล้ว** — แสดงรายการปลั๊กอินที่ติดตั้งพร้อม hooks ที่ประกาศไว้ ปุ่มสลับ
  activate/deactivate ปุ่ม uninstall และการดำเนินการ "สแกนหาปลั๊กอิน"
  (`POST /api/plugins/scan`)
- **มาร์เก็ตเพลส** — แสดงแค็ตตาล็อกจาก `GET /api/plugins/marketplace` พร้อม
  ช่องสำหรับกำหนด URL ของ registry แบบกำหนดเอง

หน้ากำหนดค่าเฉพาะปลั๊กอินอยู่ที่ `/dashboard/plugins/[name]/config`
(`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`)
