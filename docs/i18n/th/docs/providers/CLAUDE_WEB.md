## `claude-web`

`claude-web` ส่งคำขอแชตรูปแบบ OpenAI ผ่านเซสชันเบราว์เซอร์ `claude.ai`
ที่ผ่านการตรวจสอบสิทธิ์แล้ว ตัวประมวลผลจะปรับคุกกี้ที่ระบุให้เป็นรูปแบบมาตรฐาน ระบุองค์กรหนึ่งแห่ง
ที่ผ่านการตรวจสอบสิทธิ์ เตรียมสถานะการสนทนา เลือกการส่งข้อมูลแบบตรงหรือผ่านเบราว์เซอร์ และ
แปลงการตอบกลับ SSE จากต้นทางอย่างเคร่งครัด การประสานงานอยู่ใน
`open-sse/executors/claude-web.ts:320`

> **เพิ่งเริ่มใช้ผู้ให้บริการ Web Cookie ใช่ไหม?**
>
> อ่าน **`docs/getting-started/WEB-COOKIE-GUIDE.md`** เพื่อศึกษากระบวนการตั้งค่าทั่วไป คำแนะนำด้านการตรวจสอบสิทธิ์ ข้อจำกัด และการแก้ไขปัญหา ก่อนทำตามคู่มือเฉพาะสำหรับผู้ให้บริการนี้

### แค็ตตาล็อกโมเดล

ขณะนี้รีจิสทรีของผู้ให้บริการเปิดให้ใช้ ID โมเดลแบบคงที่เจ็ดรายการต่อไปนี้เท่านั้น
(`open-sse/config/providers/registry/claude/web/index.ts:11`):

| ID โมเดล                    | ชื่อที่แสดงผล            |
| --------------------------- | ------------------------ |
| `claude-fable-5`            | Claude Fable 5 (เว็บ)    |
| `claude-opus-4-8`           | Claude Opus 4.8 (เว็บ)   |
| `claude-sonnet-5`           | Claude Sonnet 5 (เว็บ)   |
| `claude-haiku-4-5-20251001` | Claude Haiku 4.5 (เว็บ)  |
| `claude-opus-4-7`           | Claude Opus 4.7 (เว็บ)   |
| `claude-opus-4-6`           | Claude Opus 4.6 (เว็บ)   |

ผู้ให้บริการนี้ยังไม่ได้รองรับการค้นหาโมเดลแบบไดนามิก รายการข้างต้นคือ
แค็ตตาล็อกที่ใช้ขณะรันไทม์

### ข้อมูลประจำตัวและการระบุองค์กร

ระบุส่วนหัว Cookie ของ `claude.ai` แบบเต็ม หรือระบุเฉพาะค่าเซสชันก็ได้ ค่าที่ระบุเฉพาะเซสชันจะถูก
ปรับให้อยู่ในรูปแบบ `sessionKey` ส่วนคุกกี้อื่นๆ จะคงไว้หากมีการระบุ ตัวประมวลผลรับ
คุกกี้ผ่าน `cookie` หรือ `apiKey` และ
อ่านค่า `deviceId` และ `orgId` ที่เป็นตัวเลือกจากข้อมูลการเชื่อมต่อ
(`open-sse/executors/claude-web.ts:72`)

หากไม่มี `orgId` ตัวประมวลผลจะเรียก `GET https://claude.ai/api/organizations` และใช้องค์กรแรก
ที่ส่งกลับโดยเซสชัน Claude Web ซึ่งผ่านการตรวจสอบสิทธิ์แล้ว
(`open-sse/executors/claude-web.ts:141`) ระบบจะปฏิเสธโดยค่าเริ่มต้นเมื่อไม่มีการส่งคืนองค์กรที่
ถูกต้อง รายงานการปฏิเสธสิทธิ์ของเซสชันเป็น 401 และแยกความแตกต่างระหว่าง
การท้าทายจาก Cloudflare กับความล้มเหลวในการตรวจสอบสิทธิ์

### การดำเนินการเกี่ยวกับการสนทนา

อ็อบเจ็กต์ `claude_web` ระดับบนสุดที่เป็นตัวเลือกมีการตรวจสอบอย่างเคร่งครัด ฟิลด์ที่ไม่รู้จักจะถูกปฏิเสธ ฟิลด์
ที่ยอมรับได้กำหนดไว้ใน `open-sse/executors/claude-web/session.ts:50`:

| ฟิลด์                 | ความหมาย                                                              |
| --------------------- | --------------------------------------------------------------------- |
| `operation`           | ค่าเริ่มต้นคือ `completion` ใช้ `retry` สำหรับการลองตอบใหม่           |
| `conversation_id`     | UUID ที่ระบุอย่างชัดเจนสำหรับการสนทนาที่มีอยู่                        |
| `parent_message_uuid` | UUID ที่ระบุอย่างชัดเจนสำหรับข้อความผู้ช่วยซึ่งเป็นข้อความแม่         |
| `timezone`            | ชื่อเขตเวลา IANA ที่ถูกต้อง                                           |
| `locale`              | โลเคลที่มีโครงสร้างถูกต้อง                                            |
| `tool_states`         | อาร์เรย์สถานะเครื่องมือของบัญชีที่เป็นตัวเลือก จำกัดไว้ที่ 128 รายการ |

คำขอที่เตรียมไว้จะใช้หนึ่งในสองเอนด์พอยต์ต้นทาง
(`open-sse/executors/claude-web.ts:203`):

- เทิร์นใหม่หรือเทิร์นต่อเนื่องจะโพสต์ไปยัง
  `POST https://claude.ai/api/organizations/{orgId}/chat_conversations/{conversationId}/completion`
- การลองตอบใหม่จะโพสต์ไปยัง
  `POST https://claude.ai/api/organizations/{orgId}/chat_conversations/{conversationId}/retry_completion`

เทิร์นใหม่จะมี `create_conversation_params` เทิร์นต่อเนื่องที่แคชไว้หรือเชื่อมโยงไว้อย่างชัดเจน
จะมี `parent_message_uuid` และไม่มี `create_conversation_params` การลองตอบใหม่ต้องมีทั้ง
สถานะการสนทนาและสถานะข้อความแม่ และจะไม่ส่งพรอมต์
(`open-sse/executors/claude-web/session.ts:254`) การสนทนาใหม่จะเปิด UI ที่ผ่านการตรวจสอบสิทธิ์แล้ว
ที่ `/new` ส่วนเทิร์นต่อเนื่องที่แคชไว้หรือเชื่อมโยงไว้อย่างชัดเจนจะเปิดหน้าการสนทนาที่ตรงกัน
(`open-sse/executors/claude-web/session.ts:324`)

สถานะการสนทนาเป็นแคชในหน่วยความจำ โดยใช้ขอบเขตบัญชีแบบ SHA-256 และทรานสคริปต์ของผู้เรียก
ในรูปแบบมาตรฐานเป็นคีย์ รายการจะหมดอายุหลังจาก 30 นาที และแคชจำกัดไว้ที่ 5,000 รายการ
(`open-sse/executors/claude-web/session.ts:12`) สถานะจะถูกบันทึกเมื่อพาร์เซอร์สตรีมแบบเข้มงวด
ตรวจพบ `message_stop` เท่านั้น การเริ่มกระบวนการใหม่จะล้างสถานะดังกล่าว เมื่อไม่พบข้อมูลในแคช
คำขอที่มีหลายข้อความจะถูกทำให้เป็นอนุกรมรวมเป็นพรอมต์กู้คืนหนึ่งรายการ แทนที่จะละทิ้ง
ข้อความก่อนหน้าโดยไม่แจ้งให้ทราบ

โลเคลและเขตเวลาใช้ลำดับความสำคัญดังนี้: ค่า `claude_web` ของคำขอ ค่าการเชื่อมต่อ
ค่ารันไทม์ จากนั้นใช้ `en-US` สำหรับโลเคล หรือ `UTC` สำหรับเขตเวลา
(`open-sse/executors/claude-web/session.ts:218`)

### เครื่องมือและเพย์โหลดของคำขอ

คำขอแบบตรงจะแปลงเฉพาะเครื่องมือฟังก์ชัน OpenAI ที่มีโครงสร้างถูกต้องซึ่งผู้เรียกระบุมา
ไม่มีการสร้างรายการเครื่องมือเริ่มต้นแบบคงที่ขึ้นมาเอง
(`open-sse/executors/claude-web/payload.ts:102`)

ส่วนคำขอผ่านเบราว์เซอร์จะจับคำขอจาก UI ที่ผ่านการตรวจสอบสิทธิ์แล้ว และเก็บเครื่องมือของบัญชี
สถานะเครื่องมือ และสไตล์เฉพาะบุคคลไว้ ฟิลด์การสนทนา โมเดล การใช้เหตุผล พรอมต์ และ
UUID ของข้อความที่เตรียมไว้จะยังคงเขียนทับคำขอที่จับมา
(`open-sse/executors/claude-web/browserTransport.ts:175`) เทมเพลตเบราว์เซอร์ถูกกำหนดขอบเขตด้วย
แฮชของบัญชี องค์กร คุกกี้ โลเคล และเขตเวลา และจะหมดอายุหลังจาก 30 นาที
(`open-sse/executors/claude-web/browserTransport.ts:11`,
`open-sse/executors/claude-web/browserTransport.ts:158`) เมื่อคำขอแบบตรงไม่มีเครื่องมือจากผู้เรียก
คำขอนั้นสามารถนำเทมเพลตที่อยู่ในขอบเขตดังกล่าวกลับมาใช้ได้ ส่วนเครื่องมือที่ผู้เรียกระบุไว้อย่างชัดเจน
จะมีลำดับความสำคัญสูงกว่า
(`open-sse/executors/claude-web/browserTransport.ts:214`)

### การเลือกวิธีส่งข้อมูล

เส้นทางเริ่มต้นคือ `sendClaudeWebDirect()` ซึ่งเรียก `tlsFetchClaude()` ด้วยโปรไฟล์
Chrome 146 ที่กำหนดค่าไว้และคุกกี้ที่ระบุ (`open-sse/services/claudeTlsClient.ts:23`) โดยจะไม่
เปิดใช้ตัวแก้โจทย์หรือสร้างคุกกี้ทดแทนขึ้นมาเอง

ตั้งค่า `WEB_COOKIE_USE_BROWSER` เป็น `1`, `true` หรือ `on` เพื่อกำหนดให้อะแดปเตอร์เบราว์เซอร์ที่จำกัดขอบเขตตามบัญชีเป็นทรานสปอร์ตหลัก ตั้งค่า `OMNIROUTE_BROWSER_POOL` เป็นค่าใดค่าหนึ่งเดียวกันเพื่ออนุญาตให้การท้าทาย Cloudflare 403 ที่ระบบรู้จักเปลี่ยนจากทรานสปอร์ตโดยตรงไปใช้อะแดปเตอร์เบราว์เซอร์เป็นทางเลือกสำรอง (`open-sse/executors/claude-web.ts:195`) ความล้มเหลว HTTP อื่นๆ จะไม่ทริกเกอร์การใช้ทางเลือกสำรองดังกล่าว

อะแดปเตอร์เบราว์เซอร์จะเก็บคุกกี้ไว้ภายในบริบท Playwright แบบพูลเดียวกัน ใช้คีย์แบบแฮชที่จำกัดขอบเขตตามที่อธิบายไว้ข้างต้น และส่งผลลัพธ์การสร้างข้อความจากบริบทนั้น (`open-sse/executors/claude-web/browserTransport.ts:444`) โดยจะไม่ส่งออกคุกกี้ที่เบราว์เซอร์แก้การท้าทายแล้วไปยังไคลเอนต์ TLS โดยตรง การลองใหม่ผ่านเบราว์เซอร์ต้องใช้เทมเพลต UI ที่ยังไม่หมดอายุและผูกอยู่กับบริบท Playwright จริงเดียวกัน (`open-sse/executors/claude-web/browserTransport.ts:467`) การอ่านการตอบกลับของเบราว์เซอร์จะดำเนินการแบบเพิ่มทีละส่วนในหน้าที่ผ่านการตรวจสอบสิทธิ์ รองรับการยกเลิกคำขอ และยกเลิกเนื้อหาต้นทางทันทีที่มีขนาดเกิน 16 MiB (`open-sse/executors/claude-web/browserTransport.ts:259`)

ตัวดำเนินการจะส่งคืนมุมมองการตรวจสอบที่ปกปิดข้อมูลแล้วไปยังตัวบันทึกคำขอที่ใช้ร่วมกัน โดยไม่รวม UUID ขององค์กร การสนทนา และข้อความ ตลอดจนข้อความพรอมต์ นิยามเครื่องมือ คุกกี้ และตัวระบุอุปกรณ์ (`open-sse/executors/claude-web.ts:237`, `open-sse/executors/claude-web.ts:252`) ข้อยกเว้นของทรานสปอร์ตจะส่งคืนข้อผิดพลาดการเชื่อมต่อแบบทั่วไปแทนข้อความจากข้อยกเว้นที่ถูกโยน

### พฤติกรรม SSE

`createClaudeWebResponse()` รองรับการแบ่งเฟรมแบบ LF หรือ CRLF และฟิลด์ `data:` แบบหลายบรรทัด โดยแมปเดลตาของข้อความไปยัง `content` เดลตาของกระบวนการคิดไปยัง `reasoning_content` และเหตุการณ์เมทาดาทาที่รู้จักไปยังส่วนขยายการตอบกลับ `claude_web` เหตุการณ์เมทาดาทาแต่ละรายการจะถูกฉายผ่านรายการฟิลด์ที่อนุญาตของตนเอง (`open-sse/executors/claude-web/stream.ts:37`) เมทาดาทาของการสนทนา ข้อความหลัก ข้อความผู้ช่วย และการดำเนินการจะถูกส่งคืนในส่วนหัว `X-OmniRoute-Claude-Web-*` ด้วย (`open-sse/executors/claude-web/stream.ts:364`)

ตัวแยกวิเคราะห์จะปฏิเสธโดยค่าเริ่มต้นเมื่อพบ JSON ที่มีรูปแบบไม่ถูกต้อง เหตุการณ์ `error` จากต้นทาง ประเภทเหตุการณ์ที่ไม่รู้จัก ลำดับที่ไม่ถูกต้อง บล็อกเนื้อหาที่ไม่ตรงกัน หรือ EOF ก่อน `message_stop` เอาต์พุตแบบสตรีมจะปล่อยชังก์สิ้นสุดหนึ่งรายการและ `[DONE]` หนึ่งรายการ ส่วนเอาต์พุตแบบบัฟเฟอร์จะใช้ตัวแยกวิเคราะห์เดียวกัน ตัวแยกวิเคราะห์จะถือว่า `message_stop` เป็นจุดสิ้นสุดทันที ยกเลิกข้อมูลต้นทางที่ตามมา และส่งต่อการยกเลิกจากปลายทางไปยังตัวอ่านต้นทาง (`open-sse/executors/claude-web/stream.ts:461`, `open-sse/executors/claude-web/stream.ts:563`) บรรทัด SSE ที่ไม่ได้ปิดท้ายและเหตุการณ์ที่สะสมจะถูกจำกัดไว้ที่ 1 MiB (`open-sse/executors/claude-web/stream.ts:17`, `open-sse/executors/claude-web/stream.ts:62`)

กรณีที่ขึ้นอยู่กับ Playwright ใน `tests/unit/claude-web-auto-refresh.test.ts` ถูกข้ามไว้อย่างชัดเจน ขณะนี้รีโพซิทอรีนี้ยังไม่ได้กำหนดสคริปต์ทดสอบ Claude Web แบบไลฟ์ที่ใช้ข้อมูลประจำตัว ดังนั้นกรณีที่ถูกข้ามเหล่านั้นจึงไม่ใช่หลักฐานยืนยันการทำงานขณะรันไทม์

### การตั้งค่า

1. เริ่ม OmniRoute ด้วย `npm run dev` หรือการติดตั้งที่บิลด์แล้ว
2. เปิดแดชบอร์ด → ผู้ให้บริการ → เพิ่มผู้ให้บริการ
3. เลือกหมวดหมู่ Web Cookie และ Claude Web
4. วางส่วนหัว Cookie แบบเต็มที่คัดลอกมาจากคำขอ `claude.ai` ที่ผ่านการตรวจสอบสิทธิ์แล้ว
