เอกสารนี้บันทึกการตัดสินใจด้านการใช้งานสำหรับ
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854) โดยผลิตภัณฑ์ที่เผยแพร่ต่อสาธารณะจะแสดงเป็นกลุ่มผู้ให้บริการสี่กลุ่ม ส่วนภูมิภาคเป็นข้อมูลการเชื่อมต่อ ไม่ใช่ผลิตภัณฑ์แยกต่างหาก

## การตัดสินใจ

| กลุ่มผู้ให้บริการ                             | OmniRoute ID            | ภูมิภาคทั่วโลก | ภูมิภาคจีน |
| --------------------------------------------- | ----------------------- | -------------- | ---------- |
| Alibaba Cloud Model Studio (จ่ายตามการใช้งาน) | `alibaba`               | สิงคโปร์       | ปักกิ่ง    |
| Alibaba Cloud Token Plan                      | `bailian-coding-plan`   | สิงคโปร์       | ปักกิ่ง    |
| Qwen Cloud (จ่ายตามการใช้งาน)                 | `qwen-cloud`            | ทั่วโลก        | ปักกิ่ง    |
| Qwen Cloud Token Plan                         | `qwen-cloud-token-plan` | สิงคโปร์       | ปักกิ่ง    |

ID `alibaba-cn` ที่มีอยู่จะยังคงเป็นนามแฝงเพื่อความเข้ากันได้ขณะรันไทม์สำหรับการเชื่อมต่อที่บันทึกไว้ เส้นทางโมเดล คอมโบ และข้อมูลการใช้งานในอดีต การ์ดแดชบอร์ดของ ID นี้จะถูกรวมไว้ใน `alibaba` โดยไม่จำเป็นต้องเขียนข้อมูลในฐานข้อมูลใหม่

ปัจจุบัน Qwen Cloud แบบจ่ายตามการใช้งานและ Alibaba Cloud Model Studio ใช้โฮสต์รันไทม์ที่เข้ากันได้กับ DashScope ร่วมกัน แต่ยังคงเป็นผู้ให้บริการที่มีอัตลักษณ์แยกจากกัน เนื่องจากผู้ใช้รับคีย์และจัดการบัญชีผ่านหน้าผลิตภัณฑ์ที่แตกต่างกัน ผลิตภัณฑ์ Alibaba และ Qwen Cloud Token Plan ใช้กลุ่มเอนด์พอยต์ที่แตกต่างกัน ดังนั้น ผลิตภัณฑ์ทั้งสี่จึงยังคงใช้ ID ผู้ให้บริการแยกกัน

## เมทริกซ์เอนด์พอยต์

| กลุ่มผู้ให้บริการ       | `global-sg`                                                              | `china-beijing`                                                      | รูปแบบข้อมูลบนสายสื่อสาร |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ------------------------ |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI                   |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic                |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI                   |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI                   |

คีย์ API และเอนด์พอยต์ต้องเป็นของผลิตภัณฑ์และภูมิภาคเดียวกัน การเลือกภูมิภาคจะเปลี่ยนเอนด์พอยต์ที่ตั้งค่าไว้ล่วงหน้าซึ่งใช้สำหรับการตรวจสอบความถูกต้องและคำขอทั่วไป

## ข้อกำหนดการเชื่อมต่อ

การเชื่อมต่อใหม่จะจัดเก็บคีย์ภูมิภาคที่คงที่ไว้ใน `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

ค่าที่อนุญาตคือ `global-sg` และ `china-beijing` โดยเอนด์พอยต์จะถูกอนุมานจาก ID ผู้ให้บริการและภูมิภาคจากส่วนกลาง ค่า `providerSpecificData.baseUrl` ที่ไม่ได้ตั้งไว้ล่วงหน้าจะยังคงเป็นการกำหนดทับโดยผู้ปฏิบัติงานอย่างชัดเจนและมีลำดับความสำคัญสูงกว่า ขณะที่ URL ที่ตั้งไว้ล่วงหน้าซึ่งบันทึกไว้เดิมจะถูกปรับให้เป็นมาตรฐานตามเมทริกซ์ภูมิภาค

แนวทางนี้ทำให้สคีมาการเชื่อมต่อสามารถขยายเพิ่มเติมได้ โดยสามารถเพิ่มภูมิภาคอื่นลงในตัวแก้ไขได้โดยไม่ต้องสร้างการ์ดผู้ให้บริการใหม่หรือเปลี่ยน ID ผู้ให้บริการที่บันทึกไว้

## ความเข้ากันได้และการทยอยเปิดใช้งาน

1. เพิ่มตัวแก้ไขปลายทางตามภูมิภาคและคงค่าเริ่มต้นแบบส่วนกลางในปัจจุบันไว้
2. ใช้การค้นหา DashScope `/models` ตามภูมิภาคแบบเรียลไทม์สำหรับ `alibaba`, ID ความเข้ากันได้ `alibaba-cn` และ `qwen-cloud` โดยการตอบกลับจะผ่านตัวกรองโมเดลสร้างข้อความหนึ่งชั้นก่อน เนื่องจากปลายทางทั่วไปยังส่งคืนโมเดลรูปภาพ วิดีโอ เสียง embedding และโมเดลอื่นที่ไม่ใช่แชตด้วย จากนั้น `qwen-cloud` จะใช้รายการอนุญาตที่ดูแลไว้และประกาศในรีจิสทรีของผู้ให้บริการ Alibaba Model Studio และ Qwen Cloud ยังคงมีแค็ตตาล็อกที่คัดสรรแยกจากกัน แม้ปัจจุบันจะใช้โฮสต์รันไทม์ร่วมกันก็ตาม
3. ลงทะเบียน `qwen-cloud-token-plan` ด้วยรายการอนุญาตโมเดลข้อความของ Token Plan ในปัจจุบัน
4. เพิ่มตัวเลือกภูมิภาคแบบมีชนิดข้อมูลในกล่องโต้ตอบสำหรับเพิ่ม/แก้ไขการเชื่อมต่อ
5. ซ่อนการ์ด `alibaba-cn` ที่ซ้ำกัน และรวมการเชื่อมต่อที่มีอยู่ของการ์ดดังกล่าวไว้ในหน้าผู้ให้บริการ `alibaba`
6. คงตัวเลือกการกำหนดปลายทางแบบกำหนดเองไว้สำหรับการปรับใช้ขั้นสูงและการปรับใช้เฉพาะเวิร์กสเปซ

โมเดลสื่อของ Token Plan ยังคงอยู่นอกแค็ตตาล็อกแชต เนื่องจากใช้ปลายทางเฉพาะ
`wan2.7-image` และ `wan2.7-image-pro` ลงทะเบียนอยู่ใน `open-sse/config/imageRegistry.ts`;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` และ `happyhorse-1.1-r2v` ลงทะเบียนอยู่ใน
`open-sse/config/videoRegistry.ts` รีจิสทรีทั้งสองใช้ข้อมูลประจำตัวการเชื่อมต่อ
`qwen-cloud-token-plan` และข้อมูลรับรองเฉพาะภูมิภาคร่วมกัน

Qwen Cloud แบบปกติมีแค็ตตาล็อกรูปภาพและวิดีโอแบบจ่ายตามการใช้งานแยกต่างหากภายใต้ข้อมูลประจำตัว
`qwen-cloud` โมเดลรูปภาพ ได้แก่ `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` และ `z-image-turbo` ส่วนโมเดลวิดีโอ
ได้แก่ `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` และ
`wan2.7-videoedit` โมเดลเหล่านี้ใช้เฉพาะการเชื่อมต่อ `qwen-cloud` แบบปกติและปลายทางสื่อ DashScope
ตามภูมิภาค รีจิสทรีของ Token Plan และแบบจ่ายตามการใช้งานจะไม่สืบทอดหรือรวมรายการโมเดลของกันและกัน

ข้อมูลประจำตัว `bailian-coding-plan` ยังมีรายการอนุญาตสำหรับสื่อของตนเองด้วย ได้แก่
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` และ `qwen-image-2.0-pro` สำหรับการสร้างรูปภาพ
รวมถึง
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` และ `happyhorse-1.1-r2v` สำหรับการสร้างวิดีโอ
โดยใช้เฉพาะการเชื่อมต่อ Bailian Coding Plan และปลายทาง Coding Plan ตามภูมิภาค
รีจิสทรีรูปภาพและวิดีโอจะไม่สืบทอดจากหรือรวมเข้ากับผู้ให้บริการ Qwen Cloud รายใด

ข้อมูลประจำตัว `alibaba` แบบปกติมีรายการอนุญาตสำหรับรูปภาพและวิดีโอแยกกัน โมเดลรูปภาพ ได้แก่
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` และ `wan2.6-t2i` โมเดลวิดีโอที่เพิ่มเข้ามา ได้แก่ `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` และ `wan2.7-videoedit` โมเดลเหล่านี้ใช้เฉพาะการเชื่อมต่อ Alibaba Model Studio
และปลายทางสื่อตามภูมิภาคที่เลือกไว้เท่านั้น โดยจะไม่ถูกเพิ่มลงในรีจิสทรี Coding Plan หรือ Qwen
Cloud ใด ๆ

แค็ตตาล็อกแชตของ Qwen Cloud Token Plan ใช้รายการอนุญาตโมเดลข้อความแบบตรงกับสตริงทุกประการของแผน Individual:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` และ
`deepseek-v4-pro` รายการ Wan และ HappyHorse เป็นของ API สำหรับสร้างรูปภาพ/วิดีโอที่แยกต่างหาก

Alibaba Token Plan ให้บริการ ID โมเดลสร้างข้อความปัจจุบันหกรายการเดียวกันผ่านปลายทางที่เข้ากันได้กับ
Anthropic ตัวเลือกสิงคโปร์จะจัดเก็บคีย์ภูมิภาค `global-sg` ที่มีอยู่ โดยต่างกันเฉพาะป้ายกำกับที่แสดงต่อผู้ใช้
เมื่อเทียบกับตระกูลผู้ให้บริการที่เรียกภูมิภาคนี้ว่า Global

แค็ตตาล็อกแชตของ Qwen Cloud แบบปกติถูกกำหนดให้แคบกว่าการตอบกลับข้อความแบบเรียลไทม์ทั้งหมดโดยเจตนา
รายการอนุญาตที่ดูแลไว้จะอยู่ใน `open-sse/config/providers/registry/qwen-cloud/index.ts`;
การค้นหาแบบเรียลไทม์จะส่งคืนเฉพาะ ID ที่ปรากฏทั้งในการตอบกลับจากต้นทางและในรายการของรีจิสทรีดังกล่าว

Alibaba Model Studio ใช้กฎการตัดกันแบบเรียลไทม์เดียวกันกับรายการอนุญาตที่ดูแลแยกต่างหาก
ใน `open-sse/config/providers/registry/alibaba/index.ts` ผู้ให้บริการความเข้ากันได้ `alibaba-cn`
จะใช้แค็ตตาล็อกดังกล่าวซ้ำ โดยแก้ไขปลายทางสำหรับการค้นหาให้เป็นปลายทางปักกิ่ง
