`copilot-m365-web` (นามแฝง `m365copilot`) ส่งคำขอแชตในรูปแบบ OpenAI ผ่านเซสชันเบราว์เซอร์ Microsoft 365 Copilot BizChat ที่ผ่านการยืนยันตัวตนบน
`m365.cloud.microsoft/chat` นี่เป็นการผสานรวมอย่างไม่เป็นทางการ

> **เพิ่งเริ่มใช้ผู้ให้บริการ Web Cookie ใช่ไหม?**
>
> อ่าน **`docs/getting-started/WEB-COOKIE-GUIDE.md`** เพื่อดูขั้นตอนการตั้งค่าทั่วไป แนวทางการยืนยันตัวตน ข้อจำกัด และการแก้ไขปัญหา ก่อนดำเนินการตามคู่มือเฉพาะสำหรับผู้ให้บริการนี้
>
> **สำคัญ:** ข้อมูลประจำตัวสำหรับผู้ให้บริการนี้ **ไม่ใช่คุกกี้** อย่าคัดลอก
> คุกกี้จาก `m365.cloud.microsoft` ข้อมูลประจำตัวประกอบด้วยพารามิเตอร์คำค้นหาของ URL สำหรับ WebSocket และส่วนเส้นทาง ซึ่งทั้งสองค่าอ่านได้จากแท็บ Network ใน DevTools

## ข้อกำหนดเบื้องต้น

- บัญชี Microsoft 365 ที่มีสิทธิ์เข้าถึง BizChat ที่ `m365.cloud.microsoft/chat`
- เบราว์เซอร์ที่ใช้ Chromium (Chrome, Edge) สำหรับตรวจสอบ WebSocket ใน DevTools
- สิทธิ์การใช้งาน M365 Copilot (รวมอยู่ในแผน Microsoft 365 Business/Enterprise หลายแผน)

## การบันทึกข้อมูลประจำตัว (วิธี WebSocket)

1. ลงชื่อเข้าใช้ที่ `https://m365.cloud.microsoft/chat` และเริ่มการสนทนา
2. เปิด **DevTools → Network**
3. กรองด้วย **WS** (WebSocket)
4. คลิกการเชื่อมต่อ WebSocket ของ Chathub มองหา URL ที่ขึ้นต้นด้วย
   `wss://substrate.office.com/m365Copilot/Chathub/`
5. จาก **Request URL** ให้คัดลอก:
   - ค่าพารามิเตอร์คำค้นหา `access_token` (JWT ที่มีอายุสั้น)
   - ส่วนเส้นทาง Chathub หลัง `/Chathub/` (เช่น `<oid>@<tenant>`)

URL แบบเต็มมีรูปแบบดังนี้:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. ใน OmniRoute ไปที่ **Providers → Add Provider** เลือก **Microsoft 365 Copilot
   (BizChat)** แล้ววางข้อมูลประจำตัวในรูปแบบ:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. คลิก **Test Connection** และ **Save**

## การบันทึกข้อมูลประจำตัว (การนำเข้า HAR)

แทนที่จะคัดลอกค่าจาก URL ของ WebSocket ด้วยตนเอง คุณสามารถส่งออกไฟล์ HAR จาก DevTools
ได้ดังนี้:

1. เปิด **DevTools → Network**
2. เริ่มหรือดำเนินการสนทนา BizChat ต่อ (การดำเนินการนี้จะทริกเกอร์การเชื่อมต่อ WebSocket)
3. คลิกขวาในแผง Network แล้วเลือก **Save all as HAR with content**
4. ใน OmniRoute ใช้ปุ่ม **Import .har file** ในกล่องโต้ตอบการเชื่อมต่อผู้ให้บริการ

OmniRoute จะสแกน HAR เพื่อค้นหา URL ของ WebSocket สำหรับ Chathub แยกค่า
`access_token` และ `chathubPath` แล้วกรอกข้อมูลในฟิลด์ข้อมูลประจำตัวโดยอัตโนมัติ การนำเข้า
HAR จะถอดรหัสเวลาหมดอายุของ JWT และแสดงอายุคงเหลือของโทเค็น

> **ห้ามคอมมิตไฟล์ HAR ที่ส่งออกจริง โทเค็นการเข้าถึง หรือโทเค็นรีเฟรชโดยเด็ดขาด** ค่าที่ใช้ในการทดสอบและ
> เอกสารประกอบต้องเป็นค่าตัวยึดตำแหน่งเสมอ

## อายุโทเค็นและการรีเฟรช

`access_token` มีอายุสั้น (โดยทั่วไปประมาณ **~75 นาที**) หลังจากหมดอายุ ผู้ให้บริการ
จะรายงานข้อผิดพลาดในการเชื่อมต่อ และคุณต้องบันทึกข้อมูลประจำตัวใหม่

### การรีเฟรชอัตโนมัติด้วย `refreshToken`

เพื่อหลีกเลี่ยงการบันทึกข้อมูลประจำตัวใหม่ด้วยตนเอง คุณสามารถจัดเก็บโทเค็นรีเฟรชของ Microsoft ไว้ในการตั้งค่า
**Advanced Settings → providerSpecificData** ของการเชื่อมต่อ:

| ฟิลด์          | คำอธิบาย                                                                |
| -------------- | ----------------------------------------------------------------------- |
| `refreshToken` | โทเค็นรีเฟรช Microsoft OAuth สำหรับขอบเขต `substrate.office.com/sydney` |
| `tier`         | `individual` (ค่าเริ่มต้น), `edu` หรือ `enterprise`                     |

รับโทเค็นรีเฟรชจากโฟลว์ device-code หรือ authorization-code ของ Microsoft
ที่กำหนดขอบเขตเป็น `substrate.office.com/sydney` เมื่อตั้งค่า `refreshToken` แล้ว OmniRoute
จะรีเฟรช `access_token` ล่วงหน้าก่อนแต่ละคำขอ คุณจึงไม่จำเป็นต้อง
บันทึกข้อมูลประจำตัวใหม่ทุกครั้งหลังโทเค็นหมดอายุประมาณ 75 นาที

หากไม่ได้ตั้งค่า `refreshToken` คุณต้องบันทึกข้อมูลประจำตัว WebSocket ใหม่ด้วยตนเอง
หลังจากหมดอายุแต่ละครั้ง

### การเลือกระดับ

| ระดับ        | นามแฝง          | พื้นผิว                      |
| ------------ | --------------- | ---------------------------- |
| `individual` | _(ค่าเริ่มต้น)_ | M365 Copilot สำหรับผู้บริโภค |
| `edu`        | `included`      | M365 Copilot สำหรับการศึกษา  |
| `enterprise` | `work`          | M365 Copilot สำหรับการทำงาน  |

ตั้งค่าระดับใน **Advanced Settings → providerSpecificData → tier** ระดับนี้ส่งผลต่อ
การกำหนดเส้นทาง BizChat และการเข้าถึงโมเดล

## โมเดลความปลอดภัย

- **การผสานรวมที่ไม่เป็นทางการ** ผู้ให้บริการนี้ทำวิศวกรรมย้อนกลับโปรโตคอล
  WebSocket ของ BizChat ซึ่งอาจหยุดทำงานโดยไม่มีการแจ้งเตือนเมื่อ Microsoft เปลี่ยนปลายทาง
- แฟล็ก `subscriptionRisk: true` แสดงว่าการผสานรวมนี้อาศัยปลายทางที่
  ไม่มีเอกสารกำกับ บัญชีอาจถูกจำกัดการใช้งานได้ แต่ยังไม่มีการยืนยัน
- โทเค็นการเข้าถึงเป็น JWT ที่มีอายุสั้น ให้ปฏิบัติต่อโทเค็นนี้เสมือนรหัสผ่าน: ห้ามคอมมิต
  บันทึกลงล็อก หรือแชร์
- โทเค็นรีเฟรชมอบสิทธิ์การเข้าถึงพื้นผิว BizChat ในระยะยาว ให้จัดเก็บด้วย
  ความระมัดระวังเช่นเดียวกับคีย์ API

## การแก้ไขปัญหา

### การตรวจสอบสิทธิ์ล้มเหลวทันที

- ตรวจสอบว่าคุณคัดลอกจาก **URL ของ WebSocket** ไม่ใช่จากคำขอ XHR/Fetch
  ข้อมูลประจำตัวอยู่ในพารามิเตอร์คิวรี `access_token` ของการเชื่อมต่อ WebSocket
  ของ Chathub — ไม่ได้อยู่ในส่วนหัว `Authorization: Bearer`
- ตรวจสอบให้แน่ใจว่า `chathubPath` มีส่วน `<oid>@<tenant>` แบบเต็มจากพาธ
  ของ URL

### โทเค็นหมดอายุหลังจากประมาณ 75 นาที

นี่เป็นพฤติกรรมที่คาดไว้ หากไม่มี `refreshToken` โทเค็นการเข้าถึงจะมีอายุสั้น ให้เลือกอย่างใดอย่างหนึ่ง:

- บันทึกข้อมูลประจำตัวจาก DevTools อีกครั้ง หรือ
- กำหนดค่า `refreshToken` ในการตั้งค่าขั้นสูงเพื่อให้รีเฟรชโดยอัตโนมัติ

### การทดสอบการเชื่อมต่อผ่าน แต่แชตส่งคืน 401

โทเค็นอาจหมดอายุระหว่างการตรวจสอบความถูกต้องกับคำขอแรก ให้บันทึก
ข้อมูลประจำตัวใหม่อีกครั้ง

### Copilot ไม่ปรากฏในรายชื่อผู้ให้บริการ

ตรวจสอบว่าเปิดใช้งาน `copilot-m365-web` ใน **แดชบอร์ด → ผู้ให้บริการ** แล้ว ผู้ให้บริการอาจ
ถูกซ่อนไว้ตามค่าเริ่มต้นในบางระดับแพ็กเกจ
