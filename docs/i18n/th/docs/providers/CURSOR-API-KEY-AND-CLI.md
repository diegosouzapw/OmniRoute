สองวิธีในการใช้งาน Cursor ผ่าน OmniRoute โดยไม่ต้องมีเซสชัน IDE:

1. **ผู้ให้บริการ `cursor-api`** (การ์ด "Cursor API", นามแฝง `cua`): ผู้ให้บริการแบบคีย์ API
   ที่จัดเก็บคีย์ API ผู้ใช้ Cursor (`crsr_…` ซึ่งสร้างได้ที่
   `https://cursor.com/dashboard/api`) จากนั้นไคลเอนต์ OmniRoute ใดๆ ก็สามารถเข้าถึง
   โมเดล Cursor ผ่าน `/v1/chat/completions` ในชื่อ `cursor-api/<model>` หรือ
   `cua/<model>` พร้อมใช้ชั้นโควตา การสำรอง และการบันทึกตามปกติ ส่วนผู้ให้บริการ IDE
   (`cursor`, เซสชัน OAuth/IDE) จะไม่มีการเปลี่ยนแปลง
2. **การส่งผ่าน Cursor CLI**: กำหนดให้ Cursor CLI (`agent`) ชี้ไปยัง OmniRoute เพื่อให้
   ทุก RPC ที่ CLI ส่งมีการยืนยันตัวตนด้วยคีย์ API ของ OmniRoute ถูกส่งต่อ
   ไปยัง Cursor โดยใช้ข้อมูลประจำตัวของการเชื่อมต่อ `cursor-api` และถูกบันทึก
   ในหน้า Logs

## เหตุผลที่ต้องแลกเปลี่ยนคีย์

`api2.cursor.sh` ปฏิเสธคีย์ดิบ `crsr_…` เมื่อใช้เป็นโทเค็น Bearer (401) โดย Cursor
CLI จะ POST คีย์ไปยัง `/auth/exchange_user_api_key` ก่อน และรับ JWT ของเซสชัน
ที่หมดอายุหลังจากหนึ่งชั่วโมง ส่วน `refreshToken` ที่ส่งกลับมาจะมีค่า
`exp` เดียวกัน ดังนั้นการรีเฟรชจึงหมายถึงการแลกเปลี่ยนคีย์ใหม่
`open-sse/services/cursorApiKeyAuth.ts` ดำเนินการแลกเปลี่ยนดังกล่าว แคชโทเค็นเซสชันหนึ่งรายการ
ต่อหนึ่งคีย์ แลกเปลี่ยนใหม่ห้านาทีก่อนหมดอายุ และลบโทเค็นที่แคชไว้
เมื่อ Cursor ตอบกลับด้วย 401 โดย `CursorExecutor` จะเรียกใช้ส่วนนี้ก่อนเปิด
สตรีมต้นทางสำหรับการเชื่อมต่อ `cursor-api`

## ผู้ให้บริการ `cursor-api`

รีจิสทรี: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"` และใช้ `format`, `baseUrl` รวมถึง
`models` เดียวกับ `cursor`) การ์ดแค็ตตาล็อก:
`src/shared/constants/providers/apikey/specialty-media.ts` แมปตัวดำเนินการ:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`)

แดชบอร์ด: Providers → Cursor API → Add API key

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

จากนั้น:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

หมายเหตุ:

- รายการโมเดลสำหรับ `cursor-api` มาจากรีจิสทรี Cursor แบบคงที่ (เป็น
  รายการเดียวกับที่ผู้ให้บริการ IDE ใช้เป็นตัวสำรอง) โดยไม่จำเป็นต้องติดตั้ง
  `cursor-agent` บนโฮสต์ OmniRoute
- `POST /api/providers/{id}/refresh-cursor` ใช้สำหรับผู้ให้บริการ `cursor` IDE
  เท่านั้น การเชื่อมต่อ `cursor-api` ไม่มีเซสชัน IDE ที่ต้องต่ออายุ

## การส่งผ่าน Cursor CLI

เส้นทาง: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts` คำนำหน้า `/api/cursor-cli/` ได้รับการ
ลงทะเบียนไว้ใน `src/shared/constants/publicApiRoutes.ts` เนื่องจากตัวจัดการ
บังคับใช้การยืนยันตัวตนของตนเอง:

| พาธ                                                                                                                        | การยืนยันตัวตนที่คาดหวังจาก CLI | สิ่งที่ OmniRoute ดำเนินการ                                                                                                                                                      |
| -------------------------------------------------------------------------------------------------------------------------- | ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                         | `Bearer <OmniRoute API key>`    | ตรวจสอบคีย์ สร้าง JWT แบบ HS256 อายุ 1 ชั่วโมง (ลงนามด้วย `JWT_SECRET`) และส่งกลับ                                                                                               |
| พาธอื่นทั้งหมด (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`             | ตรวจสอบผู้ออกโทเค็น/กลุ่มเป้าหมาย/การหมดอายุ เลือกการเชื่อมต่อ `cursor-api` ที่ใช้งานอยู่ สลับเฮดเดอร์ Authorization เป็นโทเค็น Cursor ที่แลกเปลี่ยนมา แล้วสตรีมการตอบกลับกลับไป |

CLI จะถอดรหัส `exp` จากโทเค็นใดๆ ที่ได้รับ ดังนั้นการส่งโทเค็นแบบทึบแสง
ให้แก่ CLI จะทำให้มีการแลกเปลี่ยนใหม่ก่อนคำขอแทบทุกครั้ง ส่วน JWT ที่สร้างขึ้น
ช่วยหลีกเลี่ยงปัญหานี้ การตอบกลับ 401 จาก OmniRoute จะทำให้ CLI แลกเปลี่ยนอีกครั้ง

### การตั้งค่า

1. สร้างคีย์ API ของ OmniRoute (Dashboard → API keys) และการเชื่อมต่อ `cursor-api`
2. กำหนดให้ CLI ใช้ HTTP/1.1 สำหรับสตรีมของเอเจนต์ ใน
   `~/.cursor/cli-config.json`:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   หากไม่มีการตั้งค่านี้ CLI จะเปิดรอบการทำงานของเอเจนต์ผ่าน HTTP/2 ไปยังโฮสต์
   เอเจนต์ที่กำหนดค่าแยกต่างหาก และมีเพียง RPC ของระนาบควบคุมเท่านั้นที่ผ่าน
   เอนด์พอยต์นี้

3. เรียกใช้ CLI ผ่าน OmniRoute:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

ทุกฮอปจะปรากฏใน Logs โดยมีผู้ให้บริการเป็น `cursor-api` ประเภทคำขอเป็น `cursor-cli`
พาธเป็น `/api/cursor-cli/<rpc>` และเชื่อมโยงกับคีย์ API ของ OmniRoute รวมถึง
การเชื่อมต่อที่ให้บริการคำขอนั้น

### รูปแบบความล้มเหลว

| สถานการณ์                                             | การตอบสนองต่อ CLI                                      |
| ----------------------------------------------------- | ------------------------------------------------------ |
| คีย์ OmniRoute ที่ไม่รู้จักและ `REQUIRE_API_KEY=true` | 401 `unauthenticated` ระหว่างการแลกเปลี่ยน             |
| `REQUIRE_API_KEY=false`                               | เซสชันแบบไม่ระบุตัวตน (สอดคล้องกับพฤติกรรมของ `/v1/*`) |
| JWT ของเซสชันหมดอายุ / มาจากภายนอก / ถูกแก้ไข         | 401 และ CLI จะแลกเปลี่ยนใหม่                           |
| คีย์ OmniRoute API ถูกเพิกถอนหลังการแลกเปลี่ยน        | 401 ใน RPC ถัดไป                                       |
| ไม่มีการเชื่อมต่อ `cursor-api` ที่ใช้งานอยู่          | 503 `unavailable`                                      |
| Cursor ปฏิเสธคีย์ของการเชื่อมต่อ                      | 401 `unauthenticated` และลบเซสชันที่แคชไว้             |
| ไม่สามารถเข้าถึงต้นทางได้                             | 502 `unavailable` (ข้อความที่ผ่านการกรองแล้ว)          |
| ไม่ได้ตั้งค่า `JWT_SECRET`                            | 503 ระหว่างการแลกเปลี่ยน                               |
