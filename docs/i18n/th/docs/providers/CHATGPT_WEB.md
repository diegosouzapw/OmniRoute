`chatgpt-web-codex` (ชื่อแทน `cgpt-codex`) เชื่อมต่อรอบการโต้ตอบของ Codex Responses ผ่านเซสชันเบราว์เซอร์ ChatGPT ที่ผ่านการยืนยันตัวตน โดยเป็นอิสระจากผู้ให้บริการส่วนกลาง `chatgpt-web` ที่เลิกใช้งานแล้ว และใช้การติดตั้งใช้งานที่มีประกาศสิทธิ์การใช้งาน MIT ภายใต้ `open-sse/vendor/codex-chatgpt-web/` ซึ่งอัปเดตตาม upstream v4.0.7 commit `b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494`

## การเลิกใช้งานผู้ให้บริการส่วนกลาง

ID ผู้ให้บริการส่วนกลางเดิม `chatgpt-web` และ `cgpt-web` ไม่ได้รวมมาให้อีกต่อไป เนื่องจากไม่สามารถตรวจสอบที่มาของการติดตั้งใช้งาน pre-key/proof-of-work ให้ชัดเจนได้ คำขอที่ระบุ ID ใด ID หนึ่งอย่างชัดเจน รวมถึง ID โมเดลที่มีเครื่องหมายทับนำหน้าและชื่อแทนที่บันทึกไว้ จะล้มเหลวแบบปิดด้วย HTTP `410` และรหัส **PROVIDER_RETIRED** ก่อนส่งคำขอใดๆ ไปยัง upstream

การย้ายข้อมูล `168_retire_chatgpt_web.sql` ทำเครื่องหมาย tombstone ให้กับการเชื่อมต่อผู้ให้บริการที่ตรงกัน และทำให้สิทธิ์เช่าเซสชันที่ใช้งานอยู่ของการเชื่อมต่อเหล่านั้นเป็นโมฆะ โดยยังคงเก็บประวัติการเชื่อมต่อและรายการอนุญาตของ API key ไว้ และจะไม่เพิ่มสิทธิ์การเข้าถึงทดแทนลงในรายการอนุญาต การเลิกใช้งานนี้ไม่ครอบคลุมผู้ให้บริการ Codex และการเชื่อมต่อของผู้ให้บริการดังกล่าว

## ข้อกำหนดเบื้องต้น

- ส่วนหัว Cookie แบบเต็มจากเซสชัน ChatGPT ที่ลงชื่อเข้าใช้แล้ว
- Chrome หรือ Chromium พร้อมเซสชันกราฟิกหรือจอแสดงผล Xvfb สำหรับการติดตั้งด้วย npm, systemd และ PM2
- เมื่อใช้โปรไฟล์ Docker `web` ให้ใช้บริการ Chromium ภายในจาก `docker-compose.yml`
- OpenAI `tunnel-client` v0.0.13 และตัวเชื่อมต่อแบบกำหนดเองของ ChatGPT สำหรับเครื่องมือ Codex ภายในเครื่อง

จำเป็นต้องใช้ tunnel เฉพาะสำหรับรอบการโต้ตอบที่ใช้เครื่องมือเท่านั้น ทุก route ที่ระบุไว้ รวมถึง `pro` สามารถใช้ความสามารถของเครื่องมือภายในเครื่องที่ผูกกับรอบการโต้ตอบแบบเดียวกันได้ เมื่อกำหนดค่า tunnel และตัวเชื่อมต่อแล้ว

## การตั้งค่าแดชบอร์ด

1. เปิดผู้ให้บริการ **ChatGPT Web (Codex)** และเพิ่มการเชื่อมต่อ
2. วางส่วนหัว Cookie ของ ChatGPT แบบเต็ม, tunnel ID, runtime key และชื่อตัวเชื่อมต่อแบบกำหนดเอง การตั้งค่าใหม่ที่รองรับเครื่องมือต้องใช้ตัวเชื่อมต่อที่สร้างขึ้นใหม่และตั้งชื่อว่า `OmniRoute Codex v2` ทุกตัวอักษร โดยตั้งค่า Authentication เป็น None และ Permissions เป็น Allow all actions
3. เรียกใช้การตรวจสอบการเชื่อมต่อ OmniRoute จะเปิด Temporary Chat ที่ทำงานผ่านเบราว์เซอร์ และตรวจสอบว่า Sol และ Pro พร้อมใช้งานสำหรับบัญชีดังกล่าวหรือไม่
4. บันทึกการเชื่อมต่อ OmniRoute จะแทนที่ cookie ที่วางไว้ด้วยสถานะพื้นที่จัดเก็บของ Playwright ที่ผ่านการตรวจสอบแล้ว และจัดเก็บสถานะดังกล่าวพร้อม runtime key ผ่านกลไกจัดการข้อมูลรับรองที่เข้ารหัส

ระบบจะไม่เก็บ cookie ดิบไว้หลังบันทึกสำเร็จ เมื่อเซสชันหมดอายุ ให้เปิดการเชื่อมต่อ วางส่วนหัว Cookie แบบเต็มชุดใหม่ แล้วเรียกใช้การตรวจสอบอีกครั้ง สถานะ doctor ในกล่องโต้ตอบแก้ไขจะแสดงผลแยกกันสำหรับเบราว์เซอร์, สถานะพื้นที่จัดเก็บ, การลงชื่อเข้าใช้, Temporary Chat, tunnel, ตัวเชื่อมต่อ และการทดสอบเครื่องมือแบบไปกลับ

> ห้าม commit cookie จริง, runtime key, สถานะพื้นที่จัดเก็บ หรือ capability token โดยเด็ดขาด ค่าที่ใช้ในการทดสอบและเอกสารต้องเป็น placeholder เสมอ

## โมเดลและคอมโบ

route ของโมเดลแบบคงที่มีดังนี้:

- `chatgpt-web-codex/luna` — GPT-5.6 Luna, effort ระดับต่ำ
- `chatgpt-web-codex/think` — GPT-5.6 Luna, effort ระดับปานกลาง
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

เพิ่ม route ใด route หนึ่งลงในคอมโบได้เช่นเดียวกับโมเดลอื่น แอป Codex จะส่งชื่อคอมโบเป็น `model` ไปยัง endpoint ปกติของ Responses ที่ `/v1/responses` โดยไม่มี endpoint ของ Codex หรือสวิตช์โหมดแยกต่างหาก

บัญชี Free/Go สามารถใช้ route ของ Luna ได้ บัญชีที่รองรับ Sol สามารถใช้ตั้งแต่ Instant ถึง High และบัญชีที่รองรับ Pro จะสามารถใช้ Extra High และ Pro เพิ่มเติมได้ แต่ละ route มีโมเดล backend และ reasoning effort แบบคงที่ หากระบุ Responses effort ที่ขัดแย้งกันอย่างชัดเจน ระบบจะล้มเหลวแบบปิดแทนที่จะเปลี่ยนโหมดเบราว์เซอร์ที่เลือกไว้อย่างเงียบๆ

ห้ามเปลี่ยนชื่อหรือนำตัวเชื่อมต่อ `Codex Native` หรือ `OmniRoute Codex` รุ่นเก่ากลับมาใช้ใหม่ ChatGPT จะแคชสัญญา MCP สาธารณะตามข้อมูลประจำตัวของตัวเชื่อมต่อ ขณะที่ bridge ที่อัปเดตใหม่ใช้สัญญา turn-token โดยตรงแบบใหม่ runtime จะปฏิเสธข้อมูลประจำตัวเดิมเหล่านั้น และกำหนดให้ใช้ตัวเชื่อมต่อ `OmniRoute Codex v2` ที่สร้างขึ้นใหม่

## โมเดลความปลอดภัย

- เส้นทางแบบเนทีฟต้องใช้คำขอ Responses, ไคลเอนต์ Codex ที่ระบบรู้จัก และข้อมูลระบุตัวตนของเธรดและเทิร์นที่ตรงกัน
- เวิร์กสเปซ, แซนด์บ็อกซ์, นโยบายการอนุมัติ และแค็ตตาล็อกเครื่องมือมาจากเชลล์ Codex แบบเนทีฟ โดยข้อความพรอมต์แบบอิสระไม่มีสิทธิ์กำหนดสิ่งเหล่านี้
- ChatGPT ได้รับเฉพาะความสามารถที่มีอายุสั้นในแต่ละเทิร์น โบรกเกอร์ MCP ยอมรับเฉพาะเครื่องมือที่ Codex เสนอในเทิร์นนั้นโดยเฉพาะ
- การยืนยัน **Allow once** โดยอัตโนมัติเป็นเพียงการส่งคำขอใช้เครื่องมือกลับไปยัง Codex เท่านั้น Codex เป็นผู้ตัดสินใจแต่เพียงผู้เดียวเกี่ยวกับการอนุมัติและการดำเนินการ
- ก่อนเอาต์พุตแรก ชุดค่าผสมอาจเปลี่ยนไปใช้เป้าหมายอื่นที่เข้ากันได้ แต่หลังจากเริ่มส่งเอาต์พุตแล้ว ผู้ให้บริการ, โมเดล, การเชื่อมต่อ และเทิร์นของเบราว์เซอร์จะถูกตรึงไว้จนกว่าเทิร์นจะเสร็จสมบูรณ์
- คุกกี้, คีย์รันไทม์, สถานะพื้นที่จัดเก็บ และโทเค็นความสามารถจะไม่ปรากฏในการตอบกลับจากผู้ให้บริการหรือบันทึกคำขอ

## VPS แบบไม่มีจอแสดงผลและ Docker

สำหรับการติดตั้งด้วย npm, systemd และ PM2 นั้น OmniRoute จะตรวจหาเส้นทางทั่วไปของ Chrome และ Chromium หรือสามารถตั้งค่า `CHATGPT_WEB_CODEX_CHROME_PATH` แทนได้ เทิร์นรันไทม์จงใจใช้ Chrome แบบมีส่วนติดต่อผู้ใช้ เนื่องจาก ChatGPT ปฏิเสธรูปแบบเบราว์เซอร์แบบ headless อย่างแท้จริง ดังนั้นโฮสต์ที่ไม่มีจอแสดงผลจึงต้องเรียกใช้ OmniRoute พร้อมจอแสดงผล Xvfb ส่วนตัว การตั้งค่าเฉพาะเส้นทาง Chrome ไม่ได้จัดเตรียมจอแสดงผลดังกล่าวให้

โปรไฟล์ `web` ของ Docker จะเริ่ม `chatgpt-web-codex-browser` บนเครือข่าย Compose ภายใน sidecar เรียกใช้ Chrome แบบมีส่วนติดต่อผู้ใช้ภายใน Xvfb จึงไม่จำเป็นต้องมีจอแสดงผลจริง พอร์ต CDP ของ sidecar จะไม่ถูกเผยแพร่บนโฮสต์ โวลุ่มโปรไฟล์เบราว์เซอร์ที่ได้รับการป้องกันจะแยกจากโวลุ่มข้อมูลของ OmniRoute และเบราว์เซอร์จะได้รับหน่วยความจำที่ใช้ร่วมกันอย่างเพียงพอ พร็อกซี CDP ภายในรับฟังเฉพาะบนพอร์ต `9223` ภายในเครือข่าย Compose ส่วน Chrome ยังคงผูกอยู่กับลูปแบ็กใน sidecar

สัญญาเช่าของตัวควบคุมภายใต้ `DATA_DIR` จะป้องกันไม่ให้กระบวนการ OmniRoute หลายกระบวนการครอบครองสถานะทันเนลและโบรกเกอร์เดียวกัน doctor จะรายงานเมื่อเกิดข้อขัดแย้ง

## การกู้คืนแบบโต้ตอบ

เส้นทาง Docker อัตโนมัติไม่มีหน้าต่างที่มองเห็นได้จากโฮสต์ แต่ Chrome เองทำงานแบบมีส่วนติดต่อผู้ใช้ภายในจอแสดงผล Xvfb ส่วนตัว เมื่อ ChatGPT ต้องการการลงชื่อเข้าใช้หรือการตรวจสอบแบบโต้ตอบ สามารถใช้โครงสร้างพื้นฐานเบราว์เซอร์ VNC ที่มีอยู่เพื่อกู้คืนได้ UI ของเบราว์เซอร์และ CDP ต้องสามารถเข้าถึงได้เฉพาะผ่านลูปแบ็ก, การเชื่อมต่อเพื่อการจัดการที่ผ่านการตรวจสอบสิทธิ์ หรือทันเนล SSH เท่านั้น ส่วน noVNC จะยังคงปิดใช้งานระหว่างการทำงานตามปกติ

## การย้อนกลับไปใช้ WebSocket

เมื่อชุดค่าผสมมี ChatGPT Web (Codex) บริดจ์ Responses WebSocket จะร้องขอการย้อนกลับไปใช้ HTTP/SSE ก่อนเชื่อมต่อไปยังต้นทาง จากนั้นการถ่ายโอนจะดำเนินการผ่าน `/v1/responses`

## การตรวจสอบ

เรียกใช้การควบคุมผู้ให้บริการโดยไม่เรียกใช้ผู้ให้บริการที่เลิกใช้งานแล้ว:

```bash
node --import tsx/esm --test \\
  tests/unit/chatgpt-web-codex.test.ts \\
  tests/unit/chatgpt-web-codex-turn-pin.test.ts \\
  tests/unit/chatgpt-web-environment-double-unescape.test.ts
```

- `tests/unit/chatgpt-web-image-handler-retirement.test.ts`
- `tests/unit/chatgpt-web-source-retirement.test.ts`
