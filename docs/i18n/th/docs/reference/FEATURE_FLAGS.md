## Feature Flags คืออะไร

Feature flag คือตัวสลับที่มีชื่อ (ชนิด boolean หรือ enum) ซึ่งสามารถเปลี่ยนค่าได้ใน
ขณะรันไทม์และบันทึกถาวรไว้ในฐานข้อมูล โดยไม่จำเป็นต้องปรับใช้โปรเซสใหม่ แต่ละ
แฟล็กอธิบายด้วย `FeatureFlagDefinition` ซึ่งประกอบด้วย `key`, `label`,
`description`, `category`, `defaultValue`, `type` และคำใบ้ `requiresRestart`

### ลำดับการกำหนดค่า

**ค่าที่มีผลจริง** ของแฟล็กจะถูกกำหนดโดย
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) ตามลำดับ
ความสำคัญต่อไปนี้ (ลำดับที่สูงกว่าจะมีผล):

1. **ค่าที่กำหนดทับใน DB** — ค่าที่จัดเก็บไว้ในตาราง `key_value` ภายใต้
   namespace `feature_flags` (ตั้งค่าผ่านแดชบอร์ดหรือ REST API)
2. **ตัวแปรสภาพแวดล้อม** — `process.env[<KEY>]` หากมีการตั้งค่าและค่าไม่ว่างเปล่า
3. **ค่าเริ่มต้นจากข้อกำหนด** — `defaultValue` จาก `featureFlagDefinitions.ts`

แฟล็กชนิด boolean จะถือว่า **เปิดใช้งาน** เมื่อค่าที่มีผลจริงคือ `"true"`,
`"1"` หรือ `"yes"` (ดู `isFeatureFlagEnabled()`)

> [!NOTE]
> แฟล็กส่วนใหญ่ยังมีตัวแปรสภาพแวดล้อมที่ตรงกันและใช้ **ชื่อเดียวกัน**
> ซึ่งจัดทำเอกสารไว้ใน [`ENVIRONMENT.md`](./ENVIRONMENT.md) ค่าที่กำหนดทับใน DB
> ของแฟล็กจะมีลำดับความสำคัญเหนือกว่าตัวแปรสภาพแวดล้อมดังกล่าว แฟล็กที่มี
> `requiresRestart: true` จะถูกบันทึกถาวรทันที แต่จะถูกอ่านใหม่เฉพาะตอนเริ่มต้น
> โปรเซสเท่านั้น การสลับแฟล็กดังกล่าวจะแสดงแบนเนอร์ **"รีสตาร์ตเซิร์ฟเวอร์"** ในแดชบอร์ด

## แค็ตตาล็อกแฟล็ก

แฟล็ก 76 รายการใน 6 หมวดหมู่ **ค่าเริ่มต้น** คือค่าเริ่มต้นที่กำหนดไว้ — ค่าที่ใช้
เมื่อไม่มีทั้งค่าที่เขียนทับจาก DB และตัวแปรสภาพแวดล้อม

### ความปลอดภัย (10)

| คีย์                                    | ชนิด  | ค่าเริ่มต้น | คำอธิบาย                                                                                                                                                                                                                                             |
| --------------------------------------- | ----- | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `REQUIRE_API_KEY`                       | บูลีน | `false`     | กำหนดให้คำขอขาเข้าทั้งหมดต้องใช้ API key                                                                                                                                                                                                             |
| `INPUT_SANITIZER_ENABLED`               | บูลีน | `true`      | เปิดใช้การทำความสะอาดข้อมูลอินพุตสำหรับคำขอทั้งหมด                                                                                                                                                                                                   |
| `INJECTION_GUARD_MODE`                  | enum  | `off`       | โหมดป้องกัน prompt injection ค่า: `off`, `warn`, `block`, `redact`                                                                                                                                                                                   |
| `PII_REDACTION_ENABLED`                 | บูลีน | `false`     | ปกปิด PII จากคำขอ (ทำงานเป็นอิสระจาก `INPUT_SANITIZER_MODE`)                                                                                                                                                                                         |
| `PII_RESPONSE_SANITIZATION`             | บูลีน | `false`     | ทำความสะอาด PII จากการตอบกลับของผู้ให้บริการ                                                                                                                                                                                                         |
| `PII_RESPONSE_SANITIZATION_MODE`        | enum  | `redact`    | โหมดสำหรับการทำความสะอาด PII ในการตอบกลับ ค่า: `redact`, `warn`, `block`, `off`                                                                                                                                                                      |
| `OUTBOUND_SSRF_GUARD_ENABLED`           | บูลีน | `true`      | บล็อกคำขอขาออกไปยังช่วง IP ส่วนตัว/ภายใน                                                                                                                                                                                                             |
| `ALLOW_API_KEY_REVEAL`                  | บูลีน | `false`     | อนุญาตให้ผู้ใช้แดชบอร์ดที่ผ่านการตรวจสอบสิทธิ์เปิดเผย API key ที่จัดเก็บไว้ แทนที่จะเห็นเฉพาะค่าที่ถูกปิดบัง                                                                                                                                         |
| `AUTH_LOG_INCLUDE_ACCOUNT_ID`           | บูลีน | `false`     | รวมคำนำหน้าบัญชีในบรรทัดบันทึก AUTH (เช่น "กำลังใช้บัญชี <provider>: abc12345...") โดยค่าเริ่มต้นจะปิดใช้งานเพื่อให้ตัวระบุบัญชีถูกปกปิดจากบันทึกกระบวนการที่แชร์/รองรับหลายผู้เช่า ทำงานเป็นอิสระจากโหมดดีบัก การสลับโหมดดีบักจะไม่เปิดเผยข้อมูลนี้ |
| `OMNIROUTE_OIDC_DISABLE_PASSWORD_LOGIN` | บูลีน | `false`     | เมื่อเปิดใช้ OIDC ให้ปิดใช้งานการเข้าสู่ระบบด้วยรหัสผ่าน เพื่อให้ผู้ใช้ตรวจสอบสิทธิ์ได้ผ่าน OIDC Single Sign-On เท่านั้น เมื่อปิดใช้งาน (ค่าเริ่มต้น) จะสามารถใช้ได้ทั้งการเข้าสู่ระบบด้วยรหัสผ่านและ OIDC                                           |

| `PROXY_AUTO_SELECT_ENABLED`                     | boolean    | `false`     |          | เมื่อไม่มีพร็อกซีถูกกำหนดให้กับการเชื่อมต่อ ให้เลือกพร็อกซีตัวแรกที่ใช้งานได้จากรีจิสทรีโดยอัตโนมัติ ปิดไว้เป็นค่าเริ่มต้น (มิฉะนั้น พร็อกซีใดๆ ในรีจิสทรีจะกลายเป็นตัวสำรองส่วนกลาง — #3332)                                                                                                                                                                                                                                                                                |

| `PROXY_HEALTH_BLOCKED_RESETS_STREAK`      | boolean | `false`     | ในการตรวจสอบสถานะพร็อกซีแบบกวาด การตรวจสอบที่เป้าหมายปฏิเสธ (401/403/429) จะรีเซ็ตจำนวนความล้มเหลวต่อเนื่องของพร็อกซี ค่าเริ่มต้นคือปิด: การปฏิเสธยังคงเป็นกลาง (#10654) ส่วน 5xx ยังคงถือว่าสรุปไม่ได้ไม่ว่าจะตั้งค่าอย่างไร และการปฏิเสธจะไม่ลบ ปิดใช้งาน หรือเปิดใช้งานพร็อกซีอีกครั้ง |
| `DB_HEALTHCHECK_STARTUP_DEFERRED_ENABLED` | boolean | `false`     | เรียกใช้การตรวจสอบความสมบูรณ์/สถานะของ DB ตอนเริ่มต้น หลังจากเซิร์ฟเวอร์เริ่มรับคำขอแล้ว (ผ่าน `setImmediate`) แทนที่จะบล็อกการเริ่มต้นจนกว่าจะตรวจสอบเสร็จสิ้น (#13717) ค่าเริ่มต้นคือปิด: การเริ่มต้นจะถูกบล็อกเหมือนกับก่อน PR นี้ทุกประการ                                            |

> [!NOTE]
> `INPUT_SANITIZER_BLOCK_THRESHOLD` และชื่อแทนเดิม
> `INJECTION_GUARD_BLOCK_THRESHOLD` ใช้ปรับโหมด `block` ของ
> `INJECTION_GUARD_MODE` แต่ทั้งสองเป็นตัวแปรสภาพแวดล้อมธรรมดาที่อ่านโดย
> [`src/shared/utils/injectionSeverity.ts`](../../src/shared/utils/injectionSeverity.ts)
> ไม่ใช่แฟล็กฟีเจอร์: ไม่มีการแทนที่ค่าผ่าน DB และไม่มีสวิตช์บนแดชบอร์ด ดู
> [`ENVIRONMENT.md`](./ENVIRONMENT.md#4-security--authentication)

> [!NOTE]
> คอลัมน์ `Restart` ใช้ระบุแฟล็กที่มี `requiresRestart: true` — ค่าจะถูกบันทึก
> ทันที แต่จะมีผลหลังจากโหลดกระบวนการใหม่เท่านั้น แฟล็กชนิด enum
> จะปฏิเสธค่าที่อยู่นอกชุดค่าที่อนุญาต (ตรวจสอบความถูกต้องฝั่งเซิร์ฟเวอร์ทั้งใน
> `setFeatureFlagOverride()` และตัวจัดการ `PUT` ของ REST)

## การสลับสถานะ Flag

### แดชบอร์ด

ไปที่ **แดชบอร์ด → การตั้งค่า → Feature Flags**
(`/dashboard/settings/feature-flags`) กริด
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
รองรับ:

- **การค้นหา** ตามคีย์หรือคำอธิบาย และ **การกรอง** ตามหมวดหมู่ (รวมถึงมุมมอง
  **ต้องรีสตาร์ต** ที่สร้างขึ้นเพิ่มเติม)
- **สวิตช์** สำหรับ Flag แบบบูลีน และ **รายการแบบเลื่อนลง** สำหรับ Flag แบบ enum
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`)
- **ป้ายกำกับแหล่งที่มา** สำหรับแต่ละ Flag — `DB`, `ENV` หรือ `DEF` — ซึ่งแสดงว่า
  ค่าที่มีผลมาจากที่ใด
- ปุ่ม **รีเซ็ต** (แสดงเฉพาะ Flag ที่มีแหล่งที่มาเป็น `DB`) เพื่อลบค่าที่เขียนทับ
  และปุ่ม **รีเซ็ตค่าที่เขียนทับทั้งหมด** ที่ด้านล่าง
- แบนเนอร์ **รีสตาร์ตเซิร์ฟเวอร์** เมื่อมีการเปลี่ยนแปลง Flag ที่มี `requiresRestart`

### REST API

การดำเนินการทั้งหมดจะผ่าน Route เดียว:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts)
ทุกเมธอดต้องใช้เซสชันแดชบอร์ดที่ผ่านการตรวจสอบสิทธิ์แล้ว (มิฉะนั้นจะส่งคืน `401`)

#### `GET /api/settings/feature-flags`

ส่งคืน Flag ทุกตัวพร้อมค่าที่มีผล แหล่งที่มา และข้อมูลสรุป

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... Flag ทั้งหมด 75 ตัว
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

กำหนดหรือลบค่าที่เขียนทับรายการเดียว Body: `{ key: string; value?: string }`
การไม่ระบุ `value` จะเป็นการลบค่าที่เขียนทับ (และคืนค่า env / ค่าเริ่มต้น)

```bash
# กำหนดค่าที่เขียนทับใน DB
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# ลบค่าที่เขียนทับ (ไม่มี "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

การตอบกลับจะส่งคืน `effectiveValue`/`source` ใหม่, `previousValue`/
`previousSource` และ `requiresRestart` คีย์ที่ไม่รู้จักและค่า enum
ที่อยู่นอกช่วงจะถูกปฏิเสธด้วย `400`

#### `DELETE /api/settings/feature-flags`

ล้างค่าที่เขียนทับใน DB **ทั้งหมด** พร้อมกัน โดยคืนค่า Flag ทุกตัวเป็นค่า env /
ค่าเริ่มต้น ส่งคืน `{ cleared: <count>, message: "..." }`

> [!NOTE]
> Flag ที่มี `requiresRestart: true` จะมีผลหลังจากโหลดโปรเซสใหม่แล้วเท่านั้น
> ขั้นตอนการรีสตาร์ตของแดชบอร์ดจะเรียก `POST /api/restart` แล้วสำรวจ
> `GET /api/health/ping` ซ้ำจนกว่าเซิร์ฟเวอร์จะกลับมาทำงาน

## การใช้เส้นทางสำรองฉุกเฉินเมื่องบประมาณหมด

`OMNIROUTE_EMERGENCY_FALLBACK` (หมวดหมู่ `runtime`, ค่าเริ่มต้น `true`) ควบคุม
เส้นทางสำรองฟรีฉุกเฉินใน
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)
เมื่อเปิดใช้งาน คำขอที่ใช้งบประมาณจนหมดจะถูกส่งไปยังผู้ให้บริการ/โมเดลสำรองฟรี
แทนที่จะล้มเหลวทันที ตั้งค่าเป็น `false` (หรือ `0`) — ผ่านสวิตช์บนแดชบอร์ด
ค่าที่เขียนทับใน DB หรือตัวแปรสภาพแวดล้อม `OMNIROUTE_EMERGENCY_FALLBACK` —
เพื่อปิดใช้งานลักษณะการทำงานนี้ และปล่อยให้คำขอที่ใช้งบประมาณหมดล้มเหลว
(แสดงเป็นสวิตช์บนแดชบอร์ดใน PR #3741 / #3752)
