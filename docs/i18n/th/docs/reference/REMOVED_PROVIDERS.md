Some services were integrated into OmniRoute and later removed because the people who run
them asked for it. This page is the durable record of those removals. Its only purpose is to
keep them from coming back by accident: a contributor who finds an old fork, a cached npm
tarball, an archived issue or a "restore provider X" request needs one place that says **do
not reintroduce**.

This page is **not** a list of dead or discontinued services. Those are tracked in
[`FREE_TIERS.md`](FREE_TIERS.md) ("Removed / no free tier") and can come back if the service
does. The entries below can only come back with written permission from the operator named in
the request, and that permission must be linked from the entry.

## นโยบาย (Policy)

1. **คำขอถอดถอนจากผู้ให้บริการจะได้รับการปฏิบัติตามทันทีโดยไม่มีการต่อรอง** OmniRoute
   ไม่มีส่วนเกี่ยวข้องกับบริการต้นทางใดๆ ทั้งสิ้น เมื่อผู้ให้บริการขอให้ถอดการเชื่อมต่อออก
   ก็จะต้องถูกถอดออก ไม่ว่าการเชื่อมต่อรวนนั้นจะใช้ API อย่างเป็นทางการหรือไม่ก็ตาม
2. **คำว่า "ถอดออก" หมายถึงทุกส่วนที่ OmniRoute ควบคุมอยู่ทั้งหมด** ได้แก่ Executor, รายการใน Registry, ID และ Alias ของ Provider, รายการ Model, Endpoint, ตัวแปรสภาพแวดล้อม (Environment Variables), ไอคอน, การ์ดบนแดชบอร์ด, เอกสารอ้างอิง Provider ที่สร้างขึ้น, `FREE_TIERS.md`, เอกสารอ้างอิงสภาพแวดล้อม, จำนวนนับใน README, ไฟล์สะท้อน (Mirrors) ของ `llm.txt`, การทดสอบเฉพาะและ Golden Snapshots, ความเห็นในโค้ด, จุดกระสุน (Bullets) ใน CHANGELOG (พร้อมการทำบัญชีแยกประเภท ดูที่ `config/release/changelog-reconciliations.json`), บันทึก GitHub Releases, วิกิ (Wiki), รวมถึง Issue, Discussion และ Pull Request บน GitHub ที่มีเนื้อหาเกี่ยวกับ Provider นั้นๆ (Issue และ Discussion จะถูกลบ; ส่วน Pull Request จะถูกเปลี่ยนชื่อ, แทนที่คำอธิบาย และล็อกเธรด เนื่องจาก GitHub ไม่สามารถลบ Pull Request ได้)
3. **ห้ามนำรายการในหน้านี้กลับมาเพิ่มใหม่อย่างเด็ดขาดโดยไม่มีลายลักษณ์อักษรอนุญาต** ซึ่งรวมถึงการเพิ่ม ID หรือ Alias กลับเข้าไปในแคตตาล็อก Provider ใดๆ, การเพิ่มโดเมนลงใน Executor, การยอมรับ PR ของ Contributor ที่ทำการ "กู้คืน", การเพิ่มกลับเข้าไปในแคตตาล็อกโมเดลฟรี หรือการจัดทำเอกสารวิธีเข้าถึงผ่าน OmniRoute ด้วยตนเอง ให้ปิด PR และ Issue ลักษณะดังกล่าวพร้อมแนบลิงก์มายังหน้านี้
4. **บันทึกข้อมูลในรายการให้น้อยที่สุด** ให้บันทึกเฉพาะสิ่งที่ Reviewer จำเป็นต้องใช้ในการสังเกตเห็นการนำกลับเข้ามาใหม่เท่านั้น ได้แก่ ตัวระบุ (Identifiers), โดเมน, วันที่ และ Pull Request ที่ทำการถอดออก ห้ามอธิบายว่าการเชื่อมต่อเคยทำงานอย่างไร
5. **เกราะป้องกันการถดถอย (Regression Guard) คือ `tests/unit/removed-providers-blocklist.test.ts`** ไฟล์นี้จะล้มเหลวหากมีตัวระบุหรือโดเมนใดๆ ด้านล่างนี้ปรากฏขึ้นอีกครั้งในแคตตาล็อก Provider, แผนผัง Executor หรือแหล่งข้อมูล Provider Registry ให้เพิ่มตัวระบุใหม่ลงในการทดสอบนั้นใน PR เดียวกันกับที่มีการเพิ่มแถวข้อมูลที่นี่

## การเพิ่มรายการ

เมื่อมีคำขอถอดถอนใหม่เข้ามา:

1.  ยืนยันว่าคำขอมาจากผู้ดำเนินการบริการ (ที่อยู่อีเมลฝ่ายสนับสนุนของพวกเขา หรือโดเมนที่พวกเขาควบคุม) และเก็บข้อความไว้เป็นความลับ
2.  ลบการเชื่อมต่อตามรายการตรวจสอบในนโยบายข้อ 2. ใช้ [#12440](https://github.com/diegosouzapw/OmniRoute/pull/12440) เป็นข้อมูลอ้างอิงสำหรับผู้ให้บริการที่ไม่มีคีย์ และ [#10210](https://github.com/diegosouzapw/OmniRoute/pull/10210) สำหรับผู้ให้บริการ API-key ที่มีการเชื่อมต่อที่จัดเก็บไว้ (เพิ่มการย้ายข้อมูล)
3.  เพิ่มหนึ่งแถวลงในตารางด้านบน และเพิ่มตัวระบุลงใน `tests/unit/removed-providers-blocklist.test.ts` ใน PR เดียวกัน
4.  ตอบกลับผู้ดำเนินการเมื่อ PR ถูกรวมแล้ว โดยระบุสิ่งที่ถูกลบออกไป และสิ่งที่ OmniRoute ไม่สามารถเปลี่ยนแปลงได้ (เวอร์ชัน npm และ Docker ที่เผยแพร่ไปแล้ว, ประวัติ git, การแยกโค้ดของบุคคลที่สาม)
