บริการบางรายการเคยถูกรวมเข้ากับ OmniRoute และถูกนำออกในภายหลัง เนื่องจากผู้ที่ดูแล
บริการเหล่านั้นร้องขอ หน้านี้เป็นบันทึกถาวรเกี่ยวกับการนำออกดังกล่าว โดยมีวัตถุประสงค์เพียงเพื่อ
ป้องกันไม่ให้บริการเหล่านั้นถูกนำกลับมาโดยไม่ได้ตั้งใจ กล่าวคือ ผู้มีส่วนร่วมที่พบ fork เก่า, tarball ของ npm
ที่ถูกแคชไว้, issue ที่เก็บถาวร หรือคำขอให้ "กู้คืนผู้ให้บริการ X" ต้องมีแหล่งอ้างอิงเพียงแห่งเดียวที่ระบุว่า **ห้าม
นำกลับมา**

หน้านี้ **ไม่ใช่** รายการบริการที่ยุติการให้บริการหรือเลิกดำเนินการ บริการเหล่านั้นได้รับการติดตามใน
[`FREE_TIERS.md`](FREE_TIERS.md) ("นำออกแล้ว / ไม่มีระดับฟรี") และสามารถกลับมาได้หากบริการ
กลับมาให้บริการอีกครั้ง ส่วนรายการด้านล่างจะกลับมาได้ก็ต่อเมื่อได้รับอนุญาตเป็นลายลักษณ์อักษรจากผู้ดำเนินการที่ระบุไว้ใน
คำขอ และต้องลิงก์หลักฐานการอนุญาตนั้นจากรายการดังกล่าว

## นโยบาย

1. **คำขอให้นำออกจากผู้ดำเนินการบริการจะได้รับการปฏิบัติตามโดยไม่มีการเจรจาต่อรอง** OmniRoute
   ไม่มีความเกี่ยวข้องกับบริการต้นทางใด ๆ เมื่อผู้ดำเนินการบริการร้องขอให้นำการผสานการทำงาน
   ออก ก็ต้องนำออก ไม่ว่าการผสานการทำงานนั้นจะใช้ API อย่างเป็นทางการหรือไม่ก็ตาม
2. **"นำออกแล้ว" หมายถึงทุกส่วนที่ OmniRoute ควบคุม** Executor, รายการใน registry, id และ alias
   ของผู้ให้บริการ, รายการโมเดล, endpoints, environment variables, ไอคอน, การ์ดบน dashboard,
   เอกสารอ้างอิงผู้ให้บริการที่สร้างขึ้น, `FREE_TIERS.md`, เอกสารอ้างอิง environment, จำนวนที่ระบุใน README,
   สำเนา `llm.txt`, การทดสอบเฉพาะและ golden snapshots, ความคิดเห็นในโค้ด, รายการใน CHANGELOG
   (พร้อมการกระทบยอดที่บันทึกไว้ โปรดดู `config/release/changelog-reconciliations.json`),
   บันทึก GitHub Releases, wiki รวมถึง GitHub issues, discussions และ pull requests ที่มี
   ผู้ให้บริการดังกล่าวเป็นหัวข้อ (ลบ issues และ discussions; เปลี่ยนชื่อ pull requests, แทนที่
   คำอธิบาย และล็อกเธรด เนื่องจาก GitHub ไม่สามารถลบ pull requests ได้)
3. **ห้ามนำรายการใดในหน้านี้กลับมาโดยไม่ได้รับอนุญาตเป็นลายลักษณ์อักษร** ซึ่งรวมถึง
   การเพิ่ม id หรือ alias กลับเข้าไปในแค็ตตาล็อกผู้ให้บริการใด ๆ, การเพิ่มโดเมนลงใน executor,
   การยอมรับ PR จากผู้มีส่วนร่วมที่ "กู้คืน" รายการนั้น, การเพิ่มรายการนั้นลงในแค็ตตาล็อกโมเดลฟรี หรือ
   การจัดทำเอกสารวิธีเข้าถึงรายการนั้นผ่าน OmniRoute ด้วยตนเอง ให้ปิด PRs และ issues ดังกล่าวพร้อม
   ลิงก์มายังหน้านี้
4. **เก็บรายละเอียดของรายการให้น้อยที่สุด** บันทึกเฉพาะสิ่งที่ผู้ตรวจสอบต้องใช้เพื่อระบุว่าเป็นการ
   นำกลับมา ได้แก่ identifiers, domains, dates และ pull request ที่ใช้ดำเนินการนำออก
   อย่าอธิบายว่าการผสานการทำงานนั้นทำงานอย่างไร
5. **ตัวป้องกัน regression คือ `tests/unit/removed-providers-blocklist.test.ts`** การทดสอบนี้จะล้มเหลวเมื่อ
   identifier หรือ domain ใด ๆ ด้านล่างปรากฏขึ้นอีกครั้งในแค็ตตาล็อกผู้ให้บริการ, executor map หรือ
   ซอร์สของ provider registry ให้เพิ่ม identifiers ใหม่ลงในการทดสอบดังกล่าวใน PR เดียวกับที่
   เพิ่มแถวในหน้านี้

## การเพิ่มรายการ

เมื่อได้รับคำขอให้นำออกรายการใหม่:

1. ยืนยันว่าคำขอมาจากผู้ดำเนินการบริการ (ที่อยู่ฝ่ายสนับสนุนหรือ
   โดเมนที่พวกเขาควบคุม) และเก็บข้อความดังกล่าวไว้เป็นการส่วนตัว
2. นำการผสานการทำงานออกตามรายการตรวจสอบในนโยบายข้อ 2 ใช้
   [#12440](https://github.com/diegosouzapw/OmniRoute/pull/12440) เป็นข้อมูลอ้างอิงสำหรับ
   ผู้ให้บริการที่ไม่ใช้คีย์ และใช้ [#10210](https://github.com/diegosouzapw/OmniRoute/pull/10210) สำหรับ
   ผู้ให้บริการที่ใช้คีย์ API และมีการเชื่อมต่อที่จัดเก็บไว้ (ให้เพิ่ม migration)
3. เพิ่มหนึ่งแถวลงในตารางด้านบนและเพิ่ม identifiers ลงใน
   `tests/unit/removed-providers-blocklist.test.ts` ภายใน PR เดียวกัน
4. ตอบกลับผู้ดำเนินการเมื่อ merge PR แล้ว โดยระบุสิ่งที่นำออกและสิ่งที่ OmniRoute
   ไม่สามารถเปลี่ยนแปลงได้ (เวอร์ชัน npm และ Docker ที่เผยแพร่ไปแล้ว, ประวัติ git, forks ของบุคคลที่สาม)
