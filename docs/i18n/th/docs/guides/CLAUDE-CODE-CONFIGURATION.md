กำหนดให้ CLI ของ **Claude Code** (`claude`) ชี้ไปยัง OmniRoute — ทั้งแบบภายในเครื่องหรือ VPS ระยะไกล —
พร้อมโปรไฟล์แยกตามโมเดล โดยเลียนแบบการตั้งค่าของ Codex

---

## เริ่มต้นอย่างรวดเร็ว

```bash
# เปิด Claude Code โดยเชื่อมต่อกับ OmniRoute ภายในเครื่อง (ตรวจหาคอนเท็กซ์ที่ใช้งานอยู่โดยอัตโนมัติ)
omniroute launch

# เชื่อมต่อกับ OmniRoute ระยะไกล (หลังจาก `omniroute connect <host>` ขั้นตอนนี้จะเป็นอัตโนมัติ)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# สร้างโปรไฟล์แยกตามโมเดล จากนั้นเปิดใช้งานโปรไฟล์หนึ่ง
omniroute setup-claude            # เขียนไปยัง ~/.claude/profiles/<name>/settings.json
omniroute launch --profile glm52  # Claude Code ที่ใช้ glm/glm-5.2 ผ่าน OmniRoute
```

## วิธีที่ Claude Code เชื่อมต่อกับเกตเวย์

Claude Code สื่อสารผ่าน **Anthropic Messages API** และถูกกำหนดให้ชี้ไปยัง
เอนด์พอยต์แบบกำหนดเองด้วยตัวแปรสภาพแวดล้อม (ไม่มีแฟล็ก `--base-url`):

| ตัวแปร                                       | วัตถุประสงค์                                                                                      |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `ANTHROPIC_BASE_URL`                         | URL รากของเกตเวย์ (Claude Code จะต่อท้ายด้วย `/v1/messages`) **ห้ามมีส่วนต่อท้าย `/v1`**          |
| `ANTHROPIC_AUTH_TOKEN`                       | ส่งเป็น `Authorization: Bearer …` — ใช้โทเค็นการเข้าถึง / API key ของ OmniRoute                   |
| `ANTHROPIC_API_KEY`                          | ทางเลือก: ส่งเป็น `x-api-key` หากกำหนดทั้งสองค่า `ANTHROPIC_AUTH_TOKEN` จะมีลำดับความสำคัญสูงกว่า |
| `ANTHROPIC_MODEL`                            | บังคับใช้โมเดลที่ระบุ (แทนที่ค่าเริ่มต้นของตัวเลือก `/model`)                                     |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` → ตัวเลือก `/model` แบบเนทีฟจะแสดงโมเดล `claude*`/`anthropic*` จาก `/v1/models`               |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`              | จำกัดจำนวนโทเค็นเอาต์พุตต่อการตอบกลับ (เช่น `65536`)                                              |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`            | เกณฑ์จำนวนโทเค็นสำหรับการย่ออัตโนมัติ                                                             |

> ตัวแปรสภาพแวดล้อมจะถูกอ่าน **เพียงครั้งเดียวเมื่อเริ่มต้น** — ให้รีสตาร์ต Claude Code หลังจากเปลี่ยนแปลงค่า

`omniroute launch` จะตั้งค่าทั้งหมดนี้ให้คุณ: คำสั่งนี้จะค้นหา URL ฐานและโทเค็น
จากคอนเท็กซ์ที่ใช้งานอยู่ (ดังนั้นเมื่อใช้ `omniroute connect <vps>` แล้วตามด้วย `omniroute launch`
ก็จะใช้งานได้ทันที) ตรวจสอบสถานะของเซิร์ฟเวอร์ และเรียกใช้ `claude`

## นามแฝงสำหรับการค้นหา — แสดงโมเดลที่ไม่ใช่ Claude ในตัวเลือก `/model`

การค้นหาโมเดลผ่านเกตเวย์ของ Claude Code จะแสดงเฉพาะ ID ที่ขึ้นต้นด้วย `claude`
หรือ `anthropic` ดังนั้นเมื่อใช้ `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` ตัวเลือก
`/model` แบบเนทีฟจึงมักแสดง **เฉพาะ** โมเดล Claude/Anthropic ของ OmniRoute — โมเดลอย่าง
`kimi/kimi-k2.6` หรือ `glm/glm-5.2` จะไม่ปรากฏ แม้ว่าจะกำหนดเส้นทางได้ตามปกติก็ตาม

OmniRoute สามารถสร้างตัวแทนของโมเดลที่เปิดใช้งานอยู่ (รวมถึงคอมโบ) ภายใต้ ID แบบ `claude/…`
เพื่อให้ผ่านตัวกรองดังกล่าวและปรากฏในตัวเลือก:

```
kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<คอมโบ "custo-otimizado"> →  claude/combo/custo-otimizado
```

เมื่อคุณเลือกหนึ่งในรายการเหล่านี้ภายใน Claude Code ทาง OmniRoute จะนำส่วนครอบ `claude/`
ออกให้กลับเป็น ID จริงก่อนกำหนดเส้นทาง — ส่วน ID จริงแบบ `claude/<real-claude-model>`
(ผู้ให้บริการ Claude OAuth จริง) จะไม่ถูกแก้ไขเสมอ

**ฟีเจอร์นี้ปิดอยู่โดยค่าเริ่มต้น** และควบคุมด้วยการตั้งค่าสามระดับ (ค่าที่เฉพาะเจาะจงที่สุด
จะมีผลเหนือกว่า) ดังนั้น OmniRoute แบบปกติจะไม่สร้างรายการในแค็ตตาล็อกซ้ำสำหรับไคลเอนต์ที่ไม่ได้ใช้
Claude Code:

| ระดับ        | ตำแหน่ง                                                                      |
| ------------ | ---------------------------------------------------------------------------- |
| โมเดล        | หน้ารายละเอียดผู้ให้บริการ → สวิตช์ "Expose in Claude Code" แยกตามโมเดล      |
| ผู้ให้บริการ | หน้ารายละเอียดผู้ให้บริการ → สวิตช์ระดับผู้ให้บริการ (ครอบคลุมทุกโมเดล)      |
| ส่วนกลาง     | Settings → Feature Flags → `EXPOSE_CC_DISCOVERY_ALIASES` (ปิดโดยค่าเริ่มต้น) |

ตัวแปรสภาพแวดล้อม `EXPOSE_CC_DISCOVERY_ALIASES` จะบังคับเปิดการตั้งค่าระดับส่วนกลาง
และมีลำดับความสำคัญเหนือการตั้งค่าทับจากแดชบอร์ด (หน้าจอ Feature Flags จะแสดงหมายเหตุ
"active via environment variable" เมื่อมีผล) จากนั้นสามารถปรับให้เฉพาะเจาะจงยิ่งขึ้นด้วยสวิตช์
แยกตามผู้ให้บริการและแยกตามโมเดล — เช่น เมื่อปิดระดับส่วนกลางแต่เปิดผู้ให้บริการ Kimi
ระบบจะแสดงเฉพาะโมเดลของ Kimi

> ⚠️ **ขนาดหน้าต่างไม่ตรงกันสำหรับโมเดลที่ไม่ใช่ Claude** Claude Code จะถือว่า ID ใด ๆ
> ที่ไม่รู้จักมีหน้าต่างคอนเท็กซ์ขนาด 200K (ไม่สามารถอ่านขนาดหน้าต่างจริงจาก
> `/v1/models` ได้) สำหรับโมเดลที่มีหน้าต่างใหญ่กว่า (เช่น 256K ของ Kimi K2) ให้ตั้งค่า
> `CLAUDE_CODE_AUTO_COMPACT_WINDOW` เป็นค่าที่ต่ำกว่าขนาดหน้าต่างจริงของโมเดล เพื่อไม่ให้
> การย่ออัตโนมัติทำงานก่อนเวลาอันควร โปรไฟล์ที่สร้างขึ้นข้างต้นได้ตั้งค่านี้แยกตามโมเดลไว้แล้ว

## บล็อกการเริ่มต้นใช้งานบนแดชบอร์ด

การ์ดเครื่องมือ Claude (**แดชบอร์ด → CLI Code**) จะแสดงส่วนย่อยของ `settings.json` ที่ตรงกับ
อินสแตนซ์นี้ทุกประการ ถัดจากปุ่มข้อมูล discovery-alias พร้อมปุ่มคัดลอก:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<OmniRoute ของคุณ>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<คีย์ OmniRoute API ของคุณ>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}
```

URL ฐานคือ URL ที่การ์ดระบุได้ (รวมถึงค่ากำหนดเองที่คุณป้อน) และผ่านการปรับรูปแบบแล้ว —
ไม่มีส่วนต่อท้าย `/v1` และไม่มีเครื่องหมายทับปิดท้าย **ระบบจะไม่แสดงคีย์จริงโดยเด็ดขาด**:
บล็อกนี้ใช้ข้อความตัวอย่างแทน ดังนั้นภาพหน้าจอหรือส่วนย่อยที่นำไปวางจึงไม่ทำให้คีย์รั่วไหล
ให้วางคีย์ของคุณทับข้อความดังกล่าว

เพิ่ม `CLAUDE_CODE_AUTO_COMPACT_WINDOW` ภายใต้บล็อก `env` เดียวกันสำหรับโมเดลที่มี
ขนาดหน้าต่างบริบทจริงไม่เท่ากับ 200K — Claude Code จะถือว่าทุก id ที่ระบบไม่รู้จักมีขนาด
200K ดังนั้นหากไม่กำหนดค่านี้ การบีบอัดอัตโนมัติจะทำงานผิดจังหวะ (ดูคำเตือนในส่วนก่อนหน้า)
ตัวสร้างส่วนย่อยรองรับค่านี้เช่นกัน ดังนั้นตัวเรียกที่ทราบขนาดหน้าต่างของโมเดลเป้าหมาย
จึงสามารถสร้างค่านี้ได้โดยตรง

แหล่งที่มา: `src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet`
(ตัวสร้างแบบ pure ที่ผ่านการทดสอบระดับหน่วย) ซึ่งแสดงผลโดย `ClaudeGatewayOnboardingBlock`

## โปรไฟล์ (`CLAUDE_CONFIG_DIR`)

Claude Code **ไม่มีไฟล์โปรไฟล์ในตัว** (ต่างจาก `~/.codex/<name>.config.toml` ของ Codex)
กลไกที่ใช้กันตามแบบแผนคือ `CLAUDE_CONFIG_DIR` — ไดเรกทอรีการกำหนดค่าที่แยกกันสำหรับแต่ละ
โปรไฟล์ โดยแต่ละโปรไฟล์มี `settings.json`, ข้อมูลรับรอง, ประวัติ และแคชเป็นของตนเอง

`omniroute setup-claude` จะดึงแค็ตตาล็อก `/v1/models` ปัจจุบันและเขียนหนึ่งโปรไฟล์
ต่อหนึ่งโมเดลไว้ที่ `~/.claude/profiles/<name>/settings.json` โดยใช้
**ชื่อเดียวกับ `setup-codex`** (`glm52`, `kimi-k27`, `deepseek-pro`, …):

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}
```

> **ระบบจะไม่เขียนโทเค็นการยืนยันตัวตนลงในโปรไฟล์โดยเด็ดขาด** เริ่มใช้งานด้วย
> `omniroute launch --profile <name>` (คำสั่งนี้จะแทรก `ANTHROPIC_AUTH_TOKEN` จาก
> บริบทที่ใช้งานอยู่) หรือ export `ANTHROPIC_AUTH_TOKEN` ด้วยตนเองแล้วเรียกใช้
> `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude`

**ซิงค์อัตโนมัติหลังการค้นพบโมเดล (เลือกเปิดใช้ได้)** OmniRoute สามารถสร้างไฟล์
`~/.claude/profiles/<name>/settings.json` ชุดเดิมเหล่านี้ใหม่โดยอัตโนมัติทุกครั้งที่
การซิงค์โมเดลของผู้ให้บริการทำให้แค็ตตาล็อกปัจจุบันเปลี่ยนแปลง — เพื่อให้โมเดลใหม่หรือ
โมเดลที่เปลี่ยนชื่อได้รับโปรไฟล์โดยไม่ต้องเรียกใช้คำสั่งอีกครั้ง คุณสมบัตินี้
**ปิดอยู่โดยค่าเริ่มต้น**: เปิดได้จาก **แดชบอร์ด CLI Code** ("ซิงค์โปรไฟล์ CLI อัตโนมัติ"
→ Claude Code) หรือตั้งค่า `OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true` (และยังเคารพค่า
`CLI_ALLOW_CONFIG_WRITES` ซึ่งเปิดอยู่โดยค่าเริ่มต้น) เมื่อเปิดใช้ ระบบจะเขียนเฉพาะไฟล์
โปรไฟล์เท่านั้น โดยจะไม่เปลี่ยนการกำหนดค่า Claude ที่ใช้งานอยู่/ค่าเริ่มต้น ข้อมูลการยืนยัน
ตัวตน หรือ `~/.claude/settings.json`

### การสร้างและใช้งานโปรไฟล์

```bash
# OmniRoute ภายในเครื่อง
omniroute setup-claude

# VPS ระยะไกล (ฝัง URL ของ VPS ลงในทุกโปรไฟล์)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# เฉพาะผู้ให้บริการบางราย
omniroute setup-claude --only glm,kimi

# แสดงตัวอย่างโดยไม่เขียนไฟล์
omniroute setup-claude --dry-run

# เริ่มใช้งานโปรไฟล์
omniroute launch --profile kimi-k27
```

## ระดับโมเดล (ไม่บังคับ)

Claude Code จะกำหนดเส้นทางไปยังระดับความสามารถต่าง ๆ คุณสามารถแมปแต่ละระดับกับโมเดล OmniRoute ผ่าน env /
การตั้งค่าได้ หากต้องการใช้ผู้ให้บริการที่แตกต่างกันในแต่ละระดับ:

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm/glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="kmc/kimi-k2.6"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="glm/glm-4.7-flash"
```

มิฉะนั้น ระบบจะใช้ `ANTHROPIC_MODEL` รายการเดียว (ที่โปรไฟล์กำหนดไว้) สำหรับทุกอย่าง

## โหมดระยะไกล

เมื่อคุณเรียกใช้ `omniroute connect <host>` แล้ว (ดู
[โหมดระยะไกล](./REMOTE-MODE.md)) `omniroute launch` และ `omniroute setup-claude`
จะกำหนดเป้าหมายไปยังเซิร์ฟเวอร์ระยะไกลนั้นโดยอัตโนมัติ และใช้โทเค็นการเข้าถึงที่จำกัดขอบเขตของเซิร์ฟเวอร์ — ไม่
จำเป็นต้องใช้แฟล็กเพิ่มเติม คุณสามารถเขียนทับเป็นรายคำสั่งได้ด้วย `--remote` / `--api-key`

## การแก้ไขปัญหา

**Claude Code ไม่ใช้เกตเวย์** — ตรวจสอบว่า `ANTHROPIC_BASE_URL` **ไม่มี
`/v1`** และรีสตาร์ต `claude` (ระบบจะอ่าน env เพียงครั้งเดียวเมื่อเริ่มทำงาน) `omniroute launch`
จะจัดการเรื่องนี้ให้คุณ

**ตัวเลือก `/model` ว่างเปล่า / ไม่มีโมเดลของเกตเวย์** — ต้องใช้ Claude Code
v2.1.219+ และ `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` เฉพาะ ID โมเดล `claude*` /
`anthropic*` เท่านั้นที่จะแสดงในตัวเลือก หากต้องการบังคับใช้โมเดลอื่น ให้ใช้
`ANTHROPIC_MODEL=<id>` (นี่คือสิ่งที่โปรไฟล์ทำ)

**`400 Ambiguous model 'claude-…'`** — Claude Code จะส่ง ID โมเดลแบบ **ไม่มีคำนำหน้า**
เสมอ (เช่น `claude-opus-4-8`) ดังนั้นเมื่อเชื่อมต่อทั้งผู้ให้บริการ Claude Code (`cc/…`) และ
Claude (`claude/…`) แล้ว ID ที่ไม่มีคำนำหน้าจะตรงกับสองเส้นทาง และ
OmniRoute จะไม่คาดเดาให้ แก้ไขได้สองวิธี: ระบุ ID ที่มีคำนำหน้าด้วย
`ANTHROPIC_MODEL=cc/claude-opus-4-8` หรือเปิดใช้ **เลือก Claude Code ก่อน
สำหรับโมเดล Claude ที่ไม่มีคำนำหน้า** — ใช้สวิตช์ในหน้าผู้ให้บริการ Claude หรือ
`OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true` (ปิดไว้โดยค่าเริ่มต้น;
ดู [สภาพแวดล้อม](../reference/ENVIRONMENT.md)) — ซึ่งจะกำหนดเส้นทาง ID `claude-*`
ที่ไม่มีคำนำหน้าไปยัง Claude Code แทน คำนำหน้าผู้ให้บริการที่ระบุไว้อย่างชัดเจนจะมีลำดับความสำคัญสูงสุดเสมอ

**ข้อผิดพลาดด้านการยืนยันตัวตน** — โปรไฟล์ไม่มีโทเค็น ให้ใช้ `omniroute launch --profile`
(เพื่อแทรกโทเค็น) หรือ export `ANTHROPIC_AUTH_TOKEN`

**โปรไฟล์ไม่แยกจากกัน** — แต่ละโปรไฟล์ใช้ `CLAUDE_CONFIG_DIR` ที่แตกต่างกัน;
ตรวจสอบว่า `echo $CLAUDE_CONFIG_DIR` ภายในเซสชันชี้ไปที่
`~/.claude/profiles/<name>`
