OmniRoute ประเมิน บันทึก และรายงานค่าใช้จ่ายของทุกคำขออย่างไร — และเหตุใดตัวเลขบน
แดชบอร์ดจึงเป็น **ตัวติดตามการประหยัด** ไม่ใช่ใบเรียกเก็บเงิน

ดูเพิ่มเติม: [คู่มือผู้ใช้](./USER_GUIDE.md) · [แกลเลอรีฟีเจอร์](./FEATURES.md)

## สิ่งนี้คืออะไร (และไม่ใช่อะไร)

OmniRoute ระบุค่าใช้จ่ายเป็น USD ต่อคำขอให้กับทุก completion โดยนำจำนวนโทเค็น
มาคูณกับอัตราราคาของโมเดล ตัวเลขเหล่านี้ใช้ขับเคลื่อนแดชบอร์ด **ค่าใช้จ่าย**
CLI `omniroute cost` / `omniroute usage` การส่งออก CSV/JSON และงบประมาณต่อ API key

> **"ค่าใช้จ่าย" บนแดชบอร์ดคือตัวติดตามการประหยัด ไม่ใช่ใบเรียกเก็บเงิน** OmniRoute ไม่เคยเรียกเก็บเงินจากคุณ
> — แต่จะกำหนดเส้นทางคำขอของคุณไปยังผู้ให้บริการที่คุณเชื่อมต่อไว้แล้ว (การสมัครใช้งาน
> แพ็กเกจฟรี และ API key ของคุณเอง) หากมี "ค่าใช้จ่ายรวม $290" ที่เกิดจากโมเดลฟรีทั้งหมด
> นั่นหมายความว่าโดยประมาณคุณ **ไม่ได้จ่ายเงิน $290** ให้กับ API แบบชำระเงิน ตัวเลขดังกล่าวเป็น
> _ค่าประมาณ_ ว่าทราฟฟิกเดียวกันนี้จะมีค่าใช้จ่ายเท่าใดตามราคามาตรฐาน เพื่อให้คุณเห็นว่า
> การใช้งานของคุณกระจุกตัวอยู่ที่ใด และการกำหนดเส้นทางไปยังผู้ให้บริการที่ราคาถูกกว่า/ฟรีช่วยประหยัดเงินให้คุณได้มากเพียงใด

กรอบแนวคิดนี้ระบุไว้อย่างชัดเจนใน [README](../../README.md) ของโปรเจกต์ ("'ค่าใช้จ่าย'
บนแดชบอร์ดคือตัวติดตามการประหยัด ไม่ใช่ใบเรียกเก็บเงิน")

เนื่องจากตัวเลขนี้เป็นค่าประมาณ:

- ตัวเลขจะขึ้นอยู่กับตารางราคาที่ OmniRoute มีสำหรับแต่ละโมเดล โมเดลที่ไม่มีรายการราคา
  จะมีค่าใช้จ่าย `0` (แสดงเป็นแถว "รุ่นเก่า / ฟรี" ในเครื่องมือสำรวจ)
- ทราฟฟิกจากแพ็กเกจฟรีและการสมัครใช้งานยังคงสะสมค่าใช้จ่าย _โดยประมาณ_ — ซึ่งก็คือ
  จำนวนเงินที่คุณประหยัดได้ ไม่ใช่จำนวนเงินที่ต้องชำระ

## วิธีประเมินค่าใช้จ่าย

### แหล่งที่มาของราคา

ค่าใช้จ่ายมาจากตารางราคาที่พิจารณาตามลำดับความสำคัญดังต่อไปนี้
([`src/lib/pricingSync.ts`](../../src/lib/pricingSync.ts)):

1. **ค่าที่ผู้ใช้กำหนดแทน** — ราคาที่คุณตั้งค่าในแดชบอร์ด / ผ่าน `PATCH /api/pricing`
2. **ราคาภายนอกที่ซิงค์แล้ว** — ดึงมาจาก
   `model_prices_and_context_window.json` แบบสาธารณะของ LiteLLM เมื่อเปิดใช้งานการซิงค์ (จัดเก็บไว้ใน namespace
   `pricing_synced` แยกต่างหาก เพื่อไม่ให้เขียนทับค่าที่คุณกำหนดไว้)
3. **ค่าเริ่มต้นที่ฮาร์ดโค้ดไว้** — มาพร้อมกับ OmniRoute

การซิงค์ราคาภายนอกเป็นแบบ **เลือกเปิดใช้** และปิดใช้งานโดยค่าเริ่มต้น env var ที่เกี่ยวข้อง
(ดู [`.env.example`](../../.env.example)):

| Env var                 | ค่าเริ่มต้น | วัตถุประสงค์                                                      |
| ----------------------- | ----------- | ----------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`     | เปิดใช้งานการซิงค์ราคา LiteLLM ในเบื้องหลังเมื่อเริ่มต้นระบบ      |
| `PRICING_SYNC_INTERVAL` | `86400`     | ช่วงเวลาการซิงค์เป็น **วินาที** (ค่าเริ่มต้นคือวันละครั้ง)        |
| `PRICING_SYNC_SOURCES`  | `litellm`   | รายการแหล่งที่มาที่คั่นด้วยจุลภาค (ปัจจุบันรองรับเฉพาะ `litellm`) |

### สูตรคำนวณค่าใช้จ่าย

ค่าใช้จ่ายจะคำนวณต่อคำขอจากจำนวนโทเค็นและอัตราราคาต่อหนึ่งล้านโทเค็นใน
[`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts)
(`computeCostFromPricing` / `calculateCost`):

- **โทเค็นอินพุต** (หักการอ่านแคชและโทเค็นสำหรับสร้างแคช) × อัตรา `input`
- **โทเค็นที่อ่านจากแคช** × อัตรา `cached` (หากไม่มีจะใช้อัตราอินพุตแทน)
- **โทเค็นสำหรับสร้างแคช** × อัตรา `cache_creation` (หากไม่มีจะใช้อัตราอินพุตแทน)
- **โทเค็นเอาต์พุต** × อัตรา `output`
- **โทเค็นการให้เหตุผล** × อัตรา `reasoning` (หากไม่มีจะใช้อัตราเอาต์พุตแทน)

อัตราทั้งหมดตีความเป็น USD ต่อ 1,000,000 โทเค็น ระดับบริการ "fast"/"priority" หรือ
"flex" ของ Codex จะใช้ตัวคูณค่าใช้จ่าย (`getCodexFastCostMultiplier`) — เช่น flex
คิดค่าบริการโดยให้ส่วนลดค่าโทเค็น 50% ซึ่งแสดงบนแดชบอร์ดเป็น **การประหยัดจาก flex**

ชื่อโมเดลจะได้รับการปรับให้อยู่ในรูปแบบมาตรฐานก่อน (โดยตัดคำนำหน้าพาธของผู้ให้บริการ เช่น `openai/` หรือ
`accounts/fireworks/models/` ออก) เพื่อให้แถวข้อมูลย้อนหลังยังคงจับคู่กับราคาได้

### วิธีบันทึกค่าใช้จ่าย

- ค่าใช้จ่ายต่อคำขอจะคำนวณหลังจากได้รับการตอบกลับ และบันทึกแบบ fire-and-forget เพื่อไม่ให้
  เพิ่มเวลาแฝงแก่ไคลเอนต์ การใช้โควตาร่วมจะถูกกำหนดเวลาไว้ใน tick ถัดไปของ event loop
  ผ่าน [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts)
- ค่าใช้จ่ายของ API key จะถูกบัฟเฟอร์และเขียนเป็นชุดโดย
  [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (ช่วงเวลาการเขียนค่าเริ่มต้น 60 วินาที
  บัฟเฟอร์ 1,000 รายการ) ปรับแต่งได้ผ่าน:

  | Env var                             | ค่าเริ่มต้น | วัตถุประสงค์                             |
  | ----------------------------------- | ----------- | ---------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000`     | ช่วงเวลาการเขียนข้อมูลเป็นมิลลิวินาที    |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`      | จำนวนรายการสูงสุดที่บัฟเฟอร์ไว้ก่อนเขียน |

ตัวเลขค่าใช้จ่ายบนแดชบอร์ด **ไม่ได้** อ่านมาจากจำนวนเงินดอลลาร์ต่อแถวที่จัดเก็บไว้ — แต่จะ
คำนวณใหม่แบบทันทีจากจำนวนโทเค็นและตารางราคาปัจจุบันทุกครั้งที่ endpoint การวิเคราะห์ทำงาน
ซึ่งหมายความว่าการแก้ไขราคาที่ไม่ถูกต้อง (และซิงค์ใหม่) จะอัปเดตค่าประมาณค่าใช้จ่ายในอดีตย้อนหลัง

## แดชบอร์ด: หน้า Costs

หน้า **Costs** อยู่ที่ `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`)
มุมมองหลักคือแท็บ **Cost Overview**
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`)
ซึ่งโหลดข้อมูลทั้งหมดจาก `GET /api/usage/analytics`

สิ่งที่แสดง:

- **การ์ดค่าใช้จ่าย** — ค่าใช้จ่ายโดยประมาณสำหรับ _วันนี้ (1d)_, _7d_, _30d_ และช่วงเวลา
  ที่เลือก ตัวเลือกช่วงเวลา: `7d`, `30d`, `90d`, `all`
- **เมตริกหลัก** — จำนวนคำขอในช่วงเวลา, ผู้ให้บริการที่ใช้งานอยู่, โมเดลที่ใช้งานอยู่ และค่าใช้จ่ายเฉลี่ย
  ต่อคำขอ
- **เครื่องมือสำรวจค่าใช้จ่าย** — ตารางที่จัดเรียง/กรองได้ โดยจัดกลุ่มตาม **ผู้ให้บริการ**, **โมเดล**,
  **คีย์ API**, **บัญชี** หรือ **ระดับบริการ** พร้อมค่าใช้จ่าย, จำนวนคำขอ, โทเค็น, ค่าใช้จ่ายเฉลี่ย
  ต่อคำขอ และเปอร์เซ็นต์สัดส่วนของยอดรวม
- **การใช้โทเค็น** — จำนวนโทเค็นทั้งหมด / อินพุต / เอาต์พุต และอัตราส่วนอินพุต:เอาต์พุต
- **ประสิทธิภาพการกำหนดเส้นทาง** — จำนวนการใช้ตัวเลือกสำรอง, อัตราการใช้ตัวเลือกสำรอง และความครอบคลุมของโมเดลที่ร้องขอ
- **การคาดการณ์รายเดือน** — คาดการณ์ค่าใช้จ่าย ณ สิ้นเดือนจากค่าเฉลี่ยรายวันล่าสุด
- **การเปรียบเทียบช่วงเวลา** — เปอร์เซ็นต์การเปลี่ยนแปลงระหว่างครึ่งแรกและครึ่งหลังของช่วงเวลา
- **แผนภูมิ** — แนวโน้มค่าใช้จ่ายรายวัน, สัดส่วนผู้ให้บริการ (แผนภูมิวงกลม), ผู้ให้บริการอันดับต้น ๆ, โมเดลอันดับต้น ๆ, ค่าใช้จ่าย
  ตามคีย์ API, ค่าใช้จ่ายตามบัญชี, รูปแบบการใช้งานรายสัปดาห์ และแผนที่ความร้อนของกิจกรรม
- **ส่งออก** — ดาวน์โหลดข้อมูลของช่วงเวลาปัจจุบันเป็น **CSV** หรือ **JSON** (ปุ่มจะปรากฏ
  เมื่อมีข้อมูลค่าใช้จ่ายที่มากกว่าศูนย์)

เมื่อไม่มีทราฟฟิกที่มีการคิดราคา แถวจะแสดงป้ายกำกับ "Legacy / Free" แทน `$0`
เพื่อสะท้อนโมเดลติดตามการประหยัดค่าใช้จ่าย

### หน้าย่อยที่เกี่ยวข้องใน Costs

พื้นที่ Costs ยังมีหน้าต่อไปนี้ (ทั้งหมดอยู่ภายใต้ `/dashboard/costs/`):

- **การกำหนดราคา** (`/dashboard/costs/pricing`) — ดูและแทนที่ราคาของแต่ละโมเดล (แสดงผล
  แท็บ Pricing ที่ใช้ร่วมกัน)
- **งบประมาณ** (`/dashboard/costs/budget`) — กำหนดขีดจำกัดค่าใช้จ่ายสำหรับแต่ละขอบเขต (แสดงผลแท็บ
  Budget ที่ใช้ร่วมกัน)
- **โควตาที่ใช้ร่วมกัน** (`/dashboard/costs/quota-share`) — พูลโควตาที่ใช้ร่วมกันและมุมมอง
  อัตราการใช้โควตา

## เอ็นด์พอยต์ API

เอ็นด์พอยต์ทั้งหมดนี้ต้องใช้การยืนยันตัวตนสำหรับการจัดการ (loopback/JWT ผ่าน `requireManagementAuth`) เว้นแต่
จะระบุไว้เป็นอย่างอื่น

### การวิเคราะห์การใช้งานและค่าใช้จ่าย

| เมธอด | เอ็นด์พอยต์              | วัตถุประสงค์                                                                                                                                                                           |
| ----- | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET` | `/api/usage/analytics`   | การวิเคราะห์ค่าใช้จ่าย/การใช้งานแบบเต็มรูปแบบ: สรุป, แนวโน้มรายวัน, แยกตามผู้ให้บริการ/โมเดล/คีย์ API/บัญชี/ระดับบริการ คิวรี: `range`, `startDate`, `endDate`, `apiKeyIds`, `presets` |
| `GET` | `/api/usage/utilization` | การใช้โควตาของแต่ละผู้ให้บริการตามช่วงเวลา คิวรี: `range` (`1h`/`24h`/`7d`/`30d`), `provider`                                                                                          |
| `GET` | `/api/usage/history`     | แถวประวัติการใช้งานดิบ                                                                                                                                                                 |
| `GET` | `/api/usage/call-logs`   | บันทึกการเรียกใช้แยกตามคำขอ (โมเดล, โทเค็น, ค่าใช้จ่าย, เวลาแฝง, สถานะ)                                                                                                                |
| `GET` | `/api/usage/quota`       | สถานะโควตาของผู้ให้บริการ                                                                                                                                                              |
| `GET` | `/api/usage/proxy-logs`  | บันทึกคำขอของพร็อกซี                                                                                                                                                                   |

### งบประมาณ

| เมธอด  | เอ็นด์พอยต์              | วัตถุประสงค์                                                                                     |
| ------ | ------------------------ | ------------------------------------------------------------------------------------------------ |
| `GET`  | `/api/usage/budget`      | สรุปค่าใช้จ่าย + ตรวจสอบงบประมาณสำหรับคีย์ API หนึ่งรายการ (ต้องระบุพารามิเตอร์คิวรี `apiKeyId`) |
| `POST` | `/api/usage/budget`      | กำหนดขีดจำกัดรายวัน/รายสัปดาห์/รายเดือนในสกุล USD + เกณฑ์การแจ้งเตือนสำหรับคีย์ API              |
| `GET`  | `/api/usage/budget/bulk` | สรุปงบประมาณจำนวนมากจากหลายคีย์ API                                                              |

> API งบประมาณมีขอบเขตต่อ **คีย์ API** (`apiKeyId`) ขีดจำกัดที่ส่งคืนโดย
> `GET /api/usage/budget` ประกอบด้วย `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`,
> `warningThreshold` และยอดสะสม (`totalCostToday`, `totalCostMonth`, …)

### การกำหนดราคา

| เมธอด    | เอ็นด์พอยต์             | วัตถุประสงค์                                                                                                      |
| -------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/pricing`          | ราคาปัจจุบันที่รวมแล้ว (ผู้ใช้ + ซิงค์แล้ว + ค่าเริ่มต้น) ใช้ `?includeSources=1` เพื่อดูแหล่งที่มาของแต่ละรายการ |
| `PATCH`  | `/api/pricing`          | แทนที่ราคาสำหรับ `{ provider: { model: { input, output, cached, … } } }`                                          |
| `DELETE` | `/api/pricing`          | รีเซ็ตราคาเป็นค่าเริ่มต้น (สามารถจำกัดขอบเขตด้วย `?provider=&model=` ได้)                                         |
| `GET`    | `/api/pricing/defaults` | แสดงอัตราสำรองเริ่มต้นต่อ 1 ล้านหน่วย                                                                             |
| `GET`    | `/api/pricing/models`   | ราคาที่กำหนดคีย์ตามโมเดล                                                                                          |
| `POST`   | `/api/pricing/sync`     | เริ่มการซิงค์ด้วยตนเองจากแหล่งข้อมูลภายนอก (LiteLLM)                                                              |
| `GET`    | `/api/pricing/sync`     | สถานะการซิงค์ปัจจุบัน                                                                                             |
| `DELETE` | `/api/pricing/sync`     | ล้างข้อมูลราคาที่ซิงค์ทั้งหมด                                                                                     |

### เอ็นด์พอยต์อื่น ๆ ที่เกี่ยวข้องกับค่าใช้จ่าย

| เมธอด | เอ็นด์พอยต์                   | วัตถุประสงค์                                                                |
| ----- | ----------------------------- | --------------------------------------------------------------------------- |
| `GET` | `/api/free-tier/summary`      | จำนวนโทเค็นของโมเดลฟรีทั้งหมด จำนวนที่ใช้ในเดือนนี้ และโควตาฟรีที่เหลืออยู่ |
| `GET` | `/api/quota/pools/[id]/usage` | การใช้งานสำหรับพูลโควตาที่ใช้ร่วมกัน                                        |

## CLI

CLI ของ OmniRoute มีคำสั่งสำหรับค่าใช้จ่าย การใช้งาน และการกำหนดราคา (ลงทะเบียนไว้ใน
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs))

### `omniroute cost`

รายงานค่าใช้จ่ายที่รวบรวมจาก `/api/usage/analytics`

```bash
omniroute cost                          # 30 วันที่ผ่านมา จัดกลุ่มตามผู้ให้บริการ
omniroute cost --period 7d              # 7 วันที่ผ่านมา
omniroute cost --group-by model         # จัดกลุ่มตาม provider | model | combo | api-key | day
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

คอลัมน์: กลุ่ม, จำนวนคำขอ, โทเค็นขาเข้า/ขาออก, ค่าใช้จ่าย (USD) และเปอร์เซ็นต์ของยอดรวม ระบบจะแสดงบรรทัดยอดรวมทั้งหมด
ที่ส่วนท้าย (ไม่แสดงเมื่อใช้ `--quiet` หรือ `--output json`)

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # สรุปค่าใช้จ่ายแยกตามผู้ให้บริการ
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# งบประมาณ
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` อ่านข้อมูลจาก `GET /api/pricing/defaults` หากต้องการแก้ไขราคาเฉพาะโมเดล
> ให้ใช้หน้าแดชบอร์ด **การกำหนดราคา** หรือ `PATCH /api/pricing` แทน

## การแก้ไขปัญหา

- **ค่าใช้จ่ายทั้งหมดแสดงเป็น $0 / "Legacy / Free"** โมเดลที่ใช้งานไม่มีรายการราคา
  ให้เปิดใช้การซิงค์ภายนอก (`PRICING_SYNC_ENABLED=true`) และเรียกใช้ `omniroute pricing sync` หรือ
  กำหนดราคาด้วยตนเองผ่านหน้าการกำหนดราคา / `PATCH /api/pricing`
- **ราคาของโมเดลในอดีตไม่ถูกต้อง** แก้ไขราคา (เขียนทับหรือซิงค์ใหม่) — ระบบจะ
  คำนวณค่าใช้จ่ายใหม่จากจำนวนโทเค็นทุกครั้งที่อ่านข้อมูลวิเคราะห์ ดังนั้นค่าประมาณจะได้รับการอัปเดตย้อนหลัง
- **ยอดใช้จ่ายล่าช้ากว่าเวลาจริง** ยอดใช้จ่ายต่อคีย์จะถูกประมวลผลเป็นชุด ให้ลดค่า
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` หากต้องการตัวเลขที่เป็นปัจจุบันมากขึ้น
