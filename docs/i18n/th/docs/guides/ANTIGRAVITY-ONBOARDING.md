## 1. Antigravity เทียบกับ Antigravity CLI (agy)

ผู้ให้บริการทั้งสองรายใช้ **แบ็กเอนด์ Google เดียวกัน** — โดยมีไคลเอนต์ OAuth, การรีเฟรชโทเค็น, เอนด์พอยต์ และบัญชี Google เหมือนกันทั้งหมด สิ่งที่แตกต่างกันคือโมเดลที่คุณมองเห็น

> ดูการเปรียบเทียบอย่างเป็นทางการจาก Google ได้ที่ [ประกาศเปิดตัว Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli)

| ด้าน                   | `antigravity` (IDE)                                     | `agy` (CLI)                                         |
| ---------------------- | ------------------------------------------------------- | --------------------------------------------------- |
| **ผลิตภัณฑ์ Google**   | Antigravity 2.0 / Antigravity IDE                       | Antigravity CLI                                     |
| **แบ็กเอนด์**          | Google Cloud Code API เดียวกัน                          | Google Cloud Code API เดียวกัน                      |
| **OAuth / โทเค็น**     | ไคลเอนต์เดียวกัน การรีเฟรชแบบเดียวกัน                   | ไคลเอนต์เดียวกัน การรีเฟรชแบบเดียวกัน               |
| **แค็ตตาล็อกโมเดล**    | รายการที่คัดสรรไว้แบบคงที่ (กำหนดไว้ตายตัวใน OmniRoute) | ตรวจสอบแบบสดจาก Google ผ่าน `:fetchAvailableModels` |
| **โมเดล Claude**       | Sonnet 4.6, Opus 4.6 (อย่างละ 4 ตัวแปร)                 | Sonnet 4.6, Opus 4.6 (อย่างละ 4 ตัวแปร)             |
| **การตั้งชื่อ Gemini** | ป้ายกำกับที่เข้าใจง่าย (ต่ำ/ปานกลาง/สูง)                | ID ต้นทาง (extra-low/low/agent)                     |
| **โมเดลเพิ่มเติม**     | `gpt-oss-120b-medium`                                   | อาจมีโมเดลเพิ่มเติมจาก Google                       |
| **กรณีใช้งานเริ่มต้น** | การผสานรวมกับ IDE (VS Code, JetBrains)                  | การเข้าถึงผ่าน CLI / API                            |
| **โควตา**              | ใช้ร่วมกับ agy (บัญชี Google เดียวกัน)                  | ใช้ร่วมกับ antigravity (บัญชี Google เดียวกัน)      |

**โมเดลที่พร้อมใช้งาน (ตรวจสอบยืนยันผ่านการทดลองเมื่อ 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (มีระดับการคิดหลากหลาย)
- Claude: Sonnet 4.6, Opus 4.6 (แต่ละโมเดลมีตัวแปร default/low/medium/high)
- อื่นๆ: GPT-OSS 120B Medium
- **Claude Sonnet 5 ไม่พร้อมใช้งาน** — รองรับเฉพาะตัวแปร 4.6 เท่านั้น

**เหตุผลที่แค็ตตาล็อกโมเดลแตกต่างกัน**: CLI ของ Google ได้รับการ "ปรับให้เหมาะสมเพื่อความเร็วและโอเวอร์เฮดต่ำ" และ "ปรับให้ทำงานร่วมกับโมเดล Gemini ได้อย่างเหมาะสม" (ตามบล็อกอย่างเป็นทางการของ Google) ผลิตภัณฑ์ Web/IDE ได้รับการ "ปรับให้เหมาะสมเพื่อความครอบคลุม" CLI ใช้ `:fetchAvailableModels` เพื่อค้นหาโมเดลแบบไดนามิก ขณะที่ IDE ใช้รายการที่คัดสรรไว้แบบคงที่

**ในการใช้งานจริง**: ใช้คำนำหน้า `agy/` สำหรับโมเดล Gemini (เช่น `agy/gemini-3.7-flash-high`) ใช้ `antigravity/` สำหรับรายการที่คัดสรรไว้แบบคงที่ ทั้งสองเชื่อมต่อไปยังแบ็กเอนด์ Google เดียวกัน แต่แสดงรูปแบบการตั้งชื่อโมเดลที่แตกต่างกัน โควตาจะใช้ร่วมกัน — การใช้ผู้ให้บริการรายใดรายหนึ่งจะถูกนับรวมในขีดจำกัดของบัญชี Google เดียวกัน

## 2. Google One AI Pro: ระบบโควตา

> ดูรายละเอียดโควตาอย่างเป็นทางการได้ที่ [เอกสาร Antigravity: แผนบริการ](https://antigravity.google/docs/plans) และดูข้อมูลอัปเดตราคาล่าสุดได้ที่ [การเปลี่ยนแปลงแผนบริการ Antigravity](https://antigravity.google/blog/changes-to-antigravity-plans)

Google Antigravity ใช้ **โควตาแบบสองชั้น** ซึ่งอิงตาม "ปริมาณงานที่ทำ" (น้ำหนักการประมวลผล) ไม่ใช่จำนวนข้อความ

### โควตาสองชั้น

| ชั้น                   | คืออะไร                                  | รอบการรีเฟรช                                                                      |
| ---------------------- | ---------------------------------------- | --------------------------------------------------------------------------------- |
| **รอบ 5 ชั่วโมง**      | โควตา "ปริมาณงานที่ทำ" สำหรับใช้งานทันที | รีเซ็ตเมื่อครบ 5 ชั่วโมงหลังจากคำขอแรกในเซสชัน                                    |
| **โควตาพื้นฐาน 7 วัน** | เพดานสูงสุดรายสัปดาห์                    | หากใช้ถึงขีดจำกัด จะมีผลเหนือการรีเฟรช 5 ชั่วโมง และล็อกจนกว่าจะถึงรอบ 7 วันถัดไป |

**วิธีคำนวณ "ปริมาณงานที่ทำ"**: งานที่ใช้เอเจนต์อย่างหนัก (เช่น "ปรับโครงสร้างทั้ง repository นี้") จะใช้โควตาเร็วกว่างานง่ายๆ มาก (เช่น "แก้ไขฟังก์ชันนี้") ไม่มีแดชบอร์ดแบบเรียลไทม์ที่แสดงปริมาณการใช้งาน

### ระดับแผนบริการ

| AI Pro       | $19.99/mo  | โควตาสูง รีเฟรชแบบต่อเนื่องทุก 5 ชั่วโมง  | มี (มีผลเหนือรอบ 5 ชั่วโมงเมื่อใช้ถึงขีดจำกัด) |

### โมเดล Gemini เทียบกับโมเดลที่ไม่ใช่ Gemini

- **โมเดล Gemini** (Flash + Pro): ใช้ขีดจำกัดอัตราการใช้งานร่วมกัน โดยหักตามราคา API หาก Flash ถูกกว่า Pro 8 เท่า คุณจะได้รับโทเค็น Flash มากกว่า 8 เท่า
- **โมเดลที่ไม่ใช่ Gemini** (Claude, GPT-OSS): มีขีดจำกัดอัตราการใช้งาน **แยกต่างหาก** และอาจยังคงใช้งานได้แม้ Gemini จะถูกล็อก

### เครดิต AI (การใช้งานเกินโควตา)

> ดูวิธีการทำงานของเครดิตได้ที่ [เครดิต Google One AI](https://support.google.com/googleone/answer/14534406)

เมื่อโควตาพื้นฐานหมด:

- **Never**: รอให้โควตารีเฟรช โดยจะแสดงข้อความ "Baseline model quota reached"
- **Always**: ใช้เครดิต AI โดยอัตโนมัติ และเปลี่ยนกลับไปใช้โควตาพื้นฐานเมื่อรีเฟรชแล้ว

ต้องซื้อเครดิตแยกต่างหาก และเครดิตจะถูกหักตามราคา API มาตรฐาน

### รายละเอียดสำคัญ

- โควตา **ใช้ร่วมกันในระดับบัญชี** — บัญชี Google เดียวกันที่ใช้ใน Antigravity IDE, CLI และ OmniRoute จะใช้โควตาจากกลุ่มเดียวกัน
- บัญชี Google แต่ละบัญชีมีโควตาแยกจากกัน — หลายบัญชี = หลายกลุ่มโควตา
- ผู้ใช้ AI Pro รายงานว่าพบการ **ล็อกเป็นเวลา 7 วัน** แทนการรีเซ็ตทุก 5 ชั่วโมงเมื่อใช้โควตาพื้นฐานรายสัปดาห์ถึงขีดจำกัด (Google ยืนยันว่าเป็นการออกแบบโดยตั้งใจเพื่อรองรับความต้องการใช้งานสูง)

**เมื่อโควตาของบัญชีหมด**: OmniRoute จะลองอีกครั้งโดยอัตโนมัติด้วยบัญชีถัดไปที่พร้อมใช้งานในเส้นทางแบบผสม โดยไม่ต้องดำเนินการด้วยตนเอง

## 3. วิธีรับ projectId

การเชื่อมต่อ antigravity/agy ทุกครั้งต้องมี `projectId` ของ Google Cloud Code หากไม่มี endpoint `/v1internal:models` จะส่งคืนสถานะ 404

### วิธี A: อัตโนมัติ (แนะนำ)

OmniRoute จัดการขั้นตอนนี้โดยอัตโนมัติ เมื่อคุณเพิ่มบัญชี Google ใหม่ผ่าน Dashboard OAuth:

1. OmniRoute รีเฟรชโทเค็น
2. เรียก `loadCodeAssist` เพื่อค้นหา projectId
3. หากยังไม่มีโปรเจกต์ จะเรียก `onboardUser` เพื่อสร้างโปรเจกต์
4. ลองเรียก `loadCodeAssist` อีกครั้งเพื่อรับ projectId ที่เพิ่งสร้าง
5. บันทึกลงในฐานข้อมูล

**วิธีนี้ใช้ได้กับบัญชีส่วนใหญ่** — ไม่จำเป็นต้องดำเนินการด้วยตนเอง

### วิธี B: ดำเนินการด้วยตนเองผ่าน agy CLI

หากการค้นหาอัตโนมัติล้มเหลว (ดูกรณีที่อาจเกิดเหตุการณ์นี้ได้ในส่วนที่ 5):

```bash
# ติดตั้ง agy CLI (หากยังไม่ได้ติดตั้ง)
npm install -g @anthropic-ai/agy

# เข้าสู่ระบบด้วยบัญชี Google ของคุณ
agy login

# เลือกบัญชีที่ต้องดำเนินการเริ่มต้นใช้งาน
# ขั้นตอนนี้จะเรียกใช้การลงทะเบียน Cloud Code และกำหนด projectId
```

หลังจาก `agy login` สำเร็จ ให้รีเฟรชโทเค็นใน OmniRoute Dashboard ระบบจะค้นพบ projectId โดยอัตโนมัติ

### วิธีตรวจสอบ

ตรวจสอบฐานข้อมูล:

```bash
# ภายในคอนเทนเนอร์ OmniRoute
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

หรือตรวจสอบบันทึก:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. URI การเปลี่ยนเส้นทาง OAuth

### ปัญหา

Google OAuth ต้องใช้ URI การเปลี่ยนเส้นทางที่ถูกต้อง ค่าเริ่มต้นของ OmniRoute ใช้ `http://127.0.0.1:20128/callback` (ลูปแบ็ก) วิธีนี้ใช้ได้กับบิลด์ภายในเครื่อง แต่ **ใช้ไม่ได้กับการติดตั้งใช้งานระยะไกล** (เช่น เซิร์ฟเวอร์ที่เข้าถึงผ่าน IP ของ LAN)

Google จะปฏิเสธ URI การเปลี่ยนเส้นทางที่:

- ใช้ที่อยู่ IP (ต้องเป็นโดเมนที่ลงท้ายด้วย `.com`, `.org` เป็นต้น)
- ไม่ตรงกับ URI การเปลี่ยนเส้นทางที่ลงทะเบียนไว้ในการกำหนดค่าไคลเอนต์ OAuth

### วิธีแก้ไข

**ตัวเลือก A: ใช้โฟลว์ OAuth ในตัว (ค่าเริ่มต้น)**

- ใช้ได้เมื่อคุณเข้าถึง OmniRoute จาก `localhost` หรือ `127.0.0.1`
- ไม่จำเป็นต้องกำหนดค่า

**ตัวเลือก B: ข้อมูลประจำตัว OAuth แบบกำหนดเอง**

- ตั้งค่า `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` ในสภาพแวดล้อมของคุณ
- ระบุข้อมูลประจำตัว Google OAuth ของคุณเอง:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- ลงทะเบียน `https://your-domain.com/callback` เป็น URI การเปลี่ยนเส้นทางที่ได้รับอนุญาตใน Google Cloud Console

**ตัวเลือก C: ใช้ agy CLI สำหรับการเข้าสู่ระบบครั้งแรก**

- เรียกใช้ `agy login` บนเครื่องที่จะใช้เข้าถึง OmniRoute
- โฟลว์ OAuth จะเสร็จสมบูรณ์ภายในเครื่องและโทเค็นจะถูกจัดเก็บ
- นำเข้าการเชื่อมต่อไปยัง OmniRoute ผ่านแดชบอร์ด

### ข้อจำกัด

- ข้อมูลประจำตัว OAuth แบบกำหนดเองต้องใช้ชื่อโดเมน (Google ไม่ยอมรับที่อยู่ IP เป็น URI การเปลี่ยนเส้นทาง)
- หากคุณไม่มีโดเมน ให้ใช้ตัวเลือก A หรือ C แทน

## 5. การแก้ไขปัญหา: เมื่อการตั้งค่าอัตโนมัติล้มเหลว

OmniRoute จัดการการค้นหา projectId และการเริ่มต้นใช้งานโดยอัตโนมัติสำหรับบัญชีส่วนใหญ่ เมื่อกระบวนการล้มเหลว สาเหตุหลักมักเป็นหนึ่งในกรณีต่อไปนี้:

### ภูมิภาคของบัญชีถูกบล็อก

**อาการ**: `agy login` แสดงข้อความ "การตรวจสอบสิทธิ์ล้มเหลว: บัญชีปัจจุบันของคุณไม่มีสิทธิ์ใช้งาน Antigravity เนื่องจากยังไม่พร้อมให้บริการในตำแหน่งที่ตั้งของคุณ"

**สาเหตุหลัก**: บัญชี Google มีฟิลด์ "Country Association" ในระบบแบ็กเอนด์ ซึ่งถูกกำหนดไว้ขณะลงทะเบียน agy CLI และ Cloud Code API จะตรวจสอบฟิลด์นี้อย่างเข้มงวด ซึ่งแตกต่างจาก Gemini บนเว็บที่ตรวจสอบเฉพาะ IP ปัจจุบันของคุณ

> หากต้องการตรวจสอบหรือเปลี่ยนภูมิภาคที่เชื่อมโยงกับบัญชีของคุณ โปรดไปที่ [แบบฟอร์มการเชื่อมโยงประเทศของ Google](https://policies.google.com/country-association-form)

**เหตุผลที่ Gemini บนเว็บใช้งานได้ แต่ agy ใช้งานไม่ได้**:

- Gemini บนเว็บ / Google One: ตรวจสอบเฉพาะ IP ปัจจุบัน (พร็อกซีช่วยให้ผ่านได้)
- agy CLI / Cloud Code API: อ่านฟิลด์ Country Association ในระบบแบ็กเอนด์ (พร็อกซีไม่ช่วย)

**วิธีแก้ไข**:

1. ไปที่ [แบบฟอร์มการเชื่อมโยงประเทศของ Google](https://policies.google.com/country-association-form) ขณะใช้ IP ของสหรัฐอเมริกา
2. ส่งคำขอเปลี่ยนภูมิภาค (เลือก "ฉันอาศัยอยู่ในประเทศอื่น")
3. รอ 1-24 ชั่วโมงเพื่อให้ Google ดำเนินการและส่งอีเมลแจ้งเตือน
4. จากนั้น `agy login` ควรทำงานสำเร็จ

### บัญชีไม่มีโปรเจกต์ Cloud Code

**อาการ**: บันทึกแสดง `loadCodeAssist returned no project id` และ `onboardUser failed (400)`

**สาเหตุหลัก**: บัญชีไม่เคยลงทะเบียนกับ Google Cloud Code และการเริ่มต้นใช้งานอัตโนมัติล้มเหลว

**วิธีแก้ไข**: เรียกใช้ `agy login` ด้วยตนเองเพื่อเริ่มการลงทะเบียน Cloud Code จากนั้นรีเฟรชโทเค็นในแดชบอร์ด OmniRoute

### โทเค็นหมดอายุหรือถูกเพิกถอน

**อาการ**: พบข้อผิดพลาด 401 ในบันทึก หรือข้อความ "โทเค็นหมดอายุแล้ว"

**วิธีแก้ไข**: รีเฟรชโทเค็นในแดชบอร์ด → ผู้ให้บริการ → agy → คลิกไอคอนรีเฟรช หากรีเฟรชโทเค็นถูกเพิกถอนด้วย คุณจะต้องยืนยันตัวตนอีกครั้งผ่าน OAuth
