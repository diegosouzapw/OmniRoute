OmniRoute มีวิธีใช้ OpenAI Codex **สอง** วิธี:

| ผู้ให้บริการ           | วิธีสื่อสารกับ OpenAI                                                                                                                                                                          | ข้อควรระวังในการใช้งาน                                                  |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| **`codex`**            | ส่งโทเค็น OAuth ของ ChatGPT/OpenAI ของคุณซ้ำไปยัง Responses API โดยตรง                                                                                                                         | **มี** — เซสชันอย่างเป็นทางการไม่ได้รับอนุญาตให้ใช้ผ่านพร็อกซี/เราเตอร์ |
| **`codex-app-server`** | ควบคุม **`codex app-server` ของ Codex CLI เอง** ผ่าน JSON-RPC/WebSocket โดย CLI จะเป็นเจ้าของและรีเฟรช OAuth ของตนเอง (`~/.codex/auth.json`) โดยอัตโนมัติ เช่นเดียวกับเซสชัน `codex` แบบโต้ตอบ | **ไม่มี** — OmniRoute ไม่เคยส่งโทเค็นซ้ำไปยัง API                       |

เนื่องจาก `codex-app-server` ไม่เคยส่งโทเค็นซ้ำ จึงไม่มีข้อควรระวังในการใช้งาน
เกี่ยวกับการส่งเซสชันซ้ำ แต่จำเป็นต้องมี **Codex CLI ที่เข้าถึงได้ผ่าน
URL ของ app-server ที่กำหนดค่าไว้** และ CLI นั้นต้อง **ลงชื่อเข้าใช้แล้ว**

## 1. สถาปัตยกรรม

```
┌─ แอป OmniRoute ─────────────────┐        ┌─ ไซด์คาร์ codex-app-server ─────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ โทเค็นความสามารถ)            │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  จัดการ OpenAI OAuth ด้วยตนเอง      │
└──────────────────────────────────┘        │  (~/.codex/auth.json, รีเฟรชอัตโนมัติ) │
        │ ใช้ร่วมกัน (วอลุ่ม compose)        └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → โทเค็นความสามารถของ WS (ทั้งสองฝั่งเมานต์วอลุ่มนี้)
  codex-appserver-home    → ~/.codex (แดชบอร์ดเขียน auth.json
                             และ codex app-server ของไซด์คาร์อ่านไฟล์นี้)
```

- ไซด์คาร์รับฟัง **เฉพาะ** บนเครือข่าย compose ภายใน
  (`ws://codex-app-server:1456`) โดยมีโทเค็นความสามารถป้องกันอยู่ และจะ **ไม่**
  ถูกเผยแพร่ไปยังโฮสต์หรืออินเทอร์เน็ต
- Codex CLI รวมอยู่ใน `omniroute:base` แล้ว ดังนั้นจึงไม่จำเป็นต้องติดตั้ง codex
  บนโฮสต์หรือเครื่องของผู้ใช้เมื่อคุณเรียกใช้ไซด์คาร์

## 2. เริ่มระบบ

```bash
# เริ่มสแตกพร้อมโปรไฟล์ไซด์คาร์ codex app-server:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

ไซด์คาร์จะสร้างโทเค็นความสามารถของ WS เมื่อบูตครั้งแรก (ลงในวอลุ่ม
`codex-appserver-token` ที่ใช้ร่วมกัน) และแอปจะอ่านโทเค็นเดียวกันผ่าน
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE` โดยไม่จำเป็นต้องเชื่อมโยงโทเค็นด้วยตนเอง

## 3. เชื่อมต่อ + ลงชื่อเข้าใช้

1. ในแดชบอร์ด ให้เพิ่มการเชื่อมต่อสำหรับ **OpenAI Codex (App-Server)** โดยไม่ต้องใช้
   คีย์ API หรือโทเค็น (เป็นผู้ให้บริการที่ไม่ต้องมีการยืนยันตัวตน — ไซด์คาร์เป็นผู้จัดการการยืนยันตัวตน)
2. หาก Codex CLI ของไซด์คาร์ **ยังไม่ได้ลงชื่อเข้าใช้** การตรวจสอบสถานะการเชื่อมต่อ
   จะรายงานว่า _"กำลังทำงานแต่ยังไม่ได้ลงชื่อเข้าใช้"_ (ไม่ใช่ข้อผิดพลาดการยืนยันตัวตนสีแดง) ให้ใช้
   **ลงชื่อเข้าใช้ด้วย ChatGPT**: การดำเนินการนี้จะเรียกใช้ device-OAuth มาตรฐานของ Codex
   ในเบราว์เซอร์ของคุณ จากนั้นเขียน `~/.codex/auth.json` ลงในวอลุ่มที่ใช้ร่วมกันผ่าน
   **ใช้ข้อมูลการยืนยันตัวตน** (การลงชื่อเข้าใช้เพียงครั้งเดียวกันนี้ใช้ได้กับทั้งผู้ให้บริการ `codex` และ
   `codex-app-server`)
3. เมื่อลงชื่อเข้าใช้แล้ว การตรวจสอบสถานะจะเปลี่ยนเป็นสีเขียว (โดยตรวจสอบทั้ง `/readyz` **และ**
   `account/read` — กล่าวคือ ทั้งทำงานอยู่ _และ_ ยืนยันตัวตนแล้ว) และเริ่มทำงานได้

แดชบอร์ดจะไม่เขียนทับ `~/.codex/auth.json` ที่มีอยู่และใช้งานได้ — โดยจะเขียน
เฉพาะเมื่อไม่มีไฟล์หรือโทเค็นในไฟล์หมดอายุแล้วเท่านั้น (มีการสำรองข้อมูลไว้เสมอ)

## 4. รูปแบบการติดตั้งใช้งาน

- **ผู้ดูแลระบบที่มี Codex CLI ซึ่งยืนยันตัวตนแล้ว** — เมานต์ `~/.codex`
  ของโฮสต์เข้าในไซด์คาร์ (`codex-appserver-home`) และข้ามขั้นตอนการลงชื่อเข้าใช้
- **ผู้ใช้ทั่วไปที่ไม่ได้ติดตั้ง codex ไว้ในเครื่อง** — ไม่มีผล: ไซด์คาร์มี
  CLI อยู่แล้ว ผู้ใช้เพียงยืนยันตัวตนผ่านแดชบอร์ด
- **OmniRoute บนเครื่องโดยตรง (ไม่มีไซด์คาร์ ใช้ codex ของโฮสต์)** — กำหนดให้
  `OMNIROUTE_CODEX_APPSERVER_WS` ชี้ไปยัง `codex app-server` ของคุณเอง และตรวจสอบว่า
  codex บนโฮสต์ลงชื่อเข้าใช้แล้ว คำแนะนำ "ไม่ได้ติดตั้ง codex" จะปรากฏขึ้นหากไม่มี
  ไบนารี

## 5. การส่งทราฟฟิกขาออกผ่านเครือข่ายที่พักอาศัย / UDP (ส่วนเสริมสำหรับผู้ดูแลระบบ ไม่ได้รวมมาให้)

ไซด์คาร์ทั่วไปข้างต้นจะส่งทราฟฟิกขาออกผ่านเครือข่ายปกติของคอนเทนเนอร์ ผู้ดูแลระบบ
ที่ต้องการให้ทราฟฟิกของ Codex ออกผ่าน **จุดออกของเครือข่ายที่พักอาศัย** (เช่น ไซด์คาร์
tailscale แบบ TUN ที่รองรับ TCP + UDP/QUIC) จะเรียกใช้ส่วนดังกล่าวเป็น compose
override แยกต่างหาก โดยตั้งใจ **ไม่** รวมไว้ในโปรไฟล์ `codex-app-server`
ที่จัดส่งมาให้ โปรดดูคู่มือปฏิบัติการภายในสำหรับการตั้งค่านี้
