## 🎯 กรณีการใช้งาน

### กรณีที่ 1: "ฉันมีการสมัครสมาชิก Claude Pro"

**ปัญหา:** โควตาหมดอายุโดยไม่ได้ใช้งาน และติดข้อจำกัดอัตราการใช้งานระหว่างเขียนโค้ดหนัก

```
ชุดผสม: "maximize-claude"
  1. cc/claude-opus-4-7        (ใช้สิทธิ์การสมัครสมาชิกอย่างเต็มที่)
  2. glm/glm-4.7               (ตัวสำรองราคาประหยัดเมื่อโควตาหมด)
  3. if/qwen3.8-max-preview       (ตัวสำรองฉุกเฉินฟรี)

ค่าใช้จ่ายรายเดือน: $20 (ค่าสมัครสมาชิก) + ~$5 (ตัวสำรอง) = รวม $25
เทียบกับ $20 + การติดข้อจำกัด = ความหงุดหงิด
```

### กรณีที่ 2: "ฉันไม่ต้องการเสียค่าใช้จ่ายเลย"

**ปัญหา:** ไม่สามารถจ่ายค่าสมัครสมาชิกได้ แต่ต้องการ AI สำหรับเขียนโค้ดที่เชื่อถือได้

```
ชุดผสม: "zero-cost"
  1. if/kimi-k2.7-code          (ระบุว่าเข้าถึงได้ฟรี แต่อาจมีข้อจำกัดอัตราการใช้งาน)
  2. kr/qwen3-coder-next        (ตัวสำรอง Kiro ฟรี)

ค่าใช้จ่ายรายเดือน: $0
คุณภาพ: ตรวจสอบโมเดล ข้อจำกัด ความเป็นส่วนตัว และ SLA ให้เหมาะกับเวิร์กโหลดของคุณ
```

### กรณีที่ 3: "ฉันต้องการเขียนโค้ดได้ตลอด 24/7 โดยไม่สะดุด"

**ปัญหา:** มีเส้นตายและไม่สามารถยอมรับช่วงเวลาที่ระบบหยุดให้บริการได้

```
ชุดผสม: "always-on"
  1. cc/claude-opus-4-7        (คุณภาพดีที่สุด)
  2. cx/gpt-5.5                (การสมัครสมาชิกรายการที่สอง)
  3. glm/glm-4.7               (ราคาประหยัด รีเซ็ตทุกวัน)
  4. minimax/MiniMax-M2.1      (ถูกที่สุด รีเซ็ตทุก 5 ชม.)
  5. if/deepseek-v4-flash       (ระบุว่าเข้าถึงได้ฟรี แต่อาจมีข้อจำกัดอัตราการใช้งาน)

ผลลัพธ์: ตัวสำรอง 5 ชั้นช่วยเพิ่มความยืดหยุ่น แต่ไม่รับประกันความพร้อมใช้งานของบริการต้นทาง
ค่าใช้จ่ายรายเดือน: $20-200 (ค่าสมัครสมาชิก) + $10-20 (ตัวสำรอง)
```

### กรณีที่ 4: "ฉันต้องการ AI ฟรีใน OpenClaw"

**ปัญหา:** ต้องการผู้ช่วย AI ในแอปรับส่งข้อความโดยไม่มีค่าใช้จ่ายใด ๆ

```
ชุดผสม: "openclaw-free"

  2. if/deepseek-v4-flash       (ระบุว่าเข้าถึงได้ฟรี แต่อาจมีข้อจำกัดอัตราการใช้งาน)
  3. if/kimi-k2.7-code          (ระบุว่าเข้าถึงได้ฟรี แต่อาจมีข้อจำกัดอัตราการใช้งาน)

ค่าใช้จ่ายรายเดือน: $0
เข้าถึงผ่าน: WhatsApp, Telegram, Slack, Discord, iMessage, Signal...
```

## 📖 การตั้งค่าผู้ให้บริการ

หากต้องการเพิ่มการเชื่อมต่อด้วย API key จำนวนมากจากไฟล์ CSV หรือ JSON ให้ใช้ **แดชบอร์ด → ผู้ให้บริการ → นำเข้าจากไฟล์** คอลัมน์เรียงตามตำแหน่ง (`provider,name,apiKey,baseUrl,priority`) โดย `provider` ต้องมีอยู่แล้วในฐานะผู้ให้บริการที่มีการจัดการหรือโหนดที่เข้ากันได้ ดู [การนำเข้าผู้ให้บริการจากไฟล์ CSV หรือ JSON](../providers/CSV-IMPORT.md)

### 🔐 ผู้ให้บริการแบบสมัครสมาชิก

#### Claude Code (Pro/Max)

```bash
แดชบอร์ด → ผู้ให้บริการ → เชื่อมต่อ Claude Code
→ เข้าสู่ระบบด้วย OAuth → รีเฟรชโทเค็นอัตโนมัติ
→ ติดตามโควตาแบบ 5 ชั่วโมง + รายสัปดาห์

โมเดล:
  cc/claude-opus-4-7
  cc/claude-sonnet-4-6
  cc/claude-haiku-4-5-20251001
```


CLI จะโหลด `.env` จาก `~/.omniroute/.env` หรือ `./.env` โดยอัตโนมัติ

### โหมดถาดระบบ

เริ่มต้น OmniRoute ในถาดระบบ:

```bash
omniroute serve --tray
```

คำสั่งจะสิ้นสุดการทำงานหลังจากเซิร์ฟเวอร์และถาดระบบพร้อมใช้งานแล้ว

เซิร์ฟเวอร์จะทำงานต่อไปโดยไม่ต้องเปิดเทอร์มินัลไว้

โหมดถาดระบบรองรับ macOS, Windows และเซสชัน Linux แบบกราฟิก โหมดถาดระบบจะไม่เปิดแดชบอร์ดโดยอัตโนมัติ

ใช้เมนูถาดระบบเพื่อดำเนินการต่อไปนี้:

- เปิดแดชบอร์ด
- เปิด `/dashboard/logs`
- เปลี่ยนการตั้งค่าเริ่มต้นอัตโนมัติ
- หยุด OmniRoute

อย่าใช้ `--tray` ร่วมกับตัวเลือกต่อไปนี้:

- `--daemon`
- `--log`
- `--no-recovery`

โหมดเหล่านี้ต้องใช้การเป็นเจ้าของโปรเซสที่แตกต่างกัน

เปิดใช้งานการเริ่มต้นระบบเมื่อเข้าสู่ระบบเครื่องครั้งถัดไป:

```bash
omniroute autostart enable
```

การเริ่มต้นอัตโนมัติจะใช้โหมดถาดระบบบน macOS, Windows และเซสชัน Linux แบบกราฟิก ส่วน Linux แบบไม่มีส่วนติดต่อกราฟิกจะใช้บริการผู้ใช้ systemd ที่มีอยู่

ปิดใช้งานการเริ่มต้นระบบเมื่อเข้าสู่ระบบ:

```bash
omniroute autostart disable
```

### การถอนการติดตั้ง

เมื่อคุณไม่ต้องการใช้ OmniRoute อีกต่อไป เรามีสคริปต์ด่วนสองรายการสำหรับการลบออกอย่างหมดจด:

| คำสั่ง                   | การดำเนินการ                                                             |
| ------------------------ | ------------------------------------------------------------------------ |
| `npm run uninstall`      | ลบแอประบบ แต่ **เก็บฐานข้อมูลและการกำหนดค่าของคุณไว้** ใน `~/.omniroute` |
| `npm run uninstall:full` | ลบแอป และ **ลบการกำหนดค่า คีย์ และฐานข้อมูลทั้งหมดอย่างถาวร**            |

> หมายเหตุ: หากต้องการเรียกใช้คำสั่งเหล่านี้ ให้ไปยังโฟลเดอร์โปรเจกต์ OmniRoute (หากคุณโคลนโปรเจกต์ไว้) แล้วเรียกใช้คำสั่งดังกล่าว หรือหากติดตั้งแบบส่วนกลาง คุณสามารถเรียกใช้ `npm uninstall -g omniroute` ได้โดยตรง

<summary><b>ดูเทมเพลต xbps-src</b></summary>

```bash

pkgname=omniroute
version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"
maintainer="zenobit <zenobit@disroot.org>"
license="MIT"
homepage="https://github.com/diegosouzapw/OmniRoute"
distfiles="https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz"
checksum=009400afee90a9f32599d8fe734145cfd84098140b7287990183dde45ae2245b
system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	# กำหนดสถาปัตยกรรม CPU เป้าหมายสำหรับ node-gyp
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	# 1) ติดตั้งการขึ้นต่อกันทั้งหมด – ข้ามสคริปต์
	NODE_ENV=development npm ci --ignore-scripts

	# 2) สร้างบันเดิล Next.js แบบสแตนด์อโลน
	npm run build

	# 3) คัดลอกแอสเซ็ตแบบสแตติกไปยังสแตนด์อโลน
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	# 4) คอมไพล์ไบนารีไบน์ดิงแบบเนทีฟของ better-sqlite3
	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	# 5) วางไบนารีไบน์ดิงที่คอมไพล์แล้วลงในบันเดิลสแตนด์อโลน
	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	# 6) ลบบันเดิล sharp ที่เจาะจงตามสถาปัตยกรรม
	rm -rf .next/standalone/node_modules/@img

	# 7) คัดลอกการขึ้นต่อกันขณะรันไทม์ของ pino ที่การวิเคราะห์แบบสแตติกของ Next.js ไม่ได้นำมารวมไว้:
	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	# ป้องกันไม่ให้ฮุกหลังการติดตั้งลบไดเรกทอรีเราเตอร์แอป Next.js ที่ว่างเปล่า
	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
```

### โมเดลแบบกำหนดเอง

เพิ่ม ID โมเดลใดๆ ไปยังผู้ให้บริการรายใดก็ได้โดยไม่ต้องรอการอัปเดตแอป:

```bash
# ผ่าน API
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# แสดงรายการ: curl http://localhost:20128/api/provider-models?provider=openai
# ลบ: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

หรือใช้แดชบอร์ด: **ผู้ให้บริการ → [ผู้ให้บริการ] → โมเดลแบบกำหนดเอง**

หมายเหตุ:

- ผู้ให้บริการ OpenRouter และผู้ให้บริการที่เข้ากันได้กับ OpenAI/Anthropic จะได้รับการจัดการจาก **โมเดลที่พร้อมใช้งาน** เท่านั้น การเพิ่มด้วยตนเอง การนำเข้า และการซิงค์อัตโนมัติทั้งหมดจะรวมอยู่ในรายการโมเดลที่พร้อมใช้งานเดียวกัน ดังนั้นผู้ให้บริการเหล่านั้นจึงไม่มีส่วนโมเดลแบบกำหนดเองแยกต่างหาก
- ส่วน **โมเดลแบบกำหนดเอง** มีไว้สำหรับผู้ให้บริการที่ไม่มีการนำเข้าโมเดลที่พร้อมใช้งานแบบมีการจัดการ

### ผู้ให้บริการแบบกำหนดเองที่เข้ากันได้กับ OpenAI

เกตเวย์ใดๆ ที่รองรับ OpenAI API (พร็อกซีที่โฮสต์เอง, vLLM หรือตัวรวบรวมจากบุคคลที่สาม)
สามารถเพิ่มเป็นโหนดผู้ให้บริการแยกต่างหากได้:

1. **ผู้ให้บริการ → เพิ่มผู้ให้บริการที่เข้ากันได้กับ OpenAI**
2. **ชื่อ**: ป้ายชื่อที่ใช้แสดงสำหรับโหนด
3. **คำนำหน้า**: ชื่อที่ใช้กำหนดเส้นทาง ไคลเอนต์เรียกโมเดลในรูปแบบ `<prefix>/<model>` ดังนั้นโหนดที่มี
   คำนำหน้า `mygw` จะให้บริการ `mygw/gpt-4o-mini` จำเป็นต้องระบุ และไม่มีข้อจำกัดด้านอักขระ
4. **ประเภท API**: กลุ่มเอนด์พอยต์ที่เกตเวย์ให้บริการ (Chat Completions, Responses,
   Embeddings, เสียง, รูปภาพ)
5. **URL ฐาน**: รูทของ API จนถึงและรวม `/v1` (ตัวอย่างเช่น
   `https://gateway.example.com/v1`) ไม่ใช่พาธ `/chat/completions` แบบเต็ม สำหรับเกตเวย์ที่มี
   พาธที่ไม่เป็นมาตรฐาน ให้ตั้งค่าภายใต้ **การตั้งค่าขั้นสูง** (พาธแชต, พาธโมเดล)
6. ช่อง **คีย์ API (สำหรับตรวจสอบ)** ใช้ทดสอบการเชื่อมต่อเท่านั้น หลังจากสร้างโหนดแล้ว
   ให้เปิดโหนดและใช้ **เพิ่มการเชื่อมต่อ** เพื่อจัดเก็บคีย์ที่คำขอจะใช้

โหนดจะได้รับ ID ภายในในรูปแบบ `openai-compatible-<apiType>-<uuid>` คุณไม่จำเป็น
ต้องพิมพ์ ID นี้ เนื่องจากคำนำหน้าคือชื่อที่เปิดเผยต่อสาธารณะ

#### คำนำหน้าที่สงวนไว้

คำนำหน้าต้องไม่เป็น ID หรือนามแฝงของผู้ให้บริการในตัว (ตัวอย่างเช่น `openai`, `cf`) หรือ
ID ของผู้ให้บริการที่เลิกใช้งานแล้ว ตัวแก้ไขเส้นทางโมเดลจะตรวจสอบ ID และนามแฝงในตัวก่อน
โหนดแบบกำหนดเอง ดังนั้นโหนดที่ใช้คำนำหน้าเหล่านั้นจะไม่มีวันได้รับทราฟฟิก:
`<prefix>/model` จะถูกส่งไปยังผู้ให้บริการในตัวแทน หรือถูกปฏิเสธแบบปิดหากผู้ให้บริการนั้น
เลิกใช้งานแล้ว การสร้างหรือแก้ไขโหนดด้วยคำนำหน้าดังกล่าวจะถูกปฏิเสธพร้อมข้อความ:

```text
prefix: "<prefix>" เป็นคำนำหน้าผู้ให้บริการที่สงวนไว้ — โปรดเลือกคำนำหน้าอื่น (ไม่สามารถใช้ ID/นามแฝงที่สงวนไว้กับโหนดแบบกำหนดเองได้ เนื่องจากคำขออย่าง <prefix>/model จะถูกส่งไปยังผู้ให้บริการในตัว หรือถูกปฏิเสธแบบปิดเมื่อผู้ให้บริการนั้นเลิกใช้งานแล้ว)
```

เลือกคำนำหน้าที่ไม่ซ้ำกัน (`mygw`, `acme-proxy`) หากคำขอไปยังโหนดแบบกำหนดเองล้มเหลวพร้อม
ข้อผิดพลาดที่ระบุชื่อผู้ให้บริการในตัวหรือข้อมูลประจำตัวของผู้ให้บริการนั้น ให้ตรวจสอบว่าคำนำหน้าของโหนด
ถูกสงวนไว้หรือไม่: โหนดที่บันทึกไว้ก่อนมีกฎนี้จะยังคงถูกจัดเก็บ แต่คำนำหน้าของโหนดจะกำหนดเส้นทางไปยัง
ผู้ให้บริการในตัว ให้แก้ไขโหนดและกำหนดคำนำหน้าใหม่

### การเชื่อมโยงเพียร์ OmniRoute

สามารถเพิ่มเกตเวย์ OmniRoute อื่นเป็นผู้ให้บริการ **แบบกำหนดเองที่เข้ากันได้กับ OpenAI** ได้ ใช้
URL ฐาน `/v1` ของเพียร์และคีย์ API เฉพาะที่มีสิทธิ์น้อยที่สุดซึ่งออกโดยเพียร์นั้น

สำหรับเชนแบบสองทางหรือหลายฮอป ให้เปิดใช้กลไกป้องกันลูปแบบเลือกเข้าร่วมบนทุกเกตเวย์:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

เฉพาะคำขอที่ส่งไปยัง URL เพียร์ซึ่งได้รับอนุญาตไว้อย่างชัดเจนเท่านั้นที่จะได้รับส่วนหัว
`X-OmniRoute-Peer-Trace` เกตเวย์จะปฏิเสธ ID อินสแตนซ์ที่ซ้ำกันหรืองบประมาณฮอปที่หมดลง
ด้วย HTTP `508 Loop Detected` ส่วนผู้ให้บริการอัปสตรีมทั่วไปจะไม่ได้รับข้อมูลเมตาของเพียร์

การเชื่อมโยงเพียร์ไม่ใช่การจำลองฐานข้อมูลหรือการทำเฟลโอเวอร์ของโฮสต์ แต่ละเกตเวย์จะเก็บ
สถานะ SQLite, แคช, ตัวนับอัตรา และเซสชันแยกจากกัน ใช้รีเวิร์สพร็อกซีที่มีการตรวจสอบสถานะหรือ
การทำเฟลโอเวอร์ฝั่งไคลเอนต์สำหรับความพร้อมใช้งานแบบแอ็กทีฟ/แพสซีฟหรือแอ็กทีฟ/แอ็กทีฟ และห้ามเมานต์ฐานข้อมูล SQLite
หนึ่งฐานเข้ากับอินสแตนซ์ OmniRoute หลายอินสแตนซ์ที่กำลังทำงานอยู่

### เส้นทางเฉพาะสำหรับผู้ให้บริการ

กำหนดเส้นทางคำขอไปยังผู้ให้บริการที่ระบุโดยตรง พร้อมการตรวจสอบโมเดล:

```bash
POST http://localhost:20128/v1/providers/openai/chat/completions
POST http://localhost:20128/v1/providers/openai/embeddings
POST http://localhost:20128/v1/providers/fireworks/images/generations
```

ระบบจะเพิ่มคำนำหน้าผู้ให้บริการโดยอัตโนมัติหากยังไม่มี โมเดลที่ไม่ตรงกันจะส่งคืน `400`

### การกำหนดค่าพร็อกซีเครือข่าย

```bash
# ตั้งค่าพร็อกซีส่วนกลาง
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"global": {"type":"http","host":"proxy.example.com","port":"8080"}}'

# พร็อกซีแยกตามผู้ให้บริการ
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"providers": {"openai": {"type":"socks5","host":"proxy.example.com","port":"1080"}}}'

# ทดสอบพร็อกซี
curl -X POST http://localhost:20128/api/settings/proxy/test \
  -d '{"proxy":{"type":"socks5","host":"proxy.example.com","port":"1080"}}'
```

**ลำดับความสำคัญ:** เฉพาะคีย์ → เฉพาะคอมโบ → เฉพาะผู้ให้บริการ → ส่วนกลาง → สภาพแวดล้อม

### API แค็ตตาล็อกโมเดล

```bash
curl http://localhost:20128/api/models/catalog
```

ส่งคืนโมเดลที่จัดกลุ่มตามผู้ให้บริการ พร้อมประเภท (`chat`, `embedding`, `image`)

### การซิงค์กับคลาวด์

- ซิงค์ผู้ให้บริการ คอมโบ และการตั้งค่าระหว่างอุปกรณ์
- ซิงค์เบื้องหลังโดยอัตโนมัติ พร้อมการหมดเวลาและการล้มเหลวทันที
- ในระบบใช้งานจริง ควรใช้ `NEXT_PUBLIC_BASE_URL`/`NEXT_PUBLIC_CLOUD_URL` ฝั่งเซิร์ฟเวอร์

### Cloudflare Quick Tunnel

- พร้อมใช้งานใน **Dashboard → Endpoints** สำหรับ Docker และการติดตั้งแบบโฮสต์ด้วยตนเองอื่นๆ
- สร้าง URL `https://*.trycloudflare.com` ชั่วคราวที่ส่งต่อไปยัง endpoint `/v1` ที่เข้ากันได้กับ OpenAI ในปัจจุบันของคุณ
- การเปิดใช้งานครั้งแรกจะติดตั้ง `cloudflared` เฉพาะเมื่อจำเป็น ส่วนการรีสตาร์ตครั้งถัดไปจะใช้ไบนารีที่จัดการไว้ตัวเดิม
- Quick Tunnels จะไม่ถูกกู้คืนโดยอัตโนมัติหลังจากรีสตาร์ต OmniRoute หรือคอนเทนเนอร์ ให้เปิดใช้งานอีกครั้งจากแดชบอร์ดเมื่อจำเป็น
- URL ของ Tunnel เป็นแบบชั่วคราวและจะเปลี่ยนทุกครั้งที่คุณหยุด/เริ่ม tunnel
- Managed Quick Tunnels ใช้การรับส่งข้อมูลผ่าน HTTP/2 เป็นค่าเริ่มต้น เพื่อหลีกเลี่ยงคำเตือนเกี่ยวกับบัฟเฟอร์ QUIC UDP ที่รบกวนในคอนเทนเนอร์ที่มีข้อจำกัด
- ตั้งค่า `CLOUDFLARED_PROTOCOL=quic` หรือ `auto` หากคุณต้องการแทนที่ตัวเลือกการรับส่งข้อมูลที่ระบบจัดการไว้
- ตั้งค่า `CLOUDFLARED_BIN` หากคุณต้องการใช้ไบนารี `cloudflared` ที่ติดตั้งไว้ล่วงหน้าแทนการดาวน์โหลดที่ระบบจัดการ
- คุณสามารถแสดงหรือซ่อนแผง Cloudflare Quick Tunnel, Tailscale Funnel และ ngrok Tunnel ได้ใน **Settings → Appearance** การซ่อนแผงจะไม่หยุด tunnel ที่กำลังทำงานอยู่

### ระบบอัจฉริยะของเกตเวย์ LLM (เฟส 9)

- **แคชเชิงความหมาย** — แคชการตอบกลับแบบไม่สตรีมที่มี temperature=0 โดยอัตโนมัติ (ข้ามได้ด้วย `X-OmniRoute-No-Cache: true`)
- **การป้องกันคำขอซ้ำ** — กำจัดคำขอซ้ำภายใน 5 วินาทีผ่านเฮดเดอร์ `Idempotency-Key` หรือ `X-Request-Id`
- **การติดตามความคืบหน้า** — เลือกเปิดใช้เหตุการณ์ SSE `event: progress` ผ่านเฮดเดอร์ `X-OmniRoute-Progress: true`

### พื้นที่ทดลองตัวแปล

เข้าถึงผ่าน **Dashboard → Translator** ใช้ดีบักและแสดงภาพวิธีที่ OmniRoute แปลคำขอ API ระหว่างผู้ให้บริการ

| โหมด                       | วัตถุประสงค์                                                                     |
| -------------------------- | -------------------------------------------------------------------------------- |
| **พื้นที่ทดลอง**           | เลือกรูปแบบต้นทาง/ปลายทาง วางคำขอ และดูผลลัพธ์ที่แปลแล้วได้ทันที                 |
| **ตัวทดสอบแชต**            | ส่งข้อความแชตจริงผ่านพร็อกซีและตรวจสอบวงจรคำขอ/การตอบกลับทั้งหมด                 |
| **ชุดทดสอบ**               | เรียกใช้การทดสอบแบบกลุ่มกับรูปแบบหลายชุดร่วมกัน เพื่อตรวจสอบความถูกต้องของการแปล |
| **การตรวจสอบแบบเรียลไทม์** | ดูการแปลแบบเรียลไทม์ขณะที่คำขอไหลผ่านพร็อกซี                                     |

**กรณีการใช้งาน:**

- ดีบักสาเหตุที่ชุดไคลเอนต์/ผู้ให้บริการบางชุดทำงานล้มเหลว
- ตรวจสอบว่าแท็กการคิด การเรียกใช้เครื่องมือ และพรอมต์ระบบได้รับการแปลอย่างถูกต้อง
- เปรียบเทียบความแตกต่างของรูปแบบระหว่าง OpenAI, Claude, Gemini และรูปแบบ Responses API

### กลยุทธ์การกำหนดเส้นทาง

กำหนดค่าผ่าน **Dashboard → Settings → Routing** แดชบอร์ดแสดงกลยุทธ์ที่ใช้งานบ่อยที่สุดหกรายการ ส่วน combo และ auto-router รองรับกลยุทธ์ที่หลากหลายกว่าภายในระบบ

**กลยุทธ์ที่แสดงในแดชบอร์ด (การกำหนดเส้นทางระดับบัญชี):**

| กลยุทธ์                       | คำอธิบาย                                                                                                              |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **ใช้บัญชีแรกจนเต็ม**         | ใช้บัญชีตามลำดับความสำคัญ โดยบัญชีหลักจะจัดการคำขอทั้งหมดจนกว่าจะไม่พร้อมใช้งาน                                       |
| **วนรอบ**                     | วนใช้บัญชีทั้งหมดตามขีดจำกัดการยึดติดที่กำหนดค่าได้ (ค่าเริ่มต้น: 3 ครั้งต่อบัญชี)                                    |
| **P2C (เลือกจากสองตัวเลือก)** | สุ่มเลือก 2 บัญชีและกำหนดเส้นทางไปยังบัญชีที่มีสถานะดีกว่า เพื่อกระจายโหลดโดยคำนึงถึงสถานะของระบบ                     |
| **สุ่ม**                      | สุ่มเลือกบัญชีสำหรับแต่ละคำขอโดยใช้การสับเปลี่ยนแบบ Fisher-Yates                                                      |
| **ใช้งานน้อยที่สุด**          | กำหนดเส้นทางไปยังบัญชีที่มีการประทับเวลา `lastUsedAt` เก่าที่สุด เพื่อกระจายทราฟฟิกอย่างสม่ำเสมอ                      |
| **ปรับให้เหมาะสมตามต้นทุน**   | กำหนดเส้นทางไปยังบัญชีที่มีค่าลำดับความสำคัญต่ำที่สุด เพื่อเพิ่มประสิทธิภาพในการเลือกผู้ให้บริการที่มีต้นทุนต่ำที่สุด |

**กลยุทธ์ combo และ auto ขั้นสูง** (กำหนดค่าได้ต่อ combo หรือผ่านคำนำหน้า `auto/*` — ดู [AUTO-COMBO.md](../routing/AUTO-COMBO.md)):

- `priority` — ใช้ลำดับอย่างเคร่งครัดและไม่วนรอบ
- `weighted` — แบ่งทราฟฟิกตามสัดส่วนด้วยน้ำหนักของแต่ละโมเดล
- `fill-first` — ใช้โมเดลแรกจนถึงขีดจำกัด
- `round-robin` / `strict-random` / `random`
- `p2c` (เลือกจากสองตัวเลือก)
- `least-used` และ `cost-optimized`
- `auto` — ใช้คะแนนในการเลือกจากตัวเลือกทั้งหมด
- `lkgp` (ผู้ให้บริการล่าสุดที่ทราบว่าใช้งานได้) — ยึดผู้ให้บริการรายล่าสุดที่ดำเนินการสำเร็จ จากนั้นจึงย้อนกลับไปใช้กฎ
- `context-optimized` — เลือกโมเดลที่มีพื้นที่ว่างในหน้าต่างบริบทมากที่สุด
- `context-relay` — เชื่อมต่อโมเดลที่รองรับบริบทยาวสำหรับรอบการสนทนาต่อเนื่อง

#### เฮดเดอร์เซสชันยึดติดภายนอก

สำหรับการรักษาความสัมพันธ์ของเซสชันภายนอก (เช่น เอเจนต์ Claude Code/Codex ที่อยู่หลัง reverse proxy) ให้ส่ง:

```http
X-Session-Id: your-session-key
```

OmniRoute ยังยอมรับ `x_session_id` และส่งคืนคีย์เซสชันที่มีผลใน `X-OmniRoute-Session-Id`

หากคุณใช้ Nginx และส่งเฮดเดอร์ในรูปแบบที่มีขีดล่าง ให้เปิดใช้:

```nginx
underscores_in_headers on;
```

#### นามแฝงโมเดลแบบไวลด์การ์ด

สร้างรูปแบบไวลด์การ์ดเพื่อแมปชื่อโมเดลใหม่:

```
รูปแบบ: claude-sonnet-*     →  เป้าหมาย: cc/claude-sonnet-4-6
รูปแบบ: gpt-*               →  เป้าหมาย: gh/gpt-5.3-codex
```

ไวลด์การ์ดรองรับ `*` (อักขระจำนวนเท่าใดก็ได้) และ `?` (อักขระหนึ่งตัว)

#### เชนสำรอง

กำหนดเชนสำรองส่วนกลางที่ใช้กับคำขอทั้งหมด:

```
เชน: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### ความยืดหยุ่นและเซอร์กิตเบรกเกอร์

กำหนดค่าผ่าน **Dashboard → Settings → Resilience**

OmniRoute ใช้ระบบความยืดหยุ่นระดับผู้ให้บริการซึ่งประกอบด้วยองค์ประกอบห้าส่วน:

1. **คิวคำขอและการควบคุมจังหวะ** — การปรับรูปแบบคำขอระดับระบบ:
   - **จำนวนคำขอต่อนาที (RPM)** — จำนวนคำขอสูงสุดต่อนาทีต่อบัญชี
   - **เวลาขั้นต่ำระหว่างคำขอ** — ช่วงห่างขั้นต่ำระหว่างคำขอในหน่วยมิลลิวินาที
   - **จำนวนคำขอพร้อมกันสูงสุด** — จำนวนคำขอพร้อมกันสูงสุดต่อบัญชี
2. **คูลดาวน์การเชื่อมต่อ** — การกำหนดค่าตามประเภทการยืนยันตัวตนสำหรับการเชื่อมต่อแต่ละรายการหลังเกิดความล้มเหลวที่ลองใหม่ได้:
   - **คูลดาวน์พื้นฐาน** — ช่วงเวลาคูลดาวน์เริ่มต้นสำหรับความล้มเหลวจากต้นทางที่ลองใหม่ได้
   - **ใช้คำแนะนำการลองใหม่จากต้นทาง** — ปฏิบัติตามคำแนะนำ `Retry-After` หรือการรีเซ็ตที่เชื่อถือได้เมื่อมีการระบุ
   - **จำนวนขั้นตอน Backoff สูงสุด** — ระดับ Exponential Backoff สูงสุดสำหรับความล้มเหลวที่เกิดซ้ำ

3. **เซอร์กิตเบรกเกอร์ของผู้ให้บริการ** — ติดตามความล้มเหลวแบบต้นทางถึงปลายทางของผู้ให้บริการ ทำเครื่องหมายผู้ให้บริการว่าเสื่อมประสิทธิภาพเมื่อถึงเกณฑ์คำเตือนที่กำหนด และเปิดเบรกเกอร์เมื่อถึงเกณฑ์ความล้มเหลวที่กำหนด:
   - **เกณฑ์การเสื่อมประสิทธิภาพ** — จำนวนความล้มเหลวต่อเนื่องของผู้ให้บริการก่อนเข้าสู่สถานะ `DEGRADED`
   - **เกณฑ์ความล้มเหลว** — จำนวนความล้มเหลวต่อเนื่องของผู้ให้บริการก่อนเข้าสู่สถานะ `OPEN`
   - **ระยะเวลาก่อนรีเซ็ต** — ช่วงเวลาก่อนที่จะทดสอบผู้ให้บริการอีกครั้ง
   - **CLOSED** (ปกติ) — คำขอไหลผ่านตามปกติ
   - **DEGRADED** — คำขอยังคงไหลผ่าน ขณะที่ระบบติดตามความล้มเหลวที่เพิ่มสูงขึ้น
   - **OPEN** — ผู้ให้บริการถูกบล็อกชั่วคราวหลังเกิดความล้มเหลวซ้ำ
   - **HALF_OPEN** — กำลังทดสอบว่าผู้ให้บริการฟื้นตัวแล้วหรือไม่

   ขีดจำกัดอัตรา `429` ที่มีขอบเขตระดับการเชื่อมต่อจะยังคงอยู่ใน **คูลดาวน์การเชื่อมต่อ** และไม่นับรวมในเบรกเกอร์ของผู้ให้บริการ

   สถานะรันไทม์ของเบรกเกอร์ผู้ให้บริการจะแสดงเฉพาะใน **แดชบอร์ด → สุขภาพระบบ** เท่านั้น

4. **รอคูลดาวน์** — หากการเชื่อมต่อที่เป็นตัวเลือกทั้งหมดอยู่ระหว่างคูลดาวน์แล้ว OmniRoute สามารถรอจนกว่าคูลดาวน์ที่สิ้นสุดเร็วที่สุดจะครบกำหนด และลองคำขอเดิมของไคลเอนต์อีกครั้งโดยอัตโนมัติ

5. **ตรวจหาขีดจำกัดอัตราโดยอัตโนมัติ** — เมื่อผู้ให้บริการต้นทางส่งคืนช่วงเวลารอที่ระบุไว้อย่างชัดเจน คำแนะนำเหล่านั้นจะแทนที่คูลดาวน์การเชื่อมต่อภายในเครื่องเมื่อเปิดใช้งานการตั้งค่านี้

**เคล็ดลับระดับมืออาชีพ:** ใช้หน้า **สุขภาพระบบ** เพื่อตรวจสอบและรีเซ็ตเบรกเกอร์ผู้ให้บริการที่กำลังทำงานหลังระบบขัดข้อง หน้า Resilience ใช้สำหรับเปลี่ยนการกำหนดค่าเท่านั้น

### การส่งออก / นำเข้าฐานข้อมูล

จัดการข้อมูลสำรองของฐานข้อมูลใน **แดชบอร์ด → การตั้งค่า → ระบบและพื้นที่จัดเก็บข้อมูล**

| การดำเนินการ                | คำอธิบาย                                                                                                                                          |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ส่งออกฐานข้อมูล**         | ดาวน์โหลดฐานข้อมูล SQLite ปัจจุบันเป็นไฟล์ `.sqlite`                                                                                              |
| **ส่งออกทั้งหมด (.tar.gz)** | ดาวน์โหลดไฟล์เก็บถาวรสำรองฉบับเต็ม ซึ่งรวมถึง: ฐานข้อมูล การตั้งค่า คอมโบ การเชื่อมต่อผู้ให้บริการ (ไม่มีข้อมูลประจำตัว) และข้อมูลเมตาของคีย์ API |
| **นำเข้าฐานข้อมูล**         | อัปโหลดไฟล์ `.sqlite` เพื่อแทนที่ฐานข้อมูลปัจจุบัน ระบบจะสร้างข้อมูลสำรองก่อนนำเข้าโดยอัตโนมัติ เว้นแต่กำหนด `DISABLE_SQLITE_AUTO_BACKUP=true`    |

```bash
# API: ส่งออกฐานข้อมูล
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: ส่งออกทั้งหมด (ไฟล์เก็บถาวรฉบับเต็ม)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: นำเข้าฐานข้อมูล
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**การตรวจสอบความถูกต้องของการนำเข้า:** ไฟล์ที่นำเข้าจะได้รับการตรวจสอบความสมบูรณ์ (การตรวจสอบด้วย SQLite pragma), ตารางที่จำเป็น (`provider_connections`, `provider_nodes`, `combos`, `api_keys`) และขนาด (สูงสุด 100MB)

**กรณีการใช้งาน:**

- ย้าย OmniRoute ระหว่างเครื่อง
- สร้างข้อมูลสำรองภายนอกเพื่อการกู้คืนจากภัยพิบัติ
- แชร์การกำหนดค่าระหว่างสมาชิกในทีม (ส่งออกทั้งหมด → แชร์ไฟล์เก็บถาวร)

### แดชบอร์ดการตั้งค่า

หน้าการตั้งค่าจัดระเบียบเป็น **7 แท็บ** เพื่อให้นำทางได้ง่าย:

| แท็บ                | เนื้อหา                                                                                                                                                                       |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ทั่วไป**          | เครื่องมือพื้นที่จัดเก็บข้อมูลของระบบ ลักษณะการทำงานเริ่มต้น การมองเห็นทันเนล Endpoint                                                                                        |
| **รูปลักษณ์**       | ตัวควบคุมธีม (สว่าง/มืด/ระบบ), การมองเห็นแถบด้านข้าง, ตัวเลือกเปิด/ปิดแผงสำหรับการ์ดทันเนล Cloudflare/Tailscale/ngrok                                                         |
| **AI**              | งบประมาณการคิด (ส่งผ่าน / ตัดออกอัตโนมัติ / กำหนดเอง / ปรับเปลี่ยนตามสถานการณ์ — ดู [THINKING_BUDGET.md](./THINKING_BUDGET.md)), พรอมต์ระบบส่วนกลาง, สถิติแคชพรอมต์           |
| **ความปลอดภัย**     | การตั้งค่าการเข้าสู่ระบบ/รหัสผ่าน, การควบคุมการเข้าถึงด้วย IP, การยืนยันตัวตน API สำหรับ `/models`, การบล็อกผู้ให้บริการ, การป้องกัน Prompt Injection                         |
| **การกำหนดเส้นทาง** | กลยุทธ์การกำหนดเส้นทางส่วนกลาง (เติมรายการแรก / วนตามลำดับ / P2C / สุ่ม / ใช้น้อยที่สุด / ปรับต้นทุนให้เหมาะสม), นามแฝงโมเดลแบบ Wildcard, ลำดับ Fallback, ค่าเริ่มต้นของคอมโบ |
| **ความยืดหยุ่น**    | คิวคำขอ, คูลดาวน์การเชื่อมต่อ, การกำหนดค่าเบรกเกอร์ผู้ให้บริการ และลักษณะการทำงานของการรอคูลดาวน์                                                                             |
| **ขั้นสูง**         | การกำหนดค่าพร็อกซีส่วนกลาง (HTTP/SOCKS5), การตั้งค่าพร็อกซีแทนที่สำหรับผู้ให้บริการแต่ละราย                                                                                   |

ทั่วไปจะไม่แสดงหมายเหตุเกี่ยวกับการบันทึกและแคชแบบอ่านอย่างเดียวซ้ำอีกต่อไป การตั้งค่าการเก็บรักษาฐานข้อมูลและ
การปรับให้เหมาะสมจะถูกบันทึกผ่าน `/api/settings/database`; การล้างแคชด้วยตนเองใช้
`DELETE /api/cache` ขีดจำกัดจำนวนแถวของบันทึกคำขอและบันทึกพร็อกซีควบคุมโดย
`CALL_LOGS_TABLE_MAX_ROWS` และ `PROXY_LOGS_TABLE_MAX_ROWS`

### กลยุทธ์การกระจายโหลดของคอมโบ

กำหนดค่าการกระจายโหลดสำหรับแต่ละคอมโบได้ที่ **แดชบอร์ด → คอมโบ → สร้าง/แก้ไข → กลยุทธ์**

| กลยุทธ์                   | คำอธิบาย                                                                 |
| ------------------------- | ------------------------------------------------------------------------ |
| **วนตามลำดับ**            | หมุนเวียนใช้โมเดลตามลำดับ                                                |
| **ตามลำดับความสำคัญ**     | ลองใช้โมเดลแรกเสมอ และจะสลับไปใช้โมเดลสำรองเฉพาะเมื่อเกิดข้อผิดพลาด      |
| **สุ่ม**                  | สุ่มเลือกโมเดลจากคอมโบสำหรับแต่ละคำขอ                                    |
| **ถ่วงน้ำหนัก**           | กำหนดเส้นทางตามสัดส่วนโดยอิงจากน้ำหนักที่กำหนดให้แต่ละโมเดล              |
| **ใช้งานน้อยที่สุด**      | กำหนดเส้นทางไปยังโมเดลที่มีจำนวนคำขอล่าสุดน้อยที่สุด (ใช้เมตริกของคอมโบ) |
| **ปรับให้เหมาะกับต้นทุน** | กำหนดเส้นทางไปยังโมเดลที่มีราคาถูกที่สุดที่พร้อมใช้งาน (ใช้ตารางราคา)    |

สามารถตั้งค่าเริ่มต้นของคอมโบส่วนกลางได้ที่ **แดชบอร์ด → การตั้งค่า → การกำหนดเส้นทาง → ค่าเริ่มต้นของคอมโบ**
โดยค่าเริ่มต้น การหมดเวลาของเป้าหมายคอมโบจะรับค่ามาจากการหมดเวลาของคำขอปัจจุบัน ใช้ **การหมดเวลาของเป้าหมาย
(วินาที)** ในค่าเริ่มต้นของคอมโบหรือในคอมโบแต่ละรายการ เฉพาะเมื่อต้องการให้ขีดจำกัดต่อเป้าหมายที่สั้นกว่า
เรียกใช้กลไกสำรองได้เร็วขึ้น

การปรับแต่งคอมโบเพื่อให้มีเวลาแฝงเป็นศูนย์เป็นฟีเจอร์ที่ต้องเลือกเปิดใช้งาน ปล่อยให้ **การปรับแต่งเวลาแฝงเป็นศูนย์** ปิดอยู่เพื่อ
ป้องกันไม่ให้ฟีเจอร์ด้านเวลาแฝงเหล่านี้แข่งขันกับเป้าหมายสำรอง ข้ามเป้าหมายตามประวัติ
TTFT หรือบีบอัดคำขอสำรอง การเปิดใช้งานจะอนุญาตให้ใช้การส่งคำขอสำรองแบบซ้อนเหลื่อม การคาดการณ์ TTFT
เพื่อข้ามเป้าหมาย และการบีบอัดการสำรองเชิงรุกที่กำหนดค่าไว้ เพื่อแลกความเที่ยงตรงของการกำหนดเส้นทาง/คำขอกับ
เวลาแฝงช่วงปลายที่ต่ำลง

ปิดใช้งาน **บัฟเฟอร์โทเค็นสำหรับการให้เหตุผล** เมื่อผู้ให้บริการต้นทางกำหนดขีดจำกัด
`max_tokens` / `maxOutputTokens` อย่างเคร่งครัด เมื่อเปิดใช้งาน การกำหนดเส้นทางคอมโบจะเพิ่มพื้นที่สำรองสำหรับโมเดลที่ใช้
การให้เหตุผลเฉพาะโมเดลที่ทราบขีดจำกัดเอาต์พุต และจะไม่เปลี่ยนขีดจำกัดโทเค็นของไคลเอนต์เมื่อค่า
บัฟเฟอร์ที่ปลอดภัยจะเกินขีดจำกัดดังกล่าว หากขีดจำกัดของไคลเอนต์สูงกว่าขีดจำกัดที่ทราบอยู่แล้ว
OmniRoute จะลดค่าให้เท่ากับขีดจำกัดดังกล่าวก่อนส่งคำขอไปยังต้นทาง

### แดชบอร์ดสถานะระบบ

เข้าถึงได้ผ่าน **แดชบอร์ด → สถานะระบบ** ภาพรวมสถานะระบบแบบเรียลไทม์พร้อมการ์ด 6 ใบ:

| การ์ด                   | ข้อมูลที่แสดง                                                     |
| ----------------------- | ----------------------------------------------------------------- |
| **สถานะระบบ**           | ระยะเวลาทำงาน เวอร์ชัน การใช้หน่วยความจำ ไดเรกทอรีข้อมูล          |
| **สถานะผู้ให้บริการ**   | สถานะรันไทม์ของวงจรตัดการทำงานส่วนกลางของผู้ให้บริการ             |
| **ขีดจำกัดอัตรา**       | ช่วงพักการเชื่อมต่อที่ทำงานอยู่แยกตามบัญชี พร้อมเวลาที่เหลือ      |
| **การล็อกที่ทำงานอยู่** | การล็อกที่จำกัดขอบเขตตามโมเดลและการยกเว้นชั่วคราวที่ทำงานอยู่     |
| **แคชลายเซ็น**          | สถิติแคชการขจัดข้อมูลซ้ำ (คีย์ที่ทำงานอยู่ อัตราการพบข้อมูลในแคช) |
| **เทเลเมทรีเวลาแฝง**    | การรวมข้อมูลเวลาแฝง p50/p95/p99 แยกตามผู้ให้บริการ                |

**เคล็ดลับระดับมืออาชีพ:** หน้าสถานะระบบจะรีเฟรชอัตโนมัติทุก 10 วินาที ใช้การ์ดวงจรตัดการทำงานเพื่อระบุว่าผู้ให้บริการรายใดกำลังประสบปัญหา

## 🤖 การกำหนดเส้นทางอัตโนมัติ (ไม่ต้องตั้งค่า)

OmniRoute มาพร้อมกับ **เราเตอร์อัตโนมัติที่ขับเคลื่อนด้วยคะแนน** ซึ่งเลือกโมเดลที่ดีที่สุดสำหรับแต่ละคำขอจากผู้ให้บริการที่เชื่อมต่อทั้งหมด โดยไม่ต้องดูแลคอมโบใดๆ เพียงส่งคำขอโดยใช้คำนำหน้า `auto/*` รายการใดรายการหนึ่ง แล้ว OmniRoute จะประกอบคอมโบเสมือนขึ้นทันที พร้อมให้คะแนนตัวเลือกโดยพิจารณาจากเวลาแฝง ต้นทุน อัตราความสำเร็จ ความเหมาะสมกับบริบท ความเหมาะสมของโมเดลต่องาน ความล้มเหลวล่าสุด โควตา และสถานะของเซอร์กิตเบรกเกอร์

| คำนำหน้า       | ปรับให้เหมาะสมสำหรับ                                                                                       |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| `auto`         | ค่าเริ่มต้นแบบสมดุล (เวลาแฝง × ต้นทุน × อัตราความสำเร็จ)                                                   |
| `auto/coding`  | งานเขียนโค้ด: ให้ความสำคัญกับ Claude, GPT-5, GLM, Kimi, Qwen Coder และโมเดลเขียนโค้ดของ DeepSeek           |
| `auto/cheap`   | ราคาต่อโทเค็นต่ำที่สุด โดยยอมรับเวลาแฝงที่สูงขึ้น                                                          |
| `auto/fast`    | เวลาแฝงต่ำที่สุด โดยไม่คำนึงถึงต้นทุน                                                                      |
| `auto/offline` | ผู้ให้บริการภายในเครื่องเท่านั้น (Ollama, vLLM, llama.cpp) — มีประโยชน์สำหรับระบบที่ตัดขาดจากเครือข่าย     |
| `auto/smart`   | ให้ความสำคัญกับคุณภาพการให้เหตุผลเป็นอันดับแรก (Opus, GPT-5 xhigh, R1, การให้เหตุผลของ GLM 5.1)            |
| `auto/lkgp`    | "ผู้ให้บริการล่าสุดที่ใช้งานได้" — ตรึงไว้กับผู้ให้บริการรายล่าสุดที่ทำงานสำเร็จ จากนั้นจึงย้อนกลับไปใช้กฎ |

ตัวอย่าง:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "ปรับโครงสร้างฟังก์ชัน Python นี้" }],
    "stream": true
  }'
```

เราเตอร์อัตโนมัติมีคำอธิบายฉบับสมบูรณ์อยู่ใน [AUTO-COMBO.md](../routing/AUTO-COMBO.md) ซึ่งรวมถึงวิธีปรับแต่งค่าน้ำหนักการให้คะแนน ขึ้นบัญชีดำผู้ให้บริการ และตรวจสอบการตัดสินใจกำหนดเส้นทางใน **แดชบอร์ด → คอมโบอัตโนมัติ**

## 🔌 การผสานรวม MCP และ A2A

OmniRoute เป็นทั้ง **เซิร์ฟเวอร์ MCP** (Model Context Protocol) และ **เซิร์ฟเวอร์ A2A** (Agent-to-Agent JSON-RPC 2.0) IDE หรือโฮสต์เอเจนต์ใดๆ ที่รองรับ MCP สามารถเรียกใช้เครื่องมือของ OmniRoute ได้โดยตรง โดยไม่ต้องมีแรปเปอร์เพิ่มเติม

### การรับส่งข้อมูลของ MCP

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **HTTP แบบสตรีมได้**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (สำหรับปลั๊กอิน IDE ที่ต้องการใช้ stdio)

### เชื่อมต่อ Claude Desktop

แก้ไข `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) หรือไฟล์ที่เทียบเท่ากันบน Windows/Linux:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### เชื่อมต่อ Cursor / Continue / VS Code MCP

ใช้ URL ของ SSE `http://localhost:20128/api/mcp/sse` และคีย์ Bearer API ที่สร้างใน **แดชบอร์ด → คีย์ API**

### ขอบเขตสิทธิ์

ปัจจุบัน MCP กำหนดขอบเขตสิทธิ์ที่มีชื่อไว้ 32 รายการ โดยคีย์ Bearer แต่ละคีย์สามารถจำกัดให้ใช้เฉพาะขอบเขตสิทธิ์ที่กำหนดได้ — ดูรายการขอบเขตสิทธิ์และเครื่องมือที่เป็นแหล่งอ้างอิงหลักได้ใน [MCP-SERVER.md](../frameworks/MCP-SERVER.md) และดูสคีมา JSON-RPC ได้ใน [A2A-SERVER.md](../frameworks/A2A-SERVER.md)

## 🧠 ระบบทักษะ

OmniRoute มี **เฟรมเวิร์กทักษะ** ที่ขยายความสามารถได้ (`src/lib/skills/`) เพื่อให้เอเจนต์และปลายทาง A2A สามารถเรียกใช้รูทีนเฉพาะด้านได้ (เช่น `code-review`, `summarize`, `extract-facts`, `web-research`)

- **UI มาร์เก็ตเพลส** — เรียกดูและติดตั้งทักษะจาก **แดชบอร์ด → ทักษะ**
- **ขอบเขตต่อคีย์** — จำกัดว่า API key ใดสามารถเรียกใช้ทักษะใดได้บ้าง
- **ทักษะแบบกำหนดเอง** — วางไฟล์ TypeScript ใน `src/lib/a2a/skills/` ลงทะเบียนไฟล์ดังกล่าว แล้วทักษะนั้นจะพร้อมให้เรียกใช้ผ่าน A2A ได้ทันที

เอกสารอ้างอิงฉบับเต็ม: [SKILLS.md](../frameworks/SKILLS.md)

## 💾 ระบบหน่วยความจำ

OmniRoute จัดเก็บ **หน่วยความจำการสนทนาระยะยาว** พร้อมการค้นคืนแบบไฮบริด:

- **SQLite FTS5** สำหรับค้นหาด้วยคีย์เวิร์ดจากบทสนทนาที่ผ่านมา
- **ที่เก็บเวกเตอร์ Qdrant** (ไม่บังคับ) สำหรับเรียกคืนข้อมูลตามความหมาย
- **การสกัดข้อเท็จจริงอัตโนมัติ** — เอนทิตี ความชอบ และการตัดสินใจจะถูกสรุปหลังจากแต่ละเซสชันและจัดเก็บไว้ในตาราง `memory_facts`
- หน่วยความจำจะถูกแยกขอบเขตตาม API key และตามเซสชัน

จัดการหน่วยความจำได้ใน **แดชบอร์ด → หน่วยความจำ** (ค้นหา แก้ไข ส่งออก ล้างข้อมูล) อินเทอร์เฟซ HTTP (`/api/memory/*`) ช่วยให้เอเจนต์ส่งและค้นหาข้อเท็จจริงผ่านโปรแกรมได้ — ดู [MEMORY.md](../frameworks/MEMORY.md)

## 🔔 Webhook

สมัครรับเหตุการณ์จาก OmniRoute เพื่อการตรวจสอบและระบบอัตโนมัติแบบเรียลไทม์

- สร้าง webhook ใน **แดชบอร์ด → Webhook** พร้อม URL ปลายทางและข้อมูลลับสำหรับการลงนาม HMAC
- เหตุการณ์ที่พร้อมใช้งาน: `request.completed`, `request.failed`, `provider.unavailable`, `budget.exceeded`, `combo.switched`, `circuit_breaker.opened`, `circuit_breaker.closed`
- ทุกเพย์โหลดมี `X-OmniRoute-Signature` (HMAC-SHA256) สำหรับการตรวจสอบความถูกต้อง
- การลองใหม่: 3 ครั้งโดยเพิ่มระยะเวลารอแบบทวีคูณ จากนั้นส่งไปยังคิวข้อความที่ไม่สามารถประมวลผลได้

สคีมาฉบับเต็มอยู่ใน [WEBHOOKS.md](../frameworks/WEBHOOKS.md)

## 🛠️ การจัดการผ่านโปรแกรม

คุณสามารถจัดการทรัพยากรทั้งหมดของ OmniRoute (ผู้ให้บริการ คอมโบ คีย์ และการตั้งค่า) ผ่าน HTTP โดยใช้ **Bearer key ที่มีขอบเขต `manage`**

สร้างคีย์ใน **แดชบอร์ด → API Key → คีย์ใหม่ → ขอบเขต: manage** จากนั้น:

```bash
# แสดงรายการผู้ให้บริการ
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# เพิ่มการเชื่อมต่อผู้ให้บริการ
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# สร้างคอมโบ
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# แสดงรายการ/สร้าง API key
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

ดูแค็ตตาล็อกปลายทางและสคีมาคำขอ/การตอบกลับทั้งหมดได้ใน [API_REFERENCE.md](../reference/API_REFERENCE.md)

## 💻 CLI ภายใน

OmniRoute มาพร้อม CLI ภายใน (`omniroute …`) สำหรับการตั้งค่า การวินิจฉัย และการควบคุมขณะรันไทม์ ซึ่ง **แยกจากหน้า "CLI Tools" ในแดชบอร์ด** ที่ใช้กำหนดค่า CLI ของบุคคลที่สาม (Claude Code, Cursor, Codex, Cline, …) เพื่อให้สามารถสื่อสารกับ OmniRoute ได้

```bash
omniroute setup                    # วิซาร์ดแบบโต้ตอบ (รหัสผ่าน ผู้ให้บริการ คอมโบ)
omniroute setup --non-interactive  # เหมาะสำหรับ CI
omniroute doctor                   # การวินิจฉัยสถานะ (ไดเรกทอรีข้อมูล, DB, ผู้ให้บริการ, พอร์ต)
omniroute providers available      # แสดงรายการผู้ให้บริการที่รองรับ
omniroute providers list           # แสดงรายการการเชื่อมต่อที่กำหนดค่าไว้
omniroute providers test <id>      # ทดสอบการเชื่อมต่อผู้ให้บริการแบบสด
omniroute combos list              # แสดงรายการคอมโบ
omniroute combos switch <name>     # ตั้งค่าคอมโบเริ่มต้น
omniroute models                   # แสดงรายการโมเดลที่พร้อมใช้งาน (--json, --search)
omniroute keys add | list | remove # จัดการคีย์ API จากเทอร์มินัล
omniroute backup                   # สร้างสแนปช็อตการกำหนดค่า + DB
omniroute restore [<timestamp>]    # กู้คืนจากสแนปช็อต
omniroute health                   # สถานะโดยละเอียด (เบรกเกอร์, แคช, หน่วยความจำ)
omniroute quota                    # การใช้โควตาของผู้ให้บริการ
omniroute mcp status               # สถานะเซิร์ฟเวอร์ MCP
omniroute a2a status               # สถานะเซิร์ฟเวอร์ A2A
omniroute tunnel list|create|stop  # ทันเนล Cloudflare/Tailscale/ngrok
omniroute reset-password           # รีเซ็ตรหัสผ่านผู้ดูแลระบบ
omniroute --mcp                    # เริ่มเซิร์ฟเวอร์ MCP ผ่าน stdio
omniroute --port 3000              # เริ่มเซิร์ฟเวอร์บนพอร์ตที่กำหนดเอง
```

เคล็ดลับ: ใช้ `omniroute doctor --json` ร่วมกับเครื่องมือตรวจสอบของคุณเพื่อแจ้งเตือนเมื่อการเชื่อมต่อผู้ให้บริการมีปัญหา
