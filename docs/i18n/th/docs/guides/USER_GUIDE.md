## 🎯 กรณีการใช้งาน

### กรณีที่ 1: "ฉันมีการสมัครสมาชิก Claude Pro"

**ปัญหา:** โควตาหมดอายุโดยไม่ได้ใช้งาน และติดข้อจำกัดอัตราการใช้งานระหว่างเขียนโค้ดหนัก

```
ชุดผสม: "maximize-claude"
  1. cc/claude-opus-4-7        (ใช้สิทธิ์การสมัครสมาชิกอย่างเต็มที่)
  2. glm/glm-4.7               (ตัวสำรองราคาประหยัดเมื่อโควตาหมด)
  3. if/qwen3.8-max-preview       (ตัวสำรองฉุกเฉินฟรี)

ค่าใช้จ่ายรายเดือน: $20 (ค่าสมัครสมาชิก) + ~$5 (ตัวสำรอง) = รวม $25
เทียบกับ $20 + การติดข้อจำกัด = ความหงุดหงิด
```

### กรณีที่ 2: "ฉันไม่ต้องการเสียค่าใช้จ่ายเลย"

**ปัญหา:** ไม่สามารถจ่ายค่าสมัครสมาชิกได้ แต่ต้องการ AI สำหรับเขียนโค้ดที่เชื่อถือได้

```
ชุดผสม: "zero-cost"
  1. if/kimi-k2.7-code          (ระบุว่าเข้าถึงได้ฟรี แต่อาจมีข้อจำกัดอัตราการใช้งาน)
  2. kr/qwen3-coder-next        (ตัวสำรอง Kiro ฟรี)

ค่าใช้จ่ายรายเดือน: $0
คุณภาพ: ตรวจสอบโมเดล ข้อจำกัด ความเป็นส่วนตัว และ SLA ให้เหมาะกับเวิร์กโหลดของคุณ
```

### กรณีที่ 3: "ฉันต้องการเขียนโค้ดได้ตลอด 24/7 โดยไม่สะดุด"

**ปัญหา:** มีเส้นตายและไม่สามารถยอมรับช่วงเวลาที่ระบบหยุดให้บริการได้

```
ชุดผสม: "always-on"
  1. cc/claude-opus-4-7        (คุณภาพดีที่สุด)
  2. cx/gpt-5.5                (การสมัครสมาชิกรายการที่สอง)
  3. glm/glm-4.7               (ราคาประหยัด รีเซ็ตทุกวัน)
  4. minimax/MiniMax-M2.1      (ถูกที่สุด รีเซ็ตทุก 5 ชม.)
  5. if/deepseek-v4-flash       (ระบุว่าเข้าถึงได้ฟรี แต่อาจมีข้อจำกัดอัตราการใช้งาน)

ผลลัพธ์: ตัวสำรอง 5 ชั้นช่วยเพิ่มความยืดหยุ่น แต่ไม่รับประกันความพร้อมใช้งานของบริการต้นทาง
ค่าใช้จ่ายรายเดือน: $20-200 (ค่าสมัครสมาชิก) + $10-20 (ตัวสำรอง)
```

### กรณีที่ 4: "ฉันต้องการ AI ฟรีใน OpenClaw"

**ปัญหา:** ต้องการผู้ช่วย AI ในแอปรับส่งข้อความโดยไม่มีค่าใช้จ่ายใด ๆ

```
ชุดผสม: "openclaw-free"
  1. if/qwen3.8-max-preview     (ระบุว่าเข้าถึงได้ฟรี แต่อาจมีข้อจำกัดอัตราการใช้งาน)
  2. if/deepseek-v4-flash       (ระบุว่าเข้าถึงได้ฟรี แต่อาจมีข้อจำกัดอัตราการใช้งาน)
  3. if/kimi-k2.7-code          (ระบุว่าเข้าถึงได้ฟรี แต่อาจมีข้อจำกัดอัตราการใช้งาน)

ค่าใช้จ่ายรายเดือน: $0
เข้าถึงผ่าน: WhatsApp, Telegram, Slack, Discord, iMessage, Signal...
```

## 📖 การตั้งค่าผู้ให้บริการ

หากต้องการเพิ่มการเชื่อมต่อ API Key จำนวนมากจากไฟล์ CSV หรือ JSON ให้ใช้ **แดชบอร์ด → ผู้ให้บริการ → นำเข้าจากไฟล์** คอลัมน์จะเรียงตามตำแหน่ง (`provider,name,apiKey,baseUrl,priority`) โดย `provider` ต้องมีอยู่แล้วในฐานะผู้ให้บริการที่มีการจัดการหรือโหนดที่เข้ากันได้ ดู [นำเข้าผู้ให้บริการจากไฟล์ CSV หรือ JSON](../providers/CSV-IMPORT.md)

### 🔐 ผู้ให้บริการแบบสมัครสมาชิก

#### Claude Code (Pro/Max)

```bash
แดชบอร์ด → ผู้ให้บริการ → เชื่อมต่อ Claude Code
→ เข้าสู่ระบบด้วย OAuth → รีเฟรชโทเค็นอัตโนมัติ
→ ติดตามโควตาแบบ 5 ชั่วโมงและรายสัปดาห์

โมเดล:
  cc/claude-opus-4-7
  cc/claude-sonnet-4-6
  cc/claude-haiku-4-5-20251001
```

**เคล็ดลับ:** ใช้ Opus สำหรับงานที่ซับซ้อน และ Sonnet เมื่อต้องการความเร็ว OmniRoute ติดตามโควตาแยกตามโมเดล!

CLI จะโหลด `.env` จาก `~/.omniroute/.env` หรือ `./.env` โดยอัตโนมัติ

### โหมดถาดระบบ

เริ่มต้น OmniRoute ในถาดระบบ:

```bash
omniroute serve --tray
```

คำสั่งจะสิ้นสุดการทำงานหลังจากเซิร์ฟเวอร์และถาดระบบพร้อมใช้งานแล้ว

เซิร์ฟเวอร์จะทำงานต่อไปโดยไม่ต้องเปิดเทอร์มินัลไว้

โหมดถาดระบบรองรับ macOS, Windows และเซสชัน Linux แบบกราฟิก โหมดถาดระบบจะไม่เปิดแดชบอร์ดโดยอัตโนมัติ

ใช้เมนูถาดระบบเพื่อดำเนินการต่อไปนี้:

- เปิดแดชบอร์ด
- เปิด `/dashboard/logs`
- เปลี่ยนการตั้งค่าเริ่มต้นอัตโนมัติ
- หยุด OmniRoute

อย่าใช้ `--tray` ร่วมกับตัวเลือกต่อไปนี้:

- `--daemon`
- `--log`
- `--no-recovery`

โหมดเหล่านี้ต้องใช้การเป็นเจ้าของโปรเซสที่แตกต่างกัน

เปิดใช้งานการเริ่มต้นระบบเมื่อเข้าสู่ระบบเครื่องครั้งถัดไป:

```bash
omniroute autostart enable
```

การเริ่มต้นอัตโนมัติจะใช้โหมดถาดระบบบน macOS, Windows และเซสชัน Linux แบบกราฟิก ส่วน Linux แบบไม่มีส่วนติดต่อกราฟิกจะใช้บริการผู้ใช้ systemd ที่มีอยู่

ปิดใช้งานการเริ่มต้นระบบเมื่อเข้าสู่ระบบ:

```bash
omniroute autostart disable
```

### การถอนการติดตั้ง

เมื่อคุณไม่ต้องการใช้ OmniRoute อีกต่อไป เรามีสคริปต์ด่วนสองรายการสำหรับการลบออกอย่างหมดจด:

| คำสั่ง                   | การดำเนินการ                                                             |

	cp -r .next/static .next/standalone/.next/static

	rm -rf .next/standalone/node_modules/@img

	for _mod in pino-abstract-transport split2 process-warning; do

}

### โมเดลแบบกำหนดเอง

เพิ่ม ID ของโมเดลใดก็ได้ให้กับผู้ให้บริการรายใดก็ได้ โดยไม่ต้องรอการอัปเดตแอป:

```bash
# ผ่าน API
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# แสดงรายการ: curl http://localhost:20128/api/provider-models?provider=openai
# ลบ: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

หรือใช้แดชบอร์ด: **Providers → [Provider] → Custom Models**

หมายเหตุ:

- ผู้ให้บริการที่เข้ากันได้กับ OpenRouter และ OpenAI/Anthropic จะได้รับการจัดการจาก **Available Models** เท่านั้น การเพิ่มด้วยตนเอง การนำเข้า และการซิงค์อัตโนมัติทั้งหมดจะรวมอยู่ในรายการโมเดลที่พร้อมใช้งานเดียวกัน ดังนั้นจึงไม่มีส่วน Custom Models แยกต่างหากสำหรับผู้ให้บริการเหล่านั้น
- ส่วน **Custom Models** มีไว้สำหรับผู้ให้บริการที่ไม่มีการนำเข้าโมเดลที่พร้อมใช้งานแบบมีการจัดการ

### ผู้ให้บริการแบบกำหนดเองที่เข้ากันได้กับ OpenAI

เกตเวย์ใดก็ตามที่รองรับ OpenAI API (พร็อกซีที่โฮสต์เอง, vLLM, ตัวรวบรวมจากบุคคลที่สาม)
สามารถเพิ่มเป็นโหนดผู้ให้บริการแยกต่างหากได้:

1. **Providers → Add OpenAI Compatible**
2. **Name**: ป้ายชื่อที่ใช้แสดงสำหรับโหนด
3. **Prefix**: ชื่อสำหรับการกำหนดเส้นทาง ไคลเอนต์เรียกโมเดลในรูปแบบ `<prefix>/<model>` ดังนั้นโหนดที่มี
   คำนำหน้า `mygw` จะให้บริการ `mygw/gpt-4o-mini` จำเป็นต้องระบุ และไม่มีข้อจำกัดด้านอักขระ
4. **API Type**: กลุ่มเอนด์พอยต์ที่เกตเวย์ให้บริการ (Chat Completions, Responses,
   Embeddings, เสียง, รูปภาพ)
5. **Base URL**: รากของ API จนถึงและรวม `/v1` (ตัวอย่างเช่น
   `https://gateway.example.com/v1`) ไม่ใช่พาธ `/chat/completions` แบบเต็ม สำหรับเกตเวย์ที่มี
   พาธที่ไม่เป็นมาตรฐาน ให้ตั้งค่าภายใต้ **Advanced Settings** (พาธแชต, พาธโมเดล)
6. ช่อง **API Key (for Check)** ใช้ทดสอบการเชื่อมต่อเท่านั้น หลังจากสร้างโหนดแล้ว
   ให้เปิดโหนดและใช้ **Add Connection** เพื่อจัดเก็บคีย์ที่จะใช้กับคำขอ

โหนดจะได้รับ ID ภายในในรูปแบบ `openai-compatible-<apiType>-<uuid>` โดยคุณไม่จำเป็นต้อง
พิมพ์ ID นี้ เนื่องจากคำนำหน้าคือชื่อสาธารณะ

#### คำนำหน้าที่สงวนไว้

คำนำหน้าต้องไม่เป็น ID หรือนามแฝงของผู้ให้บริการในตัว (ตัวอย่างเช่น `openai`, `cf`) และต้องไม่เป็น
ID ของผู้ให้บริการที่ยุติการใช้งานแล้ว ตัวแก้ไขโมเดลจะตรวจสอบ ID และนามแฝงในตัวก่อน
โหนดแบบกำหนดเอง ดังนั้นโหนดที่ใช้คำนำหน้าเหล่านั้นจะไม่มีวันได้รับทราฟฟิก:
`<prefix>/model` จะถูกส่งไปยังผู้ให้บริการในตัวแทน หรือถูกปฏิเสธแบบ fail-closed หากผู้ให้บริการนั้น
ยุติการใช้งานแล้ว การสร้างหรือแก้ไขโหนดด้วยคำนำหน้าดังกล่าวจะถูกปฏิเสธพร้อมข้อความ:

```text
prefix: "<prefix>" เป็นคำนำหน้าผู้ให้บริการที่สงวนไว้ — โปรดเลือกคำนำหน้าอื่น (ไม่สามารถใช้ ID/นามแฝงที่สงวนไว้กับโหนดแบบกำหนดเองได้ เนื่องจากคำขออย่าง <prefix>/model จะถูกกำหนดเส้นทางไปยังผู้ให้บริการในตัว หรือถูกปฏิเสธแบบ fail-closed เมื่อยุติการใช้งานแล้ว)
```

เลือกคำนำหน้าที่ไม่ซ้ำกัน (`mygw`, `acme-proxy`) หากคำขอไปยังโหนดแบบกำหนดเองล้มเหลวโดยมี
ข้อผิดพลาดที่ระบุชื่อผู้ให้บริการในตัวหรือข้อมูลประจำตัวของผู้ให้บริการนั้น ให้ตรวจสอบว่าคำนำหน้าของโหนด
เป็นคำนำหน้าที่สงวนไว้หรือไม่: โหนดที่บันทึกไว้ก่อนมีกฎนี้จะยังคงถูกจัดเก็บอยู่ แต่คำนำหน้าของโหนดจะกำหนดเส้นทางไปยัง
ผู้ให้บริการในตัว ให้แก้ไขโหนดและกำหนดคำนำหน้าใหม่

### การเชื่อมต่อ OmniRoute เพียร์แบบลูกโซ่

สามารถเพิ่มเกตเวย์ OmniRoute อื่นเป็นผู้ให้บริการ **Custom OpenAI-compatible** ได้ โดยใช้
Base URL `/v1` ของเพียร์และ API key เฉพาะที่มีสิทธิ์น้อยที่สุดซึ่งออกโดยเพียร์นั้น

สำหรับลูกโซ่แบบสองทางหรือหลายทอด ให้เปิดใช้กลไกป้องกันลูปแบบเลือกเข้าร่วมบนทุกเกตเวย์:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

เฉพาะคำขอที่ส่งไปยัง URL ของเพียร์ซึ่งอยู่ในรายการอนุญาตอย่างชัดเจนเท่านั้นที่จะได้รับส่วนหัว
`X-OmniRoute-Peer-Trace` เกตเวย์จะปฏิเสธ ID ของอินสแตนซ์ที่ซ้ำกันหรือเมื่อโควตาจำนวนทอด
หมดลงด้วย HTTP `508 Loop Detected` ส่วนผู้ให้บริการต้นทางทั่วไปจะไม่ได้รับเมตาดาต้าของเพียร์

การเชื่อมต่อเพียร์แบบลูกโซ่ไม่ใช่การจำลองฐานข้อมูลหรือการทำ failover ของโฮสต์ แต่ละเกตเวย์จะเก็บ
สถานะ SQLite, แคช, ตัวนับอัตรา และเซสชันแยกจากกัน ใช้ reverse proxy ที่มีการตรวจสอบสถานะหรือกลไก
failover ฝั่งไคลเอนต์สำหรับความพร้อมใช้งานแบบ active/passive หรือ active/active และห้ามเมานต์ฐานข้อมูล SQLite เดียวกัน
เข้ากับอินสแตนซ์ OmniRoute หลายตัวที่กำลังทำงานอยู่

### เส้นทางเฉพาะสำหรับผู้ให้บริการ

กำหนดเส้นทางคำขอไปยังผู้ให้บริการที่ระบุโดยตรง พร้อมการตรวจสอบความถูกต้องของโมเดล:

```bash
POST http://localhost:20128/v1/providers/openai/chat/completions
POST http://localhost:20128/v1/providers/openai/embeddings
POST http://localhost:20128/v1/providers/fireworks/images/generations
```

ระบบจะเพิ่มคำนำหน้าของผู้ให้บริการโดยอัตโนมัติหากยังไม่มี โมเดลที่ไม่ตรงกันจะส่งคืน `400`

### การกำหนดค่าพร็อกซีเครือข่าย

```bash
# ตั้งค่าพร็อกซีส่วนกลาง
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"global": {"type":"http","host":"proxy.example.com","port":"8080"}}'

# พร็อกซีรายผู้ให้บริการ
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"providers": {"openai": {"type":"socks5","host":"proxy.example.com","port":"1080"}}}'

# ทดสอบพร็อกซี
curl -X POST http://localhost:20128/api/settings/proxy/test \
  -d '{"proxy":{"type":"socks5","host":"proxy.example.com","port":"1080"}}'
```

**ลำดับความสำคัญ:** เฉพาะคีย์ → เฉพาะคอมโบ → เฉพาะผู้ให้บริการ → ส่วนกลาง → สภาพแวดล้อม

### API แค็ตตาล็อกโมเดล

```bash
curl http://localhost:20128/api/models/catalog
```

ส่งคืนโมเดลที่จัดกลุ่มตามผู้ให้บริการพร้อมประเภท (`chat`, `embedding`, `image`)

### การซิงค์บนคลาวด์

- ซิงค์ผู้ให้บริการ คอมโบ และการตั้งค่าระหว่างอุปกรณ์
- ซิงค์เบื้องหลังโดยอัตโนมัติ พร้อมการหมดเวลาและการล้มเหลวอย่างรวดเร็ว
- ในระบบใช้งานจริง ควรเลือกใช้ `NEXT_PUBLIC_BASE_URL`/`NEXT_PUBLIC_CLOUD_URL` ฝั่งเซิร์ฟเวอร์

### Cloudflare Quick Tunnel

- พร้อมใช้งานใน **Dashboard → Endpoints** สำหรับ Docker และการติดตั้งแบบโฮสต์ด้วยตนเองอื่นๆ
- สร้าง URL ชั่วคราว `https://*.trycloudflare.com` ซึ่งส่งต่อไปยัง endpoint `/v1` ปัจจุบันของคุณที่เข้ากันได้กับ OpenAI
- การเปิดใช้งานครั้งแรกจะติดตั้ง `cloudflared` เฉพาะเมื่อจำเป็น ส่วนการรีสตาร์ตครั้งต่อๆ ไปจะใช้ไบนารีที่จัดการไว้ตัวเดิม
- Quick Tunnels จะไม่ถูกกู้คืนโดยอัตโนมัติหลังจากรีสตาร์ต OmniRoute หรือคอนเทนเนอร์ ให้เปิดใช้งานอีกครั้งจากแดชบอร์ดเมื่อจำเป็น
- URL ของ tunnel เป็นแบบชั่วคราวและจะเปลี่ยนทุกครั้งที่คุณหยุด/เริ่ม tunnel
- Quick Tunnels ที่จัดการโดยระบบจะใช้การรับส่งข้อมูลผ่าน HTTP/2 เป็นค่าเริ่มต้น เพื่อหลีกเลี่ยงคำเตือนเกี่ยวกับบัฟเฟอร์ UDP ของ QUIC ที่รบกวนในคอนเทนเนอร์ซึ่งมีทรัพยากรจำกัด
- ตั้งค่า `CLOUDFLARED_PROTOCOL=quic` หรือ `auto` หากคุณต้องการแทนที่ตัวเลือกการรับส่งข้อมูลที่ระบบจัดการไว้
- ตั้งค่า `CLOUDFLARED_BIN` หากคุณต้องการใช้ไบนารี `cloudflared` ที่ติดตั้งไว้ล่วงหน้าแทนการดาวน์โหลดที่ระบบจัดการให้
- สามารถแสดงหรือซ่อนแผง Cloudflare Quick Tunnel, Tailscale Funnel และ ngrok Tunnel ได้ใน **Settings → Appearance** การซ่อนแผงจะไม่หยุด tunnel ที่กำลังทำงานอยู่

### ความสามารถอัจฉริยะของ LLM Gateway (ระยะที่ 9)

- **แคชเชิงความหมาย** — แคชการตอบกลับแบบไม่สตรีมและ temperature=0 โดยอัตโนมัติ (ข้ามแคชด้วย `X-OmniRoute-No-Cache: true`)
- **การรับประกันว่าแต่ละคำขอมีผลเพียงครั้งเดียว** — กำจัดคำขอซ้ำภายใน 5 วินาทีผ่านเฮดเดอร์ `Idempotency-Key` หรือ `X-Request-Id`
- **การติดตามความคืบหน้า** — เลือกรับเหตุการณ์ SSE `event: progress` ผ่านเฮดเดอร์ `X-OmniRoute-Progress: true`

### กลยุทธ์การกำหนดเส้นทาง

กำหนดค่าผ่าน **Dashboard → Settings → Routing** แดชบอร์ดแสดงกลยุทธ์ที่ใช้บ่อยที่สุดหกแบบ ส่วน combo และ auto-router รองรับกลยุทธ์ที่หลากหลายกว่าภายในระบบ

**กลยุทธ์ที่แสดงในแดชบอร์ด (การกำหนดเส้นทางระดับบัญชี):**

| กลยุทธ์                        | คำอธิบาย                                                                                                    |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| **Fill First**                 | ใช้บัญชีตามลำดับความสำคัญ โดยบัญชีหลักจะจัดการคำขอทั้งหมดจนกว่าจะไม่พร้อมใช้งาน                             |
| **Round Robin**                | วนใช้ทุกบัญชีโดยมีขีดจำกัดการยึดติดที่กำหนดค่าได้ (ค่าเริ่มต้น: 3 การเรียกต่อบัญชี)                         |
| **P2C (Power of Two Choices)** | เลือกบัญชีแบบสุ่ม 2 บัญชีและกำหนดเส้นทางไปยังบัญชีที่มีสถานะดีกว่า เพื่อกระจายโหลดโดยคำนึงถึงสถานะความพร้อม |
| **Random**                     | เลือกบัญชีแบบสุ่มสำหรับแต่ละคำขอโดยใช้การสับแบบ Fisher-Yates                                                |
| **Least Used**                 | กำหนดเส้นทางไปยังบัญชีที่มีเวลาประทับ `lastUsedAt` เก่าที่สุด เพื่อกระจายทราฟฟิกอย่างสม่ำเสมอ               |
| **Cost Optimized**             | กำหนดเส้นทางไปยังบัญชีที่มีค่าลำดับความสำคัญต่ำที่สุด เพื่อเลือกผู้ให้บริการที่มีต้นทุนต่ำที่สุด            |

**กลยุทธ์ combo และ auto ขั้นสูง** (กำหนดค่าได้ต่อ combo หรือผ่านคำนำหน้า `auto/*` — ดู [AUTO-COMBO.md](../routing/AUTO-COMBO.md)):

- `priority` — ใช้ลำดับอย่างเคร่งครัดและไม่สลับแบบ round-robin
- `weighted` — แบ่งทราฟฟิกตามสัดส่วนโดยอิงน้ำหนักของแต่ละโมเดล
- `fill-first` — ใช้โมเดลแรกจนถึงขีดจำกัด
- `round-robin` / `strict-random` / `random`
- `p2c` (Power of Two Choices)
- `least-used` และ `cost-optimized`
- `auto` — ขับเคลื่อนด้วยคะแนนจากตัวเลือกทั้งหมด
- `lkgp` (Last Known Good Provider) — ยึดกับผู้ให้บริการล่าสุดที่ทำงานสำเร็จ จากนั้นจึงย้อนกลับไปใช้กฎ
- `context-optimized` — เลือกโมเดลที่มีหน้าต่างบริบทว่างมากที่สุด
- `context-relay` — เชื่อมต่อโมเดลบริบทยาวเป็นลำดับสำหรับรอบการสนทนาต่อเนื่อง

#### เฮดเดอร์ Sticky Session ภายนอก

สำหรับการยึดโยงเซสชันจากภายนอก (ตัวอย่างเช่น เอเจนต์ Claude Code/Codex ที่อยู่หลัง reverse proxy) ให้ส่ง:

```http
X-Session-Id: your-session-key
```

OmniRoute ยังยอมรับ `x_session_id` และส่งคืนคีย์เซสชันที่ใช้งานจริงใน `X-OmniRoute-Session-Id`

หากคุณใช้ Nginx และส่งเฮดเดอร์ในรูปแบบที่มีเครื่องหมายขีดล่าง ให้เปิดใช้งาน:

```nginx
underscores_in_headers on;
```

#### นามแฝงโมเดลแบบ Wildcard

สร้างรูปแบบ wildcard เพื่อแมปชื่อโมเดลใหม่:

```
Pattern: claude-sonnet-*     →  Target: cc/claude-sonnet-4-6
Pattern: gpt-*               →  Target: gh/gpt-5.3-codex
```

Wildcard รองรับ `*` (อักขระใดๆ) และ `?` (อักขระหนึ่งตัว)

#### ลำดับ Fallback

กำหนดลำดับ fallback ส่วนกลางที่ใช้กับคำขอทั้งหมด:

```
Chain: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### ชุดผู้ให้บริการและรูปแบบการกำหนดเส้นทางที่ใช้บ่อย

ต่อไปนี้คือตัวอย่างรูปแบบสำหรับการรวมผู้ให้บริการหลายรายและกำหนดเส้นทางระหว่างผู้ให้บริการเหล่านั้นใน OmniRoute:

#### 1. Combo สำหรับเอเจนต์เขียนโค้ด: การให้เหตุผลระดับสูงพร้อม Fallback ด้านต้นทุน/ความเร็ว

เหมาะสำหรับเอเจนต์เขียนโค้ด (OpenCode, Claude Code, Cursor, Cline) โดยเริ่มกำหนดเส้นทางไปยังโมเดลการให้เหตุผลระดับแนวหน้า และ fallback ไปยังโมเดลเขียนโค้ดที่รวดเร็วเมื่อโควตาหมดหรือเกิดข้อผิดพลาด

- **Dashboard**: Combos → New Combo → Name: `agent-coding` → Strategy: `Priority`
- **โมเดล**:
  1. `claude/claude-sonnet-4-6` (เอเจนต์เขียนโค้ดหลัก)
  2. `openai/gpt-4o` (fallback รองที่มีความจุสูง)
  3. `deepseek/deepseek-v4-flash` (fallback ประสิทธิภาพสูงและคุ้มค่า)

```bash
# ตัวอย่างผ่าน API
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "agent-coding",
    "strategy": "priority",
    "models": [
      { "model": "claude/claude-sonnet-4-6" },
      { "model": "openai/gpt-4o" },
      { "model": "deepseek/deepseek-v4-flash" }
    ]
  }'
```

#### 2. คอมโบสลับไปใช้ Free Tier โดยอัตโนมัติ

เชื่อมต่อผู้ให้บริการแบบ Free Tier และแบบไม่ต้องใช้คีย์หลายรายเข้าด้วยกัน เพื่อเพิ่มความพร้อมใช้งานสูงสุดโดยไม่มีค่าใช้จ่าย API

- **กลยุทธ์**: `Least Used` หรือ `Round Robin` (กระจายโหลดระหว่างโควตา)
- **โมเดล**:
  1. `groq/llama-3.3-70b-versatile`
  2. `gemini/gemini-2.5-flash`
  3. `cerebras/gpt-oss-120b`

```bash
# ตัวอย่างผ่าน CLI
omniroute combo create free-stack \
  --models "groq/llama-3.3-70b-versatile,gemini/gemini-2.5-flash,cerebras/gpt-oss-120b" \
  --strategy round-robin
```

#### 3. ไปป์ไลน์มัลติโมดัล / ภาพและข้อความ

จับคู่โมเดลด้านการมองเห็นเฉพาะทางกับการสร้างข้อความความเร็วสูง สำหรับเวิร์กโฟลว์ที่เกี่ยวข้องกับการทำความเข้าใจรูปภาพและการสร้างโค้ด

- **รูปแบบ**: คอมโบ `Priority` ที่เรียงโมเดลซึ่งรองรับการมองเห็นไว้ก่อน และวางโมเดลข้อความ/โค้ดที่มีอัตราการประมวลผลสูงไว้ท้ายสุด
- **โมเดล**:
  1. `gemini/gemini-2.5-pro` (มีความสามารถสูงในการทำความเข้าใจรูปภาพ/มัลติโมดัล)
  2. `openai/gpt-4o` (สมดุลระหว่างการมองเห็นและการใช้เครื่องมือ)
  3. `deepseek/deepseek-v4-flash` (การสร้างข้อความ/โค้ด)

### ความทนทานและ Circuit Breaker

กำหนดค่าผ่าน **แดชบอร์ด → การตั้งค่า → ความทนทาน**

OmniRoute ใช้กลไกความทนทานระดับผู้ให้บริการซึ่งประกอบด้วยองค์ประกอบ 5 ส่วน:

1. **คิวคำขอและการควบคุมจังหวะ** — การปรับรูปแบบคำขอในระดับระบบ:
   - **คำขอต่อนาที (RPM)** — จำนวนคำขอสูงสุดต่อนาทีต่อบัญชี
   - **ช่วงเวลาขั้นต่ำระหว่างคำขอ** — ระยะห่างขั้นต่ำเป็นมิลลิวินาทีระหว่างคำขอ
   - **จำนวนคำขอพร้อมกันสูงสุด** — จำนวนคำขอที่ทำงานพร้อมกันสูงสุดต่อบัญชี

2. **ช่วงพักการเชื่อมต่อ** — การกำหนดค่าตามประเภทการยืนยันตัวตนสำหรับการเชื่อมต่อหนึ่งรายการหลังเกิดข้อผิดพลาดที่ลองใหม่ได้:
   - **ช่วงพักพื้นฐาน** — ช่วงพักเริ่มต้นสำหรับข้อผิดพลาดจากต้นทางที่ลองใหม่ได้
   - **ใช้คำแนะนำการลองใหม่จากต้นทาง** — ปฏิบัติตามค่า `Retry-After` หรือคำแนะนำการรีเซ็ตที่เชื่อถือได้เมื่อมีการระบุ
   - **ขั้นตอนการถอยกลับสูงสุด** — ระดับการถอยกลับแบบทวีคูณสูงสุดสำหรับความล้มเหลวที่เกิดซ้ำ

3. **Circuit Breaker ของผู้ให้บริการ** — ติดตามความล้มเหลวแบบต้นทางถึงปลายทางของผู้ให้บริการ ทำเครื่องหมายว่าผู้ให้บริการมีประสิทธิภาพลดลงเมื่อถึงเกณฑ์คำเตือนที่กำหนด และเปิด Breaker เมื่อถึงเกณฑ์ความล้มเหลวที่กำหนด:
   - **เกณฑ์การลดประสิทธิภาพ** — จำนวนความล้มเหลวต่อเนื่องของผู้ให้บริการก่อนเข้าสู่สถานะ `DEGRADED`
   - **เกณฑ์ความล้มเหลว** — จำนวนความล้มเหลวต่อเนื่องของผู้ให้บริการก่อนเข้าสู่สถานะ `OPEN`
   - **ระยะเวลารอก่อนรีเซ็ต** — ช่วงเวลาก่อนทดสอบผู้ให้บริการอีกครั้ง
   - **CLOSED** (ปกติ) — คำขอไหลผ่านตามปกติ
   - **DEGRADED** — คำขอยังคงไหลผ่าน ขณะที่ระบบติดตามความล้มเหลวที่เพิ่มสูงขึ้น
   - **OPEN** — ผู้ให้บริการถูกบล็อกชั่วคราวหลังจากเกิดความล้มเหลวซ้ำหลายครั้ง
   - **HALF_OPEN** — กำลังทดสอบว่าผู้ให้บริการกลับมาทำงานได้แล้วหรือไม่

   ขีดจำกัดอัตรา `429` ในขอบเขตการเชื่อมต่อจะยังคงอยู่ใน **ช่วงพักการเชื่อมต่อ** และไม่นับรวมใน Breaker ของผู้ให้บริการ

   สถานะรันไทม์ของ Breaker ผู้ให้บริการจะแสดงเฉพาะใน **แดชบอร์ด → สถานะระบบ** เท่านั้น

4. **รอช่วงพัก** — หากการเชื่อมต่อที่เป็นตัวเลือกทั้งหมดอยู่ในช่วงพักแล้ว OmniRoute สามารถรอจนกว่าช่วงพักที่สิ้นสุดเร็วที่สุดจะหมดลง แล้วลองคำขอเดิมของไคลเอ็นต์อีกครั้งโดยอัตโนมัติ

5. **การตรวจจับขีดจำกัดอัตราอัตโนมัติ** — เมื่อผู้ให้บริการต้นทางส่งคืนช่วงเวลารออย่างชัดเจน คำแนะนำเหล่านั้นจะแทนที่ช่วงพักการเชื่อมต่อภายในเครื่องเมื่อเปิดใช้งานการตั้งค่านี้

**เคล็ดลับระดับมืออาชีพ:** ใช้หน้า **สถานะระบบ** เพื่อตรวจสอบและรีเซ็ต Breaker ของผู้ให้บริการที่กำลังทำงานอยู่หลังจากระบบหยุดให้บริการ หน้าความทนทานมีไว้สำหรับเปลี่ยนการกำหนดค่าเท่านั้น

### การส่งออก / นำเข้าฐานข้อมูล

จัดการข้อมูลสำรองของฐานข้อมูลใน **แดชบอร์ด → การตั้งค่า → ระบบและพื้นที่จัดเก็บข้อมูล**

| การดำเนินการ                | คำอธิบาย                                                                                                                                           |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ส่งออกฐานข้อมูล**         | ดาวน์โหลดฐานข้อมูล SQLite ปัจจุบันเป็นไฟล์ `.sqlite`                                                                                               |
| **ส่งออกทั้งหมด (.tar.gz)** | ดาวน์โหลดไฟล์เก็บถาวรสำรองแบบเต็ม ซึ่งประกอบด้วยฐานข้อมูล การตั้งค่า คอมโบ การเชื่อมต่อผู้ให้บริการ (ไม่มีข้อมูลประจำตัว) และข้อมูลเมตาของคีย์ API |
| **นำเข้าฐานข้อมูล**         | อัปโหลดไฟล์ `.sqlite` เพื่อแทนที่ฐานข้อมูลปัจจุบัน ระบบจะสร้างข้อมูลสำรองก่อนนำเข้าโดยอัตโนมัติ เว้นแต่กำหนด `DISABLE_SQLITE_AUTO_BACKUP=true`     |

```bash
# API: ส่งออกฐานข้อมูล
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: ส่งออกทั้งหมด (ไฟล์เก็บถาวรแบบเต็ม)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: นำเข้าฐานข้อมูล
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**การตรวจสอบความถูกต้องเมื่อนำเข้า:** ไฟล์ที่นำเข้าจะได้รับการตรวจสอบความสมบูรณ์ (การตรวจสอบด้วย pragma ของ SQLite) ตารางที่จำเป็น (`provider_connections`, `provider_nodes`, `combos`, `api_keys`) และขนาด (สูงสุด 100MB)

**กรณีการใช้งาน:**

- ย้าย OmniRoute ระหว่างเครื่อง
- สร้างข้อมูลสำรองภายนอกสำหรับการกู้คืนจากภัยพิบัติ
- แชร์การกำหนดค่าระหว่างสมาชิกในทีม (ส่งออกทั้งหมด → แชร์ไฟล์เก็บถาวร)

### แดชบอร์ดการตั้งค่า

หน้าการตั้งค่าแบ่งออกเป็น **7 แท็บ** เพื่อให้ไปยังส่วนต่าง ๆ ได้ง่าย:

| แท็บ                | เนื้อหา                                                                                                                                                         |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ทั่วไป**          | เครื่องมือจัดเก็บข้อมูลของระบบ ลักษณะการทำงานเริ่มต้น การมองเห็นทันเนลของ Endpoint                                                                              |
| **รูปลักษณ์**       | การควบคุมธีม (สว่าง/มืด/ระบบ) การมองเห็นแถบด้านข้าง การเปิด/ปิดแผงการ์ดทันเนล Cloudflare/Tailscale/ngrok                                                        |
| **AI**              | งบประมาณการคิด (ส่งผ่าน / ตัดออกอัตโนมัติ / กำหนดเอง / ปรับตามสถานการณ์ — ดู [THINKING_BUDGET.md](./THINKING_BUDGET.md)) พรอมต์ระบบส่วนกลาง สถิติแคชพรอมต์      |
| **ความปลอดภัย**     | การตั้งค่าการเข้าสู่ระบบ/รหัสผ่าน การควบคุมการเข้าถึงด้วย IP การยืนยันตัวตน API สำหรับ `/models` การบล็อกผู้ให้บริการ ระบบป้องกันการแทรกพรอมต์                  |
| **การกำหนดเส้นทาง** | กลยุทธ์การกำหนดเส้นทางส่วนกลาง (Fill First / Round Robin / P2C / Random / Least Used / Cost Optimized) นามแฝงโมเดลแบบไวลด์การ์ด สายโซ่สำรอง ค่าเริ่มต้นของคอมโบ |
| **ความทนทาน**       | คิวคำขอ ช่วงพักการเชื่อมต่อ การกำหนดค่าเบรกเกอร์ของผู้ให้บริการ และลักษณะการรอให้ช่วงพักสิ้นสุด                                                                 |
| **ขั้นสูง**         | การกำหนดค่าพร็อกซีส่วนกลาง (HTTP/SOCKS5) การแทนที่ค่าพร็อกซีแยกตามผู้ให้บริการ                                                                                  |

ส่วนทั่วไปจะไม่แสดงหมายเหตุแบบอ่านอย่างเดียวเกี่ยวกับการบันทึกและแคชซ้ำอีกต่อไป การตั้งค่าการเก็บรักษาและ
การเพิ่มประสิทธิภาพฐานข้อมูลจะถูกบันทึกผ่าน `/api/settings/database`; การล้างแคชด้วยตนเองใช้
`DELETE /api/cache` จำนวนแถวสูงสุดของบันทึกคำขอและบันทึกพร็อกซีควบคุมโดย
`CALL_LOGS_TABLE_MAX_ROWS` และ `PROXY_LOGS_TABLE_MAX_ROWS`

### กลยุทธ์การกระจายโหลดของคอมโบ

กำหนดค่าการกระจายโหลดสำหรับแต่ละคอมโบได้ที่ **แดชบอร์ด → คอมโบ → สร้าง/แก้ไข → กลยุทธ์**

| กลยุทธ์            | คำอธิบาย                                                              |
| ------------------ | --------------------------------------------------------------------- |
| **Round-Robin**    | หมุนเวียนใช้งานโมเดลตามลำดับ                                          |
| **Priority**       | ลองใช้โมเดลแรกเสมอ และเปลี่ยนไปใช้โมเดลสำรองเฉพาะเมื่อเกิดข้อผิดพลาด  |
| **Random**         | สุ่มเลือกโมเดลจากคอมโบสำหรับแต่ละคำขอ                                 |
| **Weighted**       | กำหนดเส้นทางตามสัดส่วนของน้ำหนักที่กำหนดให้แต่ละโมเดล                 |
| **Least-Used**     | กำหนดเส้นทางไปยังโมเดลที่มีคำขอล่าสุดน้อยที่สุด (ใช้เมตริกของคอมโบ)   |
| **Cost-Optimized** | กำหนดเส้นทางไปยังโมเดลที่พร้อมใช้งานและมีราคาถูกที่สุด (ใช้ตารางราคา) |

สามารถตั้งค่าเริ่มต้นของคอมโบส่วนกลางได้ที่ **แดชบอร์ด → การตั้งค่า → การกำหนดเส้นทาง → ค่าเริ่มต้นของคอมโบ**
โดยค่าเริ่มต้น การหมดเวลาของเป้าหมายคอมโบจะสืบทอดค่าหมดเวลาของคำขอปัจจุบัน ใช้ **การหมดเวลาของเป้าหมาย
(วินาที)** ในค่าเริ่มต้นของคอมโบหรือในคอมโบแต่ละรายการ เฉพาะเมื่อต้องการให้ขีดจำกัดต่อเป้าหมายที่สั้นกว่า
เรียกใช้กลไกสำรองได้เร็วขึ้น

การเพิ่มประสิทธิภาพคอมโบแบบไม่มีเวลาแฝงเป็นคุณสมบัติที่ต้องเลือกเปิดใช้งาน ปล่อยให้ **การเพิ่มประสิทธิภาพแบบไม่มีเวลาแฝง** ปิดอยู่เพื่อ
ป้องกันไม่ให้คุณสมบัติด้านเวลาแฝงเหล่านี้แข่งขันกับเป้าหมายสำรอง ข้ามเป้าหมายตามประวัติ TTFT
หรือบีบอัดคำขอสำรอง; การเปิดใช้งานจะอนุญาตให้ใช้การส่งคำขอแบบป้องกันความเสี่ยงที่กำหนดค่าไว้ การข้ามตามการคาดการณ์ TTFT
และการบีบอัดคำขอสำรองเชิงรุก เพื่อแลกความเที่ยงตรงของการกำหนดเส้นทาง/คำขอกับเวลาแฝงส่วนปลายที่ต่ำลง

ปิดใช้งาน **บัฟเฟอร์โทเค็นสำหรับการให้เหตุผล** เมื่อผู้ให้บริการต้นทางกำหนดขีดจำกัด
`max_tokens` / `maxOutputTokens` อย่างเคร่งครัด เมื่อเปิดใช้งาน การกำหนดเส้นทางแบบผสมจะเพิ่มพื้นที่สำรองสำหรับโมเดลการให้เหตุผลเฉพาะ
โมเดลที่ทราบขีดจำกัดเอาต์พุตเท่านั้น และจะคงขีดจำกัดโทเค็นของไคลเอ็นต์ไว้โดยไม่เปลี่ยนแปลง หากค่าที่บัฟเฟอร์ไว้อย่างปลอดภัย
จะเกินขีดจำกัดดังกล่าว หากขีดจำกัดของไคลเอ็นต์สูงกว่าขีดจำกัดที่ทราบอยู่แล้ว
OmniRoute จะลดค่าให้เท่ากับขีดจำกัดดังกล่าวก่อนส่งคำขอไปยังต้นทาง

เข้าถึงผ่าน **แดชบอร์ด → สถานะระบบ** ภาพรวมสถานะระบบแบบเรียลไทม์ประกอบด้วยการ์ด 6 ใบ:

| **ขีดจำกัดอัตรา**       | ช่วงพักการเชื่อมต่อที่มีผลอยู่ในแต่ละบัญชี พร้อมเวลาที่เหลือ       |

## 🤖 การกำหนดเส้นทางอัตโนมัติ (ไม่ต้องตั้งค่า)

OmniRoute มาพร้อมกับ **เราเตอร์อัตโนมัติที่ขับเคลื่อนด้วยคะแนน** ซึ่งเลือกโมเดลที่ดีที่สุดสำหรับแต่ละคำขอจากผู้ให้บริการที่เชื่อมต่อทั้งหมด โดยไม่ต้องดูแลคอมโบใดๆ เพียงส่งคำขอโดยใช้คำนำหน้า `auto/*` รายการใดรายการหนึ่ง แล้ว OmniRoute จะประกอบคอมโบเสมือนขึ้นทันที พร้อมให้คะแนนตัวเลือกโดยพิจารณาจากเวลาแฝง ต้นทุน อัตราความสำเร็จ ความเหมาะสมกับบริบท ความเหมาะสมของโมเดลต่องาน ความล้มเหลวล่าสุด โควตา และสถานะของเซอร์กิตเบรกเกอร์

| คำนำหน้า       | ปรับให้เหมาะสมสำหรับ                                                                                       |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| `auto`         | ค่าเริ่มต้นแบบสมดุล (เวลาแฝง × ต้นทุน × อัตราความสำเร็จ)                                                   |
| `auto/coding`  | งานเขียนโค้ด: ให้ความสำคัญกับ Claude, GPT-5, GLM, Kimi, Qwen Coder และโมเดลเขียนโค้ดของ DeepSeek           |
| `auto/cheap`   | ราคาต่อโทเค็นต่ำที่สุด โดยยอมรับเวลาแฝงที่สูงขึ้น                                                          |
| `auto/fast`    | เวลาแฝงต่ำที่สุด โดยไม่คำนึงถึงต้นทุน                                                                      |
| `auto/offline` | ผู้ให้บริการภายในเครื่องเท่านั้น (Ollama, vLLM, llama.cpp) — มีประโยชน์สำหรับระบบที่ตัดขาดจากเครือข่าย     |
| `auto/smart`   | ให้ความสำคัญกับคุณภาพการให้เหตุผลเป็นอันดับแรก (Opus, GPT-5 xhigh, R1, การให้เหตุผลของ GLM 5.1)            |
| `auto/lkgp`    | "ผู้ให้บริการล่าสุดที่ใช้งานได้" — ตรึงไว้กับผู้ให้บริการรายล่าสุดที่ทำงานสำเร็จ จากนั้นจึงย้อนกลับไปใช้กฎ |

ตัวอย่าง:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "ปรับโครงสร้างฟังก์ชัน Python นี้" }],
    "stream": true
  }'
```

เราเตอร์อัตโนมัติมีคำอธิบายฉบับสมบูรณ์อยู่ใน [AUTO-COMBO.md](../routing/AUTO-COMBO.md) ซึ่งรวมถึงวิธีปรับแต่งค่าน้ำหนักการให้คะแนน ขึ้นบัญชีดำผู้ให้บริการ และตรวจสอบการตัดสินใจกำหนดเส้นทางใน **แดชบอร์ด → คอมโบอัตโนมัติ**

## 🔌 การผสานรวม MCP และ A2A

OmniRoute เป็นทั้ง **เซิร์ฟเวอร์ MCP** (Model Context Protocol) และ **เซิร์ฟเวอร์ A2A** (Agent-to-Agent JSON-RPC 2.0) IDE หรือโฮสต์เอเจนต์ใดๆ ที่รองรับ MCP สามารถเรียกใช้เครื่องมือของ OmniRoute ได้โดยตรง โดยไม่ต้องมีแรปเปอร์เพิ่มเติม

### การรับส่งข้อมูลของ MCP

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **HTTP แบบสตรีมได้**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (สำหรับปลั๊กอิน IDE ที่ต้องการใช้ stdio)

### เชื่อมต่อ Claude Desktop

แก้ไข `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) หรือไฟล์ที่เทียบเท่ากันบน Windows/Linux:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### เชื่อมต่อ Cursor / Continue / VS Code MCP

ใช้ URL ของ SSE `http://localhost:20128/api/mcp/sse` และคีย์ Bearer API ที่สร้างใน **แดชบอร์ด → คีย์ API**

### ขอบเขตสิทธิ์

ปัจจุบัน MCP กำหนดขอบเขตสิทธิ์ที่มีชื่อไว้ 32 รายการ โดยคีย์ Bearer แต่ละคีย์สามารถจำกัดให้ใช้เฉพาะขอบเขตสิทธิ์ที่กำหนดได้ — ดูรายการขอบเขตสิทธิ์และเครื่องมือที่เป็นแหล่งอ้างอิงหลักได้ใน [MCP-SERVER.md](../frameworks/MCP-SERVER.md) และดูสคีมา JSON-RPC ได้ใน [A2A-SERVER.md](../frameworks/A2A-SERVER.md)

## 💾 ระบบหน่วยความจำ

OmniRoute จัดเก็บ **หน่วยความจำการสนทนาระยะยาว** พร้อมการค้นคืนแบบไฮบริด:

- **SQLite FTS5** สำหรับค้นหาด้วยคีย์เวิร์ดจากบทสนทนาที่ผ่านมา
- **ที่เก็บเวกเตอร์ Qdrant** (ไม่บังคับ) สำหรับเรียกคืนข้อมูลตามความหมาย
- **การสกัดข้อเท็จจริงอัตโนมัติ** — เอนทิตี ความชอบ และการตัดสินใจจะถูกสรุปหลังจากแต่ละเซสชันและจัดเก็บไว้ในตาราง `memory_facts`
- หน่วยความจำจะถูกแยกขอบเขตตาม API key และตามเซสชัน

จัดการหน่วยความจำได้ใน **แดชบอร์ด → หน่วยความจำ** (ค้นหา แก้ไข ส่งออก ล้างข้อมูล) อินเทอร์เฟซ HTTP (`/api/memory/*`) ช่วยให้เอเจนต์ส่งและค้นหาข้อเท็จจริงผ่านโปรแกรมได้ — ดู [MEMORY.md](../frameworks/MEMORY.md)

## 🔔 Webhook

สมัครรับเหตุการณ์จาก OmniRoute เพื่อการตรวจสอบและระบบอัตโนมัติแบบเรียลไทม์

- สร้าง webhook ใน **แดชบอร์ด → Webhook** พร้อม URL ปลายทางและข้อมูลลับสำหรับการลงนาม HMAC

- การลองใหม่: 3 ครั้งโดยเพิ่มระยะเวลารอแบบทวีคูณ จากนั้นส่งไปยังคิวข้อความที่ไม่สามารถประมวลผลได้

## 🛠️ การจัดการผ่านโปรแกรม

คุณสามารถจัดการทรัพยากรทั้งหมดของ OmniRoute (ผู้ให้บริการ คอมโบ คีย์ และการตั้งค่า) ผ่าน HTTP โดยใช้ **Bearer key ที่มีขอบเขต `manage`**

สร้างคีย์ใน **แดชบอร์ด → API Key → คีย์ใหม่ → ขอบเขต: manage** จากนั้น:

```bash
# แสดงรายการผู้ให้บริการ
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# เพิ่มการเชื่อมต่อผู้ให้บริการ
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# สร้างคอมโบ
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# แสดงรายการ/สร้าง API key
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

ดูแค็ตตาล็อกปลายทางและสคีมาคำขอ/การตอบกลับทั้งหมดได้ใน [API_REFERENCE.md](../reference/API_REFERENCE.md)

## 💻 CLI ภายใน

OmniRoute มาพร้อม CLI ภายใน (`omniroute …`) สำหรับการตั้งค่า การวินิจฉัย และการควบคุมขณะรันไทม์ ซึ่ง **แยกจากหน้า "CLI Tools" ในแดชบอร์ด** ที่ใช้กำหนดค่า CLI ของบุคคลที่สาม (Claude Code, Cursor, Codex, Cline, …) เพื่อให้สามารถสื่อสารกับ OmniRoute ได้

```bash
omniroute setup                    # วิซาร์ดแบบโต้ตอบ (รหัสผ่าน ผู้ให้บริการ คอมโบ)
omniroute setup --non-interactive  # เหมาะสำหรับ CI
omniroute doctor                   # การวินิจฉัยสถานะ (ไดเรกทอรีข้อมูล, DB, ผู้ให้บริการ, พอร์ต)
omniroute providers available      # แสดงรายการผู้ให้บริการที่รองรับ
omniroute providers list           # แสดงรายการการเชื่อมต่อที่กำหนดค่าไว้
omniroute providers test <id>      # ทดสอบการเชื่อมต่อผู้ให้บริการแบบสด
omniroute combos list              # แสดงรายการคอมโบ
omniroute combos switch <name>     # ตั้งค่าคอมโบเริ่มต้น
omniroute models                   # แสดงรายการโมเดลที่พร้อมใช้งาน (--json, --search)
omniroute keys add | list | remove # จัดการคีย์ API จากเทอร์มินัล
omniroute backup                   # สร้างสแนปช็อตการกำหนดค่า + DB
omniroute restore [<timestamp>]    # กู้คืนจากสแนปช็อต
omniroute health                   # สถานะโดยละเอียด (เบรกเกอร์, แคช, หน่วยความจำ)
omniroute quota                    # การใช้โควตาของผู้ให้บริการ
omniroute mcp status               # สถานะเซิร์ฟเวอร์ MCP
omniroute a2a status               # สถานะเซิร์ฟเวอร์ A2A
omniroute tunnel list|create|stop  # ทันเนล Cloudflare/Tailscale/ngrok
omniroute reset-password           # รีเซ็ตรหัสผ่านผู้ดูแลระบบ
omniroute --mcp                    # เริ่มเซิร์ฟเวอร์ MCP ผ่าน stdio
omniroute --port 3000              # เริ่มเซิร์ฟเวอร์บนพอร์ตที่กำหนดเอง
```

เคล็ดลับ: ใช้ `omniroute doctor --json` ร่วมกับเครื่องมือตรวจสอบของคุณเพื่อแจ้งเตือนเมื่อการเชื่อมต่อผู้ให้บริการมีปัญหา

## 🖥️ แอปพลิเคชันเดสก์ท็อป (Electron)

OmniRoute มีให้ใช้งานเป็นแอปพลิเคชันเดสก์ท็อปแบบเนทีฟสำหรับ Windows, macOS และ Linux

### การติดตั้ง

```bash
# จากไดเรกทอรี electron:
cd electron
npm install

# โหมดการพัฒนา (เชื่อมต่อกับเซิร์ฟเวอร์สำหรับการพัฒนา Next.js ที่กำลังทำงานอยู่):
npm run dev

# โหมดโปรดักชัน (ใช้บิลด์แบบสแตนด์อโลน):
npm start
```

### การสร้างตัวติดตั้ง

```bash
cd electron
npm run build          # แพลตฟอร์มปัจจุบัน
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg universal)
npm run build:linux    # Linux (.AppImage)
```

เอาต์พุต → `electron/dist-electron/`

### คุณสมบัติหลัก

| คุณสมบัติ                       | คำอธิบาย                                                            |
| ------------------------------- | ------------------------------------------------------------------- |
| **ความพร้อมของเซิร์ฟเวอร์**     | ตรวจสอบเซิร์ฟเวอร์เป็นระยะก่อนแสดงหน้าต่าง (ไม่มีหน้าจอว่าง)        |
| **ถาดระบบ**                     | ย่อไปยังถาดระบบ เปลี่ยนพอร์ต และออกจากเมนูถาดระบบ                   |
| **การจัดการพอร์ต**              | เปลี่ยนพอร์ตเซิร์ฟเวอร์จากถาดระบบ (รีสตาร์ตเซิร์ฟเวอร์โดยอัตโนมัติ) |
| **นโยบายความปลอดภัยของเนื้อหา** | CSP แบบเข้มงวดผ่านส่วนหัวเซสชัน                                     |
| **อินสแตนซ์เดียว**              | สามารถเรียกใช้แอปได้ครั้งละหนึ่งอินสแตนซ์เท่านั้น                   |
| **โหมดออฟไลน์**                 | เซิร์ฟเวอร์ Next.js ที่รวมมาด้วยสามารถทำงานได้โดยไม่ใช้อินเทอร์เน็ต |
