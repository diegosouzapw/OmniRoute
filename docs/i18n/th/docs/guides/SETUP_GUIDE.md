## วิธีการติดตั้ง

### npm (แนะนำ)

```bash
npm install -g omniroute
omniroute
```

แดชบอร์ดจะเปิดที่ `http://localhost:20128` และ URL ฐานของ API คือ `http://localhost:20128/v1`

### pnpm

```bash
pnpm add -g omniroute@latest --allow-build=better-sqlite3 --allow-build=@swc/core
omniroute
```

> **ผู้ใช้ pnpm:** จำเป็นต้องใช้แฟล็ก `--allow-build` เพื่อเปิดใช้งานสคริปต์การบิลด์แบบเนทีฟสำหรับ `better-sqlite3` และ `@swc/core` คำสั่ง `pnpm approve-builds -g` ไม่รองรับการติดตั้งแบบส่วนกลางบน pnpm v11

### Arch Linux (AUR)

```bash
yay -S omniroute-bin
systemctl --user enable --now omniroute.service
```

[แพ็กเกจ AUR](https://aur.archlinux.org/packages/omniroute-bin) จะติดตั้ง OmniRoute และจัดเตรียมบริการผู้ใช้ systemd

### จากซอร์สโค้ด

```bash
npm install
PORT=20128 DASHBOARD_PORT=20129 NEXT_PUBLIC_BASE_URL=http://localhost:20129 npm run dev
```

> **หมายเหตุสำหรับ Windows:** ตามค่าเริ่มต้น OmniRoute จะใช้ `%APPDATA%\omniroute` เมื่อไม่มีไดเรกทอรีแบบเดิม `%USERPROFILE%\.omniroute` กำหนด `DATA_DIR` เพื่อเลือกตำแหน่งไดเรกทอรีข้อมูลอื่น

> **หมายเหตุ:** `npm install` จะสร้าง `.env` จาก `.env.example` โดยอัตโนมัติเมื่อเรียกใช้ครั้งแรก การติดตั้งครั้งต่อไปจะไม่เขียนทับ `.env` ที่มีอยู่ ดังนั้นการปรับแต่งต่างๆ จะยังคงอยู่ หากต้องการสร้างใหม่จากต้นฉบับ ให้ลบ `.env` ก่อนเรียกใช้อีกครั้ง

### Docker

โปรดดู [คู่มือ Docker](./DOCKER_GUIDE.md) สำหรับการตั้งค่า Docker ฉบับสมบูรณ์ รวมถึงโปรไฟล์ Compose และ Caddy HTTPS

### แอปเดสก์ท็อป (Electron)

OmniRoute มาพร้อมแรปเปอร์เดสก์ท็อปที่สร้างด้วย Electron 41 + electron-builder 26.10 สคริปต์ที่ใช้งานได้ (ที่รากของ workspace):

```bash
npm run electron:dev          # เรียกใช้เดสก์ท็อปพร้อมการโหลดซ้ำอัตโนมัติ
npm run electron:build        # บิลด์สำหรับ OS ปัจจุบัน (ตรวจหาอัตโนมัติ)
npm run electron:build:win    # ตัวติดตั้ง Windows (NSIS + แบบพกพา)
npm run electron:build:mac    # macOS (dmg + zip, arm64+x64)
npm run electron:build:linux  # Linux (AppImage + deb + rpm)
npm run electron:smoke:packaged  # ทดสอบเบื้องต้นสำหรับบิลด์แบบแพ็กเกจ
```

ตัวติดตั้งเดสก์ท็อปแต่ละรุ่นจะแนบมากับ GitHub Releases สำหรับรายละเอียดเชิงลึกทั้งหมดเกี่ยวกับ Electron (การลงนาม บริดจ์ IPC และดิสโทรต่างๆ) โปรดดู [`ELECTRON_GUIDE.md`](./ELECTRON_GUIDE.md) _(สร้างขึ้นในระยะถัดไป)_

### เซิร์ฟเวอร์แบบ Headless (CI/ระบบอัตโนมัติ)

สำหรับการตั้งค่าแบบไม่ต้องมีผู้ดูแล (Docker, Kubernetes, CI) ให้ใช้:

```bash
omniroute setup --non-interactive
omniroute providers test-batch
```

เมื่อใช้ร่วมกับตัวแปรสภาพแวดล้อม (`INITIAL_PASSWORD`, `OMNIROUTE_WS_BRIDGE_SECRET` เป็นต้น) คุณจะสามารถเปิดใช้อินสแตนซ์ OmniRoute ที่ควบคุมทั้งหมดผ่านสคริปต์ได้

### ตัวเลือก CLI

| คำสั่ง                  | คำอธิบาย                                                                                   |
| ----------------------- | ------------------------------------------------------------------------------------------ |
| `omniroute`             | เริ่มเซิร์ฟเวอร์ (`PORT=20128` โดย API และแดชบอร์ดใช้พอร์ตเดียวกัน)                        |
| `omniroute setup`       | ขั้นตอนเริ่มต้นใช้งานผ่าน CLI แบบมีคำแนะนำสำหรับรหัสผ่านและผู้ให้บริการรายแรก              |
| `omniroute doctor`      | เรียกใช้การตรวจสอบสถานะภายในเครื่องโดยไม่ต้องเริ่มเซิร์ฟเวอร์                              |
| `omniroute providers`   | ค้นหา แสดงรายการ ตรวจสอบความถูกต้อง และทดสอบผู้ให้บริการจาก CLI                            |
| `omniroute config`      | การกำหนดค่าเครื่องมือ CLI — แสดงรายการ เรียกดู ตั้งค่า และตรวจสอบความถูกต้องของการกำหนดค่า |
| `omniroute status`      | แดชบอร์ดสถานะแบบออฟไลน์ — เวอร์ชัน ฐานข้อมูล เครื่องมือ และการกำหนดค่า                     |
| `omniroute logs`        | สตรีมบันทึกการใช้งานจาก API (รองรับ `--follow`)                                            |
| `omniroute update`      | ตรวจสอบหรือใช้การอัปเดต OmniRoute                                                          |
| `omniroute provider`    | จัดการการเชื่อมต่อผู้ให้บริการ — เพิ่ม แสดงรายการ ลบ ทดสอบ และตั้งค่าเริ่มต้น              |
| `omniroute --port 3000` | ตั้งค่าพอร์ตหลัก/API เป็น 3000                                                             |
| `omniroute --mcp`       | เริ่มเซิร์ฟเวอร์ MCP (การรับส่งข้อมูลผ่าน stdio)                                           |
| `omniroute --no-open`   | ไม่เปิดเบราว์เซอร์โดยอัตโนมัติ                                                             |
| `omniroute --help`      | แสดงวิธีใช้                                                                                |

การตั้งค่าแบบ Headless สามารถควบคุมผ่านสคริปต์ได้ด้วยแฟล็กหรือตัวแปรสภาพแวดล้อม:

```bash
omniroute setup --non-interactive --password "$OMNIROUTE_PASSWORD"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY" --test-provider
```

เรียกใช้การวินิจฉัยภายในเครื่องโดยไม่ต้องเปิดแดชบอร์ด:

```bash
omniroute doctor
omniroute doctor --json
omniroute doctor --no-liveness
```

จัดการผู้ให้บริการจาก SSH หรือสคริปต์โดยไม่ต้องเปิดแดชบอร์ด:

```bash
omniroute providers available
omniroute providers available --search openai
omniroute providers available --category api-key
omniroute providers list
omniroute providers test <id-or-name>
omniroute providers test-all
omniroute providers validate
```

## การกำหนดค่าเครื่องมือ CLI

### 1) เชื่อมต่อผู้ให้บริการและสร้างคีย์ API

1. เปิดแดชบอร์ด → `Providers` แล้วเชื่อมต่อผู้ให้บริการอย่างน้อยหนึ่งราย (OAuth หรือคีย์ API)
2. เปิดแดชบอร์ด → `Endpoints` แล้วสร้างคีย์ API
3. (ไม่บังคับ) เปิดแดชบอร์ด → `Combos` แล้วกำหนดลำดับสำรองของคุณ

### 2) กำหนดค่าเครื่องมือเขียนโค้ดของคุณ

```txt
URL ฐาน:   http://localhost:20128/v1
คีย์ API:  [คัดลอกจากหน้า Endpoint]
โมเดล:     if/qwen3.8-max-preview (หรือคำนำหน้าผู้ให้บริการ/โมเดลใดก็ได้)
```

หากเอดิเตอร์ของคุณไม่สามารถส่ง `Authorization: Bearer ...` ได้ ให้ใช้ URL ฐานสำหรับความเข้ากันได้แบบมีโทเค็นแทน:

```txt
URL ฐาน: http://localhost:20128/api/v1/vscode/YOUR_KEY/
URL โมเดล: http://localhost:20128/api/v1/vscode/YOUR_KEY/models
URL แชต: http://localhost:20128/api/v1/vscode/YOUR_KEY/chat/completions
URL แท็ก Ollama: http://localhost:20128/api/v1/vscode/YOUR_KEY/api/tags
```

ใช้งานได้กับ Claude Code, Codex CLI, Cursor, Cline, OpenClaw, OpenCode และ SDK ที่เข้ากันได้กับ OpenAI

#### กำหนดค่าอัตโนมัติด้วย `setup-*`

แทนที่จะวาง URL ฐานและคีย์ด้วยตนเอง ให้ OmniRoute เขียนการกำหนดค่าเฉพาะของแต่ละเครื่องมือ
จากแค็ตตาล็อกโมเดลที่ใช้งานอยู่ โดยใช้หนึ่งคำสั่งต่อหนึ่งเครื่องมือ:

```bash
omniroute setup-codex        # โปรไฟล์ ~/.codex/<name>.config.toml
omniroute setup-claude       # ~/.claude/profiles/<name>/settings.json
omniroute setup-opencode     # ~/.config/opencode/opencode.json (เข้ากันได้กับ OpenAI)
omniroute setup-cline        # การตั้งค่า Cline CLI + ส่วนขยาย VS Code
omniroute setup-kilo         # Kilo Code
omniroute setup-continue     # ~/.continue/config.yaml (Continue / cn)
omniroute setup-cursor       # แสดงขั้นตอนภายในแอปของ Cursor
omniroute setup-roo          # การนำเข้า Roo Code + ตัวชี้ autoImport
omniroute setup-crush        # ~/.config/crush/crush.json
omniroute setup-goose        # ~/.config/goose/config.yaml
omniroute setup-aider        # ~/.aider.conf.yml
omniroute setup-qwen         # ~/.qwen/settings.json + ~/.qwen/.env
```

แต่ละคำสั่งรองรับ `--remote <url> --api-key <key>` เพื่อกำหนดค่าเครื่องมือภายในเครื่องให้ทำงานกับ
OmniRoute **ระยะไกล** รวมถึง `--dry-run` สำหรับดูตัวอย่าง หากต้องการเปิด CLI โดยฉีดค่า
สภาพแวดล้อมที่ถูกต้องและไม่เขียนการกำหนดค่าใดๆ เลย ให้ใช้ตัวเรียกใช้งานทั่วไป
`omniroute run <target>` (claude, codex, aider, goose, opencode, qwen, gemini);
ตัวเรียกใช้งานเฉพาะเครื่องมือแบบเดิม `omniroute launch` (Claude Code) และ
`omniroute launch-codex` (Codex) ยังคงพร้อมใช้งาน

สำหรับตารางฉบับเต็ม (สิ่งที่แต่ละคำสั่งเขียน แฟล็กทั้งหมด แบบภายในเครื่องเทียบกับระยะไกล และรูปแบบ URL ฐาน
`/v1`) โปรดดู **[การผสานรวม CLI](./CLI-INTEGRATIONS.md)**

สำหรับการกำหนดค่าโดยละเอียดของแต่ละเครื่องมือ (Claude Code, Codex CLI, Cursor, Cline, OpenClaw, Kilo Code, Copilot และอื่นๆ) โปรดดู **[คู่มือเครื่องมือ CLI](../reference/CLI-TOOLS.md)** โดยเฉพาะ

## การตั้งค่าโปรโตคอล (MCP + A2A)

### การตั้งค่า MCP (Model Context Protocol)

เริ่มการรับส่งข้อมูล MCP ในโหมด stdio:

```bash
omniroute --mcp
```

ขั้นตอนการตรวจสอบที่แนะนำ:

```bash
# 1. เริ่มเซิร์ฟเวอร์ MCP
omniroute --mcp

# 2. เรียกใช้จากไคลเอนต์ MCP ของคุณ:
omniroute_get_health        # ควรส่งคืนสถานะความสมบูรณ์ของระบบ
omniroute_list_combos       # ควรส่งคืนคอมโบที่ใช้งานอยู่

# 3. หรือเรียกใช้ชุดทดสอบ E2E แบบเต็ม:
npm run test:protocols:e2e
```

#### การกำหนดค่าไคลเอนต์ MCP

**Claude Code:**

```bash
claude mcp add-server omniroute --type http --url http://localhost:20128/api/mcp/stream
```

**Cursor / Cline:**

เพิ่มลงในการตั้งค่า MCP ของคุณ:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"],
      "env": {}
    }
  }
}
```

**เอกสาร MCP ฉบับเต็ม:** [README ของเซิร์ฟเวอร์ MCP](../../open-sse/mcp-server/README.md) — เครื่องมือ 110 รายการ การกำหนดค่า IDE และไคลเอนต์ Python/TS/Go

### การตั้งค่า A2A (Agent-to-Agent Protocol)

ตรวจสอบ Agent Card:

```bash
curl http://localhost:20128/.well-known/agent.json
```

ส่งงาน:

```bash
curl -X POST http://localhost:20128/a2a \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":"quickstart","method":"message/send","params":{"skill":"quota-management","messages":[{"role":"user","content":"Give me a short quota summary."}]}}'
```

**เอกสาร A2A ฉบับเต็ม:** [README ของเซิร์ฟเวอร์ A2A](../../src/lib/a2a/README.md) — JSON-RPC 2.0, ทักษะ, การสตรีม และวงจรชีวิตของงาน

## การกำหนดค่าการหมดเวลา

### การหมดเวลาพื้นฐาน

สำหรับการปรับใช้ส่วนใหญ่ คุณต้องใช้ตัวแปรเพียงสองรายการนี้:

| ตัวแปร                   | ค่าเริ่มต้น                    | วัตถุประสงค์                                                                                                                                               |
| ------------------------ | ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `REQUEST_TIMEOUT_MS`     | `600000`                       | ค่าพื้นฐานร่วมสำหรับการหมดเวลาขณะรอการตอบสนองเริ่มต้นจาก upstream, การหมดเวลาภายในของ Undici, คำขอ TLS fingerprint และการหมดเวลาของคำขอ/พร็อกซี API bridge |
| `STREAM_IDLE_TIMEOUT_MS` | สืบทอดจาก `REQUEST_TIMEOUT_MS` | ช่วงเวลาสูงสุดระหว่าง chunk ของสตรีม ก่อนที่ OmniRoute จะยกเลิกสตรีม SSE                                                                                   |

ยังคงรองรับความเข้ากันได้แบบย้อนหลัง: `FETCH_TIMEOUT_MS`, `API_BRIDGE_PROXY_TIMEOUT_MS` และตัวแปรการหมดเวลาระดับเลเยอร์อื่นๆ ที่มีอยู่เดิมยังคงใช้งานได้ และจะเขียนทับค่าพื้นฐานร่วม

### หมายเหตุเฉพาะผู้ให้บริการ

สำหรับ upstream ที่เข้ากันได้กับ Claude Code (`anthropic-compatible-cc-*`) OmniRoute จะสร้างส่วนหัว `X-Stainless-Timeout` ขาออกจากค่าการหมดเวลาการดึงข้อมูลที่คำนวณแล้ว เพื่อให้การหมดเวลาการอ่านฝั่งผู้ให้บริการสอดคล้องกับการกำหนดค่า env ของคุณ

สำหรับ reverse proxy ของบุคคลที่สามที่เข้ากันได้กับ Claude Code นั้น OmniRoute จะคงชุด `anthropic-beta` เริ่มต้นไว้อย่างรัดกุม และเมื่อปล่อย `Client Cache Control` ไว้ที่ `Auto` จะส่งต่อเฉพาะเครื่องหมาย `cache_control` ที่ไคลเอนต์ระบุเท่านั้น เปิดสวิตช์ "Enable redact-thinking beta" สำหรับแต่ละการเชื่อมต่อเฉพาะเมื่อ upstream ต้องการสตรีมกระบวนการคิดของ Claude ที่ผ่านการปกปิดโดยเฉพาะ

### การเขียนทับการหมดเวลาขั้นสูง

| ตัวแปร                                   | ค่าเริ่มต้น                                  | วัตถุประสงค์                                                                         |
| ---------------------------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------ |
| `FETCH_TIMEOUT_MS`                       | สืบทอดจาก `REQUEST_TIMEOUT_MS`               | การหมดเวลาขณะรอการตอบสนองเริ่มต้นจาก upstream ซึ่งใช้จนกว่าจะได้รับส่วนหัวการตอบสนอง |
| `FETCH_HEADERS_TIMEOUT_MS`               | สืบทอดจาก `FETCH_TIMEOUT_MS`                 | ขีดจำกัดเวลาของ Undici สำหรับการรับส่วนหัวการตอบสนองจาก upstream                     |
| `FETCH_BODY_TIMEOUT_MS`                  | สืบทอดจาก `FETCH_TIMEOUT_MS`                 | ขีดจำกัดเวลาของ Undici ระหว่าง chunk ของเนื้อหา upstream (`0` หมายถึงปิดใช้งาน)      |
| `FETCH_CONNECT_TIMEOUT_MS`               | `30000`                                      | การหมดเวลาการเชื่อมต่อ TCP ของ Undici                                                |
| `FETCH_KEEPALIVE_TIMEOUT_MS`             | `4000`                                       | การหมดเวลาของซ็อกเก็ต keep-alive ที่ไม่มีการใช้งานของ Undici                         |
| `TLS_CLIENT_TIMEOUT_MS`                  | สืบทอดจาก `FETCH_TIMEOUT_MS`                 | การหมดเวลาสำหรับคำขอ TLS fingerprint ที่ส่งผ่าน `wreq-js`                            |
| `API_BRIDGE_PROXY_TIMEOUT_MS`            | สืบทอดจาก `REQUEST_TIMEOUT_MS` หรือ `600000` | การหมดเวลาสำหรับการส่งต่อพร็อกซี `/v1` จากพอร์ต API ไปยังพอร์ตแดชบอร์ด               |
| `API_BRIDGE_SERVER_REQUEST_TIMEOUT_MS`   | `max(API_BRIDGE_PROXY_TIMEOUT_MS, 300000)`   | การหมดเวลาของคำขอขาเข้าบนเซิร์ฟเวอร์ API bridge                                      |
| `API_BRIDGE_SERVER_HEADERS_TIMEOUT_MS`   | `60000`                                      | การหมดเวลาของส่วนหัวขาเข้าบนเซิร์ฟเวอร์ API bridge                                   |
| `API_BRIDGE_SERVER_KEEPALIVE_TIMEOUT_MS` | `5000`                                       | การหมดเวลา keep-alive บนเซิร์ฟเวอร์ API bridge                                       |
| `API_BRIDGE_SERVER_SOCKET_TIMEOUT_MS`    | `0`                                          | การหมดเวลาเมื่อซ็อกเก็ตไม่มีกิจกรรมบนเซิร์ฟเวอร์ API bridge (`0` หมายถึงปิดใช้งาน)   |

> **หมายเหตุ:** สำหรับคำขอแบบสตรีม `FETCH_TIMEOUT_MS` จะครอบคลุมเฉพาะการตั้งค่าการเชื่อมต่อ / การรอการตอบสนองแรกจาก upstream เท่านั้น เมื่อสตรีมเริ่มทำงานแล้ว OmniRoute จะยกเลิกเฉพาะเมื่อเกิดการหยุดชะงักจริง (`STREAM_IDLE_TIMEOUT_MS`) หรือเมื่อเนื้อหา Undici ไม่มีกิจกรรม (`FETCH_BODY_TIMEOUT_MS`)

### ความเข้ากันได้กับ Reverse Proxy

หากคุณใช้งาน OmniRoute อยู่หลัง Nginx, Caddy, Cloudflare หรือ reverse proxy อื่นๆ โปรดตรวจสอบให้แน่ใจว่าค่าการหมดเวลาของพร็อกซีสูงกว่าค่าการหมดเวลาของสตรีม/การดึงข้อมูลของ OmniRoute ด้วย

## เทมเพลตสำหรับ Void Linux (xbps-src)

สำหรับผู้ใช้ Void Linux คุณสามารถสร้างแพ็กเกจแบบเนทีฟโดยใช้ `xbps-src` ได้ บันทึกบล็อกนี้เป็น `srcpkgs/omniroute/template`:

```bash
# ไฟล์เทมเพลตสำหรับ 'omniroute'
pkgname=omniroute
version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"
maintainer="zenobit <zenobit@disroot.org>"
license="MIT"
homepage="https://github.com/diegosouzapw/OmniRoute"
distfiles="https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz"
# สร้าง checksum ใหม่สำหรับแต่ละรีลีสด้วย:
#   curl -L -o /tmp/omniroute.tar.gz "https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz" && sha256sum /tmp/omniroute.tar.gz
checksum=PLACEHOLDER_REGENERATE_PER_RELEASE
system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	NODE_ENV=development npm ci --ignore-scripts
	npm run build
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	rm -rf .next/standalone/node_modules/@img

	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
		touch "${DESTDIR}/usr/lib/omniroute/${_d}/.keep"
	done

	cat > "${WRKDIR}/omniroute" <<'EOF'
#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"
mkdir -p "${DATA_DIR}"
exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```
