> **สรุปสั้นๆ**: OmniRoute จัดอันดับผู้ให้บริการ **ฟรี** ตามคุณภาพของโมเดลโดยใช้ **คะแนน ELO
> จาก Arena AI (รูปแบบเดียวกับ LMArena)** เปิดหน้า **Free Provider Rankings** ใน
> แดชบอร์ดเพื่อดูว่าผู้ให้บริการฟรีรายใดมีโมเดลที่ทรงประสิทธิภาพที่สุดสำหรับงานของคุณ —
> ทั้งในภาพรวมหรือกรองตามหมวดหมู่ (การเขียนโค้ด การรีวิว การจัดทำเอกสาร การดีบัก)

## คืออะไร

OmniRoute ลงทะเบียนผู้ให้บริการไว้ 329 ราย ซึ่งรวมถึงรายการในแค็ตตาล็อก 155 รายการที่ระบุว่า **ฟรี/ไม่ต้องยืนยันตัวตน**
(no-auth,
OAuth ระดับฟรี หรือ API key ระดับฟรี — ดู
[คู่มือระดับฟรี](../getting-started/FREE-TIERS-GUIDE.md) และ
[ไดเรกทอรีระดับฟรี](../reference/FREE_TIERS.md) ฉบับเต็ม) แต่ประเด็นสำคัญคือ ผู้ให้บริการฟรีมี
คุณภาพของโมเดลแตกต่างกันอย่างมาก ผู้ให้บริการแบบไม่ต้องยืนยันตัวตนที่ให้บริการโมเดลระดับแนวหน้า
มีประโยชน์มากกว่าผู้ให้บริการที่ให้บริการโมเดลรุ่นเก่าขนาดเล็กอย่างมาก

**Free Provider Rankings** ตอบคำถามว่า "**ผู้ให้บริการฟรีรายใดมอบโมเดลที่ดีที่สุดให้ฉัน?**" โดย
เชื่อมโยงแค็ตตาล็อกของผู้ให้บริการฟรีแต่ละรายเข้ากับ **คะแนนคุณภาพที่รวบรวมจากชุมชน** จาก
**ลีดเดอร์บอร์ด Arena AI** (ELO จากความชอบของมนุษย์ ซึ่งเป็นแนวคิดเดียวกับที่อยู่เบื้องหลัง
สนามประลองแชตบอต LMArena) จากนั้นผู้ให้บริการจะถูกจัดอันดับตามความสามารถของ **โมเดลฟรีที่ดีที่สุด** ของตน

การจัดอันดับคำนวณจากแหล่งข้อมูลจริงสามแหล่ง:

1. รายชื่อผู้ให้บริการฟรี — `NOAUTH_PROVIDERS` รวมถึงรายการ `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` ที่มีแฟล็ก `hasFree`
   (`src/shared/constants/providers.ts`)
2. แค็ตตาล็อกโมเดลของผู้ให้บริการแต่ละรายจากรีจิสทรีผู้ให้บริการ
   (`open-sse/config/providerRegistry.ts`)
3. คะแนนความเหมาะสมกับงานที่คำนวณจาก ELO ซึ่งจัดเก็บไว้ในตาราง DB `model_intelligence` โดย
   เอนจินซิงก์ Arena ELO (`src/lib/arenaEloSync.ts`)

ตรรกะการเชื่อมโยงอยู่ใน `src/lib/freeProviderRankings.ts`

## วิธีเข้าถึง

### หน้าแดชบอร์ด

เปิดแดชบอร์ดแล้วไปที่ **Costs → Free Provider Rankings** หรือไปยังเส้นทางต่อไปนี้โดยตรง:

```
/dashboard/free-provider-rankings
```

หน้า (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) แสดง:

- **โพเดียม 3 อันดับแรก** (🥇 🥈 🥉) ของผู้ให้บริการฟรีที่ได้รับการจัดอันดับสูงสุด
- **ตารางจัดอันดับ** ฉบับเต็มพร้อมคอลัมน์: **อันดับ**, **ผู้ให้บริการ**, **โมเดลยอดนิยม**,
  **คะแนน**, **คะแนนเฉลี่ย**, **โมเดล**, **ประเภท**
- **ปุ่มกรองหมวดหมู่**: _ทุกหมวดหมู่_, _ค่าเริ่มต้น_, _การเขียนโค้ด_, _การรีวิว_,
  _การจัดทำเอกสาร_, _การดีบัก_

ป้าย **ประเภท** ของผู้ให้บริการแต่ละรายบอกให้ทราบว่าให้บริการฟรีในรูปแบบใด:

| ป้าย     | ความหมาย                                             |
| -------- | ---------------------------------------------------- |
| `NOAUTH` | ฟรีตลอดเวลา โดยไม่ต้องใช้ข้อมูลประจำตัว              |
| `OAUTH`  | ผู้ให้บริการ OAuth ที่มีระดับฟรี (`hasFree`)         |
| `APIKEY` | ผู้ให้บริการที่ใช้ API key และมีระดับฟรี (`hasFree`) |

คะแนนจะแสดงเป็นป้ายกำกับที่มนุษย์อ่านเข้าใจได้ (เช่น _ยอดเยี่ยมที่สุด_, _ยอดเยี่ยม_, _ดีมาก_,
_ดี_, _ปานกลาง_) แทนตัวเลขดิบ เนื่องจากค่าพื้นฐานเป็นคุณภาพการจัดอันดับเชิงสัมพัทธ์
ไม่ใช่เปอร์เซ็นต์

### API endpoint

หน้านี้ใช้ endpoint สำหรับการอ่านแบบสาธารณะ
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

พารามิเตอร์คิวรี (ตรวจสอบความถูกต้องด้วย Zod):

| พารามิเตอร์ | ประเภท | ค่าเริ่มต้น | หมายเหตุ                                                                                                              |
| ----------- | ------ | ----------- | --------------------------------------------------------------------------------------------------------------------- |
| `category`  | string | (ไม่มี)     | ค่าใดค่าหนึ่งใน `default`, `coding`, `review`, `documentation`, `debugging` ละเว้นพารามิเตอร์นี้สำหรับการจัดอันดับรวม |
| `limit`     | number | `50`        | จำกัดให้อยู่ในช่วง `1–100`                                                                                            |

รูปแบบการตอบกลับ:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` คือค่า Arena ELO ดั้งเดิม ส่วน `score` คือค่าความเหมาะสมกับงานที่ผ่านการปรับมาตรฐานแล้ว
(ดูด้านล่าง) ผู้ให้บริการที่ไม่มีโมเดลซึ่งได้รับคะแนนจะไม่รวมอยู่ในการตอบกลับ

## คะแนนทำงานอย่างไร

### แหล่งที่มา: ลีดเดอร์บอร์ด Arena AI

เอนจินซิงค์ Arena ELO (`src/lib/arenaEloSync.ts`) ดึงลีดเดอร์บอร์ดสองรายการ ได้แก่ `text`
และ `code` จาก API ลีดเดอร์บอร์ด Arena AI
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) แต่ละรายการในลีดเดอร์บอร์ด
ประกอบด้วยชื่อโมเดล ผู้ให้บริการ `score` แบบ ELO ช่วงความเชื่อมั่น และจำนวนโหวต

หมวดหมู่ของลีดเดอร์บอร์ดจะจับคู่กับหมวดหมู่งานของ OmniRoute ดังนี้:

| ลีดเดอร์บอร์ด Arena | หมวดหมู่งาน OmniRoute                             |
| ------------------- | ------------------------------------------------- |
| `text`              | `default`, `review`, `documentation`, `debugging` |
| `code`              | `coding`                                          |

### การปรับให้อยู่ในมาตรฐานเดียวกัน (คะแนนความเหมาะสมกับงาน)

คะแนน ELO ดิบจะถูกปรับแยกตามแต่ละลีดเดอร์บอร์ดให้เป็น **ค่าความเหมาะสมกับงานในช่วง `[0.4, 0.98]`**:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

คะแนนจะไม่ถึง `0` หรือ `1` เพื่อเผื่อช่วงสำหรับการกำหนดค่าแทนที่โดยผู้ใช้ ค่านี้คือฟิลด์
`score` ที่คุณเห็นในการตอบกลับจาก API และเป็นป้ายกำกับที่แสดงบนแดชบอร์ด

### ความเชื่อมั่น

แต่ละรายการจะได้รับระดับความเชื่อมั่นตามจำนวนโหวตใน Arena:

| ความเชื่อมั่น | จำนวนโหวต |
| ------------- | --------- |
| `high`        | ≥ 5,000   |
| `medium`      | ≥ 1,000   |
| `low`         | < 1,000   |

### การจัดเก็บและความใหม่ของข้อมูล

รายการที่ผ่านการปรับให้อยู่ในมาตรฐานเดียวกันจะถูกเขียนลงในตาราง DB `model_intelligence` โดยมี
`source = "arena_elo"` (`src/lib/db/modelIntelligence.ts`) รายการจะ **หมดอายุหลังจาก
7 วัน** ดังนั้นผู้ให้บริการที่หยุดซิงค์จะหายไปในที่สุด แทนที่จะยังคงให้บริการ
ข้อมูลที่ล้าสมัย

การซิงค์จะ **เปิดใช้งานโดยค่าเริ่มต้น**:

- การซิงค์จะทำงานหนึ่งครั้งเมื่อเซิร์ฟเวอร์เริ่มต้น จากนั้นทำงานตามตัวจับเวลาเป็นระยะ
  (`src/lib/arenaEloSync.ts` ซึ่งเชื่อมต่อจาก `src/instrumentation-node.ts`)
- การซิงค์ **ไม่ปิดกั้นการทำงานและไม่ทำให้ระบบล้มเหลว** — หากการดึงข้อมูลจากต้นทางล้มเหลว OmniRoute จะยังคง
  ทำงานต่อ และการจัดอันดับจะแสดงข้อมูลล่าสุดที่ใช้ได้ (หรือสถานะว่าง) เท่านั้น

ตัวแปรสภาพแวดล้อมสองตัวใช้ควบคุมการทำงานนี้ (มีเอกสารกำกับใน
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)):

| ตัวแปร                    | ค่าเริ่มต้น   | วัตถุประสงค์                                    |
| ------------------------- | ------------- | ----------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | ตั้งค่าเป็น `false` เพื่อปิดการซิงค์ข้อมูลขาออก |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | ช่วงเวลาการซิงค์ หน่วยเป็นวินาที                |

### การซิงค์ด้วยตนเอง / สถานะ / การล้างข้อมูล

สำหรับผู้ดูแลระบบ เอนด์พอยต์การจัดการที่ต้องผ่านการยืนยันตัวตนรองรับการควบคุมด้วยตนเอง
(`src/app/api/intelligence/sync/route.ts` — ต้องมีการยืนยันตัวตนสำหรับการจัดการ):

```
GET    /api/intelligence/sync          # สถานะการซิงค์ปัจจุบัน (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # เรียกใช้การซิงค์ด้วยตนเอง; เนื้อหา: { "dryRun": true } เพื่อดูตัวอย่างโดยไม่เขียนข้อมูล
DELETE /api/intelligence/sync          # ล้างรายการข้อมูลอัจฉริยะ arena_elo ที่ซิงค์ทั้งหมด
```

หากหน้าการจัดอันดับว่างเปล่า การส่ง `POST /api/intelligence/sync` ด้วยตนเอง (หรือเพียง
รีสตาร์ตเซิร์ฟเวอร์) จะเติมข้อมูลกลับเข้าไปอีกครั้ง

### การจับคู่โมเดลกับลีดเดอร์บอร์ด

ID โมเดลในรีจิสทรีและชื่อโมเดลใน Arena อาจไม่ตรงกันทุกประการ การจัดอันดับใช้
การจับคู่แบบยืดหยุ่น (`findMatchingIntelligence` ใน `src/lib/freeProviderRankings.ts`):

1. จับคู่แบบตรงกันทุกประการด้วย ID โมเดลที่ผ่านการปรับรูปแบบแล้ว
2. จับคู่หลังจากตัดคำต่อท้ายเวอร์ชันที่ส่วนท้ายออก (เช่น `kimi-k2.6` → `kimi-k2`)
3. จับคู่ด้วยคำนำหน้า (ชื่อโมเดลในลีดเดอร์บอร์ดเป็นคำนำหน้าของ ID ในรีจิสทรี)

ในฝั่งการซิงค์ คำนำหน้าผู้ให้บริการที่รู้จัก (`anthropic/`, `openai/`, `google/`, …) จะถูก
ตัดออก และแมปนามแฝงขนาดเล็กจะขยายชื่อมาตรฐานเป็นรูปแบบชื่อต่าง ๆ ที่ OmniRoute ใช้
ภายใน เพื่อให้ค้นหาโมเดลได้ไม่ว่าจะใช้ชื่อใดก็ตาม

### วิธีจัดอันดับผู้ให้บริการ

สำหรับผู้ให้บริการฟรีแต่ละราย เอนจินจะให้คะแนนทุกโมเดลในแค็ตตาล็อก จากนั้น:

- **โมเดลยอดนิยม** = โมเดลของผู้ให้บริการที่มีคะแนนสูงสุด
- **คะแนนเฉลี่ย** = ค่าเฉลี่ยของคะแนนจากโมเดลทั้งหมดของผู้ให้บริการที่ได้รับการให้คะแนน
- **โมเดล** = จำนวนโมเดลของผู้ให้บริการที่มีคะแนนจาก Arena

ผู้ให้บริการจะถูกเรียงตาม **คะแนนโมเดลยอดนิยม** ก่อน แล้วจึงเรียงตามคะแนนเฉลี่ย วิธีนี้ให้ความสำคัญกับ
ผู้ให้บริการที่มีโมเดลฟรีประสิทธิภาพสูงอย่างน้อยหนึ่งโมเดล

## การใช้ข้อมูลนี้เพื่อเลือกผู้ให้บริการฟรี

1. **เลือกหมวดหมู่ที่เหมาะสม** ใช้ตัวกรอง **Coding** สำหรับเวิร์กโหลดแบบเอเจนต์/งานเขียนโค้ด หรือ
   คงไว้ที่ **All Categories** / **Default** สำหรับการแชททั่วไป ผู้ให้บริการรายเดียวกันอาจ
   มีอันดับแตกต่างกันในแต่ละหมวดหมู่ เนื่องจากโมเดลอันดับสูงสุดของผู้ให้บริการจะแตกต่างกันไปตามแต่ละลีดเดอร์บอร์ด
2. **เลือกผู้ให้บริการบนโพเดียมสำหรับการตั้งค่าแบบครั้งเดียว** หากคุณต้องการเชื่อมต่อผู้ให้บริการฟรี
   เพียงหนึ่งหรือสองราย ให้เริ่มจากรายที่มีอันดับสูงสุดในหมวดหมู่ของคุณ
3. **ตรวจสอบป้าย Type** ผู้ให้บริการ `NOAUTH` เชื่อมต่อได้รวดเร็วที่สุด (ไม่ต้องใช้
   ข้อมูลประจำตัว) แพ็กเกจฟรีแบบ `OAUTH` / `APIKEY` ต้องสมัครใช้งานอย่างรวดเร็ว แต่มักเปิดให้ใช้
   โมเดลที่มีประสิทธิภาพสูงกว่า ดูขั้นตอนการเชื่อมต่อได้ที่ [คู่มือแพ็กเกจฟรี](../getting-started/FREE-TIERS-GUIDE.md)
4. **เชื่อมต่อหลายรายแล้วให้ Auto-Combo ตัดสินใจ** ข้อมูล Arena ELO ชุดเดียวกับที่ขับเคลื่อน
   หน้านี้ยังถูกนำไปใช้เป็น **ปัจจัยความเหมาะสมกับงาน** ของเอนจินให้คะแนน Auto-Combo
   (`open-sse/services/autoCombo/taskFitness.ts`, ลำดับการพิจารณา
   `user_override → arena_elo → models_dev_tier → static table`) ดังนั้น หลังจากเชื่อมต่อ
   ผู้ให้บริการฟรีอันดับต้น ๆ แล้ว การกำหนดเส้นทางด้วย `model: "auto"` (เช่น `auto/coding`) จะ
   เลือกใช้โมเดลฟรีที่มีคุณภาพสูงกว่าสำหรับแต่ละคำขอโดยอัตโนมัติ ดูรายละเอียดการให้คะแนนครบทั้ง 16 ปัจจัยได้ที่
   [Auto-Combo](../routing/AUTO-COMBO.md)
