`devin-cli-agentic` ช่วยให้รันไทม์ Claude Code จริงสามารถใช้เอนด์พอยต์ Anthropic
Messages ภายในเครื่องของ OmniRoute ขณะที่ Devin CLI อย่างเป็นทางการส่งการตอบกลับของโมเดลผ่าน ACP stdio โดย
ไม่แก้ไขผู้ให้บริการ Anthropic, Claude OAuth, Claude Web หรือ `devin-cli` ที่มีอยู่

> **สถานะปัจจุบัน: ตรึง Claude Code ไว้ที่ `2.1.258`; การตรวจสอบแบบออฟไลน์และแบบใช้งานจริงล่าสุดถูกบันทึก
> ไว้บน `2.1.220`** การตรึงเวอร์ชัน `2.1.220` ทำงานครบสามสถานการณ์ที่แยกจากกันผ่าน Devin CLI
> `3000.2.17` และโมเดล `swe-1-7-lightning`; การทดสอบแบบใช้งานจริงครั้งสุดท้ายนั้นยืนยันเทิร์น `Read`,
> `Edit` และ `Bash` ที่ควบคุมโดยไคลเอนต์, ผลลัพธ์ `npm test` ที่สำเร็จ, การค้นพบคำสั่งและสกิล
> ของโปรเจกต์, การกำหนดเส้นทางไปยัง Devin เท่านั้น และไม่มีทราฟฟิกขาออกไปยัง Claude จากนั้นจึงเพิ่มเวอร์ชันที่ตรึงเป็น `2.1.258`
> (รุ่น CLI ที่ข้อมูลระบุตัวตน Claude ของ OmniRoute เลียนแบบ และรุ่นแรกที่รองรับระดับ Fable 5.1
> โดยตรง) สำหรับเวอร์ชันที่ตรึงใหม่นี้ ได้ตรวจสอบเลเยอร์การติดตั้งและ `claude --version`
> บนอิมเมจฐานที่ตรึงไว้แล้ว และชุดทดสอบหน่วยของบริดจ์, `compose config` ตลอดจน
> หลักฐานการแยกระบบแบบสแตติกก็ผ่านทั้งหมด — แต่ยังไม่ได้เรียกใช้สถานการณ์จำลองแบบออฟไลน์และ
> ชุดทดสอบแบบใช้งานจริงสามสถานการณ์ซ้ำ โปรดเรียกใช้ใหม่ (ดู "การอัปเดตเครื่องมือที่ตรึงไว้") ก่อนใช้งาน
> บริดจ์กับเวอร์ชันที่ตรึงนี้โดยวางใจในผลลัพธ์

## สถาปัตยกรรม

```text
Claude Code 2.1.258 (คอนเทนเนอร์ Linux แบบ non-root ที่แยกจากระบบ)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (ผู้ให้บริการรูปแบบ Claude ที่ไม่ต้องยืนยันตัวตน)
  -> devin acp --agent-type summarizer (ACP stdio อย่างเป็นทางการ ไม่มีเครื่องมือ Devin)
  -> บัญชี Devin ในวอลุ่ม devin-auth โดยเฉพาะ
```

เอเจนต์ ACP เริ่มต้นของ CLI อย่างเป็นทางการสามารถเรียกใช้เครื่องมือของตนเองได้ ดังนั้นบริดจ์นี้จึงไม่ใช้
เอเจนต์ดังกล่าว แต่จะเริ่มเอเจนต์ ACP แบบคงที่ชื่อ `summarizer` ซึ่งโหมด CLI อย่างเป็นทางการไม่มีเครื่องมือ และ
จัดเฟรมคำขอ Anthropic ที่ผ่านการซีเรียลไลซ์ให้อยู่ในรูปของร่องรอยการดำเนินการ เมื่อจำเป็นต้องมีการดำเนินการอื่น
ที่ควบคุมโดย Claude การตอบกลับต้องมีเอนเวโลปเครื่องมือไคลเอนต์เพียงหนึ่งรายการเท่านั้น `tool_call` หรือ
`tool_call_update` ใดๆ จาก ACP จะถูกปฏิเสธก่อนที่จะสามารถรายงานว่าการตอบกลับ
สำเร็จได้

ซีเรียลไลเซอร์ใน `open-sse/executors/devin-agentic/serializer.ts` จะคง `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` และ
เครื่องมือที่ Claude Code จัดเตรียมไว้ รูปภาพและบล็อกที่ไม่รู้จักจะทำให้ล้มเหลวอย่างชัดเจน ผลลัพธ์จากเครื่องมือ
ที่มีขนาดใหญ่จะใช้เครื่องหมายระบุการตัดทอนที่มองเห็นได้

พาร์เซอร์ยอมรับเอนเวโลป `<tool>{...}</tool>` ที่อยู่เดี่ยวได้หนึ่งรายการต่อเทิร์นของโมเดล โดยจะตรวจสอบ
ชื่อกับรายการเครื่องมือของคำขอ ตรวจสอบความถูกต้องของอาร์กิวเมนต์ตาม JSON
Schema ของเครื่องมือนั้น ปฏิเสธการผสมข้อความบรรยายกับการดำเนินการ และอนุญาตให้ซ่อมแซมได้หนึ่งครั้งภายในขอบเขตที่กำหนด จากนั้น Claude Code
จะเรียกใช้ `tool_use` ของ Anthropic ที่ได้ภายในเครื่อง และส่ง `tool_result` กลับผ่าน
OmniRoute

## การแยกระบบและแบบจำลองภัยคุกคาม

การติดตั้ง บัญชี และการกำหนดค่า Claude ของโฮสต์อยู่นอกขอบเขตและถือว่า
ห้ามเข้าถึง บริการ Compose จะ:

- ทำงานด้วย UID/GID `10001:10001` โดยมีระบบไฟล์รูทแบบอ่านอย่างเดียว ลดสิทธิ์ความสามารถ และใช้
  `no-new-privileges`;
- ใช้ `/home/bridge` ส่วนตัว, วอลุ่มการกำหนดค่า Claude โดยเฉพาะ, ข้อมูล OmniRoute ที่แยกต่างหาก
  และวอลุ่ม `devin-auth` แยกต่างหาก;
- เมานต์เฉพาะเวิร์กสเปซ/หลักฐาน `.sandbox` ที่สามารถทิ้งได้;
- ไม่เมานต์โฮมของโฮสต์, Keychain, SSH, ข้อมูลรับรองคลาวด์ หรือซ็อกเก็ต Docker;
- สร้างสภาพแวดล้อมอย่างชัดเจนและลบตัวแปร API/OAuth/การกำหนดเส้นทางของ Anthropic;
- กำหนดให้การอนุมานของ Claude Code ไปยัง `http://omniroute:20128` เท่านั้น โดยใช้คีย์ที่ใช้ได้เฉพาะภายในเครื่อง

โปรไฟล์ออฟไลน์ใช้เครือข่ายภายใน สำหรับโปรไฟล์แบบใช้งานจริง OmniRoute จะเข้าถึง
เอนด์พอยต์ Devin อย่างเป็นทางการผ่าน `network-guard` เท่านั้น และปลายทางอื่นที่ไม่เกี่ยวข้องจะถูกปฏิเสธ
Claude Code มีตัวควบคุมทราฟฟิกขาออกแบบปฏิเสธทั้งหมดแยกต่างหาก และสามารถเข้าถึงได้เฉพาะบริการ OmniRoute
ภายในเครื่องผ่าน `NO_PROXY` ไฟล์บันทึกการตรวจสอบของตัวควบคุมจะถูกเมานต์โดยกระบวนการตัวควบคุมของไฟล์เหล่านั้นเท่านั้น
สคริปต์จะตรวจสอบความเป็นเจ้าของไฟล์ โหมด จำนวนลิงก์ และทุกการตัดสินใจ ก่อนส่งออก
หลักฐานที่ไม่มีโทเค็น

เรียกใช้การพิสูจน์การแยกระบบอย่างอิสระ:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

สคริปต์นี้จะตรวจสอบโทโพโลยี, named mounts, การตั้งค่า non-root/อ่านอย่างเดียว, การกำหนดเส้นทางภายในเครื่อง
อย่างชัดเจน, การไม่มีตัวแปรสภาพแวดล้อมที่ละเอียดอ่อน, การไม่มีซ็อกเก็ต Docker, การบล็อกการเข้าถึง
`api.anthropic.com` และ `claude.ai`, การเลือกผู้ให้บริการเฉพาะ Devin และการล้มเหลวอย่างชัดเจนเมื่อ
แบ็กเอนด์ ACP ไม่พร้อมใช้งาน

## การตั้งค่าครั้งแรกและการใช้งานตามปกติ

สร้างอิมเมจตามเวอร์ชันที่ตรึงไว้:

```bash
./scripts/devin-bridge/build
```

ยืนยันตัวตนเฉพาะวอลุ่ม Devin ที่แยกไว้:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

คำสั่งเข้าสู่ระบบใช้ขั้นตอนโทเค็นแบบกำหนดเองอย่างเป็นทางการ ซึ่งออกแบบมาสำหรับสภาพแวดล้อมระยะไกล/คอนเทนเนอร์ โดยป้อนค่าลงในพรอมต์ของ CLI โดยตรง ค่านี้จะไม่ถูกส่งเป็นอาร์กิวเมนต์ของโปรเซส เขียนลงใน Git หรือคัดลอกจากโฮสต์

เปิดใช้รันไทม์ Claude Code ที่แยกไว้:

```bash
./scripts/devin-bridge/launch
```

`launch` จะตรวจสอบการแยกสภาพแวดล้อม การยืนยันตัวตนของ Devin และการค้นหาโมเดลอีกครั้งก่อนเริ่ม Claude Code ที่ทำงานในคอนเทนเนอร์ โดยจะไม่เรียกใช้ไฟล์ปฏิบัติการ Claude ของโฮสต์ นามแฝงของโมเดลสามารถตั้งค่าได้ใน `.env.devin-bridge` โดยค่าที่กำหนดค่าทั้งหมดต้องคงคำนำหน้า `devin-cli-agentic/` ไว้

## คำสั่งตรวจสอบความถูกต้อง

เส้นทางออฟไลน์ที่ทำซ้ำได้ไม่จำเป็นต้องมีบัญชี Devin และไม่มีการใช้อินเทอร์เน็ตระหว่างรัน:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

เส้นทางไลฟ์ที่ต้องยืนยันตัวตนและเปิดใช้งานโดยสมัครใจคือ:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

ตัวรันแบบไลฟ์จะรอระหว่างแต่ละสถานการณ์เพื่อหลีกเลี่ยงการเปิดเซสชัน ACP พร้อมกันเป็นจำนวนมาก และตรวจสอบเหตุการณ์สตรีมแบบมีโครงสร้างของ Claude แทนการเชื่อถือข้อความกล่าวอ้าง สถานการณ์ทั้งสามพิสูจน์ว่า:

1. สามารถอ่านโปรเจกต์โดยตรงและวิเคราะห์ข้อบกพร่องได้;
2. มีการใช้ `Edit` จริง การเรียก `Bash` `npm test` ที่ควบคุมโดยไคลเอนต์ และผลลัพธ์ปลายทาง;
3. สามารถค้นพบ `/bridge-check` พร้อมกับ `bridge-proof` อ่านโปรเจกต์ เรียก `npm test` ที่ควบคุมโดยไคลเอนต์และสำเร็จอีกครั้ง และทำงานเสร็จโดยไม่มีงานค้าง

เกตสุดท้ายยังตรวจสอบบันทึกการตรวจสอบเครือข่ายของ Devin และกำหนดให้บันทึกการตรวจสอบทราฟฟิกขาออกของ Claude ยังคงว่างเปล่า

## การอัปเดตเครื่องมือที่ตรึงเวอร์ชันไว้

อิมเมจจะตรึง Node, Claude Code และ Devin CLI ไว้ใน
`docker/devin-bridge/Dockerfile` หากต้องการอัปเดต:

1. เปลี่ยนเวอร์ชันที่ระบุไว้อย่างชัดเจน;
2. แทนที่เช็กซัมของไฟล์เก็บถาวร Devin สำหรับทั้งสองสถาปัตยกรรมด้วยค่าของอาร์ติแฟกต์อย่างเป็นทางการ;
3. สร้างใหม่และเรียกใช้คำสั่งตรวจสอบแบบออฟไลน์ทั้งหมด;
4. ยืนยันเวอร์ชันภายในอิมเมจ;
5. เรียกใช้ชุดทดสอบไลฟ์สามสถานการณ์ที่ยืนยันตัวตนแล้วอีกครั้ง

ห้ามติดตั้ง CLI ใด CLI หนึ่งแบบส่วนกลางบนโฮสต์ หรือแทนที่การตรวจสอบเช็กซัมด้วยการดาวน์โหลดที่ไม่ได้รับการตรวจสอบ

## การวินิจฉัยและการล้างข้อมูล

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  แสดงการกำหนดเส้นทางภายในเครื่องและข้อผิดพลาดของตัวดำเนินการที่ผ่านการลบข้อมูลละเอียดอ่อนแล้ว
- `.sandbox/evidence/mock-acp.jsonl` บันทึกการดำเนินการ ACP จำลองที่ให้ผลลัพธ์แน่นอน
- `.sandbox/evidence/claude-stream.jsonl` บันทึกการรัน Claude Code แบบออฟไลน์จริง
- `.sandbox/evidence/live-*.jsonl` บันทึกสตรีมไลฟ์ที่ผ่านการตรวจสอบทั้งสามรายการ
- `.sandbox/evidence/egress.jsonl` และ `.sandbox/evidence/claude-egress.jsonl` เป็นสำเนาบันทึกการตรวจสอบของตัวควบคุมที่ผ่านการตรวจสอบและไม่มีโทเค็น

หยุดคอนเทนเนอร์และเครือข่ายที่ระบบเป็นเจ้าของ โดยคงวอลุ่มการเข้าสู่ระบบ/การกำหนดค่าไว้:

```bash
./scripts/devin-bridge/clean
```

ลบสภาพแวดล้อมทั้งหมดที่บริดจ์เป็นเจ้าของ รวมถึงวอลุ่มที่มีชื่อ:

```bash
./scripts/devin-bridge/clean --all
```

## ข้อจำกัด

- บริดจ์ต้องพึ่งพาบทบาท `summarizer` แบบไม่ใช้เครื่องมือที่กำหนดไว้ตายตัว เนื่องจาก Devin CLI `3000.2.17`
  ไม่มีเอเจนต์ ACP แบบเป็นกลางที่ไม่ใช้เครื่องมือ อะแดปเตอร์จะชดเชยการตอบกลับระหว่างทาง
  ที่มีรูปแบบคล้ายบทสรุป แต่การซ่อมแซมที่จำกัดไว้หนึ่งครั้งยังคงอาจล้มเหลวอย่างชัดเจนได้
- การเรียก ACP จริงอาจส่งคืนการตอบกลับ `502`/`504` ชั่วคราว ชุดทดสอบจะเว้นช่วงระหว่างสถานการณ์ต่าง ๆ;
  หากความล้มเหลวยังคงเกิดขึ้น ระบบจะคงสถานะล้มเหลวแบบปิดและจะไม่เลือกผู้ให้บริการรายอื่น
- บริบท ACP จะถูกสร้างขึ้นใหม่จากคำขอ Anthropic แต่ละรายการ โดยไม่มีการผูกกับโปรเซส/เซสชัน
- รองรับการเรียกเครื่องมือหนึ่งครั้งต่อการตอบกลับของโมเดล; การเรียกแบบขนานจะถูกปฏิเสธ
- ไม่รองรับรูปภาพอย่างชัดเจน และไม่มีการประกาศรองรับวิชัน เอาต์พุตกระบวนการคิด การควบคุมระดับความพยายาม
  หรือหน้าต่างบริบทขนาด 1M
- SSE ใช้เหตุการณ์วงจรชีวิตของ Anthropic ที่ถูกต้อง แต่จะส่งออกหลังจากรวบรวมรอบการทำงาน ACP
  ที่มีขอบเขตจำกัดเสร็จแล้ว; ชิ้นข้อมูล ACP จะไม่ถูกส่งต่อตามลำดับแบบเพิ่มขึ้นทีละส่วน
