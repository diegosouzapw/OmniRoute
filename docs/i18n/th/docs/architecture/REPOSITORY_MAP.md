## โครงสร้างระดับบนสุด

```
OmniRoute/
├── src/                  # แอปพลิเคชัน Next.js 16 (UI + เส้นทาง API + ไลบรารี + โดเมน + เซิร์ฟเวอร์)
├── open-sse/             # เวิร์กสเปซเอนจินสตรีมมิง (ตัวจัดการ ตัวดำเนินการ ตัวแปล และเซิร์ฟเวอร์ MCP)
├── electron/             # ตัวครอบเดสก์ท็อป (Electron 41 + electron-builder 26.10)
├── bin/                  # จุดเริ่มต้น CLI และตัวจัดการคำสั่ง
├── scripts/              # สคริปต์สำหรับบิลด์ ตรวจสอบ ซิงก์ และงานเฉพาะกิจ
├── docs/                 # เอกสารสาธารณะ (คุณอยู่ที่นี่)
├── tests/                # ชุดทดสอบทั้งหมด (ยูนิต อินทิเกรชัน e2e และไคลเอนต์โปรโตคอล)
├── public/               # แอสเซตแบบสแตติกของ Next.js, ไฟล์ manifest ของ PWA, service worker และไอคอน
├── config/               # การกำหนดค่าแบบสแตติก + สถานะเกณฑ์คุณภาพ (i18n, payloadRules, quality/)
├── images/               # แอสเซตรูปภาพสำหรับการตลาด / README
├── @omniroute/           # แพ็กเกจเสริมที่เผยแพร่ได้ (opencode-plugin, opencode-provider)
├── skills/               # ชุดทักษะสำหรับ CLI/เอเจนต์ (cli-* + omni-* + config-codex-cli)
├── examples/             # ปลั๊กอินตัวอย่าง + โปรเจกต์เริ่มต้น omniroute-cmd-hello
├── contrib/              # ผลงานจากชุมชน (podman/)
├── .source/              # การกำหนดค่าแหล่งที่มาของ Fumadocs (source.config.mjs + server/browser/dynamic)
├── .github/              # เวิร์กโฟลว์ GitHub Actions + เทมเพลต issue + เทมเพลต PR
├── .husky/               # Git hooks (pre-commit, pre-push)
├── .claude/              # คำสั่ง slash ของ Claude Code (เฉพาะโปรเจกต์)
├── .agents/              # เวิร์กโฟลว์ + ทักษะสำหรับ Codex / เอเจนต์ทั่วไป (สำเนาของ .claude/)
├── .vscode/              # การตั้งค่าเวิร์กสเปซ VS Code
├── _ideia/               # บันทึกการวางแผน (ไม่เป็นทางการ และไม่รวมในการเผยแพร่)
├── _mono_repo/           # โปรเจกต์ย่อยในอดีต (cloud, site, vscode-extension)
├── _references/          # โคลนอ้างอิงแบบอ่านอย่างเดียวจากโปรเจกต์ OSS ที่เกี่ยวข้อง
├── _tasks/               # ไฟล์ติดตามงานแยกตามรุ่น (ไม่เป็นทางการ)
├── .build/ .worktrees/ dist/   # พื้นที่ชั่วคราวสำหรับบิลด์ในเครื่อง / git-worktree / เอาต์พุตบิลด์ (ถูกละเว้นโดย git)
├── .issues/              # แคช issue ในเครื่อง (ถูกละเว้นโดย git)
├── .playwright-mcp/      # อาร์ติแฟกต์การทดสอบ Playwright MCP
├── coverage/             # เอาต์พุตความครอบคลุมของ c8 (ถูกละเว้นโดย git)
├── logs/                 # ล็อกขณะรันไทม์ (ถูกละเว้นโดย git)
├── node_modules/         # การขึ้นต่อกัน (ถูกละเว้นโดย git)
├── package/              # พื้นที่เตรียม npm pack (อาร์ติแฟกต์บิลด์)
├── .next/                # เอาต์พุตบิลด์ของ Next.js (ถูกละเว้นโดย git)
└── (ไฟล์รูท — ดูด้านล่าง)
```

## `src/` — แอปพลิเคชัน Next.js

```
src/
├── app/                 # App Router (เพจ + เส้นทาง API + เพจสถานะ + แลนดิ้งเพจ)
├── lib/                 # ไลบรารีหลัก / โมดูลโดเมน (ไดเรกทอรีย่อย 80 รายการ + ไฟล์ระดับบนสุดประมาณ 70 ไฟล์)
├── domain/              # ตรรกะโดเมนล้วน (กลไกนโยบาย, การสำรอง, ต้นทุน, การล็อกไม่ให้เข้าใช้งาน, comboResolver, การประเมิน)
├── server/              # โมดูลสำหรับเซิร์ฟเวอร์เท่านั้น (ไปป์ไลน์การอนุญาต, cors, มิดเดิลแวร์การยืนยันตัวตน) — ไม่สามารถนำเข้าจากไคลเอนต์ได้
├── shared/              # ใช้ร่วมกันระหว่างเซิร์ฟเวอร์และไคลเอนต์ในส่วนที่ปลอดภัย (ค่าคงที่, ชนิดข้อมูล, การตรวจสอบความถูกต้อง, สัญญา, ยูทิลิตี)
```

## `_ideia/`, `_mono_repo/`, `_references/`, `_tasks/` — นอกโครงสร้างหลัก

ไดเรกทอรีที่ขึ้นต้นด้วยขีดล่างเหล่านี้ใช้เก็บเนื้อหาที่ไม่รวมไปกับการเผยแพร่:

- **`_ideia/`** — บันทึกการออกแบบ (หมวดหมู่ defer / notfit / viable)
- **`_mono_repo/`** — โปรเจกต์ย่อยในอดีต (omnirouteCloud, omnirouteSite, vscode-extension)
- **`_references/`** — clone แบบอ่านอย่างเดียวของโปรเจกต์ OSS ที่เกี่ยวข้อง (LiteLLM, 9router, ClawRouter, CLIProxyAPI, modelrelay, new-api ฯลฯ) เพื่อใช้อ้างอิงระหว่างการพัฒนา
- **`_tasks/`** — ไฟล์ติดตามงานแยกตาม release (อย่างไม่เป็นทางการ)

ไม่รวมอยู่ในผลลัพธ์ของ `npm pack` ดู `.npmignore`
