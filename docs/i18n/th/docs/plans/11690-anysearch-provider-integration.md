## 1. ข้อเท็จจริงพื้นฐานของบริการ (เอกสารอย่างเป็นทางการ, ตรวจสอบเทียบเคียงแล้ว)

- URL ฐาน: `https://api.anysearch.com` (REST) + `POST /mcp` (MCP, JSON-RPC 2.0)
- `POST /v1/search` - พารามิเตอร์: `query` (จำเป็น), `max_results` (1-10, ค่าเริ่มต้น 10), `tag` (การกำหนดเส้นทางแนวดิ่งด้วย `{domain}.{sub_domain}`), `zone` (cn/intl), `language`, `params` (ฟิลด์แนวดิ่งแบบมีโครงสร้าง), `format` (json/markdown)
- `GET /v1/sub-domains?domain=...` - แค็ตตาล็อกความสามารถ, ไม่นับรวมในโควตา
- `POST /v1/extract` - ดึงข้อมูล/แยก `{url, title, content}`; เนื้อหา JSON แบบเคร่งครัด, จำกัดที่ 16 KiB
- `POST /v1/auth/email/register` - การลงทะเบียนด้วยการเรียกเพียงครั้งเดียว, ส่งคืนคีย์ข้อความธรรมดาแบบใช้ครั้งเดียว `as_sk_...`
- การยืนยันตัวตน: `Authorization: Bearer <as_sk_...>` เป็นตัวเลือก; การใช้งานแบบไม่ระบุตัวตนจะถูกลดระดับเป็นข้อจำกัดต่อ IP โดยใช้โควตาฟรีรายวัน; คีย์ที่ไม่ถูกต้องจะส่งคืน 401/403 โดยไม่มีการย้อนกลับไปใช้โหมดไม่ระบุตัวตนโดยอัตโนมัติ
- ระดับฟรี: 1000 คำขอ/วัน, 20 QPS ต่อคีย์ ระดับชำระเงิน: ยังไม่กำหนดราคา (เร็ว ๆ นี้)
- ซองหุ้มการตอบกลับ: สำเร็จ `{code: 0, message: "success", request_id, data}`; ล้มเหลว `{code: -1, message}` ข้อผิดพลาดด้านการยืนยันตัวตน/โควตาไม่มี `error_code` แบบมีโครงสร้าง (ใช้ข้อความใน message เป็นสัญญาณ); ข้อผิดพลาดเฉพาะการแยกข้อมูลมี `error_code` (`invalid_extract_url`, `extract_failed`) ไม่มีส่วนหัว `Retry-After` เมื่อได้รับ 429

## 3. การตัดสินใจ (ทั้งหมดได้ข้อสรุปเมื่อ 2026-08-26)

1. **แนวทางการกำหนดเส้นทาง: `fallbackOnly`** เหตุผล: ผู้ให้บริการฟรีที่มีต้นทุนเป็น 0 ต้องไม่ครอบงำการกำหนดเส้นทางอัตโนมัติตามต้นทุน ส่วนการเลือกอย่างชัดเจนและการย้อนกลับหลังการสลับเมื่อเกิดข้อผิดพลาดจะไม่ได้รับผลกระทบ แบบอย่าง: รายการ xquik ที่ผสานแล้ว
2. **ขอบเขต: webSearch + webFetch ผ่าน `POST /v1/extract` ใน v1** สอดคล้องกับโมเดลเชิงแนวคิดแบบความสามารถคู่ของ tavily/exa ส่วนพื้นผิวเฉพาะทาง (`tag`, `sub-domains`, `batch_search`) ยังคงอยู่นอกขอบเขต — ปัจจุบันยังไม่มี IR สำหรับพารามิเตอร์เฉพาะทาง
3. **การแสดงโควตา: `freeMonthlyQuota: 0`** (การแสดงผลแบบระมัดระวังตามแนวทางของ xquik) สิทธิ์การใช้งานจริง (1000 คำขอ/วัน รีเซ็ตรายวัน) จะแสดงไว้ในข้อความ `authHint` ของแค็ตตาล็อก UI แทน เหตุผล: การแสดงโควตาต้องสอดคล้องกับรูปแบบการรีเซ็ต การแปลงขีดจำกัดรายวันเป็นค่ารายเดือนโดยประมาณ (30000) ถือเป็นคำมั่นที่ไม่ถูกต้องซึ่ง UI ไม่สามารถรับรองได้
4. **searchTypes: `["web"]` เท่านั้น** ไม่มีหลักฐานสาธารณะว่า AnySearch API มีหมวดเฉพาะสำหรับข่าว/รูปภาพ เกตเวย์ที่ผสานรวม API ซึ่งไม่มีหมวดเฉพาะที่มีเอกสารกำกับ (เช่น Google Custom Search) จะแสดงเฉพาะเว็บ แทนที่จะจับคู่ news -> web โดยไม่แจ้งให้ทราบ
5. **แนวทางเกี่ยวกับคีย์:** ใช้งานได้โดยไม่ต้องมีคีย์ ส่วนคีย์ที่ไม่ถูกต้องจะส่งคืน 401/403 และจะไม่ถูกลดระดับเป็นแบบไม่ระบุตัวตนโดยไม่มีการแจ้งเตือน (สอดคล้องกับสัญญาของระบบต้นทาง)
6. **สิ่งที่จงใจไม่รวม:** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (การสกัดกั้นแชตยังคงใช้ firecrawl/jina/tavily), `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (เอนด์พอยต์ระยะไกลแบบไม่ระบุตัวตนใช้พูลเดียวกันที่จำกัดตาม IP สำหรับแต่ละ IP ขาออก ดังนั้นการ extract แบบไม่ใช้คีย์จึงเป็นการเลือกใช้โดยสมัครใจ ไม่ใช่ตัวเลือกสำหรับการกำหนดเส้นทางอัตโนมัติ), `QUOTA_STATUS_PROVIDERS` (AnySearch ส่งสัญญาณโควตาผ่าน 429/เอนเวโลป ไม่ใช่สถานะ 402/403)

## 4. เอกสารอ้างอิง

- เทมเพลต xquik: คอมมิต a0ceccc, PR #11370 (อยู่ในซอร์สทรีที่ release/v3.8.51)
- เอกสารทางการของ AnySearch: https://anysearch.com/docs, https://anysearch.com/pricing; แค็ตตาล็อก MCP mcpservers.org/servers/anysearch-ai/anysearch-mcp-server; รีโพซิทอรีสกิล github.com/anysearch-ai/anysearch-skill
- โมเดลเชิงแนวคิดของอุตสาหกรรม: เอกสารการค้นหาของ LiteLLM (รีจิสทรี + search() แบบรวมศูนย์ + IR ตามข้อกำหนดของ Perplexity), การค้นหาเว็บของ open-webui (ผู้ให้บริการในตัว เครื่องมือคู่ search_web/fetch_url), รูปแบบปลั๊กอินเครื่องมือของ Dify; ลำดับการสำรองตามต้นทุน: โฮสต์เอง -> โควตาฟรี -> แบบชำระเงิน
