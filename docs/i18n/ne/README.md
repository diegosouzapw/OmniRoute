# 🚀 OmniRoute — निःशुल्क AI गेटवे

<img src="./docs/diagrams/readme-hero.svg" width="100%" alt="OmniRoute — कोडिङ कहिल्यै नरोक्नुहोस्। प्रत्येक AI उपकरण → 359 प्रदायक — 150+ निःशुल्क — एउटै endpoint मार्फत। Claude Code, Codex, Cursor, Cline, Copilot र Antigravity लाई स्वतः fallback सहित निःशुल्क Claude / GPT / Gemini मा जोड्नुहोस्। RTK + Caveman को तहगत compression ले 15–95% tokens (~89% औसत) बचत गर्छ — कहिल्यै सीमामा नपुग्नुहोस्। 359 AI प्रदायक · 150+ निःशुल्क tiers · ~1.62B निःशुल्क tokens/महिना · 19 routing रणनीतिहरू · सुरु गर्न $0।"/>

## 💰 ~1.62B निःशुल्क टोकन / महिना

</div>

> निःशुल्क टियरहरू हातैले एकत्रित गर्नु झन्झटिलो हुन्छ — दर्जनौँ SDK, दर्जनौँ दर सीमाहरू, र वास्तवमा आफूसँग कति उपलब्ध छ भन्ने कुनै जानकारी हुँदैन। OmniRoute ले **35 आवर्ती पूल कुञ्जीहरूमा 491 निःशुल्क-टियर प्रविष्टिहरू** सूचीकृत गर्छ र **प्रकाशित सकारात्मक मासिक बजेट भएका 17 पूलहरूका साथै प्रति-मोडेल पाँच Groq सीमाहरूबाट** टोकनको मुख्य आँकडा गणना गर्छ, साझा पूलका आधारमा दोहोरो गणना हटाउँदै। क्षेत्रीय पहिचान प्रमाणीकरणपछि मात्र खुल्ने कोटाहरू (हाल: ModelScope) अलग्गै देखाइन्छन्, क्षेत्रीय पहिचान प्रमाणीकरणपछाडि +~6M उपलब्ध छन्, र तिनलाई मुख्य आँकडामा कहिल्यै जोडिँदैन। नतिजा ड्यासबोर्डमा (`/dashboard/free-tiers`) देखिइरहन्छ।

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="OmniRoute निःशुल्क-टियर बजेट कार्ड: नियमित रूपमा प्रति महिना ~1.62B निःशुल्क टोकन, साइनअप क्रेडिटसहित पहिलो महिनामा ~2.22B सम्म, एउटै एन्डपोइन्टपछाडि सूचीकृत 491 निःशुल्क-टियर प्रविष्टिहरू समेट्ने 35 दस्तावेजीकृत आवर्ती पूल कुञ्जीहरूबाट। इमानदार पूल-डिडुप गरिएको गणना — प्रत्येक साझा पूललाई एकपटक मात्र गणना गरिएको छ, जसमा प्रकाशित सकारात्मक मासिक टोकन बजेट भएका 17 आवर्ती पूलहरूका साथै प्रति-मोडेल पाँच Groq सीमाहरू समावेश छन्; सर्त-जोखिम सूचीमा 13 प्रदायकलाई बेवास्ता गर्नुपर्ने भनी चिन्ह लगाइएको छ, ताकि निर्णय तपाईंले गर्न सक्नुहोस्। बजेट बारमा Mistral 1B, Nara 210M, LLM7 150M, xKiro 150M, Groq 30M (प्रति-मोडेल पाँच सीमा) र साना पूलहरू समावेश छन्; साथै पहिलो-महिनाका साइनअप क्रेडिटहरू र स्थायी रूपमा निःशुल्क, टोकन-सीमा नभएका प्रदायकहरू अलग्गै देखाइन्छन्, ताकि तिनले मुख्य आँकडालाई कहिल्यै कृत्रिम रूपमा नबढाऊन्। /dashboard/free-tiers मा प्रयोग भएको/बाँकी रहेको प्रत्यक्ष विवरण।"/>

> प्रत्यक्ष `/dashboard/free-tiers` पृष्ठको एनिमेटेड सारांश। पूर्ण कार्यविधि (पूल डिडुप, क्रेडिट टियरहरू, प्रदायकका सर्तहरू): **[docs/reference/FREE_TIERS.md](docs/reference/FREE_TIERS.md)**।
>
> <sub>यी आँकडाहरूलाई प्रत्यक्ष सूचीसँग तुलना गरी प्रत्येक दुई हप्तामा पुनः परीक्षण गरिन्छ र ती **दुवै दिशामा परिवर्तन हुन्छन्** — कुनै प्रदायकले निःशुल्क टियर बन्द गरेमा संख्या घट्छ; नयाँ थपिएमा बढ्छ। हामी सूचीले वास्तवमै गणना गरेको आँकडा प्रकाशित गर्छौँ, माथितिर पूर्णाङ्कित उत्कृष्ट सम्भावित अवस्था कहिल्यै होइन।</sub>

## 📡 OmniRoute Radar

माथि दस्तावेजीकृत, पूलमा दोहोरिएका प्रविष्टि हटाइएको क्याटलगबाट प्राप्त हुने मुख्य निःशुल्क-स्तरको परिमाण **~1.62B टोकन/महिना** नै रहन्छ।
प्रदायकको अस्थायी साइनअप क्रेडिटले पहिलो महिनाको परिमाणलाई छुट्टै रूपमा
**~2.22B** सम्म बढाउन सक्छ। OmniRoute का रिलीजहरूबीच निःशुल्क मोडेलहरूको उपलब्धताबारे अझ नवीन जानकारी चाहनेहरूका लागि Radar एउटा वैकल्पिक, हस्ताक्षरित क्याटलग ओभरले हो; सामुदायिक क्याटलग र हाल उपलब्ध प्रत्येक निःशुल्क
सुविधा निःशुल्क नै रहन्छन्।

समर्थकहरूले लाइभ क्याटलग र प्रदायकका थप अवसरहरू प्राप्त गर्न सक्छन्। यसको छुट्टै,
परिवर्तनशील अधिकतम सीमा प्रदायकको उपलब्धताअनुसार **बढीमा लगभग 3B टोकन/महिना** हो।
त्यो सीमा सुनिश्चित गरिएको होइन: प्रदायकहरूले कुनै पनि
समयमा कोटा, योग्यता, मोडेल वा क्षेत्र परिवर्तन गर्न सक्छन्।

Radar वैकल्पिक रूपमा सक्रिय गर्न सकिन्छ र GET-मात्र हो। OmniRoute क्लाइन्टले प्रम्प्ट, ट्राफिक, प्रदायक
कन्फिगरेसन, प्रयोगसम्बन्धी टेलिमेट्री वा घोषणाहरू नदेखाउने स्थानीय अवस्थासम्बन्धी डेटा अपलोड गर्दैन। योग्यता र
हालको क्याटलगबारे **[radar.omniroute.online/planos](https://radar.omniroute.online/planos)** मा जान्नुहोस्।

## 🔌 पूर्ण CLI + A2A र MCP

</div>

> सर्भरभन्दा पर, OmniRoute **80+ कमान्डहरू** भएको **पूर्ण कमान्ड-लाइन ककपिट** हो, साथै खुला एजेन्ट प्रोटोकलहरू पनि छन्, जसले गर्दा AI एजेन्टले यसलाई **आफैं** सञ्चालन गर्न सक्छ।

### ⌨️ वास्तविक CLI (`start` मात्र होइन)

```bash
omniroute               # गेटवे + ड्यासबोर्ड सञ्चालन गर्नुहोस् (पोर्ट 20128)
omniroute chat          # अन्तरक्रियात्मक TUI च्याट क्लाइन्ट (स्ल्यास: /model /combo /skill /memory)
omniroute setup         # निर्देशित पहिलो-पटक सञ्चालन विजार्ड
omniroute doctor        # प्रदायकहरू, पोर्टहरू र नेटिभ निर्भरताहरूको निदान गर्नुहोस्
```

### 🛰️ रिमोट मोड — CLI यहाँ चलाउनुहोस्, OmniRoute VPS मा

OmniRoute सर्भरमा छ? **उही CLI** प्रयोग गरेर आफ्नो ल्यापटपबाट यसलाई सञ्चालन गर्नुहोस्। स्कोप गरिएको पहुँच टोकनमार्फत एकपटक
लगइन गर्नुहोस्; त्यसपछि प्रत्येक कमान्डले रिमोटलाई लक्षित गर्छ।

```bash
omniroute connect 192.168.0.15            # पासवर्ड → स्कोप गरिएको टोकन, कन्टेक्स्टका रूपमा सुरक्षित
omniroute models list                     # ← रिमोट सर्भरविरुद्ध चल्छ
omniroute configure codex                 # ← रिमोट मोडेल छान्छ, स्थानीय Codex प्रोफाइल लेख्छ
omniroute tokens create --name ci --scope read   # अन्य मेसिनहरूका लागि अझ सीमित टोकनहरू जारी गर्नुहोस्
omniroute contexts use default            # ← स्थानीय सर्भरमा फिर्ता जानुहोस्
```

टोकनहरू `read` / `write` / `admin` मा स्कोप गरिएका हुन्छन्; प्रक्रिया सुरु गर्ने रुटहरू लुपब्याकमा मात्र सीमित रहन्छन्।

### 📖 यसले कसरी काम गर्छ — पाइपलाइन, आर्किटेक्चर र बचतको गणना

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute कम्प्रेसन पाइपलाइन: उदाहरणका रूपमा 10,000-टोकनको क्लाइन्ट अनुरोध 12 वटा संयोजनयोग्य इन्जिनहरू — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra र OmniGlyph — हुँदै जान्छ र दस्तावेजीकृत स्ट्याक गरिएको उदाहरणमा करिब 1,080 टोकनमा प्रदायकसम्म पुग्न सक्छ। संरचित सामग्रीलाई संरक्षण गार्ड र प्रत्येक चरणका फिडेलिटी गेटहरूले सुरक्षित राख्छन्; स्पष्ट रूपमा चयन गरिएका हानियुक्त वा प्रयोगात्मक मोडहरूले योग्य सामग्रीलाई रूपान्तरण गर्न सक्छन्।"/>

पूर्वनिर्धारित स्ट्याक गरिएको संयोजनले `RTK → Caveman` चलाउँछ। दुवैले एउटै टुल/कन्टेक्स्ट पेलोडमा काम गर्दा बचत चक्रवृद्धि हुन्छ:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

कोड ब्लकहरू, URLs, JSON र संरचित डेटा संरक्षण इन्जिनद्वारा **सधैँ सुरक्षित राखिन्छन्**।

> **थोरै टोकनले काम हुने हुँदा धेरै टोकन किन प्रयोग गर्ने?** प्रत्येक अनुरोध OmniRoute को कम्प्रेसन पाइपलाइन हुँदै **पारदर्शी रूपमा** जान्छ — क्लाइन्टमा कुनै परिवर्तन आवश्यक पर्दैन। अब यो **क्रमबद्ध रूपमा चल्ने र प्रत्येक राउटिङ संयोजनअनुसार मिसाउन तथा मिलाउन सकिने 12 वटा संयोजनयोग्य इन्जिनहरूको स्ट्याक** हो — जुन [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K+), [LLMLingua-2](https://github.com/microsoft/LLMLingua), र [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR) का अवधारणाहरूमा आधारित छ।

### 🎚️ इन्जिनहरूभन्दा पर — आउटपुट शैलीहरू, अनुकूली डायल र प्रत्येक अनुरोधको नियन्त्रण

माथिका 12 इन्जिनले **भित्र जाने** सामग्री घटाउँछन्। थप तीन तहले **कसरी**, **कहिले**, र **के बाहिर आउँछ** भन्ने निर्धारण गर्छन्:

- **🪄 आउटपुट शैलीहरू** _(आउटपुट-अक्ष निर्देशन)_ — निर्धारणात्मक, cache-सुरक्षित प्रतिक्रिया-आकार निर्देशनहरू प्रविष्ट गर्छ; संयोजन गर्न मिल्ने, प्रत्येकलाई `lite` / `full` / `ultra` तीव्रतामा प्रयोग गर्न सकिन्छ। शैली थप्न registry मा एक लाइनको entry पर्याप्त हुन्छ:
  - **संक्षिप्त गद्य** — अनावश्यक शब्द / articles / अनिश्चित अभिव्यक्ति हटाउनुहोस्; प्राविधिक सार ठ्याक्कै कायम राख्नुहोस्।
  - **कम code** — "अल्छी वरिष्ठ dev" YAGNI: काम गर्ने सबैभन्दा सानो परिवर्तन, अनुरोध नगरिएको scaffolding बिना।
  - **Ponytail (अल्छी वरिष्ठ dev)** — YAGNI को सिँढी चढ्नुहोस्, मूल कारण समाधान गर्नुहोस्, काम गर्ने सबैभन्दा सानो diff।
  - **मलाई ADHD छ (कार्य-पहिले)** — अर्को कार्य सुरुमा, चरणहरू क्रमाङ्कित, एउटा ठोस अर्को कदम, कुनै प्रस्तावना छैन।
  - **संक्षिप्त CJK (文言)** — शास्त्रीय-चिनियाँ अति-संक्षिप्त शैली (`zh` मा locale-gated)।
- **🎯 अनुकूली context-budget** _(डायल)_ — एउटै on/off token threshold को सट्टा, **मोडेलको context window भित्र अटाउन** आवश्यक हदसम्म मात्र सबैभन्दा सस्ता, न्यूनतम-हानियुक्त इन्जिनहरू क्रमशः सक्रिय गर्छ। नीति: `reserve-output` (पूर्वनिर्धारित, मोडेल-सचेत) · `percentage` · `absolute`। मोड: `floor` (अट्ने सुनिश्चितता) · `replace-autotrigger` (तपाईंको स्पष्ट छनोट लागू हुन्छ) · `off` (पुरानो threshold)।
- **🎛️ Compression कहाँ निर्धारण हुन्छ** _(प्राथमिकता, उच्च → न्यून)_ — प्रत्येक अनुरोधको `x-omniroute-compression` header › routing-combo override › सक्रिय नामित profile › adaptive / auto-trigger › panel default › off। लागू गरिएको योजना `X-OmniRoute-Compression: <mode>; source=<source>` response header मा फर्काइन्छ।

Token threshold अनुसार auto-trigger गर्नुहोस्, अनुकूली डायल खोल्नुहोस्, नामित profile pin गर्नुहोस्, प्रत्येक अनुरोधका लागि एकपटकको सेटिङ राख्नुहोस्, वा प्रत्येक routing combo मा pipeline तोक्नुहोस् — workload लाई जे उपयुक्त हुन्छ। Opt-in offline **eval harness** (`npm run eval:compression`) ले परिवर्तन प्रवर्द्धन गर्नुअघि pinned corpus मा fidelity र savings मूल्याङ्कन गर्छ।

तपाईंले जडान गरेका models को सूची देख्नुपर्छ। 🎉 यति नै हो — coding सुरु गर्नुहोस्, र OmniRoute ले तपाईंका लागि स्वतः route तथा fallback गर्छ।

तपाईंको client ले custom headers पठाउन सक्दैन भने, OmniRoute ले tokenized compatibility aliases पनि उपलब्ध गराउँछ:

```txt
OpenAI catalog:   http://localhost:20128/vscode/YOUR_KEY/
OpenAI models:    http://localhost:20128/vscode/YOUR_KEY/models
OpenAI chat:      http://localhost:20128/vscode/YOUR_KEY/chat/completions
OpenAI responses: http://localhost:20128/vscode/YOUR_KEY/responses
Ollama chat:      http://localhost:20128/vscode/YOUR_KEY/api/chat
Ollama tags:      http://localhost:20128/vscode/YOUR_KEY/api/tags
```

यी केवल `Authorization: Bearer ...` संलग्न गर्न नसक्ने clients का लागि प्रयोग गर्नुहोस्। Header auth नै रुचाइएको mode हो।

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

`:latest` ले उच्चतम **प्रकाशित** स्थिर SemVer पछ्याउँछ। यसले git `main` लाई पछ्याउँदैन। GitOps का लागि `:X.Y.Z` निश्चित गर्नुहोस्। [Docker रिलिज च्यानलहरू](docs/guides/DOCKER_GUIDE.md#release-channels) हेर्नुहोस्। इमेजले **`OMNIROUTE_MEMORY_MB=1024`** निश्चित गर्छ। यो ड्यासबोर्ड र हल्का च्याटका लागि पर्याप्त छ। **कोडिङ एजेन्टहरू** (Claude Code, Codex, Grok, … बाट `POST /v1/responses`) लाई धेरै ठूलो V8 heap आवश्यक पर्छ, अन्यथा दुईवटा एक-अर्कासँग खप्टिएका लामा कन्टेक्स्टअन्तर्गत प्रक्रिया ~12 GiB मा `FATAL ERROR` सहित बन्द हुन्छ। कन्टेनरको आकार heap भन्दा ठूलो राख्नुहोस् (नेटिभ बफरहरू V8 बाहिर रहन्छन्):

| कार्यभार                             | Heap (`-e OMNIROUTE_MEMORY_MB`)    | कन्टेनर (`--memory`) |
| ------------------------------------ | ---------------------------------- | -------------------- |
| ड्यासबोर्ड / हल्का च्याट             | `1024` (इमेजको पूर्वनिर्धारित मान) | ≥2 g                 |
| एउटा कोडिङ एजेन्ट                    | `8192`                             | ≥10 g                |
| एकसाथ चल्ने दुई लामा `/v1/responses` | `10240`–`12288`                    | ≥12–16 g             |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

**🥟 Bun**

Bun रनटाइम पहिचानमार्फत मानक `bun install` र ग्लोबल स्थापना (`bun install -g omniroute`) समर्थित छन्:

- **अन्तर्निर्मित `bun:sqlite`**: Bun अन्तर्गत चल्दा OmniRoute ले Bun को अन्तर्निर्मित `bun:sqlite` ड्राइभर प्रयोग गर्छ र Node.js मा `better-sqlite3` वा `sql.js` मा फलब्याक गर्छ।
- **डेभमा स्वचालित Webpack बन्डलर चयन**: विकास (`bun run dev`) ले Bun स्वतः पहिचान गर्छ र नेटिभ V8 बाइन्डिङ असङ्गतिहरू रोक्न Turbopack लाई निष्क्रिय पारेर Webpack प्रयोग गर्छ। उत्पादन बिल्डहरू (`bun run build`) ले Node मा जस्तै ठ्याक्कै `OMNIROUTE_USE_TURBOPACK` पछ्याउँछन्: पूर्वनिर्धारित रूपमा Turbopack, Webpack मार्फत बिल्ड गर्न `OMNIROUTE_USE_TURBOPACK=0` (`Dockerfile.bun` ले यसलाई `--build-arg` का रूपमा उपलब्ध गराउँछ)।
- **समर्पित Bun Dockerfile**: नेटिभ Bun उत्पादन डिप्लोयमेन्टहरूका लागि बहु-चरणीय `Dockerfile.bun` (`docker build -f Dockerfile.bun -t omniroute:bun .`)।

```bash
# 3. रनटाइम सङ्केत सेट गर्नुहोस्, स्थानीय Compose इमेज बिल्ड गर्नुहोस् र सुरु गर्नुहोस्
echo "CONTAINER_HOST=podman" >> .env
podman compose --profile base up -d --build
```

macOS वा Windows मा Podman ले रिमोट Podman Machine प्रयोग गर्छ: `podman unshare` छोड्नुहोस् र
[टोपोलोजी-विशिष्ट डेटा डाइरेक्टरी मार्गदर्शन](contrib/podman/README.md#data-directory-permissions-by-topology) पालना गर्नुहोस्।

📖 [Podman गाइड](contrib/podman/README.md) — Compose बिल्डहरू, Podman Machine, र
Linux/systemd Quadlet सेटअप।

**⚡ छिटो / हल्का स्थापना (नेटिभ बिल्ड छोड्नुहोस्)**

नेटिभ SQLite इन्जिन (`better-sqlite3`) एउटा **वैकल्पिक** निर्भरता हो, त्यसैले ग्लोबल
स्थापना स्रोतबाट कम्पाइल हुने प्रतीक्षामा कहिल्यै रोकिन्न: तपाईंको प्लेटफर्म/Node सँग मिल्दा यसले पूर्वनिर्मित बाइनरी प्रयोग गर्छ
र अन्यथा पारदर्शी रूपमा शुद्ध-JS इन्जिनमा फलब्याक गर्छ
(Node 22+ मा `node:sqlite`, अन्यथा समावेश गरिएको `sql.js` WASM) — कुनै बिल्ड उपकरण आवश्यक पर्दैन।

स्थापनापछिको नेटिभ वार्म-अप पूर्ण रूपमा छोड्न (CI, हेडलेस वा ढिला मेसिनहरू):

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 ले पनि यसलाई छोड्छ
```

सबैभन्दा छिटो स्थापनाका लागि **pnpm** रोज्नुहोस् (कन्टेन्ट-अड्रेस्ड स्टोर + हार्ड लिङ्कहरू — माथि हेर्नुहोस्)।
ड्यासबोर्डरहित, हेडलेस रनटाइमका लागि Docker को `base` प्रोफाइल (माथि) वा
[Termux गाइड](docs/guides/TERMUX_GUIDE.md) प्रयोग गर्नुहोस्। CLI र वेब ड्यासबोर्ड एउटै पोर्टमा एउटै
प्रक्रियाद्वारा सेवा गरिन्छन्, त्यसैले हाल कुनै छुट्टै CLI-मात्र प्याकेज छैन।
