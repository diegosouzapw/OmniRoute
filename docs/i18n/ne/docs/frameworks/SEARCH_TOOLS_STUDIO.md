## अवलोकन

Search Tools Studio ले `/dashboard/search-tools` लाई सामान्य खोज प्रयोगस्थलबाट वेब खोज, वेब स्क्र्यापिङ र प्रदायकहरूको सँगसँगै तुलना गर्ने तीन-ट्याबयुक्त Studio मा रूपान्तरण गर्छ।

```
┌ खोज उपकरणहरू ─────────────────────────────────────────────────────────┐

│ ⓘ [मोडालिटी मार्गदर्शिका]                                              │
├──────────────────────────────────────────┬─────────────────────────────┤
│  {सक्रिय ट्याबको सामग्री}                │ ─ कन्फिगरेसन               │
```

## ट्याबहरू

### खोज ट्याब

विद्यमान `SearchForm` + `ResultsPanel` + `RerankPanel` लाई एउटा ट्याबमा विकसित गर्छ:

- क्वेरी → नतिजाहरू (शीर्षक, URL, स्निपेट, सान्दर्भिकता स्कोर)।
- कन्फिगरेसन पेनमा प्रदायकको मेटाडेटा (लागत, कोटा, स्थिति)।
- पुनःक्रम खण्ड: पुनःक्रम मोडेल छान्ने, नतिजाहरू पुनःक्रमबद्ध गर्ने र `positionDelta` देखाउने।
- कुनै पनि खोज प्रदायक कन्फिगर नगरिएको अवस्थामा CTA सहितको खाली स्थिति।
- `SearchHistory.tsx` मार्फत खोज इतिहास।
- `POST /v1/search` कल गर्छ (विद्यमान एन्डपोइन्ट, कुनै परिवर्तन छैन)।

### स्क्र्याप ट्याब

`POST /v1/web/fetch` (योजना 05 मा सिर्जना गरिएको) मार्फत URL बाट सामग्री निकाल्ने नयाँ ट्याब:

- इनपुट: URL + पूर्ण-पृष्ठ टगल + ढाँचा चयनकर्ता (markdown / text / HTML)।
- पेस गर्ने → फेच गर्ने → `ScrapeResult.tsx` रेन्डर गर्ने।
- `ScrapeResult` ले markdown पूर्वावलोकन + कच्चा सामग्री टगल रेन्डर गर्छ।
- सीमा: प्रतिक्रिया बडी **256 KB** भन्दा ठूलो भएमा UI ले `(काटिएको, कच्चा सामग्री हेर्नुहोस्)` देखाउँछ र कच्चा सामग्रीलाई Monaco मोडलमा खोल्छ (D21)।
- मेटाडेटा प्यानल: प्रदायक (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search), विलम्बता, लागत, प्रतिक्रियाको आकार, लिङ्क सङ्ख्या।
- `useScrapeFetch.ts` हुक प्रयोग गर्छ।

### तुलना ट्याब

एउटै क्वेरी/URL लाई बढीमा **4 प्रदायकहरूमा समानान्तर रूपमा** चलाउँछ (D22):

- प्रत्येक प्रदायकका लागि सँगसँगै स्तम्भहरू।
- मेट्रिक्स: विलम्बता, लागत, नतिजा सङ्ख्या, प्रतिक्रियाको आकार।
- खोजका लागि URL ओभरल्याप गणना (प्रारम्भिक नतिजाको तुलनामा साझा URL हरूको सङ्ख्या)।
- प्रत्येक प्रदायकका लागि `POST /v1/search` (खोज) वा `POST /v1/web/fetch` (स्क्र्याप) कल गर्छ।

| फिल्ड          | टिप्पणीहरू                                                             |
| -------------- | ---------------------------------------------------------------------- |
| प्रदायक        | स्थिति ब्याजसहितको ड्रपडाउन (कन्फिगर गरिएको / अनुपलब्ध / दर सीमित)     |

`SearchConceptCard.tsx` — सधैं देखिने, संकुचन गर्न मिल्ने अकर्डियन। यसले निम्न कुरा व्याख्या गर्छ:

| अवधारणा                    | एक-वाक्यीय विवरण                                                            |
| -------------------------- | --------------------------------------------------------------------------- |
| **खोज**                    | वेब नतिजाहरूको सूची प्राप्त गर्छ (शीर्षक, URL, स्निपेट, सान्दर्भिकता स्कोर) |
| **स्क्रेप**                | URL को पूर्ण सामग्री निकाल्छ (markdown, text वा HTML)                       |

| **पुनःक्रम निर्धारण**      | क्वेरीको सान्दर्भिकता सुधार्न LLM मार्फत नतिजाहरूलाई पुनःक्रमबद्ध गर्छ      |
| **स्वतः (सबैभन्दा सस्तो)** | उपलब्ध सबैभन्दा सस्तो प्रदायक स्वतः चयन गर्छ                                |

## प्रदायक क्याटलग

`ProviderCatalog.tsx` ले `GET /api/search/providers` बाट प्रदायकहरूको पूर्ण सूची उपलब्ध गराउँछ
(fetch प्रदायकहरू समावेश गर्न F4 मा विस्तार गरिएको):

| `kind` | `"search"` (20 प्रदायक) वा `"fetch"` (firecrawl, jina-reader, tavily-search, tinyfish, nimble-search, anysearch-search) |

स्थिति **अनुरोधको समयमा व्युत्पन्न गरिन्छ**, जसका लागि प्रमाणपत्रहरू उपलब्ध छन् कि छैनन् र
सबै कुञ्जीहरू हाल cooldown मा छन् कि छैनन् भनेर जाँच गरिन्छ।

## कोड निर्यात

`ExportCodeModal` (Playground Studio बाट आयात गरिएको) + `codeExport.ts` ले
`/v1/search` र `/v1/web/fetch` दुवै कलका लागि curl / Python / TypeScript स्निपेटहरू उत्पन्न गर्छन्।
API कुञ्जीको प्लेसहोल्डर सधैं `$OMNIROUTE_API_KEY` हुन्छ (D11, Playground Studio सँग साझा गरिएको)।

## ब्याकएन्ड परिवर्तनहरू

यस सुविधाका लागि केवल एउटा ब्याकएन्ड परिवर्तन आवश्यक थियो:

### विस्तारित `GET /api/search/providers`

`src/app/api/search/providers/route.ts` लाई निम्न कार्यका लागि विस्तार गरिएको थियो:

- एरेमा सबै 6 fetch प्रदायकहरू (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`) समावेश गर्ने।
- प्रत्येक आइटममा `kind: "search" | "fetch"` थप्ने।
- प्रत्यक्ष प्रमाणपत्र अवस्थाबाट व्युत्पन्न गरिएको `status: "configured" | "missing" | "rate_limited"` थप्ने।
- पश्चगामी अनुकूलता कायम राख्ने — विद्यमान फिल्डहरू (`id`, `name`, आदि) अपरिवर्तित छन्।
