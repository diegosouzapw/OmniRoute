OmniRoute मा स्थानीयतालाई प्राथमिकता दिने गेमिफिकेसन तह समावेश छ, जसले
प्लेटफर्मसँग अन्तर्क्रिया गरेबापत प्रयोगकर्ताहरूलाई पुरस्कृत गर्छ — अनुरोधहरू गर्ने, प्रदायकहरू बदल्ने,
कम्बोहरू सिर्जना गर्ने, टोकनहरू साझा गर्ने, र समुदायमा योगदान गर्ने। सबै अवस्था
SQLite मा रहन्छन्; सामुदायिक सर्भरहरूसँगको फेडरेसन ऐच्छिक र पुश-आधारित छ।

प्रणालीलाई **मुख्य कार्यपथमा शून्य विलम्बता** हुने गरी डिजाइन गरिएको छ — गेमिफिकेसन
घटनाहरू अनुरोध पाइपलाइनबाट पठाएर बिर्सने शैलीमा डिस्प्याच गरिन्छन् र तिनले
LLM प्रतिक्रिया कहिल्यै अवरुद्ध गर्दैनन्।

## अवलोकन

### उद्देश्य

दृश्यात्मक प्रगति (XP,
स्तरहरू, ब्याजहरू), सामाजिक प्रमाण (लिडरबोर्डहरू), र आर्थिक प्रोत्साहनहरू (टोकन
साझेदारी, आमन्त्रण पुरस्कारहरू) प्रदान गरेर प्रयोगकर्ता संलग्नता र निरन्तरता बढाउनु।

### कार्यक्षेत्र

| सुविधा             | विवरण                                                                   |
| ------------------ | ----------------------------------------------------------------------- |
| XP र स्तरहरू       | प्रत्येक कार्यमा XP आर्जन गर्नुहोस्; बहुपदीय वक्रअनुसार स्तर बढाउनुहोस् |
| ब्याजहरू           | 4 दुर्लभता तहसहित 5 श्रेणीमा 20+ उपलब्धिहरू                             |
| निरन्तरताहरू       | हालको/सबैभन्दा लामो निरन्तरतासहित दैनिक सक्रिय प्रयोगको ट्र्याकिङ       |
| लिडरबोर्डहरू       | विश्वव्यापी, साप्ताहिक, मासिक, टोकन-साझेदारी, र योगदान कार्यक्षेत्रहरू  |
| टोकन साझेदारी      | दोहोरो-प्रविष्टि लेजरमार्फत प्रयोगकर्ताहरूबीच क्रेडिट स्थानान्तरण       |
| आमन्त्रण र रिडिम   | SHA-256 ह्यास गरिएको भण्डारणसहितका रेफरल कोडहरू                         |
| सामुदायिक सर्भरहरू | बाह्य OmniRoute इन्स्ट्यान्सहरूसँग फेडरेट गर्ने                         |
| ठगी-रोध            | सर्भर-साइड स्कोरिङ, दर सीमितता, z-score विसङ्गति पत्ता लगाउने           |

### डिजाइन सिद्धान्तहरू

1. **स्थानीयतालाई प्राथमिकता** — सबै अवस्था SQLite मा हुन्छन्, बाह्य सेवाहरू आवश्यक पर्दैनन्।
2. **अवरुद्ध नगर्ने** — घटनाहरू पठाएर बिर्सने शैलीका हुन्छन्; गेमिफिकेसन तर्कले
   LLM प्रतिक्रिया पथलाई कहिल्यै ढिलो गर्दैन।
3. **सर्भर-आधिकारिक** — XP सर्भर-साइडमा मात्र गणना गरिन्छ; क्लाइन्टहरूले
   स्कोर कृत्रिम रूपमा बढाउन सक्दैनन्।
4. **गोपनीयताको सम्मान गर्ने** — लिडरबोर्डमा सहभागिता ऐच्छिक हुन्छ; प्रयोगकर्ताहरूले
   आफ्नो प्रोफाइल लुकाउन सक्छन्।
5. **फेडरेसनका लागि तयार** — सामुदायिक सर्भरहरूले हस्ताक्षरित API मार्फत स्कोरहरू पुश गर्न सक्छन्;
   सिंक अधिलेखन हो, योगात्मक होइन।

## वास्तुकला

### उच्च-स्तरीय प्रवाह

```
क्लाइन्ट अनुरोध
  → /v1/chat/completions
    → handleChatCore()                      [open-sse/handlers/chatCore.ts]
      → ... (अवस्थित पाइपलाइन) ...
      → अपस्ट्रिम प्रतिक्रिया क्लाइन्टलाई पठाइयो
      → setImmediate (पठाएर बिर्सने):
        → emitGamificationEvent()           [src/lib/gamification/events.ts]
          → awardXp()                       [src/lib/gamification/xp.ts]
          → updateStreak()                  [src/lib/gamification/streaks.ts]
          → evaluateBadges()                [src/lib/gamification/badges.ts]
          → updateLeaderboard()             [src/lib/gamification/leaderboard.ts]
          → checkAnomalies()                [src/lib/gamification/antiCheat.ts]
```

घटना इमिटर एकल एकीकरण बिन्दु हो। `chatCore.ts` ले
प्रतिक्रिया पठाइसकेपछि `emitGamificationEvent()` कल गर्छ; घटना मोड्युलले
XP, निरन्तरता, ब्याज, लिडरबोर्ड, र ठगी-रोध उपप्रणालीहरूमा वितरण गर्छ।

## XP / स्तर प्रणाली

**फाइल:** `src/lib/gamification/xp.ts`

### स्तर वक्र

स्तर `n` मा पुग्न आवश्यक XP ले बहुपदीय वक्र अनुसरण गर्छ:

```
xp_for_level(n) = floor(100 * n^1.5)
```

| स्तर | अर्को स्तरका लागि XP | सञ्चित XP | उपाधि      |
| ---- | -------------------- | --------- | ---------- |
| 1    | 100                  | 100       | प्रारम्भिक |
| 5    | 1,118                | 2,415     | प्रारम्भिक |
| 10   | 3,162                | 10,523    | अन्वेषक    |
| 25   | 12,500               | 86,024    | अन्वेषक    |
| 50   | 35,355               | 345,529   | विशेषज्ञ   |
| 75   | 64,952               | 948,683   | निपुण      |

### पुरस्कार प्रवाह

```typescript
export async function awardXp(
  apiKeyId: string,
  action: XpAction,
  metadata?: Record<string, unknown>
): Promise<{ xp: number; level: number; title: string; levelUp: boolean }>;
```

1. XP परिमाण प्राप्त गर्न `XP_REWARDS[action]` खोज्नुहोस्।
2. `checkRateLimit()` मार्फत पठाउनुहोस् (ठगी-रोधी: प्रति की प्रति मिनेट अधिकतम 1000 XP)।
3. ट्रान्ज्याक्सन खोल्नुहोस्:
   - हालको `user_levels` पङ्क्ति पढ्नुहोस्।
   - XP थप्नुहोस्; `levelFromXp(totalXp)` मार्फत स्तर पुनः गणना गर्नुहोस्।
   - स्तर परिवर्तन भएमा `levelUp = true` सेट गर्नुहोस्।
   - `user_levels` पङ्क्ति अद्यावधिक गर्नुहोस्।
   - `xp_audit_log` मा घुसाउनुहोस्।
4. नतिजा फर्काउनुहोस्। कलरले सूचनाहरू व्यवस्थापन गर्छ।

### सहायक: `levelFromXp(totalXp)`

स्तर 1..100 सम्म पुनरावृत्ति गर्दै, सञ्चित XP ले `totalXp` नाघेसम्म `xp_for_level(n)` को योग गर्छ।
थ्रेसहोल्ड पूरा भएको सबैभन्दा उच्च स्तर फर्काउँछ।
यो O(100) हो — स्तरहरू अधिकतम 100 सम्म सीमित भएकाले स्वीकार्य छ।

### मूल्याङ्कन प्रवाह

```

  → evaluateBadges(apiKeyId, event)
    → getBadgeDefinitions()           # सबै परिभाषाहरू
    → getUserBadges(apiKeyId)         # पहिले नै प्राप्त भएका (छोड्नुहोस्)
```

## स्ट्रीक ट्र्याकर

**फाइल:** `src/lib/gamification/streaks.ts`

### डेटा मोडेल

स्ट्रीकहरू `key_value` तालिका (साझा उपयोगिता तालिका) मा नेमस्पेस गरिएका
कुञ्जीहरूअन्तर्गत भण्डारण गरिन्छन्:

| कुञ्जी                        | मान                              | विवरण               |
| ----------------------------- | -------------------------------- | ------------------- |
| `gamification:streak:{keyId}` | `{current},{longest},{lastDate}` | सक्रिय स्ट्रीक डेटा |

### तर्क

```typescript
export async function updateStreak(
  apiKeyId: string
): Promise<{ current: number; longest: number; milestone: boolean }>;
```

1. `key_value` बाट स्ट्रीक रेकर्ड पढ्नुहोस्।
2. `{current}`, `{longest}`, `{lastDate}` (ISO मिति स्ट्रिङ) पार्स गर्नुहोस्।
3. यदि `lastDate === today` — कुनै परिवर्तन नगर्नुहोस् (आज पहिले नै गणना भइसकेको छ)।
4. यदि `lastDate === yesterday` — `current` बढाउनुहोस्; आवश्यक भएमा `longest` अद्यावधिक गर्नुहोस्।
5. यदि `lastDate < yesterday` — `current = 1` मा रिसेट गर्नुहोस् (स्ट्रीक टुट्यो)।
6. अद्यावधिक गरिएको रेकर्ड लेख्नुहोस्।
7. माइलस्टोनहरू जाँच्नुहोस्: 7, 14, 30, 60, 90, 180, 365 दिन। कुनै माइलस्टोन पार भएमा,
   `milestone = true` सेट गर्नुहोस् (कलरले XP प्रदान गर्छ र ब्याजहरू जाँच्छ)।

### विशेष अवस्थाहरू

- **समय क्षेत्र**: स्ट्रीकहरूले UTC मितिहरू (`new Date().toISOString().slice(0, 10)`) प्रयोग गर्छन्।
  यो जानाजानी गरिएको हो — एउटै प्रामाणिक समय क्षेत्रले समय क्षेत्र परिवर्तन गरेर अनुचित लाभ लिनबाट
  रोक्छ।
- **नयाँ प्रयोगकर्ताहरू**: कुनै स्ट्रीक रेकर्ड हुँदैन; पहिलो अनुरोधले
  `current=1, longest=1, lastDate=today` सहित रेकर्ड सिर्जना गर्छ।
- **प्रतिदिन धेरै अनुरोधहरू**: UTC दिनको पहिलो अनुरोधले मात्र
  स्ट्रीक बढाउँछ।

| पङ्क्ति       | `from_key_id` | `to_key_id`  | `amount` | अर्थ                  |
| ------------- | ------------- | ------------ | -------- | --------------------- |
| पठाउने        | प्रेषक        | प्राप्तकर्ता | +रकम     | प्रेषकबाट बहिर्गमन    |
| प्राप्त गर्ने | प्राप्तकर्ता  | प्रेषक       | +रकम     | प्राप्तकर्तातर्फ आगमन |

ब्यालेन्स यसरी गणना गरिन्छ:

```sql
SELECT
  COALESCE(SUM(CASE WHEN to_key_id = ? THEN amount ELSE 0 END), 0)
  - COALESCE(SUM(CASE WHEN from_key_id = ? THEN amount ELSE 0 END), 0)
  AS balance
FROM token_ledger
WHERE from_key_id = ? OR to_key_id = ?
```

### स्थानान्तरण प्रवाह

```typescript
export async function transferTokens(
  fromKeyId: string,
  toKeyId: string,
  amount: number,
  idempotencyKey: string
): Promise<{ success: boolean; balance: number }>;
```

1. **प्रमाणीकरण गर्नुहोस्**: `amount > 0`, `fromKeyId !== toKeyId`।
2. **आइडेम्पोटेन्सी**: लेजरमा `idempotency_key` पहिले नै अवस्थित छ कि छैन जाँच गर्नुहोस्।
   यदि छ भने, क्यास गरिएको परिणाम फिर्ता गर्नुहोस्।
3. **लेनदेन** (एकल SQLite लेनदेन):
   a. प्रेषकको ब्यालेन्स गणना गर्नुहोस्।
   b. यदि `balance < amount` भएमा, रद्द गर्नुहोस् (अपर्याप्त रकम)।
   c. पठाउने पङ्क्ति घुसाउनुहोस् (`from=sender,` फिर्ता गर्नुहोस्।

### दर सीमितता

- प्रति API कुञ्जी प्रति मिनेट अधिकतम 10 स्थानान्तरण।
- एउटै स्थानान्तरणमा अधिकतम 10,000 टोकन।
- प्रति API कुञ्जी प्रति दिन अधिकतम 100,000 टोकन स्थानान्तरण।

## आमन्त्रण र टोकन रिडिम

**फाइल:** `src/lib/gamification/invites.ts`

### कोड ढाँचा

- **कोड**: 8-वर्णको अक्षराङ्कीय कोड (जस्तै, `A3K9-X7M2`), मानिसले पढ्न सक्ने,
  प्रयोगकर्तालाई देखाइने।
- **टोकन**: 32-बाइटको अनियमित टोकन, SHA-256 ह्यासका रूपमा भण्डारण गरिने। प्रोग्रामगत
  रिडेम्प्सनका लागि प्रयोग गरिने (जस्तै, URL लिङ्कहरू)।

### भण्डारण

| स्तम्भ       | मान                              |
| ------------ | -------------------------------- |
| `code`       | `A3K9X7M2` (अद्वितीय, अनुक्रमित) |
| `token_hash` | SHA-256(raw_token)               |

कच्चा टोकन सिर्जना गर्ने समयमा प्रयोगकर्तालाई ठीक एकपटक मात्र फिर्ता गरिन्छ। त्यसपछि OmniRoute ले
यसलाई कहिल्यै भण्डारण वा प्रदर्शन गर्दैन — ह्यास मात्र कायम रहन्छ।

### स्व-सिफारिस रोकथाम

प्रयोगकर्ताले कोड रिडिम गर्दा, प्रणालीले निम्न कुराहरू जाँच गर्छ:

1. कोड फरक `api_key_id` सँग सम्बन्धित छ।
2. रिडिम गर्ने प्रयोगकर्ताले पहिले सोही
   सिफारिसकर्ताको कुनै पनि कोड रिडिम गरेको छैन (`invite_tokens` + रिडेम्प्सन लगमा जोइन गर्छ)।

कुनै एक जाँच असफल भएमा, स्पष्ट त्रुटि सन्देशसहित रिडेम्प्सन अस्वीकार गरिन्छ।

### म्याद समाप्ति र सीमाहरू

- पूर्वनिर्धारित `max_uses`: 10 (सिर्जना गर्दा कन्फिगर गर्न सकिने)।
- पूर्वनिर्धारित `expires_at`: सिर्जना गरेको मितिबाट 30 दिन।
- म्याद सकिएका वा प्रयोग सीमा समाप्त भएका कोडहरूले HTTP 410 Gone फिर्ता गर्छन्।

## सामुदायिक सर्भर फेडरेसन

**फाइल:** `src/lib/gamification/servers.ts`

### जडान

सामुदायिक सर्भरलाई रिमोट सर्भरद्वारा जारी गरिएको आमन्त्रण टोकनमार्फत दर्ता गरिन्छ। स्थानीय इन्स्ट्यान्सले:

1. आमन्त्रण टोकन प्राप्त गर्छ (उदाहरणका लागि, ड्यासबोर्डमा टाँसिएको)।
2. टोकन प्रमाणीकरण गर्न र हालको लिडरबोर्ड प्राप्त गर्न रिमोट सर्भरमा `POST /api/gamification/federation/leaderboard` कल गर्छ।
3. `status: connected` सहित सर्भर रेकर्ड भण्डारण गर्छ।

### सिंक मोडेल

फेडरेसनले योगात्मक नभई **ओभरराइट सिंक** प्रयोग गर्छ:

```
स्थानीय इन्स्ट्यान्स              सामुदायिक सर्भर
     │                              │
     ├── स्कोर पुश ────────────────►│  POST /federation/score
     │   { api_key_id, score }      │  (सर्भरले टोकन ह्यास प्रमाणीकरण गर्छ)
     │                              │
     ├── लिडरबोर्ड पुल ────────────►│  GET /federation/leaderboard
     │◄── शीर्ष-N प्रविष्टिहरू ─────┤  (स्थानीय क्यास ओभरराइट गर्छ)
     │                              │
     └── स्वास्थ्य जाँच ───────────►│  GET /federation/health
         (हरेक 60s मा, टाइमआउट 5s)  │
```

### प्रमाणीकरण

फेडरेसन अनुरोधहरूमा निम्न समावेश हुन्छन्:

```
Authorization: Bearer <raw_token>
X-Federation-Version: 1
```

रिमोट सर्भरले टोकन ह्यास गर्छ र मिल्दो `community_servers` पङ्क्ति खोज्छ। यसले भण्डारण गरिएको ह्यास प्रसारण गर्नबाट जोगाउँछ।

### स्वास्थ्य अनुगमन

प्रत्येक सर्भर रेकर्डले निम्न विवरण ट्र्याक गर्छ:

| फिल्ड       | विवरण                                  |
| ----------- | -------------------------------------- |
| `status`    | `connected`, `degraded`, `unreachable` |
| `last_sync` | अन्तिम सफल सिंकको ISO टाइमस्ट्याम्प    |
| `failures`  | लगातार असफल भएका स्वास्थ्य जाँचहरू     |

लगातार 5 पटक असफल भएपछि, स्थिति `unreachable` मा परिवर्तन हुन्छ र म्यानुअल स्वास्थ्य जाँच सफल नहुँदासम्म सिंक रोकिएको रहन्छ।

## एन्टी-चिट

**फाइल:** `src/lib/gamification/antiCheat.ts`

### सर्भर-साइड स्कोरिङ

सबै XP गणनाहरू `src/lib/gamification/xp.ts` मा हुन्छन्। क्लाइन्टहरूले कहिल्यै स्कोर पेस गर्दैनन् — उनीहरूले कार्यहरू पेस गर्छन्, र सर्भरले XP गणना गर्छ। `leaderboard.score` स्तम्भ सर्भर-साइड कोडद्वारा मात्र लेख्न मिल्छ।

### दर सीमितता

| सीमा                         | मान     | दायरा            |
| ---------------------------- | ------- | ---------------- |
| प्रति मिनेट अधिकतम XP        | 1,000   | प्रति API कुञ्जी |
| प्रति मिनेट अधिकतम ट्रान्सफर | 10      | प्रति API कुञ्जी |
| अधिकतम ट्रान्सफर रकम         | 10,000  | प्रति ट्रान्सफर  |
| अधिकतम दैनिक ट्रान्सफर       | 100,000 | प्रति API कुञ्जी |

दर सीमाहरूले इन-मेमोरी स्लाइडिङ विन्डो (`open-sse/services/` मा रहेको `RateLimitManager` कै ढाँचा) प्रयोग गर्छन्। प्रक्रिया पुनः सुरु भएमा SQLite-समर्थित काउन्टरहरूमा फर्किन्छ।

### Z-स्कोर विसङ्गति पहिचान

प्रत्येक API कुञ्जीका लागि, प्रणालीले प्रतिघण्टा आर्जन गरिएको XP को रोलिङ 7-दिने विन्डो कायम राख्छ। प्रत्येक XP प्रदान गर्दा:

1. प्रयोगकर्ताको हालको प्रतिघण्टा XP दर गणना गर्नुहोस्।
2. जनसङ्ख्याको औसत र मानक विचलन गणना गर्नुहोस्।
3. `z = (user_rate - mean) / stddev` गणना गर्नुहोस्।
4. यदि `z > 3.0` (3 मानक विचलन) भएमा, विसङ्गतिका रूपमा चिन्ह लगाउनुहोस्।

विसङ्गतिहरूलाई `action = 'anomaly_detected'` सहित `xp_audit_log` मा लग गरिन्छ र एडमिन ड्यासबोर्डमा देखाइन्छ।

### अडिट ट्रेल

प्रत्येक XP प्रदान, ट्रान्सफर, ब्याज प्राप्ति र विसङ्गति पहिचानलाई निम्न विवरणसहित `xp_audit_log` मा लग गरिन्छ:

| फिल्ड        | विवरण                                          |
| ------------ | ---------------------------------------------- |
| `api_key_id` | को                                             |
| `action`     | के भयो (xp_award, transfer, anomaly, …)        |
| `xp_awarded` | रकम (गैर-XP घटनाहरूका लागि 0)                  |
| `metadata`   | सन्दर्भसहितको JSON (कार्यको प्रकार, लक्ष्य, …) |
| `created_at` | कहिले (ISO 8601)                               |

एडमिनहरूले `GET /api/gamification/anomalies` मार्फत पूर्ण अडिट ट्रेल क्वेरी गर्न सक्छन्।

  (लुकेका ब्याजहरू प्राप्त नभएसम्म "???" देखाउँछन्)।
- ज्वाला आइकनसहितको स्ट्रीक गणक; स्ट्रीक पात्रो (पछिल्ला 30 दिन)।

### `/dashboard/tokens`

- टोकन मौज्दात (प्रमुख रूपमा, पृष्ठको शीर्षमा)।
- स्थानान्तरण फाराम: प्राप्तकर्ता, रकम, पुष्टि संवाद।
- फिल्टरहरू (पठाइएका/प्राप्त भएका/सबै) सहितको स्थानान्तरण इतिहास तालिका।
- आमन्त्रण खण्ड: सक्रिय कोडहरू, नयाँ सिर्जना, लिङ्क साझा गर्ने।
- सामुदायिक सर्भरहरू: स्वास्थ्य स्थितिसहितको सूची, जडान/विच्छेदन।

### `/dashboard/gamification/admin`

- गम्भीरता, प्रयोगकर्ता, टाइमस्ट्याम्प र z-score सहितको असामान्यता सूची।
- फिल्टरहरू (कार्यको प्रकार, प्रयोगकर्ता, मिति दायरा) सहितको अडिट लग दर्शक।
- प्रणाली तथ्याङ्क: प्रदान गरिएको कुल XP, सक्रिय प्रयोगकर्ताहरू, ब्याज प्राप्ति दरहरू।
- फेडरेसन सर्भरको स्वास्थ्यसम्बन्धी समग्र अवलोकन।

## पाइपलाइन एकीकरण

### एकीकरण बिन्दु

गेमिफिकेसन `open-sse/handlers/chatCore.ts` मा रहेको अनुरोध पाइपलाइनको एउटै बिन्दुमा
जोडिन्छ:

```typescript
// क्लाइन्टलाई प्रतिक्रिया पठाएपछि:
setImmediate(() => {
  emitGamificationEvent({
    type: "request.completed",
    apiKeyId,
    metadata: {
      provider: selectedProvider,
      model: selectedModel,
      comboId: resolvedCombo?.id,
      compressionUsed: compressionStats?.applied,
      skillUsed: skillExecution?.name,
    },
  }).catch(() => {
    // फायर-एन्ड-फर्गेट: लग गर्नुहोस् तर क्लाइन्टमा कहिल्यै प्रसार नगर्नुहोस्
  });
});
```

### घटना प्रकारहरू

| घटना प्रकार         | कहिले उत्सर्जन गरिन्छ                                  |
| ------------------- | ------------------------------------------------------ |
| `request.completed` | सफल LLM प्रतिक्रिया पठाइएपछि                           |
| `provider.switch`   | प्रदायक परिवर्तन हुँदा (कम्बो फलब्याकहरू गणना हुन्छन्) |
| `combo.created`     | नयाँ कम्बो कन्फिगरेसन सुरक्षित गरिँदा                  |
| `combo.used`        | कम्बो लक्ष्य सफलतापूर्वक प्राप्त हुँदा                 |
| `badge.earned`      | ब्याज मूल्याङ्कनले मिल्दो परिणाम फेला पार्दा           |
| `streak.milestone`  | स्ट्रीक थ्रेसहोल्ड पार हुँदा                           |
| `transfer.sent`     | टोकन स्थानान्तरण पूरा हुँदा                            |
| `referral.redeemed` | आमन्त्रण कोड सफलतापूर्वक रिडिम हुँदा                   |
| `compression.used`  | प्रम्प्ट कम्प्रेसन लागू हुँदा                          |
| `skill.executed`    | सीप कार्यान्वयन पूरा हुँदा                             |
| `model.first_use`   | मोडेल पछिल्ला 7 दिनमा प्रयोग नभएको हुँदा               |

### नन-ब्लकिङ प्रत्याभूति

`setImmediate` + `.catch(() => {})` ढाँचाले निम्न कुरा सुनिश्चित गर्छ:

1. गेमिफिकेसन चल्नुअघि प्रतिक्रिया पूर्ण रूपमा पठाइन्छ।
2. गेमिफिकेसनका त्रुटिहरू क्लाइन्टमा कहिल्यै देखा पर्दैनन्।
3. घटना प्रशोधन इनलाइन नभई अर्को माइक्रोटास्कमा चल्छ।

### प्रमाणीकरण आवश्यकताहरू

- **सार्वजनिक** (प्रमाणीकरण आवश्यक छैन): `GET /leaderboard`, `GET /stream` (पढ्न-मात्र
  मिल्ने लिडरबोर्डहरू)।
- **API कुञ्जी आवश्यक**: सबै लेखन कार्यहरू, प्रोफाइल, स्थानान्तरणहरू, निमन्त्रणाहरू।
- **एडमिन मात्र**: विसङ्गति ड्यासबोर्ड, अडिट लग भ्युअर।
- **फेडरेसन**: `Authorization` हेडरमा कच्चा टोकन प्रयोग गर्ने छुट्टै प्रमाणीकरण
  मार्ग, जुन भण्डारण गरिएको SHA-256 ह्याससँग जाँच गरिन्छ।
