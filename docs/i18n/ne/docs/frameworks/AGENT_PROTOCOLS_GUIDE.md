OmniRoute ले एजेन्टसँग सम्बन्धित तीन फरक इन्टरफेस उपलब्ध गराउँछ। पहिलो नजरमा तिनीहरू उस्तै देखिन्छन्, तर फरक समस्याहरू समाधान गर्छन्। सही इन्टरफेस छनोट गर्न यो पृष्ठ प्रयोग गर्नुहोस्।

## छोटकरीमा

| इन्टरफेस                       | यसका लागि उत्तम                                                                                                                                   | ट्रान्सपोर्ट                    | मानक                       |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- | -------------------------- |
| **A2A — एजेन्ट-देखि-एजेन्ट**   | A2A प्रोटोकल प्रयोग गर्ने सहकर्मी एजेन्टहरूसँग अन्तर-एजेन्ट सहकार्य                                                                               | HTTP मार्फत JSON-RPC 2.0        | A2A v0.3 (खुला विनिर्देशन) |
| **ACP — CLI एजेन्ट रजिस्ट्री** | प्रयोगकर्ताको मेसिनमा इन्स्टल गरिएका CLI कोडिङ एजेन्टहरू (Cursor, Cline, Codex CLI, Claude Code, Aider, आदि) पत्ता लगाउन / दर्ता गर्न / सुरु गर्न | HTTP REST                       | OmniRoute-विशिष्ट          |
| **क्लाउड एजेन्टहरू**           | बाह्य क्लाउड सेवाहरू (Codex Cloud, Devin, Jules, Cursor Cloud) मा लामो समय चल्ने कोडिङ कार्यहरू पठाउन                                             | HTTP REST + DB-समर्थित कार्यहरू | OmniRoute-विशिष्ट          |

यी तीनवटै स्वतन्त्र छन् — कुनै पनि उपसमूह छनोट गर्नुहोस्।

```

├─ हो → क्लाउड एजेन्टहरू (POST /api/v1/agents/tasks)

    ├─ हो → A2A (POST /a2a)
    └─ होइन → अगाडि बढ्नुहोस्
        │

        ├─ हो → ACP (GET /api/acp/agents)
        └─ होइन → सामान्य /v1/chat/completions प्रयोग गर्नुहोस्
```

## 1. A2A — एजेन्ट-देखि-एजेन्ट

**विनिर्देशन:** [A2A v0.3](https://a2a-protocol.org)
**OmniRoute इन्डपोइन्ट:** `POST /a2a` (JSON-RPC 2.0)
**एजेन्ट कार्ड:** `GET /.well-known/agent.json`

### कहिले प्रयोग गर्ने

- OmniRoute सहकर्मीहरूमध्ये एक हुने बहु-एजेन्ट प्रणाली निर्माण गर्दा
- Google ADK वा सामान्य एजेन्ट मेसजस्ता फ्रेमवर्कका एजेन्टहरूलाई OmniRoute को राउटिङ बुद्धिमत्ता (स्मार्ट-राउटिङ, कोटा-व्यवस्थापन, आदि) उपलब्ध गराउँदा
- OmniRoute लाई मानक खोज + आह्वान इन्टरफेसपछाडि र्याप गर्दा

### विधिहरू

- `message/send` — सन्देश पठाउनुहोस् र सिंक्रोनस प्रतिक्रिया प्राप्त गर्नुहोस्
- `message/stream` — सन्देश पठाउनुहोस् र SSE-स्ट्रिम गरिएका प्रगति घटनाहरू प्राप्त गर्नुहोस्
- `tasks/get` — ID अनुसार कार्य पढ्नुहोस्
- `tasks/cancel` — चलिरहेको कार्य रद्द गर्नुहोस्

### अन्तर्निर्मित सीपहरू (6)

- `smart-routing` — प्रम्प्टलाई इष्टतम संयोजनमार्फत रुट गर्नुहोस्
- `quota-management` — प्रत्येक प्रदायकको कोटा स्थिति रिपोर्ट गर्नुहोस्
- `provider-discovery` — क्षमताहरूसहित इन्स्टल गरिएका प्रदायकहरूको सूची देखाउनुहोस्
- `cost-analysis` — अनुरोध/वार्तालापको लागत अनुमान गर्नुहोस्
- `health-report` — प्रत्येक प्रदायकको ब्रेकर/कुलडाउन/लकआउट स्थिति एकीकृत गर्नुहोस्
- `list-capabilities` — एजेन्टका उपलब्ध सीप र मेटाडेटा सूचीबद्ध गर्नुहोस्

### विस्तृत विवरण

ट्रान्सपोर्ट विवरण, एजेन्ट कार्डको संरचना, कार्य TTL कन्फिगरेसन र नयाँ सीपहरू थप्ने टेम्प्लेटका लागि [A2A-SERVER.md](./A2A-SERVER.md) हेर्नुहोस्।

## 2. ACP — CLI एजेन्ट रजिस्ट्री

**OmniRoute एन्डपोइन्ट:** `GET /api/acp/agents`
**स्रोत:** `src/lib/acp/{index,manager,registry}.ts`

### यो के हो

ACP OmniRoute को **स्थानीय CLI एजेन्ट सूची** हो। यसले होस्टमा कुन-कुन कोडिङ CLI हरू इन्स्टल भएका छन् (Cursor, Cline, Claude Code, Codex CLI, Continue आदि) भनेर पत्ता लगाउँछ, तिनका संस्करणहरू निर्धारण गर्छ, र तिनलाई ड्यासबोर्डमा देखाउँछ, ताकि प्रयोगकर्ताले प्रत्येक CLI लाई OmniRoute तर्फ निर्देशित गर्न कन्फिगर गर्न सकोस्।

यो कुनै बाह्य प्रोटोकल होइन — यो "CLI Tools" UI र CLI फिङ्गरप्रिन्ट ट्र्याकिङ सञ्चालन गर्ने आन्तरिक रजिस्ट्री हो ([CLI-TOOLS.md](../reference/CLI-TOOLS.md) हेर्नुहोस्)।

### यसले के गर्छ

- इन्स्टल गरिएका CLI बाइनरीहरूका लागि होस्ट जाँच गर्छ (OS अनुसार `which` / `where` प्रयोग गर्छ)
- प्रत्येक CLI को संस्करण पढ्छ (`<bin> --version` कल गर्छ)
- वैकल्पिक रूपमा प्रयोगकर्ताले परिभाषित गरेका अनुकूलन एजेन्टहरू स्वीकार गर्छ (बाइनरी पाथ + संस्करण जाँच + स्पन आर्गुमेन्टहरू)
- अनुकूलन एजेन्टहरूलाई सेटिङहरूमा स्थायी रूपमा भण्डारण गर्छ
- एकीकृत सूची ड्यासबोर्डमा फर्काउँछ

### REST API

| एन्डपोइन्ट        | विधि | विवरण                                                                    | प्रमाणीकरण |
| ----------------- | ---- | ------------------------------------------------------------------------ | ---------- |
| `/api/acp/agents` | GET  | पत्ता लागेका + अनुकूलन एजेन्टहरूको सूची (इन्स्टल भएका/कुल सङ्ख्या)       | API कुञ्जी |
| `/api/acp/agents` | POST | अनुकूलन एजेन्ट थप्ने/अद्यावधिक गर्ने/हटाउने (बडीमा एक्सन डिस्क्रिमिनेटर) | API कुञ्जी |

POST का लागि बडीको संरचना (`src/app/api/acp/agents/route.ts` मा `customAgentBodySchema`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### प्रयोगका अवस्थाहरू

- ड्यासबोर्डको "CLI Tools" पृष्ठले के-के इन्स्टल भएका छन् भनेर सूचीबद्ध गर्छ र प्रत्येकलाई OmniRoute तर्फ निर्देशित गर्न मद्दत गर्छ
- अनुकूलन एजेन्टहरूले उन्नत प्रयोगकर्ताहरूलाई OmniRoute ले पूर्वनिर्धारित रूपमा नचिन्ने आन्तरिक/स्वामित्वयुक्त CLI हरू दर्ता गर्न दिन्छन्
- पत्ता लगाउने नतिजाले `cli-tools` फिङ्गरप्रिन्ट म्याट्रिक्सलाई डेटा उपलब्ध गराउँछ

### ACP कहिले प्रयोग नगर्ने

- ACP ले कार्यहरू _चलाउँदैन_। यसले CLI हरू पत्ता लगाउने र कन्फिगर गर्ने मात्र गर्छ। CLI लाई वास्तवमै आह्वान गर्न, OmniRoute ले उपलब्ध गराएका वातावरणीय चरहरू (`OPENAI_BASE_URL`, `OPENAI_API_KEY` आदि) सहित तपाईं आफैँले यसलाई सुरु गर्नुपर्छ।

## 3. क्लाउड एजेन्टहरू

**OmniRoute एन्डपोइन्टहरू:** `/api/v1/agents/tasks/*` (जीवनचक्र) + `/api/cloud/*` (आन्तरिक जडान व्यवस्था)
**स्रोत:** `src/lib/cloudAgent/`

### यो के हो

तेस्रो-पक्षीय क्लाउड कोडिङ एजेन्टहरूमाथिको एक समान इन्टरफेस। तपाईंले प्रम्प्ट + रिपोजिटरी URL पेस गर्नुहुन्छ, OmniRoute ले सही क्लाउड एजेन्टलाई पठाउँछ, स्थिति पोल गर्छ, र नतिजाहरू फर्काउँछ।

### समर्थित एजेन्टहरू (४ वटा, सबै `src/lib/cloudAgent/agents/` मा पुष्टि गरिएका)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### जीवनचक्र

```
POST /api/v1/agents/tasks
  → प्रत्येक एजेन्ट क्लासका लागि BaseAgent.createTask()
  → बाह्य सेवाले काम सुरु गर्छ
  → DB मा कार्य पङ्क्ति सिर्जना हुन्छ (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → प्रदायकबाट आवश्यकताअनुसार स्थिति समक्रमण
  → हालको स्थिति + योजना + गतिविधि लग फर्काउँछ
  ↓
POST /api/v1/agents/tasks/[id]   (कार्य: "approve" | "message" | "cancel")
  → प्रदायकलाई फर्वार्ड गर्छ (वा स्थानीय रूपमा रद्द भएको चिन्ह लगाउँछ)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → स्थानीय रूपमा रद्द गर्छ
```

### प्रमाणीकरण

⚠️ **सबै `/api/v1/agents/tasks/*` एन्डपोइन्टहरूलाई व्यवस्थापन प्रमाणीकरण आवश्यक हुन्छ** (कमिट `588a0333`)। v3.8.0 देखि केवल Bearer प्रयोग गर्ने कलरहरूले 401 प्राप्त गर्छन्।

### विस्तृत जानकारी

`CloudAgentBase` कन्ट्र्याक्ट, प्रत्येक एजेन्टका विशेष विवरणहरू, स्किमा विवरणहरू, र क्रेडेन्सियल जडान एन्डपोइन्टहरूका लागि [CLOUD_AGENT.md](./CLOUD_AGENT.md) हेर्नुहोस्।

## तुलना: A2A बनाम Cloud Agents

दुवैमा "लामो समयसम्म चल्ने कार्यहरू" हुन्छन्, तर फरक तहहरूमा:

| पक्ष               | A2A                                                                                       | Cloud Agents                                  |

## एकीकरणका उदाहरणहरू

### OmniRoute का A2A क्षमताहरू पत्ता लगाउनुहोस्

```bash
curl http://localhost:20128/.well-known/agent.json
```

सबै 6 सीप, ट्रान्सपोर्ट र संस्करणसहितको Agent Card फर्काउँछ।

### OmniRoute लाई A2A एजेन्टका रूपमा कल गर्नुहोस्

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### ACP मार्फत इन्स्टल गरिएका CLI एजेन्टहरूको सूची हेर्नुहोस्

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### अनुकूलन गरिएको CLI एजेन्ट थप्नुहोस्

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### Cloud Agent कार्य पेस गर्नुहोस्

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### क्लाउड कार्यको स्थिति पोल गर्नुहोस्

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## कुन अवस्थामा के प्रयोग गर्ने

- **च्याटबट / कोपाइलट फ्रन्टएन्ड** → `/v1/chat/completions` (OpenAI-सङ्गत — एजेन्ट प्रोटोकल होइन)
- **बहु-एजेन्ट सहकार्य** → A2A
- **ड्यासबोर्डमा स्थानीय CLI हरूको सूची देखाउने** → ACP
- **लामो समयसम्म चल्ने कोडिङ कार्यहरू क्लाउड सेवाहरूलाई प्रत्यायोजन गर्ने** → Cloud Agents
