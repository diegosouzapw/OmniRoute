OmniRoute ले तेस्रो-पक्षका क्लाउड-होस्टेड कोडिङ एजेन्टहरू (Codex Cloud, Cursor,
Devin, Jules) लाई लामो समयसम्म चल्ने कार्यका रूपमा समन्वय गर्छ। प्रत्येक एजेन्टलाई एउटै समान इन्टरफेसभित्र समेटिएको छ, जसले गर्दा
क्लाइन्टहरूले प्रदायक-विशिष्ट API हरू सम्हाल्नु नपरीकन prompt + repo URL पेस गर्न र परिणामहरू प्राप्त गर्न सक्छन्।

Cloud Agent कार्य नियमित च्याट पूर्णता **होइन**। यो मिनेटदेखि घण्टासम्म लाग्न सक्ने, Pull Request लाई आफ्नो
कलाकृतिका रूपमा उत्पादन गर्न सक्ने, र फलो-अप सन्देशहरू तथा (केही प्रदायकहरूमा) योजना अनुमोदन चरणहरूलाई समर्थन गर्ने
टिकाउ, बहु-चरणीय कार्य एकाइ हो।

## वास्तुकला

```
क्लाइन्ट (ड्यासबोर्ड / CLI / API)
  → POST /api/v1/agents/tasks (व्यवस्थापन प्रमाणीकरण आवश्यक)
    → CreateCloudAgentTaskSchema प्रमाणीकरण (Zod)
    → registry.getAgent(providerId)
    → getCloudAgentCredentials(providerId)
      └─ getProviderConnections({ provider, isActive: true }) बाट प्राप्त गर्छ
         (पहिले apiKey, नभए accessToken)
    → agent.createTask({ prompt, source, options }, credentials)
      └─ अपस्ट्रिम प्रदायक API मा HTTP POST
      └─ आन्तरिक id + externalId सहित CloudAgentTask फर्काउँछ
    → cloud_agent_tasks (SQLite) मा insertCloudAgentTask(...)

पोलिङ (पढ्दा हुने अल्छी समक्रमण):
  GET /api/v1/agents/tasks/[id]
    → getCloudAgentTaskById(id)
    → agent.getStatus(externalId, credentials)  // स्थिति + गतिविधिहरू ताजा गर्छ
    → नयाँ स्थिति, परिणाम, completed_at सहित updateCloudAgentTask(...)
    → क्रमबद्ध गरिएको कार्य फर्काउँछ

अन्तरक्रियाहरू:
  POST /api/v1/agents/tasks/[id]  body: { action: "approve" | "message" | "cancel" }
    → "approve" का लागि agent.approvePlan(externalId, credentials)
    → "message" का लागि agent.sendMessage(externalId, message, credentials)
    → "cancel" का लागि स्थिति "cancelled" मा परिवर्तन हुन्छ (स्थानीय-मात्र)
```

समक्रमण **अल्छी** हुन्छ: प्रत्येक `GET /tasks/[id]` मा अपस्ट्रिमबाट स्थिति ताजा गरिन्छ।
कुनै पृष्ठभूमि पोलर छैन। नवीन स्थिति आवश्यक पर्ने ड्यासबोर्डहरूले उपयुक्त अन्तरालमा GET
endpoint लाई पोल गर्नुपर्छ।

## `CloudAgentBase` इन्टरफेस

स्रोत: `src/lib/cloudAgent/baseAgent.ts`

```typescript
export interface AgentCredentials {
  apiKey: string;
  baseUrl?: string;
}

export interface CreateTaskParams {
  prompt: string;
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
}

export interface GetStatusResult {
  status: CloudAgentStatus;
  externalId?: string;
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
}

export abstract class CloudAgentBase {
  abstract readonly providerId: string;
  abstract readonly baseUrl: string;

  abstract createTask(p: CreateTaskParams, c: AgentCredentials): Promise<CloudAgentTask>;
  abstract getStatus(externalId: string, c: AgentCredentials): Promise<GetStatusResult>;
  abstract approvePlan(externalId: string, c: AgentCredentials): Promise<void>;
  abstract sendMessage(
    externalId: string,
    message: string,
    c: AgentCredentials
  ): Promise<CloudAgentActivity>;
  abstract listSources(
    c: AgentCredentials
  ): Promise<{ name: string; url: string; branch?: string }[]>;

  protected mapStatus(raw: string): CloudAgentStatus; // ह्युरिस्टिक अपस्ट्रिम-स्ट्रिङ → enum
  protected generateTaskId(): string; // `task_<ts>_<rand>`
  protected generateActivityId(): string; // `act_<ts>_<rand>`
}
```

`CodexCloudAgent.approvePlan` ले जानाजानी त्रुटि फ्याँक्छ — Codex Cloud ले स्वचालित रूपमा योजना बनाउँछ र यसमा
कुनै स्वीकृति गेट छैन। `CodexCloudAgent.listSources` ले `[]` फर्काउँछ।

`CursorCloudAgent` ले Cursor का Background / Cloud Agents लाई यसको आधिकारिक REST
API (`api.cursor.com/v0`) मार्फत **प्रयोगकर्ता वा सेवा-खाता API key** प्रयोग गरेर सञ्चालन गर्छ — यो Cursor IDE को OAuth सत्र पुनः प्रयोग गर्नेभन्दा सुरक्षित,
प्रथम-पक्षीय विकल्प हो (प्रदायक `cursor`,
जसमा प्रतिबन्ध लाग्ने जोखिमसम्बन्धी चेतावनी छ)। यो सामान्य REST एडाप्टर हो (`@cursor/sdk` को मूल
निर्भरता छैन)। `approvePlan` ले त्रुटि फ्याँक्छ (Cursor agents स्वायत्त रूपमा चल्छन्); `listSources` ले
उक्त key मार्फत पहुँचयोग्य रिपोजिटरीहरू सूचीबद्ध गर्छ। Cursor ले UPPERCASE स्थिति enum हरू
(`CREATING`/`RUNNING`/`FINISHED`/`ERROR`) फर्काउँछ, जसलाई साझा
`CloudAgentStatus` मा स्पष्ट रूपमा म्याप गरिन्छ। `baseUrl` लाई प्रत्येक credential का लागि ओभरराइड गर्न सकिन्छ, जसले API संस्करण/पाथलाई
कोड परिवर्तन नगरी सच्याउन सम्भव बनाउँछ।

```typescript
export const CLOUD_AGENT_STATUS = {
  QUEUED: "queued",
  RUNNING: "running",
  AWAITING_APPROVAL: "awaiting_approval",
  COMPLETED: "completed",
  FAILED: "failed",
  CANCELLED: "cancelled",
} as const;

export interface CloudAgentSource {
  repoName: string;
  repoUrl: string; // मान्य URL हुनुपर्छ
  branch?: string;
}

export interface CloudAgentResult {
  prUrl?: string;
  prNumber?: number;
  commitMessage?: string;
  diffUrl?: string;
  summary?: string;
  duration?: number; // सेकेन्ड, धनात्मक पूर्णाङ्क

export interface CloudAgentActivity {
  id: string;
  type: "plan" | "command" | "code_change" | "message" | "error" | "completion";
  content: string;
  timestamp: string; // ISO 8601
  metadata?: Record<string, unknown>;
}

export interface CloudAgentTask {
  id: string; // आन्तरिक `task_...` id
  providerId: "jules" | "devin" | "codex-cloud" | "cursor-cloud";
  externalId?: string; // अपस्ट्रिम प्रदायकको id
  status: CloudAgentStatus;
  prompt: string; // 1..10000 वर्ण
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
  createdAt: string;
  updatedAt: string;
  completedAt?: string;
}
```

प्रमाणीकरण स्किमाहरू (`CreateCloudAgentTaskSchema`, `UpdateCloudAgentTaskSchema`) प्रकारहरूसँगै

## डेटाबेस

स्रोत: `src/lib/cloudAgent/db.ts` — तालिका `createCloudAgentTaskTable()` मार्फत आवश्यक पर्दा मात्र सिर्जना गरिन्छ
(मोड्युल आयात हुँदा `src/lib/cloudAgent/index.ts` बाट पनि बोलाइन्छ)।

```sql
CREATE TABLE IF NOT EXISTS cloud_agent_tasks (
  id           TEXT PRIMARY KEY,
  provider_id  TEXT NOT NULL,
  external_id  TEXT,
  status       TEXT NOT NULL DEFAULT 'queued',
  prompt       TEXT NOT NULL,
  source       TEXT NOT NULL,             -- JSON
  options      TEXT DEFAULT '{}',         -- JSON
  result       TEXT,                       -- JSON
  activities   TEXT DEFAULT '[]',          -- JSON
  error        TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_provider ON cloud_agent_tasks(provider_id);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_status   ON cloud_agent_tasks(status);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_created  ON cloud_agent_tasks(created_at DESC);
```

SQL injection रोक्न `updateCloudAgentTask` ले **स्तम्भ अनुमति-सूची** लागू गर्छ:
`status`, `prompt`, `source`, `options`, `result`, `activities`, `error`,
`completed_at`। आंशिक अद्यावधिकमा रहेको अन्य कुनै पनि key कुनै सूचना नदिई हटाइन्छ।

## REST API — कार्य जीवनचक्र

**प्रमाणीकरण:** सबै `/api/v1/agents/tasks*` endpoint लाई **व्यवस्थापन प्रमाणीकरण**
आवश्यक हुन्छ (`requireCloudAgentManagementAuth` ले
`src/lib/api/requireManagementAuth` को `requireManagementAuth` लाई wrap गर्छ)। यो commit `588a0333`
(_"fix(auth): require management auth for agent and cooldown APIs"_) पछि लागू गरिएको हो।

| विधि    | मार्ग                         | उद्देश्य                                                             |
| ------- | ----------------------------- | -------------------------------------------------------------------- |
| OPTIONS | `/api/v1/agents/tasks`        | CORS preflight                                                       |
| GET     | `/api/v1/agents/tasks`        | कार्यहरू सूचीबद्ध गर्ने (फिल्टर: `provider`, `status`, `limit≤500`)  |
| POST    | `/api/v1/agents/tasks`        | कार्य सिर्जना गर्ने (upstream मा पठाउँछ र स्थायी रूपमा भण्डारण गर्छ) |
| DELETE  | `/api/v1/agents/tasks?id=...` | query id अनुसार कार्य मेटाउने (upstream मा **रद्द गर्दैन**)          |
| OPTIONS | `/api/v1/agents/tasks/[id]`   | CORS preflight                                                       |
| GET     | `/api/v1/agents/tasks/[id]`   | कार्य पढ्ने र upstream बाट status lazy-sync गर्ने                    |
| POST    | `/api/v1/agents/tasks/[id]`   | कार्य: `approve` / `message` / `cancel`                              |
| DELETE  | `/api/v1/agents/tasks/[id]`   | path id अनुसार कार्य मेटाउने                                         |

### कार्य सिर्जना गर्ने

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Fix the bug in src/foo.ts where the parser returns null",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    },
    "options": {
      "autoCreatePr": true,
      "planApprovalRequired": false
    }
  }'
```

प्रतिक्रिया `201`:

```json
{
  "data": {
    "id": "task_1731512345678_abc123def",
    "providerId": "devin",
    "externalId": "session_xyz",
    "status": "queued",
    "prompt": "...",
    "source": { "repoName": "user/repo", "repoUrl": "...", "branch": "main" },
    "options": { "autoCreatePr": true },
    "createdAt": "2026-05-13T12:34:56.789Z"
  }
}
```

### योजना अनुमोदन गर्ने

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"action":"approve"}'
```

### फलो-अप सन्देश पठाउने

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"message","message":"Also add a unit test for the parser"}'
```

### रद्द गर्ने (स्थानीय status मात्र)

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"cancel"}'
```

`cancel` ले स्थानीय DB मा `status` लाई `"cancelled"` मा परिवर्तन गर्छ, तर
upstream provider लाई call **गर्दैन** — `CloudAgentBase` मा abort RPC छैन। upstream मा
billing रोक्न provider को आफ्नै console बाट कार्य समाप्त गर्नुहोस्।

## REST API — क्लाउड प्रदायक प्लम्बिङ

`src/app/api/cloud/` अन्तर्गतका यी सहायक एन्डपोइन्टहरू दूरस्थ क्लाइन्टहरू
(CLI, Electron एप, वा सिंक वर्करहरू) द्वारा प्रदायक जडान मेटाडेटा पढ्न
र मोडेल एलियासहरू समाधान गर्न प्रयोग गरिन्छन्। यी कार्य एन्डपोइन्टहरूले प्रयोग गर्ने व्यवस्थापन प्रमाणीकरणद्वारा नभई **नियमित API कुञ्जी**
(`validateApiKey` मार्फत) द्वारा प्रमाणीकृत हुन्छन्।

| विधि | पथ                              | उद्देश्य                                                                         |
| ---- | ------------------------------- | -------------------------------------------------------------------------------- |
| POST | `/api/cloud/auth`               | API कुञ्जी प्रमाणित गर्ने, मास्क गरिएको जडान मेटाडेटा + मोडेल एलियासहरू फर्काउने |
| PUT  | `/api/cloud/credentials/update` | `accessToken` / `refreshToken` / `expiresAt` ताजा गर्ने                          |
| POST | `/api/cloud/model/resolve`      | मोडेल एलियासलाई `{ provider, model }` मा समाधान गर्ने                            |
| GET  | `/api/cloud/models/alias`       | सबै मोडेल एलियासहरू सूचीबद्ध गर्ने                                               |
| PUT  | `/api/cloud/models/alias`       | मोडेल एलियास सेट गर्ने (र सक्षम भएमा Cloud सँग स्वतः सिंक गर्ने)                 |

`/api/cloud/auth` ले कहिल्यै कच्चा `apiKey` / `accessToken` / `refreshToken` फर्काउँदैन। यसले
`hasApiKey`, `hasAccessToken`, `hasRefreshToken`, र मास्क गरिएको पूर्वावलोकन
(`maskedApiKey`: पहिलो 4 + `****` + अन्तिम 4) फर्काउँछ।

## क्रेडेन्सियल समाधान

`src/lib/cloudAgent/api.ts` मा रहेको `getCloudAgentCredentials(providerId)`:

1. `getProviderConnections({ provider: providerId, isActive: true })` मार्फत सक्रिय प्रदायक जडानहरू लोड गर्छ।
2. प्रत्येक जडानका लागि, `apiKey` (ट्रिम गरिएको) लाई प्राथमिकता दिन्छ। नभए `accessToken` प्रयोग गर्छ।
3. पहिलो गैर-रिक्त टोकनलाई `{ apiKey: token }` का रूपमा बेरेर फर्काउँछ।
4. प्रयोग गर्न मिल्ने कुनै टोकन नभेटिएमा `null` फर्काउँछ — API ले `400` सहित
   `"क्लाउड एजेन्ट प्रदायकका लागि कुनै सक्रिय क्रेडेन्सियल कन्फिगर गरिएको छैन: <id>"` प्रतिक्रिया दिन्छ।

यसको अर्थ Cloud Agents ले नियमित LLM प्रदायकहरूले प्रयोग गर्ने उही Provider Connection तालिका पुनः प्रयोग गर्छन्।
Jules सक्षम गर्न, `provider: "jules"` भएको सक्रिय जडान सिर्जना गरी त्यसमा
`apiKey` भर्नुहोस्।

## ड्यासबोर्ड

स्रोत: `src/app/(dashboard)/dashboard/cloud-agents/page.tsx`

एउटा `"use client"` React पृष्ठ जसले:

- कार्यहरू सूचीबद्ध गर्छ (`GET /api/v1/agents/tasks` मार्फत आवधिक रूपमा जाँच गरिन्छ)।
- `CreateCloudAgentTaskSchema` मा म्याप हुने फारममार्फत नयाँ कार्यहरू पेस गर्छ।
- स्थिति ब्याजहरू (`queued`, `running`, `awaiting_approval`, `completed`,
  `failed`, `cancelled`) देखाउँछ र `activities[]` समयरेखा रेन्डर गर्छ।
- `status === "completed"` हुँदा `result.prUrl` / `commitMessage` / `summary` देखाउँछ।

## A2A सँग एकीकरण

Cloud Agents लाई A2A सीपका रूपमा उपलब्ध गराउन, यसको `tasks/send` ह्यान्डलरलाई
`getAgent(...).createTask(...)` मा प्रत्यायोजन गर्ने र A2A कार्य स्थिति घटनाहरूलाई
JSON-RPC 2.0 प्रोटोकलमा रूपान्तरण गर्ने A2A सीप दर्ता गर्न सकिन्छ। [A2A-SERVER.md](./A2A-SERVER.md) हेर्नुहोस्।

## नयाँ क्लाउड एजेन्ट थप्ने

1. `CloudAgentBase` विस्तार गर्ने `src/lib/cloudAgent/agents/<name>.ts` सिर्जना गर्नुहोस्।
2. `createTask`, `getStatus`, `approvePlan` (वा लागू नहुने भए त्रुटि फ्याँक्ने),
   `sendMessage`, `listSources` कार्यान्वयन गर्नुहोस्। स्थिति सामान्यीकरणका लागि `this.mapStatus(...)` प्रयोग गर्नुहोस्।
3. स्थिर `providerId` अन्तर्गत `src/lib/cloudAgent/registry.ts` मा दर्ता गर्नुहोस्।
4. `src/lib/cloudAgent/types.ts` मा रहेको `providerId` लिटरल युनियन विस्तार गर्नुहोस्
   (`CloudAgentTask.providerId` र `CreateCloudAgentTaskSchema`)।
5. जडान रेकर्ड आवश्यक भए प्रदायकलाई `src/shared/constants/providers.ts` मा थप्नुहोस्।
   OAuth-आधारित प्रदायकहरूलाई `src/lib/oauth/providers/` पनि आवश्यक हुन्छ।
6. `tests/unit/cloud-agent-*.test.ts` अन्तर्गत परीक्षणहरू थप्नुहोस्।
7. यो कागजात र ड्यासबोर्डको `CLOUD_AGENTS` स्थिरांक अद्यावधिक गर्नुहोस्।
