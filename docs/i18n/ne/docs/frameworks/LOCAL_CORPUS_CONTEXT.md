## यो के हो

Local Corpus ले अपरेटरलाई पाठ फाइलहरूको स्पष्ट रूपमा स्वीकृत एउटा डाइरेक्टरी
OmniRoute को MCP सर्भरमा उपलब्ध गराउन दिन्छ। फाइलहरू आफ्नै मूल डाइरेक्टरीमा रहन्छन्:
OmniRoute ले SQLite मा केवल क्यानोनिकल मूल पथ भण्डारण गर्छ र इन-मेमोरी खोज अनुक्रमणिका
कायम राख्छ। यसले कर्पसको सामग्रीलाई रिपोजिटरी वा डेटाबेसमा प्रतिलिपि गर्दैन।

अनुक्रमणिका रिफ्रेस क्रमिक रूपमा हुन्छ। परिवर्तन नभएका फाइलहरू तिनको आकार र परिमार्जन
समयका आधारमा पुनः प्रयोग गरिन्छन्, परिवर्तन भएका फाइलहरू पुनः पढेर SHA-256 मार्फत
ह्यास गरिन्छन्, र मेटिएका फाइलहरू हटाइन्छन्। खोज गर्दा ३० सेकेन्डभन्दा पुरानो अनुक्रमणिका
रिफ्रेस हुन्छ; कलरहरूले तत्काल रिफ्रेसको अनुरोध पनि गर्न सक्छन्।

## स्रोत कन्फिगर गर्नुहोस्

सेटिङ्स रुटलाई अन्य सेटिङ्स API हरूलाई जस्तै व्यवस्थापन प्रमाणीकरण आवश्यक पर्छ।
पेस गरिएको पथ पहिले नै अवस्थित हुनुपर्छ र निरपेक्ष डाइरेक्टरी पथ हुनुपर्छ।

```bash
# स्वीकृत डाइरेक्टरी जडान गर्नुहोस्
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# कन्फिगरेसन र अनुक्रमणिका स्थिति जाँच गर्नुहोस्
curl http://localhost:20128/api/settings/local-corpus

# स्रोत फाइलहरू परिवर्तन नगरी विच्छेद गर्नुहोस्
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## MCP उपकरणहरू

तीनै उपकरणका लागि `read:local-corpus` आवश्यक पर्छ। उपकरणका प्रतिक्रियाहरूले सापेक्ष पथहरू
र मूल डाइरेक्टरीको आधार नाम देखाउँछन्, यसको निरपेक्ष पथ कहिल्यै देखाउँदैनन्।

| उपकरण                 | विवरण                                                                             |
| :-------------------- | :-------------------------------------------------------------------------------- |
| `local_corpus_status` | कन्फिगरेसन अवस्था, अनुक्रमणिका आकार, सीमाहरू र पछिल्लो रिफ्रेस समय रिपोर्ट गर्छ   |
| `local_corpus_search` | अनुक्रमित पाठ खोज्छ र सीमित, लाइन-क्षेत्रका स्निपेटहरू फर्काउँछ (बढीमा २० परिणाम) |
| `local_corpus_read`   | एउटा अनुमति प्राप्त कर्पस-सापेक्ष फाइलबाट सीमित लाइन दायरा पढ्छ                   |

MCP इनपुटका उदाहरणहरू:

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## सुरक्षा सीमाहरू

- अनुमति सूची पाठ-केन्द्रित छ: `.cfg`, `.csv`, `.geojson`, `.htm`, `.html`, `.ini`,
  `.js`, `.json`, `.jsonl`, `.jsx`, `.log`, `.md`, `.mjs`, `.ps1`, `.py`, `.sh`,
  `.sql`, `.toml`, `.ts`, `.tsx`, `.txt`, `.xml`, `.yaml`, र `.yml`।
- सिमलिङ्कहरू छोडिन्छन्। पढ्ने पथहरू क्यानोनिकल बनाइन्छन् र कन्फिगर गरिएको मूलभित्रै
  रहनुपर्छ; निरपेक्ष पथ र ट्राभर्सल प्रयासहरू अस्वीकार गरिन्छन्।
- संवेदनशील र उत्पन्न गरिएका डाइरेक्टरी नामहरू समावेश गरिँदैनन्: `.build`, `.codex`, `.env`,
  `.git`, `.next`, `.omniroute`, `.ssh`, `coverage`, `dist`, `node_modules`, र
  `secrets`।
- पूर्वनिर्धारित सीमाहरू ५,००० फाइल, प्रति फाइल १ MiB, कुल अनुक्रमित सामग्री ६४ MiB,
  प्रति खोज खण्ड लगभग ४,००० वर्ण, र प्रति पढाइ ४०० लाइन हुन्।
- NUL समावेश भएका फाइलहरूलाई गैर-पाठका रूपमा लिइन्छ र छोडिन्छ वा अस्वीकार गरिन्छ।

PDF, DOCX, छवि र अभिलेखजस्ता बाइनरी कागजातहरू जानाजानी समर्थित छैनन्।
अनुक्रमणिकामा राख्नुअघि तिनलाई कन्फिगर गरिएको डाइरेक्टरीमा स्वीकृत पाठ ढाँचामा रूपान्तरण गर्नुहोस्।

## सञ्चालनसम्बन्धी टिप्पणीहरू

- कन्फिगर गरिएको मूल परिवर्तन वा मेटाउँदा साझा इन-मेमोरी अनुक्रमणिका खाली हुन्छ।
- प्रक्रिया पुनः सुरु गर्दा अनुक्रमणिका हट्छ; अर्को खोजले यसलाई कन्फिगर गरिएको
  स्रोतबाट पुनर्निर्माण गर्छ।
- `local_corpus_status` ले स्क्यान गर्न बाध्य पार्दैन। तत्काल पुनः स्क्यान आवश्यक हुँदा
  `refresh: true` सहित `local_corpus_search` प्रयोग गर्नुहोस्।
- स्क्यान र पढाइका विफलताहरू गणना गरिन्छन् वा सफा गरिएका त्रुटिका रूपमा फर्काइन्छन्;
  स्रोत फाइलहरू कहिल्यै परिमार्जन गरिँदैनन्।
