> **सत्यको स्रोत:** `src/lib/obsidian/api.ts` (REST + सिंक क्लाइन्ट),
> `src/lib/db/obsidian.ts` (टोकन / आधार-URL / WebDAV स्थायित्व),
> `src/lib/obsidianSync.ts` (WebDAV भल्ट सिंक), `open-sse/mcp-server/tools/obsidianTools.ts`
> (22 MCP उपकरण), `src/app/api/settings/obsidian/route.ts` +
> `src/app/api/settings/obsidian/webdav/route.ts` (सेटिङ API हरू)। उपकरण दर्ता
> र स्कोप वायरिङ `open-sse/mcp-server/server.ts` मा हुन्छ।

## यो के हो

OmniRoute ले **Obsidian** भल्टलाई **सन्दर्भ स्रोत** का रूपमा जडान गर्छ — यो स्थानीय Markdown
ज्ञानकोष हो, जसलाई एजेन्टहरूले अन्तर्निर्मित MCP सर्भरमार्फत पढ्न र लेख्न सक्छन्। यो
एकीकरणले डेस्कटप एपभित्र चलिरहेको **Obsidian Local REST API** सामुदायिक प्लगइनसँग
सञ्चार गर्छ, जसले एजेन्टहरूलाई नोट खोज्न, फाइलहरू पढ्न/लेख्न/प्याच गर्न, भल्टको सूची हेर्न,
दैनिक/साप्ताहिक आवधिक नोटहरूसँग काम गर्न, ट्यागहरू व्यवस्थापन गर्न, Obsidian कमान्डहरू
चलाउन, र (वैकल्पिक रूपमा) द्विदिशात्मक डेस्कटप↔मोबाइल भल्ट सिंक समन्वय गर्न दिन्छ।

क्लाइन्ट (`src/lib/obsidian/api.ts`) ले Local REST API लाई निम्न सुविधासहित र्याप गर्छ:

- अस्थायी `5xx` का लागि **ब्याकअफसहित पुनः प्रयास**, `AbortController` मार्फत **30-सेकेन्ड टाइमआउट**।
- **टाइप गरिएको त्रुटि वर्गीकरण** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`।
- सामान्य पोर्टसम्बन्धी गल्ती (HTTP `27123` मा, `27124` को MCP एन्डपोइन्टमा **होइन**) र
  Tailscale ढाँचा औँल्याउने प्रयोगकर्तामैत्री **"Obsidian सम्म पुग्न सकिएन" सङ्केत**।
- खाली ठाउँ/स्ल्यास भएका नोट पथहरू सुरक्षित राख्न भल्ट-सापेक्ष **पथ इन्कोडिङ**।

## सेटअप

Obsidian टोकन वा आधार URL का लागि **कुनै वातावरण चर छैन** — दुवैलाई
`src/lib/db/obsidian.ts` मार्फत SQLite को `key_value` तालिका (नेमस्पेस `obsidian`) मा
भण्डारण गरिन्छ। टोकनलाई **भण्डारण अवस्थामा इन्क्रिप्ट** गरिन्छ (AES-256-GCM, प्लेनटेक्स्ट
पछाडि-सङ्गतता फलब्याकसहित)। Endpoint ड्यासबोर्डको **Context Sources** ट्याब
(`ObsidianSourceCard`) बाट वा सेटिङ REST API मार्फत कन्फिगर गर्नुहोस्।

> [!IMPORTANT]
> **Obsidian Local REST API** प्लगइन इन्स्टल गरिएको र चलिरहेको हुनुपर्छ। यसको REST
> इन्टरफेसले **HTTP `127.0.0.1:27123`** मा सुन्छ (पूर्वनिर्धारित आधार URL)। पोर्ट `27124`
> एउटा _छुट्टै_ MCP/HTTPS एन्डपोइन्ट हो र सेटिङ रुटले यसलाई स्पष्ट रूपमा अस्वीकार गर्छ।
> अर्को उपकरणबाट जडान गर्दै हुनुहुन्छ भने `http://<tailscale-ip>:27123` प्रयोग गर्नुहोस्।

### कन्फिगरेसन कुञ्जीहरू (SQLite `key_value`, नेमस्पेस `obsidian`)

| कुञ्जी            | प्रयोजन                                                 | इन्क्रिप्ट गरिएको |
| ----------------- | ------------------------------------------------------- | ----------------- |
| `api_key`         | Local REST API बियरर टोकन                               | हो                |
| `base_url`        | REST आधार URL (पूर्वनिर्धारित `http://127.0.0.1:27123`) | होइन              |
| `vault_path`      | भल्ट डाइरेक्टरीको निरपेक्ष पथ (सिंकका लागि)             | होइन              |
| `webdav_username` | उत्पन्न गरिएको WebDAV प्रयोगकर्ता नाम (भल्ट सिंक)       | होइन              |
| `webdav_password` | उत्पन्न गरिएको WebDAV पासवर्ड (भल्ट सिंक)               | हो                |
| `webdav_enabled`  | WebDAV भल्ट सिंक सक्षम छ कि छैन                         | होइन              |

### REST मार्फत कन्फिगर गर्नुहोस्

```bash
# Local REST API टोकन सेभ + मान्य गर्नुहोस् (POST ले स्थिति जाँचमार्फत मान्य गर्छ)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# जडान स्थिति जाँच गर्नुहोस् (connected, hasToken, baseUrl, vaultPath फर्काउँछ)
curl http://localhost:20128/api/settings/obsidian

# जडान विच्छेद गर्नुहोस् (भण्डारण गरिएको टोकन हटाउँछ)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

सबै विधिहरूलाई ड्यासबोर्ड प्रमाणीकरण आवश्यक हुन्छ। `POST` ले पोर्ट `27124` मा भएको कुनै
पनि URL अस्वीकार गर्छ र सुरक्षित राख्नुअघि Local REST API को स्थिति एन्डपोइन्ट कल गरेर
टोकन मान्य गर्छ।

### WebDAV भल्ट सिंक

`src/app/api/settings/obsidian/webdav/route.ts` ले वैकल्पिक WebDAV-समर्थित
भल्ट सिंक व्यवस्थापन गर्छ (`src/lib/obsidianSync.ts` द्वारा सञ्चालित)। यसलाई सक्षम गर्दा
OmniRoute लाई स्थानीय भल्ट डाइरेक्टरीतर्फ देखाइन्छ र अनियमित WebDAV प्रयोगकर्ता
नाम/पासवर्ड जोडी सिर्जना गरिन्छ:

```bash
# भल्ट डाइरेक्टरीका लागि WebDAV सिंक सक्षम गर्नुहोस् (प्रयोगकर्ता नाम/पासवर्ड सिर्जना गर्छ)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# WebDAV सिंक स्थिति प्राप्त गर्नुहोस् (सक्षम हुँदा मात्र प्रमाणहरू फर्काइन्छ)
curl http://localhost:20128/api/settings/obsidian/webdav

# WebDAV सिंक असक्षम गर्नुहोस् (प्रमाणहरू + व्यवस्थापित .stignore हटाउँछ)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### प्रति-API-कुञ्जी सन्दर्भ स्रोत (वैकल्पिक)

Obsidian कन्फिगलाई `api_key_context_sources` तालिकामार्फत **प्रति API कुञ्जी**
स्कोप गर्न सकिन्छ (`src/lib/db/apiKeyContextSources.ts`)। MCP कलले प्रमाणीकरण गरिएको
API कुञ्जी id बोक्दा, `getObsidianConfigForApiKey()` ले पहिले उक्त कुञ्जीकै
टोकन/आधार-URL/भल्ट-पथ (`source: "api_key"`) रोज्छ र त्यो नभए ग्लोबल कन्फिग
(`source: "global"`) मा फलब्याक गर्छ।

## MCP उपकरणहरू (22)

`open-sse/mcp-server/tools/obsidianTools.ts` मा परिभाषित। टोकन/base-URL प्रत्येक कलका लागि समाधान गरिन्छ
(पहिले प्रति-API-key, त्यसपछि ग्लोबल)। OmniRoute **sync server** प्रयोग गर्ने उपकरणहरू
(चारवटा `obsidian_sync_*` उपकरणहरू) लाई थप रूपमा OmniRoute सेटिङहरूमा कन्फिगर गरिएको sync auth token आवश्यक पर्छ।

### पढ्ने उपकरणहरू (`read:obsidian`)

| उपकरण                        | विवरण                                                                                             |
| ---------------------------- | ------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Local REST API पहुँचयोग्य र प्रमाणीकरण गरिएको छ कि छैन जाँच गर्नुहोस्।                            |
| `obsidian_search_simple`     | नोट सामग्रीको पूर्ण-पाठ खोज; फाइल पाथसहित स्निपेटहरू फर्काउँछ।                                    |
| `obsidian_search_structured` | JSON Logic अभिव्यक्ति (and/or/regex/path फिल्टरहरू) प्रयोग गरेर खोज्नुहोस्।                       |
| `obsidian_read_note`         | vault-relative पाथद्वारा नोट पढ्नुहोस्; वैकल्पिक रूपमा कुनै विशिष्ट heading/block/frontmatter।    |
| `obsidian_list_vault`        | vault भित्रका फाइल र डाइरेक्टरीहरू सूचीबद्ध गर्नुहोस् (प्रविष्टिहरूको ट्री)।                      |
| `obsidian_get_document_map`  | नोटको heading संरचना headings → line numbers को म्यापका रूपमा प्राप्त गर्नुहोस्।                  |
| `obsidian_get_note_metadata` | पूर्ण सामग्रीबिना frontmatter, tags, links, char/word count प्राप्त गर्नुहोस्।                    |
| `obsidian_get_active_file`   | Obsidian मा हाल सक्रिय फाइलको पाथ + सामग्री प्राप्त गर्नुहोस्।                                    |
| `obsidian_get_periodic_note` | कुनै मितिका लागि दैनिक/साप्ताहिक/मासिक periodic note प्राप्त गर्नुहोस् (नदिइएमा आजको)।            |
| `obsidian_get_tags`          | सबै vault tags तिनको आवृत्तिसहित सूचीबद्ध गर्नुहोस्।                                              |
| `obsidian_list_commands`     | उपलब्ध Obsidian command IDs सूचीबद्ध गर्नुहोस् (`obsidian_execute_command` सँग प्रयोग गर्नुहोस्)। |
| `obsidian_sync_status`       | OmniRoute sync server को स्थिति: चलिरहेको अवस्था, vault नाम, port, uptime, पछिल्लो sync।          |
| `obsidian_sync_conflicts`    | समाधान नगरिएका sync conflicts सूचीबद्ध गर्नुहोस् (path, conflict path, detected-at)।              |

### लेख्ने उपकरणहरू (`write:obsidian`)

| उपकरण                            | विवरण                                                                                            |
| -------------------------------- | ------------------------------------------------------------------------------------------------ |
| `obsidian_write_note`            | दिइएको Markdown सामग्रीसहित नोट सिर्जना गर्नुहोस् वा अधिलेखन गर्नुहोस्।                          |
| `obsidian_append_note`           | नोटमा सामग्री थप्नुहोस्; वैकल्पिक रूपमा कुनै विशिष्ट heading/block मा।                           |
| `obsidian_patch_note`            | heading, block, वा frontmatter field मा सटीक रूपमा append/prepend/replace गर्नुहोस्।             |
| `obsidian_delete_note`           | vault बाट नोट स्थायी रूपमा मेटाउनुहोस्।                                                          |
| `obsidian_move_note`             | vault भित्र नोट सार्नुहोस् वा पुनः नामकरण गर्नुहोस्।                                             |
| `obsidian_execute_command`       | यसको command ID द्वारा Obsidian command कार्यान्वयन गर्नुहोस्।                                   |
| `obsidian_open_file`             | Obsidian मा फाइल खोल्नुहोस् (अवस्थित नभएमा सिर्जना गर्छ)।                                        |
| `obsidian_sync_trigger`          | तत्काल द्विदिशात्मक desktop↔mobile vault sync सुरु गर्नुहोस्।                                    |
| `obsidian_sync_resolve_conflict` | sync conflict समाधान गर्नुहोस्: `local` (mobile), `remote` (desktop), वा `keep-both` राख्नुहोस्। |

> [!NOTE]
> `obsidian_patch_note` का targets ले `heading | block | frontmatter` मध्ये `targetType`
> र `append | prepend | replace` मध्ये `operation` स्वीकार गर्छन्, साथै वैकल्पिक
> `createTargetIfMissing`। चारवटा `obsidian_sync_*` उपकरणहरूले स्थानीय sync
> server (पूर्वनिर्धारित रूपमा `http://127.0.0.1:27781`) सँग सञ्चार गर्छन् र sync token आवश्यक पर्छ।

### स्कोपहरू

पढ्ने उपकरणहरूलाई `read:obsidian` आवश्यक पर्छ; लेख्ने उपकरणहरूलाई `write:obsidian` आवश्यक पर्छ। प्रवर्तन
Notion सरह नै छ — `open-sse/mcp-server/server.ts` मा `withScopeEnforcement()` द्वारा सम्हालिन्छ,
`OMNIROUTE_MCP_ENFORCE_SCOPES=true` हुँदा सक्रिय हुन्छ, र अनुमति दिइएका स्कोपहरू
`OMNIROUTE_MCP_SCOPES` वा API key को scope context बाट लिइन्छन्। हेर्नुहोस्
[MCP-SERVER.md](./MCP-SERVER.md)।

## एन्डपोइन्टहरू

| विधि     | पथ                              | उद्देश्य                                                            |
| -------- | ------------------------------- | ------------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | `{ connected, hasToken, baseUrl, vaultPath }` फिर्ता गर्छ।          |
| `POST`   | `/api/settings/obsidian`        | टोकन सुरक्षित गर्छ र प्रमाणीकरण गर्छ (`27124` पोर्ट अस्वीकार गर्छ)। |
| `DELETE` | `/api/settings/obsidian`        | जडान विच्छेद गर्छ (भण्डारण गरिएको टोकन हटाउँछ)।                     |
| `GET`    | `/api/settings/obsidian/webdav` | WebDAV सिंकको स्थिति र प्रमाणहरू (सक्षम रहँदा)।                     |
| `POST`   | `/api/settings/obsidian/webdav` | भल्ट डाइरेक्टरीका लागि WebDAV सिंक सक्षम गर्छ।                      |
| `DELETE` | `/api/settings/obsidian/webdav` | WebDAV सिंक असक्षम गर्छ।                                            |

> यी ड्यासबोर्ड सेटिङ मार्गहरू हुन्। भल्टमा Obsidian
> Local REST API (कन्फिगर गरिएको `base_url`) र माथिका MCP उपकरणहरूमार्फत पहुँच गरिन्छ —
> कुनै सार्वजनिक `/v1` Obsidian प्रोक्सी एन्डपोइन्ट छैन।

## प्रयोगका अवस्थाहरू

- **भल्टमा आधारित उत्तरहरू** — `obsidian_search_simple` / `obsidian_search_structured`
  र त्यसपछि `obsidian_read_note`, जसले गर्दा एजेन्टले तपाईंका वास्तविक नोटहरूबाट उत्तर दिन्छ।
- **नोट लेखन / जर्नलिङ** — एजेन्टको आउटपुट, सारांश वा दैनिक नोटहरू
  (`obsidian_get_periodic_note`) भल्टमा अभिलेख गर्न `obsidian_write_note`, `obsidian_append_note`, वा
  सूक्ष्म सम्पादनका लागि `obsidian_patch_note`।
- **भल्ट नेभिगेसन** — पढ्नु/लेख्नुअघि संरचना अन्वेषण गर्न `obsidian_list_vault`, `obsidian_get_document_map`, र
  `obsidian_get_tags`।
- **Obsidian स्वचालन** — एजेन्टबाट प्लगइन/कमाण्डहरू सञ्चालन गर्न `obsidian_list_commands` + `obsidian_execute_command`;
  UI मा नोट देखाउन `obsidian_open_file`।
- **मोबाइल सिंक** — WebDAV सिंक सक्षम गर्नुहोस्, त्यसपछि डेस्कटप↔मोबाइल समन्वय गर्न र द्वन्द्वहरू समाधान गर्न
  `obsidian_sync_trigger` / `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`।
