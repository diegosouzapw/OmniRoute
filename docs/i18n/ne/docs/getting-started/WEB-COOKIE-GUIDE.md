वेब कुकी प्रदायकहरूले OmniRoute लाई API कुञ्जीको सट्टा तपाईंको विद्यमान ब्राउजर सत्रमार्फत AI सेवा प्रयोग गर्न दिन्छन्। तपाईंले कुनै सेवाको वेबसाइटमार्फत पहिले नै पहुँच प्राप्त गर्नुभएको छ र OmniRoute ले पनि त्यही प्रमाणीकरण गरिएको सत्र प्रयोग गरोस् भन्ने चाहनुहुन्छ भने यी उपयोगी हुन्छन्।

API-कुञ्जी प्रदायकहरूभन्दा फरक, वेब कुकी प्रदायकहरूले तपाईंको ब्राउजरले वेबसाइटमा पठाउने प्रमाणहरू प्रयोग गरेर प्रमाणीकरण गर्छन्।

---

# सुरु गर्नुअघि

> **महत्त्वपूर्ण:** प्रमाणहरू सधैँ **प्रत्यक्ष नेटवर्क अनुरोधबाट** प्रतिलिपि गर्नुहोस्, तपाईंको ब्राउजरको कुकी भण्डारणबाट **होइन**।

धेरै प्रमाणीकरण समस्याहरू गलत स्थानबाट कुकीहरू प्रतिलिपि गर्दा उत्पन्न हुन्छन्।

## कुकी भण्डारणबाट प्रतिलिपि नगर्नुहोस्

धेरैजसो ब्राउजरहरूले भण्डारण गरिएका कुकीहरू यहाँ देखाउँछन्:

```
डेभलपर उपकरणहरू
→ Application (वा Storage)
→ Cookies
```

यी कुकीहरू सही देखिए तापनि, तिनीहरू:

- पुराना हुन सक्छन्
- अपूर्ण हुन सक्छन्
- प्रमाणीकरण गरिएका अनुरोधहरूमा मात्र पठाइने कुकीहरू छुटेका हुन सक्छन्

यी मानहरू प्रयोग गर्दा तिनीहरू मान्य देखिए पनि प्रमाणीकरण असफल हुन सक्छ।

## प्रत्यक्ष अनुरोधबाट प्रतिलिपि गर्नुहोस्

यसको सट्टा, सफल अनुरोधका कुकीहरू प्रयोग गर्नुहोस्:

```
डेभलपर उपकरणहरू
→ Network
→ पृष्ठ रिफ्रेस गर्नुहोस्
→ च्याट वा वार्तालाप अनुरोध खोल्नुहोस्
→ Request Headers
→ Cookie
```

`Cookie` अनुरोध हेडरमा तपाईंको ब्राउजरले सफलतापूर्वक प्रयोग गरेको ठ्याक्कै प्रमाणीकरण जानकारी हुन्छ।

धेरैजसो वेब कुकी प्रदायकहरूका लागि, OmniRoute मा टाँस्नुपर्ने मान यही हो।

# सामान्य सेटअप

धेरैजसो वेब कुकी प्रदायकहरूका लागि सेटअप प्रक्रिया समान हुन्छ।

1. प्रदायकको वेबसाइटमा साइन इन गर्नुहोस्।
2. ब्राउजरको डेभलपर उपकरणहरू खोल्नुहोस्।
3. **Network** ट्याब खोल्नुहोस्।
4. पृष्ठ रिफ्रेस गर्नुहोस्।
5. प्रमाणीकरण गरिएको च्याट वा वार्तालाप अनुरोध खोल्नुहोस्।
6. आवश्यक प्रमाणीकरण प्रमाणहरू प्रतिलिपि गर्नुहोस्।
7. OmniRoute खोल्नुहोस्।
8. **Providers → Add Provider** मा जानुहोस्।
9. आफ्नो वेब कुकी प्रदायक चयन गर्नुहोस्।
10. प्रमाणहरू टाँस्नुहोस्।
11. **Test Connection** मा क्लिक गर्नुहोस्।
12. प्रदायक सेभ गर्नुहोस्।

आवश्यक पर्ने ठ्याक्कै प्रमाणहरू प्रदायकअनुसार फरक हुन्छन्।

# वेब कुकी प्रदायकहरूले के गर्न सक्छन् र के गर्न सक्दैनन्

वेब कुकी प्रदायकहरूले वेबसाइटको च्याट इन्टरफेस पुनः प्रयोग गर्छन्। तिनीहरूले आधिकारिक API हरूजस्तै क्षमताहरू **प्रदान गर्दैनन्**।

## समर्थित

- तपाईंको विद्यमान ब्राउजर सत्र प्रयोग गरेर प्रमाणीकरण गर्ने
- तपाईंको खातामार्फत उपलब्ध मोडेलहरूमा पहुँच गर्ने
- च्याट प्रतिक्रियाहरू स्ट्रिम गर्ने
- API कुञ्जी आवश्यक नपर्ने

## समर्थित छैन

- फङ्क्सन कलिङ
- टुल कलिङ
- स्वचालित फाइल सम्पादन
- एजेन्टिक IDE कार्यप्रवाहहरू
- API मा मात्र उपलब्ध सुविधाहरू

यो अपेक्षित व्यवहार हो र **बग होइन**।

तपाईंलाई टुल कार्यान्वयन, स्वचालित फाइल सम्पादन वा अन्य एजेन्ट कार्यप्रवाहहरू आवश्यक छन् भने वेब कुकी प्रदायकको सट्टा **API-कुञ्जी प्रदायक** प्रयोग गर्नुहोस्।

# प्रमाणीकरणसम्बन्धी सावधानी

सफल **Test Connection** वा कुकी प्रमाणीकरणले उपलब्ध गराइएका प्रमाणहरू अपेक्षित ढाँचामा भएको देखिन्छ भन्ने मात्र पुष्टि गर्छ।

Issue #7857 समाधान नभएसम्म, सफल प्रमाणीकरणले प्रदायक सफलतापूर्वक प्रमाणीकृत हुनेछ भन्ने **ग्यारेन्टी गर्दैन**।

प्रमाणीकरण अझै असफल भएमा, तपाईंले प्रमाणहरू ब्राउजरको कुकी भण्डारणबाट नभई प्रत्यक्ष नेटवर्क अनुरोधबाट प्रतिलिपि गर्नुभएको हो भनी जाँच गर्नुहोस्।

# समस्या समाधान

## प्रमाणीकरण असफल हुन्छ

प्रमाणहरू यहाँबाट प्रतिलिपि गरिएको हो भनी जाँच गर्नुहोस्:

```
Network
→ Request Headers
→ Cookie
```

र यहाँबाट **होइन**:

```
Application
→ Cookies
```

---

## कुकी ब्राउजरमा काम गर्छ तर OmniRoute मा गर्दैन

केही प्रदायकहरूले प्रमाणीकरण गरिएका अनुरोधहरूका क्रममा मात्र पठाइने कुकीहरू समावेश गर्छन्।

वार्तालाप सफलतापूर्वक खोलेपछि नयाँ नेटवर्क अनुरोधबाट प्रमाणहरू पुनः प्रतिलिपि गर्नुहोस्।

---

## सत्रको म्याद समाप्त भयो

वेब कुकी प्रदायकहरूले तपाईंको विद्यमान ब्राउजर सत्र प्रयोग गर्छन्।

तपाईंको ब्राउजर सत्रको म्याद समाप्त भएमा वा तपाईंले साइन आउट गर्नुभयो भने, तपाईंले प्रमाणहरूको नयाँ सेट प्रतिलिपि गर्नुपर्छ।

---

## Test Connection सफल हुन्छ तर अनुरोधहरू असफल हुन्छन्

Issue #7857 समाधान नभएसम्म, प्रमाणीकरण सफल हुनुले प्रमाणीकरण अनुरोध सफल हुनेछ भन्ने ग्यारेन्टी गर्दैन।

थप समस्या समाधान गर्नुअघि नयाँ प्रमाणीकरण गरिएको अनुरोधबाट आफ्ना प्रमाणहरू पुनः प्रतिलिपि गर्नुहोस्।

# प्रदायकको उदाहरण

प्रदायक-विशिष्ट पूर्ण चरणबद्ध निर्देशनका लागि, हेर्नुहोस्:

Claude Web निर्देशिकाले वेब कुकी प्रदायकको पूर्ण सेटअप प्रक्रिया देखाउँछ र सन्दर्भ कार्यान्वयनका रूपमा काम गर्छ।

# उत्कृष्ट अभ्यासहरू

- नयाँ प्रमाणीकरण गरिएको अनुरोधबाट प्रमाणहरू प्रतिलिपि गर्नुहोस्।
- पुराना कुकीहरू पुनः प्रयोग नगर्नुहोस्।
- वेब कुकी प्रदायकहरू प्रयोग गर्दा आफ्नो ब्राउजर सत्र सक्रिय राख्नुहोस्।
- प्रतिलिपि गरिएका कुकीहरूलाई संवेदनशील प्रमाणका रूपमा व्यवहार गर्नुहोस्।
- तपाईंलाई फङ्क्सन कलिङ वा एजेन्ट कार्यप्रवाहहरू आवश्यक हुँदा API-कुञ्जी प्रदायकहरू प्रयोग गर्नुहोस्।
