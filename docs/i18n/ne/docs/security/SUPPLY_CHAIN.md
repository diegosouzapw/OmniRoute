OmniRoute ले npm + Docker आर्टिफ्याक्टहरू प्रकाशित गर्छ। यी गेटहरूले उद्गम प्रमाण,
इन्भेन्टरी (SBOM) र CVE स्क्यानिङ उपलब्ध गराउँछन्; यी सबै OSS हुन् र रिलिज कार्यप्रवाहहरूमा जडान गरिएका छन्।
**पहिले-सूचना** दृष्टिकोण — अहिले तिनले रिपोर्ट गर्छन् र पहिलो
सफल रिलिजपछि अवरोधक बनाइन्छन्।

| गेट                     | उपकरण                                          | कहाँ                          | अवरोध गर्छ?             | आउटपुट                                                   |
| ----------------------- | ---------------------------------------------- | ----------------------------- | ----------------------- | -------------------------------------------------------- |
| SLSA उद्गम प्रमाण (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | प्रकाशन असफल भएमा मात्र | npmjs ब्याज / `npm audit signatures`                     |
| SBOM npm                | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | उत्पादन असफल भएमा मात्र | रिलिज एसेट + आर्टिफ्याक्ट                                |
| SBOM इमेज               | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (मर्ज)   | सूचनामूलक               | CycloneDX आर्टिफ्याक्ट                                   |
| Trivy CVE (SARIF)       | `aquasecurity/trivy-action`                    | `docker-publish.yml` (मर्ज)   | सूचनामूलक               | SARIF (HIGH+CRITICAL) → Security ट्याब                   |
| Trivy CRITICAL गेट      | `aquasecurity/trivy-action`                    | `docker-publish.yml` (मर्ज)   | **अवरोधक**              | समाधानयोग्य CRITICAL मा `exit-code: '1'`                 |
| osv vulnCount           | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **अवरोधक**              | `metrics.vulnCount` लाई क्रमशः घटाउँछ (`direction:down`) |
| OpenSSF Scorecard       | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | सूचनामूलक               | SARIF → Security + ब्याज                                 |

इमेज CVE र्याचेटले `docker-publish.yml` मा **दुई चरणहरू** प्रयोग गर्छ: SARIF चरणले
(`HIGH,CRITICAL`, `exit-code: 0`) अवरोध नगरी HIGH+CRITICAL लाई Security ट्याबमा
दृश्य राख्छ; _CRITICAL गेट_ चरणले (`severity: CRITICAL`, `ignore-unfixed: true`,
`exit-code: 1`) **समाधान उपलब्ध भएको** CRITICAL CVE भेटिँदा रिलिज असफल बनाउँछ। `ignore-unfixed`
ले अपस्ट्रिम प्याच नभएको बेस-इमेज CVE का कारण रिलिज अवरुद्ध हुनबाट रोक्छ।

## ⚠️ CVE भिन्नता (अवरोधक osv/Trivy गेटहरू)

osv र Trivy ले निर्भरताहरूलाई **निरन्तर बढिरहेका** CVE डेटाबेसहरूसँग तुलना गर्छन्। कुनै PR ले
**कुनै पनि निर्भरता नछोए पनि**, विद्यमान निर्भरतामा नयाँ CVE
सार्वजनिक हुँदा अचानक असफल हुन सक्छ (osv: मापन गरिएको `vulnCount` > आधाररेखा; Trivy: इमेजमा नयाँ
समाधानयोग्य CRITICAL)। **यो अवरोधक CVE गेटको अपेक्षित सञ्चालन व्यवहार हो,
उत्पादनको रिग्रेसन होइन।**

नयाँ सार्वजनिक गरिएको CVE का कारण osv वा Trivy असफल हुँदा, समाधान यस्तो हुन्छ:

1. **प्रभावित निर्भरताको संस्करण बढाउनुहोस्** (प्राथमिकता प्राप्त) — `package.json`
   `overrides` (अप्रत्यक्ष निर्भरताहरू) मार्फत प्याच गरिएको संस्करणमा अपग्रेड गर्नुहोस् वा प्याच गरिएको बेसमा इमेज पुनर्निर्माण गर्नुहोस्।
2. **यदि कुनै अपस्ट्रिम समाधान छैन भने:**
   - **osv:** `config/quality/quality-baseline.json` मा `metrics.vulnCount` को आधाररेखा पुनः निर्धारण गर्नुहोस्
     (`npm run quality:ratchet -- --update` ले समर्पित गेटहरू समेट्दैन — औचित्य टिप्पणी + ट्र्याकिङ इस्यूसहित
     मानलाई हातैले सम्पादन गर्नुहोस्, `direction:down`)।
   - **Trivy:** औचित्य टिप्पणी + ट्र्याकिङ इस्यूसहित `.trivyignore` मा एउटा प्रविष्टि
     (प्रति पङ्क्ति CVE-ID) थप्नुहोस्। `ignore-unfixed: true` ले प्याच नभएका CVE हरूलाई
     पहिले नै स्वचालित रूपमा समेट्छ।

उपकरण अनुपस्थित हुँदा वा मापन असफल हुँदा (osv-scanner PATH मा नभएको,
osv.dev/network पहुँचयोग्य नभएको, अमान्य JSON) दुवै गेटले **सहज रूपमा SKIP** (exit 0) गर्छन् —
**मापन** असफलताले कहिल्यै अवरोध गर्दैन; **मापन गरिएको** रिग्रेसनले मात्र अवरोध गर्छ।

## बाँकी कार्य: Scorecard सूचनामूलक → अवरोधक

Scorecard रिपोर्टिङसहितको पहिलो सफल रिलिजपछि:

- Scorecard: स्कोर र्याचेट (मापन गरिएको स्कोर स्थिर गर्छ; घट्न सक्दैन)।

यसले Phase 7 गेटहरू (osv-scanner, gitleaks, actionlint+zizmor) लाई परिपूरक बनाउँछ: zizmor ले
कार्यप्रवाहहरूकै अडिट गर्छ; Scorecard ले रिपोजिटरीको समग्र सुरक्षा अवस्थिति मापन गर्छ।
