Caveman कम्प्रेसनले अन्तर्निर्मित अंग्रेजी नियमहरूका अतिरिक्त भाषाविशेष नियम प्याकहरू लोड गर्न सक्छ।
यसले मूल इन्जिनलाई स्थिर राख्दै पोर्चुगिज, स्पेनी, जर्मन, फ्रान्सेली, इटालियन, जापानी, र
भविष्यका भाषा प्याकहरूलाई स्वतन्त्र रूपमा विकसित हुन दिन्छ।

## स्थान

भाषा प्याकहरू यहाँ रहन्छन्:

```txt
open-sse/services/compression/rules/<language>/
```

हाल उपलब्ध प्याकहरू (`rules/` डाइरेक्टरीका सामग्रीहरूसँग प्रमाणीकरण गरिएका):

| भाषा                | डाइरेक्टरी     | उपलब्ध नियमका श्रेणीहरू                             |
| ------------------- | -------------- | --------------------------------------------------- |
| अंग्रेजी            | `rules/en/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| स्पेनी              | `rules/es/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| पोर्चुगिज (ब्राजिल) | `rules/pt-BR/` | `context`, `dedup`, `filler`, `structural`, `ultra` |
| इन्डोनेसियाली       | `rules/id/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| इटालियन             | `rules/it/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| जर्मन               | `rules/de/`    | `context`, `filler`, `structural`                   |
| फ्रान्सेली          | `rules/fr/`    | `context`, `filler`, `structural`                   |
| जापानी              | `rules/ja/`    | `context`, `filler`, `structural`                   |

> **समानतासम्बन्धी टिप्पणी:** `en`, `es`, `pt-BR`, `id`, र `it` प्याकहरूमा सबै ५ वटा श्रेणी छन्; `de`, `fr`, `ja` मा ३ वटा श्रेणी उपलब्ध छन्। अनुपस्थित `dedup` र `ultra` श्रेणीहरू स्वतः अन्तर्निर्मित अंग्रेजी नियमहरूमा फर्कन्छन्। साना प्याकहरूमा `dedup.json` र `ultra.json` थप्न योगदानहरू स्वागतयोग्य छन्।
>
> `pt-BR` प्याक Lenine Júnior द्वारा निर्मित **[Troglodita](https://github.com/leninejunior/troglodita)** मा आधारित छ — यो ब्राजिली पोर्चुगिज व्याकरणका लागि सुरुदेखि नै डिजाइन गरिएको कम्प्रेसन प्रणाली हो (अनावश्यक पुनरुक्ति न्यूनीकरण, PT-BR का अनावश्यक पूरक शब्द हटाउने, BR विकासकर्ता समुदायका लागि प्राविधिक संक्षिप्त रूपहरू)।
>
> आधिकारिक श्रेणी सूची र प्रत्येक श्रेणीको स्किमा [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) मा छन् (JSON Schema draft 2020-12)।

## भाषा पहिचान

`languageDetector.ts` ले प्रम्प्ट पाठबाट भाषा अनुमान गर्न हल्का ह्युरिस्टिक्स प्रयोग गर्छ। कन्फिगर गरिएको
पूर्वनिर्धारित भाषालाई अझै पनि सम्मान गरिन्छ, र सटीक नियन्त्रण आवश्यक हुँदा कन्फिगद्वारा पहिचान
अक्षम गर्न सकिन्छ।

पहिचानको आउटपुट नियम प्याकहरू चयन गर्न मात्र प्रयोग गरिन्छ। यसले प्रदायक राउटिङ, लोकेल
चयन, वा UI को भाषा परिवर्तन गर्दैन।

## कन्फिग संरचना

कम्प्रेसन सेटिङहरूमा निम्न समावेश गर्न सकिन्छ:

```json
{
  "languageConfig": {
    "enabled": true,
    "defaultLanguage": "en",
    "autoDetect": true,
    "enabledPacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  },
  "cavemanConfig": {
    "language": "en",
    "autoDetectLanguage": true,
    "enabledLanguagePacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  }
}
```

`languageConfig` ले ड्यासबोर्ड/पूर्वावलोकनका पूर्वनिर्धारित मानहरू नियन्त्रण गर्छ। `cavemanConfig` भने Caveman ले
सन्देशको पाठ कम्प्रेस गर्दा प्रयोग गर्ने रनटाइम इन्जिन कन्फिग हो।

## भाषा प्याक थप्ने

1. `open-sse/services/compression/rules/<language>/<pack>.json` सिर्जना गर्नुहोस्।
2. `docs/compression/COMPRESSION_RULES_FORMAT.md` मा भएको Caveman नियम ढाँचा प्रयोग गर्नुहोस्।
3. प्रतिस्थापनहरू सावधानीपूर्वक सीमित राख्नुहोस् र कोड, पहिचानकर्ताहरू, URLs वा JSON परिवर्तन नगर्नुहोस्।
4. भाषा चयन र प्रतिस्थापन व्यवहारका लागि परीक्षणहरू थप्नुहोस् वा अद्यावधिक गर्नुहोस्।
5. भाषा UI चयनकर्ताहरूमा देखिन्छ भने नयाँ dashboard/i18n लेबलहरू उपलब्ध गराउनुहोस्।

## API

उपलब्ध प्याकहरू यसरी क्वेरी गर्न सकिन्छ:

```bash
curl http://localhost:20128/api/compression/language-packs
```

पूर्वावलोकन endpoint ले भाषा कन्फिग ओभरराइडहरू स्वीकार गर्छ:

```bash
curl -X POST http://localhost:20128/api/compression/preview \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "standard",
    "text": "Por favor, eu gostaria que voce basicamente resumisse isso.",
    "config": {
      "languageConfig": {
        "defaultLanguage": "pt-BR",
        "autoDetect": true
      }
    }
  }'
```

## SHARED_BOUNDARIES (v3.8.0)

सबै 6 भाषा प्याकहरूले v3.8.0 मा `SHARED_BOUNDARIES` खण्ड प्राप्त गरे, जुन प्रत्येक
Caveman तीव्रता (LITE, FULL, ULTRA) मा लागू हुन्छ। यसले वरपरका अनावश्यक शब्दहरू हटाइए पनि
यी ढाँचाहरूलाई जस्ताको तस्तै सुरक्षित राख्न इन्जिनलाई निर्देशन दिन्छ:

| ढाँचाको प्रकार                   | उदाहरण                                 |
| -------------------------------- | -------------------------------------- |
| फेन्स गरिएका कोड ब्लकहरू         | ` ```python\n...\n``` `                |
| इनलाइन कोड                       | `` `my_var` ``                         |
| URLs                             | `https://example.com/path`             |
| फाइल पाथहरू (निरपेक्ष + सापेक्ष) | `/etc/hosts`, `./src/index.ts`         |
| त्रुटि हेडरहरू                   | `Error:`, `TypeError:`, `SyntaxError:` |
| स्ट्याक ट्रेस लाइनहरू            | `  at functionName (file.ts:12:3)`     |

यी ढाँचाहरू `DEFAULT_CAVEMAN_CONFIG.preservePatterns` मा राखिएका छन् (यसअघि `[]`)। यो
स्थिरांक `open-sse/services/compression/types.ts` मा रहेको छ।

### यो किन महत्त्वपूर्ण छ

SHARED_BOUNDARIES बिना, आक्रामक Caveman मोडहरूले दोहोरिएको
गद्यजस्तो देखिने तर वास्तवमा कोड स्निपेट, फाइल पाथ वा त्रुटि स्ट्याक भएको सामग्री हटाउन सक्थे। SHARED_BOUNDARIES ले
अनावश्यक शब्द हटाउने नियमहरू चल्नुअघि लागू हुने भाषा-निरपेक्ष सुरक्षा जालको रूपमा काम गर्छ।

### preservePatterns अनुकूलन गर्ने

compression सेटिङहरूमार्फत runtime मा थप ढाँचाहरू थप्न सकिन्छ:

````json
{
  "cavemanConfig": {
    "preservePatterns": [
      "```[\\s\\S]*?```",
      "`[^`]+`",
      "https?://\\S+",
      "(?:/|\\./)[^\\s]+",
      "\\b(?:Error|TypeError|SyntaxError|RangeError):",
      "\\s+at\\s+\\S+\\s+\\(\\S+:\\d+:\\d+\\)"
    ]
  }
}
````

अनुकूलित ढाँचाहरूले 6 पूर्वनिर्धारित ढाँचाहरूलाई विस्तार गर्छन् (प्रतिस्थापन गर्दैनन्)।

## सञ्चालनसम्बन्धी टिप्पणीहरू

- भाषा प्याक उपलब्ध नभएमा अन्तर्निर्मित अंग्रेजी नियमहरू fallback का रूपमा रहन्छन्।
- अमान्य अन्तर्निर्मित JSON प्याकहरू validation मा असफल हुन्छन्, जसले गर्दा release assets को गुणस्तर थाहै नपाई खस्किँदैन।
- नियम प्याकहरू data-only हुन्छन् र तिनले कोड import गर्नु वा स्वेच्छाचारी logic चलाउनु हुँदैन।
- compression analytics तहले चयन गरिएको mode र engine रेकर्ड गर्छ, पूर्ण prompt text होइन।
