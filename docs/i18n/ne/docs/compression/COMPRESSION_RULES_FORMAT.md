कम्प्रेसन नियमहरू रनटाइममा लोड गरिने JSON फाइलहरू हुन्। तिनीहरूलाई जानाजानी डेटा-मात्र राखिएको छ, ताकि नयाँ
भाषा प्याकहरू र RTK कमान्ड फिल्टरहरू इन्जिन कोड परिवर्तन नगरी समीक्षा गर्न सकियोस्।

> **आधिकारिक स्किमा (सत्यको स्रोत):** [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) (JSON Schema draft 2020-12)।
> तलका उदाहरणहरू केवल उदाहरणात्मक हुन् — अन्योल भएमा, आफ्नो प्याकलाई `_schema.json` विरुद्ध मान्य गर्नुहोस्।

## केभम्यान नियम प्याकहरू

केभम्यान नियम प्याकहरू यहाँ राखिन्छन्:

```txt
open-sse/services/compression/rules/<language>/<pack>.json
```

प्रत्येक प्याकमा सुरक्षित क्षेत्रहरू छुट्याइएपछि सामान्य गद्यमा लागू हुने प्रतिस्थापनहरू हुन्छन्।

```json
{
  "language": "en",
  "category": "filler",
  "rules": [
    {
      "name": "question_to_directive",
      "pattern": "\\b(?:Can you explain why|Could you show me how)\\b\\s*",
      "replacement": "Explain why ",
      "replacementMap": {
        "can you explain why": "Explain why ",
        "could you show me how": "Show how "
      },
      "flags": "gi",
      "context": "all",
      "category": "context",
      "minIntensity": "lite",
      "description": "Convert verbose questions into direct requests."
    }
  ]
}
```

### केभम्यान फिल्डहरू

| फिल्ड                    | आवश्यक | विवरण                                                                     |
| ------------------------ | ------ | ------------------------------------------------------------------------- |
| `language`               | हो     | `en`, `pt-BR`, `es` जस्ता BCP-47-सदृश भाषा कुञ्जी                         |
| `category`               | हो     | प्याकको श्रेणी फाइलनाम/श्रेणी, उदाहरणका लागि `filler` वा `dedup`          |
| `rules`                  | हो     | regex प्रतिस्थापन नियमहरूको एरे                                           |
| `rules[].name`           | हो     | स्थिर नियम नाम                                                            |
| `rules[].pattern`        | हो     | JavaScript regex स्रोत                                                    |
| `rules[].flags`          | होइन   | JavaScript regex फ्ल्यागहरू; पूर्वनिर्धारित `gi`                          |
| `rules[].replacement`    | होइन   | प्रतिस्थापन स्ट्रिङ वा `replacementMap` मा मिलान नभेटिँदाको वैकल्पिक मान  |
| `rules[].replacementMap` | होइन   | सामान्यीकृत मिलान गरिएको पाठद्वारा कुञ्जीकृत मिलान-विशिष्ट प्रतिस्थापनहरू |
| `rules[].context`        | होइन   | `all`, `user`, `assistant`, वा `system`; पूर्वनिर्धारित `all`             |
| `rules[].category`       | होइन   | `filler`, `context`, `structural`, `dedup`, `terse`, वा `ultra`           |
| `rules[].minIntensity`   | होइन   | `lite`, `full`, वा `ultra`; पूर्वनिर्धारित `lite`                         |
| `rules[].description`    | होइन   | मानिसले पढ्न सक्ने नियमको सारांश                                          |

अक्षरको केसप्रति संवेदनशील मिलान महत्त्वपूर्ण हुँदा `flags` प्रयोग गर्नुहोस्, उदाहरणका लागि
`the OpenAI API` नहटाई सानो अक्षरबाट सुरु हुने गद्यअघि रहेको article हटाउन। एउटै regex मा फरक आउटपुट आवश्यक पर्ने
धेरै विकल्पहरू हुँदा `replacementMap` प्रयोग गर्नुहोस्; यसले अझ समृद्ध अन्तर्निर्मित TypeScript प्रतिस्थापन
फङ्सनहरूको व्यवहार जोगाउँदै JSON नियम प्याकहरूलाई डेटा-मात्र राख्छ।

## RTK फिल्टर प्याकहरू

RTK फिल्टरहरू यहाँ अवस्थित हुन्छन्:

```txt
open-sse/services/compression/engines/rtk/filters/<filter>.json
```

प्रत्येक फिल्टरले कमान्ड-आउटपुट परिवारलाई कसरी पहिचान र कम्प्रेस गर्ने भन्ने वर्णन गर्छ।

```json
{
  "id": "test-vitest",
  "label": "Vitest output",
  "category": "test",
  "priority": 92,
  "match": {
    "outputTypes": ["test-vitest"],
    "commands": ["vitest", "npm test", "npm run test"],
    "patterns": ["\\bFAIL\\b", "\\bPASS\\b", "\\bTest Files\\b"]
  },
  "rules": {
    "stripAnsi": true,
    "replace": [{ "pattern": "\\s+\\[[0-9]+ms\\]", "replacement": "" }],
    "matchOutput": [
      {
        "pattern": "All tests passed",
        "message": "vitest: ok",
        "unless": "FAIL|Error:"
      }
    ],
    "includePatterns": ["FAIL", "Error:", "Test Files", "Tests"],
    "dropPatterns": ["^\\s*$", "Duration\\s+\\d+"],
    "collapsePatterns": ["^\\s+at "],
    "deduplicate": true,
    "truncateLineAt": 240,
    "maxLines": 160,
    "headLines": 24,
    "tailLines": 40,
    "onEmpty": "vitest: ok",
    "filterStderr": false
  },
  "preserve": {
    "errorPatterns": ["FAIL", "Error:", "AssertionError"],
    "summaryPatterns": ["Test Files", "Tests", "Snapshots"]
  },
  "tests": [
    {
      "name": "keeps failing tests",
      "command": "vitest",
      "input": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed",
      "expected": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed"
    }
  ]
}
```

### RTK फिल्डहरू

| फिल्ड                      | आवश्यक | वर्णन                                                                          |
| -------------------------- | ------ | ------------------------------------------------------------------------------ |
| `id`                       | हो     | स्थिर फिल्टर आईडी                                                              |
| `label`                    | हो     | ड्यासबोर्डमा पढ्न मिल्ने नाम                                                   |
| `category`                 | हो     | फिल्टर परिवार: git, test, build, shell, docker, package, infra, cloud, generic |
| `priority`                 | होइन   | धेरै फिल्टरहरू मेल खाँदा उच्च प्राथमिकता भएको फिल्टर चयन हुन्छ                 |
| `match.outputTypes`        | होइन   | यस फिल्टरलाई चयन गर्ने डिटेक्टर आउटपुट आईडीहरू                                 |
| `match.commands`           | होइन   | यस फिल्टरलाई चयन गर्ने कमान्ड टोकनहरू                                          |
| `match.patterns`           | होइन   | आउटपुट पाठबाट यस फिल्टरलाई चयन गर्ने regex ढाँचाहरू                            |
| `rules.stripAnsi`          | होइन   | regex चरणहरूअघि ANSI escape अनुक्रमहरू हटाउने                                  |
| `rules.replace`            | होइन   | प्रत्येक लाइनमा क्रमबद्ध रूपमा लागू गरिने regex प्रतिस्थापनहरू                 |
| `rules.matchOutput`        | होइन   | वैकल्पिक `unless` गार्ड भएका सर्ट-सर्किट आउटपुट नियमहरू                        |
| `rules.includePatterns`    | होइन   | प्राथमिकतासाथ सुरक्षित राखिने लाइनहरू                                          |
| `rules.dropPatterns`       | होइन   | अनावश्यक सामग्रीका रूपमा हटाइने लाइनहरू                                        |
| `rules.collapsePatterns`   | होइन   | संक्षिप्त गर्न सकिने बारम्बार मेल खाने लाइनहरू                                 |
| `rules.deduplicate`        | होइन   | दोहोरिएका सामान्यीकृत लाइनहरूलाई संक्षिप्त गर्ने                               |
| `rules.truncateLineAt`     | होइन   | प्रत्येक लाइनका लागि Unicode-सुरक्षित क्यारेक्टर सीमा                          |
| `rules.maxLines`           | होइन   | अन्तिम भाग सुरक्षित गर्नुअघिको अधिकतम राखिने लाइन सङ्ख्या                      |
| `rules.headLines`          | होइन   | काटछाँट गर्दा राखिने सुरुका लाइनहरू                                            |
| `rules.tailLines`          | होइन   | हालैको सन्दर्भका लागि राखिने अन्तिम लाइनहरू                                    |
| `rules.onEmpty`            | होइन   | फिल्टरिङले सबै सामग्री हटाउँदा प्रयोग हुने वैकल्पिक सन्देश                     |
| `rules.filterStderr`       | होइन   | पछिल्ला फिल्टरिङ चरणहरूअघि सामान्य stderr उपसर्गहरूलाई सामान्यीकरण गर्ने       |
| `preserve.errorPatterns`   | होइन   | काटछाँटपछि पनि बाँकी रहनुपर्ने त्रुटि लाइनहरू                                  |
| `preserve.summaryPatterns` | होइन   | काटछाँटपछि पनि बाँकी रहनुपर्ने सारांश लाइनहरू                                  |
| `tests[]`                  | होइन   | RTK प्रमाणीकरण गेटद्वारा प्रयोग गरिने इनलाइन प्रमाणीकरण नमुनाहरू               |

RTK ले घोषणात्मक चरणहरू यस क्रममा लागू गर्छ: `stripAnsi`, `filterStderr`, `replace`,
`matchOutput`, `dropPatterns`/`includePatterns`, `truncateLineAt`, `headLines`/`tailLines`,
`maxLines`, र `onEmpty`।

अनुकूलन फिल्टरहरू यहाँबाट लोड गर्न सकिन्छ:

1. मेल खाने `.rtk/trust.json` ह्यास उपस्थित भएपछि मात्र वा
   `trustProjectFilters` सक्षम गरिएको अवस्थामा प्रोजेक्टका `.rtk/filters.json` फाइलहरूबाट।
2. ग्लोबल `DATA_DIR/rtk/filters.json`।
3. बिल्ट-इन फिल्टरहरू।

प्रोजेक्ट/ग्लोबल अनुकूलन फाइलहरूमा एउटा फिल्टर वस्तु वा फिल्टर वस्तुहरूको एरे हुन सक्छ। अमान्य
अनुकूलन फिल्टरहरूलाई निदान सन्देशसहित छोडिन्छ; अमान्य बिल्ट-इन फिल्टरहरूले प्रमाणीकरण असफल गराउँछन्।

प्रोजेक्ट विश्वास फाइल:

```json
{
  "filtersSha256": "0123456789abcdef..."
}
```

वातावरण ओभरराइड `OMNIROUTE_RTK_TRUST_PROJECT_FILTERS=1` ले ह्यासबिना नै प्रोजेक्ट फिल्टरहरूलाई
विश्वास गर्छ र यसको प्रयोग नियन्त्रित स्थानीय विकासमा मात्र सीमित गर्नुपर्छ।

## सुरक्षा नियमहरू

- नियमहरूलाई आइडेम्पोटेन्ट राख्नुहोस्: एउटै फिल्टर दुई पटक चलाउँदा आउटपुट बिग्रनु हुँदैन।
- सम्भव भएसम्म त्रुटिको ठ्याक्कै पाठ, फाइल पथहरू, लाइन नम्बरहरू र कमाण्ड सारांशहरू सुरक्षित राख्नुहोस्।
- कोड ब्लकहरू, JSON पेलोडहरू, URLs वा गोप्य जानकारी परिमार्जन गर्ने नियमहरूबाट बच्नुहोस्।
- डिटेक्टर/फिल्टर परीक्षणहरूमा नयाँ कमाण्ड परिवारहरूका लागि युनिट कभरेज थप्नुहोस्।
- प्रत्येक बिल्ट-इन फिल्टर र साझा कस्टम फिल्टरहरूमा `tests[]` नमुनाहरू थप्नुहोस्।

## प्रमाणीकरण

नियम प्याकहरू प्रयोग गर्नुअघि प्रमाणीकरण गरिन्छ। बिल्ट-इन Caveman प्याकहरू र बिल्ट-इन RTK फिल्टरहरू प्रमाणीकरणका क्रममा तुरुन्तै असफल हुन्छन्, जसले गर्दा बिग्रिएका रिलिज एसेटहरू पठाउनुअघि नै पत्ता लाग्छन्। पार्सिङ वा विश्वाससम्बन्धी प्रमाणीकरण असफल हुँदा कस्टम RTK फिल्टरहरूलाई निदानात्मक जानकारीसहित छोडिन्छ।

केन्द्रित प्रमाणीकरण:

```bash
node --import tsx/esm --test tests/unit/compression/rule-loader.test.ts tests/unit/compression/language-packs.test.ts
node --import tsx/esm --test tests/unit/compression/rtk-verify.test.ts tests/unit/compression/rtk-dsl-pipeline.test.ts
```
