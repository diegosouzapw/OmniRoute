> पुनः डिप्लोय नगरीकन OmniRoute को व्यवहार परिवर्तन गर्ने रनटाइम टगलहरू।
> यहाँ सूचीबद्ध प्रत्येक फ्ल्याग
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> मा परिभाषित छ — सत्यको एकल स्रोत। ड्यासबोर्ड र REST API दुवैले
> त्यही फाइलबाट पढ्छन्, त्यसैले तलको तालिका त्यससँग 1:1 मिल्ने गरी उत्पन्न गरिएको छ।

## फिचर फ्ल्यागहरू के हुन्

फिचर फ्ल्याग एउटा नाम दिइएको टगल (बुलियन वा इनम) हो जसको मान रनटाइममा
परिवर्तन गरी डेटाबेसमा स्थायी रूपमा भण्डारण गर्न सकिन्छ, र यसका लागि प्रक्रिया पुनः डिप्लोय गर्नु पर्दैन। प्रत्येक
फ्ल्यागलाई `key`, `label`, `description`, `category`, `defaultValue`, `type`,
र `requiresRestart` सङ्केत भएको `FeatureFlagDefinition` द्वारा वर्णन गरिन्छ।

### समाधान प्राथमिकता क्रम

फ्ल्यागको **प्रभावकारी मान**
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) द्वारा निम्न
प्राथमिकताअनुसार समाधान गरिन्छ (सबैभन्दा उच्च प्राथमिकता विजयी हुन्छ):

1. **DB ओभरराइड** — `feature_flags` नेमस्पेसअन्तर्गत `key_value` तालिकामा
   भण्डारण गरिएको मान (ड्यासबोर्ड वा REST API मार्फत सेट गरिएको)।
2. **वातावरण चर** — सेट गरिएको र खाली नभएको अवस्थामा `process.env[<KEY>]`।
3. **परिभाषाको पूर्वनिर्धारित मान** — `featureFlagDefinitions.ts` बाट प्राप्त `defaultValue`।

कुनै बुलियन फ्ल्यागको प्रभावकारी मान `"true"`,
`"1"`, वा `"yes"` हुँदा त्यसलाई **सक्षम** मानिन्छ (`isFeatureFlagEnabled()` हेर्नुहोस्)।

> [!NOTE]
> अधिकांश फ्ल्यागहरूसँग [`ENVIRONMENT.md`](./ENVIRONMENT.md) मा दस्तावेजीकृत
> **उही नामको** मिल्दो वातावरण चर पनि हुन्छ। फ्ल्यागको DB ओभरराइडले
> उक्त वातावरण चरभन्दा प्राथमिकता पाउँछ। `requiresRestart: true` भएको फ्ल्याग
> तुरुन्तै स्थायी रूपमा भण्डारण हुन्छ, तर प्रक्रिया सुरु हुँदा मात्र पुनः पढिन्छ —
> यसलाई टगल गर्दा ड्यासबोर्डमा **"सर्भर पुनः सुरु गर्नुहोस्"** ब्यानर देखिन्छ।

## फ्ल्यागहरू टगल गर्दै

### ड्यासबोर्ड

**ड्यासबोर्ड → सेटिङ्स → फिचर फ्ल्याग्स** (`/dashboard/settings/feature-flags`) मा जानुहोस्। ग्रिड
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`) ले निम्नलाई समर्थन गर्दछ:

- कुञ्जी वा विवरणद्वारा **खोज्ने**, र श्रेणीद्वारा **फिल्टर गर्ने** (साथै एक सिंथेटिक **पुनः सुरु आवश्यक** दृश्य)।
- बुलियन फ्ल्यागहरूको लागि **टगल** र इनम फ्ल्यागहरूको लागि **ड्रपडाउन**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`)।
- प्रत्येक फ्ल्यागको लागि एक **स्रोत ब्याज** — `DB`, `ENV`, वा `DEF` — जसले प्रभावकारी मान कहाँबाट आयो भनेर देखाउँछ।
- ओभरराइड हटाउनको लागि **रिसेट** बटन (`DB`-स्रोत फ्ल्यागहरूको लागि मात्र देखाइन्छ), र तल **सबै ओभरराइडहरू रिसेट गर्नुहोस्** बटन।
- `requiresRestart` फ्ल्याग परिवर्तन हुँदा **सर्भर पुनः सुरु गर्नुहोस्** ब्यानर।

### REST API

सबै कार्यहरू एउटै मार्गबाट हुन्छन्:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts)।
प्रत्येक विधिलाई प्रमाणीकृत ड्यासबोर्ड सत्र आवश्यक पर्दछ (अन्यथा `401`)।

#### `GET /api/settings/feature-flags`

प्रत्येक फ्ल्यागलाई यसको प्रभावकारी मान, स्रोत, र सारांश सहित फर्काउँछ।

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... all 77 flags
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

एकल ओभरराइड सेट गर्नुहोस् वा हटाउनुहोस्। बडी: `{ key: string; value?: string }`।
`value` छोड्दा ओभरराइड हट्छ (env / पूर्वनिर्धारितमा पुनर्स्थापित गर्दछ)।

```bash
# DB ओभरराइड सेट गर्नुहोस्
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# ओभरराइड हटाउनुहोस् ("value" बिना)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

प्रतिक्रियाले नयाँ `effectiveValue`/`source`, `previousValue`/
`previousSource`, र `requiresRestart` लाई प्रतिध्वनित गर्दछ। अज्ञात कुञ्जीहरू र दायरा बाहिरका इनम
मानहरूलाई `400` सहित अस्वीकार गरिन्छ।

#### `DELETE /api/settings/feature-flags`

एकैचोटि **सबै** DB ओभरराइडहरू खाली गर्दछ, प्रत्येक फ्ल्यागलाई यसको env / पूर्वनिर्धारित
मानमा पुनर्स्थापित गर्दछ। `{ cleared: <count>, message: "..." }` फर्काउँछ।

> [!NOTE]
> `requiresRestart: true` भएका फ्ल्यागहरू प्रक्रिया पुनः लोड भएपछि मात्र प्रभावकारी हुन्छन्।
> ड्यासबोर्डको पुनः सुरु प्रवाहले `POST /api/restart` लाई कल गर्छ र त्यसपछि
> सर्भर पुनः सुरु नभएसम्म `GET /api/health/ping` लाई पोल गर्छ।

## आपतकालीन बजेट फलब्याक

`OMNIROUTE_EMERGENCY_FALLBACK` (श्रेणी `runtime`, पूर्वनिर्धारित `true`) ले
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)
मा रहेको आपतकालीन निःशुल्क फलब्याक मार्गलाई नियन्त्रण गर्छ।
यो सक्षम हुँदा, आफ्नो बजेट समाप्त गरेका अनुरोधहरू पूर्ण रूपमा असफल हुनुको सट्टा
निःशुल्क फलब्याक प्रदायक/मोडेलमा रुट गरिन्छन्। यो व्यवहार असक्षम पार्न र बजेट
समाप्त भएका अनुरोधहरूलाई असफल हुन दिन ड्यासबोर्ड टगल, DB ओभरराइड वा
`OMNIROUTE_EMERGENCY_FALLBACK` वातावरण चरमार्फत यसलाई `false` (वा `0`) मा
सेट गर्नुहोस्। (PRs #3741 / #3752 मा ड्यासबोर्ड टगलका रूपमा उपलब्ध गराइएको।)

यस फलब्याकद्वारा प्रदान गरिएको प्रतिक्रियामा
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>` हुन्छ,
जसले गर्दा क्लाइन्टले आफ्नो अनुरोधसँग `X-OmniRoute-Provider` को भिन्नता तुलना
नगरीकनै अनुरोध पुनः रुट गरिएको थियो भनेर थाहा पाउन सक्छ। अन्य प्रत्येक
प्रतिक्रियामा यो हेडर अनुपस्थित हुन्छ।
