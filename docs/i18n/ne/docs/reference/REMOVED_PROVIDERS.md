केही सेवाहरू OmniRoute मा एकीकृत गरिएका थिए र पछि तिनलाई सञ्चालन गर्ने व्यक्तिहरूले हटाउन अनुरोध गरेकाले हटाइए। यो पृष्ठ ती हटाइहरूको स्थायी अभिलेख हो। यसको एकमात्र उद्देश्य तिनलाई संयोगवश पुनः समावेश हुनबाट रोक्नु हो: पुरानो fork, cache गरिएको npm tarball, संग्रहित issue वा "प्रदायक X पुनर्स्थापना गर्नुहोस्" अनुरोध भेट्टाउने योगदानकर्तालाई **पुनः समावेश नगर्नुहोस्** भनेर बताउने एउटै स्थान आवश्यक हुन्छ।

यो पृष्ठ बन्द भएका वा सञ्चालनमा नरहेका सेवाहरूको सूची **होइन**। तिनलाई
[`FREE_TIERS.md`](FREE_TIERS.md) ("हटाइएको / निःशुल्क तह नभएको") मा अभिलेख गरिन्छ र सेवा पुनः उपलब्ध भएमा तिनीहरू फर्कन सक्छन्। तलका प्रविष्टिहरू अनुरोधमा उल्लेखित सञ्चालकको लिखित अनुमतिबिना पुनः समावेश गर्न पाइँदैन, र उक्त अनुमतिको लिङ्क प्रविष्टिबाट दिइनुपर्छ।

## नीति

1. **सेवा सञ्चालकबाट आएको हटाउने अनुरोधलाई स्वीकार गरिन्छ, वार्ता गरिँदैन।** OmniRoute कुनै पनि upstream सेवासँग सम्बद्ध छैन। कुनै सेवाको सञ्चालकले एकीकरण हटाउन अनुरोध गर्दा, एकीकरणले आधिकारिक API प्रयोग गरेको होस् वा नहोस्, त्यसलाई हटाइन्छ।
2. **"हटाइएको" भन्नाले OmniRoute ले नियन्त्रण गर्ने प्रत्येक सतह बुझिन्छ।** Executor, registry प्रविष्टि, प्रदायक id र alias, मोडेल सूची, endpoints, environment variables, icon, dashboard cards, उत्पन्न गरिएको प्रदायक सन्दर्भ, `FREE_TIERS.md`, environment सन्दर्भ, README का सङ्ख्याहरू, `llm.txt` mirrors, समर्पित tests र golden snapshots, code comments, CHANGELOG bullets (अभिलेखित reconciliation सहित, `config/release/changelog-reconciliations.json` हेर्नुहोस्), GitHub Releases notes, wiki, र उक्त प्रदायक विषय भएका GitHub issues, discussions तथा pull requests (issues र discussions मेटाइन्छन्; pull requests को शीर्षक परिवर्तन गरिन्छ, तिनको विवरण प्रतिस्थापन गरिन्छ र thread lock गरिन्छ, किनभने GitHub ले pull requests मेटाउन सक्दैन)।
3. **लिखित अनुमतिबिना यस पृष्ठको कुनै प्रविष्टिलाई कहिल्यै पुनः समावेश नगर्नुहोस्।** यसमा कुनै provider catalog मा id वा alias पुनः थप्ने, executor मा domains थप्ने, त्यसलाई "पुनर्स्थापना" गर्ने योगदानकर्ताको PR स्वीकार गर्ने, free-model catalog मा थप्ने वा OmniRoute मार्फत त्यसमा म्यानुअल रूपमा पुग्ने तरिका दस्तावेजीकरण गर्ने कार्य समावेश छन्। त्यस्ता PRs र issues लाई यस पृष्ठको लिङ्कसहित बन्द गर्नुहोस्।
4. **प्रविष्टिलाई न्यूनतम राख्नुहोस्।** समीक्षकलाई पुनः समावेश गरिएको कुरा पहिचान गर्न आवश्यक जानकारी मात्र अभिलेख गर्नुहोस्: identifiers, domains, dates र हटाउने कार्य गरिएको pull request। एकीकरणले कसरी काम गर्थ्यो भन्ने वर्णन नगर्नुहोस्।
5. **Regression guard `tests/unit/removed-providers-blocklist.test.ts` हो।** तलका कुनै identifier वा domain प्रदायक catalogs, executor map वा प्रदायक registry sources मा पुनः देखा परेमा यो असफल हुन्छ। यहाँ नयाँ पङ्क्ति थप्ने उही PR मा उक्त test मा नयाँ identifiers थप्नुहोस्।

## प्रविष्टि थप्ने

नयाँ हटाउने अनुरोध आउँदा:

1. अनुरोध सेवाको सञ्चालकबाट आएको हो भनी पुष्टि गर्नुहोस् (उनीहरूको support address वा उनीहरूले नियन्त्रण गर्ने domain), र सन्देशलाई निजी रूपमा सुरक्षित राख्नुहोस्।
2. नीति बुँदा 2 को checklist पालना गर्दै एकीकरण हटाउनुहोस्। Keyless प्रदायकका लागि
   [#12440](https://github.com/diegosouzapw/OmniRoute/pull/12440) लाई सन्दर्भका रूपमा र भण्डारित connections भएको API-key प्रदायकका लागि [#10210](https://github.com/diegosouzapw/OmniRoute/pull/10210) लाई प्रयोग गर्नुहोस् (migration थप्नुहोस्)।
3. उही PR मा माथिको तालिकामा एउटा पङ्क्ति र
   `tests/unit/removed-providers-blocklist.test.ts` मा identifiers थप्नुहोस्।
4. PR merge भएपछि सञ्चालकलाई जवाफ दिनुहोस् र के-के हटाइयो तथा OmniRoute ले के परिवर्तन गर्न सक्दैन (पहिल्यै प्रकाशित npm र Docker versions, git history, third-party forks) भन्ने सूची दिनुहोस्।
