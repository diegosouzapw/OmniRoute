`copilot-m365-web` (उपनाम `m365copilot`) ले `m365.cloud.microsoft/chat` मा रहेको प्रमाणीकरण गरिएको Microsoft 365 Copilot BizChat ब्राउजर सत्रमार्फत OpenAI-ढाँचाका च्याट अनुरोधहरू पठाउँछ। यो अनौपचारिक एकीकरण हो।

> **वेब कुकी प्रदायकहरूमा नयाँ हुनुहुन्छ?**
>
> यो प्रदायक-विशिष्ट मार्गदर्शिका पालना गर्नुअघि सामान्य सेटअप प्रक्रिया, प्रमाणीकरणसम्बन्धी मार्गदर्शन, सीमितताहरू र समस्या समाधानका लागि **`docs/getting-started/WEB-COOKIE-GUIDE.md`** पढ्नुहोस्।
>
> **महत्त्वपूर्ण:** यस प्रदायकको प्रमाणपत्र **कुकी होइन**। `m365.cloud.microsoft` बाट कुकीहरू प्रतिलिपि नगर्नुहोस्। प्रमाणपत्र एउटा WebSocket URL क्वेरी प्यारामिटर र पाथ खण्ड हो, जुन दुवै DevTools को Network ट्याबबाट पढिन्छन्।

## पूर्वापेक्षाहरू

- `m365.cloud.microsoft/chat` मा BizChat पहुँच भएको Microsoft 365 खाता
- DevTools मार्फत WebSocket निरीक्षण गर्न Chromium-आधारित ब्राउजर (Chrome, Edge)
- M365 Copilot इजाजतपत्र (धेरै Microsoft 365 Business/Enterprise योजनाहरूसँग समावेश)

## प्रमाणपत्र सङ्कलन (WebSocket विधि)

1. `https://m365.cloud.microsoft/chat` मा साइन इन गर्नुहोस् र कुराकानी सुरु गर्नुहोस्।
2. **DevTools → Network** खोल्नुहोस्।
3. **WS** (WebSocket) द्वारा फिल्टर गर्नुहोस्।
4. Chathub WebSocket जडानमा क्लिक गर्नुहोस्। `wss://substrate.office.com/m365Copilot/Chathub/` बाट सुरु हुने URL खोज्नुहोस्।
5. यसको **Request URL** बाट निम्न प्रतिलिपि गर्नुहोस्:
   - `access_token` क्वेरी प्यारामिटरको मान (छोटो अवधिका लागि मान्य JWT)।
   - `/Chathub/` पछिको Chathub पाथ खण्ड (जस्तै `<oid>@<tenant>`)।

पूर्ण URL को स्वरूप यस्तो हुन्छ:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute मा **Providers → Add Provider** मा जानुहोस्, **Microsoft 365 Copilot (BizChat)** चयन गर्नुहोस् र निम्न ढाँचामा प्रमाणपत्र टाँस्नुहोस्:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. **Test Connection** र **Save** मा क्लिक गर्नुहोस्।

## प्रमाणपत्र सङ्कलन (HAR आयात)

WebSocket URL बाट मानहरू म्यानुअल रूपमा प्रतिलिपि गर्नुको सट्टा, तपाईं DevTools HAR फाइल निर्यात गर्न सक्नुहुन्छ:

1. **DevTools → Network** खोल्नुहोस्।
2. BizChat कुराकानी सुरु गर्नुहोस् वा जारी राख्नुहोस् (यसले WebSocket जडान सक्रिय गर्छ)।
3. Network प्यानलमा दायाँ-क्लिक गर्नुहोस् र **Save all as HAR with content** चयन गर्नुहोस्।
4. OmniRoute मा, प्रदायक जडान संवादमा रहेको **Import .har file** बटन प्रयोग गर्नुहोस्।

OmniRoute ले Chathub WebSocket URL का लागि HAR स्क्यान गर्छ, `access_token` र `chathubPath` निकाल्छ र प्रमाणपत्र फिल्डहरू स्वचालित रूपमा भर्छ। HAR आयातले JWT को म्याद समाप्त हुने समय डिकोड गर्छ र बाँकी टोकन अवधि देखाउँछ।

> **वास्तविक HAR निर्यात, पहुँच टोकन वा रिफ्रेस टोकन कहिल्यै कमिट नगर्नुहोस्।** परीक्षण र कागजातका मानहरू सधैं प्लेसहोल्डर हुनुपर्छ।

## टोकनको अवधि र रिफ्रेस

`access_token` छोटो अवधिका लागि मान्य हुन्छ (सामान्यतया **~75 मिनेट**)। म्याद समाप्त भएपछि प्रदायकले जडान त्रुटि रिपोर्ट गर्छ र तपाईंले प्रमाणपत्र पुनः सङ्कलन गर्नुपर्छ।

### `refreshToken` मार्फत स्वचालित रिफ्रेस

म्यानुअल पुनः सङ्कलनबाट बच्न, तपाईं जडानको **Advanced Settings → providerSpecificData** मा Microsoft रिफ्रेस टोकन भण्डारण गर्न सक्नुहुन्छ:

| फिल्ड          | विवरण                                                                   |
| -------------- | ----------------------------------------------------------------------- |
| `refreshToken` | `substrate.office.com/sydney` स्कोपका लागि Microsoft OAuth रिफ्रेस टोकन |
| `tier`         | `individual` (पूर्वनिर्धारित), `edu`, वा `enterprise`                   |

`substrate.office.com/sydney` मा स्कोप गरिएको Microsoft device-code वा authorization-code फ्लोबाट रिफ्रेस टोकन प्राप्त गर्नुहोस्। `refreshToken` सेट गरिएको अवस्थामा, OmniRoute ले प्रत्येक अनुरोधअघि `access_token` लाई पूर्व-रिफ्रेस गर्छ, त्यसैले प्रत्येक ~75-मिनेटको म्याद समाप्तिपछि पुनः सङ्कलन गर्नुपर्दैन।

यदि `refreshToken` सेट गरिएको छैन भने, प्रत्येक पटक म्याद समाप्त भएपछि तपाईंले WebSocket प्रमाणपत्र म्यानुअल रूपमा पुनः सङ्कलन गर्नुपर्छ।

### टियर चयन

| टियर         | उपनाम              | सतह                       |
| ------------ | ------------------ | ------------------------- |
| `individual` | _(पूर्वनिर्धारित)_ | उपभोक्ता M365 Copilot     |
| `edu`        | `included`         | शैक्षिक M365 Copilot      |
| `enterprise` | `work`             | कार्यका लागि M365 Copilot |

**Advanced Settings → providerSpecificData → tier** मा टियर सेट गर्नुहोस्। टियरले BizChat राउटिङ र मोडेल पहुँचलाई असर गर्छ।

## सुरक्षा मोडेल

- **अनौपचारिक एकीकरण।** यो प्रदायकले BizChat WebSocket प्रोटोकललाई रिभर्स-इन्जिनियर गर्छ। Microsoft ले endpoint परिवर्तन गर्दा यो पूर्वसूचनाबिनै काम गर्न छोड्न सक्छ।
- `subscriptionRisk: true` फ्ल्यागले यो एकीकरण कागजातमा उल्लेख नभएको endpoint मा निर्भर रहेको जनाउँछ। खातामा प्रतिबन्ध लाग्न सक्ने सम्भावना छ, तर यसको पुष्टि भएको छैन।
- access token छोटो अवधिका लागि मान्य JWT हो। यसलाई password सरह व्यवहार गर्नुहोस्: यसलाई commit, log वा साझा नगर्नुहोस्।
- refresh token ले BizChat सतहमा दीर्घकालीन पहुँच प्रदान गर्छ। यसलाई API key जत्तिकै सावधानीपूर्वक भण्डारण गर्नुहोस्।

## समस्या निवारण

### प्रमाणीकरण तुरुन्तै असफल हुन्छ

- तपाईंले XHR/Fetch अनुरोधबाट नभई **WebSocket URL** बाट प्रतिलिपि गर्नुभएको हो भनी पुष्टि गर्नुहोस्। credential Chathub WebSocket जडानको `access_token` query parameter मा हुन्छ — `Authorization: Bearer` header मा होइन।
- `chathubPath` मा URL path बाट पूर्ण `<oid>@<tenant>` खण्ड समावेश भएको सुनिश्चित गर्नुहोस्।

### Token को म्याद ~75 मिनेटपछि समाप्त हुन्छ

यो अपेक्षित व्यवहार हो। `refreshToken` बिना access token छोटो अवधिका लागि मात्र मान्य हुन्छ। निम्नमध्ये कुनै एक गर्नुहोस्:

- DevTools बाट credential पुनः क्याप्चर गर्नुहोस्, वा
- स्वचालित refresh का लागि Advanced Settings मा `refreshToken` कन्फिगर गर्नुहोस्।

### Test Connection सफल हुन्छ तर chat ले 401 फर्काउँछ

प्रमाणीकरण र पहिलो अनुरोधबीच token को म्याद समाप्त भएको हुन सक्छ। नयाँ credential पुनः क्याप्चर गर्नुहोस्।

### प्रदायक सूचीमा Copilot देखा पर्दैन

**Dashboard → Providers** मा `copilot-m365-web` सक्षम गरिएको सुनिश्चित गर्नुहोस्। केही tiers मा प्रदायक पूर्वनिर्धारित रूपमा लुकेको हुन सक्छ।
