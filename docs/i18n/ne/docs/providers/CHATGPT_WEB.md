`chatgpt-web-codex` (उपनाम `cgpt-codex`) ले प्रमाणीकरण गरिएको ChatGPT ब्राउजर
सत्रमार्फत Codex Responses का टर्नहरूलाई जोड्छ। यो सेवानिवृत्त साझा `chatgpt-web`
प्रदायकबाट स्वतन्त्र छ र `open-sse/vendor/codex-chatgpt-web/` अन्तर्गतको MIT-सूचना
समावेश भएको कार्यान्वयन प्रयोग गर्छ, जसलाई अपस्ट्रिम v4.0.7 कमिट
`b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494` मार्फत अद्यावधिक गरिएको छ।

## साझा प्रदायकको सेवानिवृत्ति

पहिलेका साझा प्रदायक ID हरू `chatgpt-web` र `cgpt-web` अब वितरण गरिँदैनन्, किनभने
तिनको pre-key/proof-of-work कार्यान्वयनको उत्पत्ति प्रमाणित गर्न सकिएन। स्ल्यासले सुरु
हुने मोडेल ID र कायम राखिएका उपनामहरूसहित कुनै पनि ID का लागि गरिएका स्पष्ट अनुरोधहरू
कुनै पनि अपस्ट्रिम अनुरोध हुनुअघि HTTP `410` र **PROVIDER_RETIRED** कोडसहित
बन्द भएर असफल हुन्छन्।

माइग्रेसन `168_retire_chatgpt_web.sql` ले मेल खाने प्रदायक जडानहरूलाई tombstone गर्छ र
तिनका सक्रिय सत्र लिजहरू अमान्य बनाउँछ। यसले जडान इतिहास र API-key का
अनुमति-सूचीहरू सुरक्षित राख्छ; यसले अनुमति-सूचीमा प्रतिस्थापन पहुँच थप्दैन। Codex प्रदायक
र यसका जडानहरू यस सेवानिवृत्तिसँग मेल खाँदैनन्।

## पूर्वावश्यकताहरू

- साइन-इन गरिएको ChatGPT सत्रबाट प्राप्त पूर्ण Cookie हेडर;
- npm, systemd, र PM2 स्थापनाहरूका लागि Chrome वा Chromium सहित ग्राफिकल सत्र वा
  Xvfb डिस्प्ले;
- Docker को `web` प्रोफाइल प्रयोग गर्दा, `docker-compose.yml` बाट प्राप्त आन्तरिक
  Chromium सेवा;
- स्थानीय Codex उपकरणहरूका लागि OpenAI `tunnel-client` v0.0.13 र ChatGPT कस्टम
  कनेक्टर।

टनेल केवल उपकरण टर्नहरूका लागि आवश्यक हुन्छ। टनेल र कनेक्टर कन्फिगर गरिएका हुँदा
`pro` सहित सूचीबद्ध प्रत्येक रुटले उही टर्न-बाउन्ड स्थानीय उपकरण क्षमता प्रयोग गर्न सक्छ।

## ड्यासबोर्ड सेटअप

1. **ChatGPT Web (Codex)** प्रदायक खोल्नुहोस् र एउटा जडान थप्नुहोस्।
2. पूर्ण ChatGPT Cookie हेडर, टनेल ID, रनटाइम कुञ्जी, र कस्टम कनेक्टरको नाम
   टाँस्नुहोस्। उपकरण-सक्षम नयाँ सेटअपहरूले ठ्याक्कै `OmniRoute Codex v2` नाम भएको
   नयाँ सिर्जना गरिएको कनेक्टर प्रयोग गर्नुपर्छ, जसमा Authentication लाई None र
   Permissions लाई Allow all actions मा सेट गरिएको हुनुपर्छ।
3. जडान जाँच चलाउनुहोस्। OmniRoute ले ब्राउजर-समर्थित Temporary Chat खोल्छ र
   खाताका लागि Sol र Pro उपलब्ध छन् कि छैनन् भनेर पत्ता लगाउँछ।
4. जडान सुरक्षित गर्नुहोस्। OmniRoute ले टाँसिएको कुकीलाई प्रमाणित Playwright भण्डारण
   अवस्थाले प्रतिस्थापन गर्छ र इन्क्रिप्टेड क्रेडेन्सियल अमूर्तीकरणमार्फत त्यसलाई रनटाइम
   कुञ्जीसँग भण्डारण गर्छ।

सफलतापूर्वक सुरक्षित गरेपछि कच्चा कुकी राखिँदैन। सत्रको म्याद सकिएपछि जडान खोल्नुहोस्,
नयाँ पूर्ण Cookie हेडर टाँस्नुहोस्, र जाँच पुनः चलाउनुहोस्। सम्पादन संवादमा रहेको doctor
स्थितिले ब्राउजर, भण्डारण अवस्था, साइन-इन, Temporary Chat, टनेल, कनेक्टर, र उपकरणको
राउन्ड-ट्रिपलाई छुट्टाछुट्टै रिपोर्ट गर्छ।

> वास्तविक कुकी, रनटाइम कुञ्जी, भण्डारण अवस्था, वा क्षमता टोकन कहिल्यै कमिट नगर्नुहोस्।
> परीक्षण र दस्तावेजीकरणका मानहरू सधैँ प्लेसहोल्डर हुनुपर्छ।

## मोडेल र कम्बोहरू

निश्चित मोडेल रुटहरू यी हुन्:

- `chatgpt-web-codex/luna` — GPT-5.6 Luna, न्यून प्रयास
- `chatgpt-web-codex/think` — GPT-5.6 Luna, मध्यम प्रयास
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

अन्य कुनै मोडेलजस्तै यीमध्ये एउटा कम्बोमा थप्नुहोस्। Codex एपले नियमित Responses
एन्डपोइन्ट `/v1/responses` मा कम्बोको नाम `model` का रूपमा पठाउँछ; त्यहाँ छुट्टै Codex
एन्डपोइन्ट वा मोड स्विच छैन।

Free/Go खाताहरूले Luna रुटहरू उपलब्ध गराउँछन्। Sol-सक्षम खाताहरूले Instant देखि
High सम्म उपलब्ध गराउँछन्, र Pro-सक्षम खाताहरूले थप रूपमा Extra High र Pro पनि उपलब्ध
गराउँछन्। प्रत्येक रुटमा निश्चित ब्याकएन्ड मोडेल र तर्क प्रयास हुन्छ; बाझिने स्पष्ट Responses
प्रयासले चयन गरिएको ब्राउजर मोडलाई चुपचाप परिवर्तन गर्नुको सट्टा बन्द भएर असफल हुन्छ।

पुरानो `Codex Native` वा `OmniRoute Codex` कनेक्टरको नाम परिवर्तन वा पुनः प्रयोग
नगर्नुहोस्। ChatGPT ले सार्वजनिक MCP करारलाई कनेक्टर पहिचानअनुसार क्यास गर्छ, जबकि
अद्यावधिक गरिएको ब्रिजले नयाँ प्रत्यक्ष टर्न-टोकन करार प्रयोग गर्छ। रनटाइमले ती लिगेसी
पहिचानहरू अस्वीकार गर्छ र नयाँ `OmniRoute Codex v2` कनेक्टर आवश्यक बनाउँछ।

## सुरक्षा मोडेल

- नेटिभ पथका लागि Responses अनुरोध, मान्यताप्राप्त Codex क्लाइन्ट, र मेल खाने
  थ्रेड तथा टर्न पहिचानहरू आवश्यक हुन्छन्।
- Workspace, sandbox, स्वीकृति नीति, र उपकरण सूची नेटिभ Codex shell बाट आउँछन्;
  स्वच्छन्द prompt पाठ तिनका लागि आधिकारिक स्रोत होइन।
- ChatGPT ले प्रत्येक टर्नका लागि छोटो अवधिको capability मात्र प्राप्त गर्छ। MCP broker ले
  Codex ले सोही टर्नमा प्रस्ताव गरेका उपकरणहरू मात्र स्वीकार गर्छ।
- **Allow once** लाई स्वतः पुष्टि गर्दा उपकरण अनुरोध Codex मा मात्र फिर्ता पठाइन्छ। स्वीकृति र
  कार्यान्वयनबारे Codex ले मात्र निर्णय गर्छ।
- पहिलो आउटपुटअघि, कुनै संयोजन अर्को अनुकूल target मा फर्कन सक्छ। आउटपुट
  सुरु भएपछि, टर्न पूरा नहुँदासम्म provider, model, connection, र browser turn स्थिर रहन्छन्।
- Cookies, runtime keys, storage state, र capability tokens provider का
  responses वा request logs मा देखा पर्दैनन्।

## डिस्प्लेरहित VPS र Docker

npm, systemd, र PM2 स्थापनाहरूका लागि, OmniRoute ले प्रचलित Chrome र Chromium पथहरू पत्ता लगाउँछ।
वैकल्पिक रूपमा, `CHATGPT_WEB_CODEX_CHROME_PATH` सेट गर्नुहोस्। Runtime turns ले जानाजानी headed
Chrome प्रयोग गर्छन्, किनकि ChatGPT ले वास्तविक headless browser को स्वरूप अस्वीकार गर्छ। त्यसैले डिस्प्लेरहित host ले
निजी Xvfb display सहित OmniRoute चलाउनुपर्छ; Chrome path मात्र सेट गर्दा display उपलब्ध हुँदैन।

Docker को `web` profile ले आन्तरिक Compose
network मा `chatgpt-web-codex-browser` सुरु गर्छ। Sidecar ले Xvfb भित्र headed Chrome चलाउँछ, त्यसैले कुनै भौतिक display आवश्यक पर्दैन। यसको CDP
port host मा प्रकाशित हुँदैन। सुरक्षित browser profile volume
OmniRoute data volume बाट अलग हुन्छ, र browser ले पर्याप्त shared memory प्राप्त गर्छ। आन्तरिक CDP proxy ले
Compose network भित्रको port `9223` मा मात्र सुन्छ; Chrome sidecar मा loopback मै बाँधिएको रहन्छ।

`DATA_DIR` अन्तर्गतको supervisor lease ले धेरै OmniRoute प्रक्रियाहरूलाई एउटै
tunnel र broker state को स्वामित्व लिनबाट रोक्छ। द्वन्द्वबारे doctor ले जानकारी दिन्छ।

## अन्तरक्रियात्मक पुनःप्राप्ति

स्वचालित Docker पथमा host बाट देखिने window हुँदैन, तर निजी Xvfb display भित्र Chrome स्वयं headed
हुन्छ। ChatGPT लाई अन्तरक्रियात्मक sign-in वा challenge आवश्यक पर्दा, पुनःप्राप्तिका लागि विद्यमान VNC
browser infrastructure प्रयोग गर्न सकिन्छ। Browser UI र CDP केवल loopback,
प्रमाणीकृत management connection, वा SSH tunnel मार्फत मात्र पहुँचयोग्य रहनुपर्छ; सामान्य सञ्चालनका बेला noVNC अक्षम
रहन्छ।

## WebSocket fallback

जब कुनै संयोजनमा ChatGPT Web (Codex) समावेश हुन्छ, Responses WebSocket bridge ले
upstream मा जडान गर्नुअघि HTTP/SSE fallback अनुरोध गर्छ। त्यसपछि स्थानान्तरण
`/v1/responses` मार्फत हुन्छ।
