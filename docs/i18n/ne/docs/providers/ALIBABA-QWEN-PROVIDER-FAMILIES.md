यो दस्तावेजले
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854) का लागि गरिएको कार्यान्वयनसम्बन्धी निर्णय अभिलेख गर्छ। सार्वजनिक उत्पादनहरूलाई चार प्रदायक परिवारका रूपमा प्रस्तुत गरिएको छ। क्षेत्र जडानसम्बन्धी डेटा हो, छुट्टै उत्पादन होइन।

## निर्णय

| प्रदायक परिवार                                     | OmniRoute ID            | विश्वव्यापी क्षेत्र | चीन क्षेत्र |
| -------------------------------------------------- | ----------------------- | ------------------- | ----------- |
| Alibaba Cloud Model Studio (प्रयोगअनुसार भुक्तानी) | `alibaba`               | सिङ्गापुर           | बेइजिङ      |
| Alibaba Cloud Token Plan                           | `bailian-coding-plan`   | सिङ्गापुर           | बेइजिङ      |
| Qwen Cloud (प्रयोगअनुसार भुक्तानी)                 | `qwen-cloud`            | विश्वव्यापी         | बेइजिङ      |
| Qwen Cloud Token Plan                              | `qwen-cloud-token-plan` | सिङ्गापुर           | बेइजिङ      |

अवस्थित `alibaba-cn` ID सुरक्षित गरिएका जडानहरू, मोडेल रुटहरू, कम्बोहरू र ऐतिहासिक प्रयोगका लागि रनटाइम अनुकूलता उपनामका रूपमा कायम रहन्छ। यसको ड्यासबोर्ड कार्डलाई `alibaba` मा समेटिएको छ; डेटाबेस पुनर्लेखन आवश्यक छैन।

Qwen Cloud को प्रयोगअनुसार भुक्तानी सेवा र Alibaba Cloud Model Studio ले हाल DashScope-सङ्गत रनटाइम होस्टहरू साझा गर्छन्, तर प्रयोगकर्ताहरूले फरक उत्पादन इन्टरफेसहरूमार्फत कुञ्जीहरू प्राप्त गर्ने र खाताहरू व्यवस्थापन गर्ने भएकाले तिनीहरू छुट्टाछुट्टै प्रदायक पहिचानका रूपमा रहन्छन्। Alibaba र Qwen Cloud Token Plan उत्पादनहरूले फरक इन्डपोइन्ट परिवारहरू प्रयोग गर्छन्, त्यसैले चारै उत्पादनहरू छुट्टाछुट्टै प्रदायक ID का रूपमा रहन्छन्।

API कुञ्जी र इन्डपोइन्ट एउटै उत्पादन र क्षेत्रसँग सम्बन्धित हुनुपर्छ। क्षेत्र चयन गर्दा प्रमाणीकरण र सामान्य अनुरोधहरूले प्रयोग गर्ने पूर्वनिर्धारित इन्डपोइन्ट परिवर्तन हुन्छ।

## जडान सम्झौता

नयाँ जडानहरूले स्थिर क्षेत्र कुञ्जीलाई `providerSpecificData` मा भण्डारण गर्छन्:

```json
{
  "region": "global-sg"
}
```

अनुमति दिइएका मानहरू `global-sg` र `china-beijing` हुन्। इन्डपोइन्टलाई प्रदायक ID र क्षेत्रका आधारमा केन्द्रीय रूपमा व्युत्पन्न गरिन्छ। पूर्वनिर्धारित नभएको `providerSpecificData.baseUrl` स्पष्ट अपरेटर ओभरराइडका रूपमा कायम रहन्छ र त्यसले प्राथमिकता पाउँछ, जबकि पुराना सुरक्षित पूर्वनिर्धारित URL हरूलाई क्षेत्रीय म्याट्रिक्सअनुसार पुनः सामान्यीकृत गरिन्छ।

यसले जडान स्किमालाई विस्तारयोग्य राख्छ: अर्को प्रदायक कार्ड सिर्जना नगरी वा सुरक्षित गरिएका प्रदायक ID हरू परिवर्तन नगरी रिजोल्भरमा अर्को क्षेत्र थप्न सकिन्छ।

## अनुकूलता र रोलआउट

1. क्षेत्रीय endpoint resolver थप्नुहोस् र हालका global defaults कायम राख्नुहोस्।
2. `alibaba`, यसको `alibaba-cn` अनुकूलता ID, र `qwen-cloud` का लागि live क्षेत्रीय DashScope `/models` discovery प्रयोग गर्नुहोस्। तिनका responses पहिले एउटा text-generation filter बाट पार हुन्छन्, किनकि generic endpoint ले image, video, audio, embedding, र अन्य non-chat models पनि फर्काउँछ। त्यसपछि `qwen-cloud` ले आफ्नो provider registry मा घोषणा गरिएको maintained allowlist लागू गर्छ। हाल तिनीहरूले runtime hosts साझा गरे तापनि Alibaba Model Studio र Qwen Cloud ले छुट्टाछुट्टै curated catalogs कायम राख्छन्।
3. हालको Token Plan text-model allowlist सहित `qwen-cloud-token-plan` दर्ता गर्नुहोस्।
4. connection थप्ने/सम्पादन गर्ने dialogs मा typed region selector थप्नुहोस्।
5. duplicate `alibaba-cn` card लुकाउनुहोस् र यसका विद्यमान connections लाई `alibaba` provider page मा समावेश गर्नुहोस्।
6. advanced र workspace-specific deployments का लागि custom endpoint overrides उपलब्ध राख्नुहोस्।

Token Plan media models chat catalog बाहिरै रहन्छन्, किनकि तिनीहरूले dedicated endpoints प्रयोग गर्छन्।
`wan2.7-image` र `wan2.7-image-pro` लाई `open-sse/config/imageRegistry.ts` मा दर्ता गरिएको छ;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, र `happyhorse-1.1-r2v` लाई
`open-sse/config/videoRegistry.ts` मा दर्ता गरिएको छ। दुवै registries ले `qwen-cloud-token-plan` connection
identity र यसका region-specific credentials पुनः प्रयोग गर्छन्।

नियमित Qwen Cloud सँग `qwen-cloud` identity अन्तर्गत छुट्टै pay-as-you-go image र video catalogs छन्।
यसका image models `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03`, र `z-image-turbo` हुन्। यसका video
models `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12`, र
`wan2.7-videoedit` हुन्। यी models ले नियमित `qwen-cloud` connection र क्षेत्रीय
DashScope media endpoint मात्र पुनः प्रयोग गर्छन्। Token Plan र pay-as-you-go registries ले एकअर्काका
model lists inherit वा merge गर्दैनन्।

`bailian-coding-plan` identity सँग पनि आफ्नै media allowlists छन्:
image generation का लागि `wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0`, र `qwen-image-2.0-pro`,
साथै video generation का लागि
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, र `happyhorse-1.1-r2v`।
यसले Bailian Coding Plan connection र क्षेत्रीय Coding Plan endpoint मात्र प्रयोग गर्छ।
यसका image र video registries ले कुनै पनि Qwen Cloud provider बाट inherit गर्दैनन् वा तिनीसँग merge हुँदैनन्।

नियमित `alibaba` identity सँग छुट्टै image र video allowlists छन्। यसका image models
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo`, र `wan2.6-t2i` हुन्। यसमा थपिएका video models `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12`, र `wan2.7-videoedit` हुन्। यी models ले Alibaba Model Studio
connection र यसमा चयन गरिएको क्षेत्रीय media endpoint मात्र प्रयोग गर्छन्; तिनीहरूलाई कुनै पनि Coding Plan वा Qwen
Cloud registry मा थपिँदैन।

Qwen Cloud Token Plan chat catalog ले Individual plan को exact-string text allowlist पालना गर्छ:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2`, र
`deepseek-v4-pro`। Wan र HappyHorse entries छुट्टै image/video generation APIs अन्तर्गत पर्छन्।

Alibaba Token Plan ले आफ्ना Anthropic-compatible endpoint मार्फत तिनै हालका छवटा text-generation model IDs उपलब्ध गराउँछ।
यसको Singapore विकल्पले विद्यमान `global-sg` region key भण्डारण गर्छ;
region लाई Global भन्ने provider families भन्दा user-facing label मात्र फरक छ।

नियमित Qwen Cloud chat catalog लाई जानाजानी पूर्ण live text response भन्दा साँघुरो राखिएको छ। यसको
maintained allowlist `open-sse/config/providers/registry/qwen-cloud/index.ts` मा छ; live
discovery ले upstream response र उक्त registry list दुवैमा रहेका IDs मात्र फर्काउँछ।

Alibaba Model Studio ले पनि `open-sse/config/providers/registry/alibaba/index.ts` मा रहेको
आफ्नै स्वतन्त्र रूपमा maintained allowlist सहित उही live-intersection नियम पालना गर्छ। `alibaba-cn` compatibility
provider ले discovery लाई Beijing endpoint विरुद्ध resolve गर्दै उक्त catalog पुनः प्रयोग गर्छ।
