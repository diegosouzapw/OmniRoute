OmniRoute ले OpenAI Codex प्रयोग गर्ने **दुई** तरिका उपलब्ध गराउँछ:

| प्रदायक                | यसले OpenAI सँग कसरी सञ्चार गर्छ                                                                                                                                                                     | प्रयोगसम्बन्धी सावधानी                                           |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| **`codex`**            | तपाईंको ChatGPT/OpenAI OAuth टोकनलाई सीधै Responses API मा पुनः प्रयोग गर्छ                                                                                                                          | **छ** — आधिकारिक सत्रलाई प्रोक्सी/राउटर प्रयोगका लागि अनुमति छैन |
| **`codex-app-server`** | JSON-RPC/WebSocket मार्फत **Codex CLI कै आफ्नै `codex app-server`** सञ्चालन गर्छ; CLI ले अन्तरक्रियात्मक `codex` सत्रले जस्तै आफ्नो OAuth (`~/.codex/auth.json`) आफैं व्यवस्थापन र स्वतः नवीकरण गर्छ | **छैन** — OmniRoute ले API मा कहिल्यै टोकन पुनः प्रयोग गर्दैन    |

`codex-app-server` ले टोकन कहिल्यै पुनः प्रयोग नगर्ने भएकाले, यसमा
सत्र-पुनःप्रयोगसम्बन्धी सावधानी लागू हुँदैन। यसका लागि भने **कन्फिगर गरिएको
app-server URL मा पहुँचयोग्य Codex CLI** आवश्यक हुन्छ, र उक्त CLI मा **साइन इन
गरिएको** हुनुपर्छ।

## 1. वास्तुकला

```
┌─ OmniRoute एप ───────────────────┐        ┌─ codex-app-server साइडकार ─────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ क्षमता टोकन)                 │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  OpenAI OAuth आफैं व्यवस्थापन गर्छ │
└──────────────────────────────────┘        │  (~/.codex/auth.json, स्वतः नवीकरण)│
        │ साझा हुन्छ (compose volumes)       └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → WS क्षमता टोकन (दुवैले यसलाई माउन्ट गर्छन्)
  codex-appserver-home    → ~/.codex (ड्यासबोर्डद्वारा लेखिएको auth.json,
                             साइडकारको codex app-server द्वारा पढिने)
```

- साइडकारले क्षमता टोकनद्वारा सुरक्षित आन्तरिक compose नेटवर्कमा
  (`ws://codex-app-server:1456`) **मात्र** सुन्छ। यसलाई होस्ट वा इन्टरनेटमा
  **कहिल्यै** प्रकाशित गरिँदैन।
- Codex CLI लाई `omniroute:base` भित्रै समावेश गरिएको छ, त्यसैले साइडकार चलाउँदा
  होस्ट वा प्रयोगकर्ताको मेसिनमा codex इन्स्टल गर्नुपर्दैन।

## 2. यसलाई सुरु गर्नुहोस्

```bash
# codex app-server साइडकार प्रोफाइलसहित स्ट्याक सुरु गर्नुहोस्:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

साइडकारले पहिलोपटक बुट हुँदा आफ्नो WS क्षमता टोकन सिर्जना गर्छ (साझा
`codex-appserver-token` भोल्युममा) र एपले `OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE`
मार्फत त्यही टोकन पढ्छ। टोकनलाई म्यानुअल रूपमा जडान गर्न आवश्यक पर्दैन।

## 3. जडान गर्नुहोस् + साइन इन गर्नुहोस्

1. ड्यासबोर्डमा **OpenAI Codex (App-Server)** का लागि एउटा जडान थप्नुहोस्। कुनै API
   कुञ्जी वा टोकन आवश्यक पर्दैन (यो प्रमाणीकरण-रहित प्रदायक हो — प्रमाणीकरण
   साइडकारले व्यवस्थापन गर्छ)।
2. यदि साइडकारको Codex CLI मा **अझै साइन इन गरिएको छैन** भने, जडानको स्वास्थ्य
   जाँचले _"चलिरहेको छ तर साइन इन गरिएको छैन"_ देखाउँछ (रातो प्रमाणीकरण त्रुटि
   होइन)। **ChatGPT मार्फत साइन इन गर्नुहोस्** प्रयोग गर्नुहोस्: यसले तपाईंको
   ब्राउजरमा मानक Codex device-OAuth चलाउँछ र त्यसपछि **प्रमाणीकरण लागू गर्नुहोस्**
   मार्फत साझा भोल्युममा `~/.codex/auth.json` लेख्छ (एउटै लगइनले `codex` र
   `codex-app-server` दुवै प्रदायकलाई सेवा दिन्छ)।
3. साइन इन भएपछि, स्वास्थ्य जाँच हरियो हुन्छ (यसले `/readyz` **र**
   `account/read` दुवै प्रमाणित गर्छ — अर्थात् सेवा चालू _र_ प्रमाणीकृत छ) र
   काम गर्न थाल्छ।

ड्यासबोर्डले स्वस्थ अवस्थामा रहेको विद्यमान `~/.codex/auth.json` लाई कहिल्यै
अधिलेखन गर्दैन — फाइल नभएको वा यसको टोकन पुरानो भएको अवस्थामा मात्र लेख्छ
(सधैं ब्याकअप लिइन्छ)।

## 4. डिप्लोयमेन्ट परिदृश्यहरू

- **पहिले नै प्रमाणीकृत Codex CLI भएको सञ्चालक** — आफ्नो होस्टको
  `~/.codex` लाई साइडकार (`codex-appserver-home`) मा माउन्ट गर्नुहोस् र साइन-इन
  चरण छोड्नुहोस्।
- **सार्वजनिक प्रयोगकर्ता, स्थानीय रूपमा codex इन्स्टल नभएको** — यसले फरक पर्दैन:
  साइडकारसँग CLI हुन्छ। प्रयोगकर्ताले ड्यासबोर्डमार्फत मात्र प्रमाणीकरण गर्छ।
- **बेयर-मेटल OmniRoute (साइडकारविना, होस्टमा codex)** — आफ्नो
  `codex app-server` तर्फ `OMNIROUTE_CODEX_APPSERVER_WS` लक्षित गर्नुहोस् र होस्टको
  codex मा साइन इन गरिएको सुनिश्चित गर्नुहोस्; बाइनरी नभएमा "codex इन्स्टल गरिएको
  छैन" भन्ने सङ्केत देखिन्छ।

## 5. आवासीय / UDP इग्रेस (सञ्चालकका लागि अतिरिक्त, वितरणमा समावेश छैन)

माथिको सामान्य साइडकारले कन्टेनरको सामान्य नेटवर्कमार्फत इग्रेस गर्छ। Codex
ट्राफिकलाई **आवासीय निकास** मार्फत इग्रेस गराउनुपर्ने सञ्चालकले (जस्तै TCP +
UDP/QUIC बोक्ने TUN tailscale साइडकार) त्यसलाई छुट्टै compose override का रूपमा
चलाउँछ; यसलाई जानीजानी वितरण गरिएको `codex-app-server` प्रोफाइलको भाग बनाइएको
छैन। उक्त सेटअपका लागि आन्तरिक सञ्चालन रनबुक हेर्नुहोस्।
