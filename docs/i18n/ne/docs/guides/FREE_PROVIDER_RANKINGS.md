> **छोटकरीमा**: OmniRoute ले आफ्ना **निःशुल्क** प्रदायकहरूलाई मोडेलको गुणस्तरका आधारमा **Arena AI
> (LMArena-शैलीका) ELO स्कोरहरू** प्रयोग गरेर क्रमबद्ध गर्छ। आफ्नो कार्यका लागि सबैभन्दा शक्तिशाली मोडेलहरू
> उपलब्ध गराउने निःशुल्क प्रदायकहरू हेर्न ड्यासबोर्डको **निःशुल्क प्रदायक क्रमाङ्कन** पृष्ठ खोल्नुहोस् —
> समग्रमा वा वर्गअनुसार फिल्टर गरेर (कोडिङ, समीक्षा, दस्तावेजीकरण, डिबगिङ)।

## यो के हो

OmniRoute ले 329 प्रदायकहरू दर्ता गर्छ, जसमा **निःशुल्क/प्रमाणीकरण-रहित** भनेर चिन्ह लगाइएका 155 क्याटलग प्रविष्टिहरू
(प्रमाणीकरण-रहित,
निःशुल्क-स्तरको OAuth वा निःशुल्क-स्तरको API कुञ्जी —
[निःशुल्क स्तरसम्बन्धी मार्गदर्शिका](../getting-started/FREE-TIERS-GUIDE.md) र पूर्ण
[निःशुल्क स्तरहरूको निर्देशिका](../reference/FREE_TIERS.md) हेर्नुहोस्) समावेश छन्। तर समस्या के छ भने: निःशुल्क प्रदायकहरूको
मोडेल गुणस्तरमा ठूलो भिन्नता हुन्छ। अत्याधुनिक मोडेल उपलब्ध गराउने प्रमाणीकरण-रहित प्रदायक,
सानो पुरानो मोडेल उपलब्ध गराउने प्रदायकभन्दा धेरै उपयोगी हुन्छ।

**निःशुल्क प्रदायक क्रमाङ्कन** ले प्रत्येक निःशुल्क प्रदायकको क्याटलगलाई
**Arena AI लिडरबोर्ड** बाट प्राप्त **समुदाय-स्रोतित गुणस्तर स्कोरहरू** सँग जोडेर
"**कुन निःशुल्क प्रदायकले मलाई सबैभन्दा राम्रो मोडेल दिन्छ?**" भन्ने प्रश्नको उत्तर दिन्छ
(मानवीय प्राथमिकतामा आधारित ELO, अर्थात् LMArena च्याटबट एरिनामा प्रयोग भएको जस्तै अवधारणा)।
त्यसपछि प्रदायकहरूलाई उनीहरूको **उत्कृष्ट निःशुल्क मोडेल** को क्षमताका आधारमा क्रमबद्ध गरिन्छ।

क्रमाङ्कन तीन वास्तविक स्रोतहरूबाट गणना गरिन्छ:

1. निःशुल्क प्रदायकका सूचीहरू — `NOAUTH_PROVIDERS`, साथै `hasFree` ले चिन्ह लगाइएका
   `OAUTH_PROVIDERS` / `APIKEY_PROVIDERS` प्रविष्टिहरू
   (`src/shared/constants/providers.ts`)।
2. प्रदायक रजिस्ट्रीबाट प्रत्येक प्रदायकको मोडेल क्याटलग
   (`open-sse/config/providerRegistry.ts`)।
3. Arena ELO समक्रमण इन्जिन (`src/lib/arenaEloSync.ts`) द्वारा `model_intelligence` DB तालिकामा
   भण्डारण गरिएका ELO-व्युत्पन्न कार्य-अनुकूलता स्कोरहरू।

जोड्ने तर्क `src/lib/freeProviderRankings.ts` मा छ।

## कसरी पहुँच गर्ने

### ड्यासबोर्ड पृष्ठ

ड्यासबोर्ड खोल्नुहोस् र **लागतहरू → निःशुल्क प्रदायक क्रमाङ्कन** मा जानुहोस्, वा सिधै यहाँ जानुहोस्:

```
/dashboard/free-provider-rankings
```

पृष्ठ (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) ले निम्न देखाउँछ:

- उत्कृष्ट क्रमाङ्कन भएका निःशुल्क प्रदायकहरूको **शीर्ष-3 पोडियम** (🥇 🥈 🥉)।
- यी स्तम्भहरू भएको पूर्ण **क्रमाङ्कन तालिका**: **स्थान**, **प्रदायक**, **शीर्ष मोडेल**,
  **स्कोर**, **औसत स्कोर**, **मोडेलहरू**, **प्रकार**।
- **वर्ग फिल्टर बटनहरू**: _सबै वर्गहरू_, _पूर्वनिर्धारित_, _कोडिङ_, _समीक्षा_,
  _दस्तावेजीकरण_, _डिबगिङ_।

प्रत्येक प्रदायकको **प्रकार** ब्याजले त्यो कसरी निःशुल्क छ भन्ने बताउँछ:

| ब्याज    | अर्थ                                              |
| -------- | ------------------------------------------------- |
| `NOAUTH` | सधैँ निःशुल्क, कुनै प्रमाणपत्र आवश्यक पर्दैन      |
| `OAUTH`  | निःशुल्क स्तर (`hasFree`) भएको OAuth प्रदायक      |
| `APIKEY` | निःशुल्क स्तर (`hasFree`) भएको API-कुञ्जी प्रदायक |

स्कोरहरू कच्चा सङ्ख्याको सट्टा मानिसले सजिलै बुझ्न सक्ने लेबलहरू (जस्तै _विशिष्ट_, _उत्कृष्ट_, _धेरै राम्रो_,
_राम्रो_, _औसत_) का रूपमा देखाइन्छन्, किनभने अन्तर्निहित मान प्रतिशत नभई सापेक्ष
क्रमाङ्कन गुणस्तर हो।

### API अन्तिम-बिन्दु

यो पृष्ठ सार्वजनिक पठन अन्तिम-बिन्दुद्वारा समर्थित छ
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

क्वेरी प्यारामिटरहरू (Zod मार्फत प्रमाणीकरण गरिएका):

| प्यारामिटर | प्रकार | पूर्वनिर्धारित | टिप्पणी                                                                                                     |
| ---------- | ------ | -------------- | ----------------------------------------------------------------------------------------------------------- |
| `category` | string | (कुनै छैन)     | `default`, `coding`, `review`, `documentation`, `debugging` मध्ये एउटा। संयुक्त क्रमाङ्कनका लागि नदिनुहोस्। |
| `limit`    | number | `50`           | `1–100` को दायरामा सीमित गरिन्छ।                                                                            |

प्रतिक्रियाको संरचना:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` मूल Arena ELO मान हो; `score` सामान्यीकृत कार्य-अनुकूलता मान हो
(तल हेर्नुहोस्)। स्कोर प्राप्त गरेका मोडेलहरू नभएका प्रदायकहरू प्रतिक्रियाबाट हटाइन्छन्।

## स्कोरहरूले कसरी काम गर्छन्

### स्रोत: Arena AI लिडरबोर्ड

Arena ELO सिङ्क इन्जिनले (`src/lib/arenaEloSync.ts`) Arena AI लिडरबोर्ड API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) बाट दुईवटा लिडरबोर्ड — `text`
र `code` — प्राप्त गर्छ। प्रत्येक लिडरबोर्ड प्रविष्टिमा मोडेलको नाम, विक्रेता, ELO `score`,
विश्वसनीयता अन्तराल र मत सङ्ख्या हुन्छ।

लिडरबोर्डका वर्गहरू OmniRoute कार्य वर्गहरूसँग यसरी म्याप हुन्छन्:

| Arena लिडरबोर्ड | OmniRoute कार्य वर्गहरू                           |
| --------------- | ------------------------------------------------- |
| `text`          | `default`, `review`, `documentation`, `debugging` |
| `code`          | `coding`                                          |

### सामान्यीकरण (कार्य-अनुकूलता स्कोर)

कच्चा ELO स्कोरहरूलाई प्रत्येक लिडरबोर्डअनुसार सामान्यीकरण गरी **`[0.4, 0.98]` भित्रको कार्य-अनुकूलता मान** बनाइन्छ:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

स्कोर कहिल्यै `0` वा `1` सम्म पुग्दैन, जसले प्रयोगकर्ताका ओभरराइडहरूका लागि अतिरिक्त ठाउँ राख्छ। यो
तपाईंले API प्रतिक्रियामा देख्ने `score` फिल्ड र ड्यासबोर्डमा देखाइने लेबल हो।

### विश्वसनीयता

प्रत्येक प्रविष्टिले Arena को मत सङ्ख्याका आधारमा विश्वसनीयता स्तर प्राप्त गर्छ:

| विश्वसनीयता | मतहरू   |
| ----------- | ------- |
| `high`      | ≥ 5,000 |
| `medium`    | ≥ 1,000 |
| `low`       | < 1,000 |

### भण्डारण र नवीनता

सामान्यीकृत प्रविष्टिहरू `source = "arena_elo"` सहित `model_intelligence` DB तालिकामा
लेखिन्छन् (`src/lib/db/modelIntelligence.ts`)। प्रविष्टिहरू **७ दिनपछि
म्याद सकिन्छन्**, त्यसैले सिङ्क गर्न छाडेको प्रदायकले पुरानो डेटा उपलब्ध गराइरहनुको सट्टा
अन्ततः सूचीबाट हट्छ।

सिङ्क **पूर्वनिर्धारित रूपमा सक्रिय** हुन्छ:

- यो सर्भर सुरु हुँदा एक पटक र त्यसपछि आवधिक टाइमरमा चल्छ
  (`src/lib/arenaEloSync.ts`, `src/instrumentation-node.ts` बाट जोडिएको)।
- यो **नन-ब्लकिङ हुन्छ र कहिल्यै घातक हुँदैन** — यदि अपस्ट्रिम फेच असफल भयो भने, OmniRoute
  चलिरहन्छ र र्याङ्किङहरूले केवल पछिल्लो सही डेटा (वा खाली अवस्था) देखाउँछन्।

यसलाई दुई वातावरण चरहरूले नियन्त्रण गर्छन्
([`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md) मा दस्तावेजीकृत):

| चर                        | पूर्वनिर्धारित | उद्देश्य                                             |
| ------------------------- | -------------- | ---------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`         | आउटबाउन्ड सिङ्कबाट बाहिरिन `false` मा सेट गर्नुहोस्। |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h)  | सेकेन्डमा सिङ्क अन्तराल।                             |

### म्यानुअल सिङ्क / स्थिति / खाली गर्ने

अपरेटरहरूका लागि, प्रमाणीकरण गरिएको व्यवस्थापन इन्डपोइन्टले म्यानुअल नियन्त्रण उपलब्ध गराउँछ
(`src/app/api/intelligence/sync/route.ts` — व्यवस्थापन प्रमाणीकरण आवश्यक हुन्छ):

```
GET    /api/intelligence/sync          # हालको सिङ्क स्थिति (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # म्यानुअल सिङ्क सुरु गर्नुहोस्; नलेखी पूर्वावलोकन गर्न body: { "dryRun": true }
DELETE /api/intelligence/sync          # सिङ्क गरिएका सबै arena_elo इन्टेलिजेन्स प्रविष्टिहरू खाली गर्नुहोस्
```

यदि र्याङ्किङ पृष्ठ खाली छ भने, म्यानुअल `POST /api/intelligence/sync` (वा केवल
सर्भर पुनः सुरु गर्दा) यसलाई पुनः भर्छ।

### मोडेलहरूलाई लिडरबोर्डसँग मिलाउने

रजिस्ट्री मोडेल ID र Arena मोडेलका नामहरू सधैँ ठ्याक्कै मिल्दैनन्। र्याङ्किङले
लचिलो मिलान प्रयोग गर्छ (`src/lib/freeProviderRankings.ts` मा रहेको `findMatchingIntelligence`):

1. सामान्यीकृत मोडेल ID मा ठ्याक्कै मिलान।
2. अन्त्यमा रहेको संस्करण प्रत्यय हटाएपछि मिलान (जस्तै `kimi-k2.6` → `kimi-k2`)।
3. प्रिफिक्स मिलान (लिडरबोर्डको मोडेल नाम रजिस्ट्री ID को प्रिफिक्स हुन्छ)।

सिङ्कतर्फ, ज्ञात विक्रेता प्रिफिक्सहरू (`anthropic/`, `openai/`, `google/`, …)
हटाइन्छन् र एउटा सानो एलियास म्यापले प्रामाणिक नामहरूलाई OmniRoute ले आन्तरिक रूपमा प्रयोग गर्ने
भेरियन्टहरूमा विस्तार गर्छ, जसले गर्दा मोडेलहरू जुनसुकै नामअन्तर्गत पनि फेला पार्न सकिन्छन्।

### प्रदायकलाई कसरी र्याङ्क गरिन्छ

प्रत्येक निःशुल्क प्रदायकका लागि, इन्जिनले त्यसको क्याटलगमा भएका प्रत्येक मोडेललाई स्कोर गर्छ, त्यसपछि:

- **शीर्ष मोडेल** = प्रदायकको सबैभन्दा उच्च स्कोर भएको मोडेल।
- **औसत स्कोर** = उक्त प्रदायकका स्कोर गरिएका सबै मोडेलहरूको औसत स्कोर।
- **मोडेलहरू** = Arena स्कोर प्राप्त गरेका प्रदायकका मोडेलहरूको सङ्ख्या।

प्रदायकहरूलाई पहिले **शीर्ष-मोडेल स्कोर** र त्यसपछि औसत स्कोरका आधारमा क्रमबद्ध गरिन्छ। यसले
कम्तीमा एउटा बलियो निःशुल्क मोडेल उपलब्ध गराउने प्रदायकलाई पुरस्कृत गर्छ।

## निःशुल्क प्रदायकहरू छनोट गर्न यसको प्रयोग

1. **सही श्रेणी छान्नुहोस्।** एजेन्टिक/कोड कार्यभारहरूका लागि **Coding** फिल्टर प्रयोग गर्नुहोस्, वा
   सामान्य च्याटका लागि यसलाई **All Categories** / **Default** मै छोड्नुहोस्। एउटै प्रदायकको
   स्थान विभिन्न श्रेणीमा फरक हुन सक्छ, किनकि प्रत्येक लिडरबोर्डअनुसार यसको शीर्ष मोडेल फरक हुन्छ।
2. **एक-पटकको सेटअपका लागि शीर्ष तीनलाई प्राथमिकता दिनुहोस्।** यदि तपाईं एक वा दुईवटा निःशुल्क
   प्रदायक मात्र जडान गर्न चाहनुहुन्छ भने, आफ्नो श्रेणीमा शीर्ष स्थानमा रहेका प्रदायकबाट सुरु गर्नुहोस्।
3. **Type ब्याज जाँच गर्नुहोस्।** `NOAUTH` प्रदायकहरू जडान गर्न सबैभन्दा छिटो हुन्छन् (कुनै
   प्रमाणपत्र आवश्यक पर्दैन)। `OAUTH` / `APIKEY` का निःशुल्क टियरहरूका लागि छोटो साइन-अप आवश्यक पर्छ, तर तिनले प्रायः
   अझ शक्तिशाली मोडेलहरू उपलब्ध गराउँछन्। जडानका चरणहरूका लागि
   [निःशुल्क टियर मार्गदर्शिका](../getting-started/FREE-TIERS-GUIDE.md) हेर्नुहोस्।
4. **धेरैवटा जडान गर्नुहोस् र Auto-Combo लाई निर्णय गर्न दिनुहोस्।** यस पृष्ठलाई सञ्चालन गर्ने उही Arena ELO डेटाले
   Auto-Combo स्कोरिङ इन्जिनको **कार्य-उपयुक्तता कारक** लाई पनि डेटा प्रदान गर्छ
   (`open-sse/services/autoCombo/taskFitness.ts`, रिजोल्युसन क्रम
   `user_override → arena_elo → models_dev_tier → static table`)। त्यसैले शीर्ष निःशुल्क प्रदायकहरू जडान गरेपछि,
   `model: "auto"` (जस्तै `auto/coding`) प्रयोग गरी राउटिङ गर्दा प्रत्येक अनुरोधका लागि
   उच्च गुणस्तरका निःशुल्क मोडेलहरू स्वतः प्राथमिकतामा पर्छन्। पूर्ण १६-कारक स्कोरिङका लागि
   [Auto-Combo](../routing/AUTO-COMBO.md) हेर्नुहोस्।
