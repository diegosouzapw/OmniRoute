**Claude Code** CLI (`claude`) लाई OmniRoute — स्थानीय वा रिमोट VPS — तर्फ निर्देशित गर्नुहोस्,
Codex सेटअपसँग मिल्ने गरी प्रति-मोडेल प्रोफाइलहरूसहित।

---

## द्रुत सुरुवात

```bash
# स्थानीय OmniRoute विरुद्ध Claude Code सुरु गर्नुहोस् (सक्रिय सन्दर्भ स्वतः पत्ता लगाउँछ)
omniroute launch

# रिमोट OmniRoute विरुद्ध (`omniroute connect <host>` पछि, यो स्वचालित हुन्छ)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# प्रति-मोडेल प्रोफाइलहरू सिर्जना गर्नुहोस्, त्यसपछि एउटा सुरु गर्नुहोस्
omniroute setup-claude            # ~/.claude/profiles/<name>/settings.json मा लेख्छ
omniroute launch --profile glm52  # OmniRoute मार्फत glm/glm-5.2 प्रयोग गर्ने Claude Code
```

## Claude Code गेटवेसँग कसरी जडान हुन्छ

Claude Code ले **Anthropic Messages API** सँग सञ्चार गर्छ र वातावरणीय चलहरूद्वारा
अनुकूलन गरिएको एन्डपोइन्टतर्फ निर्देशित हुन्छ (यसमा `--base-url` फ्ल्याग छैन):

| चल                                           | उद्देश्य                                                                                              |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `ANTHROPIC_BASE_URL`                         | गेटवेको मूल URL (Claude Code ले `/v1/messages` थप्छ)। **`/v1` प्रत्यय नराख्नुहोस्।**                  |
| `ANTHROPIC_AUTH_TOKEN`                       | `Authorization: Bearer …` का रूपमा पठाइन्छ — आफ्नो OmniRoute पहुँच टोकन / API कुञ्जी प्रयोग गर्नुहोस् |
| `ANTHROPIC_API_KEY`                          | वैकल्पिक: `x-api-key` का रूपमा पठाइन्छ। दुवै सेट भएमा `ANTHROPIC_AUTH_TOKEN` ले प्राथमिकता पाउँछ      |
| `ANTHROPIC_MODEL`                            | कुनै निश्चित मोडेल प्रयोग गर्न बाध्य पार्छ (`/model` चयनकर्ताको पूर्वनिर्धारित मानलाई ओभरराइड गर्छ)   |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` → मूल `/model` चयनकर्ताले `/v1/models` बाट `claude*`/`anthropic*` मोडेलहरू सूचीबद्ध गर्छ          |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`              | प्रत्येक प्रतिक्रियाका आउटपुट टोकन सीमित गर्छ (जस्तै `65536`)                                         |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`            | स्वतः-सङ्कुचनका लागि टोकन सीमा                                                                        |

> वातावरणीय चलहरू **सुरु हुँदा एक पटक मात्र** पढिन्छन् — तिनलाई परिवर्तन गरेपछि Claude Code पुनः सुरु गर्नुहोस्।

`omniroute launch` ले यी सबै तपाईंका लागि सेट गर्छ: यसले सक्रिय सन्दर्भबाट आधार URL + टोकन
निर्धारण गर्छ (त्यसैले `omniroute connect <vps>` पछि `omniroute launch`
सीधै काम गर्छ), सर्भरको स्वास्थ्य जाँच गर्छ, र `claude` कार्यान्वयन गर्छ।

## डिस्कभरी उपनामहरू — `/model` चयनकर्तामा गैर-Claude मोडेलहरू देखाउनुहोस्

Claude Code को गेटवे मोडेल डिस्कभरीले `claude` वा `anthropic` बाट सुरु हुने id हरू मात्र
सूचीबद्ध गर्छ, त्यसैले `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` हुँदा मूल
`/model` चयनकर्ताले सामान्यतया OmniRoute का Claude/Anthropic मोडेलहरू **मात्र** देखाउँछ —
राउटिङ ठीकसँग भए पनि `kimi/kimi-k2.6` वा `glm/glm-5.2` कहिल्यै देखिँदैन।

OmniRoute ले सक्षम पारिएको कुनै पनि मोडेल (र कम्बो) लाई `claude/…` id अन्तर्गत प्रतिलिपि गर्न सक्छ, जसले गर्दा त्यो
फिल्टर पार गरेर चयनकर्तामा देखिन्छ:

```
kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<कम्बो "custo-otimizado"> →  claude/combo/custo-otimizado
```

Claude Code मा यीमध्ये एउटा चयन गर्दा, OmniRoute ले राउटिङ गर्नुअघि `claude/` आवरण
हटाएर वास्तविक id मा फर्काउँछ — वास्तविक `claude/<real-claude-model>` id
(वास्तविक Claude OAuth प्रदायक) लाई सधैँ जस्ताको तस्तै छोडिन्छ।

**यो पूर्वनिर्धारित रूपमा बन्द हुन्छ** र तीन-स्तरीय गेटद्वारा नियन्त्रित हुन्छ (सबैभन्दा विशिष्टले
प्राथमिकता पाउँछ), त्यसैले Claude Code प्रयोग नगर्ने क्लाइन्टहरूका लागि साधारण OmniRoute ले आफ्नो क्याटलग दोब्बर बनाउँदैन:

| स्तर        | स्थान                                                                                    |
| ----------- | ---------------------------------------------------------------------------------------- |
| मोडेल       | प्रदायक विवरण पृष्ठ → प्रति-मोडेल "Claude Code मा देखाउनुहोस्" टगल                       |
| प्रदायक     | प्रदायक विवरण पृष्ठ → प्रदायक-स्तरीय टगल (यसका सबै मोडेलहरू समेट्छ)                      |
| विश्वव्यापी | सेटिङहरू → सुविधा फ्ल्यागहरू → `EXPOSE_CC_DISCOVERY_ALIASES` (पूर्वनिर्धारित रूपमा बन्द) |

`EXPOSE_CC_DISCOVERY_ALIASES` वातावरणीय चलले विश्वव्यापी स्तरलाई जबरजस्ती सक्रिय गर्छ
र ड्यासबोर्ड ओभरराइडभन्दा प्राथमिकता पाउँछ (त्यसो हुँदा सुविधा फ्ल्याग स्क्रिनले
"वातावरणीय चलमार्फत सक्रिय" टिप्पणी देखाउँछ)। प्रति-प्रदायक र
प्रति-मोडेल टगलहरूले त्यसपछि थप परिष्कृत गर्छन् — जस्तै, विश्वव्यापी बन्द + Kimi प्रदायक सक्रिय हुँदा
Kimi का मोडेलहरू मात्र देखिन्छन्।

> ⚠️ **गैर-Claude मोडेलहरूमा विन्डो बेमेल।** Claude Code ले आफूले नचिनेको कुनै पनि id का लागि
> 200K सन्दर्भ विन्डो मान्छ (यसले `/v1/models` बाट वास्तविक विन्डो पढ्न सक्दैन)।
> अझ ठूलो विन्डो भएको मोडेलका लागि (जस्तै Kimi K2 को 256K), `CLAUDE_CODE_AUTO_COMPACT_WINDOW`
> लाई मोडेलको वास्तविक विन्डोभन्दा कम मानमा सेट गर्नुहोस्, ताकि
> स्वतः-सङ्कुचन समयभन्दा अघि सुरु नहोस्। माथि सिर्जना गरिएका प्रोफाइलहरूले यसलाई प्रत्येक
> मोडेलका लागि पहिले नै सेट गर्छन्।

## ड्यासबोर्डमा अनबोर्डिङ ब्लक

Claude उपकरण कार्डले (**Dashboard → CLI Code**) यस इन्स्ट्यान्सका लागि ठ्याक्कै `settings.json` खण्डलाई
डिस्कभरी-अलायस जानकारी बटनको छेउमा, प्रतिलिपि बटनसहित देखाउँछ:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}
```

आधार URL कार्डले रिजल्भ गरेको URL हो (तपाईंले टाइप गर्नुभएको अनुकूलन ओभरराइडसहित), जसलाई पहिले नै
सामान्यीकृत गरिएको हुन्छ — `/v1` प्रत्यय हुँदैन र अन्त्यमा स्ल्यास हुँदैन। **कुञ्जी कहिल्यै देखाइँदैन**: ब्लकमा
प्लेसहोल्डर आउँछ, त्यसैले स्क्रिनसट वा टाँसिएको स्निपेटबाट कुञ्जी चुहिन सक्दैन। त्यसमाथि आफ्नो कुञ्जी टाँस्नुहोस्।

वास्तविक कन्टेक्स्ट विन्डो 200K नभएको कुनै पनि मोडेलका लागि सोही `env` ब्लकअन्तर्गत
`CLAUDE_CODE_AUTO_COMPACT_WINDOW` थप्नुहोस् — Claude Code ले आफूले नचिनेको प्रत्येक id का लागि
200K मान्छ, त्यसैले अन्यथा स्वतः-कम्प्याक्सन गलत बिन्दुमा सक्रिय हुन्छ (अघिल्लो खण्डको चेतावनी हेर्नुहोस्)।
स्निपेट बिल्डरले पनि त्यो मान स्वीकार गर्छ, त्यसैले लक्षित मोडेलको विन्डो थाहा भएको कलरले त्यसलाई
सीधै उत्सर्जन गर्न सक्छ।

स्रोत: `src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet` (शुद्ध
बिल्डर, युनिट-परीक्षण गरिएको), जसलाई `ClaudeGatewayOnboardingBlock` ले रेन्डर गर्छ।

## प्रोफाइलहरू (`CLAUDE_CONFIG_DIR`)

Claude Code मा **नेटिभ प्रोफाइल फाइलहरू छैनन्** (Codex को `~/.codex/<name>.config.toml` भन्दा फरक)।
चलनचल्तीको संयन्त्र `CLAUDE_CONFIG_DIR` हो — प्रत्येक प्रोफाइलका लागि छुट्टै कन्फिग डाइरेक्टरी,
जसमा आ-आफ्नै `settings.json`, प्रमाणहरू, इतिहास र क्यास हुन्छन्।

`omniroute setup-claude` ले प्रत्यक्ष `/v1/models` क्याटलग ल्याउँछ र प्रत्येक मोडेलका लागि
`~/.claude/profiles/<name>/settings.json` मा एउटा प्रोफाइल लेख्छ, जसले
**`setup-codex` कै नामहरू** (`glm52`, `kimi-k27`, `deepseek-pro`, …) पुनः प्रयोग गर्छ:

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}
```

> **प्रमाणीकरण टोकन प्रोफाइलमा कहिल्यै लेखिँदैन।** यसरी सुरु गर्नुहोस्:
> `omniroute launch --profile <name>` (यसले सक्रिय कन्टेक्स्टबाट `ANTHROPIC_AUTH_TOKEN`
> इन्जेक्ट गर्छ), वा आफैं `ANTHROPIC_AUTH_TOKEN` निर्यात गरेर
> `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude` चलाउनुहोस्।

**मोडेल डिस्कभरीपछि स्वतः-सिङ्क (अप्ट-इन)।** प्रदायक मोडेल सिङ्कले प्रत्यक्ष क्याटलग परिवर्तन गर्दा
OmniRoute ले यिनै `~/.claude/profiles/<name>/settings.json` फाइलहरू स्वतः पुनः उत्पन्न गर्न सक्छ —
त्यसैले नयाँ वा पुनःनामकरण गरिएका मोडेलहरूले कमान्ड पुनः नचलाइकनै प्रोफाइल पाउँछन्। यो
**पूर्वनिर्धारित रूपमा बन्द** हुन्छ: यसलाई **CLI Code dashboard** बाट टगल गर्नुहोस् ("CLI profile
auto-sync" → Claude Code), वा `OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true` सेट गर्नुहोस् (यसले
पूर्वनिर्धारित रूपमा सक्रिय `CLI_ALLOW_CONFIG_WRITES` लाई पनि मान्छ)। सक्रिय गरिँदा यसले प्रोफाइल
फाइलहरू मात्र लेख्छ; यसले तपाईंको सक्रिय/पूर्वनिर्धारित Claude कन्फिग, प्रमाणीकरण वा
`~/.claude/settings.json` कहिल्यै परिवर्तन गर्दैन।

### प्रोफाइलहरू उत्पन्न गर्ने + प्रयोग गर्ने

```bash
# स्थानीय OmniRoute
omniroute setup-claude

# रिमोट VPS (हरेक प्रोफाइलमा VPS URL समावेश गर्छ)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# केही प्रदायकहरू मात्र
omniroute setup-claude --only glm,kimi

# नलेखी पूर्वावलोकन गर्ने
omniroute setup-claude --dry-run

# एउटा प्रोफाइल सुरु गर्ने
omniroute launch --profile kimi-k27
```

## मोडेल तहहरू (वैकल्पिक)

Claude Code ले क्षमताका तहहरूमा रुट गर्छ। यदि तपाईं प्रत्येक तहका लागि फरक प्रदायक चाहनुहुन्छ भने env /
सेटिङहरूमार्फत प्रत्येकलाई OmniRoute मोडेलसँग म्याप गर्नुहोस्:

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm/glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="kmc/kimi-k2.6"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="glm/glm-4.7-flash"
```

अन्यथा एउटै `ANTHROPIC_MODEL` (जुन प्रोफाइलहरूले सेट गर्छन्) सबै कुराका लागि प्रयोग गरिन्छ।

## रिमोट मोड

तपाईंले `omniroute connect <host>` चलाइसकेपछि ([रिमोट मोड](./REMOTE-MODE.md) हेर्नुहोस्),
`omniroute launch` र `omniroute setup-claude` ले स्वतः उक्त रिमोट सर्भरलाई लक्षित
गर्छन् र त्यसको दायराबद्ध पहुँच टोकन प्रयोग गर्छन् — कुनै अतिरिक्त फ्ल्याग आवश्यक पर्दैन।
प्रत्येक आह्वानका लागि `--remote` / `--api-key` प्रयोग गरेर ओभरराइड गर्नुहोस्।

## समस्या समाधान

**Claude Code ले गेटवे बेवास्ता गर्छ** — `ANTHROPIC_BASE_URL` मा **`/v1`
नभएको** पुष्टि गर्नुहोस् र `claude` पुनः सुरु गर्नुहोस् (env स्टार्टअपमा एक पटक मात्र पढिन्छ)।
`omniroute launch` ले तपाईंका लागि यो व्यवस्थापन गर्छ।

**`/model` चयनकर्ता खाली छ / गेटवे मोडेलहरू छुटेका छन्** — Claude Code
v2.1.219+ र `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` आवश्यक हुन्छ। चयनकर्तामा
`claude*` / `anthropic*` मोडेल ID हरू मात्र देखिन्छन्; अन्य कुनै पनि मोडेललाई
`ANTHROPIC_MODEL=<id>` मार्फत बाध्यकारी रूपमा प्रयोग गर्नुहोस् (प्रोफाइलहरूले यही गर्छन्)।

**`400 Ambiguous model 'claude-…'`** — Claude Code ले सधैँ **उपसर्गरहित**
मोडेल ID हरू पठाउँछ (जस्तै `claude-opus-4-8`), त्यसैले Claude Code (`cc/…`) र
Claude (`claude/…`) दुवै प्रदायक जडान भएका बेला उपसर्गरहित ID दुईवटा रुटसँग मेल खान्छ र
OmniRoute ले अनुमान गर्न अस्वीकार गर्छ। यसलाई दुईमध्ये कुनै एक तरिकाले समाधान गर्नुहोस्:
`ANTHROPIC_MODEL=cc/claude-opus-4-8` प्रयोग गरी उपसर्गयुक्त ID निश्चित गर्नुहोस्, वा
**उपसर्गरहित Claude मोडेलहरूका लागि Claude Code लाई प्राथमिकता दिनुहोस्** सक्षम गर्नुहोस् —
Claude प्रदायक पृष्ठमा रहेको टगल, वा
`OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true` (पूर्वनिर्धारित रूपमा बन्द;
[वातावरण](../reference/ENVIRONMENT.md) हेर्नुहोस्) — जसले उपसर्गरहित `claude-*`
ID हरूलाई Claude Code तर्फ रुट गर्छ। स्पष्ट प्रदायक उपसर्गहरूले सधैँ प्राथमिकता पाउँछन्।

**प्रमाणीकरण त्रुटिहरू** — प्रोफाइलमा कुनै टोकन हुँदैन। `omniroute launch --profile`
प्रयोग गर्नुहोस् (यसले टोकन इन्जेक्ट गर्छ) वा `ANTHROPIC_AUTH_TOKEN` export गर्नुहोस्।

**प्रोफाइलहरू अलग रहँदैनन्** — प्रत्येक प्रोफाइल छुट्टै `CLAUDE_CONFIG_DIR` हो;
सेसनभित्र `echo $CLAUDE_CONFIG_DIR` ले
`~/.claude/profiles/<name>` तर्फ सङ्केत गरेको पुष्टि गर्नुहोस्।
