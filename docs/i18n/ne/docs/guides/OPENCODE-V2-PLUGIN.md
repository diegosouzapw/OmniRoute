`@omniroute/opencode-plugin-v2` ले तपाईंको सम्पूर्ण OmniRoute क्याटलग — मोडेलहरू, कम्बोहरू र
अटो-कम्बोहरू — प्रदर्शन नाम, मूल्य निर्धारण र निःशुल्क-टियर बजेटसहित OpenCode v2 को मोडेल पिकरमा राख्छ।

यो `@omniroute/opencode-plugin` भन्दा छुट्टै प्याकेज हो, किनकि OpenCode v1 र v2 ले
फरक कन्ट्र्याक्टमार्फत प्लगइनहरू लोड गर्छन्। तपाईंको OpenCode को प्रमुख संस्करणसँग मिल्ने प्याकेज छान्नुहोस्;
तिनीहरूबीच केही पनि साझा हुँदैन, त्यसैले एउटा अपग्रेड गर्दा अर्को अपग्रेड गर्नुपर्ने हुँदैन।

## आवश्यकताहरू

- OpenCode v2।
- पहुँचयोग्य OmniRoute गेटवे (पूर्वनिर्धारित रूपमा `http://localhost:20128`)।
- Node.js 22 वा 24।

## स्थापना

`opencode.json` मा प्लगइन थप्नुहोस्:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

त्यसपछि मोडेलहरू `omniroute/<provider>/<model>` का रूपमा देखा पर्छन्; `providerId` ले उक्त उपसर्ग र
OpenCode ले क्रेडेन्सियल भण्डारण गर्ने इन्टिग्रेसनको id निर्धारण गर्छ।

## क्रेडेन्सियलहरू

प्लगइनले निम्न तीन स्थानमा, यही क्रममा, गेटवे कुञ्जी खोज्छ:

1. **तपाईंले OpenCode मा जडान गर्नुभएको क्रेडेन्सियल।** प्लगइनले एउटा इन्टिग्रेसन दर्ता गर्छ, त्यसैले
   OpenCode को आफ्नै प्रमाणीकरण प्रक्रियाले कुञ्जी भण्डारण गर्न सक्छ। `opencode.json` मा केही पनि
   लेखिँदैन — यसैलाई प्राथमिकता दिनुहोस्।
2. प्रति-प्रोजेक्ट ओभरराइडका लागि प्लगइन विकल्पहरूमा `apiKey`। यसले कुञ्जीलाई तपाईंले
   कमिट गरिरहनुभएको हुन सक्ने फाइलमा राख्छ।
3. वातावरणमा `OMNIROUTE_API_KEY`।

यी तीनमध्ये कुनै पनि नभएमा, क्याटलग खाली हुन्छ र प्लगइनले तपाईंलाई कुनै सूचना नदिई खाली पिकरमा
छोड्नुको सट्टा स्टार्टअपमा एक पटक त्यसबारे जानकारी दिन्छ।

### व्यवस्थापन टोकन फरक कुञ्जी हो

कम्बोहरू, प्रदायकको स्वास्थ्य अवस्था र संवर्धन (प्रदर्शन नाम, मूल्य निर्धारण, निःशुल्क-टियर बजेटहरू)
गेटवेको `/api/*` एन्डपोइन्टहरूबाट आउँछन्, जसलाई अधिकांश डिप्लोयमेन्टहरूले इन्फरेन्स कुञ्जीको सट्टा
**व्यवस्थापन** टोकनद्वारा सुरक्षित गर्छन्:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<management read token>"
}
```

सेट नगरिएमा, `managementReadToken` ले `apiKey` लाई फलब्याकका रूपमा प्रयोग गर्छ। गेटवेले उक्त
फलब्याक अस्वीकार गर्दा पनि क्याटलग प्रकाशित हुन्छ, तर प्रदर्शन नामको सट्टा अपरिष्कृत मोडेल id हरूसहित,
क्यानोनिकल एलियास डिडुप्लिकेसनविना, मूल्य निर्धारणविना र कम्बोहरूविना। त्यस्तो हुँदा प्लगइनले प्रत्येक
एन्डपोइन्टका लागि एक पटक चेतावनी दिन्छ, एन्डपोइन्ट र के गुम्यो भन्ने उल्लेख गर्दै — त्यसैले गुणस्तर घटेको
पिकर कहिल्यै रहस्य बन्दैन।

## विकल्पहरू

| कुञ्जी                           | पूर्वनिर्धारित                                        | टिप्पणीहरू                                                                                                              |
| -------------------------------- | ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `providerId`                     | `"omniroute"`                                         | प्रदायक id, इन्टिग्रेसन id, र मोडेलहरू देखा पर्ने उपसर्ग                                                                |
| `baseURL`                        | आवश्यक                                                | गेटवे रुट, `http(s)` मात्र; आवश्यक ठाउँमा `/v1` प्रत्यय थपिन्छ                                                          |
| `apiKey`                         | जडान गरिएको क्रेडेन्सियल, त्यसपछि `OMNIROUTE_API_KEY` | `/v1/*` का लागि च्याट कुञ्जी                                                                                            |
| `managementReadToken`            | `apiKey` मा फलब्याक हुन्छ                             | `/api/*` का लागि कुञ्जी — सामान्यतया उही कुञ्जी **होइन**                                                                |
| `displayName`                    | `"OmniRoute"`                                         | पिकरमा प्रदायकको नाम                                                                                                    |
| `timeoutMs`                      | `10000`                                               | प्रत्येक एन्डपोइन्टको फेच टाइमआउट (अटो-कम्बोहरूले 5s प्रयोग गर्छन्)                                                     |
| `modelCacheTtlMs`                | `300000`                                              | क्याटलग क्यास TTL; डिस्क स्न्यापसटले कोल्ड स्टार्टलाई वार्म गर्छ                                                        |
| `timeouts`                       | `timeoutMs` मा फलब्याक हुन्छ                          | ms मा प्रत्येक एन्डपोइन्टका बजेटहरू: `models`, `combos`, `autoCombos`, `enrichment`                                     |
| `enrichment`                     | `true`                                                | नाम, मूल्य निर्धारण र निःशुल्क-टियर बजेटहरू प्राप्त गर्नुहोस्                                                           |
| `providerTag`                    | `true`                                                | प्रदर्शन नामको अगाडि त्यसले रुट गर्ने अपस्ट्रिम प्रदायकको नाम राख्नुहोस्                                                |
| `usableOnly`                     | `false`                                               | गेटवेले प्रोभिजन गरिएको भनी रिपोर्ट गरेका प्रदायकहरू मात्र राख्नुहोस्                                                   |
| `visibleModels` / `hiddenModels` | `[]`                                                  | ठ्याक्कै-मिल्ने-वा-प्रत्ययमा-आधारित अनुमतिसूचीहरू; निषेधले प्राथमिकता पाउँछ                                             |
| `geminiSanitization`             | `true`                                                | Gemini ले टुल स्किमाबाट अस्वीकार गर्ने JSON-Schema किवर्डहरू हटाउनुहोस् (`$ref` टुलहरू परिवर्तन नगरी फर्वार्ड गरिन्छन्) |
| `apiFormat.allowAnthropic`       | `false`                                               | अनुमतिसूचीमा भएका id हरूलाई Anthropic API ब्लकमार्फत रुट गर्नुहोस्                                                      |
| `apiFormat.anthropicModels`      | `[]`                                                  | Anthropic तर्फ रुट गरिने पूर्ण मोडेल id हरू                                                                             |
| `logLevel` / `startupDebug`      | `warn` / `false`                                      | लगरको विस्तृतता                                                                                                         |

## क्याटलग कसरी अद्यावधिक रहन्छ

क्याटलग आवश्यक पर्दा मात्र प्राप्त गरिन्छ र `modelCacheTtlMs` अवधिसम्म क्यास गरिन्छ, र डिस्क स्न्यापसटले गेटवे पहुँचयोग्य नभएको अवस्थामा पनि पछिल्लो ज्ञात क्याटलग उपलब्ध राख्छ — सेवा अवरोध हुँदा तपाईंले गुमाउने भनेको अद्यावधिकता मात्र हो। मोडेल र कम्बोहरू आइपुग्नेबित्तिकै प्रकाशित हुन्छन्; अटो-कम्बोहरू, प्रदायक सूची र संवर्धन ओभरले आइपुगेपछि समाहित हुन्छन्, त्यसैले एउटा ढिलो एन्डपोइन्टले सम्पूर्ण पिकरलाई रोक्न सक्दैन।

नामहरूले गेटवेलाई थाहा भएको जानकारी समेट्छन्: मोडेल रुट हुने अपस्ट्रिम प्रदायक, `[Free]` चिन्ह र त्यससँग आउने बजेट — त्यसैले एउटै मोडेल बेच्ने दुईवटा कनेक्सन छुट्याउन सकिन्छ। `"providerTag": false` प्रयोग गरेर प्रिफिक्स बन्द गर्नुहोस्।

म्यानुअल रिफ्रेस कमान्ड छैन: OpenCode v2 कमान्डहरू प्रम्प्ट टेम्प्लेट हुन्, कलब्याक होइनन्, त्यसैले प्लगइनले यस्तो कमान्ड उपलब्ध गराउन सक्दैन। रिफ्रेसहरू TTL अनुसार हुन्छन्; क्याटलग वा ओभरले वास्तवमै परिवर्तन भएको अवस्थामा मात्र होस्टलाई रिलोड गर्न भनिन्छ, हरेक रिफ्रेसमा होइन।

## Gemini मा टुल कलिङ

टुल घोषणाहरूमा `$schema` वा `additionalProperties` भएको पूरै अनुरोधलाई Gemini ले अस्वीकार गर्दै `400 INVALID_ARGUMENT` जवाफ दिन्छ। प्लगइनले यस प्रदायकको Gemini मोडेलतर्फ पठाइने टुल स्किमाहरूबाट ती किवर्डहरू हटाउँछ र अन्य सबै अनुरोधलाई अपरिवर्तित छोड्छ। `$ref` भएको टुललाई हटफेर नगरी फर्वार्ड गरिन्छ, किनकि रेफरेन्स हटाउँदा स्किमा "जे पनि स्वीकार गर्ने" गरी फराकिलो हुने थियो।
यसलाई बन्द गर्न `"geminiSanitization": false` सेट गर्नुहोस्।

## समस्या समाधान

| लक्षण                                   | कारण                                                                                                                               |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| पिकरले कुनै OmniRoute मोडेल देखाउँदैन   | कुनै की समाधान भएन (स्टार्टअप चेतावनी जाँच गर्नुहोस्), वा गेटवे पहुँचयोग्य छैन                                                     |
| कच्चा मोडेल आईडीहरू, कम्बो वा मूल्य छैन | व्यवस्थापन एन्डपोइन्टहरूले टोकन अस्वीकार गरे — `managementReadToken` सेट गर्नुहोस्                                                 |
| `opencode-<id>/…` मा पिन गरिएको सेसन    | v1 प्लगइनले `opencode-<id>` प्रकाशित गर्थ्यो; v2 ले `<id>` मात्र प्रकाशित गर्छ, त्यसैले `<id>/…` अन्तर्गत मोडेल पुनः चयन गर्नुहोस् |
