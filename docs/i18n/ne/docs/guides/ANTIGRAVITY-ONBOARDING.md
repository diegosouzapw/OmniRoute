## 1. Antigravity र Antigravity CLI (agy) बीचको तुलना

दुवै प्रदायकले **एउटै Google ब्याकएन्ड** साझा गर्छन् — उही OAuth क्लाइन्ट, टोकन रिफ्रेस, एन्डपोइन्टहरू र Google खाताहरू। भिन्नता तपाईंले देख्ने मोडेलहरूमा छ।

> Google को आधिकारिक तुलनाका लागि [Antigravity CLI घोषणा](https://antigravity.google/blog/introducing-google-antigravity-cli) हेर्नुहोस्।

| पक्ष                               | `antigravity` (IDE)                                         | `agy` (CLI)                                                     |
| ---------------------------------- | ----------------------------------------------------------- | --------------------------------------------------------------- |
| **Google उत्पादन**                 | Antigravity 2.0 / Antigravity IDE                           | Antigravity CLI                                                 |
| **ब्याकएन्ड**                      | उही Google Cloud Code API                                   | उही Google Cloud Code API                                       |
| **OAuth / टोकन**                   | उही क्लाइन्ट, उही रिफ्रेस                                   | उही क्लाइन्ट, उही रिफ्रेस                                       |
| **मोडेल सूची**                     | स्थिर रूपमा छनोट गरिएको सूची (OmniRoute मा हार्डकोड गरिएको) | `:fetchAvailableModels` मार्फत Google बाट प्रत्यक्ष जाँच गरिएको |
| **Claude मोडेलहरू**                | Sonnet 4.6, Opus 4.6 (प्रत्येकका 4 संस्करण)                 | Sonnet 4.6, Opus 4.6 (प्रत्येकका 4 संस्करण)                     |
| **Gemini नामकरण**                  | स्पष्ट लेबलहरू (न्यून/मध्यम/उच्च)                           | अपस्ट्रिम ID हरू (extra-low/low/agent)                          |
| **अतिरिक्त मोडेलहरू**              | `gpt-oss-120b-medium`                                       | Google का थप मोडेलहरू समावेश हुन सक्छन्                         |
| **पूर्वनिर्धारित प्रयोगको अवस्था** | IDE एकीकरण (VS Code, JetBrains)                             | CLI / API पहुँच                                                 |
| **कोटा**                           | agy सँग साझा (उही Google खाता)                              | antigravity सँग साझा (उही Google खाता)                          |

**उपलब्ध मोडेलहरू (प्रयोगमार्फत प्रमाणित, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (विभिन्न सोचाइ स्तरहरू)
- Claude: Sonnet 4.6, Opus 4.6 (प्रत्येकमा default/low/medium/high संस्करणहरू)
- अन्य: GPT-OSS 120B Medium
- **Claude Sonnet 5 उपलब्ध छैन** — केवल 4.6 का संस्करणहरू समर्थित छन्

**मोडेल सूची किन फरक छ**: Google को आधिकारिक ब्लगअनुसार, Google को CLI "गति र न्यून ओभरहेडका लागि अनुकूलित" र "Gemini मोडेलहरूसँग सह-अनुकूलित" छ। Web/IDE उत्पादन "व्यापकताका लागि अनुकूलित" छ। CLI ले मोडेलहरू गतिशील रूपमा पत्ता लगाउन `:fetchAvailableModels` प्रयोग गर्छ, जबकि IDE ले स्थिर रूपमा छनोट गरिएको सूची प्रयोग गर्छ।

**व्यवहारमा**: Gemini मोडेलहरूका लागि `agy/` उपसर्ग प्रयोग गर्नुहोस् (जस्तै `agy/gemini-3.7-flash-high`)। स्थिर रूपमा छनोट गरिएको सूचीका लागि `antigravity/` प्रयोग गर्नुहोस्। दुवैले एउटै Google ब्याकएन्ड प्रयोग गर्छन्, तर फरक मोडेल नामकरण प्रस्तुत गर्छन्। कोटा साझा हुन्छ — जुनसुकै प्रदायक प्रयोग गरे पनि त्यसको गणना उही Google खाताको सीमामा हुन्छ।

## 2. Google One AI Pro: कोटा प्रणाली

> आधिकारिक कोटा विवरणका लागि [Antigravity Docs: Plans](https://antigravity.google/docs/plans) र नवीनतम मूल्यसम्बन्धी अद्यावधिकहरूका लागि [Changes to Antigravity Plans](https://antigravity.google/blog/changes-to-antigravity-plans) हेर्नुहोस्।

Google Antigravity ले सन्देश सङ्ख्यामा नभई "Work Done" (कम्प्युटेसनल भार) मा आधारित **दोहोरो-तहको कोटा** प्रयोग गर्छ।

### दुई तहहरू

| तह                    | यो के हो                  | रिफ्रेस चक्र                                                                  |
| --------------------- | ------------------------- | ----------------------------------------------------------------------------- |
| **5-घण्टे स्प्रिन्ट** | "work done" को तत्काल पूल | सत्रमा पहिलो अनुरोध गरेको 5 घण्टापछि रिसेट हुन्छ                              |
| **7-दिने आधारसीमा**   | साप्ताहिक कडा सीमा        | सीमा पुगेमा 5-घण्टे रिफ्रेसलाई ओभरराइड गर्छ; अर्को 7-दिने अवधिसम्म रोक लगाउँछ |

**"Work Done" कसरी गणना गरिन्छ**: एजेन्टमा बढी निर्भर कार्यहरू (जस्तै, "यो सम्पूर्ण रिपोजिटरी रिफ्याक्टर गर्नुहोस्") ले सामान्य कार्यहरूभन्दा (जस्तै, "यो फङ्सन ठीक गर्नुहोस्") कोटा धेरै छिटो खपत गर्छन्। खपत देखाउने कुनै रियल-टाइम ड्यासबोर्ड छैन।

### Gemini र गैर-Gemini मोडेलहरू

- **Gemini मोडेलहरू** (Flash + Pro): API मूल्यअनुसार खपत हुने एउटै दर सीमा साझा गर्छन्। यदि Flash, Pro भन्दा 8x सस्तो छ भने, तपाईंले 8x बढी Flash टोकन पाउनुहुन्छ।
- **गैर-Gemini मोडेलहरू** (Claude, GPT-OSS): यिनका **छुट्टाछुट्टै** दर सीमाहरू हुन्छन्। Gemini मा रोक लाग्दा पनि यी उपलब्ध रहन सक्छन्।

### AI क्रेडिटहरू (अतिरिक्त प्रयोग)

> क्रेडिटहरूले कसरी काम गर्छन् भन्ने जानकारीका लागि [Google One AI credits](https://support.google.com/googleone/answer/14534406) हेर्नुहोस्।

आधारभूत कोटा सकिएपछि:

- **कहिल्यै होइन**: कोटा रिफ्रेस नहुँदासम्म प्रतीक्षा गर्छ; "Baseline model quota reached" देखाउँछ
- **सधैँ**: AI क्रेडिटहरू स्वतः प्रयोग गर्छ; आधारभूत कोटा रिफ्रेस भएपछि त्यसैमा फर्कन्छ

क्रेडिटहरू छुट्टै खरिद गरिन्छन् र मानक API मूल्यअनुसार कटौती हुन्छन्।

### मुख्य विवरणहरू

- कोटा **खाता-स्तरमा साझा** हुन्छ — Antigravity IDE, CLI र OmniRoute मा प्रयोग गरिएको एउटै Google खाताले एउटै कोटा पूल साझा गर्छ
- प्रत्येक Google खाताको आफ्नै स्वतन्त्र कोटा हुन्छ — धेरै खाता = धेरै कोटा पूल
- AI Pro प्रयोगकर्ताहरूले साप्ताहिक आधारसीमा पुगेपछि 5-घण्टे रिसेटको सट्टा **7-दिने रोक** लागेको रिपोर्ट गरेका छन् (Google ले उच्च मागका लागि यो योजनाअनुसार नै भएको पुष्टि गरेको छ)

**तपाईंको खाताको कोटा सकिँदा**: OmniRoute ले कम्बो रुटमा उपलब्ध अर्को खाताबाट स्वतः पुनः प्रयास गर्छ। म्यानुअल हस्तक्षेप आवश्यक पर्दैन।

## 3. projectId कसरी प्राप्त गर्ने

हरेक antigravity/agy जडानलाई Google Cloud Code `projectId` आवश्यक पर्छ। यो नभएमा `/v1internal:models` एन्डपोइन्टले 404 फर्काउँछ।

### विधि A: स्वचालित (सिफारिस गरिएको)

OmniRoute ले यसलाई स्वचालित रूपमा व्यवस्थापन गर्छ। तपाईंले Dashboard OAuth मार्फत नयाँ Google खाता थप्दा:

1. OmniRoute ले टोकन रिफ्रेस गर्छ
2. projectId पत्ता लगाउन `loadCodeAssist` कल गर्छ
3. कुनै प्रोजेक्ट नभएमा एउटा सिर्जना गर्न `onboardUser` कल गर्छ
4. भर्खरै सिर्जना गरिएको projectId प्राप्त गर्न `loadCodeAssist` पुनः प्रयास गर्छ
5. यसलाई डेटाबेसमा सेभ गर्छ

**यसले अधिकांश खातामा काम गर्छ** — कुनै म्यानुअल चरण आवश्यक पर्दैन।

### विधि B: agy CLI मार्फत म्यानुअल रूपमा

यदि स्वचालित खोज असफल भयो भने (यो कहिले हुन्छ भन्ने जानकारीका लागि खण्ड 5 हेर्नुहोस्):

```bash
# agy CLI इन्स्टल गर्नुहोस् (पहिले नै गरिएको छैन भने)
npm install -g @anthropic-ai/agy

# आफ्नो Google खाताबाट लगइन गर्नुहोस्
agy login

# अनबोर्डिङ आवश्यक भएको खाता चयन गर्नुहोस्
# यसले Cloud Code दर्ता सुरु गर्छ र projectId प्रदान गर्छ
```

`agy login` सफल भएपछि OmniRoute Dashboard मा टोकन रिफ्रेस गर्नुहोस्। projectId स्वतः पत्ता लाग्नेछ।

### कसरी प्रमाणीकरण गर्ने

डेटाबेस जाँच गर्नुहोस्:

```bash
# OmniRoute कन्टेनरभित्र
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

वा लगहरू जाँच गर्नुहोस्:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. OAuth रिडिरेक्ट URI

### समस्या

Google OAuth लाई मान्य रिडिरेक्ट URI आवश्यक हुन्छ। OmniRoute को पूर्वनिर्धारित सेटिङले `http://127.0.0.1:20128/callback` (लुपब्याक) प्रयोग गर्छ। यसले स्थानीय बिल्डहरूमा काम गर्छ, तर **रिमोट डिप्लोयमेन्टहरूमा असफल हुन्छ** (जस्तै, LAN IP मार्फत पहुँच गरिएको सर्भर)।

Google ले निम्न रिडिरेक्ट URI हरू अस्वीकार गर्छ:

- IP ठेगाना प्रयोग गर्ने (URI को अन्त्य `.com`, `.org` आदि भएको डोमेन हुनुपर्छ)
- OAuth क्लाइन्ट कन्फिगमा दर्ता गरिएका रिडिरेक्ट URI हरूसँग नमिल्ने

### समाधान

**विकल्प A: बिल्ट-इन OAuth फ्लो प्रयोग गर्नुहोस् (पूर्वनिर्धारित)**

- तपाईंले `localhost` वा `127.0.0.1` बाट OmniRoute पहुँच गर्दा काम गर्छ
- कुनै कन्फिगरेसन आवश्यक पर्दैन

**विकल्प B: कस्टम OAuth क्रेडेन्सियलहरू**

- आफ्नो वातावरणमा `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` सेट गर्नुहोस्
- आफ्नै Google OAuth क्रेडेन्सियलहरू प्रदान गर्नुहोस्:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Google Cloud Console मा `https://your-domain.com/callback` लाई आधिकारिक रिडिरेक्ट URI का रूपमा दर्ता गर्नुहोस्

**विकल्प C: प्रारम्भिक लगइनका लागि agy CLI प्रयोग गर्नुहोस्**

- OmniRoute पहुँच गर्ने मेसिनमा `agy login` चलाउनुहोस्
- OAuth फ्लो स्थानीय रूपमा पूरा हुन्छ र टोकनहरू भण्डारण हुन्छन्
- Dashboard मार्फत कनेक्सनलाई OmniRoute मा इम्पोर्ट गर्नुहोस्

### सीमितताहरू

- कस्टम OAuth क्रेडेन्सियलहरूका लागि डोमेन नाम आवश्यक हुन्छ (Google ले IP ठेगानाहरूलाई रिडिरेक्ट URI का रूपमा स्वीकार गर्दैन)
- तपाईंसँग डोमेन छैन भने, यसको सट्टा विकल्प A वा C प्रयोग गर्नुहोस्

## 5. समस्या समाधान: स्वचालित सेटअप असफल हुँदा

OmniRoute ले अधिकांश खाताहरूका लागि projectId पत्ता लगाउने र अनबोर्डिङ गर्ने कार्य स्वचालित रूपमा व्यवस्थापन गर्छ। यो असफल हुँदा, मूल कारण सामान्यतया निम्नमध्ये कुनै एक हुन्छ:

### खाताको क्षेत्र ब्लक गरिएको छ

**लक्षण**: `agy login` ले "Eligibility check failed: Your current account is not eligible for Antigravity, because it is not currently available in your location." फर्काउँछ।

**मूल कारण**: Google खाताहरूमा दर्ता गर्ने समयमा सेट गरिएको ब्याकएन्ड "Country Association" फिल्ड हुन्छ। agy CLI र Cloud Code API ले यो फिल्डलाई कडाइका साथ जाँच गर्छन् — वेब Gemini ले भने तपाईंको हालको IP मात्र जाँच गर्छ।

> आफ्नो खातासँग सम्बद्ध क्षेत्र जाँच्न वा परिवर्तन गर्न [Google Country Association Form](https://policies.google.com/country-association-form) मा जानुहोस्।

**वेब Gemini ले काम गर्ने तर agy ले नगर्ने कारण**:

- वेब Gemini / Google One: हालको IP मात्र जाँच गर्छ (प्रोक्सीले काम गर्छ)
- agy CLI / Cloud Code API: ब्याकएन्ड Country Association फिल्ड पढ्छ (प्रोक्सीले मद्दत गर्दैन)

**समाधान**:

1. US IP प्रयोग गरिरहेको बेला [Google Country Association Form](https://policies.google.com/country-association-form) मा जानुहोस्
2. क्षेत्र परिवर्तन अनुरोध पेस गर्नुहोस् ("I live in a different country" चयन गर्नुहोस्)
3. Google ले प्रक्रिया पूरा गरेर इमेल सूचना पठाउन 1-24 घण्टा पर्खनुहोस्
4. त्यसपछि `agy login` सफल हुनुपर्छ

### खातामा Cloud Code प्रोजेक्ट छैन

**लक्षण**: लगहरूमा `loadCodeAssist returned no project id` र `onboardUser failed (400)` देखिन्छ।

**मूल कारण**: खाता Google Cloud Code मा कहिल्यै दर्ता गरिएको छैन र स्वचालित अनबोर्डिङ असफल भयो।

**समाधान**: Cloud Code दर्ता सुरु गर्न `agy login` म्यानुअल रूपमा चलाउनुहोस्, त्यसपछि OmniRoute Dashboard मा टोकन रिफ्रेस गर्नुहोस्।

### टोकनको म्याद सकिएको वा खारेज गरिएको छ

**लक्षण**: लगहरूमा 401 त्रुटिहरू वा "Token has expired" सन्देशहरू देखिन्छन्।

**समाधान**: Dashboard → Providers → agy → रिफ्रेस आइकनमा क्लिक गरेर टोकन रिफ्रेस गर्नुहोस्। रिफ्रेस टोकन नै खारेज गरिएको छ भने, तपाईंले OAuth मार्फत पुनः प्रमाणीकरण गर्नुपर्नेछ।

```
│  │         1-24 घण्टा पर्खनुहोस्, त्यसपछि पुनः प्रयास गर्नुहोस्

│  ├─ छैन → पहिले one.google.com मा सदस्यता लिनुहोस्
│  └─ छ ↓

│  └─ अझै असफल हुन्छ ↓

   ├─ काम गर्छ → Dashboard मा टोकन रिफ्रेस गर्नुहोस्, projectId पत्ता लाग्छ
   └─ असफल हुन्छ → त्रुटि सन्देश जाँच गर्नुहोस्, सम्भवतः क्षेत्र वा सदस्यतासम्बन्धी समस्या
```
