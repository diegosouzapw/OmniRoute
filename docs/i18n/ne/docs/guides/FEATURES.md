## ✨ v3.8.0 का मुख्य आकर्षण

v3.7.x → v3.8.0 चक्रले शून्य-कन्फिग स्वतः राउटिङ, नयाँ प्रदायकहरू, OAuth प्रवाहहरू, अझ गहन लचिलोपन, र धेरै समृद्ध CLI अनुभव थपेको छ। प्रमुख सुविधाहरू तल छन् — पूर्ण विवरण यस दस्तावेजमा अगाडि र लिङ्क गरिएका स्पेसिफिकेसनहरूमा उपलब्ध छन्।

- 🤖 **Auto Combo / शून्य-कन्फिग स्वतः राउटिङ** — `auto/coding`, `auto/fast`, `auto/cheap`, `auto/offline`, `auto/smart`, `auto/lkgp`, `auto/chaos` प्रिफिक्सहरू प्रयोग गर्नुहोस्। १६-कारक स्कोरिङ इन्जिन र सावधानीपूर्वक तयार गरिएका ६ वटा **मोड प्याकहरू** (ship-fast, cost-saver, quality-first, offline-friendly, reliability-first, chaos-mode) द्वारा समर्थित
- 🆕 **Command Code प्रदायक** (#2199) — मोडेल क्याटलग र कोटा ट्र्याकिङसहितको प्रथम-श्रेणी दर्ता
- 🆕 **Z.AI प्रदायक** — कोटा लेबलहरू भएको नयाँ निःशुल्क-टियर प्रदायक
- 🎬 **KIE मिडिया विस्तार** — भिडियो उत्पादन मोडेलहरू समावेश भएको विस्तारित क्याटलग
- 🔐 **Devin प्रमाणीकरण** — Desktop ले विद्यमान Devin API कुञ्जी आयात गर्छ; CLI ले स्थानीय `devin auth login` प्रमाणहरू प्रयोग गर्छ
- 🆓 **८ नयाँ निःशुल्क प्रदायकहरू** — LLM7, Lepton, UncloseAI, BazaarLink, Completions, Enally, FreeTheAi, Command Code
- 🎯 **म्यानिफेस्ट-सचेत W1–W4 टियर राउटिङ** — प्रदायक म्यानिफेस्टहरूले भारित टियर चयन सञ्चालन गर्छन्
- 🎨 **Cursor मा पूर्ण OpenAI समानता** — उपकरण कलहरू, स्ट्रिमिङ, र सत्र व्यवस्थापन सुरुदेखि अन्त्यसम्म
- 📊 **Cursor Pro योजनाको प्रयोग** — कोटा र चक्र डेटा प्रदायक-सीमा ड्यासबोर्डमा देखाइन्छ
- ⚡ **सेवा टियर विभाजन / Codex द्रुत टियर विश्लेषण** — प्रत्येक टियरको खपत दृश्यता

## 🔌 प्रदायकहरू

AI प्रदायक जडानहरू व्यवस्थापन गर्नुहोस्: OAuth प्रदायकहरू (Claude Code, Codex), API कुञ्जी प्रदायकहरू (Groq, DeepSeek, OpenRouter), र निःशुल्क प्रदायकहरू (Qoder, Kiro)। Kiro खाताहरूमा क्रेडिट मौज्दात ट्र्याकिङ समावेश हुन्छ — बाँकी क्रेडिट, कुल सीमा, र नवीकरण मिति Dashboard → Usage मा देखिन्छन्।

OpenRouter जडानहरूले Advanced Settings मा प्रत्येक जडानका लागि छुट्टै `preset` भण्डारण गर्न सक्छन्। सेट गरिएको अवस्थामा, क्लाइन्ट अनुरोधले आफ्नै `preset` पहिले नै उपलब्ध नगराएसम्म OmniRoute ले यसलाई OpenRouter को शीर्ष-स्तरीय अनुरोध फिल्डका रूपमा पठाउँछ, उदाहरणका लागि `"preset": "email-copywriter"`।

## 🎨 कम्बोहरू

१९ वटा सार्वजनिक रणनीतिहरूसहित मोडेल राउटिङ कम्बोहरू सिर्जना गर्नुहोस्: प्राथमिकता, भारित, राउन्ड-रोबिन, कन्टेक्स्ट-रिले, फिल-फर्स्ट, p2c (दुई विकल्पको शक्ति), र्यान्डम, सबैभन्दा कम प्रयोग भएको, लागत-अनुकूलित, रिसेट-सचेत, रिसेट-विन्डो, हेडरुम, स्ट्रिक्ट-र्यान्डम, अटो, lkgp (पछिल्लो-पटक-ठीक-रहेको-प्रदायक), कन्टेक्स्ट-अनुकूलित, क्यास-अनुकूलित, **फ्युजन** (मोडेलहरूको प्यानलमा समानान्तर रूपमा अनुरोध पठाउने, त्यसपछि निर्णायकमार्फत एउटै उत्तर संश्लेषण गर्ने), र **पाइपलाइन**। प्रत्येक कम्बोले स्वचालित फलब्याकसहित धेरै मोडेलहरूलाई शृङ्खलाबद्ध गर्छ र द्रुत टेम्प्लेट तथा तत्परता जाँचहरू समावेश गर्छ।

कम्बोमा हालै गरिएका सुधारहरू:

- **संरचित कम्बो बिल्डर** — प्रदायक, मोडेल, र ठ्याक्कै खाता/जडान चयन गरेर प्रत्येक चरण सिर्जना गर्नुहोस्
- **दोहोरिएको प्रदायक समर्थन** — `(provider, model, connection)` ट्युपल अद्वितीय रहेसम्म एउटै कम्बोमा उही प्रदायकलाई धेरैपटक पुनः प्रयोग गर्नुहोस्
- **कम्बो लक्ष्यको स्वास्थ्य** — एनालिटिक्स र स्वास्थ्यसम्बन्धी सतहहरूले अब सबै कुरालाई मोडेल स्ट्रिङमा समेट्नुको सट्टा प्रत्येक कम्बो लक्ष्य/चरणलाई छुट्टाछुट्टै पहिचान गर्छन्
- **कम्पोजिट टियर क्रम** — `defaultTier -> fallbackTier` ले अब शीर्ष-स्तरीय कम्बो चरणहरूको रनटाइम कार्यान्वयन/फलब्याक क्रमलाई प्रभाव पार्छ
- **सिस्टम प्रम्प्ट टेम्प्लेटहरू** — कम्बो `system_message` ले सर्भर-साइड
  `{{MODEL_ID}}`, `{{PROVIDER_ID}}`, `{{ACCOUNT}}` र `{{FINGERPRINT}}`
  प्लेसहोल्डरहरू समर्थन गर्छ, जसलाई पठाउनुभन्दा ठीकअघि वास्तवमै राउट गरिएको लक्ष्यबाट विस्तार गरिन्छ।
  यी अनुमति-सूचीमा आधारित र नन-रिकर्सिभ छन्; अज्ञात प्लेसहोल्डरहरू जस्ताको तस्तै रहन्छन्; खाली मानहरू
  खालीमा विस्तार हुन्छन्; क्लाइन्ट सिस्टम प्रम्प्टहरू कहिल्यै पुनर्लेखन गरिँदैनन्। `{{FINGERPRINT}}`
  पिन गरिएको वा स्वतः-रोटेट गरिएको फिङ्गरप्रिन्ट भएका फिङ्गरप्रिन्ट-आधारित निःशुल्क प्रदायकहरूका लागि मात्र
  समाधान हुन्छ — अन्यत्र यो खालीमा विस्तार हुन्छ (जस्तै
  एकल-फिङ्गरप्रिन्ट जडानहरू, गैर-fp प्रदायकहरू)। विस्तारले
  मानक डिस्प्याच लुप, राउन्ड-रोबिन, र पिन गरिएका कन्टेक्स्ट-क्यास सत्रहरू समेट्छ;
  फ्युजन, केअस, पाइपलाइन र नेस्टेड-एक्जिक्युट रणनीतिहरूले अझै
  प्लेसहोल्डरहरू विस्तार गर्दैनन्।

## 🔧 OAuth Env मर्मत _(v3.6.1+)_

## 🌐 V1 WebSocket ब्रिज _(v3.6.6+)_

OmniRoute ले अब `/v1/ws` अपग्रेड एन्डपोइन्टमार्फत **OpenAI-सङ्गत WebSocket क्लाइन्टहरू** समर्थन गर्छ। अनुकूलित `scripts/dev/v1-ws-bridge.mjs` सर्भरले Next.js लाई र्याप गर्छ र WS जडानहरूलाई पूर्ण द्विदिशात्मक स्ट्रिमिङ सत्रहरूमा अपग्रेड गर्छ। प्रमाणीकरणले HTTP अनुरोधहरूकै समान API कुञ्जी वा सत्र कुकी प्रयोग गर्छ।

## 🔑 सिङ्क टोकनहरू र कन्फिग बन्डल _(v3.6.6+)_

अब **स्कोप गरिएका सिङ्क टोकनहरू** मार्फत बहु-यन्त्र र बाह्य अपरेटर पहुँच सम्भव छ:

- **`POST /api/sync/tokens`** — नयाँ सिङ्क टोकन जारी गर्ने (स्कोप गरिएको, वैकल्पिक म्याद समाप्तिसहित)
- **`DELETE /api/sync/tokens/:id`** — टोकन रद्द गर्ने
- **`GET /api/sync/bundle`** — सबै गैर-संवेदनशील सेटिङहरूको संस्करणयुक्त, ETag-कुञ्जीकृत JSON स्न्यापसट डाउनलोड गर्ने (पासवर्डहरू लुकाइएका)

कन्फिग बन्डल `src/lib/sync/bundle.ts` द्वारा निर्माण गरिन्छ। पूर्ण पेलोड पुनः डाउनलोड नगरी परिवर्तनहरू पत्ता लगाउन उपभोक्ताहरूले `ETag` प्रतिक्रिया हेडर तुलना गर्छन्।

## 🛡️ सुरक्षित आउटबाउन्ड फेच र SSRF गार्ड _(v3.6.6+)_

सबै प्रदायक प्रमाणीकरण र मोडेल खोज कलहरू अब दुई-तहको आउटबाउन्ड गार्डमार्फत जान्छन्:

1. **URL गार्ड** (`src/shared/network/outboundUrlGuard.ts`) — सकेट खोलिनुअघि निजी/लुपब्याक/लिङ्क-लोकल IP दायराहरू रोक्छ।
2. **सुरक्षित फेच र्यापर** (`src/shared/network/safeOutboundFetch.ts`) — URL गार्ड लागू गर्छ, टाइमआउटहरू मानकीकरण गर्छ, र अस्थायी त्रुटिहरूमा एक्स्पोनेन्सियल ब्याकअफसहित पुनः प्रयास गर्छ।

गार्ड उल्लङ्घनहरू HTTP 422 (`URL_GUARD_BLOCKED`) का रूपमा देखिन्छन् र `providerAudit.ts` मार्फत अनुपालन अडिट लगमा लेखिन्छन्।
