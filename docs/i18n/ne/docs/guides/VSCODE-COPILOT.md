**OmniCopilot** ले तपाईंको OmniRoute ले उपलब्ध गराउने प्रत्येक मोडेललाई _नेटिभ_ GitHub Copilot Chat
मोडेल चयनकर्तामा राख्छ। दोस्रो साइडबार वा छुट्टै च्याट UI छैन — Copilot को एजेन्ट मोड, टुल कलिङ,
MCP सर्भरहरू र अनुकूलन निर्देशनहरू सबैले काम गरिरहन्छन्, केवल तपाईंले रोजेको मोडेलमा चल्छन्।

> एम्बेडिङ-आधारित सुविधाहरू प्रदायक API बाहिरै रहन्छन् र तिनका लागि अझै पनि Copilot आवश्यक हुन्छ।

## सेटअप

1. **OmniRoute चलाउनुहोस्** — `npm install -g omniroute && omniroute` (`http://localhost:20128` मा ड्यासबोर्ड)।
2. **एक्सटेन्सन स्थापना गर्नुहोस्** — Extensions दृश्यमा "OmniRoute" खोज्नुहोस्।
3. **मोडेल रोज्नुहोस्** — Copilot Chat → मोडेल चयनकर्ता → **Manage Models…** → **OmniRoute**, त्यसपछि
   आफूले चाहेका विकल्पहरूमा चिनो लगाउनुहोस्।

OmniRoute पूर्वनिर्धारित पोर्टमा चल्दा केही पनि कन्फिगर गर्नु पर्दैन। रिमोट इन्स्ट्यान्सका लागि,
**Activity Bar मा रहेको OmniRoute आइकन** खोल्नुहोस् (वा `OmniRoute: Manage Connection` चलाउनुहोस्) र निम्न सेट गर्नुहोस्:

- **सर्भर URL** — सर्भरको रुट, जस्तै `http://192.168.0.15:20128`। `/v1` प्रत्यय
  एक्सटेन्सनले थप्छ; यसलाई समावेश नगर्नुहोस्।
- **API कुञ्जी** — सर्भरले `REQUIRE_API_KEY` सेट गरेको अवस्थामा मात्र। VS
  Code SecretStorage मार्फत OS कीचेनमा भण्डारण हुन्छ, `settings.json` मा कहिल्यै हुँदैन।

## चयनकर्ताले के देखाउनेछ

एक्सटेन्सनले कच्चा `GET /v1/models` पेलोड देखाउँदैन — यसले त्यसलाई उपयुक्त स्वरूप दिन्छ, र तपाईंले
देख्ने सङ्ख्या दुईवटा जानाजानी राखिएका कारणले क्याटलगको आकारभन्दा कम हुन्छ।

### यसले प्रत्येक मोडेलका लागि एउटा id माग्छ

`MODELS_CATALOG_PREFIX_MODE` को पूर्वनिर्धारित मान **`dual`** हो, जसले प्रत्येक मोडेललाई दुई पटक विज्ञापित गर्छ — एक पटक
छोटो उपनाम प्रिफिक्सअन्तर्गत र अर्को पटक क्यानोनिकल प्रदायक प्रिफिक्सअन्तर्गत — ताकि पुराना क्लाइन्ट
कन्फिगहरूले दुवै स्वरूपलाई रिजोल्भ गर्न सकून्:

```
cc/claude-sonnet-4-6        ← उपनाम प्रिफिक्स
claude/claude-sonnet-4-6    ← क्यानोनिकल प्रिफिक्स, उही मोडेल
```

एक्सटेन्सनले **`GET /v1/models?prefix=alias`** अनुरोध गर्छ, जसले तपाईंका अन्य क्लाइन्टहरूका लागि
सर्भर-व्यापी सेटिङ परिवर्तन नगरी प्रत्येक मोडेलका लागि एउटा id ल्याउँछ। एउटा सन्दर्भ इन्स्ट्यान्समा यसले
**2345 प्रविष्टिहरूलाई 1396 मा घटायो — 949 नक्कल, एउटा पनि मोडेल हराएन।**

यदि तपाईं यसलाई _हरेक_ क्लाइन्टका लागि सर्भर-व्यापी रूपमा समाधान गर्न चाहनुहुन्छ भने, ड्यासबोर्डमा
`MODELS_CATALOG_PREFIX_MODE` फिचर फ्ल्यागलाई `alias` मा सेट गर्नुहोस्। क्वेरी प्यारामिटर र
प्रत्येक मोडको तालिकाका लागि [API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) हेर्नुहोस्।

### यसले च्याट गर्न नसक्ने मोडेलहरू लुकाउँछ

क्याटलगमा छवि, भिडियो, अडियो, रिर्याङ्क, एम्बेडिङ र मोडरेसन मोडेलहरू पनि सूचीबद्ध हुन्छन्। ती
च्याट अनुरोधमा जसरी पनि अस्वीकृत हुन्छन्:

```
HTTP 400 — मोडेल '<id>' छवि-उत्पादन मोडेल हो र यसलाई
/v1/chat/completions मा प्रयोग गर्न सकिँदैन। यसको सट्टा POST /v1/images/generations प्रयोग गर्नुहोस्।
```

त्यसैले चयनकर्तामा पुग्नुअघि तिनीहरूको `type` फिल्डअनुसार तिनलाई फिल्टर गरिन्छ। **Responses-API
मोडेलहरू राखिन्छन्** — प्रत्येक Codex / GPT-5.x प्रविष्टिले `supported_endpoints: ["responses"]`
विज्ञापित गर्छ, र OmniRoute ले तिनलाई `/v1/chat/completions` का लागि अनुवाद गर्छ, त्यसैले ती पूर्ण रूपमा प्रयोगयोग्य छन्।

### तपाईंले कहिल्यै कन्फिगर नगरेका प्रदायकहरू

क्याटलगले **सक्रिय जडान** भएका प्रदायकहरूका मोडेलहरूका साथै प्रत्येक **noAuth**
प्रदायकलाई सूचीबद्ध गर्छ — अर्थात् निःशुल्क टियरको ठूलो हिस्सा बनाउने कुञ्जीविहीन प्रदायकहरू। यो जानाजानी गरिएको हो। तिनलाई लुकाउन,
ड्यासबोर्ड सेटिङमा रहेको `blockedProviders` मा तिनलाई थप्नुहोस्; एक्सटेन्सनमा केही पनि परिवर्तन हुँदैन।

## VS Code ट्याबभित्रको Dashboard

`omnicopilot.dashboardOpen: "editor"` ले OmniRoute dashboard लाई बाह्य ब्राउजरको सट्टा Simple Browser मार्फत editor ट्याबमा रेन्डर गर्छ। Embedding लाई सर्भरमा `DASHBOARD_ALLOW_EMBED=vscode` मार्फत **स्पष्ट रूपमा सक्षम गर्नुपर्छ**, जसले पूर्वनिर्धारित `frame-ancestors 'none'` + `X-Frame-Options: DENY` को सट्टा `frame-ancestors 'self' vscode-webview:` सहित HTML पृष्ठहरू उपलब्ध गराउँछ। API सतह (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) ले दुवै अवस्थामा कडा headers कायम राख्छ।

> ⚠️ **यो build-time flag हो, runtime flag होइन।** Next.js ले `headers()` लाई route manifest मा compile गर्छ, त्यसैले bundle build हुँदा `next.config.mjs` ले variable पढ्छ
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`)।
> पहिले नै build गरिएको सर्भरको अगाडि यसलाई export गर्दा केही परिवर्तन हुँदैन — headers पहिले नै समावेश गरिएका हुन्छन्।

```bash
# variable BUILD command मा उपस्थित हुनुपर्छ
DASHBOARD_ALLOW_EMBED=vscode npm run build        # वा npm run build:release
npm start
```

| तपाईंले कसरी स्थापना गर्नुभयो | के तपाईं embedding सक्षम गर्न सक्नुहुन्छ?                                                                                                   |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| स्रोतबाट                      | ✅ माथि देखाइएअनुसार build command मा variable सेट गर्नुहोस्                                                                                |
| `npm install -g omniroute`    | ❌ प्रकाशित package सँग prebuilt bundle आउँछ — यसको सट्टा स्रोतबाट build गर्नुहोस्                                                          |
| Docker image                  | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — Docker Hub मा रहेको prebuilt image मा embedding सक्षम छैन |

Embedding सक्षम गरिएको build बिना पृष्ठले frame हुन अस्वीकार गर्छ, extension ले response headers बाट त्यो पत्ता लगाउँछ र बाह्य ब्राउजरमा फर्कन्छ — केही पनि बिग्रँदैन, र यसले एकपटक त्यसबारे जानकारी दिन्छ।
[`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) र issue
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273) हेर्नुहोस्।
