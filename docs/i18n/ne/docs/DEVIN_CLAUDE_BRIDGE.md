`devin-cli-agentic` ले वास्तविक Claude Code रनटाइमलाई OmniRoute को स्थानीय Anthropic
Messages एन्डपोइन्ट प्रयोग गर्न दिन्छ, जबकि आधिकारिक Devin CLI ले ACP stdio मार्फत मोडेलका प्रतिक्रियाहरू उपलब्ध गराउँछ। यसले
विद्यमान Anthropic, Claude OAuth, Claude Web, वा `devin-cli` प्रदायकहरू परिमार्जन गर्दैन।

> **हालको स्थिति: Claude Code `2.1.258` मा पिन गरिएको; अफलाइन र लाइभ प्रमाणीकरण अन्तिम पटक
> `2.1.220` मा अभिलेख गरिएको।** `2.1.220` पिनले Devin CLI
> `3000.2.17` र मोडेल `swe-1-7-lightning` मार्फत तीनवटा पृथक् परिदृश्य पूरा गर्यो; उक्त अन्तिम लाइभ रनले क्लाइन्ट-स्वामित्वका `Read`,
> `Edit`, र `Bash` टर्नहरू, सफल `npm test` नतिजाहरू, प्रोजेक्ट कमान्ड र स्किल
> डिस्कभरी, Devin-मात्र राउटिङ, र Claude तर्फ शून्य इग्रेस प्रमाणित गर्यो। त्यसपछि पिनलाई `2.1.258`
> मा बढाइयो (OmniRoute को Claude पहिचानले प्रतिरूपण गर्ने CLI पुस्ता, र
> Fable 5.1 टियर नेटिभ रूपमा समावेश गर्ने पहिलो लाइन)। नयाँ पिनमा पिन गरिएको बेस इमेजमा इन्स्टल तह र `claude --version`
> प्रमाणीकरण गरियो, र ब्रिज युनिट सुइट, `compose config` तथा
> स्थिर आइसोलेसन प्रमाण सफल छन् — तर अफलाइन मक परिदृश्य र लाइभ तीन-परिदृश्य
> सुइट अझै पुनः चलाइएका छैनन्। यो पिनसँग ब्रिजमा निर्भर हुनुअघि तिनलाई पुनः चलाउनुहोस्
> ("पिन गरिएका उपकरणहरू अद्यावधिक गर्ने" हेर्नुहोस्)।

## वास्तुकला

```text
Claude Code 2.1.258 (पृथक् गैर-root Linux कन्टेनर)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-ढाँचा, प्रमाणीकरण-रहित प्रदायक)
  -> devin acp --agent-type summarizer (आधिकारिक ACP stdio, Devin उपकरणहरूबिना)
  -> समर्पित devin-auth भोल्युममा Devin खाता
```

आधिकारिक CLI को पूर्वनिर्धारित ACP एजेन्टले आफ्नै उपकरणहरू कार्यान्वयन गर्न सक्छ, त्यसैले यो ब्रिजले
त्यसलाई प्रयोग गर्दैन। यसले कुनै उपकरण नभएको आधिकारिक CLI मोडको निश्चित `summarizer` ACP एजेन्ट सुरु गर्छ, र
क्रमबद्ध गरिएको Anthropic अनुरोधलाई कार्यान्वयन ट्रेसका रूपमा फ्रेम गर्छ। Claude-स्वामित्वको अर्को
कार्य आवश्यक हुँदा, प्रतिक्रियामा ठ्याक्कै एउटा क्लाइन्ट उपकरण एनभेलप हुनुपर्छ। कुनै पनि ACP
`tool_call` वा `tool_call_update` लाई प्रतिक्रिया सफल भएको रूपमा रिपोर्ट गर्नुअघि अस्वीकार गरिन्छ।

`open-sse/executors/devin-agentic/serializer.ts` मा रहेको सिरियलाइजरले `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice`, र
Claude Code द्वारा उपलब्ध गराइएका उपकरणहरू जोगाउँछ। इमेजहरू र अज्ञात ब्लकहरू स्पष्ट रूपमा विफल हुन्छन्। ठूला उपकरण नतिजाहरूले
देखिने ट्रन्केसन मार्कर प्रयोग गर्छन्।

पार्सरले प्रत्येक मोडेल टर्नमा एउटा स्वतन्त्र `<tool>{...}</tool>` एनभेलप स्वीकार गर्छ। यसले
नामलाई अनुरोधको उपकरण सूचीसँग जाँच गर्छ, त्यस उपकरणको JSON
Schema विरुद्ध आर्गुमेन्टहरू प्रमाणीकरण गर्छ, मिश्रित वर्णन/कार्यहरू अस्वीकार गर्छ, र एउटा सीमित मर्मत प्रयासलाई अनुमति दिन्छ। त्यसपछि Claude Code ले
नतिजास्वरूप प्राप्त Anthropic `tool_use` लाई स्थानीय रूपमा कार्यान्वयन गर्छ र `tool_result` लाई
OmniRoute मार्फत फिर्ता पठाउँछ।

## आइसोलेसन र खतरा मोडेल

होस्टको Claude स्थापना, खाता, र कन्फिगरेसन दायराबाहिर छन् र निषेधित मानिन्छन्।
Compose सेवाहरूले:

- UID/GID `10001:10001` का रूपमा, पढ्न-मात्र मिल्ने रुट फाइलसिस्टम, हटाइएका क्षमताहरू, र
  `no-new-privileges` सहित चल्छन्;
- निजी `/home/bridge`, समर्पित Claude कन्फिग भोल्युम, पृथक् OmniRoute डेटा,
  र छुट्टै `devin-auth` भोल्युम प्रयोग गर्छन्;
- डिस्पोजेबल `.sandbox` कार्यस्थान/प्रमाण मात्र माउन्ट गर्छन्;
- होस्ट होम, Keychain, SSH, क्लाउड क्रेडेन्सियलहरू, वा Docker सकेट माउन्ट गर्दैनन्;
- स्पष्ट वातावरणहरू निर्माण गर्छन् र Anthropic API/OAuth/राउटिङ भेरिएबलहरू हटाउँछन्;
- स्थानीय-मात्र कुञ्जीसहित Claude Code इन्फरेन्सलाई `http://omniroute:20128` मा मात्र निर्देशित गर्छन्।

अफलाइन प्रोफाइलले आन्तरिक नेटवर्क प्रयोग गर्छ। लाइभ प्रोफाइलमा, OmniRoute ले
`network-guard` मार्फत मात्र आधिकारिक Devin एन्डपोइन्टहरूमा पहुँच गर्छ; असम्बन्धित गन्तव्यहरू अस्वीकार गरिन्छन्।
Claude Code सँग छुट्टै सबै इग्रेस अस्वीकार गर्ने गार्ड छ र `NO_PROXY` मार्फत स्थानीय OmniRoute
सेवामा मात्र पहुँच गर्न सक्छ। गार्ड अडिट फाइलहरू तिनका सम्बन्धित गार्ड प्रक्रियाद्वारा मात्र माउन्ट गरिन्छन्। स्क्रिप्टहरूले
टोकन-रहित प्रमाण निर्यात गर्नुअघि फाइल स्वामित्व, मोड, लिङ्क सङ्ख्या, र प्रत्येक निर्णय प्रमाणीकरण गर्छन्।

आइसोलेसन प्रमाणलाई स्वतन्त्र रूपमा चलाउनुहोस्:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

यसले टोपोलोजी, नामयुक्त माउन्टहरू, गैर-root/पढ्न-मात्र सेटिङहरू, स्पष्ट स्थानीय राउटिङ,
संवेदनशील वातावरण भेरिएबलहरूको अनुपस्थिति, Docker सकेटको अनुपस्थिति,
`api.anthropic.com` र `claude.ai` मा रोकिएको पहुँच, Devin-मात्र प्रदायक चयन, र
ACP ब्याकएन्ड अनुपलब्ध हुँदा स्पष्ट विफलता प्रमाणीकरण गर्छ।

## पहिलो पटकको सेटअप र सामान्य प्रयोग

पिन गरिएको इमेज बिल्ड गर्नुहोस्:

```bash
./scripts/devin-bridge/build
```

पृथक गरिएको Devin भोल्युमलाई मात्र प्रमाणीकरण गर्नुहोस्:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

लगइन कमाण्डले रिमोट/कन्टेनर वातावरणका लागि बनाइएको आधिकारिक म्यानुअल-टोकन प्रवाह प्रयोग गर्छ। मान सिधै CLI प्रम्प्टमा प्रविष्ट गरिन्छ; यसलाई प्रक्रिया आर्गुमेन्टका रूपमा पठाइँदैन, Git मा लेखिँदैन वा होस्टबाट प्रतिलिपि गरिँदैन।

पृथक गरिएको Claude Code रनटाइम सुरु गर्नुहोस्:

```bash
./scripts/devin-bridge/launch
```

`launch` ले कन्टेनराइज गरिएको Claude Code सुरु गर्नुअघि पृथकीकरण, Devin प्रमाणीकरण र मोडेल पहिचानलाई पुनः जाँच गर्छ। यसले होस्टको Claude एक्जिक्युटेबल कहिल्यै चलाउँदैन। मोडेल एलियासहरू `.env.devin-bridge` मा सेट गर्न सकिन्छ; कन्फिगर गरिएको प्रत्येक मानले `devin-cli-agentic/` उपसर्ग कायम राख्नुपर्छ।

## प्रमाणीकरण कमाण्डहरू

पुनरुत्पादनयोग्य अफलाइन मार्गलाई Devin खाता आवश्यक पर्दैन र यसमा रनटाइम इन्टरनेट हुँदैन:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

प्रमाणीकृत, अप्ट-इन लाइभ मार्ग यस्तो छ:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

लाइभ रनरले ACP सत्रहरू एकैचोटि खोलिनबाट जोगाउन परिदृश्यहरूबीच प्रतीक्षा गर्छ र पाठ्य दाबीहरूमा विश्वास गर्नुको सट्टा संरचित Claude स्ट्रिम इभेन्टहरू प्रमाणीकरण गर्छ। यसका तीन परिदृश्यले निम्न कुरा प्रमाणित गर्छन्:

1. प्रत्यक्ष प्रोजेक्ट रिडहरू र त्रुटि विश्लेषण;
2. वास्तविक `Edit`, क्लाइन्ट-स्वामित्वको `Bash` `npm test` र टर्मिनल परिणाम;
3. `/bridge-check` सहित `bridge-proof` पहिचान, प्रोजेक्ट रिडहरू, अर्को सफल क्लाइन्ट-स्वामित्वको `npm test` र कुनै बाँकी कामबिना समापन।

अन्तिम गेटले Devin नेटवर्क अडिट पनि जाँच गर्छ र Claude इग्रेस अडिट खाली नै रहनुपर्ने आवश्यकता राख्छ।

## पिन गरिएका उपकरणहरू अद्यावधिक गर्ने

इमेजले Node, Claude Code र Devin CLI लाई `docker/devin-bridge/Dockerfile` मा पिन गर्छ। अद्यावधिक गर्न:

1. स्पष्ट रूपमा तोकिएका संस्करणहरू परिवर्तन गर्नुहोस्;
2. दुवै आर्किटेक्चर-विशिष्ट Devin आर्काइभ चेकसमलाई आधिकारिक आर्टिफ्याक्टका मानहरूले प्रतिस्थापन गर्नुहोस्;
3. पुनः बिल्ड गर्नुहोस् र प्रत्येक अफलाइन प्रमाणीकरण कमाण्ड चलाउनुहोस्;
4. इमेजभित्रका संस्करणहरू पुष्टि गर्नुहोस्;
5. प्रमाणीकृत तीन-परिदृश्य लाइभ सुइट पुनः चलाउनुहोस्।

कुनै पनि CLI लाई होस्टमा ग्लोबल रूपमा इन्स्टल नगर्नुहोस् वा चेकसम प्रमाणीकरणलाई अप्रमाणित डाउनलोडले प्रतिस्थापन नगर्नुहोस्।

## निदान र सफाइ

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  ले स्थानीय राउटिङ र संवेदनशील विवरण हटाइएका एक्जिक्युटर त्रुटिहरू देखाउँछ।
- `.sandbox/evidence/mock-acp.jsonl` ले निर्धारणयोग्य मक ACP कार्यहरू रेकर्ड गर्छ।
- `.sandbox/evidence/claude-stream.jsonl` ले वास्तविक Claude Code अफलाइन रन रेकर्ड गर्छ।
- `.sandbox/evidence/live-*.jsonl` ले प्रमाणीकरण गरिएका तीन लाइभ स्ट्रिमहरू रेकर्ड गर्छ।
- `.sandbox/evidence/egress.jsonl` र `.sandbox/evidence/claude-egress.jsonl` गार्ड अडिटका प्रमाणीकरण गरिएका, टोकन-रहित प्रतिलिपिहरू हुन्।

लगइन/कन्फिग भोल्युमहरू सुरक्षित राख्दै स्वामित्वमा रहेका कन्टेनर र नेटवर्कहरू रोक्नुहोस्:

```bash
./scripts/devin-bridge/clean
```

नेम्ड भोल्युमहरूसहित ब्रिजको स्वामित्वमा रहेको सम्पूर्ण वातावरण हटाउनुहोस्:

```bash
./scripts/devin-bridge/clean --all
```

## सीमाहरू

- ब्रिज निश्चित no-tools `summarizer` भूमिकामा निर्भर हुन्छ, किनभने Devin CLI `3000.2.17` ले तटस्थ no-tools ACP एजेन्ट उपलब्ध गराउँदैन। एडाप्टरले सारांश-जस्ता मध्यवर्ती प्रतिक्रियाहरूको क्षतिपूर्ति गर्छ, तर एक पटकको सीमित सुधार अझै पनि स्पष्ट रूपमा असफल हुन सक्छ।
- प्रत्यक्ष ACP कलहरूले क्षणिक `502`/`504` प्रतिक्रियाहरू फर्काउन सक्छन्। हार्नेसले परिदृश्यहरूबीच समय अन्तर राख्छ; निरन्तर असफलता fail-closed नै रहन्छ र कहिल्यै अर्को प्रदायक चयन गर्दैन।
- प्रत्येक Anthropic अनुरोधबाट ACP सन्दर्भ पुनर्निर्माण गरिन्छ; कुनै प्रक्रिया/सत्र आबद्धता हुँदैन।
- प्रत्येक मोडेल प्रतिक्रियामा एउटा उपकरण कल समर्थित छ; समानान्तर कलहरू अस्वीकृत हुन्छन्।
- छविहरू स्पष्ट रूपमा असमर्थित छन्। भिजन, सोच आउटपुट, प्रयास नियन्त्रणहरू, र 1M सन्दर्भ विन्डोको घोषणा गरिँदैन।
- SSE ले मान्य Anthropic जीवनचक्र घटनाहरू प्रयोग गर्छ, तर सीमित ACP टर्न सङ्कलन भएपछि मात्र उत्सर्जित हुन्छ; ACP खण्डहरू क्रमिक रूपमा फर्वार्ड गरिँदैनन्।
