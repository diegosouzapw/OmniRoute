1. अवस्थित एकल-कुञ्जी semaphore अनुबन्ध र नयाँ atomic बहु-कुञ्जी अनुबन्धलाई केन्द्रित परीक्षणहरूद्वारा सुनिश्चित गर्नुहोस्: आंशिक reservation नहुने, FIFO queueing, abort, timeout, queue-full, idempotent release, stats, र cleanup।
2. अवस्थित account semaphore लाई सोही स्थानमा सामान्यीकृत गर्नुहोस्। `acquire()` लाई `acquireMany()` वरिपरिको compatibility wrapper का रूपमा कायम राख्नुहोस्; दोस्रो scheduler वा dependency नथप्नुहोस्।
3. `chatCore` मा account-मात्र acquisition लाई `withRateLimit` भन्दा ठीकअघि गरिने एउटा cumulative global/provider/account acquisition ले प्रतिस्थापन गर्नुहोस्। account rotation ले connection परिवर्तन गर्दा हरेकपटक सम्पूर्ण set पुनः acquire गर्नुहोस्, र streaming पूरा नहुँदासम्म release कायम राख्नुहोस्।
4. अवस्थित resilience settings pipeline (types, defaults, normalization, schema, API response, UI, र translations) लाई global र provider caps सहित विस्तार गर्नुहोस्। पुरानो Bottleneck concurrency control लाई connection/quota-scope concurrency का रूपमा पुनः label गर्नुहोस्, ताकि यसको वास्तविक scope स्पष्ट होस्।
5. केन्द्रित परीक्षणहरू, lint, typecheck, static checks, र पूर्ण test suite चलाउनुहोस्; behavioral change लाई changelog मा अभिलेख गर्नुहोस्।

जानाजानी यथावत् राखिएका व्यवहारहरू: zero/null concurrency ले gate लाई bypass गर्छ, account-मात्र callers ले `acquire()` प्रयोग गरिरहन्छन्, blocked-account controls ले आफ्नो key format र API कायम राख्छन्, र provider rate-limit queue को व्यवहार अपरिवर्तित रहन्छ।
