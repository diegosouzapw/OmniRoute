Cloudflare मार्फत व्यवस्थापन गरिएको डोमेनसहित VM (VPS) मा OmniRoute स्थापना र कन्फिगर गर्ने पूर्ण मार्गदर्शिका।

---

## पूर्वापेक्षाहरू

| वस्तु      | न्यूनतम                    | सिफारिस गरिएको   |
| ---------- | -------------------------- | ---------------- |
| **CPU**    | 1 vCPU                     | 2 vCPU           |
| **RAM**    | 1 GB                       | 2 GB             |
| **डिस्क**  | 10 GB SSD                  | 25 GB SSD        |
| **OS**     | Ubuntu 22.04 LTS           | Ubuntu 24.04 LTS |
| **डोमेन**  | Cloudflare मा दर्ता गरिएको | —                |
| **Docker** | Docker Engine 24+          | Docker 27+       |

**परीक्षण गरिएका प्रदायकहरू**: Akamai (Linode), DigitalOcean, Vultr, Hetzner, AWS Lightsail।

## 1. VM कन्फिगर गर्नुहोस्

### 1.1 इन्स्टेन्स सिर्जना गर्नुहोस्

आफूले रुचाएको VPS प्रदायकमा:

- Ubuntu 24.04 LTS छनोट गर्नुहोस्
- न्यूनतम योजना (1 vCPU / 1 GB RAM) छनोट गर्नुहोस्
- बलियो root पासवर्ड सेट गर्नुहोस् वा SSH key कन्फिगर गर्नुहोस्
- **सार्वजनिक IP** टिपोट गर्नुहोस् (उदाहरणका लागि, `203.0.113.10`)

### 1.2 SSH मार्फत जडान गर्नुहोस्

```bash
ssh root@203.0.113.10
```

### 1.3 प्रणाली अद्यावधिक गर्नुहोस्

```bash
apt update && apt upgrade -y
```

### 1.4 Docker स्थापना गर्नुहोस्

```bash
# निर्भरताहरू स्थापना गर्नुहोस्
apt install -y ca-certificates curl gnupg

# आधिकारिक Docker रिपोजिटरी थप्नुहोस्
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
chmod a+r /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $ (. /etc/os-release && echo "$VERSION_CODENAME") stable" | tee /etc/apt/sources.list.d/docker.list > /dev/null
apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

### 1.5 nginx स्थापना गर्नुहोस्

```bash
apt install -y nginx
```

### 1.6 फायरवाल (UFW) कन्फिगर गर्नुहोस्

```bash
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp    # SSH
ufw allow 80/tcp    # HTTP (रिडाइरेक्ट)
ufw allow 443/tcp   # HTTPS
ufw enable
```

> **सुझाव**: अधिकतम सुरक्षाका लागि, पोर्ट 80 र 443 लाई Cloudflare IP हरूमा मात्र सीमित गर्नुहोस्। [उन्नत सुरक्षा](#advanced-security) खण्ड हेर्नुहोस्।

## 2. OmniRoute स्थापना गर्नुहोस्

### 2.1 कन्फिगरेसन डाइरेक्टरी सिर्जना गर्नुहोस्

```bash
mkdir -p /opt/omniroute
```

### 2.2 वातावरणीय चरहरूको फाइल सिर्जना गर्नुहोस्

```bash
cat > /opt/omniroute/.env << 'EOF'
# === सुरक्षा ===
JWT_SECRET=CHANGE-TO-A-UNIQUE-64-CHAR-SECRET-KEY
INITIAL_PASSWORD=YourSecurePassword123!
API_KEY_SECRET=REPLACE-WITH-ANOTHER-SECRET-KEY
STORAGE_ENCRYPTION_KEY=REPLACE-WITH-THIRD-SECRET-KEY
STORAGE_ENCRYPTION_KEY_VERSION=v1
MACHINE_ID_SALT=CHANGE-TO-A-UNIQUE-SALT
OMNIROUTE_WS_BRIDGE_SECRET=REPLACE-WITH-WS-BRIDGE-SECRET  # उत्पादनमा आवश्यक: Codex Responses WS bridge द्वारा प्रयोग गरिन्छ

# === एप ===
PORT=20128
NODE_ENV=production
HOSTNAME=0.0.0.0
DATA_DIR=/app/data
APP_LOG_TO_FILE=true
AUTH_COOKIE_SECURE=true
REQUIRE_API_KEY=false

# === URL हरू (आफ्नो डोमेनमा परिवर्तन गर्नुहोस्) ===
# निर्धारित कार्यहरू / स्व-पुनःप्राप्तिहरूका लागि आन्तरिक सर्भर-देखि-सर्भर आधार URL।
BASE_URL=http://127.0.0.1:20128
# OAuth कलब्याकहरू, ड्यासबोर्ड लिङ्कहरू र उत्पन्न सार्वजनिक URL हरूका लागि प्रयोग गरिने ब्राउजर-सामुन्नेको URL।
NEXT_PUBLIC_BASE_URL=https://llms.seudominio.com
# उत्पन्न सार्वजनिक एसेट URL हरूका लागि वैकल्पिक स्पष्ट सार्वजनिक ओरिजिन ओभरराइड।
# OMNIROUTE_PUBLIC_BASE_URL=https://llms.seudominio.com

# === क्लाउड सिंक (वैकल्पिक) ===
# CLOUD_URL=https://cloud.omniroute.online
# NEXT_PUBLIC_CLOUD_URL=https://cloud.omniroute.online
EOF
```

> ⚠️ **महत्त्वपूर्ण**: अद्वितीय गोप्य कुञ्जीहरू उत्पन्न गर्नुहोस्! प्रत्येक कुञ्जीका लागि `openssl rand -hex 32` प्रयोग गर्नुहोस्।

### 2.3 कन्टेनर सुरु गर्नुहोस्

```bash
docker pull diegosouzapw/omniroute:latest

docker run -d \
  --name omniroute \
  --restart unless-stopped \
  --env-file /opt/omniroute/.env \
  -p 20128:20128 \
  -v omniroute-data:/app/data \
  diegosouzapw/omniroute:latest
```

### 2.4 यो चलिरहेको छ भनी प्रमाणित गर्नुहोस्

```bash
docker ps | grep omniroute
docker logs omniroute --tail 20
```

यसले `[DB] SQLite database ready` र `listening on port 20128` प्रदर्शन गर्नुपर्छ।

## 3. nginx कन्फिगर गर्नुहोस् (रिभर्स प्रोक्सी)

### 3.1 SSL प्रमाणपत्र उत्पन्न गर्नुहोस् (Cloudflare Origin)

Cloudflare ड्यासबोर्डमा:

1. **SSL/TLS → Origin Server** मा जानुहोस्
2. **Create Certificate** मा क्लिक गर्नुहोस्
3. पूर्वनिर्धारित सेटिङहरू (15 वर्ष, \*.yourdomain.com) यथावत् राख्नुहोस्
4. **Origin Certificate** र **Private Key** प्रतिलिपि गर्नुहोस्

```bash
mkdir -p /etc/nginx/ssl

# प्रमाणपत्र टाँस्नुहोस्
nano /etc/nginx/ssl/origin.crt

# निजी कुञ्जी टाँस्नुहोस्
nano /etc/nginx/ssl/origin.key

chmod 600 /etc/nginx/ssl/origin.key
```

### 3.2 Nginx कन्फिगरेसन

```bash
cat > /etc/nginx/sites-available/omniroute << 'NGINX'
# पूर्वनिर्धारित सर्भर — IP मार्फत हुने प्रत्यक्ष पहुँच रोक्छ
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    listen 443 ssl default_server;
    listen [::]:443 ssl default_server;
    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    server_name _;
    return 444;
}

# OmniRoute — HTTPS
server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name llms.yourdomain.com;  # आफ्नो डोमेनमा परिवर्तन गर्नुहोस्

    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    client_max_body_size 100M;

    location / {
        proxy_pass http://127.0.0.1:20128;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket समर्थन
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # SSE (सर्भरद्वारा पठाइने इभेन्टहरू) — स्ट्रिमिङ AI प्रतिक्रियाहरू
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }
}

# HTTP → HTTPS पुनर्निर्देशन
server {
    listen 80;
    listen [::]:80;
    server_name llms.yourdomain.com;
    return 301 https://$server_name$request_uri;
}
NGINX
```

रिभर्स-प्रोक्सी स्ट्रिम टाइमआउटहरूलाई आफ्ना OmniRoute टाइमआउट env vars सँग मिलाएर राख्नुहोस्। यदि तपाईंले
`FETCH_TIMEOUT_MS` / `STREAM_IDLE_TIMEOUT_MS` बढाउनुभयो भने, `proxy_read_timeout` / `proxy_send_timeout`
लाई पनि सोही सीमाभन्दा माथि बढाउनुहोस्।

OmniRoute ले OAuth कलब्याकहरू र उत्पन्न गरिएका सार्वजनिक लिङ्कहरूका लागि ब्राउजरले देख्ने मानक origin का रूपमा `NEXT_PUBLIC_BASE_URL` प्रयोग गर्छ।
प्रमाणीकरण गरिएका ड्यासबोर्ड लेखनहरूले session-bound CSRF सुरक्षासहित same-origin अनुरोधहरू प्रयोग गर्छन्,
त्यसैले तिनलाई स्थिर सार्वजनिक base URL आवश्यक पर्दैन। माथिका
`X-Forwarded-*` हेडरहरू अझै पनि उपयोगी राउटिङ मेटाडेटा हुन्, तर OAuth वा उत्पन्न गरिएका ब्राउजर लिङ्कहरूलाई आवश्यक पर्दा
तिनीहरू स्पष्ट सार्वजनिक URL सेट गर्नुको विकल्प होइनन्। OmniRoute लाई क्लाइन्टहरूले प्रत्यक्ष रूपमा पहुँच गर्न नसक्ने र तपाईंको प्रोक्सीले
आगमन forwarded हेडरहरू हटाएर/पुनर्निर्माण गर्ने अवस्थामा मात्र `OMNIROUTE_TRUST_PROXY` सक्षम गर्नुहोस्।

### 3.3 सक्षम पार्नुहोस् र परीक्षण गर्नुहोस्

## न्यून-मेमोरी / सानो VPS अनुकूलन

साना VPS इन्स्ट्यान्सहरूमा (1 GB RAM वा कम) डिप्लोय गर्दा:

- **पृष्ठभूमि सेवाहरू निष्क्रिय गर्नुहोस्** — scheduler, MCP server, र आवधिक मर्मत कार्यहरू छोड्न `OMNIROUTE_DISABLE_BACKGROUND_SERVICES=1` सेट गर्नुहोस्। `docs/reference/ENVIRONMENT.md` हेर्नुहोस्।
- **SQLite WAL मोड प्रयोग गर्नुहोस्** — यो पूर्वनिर्धारित रूपमा सक्षम हुन्छ र समवर्ती रिडहरूका क्रममा अधिकतम मेमोरी खपत घटाउँछ।
- **V8 heap मा सीमा लगाउनुहोस्** — runtime ले VM भन्दा ठूलो सीमा क्यालिब्रेट नगरोस् भनेर `OMNIROUTE_MEMORY_MB` (जस्तै `512`) सेट गर्नुहोस्। `docs/reference/ENVIRONMENT.md` हेर्नुहोस्।
- **हेभीवेट एडमिसन heap सीमाअनुसार स्वतः स्केल हुन्छ** -- माथि `OMNIROUTE_MEMORY_MB` सेट गरेपछि, ingest byte बजेट (`OMNIROUTE_CHAT_MAX_INFLIGHT_BYTES`) त्यही सीमाबाट स्वतः निर्धारित हुन्छ, त्यसैले मेमोरी-सीमित VM ले कुनै अतिरिक्त ट्युनिङबिना नै सानो समवर्ती-अनुरोध बजेट पाउँछ; अतिरिक्त अनुरोधहरूले मेमोरीका लागि प्रतिस्पर्धा गर्नुको सट्टा `Retry-After` सहित पुनः प्रयास गर्न मिल्ने `503` प्राप्त गर्छन्। त्यसमाथि पनि अनुरोध सङ्ख्याको कडा सीमा आवश्यक भएमा मात्र पुरानो `OMNIROUTE_CHAT_MAX_HEAVY_IN_FLIGHT` request-count सीमा सेट गर्नुहोस्।
- **VPS मा `next build` नगर्नुहोस्** — स्थानीय रूपमा build गर्नुहोस् र standalone output (`.next/standalone/`) डिप्लोय गर्नुहोस्।
- **`top` / `free -m` मार्फत निगरानी गर्नुहोस्** — 1 GB VM मा निष्क्रिय अवस्थामा OmniRoute ले सामान्यतया 200-400 MB RSS प्रयोग गर्छ।
