Itinatala ng dokumentong ito ang desisyon sa pagpapatupad para sa
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854). Kinakatawan ang mga pampublikong produkto
bilang apat na pamilya ng provider. Ang rehiyon ay datos ng koneksyon, hindi isang hiwalay na produkto.

## Desisyon

| Pamilya ng provider                                 | OmniRoute ID            | Pandaigdigang rehiyon | Rehiyon ng China |
| --------------------------------------------------- | ----------------------- | --------------------- | ---------------- |
| Alibaba Cloud Model Studio (bayad ayon sa paggamit) | `alibaba`               | Singapore             | Beijing          |
| Alibaba Cloud Token Plan                            | `bailian-coding-plan`   | Singapore             | Beijing          |
| Qwen Cloud (bayad ayon sa paggamit)                 | `qwen-cloud`            | Global                | Beijing          |
| Qwen Cloud Token Plan                               | `qwen-cloud-token-plan` | Singapore             | Beijing          |

Mananatiling runtime compatibility alias ang kasalukuyang `alibaba-cn` ID para sa mga naka-save na koneksyon, ruta ng modelo,
combo, at dating paggamit. Isinasama ang dashboard card nito sa `alibaba`; walang kinakailangang
muling pagsulat sa database.

Kasalukuyang gumagamit ang pay-as-you-go ng Qwen Cloud at Alibaba Cloud Model Studio ng parehong mga runtime host
na compatible sa DashScope, ngunit nananatili silang magkahiwalay na pagkakakilanlan ng provider dahil kumukuha ang mga user ng mga key at namamahala
ng mga account sa pamamagitan ng magkaibang interface ng produkto. Gumagamit ang mga produktong Alibaba at Qwen Cloud Token Plan ng
magkakaibang pamilya ng endpoint, kaya nananatiling magkakahiwalay na provider ID ang lahat ng apat na produkto.

## Matrix ng endpoint

| Pamilya ng provider     | `global-sg`                                                              | `china-beijing`                                                      | Format ng wire |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | -------------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI         |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic      |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI         |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI         |

Dapat nabibilang sa iisang produkto at rehiyon ang API key at endpoint. Kapag pumili ng rehiyon,
nagbabago ang preset na endpoint na ginagamit sa validation at mga karaniwang kahilingan.

## Kontrata ng koneksyon

Iniimbak ng mga bagong koneksyon ang stable na region key sa `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

Ang mga pinapayagang value ay `global-sg` at `china-beijing`. Sentral na kinukuha ang endpoint mula sa
provider ID at rehiyon. Ang hindi preset na `providerSpecificData.baseUrl` ay nananatiling tahasang
override ng operator at ito ang inuuna, habang muling ino-normalize sa panrehiyong
matrix ang mga lumang naka-save na preset URL.

Pinapanatili nitong extensible ang schema ng koneksyon: maaaring magdagdag ng isa pang rehiyon sa resolver nang hindi
gumagawa ng panibagong provider card o binabago ang mga naka-save na provider ID.

## Compatibility at rollout

1. Idagdag ang panrehiyong endpoint resolver at panatilihin ang kasalukuyang mga pandaigdigang default.
2. Gamitin ang live na panrehiyong DashScope `/models` discovery para sa `alibaba`, sa compatibility
   ID nitong `alibaba-cn`, at sa `qwen-cloud`. Daraan muna ang kanilang mga tugon sa isang filter
   para sa text generation dahil nagbabalik din ang generic na endpoint ng mga modelo para sa image,
   video, audio, embedding, at iba pang hindi pang-chat. Pagkatapos, ilalapat ng `qwen-cloud` ang
   pinananatiling allowlist na idineklara sa provider registry nito. Pinananatili ng Alibaba Model
   Studio at Qwen Cloud ang magkahiwalay na mga curated catalog kahit kasalukuyan silang gumagamit
   ng parehong mga runtime host.
3. Irehistro ang `qwen-cloud-token-plan` gamit ang kasalukuyang allowlist ng mga text model ng Token Plan.
4. Magdagdag ng typed na selector ng rehiyon sa mga dialog para sa pagdagdag/pag-edit ng koneksyon.
5. Itago ang duplicate na `alibaba-cn` card at isama ang mga umiiral na koneksyon nito sa provider
   page ng `alibaba`.
6. Panatilihing available ang mga custom endpoint override para sa mga advanced at deployment na
   partikular sa workspace.

Nananatili sa labas ng chat catalog ang mga media model ng Token Plan dahil gumagamit ang mga ito
ng mga nakalaang endpoint. Nakarehistro ang `wan2.7-image` at `wan2.7-image-pro` sa
`open-sse/config/imageRegistry.ts`; nakarehistro naman ang `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, at `happyhorse-1.1-r2v` sa
`open-sse/config/videoRegistry.ts`. Muling ginagamit ng dalawang registry ang identity ng
koneksyong `qwen-cloud-token-plan` at ang mga kredensyal nitong partikular sa rehiyon.

May magkahiwalay na pay-as-you-go na image at video catalog ang regular na Qwen Cloud sa ilalim ng
identity na `qwen-cloud`. Ang mga image model nito ay `wan2.7-image-pro`, `wan2.7-image`,
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03`, at
`z-image-turbo`. Ang mga video model nito ay `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`,
`happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`,
`wan2.7-r2v-2026-06-12`, at `wan2.7-videoedit`. Muling ginagamit lamang ng mga modelong ito ang
regular na koneksyong `qwen-cloud` at ang panrehiyong DashScope media endpoint. Hindi nagmamana o
nagsasama ng mga listahan ng modelo ng isa't isa ang mga registry ng Token Plan at pay-as-you-go.

May sarili ring mga media allowlist ang identity na `bailian-coding-plan`:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0`, at `qwen-image-2.0-pro` para sa pagbuo ng
image, at
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, at `happyhorse-1.1-r2v` para sa pagbuo ng
video. Ginagamit lamang nito ang koneksyon ng Bailian Coding Plan at ang panrehiyong Coding Plan
endpoint. Hindi nagmamana mula sa o nagsasama sa alinmang Qwen Cloud provider ang mga image at video
registry nito.

May magkahiwalay na mga image at video allowlist ang regular na identity na `alibaba`. Ang mga image
model nito ay `qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo`, at `wan2.6-t2i`. Ang mga idinagdag na video model nito ay `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12`, at `wan2.7-videoedit`. Ginagamit lamang ng mga modelong ito ang koneksyon
ng Alibaba Model Studio at ang napili nitong panrehiyong media endpoint; hindi idinaragdag ang mga
ito sa anumang Coding Plan o Qwen Cloud registry.

Sinusunod ng chat catalog ng Qwen Cloud Token Plan ang exact-string na text allowlist ng Individual
plan: `qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2`, at
`deepseek-v4-pro`. Nabibilang ang mga Wan at HappyHorse entry sa magkahiwalay na API para sa pagbuo
ng image/video.

Inilalantad ng Alibaba Token Plan ang parehong anim na kasalukuyang text-generation model ID sa
pamamagitan ng endpoint nitong compatible sa Anthropic. Iniimbak ng opsyon nitong Singapore ang
umiiral na region key na `global-sg`; ang label lamang na nakikita ng user ang naiiba sa mga provider
family na tumatawag sa rehiyon bilang Global.

Sadyang mas limitado ang regular na chat catalog ng Qwen Cloud kaysa sa buong live na text response.
Matatagpuan ang pinananatili nitong allowlist sa
`open-sse/config/providers/registry/qwen-cloud/index.ts`; nagbabalik lamang ang live discovery ng
mga ID na kapwa nasa upstream response at nasa listahan ng registry na iyon.

Sinusunod ng Alibaba Model Studio ang parehong panuntunan ng live intersection gamit ang hiwalay
nitong pinananatiling allowlist sa `open-sse/config/providers/registry/alibaba/index.ts`. Muling
ginagamit ng compatibility provider na `alibaba-cn` ang catalog na iyon habang nire-resolve ang
discovery laban sa Beijing endpoint.
