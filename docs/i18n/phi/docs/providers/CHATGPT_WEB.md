Ang `chatgpt-web-codex` (alias na `cgpt-codex`) ay nag-uugnay sa mga turn ng Codex Responses sa pamamagitan ng isang
authenticated na browser session ng ChatGPT. Hiwalay ito sa inalis nang common
na provider na `chatgpt-web` at ginagamit nito ang implementasyong may abiso ng MIT sa ilalim ng
`open-sse/vendor/codex-chatgpt-web/`, na na-refresh sa pamamagitan ng upstream v4.0.7 commit na
`b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494`.

## Pag-aalis sa common provider

Hindi na kasama ang mga dating common provider ID na `chatgpt-web` at `cgpt-web` dahil hindi
mapatunayan ang pinagmulan ng kanilang implementasyon ng pre-key/proof-of-work. Ang mga tahasang
kahilingan sa alinmang ID, kabilang ang mga model ID na may slash prefix at mga naka-save na alias, ay
ligtas na nabibigo nang may HTTP `410` at code na **PROVIDER_RETIRED** bago ang anumang upstream na kahilingan.

Minamarkahan ng migration na `168_retire_chatgpt_web.sql` bilang tombstone ang mga katugmang koneksyon ng provider at
pinapawalang-bisa ang kanilang mga aktibong session lease. Pinapanatili nito ang kasaysayan ng koneksyon at mga allowlist ng API key;
hindi ito nagdaragdag ng kapalit na access sa isang allowlist. Hindi saklaw ng pag-aalis na ito ang Codex provider at
ang mga koneksyon nito.

## Mga kinakailangan

- isang kumpletong Cookie header mula sa isang naka-sign in na ChatGPT session;
- Chrome o Chromium kasama ang isang graphical session o Xvfb display para sa mga installation ng npm, systemd, at PM2;
- gamit ang Docker `web` profile, ang internal na Chromium service mula sa
  `docker-compose.yml`;
- OpenAI `tunnel-client` v0.0.13 at isang custom connector ng ChatGPT para sa mga lokal na Codex tool.

Kailangan lamang ang tunnel para sa mga turn na gumagamit ng tool. Magagamit ng bawat nakalistang route, kabilang ang `pro`, ang
parehong lokal na tool capability na nakatali sa turn kapag naka-configure ang tunnel at connector.

## Pag-setup sa dashboard

1. Buksan ang provider na **ChatGPT Web (Codex)** at magdagdag ng koneksyon.
2. I-paste ang kumpletong ChatGPT Cookie header, tunnel ID, runtime key, at pangalan ng custom connector.
   Dapat gumamit ang mga bagong setup na may kakayahang gumamit ng tool ng bagong gawang connector na eksaktong pinangalanang
   `OmniRoute Codex v2`, na nakatakda ang Authentication sa None at ang Permissions sa Allow all
   actions.
3. Patakbuhin ang pagsusuri sa koneksyon. Nagbubukas ang OmniRoute ng browser-backed na Temporary Chat at tinutukoy
   kung available sa account ang Sol at Pro.
4. I-save ang koneksyon. Pinapalitan ng OmniRoute ang naka-paste na cookie ng na-verify na
   Playwright storage state at iniimbak ito kasama ng runtime key sa pamamagitan ng encrypted
   credential abstraction.

Hindi pinananatili ang raw cookie pagkatapos ng matagumpay na pag-save. Kapag nag-expire ang session, buksan
ang koneksyon, mag-paste ng bagong kumpletong Cookie header, at patakbuhing muli ang pagsusuri. Hiwalay na iniuulat ng doctor status
sa dialog ng pag-edit ang browser, storage state, pag-sign in, Temporary Chat, tunnel,
connector, at tool round-trip.

> Huwag kailanman mag-commit ng totoong cookie, runtime key, storage state, o capability token. Ang mga value para sa test at
> dokumentasyon ay dapat palaging mga placeholder.

## Mga model at combo

Ang mga nakapirming model route ay:

- `chatgpt-web-codex/luna` — GPT-5.6 Luna, mababang effort
- `chatgpt-web-codex/think` — GPT-5.6 Luna, katamtamang effort
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

Idagdag ang isa sa mga ito sa isang combo tulad ng anumang iba pang model. Ipinapadala ng Codex app ang pangalan ng combo bilang
`model` sa karaniwang Responses endpoint na `/v1/responses`; walang hiwalay na Codex
endpoint o mode switch.

Inilalantad ng mga Free/Go account ang mga Luna route. Inilalantad ng mga account na may kakayahang gumamit ng Sol ang Instant hanggang
High, at inilalantad din ng mga account na may kakayahang gumamit ng Pro ang Extra High at Pro. Ang bawat route ay may
nakapirming backend model at reasoning effort; ang sumasalungat na tahasang Responses effort ay ligtas na nabibigo
sa halip na tahimik na baguhin ang napiling browser mode.

Huwag palitan ang pangalan o muling gamitin ang mas lumang `Codex Native` o `OmniRoute Codex` connector. Kino-cache ng ChatGPT
ang pampublikong MCP contract ayon sa pagkakakilanlan ng connector, samantalang gumagamit ang na-refresh na bridge ng isang
bagong direct turn-token contract. Tinatanggihan ng runtime ang mga legacy identity na iyon at nangangailangan
ng bagong `OmniRoute Codex v2` connector.

## Modelo ng seguridad

- Ang native na path ay nangangailangan ng isang Responses request, isang kinikilalang Codex client, at magkatugmang
  pagkakakilanlan ng thread at turn.
- Ang workspace, sandbox, patakaran sa pag-apruba, at katalogo ng tool ay nagmumula sa native na Codex shell;
  ang malayang-formang prompt text ay walang awtoridad sa mga ito.
- Tanging isang panandaliang capability sa bawat turn ang natatanggap ng ChatGPT. Tanging ang
  mga tool na inalok ng Codex sa eksaktong turn na iyon ang tinatanggap ng MCP broker.
- Ang awtomatikong pagkumpirma sa **Payagan nang isang beses** ay ibinabalik lamang ang kahilingan sa tool sa Codex. Ang Codex lamang
  ang nagpapasya tungkol sa pag-apruba at pagpapatupad.
- Bago ang unang output, maaaring bumalik ang isang combo sa isa pang katugmang target. Pagkatapos
  magsimula ang output, mananatiling naka-pin ang provider, model, koneksyon, at browser turn hanggang sa
  makumpleto ang turn.
- Hindi lumilitaw ang cookies, runtime keys, storage state, at capability tokens sa mga tugon
  ng provider o sa mga request log.

## VPS na walang display at Docker

Para sa mga pag-install gamit ang npm, systemd, at PM2, tinutukoy ng OmniRoute ang mga karaniwang path ng Chrome at Chromium.
Bilang alternatibo, itakda ang `CHATGPT_WEB_CODEX_CHROME_PATH`. Sadyang gumagamit ang mga runtime turn ng Chrome
na may interface dahil tinatanggihan ng ChatGPT ang tunay na headless na anyo ng browser. Samakatuwid, dapat
patakbuhin ng host na walang display ang OmniRoute gamit ang isang pribadong Xvfb display; hindi sapat ang pagtatakda lamang ng Chrome path upang magkaroon nito.

Sinisimulan ng Docker `web` profile ang `chatgpt-web-codex-browser` sa internal na Compose
network. Pinapatakbo ng sidecar ang Chrome na may interface sa loob ng Xvfb, kaya hindi kinakailangan ang pisikal na display. Ang CDP
port nito ay hindi inilalathala sa host. Hiwalay ang protektadong browser profile volume mula sa
OmniRoute data volume, at tumatanggap ang browser ng sapat na shared memory. Ang internal na CDP proxy
ay nakikinig lamang sa port `9223` sa loob ng Compose network; nananatiling naka-bind ang Chrome sa loopback sa
sidecar.

Pinipigilan ng isang supervisor lease sa ilalim ng `DATA_DIR` ang maraming proseso ng OmniRoute na magkaroon ng kontrol
sa parehong tunnel at broker state. Iniuulat ng doctor ang isang conflict.

## Interaktibong pagbawi

Walang window na nakikita ng host ang automated na Docker path, ngunit ang Chrome mismo ay may interface sa loob ng
pribadong Xvfb display. Kapag nangangailangan ang ChatGPT ng interaktibong pag-sign in o challenge, maaaring gamitin ang umiiral na
imprastraktura ng VNC browser para sa pagbawi. Dapat manatiling naaabot lamang ang browser UI at CDP
sa pamamagitan ng loopback, isang authenticated na management connection, o isang SSH tunnel; nananatiling naka-disable ang noVNC
sa panahon ng normal na operasyon.

## WebSocket fallback

Kapag naglalaman ang isang combo ng ChatGPT Web (Codex), hinihiling ng Responses WebSocket bridge ang
HTTP/SSE fallback bago kumonekta sa upstream. Pagkatapos, dumadaan ang paglilipat sa
`/v1/responses`.
