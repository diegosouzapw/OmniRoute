Ang `copilot-m365-web` (alias na `m365copilot`) ay nagpapadala ng mga kahilingan sa chat na nasa OpenAI format sa pamamagitan ng isang napatotohanang browser session ng Microsoft 365 Copilot BizChat sa
`m365.cloud.microsoft/chat`. Isa itong hindi opisyal na integrasyon.

> **Bago ka ba sa mga provider ng Web Cookie?**
>
> Basahin ang **`docs/getting-started/WEB-COOKIE-GUIDE.md`** para sa pangkalahatang proseso ng pag-set up, gabay sa pagpapatotoo, mga limitasyon, at pag-troubleshoot bago sundin ang gabay na ito na partikular sa provider.
>
> **Mahalaga:** Ang kredensyal para sa provider na ito ay **hindi cookie**. Huwag kumopya ng
> mga cookie mula sa `m365.cloud.microsoft`. Ang kredensyal ay isang query
> parameter at segment ng path ng WebSocket URL, na parehong kinukuha mula sa tab na Network ng DevTools.

## Mga kinakailangan

- Isang Microsoft 365 account na may access sa BizChat sa `m365.cloud.microsoft/chat`
- Isang browser na nakabatay sa Chromium (Chrome, Edge) para sa pagsiyasat ng WebSocket sa DevTools
- Isang lisensya ng M365 Copilot (kasama sa maraming Microsoft 365 Business/Enterprise plan)

## Pagkuha ng kredensyal (pamamaraang WebSocket)

1. Mag-sign in sa `https://m365.cloud.microsoft/chat` at magsimula ng pag-uusap.
2. Buksan ang **DevTools → Network**.
3. I-filter ayon sa **WS** (WebSocket).
4. I-click ang koneksyong Chathub WebSocket. Maghanap ng URL na nagsisimula sa
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Mula sa **Request URL** nito, kopyahin ang:
   - Value ng `access_token` query parameter (isang panandaliang JWT).
   - Segment ng Chathub path pagkatapos ng `/Chathub/` (hal. `<oid>@<tenant>`).

Ganito ang anyo ng buong URL:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. Sa OmniRoute, pumunta sa **Providers → Add Provider**, piliin ang **Microsoft 365 Copilot
   (BizChat)**, at i-paste ang kredensyal sa format na:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. I-click ang **Test Connection** at **Save**.

## Pagkuha ng kredensyal (pag-import ng HAR)

Sa halip na manu-manong kopyahin ang mga value mula sa WebSocket URL, maaari kang mag-export ng DevTools HAR
file:

1. Buksan ang **DevTools → Network**.
2. Magsimula o magpatuloy ng isang pag-uusap sa BizChat (mati-trigger nito ang koneksyong WebSocket).
3. Mag-right-click sa Network panel at piliin ang **Save all as HAR with content**.
4. Sa OmniRoute, gamitin ang button na **Import .har file** sa dialog ng koneksyon ng provider.

Sinusuri ng OmniRoute ang HAR para sa Chathub WebSocket URL, kinukuha ang
`access_token` at `chathubPath`, at awtomatikong pinupunan ang mga field ng kredensyal. Dine-decode ng
pag-import ng HAR ang pag-expire ng JWT at ipinapakita ang natitirang tagal ng token.

> **Huwag kailanman mag-commit ng totoong HAR export, access token, o refresh token.** Ang mga value para sa pagsubok at
> dokumentasyon ay dapat palaging mga placeholder.

## Tagal at pag-refresh ng token

Panandalian ang `access_token` (karaniwang **~75 minuto**). Pagkatapos itong mag-expire, mag-uulat ang provider
ng error sa koneksyon at kailangan mong kunin muli ang kredensyal.

### Awtomatikong pag-refresh gamit ang `refreshToken`

Upang maiwasan ang manu-manong muling pagkuha, maaari kang mag-imbak ng Microsoft refresh token sa
**Advanced Settings → providerSpecificData** ng koneksyon:

| Field          | Paglalarawan                                                                 |
| -------------- | ---------------------------------------------------------------------------- |
| `refreshToken` | Microsoft OAuth refresh token para sa scope na `substrate.office.com/sydney` |
| `tier`         | `individual` (default), `edu`, o `enterprise`                                |

Kunin ang refresh token mula sa isang Microsoft device-code o authorization-code flow
na naka-scope sa `substrate.office.com/sydney`. Kapag nakatakda ang `refreshToken`, nire-refresh muna ng OmniRoute
ang `access_token` bago ang bawat kahilingan, kaya hindi mo na kailangang kunin itong muli
pagkatapos ng bawat ~75 minutong pag-expire.

Kung hindi nakatakda ang `refreshToken`, kailangan mong manu-manong kunin muli ang kredensyal ng WebSocket
pagkatapos ng bawat pag-expire.

### Pagpili ng tier

| Tier         | Alias       | Surface                        |
| ------------ | ----------- | ------------------------------ |
| `individual` | _(default)_ | M365 Copilot para sa Consumer  |
| `edu`        | `included`  | M365 Copilot para sa Edukasyon |
| `enterprise` | `work`      | M365 Copilot para sa Trabaho   |

Itakda ang tier sa **Advanced Settings → providerSpecificData → tier**. Naaapektuhan ng tier
ang pagruruta ng BizChat at access sa modelo.

## Modelo ng seguridad

- **Hindi opisyal na integrasyon.** Nire-reverse-engineer ng provider na ito ang BizChat WebSocket
  protocol. Maaari itong masira nang walang abiso kapag binago ng Microsoft ang endpoint.
- Ipinapahiwatig ng flag na `subscriptionRisk: true` na umaasa ang integrasyon sa isang
  hindi dokumentadong endpoint. Posible ang mga paghihigpit sa account ngunit hindi pa ito nakukumpirma.
- Ang access token ay isang panandaliang JWT. Ituring ito na parang password: huwag itong i-commit,
  i-log, o ibahagi.
- Nagbibigay ang refresh token ng pangmatagalang access sa BizChat surface. Itago ito nang
  kasing-ingat ng isang API key.

## Pag-troubleshoot

### Agad na nabibigo ang pagpapatotoo

- Tiyaking mula sa **WebSocket URL** ka kumopya, hindi mula sa isang XHR/Fetch request. Ang
  credential ay nasa `access_token` query parameter ng Chathub WebSocket
  connection — hindi sa isang `Authorization: Bearer` header.
- Tiyaking kasama sa `chathubPath` ang buong `<oid>@<tenant>` segment mula sa URL
  path.

### Nag-e-expire ang token pagkalipas ng ~75 minuto

Inaasahan ito. Kung walang `refreshToken`, panandalian lang ang access token. Maaari mong:

- Kunin muli ang credential mula sa DevTools, o
- Mag-configure ng `refreshToken` sa Advanced Settings para sa awtomatikong pag-refresh.

### Pumapasa ang Test Connection ngunit nagbabalik ng 401 ang chat

Maaaring nag-expire ang token sa pagitan ng validation at ng unang request. Kunin muli ang isang
bagong credential.

### Hindi lumalabas ang Copilot sa listahan ng provider

Tiyaking naka-enable ang `copilot-m365-web` sa **Dashboard → Providers**. Maaaring
nakatago bilang default ang provider sa ilang tier.
