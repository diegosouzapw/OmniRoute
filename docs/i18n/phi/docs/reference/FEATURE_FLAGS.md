> Mga runtime toggle na nagbabago sa gawi ng OmniRoute **nang hindi muling nagde-deploy**.
> Ang bawat flag na nakalista rito ay tinukoy sa
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> — ang nag-iisang pinagmumulan ng katotohanan. Parehong nagbabasa ang dashboard at ang REST API mula sa
> file na iyon, kaya ang talahanayan sa ibaba ay binuo upang tumugma rito nang 1:1.

---

## Ano ang Mga Feature Flag

Ang feature flag ay isang may-pangalang toggle (boolean o enum) na maaaring baguhin ang value
habang tumatakbo at i-persist sa database, nang hindi kinakailangang muling i-deploy ang proseso. Ang bawat
flag ay inilalarawan ng isang `FeatureFlagDefinition` na may `key`, `label`,
`description`, `category`, `defaultValue`, `type`, at isang `requiresRestart` na pahiwatig.

### Pagkakasunod-sunod ng Pag-resolve

Ang **effective value** ng isang flag ay nire-resolve ng
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) ayon sa sumusunod na
pagkakasunod-sunod ng prayoridad (pinakamataas ang mananaig):

1. **DB override** — isang value na nakaimbak sa talahanayang `key_value` sa ilalim ng
   namespace na `feature_flags` (itinakda sa pamamagitan ng dashboard o REST API).
2. **Environment variable** — `process.env[<KEY>]`, kung nakatakda at hindi walang laman.
3. **Default ng definition** — ang `defaultValue` mula sa `featureFlagDefinitions.ts`.

Itinuturing na **enabled** ang isang boolean flag kapag ang effective value nito ay `"true"`,
`"1"`, o `"yes"` (tingnan ang `isFeatureFlagEnabled()`).

> [!NOTE]
> Karamihan sa mga flag ay mayroon ding katugmang environment variable na may **parehong pangalan**
> na nakadokumento sa [`ENVIRONMENT.md`](./ENVIRONMENT.md). Mas inuuna ang DB override ng flag
> kaysa sa environment variable na iyon. Ang isang flag na may
> `requiresRestart: true` ay agad na pini-persist ngunit muli lamang binabasa sa pagsisimula ng proseso
> — ang pag-toggle rito ay nagpapakita ng banner na **"I-restart ang Server"** sa dashboard.

## Pag-toggle ng mga Flag

### Dashboard

Pumunta sa **Dashboard → Settings → Feature Flags**
(`/dashboard/settings/feature-flags`). Sinusuportahan ng grid
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
ang:

- **Paghahanap** ayon sa key o paglalarawan, at **pag-filter** ayon sa kategorya (kasama ang sintetikong
  view na **Requires Restart**).
- Isang **toggle** para sa mga boolean flag at isang **dropdown** para sa mga enum flag
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- Isang **source badge** para sa bawat flag — `DB`, `ENV`, o `DEF` — na nagpapakita kung saan
  nagmula ang aktuwal na value.
- Isang button na **Reset** (ipinapakita lamang para sa mga flag na mula sa `DB`) upang alisin ang override,
  at isang button na **Reset All Overrides** sa ibaba.
- Isang banner na **Restart Server** kapag binago ang isang flag na `requiresRestart`.

### REST API

Dumadaan ang lahat ng operasyon sa iisang route:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Nangangailangan ang bawat method ng authenticated na dashboard session (`401` kung wala).

#### `GET /api/settings/feature-flags`

Ibinabalik ang bawat flag kasama ang aktuwal na value, source, at buod nito.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... lahat ng 75 flag
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Magtakda o mag-alis ng isang override. Body: `{ key: string; value?: string }`.
Kapag hindi isinama ang `value`, aalisin ang override (at ibabalik ang env / default).

```bash
# Magtakda ng DB override
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Alisin ang override (walang "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Inuulit sa response ang bagong `effectiveValue`/`source`, ang `previousValue`/
`previousSource`, at ang `requiresRestart`. Ang mga hindi kilalang key at enum
value na wala sa pinapayagang saklaw ay tinatanggihan gamit ang `400`.

#### `DELETE /api/settings/feature-flags`

Sabay-sabay na nililinis ang **lahat** ng DB override, na ibinabalik ang bawat flag sa env / default
value nito. Nagbabalik ng `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> Magkakabisa lamang ang mga flag na may `requiresRestart: true` pagkatapos i-reload ang process.
> Tinatawag ng restart flow ng dashboard ang `POST /api/restart` at pagkatapos ay paulit-ulit na sinusuri ang
> `GET /api/health/ping` hanggang sa muling maging available ang server.

## Pang-emergency na Fallback sa Badyet

Kinokontrol ng `OMNIROUTE_EMERGENCY_FALLBACK` (kategoryang `runtime`, default na `true`) ang
pang-emergency na libreng fallback path sa
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Kapag naka-enable, ang mga request na nakaubos ng kanilang badyet ay ipinapasa sa isang libreng fallback
provider/model sa halip na tuluyang mabigo. Itakda ito sa `false` (o `0`) — sa pamamagitan ng
dashboard toggle, DB override, o environment variable na `OMNIROUTE_EMERGENCY_FALLBACK`
— upang i-disable ang gawi at hayaang mabigo ang mga request na nakaubos ng badyet.
(Inilabas bilang dashboard toggle sa mga PR #3741 / #3752.)
