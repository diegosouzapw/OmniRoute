## Mga Panuntunan

- Nalalapat ang mga target ng coverage sa mga source file, hindi sa `tests/**`.
- Bahagi ng produkto ang `open-sse/**` at dapat manatiling kasama sa saklaw.
- Hindi dapat pababain ng bagong code ang coverage sa mga bahaging binago.
- Mas piliing subukan ang gawi at mga resulta ng branch kaysa sa mga detalye ng implementasyon.
- Mas piliin ang mga pansamantalang SQLite database at maliliit na fixture kaysa sa malawakang paggamit ng mga mock para sa `src/lib/db/**`.

## Kasalukuyang hanay ng mga command

- `npm run test:coverage`
  - Pangunahing source coverage gate para sa unit test suite
  - Bumubuo ng `text-summary`, `html`, `json-summary`, at `lcov`
- `npm run coverage:report`
  - Detalyadong ulat para sa bawat file mula sa pinakabagong run
- `npm run test:coverage:legacy`
  - Para lamang sa makasaysayang paghahambing

## Patakaran sa ratchet

I-update lamang ang mga threshold ng `npm run test:coverage` kapag aktuwal nang lumampas ang proyekto sa susunod na milestone nang may sapat na palugit.

**Kasalukuyang gate:** Ipinapatupad ng `npm run test:coverage` ang **60 pahayag / 60 linya / 60 function / 60 sangay** (muling ibinatay ang sukatan sa Quality-Gates Yugto 6A.1 — masyadong mataas ang naunang baseline na 82.58% dahil isinama nito ang mga test file at hindi isinama ang `open-sse`). Pinapanatili ng command na `test:coverage:legacy` ang lumang sukatang 50/50/50 para sa makasaysayang paghahambing.

Para sa mga ad-hoc na pagsusuri ng threshold batay sa pinakabagong ulat, gamitin ang:

```bash
node scripts/check/test-report-summary.mjs --threshold 75
```

Inirerekomendang pagkakasunod-sunod ng ratchet (ang ayos ay `mga pahayag-mga linya / mga sangay / mga function`):

1. 55/60/55
2. 60/62/58
3. 65/64/62
4. 70/66/66
5. 75/70/72 <-- kasalukuyang gate (75/70/75)
6. 80/75/78
7. 85/80/84
8. 90/85/88

Ang susunod na target ng ratchet ay `80/75/78` kapag nanatiling mas mataas sa 78% ang coverage ng mga sangay sa dalawang magkasunod na pagpapatakbo.

## Kilalang kakulangan

Sinusukat ng kasalukuyang coverage command ang pangunahing Node unit suite at isinasama ang source na naaabot mula rito, kabilang ang `open-sse`. Hindi pa nito pinagsasama ang coverage ng Vitest sa iisang pinag-isang ulat. Makabuluhang gawin ang pagsasamang iyon sa hinaharap, ngunit hindi ito hadlang upang simulan ang pag-angat mula 60% -> 80%.
