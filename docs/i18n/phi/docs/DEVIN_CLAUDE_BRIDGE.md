Hinahayaan ng `devin-cli-agentic` ang tunay na Claude Code runtime na gamitin ang lokal na Anthropic
Messages endpoint ng OmniRoute habang ibinibigay ng opisyal na Devin CLI ang mga tugon ng modelo sa pamamagitan ng ACP stdio. Hindi
nito binabago ang kasalukuyang mga provider na Anthropic, Claude OAuth, Claude Web, o `devin-cli`.

> **Kasalukuyang katayuan: naka-pin sa Claude Code `2.1.258`; huling naitala ang offline at live na pagpapatunay
> sa `2.1.220`.** Nakumpleto ng `2.1.220` pin ang tatlong nakahiwalay na sitwasyon sa pamamagitan ng Devin CLI
> `3000.2.17` at modelong `swe-1-7-lightning`; pinatunayan ng huling live run na iyon ang mga turn na `Read`,
> `Edit`, at `Bash` na pagmamay-ari ng client, matagumpay na mga resulta ng `npm test`, pagtuklas sa project command at skill,
> Devin-only na pagruruta, at walang Claude egress. Pagkatapos ay itinaas ang pin sa `2.1.258`
> (ang henerasyon ng CLI na ginagaya ng Claude identity ng OmniRoute, at ang unang linya na likas na naglalaman
> ng Fable 5.1 tier). Sa bagong pin, napatunayan ang install layer at `claude --version` sa
> naka-pin na base image, at pumapasa ang bridge unit suite, `compose config`, at ang
> static isolation proof — ngunit hindi pa muling pinapatakbo ang offline mock scenario at ang live na suite na may tatlong sitwasyon.
> Muling patakbuhin ang mga ito (tingnan ang "Pag-update ng mga naka-pin na tool") bago umasa sa
> bridge gamit ang pin na ito.

## Arkitektura

```text
Claude Code 2.1.258 (nakahiwalay na non-root Linux container)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-format, no-auth provider)
  -> devin acp --agent-type summarizer (opisyal na ACP stdio, walang Devin tools)
  -> Devin account sa nakalaang devin-auth volume
```

Kayang magpatakbo ng sarili nitong mga tool ang default na ACP agent ng opisyal na CLI, kaya hindi ito ginagamit
ng bridge na ito. Sinisimulan nito ang nakapirming `summarizer` ACP agent, na walang mga tool sa opisyal nitong CLI mode, at
binabalangkas ang serialized na Anthropic request bilang isang execution trace. Kapag kailangan ng isa pang
action na pagmamay-ari ni Claude, dapat maglaman ang tugon ng eksaktong isang client tool envelope. Ang anumang ACP
`tool_call` o `tool_call_update` ay tinatanggihan bago maiulat ang isang tugon bilang
matagumpay.

Pinapanatili ng serializer sa `open-sse/executors/devin-agentic/serializer.ts` ang `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice`, at ang
mga tool na ibinigay ng Claude Code. Tahasang nagdudulot ng pagkabigo ang mga image at hindi kilalang block. Gumagamit ang malalaking resulta ng tool
ng nakikitang truncation marker.

Tumatanggap ang parser ng isang hiwalay na `<tool>{...}</tool>` envelope sa bawat model turn. Sinusuri nito
ang pangalan laban sa listahan ng mga tool ng request, pinapatunayan ang mga argument laban sa JSON
Schema ng tool na iyon, tinatanggihan ang pinaghalong salaysay/mga action, at nagpapahintulot ng isang limitadong repair. Pagkatapos ay
lokal na isinasagawa ng Claude Code ang nabuong Anthropic `tool_use` at ipinapadala pabalik ang `tool_result` sa pamamagitan
ng OmniRoute.

## Isolation at threat model

Hindi saklaw at itinuturing na ipinagbabawal ang Claude installation, account, at configuration ng host.
Ang mga Compose service ay:

- tumatakbo bilang UID/GID `10001:10001`, na may read-only na root filesystem, inalis na mga capability, at
  `no-new-privileges`;
- gumagamit ng pribadong `/home/bridge`, nakalaang Claude config volume, nakahiwalay na data ng OmniRoute,
  at hiwalay na `devin-auth` volume;
- nagma-mount lamang ng mga disposable na `.sandbox` workspace/evidence;
- hindi nagma-mount ng host home, Keychain, SSH, cloud credentials, o Docker socket;
- bumubuo ng mga tahasang environment at nag-aalis ng mga Anthropic API/OAuth/routing variable;
- idinidirekta lamang ang inference ng Claude Code sa `http://omniroute:20128` gamit ang local-only na key.

Gumagamit ang offline profile ng internal network. Sa live profile, naaabot lamang ng OmniRoute ang
mga opisyal na Devin endpoint sa pamamagitan ng `network-guard`; tinatanggihan ang mga hindi kaugnay na destination.
May hiwalay na deny-all egress guard ang Claude Code at maaabot lamang nito ang lokal na OmniRoute
service sa pamamagitan ng `NO_PROXY`. Ang mga guard audit file ay mino-mount lamang ng kani-kanilang guard process. Bine-verify ng
mga script ang pagmamay-ari ng file, mode, link count, at bawat desisyon bago mag-export ng
token-free na evidence.

Patakbuhin nang hiwalay ang isolation proof:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

Pinapatunayan nito ang topology, mga pinangalanang mount, mga setting na non-root/read-only, tahasang lokal na routing,
kawalan ng mga sensitibong environment variable, kawalan ng Docker socket, naka-block na access sa
`api.anthropic.com` at `claude.ai`, Devin-only na pagpili ng provider, at tahasang pagkabigo kapag
hindi available ang ACP backend.

## Unang beses na pag-setup at normal na paggamit

Buuin ang naka-pin na image:

```bash
./scripts/devin-bridge/build
```

I-authenticate lamang ang nakahiwalay na Devin volume:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

Ginagamit ng login command ang opisyal na manual-token flow na inilaan para sa mga remote/container environment. Direktang inilalagay ang value sa CLI prompt; hindi ito ipinapasa bilang process argument, isinusulat sa Git, o kinokopya mula sa host.

Ilunsad ang nakahiwalay na Claude Code runtime:

```bash
./scripts/devin-bridge/launch
```

Muling sinusuri ng `launch` ang isolation, Devin authentication, at model discovery bago simulan ang naka-container na Claude Code. Hindi nito kailanman pinapatakbo ang Claude executable ng host. Maaaring itakda ang mga model alias sa `.env.devin-bridge`; kailangang panatilihin ng bawat naka-configure na value ang prefix na `devin-cli-agentic/`.

## Mga command sa pag-validate

Hindi nangangailangan ng Devin account ang reproducible offline path at wala itong runtime Internet:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

Ang authenticated at opt-in na live path ay:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

Naghihintay ang live runner sa pagitan ng mga scenario upang maiwasang magbukas ng maraming ACP session nang sabay-sabay at nagva-validate ito ng mga structured Claude stream event sa halip na basta pagkatiwalaan ang mga textual claim. Pinatutunayan ng tatlong scenario nito ang:

1. direktang pagbasa sa project at pagsusuri ng defect;
2. isang tunay na `Edit`, isang `Bash` `npm test` na pagmamay-ari ng client, at isang terminal result;
3. `/bridge-check` kasama ang pagtuklas sa `bridge-proof`, mga pagbasa sa project, isa pang matagumpay na `npm test` na pagmamay-ari ng client, at pagkumpleto nang walang nakabinbing gawain.

Sinusuri rin ng panghuling gate ang Devin network audit at hinihinging manatiling walang laman ang Claude egress audit.

## Pag-update ng mga naka-pin na tool

Naka-pin sa image ang Node, Claude Code, at Devin CLI sa `docker/devin-bridge/Dockerfile`. Upang mag-update:

1. baguhin ang mga tahasang version;
2. palitan ang parehong architecture-specific na Devin archive checksum ng mga value para sa opisyal na artifact;
3. muling buuin at patakbuhin ang bawat offline validation command;
4. kumpirmahin ang mga version sa loob ng image;
5. muling patakbuhin ang authenticated na tatlong-scenario na live suite.

Huwag i-install nang global sa host ang alinmang CLI o palitan ang checksum verification ng hindi na-verify na download.

## Diagnosis at paglilinis

- Ipinapakita ng `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute` ang local routing at mga na-sanitize na executor error.
- Itinatala ng `.sandbox/evidence/mock-acp.jsonl` ang mga deterministic mock ACP action.
- Itinatala ng `.sandbox/evidence/claude-stream.jsonl` ang tunay na offline run ng Claude Code.
- Itinatala ng `.sandbox/evidence/live-*.jsonl` ang tatlong na-validate na live stream.
- Ang `.sandbox/evidence/egress.jsonl` at `.sandbox/evidence/claude-egress.jsonl` ay mga na-validate at token-free na kopya ng mga guard audit.

Ihinto ang mga pagmamay-aring container at network habang pinananatili ang mga login/config volume:

```bash
./scripts/devin-bridge/clean
```

Alisin ang buong environment na pagmamay-ari ng bridge, kabilang ang mga named volume:

```bash
./scripts/devin-bridge/clean --all
```

## Mga Limitasyon

- Umaasa ang bridge sa nakapirming no-tools na tungkuling `summarizer` dahil hindi naglalantad ang Devin CLI `3000.2.17`
  ng neutral na no-tools ACP agent. Binabawi ng adapter ang mga intermediate na tugon na
  nasa anyong buod, ngunit maaari pa ring tahasang mabigo ang isang limitadong pagkukumpuni.
- Maaaring magbalik ang mga live na tawag sa ACP ng mga pansamantalang tugon na `502`/`504`. Nilalagyan ng pagitan ng harness ang mga senaryo;
  ang tuloy-tuloy na pagkabigo ay nananatiling fail-closed at hindi kailanman pumipili ng ibang provider.
- Muling binubuo ang konteksto ng ACP mula sa bawat kahilingan ng Anthropic; walang
  affinity sa proseso/session.
- Isang tool call ang sinusuportahan sa bawat tugon ng modelo; tinatanggihan ang mga parallel na tawag.
- Tahasang hindi sinusuportahan ang mga larawan. Hindi iniaalok ang vision, thinking output, effort controls, at 1M
  context window.
- Gumagamit ang SSE ng mga wastong lifecycle event ng Anthropic ngunit ipinapadala lamang matapos
  makolekta ang limitadong ACP turn; hindi ipinapasa nang incremental ang mga ACP chunk.
