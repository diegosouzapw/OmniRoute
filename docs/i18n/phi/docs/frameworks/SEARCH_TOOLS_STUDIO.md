## Pangkalahatang-ideya

Binabago ng Search Tools Studio ang `/dashboard/search-tools` mula sa isang simpleng search playground tungo sa isang
Studio na may tatlong tab, na pinag-iisa ang paghahanap sa web, pag-scrape sa web, at magkatabing paghahambing ng mga provider.

```
┌ Search Tools ──────────────────────────────────────────────────────────┐
│ [🔍 Maghanap] [📄 Mag-scrape] [⚖ Ihambing]      142ms · $0.001  </>    │
│ ⓘ [Gabay sa mga modality]                                              │
├──────────────────────────────────────────┬─────────────────────────────┤
│  {nilalaman ng aktibong tab}             │ ─ Configuration             │
│                                          │ Provider [auto ∨]           │
│                                          │   🟢 Serper  $0.001         │
│                                          │   🟢 Tavily  $0.008         │
│                                          │   🔥 Firecrawl (pag-fetch)  │
│                                          │ Uri    [web | news]         │
│                                          │ Buong page [ ] (scrape)     │
│                                          │ Format [md|text|html]       │
│                                          │ Rerank model [∨]            │
└──────────────────────────────────────────┴─────────────────────────────┘
```

## Mga Tab

### Tab na Search

Pinapalawak nito ang kasalukuyang `SearchForm` + `ResultsPanel` + `RerankPanel` bilang isang tab:

- Query → mga resulta (pamagat, URL, snippet, relevance score).
- Metadata ng provider sa Config pane (gastos, quota, status).
- Seksyon ng rerank: pumili ng rerank model, muling ayusin ang mga resulta, ipakita ang `positionDelta`.
- Empty state na may CTA kapag walang naka-configure na search provider.
- History ng paghahanap sa pamamagitan ng `SearchHistory.tsx`.
- Tumatawag sa `POST /v1/search` (kasalukuyang endpoint, walang pagbabago).

### Tab na Scrape

Bagong tab para sa pag-extract ng content mula sa isang URL sa pamamagitan ng `POST /v1/web/fetch` (ginawa sa plan 05):

- Input: URL + toggle para sa buong page + selector ng format (markdown / text / HTML).
- I-submit → i-fetch → i-render ang `ScrapeResult.tsx`.
- Nagre-render ang `ScrapeResult` ng preview na markdown + toggle para sa raw.
- Limitasyon: kung ang response body ay higit sa **256 KB**, ipapakita ng UI ang `(pinaikli, tingnan ang raw)` at bubuksan ang raw sa isang Monaco modal (D21).
- Panel ng metadata: provider (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search), latency, gastos, laki ng response, bilang ng mga link.
- Ginagamit ang `useScrapeFetch.ts` hook.

### Tab na Compare

Pinapatakbo ang parehong query/URL sa hanggang **4 na provider nang sabay-sabay** (D22):

- Magkatabing column para sa bawat provider.
- Mga sukatan: latency, gastos, bilang ng resulta, laki ng response.
- Pagkalkula ng overlap ng URL para sa paghahanap (bilang ng magkakaparehong URL kumpara sa paunang resulta).
- Tumatawag sa `POST /v1/search` (paghahanap) o `POST /v1/web/fetch` (pag-scrape) para sa bawat provider.

## Config Pane (Pinagsasaluhan)

`SearchToolsConfigPane.tsx` — palaging nakikita at maaaring i-collapse.

| Field        | Mga Tala                                                                                     |
| ------------ | -------------------------------------------------------------------------------------------- |
| Provider     | Dropdown na may status badge (naka-configure / nawawala / nalimitahan ang rate)              |
| Uri          | `web` o `news` (para lamang sa paghahanap)                                                   |
| Buong page   | Toggle para sa pag-scrape — kinukuha ang buong page sa halip na ang unang nakikitang content |
| Format       | `markdown`, `text`, o `html` (para lamang sa pag-scrape)                                     |
| Rerank model | Opsyonal na model para sa reranking pagkatapos ng paghahanap                                 |
| History      | Nako-collapse na seksyon ng history ng paghahanap                                            |

---

## SearchConceptCard

`SearchConceptCard.tsx` — palaging nakikita at maaaring i-collapse na accordion. Ipinapaliwanag nito ang:

| Konsepto              | Maikling paliwanag                                                                  |
| --------------------- | ----------------------------------------------------------------------------------- |
| **Paghahanap**        | Kumukuha ng listahan ng mga resulta sa web (pamagat, URL, snippet, relevance score) |
| **Pag-scrape**        | Kinukuha ang buong nilalaman ng isang URL (markdown, text, o HTML)                  |
| **Paghahambing**      | Pinapatakbo ang parehong query sa N provider nang magkatabi                         |
| **Muling pag-rank**   | Muling inaayos ang mga resulta gamit ang LLM upang mapahusay ang kaugnayan sa query |
| **Auto (pinakamura)** | Awtomatikong pinipili ang pinakamurang available na provider                        |

## Catalog ng Provider

Inilalantad ng `ProviderCatalog.tsx` ang kumpletong listahan ng provider mula sa `GET /api/search/providers`
(pinalawak sa F4 upang isama ang mga fetch provider):

| `kind` | `"search"` (20 provider) o `"fetch"` (firecrawl, jina-reader, tavily-search, tinyfish, nimble-search, anysearch-search) |

Ang status ay **tinutukoy sa oras ng request** sa pamamagitan ng pagsusuri kung may mga credential at kung
ang lahat ng key ay kasalukuyang nasa cooldown.

---

## Pag-export ng Code

Ang `ExportCodeModal` (in-import mula sa Playground Studio) + `codeExport.ts` ay bumubuo ng
mga curl / Python / TypeScript snippet para sa parehong `/v1/search` at `/v1/web/fetch` na call.
Ang placeholder ng API key ay palaging `$OMNIROUTE_API_KEY` (D11, ibinabahagi sa Playground Studio).

## Mga Pagbabago sa Backend

Isang pagbabago lamang sa backend ang kinailangan para sa feature na ito:

### Pinalawak na `GET /api/search/providers`

Pinalawak ang `src/app/api/search/providers/route.ts` upang:

- Isama ang lahat ng 6 na fetch provider (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`) sa array.
- Magdagdag ng `kind: "search" | "fetch"` sa bawat item.
- Magdagdag ng `status: "configured" | "missing" | "rate_limited"` na tinutukoy mula sa live na estado ng credential.
- Panatilihin ang backward compatibility — hindi binago ang mga kasalukuyang field (`id`, `name`, atbp.).

## Pag-troubleshoot

| Sintomas                                                  | Sanhi                                   | Solusyon                                                                                                   |
| --------------------------------------------------------- | --------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Ipinapakita ng tab na Scrape ang "endpoint not available" | Hindi nakakonekta ang `/v1/web/fetch`   | Tiyaking naka-merge ang plan 05; tingnan kung umiiral ang `src/app/api/v1/web/fetch/route.ts`              |
| Ipinapakita ng catalog ng provider na "missing" ang lahat | Hindi naka-configure ang mga credential | Magdagdag ng mga credential sa `/dashboard/providers`                                                      |
| Napuputol ang content ng scrape                           | Response > 256 KB cap                   | Inaasahang gawi (D21). Gamitin ang button na "view raw" para sa buong content                              |
| 2 provider lang ang ipinapakita ng tab na Compare         | Aktibo ang rate limit                   | Maaaring nasa cooldown ang dalawa o higit pang provider — tingnan ang status ng provider sa pane na Config |
| Ipinapakita ang "Size" bilang raw key sa talahanayan      | Nawawalang i18n key                     | Tiyaking umiiral ang `search.size` sa locale file; i-rebuild ang i18n                                      |
