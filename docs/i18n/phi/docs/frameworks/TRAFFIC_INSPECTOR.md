Ang Traffic Inspector ay ang built-in na HTTPS traffic debugger ng OmniRoute — isang tool na katulad ng Charles Proxy / mitmweb / HTTP Toolkit na **LLM-aware** at **agent-aware**. Matatagpuan ito sa `/dashboard/tools/traffic-inspector` at tumatanggap ng live na traffic mula sa hanggang 5 sabay-sabay na capture source.

**Lokasyon sa dashboard:** `/dashboard/tools/traffic-inspector`
**Grupo sa sidebar:** Tools (pagkatapos ng AgentBridge)
**Tingnan din:** [`AGENTBRIDGE.md`](./AGENTBRIDGE.md) — Ang AgentBridge ang capture mode 1.

### Arkitektura sa isang talata

Ang `TrafficBuffer` (`src/mitm/inspector/buffer.ts`) ay isang nakabahaging in-memory ring buffer (default na 1000 entry, nako-configure sa pamamagitan ng `INSPECTOR_BUFFER_SIZE`). Sumusulat dito ang lahat ng capture source sa pamamagitan ng `push()`. Inuuri ng buffer ang bawat entry gamit ang `kindDetector.ts` (tinutukoy kung isa itong LLM request), kinakalkula ang isang `contextKey` (SHA-256 fingerprint ng system prompt), at bina-broadcast ito sa lahat ng WebSocket subscriber sa pamamagitan ng `globalTrafficBuffer.subscribe()`. Kumokonekta ang dashboard sa pamamagitan ng `GET /api/tools/traffic-inspector/ws` at tumatanggap ng snapshot kapag kumonekta, na sinusundan ng mga event na `new`/`update`/`clear`.

## §2 Mga mode ng pag-capture

Sinusuportahan ng Traffic Inspector ang **5 sabay-sabay na pinagmumulan ng pag-capture**. Maaaring i-toggle nang hiwalay ang bawat isa. Ang field na `source` sa bawat `InterceptedRequest` (`src/mitm/inspector/types.ts`) ay isa sa `"agent-bridge"`, `"custom-host"`, `"http-proxy"`, `"system-proxy"`, o `"tproxy"`.

### Mode 1 — AgentBridge (default, palaging naka-on)

**Pinagmulan:** Mga handler ng AgentBridge (`src/mitm/handlers/base.ts`)
**Mekanismo:** Tinatawag ng bawat `intercept()` call sa `MitmHandlerBase` ang `hookBufferStart()` bago mag-forward at ang `hookBufferUpdate()` kapag nakumpleto. Walang karagdagang configuration — gumagana agad kapag tumatakbo na ang AgentBridge.
**Saklaw:** Ang 9 na IDE agent na naka-configure sa AgentBridge
**Tandaan:** Ang field na `source` sa `InterceptedRequest` = `"agent-bridge"`

### Mode 2 — Mga Custom Host (pag-redirect ng DNS)

**Pinagmulan:** Listahan ng mga host na tinukoy ng user (`inspector_custom_hosts` table)
**Mekanismo:** Kapag nagdagdag ng host sa pamamagitan ng UI, idinaragdag ang `127.0.0.1 <host>` sa `/etc/hosts` (nangangailangan ng sudo). Dinamikong bumubuo ang umiiral na AgentBridge MITM server (port 443) ng SNI cert para sa bagong host.
**Saklaw:** Anumang application na gumagamit ng idinagdag na host — walang kinakailangang pagbabago sa configuration ng app
**Tandaan:** `source` = `"custom-host"`

Mga halimbawa ng paggamit:

- Subaybayan ang `api.openai.com` mula sa mga Python script
- I-debug ang `my-internal-llm.company.com`
- I-capture ang traffic mula sa mga mobile device sa parehong network (sa pamamagitan ng ARP spoofing — advanced)

### Mode 3 — HTTP_PROXY listener (port 8080)

**Pinagmulan:** Mga application na gumagamit ng `HTTP_PROXY`/`HTTPS_PROXY` environment variable
**Mekanismo:** Pangalawang listener sa port 8080 (`src/mitm/inspector/httpProxyServer.ts`) na gumaganap bilang karaniwang explicit HTTP/HTTPS proxy. Tumatanggap ng mga `CONNECT` tunnel (HTTPS) at direktang HTTP request.
**Saklaw:** Anumang application na sumusunod sa `HTTP_PROXY` env — walang pagbabago sa DNS, walang sudo
**Tandaan:** `source` = `"http-proxy"`

```bash
# Mabilis na pag-capture para sa isang command:
HTTPS_PROXY=http://127.0.0.1:8080 curl https://api.openai.com/v1/models

# Tuloy-tuloy na pag-capture sa isang shell session:
export HTTP_PROXY=http://127.0.0.1:8080
export HTTPS_PROXY=http://127.0.0.1:8080
```

**Limitasyon ng TLS:** Naka-capture lamang bilang metadata ang mga HTTPS `CONNECT` tunnel (host, port, timing) — hindi dine-decrypt ang TLS body bilang default. I-enable ang toggle na "I-decrypt ang HTTPS sa proxy mode" (opt-in, nangangailangang pinagkakatiwalaan ang AgentBridge cert) para sa buong inspeksyon ng body.

**Salungatan sa port:** Kung ginagamit na ang port 8080, nagbabalik ang AgentBridge ng 409 na may structured error. Baguhin ang port sa pamamagitan ng `INSPECTOR_HTTP_PROXY_PORT` env var.

### Mode 4 — System-wide proxy (advanced, opt-in)

**Pinagmulan:** Mga proxy setting sa antas ng OS (nalalapat sa lahat ng app sa machine)
**Mekanismo:** Gumagamit ng mga OS API upang i-redirect ang lahat ng HTTP/HTTPS traffic sa pamamagitan ng HTTP_PROXY listener:

- **macOS:** `networksetup -setwebproxy / -setsecurewebproxy`
- **Linux:** `gsettings set org.gnome.system.proxy` + `/etc/environment`
- **Windows:** `netsh winhttp set proxy 127.0.0.1:8080`
  **Saklaw:** Bawat application sa machine na sumusunod sa mga system proxy setting
  **Tandaan:** `source` = `"system-proxy"`

**Mga mekanismo sa kaligtasan:**

- Timer para sa awtomatikong pag-disable (default na 30 min, maaaring i-configure sa pamamagitan ng `INSPECTOR_SYSTEM_PROXY_GUARD_MINUTES`)
- Sine-save sa DB ang dating estado ng system proxy at nire-restore kapag nag-revert
- Ipinapakita ng dashboard ang prompt na "Ibinabalik ang system proxy" kung aalis ang user sa page habang aktibo ito
- Ipinapakita ng UI ang badge na `⚠ Advanced` + tahasang checkbox ng pagkumpirma

### Mode 5 — TPROXY transparent decrypt (Linux, root, opt-in)

**Pinagmulan:** Kernel TPROXY + policy routing (`src/mitm/tproxy/`)
**Mekanismo:** Minamarkahan ang mga bagong lokal na outbound TCP connection patungo sa target na port (default na `443`) sa `mangle OUTPUT`, nire-reroute ng isang `ip rule` ang mga minarkahang packet tungo sa lokal na delivery, at ipinapasa ng `TPROXY` target ng `mangle PREROUTING` ang mga ito sa isang transparent (**IP_TRANSPARENT**) listener (default na port `8443`). Tinatapos ng listener ang TLS gamit ang isang leaf certificate na ibinibigay **para sa bawat SNI hostname kapag hiniling** ng isang dynamic CA, kino-capture ang na-decrypt na exchange, at ipinapasa ang request na muling na-encrypt sa orihinal na destinasyon.
**Saklaw:** Mga **arbitraryong** destination host sa target na port — walang `/etc/hosts` spoof, walang `HTTP_PROXY` env, walang pagbabago sa system-wide proxy. Hindi nangangailangan ng anumang pagbabago sa configuration ang na-intercept na process, ngunit dapat nitong pagkatiwalaan ang dynamic CA.
**Tandaan:** `source` = `"tproxy"`

**Mga kinakailangan:** Linux lamang (ang **IP_TRANSPARENT** ay para lamang sa Linux), ang **CAP_NET_ADMIN** capability (root), at isang native N-API addon na dapat i-build gamit ang C toolchain (`npm run build:native:tproxy`). Kapag hindi available, naka-disable ang toggle sa dashboard at may tooltip na "Nangangailangan ang TPROXY decrypt ng Linux + root + native addon". Transactional na inilalapat/ibinabalik ang mga firewall rule (hindi kailanman mag-iiwan ang isang crash ng `mangle` rule) at nawawala ang mga ito kapag nag-reboot. Pinipigilan ng isang SO_MARK-based anti-loop na ma-intercept muli ang sariling muling na-encrypt na forward ng proxy.

Isa itong malaking subsystem na may sarili nitong nakalaang gabay para sa operator — tingnan ang `docs/security/MITM-TPROXY-DECRYPT.md` (git; hindi kino-compile sa `/docs`) para sa kumpletong firewall recipe, ang per-SNI dynamic CA + trust-store installer, ang local-only route, mga detalye ng anti-loop, at ang configuration schema. Kinokontrol ang toggle ng `GET / POST / DELETE /api/tools/agent-bridge/tproxy` (tandaan: nasa ilalim ng AgentBridge prefix ang route, hindi sa Traffic Inspector prefix).

## §4 Mga feature na LLM-aware

### 4.1 Detector ng uri (`src/mitm/inspector/kindDetector.ts`)

Inuuri ang bawat request bilang `"llm"`, `"app"`, o `"unknown"` gamit ang 4 na signal:

1. **Registry ng host** — ~18 kilalang hostname ng LLM API (OpenAI, Anthropic, Gemini, Groq, Mistral, Together, Fireworks, Cohere, Perplexity, Hugging Face, OpenRouter, xAI, Moonshot, atbp.)
2. **Mga pattern ng path** — `/v1/chat/completions`, `/v1/messages`, `/generateContent`, `/v1/responses`, atbp.
3. **Hugis ng body** — nakikita ang mga field na `messages[]` (OpenAI/Claude), `contents[]` (Gemini), `prompt`, `input`
4. **Mga pahiwatig ng user-agent** — `codex`, `claude`, `gemini`, `antigravity`, `kiro`, `copilot`, `cursor` sa UA string

Ang mga custom na host na idinagdag sa pamamagitan ng Mode 2 ay nagmamana ng kanilang `kind` mula sa input ng form (naka-default sa `"custom"`).

### 4.2 SSE merger (`src/mitm/inspector/sseMerger.ts`)

**Hiwalay na clean-room implementation.** Ang pag-parse ng event ay sumusunod sa
[WHATWG server-sent events algorithm](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream),
samantalang ang reconstruction ay sumusunod sa mga pampublikong streaming schema ng [OpenAI](https://platform.openai.com/docs/api-reference/chat/create),
[Anthropic](https://platform.claude.com/docs/en/build-with-claude/streaming), at
[Gemini](https://ai.google.dev/api/generate-content#method:-models.streamgeneratecontent).

Binubuo muli ang panghuling mensahe ng assistant mula sa mga raw SSE delta event:

- **Anthropic**: iniipon ang `content_block_delta` ayon sa index; pinangangasiwaan ang `text_delta`, `input_json_delta` (mga tool call), `thinking_delta`
- **OpenAI**: iniipon ang mga choice/tool call ng Chat Completions at mga output item ng Responses API
  ayon sa index
- **Gemini**: iniipon ang `candidates[i].content.parts`
- **Unknown**: ibinabalik ang mga raw event nang walang pagbabago

Nagpapakita ang tab na Response ng toggle: **"Mga raw event ↔ Pinagsama"**.

### 4.3 Conversation normalizer (`src/mitm/inspector/conversationNormalizer.ts`)

**Hiwalay na clean-room implementation.** Tinutukoy ang normalization ng mga lokal na black-box
contract at ng mga pampublikong message schema ng OpenAI, Anthropic, at Gemini; walang ginagamit na
source ng upstream implementation.

Kino-convert ang mga format ng mensahe ng OpenAI, Anthropic, at Gemini sa iisang `NormalizedConversation` bago i-render:

```ts
interface NormalizedConversation {
  request: NormalizedTurn[]; // mga mensahe / nilalaman / prompt mula sa body ng request
  response: NormalizedTurn[]; // tugon ng assistant (pinagsama sa pamamagitan ng sseMerger)
  contextKey: string | null; // SHA-256 fingerprint ng system prompt
}
```

Mga uri ng block: `text`, `tool_use`, `tool_result`. Ginagamit ng tab na Conversation ang hugis na ito anuman ang provider.

### 4.4 Pagbibigay-kulay sa context key (`src/mitm/inspector/contextKey.ts`)

- Kinukuwenta ang `SHA-256` ng system prompt (unang mensaheng `role:system`, o field na `system`, o `systemInstruction` ng Gemini)
- Nagbabalik ng 12-character na hex prefix (`"a3f9c2..."`)
- Itinatapat ng frontend ang key sa isang deterministic na HSL color para sa bar sa kaliwang border
- **Filter na "same context"**: kapag na-click ang chip na `ctx #a3f`, nagdaragdag ito ng filter upang ipakita lamang ang mga request na may parehong fingerprint

Pinapadali nito ang biswal na pagkilala sa magkakaibang "persona" o gawaing tumatakbo sa iisang session ng agent.

### 4.5 Pagkuha ng LLM metadata

Para sa mga LLM request, kinukuha ng tab na LLM Details ang:

```ts
interface LlmMetadata {
  provider: string | null; // "openai" | "anthropic" | "gemini" | ...
  apiKind: string | null; // "chat.completions" | "messages" | "embeddings" | ...
  model: string | null; // mula sa body ng request o tugon
  messages: number; // bilang ng mga turn
  tokensIn: number | null; // usage.prompt_tokens / usage.input_tokens
  tokensOut: number | null; // usage.completion_tokens / usage.output_tokens
  streamed: boolean; // true kung SSE ang tugon
  mappedTo: string | null; // x-omniroute-mapped header
  costEstimateUsd: number | null; // tinatayang gastos batay sa pagpepresyo ng OmniRoute
}
```

### 4.6 Live na filter ng mga kasalukuyang pinoprosesong request

Ang field na `status` ng request ay `number | "in-flight" | "error"` — itinutulak ang isang entry
bilang `"in-flight"` sa mismong sandaling magsimula ang request at **ina-update sa mismong puwesto**
kapag dumating ang tugon (o error). Nililimitahan ng toggle na **"Live"** sa toolbar
(`liveOnly`, i18n key na `trafficInspector.liveOnly`) ang listahan sa mga entry
na may `status === "in-flight"`, kaya maaari mong subaybayan ang mga bukas na koneksyon nang real time.

Ang filter ay isang purong client-side predicate sa
`src/lib/inspector/matchesTrafficFilter.ts`:

```ts
if (f.liveOnly && req.status !== "in-flight") return false;
```

Nasa `useTrafficFilters` ang state ng toggle (ang mga hook ng inspector dashboard) at
pinagsasama ito sa iba pang mga filter (profile, host, agent, source, status, context).

### 4.7 Pag-uugnay sa proseso (Linux)

Sa Linux, maaaring iugnay ang bawat na-intercept na request sa **pinagmulan nitong lokal na
proseso**. Dalawang opsyonal na field ang idinaragdag sa `InterceptedRequest`:

```ts
pid?: number;          // id ng pinagmulan na proseso (Linux lamang)
processName?: string;  // pangalan ng pinagmulan na proseso (Linux lamang)
```

Itinatapat ng `src/mitm/inspector/processAttribution.ts` ang ephemeral port ng _client_
ng koneksyon sa isang PID + pangalan sa pamamagitan ng:

1. Pagbasa sa `/proc/net/tcp` at `/proc/net/tcp6` upang mahanap ang socket inode para sa
   port (`parseProcNetTcpForInode`, isang purong parser na nasusubukan gamit ang mga fixture).
2. Pag-scan sa `/proc/<pid>/fd/` para sa symlink patungo sa `socket:[<inode>]`.
3. Pagbasa sa pangalan ng proseso mula sa `/proc/<pid>/comm`.

Nililimitahan ng cache na may 1-segundong TTL ang gastos sa pag-scan ng procfs kapag mataas ang load. Ang pag-uugnay ay
**best-effort** — ang anumang pagkabigo ay nagre-resolve sa `null` at hindi kailanman humaharang sa capture. Sa
macOS/Windows, nagbabalik ang function ng `null` (stub; ang suporta para sa `lsof`/`GetExtendedTcpTable`
ay nakalaan bilang kasunod na gawain).

## §6 Seguridad

Ipinapakita ng Traffic Inspector ang **lahat ng na-intercept na trapiko ng HTTPS**, kabilang ang mga authorization header at body ng request. Ipinapatupad ang mga sumusunod na kontrol:

| Kontrol                               | Mga detalye                                                                                                                                                                                   |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LOCAL_ONLY**                        | Loopback-only ang lahat ng route at ang WebSocket endpoint (ipinapatupad sa `routeGuard.ts` bago ang auth)                                                                                    |
| **Pagtatakip ng secret**              | Inaalis ng linear na scanner na `maskSecret()` ang mga RFC 6750 Bearer credential, key na may prefix ng provider, at mahahabang opaque token bago ang `TrafficBuffer.push()`                  |
| **Limitasyon sa laki ng body**        | Ang mga body na > `INSPECTOR_MAX_BODY_KB` (default na 1024 KB) ay pinuputol na may abisong `"(pinutol para sa performance)"`                                                                  |
| **Paglilinis ng header**              | Kino-convert sa lowercase ang mga pangalan; inaalis ang mga framing/hop-by-hop at proxy-auth header; ganap na inaalis ang mga cookie; ipinapasa sa `maskSecret()` ang mga value ng credential |
| **CSP**                               | Mahigpit na Content Security Policy sa mga page ng Traffic Inspector upang pigilan ang XSS sa pamamagitan ng mga na-inject na response body                                                   |
| **Walang persistence bilang default** | Nasa memory lang ang `TrafficBuffer` at nawawala kapag nag-restart ang server. Pine-persist lamang ang mga session kapag tahasang ni-record                                                   |

### Mga inilalapat na Mahigpit na Panuntunan

| Panuntunan                        | Paglalapat                                                                                      |
| --------------------------------- | ----------------------------------------------------------------------------------------------- |
| **#12** `sanitizeErrorMessage`    | Nililinis ang lahat ng HTTP error response mula sa mga route ng Traffic Inspector               |
| **#15 + #17** `isLocalOnlyPath()` | Ang `/api/tools/traffic-inspector/` ay LOCAL_ONLY + SPAWN_CAPABLE (mga command ng system proxy) |

### Mga kilalang limitasyon

- Naaapektuhan ng **system-wide proxy mode** ang lahat ng application sa machine, kabilang ang mga VPN client at SSO. Palaging gamitin ito nang may timer para sa awtomatikong pag-disable. Huwag gamitin sa mga shared na machine.
- **CONNECT tunnel HTTPS**: Nakukuha lamang ng Mode 3 (HTTP_PROXY) ang metadata ng tunnel para sa mga HTTPS destination maliban kung naka-enable ang TLS interception. Sinadya ito — ang transparent na pagkuha nang hindi pinagkakatiwalaan ang AgentBridge cert ay makakasira sa TLS verification para sa mga app na iyon.
- **Mga hardcoded na string sa ilang component**: May kaunting hardcoded na string ang ilang UI component (F7/F8) na hindi pa saklaw ng mga i18n key. Nakadokumento ang mga ito bilang Kilalang Limitasyon sa ulat ng puwang sa i18n; ima-migrate ang mga ito sa susunod na pass. Ang mga apektadong string ay mga dekoratibong label ng UI na hindi kailangang isalin para sa functional na paggamit.

## §7 Pag-troubleshoot

### Pagkadiskonekta ng WebSocket

Kung ipinapakita ng live tail ang "Nadiskonekta":

1. Tiyaking tumatakbo pa rin ang server: `GET /api/tools/traffic-inspector/capture-modes`
2. I-reload ang page — muling kokonekta ang WebSocket at tatanggap ng bagong snapshot
3. Kung na-restart ang server, na-clear ang in-memory buffer — wala na ang mga lumang entry maliban kung may na-record na session

### Salungatan sa port 8080

Kung hindi makapagsimula ang HTTP_PROXY mode:

```bash
lsof -i :8080    # hanapin ang proseso
```

Palitan ang port:

```bash
# .env
INSPECTOR_HTTP_PROXY_PORT=8888
```

### Hindi naibalik ang system proxy

Kung mag-crash ang OmniRoute habang aktibo ang system-wide proxy mode:

**macOS:**

```bash
networksetup -setwebproxystate Wi-Fi off
networksetup -setsecurewebproxystate Wi-Fi off
```

**Linux (GNOME):**

```bash
gsettings set org.gnome.system.proxy mode 'none'
```

**Windows:**

```cmd
netsh winhttp reset proxy
```

Mag-aalok din ang dashboard ng "Ibalik ang system proxy" sa susunod na pag-load kung matutukoy nitong ipinapahiwatig ng estado ng DB na aktibo ang proxy.

### Puno ang buffer

Kapag naabot ng buffer ang `INSPECTOR_BUFFER_SIZE` (default na 1000), aalisin ng mga bagong entry ang mga pinakaluma. Kung nawawala ang mahahalagang request:

- Taasan ang `INSPECTOR_BUFFER_SIZE` (hal., 5000) — kapalit ng mas mahabang retention ang mas malaking paggamit ng memory
- Mag-record ng session upang mapanatili sa DB ang nauugnay na window

## §8 Sanggunian ng API

Ang lahat ng route ay `LOCAL_ONLY` (loopback-only) at `SPAWN_CAPABLE` (mga command ng system proxy). Tingnan ang `src/server/authz/routeGuard.ts`.

### Pamamahala ng request

| Paraan | Path                        | Paglalarawan                                                                                       |

| DELETE | `/requests`                 | I-clear ang in-memory buffer                                                                       |
| POST   | `/requests/{id}/replay`     | Isagawang muli ang parehong request sa pamamagitan ng OmniRoute router                             |

### Pag-export
