> **Pinagmumulan ng katotohanan:** `src/lib/obsidian/api.ts` (REST + sync client),
> `src/lib/db/obsidian.ts` (pagpapanatili ng token / base-URL / WebDAV),
> `src/lib/obsidianSync.ts` (WebDAV vault sync), `open-sse/mcp-server/tools/obsidianTools.ts`
> (22 MCP tool), `src/app/api/settings/obsidian/route.ts` +
> `src/app/api/settings/obsidian/webdav/route.ts` (mga settings API). Ang pagpaparehistro
> ng tool at pagkakabit ng scope ay nasa `open-sse/mcp-server/server.ts`.

## Ano ito

Kumokonekta ang OmniRoute sa isang **Obsidian** vault bilang **pinagmumulan ng konteksto** — isang lokal na
Markdown knowledge base na binabasa at sinusulatan ng mga agent sa pamamagitan ng built-in na MCP server. Ang
integration ay nakikipag-ugnayan sa **Obsidian Local REST API** community plugin na tumatakbo sa loob ng
desktop app, kaya maaaring maghanap ang mga agent sa mga note, magbasa/magsulat/mag-patch ng mga file, ilista ang vault, gumawa
sa mga pang-araw-araw/panglingguhang periodic note, mamahala ng mga tag, magpatakbo ng mga Obsidian command, at (opsyonal)
mag-coordinate ng bidirectional na desktop↔mobile vault sync.

Binabalot ng client (`src/lib/obsidian/api.ts`) ang Local REST API gamit ang:

- **Muling pagsubok na may backoff** para sa pansamantalang `5xx`, **30-segundong timeout** sa pamamagitan ng `AbortController`.
- **Typed na pag-uuri ng error** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- Isang **madaling maunawaang pahiwatig na "hindi maabot ang Obsidian"** na binibigyang-diin ang karaniwang pagkakamali sa port
  (HTTP sa `27123`, **hindi** ang MCP endpoint sa `27124`) at ang anyo para sa Tailscale.
- **Path encoding** na relative sa vault upang maging ligtas ang mga path ng note na may mga space/slash.

## Pag-setup

**Walang environment variable** para sa Obsidian token o base URL — parehong
iniimbak sa SQLite `key_value` table (namespace `obsidian`) sa pamamagitan ng
`src/lib/db/obsidian.ts`. Ang token ay **naka-encrypt habang nakaimbak** (AES-256-GCM, na may
plaintext fallback para sa backward compatibility). I-configure mula sa tab na **Context Sources** ng
Endpoint dashboard (`ObsidianSourceCard`), o sa pamamagitan ng settings REST API.

> [!IMPORTANT]
> Dapat naka-install at tumatakbo ang **Obsidian Local REST API** plugin. Nakikinig ang REST
> interface nito sa **HTTP `127.0.0.1:27123`** (ang default na base URL). Ang port `27124`
> ay isang _hiwalay_ na MCP/HTTPS endpoint at tahasang tinatanggihan ng settings route.
> Kung kumokonekta mula sa ibang device, gamitin ang `http://<tailscale-ip>:27123`.

### Mga configuration key (SQLite `key_value`, namespace `obsidian`)

| Key               | Layunin                                                 | Naka-encrypt |
| ----------------- | ------------------------------------------------------- | ------------ |
| `api_key`         | Local REST API bearer token                             | oo           |
| `base_url`        | REST base URL (default `http://127.0.0.1:27123`)        | hindi        |
| `vault_path`      | Absolute path patungo sa vault directory (para sa sync) | hindi        |
| `webdav_username` | Nabuong WebDAV username (vault sync)                    | hindi        |
| `webdav_password` | Nabuong WebDAV password (vault sync)                    | oo           |
| `webdav_enabled`  | Kung naka-enable ang WebDAV vault sync                  | hindi        |

### I-configure sa pamamagitan ng REST

```bash
# I-save at i-validate ang Local REST API token (nagva-validate ang POST sa pamamagitan ng status check)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Suriin ang status ng koneksyon (ibinabalik ang connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# Idiskonekta (binubura ang nakaimbak na token)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Nangangailangan ang lahat ng method ng dashboard authentication. Tinatanggihan ng `POST` ang anumang URL sa port `27124`
at vina-validate ang token sa pamamagitan ng pagtawag sa status endpoint ng Local REST API bago ito i-save.

### WebDAV vault sync

Pinamamahalaan ng `src/app/api/settings/obsidian/webdav/route.ts` ang isang opsyonal na WebDAV-backed na
vault sync (na pinapatakbo ng `src/lib/obsidianSync.ts`). Kapag in-enable ito, itinuturo nito ang OmniRoute sa isang
lokal na vault directory at bumubuo ng random na WebDAV username/password pair:

```bash
# I-enable ang WebDAV sync para sa isang vault directory (bumubuo ng username/password)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# Kunin ang status ng WebDAV sync (ibinabalik lamang ang mga credential habang naka-enable)
curl http://localhost:20128/api/settings/obsidian/webdav

# I-disable ang WebDAV sync (binubura ang mga credential + pinamamahalaang .stignore)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Pinagmumulan ng konteksto para sa bawat API key (opsyonal)

Maaaring i-scope ang Obsidian config **para sa bawat API key** sa pamamagitan ng `api_key_context_sources` table
(`src/lib/db/apiKeyContextSources.ts`). Kapag may dalang authenticated na API
key id ang isang MCP call, inuuna ng `getObsidianConfigForApiKey()` ang sariling token/base-URL/vault-path
ng key na iyon (`source: "api_key"`) at kung wala, ginagamit nito ang global config bilang fallback (`source: "global"`).

## Mga MCP tool (22)

Tinukoy sa `open-sse/mcp-server/tools/obsidianTools.ts`. Nireresolba ang token/base-URL
sa bawat tawag (API key muna, pagkatapos ay global). Ang mga tool na kumokonekta sa **sync server**
ng OmniRoute (ang apat na `obsidian_sync_*` tool) ay nangangailangan din ng sync auth token na naka-configure
sa mga setting ng OmniRoute.

### Mga tool sa pagbasa (`read:obsidian`)

| Tool                         | Paglalarawan                                                                                                   |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Suriin kung naaabot at authenticated ang Local REST API.                                                       |
| `obsidian_search_simple`     | Full-text na paghahanap sa nilalaman ng note; nagbabalik ng mga snippet na may mga file path.                  |
| `obsidian_search_structured` | Maghanap gamit ang isang JSON Logic expression (mga filter na and/or/regex/path).                              |
| `obsidian_read_note`         | Basahin ang isang note ayon sa path na relative sa vault; opsyonal na partikular na heading/block/frontmatter. |
| `obsidian_list_vault`        | Ilista ang mga file at directory sa vault (tree ng mga entry).                                                 |
| `obsidian_get_document_map`  | Kunin ang estruktura ng heading ng note bilang mapa ng mga heading → numero ng linya.                          |
| `obsidian_get_note_metadata` | Kunin ang frontmatter, mga tag, link, at bilang ng character/salita nang wala ang buong nilalaman.             |
| `obsidian_get_active_file`   | Kunin ang path + nilalaman ng kasalukuyang aktibong file sa Obsidian.                                          |
| `obsidian_get_periodic_note` | Kunin ang pang-araw-araw/panlingguhan/buwanang periodic note para sa isang petsa (ngayon kung hindi tinukoy).  |
| `obsidian_get_tags`          | Ilista ang lahat ng tag sa vault kasama ang dalas ng paglitaw ng mga ito.                                      |
| `obsidian_list_commands`     | Ilista ang mga available na Obsidian command ID (gamitin kasama ng `obsidian_execute_command`).                |
| `obsidian_sync_status`       | Status ng sync server ng OmniRoute: gumagana, pangalan ng vault, port, uptime, huling sync.                    |
| `obsidian_sync_conflicts`    | Ilista ang mga hindi pa nareresolbang sync conflict (path, conflict path, oras ng pagkakatukoy).               |

### Mga tool sa pagsusulat (`write:obsidian`)

| Tool                             | Paglalarawan                                                                                             |
| -------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Gumawa o mag-overwrite ng note gamit ang ibinigay na nilalamang Markdown.                                |
| `obsidian_append_note`           | Magdagdag ng nilalaman sa isang note; opsyonal na sa isang partikular na heading/block.                  |
| `obsidian_patch_note`            | Tiyak na mag-append/mag-prepend/magpalit sa isang heading, block, o field ng frontmatter.                |
| `obsidian_delete_note`           | Permanenteng burahin ang isang note mula sa vault.                                                       |
| `obsidian_move_note`             | Ilipat o palitan ang pangalan ng isang note sa loob ng vault.                                            |
| `obsidian_execute_command`       | Magpatupad ng Obsidian command ayon sa command ID nito.                                                  |
| `obsidian_open_file`             | Magbukas ng file sa Obsidian (gagawa nito kung hindi pa ito umiiral).                                    |
| `obsidian_sync_trigger`          | Mag-trigger ng agarang bidirectional na desktop↔mobile vault sync.                                       |
| `obsidian_sync_resolve_conflict` | Resolbahin ang isang sync conflict: panatilihin ang `local` (mobile), `remote` (desktop), o `keep-both`. |

> [!NOTE]
> Ang mga target ng `obsidian_patch_note` ay tumatanggap ng `targetType` na `heading | block | frontmatter`
> at `operation` na `append | prepend | replace`, na may opsyonal na
> `createTargetIfMissing`. Ang apat na `obsidian_sync_*` tool ay nakikipag-ugnayan sa lokal na sync
> server (`http://127.0.0.1:27781` bilang default) at nangangailangan ng sync token.

### Mga scope

Nangangailangan ang mga tool sa pagbasa ng `read:obsidian`; nangangailangan ang mga tool sa pagsusulat ng `write:obsidian`. Ang pagpapatupad
ay kapareho ng sa Notion — pinangangasiwaan ng `withScopeEnforcement()` sa
`open-sse/mcp-server/server.ts`, nakadepende sa `OMNIROUTE_MCP_ENFORCE_SCOPES=true`, at ang mga
pinapayagang scope ay kinukuha mula sa `OMNIROUTE_MCP_SCOPES` o sa scope context ng API key. Tingnan ang
[MCP-SERVER.md](./MCP-SERVER.md).

## Mga Endpoint

| Paraan   | Path                            | Layunin                                                             |
| -------- | ------------------------------- | ------------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | Ibalik ang `{ connected, hasToken, baseUrl, vaultPath }`.           |
| `POST`   | `/api/settings/obsidian`        | I-save at i-validate ang token (tinatanggihan ang port na `27124`). |
| `DELETE` | `/api/settings/obsidian`        | Idiskonekta (burahin ang nakaimbak na token).                       |
| `GET`    | `/api/settings/obsidian/webdav` | Status ng WebDAV sync at mga kredensyal (habang naka-enable).       |
| `POST`   | `/api/settings/obsidian/webdav` | I-enable ang WebDAV sync para sa isang vault directory.             |
| `DELETE` | `/api/settings/obsidian/webdav` | I-disable ang WebDAV sync.                                          |

> Ang mga ito ay mga route ng mga setting ng dashboard. Naa-access ang vault mismo sa pamamagitan ng Obsidian
> Local REST API (ang naka-configure na `base_url`) at sa pamamagitan ng mga MCP tool sa itaas — walang
> pampublikong `/v1` Obsidian proxy endpoint.

## Mga sitwasyon ng paggamit

- **Mga sagot na nakabatay sa vault** — `obsidian_search_simple` / `obsidian_search_structured`
  pagkatapos ay `obsidian_read_note` upang sumagot ang isang agent batay sa iyong mga aktuwal na tala.
- **Pagsulat ng tala / pag-journal** — `obsidian_write_note`, `obsidian_append_note`, o
  ang eksaktong `obsidian_patch_note` upang i-log sa vault ang output ng agent, mga buod, o mga pang-araw-araw na tala
  (`obsidian_get_periodic_note`).
- **Pag-navigate sa vault** — `obsidian_list_vault`, `obsidian_get_document_map`, at
  `obsidian_get_tags` upang galugarin ang istruktura bago magbasa/magsulat.
- **Pag-automate ng Obsidian** — `obsidian_list_commands` + `obsidian_execute_command` upang
  patakbuhin ang mga plugin/command mula sa isang agent; `obsidian_open_file` upang ipakita ang isang tala sa UI.
- **Pag-sync sa mobile** — i-enable ang WebDAV sync, pagkatapos ay gamitin ang `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  upang i-coordinate ang desktop↔mobile at lutasin ang mga conflict.
