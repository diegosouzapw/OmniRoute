> **Pinagmumulan ng katotohanan:** `src/lib/localCorpus/index.ts` (indeks ng tekstong may hangganan),
> `src/lib/localCorpus/configured.ts` (naka-configure na runtime),
> `src/lib/db/localCorpus.ts` (pagpapanatili ng root path),
> `open-sse/mcp-server/tools/localCorpusTools.ts` (3 read-only na MCP tool), at
> `src/app/api/settings/local-corpus/route.ts` (settings API).

## Ano ito

Pinahihintulutan ng Local Corpus ang isang operator na ilantad sa MCP server ng
OmniRoute ang isang tahasang inaprubahang direktoryo ng mga text file. Nananatili ang
mga file sa orihinal nilang direktoryo: ang canonical root path lamang ang iniimbak ng
OmniRoute sa SQLite, at nagpapanatili ito ng in-memory na search index. Hindi nito
kinokopya ang nilalaman ng corpus sa repository o database.

Incremental ang pag-refresh ng indeks. Muling ginagamit ang mga hindi nabagong file
batay sa laki at oras ng pagbabago, muling binabasa at hina-hash gamit ang SHA-256 ang
mga nabagong file, at inaalis ang mga naburang file. Nire-refresh ng paghahanap ang
indeks na mahigit 30 segundo na; maaari ring humiling ang mga tumatawag ng agarang
pag-refresh.

## I-configure ang pinagmulan

Kinakailangan ng settings route ang kaparehong management authentication na ginagamit
ng iba pang settings API. Dapat umiiral na ang isinumiteng path at dapat itong isang
absolute directory path.

```bash
# Ikonekta ang isang inaprubahang direktoryo
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# Suriin ang configuration at status ng indeks
curl http://localhost:20128/api/settings/local-corpus

# Idiskonekta nang hindi binabago ang mga source file
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## Mga MCP tool

Kinakailangan ng lahat ng tatlong tool ang `read:local-corpus`. Inilalantad ng mga tugon
ng tool ang mga relative path at ang basename ng root directory, ngunit hindi kailanman
ang absolute path nito.

| Tool                  | Paglalarawan                                                                                                               |
| :-------------------- | :------------------------------------------------------------------------------------------------------------------------- |
| `local_corpus_status` | Iulat ang estado ng configuration, laki ng indeks, mga limitasyon, at oras ng huling pag-refresh                           |
| `local_corpus_search` | Maghanap sa naka-index na teksto at magbalik ng mga snippet na may hangganan at saklaw ayon sa linya (hanggang 20 resulta) |
| `local_corpus_read`   | Magbasa ng limitadong saklaw ng mga linya mula sa isang pinahihintulutang corpus-relative na file                          |

Mga halimbawang MCP input:

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## Mga hangganan sa kaligtasan

- Nakatuon sa teksto ang allowlist: `.cfg`, `.csv`, `.geojson`, `.htm`, `.html`, `.ini`,
  `.js`, `.json`, `.jsonl`, `.jsx`, `.log`, `.md`, `.mjs`, `.ps1`, `.py`, `.sh`,
  `.sql`, `.toml`, `.ts`, `.tsx`, `.txt`, `.xml`, `.yaml`, at `.yml`.
- Nilalaktawan ang mga symlink. Kino-canonicalize ang mga read path at dapat manatili
  ang mga ito sa loob ng naka-configure na root; tinatanggihan ang mga absolute path at
  pagtatangkang mag-traverse.
- Hindi isinasama ang mga pangalan ng sensitibo at nabuong direktoryo: `.build`, `.codex`, `.env`,
  `.git`, `.next`, `.omniroute`, `.ssh`, `coverage`, `dist`, `node_modules`, at
  `secrets`.
- Ang mga default na limitasyon ay 5,000 file, 1 MiB bawat file, 64 MiB ng kabuuang
  naka-index na nilalaman, humigit-kumulang 4,000 character bawat search chunk, at 400
  linya bawat pagbasa.
- Ang mga file na naglalaman ng NUL ay itinuturing na hindi teksto at nilalaktawan o
  tinatanggihan.

Sadyang hindi sinusuportahan ang mga binary document gaya ng PDF, DOCX, mga larawan, at
archive. I-convert ang mga ito sa isang inaprubahang format ng teksto sa naka-configure
na direktoryo bago i-index.

## Mga tala sa operasyon

- Ang pagbabago o pagbura sa naka-configure na root ay nagki-clear sa pinagsasaluhang
  in-memory na indeks.
- Itinatapon ng pag-restart ng proseso ang indeks; muli itong binubuo ng susunod na
  paghahanap mula sa naka-configure na pinagmulan.
- Hindi pinipilit ng `local_corpus_status` ang pag-scan. Gamitin ang
  `local_corpus_search` na may `refresh: true` kapag kinakailangan ang agarang muling
  pag-scan.
- Binibilang o ibinabalik bilang mga na-sanitize na error ang mga pagkabigo sa pag-scan
  at pagbasa; hindi kailanman binabago ang mga source file.
