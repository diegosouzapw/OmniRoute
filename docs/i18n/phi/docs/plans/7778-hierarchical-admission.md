1. I-lock ang kasalukuyang kontrata ng single-key semaphore at ang bagong atomic multi-key
   na kontrata gamit ang mga nakatuong test: walang bahagyang reservation, FIFO queueing, abort,
   timeout, queue-full, idempotent release, stats, at cleanup.
2. I-generalize sa kasalukuyang puwesto ang umiiral na account semaphore. Panatilihin ang `acquire()` bilang
   compatibility wrapper sa `acquireMany()`; huwag magdagdag ng pangalawang scheduler
   o dependency.
3. Palitan ang account-only acquisition sa `chatCore` ng isang pinagsama-samang
   global/provider/account acquisition kaagad bago ang `withRateLimit`.
   Muling kunin ang buong set tuwing binabago ng account rotation ang connection,
   at panatilihin ang release hanggang sa makumpleto ang streaming.
4. Palawakin ang kasalukuyang pipeline ng resilience settings (mga type, default,
   normalization, schema, API response, UI, at mga salin) gamit ang global
   at provider caps. Palitan ang label ng lumang Bottleneck concurrency control bilang
   connection/quota-scope concurrency upang maging tahasan ang tunay nitong scope.
5. Patakbuhin ang mga nakatuong test, lint, typecheck, static checks, at ang buong test suite;
   idokumento ang pagbabago sa gawi sa changelog.

Mga gawing sinadyang panatilihin: nilalampasan ng zero/null concurrency ang isang gate,
patuloy na gumagamit ng `acquire()` ang mga account-only caller, pinananatili ng
blocked-account controls ang kanilang key format at API, at nananatiling
hindi nagbabago ang gawi ng provider rate-limit queue.
