Ang upstream gateway na `agentrouter` ay nagpapatakbo ng content filter na nakabatay sa keyword sa
`messages[].content`. Bahagyang deterministic ang filter (palaging bina-block ang
ilang partikular na parirala) at bahagyang probabilistic (sensitibo sa burst — nagiging
mas agresibo pagkatapos ng mabilisang sunod-sunod na request at bumabalik sa normal pagkatapos ng cooldown).

Kapag bina-block ng WAF ang isang request, ibinabalik nito ang:

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## Saklaw ng filter

Sinusuri lamang ng WAF ang `messages[].content`. **Hindi** nito sinusuri ang:

- `system` prompt
- Mga structured content block (`tool_result`, `tool_use`, `thinking`, `image`)
- Mga field na `description` at `input_schema` ng tool
- Metadata ng request, mga header, o model id

## Mga pattern na palaging bina-block (hindi sensitibo sa laki o liit ng titik)

| Pattern                          | Mga tala                                                       |
| -------------------------------- | -------------------------------------------------------------- |
| Anumang variant ng `Lorem ipsum` | Bina-block ang buong bokabularyong Latin lorem                 |
| `language model` (nang mag-isa)  | Nakakalusot ang "the language model" at "large language model" |
| `virtual assistant`              | Nakakalusot ang "AI assistant"                                 |
| `I'm here to help`               | Bina-block din ang "here to help" nang mag-isa                 |
| `Claude, made by Anthropic`      | Buong parirala lamang                                          |

## Mga pattern na halos palaging bina-block

| Pattern                                                          | Mga tala                                                                    |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `placeholder`                                                    | Kapag nakatayo ito nang mag-isa (hindi bilang pangalan ng parameter, atbp.) |
| `dummy data`                                                     | Karaniwang seed phrase para sa mga fixture                                  |
| `foo bar baz`                                                    | Kanonikal na placeholder phrase                                             |
| Mga inuulit na maiikling token (`AAA BBB CCC`, `test test test`) | Detector para sa keyword stuffing                                           |

## Pag-uugali kapag mataas ang load

Pagkatapos ng ~5 mabilisang request sa loob ng maikling panahon, nagsisimulang mag-block ang WAF ng content
na karaniwang makakalusot. Lumaluwag ang bucket pagkatapos ng ~5–10 segundo na walang
aktibidad. Ito rin ang rate limiter na nakatali sa parehong IP at key na nagdudulot ng
paminsan-minsang `400 content-blocked` error kapag gumagawa ang Claude Code o Codex CLI
ng maraming tool-use / message-send call nang mabilis at sunod-sunod.

## Mga mitigation na nailapat na sa OmniRoute

1. **`open-sse/services/wafRateLimit.ts`** — burst guard na nagpapatupad ng
   minimum na 500 ms na pagitan sa mga outbound request patungo sa anumang `agentrouter:*`
   URL. Ang pagitan ay mas maikli kaysa sa latensyang mapapansin ng tao at pinipigilan nitong
   ma-activate ang WAF sa normal na traffic.

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — kapag nagbalik ang upstream ng
   `400 content-blocked`, sinusubukang muli ng executor ang parehong URL gamit ang
   exponential backoff (1.5 s, 3.0 s, maximum na 2 pagtatangka). Pagkatapos ng backoff,
   karaniwang lumuluwag ang WAF at nagtatagumpay ang muling pagtatangka.

3. **`tests/unit/compression/harness.test.ts`** — binago ang test fixture na
   `longInput` mula sa `"lorem ipsum dolor sit amet ".repeat(40)`
   patungo sa `"example content for testing purposes ".repeat(40)` upang kapag
   binasa ng Claude Code ang file na ito sa pamamagitan ng tool na `Read`, hindi
   dumaloy pabalik ang nilalaman ng file sa isang `tool_result` block at ma-trigger ang WAF.

## Gabay para sa mga prompt at output ng tool

Kung paulit-ulit na nakakatanggap ang isang session ng Claude Code o Codex CLI ng
`400 content-blocked`, tingnan ang pinakabagong mensahe ng user at ang pinakabagong
resulta ng tool para sa alinman sa mga pattern sa itaas at muling ipahayag ang mga ito.
Mga karaniwang workaround:

- Palitan ang `Lorem ipsum …` ng `example text …` o ng aktuwal na content
  na sinusubukang imodelo ng test o fixture.
- Palitan ang `placeholder` (kapag nakatayo nang mag-isa) ng `example value`,
  `sample value`, o ng tunay na value.
- Palitan ang `language model` ng `large language model` o `the model`.
- Palitan ang `dummy data` ng `sample data` o makatotohanang mga seed value.
- Palitan ang `I'm here to help` / `here to help` ng mas partikular na
  pambungad (hal. "I'll review the file you mentioned").

## Pag-uulat ng mga false positive sa upstream

Masyadong agresibo ang kasalukuyang filter — bina-block nito ang "Lorem ipsum" sa
mga `tool_result` block kahit malinaw na hindi nilayon ng operator na
mag-inject ng prompt. Ang mga operator na gustong maayos ito sa pinagmulan ay dapat
makipag-ugnayan sa `agentrouter.org` upang iulat ang mga false positive. Ang blocklist
sa itaas ay ang empirikal na resulta ng pagsubok sa upstream noong 2026-08-03.
