> **TL;DR**: Itakda ang iyong model sa `auto` at awtomatikong pipiliin ng OmniRoute ang pinakamahusay na AI provider para sa bawat request. Walang kailangang configuration.

---

## Ano ang Ginagawa Nito

Sa halip na pumili ng partikular na AI model (tulad ng GPT-4o o Claude), maaari mong hayaan ang OmniRoute na **awtomatikong piliin ang pinakamahusay** para sa bawat request. Isinasaalang-alang nito ang:

- **Kalagayan** — Gumagana ba ngayon ang provider?
- **Bilis** — Gaano ito kabilis?
- **Gastos** — Magkano ang halaga nito?
- **Kalidad** — Mahusay ba ito sa ganitong uri ng gawain?
- **Kapasidad** — May natitira pa ba itong quota?

Binibigyan ng OmniRoute ng score ang lahat ng nakakonekta mong provider at pinipili ang pinakamahusay. Kung mabigo ito, awtomatiko nitong susubukan ang susunod.

---

## Mabilisang Pagsisimula

**Hakbang 1**: Itakda ang iyong model sa `auto` sa iyong IDE o CLI:

```
model: "auto"
```

**Hakbang 2**: Iyon lang! OmniRoute na ang bahala sa iba.

**Hakbang 3** (opsyonal): Gumamit ng variant para sa mga partikular na gawain:

```
model: "auto/coding"    # Pinakamahusay para sa code
model: "auto/fast"      # Pinakamabilis na tugon
model: "auto/cheap"     # Pinakamurang opsyon
```

## Aling "auto" ang Dapat Kong Gamitin?

| Kung gusto mo ng...        | Gamitin ito    | Pinakamahusay para sa              | Paano ito gumagana                                        |
| -------------------------- | -------------- | ---------------------------------- | --------------------------------------------------------- |
| **Pinakamahusay sa lahat** | `auto`         | Mga pangkalahatang tanong, chat    | Binabalanse ang bilis, gastos, at kalidad                 |
| **Pinakamahusay na code**  | `auto/coding`  | Pagsulat ng code, pag-debug        | Pumipili ng mga model na mahusay sa coding                |
| **Pinakamabilis na tugon** | `auto/fast`    | Mabilisang sagot, mababang latency | Inuuna ang bilis kaysa sa lahat                           |
| **Pinakamurang opsyon**    | `auto/cheap`   | Pagtitipid                         | Pinipili ang pinakamurang provider                        |
| **Pinakamatalinong model** | `auto/smart`   | Mga kumplikadong gawain            | Inuuna ang kalidad + sumusubok ng bagong model            |
| **Pinaka-available**       | `auto/offline` | Kapag abala ang mga provider       | Pinipili ang mga provider na may pinakamalaking kapasidad |

### Mga Halimbawa

```bash
# Pangkalahatang chat — balanse
curl http://localhost:20128/v1/chat/completions \

# Pagbuo ng code — inuuna ang kalidad
```

## Paano Ito Gumagana (Simpleng Bersyon)

Kapag nagpadala ka ng request na may `model: "auto"`, ang OmniRoute ay:

1. **Sinusuri ang lahat ng nakakonekta mong provider** — Bawat provider na idinagdag mo (OpenAI, Anthropic, Google, atbp.)
2. **Binibigyan ng score ang bawat isa**, na isinasaalang-alang, bukod sa iba pang bagay, ang:
   - Gumagana ba ito? (kalagayan)
   - May kapasidad ba ito? (quota)
   - Magkano ang halaga nito? (presyo)
   - Gaano ito kabilis? (bilis)
   - Mahusay ba ito sa gawaing ito? (kalidad)
3. **Pinipili ang pinakamahusay** — Ang provider na may pinakamataas na score ang tatanggap ng iyong request
4. **Awtomatikong bumabawi** — Kung mabigo ito, awtomatikong susubukan ng OmniRoute ang susunod

### Ang Sistema ng Pagbibigay ng Score

Ang bawat provider ay nakakakuha ng score mula 0 hanggang 1. Kapag mas mataas ang score, mas angkop ito.

| Salik                 | Timbang | Ano ang ibig sabihin nito                                       |
| --------------------- | ------- | --------------------------------------------------------------- |
| Kalagayan             | 20%     | Gumagana ba ang provider? (circuit breaker state)               |
| Quota                 | 15%     | May natitira pa ba itong kapasidad?                             |
| Gastos                | 15%     | Gaano ito kamahal? (mas mura = mas mataas na score)             |
| Bilis                 | 12%     | Gaano ito kabilis? (mas mababang latency = mas mataas na score) |
| Pagkaangkop sa Gawain | 8%      | Mahusay ba ito sa ganitong uri ng gawain?                       |
| Katatagan             | 5%      | Consistent ba ito? (mababang error rate)                        |
| Tier                  | 5%      | Tier ng account (Ultra > Pro > Free)                            |
| Iba pa                | 20%     | Context affinity, connection density, atbp.                     |

### Paano Binabago ng mga Variant ang Pagbibigay ng Score

Gumagamit ang bawat variant ng magkakaibang timbang:

| Variant        | Inuuna                      | Mga Pangunahing Timbang         |
| -------------- | --------------------------- | ------------------------------- |
| `auto`         | Balanse                     | health=20%, quota=15%, cost=15% |
| `auto/coding`  | Kalidad                     | taskFit=37%, stability=15%      |
| `auto/fast`    | Bilis                       | latency=32%, health=28%         |
| `auto/cheap`   | Gastos                      | cost=37%                        |
| `auto/smart`   | Kalidad + Pag-eeksperimento | taskFit=37%, exploration=10%    |
| `auto/offline` | Kapasidad                   | quota=37%, health=28%           |

## Paano Nito Hinaharap ang mga Pagkabigo

May **tatlong antas ng proteksyon** ang OmniRoute:

### 1. Awtomatikong Fallback

Kung mabigo ang pinakamahusay na provider, awtomatikong susubukan ng OmniRoute ang susunod. Wala kang kailangang gawin.

### 2. Kusang Pag-aayos

Kung patuloy na nabibigo ang isang provider:

- **Score < 0.2** → Hindi isasama sa loob ng 5 minuto
- **Bukas ang circuit breaker** → Awtomatikong hindi isasama
- **Hindi gumagana ang mahigit 50% ng mga provider** → Incident mode (walang exploration)

### 3. Pang-emergency na Fallback

Kung mabigo ang lahat ng provider, bilang huling opsyon ay iruruta ng OmniRoute ang mga request sa mga matatag at libreng provider (gaya ng Kiro o Qoder).

## Suporta sa Maramihang Account

Kung marami kang account para sa iisang provider (hal., dalawang OpenAI key), itinuturing ng OmniRoute ang bawat isa bilang **hiwalay na kandidato**. Ibig sabihin:

- May natitirang quota ang Account A → gamitin ito
- Rate-limited ang Account B → laktawan ito
- Mas mura ang Account C → piliin ito

Hiwalay na binibigyan ng score ang bawat account batay sa sarili nitong kalagayan, quota, at bilis.

---

## Bandit Exploration

Paminsan-minsang **sumusubok** ang OmniRoute ng mga bagong provider upang makahanap ng mas mahuhusay na opsyon:

- **Default**: 5% ng mga request ang ipinapadala sa mga random na provider
- **Auto/smart**: 10% exploration rate
- **Naka-disable** kapag hindi maayos ang lagay ng mahigit 50% ng mga provider

Nakakatulong ito sa OmniRoute na matutuhan kung aling mga provider ang pinakamahusay para sa iyong mga pattern ng paggamit.

## Mga Karaniwang Tanong

### "Palagi ba nitong pipiliin ang pinakamahal na model?"

**Hindi.** Bilang default, 15% lamang ng score ang nakabatay sa gastos. Maaaring higitan ng isang mura, mabilis, at maayos na provider ang isang mahal na provider. Gamitin ang `auto/cheap` kung gusto mong higit pang bigyang-priyoridad ang gastos.

### "Paano kung tumigil sa paggana ang isang provider?"

Awtomatikong lalaktawan ito ng OmniRoute at susubukan ang susunod. Kung patuloy na mabibigo ang isang provider, pansamantala itong hindi isasama (5-30 minuto). Wala kang kailangang gawin.

### "Makikita ko ba kung aling provider ang ginamit?"

Tingnan ang mga response header — isinasama ng OmniRoute sa bawat response ang provider at model na ginamit.

### "Natututo ba ito mula sa paggamit ko?"

Oo! Gumagamit ang scoring system ng makasaysayang data (latency, error rate, at success rate) upang makagawa ng mas mahuhusay na desisyon sa paglipas ng panahon.

### "Ano ang pagkakaiba ng `auto` at `auto/smart`?"

- `auto` — Balanseng opsyon, 5% exploration
- `auto/smart` — Inuuna ang kalidad (kaparehong mga weight ng `auto/coding`), 10% exploration

Gamitin ang `auto/smart` kapag gusto mo ang pinakamahusay na kalidad at ayos lang sa iyo ang paminsan-minsang exploration.

### "Maaari ko bang piliting gumamit ng partikular na provider?"

Oo! Gumamit ng combo na may `priority` strategy sa halip na `auto`, pagkatapos ay ipadala ang **eksaktong pangalan** ng combo bilang `model` field (hal. `model: "my-combo"` — hindi `auto`). Tingnan ang [Teknikal na Sanggunian](../routing/AUTO-COMBO.md) para sa mga detalye.

### "Paano ito naiiba sa round-robin?"

Salit-salitang ginagamit ng round-robin ang mga provider ayon sa pagkakasunod-sunod. **Binibigyan ng score ng auto-combo ang bawat provider** at pinipili ang pinakamahusay. Mas matalino ito — isinasaalang-alang nito ang kalagayan, bilis, gastos, at kalidad.
