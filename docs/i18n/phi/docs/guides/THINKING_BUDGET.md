> **Dashboard:** Settings → **AI** → Thinking Budget  
> **API:** `GET` / `PUT` `/api/settings/thinking-budget`  
> **Source:** `open-sse/services/thinkingBudget.ts`

Kinokontrol ng Thinking Budget kung **muling isinusulat ng OmniRoute ang mga parameter ng thinking/reasoning ng client** habang ipinapadala ang mga ito sa mga provider. **Hindi** nito ino-on o ino-off ang compression, routing, o prompt cache.

## Mga Mode

| Mode                        | Ang ginagawa ng OmniRoute                                                                                                     | Kailan gagamitin                                                                                                                                                                                           |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`passthrough`** (default) | Hindi binabago ang mga field ng client (`reasoning`, `reasoning_effort`, Claude `thinking`, Gemini `thinking_config`, atbp.). | **Codex / Desktop / anumang client na dapat kumontrol sa effort + mga buod ng reasoning.** Kinakailangan para makita ang mga thinking panel kapag humiling ang client ng `reasoning.summary`.              |
| **`auto`**                  | **Inaalis ang lahat** ng thinking/reasoning field mula sa request body bago ipadala sa upstream.                              | Kapag sadya mo lamang gustong ang **provider** ang bumuo ng mga default at **hindi** mo kailangan ng thinking na kontrolado ng client. **Hindi** ito nangangahulugang “awtomatikong ipakita ang thinking”. |
| **`custom`**                | Pinapalitan ang bawat request gamit ang isang nakapirming token budget para sa thinking.                                      | Mahigpit na limitasyon sa mga thinking token para sa lahat ng traffic.                                                                                                                                     |
| **`adaptive`**              | Ini-scale ang budget mula sa isang batayang effort gamit ang bilang ng mga message, mga tool, at haba ng prompt.              | Flexible na pagkontrol sa token nang hindi ganap na inaalis ang layunin ng client.                                                                                                                         |

### Ang inaalis ng `auto`

Kapag `auto` ang mode, dine-delete ng `stripThinkingConfig()` ang mga sumusunod (bukod sa iba pa):

- OpenAI / Responses: `reasoning`, `reasoning_effort`
- Claude: `thinking`, at `output_config.effort` kapag mayroon
- Gemini: `generationConfig.thinking_config` / `thinkingConfig`

Kung nagpadala ang isang client (hal. Codex Desktop) ng `reasoning: { effort: "ultra", summary: "detailed" }`, **inaalis ng auto ang object na iyon**. Maaari pa ring maningil ang upstream para sa ilang reasoning token, ngunit kadalasan ay nagbabalik ito ng mga reasoning item na **walang laman o encrypted-only** — kaya walang kapaki-pakinabang na thinking stream na ipinapakita ang UI.

## Ano ang **hindi** nito ginagawa

| Feature                                      | Kaugnayan                                                                                                                                              |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Compression** (Caveman, RTK, stacked, …)   | Hiwalay na pipeline. Gumagana sa bawat thinking-budget mode.                                                                                           |
| **Prompt / semantic cache**                  | Hiwalay. Hindi naaapektuhan ng thinking-budget mode.                                                                                                   |
| **Combo routing / fallbacks**                | Hiwalay. Hindi naaapektuhan.                                                                                                                           |
| **Mga token limit / cost budget ng API key** | Hiwalay. Hindi naaapektuhan.                                                                                                                           |
| **Reasoning replay cache**                   | Multi-turn na muling pag-inject para sa mga mahigpit na provider (DeepSeek, Kimi, Qwen-thinking, …). Hindi ito kapareho ng “show thinking” ng Desktop. |
| **Pag-decrypt ng `encrypted_content`**       | **Imposible.** Opaque ang mga pribadong reasoning blob ng OpenAI/Codex. Hindi kailanman dine-decrypt ng OmniRoute ang mga ito (#7095 / #7176 / #7304). |

## Nakikitang pag-iisip (mga Codex / Responses client)

Para maipakita ng isang client ang teksto ng pag-iisip, kailangan mo ang **lahat** ng sumusunod:

1. Thinking Budget mode = **`passthrough`** (o custom/adaptive na pinananatiling sapat na buo ang mga kahilingan para sa buod para sa path na ginagamit mo).
2. Humihiling ang client ng buod, hal. Codex `model_reasoning_summary = "detailed"` / `auto` (hindi `none`).
3. Aktuwal na sini-stream ng upstream ang `response.reasoning_summary_text.*` (o may hindi bakanteng `reasoning.summary` sa item).

Kung “encrypted private reasoning” lang ang nakukuha mo, alinman sa:

- **`auto`** ang mode (inalis ang kahilingan ng client), o
- nagbalik ang upstream ng `encrypted_content` nang walang teksto ng buod (limitasyon ng provider; placeholder lang ang maipapakita ng OmniRoute, hindi plaintext).

## Mga halimbawa ng API

```bash
# Basahin
curl -sS https://localhost:20128/api/settings/thinking-budget \
  -H "Authorization: Bearer $OMNIROUTE_TOKEN"

# Inirerekomenda para sa kakayahang makita ang pag-iisip sa Codex / Desktop
curl -sS -X PUT https://localhost:20128/api/settings/thinking-budget \
  -H "Authorization: Bearer $OMNIROUTE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"mode":"passthrough","customBudget":10240,"effortLevel":"medium"}'
```

Schema (`updateThinkingBudgetSchema`): `mode` ∈ `passthrough|auto|custom|adaptive`; opsyonal ang `customBudget`, `effortLevel`, `baseBudget`, `complexityMultiplier`.

### Pagpapanatili / pag-restart

Iniimbak ang value sa ilalim ng settings key na `thinkingBudget` at nilo-load sa pagsisimula ng proseso (`hydrateThinkingBudgetConfig`). Pagkatapos baguhin sa pamamagitan ng DB o ilang path na hindi API, **i-restart ang proseso ng OmniRoute** para tumugma sa disk ang singleton na nasa memory.

## Checklist ng operator

- [ ] Mga gumagamit ng Codex / Desktop: mode = **passthrough**
- [ ] Panatilihing naka-enable ang compression kung gusto mong makatipid ng token sa **mga mensahe**, hindi sa pamamagitan ng pag-aalis ng pag-iisip
- [ ] Huwag asahang “magpakita ng higit pang pag-iisip” ang `auto`
- [ ] Ang mga encrypted-only na buod ay gawi ng **provider**; hindi made-decrypt ng passthrough ang mga ito
