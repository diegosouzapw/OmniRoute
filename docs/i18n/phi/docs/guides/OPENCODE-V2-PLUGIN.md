Inilalagay ng `@omniroute/opencode-plugin-v2` ang buong catalog ng OmniRoute mo — mga model, combo, at
auto-combo — sa model picker ng OpenCode v2, kasama ang mga display name, presyo, at badyet
para sa free tier.

Hiwalay itong package sa `@omniroute/opencode-plugin` dahil magkaiba ang mga contract na ginagamit ng OpenCode v1 at v2 sa pag-load
ng mga plugin. Piliin ang tumutugma sa major version ng OpenCode mo; walang
pinagsasaluhan ang dalawa, kaya hindi kailanman mapipilit ng pag-upgrade sa isa ang pag-upgrade sa kabila.

## Mga Kinakailangan

- OpenCode v2.
- Isang naaabot na OmniRoute gateway (`http://localhost:20128` bilang default).
- Node.js 22 o 24.

## Pag-install

Idagdag ang plugin sa `opencode.json`:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

Pagkatapos, lalabas ang mga model bilang `omniroute/<provider>/<model>`; ang `providerId` ang tumutukoy sa prefix na iyon at
sa id ng integration kung saan iniimbak ng OpenCode ang credential.

## Mga Credential

Hinahanap ng plugin ang gateway key sa tatlong lugar, sa ganitong pagkakasunod-sunod:

1. **Ang credential na ikinonekta mo sa OpenCode.** Nagrerehistro ang plugin ng isang integration, kaya
   maaaring iimbak ng sariling auth flow ng OpenCode ang key. Walang inilalagay sa `opencode.json` — ito ang mas mainam.
2. `apiKey` sa mga option ng plugin, para sa override na para sa bawat project. Inilalagay nito ang key sa isang file na
   maaaring kino-commit mo.
3. `OMNIROUTE_API_KEY` sa environment.

Kapag wala ang tatlo, walang laman ang catalog at minsang ipapaalam ito ng plugin sa startup sa halip na
hayaan kang magkaroon ng tahimik na walang-lamang picker.

### Ibang key ang management token

Ang mga combo, kalagayan ng provider, at enrichment (mga display name, presyo, at badyet para sa free tier) ay nagmumula sa
mga endpoint na `/api/*` ng gateway, na sa karamihan ng deployment ay protektado ng **management** token
sa halip na inference key:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<management read token>"
}
```

Kapag hindi itinakda, gagamitin ng `managementReadToken` ang `apiKey` bilang fallback. Kapag tinanggihan ng gateway ang fallback na iyon,
ilalathala pa rin ang catalog, ngunit may mga raw model id sa halip na mga display name, walang pag-aalis ng duplicate batay sa canonical
alias, walang presyo, at walang mga combo. Minsang magbibigay ng babala ang plugin para sa bawat endpoint kapag nangyari iyon,
na binabanggit ang endpoint at kung ano ang nawala — kaya hindi magiging palaisipan ang isang degraded na picker.

## Mga Option

| Key                              | Default                                                     | Mga Tala                                                                                                                                   |
| -------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `providerId`                     | `"omniroute"`                                               | Provider id, integration id, at ang prefix kung saan lumalabas ang mga model                                                               |
| `baseURL`                        | kinakailangan                                               | Root ng gateway, `http(s)` lamang; idinaragdag ang suffix na `/v1` kung kinakailangan                                                      |
| `apiKey`                         | nakakonektang credential, pagkatapos ay `OMNIROUTE_API_KEY` | Chat key para sa `/v1/*`                                                                                                                   |
| `managementReadToken`            | ginagamit ang `apiKey` bilang fallback                      | Key para sa `/api/*` — karaniwang **hindi** ito ang parehong key                                                                           |
| `displayName`                    | `"OmniRoute"`                                               | Pangalan ng provider sa picker                                                                                                             |
| `timeoutMs`                      | `10000`                                                     | Timeout ng fetch para sa bawat endpoint (5s ang ginagamit ng mga auto-combo)                                                               |
| `modelCacheTtlMs`                | `300000`                                                    | TTL ng cache ng catalog; pinapabilis ng snapshot sa disk ang mga cold start                                                                |
| `timeouts`                       | ginagamit ang `timeoutMs` bilang fallback                   | Mga badyet para sa bawat endpoint sa ms: `models`, `combos`, `autoCombos`, `enrichment`                                                    |
| `enrichment`                     | `true`                                                      | Kunin ang mga pangalan, presyo, at badyet para sa free tier                                                                                |
| `providerTag`                    | `true`                                                      | Lagyan ng prefix ang display name gamit ang upstream provider kung saan ito idinuruta                                                      |
| `usableOnly`                     | `false`                                                     | Panatilihin lamang ang mga provider na iniulat ng gateway bilang provisioned                                                               |
| `visibleModels` / `hiddenModels` | `[]`                                                        | Mga allowlist na exact-or-suffix; nangingibabaw ang deny                                                                                   |
| `geminiSanitization`             | `true`                                                      | Alisin sa mga tool schema ang mga keyword ng JSON-Schema na tinatanggihan ng Gemini (ipinapasa nang hindi binabago ang mga tool na `$ref`) |
| `apiFormat.allowAnthropic`       | `false`                                                     | Iruta ang mga naka-allowlist na id sa pamamagitan ng Anthropic API block                                                                   |
| `apiFormat.anthropicModels`      | `[]`                                                        | Mga buong model id na idinuruta sa Anthropic                                                                                               |
| `logLevel` / `startupDebug`      | `warn` / `false`                                            | Antas ng detalye ng logger                                                                                                                 |

## Paano nananatiling napapanahon ang catalog

Kinukuha ang catalog kapag kailangan lamang at kino-cache sa loob ng `modelCacheTtlMs`, at pinananatiling available ng snapshot sa disk ang
huling nalalamang catalog kapag hindi maabot ang gateway — walang ibang epekto sa iyo ang outage kundi
ang pagiging hindi napapanahon. Agad na inilalathala ang mga model at combo pagdating ng mga ito; isinasama ang mga auto-combo, ang listahan ng provider,
at ang enrichment overlay kapag dumating ang mga ito, kaya hindi maaaring pigilan ng isang mabagal na endpoint ang
buong picker.

Makikita sa mga pangalan ang nalalaman ng gateway: ang upstream provider kung saan niruruta ang isang model, isang marker na `[Free]`,
at ang kasama nitong budget — kaya nananatiling madaling makilala ang dalawang connection na nagbebenta ng parehong model.
I-off ang prefix gamit ang `"providerTag": false`.

Walang manual refresh command: ang mga command ng OpenCode v2 ay mga prompt template, hindi mga callback,
kaya hindi maaaring mag-expose ng ganito ang isang plugin. Sumusunod ang mga refresh sa TTL; hinihiling lamang sa host na mag-reload kapag
talagang nagbago ang catalog o ang overlay, at hindi sa bawat refresh.

## Pagtawag sa tool sa Gemini

Tinatanggihan ng Gemini ang isang buong request kapag may `$schema` o
`additionalProperties` ang mga deklarasyon ng tool nito, at tumutugon ito ng `400 INVALID_ARGUMENT`. Inaalis ng plugin ang mga keyword na iyon mula sa
mga tool schema na nakalaan para sa isang Gemini model ng provider na ito at hindi nito binabago ang lahat ng iba pang request.
Ang isang tool na may `$ref` ay ipinapasa nang hindi binabago sa halip na alisin ito, dahil ang pag-aalis sa
reference ay magpapalawak sa schema upang "tanggapin ang kahit ano".
Itakda ang `"geminiSanitization": false` upang i-off ito.

## Pag-troubleshoot

| Sintomas                                        | Sanhi                                                                                                                                      |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Walang ipinapakitang OmniRoute model ang picker | Walang na-resolve na key (tingnan ang babala sa startup), o hindi maabot ang gateway                                                       |
| Mga raw model id, walang combo, walang presyo   | Tinanggihan ng mga management endpoint ang token — itakda ang `managementReadToken`                                                        |
| Isang session na naka-pin sa `opencode-<id>/…`  | Inilathala ng v1 plugin ang `opencode-<id>`; inilalathala ito ng v2 bilang `<id>` lamang, kaya piliin muli ang model sa ilalim ng `<id>/…` |
