> **TL;DR**: Niraranggo ng OmniRoute ang mga **libreng** provider nito batay sa kalidad ng modelo gamit ang mga **ELO score ng Arena AI
> (LMArena-style)**. Buksan ang pahina ng **Free Provider Rankings** sa
> dashboard upang makita kung aling mga libreng provider ang naghahatid ng pinakamahuhusay na modelo para sa iyong gawain —
> sa kabuuan, o sinala ayon sa kategorya (coding, review, documentation, debugging).

---

## Ano Ito

Nagrerehistro ang OmniRoute ng 329 na provider, kabilang ang 155 entry sa catalog na minarkahang **free/no-auth**
(no-auth,
free-tier OAuth, o free-tier API key — tingnan ang
[Free Tiers Guide](../getting-started/FREE-TIERS-GUIDE.md) at ang kumpletong
[Free Tiers directory](../reference/FREE_TIERS.md)). Ang kaakibat na limitasyon: lubhang
nagkakaiba-iba ang kalidad ng modelo ng mga libreng provider. Higit na kapaki-pakinabang
ang isang no-auth provider na naghahatid ng frontier model kaysa sa naghahatid ng maliit at lumang modelo.

Sinasagot ng **Free Provider Rankings** ang "**aling libreng provider ang nagbibigay sa akin ng pinakamahusay na modelo?**" sa pamamagitan ng
pagtutugma ng catalog ng bawat libreng provider sa mga **crowd-sourced na score ng kalidad** mula sa
**leaderboard ng Arena AI** (human-preference ELO, ang kaparehong konsepto sa likod ng LMArena
chatbot arena). Pagkatapos, niraranggo ang mga provider batay sa kakayahan ng kanilang **pinakamahusay na libreng modelo**.

Kinukuwenta ang ranking mula sa tatlong aktuwal na source:

1. Ang mga listahan ng libreng provider — `NOAUTH_PROVIDERS`, kasama ang mga entry ng `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` na may flag na `hasFree`
   (`src/shared/constants/providers.ts`).
2. Ang model catalog ng bawat provider mula sa provider registry
   (`open-sse/config/providerRegistry.ts`).
3. Mga task-fit score na hinango mula sa ELO at iniimbak sa DB table na `model_intelligence` ng
   Arena ELO sync engine (`src/lib/arenaEloSync.ts`).

Makikita ang join logic sa `src/lib/freeProviderRankings.ts`.

## Paano I-access

### Pahina ng dashboard

Buksan ang dashboard at pumunta sa **Costs → Free Provider Rankings**, o direktang pumunta sa:

```
/dashboard/free-provider-rankings
```

Ipinapakita ng pahina (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) ang:

- Isang **top-3 podium** (🥇 🥈 🥉) ng mga libreng provider na may pinakamataas na ranking.
- Isang kumpletong **ranking table** na may mga column na: **Rank**, **Provider**, **Top Model**,
  **Score**, **Avg Score**, **Models**, **Type**.
- Mga **button ng filter ayon sa kategorya**: _All Categories_, _Default_, _Coding_, _Review_,
  _Documentation_, _Debugging_.

Ipinapakita ng **Type** badge ng bawat provider kung paano ito nagiging libre:

| Badge    | Kahulugan                                        |
| -------- | ------------------------------------------------ |
| `NOAUTH` | Palaging libre, walang kinakailangang credential |
| `OAUTH`  | OAuth provider na may libreng tier (`hasFree`)   |
| `APIKEY` | API-key provider na may libreng tier (`hasFree`) |

Ipinapakita ang mga score bilang mga label na madaling maunawaan ng tao (hal. _Elite_, _Excellent_, _Very Good_,
_Good_, _Average_) sa halip na mga raw number, dahil ang pinagbabatayang value ay isang relatibong
ranking ng kalidad, hindi porsyento.

### API endpoint

Sinusuportahan ang pahina ng isang pampublikong read endpoint
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

Mga query parameter (vina-validate gamit ang Zod):

| Param      | Type   | Default | Mga Tala                                                                                                |
| ---------- | ------ | ------- | ------------------------------------------------------------------------------------------------------- |
| `category` | string | (wala)  | Isa sa `default`, `coding`, `review`, `documentation`, `debugging`. Alisin para sa pinagsamang ranking. |
| `limit`    | number | `50`    | Nililimitahan sa saklaw na `1–100`.                                                                     |

Anyo ng response:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

Ang `eloRaw` ay ang orihinal na Arena ELO value; ang `score` ay ang na-normalize na task-fit value
(tingnan sa ibaba). Hindi isinasama sa response ang mga provider na walang scored model.

## Paano Gumagana ang mga Score

### Pinagmulan: leaderboard ng Arena AI

Kinukuha ng Arena ELO sync engine (`src/lib/arenaEloSync.ts`) ang dalawang leaderboard — `text`
at `code` — mula sa Arena AI leaderboard API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`). Ang bawat entry sa leaderboard
ay naglalaman ng pangalan ng modelo, vendor, ELO `score`, confidence interval, at bilang ng boto.

Ang mga kategorya ng leaderboard ay itinutugma sa mga kategorya ng gawain ng OmniRoute:

| Arena leaderboard | Mga kategorya ng gawain ng OmniRoute              |
| ----------------- | ------------------------------------------------- |
| `text`            | `default`, `review`, `documentation`, `debugging` |
| `code`            | `coding`                                          |

### Normalisasyon (score ng pagiging angkop sa gawain)

Ang mga raw na ELO score ay ginagawang normal kada leaderboard bilang isang **task-fit value sa `[0.4, 0.98]`**:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

Hindi kailanman umaabot sa `0` o `1` ang score, upang mag-iwan ng puwang para sa mga override ng user. Ito ang
`score` field na makikita mo sa tugon ng API at ang label na ipinapakita sa dashboard.

### Kumpiyansa

Ang bawat entry ay binibigyan ng antas ng kumpiyansa batay sa bilang ng boto sa Arena:

| Kumpiyansa | Mga boto |
| ---------- | -------- |
| `high`     | ≥ 5,000  |
| `medium`   | ≥ 1,000  |
| `low`      | < 1,000  |

### Pag-iimbak at pagiging napapanahon

Isinusulat ang mga na-normalize na entry sa `model_intelligence` DB table na may
`source = "arena_elo"` (`src/lib/db/modelIntelligence.ts`). Ang mga entry ay **nag-e-expire pagkalipas ng
7 araw**, kaya ang provider na tumigil sa pag-sync ay kalaunang inaalis sa halip na maghatid
ng lipas na data.

**Naka-on bilang default** ang pag-sync:

- Tumatakbo ito nang isang beses sa pagsisimula ng server at pagkatapos ay sa pana-panahong timer
  (`src/lib/arenaEloSync.ts`, na nakakonekta mula sa `src/instrumentation-node.ts`).
- Ito ay **non-blocking at hindi kailanman fatal** — kung mabigo ang pagkuha mula sa upstream, patuloy na
  tumatakbo ang OmniRoute at ipinapakita lamang ng mga ranking ang huling wastong data (o isang walang-lamang estado).

Dalawang environment variable ang kumokontrol dito (nakadokumento sa
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)):

| Variable                  | Default       | Layunin                                                |
| ------------------------- | ------------- | ------------------------------------------------------ |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | Itakda sa `false` upang hindi sumali sa outbound sync. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | Agwat ng pag-sync, sa mga segundo.                     |

### Manu-manong pag-sync / status / pag-clear

Para sa mga operator, nagbibigay ang isang authenticated management endpoint ng manu-manong kontrol
(`src/app/api/intelligence/sync/route.ts` — nangangailangan ng management auth):

```
GET    /api/intelligence/sync          # kasalukuyang status ng pag-sync (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # mag-trigger ng manu-manong pag-sync; body: { "dryRun": true } upang i-preview nang hindi nagsusulat
DELETE /api/intelligence/sync          # i-clear ang lahat ng naka-sync na arena_elo intelligence entry
```

Kung walang laman ang pahina ng mga ranking, muli itong mapupunan ng manu-manong `POST /api/intelligence/sync` (o simpleng
pag-restart ng server).

### Pagtutugma ng mga modelo sa leaderboard

Hindi palaging eksaktong magkatugma ang mga registry model ID at mga pangalan ng modelo sa Arena. Gumagamit ang ranking ng
flexible matching (`findMatchingIntelligence` sa `src/lib/freeProviderRankings.ts`):

1. Eksaktong tugma sa na-normalize na model ID.
2. Pagtutugma matapos alisin ang version suffix sa dulo (hal. `kimi-k2.6` → `kimi-k2`).
3. Prefix match (ang pangalan ng modelo sa leaderboard ay prefix ng registry ID).

Sa panig ng pag-sync, inaalis ang mga kilalang vendor prefix (`anthropic/`, `openai/`, `google/`, …)
at pinapalawak ng isang maliit na alias map ang mga canonical name sa mga variant na ginagamit ng OmniRoute
sa loob, upang manatiling nahahanap ang mga modelo sa ilalim ng anumang pangalan.

### Paano niraranggo ang isang provider

Para sa bawat libreng provider, binibigyan ng engine ng score ang bawat modelo sa catalog nito, pagkatapos:

- **Nangungunang Modelo** = ang modelo ng provider na may pinakamataas na score.
- **Average na Score** = ang mean score ng lahat ng modelo ng provider na nabigyan ng score.
- **Mga Modelo** = kung ilan sa mga modelo ng provider ang may Arena score.

Inaayos muna ang mga provider ayon sa **score ng nangungunang modelo**, pagkatapos ay ayon sa average na score. Ginagantimpalaan nito ang
provider na nag-aalok ng kahit isang mahusay na libreng modelo.

## Paggamit Nito sa Pagpili ng mga Libreng Provider

1. **Piliin ang tamang kategorya.** Gamitin ang filter na **Coding** para sa mga agentic/code workload, o
   panatilihin ito sa **All Categories** / **Default** para sa pangkalahatang chat. Maaaring
   magkaiba ang ranggo ng parehong provider sa bawat kategorya dahil magkakaiba ang nangungunang modelo nito sa bawat leaderboard.
2. **Unahin ang mga nasa podium para sa mga one-shot setup.** Kung isa o dalawang libreng
   provider lang ang gusto mong ikonekta, magsimula sa mga may pinakamataas na ranggo para sa iyong kategorya.
3. **Suriin ang badge na Type.** Ang mga provider na `NOAUTH` ang pinakamabilis ikonekta (walang
   kinakailangang kredensyal). Ang mga libreng tier na `OAUTH` / `APIKEY` ay nangangailangan ng mabilisang pag-sign up ngunit kadalasang nagbibigay ng access sa
   mas mahuhusay na modelo. Tingnan ang [Gabay sa mga Libreng Tier](../getting-started/FREE-TIERS-GUIDE.md) para sa
   mga hakbang sa pagkonekta.
4. **Magkonekta ng ilan at hayaang Auto-Combo ang magpasya.** Ang parehong datos ng Arena ELO na nagpapatakbo
   sa pahinang ito ay ginagamit din sa **task-fitness factor** ng Auto-Combo scoring engine
   (`open-sse/services/autoCombo/taskFitness.ts`, pagkakasunod-sunod ng resolusyon:
   `user_override → arena_elo → models_dev_tier → static table`). Kaya pagkatapos mong ikonekta
   ang mga nangungunang libreng provider, ang pag-route gamit ang `model: "auto"` (hal. `auto/coding`) ay
   awtomatikong magbibigay-priyoridad sa mas de-kalidad na libreng modelo para sa bawat request. Tingnan ang
   [Auto-Combo](../routing/AUTO-COMBO.md) para sa kumpletong 16-factor scoring.
