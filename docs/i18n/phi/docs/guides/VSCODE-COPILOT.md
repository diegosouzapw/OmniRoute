**OmniCopilot** inilalagay ang bawat model na inihahatid ng iyong OmniRoute sa _native_ na GitHub Copilot Chat
model picker. Walang pangalawang sidebar, walang hiwalay na chat UI — patuloy na gumagana ang agent mode, tool calling,
mga MCP server, at mga custom na tagubilin ng Copilot, ngunit tumatakbo sa model na pipiliin mo.

|                          |                                                                                                                                                 |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **I-install (VS Code)**  | [Marketplace → `diegosouzapw.omnicopilot`](https://marketplace.visualstudio.com/items?itemName=diegosouzapw.omnicopilot)                        |
| **I-install (mga fork)** | [Open VSX](https://open-vsx.org/extension/diegosouzapw/omnicopilot) — Cursor, Windsurf, VSCodium, Theia, code-server, Gitpod, Antigravity, Kiro |
| **Source / mga issue**   | [github.com/diegosouzapw/OmniCopilot](https://github.com/diegosouzapw/OmniCopilot) (MIT)                                                        |
| **Kinakailangan**        | VS Code 1.104+                                                                                                                                  |

> **Hindi kailangan ng subscription sa Copilot.** Simula sa VS Code 1.122, gumagana ang isang language-model provider
> nang walang pag-sign in sa GitHub at nang walang anumang Copilot plan. Ang mga inline completion at
> feature na nakabatay sa embeddings ay nananatiling labas sa provider API at nangangailangan pa rin ng Copilot.

## Pag-set up

1. **Patakbuhin ang OmniRoute** — `npm install -g omniroute && omniroute` (dashboard sa `http://localhost:20128`).
2. **I-install ang extension** — hanapin ang "OmniRoute" sa Extensions view.
3. **Pumili ng model** — Copilot Chat → model picker → **Manage Models…** → **OmniRoute**, pagkatapos ay lagyan ng tsek
   ang gusto mo.

Walang kailangang i-configure kapag tumatakbo ang OmniRoute sa default na port. Para sa remote na instance, buksan ang
**OmniRoute icon sa Activity Bar** (o patakbuhin ang `OmniRoute: Manage Connection`) at itakda ang:

- **Server URL** — ang server root, hal. `http://192.168.0.15:20128`. Ang `/v1` suffix ay
  idinaragdag ng extension; huwag itong isama.
- **API key** — kapag itinakda lamang ng server ang `REQUIRE_API_KEY`. Iniimbak sa OS keychain sa pamamagitan ng VS
  Code SecretStorage, at hindi kailanman sa `settings.json`.

## Ang ipapakita ng picker

Hindi ipinapakita ng extension ang raw na `GET /v1/models` payload — inaayos nito ang anyo nito, at ang bilang na
makikita mo ay mas mababa kaysa sa laki ng catalog dahil sa dalawang sinadyang dahilan.

### Humihiling ito ng isang id bawat model

Ang `MODELS_CATALOG_PREFIX_MODE` ay naka-default sa **`dual`**, na ina-advertise ang bawat model nang dalawang beses — minsan
sa ilalim ng maikling alias prefix at minsan sa ilalim ng canonical provider prefix — upang patuloy na ma-resolve ng mga lumang client
config ang alinmang anyo:

```
cc/claude-sonnet-4-6        ← alias prefix
claude/claude-sonnet-4-6    ← canonical prefix, parehong model
```

Hinihiling ng extension ang **`GET /v1/models?prefix=alias`** upang isang id ang dumating bawat model, nang hindi
binabago ang server-wide na setting para sa iba mong mga client. Sa isang reference instance, pinaikli nito ang
**2345 entry sa 1396 — 949 duplicate, walang nawalang model.**

Kung mas gugustuhin mong ayusin ito sa buong server para sa _bawat_ client, itakda ang
`MODELS_CATALOG_PREFIX_MODE` feature flag sa `alias` sa dashboard. Tingnan ang
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) para sa
query parameter at table para sa bawat mode.

### Itinatago nito ang mga model na hindi kayang makipag-chat

Nakalista rin sa catalog ang mga image, video, audio, rerank, embedding, at moderation model. Ang mga iyon ay
tinatanggihan din naman sa isang chat request:

```
HTTP 400 — Ang model na '<id>' ay isang image-generation model at hindi maaaring gamitin sa
/v1/chat/completions. Gamitin sa halip ang POST /v1/images/generations.
```

kaya fina-filter ang mga ito ayon sa kanilang `type` field bago makarating sa picker. **Pinananatili ang mga Responses-API
model** — ina-advertise ng bawat Codex / GPT-5.x entry ang `supported_endpoints: ["responses"]`,
at isinasalin ng OmniRoute ang mga iyon para sa `/v1/chat/completions`, kaya lubos na magagamit ang mga ito.

### Mga provider na hindi mo kailanman na-configure

Nakalista sa catalog ang mga model mula sa mga provider na may **aktibong koneksyon** _kasama_ ang bawat **noAuth**
provider — ang mga hindi nangangailangan ng key na bumubuo sa malaking bahagi ng libreng tier. Sinadya iyon. Upang itago
ang mga ito, idagdag ang mga ito sa `blockedProviders` sa mga setting ng dashboard; walang magbabago sa
extension.

## Dashboard sa loob ng tab ng VS Code

Nire-render ng `omnicopilot.dashboardOpen: "editor"` ang dashboard ng OmniRoute sa isang tab ng editor sa pamamagitan ng
Simple Browser sa halip na sa isang external na browser. Ang pag-embed ay **kailangang tahasang i-enable sa server** sa pamamagitan ng
`DASHBOARD_ALLOW_EMBED=vscode`, na naghahatid sa mga HTML page gamit ang
`frame-ancestors 'self' vscode-webview:` sa halip na ang default na `frame-ancestors 'none'` +
`X-Frame-Options: DENY`. Pinapanatili ng API surface (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) ang
mahihigpit na header sa alinmang paraan.

> ⚠️ **Isa itong build-time flag, hindi runtime flag.** Kino-compile ng Next.js ang `headers()` sa route
> manifest, kaya binabasa ng `next.config.mjs` ang variable habang bina-build ang bundle
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> Walang mababago ang pag-export nito bago patakbuhin ang isang server na na-build na — nakapaloob na ang mga header.

```bash
# kailangang naroon ang variable sa BUILD command
DASHBOARD_ALLOW_EMBED=vscode npm run build        # o npm run build:release
npm start
```

| Paraan ng pag-install mo   | Maaari mo bang i-enable ang pag-embed?                                                                                                            |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Mula sa source             | ✅ itakda ang variable sa build command, gaya ng nasa itaas                                                                                       |
| `npm install -g omniroute` | ❌ may kasamang prebuilt bundle ang naka-publish na package — sa halip, mag-build mula sa source                                                  |
| Docker image               | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — hindi naka-enable ang pag-embed sa prebuilt image sa Docker Hub |

Kung walang build na naka-enable ang pag-embed, tatanggi ang page na ma-frame, matutukoy iyon ng extension mula sa mga
response header at babalik ito sa external na browser — walang masisira, at isang beses nitong ipapaalam iyon.
Tingnan ang [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) at issue
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273).

## Pag-configure ng iba mo pang tool mula sa loob ng VS Code

Ginagamit ng **`OmniRoute: Configure Coding CLI`** ang `omniroute` CLI upang magsulat ng mga profile na handa nang gamitin
para sa Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code,
Kilo at Roo — ang parehong mga config na inilalarawan sa
[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md). Ipinapasa ang API key sa CLI sa pamamagitan ng
`OMNIROUTE_API_KEY` environment variable, at hindi kailanman sa command line.

## Pag-troubleshoot

| Sintomas                                                         | Sanhi / solusyon                                                                                                                                                                                                                                                                                                    |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Walang mga modelo ng OmniRoute sa picker                         | Hindi maabot ang server. Magiging kulay abo ang tuldok sa status bar; patakbuhin ang `OmniRoute: Check Connection`. Sadyang tahimik ang discovery at hindi ito nagdaragdag ng anumang modelo sa halip na magpakita ng prompt.                                                                                       |
| Dalawang beses lumilitaw ang bawat modelo                        | Gumagamit ka ng OmniCopilot na mas luma sa 1.0.1 — mag-update. Humihiling na ngayon ang extension ng `?prefix=alias`.                                                                                                                                                                                               |
| Dating nakalista ang isang image/audio model ngunit wala na ito  | Sinadya ito simula 1.0.1 — hindi naman talaga ito makakasagot sa isang chat request.                                                                                                                                                                                                                                |
| Nawawala ang panel sa Activity Bar                               | Inililipat ng VS Code ang mga sobrang view container sa **"…"** overflow sa ibaba ng Activity Bar, at nananatiling nakatago ang isang container na itinago sa pamamagitan ng right-click. I-right-click ang Activity Bar → lagyan ng tsek ang **OmniRoute**, o buksan ito gamit ang `OmniRoute: Manage Connection`. |
| Bumubukas ang dashboard sa browser sa kabila ng `editor` mode    | Hindi **na-build** ang server gamit ang `DASHBOARD_ALLOW_EMBED=vscode` (tingnan sa itaas) — walang epekto ang pagtatakda nito sa startup sa isang prebuilt na installation. Sinadya ang fallback.                                                                                                                   |
| Luma ang listahan ng mga modelo matapos baguhin ang mga provider | Gamitin ang `OmniRoute: Refresh Models`, o ang ↻ link sa panel.                                                                                                                                                                                                                                                     |
