## 1. Antigravity kumpara sa Antigravity CLI (agy)

Parehong ginagamit ng dalawang provider ang **iisang Google backend** — magkaparehong OAuth client, token refresh, mga endpoint, at mga Google account. Ang pagkakaiba ay kung aling mga modelo ang makikita mo.

> Tingnan ang [anunsyo tungkol sa Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli) para sa opisyal na paghahambing ng Google.

| Aspeto                      | `antigravity` (IDE)                                      | `agy` (CLI)                                                               |
| --------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------- |
| **Produkto ng Google**      | Antigravity 2.0 / Antigravity IDE                        | Antigravity CLI                                                           |
| **Backend**                 | Parehong Google Cloud Code API                           | Parehong Google Cloud Code API                                            |
| **OAuth / Token**           | Parehong client, parehong refresh                        | Parehong client, parehong refresh                                         |
| **Katalogo ng modelo**      | Statikong piniling listahan (naka-hardcode sa OmniRoute) | Live na sinusuri mula sa Google sa pamamagitan ng `:fetchAvailableModels` |
| **Mga modelo ng Claude**    | Sonnet 4.6, Opus 4.6 (tig-4 na variant)                  | Sonnet 4.6, Opus 4.6 (tig-4 na variant)                                   |
| **Pagpapangalan sa Gemini** | Malilinaw na label (Low/Medium/High)                     | Mga upstream ID (extra-low/low/agent)                                     |
| **Mga karagdagang modelo**  | `gpt-oss-120b-medium`                                    | Maaaring magsama ng mga karagdagang modelo mula sa Google                 |
| **Default na gamit**        | Integrasyon sa IDE (VS Code, JetBrains)                  | Access sa CLI / API                                                       |
| **Quota**                   | Ibinabahagi sa agy (parehong Google account)             | Ibinabahagi sa antigravity (parehong Google account)                      |

**Mga available na modelo (napatunayan sa pamamagitan ng eksperimento, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (iba't ibang antas ng pag-iisip)
- Claude: Sonnet 4.6, Opus 4.6 (bawat isa ay may default/low/medium/high na variant)
- Iba pa: GPT-OSS 120B Medium
- **HINDI available ang Claude Sonnet 5** — mga variant lang ng 4.6 ang sinusuportahan

**Bakit naiiba ang katalogo ng modelo**: Ang CLI ng Google ay "na-optimize para sa bilis at mababang overhead" at "sabay na na-optimize kasama ng mga modelo ng Gemini" (ayon sa opisyal na blog ng Google). Ang produktong Web/IDE ay "na-optimize para sa pagiging komprehensibo." Ginagamit ng CLI ang `:fetchAvailableModels` upang dynamic na tumuklas ng mga modelo, habang gumagamit ang IDE ng statikong piniling listahan.

**Sa aktuwal na paggamit**: Gamitin ang prefix na `agy/` para sa mga modelo ng Gemini (hal. `agy/gemini-3.7-flash-high`). Gamitin ang `antigravity/` para sa statikong piniling listahan. Parehong gumagamit ang mga ito ng iisang Google backend, ngunit magkaiba ang paraan ng pagpapangalan sa mga modelong inilalantad nila. Ibinabahagi ang quota — ang paggamit sa alinmang provider ay ibinibilang sa parehong mga limitasyon ng Google account.

## 2. Google One AI Pro: Sistema ng Quota

> Tingnan ang [Antigravity Docs: Plans](https://antigravity.google/docs/plans) para sa mga opisyal na detalye ng quota at [Changes to Antigravity Plans](https://antigravity.google/blog/changes-to-antigravity-plans) para sa mga pinakabagong pagbabago sa presyo.

Gumagamit ang Google Antigravity ng **dalawang antas na quota** batay sa "Work Done" (bigat ng pagkalkula), hindi sa bilang ng mga mensahe.

### Ang Dalawang Antas

| Antas                  | Ano ito                           | Siklo ng pag-refresh                                                                                   |
| ---------------------- | --------------------------------- | ------------------------------------------------------------------------------------------------------ |
| **5-oras na sprint**   | Agarang pool ng "work done"       | Nire-reset 5 oras pagkatapos ng unang request sa isang session                                         |
| **7-araw na baseline** | Lingguhang mahigpit na limitasyon | Pinapawalang-bisa ang 5-oras na refresh kapag naabot; naka-lock hanggang sa susunod na 7-araw na yugto |

**Paano kinakalkula ang "Work Done"**: Mas mabilis makaubos ng quota ang mga gawaing malakas gumamit ng agent (hal. "I-refactor ang buong repository na ito") kaysa sa mga simpleng gawain (hal. "Ayusin ang function na ito"). Walang real-time na dashboard na nagpapakita ng konsumo.

### Mga Antas ng Plan

| Plan         | Presyo     | Quota                                          | Lingguhang limitasyon                                     |
| ------------ | ---------- | ---------------------------------------------- | --------------------------------------------------------- |
| Free         | $0         | Makabuluhang quota, nire-refresh linggu-linggo | Oo                                                        |
| AI Pro       | $19.99/mo  | Mataas na quota, rolling refresh kada 5 oras   | Oo (pinapawalang-bisa ang 5-oras na refresh kapag naabot) |
| AI Ultra 5x  | $99.99/mo  | 5x na quota ng Pro                             | Walang lingguhang limitasyon                              |
| AI Ultra 20x | $199.99/mo | 20x na quota ng Pro                            | Walang lingguhang limitasyon                              |

### Gemini kumpara sa mga Non-Gemini Model

- **Mga Gemini model** (Flash + Pro): Magkabahagi sa iisang rate limit, na nababawasan batay sa presyo ng API. Kung 8x na mas mura ang Flash kaysa sa Pro, makakakuha ka ng 8x na mas maraming Flash token.
- **Mga non-Gemini model** (Claude, GPT-OSS): May **magkahiwalay** na mga rate limit. Maaaring manatiling available kahit naka-lock out ang Gemini.

### Mga AI Credit (Labis na Paggamit)

> Tingnan ang [Google One AI credits](https://support.google.com/googleone/answer/14534406) para malaman kung paano gumagana ang mga credit.

Kapag naubos ang baseline quota:

- **Never**: Hintaying mag-refresh ang quota; ipinapakita ang "Naabot na ang baseline model quota"
- **Always**: Awtomatikong gamitin ang mga AI credit; bumabalik sa baseline kapag nag-refresh ito

Hiwalay na binibili ang mga credit at ibinabawas batay sa karaniwang presyo ng API.

### Mahahalagang Detalye

- Ang quota ay **pinagsasaluhan sa antas ng account** — iisang quota pool ang pinagsasaluhan ng parehong Google account sa Antigravity IDE, CLI, at OmniRoute
- May sariling hiwalay na quota ang bawat Google account — maraming account = maraming quota pool
- Iniulat ng mga user ng AI Pro ang mga **7-araw na lockout** sa halip na mga 5-oras na reset kapag naabot ang lingguhang baseline (kinumpirma ng Google na sadyang ganito ang disenyo para sa mataas na demand)

**Kapag naubos ang quota ng iyong account**: Awtomatikong sumusubok muli ang OmniRoute gamit ang susunod na available na account sa combo route. Walang kinakailangang manu-manong interbensyon.

## 3. Paano Kumuha ng projectId

Kailangan ng bawat koneksyong antigravity/agy ng Google Cloud Code `projectId`. Kung wala ito, nagbabalik ng 404 ang `/v1internal:models` endpoint.

### Paraan A: Awtomatiko (Inirerekomenda)

Awtomatikong pinangangasiwaan ito ng OmniRoute. Kapag nagdagdag ka ng bagong Google account sa pamamagitan ng Dashboard OAuth:

1. Nire-refresh ng OmniRoute ang token
2. Tinatawag ang `loadCodeAssist` upang matukoy ang projectId
3. Kung walang umiiral na proyekto, tinatawag ang `onboardUser` upang gumawa nito
4. Muling sinusubukan ang `loadCodeAssist` upang makuha ang bagong gawang projectId
5. Sine-save ito sa database

**Gumagana ito para sa karamihan ng mga account** — walang kinakailangang manu-manong hakbang.

### Paraan B: Manu-mano sa Pamamagitan ng agy CLI

Kung mabigo ang awtomatikong pagtukoy (tingnan ang Seksyon 5 para malaman kung kailan ito nangyayari):

```bash
# I-install ang agy CLI (kung hindi pa naka-install)
npm install -g @anthropic-ai/agy

# Mag-login gamit ang iyong Google account
agy login

# Piliin ang account na kailangang i-onboard
# Sisimulan nito ang pagpaparehistro sa Cloud Code at magtatalaga ng projectId
```

Kapag nagtagumpay ang `agy login`, i-refresh ang token sa OmniRoute Dashboard. Awtomatikong matutukoy ang projectId.

### Paano i-verify

Suriin ang database:

```bash
# Sa loob ng OmniRoute container
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

O suriin ang mga log:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. OAuth Redirect URI

### Ang Problema

Nangangailangan ang Google OAuth ng wastong redirect URI. Ginagamit ng default ng OmniRoute ang `http://127.0.0.1:20128/callback` (loopback). Gumagana ito para sa mga lokal na build ngunit **hindi gumagana sa mga remote deployment** (hal., isang server na ina-access sa pamamagitan ng LAN IP).

Tinatanggihan ng Google ang mga redirect URI na:

- Gumagamit ng mga IP address (dapat ay domain na nagtatapos sa `.com`, `.org`, atbp.)
- Hindi tumutugma sa mga nakarehistrong redirect URI sa OAuth client config

### Ang Solusyon

**Opsyon A: Gamitin ang built-in na OAuth flow (default)**

- Gumagana kapag ina-access mo ang OmniRoute mula sa `localhost` o `127.0.0.1`
- Walang kinakailangang configuration

**Opsyon B: Mga custom na OAuth credential**

- Itakda ang `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` sa iyong environment
- Ibigay ang sarili mong mga Google OAuth credential:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Irehistro ang `https://your-domain.com/callback` bilang awtorisadong redirect URI sa Google Cloud Console

**Opsyon C: Gamitin ang agy CLI para sa paunang pag-login**

- Patakbuhin ang `agy login` sa machine na gagamit sa pag-access sa OmniRoute
- Lokal na matatapos ang OAuth flow at mase-save ang mga token
- I-import ang connection sa OmniRoute sa pamamagitan ng Dashboard

### Mga Limitasyon

- Nangangailangan ang mga custom na OAuth credential ng domain name (hindi tumatanggap ang Google ng mga IP address bilang mga redirect URI)
- Kung wala kang domain, gamitin sa halip ang Opsyon A o C

## 5. Pag-troubleshoot: Kapag Nabigo ang Awtomatikong Setup

Awtomatikong pinangangasiwaan ng OmniRoute ang pagtukoy sa projectId at onboarding para sa karamihan ng mga account. Kapag nabigo ito, karaniwang isa sa mga sumusunod ang pangunahing sanhi:

### Naka-block ang rehiyon ng account

**Sintomas**: Ibinabalik ng `agy login` ang "Eligibility check failed: Your current account is not eligible for Antigravity, because it is not currently available in your location."

**Pangunahing sanhi**: May backend na field na "Country Association" ang mga Google account na itinatakda sa oras ng pagpaparehistro. Mahigpit na sinusuri ng agy CLI at Cloud Code API ang field na ito — hindi tulad ng web Gemini na ang kasalukuyang IP mo lang ang sinusuri.

> Upang tingnan o baguhin ang nauugnay na rehiyon ng iyong account, bisitahin ang [Google Country Association Form](https://policies.google.com/country-association-form).

**Bakit gumagana ang web Gemini ngunit hindi ang agy**:

- Web Gemini / Google One: kasalukuyang IP lang ang sinusuri (gumagana ang proxy)
- agy CLI / Cloud Code API: binabasa ang backend na field na Country Association (hindi nakatutulong ang proxy)

**Ayusin**:

1. Bisitahin ang [Google Country Association Form](https://policies.google.com/country-association-form) habang gumagamit ng US IP
2. Magsumite ng kahilingan na baguhin ang rehiyon (piliin ang "I live in a different country")
3. Maghintay nang 1-24 na oras para maproseso ito ng Google at matanggap ang email notification
4. Pagkatapos, dapat nang magtagumpay ang `agy login`

### Walang Cloud Code project ang account

**Sintomas**: Ipinapakita ng mga log ang `loadCodeAssist returned no project id` at `onboardUser failed (400)`.

**Pangunahing sanhi**: Hindi pa kailanman nairehistro ang account sa Google Cloud Code, at nabigo ang awtomatikong onboarding.

**Ayusin**: Manu-manong patakbuhin ang `agy login` upang simulan ang pagpaparehistro sa Cloud Code, pagkatapos ay i-refresh ang token sa OmniRoute Dashboard.

### Nag-expire o binawi ang token

**Sintomas**: Mga 401 error sa mga log, o mga mensaheng "Token has expired."

**Ayusin**: I-refresh ang token sa Dashboard → Providers → agy → I-click ang icon na refresh. Kung binawi rin ang refresh token, kakailanganin mong muling mag-authenticate sa pamamagitan ng OAuth.

```

├─ May subscription ba sa Google One AI Pro ang account?

│  └─ MAYROON ↓
│
├─ Subukan ang awtomatikong pagtuklas (i-refresh ang token sa Dashboard)
│  ├─ Gumagana → Tapos na
│  └─ Hindi pa rin gumagana ↓
│
└─ Manu-mano: Patakbuhin ang `agy login` sa makina
   ├─ Gumagana → I-refresh ang token sa Dashboard, natuklasan ang projectId

```
