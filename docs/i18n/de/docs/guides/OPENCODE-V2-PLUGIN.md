`@omniroute/opencode-plugin-v2` integriert Ihren gesamten OmniRoute-Katalog — Modelle, Combos und
Auto-Combos — in die Modellauswahl von OpenCode v2, einschließlich Anzeigenamen, Preisen und
Budgets für die kostenlose Nutzung.

Es handelt sich um ein separates Paket von `@omniroute/opencode-plugin`, da OpenCode v1 und v2
Plugins über unterschiedliche Schnittstellen laden. Wählen Sie das Paket, das zu Ihrer
OpenCode-Hauptversion passt; zwischen ihnen wird nichts gemeinsam genutzt, sodass die
Aktualisierung des einen niemals eine Aktualisierung des anderen erzwingt.

## Voraussetzungen

- OpenCode v2.
- Ein erreichbares OmniRoute-Gateway (standardmäßig `http://localhost:20128`).
- Node.js 22 oder 24.

## Installation

Fügen Sie das Plugin zu `opencode.json` hinzu:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

Modelle erscheinen anschließend als `omniroute/<provider>/<model>`; `providerId` bestimmt
dieses Präfix sowie die ID der Integration, unter der OpenCode die Anmeldedaten speichert.

## Anmeldedaten

Das Plugin sucht an drei Stellen nach einem Gateway-Schlüssel, und zwar in dieser Reihenfolge:

1. **Die in OpenCode hinterlegten Anmeldedaten.** Das Plugin registriert eine Integration,
   sodass der OpenCode-eigene Authentifizierungsablauf den Schlüssel speichern kann. Nichts
   davon landet in `opencode.json` — diese Option ist vorzuziehen.
2. `apiKey` in den Plugin-Optionen für eine projektspezifische Überschreibung. Dadurch wird der
   Schlüssel in einer Datei abgelegt, die möglicherweise eingecheckt wird.
3. `OMNIROUTE_API_KEY` in der Umgebung.

Ist keine der drei Optionen vorhanden, bleibt der Katalog leer und das Plugin weist beim Start
einmal darauf hin, anstatt eine kommentarlos leere Modellauswahl anzuzeigen.

### Das Verwaltungs-Token ist ein anderer Schlüssel

Combos, Anbieterstatus und Anreicherung (Anzeigenamen, Preise und Budgets für die kostenlose
Nutzung) stammen von den `/api/*`-Endpunkten des Gateways, die in den meisten Bereitstellungen
durch ein **Verwaltungs-Token** anstatt durch den Inferenzschlüssel geschützt sind:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<Verwaltungs-Lese-Token>"
}
```

Wenn `managementReadToken` nicht gesetzt ist, wird ersatzweise `apiKey` verwendet. Lehnt ein
Gateway diesen Ersatz ab, wird der Katalog dennoch veröffentlicht, jedoch mit den rohen
Modell-IDs anstelle von Anzeigenamen, ohne Deduplizierung kanonischer Aliase, ohne Preise und
ohne Combos. Das Plugin warnt in diesem Fall einmal pro Endpunkt und nennt dabei den Endpunkt
sowie die verlorenen Informationen — eine eingeschränkte Modellauswahl bleibt somit nie
ungeklärt.

## Optionen

| Schlüssel                        | Standardwert                                       | Hinweise                                                                                                                      |
| -------------------------------- | -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `providerId`                     | `"omniroute"`                                      | Anbieter-ID, Integrations-ID und das Präfix, unter dem Modelle erscheinen                                                     |
| `baseURL`                        | erforderlich                                       | Gateway-Stamm-URL, nur `http(s)`; das Suffix `/v1` wird bei Bedarf hinzugefügt                                                |
| `apiKey`                         | hinterlegte Anmeldedaten, dann `OMNIROUTE_API_KEY` | Chat-Schlüssel für `/v1/*`                                                                                                    |
| `managementReadToken`            | verwendet ersatzweise `apiKey`                     | Schlüssel für `/api/*` — normalerweise **nicht** derselbe                                                                     |
| `displayName`                    | `"OmniRoute"`                                      | Anbietername in der Modellauswahl                                                                                             |
| `timeoutMs`                      | `10000`                                            | Abruf-Zeitüberschreitung pro Endpunkt (Auto-Combos verwenden 5 s)                                                             |
| `modelCacheTtlMs`                | `300000`                                           | TTL des Katalog-Caches; ein Snapshot auf der Festplatte beschleunigt Kaltstarts                                               |
| `timeouts`                       | verwendet ersatzweise `timeoutMs`                  | Endpunktspezifische Zeitbudgets in ms: `models`, `combos`, `autoCombos`, `enrichment`                                         |
| `enrichment`                     | `true`                                             | Namen, Preise und Budgets für die kostenlose Nutzung abrufen                                                                  |
| `providerTag`                    | `true`                                             | Dem Anzeigenamen den vorgelagerten Anbieter voranstellen, an den weitergeleitet wird                                          |
| `usableOnly`                     | `false`                                            | Nur Anbieter beibehalten, die das Gateway als bereitgestellt meldet                                                           |
| `visibleModels` / `hiddenModels` | `[]`                                               | Positiv- und Negativlisten mit exakter oder suffixbasierter Übereinstimmung; Ausschluss hat Vorrang                           |
| `geminiSanitization`             | `true`                                             | Von Gemini abgelehnte JSON-Schema-Schlüsselwörter aus Tool-Schemas entfernen (`$ref`-Tools werden unverändert weitergeleitet) |
| `apiFormat.allowAnthropic`       | `false`                                            | IDs auf der Positivliste über den Anthropic-API-Block weiterleiten                                                            |
| `apiFormat.anthropicModels`      | `[]`                                               | Vollständige Modell-IDs, die an Anthropic weitergeleitet werden                                                               |
| `logLevel` / `startupDebug`      | `warn` / `false`                                   | Ausführlichkeit der Protokollierung                                                                                           |

## So bleibt der Katalog aktuell

Der Katalog wird bei Bedarf abgerufen und für `modelCacheTtlMs` zwischengespeichert. Ein Snapshot auf der Festplatte sorgt dafür, dass der zuletzt bekannte Katalog verfügbar bleibt, wenn das Gateway nicht erreichbar ist — ein Ausfall kostet Sie also lediglich Aktualität. Modelle und Kombinationen werden veröffentlicht, sobald sie eintreffen; automatische Kombinationen, die Anbieterliste und das Anreicherungs-Overlay werden nach ihrem Eintreffen eingebunden, sodass ein langsamer Endpunkt nicht die gesamte Modellauswahl blockieren kann.

Die Namen enthalten die dem Gateway bekannten Informationen: den vorgelagerten Anbieter, an den ein Modell weitergeleitet wird, eine `[Free]`-Kennzeichnung und das zugehörige Budget — damit zwei Verbindungen, die dasselbe Modell anbieten, unterscheidbar bleiben. Deaktivieren Sie das Präfix mit `"providerTag": false`.

Es gibt keinen Befehl zur manuellen Aktualisierung: OpenCode-v2-Befehle sind Prompt-Vorlagen und keine Callbacks, daher kann ein Plugin keinen solchen Befehl bereitstellen. Aktualisierungen richten sich nach der TTL; der Host wird nur dann zum Neuladen aufgefordert, wenn sich der Katalog oder das Overlay tatsächlich geändert hat, niemals bei jeder Aktualisierung.

## Tool-Aufrufe mit Gemini

Gemini lehnt eine gesamte Anfrage ab, wenn deren Tool-Deklarationen `$schema` oder
`additionalProperties` enthalten, und antwortet mit `400 INVALID_ARGUMENT`. Das Plugin entfernt diese Schlüsselwörter aus Tool-Schemas, die für ein Gemini-Modell dieses Anbieters bestimmt sind, und lässt alle anderen Anfragen unverändert. Ein Tool mit einem `$ref` wird unverändert weitergeleitet und nicht bereinigt, da das Entfernen der Referenz das Schema auf „alles akzeptieren“ erweitern würde.
Legen Sie `"geminiSanitization": false` fest, um diese Funktion zu deaktivieren.

## Fehlerbehebung

| Symptom                                                      | Ursache                                                                                                                            |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| Die Modellauswahl zeigt kein OmniRoute-Modell                | Es wurde kein Schlüssel aufgelöst (prüfen Sie die Startwarnung), oder das Gateway ist nicht erreichbar                             |
| Unverarbeitete Modell-IDs, keine Kombinationen, keine Preise | Die Verwaltungsendpunkte haben das Token abgelehnt — legen Sie `managementReadToken` fest                                          |
| Eine Sitzung ist an `opencode-<id>/…` gebunden               | Das v1-Plugin veröffentlichte `opencode-<id>`; v2 veröffentlicht nur `<id>`, wählen Sie das Modell daher erneut unter `<id>/…` aus |
