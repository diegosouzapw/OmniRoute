## 1. Antigravity im Vergleich zu Antigravity CLI (agy)

Beide Anbieter nutzen dasselbe **Google-Backend** — identischer OAuth-Client, identische Token-Aktualisierung, identische Endpunkte und Google-Konten. Der Unterschied liegt darin, welche Modelle Ihnen angezeigt werden.

> Googles offiziellen Vergleich finden Sie in der [Ankündigung der Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli).

| Aspekt                     | `antigravity` (IDE)                                   | `agy` (CLI)                                          |
| -------------------------- | ----------------------------------------------------- | ---------------------------------------------------- |
| **Google-Produkt**         | Antigravity 2.0 / Antigravity IDE                     | Antigravity CLI                                      |
| **Backend**                | Dieselbe Google Cloud Code API                        | Dieselbe Google Cloud Code API                       |
| **OAuth / Token**          | Derselbe Client, dieselbe Aktualisierung              | Derselbe Client, dieselbe Aktualisierung             |
| **Modellkatalog**          | Statisch kuratierte Liste (in OmniRoute fest codiert) | Live-Abfrage bei Google über `:fetchAvailableModels` |
| **Claude-Modelle**         | Sonnet 4.6, Opus 4.6 (jeweils 4 Varianten)            | Sonnet 4.6, Opus 4.6 (jeweils 4 Varianten)           |
| **Gemini-Benennung**       | Übersichtliche Bezeichnungen (Low/Medium/High)        | Upstream-IDs (extra-low/low/agent)                   |
| **Zusätzliche Modelle**    | `gpt-oss-120b-medium`                                 | Kann zusätzliche Modelle von Google enthalten        |
| **Standardanwendungsfall** | IDE-Integration (VS Code, JetBrains)                  | CLI-/API-Zugriff                                     |
| **Kontingent**             | Wird mit agy geteilt (dasselbe Google-Konto)          | Wird mit antigravity geteilt (dasselbe Google-Konto) |

**Verfügbare Modelle (experimentell verifiziert, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (verschiedene Denkstufen)
- Claude: Sonnet 4.6, Opus 4.6 (jeweils mit den Varianten default/low/medium/high)
- Sonstige: GPT-OSS 120B Medium
- **Claude Sonnet 5 ist NICHT verfügbar** — nur Varianten von 4.6 werden unterstützt

**Warum sich der Modellkatalog unterscheidet**: Googles CLI ist laut offiziellem Google-Blog „für Geschwindigkeit und geringen Overhead optimiert“ und „gemeinsam mit Gemini-Modellen optimiert“. Das Web-/IDE-Produkt ist „auf Vollständigkeit optimiert“. Die CLI verwendet `:fetchAvailableModels`, um Modelle dynamisch zu ermitteln, während die IDE eine statisch kuratierte Liste verwendet.

**In der Praxis**: Verwenden Sie für Gemini-Modelle das Präfix `agy/` (z. B. `agy/gemini-3.7-flash-high`). Verwenden Sie `antigravity/` für die statisch kuratierte Liste. Beide greifen auf dasselbe Google-Backend zu, stellen jedoch unterschiedliche Modellbezeichnungen bereit. Das Kontingent wird geteilt — die Nutzung eines der beiden Anbieter wird auf die Limits desselben Google-Kontos angerechnet.

## 2. Google One AI Pro: Kontingentsystem

> Offizielle Kontingentdetails finden Sie unter [Antigravity-Dokumentation: Tarife](https://antigravity.google/docs/plans) und die neuesten Preisaktualisierungen unter [Änderungen an den Antigravity-Tarifen](https://antigravity.google/blog/changes-to-antigravity-plans).

Google Antigravity verwendet ein **zweistufiges Kontingent**, das auf „Erledigter Arbeit“ (Rechenaufwand) und nicht auf der Anzahl der Nachrichten basiert.

### Die zwei Ebenen

| Ebene                 | Beschreibung                               | Aktualisierungszyklus                                                                                 |
| --------------------- | ------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| **5-Stunden-Sprint**  | Sofort verfügbares Kontingent für „Arbeit“ | Wird 5 Stunden nach der ersten Anfrage einer Sitzung zurückgesetzt                                    |
| **7-Tage-Basislimit** | Wöchentliches hartes Limit                 | Setzt bei Erreichen die 5-Stunden-Aktualisierung außer Kraft; Sperre bis zum nächsten 7-Tage-Zeitraum |

**So wird „Erledigte Arbeit“ berechnet**: Aufgaben mit intensiver Agentennutzung (z. B. „Überarbeite dieses gesamte Repository“) verbrauchen das Kontingent wesentlich schneller als einfache Aufgaben (z. B. „Korrigiere diese Funktion“). Es gibt kein Echtzeit-Dashboard, das den Verbrauch anzeigt.

### Tarifstufen

| Tarif        | Preis         | Kontingent                                             | Wöchentliches Limit                                               |
| ------------ | ------------- | ------------------------------------------------------ | ----------------------------------------------------------------- |
| Kostenlos    | $0            | Sinnvolles Kontingent, wöchentliche Aktualisierung     | Ja                                                                |
| AI Pro       | $19.99/Monat  | Hohes Kontingent, rollierende 5-Stunden-Aktualisierung | Ja (setzt bei Erreichen die 5-Stunden-Aktualisierung außer Kraft) |
| AI Ultra 5x  | $99.99/Monat  | 5-faches Pro-Kontingent                                | Kein wöchentliches Limit                                          |
| AI Ultra 20x | $199.99/Monat | 20-faches Pro-Kontingent                               | Kein wöchentliches Limit                                          |

### Gemini- und Nicht-Gemini-Modelle

- **Gemini-Modelle** (Flash + Pro): Nutzen gemeinsam ein einziges Ratenlimit, das entsprechend der API-Preisgestaltung verbraucht wird. Wenn Flash achtmal günstiger als Pro ist, erhalten Sie achtmal mehr Flash-Tokens.
- **Nicht-Gemini-Modelle** (Claude, GPT-OSS): Verfügen über **separate** Ratenlimits. Sie können weiterhin verfügbar sein, selbst wenn Gemini gesperrt ist.

### AI-Guthaben (Mehrverbrauch)

> Informationen zur Funktionsweise von Guthaben finden Sie unter [Google One AI-Guthaben](https://support.google.com/googleone/answer/14534406).

Wenn das Basiskontingent aufgebraucht ist:

- **Nie**: Auf die Aktualisierung des Kontingents warten; zeigt „Basiskontingent des Modells erreicht“ an
- **Immer**: AI-Guthaben automatisch verwenden; wechselt nach der Aktualisierung wieder zum Basiskontingent zurück

Guthaben wird separat erworben und gemäß den standardmäßigen API-Preisen abgezogen.

### Wichtige Details

- Das Kontingent wird **auf Kontoebene gemeinsam genutzt** — dasselbe Google-Konto in der Antigravity IDE, der CLI und OmniRoute nutzt ein gemeinsames Kontingent
- Jedes Google-Konto verfügt über ein eigenes unabhängiges Kontingent — mehrere Konten = mehrere Kontingente
- AI Pro-Nutzer haben von **7-tägigen Sperren** anstelle von Zurücksetzungen nach 5 Stunden berichtet, wenn das wöchentliche Basislimit erreicht wurde (Google hat bestätigt, dass dies bei hoher Nachfrage beabsichtigt ist)

**Wenn das Kontingent Ihres Kontos aufgebraucht ist**: OmniRoute versucht es automatisch mit dem nächsten verfügbaren Konto in der Kombinationsroute erneut. Es ist kein manueller Eingriff erforderlich.

## 3. So erhalten Sie eine projectId

Jede antigravity/agy-Verbindung benötigt eine Google Cloud Code-`projectId`. Ohne sie gibt der Endpunkt `/v1internal:models` den Statuscode 404 zurück.

### Methode A: Automatisch (empfohlen)

OmniRoute übernimmt dies automatisch. Wenn Sie über Dashboard OAuth ein neues Google-Konto hinzufügen:

1. OmniRoute aktualisiert das Token
2. Ruft `loadCodeAssist` auf, um die projectId zu ermitteln
3. Wenn kein Projekt vorhanden ist, wird `onboardUser` aufgerufen, um eines zu erstellen
4. Ruft `loadCodeAssist` erneut auf, um die neu erstellte projectId abzurufen
5. Speichert sie in der Datenbank

**Dies funktioniert für die meisten Konten** — es sind keine manuellen Schritte erforderlich.

### Methode B: Manuell über die agy CLI

Wenn die automatische Ermittlung fehlschlägt (siehe Abschnitt 5 für mögliche Ursachen):

```bash
# agy CLI installieren (falls noch nicht geschehen)
npm install -g @anthropic-ai/agy

# Mit Ihrem Google-Konto anmelden
agy login

# Das Konto auswählen, das registriert werden muss
# Dadurch wird die Cloud Code-Registrierung ausgelöst und eine projectId zugewiesen
```

Nachdem `agy login` erfolgreich abgeschlossen wurde, aktualisieren Sie das Token im OmniRoute Dashboard. Die projectId wird automatisch ermittelt.

### So überprüfen Sie es

Überprüfen Sie die Datenbank:

```bash
# Innerhalb des OmniRoute-Containers
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Oder überprüfen Sie die Protokolle:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. OAuth-Weiterleitungs-URI

### Das Problem

Google OAuth erfordert eine gültige Weiterleitungs-URI. OmniRoute verwendet standardmäßig `http://127.0.0.1:20128/callback` (Loopback). Dies funktioniert für lokale Builds, **schlägt jedoch bei Remote-Bereitstellungen fehl** (z. B. bei einem Server, auf den über eine LAN-IP zugegriffen wird).

Google lehnt Weiterleitungs-URIs ab, die:

- IP-Adressen verwenden (es muss sich um eine Domain handeln, die auf `.com`, `.org` usw. endet)
- Nicht mit den registrierten Weiterleitungs-URIs in der OAuth-Client-Konfiguration übereinstimmen

### Die Lösung

**Option A: Den integrierten OAuth-Ablauf verwenden (Standard)**

- Funktioniert, wenn Sie über `localhost` oder `127.0.0.1` auf OmniRoute zugreifen
- Keine Konfiguration erforderlich

**Option B: Benutzerdefinierte OAuth-Anmeldedaten**

- Legen Sie `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` in Ihrer Umgebung fest
- Geben Sie Ihre eigenen Google-OAuth-Anmeldedaten an:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Registrieren Sie `https://your-domain.com/callback` in der Google Cloud Console als autorisierte Weiterleitungs-URI

**Option C: agy CLI für die erstmalige Anmeldung verwenden**

- Führen Sie `agy login` auf dem Computer aus, der auf OmniRoute zugreifen wird
- Der OAuth-Ablauf wird lokal abgeschlossen und die Tokens werden gespeichert
- Importieren Sie die Verbindung über das Dashboard in OmniRoute

### Einschränkungen

- Benutzerdefinierte OAuth-Anmeldedaten erfordern einen Domainnamen (Google akzeptiert keine IP-Adressen als Weiterleitungs-URIs)
- Wenn Sie keine Domain haben, verwenden Sie stattdessen Option A oder C

## 5. Fehlerbehebung: Wenn die automatische Einrichtung fehlschlägt

OmniRoute übernimmt für die meisten Konten automatisch die Ermittlung der projectId und das Onboarding. Wenn dies fehlschlägt, liegt meist eine der folgenden Ursachen vor:

### Kontoregion ist gesperrt

**Symptom**: `agy login` gibt „Eligibility check failed: Your current account is not eligible for Antigravity, because it is not currently available in your location.“ zurück.

**Ursache**: Google-Konten verfügen über ein Backend-Feld namens „Country Association“, das bei der Registrierung festgelegt wird. Die agy CLI und die Cloud Code API prüfen dieses Feld strikt – anders als Gemini im Web, das nur Ihre aktuelle IP-Adresse prüft.

> Um die mit Ihrem Konto verknüpfte Region zu überprüfen oder zu ändern, besuchen Sie das [Google-Formular zur Länderzuordnung](https://policies.google.com/country-association-form).

**Warum Gemini im Web funktioniert, agy jedoch nicht**:

- Gemini im Web / Google One: Prüft nur die aktuelle IP-Adresse (Proxy funktioniert)
- agy CLI / Cloud Code API: Liest das Backend-Feld „Country Association“ (ein Proxy hilft nicht)

**Behebung**:

1. Rufen Sie über eine US-IP-Adresse das [Google-Formular zur Länderzuordnung](https://policies.google.com/country-association-form) auf
2. Reichen Sie einen Antrag auf Änderung der Region ein (wählen Sie „I live in a different country“)
3. Warten Sie 1–24 Stunden auf die Bearbeitung durch Google und die E-Mail-Benachrichtigung
4. Danach sollte `agy login` erfolgreich sein

### Das Konto hat kein Cloud-Code-Projekt

**Symptom**: Die Protokolle zeigen `loadCodeAssist returned no project id` und `onboardUser failed (400)`.

**Ursache**: Das Konto wurde noch nie bei Google Cloud Code registriert, und das automatische Onboarding ist fehlgeschlagen.

**Behebung**: Führen Sie `agy login` manuell aus, um die Cloud-Code-Registrierung auszulösen, und aktualisieren Sie anschließend das Token im OmniRoute-Dashboard.

### Token ist abgelaufen oder wurde widerrufen

**Symptom**: 401-Fehler in den Protokollen oder Meldungen wie „Token has expired“.

**Behebung**: Aktualisieren Sie das Token unter Dashboard → Providers → agy → Klicken Sie auf das Aktualisierungssymbol. Wenn das Aktualisierungs-Token selbst widerrufen wurde, müssen Sie sich erneut über OAuth authentifizieren.

