> `src/app/api/settings/obsidian/webdav/route.ts` (Einstellungs-APIs). Die Tool-Registrierung
> und Scope-Verknüpfung befinden sich in `open-sse/mcp-server/server.ts`.

## Was es ist

OmniRoute bindet einen **Obsidian**-Tresor als **Kontextquelle** ein — eine lokale
Markdown-Wissensdatenbank, die Agenten über den integrierten MCP-Server lesen und
bearbeiten können. Die Integration kommuniziert mit dem Community-Plugin
**Obsidian Local REST API**, das innerhalb der Desktop-App ausgeführt wird. Dadurch
können Agenten Notizen durchsuchen, Dateien lesen/schreiben/patchen, den Tresor
auflisten, mit täglichen/wöchentlichen periodischen Notizen arbeiten, Tags verwalten,
Obsidian-Befehle ausführen und (optional) eine bidirektionale
Desktop↔Mobilgerät-Tresorsynchronisierung koordinieren.

Der Client (`src/lib/obsidian/api.ts`) kapselt die Local REST API mit:

- **Wiederholungsversuchen mit Backoff** bei vorübergehenden `5xx`-Fehlern und einem
  **30-Sekunden-Timeout** über `AbortController`.
- **Typisierter Fehlerklassifizierung** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- Einem **verständlichen Hinweis „Obsidian kann nicht erreicht werden“**, der auf den
  häufigen Portfehler hinweist (HTTP auf `27123`, **nicht** der MCP-Endpunkt auf
  `27124`) und die Tailscale-Variante nennt.
- Tresorrelativer **Pfadkodierung**, damit Notizpfade mit Leerzeichen/Schrägstrichen
  sicher verarbeitet werden.

## Einrichtung

Für das Obsidian-Token oder die Basis-URL gibt es **keine Umgebungsvariable** — beide
werden über `src/lib/db/obsidian.ts` in der SQLite-Tabelle `key_value` (Namespace
`obsidian`) gespeichert. Das Token ist **im Ruhezustand verschlüsselt** (AES-256-GCM,
mit Klartext-Fallback für Abwärtskompatibilität). Die Konfiguration erfolgt über den
Tab **Kontextquellen** im Endpoint-Dashboard (`ObsidianSourceCard`) oder über die
Einstellungs-REST-API.

> [!IMPORTANT]
> Das Plugin **Obsidian Local REST API** muss installiert sein und ausgeführt werden.
> Seine REST-Schnittstelle lauscht auf **HTTP `127.0.0.1:27123`** (die standardmäßige
> Basis-URL). Port `27124` ist ein _separater_ MCP-/HTTPS-Endpunkt und wird von der
> Einstellungsroute ausdrücklich abgelehnt. Verwenden Sie bei einer Verbindung von
> einem anderen Gerät `http://<tailscale-ip>:27123`.

### Konfigurationsschlüssel (SQLite `key_value`, Namespace `obsidian`)

| Schlüssel         | Zweck                                                       | Verschlüsselt |
| ----------------- | ----------------------------------------------------------- | ------------- |
| `api_key`         | Bearer-Token der Local REST API                             | ja            |
| `base_url`        | REST-Basis-URL (Standard: `http://127.0.0.1:27123`)         | nein          |
| `vault_path`      | Absoluter Pfad zum Tresorverzeichnis (für Synchronisierung) | nein          |
| `webdav_username` | Generierter WebDAV-Benutzername (Tresorsynchronisierung)    | nein          |
| `webdav_password` | Generiertes WebDAV-Passwort (Tresorsynchronisierung)        | ja            |
| `webdav_enabled`  | Ob die WebDAV-Tresorsynchronisierung aktiviert ist          | nein          |

### Konfiguration über REST

```bash
# Local-REST-API-Token speichern und validieren (POST validiert es über eine Statusprüfung)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Verbindungsstatus prüfen (gibt connected, hasToken, baseUrl, vaultPath zurück)
curl http://localhost:20128/api/settings/obsidian

# Verbindung trennen (löscht das gespeicherte Token)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Alle Methoden erfordern eine Dashboard-Authentifizierung. `POST` lehnt jede URL auf
Port `27124` ab und validiert das Token durch einen Aufruf des Statusendpunkts der
Local REST API, bevor es gespeichert wird.

### WebDAV-Tresorsynchronisierung

`src/app/api/settings/obsidian/webdav/route.ts` verwaltet eine optionale
WebDAV-gestützte Tresorsynchronisierung (gesteuert durch
`src/lib/obsidianSync.ts`). Bei der Aktivierung wird OmniRoute auf ein lokales
Tresorverzeichnis ausgerichtet und ein zufälliges Paar aus WebDAV-Benutzername und
-Passwort erzeugt:

```bash
# WebDAV-Synchronisierung für ein Tresorverzeichnis aktivieren (erzeugt Benutzername/Passwort)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# WebDAV-Synchronisierungsstatus abrufen (Anmeldedaten werden nur im aktivierten Zustand zurückgegeben)
curl http://localhost:20128/api/settings/obsidian/webdav

# WebDAV-Synchronisierung deaktivieren (löscht Anmeldedaten + verwaltete .stignore)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### API-Schlüsselbezogene Kontextquelle (optional)

Die Obsidian-Konfiguration kann über die Tabelle `api_key_context_sources`
**pro API-Schlüssel** festgelegt werden (`src/lib/db/apiKeyContextSources.ts`). Wenn
ein MCP-Aufruf die ID eines authentifizierten API-Schlüssels enthält, bevorzugt
`getObsidianConfigForApiKey()` das eigene Token, die eigene Basis-URL und den eigenen
Tresorpfad dieses Schlüssels (`source: "api_key"`); andernfalls wird auf die globale
Konfiguration (`source: "global"`) zurückgegriffen.

## MCP-Tools (22)

Definiert in `open-sse/mcp-server/tools/obsidianTools.ts`. Token und Basis-URL werden
für jeden Aufruf aufgelöst (zuerst pro API-Schlüssel, dann global). Tools, die auf den OmniRoute-**Sync-Server**
zugreifen (die vier `obsidian_sync_*`-Tools), benötigen zusätzlich das in den
OmniRoute-Einstellungen konfigurierte Sync-Authentifizierungstoken.

### Lese-Tools (`read:obsidian`)

| Tool                         | Beschreibung                                                                                                                 |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Prüft, ob die lokale REST-API erreichbar und authentifiziert ist.                                                            |
| `obsidian_search_simple`     | Volltextsuche in Notizinhalten; gibt Ausschnitte mit Dateipfaden zurück.                                                     |
| `obsidian_search_structured` | Suche mithilfe eines JSON-Logic-Ausdrucks (and/or/regex/path-Filter).                                                        |
| `obsidian_read_note`         | Liest eine Notiz anhand ihres Vault-relativen Pfads; optional eine bestimmte Überschrift/einen bestimmten Block/Frontmatter. |
| `obsidian_list_vault`        | Listet Dateien und Verzeichnisse im Vault auf (Eintragsbaum).                                                                |
| `obsidian_get_document_map`  | Ruft die Überschriftenstruktur der Notiz als Zuordnung von Überschriften → Zeilennummern ab.                                 |
| `obsidian_get_note_metadata` | Ruft Frontmatter, Tags, Links sowie Zeichen-/Wortanzahl ohne den vollständigen Inhalt ab.                                    |
| `obsidian_get_active_file`   | Ruft Pfad und Inhalt der aktuell aktiven Datei in Obsidian ab.                                                               |
| `obsidian_get_periodic_note` | Ruft die tägliche/wöchentliche/monatliche periodische Notiz für ein Datum ab (heute, falls nicht angegeben).                 |
| `obsidian_get_tags`          | Listet alle Vault-Tags mit ihrer Häufigkeit auf.                                                                             |
| `obsidian_list_commands`     | Listet verfügbare Obsidian-Befehls-IDs auf (zur Verwendung mit `obsidian_execute_command`).                                  |
| `obsidian_sync_status`       | Status des OmniRoute-Sync-Servers: Ausführung, Vault-Name, Port, Betriebszeit, letzte Synchronisierung.                      |
| `obsidian_sync_conflicts`    | Listet ungelöste Synchronisierungskonflikte auf (Pfad, Konfliktpfad, Erkennungszeitpunkt).                                   |

### Schreib-Tools (`write:obsidian`)

| Tool                             | Beschreibung                                                                                                           |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Erstellt oder überschreibt eine Notiz mit dem angegebenen Markdown-Inhalt.                                             |
| `obsidian_append_note`           | Hängt Inhalt an eine Notiz an; optional an eine bestimmte Überschrift/einen bestimmten Block.                          |
| `obsidian_patch_note`            | Hängt gezielt Inhalt an eine Überschrift, einen Block oder ein Frontmatter-Feld an, stellt ihn voran oder ersetzt ihn. |
| `obsidian_delete_note`           | Löscht eine Notiz dauerhaft aus dem Vault.                                                                             |
| `obsidian_move_note`             | Verschiebt eine Notiz innerhalb des Vaults oder benennt sie um.                                                        |
| `obsidian_execute_command`       | Führt einen Obsidian-Befehl anhand seiner Befehls-ID aus.                                                              |
| `obsidian_open_file`             | Öffnet eine Datei in Obsidian (erstellt sie, falls sie nicht vorhanden ist).                                           |
| `obsidian_sync_trigger`          | Löst eine sofortige bidirektionale Desktop↔Mobilgerät-Vault-Synchronisierung aus.                                      |
| `obsidian_sync_resolve_conflict` | Löst einen Synchronisierungskonflikt: `local` (Mobilgerät), `remote` (Desktop) oder `keep-both` beibehalten.           |

> [!NOTE]
> Ziele von `obsidian_patch_note` akzeptieren einen `targetType` vom Typ `heading | block | frontmatter`
> und eine `operation` vom Typ `append | prepend | replace`, mit einem optionalen
> `createTargetIfMissing`. Die vier `obsidian_sync_*`-Tools kommunizieren mit dem lokalen Sync-
> Server (standardmäßig `http://127.0.0.1:27781`) und benötigen das Sync-Token.

### Berechtigungsbereiche

Lese-Tools benötigen `read:obsidian`; Schreib-Tools benötigen `write:obsidian`. Die Durchsetzung
ist identisch mit Notion — sie wird von `withScopeEnforcement()` in
`open-sse/mcp-server/server.ts` übernommen, durch `OMNIROUTE_MCP_ENFORCE_SCOPES=true` aktiviert und
bezieht die zulässigen Berechtigungsbereiche aus `OMNIROUTE_MCP_SCOPES` oder dem Berechtigungsbereichskontext des API-Schlüssels. Siehe
[MCP-SERVER.md](./MCP-SERVER.md).

## Endpunkte

| Methode  | Pfad                            | Zweck                                                               |
| -------- | ------------------------------- | ------------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | Gibt `{ connected, hasToken, baseUrl, vaultPath }` zurück.          |
| `POST`   | `/api/settings/obsidian`        | Speichert und validiert das Token (Port `27124` wird abgelehnt).    |
| `DELETE` | `/api/settings/obsidian`        | Trennt die Verbindung (gespeichertes Token wird gelöscht).          |
| `GET`    | `/api/settings/obsidian/webdav` | WebDAV-Synchronisierungsstatus und Zugangsdaten (sofern aktiviert). |
| `POST`   | `/api/settings/obsidian/webdav` | Aktiviert die WebDAV-Synchronisierung für ein Vault-Verzeichnis.    |
| `DELETE` | `/api/settings/obsidian/webdav` | Deaktiviert die WebDAV-Synchronisierung.                            |

> Dies sind Einstellungsrouten des Dashboards. Der Vault selbst ist über die lokale
> REST-API von Obsidian (die konfigurierte `base_url`) sowie über die obigen MCP-Werkzeuge erreichbar —
> es gibt keinen öffentlichen Obsidian-Proxy-Endpunkt unter `/v1`.

## Anwendungsfälle

- **Vault-basierte Antworten** — `obsidian_search_simple` / `obsidian_search_structured`
  und anschließend `obsidian_read_note`, damit ein Agent auf Grundlage Ihrer tatsächlichen Notizen antwortet.
- **Erstellen von Notizen / Journaling** — `obsidian_write_note`, `obsidian_append_note` oder
  das präzise `obsidian_patch_note`, um Agentenausgaben, Zusammenfassungen oder tägliche Notizen
  (`obsidian_get_periodic_note`) im Vault zu protokollieren.
- **Vault-Navigation** — `obsidian_list_vault`, `obsidian_get_document_map` und
  `obsidian_get_tags`, um die Struktur vor dem Lesen oder Schreiben zu erkunden.
- **Obsidian-Automatisierung** — `obsidian_list_commands` + `obsidian_execute_command`, um
  Plugins/Befehle über einen Agenten zu steuern; `obsidian_open_file`, um eine Notiz in der Benutzeroberfläche anzuzeigen.
- **Mobile Synchronisierung** — Aktivieren Sie die WebDAV-Synchronisierung und verwenden Sie anschließend `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`,
  um Desktop und Mobilgerät zu koordinieren und Konflikte zu lösen.
