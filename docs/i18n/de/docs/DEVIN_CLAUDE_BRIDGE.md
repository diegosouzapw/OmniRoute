`devin-cli-agentic` ermöglicht es der echten Claude-Code-Laufzeitumgebung, den lokalen Anthropic-
Messages-Endpunkt von OmniRoute zu verwenden, während die offizielle Devin CLI Modellantworten über ACP stdio
bereitstellt. Die bestehenden Anbieter für Anthropic, Claude OAuth, Claude Web oder `devin-cli`
werden dabei nicht verändert.

> **Aktueller Status: Claude Code ist auf `2.1.258` festgesetzt; Offline- und Live-Validierung wurden zuletzt
> für `2.1.220` aufgezeichnet.** Mit der Festsetzung auf `2.1.220` wurden drei isolierte Szenarien über Devin CLI
> `3000.2.17` und das Modell `swe-1-7-lightning` abgeschlossen; dieser abschließende Live-Lauf bestätigte von
> Clientseite gesteuerte `Read`-, `Edit`- und `Bash`-Durchläufe, erfolgreiche `npm test`-Ergebnisse,
> die Erkennung von Projektbefehlen und Skills, ausschließliches Routing über Devin
> sowie keinerlei ausgehenden Claude-Datenverkehr. Anschließend wurde die Festsetzung auf `2.1.258`
> angehoben (die CLI-Generation, deren Claude-Identität OmniRoute nachahmt, und die erste Version,
> die die Fable-5.1-Stufe nativ ausliefert). Mit der neuen Festsetzung wurden die Installationsschicht
> und `claude --version` auf dem festgesetzten Basis-Image überprüft; außerdem bestehen die
> Unit-Test-Suite der Bridge, `compose config` und der statische Isolationsnachweis — das
> Offline-Mock-Szenario und die Live-Suite mit drei Szenarien wurden jedoch noch nicht erneut
> ausgeführt. Führen Sie diese erneut aus (siehe „Aktualisieren festgesetzter Tools“), bevor Sie sich
> mit dieser Festsetzung auf die Bridge verlassen.

## Architektur

```text
Claude Code 2.1.258 (isolierter Linux-Container ohne Root-Rechte)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-Format, Anbieter ohne Authentifizierung)
  -> devin acp --agent-type summarizer (offizielles ACP stdio, keine Devin-Tools)
  -> Devin-Konto im dedizierten devin-auth-Volume
```

Der standardmäßige ACP-Agent der offiziellen CLI kann seine eigenen Tools ausführen, daher verwendet
diese Bridge ihn nicht. Sie startet den fest vorgegebenen ACP-Agenten `summarizer`, dessen offizieller
CLI-Modus keine Tools besitzt, und rahmt die serialisierte Anthropic-Anfrage als Ausführungsspur ein.
Wenn eine weitere von Claude gesteuerte Aktion erforderlich ist, muss die Antwort genau einen
Client-Tool-Umschlag enthalten. Jeder ACP-Aufruf `tool_call` oder `tool_call_update` wird abgelehnt,
bevor eine Antwort als erfolgreich gemeldet werden kann.

Der Serializer in `open-sse/executors/devin-agentic/serializer.ts` bewahrt `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` sowie die
von Claude Code bereitgestellten Tools. Bilder und unbekannte Blöcke führen explizit zu einem
Fehler. Große Tool-Ergebnisse verwenden eine sichtbare Kürzungsmarkierung.

Der Parser akzeptiert pro Modelldurchlauf einen einzelnen, eigenständigen `<tool>{...}</tool>`-Umschlag.
Er gleicht den Namen mit der Tool-Liste der Anfrage ab, validiert die Argumente anhand des
JSON-Schemas dieses Tools, lehnt gemischte Erzählungen und Aktionen ab und erlaubt einen
begrenzten Reparaturversuch. Claude Code führt anschließend den resultierenden Anthropic-`tool_use`
lokal aus und sendet das `tool_result` über OmniRoute zurück.

## Isolation und Bedrohungsmodell

Die Claude-Installation, das Konto und die Konfiguration des Hosts liegen außerhalb des
Geltungsbereichs und gelten als nicht zulässig. Die Compose-Dienste:

- werden mit UID/GID `10001:10001`, einem schreibgeschützten Root-Dateisystem, entfernten
  Capabilities und `no-new-privileges` ausgeführt;
- verwenden ein privates `/home/bridge`, ein dediziertes Claude-Konfigurations-Volume,
  isolierte OmniRoute-Daten und ein separates `devin-auth`-Volume;
- binden ausschließlich kurzlebige `.sandbox`-Arbeitsbereiche und Nachweise ein;
- binden weder das Home-Verzeichnis des Hosts noch Keychain, SSH, Cloud-Anmeldedaten oder
  den Docker-Socket ein;
- erstellen explizite Umgebungen und entfernen Variablen für Anthropic API/OAuth/Routing;
- leiten Claude-Code-Inferenz ausschließlich mit einem rein lokalen Schlüssel an
  `http://omniroute:20128` weiter.

Das Offline-Profil verwendet ein internes Netzwerk. Im Live-Profil erreicht OmniRoute die
offiziellen Devin-Endpunkte ausschließlich über `network-guard`; Verbindungen zu anderen
Zielen werden verweigert. Claude Code verfügt über eine separate Egress-Sperre und kann über
`NO_PROXY` ausschließlich den lokalen OmniRoute-Dienst erreichen. Die Audit-Dateien der
Sperren werden ausschließlich von ihrem jeweiligen Sperrprozess eingebunden. Die Skripte
überprüfen Dateieigentümerschaft, Modus, Link-Anzahl und jede Entscheidung, bevor sie
tokenfreie Nachweise exportieren.

Führen Sie den Isolationsnachweis unabhängig aus:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

Er validiert die Topologie, benannte Einbindungen, Einstellungen für die Ausführung ohne
Root-Rechte und mit Schreibschutz, explizites lokales Routing, das Fehlen sensibler
Umgebungsvariablen, das Fehlen des Docker-Sockets, den blockierten Zugriff auf
`api.anthropic.com` und `claude.ai`, die ausschließliche Auswahl des Devin-Anbieters sowie
einen expliziten Fehler, wenn das ACP-Backend nicht verfügbar ist.

## Ersteinrichtung und normale Verwendung

Erstellen Sie das gepinnte Image:

```bash
./scripts/devin-bridge/build
```

Authentifizieren Sie ausschließlich das isolierte Devin-Volume:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

Der Anmeldebefehl verwendet den offiziellen manuellen Token-Ablauf, der für Remote-/Container-Umgebungen vorgesehen ist. Der Wert wird direkt in die CLI-Eingabeaufforderung eingegeben; er wird weder als Prozessargument übergeben noch in Git geschrieben oder vom Host kopiert.

Starten Sie die isolierte Claude-Code-Laufzeitumgebung:

```bash
./scripts/devin-bridge/launch
```

`launch` überprüft vor dem Start des containerisierten Claude Code erneut die Isolation, die Devin-Authentifizierung und die Modellerkennung. Der Claude-Code des Hosts wird niemals ausgeführt. Modellaliase können in `.env.devin-bridge` festgelegt werden; jeder konfigurierte Wert muss das Präfix `devin-cli-agentic/` beibehalten.

## Validierungsbefehle

Der reproduzierbare Offline-Pfad benötigt kein Devin-Konto und hat zur Laufzeit keinen Internetzugriff:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

Der authentifizierte, explizit zu aktivierende Live-Pfad lautet:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

Der Live-Runner wartet zwischen den Szenarien, um zu vermeiden, dass ACP-Sitzungen schubweise geöffnet werden, und validiert strukturierte Claude-Stream-Ereignisse, statt textuellen Aussagen zu vertrauen. Seine drei Szenarien weisen Folgendes nach:

1. direkte Projektlesezugriffe und Fehleranalyse;
2. eine echte `Edit`-Operation, einen clientseitig gesteuerten `Bash`-Aufruf von `npm test` und ein abschließendes Ergebnis;
3. die Erkennung von `/bridge-check` und `bridge-proof`, Projektlesezugriffe, einen weiteren erfolgreichen clientseitig gesteuerten `npm test`-Aufruf und den Abschluss ohne ausstehende Aufgaben.

Die abschließende Prüfstufe kontrolliert außerdem das Devin-Netzwerk-Audit und verlangt, dass das Claude-Egress-Audit leer bleibt.

## Aktualisieren gepinnter Tools

Das Image pinnt Node, Claude Code und Devin CLI in `docker/devin-bridge/Dockerfile`. So führen Sie eine Aktualisierung durch:

1. Ändern Sie die expliziten Versionen;
2. ersetzen Sie beide architekturspezifischen Prüfsummen des Devin-Archivs durch die Werte für das offizielle Artefakt;
3. erstellen Sie das Image neu und führen Sie alle Offline-Validierungsbefehle aus;
4. bestätigen Sie die Versionen innerhalb des Images;
5. führen Sie die authentifizierte Live-Suite mit drei Szenarien erneut aus.

Installieren Sie keines der beiden CLI-Tools global auf dem Host und ersetzen Sie die Prüfsummenverifizierung nicht durch einen nicht verifizierten Download.

## Diagnose und Bereinigung

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  zeigt das lokale Routing und bereinigte Executor-Fehler an.
- `.sandbox/evidence/mock-acp.jsonl` zeichnet deterministische Mock-ACP-Aktionen auf.
- `.sandbox/evidence/claude-stream.jsonl` zeichnet den echten Offline-Lauf von Claude Code auf.
- `.sandbox/evidence/live-*.jsonl` zeichnet die drei validierten Live-Streams auf.
- `.sandbox/evidence/egress.jsonl` und `.sandbox/evidence/claude-egress.jsonl` sind validierte,
  tokenfreie Kopien der Guard-Audits.

Stoppen Sie die zugehörigen Container und Netzwerke, wobei die Anmelde-/Konfigurations-Volumes erhalten bleiben:

```bash
./scripts/devin-bridge/clean
```

Entfernen Sie die vollständige Bridge-eigene Umgebung einschließlich benannter Volumes:

```bash
./scripts/devin-bridge/clean --all
```

## Einschränkungen

- Die Bridge stützt sich auf die festgelegte werkzeuglose Rolle `summarizer`, da Devin CLI `3000.2.17`
  keinen neutralen werkzeuglosen ACP-Agenten bereitstellt. Der Adapter kompensiert zusammenfassungsartige
  Zwischenantworten, aber ein einzelner begrenzter Reparaturversuch kann dennoch ausdrücklich fehlschlagen.
- Live-ACP-Aufrufe können vorübergehend `502`-/`504`-Antworten zurückgeben. Das Testsystem führt Szenarien
  mit zeitlichem Abstand aus; ein anhaltender Fehler wird weiterhin nach dem Fail-Closed-Prinzip behandelt, und es wird niemals ein anderer Anbieter ausgewählt.
- Der ACP-Kontext wird aus jeder Anthropic-Anfrage rekonstruiert; es gibt keine
  Prozess-/Sitzungsaffinität.
- Pro Modellantwort wird ein Werkzeugaufruf unterstützt; parallele Aufrufe werden abgelehnt.
- Bilder werden ausdrücklich nicht unterstützt. Bildverarbeitung, Denkausgaben, Steuerung des Verarbeitungsaufwands und ein Kontextfenster
  von 1M werden nicht angeboten.
- SSE verwendet gültige Anthropic-Lebenszyklusereignisse, wird jedoch erst ausgegeben, nachdem der begrenzte ACP-Durchlauf
  vollständig erfasst wurde; ACP-Chunks werden nicht schrittweise weitergeleitet.
