## Ausgangsbasis

Je nachdem, wie der Bericht berechnet wird, ergeben sich unterschiedliche Abdeckungswerte. Für die Planung ist nur einer davon relevant.

| Metrik                   | Umfang                                                  | Anweisungen / Zeilen | Verzweigungen | Funktionen | Hinweise                                                            |
| ------------------------ | ------------------------------------------------------- | -------------------: | ------------: | ---------: | ------------------------------------------------------------------- |
| Veraltet                 | Altes `npm run test:coverage`                           |               79.42% |        75.15% |     67.94% | Überhöht: zählt Testdateien und schließt `open-sse` aus             |
| Diagnose                 | Nur Quellcode, ohne Tests und ohne `open-sse`           |               68.16% |        63.55% |     64.06% | Nur zur isolierten Betrachtung von `src/**` nützlich                |
| Empfohlene Ausgangsbasis | Nur Quellcode, ohne Tests und einschließlich `open-sse` |               82.58% |        75.22% |     84.23% | Dies ist die projektweite Ausgangsbasis, die verbessert werden soll |

Die empfohlene Ausgangsbasis ist der Wert, der optimiert werden soll.

## Regeln

- Abdeckungsziele gelten für Quelldateien, nicht für `tests/**`.
- `open-sse/**` ist Teil des Produkts und muss im Umfang enthalten bleiben.
- Neuer Code darf die Abdeckung in den betroffenen Bereichen nicht verringern.
- Tests sollten sich vorzugsweise auf Verhalten und Ergebnisse von Verzweigungen statt auf Implementierungsdetails konzentrieren.
- Für `src/lib/db/**` sind temporäre SQLite-Datenbanken und kleine Fixtures umfassenden Mocks vorzuziehen.

## Aktueller Befehlssatz

- `npm run test:coverage`
  - Zentrale Abdeckungsprüfung des Quellcodes für die Unit-Test-Suite
  - Erzeugt `text-summary`, `html`, `json-summary` und `lcov`
- `npm run coverage:report`
  - Detaillierter Bericht für jede einzelne Datei aus dem letzten Durchlauf
- `npm run test:coverage:legacy`
  - Nur für historische Vergleiche

## Ratchet-Richtlinie

Aktualisieren Sie die Schwellenwerte von `npm run test:coverage` erst, nachdem das Projekt den nächsten Meilenstein tatsächlich mit einem komfortablen Puffer überschritten hat.

**Aktuelle Schwelle:** `npm run test:coverage` erzwingt **60 Statements / 60 Zeilen / 60 Funktionen / 60 Verzweigungen** (die Metrik wurde in Quality-Gates-Phase 6A.1 neu festgelegt — die frühere Ausgangsbasis von 82,58 % war überhöht, da sie Testdateien mitzählte und `open-sse` ausschloss). Der Befehl `test:coverage:legacy` behält zum historischen Vergleich die alte 50/50/50-Metrik bei.

Der aktuelle Coverage-Befehl misst die zentrale Node-Unit-Test-Suite und bezieht den darüber erreichten Quellcode einschließlich `open-sse` ein. Die Vitest-Coverage wird noch nicht in einem einzigen, vereinheitlichten Bericht zusammengeführt.
