`devin-cli-agentic`-ը թույլ է տալիս իրական Claude Code գործարկման միջավայրին օգտագործել OmniRoute-ի տեղային Anthropic
Messages վերջնակետը, մինչդեռ պաշտոնական Devin CLI-ն մոդելի պատասխանները տրամադրում է ACP stdio-ի միջոցով։ Այն
չի փոփոխում գոյություն ունեցող Anthropic, Claude OAuth, Claude Web կամ `devin-cli` մատակարարները։

> **Ընթացիկ կարգավիճակ՝ Claude Code-ը ամրագրված է `2.1.258` տարբերակին, իսկ անցանց և իրական միջավայրի վերջին վավերացումը
> գրանցվել է `2.1.220` տարբերակի համար։** `2.1.220` ամրագրումը Devin CLI-ի միջոցով ավարտել է երեք մեկուսացված սցենար՝
> օգտագործելով `3000.2.17` տարբերակը և `swe-1-7-lightning` մոդելը։ Այդ վերջնական իրական գործարկումը հաստատել է հաճախորդի կողմից կառավարվող `Read`,
> `Edit` և `Bash` քայլերը, `npm test`-ի հաջող արդյունքները, նախագծի հրամանների և հմտությունների
> հայտնաբերումը, միայն Devin-ի միջոցով երթուղավորումը և Claude-ի զրոյական ելքային կապը։ Այնուհետև ամրագրված տարբերակը բարձրացվել է մինչև `2.1.258`
> (CLI-ի այն սերունդը, որի Claude ինքնությունն է նմանակում OmniRoute-ը, և առաջին թողարկման ճյուղը, որը
> ներկառուցված կերպով տրամադրում է Fable 5.1 մակարդակը)։ Նոր ամրագրված տարբերակի դեպքում տեղադրման շերտը և `claude --version`-ը
> ստուգվել են ամրագրված բազային պատկերի վրա, իսկ կամրջի մոդուլային թեստերի հավաքածուն, `compose config`-ը և
> ստատիկ մեկուսացման ապացույցը հաջողությամբ անցնում են, սակայն անցանց կեղծ սցենարը և իրական երեք սցենարից բաղկացած
> հավաքածուն դեռ կրկին չեն գործարկվել։ Կրկին գործարկեք դրանք (տե՛ս «Ամրագրված գործիքների թարմացում» բաժինը), նախքան
> այս ամրագրմամբ կամրջին ապավինելը։

## Ճարտարապետություն

```text
Claude Code 2.1.258 (մեկուսացված ոչ արմատային Linux կոնտեյներ)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude ձևաչափով, նույնականացում չպահանջող մատակարար)
  -> devin acp --agent-type summarizer (պաշտոնական ACP stdio, առանց Devin գործիքների)
  -> Devin հաշիվ՝ հատուկ devin-auth հատորում
```

Պաշտոնական CLI-ի լռելյայն ACP գործակալը կարող է գործարկել իր սեփական գործիքները, ուստի այս կամուրջը չի օգտագործում
այն։ Այն գործարկում է ամրագրված `summarizer` ACP գործակալը, որի պաշտոնական CLI ռեժիմը գործիքներ չունի, և
սերիականացված Anthropic հարցումը ձևավորում է որպես կատարման հետագիծ։ Երբ անհրաժեշտ է Claude-ի կողմից կառավարվող
մեկ այլ գործողություն, պատասխանը պետք է պարունակի հաճախորդի գործիքի ճիշտ մեկ ծրար։ Ցանկացած ACP
`tool_call` կամ `tool_call_update` մերժվում է՝ նախքան պատասխանը որպես
հաջողված ներկայացնելը։

`open-sse/executors/devin-agentic/serializer.ts`-ում գտնվող սերիականացնողը պահպանում է `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` և Claude Code-ի
տրամադրած գործիքները։ Պատկերները և անհայտ բլոկները բացահայտ կերպով ձախողվում են։ Գործիքների մեծ արդյունքներում
օգտագործվում է տեսանելի կրճատման նշիչ։

Վերլուծիչն ընդունում է յուրաքանչյուր մոդելային քայլի համար մեկ առանձին `<tool>{...}</tool>` ծրար։ Այն ստուգում է
անունը հարցման գործիքների ցանկի համեմատ, վավերացնում է արգումենտները տվյալ գործիքի JSON
Schema-ի համաձայն, մերժում է խառը շարադրանքն ու գործողությունները և թույլատրում է մեկ սահմանափակ ուղղման փորձ։ Այնուհետև Claude Code-ը
տեղայնորեն գործարկում է ստացված Anthropic `tool_use`-ը և `tool_result`-ը OmniRoute-ի միջոցով
հետ է ուղարկում։

## Մեկուսացում և սպառնալիքների մոդել

Հոսթի Claude տեղադրումը, հաշիվը և կազմաձևումը դիտարկման շրջանակից դուրս են և համարվում են
արգելված։ Compose ծառայությունները՝

- գործարկվում են UID/GID `10001:10001`-ով՝ միայն կարդալու արմատային ֆայլային համակարգով, հեռացված հնարավորություններով և
  `no-new-privileges`-ով,
- օգտագործում են մասնավոր `/home/bridge`, հատուկ Claude կազմաձևման հատոր, մեկուսացված OmniRoute տվյալներ
  և առանձին `devin-auth` հատոր,
- միացնում են միայն մեկանգամյա օգտագործման `.sandbox` աշխատանքային տարածքներն ու ապացույցները,
- չեն միացնում հոսթի տնային պանակը, Keychain-ը, SSH-ը, ամպային հավատարմագրերը կամ Docker սոկետը,
- կառուցում են բացահայտ միջավայրեր և հեռացնում Anthropic API/OAuth/երթուղավորման փոփոխականները,
- Claude Code-ի ինֆերենսն ուղղորդում են միայն դեպի `http://omniroute:20128`՝ օգտագործելով միայն տեղային բանալի։

Անցանց պրոֆիլն օգտագործում է ներքին ցանց։ Իրական պրոֆիլում OmniRoute-ը պաշտոնական Devin
վերջնակետերին հասնում է միայն `network-guard`-ի միջոցով, իսկ կապը չառնչվող նպատակակետերի հետ արգելվում է։
Claude Code-ն ունի առանձին՝ ամբողջ ելքային կապն արգելող պաշտպանիչ շերտ և կարող է հասնել միայն տեղային OmniRoute
ծառայությանը՝ `NO_PROXY`-ի միջոցով։ Պաշտպանիչ շերտի աուդիտի ֆայլերը միացվում են միայն դրանց համապատասխան պաշտպանիչ գործընթացի կողմից։
Սկրիպտները ստուգում են ֆայլի սեփականատիրոջը, ռեժիմը, հղումների քանակը և յուրաքանչյուր որոշում՝ նախքան
թոքեններ չպարունակող ապացույցների արտահանումը։

Մեկուսացման ապացույցն ինքնուրույն գործարկելու համար՝

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

Այն վավերացնում է տոպոլոգիան, անվանված միացումները, ոչ արմատային/միայն կարդալու կարգավորումները, բացահայտ տեղային երթուղավորումը,
զգայուն միջավայրային փոփոխականների բացակայությունը, Docker սոկետի բացակայությունը, դեպի
`api.anthropic.com` և `claude.ai` մուտքի արգելափակումը, միայն Devin մատակարարի ընտրությունը և բացահայտ ձախողումը, երբ
ACP հետնամասը հասանելի չէ։

## Սկզբնական կարգավորում և սովորական օգտագործում

Կառուցեք ամրագրված image-ը՝

```bash
./scripts/devin-bridge/build
```

Նույնականացրեք միայն մեկուսացված Devin volume-ը՝

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

Մուտքի հրամանն օգտագործում է հեռավար/container միջավայրերի համար նախատեսված պաշտոնական՝ ձեռքով token-ի հոսքը։ Արժեքը մուտքագրվում է անմիջապես CLI-ի հուշման մեջ․ այն չի փոխանցվում որպես
գործընթացի արգումենտ, չի գրվում Git-ում և չի պատճենվում host-ից։

Գործարկեք մեկուսացված Claude Code runtime-ը՝

```bash
./scripts/devin-bridge/launch
```

`launch`-ը նախքան container-ացված Claude Code-ը գործարկելը կրկին ստուգում է մեկուսացումը, Devin-ի նույնականացումը և model-ների հայտնաբերումը։ Այն երբեք չի գործարկում host-ի Claude executable-ը։ Model alias-ները կարող են
սահմանվել `.env.devin-bridge`-ում․ կազմաձևված յուրաքանչյուր արժեք պետք է պահպանի
`devin-cli-agentic/` նախածանցը։

## Վավերացման հրամաններ

Վերարտադրելի offline ուղին Devin հաշիվ չի պահանջում և runtime-ի ընթացքում ինտերնետ չի օգտագործում՝

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

Նույնականացում պահանջող, ըստ ցանկության միացվող live ուղին հետևյալն է՝

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

Live runner-ը սպասում է սցենարների միջև՝ ACP session-ները միանգամից չբացելու համար, և
տեքստային պնդումներին վստահելու փոխարեն վավերացնում է Claude-ի կառուցվածքային stream event-ները։ Դրա երեք
սցենարներն ապացուցում են՝

1. նախագծի անմիջական ընթերցում և թերությունների վերլուծություն,
2. իրական `Edit`, client-ին պատկանող `Bash` `npm test` և վերջնական արդյունք,
3. `/bridge-check`՝ `bridge-proof`-ի հայտնաբերմամբ, նախագծի ընթերցումներ, client-ին պատկանող ևս մեկ հաջող
   `npm test` և ավարտ՝ առանց սպասող աշխատանքի։

Վերջնական gate-ը նաև ստուգում է Devin-ի network audit-ը և պահանջում, որ Claude-ի egress audit-ը
դատարկ մնա։

## Ամրագրված գործիքների թարմացում

Image-ը ամրագրում է Node-ի, Claude Code-ի և Devin CLI-ի տարբերակները
`docker/devin-bridge/Dockerfile`-ում։ Թարմացնելու համար՝

1. փոխեք հստակ նշված տարբերակները,
2. երկու architecture-ներին հատուկ Devin archive checksum-ները փոխարինեք պաշտոնական
   artifact-ի արժեքներով,
3. վերակառուցեք և գործարկեք բոլոր offline վավերացման հրամանները,
4. հաստատեք image-ի ներսում առկա տարբերակները,
5. կրկին գործարկեք նույնականացում պահանջող, երեք սցենարից բաղկացած live suite-ը։

Մի տեղադրեք CLI-ներից որևէ մեկը գլոբալ կերպով host-ում և checksum-ի ստուգումը մի փոխարինեք
չստուգված ներբեռնմամբ։

## Ախտորոշում և մաքրում

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  ցուցադրում է տեղային routing-ը և մաքրված executor-ի սխալները։
- `.sandbox/evidence/mock-acp.jsonl`-ում գրանցվում են որոշարկված mock ACP գործողությունները։
- `.sandbox/evidence/claude-stream.jsonl`-ում գրանցվում է Claude Code-ի իրական offline գործարկումը։
- `.sandbox/evidence/live-*.jsonl`-ում գրանցվում են վավերացված երեք live stream-ները։
- `.sandbox/evidence/egress.jsonl`-ը և `.sandbox/evidence/claude-egress.jsonl`-ը guard audit-ների վավերացված,
  token չպարունակող պատճեններն են։

Կանգնեցրեք պատկանող container-ներն ու network-ները՝ պահպանելով մուտքի/config volume-ները՝

```bash
./scripts/devin-bridge/clean
```

Հեռացրեք bridge-ին պատկանող ամբողջ միջավայրը՝ ներառյալ անվանակոչված volume-ները՝

```bash
./scripts/devin-bridge/clean --all
```

## Սահմանափակումներ

- Կամուրջը հիմնվում է ֆիքսված, առանց գործիքների `summarizer` դերի վրա, քանի որ Devin CLI `3000.2.17`-ը չի տրամադրում չեզոք, առանց գործիքների ACP գործակալ։ Ադապտերը փոխհատուցում է ամփոփման ձև ունեցող միջանկյալ պատասխանները, սակայն մեկ սահմանափակ վերականգնման փորձը, միևնույն է, կարող է բացահայտ ձախողվել։
- Իրական ACP կանչերը կարող են վերադարձնել ժամանակավոր `502`/`504` պատասխաններ։ Փորձարկման համակարգը սցենարների միջև դադարներ է պահպանում․ շարունակական ձախողման դեպքում այն մնում է փակ՝ սխալով, և երբեք այլ մատակարար չի ընտրում։
- ACP համատեքստը վերակառուցվում է Anthropic-ի յուրաքանչյուր հարցումից․ պրոցեսի/աշխատաշրջանի հետ կապվածություն չկա։
- Մոդելի յուրաքանչյուր պատասխանի համար աջակցվում է գործիքի մեկ կանչ․ զուգահեռ կանչերը մերժվում են։
- Պատկերները բացահայտորեն չեն աջակցվում։ Տեսողական հնարավորությունները, մտածողության արդյունքը, ջանքերի կառավարման տարրերը և 1M համատեքստային պատուհանը չեն հայտարարվում։
- SSE-ն օգտագործում է Anthropic-ի կենսացիկլի վավեր իրադարձություններ, սակայն դրանք ուղարկվում են սահմանափակ ACP քայլի ամբողջական հավաքագրումից հետո․ ACP հատվածներն աստիճանաբար չեն փոխանցվում։
