OmniRoute-ը ներառում է տեղային առաջնահերթությամբ գեյմիֆիկացիայի շերտ, որը պարգևատրում է օգտատերերին հարթակի հետ փոխգործակցության համար՝ հարցումներ կատարելու, մատակարարներ փոխելու, կոմբինացիաներ ստեղծելու, թոքեններ կիսելու և համայնքին աջակցելու համար։ Ամբողջ վիճակը պահվում է
SQLite-ում․ համայնքային սերվերների հետ ֆեդերացիան կամընտիր է և հիմնված է տվյալների ուղարկման վրա։

Համակարգը նախագծված է այնպես, որ **կրիտիկական ուղու վրա ունենա զրոյական ուշացում**․ գեյմիֆիկացիայի
իրադարձությունները հարցումների մշակման խողովակաշարից ուղարկվում են առանց պատասխանին սպասելու և երբեք չեն արգելափակում
LLM-ի պատասխանը։

## Ընդհանուր ակնարկ

### Նպատակ

Բարձրացնել օգտատերերի ներգրավվածությունն ու պահպանումը՝ տրամադրելով տեսանելի առաջընթաց (XP,
մակարդակներ, կրծքանշաններ), սոցիալական հավաստում (առաջատարների աղյուսակներ) և տնտեսական խթաններ (թոքենների
կիսում, հրավերների պարգևներ)։

### Շրջանակ

| Խարդախության կանխարգելում | Սերվերային գնահատում, հաճախականության սահմանափակում, z-score-ով անոմալիաների հայտնաբերում |

### Նախագծման սկզբունքներ

1. **Տեղային առաջնահերթություն** — ամբողջ վիճակը SQLite-ում է, արտաքին ծառայություններ չեն պահանջվում։
2. **Չարգելափակող աշխատանք** — իրադարձություններն ուղարկվում են առանց պատասխանին սպասելու․ LLM-ի պատասխանի ուղին
   երբեք չի ուշացվում գեյմիֆիկացիայի տրամաբանության պատճառով։
3. **Սերվերի կողմից վերահսկվող** — XP-ն հաշվարկվում է միայն սերվերի կողմից․ հաճախորդները չեն կարող
   արհեստականորեն մեծացնել միավորները։
4. **Գաղտնիությունը հարգող** — առաջատարների աղյուսակին մասնակցությունը կամընտիր է․ օգտատերերը կարող են
   թաքցնել իրենց պրոֆիլը։
5. **Ֆեդերացիայի համար պատրաստ** — համայնքային սերվերները կարող են ստորագրված API-ի միջոցով ուղարկել միավորներ․
   համաժամացումը վերագրում է տվյալները, այլ ոչ թե գումարում։

## Ճարտարապետություն

### Բարձր մակարդակի հոսք

```
Հաճախորդի հարցում
  → /v1/chat/completions
    → handleChatCore()                      [open-sse/handlers/chatCore.ts]
      → ... (առկա խողովակաշար) ...
      → վերին մակարդակի պատասխանը ուղարկվում է հաճախորդին
      → setImmediate (առանց պատասխանին սպասելու).
        → emitGamificationEvent()           [src/lib/gamification/events.ts]
          → awardXp()                       [src/lib/gamification/xp.ts]
          → updateStreak()                  [src/lib/gamification/streaks.ts]
          → evaluateBadges()                [src/lib/gamification/badges.ts]
          → updateLeaderboard()             [src/lib/gamification/leaderboard.ts]
          → checkAnomalies()                [src/lib/gamification/antiCheat.ts]
```

Իրադարձությունների թողարկիչը միակ ինտեգրման կետն է։ `chatCore.ts`-ը կանչում է
`emitGamificationEvent()`-ը պատասխանը ուղարկելուց հետո․ իրադարձությունների մոդուլն այն
բաշխում է XP-ի, շարքերի, կրծքանշանների, առաջատարների աղյուսակի և խարդախության կանխարգելման ենթահամակարգերին։

```
src/lib/db/

src/app/api/gamification/

  federation/score/  ← POST միավորի ուղարկում սերվերին
  federation/leaderboard/ ← GET առաջատարների աղյուսակի ստացում սերվերից
  notifications/     ← SSE կրծքանշանի/մակարդակի բարձրացման ծանուցումներ

```

## XP / մակարդակների համակարգ

**Ֆայլ՝** `src/lib/gamification/xp.ts`

### Մակարդակների կոր

`n` մակարդակին հասնելու համար անհրաժեշտ XP-ն հաշվարկվում է բազմանդամային կորով՝

```
xp_for_level(n) = floor(100 * n^1.5)
```

| Մակարդակ | XP մինչև հաջորդը | Կուտակային XP | Կոչում    |
| -------- | ---------------- | ------------- | --------- |
| 1        | 100              | 100           | Սկսնակ    |
| 5        | 1,118            | 2,415         | Սկսնակ    |
| 10       | 3,162            | 10,523        | Հետազոտող |
| 25       | 12,500           | 86,024        | Հետազոտող |
| 50       | 35,355           | 345,529       | Փորձագետ  |
| 75       | 64,952           | 948,683       | Վարպետ    |
| 100      | 100,000          | 2,050,000     | Լեգենդ    |

### Կոչումներ

| Մակարդակների միջակայք | Կոչում    |
| --------------------- | --------- |
| 1 – 9                 | Սկսնակ    |
| 10 – 24               | Հետազոտող |
| 25 – 49               | Փորձագետ  |
| 50 – 74               | Վարպետ    |
| 75 – 100              | Լեգենդ    |

### XP պարգևներ

| Գործողություն     | XP  | Նկարագրություն                                                                     |
| ----------------- | --- | ---------------------------------------------------------------------------------- |
| `request`         | 1   | OmniRoute-ի միջոցով ուղղորդված յուրաքանչյուր API հարցման համար                     |
| `provider_switch` | 5   | Մեկ այլ մատակարարի անցնելու համար                                                  |
| `model_switch`    | 3   | Մեկ այլ մոդելի անցնելու համար                                                      |
| `combo_create`    | 10  | Նոր կոմբո ստեղծելու համար                                                          |
| `combo_use`       | 2   | Հարցման համար կոմբո օգտագործելու համար                                             |
| `token_share`     | 1   | Մեկ այլ օգտատիրոջ հետ կիսված յուրաքանչյուր 1 000 թոքենի համար                      |
| `invite_redeem`   | 50  | Հրավերի կոդն ակտիվացնելու համար                                                    |
| `daily_login`     | 5   | Օրական ակտիվ օգտագործման համար (օրական մեկ անգամ)                                  |
| `streak_bonus`    | 2   | Յուրաքանչյուր անընդմեջ ակտիվության օրվա համար (բազմապատկվում է շարքի երկարությամբ) |
| `badge_unlock`    | 10  | Կրծքանշան ապակողպելու համար                                                        |

### Շնորհման հոսք

```typescript
export async function awardXp(
  apiKeyId: string,
  action: XpAction,
  metadata?: Record<string, unknown>
): Promise<{ xp: number; level: number; title: string; levelUp: boolean }>;
```

1. Գտնել `XP_REWARDS[action]`-ը՝ XP-ի քանակը ստանալու համար։
2. Անցկացնել `checkRateLimit()`-ով (խարդախության կանխարգելում՝ առավելագույնը 1000 XP/րոպե յուրաքանչյուր բանալու համար)։
3. Բացել տրանզակցիա՝
   - Կարդալ `user_levels`-ի ընթացիկ տողը։
   - Ավելացնել XP-ն, վերահաշվարկել մակարդակը `levelFromXp(totalXp)`-ի միջոցով։
   - Եթե մակարդակը փոխվել է, սահմանել `levelUp = true`։
   - Թարմացնել `user_levels`-ի տողը։
   - Գրառում ավելացնել `xp_audit_log`-ում։
4. Վերադարձնել արդյունքը։ Կանչող կողմը մշակում է ծանուցումները։

### Օժանդակ ֆունկցիա՝ `levelFromXp(totalXp)`

Շրջանցում է 1..100 մակարդակները՝ գումարելով `xp_for_level(n)`-ը, մինչև կուտակային XP-ն
գերազանցի `totalXp`-ը։ Վերադարձնում է ամենաբարձր մակարդակը, որի շեմը հաղթահարված է։
Սա O(100) է, ինչը ընդունելի է, քանի որ առավելագույն մակարդակը 100 է։

Կրծքանշանների սահմանումները պահվում են `badge_definitions`-ում՝ որպես JSON `criteria`՝

```json
{
  "type": "action_count",
  "action": "request",
  "count": 1000
}
```

### Գնահատման հոսք

```
emitGamificationEvent(event)
  → evaluateBadges(apiKeyId, event)
    → getBadgeDefinitions()           # բոլոր սահմանումները
    → getUserBadges(apiKeyId)         # արդեն վաստակվածները (բաց թողնել)
    → յուրաքանչյուր չվաստակած կրծքանշանի համար՝
       → matchesCriteria(badge, event, userState)
       → համապատասխանության դեպքում՝ awardBadge(apiKeyId, badgeId)
         → վերադարձնել ծանուցման տվյալները
```

Գնահատումը **իրադարձություններով պայմանավորված** է. այն գործարկվում է խաղայնացման յուրաքանչյուր իրադարձությունից հետո, սակայն
ստուգում է միայն այն կրծքանշանները, որոնց `criteria.type`-ը համապատասխանում է իրադարձության գործողությանը։ Սա
արագ է պահում գնահատումը (իրադարձությունների մեծ մասի համար՝ < 5ms)։

### `matchesCriteria(badge, event, userState)`

| Չափանիշի տեսակ | Ստուգում                                                            |
| -------------- | ------------------------------------------------------------------- |
| `action_count` | `getActionCount(apiKeyId, action) >= count`                         |
| `streak`       | `getCurrentStreak(apiKeyId) >= days`                                |
| `unique_count` | `getUniqueCount(apiKeyId, field) >= n`                              |
| `rank`         | `getRank(apiKeyId, scope) <= n`                                     |
| `first`        | Այս գործողության տեսակի համար `xp_audit_log`-ում նախորդ գրառում չկա |
| `hidden`       | Փոխանցում է համապատասխան ենթաստուգմանը                              |

## Շարքի հետևում

**Ֆայլ՝** `src/lib/gamification/streaks.ts`

### Տվյալների մոդել

Շարքերը պահվում են `key_value` աղյուսակում (ընդհանուր օգտագործման աղյուսակ)՝ անվանատարածքով բանալիների ներքո.

| Բանալի                        | Արժեք                            | Նկարագրություն       |
| ----------------------------- | -------------------------------- | -------------------- |
| `gamification:streak:{keyId}` | `{current},{longest},{lastDate}` | Ակտիվ շարքի տվյալներ |

### Տրամաբանություն

```typescript
export async function updateStreak(
  apiKeyId: string
): Promise<{ current: number; longest: number; milestone: boolean }>;
```

1. Կարդալ շարքի գրառումը `key_value`-ից։
2. Վերլուծել `{current}`, `{longest}`, `{lastDate}` արժեքները (ISO ամսաթվի տող)։
3. Եթե `lastDate === today`՝ փոփոխություն չկա (այսօր արդեն հաշվարկվել է)։
4. Եթե `lastDate === yesterday`՝ ավելացնել `current`-ը և անհրաժեշտության դեպքում թարմացնել `longest`-ը։
5. Եթե `lastDate < yesterday`՝ վերակայել `current = 1` (շարքն ընդհատվել է)։
6. Գրանցել թարմացված գրառումը։
7. Ստուգել նշաձողերը՝ 7, 14, 30, 60, 90, 180, 365 օր։ Եթե որևէ նշաձող հաղթահարվել է, սահմանել
   `milestone = true` (կանչող կողմը շնորհում է XP և ստուգում կրծքանշանները)։

### Սահմանային դեպքեր

- **Ժամային գոտի**․ շարքերի համար օգտագործվում են UTC ամսաթվեր (`new Date().toISOString().slice(0, 10)`)։
  Սա միտումնավոր է․ մեկ կանոնական ժամային գոտին կանխում է ժամային գոտիների միջև
  անցում կատարելով համակարգը շահարկելը։
- **Նոր օգտատերեր**․ շարքի գրառում գոյություն չունի. առաջին հարցումը ստեղծում է այն՝
  `current=1, longest=1, lastDate=today` արժեքներով։
- **Օրական մի քանի հարցում**․ միայն UTC օրվա առաջին հարցումն է
  ավելացնում շարքը։

### Ժամանակաշրջանի հերթափոխ

Շաբաթական և ամսական առաջատարների աղյուսակները հերթափոխվում են ինքնաբերաբար.

## Թոքենների փոխանցում

**Ֆայլ՝** `src/lib/gamification/sharing.ts`

### Կրկնակի գրանցմամբ հաշվապահական մատյան

Յուրաքանչյուր փոխանցում `token_ledger`-ում ստեղծում է երկու տող՝

| Տող    | `from_key_id` | `to_key_id` | `amount` |
| ------ | ------------- | ----------- | -------- |
| Դեբետ  | ուղարկող      | ստացող      | +գումար  |
| Կրեդիտ | ստացող        | ուղարկող    | -գումար  |

Սակայն կիրառվող սկզբունքը հետևյալն է՝

| Տող       | `from_key_id` | `to_key_id` | `amount` | Նշանակություն       |
| --------- | ------------- | ----------- | -------- | ------------------- |
| Ուղարկում | ուղարկող      | ստացող      | +գումար  | Արտահոսք ուղարկողից |
| Ստացում   | ստացող        | ուղարկող    | +գումար  | Ներհոսք դեպի ստացող |

Մնացորդը հաշվարկվում է հետևյալ կերպ՝

```sql
SELECT
  COALESCE(SUM(CASE WHEN to_key_id = ? THEN amount ELSE 0 END), 0)
  - COALESCE(SUM(CASE WHEN from_key_id = ? THEN amount ELSE 0 END), 0)
  AS balance
FROM token_ledger
WHERE from_key_id = ? OR to_key_id = ?
```

### Փոխանցման ընթացքը

```typescript
export async function transferTokens(
  fromKeyId: string,
  toKeyId: string,
  amount: number,
  idempotencyKey: string
): Promise<{ success: boolean; balance: number }>;
```

1. **Վավերացում**՝ `amount > 0`, `fromKeyId !== toKeyId`։
2. **Իդեմպոտենտություն**՝ ստուգել՝ արդյոք `idempotency_key`-ն արդեն գոյություն ունի մատյանում։
   Եթե այո, վերադարձնել պահված արդյունքը։
3. **Գործարք** (SQLite-ի մեկ գործարքի շրջանակում)՝
   a. Հաշվարկել ուղարկողի մնացորդը։
   b. Եթե `balance < amount`, չեղարկել (անբավարար միջոցներ)։
   c. Ավելացնել ուղարկման տող (`from=ուղարկող, to=ստացող, amount`)։
   d. Ավելացնել ստացման տող (`from=ստացող, to=ուղարկող, amount`)։
4. **Հաճախականության սահմանափակում**՝ ստուգել ուղարկողի փոխանցումների հաճախականությունը (առավելագույնը՝ 10 փոխանցում/րոպե)։
5. **Իրադարձություն**՝ արձակել `token_share` գեյմիֆիկացիոն իրադարձություն՝ XP-ի և կրծքանշանի գնահատման համար։
6. Վերադարձնել `{ success: true, balance: newBalance }`։

### Հաճախականության սահմանափակում

- Առավելագույնը՝ 10 փոխանցում մեկ րոպեում՝ յուրաքանչյուր API բանալու համար։
- Առավելագույնը՝ 10,000 թոքեն մեկ փոխանցման համար։
- Առավելագույնը՝ օրական փոխանցված 100,000 թոքեն՝ յուրաքանչյուր API բանալու համար։

## Հրավերի և մարման թոքեններ

**Ֆայլ՝** `src/lib/gamification/invites.ts`

### Կոդի ձևաչափը

- **Կոդ**՝ 8 նիշից բաղկացած տառաթվային արժեք (օրինակ՝ `A3K9-X7M2`), ընթեռնելի մարդու համար և
  ցուցադրվող օգտատիրոջը։
- **Թոքեն**՝ պատահական 32-բայթանոց թոքեն, որը պահվում է որպես SHA-256 հեշ։ Օգտագործվում է
  ծրագրային մարման համար (օրինակ՝ URL հղումներով)։

### Պահպանում

| Սյունակ      | Արժեք                             |
| ------------ | --------------------------------- |
| `code`       | `A3K9X7M2` (եզակի, ինդեքսավորված) |
| `token_hash` | SHA-256(raw_token)                |

Չմշակված թոքենն օգտատիրոջը վերադարձվում է միայն մեկ անգամ՝ ստեղծման պահին։ OmniRoute-ը
այլևս երբեք չի պահում կամ ցուցադրում այն․ պահպանվում է միայն հեշը։

### Ինքնահրավերի կանխարգելում

Երբ օգտատերը մարում է կոդը, համակարգը ստուգում է՝

1. Կոդը պատկանում է այլ `api_key_id`-ի։
2. Մարող օգտատերը նախկինում չի մարել նույն
   հրավիրողից ստացված որևէ կոդ (միացում `invite_tokens`-ի և մարման մատյանի միջոցով)։

Եթե ստուգումներից որևէ մեկը ձախողվում է, մարումը մերժվում է հստակ սխալի հաղորդագրությամբ։

### Վավերականության ժամկետ և սահմանաչափեր

- Լռելյայն `max_uses`՝ 10 (կարգավորվում է ստեղծման պահին)։
- Լռելյայն `expires_at`՝ ստեղծումից 30 օր հետո։
- Ժամկետանց կամ օգտագործումների սահմանաչափին հասած կոդերը վերադարձնում են HTTP 410 Gone։

## Համայնքային սերվերների ֆեդերացիա

**Ֆայլ՝** `src/lib/gamification/servers.ts`

### Միացում

Համայնքային սերվերը գրանցվում է հեռակա սերվերի կողմից տրամադրված հրավերի թոքենի միջոցով։ Տեղային օրինակը՝

1. Ստանում է հրավերի թոքենը (օրինակ՝ կառավարման վահանակում տեղադրված)։
2. Կանչում է հեռակա սերվերի `POST /api/gamification/federation/leaderboard` վերջնակետը՝ թոքենը վավերացնելու և ընթացիկ առաջատարների աղյուսակը ստանալու համար։
3. Պահպանում է սերվերի գրառումը՝ `status: connected` արժեքով։

### Համաժամացման մոդել

Ֆեդերացիան օգտագործում է **վերագրող համաժամացում**, ոչ թե գումարային․

```
Տեղային օրինակ                  Համայնքային սերվեր
     │                              │
     ├── միավորի ուղարկում ────────►│  POST /federation/score
     │   { api_key_id, score }      │  (սերվերը վավերացնում է թոքենի հեշը)
     │                              │
     ├── առաջատարների աղյուսակի ───►│  GET /federation/leaderboard
     │   ստացում                    │
     │◄── լավագույն N գրառում ──────┤  (վերագրում է տեղային քեշը)
     │                              │
     └── առողջության ստուգում ─────►│  GET /federation/health
         (յուրաքանչյուր 60վ,         │
          ընդհատում՝ 5վ)            │
```

### Նույնականացում

Ֆեդերացիայի հարցումները ներառում են՝

```
Authorization: Bearer <raw_token>
X-Federation-Version: 1
```

Հեռակա սերվերը հեշավորում է թոքենը և որոնում համապատասխան `community_servers` տողը։ Սա թույլ է տալիս խուսափել պահպանված հեշի փոխանցումից։

### Առողջության մշտադիտարկում

Սերվերի յուրաքանչյուր գրառում հետևում է՝

| Դաշտ        | Նկարագրություն                               |
| ----------- | -------------------------------------------- |
| `status`    | `connected`, `degraded`, `unreachable`       |
| `last_sync` | Վերջին հաջող համաժամացման ISO ժամանակակնիքը  |
| `failures`  | Առողջության ստուգման հաջորդական ձախողումները |

5 հաջորդական ձախողումից հետո կարգավիճակը փոխվում է `unreachable`-ի, իսկ համաժամացումը դադարեցվում է, մինչև առողջության ձեռքով կատարված ստուգումը հաջողվի։

## Խարդախության կանխարգելում

**Ֆայլ՝** `src/lib/gamification/antiCheat.ts`

### Սերվերային կողմում միավորների հաշվարկ

XP-ի բոլոր հաշվարկները կատարվում են `src/lib/gamification/xp.ts`-ում։ Հաճախորդները երբեք միավոր չեն ուղարկում․ նրանք ուղարկում են գործողություններ, իսկ սերվերը հաշվարկում է XP-ն։ `leaderboard.score` սյունակում կարող է գրել միայն սերվերային կողմի կոդը։

### Հաճախականության սահմանափակում

| Սահմանափակում                                 | Արժեք   | Շրջանակ                         |
| --------------------------------------------- | ------- | ------------------------------- |
| Առավելագույն XP-ն մեկ րոպեում                 | 1,000   | Յուրաքանչյուր API բանալիի համար |
| Փոխանցումների առավելագույն քանակը մեկ րոպեում | 10      | Յուրաքանչյուր API բանալիի համար |
| Փոխանցման առավելագույն չափը                   | 10,000  | Յուրաքանչյուր փոխանցման համար   |
| Օրական փոխանցումների առավելագույն չափը        | 100,000 | Յուրաքանչյուր API բանալիի համար |

Հաճախականության սահմանափակումներն օգտագործում են հիշողության մեջ պահվող սահող պատուհան (նույն ձևանմուշը, ինչ `RateLimitManager`-ը՝ `open-sse/services/`-ում)։ Եթե գործընթացը վերագործարկվում է, որպես պահուստային տարբերակ օգտագործվում են SQLite-ի վրա հիմնված հաշվիչներ։

### Z-միավորով անոմալիաների հայտնաբերում

Յուրաքանչյուր API բանալիի համար համակարգը պահպանում է ժամում վաստակած XP-ի՝ վերջին 7 օրերի սահող պատուհանը։ XP-ի յուրաքանչյուր շնորհման ժամանակ՝

1. Հաշվարկվում է օգտատիրոջ ընթացիկ ժամային XP-ի արագությունը։
2. Հաշվարկվում են համախմբության միջինը և ստանդարտ շեղումը։
3. Հաշվարկվում է `z = (user_rate - mean) / stddev`։
4. Եթե `z > 3.0` (3 ստանդարտ շեղում), այն նշվում է որպես անոմալիա։

Անոմալիաները գրանցվում են `xp_audit_log`-ում՝ `action = 'anomaly_detected'` արժեքով, և ցուցադրվում են ադմինիստրատորի կառավարման վահանակում։

### Աուդիտի հետագիծ

XP-ի յուրաքանչյուր շնորհում, փոխանցում, կրծքանշանի ստացում և անոմալիայի հայտնաբերում գրանցվում է `xp_audit_log`-ում՝ հետևյալ տվյալներով․

| Դաշտ         | Նկարագրություն                                           |
| ------------ | -------------------------------------------------------- |
| `api_key_id` | Ով                                                       |
| `action`     | Ինչ է տեղի ունեցել (xp_award, transfer, anomaly, …)      |
| `xp_awarded` | Չափը (0՝ XP-ին չվերաբերող իրադարձությունների համար)      |
| `metadata`   | Համատեքստ պարունակող JSON (գործողության տեսակ, թիրախ, …) |
| `created_at` | Երբ (ISO 8601)                                           |

Ադմինիստրատորները կարող են հարցում կատարել աուդիտի ամբողջական հետագծի համար՝ `GET /api/gamification/anomalies`-ի միջոցով։

## Վահանակի էջեր

### `/dashboard/leaderboard`

- Պատվանդանի ցուցադրում (առաջին 3-ը՝ ավատարներով և XP-ով)։
- Տիրույթի ընտրիչ՝ գլոբալ / շաբաթական / ամսական / փոխանցված թոքեններ / ներդրումներ։
- Էջավորված աղյուսակ (յուրաքանչյուր էջում՝ 25)՝ վարկանիշով, անունով, միավորով, մակարդակով և կոչմամբ։
- SSE իրական ժամանակի թարմացումներ. վարկանիշի փոփոխությունները ցուցադրվում են անիմացիայով։
- Ընթացիկ օգտատերն ընդգծված է աղյուսակում՝ ամրացված «Ձեր վարկանիշը» տողով։

### `/dashboard/profile`

- XP-ի առաջընթացի գոտի՝ ընթացիկ մակարդակով և հաջորդ մակարդակի շեմով։
- Կոչման կրծքանշանը ցուցադրվում է տեսանելի տեղում։
- Կրծքանշանների պատկերասրահ՝ վաստակած կրծքանշանները՝ վաստակման ամսաթվով, իսկ չվաստակածները՝ մգեցված
  (թաքնված կրծքանշանների համար ցուցադրվում է «???», մինչև դրանք վաստակվեն)։
- Շարքի հաշվիչ՝ կրակի պատկերակով, և շարքի օրացույց (վերջին 30 օրը)։
- XP-ի պատմության գծապատկեր (օրական XP-ն վերջին 30 օրվա ընթացքում)։

### `/dashboard/tokens`

- Թոքենների մնացորդ (տեսանելի տեղում՝ էջի վերևում)։
- Փոխանցման ձև՝ ստացող, գումար, հաստատման երկխոսության պատուհան։
- Փոխանցումների պատմության աղյուսակ՝ զտիչներով (ուղարկված/ստացված/բոլորը)։
- Հրավերների բաժին՝ ակտիվ կոդեր, նորի ստեղծում, կիսվելու հղում։
- Համայնքային սերվերներ՝ ցանկ՝ առողջական վիճակով, միացում/անջատում։

### `/dashboard/gamification/admin`

- Անոմալիաների ցանկ՝ լրջության աստիճանով, օգտատիրոջով, ժամանակային նշումով և z-միավորով։
- Աուդիտի մատյանի դիտարկիչ՝ զտիչներով (գործողության տեսակ, օգտատեր, ամսաթվերի միջակայք)։
- Համակարգի վիճակագրություն՝ շնորհված XP-ի ընդհանուր քանակ, ակտիվ օգտատերեր, կրծքանշանների վաստակման ցուցանիշներ։
- Ֆեդերացիայի սերվերների առողջական վիճակի ընդհանուր տեսություն։

## Կոնվեյերի ինտեգրում

### Ինտեգրման կետ

Գեյմիֆիկացիան միանում է հարցումների կոնվեյերին մեկ կետում՝
`open-sse/handlers/chatCore.ts`-ում.

```typescript
// Պատասխանը հաճախորդին ուղարկելուց հետո՝
setImmediate(() => {
  emitGamificationEvent({
    type: "request.completed",
    apiKeyId,
    metadata: {
      provider: selectedProvider,
      model: selectedModel,
      comboId: resolvedCombo?.id,
      compressionUsed: compressionStats?.applied,
      skillUsed: skillExecution?.name,
    },
  }).catch(() => {
    // Գործարկել և չսպասել. գրանցել մատյանում, բայց երբեք չփոխանցել հաճախորդին
  });
});
```

### Իրադարձությունների տեսակներ

| Իրադարձության տեսակ | Երբ է արձակվում                                                            |
| ------------------- | -------------------------------------------------------------------------- |
| `request.completed` | Հաջող LLM պատասխանը ուղարկվել է                                            |
| `provider.switch`   | Մատակարարը փոխվել է (combo-ի պահուստային տարբերակն ակտիվացնելը հաշվվում է) |
| `combo.created`     | Նոր combo կազմաձևը պահպանվել է                                             |
| `combo.used`        | Combo-ի թիրախը հաջողությամբ գործարկվել է                                   |
| `badge.earned`      | Կրծքանշանի գնահատումը համապատասխանություն է հայտնաբերել                    |
| `streak.milestone`  | Շարքի շեմը հատվել է                                                        |
| `transfer.sent`     | Թոքենների փոխանցումն ավարտվել է                                            |
| `referral.redeemed` | Հրավերի կոդը հաջողությամբ օգտագործվել է                                    |
| `compression.used`  | Հուշման սեղմումը կիրառվել է                                                |
| `skill.executed`    | Հմտության կատարումն ավարտվել է                                             |
| `model.first_use`   | Մոդելը չի օգտագործվել վերջին 7 օրվա ընթացքում                              |

### Չարգելափակման երաշխիք

`setImmediate` + `.catch(() => {})` ձևանմուշն ապահովում է՝

1. Պատասխանն ամբողջությամբ ուղարկվում է նախքան գեյմիֆիկացիայի գործարկումը։
2. Գեյմիֆիկացիայի սխալները երբեք չեն ցուցադրվում հաճախորդին։
3. Իրադարձության մշակումը կատարվում է հաջորդ միկրոառաջադրանքում, այլ ոչ թե ներկառուցված կերպով։

## Անվտանգություն

### Սպառնալիքների մոդել

| Սպառնալիք                            | Կանխարգելիչ միջոց                                                                                |
| ------------------------------------ | ------------------------------------------------------------------------------------------------ |
| Միավորների արհեստական աճ             | XP-ի հաշվարկը՝ միայն սերվերի կողմից. հաճախորդներն ուղարկում են գործողություններ, ոչ թե միավորներ |
| Կրկնակի վերարտադրման գրոհներ         | Փոխանցումների իդեմպոտենտության բանալիներ. աուդիտի մատյանի կրկնագրերի հեռացում                    |
| Փոխանցումների խարդախություն          | Կրկնակի գրանցմամբ հաշվառում. ատոմար գործարքներ. հաճախականության սահմանափակումներ                 |
| Ինքնուղղորդում                       | Օգտագործման ժամանակ `api_key_id`-ի խաչաձև ստուգում                                               |
| Առաջատարների աղյուսակի մանիպուլյացիա | Z-միավորով անոմալիաների հայտնաբերում. ադմինիստրատորի անոմալիաների վահանակ                        |
| Ֆեդերացիայի տոկենի գողություն        | SHA-256 հեշավորված պահպանում. չմշակված տոկենը ցուցադրվում է միայն մեկ անգամ                      |
| Հրավերի կոդերի ամբողջական փորձարկում | Օգտագործման վերջնակետում հաճախականության սահմանափակում. 8-նիշանոց էնտրոպիա                       |
| XSS ցուցադրվող անուններում           | Ցուցադրվող անունները մաքրվում են. առաջատարների աղյուսակի գրառումները էկրանավորվում են            |
| Հեշերի նկատմամբ ժամանակային գրոհներ  | `crypto.timingSafeEqual`՝ տոկենի հեշերը համեմատելու համար                                        |

### Նույնականացման պահանջներ

- **Հանրային** (առանց նույնականացման)՝ `GET /leaderboard`, `GET /stream` (միայն
  ընթերցման համար նախատեսված առաջատարների աղյուսակներ)։
- **Պահանջվում է API բանալի**՝ գրանցման բոլոր գործողությունների, պրոֆիլի, փոխանցումների և հրավերների համար։
- **Միայն ադմինիստրատորի համար**՝ անոմալիաների վահանակ, աուդիտի մատյանի դիտիչ։
- **Ֆեդերացիա**՝ առանձին նույնականացման ուղի՝ `Authorization`
  վերնագրում չմշակված տոկենի օգտագործմամբ, որը վավերացվում է պահպանված SHA-256 հեշի նկատմամբ։

## Ապագա նկատառումներ

- **Սեզոնային իրադարձություններ**․ ժամանակով սահմանափակված կրծքանշանների հավաքածուներ և առաջատարների աղյուսակի սեզոններ։
- **Թիմային առաջատարների աղյուսակներ**․ օգտատերերին խմբավորել ըստ կազմակերպության կամ համակցման։
- **XP բազմապատկիչներ**․ ավելացնել XP-ն գովազդային ժամանակահատվածներում։
- **Ձեռքբերումների տարածում**․ ստեղծել տարածելի կրծքանշանային քարտեր (OpenGraph պատկերներ)։
- **Բջջային push ծանուցումներ**․ webhook-ի վրա հիմնված ծանուցումներ կրծքանշանների/մակարդակների իրադարձությունների համար։
- **Առաջատարների աղյուսակի API**․ հանրային API՝ երրորդ կողմի ինտեգրումների համար։
