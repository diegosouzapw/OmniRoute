OmniRoute-ը տարանջատում է **CLI-ի հայտնաբերումը**, **բնիկ Agent Client Protocol-ը** և
**ժառանգական stdio ադապտերները**։ Տեղադրված երկուական ֆայլի հայտնաբերումը չի ապացուցում դրա
նույնականացումը, մոդելի հետ համատեղելիությունը կամ հուշում մշակելու պատրաստ լինելը։

Կառավարման վահանակն օգտագործում է `GET /api/acp/agents` և `POST /api/acp/agents`՝ գույքագրման
և անհատական գործակալների գրանցման համար։ Սրանք միայն տեղային կառավարման երթուղիներ են, այլ ոչ թե
գործընթացներ մեկնարկելու կամ հուշումներ ուղարկելու հանրային API։ Ներքին
`AcpManager`-ը ինքնաբերաբար չի դառնում HTTP մատակարարի պահուստային տարբերակ։

## Գրանցված պայմանագրեր

`config/cli-tools-manifest.json`-ը ներկառուցված գործարկման
երկուական ֆայլերի, արգումենտների և հետնամասային ռեժիմների հավաստի աղբյուրն է։ Ռեեստրն իր սահմանումները
ստանում է այդ մանիֆեստից։ Հայտնաբերման արդյունքը պահվում է քեշում 60 վայրկյան։

- `acp`՝ Gemini-ի պայմանագիրը գործարկում է `gemini --experimental-acp` և պաշտոնական TypeScript SDK-ի միջոցով
  հաղորդակցվում նոր տողով սահմանազատված ACP JSON-RPC-ով։
- `stdio-adapter`՝ մյուս գրանցված պայմանագրերը պահպանում են ժառանգական՝ նոր տողով մուտքագրման և
  stdout-ով արտածման ադապտերը։ Արտածման երկու վայրկյան անգործությունը ավարտում է դրա պատասխանը։
  Այս ադապտերը **չի** հաստատում այդ CLI-ների կողմից բնիկ ACP-ի աջակցությունը։

Gemini-ն գործարկման դրոշակը փաստաթղթավորում է իր [CLI տեղեկագրում](https://geminicli.com/docs/cli/cli-reference/)։
Հաճախորդն օգտագործում է [պաշտոնական ACP SDK-ն](https://github.com/agentclientprotocol/typescript-sdk)՝
նախաստորագրման, աշխատաշրջանի ստեղծման, հուշման հարցումների, ծանուցումների և չեղարկման համար։

Անհատական գործակալների սահմանումները մնում են ադմինիստրատորի կողմից կառավարվող գործարկման պայմանագրեր։
Երկուական ֆայլի և արգումենտների գրանցումն այդ գործընթացին տրամադրում է սերվերի օգտատիրոջ տեղային
կատարման արտոնությունները․ գրանցումը մեկուսացված միջավայր չէ։ Տարբերակի ստուգումները
ընդունում են միայն գրանցված գործարկվող ֆայլը և ճանաչված տարբերակի դրոշակը։

## Ներքին գործարկման API

```typescript
import { acpManager } from "@/lib/acp";

const session = acpManager.spawn("gemini", {
  cwd: process.cwd(),
  // Փոխանցեք միայն այս գործակալին միտումնավոր վերագրված մատակարարի փոփոխականները։
  env: {
    GEMINI_API_KEY: process.env.GEMINI_API_KEY,
  },
});

try {
  const response = await acpManager.sendPrompt(session.id, "Բացատրիր այս նախագիծը", 120_000);
  // Օգտագործեք պատասխանը կանչող հավելվածում։
} finally {
  acpManager.kill(session.id);
}
```

`spawn(agentId, options)`-ը որոշում է գործարկվող ֆայլը և արգումենտները՝ ըստ
գրանցված սահմանման։ Կանչողի միակ ընտրանքներն են `cwd`-ն և `env`-ը․ հին
`spawn(agentId, binary, args, env)` ստորագրությունը և գործարկվող ֆայլի վերասահմանումները
մերժվում են։ Այս կառավարիչը չի աջակցում HTTP գործարկման պայմանագրերը։

Դուստր գործընթացը ժառանգում է նույն օպերացիոն համակարգի, տերմինալի, տեղայնացման և վկայականների
թույլատրացուցակը, ինչ CLI գործարկիչները։ Սերվերի/մատակարարի գաղտնիքները չեն պատճենվում
ծնող միջավայրից։ Ընտրված CLI-ին անհրաժեշտ հավատարմագրերը պետք է փոխանցվեն
բացահայտորեն կամ տրամադրվեն տվյալ CLI-ի սեփական տեղային նույնականացման միջոցով։ Դուստր գործընթացը
շարունակում է ունենալ տեղային օգտատիրոջ ֆայլային համակարգի թույլտվությունները և կարող է կարդալ իր կազմաձևը։

## Բնիկ կենսացիկլ և սահմանափակումներ

1. Գործարկել գրանցված երկուական ֆայլը, նախաստորագրել ACP-ն և ստեղծել ընտրված աշխատանքային գրացուցակում
   արմատավորված աշխատաշրջան։ Նախաստորագրումը սահմանափակված է տասը վայրկյանով։
2. Ուղարկել հուշում և հավաքել տեքստային ծանուցումները միայն այդ աշխատաշրջանի համար։
   Ավարտը հուշման RPC պատասխանն է, ոչ թե stdout-ի լռության ժամանակահատվածը։
3. Օգտագործել հուշման մեկ վերջնաժամկետ՝ ներառյալ ցանկացած չավարտված նախաստորագրում․ լռելյայնը
   120 վայրկյան է։ Նույն գործընթացում զուգահեռ հուշումները մերժվում են։
4. Բնիկ ռեժիմի ժամանակի սպառման դեպքում փորձել `session/cancel` և ավարտել գործընթացը։
   Սահմանափակ՝ 100 ms պատուհանը թույլ է տալիս ծանուցումը դուրս գրել մինչև գործընթացի ավարտը։
5. Փակել փոխադրամիջոցի վիճակը և հեռացնել աշխատաշրջանը, երբ նախաստորագրումը ձախողվում է,
   կապը փակվում է, գործընթացն ավարտվում է, կամ կանչողը դադարեցնում է այն։

Գործիքի թույլտվությունների հարցումները մերժվում են։ Ֆայլային համակարգի կամ տերմինալի հաճախորդի
հնարավորություններ չեն հայտարարվում։ Այս սահմանափակումները չեն մեկուսացնում հենց դուստր երկուական ֆայլը
և չեն փոխարինում CLI-ի սեփական թույլտվությունների կարգավորումներին։

Թե՛ բնիկ տեքստը, թե՛ ժառանգական stdout/stderr-ը պահպանում են առավելագույնը 1 MiB նիշ՝
պահելով ամենավերջին արտածումը՝ կրճատման մասին ծանուցմամբ։ Առանձին բնիկ հաղորդալարի
շրջանակը մինչև SDK-ի վերլուծումը սահմանափակված է 2 MiB բայթով։ Բուֆերները զրոյացվում են յուրաքանչյուր հուշման համար։

`kill(sessionId)`-ն ուղարկում է SIGTERM, ապա հինգ վայրկյանից հետո՝ SIGKILL, եթե գործընթացը
չի ավարտվել։ Ժառանգական հուշումների ժամանակի սպառումն ազատում է ունկնդիրներն ու ժամանակաչափերը, սակայն
աշխատաշրջանը հասանելի է թողնում մեկ այլ հուշման համար․ ավարտելուց հետո կանչողները շարունակում են պատասխանատու լինել
`kill()` կամ `killAll()` կանչելու համար։

## Իրադարձություններ և զննում

Կառավարիչը արձակում է `stdout`, `stderr` և `exit` իրադարձություններ, որոնցից յուրաքանչյուրն ունի `sessionId`։
`sessionError`-ը հաղորդում է մաքրված փոխադրամիջոցի սխալը։ Համատեղելիության `error`
իրադարձությունն արձակվում է միայն բաժանորդ ունենալու դեպքում, ուստի բացակայող երկուական ֆայլը չի կարող
առաջացնել չմշակված EventEmitter սխալ։

- `getSession(sessionId)`-ը վերադարձնում է կառավարվող աշխատաշրջան կամ `undefined`։
- `getActiveSessions()`-ը բացառում է դադարեցված կամ դադարեցման ընթացքում գտնվող աշխատաշրջանները։
- `sendInput(sessionId, input)`-ը հասանելի է միայն գործող ժառանգական ադապտերի համար․
  բնիկ ACP-ն մերժում է անմշակ մուտքը՝ իր JSON-RPC հոսքը պաշտպանելու նպատակով։
- `killAll()`-ն ավարտում է տվյալ օրինակի կողմից կառավարվող բոլոր աշխատաշրջանները։

## Վավերացման սահմաններ

Որոշակիացված ֆիքստուրները ծածկում են բնիկ համաձայնեցումը, տեքստային արտածումը, մերժված
թույլտվությունները, չեղարկումը, զուգահեռ հուշումները, ձախողված նախաստորագրումը, գործընթացի
ավարտը, արտածման սահմանաչափերը և գաղտնիքների մեկուսացումը։ Ժառանգական բուֆերի/ունկնդրի առկա
հետընթաց սխալները նույնպես շարունակում են ծածկված մնալ։ Այս թեստերը չեն ցուցադրում Gemini-ի իրական մուտք
կամ մատակարարի միջոցով հաջող եզրակացություն․ դրանք պահանջում են թիրախային միջավայրում առանձին լիազորված ծխային
թեստ։
