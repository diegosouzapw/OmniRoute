> (թոքենի պահպանում), `open-sse/mcp-server/tools/notionTools.ts` (6 MCP գործիք),
> `src/app/api/settings/notion/route.ts` (կարգավորումների API)։ Գործիքների գրանցումը և հասանելիության շրջանակների
> կապակցումը գտնվում են `open-sse/mcp-server/server.ts`-ում։

## Ինչ է սա

OmniRoute-ը կարող է միանալ **Notion** աշխատանքային տարածքին՝ որպես **համատեքստի աղբյուր**՝ կարդալու/գրելու
հնարավորությամբ գիտելիքների բազա, որին գործակալները հասանելիություն են ստանում ներկառուցված MCP սերվերի միջոցով։ Notion-ի
ինտեգրման թոքենը կարգավորելուց հետո MCP գործիքները LLM-ին թույլ են տալիս որոնել էջեր և տվյալների բազաներ,
կարդալ էջերի բովանդակությունն ու բլոկների ծառերը, հարցումներ կատարել տվյալների բազաներում՝ զտիչներով/տեսակավորումներով, և ավելացնել նոր
բլոկներ։ Այս ամենը միջնորդավորվում է OmniRoute-ի միջոցով (կրկին փորձելու, ժամանակի սահմանափակման և սխալների դասակարգման
հնարավորություններով), որպեսզի մոդելը երբեք ուղղակիորեն չդիմի Notion API-ին։

Ինտեգրումը պաշտոնական Notion REST API-ի վրա կառուցված պարզեցված, ամրապնդված շերտ է
(`https://api.notion.com/v1`, `Notion-Version: 2026-03-11`)։ Հաճախորդը
(`src/lib/notion/api.ts`) ավելացնում է՝

- **Էքսպոնենցիալ հետաձգմամբ կրկին փորձելու մեխանիզմ** (մինչև 3 փորձ)՝ `429` և `5xx` պատասխանների համար։
- **Հարցման 55 վայրկյանանոց ժամանակի սահմանափակում**՝ `AbortController`-ի միջոցով։
- **Տիպավորված սխալների դասակարգում**՝ `NotionAuthError` (401/403),
  `NotionNotFoundError` (404), `NotionRateLimitError` (429, հաշվի է առնում `retry after`
  հուշումները), `NotionValidationError` (400/409), `NotionServerError` (5xx),
  `NotionTimeoutError`։
- **Հաղորդագրությունների մաքրում**, որը նախքան ցուցադրումը հեռացնում է կանչերի շղթայի հետագծմանը նման հատվածները։

## Կարգավորում

Notion-ի թոքենի համար **միջավայրի փոփոխական չկա**․ այն պահվում է
SQLite-ի `key_value` աղյուսակում (`notion` անվանատարածք, `integration_token` բանալի)՝
`src/lib/db/notion.ts`-ի միջոցով։ Կարգավորեք այն Endpoint-ի կառավարման վահանակի **Context Sources**
ներդիրից (`ObsidianSourceCard`-ի հարակից `NotionSourceCard`-ը) կամ կարգավորումների REST API-ի միջոցով։

> [!NOTE]
> Թոքենը **Notion-ի ներքին ինտեգրման թոքեն** է։ Ստեղծեք ինտեգրում
> <https://www.notion.com/my-integrations> հասցեում, ապա այդ ինտեգրմանը հասանելի դարձրեք այն էջերը/տվյալների բազաները, որոնց
> OmniRoute-ը պետք է հասանելիություն ունենա (Notion-ի թույլտվությունների մոդելը հիմնված է համօգտագործման վրա,
> ոչ թե ամբողջ աշխատանքային տարածքի հասանելիության)։

### Կարգավորում REST-ի միջոցով

```bash
# Պահպանել և վավերացնել ինտեգրման թոքենը (POST-ը վավերացնում է՝ փորձնական որոնում կատարելով)
curl -X POST http://localhost:20128/api/settings/notion \
  -H "Content-Type: application/json" \
  -d '{"token":"ntn_xxx"}'

# Ստուգել կապի կարգավիճակը
curl http://localhost:20128/api/settings/notion

# Անջատել կապը (մաքրում է պահպանված թոքենը)
curl -X DELETE http://localhost:20128/api/settings/notion
```

Բոլոր երեք մեթոդները պահանջում են կառավարման վահանակի նույնականացում (`isAuthenticated`)։ `POST`-ի դեպքում
OmniRoute-ը պահպանում է թոքենը և անմիջապես կատարում 1 արդյունքով փորձնական որոնում։ Եթե Notion-ը
վերադարձնում է սխալի օբյեկտ, թոքենը մաքրվում է, իսկ կանչը ձախողվում է `400` կոդով։

## MCP գործիքներ (6)

Սահմանված են `open-sse/mcp-server/tools/notionTools.ts`-ում։ Թոքենը որոշվում է կանչի
պահին՝ `getNotionToken()`-ի միջոցով։ Եթե որևէ թոքեն կարգավորված չէ, գործիքը նետում է
`"Notion-ի ինտեգրման թոքենը կարգավորված չէ։ Սահմանեք այն Settings > Context Sources բաժնում։"`

| Գործիք                       | Շրջանակ        | Նկարագրություն                                                                                                    |
| ---------------------------- | -------------- | ----------------------------------------------------------------------------------------------------------------- |
| `notion_search`              | `read:notion`  | Որոնում է էջեր և տվյալների բազաներ՝ տեքստային հարցմամբ (վերադարձնում է վերնագրեր, ID-ներ, URL-ներ)։ Էջավորված է։  |
| `notion_get_page`            | `read:notion`  | Ստանում է էջի բովանդակությունն ու մետատվյալները՝ ըստ դրա ID-ի։                                                    |
| `notion_list_block_children` | `read:notion`  | Ցուցադրում է բլոկի կամ էջի բոլոր ենթաբլոկները (բլոկների ծառը)։ Էջավորված է։                                       |
| `notion_query_database`      | `read:notion`  | Հարցում է կատարում տվյալների բազայում՝ կամընտիր `filter` + `sorts` պարամետրերով (Notion API ձևաչափ)։ Էջավորված է։ |
| `notion_get_database`        | `read:notion`  | Ստանում է տվյալների բազայի սխեման/մետատվյալները՝ ըստ ID-ի։                                                        |
| `notion_append_blocks`       | `write:notion` | Բլոկի կամ էջի վերջում ավելացնում է ենթաբլոկներ (առավելագույնը 100 բլոկ՝ մեկ հարցման համար)։                       |

### Մուտքային պարամետրեր

- `notion_search` — `query` (1–500 նիշ), `pageSize` (1–100, լռելյայն՝ 20),
  `startCursor` (կամընտիր)։
- `notion_get_page` — `pageId` (32 նիշանոց տասնվեցական արժեք կամ UUID)։
- `notion_list_block_children` — `blockId`, `pageSize` (1–100, լռելյայն՝ 50),
  `startCursor` (կամընտիր)։
- `notion_query_database` — `databaseId`, `filter` (կամընտիր, Notion-ի զտիչի ձևաչափ),
  `sorts` (կամընտիր զանգված), `pageSize` (1–100, լռելյայն՝ 50), `startCursor` (կամընտիր)։
- `notion_get_database` — `databaseId`։
- `notion_append_blocks` — `blockId`, `children` (բլոկների օբյեկտների զանգված),
  `after` (կամընտիր դիրք)։

### Հասանելիության շրջանակներ

Կարդալու գործիքները պահանջում են `read:notion`, իսկ գրելու գործիքը՝ `write:notion`։
Հասանելիության շրջանակները պարտադրվում են `withScopeEnforcement()`-ի միջոցով՝
`open-sse/mcp-server/server.ts`-ում, միայն երբ `OMNIROUTE_MCP_ENFORCE_SCOPES=true` է։ Կանչողի
թույլատրված շրջանակները վերցվում են `OMNIROUTE_MCP_SCOPES`-ից (ստորակետերով բաժանված) կամ
նույնականացված API բանալու շրջանակների համատեքստից։ Հասանելիության շրջանակների ամբողջական մոդելի համար
տես [MCP-SERVER.md](./MCP-SERVER.md)։

## Վերջնակետեր

| Մեթոդ    | Ուղի                   | Նպատակ                                  |
| -------- | ---------------------- | --------------------------------------- |
| `GET`    | `/api/settings/notion` | Վերադարձնել `{ connected, hasToken }`։  |
| `POST`   | `/api/settings/notion` | Պահպանել և վավերացնել ինտեգրման թոքենը։ |
| `DELETE` | `/api/settings/notion` | Անջատել (մաքրել պահպանված թոքենը)։      |

> Սրանք կառավարման վահանակի կարգավորումների երթուղիներ են։ **Հանրային `/v1` Notion պրոքսի
> վերջնակետ չկա** — Notion-ը հասանելի է բացառապես վերոնշյալ MCP գործիքների միջոցով։

## Օգտագործման դեպքեր

- **Գիտելիքի վրա հիմնված պատասխաններ** — թույլ տվեք գործակալին `notion_search`-ի միջոցով որոնել աշխատանքային տարածքում և
  պատասխանելուց առաջ `notion_get_page`-ի միջոցով ստանալ լավագույն արդյունքը, որպեսզի պատասխանները հղում կատարեն իրական ներքին փաստաթղթերին։
- **Տվյալների բազայի վրա հիմնված աշխատանքային հոսքեր** — `notion_query_database`-ի միջոցով հարցում կատարել առաջադրանքների/CRM տվյալների բազային՝
  զտիչներով և տեսակավորումներով, ապա ամփոփել կամ առաջնահերթություն տալ տողերին։
- **Հետգրում / գրանցամատյանի վարում** — `notion_append_blocks`-ի միջոցով առկա էջին ավելացնել հանդիպման նշումներ, գործարկման
  ամփոփումներ կամ գործակալի ելքային տվյալներ (միայն ավելացում՝ առանց քայքայիչ խմբագրումների)։
- **Կառուցվածքի ուսումնասիրություն** — `notion_list_block_children`-ի միջոցով անցնել էջի բլոկների ծառով,
  կամ `notion_get_database`-ի միջոցով բացահայտել տվյալների բազայի հատկությունների սխեման՝ նախքան դրան հարցում կատարելը։
