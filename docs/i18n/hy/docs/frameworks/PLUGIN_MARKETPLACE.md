> **Ճշմարտության աղբյուր՝** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/` և
> `src/app/(dashboard)/dashboard/plugins/`
> **Վերջին թարմացումը՝** 2026-06-28 — v3.8.40

OmniRoute-ը տրամադրվում է WordPress-ի ոճով փլագինային համակարգով։ Փլագիններն ինքնաբավ
պանակներ են, որոնցից յուրաքանչյուրն ունի `plugin.json` մանիֆեստ և մուտքային ֆայլ, որոնք կցվում
են հարցումների մշակման շղթային (`onRequest` / `onResponse` / `onError`) և
կենսացիկլի իրադարձություններին (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`)։

**Փլագինների շուկան** այդ համակարգի վրա կառուցված հայտնաբերման շերտն է։ Այն
տրամադրում է տեղադրվող փլագինների զննարկելի կատալոգ։ Լռելյայնորեն կատալոգը
փոքր ներկառուցված սկզբնական ռեեստր է․ օպերատորը կարող է այն ուղղորդել դեպի հատուկ հեռավար
ռեեստրի URL, որի դեպքում հարցումը պաշտպանվում է DNS լուծող SSRF պաշտպանիչով
(տե՛ս [Անվտանգություն](#security))։

Փլագինների յուրաքանչյուր երթուղի **հասանելի է միայն loopback-ից** (Մակարդակ 1 — `LOCAL_ONLY`)․ փլագինները
բեռնում և կատարում են կոդը դուստր գործընթացներում, ուստի երթուղիները հասանելի չեն
ոչ loopback սկզբնաղբյուրից՝ անկախ նույնականացումից։ Տե՛ս
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md)։

## Ինչպես են բաղադրիչները փոխկապակցվում

```
Կառավարման վահանակ (/dashboard/plugins)
  ├─ «Տեղադրված» ներդիր → GET /api/plugins            (listPlugins)
  │                       POST /api/plugins/scan      (pluginManager.scan)
  │                       POST /api/plugins/{name}/activate|deactivate
  │                       DELETE /api/plugins/{name}   (հեռացում)
  └─ «Շուկա» ներդիր      → GET /api/plugins/marketplace
                            → listMarketplacePlugins()
                              ├─ հատուկ URL չկա → ներկառուցված SEED_REGISTRY
                              └─ հատուկ URL → isSafeMarketplaceUrl() SSRF պաշտպանիչ
                                            → safeOutboundFetch(guard:"public-only")
```

- **Ռեեստրի շերտ** — `src/lib/plugins/marketplace.ts`․ ցուցակագրում / որոնում է
  կատալոգը՝ ցանկացած ձախողման դեպքում անցնելով սկզբնական ռեեստրին։
- **Կենսացիկլի շերտ** — `src/lib/plugins/manager.ts` (`pluginManager` եզակի նմուշ)․
  տեղադրում, արդիականացում, ակտիվացում, ապակտիվացում, հեռացում, սկանավորում, մեկնարկային բեռնում։
- **Մանիֆեստի շերտ** — `src/lib/plugins/manifest.ts`․ Zod սխեմա + լռելյայն արժեքներ
  `plugin.json`-ի համար։
- **Սկանավորիչ** — `src/lib/plugins/scanner.ts`․ փլագինների պանակում
  հայտնաբերում է սկավառակի վրա գտնվող փլագինները։
- **Բեռնիչ** — `src/lib/plugins/loader.ts`․ յուրաքանչյուր փլագին գործարկում է մեկուսացված
  դուստր գործընթացում և IPC-ի միջոցով միջնորդում է hook կանչերը։

## Շուկայի կատալոգ

`listMarketplacePlugins()`-ը (`src/lib/plugins/marketplace.ts`) վերադարձնում է
`MarketplaceEntry` օբյեկտների ցուցակ․

| Դաշտ          | Տեսակ    | Նշումներ                                       |
| ------------- | -------- | ---------------------------------------------- |
| `name`        | string   | kebab-case ձևաչափով փլագինի անուն              |
| `version`     | string   | semver                                         |
| `description` | string   | Կարճ ամփոփագիր                                 |
| `author`      | string   | Հեղինակ / կազմակերպություն                     |
| `license`     | string   | SPDX-ի ոճով արտոնագրի նույնացուցիչ             |
| `downloadUrl` | string   | Աղբյուրի ներբեռնման URL (կարող է դատարկ լինել) |
| `repository`  | string?  | Ռեպոզիտորիայի ոչ պարտադիր URL                  |
| `tags`        | string[] | Որոնման/զտման պիտակներ                         |
| `downloads`   | number   | Ներբեռնումների քանակ                           |
| `rating`      | number   | 0–5                                            |
| `verified`    | boolean  | Արդյոք գրառումը նշված է որպես հաստատված        |
| `lastUpdated` | string   | ISO-ին մոտ ձևաչափով ամսաթվի տող                |

Երբ հատուկ ռեեստրի URL կազմաձևված չէ, կատալոգը ներկառուցված
`SEED_REGISTRY`-ն է (ներկայում՝ `request-logger`, `rate-limiter`, `cost-tracker` և
`theme-manager`)։ Սկզբնական ռեեստրը միշտ հասանելի է․ եթե կազմաձևված հեռավար
ռեեստրն անհասանելի է, վերադարձնում է `200`-ից տարբեր կարգավիճակ կամ վերադարձնում է չճանաչված
մարմին, `listMarketplacePlugins()`-ը գրանցում է նախազգուշացում և անցնում սկզբնական ցուցակին։

> Նշում․ շուկայի **կատալոգը** (զննում/որոնում) ամբողջությամբ կապակցված է, սակայն
> կատալոգից մեկ սեղմումով շուկայական **տեղադրումը** դեռ իրականացված չէ․
> շուկայի գրառման համար կառավարման վահանակի «Տեղադրել» կոճակը ներկայում ցուցադրում է
> «շուտով հասանելի կլինի» ծանուցում։ Այս պահին տեղադրումը կատարվում է տեղային ուղու տեղադրման
> հոսքի (`POST /api/plugins`) և սկավառակի վրա հայտնաբերման (`POST /api/plugins/scan`) միջոցով։

## REST API

Բոլոր վերջնակետերը պահանջում են կառավարման նույնականացում (`requireManagementAuth`) **և**
հասանելի են միայն loopback-ից․ `/api/plugins` և `/api/plugins/` ուղիները նշված են
`LOCAL_ONLY_API_PREFIXES`-ում (`src/server/authz/routeGuard.ts`)։

| Վերջնակետ                        | Մեթոդ  | Նկարագրություն                                              |
| -------------------------------- | ------ | ----------------------------------------------------------- |
| `/api/plugins`                   | GET    | Տեղադրված փլագինների ցանկ (ըստ ցանկության՝ `?status=` զտիչ) |
| `/api/plugins`                   | POST   | Տեղադրել փլագին բացարձակ տեղային ուղուց                     |
| `/api/plugins/scan`              | POST   | Սկանավորել փլագինների գրացուցակը և գրանցել նոր փլագինները   |
| `/api/plugins/marketplace`       | GET    | Marketplace կատալոգի գրառումների ցանկ                       |
| `/api/plugins/[name]`            | GET    | Ստանալ տեղադրված փլագինի մանրամասները                       |
| `/api/plugins/[name]`            | DELETE | Հեռացնել փլագինը                                            |
| `/api/plugins/[name]/activate`   | POST   | Ակտիվացնել (բեռնել + գրանցել hook-երը)                      |
| `/api/plugins/[name]/deactivate` | POST   | Ապաակտիվացնել (կանչել `onDeactivate`, ապագրանցել hook-երը)  |
| `/api/plugins/[name]/config`     | GET    | Ստանալ փլագինի կազմաձևը + կազմաձևի սխեման                   |
| `/api/plugins/[name]/config`     | PUT    | Թարմացնել փլագինի կազմաձևը (սխեմայով վավերացմամբ)           |

`GET /api/plugins` հարցման `status` զտիչն ընդունում է հետևյալներից մեկը՝
`installed` / `active` / `inactive` / `error`։ Անվավեր արժեքի դեպքում վերադարձվում է `400`։

### Տեղադրված փլագինների ցանկը

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### Տեղադրում տեղային ուղուց

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path`-ը պետք է լինի **բացարձակ** և չպետք է պարունակի `..` անցման հատվածներ կամ
զրոյական բայթեր (պարտադրվում է Zod-ի միջոցով)։ Աղբյուր գրացուցակը պետք է պարունակի վավեր
`plugin.json` (կամ լինի այն պարունակող ծնող գրացուցակ)։ Հաջողության դեպքում պատասխանը `201` է՝
տեղադրված փլագինի տողով։

### Marketplace-ի դիտարկում

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### Փլագինի կազմաձևի թարմացում

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config`-ը տրամադրված յուրաքանչյուր արժեք վավերացնում է փլագինի
`configSchema`-ի նկատմամբ (հայտարարված է manifest-ում)․ `number` դաշտերը հաշվի են առնում `min`/`max`-ը,
իսկ `select` դաշտերը պետք է համապատասխանեն հայտարարված `enum`-ին։ Սխեմայում չներառված բանալիները
թույլատրվում են։

## Կազմաձևում

### Փլագինների գրացուցակ

Փլագինները գտնվում են OmniRoute-ի տվյալների գրացուցակի ներքո․

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (կամ այն ֆայլը, որին հղվում է manifest.main-ը)
```

`getDefaultPluginDir()`-ը (`src/lib/plugins/scanner.ts`) այդ գրացուցակը որոշում է
երեք քայլով․

1. **`OMNIROUTE_PLUGINS_DIR`**, երբ այն սահմանված է՝ օգտագործվում է բառացիորեն՝ անկախ `HOME`-ի արժեքից։ Սա
   Docker/K8s-ի համար նախատեսված բացահայտ կարգավորիչն է, որտեղ փլագինների ծառը bind-mount-ով միացվում է մի ուղու,
   որը սովորաբար որևէ կապ չունի կոնտեյների տնային գրացուցակի հետ (#11827)։
2. `<home>/.omniroute/plugins`, որտեղ `<home>`-ը վերցվում է `HOME` / `USERPROFILE`
   միջավայրի փոփոխականներից։
3. `/tmp/.omniroute/plugins`, երբ գործընթացն ընդհանրապես տնային գրացուցակ չի արտահանում։

Որոշված գրացուցակը մեկնարկի ժամանակ մեկ անգամ գրանցվում է մատյանում որպես `scanner.dir_resolved`՝ նշելով
գերակշռած մուտքային արժեքը (`OMNIROUTE_PLUGINS_DIR`, `home` կամ `no-home-fallback`)։ Այսպիսով՝ այն image-ը,
որը լռելյայն անցնում է 3-րդ քայլին, հայտնում է այդ մասին՝ պարզապես փլագինների դատարկ ցանկ հաղորդելու փոխարեն։
`POST /api/plugins/scan`-ը հայտնաբերում է այնտեղ գտնվող ցանկացած ենթագրացուցակ, որը պարունակում է վավեր
`plugin.json`, և գրանցում է այն։ Նույն գրացուցակն այն արմատն է, որի մեջ
`pluginManager.install()`-ը պատճենում է փլագինները, ուստի վերասահմանումը հայտնաբերումն ու
տեղադրումը տեղափոխում է միասին։

> **`OMNIROUTE_PLUGINS_DIR`-ը `OMNIROUTE_PLUGIN_PATH` չէ։** Վերջինս կարդացվում է միայն
> CLI հրամանների փլագինների բեռնիչի (`bin/cli/plugins.mjs`) կողմից՝ `omniroute-cmd-*` npm
> փաթեթները գտնելու համար, որոնք ավելացնում են `omniroute` ենթահրամաններ․ այն որևէ ազդեցություն չունի այստեղ
> նկարագրված runtime սկանավորիչի վրա։ Այդ մասի մասին տե՛ս [PLUGINS.md](./PLUGINS.md)։

### Marketplace-ի հատուկ registry URL

Marketplace կատալոգի աղբյուրը կարդացվում է `pluginMarketplaceUrl` կարգավորումից
(`src/lib/plugins/marketplace.ts`-ը կարդում է `settings.pluginMarketplaceUrl`)։ Երբ
այն սահմանված է որպես `http(s)` URL, `listMarketplacePlugins()`-ը հարցում է կատարում այդ URL-ին և ընդունում
է կա՛մ վերին մակարդակի JSON գրառումների զանգված, կա՛մ `plugins` զանգվածով օբյեկտ։
Տողային `name` չունեցող գրառումները զտվում են։ Երբ այն սահմանված չէ (կամ երբ հարցումը
չի անցնում SSRF պաշտպանությունը / վերադարձնում է անվավեր պատասխան), օգտագործվում է ներկառուցված սկզբնական registry-ն։

Կառավարման վահանակի «Marketplace» ներդիրը ցուցադրում է այս URL-ի համար նախատեսված դաշտ (հետ է կարդացվում
`GET /api/settings`-ից)։

> Իրականացման նշում․ կառավարման վահանակի «Save» գործողությունն ուղարկում է
> `pluginMarketplaceUrl`-ը դեպի `PATCH /api/settings`։ Այս տեքստը գրելու պահին այդ
> բանալին հայտարարված չէ `updateSettingsSchema`-ում
> (`src/shared/validation/settingsSchemas.ts`), ուստի, նախքան դրա վրա հույս դնելը, ստուգեք պահպանումը ձեր
> թողարկման մեջ։ **Ընթերցման** ուղին (`getSettings()` →
> `listMarketplacePlugins()`) հաշվի է առնում բանալին, հենց որ այն առկա է կարգավորումների
> պահոցում։

## Անվտանգություն

### Երթուղու մակարդակ — միայն loopback

Փլագինները կոդ են կատարում գործարկված ենթապրոցեսներում, ուստի ամբողջ `/api/plugins`
մակերեսը դասակարգվում է որպես `LOCAL_ONLY` (մակարդակ 1)։ Loopback-ի կիրառումն
անվերապահորեն կատարվում է նույնականացման ցանկացած ստուգումից **առաջ**, այնպես որ
նույնիսկ թունելի միջոցով սարքին հասած կառավարման արտահոսած տոկենը չի կարող
տեղադրել, ակտիվացնել կամ հեռացնել փլագին։ Տե՛ս
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) և
Խիստ կանոններ #15 / #17։

### Marketplace-ի ռեեստրի SSRF պաշտպանություն

Հատուկ ռեեստրի URL-ը հարձակվողի կողմից ազդեցության ենթակա կազմաձևում է, ուստի
այն ստանալուց առաջ `listMarketplacePlugins()`-ն այն անցկացնում է երկու շերտով․

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`)․
   - Մերժում է այն ամենը, ինչը `http:` / `https:` չէ։
   - Մերժում է բացահայտ private/loopback/link-local/ULA հոսթերը (IPv4 **և** IPv6,
     ներառյալ IPv4-mapped հասցեները)՝ կանոնական `isPrivateHost`-ի միջոցով
     (`src/shared/network/outboundUrlGuard.ts`)։
   - Որոշում է **և՛** `A`, **և՛** `AAAA` գրառումները և մերժում է, եթե որոշված
     հասցեներից **որևէ մեկը** մասնավոր է՝ փակելով հանրային հոսթի անուն → մասնավոր IP
     շրջանցումը։
   - **Խափանման դեպքում մերժում է**․ DNS որոշման ձախողման դեպքում URL-ը մերժվում է։
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`**
   (`src/shared/network/safeOutboundFetch.ts`)․ ստացման պահին կրկին կիրառում է
   միայն հանրային URL-ների պաշտպանությունը և **արգելափակում է վերահղումները**
   (հանրային → մասնավոր `30x` անցում չի թույլատրվում)։

Այս շերտերից որևէ մեկը չանցած URL-ը չի ընդհատում հարցումը․ marketplace-ը
աննկատ անցնում է ներկառուցված սկզբնական ռեեստրին և գրանցում նախազգուշացում։

> Այս պաշտպանությունը խստացվել է PR #3774-ում՝ հատուկ A + AAAA գրառումները որոշելու
> և միայն IPv4-ի ստուգման փոխարեն կանոնական `isPrivateHost`-ն օգտագործելու համար։

### Փլագինի կատարման մեկուսացում

- **Պրոցեսի մեկուսացում** — `loadPlugin()`-ը (`src/lib/plugins/loader.ts`)
  յուրաքանչյուր փլագին գործարկում է առանձին Node.js ենթապրոցեսում և հաղորդակցվում
  է IPC-ի միջոցով։ Hook կանչերն ունեն ժամանակի սահմանափակում՝ `SIGTERM` →
  `SIGKILL` էսկալացիայով։
- **Միջավայրի թույլատրելի ցուցակ** — ենթապրոցեսը ստանում է միայն թույլատրելի
  ցուցակում ներառված միջավայրի փոփոխականները․ ավելի լայն հավաքածուն տրամադրվում է
  միայն այն դեպքում, երբ մանիֆեստը պահանջում է `env` թույլտվությունը։
- **Ուղու սահմանափակում** — տեղադրման/թարմացման/հեռացման ժամանակ հաստատվում է,
  որ փլագինի գրացուցակը և `manifest.main`-ը որոշվում են կառավարվող փլագինների
  արմատային գրացուցակի **ներսում**՝ նախքան որևէ պատճենում կամ ռեկուրսիվ ջնջում
  (պաշտպանում է կեղծված DB ուղիներից և `manifest.main`-ում `../` անցումից)։
  Ակտիվացման ժամանակ սիմվոլիկ հղումները որոշվում են `realpath`-ի միջոցով, և
  մուտքի կետը չի բեռնվում, եթե այն դուրս է գալիս փլագինի գրացուցակից։
- **Ընտրովի ամբողջականության ամրագրում** — մանիֆեստը կարող է հայտարարել
  `integrity` (`sha256-<base64>`, SRI ձևաչափ) դաշտ։ Դրա առկայության դեպքում
  բեռնիչը բեռնման ժամանակ ստուգում է մուտքի ֆայլի հեշը և անհամապատասխանության
  դեպքում հրաժարվում է ակտիվացումից։ Սա ըստ ընտրության կեղծման հայտնաբերման
  միջոց է, **ոչ թե** անվտանգության սահման․ միայն loopback երթուղավորումն ու
  թույլտվությունների մոդելն են իրական սահմանները։

## Մանիֆեստ (`plugin.json`)

Վավերացվում է `PluginManifestSchema`-ի միջոցով (`src/lib/plugins/manifest.ts`)․

| Դաշտ               | Տեսակ     | Նշումներ                                                            |
| ------------------ | --------- | ------------------------------------------------------------------- |
| `name`             | string    | Պարտադիր․ kebab-case (`^[a-z0-9-]+$`), 1–100 նիշ                    |
| `version`          | string    | Պարտադիր․ semver (`MAJOR.MINOR.PATCH`)                              |
| `description`      | string?   | ≤ 500 նիշ                                                           |
| `author`           | string?   | ≤ 200 նիշ                                                           |
| `license`          | string?   | Լռելյայն՝ `MIT`                                                     |
| `main`             | string?   | Մուտքի ֆայլ․ լռելյայն՝ `index.js`                                   |
| `source`           | enum?     | `local` \| `marketplace` (լռելյայն՝ `local`)                        |
| `tags`             | string[]? | Որոնման թեգեր                                                       |
| `requires`         | object?   | `{ omniroute?, permissions[] }`                                     |
| `hooks`            | object?   | Բուլյան արժեքներ, որոնք հայտարարում են փլագինի իրականացրած hook-երը |
| `skills`           | object[]? | Ընտրովի հմտությունների սահմանումներ                                 |
| `enabledByDefault` | boolean?  | Տեղադրելիս ավտոմատ ակտիվացում                                       |
| `configSchema`     | object?   | Կազմաձևման դաշտերի քարտեզ (`string`/`number`/`boolean`/`select`)    |
| `integrity`        | string?   | Մուտքի ֆայլի ընտրովի `sha256-<base64>` ամրագրում                    |

Թույլտվությունները վերցվում են հետևյալ enum-ից՝
`network` / `file-read` / `file-write` / `env` / `exec`։

## Կենսացիկլի հոսք

```
install (POST /api/plugins, ուղի)
  → սկանավորել/վավերացնել մանիֆեստը → պատճենել staging տարածք → համոզվել, որ main-ը գրացուցակի ներսում է
  → ատոմային վերանվանում դեպի ~/.omniroute/plugins/<name> → ավելացնել տող DB-ում
  → կանչել onInstall → եթե enabledByDefault է՝ activate

activate (POST /api/plugins/{name}/activate)
  → realpath-ի պատկանելիության ստուգում → loadPlugin() (գործարկել ենթապրոցես)
  → գրանցել հայտարարված hook-երը → status = "active" → կանչել onActivate

deactivate (POST /api/plugins/{name}/deactivate)
  → կանչել onDeactivate (գրանցումից հանելուց ԱՌԱՋ) → գրանցումից հանել hook-երը
  → ավարտել ենթապրոցեսը → status = "inactive"

uninstall (DELETE /api/plugins/{name})
  → եթե ակտիվ է՝ deactivate → կանչել onUninstall
  → պատկանելիության ստուգմամբ ռեկուրսիվորեն ջնջել plugin-ի գրացուցակը → ջնջել տողը DB-ից
```

`install`-ի կրկնակի գործարկումը մի գրացուցակի համար, որի մանիֆեստի տարբերակը **խստորեն
ավելի նոր է**, քան տեղադրված տարբերակը, ավտոմատ թարմացում է կատարում (մաքուր վերատեղադրում․ կազմաձևումը
վերակայվում է լռելյայն արժեքներին)։ Նույն կամ ավելի հին տարբերակը մերժվում է։

## Տվյալների բազա

`plugins` աղյուսակ (միգրացիա՝ `076_create_plugins.sql`)․

| Սյունակ         | Տիպ     | Նշումներ                                                    |
| --------------- | ------- | ----------------------------------------------------------- |
| `id`            | TEXT PK | UUID                                                        |
| `name`          | TEXT    | Եզակի                                                       |
| `version`       | TEXT    | semver․ լռելյայն՝ `1.0.0`                                   |
| `description`   | TEXT    | Ոչ պարտադիր                                                 |
| `author`        | TEXT    | Ոչ պարտադիր                                                 |
| `license`       | TEXT    | Լռելյայն՝ `MIT`                                             |
| `main`          | TEXT    | Մուտքային ֆայլ․ լռելյայն՝ `index.js`                        |
| `source`        | TEXT    | Լռելյայն՝ `local`                                           |
| `tags`          | TEXT    | JSON զանգված․ լռելյայն՝ `[]`                                |
| `status`        | TEXT    | `installed` \| `active` \| `inactive` \| `error`            |
| `enabled`       | INT     | 0/1․ լռելյայն՝ 0                                            |
| `manifest`      | TEXT    | Ամբողջական մանիֆեստի JSON-ը                                 |
| `config`        | TEXT    | JSON․ լռելյայն՝ `{}`                                        |
| `config_schema` | TEXT    | JSON․ լռելյայն՝ `{}`                                        |
| `hooks`         | TEXT    | Հայտարարված hook-երի անունների JSON զանգված․ լռելյայն՝ `[]` |
| `permissions`   | TEXT    | JSON զանգված․ լռելյայն՝ `[]`                                |
| `plugin_dir`    | TEXT    | Տեղադրման բացարձակ գրացուցակը                               |
| `error_message` | TEXT    | Սահմանվում է, երբ `status = "error"`                        |
| `installed_at`  | TEXT    | `datetime('now')`                                           |
| `updated_at`    | TEXT    | `datetime('now')`                                           |
| `activated_at`  | TEXT    | Սահմանվում է ակտիվացման ժամանակ                             |

Plugin-ի չափորոշիչներն ու վերլուծական տվյալները պահվում են լրացուցիչ աղյուսակներում
(`090_plugin_metrics.sql`, `091_plugin_analytics.sql`)։

## Կառավարման վահանակ

`/dashboard/plugins` հասցեում գտնվող կառավարման վահանակի էջը
(`src/app/(dashboard)/dashboard/plugins/page.tsx`) ունի երկու ներդիր․

- **Տեղադրված** — ցուցադրում է տեղադրված plugin-երը՝ դրանց հայտարարված hook-երով, ակտիվացման/ապաակտիվացման փոխարկիչով, հեռացման կոճակով և «Սկանավորել plugin-ների համար»
  գործողությամբ (`POST /api/plugins/scan`)։
- **Շուկա** — ցուցադրում է `GET /api/plugins/marketplace`-ից ստացված կատալոգը և
  հատուկ ռեեստրի URL-ը սահմանելու դաշտ։

Յուրաքանչյուր plugin-ի կազմաձևման էջը գտնվում է `/dashboard/plugins/[name]/config`
հասցեում (`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`)։
