## Ինչ է սա

Local Corpus-ը օպերատորին թույլ է տալիս տեքստային ֆայլերի՝ հստակ հաստատված մեկ գրացուցակ հասանելի դարձնել
OmniRoute-ի MCP սերվերին։ Ֆայլերը մնում են իրենց սկզբնական գրացուցակում․ OmniRoute-ը SQLite-ում պահում է միայն
կանոնական արմատային ուղին և պահպանում է հիշողության մեջ գտնվող որոնման ինդեքս։ Այն չի
պատճենում կորպուսի բովանդակությունը շտեմարան կամ տվյալների բազա։

Ինդեքսի թարմացումն աստիճանական է։ Չփոփոխված ֆայլերը կրկին օգտագործվում են՝ հիմնվելով չափի և փոփոխման
ժամանակի վրա, փոփոխված ֆայլերը կրկին ընթերցվում և հեշավորվում են SHA-256-ով, իսկ ջնջված ֆայլերը հեռացվում են։
Որոնումը թարմացնում է 30 վայրկյանից ավելի հին ինդեքսը․ կանչողները կարող են նաև պահանջել անհապաղ
թարմացում։

## Աղբյուրի կազմաձևում

Կարգավորումների երթուղին պահանջում է կառավարման նույն նույնականացումը, ինչ կարգավորումների մյուս API-ները։
Ներկայացվող ուղին պետք է արդեն գոյություն ունենա և լինի գրացուցակի բացարձակ ուղի։

```bash
# Միացնել հաստատված գրացուցակը
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# Ստուգել կազմաձևումը և ինդեքսի կարգավիճակը
curl http://localhost:20128/api/settings/local-corpus

# Անջատել՝ առանց աղբյուրի ֆայլերը փոփոխելու
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## MCP գործիքներ

Բոլոր երեք գործիքները պահանջում են `read:local-corpus`։ Գործիքների պատասխանները բացահայտում են հարաբերական ուղիները և
արմատային գրացուցակի հիմնական անունը, բայց երբեք՝ դրա բացարձակ ուղին։

| Գործիք                | Նկարագրություն                                                                                      |
| :-------------------- | :-------------------------------------------------------------------------------------------------- |
| `local_corpus_status` | Հաղորդում է կազմաձևման վիճակը, ինդեքսի չափը, սահմանաչափերը և վերջին թարմացման ժամանակը              |
| `local_corpus_search` | Որոնում է ինդեքսավորված տեքստում և վերադարձնում տողերով սահմանափակված հատվածներ (մինչև 20 արդյունք) |
| `local_corpus_read`   | Ընթերցում է տողերի սահմանափակված տիրույթը կորպուսի մեկ թույլատրված հարաբերական ֆայլից               |

MCP մուտքային տվյալների օրինակներ․

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## Անվտանգության սահմաններ

- Թույլատրվածների ցանկը նախատեսված է տեքստային ձևաչափերի համար՝ `.cfg`, `.csv`, `.geojson`, `.htm`, `.html`, `.ini`,
  `.js`, `.json`, `.jsonl`, `.jsx`, `.log`, `.md`, `.mjs`, `.ps1`, `.py`, `.sh`,
  `.sql`, `.toml`, `.ts`, `.tsx`, `.txt`, `.xml`, `.yaml` և `.yml`։
- Խորհրդանշական հղումները բաց են թողնվում։ Ընթերցման ուղիները կանոնականացվում են և պետք է մնան
  կազմաձևված արմատի ներսում․ բացարձակ ուղիները և վերադաս գրացուցակներ անցնելու փորձերը մերժվում են։
- Զգայուն և գեներացված գրացուցակների անունները բացառվում են՝ `.build`, `.codex`, `.env`,
  `.git`, `.next`, `.omniroute`, `.ssh`, `coverage`, `dist`, `node_modules` և
  `secrets`։
- Լռելյայն սահմանաչափերն են՝ 5,000 ֆայլ, յուրաքանչյուր ֆայլի համար 1 MiB, ընդհանուր ինդեքսավորված բովանդակության համար 64 MiB,
  յուրաքանչյուր որոնման հատվածի համար մոտավորապես 4,000 նիշ և յուրաքանչյուր ընթերցման համար 400 տող։
- NUL պարունակող ֆայլերը համարվում են ոչ տեքստային և բաց են թողնվում կամ մերժվում։

Երկուական փաստաթղթերը, ինչպիսիք են PDF-ը, DOCX-ը, պատկերները և արխիվները, միտումնավոր չեն աջակցվում։
Նախքան ինդեքսավորումը դրանք փոխարկեք կազմաձևված գրացուցակում թույլատրված տեքստային ձևաչափի։

## Շահագործման նշումներ

- Կազմաձևված արմատի փոփոխումը կամ ջնջումը մաքրում է ընդհանուր՝ հիշողության մեջ գտնվող ինդեքսը։
- Գործընթացի վերագործարկումը վերացնում է ինդեքսը․ հաջորդ որոնումը վերակառուցում է այն կազմաձևված
  աղբյուրից։
- `local_corpus_status`-ը հարկադրաբար սկանավորում չի կատարում։ Երբ անհրաժեշտ է անհապաղ վերասկավառում, օգտագործեք `local_corpus_search`-ը՝
  `refresh: true`-ով։
- Սկանավորման և ընթերցման ձախողումները հաշվվում կամ վերադարձվում են որպես մաքրված սխալներ․ աղբյուրի ֆայլերը
  երբեք չեն փոփոխվում։
