> **Ճշմարտության աղբյուր՝** `src/lib/skills/` և `src/app/api/skills/`
> **Վերջին թարմացումը՝** 2026-06-28 — v3.8.40

OmniRoute-ը տրամադրում է ընդլայնելի Skills հենք, որը լեզվային մոդելներին (և օպերատորներին) թույլ է տալիս համակցել վերօգտագործելի հնարավորություններ՝ ֆայլային համակարգից ընթերցումից և HTTP հարցումներից մինչև մեկուսացված միջավայրում կոդի կատարում ու շուկայից ընտրված հմտություններ։

Հմտությունը տարբերակավորված և սխեմայով սահմանված աշխատանքի միավոր է։ OmniRoute-ը կարող է հմտությունները՝ որպես գործիքների սահմանումներ, ներարկել ելքային հարցումների մեջ, որսալ մոդելից վերադարձող գործիքների կանչերը, գործարկել համապատասխան մշակիչը և արդյունքը վերադարձնել մոդելին, որպեսզի խոսակցությունը շարունակվի։ Մոդելը երբեք չի տեսնում իրականացումը՝ միայն գործիքի միջերեսը։

## Agent Skills-ն ընդդեմ Omni Skills-ի

OmniRoute-ն ունի երկու տարբեր, սակայն միմյանց լրացնող հմտությունների համակարգեր․

| Չափանիշ              | **Omni Skills** (այս փաստաթուղթը)                                                         | **Agent Skills**                                                                                |
| :------------------- | :---------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------- |
| Նպատակ               | LLM գործիքների ներարկում + մեկուսացված կատարում                                           | SKILL.md կատալոգ՝ արտաքին գործակալների կողմից հայտնաբերման և օգտագործման համար                  |
| Ճշմարտության աղբյուր | `src/lib/skills/` + շուկա                                                                 | `src/lib/agentSkills/` + `skills/` պանակ                                                        |
| Կատարման ռեժիմ       | Ներարկվում են ելքային հարցումների մեջ, կատարվում գործիքի կանչի իրադարձությունների ժամանակ | Ստատիկ markdown կատալոգ + REST/MCP/A2A հայտնաբերման վերջնակետեր                                 |
| Ով է օգտագործում     | Ինքը՝ OmniRoute-ը (համակցված երթուղավորում, մուտքային LLM կանչեր)                         | Արտաքին գործակալներ, MCP հաճախորդներ, A2A նվագավարներ                                           |
| Քանակ                | Փոփոխական (կախված շուկայից)                                                               | 45 կատալոգային գրառում (23 API + 21 CLI + 1 կազմաձևում)                                         |
| Ձևաչափ               | `SkillDefinition`՝ գործիքի սխեմայով + մշակիչով                                            | `SKILL.md` սկզբնական մետատվյալներ + markdown բովանդակություն                                    |
| Հայտնաբերում         | `/api/skills/*` REST + `omniroute_skills_*` MCP գործիքներ                                 | `/api/agent-skills/*` REST + `omniroute_agent_skills_*` MCP գործիքներ + A2A `list-capabilities` |

**Omni Skills**-ը կատարման շարժիչն է․ դրանք սահմանում են, թե OmniRoute-ը _ինչ կարող է անել_, երբ LLM-ը կանչում է որևէ գործիք։

**Agent Skills**-ը փաստաթղթավորման կատալոգն է․ դրանք արտաքին գործակալներին բացատրում են, թե _ինչպես օգտագործել_ OmniRoute-ի REST API-ն և CLI-ն՝ կառուցվածքային SKILL.md ֆայլերի միջոցով, որոնք կարելի է անմիջապես տրամադրել գործակալների հուշումներում։

Agent Skills կատալոգի, գեներատորի, MCP գործիքների և A2A հմտության մասին տե՛ս [docs/frameworks/AGENT-SKILLS.md](./AGENT-SKILLS.md)։

## Հասկացություններ

### Հմտությունների աղբյուրներ

Հմտությունների երեք աղբյուր համատեղ գոյություն ունեն միևնույն գրանցամատյանում․

1. **Ներկառուցված հմտություններ** (`src/lib/skills/builtins.ts`) — մատակարարվում են OmniRoute-ի հետ։ Ընդգրկում են տարածված դեպքերը․
   - `file_read`, `file_write` — յուրաքանչյուր API բանալու համար առանձին մեկուսացված աշխատանքային տարածք՝ `<DATA_DIR>/skills/workspaces/<hashed-key>/` հասցեում
   - `http_request` — ելքային HTTP՝ `safeOutboundFetch`-ի միջոցով, `guard: "public-only"` պարամետրով
   - `web_search` — փոխարինելի որոնման մատակարար՝ քեշավորմամբ (`executeWebSearch`)
   - `eval_code` — Docker-ով մեկուսացված `node` կամ `python` կոդի կատարում
   - `execute_command` — Docker-ով մեկուսացված հրամանի տողի հրամանի կատարում
   - `browser` — Playwright-ի վրա հիմնված նախնական կառուցվածք, լռելյայն անջատված (`builtin/browser.ts`)
2. **SkillsMP** (OmniRoute-ի շուկան) — ստացվում է `https://skillsmp.com/api/v1/skills/search` հասցեից։ Settings-ում պահանջում է `skillsmpApiKey`։
3. **SkillsSH** (`skills.sh` համայնքային կատալոգը) — ստացվում է `https://skills.sh/api/search` հասցեից։ Նույնականացում չի պահանջվում․ SKILL.md բովանդակությունը վերցվում է GitHub raw-ից։

Մեկ «ակտիվ մատակարար» է որոշում, թե կառավարման վահանակը որ կատալոգից է տեղադրում (`src/lib/skills/providerSettings.ts`)։ Փոխեք այն **Settings → Memory & Skills** բաժնում։ Լռելյայն՝ `skillsmp`։

### Հմտության ինքնություն

Հմտությունները հիշողության մեջ գտնվող գրանցամատյանում (`src/lib/skills/registry.ts`) բանալվում են `name@version` ձևաչափով։ Տարբերակը պետք է լինի semver ձևաչափով (`^\d+\.\d+\.\d+$`)։ `resolveVersion()`-ը հասկանում է `^`, `~`, `>`, `>=`, `<`, `<=`, `==` և ճշգրիտ համընկնման սահմանափակումները։

### Հմտության ռեժիմ

Յուրաքանչյուր հմտություն ունի կատարման ռեժիմ, որը որոշում է, թե երբ է այն ներարկվում․

| Ռեժիմ  | Վարքագիծ                                                                                                                 |
| ------ | ------------------------------------------------------------------------------------------------------------------------ |
| `on`   | Միշտ ներարկվում է որպես գործիքի սահմանում                                                                                |
| `off`  | Երբեք չի ներարկվում և չի կարող կատարվել                                                                                  |
| `auto` | Գնահատվում է մուտքային հարցման համեմատ․ ներարկվում է միայն այն դեպքում, երբ գնահատականը ≥ `AUTO_MIN_SCORE` (լռելյայն՝ 3) |

`auto`-ն շուկայից տեղադրված հմտությունների լռելյայն ռեժիմն է։ `enabled=true`-ն և `mode="off"`-ը միասին նշանակում են «գրանցված, բայց ոչ ակտիվ»․ ժառանգական սյունակի միջոցով `enabled`-ի փոխարկումը նաև փոխում է `mode`-ը, որպեսզի հին կոդային ուղիները պահպանեն համատեղելիությունը (`src/app/api/skills/[id]/route.ts`)։

### Կարգավիճակ (կատարումներ)

Հմտությունների կատարումները հետևվում են `skill_executions` աղյուսակում՝ հետևյալ կարգավիճակներով (`src/lib/skills/types.ts`)․

```ts
enum SkillStatus {
  PENDING = "pending",
  RUNNING = "running",
  SUCCESS = "success",
  ERROR = "error",
  TIMEOUT = "timeout",
}
```

### Գրանցամատյանի քեշ

`SkillRegistry`-ն եզակի օրինակ է՝ 60 վայրկյան TTL քեշով (`registry.ts:14`)։ `loadFromDatabase()`-ն իդեմպոտենտ է և `pendingLoad`-ի միջոցով վերացնում է զուգահեռ կանչերի կրկնօրինակումը։ Ցանկացած գրառում (`register`/`unregister`/`unregisterById`) անվավեր է դարձնում քեշը։ Տարբերակները որոնեք `getSkillVersions(name)`-ի և `resolveVersion(name, constraint)`-ի միջոցով։

### Մատակարարին համապատասխան ներարկում

`src/lib/skills/injection.ts`-ում գտնվող `injectSkills()`-ը մուտքային կետն է, որը գրանցված հմտությունները վերածում է մատակարարին հատուկ գործիքների սահմանումների․

- **OpenAI** — `{ type: "function", function: { name, description, parameters } }`
- **Anthropic** — `{ name, description, input_schema }`
- **Google (Gemini)** — `{ name, description, parameters }`

Գործիքի անունը կոդավորվում է որպես `name@version`, որպեսզի մշակիչը կարողանա ընտրել ճիշտ տարբերակը, երբ մոդելը հետ է կանչում այն։

### AUTO գնահատում

Երբ `mode="auto"` է, յուրաքանչյուր թեկնածու հմտություն գնահատվում է հարցման համատեքստի նկատմամբ (`scoreAutoSkill()`՝ `injection.ts`-ում)․

| Ազդակ                                                            | Միավորներ                     |
| ---------------------------------------------------------------- | ----------------------------- |
| Հմտության անունը համատեքստում հանդիպում է բառացիորեն             | +6                            |
| Անվան յուրաքանչյուր թոքեն համընկնում է համատեքստի թոքենի հետ     | +2                            |

### Գործիքի կանչի ընդհատում

`src/lib/skills/interception.ts`-ում գտնվող `handleToolCallExecution()`-ը կանչվում է զրույցի մշակիչի կողմից այն բանից հետո, երբ վերին հոսքի ծառայությունը վերադարձնում է գործիք կանչող պատասխան․

1. `extractToolCalls()`-ը կարդում է մատակարարին հատուկ կառուցվածքները (OpenAI-ի `tool_calls` / Responses-ի `function_call`, Anthropic-ի `tool_use`, Gemini-ի `functionCalls`)։
2. Ներկառուցված գործիքների կեղծանունները (օրինակ՝ `omniroute_web_search` → `web_search`) նախ լուծվում են։ Ներկառուցված մշակիչները կատարվում են տեղում։
3. Մնացած ամեն ինչ ուղղորդվում է `skillExecutor.execute(name@version, args, { apiKeyId, sessionId })`-ի միջոցով։
4. Արդյունքները համապատասխան ձևով զետեղվում են պատասխանի մեջ՝ որպես `tool_results`, `function_call_output` տարրեր կամ Anthropic-ի `tool_result` բլոկներ։

Կատարման համատեքստում `customSkillExecutionEnabled`-ը կարող է սահմանվել որպես `false`՝ թույլատրելու միայն ներկառուցված ընդհատումը (օգտագործվում է հարցումների այն ուղիներում, որոնք բացահայտորեն անջատում են օգտատիրոջ կողմից սահմանված մշակիչները)։

## Docker ավազարկղ

Ներկառուցված չհանդիսացող կոդի ուղիները (`eval_code`, `execute_command`) գործարկվում են Docker-ի ներսում՝ `SandboxRunner`-ի միջոցով (`src/lib/skills/sandbox.ts`)։ Յուրաքանչյուր կոնտեյներ գործարկվում է հետևյալ պարամետրերով՝

```
--rm --network none|bridge --cap-drop ALL
--security-opt no-new-privileges --pids-limit 100
--cpus <cpuLimit/1000> --memory <memoryLimit>m
--tmpfs /tmp:rw,noexec,nosuid,size=64m
--tmpfs /workspace:rw,noexec,nosuid,size=64m
--read-only (երբ readOnly=true)
```

Լռելյայն արժեքները (`SandboxRunner.DEFAULT_CONFIG`)՝

| Դաշտ             | Լռելյայն        | Նշումներ                                                                   |
| ---------------- | --------------- | -------------------------------------------------------------------------- |
| `cpuLimit`       | 100 (= 0.1 CPU) | Բաժանվում է 1000-ի՝ նախքան `--cpus`-ին փոխանցելը                           |
| `memoryLimit`    | 256 MB          | Խիստ սահմանաչափ                                                            |
| `timeout`        | 30000 ms        | Մեղմ դադարեցում՝ `SIGTERM` + `docker kill` միջոցով                         |
| `networkEnabled` | `false`         | Փոխակերպվում է `--network none`-ի                                          |
| `readOnly`       | `true`          | Արմատային FS-ը միայն ընթերցման համար է․ `/tmp`-ը և `/workspace`-ը tmpfs են |

`SandboxRunner.kill(id)`-ը և `killAll()`-ը հասանելի են աշխատանքն ավարտելու համար․ գործարկվող կոնտեյներները հետևվում են `runningContainers: Map<string, ChildProcess>`-ում։

### Ավազարկղի միջավայրի փոփոխականներ

Կարգավորվում են `process.env`-ի միջոցով՝ `src/lib/skills/builtins.ts`-ում՝

| Միջավայրի փոփոխական               | Լռելյայն         | Նպատակ                                                                                                                               |
| --------------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `SKILLS_MAX_FILE_BYTES`           | `1048576` (1 MB) | `file_read`-ի և `file_write`-ի սահմանաչափը                                                                                           |
| `SKILLS_MAX_HTTP_RESPONSE_BYTES`  | `256000`         | `http_request`-ի պատասխանի մարմնի սահմանաչափը                                                                                        |
| `SKILLS_MAX_SANDBOX_OUTPUT_CHARS` | `100000`         | Կանչողին վերադարձվող stdout/stderr-ի սահմանաչափը                                                                                     |
| `SKILLS_SANDBOX_TIMEOUT_MS`       | `10000`          | Ավազարկղում գործարկվող հրամանների լռելյայն ժամանակի սահմանաչափը՝ առավելագույնը 60 s                                                  |
| `SKILLS_SANDBOX_NETWORK_ENABLED`  | `false`          | Ելքային կապի գլխավոր թույլատրման անջատիչը։ Սահմանեք `1` կամ `true`՝ յուրաքանչյուր կանչի համար առանձին միացումը թույլատրելու նպատակով |
| `SKILLS_ALLOWED_SANDBOX_IMAGES`   | (տե՛ս ստորև)     | Docker պատկերների՝ ստորակետերով բաժանված թույլատրված ցանկը                                                                           |

Լռելյայն թույլատրված պատկերներն են՝ `alpine:3.20`, `node:22-alpine`, `python:3.12-alpine`։ `SKILLS_ALLOWED_SANDBOX_IMAGES`-ի միջոցով ցանկացած հավելում միավորվում է լռելյայն արժեքների հետ․ անհայտ պատկերները մերժվում են `normalizeImage()`-ի կողմից։

> Նշում․ առանձին `SKILLS_EXECUTION_TIMEOUT_MS` միջավայրի փոփոխական չկա։ Ավազարկղից դուրս մշակիչի ժամանակի սահմանաչափը `SkillExecutor`-ում (`executor.ts:13`) ամրագրված է 30 s-ի վրա, սակայն գործարկման պահին կարող է վերասահմանվել `skillExecutor.setTimeout(ms)`-ի միջոցով։

### Աշխատանքային տարածքի մեկուսացում

`file_read`-ը և `file_write`-ը յուրաքանչյուր ուղի լուծում են API-ի յուրաքանչյուր բանալու համար նախատեսված աշխատանքային տարածքի նկատմամբ՝ `<DATA_DIR>/skills/workspaces/<sha256(apiKeyId).slice(0,24)>/` հասցեում։ Ուղու սահմաններից դուրս անցումը (`..`) և արգելված հատվածները (`.env`, `.git`, `.ssh`, `.omniroute`, `.codex`, `secrets`) մերժվում են՝ նախքան սկավառակի հետ մուտք/ելքի որևէ գործողություն։

### HTTP-ի պաշտպանվածության ուժեղացում

`http_request` (`builtins.ts:257`)՝

- Թույլատրված մեթոդների ցանկ՝ `GET, HEAD, POST, PUT, PATCH, DELETE`
- Արգելափակված ելքային վերնագրեր՝ `host, connection, content-length, cookie, set-cookie, authorization, proxy-authorization`
- Վերահղումներն անջատված են (`allowRedirect: false`)
- Ուղղորդվում է `safeOutboundFetch`-ի միջոցով՝ `guard: "public-only"` պարամետրով (մասնավոր/հետադարձ կապի հասցեների տիրույթներն արգելափակված են)
- Պատասխանը կրճատվում է `SKILLS_MAX_HTTP_RESPONSE_BYTES`-ի չափով․ հաճախորդը տեսնում է `truncated: true`

## Հիբրիդային կատարիչ (նախադիտում)

`src/lib/skills/hybrid.ts`-ը սահմանում է `HybridExecutor`, որը յուրաքանչյուր կանչի համար ընտրում է `direct` (նույն գործընթացի ներսում) և `sandbox` կատարումների միջև՝ timeout/հիշողության սխալների դեպքում կիրառելով `autoUpgrade`-ով կրկնափորձի ուղի։ Ներկառուցված `directExecutor` / `sandboxRunner` իրականացումները stub-եր են (`executeDirect`, `executeInSandbox` վերադարձնում են ժամանակավոր օբյեկտներ). այս մոդուլը դիտարկեք որպես մշակման փուլում գտնվող պայմանագիր։ Իրական կատարումը դեռևս իրականացվում է `skillExecutor` + `SandboxRunner`-ի միջոցով։

## REST API

Բոլոր endpoint-ները գտնվում են `src/app/api/skills/`-ի ներքո։ Կառավարման endpoint-ները (`/api/skills`, `/api/skills/[id]`, `/api/skills/install`) պահանջում են **կառավարման նույնականացում**՝ `requireManagementAuth()`-ի միջոցով։ Marketplace-ի/տեղադրման հոսքերն օգտագործում են ավելի թեթև `isAuthenticated()`-ը (session կամ API key)։

| --------------------------------- | ------ | ------------------------------------------------------------------------ | --- | ------------------------ | -------- | ------------------ |
| `/api/skills` | GET | Ցուցակագրել գրանցված skill-երը։ Աջակցում է `?q=`, `?mode=on                        | off | auto`, `?source=skillsmp | skillssh | local`, էջավորմանը |

| `/api/skills/[id]` | DELETE | Չգրանցել ըստ id-ի |
| `/api/skills/install` | POST | Տեղադրել անհատական skill (handler-ի կոդ + schema) |
| `/api/skills/marketplace` | GET | Որոնել SkillsMP կատալոգում (`q`-ն դատարկ լինելու դեպքում վերադարձնում է լռելյայն հանրաճանաչ տարբերակները) |

| `/api/skills/skillssh` | GET | Որոնել skills.sh կատալոգում (`?q=&limit=`, առավելագույնը՝ 100) |
| `/api/skills/skillssh/install` | POST | Տեղադրել skills.sh skill (պահանջում է ակտիվ provider = `skillssh`) |
| `/api/skills/executions` | GET | Էջավորված կատարման պատմություն (`?apiKeyId=`) |

`POST /api/skills/executions` endpoint-ը վերադարձնում է HTTP `503`՝ `{ error: "Skills execution is disabled..." }`-ով, երբ `settings.skillsEnabled === false` (`executor.ts:42-45`)։ Օպերատորները կարող են փոխել գլխավոր անջատիչի վիճակը **Կարգավորումներ → AI** բաժնից։

### Օրինակ. անհատական skill-ի տեղադրում

```bash
curl -X POST http://localhost:20128/api/skills/install \
  -H "Authorization: Bearer $OMNIROUTE_MGMT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "reverse-text",
    "version": "1.0.0",
    "description": "Reverses a string",
    "schema": {
      "input":  { "type": "object", "properties": { "text": { "type": "string" } }, "required": ["text"] },
      "output": { "type": "object", "properties": { "reversed": { "type": "string" } } }
    },
    "handlerCode": "echo-handler",
    "apiKeyId": "your-api-key-id"
  }'
```

`handlerCode` տողը **handler-ի անվան որոնման բանալի է**, այլ ոչ թե կատարվող կոդ։ Կատարիչն այն համադրում է `skillExecutor.registerHandler(name, fn)`-ի միջոցով (`executor.ts:25`)։ Marketplace-ից տեղադրումները SKILL.md-ի տեքստը պահում են այս դաշտում որպես փաստաթղթավորում և կատարումն ուղղորդում են մոդելի կողմից ստեղծված գործիքների կանչերի միջոցով։ Օգտատիրոջ կողմից տրամադրված կամայական սկզբնական կոդը չի փոխանցվում eval-ին։

## MCP գործիքներ

Չորս MCP գործիքներ ներառում են հմտությունների մակերեսը (`open-sse/mcp-server/tools/skillTools.ts`)։ Դրանք ավտոմատ գրանցվում են MCP սերվերի գործարկման ժամանակ։

| Գործիք                        | Նկարագրություն                                                                |
| ----------------------------- | ----------------------------------------------------------------------------- |
| `omniroute_skills_list`       | Ցուցակագրում է հմտությունները, ընտրովի զտիչներ՝ `apiKeyId`, `name`, `enabled` |
| `omniroute_skills_enable`     | Միացնում/անջատում է հմտությունը՝ ըստ `skillId`-ի                              |
| `omniroute_skills_execute`    | Կատարում է հմտությունը՝ մուտքային տվյալների բեռնվածքով                        |
| `omniroute_skills_executions` | Կատարման վերջին պատմությունը (լռելյայն՝ 50, առավելագույնը՝ 100)               |

Փոխադրման կարգավորման և շրջանակների նշանակման համար տե՛ս [MCP-SERVER.md](./MCP-SERVER.md)։

## Նոր ներկառուցված հմտության ավելացում

1. **Սահմանեք մշակիչը** `src/lib/skills/builtins.ts`-ում (կամ `src/lib/skills/builtin/`-ի տակ գտնվող հարակից ֆայլում)։ Ստորագրություն՝ `(input, { apiKeyId, sessionId }) => Promise<output>`։
2. **Մեկուսացված կոդի ուղի՞։** Կանչեք `sandboxRunner.run(image, command, env, sandboxConfig({...}))`։ Թույլատրվածների ցանկի նկատմամբ օգտագործեք `normalizeImage()`։
3. **Ֆայլային համակարգի ուղի՞։** Նախքան սկավառակին դիմելը միշտ փոխանցեք `resolveWorkspacePath(input, context)`-ով։
4. **Ցանցային կանչ՞։** Օգտագործեք `safeOutboundFetch`՝ `guard: "public-only"` պարամետրով, իսկ վերնագրերը մաքրեք `sanitizeHeaders()`-ի միջոցով։
5. **Գրանցեք**՝ գրառումն ավելացնելով `builtinSkills`-ում (կամ գործարկման ժամանակ կանչելով `registerBrowserSkill(executor)`-ի նման ֆունկցիա)։
6. **Կապակցեք ներկառուցված գործիքների այլանունները** (ըստ ցանկության) `BUILTIN_TOOL_ALIASES`-ում (`interception.ts:23`), եթե վերին հոսքի մոդելը տրամադրում է այլ անուն։
7. **Թեստերը** տեղադրեք `src/lib/skills/__tests__/`-ում (Vitest)։

## Հատուկ (ոչ ներկառուցված) հմտության ավելացում

1. Գրանցեք մշակիչը պրոցեսի գործարկման պահին․

2. Ավելացրեք հմտությունը `POST /api/skills/install`-ի միջոցով (`handlerCode` դաշտը պետք է համընկնի գրանցված մշակիչի անվան հետ)։
3. `PUT /api/skills/[id]`-ի միջոցով `mode`-ը փոխարկեք `on`-ի կամ `auto`-ի։

## Գործառնական խորհուրդներ

- **Գլխավոր անջատիչ․** `settings.skillsEnabled = false`-ն արգելափակում է բոլոր կատարումները և `/api/skills/executions`-ում վերադարձնում HTTP `503`։ Ռեեստրը շարունակում է բեռնվել։
- **Սահմանափակեք ելքային կապը․** լիովին ցանցից մեկուսացված սանդբոքսի համար `SKILLS_SANDBOX_NETWORK_ENABLED`-ը թողեք չսահմանված (լռելյայն)։ Յուրաքանչյուր կանչի `networkEnabled: true`-ը դեռևս պահանջում է գլխավոր թույլտվության միացված լինելը։
- **Թույլատրեք որոշակի պատկերներ․** թույլատրվածների ցանկն ընդլայնելու համար սահմանեք `SKILLS_ALLOWED_SANDBOX_IMAGES="myorg/sandbox:1.0,node:22-alpine"`։
- **Աուդիտի ենթարկեք կատարումները․** `/dashboard/skills/executions`-ը և `omniroute_skills_executions`-ը երկուսն էլ հարցումներ են կատարում `skill_executions`-ից։ Հաջող կատարումները ներառում են `durationMs`, իսկ ձախողումները՝ `errorMessage`։
- **Քեշի անվավերացում․** տվյալների բազայի ձեռքով խմբագրումներից հետո կանչեք `skillRegistry.invalidateCache()`, հակառակ դեպքում սպասեք 60 վ։
- **Անանուն աշխատանքային տարածք․** երբ `apiKeyId`-ը դատարկ է, բոլոր կանչերի հեշը համապատասխանում է նույն `"anonymous"` աշխատանքային տարածքին. համատեղ օգտագործումը հաշվի առնող կոդը միշտ պետք է փոխանցի իրական բանալի։

## Կատարման կենսացիկլը (v3.8.16+)

`SkillExecutor`-ը (`src/lib/skills/executor.ts`) **միակ օրինակով օբյեկտ է (singleton)**, որը կառավարում է յուրաքանչյուր հմտության կանչը։ Դրա կենսացիկլը հասկանալը կարևոր է ժամանակի սպառման, կրկնակի փորձերի և կատարման վիճակի վրիպազերծման համար։

### 5-փուլանոց կենսացիկլը

```
   execute()-ը կանչված է
        │
        ▼
  ┌─────────────┐
  │  PENDING    │  ← հերթագրված է, դեռ չի սկսվել (ստեղծվել է DB տող)
  └──────┬──────┘
         │ մշակիչի մեկնարկ
         ▼
  ┌─────────────┐
  │  RUNNING    │  ← մշակիչը կանչված է ժամանակային սահմանափակմամբ
  └──────┬──────┘
         │
    ┌────┴────┬──────────┬──────────┐
    │         │          │          │
    ▼         ▼          ▼          ▼
  SUCCESS   ERROR     TIMEOUT   (այլ ուղի չկա՝ դադարեցվել է ծնող գործընթացի կողմից)
    │         │          │
    └────┬────┴──────────┘
         │
         ▼
   DB տողը թարմացվում է՝ ներառելով վիճակը, ելքը և durationMs-ը
```

### Լռելյայն կազմաձևումը

| Կարգավորում  | Լռելյայն      | Կազմաձևվում է հետևյալի միջոցով       |
| ------------ | ------------- | ------------------------------------ |
| `timeout`    | `30000` (30վ) | `skillExecutor.setTimeout(ms)`       |
| `maxRetries` | `3`           | `skillExecutor.setMaxRetries(count)` |

> **Կարևոր է**․ կատարիչը միակ օրինակով օբյեկտ է (singleton), ուստի `setTimeout()`-ի կանչը գլոբալ կերպով ազդում է բոլոր հաջորդ կանչերի վրա։ Յուրաքանչյուր հմտության համար առանձին ժամանակային սահմանափակումներ ներկայումս չեն աջակցվում․ եթե տարբեր հմտությունների համար տարբեր ժամանակային սահմանափակումներ են անհրաժեշտ, գործարկեք առանձին գործընթացներ կամ պատառաքաղեք կատարիչը։

### Վիճակի արժեքները

`src/lib/skills/types.ts`-ից․

```ts
enum SkillStatus {
  PENDING = "pending", // Հերթագրված է, դեռ չի սկսվել
  RUNNING = "running", // Մշակիչը կանչված է
  SUCCESS = "success", // Մշակիչը վերադարձրել է վավեր ելք
  ERROR = "error", // Մշակիչը բացառություն է նետել
  TIMEOUT = "timeout", // Գերազանցվել է կատարիչի ժամանակային սահմանափակումը
}
```

> **Նշում**․ `TIMEOUT` վիճակը սահմանված է թվարկման մեջ, սակայն կատարիչի ընթացիկ իրականացմամբ այն **փաստացի չի գրվում DB-ում**․ ժամանակի սպառումը ներկայացվում է որպես `ERROR`՝ `"Skill execution timed out"` հաղորդագրությամբ։ Վիճակի այս արժեքը պահված է ապագա օգտագործման համար։

### Կատարումների դիտարկումը

```ts
import { skillExecutor } from "omniroute/skills/executor";

// Ստանալ կոնկրետ կատարում՝ ըստ ID-ի
const exec = skillExecutor.getExecution("exec-uuid-123");
if (exec) {
  console.log(`${exec.skillName}: ${exec.status} in ${exec.durationMs}ms`);
}

// Ցուցակել API բանալու վերջին կատարումները
const recent = skillExecutor.listExecutions("api-key-id", 50, 0);
for (const e of recent) {
  console.log(`${e.skillName} → ${e.status} (${e.durationMs}ms)`);
}

// Հաշվել կատարումների ընդհանուր քանակը
const total = skillExecutor.countExecutions("api-key-id");
```

### Կրկնակի փորձերի վարքագիծը

`maxRetries` կարգավորումը պահպանվում է, սակայն կատարիչի `execute()` մեթոդը **ներկայումս այն չի օգտագործում**․ այն կատարում է միայն մեկ փորձ։ `maxRetries` արժեքը հասանելի է ապագա իրականացման և այն կեռիկների համար, որոնք ցանկանում են կարդալ այն։

Առայժմ կրկնակի փորձերը պետք է իրականացվեն հենց հմտության մշակիչի ներսում։ Ներկառուցված
հմտությունները գրանցվում են կատարիչում (օրինակ՝ `registerBuiltinSkills(executor)`
/ `registerBrowserSkill(executor)`՝ `src/lib/skills/builtin/`-ում)․ ձեր գրանցած ցանկացած մշակիչ
կարող է ներառել կրկնակի փորձերի սեփական ցիկլը․

```ts
// հմտության մշակիչի ներսում
async function handler(input, ctx) {
  const maxRetries = 3;
  let lastError: Error | null = null;

  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      return await fetchSomething(input);
    } catch (err) {
      lastError = err as Error;
      if (attempt < maxRetries) {
        await new Promise((r) => setTimeout(r, 1000 * attempt));
      }
    }
  }
  throw lastError;
}
```

## SkillMode-ը մանրամասն

`SkillMode` թվարկումը (`src/lib/skills/types.ts`) վերահսկում է, թե **երբ և ինչպես** են հմտությունները կանչվում․

```ts
enum SkillMode {
  AUTO = "auto", // LLM-ը որոշում է՝ երբ կանչել հմտությունը
  MANUAL = "manual", // Կանչվում է միայն օգտատիրոջ բացահայտ հարցմամբ
  HYBRID = "hybrid", // AUTO գնահատում + ձեռքով գերակայում
}
```

> **Նշում**․ կոդային բազան սահմանում է `SkillMode`-ը (AUTO/MANUAL/HYBRID), մինչդեռ `Skill.mode` դաշտն օգտագործում է այլ ձևաչափ (`"on" | "off" | "auto"`)։ Դրանք փոխկապակցված են, բայց նույնական չեն․ `SkillMode`-ը կատարողի քաղաքականության համար է, իսկ `Skill.mode`-ը՝ առանձին հմտության միացման կամ անջատման համար։

### Երբ օգտագործել յուրաքանչյուր ռեժիմը

| Ռեժիմ    | LLM-ի վարքագիծ                                                                             | Օգտագործման դեպք                                                          |
| -------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| `AUTO`   | LLM-ը կարող է կանչել հմտությունը, երբ դա անհրաժեշտ է համարում                              | Ընդհանուր նշանակության հմտություններ (ֆայլերի ընթերցում, HTTP հարցումներ) |
| `MANUAL` | LLM-ը չի կարող կանչել հմտությունը․ այն կանչվում է միայն բացահայտ `executeSkill` API կանչով | Զգայուն գործողություններ (տվյալների բազայում գրանցումներ, վճարումներ)     |
| `HYBRID` | LLM-ը կարող է առաջարկել հմտությունը, սակայն օգտատերը պետք է հաստատի                        | Կողմնակի ազդեցություններ ունեցող, բայց ոչ վտանգավոր հմտություններ         |

### AUTO գնահատում

Երբ `AUTO` ռեժիմն ակտիվ է, յուրաքանչյուր թեկնածու հմտություն գնահատվում է հարցման
համատեքստի նկատմամբ՝ `src/lib/skills/injection.ts`-ում գտնվող `scoreAutoSkill()`-ի միջոցով՝ գումարային,
ամբողջաթիվ միավորների համակարգով (հմտության անվան համապատասխանություն, անվան/պիտակի/նկարագրության թոքենների համընկնում,
ֆոնային պատճառների հուշումներ, մատակարարի հուշման բոնուս/տուգանք)։ Ամենաբարձր գնահատական ունեցող
`AUTO_MAX_SKILLS = 5` հմտությունները, որոնց `score >= AUTO_MIN_SCORE = 3`, ներարկվում են որպես
կանչվող գործիքներ, իսկ հավասարության դեպքում առաջնահերթությունը որոշվում է նախ `installCount`-ով, ապա՝ անունով։ Ամբողջական միավորների աղյուսակը տե՛ս այս
փաստաթղթում ավելի վաղ գտնվող [**Գործիքի սխեմայի ստեղծում → AUTO գնահատում**](#auto-scoring)
բաժնում․ այստեղ չկա `0.6`-ի նման տասնորդական շեմ և չկա `registry.ts` գնահատում։

## Ներկառուցված հմտությունների կատալոգ

OmniRoute-ը տրամադրվում է `src/lib/skills/builtin/`-ում գտնվող՝ խնամքով ընտրված ներկառուցված հմտությունների հավաքածուով։ Ամենատարածվածները՝

### Բրաուզերի ավտոմատացման հմտություն

Բրաուզերի հմտությունը (`src/lib/skills/builtin/browser.ts`) ապահովում է առանց գրաֆիկական միջերեսի բրաուզերի ավտոմատացում Playwright/Puppeteer-ի միջոցով։ **Այն իրականացված է, սակայն ներառված չէ հմտությունների լռելյայն կատալոգում**․ այն օգտագործելու համար առանձին տեղադրեք բրաուզերի ընդլայնման պլագինը։

```ts
// Միացրեք ձեր կազմաձևում
const config: SkillConfig = {
  enabled: true,
  mode: SkillMode.MANUAL, // Միշտ պահանջել բացահայտ կանչ
  allowedSkills: ["browser"],
  timeout: 60000, // 60 վրկ․ էջերի բեռնման համար
  maxRetries: 1,
};
```

### Այլ ներկառուցված կատեգորիաներ

| Կատեգորիա     | Հմտություններ                                | Ռեժիմ  |
| ------------- | -------------------------------------------- | ------ |
| Ֆայլային I/O  | `file_read`, `file_write`                    | AUTO   |
| HTTP          | `http_request`                               | AUTO   |
| Որոնում       | `web_search`                                 | AUTO   |
| Կոդի կատարում | `eval_code` (մեկուսացված JavaScript/Python)  | HYBRID |
| Համակարգ      | `execute_command` (մեկուսացված CLI կատարում) | MANUAL |

### Հատուկ հմտության ավելացում

Պլագինների համակարգի միջոցով հատուկ հմտություն ավելացնելու եղանակը տե՛ս [Plugin SDK-ի և հմտությունների ինտեգրում](./PLUGIN_SDK.md) բաժնում։
