OmniRoute-ը տրամադրում է գործակալների հետ կապված երեք տարբեր միջերես։ Առաջին հայացքից դրանք նման են, սակայն լուծում են տարբեր խնդիրներ։ Օգտագործեք այս էջը՝ ճիշտ տարբերակն ընտրելու համար։

## Համառոտ

| Միջերես                                 | Առավել հարմար է                                                                                                                                               | Փոխանցման եղանակ                        | Ստանդարտ                 |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- | ------------------------ |
| **A2A — գործակալից գործակալ**           | A2A արձանագրությամբ հաղորդակցվող գործընկեր գործակալների միջև համագործակցության համար                                                                          | JSON-RPC 2.0՝ HTTP-ի միջոցով            | A2A v0.3 (բաց մասնագիր)  |

| **Ամպային գործակալներ**                 | Երկարատև կոդավորման առաջադրանքներն արտաքին ամպային ծառայություններին (Codex Cloud, Devin, Jules, Cursor Cloud) ուղարկելու համար                               | HTTP REST + ՏԲ-ում պահվող առաջադրանքներ | Հատուկ OmniRoute-ի համար |

Այս երեքը միմյանցից անկախ են. ընտրեք դրանցից ցանկացած ենթաբազմություն։

## Որոշումների ծառ

```
Արդյո՞ք անհրաժեշտ է, որ ամպային ծառայությունն աշխատանք կատարի այս համակարգչից դուրս (Codex Cloud / Cursor Cloud / Devin / Jules)։
├─ ԱՅՈ → Ամպային գործակալներ (POST /api/v1/agents/tasks)
└─ ՈՉ → Շարունակեք
    │
    Ունե՞ք գործընկեր գործակալ, որը հաղորդակցվում է A2A արձանագրությամբ և ցանկանում է համագործակցել։
    ├─ ԱՅՈ → A2A (POST /a2a)
    └─ ՈՉ → Շարունակեք
        │
        Անհրաժե՞շտ է ցուցակագրել / կազմաձևել տեղային համակարգում տեղադրված CLI կոդավորման գործակալները։
        ├─ ԱՅՈ → ACP (GET /api/acp/agents)
        └─ ՈՉ → Օգտագործեք սովորական /v1/chat/completions
```

## 1. A2A — գործակալից գործակալ

**Մասնագիր՝** [A2A v0.3](https://a2a-protocol.org)
**OmniRoute-ի վերջնակետ՝** `POST /a2a` (JSON-RPC 2.0)
**Գործակալի քարտ՝** `GET /.well-known/agent.json`

### Երբ օգտագործել

- Բազմագործակալ համակարգ կառուցելիս, որտեղ OmniRoute-ը գործընկերներից մեկն է
- OmniRoute-ի երթուղավորման հնարավորությունները (խելացի երթուղավորում, քվոտաների կառավարում և այլն) Google ADK-ի նման հենքերում կամ ընդհանուր գործակալային ցանցերում գործող գործակալներին հասանելի դարձնելու համար
- OmniRoute-ը ստանդարտ հայտնաբերման և կանչման միջերեսով պարուրելու համար

### Մեթոդներ

- `message/send` — ուղարկել հաղորդագրություն և ստանալ համաժամանակյա պատասխան
- `message/stream` — ուղարկել հաղորդագրություն և ստանալ SSE-ով հոսքային առաջընթացի իրադարձություններ
- `tasks/get` — կարդալ առաջադրանքն ըստ ID-ի
- `tasks/cancel` — չեղարկել ընթացիկ առաջադրանքը

### Ներկառուցված հմտություններ (6)

- `smart-routing` — ուղղորդել հուշումն օպտիմալ համակցությամբ
- `quota-management` — հաղորդել յուրաքանչյուր մատակարարի քվոտայի վիճակը
- `provider-discovery` — ցուցակագրել տեղադրված մատակարարները՝ իրենց հնարավորություններով
- `cost-analysis` — գնահատել հարցման/զրույցի արժեքը
- `health-report` — ամփոփել յուրաքանչյուր մատակարարի խափանման անջատիչի/սպասման ժամանակահատվածի/արգելափակման վիճակը
- `list-capabilities` — թվարկել գործակալի հասանելի հմտություններն ու մետատվյալները

### Մանրամասն նկարագրություն

Փոխանցման մանրամասների, գործակալի քարտի կառուցվածքի, առաջադրանքների TTL-ի կազմաձևման և նոր հմտություններ ավելացնելու ձևանմուշի համար տե՛ս [A2A-SERVER.md](./A2A-SERVER.md)։

## 2. ACP — CLI գործակալների ռեեստր

**OmniRoute վերջնակետ:** `GET /api/acp/agents`
**Աղբյուր:** `src/lib/acp/{index,manager,registry}.ts`

### Ինչ է սա

ACP-ն OmniRoute-ի **տեղային CLI գործակալների գույքացուցակն** է։ Այն հայտնաբերում է, թե ծրագրավորման որ CLI-ներն են տեղադրված հոսթում (Cursor, Cline, Claude Code, Codex CLI, Continue և այլն), որոշում է դրանց տարբերակները և դրանք ներկայացնում կառավարման վահանակում, որպեսզի օգտատերը կարողանա յուրաքանչյուր CLI կարգավորել այնպես, որ այն ուղղվի դեպի OmniRoute։

Սա արտաքին արձանագրություն ՉԷ․ սա ներքին ռեեստր է, որն ապահովում է «CLI գործիքներ» օգտատիրոջ միջերեսի և CLI մատնահետքերի հետագծման աշխատանքը (տե՛ս [CLI-TOOLS.md](../reference/CLI-TOOLS.md))։

### Ինչ է այն անում

- Ստուգում է հոսթը՝ տեղադրված CLI երկուական ֆայլերը հայտնաբերելու համար (ըստ ՕՀ-ի օգտագործում է `which` / `where`)
- Կարդում է յուրաքանչյուր CLI-ի տարբերակը (կանչում է `<bin> --version`)
- Ընտրովի ընդունում է օգտատիրոջ սահմանած հատուկ գործակալներ (երկուական ֆայլի ուղի + տարբերակի ստուգման հրաման + գործարկման արգումենտներ)
- Հատուկ գործակալները պահպանում է կարգավորումներում
- Կառավարման վահանակին վերադարձնում է միասնական ցանկը

### REST API

| Վերջնակետ         | Մեթոդ | Նկարագրություն                                                                    | Նույնականացում |
| ----------------- | ----- | --------------------------------------------------------------------------------- | -------------- |
| `/api/acp/agents` | GET   | Հայտնաբերված + հատուկ գործակալների ցանկը (տեղադրված/ընդհանուր քանակներ)           | API բանալի     |
| `/api/acp/agents` | POST  | Հատուկ գործակալի ավելացում/թարմացում/հեռացում (գործողության տարբերակիչը մարմնում) | API բանալի     |

POST-ի մարմնի կառուցվածքը (`customAgentBodySchema`՝ `src/app/api/acp/agents/route.ts`-ում)․

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Օգտագործման դեպքեր

- Կառավարման վահանակի «CLI գործիքներ» էջը ցուցադրում է, թե ինչ է տեղադրված, և օգնում է յուրաքանչյուր գործիք ուղղել դեպի OmniRoute
- Հատուկ գործակալները փորձառու օգտատերերին թույլ են տալիս գրանցել ներքին/սեփականատիրական CLI-ներ, որոնց OmniRoute-ը լռելյայն չի ճանաչում
- Հայտնաբերման արդյունքը լրացնում է `cli-tools` մատնահետքերի մատրիցը

### Երբ ACP-ն ՉՕԳՏԱԳՈՐԾԵԼ

- ACP-ն առաջադրանքներ չի _գործարկում_։ Այն միայն հայտնաբերում և կարգավորում է CLI-ները։ CLI-ն փաստացի կանչելու համար այն ինքներդ եք գործարկում՝ OmniRoute-ի տրամադրած միջավայրի փոփոխականներով (`OPENAI_BASE_URL`, `OPENAI_API_KEY` և այլն)։

## 3. Ամպային գործակալներ

**OmniRoute վերջնակետեր:** `/api/v1/agents/tasks/*` (կենսացիկլ) + `/api/cloud/*` (ենթակառուցվածքային կապակցում)
**Աղբյուր:** `src/lib/cloudAgent/`

### Ինչ է սա

Երրորդ կողմի ամպային ծրագրավորման գործակալների համար միասնական միջերես։ Դուք ուղարկում եք հուշում + ռեպոզիտորիայի URL, OmniRoute-ն այն փոխանցում է համապատասխան ամպային գործակալին, պարբերաբար ստուգում է կարգավիճակը և վերադարձնում արդյունքները։

### Աջակցվող գործակալներ (4, բոլորը հաստատված են `src/lib/cloudAgent/agents/`-ում)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### Կենսացիկլ

```
POST /api/v1/agents/tasks
  → BaseAgent.createTask()՝ ըստ գործակալի դասի
  → արտաքին ծառայությունն սկսում է աշխատանքը
  → ՏԲ-ում ստեղծվում է առաջադրանքի տող (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → մատակարարից կարգավիճակի հետաձգված համաժամացում
  → վերադարձնում է ընթացիկ կարգավիճակը + պլանը + գործունեության մատյանը
  ↓
POST /api/v1/agents/tasks/[id]   (գործողություն՝ "approve" | "message" | "cancel")
  → փոխանցում է մատակարարին (կամ տեղային մակարդակում նշում որպես չեղարկված)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → տեղային չեղարկում
```

### Նույնականացում

⚠️ **Բոլոր `/api/v1/agents/tasks/*` վերջնակետերը պահանջում են կառավարման նույնականացում** (`588a0333` կոմիթ)։ Միայն Bearer օգտագործող կանչողները v3.8.0-ից սկսած ստանում են 401։

### Մանրամասն ուսումնասիրություն

`CloudAgentBase` պայմանագրի, յուրաքանչյուր գործակալի առանձնահատկությունների, սխեմայի մանրամասների և հավատարմագրերի կապակցման վերջնակետերի մասին տե՛ս [CLOUD_AGENT.md](./CLOUD_AGENT.md)։

## Համեմատություն՝ A2A-ն ընդդեմ Cloud Agents-ի

Երկուսն էլ ունեն «երկարատև առաջադրանքներ», սակայն տարբեր շերտերում․

| Բնութագիր                      | A2A                                                                                            | Cloud Agents                                             |
| ------------------------------ | ---------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| Ստանդարտ                       | Բաց A2A v0.3                                                                                   | Հատուկ OmniRoute-ի համար                                 |
| Որտեղ են կատարվում հաշվարկները | OmniRoute-ի ներսում (օգտագործում է կազմաձևված համակցությունները)                               | Արտաքին միջավայրում (Codex / Devin / Jules սերվերներում) |
| Առաջադրանքի տևողություն        | Լռելյայն TTL-ը՝ 5 րոպե (կազմաձևելի է `TaskManager`-ում)                                        | Մի քանի րոպեից մինչև մի քանի ժամ                         |
| Շտեմարանին իրազեկ              | Ոչ (փոխանցում է միայն հուշումները)                                                             | Այո (շտեմարանի URL + ճյուղ)                              |
| Օգտագործման դեպք               | Գործակալների միջև համագործակցություն, խելացի ուղղորդումը՝ որպես ծառայություն                   | Պատվիրակել «իրականացնել X գործառույթը Y շտեմարանում»     |
| Նույնականացում                 | Ընտրովի `OMNIROUTE_API_KEY`՝ `/a2a`-ի համար, կառավարում՝ `/api/a2a/*` REST օժանդակիչների համար | Միշտ կառավարում                                          |

## Ինտեգրման օրինակներ

### Բացահայտել OmniRoute-ի A2A հնարավորությունները

```bash
curl http://localhost:20128/.well-known/agent.json
```

Վերադարձնում է Agent Card-ը՝ բոլոր 6 հմտություններով, փոխադրամիջոցներով և տարբերակով։

### Կանչել OmniRoute-ը որպես A2A գործակալ

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### ACP-ի միջոցով ցուցակագրել տեղադրված CLI գործակալները

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Ավելացնել հատուկ CLI գործակալ

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### Ուղարկել Cloud Agent-ի առաջադրանք

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### Պարբերաբար ստուգել ամպային առաջադրանքի կարգավիճակը

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## Ինչը երբ օգտագործել

- **Չաթբոտի / copilot-ի ճակատային մաս** → `/v1/chat/completions` (OpenAI-ի հետ համատեղելի է, սակայն գործակալային արձանագրություն չէ)
- **Բազմագործակալային համագործակցություն** → A2A
- **Տեղային CLI-ների ցուցակագրում կառավարման վահանակում** → ACP
- **Երկարատև ծրագրավորման առաջադրանքների պատվիրակում ամպային ծառայություններին** → Cloud Agents
