> և հասանելիության տիրույթների կապակցումը գտնվում են `open-sse/mcp-server/server.ts`-ում։

## Ինչ է սա

OmniRoute-ը միանում է **Obsidian** պահոցին՝ որպես **համատեքստի աղբյուր**՝ տեղային Markdown
գիտելիքների բազա, որը գործակալները կարդում և փոփոխում են ներկառուցված MCP սերվերի միջոցով։
Ինտեգրումը հաղորդակցվում է աշխատասեղանի հավելվածի ներսում աշխատող համայնքային
**Obsidian Local REST API** հավելման հետ, այնպես որ գործակալները կարող են որոնել նշումներ,
կարդալ/գրել/մասնակիորեն փոփոխել ֆայլեր, ցուցակել պահոցի պարունակությունը, աշխատել օրական/շաբաթական
պարբերական նշումների հետ, կառավարել պիտակները, գործարկել Obsidian հրամաններ և (ըստ ցանկության)
համակարգել աշխատասեղան↔բջջային սարք պահոցի երկկողմ համաժամացումը։

Հաճախորդը (`src/lib/obsidian/api.ts`) Local REST API-ն համալրում է հետևյալով՝

- **Կրկնափորձ՝ աճող դադարով**՝ ժամանակավոր `5xx` սխալների դեպքում, **30 վայրկյանանոց ժամանակի սահմանափակում**՝ `AbortController`-ի միջոցով։
- **Տիպավորված սխալների դասակարգում**՝ `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`։
- **«Չի հաջողվում կապ հաստատել Obsidian-ի հետ» հասկանալի հուշում**, որը նշում է պորտի տարածված
  սխալը (HTTP-ը՝ `27123`-ում, **ոչ թե** MCP վերջնակետը՝ `27124`-ում) և Tailscale ձևաչափը։
- Պահոցի նկատմամբ հարաբերական **ուղիների կոդավորում**, որպեսզի բացատներ/շեղագծեր պարունակող նշումների ուղիներն անվտանգ լինեն։

## Կարգավորում

Obsidian-ի թոքենի կամ բազային URL-ի համար **միջավայրի փոփոխական չկա**․ երկուսն էլ
պահվում են SQLite-ի `key_value` աղյուսակում (`obsidian` անվանատարածք)՝
`src/lib/db/obsidian.ts`-ի միջոցով։ Թոքենը **գաղտնագրված է պահպանման վիճակում** (AES-256-GCM՝
բաց տեքստով հետադարձ համատեղելիության պահուստային տարբերակով)։ Կարգավորեք Endpoint վահանակի
**Context Sources** ներդիրից (`ObsidianSourceCard`) կամ կարգավորումների REST API-ի միջոցով։

> [!IMPORTANT]
> **Obsidian Local REST API** հավելումը պետք է տեղադրված և աշխատող լինի։ Դրա REST
> միջերեսը լսում է **HTTP `127.0.0.1:27123`** հասցեում (կանխադրված բազային URL-ը)։ `27124`
> պորտը _առանձին_ MCP/HTTPS վերջնակետ է և կարգավորումների երթուղու կողմից հստակ մերժվում է։
> Այլ սարքից միանալու դեպքում օգտագործեք `http://<tailscale-ip>:27123`։

### Կարգավորման բանալիներ (SQLite `key_value`, `obsidian` անվանատարածք)

| Բանալի            | Նպատակ                                                    | Գաղտնագրված |
| ----------------- | --------------------------------------------------------- | ----------- |
| `api_key`         | Local REST API-ի bearer թոքեն                             | այո         |
| `base_url`        | REST-ի բազային URL (կանխադրված՝ `http://127.0.0.1:27123`) | ոչ          |
| `vault_path`      | Պահոցի գրացուցակի բացարձակ ուղի (համաժամացման համար)      | ոչ          |
| `webdav_username` | Ստեղծված WebDAV օգտանուն (պահոցի համաժամացում)            | ոչ          |
| `webdav_password` | Ստեղծված WebDAV գաղտնաբառ (պահոցի համաժամացում)           | այո         |
| `webdav_enabled`  | Արդյոք WebDAV պահոցի համաժամացումը միացված է              | ոչ          |

### Կարգավորում REST-ի միջոցով

```bash
# Պահել և վավերացնել Local REST API-ի թոքենը (POST-ը վավերացնում է կարգավիճակի ստուգման միջոցով)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Ստուգել կապի կարգավիճակը (վերադարձնում է connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# Անջատել կապը (ջնջում է պահված թոքենը)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Բոլոր մեթոդները պահանջում են վահանակի նույնականացում։ `POST`-ը մերժում է `27124`
պորտն օգտագործող ցանկացած URL և, նախքան պահպանումը, վավերացնում է թոքենը՝ կանչելով Local REST API-ի կարգավիճակի վերջնակետը։

### WebDAV պահոցի համաժամացում

`src/app/api/settings/obsidian/webdav/route.ts`-ը կառավարում է WebDAV-ի վրա հիմնված
պահոցի կամընտիր համաժամացումը (իրականացվում է `src/lib/obsidianSync.ts`-ի միջոցով)։ Այն միացնելիս
OmniRoute-ին տրվում է տեղային պահոցի գրացուցակը, և ստեղծվում է պատահական WebDAV օգտանուն/գաղտնաբառ զույգ՝

```bash
# Միացնել WebDAV համաժամացումը պահոցի գրացուցակի համար (ստեղծում է օգտանուն/գաղտնաբառ)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# Ստանալ WebDAV համաժամացման կարգավիճակը (մուտքանունային տվյալները վերադարձվում են միայն միացված լինելու դեպքում)
curl http://localhost:20128/api/settings/obsidian/webdav

# Անջատել WebDAV համաժամացումը (ջնջում է մուտքանունային տվյալները և կառավարվող .stignore-ը)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Յուրաքանչյուր API բանալու համար առանձին համատեքստի աղբյուր (ըստ ցանկության)

Obsidian-ի կարգավորումը կարող է սահմանափակվել **յուրաքանչյուր API բանալու համար**՝
`api_key_context_sources` աղյուսակի միջոցով (`src/lib/db/apiKeyContextSources.ts`)։ Երբ MCP կանչը
պարունակում է նույնականացված API բանալու id, `getObsidianConfigForApiKey()`-ը նախընտրում է տվյալ
բանալու սեփական թոքենը/բազային URL-ը/պահոցի ուղին (`source: "api_key"`), իսկ դրանց բացակայության դեպքում
օգտագործում է գլոբալ կարգավորումը (`source: "global"`)։

## MCP գործիքներ (22)

Սահմանված են `open-sse/mcp-server/tools/obsidianTools.ts`-ում։ Թոքենը/բազային URL-ը որոշվում են
յուրաքանչյուր կանչի համար (նախ՝ ըստ API բանալու, ապա՝ գլոբալ)։ OmniRoute-ի **համաժամացման սերվերին**
դիմող գործիքները (`obsidian_sync_*` չորս գործիքները) լրացուցիչ պահանջում են OmniRoute-ի
կարգավորումներում սահմանված համաժամացման նույնականացման թոքենը։

### Ընթերցման գործիքներ (`read:obsidian`)

| Գործիք                       | Նկարագրություն                                                                                                |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Ստուգել՝ արդյոք Local REST API-ն հասանելի է և նույնականացված։                                                 |
| `obsidian_search_simple`     | Նշումների բովանդակության լիատեքստ որոնում․ վերադարձնում է հատվածներ՝ ֆայլերի ուղիներով։                       |
| `obsidian_search_structured` | Որոնել JSON Logic արտահայտության միջոցով (and/or/regex/path զտիչներ)։                                         |
| `obsidian_read_note`         | Կարդալ նշումը պահոցին հարաբերական ուղով՝ ըստ ցանկության սահմանելով վերնագիր/բլոկ/frontmatter։                 |
| `obsidian_list_vault`        | Թվարկել պահոցի ֆայլերն ու պանակները (տարրերի ծառ)։                                                            |
| `obsidian_get_document_map`  | Ստանալ նշման վերնագրերի կառուցվածքը՝ որպես վերնագրեր → տողերի համարներ քարտեզ։                                |
| `obsidian_get_note_metadata` | Ստանալ frontmatter-ը, պիտակները, հղումները, նիշերի/բառերի քանակը՝ առանց ամբողջական բովանդակության։            |
| `obsidian_get_active_file`   | Ստանալ Obsidian-ում տվյալ պահին ակտիվ ֆայլի ուղին և բովանդակությունը։                                         |
| `obsidian_get_periodic_note` | Ստանալ տվյալ ամսաթվի ամենօրյա/շաբաթական/ամսական պարբերական նշումը (եթե բաց է թողնված՝ այսօրվանը)։             |
| `obsidian_get_tags`          | Թվարկել պահոցի բոլոր պիտակներն իրենց հաճախականություններով։                                                   |
| `obsidian_list_commands`     | Թվարկել Obsidian-ի հասանելի հրամանների ID-ները (`obsidian_execute_command`-ի հետ օգտագործելու համար)։         |
| `obsidian_sync_status`       | OmniRoute համաժամացման սերվերի կարգավիճակը՝ աշխատանք, պահոցի անուն, պորտ, աշխատաժամանակ, վերջին համաժամացում։ |
| `obsidian_sync_conflicts`    | Թվարկել համաժամացման չլուծված հակասությունները (ուղի, հակասության ուղի, հայտնաբերման ժամանակ)։                |

### Գրման գործիքներ (`write:obsidian`)

| Գործիք                           | Նկարագրություն                                                                                          |
| -------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Ստեղծել կամ վերագրել նշումը տրված Markdown բովանդակությամբ։                                             |
| `obsidian_append_note`           | Բովանդակություն ավելացնել նշմանը՝ ըստ ցանկության կոնկրետ վերնագրում/բլոկում։                            |
| `obsidian_patch_note`            | Ճշգրտորեն ավելացնել վերջում/սկզբում կամ փոխարինել վերնագրում, բլոկում կամ frontmatter դաշտում։          |
| `obsidian_delete_note`           | Ընդմիշտ ջնջել նշումը պահոցից։                                                                           |
| `obsidian_move_note`             | Տեղափոխել կամ վերանվանել նշումը պահոցի ներսում։                                                         |
| `obsidian_execute_command`       | Կատարել Obsidian հրաման՝ ըստ դրա հրամանի ID-ի։                                                          |
| `obsidian_open_file`             | Բացել ֆայլը Obsidian-ում (ստեղծում է այն, եթե գոյություն չունի)։                                        |
| `obsidian_sync_trigger`          | Անմիջապես գործարկել աշխատասեղան↔բջջային սարք պահոցի երկկողմանի համաժամացումը։                           |
| `obsidian_sync_resolve_conflict` | Լուծել համաժամացման հակասությունը՝ պահել `local` (բջջային), `remote` (աշխատասեղանային) կամ `keep-both`։ |

> [!NOTE]
> `obsidian_patch_note`-ի թիրախներն ընդունում են `heading | block | frontmatter`
> `targetType` և `append | prepend | replace` `operation`՝ ըստ ցանկության
> `createTargetIfMissing`-ով։ `obsidian_sync_*` չորս գործիքները հաղորդակցվում են տեղային համաժամացման
> սերվերի հետ (լռելյայն՝ `http://127.0.0.1:27781`) և պահանջում են համաժամացման թոքենը։

### Թույլտվությունների շրջանակներ

Ընթերցման գործիքները պահանջում են `read:obsidian`, իսկ գրման գործիքները՝ `write:obsidian`։ Կիրառումը
նույնական է Notion-ին՝ իրականացվում է `withScopeEnforcement()`-ի միջոցով՝
`open-sse/mcp-server/server.ts`-ում, ակտիվացվում է `OMNIROUTE_MCP_ENFORCE_SCOPES=true`-ով, իսկ
թույլատրված շրջանակները վերցվում են `OMNIROUTE_MCP_SCOPES`-ից կամ API բանալու շրջանակի համատեքստից։ Տե՛ս
[MCP-SERVER.md](./MCP-SERVER.md)։

## Վերջնակետեր

| Մեթոդ    | Ուղի                            | Նպատակ                                                            |
| -------- | ------------------------------- | ----------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | Վերադարձնել `{ connected, hasToken, baseUrl, vaultPath }`։        |
| `POST`   | `/api/settings/obsidian`        | Պահպանել և վավերացնել թոքենը (մերժում է `27124` պորտը)։           |
| `DELETE` | `/api/settings/obsidian`        | Անջատել կապը (մաքրել պահպանված թոքենը)։                           |
| `GET`    | `/api/settings/obsidian/webdav` | WebDAV համաժամացման վիճակը և հավատարմագրերը (քանի դեռ միացված է)։ |
| `POST`   | `/api/settings/obsidian/webdav` | Միացնել WebDAV համաժամացումը պահոցի պանակի համար։                 |
| `DELETE` | `/api/settings/obsidian/webdav` | Անջատել WebDAV համաժամացումը։                                     |

> Սրանք կառավարման վահանակի կարգավորումների երթուղիներն են։ Պահոցն ինքնին հասանելի է Obsidian
> Local REST API-ի (կարգավորված `base_url`-ի) և վերոնշյալ MCP գործիքների միջոցով․
> Obsidian-ի հանրային `/v1` պրոքսի վերջնակետ գոյություն չունի։

## Օգտագործման դեպքեր

- **Պահոցի վրա հիմնված պատասխաններ** — `obsidian_search_simple` / `obsidian_search_structured`,
  ապա՝ `obsidian_read_note`, որպեսզի գործակալը պատասխանի ձեր իրական նշումների հիման վրա։
- **Նշումների ստեղծում / օրագրի վարում** — `obsidian_write_note`, `obsidian_append_note` կամ
  ճշգրիտ `obsidian_patch_note`՝ գործակալի ելքը, ամփոփագրերը կամ ամենօրյա նշումները
  (`obsidian_get_periodic_note`) պահոցում գրանցելու համար։
- **Նավարկում պահոցում** — `obsidian_list_vault`, `obsidian_get_document_map` և
  `obsidian_get_tags`՝ նախքան կարդալը/գրելը կառուցվածքն ուսումնասիրելու համար։
- **Obsidian-ի ավտոմատացում** — `obsidian_list_commands` + `obsidian_execute_command`՝
  գործակալից փլագիններ/հրամաններ կառավարելու համար, իսկ `obsidian_open_file`՝ նշումը UI-ում ցուցադրելու համար։
- **Բջջային համաժամացում** — միացրեք WebDAV համաժամացումը, ապա օգտագործեք `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  աշխատասեղանային↔բջջային համաժամացումը համակարգելու և հակասությունները լուծելու համար։
