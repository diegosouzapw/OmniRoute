> **Կարճ ասած**․ Սահմանեք ձեր մոդելը որպես `auto`, և OmniRoute-ը յուրաքանչյուր հարցման համար ավտոմատ կընտրի լավագույն AI մատակարարին։ Կարգավորում անհրաժեշտ չէ։

## Ինչ է այն անում

Կոնկրետ AI մոդել (օրինակ՝ GPT-4o կամ Claude) ընտրելու փոխարեն կարող եք թույլ տալ OmniRoute-ին՝ յուրաքանչյուր հարցման համար **ավտոմատ ընտրել լավագույնը**։ Այն հաշվի է առնում՝

- **Առողջական վիճակը** — Մատակարարն այժմ աշխատո՞ւմ է։
- **Արագությունը** — Որքա՞ն արագ է այն։
- **Արժեքը** — Որքա՞ն արժե այն։
- **Որակը** — Արդյո՞ք այն հարմար է այս տեսակի առաջադրանքի համար։
- **Թողունակությունը** — Արդյո՞ք մնացած քվոտա ունի։

OmniRoute-ը գնահատում է ձեր բոլոր միացված մատակարարներին և ընտրում լավագույնին։ Եթե այն ձախողվում է, OmniRoute-ն ավտոմատ փորձում է հաջորդին։

## Արագ մեկնարկ

**Քայլ 1**․ Ձեր IDE-ում կամ CLI-ում սահմանեք մոդելը որպես `auto`․

```
model: "auto"
```

**Քայլ 2**․ Ահա և վերջ։ OmniRoute-ը կանի մնացածը։

**Քայլ 3** (ըստ ցանկության)․ Կոնկրետ առաջադրանքների համար օգտագործեք տարբերակներից մեկը․

```
model: "auto/coding"    # Լավագույնը՝ կոդի համար
model: "auto/fast"      # Ամենաարագ պատասխանը
model: "auto/cheap"     # Ամենաէժան տարբերակը
```

## Ո՞ր «auto»-ն օգտագործել

| Եթե ցանկանում եք...             | Օգտագործեք սա  | Լավագույնն է                    | Ինչպես է այն աշխատում                                          |
| ------------------------------- | -------------- | ------------------------------- | -------------------------------------------------------------- |
| **Ընդհանուր առմամբ լավագույնը** | `auto`         | Ընդհանուր հարցեր, զրույց        | Հավասարակշռում է արագությունը, արժեքը և որակը                  |
| **Լավագույն կոդը**              | `auto/coding`  | Կոդ գրել, վրիպազերծում          | Ընտրում է կոդավորման առաջադրանքներում լավ մոդելներ             |
| **Ամենաարագ պատասխանը**         | `auto/fast`    | Արագ պատասխաններ, ցածր ուշացում | Արագությունը գերադասում է մնացած ամեն ինչից                    |
| **Ամենաէժան տարբերակը**         | `auto/cheap`   | Գումար խնայել                   | Ընտրում է ամենաէժան մատակարարին                                |
| **Ամենախելացի մոդելը**          | `auto/smart`   | Բարդ առաջադրանքներ              | Առաջնահերթություն է տալիս որակին և ուսումնասիրում նոր մոդելներ |
| **Ամենահասանելին**              | `auto/offline` | Երբ մատակարարները զբաղված են    | Ընտրում է առավել մեծ թողունակությամբ մատակարարներին            |

## Ինչպես է այն աշխատում (պարզ տարբերակ)

Երբ հարցում եք ուղարկում `model: "auto"`-ով, OmniRoute-ը՝

1. **Դիտարկում է ձեր բոլոր միացված մատակարարներին** — Ձեր ավելացրած յուրաքանչյուր մատակարարին (OpenAI, Anthropic, Google և այլն)
2. **Գնահատում է յուրաքանչյուրին**՝ ի թիվս այլ գործոնների կշռադատելով՝
   - Արդյո՞ք այն աշխատում է։ (առողջական վիճակ)
   - Արդյո՞ք այն ունի թողունակություն։ (քվոտա)
   - Որքա՞ն արժե այն։ (գին)
   - Որքա՞ն արագ է այն։ (արագություն)
   - Արդյո՞ք այն հարմար է այս առաջադրանքի համար։ (որակ)
3. **Ընտրում է լավագույնին** — Ամենաբարձր գնահատականն ունեցող մատակարարը ստանում է ձեր հարցումը
4. **Ավտոմատ վերականգնվում է** — Եթե այն ձախողվում է, OmniRoute-ն ավտոմատ փորձում է հաջորդին

### Գնահատման համակարգը

Յուրաքանչյուր մատակարար ստանում է 0-ից 1 գնահատական։ Որքան բարձր է գնահատականը, այնքան ավելի համապատասխան է մատակարարը։

| Գործոն                           | Կշիռ | Ինչ է դա նշանակում                                                |
| -------------------------------- | ---- | ----------------------------------------------------------------- |
| Առողջական վիճակ                  | 20%  | Արդյո՞ք մատակարարն աշխատում է։ (circuit breaker-ի վիճակ)          |
| Քվոտա                            | 15%  | Արդյո՞ք մնացած թողունակություն ունի։                              |
| Արժեք                            | 15%  | Որքա՞ն թանկ է այն։ (ավելի էժան = ավելի բարձր գնահատական)          |
| Արագություն                      | 12%  | Որքա՞ն արագ է այն։ (ավելի ցածր ուշացում = ավելի բարձր գնահատական) |
| Առաջադրանքին համապատասխանություն | 8%   | Արդյո՞ք այն հարմար է այս տեսակի առաջադրանքի համար։                |
| Կայունություն                    | 5%   | Արդյո՞ք այն հետևողական է։ (սխալների ցածր հաճախականություն)        |
| Մակարդակ                         | 5%   | Հաշվի մակարդակը (Ultra > Pro > Free)                              |
| Այլ                              | 20%  | Համատեքստային համապատասխանություն, կապերի խտություն և այլն։       |

### Ինչպես են տարբերակները փոխում գնահատումը

Յուրաքանչյուր տարբերակ օգտագործում է տարբեր կշիռներ․

| Տարբերակ       | Առաջնահերթություն է տալիս   | Հիմնական կշիռներ                |
| -------------- | --------------------------- | ------------------------------- |
| `auto`         | Հավասարակշռությանը          | health=20%, quota=15%, cost=15% |
| `auto/coding`  | Որակին                      | taskFit=37%, stability=15%      |
| `auto/fast`    | Արագությանը                 | latency=32%, health=28%         |
| `auto/cheap`   | Արժեքին                     | cost=37%                        |
| `auto/smart`   | Որակին և ուսումնասիրությանը | taskFit=37%, exploration=10%    |
| `auto/offline` | Թողունակությանը             | quota=37%, health=28%           |

## Ինչպես է այն մշակում խափանումները

OmniRoute-ն ունի **պաշտպանության երեք մակարդակ**․

### 1. Ավտոմատ պահուստային անցում

Եթե լավագույն պրովայդերը խափանվում է, OmniRoute-ն ավտոմատ կերպով փորձում է հաջորդը։ Ձեզնից որևէ գործողություն չի պահանջվում։

### 2. Ինքնավերականգնում

Եթե պրովայդերը շարունակաբար խափանվում է․

- **Գնահատականը < 0.2** → Բացառվում է 5 րոպեով
- **Շղթայի անջատիչը բաց է** → Ավտոմատ բացառվում է
- **Պրովայդերների ավելի քան 50%-ն անհասանելի է** → Միջադեպի ռեժիմ (առանց հետազոտման)

### 3. Արտակարգ պահուստային անցում

Եթե բոլոր պրովայդերները խափանվում են, OmniRoute-ը, որպես վերջին միջոց, հարցումներն ուղղորդում է կայուն անվճար պրովայդերներին (օրինակ՝ Kiro կամ Qoder)։

## Բազմահաշիվ աջակցություն

Եթե նույն պրովայդերի համար ունեք մի քանի հաշիվ (օրինակ՝ OpenAI-ի երկու բանալի), OmniRoute-ը յուրաքանչյուրին դիտարկում է որպես **առանձին թեկնածու**։ Սա նշանակում է․

- A հաշվում հասանելի քվոտա կա → օգտագործել այն
- B հաշվի հարցումների հաճախականությունը սահմանափակված է → բաց թողնել այն
- C հաշիվն ավելի էժան է → նախընտրել այն

Յուրաքանչյուր հաշիվ գնահատվում է անկախ՝ իր հասանելիության, քվոտայի և արագության հիման վրա։

---

## Բանդիտային հետազոտում

OmniRoute-ը երբեմն **հետազոտում է** նոր պրովայդերներ՝ ավելի լավ տարբերակներ հայտնաբերելու համար․

- **Լռելյայն**՝ հարցումների 5%-ն ուղղվում է պատահական պրովայդերների
- **Auto/smart**՝ հետազոտման 10% հաճախականություն
- **Անջատվում է**, երբ պրովայդերների ավելի քան 50%-ն անառողջ վիճակում է

Սա օգնում է OmniRoute-ին պարզել, թե որ պրովայդերներն են լավագույնս համապատասխանում ձեր օգտագործման ձևաչափերին։

## Հաճախակի հարցեր

### «Այն միշտ կընտրի՞ ամենաթանկ մոդելը»

**Ոչ։** Լռելյայն արժեքը գնահատականի ընդամենը 15%-ն է կազմում։ Էժան, արագ և առողջ վիճակում գտնվող պրովայդերը կարող է գերազանցել թանկ պրովայդերին։ Օգտագործեք `auto/cheap`, եթե ցանկանում եք ծախսն էլ ավելի առաջնահերթ դարձնել։

### «Ի՞նչ կլինի, եթե պրովայդերն անհասանելի դառնա»

OmniRoute-ն ավտոմատ կերպով բաց է թողնում այն և փորձում հաջորդը։ Եթե պրովայդերը շարունակաբար խափանվում է, այն ժամանակավորապես բացառվում է (5-30 րոպեով)։ Ձեզնից որևէ գործողություն չի պահանջվում։

### «Կարո՞ղ եմ տեսնել, թե որ պրովայդերն է օգտագործվել»

Ստուգեք պատասխանի վերնագրերը․ OmniRoute-ը յուրաքանչյուր պատասխանում ներառում է օգտագործված պրովայդերն ու մոդելը։

### «Այն սովորո՞ւմ է իմ օգտագործման տվյալներից»

Այո՛։ Գնահատման համակարգն օգտագործում է պատմական տվյալները (ուշացում, սխալների հաճախականություն, հաջողության հաճախականություն)՝ ժամանակի ընթացքում ավելի լավ որոշումներ կայացնելու համար։

### «Ո՞րն է `auto`-ի և `auto/smart`-ի տարբերությունը»

- `auto` — Հավասարակշռված, 5% հետազոտում
- `auto/smart` — Որակն առաջնային է (նույն կշիռները, ինչ `auto/coding`-ի դեպքում), 10% հետազոտում

Օգտագործեք `auto/smart`, երբ ցանկանում եք լավագույն որակը և դեմ չեք ժամանակ առ ժամանակ կատարվող հետազոտմանը։

### «Կարո՞ղ եմ պարտադրել որոշակի պրովայդերի օգտագործումը»

Այո՛։ `auto`-ի փոխարեն օգտագործեք `priority` ռազմավարությամբ կոմբինացիա, ապա որպես `model` դաշտ ուղարկեք կոմբինացիայի **ճշգրիտ անունը** (օրինակ՝ `model: "my-combo"` — ոչ թե `auto`)։ Մանրամասների համար տե՛ս [Տեխնիկական տեղեկատուն](../routing/AUTO-COMBO.md)։

### «Ինչո՞վ է սա տարբերվում հերթափոխային բաշխումից»

Հերթափոխային բաշխումը սահմանված հերթականությամբ անցնում է պրովայդերներով։ Auto-combo-ն **գնահատում է յուրաքանչյուր պրովայդերի** և ընտրում լավագույնը։ Այն ավելի խելացի է՝ հաշվի է առնում հասանելիությունը, արագությունը, արժեքը և որակը։
