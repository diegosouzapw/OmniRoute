Web Cookie մատակարարները OmniRoute-ին թույլ են տալիս օգտագործել AI ծառայություն ձեր զննարկչի առկա աշխատաշրջանի միջոցով՝ API բանալու փոխարեն։ Դրանք օգտակար են, երբ ծառայությունն արդեն հասանելի է ձեզ իր կայքի միջոցով, և ցանկանում եք, որ OmniRoute-ն օգտագործի նույն նույնականացված աշխատաշրջանը։

Ի տարբերություն API բանալի օգտագործող մատակարարների՝ Web Cookie մատակարարները նույնականացվում են այն հավատարմագրերի միջոցով, որոնք ձեր զննարկիչն ուղարկում է կայքին։

# Նախքան սկսելը

> **Կարևոր․** Հավատարմագրերը միշտ պատճենեք **ակտիվ ցանցային հարցումից**, այլ **ոչ թե** զննարկչի cookie-ների պահոցից։

Նույնականացման բազմաթիվ խնդիրներ առաջանում են սխալ տեղից cookie-ներ պատճենելու պատճառով։

## ՄԻ՛ պատճենեք Cookie Storage-ից

Զննարկիչների մեծ մասը պահված cookie-ները հասանելի է դարձնում հետևյալ բաժնում՝

```
DevTools
→ Application (կամ Storage)
→ Cookies
```

Թեև այս cookie-ները կարող են ճիշտ թվալ, դրանք կարող են լինել՝

- հնացած
- ոչ ամբողջական
- առանց այն cookie-ների, որոնք ուղարկվում են միայն նույնականացված հարցումների ժամանակ

Այս արժեքների օգտագործումը կարող է նույնականացման ձախողումներ առաջացնել, նույնիսկ եթե դրանք վավեր են թվում։

## Պատճենեք ակտիվ հարցումից

Փոխարենը օգտագործեք հաջողված հարցման cookie-ները՝

```
DevTools
→ Network
→ Թարմացրեք էջը
→ Բացեք զրույցի կամ խոսակցության հարցում
→ Request Headers
→ Cookie
```

`Cookie` հարցման վերնագիրը պարունակում է նույնականացման ճշգրիտ տեղեկությունները, որոնք ձեր զննարկիչը հաջողությամբ օգտագործել է։

Web Cookie մատակարարների մեծ մասի դեպքում հենց այս արժեքը պետք է տեղադրել OmniRoute-ում։

# Ընդհանուր կարգավորում

Կարգավորման գործընթացը նույնն է Web Cookie մատակարարների մեծ մասի համար։

1. Մուտք գործեք մատակարարի կայք։
2. Բացեք զննարկչի Developer Tools-ը։
3. Բացեք **Network** ներդիրը։
4. Թարմացրեք էջը։
5. Բացեք նույնականացված զրույցի կամ խոսակցության հարցում։
6. Պատճենեք պահանջվող նույնականացման հավատարմագրերը։
7. Բացեք OmniRoute-ը։
8. Անցեք **Providers → Add Provider**։
9. Ընտրեք ձեր Web Cookie մատակարարին։
10. Տեղադրեք հավատարմագրերը։
11. Սեղմեք **Test Connection**։
12. Պահպանեք մատակարարին։

Պահանջվող ճշգրիտ հավատարմագրերը կախված են մատակարարից։

# Ինչ կարող են և չեն կարող անել Web Cookie մատակարարները

Web Cookie մատակարարները վերօգտագործում են կայքի զրույցի միջերեսը։ Դրանք **չեն** տրամադրում նույն հնարավորությունները, ինչ պաշտոնական API-ները։

## Աջակցվում է

- Նույնականացում՝ օգտագործելով ձեր զննարկչի առկա աշխատաշրջանը
- Ձեր հաշվի միջոցով հասանելի մոդելների օգտագործում
- Զրույցի պատասխանների հոսքային փոխանցում
- API բանալի չի պահանջվում

## Չի աջակցվում

- Ֆունկցիաների կանչում
- Գործիքների կանչում
- Ֆայլերի ավտոմատ խմբագրում
- Գործակալային IDE աշխատանքային հոսքեր
- Միայն API-ով հասանելի գործառույթներ

Սա ակնկալվող վարքագիծ է և **սխալ չէ**։

Եթե ձեզ անհրաժեշտ են գործիքների կատարում, ֆայլերի ավտոմատ խմբագրում կամ այլ գործակալային աշխատանքային հոսքեր, Web Cookie մատակարարի փոխարեն օգտագործեք **API բանալի օգտագործող մատակարար**։

# Վավերացման սահմանափակում

Հաջողված **Test Connection**-ը կամ cookie-ի վավերացումը միայն հաստատում է, որ տրամադրված հավատարմագրերը, ըստ երևույթին, ունեն ակնկալվող ձևաչափը։

Մինչև Issue #7857-ի լուծումը՝ հաջողված վավերացումը **չի երաշխավորում**, որ մատակարարը կկարողանա հաջողությամբ նույնականացվել։

Եթե նույնականացումը դեռ ձախողվում է, համոզվեք, որ հավատարմագրերը պատճենել եք ակտիվ ցանցային հարցումից, այլ ոչ թե զննարկչի cookie-ների պահոցից։

# Խնդիրների վերացում

## Նույնականացումը ձախողվում է

Համոզվեք, որ հավատարմագրերը պատճենվել են հետևյալ բաժնից՝

```
Network
→ Request Headers
→ Cookie
```

և **ոչ թե** հետևյալ բաժնից՝

```
Application
→ Cookies
```

---

## Cookie-ն աշխատում է զննարկչում, բայց ոչ OmniRoute-ում

Որոշ մատակարարներ ներառում են cookie-ներ, որոնք ուղարկվում են միայն նույնականացված հարցումների ժամանակ։

Հաջողությամբ խոսակցություն բացելուց հետո կրկին պատճենեք հավատարմագրերը նոր ցանցային հարցումից։

---

## Աշխատաշրջանի ժամկետը լրացել է

Web Cookie մատակարարներն օգտագործում են ձեր զննարկչի առկա աշխատաշրջանը։

Եթե զննարկչի աշխատաշրջանի ժամկետը լրանում է կամ դուրս եք գալիս հաշվից, պետք է պատճենեք հավատարմագրերի նոր հավաքածու։

---

## Test Connection-ը հաջողվում է, բայց հարցումները ձախողվում են

Մինչև Issue #7857-ի լուծումը՝ վավերացման հաջողումը չի երաշխավորում, որ նույնականացման հարցումը հաջող կլինի։

Նախքան խնդրի հետագա ուսումնասիրությունը՝ կրկին պատճենեք ձեր հավատարմագրերը նոր նույնականացված հարցումից։

# Մատակարարի օրինակ

Մատակարարին հատուկ ամբողջական քայլ առ քայլ ուղեցույցի համար տե՛ս՝

- **Claude Web** — `docs/providers/CLAUDE_WEB.md`

Claude Web-ի ուղեցույցը ցուցադրում է Web Cookie մատակարարի կարգավորման ամբողջական գործընթացը և ծառայում է որպես հղումային իրականացում։

# Լավագույն գործելակերպեր

- Պատճենեք հավատարմագրերը նոր նույնականացված հարցումից։
- Խուսափեք հին cookie-ների վերօգտագործումից։
- Web Cookie մատակարարներ օգտագործելիս ակտիվ պահեք ձեր զննարկչի աշխատաշրջանը։
- Պատճենված cookie-ներին վերաբերվեք որպես զգայուն հավատարմագրերի։
- Երբ անհրաժեշտ է ֆունկցիաների կանչում կամ գործակալային աշխատանքային հոսքեր, օգտագործեք API բանալի օգտագործող մատակարարներ։
