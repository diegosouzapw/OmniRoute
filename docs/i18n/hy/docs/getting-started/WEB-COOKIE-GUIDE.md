Web Cookie մատակարարները OmniRoute-ին թույլ են տալիս AI ծառայություն օգտագործել ձեր առկա դիտարկիչի աշխատաշրջանի միջոցով՝ API բանալու փոխարեն։ Դրանք օգտակար են, երբ արդեն հասանելիություն ունեք որևէ ծառայության՝ դրա կայքի միջոցով, և ցանկանում եք, որ OmniRoute-ն օգտագործի նույն նույնականացված աշխատաշրջանը։

Ի տարբերություն API բանալի օգտագործող մատակարարների՝ Web Cookie մատակարարները նույնականացումն իրականացնում են այն հավատարմագրերի միջոցով, որոնք ձեր դիտարկիչն ուղարկում է կայքին։

# Նախքան սկսելը

> **Կարևոր․** Հավատարմագրերը միշտ պատճենեք **ակտիվ ցանցային հարցումից**, այլ **ոչ թե** ձեր դիտարկիչի cookie-ների պահոցից։

Նույնականացման բազմաթիվ խնդիրներ առաջանում են սխալ տեղից cookie-ներ պատճենելու պատճառով։

## Մի՛ պատճենեք Cookie Storage-ից

Դիտարկիչների մեծ մասը պահպանված cookie-ները հասանելի է դարձնում հետևյալ բաժնում․

```
DevTools
→ Application (կամ Storage)
→ Cookies
```

Թեև այս cookie-ները կարող են ճիշտ թվալ, դրանք կարող են լինել՝

- հնացած
- ոչ ամբողջական
- առանց այն cookie-ների, որոնք ուղարկվում են միայն նույնականացված հարցումների ժամանակ

Այս արժեքների օգտագործումը կարող է նույնականացման ձախողումներ առաջացնել, նույնիսկ եթե դրանք վավեր են թվում։

## Պատճենեք ակտիվ հարցումից

Փոխարենը՝ օգտագործեք հաջողված հարցման cookie-ները․

```
DevTools
→ Network
→ Թարմացրեք էջը
→ Բացեք չատի կամ զրույցի հարցումը
→ Request Headers
→ Cookie
```

`Cookie` հարցման վերնագիրը պարունակում է նույնականացման ճշգրիտ տվյալները, որոնք ձեր դիտարկիչը հաջողությամբ օգտագործել է։

Web Cookie մատակարարների մեծ մասի դեպքում հենց այս արժեքը պետք է տեղադրել OmniRoute-ում։

# Ընդհանուր կարգավորում

Կարգավորման գործընթացը Web Cookie մատակարարների մեծ մասի համար նույնն է։

1. Մուտք գործեք մատակարարի կայք։
2. Բացեք դիտարկիչի Developer Tools-ը։
3. Բացեք **Network** ներդիրը։
4. Թարմացրեք էջը։
5. Բացեք նույնականացում պահանջող չատի կամ զրույցի հարցումը։
6. Պատճենեք պահանջվող նույնականացման հավատարմագրերը։
7. Բացեք OmniRoute-ը։
8. Անցեք **Providers → Add Provider**։
9. Ընտրեք ձեր Web Cookie մատակարարին։
10. Տեղադրեք հավատարմագրերը։
11. Սեղմեք **Test Connection**։
12. Պահպանեք մատակարարին։

Պահանջվող ճշգրիտ հավատարմագրերը կախված են մատակարարից։

# Մատակարարների հավատարմագրերի ձևաչափերը

| Մատակարար                       | Հավատարմագրերի ձևաչափ              | Մատակարարի ուղեցույց             |
| ------------------------------- | ---------------------------------- | -------------------------------- |
| Claude Web                      | Cookie հարցման ամբողջական վերնագիր | `docs/providers/CLAUDE_WEB.md`   |
| ChatGPT Web (Codex)             | Cookie-ի ամբողջական վերնագիր       | `docs/providers/CHATGPT_WEB.md`  |
| Gemini Web                      | _(ստուգել)_                        |                                  |
| Copilot Web                     | _(ստուգել)_                        | `docs/providers/COPILOT-M365.md` |
| Microsoft 365 Copilot (BizChat) | WS access_token + chathubPath      | `docs/providers/COPILOT-M365.md` |
| Grok Web                        | _(ստուգել)_                        |                                  |
| ...                             | ...                                | ...                              |

> Թարմացրեք այս աղյուսակը, երբ ավելացվում են Web Cookie-ի նոր մատակարարներ կամ փոխվում են առկա մատակարարների նույնականացման պահանջները։

## NoTrack (notrack-web)

NoTrack-ը ([notrack.ai](https://notrack.ai)) գրանցում չպահանջող անվճար սպառողական չաթային հարթակ է․ առաջին այցելության ժամանակ աշխատաշրջանը ստեղծվում է անանուն կերպով և պահպանվում է երեք cookie-ի միջոցով՝ `uid`, `si_usr_id` և `si_ses_id`։ OmniRoute-ը նույն `/api/dispatch` վերջնակետը պրոքսիացնում է մեկ մոդելի նույնացուցիչի միջոցով (`notrack-c`, կեղծանունը՝ `ntw`)։

### Միացման քայլերը

1. Բացեք [notrack.ai](https://notrack.ai)-ը ձեր դիտարկիչում և սպասեք, մինչև անանուն աշխատաշրջանի cookie-ն սահմանվի։
2. Բացեք **DevTools → Network** բաժինը, թարմացրեք էջը և սեղմեք ցանկացած `/api` հարցման վրա։
3. **Request Headers** բաժնում պատճենեք `Cookie` վերնագրի ամբողջական արժեքը։
4. OmniRoute-ում անցեք **Providers → Add Provider → NoTrack Web (Free)**։
5. Տեղադրեք cookie-ի տողը `apiKey` դաշտում և սեղմեք **Save**։

OmniRoute-ը տեղադրված տողից առանձնացնում է `uid`, `si_usr_id` և `si_ses_id` արժեքները և վերակառուցում է մաքուր `Cookie` վերնագիր՝ միայն այդ զույգերով, ինչպես նաև ավելացնում է `nt_session`-ը (մուտք գործած հաշիվների համար սահմանված `ntk_…` թոքենը), եթե այն առկա է։ Եթե երեքից որևէ մեկը բացակայում է, տեղադրված չմշակված տողը փոխանցվում է անփոփոխ, որպեսզի օպերատորները կարողանան փորձարկել այլ ձևաչափեր։

### Մոդելների նույնացուցիչները

| Մոդելի նույնացուցիչ | Ցուցադրվող անուն | Նշումներ                                                     |
| ------------------- | ---------------- | ------------------------------------------------------------ |
| `notrack-c`         | NoTrack C        | Լռելյայն՝ վերին հոսքի dispatch մոդելը՝ `C`։                  |
| `C`                 | NoTrack C        | `notrack-c`-ի կեղծանունը (վերին հոսքի dispatch-ի հում կոդը)։ |
| `notrack`           | NoTrack C        | `notrack-c`-ի կեղծանունը։                                    |
| `ntw`               | NoTrack C        | `notrack-c`-ի կարճ կեղծանունը։                               |

Բոլոր չորս մոդելների նույնացուցիչները համապատասխանում են վերին հոսքի նույն dispatch մոդելին (`C`)։

### Հարցման ընտրանքները

Կատարիչը հարցման մարմնում ընդունում է հետևյալ ոչ պարտադիր դաշտերը․

| Մարմնի դաշտ           | Լռելյայն | Նպատակ                                                                           |
| --------------------- | -------- | -------------------------------------------------------------------------------- |
| `notrack_mode`        | `usual`  | Ուղղորդման ռեժիմ (ազատ ձևաչափի տող․ վերին հոսքն ընդունում է `usual`, …)          |
| `notrack_max_turns`   | `6`      | Ներքին քայլերի քանակը, որոնք վերին հոսքը կարող է կատարել մինչև պատասխանելը։      |
| `notrack_chat_id`     | `null`   | Շարունակել գոյություն ունեցող վերին հոսքի չաթը (բաց թողեք նոր չաթի համար)։       |
| `notrack_attachments` | `[]`     | Վերին հոսքի կցորդների նկարագրիչների անփոփոխ փոխանցվող զանգված։                   |
| `notrack_regenerate`  | `false`  | Սահմանեք `true`՝ նախորդ քայլի համար վերագեներացված պատասխան պահանջելու նպատակով։ |

### Հնարավորությունները

- Չաթի պատասխանների **հոսքային և ոչ հոսքային** տրամադրում։
- **Գործիքների կանչում** — հարցման մեջ սահմանեք `tools: [...]`․ կատարիչը սերիականացնում է դրանք գործիքի կանչի ծրարային պայմանագրի մեջ և մոդելի պատասխանները կրկին վերլուծում է OpenAI-ի `tool_calls` ձևաչափով։
- **`response_format`** — աջակցվում են `json_object` և `json_schema` ձևաչափերը։ Կատարիչը մոդելի պատասխանից առանձնացնում է առաջին JSON օբյեկտը և վերադարձնելուց առաջ այն փոխակերպում է տողի։
- **Դատողության հուշում** — երբ վերին հոսքն ուղարկում է `thinking` իրադարձություն, կատարիչն արձակում է `reasoning` դելտա։

### Սահմանափակումները

- Վերին հոսքը կիրառում է անանուն օգտագործման քվոտաներ․ դրանց գերազանցման դեպքում կատարիչը վերադարձնում է 429 կարգավիճակ՝ հասկանալի հաղորդագրությամբ։
- Բոլոր մոդելների նույնացուցիչները հանգում են վերին հոսքի նույն dispatch մոդելին․ առանձին մոդելների միջև անցում չկա։
- Կատարիչը չի կանչում վերին հոսքի `/api/chats` վերջնակետը, ուստի չաթի պատմությունը / աշխատաշրջաններն ինքնաբերաբար չեն կառավարվում։ Գոյություն ունեցող վերին հոսքի չաթը շարունակելու համար օգտագործեք `notrack_chat_id`։

# Ինչ կարող են և չեն կարող անել Web Cookie մատակարարները

Web Cookie մատակարարները վերօգտագործում են կայքի չաթային միջերեսը։ Դրանք **չեն** տրամադրում նույն հնարավորությունները, ինչ պաշտոնական API-ները։

## Աջակցվում է

- Նույնականացում՝ օգտագործելով դիտարկիչի ձեր առկա աշխատաշրջանը
- Ձեր հաշվի միջոցով հասանելի մոդելների օգտագործում
- Զրույցի պատասխանների հոսքային փոխանցում
- API բանալի չի պահանջվում

## Չի աջակցվում

- Ֆունկցիաների կանչում
- Գործիքների կանչում
- Ֆայլերի ավտոմատ խմբագրում
- Գործակալային IDE աշխատանքային հոսքեր
- Միայն API-ի միջոցով հասանելի գործառույթներ

Սա ակնկալվող վարքագիծ է և **սխալ չէ**։

Եթե ձեզ անհրաժեշտ է գործիքների գործարկում, ֆայլերի ավտոմատ խմբագրում կամ այլ գործակալային աշխատանքային հոսքեր, Web Cookie մատակարարի փոխարեն օգտագործեք **API բանալիով մատակարար**։

# Վավերացման սահմանափակում

Հաջողված **Test Connection**-ը կամ cookie-ի վավերացումը միայն հաստատում է, որ տրամադրված նույնականացման տվյալներն ունեն ակնկալվող ձևաչափը։

Քանի դեռ Issue #7857-ը լուծված չէ, հաջող վավերացումը **չի երաշխավորում**, որ մատակարարը հաջողությամբ կիրականացնի նույնականացումը։

Եթե նույնականացումը դեռ ձախողվում է, համոզվեք, որ նույնականացման տվյալները պատճենել եք գործող ցանցային հարցումից, այլ ոչ թե դիտարկիչի cookie-ների պահոցից։

# Խնդիրների լուծում

## Նույնականացումը ձախողվում է

Համոզվեք, որ նույնականացման տվյալները պատճենվել են հետևյալ բաժնից՝

```
Network
→ Request Headers
→ Cookie
```

և **ոչ** հետևյալ բաժնից՝

```
Application
→ Cookies
```

---

## Cookie-ն աշխատում է դիտարկիչում, բայց ոչ OmniRoute-ում

Որոշ մատակարարներ ներառում են cookie-ներ, որոնք ուղարկվում են միայն նույնականացված հարցումների ժամանակ։

Հաջողությամբ զրույց բացելուց հետո նույնականացման տվյալները կրկին պատճենեք նոր ցանցային հարցումից։

---

## Աշխատաշրջանի ժամկետը լրացել է

Web Cookie մատակարարներն օգտագործում են դիտարկիչի ձեր առկա աշխատաշրջանը։

Եթե դիտարկիչի ձեր աշխատաշրջանի ժամկետը լրանում է կամ դուրս եք գալիս հաշվից, պետք է պատճենեք նույնականացման տվյալների նոր հավաքածու։ Աջակցվող վեբ մատակարարների համար cookie-ների թարմացումն ավտոմատացնելու նպատակով տե՛ս ուղեկցող [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md) գործիքը։

Քանի դեռ Issue #7857-ը լուծված չէ, հաջող վավերացումը չի երաշխավորում, որ նույնականացման հարցումը հաջող կլինի։

Նախքան խնդիրների հետագա լուծումը, նույնականացման տվյալները կրկին պատճենեք նոր նույնականացված հարցումից։

# Լավագույն գործելակերպեր

- Նույնականացման տվյալները պատճենեք նոր նույնականացված հարցումից։
- Խուսափեք հին cookie-ների կրկնակի օգտագործումից։
- Web Cookie մատակարարներ օգտագործելիս դիտարկիչի ձեր աշխատաշրջանը պահեք ակտիվ։
- Պատճենված cookie-ներին վերաբերվեք որպես գաղտնի նույնականացման տվյալների։
- Երբ ձեզ անհրաժեշտ է ֆունկցիաների կանչում կամ գործակալային աշխատանքային հոսքեր, օգտագործեք API բանալիով մատակարարներ։
