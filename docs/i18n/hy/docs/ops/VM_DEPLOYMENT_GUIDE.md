## Նախադրյալներ

| Բաղադրիչ     | Նվազագույն              | Առաջարկվող       |
| ------------ | ----------------------- | ---------------- |
| **CPU**      | 1 vCPU                  | 2 vCPU           |
| **RAM**      | 1 GB                    | 2 GB             |
| **Սկավառակ** | 10 GB SSD               | 25 GB SSD        |
| **ՕՀ**       | Ubuntu 22.04 LTS        | Ubuntu 24.04 LTS |
| **Դոմեն**    | Գրանցված Cloudflare-ում | —                |
| **Docker**   | Docker Engine 24+       | Docker 27+       |

**Փորձարկված մատակարարներ**՝ Akamai (Linode), DigitalOcean, Vultr, Hetzner, AWS Lightsail։

## 1. Կարգավորեք VM-ը

### 1.1 Ստեղծեք ինստանսը

Ձեր նախընտրած VPS մատակարարի հարթակում՝

- Ընտրեք Ubuntu 24.04 LTS
- Ընտրեք նվազագույն սակագնային պլանը (1 vCPU / 1 GB RAM)
- Սահմանեք հուսալի root գաղտնաբառ կամ կարգավորեք SSH բանալի
- Գրանցեք **հանրային IP հասցեն** (օրինակ՝ `203.0.113.10`)

### 1.2 Միացեք SSH-ի միջոցով

```bash
ssh root@203.0.113.10
```

### 1.3 Թարմացրեք համակարգը

```bash
apt update && apt upgrade -y
```

### 1.4 Տեղադրեք Docker-ը

```bash
# Տեղադրեք կախվածությունները
apt install -y ca-certificates curl gnupg

# Ավելացրեք Docker-ի պաշտոնական ռեպոզիտորիան
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
chmod a+r /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $ (. /etc/os-release && echo "$VERSION_CODENAME") stable" | tee /etc/apt/sources.list.d/docker.list > /dev/null
apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

### 1.5 Տեղադրեք nginx-ը

```bash
apt install -y nginx
```

### 1.6 Կարգավորեք Firewall-ը (UFW)

```bash
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp    # SSH
ufw allow 80/tcp    # HTTP (վերահղում)
ufw allow 443/tcp   # HTTPS
ufw enable
```

> **Խորհուրդ**․ Առավելագույն անվտանգության համար սահմանափակեք 80 և 443 պորտերի հասանելիությունը՝ թույլատրելով միայն Cloudflare-ի IP հասցեները։ Տե՛ս [Ընդլայնված անվտանգություն](#advanced-security) բաժինը։

## 2. Տեղադրեք OmniRoute-ը

### 2.1 Ստեղծեք կազմաձևման գրացուցակը

```bash
mkdir -p /opt/omniroute
```

### 2.2 Ստեղծեք միջավայրի փոփոխականների ֆայլը

```bash
cat > /opt/omniroute/.env << 'EOF'
# === Անվտանգություն ===
JWT_SECRET=CHANGE-TO-A-UNIQUE-64-CHAR-SECRET-KEY
INITIAL_PASSWORD=YourSecurePassword123!
API_KEY_SECRET=REPLACE-WITH-ANOTHER-SECRET-KEY
STORAGE_ENCRYPTION_KEY=REPLACE-WITH-THIRD-SECRET-KEY
STORAGE_ENCRYPTION_KEY_VERSION=v1
MACHINE_ID_SALT=CHANGE-TO-A-UNIQUE-SALT
OMNIROUTE_WS_BRIDGE_SECRET=REPLACE-WITH-WS-BRIDGE-SECRET  # ՊԱՐՏԱԴԻՐ է արտադրական միջավայրում․ օգտագործվում է Codex Responses WS կամրջի կողմից

# === Հավելված ===
PORT=20128
NODE_ENV=production
HOSTNAME=0.0.0.0
DATA_DIR=/app/data
APP_LOG_TO_FILE=true
AUTH_COOKIE_SECURE=true
REQUIRE_API_KEY=false

# === URL-ներ (փոխարինեք ձեր դոմենով) ===
# Ներքին՝ սերվերից սերվեր բազային URL՝ պլանավորված առաջադրանքների / ինքնահարցումների համար։
BASE_URL=http://127.0.0.1:20128
# Զննարկչին հասանելի URL, որն օգտագործվում է OAuth հետադարձ կանչերի, կառավարման վահանակի հղումների և ստեղծվող հանրային URL-ների համար։
NEXT_PUBLIC_BASE_URL=https://llms.seudominio.com
# Ընտրովի բացահայտ հանրային սկզբնաղբյուրի վերասահմանում՝ ստեղծվող հանրային ռեսուրսների URL-ների համար։
# OMNIROUTE_PUBLIC_BASE_URL=https://llms.seudominio.com

# === Ամպային համաժամացում (ընտրովի) ===
# CLOUD_URL=https://cloud.omniroute.online
# NEXT_PUBLIC_CLOUD_URL=https://cloud.omniroute.online
EOF
```

> ⚠️ **ԿԱՐԵՎՈՐ**․ Ստեղծեք եզակի գաղտնի բանալիներ։ Յուրաքանչյուր բանալու համար օգտագործեք `openssl rand -hex 32`։

### 2.3 Գործարկեք կոնտեյները

```bash
docker pull diegosouzapw/omniroute:latest

docker run -d \
  --name omniroute \
  --restart unless-stopped \
  --env-file /opt/omniroute/.env \
  -p 20128:20128 \
  -v omniroute-data:/app/data \
  diegosouzapw/omniroute:latest
```

### 2.4 Ստուգեք, որ այն աշխատում է

```bash
docker ps | grep omniroute
docker logs omniroute --tail 20
```

Պետք է ցուցադրվեն՝ `[DB] SQLite database ready` և `listening on port 20128`։

## 3. Կարգավորեք nginx-ը (հակադարձ պրոքսի)

### 3.1 Ստեղծեք SSL վկայագիր (Cloudflare Origin)

Cloudflare-ի կառավարման վահանակում՝

1. Անցեք **SSL/TLS → Origin Server**
2. Սեղմեք **Create Certificate**
3. Պահպանեք լռելյայն կարգավորումները (15 տարի, \*.yourdomain.com)
4. Պատճենեք **Origin Certificate**-ը և **Private Key**-ը

```bash
mkdir -p /etc/nginx/ssl

# Տեղադրեք վկայագիրը
nano /etc/nginx/ssl/origin.crt

# Տեղադրեք մասնավոր բանալին
nano /etc/nginx/ssl/origin.key

chmod 600 /etc/nginx/ssl/origin.key
```

### 3.2 Nginx-ի կարգավորում

```bash
cat > /etc/nginx/sites-available/omniroute << 'NGINX'
# Լռելյայն սերվեր — արգելափակում է IP-ի միջոցով ուղիղ հասանելիությունը
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    listen 443 ssl default_server;
    listen [::]:443 ssl default_server;
    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    server_name _;
    return 444;
}

# OmniRoute — HTTPS
server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name llms.yourdomain.com;  # Փոխարինեք ձեր դոմենով

    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    client_max_body_size 100M;

    location / {
        proxy_pass http://127.0.0.1:20128;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket-ի աջակցություն
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # SSE (սերվերի կողմից ուղարկվող իրադարձություններ) — AI-ի պատասխանների հոսքային փոխանցում
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }
}

# HTTP → HTTPS վերահղում
server {
    listen 80;
    listen [::]:80;
    server_name llms.yourdomain.com;
    return 301 https://$server_name$request_uri;
}
NGINX
```

Հակադարձ պրոքսիի հոսքերի ժամանակային սահմանափակումները համապատասխանեցրեք OmniRoute-ի ժամանակային սահմանափակումների միջավայրի փոփոխականներին։ Եթե մեծացնեք
`FETCH_TIMEOUT_MS` / `STREAM_IDLE_TIMEOUT_MS` արժեքները, ապա `proxy_read_timeout` / `proxy_send_timeout`
արժեքները բարձրացրեք նույն շեմից վեր։

OmniRoute-ն օգտագործում է `NEXT_PUBLIC_BASE_URL`-ը՝ որպես դիտարկիչի համար կանոնական սկզբնաղբյուր՝ OAuth-ի
հետադարձ կանչերի և ստեղծվող հանրային հղումների համար։ Նույնականացված կառավարման վահանակի գրանցման հարցումներն օգտագործում են նույն սկզբնաղբյուրի հարցումներ՝
գումարած աշխատաշրջանին կապված CSRF պաշտպանություն, ուստի դրանց համար ստատիկ հանրային բազային URL չի պահանջվում։ Վերոնշյալ
`X-Forwarded-*` վերնագրերը դեռևս օգտակար երթուղավորման մետատվյալներ են, սակայն դրանք չեն փոխարինում
հստակ հանրային URL-ի սահմանմանը, երբ այն անհրաժեշտ է OAuth-ի կամ ստեղծվող դիտարկիչային հղումների համար։ `OMNIROUTE_TRUST_PROXY`-ն միացրեք միայն այն դեպքում,
եթե OmniRoute-ն ուղղակիորեն հասանելի չէ հաճախորդներին, և ձեր պրոքսին հեռացնում/վերակառուցում է մուտքային վերահասցեավորման վերնագրերը։

### 3.3 Միացրեք և ստուգեք

```bash
# Հեռացրեք լռելյայն կարգավորումը
rm -f /etc/nginx/sites-enabled/default

# Միացրեք OmniRoute-ը

# Ստուգեք և վերաբեռնեք
```

## Փոքր հիշողությամբ / փոքր VPS-ի օպտիմալացում

Փոքր VPS օրինակների վրա տեղակայումների համար (1 GB RAM կամ պակաս).

- **Անջատեք ֆոնային ծառայությունները** — սահմանեք `OMNIROUTE_DISABLE_BACKGROUND_SERVICES=1`՝ ժամանակացույցը, MCP սերվերը և պարբերական սպասարկման առաջադրանքները բաց թողնելու համար։ Տե՛ս `docs/reference/ENVIRONMENT.md`։
- **Օգտագործեք SQLite WAL ռեժիմը** — լռելյայն միացված է և նվազեցնում է հիշողության առավելագույն օգտագործումը միաժամանակյա ընթերցումների ժամանակ։
- **Սահմանափակեք V8 կույտը** — սահմանեք `OMNIROUTE_MEMORY_MB` (օրինակ՝ `512`), որպեսզի կատարման միջավայրը VM-ից մեծ վերին սահման չչափաբերի։ Տե՛ս `docs/reference/ENVIRONMENT.md`։
- **Ծանր հարցումների ընդունումն ավտոմատ մասշտաբավորվում է կույտի սահմանաչափին համապատասխան** -- վերևում `OMNIROUTE_MEMORY_MB`-ը սահմանելուց հետո մուտքային տվյալների բայթային բյուջեն (`OMNIROUTE_CHAT_MAX_INFLIGHT_BYTES`) հաշվարկվում է նույն վերին սահմանից, ուստի հիշողությամբ սահմանափակված VM-ն առանց լրացուցիչ կարգավորման արդեն ստանում է միաժամանակյա հարցումների ավելի փոքր բյուջե․ ավելցուկային հարցումները հիշողության համար մրցակցելու փոխարեն ստանում են կրկին փորձարկելի `503` պատասխան՝ `Retry-After`-ով։ Սահմանեք հին `OMNIROUTE_CHAT_MAX_HEAVY_IN_FLIGHT` հարցումների քանակի սահմանաչափը միայն այն դեպքում, եթե դրանից բացի անհրաժեշտ է նաև կոշտ վերին սահման։
- **VPS-ում խուսափեք `next build`-ից** — կառուցեք տեղային միջավայրում և տեղակայեք ինքնուրույն ելքային տարբերակը (`.next/standalone/`)։
- **Վերահսկեք `top` / `free -m` հրամաններով** — 1 GB հիշողությամբ VM-ում անգործության ժամանակ OmniRoute-ը սովորաբար օգտագործում է 200-400 MB RSS։
