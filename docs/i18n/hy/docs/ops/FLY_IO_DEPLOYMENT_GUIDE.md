Այս փաստաթուղթը նկարագրում է OmniRoute-ի՝ Fly.io-ում տեղակայման փաստացի գործընթացը՝ ներառելով երեք սցենար.

- Ընթացիկ նախագծի առաջին տեղակայումը Fly.io-ում
- Կոդի հետագա թարմացումների հրապարակումը
- Նույն տեղակայման աշխատանքային գործընթացին հետևող նոր նախագծերը

Այս ուղեցույցը հիմնված է ընթացիկ նախագծի համար ստուգված և աշխատող կազմաձևման վրա։ Հավելվածի անունն է `omniroute`։

---

## 1. Տեղակայման նպատակները

- Հարթակ՝ Fly.io
- Տեղակայման եղանակ՝ տեղային `flyctl`-ով անմիջական հրապարակում
- Կատարման միջավայր՝ պահոցում առկա `Dockerfile`-ի և `fly.toml`-ի օգտագործմամբ
- Տվյալների կայուն պահպանում՝ `/data` ուղու վրա միացված Fly Volume
- Հասանելիության URL՝ `https://omniroute.fly.dev/`

---

## 2. Ընթացիկ նախագծի հիմնական կազմաձևումը

Հաստատվել է, որ ընթացիկ պահոցի `fly.toml`-ը պարունակում է հետևյալ հիմնական տարրերը.

```toml
app = 'omniroute'
primary_region = 'sin'

[[mounts]]
  source = 'data'
  destination = '/data'

[processes]
  app = 'node run-standalone.mjs'

[http_service]
  internal_port = 20128

[env]
  TZ = "Asia/Shanghai"
  HOST = "0.0.0.0"
  HOSTNAME = "0.0.0.0"
  BIND = "0.0.0.0"
```

Նշումներ.

- `app = 'omniroute'`-ը որոշում է, թե Fly-ի որ հավելվածին է ուղղված տեղակայումը
- `destination = '/data'`-ը որոշում է կայուն հատորի միացման գրացուցակը
- Այս նախագծում անհրաժեշտ է սահմանել `DATA_DIR=/data`, հակառակ դեպքում տվյալների բազան և բանալիները կգրվեն կոնտեյների ժամանակավոր գրացուցակում

## 3. Նախապայմաններ

### 3.1 Fly CLI-ի տեղադրում

Windows PowerShell.

```powershell
pwsh -Command "iwr https://fly.io/install.ps1 -useb | iex"
```

Եթե տեղադրման սկրիպտը ձեր միջավայրում ձախողվում է, կարող եք նաև ձեռքով ներբեռնել `flyctl` երկուական ֆայլը և ավելացնել այն ձեր `PATH`-ում։

### 3.2 Մուտք Fly-ի ձեր հաշիվ

```powershell
flyctl auth login
```

### 3.3 Մուտքի կարգավիճակի ստուգում

```powershell
flyctl auth whoami
flyctl version
```

## 4. Ընթացիկ նախագծի առաջին տեղակայումը

### 4.1 Կլոնավորեք կոդը և անցեք գրացուցակ

```powershell
git clone https://github.com/diegosouzapw/OmniRoute.git
cd OmniRoute
```

### 4.2 Հաստատեք հավելվածի անունը

Բացեք `fly.toml`-ը և ստուգեք հետևյալ տողը.

```toml
app = 'omniroute'
```

Եթե տեղակայում եք ձեր սեփական նոր հավելվածում, կարող եք այն փոխել համաշխարհային մասշտաբով եզակի անունով, օրինակ՝

```toml
app = 'omniroute-yourname'
```

Նշում.

- Համոզվեք, որ կառավարման վահանակում ցուցադրվող հավելվածը համապատասխանում է `fly.toml`-ի `app` արժեքին
- Եթե նախկինում օգտագործել եք այլ անուն, օրինակ՝ `oroute`, մի շփոթեք այն `omniroute`-ի հետ

### 4.3 Ստեղծեք հավելվածը

Եթե հավելվածը դեռ գոյություն չունի՝

```powershell
flyctl apps create omniroute
```

Եթե փոխել եք հավելվածի անունը, `omniroute`-ը փոխարինեք ձեր ընտրած անունով։

### 4.4 Առաջին տեղակայում

```powershell
flyctl deploy
```

## 5. Պարտադիր պարամետրեր

Այս նախագծի համար խորհուրդ է տրվում Fly.io-ում կազմաձևել առնվազն հետևյալ պարամետրերը։

### 5.1 Ստուգված պարամետրեր

Այս պարամետրերն օգտագործվել են ընթացիկ `omniroute` հավելվածի իրական տեղակայումներում.

- `API_KEY_SECRET`
- `DATA_DIR`
- `JWT_SECRET`
- `MACHINE_ID_SALT`
- `NEXT_PUBLIC_BASE_URL`
- `OMNIROUTE_WS_BRIDGE_SECRET` (պարտադիր է արտադրական միջավայրում. օգտագործվում է WebSocket կամրջակի իսկորոշման համար)
- `STORAGE_ENCRYPTION_KEY`

### 5.2 `INITIAL_PASSWORD`-ի մասին

Ընթացիկ նախագծում `INITIAL_PASSWORD` սահմանված չէ, քանի որ այս տեղակայման համար այն պարտադիր չէ։

Եթե այն սահմանված չէ՝

- Գործարկման մատյանը կնշի, որ լռելյայն գաղտնաբառը `CHANGEME` է
- Տեղակայումից հետո պետք է հնարավորինս շուտ փոխեք մուտքի գաղտնաբառը համակարգի կարգավորումներում

Եթե ցանկանում եք առանց միջամտության սկզբնարժեքավորել հետնամասի գաղտնաբառը, կարող եք հետագայում ավելացնել այն.

- `INITIAL_PASSWORD`

## 6. Առաջարկվող պարամետրեր

### 6.1 Գաղտնիքների կազմաձևում

Fly Secrets-ի համար առաջարկվում են հետևյալ փոփոխականները.

| Փոփոխական                        | Առաջարկություն                  | Նկարագրություն                                                       |
| -------------------------------- | ------------------------------- | -------------------------------------------------------------------- |
| `API_KEY_SECRET`                 | Պարտադիր                        | Օգտագործվում է API բանալիների ստեղծման և վավերացման համար            |
| `JWT_SECRET`                     | Պարտադիր                        | Օգտագործվում է մուտքի աշխատաշրջանների և JWT ստորագրման համար         |
| `OMNIROUTE_WS_BRIDGE_SECRET`     | Արտադրական միջավայրում պարտադիր | WebSocket կամրջի նույնականացման գաղտնիք                              |
| `STORAGE_ENCRYPTION_KEY`         | Խստորեն առաջարկվում է           | Գաղտնագրում է պահպանված զգայուն կապի տվյալները                       |
| `MACHINE_ID_SALT`                | Առաջարկվում է                   | Ստեղծում է մեքենայի կայուն նույնացուցիչ                              |
| `INITIAL_PASSWORD`               | Ընտրովի                         | Սահմանում է backend-ի սկզբնական գաղտնաբառն առաջին տեղակայման ժամանակ |
| OAuth/API մասնավոր հավատարմագրեր | Ըստ անհրաժեշտության             | Արտաքին հարթակի նույնականացման կազմաձևում                            |

### 6.2 Ընթացիկ նախագծի համար առաջարկվող արժեքներ

| Փոփոխական              | Առաջարկվող արժեք            |
| ---------------------- | --------------------------- |
| `DATA_DIR`             | `/data`                     |
| `NEXT_PUBLIC_BASE_URL` | `https://omniroute.fly.dev` |

Նշումներ.

- `DATA_DIR=/data`-ն կարևոր նշանակություն ունի և պետք է համապատասխանի Fly Volume-ի միացման կետին
- `NEXT_PUBLIC_BASE_URL`-ն օգտագործվում է ժամանակացույցի կառավարչի, frontend-ի հետկանչերի և նմանատիպ սցենարների կողմից

### 6.3 OAuth հետկանչի URL-ի կազմաձևում

Եթե Fly.io-ի տեղակայման մեջ անհրաժեշտ է միացնել OAuth-ի վրա հիմնված մատակարարներ (օրինակ՝ Antigravity, Gemini, Cursor), համոզվեք հետևյալ երկու կետերում.

1. **Սահմանեք `NEXT_PUBLIC_BASE_URL`-ը որպես ձեր հանրային HTTPS տիրույթ**

   ```powershell
   flyctl secrets set NEXT_PUBLIC_BASE_URL=https://omniroute.fly.dev -a omniroute
   ```

   Եթե օգտագործում եք անհատական տիրույթ, փոխարինեք այն համապատասխան տիրույթով (օրինակ՝ `https://omniroute.yourdomain.com`)։

2. **Մատակարարի կառավարման վահանակում կազմաձևեք հետկանչի URL-ը**

   OAuth-ի բոլոր մատակարարներն օգտագործում են միասնական `/callback` հետկանչի ուղին. յուրաքանչյուր մատակարարի համար առանձին հետկանչի երթուղի ՉԿԱ.

   ```text
   <NEXT_PUBLIC_BASE_URL>/callback
   ```

   Օրինակ՝ անկախ նրանից՝ օգտագործվում է Gemini, Antigravity, Cursor, թե GitLab Duo.
   - `https://omniroute.fly.dev/callback`

   Եթե `NEXT_PUBLIC_BASE_URL`-ը չի համապատասխանում մատակարարի մոտ գրանցված հետկանչի URL-ին, OAuth հոսքը կձախողվի դիտարկիչի վերահղման փուլում։

## 7. Գաղտնիքների կարգավորում մեկ հրամանով

Հետևյալ հրամանները ստեղծում են անվտանգ պատահական արժեքներ և մեկ քայլով ընթացիկ նախագծի համար անհրաժեշտ բոլոր պարամետրերը գրում Fly Secrets-ում։

Նշումներ.

- Չի ներառում `INITIAL_PASSWORD`-ը
- Նախատեսված է ընթացիկ `omniroute` նախագծի համար

```powershell
$apiKeySecret = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$jwtSecret = [Convert]::ToHexString((1..64 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$machineIdSalt = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$storageKey = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$wsBridgeSecret = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()

flyctl secrets set `
  API_KEY_SECRET=$apiKeySecret `
  JWT_SECRET=$jwtSecret `
  MACHINE_ID_SALT=$machineIdSalt `
  STORAGE_ENCRYPTION_KEY=$storageKey `
  OMNIROUTE_WS_BRIDGE_SECRET=$wsBridgeSecret `
  DATA_DIR=/data `
  NEXT_PUBLIC_BASE_URL=https://omniroute.fly.dev `
  -a omniroute
```

Linux / macOS համակարգերում կարող եք նաև օգտագործել `openssl rand -hex 32` հրամանը.

```bash
flyctl secrets set OMNIROUTE_WS_BRIDGE_SECRET=$(openssl rand -hex 32) -a omniroute
```

Նշումներ.

- `OMNIROUTE_WS_BRIDGE_SECRET`-ը պարտադիր է արտադրական միջավայրում. դրա բացակայությունը կխափանի WebSocket կամրջի հաստատման գործընթացը

Եթե նաև ցանկանում եք սահմանել սկզբնական գաղտնաբառ.

```powershell
flyctl secrets set INITIAL_PASSWORD=your-strong-password -a omniroute
```

## 9. Հետագա թարմացումներ և թողարկումներ

Կոդի թարմացումներից հետո թողարկման գործընթացը պարզ է՝

```powershell
git pull
flyctl deploy
```

Եթե անհրաժեշտ է միայն թարմացնել պարամետրերը՝ առանց կոդը փոխելու՝

```powershell
flyctl secrets set KEY=value -a omniroute
```

Fly-ն ավտոմատ կերպով կիրականացնի մեքենաների փուլային թարմացում։

### 9.1 Վերին հոսքի շտեմարանի թարմացումներին հետևելը՝ պահպանելով ձեր ֆորքի `fly.toml`-ը

Եթե ընթացիկ շտեմարանը ֆորք է, և ցանկանում եք համաժամացնել վերին հոսքի `https://github.com/diegosouzapw/OmniRoute` շտեմարանի թարմացումները, հետևեք ստորև ներկայացված աշխատանքային ընթացքին։

Նախ ստուգեք հեռակա շտեմարանները՝

```powershell
git remote -v
```

Պետք է տեսնեք առնվազն՝

- `origin`, որը մատնանշում է ձեր սեփական ֆորքը
- `upstream`, որը մատնանշում է սկզբնական շտեմարանը

Եթե `upstream`-ը կազմաձևված չէ, ավելացրեք այն՝

```powershell
git remote add upstream https://github.com/diegosouzapw/OmniRoute.git
```

Նախքան վերին հոսքի հետ համաժամացումը՝ ստացեք վերջին կոմիթներն ու թեգերը՝

```powershell
git fetch upstream --tags
```

Ստուգեք ընթացիկ տարբերակը և վերին հոսքի թեգերը՝

```powershell
git describe --tags --always
git show --no-patch --oneline v3.4.7
```

> Նշում․ նախագծի ընթացիկ տարբերակը `v3.8.0` է։ Ստորև ներկայացված `v3.4.7` հղումները պահպանվել են միայն որպես պատմական օրինակներ։ Իրական թողարկումների համար օգտագործեք `:latest` կամ ընթացիկ տարբերակի թեգը (օրինակ՝ `:v3.8.0`)։

Եթե ցանկանում եք միավորել վերին հոսքի վերջին `main` ճյուղը՝ միաժամանակ հարկադրաբար պահպանելով ձեր ֆորքի `fly.toml`-ը, հետևեք այս աշխատանքային ընթացքին՝

```powershell
git merge upstream/main
git checkout HEAD~1 -- fly.toml
git add -- fly.toml
git commit -m "chore(deploy): keep fork fly.toml"
git push origin main
```

Նշումներ՝

- `git merge upstream/main`-ը համաժամացնում է սկզբնական շտեմարանի վերջին կոդը
- `git checkout HEAD~1 -- fly.toml`-ը վերականգնում է ձեր ֆորքի սեփական `fly.toml`-ը՝ միավորումից առաջվա վիճակից
- Եթե վերին հոսքում `fly.toml`-ը չի փոփոխվել, այս քայլը որևէ տարբերություն չի առաջացնի
- Եթե վերին հոսքում `fly.toml`-ը փոփոխվել է, այս քայլն ապահովում է, որ ձեր Fly հավելվածի անունը, հատորի միացման կետը, տարածաշրջանը և ֆորքին հատուկ տեղակայման այլ կազմաձևերը չվերագրվեն

Եթե ցանկանում եք համապատասխանեցնել որևէ կոնկրետ թողարկման թեգի (օրինակ՝ `v3.4.7`), նախ ստուգեք, որ թեգն արդեն ներառված է `upstream/main`-ում՝

```powershell
git merge-base --is-ancestor v3.4.7 upstream/main
```

Հաջող վերադարձը նշանակում է, որ `upstream/main`-ն արդեն պարունակում է այդ տարբերակը․ կարող եք պարզապես միավորել `upstream/main`-ը։

### 9.2 Թողարկման ստանդարտ հաջորդականությունը՝ վերին հոսքի համաժամացումից հետո

Սկզբնական շտեմարանի հետ համաժամացումից հետո հետևեք թողարկման այս առաջարկվող հերթականությանը՝

1. `git fetch upstream --tags`
2. `git merge upstream/main`
3. Վերականգնեք ֆորքի `fly.toml`-ը
4. `git push origin main`
5. `flyctl deploy`
6. `flyctl status -a omniroute`
7. `flyctl logs --no-tail -a omniroute`

Սա այն փաստացի աշխատանքային ընթացքն է, որն օգտագործվել է ընթացիկ նախագիծը `v3.4.7`-ի թարմացնելիս (օրինակը վերաբերում է պատմական տարբերակի․ ընթացիկ փաստացի տարբերակը `v3.8.0` է)։

## 11. Հաջողության ցուցիչներ

Հաջող տեղակայումից հետո մատյաններում պետք է ցուցադրվի հետևյալին նման բովանդակություն․

```text
[bootstrap] Secrets persisted to: /data/server.env
[DB] SQLite database ready: /data/storage.sqlite
```

Այս երկու կետերը կարևոր են․

- `/data/server.env`-ը հաստատում է, որ կատարման միջավայրի գաղտնիքները գրվել են մշտական հատորի վրա
- `/data/storage.sqlite`-ը հաստատում է, որ տվյալների բազան գրվել է մշտական հատորի վրա

Եթե փոխարենը տեսնում եք `/app/data/...`, ապա `DATA_DIR`-ը սխալ է կազմաձևված և պետք է անմիջապես ուղղվի։

## 12. Տարածված խնդիրներ

### 12.1 `Secrets` էջը դատարկ է

Սովորաբար կա երկու պատճառ․

- Դեռ չեք գործարկել `flyctl secrets set` հրամանը
- Դիտում եք այլ հավելված (օրինակ՝ `oroute`՝ `omniroute`-ի փոխարեն)

### 12.2 `flyctl deploy`-ը հաղորդում է `app not found`

Նախ ստեղծեք հավելվածը․

```powershell
flyctl apps create omniroute
```

### 12.3 `fly.toml`-ի վերլուծումը ձախողվում է

Ստուգեք հետևյալը․

- Արդյոք մեկնաբանություններում կան աղավաղված նիշեր
- Արդյոք TOML-ի չակերտավորումն ու նահանջները ճիշտ են

### 12.4 Տվյալները չեն պահպանվում

Ստուգեք հետևյալ երկու կետերը․

- `fly.toml`-ը պարունակում է `destination = '/data'`
- `DATA_DIR`-ը սահմանված է որպես `/data`

### 12.5 Կարո՞ղ է աշխատել առանց `INITIAL_PASSWORD`-ի

Այո, կարող է աշխատել։ Այդ դեպքում կօգտագործվի լռելյայն `CHANGEME` գաղտնաբառը։ Արտադրական միջավայրում խորհուրդ է տրվում հնարավորինս շուտ փոխել հետնամասի գաղտնաբառը։

## 13. Վերօգտագործում նոր նախագծերի համար

Եթե այս փաստաթղթին հետևելով տեղակայում եք նոր նախագիծ, անհրաժեշտ է փոխել միայն հետևյալ կետերը․

1. Փոխեք `app` արժեքը `fly.toml`-ում
2. Փոխեք `NEXT_PUBLIC_BASE_URL`-ը
3. Պահպանեք `DATA_DIR=/data`
4. Վերագեներացրեք `API_KEY_SECRET`, `JWT_SECRET`, `MACHINE_ID_SALT` և `STORAGE_ENCRYPTION_KEY` արժեքները
5. Առաջին տեղակայումից հետո ստուգեք, որ մատյանները գրվում են `/data`-ում

Մի վերօգտագործեք նախորդ նախագծի բանալիները։

## 14. Ընթացիկ նախագծի թողարկման նվազագույն ստուգաթերթ

Հետագա թողարկումների համար առավել հաճախ օգտագործվող հրամաններն են․

```powershell
flyctl deploy
```

1. `flyctl auth login`
2. `flyctl apps create omniroute`
3. `flyctl secrets set ... -a omniroute`
4. `flyctl deploy`
5. `flyctl logs --no-tail -a omniroute`
