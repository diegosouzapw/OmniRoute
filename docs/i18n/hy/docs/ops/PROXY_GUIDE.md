OmniRoute-ը ներառում է պրոքսիների կառավարման լիարժեք համակարգ, որը թույլ է տալիս AI մատակարարներին ուղղված ելքային թրաֆիկն ուղղորդել HTTP, HTTPS կամ SOCKS5 պրոքսիների միջոցով։ Անկախ նրանից՝ գտնվում եք արգելափակված տարածաշրջանում, IP-ների ռոտացիայի կարիք ունեք, թե ցանկանում եք կիրառել աննկատ մատնահետքերի ձևավորում՝ այս ուղեցույցն ընդգրկում է ամեն ինչ։

## Ինչո՞ւ օգտագործել պրոքսիներ

AI բազմաթիվ մատակարարներ սահմանափակում են հասանելիությունն ըստ աշխարհագրական տարածաշրջանի։ **Ռուսաստանում, Չինաստանում, Իրանում, Կուբայում, Թուրքիայում** և այլ երկրներում գտնվող մշակողները հանդիպում են հետևյալպիսի սխալների՝

```
unsupported_country_region_territory
```

Նույնիսկ արգելափակված տարածաշրջաններից դուրս պրոքսիներն օգտակար են հետևյալ դեպքերում՝

| Օգտագործման դեպք            | Նկարագրություն                                                                                |
| --------------------------- | --------------------------------------------------------------------------------------------- |
| **Աշխարհագրական շրջանցում** | Արգելափակված երկրներից OpenAI, Anthropic, Codex, Copilot ծառայությունների հասանելիություն     |
| **IP-ների ռոտացիա**         | Հարցումների բաշխում մի քանի IP-ների միջև՝ հաճախականության սահմանափակումներից խուսափելու համար |
| **Գաղտնիություն**           | Ձեր իրական IP-ի թաքցնում ելքային մատակարարներից                                               |
| **Համապատասխանություն**     | Թրաֆիկի ուղղորդում որոշակի իրավազորությունների միջոցով                                        |
| **Թեստավորում**             | Տարբեր տարածաշրջաններից ուղարկվող հարցումների նմանակում                                       |

### Հիմնական բաղադրիչներ

| Բաղադրիչ                    | Ֆայլ                                         | Դեր                                                                     |
| --------------------------- | -------------------------------------------- | ----------------------------------------------------------------------- |
| **Պրոքսիների ռեեստր**       | `src/lib/db/proxies.ts`                      | CRUD՝ պրոքսի գրառումների և գործողության շրջանակների նշանակումների համար |

## 4-մակարդակ պրոքսի համակարգ

OmniRoute-ն աջակցում է պրոքսիի կազմաձևմանը **չորս անկախ տիրույթներում**, որոնք որոշվում են ըստ առաջնահերթության՝

```
Առաջնահերթության որոշման կարգը (ամենաբարձրից → ամենացածր).

  1. 🔵 Հաշվի/միացման պրոքսի  →  յուրաքանչյուր API բանալու / OAuth միացման համար
  2. 🟡 Մատակարարի պրոքսի     →  յուրաքանչյուր մատակարարի համար (օրինակ՝ OpenAI-ի ամբողջ տրաֆիկը)
  3. 🟠 Համակցման պրոքսի      →  յուրաքանչյուր համակցման/երթուղավորման կազմաձևման համար
  4. 🟢 Գլոբալ պրոքսի         →  ամբողջ տրաֆիկը, բոլոր մատակարարները
```

### Ինչպես է աշխատում որոշումը

Երբ OmniRoute-ը հարցում է ուղարկում վերին մակարդակի մատակարարին, այն կանչում է `resolveProxyForConnectionFromRegistry()` ֆունկցիան, որը հերթականությամբ ստուգում է յուրաքանչյուր մակարդակը՝

1. **Հաշվի մակարդակ** — Արդյո՞ք տվյալ միացման ID-ին պրոքսի է նշանակված։
2. **Մատակարարի մակարդակ** — Արդյո՞ք տվյալ մատակարարին (օրինակ՝ `openai`) պրոքսի է նշանակված։
3. **Գլոբալ մակարդակ** — Արդյո՞ք գլոբալ պրոքսի է կազմաձևված։
4. **Առանց պրոքսիի** — Ուղիղ միացում մատակարարին։

Օգտագործվում է առաջին համընկնումը։ Սա նշանակում է, որ կարող եք գլոբալ պրոքսին սահմանել որպես պահուստային տարբերակ, սակայն վերասահմանել այն որոշակի մատակարարների կամ միացումների համար։

### Ինչն է անցնում պրոքսիով

| Տրաֆիկի տեսակը          | Պրոքսիավորվո՞ւմ է | Նշումներ                                                |
| ----------------------- | ----------------- | ------------------------------------------------------- |
| Չատի լրացումներ         | ✅                | Բոլոր `/v1/chat/completions` հարցումները                |
| Ներդրումներ             | ✅                | `/v1/embeddings`                                        |
| Պատկերների գեներացում   | ✅                | `/v1/images/generations`                                |
| Ձայնանյութ (TTS/STT)    | ✅                | `/v1/audio/*`                                           |
| OAuth թոքենի փոխանակում | ✅                | Լուծում է `unsupported_country_region_territory` խնդիրը |
| Միացման ստուգումներ     | ✅                | «Ստուգել միացումը» կոճակն օգտագործում է պրոքսի          |
| Թոքենի թարմացում        | ✅                | OAuth-ի ֆոնային թարմացում                               |
| Մոդելների համաժամացում  | ✅                | Մոդելների ցուցակագրում և հայտնաբերում                   |

## Պրոքսիների ռեեստր (CRUD)

Պրոքսիների ռեեստրը SQLite աղյուսակ է (`proxy_registry`), որը պահում է ձեր բոլոր պրոքսիները։ Յուրաքանչյուր պրոքսի ունի՝

| Դաշտ       | Տեսակ      | Նկարագրություն                                           |
| ---------- | ---------- | -------------------------------------------------------- |
| `id`       | UUID       | Եզակի նույնացուցիչ                                       |
| `name`     | Տող        | Մարդու համար ընթեռնելի պիտակ                             |
| `type`     | Տող        | Արձանագրություն՝ `http`, `https`, `socks5`               |
| `host`     | Տող        | Պրոքսիի հոսթանունը կամ IP հասցեն                         |
| `port`     | Ամբողջ թիվ | Պորտի համարը                                             |
| `username` | Տող        | Նույնականացման օգտանունը (պահպանման ժամանակ կոդավորված)  |
| `password` | Տող        | Նույնականացման գաղտնաբառը (պահպանման ժամանակ կոդավորված) |
| `region`   | Տող        | Աշխարհագրական տարածաշրջանի պիտակ                         |
| `notes`    | Տող        | Ազատ ձևաչափով նշումներ                                   |
| `status`   | Տող        | `active` կամ `inactive`                                  |
| `source`   | Տող        | `manual` կամ `oneproxy`                                  |

### Պրոքսիի ստեղծում

**Կառավարման վահանակի միջոցով՝**

1. Անցեք **Կարգավորումներ → Պրոքսի**
2. Սեղմեք **Ավելացնել պրոքսի**
3. Լրացրեք տեսակը, հոսթը, պորտը և նույնականացման ոչ պարտադիր տվյալները
4. Պահպանեք

**API-ի միջոցով՝**

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "US Proxy",
    "type": "http",
    "host": "proxy.example.com",
    "port": 8080,
    "username": "user",
    "password": "pass",
    "region": "US"
  }'
```

### Պրոքսիի թարմացում

```bash
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "id": "proxy-uuid-here",
    "host": "new-proxy.example.com",
    "port": 9090
  }'
```

> **Նշում․** Նույնականացման տվյալները պահպանվում են, եթե բացահայտորեն չեք ուղարկում նոր՝ ոչ դատարկ արժեքներ։ `username`/`password` դաշտերի համար դատարկ տողեր ուղարկելու դեպքում պահպանված արժեքները կմնան անփոփոխ։

### Պրոքսիի ջնջում

```bash
# Չի հաջողվում, եթե պրոքսին նշանակված է որևէ տիրույթի
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid"

# Հարկադիր ջնջում (նաև հեռացնում է նշանակումները)
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid&force=1"
```

### Պրոքսիների ցուցակագրում

```bash
curl "http://localhost:20128/api/v1/management/proxies?limit=50&offset=0"
```

### Պրոքսիների նշանակում տիրույթներին

```bash
# Նշանակել գլոբալ տիրույթին
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "global", "proxy": {"type":"http","host":"proxy.example.com","port":8080}}'

# Նշանակել որոշակի մատակարարի
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "provider", "id": "openai", "proxy": {"type":"socks5","host":"socks.example.com","port":1080}}'

# Նշանակել որոշակի միացման/բանալու
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "key", "id": "connection-uuid", "proxy": {"type":"http","host":"key-proxy.com","port":3128}}'
```

### Գործող պրոքսիի որոշում

Ստուգեք, թե որ պրոքսին կօգտագործվի տվյալ միացման համար՝

```bash
curl "http://localhost:20128/api/settings/proxy?resolve=connection-uuid"
```

Վերադարձնում է որոշված պրոքսին՝ դրա մակարդակով (`account`, `provider` կամ `global`) և աղբյուրով։

### Զանգվածային նշանակում

Միևնույն պրոքսին միանգամից նշանակեք մի քանի մատակարարների կամ միացումների՝

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies/bulk-assign \
  -H "Content-Type: application/json" \
  -d '{
    "scope": "provider",
    "scopeIds": ["openai", "anthropic", "codex"],
    "proxyId": "proxy-uuid"
  }'
```

### Ներմուծում/արտահանում

Պրոքսիները ներառված են **Պահուստավորում/վերականգնում** համակարգում։ OmniRoute-ի կազմաձևումն արտահանելիս՝

1. Անցեք **Կառավարման վահանակ → Կարգավորումներ → Պահուստավորում**
2. Սեղմեք **Արտահանել** — պրոքսիների ռեեստրն ու նշանակումները ներառված են
3. Վերականգնելու համար սեղմեք **Ներմուծել** և վերբեռնեք պահուստային ֆայլը

Պրոքսիների ռեեստրը նաև աջակցում է **upsert ըստ host+port-ի** գործառույթին․ եթե ներմուծում եք արդեն գոյություն ունեցող պրոքսի (նույն հոսթով և պորտով), կրկնօրինակ ստեղծելու փոխարեն այն թարմացվում է։

### Հին տարբերակից միգրացիա

Եթե պրոքսիները կազմաձևել եք ավելի հին տարբերակում (ռեեստրից առաջ), OmniRoute-ն ավտոմատ կերպով տեղափոխում է դրանք․

```
Հին key_value պահոց → proxy_registry + proxy_assignments
```

Դա կատարվում է մեկ անգամ՝ թարմացումից հետո առաջին գործարկման ժամանակ։ Կրկին գործարկելու համար օգտագործեք `migrateLegacyProxyConfigToRegistry({ force: true })`։

## 1proxy անվճար պրոքսիների շուկա

> 🆕 **Ներդրվել է [@oyi77](https://github.com/oyi77)-ի կողմից** — PR [#1847](https://github.com/diegosouzapw/OmniRoute/pull/1847) (Խնդիր [#1788](https://github.com/diegosouzapw/OmniRoute/issues/1788))

OmniRoute-ը ինտեգրվում է **[1proxy](https://1proxy-api.aitradepulse.com)** համայնքային հարթակի հետ՝ ամբողջ աշխարհից **հարյուրավոր անվճար, վավերացված պրոքսիների** հասանելիություն ապահովելու համար։ Սա կատարյալ լուծում է այն օգտատերերի համար, որոնք չունեն սեփական պրոքսի ենթակառուցվածք։

### Ինչպես է այն աշխատում

```
┌─────────────┐  Համաժամացում  ┌─────────────────┐  Հերթափոխում  ┌─────────────┐
│  1proxy API │ ─────────────▶ │  proxy_registry  │ ────────────▶ │ Մատակարարի │
│  (արտաքին)  │  մինչև 500     │  source=oneproxy │  ըստ որակի    │     API     │
└─────────────┘  պրոքսի        └─────────────────┘               └─────────────┘
```

1. **Համաժամացում** — OmniRoute-ը 1proxy API-ից ստանում է վավերացված պրոքսիներ
2. **Պահպանում** — Պրոքսիները պահվում են նույն `proxy_registry` աղյուսակում՝ `source = 'oneproxy'` արժեքով
3. **Զտում** — Զտում ըստ արձանագրության, երկրի և որակի գնահատականի
4. **Հերթափոխում** — Ընտրում է լավագույն պրոքսին՝ օգտագործելով որակային, պատահական կամ հաջորդական ռազմավարություններ
5. **Ավտոմատ վատթարացում** — Խափանված պրոքսիների որակի գնահատականը նվազեցվում է․ շեմից ցածր լինելու դեպքում → նշվում են որպես ոչ ակտիվ

### Պրոքսիների համաժամացում

**Կառավարման վահանակի միջոցով․**

1. Անցեք **Settings → 1proxy** ներդիր
2. Սեղմեք **«Sync Now»**
3. Դիտեք վիճակագրությունը՝ պրոքսիների ընդհանուր քանակը, ակտիվների քանակը, միջին որակը և բաշխումն ըստ երկրների

**API-ի միջոցով․**

```bash
# Գործարկել համաժամացումը
curl -X POST http://localhost:20128/api/settings/oneproxy \
  -H "Content-Type: application/json" \
  -d '{}'

# Պատասխան․
# { "success": true, "added": 127, "updated": 45, "failed": 2, "total": 172 }
```

### Պրոքսիների զտում

```bash
# Զտել ըստ արձանագրության
curl "http://localhost:20128/api/settings/oneproxy?protocol=socks5"

# Զտել ըստ երկրի
curl "http://localhost:20128/api/settings/oneproxy?countryCode=US"

# Զտել ըստ որակի նվազագույն գնահատականի
curl "http://localhost:20128/api/settings/oneproxy?minQuality=80"

# Համակցել զտիչները
curl "http://localhost:20128/api/settings/oneproxy?protocol=http&countryCode=DE&minQuality=70"
```

### Պրոքսիների որակի գնահատականներ

Յուրաքանչյուր 1proxy պրոքսի ունի մետատվյալներ․

| Դաշտ            | Նկարագրություն                                                 |
| --------------- | -------------------------------------------------------------- |
| `qualityScore`  | 1proxy-ի վավերացման 0-100 գնահատականը                          |
| `latencyMs`     | Չափված ցանցային ուշացումը                                      |
| `anonymity`     | `transparent`, `anonymous` կամ `elite`                         |
| `googleAccess`  | Արդյոք պրոքսին հասանելիություն ունի Google-ի ծառայություններին |
| `countryCode`   | Երկտառ ISO երկրի կոդը                                          |
| `lastValidated` | Վերջին վավերացման ժամանակային դրոշմը                           |

Որակի գնահատականները դինամիկորեն ճշգրտվում են․

- **Ձախողված հարցումները** նվազեցնում են գնահատականը 10 միավորով
- **Գնահատականը նվազում է մինչև ≤10** → պրոքսին նշվում է որպես `inactive`
- Ոչ ակտիվ պրոքսիները բացառվում են հերթափոխից

### Հերթափոխման ռազմավարություններ

```bash
# Հերթափոխել ըստ որակի (լավագույն պրոքսին՝ առաջինը) — լռելյայն
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -H "Content-Type: application/json" \
  -d '{"strategy": "quality"}'

# Պատահական հերթափոխում
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -d '{"strategy": "random"}'

# Հաջորդական (առաջինը՝ ամենավաղ վավերացվածը)
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -d '{"strategy": "sequential"}'
```

### Խափանումներից պաշտպանության մեխանիզմ

1proxy-ի համաժամացումն ունի ներկառուցված խափանումներից պաշտպանության մեխանիզմ․

- **Համաժամացման 5 անընդմեջ ձախողումից** հետո համաժամացման հետագա փորձերն արգելափակվում են
- Վերակայեք `resetOneproxyCircuitBreaker()`-ի միջոցով կամ վերագործարկեք սերվերը
- Համաժամացման կարգավիճակը հասանելի է `GET /api/settings/oneproxy?action=status` հասցեով

### 1proxy պրոքսիների մաքրում

```bash
# Ջնջել մեկ 1proxy պրոքսի
curl -X DELETE "http://localhost:20128/api/settings/oneproxy?id=proxy-uuid"

# Մաքրել ԲՈԼՈՐ 1proxy պրոքսիները (ձեռքով ավելացված պրոքսիները չեն փոփոխվում)
curl -X DELETE "http://localhost:20128/api/settings/oneproxy?clearAll=1"
```

## Հայտնաբերումից խուսափում և քողարկում

OmniRoute-ը ոչ միայն ուղղորդում է տրաֆիկը պրոքսիի միջոցով, այլև ապահովում է, որ տրաֆիկը օրինական տեսք ունենա։

### TLS մատնահետքի կեղծում

Օգտագործում է `wreq-js`՝ դիտարկիչին բնորոշ TLS մատնահետքեր ստեղծելու համար՝ շրջանցելով բոտերի հայտնաբերման համակարգերը, որոնք նշում են ոչ դիտարկչային TLS հաստատումները։

### CLI մատնահետքի համապատասխանեցում

**CLI մատնահետքի փոխարկիչը** (`Settings → Security`) վերադասավորում է HTTP վերնագրերը և JSON մարմնի դաշտերը՝ դրանք համապատասխանեցնելով բնիկ CLI երկուական ֆայլերի ճշգրիտ ստորագրությանը (Claude Code, Codex և այլն)։ Սա գործում է պրոքսիին **զուգահեռ**․

```
Ձեր IP-ն (արգելափակված) → Պրոքսիի IP-ն (US) → Մատակարարի API
                          + TLS կեղծում
                          + CLI մատնահետք
```

Դուք միաժամանակ ստանում եք և՛ **IP-ի քողարկում**, և՛ **հարցման իսկության ապահովում**։

### Պրոքսիի IP-ի պահպանում

Կառավարման վահանակի գունային նշանները ցույց են տալիս, թե պրոքսիի որ մակարդակն է ակտիվ․

| Նշան | Մակարդակ  | Նշանակություն                                        |
| ---- | --------- | ---------------------------------------------------- |
| 🟢   | Գլոբալ    | Ամբողջ տրաֆիկն անցնում է այս պրոքսիի միջոցով         |
| 🟡   | Մատակարար | Պրոքսիավորվում է միայն այս մատակարարի տրաֆիկը        |
| 🔵   | Միացում   | Այս կոնկրետ բանալին/հաշիվն օգտագործում է այս պրոքսին |

Ստուգման համար նշանը նաև ցուցադրում է որոշված պրոքսիի IP-ն։

## Վերին մակարդակի պրոքսիի ռեժիմներ

CLIProxyAPI ձևանմուշն օգտագործող մատակարարների համար OmniRoute-ն աջակցում է վերին մակարդակի պրոքսիի երեք ռեժիմ․

| Ռեժիմ         | Նկարագրություն                                                         |
| ------------- | ---------------------------------------------------------------------- |
| `native`      | OmniRoute-ն անմիջականորեն կառավարում է պրոքսիով ուղղորդումը (լռելյայն) |
| `cliproxyapi` | Կառավարումը փոխանցում է արտաքին CLIProxyAPI օրինակին                   |
| `fallback`    | Նախ փորձում է բնիկ եղանակը, ապա անցնում է CLIProxyAPI-ին               |

Կարգավորեք յուրաքանչյուր մատակարարի համար առանձին․

```bash
curl -X PUT "http://localhost:20128/api/upstream-proxy/openai" \
  -H "Content-Type: application/json" \
  -d '{"mode": "native", "enabled": true}'
```

## Կառավարման վահանակի միջերես

### Settings → Proxy ներդիր

- **Գլոբալ պրոքսիի** կարգավորում (մեկ անգամ՝ ամբողջ տրաֆիկի համար)
- **Յուրաքանչյուր մատակարարի համար պրոքսիի** վերագրումներ
- **Յուրաքանչյուր միացման համար պրոքսիի** նշանակումներ
- **Միացման ստուգում** կարգավորված պրոքսիի միջոցով
- **Գունային նշաններ**, որոնք ցույց են տալիս պրոքսիի ակտիվ մակարդակը

### Settings → 1proxy ներդիր

- **Sync Now** կոճակ՝ անվճար պրոքսիներ ստանալու համար
- **Վիճակագրության քարտեր**՝ Ընդամենը, Ակտիվ, Միջին որակ, Վերջին համաժամացում
- **Զտիչներ**՝ Արձանագրություն, Երկրի կոդ, Նվազագույն որակ
- **Պրոքսիների աղյուսակ**՝ հոսթով, արձանագրությամբ, երկրով, որակի գնահատականով, ուշացմամբ, անանունությամբ և Google-ի հասանելիությամբ
- **Համաժամացման կարգավիճակի** վահանակ՝ հաջողությունների/ձախողումների հետևմամբ և հաջորդական ձախողումների քանակով
- **Clear All**՝ 1proxy-ի բոլոր գրառումները հեռացնելու համար

## Խնդիրների լուծում

### «SOCKS5 պրոքսին անջատված է»

Ձեր `.env` ֆայլում սահմանեք `ENABLE_SOCKS5_PROXY=true` և վերագործարկեք։

### «socket hang up» սխալներ պրոքսիի միջոցով

Սա սովորական է էժան պրոքսիների դեպքում, որոնք ընդհատում են անգործուն կապերը։ OmniRoute-ն արդեն մշակում է սա՝

- Անջատելով keep-alive-ը պրոքսի կապերի համար (`keepAliveTimeout: 1`)
- Անջատելով pipelining-ը (`pipelining: 0`)
- Քեշավորելով dispatcher-ները՝ կրկնվող handshake-ներից խուսափելու համար

Եթե խնդիրը շարունակվում է, փորձեք այլ պրոքսի կամ օգտագործեք 1proxy-ի ռոտացիայի գործառույթը։

### «unsupported_country_region_territory» OAuth-ի ընթացքում

Համոզվեք, որ պրոքսին կազմաձևված է **մինչև** OAuth հոսքը սկսելը։ OmniRoute-ն OAuth թոքենների փոխանակումն ուղղորդում է կազմաձևված պրոքսիի միջոցով։ Նախ սահմանեք գլոբալ կամ մատակարարի մակարդակի պրոքսի, ապա միացեք։

### Պրոքսին չի օգտագործվում

Ստուգեք լուծման հերթականությունը՝

1. Ստուգեք `GET /api/settings/proxy?resolve=your-connection-id`-ի միջոցով
2. Ստուգեք՝ արդյոք պրոքսիի `status`-ը `active` է (ոչ թե `inactive`)
3. Համոզվեք, որ պրոքսիի նշանակման տիրույթը համապատասխանում է ձեր կապին

### 1proxy-ի համաժամացումը ձախողվում է

Ստուգեք համաժամացման կարգավիճակը՝

```bash
curl "http://localhost:20128/api/settings/oneproxy?action=status"
```

Եթե `consecutiveFailures >= 5`, ապա circuit breaker-ը գործարկվել է։ Վերագործարկեք սերվերը՝ այն վերակայելու համար, կամ սպասեք ձեռքով վերակայմանը։

## Տվյալների բազայի սխեմա

### `proxy_registry` աղյուսակ

```sql
CREATE TABLE proxy_registry (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  type TEXT NOT NULL DEFAULT 'http',
  host TEXT NOT NULL,
  port INTEGER NOT NULL,
  username TEXT DEFAULT '',
  password TEXT DEFAULT '',
  region TEXT,
  notes TEXT,
  status TEXT DEFAULT 'active',
  source TEXT NOT NULL DEFAULT 'manual',    -- 'manual' կամ 'oneproxy'
  quality_score INTEGER,                     -- 0-100 (միայն 1proxy)
  latency_ms INTEGER,                        -- միլիվայրկյաններ (միայն 1proxy)
  anonymity TEXT,                            -- թափանցիկ/անանուն/էլիտար
  google_access INTEGER DEFAULT 0,           -- կարո՞ղ է հասանելիություն ստանալ Google-ին (1proxy)
  last_validated TEXT,                       -- ISO ժամանակային դրոշմ (1proxy)
  country_code TEXT,                         -- ISO երկտառ կոդ (1proxy)
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

### `proxy_assignments` աղյուսակ

```sql
CREATE TABLE proxy_assignments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  proxy_id TEXT NOT NULL REFERENCES proxy_registry(id),
  scope TEXT NOT NULL,        -- 'global', 'provider', 'account', 'combo'
  scope_id TEXT,              -- մատակարարի ID, կապի ID կամ համակցության ID
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE(scope, scope_id)
);
```

## Պրոքսիի աշխատունակության ստուգում (v3.8.16+)

OmniRoute-ի **պրոքսիի արագ ձախողման** մեխանիզմը (`src/lib/proxyHealth.ts`) արագ TCP կապի ստուգման միջոցով հայտնաբերում է չաշխատող պրոքսիները <2վ-ում, այնուհետև **քեշավորում է արդյունքը**՝ յուրաքանչյուր հարցման լրացուցիչ ծախսերից խուսափելու համար։

### Ինչպես է այն աշխատում

```
Հարցում ──▶ ProxyHealthCache.get(url)
             │
             ├─ Քեշում կա + թա՞րմ է  ──▶ վերադարձնել քեշավորված կարգավիճակը
             │
             └─ Քեշում չկա / հնացա՞ծ է  ──▶ TCP կապ host:port-ին
                                              (ժամանակի սահմանաչափ՝ FAST_FAIL_TIMEOUT_MS)
                                              ──▶ քեշավորել HEALTH_CACHE_TTL_MS ժամանակով
                                              ──▶ վերադարձնել արդյունքը
```

Առանց դրա՝ չաշխատող պրոքսին կարգելափակեր յուրաքանչյուր հարցում ամբողջ `PROXY_TIMEOUT_MS` ժամանակով (լռելյայն՝ 30վ), մինչև ձախողվելը։

### Կարգավորվող միջավայրի փոփոխականներ

| Փոփոխական                    | Լռելյայն | Նպատակ                                                     |
| ---------------------------- | -------- | ---------------------------------------------------------- |
| `PROXY_FAST_FAIL_TIMEOUT_MS` | `2000`   | TCP կապի ժամանակի սահմանաչափ՝ յուրաքանչյուր ստուգման համար |
| `PROXY_HEALTH_CACHE_TTL_MS`  | `30000`  | Որքան ժամանակ է քեշավորվում աշխատունակության արդյունքը     |

**Առաջարկվող արժեքներ՝**

| Սցենար                                   | Արագ ձախողման ժամանակի սահմանաչափ | Քեշի TTL | Հիմնավորում                                                                         |
| ---------------------------------------- | --------------------------------- | -------- | ----------------------------------------------------------------------------------- |
| Բարձր թողունակությամբ API gateway        | 1500ms                            | 60000ms  | Ագրեսիվ արագ ձախողում, ավելի երկար քեշ՝ ստուգումների քանակը նվազեցնելու համար       |
| Աշխարհագրորեն բաշխված հանգույցներ        | 3000ms                            | 15000ms  | Դանդաղ ցանցերին ավելի շատ ժամանակ է պետք, իսկ կարճ քեշը՝ արագ failover-ի համար      |
| Մշակում / թեստավորում                    | 1000ms                            | 10000ms  | Տեղային պրոքսիների վրա արագ կրկնափորձարկում                                         |
| Գաղտնիություն / հայտնաբերումից խուսափում | 2500ms                            | 45000ms  | Խուսափել արագ զոնդավորումից, որը կարող է գործարկել հաճախականության սահմանափակումներ |

### Պրոքսիի աշխատունակության ստուգում

```ts
import { getAllProxyHealthStatuses, invalidateProxyHealth } from "omniroute/proxyHealth";

const statuses = getAllProxyHealthStatuses();
for (const s of statuses) {
  console.log(`${s.proxyUrl} → healthy=${s.healthy}, stale=${s.stale}`);
}

// Հարկադրաբար կրկին ստուգել որոշակի պրոքսին
invalidateProxyHealth("http://user:pass@203.0.113.7:8080");
```

`stale` դրոշը `true` է, երբ քեշի գրառումը գերազանցել է `HEALTH_CACHE_TTL_MS`-ը, և հաջորդ հարցումը նոր ստուգում կգործարկի։

### Լռելյայն արժեքներ՝ ըստ պրոքսիի տեսակի

Աշխատունակության ստուգումն օգտագործում է URL սխեմայի վրա հիմնված ողջամիտ լռելյայն արժեքներ՝

| Սխեմա                      | Լռելյայն պորտ |
| -------------------------- | ------------- |
| `http://`                  | 8080          |
| `https://`                 | 443           |
| `socks5://` / `socks5h://` | 1080          |

URL-ում նշված հատուկ պորտերը (`http://host:9999`) միշտ գերակա են սխեմայի լռելյայն արժեքի նկատմամբ։

## Պրոքսիի վերլուծություն և դիտարկելիություն

OmniRoute-ը հետևում է յուրաքանչյուր պրոքսիի օգտագործմանը՝ օգնելով օպերատորներին ախտորոշել երթուղավորման օրինաչափությունները, ուշացման կտրուկ աճերը և կրկնվող խափանումները։

### Ինչին է հետևում համակարգը

Կարգավորված պրոքսիով անցնող յուրաքանչյուր հարցման համար OmniRoute-ը գրանցում է՝

| Չափանիշ      | Նկարագրություն                                                   |
| ------------ | ---------------------------------------------------------------- |
| `proxy_url`  | Պրոքսիի ամբողջական URL-ը (նույնականացման տվյալները քողարկված են) |
| `provider`   | Վերին հոսքի մատակարարի ID-ն (openai, anthropic և այլն)           |
| `latency_ms` | Ընդհանուր երկկողմանի ժամանակը՝ ներառյալ պրոքսիի կապի հաստատումը  |
| `connect_ms` | Միայն TCP կապի հաստատման ժամանակը                                |
| `status`     | Վերին հոսքից ստացված HTTP կարգավիճակի կոդը                       |
| `error`      | Սխալի դասը, եթե հարցումը ձախողվել է                              |
| `timestamp`  | ISO 8601 UTC                                                     |

### Տվյալներին հասանելիություն

```bash
# Պրոքսիի վերջին իրադարձությունները
curl -H "Authorization: Bearer $OMNIROUTE_KEY" \
  "http://localhost:20128/api/usage/proxy-logs?limit=100"
```

Իրական վերջնակետը `/api/usage/proxy-logs` է (տես՝ `src/app/api/usage/proxy-logs/route.ts`)։ Այս վերջնակետն աջակցում է՝

- `GET /api/usage/proxy-logs` — ստանալ պրոքսիի մատյանները
- `DELETE /api/usage/proxy-logs` — մաքրել պրոքսիի բոլոր մատյանները

Անհրաժեշտության դեպքում համախմբված վիճակագրությունը կարելի է SQL-ի միջոցով անմիջապես հարցել `proxy_logs` աղյուսակից։ Վահանակի միջերեսը կարող է առաջարկել համախմբված ներկայացումներ։

### Տարածված օրինաչափություններ

**Հայտնաբերել անկայուն պրոքսին** (հաջող և ձախողված վիճակների միջև հերթագայվող)՝

```sql
SELECT proxy_url,
       COUNT(*) AS total,
       SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) AS errors,
       ROUND(100.0 * SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) / COUNT(*), 1) AS error_pct
FROM proxy_logs
WHERE timestamp > datetime('now', '-1 hour')
GROUP BY proxy_url
HAVING error_pct > 5
ORDER BY error_pct DESC;
```

**Գտնել դանդաղ պրոքսիները** (p95 ուշացում > 2վ)՝

```sql
WITH ranked AS (
  SELECT proxy_url, latency_ms,
         PERCENT_RANK() OVER (PARTITION BY proxy_url ORDER BY latency_ms) AS pct
  FROM proxy_logs
  WHERE timestamp > datetime('now', '-24 hour')
)
SELECT proxy_url, latency_ms
FROM ranked
WHERE pct >= 0.95
ORDER BY latency_ms DESC;
```

## Ռոտացիայի ռազմավարության որոշման ծառ

Երբ մեկ տիրույթին նշանակված են մի քանի պրոքսիներ, OmniRoute-ն օգտագործում է **ռոտացիայի ռազմավարություն**՝ յուրաքանչյուր հարցման համար օգտագործվող պրոքսին ընտրելու նպատակով։ Ռազմավարությունը կարգավորվում է տիրույթի մակարդակում (գլոբալ, ըստ մատակարարի, ըստ հաշվի, ըստ համակցման)։

### Հասանելի ռազմավարություններ

| Ռազմավարություն      | Երբ օգտագործել                                   | Փոխզիջում                                                                                     |
| -------------------- | ------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| `quality` (լռելյայն) | Արտադրական միջավայրում՝ տարբեր որակի պրոքսիներով | Նախապատվություն է տալիս բարձր գնահատված պրոքսիներին․ ցածր գնահատվածները կարող են չօգտագործվել |
| `random`             | Բեռնվածության բաշխում, գաղտնիություն             | Հավասարաչափ բաշխում․ անտեսում է որակի ազդանշանները                                            |
| `sequential`         | Վրիպազերծում, կանխորոշված թեստավորում            | Պրոքսիներով անցնում է հերթականությամբ․ վարքագիծը հեշտ է հասկանալ                              |

### Որոշման ծառ

```
                    Ունե՞ք ձեր պրոքսիների որակի գնահատականները։
                    │
        ┌───────────┴───────────┐
        │                       │
       ԱՅՈ                     ՈՉ
        │                       │
   Արդյո՞ք բոլոր              │
   պրոքսիները մոտավորապես       │
   նույն որակն ունեն։           │
        │                       │
   ┌────┴────┐                  │
   │         │                  │
  ԱՅՈ       ՈՉ              Օգտագործեք
   │         │              `random`
   │         │              (հավասարաչափ
   │         │              բաշխումը ժամանակի
   │         │              ընթացքում որակի
   │         │              տվյալներ է կուտակում)
   │         │
   │    Օգտագործեք `quality`
   │    (լավագույնը տարբեր
   │    որակների դեպքում)
   │
Օգտագործեք `random`
(բեռնվածությունը
հավասարաչափ բաշխելու համար)
```

## Ձեր սեփական պրոքսիների խափանումների ավտոմատ բացառում

1proxy-ի marketplace pool-ն արդեն ինքնուրույն ավտոմատ կերպով իջեցնում է խափանված պրոքսիների վարկանիշը (տե՛ս
[Պրոքսիների որակի գնահատականներ](#proxy-quality-scores))։ Registry-ում **ձեր** ավելացրած
պրոքսիների համար ֆոնային հասանելիության ժամանակացույցը
(`src/lib/proxyHealth/scheduler.ts`) ապահովում է նույն՝ «չաշխատող անդամին շղթայից
ավտոմատ կերպով բացառելու» վարքագիծը՝ առանց որևէ բան ջնջելու․

```bash
# .env — 3 հաջորդական ձախողված ստուգումից հետո ժամանակավորապես անջատել պրոքսին և
# այն ավտոմատ կերպով կրկին միացնել, երբ նորից սկսի պատասխանել ստուգումներին։
PROXY_AUTO_DISABLE=true
PROXY_AUTO_REMOVE_AFTER=3
```

Ինչպես է այն գործում բազմապրոքսի շղթայում․

1. Ժամանակացույցը ստուգում է գրանցված յուրաքանչյուր պրոքսի՝ յուրաքանչյուր `PROXY_HEALTH_INTERVAL_MS`
   ժամանակահատվածում (կանխադրվածը՝ 10 րոպե, նվազագույնը՝ 1 րոպե)։
2. `PROXY_AUTO_REMOVE_AFTER` թվով հաջորդական **հաստատված** խափանումներից հետո (իրական
   կապի խափանում. ժամանակի սպառումը կամ ստուգման թիրախի սեփական 5xx պատասխանը երբեք
   չի հաշվարկվում, տե՛ս [Պրոքսիի հասանելիության ստուգում](#proxy-health-checking-v3816)) պրոքսիի `status`-ը
   սահմանվում է որպես `dead`։
3. `dead`-ը այն կարգավիճակներից է, որոնք pool/rotation-ի որոշման ժամանակ օգտագործվող՝
   աշխատող կարգավիճակների զտիչը բացառում է, ուստի տվյալ scope-ի ռոտացիան (round-robin / random / sticky /
   latency — տե՛ս [Ռոտացիայի ռազմավարության որոշումների ծառ](#rotation-strategy-decision-tree))
   անմիջապես դադարում է այդ պրոքսին տրամադրել նոր հարցումներին։ Pool-ի մյուս պրոքսիներից
   ոչ մեկը չի ազդվում, և ամբողջ pool-ը երբեք աննկատ չի անցնում ուղիղ կապի․
   տե՛ս [4-մակարդակ պրոքսի համակարգի](#4-level-proxy-system)՝ ձախողման դեպքում կապը
   փակ պահող պաշտպանությունը։
4. Ժամանակացույցը շարունակում է նույն պարբերականությամբ ստուգել `dead` պրոքսիները։
   Հաջորդ հաջող ստուգումը `status`-ը կրկին փոխում է `active`-ի, և պրոքսին վերադառնում է
   ռոտացիա՝ առանց ձեռքով նորից ավելացնելու անհրաժեշտության։

Սա միտումնավոր **ըստ ցանկության միացվող և ոչ կործանարար** գործառույթ է․ կանխադրված
կարգավորմամբ ժամանակացույցը միայն հաշվում և գրանցամատյանում արձանագրում է խափանումները
(տե՛ս C քաղաքականությունը `decision.ts`-ում), իսկ `PROXY_AUTO_DISABLE`-ը երբեք տող չի
ջնջում. դրա համար նախատեսված է առանձին, ավելի ագրեսիվ `PROXY_AUTO_REMOVE` դրոշը։
Եթե երկուսն էլ սահմանված են որպես `true`, առաջնահերթ է `PROXY_AUTO_REMOVE`-ը
(ջնջման ենթակա պրոքսին մինչ այդ ժամանակավորապես անջատելն իմաստ չունի)։ Փոփոխականների
ամբողջական ցանկի համար տե՛ս [Միջավայրի կազմաձևում](../reference/ENVIRONMENT.md)
տեղեկատուն։
