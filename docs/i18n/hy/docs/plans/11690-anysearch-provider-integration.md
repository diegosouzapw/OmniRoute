Կաղապար՝ xquik #11370 (միավորված է release/v3.8.51-ում)։ Ռեժիմ՝ `fallbackOnly`։
Վերին հոսքի առաջարկ՝ issue diegosouzapw/OmniRoute#11637։

## 1. Ծառայության փաստացի տվյալները (պաշտոնական փաստաթղթեր, խաչաձև ստուգված)

- Հիմնական URL՝ `https://api.anysearch.com` (REST) + `POST /mcp` (MCP, JSON-RPC 2.0)։
- `POST /v1/search` - պարամետրեր՝ `query` (պարտադիր), `max_results` (1-10, լռելյայն՝ 10), `tag` (`{domain}.{sub_domain}` ուղղահայաց երթուղավորում), `zone` (cn/intl), `language`, `params` (կառուցվածքային ուղղահայաց դաշտեր), `format` (json/markdown)։
- `GET /v1/sub-domains?domain=...` - հնարավորությունների կատալոգ, ՉԻ հաշվարկվում քվոտայի մեջ։
- `POST /v1/extract` - ստանում/արտահանում է `{url, title, content}`-ը․ խիստ JSON մարմին, 16 KiB սահմանաչափ։
- `POST /v1/auth/email/register` - մեկ կանչով գրանցում, վերադարձնում է մեկանգամյա բաց տեքստով `as_sk_...` բանալի։
- Նույնականացում՝ կամընտրական `Authorization: Bearer <as_sk_...>`․ անանուն հասանելիությունը սահմանափակվում է մեկ IP-ի համար սահմանաչափերով՝ սպառելով օրական անվճար քվոտան․ անվավեր բանալին վերադարձնում է 401/403՝ ԱՌԱՆՑ աննկատ անանուն հետադարձ անցման։
- Անվճար մակարդակ՝ օրական 1000 հարցում, մեկ բանալու համար՝ 20 QPS։ Վճարովի մակարդակ՝ գինը սահմանված չէ (Շուտով)։
- Պատասխանի փաթեթ՝ հաջողություն՝ `{code: 0, message: "success", request_id, data}`․ ձախողում՝ `{code: -1, message}`։ Նույնականացման/քվոտայի սխալները չեն պարունակում կառուցվածքային `error_code` (`message`-ի տեքստն է ազդանշանը)․ արտահանմանը հատուկ սխալները պարունակում են `error_code` (`invalid_extract_url`, `extract_failed`)։ 429-ի դեպքում `Retry-After` վերնագիր չկա։

## 3. Որոշումներ (բոլորն ընդունվել են 2026-08-26-ին)

1. **Երթուղավորման մոտեցում՝ `fallbackOnly`:** Հիմնավորում՝ 0 արժեքով անվճար մատակարարը երբեք չպետք է գերակայի արժեքի վրա հիմնված ավտոմատ երթուղավորման ժամանակ․ բացահայտ ընտրությունն ու խափանումից հետո վերադարձը մնում են անփոփոխ։ Նախադեպ՝ միավորված xquik գրառումը։
2. **Շրջանակ՝ webSearch + webFetch՝ v1-ում `POST /v1/extract`-ի միջոցով։** Համապատասխանում է tavily/exa-ի երկակի հնարավորությունների մտային մոդելին։ Ուղղահայաց հնարավորությունները (`tag`, `sub-domains`, `batch_search`) մնում են շրջանակից դուրս. ներկայում ուղղահայաց պարամետրերի համար IR չկա։
3. **Քվոտայի ցուցադրում՝ `freeMonthlyQuota: 0`** (xquik-ի ոճով պահպանողական ցուցադրում)։ Իրական սահմանաչափը (օրական 1000 հարցում, օրական զրոյացում) փոխարենը ներկայացվում է UI կատալոգի `authHint` տեքստում։ Հիմնավորում՝ քվոտայի ցուցադրումը պետք է համապատասխանի զրոյացման իմաստաբանությանը․ օրական սահմանաչափը ամսական համարժեքի (30000) փոխակերպելը կեղծ խոստում է, որը UI-ը չի կարող կատարել։
4. **searchTypes՝ միայն `["web"]`:** AnySearch API-ում նորությունների/պատկերների ուղղահայաց հնարավորության վերաբերյալ հրապարակային ապացույց չկա․ առանց փաստաթղթավորված ուղղահայացի API-ներ ինտեգրող դարպասները (օրինակ՝ Google Custom Search) ցուցադրում են միայն վեբ որոնումը՝ news -> web փոխ映ումը լռելյայն կատարելու փոխարեն։
5. **Բանալու մոտեցում.** Առանց բանալու աշխատանքը հնարավոր է․ անվավեր բանալին վերադարձնում է 401/403 և երբեք լռելյայն չի իջեցվում անանուն ռեժիմի (արտացոլում է վերին հոսքի պայմանագիրը)։
6. **Գիտակցված բացառումներ՝** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (զրույցի միջնորդագրավումը մնում է firecrawl/jina/tavily-ի վրա), `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (անանուն հեռակա վերջնակետերը յուրաքանչյուր ելքային IP հասցեի համար կիսում են IP-ով սահմանափակված մեկ ընդհանուր պուլ, ուստի առանց բանալու extract-ը ընտրովի է, այլ ոչ թե ավտոմատ երթուղավորման թեկնածու), `QUOTA_STATUS_PROVIDERS` (AnySearch-ը քվոտայի մասին ազդանշում է 429/ծրարի միջոցով, ոչ թե 402/403 կարգավիճակով)։

- AnySearch-ի պաշտոնական փաստաթղթեր՝ https://anysearch.com/docs, https://anysearch.com/pricing; MCP կատալոգ՝ mcpservers.org/servers/anysearch-ai/anysearch-mcp-server; հմտության պահոց՝ github.com/anysearch-ai/anysearch-skill։
