Սեղմման կանոնները JSON ֆայլեր են, որոնք բեռնվում են կատարման ժամանակ։ Դրանք միտումնավոր պարունակում են միայն տվյալներ, որպեսզի նոր
լեզվական փաթեթներն ու RTK հրամանների զտիչները հնարավոր լինի վերանայել՝ առանց շարժիչի կոդը փոխելու։

> **Կանոնական սխեմա (ճշմարտության աղբյուր):** [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) (JSON Schema-ի 2020-12 սևագիր)։
> Ստորև բերված օրինակները ցուցադրական են. կասկածի դեպքում ստուգեք ձեր փաթեթը `_schema.json`-ի նկատմամբ։

## Caveman կանոնների փաթեթներ

Caveman կանոնների փաթեթները գտնվում են հետևյալ ուղու ներքո.

```txt
open-sse/services/compression/rules/<language>/<pack>.json
```

Յուրաքանչյուր փաթեթ պարունակում է փոխարինումներ, որոնք կիրառվում են սովորական արձակի նկատմամբ՝ պաշտպանված հատվածները մեկուսացնելուց հետո։

```json
{
  "language": "en",
  "category": "filler",
  "rules": [
    {
      "name": "question_to_directive",
      "pattern": "\\b(?:Can you explain why|Could you show me how)\\b\\s*",
      "replacement": "Explain why ",
      "replacementMap": {
        "can you explain why": "Explain why ",
        "could you show me how": "Show how "
      },
      "flags": "gi",
      "context": "all",
      "category": "context",
      "minIntensity": "lite",
      "description": "Convert verbose questions into direct requests."
    }
  ]
}
```

### Caveman-ի դաշտերը

| Դաշտ                     | Պարտադիր է | Նկարագրություն                                                                 |
| ------------------------ | ---------- | ------------------------------------------------------------------------------ |
| `language`               | այո        | BCP-47-ին նման լեզվի բանալի, օրինակ՝ `en`, `pt-BR`, `es`                       |
| `category`               | այո        | Փաթեթի կատեգորիայի ֆայլի անունը/կատեգորիան, օրինակ՝ `filler` կամ `dedup`       |
| `rules`                  | այո        | Կանոնավոր արտահայտություններով փոխարինման կանոնների զանգված                    |
| `rules[].name`           | այո        | Կանոնի կայուն անուն                                                            |
| `rules[].pattern`        | այո        | JavaScript կանոնավոր արտահայտության սկզբնաղբյուր                               |
| `rules[].flags`          | ոչ         | JavaScript կանոնավոր արտահայտության դրոշներ. լռելյայն՝ `gi`                    |
| `rules[].replacement`    | ոչ         | Փոխարինման տող կամ պահուստային արժեք, երբ `replacementMap`-ում համընկնում չկա  |
| `rules[].replacementMap` | ոչ         | Համընկնմանը հատուկ փոխարինումներ՝ բանալիներով որպես նորմալացված համընկած տեքստ |
| `rules[].context`        | ոչ         | `all`, `user`, `assistant` կամ `system`. լռելյայն՝ `all`                       |
| `rules[].category`       | ոչ         | `filler`, `context`, `structural`, `dedup`, `terse` կամ `ultra`                |
| `rules[].minIntensity`   | ոչ         | `lite`, `full` կամ `ultra`. լռելյայն՝ `lite`                                   |
| `rules[].description`    | ոչ         | Մարդու համար ընթեռնելի կանոնի ամփոփում                                         |

Օգտագործեք `flags`, երբ մեծատառերի և փոքրատառերի տարբերակմամբ համընկնումը կարևոր է, օրինակ՝ փոքրատառ արձակից առաջ հոդը հեռացնելիս՝
առանց `the OpenAI API`-ից `the`-ն հեռացնելու։ Օգտագործեք `replacementMap`, երբ մեկ կանոնավոր արտահայտությունն ունի մի քանի այլընտրանք,
որոնց համար անհրաժեշտ են տարբեր ելքեր. սա թույլ է տալիս JSON կանոնների փաթեթներում պահել միայն տվյալներ՝ միաժամանակ պահպանելով
ավելի հարուստ ներկառուցված TypeScript փոխարինման գործառույթների վարքագիծը։

## RTK զտիչների փաթեթներ

RTK զտիչները գտնվում են հետևյալ հասցեում՝

```txt
open-sse/services/compression/engines/rtk/filters/<filter>.json
```

Յուրաքանչյուր զտիչ նկարագրում է, թե ինչպես ճանաչել և սեղմել հրամանների ելքերի որոշակի ընտանիք։

```json
{
  "id": "test-vitest",
  "label": "Vitest output",
  "category": "test",
  "priority": 92,
  "match": {
    "outputTypes": ["test-vitest"],
    "commands": ["vitest", "npm test", "npm run test"],
    "patterns": ["\\bFAIL\\b", "\\bPASS\\b", "\\bTest Files\\b"]
  },
  "rules": {
    "stripAnsi": true,
    "replace": [{ "pattern": "\\s+\\[[0-9]+ms\\]", "replacement": "" }],
    "matchOutput": [
      {
        "pattern": "All tests passed",
        "message": "vitest: ok",
        "unless": "FAIL|Error:"
      }
    ],
    "includePatterns": ["FAIL", "Error:", "Test Files", "Tests"],
    "dropPatterns": ["^\\s*$", "Duration\\s+\\d+"],
    "collapsePatterns": ["^\\s+at "],
    "deduplicate": true,
    "truncateLineAt": 240,
    "maxLines": 160,
    "headLines": 24,
    "tailLines": 40,
    "onEmpty": "vitest: ok",
    "filterStderr": false
  },
  "preserve": {
    "errorPatterns": ["FAIL", "Error:", "AssertionError"],
    "summaryPatterns": ["Test Files", "Tests", "Snapshots"]
  },
  "tests": [
    {
      "name": "keeps failing tests",
      "command": "vitest",
      "input": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed",
      "expected": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed"
    }
  ]
}
```

### RTK դաշտեր

| Դաշտ                       | Պարտադիր | Նկարագրություն                                                                         |
| -------------------------- | -------- | -------------------------------------------------------------------------------------- |
| `id`                       | այո      | Զտիչի կայուն նույնացուցիչ                                                              |
| `label`                    | այո      | Կառավարման վահանակում ընթեռնելի անուն                                                  |
| `category`                 | այո      | Զտիչների ընտանիք՝ git, test, build, shell, docker, package, infra, cloud, generic      |
| `priority`                 | ոչ       | Երբ մի քանի զտիչ համընկնում է, հաղթում է ավելի բարձր առաջնահերթությամբ զտիչը           |
| `match.outputTypes`        | ոչ       | Դետեկտորի ելքային նույնացուցիչներ, որոնք ընտրում են այս զտիչը                          |
| `match.commands`           | ոչ       | Հրամանի թոքեններ, որոնք ընտրում են այս զտիչը                                           |
| `match.patterns`           | ոչ       | Կանոնավոր արտահայտություններ, որոնք այս զտիչն ընտրում են ելքային տեքստից               |
| `rules.stripAnsi`          | ոչ       | Հեռացնել ANSI escape հաջորդականությունները կանոնավոր արտահայտությունների փուլերից առաջ |
| `rules.replace`            | ոչ       | Ըստ հերթականության կանոնավոր արտահայտությունների փոխարինումներ՝ տող առ տող             |
| `rules.matchOutput`        | ոչ       | Ելքի կարճ միացման կանոններ՝ ընտրովի `unless` պաշտպանիչ պայմանով                        |
| `rules.includePatterns`    | ոչ       | Տողեր, որոնց պահպանումը պետք է նախընտրել                                               |
| `rules.dropPatterns`       | ոչ       | Որպես աղմուկ հեռացվող տողեր                                                            |
| `rules.collapsePatterns`   | ոչ       | Կրկնվող համընկնող տողեր, որոնք կարելի է միավորել                                       |
| `rules.deduplicate`        | ոչ       | Միավորել կրկնվող նորմալացված տողերը                                                    |
| `rules.truncateLineAt`     | ոչ       | Յուրաքանչյուր տողի համար Unicode-ին անվտանգ նիշերի սահմանաչափ                          |
| `rules.maxLines`           | ոչ       | Պահպանվող տողերի առավելագույն քանակը՝ մինչև վերջնամասի պահպանումը                      |
| `rules.headLines`          | ոչ       | Կրճատման ընթացքում պահպանվող սկզբնական տողեր                                           |
| `rules.tailLines`          | ոչ       | Վերջին համատեքստի համար պահպանվող եզրափակիչ տողեր                                      |
| `rules.onEmpty`            | ոչ       | Պահուստային հաղորդագրություն, երբ զտումը հեռացնում է ամբողջ բովանդակությունը           |
| `rules.filterStderr`       | ոչ       | Նորմալացնել stderr-ի տարածված նախածանցները՝ զտման հետագա փուլերից առաջ                 |
| `preserve.errorPatterns`   | ոչ       | Սխալների տողեր, որոնք պետք է պահպանվեն կրճատման ժամանակ                                |
| `preserve.summaryPatterns` | ոչ       | Ամփոփման տողեր, որոնք պետք է պահպանվեն կրճատման ժամանակ                                |
| `tests[]`                  | ոչ       | RTK-ի ստուգման փուլի կողմից օգտագործվող ներկառուցված ստուգման նմուշներ                 |

RTK-ն հայտարարագրային փուլերը կիրառում է հետևյալ հերթականությամբ՝ `stripAnsi`, `filterStderr`, `replace`,
`matchOutput`, `dropPatterns`/`includePatterns`, `truncateLineAt`, `headLines`/`tailLines`,
`maxLines` և `onEmpty`։

Հատուկ զտիչները կարող են բեռնվել հետևյալ աղբյուրներից՝

1. Նախագծի `.rtk/filters.json` ֆայլերից՝ միայն համապատասխան `.rtk/trust.json` հեշի առկայությունից կամ
   `trustProjectFilters`-ը միացնելուց հետո։
2. Գլոբալ `DATA_DIR/rtk/filters.json`-ից։
3. Ներկառուցված զտիչներից։

Նախագծային/գլոբալ հատուկ ֆայլերը կարող են պարունակել մեկ զտիչի օբյեկտ կամ զտիչների օբյեկտների զանգված։ Անվավեր
հատուկ զտիչները բաց են թողնվում ախտորոշիչ հաղորդագրություններով, իսկ անվավեր ներկառուցված զտիչները ձախողում են վավերացումը։

Նախագծի վստահության ֆայլ՝

```json
{
  "filtersSha256": "0123456789abcdef..."
}
```

`OMNIROUTE_RTK_TRUST_PROJECT_FILTERS=1` միջավայրի վերասահմանումը վստահում է նախագծի զտիչներին առանց
հեշի և պետք է սահմանափակվի վերահսկվող տեղային մշակման միջավայրերով։

## Անվտանգության կանոններ

- Կանոնները պահեք իդեմպոտենտ. նույն զտիչը երկու անգամ գործարկելը չպետք է վնասի ելքային տվյալները։
- Հնարավորության դեպքում ճշգրտորեն պահպանեք սխալի տեքստը, ֆայլերի ուղիները, տողերի համարները և հրամանների ամփոփագրերը։
- Խուսափեք այնպիսի կանոններից, որոնք փոփոխում են կոդի բլոկները, JSON օգտակար բեռները, URL-ները կամ գաղտնի տվյալները։
- Դետեկտորի/զտիչի թեստերում ավելացրեք միավորային թեստեր հրամանների նոր ընտանիքների համար։
- Յուրաքանչյուր ներկառուցված զտիչում և համօգտագործվող հատուկ զտիչներում ավելացրեք `tests[]` նմուշներ։

## Վավերացում

Կանոնների փաթեթները վավերացվում են օգտագործումից առաջ։ Ներկառուցված Caveman փաթեթները և ներկառուցված RTK զտիչները վավերացման ընթացքում անմիջապես ձախողվում են, որպեսզի թողարկման վնասված ռեսուրսները հայտնաբերվեն մինչև առաքումը։ Հատուկ RTK զտիչները բաց են թողնվում ախտորոշիչ հաղորդագրություններով, երբ վերլուծումը կամ վստահության վավերացումը ձախողվում է։

Թիրախային վավերացում.

```bash
node --import tsx/esm --test tests/unit/compression/rule-loader.test.ts tests/unit/compression/language-packs.test.ts
node --import tsx/esm --test tests/unit/compression/rtk-verify.test.ts tests/unit/compression/rtk-dsl-pipeline.test.ts
```
