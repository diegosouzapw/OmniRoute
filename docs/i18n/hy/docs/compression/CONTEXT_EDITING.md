Պատվիրակված **Context Editing**-ը միայն Claude-ի համար նախատեսված համատեքստի կառավարման գործառույթ է։ Ի տարբերություն OmniRoute-ի տեղային
սեղմման շարժիչների (Caveman, RTK, LLMLingua, շղթայված խողովակաշարեր), որոնք վերագրում են հարցման մարմինը
_մինչև_ այն լքի պրոքսին, Context Editing-ը խնդրում է **մատակարարին** իր ընթացիկ համատեքստային պատուհանից հեռացնել հնացած
գործիքի օգտագործման / գործիքի արդյունքի բլոկները։ OmniRoute-ը միայն ավելացնում է մարմնի
պարամետր (`context_management.edits[]`), իսկ Claude-ն իրականացնում է փաստացի մաքրումը՝ իր սեփական տոկենիզատորի հիման վրա։

Սա իր բնույթով պատվիրակված հնարավորություն է․ մյուս մատակարարները մերժում են պարամետրը, ուստի OmniRoute-ը դրա
կիրառման տիրույթը խստորեն սահմանափակում է Claude-ով և Claude Code-ի հետ համատեղելի ռելեներով։

Ճշմարտության աղբյուր՝ `open-sse/config/contextEditing.ts` (ռազմավարությունների նույնացուցիչներ, մարմնի մեջ ներարկում, տելեմետրիայի
արտահանում), `open-sse/executors/base.ts` (ներարկման թույլտվության ստուգում + 400-ի դեպքում պահուստային վարքագիծ) և
`open-sse/services/compression/types.ts` (կազմաձևի կառուցվածք + լռելյայն արժեք)։

## Ինչ է անում `clear_tool_uses`-ը

OmniRoute-ը մեկ խմբագրում է ներարկում ելքային Anthropic Messages մարմնի մեջ․

```json
{
  "context_management": {
    "edits": [
      {
        "type": "clear_tool_uses_20250919",
        "trigger": { "type": "input_tokens", "value": 100000 },
        "keep": { "type": "tool_uses", "value": 3 }
      }
    ]
  }
}
```

- `type: "clear_tool_uses_20250919"` — թվագրված Anthropic ռազմավարության նույնացուցիչը (`CLEAR_TOOL_USES_STRATEGY`)։
- `trigger.value: 100000` — երբ հարցման մուտքային տոկենների քանակը գերազանցում է այս շեմը, Claude-ն սկսում է
  մաքրել հին գործիքի օգտագործման/արդյունքի զույգերը (`CONTEXT_EDITING_DEFAULT_TRIGGER_TOKENS`, Anthropic-ի լռելյայն արժեքը)։
- `keep.value: 3` — գործիքի օգտագործման/արդյունքի վերջին N զույգերը պահպանվում են անփոփոխ
  (`CONTEXT_EDITING_DEFAULT_KEEP_TOOL_USES`)։

Բետա հնարավորության մասին ազդարարվում է `anthropic-beta: context-management-2025-06-27` վերնագրի միջոցով, որը
OmniRoute-ն արդեն ուղարկում է Claude-ի հարցումների հետ։

Ներարկումն իրականացվում է `applyContextEditingToBody()`-ի միջոցով և **իդեմպոտենտ** է․ եթե `clear_tool_uses`
խմբագրումն արդեն առկա է մարմնում (ավելացված նախորդ կանչի կողմից կամ տրամադրված հաճախորդի կողմից), մարմինը
մնում է անփոփոխ։ Եթե առկա է նաև `clear_thinking_20251015` խմբագրումը, OmniRoute-ը կայուն տեսակավորմամբ
`clear_thinking` խմբագրումը տեղափոխում է սկիզբ, քանի որ Anthropic-ը պահանջում է, որ `clear_thinking`-ը նախորդի
`clear_tool_uses`-ին `edits[]` զանգվածում։

## Յուրաքանչյուր համակցության միացման փոխարկիչը

Context Editing-ը **լռելյայն անջատված է** և պահանջում է հստակ միացում։ Փոխարկիչը մեկ բուլյան արժեք է, որը պահվում է
սեղմման կազմաձևում․

- Կարգավորման բանալի՝ `contextEditing.enabled` (camelCase — **ոչ** `context_editing` / `context-editing`)։
- Տեսակ՝ `ContextEditingConfig { enabled: boolean }`՝
  `open-sse/services/compression/types.ts`-ում։
- Լռելյայն արժեք՝ `DEFAULT_CONTEXT_EDITING_CONFIG = { enabled: false }`։
- Zod սխեմա՝ `contextEditingConfigSchema`՝ `src/shared/validation/compressionConfigSchemas.ts`-ում։
- Պահպանում՝ պահպանվում է սեղմման մնացած կարգավորումների հետ միասին (նորմալացվում է
  `src/lib/db/compression.ts`-ում)։

Կառավարման վահանակում փոխարկիչը գտնվում է սեղմման հանգույցում
(`src/app/(dashboard)/dashboard/context/combos/CompressionHub.tsx`) և
`{ contextEditing: { enabled: … } }`-ը հետ է գրում `saveSettings()`-ի միջոցով։ Քանի որ այն փոխանցվում է
սեղմման կարգավորումների օբյեկտի կազմում, այն համադրվում է յուրաքանչյուր համակցության սեղմման պրոֆիլի հետ՝ ամբողջովին
անկախ մակերես լինելու փոխարեն․ կազմաձևը պարունակում է միայն միացման/անջատման դրոշը, իսկ բոլոր շեմերը (`trigger`,
`keep`) վերը փաստագրված հաստատուններն են։

## Միայն Claude-ի համար սահմանափակում

Ներարկումը կատարվում է միայն իրական Claude-ի կամ Claude-Code-ի հետ համատեղելի ռելեների համար։ `open-sse/executors/base.ts`-ում ստուգումն այսպիսին է․

```ts
if (
  (this.provider === "claude" || isClaudeCodeCompatible(this.provider)) &&
  contextEditing?.enabled &&
  !contextEditingDisabled
) {
  applyContextEditingToBody(transformedBody, { enabled: true });
}
```

- `this.provider === "claude"` — իրական Anthropic բանալի/OAuth։
- `isClaudeCodeCompatible(this.provider)` — ռելեներ, որոնց մատակարարի id-ն սկսվում է `anthropic-compatible-cc-` նախածանցով (դրանք հայտարարում են Claude Code-ի հետ համատեղելիության մասին, ուստի ամենայն հավանականությամբ կընդունեն բետա հնարավորությունը)։ Տե՛ս `open-sse/services/provider.ts`։

Դիտավորյալ **բացառված են**․

- `claude-web` — զննարկչային ռելե՝ `create_conversation_params` հարցման կառուցվածքով, որը երբեք չի ստանում `context_management`։
- Ընդհանուր `anthropic-compatible-*` ռելեներ (առանց `-cc-` նախածանցի) — երրորդ կողմի վերջնակետեր՝ բետա հնարավորության անորոշ աջակցությամբ։

Ոչ Claude մատակարարները երբեք չեն ստանում `context_management` պարամետրը, նույնիսկ երբ փոխարկիչը միացված է։

## 400 հետադարձ մեխանիզմը / ռելեների ընդգրկումը

Claude-ի հետ համատեղելի ռելեն կարող է հայտարարել բետա հնարավորության մասին, սակայն այնուամենայնիվ մերժել `context_management` պարամետրը HTTP 400-ով։ Հարցումը ձախողելու փոխարեն գործունակությունը նրբորեն նվազեցնելու համար կատարիչը հեռացնում է պարամետրը և նույն URL-ով կրկին փորձում է **մեկ անգամ**․

```ts
if (
  response.status === HTTP_STATUS.BAD_REQUEST &&
  contextEditing?.enabled &&
  !contextEditingDisabled &&
  transformedBody?.context_management !== undefined
) {
  const errText = await response
    .clone()
    .text()
    .catch(() => "");
  if (/context[_-]management|context editing/i.test(errText)) {
    contextEditingDisabled = true;
    delete transformedBody.context_management;
    let retryBody = JSON.stringify(transformedBody);
    if (isClaudeCodeCompatible(this.provider) || this.provider === "claude") {
      retryBody = await signRequestBody(retryBody);
    }
    response = await fetch(url, { ...fetchOptions, body: retryBody });
  }
}
```

Վարքագիծը․

1. Գործարկվում է միայն `400`-ի դեպքում, երբ համատեքստի խմբագրումը միացված է, և հարցման մարմինն իրականում պարունակում է `context_management`։
2. 400 պատասխանի մարմինը կարդացվում է `clone()`-ի միջոցով, որպեսզի սկզբնական պատասխանը չփոփոխվի չհամընկնող ուղու համար։
3. Սխալի տեքստը պետք է համապատասխանի `/context[_-]management|context editing/i` արտահայտությանը․ կապ չունեցող 400 սխալը (օրինակ՝ `max_tokens must be >= 1`) **չի** գործարկում հետադարձ մեխանիզմը, և սկզբնական սխալը փոխանցվում է վերև։
4. Համընկնման դեպքում այն սահմանում է `contextEditingDisabled = true` (ինչը կանխում է կրկնակի ներարկումը, եթե հետագայում նոր `transformedBody` կառուցվի կրկնափորձի/հետադարձ URL-ի համար), ջնջում է `context_management`-ը, կրկին ստորագրում մարմինը Claude-ի / Claude-Code-ի հետ համատեղելի ռելեների համար (`signRequestBody`) և նույն URL-ով մեկ անգամ կրկին փորձում է։

Իրական Claude-ը բետա հնարավորությունը փոխանցում է `ANTHROPIC_BETA_BASE`-ում և չի անցնում այս հետադարձ ուղով։

## `applied_edits` հեռաչափություն

Claude-ի պատասխանից հետո OmniRoute-ը գրանցում է, թե մատակարարն իրականում համատեքստի որքան մասն է մաքրել։ Սա **հոսքային եղանակով չի փոխանցվում**․ այն հնարավորության սահմաններում արտահանվում է ոչ հոսքային պատասխանի մարմնից և երբեք չի ազդում պատասխանի վրա (հեռաչափության սխալներն անտեսվում են)։

- Արտահանում՝ `extractContextEditingTelemetry(responseBody)`՝ `open-sse/config/contextEditing.ts`-ում։
  Այն ստուգում է `applied_edits`-ը երեք տեղում (ի պաշտպանություն պատասխանի կառուցվածքի տարբերակների)․
  - `context_management.applied_edits`
  - `usage.context_management.applied_edits`
  - `usage.applied_edits`
- Յուրաքանչյուր գրառումից կարդացվող դաշտերն են՝ `cleared_input_tokens` և `cleared_tool_uses`
  (snake_case, Anthropic-ի բնիկ ձևաչափ), իսկ որպես պահուստային տարբերակներ՝ `clearedInputTokens` / `clearedToolUses` camelCase դաշտերը։
- Վերադարձնում է `null`, երբ `applied_edits` զանգված չի գտնվել կամ իրականում ոչինչ չի մաքրվել։

Ստացականի կառուցվածքն է՝ `ContextEditingTelemetry { editCount, clearedInputTokens, clearedToolUses }`։ Գրանցումը կատարվում է `open-sse/handlers/chatCore.ts`-ում (սահմանափակված է `provider === "claude"` պայմանով)՝ `recordContextEditingTelemetry()`-ի միջոցով (`src/lib/db/compressionAnalytics.ts`), որը գրում է սեղմման վերլուծական տվյալների տող՝ հետևյալ պիտակներով․

- `mode: "context-editing"`
- `engine: "context-editing"`
- `tokens_saved` / `original_tokens` = մաքրված մուտքային թոքենների քանակը
- `request_id`՝ `::context-editing` վերջածանցով

Այսպիսով, պատվիրակված մաքրումը հայտնվում է սեղմման վերլուծական տվյալներում տեղային շարժիչների կողքին՝ `context-editing` շարժիչի պիտակով, և տարբերակելի է RTK/Caveman/LLMLingua խնայողություններից։

## Կապը տեղային սեղմման շարժիչների հետ

| Բնութագիր                   | Տեղային շարժիչներ (Caveman / RTK / LLMLingua / stacked)     | Պատվիրակված համատեքստի խմբագրում                           |
| --------------------------- | ----------------------------------------------------------- | ---------------------------------------------------------- |
| Որտեղ է աշխատում            | OmniRoute-ում՝ նախքան հարցումը կլքի պրոքսին                 | Մատակարարի մոտ (Claude)՝ սերվերի կողմում                   |
| Ինչ է խմբագրում             | Հուշման / համատեքստի / գործիքի արդյունքի տեքստը             | Գործիքի օգտագործման / գործիքի արդյունքի հին բլոկները       |
| Մատակարարների շրջանակը      | Բոլոր մատակարարները                                         | Միայն `claude` + `anthropic-compatible-cc-*`               |
| Փոխարկիչ                    | Սեղմման ռեժիմի կարգավորումները                              | `contextEditing.enabled`                                   |
| Խափանման վարքագիծը          | Խափանման դեպքում շարունակում է աշխատանքը (բնօրինակ տեքստով) | 400-ի դեպքում՝ հեռացնել պարամետրը և կրկին փորձել մեկ անգամ |
| Խնայողության հեռաչափություն | `engine: <engine id>`                                       | `engine: "context-editing"`                                |

Այս երկուսը փոխլրացնող են․ տեղային շարժիչները սեղմում են OmniRoute-ի ուղարկած բայթերը, իսկ Համատեքստի խմբագրումը թույլ է տալիս
Claude-ին հերթերի ընթացքում կրճատել ընթացիկ համատեքստը։ Դրանք կարող են միաժամանակ միացված լինել։
