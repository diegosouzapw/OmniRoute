Cursor-ը OmniRoute-ի հետևում առանց IDE աշխատաշրջանի տեղադրելու երկու եղանակ.

1. **`cursor-api` մատակարար** («Cursor API» քարտ, `cua` այլանուն). API բանալիով
   մատակարար, որը պահում է Cursor-ի օգտատիրոջ API բանալին (`crsr_…`, ստեղծվում է
   `https://cursor.com/dashboard/api` հասցեում)։ Այնուհետև OmniRoute-ի ցանկացած հաճախորդ
   `/v1/chat/completions`-ի միջոցով հասանելիություն է ստանում Cursor-ի մոդելներին՝ որպես
   `cursor-api/<model>` կամ `cua/<model>`, քվոտայի, պահուստային երթուղավորման և գրանցամատյանների
   սովորական շերտերով։ IDE մատակարարը (`cursor`, OAuth/IDE աշխատաշրջան) մնում է անփոփոխ։
2. **Cursor CLI-ի միջանցիկ փոխանցում**. Cursor CLI-ն (`agent`) ուղղեք դեպի OmniRoute, որպեսզի
   CLI-ի կատարած յուրաքանչյուր RPC նույնականացվի OmniRoute API բանալիով, փոխանցվի
   Cursor-ին՝ օգտագործելով `cursor-api` կապի հավատարմագրերը, և գրանցվի
   Logs էջում։

## Ինչու է բանալին փոխանակվում

`api2.cursor.sh`-ը մերժում է չմշակված `crsr_…` բանալին որպես Bearer նշան (401)։ Cursor
CLI-ն նախ POST հարցմամբ ուղարկում է բանալին `/auth/exchange_user_api_key` և ստանում
աշխատաշրջանի JWT, որի ժամկետը լրանում է մեկ ժամ անց։ Վերադարձված `refreshToken`-ն ունի նույն
`exp` արժեքը, ուստի թարմացումը նշանակում է բանալու կրկնակի փոխանակում։
`open-sse/services/cursorApiKeyAuth.ts`-ը կատարում է այդ փոխանակումը, յուրաքանչյուր բանալու
համար քեշավորում է մեկ աշխատաշրջանային նշան, այն կրկին փոխանակում է ժամկետի ավարտից հինգ
րոպե առաջ և հեռացնում է քեշավորված նշանը, երբ Cursor-ը պատասխանում է 401-ով։ `CursorExecutor`-ը
կանչում է այն անմիջապես `cursor-api` կապերի համար վերին հոսքի բացումից առաջ։

## `cursor-api` մատակարարը

Ռեեստր՝ `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, նույն `format`, `baseUrl` և
`models`, ինչ `cursor`-ի դեպքում)։ Կատալոգի քարտ՝
`src/shared/constants/providers/apikey/specialty-media.ts`։ Կատարիչների քարտեզ՝
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`)։

Կառավարման վահանակ՝ Providers → Cursor API → Add API key։

REST՝

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

Այնուհետև՝

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

Նշումներ՝

- `cursor-api`-ի մոդելների ցանկը վերցվում է Cursor-ի ստատիկ ռեեստրից (նույն
  ցանկը, որին որպես պահուստային տարբերակ անցնում է IDE մատակարարը)։ OmniRoute հոսթում
  `cursor-agent`-ի տեղադրում չի պահանջվում։
- `POST /api/providers/{id}/refresh-cursor`-ը նախատեսված է միայն `cursor` IDE մատակարարի
  համար։ `cursor-api` կապերը չունեն թարմացման ենթակա IDE աշխատաշրջան։

## Բնիկ մոդելների ID-ներ և ջանքի մակարդակ

`cursor` / `cu` և `cursor-api` / `cua` տարբերակների համար Claude-ի ջանքի մակարդակի ընդհանուր նորմալացուցիչը
պահպանում է հարցված մոդելի ID-ն անփոփոխ։ Cursor-ը կարող է `-low`-ի նման վերջածանցը
ներկայացնել որպես իրական մոդելի ID-ի մաս, այլ ոչ թե որպես OmniRoute-ի ջանքի մակարդակի այլանուն։
Cursor-ի կատարիչը պահպանում է գործող կատալոգում ճշգրիտ համընկնումը։ Երբ համընկնում չկա,
վերջածանցը պարամետրի փոխակերպելու պահուստային մշակումը կատարում է դրա գործող մոդելի լուծիչը։

Սա չի փոխում ջանքի մակարդակի նորմալացումը Claude-ի ուղիղ, Claude-ի հետ համատեղելի
կամ Vertex երթուղիների համար։ Հասանելիությունը նախկինի պես կախված է ընտրված Cursor հաշվի
կատալոգից և հասանելիության իրավունքներից։

## Cursor CLI-ի միջանցիկ փոխանցում

Երթուղի՝ `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`։ `/api/cursor-cli/` նախածանցը
գրանցված է `src/shared/constants/publicApiRoutes.ts`-ում, քանի որ մշակիչը
կիրառում է իր սեփական նույնականացումը․

| Ուղի                                                                                                                               | CLI-ից ակնկալվող նույնականացում | Ինչ է անում OmniRoute-ը                                                                                                                                                                  |
| ---------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                                 | `Bearer <OmniRoute API key>`    | Վավերացնում է բանալին, ստեղծում է 1 ժամ վավերականությամբ HS256 JWT (`JWT_SECRET`-ով ստորագրված) և վերադարձնում այն                                                                       |
| յուրաքանչյուր այլ ուղի (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`             | Ստուգում է թողարկողին/լսարանին/վավերականության ժամկետը, ընտրում է ակտիվ `cursor-api` կապ, Authorization վերնագիրը փոխարինում է փոխանակված Cursor թոքենով և պատասխանը հոսքով վերադարձնում |

CLI-ն վերծանում է `exp`-ը ստացած ցանկացած թոքենից, ուստի նրան ոչ թափանցիկ
թոքեն փոխանցելու դեպքում այն գրեթե յուրաքանչյուր հարցումից առաջ նորից է
փոխանակում կատարում․ ստեղծված JWT-ն խուսափում է դրանից։ OmniRoute-ից ստացված
401 պատասխանը CLI-ին ստիպում է կրկին փոխանակում կատարել։

### Կարգավորում

1. Ստեղծեք OmniRoute API բանալի (Կառավարման վահանակ → API բանալիներ) և
   `cursor-api` կապ։
2. Հանձնարարեք CLI-ին գործակալի հոսքի համար օգտագործել HTTP/1.1։
   `~/.cursor/cli-config.json`-ում՝

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   Առանց դրա CLI-ն գործակալի քայլը բացում է HTTP/2-ով՝ առանձին
   կազմաձևված գործակալի հոսթում, և վերջնակետով անցնում են միայն
   կառավարման հարթության RPC-ները։

3. Գործարկեք CLI-ն OmniRoute-ի միջոցով՝

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

Յուրաքանչյուր անցում գրանցվում է Logs-ում՝ որպես `cursor-api` մատակարար,
`cursor-cli` հարցման տեսակ և `/api/cursor-cli/<rpc>` ուղի՝ վերագրված
OmniRoute API բանալուն և այն սպասարկած կապին։

### Խափանման սցենարներ

| Իրավիճակ                                            | Պատասխան CLI-ին                                            |
| --------------------------------------------------- | ---------------------------------------------------------- |
| Անհայտ OmniRoute բանալի և `REQUIRE_API_KEY=true`    | 401 `unauthenticated`՝ փոխանակման ժամանակ                  |
| `REQUIRE_API_KEY=false`                             | անանուն աշխատաշրջան (նմանակում է `/v1/*` վարքագիծը)        |
| Ժամկետանց / օտար / կեղծված աշխատաշրջանի JWT         | 401, CLI-ն կրկին փոխանակում է կատարում                     |
| OmniRoute API բանալին չեղարկվել է փոխանակումից հետո | 401՝ հաջորդ RPC-ի ժամանակ                                  |
