`copilot-m365-web`-ը (`m365copilot` կեղծանունով) OpenAI ձևաչափի զրույցի հարցումներ է ուղարկում `m365.cloud.microsoft/chat` հասցեում նույնականացված Microsoft 365 Copilot BizChat դիտարկչային աշխատաշրջանի միջոցով։ Սա ոչ պաշտոնական ինտեգրում է։

> **Առաջին անգա՞մ եք օգտվում Web Cookie մատակարարներից։**
>
> Նախքան մատակարարին հատուկ այս ուղեցույցին հետևելը՝ կարդացեք **`docs/getting-started/WEB-COOKIE-GUIDE.md`**՝ կարգավորման ընդհանուր գործընթացին, նույնականացման ցուցումներին, սահմանափակումներին և անսարքությունների վերացմանը ծանոթանալու համար։
>
> **Կարևոր է․** Այս մատակարարի հավատարմագիրը **cookie չէ**։ Մի պատճենեք cookie-ները `m365.cloud.microsoft`-ից։ Հավատարմագիրը WebSocket URL-ի հարցման պարամետր է և ուղու հատված, որոնք երկուսն էլ վերցվում են DevTools-ի Network ներդիրից։

## Նախապայմաններ

- Microsoft 365 հաշիվ՝ `m365.cloud.microsoft/chat` հասցեում BizChat-ի հասանելիությամբ
- Chromium-ի հիմքով դիտարկիչ (Chrome, Edge)՝ DevTools-ում WebSocket-ը ստուգելու համար
- M365 Copilot լիցենզիա (ներառված է Microsoft 365 Business/Enterprise բազմաթիվ փաթեթներում)

## Հավատարմագրի ստացում (WebSocket մեթոդ)

1. Մուտք գործեք `https://m365.cloud.microsoft/chat` և սկսեք զրույց։
2. Բացեք **DevTools → Network**։
3. Զտեք ըստ **WS**-ի (WebSocket)։
4. Սեղմեք Chathub WebSocket կապի վրա։ Փնտրեք URL, որը սկսվում է հետևյալով՝ `wss://substrate.office.com/m365Copilot/Chathub/`։
5. Դրա **Request URL**-ից պատճենեք՝
   - `access_token` հարցման պարամետրի արժեքը (կարճաժամկետ JWT)։
   - `/Chathub/`-ից հետո գտնվող Chathub ուղու հատվածը (օրինակ՝ `<oid>@<tenant>`)։

Ամբողջական URL-ն ունի հետևյալ ձևը․

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute-ում անցեք **Providers → Add Provider**, ընտրեք **Microsoft 365 Copilot (BizChat)** և տեղադրեք հավատարմագիրը հետևյալ ձևաչափով․

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Սեղմեք **Test Connection**, ապա՝ **Save**։

## Հավատարմագրի ստացում (HAR ներմուծում)

WebSocket URL-ից արժեքները ձեռքով պատճենելու փոխարեն կարող եք արտահանել DevTools HAR ֆայլ․

1. Բացեք **DevTools → Network**։
2. Սկսեք կամ շարունակեք BizChat զրույցը (դա գործարկում է WebSocket կապը)։
3. Network վահանակում աջ սեղմեք և ընտրեք **Save all as HAR with content**։
4. OmniRoute-ում մատակարարի կապի երկխոսության պատուհանում օգտագործեք **Import .har file** կոճակը։

OmniRoute-ը HAR-ում որոնում է Chathub WebSocket URL-ը, դուրս է բերում `access_token`-ը և `chathubPath`-ը և ավտոմատ լրացնում հավատարմագրի դաշտերը։ HAR ներմուծումը վերծանում է JWT-ի վավերականության ավարտի ժամանակը և ցույց է տալիս թոքենի մնացած գործողության ժամկետը։

> **Երբեք մի commit արեք իրական HAR արտահանումը, հասանելիության թոքենը կամ թարմացման թոքենը։** Թեստերում և փաստաթղթերում արժեքները միշտ պետք է լինեն տեղապահներ։

## Թոքենի գործողության ժամկետը և թարմացումը

`access_token`-ը կարճաժամկետ է (սովորաբար՝ **~75 րոպե**)։ Ժամկետը լրանալուց հետո մատակարարը հաղորդում է կապի սխալի մասին, և անհրաժեշտ է կրկին ստանալ հավատարմագիրը։

### Ավտոմատ թարմացում `refreshToken`-ով

Կրկին ձեռքով ստանալու անհրաժեշտությունից խուսափելու համար կարող եք Microsoft-ի թարմացման թոքենը պահել կապի **Advanced Settings → providerSpecificData** բաժնում․

| Դաշտ           | Նկարագրություն                                                               |
| -------------- | ---------------------------------------------------------------------------- |
| `refreshToken` | Microsoft OAuth թարմացման թոքեն՝ `substrate.office.com/sydney` scope-ի համար |
| `tier`         | `individual` (լռելյայն), `edu` կամ `enterprise`                              |

Ստացեք թարմացման թոքենը Microsoft-ի սարքի կոդով կամ լիազորման կոդով հոսքից՝ սահմանված `substrate.office.com/sydney` scope-ով։ Երբ `refreshToken`-ը սահմանված է, OmniRoute-ը յուրաքանչյուր հարցումից առաջ նախապես թարմացնում է `access_token`-ը, ուստի յուրաքանչյուր ~75 րոպեանոց ժամկետի ավարտից հետո այն կրկին ստանալու կարիք չկա։

Եթե `refreshToken`-ը սահմանված չէ, յուրաքանչյուր ժամկետի ավարտից հետո պետք է ձեռքով կրկին ստանաք WebSocket հավատարմագիրը։

### Մակարդակի ընտրություն

| Մակարդակ     | Կեղծանուն    | Միջերես                                   |
| ------------ | ------------ | ----------------------------------------- |
| `individual` | _(լռելյայն)_ | Սպառողական M365 Copilot                   |
| `edu`        | `included`   | Կրթական M365 Copilot                      |
| `enterprise` | `work`       | M365 Copilot աշխատանքային միջավայրի համար |

Մակարդակը սահմանեք **Advanced Settings → providerSpecificData → tier** բաժնում։ Մակարդակն ազդում է BizChat-ի երթուղավորման և մոդելների հասանելիության վրա։

## Անվտանգության մոդել

- **Ոչ պաշտոնական ինտեգրում։** Այս մատակարարը հակադարձ ինժեներիայի միջոցով վերարտադրում է BizChat WebSocket-ի
  արձանագրությունը։ Այն կարող է դադարել աշխատել առանց նախազգուշացման, երբ Microsoft-ը փոխի վերջնակետը։
- `subscriptionRisk: true` դրոշը ցույց է տալիս, որ ինտեգրումը հիմնված է
  չփաստաթղթավորված վերջնակետի վրա։ Հաշվի սահմանափակումները հնարավոր են, սակայն հաստատված չեն։
- Մուտքի թոքենը կարճաժամկետ JWT է։ Վերաբերվեք դրան որպես գաղտնաբառի՝ մի՛ ներառեք այն commit-ում,
  մի՛ գրանցեք մատյանում և մի՛ տարածեք։
- Թարմացման թոքենը երկարաժամկետ հասանելիություն է տրամադրում BizChat միջերեսին։ Պահպանեք այն նույն
  զգուշությամբ, ինչ API բանալին։

## Խնդիրների լուծում

### Նույնականացումն անմիջապես ձախողվում է

- Համոզվեք, որ պատճենել եք **WebSocket URL**-ից, այլ ոչ թե XHR/Fetch հարցումից։ Հավաստագիրը
  գտնվում է Chathub WebSocket կապի `access_token` հարցման պարամետրում,
  այլ ոչ թե `Authorization: Bearer` վերնագրում։
- Համոզվեք, որ `chathubPath`-ը ներառում է URL-ի ուղուց ամբողջական `<oid>@<tenant>`
  հատվածը։

### Թոքենի ժամկետը լրանում է մոտավորապես 75 րոպե անց

Սա սպասելի է։ Առանց `refreshToken`-ի՝ մուտքի թոքենը կարճաժամկետ է։ Կատարեք հետևյալներից մեկը՝

- Կրկին ստացեք հավաստագիրը DevTools-ից, կամ
- Ավտոմատ թարմացման համար Advanced Settings-ում կազմաձևեք `refreshToken`։

### Test Connection-ը հաջողվում է, սակայն զրույցը վերադարձնում է 401

Թոքենի ժամկետը կարող էր լրանալ վավերացման և առաջին հարցման միջև ընկած ժամանակահատվածում։ Կրկին ստացեք
թարմ հավաստագիր։

### Copilot-ը չի ցուցադրվում մատակարարների ցանկում

Համոզվեք, որ `copilot-m365-web`-ը միացված է **Dashboard → Providers** բաժնում։ Որոշ
մակարդակներում մատակարարը կարող է լռելյայն թաքցված լինել։
