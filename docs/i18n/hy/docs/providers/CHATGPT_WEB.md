`chatgpt-web-codex`-ը (կեղծանուն՝ `cgpt-codex`) Codex Responses-ի հարցուպատասխանային քայլերը կապում է նույնականացված ChatGPT բրաուզերային աշխատաշրջանի միջոցով։ Այն անկախ է շահագործումից հանված ընդհանուր `chatgpt-web` մատակարարից և օգտագործում է MIT ծանուցմամբ իրականացումը՝ տեղակայված `open-sse/vendor/codex-chatgpt-web/`-ում և թարմացված մինչև վերին հոսքի v4.0.7 տարբերակի `b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494` commit-ը։

## Ընդհանուր մատակարարի շահագործումից հանումը

Նախկին ընդհանուր մատակարարների `chatgpt-web` և `cgpt-web` ID-ներն այլևս չեն մատակարարվում, քանի որ դրանց նախնական բանալու/աշխատանքի ապացույցի իրականացման ծագումը չհաջողվեց հստակեցնել։ Այդ ID-ներից որևէ մեկին ուղղված բացահայտ հարցումները, ներառյալ շեղագծով սկսվող մոդելների ID-ները և պահպանված կեղծանունները, որևէ վերին հոսքի հարցումից առաջ փակ ռեժիմով ձախողվում են HTTP `410`-ով և **PROVIDER_RETIRED** կոդով։

`168_retire_chatgpt_web.sql` միգրացիան որպես հեռացված է նշում համապատասխան մատակարարների կապերը և անվավերացնում դրանց ակտիվ աշխատաշրջանների վարձակալումները։ Այն պահպանում է կապերի պատմությունը և API բանալիների թույլատրված ցանկերը, սակայն չի ավելացնում փոխարինող հասանելիություն որևէ թույլատրված ցանկում։ Այս շահագործումից հանումը չի վերաբերում Codex մատակարարին և դրա կապերին։

## Նախապայմաններ

- մուտք գործած ChatGPT աշխատաշրջանի ամբողջական Cookie վերնագիր,
- Chrome կամ Chromium, ինչպես նաև գրաֆիկական աշխատաշրջան կամ Xvfb ցուցադրիչ՝ npm, systemd և PM2 տեղադրումների համար,
- Docker-ի `web` պրոֆիլի դեպքում՝ `docker-compose.yml`-ում սահմանված ներքին Chromium ծառայությունը,
- OpenAI `tunnel-client` v0.0.13 և ChatGPT-ի անհատական միակցիչ՝ տեղային Codex գործիքների համար։

Թունելն անհրաժեշտ է միայն գործիքների օգտագործմամբ քայլերի համար։ Թվարկված յուրաքանչյուր երթուղի, ներառյալ `pro`-ն, կարող է օգտագործել քայլի հետ կապված նույն տեղային գործիքային հնարավորությունը, երբ թունելն ու միակցիչը կազմաձևված են։

## Կառավարման վահանակի կարգավորում

1. Բացեք **ChatGPT Web (Codex)** մատակարարը և ավելացրեք կապ։
2. Տեղադրեք ChatGPT-ի ամբողջական Cookie վերնագիրը, թունելի ID-ն, կատարման միջավայրի բանալին և անհատական միակցիչի անունը։ Գործիքներ օգտագործելու հնարավորություն ունեցող նոր կարգավորումները պետք է օգտագործեն նոր ստեղծված միակցիչ՝ ճիշտ `OmniRoute Codex v2` անունով, որի Authentication պարամետրը դրված է None, իսկ Permissions պարամետրը՝ Allow all actions։
3. Գործարկեք կապի ստուգումը։ OmniRoute-ը բացում է բրաուզերի միջոցով աշխատող Ժամանակավոր զրույց և հայտնաբերում՝ արդյոք Sol-ն ու Pro-ն հասանելի են տվյալ հաշվի համար։
4. Պահպանեք կապը։ OmniRoute-ը տեղադրված cookie-ն փոխարինում է ստուգված Playwright պահպանման վիճակով և այն կատարման միջավայրի բանալու հետ միասին պահում է հավատարմագրերի գաղտնագրված աբստրակցիայի միջոցով։

Հաջող պահպանումից հետո սկզբնական cookie-ն չի պահպանվում։ Երբ աշխատաշրջանի ժամկետը լրանա, բացեք կապը, տեղադրեք նոր ամբողջական Cookie վերնագիր և կրկին գործարկեք ստուգումը։ Խմբագրման երկխոսության պատուհանում ախտորոշման կարգավիճակն առանձին ցուցադրում է բրաուզերի, պահպանման վիճակի, մուտք գործելու, Ժամանակավոր զրույցի, թունելի, միակցիչի և գործիքի երկկողմանի փոխանակման վիճակները։

> Երբեք մի commit արեք իրական cookie, կատարման միջավայրի բանալի, պահպանման վիճակ կամ հնարավորության token։ Թեստային և
> փաստաթղթային արժեքները միշտ պետք է լինեն տեղապահեր։

## Մոդելներ և համակցություններ

Մոդելների ֆիքսված երթուղիներն են՝

- `chatgpt-web-codex/luna` — GPT-5.6 Luna, ցածր ջանք
- `chatgpt-web-codex/think` — GPT-5.6 Luna, միջին ջանք
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

Դրանցից որևէ մեկը համակցությանը ավելացրեք ցանկացած այլ մոդելի պես։ Codex հավելվածը համակցության անունը որպես `model` ուղարկում է Responses-ի սովորական վերջնակետին՝ `/v1/responses`։ Codex-ի առանձին վերջնակետ կամ ռեժիմի փոխարկիչ չկա։

Free/Go հաշիվներին հասանելի են Luna երթուղիները։ Sol-ի հնարավորություն ունեցող հաշիվներին հասանելի են Instant-ից մինչև High երթուղիները, իսկ Pro-ի հնարավորություն ունեցող հաշիվներին՝ լրացուցիչ նաև Extra High-ը և Pro-ն։ Յուրաքանչյուր երթուղի ունի ֆիքսված հետնամասային մոդել և դատողության ջանք։ Responses-ի՝ դրա հետ հակասող բացահայտ ջանքի պարամետրը փակ ռեժիմով ձախողվում է՝ ընտրված բրաուզերային ռեժիմը լռելյայն փոխելու փոխարեն։

Մի վերանվանեք կամ կրկին օգտագործեք ավելի հին `Codex Native` կամ `OmniRoute Codex` միակցիչ։ ChatGPT-ն հրապարակային MCP պայմանագիրը քեշավորում է ըստ միակցիչի ինքնության, մինչդեռ թարմացված կամուրջն օգտագործում է նոր՝ քայլի անմիջական token-ի պայմանագիր։ Կատարման միջավայրը մերժում է այդ ժառանգված ինքնությունները և պահանջում է նոր `OmniRoute Codex v2` միակցիչ։

## Անվտանգության մոդել

- Բնիկ ուղին պահանջում է Responses հարցում, ճանաչված Codex հաճախորդ և համապատասխանող շղթայի ու քայլի նույնականացուցիչներ։
- Աշխատանքային տարածքը, sandbox-ը, հաստատման քաղաքականությունը և գործիքների կատալոգը տրամադրվում են բնիկ Codex shell-ի կողմից․ ազատ ձևաչափով հուշման տեքստը դրանց համար լիազորության աղբյուր չէ։
- ChatGPT-ն յուրաքանչյուր քայլի համար ստանում է միայն կարճաժամկետ հասանելիության հնարավորություն։ MCP միջնորդն ընդունում է միայն այն գործիքները, որոնք Codex-ն առաջարկել է հենց այդ քայլում։
- **Allow once**-ի ինքնաշխատ հաստատումը միայն գործիքի հարցումն է վերադարձնում Codex-ին։ Միայն Codex-ն է որոշում հաստատման և կատարման մասին։
- Առաջին ելքային տվյալներից առաջ համակցությունը կարող է անցնել մեկ այլ համատեղելի թիրախի։ Ելքի մեկնարկից հետո մատակարարը, մոդելը, կապը և դիտարկիչի քայլը մնում են ամրագրված մինչև քայլի ավարտը։
- Cookie-ները, կատարման միջավայրի բանալիները, պահեստավորման վիճակը և հասանելիության թոքենները չեն հայտնվում մատակարարի պատասխաններում կամ հարցումների մատյաններում։

## Առանց էկրանի VPS և Docker

npm, systemd և PM2 տեղադրումների դեպքում OmniRoute-ը հայտնաբերում է Chrome-ի և Chromium-ի տարածված ուղիները։
Այլընտրանքային տարբերակով սահմանեք `CHATGPT_WEB_CODEX_CHROME_PATH`։ Կատարման միջավայրի քայլերը միտումնավոր օգտագործում են տեսանելի ինտերֆեյսով Chrome, քանի որ ChatGPT-ն մերժում է իրական headless դիտարկիչի կառուցվածքը։ Հետևաբար, առանց էկրանի հոսթը պետք է OmniRoute-ը գործարկի մասնավոր Xvfb ցուցադրիչով․ միայն Chrome-ի ուղին սահմանելը ցուցադրիչ չի տրամադրում։

Docker-ի `web` պրոֆիլը ներքին Compose ցանցում գործարկում է `chatgpt-web-codex-browser`-ը։
Կողային կոնտեյները տեսանելի ինտերֆեյսով Chrome-ը գործարկում է Xvfb-ի ներսում, ուստի ֆիզիկական էկրան չի պահանջվում։ Դրա CDP պորտը հոսթի վրա հրապարակված չէ։ Պաշտպանված դիտարկիչի պրոֆիլի հատորը առանձնացված է OmniRoute-ի տվյալների հատորից, իսկ դիտարկիչին տրամադրվում է բավարար համօգտագործվող հիշողություն։ Ներքին CDP պրոքսին Compose ցանցի ներսում լսում է միայն `9223` պորտը․ կողային կոնտեյներում Chrome-ը շարունակում է կապված մնալ loopback-ին։

`DATA_DIR`-ի ներքո վերահսկիչի վարձակալման մեխանիզմը կանխում է, որ OmniRoute-ի մի քանի գործընթացներ միաժամանակ տնօրինեն նույն թունելի և միջնորդի վիճակը։ Հակասության մասին հայտնում է doctor-ը։

## Ինտերակտիվ վերականգնում

Docker-ի ավտոմատացված ուղին հոսթում տեսանելի պատուհան չունի, սակայն մասնավոր Xvfb ցուցադրիչի ներսում Chrome-ն ինքնին աշխատում է տեսանելի ինտերֆեյսով։ Երբ ChatGPT-ն պահանջում է ինտերակտիվ մուտք կամ ստուգում, վերականգնման համար կարելի է օգտագործել առկա VNC դիտարկիչային ենթակառուցվածքը։ Դիտարկիչի UI-ն և CDP-ն պետք է հասանելի մնան միայն loopback-ի, նույնականացված կառավարման կապի կամ SSH թունելի միջոցով․ սովորական աշխատանքի ընթացքում noVNC-ն մնում է անջատված։

## WebSocket-ի պահուստային տարբերակ

Երբ համակցությունը պարունակում է ChatGPT Web (Codex), Responses WebSocket կամուրջը, նախքան վերին հոսքին միանալը, պահանջում է անցում HTTP/SSE պահուստային տարբերակին։ Այնուհետև փոխանցումն իրականացվում է
`/v1/responses`-ի միջոցով։
