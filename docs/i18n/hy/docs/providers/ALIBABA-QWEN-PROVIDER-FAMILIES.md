Այս փաստաթուղթն արձանագրում է
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854)-ի իրականացման որոշումը։ Հանրային պրոդուկտները
ներկայացված են որպես պրովայդերների չորս ընտանիք։ Տարածաշրջանը կապի տվյալ է, այլ ոչ թե առանձին պրոդուկտ։

## Որոշում

| Պրովայդերի ընտանիք                                   | OmniRoute ID            | Գլոբալ տարածաշրջան | Չինաստանի տարածաշրջան |
| ---------------------------------------------------- | ----------------------- | ------------------ | --------------------- |
| Alibaba Cloud Model Studio (վճարում ըստ օգտագործման) | `alibaba`               | Սինգապուր          | Պեկին                 |
| Alibaba Cloud Token Plan                             | `bailian-coding-plan`   | Սինգապուր          | Պեկին                 |
| Qwen Cloud (վճարում ըստ օգտագործման)                 | `qwen-cloud`            | Գլոբալ             | Պեկին                 |
| Qwen Cloud Token Plan                                | `qwen-cloud-token-plan` | Սինգապուր          | Պեկին                 |

Գոյություն ունեցող `alibaba-cn` ID-ն շարունակում է գործել որպես կատարման ժամանակի համատեղելիության այլանուն՝ պահպանված կապերի, մոդելների
երթուղիների, համակցությունների և օգտագործման պատմական տվյալների համար։ Վահանակում դրա քարտը միավորվում է `alibaba`-ի հետ․ տվյալների բազայի
վերագրում չի պահանջվում։

Qwen Cloud-ի՝ ըստ օգտագործման վճարմամբ տարբերակը և Alibaba Cloud Model Studio-ն ներկայում օգտագործում են DashScope-ի հետ համատեղելի
կատարման միջավայրի նույն հոսթերը, սակայն շարունակում են մնալ պրովայդերների առանձին նույնություններ, քանի որ օգտատերերը բանալիներ են ստանում և
հաշիվները կառավարում տարբեր պրոդուկտային միջերեսների միջոցով։ Alibaba և Qwen Cloud Token Plan պրոդուկտներն օգտագործում են
վերջնակետերի տարբեր ընտանիքներ, ուստի բոլոր չորս պրոդուկտները շարունակում են ունենալ առանձին պրովայդերի ID-ներ։

## Վերջնակետերի մատրից

| Պրովայդերի ընտանիք      | `global-sg`                                                              | `china-beijing`                                                      | Փոխանցման ձևաչափ |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ---------------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI           |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic        |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI           |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI           |

API բանալին և վերջնակետը պետք է պատկանեն նույն պրոդուկտին և տարածաշրջանին։ Տարածաշրջան ընտրելիս
փոխվում է վավերացման և սովորական հարցումների համար օգտագործվող նախապես սահմանված վերջնակետը։

## Կապի պայմանագիր

Նոր կապերը տարածաշրջանի կայուն բանալին պահպանում են `providerSpecificData`-ում․

```json
{
  "region": "global-sg"
}
```

Թույլատրելի արժեքներն են `global-sg` և `china-beijing`։ Վերջնակետը կենտրոնացված կերպով որոշվում է
պրովայդերի ID-ի և տարածաշրջանի հիման վրա։ Նախապես սահմանված չլինող `providerSpecificData.baseUrl`-ը շարունակում է համարվել օպերատորի բացահայտ
վերասահմանում և ունի առաջնահերթություն, մինչդեռ նախկինում պահպանված նախապես սահմանված URL-ները հետ են նորմալացվում ըստ տարածաշրջանային
մատրիցի։

Սա կապի սխեման պահում է ընդլայնելի․ լուծիչում կարելի է ավելացնել ևս մեկ տարածաշրջան՝ առանց
պրովայդերի ևս մեկ քարտ ստեղծելու կամ պահպանված պրովայդերի ID-ները փոխելու։

## Համատեղելիություն և ներդրում

1. Ավելացնել տարածաշրջանային վերջնակետի որոշիչը և պահպանել ընթացիկ գլոբալ լռելյայն արժեքները։
2. Օգտագործել կենդանի տարածաշրջանային DashScope `/models` հայտնաբերումը `alibaba`-ի, դրա համատեղելիության `alibaba-cn`
   ID-ի և `qwen-cloud`-ի համար։ Դրանց պատասխանները նախ անցնում են տեքստի գեներացման մեկ զտիչով, քանի որ ընդհանուր
   վերջնակետը վերադարձնում է նաև պատկերների, տեսանյութերի, աուդիոյի, ներդրումների և զրույցի համար չնախատեսված այլ մոդելներ։ Այնուհետև `qwen-cloud`-ը
   կիրառում է իր մատակարարի գրանցամատյանում հայտարարված և սպասարկվող թույլատրված ցանկը։ Alibaba Model Studio-ն
   և Qwen Cloud-ը պահպանում են առանձին ընտրված կատալոգներ, թեև ներկայում օգտագործում են նույն գործարկման հոսթերը։
3. Գրանցել `qwen-cloud-token-plan`-ը՝ ընթացիկ Token Plan տեքստային մոդելների թույլատրված ցանկով։
4. Կապի ավելացման/խմբագրման երկխոսություններում ավելացնել տիպավորված տարածաշրջանի ընտրիչ։
5. Թաքցնել կրկնօրինակ `alibaba-cn` քարտը և դրա առկա կապերը ներառել `alibaba`
   մատակարարի էջում։
6. Ընդլայնված և աշխատանքային տարածքին հատուկ տեղակայումների համար հասանելի պահել հատուկ վերջնակետերի վերագրումները։

Token Plan-ի մեդիա մոդելները մնում են զրույցի կատալոգից դուրս, քանի որ օգտագործում են առանձնացված վերջնակետեր։
`wan2.7-image`-ը և `wan2.7-image-pro`-ն գրանցված են `open-sse/config/imageRegistry.ts`-ում,
իսկ `happyhorse-1.1-i2v`-ը, `happyhorse-1.1-t2v`-ն ու `happyhorse-1.1-r2v`-ը՝
`open-sse/config/videoRegistry.ts`-ում։ Երկու գրանցամատյաններն էլ կրկնակի օգտագործում են `qwen-cloud-token-plan` կապի
ինքնությունը և դրա տարածաշրջանին հատուկ հավատարմագրերը։

Սովորական Qwen Cloud-ն ունի ըստ օգտագործման վճարվող պատկերների և տեսանյութերի առանձին կատալոգներ՝ `qwen-cloud`
ինքնության ներքո։ Դրա պատկերային մոդելներն են `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` և `z-image-turbo`։ Դրա տեսանյութային
մոդելներն են `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` և
`wan2.7-videoedit`։ Այս մոդելները կրկնակի օգտագործում են միայն սովորական `qwen-cloud` կապը և տարածաշրջանային
DashScope մեդիա վերջնակետը։ Token Plan-ի և ըստ օգտագործման վճարվող տարբերակի գրանցամատյանները չեն ժառանգում կամ միավորում
միմյանց մոդելների ցանկերը։

`bailian-coding-plan` ինքնությունը նույնպես ունի մեդիայի իր սեփական թույլատրված ցանկերը՝
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` և `qwen-image-2.0-pro`՝ պատկերների
գեներացման համար, ինչպես նաև
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` և `happyhorse-1.1-r2v`՝ տեսանյութերի
գեներացման համար։ Այն օգտագործում է միայն Bailian Coding Plan կապը և տարածաշրջանային Coding Plan վերջնակետը։
Դրա պատկերների և տեսանյութերի գրանցամատյանները չեն ժառանգում կամ միավորվում Qwen Cloud-ի մատակարարներից որևէ մեկի հետ։

Սովորական `alibaba` ինքնությունն ունի պատկերների և տեսանյութերի առանձին թույլատրված ցանկեր։ Դրա պատկերային մոդելներն են
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` և `wan2.6-t2i`։ Դրա ավելացված տեսանյութային մոդելներն են `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` և `wan2.7-videoedit`։ Այս մոդելներն օգտագործում են միայն Alibaba Model Studio
կապը և դրա ընտրված տարածաշրջանային մեդիա վերջնակետը․ դրանք չեն ավելացվում Coding Plan-ի կամ Qwen
Cloud-ի որևէ գրանցամատյանում։

Qwen Cloud Token Plan-ի զրույցի կատալոգը հետևում է Individual պլանի՝ տողերի ճշգրիտ համընկնմամբ տեքստային թույլատրված ցանկին՝
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` և
`deepseek-v4-pro`։ Wan և HappyHorse գրառումները պատկանում են պատկերների/տեսանյութերի գեներացման առանձին API-ներին։

Alibaba Token Plan-ը նույն վեց ընթացիկ տեքստի գեներացման մոդելների ID-ները հասանելի է դարձնում իր
Anthropic-ի հետ համատեղելի վերջնակետի միջոցով։ Դրա Սինգապուրի տարբերակը պահպանում է առկա `global-sg` տարածաշրջանային բանալին․
մատակարարների մյուս ընտանիքների համեմատ տարբերվում է միայն օգտատիրոջը ցուցադրվող պիտակը, որտեղ տարածաշրջանն անվանվում է Global։

Սովորական Qwen Cloud-ի զրույցի կատալոգը դիտավորյալ ավելի նեղ է, քան ամբողջական կենդանի տեքստային պատասխանը։ Դրա
սպասարկվող թույլատրված ցանկը գտնվում է `open-sse/config/providers/registry/qwen-cloud/index.ts`-ում․ կենդանի
հայտնաբերումը վերադարձնում է միայն այն ID-ները, որոնք առկա են և՛ վերին հոսքի պատասխանում, և՛ այդ գրանցամատյանի ցանկում։

Alibaba Model Studio-ն հետևում է կենդանի հատման նույն կանոնին՝ իր անկախ սպասարկվող
թույլատրված ցանկով, որը գտնվում է `open-sse/config/providers/registry/alibaba/index.ts`-ում։ Համատեղելիության
`alibaba-cn` մատակարարը կրկնակի օգտագործում է այդ կատալոգը՝ հայտնաբերման հասցեն որոշելով Պեկինի վերջնակետի նկատմամբ։
