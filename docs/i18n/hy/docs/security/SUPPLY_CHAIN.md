OmniRoute-ը հրապարակում է npm + Docker արտեֆակտներ։ Այս դարպասներն ապահովում են ծագումնաբանություն, գույքագրում (SBOM) և CVE սկանավորում, բոլորը՝ OSS, ինտեգրված թողարկման աշխատանքային հոսքերին։ **Խորհրդատվական-առաջնային** դիրքորոշում — դրանք հիմա են զեկուցում, արգելափակողի են վերածվում 1-ին հաջող թողարկումից հետո։

| Դարպաս                        | Գործիք                                         | Որտեղ                         | Արգելափակո՞ւմ է                    | Ելք                                                               |
| :---------------------------- | :--------------------------------------------- | :---------------------------- | :--------------------------------- | :---------------------------------------------------------------- |
| SLSA ծագումնաբանություն (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | միայն հրապարակման ձախողման դեպքում | նշան npmjs / `npm audit signatures`                               |
| SBOM npm                      | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | միայն ստեղծման ձախողման դեպքում    | Թողարկման ակտիվ + արտեֆակտ                                        |
| SBOM պատկեր                   | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | խորհրդատվական                      | CycloneDX արտեֆակտ                                                |
| Trivy CVE (SARIF)             | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | խորհրդատվական                      | SARIF (ԲԱՐՁՐ+ԿՐԻՏԻԿԱԿԱՆ) → Անվտանգության ներդիր                   |
| Trivy ԿՐԻՏԻԿԱԿԱՆ դարպաս       | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | **արգելափակող**                    | `exit-code: '1'` շտկվող ԿՐԻՏԻԿԱԿԱՆ-ի դեպքում                      |
| osv vulnCount                 | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **արգելափակող**                    | սահմանում է շեմ `metrics.vulnCount`-ի համար (ուղղություն՝ նվազող) |
| OpenSSF Scorecard             | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | խորհրդատվական                      | SARIF → Անվտանգություն + նշան                                     |

Պատկերի CVE շեմը `docker-publish.yml`-ում օգտագործում է **երկու քայլ**. SARIF քայլը (`HIGH,CRITICAL`, `exit-code: 0`) պահում է ԲԱՐՁՐ+ԿՐԻՏԻԿԱԿԱՆ-ը տեսանելի Անվտանգության ներդիրում՝ առանց արգելափակելու. _ԿՐԻՏԻԿԱԿԱՆ դարպասի_ քայլը (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) ձախողում է թողարկումը ԿՐԻՏԻԿԱԿԱՆ CVE-ի դեպքում՝ **առկա շտկումով**։ `ignore-unfixed`-ը կանխում է թողարկման արգելափակումը բազային պատկերի CVE-ի համար՝ առանց վերին հոսքի կարկատանի։

## ⚠️ CVE Տարբերություն (արգելափակող osv/Trivy դարպասներ)

osv-ը և Trivy-ը համեմատում են կախվածությունները CVE տվյալների բազաների հետ, որոնք **անընդհատ աճում են**։ Մի PR, որը **չի շոշափում կախվածություններ**, կարող է հանկարծ կարմրել, քանի որ նոր CVE է բացահայտվել առկա կախվածության մեջ (osv՝ չափված `vulnCount` > բազային; Trivy՝ նոր շտկվող ԿՐԻՏԻԿԱԿԱՆ պատկերում)։ **Սա արգելափակող CVE դարպասի ԱԿՆԿԱԼՎՈՂ գործառնական վարքագիծ է, ոչ թե արտադրանքի ռեգրեսիա։**

Երբ osv-ը կամ Trivy-ը կարմրում են նոր բացահայտված CVE-ի պատճառով, լուծումը հետևյալն է.

1.  **Թարմացնել ազդակիր կախվածությունը** (նախընտրելի է) — թարմացնել մինչև կարկատված տարբերակը `package.json` `overrides`-ի միջոցով (տրանզիտիվ կախվածություններ) կամ վերակառուցել պատկերը կարկատված բազայի վրա։
2.  **Եթե վերին հոսքի շտկում չկա.**
    - **osv.** վերասահմանել `metrics.vulnCount`-ի բազային արժեքը `config/quality/quality-baseline.json`-ում (`npm run quality:ratchet -- --update`-ը չի ընդգրկում հատուկ դարպասները — արժեքը ձեռքով խմբագրել, `direction:down`) հիմնավորման նշումով + հետևման խնդրով։
    - **Trivy.** ավելացնել գրառում `.trivyignore`-ում (CVE-ID յուրաքանչյուր տողում) հիմնավորման մեկնաբանությամբ + հետևման խնդրով։ `ignore-unfixed: true`-ն արդեն ավտոմատ կերպով ընդգրկում է CVE-ները՝ առանց կարկատանների։

Երկու դարպասներն էլ **նրբորեն ԲԱՑ ԹՈՂՆՈՒՄ ԵՆ** (exit 0), երբ գործիքը բացակայում է կամ չափումը ձախողվում է (osv-scanner-ը PATH-ում չէ, osv.dev/network-ը անհասանելի է, անվավեր JSON) — **չափման** ձախողումը երբեք չի արգելափակում, միայն **չափված** ռեգրեսիան է արգելափակում։

## Հայտնի ընդունված ռիսկեր

### extract-zip 2.0.1 — GHSA-7pqw-9j4j-h8q3 / GHSA-jmr9-qjv8-65gv (#14482)

`extract-zip@2.0.1`-ը պարունակում է երկու չուղղված բարձր ծանրության symlink-traversal խորհրդատվություն։ Վերոնշյալ CVE Variance լուծման «առանց վերին հոսքի շտկման» ճյուղի համաձայն, սա **ընդունված ռիսկ է**, ոչ թե թարմացում։

- **Շղթա.** `promptfoo` (devDependency) → `@openai/codex-security` → `extract-zip@2.0.1`: Հաստատված է `package-lock.json`-ի միջոցով — կախվածությունների ամբողջ ծառում ճիշտ մեկ փաթեթ (`@openai/codex-security`) հայտարարում է `extract-zip`, և ճիշտ մեկ փաթեթ (`promptfoo`) հայտարարում է `@openai/codex-security`:
- **Շղթայի որևէ տեղում շտկված թողարկում գոյություն չունի։** `extract-zip@2.0.1` (հրապարակված 2020 թ.) փաթեթի վերջին թողարկումն է՝ այն չի սպասարկվում։ `@openai/codex-security`-ի ներկայիս npm-latest (`0.1.29`) դեռևս օգտագործում է `extract-zip@2.0.1`։
- **Անհասանելի է արտադրությունից։** `promptfoo`-ն միայն devDependency է (երբեք չի նշվում `dependencies`-ի տակ), և `src/`, `open-sse/` կամ `bin/` տակ գտնվող ոչ մի ֆայլ չի ներմուծում `extract-zip` npm փաթեթը — OmniRoute-ի սեփական `extractZip()` օգնականը (`src/lib/versionManager/binaryManager.ts:93`) օգտագործում է բնիկ `unzip`/`tar` և կապ չունի։ `@openai/codex-security`-ն նաև տրամադրում է իր սեփական symlink-traversal պաշտպանությունը `extract-zip`-ի `onEntry` callback-ի վրա։
- **Մի՛** կեղծանունավորեք `extract-zip`-ը `package.json` `overrides`-ի միջոցով — միակ կենսունակ փոխարինողը Electron-org-internal-ն է և API-անհամատեղելի է `@openai/codex-security`-ի սեփական onEntry/defaultDirMode/defaultFileMode ստուգումների հետ. այն վերագրելը լուռ կխախտեր այդ փաթեթի անվտանգության ստուգումները։
- **Հիմնագիծ.** չափված osv `vulnCount` (3) արդեն իսկ շատ ցածր է սառեցված `config/quality/quality-baseline.json` հիմնագծից (27) — ռաչետի փոփոխություն անհրաժեշտ չէ։
- **Ռեգրեսիայի պաշտպանություն.** `tests/unit/extract-zip-14482-exposure.test.ts`-ը հաստատում է վերոնշյալ շղթան և արտադրությունից ներմուծման բացակայության ինվարիանտը. այն ձախողում է CI-ը, եթե դրանցից որևէ մեկը երբևէ խախտվի (օրինակ՝ ապագա PR-ը `extract-zip`-ը հասանելի դարձնի արտադրությունից)։

## Հետաձգված. Scorecard խորհրդատվություն → արգելափակում

Scorecard-ի հաշվետվությամբ առաջին հաջող թողարկումից հետո.

- Scorecard. միավորի ռաչետ (սառեցնում է չափված միավորը. չի կարող նվազել)։

Լրացնում է Փուլ 7-ի դարպասները (osv-scanner, gitleaks, actionlint+zizmor). zizmor-ը ստուգում է հենց աշխատանքային հոսքերը. Scorecard-ը չափում է պահոցի վիճակը ընդհանուր առմամբ։
