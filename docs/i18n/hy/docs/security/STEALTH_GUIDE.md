OmniRoute-ը ինտեգրվում է այն մատակարարների հետ, որոնց եզրային համակարգերն ակտիվորեն մատնահետքում են ոչ պաշտոնական հաճախորդներին (TLS JA3/JA4, վերնագրերի հերթականություն, JSON մարմնի կառուցվածք, ամբողջականության թոքեններ)։ Այս էջը նկարագրում է OmniRoute-ի տրամադրած քողարկման մակերեսները և դրանց իրականացման վայրերը։

## Իրավական և էթիկական ծանուցում

Քողարկման գործառույթները նախատեսված են, որպեսզի OmniRoute-ը կարողանա ծառայել որպես համատեղելիության շերտ՝ օգտատերերին պատկանող պաշտոնական հաշիվների (Claude Code CLI, Codex, Antigravity, Cursor և այլն) և OmniRoute-ի միասնական API-ի միջև։ Դրանք **նախատեսված չեն** խարդախության հայտնաբերումը շրջանցելու, հավատարմագրերը համօգտագործելու կամ մատակարարի Ծառայությունների մատուցման պայմանները խախտելու համար։ Սպասարկողները ակնկալում են, որ օպերատորները կհետևեն հաշիվներ ստեղծելիս իրենց ընդունած վերին հոսքի ToS-ին։

## TLS մատնահետկման շերտ

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

Մշտական `wreq-js` աշխատաշրջանները ծույլ եղանակով ստեղծվում են յուրաքանչյուր հաշվի տիրույթի և որոշված պրոքսիի համար։ Ամբողջ գործընթացի մակարդակով գործող `TlsClient`-ը հավաքակազմում պահում է առավելագույնը 128 աշխատաշրջան, որոնք Cloudflare-ի հետևում գտնվող վերին հոսքերի համար ներկայանում են որպես **macOS-ում աշխատող Chrome 124**։ Երբ բնիկ կատարման միջավայրն անհասանելի է, `TlsClient.fetch()`-ը խափանվում է փակ սկզբունքով․ կանչող կողմը կարող է այս փաթաթիչից դուրս բացահայտորեն ընտրել պահուստային տարբերակ։

- Աշխատաշրջանի պրոֆիլ՝ `browser: "chrome_124", os: "macos"`
- Պրոքսիի որոշում (ըստ առաջնահերթության)՝ `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (նաև փոքրատառ տարբերակները)
- Ժամանակի սահմանափակում՝ `TLS_CLIENT_TIMEOUT_MS` (ժառանգվում է `FETCH_TIMEOUT_MS`-ից, լռելյայն՝ 600000)
- `wreq-js` Response-ը համատեղելի է fetch-ի հետ (`headers`, `text()`, `json()`, `clone()`, `body`)։
- Առաջին բայթի վերահսկիչ (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656)՝ `TlsClient.fetch()`-ը
  ավարտվում է վերին հոսքի վերնագրերը ստանալուն պես, ուստի միայն `TLS_CLIENT_TIMEOUT_MS`-ը չի կարող սահմանափակել այն
  մարմինը, որը երբեք առաջին բայթ չի տրամադրում։ `guardTlsFirstByte()`-ը մրցակցության մեջ է դնում մարմնի առաջին `read()`-ը
  և `TLS_FIRST_BYTE_WATCHDOG_MS`-ը (լռելյայն՝ `10000`, `0`-ն անջատում է այն)․ առողջ մարմնի վրա
  դա չի ազդում, իսկ կանգ առած մարմնի դեպքում չեղարկվում է wreq ընթերցիչը, և `proxyFetch`-ի առկա
  TLS պահուստային տրամաբանությունը շարունակում է աշխատանքը՝ անցնելով ուղղակի/պրոքսի դիսպետչերին (վերարտադրման համար ոչ անվտանգ հարցումը, օրինակ՝
  մարմին ունեցող POST-ը, այնուամենայնիվ, սխալ է նետում՝ լռելյայն կերպով կրկին փորձվելու փոխարեն)։

### Վեբ cookie օգտագործող մատակարարի փոխադրում — wreq-js 3.2.0

`open-sse/services/tlsClientBase.ts`-ը ստորև ներկայացված հինգ մասնագիտացված
վեբ cookie փոխադրումների ընդհանուր ադապտերն է։ Մատակարարի յուրաքանչյուր բարակ փաթաթիչ ընտրում է զննարկիչի/ՕՀ-ի պրոֆիլ։ Ադապտերն
օգտագործում է `open-sse/utils/tlsClient.ts`-ում գտնվող միասնական wreq կատարման միջավայրի բեռնիչը և փոխադրումների հավաքակազմը՝ բանալիավորելով
ըստ պրոֆիլի + ՕՀ-ի + որոշված պրոքսիի, մինչդեռ յուրաքանչյուր հարցում օգտագործում է `cookieMode: "ephemeral"`։ Հետևաբար, հաշիվներն ու
հարցումները համօգտագործում են փոխադրման մակարդակի կապերը, բայց երբեք չեն համօգտագործում wreq աշխատաշրջանը կամ cookie-ների պահոցը։

| Մատակարար  | Պրոֆիլ        | Նմանակված ՕՀ | Հոսքի EOF քաղաքականություն             |
| ---------- | ------------- | ------------ | -------------------------------------- |
| Claude     | `chrome_146`  | Linux        | ներառել `[DONE]`                       |
| Perplexity | `firefox_148` | macOS        | ներառել `event: end_of_stream`         |
| Grok       | `chrome_146`  | Linux        | բացառել `[DONE]`                       |
| Notion     | `chrome_146`  | Windows      | ներառել `[DONE]`                       |
| LMArena    | `chrome_146`  | Windows      | վերջանիշ չկա․ փակել բնիկ EOF-ի դեպքում |

- Հոսքային փոխանցումն անմիջապես սպառում է բնիկ պատասխանի `ReadableStream`-ը․ ժամանակավոր ֆայլ կամ օժանդակ գործընթաց
  չի ստեղծվում։
- Նախքան հոսքը հասանելի դարձնելը ստուգվում է մինչև 256 սկզբնական բայթ։ SSE մատակարարները բուֆերացնում են ոչ SSE
  սխալները․ Grok/LMArena-ն Cloudflare-ի ստուգումները փոխակերպում է `403`-ի, իսկ HTML միջանկյալ էջերը՝ `502`-ի։
- Բնիկ հարցման ժամանակի սահմանափակումը շարունակում է փաթաթված մնալ JS-ի բացարձակ կոշտ վերջնաժամկետով։ Կախված վիճակը անվավեր է դարձնում
  և փակում է միայն ազդակիր պրոֆիլ/ՕՀ/պրոքսի փոխադրումը, որը վերստեղծվում է հաջորդ հարցումից առաջ։
- Պրոքսիի որոշման առաջնահերթությունը հետևյալն է՝ յուրաքանչյուր կանչի `proxyUrl` → հարցման տիրույթում գործող հաշվի/վահանակի համատեքստ →
  `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (ներառյալ փոքրատառ տարբերակները)։ Որոշման սխալները փակ սկզբունքով են խափանվում՝
  ուղղակի կապի արտահոսքը կանխելու համար։ LMArena-ն միտումնավոր կատարում է որոշումը `arena.ai`-ի նկատմամբ։
- `byteResponse`-ը վերադարձնում է ըստ բովանդակության տեսակի սահմանված `data:` URL՝ առանց UTF-8 աղավաղման։
- Սխալներն են՝ `TlsClientUnavailableError` (փաթեթը/հավելումը հասանելի չէ), `TlsClientHangError`
  (վերջնաժամկետը գերազանցված է) և `WreqTransportCapacityError` (աշխատաշրջանի տարողության համօգտագործվող սխալի կոդը),
  երբ բոլոր 128 սահմանափակված պրոֆիլ/ՕՀ/պրոքսի բնիկներն ակտիվ են կամ փակման ընթացքում են։

Վերոնշյալ ընդհանուր `TlsClient` աշխատաշրջանը շարունակում է մասնագիտացված մնալ զննարկչով ապահովվող cookie-ների
մշտական վիճակի համար։ Երկու ուղիներն էլ կրկին օգտագործում են նույն քեշավորված wreq մոդուլի բեռնիչը և գործընթացի կենսացիկլի մշակիչը․ դրանց հավաքակազմերը
մնում են առանձին, քանի որ դրանց cookie-ների կյանքի տևողությունները միտումնավոր տարբեր են։

Պրոֆիլներն աջակցվում են ամրագրված փաթեթի կողմից, սակայն WAF-ի իրական ընդունելիությունը կարող է փոփոխվել՝ անկախ
տեղային պայմանագրային թեստերից։ Նախքան վերին հոսքի զննարկչի հետ համարժեքության մասին պնդելը՝ մատնահետքի փոփոխությունները ստուգեք
բացահայտորեն լիազորված իրական հաշվի միջոցով։

## Claude Code-ի քողարկման փաթեթ

Երբ `cliCompatMode`-ը միացված է, OmniRoute-ը վերաձևավորում է ելքային Claude հարցումները, որպեսզի դրանք չտարբերվեն `claude-cli` թրաֆիկից։ Համագործակցում են երեք մոդուլներ․

### `claudeCodeFingerprint.ts`

Հաշվում է վճարումների վերնագրում ներդրված 3-նիշանոց `cc_version` մատնահետքը․

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (կոշտ կոդավորված է, համապատասխանում է պաշտոնական հաճախորդին)
- Մուտքային տվյալներ՝ օգտատիրոջ առաջին հաղորդագրության տեքստի 4, 7 և 20 ինդեքսներում գտնվող նիշերը + տարբերակի տողը
- Ելքային տվյալ՝ 3-նիշանոց տասնվեցական նախածանց

### `claudeCodeCCH.ts` (Հաճախորդի բովանդակության հեշ)

Սերվերային ամբողջականության ստուգում, որը պաշտոնական Claude Code CLI-ն հաշվարկում է Bun/Zig-ի միջոցով։ OmniRoute-ը դա վերաիրականացնում է `xxhash-wasm`-ով․

1. Սերիականացնել մարմինը՝ օգտագործելով `cch=00000;` տեղապահը
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. Ձախից զրոներով լրացված, փոքրատառ 5-նիշանոց տասնվեցական արժեք
4. Փոխարինել `cch=00000;`-ը հաշվարկված թոքենով

Հաստատուններ․

- Սերմ՝ `0x6e52736ac806831e`
- Կաղապար՝ `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

«Զգայուն» հաճախորդների անունների առաջին նիշից հետո տեղադրում է Unicode-ի **զրոյական լայնությամբ միացնող** (`U+200D`), որպեսզի վերին հոսքի զտիչները չկարողանան դրանք գտնել grep-ով։ Լռելյայն բառացանկը՝

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

Կիրառվում է՝ `system` բլոկների, բոլոր `messages[].content`-ների և `tools[].description` / `tools[].function.description`-ների նկատմամբ։ Օպերատորը կարող է վերասահմանել `setSensitiveWords()`-ի միջոցով։

### `claudeCodeCompatible.ts` — `anthropic-compatible-cc-*` մատակարարներ

Երրորդ կողմի Anthropic ռելեների համար, որոնք ընդունում են միայն «իրական Claude Code» թրաֆիկ․

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.258 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- Լռելյայն՝ `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"`
- Յուրաքանչյուր կապի «Միացնել redact-thinking բետան» փոխարկիչն ավելացնում է `redact-thinking-2026-02-12`, երբ CC Compatible վերին հոսքը հատուկ պահանջում է խմբագրված մտածողության հոսքեր
- Յուրաքանչյուր կապի «Միացնել ամփոփ մտածողության ցուցադրումը» փոխարկիչը պահպանում է `providerSpecificData.requestDefaults.summarizeThinking`-ը և ավելացնում `display: "summarized"` այն CC Compatible մտածողության հարցումներին, որոնցում ցուցադրման ռեժիմն արդեն սահմանված չէ
- `CONTEXT_1M_BETA_HEADER = "context-1m-2025-08-07"` (Opus/Sonnet 4.x ընտանիք)
- Լռելյայն ուղի՝ `/v1/messages?beta=true`

Նույն փաթեթի հարակից մոդուլները․

- `claudeCodeConstraints.ts` — ջերմաստիճանի + cache-control-ի կանոններ
- `claudeCodeToolRemapper.ts` — գործիքների անունների վերաքարտեզագրում
- `claudeCodeExtraRemap.ts` — լրացուցիչ օգտակար բեռի նորմալացում

## Antigravity-ի քողարկում

Antigravity հարցումները պահպանում են կանչողի տեքստը բայթ առ բայթ։ OmniRoute-ը հրահանգների մեջ չի տեղադրում զրոյական լայնությամբ նիշեր և չի վերանվանում կամ ներարկում գործիքներ՝ IDE հաճախորդին նմանակելու համար։

### `antigravityHeaderScrub.ts`

Փոխանցելուց առաջ հեռացնում է Stainless SDK-ի նշիչները (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`)։

### ⚠️ Ռիսկ՝ `ANTIGRAVITY_CREDITS=always` (հաշվի արգելափակման բարձր ռիսկի կետ)

`ANTIGRAVITY_CREDITS=always`-ը (օգտագործվում է `open-sse/executors/antigravity.ts`-ի կողմից) **յուրաքանչյուր** հարցում ուղղորդում է Antigravity AI Credit Overages-ի միջոցով (Google-ի վճարովի կրեդիտներ), այլ ոչ թե թույլ տալիս, որ Google-ի անվճար մակարդակի քվոտան սահմանափակի օգտագործումը։ Սա փաստաթղթավորված է որպես գործառույթ, սակայն այն **Ծառայության պայմանների խախտման մասին մեզ հասնող հաղորդումների ամենատարածված պատճառն է**․ մի քանի Google Ultra հաշիվներ արգելափակվել են՝ ստանալով `403 / "service disabled for ToS violation" / insufficient_quota`, երբ մի քանի ժամ աշխատել են `=always`-ով։

Վերին հոսքի վերահսկողությունն իրականացվում է **Google-ի կողմից**, և OmniRoute-ը չի կարող դա կանխել։ Միջավայրի փոփոխականի անվանումը և առկա փաստաթղթերը ստեղծում են տպավորություն, թե այն միացնելն անվտանգ է, սակայն այդպես չէ։

**Ինչու է սա չարաշահման հայտնաբերման համակարգերն ավելի ագրեսիվ ակտիվացնում, քան միայն անվճար մակարդակի օգտագործումը․**

- Google-ի մեկ հաշվի միջոցով շարունակական ավտոմատացված ծախսերը տարբերվող կերպով են նշագրվում՝ համեմատած այն դեպքի հետ, երբ անվճար մակարդակը հասնում է քվոտային և կանգ է առնում։
- Լրացուցիչ կրեդիտները չունեն արագության վերին սահման, ուստի սխալ կազմաձևված հաճախորդը կարող է րոպեների ընթացքում ծախսել մի քանի հարյուր ԱՄՆ դոլար և նմանվել API բանալիների վերավաճառքի կամ բոտային թրաֆիկի։
- Միևնույն արտաքին IP-ից մի քանի OmniRoute օգտատերերի կողմից լրացուցիչ կրեդիտների զուգահեռ օգտագործումը ուժեղացնում է ազդանշանը։

**Առաջարկվող մոտեցումը․**

1. Պահպանեք լռելյայն `ANTIGRAVITY_CREDITS=off` արժեքը, եթե օպերատորը հստակորեն չի ընդունում վճարովի կրեդիտների և հաշվի նկատմամբ հարկադիր միջոցների ռիսկը։ `retry`-ն նախ ուղարկում է սովորական հարցումը և համապատասխան քվոտայի 429 պատասխանից հետո առավելագույնը մեկ անգամ ներարկում է կրեդիտներ, իսկ `always`-ը կրեդիտներ է ներարկում հենց առաջին հարցման ժամանակ։
2. **Բաշխեք բեռը մատակարարների միջև Auto-Combo-ի միջոցով** (`model: "auto"` կամ `kr/glm/etc`-combo)՝ Antigravity-ի մեկ հաշիվը գերբեռնելու փոխարեն։
3. **Սահմանեք յուրաքանչյուր կապի RPM սահմանափակումներ** Antigravity մատակարարի խմբագրման էջում (Dashboard → Providers → Antigravity → connection → rate limit)։ 30–60 RPM-ը հիմնավոր վերին սահման է շարունակական օգտագործման համար։
4. **Օգտագործեք կայուն, օպերատորի կողմից վերահսկվող վերին հոսքի ցանցային ենթակառուցվածք** և խուսափեք մեկ հաշիվը միմյանց հետ կապ չունեցող օգտատերերի կամ աշխատանքային բեռների միջև համօգտագործելուց։
5. **Արգելափակման դեպքում**՝ բողոքարկեք `support.google.com` → "Restore Workspace/Account access" բաժնի միջոցով՝ տրամադրելով Google-ի ուղարկած `quota_exceeded` / `service disabled` պատասխանի ճշգրիտ մարմինը։ Վերականգնումը երաշխավորված չէ։

Միջավայրի տեղեկատուն փաստաթղթավորում է կրեդիտների յուրաքանչյուր ռեժիմի՝ հաշվի և ծախսերի վրա ունեցած հետևանքները։

Առնչվող կետեր․

- `open-sse/executors/antigravity.ts` — կարդում է `process.env.ANTIGRAVITY_CREDITS`-ը
- `src/lib/oauth/providers/antigravity.ts` — հավատարմագրերի կապակցում
- Միջադեպի սկզբնական զեկույց՝ Քննարկում [#1183](https://github.com/diegosouzapw/OmniRoute/discussions/1183)

## CLI մատնահետքերի ռեեստր — `open-sse/config/cliFingerprints.ts`

Յուրաքանչյուր մատակարարի համար նախատեսված աղյուսակ, որն ամրագրում է պաշտոնական CLI-ների mitmproxy հետքերից ստացված վերնագրերի և JSON մարմնի դաշտերի դասավորության **ճշգրիտ** հերթականությունը։ Ներկայում գրանցված են՝ `codex`, `claude`, ինչպես նաև `providerHeaderProfiles.ts`-ում կատարման ժամանակ ձևավորվող պրոֆիլները՝ `antigravity`-ի և `github`-ի համար։

```ts
interface CliFingerprint {
  headerOrder: string[]; // մեծատառերի և փոքրատառերի նկատմամբ զգայուն
  bodyFieldOrder: string[]; // JSON-ի վերին մակարդակի բանալիներ
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

Յուրաքանչյուր մատակարարի համար միացրեք կամ անջատեք env-ի միջոցով (տե՛ս ստորև)։ Անջատված լինելու դեպքում վերնագրերը/մարմնի բանալիները հայտնվում են Node/JSON-ի տրամադրած ցանկացած հերթականությամբ, ինչը հեշտացնում է մատնահետքի որոշումը։

## MITM պրոքսի (Antigravity, Linux/macOS/Windows)

Այն CLI-ների համար, որոնց երկուական ֆայլերը հնարավոր չէ վերահղել `OPENAI_BASE_URL`-ի միջոցով, OmniRoute-ը գործարկում է տեղային TLS-ն ավարտող պրոքսի։ Վերջնակետերը գտնվում են `src/app/api/cli-tools/antigravity-mitm/`-ի ներքո։

| Մեթոդ  | Վերջնակետ                               | Նպատակ                                                   |
| ------ | --------------------------------------- | -------------------------------------------------------- |
| GET    | `/api/cli-tools/antigravity-mitm`       | Կարգավիճակ՝ running, pid, dnsConfigured, certExists      |
| POST   | `/api/cli-tools/antigravity-mitm`       | Գործարկել MITM-ը (պահանջում է `apiKey` + `sudoPassword`) |
| DELETE | `/api/cli-tools/antigravity-mitm`       | Կանգնեցնել MITM-ը                                        |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | Թվարկել մոդելների այլանունները                           |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | Պահպանել գործիքի մոդելների այլանունները                  |

Ընդհատվող նպատակային հոսթ՝ **`daily-cloudcode-pa.googleapis.com`** (Antigravity-ի վերին հոսքի ծառայությունը)։

### Գործարկման հաջորդականություն (`src/mitm/manager.ts::startMitm`)

1. Ստեղծել ինքնաստորագրված վկայագիր `selfsigned`-ի միջոցով (RSA-2048, SHA-256, 1 տարի) — `cert/generate.ts`
2. Տեղադրել վկայագիրը համակարգի վստահության պահոցում — `cert/install.ts`
3. Ավելացնել hosts գրառում՝ `127.0.0.1 daily-cloudcode-pa.googleapis.com` — `dns/dnsConfig.ts`
4. Գործարկել `src/mitm/server.cjs`-ը՝ `ROUTER_API_KEY` + `MITM_LOCAL_PORT`-ով (լռելյայն՝ `443`)
5. Պահպանել PID-ը `<DATA_DIR>/mitm/.mitm.pid`-ում

### Linux-ի վստահության պահոցի դինամիկ հայտնաբերում — `cert/install.ts`

`getLinuxCertConfig()`-ը հերթով ստուգում է առաջնահերթությունների ցանկը և ընտրում առաջին գոյություն ունեցող գրացուցակը։

| Դիստրիբուտիվների ընտանիք | Գրացուցակ                                   | Թարմացման հրաման         |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

Վկայագրի ֆայլի անուն՝ `omniroute-mitm.crt`։ Մատնահետքի համընկնումը կատարվում է `getCertFingerprint()`-ի միջոցով (DER-ի SHA-1)։

Բացի այդ, երբ հասանելի է `certutil`-ը, `updateNssDatabases()`-ը վկայագիրը տեղադրում է յուրաքանչյուր օգտատիրոջ NSS տվյալների բազաներում՝ `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, Firefox-ի բոլոր պրոֆիլներում (ներառյալ snap-ը), **`OmniRoute MITM Root CA`** մականվամբ։

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** բարձրացված արտոնություններով PowerShell → `certutil -addstore Root`

### Նույնականացում

Բոլոր MITM վերջնակետերը պահանջում են կառավարման նույնականացում (`requireCliToolsAuth`)։ sudo գաղտնաբառը քեշավորվում է մոդուլի տիրույթում (երբեք ոչ `globalThis`-ում) և մաքրվում է `stopMitm()`-ի ժամանակ։

## Մուտքային վերնագրերի մաքրում

OmniRoute-ը փոխանցելուց առաջ մաքրում է հաճախորդի մուտքային վերնագրերը, որպեսզի Cursor-ից ստացված հարցումը Claude-ի վերին հոսքին չբացահայտի `User-Agent: Cursor/X.Y.Z`-ը։ Արգելացանկը տե՛ս `src/shared/constants/upstreamHeaders.ts`-ում. այն համաժամեցված է Zod սխեմաների և միավորային թեստերի հետ։

## Մատնահետքերի թարմացում, երբ մատակարարը դրանք փոխում է

1. Գրանցեք պաշտոնական CLI-ի թրաֆիկը `mitmproxy`-ով (TLS գաղտնազերծում + արտահանում)
2. Դուրս բերեք JA3/JA4-ը և վերնագրերի ճշգրիտ հերթականությունը
3. Թարմացրեք համապատասխան `CLI_FINGERPRINTS[...]` գրառումը
4. Թարմացրեք համապատասխան `*_USER_AGENT` լռելյայն արժեքը `.env.example`-ում
5. Եթե փոխվել է հենց TLS ձեռքսեղմումը, թարմացրեք համապատասխան մատակարարի փաթեթավորիչը կամ wreq-js-ի `browser:` տարբերակը
6. Գործարկեք մատակարարին հատուկ TLS թեստերը և ձեռքով փորձնական ստուգում կատարեք գործող մատակարարի նկատմամբ
7. Թողարկեք շտկումային տարբերակով. փաստագրեք `CHANGELOG.md`-ում
