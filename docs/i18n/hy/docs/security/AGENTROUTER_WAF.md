`agentrouter`-ի վերին մակարդակի gateway-ը `messages[].content`-ի նկատմամբ կիրառում է հիմնաբառերի վրա հիմնված բովանդակության զտիչ։ Զտիչը մասամբ դետերմինիստական է (միշտ արգելափակում է որոշակի արտահայտություններ) և մասամբ հավանականային (զգայուն է հարցումների կտրուկ հաճախացման նկատմամբ՝ արագ հաջորդող հարցումներից հետո դառնում է ավելի խիստ և վերականգնվում է դադարի ժամանակահատվածից հետո)։

Երբ WAF-ն արգելափակում է հարցումը, այն վերադարձնում է՝

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## Զտիչի կիրառման շրջանակը

WAF-ը ստուգում է միայն `messages[].content`-ը։ Այն **չի** ստուգում՝

- `system` հուշումը
- Կառուցվածքային բովանդակության բլոկները (`tool_result`, `tool_use`, `thinking`, `image`)
- Գործիքների `description` և `input_schema` դաշտերը
- Հարցման մետատվյալները, վերնագրերը կամ մոդելի id-ն

## Միշտ արգելափակվող օրինաչափություններ (առանց մեծատառերն ու փոքրատառերը տարբերակելու)

| Օրինաչափություն                   | Նշումներ                                                                         |
| --------------------------------- | -------------------------------------------------------------------------------- |
| `Lorem ipsum`-ի ցանկացած տարբերակ | Լատիներեն lorem-ի ամբողջ բառապաշարն արգելափակվում է                              |
| `language model` (առանձին)        | `"the language model"` և `"large language model"` արտահայտություններն անցնում են |
| `virtual assistant`               | `"AI assistant"` արտահայտությունն անցնում է                                      |
| `I'm here to help`                | Առանձին `"here to help"` արտահայտությունը նույնպես արգելափակվում է               |
| `Claude, made by Anthropic`       | Միայն ամբողջական արտահայտությունը                                                |

## Գրեթե միշտ արգելափակվող օրինաչափություններ

| Օրինաչափություն                                         | Նշումներ                                                             |
| ------------------------------------------------------- | -------------------------------------------------------------------- |
| `placeholder`                                           | Երբ այն առանձին է օգտագործվում (ոչ որպես պարամետրի անուն և այլն)     |
| `dummy data`                                            | Թեստային տվյալների համար հաճախ օգտագործվող սկզբնական արտահայտություն |
| `foo bar baz`                                           | Կանոնական լրացուցիչ տեքստի արտահայտություն                           |
| Կրկնվող կարճ թոքեններ (`AAA BBB CCC`, `test test test`) | Հիմնաբառերով գերլցոնումը հայտնաբերող մեխանիզմ                        |

## Վարքագիծը ծանրաբեռնվածության պայմաններում

Կարճ ժամանակահատվածում մոտ 5 արագ հարցումից հետո WAF-ը սկսում է արգելափակել բովանդակություն, որը սովորաբար կանցներ։ Սահմանաչափի բաքը թուլանում է մոտ 5–10 վայրկյան անգործությունից հետո։ Սա IP-ին և բանալուն կապված նույն արագության սահմանափակիչն է, որն առաջացնում է ընդհատումներով ի հայտ եկող `400 content-blocked` սխալներ, երբ Claude Code-ը կամ Codex CLI-ն արագ հաջորդականությամբ կատարում է գործիքի օգտագործման / հաղորդագրության ուղարկման մի քանի կանչ։

## OmniRoute-ում արդեն կիրառված մեղմացման միջոցները

1. **`open-sse/services/wafRateLimit.ts`** — հարցումների կտրուկ հաճախացումը կանխող պաշտպանիչ մեխանիզմ, որը ցանկացած `agentrouter:*` URL-ին ուղարկվող հարցումների միջև ապահովում է առնվազն 500 ms ընդմիջում։ Այս ընդմիջումը զգալիորեն ցածր է ուշացման մարդկային ընկալման շեմից և կանխում է WAF-ի ակտիվացումը սովորական երթևեկության դեպքում։

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — երբ վերին մակարդակի ծառայությունը վերադարձնում է `400 content-blocked`, կատարիչը կրկին փորձում է նույն URL-ը՝ կիրառելով էքսպոնենցիալ հետաձգում (1.5 s, 3.0 s, առավելագույնը՝ 2 փորձ)։ Հետաձգումից հետո WAF-ը սովորաբար թուլանում է, և կրկնակի փորձը հաջողվում է։

3. **`tests/unit/compression/harness.test.ts`** — `longInput` թեստային ֆիքսչերը փոխվել է՝ `"lorem ipsum dolor sit amet ".repeat(40)`-ից դառնալով `"example content for testing purposes ".repeat(40)`, որպեսզի երբ Claude Code-ը կարդում է այս ֆայլը `Read` գործիքի միջոցով, ֆայլի բովանդակությունը հետ չփոխանցվի `tool_result` բլոկի միջոցով և չակտիվացնի WAF-ը։

## Հուշումների և գործիքների ելքային տվյալների վերաբերյալ ուղեցույց

Եթե Claude Code-ի կամ Codex CLI-ի աշխատաշրջանը բազմիցս բախվում է `400 content-blocked` սխալին, ստուգեք օգտատիրոջ ամենավերջին հաղորդագրությունը և գործիքի ամենավերջին արդյունքը՝ վերոնշյալ օրինաչափություններից որևէ մեկի առկայության համար, ապա վերաձևակերպեք այն։ Տարածված շրջանցման եղանակներ՝

- `Lorem ipsum …`-ը փոխարինեք `example text …`-ով կամ այն իրական բովանդակությամբ, որը փորձում է մոդելավորել թեստը կամ ֆիքսչերը։
- `placeholder`-ը (երբ այն առանձին է օգտագործվում) փոխարինեք `example value`-ով, `sample value`-ով կամ իրական արժեքով։
- `language model`-ը փոխարինեք `large language model`-ով կամ `the model`-ով։
- `dummy data`-ն փոխարինեք `sample data`-ով կամ իրատեսական սկզբնական արժեքներով։
- `I'm here to help` / `here to help` արտահայտությունը փոխարինեք ավելի կոնկրետ ներածությամբ (օրինակ՝ `"I'll review the file you mentioned"`)։

## Կեղծ դրական արդյունքների մասին վերին մակարդակի մատակարարին հաղորդելը

Ընթացիկ զտիչը չափազանց խիստ է. այն արգելափակում է `"Lorem ipsum"`-ը `tool_result` բլոկներում, թեև օպերատորն ակնհայտորեն հուշում ներարկելու մտադրություն չի ունեցել։ Այն օպերատորները, որոնք ցանկանում են, որ խնդիրը շտկվի սկզբնաղբյուրում, պետք է կապվեն `agentrouter.org`-ի հետ և հաղորդեն կեղծ դրական արդյունքների մասին։ Վերոնշյալ արգելափակման ցանկը 2026-08-03-ի դրությամբ վերին մակարդակի ծառայության փորձարկումից ստացված էմպիրիկ արդյունքն է։
