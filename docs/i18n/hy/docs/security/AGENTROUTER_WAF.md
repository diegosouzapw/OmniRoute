`agentrouter`-ի վերին մակարդակի դարպասը `messages[].content`-ի նկատմամբ կիրառում է հիմնաբառերի վրա հիմնված բովանդակության զտիչ։ Զտիչը մասամբ դետերմինիստական է (միշտ արգելափակում է որոշ արտահայտություններ) և մասամբ հավանականային (զգայուն է հարցումների կտրուկ հոսքի նկատմամբ՝ արագ հարցումներից հետո դառնում է ավելի խիստ, իսկ դադարի ընթացքում վերականգնվում է)։

Երբ WAF-ն արգելափակում է հարցումը, այն վերադարձնում է՝

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## Զտիչի կիրառման շրջանակը

WAF-ը ստուգում է միայն `messages[].content`-ը։ Այն **չի** ստուգում՝

- `system` հուշումը
- Կառուցվածքային բովանդակության բլոկները (`tool_result`, `tool_use`, `thinking`, `image`)
- Գործիքի `description` և `input_schema` դաշտերը
- Հարցման մետատվյալները, վերնագրերը կամ մոդելի id-ն

## Միշտ արգելափակվող օրինաչափություններ (առանց մեծատառերի և փոքրատառերի տարբերակման)

| Օրինաչափություն                   | Նշումներ                                                                         |
| --------------------------------- | -------------------------------------------------------------------------------- |
| `Lorem ipsum`-ի ցանկացած տարբերակ | Ամբողջ լատիներեն lorem բառապաշարն արգելափակվում է                                |
| `language model` (առանձին)        | `"the language model"` և `"large language model"` արտահայտություններն անցնում են |
| `virtual assistant`               | `"AI assistant"` արտահայտությունն անցնում է                                      |
| `I'm here to help`                | Առանձին `"here to help"` արտահայտությունը նույնպես արգելափակվում է               |
| `Claude, made by Anthropic`       | Միայն ամբողջական արտահայտությունը                                                |

## Գրեթե միշտ արգելափակվող օրինաչափություններ

| Օրինաչափություն                                         | Նշումներ                                                         |
| ------------------------------------------------------- | ---------------------------------------------------------------- |
| `placeholder`                                           | Երբ այն առանձին է օգտագործվում (ոչ որպես պարամետրի անուն և այլն) |
| `dummy data`                                            | Ֆիքսչերների համար տարածված սկզբնական արտահայտություն             |
| `foo bar baz`                                           | Կանոնական լրացուցիչ տեքստի արտահայտություն                       |
| Կրկնվող կարճ թոքեններ (`AAA BBB CCC`, `test test test`) | Հիմնաբառերի կուտակումը հայտնաբերող մեխանիզմ                      |

## Վարքագիծը ծանրաբեռնվածության պայմաններում

Կարճ ժամանակահատվածում մոտ 5 արագ հարցումից հետո WAF-ն սկսում է արգելափակել այնպիսի բովանդակություն, որը սովորաբար կանցներ։ Դույլը թուլանում է մոտ 5–10 վայրկյան անգործությունից հետո։ Սա նույն IP-ին և բանալուն կապված արագության սահմանափակիչն է, որը հանգեցնում է ընդհատվող `400 content-blocked` սխալների, երբ Claude Code-ը կամ Codex CLI-ն արագ հաջորդականությամբ կատարում են գործիքի օգտագործման / հաղորդագրության ուղարկման բազմաթիվ կանչեր։

## OmniRoute-ում արդեն կիրառված մեղմացման միջոցները

1. **`open-sse/services/wafRateLimit.ts`** — հարցումների կտրուկ հոսքի սահմանափակիչ, որը ցանկացած `agentrouter:*` URL-ին ուղարկվող հարցումների միջև ապահովում է նվազագույնը 500 ms ընդմիջում։ Այս ընդմիջումը շատ ավելի փոքր է, քան մարդու կողմից ուշացման ընկալման շեմը, և թույլ չի տալիս, որ WAF-ն ակտիվանա սովորական տրաֆիկի ժամանակ։

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — երբ վերին մակարդակի ծառայությունը վերադարձնում է `400 content-blocked`, կատարիչը նույն URL-ի համար կրկնում է հարցումը՝ էքսպոնենցիալ հետաձգմամբ (1.5 s, 3.0 s, առավելագույնը 2 փորձ)։ Հետաձգումից հետո WAF-ը սովորաբար թուլանում է, և կրկնակի հարցումը հաջողվում է։

3. **`tests/unit/compression/harness.test.ts`** — `longInput` թեստային ֆիքսչերը `"lorem ipsum dolor sit amet ".repeat(40)`-ից փոխվել է `"example content for testing purposes ".repeat(40)`-ի, որպեսզի երբ Claude Code-ը կարդա այս ֆայլը `Read` գործիքի միջոցով, ֆայլի բովանդակությունը հետ չփոխանցվի `tool_result` բլոկի միջոցով և չակտիվացնի WAF-ը։

## Հուշումների և գործիքի ելքային տվյալների վերաբերյալ ուղեցույց

Եթե Claude Code-ի կամ Codex CLI-ի աշխատաշրջանը պարբերաբար բախվում է `400 content-blocked` սխալի, ստուգեք ամենավերջին օգտատիրոջ հաղորդագրությունն ու ամենավերջին գործիքի արդյունքը՝ վերոնշյալ օրինաչափություններից որևէ մեկի առկայության համար, և վերաձևակերպեք դրանք։ Տարածված շրջանցման եղանակներ՝

- Փոխարինեք `Lorem ipsum …`-ը `example text …`-ով կամ այն իրական բովանդակությամբ, որը թեստը կամ ֆիքսչերը փորձում է մոդելավորել։
- Փոխարինեք `placeholder`-ը (երբ այն առանձին է օգտագործվում) `example value`-ով, `sample value`-ով կամ իրական արժեքով։
- Փոխարինեք `language model`-ը `large language model`-ով կամ `the model`-ով։
- Փոխարինեք `dummy data`-ն `sample data`-ով կամ իրատեսական սկզբնական արժեքներով։
- Փոխարինեք `I'm here to help` / `here to help` արտահայտությունները ավելի հստակ սկզբնական նախադասությամբ (օրինակ՝ `"I'll review the file you mentioned"`)։

## Կեղծ դրական արդյունքների մասին վերին մակարդակի ծառայությանը հաղորդելը

Ներկայիս զտիչը չափազանց խիստ է. այն արգելափակում է `"Lorem ipsum"`-ը `tool_result` բլոկներում, թեև ակնհայտ է, որ օպերատորը հուշում ներարկելու մտադրություն չի ունեցել։ Օպերատորները, որոնք ցանկանում են, որ սա շտկվի սկզբնաղբյուրում, պետք է կապվեն `agentrouter.org`-ի հետ՝ կեղծ դրական արդյունքների մասին հաղորդելու համար։ Վերոնշյալ արգելափակման ցանկը վերին մակարդակի ծառայության՝ 2026-08-03-ի դրությամբ կատարված փորձարկումների էմպիրիկ արդյունքն է։
