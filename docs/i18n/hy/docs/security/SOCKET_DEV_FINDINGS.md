> **Ծավալի նշում:** `socket.yml`-ը կազմաձևում է Socket.dev-ի ռեգիստրի կողմից npm արտեֆակտի հրապարակումից հետո սկանավորումը (անտեսվող ուղիներ չառաքվող բովանդակության համար, ինչպիսիք են `tests/`, `docs/` և կառուցման հաշվետվությունները): Այն չի միացնում CI/PR միաձուլման դարպասը — ոչ մի աշխատանքային հոսք `.github/workflows`-ում, ոչ մի `package.json` սկրիպտ և ոչ մի `Makefile` թիրախ չի կանչում Socket.dev-ը:

Այս փաստաթուղթը սպասարկողի կողմից հեղինակված հավաստագիրն է `omniroute@3.8.5`-ի դեմ բարձրացված վեց `AI-detected potential malware` հայտնաբերումների և `omniroute@3.8.6`-ում կիրառված մեղմացումների վերաբերյալ: Այն գոյություն ունի, որպեսզի.

1. Անվտանգության խողովակաշարի օպերատորները ունենան մեկ հղում՝ մեջբերելու համար, երբ անհրաժեշտ է գնահատել հայտնաբերումները իրական աղբյուրի համեմատ:
2. Ապագա AI սկաներները կարողանան վերցնել սպասարկողի կողմից ստորագրված պնդումը, որ յուրաքանչյուր նշված ուղի դիտավորյալ է, կամավոր ընտրված և փաստաթղթավորված:
3. Մենք ունենանք գրավոր արձանագրություն, թե _ինչու_ է յուրաքանչյուր կանչի կայք ձևավորված այնպես, ինչպես կա — որպեսզի ապագա վերակառուցումը պատահաբար չվերաներկայացնի մի մատնահետք, որը դիտավորյալ հեռացվել էր:

Եթե դուք շահագործում եք սկաներ, որը կրկին նշում է ստորև նշված կանչի կայքերից որևէ մեկը այն բանից հետո, երբ v3.8.6 մեղմացումներն առաքվել են, խնդրում ենք բացել խնդիր սկանավորման հետքով, և մենք կընդլայնենք հավաստագիրը այստեղ:

## §1 — MITM արմատային CA-ի տեղադրում (`77484.js`)

**Սկզբնական կոդի ֆայլեր**՝

- `src/mitm/cert/install.ts` — հանրային `installCert()` / `uninstallCert()`,
  ըստ հարթակի՝ `installCertWindows/Mac/Linux`։
- `src/mitm/systemCommands.ts` — տեղադրման ուղիների կողմից օգտագործվող ընդհանուր `execFile` / `spawn` / PowerShell
  օժանդակ գործառույթներ։

**Գործարկման պայման**՝ օգտատերը տեղային կառավարման վահանակի
`/dashboard/cli-tools/mitm` էջում սեղմում է «Միացնել MITM պրոքսին»։ Ուղին հասանելի է միայն loopback-ի միջոցով — տե՛ս #17 խիստ կանոնը
`CLAUDE.md`-ում և `src/server/authz/routeGuard.ts::isLocalOnlyPath()`-ում։ Թունելի միջոցով բացահայտված
JWT-ն **չի կարող** գործարկել այս կոդային ուղին։

**Կատարվող արտոնյալ գործողություններն ըստ հարթակի**՝

| ՕՀ                     | Հրաման(ներ)                                                                                                       |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | `certutil -addstore Root <cert>`՝ UAC-ի միջոցով                                                                   |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | յուրաքանչյուր պրոֆիլի NSS DB-ի թարմացում՝ `certutil -d sql:<profile>`-ի միջոցով                                   |

Սրանք նույն հրամաններն են, որոնք օգտագործվում են `mitmproxy`-ի, Charles Proxy-ի, Fiddler-ի և
Caddy-ի կողմից։ OmniRoute-ում դրանց առկայության փաստը նկարագրված է
`docs/security/STEALTH_GUIDE.md`-ում։

**v3.8.6-ի մեղմման միջոց**՝

- `runElevatedPowerShell()`-ն այլևս չի օգտագործում `-EncodedCommand <base64utf16le>`։
  Բարձրացված արտոնություններով կատարվող բովանդակությունը գրվում է յուրաքանչյուր կանչի համար ստեղծված ժամանակավոր `.ps1` ֆայլում (ռեժիմը՝ 0o600,
  մասնավոր `mkdtempSync` գրացուցակի ներսում) և հղվում է `-File`-ի միջոցով։ Ֆայլը
  ջնջվում է `finally`-ում։ Սա վերացնում է PowerShell-ի միջոցով
  base64-կոդավորված արտոնությունների բարձրացման դասական հատկանիշը, որը նշել էր Socket.dev-ի AI
  դասակարգիչը։
- `installCertWindows`-ը պարունակում է ներկոդային `SECURITY-AUDITOR-NOTE:` բլոկ,
  որը հղում է այստեղ։

**Ինչու ենք այն պահպանում**՝ MITM պրոքսին փաստաթղթավորված գործառույթ է, որն օգտագործվում է
`docs/security/STEALTH_GUIDE.md`-ում և `docs/frameworks/MITM-PROXY.md`-ում։ Դրա հեռացումը
կխախտեր գործակալ-կամուրջ գործառույթների հավաքածուն։

## §2 — Zed-ի հավատարմագրերի ներմուծում (`app/api/providers/zed/import/route.js`)

**Սկզբնաղբյուր ֆայլեր**․

- `src/app/api/providers/zed/discover/route.ts` _(նոր է v3.8.6-ում)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(նոր է v3.8.6-ում)_

**Գործարկման պայման**․ օգտատերը տեղային կառավարման վահանակի մատակարարների
էջում սեղմում է «Ներմուծել Zed-ից»։ Վերջնակետը պաշտպանված է
`requireManagementAuth`-ով։ Zed խմբագրիչն ինքն է իր մատակարարների API բանալիները
գրում ՕՀ-ի բանալիների շտեմարանում՝ փաստաթղթավորված ծառայությունների
անուններով․ տե՛ս https://zed.dev/docs/ai/llm-providers։

**v3.8.5-ի վարքագիծը (որը նշել էր Socket.dev-ը)**․

`POST /import`-ը հայտնաբերում էր հավատարմագրերը և մեկ հարցում-պատասխան շրջափուլով
ինքնաբերաբար պահպանում դրանք տեղային SQLite շտեմարանում։ Յուրաքանչյուր հաշվի
համար հաստատում կամ մատնահետք չկար, պարզապես՝ «գտնվել է N թոքեն, բոլորը
ներմուծվել են»։

**v3.8.6-ի մեղմացման միջոց — 2-քայլանոց հաստատում**․

1. **`POST /api/providers/zed/discover`**-ը վերադարձնում է
   `{ candidates: [{ provider, service, account, fingerprint }] }`։ Չմշակված
   թոքենը **երբեք** չի փոխանցվում։ Մատնահետքը հաշվարկվում է այսպես՝
   `sha256(service|account|token).slice(0,16)`։
2. Կառավարման վահանակը ցուցադրում է թեկնածուների ցանկը, օպերատորն ընտրում է,
   թե որոնք ներմուծել, ապա ուղարկում է
   `{ confirmedAccounts: [{ service, account, fingerprint }] }`
   **`POST /api/providers/zed/import`** հասցեին։
3. Ներմուծման վերջնակետը **սերվերում կրկին կարդում է բանալիների շտեմարանը** և
   զտում ըստ `(service, account, fingerprint)`-ի։ Կեղծված կամ կրկնակի
   օգտագործված հայտնաբերման պատասխանը չի կարող ներմուծման վերջնակետին ստիպել
   պահպանել կապ չունեցող թոքեն․ եթե կենդանի թոքենը հայտնաբերումից հետո փոխվել է,
   մատնահետքն այլևս չի համընկնի, և հավատարմագիրը բաց կթողնվի։

`OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` միջավայրի դրոշը պահպանում է v3.8.5-ի
վարքագիծն այն օպերատորների համար, որոնք դեռ չեն թարմացրել իրենց ավտոմատացումը։
Այն կհեռացվի v3.9-ում։

**Ինչու ենք այն պահպանում**․ Zed-ից ներմուծումը մեկնարկի ամենահարմար եղանակն է
այն օգտատերերի համար, որոնք արդեն օգտագործում են Zed-ը և ցանկանում են իրենց
մատակարարների բանալիները պատճենել OmniRoute՝ առանց դրանք կրկին տեղադրելու։

## §3 — `execFile` / `spawn` / բարձրացված արտոնություններով PowerShell (`21843.js`)

**Սկզբնաղբյուր ֆայլեր**․ `src/mitm/systemCommands.ts`։

**Նշվելու պատճառը**․ տվյալ հատվածը վերաարտահանում է `execFileWithPassword`,
`runElevatedPowerShell` և ընդհանուր `quotePowerShell` օժանդակ ֆունկցիան։
Socket.dev-ի AI դասակարգիչը դրանք ընկալում է որպես ընդհանուր նշանակության
«հոսթում կատարում + արտոնությունների բարձրացում գործիքակազմ»։ OmniRoute-ում
դրանք օգտագործվում են միայն MITM վկայագրի տեղադրման ճանապարհում (§1), իսկ
`execFileWithPassword`-ը՝ `sudo` հրամաններ կատարելու համար։

**v3.8.6-ի մեղմացման միջոց**․

- `runElevatedPowerShell`-ի վերակառուցում (տե՛ս §1)։
- `runElevatedPowerShell`-ի և `execFileWithPassword`-ի մոտ ներկառուցված
  `SECURITY-AUDITOR-NOTE:` բլոկը փաստաթղթավորում է թույլատրված կանչողներին և
  ամրագրված գործարկվող ֆայլերի ցանկը։
- `execFileWithPassword`-ի `spawn()` կանչը պարունակում է `nosemgrep` նշիչ՝
  այն գործարկվող ֆայլերի թույլատրացուցակով, որոնք օժանդակ ֆունկցիան կարող է
  ստանալ․ օգտատիրոջ մուտքային տվյալներից դեպի `finalCommand`/`finalArgs`
  **որևէ ուղի չկա**։

## §4 / §6 — 9router ծառայության վերահսկիչ (`api/services/9router/{start,restart}/route.js`)

**Սկզբնաղբյուր ֆայլեր**․

- `src/app/api/services/9router/_lib.ts` — վերահսկիչի գործարան։
- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`։
- `src/lib/services/ServiceSupervisor.ts` — ընդհանուր spawn / առողջության հարցում / մատյանների բուֆեր։

**Գործարկման պայման**․ օգտատերը տեղային կառավարման վահանակի ներդրված
ծառայությունների էջում սեղմում է «Տեղադրել» / «Մեկնարկել»։

**Արդեն կիրառվող պաշտպանական միջոցներ**․

- Բոլոր `/api/services/*` երթուղիները `LOCAL_ONLY` են՝ համաձայն
  `src/server/authz/routeGuard.ts`-ի (խիստ կանոն #17)։ Loopback-ի պարտադրումը
  կատարվում է նույնականացման ցանկացած ստուգումից առաջ․ արտահոսած JWT-ն չի կարող
  հասնել դրանց։
- 9router-ի ՏԲ տողը սկզբնարժեքավորվում է որպես
  `status='not_installed', auto_start=0` (տե՛ս
  `src/lib/db/migrations/071_services.sql:19`)։ Ծառայությունն առաջին գործարկման
  ժամանակ **չի** մեկնարկում։
- `spawn()`-ը կանչվում է
  `src/lib/services/installers/ninerouter.ts`-ում գտնվող
  `resolveSpawnArgs(apiKey, PORT)`-ի վերադարձրած երկուական ֆայլի ուղիով, որը
  աջակցվող երկուական ֆայլերի ֆիքսված թույլատրացուցակ է։
- Stdout/stderr-ը բուֆերացվում է հիշողության մեջ (5 MB սահմանաչափ, տե՛ս
  `_lib.ts`)․ սկավառակի վրա գրառում չի կատարվում, եթե օգտատերը կառավարման
  վահանակից չի միացնում մատյանավորումը։

**v3.8.6-ի մեղմացման միջոց**․ գործառական փոփոխություն չկա։ Նվազագույն կառուցման
պրոֆիլը (`OMNIROUTE_BUILD_PROFILE=minimal`)
`src/lib/services/installers/ninerouter.ts`-ը փոխարինում է դատարկակաղապարով այն
օգտատերերի համար, որոնք ցանկանում են արտոնյալ ուղիները ֆիզիկապես հեռացնել
փաթեթից։

**Ինչու ենք այն պահպանում**․ 9router-ը կամընտիր, տեղային եղանակով տեղադրվող
ուղեկից ծառայություն է (պատկերացրեք՝ WordPress-ի ոճի հավելում)՝ խիստ
կամավոր միացմամբ։

## §5 — OmniRoute Cloud Sync-ի հավատարմագրերի հետգրում (`api/keys/[id]/route.js`)

**Սկզբնաղբյուր ֆայլեր**․

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`։
- `src/app/api/keys/[id]/route.ts` — կանչում է `syncKeysToCloudIfEnabled()`-ը։

**Գործարկման պայման**․ `isCloudEnabled()`-ը վերադարձնում է `true` (սահմանվում է կառավարման վահանակից) **և**
`CLOUD_URL`-ը կազմաձևված է։ Երբ երկուսն էլ անջատված են, դեպի Cloud վերջնակետ
ելքային ցանցային հարցում չի կատարվում։

**v3.8.5-ի վարքագիծը (սխալը, որը Socket.dev-ը ճիշտ եղանակով հայտնաբերեց)**․

Երբ `cloudUpdatedAt > localUpdatedAt`, `updateLocalTokens()`-ը Cloud-ի պատասխանից
վերագրանցում էր `accessToken`, `refreshToken` և
`providerSpecificData` դաշտերը։ Չկար ո՛չ HMAC, ո՛չ ստորագրություն, ո՛չ ստուգիչ գումար։ Սխալ
կազմաձևված կամ վնասաբեր `CLOUD_URL`-ը (կամ կապուղում MITM-ը) կարող էր աննկատ
փոխարինել մատակարարի OAuth թոքենները։

**v3.8.6-ի մեղմացման միջոցները**․

1. **HMAC ստուգում**․ `verifyCloudSignature(rawBody, sigHeader)`-ը ստուգում է
   `X-Cloud-Sig` վերնագիրը (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`)՝ նախքան JSON-ի վերլուծումը։ Եթե գաղտնիքը սահմանված է, ստորագրությունը
   պարտադիր է։ Եթե սահմանված չէ (ժառանգական ռեժիմ), գրանցվում է նախազգուշացում, և պատասխանն
   ընդունվում է․ v3.9-ում գաղտնիքը պարտադիր կլինի։
2. **Գաղտնի դաշտերի բացահայտ միացում**․ `accessToken` / `refreshToken` /
   `providerSpecificData` դաշտերը վերագրվում են **միայն** այն դեպքում, երբ
   `OMNIROUTE_CLOUD_SYNC_SECRETS=true`։ Լռելյայն ռեժիմը համաժամացնում է միայն
   հավատարմագրեր չպարունակող մետատվյալները (`expiresAt`, `status`, `lastError*`,
   `rateLimitedUntil`, `updatedAt`)։ Սա **հետադարձ համատեղելիությունը խախտող փոփոխություն** է այն օգտատերերի
   համար, որոնք հիմնվում էին թոքենների հեռավար համաժամացման վրա․ նրանք պետք է բացահայտորեն միացնեն այն։

**Ինչու ենք այն պահպանում**․ Cloud Sync-ը OmniRoute Cloud-ի հաճախորդի համար
թիմային հավատարմագրերը կենտրոնացնելու միակ միջոցն է։ Ուղղումը սպառնալիքների մոդելը դարձնում է ազնիվ․
«սերվերը ստորագրում է, հաճախորդը ստուգում է, օպերատորը միացնում է»։

## Կառուցման պրոֆիլ՝ `minimal`

Socket-ի համար ընդունելի արտեֆակտի կարիք ունեցող օգտատերերը կարող են կառուցել հետևյալ հրամանով․

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

webpack-ի `NormalModuleReplacementPlugin`-ը չորս մոդուլ փոխարինում է խցաններով․

| Մոդուլ                                      | Խցան                                             |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

Յուրաքանչյուր խցան արտահանում է նույն միջերեսը, սակայն յուրաքանչյուր ֆունկցիա կատարման պահին
նետում է `featureDisabledError(name)`։ Անջատված մոդուլից կախված երթուղիները
զգայուն կոդային ուղին ակտիվացնելու փոխարեն վերադարձնում են HTTP 503՝ հստակ հաղորդագրությամբ։

Ստացված փաթեթը նախատեսված է `omniroute-secure` անվամբ հրապարակելու համար։ Հրապարակման
հրահանգներին ծանոթանալու համար տե՛ս `docs/ops/PUBLISHING_SECURE.md`։
