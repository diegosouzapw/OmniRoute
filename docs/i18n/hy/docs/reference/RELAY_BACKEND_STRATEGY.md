## Ամփոփում

OmniRoute-ն այժմ աջակցում է փոխանցման երեք ռեժիմ `/api/v1/relay/chat/completions`-ի համար․

- `ts`՝ օգտագործել TypeScript փոխանցիչը նույն պրոցեսի ներսում։
- `bifrost`՝ պարտադիր օգտագործել Bifrost դարպասը։
- `auto`՝ հասանելիության դեպքում նախընտրել Bifrost-ը, իսկ ձախողման դեպքում վերադառնալ TypeScript-ին։

Հարցումների բարձր հաճախականությամբ աշխատելիս (օրական մեծ քանակությամբ թոքեններ, գրեթե անընդհատ թողունակություն) լավագույն ռազմավարությունն այն է, որ պահուստային ուղին լինի հստակ և արագ, որպեսզի հիմնական ուղին երբեք չարգելափակվի չաշխատող կողմնակի ծառայության պատճառով։

## Ռեժիմների վարքագիծը

- `ts`
  - Գործառնական ամենացածր բարդությունը։
  - Ամբողջ երթուղավորումն ու վավերացումը կատարվում են Node-ում։
  - Հասանելիությունը կախված չէ կողմնակի ծառայությունից։
- `bifrost`
  - Բոլոր հարցումները պարտադիր ուղարկվում են կողմնակի դարպասի միջոցով։
  - Ավտոմատ պահուստային անցում չկա։
  - Օգտակար է միայն այն դեպքում, երբ կողմնակի ծառայության առողջությունն ու ուշացումը երաշխավորված են։
- `auto`
  - Կողմնակի ծառայությունն օգտագործվում է, երբ այն հասանելի է և միացված։
  - Ձախողված փորձերը գործարկում են պահուստային անցման վերնագրերը և տրաֆիկը վերադարձնում TS-ին, որպեսզի հարցումների հաջող մշակումը մնա սահմանափակ կանխատեսելի ժամանակի շրջանակում։
  - Այս ռեժիմն ամենաանվտանգ ընտրությունն է արտադրական միջավայրի համար, երբ անխափան աշխատանքն ավելի կարևոր է, քան բացառապես կողմնակի ծառայությամբ խիստ երթուղավորումը։

## 9router-ն ընդդեմ CLIPROXYAPI-ի՝ այսօր

9router-ը և CLIPROXYAPI-ն երկուսն էլ ինտեգրումներ են, որոնք պատմականորեն տրամադրել են վերին հոսքի մատակարարների հետ համատեղելիության ուղիներ։

- 9router-ը ներդրված ուղի է վերին հոսքի համակարգման և համատեղելիության վարքագծի համար։
- CLIPROXYAPI-ն պրոքսի API կամուրջ է CLI / SDK ոճի տրաֆիկի համար։
- Bifrost-ը կայունացվում է որպես արտաքինացված ուղի այն դեպքերի համար, երբ անհրաժեշտ է առանձնացված՝ կողմնակի ծառայությանը նման միջանկյալ հանգույց և ցածր ուշացմամբ տեղային դիսպետչերացում։

Եթե ներկայումս համեմատում եք 9router-ը և CLIPROXYAPI-ն՝

- Հարցման ստորագրումը, թույլատրվածների ցանկի ստուգումները և DB քաղաքականության սահմանափակումները պահեք API երթուղում՝ մինչև փոխանցումը։
- Եթե աշխատանքային հոսքին անհրաժեշտ է կողմնակի ծառայության խիստ վարքագիծ և մեկ հարցման հաշվով ավելի փոքր տատանում, օգտագործեք `OMNIROUTE_RELAY_BACKEND=bifrost`։
- Եթե ձեզ անհրաժեշտ է կողմնակի ծառայության դիմակայունություն՝ միջադեպերի ժամանակ աստիճանական վատթարացմամբ, օգտագործեք `OMNIROUTE_RELAY_BACKEND=auto`։

## Հետնամասի սահմանային պայմանագիր

Կայուն արտադրանքի սահմանը OmniRoute-ի փոխանցման API-ն է, այլ ոչ թե կառավարման վահանակի իրականացումը։ Next.js կառավարման վահանակը կարող է տեղադրել, կարգավորել և վերահսկել տեղային ծառայությունները, սակայն հարցումների երթուղավորումը պետք է մուտք գործի փոխանցման API-ի միջոցով և փոխանցվի այդ սահմանից այն կողմ։

Հետնամասի երկարաժամկետ ընտրանքները՝

- TypeScript փոխանցիչը պահեք որպես նույն պրոցեսի ներսում գործող քաղաքականության և պահուստային ուղի։ Auth-ը, թույլատրվածների ցանկերը, հարցումների նորմալացումը, հաշվառումը և անվտանգության ստուգումները մնում են այստեղ՝ մինչև որևէ հետնամասին փոխանցելը։
- Օգտագործեք Bifrost-ը որպես նախընտրելի, բարձր թողունակությամբ Tier-1 կողմնակի ծառայություն, երբ տեղակայման համար անհրաժեշտ են երթուղավորման ավելի փոքր տատանումներ, մատակարարների կենտրոնացված հերթափոխ կամ մասշտաբավորում OmniRoute-ի բազմաթիվ կրկնօրինակների միջև։
- 9router-ը և CLIPROXYAPI-ն պահեք որպես ներդրված համատեղելիության ծառայություններ։ Դրանք աշխատում են որպես վերահսկվող տեղային պրոցեսներ և օգտակար են, երբ ցանկալի ադապտերը դրանց մատակարարի/CLI-ի վարքագիծն է, սակայն դրանք չպետք է դառնան լռելյայն Tier-1 երթուղավորման շարժիչ։
- Թույլ մի տվեք, որ կառավարման վահանակը կամայական ծառայությունների URL-ներ փոխանցի հիմնական ուղի։ UI-ի տրամադրած URL-ները կարգավորման մուտքային տվյալներ են․ երթուղավորման կոդը պետք է սերվերային կարգավորումներից և վերահսկիչի վիճակից որոշի գրանցված ու առողջության ստուգում անցած հետնամասերը։
- Այսօր վերահսկվող ծառայությունների համար նախընտրեք loopback HTTP-ը, քանի որ կառավարվող պրոցեսներն արդեն տրամադրում են HTTP-ի հետ համատեղելի API-ներ, երթուղու պաշտպանիչը կարող է աուդիտի ենթարկել սահմանը, իսկ ձախողման և պահուստային անցման վարքագիծը տեսանելի է հարցումների գրանցամատյաններում։ Ապագա SDK կամ socket փոխադրամիջոց ավելացնելն իմաստ ունի միայն այն դեպքում, եթե այն չափելիորեն նվազեցնում է p99 երթուղավորման ուշացումը՝ առանց մեկուսացումը կամ պահուստային անցման իմաստաբանությունը թուլացնելու։

Հետևաբար, շատ բարձր թողունակությամբ տեղակայման համար լռելյայն պատասխանը միացված Bifrost-ով `auto`-ն է․ հիմնական ուղում օգտագործեք Go կողմնակի ծառայությունը՝ միաժամանակ հաջողության գործակիցը պահպանելու համար թողնելով TypeScript պահուստային ուղին։ Օգտագործեք `bifrost` միայն այն դեպքում, երբ բացառապես կողմնակի ծառայությամբ խիստ վարքագիծն ավելի կարևոր է, քան աստիճանական վատթարացումը։

## Բարձր թողունակության ուղեցույց

Կայուն բարձր RPM/RPS-ի և հաջողության խիստ SLO-ի համար՝

1. Օգտագործեք `auto`՝ գործնական սառեցման ժամանակահատվածով և ձախողումների հեռաչափությամբ։
2. Վերին հոսքի վավերացումն ու API բանալիների ստուգումները պահեք TypeScript երթուղու սահմանում։
3. Միացրեք հստակ վերնագրեր/հաշվիչներ, որպեսզի ձեր ահազանգման համակարգը տեսնի պահուստային անցումների հաճախականությունն ու պատճառները։
4. Կարգավորեք կողմնակի ծառայության ժամանակային սահմանափակումներն այնպես, որ այն արագ ձախողվի և անվերջ չսպասի։
5. Ծառայությունների ավտոմատ վերագործարկման և առողջության հեռաչափության ցիկլը պահեք առողջ վիճակում, որպեսզի պահուստային անցումն իսկապես բացառիկ դեպք լինի։

## Առաջարկվող ելակետային կարգավորում

- `OMNIROUTE_RELAY_BACKEND=auto`
- `BIFROST_ENABLED=1`
- API բանալիների, թույլատրվածների ցանկի, մաքրիչի և հաճախականության սահմանափակման ստուգումները միացված պահեք երթուղու մշակիչներում (դրանք միշտ կատարվում են մինչև ստորին հոսքին փոխանցելը)։
- Ձեր հակադարձ պրոքսիից և հարցումների գրանցամատյաններից արտահանեք պահուստային անցումների չափորոշիչները, որպեսզի կողմնակի ծառայության խափանումները տեսանելի դառնան մեկ րոպեի ընթացքում։

## Մատակարարի փլագինի պայմանագիր

Կողմնակի ծառայությունները պետք է ներմուծեն մատակարարի մետատվյալները JSON-ի համար անվտանգ մատակարարի փլագինի
մանիֆեստի միջոցով՝ TypeScript կատարիչի ներքին բաղադրիչներից կախված լինելու փոխարեն։ Կողմնակի ծառայության
համապատասխանության պայմանագրի և միգրացիայի փուլերի համար տե՛ս
[Մատակարարի փլագինի մանիֆեստ](./PROVIDER_PLUGIN_MANIFEST.md)։
