## Ինչ են ֆունկցիոնալության դրոշները

Ֆունկցիոնալության դրոշն անվանված փոխարկիչ է (բուլյան կամ թվարկում), որի արժեքը կարելի է փոխել
կատարման ժամանակ և պահպանել տվյալների բազայում՝ առանց գործընթացի վերատեղակայման անհրաժեշտության։ Յուրաքանչյուր
դրոշ նկարագրվում է `FeatureFlagDefinition`-ով, որն ունի `key`, `label`,
`description`, `category`, `defaultValue`, `type` և `requiresRestart` հուշում։

### Որոշման հերթականությունը

Դրոշի **արդյունավետ արժեքը** որոշվում է
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts)-ի միջոցով՝ հետևյալ
առաջնահերթությամբ (հաղթում է ամենաբարձր առաջնահերթությունը)․

1. **ՏԲ վերասահմանում** — `key_value` աղյուսակում՝
   `feature_flags` անվանատարածքի ներքո պահվող արժեք (սահմանվում է կառավարման վահանակի կամ REST API-ի միջոցով)։
2. **Միջավայրի փոփոխական** — `process.env[<KEY>]`, եթե սահմանված է և դատարկ չէ։
3. **Սահմանման լռելյայն արժեք** — `featureFlagDefinitions.ts`-ի `defaultValue`-ը։

Բուլյան դրոշը համարվում է **միացված**, երբ դրա արդյունավետ արժեքը `"true"` է,
`"1"` կամ `"yes"` (տե՛ս `isFeatureFlagEnabled()`)։

> [!NOTE]
> Դրոշների մեծ մասն ունի նաև **նույն անունով** համապատասխան միջավայրի փոփոխական,
> որը փաստաթղթավորված է [`ENVIRONMENT.md`](./ENVIRONMENT.md)-ում։ Դրոշի ՏԲ վերասահմանումն
> ունի առաջնահերթություն այդ միջավայրի փոփոխականի նկատմամբ։ `requiresRestart: true`
> ունեցող դրոշն անմիջապես պահպանվում է, սակայն կրկին ընթերցվում է միայն գործընթացի
> մեկնարկի ժամանակ․ այն փոխարկելիս կառավարման վահանակում ցուցադրվում է **«Վերագործարկել սերվերը»** ազդապաստառ։

## Դրոշակների կատալոգ

> `Restart` սյունակը նշում է `requiresRestart: true` ունեցող դրոշները. արժեքը

> դրոշները մերժում են իրենց թույլատրելի բազմությունից դուրս գտնվող ցանկացած արժեք (վավերացվում է սերվերի կողմում՝
> ինչպես `setFeatureFlagOverride()`-ում, այնպես էլ REST `PUT` մշակիչում)։

## Դրոշների փոխարկում

### Կառավարման վահանակ

Անցեք **Կառավարման վահանակ → Կարգավորումներ → Գործառույթների դրոշներ**
(`/dashboard/settings/feature-flags`)։ Ցանցը
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
աջակցում է՝

- **Որոնում** ըստ բանալու կամ նկարագրության և **զտում** ըստ կատեգորիայի (ինչպես նաև սինթետիկ
  **Պահանջում է վերագործարկում** տեսքի)։
- Բուլյան դրոշների համար՝ **փոխարկիչ**, իսկ թվարկման դրոշների համար՝ **բացվող ցանկ**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`)։
- Յուրաքանչյուր դրոշի համար՝ **աղբյուրի նշան**՝ `DB`, `ENV` կամ `DEF`, որը ցույց է տալիս, թե որտեղից է
  ստացվել գործող արժեքը։
- **Վերակայել** կոճակ (ցուցադրվում է միայն `DB` աղբյուրով դրոշների համար)՝ վերագրումը հեռացնելու
  համար, և ներքևում՝ **Վերակայել բոլոր վերագրումները** կոճակ։
- **Վերագործարկել սերվերը** ծանուցագիր, երբ փոփոխվում է `requiresRestart` դրոշը։

### REST API

Բոլոր գործողությունները կատարվում են մեկ երթուղու միջոցով՝
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts)։
Յուրաքանչյուր մեթոդ պահանջում է կառավարման վահանակի նույնականացված աշխատաշրջան (հակառակ դեպքում՝ `401`)։

#### `GET /api/settings/feature-flags`

Վերադարձնում է յուրաքանչյուր դրոշը՝ իր գործող արժեքով, աղբյուրով և ամփոփագրով։

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... բոլոր 75 դրոշները
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Սահմանում կամ հեռացնում է մեկ վերագրում։ Մարմինը՝ `{ key: string; value?: string }`։
`value`-ի բացթողումը հեռացնում է վերագրումը (վերականգնելով env / լռելյայն արժեքը)։

```bash
# Սահմանել DB վերագրում
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Հեռացնել վերագրումը (առանց "value"-ի)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Պատասխանը վերադարձնում է նոր `effectiveValue`/`source`-ը, `previousValue`/
`previousSource`-ը և `requiresRestart`-ը։ Անհայտ բանալիները և թույլատրելի միջակայքից դուրս թվարկման
արժեքները մերժվում են `400`-ով։

#### `DELETE /api/settings/feature-flags`

Միանգամից մաքրում է DB-ի **բոլոր** վերագրումները՝ յուրաքանչյուր դրոշի համար վերականգնելով իր env / լռելյայն
արժեքը։ Վերադարձնում է `{ cleared: <count>, message: "..." }`։

> [!NOTE]
> `requiresRestart: true` ունեցող դրոշներն ուժի մեջ են մտնում միայն գործընթացի վերագործարկումից հետո։
> Կառավարման վահանակի վերագործարկման հոսքը կանչում է `POST /api/restart`, ապա պարբերաբար հարցում է կատարում
> `GET /api/health/ping` հասցեին, մինչև սերվերը կրկին հասանելի դառնա։

## Բյուջեի արտակարգ պահուստային տարբերակ

`OMNIROUTE_EMERGENCY_FALLBACK`-ը (կատեգորիան՝ `runtime`, լռելյայն արժեքը՝ `true`) կառավարում է
արտակարգ անվճար պահուստային ուղին
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)-ում։
Միացված լինելու դեպքում իրենց բյուջեն սպառած հարցումներն ամբողջությամբ ձախողվելու փոխարեն ուղղորդվում են
անվճար պահուստային մատակարարի/մոդելի մոտ։ Սահմանեք այն որպես `false` (կամ `0`)՝ կառավարման
վահանակի փոխարկիչի, DB վերագրման կամ `OMNIROUTE_EMERGENCY_FALLBACK`
միջավայրի փոփոխականի միջոցով, որպեսզի անջատեք այս վարքագիծը և թույլ տաք, որ բյուջեն սպառած հարցումները
ձախողվեն։ (Կառավարման վահանակում ներկայացվել է որպես փոխարկիչ PR-ներում #3741 / #3752։)
