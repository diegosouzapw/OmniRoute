> այդ ֆայլից, ուստի ստորև բերված աղյուսակը գեներացված է՝ դրան 1:1 համապատասխանելու համար։

## Ինչ են ֆունկցիոնալության դրոշները

Ֆունկցիոնալության դրոշն անվանված փոխարկիչ է (բուլյան կամ թվարկում), որի արժեքը կարելի է փոխել
կատարման ժամանակ և պահպանել տվյալների բազայում՝ առանց գործընթացի վերատեղակայման անհրաժեշտության։ Յուրաքանչյուր
դրոշ նկարագրվում է `FeatureFlagDefinition`-ով, որն ունի `key`, `label`,
`description`, `category`, `defaultValue`, `type` և `requiresRestart` հուշում։

### Որոշման հերթականությունը

Դրոշի **արդյունավետ արժեքը** որոշվում է
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts)-ի միջոցով՝ հետևյալ
առաջնահերթությամբ (հաղթում է ամենաբարձր առաջնահերթությունը)․

1. **ՏԲ վերասահմանում** — `key_value` աղյուսակում՝
   `feature_flags` անվանատարածքի ներքո պահվող արժեք (սահմանվում է կառավարման վահանակի կամ REST API-ի միջոցով)։
2. **Միջավայրի փոփոխական** — `process.env[<KEY>]`, եթե սահմանված է և դատարկ չէ։
3. **Սահմանման լռելյայն արժեք** — `featureFlagDefinitions.ts`-ի `defaultValue`-ը։

Բուլյան դրոշը համարվում է **միացված**, երբ դրա արդյունավետ արժեքը `"true"` է,
`"1"` կամ `"yes"` (տե՛ս `isFeatureFlagEnabled()`)։

> [!NOTE]
> Դրոշների մեծ մասն ունի նաև **նույն անունով** համապատասխան միջավայրի փոփոխական,
> որը փաստաթղթավորված է [`ENVIRONMENT.md`](./ENVIRONMENT.md)-ում։ Դրոշի ՏԲ վերասահմանումն
> ունի առաջնահերթություն այդ միջավայրի փոփոխականի նկատմամբ։ `requiresRestart: true`
> ունեցող դրոշն անմիջապես պահպանվում է, սակայն կրկին ընթերցվում է միայն գործընթացի
> մեկնարկի ժամանակ․ այն փոխարկելիս կառավարման վահանակում ցուցադրվում է **«Վերագործարկել սերվերը»** ազդապաստառ։

## Դրոշակների փոփոխում

### Կառավարման վահանակ

Անցեք **Կառավարման վահանակ → Կարգավորումներ → Ֆունկցիոնալ դրոշակներ**
(`/dashboard/settings/feature-flags`): Ցանցը
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
աջակցում է՝

- **Որոնում** բանալիով կամ նկարագրությամբ, և **ֆիլտրում** ըստ կատեգորիայի (գումարած սինթետիկ
  **Պահանջում է վերագործարկում** տեսքը):
- Միացման/անջատման **անջատիչ** բուլյան դրոշակների համար և **բացվող ցուցակ** enum դրոշակների համար
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`):
- Յուրաքանչյուր դրոշակի համար **աղբյուրի նշան** — `DB`, `ENV`, կամ `DEF` — ցույց տալով, թե որտեղից է
  ստացվել արդյունավետ արժեքը:
- **Վերակայել** կոճակ (ցուցադրվում է միայն `DB`-ից ստացված դրոշակների համար)՝ վերացնելու վերասահմանումը,
  և **Վերակայել բոլոր վերասահմանումները** կոճակը ներքևում:
- **Վերագործարկել սերվերը** պաստառ, երբ `requiresRestart` դրոշակը փոփոխվում է:

Յուրաքանչյուր մեթոդ պահանջում է վավերացված կառավարման վահանակի սեսիա (հակառակ դեպքում՝ `401`):

#### `GET /api/settings/feature-flags`

Վերադարձնում է յուրաքանչյուր դրոշակ իր արդյունավետ արժեքով, աղբյուրով և ամփոփագրով:

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... all 74 flags
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Սահմանել կամ հեռացնել մեկ վերասահմանում: Մարմինը՝ `{ key: string; value?: string }`:
`value`-ի բացթողումը հեռացնում է վերասահմանումը (վերականգնելով միջավայրի / լռելյայն արժեքը):

```bash
# Set a DB override
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Remove the override (no "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Պատասխանը արտացոլում է նոր `effectiveValue`/`source`-ը, `previousValue`/
`previousSource`-ը և `requiresRestart`-ը: Անհայտ բանալիները և միջակայքից դուրս enum
արժեքները մերժվում են `400` կոդով:

#### `DELETE /api/settings/feature-flags`

Միանգամից մաքրում է **բոլոր** DB վերասահմանումները՝ վերականգնելով յուրաքանչյուր դրոշակ իր միջավայրի / լռելյայն
արժեքին: Վերադարձնում է `{ cleared: <count>, message: "..." }`:

> [!ՆՇՈՒՄ]
> Դրոշակները, որոնք ունեն `requiresRestart: true`, ուժի մեջ են մտնում միայն պրոցեսի վերաբեռնումից հետո:
> Կառավարման վահանակի վերագործարկման հոսքը կանչում է `POST /api/restart`, այնուհետև հարցում է կատարում
> `GET /api/health/ping` մինչև սերվերի վերագործարկումը:

## Բյուջեի արտակարգ պահուստային տարբերակ

`OMNIROUTE_EMERGENCY_FALLBACK`-ը (կատեգորիան՝ `runtime`, լռելյայն արժեքը՝ `true`) կառավարում է
արտակարգ անվճար պահուստային ուղին
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)-ում։
Միացված լինելու դեպքում իրենց բյուջեն սպառած հարցումներն ամբողջությամբ ձախողվելու փոխարեն ուղղորդվում են
անվճար պահուստային մատակարարի/մոդելի մոտ։ Սահմանեք այն որպես `false` (կամ `0`)՝ կառավարման
վահանակի փոխարկիչի, DB վերագրման կամ `OMNIROUTE_EMERGENCY_FALLBACK`
միջավայրի փոփոխականի միջոցով, որպեսզի անջատեք այս վարքագիծը և թույլ տաք, որ բյուջեն սպառած հարցումները
ձախողվեն։ (Կառավարման վահանակում ներկայացվել է որպես փոխարկիչ PR-ներում #3741 / #3752։)
