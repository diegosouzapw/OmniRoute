Որոշ ծառայություններ ինտեգրվել էին OmniRoute-ին, իսկ ավելի ուշ հեռացվել էին, քանի որ դրանք
գործարկող անձինք այդպես էին խնդրել։ Այս էջն այդ հեռացումների մշտական գրանցամատյանն է։ Դրա
միակ նպատակը պատահական վերականգնումը կանխելն է․ հին fork, քեշավորված npm tarball,
արխիվացված issue կամ «վերականգնել X մատակարարին» հարցում գտնող մասնակիցը պետք է ունենա
մեկ վայր, որտեղ ասվում է՝ **չվերաներդնել**։

Այս էջը դադարած կամ այլևս չգործող ծառայությունների ցանկ **չէ**։ Դրանք գրանցվում են
[`FREE_TIERS.md`](FREE_TIERS.md)-ում («Հեռացված / անվճար մակարդակ չկա») և կարող են
վերադառնալ, եթե ծառայությունը վերադառնա։ Ստորև բերված գրառումները կարող են վերադառնալ
միայն հարցման մեջ նշված օպերատորի գրավոր թույլտվությամբ, և այդ թույլտվության հղումը պետք է
ներառվի գրառման մեջ։

## Քաղաքականություն

1. **Ծառայության օպերատորի հեռացման հարցումը կատարվում է, ոչ թե քննարկվում։** OmniRoute-ը
   փոխկապակցված չէ վերին մակարդակի որևէ ծառայության հետ։ Երբ ծառայության օպերատորը խնդրում է
   հեռացնել ինտեգրումը, այն հեռացվում է՝ անկախ նրանից, թե ինտեգրումն օգտագործել է պաշտոնական API,
   թե ոչ։
2. **«Հեռացված» նշանակում է OmniRoute-ի կողմից վերահսկվող յուրաքանչյուր մակերես։** Executor,
   registry-ի գրառում, մատակարարի id և alias, մոդելների ցանկ, endpoint-ներ, միջավայրի
   փոփոխականներ, պատկերակ, dashboard-ի քարտեր, գեներացված մատակարարի տեղեկատու,
   `FREE_TIERS.md`, միջավայրի տեղեկատու, README-ի քանակներ, `llm.txt` հայելիներ,
   առանձնացված թեստեր և golden snapshot-ներ, կոդի մեկնաբանություններ, CHANGELOG-ի կետեր
   (գրանցամատյանում հաշվառված համաձայնեցմամբ՝ տե՛ս `config/release/changelog-reconciliations.json`),
   GitHub Releases-ի նշումներ, wiki-ն, ինչպես նաև GitHub-ի այն issue-ները, discussion-ները և pull
   request-ները, որոնց թեման տվյալ մատակարարն էր (issue-ները և discussion-ները ջնջվում են, իսկ pull
   request-ները վերանվանվում են, դրանց նկարագրությունը փոխարինվում է, և քննարկումը՝ կողպվում, քանի որ
   GitHub-ը չի կարող ջնջել pull request-ները)։
3. **Երբեք մի վերաներդրեք այս էջի որևէ գրառում առանց գրավոր թույլտվության։** Դա ներառում է
   id-ի կամ alias-ի վերադարձը մատակարարների որևէ կատալոգ, domain-ների ավելացումը executor-ին,
   այն մասնակցի PR-ի ընդունումը, որը «վերականգնում» է այն, դրա ավելացումը անվճար մոդելների
   կատալոգում կամ OmniRoute-ի միջոցով դրան ձեռքով հասնելու եղանակի փաստաթղթավորումը։ Փակեք
   այդպիսի PR-ներն ու issue-ները՝ հղում տալով այս էջին։
4. **Գրառումը պահեք նվազագույն ծավալով։** Գրանցեք միայն այն, ինչ անհրաժեշտ է վերանայողին
   վերաներդրումը ճանաչելու համար՝ նույնացուցիչներ, domain-ներ, ամսաթվեր և հեռացումն իրականացրած
   pull request-ը։ Մի նկարագրեք, թե ինչպես էր աշխատում ինտեգրումը։
5. **Հետընթացը կանխող ստուգիչը `tests/unit/removed-providers-blocklist.test.ts` է։** Այն ձախողվում է,
   երբ ստորև նշված որևէ նույնացուցիչ կամ domain կրկին հայտնվում է մատակարարների կատալոգներում,
   executor-ի քարտեզում կամ մատակարարների registry-ի աղբյուրներում։ Նոր նույնացուցիչներն ավելացրեք
   այդ թեստում նույն PR-ի շրջանակում, որով այստեղ տող եք ավելացնում։

## Գրառման ավելացում

Երբ ստացվում է հեռացման նոր հարցում՝

1. Հաստատեք, որ հարցումը գալիս է ծառայության օպերատորից (նրա աջակցության հասցեից կամ նրա
   կողմից վերահսկվող domain-ից), և հաղորդագրությունը պահեք գաղտնի։
2. Հեռացրեք ինտեգրումը՝ հետևելով քաղաքականության 2-րդ կետի ստուգաթերթին։ Օգտագործեք
   [#12440](https://github.com/diegosouzapw/OmniRoute/pull/12440)-ը որպես առանց key-ի
   մատակարարի հղման օրինակ, իսկ [#10210](https://github.com/diegosouzapw/OmniRoute/pull/10210)-ը՝
   պահված կապերով API key պահանջող մատակարարի համար (ավելացրեք միգրացիա)։
3. Վերևի աղյուսակում ավելացրեք մեկ տող, իսկ նույնացուցիչները՝
   `tests/unit/removed-providers-blocklist.test.ts`-ում՝ նույն PR-ի շրջանակում։
4. PR-ի միավորումից հետո պատասխանեք օպերատորին՝ թվարկելով, թե ինչն է հեռացվել և ինչը
   OmniRoute-ը չի կարող փոխել (արդեն հրապարակված npm և Docker տարբերակները, git-ի
   պատմությունը, երրորդ կողմերի fork-երը)։
