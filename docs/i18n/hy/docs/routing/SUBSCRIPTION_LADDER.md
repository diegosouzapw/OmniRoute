> Երկու նոր `auto/*` նույնացուցիչ՝ `auto/subscription` և `auto/thrifty`։ Երկուսն էլ միացվում են ըստ ցանկության՝
> դրանք հարցման միջոցով պահանջելով. դրանցով ոչինչ չի երթուղավորվում, եթե կանչողը նույնացուցիչն անվամբ չի պահանջում, և
> գոյություն ունեցող որևէ փուլի, ռազմավարության կամ լռելյայն վարքագծի փոփոխություն չկա։

## Ինչու է սա անհրաժեշտ

OmniRoute-ն արդեն պատասխանում է ծախսերի վերաբերյալ երկու հարցի, սակայն դրանցից ոչ մեկն այն չէ, որը տալիս են օպերատորների մեծ մասը։

| Գոյություն ունեցող մեխանիզմ                              | Ինչ հարցի է պատասխանում                           |
| -------------------------------------------------------- | ------------------------------------------------- |
| `hidePaidModels` (`autoCombo/paidModelFilter.ts`)        | «այս մոդելը կատալոգում նշվա՞ծ է որպես անվճար»     |
| `freeAccessPolicy: "strict"` (`strictZeroCostFilter.ts`) | «այս կապը երբևէ կարո՞ղ է ինձանից գումար գանձել»   |
| `quotaPreflight` (`combo/quotaExhaustionCutoff.ts`)      | «այս կապը մոտեցե՞լ է իր սահմանաչափին»             |
| `budgetCap` / `budgetFallback` (`autoCombo/engine.ts`)   | «սահմանափակել ծախսը, անցնել ամենաէժան տարբերակին» |

Միայն անվճար տարբերակներ օգտագործող յուրաքանչյուր մեխանիզմ **փակվում է ձախողման դեպքում**. սպառված անվճար փուլը դառնում է դատարկ փուլ և երբեք չի անցնում վճարովի տարբերակի, իսկ վճարովի կողմի յուրաքանչյուր մեխանիզմ անտեսում է մակարդակները։ Դրանցից ոչ մեկը չի պատասխանում հետևյալ հարցին.

> «Օգտագործել այն քվոտան, որի համար ես արդեն վճարում եմ։ Երբ այն սպառվի՝ կա՛մ կանգ առնել, կա՛մ
> աստիճանաբար բարձրանալ մեկ մակարդակով՝ անցնելով ամենաէժան վճարովի տարբերակներով, և վերադառնալ
> քվոտայի վերականգնման հենց նույն պահին»։

## Վճարումը կապի, այլ ոչ թե մոդելի հատկանիշ է

`classifyTier()`-ը (`open-sse/services/tierResolver.ts`) հիմնվում է `(provider, model)` զույգի վրա և կատալոգային գնից վերադարձնում է
`free | cheap | premium`։ Սակայն հարցումն իր հետ լրացուցիչ ծախս կբերի, թե ոչ, կախված է նրանից, թե **որ կապն է այն սպասարկում**. նույն մոդելը կարող է ներառված լինել սակագնային պլանում՝ Claude Code OAuth կապով օգտագործվելիս, և ըստ թոքենների վճարովի լինել՝ API բանալիով կապի միջոցով օգտագործվելիս։

`provider_connections.auth_type`-ը հուսալի ցուցիչ չէ ոչ մի ուղղությամբ. գոյություն ունեն հաշվարկվող OAuth կապեր և սակագնային պլանում ներառված API բանալիով կապեր (Copilot-ի բաժանորդագրության թոքենը հաշվարկվող API բանալի չէ)։ Ուստի վճարման դասը վերցվում է **խնամքով կազմված կատալոգից**՝
`open-sse/config/connectionBillingCatalog.ts`, որը ձեռքով կազմվում է յուրաքանչյուր մատակարարի հրապարակած պայմանների հիման վրա՝ նույն ձևաչափով, որն `FreeModelBudget.hardStopGuaranteed`-ն արդեն սահմանել է անվճար մոդելների համար։

```ts
type ConnectionBillingClass = "subscription" | "metered" | "keyless" | "unknown";
type ConnectionOverageBehavior = "hard-stop" | "meters-to-paid" | "unknown";
```

Որոշման հերթականությունը (`autoCombo/connectionBilling.ts`) հետևյալն է՝ առանց նույնականացման սինթետիկ պահապան արժեք →
`keyless`, մատակարարին **և** `authType`-ին համապատասխանող կատալոգային գրառում, մատակարարի ընդհանուր գրառում, իսկ հակառակ դեպքում՝ `unknown`։ **Կատալոգում չներառվածը անվճար չէ**. `unknown`-ը ամենուր դիտարկվում է որպես `metered`, այնպես որ վաղը ավելացված մատակարարն ի սկզբանե չի հայտնվի բաժանորդագրության մակարդակում և պետք է այնտեղ ներառվի միտումնավոր։

## Մակարդակների մոդելը

Սրացման հերթականությամբ հինգ մակարդակ։ Դրանք տարբերվում են ոչ միայն գնով. յուրաքանչյուրն ունի սպառման **սեփական** ազդանշանը, ինչի պատճառով սա պարզապես տեսակավորում չէ։

| #   | Մակարդակ       | Անդամակցության պայման                          | Երբ է համարվում սպառված                          |
| --- | -------------- | ---------------------------------------------- | ------------------------------------------------ |
| 0   | `subscription` | խնամքով կազմված `billing: "subscription"`      | քվոտայի պատուհանը սահմանաչափին է կամ դրանից ցածր |
| 1   | `keyless`      | առանց նույնականացման սինթետիկ ուղի             | կապի ժամանակավոր արգելափակում / անջատիչ          |
| 2   | `free`         | հաշվարկվող կապ, `classifyTier() === "free"`    | անվճար սահմանաչափը սպառված է                     |
| 3   | `cheap`        | հաշվարկվող կապ, `classifyTier() === "cheap"`   | մակարդակի բյուջեն սպառված է                      |
| 4   | `premium`      | հաշվարկվող կապ, `classifyTier() === "premium"` | մակարդակի բյուջեն սպառված է                      |

0-2 մակարդակները սպառվում են **քվոտայի** հիման վրա, որը դիտարկելի է և արդեն հետագծվում է։ 3-4 մակարդակները քվոտա չունեն. վճարովի կապը կարող է սպասարկել անվերջ, ուստի դրանց սպառման միակ ողջամիտ ազդանշանը յուրաքանչյուր մակարդակի առանձին **բյուջեն** է։ Առանց դրա «բարձրանալ, երբ էժան մակարդակը սպառված է» վարքագիծը գործարկող ազդանշան չունի։

## `auto/subscription` — ձախողվել փակ ռեժիմով

Pool = միայն 0-րդ աստիճանը՝ սահմանափակված այն կապերով, որոնց գերածախսը փաստաթղթավորված `hard-stop` է, և որոնցից յուրաքանչյուրի համար իրական ժամանակում հաստատվել է քվոտայի պահուստի առկայությունը։ Բոլոր անորոշ դեպքերը բացառվում են՝ չհամակարգված մատակարար, չստուգվող քվոտայի ցուցմունք, հնացած ցուցմունք կամ վճարովի հաշվարկվող գերածախս։

Դատարկ pool-ը **նախատեսված** արդյունք է, ոչ թե թերություն. կանչողի՝ դատարկ pool-ի համար արդեն գոյություն ունեցող ուղին այն վերածում է հստակ սխալի՝ լուռ, վճարովի պահուստային տարբերակի փոխարեն։ Սա է տվյալ id-ի ամբողջ երաշխիքը։

`keyless`-ը միտումնավոր **չի** համապատասխանում. այս խմբավորումը նշանակում է «պլանը, որի համար ես վճարում եմ», ուստի նույնականացում չպահանջող backend-ը դրան չի պատկանում։ Դրա համար օգտագործեք `auto/thrifty`-ն (կամ `auto/best-free`-ն)։

### Կապերի անվտանգություն

Թեկնածուն միշտ չէ, որ կապված է միայն մեկ կապի հետ. տրամաբանական թեկնածուն պարունակում է `allowedConnectionIds` թույլատրված արժեքների ցանկ, իսկ փաստացի օգտագործվող հաշիվն ընտրվում է ավելի ուշ՝ հարցումն ուղարկելիս, `open-sse/services/combo/autoStrategy.ts`-ի կողմից։ Հետևաբար երկու խմբավորումներն էլ **յուրաքանչյուր կապը ստուգում են առանձին** և `allowedConnectionIds`-ը վերագրում են՝ թողնելով միայն ստուգումն անցած ենթաբազմությունը. երբեք ոչ ամբողջ սկզբնական ցանկը և ոչ էլ կամայականորեն ընտրված մեկ անդամ։ Քանի որ `autoStrategy.ts`-ն արդեն այդ զանգվածը կիրառում է որպես խիստ թույլատրված արժեքների ցանկ, այստեղ այն վերագրելը կառուցվածքով իսկ «ստուգված» և «փաստացի օգտագործված» բազմությունները դարձնում է նույնը։ Սա նույն ինվարիանտն ու նույն հիմնավորումն է, ինչ [STRICT_ZERO_COST](./STRICT_ZERO_COST.md)-ի դեպքում։

## `auto/thrifty` — բարձրանալ մեկ աստիճանով յուրաքանչյուր քայլում

Pool = բոլոր աստիճանները՝ դասավորված ըստ աստիճանի ինդեքսի, ընդ որում սպառված թեկնածուները դուրս են թողնվում։ `auto` շարժիչը շարունակում է գնահատել մնացած pool-ի **ներսում**. սանդուղքը որոշում է, թե որ աստիճաններն են մասնակցում, իսկ գնահատումը՝ թե դրանց ներսում որ թեկնածուն է հաղթում։ Յուրաքանչյուր աստիճանի ներսում դասավորությունը կայուն է, ուստի այս վերադրվող շերտը երբեք չի վերադասավորում գնահատիչի սեփական վարկանիշը։

Սա դասավորման + զտման վերադրվող շերտ է, **ոչ թե** նոր dispatcher. `combo.ts`-ի սպեկուլյատիվ ցիկլն արդեն հերթականությամբ անցնում է թիրախներով և ձախողման դեպքում անցնում հաջորդին, ուստի կատարման պահին առաջացած սպառումը, որը նախնական ստուգումը չի հայտնաբերել, միևնույն հարցման ներսում դեռևս հանգեցնում է հաջորդ աստիճանին անցնելուն։

Եթե `auto/subscription`-ը ձախողվում է **փակ**, ապա `auto/thrifty`-ն ձախողվում է **բաց**. պլանում ներառված կապը, որի համար չկա օգտագործելի քվոտայի ցուցմունք, միևնույն է՝ փորձարկվում է առաջինը։ Այն փորձելն անվճար է, և եթե պարզվի, որ այն սպառված է, հաջորդին անցնելու մեխանիզմն ամեն դեպքում կհասնի հաջորդ աստիճանին։ Իսկ այն փորձելուց հրաժարվելը բացակայող հեռաչափման պատճառով հարցումը կուղարկեր վճարովի աստիճան՝ հենց այն արդյունքին, որը կանխելու համար ստեղծվել է այս խմբավորումը։

## Վերակայումից հետո վերադարձը պլանին

Երթուղավորումը 0-րդ աստիճան վերադարձնելուց առաջ երեք անկախ բան պետք է ժամկետանց դառնա։ Դրանցից միայն մեկը շտկելու դեպքում սանդուղքը պլանի վերալցավորումից դեռ երկար ժամանակ անց կմնա վճարովի աստիճաններում։

1. **Քվոտայի վիճակի cache-ը** — `freeAccessQuota.ts`-ը cacheավորում է ըստ `(provider, connection)` զույգի՝ 180s TTL-ով։ Cacheավորված գրառումը, որի սեփական `resetAt`-ն արդեն անցել է, նկարագրում է այլևս գոյություն չունեցող պատուհան, ուստի այժմ այն համարվում է հնացած՝ **անկախ տարիքից**, և պարտադրում է թարմացում։ Առանց դրա՝ կեսգիշերին վերալցավորված պլանը շարունակում է նշվել որպես սպառված, մինչև TTL-ը պատահաբար լրանա։
2. **Սանդուղքի սեփական վիճակը** — նախագծմամբ այդպիսին չկա։ Աստիճանի համապատասխանելիությունը յուրաքանչյուր pool-ի կառուցման ժամանակ վերահաշվարկվում է քվոտայի ընթացիկ վիճակից. պահպանվող «ներկայումս 3-րդ աստիճանում է» գրառում չկա, որը կարող էր վերակայումից ավելի երկար գոյատևել և արգելափակել երթուղավորումը։
3. **Կապի cooldown-ը** — սպառման պատճառ դարձած 429-ը `rateLimitedUntil`-ը սահմանում է էքսպոնենցիալ backoff-ից, որը պլանի կապի դեպքում կարող է անցնել իրական վերակայման պահը։ `clampCooldownToReset()`-ը (`subscriptionLadder.ts`) սահմանափակում է cooldown-ը վերին հոսքի սեփական վերակայման պահով և երբեք չի կարող այն երկարացնել։ **Այն իրականացված և թեստավորված է, բայց դեռ միացված չէ**. քվոտայի cache-ը `src/sse/services/auth.ts`-ում անվավերացվում է _նախքան_ որևէ cooldown գրանցելը, ուստի `resetAt`-ը պետք է այդ ֆունկցիայում ավելի վաղ վերցվի։ Սա կայունության կրիտիկական կատարման ուղու փոփոխություն է, որը պետք է կատարվի առանձին, վերանայվող PR-ում։ Մինչ այդ կրկին մուտքը սպասում է կապի cooldown-ի ավարտին (որն արդեն նախապատվությունը տալիս է վերին հոսքի `Retry-After` հուշումներին, երբ մատակարարն ուղարկում է դրանք)։

### Տատանումների կանխարգելում

Հենց նոր վերակայված աստիճանը կրկին թույլատրվում է միայն այն դեպքում, երբ ցուցանիշը բարձր է `reentryMinRemainingPercent`-ից (լռելյայն՝ 5), մինչդեռ արդեն օգտագործվող կապը պետք է պարզապես մնա `exitCutoffPercent`-ից բարձր (լռելյայն՝ 2, ինչը համապատասխանում է `quotaPreflight.defaultThresholdPercent`-ին)։ Այդ տարբերությունը հիստերեզիսի գոտին է. առանց դրա՝ շեմի մոտ տատանվող կապը հաջորդական հարցումների ընթացքում շարունակ կանցներ մի աստիճանից մյուսը։

## Կազմաձևում

Միայն ճշգրտումներ։ Դիտավորյալ **չկա** `enabled` դրոշակ․ դրանք անջատելու ունակ փոխարկիչը
կհանգեցներ նրան, որ `auto/subscription`-ը աննկատ կսպասարկեր ամբողջ պուլը՝ ներառյալ վճարովի մոդելները՝ մի
անվան տակ, որը հակառակն է խոստանում։

```jsonc
{
  "subscriptionLadder": {
    "exitCutoffPercent": 2,
    "reentryMinRemainingPercent": 5,
    "rungBudgetUsd": { "cheap": 5.0, "premium": 0 }, // 0-ն ամբողջությամբ անջատում է տվյալ աստիճանը
  },
}
```

Բյուջետային սահմանափակումը պասիվ է, քանի դեռ ծախսերի որոշման մեխանիզմ միացված չէ․ հաշվառման բացակայության դեպքում վճարովի
աստիճանը ներառվում է հերթականության մեջ, սակայն երբեք չի սահմանափակվում։ v3.8.51-ից սկսած՝ `rungBudgetUsd` կարգավորումն ընդունվում է
սխեմայի կողմից, բայց դեռ ՉԻ կիրառվում․ այն դիտարկեք որպես պահուստավորված կազմաձևում, ոչ թե որպես ծախսերի գործող սահմանաչափ։ Աստիճանների հերթականությունը, քվոտայի վրա հիմնված սպառումը և վերակայումից հետո կրկին մուտք գործելը՝ բոլորը
աշխատում են առանց դրա։

## Համադրում

`subscription`-ը և `thrifty`-ն `AutoTier` արժեքներ են, ուստի դրանք համադրվում են յուրաքանչյուր կատեգորիայի հետ՝
`auto/coding:thrifty`, `auto/reasoning:subscription` և այլն։ Երկու պարզ նույնացուցիչները
(`auto/subscription`, `auto/thrifty`) հրապարակվում են `/v1/models`-ում և կառավարման վահանակում։

Երկու նույնացուցիչներից ոչ մեկը վճարովի մակարդակի չէ, ուստի `isPaidTierAutoId()`-ը երկուսի համար էլ վերադարձնում է `false`, իսկ
`auto/subscription`-ը պահպանվում է `hidePaidModels`-ի կիրառումից հետո։
