OmniRoute-ը կարող է Termux-ի միջոցով Android-ում աշխատել որպես առանց գրաֆիկական միջերեսի սերվեր։ Electron աշխատասեղանի հավելվածը Termux-ում չի աջակցվում, սակայն վեբ կառավարման վահանակը և OpenAI-ի հետ համատեղելի API-ն հասանելի են տեղային դիտարկիչից կամ նույն ցանցում գտնվող այլ սարքերից։

## Նախապայմաններ

Տեղադրեք Termux-ը F-Droid-ից կամ GitHub-ի թողարկումներից, ապա թարմացրեք փաթեթները և տեղադրեք `better-sqlite3`-ի նման բնիկ կախվածությունների համար անհրաժեշտ կառուցման գործիքները։

```bash
pkg update
pkg upgrade
pkg install nodejs python build-essential git
```

> **Node.js-ի տարբերակ․** OmniRoute-ի համար պահանջվում է Node `>=22.22.2 <23 || >=24.0.0 <27` (համապատասխանում է `package.json`-ի `engines` / `SUPPORTED_NODE_RANGE` արժեքներին)։ Termux-ի `nodejs-lts`-ը սովորաբար տրամադրում է Node 20 LTS, որն **այլևս չի աջակցվում**․ դրա փոխարեն տեղադրեք ընթացիկ տարբերակը՝ `pkg install nodejs`, և համոզվեք, որ `node --version`-ը ցուցադրում է 22.x/24.x+ ճյուղի տարբերակ։

Եթե բնիկ փաթեթների կոմպիլյացիան ձախողվի, կրկին գործարկեք վերոնշյալ `pkg install` հրամանը, ապա նորից փորձեք տեղադրել OmniRoute-ը։

## Տեղադրում

Անմիջապես գործարկեք վերջին հրապարակված փաթեթը․

```bash
npx -y omniroute@latest
```

Այն կարող եք նաև տեղադրել գլոբալ կերպով․

```bash
npm install -g omniroute
omniroute
```

## Գործարկում

Գործարկեք OmniRoute-ը առանց գրաֆիկական միջերեսի սերվերի ռեժիմով․

```bash
omniroute
```

կամ՝

```bash
npx omniroute
```

Կառավարման վահանակը հասանելի է հետևյալ հասցեով․

```text
http://localhost:20128
```

Բացեք այդ URL-ը Android-ի դիտարկիչում։ Եթե հաճախորդները գործարկում եք Termux-ի ներսում, որպես OpenAI-ի հետ համատեղելի բազային URL օգտագործեք նույն հոսթը և պորտը։

## Ֆոնային գործարկում

Պարզ ֆոնային գործընթաց գործարկելու համար․

```bash
nohup omniroute > omniroute.log 2>&1 &
```

Այն դադարեցնելու համար․

```bash
pkill -f omniroute
```

Սարքի բեռնումից հետո ավտոմատ գործարկման համար տեղադրեք Termux:Boot հավելումը և ստեղծեք բեռնման սկրիպտ․

```bash
mkdir -p ~/.termux/boot
cat > ~/.termux/boot/omniroute.sh <<'EOF'
#!/data/data/com.termux/files/usr/bin/sh
cd "$HOME"
nohup omniroute > "$HOME/omniroute.log" 2>&1 &
EOF
chmod +x ~/.termux/boot/omniroute.sh
```

Android-ի մարտկոցի օպտիմալացումը կարող է դադարեցնել երկարատև ֆոնային գործընթացները։ Եթե ակնկալվում է, որ սերվերը պետք է մշտապես հասանելի մնա, անջատեք մարտկոցի օպտիմալացումը Termux-ի համար։

## Հասանելիություն այլ սարքերից

Գտեք հեռախոսի IP հասցեն WiFi ցանցում․

```bash
ip addr show wlan0
```

Այնուհետև մեկ այլ սարքից բացեք կառավարման վահանակը․

```text
http://PHONE_IP:20128
```

Օրինակ՝

```text
http://192.168.1.50:20128
```

Հեռախոսը և հաճախորդ սարքը պահեք նույն վստահելի ցանցում։ Եթե OmniRoute-ը հասանելի եք դարձնում հեռախոսից դուրս, միացրեք API բանալիները և կառավարման վահանակի նույնականացումը։

## Տվյալների գրացուցակ

Լռելյայնորեն OmniRoute-ը տվյալները պահում է Termux-ի տնային գրացուցակում՝ հետևելով Linux-ում օգտագործվող սերվերային տվյալների ուղու նույն վարքագծին։ Տվյալների բազան հստակ նշված վայրում պահելու համար․

```bash
export DATA_DIR="$HOME/.omniroute"
omniroute
```

## Սահմանափակումներ

- Electron-ը չի աշխատում Termux-ում։
- Համակարգային սկուտեղ կամ աշխատասեղանի ինտեգրում չկա։
- Այս կարգավորումը նախատեսված է միայն սերվերի համար․ օգտագործեք դիտարկիչի կառավարման վահանակը։
- Բնիկ կախվածությունները կարող են պահանջել տեղային կոմպիլյացիա։
- Փոքր հիշողությամբ Android սարքերում կարող է անհրաժեշտ լինել նվազեցնել միաժամանակյա հարցումների քանակը։
- MITM-ի կամ համակարգային վկայագրերի գործառույթները կարող են պահանջել Android-ի վստահության պահոցի հետ աշխատանք՝ Termux-ից դուրս։

## Խնդիրների լուծում

### Չաջակցվող հարթակ՝ android (յուրաքանչյուր հարցում վերադարձնում է HTTP 500)

**Ախտանիշ․** `omniroute` / `omniroute serve` հրամանը ցուցադրում է `✔ OmniRoute is running!`, սակայն կառավարման վահանակի կամ API-ի յուրաքանչյուր հարցում վերադարձնում է պարզ `500 Internal Server Error`։ `~/.omniroute/logs/application/app.log`-ը մնում է դատարկ, `APP_LOG_LEVEL=debug`-ը ոչ մի օգտակար տեղեկություն չի ցուցադրում, իսկ պատասխանի մարմինը սովորական տեքստ է (`Internal Server Error`)՝ առանց JSON մանրամասների։

**Պատճառ․** Termux/Node-ի որոշ կառուցումներ վերադարձնում են `process.platform === "android"`։ Next.js-ի `getCacheDirectory()`-ն չի մշակում այդ հարթակը․ այն պահանջում է, որ `~/.cache`-ը (կամ ընդհանուր ժամանակավոր գրացուցակը) _արդեն_ գոյություն ունենա, հակառակ դեպքում գործիքավորման հուկը բեռնելիս այն ձախողվում է հետևյալ սխալով․

```text
Error: An error occurred while loading instrumentation hook: Unsupported platform: android
```

Քանի որ հուկը երբեք չի բեռնվում, գրանցամատյանների վարումը չի սկսվում, և 500 սխալի պատճառը թվում է ամբողջովին անորոշ։ OmniRoute-ը CLI-ի մուտքային կետում, նախքան Next.js-ի մեկնարկը, ստեղծում է `~/.cache`-ը (և սահմանում է `XDG_CACHE_HOME`-ը, եթե այն սահմանված չէ), որպեսզի այս ստուգումը հաջողությամբ կատարվի Android/Termux-ում։

**Աջակցվող լուծում (առանց փաթեթը փոփոխելու)․**

```bash
mkdir -p ~/.cache
omniroute serve
```

OmniRoute-ի ընթացիկ կառուցումներում CLI-ն դա ավտոմատ կերպով կատարում է Android/Termux-ում․ նոր `npx -y omniroute@latest` գործարկումից կամ գլոբալ տեղադրումից հետո ձեռքով այս քայլը կատարելու անհրաժեշտություն չպետք է լինի։ Եթե թարմացումից հետո դեռ տեսնում եք սխալը, մեկ անգամ ստեղծեք `~/.cache`-ը, ինչպես ցուցադրված է վերևում, և վերագործարկեք։

**Մի՛** փոփոխեք `dist/server.js`-ը՝ `process.platform = "linux"` հարկադրաբար սահմանելու համար։ Փաթեթի այդպիսի փոփոխությունը վերագրվում է յուրաքանչյուր վերատեղադրման կամ թարմացման ժամանակ և անհրաժեշտ չէ, երբ քեշի գրացուցակը գոյություն ունի։

### better-sqlite3-ի կառուցման սխալներ

Տեղադրեք Termux-ի կառուցման գործիքակազմը․

```bash
pkg install nodejs python build-essential
```

Այնուհետև կրկին գործարկեք․

```bash
npx -y omniroute@latest
```

### Պորտն արդեն օգտագործվում է

Ստուգեք, թե ինչն է սպասարկում լռելյայն պորտը․

```bash
ss -ltnp | grep 20128
```

Դադարեցրեք հին գործընթացը․

```bash
pkill -f omniroute
```

### Կառավարման վահանակը հասանելի չէ մեկ այլ սարքից

Համոզվեք, որ երկու սարքերն էլ միացված են նույն WiFi ցանցին, ապա Termux-ից փորձարկեք․

