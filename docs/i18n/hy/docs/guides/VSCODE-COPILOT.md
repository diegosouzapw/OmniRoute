**OmniCopilot**-ը OmniRoute-ի սպասարկած բոլոր մոդելներն ավելացնում է GitHub Copilot Chat-ի _ներկառուցված_ մոդելների ընտրացանկում։
Ոչ մի երկրորդ կողագոտի, ոչ մի առանձին չաթի միջերես․ Copilot-ի գործակալի ռեժիմը, գործիքների կանչերը,
MCP սերվերներն ու հատուկ հրահանգները շարունակում են աշխատել՝ պարզապես ձեր ընտրած մոդելով։

## Կարգավորում

1. **Գործարկեք OmniRoute-ը** — `npm install -g omniroute && omniroute` (կառավարման վահանակը՝ `http://localhost:20128`)։
2. **Տեղադրեք ընդլայնումը** — Extensions դիտակերպում որոնեք «OmniRoute»։
3. **Ընտրեք մոդել** — Copilot Chat → մոդելների ընտրացանկ → **Կառավարել մոդելները…** → **OmniRoute**, ապա նշեք
   ձեր ուզածը։

Երբ OmniRoute-ն աշխատում է կանխադրված պորտով, կարգավորելու ոչինչ չկա։ Հեռակա օրինակի համար բացեք
**OmniRoute պատկերակը Activity Bar-ում** (կամ գործարկեք `OmniRoute: Manage Connection`) և սահմանեք՝

- **Սերվերի URL** — սերվերի արմատային հասցեն, օրինակ՝ `http://192.168.0.15:20128`։ `/v1` վերջածանցը
  կցվում է ընդլայնման կողմից․ մի ներառեք այն։
- **API բանալի** — միայն այն դեպքում, երբ սերվերը սահմանում է `REQUIRE_API_KEY`։ Պահվում է ՕՀ-ի բանալիների շղթայում՝ VS
  Code SecretStorage-ի միջոցով, և երբեք՝ `settings.json`-ում։

## Ինչ կցուցադրի ընտրացանկը

Ընդլայնումը չի ցուցադրում `GET /v1/models`-ի չմշակված պատասխանը․ այն ձևափոխում է տվյալները, և ձեր տեսած
քանակը կատալոգի չափից փոքր է երկու միտումնավոր պատճառով։

### Այն յուրաքանչյուր մոդելի համար պահանջում է մեկ id

`MODELS_CATALOG_PREFIX_MODE`-ի կանխադրված արժեքը **`dual`** է, որը յուրաքանչյուր մոդել հայտարարում է երկու անգամ՝ մեկ անգամ
կարճ կեղծանվան նախածանցով և մեկ անգամ կանոնական մատակարարի նախածանցով, որպեսզի հաճախորդների հին
կարգավորումները շարունակեն ճանաչել երկու ձևերն էլ․

```
cc/claude-sonnet-4-6        ← կեղծանվան նախածանց
claude/claude-sonnet-4-6    ← կանոնական նախածանց, նույն մոդելը
```

Ընդլայնումը հարցում է ուղարկում **`GET /v1/models?prefix=alias`**, որպեսզի յուրաքանչյուր մոդելի համար ստացվի մեկ id՝
առանց ձեր մյուս հաճախորդների համար սերվերի ընդհանուր կարգավորումը փոխելու։ Փորձնական օրինակում սա
**2345 գրառումը կրճատեց մինչև 1396-ի՝ 949 կրկնօրինակ, զրո կորցրած մոդել։**

Եթե նախընտրում եք դա սերվերի մակարդակով շտկել _բոլոր_ հաճախորդների համար, կառավարման վահանակում
`MODELS_CATALOG_PREFIX_MODE` գործառույթի դրոշակը սահմանեք `alias`։ Հարցման պարամետրի և ըստ ռեժիմների
աղյուսակի համար տես
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix)։

### Այն թաքցնում է մոդելները, որոնք չեն կարող չաթ վարել

Կատալոգում թվարկվում են նաև պատկերների, տեսանյութերի, ձայնի, վերադասակարգման, ներդրումների և մոդերացիայի մոդելներ։ Դրանք
միևնույն է մերժվում են չաթի հարցման ժամանակ․

```
HTTP 400 — '<id>' մոդելը պատկերների ստեղծման մոդել է և չի կարող օգտագործվել
/v1/chat/completions-ում։ Փոխարենն օգտագործեք POST /v1/images/generations։
```

ուստի դրանք, ըստ իրենց `type` դաշտի, զտվում են նախքան ընտրացանկ հասնելը։ **Responses-API-ի
մոդելները պահպանվում են**․ յուրաքանչյուր Codex / GPT-5.x գրառում հայտարարում է `supported_endpoints: ["responses"]`,
իսկ OmniRoute-ը դրանք փոխակերպում է `/v1/chat/completions`-ի համար, ուստի դրանք լիովին կիրառելի են։

### Մատակարարներ, որոնք երբեք չեք կարգավորել

Կատալոգում թվարկվում են **ակտիվ կապ** ունեցող մատակարարների մոդելները, ինչպես նաև բոլոր **noAuth**
մատակարարները՝ առանց բանալու աշխատողները, որոնք կազմում են անվճար մակարդակի մեծ մասը։ Սա միտումնավոր է։ Դրանք թաքցնելու
համար կառավարման վահանակի կարգավորումներում ավելացրեք դրանք `blockedProviders`-ում․ ընդլայնման մեջ
ոչինչ չի փոխվում։

## Վահանակը VS Code-ի ներդիրում

`omnicopilot.dashboardOpen: "editor"`-ը OmniRoute-ի վահանակը արտաքին դիտարկիչի փոխարեն ցուցադրում է խմբագրիչի ներդիրում՝ Simple Browser-ի միջոցով։ Ներդրումը սերվերում **միացվում է ըստ ցանկության**՝
`DASHBOARD_ALLOW_EMBED=vscode`-ի միջոցով, որի դեպքում HTML էջերը մատուցվում են
`frame-ancestors 'self' vscode-webview:`-ով՝ լռելյայն `frame-ancestors 'none'` +
`X-Frame-Options: DENY`-ի փոխարեն։ API-ի մակերեսը (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) երկու դեպքում էլ պահպանում է խիստ վերնագրերը։

> ⚠️ **Սա կառուցման ժամանակ կիրառվող դրոշակ է, ոչ թե կատարման ժամանակ։** Next.js-ը `headers()`-ը կոմպիլացնում է երթուղիների
> մանիֆեստում, ուստի `next.config.mjs`-ը փոփոխականը կարդում է փաթեթի կառուցման ժամանակ
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`)։
> Արդեն կառուցված սերվերը գործարկելուց առաջ այն արտահանելը ոչինչ չի փոխում․ վերնագրերն արդեն ամրագրված են։

```bash
# փոփոխականը պետք է առկա լինի BUILD հրամանի կատարման ժամանակ
DASHBOARD_ALLOW_EMBED=vscode npm run build        # կամ npm run build:release
npm start
```

| Ինչպես եք տեղադրել         | Կարո՞ղ եք միացնել ներդրումը։                                                                                                                    |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Սկզբնաղբյուրից             | ✅ փոփոխականը սահմանեք կառուցման հրամանում, ինչպես ցուցադրված է վերևում                                                                         |
| `npm install -g omniroute` | ❌ հրապարակված փաթեթը ներառում է նախապես կառուցված փաթեթ․ փոխարենը կառուցեք սկզբնաղբյուրից                                                      |
| Docker պատկեր              | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — Docker Hub-ի նախապես կառուցված պատկերում ներդրումը միացված չէ |

Առանց ներդրումը թույլատրող կառուցման՝ էջը հրաժարվում է շրջանակում ցուցադրվել, ընդլայնումը դա հայտնաբերում է պատասխանի վերնագրերից և անցնում արտաքին դիտարկիչին․ ոչինչ չի խափանվում, և այդ մասին մեկ անգամ հաղորդվում է։
Տե՛ս [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) և
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273) խնդիրը։
