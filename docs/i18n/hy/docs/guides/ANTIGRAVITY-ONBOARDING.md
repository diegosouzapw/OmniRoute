## 1. Antigravity-ն ընդդեմ Antigravity CLI-ի (agy)

Երկու մատակարարներն էլ օգտագործում են **Google-ի նույն բեքենդը**՝ նույն OAuth հաճախորդը, թոքենի թարմացումը, վերջնակետերը և Google հաշիվները։ Տարբերությունն այն է, թե ինչ մոդելներ եք տեսնում։

> Google-ի պաշտոնական համեմատության համար տե՛ս [Antigravity CLI-ի հայտարարությունը](https://antigravity.google/blog/introducing-google-antigravity-cli)։

| Բնութագիր                  | `antigravity` (IDE)                                  | `agy` (CLI)                                                            |
| -------------------------- | ---------------------------------------------------- | ---------------------------------------------------------------------- |
| **Google-ի արտադրանք**     | Antigravity 2.0 / Antigravity IDE                    | Antigravity CLI                                                        |
| **Բեքենդ**                 | Նույն Google Cloud Code API-ն                        | Նույն Google Cloud Code API-ն                                          |
| **OAuth / թոքեն**          | Նույն հաճախորդը, նույն թարմացումը                    | Նույն հաճախորդը, նույն թարմացումը                                      |
| **Մոդելների կատալոգ**      | Ստատիկ, ընտրված ցանկ (կոշտ կոդավորված OmniRoute-ում) | Google-ից իրական ժամանակում հարցվող՝ `:fetchAvailableModels`-ի միջոցով |
| **Claude մոդելներ**        | Sonnet 4.6, Opus 4.6 (յուրաքանչյուրը՝ 4 տարբերակով)  | Sonnet 4.6, Opus 4.6 (յուրաքանչյուրը՝ 4 տարբերակով)                    |
| **Gemini-ի անվանումներ**   | Հստակ պիտակներ (ցածր/միջին/բարձր)                    | Սկզբնաղբյուրի ID-ներ (extra-low/low/agent)                             |
| **Լրացուցիչ մոդելներ**     | `gpt-oss-120b-medium`                                | Կարող է ներառել Google-ի լրացուցիչ մոդելներ                            |
| **Լռելյայն կիրառման դեպք** | IDE ինտեգրում (VS Code, JetBrains)                   | CLI / API հասանելիություն                                              |
| **Քվոտա**                  | Համօգտագործվում է agy-ի հետ (նույն Google հաշիվը)    | Համօգտագործվում է antigravity-ի հետ (նույն Google հաշիվը)              |

**Հասանելի մոդելներ (փորձնականորեն հաստատված, 2026-07-29)**․

- Gemini՝ 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (մտածողության տարբեր մակարդակներով)
- Claude՝ Sonnet 4.6, Opus 4.6 (յուրաքանչյուրը՝ լռելյայն/ցածր/միջին/բարձր տարբերակներով)
- Այլ՝ GPT-OSS 120B Medium
- **Claude Sonnet 5-ը հասանելի ՉԷ**․ աջակցվում են միայն 4.6 տարբերակները

**Ինչու է մոդելների կատալոգը տարբերվում**․ Google-ի CLI-ն «օպտիմալացված է արագության և ցածր վերադիր ծախսերի համար» և «Gemini մոդելների հետ համատեղ օպտիմալացված է» (ըստ Google-ի պաշտոնական բլոգի)։ Վեբ/IDE արտադրանքը «օպտիմալացված է համապարփակության համար»։ CLI-ն օգտագործում է `:fetchAvailableModels`՝ մոդելները դինամիկ կերպով հայտնաբերելու համար, մինչդեռ IDE-ն օգտագործում է ստատիկ, ընտրված ցանկ։

**Գործնականում**․ Gemini մոդելների համար օգտագործեք `agy/` նախածանցը (օրինակ՝ `agy/gemini-3.7-flash-high`)։ Ստատիկ, ընտրված ցանկի համար օգտագործեք `antigravity/`։ Երկուսն էլ դիմում են Google-ի նույն բեքենդին, սակայն ներկայացնում են մոդելների անվանման տարբեր ձևեր։ Քվոտան համօգտագործվում է․ ցանկացած մատակարարի օգտագործումը հաշվարկվում է նույն Google հաշվի սահմանաչափերի նկատմամբ։

## 2. Google One AI Pro. Քվոտաների համակարգ

> Քվոտաների պաշտոնական մանրամասների համար տե՛ս [Antigravity-ի փաստաթղթեր. Պլաններ](https://antigravity.google/docs/plans), իսկ գնային վերջին թարմացումների համար՝ [Antigravity-ի պլանների փոփոխությունները](https://antigravity.google/blog/changes-to-antigravity-plans)։

Google Antigravity-ն օգտագործում է **երկշերտ քվոտա**, որը հիմնված է «Կատարված աշխատանքի» (հաշվողական ծանրաբեռնվածության), այլ ոչ թե հաղորդագրությունների քանակի վրա։

### Երկու շերտերը

| Շերտ                          | Ինչ է դա                             | Թարմացման պարբերաշրջան                                                                                     |
| ----------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| **5-ժամյա փուլ**              | «Կատարված աշխատանքի» անմիջական պաշար | Վերակայվում է աշխատաշրջանի առաջին հարցումից 5 ժամ հետո                                                     |
| **7-օրյա բազային սահմանաչափ** | Շաբաթական խիստ սահմանաչափ            | Գերակայում է 5-ժամյա թարմացման նկատմամբ, եթե սպառվել է. արգելափակում է մինչև հաջորդ 7-օրյա ժամանակահատվածը |

**Ինչպես է հաշվարկվում «Կատարված աշխատանքը»**. Գործակալի ինտենսիվ օգտագործմամբ առաջադրանքները (օրինակ՝ «Վերակառուցել այս ամբողջ պահոցը») շատ ավելի արագ են սպառում քվոտան, քան պարզ առաջադրանքները (օրինակ՝ «Ուղղել այս ֆունկցիան»)։ Սպառումը ցուցադրող իրական ժամանակի կառավարման վահանակ չկա։

### Gemini և ոչ Gemini մոդելներ

- **Gemini մոդելները** (Flash + Pro) ունեն մեկ ընդհանուր հարցումների հաճախականության սահմանաչափ, որը սպառվում է API-ի գնագոյացման հիման վրա։ Եթե Flash-ը Pro-ից 8x ավելի էժան է, դուք ստանում եք 8x ավելի շատ Flash տոկեններ։
- **Ոչ Gemini մոդելները** (Claude, GPT-OSS) ունեն **առանձին** հարցումների հաճախականության սահմանաչափեր։ Դրանք կարող են հասանելի մնալ նույնիսկ այն ժամանակ, երբ Gemini-ն արգելափակված է։

### AI կրեդիտներ (սահմանաչափի գերազանցում)

> Կրեդիտների աշխատանքի մասին տե՛ս [Google One AI կրեդիտներ](https://support.google.com/googleone/answer/14534406)։

Երբ բազային քվոտան սպառվում է՝

- **Երբեք**. Սպասել քվոտայի թարմացմանը. ցուցադրվում է «Բազային մոդելի քվոտան սպառված է»
- **Միշտ**. Ավտոմատ օգտագործել AI կրեդիտները. բազային քվոտայի թարմացումից հետո կրկին անցնում է դրան

Կրեդիտները գնվում են առանձին և նվազեցվում են API-ի ստանդարտ գնագոյացման համաձայն։

### Հիմնական մանրամասներ

- Քվոտան **ընդհանուր է հաշվի մակարդակում**. Antigravity IDE-ում, CLI-ում և OmniRoute-ում օգտագործվող նույն Google հաշիվն օգտվում է քվոտայի մեկ ընդհանուր պաշարից
- Յուրաքանչյուր Google հաշիվ ունի իր անկախ քվոտան. մի քանի հաշիվ = քվոտաների մի քանի պաշար
- AI Pro-ի օգտատերերը հայտնել են շաբաթական բազային սահմանաչափը սպառելու դեպքում **7-օրյա արգելափակումների**, այլ ոչ թե 5-ժամյա վերակայումների մասին (Google-ը հաստատել է, որ մեծ պահանջարկի պայմաններում սա նախատեսված վարքագիծ է)

**Երբ ձեր հաշվի քվոտան սպառվում է**. OmniRoute-ն ավտոմատ կերպով կրկին փորձում է՝ համակցված երթուղում օգտագործելով հաջորդ հասանելի հաշիվը։ Ձեռքով միջամտություն չի պահանջվում։

## 3. Ինչպես ստանալ projectId

Յուրաքանչյուր antigravity/agy կապի համար անհրաժեշտ է Google Cloud Code-ի `projectId`։ Առանց դրա `/v1internal:models` վերջնակետը վերադարձնում է 404։

### Մեթոդ A. Ավտոմատ (խորհուրդ է տրվում)

OmniRoute-ը սա իրականացնում է ավտոմատ կերպով։ Երբ Dashboard OAuth-ի միջոցով ավելացնում եք նոր Google հաշիվ՝

1. OmniRoute-ը թարմացնում է տոկենը
2. Կանչում է `loadCodeAssist`՝ projectId-ն հայտնաբերելու համար
3. Եթե որևէ նախագիծ գոյություն չունի, կանչում է `onboardUser`՝ այն ստեղծելու համար
4. Կրկին կանչում է `loadCodeAssist`՝ նոր ստեղծված projectId-ն ստանալու համար
5. Այն պահպանում է տվյալների բազայում

**Սա աշխատում է հաշիվների մեծ մասի համար**. ձեռքով քայլեր չեն պահանջվում։

### Մեթոդ B. Ձեռքով՝ agy CLI-ի միջոցով

Եթե ավտոմատ հայտնաբերումը ձախողվում է (տե՛ս Բաժին 5-ը՝ իմանալու, թե երբ է դա տեղի ունենում)՝

```bash
# Տեղադրել agy CLI-ն (եթե դեռ տեղադրված չէ)
npm install -g @anthropic-ai/agy

# Մուտք գործել ձեր Google հաշվով
agy login

# Ընտրել այն հաշիվը, որը պետք է գրանցել
# Սա սկսում է Cloud Code-ի գրանցումը և հատկացնում projectId
```

`agy login`-ի հաջող ավարտից հետո թարմացրեք տոկենը OmniRoute Dashboard-ում։ projectId-ն ավտոմատ կերպով կհայտնաբերվի։

### Ինչպես ստուգել

Ստուգեք տվյալների բազան՝

```bash
# OmniRoute կոնտեյների ներսում
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Կամ ստուգեք մատյանները՝

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. OAuth վերահղման URI

### Խնդիրը

Google OAuth-ը պահանջում է վավեր վերահղման URI։ OmniRoute-ի լռելյայն տարբերակն օգտագործում է `http://127.0.0.1:20128/callback` հասցեն (loopback)։ Սա աշխատում է տեղային կառուցումների համար, սակայն **չի աշխատում հեռավար տեղակայումների դեպքում** (օրինակ՝ LAN IP-ի միջոցով հասանելի սերվերի դեպքում)։

Google-ը մերժում է վերահղման URI-ները, որոնք՝

- Օգտագործում են IP հասցեներ (պետք է լինի `.com`, `.org` և այլն վերջավորությամբ դոմեն)
- Չեն համընկնում OAuth հաճախորդի կազմաձևում գրանցված վերահղման URI-ների հետ

### Լուծումը

**Տարբերակ A. Օգտագործել ներկառուցված OAuth հոսքը (լռելյայն)**

- Աշխատում է, երբ OmniRoute եք մուտք գործում `localhost`-ից կամ `127.0.0.1`-ից
- Կազմաձևում չի պահանջվում

**Տարբերակ B. Հատուկ OAuth հավատարմագրեր**

- Ձեր միջավայրում սահմանեք `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web`
- Տրամադրեք Google OAuth-ի ձեր սեփական հավատարմագրերը՝
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Google Cloud Console-ում գրանցեք `https://your-domain.com/callback`-ը որպես թույլատրված վերահղման URI

**Տարբերակ C. Սկզբնական մուտքի համար օգտագործել agy CLI-ն**

- Գործարկեք `agy login` այն համակարգչում, որը մուտք է գործելու OmniRoute
- OAuth հոսքն ավարտվում է տեղային համակարգում, և թոքենները պահպանվում են
- Dashboard-ի միջոցով ներմուծեք կապը OmniRoute

### Սահմանափակումներ

- Հատուկ OAuth հավատարմագրերը պահանջում են դոմենային անուն (Google-ը IP հասցեները որպես վերահղման URI չի ընդունում)
- Եթե դոմեն չունեք, փոխարենն օգտագործեք A կամ C տարբերակը

## 5. Խնդիրների լուծում. երբ ավտոմատ կարգավորումը չի հաջողվում

OmniRoute-ը հաշիվների մեծ մասի համար ավտոմատ կերպով իրականացնում է projectId-ի հայտնաբերումը և սկզբնական գրանցումը։ Երբ դա չի հաջողվում, հիմնական պատճառը սովորաբար հետևյալներից մեկն է՝

### Հաշվի տարածաշրջանն արգելափակված է

**Ախտանիշ**. `agy login`-ը վերադարձնում է «Eligibility check failed: Your current account is not eligible for Antigravity, because it is not currently available in your location.» հաղորդագրությունը։

**Հիմնական պատճառ**. Google հաշիվներն ունեն հետնամասային «Country Association» դաշտ, որը սահմանվում է գրանցման պահին։ agy CLI-ն և Cloud Code API-ն խստորեն ստուգում են այս դաշտը՝ ի տարբերություն վեբ Gemini-ի, որը ստուգում է միայն ձեր ընթացիկ IP-ն։

> Ձեր հաշվին կապված տարածաշրջանը ստուգելու կամ փոխելու համար այցելեք [Google Country Association Form](https://policies.google.com/country-association-form)։

**Ինչու է վեբ Gemini-ն աշխատում, իսկ agy-ն՝ ոչ**.

- Վեբ Gemini / Google One. ստուգում է միայն ընթացիկ IP-ն (պրոքսին անցնում է ստուգումը)
- agy CLI / Cloud Code API. կարդում է հետնամասային Country Association դաշտը (պրոքսին չի օգնում)

**Ուղղում**.

1. ԱՄՆ IP օգտագործելիս այցելեք [Google Country Association Form](https://policies.google.com/country-association-form)
2. Ուղարկեք տարածաշրջանի փոփոխման հարցում (ընտրեք «I live in a different country»)
3. Սպասեք 1-24 ժամ, մինչև Google-ը մշակի հարցումը և էլփոստով ծանուցում ուղարկի
4. Դրանից հետո `agy login`-ը պետք է հաջողվի

### Հաշիվը Cloud Code նախագիծ չունի

**Ախտանիշ**. Մատյաններում ցուցադրվում են `loadCodeAssist returned no project id` և `onboardUser failed (400)` հաղորդագրությունները։

**Հիմնական պատճառ**. Հաշիվը երբեք չի գրանցվել Google Cloud Code-ում, իսկ ավտոմատ սկզբնական գրանցումը չի հաջողվել։

**Ուղղում**. Ձեռքով գործարկեք `agy login`՝ Cloud Code-ի գրանցումը սկսելու համար, այնուհետև OmniRoute Dashboard-ում թարմացրեք թոքենը։

### Թոքենի ժամկետը լրացել է կամ այն հետ է կանչվել

**Ախտանիշ**. Մատյաններում կան 401 սխալներ կամ «Token has expired» հաղորդագրություններ։

**Ուղղում**. Թարմացրեք թոքենը Dashboard → Providers → agy → սեղմեք թարմացման պատկերակը ճանապարհով։ Եթե թարմացման թոքենն ինքնին հետ է կանչվել, անհրաժեշտ կլինի OAuth-ի միջոցով կրկին իսկորոշվել։
