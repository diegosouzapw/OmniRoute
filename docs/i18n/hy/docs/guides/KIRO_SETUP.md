Այս ուղեցույցը նկարագրում է, թե ինչպես ավելացնել Kiro-ի (AWS-ում հոսթավորված AI կոդավորման օգնական) հաշիվներ OmniRoute-ում՝
կենտրոնանալով միաժամանակ մի քանի հաշիվ առանց սեսիաների բախումների գործարկելու վրա։

---

## Նախապատմություն․ ինչու կարող են Kiro-ի հաշիվները բախվել

Kiro-ի բեքենդն օգտագործում է AWS SSO OIDC հաճախորդների գրանցումները՝ ակտիվ սեսիաներին հետևելու համար։
Հիմնական սահմանափակումը հետևյալն է․ **OIDC հաճախորդի յուրաքանչյուր գրանցում միաժամանակ աջակցում է միայն մեկ ակտիվ
սեսիա**։ Երբ երկրորդ սարքը կամ օգտատերը նույն գրանցված հաճախորդով նույնականացում է անցնում,
բեքենդն անվավեր է դարձնում առաջին հաշվի թարմացման թոքենը։

Սա նույն մեխանիզմն է, որը խնդիրներ է առաջացնում `kiro-cli login`-ը մի
սարքում գործարկելիս, որտեղ Kiro-ի մեկ այլ հաշիվ արդեն մուտք է գործել․ նոր մուտքը չեղարկում է
առաջին հաշվի թոքենը։

## Ինչպես է OmniRoute-ը լուծում այս խնդիրը (v3.8.0+)

Սկսած v3.8.0-ից՝ OmniRoute-ը Kiro-ի կապի յուրաքանչյուր ներմուծման ժամանակ կանչում է `registerClient()`-ը (AWS SSO OIDC)։
Սա OmniRoute-ի յուրաքանչյուր կապին տրամադրում է OIDC հաճախորդի առանձին գրանցում։
Քանի որ հաճախորդի յուրաքանչյուր գրանցում անկախ է, մի հաշվի թարմացումը կամ
վերանույնականացումը չի ազդում որևէ այլ հաշվի թարմացման թոքենի վրա։

Մեկուսացումը կիրառվում է թարմացման թոքենի ներմուծման մեթոդների նկատմամբ, իսկ API բանալիով նույնականացումն
ամբողջությամբ խուսափում է OIDC թարմացման սեսիաներից։

| Ներմուծման մեթոդ                                          | Մեկուսացման կարգավիճակ                                                                                                      |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| AWS Builder ID / IDC՝ սարքի կոդի հոսք                     | Մեկուսացված է սարքի կոդի հոսքի ներդրման պահից                                                                               |
| **Թոքենի ներմուծում** (թարմացման թոքենի ձեռքով տեղադրում) | Մեկուսացված է v3.8.0-ից                                                                                                     |
| **Google / GitHub սոցիալական մուտք**                      | Մեկուսացված է v3.8.0-ից                                                                                                     |
| **Ավտոմատ ներմուծում** (kiro-cli SQLite)                  | Մեկուսացված է v3.8.0-ից (SQLite ուղին արդեն մեկուսացված էր, իսկ SSO քեշի պահուստային տարբերակն այժմ նույնպես մեկուսացված է) |
| **API բանալի** (երկարաժամկետ CodeWhisperer բանալի)        | Թարմացման սեսիա չկա․ բանալին վավերացվում և պահվում է որպես bearer հավատարմագիր                                              |

## Տեղափոխման նշում՝ մինչև v3.8.0-ը ստեղծված կապերի համար

Մինչև v3.8.0-ը ներմուծված կապերը չունեն `providerSpecificData`-ում պահվող՝ OIDC հաճախորդի
առանձին գրանցում։ Այս կապերը շարունակում են աշխատել, սակայն օգտագործում են սոցիալական նույնականացման
թարմացման ընդհանուր վերջնակետը, ինչը նշանակում է, որ երկու նման կապ դեռ կարող են միմյանց
անվավեր դարձնել։

**Մեկուսացում ստանալու համար․** ջնջեք հին կապը **Կառավարման վահանակ → Մատակարարներ** բաժնից և
կրկին ներմուծեք այն՝ օգտագործելով աջակցվող ներմուծման հոսքերից որևէ մեկը։ Բոլոր նորաստեղծ կապերն
ավտոմատ կերպով կստանան հաճախորդի առանձին գրանցում։

## Kiro-ի երկու հաշիվ կողք կողքի ավելացնելը

### Նախապայմաններ

- OmniRoute v3.8.0 կամ ավելի նոր տարբերակ։
- Աշխատող Kiro հաշիվ (էլ․ փոստ + գաղտնաբառ, Google կամ GitHub մուտք)։
- Ցանկության դեպքում՝ Kiro-ի երկրորդ հաշիվ։

### Քայլ 1․ ներմուծեք առաջին հաշիվը

1. Բացեք **Կառավարման վահանակ → Մատակարարներ → Ավելացնել մատակարար → Kiro**։
2. Ընտրեք հետևյալ տարբերակներից մեկը․
   - **Թոքենի ներմուծում** — տեղադրեք `aorAAAAAG`-ով սկսվող թարմացման թոքենը։
   - **API բանալի** — տեղադրեք Kiro / CodeWhisperer-ի երկարաժամկետ API բանալին։
   - **Google / GitHub մուտք** — զննարկիչում ավարտեք OAuth հոսքը։
   - **Ավտոմատ ներմուծում** — սեղմեք կոճակը․ OmniRoute-ը հավատարմագրերը կարդում է
     տեղային kiro-cli տվյալների բազայից կամ `~/.aws/sso/cache`-ից։
3. Կապը պահպանվում է։ Թարմացման թոքենի հոսքերն ավտոմատ կերպով գրանցում են առանձին
   OIDC հաճախորդ։ API բանալիով հոսքերը վավերացնում են բանալին AWS-ի միջոցով և թարմացման թոքեն չեն պահում։

### Քայլ 2․ ներմուծեք երկրորդ հաշիվը

Երկրորդ հաշվի համար կրկնեք քայլ 1-ը։ Քանի որ յուրաքանչյուր ներմուծում ստեղծում է OIDC
հաճախորդի առանձին գրանցում, երկու կապերն ամբողջությամբ մեկուսացված են։

### Քայլ 3․ համոզվեք, որ երկու կապերն էլ ակտիվ են

1. **Կառավարման վահանակ → Մատակարարներ** — Kiro-ի երկու կապերն էլ պետք է ցուցադրեն **Ակտիվ** կարգավիճակ։
2. **Կառավարման վահանակ → Առողջական վիճակ** — երկու կապերն էլ պետք է հաջողությամբ անցնեն իրենց թոքենի առողջական վիճակի ստուգումը։

### Քայլ 4․ հաշիվների միջև երթուղավորելու համար օգտագործեք կոմբինացիա

Ստեղծեք կոմբինացիա՝ երկու կապերն էլ որպես թիրախներ նշելով, որպեսզի բեռը հավասարակշռեք դրանց միջև կամ մեկի խափանման դեպքում անցնեք մյուսին․

```
kiro/kiro-dev → kiro/kiro-pro
```

Կոմբինացիայի կազմաձևման համար տե՛ս [FEATURES.md](./FEATURES.md)-ը և երթուղավորման փաստաթղթերը։

## Ձեռնարկության / IDC օգտատերեր

AWS IAM Identity Center (IDC) հաշիվների համար օգտագործեք **AWS Builder ID / IDC սարքի կոդի**
հոսքը՝ **Կառավարման վահանակ → Մատակարարներ → Kiro → Սարքի կոդ** բաժնից։ Սարքի կոդի հոսքը
միշտ լիովին մեկուսացված է եղել։ Այս միացումների համար կրկնակի ներմուծում անհրաժեշտ չէ։

Այն ձեռնարկությունների օգտատերերը, որոնք աշխատում են AWS-ի ոչ լռելյայն տարածաշրջանում, կարող են ներմուծելիս
նշել տարածաշրջանը՝ Import Token API-ի միջոցով.

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/import \
  -H "Content-Type: application/json" \
  -d '{"refreshToken": "aorAAAAAG...", "region": "eu-west-1"}'
```

Եթե `region` դաշտը բաց է թողնված, դրա լռելյայն արժեքը `us-east-1` է։

## API բանալիի ներմուծման հոսք

API բանալիով նույնականացումը նախատեսված է երկարաժամկետ Kiro / AWS CodeWhisperer bearer հավատարմագրերի համար։ Այն
չի օգտագործում OAuth թարմացում, ուստի խուսափում է ընդհանուր OIDC աշխատաշրջանի անվավերացումից։

### Կառավարման վահանակ

1. Բացեք **Կառավարման վահանակ -> Մատակարարներ -> Kiro**։
2. Ընտրեք **API բանալի**։
3. Տեղադրեք API բանալին և, ըստ ցանկության, AWS տարածաշրջանը (լռելյայն՝ `us-east-1`)։
4. OmniRoute-ը վավերացնում է բանալին և պահպանում միացումը։

### API

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/api-key \
  -H "Content-Type: application/json" \
  -d '{"apiKey": "kiro_or_codewhisperer_key", "region": "us-east-1"}'
```

### Ներքին պայմանագիր

API երթուղին վավերացնում է բանալին՝ կանչելով `KiroService.validateApiKey()`-ը, որն
օգտագործում է `ListAvailableProfiles`-ը տարածաշրջանին համապատասխանող CodeWhisperer/Amazon Q
վերջնակետի նկատմամբ և որոշում է `profileArn`-ը։

Պահպանված միացումն օգտագործում է.

```json
{
  "authType": "apikey",
  "providerSpecificData": {
    "authMethod": "api_key",
    "region": "us-east-1",
    "profileArn": "arn:aws:codewhisperer:..."
  }
}
```

Կատարման ընթացքում `KiroExecutor.buildHeaders()`-ը բանալին ուղարկում է որպես
`Authorization: Bearer <key>` և ավելացնում է `tokentype: API_KEY`։ Քվոտայի/պրոֆիլի կանչերն
օգտագործում են նույն նշիչը, որպեսզի AWS-ը bearer-ը դիտարկի որպես երկարաժամկետ API բանալի, այլ ոչ թե
OIDC կամ սոցիալական հասանելիության թոքեն։

## OIDC հաճախորդի ժամկետի ավարտ

AWS SSO OIDC հանրային հաճախորդների ժամկետը սովորաբար ավարտվում է 90 օր հետո
(`clientSecretExpiresAt`)։ Դիտարկելիության նպատակով OmniRoute-ն այս ժամանակային դրոշմանիշը պահպանում է `providerSpecificData`-ում։
Եթե միացումը մոտ 90 օր անց դադարում է թարմացվել, կրկին ներմուծեք
միացումը՝ OIDC հաճախորդի նոր գրանցում ստանալու համար։ Ժամկետի ավարտից հետո ավտոմատ վերագրանցումը
նախատեսված է որպես հետագա բարելավում։

API բանալիով միացումները չունեն OIDC հաճախորդի ժամկետի ավարտ, քանի որ դրանք չեն թարմացվում
AWS SSO OIDC-ի միջոցով։

## Խնդիրների լուծում

### Երկրորդ հաշվից շարունակաբար դուրս է բերվում

- Ստուգեք երկու միացումներն էլ **Կառավարման վահանակ → Մատակարարներ** բաժնում և համոզվեք, որ յուրաքանչյուրի չմշակված
  JSON-ում ցուցադրվում է ոչ null `clientId` (տեսանելի է տեղեկությունների պատկերակի միջոցով)։ Եթե միացումներից որևէ մեկում
  `clientId`-ը բացակայում է, այն ներմուծվել է մինչև v3.8.0-ը․ կրկին ներմուծեք այն։

### Ներմուծումը ձախողվում է՝ ցուցադրելով «Token validation failed»

- Համոզվեք, որ թարմացման թոքենը սկսվում է `aorAAAAAG`-ով։
- Համոզվեք, որ OmniRoute-ը կարող է հասնել `https://oidc.us-east-1.amazonaws.com` հասցեին (կամ կազմաձևված
  տարածաշրջանին)։ Եթե աշխատում եք կորպորատիվ պրոքսիի հետևում, մատակարարի մակարդակի պրոքսի սահմանեք
  **Կառավարման վահանակ → Կարգավորումներ → Պրոքսիներ** բաժնում։

### API բանալիի ներմուծումը ձախողվում է

- Համոզվեք, որ բանալին Kiro / CodeWhisperer API բանալի է, այլ ոչ թե թարմացման թոքեն։
- Համոզվեք, որ AWS տարածաշրջանը համապատասխանում է բանալուն/հաշվին։ `us-east-1`-ը լռելյայն արժեքն է։
- Բանալին պետք է կարողանա կանչել `ListAvailableProfiles`-ը, հակառակ դեպքում OmniRoute-ը չի կարող
  որոշել պահանջվող `profileArn`-ը։

Այլ խնդիրների համար տե՛ս հիմնական [TROUBLESHOOTING.md](./TROUBLESHOOTING.md) ֆայլը։
