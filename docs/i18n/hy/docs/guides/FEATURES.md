## ✨ v3.8.0-ի հիմնական նորությունները

v3.7.x → v3.8.0 ցիկլն ավելացրել է առանց կարգավորման ավտոմատ երթուղավորում, նոր մատակարարներ, OAuth հոսքեր, ավելի բարձր դիմակայունություն և զգալիորեն հարստացված CLI փորձառություն։ Ստորև ներկայացված են գլխավոր հնարավորությունները, իսկ ամբողջական մանրամասները՝ փաստաթղթի հետագա բաժիններում և հղված մասնագրերում։

- 🤖 **Auto Combo / Առանց կարգավորման ավտոմատ երթուղավորում** — օգտագործեք `auto/coding`, `auto/fast`, `auto/cheap`, `auto/offline`, `auto/smart`, `auto/lkgp`, `auto/chaos` նախածանցները։ Աշխատում է 16 գործոնով գնահատման շարժիչի և խնամքով ընտրված 6 **ռեժիմային փաթեթների** հիման վրա (ship-fast, cost-saver, quality-first, offline-friendly, reliability-first, chaos-mode)
- 🆕 **Command Code մատակարար** (#2199) — լիարժեք գրանցում՝ մոդելների կատալոգով և քվոտաների հետևմամբ
- 🆕 **Z.AI մատակարար** — անվճար մակարդակի նոր մատակարար՝ քվոտաների պիտակներով
- 🎬 **KIE մեդիա ընդլայնում** — ընդլայնված կատալոգ, որը ներառում է տեսանյութերի ստեղծման մոդելներ
- 🔐 **Devin նույնականացում** — Desktop-ը ներմուծում է առկա Devin API բանալին, իսկ CLI-ն օգտագործում է տեղային `devin auth login` հավատարմագրերը
- 🆓 **8 նոր անվճար մատակարարներ** — LLM7, Lepton, UncloseAI, BazaarLink, Completions, Enally, FreeTheAi, Command Code
- 🎯 **Մանիֆեստը հաշվի առնող W1–W4 մակարդակային երթուղավորում** — մատակարարների մանիֆեստները կառավարում են մակարդակների կշռված ընտրությունը
- 🎨 **Cursor-ի լիարժեք համարժեքություն OpenAI-ի հետ** — գործիքների կանչեր, հոսքային փոխանցում և աշխատաշրջանների ամբողջական կառավարում
- 📊 **Cursor Pro պլանի օգտագործում** — քվոտաների և ցիկլերի տվյալները ցուցադրվում են մատակարարների սահմանաչափերի վահանակում
- ⚡ **Ծառայության մակարդակների մանրամասնում / Codex-ի արագ մակարդակի վերլուծություն** — սպառման տեսանելիություն՝ ըստ մակարդակի
- 📌 **Աշխատաշրջանին կցված կայուն երթուղավորում** — Codex-ի աշխատաշրջանները հարցումների միջև ամրակցվում են նույն հաշվին
- 🔊 **Inworld TTS բարելավումներ** — ձայների կատալոգներ, հոսքային փոխանցում և ուշացման բարելավումներ
- 🔑 **Kiro-ի առանց ինտերֆեյսի նույնականացում** — մուտք՝ տեղային `kiro-cli` SQLite պահոցի միջոցով, առանց դիտարկիչի անհրաժեշտության
- 📉 **DeepSeek-ի քվոտաների և սահմանաչափերի մշտադիտարկում** — օրական/ամսական օգտագործումը հասանելի է վահանակում
- 🔄 **Վերակայումը հաշվի առնող երթուղավորման ռազմավարություն** — համակցություններն այժմ նախընտրում են այն հաշիվները, որոնց քվոտայի պատուհանը շուտով կվերակայվի
- ⏱️ **`fallbackDelayMs`** և **գործիքների սահմանաչափի դինամիկ հայտնաբերում** — պահուստային տարբերակին անցնելու ավելի ճշգրիտ ժամանակավորում + յուրաքանչյուր մատակարարի համար գործիքների քանակի սահմանաչափեր
- 🔧 **Ֆոնային ռեժիմի աստիճանական նվազեցում (Responses API)** — եթե վերին հոսքի ծառայությունը չի աջակցում ֆոնային հարցմանը, կառուցվածքային նախազգուշացմամբ անցնում է համաժամանակյա ռեժիմի
- 🚦 **429 սխալների դասակարգում՝ ըստ մատակարարի** + `useUpstream429BreakerHints` փոխարկիչ — անջատիչի ավելի ճշգրիտ վարքագիծ՝ վերին հոսքի արագության սահմանափակման հուշումների օգտագործմամբ
- 🩺 **Մոդելների սառեցման վահանակ** — դիտարկեք յուրաքանչյուր մոդելի արգելափակումները և ձեռքով կրկին ակտիվացրեք դրանք UI-ից
- 🔒 **MITM-ի դինամիկ Linux վկայագրերի հայտնաբերում** — աշխատում է Debian/Ubuntu, Fedora/RHEL, Arch և այլ բաշխումներում
- 💻 **CLI բարելավումների փաթեթ** — ավելի քան 20 հրաման, այդ թվում՝ `omniroute providers`, `omniroute combos`, `omniroute doctor`, `omniroute setup`
- 🔍 **Qdrant ներդրման մոդելների հայտնաբերում** — վեկտորային պահոցի մոդելի ավտոմատ զոնդավորում
- 🔑 **API բանալիներ / Bearer բանալիներ՝ `manage` գործողության տիրույթով** — ծրագրային եղանակով կատարեք ադմինիստրատիվ գործողություններ API-ի միջոցով
- 🏥 **Համակցությունների թիրախների առողջության վերլուծություն** + **համակցությունների կառուցվածքային կառուցիչ** — յուրաքանչյուր թիրախի առողջության տվյալներ և UI կառուցիչ՝ `(provider, model, connection)` քայլեր կազմելու համար

## 🎨 Համակցություններ

Ստեղծեք մոդելների երթուղավորման համակցություններ՝ 19 հանրային ռազմավարությամբ՝ առաջնահերթություն, կշռված, շրջանաձև հերթափոխ, համատեքստի փոխանցում, առաջինի լրացում, p2c (երկուսից ընտրության մեթոդ), պատահական, ամենաքիչ օգտագործված, ծախսերի համար օպտիմալացված, վերակայումը հաշվի առնող, վերակայման պատուհան, պահուստային կարողություն, խիստ պատահական, ավտոմատ, lkgp (վերջին հայտնի լավ մատակարար), համատեքստի համար օպտիմալացված, քեշի համար օպտիմալացված, **միաձուլում** (զուգահեռ հարցում է ուղարկում մոդելների խմբին, ապա գնահատող մոդելի միջոցով համադրում է մեկ պատասխան) և **խողովակաշար**։ Յուրաքանչյուր համակցություն շղթայում է մի քանի մոդել՝ ավտոմատ պահուստային անցումով, և ներառում է արագ ձևանմուշներ ու պատրաստվածության ստուգումներ։

Համակցությունների վերջին բարելավումները՝

- **Համակցությունների կառուցվածքային կառուցիչ** — ստեղծեք յուրաքանչյուր քայլ՝ ընտրելով մատակարարը, մոդելը և ճշգրիտ հաշիվը/միացումը
- **Կրկնվող մատակարարների աջակցություն** — նույն համակցությունում բազմիցս օգտագործեք նույն մատակարարին, քանի դեռ `(provider, model, connection)` կորտեժը եզակի է
- **Համակցման թիրախների առողջական վիճակ** — վերլուծության և առողջական վիճակի բաժիններն այժմ տարբերակում են համակցման առանձին թիրախները/քայլերը՝ ամեն ինչ մոդելների տողերի մեջ միավորելու փոխարեն
- **Համակցված մակարդակների հերթականություն** — `defaultTier -> fallbackTier`-ն այժմ ազդում է վերին մակարդակի համակցման քայլերի կատարման/պահուստային անցման հերթականության վրա
- **Համակարգային հուշումների ձևանմուշներ** — համակցման `system_message`-ն աջակցում է սերվերի կողմից մշակվող
  `{{MODEL_ID}}`, `{{PROVIDER_ID}}`, `{{ACCOUNT}}` և `{{FINGERPRINT}}`
  տեղապահներին, որոնք ընդլայնվում են փաստացի երթուղավորված թիրախից՝ ուղարկելուց անմիջապես առաջ։
  Դրանք թույլատրված ցանկով են և ոչ ռեկուրսիվ․ անհայտ տեղապահները մնում են բառացի, դատարկ արժեքներն
  ընդլայնվում են դատարկի, իսկ հաճախորդի համակարգային հուշումները երբեք չեն վերագրվում։ `{{FINGERPRINT}}`-ը
  լուծվում է միայն մատնահետքի վրա հիմնված անվճար մատակարարների համար՝ ամրակցված կամ
  ավտոմատ հերթափոխվող մատնահետքով․ այլ դեպքերում այն ընդլայնվում է դատարկի (օրինակ՝
  մեկ մատնահետք ունեցող միացումների, մատնահետք չօգտագործող մատակարարների դեպքում)։ Ընդլայնումն ընդգրկում է
  ուղարկման ստանդարտ ցիկլը, շրջանաձև հերթափոխը և ամրակցված համատեքստային քեշի աշխատաշրջանները․
  միաձուլման, քաոսի, խողովակաշարի և ներդրված կատարման ռազմավարությունները դեռ չեն ընդլայնում
  տեղապահները։

## ⚙️ Կարգավորումներ

Կարգավորումների համապարփակ վահանակ՝ **7 ներդիրով**․

- **Ընդհանուր** — Համակարգային պահեստ, պահուստային պատճենների կառավարում (տվյալների բազայի արտահանում/ներմուծում)
- **Արտաքին տեսք** — Թեմայի ընտրիչ (մուգ/լուսավոր/համակարգային), գունային թեմաների նախադրվածքներ և անհատական գույներ, առողջական վիճակի մատյանի տեսանելիություն, կողագոտու տարրերի և խմբերի բաժանարարների տեսանելիության կառավարում, վերջնակետի թունելի տեսանելիության կառավարում
- **AI** — AI օգնականի հնարավորություններ, երթուղավորման լռելյայն նախադրվածքներ (ավտոմատ համակցում՝ `auto/coding`, `auto/fast`, `auto/cheap`, `auto/smart`), դատողությունների վերարտադրման քեշ և հմտությունների/հիշողության փոխարկիչներ
- **Անվտանգություն** — API վերջնակետի պաշտպանություն, անհատական մատակարարների արգելափակում, IP զտում, աշխատաշրջանի տեղեկություններ
- **Երթուղավորում** — Մոդելների կեղծանուններ, ֆոնային առաջադրանքների աստիճանական պարզեցում, մանիֆեստը հաշվի առնող մակարդակային երթուղավորում (W1–W4), `fallbackDelayMs`, յուրաքանչյուր աշխատաշրջանի համար ամրակցված երթուղավորում
- **Կայունություն** — Հարցումների հաճախականության սահմանափակման պահպանում, խափանումների կանխիչի կարգաբերում, արգելափակված հաշիվների ինքնաշխատ անջատում, մատակարարների վավերականության ժամկետի մոնիթորինգ, **Համատեքստի փոխանցման** շեմի և ամփոփման մոդելի կազմաձևում, յուրաքանչյուր մատակարարի համար 429 դասակարգում և `useUpstream429BreakerHints` փոխարկիչ, մոդելների սպասաժամանակներ
- **Ընդլայնված** — Կազմաձևման վերասահմանումներ, կազմաձևման աուդիտի հետագիծ, պահուստային աստիճանական պարզեցման ռեժիմ, Responses API-ի ֆոնային ռեժիմի աստիճանական պարզեցում

## 🤖 CLI գործակալներ _(v2.0.11+)_

CLI գործակալների հայտնաբերման և կառավարման վահանակ։ Ցուցադրում է 16 ներկառուցված գործակալների ցանց (Codex, Claude, Goose, OpenClaw, Aider, OpenCode, Cline, ForgeCode, Amazon Q, Open Interpreter, Cursor CLI, Warp, **Windsurf**, **Devin CLI**, **Kimi Coding**, **Command Code**)՝ հետևյալ հնարավորություններով․

- **Տեղադրման կարգավիճակ** — Տեղադրված է / Չի գտնվել՝ տարբերակի հայտնաբերմամբ
- **Արձանագրության պիտակներ** — stdio, HTTP և այլն
- **Անհատական գործակալներ** — Գրանցեք ցանկացած CLI գործիք ձևաթղթի միջոցով (անուն, երկուական գործարկելի ֆայլ, տարբերակի հրաման, գործարկման արգումենտներ)
- **CLI մատնահետքի համապատասխանեցում** — Յուրաքանչյուր մատակարարի համար առանձին փոխարկիչ՝ բնիկ CLI հարցումների ստորագրություններին համապատասխանելու համար՝ նվազեցնելով արգելափակման վտանգը և միաժամանակ պահպանելով պրոքսիի IP հասցեն
- **Devin-ի տեղային նույնականացում** — Devin CLI-ն օգտագործում է `devin auth login`․ դիտարկչի OAuth հոսք չի պահանջվում

## 🔗 Համատեքստի փոխանցում _(v3.5.5+)_

Համակցված ռազմավարություն, որը պահպանում է աշխատաշրջանի շարունակականությունը, երբ հաշվի փոխարկումը տեղի է ունենում զրույցի ընթացքում։ Նախքան ակտիվ հաշվի սպառվելը, OmniRoute-ը հետնապատկերում ստեղծում է փոխանցման կառուցվածքային ամփոփագիր։ Երբ հաջորդ հարցումը մշակվում է այլ հաշվի միջոցով, ամփոփագիրը ներարկվում է որպես համակարգային հաղորդագրություն, որպեսզի նոր հաշիվը շարունակի ամբողջական համատեքստով։

Կարգավորվում է համակցման մակարդակի կամ գլոբալ կարգավորումների միջոցով․

- **Փոխանցման շեմ** — Քվոտայի օգտագործման տոկոսը, որը գործարկում է ամփոփագրի ստեղծումը (լռելյայն՝ 85%)
- **Ամփոփագրի հաղորդագրությունների առավելագույն քանակ** — Վերջին պատմության այն ծավալը, որը պետք է համառոտել
- **Ամփոփման մոդել** — Փոխանցման ամփոփագիրը ստեղծող մոդելի ընտրովի վերասահմանում

Ներկայումս աջակցում է Codex հաշիվների փոխարկմանը։ Տե՛ս [Համատեքստի փոխանցման փաստաթղթերը](../architecture/ARCHITECTURE.md)։

## 🗜️ Հուշման սեղմում _(v3.7.9+)_

«Համատեքստ և քեշ» բաժինն այժմ տրամադրում է առանձին էջեր Caveman-ի, RTK-ի և սեղմման համակցումների համար․

- **Caveman** — լեզուն հաշվի առնող կանոնների փաթեթներ, նախադիտում, ելքային ռեժիմի կառավարում և վերլուծություն
- **RTK** — հրամանները հաշվի առնող սեղմում shell-ի, git-ի, թեստերի, կառուցման, փաթեթների, Docker-ի, ենթակառուցվածքի, JSON-ի և կանչերի շղթայի արտածման համար
- **Սեղմման համակցումներ** — անվանակոչված խողովակաշարեր, օրինակ՝ `rtk -> caveman`, որոնք վերագրվում են երթուղավորման համակցումներին․ երբ երկու շարժիչներն էլ կիրառվում են, լռելյայն համակցված հաշվարկն ապահովում է միջինում `~89%`, իսկ համապատասխան համատեքստի դեպքում՝ `78-95%` խնայողություն
- **Չմշակված արտածման վերականգնում** — սեղմման ձախողումները վրիպազերծելու համար RTK-ի չմշակված արտածմանը հղող ընտրովի, գաղտնազերծված տվյալները քողարկող ցուցիչներ

Տե՛ս [Սեղմման ուղեցույցը](../compression/COMPRESSION_GUIDE.md), [RTK սեղմումը](../compression/RTK_COMPRESSION.md) և
[Սեղմման շարժիչները](../compression/COMPRESSION_ENGINES.md)։

## 🛡️ Պրոքսիի պաշտպանվածության ուժեղացում _(v3.5.5+)_

Պրոքսիի կազմաձևման համապարփակ պարտադրում հարցումների մշակման ամբողջ շղթայում․

- **Թոքենի վիճակի ստուգում** — OAuth-ի հետնապատկերային թարմացումն այժմ յուրաքանչյուր կապի համար որոշում է պրոքսիի կազմաձևումը՝ կանխելով խափանումները պրոքսի պահանջող միջավայրերում
- **API բանալու վավերացում** — Մատակարարի բանալու վավերացումը (`POST /api/providers/validate`) երթուղավորվում է `runWithProxyContext`-ի միջոցով՝ պահպանելով մատակարարի մակարդակի և գլոբալ պրոքսիի կարգավորումները
- **undici դիսպետչերի ուղղում** — Պրոքսի դիսպետչերներն օգտագործում են undici-ի սեփական fetch իրականացումը՝ Node-ի ներկառուցված fetch-ի փոխարեն, ինչը վերացնում է `invalid onRequestStart method` սխալները Node.js 22-ում
- **Node.js տարբերակի հայտնաբերում** — Մուտքի էջը կանխարգելիչ կերպով հայտնաբերում է Node.js-ի անհամատեղելի տարբերակները (24+) և ցուցադրում է նախազգուշացման պաստառ՝ Node 22 LTS-ն օգտագործելու հրահանգներով

## 🔧 OAuth միջավայրի վերականգնում _(v3.6.1+)_

OAuth մատակարարների համար մեկ սեղմումով «Վերականգնել միջավայրը» գործողություն, որը վերականգնում է բացակայող միջավայրի փոփոխականները և շտկում նույնականացման խափանված վիճակը։ Հասանելի է `Կառավարման վահանակ → Մատակարարներ → [OAuth մատակարար] → Վերականգնել միջավայրը` ուղով։ Ավտոմատ հայտնաբերում և վերականգնում է՝

- Բացակայող OAuth հաճախորդի հավատարմագրերը
- Միջավայրի ֆայլի վնասված գրառումները
- Պահուստային պատճենի ուղու մաքրումը

## 🖥️ Սեղանադիր հավելված

Բնիկ Electron սեղանադիր հավելված Windows-ի, macOS-ի և Linux-ի համար։ Գործարկեք OmniRoute-ը որպես ինքնուրույն հավելված՝ համակարգային սկուտեղի ինտեգրմամբ, անցանց աջակցությամբ, ավտոմատ թարմացմամբ և մեկ սեղմումով տեղադրմամբ։

Հիմնական հնարավորություններ՝

- Սերվերի պատրաստ լինելու պարբերական ստուգում (սառը մեկնարկի ժամանակ դատարկ էկրան չի ցուցադրվում)
- Համակարգային սկուտեղ՝ պորտերի կառավարմամբ
- Բովանդակության անվտանգության քաղաքականություն
- Մեկ օրինակի գործարկման արգելափակում
- Ավտոմատ թարմացում վերագործարկման ժամանակ
- Հարթակից կախված միջերես (macOS-ի լուսացույցային կոճակներ, Windows/Linux-ի լռելյայն վերնագրագոտի)
- Electron-ի կառուցման փաթեթավորման ուժեղացված պաշտպանություն — ինքնուրույն փաթեթում սիմվոլիկ հղումով միացված `node_modules`-ը հայտնաբերվում և մերժվում է նախքան փաթեթավորումը՝ կանխելով գործարկման ժամանակ կախվածությունը կառուցման համակարգչից (v2.5.5+)
- **Կոռեկտ անջատում** — Electron-ի `before-quit`-ը մաքուր կերպով անջատում է Next.js-ը՝ կանխելով SQLite WAL տվյալների բազայի կողպումները (v3.6.2+)

📖 Ամբողջական փաստաթղթերի համար տե՛ս [`electron/README.md`](../../electron/README.md)։

## 🌐 V1 WebSocket կամուրջ _(v3.6.6+)_

OmniRoute-ն այժմ աջակցում է **OpenAI-ի հետ համատեղելի WebSocket հաճախորդներին** `/v1/ws` արդիականացման վերջնակետի միջոցով։ Հատուկ `scripts/dev/v1-ws-bridge.mjs` սերվերը փաթաթում է Next.js-ը և WS կապերը արդիականացնում՝ վերածելով լիարժեք երկկողմանի հոսքային աշխատաշրջանների։ Նույնականացման համար օգտագործվում է նույն API բանալին կամ աշխատաշրջանի cookie-ն, ինչ HTTP հարցումների դեպքում։

Հիմնական վարքագծեր՝

- WS արդիականացումը վավերացվում է `src/lib/ws/handshake.ts`-ի միջոցով՝ նախքան կապի հաստատումը
- Աշխատաշրջանի փակման կամ վերին հոսքի սխալի դեպքում հոսքերը կոռեկտ ավարտվում են
- Միաժամանակ աշխատում է գոյություն ունեցող HTTP+SSE հոսքային ուղու հետ

## 🔑 Համաժամացման թոքեններ և կազմաձևման փաթեթ _(v3.6.6+)_

Բազմասարքային և արտաքին օպերատորների հասանելիությունն այժմ հնարավոր է **սահմանափակված համաժամացման թոքենների** միջոցով.

- **`POST /api/sync/tokens`** — Թողարկել նոր համաժամացման թոքեն (սահմանափակված՝ գործողության ժամկետի կամընտրական ավարտով)
- **`DELETE /api/sync/tokens/:id`** — Հետ կանչել թոքենը
- **`GET /api/sync/bundle`** — Ներբեռնել բոլոր ոչ զգայուն կարգավորումների տարբերակավորված, ETag-ով նույնականացվող JSON պատկերը (գաղտնաբառերը թաքցված են)

Կազմաձևման փաթեթը ստեղծվում է `src/lib/sync/bundle.ts`-ի միջոցով։ Սպառողները համեմատում են պատասխանի `ETag` վերնագիրը՝ փոփոխությունները հայտնաբերելու համար՝ առանց ամբողջ օգտակար բեռը կրկին ներբեռնելու։

## 🧠 GLM Thinking նախակարգավորում _(v3.6.6+)_

**GLM Thinking (`glmt`)**-ն այժմ գրանցված լիարժեք մատակարար է՝ առավելագույնը 65 536 ելքային թոքենով, մտածողության 24 576 թոքենի բյուջեով, լռելյայն 900 վրկ ժամանակասպառմամբ, Claude-ի հետ համատեղելի API ձևաչափով և GLM ընտանիքի հետ օգտագործման համատեղ համաժամացմամբ։

**Թոքենների հիբրիդային հաշվարկը** նույնպես հասանելի է v3.6.6-ում. երբ Claude-ի հետ համատեղելի մատակարարը տրամադրում է `/messages/count_tokens`, OmniRoute-ը մեծ հարցումներից առաջ կանչում է այն՝ ձախողման դեպքում սահուն անցնելով մոտավոր գնահատման։

## 🛡️ Անվտանգ ելքային հարցումներ և SSRF պաշտպանություն _(v3.6.6+)_

Մատակարարների վավերացման և մոդելների հայտնաբերման բոլոր կանչերն այժմ անցնում են երկշերտ ելքային պաշտպանության միջոցով.

1. **URL պաշտպանություն** (`src/shared/network/outboundUrlGuard.ts`) — Արգելափակում է մասնավոր/loopback/link-local IP տիրույթները՝ նախքան սոկետի բացվելը։
2. **Անվտանգ հարցման փաթաթիչ** (`src/shared/network/safeOutboundFetch.ts`) — Կիրառում է URL պաշտպանությունը, նորմալացնում ժամանակասպառումները և ժամանակավոր սխալների դեպքում կրկին փորձում՝ էքսպոնենցիալ հետաձգմամբ։

Պաշտպանության խախտումները ներկայացվում են որպես HTTP 422 (`URL_GUARD_BLOCKED`) և `providerAudit.ts`-ի միջոցով գրանցվում են համապատասխանության աուդիտի մատյանում։

## 🔄 Սպասման ժամանակահատվածը հաշվի առնող կրկնափորձեր _(v3.6.6+)_

Զրույցի հարցումներն այժմ **ինքնաբերաբար կրկին փորձվում են**, երբ վերին մակարդակի մատակարարը վերադարձնում է մոդելին հատուկ սպասման ժամանակահատված։ Կազմաձևվում է `REQUEST_RETRY`-ի (լռելյայն՝ 2) և `MAX_RETRY_INTERVAL_SEC`-ի (լռելյայն՝ 30 վրկ) միջոցով։ Հարցումների հաճախականության սահմանափակման վերնագրերի ուսուցումը բարելավվել է `x-ratelimit-reset-requests`-ի, `x-ratelimit-reset-tokens`-ի և `Retry-After`-ի համար. յուրաքանչյուր մոդելի սպասման ժամանակահատվածի վիճակը տեսանելի է Կայունության վահանակում։

## 📋 Համապատասխանության աուդիտ v2 _(v3.6.6+)_

Աուդիտի մատյանը ընդլայնվել է կուրսորի վրա հիմնված էջավորմամբ, հարցման համատեքստի հարստացմամբ (հարցման ID, օգտատիրոջ գործակալ, IP), նույնականացման կառուցվածքավորված իրադարձություններով, տարբերությունների համատեքստ պարունակող մատակարարների CRUD իրադարձություններով և SSRF-ի կողմից արգելափակված վավերացման գրանցմամբ։ Նոր իրադարձությունները ստեղծվում են `src/lib/compliance/providerAudit.ts`-ի կողմից։
