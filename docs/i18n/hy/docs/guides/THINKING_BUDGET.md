> **Կառավարման վահանակ:** Կարգավորումներ → **AI** → Մտածողության բյուջե  
> **API:** `GET` / `PUT` `/api/settings/thinking-budget`  
> **Աղբյուր:** `open-sse/services/thinkingBudget.ts`

Մտածողության բյուջեն վերահսկում է՝ արդյոք OmniRoute-ը մատակարարներին ուղարկելու ճանապարհին **վերագրում է հաճախորդի մտածողության/դատողության պարամետրերը**։ Այն **չի** միացնում կամ անջատում սեղմումը, երթուղավորումը կամ հուշումների քեշը։

## Ռեժիմներ

| Ռեժիմ                        | Ինչ է անում OmniRoute-ը                                                                                                         | Երբ օգտագործել                                                                                                                                                                                               |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **`passthrough`** (լռելյայն) | Անփոփոխ է թողնում հաճախորդի դաշտերը (`reasoning`, `reasoning_effort`, Claude-ի `thinking`, Gemini-ի `thinking_config` և այլն)։  | **Codex / Desktop / ցանկացած հաճախորդ, որը պետք է վերահսկի ջանքի մակարդակը և դատողության ամփոփումները։** Պարտադիր է մտածողության տեսանելի վահանակների համար, երբ հաճախորդը պահանջում է `reasoning.summary`։  |
| **`auto`**                   | Դեպի վերին հոսք ուղարկելուց առաջ հարցման մարմնից **հեռացնում է բոլոր** մտածողության/դատողության դաշտերը։                        | Միայն այն դեպքում, երբ միտումնավոր ցանկանում եք, որ **մատակարարը** սահմանի լռելյայն արժեքները, և ձեզ պետք չէ հաճախորդի կողմից կառավարվող մտածողություն։ **Չի** նշանակում «մտածողությունն ավտոմատ ցուցադրել»։ |
| **`custom`**                 | Յուրաքանչյուր հարցման մեջ սահմանում է մտածողության տոկենների ֆիքսված բյուջե՝ վերագրելով առկա արժեքը։                            | Բոլոր հարցումների համար մտածողության տոկենների խիստ սահմանաչափ սահմանելու նպատակով։                                                                                                                          |
| **`adaptive`**               | Մասշտաբավորում է բյուջեն՝ ելնելով ջանքի բազային մակարդակից, հաղորդագրությունների քանակից, գործիքներից և հուշման երկարությունից։ | Տոկենների ճկուն կառավարում՝ առանց հաճախորդի մտադրությունն ամբողջությամբ հեռացնելու։                                                                                                                          |

### Ինչ է հեռացնում `auto`-ն

Երբ ռեժիմը `auto` է, `stripThinkingConfig()`-ը, ի թիվս այլ դաշտերի, ջնջում է՝

- OpenAI / Responses՝ `reasoning`, `reasoning_effort`
- Claude՝ `thinking`, ինչպես նաև `output_config.effort`, երբ այն առկա է
- Gemini՝ `generationConfig.thinking_config` / `thinkingConfig`

Եթե հաճախորդը (օրինակ՝ Codex Desktop-ը) ուղարկել է `reasoning: { effort: "ultra", summary: "detailed" }`, ապա **auto-ն հեռացնում է այդ օբյեկտը**։ Վերին հոսքի մատակարարը կարող է, այնուամենայնիվ, հաշվարկել որոշ դատողության տոկեններ, սակայն հաճախ վերադարձնում է դատողության **դատարկ կամ միայն գաղտնագրված** տարրեր, ուստի միջերեսը չի ցուցադրում մտածողության օգտակար հոսք։

## Ինչ **չէ** սա

| Գործառույթ                                                 | Փոխկապակցվածություն                                                                                                                                                      |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Սեղմում** (Caveman, RTK, stacked, …)                     | Առանձին մշակման շղթա է։ Աշխատում է մտածողության բյուջեի յուրաքանչյուր ռեժիմում։                                                                                          |
| **Հուշումների / իմաստային քեշ**                            | Առանձին է։ Մտածողության բյուջեի ռեժիմը չի ազդում դրա վրա։                                                                                                                |
| **Համակցված երթուղավորում / պահուստային ուղիներ**          | Առանձին են։ Ազդեցություն չեն կրում։                                                                                                                                      |
| **API բանալու տոկենների սահմանաչափեր / ծախսերի բյուջեներ** | Առանձին են։ Ազդեցություն չեն կրում։                                                                                                                                      |
| **Դատողության վերարտադրման քեշ**                           | Բազմափուլ զրույցներում խիստ մատակարարների համար կրկնակի ներարկում է (DeepSeek, Kimi, Qwen-thinking, …)։ Նույնը չէ, ինչ Desktop-ի «ցուցադրել մտածողությունը» գործառույթը։ |
| **`encrypted_content`-ի վերծանում**                        | **Անհնար է։** OpenAI/Codex-ի մասնավոր դատողության բլոբներն անթափանց են։ OmniRoute-ը երբեք չի վերծանում դրանք (#7095 / #7176 / #7304)։                                    |

## Տեսանելի մտածողություն (Codex / Responses հաճախորդներ)

Որպեսզի հաճախորդը ցուցադրի մտածողության տեքստը, անհրաժեշտ են ստորև նշված **բոլոր** պայմանները.

1. Thinking Budget ռեժիմը = **`passthrough`** (կամ `custom`/`adaptive`, որը դեռևս ամփոփման հարցումները բավականաչափ անփոփոխ է թողնում ձեր օգտագործած ուղու համար)։
2. Հաճախորդը պահանջում է ամփոփում, օրինակ՝ Codex-ի `model_reasoning_summary = "detailed"` / `auto` (ոչ թե `none`)։
3. Վերին մակարդակի մատակարարն իրականում հոսքային եղանակով ուղարկում է `response.reasoning_summary_text.*` (կամ տարրի մեջ առկա է ոչ դատարկ `reasoning.summary`)։

Եթե ստանում եք միայն «կոդավորված մասնավոր դատողություն», ապա՝

- ռեժիմը եղել է **`auto`** (հաճախորդի հարցումը հեռացվել է), կամ
- վերին մակարդակի մատակարարը վերադարձրել է `encrypted_content`՝ առանց ամփոփման տեքստի (մատակարարի սահմանափակում. OmniRoute-ը կարող է ցուցադրել միայն տեղապահ, ոչ թե բաց տեքստ)։

## API-ի օրինակներ

```bash
# Ընթերցում
curl -sS https://localhost:20128/api/settings/thinking-budget \
  -H "Authorization: Bearer $OMNIROUTE_TOKEN"

# Խորհուրդ է տրվում Codex / Desktop-ում մտածողության տեսանելիության համար
curl -sS -X PUT https://localhost:20128/api/settings/thinking-budget \
  -H "Authorization: Bearer $OMNIROUTE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"mode":"passthrough","customBudget":10240,"effortLevel":"medium"}'
```

Սխեմա (`updateThinkingBudgetSchema`)՝ `mode` ∈ `passthrough|auto|custom|adaptive`, ոչ պարտադիր՝ `customBudget`, `effortLevel`, `baseBudget`, `complexityMultiplier`։

### Պահպանում / վերագործարկում

Արժեքը պահվում է կարգավորումների `thinkingBudget` բանալու ներքո և բեռնվում է գործընթացի մեկնարկի ժամանակ (`hydrateThinkingBudgetConfig`)։ DB-ի կամ որոշ ոչ API ուղիների միջոցով այն փոխելուց հետո **վերագործարկեք OmniRoute գործընթացը**, որպեսզի հիշողության մեջ գտնվող եզակի օրինակը համապատասխանի սկավառակի տվյալներին։

## Օպերատորի ստուգացանկ

- [ ] Codex / Desktop-ի օգտատերեր՝ ռեժիմը = **passthrough**
- [ ] Եթե ցանկանում եք խնայել թոքենները **հաղորդագրությունների** վրա, սեղմումը թողեք միացված՝ մտածողությունը հեռացնելու փոխարեն
- [ ] Մի՛ ակնկալեք, որ `auto`-ն «ավելի շատ մտածողություն կցուցադրի»
- [ ] Միայն կոդավորված ամփոփումները **մատակարարի** վարքագիծ են. passthrough-ը չի կարող դրանք վերծանել
