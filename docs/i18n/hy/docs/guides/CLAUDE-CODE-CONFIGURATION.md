Ուղղորդեք **Claude Code** CLI-ը (`claude`) դեպի OmniRoute՝ տեղային կամ հեռակա VPS-ում՝
յուրաքանչյուր մոդելի համար առանձին պրոֆիլներով՝ Codex-ի կարգավորումների նմանությամբ։

---

## Արագ մեկնարկ

```bash
# Գործարկել Claude Code-ը տեղային OmniRoute-ի հետ (ակտիվ համատեքստը հայտնաբերվում է ավտոմատ)
omniroute launch

# Հեռակա OmniRoute-ի հետ (`omniroute connect <host>`-ից հետո սա կատարվում է ավտոմատ)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# Ստեղծել յուրաքանչյուր մոդելի համար առանձին պրոֆիլներ, ապա գործարկել դրանցից մեկը
omniroute setup-claude            # գրանցում է ~/.claude/profiles/<name>/settings.json-ում
omniroute launch --profile glm52  # Claude Code՝ OmniRoute-ի միջոցով glm/glm-5.2-ն օգտագործելով
```

---

## Ինչպես է Claude Code-ը միանում դարպասին

Claude Code-ն օգտագործում է **Anthropic Messages API**-ն և ուղղորդվում է դեպի հատուկ
վերջնակետ՝ միջավայրի փոփոխականների միջոցով (այն չունի `--base-url` դրոշակ).

| Փոփոխական                                    | Նպատակ                                                                                                         |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `ANTHROPIC_BASE_URL`                         | Դարպասի արմատային URL-ը (Claude Code-ը կցում է `/v1/messages`)։ **Առանց `/v1` վերջածանցի։**                    |
| `ANTHROPIC_AUTH_TOKEN`                       | Ուղարկվում է որպես `Authorization: Bearer …`՝ օգտագործեք ձեր OmniRoute հասանելիության թոքենը / API բանալին     |
| `ANTHROPIC_API_KEY`                          | Այլընտրանք՝ ուղարկվում է որպես `x-api-key`։ Եթե երկուսն էլ սահմանված են, գերակայում է `ANTHROPIC_AUTH_TOKEN`-ը |
| `ANTHROPIC_MODEL`                            | Պարտադրել որոշակի մոդելի օգտագործումը (գերակայում է `/model` ընտրիչի լռելյայն արժեքի նկատմամբ)                 |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` → ներկառուցված `/model` ընտրիչը `/v1/models`-ից ցուցադրում է `claude*`/`anthropic*` մոդելները              |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`              | Սահմանափակում է յուրաքանչյուր պատասխանի ելքային թոքենների քանակը (օրինակ՝ `65536`)                             |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`            | Ավտոմատ սեղմման թոքենային շեմը                                                                                 |

> Միջավայրի փոփոխականները կարդացվում են **մեկ անգամ՝ գործարկման պահին**․ դրանք փոխելուց հետո վերագործարկեք Claude Code-ը։

`omniroute launch`-ը սահմանում է այս ամենը ձեր փոխարեն․ այն ակտիվ համատեքստից
որոշում է բազային URL-ը և թոքենը (այդ պատճառով `omniroute connect <vps>`-ից հետո
`omniroute launch`-ը պարզապես աշխատում է), ստուգում է սերվերի աշխատանքային վիճակը
և կատարում `claude`-ը։

## Հայտնաբերման այլանուններ՝ ոչ Claude մոդելները `/model` ընտրիչում ցուցադրելու համար

Claude Code-ի դարպասային մոդելների հայտնաբերումը ցուցադրում է միայն այն id-ները,
որոնք սկսվում են `claude` կամ `anthropic`-ով, ուստի
`CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`-ի դեպքում ներկառուցված `/model`
ընտրիչը սովորաբար ցուցադրում է OmniRoute-ի **միայն** Claude/Anthropic մոդելները․
`kimi/kimi-k2.6`-ը կամ `glm/glm-5.2`-ը երբեք չի հայտնվում, թեև երթուղավորումը
ճիշտ է աշխատում։

OmniRoute-ը կարող է արտացոլել ցանկացած միացված մոդել (և համակցություն)՝
`claude/…` id-ի ներքո, որպեսզի այն անցնի այդ զտիչը և հայտնվի ընտրիչում.

```
kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<combo "custo-otimizado"> →  claude/combo/custo-otimizado
```

Երբ Claude Code-ում ընտրում եք դրանցից մեկը, OmniRoute-ը երթուղավորումից առաջ
հեռացնում է `claude/` փաթեթավորումը՝ վերականգնելով իրական id-ն, իսկ իսկական
`claude/<real-claude-model>` id-ն (իրական Claude OAuth մատակարարը) միշտ մնում է
անփոփոխ։

**Սա լռելյայն անջատված է** և կառավարվում է եռաստիճան դարպասով (գերակայում է
ամենահատուկ մակարդակը), որպեսզի սովորական OmniRoute-ը չկրկնապատկի իր կատալոգը
Claude Code չօգտագործող հաճախորդների համար.

| Մակարդակ  | Որտեղ                                                                                         |
| --------- | --------------------------------------------------------------------------------------------- |
| Մոդել     | Մատակարարի մանրամասների էջ → յուրաքանչյուր մոդելի «Ցուցադրել Claude Code-ում» փոխարկիչ        |
| Մատակարար | Մատակարարի մանրամասների էջ → մատակարարի մակարդակի փոխարկիչ (ներառում է նրա բոլոր մոդելները)   |
| Ընդհանուր | Կարգավորումներ → Գործառույթների դրոշակներ → `EXPOSE_CC_DISCOVERY_ALIASES` (լռելյայն անջատված) |

`EXPOSE_CC_DISCOVERY_ALIASES` միջավայրի փոփոխականը հարկադրաբար միացնում է ընդհանուր
մակարդակը և գերակայում է կառավարման վահանակի վերասահմանման նկատմամբ (Գործառույթների
դրոշակների էկրանը ցուցադրում է «ակտիվ է միջավայրի փոփոխականի միջոցով» նշում, երբ
դա այդպես է)։ Մատակարարի և մոդելի մակարդակի փոխարկիչներն այնուհետև ավելի են
հստակեցնում կարգավորումը․ օրինակ՝ ընդհանուր մակարդակն անջատված է + Kimi
մատակարարը միացված է՝ ցուցադրվում են միայն Kimi-ի մոդելները։

> ⚠️ **Պատուհանի անհամապատասխանություն ոչ Claude մոդելների դեպքում։** Claude Code-ը
> ենթադրում է 200K համատեքստային պատուհան ցանկացած անծանոթ id-ի համար (այն չի
> կարող `/v1/models`-ից կարդալ իրական պատուհանը)։ Ավելի մեծ պատուհան ունեցող
> մոդելի համար (օրինակ՝ Kimi K2-ի 256K-ը) `CLAUDE_CODE_AUTO_COMPACT_WINDOW`-ը
> սահմանեք մոդելի իրական պատուհանից փոքր արժեքով, որպեսզի ավտոմատ սեղմումը
> ժամանակից շուտ չգործարկվի։ Վերևում ստեղծված պրոֆիլներն արդեն կատարում են դա
> յուրաքանչյուր մոդելի համար։

## Կառավարման վահանակի սկզբնական կարգավորման բլոկը

Claude գործիքի քարտը (**Կառավարման վահանակ → CLI Code**) ցուցադրում է այս օրինակի համար ճշգրիտ `settings.json` հատվածը՝
հայտնաբերման այլանվան տեղեկությունների կոճակի կողքին՝ պատճենման կոճակով․

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}
```

Հիմնական URL-ը քարտի կողմից որոշված հասցեն է (ներառյալ ձեր մուտքագրած հատուկ վերասահմանումը), որն արդեն
նորմալացված է՝ առանց `/v1` վերջածանցի և առանց վերջում շեղագծի։ **Բանալին երբեք չի ցուցադրվում**․ բլոկը պարունակում է
տեղապահ, ուստի էկրանի նկարը կամ տեղադրված հատվածը չի կարող արտահոսել այն։ Փոխարինեք այն ձեր բանալիով։

Նույն `env` բլոկի ներքո ավելացրեք `CLAUDE_CODE_AUTO_COMPACT_WINDOW` ցանկացած մոդելի համար, որի իրական
համատեքստային պատուհանը 200K չէ․ Claude Code-ը 200K է ենթադրում իր կողմից չճանաչված յուրաքանչյուր id-ի համար, ուստի
հակառակ դեպքում ավտոմատ սեղմումն աշխատում է սխալ պահին (տես նախորդ բաժնի նախազգուշացումը)։
Հատվածի կառուցիչը նույնպես ընդունում է այդ արժեքը, ուստի նպատակային մոդելի պատուհանը ճանաչող կանչողը
կարող է այն ուղղակիորեն արտածել։

Աղբյուր՝ `src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet` (մաքուր
կառուցիչ, միավորային թեստերով), որը ցուցադրվում է `ClaudeGatewayOnboardingBlock`-ի կողմից։

## Պրոֆիլներ (`CLAUDE_CONFIG_DIR`)

Claude Code-ը **չունի ներկառուցված պրոֆիլային ֆայլեր** (ի տարբերություն Codex-ի `~/.codex/<name>.config.toml`-ի)։
Ընդունված մեխանիզմը `CLAUDE_CONFIG_DIR`-ն է՝ առանձին կազմաձևման գրացուցակ յուրաքանչյուր
պրոֆիլի համար, որոնցից յուրաքանչյուրն ունի իր սեփական `settings.json`-ը, հավատարմագրերը, պատմությունը և քեշը։

`omniroute setup-claude`-ը ստանում է գործող `/v1/models` կատալոգը և յուրաքանչյուր մոդելի համար գրում է մեկ
պրոֆիլ `~/.claude/profiles/<name>/settings.json` հասցեում՝ կրկին օգտագործելով
**նույն անունները, ինչ `setup-codex`-ը** (`glm52`, `kimi-k27`, `deepseek-pro`, …)․

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}
```

> **Նույնականացման թոքենը երբեք չի գրվում պրոֆիլում։** Գործարկեք
> `omniroute launch --profile <name>` հրամանով (այն ակտիվ համատեքստից ներդնում է `ANTHROPIC_AUTH_TOKEN`-ը),
> կամ ինքներդ արտահանեք `ANTHROPIC_AUTH_TOKEN`-ը և գործարկեք
> `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude`։

**Ավտոմատ համաժամացում՝ մոդելների հայտնաբերումից հետո (ըստ ցանկության)։** OmniRoute-ը կարող է ավտոմատ վերաստեղծել այս նույն
`~/.claude/profiles/<name>/settings.json` ֆայլերը, երբ մատակարարի մոդելների
համաժամացումը փոխում է գործող կատալոգը, որպեսզի նոր կամ վերանվանված մոդելները պրոֆիլներ ստանան՝ առանց հրամանը
կրկին գործարկելու։ Այն **լռելյայն անջատված է**․ միացրեք այն **CLI Code կառավարման վահանակից** («CLI պրոֆիլների
ավտոմատ համաժամացում» → Claude Code) կամ սահմանեք `OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true` (այն նաև հաշվի է առնում
`CLI_ALLOW_CONFIG_WRITES`-ը, որը լռելյայն միացված է)։ Միացված լինելու դեպքում այն գրում է միայն պրոֆիլային ֆայլերը և երբեք
չի փոխում ձեր ակտիվ կամ լռելյայն Claude կազմաձևումը, նույնականացումը կամ `~/.claude/settings.json`-ը։

### Պրոֆիլների ստեղծում և օգտագործում

```bash
# Տեղային OmniRoute
omniroute setup-claude

# Հեռակա VPS (VPS-ի URL-ը ներառում է յուրաքանչյուր պրոֆիլում)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# Միայն որոշ մատակարարներ
omniroute setup-claude --only glm,kimi

# Նախադիտում՝ առանց գրելու
omniroute setup-claude --dry-run

# Պրոֆիլի գործարկում
omniroute launch --profile kimi-k27
```

## Մոդելների մակարդակներ (ըստ ցանկության)

Claude Code-ը հարցումներն ուղղորդում է ըստ հնարավորությունների մակարդակների։ Եթե ցանկանում եք յուրաքանչյուր մակարդակի համար օգտագործել տարբեր մատակարարներ, env /
կարգավորումների միջոցով յուրաքանչյուր մակարդակ համապատասխանեցրեք OmniRoute մոդելի հետ․

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm/glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="kmc/kimi-k2.6"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="glm/glm-4.7-flash"
```

Հակառակ դեպքում ամեն ինչի համար օգտագործվում է մեկ `ANTHROPIC_MODEL` (որը սահմանում են պրոֆիլները)։

## Հեռավար ռեժիմ

Երբ գործարկեք `omniroute connect <host>`-ը (տե՛ս
[Հեռավար ռեժիմ](./REMOTE-MODE.md)), `omniroute launch`-ը և `omniroute setup-claude`-ը
ինքնաբերաբար կթիրախավորեն այդ հեռավար սերվերը և կօգտագործեն դրա սահմանափակված հասանելիության թոքենը՝ առանց
լրացուցիչ դրոշակների։ Առանձին կանչի համար վերասահմանեք `--remote` / `--api-key`-ով։

## Խնդիրների վերացում

**Claude Code-ն անտեսում է անցուղին** — համոզվեք, որ `ANTHROPIC_BASE_URL`-ը **չի
պարունակում `/v1`**, և վերագործարկեք `claude`-ը (env-ը կարդացվում է մեկ անգամ՝ գործարկման պահին)։ `omniroute launch`-ը
դա կատարում է ձեզ համար։

**`/model` ընտրիչը դատարկ է / անցուղու մոդելները բացակայում են** — անհրաժեշտ են Claude Code
v2.1.219+ և `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`։ Ընտրիչում հայտնվում են միայն `claude*` /
`anthropic*` մոդելների ID-ները․ ցանկացած այլ մոդել հարկադրաբար ընտրելու համար օգտագործեք
`ANTHROPIC_MODEL=<id>` (պրոֆիլները հենց սա են անում)։

**`400 Ambiguous model 'claude-…'`** — Claude Code-ը միշտ ուղարկում է **առանց նախածանցի**
մոդելների ID-ներ (օրինակ՝ `claude-opus-4-8`), ուստի, երբ միացված են և՛ Claude Code (`cc/…`), և՛
Claude (`claude/…`) մատակարարները, առանց նախածանցի id-ն համապատասխանում է երկու երթուղու, և
OmniRoute-ը հրաժարվում է ենթադրություն անել։ Ուղղեք դա հետևյալ եղանակներից որևէ մեկով․ ամրագրեք նախածանցով id՝
`ANTHROPIC_MODEL=cc/claude-opus-4-8`, կամ միացրեք **Նախապատվությունը տալ Claude Code-ին
առանց նախածանցի Claude մոդելների համար** տարբերակը՝ Claude մատակարարի էջի փոխանջատիչը, կամ
`OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true` (լռելյայն անջատված է․
տե՛ս [Միջավայր](../reference/ENVIRONMENT.md))․ այս դեպքում առանց նախածանցի `claude-*`
ID-ները կուղղորդվեն դեպի Claude Code։ Մատակարարի հստակ նախածանցները միշտ գերակայում են։

**Նույնականացման սխալներ** — պրոֆիլը թոքեն չի պահում։ Օգտագործեք `omniroute launch --profile`
(այն ներարկում է թոքենը) կամ արտահանեք `ANTHROPIC_AUTH_TOKEN`։

**Պրոֆիլները չեն մեկուսացվում** — յուրաքանչյուր պրոֆիլ առանձին `CLAUDE_CONFIG_DIR` է․
ստուգեք, որ աշխատաշրջանի ներսում `echo $CLAUDE_CONFIG_DIR`-ը մատնանշում է
`~/.claude/profiles/<name>`։
