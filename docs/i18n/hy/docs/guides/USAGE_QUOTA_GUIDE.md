> **Կարճ ասած**․ OmniRoute-ը հետևում է յուրաքանչյուր հարցման թոքենների օգտագործմանը, հաշվարկում է արժեքը, կիրառում է յուրաքանչյուր API բանալու քվոտան և վերլուծական տվյալները ցուցադրում կառավարման վահանակում։ Այս ուղեցույցը բացատրում է, թե ինչպես է այդ ամենն աշխատում։

**Աղբյուրներ․**

- `open-sse/services/usage.ts` (~70KB) — օգտագործման հետևման հիմնական մոդուլ
- `src/lib/usageAnalytics.ts` (~10KB) — կառավարման վահանակի համար ագրեգացում
- `src/lib/db/quotaSnapshots.ts` — քվոտայի պատմական տվյալներ
- `src/lib/db/usage*.ts` — օգտագործման հետ կապված տվյալների բազայի մի քանի մոդուլներ

## Ընդհանուր ակնարկ

OmniRoute-ով անցնող յուրաքանչյուր հարցում ստեղծում է **օգտագործման գրառում**, որը պարունակում է՝

- **Ինքնություն**․ որ API բանալին, մատակարարը, մոդելը և համակցությունն են օգտագործվել
- **Թոքեններ**․ հուշման թոքեններ, լրացման թոքեններ, քեշավորված թոքեններ, ընդհանուր քանակ
- **Արժեք**․ գումարը ԱՄՆ դոլարով՝ հաշվարկված գնագոյացման տվյալներից
- **Ժամանակագրություն**․ ուշացում, սկզբի/ավարտի ժամանակային դրոշմներ
- **Կարգավիճակ**․ հաջողություն, սխալ, արագության սահմանափակում և այլն

```
Հարցում ──▶ chatCore ──▶ usage.record() ──▶ SQLite
                                  │
                          ┌───────┼───────┐
                          ▼       ▼       ▼
                  վերլուծություն քվոտա  հաշվարկներ
                  (վահանակ)     (կիրառում) (արտահանում)
```

## Ինչ է գրանցվում

`usage.ts` ծառայությունը յուրաքանչյուր հարցման համար գրանցում է **օգտագործման իրադարձություն**․

| Դաշտ               | Տեսակ   | Աղբյուր                                                            |
| ------------------ | ------- | ------------------------------------------------------------------ |
| `id`               | string  | Գրանցելիս ստեղծված UUID                                            |
| `apiKeyId`         | string  | Հարցումը նախաձեռնած API բանալին                                    |
| `provider`         | string  | Մատակարարի ID-ն (openai, anthropic և այլն)                         |
| `model`            | string  | Մոդելի ID-ն (gpt-5, claude-opus-4-6 և այլն)                        |
| `comboId`          | string? | Համակցության ID-ն, եթե երթուղավորումն անցել է համակցությամբ        |
| `promptTokens`     | number  | Վերին հոսքի պատասխանից                                             |
| `completionTokens` | number  | Վերին հոսքի պատասխանից                                             |
| `cachedTokens`     | number  | Քեշից ստացված թոքեններ (Anthropic-ի հուշումների քեշավորում և այլն) |
| `totalTokens`      | number  | հուշում + լրացում                                                  |
| `costUsd`          | number  | Հաշվարկված է գնագոյացման տվյալներից                                |
| `latencyMs`        | number  | Հարցման ամբողջական տևողությունը                                    |
| `status`           | enum    | `success`, `error`, `rate_limited`, `timeout`, `cancelled`         |
| `errorClass`       | string? | Սխալի դասը, եթե կարգավիճակը != success                             |
| `timestamp`        | string  | ISO 8601 UTC                                                       |
| `metadata`         | object  | Ընդլայնման միջոցով ներարկված հատուկ տվյալներ                       |

### Որտեղից են ստացվում թոքենները

Թոքենները վերին հոսքի մատակարարի պատասխանից առանձնացվում են **պատասխանի մշակիչում**․

```ts
// open-sse/handlers/chatCore.ts-ից
const response = await providerExecutor.execute(provider, request);
const usage = response.usage || {
  prompt_tokens: 0,
  completion_tokens: 0,
  cached_tokens: 0,
};
```

Այն մատակարարների դեպքում, որոնք օգտագործման տվյալներ չեն վերադարձնում (վեբ cookie-ներ օգտագործող որոշ մատակարարներ), OmniRoute-ը թոքենների քանակը **մոտավոր գնահատում է**՝ կիրառելով `~4 chars per token` էվրիստիկան (տե՛ս `open-sse/services/autoCombo/pipelineRouter.ts`)։

### Քեշավորված թոքեններ

OmniRoute-ը `cached_tokens`-ը հետևում է `prompt_tokens`-ից առանձին, քանի որ՝

- Anthropic-ի հուշումների քեշավորման դեպքում քեշավորված թոքենների համար գանձվում է նվազեցված սակագին՝ սովորական արժեքի 10%-ը
- Որոշ մատակարարներ վերադարձնում են `cache_read_input_tokens`, որոնք պետք է այլ կերպ գնագոյացվեն
- Վերլուծական տվյալները կարող են ցույց տալ **քեշի համընկնման գործակիցը** = `cached_tokens / prompt_tokens`

## Արժեքի հաշվարկ

Արժեքները հաշվարկվում են LiteLLM-ից համաժամացված **գնագոյացման տվյալների** հիման վրա (`src/lib/pricingSync.ts`)․

| Մոդել             | Մուտքային $/1M | Ելքային $/1M | Քեշավորված $/1M |
| ----------------- | -------------- | ------------ | --------------- |
| gpt-5             | $2.50          | $10.00       | —               |
| claude-opus-4-6   | $15.00         | $75.00       | $1.50           |
| claude-sonnet-4-5 | $3.00          | $15.00       | $0.30           |
| gemini-2.5-pro    | $1.25          | $10.00       | —               |

Արժեքի բանաձևը (`src/lib/usage/costCalculator.ts`)․

```ts
cost =
  (prompt_tokens - cached_tokens) * input_price +
  cached_tokens * cached_price +
  completion_tokens * output_price;
```

> **Ինչո՞ւ են քեշավորված թոքենները հանվում հարցման թոքեններից։** Քեշավորված մասը գնագոյացվում է առանձին․ ամբողջ հարցման նկատմամբ մուտքային գինը կիրառելը կհանգեցներ կրկնակի հաշվարկի։

### Գնագոյացման համաժամացում

Գնագոյացման տվյալներն ավտոմատ կերպով համաժամացվում են LiteLLM-ից՝ `/api/pricing/sync` վերջնակետի միջոցով (այն գործարկվում է ներկառուցված cron առաջադրանքով, այլ ոչ թե օգտատիրոջ համար նախատեսված միջավայրի փոփոխականով)․

```bash
# Ձեռքով գործարկում
curl -X POST http://localhost:20128/api/pricing/sync
```

Այն մոդելների համար, որոնց գնագոյացման տվյալները հասանելի չեն, OmniRoute-ը **մոտավոր հաշվարկում է արժեքը**՝ օգտագործելով ներքին միջին դրույքաչափերը (որոնց աղբյուրը LiteLLM-ի գնագոյացման տվյալներն են)։

## Ամսաթվերի միջակայքով ագրեգացում

`usageAnalytics.ts` մոդուլը չմշակված օգտագործման տվյալներից հաշվարկում է կառավարման վահանակի վիջեթները։ Այն աջակցում է 7 ժամանակային միջակայք․

| Միջակայք | Ժամանակահատված                    | Օգտագործման դեպք                           |
| -------- | --------------------------------- | ------------------------------------------ |
| `1d`     | Վերջին 24 ժամը                    | Արժեքի ժամային կտրուկ աճերի հայտնաբերում   |
| `7d`     | Վերջին 7 օրը                      | Շաբաթական վերանայում                       |
| `30d`    | Վերջին 30 օրը                     | Ամսական հաշիվների կազմում                  |
| `90d`    | Վերջին 90 օրը                     | Եռամսյակային վերլուծություն                |
| `ytd`    | Ընթացիկ տարվա հունվարի 1-ից սկսած | Տարեկան բյուջեի վերահսկում                 |
| `all`    | Ամբողջ ժամանակահատվածը            | Օգտագործման ողջ պատմության վիճակագրություն |
| `custom` | Օգտատիրոջ սահմանած սկիզբ/ավարտ    | Աուդիտներ, հատուկ հարցումներ               |

### Հաշվարկվող կառավարման վահանակի վիջեթներ

Ցանկացած ամսաթվերի միջակայքի համար վերլուծական շերտը հաշվարկում է․

| Վիջեթ                           | Նկարագրություն                                                            |
| ------------------------------- | ------------------------------------------------------------------------- |
| **Ամփոփիչ քարտեր**              | Հարցումների ընդհանուր քանակ, ընդհանուր արժեք, թոքեններ, հաջողության տոկոս |
| **Օրական միտումների գծապատկեր** | Օրական արժեք + թոքեններ՝ շերտավորված ըստ մոդելի                           |
| **Ակտիվության ջերմային քարտեզ** | Օրվա ժամ × շաբաթվա օր ցանց, գույնը = հարցումների քանակ                    |
| **Բաշխում ըստ մոդելի**          | Արժեքի շրջանաձև գծապատկեր՝ ըստ մոդելի                                     |
| **Բաշխում ըստ մատակարարի**      | Հարցումների սյունակաձև գծապատկեր՝ ըստ մատակարարի                          |
| **Առաջատար API բանալիներ**      | Արժեքով առաջատար 10 բանալիների աղյուսակ                                   |
| **Սխալների վերլուծություն**     | Ժամանակի ընթացքում սխալների տոկոս, սխալների առաջատար դասեր                |

### Ծրագրային հասանելիություն

````ts
import { computeAnalytics } from "@/lib/usageAnalytics";

const analytics = await computeAnalytics(
  history,              // օգտագործման պատմության գրառումներ
  "7d",                 // ժամանակային միջակայք՝ "1d" | "7d" | "30d" | "90d" | "ytd" | "all" | "custom"
  connectionMap,        // մատակարարների կապերի քարտեզ (connectionId → հաշվի անվանում)
  {
    startDate: "2025-01-01",  // ընտրովի՝ "custom" միջակայքի համար
    endDate: "2025-06-01",   // ընտրովի՝ "custom" միջակայքի համար
  }
);

console.log(analytics.summary.totalCost);   // 12.34 (ցենտ)
console.log(analytics.byModel[0]);           // { model, cost, requests, promptTokens, completionTokens }

## Քվոտայի կիրարկում

Յուրաքանչյուր API բանալու քվոտան կիրարկվում է երկու տեղում՝

1. **Փափուկ սահմանաչափ** (`quotaWarnAt`)՝ կառավարման վահանակում նախազգուշացում, երբ օգտագործումը գերազանցում է շեմը
2. **Կոշտ սահմանաչափ** (`quotaLimit`)՝ սահմանաչափը գերազանցելու դեպքում հարցումը մերժվում է HTTP 429 կարգավիճակով

### Կազմաձևում

```ts
// Յուրաքանչյուր API բանալու համար
await updateApiKey(keyId, {
  quotaWarnAt: 5_00,    // $5.00 — ցուցադրել նախազգուշացում
  quotaLimit: 10_00,    // $10.00 — ամբողջական դադարեցում
  quotaWindow: "month", // "day" | "week" | "month" | "all"
});
````

### Կիրարկման հոսք

```
Հարցում ──▶ quotaCheck()
              │
              ├── Սահմանաչափի մե՞ջ է  ──▶ թույլատրել
              │
              └── Սահմանաչափը գերազանցվա՞ծ է  ──▶ 429 Չափազանց շատ հարցումներ
                                                   Retry-After վերնագրով
```

### Քվոտայի ակնթարթային պատկերներ

`quotaSnapshots` աղյուսակը պահպանում է **քվոտայի պատմական վիճակը**՝ միտումների վերլուծության համար․

| Դաշտ | Նկարագրություն |
| ----------- | ---------------------------------------- | ------ | ------- |
| `apiKeyId` | Հետևվող բանալին |
| `window` | "day" | "week" | "month" |
| `used` | Այս պատուհանում օգտագործված արժեքը (ցենտ) |
| `limit` | Սահմանաչափը (ցենտ) |
| `resetAt` | Երբ է պատուհանը զրոյացվում |
| `createdAt` | Երբ է ստեղծվել ակնթարթային պատկերը |

Ակնթարթային պատկերները ստեղծվում են **յուրաքանչյուր հարցման ժամանակ**, որի արժեքը > 0 է, և օգտագործվում են՝

- Կառավարման վահանակում քվոտայի առաջընթացի գոտին արտապատկերելու համար
- Քվոտայի 30-օրյա միտումների գծապատկերները ցուցադրելու համար
- Նախազգուշացումներ գործարկելու համար, երբ օգտագործումը մոտենում է սահմանաչափին

## Պահպանում և մաքրում

Օգտագործման տվյալներն աճում են յուրաքանչյուր հարցման համար մոտավորապես 1-10KB-ով։ Մեծ ծավալների դեպքում սա կարող է զգալի լինել։

### Պահպանման կարգավորումներ

Օգտագործման պատմության պահպանման ժամկետը կազմաձևվում է UI-ի Database Settings բաժնի միջոցով կամ `/api/settings/database`-ի միջոցով։

Լռելյայնորեն օգտագործման պատմությունը պահպանվում է **90 օր**։

### Մաքրում

Հին գրառումները մաքրվում են `src/lib/db/cleanup.ts`-ի միջոցով՝

- Գործարկվում է ֆոնային cron գործընթացի կողմից
- `usage_history`-ից ջնջում է կազմաձևված `usageHistory` պահպանման ժամկետից ավելի հին գրառումները

### Պահեստի ծավալի գնահատում

| Հարցումների հաճախականություն | 30 օրվա պահեստ | 90 օրվա պահեստ |
| ---------------------------- | -------------- | -------------- |
| 100 հարցում/օր               | ~3MB           | ~9MB           |
| 1,000 հարցում/օր             | ~30MB          | ~90MB          |
| 10,000 հարցում/օր            | ~300MB         | ~900MB         |
| 100,000 հարցում/օր           | ~3GB           | ~9GB           |

Շատ բարձր տրաֆիկի դեպքում դիտարկեք՝

- Database Settings-ի միջոցով պահպանման ժամկետի կրճատումը
- Չմշակված գրառումների փոխարեն `aggregated_metrics`-ի օգտագործումը (միայն վերլուծության համար)

## Ծախսերի օպտիմալացման խորհուրդներ

### 1. Օգտագործեք ճիշտ մոդելը

```bash
# Արագ պատասխան — օգտագործեք էժան + արագ տարբերակը
curl -d '{"model":"auto/fast","messages":[...]}'

# Բարդ առաջադրանք — օգտագործեք բարձր որակը
curl -d '{"model":"auto/smart","messages":[...]}'
```

### 2. Միացրեք քեշավորումը

Anthropic-ի հուշումների քեշավորումը կրկնվող համատեքստի դեպքում խնայում է **90%**՝

```ts
// Քեշավորումն ավտոմատ է — պարզապես ներառեք նույն մեծ համակարգային հուշումը
const response = await openai.chat({
  model: "claude-sonnet-4-5",
  system: longSystemPrompt, // Ինքնաբերաբար կքեշավորվի
  messages: [{ role: "user", content: "..." }],
});
```

### 3. Օգտագործեք սեղմում

RTK + Caveman սեղմումը գործիքներով հագեցած աշխատաշրջաններում խնայում է **15-95%**՝

```ts
const config = {
  compression: {
    engine: "rtk",
    intensity: "aggressive",
  },
};
```

### 4. Սահմանեք յուրաքանչյուր բանալու քվոտաներ

Անվերահսկելի ծախսերը կանխելու համար միշտ սահմանեք `quotaLimit`՝

```ts
await updateApiKey(keyId, { quotaLimit: 10_00 }); // Ամսական $10 սահմանաչափ
```

### 5. Ստուգեք ամենախոշոր սպառողներին

Օգտագործեք կառավարման վահանակը կամ **`/api/usage/analytics`**-ը՝ ըստ API բանալու խմբավորելու և ըստ ծախսի դասավորելու համար՝

```bash
GET /api/usage/analytics?groupBy=apiKey
```

## Խնդիրների լուծում

### «Ծախսն սպասվածից բարձր է»

1. Ստուգեք **`/api/usage/analytics?groupBy=model`**-ը՝ գտեք թանկ մոդելը
2. Ստուգեք **`/api/usage/analytics?groupBy=apiKey`**-ը՝ գտեք խոշոր սպառողին
3. Համոզվեք, որ գնային տվյալներն արդիական են՝ `POST /api/pricing/sync`

### «Գրառումները բացակայում են»

- Dashboard → Database → Cleanup բաժնում ստուգեք DB-ի պահպանման կարգավորումները. հին գրառումները ջնջվում են պարբերական մաքրման առաջադրանքի կողմից (`src/lib/db/cleanup.ts`)
- Ստուգեք `src/lib/db/usage*.ts`-ում առկա սխալները. DB-ում գրանցման ձախողումները գրանցվում են մատյանում, սակայն չեն ցուցադրվում
- Համոզվեք, որ հարցումն իրականում հասել է `chatCore`-ին. ստուգեք համակցված երթուղավորումը

### «Քվոտան չի կիրառվում»

- Ստուգեք բանալու `quotaLimit` կարգավորումը
- Համոզվեք, որ `quotaWindow`-ը ճիշտ է սահմանված
- Փնտրեք `quotaSnapshots` գրառումները. դրանք պետք է ստեղծվեն յուրաքանչյուր հարցման ժամանակ
