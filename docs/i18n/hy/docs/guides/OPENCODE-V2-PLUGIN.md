`@omniroute/opencode-plugin-v2`-ը ձեր ամբողջ OmniRoute կատալոգը՝ մոդելները, կոմբոները և
ավտոկոմբոները, ավելացնում է OpenCode v2-ի մոդելների ընտրիչում՝ ցուցադրվող անուններով, գնագոյացմամբ և անվճար մակարդակի
սահմանաչափերով։

Այն `@omniroute/opencode-plugin`-ից առանձին փաթեթ է, քանի որ OpenCode v1-ը և v2-ը
փլագինները բեռնում են տարբեր պայմանագրերով։ Ընտրեք ձեր OpenCode-ի հիմնական տարբերակին համապատասխանողը․
դրանց միջև ոչինչ ընդհանուր չէ, ուստի մեկի թարմացումը երբեք չի պարտադրում թարմացնել մյուսը։

## Պահանջներ

- OpenCode v2։
- Հասանելի OmniRoute դարպաս (`http://localhost:20128`՝ լռելյայն)։
- Node.js 22 կամ 24։

## Տեղադրում

Ավելացրեք փլագինը `opencode.json`-ում․

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

Այնուհետև մոդելները հայտնվում են որպես `omniroute/<provider>/<model>`․ `providerId`-ը որոշում է այդ նախածանցը և
այն ինտեգրման նույնացուցիչը, որի տակ OpenCode-ը պահում է հավատարմագիրը։

## Հավատարմագրեր

Փլագինը դարպասի բանալին որոնում է երեք տեղում՝ հետևյալ հերթականությամբ․

1. **OpenCode-ում ձեր միացրած հավատարմագիրը։** Փլագինը գրանցում է ինտեգրում, որպեսզի
   OpenCode-ի սեփական նույնականացման հոսքը կարողանա պահել բանալին։ `opencode.json`-ում ոչինչ չի հայտնվում․ նախընտրեք այս տարբերակը։
2. `apiKey`-ը՝ փլագինի ընտրանքներում, յուրաքանչյուր նախագծի համար առանձին վերագրանցման նպատակով։ Այն բանալին տեղադրում է մի ֆայլում, որը
   կարող եք ներառել commit-ում։
3. `OMNIROUTE_API_KEY`-ը՝ միջավայրում։

Եթե երեքից ոչ մեկը չկա, կատալոգը դատարկ է մնում, և փլագինը գործարկման ժամանակ մեկ անգամ հայտնում է այդ մասին՝
ձեզ լուռ դատարկ ընտրիչով թողնելու փոխարեն։

### Կառավարման թոքենն այլ բանալի է

Կոմբոները, մատակարարների վիճակը և հարստացված տվյալները (ցուցադրվող անուններ, գնագոյացում, անվճար մակարդակի սահմանաչափեր) ստացվում են
դարպասի `/api/*` վերջնակետերից, որոնք տեղակայումների մեծ մասում պաշտպանված են **կառավարման** թոքենով,
այլ ոչ թե ինֆերենցիայի բանալիով․

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<կառավարման ընթերցման թոքեն>"
}
```

Եթե սահմանված չէ, `managementReadToken`-ը հետադարձաբար օգտագործում է `apiKey`-ը։ Երբ դարպասը մերժում է այդ հետադարձ տարբերակը,
կատալոգը միևնույն է հրապարակվում է, սակայն ցուցադրվող անունների փոխարեն՝ մոդելների սկզբնական նույնացուցիչներով, առանց կանոնական
այլանունների կրկնությունների հեռացման, գնագոյացման և կոմբոների։ Երբ դա տեղի է ունենում, փլագինը յուրաքանչյուր վերջնակետի համար մեկ անգամ զգուշացնում է՝
նշելով վերջնակետը և կորցրած հնարավորությունները, որպեսզի սահմանափակված ընտրիչի պատճառը երբեք առեղծված չմնա։

## Ընտրանքներ

| Բանալի                           | Լռելյայն                                       | Նշումներ                                                                                                                 |
| -------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `providerId`                     | `"omniroute"`                                  | Մատակարարի նույնացուցիչը, ինտեգրման նույնացուցիչը և այն նախածանցը, որի տակ հայտնվում են մոդելները                        |
| `baseURL`                        | պարտադիր                                       | Դարպասի արմատային հասցեն, միայն `http(s)`․ `/v1` վերջածանցն ավելացվում է անհրաժեշտության դեպքում                         |
| `apiKey`                         | միացված հավատարմագիրը, ապա `OMNIROUTE_API_KEY` | Զրույցի բանալին՝ `/v1/*`-ի համար                                                                                         |
| `managementReadToken`            | հետադարձաբար օգտագործում է `apiKey`-ը          | Բանալին՝ `/api/*`-ի համար․ սովորաբար **նույն բանալին չէ**                                                                |
| `displayName`                    | `"OmniRoute"`                                  | Մատակարարի անունը ընտրիչում                                                                                              |
| `timeoutMs`                      | `10000`                                        | Յուրաքանչյուր վերջնակետի հարցման ժամանակային սահմանաչափը (ավտոկոմբոներն օգտագործում են 5 վրկ.)                           |
| `modelCacheTtlMs`                | `300000`                                       | Կատալոգի քեշի TTL-ը․ սկավառակի պատկերը արագացնում է սառը մեկնարկները                                                     |
| `timeouts`                       | հետադարձաբար օգտագործում է `timeoutMs`-ը       | Յուրաքանչյուր վերջնակետի ժամանակային սահմանաչափերը՝ մվ-ով․ `models`, `combos`, `autoCombos`, `enrichment`                |
| `enrichment`                     | `true`                                         | Ստանալ անունները, գնագոյացումը և անվճար մակարդակի սահմանաչափերը                                                          |
| `providerTag`                    | `true`                                         | Ցուցադրվող անվանը կցել վերին մակարդակի մատակարարի նախածանցը, որին այն ուղղորդվում է                                      |
| `usableOnly`                     | `false`                                        | Պահել միայն այն մատակարարներին, որոնք դարպասը նշում է որպես կազմաձևված                                                   |
| `visibleModels` / `hiddenModels` | `[]`                                           | Ճշգրիտ կամ վերջածանցով թույլատրացուցակներ․ արգելքն ունի գերակայություն                                                   |
| `geminiSanitization`             | `true`                                         | Գործիքների սխեմաներից հեռացնել Gemini-ի կողմից մերժվող JSON-Schema հիմնաբառերը (`$ref` գործիքները փոխանցվում են անփոփոխ) |
| `apiFormat.allowAnthropic`       | `false`                                        | Թույլատրացուցակում գտնվող նույնացուցիչներն ուղղորդել Anthropic API բլոկով                                                |
| `apiFormat.anthropicModels`      | `[]`                                           | Anthropic-ին ուղղորդվող մոդելների ամբողջական նույնացուցիչները                                                            |
| `logLevel` / `startupDebug`      | `warn` / `false`                               | Գրանցամատյանի մանրամասնության մակարդակը                                                                                  |

## Ինչպես է կատալոգը թարմ մնում

Կատալոգը բեռնվում է ըստ անհրաժեշտության և քեշավորվում `modelCacheTtlMs` ժամանակով, իսկ սկավառակի պատճենը պահպանում է վերջին հայտնի կատալոգի հասանելիությունը, երբ դարպասը հասանելի չէ. խափանման դեպքում կորցնում եք միայն թարմությունը։ Մոդելներն ու կոմբինացիաները հրապարակվում են հասնելուն պես. ավտոմատ կոմբինացիաները, մատակարարների ցանկը և հարստացման վերադիր շերտը միացվում են հասանելի դառնալուն պես, այնպես որ մեկ դանդաղ վերջնակետ չի կարող արգելափակել ընտրիչի ամբողջ աշխատանքը։

Անունները ներառում են դարպասին հայտնի տվյալները՝ վերին մակարդակի մատակարարին, որին ուղղորդվում է մոդելը, `[Free]` նշիչը և դրա հետ տրամադրվող բյուջեն, որպեսզի նույն մոդելը վաճառող երկու կապերը հնարավոր լինի տարբերակել։ Անջատեք նախածանցը՝ օգտագործելով `"providerTag": false`։

Ձեռքով թարմացման հրաման չկա. OpenCode v2-ի հրամանները հուշումների ձևանմուշներ են, ոչ թե հետադարձ կանչեր, ուստի հավելումը չի կարող նման հրաման տրամադրել։ Թարմացումները կատարվում են TTL-ի համաձայն. հոսթից վերաբերեռնում է պահանջվում միայն այն ժամանակ, երբ կատալոգը կամ վերադիր շերտն իսկապես փոխվել է, և ոչ երբեք յուրաքանչյուր թարմացման ժամանակ։

## Գործիքների կանչը Gemini-ում

Gemini-ն մերժում է ամբողջ հարցումը, եթե դրա գործիքների հայտարարությունները պարունակում են `$schema` կամ `additionalProperties՝ պատասխանելով `400 INVALID_ARGUMENT`։ Հավելումը հեռացնում է այդ բանալի բառերը այս մատակարարի Gemini մոդելին ուղարկվող գործիքների սխեմաներից և բոլոր մյուս հարցումները թողնում է անփոփոխ։ `$ref`պարունակող գործիքն ուղարկվում է անփոփոխ՝ առանց մաքրման, քանի որ հղումը հեռացնելը կընդլայներ սխեման՝ դարձնելով այն «ընդունել ամեն ինչ»։
Այն անջատելու համար սահմանեք`"geminiSanitization": false`։
