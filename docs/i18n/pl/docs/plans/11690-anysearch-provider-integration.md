## 1. Fakty dotyczące usługi (oficjalna dokumentacja, zweryfikowana krzyżowo)

- Bazowy adres URL: `https://api.anysearch.com` (REST) + `POST /mcp` (MCP, JSON-RPC 2.0).
- `POST /v1/search` — parametry: `query` (wymagany), `max_results` (1–10, domyślnie 10), `tag` (routing pionowy `{domain}.{sub_domain}`), `zone` (cn/intl), `language`, `params` (ustrukturyzowane pola pionowe), `format` (json/markdown).
- `GET /v1/sub-domains?domain=...` — katalog możliwości; NIE wlicza się do limitu.
- `POST /v1/extract` — pobiera/wyodrębnia `{url, title, content}`; ścisły format treści JSON, limit 16 KiB.
- `POST /v1/auth/email/register` — rejestracja jednym wywołaniem; zwraca jednorazowy klucz w postaci zwykłego tekstu `as_sk_...`.
- Uwierzytelnianie: opcjonalny nagłówek `Authorization: Bearer <as_sk_...>`; dostęp anonimowy jest ograniczany limitami na adres IP, które zużywają dzienny bezpłatny limit; nieprawidłowy klucz powoduje zwrócenie 401/403 BEZ cichego przełączenia na dostęp anonimowy.
- Plan bezpłatny: 1000 żądań dziennie, 20 QPS na klucz. Plan płatny: bez podanej ceny (Coming Soon).
- Obwiednia odpowiedzi: powodzenie `{code: 0, message: "success", request_id, data}`; niepowodzenie `{code: -1, message}`. Błędy uwierzytelniania/limitu nie zawierają ustrukturyzowanego pola `error_code` (sygnałem jest tekst komunikatu); błędy specyficzne dla wyodrębniania zawierają `error_code` (`invalid_extract_url`, `extract_failed`). Brak nagłówka `Retry-After` w odpowiedzi 429.

## 3. Decyzje (wszystkie podjęte 2026-08-26)

1. **Strategia routingu: `fallbackOnly`.** Uzasadnienie: darmowy dostawca o koszcie 0 nie może nigdy dominować w automatycznym routingu opartym na kosztach; jawny wybór i powrót awaryjny pozostają bez zmian. Precedens: scalony wpis xquik.
2. **Zakres: webSearch + webFetch za pośrednictwem `POST /v1/extract` w v1.** Jest to zgodne z modelem koncepcyjnym podwójnych możliwości tavily/exa. Wyspecjalizowane funkcje (`tag`, `sub-domains`, `batch_search`) pozostają poza zakresem — obecnie nie istnieje IR dla wyspecjalizowanych parametrów.
3. **Wyświetlanie limitu: `freeMonthlyQuota: 0`** (konserwatywne wyświetlanie w stylu xquik). Rzeczywisty limit (1000 żądań dziennie, resetowany codziennie) jest zamiast tego podany w treści `authHint` katalogu interfejsu użytkownika. Uzasadnienie: sposób wyświetlania limitu musi odpowiadać semantyce resetowania; przeliczanie dziennego limitu na miesięczny odpowiednik (30000) byłoby fałszywą obietnicą, której interfejs użytkownika nie może dotrzymać.
4. **searchTypes: tylko `["web"]`.** Nie ma publicznie dostępnych dowodów na istnienie w API AnySearch wyspecjalizowanego wyszukiwania wiadomości/obrazów; bramy integrujące API bez udokumentowanej wyspecjalizowanej funkcji (np. Google Custom Search) udostępniają wyłącznie wyszukiwanie internetowe, zamiast niejawnie mapować news -> web.
5. **Strategia dotycząca klucza:** działanie bez klucza jest obsługiwane; nieprawidłowy klucz powoduje zwrócenie kodu 401/403 i nigdy nie prowadzi do niejawnego przejścia na dostęp anonimowy (zgodnie z kontraktem usługi nadrzędnej).
6. **Celowe wyłączenia:** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (przechwytywanie czatu nadal korzysta z firecrawl/jina/tavily); `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (anonimowe zdalne punkty końcowe współdzielą jedną pulę ograniczoną adresem IP dla każdego wychodzącego adresu IP, dlatego wyodrębnianie bez klucza wymaga świadomego włączenia i nie jest kandydatem do automatycznego routingu); `QUOTA_STATUS_PROVIDERS` (AnySearch sygnalizuje wyczerpanie limitu za pomocą kodu 429/koperty odpowiedzi, a nie kodu stanu 402/403).
