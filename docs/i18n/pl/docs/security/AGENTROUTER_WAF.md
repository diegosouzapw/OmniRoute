Brama nadrzędna `agentrouter` uruchamia filtr treści oparty na słowach kluczowych dla
`messages[].content`. Filtr jest częściowo deterministyczny (zawsze blokuje
określone frazy), a częściowo probabilistyczny (wrażliwy na serie żądań — staje się
bardziej restrykcyjny po szybko następujących po sobie żądaniach i wraca do normy po okresie oczekiwania).

Gdy WAF blokuje żądanie, zwraca:

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## Zakres działania filtra

WAF sprawdza wyłącznie `messages[].content`. **Nie** sprawdza:

- Monitu `system`
- Bloków treści strukturalnej (`tool_result`, `tool_use`, `thinking`, `image`)
- Pól `description` i `input_schema` narzędzi
- Metadanych żądania, nagłówków ani identyfikatora modelu

## Wzorce blokowane zawsze (bez rozróżniania wielkości liter)

| Wzorzec                         | Uwagi                                                          |
| ------------------------------- | -------------------------------------------------------------- |
| Dowolny wariant `Lorem ipsum`   | Blokowane jest pełne łacińskie słownictwo lorem                |
| `language model` (samodzielnie) | Frazy „the language model” i „large language model” przechodzą |
| `virtual assistant`             | Fraza „AI assistant” przechodzi                                |
| `I'm here to help`              | Sama fraza „here to help” również jest blokowana               |
| `Claude, made by Anthropic`     | Tylko pełna fraza                                              |

## Wzorce blokowane prawie zawsze

| Wzorzec                                                           | Uwagi                                                      |
| ----------------------------------------------------------------- | ---------------------------------------------------------- |
| `placeholder`                                                     | Gdy występuje samodzielnie (nie jako nazwa parametru itp.) |
| `dummy data`                                                      | Częsta fraza inicjalizująca dla danych testowych           |
| `foo bar baz`                                                     | Kanoniczna fraza zastępcza                                 |
| Powtarzające się krótkie tokeny (`AAA BBB CCC`, `test test test`) | Detektor upychania słów kluczowych                         |

## Zachowanie pod obciążeniem

Po około 5 szybko następujących po sobie żądaniach w krótkim przedziale czasu WAF zaczyna blokować treści,
które normalnie zostałyby przepuszczone. Limit łagodnieje po około 5–10 sekundach
bezczynności. Jest to ten sam mechanizm ograniczania częstotliwości, powiązany z adresem IP i kluczem, który powoduje
sporadyczne błędy `400 content-blocked`, gdy Claude Code lub Codex CLI
wykonuje wiele wywołań użycia narzędzi lub wysyłania wiadomości w krótkich odstępach czasu.

## Środki zaradcze już zastosowane w OmniRoute

1. **`open-sse/services/wafRateLimit.ts`** — zabezpieczenie przed seriami żądań, które wymusza
   minimalny odstęp 500 ms między wychodzącymi żądaniami do dowolnego adresu URL `agentrouter:*`.
   Odstęp ten jest znacznie poniżej progu odczuwalnego przez człowieka i zapobiega
   aktywacji WAF przy normalnym ruchu.

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — gdy usługa nadrzędna zwraca
   `400 content-blocked`, wykonawca ponawia żądanie pod tym samym adresem URL,
   stosując wykładniczo rosnący czas oczekiwania (1,5 s, 3,0 s, maksymalnie 2 próby). Po tym czasie
   WAF zazwyczaj łagodnieje i ponowiona próba kończy się powodzeniem.

3. **`tests/unit/compression/harness.test.ts`** — dane testowe
   `longInput` zmieniono z `"lorem ipsum dolor sit amet ".repeat(40)`
   na `"example content for testing purposes ".repeat(40)`, aby podczas
   odczytywania tego pliku przez Claude Code za pomocą narzędzia `Read` jego zawartość
   nie wracała przez blok `tool_result` i nie aktywowała WAF.

## Wskazówki dotyczące monitów i danych wyjściowych narzędzi

Jeśli sesja Claude Code lub Codex CLI wielokrotnie napotyka
`400 content-blocked`, sprawdź najnowszą wiadomość użytkownika i najnowszy
wynik narzędzia pod kątem któregokolwiek z powyższych wzorców, a następnie go przeformułuj. Typowe
obejścia:

- Zastąp `Lorem ipsum …` frazą `example text …` lub rzeczywistą treścią,
  którą test albo dane testowe mają modelować.
- Zastąp `placeholder` (gdy występuje samodzielnie) frazą `example value`,
  `sample value` albo rzeczywistą wartością.
- Zastąp `language model` frazą `large language model` albo `the model`.
- Zastąp `dummy data` frazą `sample data` albo realistycznymi wartościami inicjalizującymi.
- Zastąp `I'm here to help` / `here to help` bardziej konkretnym
  początkiem wypowiedzi (np. „I'll review the file you mentioned”).

## Zgłaszanie fałszywych alarmów dostawcy usługi nadrzędnej

Obecny filtr jest nadmiernie restrykcyjny — blokuje „Lorem ipsum” w
blokach `tool_result`, mimo że operator wyraźnie nie zamierzał
wstrzyknąć monitu. Operatorzy, którzy chcą usunięcia problemu u źródła, powinni
skontaktować się z `agentrouter.org`, aby zgłosić fałszywe alarmy. Powyższa lista blokowanych fraz
jest empirycznym wynikiem testowania usługi nadrzędnej na dzień 2026-08-03.
