Dostawcy Web Cookie umożliwiają OmniRoute korzystanie z usługi AI za pośrednictwem istniejącej sesji przeglądarki zamiast klucza API. Są przydatni, gdy masz już dostęp do usługi poprzez jej witrynę i chcesz, aby OmniRoute korzystał z tej samej uwierzytelnionej sesji.

W przeciwieństwie do dostawców korzystających z kluczy API dostawcy Web Cookie uwierzytelniają przy użyciu danych logowania wysyłanych przez przeglądarkę do witryny.

---

# Zanim zaczniesz

> **Ważne:** Zawsze kopiuj dane uwierzytelniające z **aktywnego żądania sieciowego**, a **nie** z magazynu plików cookie przeglądarki.

Wiele problemów z uwierzytelnianiem wynika z kopiowania plików cookie z niewłaściwego miejsca.

## NIE kopiuj z magazynu plików cookie

Większość przeglądarek udostępnia zapisane pliki cookie poprzez:

```
DevTools
→ Application (lub Storage)
→ Cookies
```

Chociaż te pliki cookie mogą wyglądać poprawnie, mogą być:

- nieaktualne
- niekompletne
- pozbawione plików cookie wysyłanych wyłącznie wraz z uwierzytelnionymi żądaniami

Użycie tych wartości może spowodować błędy uwierzytelniania, nawet jeśli wyglądają one na prawidłowe.

## Kopiowanie z aktywnego żądania

Zamiast tego użyj plików cookie z pomyślnie wykonanego żądania:

```
DevTools
→ Network
→ Odśwież stronę
→ Otwórz żądanie czatu lub konwersacji
→ Request Headers
→ Cookie
```

Nagłówek żądania `Cookie` zawiera dokładne informacje uwierzytelniające, których przeglądarka pomyślnie użyła.

W przypadku większości dostawców Web Cookie jest to wartość, którą należy wkleić do OmniRoute.

---

# Konfiguracja ogólna

Proces konfiguracji jest taki sam dla większości dostawców Web Cookie.

1. Zaloguj się w witrynie dostawcy.
2. Otwórz narzędzia deweloperskie przeglądarki.
3. Otwórz kartę **Network**.
4. Odśwież stronę.
5. Otwórz uwierzytelnione żądanie czatu lub konwersacji.
6. Skopiuj wymagane dane uwierzytelniające.
7. Otwórz OmniRoute.
8. Przejdź do **Providers → Add Provider**.
9. Wybierz dostawcę Web Cookie.
10. Wklej dane uwierzytelniające.
11. Kliknij **Test Connection**.
12. Zapisz dostawcę.

Dokładny zestaw wymaganych danych uwierzytelniających zależy od dostawcy.

---

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) to bezpłatna platforma czatu dla użytkowników, która nie wymaga rejestracji — sesja jest tworzona anonimowo podczas pierwszej wizyty i utrzymywana za pomocą trzech plików cookie: `uid`, `si_usr_id` oraz `si_ses_id`. OmniRoute przekazuje żądania do tego samego punktu końcowego `/api/dispatch` za pośrednictwem jednego identyfikatora modelu (`notrack-c`, alias `ntw`).

### Kroki konfiguracji

1. Otwórz [notrack.ai](https://notrack.ai) w przeglądarce i poczekaj na ustawienie pliku cookie anonimowej sesji.
2. Otwórz **Narzędzia deweloperskie → Sieć**, odśwież stronę i kliknij dowolne żądanie `/api`.
3. W sekcji **Nagłówki żądania** skopiuj pełną wartość nagłówka `Cookie`.
4. W OmniRoute przejdź do **Dostawcy → Dodaj dostawcę → NoTrack Web (bezpłatny)**.
5. Wklej ciąg plików cookie w polu `apiKey` i kliknij **Zapisz**.

OmniRoute wyodrębnia `uid`, `si_usr_id` oraz `si_ses_id` z wklejonego ciągu i tworzy czysty nagłówek `Cookie`, zawierający tylko te pary — a także `nt_session` (token `ntk_…` ustawiany dla zalogowanych kont), jeśli jest obecny. Jeśli brakuje któregokolwiek z tych trzech elementów, nieprzetworzony wklejony ciąg jest przekazywany bez zmian, aby operatorzy mogli eksperymentować z alternatywnymi formatami.

### Identyfikatory modeli

| Identyfikator modelu | Nazwa wyświetlana | Uwagi                                                       |
| -------------------- | ----------------- | ----------------------------------------------------------- |
| `notrack-c`          | NoTrack C         | Domyślny — nadrzędny model dyspozytorski `C`.               |
| `C`                  | NoTrack C         | Alias dla `notrack-c` (surowy kod nadrzędnego dyspozytora). |
| `notrack`            | NoTrack C         | Alias dla `notrack-c`.                                      |
| `ntw`                | NoTrack C         | Krótki alias dla `notrack-c`.                               |

Wszystkie cztery identyfikatory modeli wskazują na ten sam nadrzędny model dyspozytorski (`C`).

### Opcje żądania

Moduł wykonawczy akceptuje następujące opcjonalne pola w treści żądania:

| Pole treści           | Wartość domyślna | Przeznaczenie                                                                    |
| --------------------- | ---------------- | -------------------------------------------------------------------------------- |
| `notrack_mode`        | `usual`          | Tryb dyspozytorski (dowolny ciąg; usługa nadrzędna akceptuje `usual`, …).        |
| `notrack_max_turns`   | `6`              | Liczba wewnętrznych tur, które usługa nadrzędna może wykonać przed odpowiedzią.  |
| `notrack_chat_id`     | `null`           | Wznawia istniejący czat nadrzędny (pomiń, aby rozpocząć nowy czat).              |
| `notrack_attachments` | `[]`             | Tablica deskryptorów załączników przekazywana do usługi nadrzędnej bez zmian.    |
| `notrack_regenerate`  | `false`          | Ustaw `true`, aby zażądać ponownego wygenerowania odpowiedzi z poprzedniej tury. |

### Możliwości

- **Strumieniowe i niestrumieniowe** uzupełnianie czatu.
- **Wywoływanie narzędzi** — ustaw `tools: [...]` w żądaniu; moduł wykonawczy serializuje je do kontraktu koperty wywołania narzędzia i przekształca odpowiedzi modelu z powrotem na `tool_calls` OpenAI.
- **`response_format`** — obsługiwane są `json_object` i `json_schema`. Moduł wykonawczy wyodrębnia pierwszy obiekt JSON z odpowiedzi modelu i serializuje go do ciągu przed zwróceniem.
- **Wskazówka dotycząca rozumowania** — moduł wykonawczy emituje deltę `reasoning`, gdy usługa nadrzędna wysyła zdarzenie `thinking`.

### Ograniczenia

- Usługa nadrzędna egzekwuje limity anonimowego użycia — po ich przekroczeniu moduł wykonawczy zwraca błąd 429 z przyjaznym komunikatem.
- Wszystkie identyfikatory modeli wskazują na ten sam nadrzędny model dyspozytorski; nie ma możliwości przełączania między modelami.
- Moduł wykonawczy nie wywołuje punktu końcowego `/api/chats` usługi nadrzędnej, dlatego historia czatów i sesje nie są zarządzane automatycznie. Użyj `notrack_chat_id`, aby wznowić istniejący czat nadrzędny.

# Co dostawcy korzystający z plików cookie mogą, a czego nie mogą robić

Dostawcy korzystający z plików cookie ponownie wykorzystują interfejs czatu witryny internetowej. **Nie** zapewniają takich samych możliwości jak oficjalne interfejsy API.

## Obsługiwane

- Uwierzytelnianie przy użyciu istniejącej sesji przeglądarki
- Dostęp do modeli dostępnych w ramach Twojego konta
- Strumieniowe przesyłanie odpowiedzi czatu
- Brak wymogu posiadania klucza API

## Nieobsługiwane

- Wywoływanie funkcji
- Wywoływanie narzędzi
- Automatyczna edycja plików
- Agentowe przepływy pracy w IDE
- Funkcje dostępne wyłącznie przez API

Jest to oczekiwane zachowanie i **nie** jest to błąd.

Jeśli potrzebujesz wykonywania operacji przez narzędzia, automatycznej edycji plików lub innych agentowych przepływów pracy, zamiast dostawcy Web Cookie użyj **dostawcy wymagającego klucza API**.

# Zastrzeżenie dotyczące walidacji

Pomyślny wynik operacji **Test Connection** lub walidacji plików cookie potwierdza jedynie, że podane dane uwierzytelniające wydają się mieć oczekiwany format.

Do czasu rozwiązania problemu #7857 pomyślna walidacja **nie gwarantuje**, że dostawca pomyślnie przeprowadzi uwierzytelnianie.

Jeśli uwierzytelnianie nadal się nie powiedzie, sprawdź, czy dane uwierzytelniające zostały skopiowane z aktywnego żądania sieciowego, a nie z magazynu plików cookie przeglądarki.

---

# Rozwiązywanie problemów

## Uwierzytelnianie nie powiodło się

Sprawdź, czy dane uwierzytelniające zostały skopiowane z:

```
Network
→ Request Headers
→ Cookie
```

a **nie** z:

```
Application
→ Cookies
```

---

## Plik cookie działa w przeglądarce, ale nie w OmniRoute

Niektórzy dostawcy używają plików cookie, które są wysyłane tylko podczas uwierzytelnionych żądań.

Ponownie skopiuj dane uwierzytelniające ze świeżego żądania sieciowego po pomyślnym otwarciu konwersacji.

---

## Sesja wygasła

Dostawcy Web Cookie korzystają z istniejącej sesji przeglądarki.

Jeśli sesja przeglądarki wygaśnie lub się wylogujesz, musisz skopiować nowy zestaw danych uwierzytelniających. Aby zautomatyzować odnawianie plików cookie dla obsługiwanych dostawców internetowych, skorzystaj z narzędzia pomocniczego [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md).

---

## Test Connection kończy się powodzeniem, ale żądania nie działają

Do czasu rozwiązania problemu #7857 pomyślna walidacja nie gwarantuje, że żądanie uwierzytelniające zakończy się powodzeniem.

Przed dalszym rozwiązywaniem problemów ponownie skopiuj dane uwierzytelniające ze świeżego, uwierzytelnionego żądania.

# Najlepsze praktyki

- Kopiuj dane uwierzytelniające ze świeżego, uwierzytelnionego żądania.
- Unikaj ponownego używania starych plików cookie.
- Podczas korzystania z dostawców Web Cookie utrzymuj aktywną sesję przeglądarki.
- Traktuj skopiowane pliki cookie jak poufne dane uwierzytelniające.
- Jeśli potrzebujesz wywoływania funkcji lub agentowych przepływów pracy, korzystaj z dostawców wymagających klucza API.
