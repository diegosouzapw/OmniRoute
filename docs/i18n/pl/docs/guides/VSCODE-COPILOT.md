**OmniCopilot** umieszcza każdy model udostępniany przez OmniRoute w _natywnym_ selektorze modeli GitHub Copilot Chat.
Bez drugiego panelu bocznego i bez osobnego interfejsu czatu — tryb agenta Copilota, wywoływanie narzędzi,
serwery MCP i niestandardowe instrukcje nadal działają, po prostu korzystając z wybranego modelu.

|                          |                                                                                                                                                 |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Instalacja (VS Code)** | [Marketplace → `diegosouzapw.omnicopilot`](https://marketplace.visualstudio.com/items?itemName=diegosouzapw.omnicopilot)                        |
| **Instalacja (forki)**   | [Open VSX](https://open-vsx.org/extension/diegosouzapw/omnicopilot) — Cursor, Windsurf, VSCodium, Theia, code-server, Gitpod, Antigravity, Kiro |
| **Kod źródłowy / błędy** | [github.com/diegosouzapw/OmniCopilot](https://github.com/diegosouzapw/OmniCopilot) (MIT)                                                        |
| **Wymagania**            | VS Code 1.104+                                                                                                                                  |

> **Subskrypcja Copilot nie jest wymagana.** Od wersji VS Code 1.122 dostawca modeli językowych działa
> bez logowania do GitHub i bez żadnego planu Copilot. Uzupełnianie kodu w tekście oraz
> funkcje oparte na embeddingach pozostają poza interfejsem API dostawcy i nadal wymagają Copilota.

## Konfiguracja

1. **Uruchom OmniRoute** — `npm install -g omniroute && omniroute` (panel pod adresem `http://localhost:20128`).
2. **Zainstaluj rozszerzenie** — wyszukaj „OmniRoute” w widoku rozszerzeń.
3. **Wybierz model** — Copilot Chat → selektor modeli → **Zarządzaj modelami…** → **OmniRoute**, a następnie zaznacz
   wybrane modele.

Gdy OmniRoute działa na domyślnym porcie, nie trzeba niczego konfigurować. W przypadku instancji zdalnej otwórz
**ikonę OmniRoute na pasku aktywności** (lub uruchom `OmniRoute: Manage Connection`) i ustaw:

- **Adres URL serwera** — główny adres serwera, np. `http://192.168.0.15:20128`. Sufiks `/v1` jest
  dodawany przez rozszerzenie; nie należy go uwzględniać.
- **Klucz API** — tylko wtedy, gdy na serwerze ustawiono `REQUIRE_API_KEY`. Jest przechowywany w systemowym magazynie kluczy za pośrednictwem
  VS Code SecretStorage, nigdy w `settings.json`.

## Co pojawi się w selektorze

Rozszerzenie nie wyświetla surowej odpowiedzi `GET /v1/models` — odpowiednio ją przetwarza, a widoczna
liczba jest mniejsza niż rozmiar katalogu z dwóch zamierzonych powodów.

### Żąda jednego identyfikatora na model

Domyślną wartością `MODELS_CATALOG_PREFIX_MODE` jest **`dual`**, co powoduje dwukrotne udostępnienie każdego modelu — raz
z krótkim prefiksem aliasu i raz z kanonicznym prefiksem dostawcy — dzięki czemu starsze konfiguracje
klientów nadal mogą rozpoznawać obie formy:

```
cc/claude-sonnet-4-6        ← prefiks aliasu
claude/claude-sonnet-4-6    ← prefiks kanoniczny, ten sam model
```

Rozszerzenie wysyła żądanie **`GET /v1/models?prefix=alias`**, dzięki czemu otrzymuje jeden identyfikator na model, bez
zmieniania ogólnoserwerowego ustawienia dla pozostałych klientów. W instancji referencyjnej zmniejszyło to liczbę
**2345 wpisów do 1396 — 949 duplikatów, zero utraconych modeli.**

Jeśli wolisz naprawić to na poziomie serwera dla _każdego_ klienta, ustaw flagę funkcji
`MODELS_CATALOG_PREFIX_MODE` na `alias` w panelu. Zobacz
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix), aby poznać
parametr zapytania i tabelę dla poszczególnych trybów.

### Ukrywa modele, które nie obsługują czatu

Katalog zawiera również modele do generowania obrazów, wideo i dźwięku, ponownego szeregowania, embeddingów oraz moderacji. Takie modele
i tak są odrzucane przy żądaniu czatu:

```
HTTP 400 — Model '<id>' jest modelem generowania obrazów i nie może być używany z
/v1/chat/completions. Zamiast tego użyj POST /v1/images/generations.
```

dlatego są odfiltrowywane na podstawie pola `type`, zanim trafią do selektora. **Modele Responses API
są zachowywane** — każdy wpis Codex / GPT-5.x deklaruje `supported_endpoints: ["responses"]`,
a OmniRoute tłumaczy je dla `/v1/chat/completions`, dzięki czemu można z nich bez problemu korzystać.

### Dostawcy, których nigdy nie skonfigurowano

Katalog zawiera modele od dostawców z **aktywnym połączeniem** oraz od wszystkich dostawców **noAuth**
— tych niewymagających klucza, które stanowią dużą część bezpłatnej oferty. Jest to zamierzone. Aby
je ukryć, dodaj ich do `blockedProviders` w ustawieniach panelu; w rozszerzeniu nie trzeba
niczego zmieniać.

## Panel sterowania w karcie VS Code

`omnicopilot.dashboardOpen: "editor"` wyświetla panel sterowania OmniRoute w karcie edytora za pośrednictwem
Simple Browser zamiast w zewnętrznej przeglądarce. Osadzanie jest **opcjonalne po stronie serwera** i włącza się je za pomocą
`DASHBOARD_ALLOW_EMBED=vscode`, co powoduje udostępnianie stron HTML z nagłówkiem
`frame-ancestors 'self' vscode-webview:` zamiast domyślnego `frame-ancestors 'none'` +
`X-Frame-Options: DENY`. Powierzchnia API (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) zachowuje
rygorystyczne nagłówki niezależnie od tego ustawienia.

> ⚠️ **Jest to flaga czasu kompilacji, a nie czasu wykonywania.** Next.js kompiluje `headers()` do manifestu
> tras, dlatego `next.config.mjs` odczytuje zmienną podczas kompilowania pakietu
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> Wyeksportowanie jej przed uruchomieniem już skompilowanego serwera niczego nie zmienia — nagłówki są wbudowane.

```bash
# zmienna musi być dostępna dla polecenia KOMPILACJI
DASHBOARD_ALLOW_EMBED=vscode npm run build        # lub npm run build:release
npm start
```

| Sposób instalacji          | Czy można włączyć osadzanie?                                                                                                                    |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Ze źródeł                  | ✅ ustaw zmienną w poleceniu kompilacji, jak pokazano powyżej                                                                                   |
| `npm install -g omniroute` | ❌ opublikowany pakiet zawiera wstępnie skompilowany pakiet wynikowy — zamiast tego skompiluj ze źródeł                                         |
| Obraz Docker               | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — wstępnie zbudowany obraz w Docker Hub nie obsługuje osadzania |

Bez kompilacji z włączonym osadzaniem strona odmawia wyświetlenia w ramce, rozszerzenie wykrywa to na podstawie
nagłówków odpowiedzi i przełącza się na zewnętrzną przeglądarkę — nic się nie psuje, a użytkownik zostaje o tym jednorazowo poinformowany.
Zobacz [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) oraz zgłoszenie
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273).

## Konfigurowanie innych narzędzi z poziomu VS Code

**`OmniRoute: Configure Coding CLI`** steruje interfejsem CLI `omniroute`, aby zapisać gotowe do użycia profile
dla Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code,
Kilo i Roo — są to te same konfiguracje, które opisano w
[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md). Klucz API jest przekazywany do interfejsu CLI za pośrednictwem
zmiennej środowiskowej `OMNIROUTE_API_KEY`, nigdy w wierszu poleceń.

## Rozwiązywanie problemów

| Objaw                                                           | Przyczyna / rozwiązanie                                                                                                                                                                                                                                                                                 |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Brak modeli OmniRoute w selektorze                              | Serwer jest nieosiągalny. Kropka na pasku stanu zmienia kolor na szary; uruchom `OmniRoute: Check Connection`. Wykrywanie z założenia odbywa się bez komunikatów i nie dodaje żadnych modeli zamiast wyświetlać monit.                                                                                  |
| Każdy model pojawia się dwukrotnie                              | Używasz wersji OmniCopilot starszej niż 1.0.1 — zaktualizuj ją. Rozszerzenie wysyła teraz żądanie `?prefix=alias`.                                                                                                                                                                                      |
| Model obrazu/dźwięku był wcześniej widoczny, ale zniknął        | Jest to zamierzone od wersji 1.0.1 — taki model nigdy nie mógł odpowiedzieć na żądanie czatu.                                                                                                                                                                                                           |
| Brak panelu na pasku aktywności                                 | VS Code przenosi dodatkowe kontenery widoków do menu przepełnienia **"…"** u dołu paska aktywności, a kontener ukryty przez kliknięcie prawym przyciskiem pozostaje ukryty. Kliknij pasek aktywności prawym przyciskiem → zaznacz **OmniRoute** lub otwórz go za pomocą `OmniRoute: Manage Connection`. |
| Panel sterowania otwiera się w przeglądarce mimo trybu `editor` | Serwer nie został **skompilowany** z ustawieniem `DASHBOARD_ALLOW_EMBED=vscode` (patrz wyżej) — ustawienie go podczas uruchamiania wstępnie skompilowanej instalacji niczego nie zmienia. Przełączenie awaryjne jest zamierzone.                                                                        |
| Lista modeli jest nieaktualna po zmianie dostawców              | Uruchom `OmniRoute: Refresh Models` lub użyj odnośnika ↻ w panelu.                                                                                                                                                                                                                                      |
