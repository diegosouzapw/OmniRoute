## 1. Antigravity a Antigravity CLI (agy)

Obaj dostawcy korzystają z **tego samego backendu Google** — identycznego klienta OAuth, odświeżania tokenów, punktów końcowych i kont Google. Różnica polega na tym, jakie modele są widoczne.

> Oficjalne porównanie Google można znaleźć w [ogłoszeniu dotyczącym Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli).

| Aspekt                        | `antigravity` (IDE)                                                 | `agy` (CLI)                                                  |
| ----------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------ |
| **Produkt Google**            | Antigravity 2.0 / Antigravity IDE                                   | Antigravity CLI                                              |
| **Backend**                   | Ten sam interfejs Google Cloud Code API                             | Ten sam interfejs Google Cloud Code API                      |
| **OAuth / token**             | Ten sam klient, to samo odświeżanie                                 | Ten sam klient, to samo odświeżanie                          |
| **Katalog modeli**            | Statyczna, wyselekcjonowana lista (zakodowana na stałe w OmniRoute) | Dynamicznie pobierany z Google przez `:fetchAvailableModels` |
| **Modele Claude**             | Sonnet 4.6, Opus 4.6 (po 4 warianty każdego)                        | Sonnet 4.6, Opus 4.6 (po 4 warianty każdego)                 |
| **Nazewnictwo Gemini**        | Czytelne etykiety (Low/Medium/High)                                 | Identyfikatory źródłowe (extra-low/low/agent)                |
| **Dodatkowe modele**          | `gpt-oss-120b-medium`                                               | Może zawierać dodatkowe modele Google                        |
| **Domyślny przypadek użycia** | Integracja z IDE (VS Code, JetBrains)                               | Dostęp przez CLI / API                                       |
| **Limit**                     | Współdzielony z agy (to samo konto Google)                          | Współdzielony z antigravity (to samo konto Google)           |

**Dostępne modele (zweryfikowane eksperymentalnie, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (różne poziomy rozumowania)
- Claude: Sonnet 4.6, Opus 4.6 (każdy w wariantach default/low/medium/high)
- Inne: GPT-OSS 120B Medium
- **Claude Sonnet 5 NIE jest dostępny** — obsługiwane są wyłącznie warianty 4.6

**Dlaczego katalog modeli się różni**: Interfejs CLI Google jest „zoptymalizowany pod kątem szybkości i niskiego narzutu” oraz „współoptymalizowany z modelami Gemini” (zgodnie z oficjalnym blogiem Google). Produkt internetowy/IDE jest „zoptymalizowany pod kątem kompleksowości”. CLI używa `:fetchAvailableModels` do dynamicznego wykrywania modeli, natomiast IDE korzysta ze statycznej, wyselekcjonowanej listy.

**W praktyce**: Używaj prefiksu `agy/` dla modeli Gemini (np. `agy/gemini-3.7-flash-high`). Używaj `antigravity/` w przypadku statycznej, wyselekcjonowanej listy. Obaj dostawcy korzystają z tego samego backendu Google, ale udostępniają inne nazewnictwo modeli. Limit jest współdzielony — korzystanie z dowolnego dostawcy wlicza się do tych samych limitów konta Google.

## 2. Google One AI Pro: system limitów

> Oficjalne informacje o limitach znajdziesz w [dokumentacji Antigravity: Plany](https://antigravity.google/docs/plans), a najnowsze zmiany cen — w artykule [Zmiany w planach Antigravity](https://antigravity.google/blog/changes-to-antigravity-plans).

Google Antigravity używa **dwuwarstwowego systemu limitów** opartego na „wykonanej pracy” (obciążeniu obliczeniowym), a nie na liczbie wiadomości.

### Dwie warstwy

| Warstwa                   | Czym jest                      | Cykl odnawiania                                                                                |
| ------------------------- | ------------------------------ | ---------------------------------------------------------------------------------------------- |
| **5-godzinny sprint**     | Bieżąca pula „wykonanej pracy” | Resetuje się 5 godzin po pierwszym żądaniu w sesji                                             |
| **7-dniowy limit bazowy** | Twardy limit tygodniowy        | Po osiągnięciu zastępuje odnowienie 5-godzinne; blokuje dostęp do następnego okresu 7-dniowego |

**Jak obliczana jest „wykonana praca”**: zadania wymagające intensywnego działania agenta (np. „Zrefaktoryzuj całe to repozytorium”) zużywają limit znacznie szybciej niż proste zadania (np. „Napraw tę funkcję”). Nie istnieje pulpit pokazujący zużycie w czasie rzeczywistym.

### Poziomy planów

| Plan         | Cena       | Limit                                | Limit tygodniowy                                |
| ------------ | ---------- | ------------------------------------ | ----------------------------------------------- |
| Free         | $0         | Znaczący limit, odnawiany co tydzień | Tak                                             |
| AI Pro       | $19.99/mo  | Wysoki limit, odnawiany co 5 godzin  | Tak (po osiągnięciu zastępuje limit 5-godzinny) |
| AI Ultra 5x  | $99.99/mo  | 5x limitu Pro                        | Brak limitu tygodniowego                        |
| AI Ultra 20x | $199.99/mo | 20x limitu Pro                       | Brak limitu tygodniowego                        |

### Modele Gemini a modele inne niż Gemini

- **Modele Gemini** (Flash + Pro): współdzielą jeden limit szybkości, zużywany zgodnie z cennikiem API. Jeśli Flash jest 8x tańszy niż Pro, możesz wykorzystać 8x więcej tokenów Flash.
- **Modele inne niż Gemini** (Claude, GPT-OSS): mają **oddzielne** limity szybkości. Mogą pozostać dostępne nawet wtedy, gdy dostęp do Gemini jest zablokowany.

### Kredyty AI (zużycie ponad limit)

> Informacje o działaniu kredytów znajdziesz na stronie [Kredyty Google One AI](https://support.google.com/googleone/answer/14534406).

Po wyczerpaniu limitu bazowego:

- **Nigdy**: oczekuj na odnowienie limitu; wyświetlany jest komunikat „Osiągnięto bazowy limit modelu”
- **Zawsze**: automatycznie używaj kredytów AI; po odnowieniu system ponownie korzysta z limitu bazowego

Kredyty są kupowane oddzielnie i rozliczane według standardowych cen API.

### Kluczowe informacje

- Limit jest **współdzielony na poziomie konta** — to samo konto Google używane w Antigravity IDE, CLI i OmniRoute współdzieli jedną pulę limitu
- Każde konto Google ma własny, niezależny limit — wiele kont = wiele pul limitów
- Użytkownicy AI Pro zgłaszali **7-dniowe blokady** zamiast resetów po 5 godzinach, gdy osiągnięto tygodniowy limit bazowy (Google potwierdziło, że jest to celowe rozwiązanie stosowane przy dużym zapotrzebowaniu)

**Gdy limit konta zostanie wyczerpany**: OmniRoute automatycznie ponawia próbę przy użyciu następnego dostępnego konta w trasie łączonej. Ręczna interwencja nie jest potrzebna.

## 3. Jak uzyskać projectId

Każde połączenie antigravity/agy wymaga `projectId` Google Cloud Code. Bez niego punkt końcowy `/v1internal:models` zwraca błąd 404.

### Metoda A: Automatyczna (zalecana)

OmniRoute obsługuje ten proces automatycznie. Po dodaniu nowego konta Google za pomocą OAuth w panelu:

1. OmniRoute odświeża token
2. Wywołuje `loadCodeAssist`, aby wykryć projectId
3. Jeśli projekt nie istnieje, wywołuje `onboardUser`, aby go utworzyć
4. Ponownie wywołuje `loadCodeAssist`, aby pobrać nowo utworzony projectId
5. Zapisuje go w bazie danych

**Działa to w przypadku większości kont** — nie są wymagane żadne czynności ręczne.

### Metoda B: Ręczna za pomocą agy CLI

Jeśli automatyczne wykrywanie nie powiedzie się (informacje o sytuacjach, w których może to nastąpić, znajdziesz w sekcji 5):

```bash
# Zainstaluj agy CLI (jeśli nie jest jeszcze zainstalowane)
npm install -g @anthropic-ai/agy

# Zaloguj się za pomocą konta Google
agy login

# Wybierz konto, które wymaga wdrożenia
# Spowoduje to rejestrację w Cloud Code i przypisanie projectId
```

Po pomyślnym wykonaniu `agy login` odśwież token w panelu OmniRoute. projectId zostanie wykryty automatycznie.

### Jak zweryfikować

Sprawdź bazę danych:

```bash
# Wewnątrz kontenera OmniRoute
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Możesz też sprawdzić logi:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. Identyfikator URI przekierowania OAuth

### Problem

Google OAuth wymaga prawidłowego identyfikatora URI przekierowania. OmniRoute domyślnie używa `http://127.0.0.1:20128/callback` (adres sprzężenia zwrotnego). Działa to w przypadku lokalnych kompilacji, ale **nie działa we wdrożeniach zdalnych** (np. na serwerze, do którego dostęp uzyskuje się za pośrednictwem adresu IP w sieci LAN).

Google odrzuca identyfikatory URI przekierowania, które:

- Używają adresów IP (wymagana jest domena kończąca się na `.com`, `.org` itd.)
- Nie są zgodne z identyfikatorami URI przekierowania zarejestrowanymi w konfiguracji klienta OAuth

### Rozwiązanie

**Opcja A: Użycie wbudowanego przepływu OAuth (domyślne)**

- Działa, gdy uzyskujesz dostęp do OmniRoute z `localhost` lub `127.0.0.1`
- Nie wymaga konfiguracji

**Opcja B: Niestandardowe dane uwierzytelniające OAuth**

- Ustaw `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` w swoim środowisku
- Podaj własne dane uwierzytelniające Google OAuth:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Zarejestruj `https://your-domain.com/callback` jako autoryzowany identyfikator URI przekierowania w Google Cloud Console

**Opcja C: Użycie interfejsu CLI agy do pierwszego logowania**

- Uruchom `agy login` na komputerze, który będzie uzyskiwać dostęp do OmniRoute
- Przepływ OAuth zostanie ukończony lokalnie, a tokeny zostaną zapisane
- Zaimportuj połączenie do OmniRoute za pośrednictwem panelu

### Ograniczenia

- Niestandardowe dane uwierzytelniające OAuth wymagają nazwy domeny (Google nie akceptuje adresów IP jako identyfikatorów URI przekierowania)
- Jeśli nie masz domeny, użyj zamiast tego opcji A lub C

## 5. Rozwiązywanie problemów: gdy automatyczna konfiguracja nie powiedzie się

OmniRoute automatycznie obsługuje wykrywanie projectId i wdrażanie użytkownika w przypadku większości kont. Gdy proces się nie powiedzie, główną przyczyną jest zwykle jeden z poniższych problemów:

### Region konta jest zablokowany

**Objaw**: `agy login` zwraca komunikat „Eligibility check failed: Your current account is not eligible for Antigravity, because it is not currently available in your location.”

**Główna przyczyna**: Konta Google mają pole zaplecza „Country Association”, które jest ustawiane podczas rejestracji. Interfejs CLI agy i interfejs API Cloud Code rygorystycznie sprawdzają to pole — w przeciwieństwie do internetowej wersji Gemini, która sprawdza wyłącznie bieżący adres IP.

> Aby sprawdzić lub zmienić region powiązany z kontem, odwiedź [formularz powiązania kraju Google](https://policies.google.com/country-association-form).

**Dlaczego internetowa wersja Gemini działa, a agy nie**:

- Internetowa wersja Gemini / Google One: sprawdza wyłącznie bieżący adres IP (serwer proxy umożliwia przejście weryfikacji)
- Interfejs CLI agy / interfejs API Cloud Code: odczytuje pole zaplecza „Country Association” (serwer proxy nie pomaga)

**Rozwiązanie**:

1. Odwiedź [formularz powiązania kraju Google](https://policies.google.com/country-association-form), korzystając z amerykańskiego adresu IP
2. Prześlij wniosek o zmianę regionu (wybierz „I live in a different country”)
3. Poczekaj 1–24 godziny na przetworzenie wniosku przez Google i otrzymanie powiadomienia e-mail
4. Następnie polecenie `agy login` powinno zakończyć się powodzeniem

### Konto nie ma projektu Cloud Code

**Objaw**: W dziennikach widoczne są komunikaty `loadCodeAssist returned no project id` i `onboardUser failed (400)`.

**Główna przyczyna**: Konto nigdy nie zostało zarejestrowane w Google Cloud Code, a automatyczne wdrażanie użytkownika nie powiodło się.

**Rozwiązanie**: Uruchom ręcznie `agy login`, aby zainicjować rejestrację w Cloud Code, a następnie odśwież token w panelu OmniRoute.

### Token wygasł lub został unieważniony

**Objaw**: Błędy 401 w dziennikach lub komunikaty „Token has expired”.

**Rozwiązanie**: Odśwież token w sekcji Panel → Dostawcy → agy → kliknij ikonę odświeżania. Jeśli sam token odświeżania został unieważniony, konieczne będzie ponowne uwierzytelnienie za pośrednictwem OAuth.

## Schemat decyzyjny

```
Konto nie działa?
│
├─ Czy ma projectId w bazie danych?
│  ├─ TAK → Problem leży gdzie indziej (token wygasł, limit żądań itp.)
│  └─ NIE ↓
│
├─ Czy ustawienie Country Association konta wskazuje region objęty ograniczeniami?
│  ├─ TAK → Zmień region w formularzu Google Country Association
│  │         (https://policies.google.com/country-association-form)
│  │         Poczekaj 1–24 godziny, a następnie spróbuj ponownie
│  └─ NIE ↓
│
├─ Czy konto ma subskrypcję Google One AI Pro?
│  ├─ NIE → Najpierw wykup subskrypcję na one.google.com
│  └─ TAK ↓
│
├─ Spróbuj automatycznego wykrywania (odśwież token w Panelu)
│  ├─ Działa → Gotowe
│  └─ Nadal nie działa ↓
│
└─ Ręcznie: uruchom `agy login` na komputerze
   ├─ Działa → Odśwież token w Panelu; projectId zostanie wykryty
   └─ Nie działa → Sprawdź komunikat o błędzie; prawdopodobnie problem dotyczy regionu lub subskrypcji
```
