`devin-cli-agentic` umożliwia rzeczywistemu środowisku wykonawczemu Claude Code korzystanie z lokalnego
punktu końcowego Anthropic Messages platformy OmniRoute, podczas gdy oficjalny Devin CLI dostarcza odpowiedzi
modelu przez ACP stdio. Nie modyfikuje istniejących dostawców Anthropic, Claude OAuth,
Claude Web ani `devin-cli`.

> **Bieżący stan: przypięta wersja Claude Code `2.1.258`; ostatnią walidację offline i na żywo
> zarejestrowano dla wersji `2.1.220`.** Przypięta wersja `2.1.220` ukończyła trzy odizolowane scenariusze za pośrednictwem Devin CLI
> `3000.2.17` i modelu `swe-1-7-lightning`; ten końcowy test na żywo potwierdził obsługiwane przez klienta operacje `Read`,
> `Edit` i `Bash`, pomyślne wyniki `npm test`, wykrywanie poleceń i umiejętności
> projektu, routing wyłącznie przez Devin oraz brak jakiegokolwiek ruchu wychodzącego do Claude. Następnie przypiętą wersję podniesiono do `2.1.258`
> (generacji CLI, pod którą podszywa się tożsamość Claude w OmniRoute, oraz pierwszej linii natywnie zawierającej
> warstwę Fable 5.1). Dla nowej przypiętej wersji zweryfikowano warstwę instalacyjną i `claude --version`
> na przypiętym obrazie bazowym, a zestaw testów jednostkowych mostu, `compose config` oraz
> statyczny dowód izolacji przechodzą pomyślnie — jednak scenariusz z atrapą offline i zestaw trzech scenariuszy
> na żywo nie zostały jeszcze uruchomione ponownie. Uruchom je ponownie (zobacz „Aktualizowanie przypiętych narzędzi”), zanim zaczniesz polegać na
> moście z tą przypiętą wersją.

## Architektura

```text
Claude Code 2.1.258 (odizolowany kontener Linux bez uprawnień roota)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (dostawca w formacie Claude, bez uwierzytelniania)
  -> devin acp --agent-type summarizer (oficjalne ACP stdio, bez narzędzi Devin)
  -> konto Devin w dedykowanym woluminie devin-auth
```

Domyślny agent ACP oficjalnego CLI może wykonywać własne narzędzia, dlatego ten most go nie używa.
Uruchamia stałego agenta ACP `summarizer`, którego oficjalny tryb CLI nie ma narzędzi, i
oprawia zserializowane żądanie Anthropic jako ślad wykonania. Gdy potrzebna jest kolejna akcja
obsługiwana przez Claude, odpowiedź musi zawierać dokładnie jedną kliencką kopertę narzędzia. Każde
`tool_call` lub `tool_call_update` ACP jest odrzucane, zanim odpowiedź będzie mogła zostać zgłoszona jako
pomyślna.

Serializator w `open-sse/executors/devin-agentic/serializer.ts` zachowuje `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` oraz
narzędzia dostarczone przez Claude Code. Obrazy i nieznane bloki powodują jawny błąd. Duże wyniki narzędzi
otrzymują widoczny znacznik obcięcia.

Parser akceptuje jedną samodzielną kopertę `<tool>{...}</tool>` na turę modelu. Sprawdza
nazwę względem listy narzędzi w żądaniu, waliduje argumenty względem schematu JSON tego narzędzia,
odrzuca połączenie narracji z akcjami i zezwala na jedną ograniczoną próbę naprawy. Następnie Claude Code
wykonuje wynikowe `tool_use` Anthropic lokalnie i odsyła `tool_result` przez
OmniRoute.

## Izolacja i model zagrożeń

Instalacja, konto i konfiguracja Claude na hoście znajdują się poza zakresem i są traktowane jako
niedozwolone. Usługi Compose:

- działają jako UID/GID `10001:10001`, z systemem plików root tylko do odczytu, usuniętymi uprawnieniami i
  ustawieniem `no-new-privileges`;
- używają prywatnego katalogu `/home/bridge`, dedykowanego woluminu konfiguracji Claude, odizolowanych danych OmniRoute
  oraz osobnego woluminu `devin-auth`;
- montują wyłącznie jednorazowe przestrzenie robocze i dane dowodowe `.sandbox`;
- nie montują katalogu domowego hosta, pęku kluczy, SSH, poświadczeń chmurowych ani gniazda Docker;
- tworzą jawne środowiska i usuwają zmienne interfejsu API, OAuth i routingu Anthropic;
- kierują wnioskowanie Claude Code wyłącznie do `http://omniroute:20128` z kluczem tylko do użytku lokalnego.

Profil offline korzysta z sieci wewnętrznej. W profilu na żywo OmniRoute łączy się z
oficjalnymi punktami końcowymi Devin wyłącznie przez `network-guard`; niepowiązane miejsca docelowe są blokowane.
Claude Code ma osobną zaporę blokującą cały ruch wychodzący i może uzyskać dostęp wyłącznie do lokalnej usługi OmniRoute
przez `NO_PROXY`. Pliki audytu zapór są montowane wyłącznie przez odpowiadający im proces zapory.
Skrypty weryfikują własność plików, tryb, liczbę dowiązań oraz każdą decyzję przed wyeksportowaniem
danych dowodowych pozbawionych tokenów.

Uruchom dowód izolacji niezależnie:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

Waliduje on topologię, nazwane punkty montowania, ustawienia użytkownika bez uprawnień roota i tylko do odczytu, jawny routing lokalny,
brak poufnych zmiennych środowiskowych, brak gniazda Docker, zablokowany dostęp do
`api.anthropic.com` i `claude.ai`, wybór dostawcy wyłącznie Devin oraz jawny błąd w przypadku
niedostępności backendu ACP.

## Pierwsza konfiguracja i zwykłe użycie

Zbuduj obraz z przypiętymi wersjami:

```bash
./scripts/devin-bridge/build
```

Uwierzytelnij tylko izolowany wolumin Devin:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

Polecenie logowania korzysta z oficjalnego przepływu z ręcznym tokenem, przeznaczonego dla środowisk zdalnych/kontenerowych. Wartość jest wprowadzana bezpośrednio w monicie CLI; nie jest przekazywana jako argument procesu, zapisywana w Git ani kopiowana z hosta.

Uruchom izolowane środowisko wykonawcze Claude Code:

```bash
./scripts/devin-bridge/launch
```

`launch` przed uruchomieniem Claude Code w kontenerze ponownie sprawdza izolację, uwierzytelnienie Devin i wykrywanie modeli. Nigdy nie uruchamia pliku wykonywalnego Claude z hosta. Aliasy modeli można ustawić w `.env.devin-bridge`; każda skonfigurowana wartość musi zachować prefiks `devin-cli-agentic/`.

## Polecenia walidacyjne

Powtarzalna ścieżka offline nie wymaga konta Devin i nie korzysta z Internetu podczas działania:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

Opcjonalna, uwierzytelniona ścieżka online to:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

Moduł uruchamiający testy online czeka między scenariuszami, aby uniknąć seryjnego otwierania sesji ACP, i weryfikuje ustrukturyzowane zdarzenia strumienia Claude zamiast polegać na deklaracjach tekstowych. Jego trzy scenariusze potwierdzają:

1. bezpośredni odczyt projektu i analizę defektów;
2. rzeczywistą operację `Edit`, należące do klienta polecenie `Bash` `npm test` oraz wynik końcowy;
3. wykrywanie `/bridge-check` oraz `bridge-proof`, odczyt projektu, kolejny pomyślny test `npm test` należący do klienta oraz zakończenie bez oczekujących zadań.

Końcowa bramka sprawdza również audyt sieci Devin i wymaga, aby audyt ruchu wychodzącego Claude pozostał pusty.

## Aktualizowanie przypiętych narzędzi

Obraz przypina wersje Node, Claude Code i Devin CLI w pliku `docker/devin-bridge/Dockerfile`. Aby je zaktualizować:

1. zmień jawnie określone wersje;
2. zastąp sumy kontrolne archiwów Devin dla obu architektur wartościami odpowiadającymi oficjalnemu artefaktowi;
3. przebuduj obraz i uruchom wszystkie polecenia walidacyjne offline;
4. potwierdź wersje wewnątrz obrazu;
5. ponownie uruchom uwierzytelniony zestaw trzech scenariuszy online.

Nie instaluj żadnego z tych CLI globalnie na hoście ani nie zastępuj weryfikacji sum kontrolnych niezweryfikowanym pobieraniem.

## Diagnostyka i czyszczenie

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  wyświetla lokalne trasowanie i oczyszczone błędy modułu wykonawczego.
- `.sandbox/evidence/mock-acp.jsonl` rejestruje deterministyczne pozorowane działania ACP.
- `.sandbox/evidence/claude-stream.jsonl` rejestruje rzeczywiste uruchomienie Claude Code offline.
- `.sandbox/evidence/live-*.jsonl` rejestruje trzy zweryfikowane strumienie online.
- `.sandbox/evidence/egress.jsonl` i `.sandbox/evidence/claude-egress.jsonl` są zweryfikowanymi, pozbawionymi tokenów kopiami audytów mechanizmu ochronnego.

Zatrzymaj należące do rozwiązania kontenery i sieci, zachowując woluminy logowania/konfiguracji:

```bash
./scripts/devin-bridge/clean
```

Usuń całe środowisko należące do mostu, w tym nazwane woluminy:

```bash
./scripts/devin-bridge/clean --all
```

## Ograniczenia

- Most opiera się na stałej roli `summarizer` bez narzędzi, ponieważ Devin CLI `3000.2.17`
  nie udostępnia neutralnego agenta ACP bez narzędzi. Adapter kompensuje odpowiedzi pośrednie
  mające formę podsumowania, ale pojedyncza ograniczona próba naprawy nadal może jawnie zakończyć się niepowodzeniem.
- Wywołania ACP na żywo mogą zwracać przejściowe odpowiedzi `502`/`504`. Mechanizm testowy rozdziela scenariusze
  w czasie; trwała awaria pozostaje obsłużona zgodnie z zasadą fail-closed i nigdy nie powoduje wybrania innego dostawcy.
- Kontekst ACP jest rekonstruowany na podstawie każdego żądania Anthropic; nie istnieje
  koligacja z procesem ani sesją.
- Obsługiwane jest jedno wywołanie narzędzia na odpowiedź modelu; wywołania równoległe są odrzucane.
- Obrazy nie są jawnie obsługiwane. Funkcje wizyjne, dane wyjściowe procesu rozumowania, ustawienia nakładu obliczeniowego oraz okno kontekstu o rozmiarze 1M
  nie są deklarowane jako dostępne.
- SSE używa prawidłowych zdarzeń cyklu życia Anthropic, ale są one emitowane po zebraniu ograniczonej tury ACP;
  fragmenty ACP nie są przekazywane przyrostowo.
