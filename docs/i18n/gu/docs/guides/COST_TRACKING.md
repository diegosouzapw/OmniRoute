OmniRoute દરેક વિનંતીની કિંમતનો અંદાજ કેવી રીતે લગાવે છે, તેને રેકોર્ડ કરે છે અને તેનો અહેવાલ આપે છે — અને શા માટે
ડૅશબોર્ડ પરનો આંકડો બિલ નહીં, પરંતુ **બચત ટ્રૅકર** છે.

આ પણ જુઓ: [વપરાશકર્તા માર્ગદર્શિકા](./USER_GUIDE.md) · [સુવિધાઓની ગૅલેરી](./FEATURES.md)

## તે શું છે (અને શું નથી)

OmniRoute ટોકનની સંખ્યાને મોડેલના કિંમત દરો વડે ગુણાકાર કરીને દરેક પૂર્ણતા માટે
પ્રતિ-વિનંતી USD કિંમત નક્કી કરે છે. આ આંકડાઓ **ખર્ચ** ડૅશબોર્ડ,
`omniroute cost` / `omniroute usage` CLI, CSV/JSON નિકાસો અને પ્રતિ-API-કી બજેટને આધાર આપે છે.

> **ડૅશબોર્ડ પરનો "ખર્ચ" બચત ટ્રૅકર છે, બિલ નહીં.** OmniRoute તમારી પાસેથી ક્યારેય શુલ્ક લેતું નથી
> — તે તમારી વિનંતીઓને તમે અગાઉથી કનેક્ટ કરેલા પ્રદાતાઓ તરફ રૂટ કરે છે (તમારા પોતાના
> સબ્સ્ક્રિપ્શન, મફત ટિયર અને API કીઓ). સંપૂર્ણપણે મફત મોડેલો પર એકત્ર થયેલો "$290 કુલ ખર્ચ"
> એટલે અંદાજે **$290 જે તમે કોઈ સશુલ્ક APIને ચૂકવ્યા _નથી_**. આ આંકડો એ જ ટ્રાફિક માટે
> માનક સૂચિ કિંમતો અનુસાર લાગ્યા હોત એવા ખર્ચનો _અંદાજ_ છે, જેથી તમે જોઈ શકો કે
> તમારો ઉપયોગ ક્યાં કેન્દ્રિત છે અને સસ્તા/મફત પ્રદાતાઓ તરફ રૂટિંગ કરવાથી તમને કેટલી બચત થઈ રહી છે.

આ અભિગમ પ્રોજેક્ટના [README](../../README.md)માં સીધો જણાવવામાં આવ્યો છે ("ડૅશબોર્ડ પરનો
'ખર્ચ' બચત ટ્રૅકર છે, બિલ નહીં").

આ આંકડો અંદાજ હોવાથી:

- તે દરેક મોડેલ માટે OmniRoute પાસે રહેલા કિંમત કોષ્ટક પર આધાર રાખે છે. જે મોડેલ માટે કિંમતની
  એન્ટ્રી નથી તે `0` ખર્ચ ઉમેરે છે (એક્સપ્લોરરમાં તે "લેગસી / મફત" પંક્તિ તરીકે દેખાય છે).
- મફત-ટિયર અને સબ્સ્ક્રિપ્શન ટ્રાફિક માટે પણ _અંદાજિત_ ખર્ચ ઉમેરાય છે — તે
  તમારી બચતની રકમ છે, ચૂકવવાની બાકી રકમ નહીં.

## ખર્ચનો અંદાજ કેવી રીતે લગાવવામાં આવે છે

### કિંમતનો સ્રોત

ખર્ચ નીચે આપેલા અગ્રતા ક્રમ પ્રમાણે નિર્ધારિત કિંમત કોષ્ટકમાંથી આવે છે
([`src/lib/pricingSync.ts`](../../src/lib/pricingSync.ts)):

1. **વપરાશકર્તા ઓવરરાઇડ્સ** — તમે ડૅશબોર્ડમાં / `PATCH /api/pricing` દ્વારા નક્કી કરેલી કિંમતો.
2. **સિંક કરેલી બાહ્ય કિંમતો** — જ્યારે સિંક સક્ષમ હોય ત્યારે LiteLLMના જાહેર
   `model_prices_and_context_window.json`માંથી મેળવેલી (અલગ `pricing_synced`
   નેમસ્પેસમાં સંગ્રહિત થાય છે, જેથી તે તમારા ઓવરરાઇડ્સને ક્યારેય બદલે નહીં).
3. **હાર્ડકોડ કરેલા ડિફૉલ્ટ્સ** — OmniRoute સાથે પૂરા પાડવામાં આવે છે.

બાહ્ય કિંમત સિંક **ઑપ્ટ-ઇન** છે અને ડિફૉલ્ટ રૂપે અક્ષમ છે. સંબંધિત env vars
([`.env.example`](../../.env.example) જુઓ):

| Env var                 | ડિફૉલ્ટ   | હેતુ                                                                  |
| ----------------------- | --------- | --------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`   | સ્ટાર્ટઅપ સમયે બૅકગ્રાઉન્ડ LiteLLM કિંમત સિંક સક્ષમ કરે છે.           |
| `PRICING_SYNC_INTERVAL` | `86400`   | **સેકન્ડમાં** સિંક અંતરાલ (ડિફૉલ્ટ રૂપે દૈનિક).                       |
| `PRICING_SYNC_SOURCES`  | `litellm` | અલ્પવિરામથી અલગ કરેલી સ્રોત સૂચિ (હાલમાં માત્ર `litellm` સમર્થિત છે). |

### ખર્ચનું સૂત્ર

ટોકનની સંખ્યા અને પ્રતિ-મિલિયન-ટોકન દરોના આધારે દરેક વિનંતી માટે ખર્ચની ગણતરી
[`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts)માં
(`computeCostFromPricing` / `calculateCost`) કરવામાં આવે છે:

- **ઇનપુટ ટોકન્સ** (કૅશ રીડ્સ અને કૅશ-નિર્માણ ટોકન્સ બાદ કરીને) × `input` દર.
- **કૅશ-રીડ ટોકન્સ** × `cached` દર (ન હોય તો ઇનપુટ દર વપરાય છે).
- **કૅશ-નિર્માણ ટોકન્સ** × `cache_creation` દર (ન હોય તો ઇનપુટ દર વપરાય છે).
- **આઉટપુટ ટોકન્સ** × `output` દર.
- **રીઝનિંગ ટોકન્સ** × `reasoning` દર (ન હોય તો આઉટપુટ દર વપરાય છે).

બધા દરોને પ્રતિ 1,000,000 ટોકન USD તરીકે સમજવામાં આવે છે. Codex "fast"/"priority" અથવા
"flex" સર્વિસ ટિયર ખર્ચ ગુણક (`getCodexFastCostMultiplier`) લાગુ કરે છે — ઉદાહરણ તરીકે, flex માટે
ટોકન ખર્ચમાં 50% છૂટ સાથે બિલિંગ થાય છે, જે ડૅશબોર્ડમાં **flex બચત** તરીકે દર્શાવવામાં આવે છે.

મોડેલનાં નામ પહેલાં સામાન્યકૃત કરવામાં આવે છે (`openai/` અથવા
`accounts/fireworks/models/` જેવા પ્રદાતા-પાથ પ્રીફિક્સ દૂર કરવામાં આવે છે), જેથી ઐતિહાસિક પંક્તિઓ હજુ પણ કિંમત સાથે મેળ ખાય.

### ખર્ચ કેવી રીતે રેકોર્ડ થાય છે

- પ્રતિ-વિનંતી ખર્ચની ગણતરી પ્રતિસાદ પછી થાય છે અને તે ક્લાયન્ટ માટે ક્યારેય વિલંબ ન વધારે તે માટે
  fire-and-forget રીતે રેકોર્ડ થાય છે. વહેંચાયેલા ક્વોટાનો વપરાશ આગલા
  event-loop tick પર [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts) દ્વારા શેડ્યૂલ કરવામાં આવે છે.
- API-કી ખર્ચને બફર કરીને
  [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) દ્વારા બૅચમાં ફ્લશ કરવામાં આવે છે (ડિફૉલ્ટ 60s ફ્લશ અંતરાલ,
  1,000-એન્ટ્રી બફર). તેને આના દ્વારા સમાયોજિત કરી શકાય છે:

  | Env var                             | ડિફૉલ્ટ | હેતુ                                            |
  | ----------------------------------- | ------- | ----------------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000` | મિલિસેકન્ડમાં ફ્લશ અંતરાલ.                      |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`  | ફ્લશ પહેલાં બફર કરેલી એન્ટ્રીઓની મહત્તમ સંખ્યા. |

ડૅશબોર્ડના ખર્ચના આંકડા સંગ્રહિત પ્રતિ-પંક્તિ ડૉલર રકમમાંથી **વાંચવામાં આવતા નથી** — જ્યારે પણ
એનાલિટિક્સ એન્ડપોઇન્ટ ચાલે છે ત્યારે ટોકનની સંખ્યા અને વર્તમાન કિંમત કોષ્ટક પરથી તેમની ફરીથી
ગણતરી કરવામાં આવે છે. તેનો અર્થ એ છે કે ખોટી કિંમત સુધારવાથી (અને ફરીથી સિંક કરવાથી)
ઐતિહાસિક ખર્ચ અંદાજો પૂર્વપ્રભાવી રીતે અપડેટ થાય છે.

## ડૅશબોર્ડ: ખર્ચ પેજ

**ખર્ચ** પેજ `/dashboard/costs` પર આવેલું છે
(`src/app/(dashboard)/dashboard/costs/`).
તેનું મુખ્ય દૃશ્ય **ખર્ચ ઝાંખી** ટૅબ છે
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`),
જે `GET /api/usage/analytics` માંથી બધું લોડ કરે છે.

તે શું દર્શાવે છે:

- **ખર્ચ ટાઇલ્સ** — _આજે (1d)_, _7d_, _30d_ અને પસંદ કરેલી
  સમયમર્યાદા માટેનો અંદાજિત ખર્ચ. શ્રેણી પસંદગીકાર: `7d`, `30d`, `90d`, `all`.
- **મુખ્ય મેટ્રિક્સ** — સમયમર્યાદામાં વિનંતીઓ, સક્રિય પ્રદાતાઓ, સક્રિય મોડેલો અને પ્રતિ
  વિનંતી સરેરાશ ખર્ચ.
- **ખર્ચ એક્સપ્લોરર** — **પ્રદાતા**, **મોડેલ**,
  **API કી**, **એકાઉન્ટ** અથવા **સેવા સ્તર** પ્રમાણે જૂથબદ્ધ કરી શકાય તેવું, સૉર્ટ/ફિલ્ટર કરી શકાય એવું ટેબલ, જેમાં ખર્ચ, વિનંતીઓ, ટોકન્સ, સરેરાશ
  ખર્ચ/વિનંતી અને કુલ ખર્ચમાં ટકાવારી હિસ્સો હોય છે.
- **ટોકન વપરાશ** — કુલ / ઇનપુટ / આઉટપુટ ટોકન્સ અને ઇનપુટ:આઉટપુટ ગુણોત્તર.
- **રૂટિંગ કાર્યક્ષમતા** — ફૉલબૅક સંખ્યા, ફૉલબૅક દર અને વિનંતી કરાયેલા મોડેલનું કવરેજ.
- **માસિક પૂર્વાનુમાન** — તાજેતરની દૈનિક સરેરાશના આધારે મહિનાના અંત સુધીના ખર્ચનો અંદાજ લગાવે છે.
- **સમયગાળા સરખામણી** — સમયમર્યાદાના પહેલા અને બીજા અર્ધભાગ વચ્ચેનો % ફેરફાર.
- **ચાર્ટ્સ** — દૈનિક ખર્ચ વલણ, પ્રદાતા હિસ્સો (પાઇ), ટોચના પ્રદાતાઓ, ટોચના મોડેલો, API કી પ્રમાણે ખર્ચ, એકાઉન્ટ પ્રમાણે ખર્ચ, સાપ્તાહિક વપરાશ પેટર્ન અને પ્રવૃત્તિ હીટમૅપ.
- **નિકાસ** — વર્તમાન સમયમર્યાદાને **CSV** અથવા **JSON** તરીકે ડાઉનલોડ કરો (શૂન્ય કરતાં વધુ ખર્ચનો ડેટા હોય ત્યારે
  બટનો દેખાય છે).

જ્યારે કિંમત નિર્ધારિત ટ્રાફિક ન હોય, ત્યારે પંક્તિઓ `$0` ને બદલે "લેગસી / મફત" લેબલ તરીકે રેન્ડર થાય છે,
જે બચત-ટ્રૅકર મોડેલને પ્રતિબિંબિત કરે છે.

### ખર્ચ સંબંધિત ઉપપૃષ્ઠો

ખર્ચ વિભાગમાં આ પણ સામેલ છે (બધાં `/dashboard/costs/` હેઠળ):

- **કિંમત નિર્ધારણ** (`/dashboard/costs/pricing`) — પ્રતિ-મોડેલ કિંમતો જુઓ અને ઓવરરાઇડ કરો (શેર કરેલો Pricing ટૅબ
  રેન્ડર કરે છે).
- **બજેટ** (`/dashboard/costs/budget`) — પ્રતિ-સ્કોપ ખર્ચ મર્યાદાઓ સેટ કરો (શેર કરેલો
  Budget ટૅબ રેન્ડર કરે છે).
- **ક્વોટા શેર** (`/dashboard/costs/quota-share`) — શેર કરેલા ક્વોટા પૂલ્સ અને ખર્ચ-દર
  દૃશ્યો.

## API એન્ડપૉઇન્ટ્સ

નોંધ ન કરાઈ હોય ત્યાં સુધી આ બધાં માટે મેનેજમેન્ટ પ્રમાણીકરણ (લૂપબૅક/JWT, `requireManagementAuth` મારફતે)
જરૂરી છે.

### વપરાશ અને ખર્ચ વિશ્લેષણ

| પદ્ધતિ | એન્ડપૉઇન્ટ               | હેતુ                                                                                                                                                        |
| ------ | ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`  | `/api/usage/analytics`   | સંપૂર્ણ ખર્ચ/વપરાશ વિશ્લેષણ: સારાંશ, દૈનિક વલણ, પ્રદાતા/મોડેલ/API કી/એકાઉન્ટ/સ્તર પ્રમાણે. ક્વેરી: `range`, `startDate`, `endDate`, `apiKeyIds`, `presets`. |
| `GET`  | `/api/usage/utilization` | સમય સાથે પ્રતિ-પ્રદાતા ક્વોટાનો ઉપયોગ. ક્વેરી: `range` (`1h`/`24h`/`7d`/`30d`), `provider`.                                                                 |
| `GET`  | `/api/usage/history`     | અપરિષ્કૃત વપરાશ ઇતિહાસની પંક્તિઓ.                                                                                                                           |
| `GET`  | `/api/usage/call-logs`   | પ્રતિ-વિનંતી કૉલ લૉગ્સ (મોડેલ, ટોકન્સ, ખર્ચ, વિલંબ, સ્થિતિ).                                                                                                |
| `GET`  | `/api/usage/quota`       | પ્રદાતા ક્વોટાની સ્થિતિ.                                                                                                                                    |
| `GET`  | `/api/usage/proxy-logs`  | પ્રૉક્સી વિનંતી લૉગ્સ.                                                                                                                                      |

### બજેટ્સ

| પદ્ધતિ | એન્ડપૉઇન્ટ               | હેતુ                                                                       |
| ------ | ------------------------ | -------------------------------------------------------------------------- |
| `GET`  | `/api/usage/budget`      | એક API કી માટે ખર્ચ સારાંશ + બજેટ તપાસ (`apiKeyId` ક્વેરી પેરામ જરૂરી).    |
| `POST` | `/api/usage/budget`      | API કી માટે દૈનિક/સાપ્તાહિક/માસિક USD મર્યાદાઓ + ચેતવણી થ્રેશોલ્ડ સેટ કરો. |
| `GET`  | `/api/usage/budget/bulk` | API કીઓમાં બલ્ક બજેટ સારાંશ.                                               |

> બજેટ API પ્રતિ **API કી** (`apiKeyId`) સ્કોપ થયેલ છે. આના દ્વારા પરત મળતી મર્યાદાઓ
> `GET /api/usage/budget` માં `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`,
> એક `warningThreshold` અને ચાલુ કુલ રકમો (`totalCostToday`, `totalCostMonth`, …) સામેલ છે.

### કિંમત નિર્ધારણ

## CLI

OmniRouteનું CLI ખર્ચ, વપરાશ અને કિંમત નિર્ધારણના આદેશો ઉપલબ્ધ કરાવે છે (જે
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)માં નોંધાયેલા છે).

### `omniroute cost`

`/api/usage/analytics`માંથી એકત્રિત કરાયેલ ખર્ચ અહેવાલ.

```bash
omniroute cost                          # છેલ્લા 30d, provider પ્રમાણે જૂથીકૃત
omniroute cost --period 7d              # છેલ્લા 7 દિવસ
omniroute cost --group-by model         # provider | model | combo | api-key | day પ્રમાણે જૂથીકૃત કરો
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

કૉલમ: જૂથ, વિનંતીઓ, ઇનપુટ/આઉટપુટ ટોકન, ખર્ચ (USD) અને કુલના %. અંતે એકંદર કુલની પંક્તિ
છાપવામાં આવે છે (`--quiet` અથવા `--output json` વડે તેને દબાવી શકાય છે).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # provider-દીઠ ખર્ચનો સારાંશ
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# બજેટ
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show`, `GET /api/pricing/defaults`માંથી માહિતી વાંચે છે. તેના બદલે વ્યક્તિગત modelની
> કિંમતો સંપાદિત કરવા માટે, **Pricing** dashboard પેજ અથવા `PATCH /api/pricing`નો ઉપયોગ કરો.

## સમસ્યાનિવારણ

- **તમામ ખર્ચ $0 / "Legacy / Free" દર્શાવે છે.** ઉપયોગમાં રહેલા models માટે કિંમતની કોઈ એન્ટ્રી નથી.
  બાહ્ય sync સક્ષમ કરો (`PRICING_SYNC_ENABLED=true`) અને `omniroute pricing sync` ચલાવો, અથવા
  Pricing પેજ / `PATCH /api/pricing` દ્વારા કિંમતો મેન્યુઅલી સેટ કરો.
- **ઐતિહાસિક modelની કિંમત ખોટી છે.** કિંમત સુધારો (override કરો અથવા ફરી sync કરો) — analytics વાંચવામાં આવે ત્યારે દર વખતે
  tokenની સંખ્યાના આધારે ખર્ચની ફરી ગણતરી થાય છે, તેથી અંદાજો ભૂતકાળ માટે પણ અપડેટ થાય છે.
- **ખર્ચ વાસ્તવિક સમય કરતાં પાછળ રહે છે.** કી-દીઠ ખર્ચ batchમાં પ્રક્રિયા થાય છે; જો તમને વધુ તાજા આંકડાની જરૂર હોય તો
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` ઘટાડો.
