> **સત્યનો અધિકૃત સ્રોત:** `electron/` વર્કસ્પેસ
> **છેલ્લે અપડેટ કરેલું:** 2026-06-28 — v3.8.40

OmniRoute, **Electron 41** + **electron-builder 26.10** પર બનેલી ક્રોસ-પ્લેટફોર્મ ડેસ્કટૉપ ઍપ (Windows / macOS / Linux) પ્રદાન કરે છે. ડેસ્કટૉપ ઍપ Next.js સ્ટૅન્ડઅલોન સર્વરને ચાઇલ્ડ પ્રોસેસ તરીકે શરૂ કરે છે, તેના તરફ `BrowserWindow` નિર્દેશિત કરે છે અને સિસ્ટમ ટ્રે, ઑટો-અપડેટર, IPC બ્રિજ તથા ઝીરો-કન્ફિગ સિક્રેટ બુટસ્ટ્રૅપ ઉમેરે છે.

## આર્કિટેક્ચર

```
┌──────────────────────────────────────────────┐
│ Electron મુખ્ય પ્રોસેસ (electron/main.js)    │
│ ├─ સિંગલ-ઇન્સ્ટન્સ લૉક                      │
│ ├─ ચાઇલ્ડ પ્રોસેસ: Next.js સ્ટૅન્ડઅલોન સર્વર│
│ │   (Electronના Node રનટાઇમથી શરૂ કરેલો)    │
│ ├─ BrowserWindow → http://localhost:PORT     │
│ ├─ સિસ્ટમ ટ્રે + કૉન્ટેક્સ્ટ મેનૂ            │
│ ├─ electron-updater દ્વારા ઑટો-અપડેટ         │
│ ├─ કન્ટેન્ટ સિક્યુરિટી પૉલિસી (સેશન હેડર્સ) │
│ └─ સિક્રેટ બુટસ્ટ્રૅપ (JWT / API_KEY_SECRET) │
└──────────────────────────────────────────────┘
            ↕ IPC બ્રિજ (electron/preload.js)
┌──────────────────────────────────────────────┐
│ રેન્ડરર (Next.js ડૅશબોર્ડ)                   │
│   window.electronAPI.* (contextIsolation)     │
└──────────────────────────────────────────────┘
```

- `npm run pack` — સ્થાનિક પરીક્ષણ માટે માત્ર-ડિરેક્ટરી બિલ્ડ (ઇન્સ્ટૉલર વિના)

## IPC બ્રિજ (`preload.js`)

પ્રીલોડ `contextIsolation: true` અને `nodeIntegration: false` સાથે `contextBridge`
નો ઉપયોગ કરીને `window.electronAPI` પર વ્હાઇટલિસ્ટ કરેલી API ઉપલબ્ધ કરાવે છે.

```javascript
const VALID_CHANNELS = {
  invoke: [
    "get-app-info",
    "open-external",
    "get-data-dir",
    "restart-server",
    "check-for-updates",
    "download-update",
    "install-update",
    "get-app-version",
  ],
  send: ["window-minimize", "window-maximize", "window-close"],
  receive: ["server-status", "port-changed", "update-status"],
};
```

ઉપલબ્ધ કરાવેલી મેથડ્સ:

| રેન્ડરર કૉલ                                                       | પ્રકાર                        |
| ----------------------------------------------------------------- | ----------------------------- |
| `getAppInfo()` → `{ name, version, platform, isDev, port }`       | invoke                        |
| `openExternal(url)`                                               | invoke                        |
| `getDataDir()`                                                    | invoke                        |
| `restartServer()`                                                 | invoke                        |
| `getAppVersion()`                                                 | invoke                        |
| `checkForUpdates()` / `downloadUpdate()` / `installUpdate()`      | invoke                        |
| `minimizeWindow()` / `maximizeWindow()` / `closeWindow()`         | send                          |
| `onServerStatus(cb)` / `onPortChanged(cb)` / `onUpdateStatus(cb)` | receive (ડિસ્પોઝર પરત કરે છે) |

રિસીવ હેલ્પર્સ `removeAllListeners` પર આધાર રાખવાને બદલે **ડિસ્પોઝર ફંક્શન**
પરત કરે છે — React કમ્પોનન્ટ્સ ફરી માઉન્ટ થાય ત્યારે આ લિસનર્સનો સંગ્રહ થતો અટકાવે છે.

## સર્વર લાઇફસાઇકલ

સિસ્ટમ Node સાથે નેટિવ-મોડ્યુલ ABI અસંગતતા ટાળવા માટે `main.js`, Electron Node
રનટાઇમ વડે Next.js સ્ટેન્ડઅલોન બંડલને સીધું સ્પૉન કરે છે:

```js
spawn(process.execPath, [serverScript], {
  cwd: NEXT_SERVER_PATH,
  env: {
    ...serverEnv,
    PORT,
    NODE_ENV: "production",
    ELECTRON_RUN_AS_NODE: "1",
    NODE_PATH,
  },
  stdio: "pipe",
});
```

મુખ્ય વિશેષતાઓ:

- વિન્ડો દર્શાવતા પહેલાં `waitForServer()` 30 s સુધી URLને પોલ કરે છે (કોલ્ડ સ્ટાર્ટ વખતે ખાલી સ્ક્રીન દેખાતી નથી).
- `stdio: "pipe"` stdout/stderrને કૅપ્ચર કરે છે; તૈયાર હોવાનો સંકેત આપતા શબ્દસમૂહો (`Ready` / `listening`) IPC પર `server-status: running` ઉત્સર્જિત કરે છે.
- `before-quit` સુવ્યવસ્થિત SIGTERM (WAL ચેકપૉઇન્ટ) માટે 5 s સુધી રાહ જુએ છે અને ત્યારબાદ SIGKILL મોકલે છે.
- ટ્રેમાંનો પોર્ટ સ્વિચર (`20128`, `3000`, `8080`) સર્વરને બંધ કરીને ફરી શરૂ કરે છે અને ત્યારબાદ BrowserWindowને રિલોડ કરે છે.

## શૂન્ય-કૉન્ફિગ સિક્રેટ બુટસ્ટ્રૅપ

પ્રથમ વાર શરૂ કરતી વખતે, મુખ્ય પ્રોસેસ ગુમ થયેલા સિક્રેટ્સ આપમેળે જનરેટ કરીને કાયમી રીતે સંગ્રહે છે:

| સિક્રેટ                  | સ્રોત                                                                                                          |
| ------------------------ | -------------------------------------------------------------------------------------------------------------- |
| `JWT_SECRET`             | `crypto.randomBytes(64).toString("hex")`                                                                       |
| `STORAGE_ENCRYPTION_KEY` | `crypto.randomBytes(32).toString("hex")` (એન્ક્રિપ્ટેડ ક્રેડેન્શિયલ્સ પહેલેથી અસ્તિત્વમાં હોય તો ઇનકાર કરે છે) |
| `API_KEY_SECRET`         | `crypto.randomBytes(32).toString("hex")`                                                                       |

`<DATA_DIR>/server.env`માં કાયમી રીતે સંગ્રહાય છે. `DATA_DIR`નું નિરાકરણ આ પ્રમાણે થાય છે:

- Windows: `%APPDATA%\omniroute`
- Linux: `$XDG_CONFIG_HOME/omniroute` અથવા `~/.omniroute`
- macOS: `~/.omniroute`

## વિન્ડો અને ટ્રે

- `BrowserWindow`: 1400×900 (ન્યૂનતમ 1024×700), `backgroundColor: "#0a0a0a"`.
- macOS: `titleBarStyle: "hiddenInset"`, ટ્રાફિક-લાઇટ `{ x: 16, y: 16 }` પર.
- Windows/Linux: મૂળ સિસ્ટમ ટાઇટલ બાર.
- બંધ કરવાનું બટન એપ્લિકેશનને ટ્રેમાં મિનિમાઇઝ કરે છે; ટ્રે મેનૂમાં **OmniRoute ખોલો**, **ડૅશબોર્ડ ખોલો** (બાહ્ય બ્રાઉઝર), **સર્વર પોર્ટ** સબમેનૂ, **અપડેટ્સ માટે તપાસો**, **બહાર નીકળો** છે.

## કન્ટેન્ટ સિક્યુરિટી પૉલિસી

`session.defaultSession.webRequest.onHeadersReceived` દ્વારા સેટ કરવામાં આવે છે. નોંધપાત્ર ડાયરેક્ટિવ્સ:

- `frame-ancestors 'none'`, `object-src 'none'`, `child-src 'none'`
- `connect-src 'self' http://localhost:* http://127.0.0.1:* ws://localhost:* ws://127.0.0.1:* https://*.omniroute.online https://*.omniroute.dev`
- ડેવ મોડ ફક્ત `script-src`માં `'unsafe-eval'` ઉમેરે છે

## સ્વચાલિત અપડેટ

GitHub પ્રોવાઇડર (`diegosouzapw/OmniRoute`) સાથે `electron-updater`નો ઉપયોગ કરે છે.

- `autoDownload = false`, `autoInstallOnAppQuit = true`
- ઇવેન્ટ્સ `update-status` IPC દ્વારા રેન્ડરર સુધી ફૉરવર્ડ થાય છે:
  `checking`, `available`, `not-available`, `downloading` (`percent` સાથે), `downloaded`, `error`
- `installUpdate()` સર્વરને બંધ કરે છે અને પછી `autoUpdater.quitAndInstall()` કૉલ કરે છે
- ડેવ મોડ (`!app.isPackaged`)માં અવગણવામાં આવે છે

## બિલ્ડ પાઇપલાઇન

1. `npm run build` → `.next/standalone`માં Next.js સ્ટૅન્ડઅલોન.
2. `prepare-electron-standalone.mjs` → `.next/electron-standalone`માં ફરીથી સ્ટેજ કરે છે અને `server.js` + `required-server-files.json`ની અંદરના ઍબ્સોલ્યુટ પાથ્સ ફરીથી લખે છે, જેથી બંડલને સ્થાનાંતરિત કરી શકાય.
3. `electron-builder`, `main.js`, `preload.js`, `node_modules`, અને `extraResources: { ../.next/electron-standalone → app }`ને પૅકેજ કરે છે.

### બિલ્ડ લક્ષ્યો

| OS      | લક્ષ્યો                                        |
| ------- | ---------------------------------------------- |
| Windows | NSIS ઇન્સ્ટૉલર + પોર્ટેબલ (x64)                |
| macOS   | DMG (Intel + arm64, Applicationsમાં ડ્રૅગ કરો) |
| Linux   | AppImage + DEB (x64 + arm64)                   |

NSIS સેટિંગ્સ: `oneClick: false`, વપરાશકર્તાને ઇન્સ્ટૉલ ડિરેક્ટરી પસંદ કરવાની મંજૂરી આપે છે અને Desktop તથા Start-Menu શૉર્ટકટ્સ બનાવે છે.

## પૅકેજ કરેલા બિલ્ડનું સ્મોક ટેસ્ટિંગ

```bash
npm run electron:smoke:packaged
```

`scripts/dev/smoke-electron-packaged.mjs`:

- વર્તમાન પ્લૅટફૉર્મ માટે `electron/dist-electron/`માં પૅકેજ કરેલી બાઇનરી આપમેળે શોધે છે.
- અલગ રાખેલી `HOME`/`APPDATA`/`XDG_*` ડિરેક્ટરીઓ સાથે લૉન્ચ કરે છે, જેથી તે ડેવલપરના ડેટાને સ્પર્શ ન કરે.
- 45 sની અંદર HTTP 200 માટે `http://127.0.0.1:20128/login`ને વારંવાર તપાસે છે.
- ગંભીર પૅટર્ન્સ (`Cannot find module`, `MODULE_NOT_FOUND`, `ERR_DLOPEN_FAILED`, `Failed to start server`, વગેરે) માટે stderr/stdoutનું નિરીક્ષણ કરે છે.
- તૈયારી પૂર્ણ થયા પછી 2 s સુધી સ્થિર રનટાઇમની રાહ જુએ છે, ત્યારબાદ SIGTERM મોકલે છે અને પોર્ટ મુક્ત થવાની રાહ જુએ છે.
- CIમાં, આપમેળે `--no-sandbox --disable-gpu` (અને Linux પર `--disable-dev-shm-usage`) પાસ કરે છે.

પર્યાવરણ ઓવરરાઇડ્સ: `ELECTRON_SMOKE_APP_EXECUTABLE`, `ELECTRON_SMOKE_URL`, `ELECTRON_SMOKE_TIMEOUT_MS`, `ELECTRON_SMOKE_SETTLE_MS`, `ELECTRON_SMOKE_DATA_DIR`, `ELECTRON_SMOKE_KEEP_DATA`, `ELECTRON_SMOKE_STREAM_LOGS`.

## કોડ સાઇનિંગ

`electron/package.json` સાઇનિંગ ક્રેડેન્શિયલ્સને સીધા ગોઠવતું **નથી**. તેમને env vars દ્વારા `electron-builder` ને આપો:

### macOS

```bash
export APPLE_ID=<email>
export APPLE_APP_SPECIFIC_PASSWORD=<password>
export APPLE_TEAM_ID=<id>
export CSC_LINK=path/to/cert.p12
export CSC_KEY_PASSWORD=<cert-password>
npm run electron:build:mac
```

### Windows

```bash
export CSC_LINK=path/to/cert.pfx
export CSC_KEY_PASSWORD=<cert-password>
npm run electron:build:win
```

### Linux

AppImage સાઇનિંગ વૈકલ્પિક છે — સાઇનિંગ માટે `LINUX_GPG_KEY` સેટ કરો.

## વિતરણ

આર્ટિફેક્ટ્સ `electron/dist-electron/` માં બને છે:

- `OmniRoute.Setup.X.Y.Z.exe`, `OmniRoute X.Y.Z.exe` (Windows)
- `OmniRoute-X.Y.Z-mac.dmg`, `OmniRoute-X.Y.Z-arm64-mac.dmg` (macOS)
- `OmniRoute-X.Y.Z.AppImage`, `omniroute-desktop_X.Y.Z_amd64.deb` (Linux)

રિલીઝ GitHub Releases (`diegosouzapw/OmniRoute`) પર પ્રકાશિત થાય છે, જ્યાં `electron-updater` પણ નવી આવૃત્તિઓ માટે તપાસ કરે છે.

| નેટિવ મોડ્યુલ માટે `ERR_DLOPEN_FAILED`                                    | `prepare:bundle` ફરીથી ચલાવો — વર્તમાન પ્લેટફોર્મ માટે Node-API પ્રીબિલ્ડ ઉપલબ્ધ ન હોય ત્યારે તે તરત નિષ્ફળ જાય છે                                                   |

| macOS નોટરાઇઝેશન અટકી જાય છે                                              | ખાતરી કરો કે `APPLE_*` vars export કરેલા છે, માત્ર `.env` માં જ નથી                                                                                                  |

| પોર્ટ ઉપયોગમાં હોવાને કારણે સ્મોક ટેસ્ટ નિષ્ફળ જાય છે                     | `electron:smoke:packaged` ચલાવતા પહેલાં 20128 પર ચાલતા કોઈપણ સ્થાનિક ડેવ સર્વરને બંધ કરો                                                                             |
