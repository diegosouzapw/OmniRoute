> **સત્યનો અધિકૃત સ્રોત:** `electron/` વર્કસ્પેસ
> **છેલ્લે અપડેટ કરેલું:** 2026-06-28 — v3.8.40

OmniRoute **Electron 41** + **electron-builder 26.10** પર બનેલી ક્રોસ-પ્લેટફોર્મ
ડેસ્કટૉપ ઍપ (Windows / macOS / Linux) પ્રદાન કરે છે. ડેસ્કટૉપ ઍપ Next.js
સ્ટેન્ડઅલોન સર્વરને ચાઇલ્ડ પ્રોસેસ તરીકે શરૂ કરે છે, `BrowserWindow`ને તેના તરફ નિર્દેશિત કરે છે અને
સિસ્ટમ ટ્રે, સ્વચાલિત અપડેટર, IPC બ્રિજ તથા શૂન્ય-રૂપરેખાંકન સિક્રેટ બૂટસ્ટ્રૅપ ઉમેરે છે.

## આર્કિટેક્ચર

```
┌──────────────────────────────────────────────┐
│ Electron મુખ્ય પ્રોસેસ (electron/main.js)     │
│ ├─ એકલ-ઇન્સ્ટન્સ લૉક                         │
│ ├─ ચાઇલ્ડ પ્રોસેસ: Next.js સ્ટેન્ડઅલોન સર્વર │
│ │   (Electronના Node રનટાઇમ વડે શરૂ કરેલો)   │
│ ├─ BrowserWindow → http://localhost:PORT     │
│ ├─ સિસ્ટમ ટ્રે + કૉન્ટેક્સ્ટ મેનૂ             │
│ ├─ electron-updater દ્વારા સ્વચાલિત અપડેટ     │
│ ├─ કન્ટેન્ટ સિક્યુરિટી પૉલિસી (સેશન હેડર્સ)  │
│ └─ સિક્રેટ બૂટસ્ટ્રૅપ (JWT / API_KEY_SECRET) │
└──────────────────────────────────────────────┘
            ↕ IPC બ્રિજ (electron/preload.js)
┌──────────────────────────────────────────────┐
│ રેન્ડરર (Next.js ડૅશબોર્ડ)                    │
│   window.electronAPI.* (contextIsolation)     │
└──────────────────────────────────────────────┘
```

- `npm run build:mac-x64` / `build:mac-arm64` — એકલ-આર્કિટેક્ચર macOS બિલ્ડ્સ
- `npm run pack` — સ્થાનિક પરીક્ષણ માટે માત્ર-ડિરેક્ટરી બિલ્ડ (ઇન્સ્ટોલર વિના)

## IPC બ્રિજ (`preload.js`)

પ્રીલોડ `contextIsolation: true` અને `nodeIntegration: false` સાથે `contextBridge`નો
ઉપયોગ કરીને `window.electronAPI` પર વ્હાઇટલિસ્ટ કરેલું API પ્રદર્શિત કરે છે.

```javascript
const VALID_CHANNELS = {
  invoke: [
    "get-app-info",
    "open-external",
    "get-data-dir",
    "restart-server",
    "check-for-updates",
    "download-update",
    "install-update",
    "get-app-version",
  ],
  send: ["window-minimize", "window-maximize", "window-close"],
  receive: ["server-status", "port-changed", "update-status"],
};
```

પ્રદર્શિત કરેલી મેથડ્સ:

| રેન્ડરર કૉલ                                                       | પ્રકાર                        |
| ----------------------------------------------------------------- | ----------------------------- |
| `getAppInfo()` → `{ name, version, platform, isDev, port }`       | invoke                        |
| `openExternal(url)`                                               | invoke                        |
| `getDataDir()`                                                    | invoke                        |
| `restartServer()`                                                 | invoke                        |
| `getAppVersion()`                                                 | invoke                        |
| `checkForUpdates()` / `downloadUpdate()` / `installUpdate()`      | invoke                        |
| `minimizeWindow()` / `maximizeWindow()` / `closeWindow()`         | send                          |
| `onServerStatus(cb)` / `onPortChanged(cb)` / `onUpdateStatus(cb)` | receive (ડિસ્પોઝર પરત કરે છે) |

રિસીવ હેલ્પર્સ `removeAllListeners` પર આધાર રાખવાને બદલે **ડિસ્પોઝર ફંક્શન** પરત કરે છે
— જ્યારે React કમ્પોનન્ટ્સ ફરી માઉન્ટ થાય ત્યારે આ લિસનર્સના સંચયને અટકાવે છે.

## સર્વર જીવનચક્ર

સિસ્ટમ Node સાથે નેટિવ-મોડ્યુલ ABI અસંગતતા ટાળવા માટે `main.js`, Electron Node
રનટાઇમ વડે Next.js સ્ટૅન્ડઅલોન બંડલને સીધું શરૂ કરે છે:

```js
spawn(process.execPath, [serverScript], {
  cwd: NEXT_SERVER_PATH,
  env: {
    ...serverEnv,
    PORT,
    NODE_ENV: "production",
    ELECTRON_RUN_AS_NODE: "1",
    NODE_PATH,
  },
  stdio: "pipe",
});
```

મુખ્ય વિશેષતાઓ:

- `waitForServer()` વિન્ડો દર્શાવતા પહેલાં 30 s સુધી URLનું પોલિંગ કરે છે (કોલ્ડ સ્ટાર્ટ પર ખાલી સ્ક્રીન દેખાતી નથી).
- `stdio: "pipe"` stdout/stderrને કૅપ્ચર કરે છે; તૈયાર હોવાનો સંકેત આપતા શબ્દસમૂહો (`Ready` / `listening`) IPC મારફતે `server-status: running` ઉત્સર્જિત કરે છે.
- `before-quit` સૌમ્ય SIGTERM (WAL ચેકપૉઇન્ટ) માટે 5 s સુધી રાહ જુએ છે અને પછી SIGKILL મોકલે છે.
- ટ્રેમાં રહેલું પોર્ટ સ્વિચર (`20128`, `3000`, `8080`) સર્વરને બંધ કરીને ફરી શરૂ કરે છે અને ત્યારબાદ BrowserWindowને ફરી લોડ કરે છે.

## શૂન્ય-કોન્ફિગરેશન સિક્રેટ બૂટસ્ટ્રેપ

પ્રથમ વાર શરૂ કરતી વખતે, મુખ્ય પ્રોસેસ ગુમ થયેલા સિક્રેટ્સ આપમેળે જનરેટ કરીને કાયમી રીતે સંગ્રહે છે:

| સિક્રેટ                  | સ્રોત                                                                                                                 |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| `JWT_SECRET`             | `crypto.randomBytes(64).toString("hex")`                                                                              |
| `STORAGE_ENCRYPTION_KEY` | `crypto.randomBytes(32).toString("hex")` (જો એન્ક્રિપ્ટ કરેલા ક્રેડેન્શિયલ્સ પહેલેથી અસ્તિત્વમાં હોય તો ઇનકાર કરે છે) |
| `API_KEY_SECRET`         | `crypto.randomBytes(32).toString("hex")`                                                                              |

`<DATA_DIR>/server.env`માં કાયમી રીતે સંગ્રહિત થાય છે. `DATA_DIR` આ મુજબ નિર્ધારિત થાય છે:

- Windows: `%APPDATA%\omniroute`
- Linux: `$XDG_CONFIG_HOME/omniroute` અથવા `~/.omniroute`
- macOS: `~/.omniroute`

## એન્વાયરમેન્ટ ફાઇલ શોધ

સર્વર શરૂ કરતાં પહેલાં, મુખ્ય પ્રોસેસ (`electron/main.js`માં `getPreferredEnvFilePath()`) **એક** `.env` ફાઇલ પસંદ કરે છે: નીચે આપેલી અસ્તિત્વમાં રહેલી ફાઇલોમાંથી પ્રથમ.

1. `$DATA_DIR/.env`, જ્યારે ઍપ જે એન્વાયરમેન્ટ સાથે શરૂ કરવામાં આવી હતી તેમાં `DATA_DIR` સેટ કરેલું હોય.
2. ઉપર મુજબના જ ડિફૉલ્ટ્સનો ઉપયોગ કરીને `<resolved DATA_DIR>/.env`: Windows પર `%APPDATA%\omniroute\.env`,
   Linux અને macOS પર `$XDG_CONFIG_HOME/omniroute/.env` અથવા `~/.omniroute/.env`.
3. પ્રોસેસની કાર્યકારી ડિરેક્ટરીમાં `.env`.

મુખ્ય પ્રોસેસ માત્ર તે ફાઇલ વાંચે છે; પછીના ઉમેદવારો મર્જ કરવામાં આવતા નથી. ત્યારબાદ સર્વરનું
એન્વાયરમેન્ટ આ અગ્રતાક્રમથી બનાવવામાં આવે છે (સૌથી ઊંચી અગ્રતા પ્રથમ):

1. Electron પ્રોસેસનું એન્વાયરમેન્ટ (ઍપને શરૂ કરનાર પ્રક્રિયામાંથી વારસામાં મળેલા વેરિએબલ્સ).
2. પસંદ કરેલી `.env` ફાઇલ.
3. `<DATA_DIR>/server.env` (ઉપરના બૂટસ્ટ્રેપ સિક્રેટ્સ).

ઍપ શરૂ થાય ત્યારે પ્રોસેસ એન્વાયરમેન્ટ કૅપ્ચર થાય છે, તેથી ઍપ ચાલુ હોય ત્યારે સેટ કરાયેલ
સિસ્ટમ અથવા વપરાશકર્તા એન્વાયરમેન્ટ વેરિએબલ (વિન્ડો બંધ થયા પછી ઍપ ટ્રેમાં હોય ત્યારે સેટ કરાયેલ વેરિએબલ સહિત)
ઍપને સંપૂર્ણપણે બંધ કરીને ફરી શરૂ કરવામાં ન આવે ત્યાં સુધી સર્વર સુધી પહોંચતું નથી. `CONTEXT_LENGTH_<PROVIDER>` જેવા
રનટાઇમ નૉબ્સ માટે (જુઓ
[એન્વાયરમેન્ટ વેરિએબલ્સ: પ્રદાતા-દીઠ કોન્ટેક્સ્ટ લંબાઈ](../reference/ENVIRONMENT.md#per-provider-context-length-context_length_provider)),
`.env` ફાઇલને પ્રાધાન્ય આપો, ત્યારબાદ ઍપને સંપૂર્ણપણે બંધ કરો (ટ્રે, **બંધ કરો**) અને ફરી શરૂ કરો.

## વિન્ડો અને ટ્રે

- `BrowserWindow`: 1400×900 (ન્યૂનતમ 1024×700), `backgroundColor: "#0a0a0a"`.
- macOS: `titleBarStyle: "hiddenInset"`, ટ્રાફિક-લાઇટ `{ x: 16, y: 16 }` પર.
- Windows/Linux: મૂળ ટાઇટલ બાર.
- બંધ કરવાનું બટન ઍપને ટ્રેમાં મિનિમાઇઝ કરે છે; ટ્રે મેનુમાં **OmniRoute ખોલો**, **ડૅશબોર્ડ ખોલો** (બાહ્ય બ્રાઉઝર), **સર્વર પોર્ટ** સબમેનુ, **અપડેટ્સ માટે તપાસો**, **બંધ કરો** છે.

## કન્ટેન્ટ સિક્યુરિટી પોલિસી

`session.defaultSession.webRequest.onHeadersReceived` દ્વારા સેટ થાય છે. નોંધપાત્ર ડિરેક્ટિવ્સ:

- `frame-ancestors 'none'`, `object-src 'none'`, `child-src 'none'`
- `connect-src 'self' http://localhost:* http://127.0.0.1:* ws://localhost:* ws://127.0.0.1:* https://*.omniroute.online https://*.omniroute.dev`
- ડેવ મોડ માત્ર `script-src`માં `'unsafe-eval'` ઉમેરે છે

## સ્વચાલિત અપડેટ

GitHub પ્રદાતા (`diegosouzapw/OmniRoute`) સાથે `electron-updater`નો ઉપયોગ કરે છે.

- `autoDownload = false`, `autoInstallOnAppQuit = true`
- `update-status` IPC દ્વારા રેન્ડરર પર ફોરવર્ડ કરવામાં આવતી ઇવેન્ટ્સ:
  `checking`, `available`, `not-available`, `downloading` (`percent` સાથે), `downloaded`, `error`
- `installUpdate()` સર્વરને બંધ કરે છે અને પછી `autoUpdater.quitAndInstall()`ને કૉલ કરે છે
- ડેવ મોડમાં અવગણવામાં આવે છે (`!app.isPackaged`)

## બિલ્ડ પાઇપલાઇન

1. `npm run build` → `.next/standalone` માં Next.js standalone.
2. `prepare-electron-standalone.mjs` → `.next/electron-standalone` માં ફરીથી સ્ટેજ કરે છે અને `server.js` + `required-server-files.json` ની અંદરના ઍબ્સોલ્યુટ પાથ ફરીથી લખે છે, જેથી બંડલને અન્ય સ્થાને ખસેડી શકાય.
3. `electron-builder`, `main.js`, `preload.js`, `node_modules`, અને `extraResources: { ../.next/electron-standalone → app }` ને પૅકેજ કરે છે.

### બિલ્ડ લક્ષ્યો

| OS      | લક્ષ્યો                                     |
| ------- | ------------------------------------------- |
| Windows | NSIS ઇન્સ્ટોલર + પોર્ટેબલ (x64)             |
| macOS   | DMG (Intel + arm64, Applications માં ડ્રૅગ) |
| Linux   | AppImage + DEB (x64 + arm64)                |

NSIS સેટિંગ્સ: `oneClick: false`, વપરાશકર્તાને ઇન્સ્ટોલ ડિરેક્ટરી પસંદ કરવા દે છે અને Desktop તથા Start-Menu શૉર્ટકટ બનાવે છે.

## પૅકેજ કરેલા બિલ્ડનું સ્મોક ટેસ્ટિંગ

```bash
npm run electron:smoke:packaged
```

`scripts/dev/smoke-electron-packaged.mjs`:

- વર્તમાન પ્લેટફોર્મ માટે `electron/dist-electron/` માં પૅકેજ કરેલી બાઇનરી આપમેળે શોધે છે.
- અલગ રાખેલી `HOME`/`APPDATA`/`XDG_*` ડિરેક્ટરીઓ સાથે લૉન્ચ કરે છે, જેથી તે ડેવલપર ડેટાને સ્પર્શ ન કરે.
- 45 s ની અંદર HTTP 200 માટે `http://127.0.0.1:20128/login` ને વારંવાર તપાસે છે.
- ગંભીર પેટર્ન (`Cannot find module`, `MODULE_NOT_FOUND`, `ERR_DLOPEN_FAILED`, `Failed to start server`, વગેરે) માટે stderr/stdout પર નજર રાખે છે.
- તૈયાર થયા પછી 2 s સુધી સ્થિર રનટાઇમની રાહ જુએ છે, ત્યારબાદ SIGTERM મોકલે છે અને પોર્ટ મુક્ત થવાની રાહ જુએ છે.
- CI માં, આપમેળે `--no-sandbox --disable-gpu` (અને Linux પર `--disable-dev-shm-usage`) પાસ કરે છે.

Env ઓવરરાઇડ્સ: `ELECTRON_SMOKE_APP_EXECUTABLE`, `ELECTRON_SMOKE_URL`, `ELECTRON_SMOKE_TIMEOUT_MS`, `ELECTRON_SMOKE_SETTLE_MS`, `ELECTRON_SMOKE_DATA_DIR`, `ELECTRON_SMOKE_KEEP_DATA`, `ELECTRON_SMOKE_STREAM_LOGS`.

## કોડ સાઇનિંગ

`electron/package.json` સાઇનિંગ ક્રેડેન્શિયલ્સને સીધા જોડી આપતું **નથી**. તેમને env vars દ્વારા `electron-builder` ને પાસ કરો:

### macOS

```bash
export APPLE_ID=<email>
export APPLE_APP_SPECIFIC_PASSWORD=<password>
export APPLE_TEAM_ID=<id>
export CSC_LINK=path/to/cert.p12
export CSC_KEY_PASSWORD=<cert-password>
npm run electron:build:mac
```

### Windows

```bash
export CSC_LINK=path/to/cert.pfx
export CSC_KEY_PASSWORD=<cert-password>
npm run electron:build:win
```

### Linux

AppImage સાઇનિંગ વૈકલ્પિક છે — સાઇનિંગ માટે `LINUX_GPG_KEY` સેટ કરો.
