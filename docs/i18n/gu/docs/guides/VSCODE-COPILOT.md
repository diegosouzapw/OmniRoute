**OmniCopilot** તમારા OmniRoute દ્વારા ઉપલબ્ધ કરાવવામાં આવતા દરેક મોડેલને _મૂળ_ GitHub Copilot Chat
મોડેલ પિકરમાં મૂકે છે. બીજી સાઇડબાર કે અલગ ચેટ UI નથી — Copilotનું એજન્ટ મોડ, ટૂલ કૉલિંગ,
MCP સર્વર્સ અને કસ્ટમ સૂચનાઓ બધું જ કાર્યરત રહે છે, ફક્ત તમે પસંદ કરેલા મોડેલ પર ચાલે છે.

## સેટઅપ

1. **OmniRoute ચલાવો** — `npm install -g omniroute && omniroute` (`http://localhost:20128` પર ડેશબોર્ડ).
2. **એક્સ્ટેન્શન ઇન્સ્ટોલ કરો** — Extensions વ્યૂમાં "OmniRoute" શોધો.
3. **મોડેલ પસંદ કરો** — Copilot Chat → મોડેલ પિકર → **Manage Models…** → **OmniRoute**, પછી
   તમને જે જોઈએ તેના પર ટિક કરો.

જ્યારે OmniRoute ડિફૉલ્ટ પોર્ટ પર ચાલે ત્યારે કંઈપણ કૉન્ફિગર કરવાની જરૂર નથી. રિમોટ ઇન્સ્ટન્સ માટે,
**Activity Barમાં OmniRoute આઇકન** ખોલો (અથવા `OmniRoute: Manage Connection` ચલાવો) અને આ સેટ કરો:

- **Server URL** — સર્વર રૂટ, દા.ત. `http://192.168.0.15:20128`. `/v1` સફિક્સ
  એક્સ્ટેન્શન દ્વારા ઉમેરવામાં આવે છે; તેને સામેલ કરશો નહીં.
- **API key** — ફક્ત ત્યારે, જ્યારે સર્વર `REQUIRE_API_KEY` સેટ કરે. VS
  Code SecretStorage મારફતે OS કીચેઇનમાં સંગ્રહાય છે, `settings.json`માં ક્યારેય નહીં.

## પિકરમાં શું દેખાશે

એક્સ્ટેન્શન કાચો `GET /v1/models` પેલોડ બતાવતું નથી — તે તેને વ્યવસ્થિત કરે છે, અને તમને દેખાતી
સંખ્યા બે ઇરાદાપૂર્વકનાં કારણોસર કેટલોગના કદ કરતાં ઓછી હોય છે.

### તે દરેક મોડેલ માટે એક id માગે છે

`MODELS_CATALOG_PREFIX_MODE`નું ડિફૉલ્ટ મૂલ્ય **`dual`** છે, જે દરેક મોડેલને બે વાર જાહેર કરે છે — એક વાર
ટૂંકા ઉપનામ પ્રીફિક્સ હેઠળ અને એક વાર પ્રમાણભૂત પ્રોવાઇડર પ્રીફિક્સ હેઠળ — જેથી જૂના ક્લાયન્ટ
કૉન્ફિગ્સ બંને સ્વરૂપોને રિઝોલ્વ કરવાનું ચાલુ રાખે:

```
cc/claude-sonnet-4-6        ← ઉપનામ પ્રીફિક્સ
claude/claude-sonnet-4-6    ← પ્રમાણભૂત પ્રીફિક્સ, એ જ મોડેલ
```

એક્સ્ટેન્શન **`GET /v1/models?prefix=alias`**ની વિનંતી કરે છે, જેથી દરેક મોડેલ માટે એક id આવે અને
તમારા અન્ય ક્લાયન્ટ્સ માટેની સર્વર-વ્યાપી સેટિંગ બદલાય નહીં. એક સંદર્ભ ઇન્સ્ટન્સ પર આનાથી
**2345 એન્ટ્રીઓ ઘટીને 1396 થઈ — 949 ડુપ્લિકેટ્સ, એક પણ મોડેલ ગુમાવ્યા વિના.**

જો તમે તેના બદલે _દરેક_ ક્લાયન્ટ માટે તેને સર્વર-વ્યાપી રીતે સુધારવા માંગતા હો, તો ડેશબોર્ડમાં
`MODELS_CATALOG_PREFIX_MODE` ફીચર ફ્લૅગને `alias` પર સેટ કરો. ક્વેરી
પેરામીટર અને દરેક મોડ માટેના કોષ્ટક માટે
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) જુઓ.

### તે ચેટ ન કરી શકતા મોડેલ્સને છુપાવે છે

કેટલોગમાં ઇમેજ, વિડિયો, ઑડિયો, રીરૅન્ક, એમ્બેડિંગ અને મોડરેશન મોડેલ્સ પણ સૂચિબદ્ધ છે. ચેટ
વિનંતી પર એ મોડેલ્સ આમ પણ નકારવામાં આવે છે:

```
HTTP 400 — મોડેલ '<id>' એક ઇમેજ-જનરેશન મોડેલ છે અને તેનો ઉપયોગ
/v1/chat/completions પર કરી શકાતો નથી. તેના બદલે POST /v1/images/generations વાપરો.
```

તેથી પિકર સુધી પહોંચતાં પહેલાં તેમને તેમના `type` ફીલ્ડના આધારે ફિલ્ટર કરવામાં આવે છે. **Responses-API
મોડેલ્સ રાખવામાં આવે છે** — દરેક Codex / GPT-5.x એન્ટ્રી `supported_endpoints: ["responses"]`
જાહેર કરે છે, અને OmniRoute તેમને `/v1/chat/completions` માટે રૂપાંતરિત કરે છે, તેથી તેઓ સંપૂર્ણપણે ઉપયોગી છે.

### તમે ક્યારેય કૉન્ફિગર ન કરેલા પ્રોવાઇડર્સ

કેટલોગમાં **સક્રિય કનેક્શન** ધરાવતા પ્રોવાઇડર્સના મોડેલ્સની સાથે દરેક **noAuth**
પ્રોવાઇડર પણ સૂચિબદ્ધ થાય છે — એટલે કે કી વિનાના પ્રોવાઇડર્સ, જે ફ્રી ટિયરનો મોટો ભાગ બનાવે છે. આ ઇરાદાપૂર્વક છે. તેમને
છુપાવવા માટે ડેશબોર્ડ સેટિંગ્સમાં `blockedProviders`માં ઉમેરો; એક્સ્ટેન્શનમાં
કંઈપણ બદલાતું નથી.

## VS Code ટૅબની અંદર Dashboard

`omnicopilot.dashboardOpen: "editor"` બાહ્ય બ્રાઉઝરને બદલે Simple Browser દ્વારા OmniRoute dashboardને editor ટૅબમાં રેન્ડર કરે છે. એમ્બેડિંગ સર્વર પર `DASHBOARD_ALLOW_EMBED=vscode` દ્વારા **opt-in** છે, જે ડિફૉલ્ટ `frame-ancestors 'none'` +
`X-Frame-Options: DENY`ને બદલે `frame-ancestors 'self' vscode-webview:` સાથે HTML પેજો સર્વ કરે છે. API સપાટી (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) બંને સ્થિતિમાં કડક headers જાળવી રાખે છે.

> ⚠️ **આ build-time flag છે, runtime flag નહીં.** Next.js `headers()`ને route
> manifestમાં compile કરે છે, તેથી bundle build થઈ રહ્યું હોય ત્યારે `next.config.mjs` variable વાંચે છે
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> પહેલેથી build થયેલા સર્વરની આગળ તેને export કરવાથી કંઈ બદલાતું નથી — headers પહેલેથી જ સમાવિષ્ટ હોય છે.

```bash
# variable BUILD command પર હાજર હોવો જરૂરી છે
DASHBOARD_ALLOW_EMBED=vscode npm run build        # અથવા npm run build:release
npm start
```

| તમે કેવી રીતે ઇન્સ્ટોલ કર્યું | શું તમે એમ્બેડિંગ સક્ષમ કરી શકો છો?                                                                                                |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| sourceમાંથી                   | ✅ ઉપર દર્શાવ્યા મુજબ build command પર variable સેટ કરો                                                                            |
| `npm install -g omniroute`    | ❌ પ્રકાશિત package prebuilt bundle સાથે આવે છે — તેના બદલે sourceમાંથી build કરો                                                  |
| Docker image                  | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — Docker Hub પરની prebuilt image embed-enabled નથી |

embed-enabled build વિના પેજ frame થવાનો ઇનકાર કરે છે, extension response headersમાંથી તે શોધી કાઢે છે અને બાહ્ય બ્રાઉઝરનો fallback તરીકે ઉપયોગ કરે છે — કંઈ બગડતું નથી અને તે આ વિશે એક વાર જાણ કરે છે.
[`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) અને issue
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273) જુઓ.

[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md)માં કરાયું છે. API key CLIને `OMNIROUTE_API_KEY` environment variable દ્વારા આપવામાં આવે છે, command line પર ક્યારેય નહીં.

## સમસ્યાનિવારણ

| લક્ષણ                                                | કારણ / ઉકેલ                                                                                                                                                                                                                                                            |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| pickerમાં કોઈ OmniRoute models નથી                   | સર્વર સુધી પહોંચી શકાતું નથી. status-bar dot રાખોડી થઈ જાય છે; `OmniRoute: Check Connection` ચલાવો. Discovery ઇરાદાપૂર્વક મૌન રહે છે અને prompt બતાવવાને બદલે કોઈ models ઉમેરતું નથી.                                                                                  |
| દરેક model બે વાર દેખાય છે                           | તમે 1.0.1 કરતાં જૂના OmniCopilot પર છો — update કરો. extension હવે `?prefix=alias`ની request કરે છે.                                                                                                                                                                   |
| અગાઉ સૂચિબદ્ધ image/audio model હવે ગાયબ છે          | 1.0.1થી આ ઇરાદાપૂર્વક છે — તે ક્યારેય chat requestનો જવાબ આપી શકતું નહોતું.                                                                                                                                                                                            |
| Activity Barમાંથી panel ગાયબ છે                      | VS Code વધારાના view containersને Activity Barના તળિયે આવેલા **"…"** overflowમાં ખસેડે છે અને right-click દ્વારા છુપાવેલું container છુપાયેલું જ રહે છે. Activity Bar પર right-click કરો → **OmniRoute**ને tick કરો અથવા `OmniRoute: Manage Connection` વડે તેને ખોલો. |
| `editor` mode હોવા છતાં Dashboard બ્રાઉઝરમાં ખૂલે છે | સર્વર `DASHBOARD_ALLOW_EMBED=vscode` સાથે **build** કરાયો નહોતો (ઉપર જુઓ) — prebuilt install પર startup વખતે તેને સેટ કરવાથી કંઈ થતું નથી. fallback ઇરાદાપૂર્વક છે.                                                                                                    |
| providers બદલ્યા પછી modelsની સૂચિ જૂની છે           | `OmniRoute: Refresh Models` અથવા panelમાંની ↻ linkનો ઉપયોગ કરો.                                                                                                                                                                                                        |
