> **TL;DR**: OmniRoute તેના **મફત** પ્રદાતાઓને મોડેલની ગુણવત્તા અનુસાર **Arena AI
> (LMArena-શૈલીના) ELO સ્કોર્સ**નો ઉપયોગ કરીને ક્રમ આપે છે. તમારા કાર્ય માટે કયા મફત
> પ્રદાતાઓ સૌથી મજબૂત મોડેલો આપે છે તે જોવા માટે ડૅશબોર્ડમાં **મફત પ્રદાતા રૅન્કિંગ્સ**
> પેજ ખોલો — એકંદરે અથવા કૅટેગરી (કોડિંગ, સમીક્ષા, દસ્તાવેજીકરણ, ડિબગિંગ) મુજબ ફિલ્ટર કરીને.

## આ શું છે

OmniRoute 329 પ્રદાતાઓને રજિસ્ટર કરે છે, જેમાં **મફત/પ્રમાણીકરણ-વિના** તરીકે ચિહ્નિત કરેલી
155 કૅટલૉગ એન્ટ્રીઓ સામેલ છે
(પ્રમાણીકરણ-વિના,
મફત-ટિયર OAuth અથવા મફત-ટિયર API કી —
[મફત ટિયર્સ માર્ગદર્શિકા](../getting-started/FREE-TIERS-GUIDE.md) અને સંપૂર્ણ
[મફત ટિયર્સ ડિરેક્ટરી](../reference/FREE_TIERS.md) જુઓ). પરંતુ સમસ્યા એ છે કે મફત પ્રદાતાઓની
મોડેલ ગુણવત્તામાં ખૂબ મોટો તફાવત હોય છે. અગ્રણી મોડેલ આપતો પ્રમાણીકરણ-વિના પ્રદાતા,
નાનું જૂનું મોડેલ આપતા પ્રદાતા કરતાં ઘણો વધુ ઉપયોગી છે.

**મફત પ્રદાતા રૅન્કિંગ્સ** દરેક મફત પ્રદાતાના કૅટલૉગને
**Arena AI લીડરબોર્ડ**માંથી મળતા **સમુદાય-સ્રોત આધારિત ગુણવત્તા સ્કોર્સ**
(માનવીય પસંદગીના ELO, LMArena ચેટબોટ એરીના પાછળના સમાન વિચાર) સાથે જોડીને
"**કયો મફત પ્રદાતા મને શ્રેષ્ઠ મોડેલ આપે છે?**" એ પ્રશ્નનો જવાબ આપે છે. ત્યારબાદ
પ્રદાતાઓને તેમના **શ્રેષ્ઠ મફત મોડેલ**ની ક્ષમતા પ્રમાણે ક્રમ આપવામાં આવે છે.

રૅન્કિંગની ગણતરી ત્રણ વાસ્તવિક સ્રોતોમાંથી થાય છે:

1. મફત પ્રદાતાઓની યાદીઓ — `NOAUTH_PROVIDERS`, ઉપરાંત `hasFree` તરીકે ચિહ્નિત
   `OAUTH_PROVIDERS` / `APIKEY_PROVIDERS` એન્ટ્રીઓ
   (`src/shared/constants/providers.ts`).
2. પ્રદાતા રજિસ્ટ્રીમાંથી દરેક પ્રદાતાનો મોડેલ કૅટલૉગ
   (`open-sse/config/providerRegistry.ts`).
3. Arena ELO સિંક એન્જિન (`src/lib/arenaEloSync.ts`) દ્વારા `model_intelligence`
   DB ટેબલમાં સંગ્રહિત ELO-આધારિત કાર્ય-અનુકૂળતા સ્કોર્સ.

જોડાણનો તર્ક `src/lib/freeProviderRankings.ts`માં છે.

## ઍક્સેસ કરવાની રીત

### ડૅશબોર્ડ પેજ

ડૅશબોર્ડ ખોલીને **ખર્ચ → મફત પ્રદાતા રૅન્કિંગ્સ** પર જાઓ અથવા સીધા અહીં નેવિગેટ કરો:

```
/dashboard/free-provider-rankings
```

આ પેજ (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) નીચેની વસ્તુઓ દર્શાવે છે:

- શ્રેષ્ઠ ક્રમ ધરાવતા મફત પ્રદાતાઓનું **ટોચ-3 પોડિયમ** (🥇 🥈 🥉).
- આ કૉલમ સાથેનું સંપૂર્ણ **રૅન્કિંગ કોષ્ટક**: **ક્રમ**, **પ્રદાતા**, **ટોચનું મોડેલ**,
  **સ્કોર**, **સરેરાશ સ્કોર**, **મોડેલો**, **પ્રકાર**.
- **કૅટેગરી ફિલ્ટર બટનો**: _બધી કૅટેગરીઓ_, _ડિફૉલ્ટ_, _કોડિંગ_, _સમીક્ષા_,
  _દસ્તાવેજીકરણ_, _ડિબગિંગ_.

દરેક પ્રદાતાનું **પ્રકાર** બૅજ તે કેવી રીતે મફત છે તે જણાવે છે:

| બૅજ      | અર્થ                                       |
| -------- | ------------------------------------------ |
| `NOAUTH` | હંમેશાં મફત, કોઈ ઓળખપત્રોની જરૂર નથી       |
| `OAUTH`  | મફત ટિયર (`hasFree`) ધરાવતો OAuth પ્રદાતા  |
| `APIKEY` | મફત ટિયર (`hasFree`) ધરાવતો API-કી પ્રદાતા |

સ્કોર્સને કાચા આંકડાઓના બદલે માનવી સરળતાથી સમજી શકે તેવા લેબલ તરીકે દર્શાવવામાં આવે છે
(દા.ત. _શ્રેષ્ઠ_, _ઉત્કૃષ્ટ_, _ખૂબ સારું_, _સારું_, _સરેરાશ_), કારણ કે મૂળભૂત મૂલ્ય
ટકાવારી નહીં પરંતુ સાપેક્ષ રૅન્કિંગ ગુણવત્તા છે.

### API એન્ડપૉઇન્ટ

આ પેજને જાહેર રીડ એન્ડપૉઇન્ટ
(`src/app/api/free-provider-rankings/route.ts`) દ્વારા ડેટા મળે છે:

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

ક્વેરી પેરામીટર્સ (Zod વડે માન્ય કરેલા):

| પેરામીટર   | પ્રકાર | ડિફૉલ્ટ    | નોંધો                                                                                                 |
| ---------- | ------ | ---------- | ----------------------------------------------------------------------------------------------------- |
| `category` | string | (કંઈ નહીં) | `default`, `coding`, `review`, `documentation`, `debugging`માંથી એક. સંયુક્ત રૅન્કિંગ માટે તેને છોડો. |
| `limit`    | number | `50`       | `1–100`ની શ્રેણી સુધી મર્યાદિત.                                                                       |

પ્રતિસાદનું માળખું:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` મૂળ Arena ELO મૂલ્ય છે; `score` સામાન્યકૃત કાર્ય-અનુકૂળતા મૂલ્ય છે
(નીચે જુઓ). કોઈ સ્કોર કરેલા મોડેલો ન ધરાવતા પ્રદાતાઓને પ્રતિસાદમાંથી બાકાત રાખવામાં આવે છે.

## સ્કોર કેવી રીતે કાર્ય કરે છે

### સ્રોત: Arena AI લીડરબોર્ડ

Arena ELO સિંક એન્જિન (`src/lib/arenaEloSync.ts`) Arena AI લીડરબોર્ડ API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) પરથી બે લીડરબોર્ડ — `text`
અને `code` — મેળવે છે. દરેક લીડરબોર્ડ એન્ટ્રીમાં મોડલનું નામ, વેન્ડર, ELO `score`,
વિશ્વાસ અંતરાલ અને મતોની સંખ્યા હોય છે.

લીડરબોર્ડની શ્રેણીઓ OmniRouteની કાર્ય શ્રેણીઓ સાથે આ રીતે મેપ થાય છે:

| Arena લીડરબોર્ડ | OmniRoute કાર્ય શ્રેણીઓ                           |
| --------------- | ------------------------------------------------- |
| `text`          | `default`, `review`, `documentation`, `debugging` |
| `code`          | `coding`                                          |

### સામાન્યીકરણ (કાર્ય-અનુકૂળતા સ્કોર)

કાચા ELO સ્કોરને દરેક લીડરબોર્ડ દીઠ **`[0.4, 0.98]`માં કાર્ય-અનુકૂળતા મૂલ્ય** તરીકે સામાન્યીકૃત કરવામાં આવે છે:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

સ્કોર ક્યારેય `0` અથવા `1` સુધી પહોંચતો નથી, જેથી વપરાશકર્તાના ઓવરરાઇડ માટે અવકાશ રહે છે. આ તે
`score` ફીલ્ડ છે જે તમે API પ્રતિસાદમાં જુઓ છો અને ડૅશબોર્ડ પર દર્શાવાતું લેબલ છે.

### વિશ્વસનીયતા

Arenaના મતોની સંખ્યાના આધારે દરેક એન્ટ્રીને વિશ્વસનીયતાનું સ્તર મળે છે:

| વિશ્વસનીયતા | મત      |
| ----------- | ------- |
| `high`      | ≥ 5,000 |
| `medium`    | ≥ 1,000 |
| `low`       | < 1,000 |

### સંગ્રહ અને તાજગી

સામાન્યીકૃત એન્ટ્રીઓ `source = "arena_elo"` સાથે `model_intelligence` DB ટેબલમાં
લખવામાં આવે છે (`src/lib/db/modelIntelligence.ts`). એન્ટ્રીઓની સમયસીમા **7 દિવસ પછી
સમાપ્ત થાય છે**, તેથી સિંક કરવાનું બંધ કરનાર પ્રોવાઇડર જૂનો ડેટા આપવાનું ચાલુ રાખવાને બદલે
આખરે બહાર થઈ જાય છે.

સિંક **ડિફૉલ્ટ રૂપે ચાલુ** રહે છે:

- તે સર્વર શરૂ થતાં એક વાર અને ત્યારબાદ સમયાંતરે ચાલતા ટાઇમર પર ચાલે છે
  (`src/lib/arenaEloSync.ts`, `src/instrumentation-node.ts`માંથી જોડાયેલ).
- તે **બ્લોક કરતું નથી અને ક્યારેય ઘાતક બનતું નથી** — જો અપસ્ટ્રીમ ફેચ નિષ્ફળ જાય, તો OmniRoute
  ચાલતું રહે છે અને રેન્કિંગ માત્ર છેલ્લો સારો ડેટા (અથવા ખાલી સ્થિતિ) દર્શાવે છે.

બે એન્વાયર્નમેન્ટ વેરિએબલ તેને નિયંત્રિત કરે છે ([`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)માં
દસ્તાવેજીકૃત):

| વેરિએબલ                   | ડિફૉલ્ટ       | હેતુ                                                    |
| ------------------------- | ------------- | ------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | આઉટબાઉન્ડ સિંકમાંથી બહાર રહેવા માટે `false` પર સેટ કરો. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | સિંક અંતરાલ, સેકન્ડમાં.                                 |

### મેન્યુઅલ સિંક / સ્થિતિ / સાફ કરવું

ઑપરેટરો માટે, પ્રમાણીકૃત મેનેજમેન્ટ એન્ડપોઇન્ટ મેન્યુઅલ નિયંત્રણ પૂરું પાડે છે
(`src/app/api/intelligence/sync/route.ts` — મેનેજમેન્ટ પ્રમાણીકરણ જરૂરી છે):

```
GET    /api/intelligence/sync          # વર્તમાન સિંક સ્થિતિ (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # મેન્યુઅલ સિંક ટ્રિગર કરો; લખ્યા વિના પૂર્વાવલોકન માટે બોડી: { "dryRun": true }
DELETE /api/intelligence/sync          # સિંક કરેલી તમામ arena_elo ઇન્ટેલિજન્સ એન્ટ્રીઓ સાફ કરો
```

જો રેન્કિંગ પેજ ખાલી હોય, તો મેન્યુઅલ `POST /api/intelligence/sync` (અથવા માત્ર
સર્વરને ફરી શરૂ કરવાથી) તેમાં ફરી ડેટા ભરાય છે.

### મોડલને લીડરબોર્ડ સાથે મેળ ખવડાવવો

રજિસ્ટ્રી મોડલ ID અને Arena મોડલનાં નામ હંમેશાં બરાબર મેળ ખાતાં નથી. રેન્કિંગમાં
લવચીક મેચિંગનો ઉપયોગ થાય છે (`src/lib/freeProviderRankings.ts`માં `findMatchingIntelligence`):

1. સામાન્યીકૃત મોડલ ID સાથે ચોક્કસ મેળ.
2. અંતે આવેલ વર્ઝન સફિક્સ દૂર કર્યા પછી મેળ (દા.ત. `kimi-k2.6` → `kimi-k2`).
3. પ્રીફિક્સ મેળ (લીડરબોર્ડ મોડલનું નામ રજિસ્ટ્રી IDનો પ્રીફિક્સ હોય).

સિંકની બાજુએ, જાણીતા વેન્ડર પ્રીફિક્સ (`anthropic/`, `openai/`, `google/`, …)
દૂર કરવામાં આવે છે અને એક નાનો ઉપનામ મેપ કેનોનિકલ નામોને OmniRoute દ્વારા આંતરિક રીતે ઉપયોગમાં લેવાતા
વેરિઅન્ટમાં વિસ્તારે છે, જેથી મોડલ કોઈપણ નામ હેઠળ શોધી શકાય છે.

### પ્રોવાઇડરનું રેન્કિંગ કેવી રીતે થાય છે

દરેક મફત પ્રોવાઇડર માટે, એન્જિન તેના કૅટલૉગમાંના દરેક મોડલને સ્કોર આપે છે, પછી:

- **ટોચનું મોડલ** = પ્રોવાઇડરનું સૌથી વધુ સ્કોર ધરાવતું મોડલ.
- **સરેરાશ સ્કોર** = તે પ્રોવાઇડરના સ્કોર ધરાવતા તમામ મોડલના સ્કોરની સરેરાશ.
- **મોડલ** = પ્રોવાઇડરના કેટલા મોડલ પાસે Arena સ્કોર હતો.

પ્રોવાઇડરને પહેલાં **ટોચના મોડલના સ્કોર** મુજબ અને પછી સરેરાશ સ્કોર મુજબ ગોઠવવામાં આવે છે. આ
ઓછામાં ઓછું એક મજબૂત મફત મોડલ આપતા પ્રોવાઇડરને પુરસ્કૃત કરે છે.

## મફત પ્રદાતાઓ પસંદ કરવા માટે તેનો ઉપયોગ

1. **યોગ્ય શ્રેણી પસંદ કરો.** એજન્ટિક/કોડ વર્કલોડ માટે **Coding** ફિલ્ટરનો ઉપયોગ કરો અથવા
   સામાન્ય ચેટ માટે તેને **All Categories** / **Default** પર રાખો. એક જ પ્રદાતાનું
   રેન્કિંગ અલગ-અલગ શ્રેણીઓમાં જુદું હોઈ શકે છે, કારણ કે દરેક લીડરબોર્ડ મુજબ તેનું ટોચનું મોડેલ અલગ હોય છે.
2. **એક-વખતના સેટઅપ માટે પોડિયમને પ્રાધાન્ય આપો.** જો તમે માત્ર એક કે બે મફત
   પ્રદાતાઓને કનેક્ટ કરવા માંગતા હો, તો તમારી શ્રેણીમાં ટોચનું રેન્કિંગ ધરાવતા પ્રદાતાઓથી શરૂઆત કરો.
3. **Type બેજ તપાસો.** `NOAUTH` પ્રદાતાઓ સૌથી ઝડપથી કનેક્ટ થાય છે (કોઈ
   ઓળખપત્રોની જરૂર નથી). `OAUTH` / `APIKEY` મફત ટિયર માટે ઝડપી સાઇન-અપ જરૂરી છે, પરંતુ તે ઘણીવાર
   વધુ શક્તિશાળી મોડેલ ઉપલબ્ધ કરાવે છે. કનેક્શનનાં પગલાં માટે
   [મફત ટિયર માર્ગદર્શિકા](../getting-started/FREE-TIERS-GUIDE.md) જુઓ.
4. **ઘણા પ્રદાતાઓને કનેક્ટ કરો અને Auto-Comboને નિર્ણય લેવા દો.** આ પેજને
   શક્તિ આપતો એ જ Arena ELO ડેટા Auto-Combo સ્કોરિંગ એન્જિનના **કાર્ય-યોગ્યતા પરિબળ**ને પણ ડેટા પૂરો પાડે છે
   (`open-sse/services/autoCombo/taskFitness.ts`, રિઝોલ્યુશન ક્રમ
   `user_override → arena_elo → models_dev_tier → static table`). તેથી, તમે ટોચના
   મફત પ્રદાતાઓને કનેક્ટ કર્યા પછી, `model: "auto"` (દા.ત. `auto/coding`) વડે રાઉટિંગ કરવાથી
   દરેક વિનંતી માટે ઉચ્ચ-ગુણવત્તાવાળા મફત મોડેલને આપમેળે પ્રાધાન્ય મળશે. સંપૂર્ણ 16-પરિબળ સ્કોરિંગ માટે
   [Auto-Combo](../routing/AUTO-COMBO.md) જુઓ.
