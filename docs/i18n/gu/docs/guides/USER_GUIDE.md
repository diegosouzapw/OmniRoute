## 🎯 ઉપયોગના કિસ્સાઓ

### કિસ્સો 1: "મારી પાસે Claude Pro સબ્સ્ક્રિપ્શન છે"

**સમસ્યા:** ક્વોટા વપરાયા વિના સમાપ્ત થઈ જાય છે, ભારે કોડિંગ દરમિયાન રેટ લિમિટ્સ આવે છે

```
કૉમ્બો: "maximize-claude"
  1. cc/claude-opus-4-7        (સબ્સ્ક્રિપ્શનનો સંપૂર્ણ ઉપયોગ કરો)
  2. glm/glm-4.7               (ક્વોટા પૂરો થાય ત્યારે સસ્તું બૅકઅપ)
  3. if/qwen3.8-max-preview       (કટોકટી માટે મફત ફૉલબૅક)

માસિક કિંમત: $20 (સબ્સ્ક્રિપ્શન) + ~$5 (બૅકઅપ) = કુલ $25
તેની સરખામણીમાં $20 + મર્યાદાઓ સુધી પહોંચી જવું = નિરાશા
```

### કિસ્સો 2: "મારે શૂન્ય ખર્ચ જોઈએ છે"

**સમસ્યા:** સબ્સ્ક્રિપ્શન પરવડી શકતું નથી, વિશ્વસનીય AI કોડિંગની જરૂર છે

```
કૉમ્બો: "zero-cost"
  1. if/kimi-k2.7-code          (મફત ઍક્સેસ તરીકે સૂચિબદ્ધ; રેટ લિમિટ્સ લાગુ પડી શકે છે)
  2. kr/qwen3-coder-next        (Kiroનો મફત ફૉલબૅક)

માસિક કિંમત: $0
ગુણવત્તા: તમારા વર્કલોડ માટે મોડેલ, મર્યાદાઓ, ગોપનીયતા અને SLA ચકાસો
```

### કિસ્સો 3: "મારે કોઈ વિક્ષેપ વિના 24/7 કોડિંગ જોઈએ છે"

**સમસ્યા:** સમયમર્યાદાઓ છે, ડાઉનટાઇમ પરવડી શકે તેમ નથી

```
કૉમ્બો: "always-on"
  1. cc/claude-opus-4-7        (શ્રેષ્ઠ ગુણવત્તા)
  2. cx/gpt-5.5                (બીજું સબ્સ્ક્રિપ્શન)
  3. glm/glm-4.7               (સસ્તું, દરરોજ રીસેટ થાય છે)
  4. minimax/MiniMax-M2.1      (સૌથી સસ્તું, 5 કલાકે રીસેટ)
  5. if/deepseek-v4-flash       (મફત ઍક્સેસ તરીકે સૂચિબદ્ધ; રેટ લિમિટ્સ લાગુ પડી શકે છે)

પરિણામ: 5 ફૉલબૅક સ્તરો સ્થિતિસ્થાપકતાને વિસ્તૃત કરે છે; અપસ્ટ્રીમ ઉપલબ્ધતાની ખાતરી નથી
માસિક કિંમત: $20-200 (સબ્સ્ક્રિપ્શન્સ) + $10-20 (બૅકઅપ)
```

### કિસ્સો 4: "મારે OpenClawમાં મફત AI જોઈએ છે"

**સમસ્યા:** મેસેજિંગ ઍપ્સમાં સંપૂર્ણપણે મફત AI સહાયકની જરૂર છે

## 🚀 ડિપ્લૉયમેન્ટ

### વૈશ્વિક npm ઇન્સ્ટૉલ (ભલામણ કરેલ)

```bash
npm install -g omniroute

# કૉન્ફિગ ડિરેક્ટરી બનાવો
mkdir -p ~/.omniroute

# .env ફાઇલ બનાવો (.env.example જુઓ)
cp .env.example ~/.omniroute/.env

# સર્વર શરૂ કરો
omniroute
# અથવા કસ્ટમ પોર્ટ સાથે:
omniroute --port 3000
```

CLI આપમેળે `~/.omniroute/.env` અથવા `./.env`માંથી `.env` લોડ કરે છે.

### ટ્રે મોડ

સિસ્ટમ ટ્રેમાં OmniRoute શરૂ કરો:

```bash
omniroute serve --tray
```

સર્વર અને ટ્રે તૈયાર થયા પછી આ કમાન્ડ પૂર્ણ થાય છે.

સર્વર ટર્મિનલ વિના પણ ચાલુ રહે છે.

ટ્રે મોડ macOS, Windows અને ગ્રાફિકલ Linux સેશન્સને સપોર્ટ કરે છે. ટ્રે મોડ ડૅશબોર્ડને આપમેળે ખોલતું નથી.

આ ક્રિયાઓ માટે ટ્રે મેનૂનો ઉપયોગ કરો:

- ડૅશબોર્ડ ખોલો.
- `/dashboard/logs` ખોલો.
- ઑટો-સ્ટાર્ટ બદલો.
- OmniRoute બંધ કરો.

આ વિકલ્પો સાથે `--tray`ને જોડશો નહીં:

- `--daemon`
- `--log`
- `--no-recovery`

આ મોડ્સ માટે અલગ પ્રોસેસ માલિકીની જરૂર પડે છે.

મશીનમાં આગામી લૉગિન વખતે સ્ટાર્ટઅપ સક્ષમ કરો:

```bash
omniroute autostart enable
```

ઑટો-સ્ટાર્ટ macOS, Windows અને ગ્રાફિકલ Linux સેશન્સ પર ટ્રે મોડનો ઉપયોગ કરે છે. હેડલેસ Linux હાલની systemd યુઝર સર્વિસનો ઉપયોગ કરે છે.

લૉગિન વખતે સ્ટાર્ટઅપ અક્ષમ કરો:

```bash
omniroute autostart disable
```

| `npm run uninstall:full` | ઍપ દૂર કરે છે અને **બધાં કૉન્ફિગરેશન્સ, કીઝ અને ડેટાબેસ કાયમ માટે ભૂંસી નાખે છે**.          |

> નોંધ: આ કમાન્ડ્સ ચલાવવા માટે OmniRoute પ્રોજેક્ટ ફોલ્ડર પર જાઓ (જો તમે તેને ક્લોન કર્યું હોય) અને તેમને ચલાવો. વૈકલ્પિક રીતે, જો વૈશ્વિક સ્તરે ઇન્સ્ટૉલ કર્યું હોય, તો તમે ફક્ત `npm uninstall -g omniroute` ચલાવી શકો છો.

### Void Linux (xbps-src)

Void Linux વપરાશકર્તાઓ `xbps-src` ક્રોસ-કમ્પાઇલેશન ફ્રેમવર્કનો ઉપયોગ કરીને OmniRoute ને નેટિવ રીતે પૅકેજ અને ઇન્સ્ટૉલ કરી શકે છે. આ જરૂરી `better-sqlite3` નેટિવ બાઇન્ડિંગ્સની સાથે Node.js સ્ટૅન્ડઅલોન બિલ્ડને સ્વચાલિત કરે છે.

```bash
do_check() {

}
```

## 🧩 અદ્યતન સુવિધાઓ

### કસ્ટમ મોડેલ્સ

ઍપ અપડેટની રાહ જોયા વિના કોઈપણ પ્રદાતામાં કોઈપણ મોડેલ ID ઉમેરો:

```bash
# API દ્વારા
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# સૂચિ: curl http://localhost:20128/api/provider-models?provider=openai
# દૂર કરો: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

અથવા ડેશબોર્ડનો ઉપયોગ કરો: **પ્રદાતાઓ → [પ્રદાતા] → કસ્ટમ મોડેલ્સ**.

નોંધો:

- OpenRouter અને OpenAI/Anthropic-સુસંગત પ્રદાતાઓ માત્ર **ઉપલબ્ધ મોડેલ્સ**માંથી સંચાલિત થાય છે. મેન્યુઅલ ઉમેરણ, આયાત અને સ્વતઃ-સિંક—બધું એ જ ઉપલબ્ધ-મોડેલ સૂચિમાં આવે છે, તેથી આ પ્રદાતાઓ માટે અલગ કસ્ટમ મોડેલ્સ વિભાગ નથી.
- **કસ્ટમ મોડેલ્સ** વિભાગ એવા પ્રદાતાઓ માટે બનાવવામાં આવ્યો છે જે સંચાલિત ઉપલબ્ધ-મોડેલ આયાત પ્રદાન કરતા નથી.

### કસ્ટમ OpenAI-સુસંગત પ્રદાતાઓ

OpenAI API સાથે સંચાર કરતું કોઈપણ ગેટવે (સ્વ-હોસ્ટેડ પ્રોક્સી, vLLM, તૃતીય-પક્ષ ઍગ્રીગેટર)
તેના પોતાના પ્રદાતા નોડ તરીકે ઉમેરી શકાય છે:

1. **પ્રદાતાઓ → OpenAI સુસંગત ઉમેરો**.
2. **નામ**: નોડ માટે પ્રદર્શિત થતું લેબલ.
3. **પ્રીફિક્સ**: રૂટિંગ નામ. ક્લાયન્ટ્સ મોડેલ્સને `<prefix>/<model>` તરીકે કૉલ કરે છે, તેથી
   `mygw` પ્રીફિક્સ ધરાવતો નોડ `mygw/gpt-4o-mini` સેવા આપે છે. આવશ્યક છે; અક્ષરો અંગે કોઈ પ્રતિબંધ નથી.
4. **API પ્રકાર**: ગેટવે જે એન્ડપોઇન્ટ ફૅમિલી સેવા આપે છે (ચૅટ કમ્પ્લીશન્સ, રિસ્પોન્સિસ,
   એમ્બેડિંગ્સ, ઑડિયો, ઇમેજિસ).
5. **બેઝ URL**: `/v1` સુધી અને તેને સમાવતું API રૂટ (ઉદાહરણ તરીકે
   `https://gateway.example.com/v1`), સંપૂર્ણ `/chat/completions` પાથ નહીં. બિન-માનક
   પાથ ધરાવતા ગેટવે તેને **અદ્યતન સેટિંગ્સ** હેઠળ સેટ કરે છે (ચૅટ પાથ, મોડેલ્સ પાથ).
6. **API કી (ચકાસણી માટે)** ફીલ્ડ માત્ર કનેક્શનનું પરીક્ષણ કરે છે. નોડ બનાવ્યા પછી,
   તેને ખોલો અને વિનંતીઓ ઉપયોગ કરશે તે કી સંગ્રહિત કરવા માટે **કનેક્શન ઉમેરો**નો ઉપયોગ કરો.

નોડને `openai-compatible-<apiType>-<uuid>` સ્વરૂપનું આંતરિક id મળે છે; તમારે તેને ક્યારેય
ટાઇપ કરવાની જરૂર નથી, પ્રીફિક્સ એ જાહેર નામ છે.

#### આરક્ષિત પ્રીફિક્સ

પ્રીફિક્સ બિલ્ટ-ઇન પ્રદાતાનું id અથવા ઉપનામ (ઉદાહરણ તરીકે `openai`, `cf`) કે
નિવૃત્ત પ્રદાતાનું id હોઈ શકતું નથી. મોડેલ રિઝોલ્વર કસ્ટમ નોડ્સ પહેલાં બિલ્ટ-ઇન ids અને
ઉપનામો તપાસે છે, તેથી તેમાંથી કોઈ પ્રીફિક્સ વાપરતા નોડને ક્યારેય ટ્રાફિક મળશે નહીં:
`<prefix>/model` તેના બદલે બિલ્ટ-ઇન પ્રદાતા પાસે જશે, અથવા તે પ્રદાતા નિવૃત્ત થયો હોય તો
સુરક્ષિત રીતે નિષ્ફળ જશે. આવા પ્રીફિક્સ સાથે નોડ બનાવવા અથવા સંપાદિત કરવાનો પ્રયાસ આ સંદેશ સાથે નકારવામાં આવે છે:

```text
prefix: "<prefix>" આરક્ષિત પ્રદાતા પ્રીફિક્સ છે — અલગ પ્રીફિક્સ પસંદ કરો (આરક્ષિત ids/ઉપનામો કસ્ટમ નોડ્સ માટે વાપરી શકાતા નથી, કારણ કે <prefix>/model જેવી વિનંતીઓ બિલ્ટ-ઇન પ્રદાતા તરફ રૂટ થાય છે અથવા પ્રદાતા નિવૃત્ત હોય ત્યારે સુરક્ષિત રીતે નિષ્ફળ જાય છે)
```

અલગ પ્રીફિક્સ પસંદ કરો (`mygw`, `acme-proxy`). જો કસ્ટમ નોડ માટેની વિનંતીઓ બિલ્ટ-ઇન
પ્રદાતા અથવા તેના ઓળખપત્રોનો ઉલ્લેખ કરતી ભૂલ સાથે નિષ્ફળ જાય, તો નોડનું પ્રીફિક્સ આરક્ષિત
છે કે નહીં તે તપાસો: આ નિયમ અસ્તિત્વમાં આવ્યો તે પહેલાં સાચવેલા નોડ્સ હજુ પણ સંગ્રહિત છે,
પરંતુ તેમનું પ્રીફિક્સ બિલ્ટ-ઇન પ્રદાતા તરફ રૂટ કરે છે. નોડ સંપાદિત કરીને તેને નવું પ્રીફિક્સ આપો.

### OmniRoute પીઅર્સની સાંકળ બનાવવી

અન્ય OmniRoute ગેટવેને **કસ્ટમ OpenAI-સુસંગત** પ્રદાતા તરીકે ઉમેરી શકાય છે. પીઅરના
`/v1` બેઝ URL અને તે પીઅર દ્વારા જારી કરાયેલી સમર્પિત, ન્યૂનતમ-વિશેષાધિકારવાળી API કીનો ઉપયોગ કરો.

પારસ્પરિક અથવા મલ્ટિ-હૉપ સાંકળો માટે, દરેક ગેટવે પર ઑપ્ટ-ઇન લૂપ ગાર્ડ સક્ષમ કરો:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

ફક્ત સ્પષ્ટપણે અનુમતિસૂચિમાં ઉમેરેલા પીઅર URL પર મોકલેલી વિનંતીઓને
`X-OmniRoute-Peer-Trace` હેડર મળે છે. ગેટવે પુનરાવર્તિત ઇન્સ્ટન્સ ID અથવા સમાપ્ત થઈ ગયેલા હૉપ
બજેટને HTTP `508 Loop Detected` સાથે નકારે છે; સામાન્ય અપસ્ટ્રીમ પ્રદાતાઓને કોઈ પીઅર મેટાડેટા મળતો નથી.

પીઅર ચેઇનિંગ એ ડેટાબેઝ રેપ્લિકેશન અથવા હોસ્ટ ફેલઓવર નથી. દરેક ગેટવે સ્વતંત્ર
SQLite સ્થિતિ, કૅશ, દર કાઉન્ટર્સ અને સેશન્સ રાખે છે. ઍક્ટિવ/પૅસિવ અથવા ઍક્ટિવ/ઍક્ટિવ ઉપલબ્ધતા માટે
હેલ્થ-ચેક કરાયેલ રિવર્સ પ્રોક્સી અથવા ક્લાયન્ટ ફેલઓવરનો ઉપયોગ કરો અને એક SQLite ડેટાબેઝને
એકસાથે ચાલતા અનેક OmniRoute ઇન્સ્ટન્સમાં ક્યારેય માઉન્ટ ન કરો.

### સમર્પિત પ્રદાતા રૂટ્સ

મોડેલ માન્યતા સાથે વિનંતીઓને સીધી ચોક્કસ પ્રદાતા તરફ રૂટ કરો:

```bash
POST http://localhost:20128/v1/providers/openai/chat/completions
POST http://localhost:20128/v1/providers/openai/embeddings
POST http://localhost:20128/v1/providers/fireworks/images/generations
```

પ્રદાતા પ્રીફિક્સ ગેરહાજર હોય તો તે આપમેળે ઉમેરાય છે. મેળ ન ખાતા મોડેલ્સ `400` પરત કરે છે.

### નેટવર્ક પ્રોક્સી કૉન્ફિગરેશન

```bash
# ગ્લોબલ પ્રોક્સી સેટ કરો
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"global": {"type":"http","host":"proxy.example.com","port":"8080"}}'

# દરેક પ્રદાતા માટે પ્રોક્સી
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"providers": {"openai": {"type":"socks5","host":"proxy.example.com","port":"1080"}}}'

# પ્રોક્સીનું પરીક્ષણ કરો
curl -X POST http://localhost:20128/api/settings/proxy/test \
  -d '{"proxy":{"type":"socks5","host":"proxy.example.com","port":"1080"}}'
```

**અગ્રતા:** કી-વિશિષ્ટ → કોમ્બો-વિશિષ્ટ → પ્રદાતા-વિશિષ્ટ → ગ્લોબલ → એન્વાયરમેન્ટ.

### ક્લાઉડ સિંક

- પ્રદાતાઓ, કોમ્બોઝ અને સેટિંગ્સને ઉપકરણો વચ્ચે સિંક કરો
- ટાઇમઆઉટ + ફેલ-ફાસ્ટ સાથે સ્વચાલિત બૅકગ્રાઉન્ડ સિંક
- પ્રોડક્શનમાં સર્વર-સાઇડ `NEXT_PUBLIC_BASE_URL`/`NEXT_PUBLIC_CLOUD_URL`ને પ્રાથમિકતા આપો

### Cloudflare ક્વિક ટનલ

- Docker અને અન્ય self-hosted deployments માટે **Dashboard → Endpoints** માં ઉપલબ્ધ છે
- એક અસ્થાયી `https://*.trycloudflare.com` URL બનાવે છે, જે તમારા વર્તમાન OpenAI-compatible `/v1` endpoint પર ફોરવર્ડ કરે છે
- પ્રથમ વખત સક્ષમ કરતાં જરૂર હોય ત્યારે જ `cloudflared` ઇન્સ્ટોલ થાય છે; પછીના restarts એ જ managed binary નો ફરી ઉપયોગ કરે છે
- OmniRoute અથવા container restart પછી Quick Tunnels આપમેળે પુનઃસ્થાપિત થતા નથી; જરૂર પડે ત્યારે dashboard માંથી તેમને ફરી સક્ષમ કરો
- Tunnel URLs અસ્થાયી હોય છે અને જ્યારે પણ તમે tunnel ને બંધ/ચાલુ કરો ત્યારે બદલાય છે
- મર્યાદિત containers માં અવાજભરી QUIC UDP buffer warnings ટાળવા માટે managed Quick Tunnels મૂળભૂત રીતે HTTP/2 transport નો ઉપયોગ કરે છે
- જો તમે managed transport પસંદગીને override કરવા માંગતા હો, તો `CLOUDFLARED_PROTOCOL=quic` અથવા `auto` સેટ કરો
- જો તમે managed download ને બદલે પહેલેથી ઇન્સ્ટોલ કરેલ `cloudflared` binary નો ઉપયોગ કરવાનું પસંદ કરો, તો `CLOUDFLARED_BIN` સેટ કરો
- Cloudflare Quick Tunnel, Tailscale Funnel અને ngrok Tunnel panels ને **Settings → Appearance** માં બતાવી અથવા છુપાવી શકાય છે. Panel છુપાવવાથી ચાલુ tunnel બંધ થતું નથી.

### LLM Gateway ઇન્ટેલિજન્સ (Phase 9)

- **સિમેન્ટિક કૅશ** — Non-streaming, temperature=0 responses ને આપમેળે cache કરે છે (`X-OmniRoute-No-Cache: true` વડે bypass કરો)
- **Request Idempotency** — `Idempotency-Key` અથવા `X-Request-Id` header દ્વારા 5s ની અંદરની requests ને deduplicate કરે છે
- **પ્રગતિ ટ્રૅકિંગ** — `X-OmniRoute-Progress: true` header દ્વારા opt-in SSE `event: progress` events

### ટ્રાન્સલેટર પ્લેગ્રાઉન્ડ

**Dashboard → Translator** દ્વારા ઍક્સેસ કરો. OmniRoute providers વચ્ચે API requests નું ભાષાંતર કેવી રીતે કરે છે તે debug કરો અને દૃશ્યમાન બનાવો.

| મોડ              | હેતુ                                                                                      |
| ---------------- | ----------------------------------------------------------------------------------------- |
| **પ્લેગ્રાઉન્ડ** | Source/target formats પસંદ કરો, request paste કરો અને ભાષાંતરિત output તરત જુઓ            |
| **ચૅટ ટેસ્ટર**   | Proxy મારફતે live chat messages મોકલો અને સંપૂર્ણ request/response cycle નું નિરીક્ષણ કરો |
| **ટેસ્ટ બેન્ચ**  | ભાષાંતરની શુદ્ધતા ચકાસવા માટે અનેક format combinations પર batch tests ચલાવો               |
| **લાઇવ મોનિટર**  | Requests proxy મારફતે પસાર થાય ત્યારે real-time translations જુઓ                          |

**ઉપયોગના કિસ્સાઓ:**

- કોઈ ચોક્કસ client/provider combination શા માટે નિષ્ફળ જાય છે તે debug કરો
- Thinking tags, tool calls અને system prompts નું ભાષાંતર યોગ્ય રીતે થાય છે કે નહીં તે ચકાસો
- OpenAI, Claude, Gemini અને Responses API formats વચ્ચેના format તફાવતોની સરખામણી કરો

### રૂટિંગ વ્યૂહરચનાઓ

**Dashboard → Settings → Routing** દ્વારા ગોઠવો. Dashboard સૌથી વધુ ઉપયોગમાં લેવાતી છ વ્યૂહરચનાઓ દર્શાવે છે; combos અને auto-router આંતરિક રીતે વધુ વ્યાપક સમૂહને સપોર્ટ કરે છે.

**Dashboard માં દેખાતી વ્યૂહરચનાઓ (account-level routing):**

| વ્યૂહરચના                      | વર્ણન                                                                                                         |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| **ફિલ ફર્સ્ટ**                 | Priority ક્રમમાં accounts નો ઉપયોગ કરે છે — primary account અનુપલબ્ધ ન થાય ત્યાં સુધી બધી requests સંભાળે છે  |
| **રાઉન્ડ રોબિન**               | Configurable sticky limit સાથે બધા accounts માં ચક્રાકારે ફરે છે (મૂળભૂત: account દીઠ 3 calls)                |
| **P2C (Power of Two Choices)** | 2 random accounts પસંદ કરીને વધુ સ્વસ્થ account તરફ route કરે છે — health ધ્યાનમાં રાખીને load સંતુલિત કરે છે |
| **રેન્ડમ**                     | Fisher-Yates shuffle નો ઉપયોગ કરીને દરેક request માટે અવ્યવસ્થિત રીતે account પસંદ કરે છે                     |
| **લિસ્ટ યુઝ્ડ**                | સૌથી જૂના `lastUsedAt` timestamp ધરાવતા account તરફ route કરીને traffic સમાન રીતે વહેંચે છે                   |
| **કૉસ્ટ ઑપ્ટિમાઇઝ્ડ**          | સૌથી ઓછી priority value ધરાવતા account તરફ route કરીને સૌથી ઓછા ખર્ચવાળા providers માટે optimize કરે છે       |

**અદ્યતન combo અને auto વ્યૂહરચનાઓ** (દરેક combo માટે અથવા `auto/*` prefixes દ્વારા ગોઠવી શકાય છે — [AUTO-COMBO.md](../routing/AUTO-COMBO.md) જુઓ):

- `priority` — કડક ક્રમ, ક્યારેય round-robin કરતું નથી
- `weighted` — Per-model weights અનુસાર પ્રમાણસર traffic વિભાજન
- `fill-first` — Limits સુધી પહોંચે ત્યાં સુધી પ્રથમ model નો સંપૂર્ણ ઉપયોગ કરે છે
- `round-robin` / `strict-random` / `random`
- `p2c` (Power of Two Choices)
- `least-used` અને `cost-optimized`
- `auto` — બધા candidates માં score-driven પસંદગી
- `lkgp` (Last Known Good Provider) — છેલ્લે સફળ રહેલા provider પર સ્થિર રહે છે, પછી rules પર fallback કરે છે
- `context-optimized` — સૌથી મોટી ખાલી context window ધરાવતું model પસંદ કરે છે
- `context-relay` — Follow-up turns માટે long-context models ને સાંકળે છે

#### બાહ્ય સ્ટિકી સેશન હેડર

બાહ્ય session affinity માટે (ઉદાહરણ તરીકે, reverse proxies પાછળના Claude Code/Codex agents), આ મોકલો:

```http
X-Session-Id: your-session-key
```

OmniRoute `x_session_id` પણ સ્વીકારે છે અને અસરકારક session key ને `X-OmniRoute-Session-Id` માં પરત કરે છે.

જો તમે Nginx નો ઉપયોગ કરતા હો અને underscore-form headers મોકલતા હો, તો આ સક્ષમ કરો:

```nginx
underscores_in_headers on;
```

#### વાઇલ્ડકાર્ડ મોડેલ ઉપનામો

Model names ને remap કરવા માટે wildcard patterns બનાવો:

```
પૅટર્ન: claude-sonnet-*     →  લક્ષ્ય: cc/claude-sonnet-4-6
પૅટર્ન: gpt-*               →  લક્ષ્ય: gh/gpt-5.3-codex
```

Wildcards `*` (કોઈપણ characters) અને `?` (એક character) ને સપોર્ટ કરે છે.

#### ફૉલબૅક ચેઇન્સ

બધી requests પર લાગુ થતી global fallback chains વ્યાખ્યાયિત કરો:

```
ચેઇન: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### સ્થિતિસ્થાપકતા અને સર્કિટ બ્રેકર્સ

**Dashboard → Settings → Resilience** દ્વારા ગોઠવો.

OmniRoute પાંચ components સાથે provider-level resilience અમલમાં મૂકે છે:

1. **Request Queue અને Pacing** — System-level request shaping:
   - **Requests Per Minute (RPM)** — Account દીઠ પ્રતિ મિનિટ મહત્તમ requests
   - **Requests વચ્ચેનો ન્યૂનતમ સમય** — Requests વચ્ચે milliseconds માં ન્યૂનતમ અંતર
   - **મહત્તમ સમકાલીન Requests** — Account દીઠ મહત્તમ એકસાથે ચાલતી requests
2. **કનેક્શન કૂલડાઉન** — ફરી પ્રયાસ કરી શકાય તેવી નિષ્ફળતાઓ પછી એક કનેક્શન માટે પ્રતિ-ઑથ-પ્રકાર રૂપરેખાંકન:
   - **મૂળ કૂલડાઉન** — ફરી પ્રયાસ કરી શકાય તેવી અપસ્ટ્રીમ નિષ્ફળતાઓ માટે ડિફૉલ્ટ કૂલડાઉન સમયગાળો
   - **અપસ્ટ્રીમ પુનઃપ્રયાસ સંકેતોનો ઉપયોગ કરો** — ઉપલબ્ધ કરાવવામાં આવે ત્યારે અધિકૃત `Retry-After` અથવા રીસેટ સંકેતોનું પાલન કરે છે
   - **મહત્તમ બૅકઑફ સ્ટેપ્સ** — વારંવાર થતી નિષ્ફળતાઓ માટે મહત્તમ એક્સ્પોનેન્શિયલ બૅકઑફ સ્તર

3. **પ્રોવાઇડર સર્કિટ બ્રેકર** — પ્રોવાઇડરની શરૂઆતથી અંત સુધીની નિષ્ફળતાઓને ટ્રૅક કરે છે, રૂપરેખાંકિત ચેતવણી થ્રેશોલ્ડ પર પ્રોવાઇડરને નબળું ચિહ્નિત કરે છે અને રૂપરેખાંકિત નિષ્ફળતા થ્રેશોલ્ડ પર પહોંચતાં બ્રેકર ખોલે છે:
   - **ડિગ્રેડેશન થ્રેશોલ્ડ** — `DEGRADED` સ્થિતિમાં પ્રવેશતા પહેલાંની સળંગ પ્રોવાઇડર નિષ્ફળતાઓ
   - **નિષ્ફળતા થ્રેશોલ્ડ** — `OPEN` સ્થિતિમાં પ્રવેશતા પહેલાંની સળંગ પ્રોવાઇડર નિષ્ફળતાઓ
   - **રીસેટ સમયસમાપ્તિ** — પ્રોવાઇડરનું ફરી પરીક્ષણ કરવામાં આવે તે પહેલાંનો સમયગાળો
   - **CLOSED** (સ્વસ્થ) — વિનંતીઓ સામાન્ય રીતે પ્રવાહિત થાય છે
   - **DEGRADED** — નિષ્ફળતાઓના વધેલા પ્રમાણને ટ્રૅક કરવામાં આવે ત્યારે પણ વિનંતીઓ પ્રવાહિત થતી રહે છે
   - **OPEN** — વારંવારની નિષ્ફળતાઓ પછી પ્રોવાઇડર અસ્થાયી રૂપે અવરોધિત થાય છે
   - **HALF_OPEN** — પ્રોવાઇડર પુનઃસ્થાપિત થયો છે કે નહીં તેનું પરીક્ષણ થઈ રહ્યું છે

   કનેક્શન-સ્કોપવાળી `429` દર મર્યાદાઓ **કનેક્શન કૂલડાઉન**માં રહે છે અને પ્રોવાઇડર બ્રેકરની ગણતરીમાં સામેલ થતી નથી.

   પ્રોવાઇડર બ્રેકરની રનટાઇમ સ્થિતિ ફક્ત **ડૅશબોર્ડ → હેલ્થ** પર દર્શાવવામાં આવે છે.

4. **કૂલડાઉનની રાહ જુઓ** — જો દરેક ઉમેદવાર કનેક્શન પહેલેથી જ કૂલડાઉનમાં હોય, તો OmniRoute સૌથી વહેલા પૂર્ણ થતા કૂલડાઉન સુધી રાહ જોઈ શકે છે અને એ જ ક્લાયન્ટ વિનંતીનો આપમેળે ફરી પ્રયાસ કરી શકે છે.

5. **દર મર્યાદાની આપમેળે ઓળખ** — જ્યારે અપસ્ટ્રીમ પ્રોવાઇડર્સ સ્પષ્ટ પ્રતીક્ષા સમયગાળો પરત કરે છે, ત્યારે સેટિંગ સક્ષમ હોય તો તે સંકેતો સ્થાનિક કનેક્શન કૂલડાઉનને ઓવરરાઇડ કરે છે.

**પ્રો ટિપ:** આઉટેજ પછી જીવંત પ્રોવાઇડર બ્રેકર્સનું નિરીક્ષણ અને રીસેટ કરવા માટે **હેલ્થ** પેજનો ઉપયોગ કરો. રિઝિલિયન્સ પેજ ફક્ત રૂપરેખાંકન બદલે છે.

### ડેટાબેઝ એક્સપોર્ટ / ઇમ્પોર્ટ

**ડૅશબોર્ડ → સેટિંગ્સ → સિસ્ટમ અને સ્ટોરેજ**માં ડેટાબેઝ બૅકઅપ્સનું સંચાલન કરો.

| ક્રિયા                           | વર્ણન                                                                                                                                                        |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **ડેટાબેઝ એક્સપોર્ટ કરો**        | વર્તમાન SQLite ડેટાબેઝને `.sqlite` ફાઇલ તરીકે ડાઉનલોડ કરે છે                                                                                                 |
| **બધું એક્સપોર્ટ કરો (.tar.gz)** | ડેટાબેઝ, સેટિંગ્સ, કોમ્બોઝ, પ્રોવાઇડર કનેક્શન્સ (ક્રેડેન્શિયલ્સ વિના) અને API કી મેટાડેટા સહિત સંપૂર્ણ બૅકઅપ આર્કાઇવ ડાઉનલોડ કરે છે                          |
| **ડેટાબેઝ ઇમ્પોર્ટ કરો**         | વર્તમાન ડેટાબેઝને બદલવા માટે `.sqlite` ફાઇલ અપલોડ કરે છે. `DISABLE_SQLITE_AUTO_BACKUP=true` ન હોય ત્યાં સુધી ઇમ્પોર્ટ પહેલાંનો બૅકઅપ આપમેળે બનાવવામાં આવે છે |

```bash
# API: ડેટાબેઝ એક્સપોર્ટ કરો
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: બધું એક્સપોર્ટ કરો (સંપૂર્ણ આર્કાઇવ)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: ડેટાબેઝ ઇમ્પોર્ટ કરો
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**ઇમ્પોર્ટની માન્યતા ચકાસણી:** ઇમ્પોર્ટ કરેલી ફાઇલની અખંડિતતા (SQLite pragma ચકાસણી), જરૂરી ટેબલ્સ (`provider_connections`, `provider_nodes`, `combos`, `api_keys`) અને કદ (મહત્તમ 100MB) માટે માન્યતા ચકાસવામાં આવે છે.

**ઉપયોગના કિસ્સાઓ:**

- OmniRouteને એક મશીનથી બીજા મશીન પર સ્થાનાંતરિત કરો
- આપત્તિ પુનઃપ્રાપ્તિ માટે બાહ્ય બૅકઅપ્સ બનાવો
- ટીમના સભ્યો વચ્ચે રૂપરેખાંકનો શેર કરો (બધું એક્સપોર્ટ કરો → આર્કાઇવ શેર કરો)

### સેટિંગ્સ ડૅશબોર્ડ

| ટૅબ            | સામગ્રી                                                                                                                                                               |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **સામાન્ય**    | સિસ્ટમ સ્ટોરેજ સાધનો, ડિફૉલ્ટ વર્તન, એન્ડપોઇન્ટ ટનલની દૃશ્યતા                                                                                                         |
| **દેખાવ**      | થીમ નિયંત્રણો (લાઇટ/ડાર્ક/સિસ્ટમ), સાઇડબારની દૃશ્યતા, Cloudflare/Tailscale/ngrok ટનલ કાર્ડ્સ માટે પૅનલ ટૉગલ્સ                                                         |
| **AI**         | થિંકિંગ બજેટ (પાસથ્રૂ / ઑટો-સ્ટ્રિપ / કસ્ટમ / ઍડૅપ્ટિવ — [THINKING_BUDGET.md](./THINKING_BUDGET.md) જુઓ), વૈશ્વિક સિસ્ટમ પ્રૉમ્પ્ટ, પ્રૉમ્પ્ટ કૅશના આંકડા             |
| **સુરક્ષા**    | લૉગિન/પાસવર્ડ સેટિંગ્સ, IP ઍક્સેસ નિયંત્રણ, `/models` માટે API ઑથ, પ્રોવાઇડર બ્લૉકિંગ, પ્રૉમ્પ્ટ-ઇન્જેક્શન ગાર્ડ                                                      |
| **રાઉટિંગ**    | વૈશ્વિક રાઉટિંગ વ્યૂહરચના (પહેલાં ભરો / રાઉન્ડ રોબિન / P2C / રૅન્ડમ / સૌથી ઓછું વપરાયેલ / ખર્ચ-ઑપ્ટિમાઇઝ્ડ), વાઇલ્ડકાર્ડ મૉડલ ઉપનામો, ફૉલબૅક ચેઇન્સ, કોમ્બો ડિફૉલ્ટ્સ |
| **રિઝિલિયન્સ** | વિનંતી કતાર, કનેક્શન કૂલડાઉન, પ્રોવાઇડર બ્રેકર રૂપરેખાંકન અને કૂલડાઉન માટે રાહ જોવાનું વર્તન                                                                          |
| **ઍડવાન્સ્ડ**  | વૈશ્વિક પ્રૉક્સી રૂપરેખાંકન (HTTP/SOCKS5), પ્રતિ-પ્રોવાઇડર પ્રૉક્સી ઓવરરાઇડ્સ                                                                                         |

સામાન્ય વિભાગમાં હવે ફક્ત વાંચી શકાય તેવી લૉગિંગ અને કૅશ નોંધોનું પુનરાવર્તન થતું નથી. ડેટાબેઝ રિટેન્શન અને
ઑપ્ટિમાઇઝેશન સેટિંગ્સ `/api/settings/database` મારફતે જાળવી રાખવામાં આવે છે; મૅન્યુઅલ કૅશ સાફ કરવા માટે
`DELETE /api/cache`નો ઉપયોગ થાય છે. વિનંતી અને પ્રૉક્સી લૉગની પંક્તિ મર્યાદાઓ
`CALL_LOGS_TABLE_MAX_ROWS` અને `PROXY_LOGS_TABLE_MAX_ROWS` દ્વારા નિયંત્રિત થાય છે.

### ઑડિયો ટ્રાન્સક્રિપ્શન

OmniRoute OpenAI-સુસંગત એન્ડપોઇન્ટ દ્વારા ઑડિયો ટ્રાન્સક્રિપ્શનને સપોર્ટ કરે છે:

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data

# curl સાથેનું ઉદાહરણ
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@audio.mp3" \
  -F "model=openai/whisper-1"
```

`deepgram/nova-3` મૂળ Deepgram રૂટ છે અને તેને Deepgram API કીની જરૂર પડે છે.
જો માત્ર OpenRouter કૉન્ફિગર કરેલું હોય, તો `openrouter/deepgram/nova-3`નો ઉપયોગ કરો.

### કૉમ્બો સંતુલન વ્યૂહરચનાઓ

દરેક કૉમ્બો માટેનું સંતુલન **Dashboard → Combos → Create/Edit → Strategy**માં કૉન્ફિગર કરો.

| વ્યૂહરચના               | વર્ણન                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------- |
| **રાઉન્ડ-રોબિન**        | મોડલ્સને ક્રમિક રીતે ફેરવતું રહે છે                                                   |
| **પ્રાથમિકતા**          | હંમેશાં પ્રથમ મોડલનો પ્રયાસ કરે છે; માત્ર ભૂલ થાય ત્યારે જ ફૉલબૅક કરે છે              |
| **રેન્ડમ**              | દરેક વિનંતી માટે કૉમ્બોમાંથી રેન્ડમ મોડલ પસંદ કરે છે                                  |
| **વેઇટેડ**              | દરેક મોડલને ફાળવેલા વજનના આધારે પ્રમાણસર રૂટ કરે છે                                   |
| **સૌથી ઓછું વપરાયેલું** | સૌથી ઓછી તાજેતરની વિનંતીઓ ધરાવતા મોડલ પર રૂટ કરે છે (કૉમ્બો મેટ્રિક્સનો ઉપયોગ કરે છે) |
| **ખર્ચ-ઑપ્ટિમાઇઝ્ડ**    | ઉપલબ્ધ સૌથી સસ્તા મોડલ પર રૂટ કરે છે (કિંમત કોષ્ટકનો ઉપયોગ કરે છે)                    |

વૈશ્વિક કૉમ્બો ડિફૉલ્ટ્સ **Dashboard → Settings → Routing → Combo Defaults**માં સેટ કરી શકાય છે.
કૉમ્બો ટાર્ગેટ ટાઇમઆઉટ્સ ડિફૉલ્ટ રૂપે વર્તમાન વિનંતીનો ટાઇમઆઉટ વારસામાં મેળવે છે. ફક્ત જ્યારે ટૂંકી પ્રતિ-ટાર્ગેટ મર્યાદાથી
વધુ ઝડપી ફૉલબૅક ટ્રિગર થવો જોઈએ ત્યારે જ કૉમ્બો ડિફૉલ્ટ્સ અથવા કોઈ વ્યક્તિગત કૉમ્બો પર **Target timeout
(seconds)**નો ઉપયોગ કરો.

ઝીરો-લેટન્સી કૉમ્બો ઑપ્ટિમાઇઝેશન્સ પસંદગીપૂર્વક સક્ષમ કરવાના હોય છે. આ લેટન્સી સુવિધાઓ ફૉલબૅક ટાર્ગેટ્સ સાથે સ્પર્ધા ન કરે,
TTFT ઇતિહાસના આધારે ટાર્ગેટ્સને સ્કિપ ન કરે અથવા ફૉલબૅક વિનંતીઓને સંકુચિત ન કરે તે માટે **Zero-latency optimizations**ને અક્ષમ રાખો;
તેને સક્ષમ કરવાથી કૉન્ફિગર કરેલું હેજિંગ, આગાહી આધારિત TTFT સ્કિપ્સ અને સક્રિય ફૉલબૅક સંકોચન, ઓછી ટેઇલ
લેટન્સીના બદલામાં રૂટિંગ/વિનંતીની મૂળનિષ્ઠા સાથે સમાધાન કરી શકે છે.

જ્યારે અપસ્ટ્રીમ પ્રદાતાઓને સખત
`max_tokens` / `maxOutputTokens` મર્યાદાઓની જરૂર હોય ત્યારે **Reasoning token buffer**ને અક્ષમ કરો. સક્ષમ હોય ત્યારે, કૉમ્બો રૂટિંગ માત્ર જાણીતી આઉટપુટ મર્યાદા ધરાવતા મોડલ્સ માટે
રીઝનિંગ-મોડલ હેડરૂમ ઉમેરે છે અને જ્યારે સુરક્ષિત બફર કરેલું મૂલ્ય તે મર્યાદાને વટાવી જાય ત્યારે ક્લાયન્ટ ટોકન મર્યાદાને યથાવત્ રાખે છે. જો ક્લાયન્ટ મર્યાદા પહેલેથી જ જાણીતી મર્યાદા કરતાં વધુ હોય,
તો અપસ્ટ્રીમ વિનંતી મોકલતા પહેલાં OmniRoute તેને ઘટાડીને તે મર્યાદા પર સેટ કરે છે.

## 🤖 ઑટો-રાઉટિંગ (શૂન્ય-કન્ફિગ)

OmniRoute એક **સ્કોર-આધારિત ઑટો-રાઉટર** સાથે આવે છે, જે દરેક કનેક્ટેડ પ્રદાતા પરની પ્રત્યેક વિનંતી માટે શ્રેષ્ઠ મોડલ પસંદ કરે છે — જાળવવા માટે કોઈ કોમ્બો નથી. ફક્ત `auto/*` પ્રીફિક્સમાંથી કોઈ એક સાથે વિનંતી મોકલો અને OmniRoute તરત જ વર્ચ્યુઅલ કોમ્બો તૈયાર કરશે, જેમાં વિલંબ, ખર્ચ, સફળતા દર, સંદર્ભ સુસંગતતા, કાર્ય માટે મોડલની યોગ્યતા, તાજેતરની નિષ્ફળતાઓ, ક્વોટા અને સર્કિટ-બ્રેકરની સ્થિતિના આધારે ઉમેદવારોને સ્કોર કરવામાં આવશે.

| પ્રીફિક્સ      | શેના માટે ઑપ્ટિમાઇઝ કરે છે                                                                |
| -------------- | ----------------------------------------------------------------------------------------- |
| `auto`         | સંતુલિત ડિફૉલ્ટ (વિલંબ × ખર્ચ × સફળતા દર)                                                 |
| `auto/coding`  | કોડિંગ કાર્યો: Claude, GPT-5, GLM, Kimi, Qwen Coder, DeepSeek કોડર્સને પ્રાધાન્ય આપે છે   |
| `auto/cheap`   | સૌથી ઓછો $/token, વધુ વિલંબ સ્વીકારે છે                                                   |
| `auto/fast`    | સૌથી ઓછો વિલંબ, ખર્ચને અવગણે છે                                                           |
| `auto/offline` | ફક્ત સ્થાનિક પ્રદાતાઓ (Ollama, vLLM, llama.cpp) — એર-ગૅપ્ડ સેટઅપ્સ માટે ઉપયોગી            |
| `auto/smart`   | રિઝનિંગ ગુણવત્તાને પ્રથમ પ્રાધાન્ય (Opus, GPT-5 xhigh, R1, GLM 5.1 રિઝનિંગ)               |
| `auto/lkgp`    | "છેલ્લો જાણીતો સારો પ્રદાતા" — છેલ્લા સફળ પ્રદાતા સાથે પિન કરે છે, પછી નિયમોનો આશરો લે છે |

ઉદાહરણ:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Refactor this Python function" }],
    "stream": true
  }'
```

ઑટો-રાઉટરનું સંપૂર્ણ વર્ણન [AUTO-COMBO.md](../routing/AUTO-COMBO.md)માં છે — જેમાં સ્કોરિંગ વેઇટ્સને કેવી રીતે ટ્યુન કરવા, પ્રદાતાઓને બ્લૅકલિસ્ટ કરવા અને **Dashboard → Auto Combo**માં રાઉટિંગ નિર્ણયોનું નિરીક્ષણ કરવા જેવી બાબતોનો સમાવેશ થાય છે.

## 🔌 MCP અને A2A એકીકરણ

OmniRoute એક **MCP સર્વર** (Model Context Protocol) અને એક **A2A સર્વર** (Agent-to-Agent JSON-RPC 2.0) બંને છે. કોઈપણ MCP-સુસંગત IDE અથવા એજન્ટ હોસ્ટ OmniRoute ટૂલ્સને સીધા કૉલ કરી શકે છે — કોઈ વધારાના રૅપરની જરૂર નથી.

### MCP ટ્રાન્સપોર્ટ્સ

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **સ્ટ્રીમ કરી શકાય તેવું HTTP**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (stdio પસંદ કરતા IDE પ્લગઇન્સ માટે)

### Claude Desktopને કનેક્ટ કરો

`~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) અથવા Windows/Linux પર તેની સમકક્ષ ફાઇલમાં ફેરફાર કરો:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Cursor / Continue / VS Code MCPને કનેક્ટ કરો

SSE URL `http://localhost:20128/api/mcp/sse` અને **Dashboard → API Keys**માં જનરેટ કરેલી Bearer API કીનો ઉપયોગ કરો.

### સ્કોપ્સ

MCP હાલમાં 32 નામિત સ્કોપ્સ વ્યાખ્યાયિત કરે છે. દરેક Bearer કીને ચોક્કસ સ્કોપ્સ સુધી મર્યાદિત કરી શકાય છે — અધિકૃત સ્કોપ અને ટૂલ ઇન્વેન્ટરી માટે [MCP-SERVER.md](../frameworks/MCP-SERVER.md) અને JSON-RPC સ્કીમા માટે [A2A-SERVER.md](../frameworks/A2A-SERVER.md) જુઓ.

## 🧠 કૌશલ્ય સિસ્ટમ

OmniRoute એક વિસ્તૃત કરી શકાય તેવું **કૌશલ્ય ફ્રેમવર્ક** (`src/lib/skills/`) પ્રદાન કરે છે, જેથી એજન્ટો અને A2A એન્ડપોઇન્ટ ડોમેન-વિશિષ્ટ રૂટિન્સ (દા.ત. `code-review`, `summarize`, `extract-facts`, `web-research`) ચલાવી શકે.

- **માર્કેટપ્લેસ UI** — **Dashboard → Skills**માંથી કૌશલ્યો બ્રાઉઝ અને ઇન્સ્ટૉલ કરો
- **પ્રતિ-કી સ્કોપ્સ** — કઈ API કીઓ કયા કૌશલ્યોને આમંત્રિત કરી શકે તે નિયંત્રિત કરો
- **કસ્ટમ કૌશલ્યો** — `src/lib/a2a/skills/`માં TypeScript ફાઇલ મૂકો, તેને રજિસ્ટર કરો અને તે તરત જ A2A મારફતે આમંત્રિત કરી શકાય તેવી બની જાય છે

સંપૂર્ણ સંદર્ભ: [SKILLS.md](../frameworks/SKILLS.md).

## 💾 મેમરી સિસ્ટમ

OmniRoute હાઇબ્રિડ રિટ્રીવલ સાથે **લાંબા ગાળાની સંવાદાત્મક મેમરી** જાળવી રાખે છે:

- અગાઉના સંવાદોમાં કીવર્ડ શોધ માટે **SQLite FTS5**
- અર્થ-આધારિત પુનઃસ્મરણ માટે **Qdrant vector store** (વૈકલ્પિક)
- **સ્વચાલિત હકીકત નિષ્કર્ષણ** — દરેક સત્ર પછી એન્ટિટીઝ, પસંદગીઓ અને નિર્ણયોનો સારાંશ બનાવીને `memory_facts` ટેબલમાં સંગ્રહિત કરવામાં આવે છે
- મેમરીઝને દરેક API કી અને દરેક સત્ર દીઠ અલગ સ્કોપ કરવામાં આવે છે

**Dashboard → Memory**માં મેમરીઝનું સંચાલન કરો (શોધો, સંપાદિત કરો, નિકાસ કરો, સાફ કરો). HTTP ઇન્ટરફેસ (`/api/memory/*`) એજન્ટોને પ્રોગ્રામેટિક રીતે હકીકતો પુશ કરવા અને ક્વેરી કરવાની સુવિધા આપે છે — [MEMORY.md](../frameworks/MEMORY.md) જુઓ.

## 🛠️ પ્રોગ્રામેટિક સંચાલન

તમે **`manage` સ્કોપ ધરાવતી Bearer કી**નો ઉપયોગ કરીને HTTP મારફતે દરેક OmniRoute સંસાધન (પ્રોવાઇડર્સ, કોમ્બોઝ, કીઓ, સેટિંગ્સ)નું સંચાલન કરી શકો છો.

**Dashboard → API Keys → New Key → Scope: manage**માં કી જનરેટ કરો, ત્યારબાદ:

```bash
# પ્રોવાઇડર્સની યાદી મેળવો
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# પ્રોવાઇડર કનેક્શન ઉમેરો
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# કોમ્બો બનાવો
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# API કીઓની યાદી મેળવો/બનાવો
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
```

## 💻 આંતરિક CLI

OmniRoute સેટઅપ, નિદાન અને રનટાઇમ નિયંત્રણ માટે આંતરિક CLI (`omniroute …`) સાથે આવે છે. આ **ડૅશબોર્ડમાંના "CLI Tools" પૃષ્ઠથી અલગ છે**, જે તૃતીય-પક્ષ CLI (Claude Code, Cursor, Codex, Cline, …) ને ગોઠવે છે જેથી તેઓ OmniRoute સાથે સંચાર કરી શકે.

```bash
omniroute setup                    # ઇન્ટરેક્ટિવ વિઝાર્ડ (પાસવર્ડ, પ્રોવાઇડર્સ, કોમ્બોઝ)
omniroute setup --non-interactive  # CI માટે અનુકૂળ
omniroute doctor                   # સ્વાસ્થ્ય નિદાન (ડેટા ડિરેક્ટરી, DB, પ્રોવાઇડર્સ, પોર્ટ્સ)
omniroute providers available      # સપોર્ટેડ પ્રોવાઇડર્સની યાદી
omniroute providers list           # ગોઠવેલા કનેક્શન્સની યાદી
omniroute providers test <id>      # પ્રોવાઇડર કનેક્શનનું લાઇવ પરીક્ષણ
omniroute combos list              # કોમ્બોઝની યાદી
omniroute combos switch <name>     # ડિફૉલ્ટ કોમ્બો સેટ કરો
omniroute models                   # ઉપલબ્ધ મોડલ્સની યાદી (--json, --search)
omniroute keys add | list | remove # ટર્મિનલમાંથી API કીઝનું સંચાલન કરો
omniroute backup                   # કન્ફિગ + DBનો સ્નૅપશૉટ
omniroute restore [<timestamp>]    # સ્નૅપશૉટમાંથી પુનઃસ્થાપિત કરો
omniroute health                   # વિગતવાર સ્વાસ્થ્ય (બ્રેકર્સ, કૅશ, મેમરી)
omniroute quota                    # પ્રોવાઇડર ક્વોટાનો વપરાશ
omniroute mcp status               # MCP સર્વરની સ્થિતિ
omniroute a2a status               # A2A સર્વરની સ્થિતિ
omniroute tunnel list|create|stop  # Cloudflare/Tailscale/ngrok ટનલ્સ
omniroute reset-password           # એડમિન પાસવર્ડ રીસેટ કરો
omniroute --mcp                    # stdio પર MCP સર્વર શરૂ કરો
omniroute --port 3000              # કસ્ટમ પોર્ટ પર સર્વર શરૂ કરો
```

સૂચન: અસ્વસ્થ પ્રોવાઇડર કનેક્શન્સ વિશે ચેતવણી મેળવવા માટે `omniroute doctor --json` ને તમારા મોનિટરિંગ ટૂલ સાથે જોડો.

## 🖥️ ડેસ્કટૉપ એપ્લિકેશન (Electron)

OmniRoute Windows, macOS અને Linux માટે મૂળ ડેસ્કટૉપ એપ્લિકેશન તરીકે ઉપલબ્ધ છે.

### ઇન્સ્ટોલેશન

```bash
# electron ડિરેક્ટરીમાંથી:
cd electron
npm install

# ડેવલપમેન્ટ મોડ (ચાલતા Next.js ડેવ સર્વર સાથે કનેક્ટ કરો):
npm run dev

# પ્રોડક્શન મોડ (સ્ટૅન્ડઅલોન બિલ્ડનો ઉપયોગ કરે છે):
npm start
```

### ઇન્સ્ટોલર્સ બનાવવા

```bash
cd electron
npm run build          # વર્તમાન પ્લેટફોર્મ
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg યુનિવર્સલ)
npm run build:linux    # Linux (.AppImage)
```

આઉટપુટ → `electron/dist-electron/`

### મુખ્ય સુવિધાઓ

| સુવિધા                         | વર્ણન                                                        |
| ------------------------------ | ------------------------------------------------------------ |
| **સર્વરની તૈયારી**             | વિન્ડો બતાવતાં પહેલાં સર્વરને પોલ કરે છે (ખાલી સ્ક્રીન નહીં) |
| **સિસ્ટમ ટ્રે**                | ટ્રેમાં મિનિમાઇઝ કરો, પોર્ટ બદલો, ટ્રે મેનૂમાંથી બંધ કરો     |
| **પોર્ટ સંચાલન**               | ટ્રેમાંથી સર્વર પોર્ટ બદલો (સર્વર આપમેળે રીસ્ટાર્ટ થાય છે)   |
| **કન્ટેન્ટ સિક્યોરિટી પૉલિસી** | સેશન હેડર્સ મારફતે પ્રતિબંધિત CSP                            |
| **સિંગલ ઇન્સ્ટન્સ**            | એક સમયે એપ્લિકેશનનો માત્ર એક ઇન્સ્ટન્સ ચાલી શકે છે           |
| **ઑફલાઇન મોડ**                 | બંડલ કરેલું Next.js સર્વર ઇન્ટરનેટ વિના કામ કરે છે           |
