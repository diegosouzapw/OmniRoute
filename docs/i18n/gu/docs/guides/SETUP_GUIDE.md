## ઇન્સ્ટોલ કરવાની પદ્ધતિઓ

### npm (ભલામણ કરેલ)

```bash
npm install -g omniroute
omniroute
```

ડૅશબોર્ડ `http://localhost:20128` પર ખુલે છે અને API બેઝ URL `http://localhost:20128/v1` છે.

### pnpm

```bash
pnpm add -g omniroute@latest --allow-build=better-sqlite3 --allow-build=@swc/core
omniroute
```

> **pnpm વપરાશકર્તાઓ:** `better-sqlite3` અને `@swc/core` માટે નેટિવ બિલ્ડ સ્ક્રિપ્ટ્સ સક્ષમ કરવા `--allow-build` ફ્લૅગ આવશ્યક છે. pnpm v11 પર ગ્લોબલ ઇન્સ્ટોલ માટે `pnpm approve-builds -g` કમાન્ડ સમર્થિત નથી.

### Arch Linux (AUR)

```bash
yay -S omniroute-bin
systemctl --user enable --now omniroute.service
```

[AUR પૅકેજ](https://aur.archlinux.org/packages/omniroute-bin) OmniRoute ઇન્સ્ટોલ કરે છે અને systemd યુઝર સર્વિસ પ્રદાન કરે છે.

### સોર્સમાંથી

```bash
npm install
PORT=20128 DASHBOARD_PORT=20129 NEXT_PUBLIC_BASE_URL=http://localhost:20129 npm run dev
```

> **Windows નોંધ:** ડિફૉલ્ટ રૂપે, જ્યારે લેગસી `%USERPROFILE%\.omniroute` ડિરેક્ટરી હાજર ન હોય ત્યારે OmniRoute `%APPDATA%\omniroute` નો ઉપયોગ કરે છે. અલગ ડેટા-ડિરેક્ટરી સ્થાન પસંદ કરવા માટે `DATA_DIR` સેટ કરો.

> **નોંધ:** પ્રથમ વખત ચલાવતી વખતે `npm install`, `.env.example` માંથી `.env` આપમેળે જનરેટ કરે છે. ત્યાર પછીના ઇન્સ્ટોલ હાલની `.env` ફાઇલને ઓવરરાઇટ કરશે નહીં, જેથી કસ્ટમાઇઝેશનો જળવાઈ રહે છે. ફરીથી પ્રારંભિક મૂલ્યો ભરવા માટે, ફરી ચલાવતા પહેલાં `.env` કાઢી નાખો.

### Docker

Compose પ્રોફાઇલ્સ અને Caddy HTTPS સહિતના સંપૂર્ણ Docker સેટઅપ માટે [Docker માર્ગદર્શિકા](./DOCKER_GUIDE.md) જુઓ.

### ડેસ્કટૉપ ઍપ (Electron)

OmniRoute સાથે Electron 41 + electron-builder 26.10 પર બનેલું ડેસ્કટૉપ રૅપર આપવામાં આવે છે. ઉપલબ્ધ સ્ક્રિપ્ટ્સ (વર્કસ્પેસ રૂટ):

```bash
npm run electron:dev          # હૉટ-રિલોડ સાથે ડેસ્કટૉપ ચલાવો
npm run electron:build        # વર્તમાન OS માટે બિલ્ડ કરો (આપમેળે શોધાયેલ)
npm run electron:build:win    # Windows ઇન્સ્ટોલર (NSIS + પોર્ટેબલ)
npm run electron:build:mac    # macOS (dmg + zip, arm64+x64)
npm run electron:build:linux  # Linux (AppImage + deb + rpm)
npm run electron:smoke:packaged  # પૅકેજ કરેલા બિલ્ડનું સ્મોક-ટેસ્ટ કરો
```

ડેસ્કટૉપ ઇન્સ્ટોલર્સની રિલીઝ GitHub Releases સાથે જોડવામાં આવે છે. Electron વિશેની સંપૂર્ણ વિગતવાર માહિતી (સાઇનિંગ, IPC બ્રિજ, ડિસ્ટ્રોઝ) માટે [`ELECTRON_GUIDE.md`](./ELECTRON_GUIDE.md) _(પછીના તબક્કામાં બનાવેલ)_ જુઓ.

### હેડલેસ સર્વર (CI/ઑટોમેશન)

માનવીય હસ્તક્ષેપ વિનાના સેટઅપ્સ (Docker, Kubernetes, CI) માટે આનો ઉપયોગ કરો:

```bash
omniroute setup --non-interactive
omniroute providers test-batch
```

એન્વાયરમેન્ટ વેરિએબલ્સ (`INITIAL_PASSWORD`, `OMNIROUTE_WS_BRIDGE_SECRET`, વગેરે) સાથે સંયોજિત કરીને, આ તમને સંપૂર્ણપણે સ્ક્રિપ્ટ કરી શકાય તેવો OmniRoute ઇન્સ્ટન્સ શરૂ કરવાની સુવિધા આપે છે.

### CLI વિકલ્પો

| કમાન્ડ                  | વર્ણન                                                                                |
| ----------------------- | ------------------------------------------------------------------------------------ |
| `omniroute`             | સર્વર શરૂ કરો (`PORT=20128`, API અને ડૅશબોર્ડ એક જ પોર્ટ પર)                         |
| `omniroute setup`       | પાસવર્ડ અને પ્રથમ પ્રોવાઇડર માટે માર્ગદર્શિત CLI ઑનબોર્ડિંગ                          |
| `omniroute doctor`      | સર્વર શરૂ કર્યા વિના સ્થાનિક હેલ્થ ચેક્સ ચલાવો                                       |
| `omniroute providers`   | CLI માંથી પ્રોવાઇડર્સ શોધો, સૂચિબદ્ધ કરો, માન્ય કરો અને ચકાસો                        |
| `omniroute config`      | CLI ટૂલ રૂપરેખાંકન — રૂપરેખાંકનો સૂચિબદ્ધ કરો, મેળવો, સેટ કરો અને માન્ય કરો          |
| `omniroute status`      | ઑફલાઇન સ્ટેટસ ડૅશબોર્ડ — વર્ઝન, DB, ટૂલ્સ, રૂપરેખાંકન                                |
| `omniroute logs`        | API માંથી વપરાશ લૉગ્સ સ્ટ્રીમ કરો (`--follow` ને સમર્થન આપે છે)                      |
| `omniroute update`      | OmniRoute અપડેટ્સ તપાસો અથવા લાગુ કરો                                                |
| `omniroute provider`    | પ્રોવાઇડર કનેક્શન્સ મેનેજ કરો — ઉમેરો, સૂચિબદ્ધ કરો, દૂર કરો, ચકાસો, ડિફૉલ્ટ સેટ કરો |
| `omniroute --port 3000` | કૅનોનિકલ/API પોર્ટને 3000 પર સેટ કરો                                                 |
| `omniroute --mcp`       | MCP સર્વર શરૂ કરો (stdio ટ્રાન્સપોર્ટ)                                               |
| `omniroute --no-open`   | બ્રાઉઝર આપમેળે ખોલશો નહીં                                                            |
| `omniroute --help`      | સહાય બતાવો                                                                           |

હેડલેસ સેટઅપને ફ્લૅગ્સ અથવા એન્વાયરમેન્ટ વેરિએબલ્સ વડે સ્ક્રિપ્ટ કરી શકાય છે:

```bash
omniroute setup --non-interactive --password "$OMNIROUTE_PASSWORD"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY" --test-provider
```

ડૅશબોર્ડ ખોલ્યા વિના સ્થાનિક ડાયગ્નોસ્ટિક્સ ચલાવો:

```bash
omniroute doctor
omniroute doctor --json
omniroute doctor --no-liveness
```

ડૅશબોર્ડ ખોલ્યા વિના SSH અથવા સ્ક્રિપ્ટ્સમાંથી પ્રોવાઇડર્સ મેનેજ કરો:

```bash
omniroute providers available
omniroute providers available --search openai
omniroute providers available --category api-key
omniroute providers list
omniroute providers test <id-or-name>
omniroute providers test-all
omniroute providers validate
```

## CLI ટૂલ કૉન્ફિગરેશન

### 1) પ્રોવાઇડર્સ કનેક્ટ કરો અને API કી બનાવો

1. Dashboard → `Providers` ખોલો અને ઓછામાં ઓછો એક પ્રોવાઇડર કનેક્ટ કરો (OAuth અથવા API કી).
2. Dashboard → `Endpoints` ખોલો અને API કી બનાવો.
3. (વૈકલ્પિક) Dashboard → `Combos` ખોલો અને તમારી ફૉલબૅક ચેઇન સેટ કરો.

### 2) તમારા કોડિંગ ટૂલને નિર્દેશિત કરો

```txt
બેઝ URL: http://localhost:20128/v1
API કી:  [Endpoint પેજ પરથી કૉપિ કરો]
મોડલ:    if/qwen3.8-max-preview (અથવા કોઈપણ પ્રોવાઇડર/મોડલ પ્રીફિક્સ)
```

જો તમારું એડિટર `Authorization: Bearer ...` મોકલી શકતું ન હોય, તો તેના બદલે ટોકનાઇઝ્ડ કમ્પેટિબિલિટી બેઝનો ઉપયોગ કરો:

```txt
બેઝ URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/
મોડલ્સ URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/models
ચૅટ URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/chat/completions
Ollama ટૅગ્સ URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/api/tags
```

Claude Code, Codex CLI, Cursor, Cline, OpenClaw, OpenCode અને OpenAI-સુસંગત SDKs સાથે કાર્ય કરે છે.

#### `setup-*` વડે ઑટો-કૉન્ફિગર કરો

બેઝ URL અને કીને મૅન્યુઅલી પેસ્ટ કરવાને બદલે, OmniRoute ને લાઇવ મોડલ કૅટલૉગમાંથી દરેક ટૂલનું
પોતાનું કૉન્ફિગ લખવા દો. દરેક ટૂલ માટે એક કમાન્ડ:

```bash
omniroute setup-codex        # ~/.codex/<name>.config.toml પ્રોફાઇલ્સ
omniroute setup-claude       # ~/.claude/profiles/<name>/settings.json
omniroute setup-opencode     # ~/.config/opencode/opencode.json (openai-સુસંગત)
omniroute setup-cline        # Cline CLI + VS Code એક્સ્ટેન્શન સેટિંગ્સ
omniroute setup-kilo         # Kilo Code
omniroute setup-continue     # ~/.continue/config.yaml (Continue / cn)
omniroute setup-cursor       # Cursor ના ઇન-ઍપ પગલાં પ્રિન્ટ કરે છે
omniroute setup-roo          # Roo Code ઇમ્પોર્ટ + autoImport પોઇન્ટર
omniroute setup-crush        # ~/.config/crush/crush.json
omniroute setup-goose        # ~/.config/goose/config.yaml
omniroute setup-aider        # ~/.aider.conf.yml
omniroute setup-qwen         # ~/.qwen/settings.json + ~/.qwen/.env
```

સ્થાનિક ટૂલને **રિમોટ** OmniRoute સામે કૉન્ફિગર કરવા માટે દરેક કમાન્ડ `--remote <url> --api-key <key>` સ્વીકારે છે, તેમજ પૂર્વાવલોકન માટે `--dry-run` સ્વીકારે છે. યોગ્ય
env ઇન્જેક્ટ કરીને અને કોઈ કૉન્ફિગ લખ્યા વિના CLI લૉન્ચ કરવા માટે સામાન્ય લૉન્ચર
`omniroute run <target>` (claude, codex, aider, goose, opencode, qwen, gemini) નો ઉપયોગ કરો;
જૂના પ્રતિ-ટૂલ લૉન્ચર્સ `omniroute launch` (Claude Code) અને
`omniroute launch-codex` (Codex) ઉપલબ્ધ રહે છે.

સંપૂર્ણ કોષ્ટક માટે (દરેક કમાન્ડ શું લખે છે, દરેક ફ્લૅગ, સ્થાનિક વિરુદ્ધ રિમોટ, બેઝ-URL
`/v1` પરંપરાઓ), **[CLI ઇન્ટિગ્રેશન્સ](./CLI-INTEGRATIONS.md)** જુઓ.

વિગતવાર પ્રતિ-ટૂલ કૉન્ફિગરેશન (Claude Code, Codex CLI, Cursor, Cline, OpenClaw, Kilo Code, Copilot અને વધુ) માટે, સમર્પિત **[CLI ટૂલ્સ માર્ગદર્શિકા](../reference/CLI-TOOLS.md)** જુઓ.

## પ્રોટોકૉલ સેટઅપ (MCP + A2A)

stdio મોડમાં MCP ટ્રાન્સપોર્ટ શરૂ કરો:


ભલામણ કરેલ વૅલિડેશન પ્રવાહ:

```bash
omniroute_list_combos       # સક્રિય કોમ્બોઝ પરત કરવા જોઈએ

# 3. અથવા સંપૂર્ણ E2E સ્યુટ ચલાવો:
npm run test:protocols:e2e
```

```bash
claude mcp add-server omniroute --type http --url http://localhost:20128/api/mcp/stream
```

```json
  "mcpServers": {
```

**સંપૂર્ણ MCP દસ્તાવેજીકરણ:** [MCP સર્વર README](../../open-sse/mcp-server/README.md) — 110 ટૂલ્સ, IDE કૉન્ફિગ્સ, Python/TS/Go ક્લાયન્ટ્સ.

## ટાઇમઆઉટ રૂપરેખાંકન

### મૂળભૂત ટાઇમઆઉટ્સ

મોટાભાગના ડિપ્લોયમેન્ટ્સ માટે, તમને ફક્ત આ બે વેરિએબલ્સની જરૂર છે:

| વેરિએબલ                  | ડિફૉલ્ટ                                | હેતુ                                                                                                                                                      |
| ------------------------ | -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `REQUEST_TIMEOUT_MS`     | `600000`                               | અપસ્ટ્રીમ પ્રતિસાદ શરૂ થવાના ટાઇમઆઉટ, છુપાયેલા Undici ટાઇમઆઉટ્સ, TLS ફિંગરપ્રિન્ટ વિનંતીઓ અને API બ્રિજ વિનંતી/પ્રોક્સી ટાઇમઆઉટ્સ માટેની સહિયારી આધારરેખા |
| `STREAM_IDLE_TIMEOUT_MS` | `REQUEST_TIMEOUT_MS` વારસામાં મેળવે છે | OmniRoute દ્વારા SSE સ્ટ્રીમ રદ કરવામાં આવે તે પહેલાં સ્ટ્રીમિંગ ચંક્સ વચ્ચેનો મહત્તમ વિરામ                                                               |

પશ્ચાદવર્તી સુસંગતતા જાળવવામાં આવી છે: હાલના `FETCH_TIMEOUT_MS`, `API_BRIDGE_PROXY_TIMEOUT_MS` અને અન્ય પ્રતિ-સ્તર ટાઇમઆઉટ વેરિએબલ્સ હજી પણ કાર્ય કરે છે અને સહિયારી આધારરેખાને ઓવરરાઇડ કરે છે.

### પ્રદાતા-વિશિષ્ટ નોંધો

Claude Code-સુસંગત અપસ્ટ્રીમ્સ (`anthropic-compatible-cc-*`) માટે, OmniRoute ઉકેલાયેલા ફેચ ટાઇમઆઉટ પરથી આઉટબાઉન્ડ `X-Stainless-Timeout` હેડર મેળવે છે, જેથી પ્રદાતા-બાજુના રીડ ટાઇમઆઉટ્સ તમારા env રૂપરેખાંકન સાથે સુમેળમાં રહે.

તૃતીય-પક્ષ Claude Code-સુસંગત રિવર્સ પ્રોક્સીઓ માટે, OmniRoute ડિફૉલ્ટ `anthropic-beta` સેટને સાવચેતીપૂર્ણ રાખે છે અને જ્યારે `Client Cache Control` ને `Auto` પર રાખવામાં આવે છે, ત્યારે માત્ર ક્લાયન્ટ દ્વારા પ્રદાન કરાયેલા `cache_control` માર્કર્સને જ ફોરવર્ડ કરે છે. જ્યારે અપસ્ટ્રીમને ખાસ કરીને રિડેક્ટ કરેલા Claude થિંકિંગ સ્ટ્રીમ્સની જરૂર હોય ત્યારે જ પ્રતિ-કનેક્શન "Enable redact-thinking beta" ટૉગલ સક્ષમ કરો.

### અદ્યતન ટાઇમઆઉટ ઓવરરાઇડ્સ

| વેરિએબલ                                  | ડિફૉલ્ટ                                              | હેતુ                                                                     |
| ---------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------ |
| `FETCH_TIMEOUT_MS`                       | `REQUEST_TIMEOUT_MS` વારસામાં મેળવે છે               | પ્રતિસાદ હેડર્સ આવે ત્યાં સુધી વપરાતો અપસ્ટ્રીમ પ્રતિસાદ-પ્રારંભ ટાઇમઆઉટ |
| `FETCH_HEADERS_TIMEOUT_MS`               | `FETCH_TIMEOUT_MS` વારસામાં મેળવે છે                 | અપસ્ટ્રીમ પ્રતિસાદ હેડર્સ મેળવવા માટેની Undici સમયમર્યાદા                |
| `FETCH_BODY_TIMEOUT_MS`                  | `FETCH_TIMEOUT_MS` વારસામાં મેળવે છે                 | અપસ્ટ્રીમ બોડી ચંક્સ વચ્ચેની Undici સમયમર્યાદા (`0` તેને અક્ષમ કરે છે)   |
| `FETCH_CONNECT_TIMEOUT_MS`               | `30000`                                              | Undici TCP કનેક્ટ ટાઇમઆઉટ                                                |
| `FETCH_KEEPALIVE_TIMEOUT_MS`             | `4000`                                               | Undici નિષ્ક્રિય કીપ-અલાઇવ સોકેટ ટાઇમઆઉટ                                 |
| `TLS_CLIENT_TIMEOUT_MS`                  | `FETCH_TIMEOUT_MS` વારસામાં મેળવે છે                 | `wreq-js` મારફતે કરવામાં આવેલી TLS ફિંગરપ્રિન્ટ વિનંતીઓ માટેનો ટાઇમઆઉટ   |
| `API_BRIDGE_PROXY_TIMEOUT_MS`            | `REQUEST_TIMEOUT_MS` અથવા `600000` વારસામાં મેળવે છે | API પોર્ટથી ડેશબોર્ડ પોર્ટ પર `/v1` પ્રોક્સી ફોરવર્ડિંગ માટેનો ટાઇમઆઉટ   |
| `API_BRIDGE_SERVER_REQUEST_TIMEOUT_MS`   | `max(API_BRIDGE_PROXY_TIMEOUT_MS, 300000)`           | API બ્રિજ સર્વર પર ઇનકમિંગ વિનંતીનો ટાઇમઆઉટ                              |
| `API_BRIDGE_SERVER_HEADERS_TIMEOUT_MS`   | `60000`                                              | API બ્રિજ સર્વર પર ઇનકમિંગ હેડરનો ટાઇમઆઉટ                                |
| `API_BRIDGE_SERVER_KEEPALIVE_TIMEOUT_MS` | `5000`                                               | API બ્રિજ સર્વર પર કીપ-અલાઇવ ટાઇમઆઉટ                                     |
| `API_BRIDGE_SERVER_SOCKET_TIMEOUT_MS`    | `0`                                                  | API બ્રિજ સર્વર પર સોકેટ નિષ્ક્રિયતા ટાઇમઆઉટ (`0` તેને અક્ષમ કરે છે)     |

> **નોંધ:** સ્ટ્રીમિંગ વિનંતીઓ માટે, `FETCH_TIMEOUT_MS` ફક્ત કનેક્શન સેટઅપ / પ્રથમ અપસ્ટ્રીમ પ્રતિસાદની રાહ જોવાને આવરી લે છે. સ્ટ્રીમ સક્રિય થયા પછી, OmniRoute ફક્ત વાસ્તવિક અવરોધ (`STREAM_IDLE_TIMEOUT_MS`) અથવા Undici બોડી નિષ્ક્રિયતા (`FETCH_BODY_TIMEOUT_MS`) પર જ તેને રદ કરશે.

### રિવર્સ પ્રોક્સી સુસંગતતા

જો તમે OmniRoute ને Nginx, Caddy, Cloudflare અથવા અન્ય રિવર્સ પ્રોક્સીની પાછળ ચલાવો છો, તો ખાતરી કરો કે પ્રોક્સી ટાઇમઆઉટ્સ પણ તમારા OmniRoute સ્ટ્રીમ/ફેચ ટાઇમઆઉટ્સ કરતાં વધારે હોય.

## Void Linux (`xbps-src`) ટેમ્પલેટ

Void Linux વપરાશકર્તાઓ `xbps-src`નો ઉપયોગ કરીને મૂળ પૅકેજ બનાવી શકે છે. આ બ્લૉકને `srcpkgs/omniroute/template` તરીકે સાચવો:

```bash
# 'omniroute' માટેની ટેમ્પલેટ ફાઇલ
pkgname=omniroute
version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"
maintainer="zenobit <zenobit@disroot.org>"
license="MIT"
homepage="https://github.com/diegosouzapw/OmniRoute"
distfiles="https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz"
# દરેક રિલીઝ માટે આ રીતે checksum ફરીથી બનાવો:
#   curl -L -o /tmp/omniroute.tar.gz "https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz" && sha256sum /tmp/omniroute.tar.gz
checksum=PLACEHOLDER_REGENERATE_PER_RELEASE
system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	NODE_ENV=development npm ci --ignore-scripts
	npm run build
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	rm -rf .next/standalone/node_modules/@img

	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
		touch "${DESTDIR}/usr/lib/omniroute/${_d}/.keep"
	done

	cat > "${WRKDIR}/omniroute" <<'EOF'
#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"
mkdir -p "${DATA_DIR}"
exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```
