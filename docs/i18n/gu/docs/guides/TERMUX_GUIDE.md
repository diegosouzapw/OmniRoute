OmniRoute, Termux દ્વારા Android પર હેડલેસ સર્વર તરીકે ચાલી શકે છે. Electron ડેસ્કટૉપ ઍપ Termuxમાં સમર્થિત નથી, પરંતુ વેબ ડૅશબોર્ડ અને OpenAI-સુસંગત API સ્થાનિક બ્રાઉઝર અથવા સમાન નેટવર્ક પરનાં અન્ય ઉપકરણોમાંથી કાર્ય કરે છે.

## પૂર્વજરૂરિયાતો

F-Droid અથવા GitHub releasesમાંથી Termux ઇન્સ્ટૉલ કરો, ત્યારબાદ પૅકેજ અપડેટ કરો અને `better-sqlite3` જેવી નેટિવ ડિપેન્ડન્સી માટે જરૂરી બિલ્ડ ટૂલ્સ ઇન્સ્ટૉલ કરો.

```bash
pkg update
pkg upgrade
pkg install nodejs python build-essential git
```

> **Node.js વર્ઝન:** OmniRoute માટે Node `>=22.22.2 <23 || >=24.0.0 <27` જરૂરી છે (`package.json` / `SUPPORTED_NODE_RANGE`માંના `engines` સાથે મેળ ખાય છે). Termuxનું `nodejs-lts` સામાન્ય રીતે Node 20 LTS આપે છે, જે **હવે સમર્થિત નથી** — તેના બદલે `pkg install nodejs` (વર્તમાન) ઇન્સ્ટૉલ કરો અને ખાતરી કરો કે `node --version` 22.x/24.x+ શ્રેણી દર્શાવે છે.

જો નેટિવ પૅકેજ કમ્પાઇલેશન નિષ્ફળ જાય, તો ઉપરનો `pkg install` કમાન્ડ ફરી ચલાવો અને ત્યારબાદ OmniRouteનું ઇન્સ્ટૉલેશન ફરી અજમાવો.

## ઇન્સ્ટૉલેશન

તાજેતરમાં પ્રકાશિત થયેલું પૅકેજ સીધું ચલાવો:

```bash
npx -y omniroute@latest
```

તમે તેને વૈશ્વિક સ્તરે પણ ઇન્સ્ટૉલ કરી શકો છો:

```bash
npm install -g omniroute
omniroute
```

## ચલાવવું

OmniRouteને હેડલેસ સર્વર મોડમાં શરૂ કરો:

```bash
omniroute
```

અથવા:

```bash
npx omniroute
```

ડૅશબોર્ડ અહીં સાંભળે છે:

```text
http://localhost:20128
```

Android બ્રાઉઝરમાં તે URL ખોલો. જો તમે Termuxની અંદર ક્લાયન્ટ ચલાવો છો, તો OpenAI-સુસંગત બેઝ URL તરીકે એ જ હોસ્ટ અને પોર્ટનો ઉપયોગ કરો.

## બૅકગ્રાઉન્ડમાં ચલાવવું

સરળ બૅકગ્રાઉન્ડ પ્રોસેસ માટે:

```bash
nohup omniroute > omniroute.log 2>&1 &
```

તેને બંધ કરવા માટે:

```bash
pkill -f omniroute
```

ઉપકરણ બૂટ થયા પછી આપમેળે શરૂ કરવા માટે, Termux:Boot ઍડ-ઑન ઇન્સ્ટૉલ કરો અને બૂટ સ્ક્રિપ્ટ બનાવો:

```bash
mkdir -p ~/.termux/boot
cat > ~/.termux/boot/omniroute.sh <<'EOF'
#!/data/data/com.termux/files/usr/bin/sh
cd "$HOME"
nohup omniroute > "$HOME/omniroute.log" 2>&1 &
EOF
chmod +x ~/.termux/boot/omniroute.sh
```

Androidનું બૅટરી ઑપ્ટિમાઇઝેશન લાંબા સમય સુધી ચાલતી બૅકગ્રાઉન્ડ પ્રોસેસને બંધ કરી શકે છે. જો સર્વર સતત ઑનલાઇન રહેવાની અપેક્ષા હોય, તો Termux માટે બૅટરી ઑપ્ટિમાઇઝેશન અક્ષમ કરો.

## અન્ય ઉપકરણોમાંથી ઍક્સેસ

WiFi નેટવર્ક પર ફોનનું IP સરનામું શોધો:

```bash
ip addr show wlan0
```

પછી બીજા ઉપકરણમાંથી ડૅશબોર્ડ ખોલો:

```text
http://PHONE_IP:20128
```

ઉદાહરણ તરીકે:

```text
http://192.168.1.50:20128
```

ફોન અને ક્લાયન્ટને સમાન વિશ્વસનીય નેટવર્ક પર રાખો. જો તમે OmniRouteને ફોનની બહારથી ઍક્સેસ કરવા માટે ખુલ્લું કરો, તો API કી અને ડૅશબોર્ડ પ્રમાણીકરણ સક્ષમ કરો.

## ડેટા ડિરેક્ટરી

ડિફૉલ્ટ રૂપે OmniRoute, Linux પર ઉપયોગમાં લેવાતી સમાન સર્વર-સાઇડ ડેટા પાથની વર્તણૂકને અનુસરીને, Termux હોમ ડિરેક્ટરી હેઠળ ડેટા સંગ્રહિત કરે છે. ડેટાબેઝને કોઈ સ્પષ્ટ સ્થાન પર રાખવા માટે:

```bash
export DATA_DIR="$HOME/.omniroute"
omniroute
```

## મર્યાદાઓ

- Electron, Termuxમાં ચાલતું નથી.
- કોઈ સિસ્ટમ ટ્રે અથવા ડેસ્કટૉપ એકીકરણ નથી.
- આ સેટઅપ માત્ર સર્વર માટે છે: બ્રાઉઝર ડૅશબોર્ડનો ઉપયોગ કરો.
- નેટિવ ડિપેન્ડન્સીને સ્થાનિક કમ્પાઇલેશનની જરૂર પડી શકે છે.
- ઓછી મેમરી ધરાવતાં Android ઉપકરણોમાં ઓછા સમકાલીન રિક્વેસ્ટની જરૂર પડી શકે છે.
- MITM/સિસ્ટમ સર્ટિફિકેટ સુવિધાઓ માટે Termuxની બહાર Android-સ્તરના ટ્રસ્ટ સ્ટોર સંબંધિત કાર્યની જરૂર પડી શકે છે.

## સમસ્યાનિવારણ

### અસમર્થિત પ્લૅટફૉર્મ: android (દરેક રિક્વેસ્ટ HTTP 500 આપે છે)

**લક્ષણ:** `omniroute` / `omniroute serve`, `✔ OmniRoute is running!` પ્રિન્ટ કરે છે, પરંતુ દરેક ડૅશબોર્ડ અથવા API રિક્વેસ્ટ સાદો `500 Internal Server Error` આપે છે. `~/.omniroute/logs/application/app.log` ખાલી રહે છે, `APP_LOG_LEVEL=debug` કંઈ ઉપયોગી પ્રિન્ટ કરતું નથી અને રિસ્પૉન્સ બૉડી કોઈ JSON વિગત વિના સાદું ટેક્સ્ટ (`Internal Server Error`) હોય છે.

**કારણ:** કેટલાક Termux/Node બિલ્ડ `process.platform === "android"` રિપોર્ટ કરે છે. Next.jsનું `getCacheDirectory()` તે પ્લૅટફૉર્મને સંભાળતું નથી: તેના માટે `~/.cache` (અથવા સામાન્ય tmp ડિરેક્ટરી) _પહેલેથી_ અસ્તિત્વમાં હોવી જરૂરી છે, નહીં તો ઇન્સ્ટ્રુમેન્ટેશન હૂક લોડ કરતી વખતે તે નીચેની ભૂલ સાથે નિષ્ફળ જાય છે:

```text
Error: An error occurred while loading instrumentation hook: Unsupported platform: android
```

હૂક ક્યારેય લોડ થતું ન હોવાથી, લૉગિંગ ક્યારેય શરૂ થતું નથી — તેથી 500નું નિદાન કરવું સંપૂર્ણપણે અશક્ય લાગે છે. Next.js શરૂ થાય તે પહેલાં OmniRoute, CLI એન્ટ્રીપૉઇન્ટમાં `~/.cache` બનાવે છે (અને `XDG_CACHE_HOME` સેટ ન હોય ત્યારે તેને સેટ કરે છે), જેથી આ તપાસ Android/Termux પર સફળ થાય.

**સમર્થિત ઉકેલ (પૅકેજમાં પૅચ કર્યા વિના):**

```bash
mkdir -p ~/.cache
omniroute serve
```

વર્તમાન OmniRoute બિલ્ડમાં CLI આ પ્રક્રિયા Android/Termux પર આપમેળે કરે છે — નવા `npx -y omniroute@latest` / વૈશ્વિક ઇન્સ્ટૉલેશન માટે આ મૅન્યુઅલ પગલું જરૂરી ન હોવું જોઈએ. અપગ્રેડ કર્યા પછી પણ જો તમને ભૂલ દેખાય, તો ઉપર દર્શાવ્યા મુજબ એક વાર `~/.cache` બનાવો અને ફરી શરૂ કરો.

`process.platform = "linux"`ને ફરજિયાત કરવા માટે `dist/server.js`ને પૅચ **કરશો નહીં**. આવા પૅકેજ પૅચ દરેક પુનઃઇન્સ્ટૉલેશન/અપગ્રેડ વખતે ઓવરરાઇટ થઈ જાય છે અને કૅશ ડિરેક્ટરી અસ્તિત્વમાં આવ્યા પછી તે બિનજરૂરી છે.

### better-sqlite3 બિલ્ડ ભૂલો

Termux બિલ્ડ ટૂલચેઇન ઇન્સ્ટૉલ કરો:

```bash
pkg install nodejs python build-essential
```

પછી ફરી ચલાવો:

```bash
npx -y omniroute@latest
```

### પોર્ટ પહેલેથી ઉપયોગમાં છે

ડિફૉલ્ટ પોર્ટ પર શું સાંભળી રહ્યું છે તે તપાસો:

```bash
ss -ltnp | grep 20128
```

જૂની પ્રોસેસ બંધ કરો:

```bash
pkill -f omniroute
```

### અન્ય ઉપકરણમાંથી ડૅશબોર્ડ સુધી પહોંચી શકાતું નથી

બંને ઉપકરણો સમાન WiFi નેટવર્ક પર છે તેની ખાતરી કરો, પછી Termuxમાંથી પરીક્ષણ કરો:

```bash
curl http://localhost:20128
```

જો સ્થાનિક ઍક્સેસ કાર્ય કરે છે પરંતુ LAN ઍક્સેસ કાર્ય કરતું નથી, તો Android હૉટસ્પૉટ/WiFi આઇસોલેશન અને ફોન પરની કોઈપણ ફાયરવૉલ અથવા VPN પ્રોફાઇલ તપાસો.
