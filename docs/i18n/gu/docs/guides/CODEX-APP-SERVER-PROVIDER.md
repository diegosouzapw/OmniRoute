OmniRoute OpenAI Codexનો ઉપયોગ કરવાની **બે** રીતો પ્રદાન કરે છે:

| પ્રદાતા                | તે OpenAI સાથે કેવી રીતે સંચાર કરે છે                                                                                                                                                                 | ઉપયોગ સંબંધિત ચેતવણી                                     |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| **`codex`**            | તમારા ChatGPT/OpenAI OAuth ટોકનને સીધું Responses API પર ફરીથી મોકલે છે                                                                                                                               | **હા** — અધિકૃત સત્ર proxy/router ઉપયોગ માટે અધિકૃત નથી  |
| **`codex-app-server`** | JSON-RPC/WebSocket મારફતે **Codex CLIના પોતાના `codex app-server`**ને ચલાવે છે; CLI તેના OAuth (`~/.codex/auth.json`)ની માલિકી ધરાવે છે અને ઇન્ટરેક્ટિવ `codex` સત્રની જેમ જ તેને જાતે રિફ્રેશ કરે છે | **ના** — OmniRoute ક્યારેય API પર ટોકન ફરીથી મોકલતું નથી |

કારણ કે `codex-app-server` ક્યારેય ટોકન ફરીથી મોકલતું નથી, તેથી તેના પર
સત્ર-રિપ્લે ઉપયોગ સંબંધિત ચેતવણી લાગુ પડતી નથી. જોકે, તેના માટે **રૂપરેખાંકિત
app-server URL પર પહોંચી શકાય તેવી Codex CLI** જરૂરી છે અને તે CLIમાં
**સાઇન ઇન કરેલું** હોવું આવશ્યક છે.

## 1. આર્કિટેક્ચર

```
┌─ OmniRoute એપ ──────────────────┐        ┌─ codex-app-server સાઇડકાર ─────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ ક્ષમતા ટોકન)                 │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  OpenAI OAuthનું સ્વ-વ્યવસ્થાપન     │
└──────────────────────────────────┘        │  (~/.codex/auth.json, સ્વતઃ-રિફ્રેશ) │
        │ શેર કરે છે (compose volumes)       └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → WS ક્ષમતા ટોકન (બંને તેને માઉન્ટ કરે છે)
  codex-appserver-home    → ~/.codex (ડૅશબોર્ડ દ્વારા લખાતી auth.json,
                             સાઇડકારના codex app-server દ્વારા વાંચવામાં આવે છે)
```

- સાઇડકાર ક્ષમતા ટોકન પાછળ ફક્ત આંતરિક compose નેટવર્ક
  (`ws://codex-app-server:1456`) પર જ સાંભળે છે. તેને હોસ્ટ અથવા ઇન્ટરનેટ પર
  **ક્યારેય** પ્રકાશિત કરવામાં આવતું નથી.
- Codex CLIને `omniroute:base`માં જ સમાવિષ્ટ કરવામાં આવી છે, તેથી સાઇડકાર
  ચલાવતી વખતે હોસ્ટ અથવા વપરાશકર્તાના મશીન પર codex ઇન્સ્ટોલ કરવાની જરૂર નથી.

## 2. તેને શરૂ કરો

```bash
# codex app-server સાઇડકાર પ્રોફાઇલ સાથે સ્ટૅક શરૂ કરો:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

સાઇડકાર પ્રથમ બૂટ વખતે પોતાનું WS ક્ષમતા ટોકન બનાવે છે (શેર કરેલા
`codex-appserver-token` વોલ્યુમમાં) અને એપ એ જ ટોકનને
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE` મારફતે વાંચે છે. મેન્યુઅલ રીતે ટોકન
જોડવાની જરૂર નથી.

## 3. કનેક્ટ કરો + સાઇન ઇન કરો

1. ડૅશબોર્ડમાં **OpenAI Codex (App-Server)** માટે કનેક્શન ઉમેરો. કોઈ API
   કી અથવા ટોકનની જરૂર નથી (તે no-auth પ્રદાતા છે — પ્રમાણીકરણ સાઇડકાર
   સંભાળે છે).
2. જો સાઇડકારની Codex CLIમાં **હજુ સુધી સાઇન ઇન કરેલું ન હોય**, તો કનેક્શન
   હેલ્થ ચેક _"ચાલી રહ્યું છે પરંતુ સાઇન ઇન કરેલું નથી"_ દર્શાવે છે (લાલ
   પ્રમાણીકરણ ભૂલ નહીં). **ChatGPT વડે સાઇન ઇન કરો**નો ઉપયોગ કરો: આ તમારા
   બ્રાઉઝરમાં પ્રમાણભૂત Codex device-OAuth ચલાવે છે અને પછી **Apply auth**
   મારફતે શેર કરેલા વોલ્યુમમાં `~/.codex/auth.json` લખે છે (એક જ લૉગિન
   `codex` અને `codex-app-server` બંને પ્રદાતાઓ માટે કામ કરે છે).
3. સાઇન ઇન થયા પછી, હેલ્થ ચેક લીલો થાય છે (તે `/readyz` **અને**
   `account/read` બંનેની ચકાસણી કરે છે — એટલે કે, ચાલુ _અને_ પ્રમાણિત) અને
   કાર્ય કરવાનું શરૂ કરે છે.

ડૅશબોર્ડ હાલની સ્વસ્થ `~/.codex/auth.json`ને ક્યારેય ઓવરરાઇટ કરતું નથી — તે
ફક્ત ફાઇલ ગેરહાજર હોય અથવા તેનું ટોકન જૂનું થઈ ગયું હોય ત્યારે જ લખે છે
(હંમેશાં બૅકઅપ લેવામાં આવે છે).

## 4. ડિપ્લોયમેન્ટ પરિસ્થિતિઓ

- **પહેલેથી પ્રમાણિત Codex CLI ધરાવતા ઑપરેટર** — તમારા હોસ્ટના
  `~/.codex`ને સાઇડકાર (`codex-appserver-home`)માં માઉન્ટ કરો અને સાઇન-ઇનનું
  પગલું છોડી દો.
- **જાહેર વપરાશકર્તા, સ્થાનિક રીતે codex ઇન્સ્ટોલ કરેલું નથી** — તે
  અપ્રસ્તુત છે: સાઇડકારમાં CLI ઉપલબ્ધ છે. વપરાશકર્તા ફક્ત ડૅશબોર્ડ મારફતે
  પ્રમાણીકરણ કરે છે.
- **બેર-મેટલ OmniRoute (સાઇડકાર વિના, હોસ્ટ codex)** — તમારા પોતાના
  `codex app-server` તરફ `OMNIROUTE_CODEX_APPSERVER_WS`ને નિર્દેશિત કરો અને
  ખાતરી કરો કે હોસ્ટ codexમાં સાઇન ઇન કરેલું છે; જો બાઇનરી ગેરહાજર હોય, તો
  "codex ઇન્સ્ટોલ કરેલું નથી" સંકેત દેખાય છે.

## 5. રહેણાંક / UDP ઇગ્રેસ (ઑપરેટર માટે વધારાનું, સાથે મોકલાતું નથી)

ઉપરોક્ત સામાન્ય સાઇડકાર કન્ટેનરના સામાન્ય નેટવર્ક મારફતે ઇગ્રેસ કરે છે. જે
ઑપરેટરને Codex ટ્રાફિક **રહેણાંક એક્ઝિટ** મારફતે ઇગ્રેસ કરાવવાની જરૂર હોય
(દા.ત. TCP + UDP/QUIC વહન કરતો TUN tailscale સાઇડકાર), તે તેને અલગ compose
ઓવરરાઇડ તરીકે ચલાવે છે; તેને ઇરાદાપૂર્વક મોકલવામાં આવેલી
`codex-app-server` પ્રોફાઇલના ભાગ તરીકે સામેલ કરવામાં આવ્યું નથી. તે સેટઅપ
માટે આંતરિક ઑપરેશન્સ રનબુક જુઓ.
