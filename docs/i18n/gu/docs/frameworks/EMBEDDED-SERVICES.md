એમ્બેડેડ સેવાઓ સ્થાનિક રીતે ઇન્સ્ટોલ કરાયેલા પ્રોસેસ સાઇડકાર ટૂલ્સ છે, જેને OmniRoute ઇન્સ્ટોલ કરે છે, તેનું નિરીક્ષણ કરે છે અને
પ્રથમ-શ્રેણીના રાઉટિંગ લક્ષ્યો તરીકે ઉપલબ્ધ કરાવે છે. બાહ્ય પ્રદાતાઓથી વિપરીત (જેમનો સંપર્ક ઇન્ટરનેટ મારફતે
API કીઓનો ઉપયોગ કરીને કરવામાં આવે છે), એમ્બેડેડ સેવાઓ OmniRouteના જ મશીન પર ચાલે છે અને લૂપબૅક મારફતે સંચાર કરે છે.

## 1. સંક્ષિપ્ત પરિચય

### એમ્બેડેડ સેવાઓ શા માટે?

છ સેવાઓ એમ્બેડ કરવામાં આવી છે:

| સેવા            | npm પૅકેજ                        | ડિફૉલ્ટ પોર્ટ | હેતુ                                                                                                                                                                                                   |
| --------------- | -------------------------------- | :-----------: | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **9Router**     | `9router`                        |     20130     | AI રાઉટર, જેનો OmniRoute ઉપ-પ્રદાતા તરીકે ઉપયોગ કરી શકે છે. મોડેલો `9router/{sub}/{model}` તરીકે ઉપલબ્ધ કરાવવામાં આવે છે                                                                               |
| **CLIProxyAPI** | GitHub રિલીઝ બાઇનરી (`cliproxy`) |     8317      | Anthropic CLI પ્રમાણીકરણ પ્રવાહો માટે સ્થાનિક પ્રૉક્સી ઍડેપ્ટર. OAuth ટોકન સમાપ્ત થાય ત્યારે ફૉલબૅક રાઉટિંગ પૂરું પાડે છે                                                                              |
| **Mux**         | `mux` (હેડલેસ `mux server`)      |     8322      | સ્થાનિક એજન્ટ-ઓર્કેસ્ટ્રેશન ડીમન (coder/mux). માત્ર લાઇફસાઇકલ-મેનેજ્ડ — રાઉટિંગ લક્ષ્ય નથી (કોઈ LLM પ્રૉક્સીઇંગ નહીં).                                                                                 |
| **Bifrost**     | `@maximhq/bifrost`               |     8080      | Go AI-ગેટવે રિલે બૅકએન્ડ. ચાલુ હોય ત્યારે, રિલે રૂટ (`/v1/relay/`) દ્વારા આપમેળે પસંદ કરવામાં આવે છે                                                                                                   |
| **Dario**       | `@askalf/dario`                  |     3456      | Claude-સબ્સ્ક્રિપ્શન પ્રૉક્સી — Claude-Code-સ્વરૂપના ટ્રાફિક માટે CLIProxyAPIનો વિકલ્પ/ફેઇલઓવર; ઇન્જેક્ટ કરેલી કી `DARIO_ADMIN_TOKEN` બને છે, જે તેના `/admin/*` OAuth કંટ્રોલ પ્લેનને સુરક્ષિત કરે છે |
| **open-wa**     | `@open-wa/wa-automate`           |     8323      | WhatsApp Web ઑટોમેશન (Puppeteer મારફતે હેડલેસ Chromium). માત્ર લાઇફસાઇકલ-મેનેજ્ડ — રાઉટિંગ લક્ષ્ય નથી.                                                                                                 |

તમામ છ સેવાઓ સમાન સુપરવાઇઝરી મોડલનું પાલન કરે છે:

- OmniRoute તેમને `DATA_DIR/services/{name}/` હેઠળ ઇન્સ્ટૉલ કરે છે (OmniRouteના પોતાના `package.json`થી અલગ)
- OmniRoute તેમને ચાઇલ્ડ પ્રોસેસ તરીકે શરૂ કરે છે અને મોનિટર કરે છે
- OmniRoute ચાઇલ્ડના એન્વાયર્નમેન્ટમાં અસ્થાયી API કી ઇન્જેક્ટ કરે છે અને ડાઉનટાઇમ વિના તેને રોટેટ કરે છે (જ્યાં લાગુ પડે ત્યાં)
- તમામ મેનેજમેન્ટ રૂટ્સ (`/api/services/*`) **LOCAL_ONLY** છે — ફક્ત લૂપબૅકથી ઍક્સેસ કરી શકાય છે (કડક નિયમ #17)

### મુખ્ય નિર્ણયો (ડિઝાઇન યોજનામાંથી)

| નિર્ણય                                  | મૂલ્ય                                                                                           |
| --------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 9Routerના નેટિવ UI માટે ડૅશબોર્ડ ઍક્સેસ | `/dashboard/providers/services/9router/embed/*` પર રિવર્સ પ્રૉક્સી                              |
| ઇન્સ્ટૉલેશન પદ્ધતિ                      | `execFile` મારફતે `npm install {package}` (કોઈ શેલ ઇન્ટરપોલેશન નહીં)                            |
| વપરાશ મોડ                               | રાઉટિંગ એન્જિનમાં `9router/{sub}/{model}` તરીકે નોંધાયેલ પ્રદાતા                                |
| API કી મેનેજમેન્ટ                       | OmniRoute જનરેટ કરે છે, ઍટ-રેસ્ટ એન્ક્રિપ્ટ કરે છે (AES-256-GCM) અને env મારફતે ઇન્જેક્ટ કરે છે |
| ડૅશબોર્ડ સ્થાન                          | `/dashboard/providers/services` (ત્રણ ટૅબ)                                                      |
| ઑટો-સ્ટાર્ટ                             | સેવા દીઠ ટૉગલ, ડિફૉલ્ટ રૂપે બંધ                                                                 |

```
│                                                                    │

│  bootstrap.ts       પ્રોસેસ શરૂ થતાં તમામ SERVICES[] બુટસ્ટ્રૅપ કરે│

│                      (ઇન્સ્ટૉલર ઍડૅપ્ટર્સ)                        │
└──────────────────────┬─────────────────────────────────────────────┘
                       │ OpenAI-સુસંગત HTTP (લૂપબૅક)
┌──────────────────────▼─────────────────────────────────────────────┐
│  સ્તર 4 — પ્રદાતા / રાઉટિંગ                                        │

│                                                                    │
│  Mux માત્ર લાઇફસાઇકલ-વ્યવસ્થાપિત છે (સ્તરો 1-3) — તે એજન્ટ-       │

│  executor/provider એન્ટ્રી નથી અને તે ક્યારેય રાઉટિંગ લક્ષ્ય નથી. │
```

## 3. લાઇફસાઇકલ સ્ટેટ મશીન

```
                    install()
  ┌─────────────┐ ──────────► ┌─────────────┐
  │ not_installed│             │   stopped   │◄──────────────────┐
  └─────────────┘             └──────┬──────┘                   │
                                     │ start()                   │
                                     ▼                           │ stop()
                               ┌──────────┐                      │
                               │ starting │                      │
                               └────┬─────┘                     │
              હેલ્થ પ્રોબ સફળ      │         ક્રેશ / SIGTERM    │
                               ┌────▼─────┐  (5sમાં એક્ઝિટ)     │
                               │ running  │──── ક્રેશ ──────────►┤
                               └────┬─────┘                   ┌─▼────┐
                             stop() │                          │error │
                                    ▼                          └──────┘
                               ┌──────────┐
                               │ stopping │
                               └──────────┘
```

સ્ટેટ્સ `version_manager` DB ટેબલમાં (`status` કૉલમ) સંગ્રહિત થાય છે અને
`ServiceSupervisor`ની ઇન-મેમરી સ્ટેટમાં પ્રતિબિંબિત થાય છે. ચાલી રહેલી પ્રોસેસ માટે
ઇન-મેમરી સ્ટેટ અધિકૃત છે; બૂટ સમયે DB સ્ટેટ ટકાઉ ફૉલબૅક છે.

### સ્ટેટ ટ્રાન્ઝિશન્સ

| માંથી           | ઇવેન્ટ                              | તરફ                    |
| --------------- | ----------------------------------- | ---------------------- |
| `not_installed` | `install()` સફળ થાય                 | `stopped`              |
| `stopped`       | `start()` કૉલ થાય                   | `starting`             |
| `starting`      | હેલ્થ પ્રોબ 200 પરત કરે             | `running`              |
| `starting`      | હેલ્ધી બનતા પહેલાં પ્રોસેસ બંધ થાય  | `error`                |
| `running`       | `stop()` કૉલ થાય                    | `stopping` → `stopped` |
| `running`       | પ્રોસેસ અણધારી રીતે બંધ થાય (< 5 s) | `error` (ઝડપી ક્રેશ)   |
| `running`       | પ્રોસેસ અણધારી રીતે બંધ થાય (> 5 s) | `error`                |
| `error`         | `start()` કૉલ થાય                   | `starting`             |
| કોઈપણ           | `stopping` દરમિયાન `stop()`         | કોઈ ક્રિયા નહીં        |

### ઑપરેશન લૉક

`ServiceSupervisor` async ઑપરેશન લૉક (`withLock()`) મારફતે લાઇફસાઇકલ ઑપરેશન્સને
ક્રમબદ્ધ કરે છે. એક જ સુપરવાઇઝર પર એકસાથે થતા `start()` કૉલ્સનું પરિણામ ચોક્કસપણે
એક spawnમાં આવે છે; બીજો કૉલર રાહ જુએ છે અને હાલનું સ્ટેટસ પરત કરે છે. ઉદાહરણ તરીકે,
auto-start અને UI બટન એકસાથે ટ્રિગર થાય ત્યારે આ રેસ કન્ડિશન્સને અટકાવે છે.

## 4. API સંદર્ભ

`/api/services/` હેઠળના તમામ રૂટ્સ **LOCAL_ONLY** છે (માત્ર લૂપબૅક, કડક નિયમ #17).
ઑથ ટોકન ગમે તે હોય, નોન-લૂપબૅક વિનંતીઓને `403 LOCAL_ONLY` પ્રતિસાદ મળે છે.

### 4.1 9Router એન્ડપોઇન્ટ્સ (11 રૂટ્સ)

#### `POST /api/services/9router/install`

npmમાંથી 9Router ઇન્સ્ટૉલ કરે છે. તેના પોતાના `package.json` અને
`node_modules/` સાથે `DATA_DIR/services/9router/` બનાવે છે. OmniRouteની પોતાની ડિપેન્ડન્સીઓ સાથે સંઘર્ષ થતો નથી.

**વિનંતી બોડી** (બધા વૈકલ્પિક):

```json
{ "version": "latest" }
```

| ફીલ્ડ     | પ્રકાર   | ડિફૉલ્ટ    | વર્ણન                                           |
| --------- | -------- | ---------- | ----------------------------------------------- |
| `version` | `string` | `"latest"` | ઇન્સ્ટૉલ કરવા માટેનું npm વર્ઝન ટૅગ અથવા semver |

**પ્રતિસાદો:**

| સ્થિતિ | વર્ણન                                                                    |
| ------ | ------------------------------------------------------------------------ |
| `200`  | `{ ok: true, installedVersion: "x.y.z", path: "..." }`                   |
| `400`  | અમાન્ય વિનંતી બોડી (Zod માન્યતા નિષ્ફળતા)                                |
| `409`  | ઇન્સ્ટૉલેશન પહેલેથી ચાલુ છે (લૉક મેળવાયેલો છે)                           |
| `500`  | npm ઇન્સ્ટૉલ નિષ્ફળ થયું — સરળતાથી સમજી શકાય તેવી ભૂલ માટે `message` જુઓ |

**નોંધો:** `execFile('npm', [...])`નો ઉપયોગ કરે છે — કોઈ શેલ નહીં, કોઈ ઇન્ટરપોલેશન નહીં (કડક નિયમ #13).
EACCES ભૂલો સરળતાથી સમજી શકાય તેવા સંદેશાઓ તરીકે દર્શાવવામાં આવે છે.

---

#### `POST /api/services/9router/start`

9Router શરૂ કરે છે. જો સુપરવાઇઝર પહેલેથી નોંધાયેલો ન હોય, તો તેને નોંધે છે અને પછી
`supervisor.start()`ને કૉલ કરે છે. પહેલેથી ચાલી રહ્યું હોય ત્યારે આ ક્રિયા આઇડેમ્પોટન્ટ છે.

**વિનંતી બોડી:** કોઈ નહીં

**પ્રતિસાદો:**

| સ્થિતિ | વર્ણન                                                   |
| ------ | ------------------------------------------------------- |
| `200`  | `ServiceStatus` ઑબ્જેક્ટ (નીચેની સ્કીમા જુઓ)            |
| `409`  | 9Router ઇન્સ્ટૉલ થયેલું નથી (`status: "not_installed"`) |
| `503`  | શરૂ કરવું નિષ્ફળ થયું (પ્રોસેસ ભૂલ — `lastError` જુઓ)   |

**ServiceStatus સ્કીમા:**

```json
{
  "tool": "9router",
  "state": "running",
  "pid": 12345,
  "port": 20130,
  "health": "healthy",
  "startedAt": "2026-05-25T10:00:00.000Z",
  "lastError": null
}
```

#### `POST /api/services/9router/stop`

9Routerને સુવ્યવસ્થિત રીતે બંધ કરે છે. SIGTERM મોકલે છે, 15 s રાહ જુએ છે અને જો હજુ પણ ચાલુ હોય તો SIGKILL મોકલે છે.
પહેલેથી બંધ હોય ત્યારે આ ક્રિયા આઇડેમ્પોટન્ટ છે.

**વિનંતી બોડી:** કોઈ નહીં

**પ્રતિસાદો:**

| સ્થિતિ | વર્ણન                                |
| ------ | ------------------------------------ |
| `200`  | `ServiceStatus` (state: "stopped")   |
| `503`  | બંધ કરવું અનપેક્ષિત રીતે નિષ્ફળ થયું |

**વિનંતી બોડી:** કોઈ નહીં

**પ્રતિસાદો:** `start` જેવા જ (અંતિમ `ServiceStatus` પરત કરે છે).

#### `POST /api/services/9router/update`

કરવામાં આવે છે, npm ઇન્સ્ટૉલ ચલાવવામાં આવે છે (નવું વર્ઝન એ જ સ્થાને ઇન્સ્ટૉલ કરીને), અને પછી

**વિનંતી બોડી** (બધા વૈકલ્પિક):

```json
{ "version": "latest" }
```

**પ્રતિસાદો:**

| સ્થિતિ | વર્ણન                                                           |
| ------ | --------------------------------------------------------------- |
| `200`  | `{ ok: true, previousVersion: "...", installedVersion: "..." }` |
| `400`  | અમાન્ય બોડી                                                     |
| `500`  | npm અપડેટ નિષ્ફળ થયું                                           |

#### `POST /api/services/9router/rotate-key`

9Router માટે નવી API કી જનરેટ કરે છે, તેને સંગ્રહિત સ્થિતિમાં એન્ક્રિપ્ટ કરે છે અને સર્વિસ
ચાલી રહી હોય તો તેને ફરી શરૂ કરે છે, જેથી તે પોતાના એન્વાયર્નમેન્ટમાંથી નવી કી મેળવી શકે. જૂની કી

**વિનંતી બોડી:** કોઈ નહીં

**પ્રતિસાદો:**

| સ્થિતિ | વર્ણન                                      |
| ------ | ------------------------------------------ |
| `200`  | `{ keyRotated: true, restarted: boolean }` |
| `500`  | કી રોટેશન નિષ્ફળ થયું                      |

**સુરક્ષા:** નવી કી પ્રતિસાદમાં ક્યારેય પરત કરવામાં આવતી નથી (ક્રેડેન્શિયલ લીક થતું નથી).

#### `GET /api/services/9router/logs`

**ક્વેરી પેરામીટર્સ:**

| પેરામીટર | પ્રકાર    | ડિફૉલ્ટ  | વર્ણન                                                              |
| -------- | --------- | -------- | ------------------------------------------------------------------ |
| `tail`   | `integer` | 200      | પહેલાં મોકલવાની ઐતિહાસિક લાઇનોની સંખ્યા (મહત્તમ 1000)              |

**SSE ઇવેન્ટ્સ:**

| ઇવેન્ટ      | ડેટા        | વર્ણન                   |
| ----------- | ----------- | ----------------------- |
| `snapshot`  | `LogLine[]` | પ્રારંભિક ઐતિહાસિક ટેઇલ |
| `log`       | `LogLine`   | લાઇવ લૉગ લાઇન           |
| `heartbeat` | `{}`        | દર 15 sએ કીપ-અલાઇવ      |

**LogLine સ્કીમા:**

```json
{
```

**API કી:** `WA_KEY` તરીકે ઇન્જેક્ટ કરવામાં આવે છે — open-waનું સામાન્ય `WA_*`-પ્રીફિક્સ ધરાવતું env
ઓવરરાઇડ તેને `--key`/`-k` CLI વિકલ્પ પર મેપ કરે છે
(`dist/cli/setup.js::envArgs()`, ઇન્સ્ટોલ કરેલા 4.76.0
પૅકેજ સામે ચકાસેલું). `generateServiceApiKey()` દ્વારા જનરેટ થાય ત્યારે `ow_` પ્રીફિક્સ ઉમેરાય છે. open-wa
કી ને `key`/`api_key` HTTP હેડરમાંથી પાછી વાંચે છે (`Authorization:
Bearer`માંથી નહીં); `/api-docs*`ને ચકાસણીમાંથી સ્પષ્ટપણે મુક્ત રાખવામાં આવ્યું છે
(`dist/cli/server.js`માં `setupAuthenticationLayer`), તેથી હેલ્થ પ્રોબને
કોઈ auth હેડરની જરૂર નથી.

**પેરિંગ:** open-wa બિનસત્તાવાર છે અને WhatsApp સાથે સંકળાયેલું નથી —
કનેક્ટ કરેલા નંબર પર WhatsAppની પોતાની ઑટોમેશન શોધ પ્રણાલીને કારણે પ્રતિબંધનું જોખમ રહે છે.
પ્રથમ વખત શરૂ કરતી વખતે, પેરિંગ QR કોડ stdout પર પ્રિન્ટ થાય છે અને
હાલની લૉગ્સ પેનલ/SSE સ્ટ્રીમ દ્વારા દર્શાવવામાં આવે છે — આ ઇન્ટિગ્રેશનમાં હજુ
કોઈ સમર્પિત QR-ઇમેજ એન્ડપોઇન્ટ નથી.

### 4.7 રિવર્સ પ્રૉક્સી (9Router ડૅશબોર્ડ એમ્બેડ)

ડૅશબોર્ડ આંતરિક રિવર્સ
પ્રૉક્સી મારફતે 9Router વેબ UIને iframeની અંદર એમ્બેડ કરે છે:

```
GET|POST|... /dashboard/providers/services/9router/embed/[...path]
```

આ પ્રૉક્સી:

- વિનંતીને `http://127.0.0.1:{port}/{path}` પર ફૉર્વર્ડ કરે છે (ફક્ત લૂપબૅક)
- ઇનકમિંગ `cookie` અને `authorization` હેડરો દૂર કરે છે (OmniRoute સેશનનું કોઈ લીકેજ નહીં)
- 9Router પ્રમાણીકરણ માટે `Authorization: Bearer {apiKey}` ઇન્જેક્ટ કરે છે
- પ્રતિસાદમાંથી `set-cookie`, `content-security-policy`, `x-frame-options`, `cross-origin-*` દૂર કરે છે
- `<base href>` ઇન્જેક્ટ કરવા અને ઍબ્સોલ્યુટ પાથને સામાન્યકૃત કરવા માટે HTML પ્રતિસાદો ફરી લખે છે (`/foo` → `/dashboard/.../embed/foo`)

એમ્બેડ કરેલા ડૅશબોર્ડ માટેના WebSocket અપગ્રેડને
સમર્પિત પોર્ટ પરના સહાયક સર્વર દ્વારા સંભાળવામાં આવે છે (`src/lib/services/embedWsProxy.ts` જુઓ).

**સુરક્ષા:** એમ્બેડ પ્રૉક્સી રૂટ્સને `LOCAL_ONLY_API_PREFIXES` હેઠળ વર્ગીકૃત કરવામાં આવ્યા છે
અને તેમને ફક્ત લૂપબૅકથી જ ઍક્સેસ કરી શકાય છે. Cloudflare/Ngrok ટનલ મારફતે
JWT મેળવનાર હુમલાખોર એમ્બેડ કરેલી સેવાઓમાં પ્રૉક્સી કરી શકતો નથી.

## 5. સુરક્ષા

### LOCAL_ONLY અમલીકરણ (કડક નિયમ #17)

`/api/services/` અને `/dashboard/providers/services/*/embed/` હેઠળના તમામ રૂટને
`src/server/authz/routeGuard.ts` માં LOCAL_ONLY તરીકે વર્ગીકૃત કરવામાં આવ્યા છે. કોઈપણ પ્રમાણીકરણ શાખા પહેલાં
લૂપબૅક તપાસ બિનશરતી રીતે ચાલે છે:

```
વિનંતી આવે છે
  → isLocalOnlyPath(path)?
      → નોન-લૂપબૅક → 403 LOCAL_ONLY (હંમેશાં, પ્રમાણીકરણ તપાસ પહેલાં)
      → લૂપબૅક     → સામાન્ય પ્રમાણીકરણ તરફ આગળ વધો
```

આ લીક થયેલા JWTને (દા.ત., ટનલ મારફતે) `npm install` અથવા
પ્રક્રિયા શરૂ કરવાનું ટ્રિગર કરવાથી અટકાવે છે. સંપૂર્ણ સ્તર
મેટ્રિક્સ માટે `docs/security/ROUTE_GUARD_TIERS.md` જુઓ.

### API કી ઇન્જેક્શન

9Router અને Muxને તેમના પોતાના HTTP એન્ડપૉઇન્ટ માટે API કી/બેરર ટોકનની જરૂર પડે છે.
OmniRoute:

1. સેવા-વિશિષ્ટ ઉપસર્ગ સાથે `crypto.randomBytes(32).toString("base64url")` દ્વારા કી
   જનરેટ કરે છે (9Router માટે `nr_`, Mux માટે `mx_`).
2. AES-256-GCMનો ઉપયોગ કરીને તેને નિષ્ક્રિય અવસ્થામાં એન્ક્રિપ્ટ કરે છે (પ્રદાતા ક્રેડેન્શિયલ્સ માટે વપરાતું એ જ સાઇફર).
3. સ્પૉન સમયે તેને ડિક્રિપ્ટ કરીને પર્યાવરણ ચલ તરીકે ઇન્જેક્ટ કરે છે —
   9Router માટે `NINEROUTER_API_KEY`, Mux માટે `MUX_SERVER_AUTH_TOKEN` (ક્યારેય CLI
   ફ્લૅગ તરીકે નહીં, જેથી ટોકન ક્યારેય `ps`/પ્રક્રિયા સૂચિઓમાં દેખાતું નથી).
4. કોઈપણ HTTP પ્રતિસાદમાં ક્યારેય પ્લેઇનટેક્સ્ટ કી પરત કરતું નથી.

CLIProxyAPIને સ્પૉન સમયે ઇન્જેક્ટ કરેલી સમર્પિત ડેટા-પ્લેન કી મળે છે
(`needsApiKey: true` — ઍડૅપ્ટર સામે મૉડલ સિંક માટે વપરાય છે).

### SSRF સામે રક્ષણ

રિવર્સ HTTP પ્રૉક્સી (`/dashboard/.../embed/[...path]`) માત્ર
`http://127.0.0.1:{port}` પર ફૉર્વર્ડ કરવા માટે હાર્ડકોડેડ છે. તે ક્યારેય નોન-લૂપબૅક
ગંતવ્ય તરફના રીડાયરેક્ટને અનુસરતી નથી. લૂપબૅક શ્રેણીની બહાર રિઝૉલ્વ થતા કોઈપણ અપસ્ટ્રીમ URLને
નકારવા માટે `ssrf-req-filter` લાઇબ્રેરીનો ઉપયોગ થાય છે.

### શેલ સુરક્ષા (કડક નિયમ #13)

`npm install`ને `execFile('npm', ['install', pkg, '--prefix', dir])` દ્વારા ચલાવવામાં આવે છે —
કોઈ ટેમ્પ્લેટ લિટરલ નહીં, કોઈ શેલ નહીં અને કમાન્ડ
સ્ટ્રિંગમાં બાહ્ય પાથનું કોઈ ઇન્ટરપોલેશન નહીં. રનટાઇમ મૂલ્યો (પોર્ટ, API કી) ચાઇલ્ડના `env` ઑબ્જેક્ટ મારફતે મોકલવામાં આવે છે.

### ભૂલ સેનિટાઇઝેશન (કડક નિયમ #12)

`/api/services/*` તરફથી આવતા તમામ ભૂલ પ્રતિસાદ `buildErrorBody()` અથવા
`sanitizeErrorMessage()` મારફતે પસાર થાય છે. કાચા `err.stack` અને `err.message` ક્યારેય
કૉલરને યથાવત્ પરત કરવામાં આવતા નથી.

## 6. નવી એમ્બેડેડ સેવા ઉમેરવી

આ 8 પગલાં અનુસરો. અધિકૃત સંદર્ભ તરીકે `src/lib/services/installers/`
અને `src/app/api/services/` માંના હાલના અમલીકરણો વાંચો.

### પગલું 1 — ઇન્સ્ટૉલર બનાવો

`ninerouter.ts`ના આધારે `src/lib/services/installers/{name}.ts` બનાવો:

```typescript
export const NAME_PACKAGE = "your-npm-package";
export const NAME_DEFAULT_PORT = 20132; // ખાલી પોર્ટ પસંદ કરો

export async function install(version = "latest"): Promise<InstallResult> { ... }
export async function update(version = "latest"): Promise<InstallResult> { ... }
export async function uninstall(): Promise<void> { ... }
export function resolveSpawnArgs(apiKey: string, port: number): SpawnArgs { ... }
export async function getInstalledVersion(): Promise<string | null> { ... }
export async function getLatestVersion(): Promise<string | null> { ... }
```

`installers/utils.ts`માંથી `runNpm(['install', NAME_PACKAGE, '--prefix', dir])`નો ઉપયોગ કરો
— ક્યારેય `execSync` અથવા શેલ ઇન્ટરપોલેશનનો ઉપયોગ ન કરો.

### પગલું 2 — બૂટસ્ટ્રૅપમાં નોંધણી કરો

`src/lib/services/bootstrap.ts`માં `SERVICES` ઍરેમાં `ServiceEntry` ઉમેરો:

```typescript
{
  tool: "myservice",
  port: NAME_DEFAULT_PORT,
  healthPath: "/health",
  healthIntervalMs: 5_000,
  stopTimeoutMs: 15_000,
  logsBufferBytes: 5_242_880,
  needsApiKey: true, // API કીની જરૂર ન હોય તો false
}
```

`cfg.tool === "myservice"`ને સંભાળવા માટે `buildSpawnArgsFactory()`ને વિસ્તારો.

#### પ્લગ કરી શકાય એવો પ્રદાતા-પ્લગઇન કરાર (તબક્કો 1, #7333)

`src/lib/services/providerPlugins/` એક `ServiceProviderPlugin` કરાર રજૂ કરે છે, જે
બૅકએન્ડના `bootstrap.ts`ના `ServiceEntry` ફીલ્ડ અને `serviceBackends.ts`ના
મૅનિફેસ્ટ-ટેમ્પ્લેટ ફીલ્ડને એક ઑબ્જેક્ટમાં પૅકેજ કરે છે, જેથી એક જ બૅકએન્ડનું સ્વરૂપ
બે અસંબંધિત ફાઇલોમાં અલગથી વ્યક્ત ન કરવું પડે. આ લખાય છે ત્યારે **માત્ર `9router`ને
માઇગ્રેટ કરવામાં આવ્યું છે** — `bootstrap.ts` તેની `SERVICES[]` એન્ટ્રી
`getServiceProviderPlugin("9router")` (`src/lib/services/providerPlugins/registry.ts`)માંથી મેળવે છે,
અને જો પ્લગઇન ક્યારેય ખૂટતું હોય તો સ્ટાર્ટઅપ ભૂલ ફેંકે છે. `cliproxy`, `mux`, અને `bifrost`
હાલના ઇનલાઇન `SERVICES[]` લિટરલ પર કોઈ ફેરફાર વિના રહે છે.

`open-sse/config/providerPluginManifest.ts`માં એક ઉમેરાત્મક
`createServiceBackendManifestEntry(pluginId, template)` હેલ્પર પણ ઉમેરાયો છે, જે
`SERVICE_BACKEND_MANIFEST_TEMPLATE` એન્ટ્રીમાંથી યોગ્ય રીતે રચાયેલ
`ProviderPluginManifestEntry` બનાવે છે — તે હજુ સુધી કોઈ લાઇવ રિક્વેસ્ટ પાથમાં
જોડાયેલો **નથી** (`generateProviderPluginManifestFromRegistry()` કે
`/v1/providers/[provider]/models` બંનેમાંથી કોઈમાં નહીં); બીજા બૅકએન્ડ માટે કરાર
સાબિત થઈ જાય ત્યાર બાદ આ અનુગામી કાર્ય તરીકે બાકી રહેશે.

ઇશ્યૂ #7333 હેઠળ ટ્રૅક થતા અનુગામી PR માટે મુલતવી રાખેલાં કાર્યો: `cliproxyapi`ને એ જ
રજિસ્ટ્રી મારફતે માઇગ્રેટ કરવું, `mux`/`bifrost`ને `ServiceBackendPluginId` યુનિયનમાં
સામાન્યીકૃત કરવું, એક્ઝિક્યુટર-રાઉટિંગના વિશિષ્ટ હૅન્ડલિંગને (`open-sse/executors/index.ts`,
`open-sse/handlers/chatCore/executorProxy.ts`) પ્લગઇન કરારમાં સમાવી લેવું, અને
`createServiceBackendManifestEntry()`ને લાઇવ મૅનિફેસ્ટ/મૉડલ કોડ પાથમાં જોડવું.

## 7. સમસ્યાનિવારણ

### સેવા શરૂ થતી નથી

**લક્ષણો:** Start બટન 503 પરત કરે છે, સ્થિતિ `"error"` અથવા `"starting"` રહે છે.

**ચેકલિસ્ટ:**

1. `GET /api/services/{name}/logs` (અથવા ડૅશબોર્ડમાં Logs પેનલ) તપાસો. `Error: ENOENT`, `address already in use`, અથવા `Cannot find module` જેવી લાઇનો શોધો.
2. OmniRoute ચલાવતા એ જ વપરાશકર્તા ખાતામાંથી `which npm` ચલાવીને ખાતરી કરો કે `npm` PATH માં છે.
3. ખાતરી કરો કે સેવા ઇન્સ્ટોલ થયેલી છે: `installedVersion` માટે `GET /api/services/{name}/status` તપાસો. જો તે `null` હોય, તો પહેલાં ઇન્સ્ટોલ ચલાવો.
4. ખાતરી કરો કે `DATA_DIR/services/{name}/node_modules/` અસ્તિત્વમાં છે અને ખાલી નથી.
5. શુદ્ધ કરાયેલ એક્ઝિટ કારણ માટે સ્ટેટસ પ્રતિસાદમાં `lastError` ફીલ્ડ તપાસો.

---

### કોલ્ડ સ્ટાર્ટ ધીમું છે (`running` સુધી પહોંચવામાં > 10 s)

**લક્ષણો:** સ્થિતિ `"running"` અથવા `"error"` પર જતાં પહેલાં લાંબા સમય સુધી `"starting"` રહે છે.

**સમજૂતી:** 9Routerના કોલ્ડ સ્ટાર્ટમાં વિશાળ ડિપેન્ડન્સી ટ્રી (DNS, ટનલ, MITM મોડ્યુલો) ઇમ્પોર્ટ કરવાનો સમાવેશ થાય છે. સુપરવાઇઝર ટાઇમઆઉટ જાહેર કરે તે પહેલાં ડિફૉલ્ટ હેલ્થ ઇન્ટરવલ 3 પ્રયાસો સાથે 2 s છે (પરંતુ તે પોલિંગ ચાલુ રાખે છે).

**ઉકેલ:** `healthIntervalMs` અને `waitForHealthy` ટાઇમઆઉટ (`healthIntervalMs * 3`) `bootstrap.ts` માં કન્ફિગર કરી શકાય છે. વધુ સ્ટાર્ટઅપ સમય ધરાવતી સેવાઓ માટે `healthIntervalMs` ને 5000 અને `stopTimeoutMs` ને 30 000 સુધી વધારો.

---

### પોર્ટ ટકરાવ (`EADDRINUSE`)

**લક્ષણો:** લૉગ્સમાં `address already in use :::20130` દેખાય છે.

**કારણો:**

- બીજી કોઈ પ્રક્રિયા પહેલેથી જ પોર્ટ 20130 નો ઉપયોગ કરી રહી છે.
- અગાઉની 9Router પ્રક્રિયા સંપૂર્ણપણે બંધ થઈ નહોતી (ઝોમ્બી PID).

**ઉકેલ:**

1. `.env` માં `NINEROUTER_PORT` એન્વાયર્નમેન્ટ વેરિએબલ દ્વારા ડિફૉલ્ટ પોર્ટ બદલો.
2. ટકરાતી પ્રક્રિયા શોધીને બંધ કરો: `lsof -ti :20130 | xargs kill -9`.
3. `bootstrap.ts` માં `port` ફીલ્ડ દ્વારા દરેક સેવા માટે પોર્ટ કન્ફિગર કરી શકાય છે.

**નોંધ:** OmniRouteના ડિફૉલ્ટ પોર્ટ 20128 સાથે ટકરાવ ટાળવા માટે 9Router ખાસ કરીને પોર્ટ 20130 ને ડિફૉલ્ટ તરીકે ઉપયોગ કરે છે.

---

### ઇન્સ્ટોલ કરતી વખતે પરવાનગી નકારી (`EACCES`)

**લક્ષણો:** ઇન્સ્ટોલ 500 પરત કરે છે, લૉગ્સમાં `EACCES` અથવા `permission denied` દેખાય છે.

**કારણો:**

- `DATA_DIR` અથવા તેની પેરેન્ટ ડિરેક્ટરી OmniRoute પ્રક્રિયા દ્વારા લખી શકાય તેવી નથી.
- મેપ કરેલા વૉલ્યૂમ માટે લખવાની ઍક્સેસ વિના Docker rootlessની અંદર ચાલી રહ્યું છે.

**ઉકેલ:**

1. `DATA_DIR` તપાસો (ડિફૉલ્ટ: `~/.omniroute/`): `ls -la ~/.omniroute/`
2. ખાતરી કરો કે OmniRoute પ્રક્રિયાનો વપરાશકર્તા ડિરેક્ટરીનો માલિક છે: `chown -R $USER ~/.omniroute/`
3. Dockerમાં ખાતરી કરો કે વૉલ્યૂમ માઉન્ટ પાસે કન્ટેનર વપરાશકર્તા માટે યોગ્ય પરવાનગીઓ છે.

---

### અપડેટ નિષ્ફળ જાય છે (`npm install` ટાઇમઆઉટ અથવા નેટવર્ક ભૂલ)

**લક્ષણો:** અપડેટ `InstallError` સાથે 500 પરત કરે છે, લૉગ્સમાં નેટવર્ક ટાઇમઆઉટ દેખાય છે.

**ચેકલિસ્ટ:**

1. ખાતરી કરો કે npm રજિસ્ટ્રી સુધી પહોંચી શકાય છે: `npm ping`.
2. કોર્પોરેટ પ્રૉક્સી તપાસો: `npm config get proxy`, `npm config get https-proxy`.
3. ઇન્સ્ટોલ મૅન્યુઅલી અજમાવો: `npm install {package}@latest --prefix ~/.omniroute/services/{name}/`.
4. જો એર-ગૅપ પાછળ હોય, તો ટારબૉલ અગાઉથી ડાઉનલોડ કરો અને `npm install /path/to/tarball.tgz` નો ઉપયોગ કરો.

---

### શરૂ કર્યા પછી સેવા તરત જ `"error"` સ્થિતિ બતાવે છે (ઝડપી ક્રૅશ)

**લક્ષણો:** સ્થિતિ 5 સેકન્ડથી ઓછા સમયમાં `"starting"` માંથી `"error"` માં બદલાય છે. `lastError` માં `"Fast crash (exited with code 1)"` દેખાય છે.

**ચેકલિસ્ટ:**

1. સંપૂર્ણ લૉગ ટેઇલ વાંચો: `GET /api/services/{name}/logs?tail=500`.
2. સામાન્ય કારણ: સેવા દ્વારા અપેક્ષિત એન્વાયર્નમેન્ટ વેરિએબલ્સ ખૂટે છે.
3. 9Router માટે: ખાતરી કરો કે `NINEROUTER_DISABLE_MITM=true` અને `NINEROUTER_DISABLE_TUNNEL=true` સ્પૉન કરતી વખતે પાસ કરાયેલા env માં છે (`installers/ninerouter.ts` માં `resolveSpawnArgs` જુઓ).

## 8. વારંવાર પૂછાતા પ્રશ્નો

**પ્ર: શું હું એમ્બેડેડ સર્વિસના એન્ડપોઇન્ટ્સને નોન-લૂપબૅક ક્લાયન્ટ્સ માટે ઉપલબ્ધ કરાવી શકું?**

ના. LOCAL_ONLY ટિયર ઇરાદાપૂર્વક રાખવામાં આવ્યું છે (કડક નિયમ #17). `npm install` ચલાવી શકતા અથવા `node` પ્રોસેસ શરૂ કરી શકતા રૂટ્સ નોન-લૂપબૅક ટ્રાફિકથી ઍક્સેસ કરી શકાય તેવા ન હોવા જોઈએ, કારણ કે ટનલ (Cloudflare, Ngrok, Tailscale) મારફતે લીક થયેલું JWT અન્યથા મનસ્વી પ્રોસેસ શરૂ કરવાની મંજૂરી આપી શકે છે. `/api/services/` માટે આમાંથી બહાર રહેવાનો કોઈ વિકલ્પ નથી — `/api/mcp/`થી વિપરીત, તેને manage-scope બાયપાસ સૂચિમાંથી બાકાત રાખવામાં આવ્યું છે. `docs/security/ROUTE_GUARD_TIERS.md` જુઓ.

---

**પ્ર: શું 9Router અને CLIProxyAPI પ્રોડક્શન/ક્લાઉડ ડિપ્લોયમેન્ટ્સમાં ઉપલબ્ધ હશે?**

હા. બંને સર્વિસ OmniRouteની જેમ જ local-first મોડલને અનુસરે છે. તેઓ એક જ મશીન પર ચાલે છે અને લૂપબૅક મારફતે સંચાર કરે છે. અહીં "પ્રોડક્શન"નો અર્થ એ VPS અથવા સ્થાનિક સર્વર છે જ્યાં OmniRoute ડિપ્લોય કરવામાં આવ્યું છે, કોઈ રિમોટ ક્લાઉડ પ્રોવાઇડર નહીં.

---

**પ્ર: હું સુપરવાઇઝરને કેવી રીતે ડિબગ કરું?**

1. SSE લૉગ સ્ટ્રીમને અનુસરો: `curl -N http://localhost:20128/api/services/9router/logs`.
2. `service:supervisor` નેમસ્પેસ દ્વારા ફિલ્ટર કરેલા OmniRouteના pino આઉટપુટમાં સ્ટ્રક્ચર્ડ લૉગ્સ તપાસો.
3. DB પંક્તિ તપાસો: `sqlite3 ~/.omniroute/omniroute.db "SELECT * FROM version_manager WHERE tool='9router'"`.
4. હાલની લાઇવ સ્થિતિ, PID, હેલ્થ અને `lastError`ને એક જ કૉલમાં જોવા માટે `GET /api/services/9router/status`નો ઉપયોગ કરો.

---

**પ્ર: સુપરવાઇઝર `health: "degraded"` અથવા `health: "unknown"` બતાવે છે, પરંતુ સ્થિતિ `"running"` છે. શું આ કોઈ સમસ્યા છે?**

`"degraded"`નો અર્થ એ છે કે હેલ્થ પ્રોબે non-200 પ્રતિસાદ પરત કર્યો છે. `"unknown"`નો અર્થ એ છે કે હજુ સુધી કોઈ પ્રોબ પૂર્ણ થયો નથી (પ્રથમ પોલ સાથેની રેસ). સ્ટાર્ટઅપ દરમિયાન બંને ક્ષણિક હોય છે. જો `"running"` થયા પછી `healthIntervalMs * 3` ms કરતાં વધુ સમય સુધી હેલ્થ `"degraded"` રહે, તો એમ્બેડેડ સર્વિસ ચાલી રહી છે, પરંતુ તેનું HTTP API પ્રતિસાદ આપી રહ્યું નથી. સ્ટેટસ પ્રતિસાદમાં પોર્ટ સાચો છે કે નહીં અને સર્વિસ ખરેખર તે પોર્ટ પર લિસન કરી રહી છે કે નહીં તે તપાસો.

---

**પ્ર: શું હું સંપૂર્ણ રીસ્ટાર્ટ કર્યા વિના 9Router API કી બદલી શકું?**

ના. API કી સ્પૉન સમયે એન્વાયર્નમેન્ટ વેરિએબલ મારફતે 9Routerને આપવામાં આવે છે. ચાલી રહેલી પ્રોસેસમાં એન્વાયર્નમેન્ટ વેરિએબલ્સ બદલી શકાતા નથી. નવી કી લાગુ કરવા માટે `POST .../rotate-key` આપમેળે સર્વિસને રોકે છે અને ફરી શરૂ કરે છે. કી રોટેશન સર્વિસના `stopTimeoutMs` (ડિફૉલ્ટ 15 s) અને તેના સ્ટાર્ટઅપ સમયમાં પ્રભાવી થાય છે.

---

**પ્ર: રિંગ બફરની મર્યાદા શું છે અને તે ભરાઈ જાય ત્યારે શું થાય છે?**

દરેક સર્વિસ પાસે સમર્પિત 5 MB રિંગ બફર હોય છે. જ્યારે બફર ભરાઈ જાય છે, ત્યારે નવી લાઇનો માટે જગ્યા બનાવવા સૌથી જૂની લૉગ લાઇનો દૂર કરવામાં આવે છે. SSE `snapshot` ઇવેન્ટ `tail` મર્યાદાની અંદરની સૌથી તાજેતરની લાઇનો પરત કરે છે. DB પંક્તિમાં `logsBufferPath` સેટ ન હોય ત્યાં સુધી લૉગ્સ ડિસ્ક પર સંગ્રહિત થતા નથી.
