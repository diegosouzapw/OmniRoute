OmniRoute તૃતીય-પક્ષના ક્લાઉડ-હોસ્ટેડ કોડિંગ એજન્ટ્સ (Codex Cloud, Cursor,
Devin, Jules) ને લાંબા સમય સુધી ચાલતા ટાસ્ક તરીકે સંચાલિત કરે છે. દરેક એજન્ટને એકસમાન ઇન્ટરફેસની પાછળ આવરવામાં આવ્યો છે, જેથી
ક્લાયન્ટ્સ પ્રદાતા-વિશિષ્ટ API સાથે કામ કર્યા વિના પ્રોમ્પ્ટ + રિપોઝિટરી URL સબમિટ કરી શકે અને પરિણામો મેળવી શકે.

Cloud Agent ટાસ્ક નિયમિત ચેટ કમ્પ્લીશન **નથી**. તે કાર્યનું એક ટકાઉ, બહુ-પગલાંવાળું
એકમ છે, જેને પૂર્ણ થવામાં મિનિટોથી લઈને કલાકો લાગી શકે છે, જે તેના
આર્ટિફેક્ટ તરીકે Pull Request બનાવી શકે છે અને ફોલો-અપ સંદેશાઓ તથા (કેટલાક પ્રદાતાઓમાં) પ્લાન મંજૂરી ગેટ્સને સપોર્ટ કરે છે.

| -------------- | ------------------ | ------------------------------------- | --------------------------------------- | ------------- |

| `devin`        | `DevinAgent`       | `src/lib/cloudAgent/agents/devin.ts`  | `https://api.devin.ai/v1`               | હા            |
| `codex-cloud`  | `CodexCloudAgent`  | `src/lib/cloudAgent/agents/codex.ts`  | `https://api.openai.com/v1/codex/cloud` | ના (સ્વચાલિત) |
| `cursor-cloud` | `CursorCloudAgent` | `src/lib/cloudAgent/agents/cursor.ts` | `https://api.cursor.com/v0`             | ના (સ્વચાલિત) |

રજિસ્ટ્રી: `src/lib/cloudAgent/registry.ts` — `getAgent(providerId)`,
`getAvailableAgents()` અને `isCloudAgentProvider(providerId)` એક્સપોર્ટ કરે છે. રજિસ્ટ્રી એ
મોડ્યુલ લોડ થતી વખતે પોપ્યુલેટ થતું સાદું ઇન-મેમરી `Record<string, CloudAgentBase>` છે.

## આર્કિટેક્ચર

```
ક્લાયન્ટ (ડૅશબોર્ડ / CLI / API)
  → POST /api/v1/agents/tasks (મેનેજમેન્ટ પ્રમાણીકરણ જરૂરી)
    → CreateCloudAgentTaskSchema માન્યકરણ (Zod)
    → registry.getAgent(providerId)
    → getCloudAgentCredentials(providerId)
      └─ getProviderConnections({ provider, isActive: true }) માંથી મેળવે છે
         (પહેલાં apiKey, પછી accessToken નો ફૉલબૅક)
    → agent.createTask({ prompt, source, options }, credentials)
      └─ અપસ્ટ્રીમ પ્રદાતા API ને HTTP POST
      └─ આંતરિક id + externalId સાથે CloudAgentTask પરત કરે છે
    → cloud_agent_tasks (SQLite) માં insertCloudAgentTask(...)

પોલિંગ (વાંચતી વખતે લેઝી સિંક):
  GET /api/v1/agents/tasks/[id]
    → getCloudAgentTaskById(id)
    → agent.getStatus(externalId, credentials)  // સ્થિતિ + પ્રવૃત્તિઓને રિફ્રેશ કરે છે
    → નવી સ્થિતિ, પરિણામ, completed_at સાથે updateCloudAgentTask(...)
    → સિરિયલાઇઝ કરેલો ટાસ્ક પરત કરે છે

ઇન્ટરૅક્શન્સ:
  POST /api/v1/agents/tasks/[id]  બોડી: { action: "approve" | "message" | "cancel" }
    → agent.approvePlan(externalId, credentials)        "approve" માટે
    → agent.sendMessage(externalId, message, credentials) "message" માટે
    → સ્થિતિ "cancelled" માં બદલાય છે                   "cancel" માટે (માત્ર સ્થાનિક)
```

સિંક **લેઝી** છે: દરેક `GET /tasks/[id]` પર સ્થિતિ અપસ્ટ્રીમમાંથી રિફ્રેશ થાય છે.
કોઈ બૅકગ્રાઉન્ડ પોલર નથી. જે ડૅશબોર્ડ્સને તાજી સ્થિતિની જરૂર હોય તેમણે GET
એન્ડપોઇન્ટને યોગ્ય અંતરાલે પોલ કરવું જોઈએ.

## `CloudAgentBase` ઇન્ટરફેસ

સ્રોત: `src/lib/cloudAgent/baseAgent.ts`

```typescript
export interface AgentCredentials {
  apiKey: string;
  baseUrl?: string;
}

export interface CreateTaskParams {
  prompt: string;
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
}

export interface GetStatusResult {
  status: CloudAgentStatus;
  externalId?: string;
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
}

export abstract class CloudAgentBase {
  abstract readonly providerId: string;
  abstract readonly baseUrl: string;

  abstract createTask(p: CreateTaskParams, c: AgentCredentials): Promise<CloudAgentTask>;
  abstract getStatus(externalId: string, c: AgentCredentials): Promise<GetStatusResult>;
  abstract approvePlan(externalId: string, c: AgentCredentials): Promise<void>;
  abstract sendMessage(
    externalId: string,
    message: string,
    c: AgentCredentials
  ): Promise<CloudAgentActivity>;
  abstract listSources(
    c: AgentCredentials
  ): Promise<{ name: string; url: string; branch?: string }[]>;

  protected mapStatus(raw: string): CloudAgentStatus; // હ્યુરિસ્ટિક અપસ્ટ્રીમ-સ્ટ્રિંગ → enum
  protected generateTaskId(): string; // `task_<ts>_<rand>`
  protected generateActivityId(): string; // `act_<ts>_<rand>`
}
```

`CodexCloudAgent.approvePlan` ઇરાદાપૂર્વક થ્રો કરે છે — Codex Cloud આપમેળે પ્લાન બનાવે છે અને તેમાં
કોઈ મંજૂરી ગેટ નથી. `CodexCloudAgent.listSources` `[]` પરત કરે છે.

`CursorCloudAgent`, Cursorના Background / Cloud Agentsને તેની અધિકૃત REST
API (`api.cursor.com/v0`) મારફતે **વપરાશકર્તા અથવા સર્વિસ-એકાઉન્ટ API કી** વડે ચલાવે છે — આ Cursor IDEના OAuth સત્રનો ફરી ઉપયોગ કરવા કરતાં વધુ સુરક્ષિત,
ફર્સ્ટ-પાર્ટી વિકલ્પ છે (પ્રદાતા `cursor`,
જે પ્રતિબંધના જોખમની ચેતવણી ધરાવે છે). તે એક સાદું REST ઍડેપ્ટર છે (કોઈ `@cursor/sdk` નેટિવ
નિર્ભરતા નથી). `approvePlan` થ્રો કરે છે (Cursor એજન્ટ્સ સ્વાયત્ત રીતે ચાલે છે); `listSources` કી દ્વારા
ઍક્સેસ કરી શકાય તેવી રિપોઝિટરીઓની યાદી આપે છે. Cursor અપરકેસ સ્ટેટસ enums
(`CREATING`/`RUNNING`/`FINISHED`/`ERROR`) પરત કરે છે, જેને સ્પષ્ટ રીતે શેર કરેલા
`CloudAgentStatus` સાથે મેપ કરવામાં આવે છે. `baseUrl` દરેક ક્રેડેન્શિયલ માટે ઓવરરાઇડ કરી શકાય છે, જેથી API વર્ઝન/પાથને
કોડમાં ફેરફાર કર્યા વિના સુધારી શકાય.

## ડોમેન પ્રકારો

સ્રોત: `src/lib/cloudAgent/types.ts`

```typescript
export const CLOUD_AGENT_STATUS = {
  QUEUED: "queued",
  RUNNING: "running",
  AWAITING_APPROVAL: "awaiting_approval",
  COMPLETED: "completed",
  FAILED: "failed",
  CANCELLED: "cancelled",
} as const;

export interface CloudAgentSource {
  repoName: string;
  repoUrl: string; // માન્ય URL હોવું આવશ્યક છે
  branch?: string;
}

export interface CloudAgentResult {
  prUrl?: string;
  prNumber?: number;
  commitMessage?: string;
  diffUrl?: string;
  summary?: string;
  duration?: number; // સેકન્ડ, ધન પૂર્ણાંક
  cost?: number; // ધન ફ્લોટ
}

export interface CloudAgentActivity {
  id: string;
  type: "plan" | "command" | "code_change" | "message" | "error" | "completion";
  content: string;
  timestamp: string; // ISO 8601
  metadata?: Record<string, unknown>;
}

export interface CloudAgentTask {
  id: string; // આંતરિક `task_...` id
  providerId: "jules" | "devin" | "codex-cloud" | "cursor-cloud";
  externalId?: string; // અપસ્ટ્રીમ પ્રદાતાનું id
  status: CloudAgentStatus;
  prompt: string; // 1..10000 અક્ષરો
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
  createdAt: string;
  updatedAt: string;
  completedAt?: string;
}
```

માન્યતા સ્કીમા (`CreateCloudAgentTaskSchema`, `UpdateCloudAgentTaskSchema`) પ્રકારોની
સાથે એક્સપોર્ટ કરવામાં આવે છે અને રૂટ હેન્ડલર્સ દ્વારા ઉપયોગમાં લેવાય છે.

## ડેટાબેઝ

સ્રોત: `src/lib/cloudAgent/db.ts` — ટેબલને
`createCloudAgentTaskTable()` દ્વારા જરૂર પડ્યે બનાવવામાં આવે છે (મોડ્યુલ ઇમ્પોર્ટ વખતે
`src/lib/cloudAgent/index.ts`માંથી પણ તેને કૉલ કરવામાં આવે છે).

```sql
CREATE TABLE IF NOT EXISTS cloud_agent_tasks (
  id           TEXT PRIMARY KEY,
  provider_id  TEXT NOT NULL,
  external_id  TEXT,
  status       TEXT NOT NULL DEFAULT 'queued',
  prompt       TEXT NOT NULL,
  source       TEXT NOT NULL,             -- JSON
  options      TEXT DEFAULT '{}',         -- JSON
  result       TEXT,                       -- JSON
  activities   TEXT DEFAULT '[]',          -- JSON
  error        TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_provider ON cloud_agent_tasks(provider_id);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_status   ON cloud_agent_tasks(status);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_created  ON cloud_agent_tasks(created_at DESC);
```

SQL ઇન્જેક્શન અટકાવવા માટે `updateCloudAgentTask` **કૉલમ વ્હાઇટલિસ્ટ** લાગુ કરે છે:
`status`, `prompt`, `source`, `options`, `result`, `activities`, `error`,
`completed_at`. આંશિક અપડેટમાં રહેલી અન્ય કોઈપણ કી કોઈ સૂચના વિના કાઢી નાખવામાં આવે છે.

## REST API — ટાસ્ક જીવનચક્ર

**પ્રમાણીકરણ:** તમામ `/api/v1/agents/tasks*` એન્ડપોઇન્ટ માટે **મેનેજમેન્ટ પ્રમાણીકરણ**
જરૂરી છે (`requireCloudAgentManagementAuth`,
`src/lib/api/requireManagementAuth`માંથી `requireManagementAuth`ને રૅપ કરે છે). કમિટ `588a0333`
(_"fix(auth): require management auth for agent and cooldown APIs"_) પછી આ લાગુ કરવામાં આવે છે.

| પદ્ધતિ  | પાથ                           | હેતુ                                                            |
| ------- | ----------------------------- | --------------------------------------------------------------- |
| OPTIONS | `/api/v1/agents/tasks`        | CORS પ્રીફ્લાઇટ                                                 |
| GET     | `/api/v1/agents/tasks`        | ટાસ્કની યાદી મેળવો (ફિલ્ટર: `provider`, `status`, `limit≤500`)  |
| POST    | `/api/v1/agents/tasks`        | ટાસ્ક બનાવો (અપસ્ટ્રીમને ડિસ્પૅચ કરે છે + સંગ્રહિત રાખે છે)     |
| DELETE  | `/api/v1/agents/tasks?id=...` | ક્વેરી id દ્વારા ટાસ્ક કાઢી નાખો (અપસ્ટ્રીમને રદ કરતું **નથી**) |
| OPTIONS | `/api/v1/agents/tasks/[id]`   | CORS પ્રીફ્લાઇટ                                                 |
| GET     | `/api/v1/agents/tasks/[id]`   | ટાસ્ક વાંચો + અપસ્ટ્રીમમાંથી સ્થિતિનું લેઝી-સિંક કરો            |
| POST    | `/api/v1/agents/tasks/[id]`   | ક્રિયા: `approve` / `message` / `cancel`                        |
| DELETE  | `/api/v1/agents/tasks/[id]`   | પાથ id દ્વારા ટાસ્ક કાઢી નાખો                                   |

`cancel` સ્થાનિક DBમાં `status`ને `"cancelled"`માં બદલે છે, પરંતુ
અપસ્ટ્રીમ પ્રોવાઇડરને કૉલ કરતું **નથી** — `CloudAgentBase`માં કોઈ abort RPC નથી. અપસ્ટ્રીમ
બિલિંગ રોકવા માટે, પ્રોવાઇડરના પોતાના કન્સોલમાં ટાસ્ક સમાપ્ત કરો.

## REST API — ક્લાઉડ પ્રોવાઇડર પ્લમ્બિંગ

`src/app/api/cloud/` હેઠળના આ સહાયક એન્ડપોઇન્ટ્સનો ઉપયોગ રિમોટ ક્લાયન્ટ્સ
(CLI, Electron એપ્લિકેશન અથવા સિંક વર્કર્સ) દ્વારા પ્રોવાઇડર કનેક્શન મેટાડેટા વાંચવા
અને મોડેલ ઉપનામો ઉકેલવા માટે થાય છે. તેઓ ટાસ્ક એન્ડપોઇન્ટ્સ દ્વારા ઉપયોગમાં લેવાતા મેનેજમેન્ટ ઑથને બદલે
**નિયમિત API કી** (`validateApiKey` મારફતે) વડે પ્રમાણિત થાય છે.

| પદ્ધતિ | પાથ                             | હેતુ                                                                   |
| ------ | ------------------------------- | ---------------------------------------------------------------------- |
| POST   | `/api/cloud/auth`               | API કી માન્ય કરો, માસ્ક કરેલું કનેક્શન મેટાડેટા + મોડેલ ઉપનામો પરત કરો |
| PUT    | `/api/cloud/credentials/update` | `accessToken` / `refreshToken` / `expiresAt` રિફ્રેશ કરો               |
| POST   | `/api/cloud/model/resolve`      | મોડેલ ઉપનામને `{ provider, model }`માં ઉકેલો                           |
| GET    | `/api/cloud/models/alias`       | તમામ મોડેલ ઉપનામોની યાદી આપો                                           |
| PUT    | `/api/cloud/models/alias`       | મોડેલ ઉપનામ સેટ કરો (અને સક્ષમ હોય તો Cloud સાથે ઑટો-સિંક કરો)         |

`/api/cloud/auth` ક્યારેય મૂળ `apiKey` / `accessToken` / `refreshToken` પરત કરતું નથી. તે
`hasApiKey`, `hasAccessToken`, `hasRefreshToken` અને માસ્ક કરેલું પૂર્વાવલોકન
(`maskedApiKey`: પ્રથમ 4 + `****` + છેલ્લા 4) પરત કરે છે.

## ક્રેડેન્શિયલ્સ રિઝોલ્યુશન

`src/lib/cloudAgent/api.ts`માં `getCloudAgentCredentials(providerId)`:

1. `getProviderConnections({ provider: providerId, isActive: true })` મારફતે સક્રિય પ્રોવાઇડર કનેક્શન્સ લોડ કરે છે.
2. દરેક કનેક્શન માટે, `apiKey` (ટ્રિમ કરેલી)ને પ્રાથમિકતા આપે છે. ન હોય તો `accessToken`નો ઉપયોગ કરે છે.
3. પ્રથમ ખાલી ન હોય તેવા ટોકનને `{ apiKey: token }` તરીકે રૅપ કરીને પરત કરે છે.
4. જો કોઈ ઉપયોગ કરી શકાય તેવું ટોકન ન મળે, તો `null` પરત કરે છે — API
   `"No active credentials configured for cloud agent provider: <id>"` સાથે `400` પ્રતિસાદ આપે છે.

આનો અર્થ એ છે કે Cloud Agents નિયમિત LLM પ્રોવાઇડર્સ જેવી જ Provider Connection ટેબલનો
ફરીથી ઉપયોગ કરે છે. Jules સક્ષમ કરવા માટે, `provider: "jules"` અને ભરેલી `apiKey`
ધરાવતું સક્રિય કનેક્શન બનાવો.

## ડૅશબોર્ડ

સ્રોત: `src/app/(dashboard)/dashboard/cloud-agents/page.tsx`

એક `"use client"` React પેજ, જે:

- `CreateCloudAgentTaskSchema` સાથે મૅપ થતા ફોર્મ મારફતે નવા ટાસ્ક્સ સબમિટ કરે છે.
- સ્ટેટસ બૅજ (`queued`, `running`, `awaiting_approval`, `completed`,
  `failed`, `cancelled`) દર્શાવે છે અને `activities[]` સમયરેખા રેન્ડર કરે છે.
- જ્યારે `status === "completed"` હોય ત્યારે `result.prUrl` / `commitMessage` / `summary` દર્શાવે છે.

## A2A સાથે ઇન્ટિગ્રેશન

Cloud Agentsને A2A સ્કિલ્સ તરીકે ઉપલબ્ધ કરાવવા માટે એવી A2A સ્કિલ રજિસ્ટર કરી શકાય છે, જે
તેના `tasks/send` હૅન્ડલરને `getAgent(...).createTask(...)`ને સોંપે અને A2A ટાસ્ક
સ્ટેટસ ઇવેન્ટ્સને JSON-RPC 2.0 પ્રોટોકોલમાં રૂપાંતરિત કરે. [A2A-SERVER.md](./A2A-SERVER.md) જુઓ.

## નવું Cloud Agent ઉમેરવું

1. `CloudAgentBase`ને એક્સ્ટેન્ડ કરતી `src/lib/cloudAgent/agents/<name>.ts` બનાવો.
2. `createTask`, `getStatus`, `approvePlan` (અથવા લાગુ ન પડતું હોય તો throw કરો),
   `sendMessage`, `listSources` ઇમ્પ્લિમેન્ટ કરો. સ્ટેટસ નોર્મલાઇઝેશન માટે `this.mapStatus(...)`નો ઉપયોગ કરો.
3. સ્થિર `providerId` હેઠળ `src/lib/cloudAgent/registry.ts`માં રજિસ્ટર કરો.
4. `src/lib/cloudAgent/types.ts`માં `providerId` લિટરલ યુનિયનને એક્સ્ટેન્ડ કરો
   (`CloudAgentTask.providerId` અને `CreateCloudAgentTaskSchema`).
5. જો પ્રોવાઇડરને કનેક્શન રેકોર્ડની જરૂર હોય, તો તેને `src/shared/constants/providers.ts`માં ઉમેરો.
   OAuth-આધારિત પ્રોવાઇડર્સને `src/lib/oauth/providers/`ની પણ જરૂર પડે છે.
6. `tests/unit/cloud-agent-*.test.ts` હેઠળ ટેસ્ટ્સ ઉમેરો.
7. આ દસ્તાવેજ અને ડૅશબોર્ડના `CLOUD_AGENTS` કૉન્સ્ટન્ટને અપડેટ કરો.
