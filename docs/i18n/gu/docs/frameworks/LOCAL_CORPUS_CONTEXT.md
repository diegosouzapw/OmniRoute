## તે શું છે

Local Corpus ઑપરેટરને ટેક્સ્ટ ફાઇલોની સ્પષ્ટપણે મંજૂર કરેલી એક ડિરેક્ટરી
OmniRouteના MCP સર્વર માટે ઉપલબ્ધ કરાવવા દે છે. ફાઇલો તેમની મૂળ ડિરેક્ટરીમાં જ રહે છે:
OmniRoute SQLiteમાં ફક્ત પ્રમાણભૂત રૂટ પાથ સંગ્રહે છે અને ઇન-મેમરી શોધ ઇન્ડેક્સ જાળવે છે.
તે કોર્પસની સામગ્રીને રિપોઝિટરી અથવા ડેટાબેઝમાં કૉપિ કરતું નથી.

ઇન્ડેક્સ રિફ્રેશ ક્રમિક છે. કદ અને ફેરફારના સમયના આધારે યથાવત ફાઇલોનો ફરી ઉપયોગ થાય છે,
બદલાયેલી ફાઇલો ફરી વાંચવામાં આવે છે અને SHA-256 વડે હૅશ કરવામાં આવે છે, તથા કાઢી નાખેલી
ફાઇલો દૂર કરવામાં આવે છે. શોધ 30 સેકન્ડથી જૂના ઇન્ડેક્સને રિફ્રેશ કરે છે; કૉલર્સ
તાત્કાલિક રિફ્રેશની વિનંતી પણ કરી શકે છે.

## સ્રોત કૉન્ફિગર કરો

સેટિંગ્સ રૂટને અન્ય સેટિંગ્સ API જેટલા જ મેનેજમેન્ટ પ્રમાણીકરણની જરૂર પડે છે.
સબમિટ કરેલો પાથ પહેલેથી અસ્તિત્વમાં હોવો જોઈએ અને ઍબ્સોલ્યુટ ડિરેક્ટરી પાથ હોવો જોઈએ.

```bash
# મંજૂર કરેલી ડિરેક્ટરી કનેક્ટ કરો
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# કૉન્ફિગરેશન અને ઇન્ડેક્સની સ્થિતિ તપાસો
curl http://localhost:20128/api/settings/local-corpus

# સ્રોત ફાઇલો બદલ્યા વિના ડિસ્કનેક્ટ કરો
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## MCP ટૂલ્સ

ત્રણેય ટૂલ્સ માટે `read:local-corpus` જરૂરી છે. ટૂલના પ્રતિસાદોમાં સાપેક્ષ પાથ અને
રૂટ ડિરેક્ટરીનું મૂળ નામ દર્શાવવામાં આવે છે, તેનો ઍબ્સોલ્યુટ પાથ ક્યારેય નહીં.

| ટૂલ                   | વર્ણન                                                                                             |
| :-------------------- | :------------------------------------------------------------------------------------------------ |
| `local_corpus_status` | કૉન્ફિગરેશનની સ્થિતિ, ઇન્ડેક્સનું કદ, મર્યાદાઓ અને છેલ્લા રિફ્રેશનો સમય જણાવે છે                  |
| `local_corpus_search` | ઇન્ડેક્સ કરેલા ટેક્સ્ટમાં શોધ કરે છે અને મર્યાદિત, લાઇન-વ્યાપી સ્નિપેટ્સ આપે છે (20 પરિણામો સુધી) |
| `local_corpus_read`   | મંજૂર કરેલી એક કોર્પસ-સાપેક્ષ ફાઇલમાંથી મર્યાદિત લાઇન રેન્જ વાંચે છે                              |

MCP ઇનપુટનાં ઉદાહરણો:

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## સુરક્ષાની સીમાઓ

- મંજૂર સૂચિ ટેક્સ્ટ-કેન્દ્રિત છે: `.cfg`, `.csv`, `.geojson`, `.htm`, `.html`, `.ini`,
  `.js`, `.json`, `.jsonl`, `.jsx`, `.log`, `.md`, `.mjs`, `.ps1`, `.py`, `.sh`,
  `.sql`, `.toml`, `.ts`, `.tsx`, `.txt`, `.xml`, `.yaml`, અને `.yml`.
- સિમલિંક્સ અવગણવામાં આવે છે. વાંચવાના પાથનું પ્રમાણીકરણ કરવામાં આવે છે અને તે
  કૉન્ફિગર કરેલા રૂટની અંદર જ રહેવા જોઈએ; ઍબ્સોલ્યુટ પાથ અને ટ્રાવર્સલના પ્રયાસો નકારવામાં આવે છે.
- સંવેદનશીલ અને જનરેટ થયેલાં ડિરેક્ટરી નામો બાકાત રાખવામાં આવે છે: `.build`, `.codex`, `.env`,
  `.git`, `.next`, `.omniroute`, `.ssh`, `coverage`, `dist`, `node_modules`, અને
  `secrets`.
- ડિફૉલ્ટ મર્યાદાઓ 5,000 ફાઇલો, ફાઇલદીઠ 1 MiB, ઇન્ડેક્સ કરેલી કુલ સામગ્રી માટે 64 MiB,
  દરેક શોધ ચંકદીઠ અંદાજે 4,000 અક્ષરો અને દરેક વાંચનદીઠ 400 લાઇનો છે.
- NUL ધરાવતી ફાઇલોને બિન-ટેક્સ્ટ તરીકે ગણવામાં આવે છે અને અવગણવામાં કે નકારવામાં આવે છે.

PDF, DOCX, છબીઓ અને આર્કાઇવ્સ જેવા બાઇનરી દસ્તાવેજો ઇરાદાપૂર્વક સમર્થિત નથી.
ઇન્ડેક્સિંગ પહેલાં તેમને કૉન્ફિગર કરેલી ડિરેક્ટરીમાં મંજૂર ટેક્સ્ટ ફોર્મેટમાં રૂપાંતરિત કરો.

## સંચાલન નોંધો

- કૉન્ફિગર કરેલા રૂટને બદલવાથી અથવા કાઢી નાખવાથી શેર કરેલ ઇન-મેમરી ઇન્ડેક્સ સાફ થાય છે.
- પ્રોસેસ ફરી શરૂ થવાથી ઇન્ડેક્સ કાઢી નાખવામાં આવે છે; આગામી શોધ તેને કૉન્ફિગર કરેલા
  સ્રોતમાંથી ફરી બનાવે છે.
- `local_corpus_status` ફરજિયાત સ્કૅન કરાવતું નથી. તાત્કાલિક ફરી સ્કૅન કરવાની જરૂર હોય ત્યારે
  `refresh: true` સાથે `local_corpus_search`નો ઉપયોગ કરો.
- સ્કૅન અને વાંચનની નિષ્ફળતાઓની ગણતરી કરવામાં આવે છે અથવા સ્વચ્છ કરેલી ભૂલો તરીકે પરત કરવામાં
  આવે છે; સ્રોત ફાઇલો ક્યારેય બદલવામાં આવતી નથી.
