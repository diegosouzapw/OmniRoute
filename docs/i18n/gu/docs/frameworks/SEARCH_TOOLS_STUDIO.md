## વિહંગાવલોકન

Search Tools Studio `/dashboard/search-tools` ને મૂળભૂત સર્ચ પ્લેગ્રાઉન્ડમાંથી વેબ સર્ચ, વેબ સ્ક્રેપિંગ અને બાજુ-બાજુ પ્રદાતા સરખામણીને એકીકૃત કરતા
ત્રણ-ટૅબ Studio માં પરિવર્તિત કરે છે.

```

├──────────────────────────────────────────┬─────────────────────────────┤
│  {સક્રિય ટૅબની સામગ્રી}                  │ ─ કૉન્ફિગ                    │

│                                          │ રીરૅન્ક મોડલ [∨]             │
└──────────────────────────────────────────┴─────────────────────────────┘
```

## ટૅબ્સ

### સર્ચ ટૅબ

હાલના `SearchForm` + `ResultsPanel` + `RerankPanel` ને ટૅબ તરીકે વિકસાવે છે:

- ક્વેરી → પરિણામો (શીર્ષક, URL, સ્નિપેટ, પ્રાસંગિકતા સ્કોર).
- કૉન્ફિગ પેનમાં પ્રદાતાનું મેટાડેટા (ખર્ચ, ક્વોટા, સ્થિતિ).
- રીરૅન્ક વિભાગ: રીરૅન્ક મોડલ પસંદ કરો, પરિણામોને ફરીથી ક્રમબદ્ધ કરો અને `positionDelta` દર્શાવો.
- કોઈ સર્ચ પ્રદાતા કૉન્ફિગર ન હોય ત્યારે CTA સાથે ખાલી સ્થિતિ.
- `SearchHistory.tsx` મારફતે સર્ચ ઇતિહાસ.
- `POST /v1/search` ને કૉલ કરે છે (હાલનો એન્ડપોઇન્ટ, કોઈ ફેરફાર નહીં).

### સ્ક્રેપ ટૅબ

`POST /v1/web/fetch` મારફતે URL માંથી સામગ્રી કાઢવા માટે નવું ટૅબ (યોજના 05 માં બનાવેલું):

- ઇનપુટ: URL + સંપૂર્ણ-પેજ ટૉગલ + ફોર્મેટ સિલેક્ટર (markdown / text / HTML).
- સબમિટ → ફેચ → `ScrapeResult.tsx` રેન્ડર કરો.
- `ScrapeResult` markdown પૂર્વાવલોકન + રૉ ટૉગલ રેન્ડર કરે છે.
- મર્યાદા: જો પ્રતિસાદ બોડી **256 KB** કરતાં મોટી હોય, તો UI `(કાપવામાં આવ્યું છે, રૉ જુઓ)` દર્શાવે છે અને રૉ સામગ્રીને Monaco મોડલમાં ખોલે છે (D21).
- મેટાડેટા પેનલ: પ્રદાતા (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search), લેટન્સી, ખર્ચ, પ્રતિસાદનું કદ, લિંક્સની સંખ્યા.
- `useScrapeFetch.ts` હૂકનો ઉપયોગ કરે છે.

### સરખામણી ટૅબ

એક જ ક્વેરી/URL ને વધુમાં વધુ **4 પ્રદાતાઓ પર સમાંતરે** ચલાવે છે (D22):

- દરેક પ્રદાતા માટે બાજુ-બાજુ કૉલમ્સ.
- માપદંડો: લેટન્સી, ખર્ચ, પરિણામોની સંખ્યા, પ્રતિસાદનું કદ.
- સર્ચ માટે URL ઓવરલૅપની ગણતરી (પ્રારંભિક પરિણામની સરખામણીમાં સહિયારા URL ની સંખ્યા).
- દરેક પ્રદાતા માટે `POST /v1/search` (સર્ચ) અથવા `POST /v1/web/fetch` (સ્ક્રેપ) ને કૉલ કરે છે.

## કૉન્ફિગ પેન (શેર કરેલ)

`SearchToolsConfigPane.tsx` — હંમેશાં દૃશ્યમાન, સંકોચી શકાય તેવું.

| ફીલ્ડ        | નોંધો                                                                 |
| ------------ | --------------------------------------------------------------------- |
| પ્રદાતા      | સ્થિતિ બૅજ સાથેનું ડ્રૉપડાઉન (કૉન્ફિગર કરેલ / ગેરહાજર / દર મર્યાદિત)  |
| પ્રકાર       | `web` અથવા `news` (માત્ર સર્ચ)                                        |
| સંપૂર્ણ પેજ  | સ્ક્રેપ માટે ટૉગલ — પ્રથમ દૃશ્યમાન સામગ્રીને બદલે આખું પેજ ફેચ કરે છે |
| ફોર્મેટ      | `markdown`, `text`, અથવા `html` (માત્ર સ્ક્રેપ)                       |
| રીરૅન્ક મોડલ | સર્ચ પછીના રીરૅન્કિંગ માટે વૈકલ્પિક મોડલ                              |
| ઇતિહાસ       | સંકોચી શકાય એવો સર્ચ ઇતિહાસ વિભાગ                                     |

## SearchConceptCard

`SearchConceptCard.tsx` — હંમેશાં દૃશ્યમાન રહેતું, સંકોચી શકાય તેવું અકોર્ડિયન. આ બાબતો સમજાવે છે:

| ખ્યાલ                      | એક-પંક્તિ વર્ણન                                                              |
| -------------------------- | ---------------------------------------------------------------------------- |
| **શોધ**                    | વેબ પરિણામોની સૂચિ મેળવે છે (શીર્ષક, URL, સ્નિપેટ, પ્રાસંગિકતા સ્કોર)        |
| **સ્ક્રેપ**                | URLની સંપૂર્ણ સામગ્રી કાઢે છે (માર્કડાઉન, ટેક્સ્ટ અથવા HTML)                 |
| **તુલના**                  | સમાન ક્વેરીને N પ્રદાતાઓમાં બાજુ-બાજુ ચલાવે છે                               |
| **પુનઃક્રમનિર્ધારણ**       | ક્વેરીની પ્રાસંગિકતા સુધારવા માટે LLM દ્વારા પરિણામોને ફરીથી ક્રમબદ્ધ કરે છે |
| **સ્વચાલિત (સૌથી સસ્તું)** | ઉપલબ્ધ સૌથી સસ્તા પ્રદાતાને આપમેળે પસંદ કરે છે                               |

## પ્રદાતા કૅટલૉગ

`ProviderCatalog.tsx`, `GET /api/search/providers`માંથી પ્રદાતાઓની સંપૂર્ણ સૂચિ ઉપલબ્ધ કરાવે છે
(ફેચ પ્રદાતાઓનો સમાવેશ કરવા માટે F4માં વિસ્તૃત કરાયેલ):

| `kind` | `"search"` (20 પ્રદાતાઓ) અથવા `"fetch"` (firecrawl, jina-reader, tavily-search, tinyfish, nimble-search, anysearch-search) |

ક્રેડેન્શિયલ્સ ઉપલબ્ધ છે કે નહીં અને બધી કીઓ હાલમાં કૂલડાઉનમાં છે કે નહીં તેની તપાસ કરીને,
સ્થિતિ **વિનંતીના સમયે નિર્ધારિત** કરવામાં આવે છે.

## કોડ નિકાસ

`ExportCodeModal` (Playground Studioમાંથી આયાત કરાયેલ) + `codeExport.ts`, `/v1/search` અને
`/v1/web/fetch` બંને કૉલ્સ માટે curl / Python / TypeScript સ્નિપેટ્સ જનરેટ કરે છે.
API કીનું પ્લેસહોલ્ડર હંમેશાં `$OMNIROUTE_API_KEY` હોય છે (D11, Playground Studio સાથે વહેંચાયેલ).

## બૅકએન્ડ ફેરફારો

આ સુવિધા માટે ફક્ત એક બૅકએન્ડ ફેરફાર જરૂરી હતો:

### વિસ્તૃત `GET /api/search/providers`

`src/app/api/search/providers/route.ts`ને આ માટે વિસ્તૃત કરવામાં આવ્યું હતું:

- એરેમાં તમામ 6 ફેચ પ્રદાતાઓ (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`)નો સમાવેશ કરવો.
- દરેક આઇટમમાં `kind: "search" | "fetch"` ઉમેરવું.
- લાઇવ ક્રેડેન્શિયલ સ્થિતિ પરથી નિર્ધારિત થતું `status: "configured" | "missing" | "rate_limited"` ઉમેરવું.
- પછાત સુસંગતતા જાળવવી — હાલનાં ફીલ્ડ્સ (`id`, `name`, વગેરે) યથાવત્ રાખવા.
