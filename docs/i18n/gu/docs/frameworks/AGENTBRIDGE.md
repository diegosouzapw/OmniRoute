AgentBridge એ OmniRouteનું MITM (મૅન-ઇન-ધ-મિડલ) પ્રૉક્સી છે, જે IDE AI એજન્ટ્સમાંથી આવતા HTTPS ટ્રાફિકને ઇન્ટરસેપ્ટ કરે છે અને તેને OmniRouteના એકીકૃત રાઉટિંગ એન્જિન મારફતે ફરીથી રૂટ કરે છે. તે **10 IDE એજન્ટ્સ**ને સપોર્ટ કરે છે — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code અને Trae (તપાસ હેઠળ) — જે OmniRouteને બજારમાં AI કોડિંગ સહાયકો માટે સૌથી વ્યાપક કવરેજ ધરાવતું MITM પ્રૉક્સી બનાવે છે.

**ડૅશબોર્ડનું સ્થાન:** `/dashboard/tools/agent-bridge`
**સાઇડબાર જૂથ:** ટૂલ્સ (Cloud Agents પછી)
**આ પણ જુઓ:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — ઇન્ટરસેપ્ટ કરાયેલા તમામ ટ્રાફિકનું રીઅલ-ટાઇમમાં નિરીક્ષણ કરો; `docs/security/MITM-TPROXY-DECRYPT.md` (git; `/docs`માં કમ્પાઇલ કરાયેલ નથી) — `/api/tools/agent-bridge/tproxy` રૂટ દ્વારા સંચાલિત Linux TPROXY ટ્રાન્સપરન્ટ-ડિક્રિપ્ટ કૅપ્ચર મોડ.

## §1 અવલોકન

### AgentBridge શું છે?

જ્યારે કોઈ IDE એજન્ટ (દા.ત., GitHub Copilot, Cursor, Claude Code) API કૉલ કરે છે, ત્યારે તે સીધો અપસ્ટ્રીમ AI પ્રદાતા (OpenAI, Anthropic વગેરે) સાથે કનેક્ટ થાય છે. AgentBridge કોઈપણ એજન્ટ કૉન્ફિગરેશન બદલવાની જરૂર વિના — TLS સ્તરે પારદર્શક રીતે — તે કનેક્શનને ઇન્ટરસેપ્ટ કરે છે અને વિનંતીને OmniRoute મારફતે ફરીથી લખે છે.

આનો અર્થ એ છે કે તમે આ કરી શકો છો:

- **કોઈપણ એજન્ટને કોઈપણ પ્રદાતા તરફ ફરીથી રૂટ કરો**: Copilot OpenAI સાથે વાત કરી રહ્યું છે? તેને Anthropic Claude, Gemini અથવા OmniRouteના 352 પ્રદાતાઓમાંથી કોઈપણ તરફ રીડાયરેક્ટ કરો.
- **મૉડલ મૅપિંગ લાગુ કરો**: હૅન્ડલર સ્તરે પારદર્શક રીતે `gemini-3-flash` → `claude-sonnet-4.7`.
- **એજન્ટના તમામ ટ્રાફિકનું નિરીક્ષણ કરો**: ઇન્ટરસેપ્ટ કરાયેલી દરેક વિનંતી [Traffic Inspector](./TRAFFIC_INSPECTOR.md)માં પ્રકાશિત થાય છે.
- **OmniRouteની સ્થિતિસ્થાપકતા લાગુ કરો**: કોમ્બો રાઉટિંગ, સર્કિટ બ્રેકર્સ, ફૉલબૅક્સ અને ખર્ચ ટ્રૅકિંગ IDE એજન્ટ ટ્રાફિક માટે પણ કાર્ય કરે છે.

## §2 આર્કિટેક્ચર

### 2.1 ઘટકોનો પરિચય

```
IDE એજન્ટ (VS Code / Cursor / વગેરે)
    │  HTTPS (પોર્ટ 443)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← DNS રીડાયરેક્ટ
    │
    ▼
src/mitm/server.cjs  (પોર્ટ 443, CJS ચાઇલ્ડ પ્રોસેસ)
    │  Host હેડર SNI દ્વારા લક્ષ્ય નિર્ધારિત કરે છે
    │  AgentBridge CA દ્વારા સહી કરેલું પ્રતિ-SNI TLS પ્રમાણપત્ર જનરેટ કરે છે
    ├── બાયપાસ સૂચિ સાથે મેળ? → TCP પાસથ્રૂ (કોઈ ડિક્રિપ્શન નહીં)
    ├── લક્ષ્ય સાથે મેળ? → fetch → OmniRoute રાઉટર (પોર્ટ 20128)
    │       └── handler.intercept() — TypeScript
    │               ├── વિનંતીના બોડી/હેડર્સ પર maskSecrets()
    │               ├── TrafficBuffer.push() — Traffic Inspector પર પ્રકાશિત કરે છે
    │               └── fetchRouter() → /v1/chat/completions
    └── કોઈ મેળ નહીં? → TCP પાસથ્રૂ (કોઈ ડિક્રિપ્શન નહીં)
```

### 2.2 MITM સર્વર (`src/mitm/server.cjs`)

મુખ્ય MITM સર્વર Node.js CJS ચાઇલ્ડ પ્રોસેસ તરીકે ચાલે છે (હાલની CJS કોડબેઝ ફરી લખવાનું ટાળવા માટે). તે:

- પોર્ટ 443 પર સાંભળે છે (વિશેષાધિકાર અથવા `authbind`/`setcap` જરૂરી છે)
- OS પાસેથી CONNECT ટનલ્સ મેળવે છે (`/etc/hosts` DNS રીડાયરેક્ટ મારફતે)
- AgentBridge CA (`DATA_DIR/mitm/ca.crt`) દ્વારા સહી કરેલા પ્રતિ-SNI TLS પ્રમાણપત્રો જનરેટ કરે છે
- `targets/index.ts` રજિસ્ટ્રી મારફતે Host હેડર દ્વારા લક્ષ્ય એજન્ટ નિર્ધારિત કરે છે
- `http://127.0.0.1:20128` પર HTTP મારફતે TypeScript હેન્ડલર સ્તર તરફ ડિસ્પેચ કરે છે

`TARGET_HOSTS`, `DATA_DIR/mitm/targets.json`માંથી લોડ થાય છે (જે બૂટ સમયે `targets/index.ts` દ્વારા લખાય છે), જેથી CJS સર્વરને પુનઃપ્રારંભ કર્યા વિના ડાયનેમિક અપડેટ્સ કરી શકાય.

> **રૂટ-CA મોડલ (#6684).** ઉપર આપેલું CA દ્વારા સહી કરાયેલ પ્રતિ-SNI પ્રમાણપત્રનું વર્ણન
> #6684માં ઉમેરાયેલ સ્થાયી રૂટ-CA મોડલ છે (`src/mitm/cert/rootCa.ts` +
> `src/mitm/_internal/rootCaShim.cjs`, જેમાં `src/mitm/tproxy/dynamicCert.ts`માં
> TPROXY માટે અગાઉથી પ્રમાણિત CA/લીફ ક્રિપ્ટોનો ફરી ઉપયોગ થાય છે) — તે જૂના એકમાત્ર
> સ્થિર, સ્વ-સહી કરેલા લીફને (`src/mitm/cert/generate.ts`, જે હજુ પણ ફક્ત antigravity
> હોસ્ટ્સ સુધી મર્યાદિત છે) બદલે છે, જેની હાજરી ડિસ્ક પરની `server.crt`/`server.key`
> જોડી દર્શાવે છે. **માઇગ્રેશન વર્તન**: નવા ઇન્સ્ટોલેશનને (અગાઉનું `server.crt` ન હોય)
> રૂટ-CA મોડલ આપમેળે મળે છે; જૂના સ્થિર લીફ પર પહેલેથી વિશ્વાસ કરતું ઇન્સ્ટોલેશન તેનો
> ઉપયોગ ત્યાં સુધી ચાલુ રાખે છે, જ્યાં સુધી ઑપરેટર `MITM_ROOT_CA_ENABLED=true` સેટ
> કરીને બ્રિજ પુનઃપ્રારંભ ન કરે (`src/mitm/cert/migration.ts` શુદ્ધ નિર્ણય ફંક્શન છે —
> **કોઈપણ** હોસ્ટ માટે લીફ પર સહી કરી શકતું વિશ્વસનીય MITM CA જૂના સ્થિર-SAN લીફ
> કરતાં નોંધપાત્ર રીતે વધુ શક્તિશાળી હોવાથી, પહેલેથી વિશ્વસનીય ઇન્સ્ટોલેશન માટે આ ફેરફાર
> ક્યારેય નિઃશબ્દ રીતે થતો નથી). CA પ્રમાણપત્ર એ જ `omniroute-mitm.crt` ટ્રસ્ટ-સ્ટોર
> સ્લોટમાં ઇન્સ્ટોલ થાય છે જેનો ઉપયોગ જૂના લીફે કર્યો હતો
> (`cert/install.ts::installCaCert`) — દ્વિ-વિશ્વાસ ક્લીનઅપની જરૂર નથી.

### 2.3 હેન્ડલર બેઝ (`src/mitm/handlers/base.ts`)

તમામ એજન્ટ હેન્ડલર્સ `MitmHandlerBase`ને એક્સ્ટેન્ડ કરે છે:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // સુરક્ષિત હેલ્પર્સ: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

દરેક હેન્ડલર પ્રોક્સી કરતાં પહેલાં `hookBufferStart()` અને પૂર્ણ થવા પર `hookBufferUpdate()`ને કૉલ કરે છે. આ `InterceptedRequest` એન્ટ્રીઓ `globalTrafficBuffer`માં પુશ કરે છે ([Traffic Inspector](./TRAFFIC_INSPECTOR.md) §4 જુઓ).

### 2.4 લક્ષ્યોની રજિસ્ટ્રી (`src/mitm/targets/`)

દરેક એજન્ટ પાસે ડિક્લેરેટિવ લક્ષ્ય ફાઇલ છે:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

રજિસ્ટ્રી (`targets/index.ts`) `ALL_TARGETS`ને એક્સપોર્ટ કરે છે અને બૂટ સમયે `DATA_DIR/mitm/targets.json` ઉત્પન્ન કરે છે.

### 2.5 પાસથ્રૂ અને બાયપાસ સૂચિ (`src/mitm/passthrough.ts`)

**બાયપાસ સૂચિ** (પહેલાં તપાસવામાં આવે છે અને લક્ષ્યના મેળ કરતાં પ્રાથમિકતા ધરાવે છે):

- ડિફૉલ્ટ પેટર્ન્સ: બેન્કિંગ હોસ્ટ્સ, `.gov.`, OAuth/SSO પ્રોવાઇડર્સ (Okta, Auth0), વગેરે
- વપરાશકર્તા પેટર્ન્સ: DB ટેબલ `agent_bridge_bypass`માં સંગ્રહિત
- બાયપાસ કરાયેલા હોસ્ટ્સને પારદર્શક TCP ટનલ મળે છે — TLSને **ક્યારેય ડિક્રિપ્ટ કરવામાં આવતું નથી**

**પાસથ્રૂ ડિફૉલ્ટ** (લક્ષ્ય સાથે મેળ ન હોય અને બાયપાસમાં પણ ન હોય):

- આને પણ TCP ટનલ મળે છે — કનેક્શન્સ ક્યારેય તોડવામાં આવતાં નથી
- AgentBridgeને સામાન્ય સિસ્ટમ HTTPS ટ્રાફિકમાં વિક્ષેપ પાડતાં અટકાવે છે

રાઉટિંગ પ્રાથમિકતા:

```
બાયપાસ સૂચિ → લક્ષ્ય સાથે મેળ → પાસથ્રૂ
```

### 2.6 અપસ્ટ્રીમ CA પ્રમાણપત્ર (`src/mitm/upstreamTrust.ts`)

કસ્ટમ CA ધરાવતા કૉર્પોરેટ નેટવર્ક પર્યાવરણો માટે:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

સેટ કરેલું હોય ત્યારે, વધારાના CA પ્રમાણપત્ર સાથે `undici`ના ગ્લોબલ ડિસ્પેચરને કન્ફિગર કરે છે, જેથી AgentBridge કૉર્પોરેટ TLS ટર્મિનેશન પ્રોક્સીઓ મારફતે અપસ્ટ્રીમ પ્રોવાઇડર્સ સુધી પહોંચી શકે.

### 2.7 સિક્રેટ માસ્કિંગ (`src/mitm/maskSecrets.ts`)

સ્વતંત્ર ક્લીન-રૂમ સ્કેનર વિનંતીના બોડીઝ અને ક્રેડેન્શિયલ હેડર્સ Traffic Inspector બફર અથવા કોઈપણ લોગમાં પ્રવેશે તે
**પહેલાં** લાગુ કરવામાં આવે છે. તે એક જ લીનિયર પાસ કરે છે:

- `sk-` / `ak-` / `pk-` પ્રીફિક્સ ધરાવતા ટોકન્સ (OpenAI/Anthropic-શૈલી)
- સંપૂર્ણ-ટોકન પ્રાથમિકતા સાથે RFC 6750 `Authorization: Bearer <token>` ક્રેડેન્શિયલ્સ
- ડોટેડ અને પેડેડ સ્વરૂપો સહિત સામાન્ય લાંબા અપારદર્શક ટોકન્સ (≥40 અક્ષરો)

`sanitizeHeaders()` જાળવી રાખેલા નામોને લોઅરકેસમાં ફેરવે છે, એરે મૂલ્યોને નિર્ધારિત રીતે જોડે છે,
વહેંચાયેલ hop-by-hop/framing denylistને (પ્રોક્સી ઑથેન્ટિકેશન સહિત) દૂર કરે છે, `cookie` અને
`set-cookie`ને સંપૂર્ણપણે રીડેક્ટ કરે છે અને ક્રેડેન્શિયલ મૂલ્યો સ્કેનરને સોંપે છે.

`/dashboard/tools/agent-bridge` પર AgentBridge સર્વર કાર્ડનો ઉપયોગ કરો:

| ક્રિયા                     | વર્ણન                                                                               |
| -------------------------- | ----------------------------------------------------------------------------------- |
| સર્વર શરૂ કરો              | પોર્ટ 443 પર `src/mitm/server.cjs` શરૂ કરે છે                                       |
| સર્વર બંધ કરો              | ચાઇલ્ડ પ્રોસેસને સુવ્યવસ્થિત રીતે બંધ કરે છે                                        |
| સર્વર પુનઃપ્રારંભ કરો      | બંધ + શરૂ કરે છે (લક્ષ્યમાં થયેલા ફેરફારો લાગુ કરે છે)                              |
| પ્રમાણપત્ર વિશ્વસનીય બનાવો | `DATA_DIR/mitm/ca.crt`ને OS ટ્રસ્ટ સ્ટોરમાં ઇન્સ્ટોલ કરે છે                         |
| પ્રમાણપત્ર ડાઉનલોડ કરો     | મેન્યુઅલ ઇન્સ્ટોલેશન માટે `ca.crt` ડાઉનલોડ કરે છે                                   |
| પ્રમાણપત્ર ફરી બનાવો       | નવી CA કીપેર બનાવે છે (દરેક એજન્ટ માટેનાં હાલનાં તમામ પ્રમાણપત્રો અમાન્ય થઈ જાય છે) |

### 3.2 પ્રમાણપત્રને વિશ્વસનીય બનાવો

IDE દ્વારા MITM કનેક્શન સ્વીકારવામાં આવે તે પહેલાં AgentBridge CA પ્રમાણપત્ર OS માટે વિશ્વસનીય હોવું આવશ્યક છે.

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Keychain):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

અથવા ડેશબોર્ડમાં "પ્રમાણપત્ર વિશ્વસનીય બનાવો" બટનનો ઉપયોગ કરો (તે તમારા OS માટે યોગ્ય કમાન્ડ ચલાવે છે અને જરૂર પડે તો sudo પ્રોમ્પ્ટ દર્શાવે છે).

#### Electron-આધારિત IDE, OS ટ્રસ્ટ સ્ટોરને અવગણે છે (`NODE_EXTRA_CA_CERTS`)

કેટલાક IDE — ખાસ કરીને **Antigravity IDE** અને અન્ય Electron / VS Codeમાંથી બનાવેલી એપ્લિકેશનો — પોતાની
Node.js રનટાઇમ સાથે આવે છે, જે આઉટબાઉન્ડ `fetch`/HTTPS માટે **OS ટ્રસ્ટ સ્ટોરનો ઉપયોગ કરતી નથી**.
OS/NSS સ્તરે CAને વિશ્વસનીય બનાવવું IDEના મૂળ **બૅકએન્ડ** માટે પૂરતું છે
(દા.ત. Go લેંગ્વેજ સર્વર, જે OS CA બંડલનો ઉપયોગ કરે છે), પરંતુ **Electron ફ્રન્ટએન્ડમાં**
TLS હજી પણ નિષ્ફળ જશે — એપ્લિકેશન _લૉગ આઉટ થઈ ગઈ_ હોય અથવા _"કનેક્શન ભૂલ"_
દર્શાવતી હોય તે રીતે આ સમસ્યા દેખાય છે, ભલે MITM લૉગમાં બૅકએન્ડના બૂટસ્ટ્રૅપ કૉલ્સ `200` પરત કરતા દેખાય.
બે પગલાં જરૂરી છે અને બંને મહત્ત્વપૂર્ણ છે:

1. રનટાઇમને સ્પષ્ટ રીતે CA તરફ નિર્દેશિત કરો:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **તે જ શેલમાંથી IDE શરૂ કરો.** તેને ડેસ્કટૉપ આઇકન / Dock / Start મેનૂમાંથી શરૂ કરવાથી
   શેલ exports વારસામાં મળતા **નથી**, અને `~/.config/environment.d/*.conf` માત્ર
   નવા ગ્રાફિકલ લૉગિન પછી જ લાગુ પડે છે. પહેલાં IDEને સંપૂર્ણપણે બંધ કરો — Electronના સિંગલટન લૉકને કારણે બીજી વાર
   શરૂ કરવાથી ફક્ત હાલની પ્રોસેસ પર ફોકસ થાય છે અને નવા એન્વાયર્નમેન્ટને અવગણવામાં આવે છે.

ઉપરનું OS-trust + NSS પગલું હજી પણ જરૂરી છે (કેટલાક ઑથ
ફ્લોમાં વપરાતો Chromium નેટવર્ક સ્ટૅક પ્રતિ-વપરાશકર્તા NSS સ્ટોર વાંચે છે અને `*.googleapis.com` માટે તેના
પોતાના સ્થિર પિન હોય છે, જેને સ્થાનિક રીતે વિશ્વસનીય બનાવેલું CA ઓવરરાઇડ કરે છે). તેની સાથે `NODE_EXTRA_CA_CERTS`
Nodeના `fetch` પાથને આવરી લે છે.

### 3.3 DNS રૂટિંગ

તમે જે દરેક એજન્ટને ઇન્ટરસેપ્ટ કરવા માંગો છો, તેના API હોસ્ટ `127.0.0.1` પર રિઝૉલ્વ થવા આવશ્યક છે. જ્યારે તમે સેટઅપ વિઝાર્ડમાં કોઈ એજન્ટ માટે DNS ટૉગલ કરો છો, ત્યારે AgentBridge આપમેળે `/etc/hosts` એન્ટ્રીઓનું સંચાલન કરે છે.

GitHub Copilot માટે `/etc/hosts` એન્ટ્રીઓનું ઉદાહરણ:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 મોડલ મૅપિંગ

સ્રોત → લક્ષ્ય મૅપિંગ નિર્ધારિત કરવા માટે દરેક એજન્ટ કાર્ડમાં રહેલા મોડલ મૅપિંગ ટેબલનો ઉપયોગ કરો:

| સ્રોત મોડલ (એજન્ટનું મૂળ) | લક્ષ્ય મોડલ (OmniRoute) |
| ------------------------- | ----------------------- |
| `gpt-4o`                  | `claude-sonnet-4.7`     |
| `*` (વાઇલ્ડકાર્ડ)         | `claude-haiku-4.7`      |

વાઇલ્ડકાર્ડ `*` કોઈપણ અજાણ્યા મોડલને નિર્દિષ્ટ લક્ષ્ય સાથે મૅપ કરે છે. તે `agent_bridge_mappings` ટેબલમાં સાચવવામાં આવે છે.

> **ટિપ — એજન્ટના વાસ્તવિક મોડલ ID શોધો.** IDE એવા મોડલ નામો મોકલી શકે છે જે
> તેના UI લેબલથી અલગ હોય અને મુખ્ય વર્ઝન વચ્ચે બદલાતા હોય. ઉદાહરણ તરીકે, **Antigravity 2**
> નેટવર્ક પર `gemini-3.1-pro-low`, `gemini-pro-agent` અને `gemini-3.1-flash-lite` મોકલે છે —
> જૂના દસ્તાવેજોમાં દર્શાવેલું `gemini-2.5-pro` નહીં. કોઈ મેળ ખાતું મૅપિંગ સેટ કર્યા વિના એક ચૅટ મોકલો:
> MITM ચોક્કસ ઇનકમિંગ `model:` લૉગ કરે છે અને વિનંતીને પસાર થવા દે છે. તે શાબ્દિક મૂલ્યને મૅપ કરો,
> ત્યારબાદ આગામી વિનંતી ઇન્ટરસેપ્ટ થઈને તમારા લક્ષ્ય તરફ રૂટ થશે.

### 3.5 જોખમ અંગે સૂચના

AgentBridge એ ક્રેડેન્શિયલ્સ (OAuth ટોકન, API કી) ઇન્ટરસેપ્ટ કરે છે જેનો ઉપયોગ IDE અપસ્ટ્રીમ પ્રદાતાઓ સાથે પ્રમાણીકરણ કરવા માટે કરે છે. લૉગિંગ પહેલાં તેમને **માસ્ક કરવામાં આવે છે** (§2.7 જુઓ), પરંતુ તેઓ OmniRouteના MITM સ્તરને દૃશ્યમાન હોય છે. દરેક એજન્ટને પ્રથમ વખત સક્રિય કરતી વખતે બંધ કરી શકાય તેવી જોખમ સૂચના મોડલ દેખાય છે.

### 3.6 જાળવણી અને નિદાન

ડેશબોર્ડ એક **જાળવણી અને નિદાન** કાર્ડ (`AgentBridgeMaintenanceCard`, `src/app/(dashboard)/dashboard/tools/agent-bridge/components/`માં) પ્રદર્શિત કરે છે, જે અગાઉ UI વિનાના ઑપરેશનલ MITM રૂટ્સને ઉપલબ્ધ બનાવે છે. તેનું ઉપશીર્ષક: _"કૅપ્ચર પાઇપલાઇનનું સ્વ-પરીક્ષણ કરો, બાકી રહેલી સિસ્ટમ સ્થિતિને પૂર્વવત્ કરો અને તમારું સેટઅપ વિવિધ મશીનો વચ્ચે ખસેડો."_ કાર્ડના ક્લાયન્ટ હેલ્પર્સ `src/lib/inspector/agentBridgeMaintenanceApi.ts`માં આવેલા છે.

| **નિદાન**         | `GET /api/tools/agent-bridge/diagnose` | કૅપ્ચર-પાઇપલાઇનનું સ્વ-પરીક્ષણ ચલાવે છે અને દરેક ચકાસણી માટેનો અહેવાલ બતાવે છે (✓/✗ + ઉપાય માટેનો સંકેત).                                                                                              |
| **સમારકામ**       | `POST /api/tools/agent-bridge/repair`  | ક્રૅશ અથવા SIGKILL પછી રહી ગયેલી અનાથ MITM સિસ્ટમ સ્થિતિ (DNS સ્પૂફ એન્ટ્રીઓ, રૂટ CA, સિસ્ટમ પ્રૉક્સી) પૂર્વવત્ કરે છે. આઇડેમ્પોટન્ટ — સ્થિતિ સ્વચ્છ હોય ત્યારે "સમારકામ કરવા જેવું કંઈ નથી" જણાવે છે. |
| **CA દૂર કરો**    | `DELETE /api/tools/agent-bridge/cert`  | OS ટ્રસ્ટ સ્ટોરમાંથી MITM રૂટ CAનો વિશ્વાસ દૂર કરે છે અને તેને કાઢી નાખે છે (સ્પષ્ટ, આઇડેમ્પોટન્ટ). CA હાલમાં વિશ્વસનીય હોય ત્યારે જ બતાવવામાં આવે છે; ઇનલાઇન "CA દૂર કરવું છે?" પુષ્ટિ જરૂરી છે.      |
| **કૉન્ફિગ નિકાસ** | `GET /api/tools/agent-bridge/config`   | પોર્ટેબલ કૉન્ફિગ JSON ડાઉનલોડ કરે છે (§3.7 જુઓ).                                                                                                                                                       |
| **કૉન્ફિગ આયાત**  | `POST /api/tools/agent-bridge/config`  | અગાઉ નિકાસ કરેલું કૉન્ફિગ JSON અપલોડ કરે છે (§3.7 જુઓ).                                                                                                                                                |

**નિદાન ચકાસણીઓ** (`src/mitm/inspector/diagnostics.ts`માં `summarizeDiagnostics()`). રૂટ દરેક માટે પ્રભાવકારી પ્રોબ ચલાવે છે અને બુલિયન મૂલ્યોને શુદ્ધ સારાંશકારમાં મોકલે છે; એક `healthy` ચુકાદો તથા દરેક નિષ્ફળતા માટેનો સંકેત પરત મળે છે:

| ચકાસણીનું નામ      | તે શું ચકાસે છે                                           | નિષ્ફળતા વખતે સંકેત                                                                                                                                              |
| ------------------ | --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server-running`   | MITM સર્વર પ્રોસેસ સક્રિય છે                              | "MITM સર્વર ચાલી રહ્યું નથી. તેને AgentBridge ટૅબમાંથી શરૂ કરો."                                                                                                 |
| `server-reachable` | MITM સર્વર તેના પોર્ટ પર કનેક્શનો સ્વીકારે છે (TCP પ્રોબ) | "MITM સર્વર તેના પોર્ટ પર કનેક્શનો સ્વીકારતું નથી. તપાસો કે પોર્ટ ખાલી છે અને તેને બાઇન્ડ કરવા માટે તમારી પાસે વિશેષાધિકારો છે."                                 |
| `cert-exists`      | MITM પ્રમાણપત્ર ડિસ્ક પર જનરેટ કરવામાં આવ્યું છે          | "હજી સુધી કોઈ MITM પ્રમાણપત્ર જનરેટ થયું નથી. AgentBridge ટૅબમાંથી એક જનરેટ કરો."                                                                                |
| `cert-trusted`     | MITM રૂટ CA OS ટ્રસ્ટ સ્ટોરમાં છે                         | "MITM રૂટ CA પર OS સ્ટોર દ્વારા વિશ્વાસ કરવામાં આવતો નથી, તેથી TLS ઇન્ટરસેપ્શન નિષ્ફળ જશે. AgentBridge ટૅબમાંથી પ્રમાણપત્રને વિશ્વસનીય બનાવો."                   |
| `dns-configured`   | લક્ષ્ય હોસ્ટનામ `/etc/hosts`માં સ્પૂફ કરેલાં છે           | "લક્ષ્ય હોસ્ટનામ `/etc/hosts`માં સ્પૂફ કરેલાં નથી, તેથી ટ્રાફિક ક્યારેય પ્રૉક્સી સુધી પહોંચતો નથી. તમે જે એજન્ટને કૅપ્ચર કરવા માંગો છો તેના માટે DNS સક્ષમ કરો." |

**અનાથ-સ્થિતિ બૅનર:** જ્યારે પેજ ક્રૅશ પછી રહી ગયેલી સ્થિતિ (DNS સ્પૂફ / CA / સિસ્ટમ પ્રૉક્સી) શોધે છે, ત્યારે કાર્ડ એમ્બર રંગનું બૅનર બતાવે છે — _"પાછલા સત્રે સિસ્ટમ સ્થિતિ પાછળ છોડી છે (DNS સ્પૂફ, CA અથવા સિસ્ટમ પ્રૉક્સી). તેને સાફ કરવા માટે સમારકામ ચલાવો."_ — અને **સમારકામ** બટનને હાઇલાઇટ કરે છે. `Repair` એ ProxyBridgeના `--cleanup` ફ્લૅગનું ઍપ્લિકેશન-લેયર સમકક્ષ છે (તે `src/mitm/manager.ts`માં `repairMitm()`ને કાર્ય સોંપે છે).

> વારંવાર sudo પ્રૉમ્પ્ટ ટાળવા માટે MITM રૂટ CAને બંધ/શરૂ કર્યા પછી પણ ઇન્સ્ટૉલ રાખવામાં આવે છે
> (mitmproxy/Charles જેવું જ વર્તન), તેથી તેને દૂર કરવું એ બંધ કરતી વખતે આપમેળે થતી
> બાબતને બદલે સ્પષ્ટ **CA દૂર કરો** ક્રિયા છે.

### 3.7 પોર્ટેબલ કૉન્ફિગની આયાત/નિકાસ

AgentBridge **ઑપરેટર દ્વારા સમાયોજિત કરી શકાય તેવી** સ્થિતિને વર્ઝનવાળા JSON બ્લૉબમાં સીરિયલાઇઝ કરી શકે છે, જેથી સેટઅપને અનેક મશીનો પર પ્રતિકૃત કરી શકાય. સીરિયલાઇઝર `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`) છે, જેને `AgentBridgeConfigSchema` દ્વારા માન્ય કરવામાં આવે છે.

નિકાસમાં ચોક્કસ ત્રણ ભાગ સામેલ છે (બિલ્ટ-ઇન ડિફૉલ્ટ્સને ઇરાદાપૂર્વક નિકાસ કરવામાં **આવતાં નથી**, જેથી આયાત કરવાથી ક્યારેય તેમની નકલ ન બને કે તેમની સાથે સંઘર્ષ ન થાય):

| ફીલ્ડ            | સ્રોત                                                      | નોંધો                                                               |
| ---------------- | ---------------------------------------------------------- | ------------------------------------------------------------------- |
| `bypassPatterns` | વપરાશકર્તા-નિર્ધારિત બાયપાસ પેટર્ન (`agent_bridge_bypass`) | ડિફૉલ્ટ bank/gov/okta પેટર્ન બાકાત રાખવામાં આવે છે                  |
| `customHosts`    | Traffic Inspector કસ્ટમ હોસ્ટ (`inspector_custom_hosts`)   | દરેક: `{ host, kind: "llm"\|"app"\|"custom", label? }`              |
| `agentMappings`  | દરેક એજન્ટ માટેનાં મૉડલ મૅપિંગ (`agent_bridge_mappings`)   | મૅપિંગ ધરાવતા દરેક એજન્ટ માટે `{ [agentId]: [{ source, target }] }` |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**આયાતનું વર્તન** (`POST /api/tools/agent-bridge/config`): બાયપાસ પેટર્ન અને દરેક એજન્ટ માટેનાં મૅપિંગ **સંપૂર્ણપણે બદલી નાખે છે**; કસ્ટમ હોસ્ટને **આઇડેમ્પોટન્ટ રીતે** ઉમેરવામાં આવે છે (`INSERT OR IGNORE`). પ્રતિસાદ દરેકમાંથી કેટલાં લાગુ કરવામાં આવ્યાં તે જણાવે છે:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

કન્ફિગમાં શું **નથી**: સર્વર ચાલી રહ્યું છે કે નહીં તેની સ્થિતિ, સર્ટિફિકેટ પાથ, દરેક એજન્ટની DNS સ્થિતિ, અપસ્ટ્રીમ CA પાથ અને TPROXY સેટિંગ્સ — આ હોસ્ટ/રનટાઇમ સ્થિતિ છે, પોર્ટેબલ પસંદગીઓ નહીં.

### સંવેદનશીલ હોસ્ટ માટે બાયપાસ સૂચિ

બાયપાસ સૂચિ ખાતરી કરે છે કે નાણાકીય સંસ્થાઓ, OAuth/SSO પ્રદાતાઓ અને અન્ય સંવેદનશીલ હોસ્ટનું ડિક્રિપ્શન **ક્યારેય થતું નથી**. તેમનો TLS ટ્રાફિક પારદર્શક TCP ટનલ તરીકે પસાર થાય છે — OmniRoute ક્યારેય પ્લેઇનટેક્સ્ટ જોતું નથી.

ડિફૉલ્ટ બાયપાસ પેટર્નમાં આનો સમાવેશ થાય છે:

- `*.bank.*`, `*.gov.*` (નાણાકીય/સરકારી)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/ઓળખ)
- `*.apple.com`, `*.icloud.com` (Apple સિસ્ટમ સેવાઓ)

વપરાશકર્તા દ્વારા ઉમેરેલા બાયપાસ પેટર્ન `agent_bridge_bypass` કોષ્ટકમાં સંગ્રહિત થાય છે અને તેમને બધી જ વસ્તુઓ કરતાં પ્રાધાન્ય મળે છે.

### સિક્રેટ માસ્કિંગ

`src/mitm/maskSecrets.ts` માંથી `maskSecrets()` લાગુ કરવામાં આવે છે:

- `TrafficBuffer.push()` પહેલાં દરેક વિનંતી બોડી પર
- લૉગિંગ અથવા બ્રોડકાસ્ટિંગ પહેલાં દરેક હેડર પર

પેટર્ન: `sk-`/`ak-`/`pk-` પ્રીફિક્સ ધરાવતા ટોકન, `Bearer` ટોકન અને ≥40 અક્ષરના સામાન્ય ટોકન.

### અપસ્ટ્રીમ CA પ્રમાણપત્ર

જ્યારે `AGENTBRIDGE_UPSTREAM_CA_CERT` સેટ હોય છે, ત્યારે સ્ટાર્ટઅપ સમયે ફાઇલ વાંચવામાં આવે છે. જો પાથ અસ્તિત્વમાં હોય પરંતુ ફાઇલ વાંચી શકાય તેવી ન હોય, તો AgentBridge સ્પષ્ટ ભૂલ લૉગ કરે છે અને શરૂ થવાનો ઇનકાર કરે છે (કોર્પોરેટ વાતાવરણમાં નિઃશબ્દ TLS નિષ્ફળતાઓ અટકાવે છે).

### જાણીતી મર્યાદાઓ

- **પોર્ટ 443 માટે વિશેષાધિકાર જરૂરી છે**: Linux પર, AgentBridge ને Node બાઇનરી પર `setcap 'cap_net_bind_service=+ep'` જરૂરી છે અથવા તેને `authbind` દ્વારા ચલાવવું પડે છે. સેટઅપ વિઝાર્ડ OS-વિશિષ્ટ સૂચનાઓ દર્શાવે છે.
- **IDE પુનઃપ્રારંભ જરૂરી છે**: DNS રીડાયરેક્ટ પછી, નવા હોસ્ટ રિઝોલ્યુશનને અસરકારક બનાવવા IDE ને પુનઃપ્રારંભ કરવું જરૂરી છે.
- **હાર્ડકોડ કરેલા OAuth ટોકન**: કેટલાક એજન્ટ (Kiro, Antigravity) OAuth રિફ્રેશ ટોકન સ્થાનિક રીતે સંગ્રહે છે. આ AgentBridge માટે પારદર્શક છે — તે દરેક વિનંતીમાં Bearer ટોકન જુએ છે, જેને લૉગિંગ પહેલાં માસ્ક કરવામાં આવે છે.
- **Electron ફ્રન્ટએન્ડને `NODE_EXTRA_CA_CERTS` જરૂરી છે**: જે IDE ના ફ્રન્ટએન્ડ બંડલ કરેલા Node/Electron રનટાઇમ પર ચાલે છે તે OS/NSS ટ્રસ્ટ સ્ટોરને અવગણે છે અને તેને `NODE_EXTRA_CA_CERTS` સેટ કરેલા શેલમાંથી લોન્ચ કરવું જરૂરી છે (§3.2 જુઓ). તે ન હોય ત્યારે લક્ષણ: IDE બેકએન્ડ પ્રમાણીકરણ કરે છે (MITM `200` દર્શાવે છે) પરંતુ UI લૉગ આઉટ જ રહે છે.
- **એક જ IDE ના બહુવિધ ઇન્સ્ટોલ સ્વતંત્ર હોય છે**: સિસ્ટમ ઇન્સ્ટોલ (દા.ત. `/usr/share/antigravity/antigravity`) અને વપરાશકર્તા-સ્થાનિક "Full" ઇન્સ્ટોલ (દા.ત. `~/AntigravityIDE_Full/antigravity-ide`) તેમની પોતાની રનટાઇમ ધરાવતી અલગ પ્રક્રિયાઓ છે — દરેકને CA ઇન્જેક્ટ કરીને ફરીથી લોન્ચ કરવું જરૂરી છે. ફરીથી લોન્ચ કરતાં પહેલાં કયું ચાલી રહ્યું છે તે તેના બાઇનરી પાથ દ્વારા ઓળખો.
- **ઓળખ રૂટ કરાયેલા મોડલથી નહીં, પરંતુ એજન્ટના સિસ્ટમ પ્રોમ્પ્ટથી નક્કી થાય છે**: જ્યારે તમે એજન્ટના મોડલને અલગ પ્રદાતા સાથે ફરીથી મેપ કરો છો, ત્યારે પણ જવાબ એજન્ટની મૂળ ઓળખનો દાવો કરે છે (દા.ત. Antigravity જવાબ આપે છે કે "હું Gemini દ્વારા સંચાલિત છું"), કારણ કે IDE તેને સિસ્ટમ પ્રોમ્પ્ટમાં ઇન્જેક્ટ કરે છે. મોડલને તેની ઓળખ પૂછવાને બદલે `call_logs` / `proxy_logs` (`provider`, `model`, `target_format`) માં વાસ્તવિક બેકએન્ડની પુષ્ટિ કરો.

## §6 સમસ્યાનિવારણ

### પોર્ટ 443 નો સંઘર્ષ

જો બીજી કોઈ પ્રક્રિયા પહેલેથી જ પોર્ટ 443 પર સાંભળી રહી હોય (વેબ સર્વર, VPN, વગેરે):

```bash
lsof -i :443          # પ્રક્રિયા શોધો
sudo fuser -k 443/tcp  # બળજબરીથી બંધ કરો (સાવધાનીપૂર્વક ઉપયોગ કરો)
```

વૈકલ્પિક રીતે, AgentBridge સેટિંગ્સમાં બિન-વિશેષાધિકૃત પોર્ટ ગોઠવો અને `iptables` / `pf` રીડાયરેક્ટ નિયમો સેટ કરો.

### પ્રમાણપત્ર વિશ્વસનીય નથી

AgentBridge શરૂ કર્યા પછી જો IDE TLS ભૂલો બતાવે:

1. પ્રમાણપત્ર ઇન્સ્ટૉલ થયું છે કે નહીં તે ચકાસો: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) અથવા `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. કેટલીક ઍપ્સ પોતાનો ટ્રસ્ટ સ્ટોર જાળવે છે (Firefox, Linux પર Chrome). "Trust Cert" ફરીથી ચલાવો અને NSS/Firefox-વિશિષ્ટ પ્રમાણપત્ર સ્ટોર તપાસો.
3. વિશ્વસનીય બનાવ્યા પછી IDE પુનઃપ્રારંભ કરો — ચાલુ TLS સત્રો જૂની ટ્રસ્ટ સ્થિતિનો ઉપયોગ કરે છે.

### વિશ્વસનીય CA હોવા છતાં IDE માંથી લૉગ આઉટ / "connection error"

લક્ષણ: DNS રીડાયરેક્ટ કર્યા અને CA ને વિશ્વસનીય બનાવ્યા પછી, Electron-આધારિત IDE (દા.ત. Antigravity)
**લૉગ આઉટ થયેલું** ખૂલે છે અથવા પ્રમાણીકરણ/કનેક્શન ભૂલ બતાવે છે, તેમ છતાં MITM લૉગમાં
બૂટસ્ટ્રૅપ કૉલ્સ (`loadCodeAssist`, `fetchAvailableModels`, …) `200` પરત કરતા દેખાય છે.

કારણ: IDE નું **બંડલ કરેલું Node/Electron રનટાઇમ OS ટ્રસ્ટ સ્ટોરને અવગણે છે**. નેટિવ
બૅકએન્ડ (Go લેંગ્વેજ સર્વર) OS CA પર વિશ્વાસ કરે છે અને પ્રમાણીકરણ કરે છે, પરંતુ Electron ફ્રન્ટએન્ડ
એવું કરતું નથી — તેથી UI એવું માને છે કે તે ઑફલાઇન છે.

ઉકેલ (બંને પગલાં): `NODE_EXTRA_CA_CERTS=<ca.crt>` એક્સપોર્ટ કરો **અને તે જ શેલમાંથી IDE ફરીથી
લૉન્ચ કરો**, ડેસ્કટૉપ આઇકનમાંથી નહીં. પહેલાં IDE સંપૂર્ણપણે બંધ કરો — Electron ના સિંગલટન લૉકનો અર્થ એ છે કે
બીજી વાર લૉન્ચ કરવાથી માત્ર હાલની પ્રક્રિયા પર ફોકસ થાય છે અને નવા એન્વાયર્નમેન્ટને અવગણવામાં આવે છે. §3.2 જુઓ.
આ એક ખુલ્લા અપસ્ટ્રીમ અહેવાલને અનુરૂપ છે, જેમાં સ્વતંત્ર એજન્ટ MITM મારફતે કાર્ય કરે છે પરંતુ IDE
વેરિઅન્ટ સમાન સેટઅપ હેઠળ નિષ્ફળ જાય છે.

### DNS પ્રસારિત થયું નથી

`/etc/hosts` અપડેટ થયું છે કે નહીં તે તપાસો:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

DNS કૅશ ફ્લશ કરો:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### IDE શોધાયું નથી

સ્વતઃ-શોધ સામાન્ય ઇન્સ્ટૉલેશન પાથ્સનો ઉપયોગ કરે છે. જો શોધ નિષ્ફળ જાય પરંતુ IDE ઇન્સ્ટૉલ કરેલું હોય:

- IDE બાઇનરી બિન-માનક સ્થાન પર છે કે નહીં તે તપાસો
- Setup Wizard હજી પણ કાર્ય કરે છે — શોધની નિષ્ફળતાનો અર્થ માત્ર એટલો છે કે બૅજ ઇન્સ્ટૉલેશન પાથ બતાવશે નહીં

### હૅન્ડલર ભૂલો (અપસ્ટ્રીમ ફેચ નિષ્ફળ જાય છે)

જો AgentBridge ઇન્ટરસેપ્ટ કરે પરંતુ બધી વિનંતીઓ નિષ્ફળ જાય:

1. `/dashboard/providers` પર ઓછામાં ઓછું એક પ્રદાતા જોડાયેલું છે કે નહીં તે ચકાસો
2. OmniRoute સર્વર લૉગ્સ તપાસો: `.env` માં `APP_LOG_LEVEL=debug`
3. `OMNIROUTE_BASE_URL` યોગ્ય રાઉટર એન્ડપોઇન્ટ તરફ નિર્દેશ કરે છે કે નહીં તે ચકાસો (ડિફૉલ્ટ: `http://127.0.0.1:20128`)

## §8 રોડમેપ

### Trae તપાસ

Trae પ્રમાણમાં નવું AI કોડિંગ સહાયક છે. હૅન્ડલર અમલમાં મૂકતા પહેલાં:

1. VS Code / JetBrains માર્કેટપ્લેસમાં અથવા સ્વતંત્ર ઍપ તરીકે બાઇનરી/એક્સ્ટેન્શન ઓળખો
2. API હોસ્ટ્સ અને એન્ડપોઇન્ટની રચનાઓ શોધવા માટે mitmproxy વડે ટ્રાફિક કૅપ્ચર કરો
3. પ્રમાણીકરણ પદ્ધતિ નક્કી કરો
4. TOS અને API શોધક્ષમતાના આધારે આગળ વધવું કે નહીં તેનું મૂલ્યાંકન કરો

તપાસ પૂર્ણ ન થાય ત્યાં સુધી, ડૅશબોર્ડમાં Trae કાર્ડ પર "તપાસ ચાલુ છે" બૅજ અને "વ્યવહાર્યતાનો અહેવાલ આપો" લિંક દેખાય છે. `src/mitm/handlers/trae.ts` પરનો હૅન્ડલર સ્ટબ સંરચિત `હજુ સુધી અમલમાં મૂકાયું નથી` ભૂલ ફેંકે છે.

### બૅકલૉગ એજન્ટ્સ (MITM આવશ્યક — કસ્ટમ બેઝ URL સપોર્ટ નથી)

નીચેના ટૂલ્સના વર્તમાન વર્ઝનમાં તેઓ કસ્ટમ બેઝ URL ને સપોર્ટ કરતા નથી, જેના કારણે MITM જ ઇન્ટરસેપ્શનનો એકમાત્ર માર્ગ રહે છે. વ્યવહાર્યતાનું મૂલ્યાંકન બાકી છે:

- **Windsurf** (Codeium/Cognition)
- **Amp** (Sourcegraph)
- **Amazon Q / Kiro CLI** (AWS Bedrock — Kiro IDE થી અલગ)
- **Cowork** (Anthropic ડેસ્કટૉપ)

નોંધ: GitHub Copilot CLI ≥v1.0.19 `COPILOT_PROVIDER_BASE_URL` ને સપોર્ટ કરે છે — તે ટૂલ માટે MITM ને બદલે સીધા કૉન્ફિગનો ઉપયોગ કરો.
