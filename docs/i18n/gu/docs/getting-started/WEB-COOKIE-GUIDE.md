Web Cookie પ્રદાતાઓ OmniRoute ને API key ના બદલે તમારા હાલના બ્રાઉઝર સેશન દ્વારા AI સેવાનો ઉપયોગ કરવાની મંજૂરી આપે છે. જ્યારે તમારી પાસે પહેલેથી જ કોઈ સેવાની વેબસાઇટ દ્વારા ઍક્સેસ હોય અને તમે ઇચ્છતા હો કે OmniRoute એ જ પ્રમાણિત સેશનનો ઉપયોગ કરે, ત્યારે તેઓ ઉપયોગી છે.

API-key પ્રદાતાઓથી વિપરીત, Web Cookie પ્રદાતાઓ વેબસાઇટને તમારું બ્રાઉઝર મોકલે છે તે ઓળખપત્રોનો ઉપયોગ કરીને પ્રમાણિત કરે છે.

# શરૂ કરતા પહેલાં

> **મહત્વપૂર્ણ:** ઓળખપત્રો હંમેશાં **લાઇવ નેટવર્ક રિક્વેસ્ટ**માંથી કૉપિ કરો, તમારા બ્રાઉઝરના કૂકી સ્ટોરેજમાંથી **નહીં**.

ખોટી જગ્યાએથી કૂકીઝ કૉપિ કરવાને કારણે પ્રમાણીકરણની ઘણી સમસ્યાઓ સર્જાય છે.

## Cookie Storageમાંથી કૉપિ કરશો નહીં

મોટાભાગનાં બ્રાઉઝર્સ સંગ્રહિત કૂકીઝને નીચેના માર્ગે દર્શાવે છે:

```
DevTools
→ Application (અથવા Storage)
→ Cookies
```

આ કૂકીઝ સાચી દેખાતી હોવા છતાં, તે કદાચ:

- જૂની હોઈ શકે
- અધૂરી હોઈ શકે
- માત્ર પ્રમાણિત રિક્વેસ્ટ્સ સાથે મોકલાતી કૂકીઝ તેમાં ન હોઈ શકે

આ મૂલ્યો માન્ય દેખાતા હોવા છતાં, તેમનો ઉપયોગ કરવાથી પ્રમાણીકરણ નિષ્ફળ થઈ શકે છે.

## લાઇવ રિક્વેસ્ટમાંથી કૉપિ કરો

તેના બદલે, સફળ રિક્વેસ્ટમાંથી કૂકીઝનો ઉપયોગ કરો:

```
DevTools
→ Network
→ પેજને રિફ્રેશ કરો
→ ચેટ અથવા વાર્તાલાપ રિક્વેસ્ટ ખોલો
→ Request Headers
→ Cookie
```

`Cookie` રિક્વેસ્ટ હેડરમાં તમારા બ્રાઉઝરે સફળતાપૂર્વક ઉપયોગ કરેલી ચોક્કસ પ્રમાણીકરણ માહિતી હોય છે.

મોટાભાગના Web Cookie પ્રદાતાઓ માટે, આ જ મૂલ્ય OmniRoute માં પેસ્ટ કરવું જોઈએ.

# સામાન્ય સેટઅપ

મોટાભાગના Web Cookie પ્રદાતાઓ માટે સેટઅપ પ્રક્રિયા સમાન છે.

1. પ્રદાતાની વેબસાઇટમાં સાઇન ઇન કરો.
2. બ્રાઉઝરના Developer Tools ખોલો.
3. **Network** ટૅબ ખોલો.
4. પેજને રિફ્રેશ કરો.
5. પ્રમાણિત ચેટ અથવા વાર્તાલાપ રિક્વેસ્ટ ખોલો.
6. જરૂરી પ્રમાણીકરણ ઓળખપત્રો કૉપિ કરો.
7. OmniRoute ખોલો.
8. **Providers → Add Provider** પર જાઓ.
9. તમારો Web Cookie પ્રદાતા પસંદ કરો.
10. ઓળખપત્રો પેસ્ટ કરો.
11. **Test Connection** પર ક્લિક કરો.
12. પ્રદાતાને સાચવો.

જરૂરી ચોક્કસ ઓળખપત્રો પ્રદાતા પર આધાર રાખે છે.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) એક મફત ગ્રાહક ચેટ પ્લેટફોર્મ છે, જેમાં સાઇન અપ કરવાની જરૂર નથી — પ્રથમ મુલાકાત વખતે સત્ર અનામી રીતે બનાવવામાં આવે છે અને તે ત્રણ કૂકીઝ દ્વારા જળવાઈ રહે છે: `uid`, `si_usr_id`, અને `si_ses_id`. OmniRoute એક જ મોડેલ id (`notrack-c`, ઉપનામ `ntw`) દ્વારા સમાન `/api/dispatch` એન્ડપોઇન્ટને પ્રૉક્સી કરે છે.

### કનેક્ટ કરવાનાં પગલાં

1. તમારા બ્રાઉઝરમાં [notrack.ai](https://notrack.ai) ખોલો અને અનામી સત્ર કૂકી સેટ થવા દો.
2. **DevTools → Network** ખોલો, પેજ રિફ્રેશ કરો અને કોઈપણ `/api` વિનંતી પર ક્લિક કરો.
3. **Request Headers** માં, સંપૂર્ણ `Cookie` હેડર મૂલ્ય કૉપિ કરો.
4. OmniRoute માં, **Providers → Add Provider → NoTrack Web (Free)** પર જાઓ.
5. કૂકી સ્ટ્રિંગને `apiKey` ફીલ્ડમાં પેસ્ટ કરો અને **Save** કરો.

OmniRoute પેસ્ટ કરેલી સ્ટ્રિંગમાંથી `uid`, `si_usr_id`, અને `si_ses_id` કાઢે છે અને માત્ર તે જ જોડીઓ સાથે સ્વચ્છ `Cookie` હેડર ફરીથી બનાવે છે — ઉપરાંત, જો હાજર હોય તો `nt_session` (લૉગ-ઇન કરેલા એકાઉન્ટ્સ માટે સેટ કરાયેલ `ntk_…` ટોકન) પણ ઉમેરે છે. જો ત્રણમાંથી કોઈપણ એક ગેરહાજર હોય, તો કાચી પેસ્ટ કરેલી સ્ટ્રિંગ કોઈ ફેરફાર વિના ફોરવર્ડ કરવામાં આવે છે, જેથી ઑપરેટરો વૈકલ્પિક બંધારણો સાથે પ્રયોગ કરી શકે.

### મોડેલ ids

| મોડેલ id    | પ્રદર્શિત નામ | નોંધો                                                   |
| ----------- | ------------- | ------------------------------------------------------- |
| `notrack-c` | NoTrack C     | ડિફૉલ્ટ — અપસ્ટ્રીમ ડિસ્પેચ મોડેલ `C`.                  |
| `C`         | NoTrack C     | `notrack-c` માટેનું ઉપનામ (કાચો અપસ્ટ્રીમ ડિસ્પેચ કોડ). |
| `notrack`   | NoTrack C     | `notrack-c` માટેનું ઉપનામ.                              |
| `ntw`       | NoTrack C     | `notrack-c` માટેનું ટૂંકું ઉપનામ.                       |

ચારેય મોડેલ ids સમાન અપસ્ટ્રીમ ડિસ્પેચ મોડેલ (`C`) સાથે મેપ થાય છે.

### વિનંતીના વિકલ્પો

એક્ઝિક્યુટર વિનંતીના બોડીમાં આ વૈકલ્પિક ફીલ્ડ્સ સ્વીકારે છે:

| બોડી ફીલ્ડ            | ડિફૉલ્ટ | હેતુ                                                                       |
| --------------------- | ------- | -------------------------------------------------------------------------- |
| `notrack_mode`        | `usual` | ડિસ્પેચ મોડ (મુક્ત-સ્વરૂપ સ્ટ્રિંગ; અપસ્ટ્રીમ `usual`, … સ્વીકારે છે)      |
| `notrack_max_turns`   | `6`     | જવાબ આપતા પહેલાં અપસ્ટ્રીમ લઈ શકે તેવા આંતરિક ટર્ન્સની સંખ્યા.             |
| `notrack_chat_id`     | `null`  | હાલની અપસ્ટ્રીમ ચેટ ફરી શરૂ કરો (નવી ચેટ માટે તેને છોડી દો).               |
| `notrack_attachments` | `[]`    | અપસ્ટ્રીમ અટૅચમેન્ટ ડિસ્ક્રિપ્ટર્સની પાસ-થ્રૂ એરે.                         |
| `notrack_regenerate`  | `false` | અગાઉના ટર્ન માટે પુનઃજનરેટ કરેલો જવાબ મેળવવાની વિનંતી કરવા `true` સેટ કરો. |

### ક્ષમતાઓ

- **સ્ટ્રીમિંગ અને નૉન-સ્ટ્રીમિંગ** ચેટ કમ્પ્લીશન્સ.
- **ટૂલ કૉલિંગ** — વિનંતીમાં `tools: [...]` સેટ કરો; એક્ઝિક્યુટર તેમને ટૂલ-કૉલ એન્વલપ કોન્ટ્રાક્ટમાં સિરિયલાઇઝ કરે છે અને મોડેલના પ્રતિસાદોને પાછા OpenAI `tool_calls` માં પાર્સ કરે છે.
- **`response_format`** — `json_object` અને `json_schema` સપોર્ટેડ છે. એક્ઝિક્યુટર મોડેલના જવાબમાંથી પ્રથમ JSON ઑબ્જેક્ટ કાઢે છે અને પરત કરતાં પહેલાં તેને સ્ટ્રિંગિફાય કરે છે.
- **રિઝનિંગ સંકેત** — જ્યારે અપસ્ટ્રીમ `thinking` ઇવેન્ટ મોકલે છે ત્યારે એક્ઝિક્યુટર `reasoning` ડેલ્ટા ઉત્સર્જિત કરે છે.

### મર્યાદાઓ

- અપસ્ટ્રીમ અનામી વપરાશ ક્વોટા લાગુ કરે છે — તે મર્યાદા વટાવાય ત્યારે, એક્ઝિક્યુટર મૈત્રીપૂર્ણ સંદેશ સાથે 429 દર્શાવે છે.
- બધા મોડેલ ids સમાન અપસ્ટ્રીમ ડિસ્પેચ મોડેલમાં રિઝોલ્વ થાય છે; દરેક મોડેલ માટે અલગ સ્વિચ ઉપલબ્ધ નથી.
- એક્ઝિક્યુટર અપસ્ટ્રીમના `/api/chats` એન્ડપોઇન્ટને કૉલ કરતું નથી, તેથી ચેટ ઇતિહાસ / સત્રો આપમેળે સંચાલિત થતા નથી. હાલની અપસ્ટ્રીમ ચેટ ફરી શરૂ કરવા માટે `notrack_chat_id` નો ઉપયોગ કરો.

# વેબ કૂકી પ્રદાતાઓ શું કરી શકે અને શું ન કરી શકે

વેબ કૂકી પ્રદાતાઓ વેબસાઇટના ચેટ ઇન્ટરફેસનો ફરી ઉપયોગ કરે છે. તેઓ અધિકૃત APIs જેવી સમાન ક્ષમતાઓ **પ્રદાન કરતા નથી**.

## સમર્થિત

- તમારા હાલના બ્રાઉઝર સત્રનો ઉપયોગ કરીને પ્રમાણીકરણ
- તમારા એકાઉન્ટ દ્વારા ઉપલબ્ધ મોડલ્સને ઍક્સેસ કરવા
- ચેટ પ્રતિસાદોને સ્ટ્રીમ કરવા
- API કી જરૂરી નથી

## અસમર્થિત

- ફંક્શન કૉલિંગ
- ટૂલ કૉલિંગ
- સ્વચાલિત ફાઇલ સંપાદન
- એજન્ટિક IDE વર્કફ્લો
- ફક્ત-API સુવિધાઓ

આ અપેક્ષિત વર્તણૂક છે અને તે **બગ નથી**.

જો તમને ટૂલ એક્ઝિક્યુશન, સ્વચાલિત ફાઇલ સંપાદન અથવા અન્ય એજન્ટ વર્કફ્લોની જરૂર હોય, તો Web Cookie પ્રદાતાને બદલે **API-key provider** નો ઉપયોગ કરો.

# માન્યતા ચકાસણીની મર્યાદા

સફળ **Test Connection** અથવા કૂકી માન્યતા ચકાસણી માત્ર એટલું જ ચકાસે છે કે આપેલાં ઓળખપત્રો અપેક્ષિત ફોર્મેટમાં હોવાનું જણાય છે.

Issue #7857 ઉકેલાય નહીં ત્યાં સુધી, સફળ માન્યતા ચકાસણીથી પ્રદાતા સફળતાપૂર્વક પ્રમાણીકરણ કરશે તેની **ખાતરી મળતી નથી**.

જો પ્રમાણીકરણ હજી પણ નિષ્ફળ જાય, તો ખાતરી કરો કે તમે ઓળખપત્રો બ્રાઉઝરની કૂકી સ્ટોરેજમાંથી નહીં, પરંતુ સક્રિય નેટવર્ક વિનંતીમાંથી કૉપિ કર્યાં છે.

---

# સમસ્યાનિવારણ

## પ્રમાણીકરણ નિષ્ફળ જાય છે

ખાતરી કરો કે ઓળખપત્રો અહીંથી કૉપિ કરવામાં આવ્યાં હતાં:

```
Network
→ Request Headers
→ Cookie
```

અને અહીંથી **નહીં**:

```
Application
→ Cookies
```

---

## કૂકી બ્રાઉઝરમાં કાર્ય કરે છે પરંતુ OmniRoute માં નહીં

કેટલાક પ્રદાતાઓ એવી કૂકીઝનો સમાવેશ કરે છે જે માત્ર પ્રમાણિત વિનંતીઓ દરમિયાન જ મોકલવામાં આવે છે.

વાતચીત સફળતાપૂર્વક ખોલ્યા પછી નવી નેટવર્ક વિનંતીમાંથી ઓળખપત્રો ફરીથી કૉપિ કરો.

---

## સત્રની મુદત સમાપ્ત થઈ

Web Cookie પ્રદાતાઓ તમારા હાલના બ્રાઉઝર સત્રનો ઉપયોગ કરે છે.

જો તમારા બ્રાઉઝર સત્રની મુદત સમાપ્ત થાય અથવા તમે સાઇન આઉટ કરો, તો તમારે ઓળખપત્રોનો નવો સમૂહ કૉપિ કરવો પડશે. સમર્થિત વેબ પ્રદાતાઓ માટે કૂકી નવીનીકરણ સ્વચાલિત કરવા, સહાયક ટૂલ [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md) જુઓ.

# શ્રેષ્ઠ પ્રથાઓ

- નવી પ્રમાણિત વિનંતીમાંથી ઓળખપત્રો કૉપિ કરો.
- જૂની કૂકીઝનો ફરીથી ઉપયોગ કરવાનું ટાળો.
- Web Cookie પ્રદાતાઓનો ઉપયોગ કરતી વખતે તમારું બ્રાઉઝર સત્ર સક્રિય રાખો.
- કૉપિ કરેલી કૂકીઝને સંવેદનશીલ ઓળખપત્રો તરીકે ગણો.
- જ્યારે તમને ફંક્શન કૉલિંગ અથવા એજન્ટ વર્કફ્લોની જરૂર હોય ત્યારે API-key providers નો ઉપયોગ કરો.
