> **TL;DR**: તમારા મોડેલને `auto` પર સેટ કરો અને OmniRoute દરેક વિનંતી માટે આપમેળે શ્રેષ્ઠ AI પ્રદાતા પસંદ કરશે. કોઈ રૂપરેખાંકનની જરૂર નથી.

---

## તે શું કરે છે

કોઈ ચોક્કસ AI મોડેલ (જેમ કે GPT-4o અથવા Claude) પસંદ કરવાને બદલે, તમે OmniRouteને દરેક વિનંતી માટે **આપમેળે શ્રેષ્ઠ મોડેલ પસંદ કરવા** દઈ શકો છો. તે આ બાબતો ધ્યાનમાં લે છે:

- **કાર્યક્ષમતા** — શું પ્રદાતા અત્યારે કાર્યરત છે?
- **ઝડપ** — તે કેટલું ઝડપી છે?
- **ખર્ચ** — તેનો ખર્ચ કેટલો છે?
- **ગુણવત્તા** — શું તે આ પ્રકારના કાર્ય માટે સારું છે?
- **ક્ષમતા** — શું તેનો ક્વોટા બાકી છે?

OmniRoute તમારા બધા કનેક્ટેડ પ્રદાતાઓને સ્કોર આપે છે અને શ્રેષ્ઠ પ્રદાતા પસંદ કરે છે. જો તે નિષ્ફળ જાય, તો તે આપમેળે આગળના પ્રદાતાનો પ્રયાસ કરે છે.

## ઝડપી શરૂઆત

**પગલું 1**: તમારા IDE અથવા CLIમાં તમારા મોડેલને `auto` પર સેટ કરો:

```
model: "auto"
```

**પગલું 2**: બસ એટલું જ! બાકીનું બધું OmniRoute સંભાળે છે.

**પગલું 3** (વૈકલ્પિક): ચોક્કસ કાર્યો માટે વેરિઅન્ટનો ઉપયોગ કરો:

```
model: "auto/coding"    # કોડ માટે શ્રેષ્ઠ
model: "auto/fast"      # સૌથી ઝડપી પ્રતિસાદ
model: "auto/cheap"     # સૌથી સસ્તો વિકલ્પ
```

## મારે કયું "auto" વાપરવું જોઈએ?

| જો તમે ઇચ્છો છો...     | આનો ઉપયોગ કરો  | આ માટે શ્રેષ્ઠ             | તે કેવી રીતે કાર્ય કરે છે                      |
| ---------------------- | -------------- | -------------------------- | ---------------------------------------------- |
| **એકંદરે શ્રેષ્ઠ**     | `auto`         | સામાન્ય પ્રશ્નો, ચેટ       | ઝડપ, ખર્ચ અને ગુણવત્તાનું સંતુલન જાળવે છે      |
| **કોડ માટે શ્રેષ્ઠ**   | `auto/coding`  | કોડ લખવો, ડિબગિંગ          | કોડિંગ કાર્યોમાં સારા મોડેલો પસંદ કરે છે       |
| **સૌથી ઝડપી પ્રતિસાદ** | `auto/fast`    | ઝડપી જવાબો, ઓછી લેટન્સી    | બાકીની દરેક બાબત કરતાં ઝડપને પ્રાથમિકતા આપે છે |
| **સૌથી સસ્તો વિકલ્પ**  | `auto/cheap`   | નાણાં બચાવવા               | સૌથી સસ્તો પ્રદાતા પસંદ કરે છે                 |
| **સૌથી સ્માર્ટ મોડેલ** | `auto/smart`   | જટિલ કાર્યો                | ગુણવત્તા-પ્રથમ + નવા મોડેલો અજમાવે છે          |
| **સૌથી વધુ ઉપલબ્ધ**    | `auto/offline` | જ્યારે પ્રદાતાઓ વ્યસ્ત હોય | સૌથી વધુ ક્ષમતા ધરાવતા પ્રદાતાઓ પસંદ કરે છે    |

## તે કેવી રીતે કાર્ય કરે છે (સરળ આવૃત્તિ)

જ્યારે તમે `model: "auto"` સાથે વિનંતી મોકલો છો, ત્યારે OmniRoute:

1. **તમારા બધા કનેક્ટેડ પ્રદાતાઓને જુએ છે** — તમે ઉમેરેલા દરેક પ્રદાતા (OpenAI, Anthropic, Google વગેરે)
2. **દરેકને સ્કોર આપે છે**, જેમાં અન્ય બાબતોની સાથે આ બાબતોને પણ મહત્ત્વ આપવામાં આવે છે:
   - શું તે કાર્યરત છે? (કાર્યક્ષમતા)
   - શું તેની પાસે ક્ષમતા છે? (ક્વોટા)
   - તેનો ખર્ચ કેટલો છે? (કિંમત)
   - તે કેટલું ઝડપી છે? (ઝડપ)
   - શું તે આ કાર્યમાં સારું છે? (ગુણવત્તા)
3. **શ્રેષ્ઠ પ્રદાતા પસંદ કરે છે** — સૌથી વધુ સ્કોર ધરાવતા પ્રદાતાને તમારી વિનંતી મળે છે
4. **આપમેળે પુનઃપ્રાપ્ત થાય છે** — જો તે નિષ્ફળ જાય, તો OmniRoute આપમેળે આગળના પ્રદાતાનો પ્રયાસ કરે છે

### સ્કોરિંગ સિસ્ટમ

દરેક પ્રદાતાને 0થી 1 સુધીનો સ્કોર મળે છે. સ્કોર જેટલો ઊંચો, તે તેટલો વધુ યોગ્ય.

| પરિબળ              | વજન | તેનો અર્થ                                        |
| ------------------ | --- | ------------------------------------------------ |
| કાર્યક્ષમતા        | 20% | શું પ્રદાતા કાર્યરત છે? (સર્કિટ બ્રેકરની સ્થિતિ) |
| ક્વોટા             | 15% | શું તેની ક્ષમતા બાકી છે?                         |
| ખર્ચ               | 15% | તે કેટલું ખર્ચાળ છે? (સસ્તું = વધુ સ્કોર)        |
| ઝડપ                | 12% | તે કેટલું ઝડપી છે? (ઓછી લેટન્સી = વધુ સ્કોર)     |
| કાર્ય માટે યોગ્યતા | 8%  | શું તે આ પ્રકારના કાર્ય માટે સારું છે?           |
| સ્થિરતા            | 5%  | શું તે સુસંગત છે? (ઓછો ભૂલ દર)                   |
| સ્તર               | 5%  | એકાઉન્ટ સ્તર (Ultra > Pro > Free)                |
| અન્ય               | 20% | સંદર્ભ અનુરૂપતા, કનેક્શનની ઘનતા વગેરે            |

### વેરિઅન્ટ્સ સ્કોરિંગને કેવી રીતે બદલે છે

દરેક વેરિઅન્ટ અલગ વજનનો ઉપયોગ કરે છે:

| વેરિઅન્ટ       | પ્રાથમિકતા આપે છે  | મુખ્ય વજનો                            |
| -------------- | ------------------ | ------------------------------------- |
| `auto`         | સંતુલન             | કાર્યક્ષમતા=20%, ક્વોટા=15%, ખર્ચ=15% |
| `auto/coding`  | ગુણવત્તા           | કાર્ય માટે યોગ્યતા=37%, સ્થિરતા=15%   |
| `auto/fast`    | ઝડપ                | લેટન્સી=32%, કાર્યક્ષમતા=28%          |
| `auto/cheap`   | ખર્ચ               | ખર્ચ=37%                              |
| `auto/smart`   | ગુણવત્તા + અન્વેષણ | કાર્ય માટે યોગ્યતા=37%, અન્વેષણ=10%   |
| `auto/offline` | ક્ષમતા             | ક્વોટા=37%, કાર્યક્ષમતા=28%           |

## તે નિષ્ફળતાઓને કેવી રીતે સંભાળે છે

OmniRoute પાસે **સુરક્ષાના ત્રણ સ્તરો** છે:

### 1. ઑટો-ફૉલબૅક

જો શ્રેષ્ઠ પ્રદાતા નિષ્ફળ જાય, તો OmniRoute આપમેળે પછીના પ્રદાતાને અજમાવે છે. તમારે કંઈ કરવાની જરૂર નથી.

### 2. સ્વ-પુનઃપ્રાપ્તિ

જો કોઈ પ્રદાતા વારંવાર નિષ્ફળ થતો રહે:

- **સ્કોર < 0.2** → 5 મિનિટ માટે બાકાત
- **સર્કિટ બ્રેકર ખુલ્લું** → આપમેળે બાકાત
- **50% કરતાં વધુ પ્રદાતાઓ બંધ** → ઘટના મોડ (કોઈ અન્વેષણ નહીં)

### 3. કટોકટી ફૉલબૅક

જો બધા પ્રદાતાઓ નિષ્ફળ જાય, તો OmniRoute અંતિમ ઉપાય તરીકે સ્થિર મફત પ્રદાતાઓ (જેમ કે Kiro અથવા Qoder) તરફ રૂટ કરે છે.

## બહુવિધ એકાઉન્ટ માટે સપોર્ટ

જો તમારી પાસે એક જ પ્રદાતા માટે બહુવિધ એકાઉન્ટ હોય (દા.ત., બે OpenAI કી), તો OmniRoute દરેકને **અલગ ઉમેદવાર** તરીકે ગણે છે. તેનો અર્થ:

- એકાઉન્ટ A પાસે ક્વોટા બાકી છે → તેનો ઉપયોગ કરો
- એકાઉન્ટ B દર-મર્યાદિત છે → તેને છોડો
- એકાઉન્ટ C સસ્તું છે → તેને પ્રાથમિકતા આપો

દરેક એકાઉન્ટને તેની પોતાની સ્થિતિ, ક્વોટા અને ગતિના આધારે સ્વતંત્ર રીતે સ્કોર આપવામાં આવે છે.

## બૅન્ડિટ અન્વેષણ

વધુ સારા વિકલ્પો શોધવા માટે OmniRoute ક્યારેક નવા પ્રદાતાઓનું **અન્વેષણ** કરે છે:

- **ડિફૉલ્ટ**: 5% વિનંતીઓ રૅન્ડમ પ્રદાતાઓને મોકલવામાં આવે છે
- **ઑટો/સ્માર્ટ**: 10% અન્વેષણ દર
- જ્યારે 50% કરતાં વધુ પ્રદાતાઓ અસ્વસ્થ હોય ત્યારે **અક્ષમ**

આનાથી OmniRoute તમારી ઉપયોગની પેટર્ન માટે કયા પ્રદાતાઓ શ્રેષ્ઠ રીતે કાર્ય કરે છે તે શીખી શકે છે.

## સામાન્ય પ્રશ્નો

### "શું તે હંમેશાં સૌથી મોંઘું મૉડલ પસંદ કરશે?"

**ના.** ડિફૉલ્ટ રૂપે ખર્ચ સ્કોરનો માત્ર 15% ભાગ છે. સસ્તો, ઝડપી અને સ્વસ્થ પ્રદાતા મોંઘા પ્રદાતા કરતાં વધુ સારો સાબિત થઈ શકે છે. જો તમે ખર્ચને હજી વધુ પ્રાથમિકતા આપવા માંગતા હો, તો `auto/cheap` નો ઉપયોગ કરો.

### "જો કોઈ પ્રદાતા બંધ થઈ જાય તો શું?"

OmniRoute આપમેળે તેને છોડી દે છે અને પછીના પ્રદાતાને અજમાવે છે. જો કોઈ પ્રદાતા વારંવાર નિષ્ફળ થતો રહે, તો તેને અસ્થાયી રૂપે (5-30 મિનિટ માટે) બાકાત કરવામાં આવે છે. તમારે કંઈ કરવાની જરૂર નથી.

### "કયા પ્રદાતાનો ઉપયોગ થયો હતો તે હું જોઈ શકું છું?"

પ્રતિસાદ હેડર્સ તપાસો — OmniRoute દરેક પ્રતિસાદમાં ઉપયોગમાં લેવાયેલા પ્રદાતા અને મૉડલનો સમાવેશ કરે છે.

### "શું તે મારા ઉપયોગમાંથી શીખે છે?"

હા! સમય જતાં વધુ સારા નિર્ણયો લેવા માટે સ્કોરિંગ સિસ્ટમ ઐતિહાસિક ડેટા (વિલંબતા, ભૂલ દરો, સફળતા દરો)નો ઉપયોગ કરે છે.

### "`auto` અને `auto/smart` વચ્ચે શું તફાવત છે?"

- `auto` — સંતુલિત, 5% અન્વેષણ
- `auto/smart` — ગુણવત્તા-પ્રથમ (`auto/coding` જેવા જ ભારાંક), 10% અન્વેષણ

જ્યારે તમને શ્રેષ્ઠ ગુણવત્તા જોઈતી હોય અને પ્રસંગોપાત થતા અન્વેષણથી વાંધો ન હોય ત્યારે `auto/smart` નો ઉપયોગ કરો.

### "શું હું કોઈ ચોક્કસ પ્રદાતાનો ઉપયોગ ફરજિયાત કરી શકું?"

હા! `auto` ને બદલે `priority` વ્યૂહરચના ધરાવતા કૉમ્બોનો ઉપયોગ કરો, પછી `model` ફીલ્ડ તરીકે કૉમ્બોનું **ચોક્કસ નામ** મોકલો (દા.ત. `model: "my-combo"` — `auto` નહીં). વિગતો માટે [ટેક્નિકલ સંદર્ભ](../routing/AUTO-COMBO.md) જુઓ.

### "આ રાઉન્ડ-રૉબિનથી કેવી રીતે અલગ છે?"

રાઉન્ડ-રૉબિન ક્રમ અનુસાર પ્રદાતાઓમાંથી ચક્રીય રીતે પસાર થાય છે. ઑટો-કૉમ્બો **દરેક પ્રદાતાને સ્કોર આપે છે** અને શ્રેષ્ઠ પ્રદાતાને પસંદ કરે છે. તે વધુ સ્માર્ટ છે — તે સ્થિતિ, ગતિ, ખર્ચ અને ગુણવત્તાને ધ્યાનમાં લે છે.
