`devin-cli-agentic` વાસ્તવિક Claude Code રનટાઇમને OmniRouteના સ્થાનિક Anthropic
Messages એન્ડપોઇન્ટનો ઉપયોગ કરવા દે છે, જ્યારે અધિકૃત Devin CLI ACP stdio દ્વારા મોડેલ પ્રતિસાદો પૂરા પાડે છે. તે
હાલના Anthropic, Claude OAuth, Claude Web અથવા `devin-cli` પ્રદાતાઓમાં ફેરફાર કરતું નથી.

> **વર્તમાન સ્થિતિ: Claude Code `2.1.258` પર પિન કરેલું છે; ઑફલાઇન અને લાઇવ માન્યતા છેલ્લે
> `2.1.220` પર નોંધાઈ હતી.** `2.1.220` પિને Devin CLI
> `3000.2.17` અને મોડેલ `swe-1-7-lightning` દ્વારા ત્રણ અલગ-અલગ દૃશ્યો પૂર્ણ કર્યા હતા; તે અંતિમ લાઇવ રને ક્લાયન્ટની માલિકીનાં `Read`,
> `Edit` અને `Bash` ટર્ન્સ, સફળ `npm test` પરિણામો, પ્રોજેક્ટ કમાન્ડ અને સ્કિલ
> ડિસ્કવરી, માત્ર Devin રૂટિંગ અને શૂન્ય Claude ઇગ્રેસ સાબિત કર્યા હતા. ત્યારબાદ પિનને `2.1.258`
> સુધી વધારવામાં આવ્યું હતું (જે CLI જનરેશનનું OmniRouteની Claude ઓળખ અનુકરણ કરે છે અને મૂળભૂત રીતે
> Fable 5.1 ટિયર સમાવતી પ્રથમ લાઇન છે). નવા પિન પર પિન કરેલી બેઝ ઇમેજમાં ઇન્સ્ટોલ લેયર અને `claude --version`
> ચકાસવામાં આવ્યાં હતાં, તેમજ બ્રિજ યુનિટ સ્યુટ, `compose config` અને
> સ્થિર આઇસોલેશન પુરાવો સફળ થાય છે — પરંતુ ઑફલાઇન મોક દૃશ્ય અને લાઇવ ત્રણ-દૃશ્ય
> સ્યુટ હજી ફરી ચલાવવામાં આવ્યાં નથી. આ પિન સાથે બ્રિજ પર આધાર રાખતાં પહેલાં તેમને ફરી ચલાવો
> ("પિન કરેલાં ટૂલ્સ અપડેટ કરવા" જુઓ).

## આર્કિટેક્ચર

```text
Claude Code 2.1.258 (અલગ કરેલું નોન-રૂટ Linux કન્ટેનર)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-ફોર્મેટ, નો-ઑથ પ્રદાતા)
  -> devin acp --agent-type summarizer (અધિકૃત ACP stdio, કોઈ Devin ટૂલ્સ નહીં)
  -> સમર્પિત devin-auth વોલ્યુમમાં Devin એકાઉન્ટ
```

અધિકૃત CLIનો ડિફૉલ્ટ ACP એજન્ટ તેના પોતાના ટૂલ્સ ચલાવી શકે છે, તેથી આ બ્રિજ તેનો ઉપયોગ કરતો નથી.
તે નિશ્ચિત `summarizer` ACP એજન્ટ શરૂ કરે છે, જેના અધિકૃત CLI મોડમાં કોઈ ટૂલ્સ નથી, અને
સીરિયલાઇઝ કરેલી Anthropic વિનંતીને એક્ઝિક્યુશન ટ્રેસ તરીકે ફ્રેમ કરે છે. જ્યારે Claudeની માલિકીની બીજી
ક્રિયા જરૂરી હોય, ત્યારે પ્રતિસાદમાં ચોક્કસ એક ક્લાયન્ટ ટૂલ એન્વલપ હોવું આવશ્યક છે. કોઈપણ ACP
`tool_call` અથવા `tool_call_update` સફળ પ્રતિસાદ તરીકે નોંધાઈ શકે તે પહેલાં નકારવામાં આવે છે.

`open-sse/executors/devin-agentic/serializer.ts`માંનો સીરિયલાઇઝર `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` અને
Claude Code દ્વારા પૂરા પાડવામાં આવેલા ટૂલ્સને જાળવી રાખે છે. ઇમેજ અને અજ્ઞાત બ્લૉક્સ સ્પષ્ટપણે નિષ્ફળ થાય છે. મોટા ટૂલ પરિણામોમાં
દૃશ્યમાન ટ્રન્કેશન માર્કરનો ઉપયોગ થાય છે.

પાર્સર દરેક મોડેલ ટર્ન દીઠ એક સ્વતંત્ર `<tool>{...}</tool>` એન્વલપ સ્વીકારે છે. તે
વિનંતીની ટૂલ સૂચિ સામે નામ તપાસે છે, તે ટૂલના JSON
Schema સામે આર્ગ્યુમેન્ટ્સને માન્ય કરે છે, મિશ્ર વર્ણન/ક્રિયાઓને નકારે છે અને એક મર્યાદિત રિપેરની પરવાનગી આપે છે. ત્યારબાદ Claude Code
પરિણામી Anthropic `tool_use`ને સ્થાનિક રીતે ચલાવે છે અને `tool_result`ને OmniRoute દ્વારા પાછું મોકલે છે.

## આઇસોલેશન અને જોખમ મોડેલ

હોસ્ટનું Claude ઇન્સ્ટોલેશન, એકાઉન્ટ અને કન્ફિગરેશન કાર્યક્ષેત્રની બહાર છે અને પ્રતિબંધિત માનવામાં આવે છે.
Compose સેવાઓ:

- UID/GID `10001:10001` તરીકે, ફક્ત વાંચી શકાય તેવી રૂટ ફાઇલસિસ્ટમ, દૂર કરેલી ક્ષમતાઓ અને
  `no-new-privileges` સાથે ચાલે છે;
- ખાનગી `/home/bridge`, સમર્પિત Claude કન્ફિગ વોલ્યુમ, અલગ કરેલો OmniRoute ડેટા
  અને અલગ `devin-auth` વોલ્યુમનો ઉપયોગ કરે છે;
- માત્ર નિકાલ કરી શકાય તેવાં `.sandbox` વર્કસ્પેસ/પુરાવા માઉન્ટ કરે છે;
- હોસ્ટ હોમ, Keychain, SSH, ક્લાઉડ ક્રેડેન્શિયલ્સ અથવા Docker સૉકેટ માઉન્ટ કરતા નથી;
- સ્પષ્ટ એન્વાયર્નમેન્ટ્સ બનાવે છે અને Anthropic API/OAuth/રૂટિંગ વેરિએબલ્સ દૂર કરે છે;
- સ્થાનિક-માત્ર કી વડે Claude Code ઇન્ફરન્સને માત્ર `http://omniroute:20128` તરફ નિર્દેશિત કરે છે.

ઑફલાઇન પ્રોફાઇલ આંતરિક નેટવર્કનો ઉપયોગ કરે છે. લાઇવ પ્રોફાઇલમાં OmniRoute અધિકૃત Devin
એન્ડપોઇન્ટ્સ સુધી માત્ર `network-guard` દ્વારા પહોંચે છે; અસંબંધિત ગંતવ્યો નકારવામાં આવે છે.
Claude Code પાસે અલગ ડિનાય-ઑલ ઇગ્રેસ ગાર્ડ છે અને તે `NO_PROXY` દ્વારા માત્ર સ્થાનિક OmniRoute
સેવા સુધી પહોંચી શકે છે. ગાર્ડ ઑડિટ ફાઇલો માત્ર તેમની ગાર્ડ પ્રક્રિયા દ્વારા માઉન્ટ કરવામાં આવે છે.
સ્ક્રિપ્ટ્સ ટોકન-મુક્ત પુરાવો નિકાસ કરતાં પહેલાં ફાઇલની માલિકી, મોડ, લિંક ગણતરી અને દરેક નિર્ણયની ચકાસણી કરે છે.

આઇસોલેશન પુરાવો સ્વતંત્ર રીતે ચલાવો:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

તે ટોપોલોજી, નામિત માઉન્ટ્સ, નોન-રૂટ/ફક્ત વાંચી શકાય તેવી સેટિંગ્સ, સ્પષ્ટ સ્થાનિક રૂટિંગ,
સંવેદનશીલ એન્વાયર્નમેન્ટ વેરિએબલ્સની ગેરહાજરી, Docker સૉકેટની ગેરહાજરી, `api.anthropic.com`
અને `claude.ai`ની અવરોધિત ઍક્સેસ, માત્ર Devin પ્રદાતા પસંદગી તથા ACP બૅકએન્ડ અનુપલબ્ધ હોય ત્યારે
સ્પષ્ટ નિષ્ફળતાની માન્યતા કરે છે.

## પ્રથમ વખતનું સેટઅપ અને સામાન્ય ઉપયોગ

પિન કરેલી ઇમેજ બિલ્ડ કરો:

```bash
./scripts/devin-bridge/build
```

માત્ર અલગ કરેલા Devin વોલ્યુમને પ્રમાણિત કરો:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

લૉગિન કમાન્ડ રિમોટ/કન્ટેનર વાતાવરણો માટે બનાવાયેલ અધિકૃત મેન્યુઅ-ટોકન પ્રવાહનો ઉપયોગ કરે છે. મૂલ્ય સીધું CLI પ્રોમ્પ્ટમાં દાખલ કરવામાં આવે છે; તેને પ્રોસેસ આર્ગ્યુમેન્ટ તરીકે મોકલવામાં, Gitમાં લખવામાં અથવા હોસ્ટમાંથી કૉપી કરવામાં આવતું નથી.

અલગ કરેલું Claude Code રનટાઇમ લૉન્ચ કરો:

```bash
./scripts/devin-bridge/launch
```

કન્ટેનરાઇઝ્ડ Claude Code શરૂ કરતાં પહેલાં `launch` અલગાવ, Devin પ્રમાણીકરણ અને મોડેલ શોધ ફરીથી તપાસે છે. તે ક્યારેય હોસ્ટના Claude એક્ઝિક્યુટેબલને ચલાવતું નથી. મોડેલ ઉપનામો `.env.devin-bridge`માં સેટ કરી શકાય છે; કૉન્ફિગર કરેલા દરેક મૂલ્યમાં `devin-cli-agentic/` પ્રીફિક્સ જળવાયેલો હોવો આવશ્યક છે.

## માન્યતા કમાન્ડ્સ

પુનરુત્પાદનક્ષમ ઑફલાઇન પાથ માટે Devin એકાઉન્ટની જરૂર નથી અને તેમાં રનટાઇમ દરમિયાન ઇન્ટરનેટ ઉપલબ્ધ નથી:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

પ્રમાણિત, વૈકલ્પિક લાઇવ પાથ આ છે:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

એકસાથે મોટી સંખ્યામાં ACP સેશનો ખોલવાનું ટાળવા માટે લાઇવ રનર દૃશ્યો વચ્ચે રાહ જુએ છે અને ટેક્સ્ટ સ્વરૂપના દાવાઓ પર વિશ્વાસ કરવાને બદલે સંરચિત Claude સ્ટ્રીમ ઇવેન્ટ્સને માન્ય કરે છે. તેના ત્રણ દૃશ્યો આ બાબતો સાબિત કરે છે:

1. પ્રોજેક્ટમાંથી સીધું વાંચન અને ખામીનું વિશ્લેષણ;
2. વાસ્તવિક `Edit`, ક્લાયન્ટ-માલિકીનું `Bash` `npm test` અને ટર્મિનલ પરિણામ;
3. `/bridge-check` ઉપરાંત `bridge-proof` શોધ, પ્રોજેક્ટમાંથી વાંચન, ક્લાયન્ટ-માલિકીનું બીજું સફળ `npm test` અને કોઈ બાકી કામ વિના પૂર્ણતા.

અંતિમ ગેટ Devin નેટવર્ક ઑડિટ પણ તપાસે છે અને Claude એગ્રેસ ઑડિટ ખાલી રહે તે જરૂરી બનાવે છે.

## પિન કરેલા ટૂલ્સ અપડેટ કરવા

ઇમેજમાં Node, Claude Code અને Devin CLIને `docker/devin-bridge/Dockerfile`માં પિન કરવામાં આવ્યા છે. અપડેટ કરવા માટે:

1. સ્પષ્ટ વર્ઝનો બદલો;
2. બંને આર્કિટેક્ચર-વિશિષ્ટ Devin આર્કાઇવ ચેકસમને અધિકૃત આર્ટિફેક્ટનાં મૂલ્યો વડે બદલો;
3. ફરી બિલ્ડ કરો અને દરેક ઑફલાઇન માન્યતા કમાન્ડ ચલાવો;
4. ઇમેજની અંદરના વર્ઝનોની પુષ્ટિ કરો;
5. પ્રમાણિત ત્રણ-દૃશ્યવાળી લાઇવ સ્યુટ ફરી ચલાવો.

હોસ્ટ પર કોઈપણ CLIને ગ્લોબલી ઇન્સ્ટૉલ કરશો નહીં અથવા ચેકસમ ચકાસણીને ચકાસ્યા વિનાના ડાઉનલોડથી બદલશો નહીં.

## નિદાન અને સાફસફાઈ

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  સ્થાનિક રાઉટિંગ અને સૅનિટાઇઝ કરેલી એક્ઝિક્યુટર ભૂલો દર્શાવે છે.
- `.sandbox/evidence/mock-acp.jsonl` નિર્ધારિત મૉક ACP ક્રિયાઓ રેકોર્ડ કરે છે.
- `.sandbox/evidence/claude-stream.jsonl` વાસ્તવિક Claude Code ઑફલાઇન રન રેકોર્ડ કરે છે.
- `.sandbox/evidence/live-*.jsonl` ત્રણ માન્ય કરેલી લાઇવ સ્ટ્રીમ્સ રેકોર્ડ કરે છે.
- `.sandbox/evidence/egress.jsonl` અને `.sandbox/evidence/claude-egress.jsonl` ગાર્ડ ઑડિટ્સની માન્ય કરેલી, ટોકન-મુક્ત નકલો છે.

લૉગિન/કૉન્ફિગ વોલ્યુમ્સ જાળવી રાખીને માલિકીવાળા કન્ટેનર્સ અને નેટવર્ક્સ બંધ કરો:

```bash
./scripts/devin-bridge/clean
```

નેમ્ડ વોલ્યુમ્સ સહિત સમગ્ર બ્રિજ-માલિકીનું વાતાવરણ દૂર કરો:

```bash
./scripts/devin-bridge/clean --all
```

## મર્યાદાઓ

- બ્રિજ નિશ્ચિત, ટૂલ-રહિત `summarizer` ભૂમિકા પર આધાર રાખે છે, કારણ કે Devin CLI `3000.2.17` કોઈ તટસ્થ, ટૂલ-રહિત ACP એજન્ટ ઉપલબ્ધ કરાવતું નથી. એડેપ્ટર સારાંશ-સ્વરૂપના મધ્યવર્તી પ્રતિસાદોની ભરપાઈ કરે છે, પરંતુ એક મર્યાદિત સુધારાનો પ્રયાસ હજી પણ સ્પષ્ટ રીતે નિષ્ફળ થઈ શકે છે.
- લાઇવ ACP કૉલ્સ અસ્થાયી `502`/`504` પ્રતિસાદો આપી શકે છે. હાર્નેસ દૃશ્યો વચ્ચે અંતર રાખે છે; સતત નિષ્ફળતાની સ્થિતિમાં તે બંધ રહીને નિષ્ફળ થાય છે અને ક્યારેય અન્ય પ્રદાતા પસંદ કરતું નથી.
- દરેક Anthropic વિનંતીમાંથી ACP સંદર્ભનું પુનઃનિર્માણ કરવામાં આવે છે; કોઈ પ્રોસેસ/સેશન સંલગ્નતા નથી.
- દરેક મોડલ પ્રતિસાદ દીઠ એક ટૂલ કૉલ સમર્થિત છે; સમાંતર કૉલ્સ નકારવામાં આવે છે.
- છબીઓ સ્પષ્ટપણે અસમર્થિત છે. વિઝન, વિચાર-પ્રક્રિયાનું આઉટપુટ, પ્રયાસ નિયંત્રણો અને 1M સંદર્ભ વિન્ડોની જાહેરાત કરવામાં આવતી નથી.
- SSE માન્ય Anthropic જીવનચક્ર ઇવેન્ટ્સનો ઉપયોગ કરે છે, પરંતુ મર્યાદિત ACP ટર્ન એકત્રિત થયા પછી જ તેને ઉત્સર્જિત કરવામાં આવે છે; ACP ચંક્સ તબક્કાવાર ફૉરવર્ડ કરવામાં આવતા નથી.
