રિલે (Vercel, Deno, Cloudflare) સર્વરલેસ બેકએન્ડ પર અપસ્ટ્રીમ કનેક્શન સમાપ્ત કરે છે, જેથી પ્રોવાઇડરની API કી સર્વર-સાઇડ પર રાખીને OmniRoute સ્થિર રીજનમાંથી આઉટબાઉન્ડ ટ્રાફિક મોકલી શકે. આ દસ્તાવેજમાં ઓપરેટરોને પ્રોડક્શનમાં આવતી બે નિષ્ફળતા પરિસ્થિતિઓ અને દરેક માટે OmniRoute દ્વારા પૂરા પાડવામાં આવતા પુનઃપ્રાપ્તિ માર્ગો આવરી લેવામાં આવ્યા છે.

## રિલે ઑથ કેવી રીતે સંગ્રહિત થાય છે

જ્યારે તમે **Settings → Proxy Pool → Deploy Relay**માંથી રિલે ડિપ્લોય કરો છો, ત્યારે ડિપ્લોય પ્રક્રિયા રિલેના ઑથ ટોકનને પ્રોક્સીના `notes` JSON ફીલ્ડમાં સંગ્રહિત કરે છે:

- જો `STORAGE_ENCRYPTION_KEY` સેટ કરેલ હોય, તો ટોકન `relayAuthEnc` તરીકે લખાય છે
  (સંગ્રહિત સ્થિતિમાં AES દ્વારા એન્ક્રિપ્ટેડ).
- અન્યથા તેને પ્લેઇનટેક્સ્ટ `relayAuth` તરીકે લખવામાં આવે છે.

રિક્વેસ્ટ સમયે `extractRelayAuth(notes)` હાજર હોય તે સ્વરૂપ પરત કરે છે,
તેથી રિસ્ટાર્ટ પછી પણ રિલે કાર્યરત રહે છે.

## નિષ્ફળતા પરિસ્થિતિ 1 — કી રોટેશન પછી ડિક્રિપ્ટ ન થઈ શકતું ટોકન

**લક્ષણ:** અગાઉ કાર્યરત રિલે હવે પર્યાવરણ અથવા સિક્રેટ-મેનેજરમાં
`STORAGE_ENCRYPTION_KEY` રોટેટ કર્યા પછી અપસ્ટ્રીમ `401`/ઑથ ભૂલો પરત કરે છે.
સંગ્રહિત `relayAuthEnc` બ્લોબ હવે ડિક્રિપ્ટ થઈ શકતો નથી, તેથી
`extractRelayAuth` ખાલી સ્ટ્રિંગ પરત કરે છે અને રિલે કોઈ ઑથ મોકલતું નથી.

**પુનઃપ્રાપ્તિ — યથાસ્થાને રિપેર કરો (ફરી ડિપ્લોય કરવાની જરૂર નથી):**

1. **Settings → Proxy Pool** ખોલો.
2. જે રિલે પંક્તિઓમાં ઑથ ગાયબ છે તેમાં પીળું `auth missing` બેજ અને
   **Repair** બટન દેખાય છે.
3. **Repair** પર ક્લિક કરો. OmniRoute
   `POST /api/settings/proxies/[id]/repair-relay`ને કૉલ કરે છે, જે:
   - **વર્તમાન** કી વડે `relayAuthEnc`ને ડિક્રિપ્ટ કરે છે,
   - પ્લેઇનટેક્સ્ટ `relayAuth`ને ફરી `notes`માં લખે છે,
   - `{ repaired: true, mode: "recovered" }` પરત કરે છે.

કોઈપણ ડિપ્લોય ક્રેડેન્શિયલ્સ ફરી દાખલ કર્યા વિના રિલે સેવા આપવાનું ફરી શરૂ કરે છે.

આ ફક્ત ત્યારે જ કાર્ય કરે છે જ્યારે વર્તમાન `STORAGE_ENCRYPTION_KEY` હજુ પણ
બ્લોબને ડિક્રિપ્ટ કરી શકે. જો તમે માઇગ્રેશન **વિના** કી રોટેટ કરી હોય, તો
બ્લોબ પુનઃપ્રાપ્ત કરી શકાતો નથી.

## નિષ્ફળતા પરિસ્થિતિ 2 — પુનઃપ્રાપ્ત ન થઈ શકતું ટોકન (જૂની કી હવે ઉપલબ્ધ નથી)

**લક્ષણ:** તમે **Repair** પર ક્લિક કર્યું અને
`{ repaired: false, mode: "redeploy", status: 409 }` મળ્યું.

**પુનઃપ્રાપ્તિ — ફરી ડિપ્લોય કરો:**

સંગ્રહિત ટોકનને વર્તમાન કી વડે પુનઃપ્રાપ્ત કરી શકાતું નથી. તમે મૂળરૂપે ઉપયોગ
કરેલા એ જ મોડલમાંથી રિલેને ફરી ડિપ્લોય કરો (**Deploy Relay** મેનુ → Vercel /
Deno / Cloudflare). ડિપ્લોય પ્રક્રિયા નવું ટોકન લખે છે (વર્તમાન કી વડે
એન્ક્રિપ્ટેડ) અને પંક્તિનું `auth missing` બેજ દૂર થઈ જાય છે.

UIમાં, ટોકન પુનઃપ્રાપ્ત ન થઈ શકે ત્યારે **Repair** બટન પોતે જ રીડિપ્લોય મોડલ
ખોલે છે, તેથી તમારે તેને મેન્યુઅલી શોધવાની જરૂર પડતી નથી.

## નિષ્ફળતા પરિસ્થિતિ 3 — રિલે સુધી પહોંચી શકાય છે પરંતુ તે અસ્વસ્થ છે

**લક્ષણ:** પ્રોક્સી ટેસ્ટ (`speed` બટન) રિલે કાર્યરત હોવાનું બતાવે છે, પરંતુ
રિક્વેસ્ટ્સ હજુ પણ વચ્ચે-વચ્ચે નિષ્ફળ થાય છે.

OmniRouteની ઑટો-ટેસ્ટ પ્રોબ દ્વારા પરત કરવામાં આવતા રિલે અવેરનેસ હેડર્સ
તપાસો (**Settings → Proxy Pool** અને `relayTested` / `relayAlive` કાઉન્ટર્સ જુઓ):

- `x-relay-url` — કયા રિલે બેકએન્ડે જવાબ આપ્યો.
- `x-relay-mode` — તે રિક્વેસ્ટ માટે `ts` | `bifrost` | `auto`.
- `x-relay-attempts` — સફળતા પહેલાં કેટલા રિલે હોપ્સ અજમાવવામાં આવ્યા.
- `x-relay-fallback` — પસંદગીના બેકએન્ડથી TypeScript રિલે પર રિક્વેસ્ટ
  ફૉલબૅક થાય ત્યારે `true`.

ઓછા `relayAlive` સાથે `x-relay-fallback`નો ઊંચો દર દર્શાવે છે કે સાઇડકાર
બેકએન્ડ અસ્વસ્થ છે અને તમારે તેને સુધારવું જોઈએ અથવા રિલે બેકએન્ડ વ્યૂહરચનાને
`ts` પર સ્વિચ કરવી જોઈએ (`RELAY_BACKEND_STRATEGY.md` જુઓ).

## API સંદર્ભ

| પદ્ધતિ | પાથ                                       | બોડી                    | સફળતા                                                                                                                                                 | નિષ્ફળતા                                                                                                   |
| ------ | ----------------------------------------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `POST` | `/api/settings/proxies/[id]/repair-relay` | `{ "id": "<proxyId>" }` | ફરીથી મેળવવામાં આવે ત્યારે `200 { repaired: true, mode: "recovered" }`; પ્લેઇનટેક્સ્ટ પહેલેથી હાજર હોય ત્યારે `200 { repaired: false, mode: "noop" }` | પુનઃપ્રાપ્ત ન થઈ શકે ત્યારે `409 { mode: "redeploy" }`; રિલે પ્રકાર ન હોય ત્યારે `400`; ન મળે ત્યારે `404` |

લિસ્ટ રૂટ `GET /api/settings/proxies` દરેક આઇટમ સાથે સિક્રેટ-મુક્ત
`relayInfo: { isRelay, authMissing, repairMode }` જોડે છે, જેથી ડૅશબોર્ડ ટોકનને
ક્યારેય જાહેર કર્યા વિના રિપેર વિકલ્પ રેન્ડર કરી શકે.
