કેટલીક સેવાઓને OmniRouteમાં એકીકૃત કરવામાં આવી હતી અને પછી તેમને સંચાલિત કરતા લોકોએ વિનંતી કરતાં તેમને દૂર કરવામાં આવી હતી. આ પૃષ્ઠ એ દૂર કરવાની કાર્યવાહીઓનો કાયમી રેકોર્ડ છે. તેનો એકમાત્ર હેતુ તેમને આકસ્મિક રીતે ફરી ઉમેરાતી અટકાવવાનો છે: કોઈ યોગદાનકર્તાને જૂનો fork, cache કરેલો npm tarball, archive કરેલો issue અથવા "provider X પુનઃસ્થાપિત કરો" એવી વિનંતી મળે, તો તેને એક જ જગ્યાએ સ્પષ્ટ સૂચના મળવી જોઈએ કે **ફરીથી રજૂ કરશો નહીં**.

આ પૃષ્ઠ બંધ થઈ ગયેલી અથવા હવે ઉપલબ્ધ ન હોય તેવી સેવાઓની સૂચિ **નથી**. આવી સેવાઓનો રેકોર્ડ [`FREE_TIERS.md`](FREE_TIERS.md) ("દૂર કરેલી / કોઈ મફત સ્તર નહીં")માં રાખવામાં આવે છે અને સેવા ફરી ઉપલબ્ધ થાય તો તેઓ પાછી આવી શકે છે. નીચેની એન્ટ્રીઓ માત્ર વિનંતીમાં નામિત ઑપરેટરની લેખિત પરવાનગીથી જ પાછી આવી શકે છે અને એ પરવાનગીની લિંક એન્ટ્રીમાંથી આપવી આવશ્યક છે.

## નીતિ

1. **સેવાના ઑપરેટર તરફથી આવેલી દૂર કરવાની વિનંતીનું પાલન કરવામાં આવે છે, તેના પર વાટાઘાટ કરવામાં આવતી નથી.** OmniRoute કોઈપણ upstream સેવા સાથે સંલગ્ન નથી. જ્યારે કોઈ સેવાનો ઑપરેટર એકીકરણ દૂર કરવાની વિનંતી કરે, ત્યારે તે દૂર કરવામાં આવે છે, પછી ભલે એકીકરણમાં અધિકૃત APIનો ઉપયોગ થયો હોય કે નહીં.
2. **"દૂર કરેલું" એટલે OmniRoute નિયંત્રિત કરે તે દરેક સપાટી પરથી દૂર કરેલું.** Executor, registry એન્ટ્રી, provider id અને alias, model સૂચિ, endpoints, environment variables, icon, dashboard cards, જનરેટ કરેલો provider સંદર્ભ, `FREE_TIERS.md`, environment સંદર્ભ, README ગણતરીઓ, `llm.txt` mirrors, સમર્પિત tests અને golden snapshots, code comments, CHANGELOG bullets (ledgerમાં નોંધાયેલા reconciliation સાથે, `config/release/changelog-reconciliations.json` જુઓ), GitHub Releases notes, wiki, તેમજ જેનો વિષય તે provider હતો એવા GitHub issues, discussions અને pull requests (issues અને discussions કાઢી નાખવામાં આવે છે; pull requestsના શીર્ષકો બદલવામાં આવે છે, તેમના વર્ણનને બદલવામાં આવે છે અને threadને lock કરવામાં આવે છે, કારણ કે GitHub pull requests કાઢી શકતું નથી).
3. **લેખિત પરવાનગી વિના આ પૃષ્ઠ પરની કોઈ એન્ટ્રીને ક્યારેય ફરીથી રજૂ કરશો નહીં.** તેમાં કોઈપણ provider catalogમાં id અથવા alias ફરી ઉમેરવું, executorમાં domains ઉમેરવા, તેને "પુનઃસ્થાપિત" કરતી યોગદાનકર્તાની PR સ્વીકારવી, તેને free-model catalogમાં ઉમેરવું અથવા OmniRoute દ્વારા તેને મેળવવાની manual રીતનું દસ્તાવેજીકરણ કરવું સામેલ છે. આવી PRs અને issuesને આ પૃષ્ઠની લિંક સાથે બંધ કરો.
4. **એન્ટ્રી ન્યૂનતમ રાખો.** સમીક્ષકને ફરી રજૂ કરાયેલી વસ્તુ ઓળખવા માટે જરૂરી હોય એટલી જ માહિતી નોંધો: identifiers, domains, તારીખો અને દૂર કરવાની કાર્યવાહી કરનાર pull request. એકીકરણ કેવી રીતે કાર્ય કરતું હતું તેનું વર્ણન કરશો નહીં.
5. **Regression guard `tests/unit/removed-providers-blocklist.test.ts` છે.** નીચેના identifiers અથવા domainsમાંથી કોઈપણ provider catalogs, executor map અથવા provider registry sourcesમાં ફરી દેખાય ત્યારે તે નિષ્ફળ જાય છે. અહીં નવી row ઉમેરતી એ જ PRમાં તે testમાં નવા identifiers ઉમેરો.

## એન્ટ્રી ઉમેરવી

દૂર કરવાની નવી વિનંતી આવે ત્યારે:

1. ખાતરી કરો કે વિનંતી સેવાના ઑપરેટર તરફથી આવી છે (તેમનું support address અથવા તેઓ નિયંત્રિત કરતા હોય તેવું domain) અને સંદેશ ખાનગી રીતે સાચવી રાખો.
2. નીતિના મુદ્દા 2માં આપેલી checklist અનુસરીને એકીકરણ દૂર કરો. Keyless provider માટે સંદર્ભ તરીકે [#12440](https://github.com/diegosouzapw/OmniRoute/pull/12440) અને સંગ્રહિત connections ધરાવતા API-key provider માટે [#10210](https://github.com/diegosouzapw/OmniRoute/pull/10210)નો ઉપયોગ કરો (migration ઉમેરો).
3. એ જ PRમાં ઉપરના tableમાં એક row અને `tests/unit/removed-providers-blocklist.test.ts`માં identifiers ઉમેરો.
4. PR merge થયા પછી ઑપરેટરને જવાબ આપો, જેમાં શું દૂર કરવામાં આવ્યું અને OmniRoute શું બદલી શકતું નથી (પહેલેથી પ્રકાશિત npm અને Docker versions, git history, third-party forks) તેની સૂચિ આપો.
