## ખર્ચ વિભાગ (નવો, સ્તર 1)

પાથ પ્રિફિક્સ: `/dashboard/costs/`

| આઇટમ           | URL                                  | વર્ણન                                            |
| -------------- | ------------------------------------ | ------------------------------------------------ |
| અવલોકન         | `/dashboard/costs`                   | એકત્રિત ખર્ચ ડૅશબોર્ડ (એનાલિટિક્સમાંથી ખસેડાયેલ) |
| કિંમત નિર્ધારણ | `/dashboard/costs/pricing`           | પ્રતિ-મોડેલ કિંમત કોષ્ટક                         |
| બજેટ           | `/dashboard/costs/budget`            | બજેટ મર્યાદાઓ + ચેતવણીઓ                          |
| ક્વોટા શેરિંગ  | `/dashboard/costs/quota-share`       | ક્વોટા શેર પૂલ્સ + વપરાશ                         |
| પ્લાન કૉન્ફિગ  | `/dashboard/costs/quota-share/plans` | પ્રતિ-પ્રદાતા પ્લાન ઓવરરાઇડ્સ                    |

**તર્ક**: કિંમત નિર્ધારણ, બજેટ અને ક્વોટા શેરિંગ અગાઉ
`મોનિટરિંગ > ખર્ચ પેરામીટર્સ` હેઠળ હતાં. તેમને સમર્પિત ટોચના-સ્તરના વિભાગમાં
ખસેડવાથી ઑબ્ઝર્વેબિલિટી ટૂલિંગમાં નેવિગેટ કર્યા વિના તેમને શોધવાનું સરળ બને છે.

## મોનિટરિંગ વિભાગ (પુનર્ગઠિત)

મોનિટરિંગ વિભાગમાં હવે ટોચ પર **પ્રવૃત્તિ** છે અને ત્યારબાદ **3 પેટાજૂથો** છે:

```
મોનિટરિંગ
├── પ્રવૃત્તિ             ← સમયરેખા ફીડ (ટોચના-સ્તરની આઇટમ)
├── લૉગ્સ જૂથ
│   ├── લૉગ્સ (બધા)
│   ├── પ્રૉક્સી લૉગ્સ
│   └── કન્સોલ લૉગ્સ
├── ઑડિટ જૂથ
│   ├── ઑડિટ લૉગ
│   ├── MCP ઑડિટ
│   └── A2A ઑડિટ
└── સિસ્ટમ જૂથ
    ├── સ્વાસ્થ્ય
    └── રનટાઇમ
```

### જૂના માળખાની સરખામણીમાં શું બદલાયું

| પહેલાં                                                                                     | પછી                                             |
| ------------------------------------------------------------------------------------------ | ----------------------------------------------- |
| પ્રવૃત્તિ = લૉગ્સની અંદરની ટૅબ જે ઑડિટ લૉગ રેન્ડર કરતી હતી                                 | પ્રવૃત્તિ = સમર્પિત ફીડ (`/dashboard/activity`) |
| મોનિટરિંગમાં ખર્ચ પેરામીટર્સ જૂથ                                                           | ખર્ચ વિભાગમાં ખસેડાયું                          |
| સપાટ સૂચિ: લૉગ્સ, પ્રવૃત્તિ (લૉગ્સ), ઑડિટ, સ્વાસ્થ્ય, રનટાઇમ, કિંમત નિર્ધારણ, બજેટ, ક્વોટા | સંરચિત 3-જૂથ + સમર્પિત ખર્ચ વિભાગ               |

## પ્રવૃત્તિ વિરુદ્ધ ઑડિટ લૉગ

હવે આ બંને અલગ છે:

| પરિમાણ                 | પ્રવૃત્તિ (`/dashboard/activity`)                                | ઑડિટ લૉગ (`/dashboard/audit`)             |
| ---------------------- | ---------------------------------------------------------------- | ----------------------------------------- |
| **હેતુ**               | વપરાશકર્તા-કેન્દ્રિત ઇવેન્ટ ફીડ ("તાજેતરમાં શું થયું")           | અનુપાલન / સુરક્ષા લૉગ                     |
| **ડેટા સ્રોત**         | `GET /api/compliance/audit-log?level=high`                       | `GET /api/compliance/audit-log?level=all` |
| **ફોર્મેટ**            | સમયરેખા, દિવસ પ્રમાણે જૂથબદ્ધ, માનવ-વાંચનક્ષમ ક્રિયાપદો + આઇકન્સ | ગીચ પૃષ્ઠાંકિત કોષ્ટક, 50/પૃષ્ઠ           |
| **ફિલ્ટર્સ**           | ઇવેન્ટ પ્રકારની શ્રેણી                                           | ક્રિયા, ગંભીરતા, કર્તા, તારીખ શ્રેણી      |
| **નિકાસ**              | ઉપલબ્ધ નથી                                                       | JSON નિકાસ                                |
| **કર્તા ફિલ્ટર**       | લાગુ પડતું નથી                                                   | કર્તા પ્રમાણે ફિલ્ટર કરી શકાય છે          |
| **દર્શાવેલી ઇવેન્ટ્સ** | માત્ર ઉચ્ચ-સ્તરની ક્રિયાઓ (અનુમતિ સૂચિ)                          | બધી ઑડિટ ઇવેન્ટ્સ                         |

### ઉચ્ચ-સ્તરની ક્રિયાઓની અનુમતિ સૂચિ

`src/lib/audit/highLevelActions.ts` માં વ્યાખ્યાયિત છે. પ્રવૃત્તિ ફીડમાં કઈ ઇવેન્ટ્સ
દેખાય છે તેનું નિયંત્રણ કરે છે. અનુમતિ સૂચિમાં આનો સમાવેશ થાય છે:

- પ્રદાતા ઉમેરવા/દૂર કરવા/પરીક્ષણ કરવાની ઇવેન્ટ્સ
- કોમ્બો બનાવવા/અપડેટ કરવા/કાઢી નાખવા
- API કી જીવનચક્ર (બનાવવી, રદ કરવી, ફેરવવી)
- બજેટ મર્યાદા સુધી પહોંચવું
- પ્રમાણીકરણ લૉગિન/લૉગઆઉટ
- ક્લાઉડ એજન્ટ સત્ર બનાવવું
- MCP ટૂલ નોંધણી
- વેબહૂક બનાવવું/કાઢી નાખવું
- ક્વોટા પૂલ/પ્લાનમાં ફેરફારો (`quota.*` ક્રિયાઓ, Group B)
- પ્લેટફોર્મ ઇવેન્ટ્સ (અપડેટ, ડિપ્લોય)
- સ્કિલ ઇન્સ્ટૉલ કરવી/દૂર કરવી

આ સૂચિમાં ન હોય તેવી ઇવેન્ટ્સ માત્ર ઑડિટ લૉગમાં દેખાય છે.

### નવી ઉચ્ચ-સ્તરની ક્રિયા ઉમેરવી

`src/lib/audit/highLevelActions.ts` માં ફેરફાર કરો અને ક્રિયા સ્ટ્રિંગને
`HIGH_LEVEL_ACTIONS` માં ઉમેરો. આ માટે PR જરૂરી છે (સૂચિ કોડ છે, DB દ્વારા કૉન્ફિગર કરી શકાતી નથી).
સંબંધિત આઇકન `src/lib/audit/activityIcons.ts` માં ઉમેરી શકાય છે.

## રીડાયરેક્ટ: `/dashboard/logs/activity`

જૂનો પાથ `/dashboard/logs/activity`, `src/app/(dashboard)/dashboard/logs/activity/page.tsx`
માં `permanentRedirect()` મારફતે `/dashboard/activity` પર કાયમી રીતે રીડાયરેક્ટ
(HTTP 308) થાય છે.

જૂના ID નો સંદર્ભ આપતા વપરાશકર્તા પ્રીસેટ્સને તૂટતા અટકાવવા માટે લેગસી સાઇડબાર ID
`logs-activity` ને `HIDEABLE_SIDEBAR_ITEM_IDS` માં જાળવવામાં આવ્યું છે
(પરંતુ `SIDEBAR_DEFINITIONS` માંથી દૂર કરવામાં આવ્યું છે).

## i18n

Group B દ્વારા ઉમેરાયેલા નેમસ્પેસ:

| નેમસ્પેસ કી             | આવરી લે છે                                                                  |
| ----------------------- | --------------------------------------------------------------------------- |

| `sidebar.activity`      | પ્રવૃત્તિ સાઇડબાર આઇટમ                                                      |
| `sidebar.logsGroup`     | લૉગ્સ પેટાજૂથનું લેબલ                                                       |
| `sidebar.systemGroup`   | સિસ્ટમ પેટાજૂથનું લેબલ                                                      |
| `sidebar.costsOverview` | ખર્ચ અવલોકન આઇટમ                                                            |
| `activity.*`            | પ્રવૃત્તિ પૃષ્ઠની બધી સ્ટ્રિંગ્સ (શીર્ષક, ક્રિયાપદો, ફિલ્ટર્સ, ખાલી સ્થિતિ) |

પ્રમાણભૂત સ્રોત લોકેલ્સ: `pt-BR` અને `en`. અન્ય તમામ 40 લોકેલ્સ
`next-intl` ફૉલબૅક મિકેનિઝમ (`src/i18n/config.ts` માં કૉન્ફિગર કરેલું) દ્વારા
અંગ્રેજી પર ફૉલબૅક થાય છે.
