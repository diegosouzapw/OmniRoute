1. હાલના single-key semaphore કરાર અને નવા atomic multi-key કરારને કેન્દ્રિત પરીક્ષણોથી સુનિશ્ચિત કરો: કોઈ આંશિક reservations નહીં, FIFO queueing, abort, timeout, queue-full, idempotent release, stats અને cleanup.
2. હાલના account semaphore ને તેની જ જગ્યાએ સામાન્ય બનાવો. `acquire()` ને `acquireMany()` આસપાસના compatibility wrapper તરીકે જાળવો; બીજું scheduler અથવા dependency ઉમેરશો નહીં.
3. `chatCore` માં account-only acquisition ને `withRateLimit` પહેલાં તરત જ એક સંચિત global/provider/account acquisition થી બદલો. account rotation દ્વારા connection બદલાય ત્યારે આખો set ફરીથી acquire કરો અને streaming પૂર્ણ થાય ત્યાં સુધી release જાળવી રાખો.
4. હાલની resilience settings pipeline (types, defaults, normalization, schema, API response, UI અને translations) ને global અને provider caps સાથે વિસ્તારો. જૂના Bottleneck concurrency control ને connection/quota-scope concurrency તરીકે ફરીથી લેબલ કરો, જેથી તેનો વાસ્તવિક scope સ્પષ્ટ થાય.
5. કેન્દ્રિત પરીક્ષણો, lint, typecheck, static checks અને સંપૂર્ણ test suite ચલાવો; behavioral change ને changelog માં દસ્તાવેજિત કરો.

ઇરાદાપૂર્વક જાળવેલું વર્તન: zero/null concurrency gate ને bypass કરે છે, account-only callers `acquire()` નો ઉપયોગ કરવાનું ચાલુ રાખે છે, blocked-account controls તેમનું key format અને API જાળવી રાખે છે અને provider rate-limit queue નું વર્તન યથાવત્ રહે છે.
