## 1. સેવાની આધારભૂત હકીકતો (સત્તાવાર દસ્તાવેજો, પરસ્પર ચકાસેલ)

- બેઝ URL: `https://api.anysearch.com` (REST) + `POST /mcp` (MCP, JSON-RPC 2.0).
- `POST /v1/search` - પેરામીટર્સ: `query` (આવશ્યક), `max_results` (1-10, ડિફૉલ્ટ 10), `tag` (`{domain}.{sub_domain}` વર્ટિકલ રાઉટિંગ), `zone` (cn/intl), `language`, `params` (સ્ટ્રક્ચર્ડ વર્ટિકલ ફીલ્ડ્સ), `format` (json/markdown).
- `GET /v1/sub-domains?domain=...` - ક્ષમતા કેટલોગ, ક્વોટામાં ગણાતું નથી.
- `POST /v1/extract` - `{url, title, content}` ફેચ/એક્સટ્રેક્ટ કરે છે; કડક JSON બોડી, 16 KiB મર્યાદા.
- `POST /v1/auth/email/register` - એક જ કૉલમાં રજિસ્ટ્રેશન, એક-વખતની પ્લેઇનટેક્સ્ટ કી `as_sk_...` પરત કરે છે.
- ઑથ: વૈકલ્પિક `Authorization: Bearer <as_sk_...>`; અનામી ઍક્સેસ પ્રતિ-IP મર્યાદાઓ સુધી ઘટે છે અને દૈનિક મફત ક્વોટાનો ઉપયોગ કરે છે; અમાન્ય કી કોઈપણ મૌન અનામી ફૉલબૅક વિના 401/403 પરત કરે છે.
- મફત સ્તર: દરરોજ 1000 રિક્વેસ્ટ્સ, પ્રતિ કી 20 QPS. પેઇડ સ્તર: કિંમત નિર્ધારિત નથી (ટૂંક સમયમાં આવી રહ્યું છે).
- રિસ્પોન્સ એન્વલપ: સફળતા `{code: 0, message: "success", request_id, data}`; નિષ્ફળતા `{code: -1, message}`. ઑથ/ક્વોટા ભૂલો કોઈ સ્ટ્રક્ચર્ડ `error_code` ધરાવતી નથી (મેસેજ ટેક્સ્ટ જ સંકેત છે); એક્સટ્રેક્ટ-વિશિષ્ટ ભૂલો `error_code` (`invalid_extract_url`, `extract_failed`) ધરાવે છે. 429 પર કોઈ `Retry-After` હેડર નથી.

## 3. નિર્ણયો (તમામ 2026-08-26ના રોજ લેવાયેલા)

1. **રાઉટિંગ અભિગમ: `fallbackOnly`.** તર્ક: ખર્ચ-0 ધરાવતો મફત પ્રદાતા આપમેળે થતા ખર્ચ-આધારિત રાઉટિંગમાં ક્યારેય પ્રભુત્વ ધરાવવો ન જોઈએ; સ્પષ્ટ પસંદગી અને ફેલઓવરથી પાછા ફરવાની પ્રક્રિયા અપ્રભાવિત રહે છે. પૂર્વદૃષ્ટાંત: મર્જ કરેલી xquik એન્ટ્રી.
2. **વ્યાપ: v1માં `POST /v1/extract` મારફતે webSearch + webFetch.** tavily/exaની દ્વિ-ક્ષમતા ધરાવતી માનસિક રૂપરેખા સાથે સુસંગત. વર્ટિકલ સપાટીઓ (`tag`, `sub-domains`, `batch_search`) વ્યાપની બહાર રહેશે — હાલમાં વર્ટિકલ પેરામીટર્સ માટે કોઈ IR નથી.
3. **ક્વોટા પ્રદર્શન: `freeMonthlyQuota: 0`** (xquik-શૈલીનું સંયમિત પ્રદર્શન). વાસ્તવિક મર્યાદા (1000 વિનંતીઓ/દિવસ, દૈનિક રીસેટ) તેના બદલે UI કેટલોગના `authHint` લખાણમાં આપવામાં આવે છે. તર્ક: ક્વોટાનું પ્રદર્શન રીસેટની અર્થવ્યવસ્થા સાથે મેળ ખાતું હોવું જોઈએ; દૈનિક મર્યાદાને માસિક-સમકક્ષ (30000)માં રૂપાંતરિત કરવું એ ખોટું વચન છે, જેને UI પૂર્ણ કરી શકતું નથી.
4. **searchTypes: ફક્ત `["web"]`.** AnySearch APIમાં સમાચાર/છબીઓ માટેના વર્ટિકલનો કોઈ જાહેર પુરાવો નથી; દસ્તાવેજીકૃત વર્ટિકલ વિના APIsને એકીકૃત કરતા ગેટવે (દા.ત. Google Custom Search) news -> webનું મૌન મેપિંગ કરવાને બદલે ફક્ત web ઉપલબ્ધ કરાવે છે.
5. **કી અભિગમ:** કી વિના કાર્ય કરે છે; અમાન્ય કી 401/403 પરત કરે છે અને તેને ક્યારેય મૌન રીતે અનામી ઍક્સેસમાં ડાઉનગ્રેડ કરવામાં આવતી નથી (અપસ્ટ્રીમ કરારને અનુરૂપ).
6. **ઇરાદાપૂર્વકના બાકાત મુદ્દાઓ:** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (ચેટ ઇન્ટરસેપ્શન firecrawl/jina/tavily પર જ રહે છે); `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (અનામી રિમોટ એન્ડપોઇન્ટ્સ દરેક એગ્રેસ IP દીઠ એક જ IP-મર્યાદિત પૂલ શેર કરે છે, તેથી કી વિનાનું extract ઑપ્ટ-ઇન છે, સ્વચાલિત રાઉટિંગ માટેનું ઉમેદવાર નથી); `QUOTA_STATUS_PROVIDERS` (AnySearch ક્વોટાને 402/403 સ્ટેટસ દ્વારા નહીં, પરંતુ 429/એન્વલપ દ્વારા સૂચવે છે).

## 4. સંદર્ભો

- xquik ટેમ્પલેટ: કમિટ a0ceccc, PR #11370 (release/v3.8.51માં ઇન-ટ્રી).
- AnySearchના અધિકૃત દસ્તાવેજો: https://anysearch.com/docs, https://anysearch.com/pricing; MCP કેટલોગ mcpservers.org/servers/anysearch-ai/anysearch-mcp-server; સ્કિલ રિપોઝિટરી github.com/anysearch-ai/anysearch-skill.
