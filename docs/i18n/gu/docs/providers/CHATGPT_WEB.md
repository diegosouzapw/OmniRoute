`chatgpt-web-codex` (ઉપનામ `cgpt-codex`) પ્રમાણિત ChatGPT બ્રાઉઝર સત્ર મારફતે Codex Responses ટર્ન્સને જોડે છે. તે નિવૃત્ત થયેલા સામાન્ય `chatgpt-web` પ્રદાતાથી સ્વતંત્ર છે અને `open-sse/vendor/codex-chatgpt-web/` હેઠળની MIT સૂચનાવાળી અમલવારીનો ઉપયોગ કરે છે, જેને upstream v4.0.7 commit `b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494` દ્વારા તાજી કરવામાં આવી છે.

## સામાન્ય પ્રદાતાની નિવૃત્તિ

અગાઉના સામાન્ય પ્રદાતા IDs `chatgpt-web` અને `cgpt-web` હવે વિતરિત થતા નથી, કારણ કે તેમની pre-key/proof-of-work અમલવારીનો સ્ત્રોત સ્પષ્ટ કરી શકાયો નહોતો. slash-prefixed model IDs અને સાચવી રાખેલા ઉપનામો સહિત, બંનેમાંથી કોઈપણ ID માટેની સ્પષ્ટ વિનંતીઓ કોઈપણ upstream વિનંતી પહેલાં HTTP `410` અને કોડ **PROVIDER_RETIRED** સાથે બંધ સ્થિતિમાં નિષ્ફળ જાય છે.

Migration `168_retire_chatgpt_web.sql` મેળ ખાતા પ્રદાતા કનેક્શન્સને tombstone કરે છે અને તેમના સક્રિય session leasesને અમાન્ય કરે છે. તે કનેક્શન ઇતિહાસ અને API-key allowlists જાળવી રાખે છે; તે allowlistમાં વૈકલ્પિક ઍક્સેસ ઉમેરતું નથી. Codex પ્રદાતા અને તેના કનેક્શન્સ આ નિવૃત્તિ સાથે મેળ ખાતા નથી.

## પૂર્વજરૂરિયાતો

- સાઇન-ઇન કરેલા ChatGPT સત્રમાંથી સંપૂર્ણ Cookie header;
- npm, systemd અને PM2 ઇન્સ્ટોલેશન્સ માટે Chrome અથવા Chromium ઉપરાંત graphical session અથવા Xvfb display;
- Docker `web` profile સાથે, `docker-compose.yml`માંથી આંતરિક Chromium service;
- સ્થાનિક Codex tools માટે OpenAI `tunnel-client` v0.0.13 અને ChatGPT custom connector.

ટનલ માત્ર tool turns માટે જરૂરી છે. `pro` સહિત સૂચિબદ્ધ દરેક route, ટનલ અને connector ગોઠવેલા હોય ત્યારે સમાન turn-bound સ્થાનિક tool capabilityનો ઉપયોગ કરી શકે છે.

## Dashboard સેટઅપ

1. **ChatGPT Web (Codex)** પ્રદાતા ખોલો અને કનેક્શન ઉમેરો.
2. સંપૂર્ણ ChatGPT Cookie header, tunnel ID, runtime key અને custom connectorનું નામ પેસ્ટ કરો. નવા tool-capable સેટઅપ્સે બરાબર `OmniRoute Codex v2` નામનો નવો બનાવેલો connector જ વાપરવો જોઈએ, જેમાં Authenticationને None અને Permissionsને Allow all actions પર સેટ કરેલા હોય.
3. કનેક્શન ચકાસણી ચલાવો. OmniRoute બ્રાઉઝર-આધારિત Temporary Chat ખોલે છે અને એકાઉન્ટ માટે Sol તથા Pro ઉપલબ્ધ છે કે કેમ તે શોધે છે.
4. કનેક્શન સાચવો. OmniRoute પેસ્ટ કરેલી cookieને ચકાસેલી Playwright storage stateથી બદલે છે અને encrypted credential abstraction મારફતે તેને runtime key સાથે સંગ્રહે છે.

સફળતાપૂર્વક સાચવ્યા પછી મૂળ cookie જાળવી રાખવામાં આવતી નથી. સત્રની મુદત પૂરી થાય ત્યારે, કનેક્શન ખોલો, નવી સંપૂર્ણ Cookie header પેસ્ટ કરો અને ચકાસણી ફરીથી ચલાવો. edit dialogમાં doctor status બ્રાઉઝર, storage state, sign-in, Temporary Chat, tunnel, connector અને tool round-trip વિશે અલગથી અહેવાલ આપે છે.

> વાસ્તવિક cookie, runtime key, storage state અથવા capability token ક્યારેય commit કરશો નહીં. પરીક્ષણ અને
> દસ્તાવેજીકરણનાં મૂલ્યો હંમેશાં placeholders હોવા જોઈએ.

## Models અને combos

નિશ્ચિત model routes આ છે:

- `chatgpt-web-codex/luna` — GPT-5.6 Luna, ઓછો પ્રયાસ
- `chatgpt-web-codex/think` — GPT-5.6 Luna, મધ્યમ પ્રયાસ
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

અન્ય કોઈપણ modelની જેમ તેમાંથી એકને comboમાં ઉમેરો. Codex app નિયમિત Responses endpoint, `/v1/responses`, પર comboનું નામ `model` તરીકે મોકલે છે; કોઈ અલગ Codex endpoint અથવા mode switch નથી.

Free/Go એકાઉન્ટ્સ Luna routes ઉપલબ્ધ કરાવે છે. Sol-capable એકાઉન્ટ્સ Instantથી High સુધી ઉપલબ્ધ કરાવે છે અને Pro-capable એકાઉન્ટ્સ વધારામાં Extra High તથા Pro ઉપલબ્ધ કરાવે છે. દરેક route માટે નિશ્ચિત backend model અને reasoning effort હોય છે; પરસ્પર વિરોધી સ્પષ્ટ Responses effort પસંદ કરેલા browser modeને મૌનપણે બદલવાને બદલે બંધ સ્થિતિમાં નિષ્ફળ જાય છે.

જૂના `Codex Native` અથવા `OmniRoute Codex` connectorનું નામ બદલશો નહીં કે તેનો પુનઃઉપયોગ કરશો નહીં. ChatGPT connector identity દ્વારા જાહેર MCP contractને cache કરે છે, જ્યારે તાજું કરાયેલ bridge નવા direct turn-token contractનો ઉપયોગ કરે છે. runtime તે legacy identitiesને નકારે છે અને નવો `OmniRoute Codex v2` connector જરૂરી બનાવે છે.

## સુરક્ષા મોડેલ

- નેટિવ પાથ માટે Responses વિનંતી, માન્ય Codex ક્લાયન્ટ અને મેળ ખાતી
  થ્રેડ તથા ટર્ન ઓળખ જરૂરી છે.
- વર્કસ્પેસ, sandbox, મંજૂરી નીતિ અને ટૂલ કૅટલૉગ નેટિવ Codex shellમાંથી આવે છે;
  મુક્ત-સ્વરૂપનું પ્રોમ્પ્ટ ટેક્સ્ટ તેમના માટે અધિકૃત સ્ત્રોત નથી.
- ChatGPT દરેક ટર્ન માટે માત્ર ટૂંકા સમય માટે માન્ય ક્ષમતા મેળવે છે. MCP બ્રોકર ફક્ત
  એ જ ચોક્કસ ટર્નમાં Codex દ્વારા ઑફર કરાયેલા ટૂલ્સ સ્વીકારે છે.
- **Allow once**ને આપમેળે પુષ્ટિ આપવાથી ટૂલ વિનંતી માત્ર Codexને પાછી મોકલાય છે. મંજૂરી અને
  અમલ અંગે માત્ર Codex જ નિર્ણય લે છે.
- પ્રથમ આઉટપુટ પહેલાં, કોઈ સંયોજન અન્ય સુસંગત લક્ષ્યનો ઉપયોગ કરી શકે છે. આઉટપુટ
  શરૂ થયા પછી, ટર્ન પૂર્ણ થાય ત્યાં સુધી પ્રદાતા, મોડેલ, કનેક્શન અને બ્રાઉઝર ટર્ન પિન કરેલા
  રહે છે.
- કૂકીઝ, રનટાઇમ કીઝ, સ્ટોરેજ સ્થિતિ અને ક્ષમતા ટોકન્સ પ્રદાતાના
  પ્રતિસાદો કે વિનંતી લૉગ્સમાં દેખાતા નથી.

## ડિસ્પ્લે વિનાનું VPS અને Docker

npm, systemd અને PM2 ઇન્સ્ટૉલેશન માટે, OmniRoute સામાન્ય Chrome અને Chromium પાથ શોધે છે.
વૈકલ્પિક રીતે, `CHATGPT_WEB_CODEX_CHROME_PATH` સેટ કરો. રનટાઇમ ટર્ન્સ ઇરાદાપૂર્વક વિન્ડોવાળા
Chromeનો ઉપયોગ કરે છે કારણ કે ChatGPT સાચા હેડલેસ બ્રાઉઝરના સ્વરૂપને નકારે છે. તેથી ડિસ્પ્લે વિનાના હોસ્ટે
OmniRouteને ખાનગી Xvfb ડિસ્પ્લે સાથે ચલાવવું આવશ્યક છે; માત્ર Chrome પાથ સેટ કરવાથી ડિસ્પ્લે મળતો નથી.

Dockerની `web` પ્રોફાઇલ આંતરિક Compose નેટવર્ક પર `chatgpt-web-codex-browser` શરૂ કરે છે.
સાઇડકાર Xvfbની અંદર વિન્ડોવાળું Chrome ચલાવે છે, તેથી કોઈ ભૌતિક ડિસ્પ્લે જરૂરી નથી. તેનો CDP
પોર્ટ હોસ્ટ પર પ્રકાશિત થતો નથી. સુરક્ષિત બ્રાઉઝર પ્રોફાઇલ વૉલ્યૂમ
OmniRoute ડેટા વૉલ્યૂમથી અલગ છે અને બ્રાઉઝરને પૂરતી શેર્ડ મેમરી મળે છે. આંતરિક CDP પ્રૉક્સી
Compose નેટવર્કની અંદર માત્ર પોર્ટ `9223` પર સાંભળે છે; સાઇડકારમાં Chrome લૂપબૅક સાથે જ બંધાયેલું
રહે છે.

`DATA_DIR` હેઠળની સુપરવાઇઝર લીઝ એકથી વધુ OmniRoute પ્રક્રિયાઓને સમાન
ટનલ અને બ્રોકર સ્થિતિની માલિકી મેળવતાં અટકાવે છે. વિરોધાભાસની જાણ doctor દ્વારા કરવામાં આવે છે.

## ઇન્ટરેક્ટિવ પુનઃપ્રાપ્તિ

સ્વચાલિત Docker પાથમાં હોસ્ટને દેખાતી કોઈ વિન્ડો નથી, પરંતુ ખાનગી Xvfb
ડિસ્પ્લેની અંદર Chrome પોતે વિન્ડોવાળું છે. જ્યારે ChatGPTને ઇન્ટરેક્ટિવ સાઇન-ઇન અથવા ચૅલેન્જની જરૂર પડે, ત્યારે પુનઃપ્રાપ્તિ માટે હાલના VNC
બ્રાઉઝર ઇન્ફ્રાસ્ટ્રક્ચરનો ઉપયોગ કરી શકાય છે. બ્રાઉઝર UI અને CDP માત્ર
લૂપબૅક, પ્રમાણિત મેનેજમેન્ટ કનેક્શન અથવા SSH ટનલ દ્વારા જ પહોંચપાત્ર રહેવા જોઈએ; સામાન્ય
કાર્યપ્રવાહ દરમિયાન noVNC અક્ષમ રહે છે.

## WebSocket ફૉલબૅક

જ્યારે કોઈ સંયોજનમાં ChatGPT Web (Codex) હોય, ત્યારે Responses WebSocket બ્રિજ અપસ્ટ્રીમ સાથે
કનેક્ટ થતાં પહેલાં HTTP/SSE ફૉલબૅકની વિનંતી કરે છે. ત્યારબાદ ટ્રાન્સફર
`/v1/responses` દ્વારા થાય છે.
