IDE સેશન વિના Cursorને OmniRoute પાછળ મૂકવાની બે રીતો:

1. **`cursor-api` પ્રોવાઇડર** (કાર્ડ "Cursor API", ઉપનામ `cua`): API કી-આધારિત
   પ્રોવાઇડર, જે Cursor વપરાશકર્તાની API કી (`crsr_…`, જે
   `https://cursor.com/dashboard/api` પર જનરેટ થાય છે) રાખે છે. ત્યારબાદ કોઈપણ OmniRoute ક્લાયન્ટ
   સામાન્ય ક્વોટા, ફૉલબૅક અને લૉગિંગ લેયર્સ સાથે `/v1/chat/completions` મારફતે
   `cursor-api/<model>` અથવા `cua/<model>` તરીકે Cursor મોડલ્સ ઍક્સેસ કરે છે. IDE
   પ્રોવાઇડર (`cursor`, OAuth/IDE સેશન) યથાવત્ રહે છે.
2. **Cursor CLI પાસથ્રૂ**: Cursor CLI (`agent`)ને OmniRoute તરફ નિર્દેશિત કરો જેથી
   CLI દ્વારા કરવામાં આવતી દરેક RPC OmniRoute API કી વડે પ્રમાણિત થાય, તેને
   `cursor-api` કનેક્શનના ક્રેડેન્શિયલ સાથે Cursor પર ફૉરવર્ડ કરવામાં આવે અને
   Logs પેજમાં રેકોર્ડ કરવામાં આવે.

## કીનું વિનિમય શા માટે થાય છે

`api2.cursor.sh` કાચી `crsr_…` કીને Bearer ટોકન તરીકે નકારે છે (401). Cursor
CLI પહેલાં કીને `/auth/exchange_user_api_key` પર POST કરે છે અને એક કલાક પછી
સમાપ્ત થતું સેશન JWT મેળવે છે; પરત મળેલું `refreshToken` સમાન
`exp` ધરાવે છે, તેથી રિફ્રેશ કરવાનો અર્થ કીનું ફરીથી વિનિમય કરવું છે.
`open-sse/services/cursorApiKeyAuth.ts` આ વિનિમય કરે છે, દરેક કી દીઠ એક સેશન
ટોકન કૅશ કરે છે, સમાપ્તિથી પાંચ મિનિટ પહેલાં ફરીથી વિનિમય કરે છે અને Cursor
401 જવાબ આપે ત્યારે કૅશ કરેલું ટોકન કાઢી નાખે છે. `CursorExecutor`
`cursor-api` કનેક્શન્સ માટે અપસ્ટ્રીમ સ્ટ્રીમ ખોલતાં તરત પહેલાં તેને કૉલ કરે છે.

## `cursor-api` પ્રોવાઇડર

રજિસ્ટ્રી: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, `cursor` જેવા જ `format`, `baseUrl` અને
`models`). કૅટલૉગ કાર્ડ:
`src/shared/constants/providers/apikey/specialty-media.ts`. એક્ઝિક્યુટર મૅપ:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

ડૅશબોર્ડ: Providers → Cursor API → Add API key.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

પછી:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

નોંધો:

- `cursor-api` માટેની મોડલ સૂચિ સ્થિર Cursor રજિસ્ટ્રીમાંથી આવે છે (એ જ સૂચિ
  જેનો IDE પ્રોવાઇડર ફૉલબૅક તરીકે ઉપયોગ કરે છે); OmniRoute હોસ્ટ પર
  `cursor-agent` ઇન્સ્ટૉલ કરવાની જરૂર નથી.
- `POST /api/providers/{id}/refresh-cursor` ફક્ત `cursor` IDE પ્રોવાઇડર માટે
  છે; `cursor-api` કનેક્શન્સ પાસે રિન્યૂ કરવા માટે કોઈ IDE સેશન નથી.

## મૂળ મોડલ IDs અને પ્રયત્ન

`cursor` / `cu` અને `cursor-api` / `cua` માટે, શેર કરેલું Claude-પ્રયત્ન નૉર્મલાઇઝર
વિનંતી કરેલ મોડલ IDને યથાવત્ રાખે છે. Cursor કોઈ OmniRoute પ્રયત્ન ઉપનામ તરીકે
નહીં, પરંતુ વાસ્તવિક મોડલ IDના ભાગરૂપે `-low` જેવું સફિક્સ જાહેર કરી શકે છે.
Cursor એક્ઝિક્યુટર લાઇવ કૅટલૉગમાં મળતી ચોક્કસ મેળવણી જાળવી રાખે છે; જ્યારે કોઈ
મેળવણી ન હોય, ત્યારે તેનું હાલનું મોડલ રિઝૉલ્વર સફિક્સ-થી-પૅરામીટર ફૉલબૅક સંભાળે છે.

આનાથી સીધા Claude, Claude-સુસંગત અથવા Vertex રૂટ્સ માટે પ્રયત્ન નૉર્મલાઇઝેશનમાં
કોઈ ફેરફાર થતો નથી. ઉપલબ્ધતા હજુ પણ પસંદ કરેલા Cursor એકાઉન્ટના કૅટલૉગ અને
અધિકાર પર આધારિત છે.

## Cursor CLI પાસથ્રૂ

રૂટ: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. ઉપસર્ગ `/api/cursor-cli/` ને
`src/shared/constants/publicApiRoutes.ts` માં નોંધવામાં આવ્યો છે કારણ કે હેન્ડલર
પોતાનું પ્રમાણીકરણ લાગુ કરે છે:

| પાથ                                                                                                                       | CLI પાસેથી અપેક્ષિત પ્રમાણીકરણ | OmniRoute શું કરે છે                                                                                                                                                            |
| ------------------------------------------------------------------------------------------------------------------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                        | `Bearer <OmniRoute API key>`   | કીને માન્ય કરે છે, 1 કલાક માટે HS256 JWT (`JWT_SECRET` વડે સહી કરેલું) બનાવે છે અને તેને પરત કરે છે                                                                             |
| દરેક અન્ય પાથ (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`            | ઇશ્યુઅર/ઑડિયન્સ/સમાપ્તિની ચકાસણી કરે છે, સક્રિય `cursor-api` કનેક્શન પસંદ કરે છે, Authorization હેડરને એક્સચેન્જ કરેલા Cursor ટોકનથી બદલે છે અને પ્રતિસાદને પાછો સ્ટ્રીમ કરે છે |

CLI તેને મળતા કોઈપણ ટોકનમાંથી `exp` ડિકોડ કરે છે, તેથી તેને અપારદર્શક
ટોકન આપવાથી તે લગભગ દરેક વિનંતી પહેલાં ફરીથી એક્સચેન્જ કરે છે; બનાવેલું JWT
આવું થતું અટકાવે છે. OmniRoute તરફથી મળતો 401 CLI ને ફરીથી એક્સચેન્જ કરવા પ્રેરે છે.

### સેટઅપ

1. OmniRoute API કી (Dashboard → API keys) અને `cursor-api`
   કનેક્શન બનાવો.
2. CLI ને એજન્ટ સ્ટ્રીમ માટે HTTP/1.1 વાપરવાનું કહો.
   `~/.cursor/cli-config.json` માં:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   આ વિના CLI અલગથી ગોઠવાયેલા એજન્ટ હોસ્ટ માટે HTTP/2 પર એજન્ટ ટર્ન ખોલે છે
   અને માત્ર કંટ્રોલ-પ્લેન RPC જ એન્ડપોઇન્ટમાંથી પસાર થાય છે.

3. OmniRoute સામે CLI ચલાવો:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

દરેક હોપ Logs માં પ્રદાતા `cursor-api`, વિનંતી પ્રકાર `cursor-cli`,
પાથ `/api/cursor-cli/<rpc>` તરીકે નોંધાય છે અને તે OmniRoute API કી તથા તેને
સેવા આપનાર કનેક્શન સાથે સંકળાયેલો હોય છે.

### નિષ્ફળતાની સ્થિતિઓ

| પરિસ્થિતિ                                       | CLI ને મળતો પ્રતિસાદ                               |
| ----------------------------------------------- | -------------------------------------------------- |
| અજ્ઞાત OmniRoute કી અને `REQUIRE_API_KEY=true`  | એક્સચેન્જ વખતે 401 `unauthenticated`               |
| `REQUIRE_API_KEY=false`                         | અનામી સત્ર (`/v1/*` ના વર્તનને પ્રતિબિંબિત કરે છે) |
| સમાપ્ત થયેલું / વિદેશી / છેડછાડ કરેલું સત્ર JWT | 401, CLI ફરીથી એક્સચેન્જ કરે છે                    |
| એક્સચેન્જ પછી OmniRoute API કી રદ કરવામાં આવી   | આગામી RPC પર 401                                   |
| કોઈ સક્રિય `cursor-api` કનેક્શન નથી             | 503 `unavailable`                                  |
| Cursor કનેક્શનની કીને નકારે છે                  | 401 `unauthenticated`, કૅશ કરેલું સત્ર દૂર થાય છે  |
| અપસ્ટ્રીમ સુધી પહોંચી શકાતું નથી                | 502 `unavailable` (શુદ્ધ કરેલો સંદેશ)              |
| `JWT_SECRET` સેટ નથી                            | એક્સચેન્જ વખતે 503                                 |
