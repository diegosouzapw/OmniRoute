IDE સત્ર વિના Cursorને OmniRoute પાછળ મૂકવાની બે રીતો:

1. **`cursor-api` પ્રદાતા** (કાર્ડ "Cursor API", ઉપનામ `cua`): API કી
   પ્રદાતા, જે Cursor વપરાશકર્તા API કી (`crsr_…`, જે
   `https://cursor.com/dashboard/api` પર જનરેટ થાય છે) સાચવે છે. ત્યારબાદ કોઈપણ OmniRoute ક્લાયન્ટ
   સામાન્ય ક્વોટા, ફૉલબૅક અને લૉગિંગ સ્તરો સાથે `/v1/chat/completions` મારફતે
   `cursor-api/<model>` અથવા `cua/<model>` તરીકે Cursor મોડલ્સને ઍક્સેસ કરે છે. IDE
   પ્રદાતા (`cursor`, OAuth/IDE સત્ર) યથાવત્ રહે છે.
2. **Cursor CLI પાસથ્રૂ**: Cursor CLI (`agent`)ને OmniRoute તરફ નિર્દેશિત કરો, જેથી
   CLI દ્વારા કરાતી દરેક RPC OmniRoute API કી વડે પ્રમાણિત થાય,
   `cursor-api` કનેક્શનના ક્રેડેન્શિયલ સાથે Cursorને ફૉર્વર્ડ થાય અને
   લૉગ્સ પેજમાં નોંધાય.

## કીનું વિનિમય શા માટે થાય છે

`api2.cursor.sh` કાચી `crsr_…` કીને Bearer ટોકન તરીકે નકારે છે (401). Cursor
CLI પહેલાં કીને `/auth/exchange_user_api_key` પર POST કરે છે અને એક કલાક પછી
સમાપ્ત થતું સત્ર JWT મેળવે છે; પાછું મળેલું `refreshToken` પણ એ જ
`exp` ધરાવે છે, તેથી રિફ્રેશ કરવાનો અર્થ કીનું ફરીથી વિનિમય કરવો થાય છે.
`open-sse/services/cursorApiKeyAuth.ts` આ વિનિમય કરે છે, દરેક કી દીઠ એક સત્ર
ટોકન કૅશ કરે છે, સમાપ્તિ પહેલાં પાંચ મિનિટે ફરી વિનિમય કરે છે અને Cursor તરફથી
401 જવાબ મળે ત્યારે કૅશ કરેલું ટોકન દૂર કરે છે. `CursorExecutor`,
`cursor-api` કનેક્શન્સ માટે અપસ્ટ્રીમ સ્ટ્રીમ ખોલતા તરત પહેલાં તેને કૉલ કરે છે.

## `cursor-api` પ્રદાતા

રજિસ્ટ્રી: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, `cursor` જેવા જ `format`, `baseUrl` અને
`models`). કૅટલૉગ કાર્ડ:
`src/shared/constants/providers/apikey/specialty-media.ts`. એક્ઝિક્યુટર મૅપ:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

ડૅશબોર્ડ: પ્રદાતાઓ → Cursor API → API કી ઉમેરો.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

ત્યારબાદ:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

નોંધો:

- `cursor-api` માટે મોડલ સૂચિ સ્થિર Cursor રજિસ્ટ્રીમાંથી આવે છે (એ જ
  સૂચિ, જેનો IDE પ્રદાતા ફૉલબૅક તરીકે ઉપયોગ કરે છે); OmniRoute હોસ્ટ પર
  `cursor-agent` ઇન્સ્ટૉલ કરવાની જરૂર નથી.
- `POST /api/providers/{id}/refresh-cursor` ફક્ત `cursor` IDE પ્રદાતા માટે છે;
  `cursor-api` કનેક્શન્સ પાસે નવીકરણ કરવા માટે કોઈ IDE સત્ર હોતું નથી.

## મૂળ મોડલ IDs અને પ્રયાસ

`cursor` / `cu` અને `cursor-api` / `cua` માટે, સહિયારું Claude-પ્રયાસ નોર્મલાઇઝર
વિનંતી કરાયેલ મોડલ IDને યથાવત્ રાખે છે. Cursor, OmniRoute પ્રયાસ ઉપનામ તરીકે નહીં,
પરંતુ વાસ્તવિક મોડલ IDના ભાગરૂપે `-low` જેવો પ્રત્યય જાહેર કરી શકે છે.
Cursor એક્ઝિક્યુટર ચોક્કસ લાઇવ-કૅટલૉગ મેળ જાળવી રાખે છે; જ્યારે કોઈ મેળ ન હોય,
ત્યારે તેનું હાલનું મોડલ રિઝૉલ્વર પ્રત્યય-થી-પૅરામીટર ફૉલબૅક સંભાળે છે.

આ સીધા Claude, Claude-સુસંગત અથવા Vertex રૂટ્સ માટે પ્રયાસ નોર્મલાઇઝેશનમાં
ફેરફાર કરતું નથી. ઉપલબ્ધતા હજુ પણ પસંદ કરાયેલા Cursor એકાઉન્ટના
કૅટલૉગ અને અધિકાર પર આધારિત છે.

## Cursor CLI પાસથ્રૂ

રૂટ: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. પ્રિફિક્સ `/api/cursor-cli/` ને
`src/shared/constants/publicApiRoutes.ts` માં રજિસ્ટર કરવામાં આવ્યો છે, કારણ કે હેન્ડલર
પોતાનું પ્રમાણીકરણ લાગુ કરે છે:

| પાથ                                                                                                                       | CLI પાસેથી અપેક્ષિત પ્રમાણીકરણ | OmniRoute શું કરે છે                                                                                                                                                   |
| ------------------------------------------------------------------------------------------------------------------------- | ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                        | `Bearer <OmniRoute API key>`   | કીને માન્ય કરે છે, 1 કલાક માટેનું HS256 JWT (`JWT_SECRET` વડે સહી કરેલું) બનાવે છે અને તેને પરત કરે છે                                                                 |
| અન્ય દરેક પાથ (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`            | ઇશ્યુઅર/ઑડિયન્સ/સમાપ્તિ ચકાસે છે, સક્રિય `cursor-api` કનેક્શન પસંદ કરે છે, Authorization હેડરને એક્સચેન્જ કરેલા Cursor ટોકનથી બદલે છે અને પ્રતિસાદ પાછો સ્ટ્રીમ કરે છે |

CLI તેને મળતા કોઈપણ ટોકનમાંથી `exp` ડિકોડ કરે છે, તેથી તેને અપારદર્શક
ટોકન આપવાથી તે લગભગ દરેક રિક્વેસ્ટ પહેલાં ફરીથી એક્સચેન્જ કરે છે; બનાવેલું JWT
આને ટાળે છે. OmniRoute તરફથી મળતો 401 CLI ને ફરીથી એક્સચેન્જ કરાવે છે.

### સેટઅપ

1. OmniRoute API કી (Dashboard → API keys) અને `cursor-api`
   કનેક્શન બનાવો.
2. CLI ને એજન્ટ સ્ટ્રીમ માટે HTTP/1.1 વાપરવાનું કહો.
   `~/.cursor/cli-config.json` માં:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   આના વિના CLI અલગથી કન્ફિગર કરેલા એજન્ટ હોસ્ટ પર HTTP/2 દ્વારા એજન્ટ ટર્ન ખોલે છે
   અને માત્ર કંટ્રોલ-પ્લેન RPCs જ એન્ડપોઇન્ટ મારફતે જાય છે.

3. OmniRoute સામે CLI ચલાવો:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

દરેક હોપ Logs માં પ્રોવાઇડર `cursor-api`, રિક્વેસ્ટ પ્રકાર `cursor-cli`,
પાથ `/api/cursor-cli/<rpc>` તરીકે નોંધાય છે અને તેને OmniRoute API કી તથા
તેને સર્વ કરનાર કનેક્શન સાથે સાંકળવામાં આવે છે.

### નિષ્ફળતાની પરિસ્થિતિઓ

| પરિસ્થિતિ                                      | CLI ને મળતો પ્રતિસાદ                                        |
| ---------------------------------------------- | ----------------------------------------------------------- |
| અજાણી OmniRoute કી અને `REQUIRE_API_KEY=true`  | એક્સચેન્જ વખતે 401 `unauthenticated`                        |
| `REQUIRE_API_KEY=false`                        | અનામી સેશન (`/v1/*` ની વર્તણૂકને પ્રતિબિંબિત કરે છે)        |
| સમાપ્ત થયેલું / વિદેશી / ચેડાં કરેલું સેશન JWT | 401, CLI ફરીથી એક્સચેન્જ કરે છે                             |
| એક્સચેન્જ પછી OmniRoute API કી રદ કરાઈ         | આગામી RPC પર 401                                            |
| કોઈ સક્રિય `cursor-api` કનેક્શન નથી            | 503 `unavailable`                                           |
| Cursor કનેક્શનની કીને નકારે છે                 | 401 `unauthenticated`, કૅશ કરેલું સેશન કાઢી નાખવામાં આવે છે |
| અપસ્ટ્રીમ પહોંચી શકાય તેમ નથી                  | 502 `unavailable` (સેનિટાઇઝ કરેલો સંદેશ)                    |
| `JWT_SECRET` સેટ નથી                           | એક્સચેન્જ વખતે 503                                          |
