## `claude-web`

`claude-web` પ્રમાણિત `claude.ai` બ્રાઉઝર સેશન મારફતે OpenAI-ફોર્મેટ ચેટ વિનંતીઓ મોકલે છે. એક્ઝિક્યુટર આપેલી કૂકીને સામાન્યકૃત કરે છે, એક પ્રમાણિત સંસ્થાનું નિરાકરણ કરે છે, વાર્તાલાપની સ્થિતિ તૈયાર કરે છે, ડાયરેક્ટ અથવા બ્રાઉઝર ટ્રાન્સપોર્ટ પસંદ કરે છે અને અપસ્ટ્રીમ SSE પ્રતિસાદનું કડક રીતે રૂપાંતર કરે છે. ઓર્કેસ્ટ્રેશન `open-sse/executors/claude-web.ts:320` માં છે.

> **Web Cookie પ્રદાતાઓ માટે નવા છો?**
>
> આ પ્રદાતા-વિશિષ્ટ માર્ગદર્શિકાને અનુસરતા પહેલાં સામાન્ય સેટઅપ પ્રક્રિયા, પ્રમાણીકરણ માર્ગદર્શન, મર્યાદાઓ અને સમસ્યાનિવારણ માટે **`docs/getting-started/WEB-COOKIE-GUIDE.md`** વાંચો.

### મોડેલ કેટલોગ

પ્રદાતા રજિસ્ટ્રી હાલમાં ચોક્કસપણે આ સાત સ્થિર મોડેલ ID ઉપલબ્ધ કરાવે છે
(`open-sse/config/providers/registry/claude/web/index.ts:11`):

| મોડેલ ID                    | પ્રદર્શિત નામ           |
| --------------------------- | ----------------------- |
| `claude-fable-5`            | Claude Fable 5 (વેબ)    |
| `claude-opus-4-8`           | Claude Opus 4.8 (વેબ)   |
| `claude-sonnet-5`           | Claude Sonnet 5 (વેબ)   |
| `claude-haiku-4-5-20251001` | Claude Haiku 4.5 (વેબ)  |
| `claude-opus-4-7`           | Claude Opus 4.7 (વેબ)   |
| `claude-opus-4-6`           | Claude Opus 4.6 (વેબ)   |
| `claude-sonnet-4-6`         | Claude Sonnet 4.6 (વેબ) |

આ પ્રદાતા માટે ડાયનેમિક મોડેલ શોધ અમલમાં મૂકવામાં આવી નથી. ઉપરની સૂચિ રનટાઇમ કેટલોગ છે.

### ક્રેડેન્શિયલ્સ અને સંસ્થાનું નિરાકરણ

સંપૂર્ણ `claude.ai` Cookie હેડર અથવા માત્ર સેશન મૂલ્ય આપો. માત્ર મૂલ્યોને `sessionKey` તરીકે સામાન્યકૃત કરવામાં આવે છે; અન્ય કૂકીઝ આપવામાં આવી હોય તો જાળવી રાખવામાં આવે છે. એક્ઝિક્યુટર `cookie` અથવા `apiKey` મારફતે કૂકી સ્વીકારે છે અને કનેક્શન ડેટામાંથી વૈકલ્પિક `deviceId` અને `orgId` મૂલ્યો વાંચે છે
(`open-sse/executors/claude-web.ts:72`).

જો `orgId` ગેરહાજર હોય, તો એક્ઝિક્યુટર `GET https://claude.ai/api/organizations` ને કૉલ કરે છે અને પ્રમાણિત Claude Web સેશન દ્વારા પરત કરાયેલી પ્રથમ સંસ્થાનો ઉપયોગ કરે છે
(`open-sse/executors/claude-web.ts:141`). કોઈ માન્ય સંસ્થા પરત ન થાય ત્યારે તે સુરક્ષિત રીતે નિષ્ફળ જાય છે, નકારાયેલ સેશન અધિકૃતતાને 401 તરીકે અહેવાલ આપે છે અને Cloudflare ચેલેન્જને પ્રમાણીકરણ નિષ્ફળતાથી અલગ પાડે છે.

### વાર્તાલાપ ઑપરેશન્સ

વૈકલ્પિક ટોચ-સ્તરીય `claude_web` ઑબ્જેક્ટ કડક છે. અજ્ઞાત ફીલ્ડ્સ નકારવામાં આવે છે. તેના સ્વીકૃત ફીલ્ડ્સ `open-sse/executors/claude-web/session.ts:50` માં વ્યાખ્યાયિત છે:

| ફીલ્ડ                 | અર્થ                                                          |
| --------------------- | ------------------------------------------------------------- |
| `operation`           | ડિફૉલ્ટ રૂપે `completion`; પુનઃપ્રયાસ ટર્ન માટે `retry` વાપરો |
| `conversation_id`     | હાલના વાર્તાલાપ માટે સ્પષ્ટ UUID                              |
| `parent_message_uuid` | પેરન્ટ આસિસ્ટન્ટ સંદેશ માટે સ્પષ્ટ UUID                       |
| `timezone`            | માન્ય IANA સમય-ઝોન નામ                                        |
| `locale`              | માળખાકીય રીતે માન્ય લોકેલ                                     |
| `tool_states`         | વૈકલ્પિક એકાઉન્ટ ટૂલ-સ્ટેટ ઍરે, 128 એન્ટ્રીઓ સુધી મર્યાદિત    |

તૈયાર કરેલી વિનંતીઓ બે અપસ્ટ્રીમ એન્ડપોઇન્ટ્સમાંથી એકનો ઉપયોગ કરે છે
(`open-sse/executors/claude-web.ts:203`):

- નવો અથવા અનુવર્તી ટર્ન
  `POST https://claude.ai/api/organizations/{orgId}/chat_conversations/{conversationId}/completion` પર પોસ્ટ કરે છે.
- પુનઃપ્રયાસ
  `POST https://claude.ai/api/organizations/{orgId}/chat_conversations/{conversationId}/retry_completion` પર પોસ્ટ કરે છે.

નવા ટર્નમાં `create_conversation_params` સામેલ હોય છે. કૅશ કરેલા અથવા સ્પષ્ટ રીતે લિંક કરેલા અનુવર્તી ટર્નમાં `parent_message_uuid` સામેલ હોય છે અને `create_conversation_params` છોડવામાં આવે છે. પુનઃપ્રયાસ માટે વાર્તાલાપ અને પેરન્ટ-સંદેશ બંનેની સ્થિતિ જરૂરી છે અને તે કોઈ પ્રોમ્પ્ટ મોકલતો નથી
(`open-sse/executors/claude-web/session.ts:254`). નવા વાર્તાલાપ પ્રમાણિત UI ને `/new` પર ખોલે છે; કૅશ કરેલા અથવા સ્પષ્ટ રીતે લિંક કરેલા અનુવર્તી ટર્ન ચોક્કસ વાર્તાલાપ પેજ ખોલે છે
(`open-sse/executors/claude-web/session.ts:324`).

વાર્તાલાપની સ્થિતિ એ SHA-256 એકાઉન્ટ સ્કોપ અને કૅનોનિકલ કૉલર ટ્રાન્સક્રિપ્ટ દ્વારા કી કરાયેલ ઇન-મેમરી કૅશ છે. એન્ટ્રીઓ 30 મિનિટ પછી સમાપ્ત થાય છે અને કૅશ 5,000 એન્ટ્રીઓ સુધી મર્યાદિત છે
(`open-sse/executors/claude-web/session.ts:12`). કડક સ્ટ્રીમ પાર્સર `message_stop` નિરીક્ષણ કરે ત્યાર પછી જ સ્થિતિ કમિટ થાય છે; પ્રોસેસ પુનઃપ્રારંભ તેને કાઢી નાખે છે. કૅશ મિસ પર, અગાઉના સંદેશાઓને મૌન રીતે છોડવાને બદલે બહુ-સંદેશ વિનંતીને એક રિકવરી પ્રોમ્પ્ટમાં સિરિયલાઇઝ કરવામાં આવે છે.

લોકેલ અને સમય ઝોન માટે આ અગ્રતા વપરાય છે: વિનંતીનું `claude_web` મૂલ્ય, કનેક્શન મૂલ્ય, રનટાઇમ મૂલ્ય, પછી લોકેલ માટે `en-US` અથવા સમય ઝોન માટે `UTC`
(`open-sse/executors/claude-web/session.ts:218`).

### ટૂલ્સ અને વિનંતી પેલોડ્સ

ડાયરેક્ટ વિનંતીઓ ફક્ત કૉલર દ્વારા આપેલા માળખાકીય રીતે માન્ય OpenAI ફંક્શન ટૂલ્સને રૂપાંતરિત કરે છે. કોઈ બનાવટી સ્થિર ડિફૉલ્ટ ટૂલ સૂચિ નથી
(`open-sse/executors/claude-web/payload.ts:102`).

તેના બદલે બ્રાઉઝર વિનંતીઓ પ્રમાણિત UI વિનંતીને કૅપ્ચર કરે છે અને તેના એકાઉન્ટ ટૂલ્સ, ટૂલ સ્ટેટ્સ અને વ્યક્તિગત શૈલીઓ જાળવી રાખે છે. તૈયાર કરેલા વાર્તાલાપ, મોડેલ, રીઝનિંગ, પ્રોમ્પ્ટ અને સંદેશ UUID ફીલ્ડ્સ હજી પણ કૅપ્ચર કરેલી વિનંતીને ઓવરરાઇડ કરે છે
(`open-sse/executors/claude-web/browserTransport.ts:175`). બ્રાઉઝર ટેમ્પ્લેટ્સ એકાઉન્ટ, સંસ્થા, કૂકી, લોકેલ અને સમય ઝોનના હૅશ દ્વારા સ્કોપ કરવામાં આવે છે અને 30 મિનિટ પછી સમાપ્ત થાય છે
(`open-sse/executors/claude-web/browserTransport.ts:11`,
`open-sse/executors/claude-web/browserTransport.ts:158`). જ્યારે ડાયરેક્ટ વિનંતીમાં કૉલર ટૂલ્સ ન હોય, ત્યારે તે તે સ્કોપ કરેલા ટેમ્પ્લેટનો ફરી ઉપયોગ કરી શકે છે; સ્પષ્ટ કૉલર ટૂલ્સને અગ્રતા મળે છે
(`open-sse/executors/claude-web/browserTransport.ts:214`).

### ટ્રાન્સપોર્ટ પસંદગી

ડિફૉલ્ટ પાથ `sendClaudeWebDirect()` છે, જે કૉન્ફિગર કરેલી Chrome 146 પ્રોફાઇલ અને આપેલી કૂકી સાથે `tlsFetchClaude()` ને કૉલ કરે છે (`open-sse/services/claudeTlsClient.ts:23`). તે કોઈ સોલ્વર શરૂ કરતું નથી અથવા બદલી કૂકી બનાવતું નથી.

એકાઉન્ટ-સ્કોપ્ડ બ્રાઉઝર ઍડેપ્ટરને પ્રાથમિક ટ્રાન્સપોર્ટ બનાવવા માટે `WEB_COOKIE_USE_BROWSER` ને `1`, `true`, અથવા `on` પર સેટ કરો. ઓળખાયેલ Cloudflare 403 ચૅલેન્જ આવે ત્યારે ડાયરેક્ટ ટ્રાન્સપોર્ટમાંથી બ્રાઉઝર ઍડેપ્ટર પર ફૉલબૅક કરવાની મંજૂરી આપવા માટે `OMNIROUTE_BROWSER_POOL` ને પણ આ જ મૂલ્યોમાંથી કોઈ એક પર સેટ કરો (`open-sse/executors/claude-web.ts:195`). અન્ય HTTP નિષ્ફળતાઓ આ ફૉલબૅકને ટ્રિગર કરતી નથી.

બ્રાઉઝર ઍડેપ્ટર એ જ પૂલ કરેલા Playwright કૉન્ટેક્સ્ટની અંદર કૂકીઝ રાખે છે, ઉપર વર્ણવેલી સ્કોપ્ડ હૅશ્ડ કીનો ઉપયોગ કરે છે અને એ જ કૉન્ટેક્સ્ટમાંથી કમ્પ્લીશન મોકલે છે (`open-sse/executors/claude-web/browserTransport.ts:444`). તે બ્રાઉઝર દ્વારા ઉકેલાયેલી કૂકીને ક્યારેય ડાયરેક્ટ TLS ક્લાયન્ટમાં એક્સપોર્ટ કરતું નથી. બ્રાઉઝર રિટ્રાય માટે એ જ વાસ્તવિક Playwright કૉન્ટેક્સ્ટ સાથે બંધાયેલું અને સમયસીમા સમાપ્ત ન થયેલું UI ટેમ્પલેટ જરૂરી છે (`open-sse/executors/claude-web/browserTransport.ts:467`). બ્રાઉઝર રિસ્પૉન્સ રીડ્સ પ્રમાણિત પેજમાં ક્રમશઃ ચાલે છે, રિક્વેસ્ટ રદ કરવાનું માન્ય રાખે છે અને અપસ્ટ્રીમ બૉડી 16 MiB કરતાં વધી જાય કે તરત તેને રદ કરે છે (`open-sse/executors/claude-web/browserTransport.ts:259`).

એક્ઝિક્યુટર શેર કરેલા રિક્વેસ્ટ લૉગરને રિડેક્ટ કરેલું ઑડિટ પ્રોજેક્શન પરત કરે છે: ઑર્ગેનાઇઝેશન, કન્વર્સેશન અને મેસેજ UUIDs, પ્રોમ્પ્ટ ટેક્સ્ટ, ટૂલ વ્યાખ્યાઓ, કૂકીઝ અને ડિવાઇસ આઇડેન્ટિફાયર્સને બાકાત રાખવામાં આવે છે (`open-sse/executors/claude-web.ts:237`,
`open-sse/executors/claude-web.ts:252`). ટ્રાન્સપોર્ટ એક્સેપ્શન્સ પણ થ્રો થયેલા મેસેજને બદલે સામાન્ય કનેક્શન ભૂલ પરત કરે છે.

### SSE વર્તણૂક

`createClaudeWebResponse()` LF અથવા CRLF ફ્રેમિંગ અને બહુ-લાઇન `data:` ફીલ્ડ્સને સંભાળે છે. તે ટેક્સ્ટ ડેલ્ટાને `content` સાથે, થિંકિંગ ડેલ્ટાને `reasoning_content` સાથે અને જાણીતી મેટાડેટા ઇવેન્ટ્સને `claude_web` રિસ્પૉન્સ એક્સ્ટેન્શન સાથે મૅપ કરે છે. દરેક મેટાડેટા ઇવેન્ટને તેની પોતાની ફીલ્ડ અલાઉલિસ્ટ મારફતે પ્રોજેક્ટ કરવામાં આવે છે (`open-sse/executors/claude-web/stream.ts:37`). કન્વર્સેશન, પેરેન્ટ-મેસેજ, આસિસ્ટન્ટ-મેસેજ અને ઑપરેશન મેટાડેટા પણ `X-OmniRoute-Claude-Web-*` હેડર્સમાં પરત કરવામાં આવે છે (`open-sse/executors/claude-web/stream.ts:364`).

ખામીયુક્ત JSON, અપસ્ટ્રીમ `error` ઇવેન્ટ્સ, અજાણ્યા ઇવેન્ટ પ્રકારો, અમાન્ય ક્રમ, કન્ટેન્ટ-બ્લૉક અસંગતતાઓ અથવા `message_stop` પહેલાં EOF આવે ત્યારે પાર્સર સુરક્ષિત રીતે નિષ્ફળ થાય છે. સ્ટ્રીમિંગ આઉટપુટ એક ફિનિશ ચંક અને એક `[DONE]` ઉત્સર્જિત કરે છે; બફર્ડ આઉટપુટ એ જ પાર્સરનો ઉપયોગ કરે છે. પાર્સર `message_stop` ને તરત જ ટર્મિનલ માને છે, ત્યારપછીનો અપસ્ટ્રીમ ડેટા રદ કરે છે અને ડાઉનસ્ટ્રીમ રદ કરવાની ક્રિયાને અપસ્ટ્રીમ રીડર સુધી પ્રસારિત કરે છે (`open-sse/executors/claude-web/stream.ts:461`,
`open-sse/executors/claude-web/stream.ts:563`). સમાપ્ત ન થયેલી SSE લાઇન્સ અને સંચિત ઇવેન્ટ્સને 1 MiB સુધી મર્યાદિત કરવામાં આવે છે (`open-sse/executors/claude-web/stream.ts:17`,
`open-sse/executors/claude-web/stream.ts:62`).

### પરીક્ષણ

વાસ્તવિક ક્રેડેન્શિયલ્સ વિના નિર્ધારિત Claude Web સ્યુટ ચલાવો:

```powershell
node --import tsx/esm --test tests/unit/claude-web-auto-refresh.test.ts tests/unit/claude-web-browser-transport.test.ts tests/unit/claude-web-executor-split.test.ts tests/unit/claude-web-live-alignment.test.ts tests/unit/claude-web-payload-runtime.test.ts tests/unit/claude-web-session.test.ts tests/unit/claude-web-sonnet5-registry-6209.test.ts tests/unit/claude-web-stream.test.ts tests/unit/claude-web-transport.test.ts tests/unit/claude-web.test.ts tests/unit/issue-6662-repro.test.ts
```

`tests/unit/claude-web-auto-refresh.test.ts` માં Playwright-આધારિત કેસોને સ્પષ્ટ રીતે સ્કિપ કરવામાં આવ્યા છે. આ રિપોઝિટરી હાલમાં ક્રેડેન્શિયલ ધરાવતી Claude Web લાઇવ-ટેસ્ટ સ્ક્રિપ્ટ વ્યાખ્યાયિત કરતી નથી, તેથી સ્કિપ કરેલા આ કેસો રનટાઇમ પુરાવો નથી.

### સેટઅપ

1. `npm run dev` અથવા બિલ્ટ ઇન્સ્ટોલેશન વડે OmniRoute શરૂ કરો.
2. Dashboard → Providers → Add Provider ખોલો.
3. Web Cookie કૅટેગરી અને Claude Web પસંદ કરો.
4. પ્રમાણિત `claude.ai` રિક્વેસ્ટમાંથી કૉપી કરેલું સંપૂર્ણ Cookie હેડર પેસ્ટ કરો.
