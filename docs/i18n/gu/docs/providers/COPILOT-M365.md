`copilot-m365-web` (ઉપનામ `m365copilot`) `m365.cloud.microsoft/chat` પરના પ્રમાણિત Microsoft 365 Copilot BizChat બ્રાઉઝર સત્ર દ્વારા OpenAI-ફોર્મેટ ચેટ વિનંતીઓ મોકલે છે. આ એક બિનસત્તાવાર એકીકરણ છે.

> **Web Cookie પ્રદાતાઓ માટે નવા છો?**
>
> આ પ્રદાતા-વિશિષ્ટ માર્ગદર્શિકાને અનુસરતા પહેલાં સામાન્ય સેટઅપ પ્રક્રિયા, પ્રમાણીકરણ માર્ગદર્શન, મર્યાદાઓ અને સમસ્યાનિવારણ માટે **`docs/getting-started/WEB-COOKIE-GUIDE.md`** વાંચો.
>
> **મહત્વપૂર્ણ:** આ પ્રદાતા માટેનું ઓળખપત્ર **કૂકી નથી**. `m365.cloud.microsoft` પરથી કૂકીઝ કૉપિ કરશો નહીં. ઓળખપત્ર એ WebSocket URL ક્વેરી પેરામીટર અને પાથ સેગમેન્ટ છે, જે બંને DevTools Network ટૅબમાંથી વાંચવામાં આવે છે.

## પૂર્વજરૂરિયાતો

- `m365.cloud.microsoft/chat` પર BizChat ઍક્સેસ ધરાવતું Microsoft 365 એકાઉન્ટ
- DevTools WebSocket નિરીક્ષણ માટે Chromium-આધારિત બ્રાઉઝર (Chrome, Edge)
- M365 Copilot લાઇસન્સ (ઘણા Microsoft 365 Business/Enterprise પ્લાનમાં સમાવિષ્ટ)

## ઓળખપત્ર મેળવવું (WebSocket પદ્ધતિ)

1. `https://m365.cloud.microsoft/chat` પર સાઇન ઇન કરો અને વાતચીત શરૂ કરો.
2. **DevTools → Network** ખોલો.
3. **WS** (WebSocket) દ્વારા ફિલ્ટર કરો.
4. Chathub WebSocket કનેક્શન પર ક્લિક કરો. `wss://substrate.office.com/m365Copilot/Chathub/` થી શરૂ થતો URL શોધો.
5. તેના **Request URL** માંથી આ કૉપિ કરો:
   - `access_token` ક્વેરી પેરામીટરનું મૂલ્ય (ટૂંકા સમય માટે માન્ય JWT).
   - `/Chathub/` પછીનો Chathub પાથ સેગમેન્ટ (દા.ત. `<oid>@<tenant>`).

સંપૂર્ણ URL નું સ્વરૂપ આ પ્રમાણે છે:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute માં **Providers → Add Provider** પર જાઓ, **Microsoft 365 Copilot
   (BizChat)** પસંદ કરો અને ઓળખપત્રને નીચેના ફોર્મેટમાં પેસ્ટ કરો:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. **Test Connection** અને **Save** પર ક્લિક કરો.

## ઓળખપત્ર મેળવવું (HAR ઇમ્પોર્ટ)

WebSocket URL માંથી મૂલ્યો જાતે કૉપિ કરવાને બદલે, તમે DevTools HAR ફાઇલ એક્સપોર્ટ કરી શકો છો:

1. **DevTools → Network** ખોલો.
2. BizChat વાતચીત શરૂ કરો અથવા ચાલુ રાખો (આ WebSocket કનેક્શનને ટ્રિગર કરે છે).
3. Network પેનલમાં રાઇટ-ક્લિક કરો અને **Save all as HAR with content** પસંદ કરો.
4. OmniRoute માં, પ્રદાતા કનેક્શન ડાયલૉગ પરના **Import .har file** બટનનો ઉપયોગ કરો.

OmniRoute, Chathub WebSocket URL માટે HAR સ્કૅન કરે છે, `access_token` અને `chathubPath` કાઢે છે અને ઓળખપત્ર ફીલ્ડ્સ આપમેળે ભરે છે. HAR ઇમ્પોર્ટ JWT સમાપ્તિ સમયને ડિકોડ કરે છે અને ટોકનનો બાકી રહેલો માન્યતા સમય દર્શાવે છે.

> **વાસ્તવિક HAR એક્સપોર્ટ, ઍક્સેસ ટોકન અથવા રિફ્રેશ ટોકન ક્યારેય કમિટ કરશો નહીં.** પરીક્ષણ અને દસ્તાવેજીકરણનાં મૂલ્યો હંમેશાં પ્લેસહોલ્ડર્સ હોવા જોઈએ.

## ટોકન માન્યતા સમય અને રિફ્રેશ

`access_token` ટૂંકા સમય માટે માન્ય હોય છે (સામાન્ય રીતે **~75 મિનિટ**). તેની સમયસીમા સમાપ્ત થયા પછી, પ્રદાતા કનેક્શન ભૂલની જાણ કરે છે અને તમારે ઓળખપત્ર ફરીથી મેળવવું પડશે.

### `refreshToken` વડે આપમેળે રિફ્રેશ

જાતે ફરીથી મેળવવાની પ્રક્રિયા ટાળવા માટે, તમે Microsoft રિફ્રેશ ટોકનને કનેક્શનના **Advanced Settings → providerSpecificData** માં સંગ્રહિત કરી શકો છો:

| ફીલ્ડ          | વર્ણન                                                                 |
| -------------- | --------------------------------------------------------------------- |
| `refreshToken` | `substrate.office.com/sydney` સ્કોપ માટે Microsoft OAuth રિફ્રેશ ટોકન |
| `tier`         | `individual` (ડિફૉલ્ટ), `edu`, અથવા `enterprise`                      |

`substrate.office.com/sydney` સ્કોપ ધરાવતા Microsoft device-code અથવા authorization-code ફ્લોમાંથી રિફ્રેશ ટોકન મેળવો. `refreshToken` સેટ કરેલું હોય ત્યારે, OmniRoute દરેક વિનંતી પહેલાં `access_token` ને પ્રી-ફ્લાઇટ-રિફ્રેશ કરે છે, તેથી દરેક ~75-મિનિટની સમયસીમા સમાપ્ત થયા પછી તમારે તેને ફરીથી મેળવવાની જરૂર રહેતી નથી.

જો `refreshToken` સેટ કરેલું ન હોય, તો દરેક સમયસીમા સમાપ્ત થયા પછી તમારે WebSocket ઓળખપત્ર જાતે ફરીથી મેળવવું પડશે.

### ટિયર પસંદગી

| ટિયર         | ઉપનામ       | સપાટી                   |
| ------------ | ----------- | ----------------------- |
| `individual` | _(ડિફૉલ્ટ)_ | ગ્રાહક M365 Copilot     |
| `edu`        | `included`  | શિક્ષણ M365 Copilot     |
| `enterprise` | `work`      | કાર્ય માટે M365 Copilot |

**Advanced Settings → providerSpecificData → tier** માં ટિયર સેટ કરો. ટિયર BizChat રૂટિંગ અને મૉડલ ઍક્સેસને અસર કરે છે.

## સુરક્ષા મોડેલ

- **બિનસત્તાવાર એકીકરણ.** આ પ્રદાતા BizChat WebSocket
  પ્રોટોકૉલનું રિવર્સ-એન્જિનિયરિંગ કરે છે. Microsoft એન્ડપોઇન્ટમાં ફેરફાર કરે ત્યારે તે કોઈ સૂચના વિના કામ કરવાનું બંધ કરી શકે છે.
- `subscriptionRisk: true` ફ્લૅગ દર્શાવે છે કે આ એકીકરણ
  દસ્તાવેજીકરણ વિનાના એન્ડપોઇન્ટ પર આધાર રાખે છે. એકાઉન્ટ પર પ્રતિબંધો શક્ય છે, પરંતુ તેની પુષ્ટિ થઈ નથી.
- ઍક્સેસ ટોકન ટૂંકા સમય માટે માન્ય JWT છે. તેને પાસવર્ડની જેમ સાચવો: તેને કમિટ,
  લૉગ કે શેર કરશો નહીં.
- રિફ્રેશ ટોકન BizChat ઇન્ટરફેસ માટે લાંબા ગાળાની ઍક્સેસ આપે છે. તેને
  API કીની જેમ જ કાળજીપૂર્વક સંગ્રહિત કરો.

## સમસ્યાનિવારણ

### પ્રમાણીકરણ તરત જ નિષ્ફળ જાય છે

- ખાતરી કરો કે તમે **WebSocket URL**માંથી કૉપિ કર્યું છે, XHR/Fetch વિનંતીમાંથી નહીં.
  ઓળખપત્ર Chathub WebSocket કનેક્શનના `access_token` ક્વેરી પેરામીટરમાં હોય છે
  — `Authorization: Bearer` હેડરમાં નહીં.
- ખાતરી કરો કે `chathubPath`માં URL
  પાથનો સંપૂર્ણ `<oid>@<tenant>` વિભાગ સામેલ છે.

### ટોકન ~75 મિનિટ પછી સમાપ્ત થાય છે

આ અપેક્ષિત છે. `refreshToken` વિના, ઍક્સેસ ટોકન ટૂંકા સમય માટે માન્ય હોય છે. આમાંથી કોઈ એક કરો:

- DevToolsમાંથી ઓળખપત્ર ફરીથી કૅપ્ચર કરો, અથવા
- આપમેળે રિફ્રેશ કરવા માટે Advanced Settingsમાં `refreshToken` ગોઠવો.

### Test Connection સફળ થાય છે પરંતુ ચૅટ 401 પરત કરે છે

માન્યતા ચકાસણી અને પ્રથમ વિનંતી વચ્ચે ટોકન સમાપ્ત થઈ ગયું હોઈ શકે છે. નવું
ઓળખપત્ર ફરીથી કૅપ્ચર કરો.

### પ્રદાતાઓની સૂચિમાં Copilot દેખાતું નથી

ખાતરી કરો કે **Dashboard → Providers**માં `copilot-m365-web` સક્ષમ છે. કેટલાક
ટિઅર્સમાં પ્રદાતા ડિફૉલ્ટ રૂપે છુપાયેલો હોઈ શકે છે.
