OmniRoute ચેટ માટેના સમાન પ્રદાતા id: `cursor` (ઉપનામ `cu`) દ્વારા `POST /v1/images/generations` પર Cursor પ્લાનનું **ઇમેજ જનરેશન** ઉપલબ્ધ કરાવે છે.

| ફીલ્ડ                | મૂલ્ય                                                                            |
| -------------------- | -------------------------------------------------------------------------------- |
| `IMAGE_PROVIDERS` id | `cursor`                                                                         |
| ફોર્મેટ              | `cursor-agent-image`                                                             |
| પ્રમાણીકરણ           | ચેટ જેવું જ OAuth / API-key કનેક્શન (`provider_connections.provider = "cursor"`) |
| મોડેલ્સ              | `cursor/auto`, `cursor/composer-2`, `cursor/composer-2.5`                        |

## Agent CLI શા માટે

OmniRouteમાં Cursor ચેટ `agent.v1.AgentService/Run` (protobuf) નો ઉપયોગ કરે છે. આ પાથ બિલ્ટ-ઇન ક્લાયન્ટ ટૂલ્સ (shell, write, …) ને **નકારે છે**. ઇમેજ જનરેશન એ Cursor-મૂળ ટૂલ છે, જે સીટ માટે **`agent` CLI** દ્વારા ચલાવવામાં આવે છે. તેથી ઇમેજ હેન્ડલર નિયંત્રિત પ્રોમ્પ્ટ અને દરેક વિનંતી માટે અલગ અસ્થાયી વર્કસ્પેસ (કમ્યુનિટી સીટ બ્રિજ જેવી જ રચના) સાથે `agent` શરૂ કરે છે અને પછી OpenAI-સુસંગત `b64_json` પરત કરે છે.

## ઍક્સેસ પ્રતિબંધ (કડક નિયમો #15 + #17)

આ એકમાત્ર `IMAGE_PROVIDERS` ફોર્મેટ છે જે ચાઇલ્ડ પ્રોસેસ (`agent`
બાઇનરી) શરૂ કરે છે. કારણ કે `POST /v1/images/generations` લગભગ 40 અન્ય, પ્રોસેસ શરૂ ન કરતા
ઇમેજ પ્રદાતાઓ દ્વારા પણ વહેંચાય છે, જેનો રિમોટ કૉલર્સ કાયદેસર રીતે ઉપયોગ કરે છે, તેથી સમગ્ર રૂટને
`LOCAL_ONLY` તરીકે વર્ગીકૃત કરવામાં આવ્યો નથી — તેના બદલે `handleCursorAgentImageGeneration` પોતાનો
ગેટ અમલમાં મૂકે છે, જેમાં authz પાઇપલાઇન દ્વારા દરેક વિનંતી પર અંકિત કરાયેલ વિશ્વસનીય
`AUTHZ_HEADER_PEER_LOCALITY` નિર્ણયનો ઉપયોગ થાય છે (વાસ્તવિક TCP પીઅરમાંથી, ક્યારેય નકલી બનાવી શકાય તેવા
`Host` હેડરમાંથી નહીં): ફક્ત `loopback` અને `lan` કૉલર્સ જ પ્રોસેસ શરૂ કરવાની ક્રિયા સુધી પહોંચી શકે છે;
બાકીના બધાને (જાહેર ટનલ મારફતે ફરી વપરાયેલી લીક થયેલી API key સહિત) કોઈપણ ઓળખપત્ર શોધ અથવા
પ્રોસેસ શરૂ થાય તે પહેલાં `403` મળે છે. બાકીના `LOCAL_ONLY` સ્તર પર લાગુ થતી સમાન
નીતિ માટે `src/server/authz/policies/management.ts` જુઓ.

## કન્કરન્સી ગેટ મોડ્યુલ-સ્તરનો છે (એકલ-ઇન્સ્ટન્સ મર્યાદા)

`CURSOR_IMG_MAX_CONCURRENT` નો અમલ Node મોડ્યુલ ઇન્સ્ટન્સ
(`open-sse/handlers/imageGeneration/providers/cursorAgentImage.ts`) ના વ્યાપમાં આવતા ઇન-મેમરી કાઉન્ટર/ક્યૂ દ્વારા થાય છે.
તે એક OmniRoute પ્રોસેસની અંદર સમકાલીન `agent` પ્રોસેસોની સંખ્યાને યોગ્ય રીતે મર્યાદિત કરે છે, પરંતુ
સમાન Cursor સીટ શેર કરતી બહુવિધ પ્રોસેસ/ઇન્સ્ટન્સ વચ્ચે **સમન્વય કરતું નથી**
(દા.ત. મલ્ટિ-રેપ્લિકા ડિપ્લોયમેન્ટ) — દરેક ઇન્સ્ટન્સ પોતાની સ્વતંત્ર મર્યાદા લાગુ કરે છે.
એકલ-ઇન્સ્ટન્સ ડિપ્લોયમેન્ટ (ડિફૉલ્ટ) માટે આ ચોક્કસ છે; હોરિઝોન્ટલી સ્કેલ કરાયેલા
ડિપ્લોયમેન્ટે દરેક ઇન્સ્ટન્સ માટે `CURSOR_IMG_MAX_CONCURRENT` ને સાવધાનીપૂર્વક ઓછું રાખવું જોઈએ અથવા
Cursor ઇમેજ ટ્રાફિકને એક જ ઇન્સ્ટન્સ તરફ રૂટ કરવો જોઈએ.

## આવશ્યકતાઓ

1. ડૅશબોર્ડમાં જોડાયેલ Cursor એકાઉન્ટ (OAuth અથવા `crsr_…` API key).
2. OmniRoute પ્રોસેસ માટે Cursor Agent બાઇનરી ઉપલબ્ધ હોવી જોઈએ:
   - env `CURSOR_AGENT_BIN=/path/to/agent`, અથવા
   - `~/.local/bin/agent`, અથવા
   - Cursor કનેક્શન પર `providerSpecificData.agentBin`.

વૈકલ્પિક ટ્યૂનિંગ:

| Env                         | ડિફૉલ્ટ                    | અર્થ                               |
| --------------------------- | -------------------------- | ---------------------------------- |
| `CURSOR_IMG_TIMEOUT_MS`     | `210000`                   | દરેક ઇમેજ માટેનો વૉલ-ક્લૉક સમય     |
| `CURSOR_IMG_MAX_CONCURRENT` | `2`                        | શેર કરેલી સીટ માટેનો કન્કરન્સી ગેટ |
| `CURSOR_IMG_MODEL`          | (વિનંતીનું મોડેલ / `auto`) | CLI `--model` ને ઓવરરાઇડ કરો       |

## ઉદાહરણ

```bash
curl -sS https://<host>/v1/images/generations \
  -H "Authorization: Bearer <omni-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor/auto","prompt":"a lantern in fog","size":"1024x1024"}'
```

જનરેશનમાં સામાન્ય રીતે 1–2 મિનિટ લાગે છે. આંતરિક નેટવર્ક પાથને પ્રાધાન્ય આપો; લગભગ 100s ટાઇમઆઉટ ધરાવતા એજ પ્રોક્સીઓ નિષ્ફળ જશે.

## LiteLLM

`mode: image_generation`, `api_base: http://omniroute:20128/v1`, અને `model: openai/cursor/auto` (અથવા તમારા LiteLLM વર્ઝનના આધારે માત્ર `cursor/auto`) સાથે ઇમેજ મોડેલ રજિસ્ટર કરો.
