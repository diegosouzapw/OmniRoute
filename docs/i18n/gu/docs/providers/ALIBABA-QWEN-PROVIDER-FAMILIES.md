આ દસ્તાવેજ
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854) માટેનો અમલીકરણ નિર્ણય નોંધે છે. જાહેર પ્રોડક્ટ્સને
ચાર પ્રોવાઇડર પરિવારો તરીકે રજૂ કરવામાં આવે છે. પ્રદેશ એ કનેક્શન ડેટા છે, અલગ પ્રોડક્ટ નથી.

## નિર્ણય

| પ્રોવાઇડર પરિવાર                               | OmniRoute ID            | વૈશ્વિક પ્રદેશ | ચીન પ્રદેશ |
| ---------------------------------------------- | ----------------------- | -------------- | ---------- |
| Alibaba Cloud Model Studio (વપરાશ મુજબ ચૂકવણી) | `alibaba`               | સિંગાપુર       | બેઇજિંગ    |
| Alibaba Cloud Token Plan                       | `bailian-coding-plan`   | સિંગાપુર       | બેઇજિંગ    |
| Qwen Cloud (વપરાશ મુજબ ચૂકવણી)                 | `qwen-cloud`            | વૈશ્વિક        | બેઇજિંગ    |
| Qwen Cloud Token Plan                          | `qwen-cloud-token-plan` | સિંગાપુર       | બેઇજિંગ    |

હાલની `alibaba-cn` ID સાચવેલાં કનેક્શન્સ, મોડેલ રૂટ્સ, કોમ્બોઝ અને ઐતિહાસિક વપરાશ માટે રનટાઇમ સુસંગતતા ઉપનામ તરીકે યથાવત્ રહે છે. તેનું ડૅશબોર્ડ કાર્ડ `alibaba`માં સમાવી દેવામાં આવ્યું છે; ડેટાબેઝ
ફરીથી લખવાની જરૂર નથી.

Qwen Cloudનું વપરાશ મુજબ ચૂકવણી મોડેલ અને Alibaba Cloud Model Studio હાલમાં DashScope-સુસંગત
રનટાઇમ હોસ્ટ્સ શેર કરે છે, પરંતુ તેઓ અલગ પ્રોવાઇડર ઓળખ તરીકે યથાવત્ રહે છે, કારણ કે વપરાશકર્તાઓ અલગ-અલગ પ્રોડક્ટ ઇન્ટરફેસ દ્વારા કીઝ મેળવે છે અને
એકાઉન્ટ્સનું સંચાલન કરે છે. Alibaba અને Qwen Cloud Token Plan પ્રોડક્ટ્સ
અલગ એન્ડપોઇન્ટ પરિવારોનો ઉપયોગ કરે છે, તેથી ચારેય પ્રોડક્ટ્સ અલગ પ્રોવાઇડર IDs તરીકે યથાવત્ રહે છે.

## એન્ડપોઇન્ટ મેટ્રિક્સ

| પ્રોવાઇડર પરિવાર        | `global-sg`                                                              | `china-beijing`                                                      | વાયર ફોર્મેટ |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ------------ |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI       |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic    |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI       |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI       |

API કી અને એન્ડપોઇન્ટ એક જ પ્રોડક્ટ અને પ્રદેશનાં હોવા આવશ્યક છે. પ્રદેશ પસંદ કરવાથી
માન્યતા અને સામાન્ય વિનંતીઓ દ્વારા ઉપયોગમાં લેવાતું પૂર્વનિર્ધારિત એન્ડપોઇન્ટ બદલાય છે.

## કનેક્શન કરાર

નવાં કનેક્શન્સ સ્થિર પ્રદેશ કીને `providerSpecificData`માં સંગ્રહે છે:

```json
{
  "region": "global-sg"
}
```

માન્ય મૂલ્યો `global-sg` અને `china-beijing` છે. એન્ડપોઇન્ટને
પ્રોવાઇડર ID અને પ્રદેશ પરથી કેન્દ્રીય રીતે નિર્ધારિત કરવામાં આવે છે. બિન-પૂર્વનિર્ધારિત `providerSpecificData.baseUrl` સ્પષ્ટ ઑપરેટર
ઓવરરાઇડ તરીકે યથાવત્ રહે છે અને તેને પ્રાથમિકતા મળે છે, જ્યારે જૂના સાચવેલા પૂર્વનિર્ધારિત URLsને પ્રાદેશિક
મેટ્રિક્સ પ્રમાણે પાછા સામાન્યકૃત કરવામાં આવે છે.

આ કનેક્શન સ્કીમાને વિસ્તરણક્ષમ રાખે છે: બીજું પ્રોવાઇડર કાર્ડ બનાવ્યા વિના
અથવા સાચવેલાં પ્રોવાઇડર IDs બદલ્યા વિના રિઝોલ્વરમાં બીજો પ્રદેશ ઉમેરી શકાય છે.

## સુસંગતતા અને રોલઆઉટ

1. પ્રાદેશિક એન્ડપોઇન્ટ રિઝૉલ્વર ઉમેરો અને વર્તમાન વૈશ્વિક ડિફૉલ્ટ્સ જાળવી રાખો.
2. `alibaba`, તેના `alibaba-cn` સુસંગતતા ID અને `qwen-cloud` માટે લાઇવ પ્રાદેશિક DashScope `/models` ડિસ્કવરીનો ઉપયોગ કરો. તેમના પ્રતિસાદો પ્રથમ એક ટેક્સ્ટ-જનરેશન ફિલ્ટરમાંથી પસાર થાય છે, કારણ કે સામાન્ય એન્ડપોઇન્ટ ઇમેજ, વિડિયો, ઑડિયો, એમ્બેડિંગ અને અન્ય નોન-ચેટ મોડલ્સ પણ પરત કરે છે. ત્યારબાદ `qwen-cloud` તેની પ્રોવાઇડર રજિસ્ટ્રીમાં જાહેર કરેલી જાળવવામાં આવતી અલાઉલિસ્ટ લાગુ કરે છે. Alibaba Model Studio અને Qwen Cloud હાલમાં રનટાઇમ હોસ્ટ્સ શેર કરતા હોવા છતાં અલગથી ક્યુરેટ કરેલા કેટલૉગ્સ જાળવે છે.
3. વર્તમાન Token Plan ટેક્સ્ટ-મોડલ અલાઉલિસ્ટ સાથે `qwen-cloud-token-plan` રજિસ્ટર કરો.
4. કનેક્શન ઉમેરવા/સંપાદિત કરવાના ડાયલૉગ્સમાં ટાઇપ્ડ રીજન સિલેક્ટર ઉમેરો.
5. ડુપ્લિકેટ `alibaba-cn` કાર્ડ છુપાવો અને તેના હાલના કનેક્શન્સને `alibaba` પ્રોવાઇડર પેજ પર સામેલ કરો.
6. અદ્યતન અને વર્કસ્પેસ-વિશિષ્ટ ડિપ્લોયમેન્ટ્સ માટે કસ્ટમ એન્ડપોઇન્ટ ઓવરરાઇડ્સ ઉપલબ્ધ રાખો.

Token Plan મીડિયા મોડલ્સ ચેટ કેટલૉગની બહાર રહે છે, કારણ કે તેઓ સમર્પિત એન્ડપોઇન્ટ્સનો ઉપયોગ કરે છે.
`wan2.7-image` અને `wan2.7-image-pro` ને `open-sse/config/imageRegistry.ts` માં રજિસ્ટર કરવામાં આવ્યા છે;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, અને `happyhorse-1.1-r2v` ને
`open-sse/config/videoRegistry.ts` માં રજિસ્ટર કરવામાં આવ્યા છે. બંને રજિસ્ટ્રીઓ `qwen-cloud-token-plan` કનેક્શન
ઓળખ અને તેના રીજન-વિશિષ્ટ ક્રેડેન્શિયલ્સનો પુનઃઉપયોગ કરે છે.

નિયમિત Qwen Cloud પાસે `qwen-cloud` ઓળખ હેઠળ અલગ પે-એઝ-યુ-ગો ઇમેજ અને વિડિયો કેટલૉગ્સ છે. તેના ઇમેજ મોડલ્સ `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03`, અને `z-image-turbo` છે. તેના વિડિયો
મોડલ્સ `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12`, અને
`wan2.7-videoedit` છે. આ મોડલ્સ ફક્ત નિયમિત `qwen-cloud` કનેક્શન અને પ્રાદેશિક
DashScope મીડિયા એન્ડપોઇન્ટનો પુનઃઉપયોગ કરે છે. Token Plan અને પે-એઝ-યુ-ગો રજિસ્ટ્રીઓ એકબીજાની મોડલ સૂચિઓ વારસામાં મેળવતી કે મર્જ કરતી નથી.

`bailian-coding-plan` ઓળખ પાસે પણ તેની પોતાની મીડિયા અલાઉલિસ્ટ્સ છે:
ઇમેજ જનરેશન માટે `wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0`, અને `qwen-image-2.0-pro`,
તેમજ વિડિયો જનરેશન માટે
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, અને `happyhorse-1.1-r2v`.
તે ફક્ત Bailian Coding Plan કનેક્શન અને પ્રાદેશિક Coding Plan એન્ડપોઇન્ટનો ઉપયોગ કરે છે.
તેની ઇમેજ અને વિડિયો રજિસ્ટ્રીઓ કોઈપણ Qwen Cloud પ્રોવાઇડર પાસેથી વારસામાં મેળવતી કે તેની સાથે મર્જ થતી નથી.

નિયમિત `alibaba` ઓળખ પાસે અલગ ઇમેજ અને વિડિયો અલાઉલિસ્ટ્સ છે. તેના ઇમેજ મોડલ્સ
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo`, અને `wan2.6-t2i` છે. તેના ઉમેરાયેલા વિડિયો મોડલ્સ `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12`, અને `wan2.7-videoedit` છે. આ મોડલ્સ ફક્ત Alibaba Model Studio
કનેક્શન અને તેના પસંદ કરેલા પ્રાદેશિક મીડિયા એન્ડપોઇન્ટનો ઉપયોગ કરે છે; તેમને કોઈપણ Coding Plan અથવા Qwen
Cloud રજિસ્ટ્રીમાં ઉમેરવામાં આવતા નથી.

Qwen Cloud Token Plan ચેટ કેટલૉગ Individual પ્લાનની ચોક્કસ-સ્ટ્રિંગ ટેક્સ્ટ અલાઉલિસ્ટને અનુસરે છે:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2`, અને
`deepseek-v4-pro`. Wan અને HappyHorse એન્ટ્રીઓ અલગ ઇમેજ/વિડિયો જનરેશન APIs સાથે સંબંધિત છે.

Alibaba Token Plan તેના Anthropic-સુસંગત એન્ડપોઇન્ટ દ્વારા એ જ છ વર્તમાન ટેક્સ્ટ-જનરેશન મોડલ IDs ઉપલબ્ધ કરાવે છે. તેનો Singapore વિકલ્પ હાલની `global-sg` રીજન કી સંગ્રહિત કરે છે;
જે પ્રોવાઇડર પરિવારો આ રીજનને Global કહે છે તેમની સરખામણીમાં ફક્ત વપરાશકર્તાને દેખાતું લેબલ અલગ છે.

નિયમિત Qwen Cloud ચેટ કેટલૉગને ઇરાદાપૂર્વક સંપૂર્ણ લાઇવ ટેક્સ્ટ પ્રતિસાદ કરતાં વધુ સીમિત રાખવામાં આવ્યો છે. તેની
જાળવવામાં આવતી અલાઉલિસ્ટ `open-sse/config/providers/registry/qwen-cloud/index.ts` માં છે; લાઇવ
ડિસ્કવરી ફક્ત એવા IDs પરત કરે છે જે અપસ્ટ્રીમ પ્રતિસાદ અને તે રજિસ્ટ્રી સૂચિ—બંનેમાં હાજર હોય.

Alibaba Model Studio પણ `open-sse/config/providers/registry/alibaba/index.ts` માં પોતાની સ્વતંત્ર રીતે જાળવવામાં આવતી
અલાઉલિસ્ટ સાથે એ જ લાઇવ-ઇન્ટરસેક્શન નિયમ અનુસરે છે. `alibaba-cn` સુસંગતતા
પ્રોવાઇડર Beijing એન્ડપોઇન્ટ સામે ડિસ્કવરી રિઝૉલ્વ કરતી વખતે તે કેટલૉગનો પુનઃઉપયોગ કરે છે.
