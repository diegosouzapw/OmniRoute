પ્રત્યાયોજિત **Context Editing** એ માત્ર Claude માટેની સંદર્ભ-વ્યવસ્થાપન સુવિધા છે. OmniRouteના સ્થાનિક
કમ્પ્રેશન એન્જિનો (Caveman, RTK, LLMLingua, સ્ટૅક્ડ પાઇપલાઇન્સ)થી વિપરીત — જે પ્રોક્સીમાંથી વિનંતી
બહાર જાય તે _પહેલાં_ તેના બૉડીને ફરીથી લખે છે — Context Editing **પ્રદાતા**ને તેની પોતાની ચાલુ
સંદર્ભ વિન્ડોમાંથી જૂના tool-use / tool-result બ્લૉક્સ સાફ કરવા કહે છે. OmniRoute માત્ર એક બૉડી
પેરામીટર (`context_management.edits[]`) જોડે છે; વાસ્તવિક સફાઈ Claude પોતાના ટોકનાઇઝર અનુસાર કરે છે.

આ સ્વભાવગત રીતે એક પ્રત્યાયોજિત ક્ષમતા છે: અન્ય પ્રદાતાઓ આ પેરામીટરને નકારે છે, તેથી OmniRoute તેનો
કાર્યક્ષેત્ર સખત રીતે Claude અને Claude-Code-સુસંગત રિલે સુધી મર્યાદિત રાખે છે.

સત્યનો સ્રોત: `open-sse/config/contextEditing.ts` (સ્ટ્રેટેજી id, બૉડી ઇન્જેક્શન, ટેલિમેટ્રી
એક્સ્ટ્રેક્શન), `open-sse/executors/base.ts` (ઇન્જેક્શન ગેટ + 400-ફૉલબૅક), અને
`open-sse/services/compression/types.ts` (કન્ફિગનું સ્વરૂપ + ડિફૉલ્ટ).

## `clear_tool_uses` શું કરે છે

OmniRoute આઉટબાઉન્ડ Anthropic Messages બૉડીમાં એક જ સંપાદન ઇન્જેક્ટ કરે છે:

```json
{
  "context_management": {
    "edits": [
      {
        "type": "clear_tool_uses_20250919",
        "trigger": { "type": "input_tokens", "value": 100000 },
        "keep": { "type": "tool_uses", "value": 3 }
      }
    ]
  }
}
```

- `type: "clear_tool_uses_20250919"` — તારીખવાળું Anthropic સ્ટ્રેટેજી id (`CLEAR_TOOL_USES_STRATEGY`).
- `trigger.value: 100000` — વિનંતીના ઇનપુટ ટોકન્સ આ થ્રેશોલ્ડને ઓળંગે ત્યારથી Claude જૂની
  tool-use/result જોડીઓ સાફ કરવાનું શરૂ કરે છે (`CONTEXT_EDITING_DEFAULT_TRIGGER_TOKENS`, Anthropicનું ડિફૉલ્ટ).
- `keep.value: 3` — સૌથી તાજેતરની N tool-use/result જોડીઓને અકબંધ રાખવામાં આવે છે
  (`CONTEXT_EDITING_DEFAULT_KEEP_TOOL_USES`).

બીટાની જાણ `anthropic-beta: context-management-2025-06-27` હેડર દ્વારા કરવામાં આવે છે, જેને
OmniRoute પહેલેથી જ Claude વિનંતીઓ પર મોકલે છે.

ઇન્જેક્શન `applyContextEditingToBody()` દ્વારા કરવામાં આવે છે અને તે **આઇડેમ્પોટન્ટ** છે: જો બૉડી પર
`clear_tool_uses` સંપાદન પહેલેથી જ હાજર હોય (અગાઉના કૉલ દ્વારા ઉમેરાયેલ અથવા ક્લાયન્ટ દ્વારા આપવામાં
આવેલ), તો બૉડીને જેમ છે તેમ જ રાખવામાં આવે છે. જો `clear_thinking_20251015` સંપાદન પણ હાજર હોય, તો
OmniRoute `clear_thinking` સંપાદનને સ્થિર રીતે સૉર્ટ કરીને સૌથી આગળ મૂકે છે, કારણ કે Anthropic મુજબ
`edits[]` ઍરેમાં `clear_thinking`, `clear_tool_uses` પહેલાં આવવું આવશ્યક છે.

## દરેક કૉમ્બો માટેનું સક્ષમકરણ ટૉગલ

Context Editing **ડિફૉલ્ટ રૂપે બંધ** હોય છે અને તેને પસંદ કરીને સક્ષમ કરવું પડે છે. આ ટૉગલ કમ્પ્રેશન
કન્ફિગમાં રહેલું એક બુલિયન મૂલ્ય છે:

- સેટિંગ કી: `contextEditing.enabled` (camelCase — `context_editing` / `context-editing` **નહીં**).
- પ્રકાર: `open-sse/services/compression/types.ts`માં
  `ContextEditingConfig { enabled: boolean }`.
- ડિફૉલ્ટ: `DEFAULT_CONTEXT_EDITING_CONFIG = { enabled: false }`.
- Zod સ્કીમા: `src/shared/validation/compressionConfigSchemas.ts`માં `contextEditingConfigSchema`.
- સ્ટોરેજ: બાકીની કમ્પ્રેશન સેટિંગ્સ સાથે જ સંગ્રહિત રહે છે
  (`src/lib/db/compression.ts`માં નૉર્મલાઇઝ કરવામાં આવે છે).

ડૅશબોર્ડમાં આ ટૉગલ કમ્પ્રેશન હબ
(`src/app/(dashboard)/dashboard/context/combos/CompressionHub.tsx`)માં રહે છે અને `saveSettings()`
દ્વારા `{ contextEditing: { enabled: … } }` પાછું લખે છે. તે કમ્પ્રેશન-સેટિંગ્સ ઑબ્જેક્ટનો ભાગ હોવાથી,
સંપૂર્ણપણે સ્વતંત્ર સપાટી બનવાને બદલે તે દરેક કૉમ્બોના કમ્પ્રેશન પ્રોફાઇલ સાથે સંયોજાય છે — કન્ફિગમાં
ફક્ત ચાલુ/બંધ ફ્લૅગ હોય છે; તમામ થ્રેશોલ્ડ (`trigger`, `keep`) ઉપર દસ્તાવેજિત કરેલા સ્થિરાંકો છે.

## માત્ર Claude માટેનું ગેટિંગ

ઇન્જેક્શન ફક્ત વાસ્તવિક Claude અથવા Claude-Code-સુસંગત રિલે માટે જ થાય છે.  
`open-sse/executors/base.ts` માં ગેટ આ છે:

```ts
if (
  (this.provider === "claude" || isClaudeCodeCompatible(this.provider)) &&
  contextEditing?.enabled &&
  !contextEditingDisabled
) {
  applyContextEditingToBody(transformedBody, { enabled: true });
}
```

- `this.provider === "claude"` — વાસ્તવિક Anthropic કી/OAuth.
- `isClaudeCodeCompatible(this.provider)` — એવા રિલે જેમનું provider id
  `anthropic-compatible-cc-` પ્રીફિક્સથી શરૂ થાય છે (તેઓ Claude Code સુસંગતતા જાહેર કરે છે, તેથી
  આ રિલે દ્વારા beta સ્વીકારવામાં આવે તેવી સંભાવના સૌથી વધુ છે). `open-sse/services/provider.ts` જુઓ.

ઇરાદાપૂર્વક **બાકાત રાખેલાં**:

- `claude-web` — `create_conversation_params` વિનંતી આકાર ધરાવતું બ્રાઉઝર રિલે, જેને ક્યારેય
  `context_management` મળતું નથી.
- સામાન્ય `anthropic-compatible-*` રિલે (`-cc-` પ્રીફિક્સ વગરનાં) — beta સપોર્ટ અનિશ્ચિત હોય તેવા
  તૃતીય-પક્ષ endpoints.

ટૉગલ ચાલુ હોય ત્યારે પણ બિન-Claude providers ને ક્યારેય `context_management` પેરામીટર મળતું નથી.

## 400-fallback / રિલે કવરેજ

Claude-સુસંગત રિલે beta જાહેર કરી શકે છે, પરંતુ તેમ છતાં `context_management` પેરામીટરને
HTTP 400 સાથે નકારી શકે છે. વિનંતીને નિષ્ફળ બનાવવાને બદલે સુવ્યવસ્થિત રીતે ક્ષમતા ઘટાડવા માટે,
executor પેરામીટર દૂર કરે છે અને એ જ URL પર **એક વાર** ફરી પ્રયાસ કરે છે:

```ts
if (
  response.status === HTTP_STATUS.BAD_REQUEST &&
  contextEditing?.enabled &&
  !contextEditingDisabled &&
  transformedBody?.context_management !== undefined
) {
  const errText = await response
    .clone()
    .text()
    .catch(() => "");
  if (/context[_-]management|context editing/i.test(errText)) {
    contextEditingDisabled = true;
    delete transformedBody.context_management;
    let retryBody = JSON.stringify(transformedBody);
    if (isClaudeCodeCompatible(this.provider) || this.provider === "claude") {
      retryBody = await signRequestBody(retryBody);
    }
    response = await fetch(url, { ...fetchOptions, body: retryBody });
  }
}
```

વર્તન:

1. context editing સક્રિય હોય અને body માં ખરેખર `context_management` સામેલ હોય ત્યારે જ `400`
   પર ટ્રિગર થાય છે.
2. 400 body ને `clone()` દ્વારા વાંચવામાં આવે છે, જેથી મેચ ન થતા પાથ માટે મૂળ response અખંડિત રહે.
3. ભૂલના ટેક્સ્ટનું `/context[_-]management|context editing/i` સાથે મેળ ખાવું આવશ્યક છે — અસંબંધિત
   400 (દા.ત. `max_tokens must be >= 1`) fallback ટ્રિગર કરતું **નથી**; મૂળ ભૂલ આગળ પ્રસારિત થાય છે.
4. મેળ મળવા પર તે `contextEditingDisabled = true` સેટ કરે છે (જેથી પછી retry/fallback URL માટે નવું
   `transformedBody` બનાવવામાં આવે તો ફરી ઇન્જેક્શન થતું અટકે છે), `context_management` દૂર કરે છે,
   Claude / Claude-Code-સુસંગત રિલે માટે body પર ફરી સહી કરે છે (`signRequestBody`), અને એ જ URL પર
   એક વાર ફરી પ્રયાસ કરે છે.

વાસ્તવિક Claude `ANTHROPIC_BETA_BASE` માં beta ધરાવે છે અને આ fallback પાથ પર આવતું નથી.

## `applied_edits` ટેલિમેટ્રી

Claude response પછી, OmniRoute provider દ્વારા ખરેખર કેટલો context સાફ કરવામાં આવ્યો તે નોંધે છે.
આ **સ્ટ્રીમ થતું નથી** — તેને non-streaming response body માંથી best-effort ધોરણે કાઢવામાં આવે છે
અને તે ક્યારેય response ને અસર કરતું નથી (ટેલિમેટ્રીની નિષ્ફળતાઓ અવગણવામાં આવે છે).

- એક્સ્ટ્રેક્શન: `open-sse/config/contextEditing.ts` માં `extractContextEditingTelemetry(responseBody)`.
  response આકાર અંગે રક્ષણાત્મક અભિગમ તરીકે, તે ત્રણ સ્થાનોમાં `applied_edits` તપાસે છે:
  - `context_management.applied_edits`
  - `usage.context_management.applied_edits`
  - `usage.applied_edits`
- દરેક એન્ટ્રીમાંથી વાંચવામાં આવતાં fields: `cleared_input_tokens` અને `cleared_tool_uses`
  (snake_case, Anthropic-native), સાથે `clearedInputTokens` / `clearedToolUses` camelCase fallbacks.
- કોઈ `applied_edits` array ન મળે અથવા વાસ્તવમાં કશું સાફ ન થયું હોય ત્યારે `null` પરત કરે છે.

રસીદનો આકાર `ContextEditingTelemetry { editCount, clearedInputTokens, clearedToolUses }` છે.
રેકોર્ડિંગ `open-sse/handlers/chatCore.ts` માં (`provider === "claude"` સુધી ગેટ કરેલું)
`recordContextEditingTelemetry()` (`src/lib/db/compressionAnalytics.ts`) દ્વારા થાય છે, જે આ રીતે
ટૅગ કરેલી compression analytics પંક્તિ લખે છે:

- `mode: "context-editing"`
- `engine: "context-editing"`
- `tokens_saved` / `original_tokens` = સાફ કરેલા input-token ની સંખ્યા
- `request_id` સાથે `::context-editing` suffix જોડાયેલું

આથી delegated clearing, સ્થાનિક engines ની સાથે compression analytics માં `context-editing`
engine label હેઠળ દેખાય છે અને તેને RTK/Caveman/LLMLingua બચતથી અલગ ઓળખી શકાય છે.

## સ્થાનિક કમ્પ્રેશન એન્જિનો સાથેનો સંબંધ

| પાસું                 | સ્થાનિક એન્જિનો (Caveman / RTK / LLMLingua / stacked) | સોંપાયેલ કૉન્ટેક્સ્ટ સંપાદન                       |
| --------------------- | ----------------------------------------------------- | ------------------------------------------------- |
| તે ક્યાં ચાલે છે      | વિનંતી પ્રોક્સીમાંથી બહાર જાય તે પહેલાં, OmniRouteમાં | પ્રદાતા (Claude)માં, સર્વર-સાઇડ પર                |
| તે શું સંપાદિત કરે છે | પ્રોમ્પ્ટ / કૉન્ટેક્સ્ટ / ટૂલ-પરિણામ ટેક્સ્ટ          | જૂના ટૂલ-ઉપયોગ / ટૂલ-પરિણામ બ્લૉક્સ               |
| પ્રદાતાનો વ્યાપ       | બધા પ્રદાતાઓ                                          | માત્ર `claude` + `anthropic-compatible-cc-*`      |
| ટૉગલ                  | કમ્પ્રેશન મોડ સેટિંગ્સ                                | `contextEditing.enabled`                          |
| નિષ્ફળતા મોડ          | નિષ્ફળતા વખતે ચાલુ રહે છે (મૂળ ટેક્સ્ટ)               | 400-ફૉલબૅક: પરિમાણ દૂર કરો, એક વાર ફરી પ્રયાસ કરો |
| બચત ટેલિમેટ્રી        | `engine: <engine id>`                                 | `engine: "context-editing"`                       |

બંને એકબીજાના પૂરક છે: સ્થાનિક એન્જિનો OmniRoute દ્વારા મોકલાતા બાઇટ્સને કમ્પ્રેસ કરે છે; કૉન્ટેક્સ્ટ સંપાદન
Claudeને અનેક ટર્નમાં ચાલુ કૉન્ટેક્સ્ટને છાંટવાની મંજૂરી આપે છે. બંનેને એકસાથે સક્ષમ કરી શકાય છે.
