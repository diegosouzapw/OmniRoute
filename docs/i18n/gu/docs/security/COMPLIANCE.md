OmniRoute વહીવટી ક્રિયાઓ, પ્રમાણીકરણ ઇવેન્ટ્સ, પ્રદાતા
ક્રેડેન્શિયલ જીવનચક્રમાં થતા ફેરફારો અને MCP ટૂલના આહ્વાનોને SQLite-આધારિત ઑડિટ
ટેબલોમાં રેકોર્ડ કરે છે. આ પૃષ્ઠમાં શું લૉગ થાય છે, તે ક્યાં સંગ્રહાય છે, કેટલા સમય સુધી
જાળવી રાખવામાં આવે છે, API કી કેવી રીતે તેમાંથી બહાર રહેવાનું પસંદ કરી શકે છે અને ડેટાની ક્વેરી કેવી રીતે કરવી તે આવરી લેવાયું છે.

અમલીકરણ `src/lib/compliance/index.ts` (T-43 — "અનુપાલન
નિયંત્રણો") અને `src/lib/compliance/providerAudit.ts`માં છે. ઑડિટ રાઇટ્સ ક્યારેય અપવાદ ફેંકતા નથી:
કોઈપણ નિષ્ફળતા પર કૉલને મૌન રીતે અવગણવામાં આવે છે, જેથી ઑડિટ લૉગિંગ
મુખ્ય રિક્વેસ્ટ પ્રવાહને વિક્ષેપિત ન કરી શકે.

## શું લૉગ થાય છે

### વહીવટી ઑડિટ ઇવેન્ટ્સ (`audit_log`)

`logAuditEvent({ action, actor, target, details, ... })`ને કરાયેલ દરેક કૉલ
એક પંક્તિ ઉત્પન્ન કરે છે. ઍક્શન સ્ટ્રિંગ્સ `domain.verb` (અથવા `domain.verb.outcome`)
પૅટર્નનું અનુસરણ કરે છે. ટ્રીમાં પુષ્ટિ થયેલા ઍક્શન પ્રકારોમાં આ સામેલ છે:

| ઍક્શન                                | સ્રોત                                   |
| ------------------------------------ | --------------------------------------- |
| `auth.login.success`                 | `src/app/api/auth/login/route.ts`       |
| `auth.login.failed`                  | `src/app/api/auth/login/route.ts`       |
| `auth.login.locked`                  | `src/app/api/auth/login/route.ts`       |
| `auth.login.error`                   | `src/app/api/auth/login/route.ts`       |
| `auth.login.misconfigured`           | `src/app/api/auth/login/route.ts`       |
| `auth.login.setup_required`          | `src/app/api/auth/login/route.ts`       |
| `auth.logout.success`                | `src/app/api/auth/logout/route.ts`      |
| `provider.credentials.created`       | `src/app/api/providers/route.ts`        |
| `provider.credentials.updated`       | `src/app/api/providers/[id]/route.ts`   |
| `provider.credentials.revoked`       | `src/app/api/providers/[id]/route.ts`   |
| `provider.credentials.batch_revoked` | `src/app/api/providers/route.ts`        |
| `sync.token.created`                 | `src/app/api/sync/tokens/route.ts`      |
| `sync.token.revoked`                 | `src/app/api/sync/tokens/[id]/route.ts` |
| `compliance.cleanup`                 | `src/lib/compliance/index.ts`           |

દરેક એન્ટ્રી `action`, `actor` (ડિફૉલ્ટ તરીકે `"system"`), `target`,
`details`/`metadata` (JSON), `ip_address`, `resource_type`, `status`,
`request_id` અને `timestamp` કૅપ્ચર કરે છે. સંવેદનશીલ કીઓ (`apiKey`, `accessToken`,
`refreshToken`, `password`, `*token`/`*secret`/`*apikey` સાથે મેળ ખાતી કોઈપણ કી,
વગેરે) પંક્તિ લખાય તે પહેલાં પુનરાવર્તિત રીતે `"[redacted]"` વડે ઢાંકી દેવામાં આવે છે.

### MCP ટૂલ કૉલ્સ (`mcp_tool_audit`)

દરેક MCP ટૂલ આહ્વાન
`open-sse/mcp-server/audit.ts` મારફતે એક પંક્તિ લખે છે. સ્કીમા (

| કૉલમ             | નોંધો                                    |
| ---------------- | ---------------------------------------- |

| `input_hash`     | ઇનપુટનો sha256 (કોઈ પેલોડ સંગ્રહાતો નથી) |

| `success`        | `1` / `0`                                |
| `error_code`     | નિષ્ફળતા વખતે અંતિમ ભૂલ કોડ              |

### રિક્વેસ્ટ / વપરાશ લૉગ્સ

આ કાર્યકારી ટેલિમેટ્રી છે (સખત અર્થમાં વહીવટી ઑડિટ નથી), પરંતુ સમાન
રીટેન્શન પાઇપલાઇનનો ઉપયોગ કરે છે:

- `usage_history` — દરેક રિક્વેસ્ટ દીઠ વપરાશનું સંકલન
- `call_logs` — દરેક રિક્વેસ્ટનો સંપૂર્ણ લૉગ (પંક્તિ-મર્યાદાને આધીન, નીચે જુઓ)
- `proxy_logs` — પ્રૉક્સી ટ્રાફિક લૉગ (પંક્તિ-મર્યાદાને આધીન)
- `request_detail_logs` — જૂનો વિગતવાર રિક્વેસ્ટ લૉગ (હાજર હોય તો હજુ પણ છાંટવામાં આવે છે)

## સ્ટોરેજ સ્કીમા

પ્રથમ ઉપયોગ વખતે `ensureAuditLogSchema()` દ્વારા `audit_log` જરૂર પડ્યે બનાવવામાં આવે છે:

```sql
CREATE TABLE IF NOT EXISTS audit_log (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  timestamp     TEXT NOT NULL DEFAULT (datetime('now')),
  action        TEXT NOT NULL,
  actor         TEXT NOT NULL DEFAULT 'system',
  target        TEXT,
  details       TEXT,
  ip_address    TEXT,
  resource_type TEXT,
  status        TEXT,
  request_id    TEXT,
  metadata      TEXT
);
```

`timestamp`, `action`, `actor`, `resource_type`, `status`, અને `request_id` પર ઇન્ડેક્સ બનાવવામાં આવે છે. લેગસી DBમાં ખૂટતી કૉલમ જરૂર પડ્યે `ALTER TABLE` દ્વારા ઉમેરવામાં આવે છે.

## જાળવણી અને સાફસફાઈ

બે અલગ જાળવણી અવધિઓનું પાલન કરવામાં આવે છે:

| એન્વાયરમેન્ટ વેરિએબલ        | ડિફૉલ્ટ  | આના પર લાગુ પડે છે                                                |
| --------------------------- | -------- | ----------------------------------------------------------------- |
| `APP_LOG_RETENTION_DAYS`    | `7`      | `audit_log`, `mcp_tool_audit`                                     |
| `CALL_LOG_RETENTION_DAYS`   | `7`      | `usage_history`, `call_logs`, `proxy_logs`, `request_detail_logs` |
| `CALL_LOGS_TABLE_MAX_ROWS`  | `100000` | `call_logs` માટે પંક્તિ-મર્યાદા મુજબ કાપછાંટ                      |
| `PROXY_LOGS_TABLE_MAX_ROWS` | `100000` | `proxy_logs` માટે પંક્તિ-મર્યાદા મુજબ કાપછાંટ                     |

`cleanupExpiredLogs()` જાળવણી પ્રક્રિયા ચલાવે છે. સર્વર શરૂ થાય ત્યારે તેને `src/instrumentation-node.ts`માંથી બોલાવવામાં આવે છે. દરેક રન પ્રતિ-ટેબલ કાઢી નાખવામાં આવેલી પંક્તિઓની સંખ્યા સાથે `compliance.cleanup` ઑડિટ ઇવેન્ટ લૉગ કરે છે. લાંબા રાઇટ લૉક્સ ટાળવા માટે પ્રૉક્સી/કૉલ લૉગની કાપછાંટ બૅચમાં (`BATCH_SIZE = 5000`) કરવામાં આવે છે.

મેન્યુઅલ રિક્વેસ્ટ-હિસ્ટ્રી સાફસફાઈ જાળવણીથી અલગ છે. Request Logs પેજ `POST /api/settings/purge-request-history`ને કૉલ કરે છે, જે `call_logs`, લેગસી `request_detail_logs`, અને `${DATA_DIR}/call_logs/` હેઠળના સ્થાનિક રિક્વેસ્ટ આર્ટિફેક્ટ્સ કાઢી નાખે છે.

ડિફૉલ્ટ મૂલ્યો `src/lib/logEnv.ts`માં વ્યાખ્યાયિત છે (`DEFAULT_APP_LOG_RETENTION_DAYS = 7`, `DEFAULT_CALL_LOG_RETENTION_DAYS = 7`).

## `noLog` ઑપ્ટ-આઉટ (દરેક API કી માટે)

API કીને ફ્લૅગ કરી શકાય છે જેથી તેનો ડાઉનસ્ટ્રીમ કૉલ ટ્રાફિક લૉગ ન થાય. આ ફ્લૅગ `api_keys` ટેબલમાં (`no_log INTEGER DEFAULT 0`) રહે છે અને ઝડપી પાથ લુકઅપ માટે તેની નકલ ઇન-મેમરી સેટમાં રાખવામાં આવે છે.

```bash
# લૉગ ન કરતી કી બનાવો (મેનેજમેન્ટ પ્રમાણીકરણ જરૂરી છે)
curl -X POST http://localhost:20128/api/keys \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"name": "Privacy key", "noLog": true}'
```

હેલ્પર્સ (`src/lib/compliance/index.ts`):

- `setNoLog(apiKeyId, true|false)` — ઇન-મેમરી એન્ટ્રીને ટૉગલ કરે છે
- `isNoLog(apiKeyId)` — રિક્વેસ્ટ પાથ પર તપાસવામાં આવે છે; જરૂર પડ્યે `api_keys.no_log`માંથી 30 s માટે કૅશ કરેલા રીડનો ઉપયોગ કરે છે
- `NO_LOG_API_KEY_IDS` (એન્વાયરમેન્ટ વેરિએબલ, કૉમા વડે અલગ કરેલા) — બૂટ સમયે ઇન-મેમરી સેટમાં અગાઉથી લોડ થાય છે; જ્યારે તમે કૉલમને સીધી રીતે ટૉગલ ન કરી શકો ત્યારે ઉપયોગી છે

એડમિનિસ્ટ્રેટિવ ઑડિટ ઇવેન્ટ્સ (લૉગિન, પ્રોવાઇડર ફેરફારો, MCP ટૂલ કૉલ્સ વગેરે) પર `noLog`ની **કોઈ અસર થતી નથી** — માત્ર પ્રતિ-રિક્વેસ્ટ ટ્રાફિક લૉગિંગમાંથી ઑપ્ટ-આઉટ કરવામાં આવે છે.

| એન્ડપોઇન્ટ                  | પદ્ધતિ | વર્ણન                                        | પ્રમાણીકરણ |
| --------------------------- | ------ | -------------------------------------------- | ---------- |
| `/api/compliance/audit-log` | `GET`  | ફિલ્ટર્સ સાથે પૃષ્ઠાંકિત એડમિન ઑડિટ એન્ટ્રીઓ | મેનેજમેન્ટ |
| `/api/mcp/audit`            | `GET`  | પૃષ્ઠાંકિત MCP ટૂલ ઑડિટ એન્ટ્રીઓ             | (open-sse) |

હાલમાં કોઈ CSV નિકાસ એન્ડપોઇન્ટ આપવામાં આવતું નથી — ડૅશબોર્ડમાંથી નિકાસ કરો અથવા
સીધો SQLite ડેટાબેઝ ક્વેરી કરો.

### `/api/compliance/audit-log` ને ક્વેરી કરવું

સમર્થિત ક્વેરી પરિમાણો (બધા વૈકલ્પિક છે અને ટેક્સ્ટ ફિલ્ટર્સ માટે બધા
`LIKE %value%` મેચિંગનો ઉપયોગ કરે છે):

- `action`, `actor`, `target`, `resourceType` (અથવા `resource_type`),
  `status`, `requestId` (અથવા `request_id`)
- `from` / `since`, `to` / `until` — ISO ટાઇમસ્ટૅમ્પ
- `limit` (ડિફૉલ્ટ `50`, ન્યૂનતમ `1`, મહત્તમ `500`)
- `offset` (ડિફૉલ્ટ `0`, મહત્તમ `10_000`)

પ્રતિસાદ એક JSON ઍરે છે. પૃષ્ઠાંકન મેટાડેટા હેડર્સમાં પરત કરવામાં આવે છે:
`x-total-count`, `x-page-limit`, `x-page-offset`.

```bash
curl "http://localhost:20128/api/compliance/audit-log?action=provider.credentials&from=2026-05-01" \
  -H "Cookie: auth_token=..."
```

## ડૅશબોર્ડ

ડૅશબોર્ડ ઑડિટ ડેટાને **`/dashboard/audit`** પર ઉપલબ્ધ કરાવે છે
(`src/app/(dashboard)/dashboard/audit/page.tsx`). પેજમાં બે ટૅબ છે:

- **અનુપાલન** (`ComplianceTab.tsx`) — `/api/compliance/audit-log` માંથી
  એડમિન ઑડિટ ઇવેન્ટ્સ. ઇવેન્ટ પ્રકાર, ગંભીરતા (માહિતી / ચેતવણી
  / ગંભીર, action + status પરથી નિર્ધારિત), અને તારીખ શ્રેણી દ્વારા ફિલ્ટર કરે છે. ગંભીરતા
  action/status સ્ટ્રિંગ્સ પરથી ક્લાયન્ટ-સાઇડ પર ગણવામાં આવે છે.
- **MCP** (`McpAuditTab.tsx`) — `/api/mcp/audit` માંથી MCP ટૂલ ઑડિટ, જેમાં
  ટૂલ નામ અને સફળતા/નિષ્ફળતા મુજબ ફિલ્ટર્સ છે.

બંને ટૅબ અનુક્રમે `50` (અનુપાલન) અને `25` (MCP) પેજ સાઇઝ સાથે પૃષ્ઠાંકન કરે છે.

## પ્રોવાઇડર ક્રેડેન્શિયલ હેલ્પર્સ

`src/lib/compliance/providerAudit.ts` પ્રોવાઇડર-મેનેજમેન્ટ રૂટ્સ દ્વારા
ક્રેડેન્શિયલ ઇવેન્ટ્સ ઉત્સર્જિત કરતી વખતે ઉપયોગમાં લેવાતા શેપિંગ હેલ્પર્સ પ્રદાન કરે છે:

- `summarizeProviderConnectionForAudit(connection)` — કનેક્શન સ્નૅપશૉટ
  `details` માં લખાય તે પહેલાં `apiKey`, `accessToken`, `refreshToken`, `idToken`, અને
  `providerSpecificData.consoleApiKey` દૂર કરે છે.
- `getProviderAuditTarget(connection)` — `target` ફીલ્ડ માટે સ્થિર
  `"<provider>:<name|id>"` સ્ટ્રિંગ બનાવે છે.
- `extractProviderWarnings(...payloads)` — નીતિ/સુરક્ષા ચેતવણીઓ
  (`[sanitizer]`, `prompt injection detected`,
  `content has been filtered`, `safety filter`, `policy violation`) માટે પ્રોવાઇડર પ્રતિસાદોને સ્કૅન કરે છે અને
  વધુમાં વધુ 5 મેળ દર્શાવે છે, જેમાંથી દરેકને 400 અક્ષરો સુધી મર્યાદિત કરવામાં આવે છે.

## શ્રેષ્ઠ પ્રથાઓ

- PII (કાનૂની, તબીબી વગેરે) સંભાળતી API કીઝને `noLog: true` વડે ફ્લૅગ કરો.
- તમારી રિટેન્શન નીતિ પૂરી કરવા `APP_LOG_RETENTION_DAYS` / `CALL_LOG_RETENTION_DAYS`
  ટ્યૂન કરો. 7-દિવસના ડિફૉલ્ટ્સ સાવધાનીપૂર્ણ છે.
- તમારા અનુપાલન કાર્યક્રમને જરૂરી હોય તે સમયાંતરે ઑડિટ ટેબલને પ્લેટફોર્મની બહાર
  (`sqlite3 dump`) નિકાસ કરો — કોઈ બિલ્ટ-ઇન આર્કાઇવલ ઉપલબ્ધ નથી.
- બ્રૂટ-ફોર્સ શોધ માટે `auth.login.failed` અને `auth.login.locked` ની સંખ્યાઓ
  ટ્રૅક કરો.
- નવા એડમિન એન્ડપોઇન્ટ્સ ઉમેરતી વખતે, સ્થિર `domain.verb.outcome` action સ્ટ્રિંગ સાથે
  `logAuditEvent({ ... })` કૉલ કરો અને `getAuditRequestContext(request)` દ્વારા
  રિક્વેસ્ટ કોન્ટેક્સ્ટ પાસ કરો જેથી IP અને `requestId` આપમેળે કૅપ્ચર થાય.
