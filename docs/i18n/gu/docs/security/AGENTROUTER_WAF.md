`agentrouter` અપસ્ટ્રીમ ગેટવે `messages[].content` પર કીવર્ડ-આધારિત કન્ટેન્ટ ફિલ્ટર ચલાવે છે. ફિલ્ટર આંશિક રીતે નિર્ધારિત છે (અમુક શબ્દસમૂહોને હંમેશાં બ્લૉક કરે છે) અને આંશિક રીતે સંભાવનાત્મક છે (બર્સ્ટ-સંવેદનશીલ — ઝડપથી વિનંતીઓ આવ્યા પછી વધુ આક્રમક બને છે અને કૂલડાઉન પછી પુનઃસામાન્ય થાય છે).

જ્યારે WAF કોઈ વિનંતીને બ્લૉક કરે છે, ત્યારે તે આ પરત કરે છે:

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## ફિલ્ટરનો વ્યાપ

WAF માત્ર `messages[].content`નું નિરીક્ષણ કરે છે. તે નીચેની વસ્તુઓનું નિરીક્ષણ **કરતું નથી**:

- `system` પ્રોમ્પ્ટ
- સ્ટ્રક્ચર્ડ કન્ટેન્ટ બ્લૉક્સ (`tool_result`, `tool_use`, `thinking`, `image`)
- ટૂલનાં `description` અને `input_schema` ફીલ્ડ્સ
- વિનંતીનું મેટાડેટા, હેડર્સ અથવા મોડેલ id

## હંમેશાં બ્લૉક થતી પેટર્ન્સ (કેસ-ઇન્સેન્સિટિવ)

| પેટર્ન                        | નોંધ                                                        |
| ----------------------------- | ----------------------------------------------------------- |
| `Lorem ipsum`નું કોઈપણ સ્વરૂપ | સંપૂર્ણ લેટિન lorem શબ્દભંડોળ બ્લૉક થાય છે                  |
| `language model` (એકલું)      | "the language model" અને "large language model" પસાર થાય છે |
| `virtual assistant`           | "AI assistant" પસાર થાય છે                                  |
| `I'm here to help`            | એકલું "here to help" પણ બ્લૉક થાય છે                        |
| `Claude, made by Anthropic`   | માત્ર સંપૂર્ણ શબ્દસમૂહ                                      |

## લગભગ હંમેશાં બ્લૉક થતી પેટર્ન્સ

| પેટર્ન                                                     | નોંધ                                                |
| ---------------------------------------------------------- | --------------------------------------------------- |
| `placeholder`                                              | જ્યારે તે એકલું હોય (પેરામીટર નામ વગેરે તરીકે નહીં) |
| `dummy data`                                               | ફિક્સ્ચર્સ માટેનો સામાન્ય સીડ શબ્દસમૂહ              |
| `foo bar baz`                                              | પ્રમાણભૂત પ્લેસહોલ્ડર શબ્દસમૂહ                      |
| પુનરાવર્તિત ટૂંકા ટોકન્સ (`AAA BBB CCC`, `test test test`) | કીવર્ડ સ્ટફિંગ માટેનું ડિટેક્ટર                     |

## લોડ હેઠળનું વર્તન

ટૂંકા સમયગાળામાં લગભગ 5 ઝડપી વિનંતીઓ પછી, WAF સામાન્ય રીતે પસાર થઈ જાય તેવી સામગ્રીને પણ બ્લૉક કરવાનું શરૂ કરે છે. લગભગ 5–10 સેકન્ડના નિષ્ક્રિય સમય પછી બકેટ શિથિલ થાય છે. આ એ જ IP-અને-key-આધારિત રેટ લિમિટર છે, જે Claude Code અથવા Codex CLI દ્વારા ઝડપથી એક પછી એક ઘણી tool-use / message-send કૉલ કરવામાં આવે ત્યારે અનિયમિત `400 content-blocked` ભૂલો સર્જે છે.

## OmniRouteમાં પહેલેથી લાગુ કરેલા ઉપાયો

1. **`open-sse/services/wafRateLimit.ts`** — બર્સ્ટ ગાર્ડ, જે કોઈપણ `agentrouter:*` URL તરફ જતી આઉટબાઉન્ડ વિનંતીઓ વચ્ચે ઓછામાં ઓછો 500 msનો અંતરાલ લાગુ કરે છે. આ અંતરાલ માનવીય રીતે અનુભવાય તેવી વિલંબ મર્યાદા કરતાં ઘણો ઓછો છે અને સામાન્ય ટ્રાફિક પર WAFને સક્રિય થતું અટકાવે છે.

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — જ્યારે કોઈ અપસ્ટ્રીમ
   `400 content-blocked` પરત કરે છે, ત્યારે એક્ઝિક્યુટર એ જ URL પર
   એક્સ્પોનેન્શિયલ બૅકઑફ (1.5 s, 3.0 s, વધુમાં વધુ 2 પ્રયાસો) સાથે ફરી પ્રયાસ કરે છે. બૅકઑફ પછી WAF સામાન્ય રીતે શિથિલ થાય છે અને પુનઃપ્રયાસ સફળ થાય છે.

3. **`tests/unit/compression/harness.test.ts`** — ટેસ્ટ ફિક્સ્ચર
   `longInput`ને `"lorem ipsum dolor sit amet ".repeat(40)`માંથી
   `"example content for testing purposes ".repeat(40)`માં બદલવામાં આવ્યું હતું, જેથી Claude Code આ ફાઇલને `Read` ટૂલ દ્વારા વાંચે ત્યારે ફાઇલની સામગ્રી `tool_result` બ્લૉક મારફતે પાછી ન વહે અને WAFને ટ્રિગર ન કરે.

## પ્રોમ્પ્ટ્સ અને ટૂલ આઉટપુટ માટે માર્ગદર્શન

જો Claude Code અથવા Codex CLI સેશનમાં વારંવાર
`400 content-blocked` આવે, તો ઉપરોક્ત કોઈ પેટર્ન માટે સૌથી તાજેતરનો યુઝર મેસેજ અને સૌથી તાજેતરનું ટૂલ પરિણામ તપાસો અને તેને ફરીથી શબ્દબદ્ધ કરો. સામાન્ય ઉપાયો:

- `Lorem ipsum …`ને `example text …` અથવા ટેસ્ટ કે ફિક્સ્ચર જે વાસ્તવિક સામગ્રીનું મોડેલિંગ કરવાનો પ્રયાસ કરે છે તેનાથી બદલો.
- `placeholder` (જ્યારે એકલું હોય)ને `example value`,
  `sample value` અથવા વાસ્તવિક મૂલ્યથી બદલો.
- `language model`ને `large language model` અથવા `the model`થી બદલો.
- `dummy data`ને `sample data` અથવા વાસ્તવિકતાસભર સીડ મૂલ્યોથી બદલો.
- `I'm here to help` / `here to help`ને વધુ ચોક્કસ
  શરૂઆતથી બદલો (દા.ત. "I'll review the file you mentioned").

## અપસ્ટ્રીમમાં ખોટા પોઝિટિવ્સની જાણ કરવી

વર્તમાન ફિલ્ટર અતિશય આક્રમક છે — તે `tool_result` બ્લૉક્સમાં "Lorem ipsum"ને બ્લૉક કરે છે, ભલે ઑપરેટરનો સ્પષ્ટપણે પ્રોમ્પ્ટ ઇન્જેક્ટ કરવાનો ઇરાદો ન હોય. જે ઑપરેટર્સ આ સમસ્યાને તેના મૂળ સ્ત્રોતે સુધારવા માંગે છે, તેમણે ખોટા પોઝિટિવ્સની જાણ કરવા માટે `agentrouter.org`નો સંપર્ક કરવો જોઈએ. ઉપરની બ્લૉકલિસ્ટ 2026-08-03ના રોજ અપસ્ટ્રીમની ચકાસણીમાંથી મળેલું પ્રયોગમૂલક પરિણામ છે.
