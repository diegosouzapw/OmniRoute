> **વ્યાપ નોંધ:** `socket.yml` npm આર્ટિફેક્ટના Socket.dev તરફના રજિસ્ટ્રી-સાઇડ પોસ્ટ-પબ્લિશ સ્કૅનને ગોઠવે છે (શિપ ન થતી સામગ્રી, જેમ કે `tests/`, `docs/`, અને બિલ્ડ રિપોર્ટ્સ માટેના ignore-paths). તે CI/PR મર્જ ગેટને જોડતું નથી — `.github/workflows`માં કોઈ workflow, `package.json`માં કોઈ script, અને કોઈ `Makefile` target Socket.devને ચલાવતું નથી.

આ દસ્તાવેજ `omniroute@3.8.5` સામે નોંધાયેલા છ
`AI-detected potential malware` તારણો અને `omniroute@3.8.6`માં લાગુ કરાયેલા
નિવારણો માટે સંભાળક-લિખિત પ્રમાણન છે. તેનો હેતુ છે કે:

1. સુરક્ષા-પાઇપલાઇન સંચાલકો પાસે તારણોનું વાસ્તવિક સ્રોત સામે મૂલ્યાંકન કરવાની જરૂર પડે ત્યારે
   ટાંકવા માટે એક જ સંદર્ભ હોય.
2. ભાવિ AI સ્કૅનર્સ સંભાળક-હસ્તાક્ષરિત દાવો ઓળખી શકે કે ચિહ્નિત કરેલો દરેક
   પાથ ઇરાદાપૂર્વકનો, સ્વૈચ્છિક રીતે સક્ષમ કરાતો, અને દસ્તાવેજીકૃત છે.
3. દરેક call siteનું સ્વરૂપ આવું _શા માટે_ છે તેનો અમારી પાસે લેખિત રેકોર્ડ હોય —
   જેથી ભાવિ refactor અજાણતાં એ fingerprint ફરી રજૂ ન કરે જેને
   જાણીજોઈને દૂર કરવામાં આવ્યું હતું.

જો તમે એવું scanner ચલાવો છો જે v3.8.6નાં નિવારણો રિલીઝ થયા પછી નીચેના કોઈપણ call siteને
ફરી ચિહ્નિત કરે, તો કૃપા કરીને scan trace સાથે issue ખોલો અને
અમે અહીં પ્રમાણનને વિસ્તૃત કરીશું.

## §1 — MITM રૂટ-CA ઇન્સ્ટોલેશન (`77484.js`)

**સ્રોત ફાઇલો**:

- `src/mitm/cert/install.ts` — જાહેર `installCert()` / `uninstallCert()`,
  દરેક પ્લેટફોર્મ માટે `installCertWindows/Mac/Linux`.
- `src/mitm/systemCommands.ts` — ઇન્સ્ટોલેશન પાથ દ્વારા ઉપયોગમાં લેવાતા વહેંચાયેલા `execFile` / `spawn` / PowerShell
  સહાયકો.

**ટ્રિગર**: વપરાશકર્તા સ્થાનિક ડૅશબોર્ડમાં
`/dashboard/cli-tools/mitm` પર "MITM પ્રોક્સી સક્ષમ કરો" પર ક્લિક કરે છે. આ રૂટ ફક્ત લૂપબૅક માટે છે — જુઓ
`CLAUDE.md` માં કડક નિયમ #17 અને `src/server/authz/routeGuard.ts::isLocalOnlyPath()`. ટનલ દ્વારા ખુલ્લું પડેલું
JWT આ કોડ પાથને **ટ્રિગર કરી શકતું નથી**.

**કરવામાં આવતી વિશેષાધિકારવાળી કામગીરીઓ (દરેક પ્લેટફોર્મ મુજબ)**:

| OS                     | કમાન્ડ                                                                                                            |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | UAC મારફતે `certutil -addstore Root <cert>`                                                                       |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | `certutil -d sql:<profile>` મારફતે દરેક પ્રોફાઇલની NSS DB અપડેટ                                                   |

આ એ જ કમાન્ડ છે જેનો ઉપયોગ `mitmproxy`, Charles Proxy, Fiddler અને
Caddy કરે છે. OmniRoute માં તેમનું અસ્તિત્વ
`docs/security/STEALTH_GUIDE.md` માં દસ્તાવેજીકૃત છે.

**v3.8.6 નિવારણ**:

- `runElevatedPowerShell()` હવે `-EncodedCommand <base64utf16le>` નો ઉપયોગ કરતું નથી.
  વિશેષાધિકાર સાથે ચાલનારી પેલોડને દરેક કૉલ માટેની અસ્થાયી `.ps1` ફાઇલમાં લખવામાં આવે છે (મોડ 0o600,
  ખાનગી `mkdtempSync` ડિરેક્ટરીની અંદર) અને `-File` મારફતે તેનો સંદર્ભ આપવામાં આવે છે. આ
  ફાઇલને `finally` માં અનલિંક કરવામાં આવે છે. આ Socket.dev ના AI
  ક્લાસિફાયર દ્વારા ચિહ્નિત કરાયેલી PowerShell મારફતે base64-એલિવેશનની પ્રચલિત ફિંગરપ્રિન્ટ દૂર કરે છે.
- `installCertWindows` માં અહીં નિર્દેશ કરતો ઇનલાઇન `SECURITY-AUDITOR-NOTE:` બ્લોક
  સામેલ છે.

**અમે તેને શા માટે રાખીએ છીએ**: MITM પ્રોક્સી એ
`docs/security/STEALTH_GUIDE.md` અને `docs/frameworks/MITM-PROXY.md` દ્વારા ઉપયોગમાં લેવાતી દસ્તાવેજીકૃત સુવિધા છે. તેને દૂર કરવાથી
એજન્ટ-બ્રિજ સુવિધા સમૂહ કામ કરવાનું બંધ કરી દેશે.

## §2 — Zed ક્રેડેન્શિયલ ઇમ્પોર્ટ (`app/api/providers/zed/import/route.js`)

**સોર્સ ફાઇલો**:

- `src/app/api/providers/zed/discover/route.ts` _(v3.8.6માં નવી)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(v3.8.6માં નવી)_

**ટ્રિગર**: વપરાશકર્તા સ્થાનિક ડૅશબોર્ડના Providers પેજ પર "Zedમાંથી ઇમ્પોર્ટ કરો" પર ક્લિક કરે છે. એન્ડપોઇન્ટ `requireManagementAuth` દ્વારા સુરક્ષિત છે. Zed એડિટર પોતે તેની પ્રોવાઇડર API કીઝને દસ્તાવેજીકૃત સર્વિસ નામો હેઠળ OS કીચેઇનમાં લખે છે — જુઓ https://zed.dev/docs/ai/llm-providers.

**v3.8.5નું વર્તન (જેને Socket.devએ ફ્લૅગ કર્યું હતું)**:

`POST /import` ક્રેડેન્શિયલ્સ શોધીને એક જ રાઉન્ડ-ટ્રિપમાં તેમને સ્થાનિક SQLite સ્ટોરમાં આપમેળે સાચવતું હતું. એકાઉન્ટ-દીઠ કોઈ પુષ્ટિ નહીં, કોઈ ફિંગરપ્રિન્ટ નહીં, માત્ર "N ટોકન્સ મળ્યાં, બધાં ઇમ્પોર્ટ કર્યાં."

**v3.8.6 નિવારણ — 2-પગલાંની પુષ્ટિ**:

1. **`POST /api/providers/zed/discover`**
   `{ candidates: [{ provider, service, account, fingerprint }] }` પરત કરે છે. મૂળ
   ટોકન **ક્યારેય** ટ્રાન્સમિટ થતું નથી. ફિંગરપ્રિન્ટ
   `sha256(service|account|token).slice(0,16)` છે.
2. ડૅશબોર્ડ ઉમેદવારોની સૂચિ રેન્ડર કરે છે, ઓપરેટર કયાને
   ઇમ્પોર્ટ કરવા તે પસંદ કરે છે અને `{ confirmedAccounts: [{ service, account, fingerprint }] }`
   ને **`POST /api/providers/zed/import`** પર પોસ્ટ કરે છે.
3. ઇમ્પોર્ટ એન્ડપોઇન્ટ **સર્વર પર કીચેઇન ફરીથી વાંચે છે** અને
   `(service, account, fingerprint)` દ્વારા ફિલ્ટર કરે છે. ચેડાં કરેલો અથવા ફરી ચલાવેલો discover
   પ્રતિસાદ ઇમ્પોર્ટ એન્ડપોઇન્ટને કોઈ અસંબંધિત ટોકન સાચવવા માટે છેતરી શકતો નથી —
   જો discover પછી લાઇવ ટોકન બદલાઈ ગયું હોય, તો ફિંગરપ્રિન્ટ હવે
   મેળ ખાતું નથી અને ક્રેડેન્શિયલ છોડી દેવામાં આવે છે.

`OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` env ફ્લૅગ એવા ઓપરેટર્સ માટે v3.8.5નું
વર્તન જાળવી રાખે છે, જેમણે હજી સુધી તેમનું ઑટોમેશન અપડેટ કર્યું નથી. તેને
v3.9માં દૂર કરવામાં આવશે.

**અમે તેને શા માટે રાખીએ છીએ**: જે વપરાશકર્તાઓ પહેલેથી Zedનો ઉપયોગ કરે છે અને
ફરીથી પેસ્ટ કર્યા વિના તેમની પ્રોવાઇડર કીઝને OmniRouteમાં મિરર કરવા માંગે છે,
તેમના માટે Zed ઇમ્પોર્ટ સૌથી સરળ ઑનબોર્ડિંગ માર્ગ છે.

## §3 — `execFile` / `spawn` / એલિવેટેડ PowerShell (`21843.js`)

**સોર્સ ફાઇલો**: `src/mitm/systemCommands.ts`.

**શા માટે ફ્લૅગ થયું**: ચંક `execFileWithPassword`,
`runElevatedPowerShell` અને શેર કરાયેલા `quotePowerShell` હેલ્પરને ફરીથી એક્સપોર્ટ કરે છે. Socket.devનું
AI ક્લાસિફાયર તેમને સામાન્ય "હોસ્ટ એક્ઝિક્યુશન + પ્રિવિલેજ એલિવેશન
ટૂલકિટ" તરીકે જુએ છે. OmniRouteમાં તેમનો ઉપયોગ ફક્ત MITM સર્ટિફિકેટ ઇન્સ્ટોલ પાથ
(§1) દ્વારા અને `sudo` કમાન્ડ એક્ઝિક્યુશન માટે `execFileWithPassword` દ્વારા થાય છે.

**v3.8.6 નિવારણ**:

- `runElevatedPowerShell` રિફેક્ટર (જુઓ §1).
- `runElevatedPowerShell` અને `execFileWithPassword` બંને પર ઇનલાઇન
  `SECURITY-AUDITOR-NOTE:` બ્લૉક મંજૂરી-સૂચિમાં રહેલા
  કૉલર્સ અને પિન કરેલી એક્ઝિક્યુટેબલ સૂચિને દસ્તાવેજીકૃત કરે છે.
- `execFileWithPassword`નો `spawn()` કૉલ `nosemgrep` માર્કર ધરાવે છે, જેમાં
  હેલ્પરને પ્રાપ્ત કરવાની મંજૂરી હોય તેવા એક્ઝિક્યુટેબલ્સની મંજૂરી-સૂચિ છે —
  વપરાશકર્તા ઇનપુટથી `finalCommand`/`finalArgs` સુધીનો **કોઈ પાથ નથી**.

## §4 / §6 — 9router સર્વિસ સુપરવાઇઝર (`api/services/9router/{start,restart}/route.js`)

**સોર્સ ફાઇલો**:

- `src/app/api/services/9router/_lib.ts` — સુપરવાઇઝર ફેક્ટરી.
- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`.
- `src/lib/services/ServiceSupervisor.ts` — સામાન્ય spawn / હેલ્થ-પોલ / લૉગ-બફર.

**ટ્રિગર**: વપરાશકર્તા સ્થાનિક ડૅશબોર્ડમાં એમ્બેડ કરેલા સર્વિસિસ પેજ પર
"ઇન્સ્ટોલ" / "સ્ટાર્ટ" ક્લિક કરે છે.

**પહેલેથી અમલમાં રહેલી સુરક્ષાઓ**:

- `src/server/authz/routeGuard.ts` મુજબ તમામ `/api/services/*` રૂટ્સ LOCAL_ONLY છે
  (કડક નિયમ #17). કોઈપણ ઑથ ચેક પહેલાં લૂપબૅક અમલીકરણ
  થાય છે — લીક થયેલું JWT તેમના સુધી પહોંચી શકતું નથી.
- 9router DB રોને `status='not_installed', auto_start=0` તરીકે સીડ કરવામાં આવે છે (જુઓ
  `src/lib/db/migrations/071_services.sql:19`). સર્વિસ પ્રથમ લૉન્ચ વખતે
  શરૂ **થતી નથી**.
- `spawn()`ને
  `src/lib/services/installers/ninerouter.ts`માં `resolveSpawnArgs(apiKey, PORT)` દ્વારા પરત કરાયેલા બાઇનરી પાથ સાથે કૉલ કરવામાં આવે છે,
  જે સમર્થિત બાઇનરીઝની નિશ્ચિત મંજૂરી-સૂચિ છે.
- Stdout/stderrને મેમરીમાં બફર કરવામાં આવે છે (5 MB મર્યાદા, જુઓ `_lib.ts`) — જ્યાં સુધી
  વપરાશકર્તા ડૅશબોર્ડમાંથી લૉગિંગ સક્ષમ ન કરે ત્યાં સુધી ડિસ્ક પર કશું લખાતું નથી.

**v3.8.6 નિવારણ**: કોઈ કાર્યાત્મક ફેરફાર નથી. ન્યૂનતમ બિલ્ડ પ્રોફાઇલ
(`OMNIROUTE_BUILD_PROFILE=minimal`) એવા વપરાશકર્તાઓ માટે
`src/lib/services/installers/ninerouter.ts`ને સ્ટબથી બદલે છે, જેઓ
બંડલમાંથી પ્રિવિલેજ્ડ પાથ્સને ભૌતિક રીતે દૂર કરવા માંગે છે.

**અમે તેને શા માટે રાખીએ છીએ**: 9router વૈકલ્પિક, સ્થાનિક રીતે ઇન્સ્ટોલ કરી શકાય તેવી સહાયક
સર્વિસ છે (વિચારો: WordPress-શૈલીનું પ્લગઇન) — સખત રીતે ઑપ્ટ-ઇન.

## §5 — OmniRoute Cloud Sync ક્રેડેન્શિયલ રાઇટ-બૅક (`api/keys/[id]/route.js`)

**સ્રોત ફાઇલો**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`.
- `src/app/api/keys/[id]/route.ts` — `syncKeysToCloudIfEnabled()`ને કૉલ કરે છે.

**ટ્રિગર**: `isCloudEnabled()` `true` પરત કરે છે (ડૅશબોર્ડમાંથી સેટ કરેલું) **અને**
`CLOUD_URL` કૉન્ફિગર કરેલું હોય. બંને બંધ હોય ત્યારે Cloud એન્ડપોઇન્ટ પર કોઈ
આઉટબાઉન્ડ નેટવર્ક કૉલ કરવામાં આવતો નથી.

**v3.8.5નું વર્તન (Socket.devએ યોગ્ય રીતે પકડી પાડેલો બગ)**:

જ્યારે `cloudUpdatedAt > localUpdatedAt` હોય ત્યારે `updateLocalTokens()`એ
Cloud પ્રતિસાદમાંથી `accessToken`, `refreshToken`, અને
`providerSpecificData`ને ઓવરરાઇટ કર્યા. કોઈ HMAC નહીં, કોઈ સહી નહીં, કોઈ
ચેકસમ નહીં. ખોટી રીતે કૉન્ફિગર કરેલું અથવા દુર્ભાવનાપૂર્ણ `CLOUD_URL` (અથવા
ચૅનલ પરનો MITM) પ્રોવાઇડરના OAuth ટોકનને શાંતિથી બદલી શકતો હતો.

**v3.8.6માં નિવારણ**:

1. **HMAC ચકાસણી**: JSON પાર્સ કરતાં પહેલાં `verifyCloudSignature(rawBody, sigHeader)`
   `X-Cloud-Sig` હેડર (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`) તપાસે છે. જો સિક્રેટ સેટ કરેલું હોય, તો સહી આવશ્યક છે.
   જો ન હોય (લેગસી મોડ), તો ચેતવણી લૉગ કરવામાં આવે છે અને પ્રતિસાદ
   સ્વીકારવામાં આવે છે — v3.9માં સિક્રેટ આવશ્યક બનશે.
2. **સિક્રેટ-ફીલ્ડ ઑપ્ટ-ઇન**: `accessToken` / `refreshToken` /
   `providerSpecificData`ને **ફક્ત** ત્યારે જ ઓવરરાઇટ કરવામાં આવે છે જ્યારે
   `OMNIROUTE_CLOUD_SYNC_SECRETS=true` હોય. ડિફૉલ્ટ મોડ માત્ર
   નૉન-ક્રેડેન્શિયલ મેટાડેટા (`expiresAt`, `status`, `lastError*`,
   `rateLimitedUntil`, `updatedAt`) સિંક કરે છે. રિમોટ ટોકન સિંક પર આધાર રાખતા
   વપરાશકર્તાઓ માટે આ એક **બ્રેકિંગ ચેન્જ** છે — તેમણે સ્પષ્ટપણે ઑપ્ટ-ઇન કરવું પડશે.

**અમે તેને શા માટે રાખીએ છીએ**: OmniRoute Cloud ટેનન્ટ માટે ટીમના
ક્રેડેન્શિયલ્સને કેન્દ્રિયકૃત કરવાનો Cloud Sync એકમાત્ર માર્ગ છે. સુધારો
થ્રેટ મોડલને પ્રામાણિક બનાવે છે:
"સર્વર સહી કરે છે, ક્લાયન્ટ ચકાસે છે, ઑપરેટર ઑપ્ટ-ઇન કરે છે."

## બિલ્ડ પ્રોફાઇલ: `minimal`

Socket-અનુકૂળ આર્ટિફેક્ટની જરૂર હોય તેવા વપરાશકર્તાઓ આ રીતે બિલ્ડ કરે:

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

webpack `NormalModuleReplacementPlugin` ચાર મોડ્યુલને સ્ટબ સાથે એલિયાસ કરે છે:

| મોડ્યુલ                                     | સ્ટબ                                             |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

દરેક સ્ટબ સમાન સરફેસ એક્સપોર્ટ કરે છે, પરંતુ દરેક ફંક્શન રનટાઇમ પર
`featureDisabledError(name)` થ્રો કરે છે. અક્ષમ કરેલા મોડ્યુલ પર આધારિત
રૂટ્સ સંવેદનશીલ કોડ પાથ સક્રિય કરવાને બદલે સ્પષ્ટ સંદેશ સાથે HTTP 503
પરત કરે છે.

પરિણામી બંડલને `omniroute-secure` તરીકે પ્રકાશિત કરવાનો હેતુ છે.
પ્રકાશન પ્રક્રિયા માટે `docs/ops/PUBLISHING_SECURE.md` જુઓ.
