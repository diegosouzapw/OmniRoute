## અવલોકન

Quota Sharing Engine એક જ કનેક્શન શેર કરતી બહુવિધ API કીઓ વચ્ચે પ્રદાતાનો સમય-આધારિત ક્વોટા (દા.ત. Codex
5-કલાકની વિન્ડો, Kimi 1500 req/h) ન્યાયસંગત રીતે વિતરિત કરે છે.

**તે જે સમસ્યા ઉકેલે છે:** OmniRoute એક જ અપસ્ટ્રીમ પ્રદાતા એકાઉન્ટ સામે ઘણી API કીઓને
પ્રોક્સી કરે છે. શેરિંગ લોજિક વિના, કી A તરફથી આવતો અચાનક ભારે પ્રવાહ એક કલાક માટેનો
પ્રદાતાનો ક્વોટા સમાપ્ત કરી શકે છે, જેના કારણે વિન્ડો રીસેટ થાય ત્યાં સુધી કીઓ B અને C અવરોધિત રહે છે.
એન્જિન આને નીચે મુજબ અટકાવે છે:

1. દરેક પરિમાણ (%, requests, tokens, $) માટે પ્રત્યેક કીના રોલિંગ વપરાશને ટ્રૅક કરીને.
2. કાર્ય-સંરક્ષક ન્યાયસંગત-હિસ્સા અલ્ગોરિધમ લાગુ કરીને: જ્યાં સુધી વૈશ્વિક પૂલ સંતૃપ્ત ન હોય ત્યાં સુધી કી નિષ્ક્રિય
   હિસ્સાઓમાંથી ઉધાર લઈ શકે છે.
3. વિનંતી અપસ્ટ્રીમ એક્ઝિક્યુટર સુધી પહોંચે તે પહેલાં હૉટ પાથ (`chatCore.ts`) માં પરિણામ
   લાગુ કરીને.

## અલ્ગોરિધમ: કાર્ય-સંરક્ષક ન્યાયસંગત હિસ્સો

`src/lib/quota/fairShare.ts` માં અમલમાં મૂકાયેલ છે.

### મોડ્સ

| શરત                                        | મોડ      | વર્તન                                                           |
| ------------------------------------------ | -------- | --------------------------------------------------------------- |
| `globalUsedPercent < saturationThreshold`  | **ઉદાર** | કી વપરાયેલા કુલને બાદ કરીને વૈશ્વિક મર્યાદા સુધી ઉધાર લઈ શકે છે |
| `globalUsedPercent >= saturationThreshold` | **કડક**  | વ્યક્તિગત ન્યાયસંગત હિસ્સો સખતાઈથી લાગુ કરો                     |

ડિફૉલ્ટ `saturationThreshold = 0.5` (env `QUOTA_SATURATION_THRESHOLD`).

### પ્રત્યેક પરિમાણ માટેનો નિર્ણય

પૂલના દરેક સક્રિય પરિમાણ માટે, એન્જિન નીચે મુજબ ગણતરી કરે છે:

```
fairShareAllowed = poolLimit × (allocationWeight / 100)
consumed        = આ કી માટેનું વર્તમાન રોલિંગ મૂલ્ય (QuotaStore.peek માંથી)
remaining       = fairShareAllowed - consumed
```

ત્યારબાદ:

- **`policy = hard`**: જો `consumed > fairShareAllowed` અને મોડ કડક હોય → **અવરોધો**.
- **`policy = soft`**: જો `consumed > fairShareAllowed` અને મોડ કડક હોય → **દંડિત કરો** (combo માં પ્રાથમિકતા ઘટાડો; ક્યારેય સખત રીતે અવરોધશો નહીં).
- **`policy = burst`**: ન્યાયસંગત હિસ્સાની પરવા કર્યા વિના વૈશ્વિક અવકાશ ઉપલબ્ધ હોય ત્યાં સુધી મંજૂરી આપો.

### નિરપેક્ષ મર્યાદા

એલોકેશન પરના `capValue` + `capUnit` એ મોડ અથવા
પૉલિસીથી સ્વતંત્ર સખત ઉચ્ચ મર્યાદા છે. જે કોઈ પરિમાણમાં `consumed >= capValue` હોય તે હંમેશાં વિનંતીને **અવરોધે** છે.

### બહુ-પરિમાણીય તપાસ

જો પૂલનું **કોઈપણ** પરિમાણ વિનંતીને અવરોધતું હોય, તો વિનંતી અવરોધવામાં આવે છે. પરિમાણો
સ્વતંત્ર છે — 5h% સમાપ્ત થવાથી weekly% પરિમાણને અસર થતી નથી.

### ઉધાર લેવું

ઉદાર મોડમાં, જે કીનું એલોકેશન ઓછું વપરાયું હોય તે અન્ય
કીઓના ફાળવાયા ન હોય તેવા હિસ્સાઓનો વધારાનો ભાગ વાપરી શકે છે. સૂત્ર આ પ્રમાણે છે:

```
maxAllowed = globalLimit - consumedByOtherKeys
```

જ્યાં `consumedByOtherKeys = consumedTotal - consumedByThisKey`. વૈશ્વિક ઉચ્ચ મર્યાદા
(તે પરિમાણ માટે પૂલની `limit`) હંમેશાં સખત મર્યાદા હોય છે.

## સ્લાઇડિંગ વિન્ડો કાઉન્ટર

`src/lib/quota/sqliteQuotaStore.ts` અને `redisQuotaStore.ts` માં અમલમાં મૂકાયેલ છે.

પ્રત્યેક `(apiKeyId, dimensionKey)` માટે બે બકેટ:

- `curr`: વર્તમાન બકેટ (`floor(nowMs / windowMs)`)
- `prev`: અગાઉનું બકેટ (`curr - 1`)

અસરકારક રોલિંગ મૂલ્ય:

```
effectiveBucketIndex = floor(nowMs / windowMs)
bucketStartMs        = effectiveBucketIndex × windowMs
elapsed              = nowMs - bucketStartMs
weight               = 1 - elapsed / windowMs

effective = prev × weight + curr
```

**ચોકસાઈ**: ~99% ચોક્કસ. બકેટ્સ વચ્ચેની સીમા પર ભૂલ વધુમાં વધુ વિન્ડોના કદના 1% જેટલી હોય છે
(2-બકેટના અંદાજમાં આ સ્વાભાવિક છે).

### સમકાલીનતા

SQLite ડ્રાઇવર: પ્રત્યેક `(apiKeyId | dimensionKey)` કી માટેનો ઇન-મેમરી mutex
read-modify-write રેસને અટકાવે છે. પેટર્ન `src/sse/services/auth.ts` ના anti-thundering-herd જેવું છે.

Redis ડ્રાઇવર: ઍટોમિક ઇન્ક્રિમેન્ટ માટે Lua EVAL સ્ક્રિપ્ટ — એક જ Redis કમાન્ડ તરીકે ચાલે છે.

## ડ્રાઇવર્સ

### SQLite (ડિફૉલ્ટ, 0-ઇન્સ્ટૉલ)

- ટેબલ: `quota_consumption` (માઇગ્રેશન `073_quota_pools.sql` / `074_quota_consumption.sql` જુઓ).
- સિંગલ-ઇન્સ્ટન્સ ડિપ્લોયમેન્ટ માટે શ્રેષ્ઠ.
- તમામ પર્સિસ્ટન્સ હાલના OmniRoute SQLite DB (`DATA_DIR/storage.sqlite`)માં રહે છે.

### Redis (વૈકલ્પિક, મલ્ટિ-ઇન્સ્ટન્સ)

- `ioredis` npm પૅકેજ જરૂરી છે.
- કાઉન્ટર્સ Redisમાં સંગ્રહિત થાય છે; મેટાડેટા (પૂલ્સ/ફાળવણીઓ) હજુ પણ SQLiteમાં રહે છે.
- જ્યાં કાઉન્ટર્સ શેર કરવા આવશ્યક હોય તેવા મલ્ટિ-રેપ્લિકા ડિપ્લોયમેન્ટ માટે શ્રેષ્ઠ.

### ડ્રાઇવર્સ બદલવા

સેટિંગ્સ UI (`/dashboard/settings` → ક્વોટા સ્ટોર) દ્વારા, અથવા env vars દ્વારા:

```bash
QUOTA_STORE_DRIVER=redis
QUOTA_STORE_REDIS_URL=redis://localhost:6379
```

DB સેટિંગને env કરતાં પ્રાથમિકતા મળે છે. જો `driver=redis` હોય પરંતુ URL ગેરહાજર હોય અથવા
`ioredis` ઇન્સ્ટૉલ ન હોય, તો ફેક્ટરી SQLite પર પાછી ફરે છે અને ચેતવણી લૉગ કરે છે.

ડ્રાઇવર પસંદગીનો ક્રમ:

1. DB સેટિંગ `quotaStore.driver`
2. Env `QUOTA_STORE_DRIVER`
3. ડિફૉલ્ટ: `sqlite`

## બહુ-પરિમાણ

એક પૂલમાં અનેક પરિમાણો હોઈ શકે છે. દરેક પરિમાણ સ્વતંત્ર છે:

```ts
QuotaDimension {
  unit: "percent" | "requests" | "tokens" | "usd",
  window: "5h" | "hourly" | "daily" | "weekly" | "monthly",
  limit: number,  // આ પરિમાણ માટે વૈશ્વિક પૂલ મર્યાદા
}
```

**ઉદાહરણ: Codex પ્લાન** (5h% + સાપ્તાહિક%):

```json
[
  { "unit": "percent", "window": "5h", "limit": 100 },
  { "unit": "percent", "window": "weekly", "limit": 100 }
]
```

વિનંતીને મંજૂરી મળવા માટે તેણે તમામ પરિમાણોને સંતોષવા આવશ્યક છે.

## પાઇપલાઇન ઇન્ટિગ્રેશન

### PRE હૂક (`open-sse/handlers/chatCore.ts`)

ઑથ અને પૉલિસી ચકાસણીઓ પછી, અપસ્ટ્રીમ એક્ઝિક્યુટર પહેલાં ચાલે છે:

```
resolveComboTargets / handleSingleModel
  → enforceQuotaShare(apiKeyId, connectionId, provider, estimatedCost)
      → પ્રત્યેક પરિમાણ માટે getQuotaStore().peek()
      → fairShare.decideFairShare()
      → જો બ્લૉક થાય → 429 પરત કરો (buildErrorBody, સખત નિયમ #12)
      → જો મંજૂરી + ડિપ્રાયોરિટાઇઝ થાય → કૅન્ડિડેટ પર quotaSoftPenalty=true સેટ કરો
  → executor.execute()
```

**ફેલ-ઓપન**: જો `enforceQuotaShare` થ્રો કરે, તો `pino.warn` લૉગ સાથે વિનંતીને
પસાર થવા દેવામાં આવે છે. આ ક્વોટા-એન્જિનની બગને તમામ ટ્રાફિક બ્લૉક કરવાથી અટકાવે છે.

### POST હૂક (વપરાશ રેકોર્ડ કરવો)

સફળ પ્રતિસાદ પછી:

```
એક્ઝિક્યુટર સફળતા પરત કરે છે
  → spendRecorder.recordConsumption(apiKeyId, connectionId, provider, actualCost)
      → પ્રત્યેક પરિમાણ માટે getQuotaStore().consume()
      → ફેલ-ઓપન: ભૂલો pino.warn તરીકે લૉગ થાય છે, ક્લાયન્ટ સુધી ક્યારેય પ્રસારિત થતી નથી
```

**ડ્રિફ્ટ નોંધ**: જો પ્રતિસાદ પછી `consume` નિષ્ફળ જાય, તો રોલિંગ કાઉન્ટર ઓછી ગણતરી કરે છે.
પ્રોવાઇડર તરફથી મળતો સૅચ્યુરેશન સિગ્નલ (દા.ત. `anthropic-ratelimit-unified-5h-utilization`)
આગલી વિનંતી પર વૈશ્વિક અંદાજને સુધારે છે.

### કોમ્બો સૉફ્ટ પેનલ્ટી (`open-sse/services/combo.ts`)

જ્યારે `decision.deprioritize === true` હોય:

```ts
if (candidate.quotaSoftPenalty) {
  score *= QUOTA_SOFT_DEPRIORITIZE_FACTOR; // ડિફૉલ્ટ 0.7
}
```

આ પેનલ્ટી અન્ય તમામ સ્કોરિંગ પરિબળો પછી લાગુ કરવામાં આવે છે. તે સૅચ્યુરેટ થયેલી કીને
હાર્ડ-બ્લૉક કર્યા વિના પસંદ કરવાની ઑટો-કોમ્બો સંભાવના ઘટાડે છે.

## સમસ્યા નિવારણ

### Redis કૉન્ફિગર કરેલું છે પરંતુ કનેક્ટ થતું નથી

ચકાસો કે `ioredis` ઇન્સ્ટૉલ થયેલું છે (`npm ls ioredis`) અને `QUOTA_STORE_REDIS_URL`
સુધી પહોંચી શકાય છે. કનેક્શન નિષ્ફળ જાય ત્યારે ફૅક્ટરી SQLite પર પાછી ફરે છે
(`warn` સ્તરે લૉગ થાય છે).

### `peek` જૂનું પરિણામ આપે છે / ફેલ-ઓપન

જો `peek` થ્રો કરે, તો `enforceQuotaShare` પરિણામને "પરવાનગી આપો" (ફેલ-ઓપન) તરીકે ગણે છે.
મૂળ કારણ ઓળખવા માટે `quota:enforce` અને `quota:factory` એન્ટ્રીઓ માટે `pino` લૉગ્સ
ચકાસો.

### વપરાશ કાઉન્ટરમાં વિસંગતિ

જો પ્રોવાઇડરનો વાસ્તવિક વપરાશ કાઉન્ટર્સથી અલગ હોય, તો તે અપેક્ષિત છે — 2-બકેટ
સ્લાઇડિંગ વિન્ડોમાં વિન્ડોની સીમાઓ પર ~1% ભૂલ હોય છે અને `consume` પ્રતિભાવ પછી
ફાયર-એન્ડ-ફર્ગેટ રીતે ચાલે છે. સૅચ્યુરેશન સિગ્નલ (`saturationSignals.ts`)
30s TTL સાથે પ્રોવાઇડરનો વાસ્તવિક ઉપયોગ વાંચે છે અને તે અનુસાર `globalUsedPercent`
સમાયોજિત કરે છે.

### પૂલ બર્ન રેટ માટે "કોઈ ડેટા નથી" બતાવે છે

`computeBurnRate` માટે ઓછામાં ઓછા 2 ઐતિહાસિક નમૂનાઓ જરૂરી છે. અગાઉના
`consume` કૉલ્સ વગરના નવા પૂલ્સ `tokensPerSecond: 0` અને `timeToExhaustionMs: null`
બતાવશે.

## DB સ્કીમાનો સારાંશ

માઇગ્રેશન `078`, `079` અને `085` દ્વારા ત્રણ ટેબલ ઉમેરવામાં આવ્યા છે:

- `quota_pools` + `quota_allocations` — પૂલની વ્યાખ્યાઓ અને દરેક કી દીઠ ફાળવણી.

બધા ટેબલ આઇડેમ્પોટન્ટ `CREATE TABLE IF NOT EXISTS` માઇગ્રેશન દ્વારા ઉમેરવામાં આવ્યા છે.
