છેલ્લે અપડેટ કરેલ: 2026-06-28

> 2026-05-13ના રોજ માપવામાં આવેલી સ્થિતિ: લાઇનો 82.58%, સ્ટેટમેન્ટ્સ 82.58%, ફંક્શન્સ 84.23%, બ્રાન્ચો 75.22%. તબક્કા 1-5 પૂર્ણ થયા છે. વર્તમાન ધ્યાન તબક્કો 6 (>=85%) અને તબક્કો 7 (>=90%) પર છે.

## આધારરેખા

## નિયમો

- કવરેજ લક્ષ્યો સોર્સ ફાઇલોને લાગુ પડે છે, `tests/**`ને નહીં.
- `open-sse/**` પ્રોડક્ટનો ભાગ છે અને તે વ્યાપમાં જ રહેવો જોઈએ.
- નવા કોડે સ્પર્શ કરેલા વિસ્તારોમાં કવરેજ ઘટાડવું જોઈએ નહીં.
- અમલીકરણની વિગતો કરતાં વર્તન અને બ્રાન્ચનાં પરિણામોનું પરીક્ષણ કરવાનું પસંદ કરો.
- `src/lib/db/**` માટે વ્યાપક મૉક્સ કરતાં અસ્થાયી SQLite ડેટાબેઝ અને નાના ફિક્સ્ચર્સને પ્રાધાન્ય આપો.

## વર્તમાન કમાન્ડ સમૂહ

- `npm run test:coverage`
  - યુનિટ ટેસ્ટ સ્યુટ માટેનું મુખ્ય સોર્સ કવરેજ ગેટ
  - `text-summary`, `html`, `json-summary`, અને `lcov` જનરેટ કરે છે
- `npm run coverage:report`
  - સૌથી તાજેતરના રનમાંથી વિગતવાર ફાઇલ-દર-ફાઇલ રિપોર્ટ
- `npm run test:coverage:legacy`
  - ફક્ત ઐતિહાસિક સરખામણી માટે

## રૅચેટ નીતિ

પ્રોજેક્ટ આરામદાયક માર્જિન સાથે આગળનો માઇલસ્ટોન વાસ્તવમાં પાર કરે ત્યાર પછી જ `npm run test:coverage` થ્રેશોલ્ડ અપડેટ કરો.

**વર્તમાન ગેટ:** `npm run test:coverage` **60 સ્ટેટમેન્ટ્સ / 60 લાઇન્સ / 60 ફંક્શન્સ / 60 બ્રાન્ચિસ** લાગુ કરે છે (Quality-Gates તબક્કા 6A.1માં મેટ્રિકને ફરીથી આધારિત કરવામાં આવ્યું હતું — અગાઉની 82.58% બેઝલાઇન વધુ દર્શાવતી હતી, કારણ કે તેમાં ટેસ્ટ ફાઇલોની ગણતરી થતી હતી અને `open-sse`ને બાકાત રાખવામાં આવતું હતું). `test:coverage:legacy` કમાન્ડ ઐતિહાસિક સરખામણી માટે જૂના 50/50/50 મેટ્રિકને જાળવી રાખે છે.

નવીનતમ રિપોર્ટ સામે તાત્કાલિક થ્રેશોલ્ડ તપાસ માટે આનો ઉપયોગ કરો:

```bash
node scripts/check/test-report-summary.mjs --threshold 75
```

જ્યારે બ્રાન્ચ કવરેજ સતત બે રન માટે 78%થી ઉપર જળવાય, ત્યારે આગામી રૅચેટ લક્ષ્ય `80/75/78` છે.

## જાણીતી ખામી

વર્તમાન કવરેજ કમાન્ડ મુખ્ય Node યુનિટ સ્યુટને માપે છે અને તેના દ્વારા પહોંચવામાં આવતા સોર્સને સમાવે છે, જેમાં `open-sse` પણ સામેલ છે. તે હજી સુધી Vitest કવરેજને એક જ એકીકૃત રિપોર્ટમાં મર્જ કરતું નથી. આ મર્જ પછીથી કરવું યોગ્ય છે, પરંતુ 60% -> 80% સુધીની પ્રગતિ શરૂ કરવા માટે તે અવરોધ નથી.
