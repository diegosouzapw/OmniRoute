હોમોલોગેશન VPS પર ચાલી રહેલા OmniRoute ડિપ્લોયનું વાસ્તવિક-પર્યાવરણ E2E માન્યકરણ
(`HOMOLOG_BASE_URL`, ઉદાહરણ તરીકે `http://192.168.0.15:20128`). એક કમાન્ડ મેન્યુઅલ
રિલીઝ STOP #2 ચેકલિસ્ટને સ્વચાલિત, પુરાવા ઉત્પન્ન કરતા રનથી બદલે છે.

## પૂર્વજરૂરિયાતો

1. `.env.homolog.example` ને `.env.homolog` માં કૉપિ કરો (gitignored — તેને ક્યારેય commit કરશો નહીં) અને આ વિગતો भरो:
   - `HOMOLOG_BASE_URL` — લક્ષ્ય deploy, દા.ત. `http://192.168.0.15:20128`.
   - `HOMOLOG_ADMIN_PASSWORD` — તે deploy માટેનો dashboard સંચાલન password.
   - `HOMOLOG_CRITICAL_PROVIDERS` — comma વડે અલગ કરેલા provider prefixes, જેમને વાસ્તવિક smoke chat request મોકલવામાં આવે છે (દા.ત. `openai,anthropic,gemini,codex,grok,glm,deepseek,openrouter`).
   - `HOMOLOG_API_KEY` — સામાન્ય runs માં ખાલી રાખો; suite પોતાની અલ્પજીવી key બનાવે છે અને revoke કરે છે. ફક્ત કોઈ એક layer ને અલગથી debug કરવા માટે જ આ સેટ કરો.
2. repo માં `npm install` ચલાવો (suite ની dependencies — `httpyac`, `promptfoo`, `playwright-ctrf-json-reporter`, `junit-to-ctrf`, `ctrf` — નિયમિત devDependencies છે).
3. જો browser binaries પહેલેથી હાજર ન હોય, તો `npx playwright install` ચલાવો.

## કેવી રીતે ચલાવવું

```bash
npm run homolog
```

જે deploy નું version સ્થાનિક `package.json` સાથે મેળ ખાતું ન હોય તેની સામે માન્યતા તપાસવા માટે (દા.ત. homologation box હજી પણ અગાઉના patch release પર હોય), અપેક્ષિત version ને સ્પષ્ટ રીતે override કરો:

```bash
HOMOLOG_EXPECT_VERSION=3.8.47 npm run homolog
```

કોઈપણ layer નિષ્ફળ જાય તો run non-zero સ્થિતિ સાથે બહાર નીકળે છે અને નિષ્ફળતા થાય તોપણ તેણે બનાવેલી અલ્પજીવી API key ને revoke કરવાનો હંમેશાં પ્રયાસ કરે છે (`scripts/homolog/run.mjs` માંનો `finally` block).

## Report વાંચવો

તમામ output `homolog-report/` માં જાય છે (gitignored):

- `summary.md` — stdout પર પ્રિન્ટ થયેલું એ જ table, દરેક layer માટે એક row (✅/❌ + વિગત).
- `homolog-ctrf.json` — એકીકૃત CTRF report (API/SSE, provider-smoke અને UI પરિણામોનું merge) — release STOP #2 checklist સાથે જોડવાનો artifact આ છે.
- `httpyac-junit.xml`, `api-ctrf.json`, `providers-ctrf.json`, `ui-ctrf.json` — દરેક layer ના raw/intermediate reports.
- `promptfooconfig.yaml`, `provider-misses.json` — વર્તમાન run માટે બનાવેલું promptfoo config અને live catalog માંથી ગેરહાજર રહેલા કોઈપણ critical providers.

નિષ્ફળ થતું L0 તરત જ પ્રક્રિયા અટકાવે છે (કોઈ અલ્પજીવી key બનાવવામાં આવતી નથી), કારણ કે version/health mismatch નો અર્થ એ થાય છે કે દરેક downstream layer ખોટા deploy ની માન્યતા તપાસશે.

## UI માં કાયદેસર ફેરફાર થાય ત્યારે baseline ફરીથી સેટ કરવું

L4b (route smoke) અને L4c (API-key UI flow) snapshots નહીં, પરંતુ વાસ્તવિક DOM locators દ્વારા સંચાલિત થાય છે, તેથી મોટાભાગના કાયદેસર UI ફેરફારો માટે suite માં કોઈ update જરૂરી નથી. જ્યારે કોઈ ફેરફાર locator ને ખરેખર તોડે (દા.ત. button label નું નામ બદલાયું હોય અથવા settings page ખસેડાયું હોય):

1. વર્તમાન source સામે locator ની ફરીથી ખાતરી કરો (દરેક locator કઈ file/line સામે ચકાસવામાં આવ્યું હતું તે specs માં પહેલેથી દસ્તાવેજિત છે — એ જ pattern અનુસરો, અનુમાન ન કરો).
2. `tests/homolog/ui/` માં spec ને update કરો.
3. સુધારાની ખાતરી કરવા માટે VPS સામે `npm run homolog` ફરીથી ચલાવો (અથવા માત્ર અસરગ્રસ્ત Playwright spec ચલાવો), ત્યારબાદ commit કરો.

આ suite માં કોઈ visual/pixel baseline નથી (F1) — તે માટે Roadmap જુઓ.

## Roadmap (F2 / F3)

Design અને તબક્કાવાર rollout આંતરિક planning spec `_tasks/superpowers/specs/2026-07-13-homolog-e2e-suite-design.md` માં છે (link કરેલું નથી — આંતરિક `_tasks/` artifact, આ repo ના tracked docs નો ભાગ નથી). સારાંશ:

- **F2** — સંપૂર્ણ walkthrough recording → Playwright Test Agents (`planner`/`generator`) તેને flow specs માં ફેરવે છે (combo બનાવવું, provider ચકાસવું, settings edit કરવું, MCP tools) + dynamic data (metrics, timestamps, logs) પર masks સાથે visual regression baseline (Lost Pixel) + દરેક release માટે `healer` maintenance routine.
- **F3** — resilience/contract/wiring coverage: devbox પર toxiproxy + નકલી OpenAI-compatible provider, તેની તરફ નિર્દેશ કરતું VPS પરનું `homolog-resilience` combo (injected timeout → `/api/monitoring/health` મારફતે fallback + circuit breaker open/close ની ખાતરી); `docs/openapi.yaml` સામે gated Schemathesis contract testing (ઓછું `--max-examples`, નિશ્ચિત seeds, ફક્ત non-LLM endpoints); અને `/generate-release` STOP #2 phase માં `npm run homolog` + તેના `summary.md` નું wiring.
