> **છેલ્લે અપડેટ કરેલું:** 2026-06-28 — v3.8.40

OmniRoute તેના સ્થાનિક સર્વર (`http://localhost:20128`)ને ત્રણ ટનલ બૅકએન્ડ દ્વારા જાહેર
ઇન્ટરનેટ પર ઉપલબ્ધ કરાવી શકે છે. આ નીચેના કિસ્સાઓમાં ઉપયોગી છે:

- જાહેર રીતે ઍક્સેસ કરી શકાય તેવા રીડાયરેક્ટ URLની જરૂર ધરાવતા ક્લાઉડ પ્રદાતાઓ
  (Antigravity, Gemini, Cursor) તરફથી આવતા OAuth કૉલબૅક્સ.
- VM ડિપ્લોય કર્યા વિના તમારી સ્થાનિક ઇન્સ્ટન્સને ટીમના સભ્યો સાથે શેર કરવી.
- મોબાઇલ, રિમોટ અથવા ક્રોસ-નેટવર્ક પરીક્ષણ.

ત્રણેય બૅકએન્ડ પ્રક્રિયાની અંદર જ સંચાલિત થાય છે — OmniRoute ડૅશબોર્ડ અથવા REST API
દ્વારા અંતર્નિહિત બાઇનરી અથવા SDKને શરૂ/બંધ કરે છે. કોઈ રિવર્સ-પ્રૉક્સી અથવા systemd
સેટઅપની જરૂર નથી.

## બૅકએન્ડ્સ એક નજરે

| બૅકએન્ડ                     | સ્થાયિત્વ                                                          | ખર્ચ                     | સેટઅપ                                            |
| --------------------------- | ------------------------------------------------------------------ | ------------------------ | ------------------------------------------------ |
| **Cloudflare Quick Tunnel** | ક્ષણિક (દરેક રીસ્ટાર્ટ વખતે URL બદલાય છે)                          | મફત                      | શૂન્ય — `cloudflared` આપમેળે ઇન્સ્ટોલ કરે છે     |
| **ngrok**                   | પેઇડ પ્લાન અથવા નિશ્ચિત ડોમેન કૉન્ફિગર કરેલું હોય ત્યાં સુધી સ્થિર | મફત ટિયર + પેઇડ          | ngrok એકાઉન્ટ + authtoken જરૂરી                  |
| **Tailscale Funnel**        | તમારા tailnetમાં દરેક નોડ માટે સ્થિર                               | વ્યક્તિગત ઉપયોગ માટે મફત | Tailscale ઇન્સ્ટોલેશન + લૉગિન + Funnel ACL જરૂરી |

ઇમ્પ્લિમેન્ટેશન્સ `src/lib/cloudflaredTunnel.ts`,
`src/lib/ngrokTunnel.ts` અને `src/lib/tailscaleTunnel.ts`માં છે. ત્રણેય `phase`,
`running`, `publicUrl`, `apiUrl`, `targetUrl` અને `lastError` ફીલ્ડ ધરાવતું એકસરખી
રચનાવાળું `status` ઑબ્જેક્ટ પરત કરે છે, જેથી ડૅશબોર્ડ તેમને એકસમાન રીતે રેન્ડર કરી શકે.

## 1. Cloudflare Tunnel (Quick Tunnel + Named Tunnel)

`src/lib/cloudflaredTunnel.ts`, `cloudflared`ને ચાઇલ્ડ પ્રોસેસ તરીકે ચલાવે છે. તે
બે મોડને સપોર્ટ કરે છે, જેની પસંદગી named-tunnel કૉન્ફિગ આપવામાં આવ્યું છે કે નહીં તેના આધારે થાય છે:

- **ક્વિક ટનલ (ડિફૉલ્ટ).** `cloudflared tunnel --url
http://localhost:<apiPort>` ચલાવે છે અને stdoutમાંથી ફાળવાયેલ `*.trycloudflare.com` URL
  પાર્સ કરે છે. URL ક્ષણિક હોય છે અને દરેક રીસ્ટાર્ટ વખતે બદલાય છે.
- **નેમ્ડ ટનલ (ઑપ્ટ-ઇન).** જ્યારે `CLOUDFLARED_CONFIG` સ્થાનિક રીતે સંચાલિત
  cloudflared `config.yml` તરફ નિર્દેશ કરે છે, ત્યારે OmniRoute `cloudflared tunnel --no-autoupdate
--config <path> run` ચલાવે છે, જે તમને **સ્થિર, નામવાળું હોસ્ટનેમ** આપે છે. કૉન્ફિગ
  ટનલ UUID, `credentials-file` અને `ingress` રૂટિંગ પૂરું પાડે છે, તેથી કોઈ
  `--url` પાસ કરવામાં આવતું નથી અને કોઈ Zero Trust ડૅશબોર્ડ ટોકનની જરૂર પડતી નથી. `run`,
  કૉન્ફિગના સંપૂર્ણ `credentials-file` પાથમાંથી ક્રેડેન્શિયલ્સ વાંચે છે — `cert.pem`
  જરૂરી નથી (તેનો ઉપયોગ માત્ર ટનલ લાઇફસાઇકલ મેનેજમેન્ટ માટે થાય છે).

મુખ્ય વર્તણૂકો:

- **ઑટો-ઇન્સ્ટોલ.** પ્રથમ ઉપયોગ વખતે OmniRoute અધિકૃત GitHub releasesમાંથી નવીનતમ
  `cloudflared` બાઇનરી ડાઉનલોડ કરે છે (સંચાલિત ઇન્સ્ટોલ
  `DATA_DIR/cloudflared/` હેઠળ રહે છે). એક્ઝિક્યુશન પહેલાં ડાઉનલોડ કરેલી ઍસેટનું SHA256,
  રિલીઝ મેનિફેસ્ટ સામે ચકાસવામાં આવે છે.
- **પ્રોસેસ સુપરવિઝન.** cloudflared PID અને નિર્ધારિત URLને
  `quick-tunnel-state.json`માં સાચવવામાં આવે છે, જેથી ડૅશબોર્ડ રિલોડ પછી પણ સ્થિતિ ફરી મેળવી શકે.

### નેમ્ડ ટનલ સેટઅપ (સ્થિર હોસ્ટનેમ)

1. cloudflared CLI વડે સ્થાનિક રીતે સંચાલિત ટનલ બનાવો (એક વખત):

   ```bash
   cloudflared tunnel login
   cloudflared tunnel create omniroute
   cloudflared tunnel route dns omniroute ai.example.com
   ```

2. તમારા હોસ્ટનેમને OmniRouteના સ્થાનિક API પોર્ટ (ડિફૉલ્ટ 20128) તરફ રૂટ કરતી
   `~/.cloudflared/config.yml` ફાઇલ લખો:

   ```yaml
   tunnel: <UUID-from-create>
   credentials-file: /home/you/.cloudflared/<UUID>.json
   ingress:
     - hostname: ai.example.com
       service: http://127.0.0.1:20128
     - service: http_status:404
   ```

3. OmniRouteને કૉન્ફિગ તરફ નિર્દેશિત કરો અને ટનલને (ફરીથી) શરૂ કરો:

   ```bash
   export CLOUDFLARED_CONFIG="/home/you/.cloudflared/config.yml"
   # વૈકલ્પિક — OmniRoute જે હોસ્ટનેમ દર્શાવે છે તેને ઓવરરાઇડ કરે છે; અન્યથા તે
   # કૉન્ફિગના પ્રથમ ingress નિયમમાંથી વાંચવામાં આવે છે:
   # export CLOUDFLARED_HOSTNAME="ai.example.com"
   ```

   ટનલને ક્વિક ટનલની જેમ જ સક્ષમ કરો (નીચે REST / ડૅશબોર્ડ / CLI).
   નેમ્ડ ટનલ સ્ક્રેપ કરવા માટે કોઈ જાહેર URL ઉત્સર્જિત કરતી નથી, તેથી તૈયારીની સ્થિતિ
   cloudflaredના નોંધાયેલા edge કનેક્શન પરથી શોધવામાં આવે છે અને `publicUrl`/`apiUrl`
   `CLOUDFLARED_HOSTNAME` (અથવા કૉન્ફિગના પ્રથમ ingress હોસ્ટનેમ) પરથી દર્શાવવામાં આવે છે.

### REST દ્વારા સક્ષમ / અક્ષમ કરવું

આ એન્ડપોઇન્ટ અલગ `start`/`stop` પાથને બદલે `{action: "enable" | "disable"}` બૉડીનો
ઉપયોગ કરે છે. મેનેજમેન્ટ ઑથ (ઍડમિન સેશન અથવા ઍડમિન API કી) જરૂરી છે.

```bash
# સક્ષમ કરો
curl -X POST http://localhost:20128/api/tunnels/cloudflared \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"enable"}'

# સ્થિતિ
curl http://localhost:20128/api/tunnels/cloudflared \
  -H "Cookie: auth_token=..."

# અક્ષમ કરો
curl -X POST http://localhost:20128/api/tunnels/cloudflared \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"disable"}'
```

અથવા ડૅશબોર્ડ દ્વારા: **Settings → Tunnels → Cloudflare**.

### વૈકલ્પિક env vars

| વેરિએબલ                                              | હેતુ                                                                                                                                                                        |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CLOUDFLARED_BIN`                                    | બાઇનરી પાથને ઓવરરાઇડ કરે છે. જો તે સેટ અને માન્ય હોય, તો OmniRoute તેને ડાઉનલોડ કરવાને બદલે તેનો ઉપયોગ કરે છે.                                                              |
| `CLOUDFLARED_PROTOCOL` / `TUNNEL_TRANSPORT_PROTOCOL` | ટ્રાન્સપોર્ટ પ્રોટોકોલ (ડિફૉલ્ટ `http2`; તેમજ `quic`, `auto`).                                                                                                              |
| `CLOUDFLARED_CONFIG`                                 | સ્થાનિક રીતે સંચાલિત cloudflared `config.yml` નો પાથ. જ્યારે સેટ કરેલું હોય, ત્યારે OmniRoute ક્વિક ટનલને બદલે **નામિત/કાયમી** ટનલ (`tunnel --config <path> run`) ચલાવે છે. |
| `CLOUDFLARED_HOSTNAME`                               | નામિત ટનલ દ્વારા દર્શાવાતા જાહેર હોસ્ટનામને ઓવરરાઇડ કરે છે (દા.ત. `ai.example.com`). સેટ ન હોય ત્યારે, કૉન્ફિગના પ્રથમ `ingress` હોસ્ટનામમાંથી વાંચે છે.                    |

## 2. ngrok

`src/lib/ngrokTunnel.ts` **`@ngrok/ngrok` SDK**નો ઉપયોગ કરે છે (પ્રક્રિયાની અંદર, કોઈ CLI
ઉપપ્રક્રિયા નહીં). મૂળ મોડ્યુલને પ્રથમ પ્રારંભ વખતે આળસપૂર્વક આયાત કરવામાં આવે છે, જેથી
પૂર્વ-બિલ્ટ બાઇનરી વિનાના પ્લેટફોર્મ પર બૂટ દરમિયાન ઍપ બંધ ન થઈ જાય.

### પૂર્વજરૂરિયાતો

1. <https://ngrok.com> પર સાઇન અપ કરો.
2. ngrok ડૅશબોર્ડમાંથી તમારું authtoken કૉપિ કરો.
3. તેને નીચેનામાંથી કોઈ એક રીતે પ્રદાન કરો:
   - `.env`: `NGROK_AUTHTOKEN=<token>`, અથવા
   - ડૅશબોર્ડ: **Settings → Tunnels → ngrok**, અથવા
   - REST બૉડી (એક વખત માટે): `{"action":"enable","authToken":"<token>"}`.

જો બંનેમાંથી કોઈ પણ ગોઠવેલું ન હોય, તો સ્થિતિ `phase: "needs_auth"` પરત કરે છે.

### REST દ્વારા સક્ષમ / અક્ષમ કરો

```bash
# સક્ષમ કરો (envમાંથી NGROK_AUTHTOKENનો ઉપયોગ કરે છે)
curl -X POST http://localhost:20128/api/tunnels/ngrok \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"enable"}'

# ઇનલાઇન ટોકન સાથે સક્ષમ કરો
curl -X POST http://localhost:20128/api/tunnels/ngrok \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"enable","authToken":"2abc..."}'

# સ્થિતિ
curl http://localhost:20128/api/tunnels/ngrok \
  -H "Cookie: auth_token=..."

# અક્ષમ કરો
curl -X POST http://localhost:20128/api/tunnels/ngrok \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"disable"}'
```

પ્રતિસાદમાં ફાળવેલ `publicUrl` સામેલ હોય છે (દા.ત.
`https://abcd-1234.ngrok-free.app`). કસ્ટમ ડોમેન, પ્રદેશો અને નીતિના નિયમો
ngrok ડૅશબોર્ડમાં ગોઠવવા આવશ્યક છે — OmniRoute પોતે ફક્ત સ્થાનિક લક્ષ્ય URLને
SDK પર ફૉર્વર્ડ કરે છે.

## 3. Tailscale Funnel

`src/lib/tailscaleTunnel.ts`, સ્થાનિક API પોર્ટને **Funnel** (સર્વ કરવા માટે
Tailscaleનું જાહેર-ઇન્ટરનેટ ઇગ્રેસ) મારફતે ઉપલબ્ધ કરાવવા માટે સિસ્ટમના
`tailscale` CLIનું સંચાલન કરે છે. તે સંપૂર્ણ જીવનચક્રને સપોર્ટ કરે છે: ઇન્સ્ટૉલ,
લૉગિન, ડેમન પ્રારંભ, સક્ષમ અને અક્ષમ કરવું.

અમલીકરણ `tailscale funnel --bg <port>` (બૅકગ્રાઉન્ડ મોડ) ચલાવે છે. જાહેર URLનું
સ્વરૂપ `https://<machine>.<tailnet>.ts.net/` હોય છે.

### પૂર્વજરૂરિયાતો

1. Tailscale ઇન્સ્ટૉલ કરો (અથવા OmniRouteને તે કરવા દો — નીચેનું `install` એન્ડપૉઇન્ટ જુઓ).
2. સાઇન ઇન કરો (`tailscale login` અથવા OmniRouteના `login` એન્ડપૉઇન્ટ દ્વારા).
3. Tailscale ઍડમિન કન્સોલમાં તમારા tailnet માટે Funnel સક્ષમ કરો:
   <https://login.tailscale.com/admin/settings/features>.

Linux અને macOS પર ડેમન (`tailscaled`)ને નિયંત્રિત કરવા માટે `sudo` જરૂરી છે.
POST એન્ડપૉઇન્ટ વૈકલ્પિક `sudoPassword` ફીલ્ડ સ્વીકારે છે, જેને કૉલના સમયગાળા
માટે OmniRouteના MITM પાસવર્ડ કૅશ (`getCachedPassword` / `setCachedPassword`)
પર ફૉર્વર્ડ કરવામાં આવે છે. Windows અહીં ડિફૉલ્ટ સર્વિસ ઇન્સ્ટૉલેશનનો ઉપયોગ કરે છે:
`C:\Program Files\Tailscale\tailscale.exe`.

### REST એન્ડપૉઇન્ટ

Tailscaleની સપાટી અન્ય બૅકએન્ડ કરતાં વધુ સમૃદ્ધ છે, કારણ કે ઇન્સ્ટૉલેશન,
લૉગિન, ડેમન અને ટનલ અલગ-અલગ બાબતો છે.

| એન્ડપૉઇન્ટ                            | પદ્ધતિ | હેતુ                                                                            |
| ------------------------------------- | ------ | ------------------------------------------------------------------------------- |
| `/api/tunnels/tailscale`              | `GET`  | એકત્રિત ટનલ સ્થિતિ (`phase`, `tunnelUrl`, `apiUrl`, વગેરે)                      |
| `/api/tunnels/tailscale/check`        | `GET`  | નિમ્ન-સ્તરીય તપાસ: ઇન્સ્ટૉલ થયેલું છે? લૉગ ઇન છે? ડેમન ચાલી રહ્યું છે?          |
| `/api/tunnels/tailscale/install`      | `POST` | Tailscale ઇન્સ્ટૉલ કરો (SSE દ્વારા સ્ટ્રીમ કરેલી પ્રગતિ ઇવેન્ટ્સ) — Linux/macOS |
| `/api/tunnels/tailscale/start-daemon` | `POST` | Linux/macOS પર `tailscaled` શરૂ કરો                                             |
| `/api/tunnels/tailscale/login`        | `POST` | લૉગિન પ્રવાહ શરૂ કરો; બ્રાઉઝરમાં ખોલવા માટે `authUrl` પરત કરે છે                |
| `/api/tunnels/tailscale/enable`       | `POST` | API પોર્ટ માટે Funnel શરૂ કરો                                                   |
| `/api/tunnels/tailscale/disable`      | `POST` | Funnel બંધ કરો                                                                  |

બધા Tailscale એન્ડપૉઇન્ટ માટે વ્યવસ્થાપન પ્રમાણીકરણ આવશ્યક છે
(`routeUtils.ts :: requireTailscaleAuth` જુઓ).

સક્ષમ કરવાનું ઉદાહરણ:

```bash
curl -X POST http://localhost:20128/api/tunnels/tailscale/enable \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"sudoPassword":"<linux-pwd>","port":20128}'
```

જો ઍડમિન કન્સોલમાં Funnel સક્ષમ ન હોય, તો પ્રતિસાદમાં
`funnelNotEnabled: true` તેમજ બ્રાઉઝરમાં ખોલવા માટેનું `enableUrl` સામેલ હોય છે.

### વૈકલ્પિક env vars

| વેરિએબલ         | હેતુ                                 |
| --------------- | ------------------------------------ |
| `TAILSCALE_BIN` | `tailscale` બાઇનરી પાથને ઓવરરાઇડ કરો |

સ્વતંત્ર છે.

## OAuth કૉલબૅક સંબંધિત બાબતો

જ્યારે તમે OmniRouteને ટનલ દ્વારા જાહેર કરો છો, ત્યારે ડૅશબોર્ડ અને OAuth પ્રવાહોએ
કૉલબૅક URLને `localhost` નહીં, પરંતુ **સાર્વજનિક** હોસ્ટનામના આધારે બનાવવા જોઈએ. અન્યથા
OAuth પ્રદાતા વપરાશકર્તાને એવા URL પર પાછા રીડાયરેક્ટ કરે છે જ્યાં તેના સર્વરો પહોંચી શકતા નથી,
અને હેન્ડશેક નિષ્ફળ જાય છે.

ડૅશબોર્ડમાં ફેરફારો અને સેટિંગ્સ સાચવવા માટે ટનલ હોસ્ટનામને
`NEXT_PUBLIC_BASE_URL`માં નિશ્ચિત કરવાની જરૂર નથી. પ્રમાણિત ડૅશબોર્ડ સેશન-બાઉન્ડ
CSRF ટોકન સાથે સમાન-ઑરિજિન અસુરક્ષિત વિનંતીઓ મોકલે છે, તેથી લૉગ ઇન કર્યા પછી
અલ્પજીવી Cloudflare Quick Tunnel હોસ્ટનો સામાન્ય UI વ્યવસ્થાપન માટે હજુ પણ ઉપયોગ કરી શકાય છે.

આ સેટ કરો:

```bash
NEXT_PUBLIC_BASE_URL=https://<your-tunnel-host>
```

અને OAuth શરૂ કરતાં પહેલાં OmniRouteને ફરી શરૂ કરો. અલ્પજીવી Cloudflare Quick
Tunnels માટે દરેક રીસ્ટાર્ટ પછી URL બદલાય છે, તેથી પ્રોડક્શન OAuth ઉપયોગ માટે આરક્ષિત
ડોમેન સાથે ngrok અથવા Tailscale Funnelને પ્રાધાન્ય આપો.

## સ્વાસ્થ્ય અને મોનિટરિંગ

ડૅશબોર્ડ **Settings → Tunnels** હેઠળ ટનલની સ્થિતિ દર્શાવે છે:

- સક્રિય બૅકએન્ડ અને વર્તમાન `phase` (`stopped`, `starting`, `running`,
  `needs_auth`, `error`).
- વર્તમાન સાર્વજનિક URL અને તેમાંથી મેળવેલ API URL (`<publicUrl>/v1`).
- સ્થાનિક લક્ષ્ય URL, જ્યાં ટનલ વિનંતીઓ ફૉર્વર્ડ કરે છે.
- છેલ્લો ભૂલ સંદેશ, જો કોઈ હોય તો.

પ્રોગ્રામેટિક મોનિટરિંગ માટે દરેક બૅકએન્ડના `GET` એન્ડપોઇન્ટને નિયમિત રીતે પોલ કરો. એકસાથે એક કરતાં
વધુ બૅકએન્ડ ચલાવવાની મંજૂરી છે; OmniRoute દરેકને
સ્વતંત્ર રીતે ટ્રૅક કરશે.

## સમસ્યાનિવારણ

### "cloudflared બાઇનરી મળી નથી"

OmniRoute પ્રથમ ઉપયોગ વખતે સ્વયં ઇન્સ્ટૉલ કરવાનો પ્રયાસ કરે છે. જો ઇન્સ્ટૉલ અવરોધિત હોય
(પ્રતિબંધિત નેટવર્ક, GitHub ઍક્સેસ ન હોય), તો
<https://github.com/cloudflare/cloudflared/releases> પરથી `cloudflared` મૅન્યુઅલી ડાઉનલોડ કરો અને
`CLOUDFLARED_BIN=/path/to/cloudflared` સેટ કરો.

### "ngrok: authtoken જરૂરી છે"

`phase: "needs_auth"`નો અર્થ એ છે કે કોઈ authtoken મળ્યું નથી. `.env`માં
`NGROK_AUTHTOKEN` સેટ કરો, તેને ડૅશબોર્ડ દ્વારા કન્ફિગર કરો અથવા enable POST
બોડીમાં `authToken` પાસ કરો.

### "tailscale: funnel સક્ષમ નથી"

જ્યારે enable પ્રતિસાદમાં `funnelNotEnabled: true` સામેલ હોય, ત્યારે તમારા tailnet માટે Funnel
અક્ષમ હોય છે. પરત મળેલ `enableUrl` (અથવા ઍડમિન કન્સોલનું ફીચર
પેજ) ખોલો અને Funnelને ચાલુ કરો.

### ટનલ URLમાં થતા ફેરફારો OAuthને નિષ્ફળ બનાવે છે

આરક્ષિત ડોમેન સાથે ngrok અથવા Tailscale Funnelનો ઉપયોગ કરો (બંને દરેક નોડ માટે સ્થિર છે).
Cloudflare Quick Tunnels મૂળભૂત રચનાથી જ અલ્પજીવી છે અને લાંબા સમય સુધી ચાલતા
OAuth કૉલબૅક માટે ભલામણ કરવામાં આવતી નથી.

### Tailscale માટે Linux/macOS પર પરવાનગી નકારી

`tailscaled`ને rootની જરૂર છે. સંબંધિત POST એન્ડપોઇન્ટને `sudoPassword` આપો,
અથવા ડિમન જાતે ચલાવો (`sudo systemctl start tailscaled`).
