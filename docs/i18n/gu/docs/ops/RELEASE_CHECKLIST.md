## npm Trusted Publishing (v3.8.51થી ડિફૉલ્ટ) — વિનંતી પર તબક્કાવાર, ફૉલબૅક તરીકે સીધું

`npm-publish.yml` ડિફૉલ્ટ રૂપે **npm Trusted Publishing (OIDC)** દ્વારા પ્રકાશિત કરે છે:
`stage-npm` જૉબ (github-hosted) તે રન માટે GitHubના id-tokenને ટૂંકા ગાળાના npm
ક્રેડેન્શિયલ સાથે એક્સચેન્જ કરે છે — રિપોઝિટરી સિક્રેટ્સમાં કોઈ લાંબા ગાળાનો npm ટોકન નહીં, કોઈ 2FA પ્રોમ્પ્ટ નહીં અને provenance જોડાયેલું.
2FAને બાયપાસ કરતા ટોકનો નિવૃત્ત કરવામાં આવી રહ્યા હોવાથી, હવે npm દ્વારા માન્ય આ જ બાયપાસ છે;
તે WS1.3ની ખાતરી જાળવી રાખીને પ્રોજેક્ટમાં v3.8.48 સુધી રહેલો સંપૂર્ણ સ્વચાલિત પ્રવાહ
પુનઃસ્થાપિત કરે છે (લીક થયેલો ટોકન એકલો પ્રકાશિત કરી શકતો નથી — કારણ કે કોઈ ટોકન જ નથી).

**એક વખતનું સેટઅપ (માલિક):** npmjs.com → package `omniroute` → Settings → _Trusted
Publisher_ → GitHub: owner `diegosouzapw`, repo `OmniRoute`, workflow `npm-publish.yml`
(environment: none). આ ઉપલબ્ધ ન થાય ત્યાં સુધી, સ્વચાલિત પગલું `ENEEDAUTH` સાથે નિષ્ફળ જાય છે:
`publish_mode=staged` (નીચે) અથવા `direct` સાથે ફરી dispatch કરો.

### તબક્કાવાર પ્રકાશન (વિનંતી પર — `publish_mode=staged`)

npm-publish વર્કફ્લો હવે સીધું પ્રકાશિત કરતું નથી: તે પૅક કરેલ tarballને
(`check:pack-boot`) બૂટ કરે છે અને પછી `npm stage publish` ચલાવે છે — બરાબર એ જ bytes રજિસ્ટ્રી પર
પાર્ક થાય છે અને માલિક મંજૂરી આપે ત્યાં સુધી **ઇન્સ્ટૉલ કરી શકાતા નથી**. માનવીય 2FA ગેટને
પુરાવાની પહેલાંથી ખસેડીને તેની પછી મૂકવામાં આવ્યો છે.

**વર્કફ્લો ગ્રીન થયા પછી માલિકનો પ્રવાહ:**

1. `npm stage list omniroute` — stage id શોધો (વર્કફ્લો સારાંશમાં પણ દર્શાવાય છે).
2. સ્ટેજ કરેલા bytes ચકાસો (ભલામણ કરેલ): `npm stage download <id>`, ત્યારબાદ ડાઉનલોડ કરેલા
   tarballને અસ્થાયી prefixમાં ઇન્સ્ટૉલ કરીને બૂટ કરો (`npm run check:pack-boot`, CIમાં
   એ જ pack→install→boot ચુકાદાને સ્વચાલિત કરે છે).
3. `npm stage approve <id>` — 2FA પ્રોમ્પ્ટ જ પ્રકાશન છે. `npm stage reject <id>` તેને કાઢી નાખે છે.
4. પ્રકાશન પછીનું સુરક્ષા જાળું: post-publish verifier (v3.8.49 યોજનાનો WS1.4) સ્વચ્છ
   containerમાં જાહેર registryમાંથી પ્રકાશિત વર્ઝન ઇન્સ્ટૉલ કરે છે અને તેને બૂટ કરે છે.

**કટોકટીનો ફૉલબૅક:** `publish_mode=direct` સાથે `workflow_dispatch`, જૂના
તાત્કાલિક `npm publish`ને પુનઃસ્થાપિત કરે છે (ફક્ત stagingમાં જ ખામી સર્જાય તો ઉપયોગ કરો; કારણ નોંધો).

**એક વખતનું હાર્ડનિંગ (માલિક, npmjs.com):** `omniroute` માટે Trusted Publisherને
stage-only મોડમાં કન્ફિગર કરો, જેથી લીક થયેલો લાંબા ગાળાનો ટોકન ક્યાંયથી સીધું `npm publish`
ન કરી શકે — CI માત્ર stage કરી શકે છે; ફક્ત માલિકનું 2FA જ રિલીઝ કરી શકે છે.

**ખામીયુક્ત આર્ટિફૅક્ટ માટેની પ્રક્રિયા (અપરિવર્તિત):** ડિફૉલ્ટ પ્રતિક્રિયા તરીકે
`npm deprecate omniroute@<bad> "<reason> — use <fixed>"` (મિનિટોમાં, પાછું ફેરવી શકાય તેવું);
`npm unpublish`નો ઉપયોગ ફક્ત 72h/no-dependents વિન્ડોની અંદર કરો અને ક્યારેય પ્રથમ પગલા તરીકે નહીં.
Docker: વર્ઝન ટૅગને ક્યારેય ફરી લખશો નહીં — રોલબૅકનો અર્થ `latest`ને છેલ્લે યોગ્ય રહેલા digest તરફ ફરી નિર્દેશિત કરવો છે.

**Docker Hub `latest` (દરેક સ્થિર SemVer પ્રકાશન પર આવશ્યક):**
`docker-publish` વર્કફ્લોએ **બંને** `X.Y.Z`ને અને, જ્યારે
`should-promote-latest.sh` સંમત થાય કે આ સૌથી ઊંચું સ્થિર SemVer છે ત્યારે, `:latest`ને
**સમાન digest** સાથે ટૅગ કરવા આવશ્યક છે. જૉબ પછી: Hubના `latest`નો digest નવા
SemVer digest સમાન હોવો જોઈએ અને `last_updated` આગળ વધેલું હોવું જોઈએ. રિલીઝ નોંધોમાં
ફક્ત git પર ઉપલબ્ધ સુધારાઓની વાત હોય ત્યારે `:latest`ને જૂના build પર છોડશો નહીં.
Compose quickstarts `:latest`નો ઉપયોગ કરે છે; GitOpsએ `X.Y.Z`ને pin કરવાનું ચાલુ રાખવું જોઈએ.
[Docker રિલીઝ ચૅનલ્સ](../guides/DOCKER_GUIDE.md#release-channels) અને #10317 જુઓ.

## હોટફિક્સ ફાસ્ટ-લેન (લેબલ `hotfix`)

`hotfix` લેબલ ધરાવતી PR ભારે CI મેટ્રિક્સ (9-shard E2E, coverage ratchet,
quality-gate, quality-extended)ને છોડી દે છે અને ઝડપી, ઉચ્ચ-સિગ્નલ ગેટ્સ જાળવી રાખે છે: build,
unit shards, integration, vitest, lint/typecheck, docs-sync, `check:pack-artifact`
અને tarball boot-smoke (`check:pack-boot`). લક્ષ્ય: ~33minના બદલે ≤15minમાં ગ્રીન.

**પ્રવેશ નીતિ — ચારેય આવશ્યક (Chromium/VS Code/Nodeની ઇમરજન્સી લેન્સના આધારે):**

1. **ગંભીરતા**: પ્રોડક્શન ખોરવાયેલું છે — પ્રકાશિત આર્ટિફેક્ટ બૂટ વખતે ક્રેશ થાય છે /
   સુરક્ષા સુધારો જરૂરી છે / રિલીઝનો દરેક વપરાશકર્તા પ્રભાવિત છે. "મહત્વપૂર્ણ" એટલે "ખોરવાયેલું" નથી.
2. **સત્તા**: માત્ર રિપોઝિટરીનો માલિક જ `hotfix` લેબલ લાગુ કરે છે. લેબલ પોતે જ
   મંજૂરી છે — કેમ્પેઇન PR પર ક્યારેય સ્વ-સેવા કરવી નહીં.
3. **પુરાવો**: PR બોડી અગાઉના સંપૂર્ણપણે-ગ્રીન ભારે રન (જે સ્યુટને
   છોડવામાં આવેલી જોબ્સ ફરીથી માન્ય કરતી) તેમજ સુધારાના પોતાના પહેલાં-નિષ્ફળ-અને-પછી-સફળ ટેસ્ટને લિંક કરે છે.
4. **વ્યાપ**: માત્ર cherry-pick — ન્યૂનતમ સુધારો, કોઈ refactors નહીં, કોઈ અસંબંધિત ફેરફારો નહીં.

છોડવામાં આવેલ coverage/ratchet સપાટીનું release branch પરના આગામી સંપૂર્ણ રન દ્વારા
ફરીથી માન્યકરણ થાય છે (સતત release-green) — આ લેન માત્ર રાહ જોવાનું છોડે છે, માન્યકરણ ક્યારેય નહીં.
માત્ર ટેસ્ટવાળા diffs (`tests/` હેઠળની બધી ફાઇલો, `tests/e2e/` હેઠળ કોઈ નહીં) કોઈપણ
લેબલ વિના E2E મેટ્રિક્સને આપમેળે છોડી દે છે.

### બિલ્ડ લેઆઉટ

રિપોઝિટરી ત્રણ અલગ output directories નો ઉપયોગ કરે છે — તેમને ક્યારેય ભેળવશો નહીં:

| ડિરેક્ટરી | હેતુ                                                        | ટ્રૅક કરેલી?    |
| --------- | ----------------------------------------------------------- | --------------- |
| `src/`    | ઍપ્લિકેશન સ્રોત (TypeScript / TSX)                          | હા              |
| `.build/` | બિલ્ડની મધ્યવર્તી ફાઇલો — `next build` output (`distDir`)   | ના (gitignored) |
| `dist/`   | વિતરણયોગ્ય npm bundle — `assembleStandalone` દ્વારા સંયોજિત | ના (gitignored) |

> **સંચાલક નોંધ:** રિમોટ VPS image directory હજુ પણ `/usr/lib/node_modules/omniroute/app/` જ રહે છે.
> માત્ર **રિપોઝિટરીની અંદરનું** build output ખસેડાયું છે (`app/` → `dist/`). deploy skills, `dist/`
> ની સામગ્રીને રિમોટ `app/` dir માં rsync કરે છે — VPS path માં કોઈ ફેરફાર જરૂરી નથી.

**એકલ-બિલ્ડ પ્રવાહ:**

```
npm run build:release
  └─ rm -rf .build dist          (સફાઈ)
  └─ next build → .build/next/   (મધ્યવર્તી ફાઇલો)
  └─ assembleStandalone          (standalone + static + public + natives ને dist/ માં કૉપિ કરે છે)
  └─ writes dist/BUILD_SHA       (HEAD sentinel)
```

deploy માટે `npm run build` ચલાવ્યા પછી અલગથી `npm run build:cli` ચલાવશો નહીં — તેના બદલે
`npm run build:release` નો ઉપયોગ કરો, જે એક જ command માં સ્વચ્છ પુનઃબિલ્ડ + sentinel કરે છે.
