## 💰 ~1.62B મફત ટોકન્સ / મહિનો

</div>

> મફત ટિયર્સને જાતે સ્ટૅક કરવું મુશ્કેલ છે — ડઝનેક SDKs, ડઝનેક રેટ મર્યાદાઓ અને તમારી પાસે ખરેખર કેટલું છે તેની કોઈ જાણકારી નહીં. OmniRoute **35 પુનરાવર્તિત પૂલ કીઝમાં 489 મફત-ટિયર એન્ટ્રીઓ**નું કૅટલૉગ બનાવે છે અને **પ્રકાશિત સકારાત્મક માસિક બજેટ ધરાવતા 17 પૂલ્સ ઉપરાંત Groqની પ્રતિ-મોડેલ પાંચ મર્યાદાઓ** પરથી ટોકન હેડલાઇનની ગણતરી કરે છે, જેમાં શેર કરેલા પૂલના આધારે ડુપ્લિકેટ્સ દૂર કરવામાં આવે છે. જે ક્વોટા માત્ર પ્રાદેશિક ઓળખ ચકાસણી પછી જ ઉપલબ્ધ થાય છે (હાલમાં: ModelScope), તેમને અલગથી દર્શાવવામાં આવે છે—પ્રાદેશિક ઓળખ ચકાસણી પાછળ +~6M—અને તેમને હેડલાઇનના કુલમાં ક્યારેય ઉમેરવામાં આવતા નથી. પરિણામ ડૅશબોર્ડ (`/dashboard/free-tiers`) પર દૃશ્યમાન રહે છે.

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="OmniRoute મફત-ટિયર બજેટ કાર્ડ: દર મહિને સ્થિર ~1.62B મફત ટોકન્સ, સાઇનઅપ ક્રેડિટ્સ સાથે પ્રથમ મહિનામાં ~2.22B સુધી, એક જ એન્ડપોઇન્ટ પાછળ કૅટલૉગ કરેલી 489 મફત-ટિયર એન્ટ્રીઓને આવરી લેતી 35 દસ્તાવેજીકૃત પુનરાવર્તિત પૂલ કીઝમાંથી. પ્રમાણિક, પૂલ-ડુપ્લિકેટ દૂર કરેલું ગણિત — દરેક શેર કરેલો પૂલ માત્ર એક વખત ગણાય છે, જેમાં પ્રકાશિત સકારાત્મક માસિક ટોકન બજેટ ધરાવતા 17 પુનરાવર્તિત પૂલ્સ ઉપરાંત Groqની પ્રતિ-મોડેલ પાંચ મર્યાદાઓનો સમાવેશ થાય છે; શરતો-જોખમ કૅટલૉગમાં 13 પ્રદાતાઓને ટાળવા યોગ્ય તરીકે ચિહ્નિત કરવામાં આવ્યા છે, જેથી તમે નિર્ણય લઈ શકો. બજેટ બારમાં Mistral 1B, Nara 210M, LLM7 150M, xKiro 150M, Groq 30M (પ્રતિ-મોડેલ પાંચ મર્યાદાઓ) અને નાના પૂલ્સનો સમાવેશ થાય છે; સાથે જ પ્રથમ મહિનાના સાઇનઅપ ક્રેડિટ્સ અને કાયમી મફત, ટોકન-મર્યાદા વિનાના પ્રદાતાઓને અલગથી દર્શાવવામાં આવે છે જેથી તેઓ હેડલાઇનના આંકડાને ક્યારેય કૃત્રિમ રીતે વધારતા નથી. `/dashboard/free-tiers` પર લાઇવ વપરાયેલ/બાકી."/>

> લાઇવ `/dashboard/free-tiers` પેજનો ઍનિમેટેડ સારાંશ. સંપૂર્ણ કાર્યપદ્ધતિ (પૂલ ડુપ્લિકેશન દૂર કરવું, ક્રેડિટ ટિયર્સ, પ્રદાતાની શરતો): **[docs/reference/FREE_TIERS.md](docs/reference/FREE_TIERS.md)**.
>
> <sub>આ આંકડાઓનું લાઇવ કૅટલૉગ સામે દર બે અઠવાડિયે ફરી ઑડિટ કરવામાં આવે છે અને તે **બંને દિશામાં બદલાય છે** — કોઈ પ્રદાતા મફત ટિયર બંધ કરે તો આંકડો ઘટે છે; નવો પ્રદાતા ઉમેરાય તો તે વધે છે. અમે કૅટલૉગ ખરેખર જે ગણતરી કરે છે તે જ પ્રકાશિત કરીએ છીએ, ક્યારેય ઉપર તરફ ગોળ કરેલો શ્રેષ્ઠ સંભવિત આંકડો નહીં.</sub>

## 🆓 ઇન્સ્ટોલ કરતાં જ કામ કરે છે — કોઈ કી નહીં, કોઈ કૉન્ફિગ નહીં

</div>

<img src="./docs/diagrams/works-zero-config.svg" width="100%" alt="ઇન્સ્ટોલ કરતાં જ કામ કરે છે — શૂન્ય કૉન્ફિગ. ત્રણ પગલાં: 1. ઇન્સ્ટોલ કરો — npm i -g omniroute, સર્વર localhost:20128 પર શરૂ થાય છે. 2. તમારા ટૂલને http://localhost:20128/v1 તરફ નિર્દેશિત કરો — કોઈપણ OpenAI-સુસંગત ટૂલ (Claude Code, Cursor, Cline). 3. તે જવાબ આપે છે — કોઈ API કી, સાઇનઅપ અથવા કૉન્ફિગરેશન વિના તાત્કાલિક જવાબ માટે model auto ને કૉલ કરો. કી-વિહોણું પ્રોવાઇડર OpenCode Free auto કૉમ્બોમાં પહેલેથી જ જોડાયેલું છે, તેથી નવું ઇન્સ્ટોલેશન તરત જ પ્રતિસાદ આપે છે."/>

```bash
# નવું ઇન્સ્ટોલેશન, શૂન્ય ઓળખપત્રો — `auto` પહેલેથી જ કામ કરે છે:
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

<sub>કોઈ ચોક્કસ મફત બૅકએન્ડ પસંદ છે? સીધું `oc/…` (OpenCode Free) કૉલ કરો. પછી `auto` પર જાઓ અને OmniRoute ને પસંદ કરવા દો.</sub>

<sub>📦 **Python, Node.js, PHP અને cURL** માટે કૉપી-પેસ્ટ ક્વિકસ્ટાર્ટ સ્ક્રિપ્ટ્સ → [`examples/quickstart/`](examples/quickstart/)</sub>

<img src="./docs/diagrams/why-pain-fix.svg" width="100%" alt="OmniRoute શા માટે — 10 ડૅશબોર્ડ્સ, નિષ્ક્રિય API કીઓ અને અણધાર્યા બિલ્સ વચ્ચે ઝઝૂમવાનું બંધ કરો. રોજની દસ સમસ્યાઓ સામે ઉકેલો: વપરાયા વિના સમાપ્ત થતો ક્વોટા → સબ્સ્ક્રિપ્શન્સનો મહત્તમ ઉપયોગ; કોડિંગની વચ્ચે રેટ લિમિટ્સ → 4-ટિયર ઑટો-ફૉલબૅક (સબ્સ્ક્રિપ્શન → API → સસ્તું → મફત); ટૂલ આઉટપુટ્સ દ્વારા ટોકન્સનો બગાડ → RTK + Caveman કમ્પ્રેશન (15–95%); ખર્ચાળ APIs → ખર્ચ-ઑપ્ટિમાઇઝ્ડ રૂટિંગ; દરેક ટૂલ માટે અલગ સેટઅપ → એક એન્ડપૉઇન્ટ, એક ડૅશબોર્ડ; AI બ્લૉક થયેલું → 3-સ્તરીય પ્રૉક્સી + TLS સ્ટેલ્થ; નિષ્ક્રિય કીઓ → 3-સ્તરીય સ્થિતિસ્થાપકતા (સર્કિટ બ્રેકર્સ, કી કૂલડાઉન, મૉડલ લૉકઆઉટ); એક સબ્સ્ક્રિપ્શન શેર કરતી ટીમ → યોગ્ય-હિસ્સાના ક્વોટા સાથે કી પૂલ્સ; કોઈ બીજાના ક્લાઉડમાંથી પસાર થતા પ્રૉમ્પ્ટ્સ → AES-256-GCM એન્ક્રિપ્ટેડ કીઓ સાથે લોકલ-ફર્સ્ટ; ખર્ચની કોઈ દૃશ્યતા નહીં → લાઇવ ઍનલિટિક્સ (ઉપયોગ, ક્વોટા, બચત, p95 લેટન્સી)."/>

### 🧱 સ્થિતિસ્થાપકતા અંદરથી જ નિર્મિત છે (3 સ્વતંત્ર સ્તરો)

<img src="./docs/diagrams/resilience-layers.svg" width="100%" alt="OmniRoute સ્થિતિસ્થાપકતા — 3 સ્વતંત્ર સ્વ-પુનઃપ્રાપ્તિ સ્તરો, યોગ્ય નિષ્ફળતા માટે યોગ્ય સ્તર. સ્તર 1 પ્રદાતા સર્કિટ બ્રેકર (સમગ્ર પ્રદાતા): માત્ર 408/5xx પર ટ્રિપ થાય છે, થ્રેશોલ્ડ OAuth 8× / API-key 12× / local 2×, HALF-OPEN પ્રોબમાં 60s/30s/15s પછી રીસેટ થાય છે, આળસુ પુનઃપ્રાપ્તિ; OPEN હોય ત્યારે કોમ્બો આગામી પ્રદાતા તરફ પુનઃમાર્ગનિર્ધારણ કરે છે. સ્તર 2 કનેક્શન કૂલડાઉન (એક કી/એકાઉન્ટ): મૂળ 5s OAuth / 3s API-key, એન્ટિ-થન્ડરિંગ-હર્ડ ગાર્ડ સાથે ઘાતાંકીય ×2 બૅકઑફ, 429 Retry-Afterનું પાલન કરે છે, સફળતા તમામ ભૂલ સ્થિતિ સાફ કરે છે; કૂલડાઉનમાં રહેલી એક કી અવગણવામાં આવે છે જ્યારે સમકક્ષ કીઓ સેવા આપતી રહે છે. સ્તર 3 મોડેલ લૉકઆઉટ (એક મોડેલ): પ્રતિ-મોડેલ 429, local 404 અથવા મોડ નકારણીઓ ફક્ત તે મોડેલને લૉક કરે છે — સમગ્ર કનેક્શનને ક્યારેય નહીં. અંતિમ સ્થિતિઓ (પ્રતિબંધિત, સમયસમાપ્ત, ક્રેડિટ સમાપ્ત) ઑપરેટર માટે છે, કૂલડાઉન માટે નહીં."/>

## 📡 OmniRoute Radar

ઉપર દસ્તાવેજીકૃત, પૂલ-ડિડુપ્લિકેટેડ કેટલોગમાંથી મુખ્ય ફ્રી-ટિયર હેડલાઇન હજી પણ **~1.62B ટોકન્સ/મહિનો** છે. અસ્થાયી પ્રદાતા સાઇનઅપ ક્રેડિટ્સ અલગથી પ્રથમ મહિનાને **~2.22B** સુધી વધારી શકે છે. Radar એ એવા લોકો માટે વૈકલ્પિક, સહી કરેલું કેટલોગ ઓવરલે છે, જેઓ OmniRoute રિલીઝની વચ્ચે ફ્રી-મોડલની વધુ તાજી ઉપલબ્ધતા ઇચ્છે છે; સમુદાય કેટલોગ અને હાલની દરેક મફત સુવિધા મફત જ રહે છે.

સમર્થકો લાઇવ કેટલોગ અને વધારાની પ્રદાતા તકો મેળવી શકે છે. તેની અલગ, પરિવર્તનશીલ મહત્તમ મર્યાદા પ્રદાતાની ઉપલબ્ધતા પર આધાર રાખીને **વધુમાં વધુ આશરે 3B ટોકન્સ/મહિનો** છે. આ મર્યાદા કોઈ ખાતરી નથી: પ્રદાતાઓ કોઈપણ સમયે ક્વોટા, પાત્રતા, મોડલ્સ અથવા પ્રદેશો બદલી શકે છે.

Radar પસંદગી-આધારિત અને માત્ર GET છે. OmniRoute ક્લાયન્ટ પ્રોમ્પ્ટ્સ, ટ્રાફિક, પ્રદાતા કન્ફિગરેશન, ઉપયોગ ટેલિમેટ્રી અથવા સ્થાનિક જાહેરાત-બરતરફીની સ્થિતિ અપલોડ કરતું નથી. પાત્રતા અને વર્તમાન કેટલોગ વિશે **[radar.omniroute.online/planos](https://radar.omniroute.online/planos)** પર જાણો.

```bash
omniroute run claude   --model openai/gpt-5.4          # Claude Code
omniroute run codex    --model glm/glm-5.2             # OpenAI Codex CLI
omniroute run aider    --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose    --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"
omniroute run qwen     --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini   --model glm/glm-5.2 -- --skip-trust -p "reply OK"

# અથવા ઇન્ટરેક્ટિવ રીતે provider+model પસંદ કરો અને ટૂલનું પોતાનું config લખો:
omniroute configure codex          # આ પણ: claude opencode qwen aider goose gemini cline continue kilo
```

દરેક કમાન્ડ સક્રિય remote context (`omniroute connect <host>`) ને અનુસરે છે, `--dry-run`
ચલાવ્યા વિના ચોક્કસ env/args નું પૂર્વાવલોકન કરે છે, અને `--api-key-env NAME` secrets ને

## 🔌 સંપૂર્ણ CLI + A2A અને MCP

> સર્વર ઉપરાંત, OmniRoute એ **80+ કમાન્ડ્સ** ધરાવતું **સંપૂર્ણ કમાન્ડ-લાઇન કૉકપિટ** છે, સાથે ખુલ્લા એજન્ટ પ્રોટોકોલ્સ પણ છે જેથી AI એજન્ટ તેને **સ્વયં** સંચાલિત કરી શકે.

### ⌨️ વાસ્તવિક CLI (માત્ર `start` નહીં)

```bash
omniroute               # ગેટવે + ડેશબોર્ડ સર્વ કરો (પોર્ટ 20128)
omniroute chat          # ઇન્ટરેક્ટિવ TUI ચેટ ક્લાયન્ટ (સ્લેશ: /model /combo /skill /memory)
omniroute setup         # માર્ગદર્શિત પ્રથમ-ઉપયોગ વિઝાર્ડ
omniroute doctor        # પ્રદાતાઓ, પોર્ટ્સ અને નેટિવ ડિપેન્ડન્સીઝનું નિદાન કરો
```

### 🛰️ રિમોટ મોડ — CLI અહીં ચલાવો, OmniRoute VPS પર

સર્વર પર OmniRoute છે? **એ જ CLI** વડે તેને તમારા લેપટોપ પરથી સંચાલિત કરો. સ્કોપ કરેલા ઍક્સેસ ટોકન વડે એક વાર લૉગ ઇન કરો;
ત્યારબાદ દરેક કમાન્ડ રિમોટને લક્ષ્ય બનાવશે.

```bash
omniroute connect 192.168.0.15            # પાસવર્ડ → સ્કોપ કરેલું ટોકન, કોન્ટેક્સ્ટ તરીકે સાચવાય છે
omniroute models list                     # ← રિમોટ સર્વર સામે ચાલે છે
omniroute configure codex                 # ← રિમોટ મોડેલ પસંદ કરે છે, સ્થાનિક Codex પ્રોફાઇલ લખે છે
omniroute tokens create --name ci --scope read   # અન્ય મશીનો માટે વધુ મર્યાદિત ટોકન્સ બનાવો
omniroute contexts use default            # ← ફરી સ્થાનિક સર્વર પર સ્વિચ કરો
```

ટોકન્સ `read` / `write` / `admin` સુધી સ્કોપ કરેલા હોય છે; પ્રોસેસ શરૂ કરતા રૂટ્સ માત્ર લૂપબૅક પૂરતા મર્યાદિત રહે છે.

### 📖 તે કેવી રીતે કાર્ય કરે છે — પાઇપલાઇન, આર્કિટેક્ચર અને બચતનું ગણિત

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute કમ્પ્રેશન પાઇપલાઇન: 10,000-ટોકનની એક દૃષ્ટાંતરૂપ ક્લાયન્ટ વિનંતી 12 સંયોજ્ય એન્જિનો — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra અને OmniGlyph —માંથી પસાર થાય છે અને દસ્તાવેજિત સ્ટૅક્ડ ઉદાહરણમાં આશરે 1,080 ટોકન્સ સાથે પ્રદાતા સુધી પહોંચી શકે છે. સંરચિત સામગ્રીને પ્રિઝર્વેશન ગાર્ડ્સ અને દરેક પગલાના ફિડેલિટી ગેટ્સ દ્વારા સુરક્ષિત કરવામાં આવે છે; સ્પષ્ટ લૉસી અથવા પ્રાયોગિક મોડ્સ પાત્ર સામગ્રીને રૂપાંતરિત કરી શકે છે."/>

ડિફૉલ્ટ સ્ટૅક્ડ કોમ્બો `RTK → Caveman` ચલાવે છે. જ્યારે બંને સમાન ટૂલ/કન્ટેક્સ્ટ પેલોડ પર લાગુ થાય છે, ત્યારે બચત ચક્રવૃદ્ધિ થાય છે:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

કોડ બ્લૉક્સ, URLs, JSON અને સંરચિત ડેટા પ્રિઝર્વેશન એન્જિન દ્વારા **હંમેશાં સુરક્ષિત** રહે છે.

> **જ્યારે થોડા ટોકન્સથી કામ થઈ જાય ત્યારે ઘણા ટોકન્સ શા માટે વાપરવા?** દરેક વિનંતી OmniRouteની કમ્પ્રેશન પાઇપલાઇનમાંથી **પારદર્શક રીતે** પસાર થાય છે — ક્લાયન્ટમાં કોઈ ફેરફાર જરૂરી નથી. હવે તે **12 સંયોજ્ય એન્જિનોનો સ્ટૅક** છે, જે ક્રમમાં ચાલે છે અને દરેક રાઉટિંગ કોમ્બો અનુસાર મિશ્રિત તથા મેળ ખાતા થાય છે — અને તે [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K+), [LLMLingua-2](https://github.com/microsoft/LLMLingua), અને [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR)ના વિચારો પર આધારિત છે.

### 🎚️ એન્જિનો ઉપરાંત — આઉટપુટ શૈલીઓ, અનુકૂલનશીલ ડાયલ અને પ્રતિ-વિનંતી નિયંત્રણ

ઉપરના 12 એન્જિન અંદર જતી સામગ્રીને સંકોચે છે. અન્ય ત્રણ સ્તરો **કેવી રીતે**, **ક્યારે**, અને બહાર **શું** આવે છે તેને આકાર આપે છે:

- **🪄 આઉટપુટ શૈલીઓ** _(આઉટપુટ-અક્ષ નિયંત્રણ)_ — નિર્ધારિત અને cache-safe પ્રતિભાવ-આકાર સૂચનાઓ ઉમેરે છે; એકસાથે વાપરી શકાય છે અને દરેક માટે `lite` / `full` / `ultra` તીવ્રતા ઉપલબ્ધ છે. શૈલી ઉમેરવા માટે registry માં માત્ર એક લાઇનની એન્ટ્રી જોઈએ:
  - **સંક્ષિપ્ત ગદ્ય** — બિનજરૂરી શબ્દો / articles / સંકોચ દર્શાવતા શબ્દો દૂર કરો; ટેક્નિકલ સાર ચોક્કસ રાખો.
  - **ઓછો કોડ** — "આળસુ સિનિયર dev" YAGNI: સૌથી નાનો કાર્યરત ફેરફાર, માગ્યા વગરનું scaffolding નહીં.
  - **Ponytail (આળસુ સિનિયર dev)** — YAGNI સીડી ચડો, મૂળ કારણ સુધારો, સૌથી નાનો કાર્યરત diff.
  - **મને ADHD છે (ક્રિયા-પ્રથમ)** — આગળની ક્રિયા પહેલાં આવે, પગલાં ક્રમાંકિત હોય, એક ચોક્કસ આગલું પગલું હોય, કોઈ પ્રસ્તાવના નહીં.
  - **સંક્ષિપ્ત CJK (文言)** — શાસ્ત્રીય-ચાઇનીઝ અતિ-સંક્ષિપ્ત શૈલી (`zh` locale સુધી મર્યાદિત).
- **🎯 અનુકૂલનશીલ context-budget** _(ડાયલ)_ — એક on/off token threshold ને બદલે, મોડલની context window માં **ફિટ થવા** માટે જરૂરી હોય એટલી જ હદ સુધી સૌથી સસ્તા અને સૌથી ઓછા નુકસાનકારક એન્જિનોને ક્રમશઃ સક્રિય કરો. નીતિ: `reserve-output` (ડિફૉલ્ટ, મોડલ-જાગૃત) · `percentage` · `absolute`. મોડ: `floor` (ફિટ થવાની ખાતરી) · `replace-autotrigger` (તમારી સ્પષ્ટ પસંદગી પ્રબળ રહે) · `off` (જૂનું threshold).
- **🎛️ સંકોચન ક્યાં નક્કી થાય છે** _(અગ્રતા, ઊંચી → નીચી)_ — પ્રતિ-વિનંતી `x-omniroute-compression` header › routing-combo override › સક્રિય નામિત profile › adaptive / auto-trigger › panel default › off. લાગુ કરાયેલ plan પ્રતિભાવના `X-OmniRoute-Compression: <mode>; source=<source>` header માં પાછો દર્શાવવામાં આવે છે.

token threshold દ્વારા auto-trigger કરો, adaptive dial ચાલુ કરો, નામિત profile pin કરો, દરેક વિનંતી માટે એક વખતનું સેટિંગ નક્કી કરો અથવા દરેક routing combo ને pipeline સોંપો — workload ને જે અનુકૂળ આવે તે પસંદ કરો. opt-in offline **eval harness** (`npm run eval:compression`) ફેરફાર અમલમાં મૂકતા પહેલાં નિશ્ચિત corpus પર fidelity અને બચતનું મૂલ્યાંકન કરે છે.

## 📦 વધુ ઇન્સ્ટોલેશન પદ્ધતિઓ — Docker, સોર્સ, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

`:latest` સૌથી ઊંચા **પ્રકાશિત** સ્થિર SemVerને અનુસરે છે. તે git `main`ને ટ્રૅક કરતું નથી. GitOps માટે `:X.Y.Z` પિન કરો. [Docker રિલીઝ ચૅનલ્સ](docs/guides/DOCKER_GUIDE.md#release-channels) જુઓ. ઇમેજમાં **`OMNIROUTE_MEMORY_MB=1024`** પિન કરેલું છે. ડૅશબોર્ડ અને હળવી ચૅટ માટે તે પૂરતું છે. **કોડિંગ એજન્ટ્સ** (Claude Code, Codex, Grok, … તરફથી `POST /v1/responses`)ને ઘણું મોટું V8 heap જરૂરી છે, નહીં તો બે ઓવરલૅપ થતા લાંબા કૉન્ટેક્સ્ટ હેઠળ પ્રક્રિયા આશરે 12 GiB પર `FATAL ERROR` સાથે નિષ્ફળ થાય છે. કન્ટેનરનું કદ heap કરતાં વધારે રાખો (નેટિવ બફર્સ V8ની બહાર રહે છે):

| વર્કલોડ                          | Heap (`-e OMNIROUTE_MEMORY_MB`) | કન્ટેનર (`--memory`) |
| -------------------------------- | ------------------------------- | -------------------- |
| ડૅશબોર્ડ / હળવી ચૅટ              | `1024` (ઇમેજ ડિફૉલ્ટ)           | ≥2 g                 |
| એક કોડિંગ એજન્ટ                  | `8192`                          | ≥10 g                |
| બે સમકાલીન લાંબા `/v1/responses` | `10240`–`12288`                 | ≥12–16 g             |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

સંપૂર્ણ કોષ્ટક: [Docker માર્ગદર્શિકા — રનટાઇમ RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

**🥟 Bun**

Bun રનટાઇમ ડિટેક્શન દ્વારા પ્રમાણભૂત `bun install` અને ગ્લોબલ ઇન્સ્ટોલેશન (`bun install -g omniroute`) સમર્થિત છે:

- **બિલ્ટ-ઇન `bun:sqlite`**: Bun હેઠળ ચાલતી વખતે OmniRoute, Bunના બિલ્ટ-ઇન `bun:sqlite` ડ્રાઇવરનો ઉપયોગ કરે છે અને Node.js પર `better-sqlite3` અથવા `sql.js` પર ફૉલબૅક કરે છે.
- **ડેવમાં આપમેળે Webpack બંડલર પસંદગી**: ડેવલપમેન્ટ (`bun run dev`) આપમેળે Bunને શોધે છે અને નેટિવ V8 બાઇન્ડિંગ અસંગતતાઓ અટકાવવા માટે Turbopackને અક્ષમ કરીને Webpackનો ઉપયોગ કરે છે. પ્રોડક્શન બિલ્ડ્સ (`bun run build`) Node પરની જેમ જ `OMNIROUTE_USE_TURBOPACK`ને ચોક્કસપણે અનુસરે છે: ડિફૉલ્ટ રૂપે Turbopack, Webpack સાથે બિલ્ડ કરવા માટે `OMNIROUTE_USE_TURBOPACK=0` (`Dockerfile.bun` તેને `--build-arg` તરીકે ઉપલબ્ધ કરે છે).
- **સમર્પિત Bun Dockerfile**: નેટિવ Bun પ્રોડક્શન ડિપ્લોયમેન્ટ્સ માટે મલ્ટિ-સ્ટેજ `Dockerfile.bun` (`docker build -f Dockerfile.bun -t omniroute:bun .`).

📖 [Podman માર્ગદર્શિકા](contrib/podman/README.md) — Compose બિલ્ડ્સ, Podman Machine અને
Linux/systemd Quadlet સેટઅપ.

**⚡ વધુ ઝડપી / હળવું ઇન્સ્ટોલેશન (નેટિવ બિલ્ડ છોડો)**

નેટિવ SQLite એન્જિન (`better-sqlite3`) એક **વૈકલ્પિક** ડિપેન્ડન્સી છે, તેથી ગ્લોબલ
ઇન્સ્ટોલેશન સોર્સમાંથી કમ્પાઇલ થવાની રાહમાં ક્યારેય અટકતું નથી: તમારા પ્લેટફોર્મ/Node માટે
મેળ ખાતી પ્રીબિલ્ટ બાઇનરી હોય ત્યારે તેનો ઉપયોગ કરે છે અને અન્યથા પારદર્શક રીતે શુદ્ધ-JS
એન્જિન પર ફૉલબૅક કરે છે (Node 22+ પર `node:sqlite`, અન્યથા બંડલ કરેલું `sql.js` WASM) — કોઈ બિલ્ડ ટૂલ્સ જરૂરી નથી.

ઇન્સ્ટોલેશન પછીનું નેટિવ વૉર્મ-અપ સંપૂર્ણપણે છોડવા માટે (CI, હેડલેસ અથવા ધીમા મશીનો):

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 પણ તેને છોડે છે
```

સૌથી ઝડપી ઇન્સ્ટોલેશન માટે **pnpm**ને પ્રાધાન્ય આપો (કન્ટેન્ટ-એડ્રેસ્ડ સ્ટોર + હાર્ડ લિંક્સ — ઉપર જુઓ).
ડૅશબોર્ડ-વિહીન, હેડલેસ રનટાઇમ માટે Docker `base` પ્રોફાઇલ (ઉપર) અથવા
[Termux માર્ગદર્શિકા](docs/guides/TERMUX_GUIDE.md)નો ઉપયોગ કરો. CLI અને વેબ ડૅશબોર્ડ એક જ પોર્ટ પર
સમાન પ્રક્રિયા દ્વારા સર્વ થાય છે, તેથી હાલમાં કોઈ અલગ CLI-માત્ર પૅકેજ નથી.
