## LTS ਸਮਰਥਨ ਮਿਆਦ (v3.9.x)

3.8.59 ਤੋਂ ਬਾਅਦ ਅਗਲਾ ਵਰਜਨ **3.9.0** ਹੈ, ਜੋ `stable/v3` ਬ੍ਰਾਂਚ ਉੱਤੇ ਲੰਬੇ ਸਮੇਂ ਦੇ ਸਮਰਥਨ ਦੀ ਲਾਈਨ ਖੋਲ੍ਹਦਾ ਹੈ (ਵੇਖੋ [`ROADMAP.md`](ROADMAP.md) → "ਪੜਾਅ 3 — v3.9.0 LTS")।

- **`stable/v3` ਨੂੰ ਕੀ ਮਿਲਦਾ ਹੈ:** ਬੱਗ ਸੁਧਾਰ, ਸੁਰੱਖਿਆ ਪੈਚ ਅਤੇ ਪ੍ਰਦਾਤਾ ਅੱਪਡੇਟ। ਨਵੀਆਂ ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ v4 ਚੈਨਲ ਵਿੱਚ ਜਾਂਦੀਆਂ ਹਨ; LTS ਲਾਈਨ ਸਥਿਰਤਾ ਨੂੰ ਪਹਿਲ ਦਿੰਦੀ ਹੈ। ਪੂਰੇ v4 ਚੱਕਰ ਦੌਰਾਨ `npm install omniroute` (`latest` dist-tag) v3 ਉੱਤੇ ਹੀ ਰਹਿੰਦਾ ਹੈ।
- **ਮਿਆਦ ਦੀ ਲੰਬਾਈ:** `<T-GAP-3: ਮਾਲਕ ਦਾ ਫ਼ੈਸਲਾ ਬਕਾਇਆ — ROADMAP.md ਵੇਖੋ>`। v4.0 GA ਤੋਂ ਬਾਅਦ (`latest` ਦੇ v4 ਉੱਤੇ ਜਾਣ ਸਮੇਂ) ਮਿਆਦ ਦੀ ਲੰਬਾਈ ਬਾਰੇ **ਹਾਲੇ ਫ਼ੈਸਲਾ ਨਹੀਂ ਹੋਇਆ**; ਜਦੋਂ ਸੰਭਾਲਕ ਇਸਦਾ ਐਲਾਨ ਕਰੇਗਾ, ਤਾਂ ਇਸ ਭਾਗ ਨੂੰ ਅੱਪਡੇਟ ਕੀਤਾ ਜਾਵੇਗਾ। ਉਦੋਂ ਤੱਕ ਕਿਸੇ ਸਮਾਪਤੀ ਮਿਤੀ ਦਾ ਅਨੁਮਾਨ ਨਾ ਲਗਾਓ।
- **LTS ਲਾਈਨ ਵਿੱਚ ਕਮਜ਼ੋਰੀ ਦੀ ਰਿਪੋਰਟ ਕਰਨਾ:** ਕਿਸੇ ਵੀ ਹੋਰ ਵਰਜਨ ਵਾਂਗ ਉਹੀ ਚੈਨਲ — ਇੱਕ ਨਿੱਜੀ [GitHub Security Advisory](https://github.com/diegosouzapw/OmniRoute/security/advisories/new), ਕਦੇ ਵੀ ਜਨਤਕ issue ਨਹੀਂ। ਦੱਸੋ ਕਿ ਤੁਸੀਂ ਕਿਹੜੇ ਵਰਜਨ ਦੀ ਜਾਂਚ ਕੀਤੀ ਸੀ (ਉਦਾਹਰਨ ਲਈ `3.9.2`); ਸੁਧਾਰ `stable/v3` ਵਿੱਚ ਸ਼ਾਮਲ ਹੁੰਦੇ ਹਨ ਅਤੇ v4 ਵਿੱਚ forward-port ਕੀਤੇ ਜਾਂਦੇ ਹਨ।
- **LTS ਨਿਰਧਾਰਨ ਵੇਲੇ ਸੁਰੱਖਿਆ ਬੇਸਲਾਈਨ:** ਮਾਪੀ ਗਈ ਸਕੈਨਰ ਸਥਿਤੀ, route-guard ਅਤੇ ਜਨਤਕ credential ਦੇ ਸਬੂਤ [`docs/security/LTS_SECURITY_BASELINE.md`](docs/security/LTS_SECURITY_BASELINE.md) ਵਿੱਚ ਦਰਜ ਹਨ।

## ਸੁਰੱਖਿਆ ਆਰਕੀਟੈਕਚਰ

OmniRoute ਇੱਕ ਬਹੁ-ਪਰਤੀ ਸੁਰੱਖਿਆ ਮਾਡਲ ਲਾਗੂ ਕਰਦਾ ਹੈ:

```
ਬੇਨਤੀ → CORS → Authz ਪਾਈਪਲਾਈਨ (ਵਰਗੀਕਰਨ → ਨੀਤੀਆਂ → ਲਾਗੂ ਕਰਨਾ)
       → ਸੁਰੱਖਿਆ ਰੋਕਾਂ (PII ਮਾਸਕਰ, ਪ੍ਰੌਂਪਟ ਇੰਜੈਕਸ਼ਨ, ਵਿਜ਼ਨ ਬ੍ਰਿਜ)
       → ਦਰ ਸੀਮਾਕਾਰ → ਸਰਕਿਟ ਬ੍ਰੇਕਰ → ਠੰਢਾ-ਅੰਤਰਾਲ → ਮਾਡਲ ਲਾਕਆਉਟ → ਪ੍ਰਦਾਤਾ
```

### 🛡️ ਸਟੋਰੇਜ ਵਿੱਚ ਇਨਕ੍ਰਿਪਸ਼ਨ

SQLite ਵਿੱਚ ਸਟੋਰ ਕੀਤਾ ਸਾਰਾ ਸੰਵੇਦਨਸ਼ੀਲ ਡੇਟਾ scrypt ਕੁੰਜੀ ਉਤਪੱਤੀ ਨਾਲ **AES-256-GCM** ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਇਨਕ੍ਰਿਪਟ ਕੀਤਾ ਜਾਂਦਾ ਹੈ:

- API keys, access tokens, refresh tokens, ਅਤੇ ID tokens
- ਵਰਜਨ ਵਾਲਾ ਫਾਰਮੈਟ: `enc:v1:<iv>:<ciphertext>:<authTag>`
- ਜਦੋਂ `STORAGE_ENCRYPTION_KEY` ਸੈੱਟ ਨਾ ਹੋਵੇ ਤਾਂ passthrough ਮੋਡ (ਪਲੇਨਟੈਕਸਟ)

```bash
# ਇਨਕ੍ਰਿਪਸ਼ਨ ਕੁੰਜੀ ਤਿਆਰ ਕਰੋ:
STORAGE_ENCRYPTION_KEY=$(openssl rand -hex 32)
```

### 🛡️ ਸੁਰੱਖਿਆ ਰੋਕਾਂ ਦਾ ਫਰੇਮਵਰਕ

OmniRoute ਤਰਜੀਹ ਅਨੁਸਾਰ ਕ੍ਰਮਬੱਧ 3 ਅੰਦਰੂਨੀ ਸੁਰੱਖਿਆ ਰੋਕਾਂ ਵਾਲੀ, ਤੁਰੰਤ ਮੁੜ ਲੋਡ ਹੋ ਸਕਣ ਵਾਲੀ **ਸੁਰੱਖਿਆ ਰੋਕਾਂ ਦੀ ਰਜਿਸਟਰੀ** (`src/lib/guardrails/`) ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ:

| ਸੁਰੱਖਿਆ ਰੋਕ        | ਤਰਜੀਹ | ਉਦੇਸ਼                                                                                     |
| ------------------ | ----- | ----------------------------------------------------------------------------------------- |
| `vision-bridge`    | 5     | ਬਿਨਾਂ ਵਿਜ਼ਨ ਵਾਲੇ ਮਾਡਲਾਂ ਨੂੰ ਚਿੱਤਰ-ਜਾਗਰੂਕ ਵੇਰਵਿਆਂ ਨਾਲ ਜੋੜਦਾ ਹੈ; ਚਿੱਤਰ URLs ਲਈ SSRF ਸੁਰੱਖਿਆ |
| `pii-masker`       | 10    | ਕਾਲ ਤੋਂ ਪਹਿਲਾਂ+ਬਾਅਦ PII ਲੁਕਾਉਣਾ (ਈਮੇਲ, ਫ਼ੋਨ, CPF, CNPJ, ਕ੍ਰੈਡਿਟ ਕਾਰਡ, SSN)                |
| `prompt-injection` | 20    | override/role-hijack/jailbreak/leak ਪੈਟਰਨਾਂ ਦੀ ਪਛਾਣ ਕਰਦਾ ਹੈ                               |

ਕਸਟਮ ਸੁਰੱਖਿਆ ਰੋਕਾਂ `registerGuardrail(new MyGuardrail())` ਰਾਹੀਂ ਰਜਿਸਟਰ ਹੁੰਦੀਆਂ ਹਨ। ਮਾਡਲ fail-open ਹੈ (ਅਪਵਾਦ ਕਦੇ ਵੀ ਟ੍ਰੈਫ਼ਿਕ ਨੂੰ ਨਹੀਂ ਰੋਕਦੇ)। ਹਰ ਬੇਨਤੀ ਲਈ `x-omniroute-disabled-guardrails` ਹੈਡਰ ਰਾਹੀਂ ਬਾਹਰ ਰਹਿਣ ਦੀ ਚੋਣ। → [`docs/security/GUARDRAILS.md`](docs/security/GUARDRAILS.md) ਵੇਖੋ।

| ਐਨਕੋਡਿੰਗ ਤੋਂ ਬਚਾਅ | ਦਰਮਿਆਨੀ | base64/rot13/hex ਡੀਕੋਡ + ਹਦਾਇਤੀ ਕੀਵਰਡ       |

`block` ਮੋਡ ਵਿੱਚ ਸਿਰਫ਼ **ਉੱਚ** ਗੰਭੀਰਤਾ ਵਾਲੀਆਂ ਖੋਜਾਂ ਨੂੰ ਬਲੌਕ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। ਦਰਮਿਆਨੀ-ਗੰਭੀਰਤਾ ਵਾਲੇ
ਪਰਿਵਾਰ ਲੌਗ ਕੀਤੇ ਜਾਂਦੇ ਹਨ, ਪਰ `sanitizeRequest` ਵੱਲੋਂ ਕਦੇ ਵੀ ਬਲੌਕ ਨਹੀਂ ਕੀਤੇ ਜਾਂਦੇ।

ਡੈਸ਼ਬੋਰਡ (Settings → Security) ਜਾਂ `.env` ਰਾਹੀਂ ਸੰਰਚਿਤ ਕਰੋ:

```env
INPUT_SANITIZER_ENABLED=true
INPUT_SANITIZER_MODE=block    # ਚੇਤਾਵਨੀ | ਬਲੌਕ (ਇੰਜੈਕਸ਼ਨ ਨੀਤੀ; ਪੁਰਾਣਾ "redact" ਇੰਜੈਕਸ਼ਨ ਟੈਕਸਟ ਨੂੰ ਨਹੀਂ ਹਟਾਉਂਦਾ)
INPUT_SANITIZER_BLOCK_THRESHOLD=high  # high (ਮੂਲ) | medium | low — ਬਲੌਕ ਮੋਡ ਵਿੱਚ ਇਸ ਪੱਧਰ ਜਾਂ ਇਸ ਤੋਂ ਵੱਧ ਗੰਭੀਰਤਾਵਾਂ ਬਲੌਕ ਕੀਤੀਆਂ ਜਾਂਦੀਆਂ ਹਨ
```

## ਲੋੜੀਂਦੇ ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲ

ਸਰਵਰ ਸ਼ੁਰੂ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਸਾਰੇ ਗੁਪਤ ਮੁੱਲ ਸੈੱਟ ਕੀਤੇ ਜਾਣੇ ਲਾਜ਼ਮੀ ਹਨ। ਜੇ ਉਹ ਮੌਜੂਦ ਨਾ ਹੋਣ ਜਾਂ ਕਮਜ਼ੋਰ ਹੋਣ, ਤਾਂ ਸਰਵਰ **ਤੁਰੰਤ ਅਸਫਲ** ਹੋ ਜਾਵੇਗਾ।

```bash
# ਲੋੜੀਂਦੇ — ਇਨ੍ਹਾਂ ਤੋਂ ਬਿਨਾਂ ਸਰਵਰ ਸ਼ੁਰੂ ਨਹੀਂ ਹੋਵੇਗਾ:
JWT_SECRET=$(openssl rand -base64 48)     # ਘੱਟੋ-ਘੱਟ 32 ਅੱਖਰ
API_KEY_SECRET=$(openssl rand -hex 32)    # ਘੱਟੋ-ਘੱਟ 16 ਅੱਖਰ

# ਸਿਫ਼ਾਰਸ਼ੀ — ਸਟੋਰੇਜ ਵਿੱਚ ਮੌਜੂਦ ਡਾਟੇ ਦੀ ਇਨਕ੍ਰਿਪਸ਼ਨ ਸਮਰੱਥ ਕਰਦਾ ਹੈ:
STORAGE_ENCRYPTION_KEY=$(openssl rand -hex 32)
```

ਸਰਵਰ `changeme`, `secret`, ਜਾਂ `password` ਵਰਗੇ ਜਾਣੇ-ਪਛਾਣੇ ਕਮਜ਼ੋਰ ਮੁੱਲਾਂ ਨੂੰ ਸਰਗਰਮੀ ਨਾਲ ਰੱਦ ਕਰਦਾ ਹੈ।

- Zod ਰਾਹੀਂ ਮੋਡੀਊਲ ਲੋਡ ਹੋਣ ਵੇਲੇ ਪ੍ਰੋਵਾਈਡਰ ਕਾਂਸਟੈਂਟਾਂ ਦੀ ਪ੍ਰਮਾਣਿਕਤਾ ਜਾਂਚੀ ਜਾਂਦੀ ਹੈ (`src/shared/validation/schemas.ts`)

## ਸਖ਼ਤ ਸੁਰੱਖਿਆ ਨਿਯਮ

ਇਹ ਨਿਯਮ ਟੂਲਿੰਗ ਅਤੇ ਸਮੀਖਿਅਕਾਂ ਦੁਆਰਾ ਲਾਗੂ ਕੀਤੇ ਜਾਂਦੇ ਹਨ:

1. **ਗੁਪਤ ਮੁੱਲ ਕਦੇ ਵੀ commit ਨਾ ਕਰੋ** — `.env` ਨੂੰ gitignore ਕੀਤਾ ਗਿਆ ਹੈ; `.env.example` ਟੈਂਪਲੇਟ ਹੈ (ਕੋਈ ਲਿਟਰਲ ਨਹੀਂ, ਸਿਰਫ਼ ਟਿੱਪਣੀਆਂ — ਹੇਠਾਂ PUBLIC_CREDS.md ਵੇਖੋ)
2. **ਕਦੇ ਵੀ `eval()`, `new Function()`, ਜਾਂ implied eval ਨਾ ਵਰਤੋ** — ESLint ਇਸਨੂੰ ਲਾਗੂ ਕਰਦਾ ਹੈ
3. **ਸਪਸ਼ਟ ਆਪਰੇਟਰ ਮਨਜ਼ੂਰੀ ਤੋਂ ਬਿਨਾਂ Husky hooks ਨੂੰ ਕਦੇ ਵੀ ਬਾਈਪਾਸ ਨਾ ਕਰੋ** (`--no-verify`, `--no-gpg-sign`)
4. **ਰੂਟਾਂ ਵਿੱਚ ਕਦੇ ਵੀ ਕੱਚੀ SQL ਨਾ ਲਿਖੋ** — ਹਮੇਸ਼ਾ `src/lib/db/` ਰਾਹੀਂ ਜਾਓ (ਪੈਰਾਮੀਟਰਾਈਜ਼ਡ)
5. **ਇਨਪੁੱਟਾਂ ਦੀ ਹਮੇਸ਼ਾ Zod ਨਾਲ ਪ੍ਰਮਾਣਿਕਤਾ ਜਾਂਚੋ** — `src/shared/validation/schemas.ts`
6. **ਅੱਪਸਟ੍ਰੀਮ ਹੈਡਰਾਂ ਨੂੰ ਹਮੇਸ਼ਾ ਸੈਨਿਟਾਈਜ਼ ਕਰੋ** — `src/shared/constants/upstreamHeaders.ts` ਵਿੱਚ denylist
7. **ਸਟੋਰੇਜ ਵਿੱਚ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲਾਂ ਨੂੰ ਇਨਕ੍ਰਿਪਟ ਕਰੋ** — `src/lib/db/encryption.ts` ਰਾਹੀਂ AES-256-GCM
8. **ਜਨਤਕ ਅੱਪਸਟ੍ਰੀਮ OAuth ਪਛਾਣਕਰਤਾ `resolvePublicCred()` ਰਾਹੀਂ** — ਸੋਰਸ ਵਿੱਚ ਕਦੇ ਵੀ `AIza…` / `GOCSPX-…` / `…apps.googleusercontent.com` ਲਿਟਰਲ ਸ਼ਾਮਲ ਨਾ ਕਰੋ। [`docs/security/PUBLIC_CREDS.md`](docs/security/PUBLIC_CREDS.md) ਵੇਖੋ।
9. **ਗਲਤੀ ਜਵਾਬ `buildErrorBody()` / `sanitizeErrorMessage()` ਰਾਹੀਂ** — HTTP / SSE / executor / MCP ਜਵਾਬ ਬਾਡੀਆਂ ਵਿੱਚ ਕਦੇ ਵੀ ਕੱਚਾ `err.stack` / `err.message` ਨਾ ਪਾਓ। [`docs/security/ERROR_SANITIZATION.md`](docs/security/ERROR_SANITIZATION.md) ਵੇਖੋ।
10. **`exec()` / `spawn()` ਦੇ ਰਨਟਾਈਮ ਮੁੱਲ `env` ਵਿਕਲਪ ਰਾਹੀਂ** — ਬਾਹਰੀ ਪਾਥਾਂ ਜਾਂ ਅਵਿਸ਼ਵਾਸਯੋਗ ਮੁੱਲਾਂ ਨੂੰ shell ਰਾਹੀਂ ਚਲਾਈਆਂ ਜਾਣ ਵਾਲੀਆਂ ਸਕ੍ਰਿਪਟਾਂ ਵਿੱਚ ਕਦੇ ਵੀ ਸਟ੍ਰਿੰਗ-ਇੰਟਰਪੋਲੇਟ ਨਾ ਕਰੋ। ਹਵਾਲਾ: `src/mitm/cert/install.ts::updateNssDatabases`।
11. **ਮੂਲ ਰੂਪ ਵਿੱਚ ਸੁਰੱਖਿਅਤ ਲਾਇਬ੍ਰੇਰੀਆਂ ਨੂੰ ਤਰਜੀਹ ਦਿਓ** — [tldrsec/awesome-secure-defaults](https://github.com/tldrsec/awesome-secure-defaults) ਵੇਖੋ (Helmet.js, DOMPurify, ssrf-req-filter, safe-regex, Google Tink)। ਆਪਣਾ ਹੱਲ ਬਣਾਉਣ ਤੋਂ ਪਹਿਲਾਂ ਇਨ੍ਹਾਂ ਦੀ ਵਰਤੋਂ ਕਰੋ।

## ਸਪਲਾਈ-ਚੇਨ ਸਕੈਨਰ ਦੇ ਨਤੀਜੇ (Socket.dev / Snyk / ਸਮਾਨ)

> **ਦਾਇਰਾ ਨੋਟ:** ਰਿਪੋਜ਼ਟਰੀ ਰੂਟ ਵਿੱਚ `socket.yml` ਸਿਰਫ਼ ਪ੍ਰਕਾਸ਼ਿਤ npm ਆਰਟੀਫੈਕਟ ਦੇ Socket.dev ਦੇ ਰਜਿਸਟਰੀ-ਪਾਸੇ ਪੋਸਟ-ਪਬਲਿਸ਼ ਸਕੈਨ ਲਈ `projectIgnorePaths` ਨੂੰ ਆਕਾਰ ਦਿੰਦੀ ਹੈ — ਇਹ ਲਾਗੂ ਕੀਤਾ ਗਿਆ CI/PR ਮਰਜ ਗੇਟ ਨਹੀਂ ਹੈ। `.github/workflows` ਵਿੱਚ ਕੋਈ ਵਰਕਫ਼ਲੋ, ਕੋਈ `package.json` ਸਕ੍ਰਿਪਟ ਅਤੇ ਕੋਈ `Makefile` ਟਾਰਗੇਟ Socket.dev ਨੂੰ ਸੱਦਾ ਨਹੀਂ ਦਿੰਦਾ।

ਪ੍ਰਕਾਸ਼ਿਤ `omniroute` npm ਆਰਟੀਫੈਕਟ Next.js `output: "standalone"`
ਬਿਲਡ ਨੂੰ ਬੰਡਲ ਕਰਦਾ ਹੈ, ਜਿਸਦਾ ਮਤਲਬ ਹੈ ਕਿ ਹਰ ਰੂਟ ਹੈਂਡਲਰ — ਦਸਤਾਵੇਜ਼ਬੱਧ ਵਿਸ਼ੇਸ਼-ਅਧਿਕਾਰ ਪ੍ਰਾਪਤ
ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ (MITM, Zed ਇੰਪੋਰਟ, Cloud Sync, ਐਮਬੈਡਿਡ ਸਰਵਿਸ ਸੁਪਰਵਾਈਜ਼ਰ) ਸਮੇਤ — ਅੰਤ ਵਿੱਚ
`.next/server/*.js` ਮਿਨੀਫਾਈਡ ਚੰਕਾਂ ਵਿੱਚ ਪਹੁੰਚ ਜਾਂਦਾ ਹੈ। ਹਿਊਰਿਸਟਿਕ ਸਪਲਾਈ-ਚੇਨ ਸਕੈਨਰ
ਅਕਸਰ ਉਹਨਾਂ ਚੰਕਾਂ ਦਾ ਮਾਲਵੇਅਰ ਸਿਗਨੇਚਰਾਂ ਨਾਲ ਪੈਟਰਨ-ਮੈਚ ਕਰਦੇ ਹਨ।

ਸਾਡੇ ਵੱਲੋਂ ਵਰਤੀ ਜਾਂਦੀ ਸਕੈਨਰ ਸੰਰਚਨਾ ਰਿਪੋ ਰੂਟ ਵਿੱਚ [`socket.yml`](socket.yml) ਵਿਖੇ ਮੌਜੂਦ ਹੈ
(Socket.dev GitHub App ਫਾਰਮੈਟ v2 — ਵੇਖੋ
<https://docs.socket.dev/docs/socket-yml>)। ਇਹ ਸਪਸ਼ਟ ਤੌਰ 'ਤੇ
ਨਾ-ਭੇਜੀਆਂ ਜਾਣ ਵਾਲੀਆਂ ਡਾਇਰੈਕਟਰੀਆਂ (`tests/`, `_tasks/`, `_references/`, `_ideia/`,
`_mono_repo/`, `docs/`, ਆਦਿ) ਨੂੰ ਬਾਹਰ ਰੱਖਦੀ ਹੈ, ਤਾਂ ਜੋ ਸਕੈਨਰ ਸਿਰਫ਼ ਉਹਨਾਂ ਕੋਡ ਪਾਥਾਂ ਬਾਰੇ
ਰਿਪੋਰਟ ਕਰੇ ਜੋ ਅਸਲ ਵਿੱਚ ਪ੍ਰਕਾਸ਼ਿਤ ਵਰਤੋਂਕਾਰਾਂ ਤੱਕ ਪਹੁੰਚਦੇ ਹਨ — ਸਕੈਨ ਖੁਦ Socket
GitHub App ਵੱਲੋਂ ਇਸ ਫ਼ਾਈਲ ਨੂੰ ਪੜ੍ਹ ਕੇ ਚਲਾਇਆ ਜਾਂਦਾ ਹੈ, ਨਾ ਕਿ ਇਸ ਰਿਪੋਜ਼ਟਰੀ ਦੇ ਕਿਸੇ ਵਰਕਫ਼ਲੋ ਦੁਆਰਾ।

ਹਰੇਕ ਨਤੀਜਾ ਸ਼੍ਰੇਣੀ ਲਈ ਅਸੀਂ ਪ੍ਰਤੀ-ਨਤੀਜਾ ਮੇਨਟੇਨਰ ਤਸਦੀਕ ਬਣਾਈ ਰੱਖਦੇ ਹਾਂ:

- **[`docs/security/SOCKET_DEV_FINDINGS.md`](docs/security/SOCKET_DEV_FINDINGS.md)** —
  ਪ੍ਰਤੀ-ਨਤੀਜਾ ਨਕਸ਼ਾ: ਸਰੋਤ ਫ਼ਾਈਲ ↔ ਫ਼ਲੈਗ ਕੀਤਾ ਚੰਕ ↔ ਵਿਹਾਰ ↔ v3.8.6 ਵਿੱਚ
  ਲਾਗੂ ਕੀਤਾ ਨਿਵਾਰਨ।
- ਹਰੇਕ ਫ਼ਲੈਗ ਕੀਤੇ ਫੰਕਸ਼ਨ 'ਤੇ ਸਰੋਤ ਦੇ ਅੰਦਰਲੇ `SECURITY-AUDITOR-NOTE:` ਬਲਾਕ
  ਉਸੇ ਦਸਤਾਵੇਜ਼ ਵੱਲ ਵਾਪਸ ਸੰਕੇਤ ਕਰਦੇ ਹਨ।

ਉਹਨਾਂ ਵਰਤੋਂਕਾਰਾਂ ਲਈ ਜਿਨ੍ਹਾਂ ਦੀ ਪਾਈਪਲਾਈਨ ਅਲਰਟ ਨੂੰ ਢਿੱਲਾ ਨਹੀਂ ਕਰ ਸਕਦੀ:
`OMNIROUTE_BUILD_PROFILE=minimal npm run build` ਨਾਲ ਬਿਲਡ ਕਰੋ। ਇਹ ਚਾਰ
ਸੰਵੇਦਨਸ਼ੀਲ ਮੋਡੀਊਲਾਂ ਨੂੰ ਅਜਿਹੇ ਸਟੱਬਾਂ ਨਾਲ ਬਦਲ ਦਿੰਦਾ ਹੈ ਜੋ ਰਨਟਾਈਮ ਦੌਰਾਨ HTTP 503
`feature-disabled` ਵਾਪਸ ਕਰਦੇ ਹਨ, ਇਸ ਲਈ ਵਿਸ਼ੇਸ਼-ਅਧਿਕਾਰ ਪ੍ਰਾਪਤ ਕੋਡ ਪਾਥ ਬੰਡਲ ਵਿੱਚ
ਭੌਤਿਕ ਤੌਰ 'ਤੇ ਮੌਜੂਦ ਨਹੀਂ ਹੁੰਦੇ। ਪ੍ਰਕਾਸ਼ਨ ਵਿਧੀ ਲਈ
[`docs/security/SOCKET_DEV_FINDINGS.md`](docs/security/SOCKET_DEV_FINDINGS.md)
ਵੇਖੋ।
