Claude Code ਉੱਤੇ ਲਾਗੂ ਹੁੰਦੀ ਹੈ — `AGENTS.md` ਵਿੱਚ ਪਹਿਲਾਂ ਤੋਂ ਪਰਿਭਾਸ਼ਿਤ ਨਿਯਮਾਂ ਦੇ ਸੰਚਾਲਕੀ ਸੁਧਾਰ।

## ਵਰਕਟ੍ਰੀ ਅਲੱਗਾਵ — Claude Code ਦੀਆਂ ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ

ਪੂਰਾ ਲਾਜ਼ਮੀ ਵਰਕਟ੍ਰੀ ਪ੍ਰੋਟੋਕੋਲ (ਬੇਸ-ਬ੍ਰਾਂਚ ਪੁਸ਼ਟੀ, `.claude/worktrees/` ਪ੍ਰਮਾਣਿਕ
ਪਾਥ, `cp -al` node_modules, ਸਮਾਪਤੀ ਨਿਯਮ) `AGENTS.md` → Git Workflow → "Worktree
isolation" ਵਿੱਚ ਹੈ। Claude-Code-ਵਿਸ਼ੇਸ਼ ਨੁਕਤੇ:

- ਜਦੋਂ ਤੱਕ ਓਪਰੇਟਰ ਨੇ ਤੁਹਾਨੂੰ ਪਹਿਲਾਂ ਹੀ ਨਾ ਦੱਸਿਆ ਹੋਵੇ, `AskUserQuestion` ਰਾਹੀਂ ਬੇਸ ਬ੍ਰਾਂਚ ਦੀ ਪੁਸ਼ਟੀ ਕਰੋ
  (ਸਖ਼ਤ ਨਿਯਮ #19)।
- ਮੂਲ `EnterWorktree` ਟੂਲ ਨੂੰ ਤਰਜੀਹ ਦਿਓ — ਇਹ ਪਹਿਲਾਂ ਹੀ
  `.claude/worktrees/` (ਪ੍ਰਮਾਣਿਕ ਪਾਥ) ਅਧੀਨ ਵਰਕਟ੍ਰੀਆਂ ਬਣਾਉਂਦਾ ਹੈ। ਦਸਤਾਵੇਜ਼ਬੱਧ `git
worktree add` ਕਮਾਂਡ ਨਾਲ ਵਰਕਟ੍ਰੀ ਬਣਾਓ, ਫਿਰ ਇਸਦੇ `path` ਨਾਲ `EnterWorktree` ਨੂੰ ਕਾਲ ਕਰੋ।

## ਕ੍ਰਾਸ-ਸੈਸ਼ਨ ਸੁਰੱਖਿਆ — Claude Code ਦੀਆਂ ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ

ਸਖ਼ਤ ਨਿਯਮ #19/#21/#22 (`AGENTS.md` ਵਿੱਚ) ਸਮਾਂਤਰ ਸੈਸ਼ਨਾਂ ਨੂੰ ਨਿਯੰਤਰਿਤ ਕਰਦੇ ਹਨ। ਇਸ
ਹਾਰਨੈੱਸ ਲਈ ਸੰਚਾਲਕੀ ਯਾਦ-ਦਹਾਨੀਆਂ:

- **git ਨੂੰ ਛੂਹਣ ਵਾਲੇ ਹਰ ਸਬ-ਏਜੰਟ ਦੇ ਪ੍ਰੌਮਪਟ ਵਿੱਚ `git stash` ਪਾਬੰਦੀ ਨੂੰ ਹੂਬਹੂ ਦੁਹਰਾਓ**
  (Agent ਟੂਲ / Workflow ਸਕ੍ਰਿਪਟਾਂ) — ਸਬ-ਏਜੰਟਾਂ ਨੂੰ ਇਹ ਫ਼ਾਈਲ ਵਿਰਾਸਤ ਵਿੱਚ ਨਹੀਂ ਮਿਲਦੀ, ਅਤੇ stash ਘਟਨਾ
  ਦੀ ਦਰਜ ਕੀਤੀ ਦੁਹਰਾਈ ਇੱਕ ਸਬ-ਏਜੰਟ ਰਾਹੀਂ ਹੋਈ ਸੀ।
- ਕਿਸੇ ਵੀ ਅਜਿਹੀ PR ਨੂੰ ਮਰਜ ਜਾਂ ਪੁਸ਼ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ, ਜੋ ਤੁਸੀਂ _ਇਸ ਸੈਸ਼ਨ_ ਵਿੱਚ ਨਹੀਂ ਬਣਾਈ, `git worktree list`
  ਚਲਾਓ ਅਤੇ `gh pr view <N> --json state,headRefOid` ਨੂੰ ਮੁੜ ਜਾਂਚੋ (ਸਖ਼ਤ ਨਿਯਮ #22b)।
- ਹਰ ਸੈਸ਼ਨ ਨੂੰ ਮੁੱਖ ਚੈੱਕਆਉਟ ਉਸੇ ਬ੍ਰਾਂਚ ਉੱਤੇ ਰੱਖ ਕੇ ਸਮਾਪਤ ਕਰੋ, ਜਿਸ ਉੱਤੇ ਇਹ ਸ਼ੁਰੂ ਹੋਇਆ ਸੀ।

## Superpowers / ਯੋਜਨਾ ਆਰਟੀਫੈਕਟ — ਪਾਥ ਓਵਰਰਾਈਡ

`_tasks/` ਰਵਾਇਤ `AGENTS.md` → "Planning & Research Artifacts" ਵਿੱਚ ਪਰਿਭਾਸ਼ਿਤ ਹੈ।
superpowers ਸਕਿੱਲਾਂ ਦੇ ਡਿਫਾਲਟ `docs/…` ਵੱਲ ਇਸ਼ਾਰਾ ਕਰਦੇ ਹਨ — ਉਹ ਡਿਫਾਲਟ ਇੱਥੇ **ਓਵਰਰਾਈਡ
ਕੀਤੇ ਗਏ ਹਨ**। ਜਦੋਂ ਕੋਈ superpowers ਸਕਿੱਲ "saved to `docs/superpowers/plans/…`" ਵਰਗੇ ਪਾਥ ਦਾ ਐਲਾਨ ਕਰੇ,
ਲਿਖਣ ਤੋਂ ਪਹਿਲਾਂ ਇਸਨੂੰ `_tasks/…` ਦੇ ਬਰਾਬਰ ਪਾਥ ਵਿੱਚ ਮੁੜ ਲਿਖੋ:

| ਆਰਟੀਫੈਕਟ (ਸਕਿੱਲ)                  | ਡਿਫਾਲਟ (ਵਰਤਣਾ ਨਹੀਂ)       | ਇਸਦੀ ਬਜਾਏ ਇੱਥੇ ਸੰਭਾਲੋ                                         |
| --------------------------------- | ------------------------- | ------------------------------------------------------------- |
| ਯੋਜਨਾਵਾਂ (`writing-plans`)        | `docs/superpowers/plans/` | `_tasks/superpowers/plans/YYYY-MM-DD-<feature>.md`            |
| ਸਪੈਕਸ / ਡਿਜ਼ਾਈਨ (`brainstorming`) | `docs/superpowers/specs/` | `_tasks/superpowers/specs/YYYY-MM-DD-<topic>-design.md`       |
| ਖੋਜ (`deep-research`, ਤਤਕਾਲ)      | `docs/research/`          | `_tasks/research/…`                                           |
| ਹੈਂਡ-ਆਫ਼ (`/handoff`)             | —                         | `_tasks/hands-off/<YYYY-MM-DD>_<branch>_v<versão>_sess-<id>/` |

ਉਨ੍ਹਾਂ ਆਰਟੀਫੈਕਟਾਂ ਨੂੰ `_tasks/` ਰਿਪੋ ਦੇ ਅੰਦਰ ਕਮਿਟ ਕਰੋ (`git -C _tasks …`), ਮੁੱਖ ਰਿਪੋ ਵਿੱਚ ਕਦੇ ਨਹੀਂ।

## PR ਖੋਲ੍ਹਣ ਤੋਂ ਪਹਿਲਾਂ ਬੇਸ-ਗ੍ਰੀਨ

ਬ੍ਰਾਂਚ ਕੱਟਣ ਜਾਂ PR ਖੋਲ੍ਹਣ ਤੋਂ ਪਹਿਲਾਂ, ਬੇਸ-ਗ੍ਰੀਨ ਜਾਂਚ ਚਲਾਓ (`AGENTS.md` → Git Workflow →
"Base-green check"; ਪ੍ਰੋਜੈਕਟ ਸਕਿੱਲ ਇਸਨੂੰ `.agents/skills/_shared/base-green.md` ਵਜੋਂ ਦਰਸਾਉਂਦੀਆਂ ਹਨ)। ਜਦੋਂ
ਬੇਸ ਟਿਪ ਰੈੱਡ ਹੋਵੇ, ਉਸ ਵੇਲੇ ਖੋਲ੍ਹੀ ਗਈ PR ਦੀ ਬਾਡੀ ਵਿੱਚ `⚠️ base-red inherited: #<issue>` ਹੋਣਾ ਲਾਜ਼ਮੀ ਹੈ। ਇਕੱਠੀ ਹੋਈ
ਰੈੱਡ ਸਥਿਤੀ (ਬੇਸ ਟਿਪ + ਰੈੱਡ PRs) ਨੂੰ ਖ਼ਤਮ ਕਰਨ ਲਈ `/sweep-reds` ਸਕਿੱਲ ਵਰਤੋ।
