> **ਆਖਰੀ ਵਾਰ ਅੱਪਡੇਟ ਕੀਤਾ:** 2026-06-28 — v3.8.40

OmniRoute ਸੋਚਣ-ਮੋਡ ਵਾਲੇ ਮਾਡਲਾਂ ਦੁਆਰਾ ਤਿਆਰ ਕੀਤੀ ਸਹਾਇਕ `reasoning_content` ਨੂੰ ਕੈਪਚਰ ਕਰਦਾ ਹੈ ਅਤੇ ਜਦੋਂ ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰਦਾਤਾ ਨੂੰ ਇਸਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ, ਤਾਂ ਬਹੁ-ਵਾਰੀ ਬੇਨਤੀਆਂ ਵਿੱਚ ਇਸਨੂੰ ਪਾਰਦਰਸ਼ੀ ਢੰਗ ਨਾਲ ਮੁੜ ਚਲਾਉਂਦਾ ਹੈ। ਇਹ ਉਹਨਾਂ HTTP 400 ਗਲਤੀਆਂ ਨੂੰ ਖਤਮ ਕਰਦਾ ਹੈ ਜੋ ਸਖ਼ਤ ਪ੍ਰਦਾਤਾ ਉਦੋਂ ਦਿੰਦੇ ਹਨ ਜਦੋਂ ਕਿਸੇ ਕਲਾਇੰਟ ਦੇ ਗੱਲਬਾਤ ਇਤਿਹਾਸ ਵਿੱਚ ਪਿਛਲੀ ਵਾਰੀ ਦੀ ਤਰਕ-ਪ੍ਰਕਿਰਿਆ ਮੌਜੂਦ ਨਹੀਂ ਹੁੰਦੀ।

## ਇਹ ਕਿਉਂ ਮੌਜੂਦ ਹੈ

ਕਈ ਸੋਚਣ-ਮੋਡ ਪ੍ਰਦਾਤਾ ਅਗਲੀ ਵਾਰੀ ਨੂੰ ਰੱਦ ਕਰ ਦਿੰਦੇ ਹਨ ਜਦੋਂ ਤੱਕ **ਪਿਛਲੇ ਸਹਾਇਕ ਸੁਨੇਹੇ ਵਿੱਚ ਮੂਲ `reasoning_content` ਸ਼ਾਮਲ ਨਾ ਹੋਵੇ**। ਅੱਪਸਟ੍ਰੀਮ ਇਸ ਤਰ੍ਹਾਂ ਦੇ ਸੁਨੇਹਿਆਂ ਨਾਲ 400 ਵਾਪਸ ਕਰਦਾ ਹੈ:

```
ਪੈਰਾਮੀਟਰ ਗਲਤ ਹੈ: ਸੋਚਣ ਮੋਡ ਵਿੱਚ reasoning_content ਨੂੰ API ਨੂੰ ਵਾਪਸ ਭੇਜਣਾ ਲਾਜ਼ਮੀ ਹੈ।
```

ਪਰ ਆਮ ਕਲਾਇੰਟ (Cursor, Cline, Roo Code, OpenAI SDK) ਆਪਣੇ ਵੱਲੋਂ ਮੁੜ ਚਲਾਏ ਜਾਣ ਵਾਲੇ ਇਤਿਹਾਸ ਵਿੱਚੋਂ `reasoning_content` ਨੂੰ ਹਟਾ ਦਿੰਦੇ ਹਨ। OmniRoute ਇਸਨੂੰ ਸਰਵਰ-ਪਾਸੇ ਕੈਸ਼ ਤੋਂ ਬਹਾਲ ਕਰਦਾ ਹੈ, ਤਾਂ ਜੋ ਅੱਪਸਟ੍ਰੀਮ ਨੂੰ ਦਿਖਾਈ ਦੇਣ ਵਾਲੀ ਬੇਨਤੀ ਇਕਸਾਰ ਰਹੇ। ਮੁੱਦਾ #1628 ਨੇ ਹਾਈਬ੍ਰਿਡ ਮੈਮੋਰੀ/SQLite ਸਥਾਇਤਾ ਪੇਸ਼ ਕੀਤੀ, ਤਾਂ ਜੋ ਕੈਸ਼ ਪ੍ਰਕਿਰਿਆ ਦੇ ਮੁੜ ਚਾਲੂ ਹੋਣ ਤੋਂ ਬਾਅਦ ਵੀ ਕਾਇਮ ਰਹੇ।

## ਆਰਕੀਟੈਕਚਰ

```
ਵਾਰੀ N (ਸਹਾਇਕ ਤਿਆਰ ਕਰਦਾ ਹੈ):
  → ਜਵਾਬ ਵਿੱਚ reasoning_content + tool_calls ਸ਼ਾਮਲ ਹਨ
  → ਜੇ requiresReasoningReplay(provider, model): cacheReasoningFromAssistantMessage()
      ਹਰ tool_call.id ਦੁਆਰਾ ਕੁੰਜੀਬੱਧ ਕਰਕੇ (ਮੈਮੋਰੀ + DB) ਵਿੱਚ ਲਿਖਦਾ ਹੈ
  → ਜਵਾਬ ਕਲਾਇੰਟ ਨੂੰ ਅੱਗੇ ਭੇਜੋ (ਜੋ ਤਰਕ ਨੂੰ ਰੱਖ ਵੀ ਸਕਦਾ ਹੈ ਜਾਂ ਨਹੀਂ ਵੀ)

ਵਾਰੀ N+1 (ਕਲਾਇੰਟ ਅਗਲੀ ਬੇਨਤੀ ਭੇਜਦਾ ਹੈ):
  → ਅਨੁਵਾਦਕ ਪਤਾ ਲਗਾਉਂਦਾ ਹੈ: requiresReasoningReplay(provider, model) === true
  → tool_calls ਵਾਲੇ ਅਤੇ reasoning_content ਤੋਂ ਬਿਨਾਂ ਹਰ ਸਹਾਇਕ ਸੁਨੇਹੇ ਲਈ:
      lookupReasoning(toolCalls[0].id) → ਮੈਮੋਰੀ → DB
      ਮਿਲਿਆ  → msg.reasoning_content = cached; recordReplay()
      ਨਾ ਮਿਲਿਆ → msg.reasoning_content = "" (ਪੁਰਾਣੇ DeepSeek ਲਈ ਵਿਰਾਸਤੀ ਫਾਲਬੈਕ)
  → ਅੱਪਸਟ੍ਰੀਮ ਨੂੰ ਇਕਸਾਰ ਇਤਿਹਾਸ ਦਿਖਾਈ ਦਿੰਦਾ ਹੈ → ਕੋਈ 400 ਨਹੀਂ
```

ਕੈਪਚਰ `open-sse/handlers/chatCore.ts` ਵਿੱਚ ਹੁੰਦਾ ਹੈ (ਦੋ ਥਾਵਾਂ 'ਤੇ, ਦੋ `cacheReasoningFromAssistantMessage` ਕਾਲ ਸਥਾਨਾਂ 'ਤੇ)। ਮੁੜ ਚਲਾਉਣਾ `open-sse/translator/index.ts` ਵਿੱਚ ਸਕੀਮਾ ਕੋਅਰਸ਼ਨ ਤੋਂ ਬਾਅਦ, ਪਰ ਡਿਸਪੈਚ ਤੋਂ ਪਹਿਲਾਂ ਹੁੰਦਾ ਹੈ।

## ਸਟੋਰੇਜ — ਹਾਈਬ੍ਰਿਡ ਮੈਮੋਰੀ + SQLite

ਹੌਟ ਪਾਥ ਇੱਕ ਇਨ-ਮੈਮੋਰੀ `Map` (ਰਚਨਾ-ਅਧਾਰਿਤ LRU) ਵਰਤਦਾ ਹੈ, ਜਿਸਨੂੰ ਕਰੈਸ਼ ਰਿਕਵਰੀ ਅਤੇ ਡੈਸ਼ਬੋਰਡ ਦਿੱਖ ਲਈ ਇੱਕ SQLite ਟੇਬਲ ਦਾ ਸਮਰਥਨ ਪ੍ਰਾਪਤ ਹੈ।

| ਪਰਤ    | ਲਾਗੂਕਰਨ                                          | ਉਦੇਸ਼                                                           |
| ------ | ------------------------------------------------ | --------------------------------------------------------------- |
| ਮੈਮੋਰੀ | `open-sse/services/reasoningCache.ts` ਵਿੱਚ `Map` | ਤੇਜ਼ ਖੋਜਾਂ, 200 'ਤੇ ਸਭ ਤੋਂ ਪੁਰਾਣੀ ਐਂਟਰੀ ਹਟਾਉਂਦਾ ਹੈ              |
| DB     | `reasoning_cache` ਟੇਬਲ (`src/lib/db/`)           | ਮੁੜ ਚਾਲੂ ਹੋਣ ਤੋਂ ਬਾਅਦ ਵੀ ਕਾਇਮ ਰਹਿੰਦਾ ਹੈ, ਅੰਕੜਿਆਂ ਨੂੰ ਚਲਾਉਂਦਾ ਹੈ |

ਲਿਖਤਾਂ ਦੋਵਾਂ ਵਿੱਚ ਜਾਂਦੀਆਂ ਹਨ। ਪੜ੍ਹਤਾਂ ਪਹਿਲਾਂ ਮੈਮੋਰੀ ਦੀ ਜਾਂਚ ਕਰਦੀਆਂ ਹਨ, ਫਿਰ DB 'ਤੇ ਫਾਲਬੈਕ ਕਰਦੀਆਂ ਹਨ (DB ਵਿੱਚ ਮਿਲੀਆਂ ਐਂਟਰੀਆਂ ਨੂੰ ਵਾਪਸ ਮੈਮੋਰੀ ਵਿੱਚ ਪ੍ਰਮੋਟ ਕੀਤਾ ਜਾਂਦਾ ਹੈ)। DB ਅਸਫਲਤਾਵਾਂ ਘਾਤਕ ਨਹੀਂ ਹੁੰਦੀਆਂ — ਇਨ-ਮੈਮੋਰੀ ਕੈਸ਼ ਹੌਟ ਪਾਥ ਦੀ ਸੇਵਾ ਜਾਰੀ ਰੱਖਦਾ ਹੈ।

**ਡਿਫਾਲਟ:**

- TTL: `2h` (`TTL_MS = 2 * 60 * 60 * 1000`)
- ਵੱਧ ਤੋਂ ਵੱਧ ਮੈਮੋਰੀ ਐਂਟਰੀਆਂ: `200` (`MAX_MEMORY_ENTRIES`)
- ਐਵਿਕਸ਼ਨ: ਸਭ ਤੋਂ ਪੁਰਾਣਾ `createdAt` ਪਹਿਲਾਂ

## ਡਾਟਾਬੇਸ ਸਕੀਮਾ

ਮਾਈਗ੍ਰੇਸ਼ਨ: `src/lib/db/migrations/033_create_reasoning_cache.sql`

```sql
CREATE TABLE IF NOT EXISTS reasoning_cache (
  tool_call_id   TEXT PRIMARY KEY,
  provider       TEXT NOT NULL,
  model          TEXT NOT NULL,
  reasoning      TEXT NOT NULL,
  char_count     INTEGER NOT NULL DEFAULT 0,
  created_at     TEXT NOT NULL DEFAULT (datetime('now')),
  expires_at     INTEGER NOT NULL
);
```

ਇੰਡੈਕਸ: `expires_at`, `provider`, `model`, `created_at`। `expires_at` ਨੂੰ Unix epoch ਸਕਿੰਟਾਂ ਵਜੋਂ ਸਟੋਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ; SELECT ਪਰਤ `EXPIRES_AT_EPOCH_SQL` ਰਾਹੀਂ ਵਿਰਾਸਤੀ ਟੈਕਸਟ ਮੁੱਲਾਂ ਨੂੰ ਨਾਰਮਲਾਈਜ਼ ਕਰਦੀ ਹੈ।

## REST API

ਕੈਸ਼ `src/app/api/cache/reasoning/route.ts` ਅਧੀਨ ਦੋ ਐਂਡਪੌਇੰਟ ਉਪਲਬਧ ਕਰਵਾਉਂਦਾ ਹੈ। ਦੋਵਾਂ ਲਈ ਪ੍ਰਬੰਧਨ ਪ੍ਰਮਾਣੀਕਰਨ (`@/shared/utils/apiAuth` ਤੋਂ `isAuthenticated`) ਲੋੜੀਂਦਾ ਹੈ।

| ਵਿਧੀ   | ਐਂਡਪੌਇੰਟ                                                  | ਵੇਰਵਾ                                                            |
| ------ | --------------------------------------------------------- | ---------------------------------------------------------------- |
| GET    | `/api/cache/reasoning`                                    | ਅੰਕੜੇ + ਪੰਨਾ-ਵੰਡੀਆਂ ਐਂਟਰੀਆਂ                                      |
| GET    | `/api/cache/reasoning?provider=deepseek&model=...&limit=` | ਫਿਲਟਰ ਕੀਤੀ ਸੂਚੀ (`limit` ਨੂੰ `[1, 200]` ਤੱਕ ਸੀਮਿਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ) |
| DELETE | `/api/cache/reasoning`                                    | ਸਭ ਕੁਝ (ਮੈਮੋਰੀ + DB) ਸਾਫ਼ ਕਰੋ ਅਤੇ ਹਿੱਟ/ਮਿਸ ਗਿਣਤੀਆਂ ਰੀਸੈੱਟ ਕਰੋ    |
| DELETE | `/api/cache/reasoning?provider=deepseek`                  | ਸਿਰਫ਼ ਇੱਕ ਪ੍ਰਦਾਤਾ ਦੀਆਂ ਐਂਟਰੀਆਂ ਸਾਫ਼ ਕਰੋ                          |
| DELETE | `/api/cache/reasoning?toolCallId=call_abc`                | ਇੱਕ ਇਕੱਲੀ ਐਂਟਰੀ ਮਿਟਾਓ                                            |

**GET ਜਵਾਬ ਦੀ ਬਣਤਰ:**

```json
{
```

## ਕਾਰਜਕਾਰੀ ਟਿੱਪਣੀਆਂ

- **ਸਫ਼ਾਈ:** `cleanupReasoningCache()` ਦੀ ਮਿਆਦ ਪੁੱਗ ਚੁੱਕੀਆਂ ਮੈਮੋਰੀ ਐਂਟਰੀਆਂ ਨੂੰ ਹਟਾਉਂਦਾ ਹੈ ਅਤੇ `DELETE FROM reasoning_cache WHERE expires_at <= unixepoch('now')` ਚਲਾਉਂਦਾ ਹੈ। ਸਿਹਤ-ਜਾਂਚ ਵਰਕਰ ਇਸਨੂੰ ਸਮੇਂ-ਸਮੇਂ 'ਤੇ ਕਾਲ ਕਰਦੇ ਹਨ।
- **ਕ੍ਰੈਸ਼ ਤੋਂ ਮੁੜ-ਪ੍ਰਾਪਤੀ:** ਰੀਸਟਾਰਟ ਤੋਂ ਬਾਅਦ ਮੈਮੋਰੀ ਖਾਲੀ ਹੁੰਦੀ ਹੈ, ਪਰ DB ਵਿੱਚ ਅਜੇ ਵੀ ਮਿਆਦ ਨਾ ਪੁੱਗੀਆਂ ਐਂਟਰੀਆਂ ਮੌਜੂਦ ਰਹਿੰਦੀਆਂ ਹਨ। ਕਿਸੇ ਦਿੱਤੇ `tool_call_id` ਲਈ ਪਹਿਲੀ ਖੋਜ DB ਹਿੱਟ ਹੁੰਦੀ ਹੈ; ਇਸ ਤੋਂ ਬਾਅਦ ਦੀਆਂ ਖੋਜਾਂ ਮੈਮੋਰੀ ਹਿੱਟ ਹੁੰਦੀਆਂ ਹਨ।
- **ਕੋਈ ਰੀਜ਼ਨਿੰਗ ਨਹੀਂ, ਕੋਈ ਕੈਸ਼ ਨਹੀਂ:** ਜਦੋਂ ਸਹਾਇਕ ਸੁਨੇਹੇ ਵਿੱਚ ਕੋਈ `reasoning_content` / `reasoning` ਫੀਲਡ ਨਹੀਂ ਹੁੰਦੀ, ਤਾਂ `cacheReasoningFromAssistantMessage` `0` ਵਾਪਸ ਕਰਦਾ ਹੈ, ਇਸ ਲਈ ਗੈਰ-ਥਿੰਕਿੰਗ ਜਵਾਬਾਂ ਦੀ ਕੋਈ ਲਾਗਤ ਨਹੀਂ ਹੁੰਦੀ।
- **ਲਿਖਣਾ ਵੀ ਸ਼ਰਤਬੱਧ ਹੈ:** `chatCore.ts` ਵਿੱਚ ਦੋਵੇਂ ਕਾਲ ਸਥਾਨ (ਗੈਰ-ਸਟ੍ਰੀਮਿੰਗ ਅਤੇ ਸਟ੍ਰੀਮਿੰਗ) ਸਿਰਫ਼ ਉਦੋਂ ਹੀ `cacheReasoningFromAssistantMessage()` ਨੂੰ ਕਾਲ ਕਰਦੇ ਹਨ ਜਦੋਂ `requiresReasoningReplay(provider, model)` `true` ਹੁੰਦਾ ਹੈ — ਇਹ ਉਹੀ ਪ੍ਰੈਡੀਕੇਟ ਹੈ ਜਿਸਦੀ ਰੀਡ ਸਾਈਡ ਜਾਂਚ ਕਰਦੀ ਹੈ। ਉਹ ਇੰਸਟਾਲੇਸ਼ਨ ਜੋ ਕਦੇ ਵੀ ਕਿਸੇ ਰੀਪਲੇ ਪ੍ਰਦਾਤਾ ਨੂੰ ਨਹੀਂ ਵਰਤਦੀਆਂ, ਹਰ ਰੀਜ਼ਨਿੰਗ-ਧਾਰਕ ਜਵਾਬ ਉੱਤੇ ਲਿਖਣ, ਇੰਡੈਕਸ ਅੱਪਡੇਟ ਅਤੇ try/catch ਦੀ ਲਾਗਤ ਦੇਣੀ ਬੰਦ ਕਰ ਦਿੰਦੀਆਂ ਹਨ।
- **ਗੈਰ-ਸਖ਼ਤ ਪ੍ਰਦਾਤਾ:** ਜਦੋਂ `requiresReasoningReplay` `false` ਹੁੰਦਾ ਹੈ ਅਤੇ ਟਾਰਗੇਟ ਫਾਰਮੈਟ OpenAI ਹੁੰਦਾ ਹੈ, ਤਾਂ ਟ੍ਰਾਂਸਲੇਟਰ ਬਾਹਰ ਜਾਣ ਵਾਲੇ ਸੁਨੇਹਿਆਂ ਵਿੱਚੋਂ ਕਿਸੇ ਵੀ `reasoning_content` ਫੀਲਡ ਨੂੰ **ਹਟਾ ਦਿੰਦਾ ਹੈ** — OpenAI Chat Completions ਇਸਨੂੰ ਸਵੀਕਾਰ ਨਹੀਂ ਕਰਦਾ।
