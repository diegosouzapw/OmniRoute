> **ਹਰ ਪ੍ਰੌਕਸੀ ਲਈ ਆਉਟਬਾਊਂਡ ਟ੍ਰੈਫਿਕ ਨੂੰ ਇੱਕੋ IP ਫੈਮਿਲੀ — `auto`, `ipv4`, ਜਾਂ `ipv6` — ਨਾਲ ਪਿੰਨ ਕਰੋ, ਤਾਂ ਜੋ ਸਿਰਫ਼-IPv6 ਈਗ੍ਰੈੱਸ ਕਦੇ ਵੀ ਚੁੱਪਚਾਪ ਮੁੜ IPv4 ਵੱਲ ਲੀਕ ਨਾ ਹੋਵੇ।**

> **ਪ੍ਰਮਾਣਿਕ ਸਰੋਤ:** `open-sse/utils/proxyFamily.ts`, `open-sse/utils/proxyDispatcher.ts`, `open-sse/utils/proxyFetch.ts`, `open-sse/utils/socksConnectorWithFamily.ts`, `open-sse/utils/proxyFamilyResolve.ts`, `src/shared/validation/schemas.ts`, `src/lib/db/proxies.ts`, `src/lib/db/upstreamProxy.ts`, `src/lib/db/migrations/099_proxy_family.sql`

OmniRoute ਹਰ ਪ੍ਰੌਕਸੀ ਨੂੰ ਇੱਕ **ਐਡਰੈੱਸ-ਫੈਮਿਲੀ ਈਗ੍ਰੈੱਸ ਨਿਰਦੇਸ਼** ਰੱਖਣ ਦਿੰਦਾ ਹੈ। ਮੂਲ ਰੂਪ ਵਿੱਚ OS IPv4 ਜਾਂ IPv6 (ਡੁਅਲ-ਸਟੈਕ, "Happy Eyeballs") ਚੁਣਦਾ ਹੈ। ਜਦੋਂ ਤੁਸੀਂ ਨਿਰਦੇਸ਼ ਨੂੰ `ipv4` ਜਾਂ `ipv6` 'ਤੇ ਸੈੱਟ ਕਰਦੇ ਹੋ, ਤਾਂ OmniRoute ਉਸ ਪ੍ਰੌਕਸੀ ਰਾਹੀਂ ਹਰ ਕਨੈਕਸ਼ਨ ਨੂੰ ਚੁਣੀ ਗਈ ਫੈਮਿਲੀ ਨਾਲ ਪਿੰਨ ਕਰਦਾ ਹੈ ਅਤੇ ਦੂਜੀ ਫੈਮਿਲੀ 'ਤੇ ਵਾਪਸ ਜਾਣ ਦੀ ਬਜਾਏ **ਸੁਰੱਖਿਅਤ ਢੰਗ ਨਾਲ ਅਸਫਲ ਹੁੰਦਾ ਹੈ**।

ਇਹ ਪੰਨਾ ਦਸਤਾਵੇਜ਼ਬੱਧ ਕਰਦਾ ਹੈ ਕਿ ਇਹ ਨਿਰਦੇਸ਼ ਕੀ ਹੈ, ਇਹ ਕਿਉਂ ਮੌਜੂਦ ਹੈ, ਤੁਸੀਂ ਇਸਨੂੰ ਕਿੱਥੇ ਸੰਰਚਿਤ ਕਰਦੇ ਹੋ, ਅਤੇ ਰਨਟਾਈਮ ਇਸਦਾ ਨਿਰਧਾਰਨ ਕਿਵੇਂ ਕਰਦਾ ਹੈ।

## ਇਹ ਕੀ ਹੈ

ਰਜਿਸਟਰੀ ਵਿੱਚ ਹਰ ਪ੍ਰੌਕਸੀ ਕੋਲ ਤਿੰਨ ਸੰਭਵ ਮੁੱਲਾਂ ਵਾਲਾ ਇੱਕ `family` ਫੀਲਡ ਹੁੰਦਾ ਹੈ, ਜਿਸਦੀ ਪੁਸ਼ਟੀ Zod enum ਰਾਹੀਂ ਕੀਤੀ ਜਾਂਦੀ ਹੈ:

```ts
// src/shared/validation/schemas.ts
family: z.enum(["auto", "ipv4", "ipv6"]).optional().default("auto"),
```

ਫੀਲਡ ਦਾ ਮੂਲ ਮੁੱਲ `"auto"` ਹੁੰਦਾ ਹੈ, ਜੋ ਪਹਿਲਾਂ ਵਾਲੇ ਡੁਅਲ-ਸਟੈਕ ਵਿਵਹਾਰ ਨੂੰ ਬਰਕਰਾਰ ਰੱਖਦਾ ਹੈ। ਇਸਨੂੰ `ipv4` ਜਾਂ `ipv6` 'ਤੇ ਸੈੱਟ ਕਰਨ ਨਾਲ ਉਸ ਪ੍ਰੌਕਸੀ ਲਈ ਕਨੈਕਸ਼ਨ ਫੈਮਿਲੀ ਪਿੰਨ ਹੋ ਜਾਂਦੀ ਹੈ।

ਨਿਰਦੇਸ਼ ਨੂੰ ਹਰ ਥਾਂ ਇੱਕੋ ਸਹਾਇਕ ਰਾਹੀਂ ਸਧਾਰਨ ਰੂਪ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ, ਤਾਂ ਜੋ ਕੋਈ ਵੀ ਅਣਜਾਣ ਮੁੱਲ `auto` ਵਿੱਚ ਬਦਲ ਜਾਵੇ:

```ts
// open-sse/utils/proxyFamily.ts
export type ProxyFamily = "auto" | "ipv4" | "ipv6";

export function parseProxyFamily(value: unknown): ProxyFamily {
  return value === "ipv4" || value === "ipv6" ? value : "auto";
}
```

| **ਅਨੁਪਾਲਨਾ/ਟੈਸਟਿੰਗ ਲਈ ਨਿਰਧਾਰਤ ਈਗ੍ਰੈੱਸ**     | ਜਦੋਂ ਤੁਹਾਨੂੰ ਇਹ ਗਾਰੰਟੀ ਦੇਣੀ ਲਾਜ਼ਮੀ ਹੋਵੇ ਕਿ ਟ੍ਰੈਫਿਕ ਕਿਸੇ ਖਾਸ ਫੈਮਿਲੀ ਰਾਹੀਂ ਹੀ ਬਾਹਰ ਜਾਂਦਾ ਹੈ, ਤਾਂ `auto` ਕਾਫ਼ੀ ਨਹੀਂ ਹੁੰਦਾ।                                                                                                                                                                                                                         |

ਇਹ ਨਿਰਦੇਸ਼ ਜਾਣਬੁੱਝ ਕੇ **ਹਰ-ਪ੍ਰੌਕਸੀ ਲਈ** ਹੈ, ਗਲੋਬਲ ਨਹੀਂ — ਤੁਹਾਡੇ ਪੂਲ ਵਿੱਚ ਵੱਖ-ਵੱਖ ਪ੍ਰੌਕਸੀਆਂ ਦੀਆਂ ਵੱਖਰੀਆਂ ਨੀਤੀਆਂ ਹੋ ਸਕਦੀਆਂ ਹਨ।

## ਇਸਨੂੰ ਕਿਵੇਂ ਕੌਂਫਿਗਰ ਕਰਨਾ ਹੈ

### ਡੈਸ਼ਬੋਰਡ

ਚੋਣਕਾਰ **Proxy Pool** ਟੈਬ ਦੇ ਪ੍ਰਾਕਸੀ ਫਾਰਮ ਵਿੱਚ ਹੈ:

1. **Dashboard → Settings → Proxy → Proxy Pool** ਖੋਲ੍ਹੋ
2. ਕੋਈ ਪ੍ਰਾਕਸੀ ਜੋੜੋ ਜਾਂ ਸੰਪਾਦਿਤ ਕਰੋ
3. **IP ਫੈਮਿਲੀ** ਡ੍ਰੌਪਡਾਊਨ ਨੂੰ `ਸਵੈਚਾਲਿਤ (ਡੁਅਲ-ਸਟੈਕ)`, `ਸਿਰਫ਼ IPv4`, ਜਾਂ `ਸਿਰਫ਼ IPv6` 'ਤੇ ਸੈੱਟ ਕਰੋ
4. ਸੇਵ ਕਰੋ

ਇਹ ਕੰਟਰੋਲ `ProxyRegistryManager.tsx` ਵੱਲੋਂ ਰੈਂਡਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ (`proxy/ProxyPoolTab.tsx` ਵਿੱਚ ਮਾਊਂਟ ਕੀਤਾ ਗਿਆ ਹੈ)।

### API

`family` ਫੀਲਡ ਪ੍ਰਾਕਸੀ ਰਜਿਸਟਰੀ ਬਣਾਉਣ/ਅੱਪਡੇਟ ਕਰਨ ਵਾਲੇ ਪੇਲੋਡਾਂ ਦਾ ਹਿੱਸਾ ਹੈ, ਜਿਸਨੂੰ `createProxyRegistrySchema` / `updateProxyRegistrySchema` (`src/shared/validation/schemas.ts`) ਵੱਲੋਂ ਪ੍ਰਮਾਣਿਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ ਅਤੇ `POST` / `PATCH /api/v1/management/proxies` ਵੱਲੋਂ ਸੰਭਾਲਿਆ ਜਾਂਦਾ ਹੈ:

```bash
# ਸਿਰਫ਼-IPv6 ਪ੍ਰਾਕਸੀ ਬਣਾਓ
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "IPv6 egress",
    "type": "socks5",
    "host": "proxy.example.com",
    "port": 1080,
    "family": "ipv6"
  }'

# ਕਿਸੇ ਮੌਜੂਦਾ ਪ੍ਰਾਕਸੀ ਨੂੰ ਸਿਰਫ਼-IPv4 ਵਿੱਚ ਬਦਲੋ
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{ "id": "proxy-uuid-here", "family": "ipv4" }'
```

ਇਹੀ ਫੀਲਡ ਅੱਪਸਟ੍ਰੀਮ-ਪ੍ਰਾਕਸੀ ਐਂਟਰੀਆਂ ਲਈ ਵਰਤੇ ਜਾਂਦੇ ਇਨਲਾਈਨ ਪ੍ਰਾਕਸੀ ਕੌਂਫਿਗ ਆਬਜੈਕਟ ਵੱਲੋਂ ਵੀ ਸਵੀਕਾਰ ਕੀਤੀ ਜਾਂਦੀ ਹੈ (`upstream_proxy_config.family`, [ਡਾਟਾ ਮਾਡਲ](#data-model) ਵੇਖੋ)।

ਪ੍ਰਾਕਸੀ CRUD/ਅਸਾਈਨਮੈਂਟ API ਦੇ ਬਾਕੀ ਹਿੱਸੇ ਲਈ, [PROXY_GUIDE.md](../ops/PROXY_GUIDE.md) ਵੇਖੋ।

## `auto` ਕਿਵੇਂ ਰਿਜ਼ੌਲਵ ਹੁੰਦਾ ਹੈ

ਜਦੋਂ `family`, `auto` ਹੁੰਦੀ ਹੈ, ਤਾਂ OmniRoute ਕੋਈ ਵੀ ਡਾਇਰੈਕਟਿਵ **ਨਹੀਂ** ਜੋੜਦਾ — ਪ੍ਰਾਕਸੀ URL ਨੂੰ ਜਿਵੇਂ ਹੈ ਤਿਵੇਂ ਵਰਤਿਆ ਜਾਂਦਾ ਹੈ ਅਤੇ ਕਨੈਕਟ ਫੈਮਿਲੀ ਅੰਦਰੂਨੀ ਤੌਰ 'ਤੇ ਨਿਰਧਾਰਤ ਹੁੰਦੀ ਹੈ।

URL ਬਣਾਉਣ ਸਮੇਂ (`open-sse/utils/proxyDispatcher.ts` ਵਿੱਚ `proxyConfigToUrl` / `normalizeProxyUrl`), ਇੱਕ `auto` ਪ੍ਰਾਕਸੀ ਬਿਨਾਂ ਕਿਸੇ ਮਾਰਕਰ ਦੇ ਸਧਾਰਨ URL ਦਿੰਦੀ ਹੈ:

```ts
// open-sse/utils/proxyDispatcher.ts
const fam = parseProxyFamily(config.family);
const normalized = normalizeProxyUrl(proxyUrlStr, "context proxy", {
  allowSocks5,
});
return fam === "auto" ? normalized : `${normalized}?family=${fam}`;
```

ਡਿਸਪੈਚ ਸਮੇਂ (`resolveDispatcherFamily`), `auto` IP-ਲਿਟਰਲ ਹੋਸਟ ਦੀ ਅੰਦਰੂਨੀ ਫੈਮਿਲੀ ਵਿੱਚ ਰਿਜ਼ੌਲਵ ਹੁੰਦਾ ਹੈ, ਜਾਂ ਹੋਸਟਨੇਮ ਲਈ `null` (OS ਨੂੰ ਫ਼ੈਸਲਾ ਕਰਨ ਦਿਓ) ਵਿੱਚ:

```ts
// open-sse/utils/proxyDispatcher.ts
function resolveDispatcherFamily(parsed: URL): 4 | 6 | null {
  const directive = parseProxyFamily(parsed.searchParams.get("family") ?? undefined);
  const literal = detectIpLiteralFamily(parsed.hostname);
  if (directive === "auto") return literal; // ਹੋਸਟਨੇਮ ਲਈ null → OS ਚੁਣਦਾ ਹੈ
  // ...
}
```

ਇਸ ਲਈ:

- `auto` + IP-ਲਿਟਰਲ ਹੋਸਟ (`192.0.2.1` / `[2001:db8::1]`) → ਉਸ ਲਿਟਰਲ ਦੀ ਫੈਮਿਲੀ।
- `auto` + ਹੋਸਟਨੇਮ → `null` → ਮਿਆਰੀ ਡੁਅਲ-ਸਟੈਕ OS ਰਿਜ਼ੋਲਿਊਸ਼ਨ।

## `ipv4` / `ipv6` ਨੂੰ ਕਿਵੇਂ ਲਾਗੂ ਕੀਤਾ ਜਾਂਦਾ ਹੈ

ਇੱਕ ਗੈਰ-`auto` ਨਿਰਦੇਸ਼ ਇੱਕੋ ਸਿੰਥੈਟਿਕ ਕਵੇਰੀ ਮਾਰਕਰ ਵਜੋਂ ਜਾਂਦਾ ਹੈ — `?family=ipv4` ਜਾਂ `?family=ipv6` — ਜਿਸਨੂੰ ਨਾਰਮਲਾਈਜ਼ ਕੀਤੇ ਪ੍ਰਾਕਸੀ URL ਦੇ ਅੰਤ ਵਿੱਚ ਇੱਕ ਵਾਰ ਜੋੜਿਆ ਜਾਂਦਾ ਹੈ। `normalizeProxyUrl` ਇਸ ਮਾਰਕਰ ਨੂੰ ਹਟਾ ਕੇ ਬਿਲਕੁਲ ਇੱਕ ਵਾਰ ਮੁੜ ਜੋੜਨ ਦਾ ਧਿਆਨ ਰੱਖਦਾ ਹੈ, ਤਾਂ ਜੋ ਇਹ ਕਦੇ ਵੀ ਪੋਰਟ ਪਾਰਸਿੰਗ ਨੂੰ ਖਰਾਬ ਨਾ ਕਰੇ।

ਜਦੋਂ ਡਿਸਪੈਚਰ ਬਣਾਇਆ ਜਾਂਦਾ ਹੈ, ਤਾਂ ਮਾਰਕਰ ਨੂੰ ਪੜ੍ਹ ਕੇ ਇੱਕ ਠੋਸ ਕਨੈਕਟ ਫੈਮਿਲੀ ਵਿੱਚ ਬਦਲਿਆ ਜਾਂਦਾ ਹੈ। ਜੇ ਹੋਸਟ **ਉਲਟ** ਫੈਮਿਲੀ ਦਾ IP ਲਿਟਰਲ ਹੈ, ਤਾਂ OmniRoute ਤਰੁੱਟੀ ਸੁੱਟਦਾ ਹੈ (ਵਿਰੋਧ ਦੀ ਸਥਿਤੀ ਵਿੱਚ fail-closed ਹੁੰਦਾ ਹੈ):

```ts
// open-sse/utils/proxyDispatcher.ts
const want = directive === "ipv6" ? 6 : 4;
if (literal !== null && literal !== want) {
  throw new Error(
    `[ProxyDispatcher] Proxy family directive ${directive} contradicts ${literal === 6 ? "IPv6" : "IPv4"} literal host`
  );
}
```

ਫਿਰ ਠੋਸ ਫੈਮਿਲੀ ਨੂੰ ਕਨੈਕਟਰ ਉੱਤੇ ਪਿੰਨ ਕੀਤਾ ਜਾਂਦਾ ਹੈ:

- **HTTP/HTTPS ਪ੍ਰਾਕਸੀਆਂ** (`ProxyAgent`): `proxyTls: { family, autoSelectFamily: false }` — Happy Eyeballs ਨੂੰ ਅਸਮਰੱਥ ਕਰਦਾ ਹੈ, ਤਾਂ ਜੋ ਸਿਰਫ਼ ਚੁਣੀ ਗਈ ਫੈਮਿਲੀ ਨੂੰ ਹੀ ਡਾਇਲ ਕੀਤਾ ਜਾਵੇ।
- **SOCKS5 ਪ੍ਰਾਕਸੀਆਂ**: ਇੱਕ ਕਸਟਮ ਕਨੈਕਟਰ SOCKS ਕਲਾਇੰਟ ਵਿੱਚ `socket_options: { family, autoSelectFamily: false }` ਪਾਸ ਕਰਦਾ ਹੈ ([SOCKS5 ਅਨੁਕੂਲਤਾ](#socks5-compatibility) ਵੇਖੋ)।

---

## SOCKS5 ਅਨੁਕੂਲਤਾ

ਫੈਮਿਲੀ ਪਿੰਨ SOCKS5 ਪ੍ਰਾਕਸੀਆਂ ਨਾਲ ਕੰਮ ਕਰਦਾ ਹੈ, ਪਰ ਮਿਆਰੀ `fetch-socks` ਪ੍ਰਾਕਸੀ ਹੌਪ ਦੀ ਫੈਮਿਲੀ ਨੂੰ ਪਿੰਨ ਕਰਨ ਲਈ ਲੋੜੀਂਦੇ ਸਾਕਟ ਵਿਕਲਪ ਉਪਲਬਧ ਨਹੀਂ ਕਰਵਾਉਂਦਾ। ਇਸ ਲਈ OmniRoute ਆਪਣੇ ਕਨੈਕਟਰ ਨਾਲ ਆਉਂਦਾ ਹੈ:

```ts
// open-sse/utils/socksConnectorWithFamily.ts
export function buildSocksFamilySocketOptions(family: 4 | 6 | null): Record<string, unknown> {
  if (family === 6) return { family: 6, autoSelectFamily: false };
  if (family === 4) return { family: 4, autoSelectFamily: false };
  return {};
}
```

ਸਾਰੇ SOCKS5 ਡਿਸਪੈਚ `family` ਦੀ ਪਰਵਾਹ ਕੀਤੇ ਬਿਨਾਂ `createSocksDispatcherWithFamily` ਰਾਹੀਂ ਜਾਂਦੇ ਹਨ (ਇਸ ਵਿੱਚ ਹੋਸਟਨੇਮ ਉੱਤੇ `null` / `auto` ਵੀ ਸ਼ਾਮਲ ਹਨ): `buildSocksFamilySocketOptions(null)` ਤੋਂ `{}` ਮਿਲਦਾ ਹੈ, ਅਤੇ ਉਹੀ `SocksClient.createConnection` + TLS `buildConnector` ਪਾਥ `socket_options` ਪਿੰਨਿੰਗ ਨਾਲ ਵਰਤਿਆ ਜਾਂਦਾ ਹੈ, ਤਾਂ ਜੋ Happy Eyeballs ਸਿਰਫ਼-IPv6 ਈਗ੍ਰੈੱਸ ਨੀਤੀ ਲਈ IPv4 ਨਾ ਚੁਣ ਸਕੇ।

SOCKS5 ਸਹਾਇਤਾ ਮੂਲ ਰੂਪ ਵਿੱਚ ਚਾਲੂ ਹੁੰਦੀ ਹੈ (`ENABLE_SOCKS5_PROXY=false` ਰਾਹੀਂ ਇਸ ਤੋਂ ਬਾਹਰ ਹੋ ਸਕਦੇ ਹੋ); [PROXY_GUIDE.md → ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲ](../ops/PROXY_GUIDE.md#environment-variables) ਵੇਖੋ।

## Fail-Closed ਵਿਵਹਾਰ

ਇਸ ਨਿਰਦੇਸ਼ ਦਾ ਪੂਰਾ ਮਕਸਦ ਗਲਤ ਫੈਮਿਲੀ ਉੱਤੇ ਚੁੱਪਚਾਪ ਫਾਲਬੈਕ ਕਰਨ ਦੀ ਬਜਾਏ ਉਸਨੂੰ **ਅਸਵੀਕਾਰ** ਕਰਨਾ ਹੈ। ਦੋ ਗਾਰਡ ਇਸਨੂੰ ਲਾਗੂ ਕਰਦੇ ਹਨ:

1. **ਲਿਟਰਲ ਵਿਰੋਧ** — ਇੱਕ ਨਿਰਦੇਸ਼ ਜੋ IP-ਲਿਟਰਲ ਹੋਸਟ ਨਾਲ ਵਿਰੋਧ ਕਰਦਾ ਹੈ, ਡਿਸਪੈਚਰ ਬਣਾਉਣ ਵੇਲੇ ਤਰੁੱਟੀ ਸੁੱਟਦਾ ਹੈ (`resolveDispatcherFamily`, ਉੱਪਰ ਦਿਖਾਇਆ ਗਿਆ ਹੈ)।

2. **ਹੋਸਟਨੇਮ ਪ੍ਰੀ-ਫਲਾਈਟ DNS ਜਾਂਚ** — ਪਿੰਨ ਕੀਤੀ ਫੈਮਿਲੀ ਵਾਲੀ ਹੋਸਟਨੇਮ ਪ੍ਰਾਕਸੀ ਲਈ, `proxyFetch.ts` ਈਗ੍ਰੈੱਸ ਕਰਨ ਤੋਂ **ਪਹਿਲਾਂ** `assertHostnameSupportsFamily` ਰਾਹੀਂ ਪੁਸ਼ਟੀ ਕਰਦਾ ਹੈ ਕਿ ਹੋਸਟਨੇਮ ਕੋਲ ਲੋੜੀਂਦੀ ਫੈਮਿਲੀ ਵਿੱਚ ਵਾਸਤਵ ਵਿੱਚ ਇੱਕ ਰਿਕਾਰਡ ਹੈ:

   ```ts
   // open-sse/utils/proxyFamilyResolve.ts
   const hasFamily = records.some((r) => r.family === family);
   if (!hasFamily) {
     throw new Error(
       `[ProxyFamily] Proxy host ${host} has no ${family === 6 ? "IPv6 (AAAA)" : "IPv4 (A)"} record; ` +
         `refusing ${family === 6 ? "IPv6" : "IPv4"}-only egress (fail-closed)`
     );
   }
   ```

   ਅਸਫਲਤਾ ਹੋਣ ਉੱਤੇ, `proxyFetch.ts` ਤਰੁੱਟੀ ਨੂੰ `code = "PROXY_FAMILY_UNAVAILABLE"` ਅਤੇ `statusCode = 503` ਨਾਲ ਟੈਗ ਕਰਦਾ ਹੈ। DNS ਰੈਜ਼ੋਲਿਊਸ਼ਨ ਦੀ ਅਸਫਲਤਾ ਨੂੰ ਵੀ ਇਸੇ ਤਰ੍ਹਾਂ fail-closed ਮੰਨਿਆ ਜਾਂਦਾ ਹੈ (ਈਗ੍ਰੈੱਸ ਕਰਨ ਤੋਂ ਇਨਕਾਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ)।

DNS ਪ੍ਰੀ-ਫਲਾਈਟ ਲਈ IP-ਲਿਟਰਲ ਹੋਸਟਾਂ ਉੱਤੇ ਕੋਈ ਕਾਰਵਾਈ ਨਹੀਂ ਹੁੰਦੀ — ਉਨ੍ਹਾਂ ਦੀ ਫੈਮਿਲੀ ਅੰਦਰੂਨੀ ਤੌਰ ਉੱਤੇ ਨਿਰਧਾਰਤ ਹੁੰਦੀ ਹੈ ਅਤੇ ਕਿਸੇ ਲੁੱਕਅੱਪ ਦੀ ਲੋੜ ਨਹੀਂ ਹੁੰਦੀ।

## ਡਾਟਾ ਮਾਡਲ

`family` ਕਾਲਮ ਨੂੰ ਮਾਈਗ੍ਰੇਸ਼ਨ `099_proxy_family.sql` ਰਾਹੀਂ **ਦੋ** ਟੇਬਲਾਂ ਵਿੱਚ ਜੋੜਿਆ ਗਿਆ ਸੀ:

```sql
-- src/lib/db/migrations/099_proxy_family.sql
ALTER TABLE proxy_registry ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
ALTER TABLE upstream_proxy_config ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
```

- `proxy_registry.family` — ਰਜਿਸਟਰੀ ਐਂਟਰੀਆਂ ਲਈ ਪ੍ਰਤੀ-ਪ੍ਰਾਕਸੀ ਨਿਰਦੇਸ਼ (`src/lib/db/proxies.ts`)। ਰਿਜ਼ੋਲਿਊਸ਼ਨ ਕਵੇਰੀਆਂ ਹੋਰ ਪ੍ਰਾਕਸੀ ਕਾਲਮਾਂ ਦੇ ਨਾਲ `family` ਨੂੰ ਵੀ ਚੁਣਦੀਆਂ ਹਨ, ਅਤੇ ਗੁੰਮ ਜਾਂ ਗੈਰ-ਸਟ੍ਰਿੰਗ ਮੁੱਲ ਨੂੰ `"auto"` ਵਿੱਚ ਬਦਲ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ।
- `upstream_proxy_config.family` — ਅੱਪਸਟ੍ਰੀਮ-ਪ੍ਰਾਕਸੀ ਐਂਟਰੀਆਂ ਲਈ ਨਿਰਦੇਸ਼ (`src/lib/db/upstreamProxy.ts`), ਉਸੇ `"auto"` ਡਿਫੌਲਟ ਦੇ ਨਾਲ।

ਜਦੋਂ ਇੱਕ ਰਿਜ਼ੋਲਵ ਕੀਤਾ ਪ੍ਰਾਕਸੀ ਆਬਜੈਕਟ ਗੈਰ-`auto` `family` ਰੱਖਦਾ ਹੈ, ਤਾਂ `proxyConfigToUrl`, `?family=` ਮਾਰਕਰ ਜੋੜਦਾ ਹੈ ਤਾਂ ਜੋ ਪਿੰਨ ਡਿਸਪੈਚਰ ਤੱਕ ਪੂਰੇ ਰਸਤੇ ਕਾਇਮ ਰਹੇ।
