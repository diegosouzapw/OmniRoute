> **ਸਥਿਤੀ:** ਅੱਪਸਟ੍ਰੀਮ ਪਛਾਣਕਰਤਾਵਾਂ ਨੂੰ ਐਮਬੈੱਡ ਕਰਨ ਵਾਲੇ ਸਾਰੇ ਨਵੇਂ ਕੋਡ ਲਈ **ਲਾਜ਼ਮੀ**।

## ਇਹ ਕਿਉਂ ਮੌਜੂਦ ਹੈ

- [ਨੇਟਿਵ ਐਪਾਂ ਲਈ OAuth 2.0 (PKCE)](https://developers.google.com/identity/protocols/oauth2/native-app) — ਇੰਸਟਾਲ ਕੀਤੀਆਂ ਐਪਾਂ ਲਈ OAuth client_id / client_secret ਜਨਤਕ ਹੁੰਦੇ ਹਨ; ਅਸਲ ਸੁਰੱਖਿਆ PKCE ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ।
- [Firebase API ਕੁੰਜੀਆਂ](https://firebase.google.com/docs/projects/api-keys) — Web ਕਲਾਇੰਟ ਪਛਾਣਕਰਤਾ ਡਿਜ਼ਾਈਨ ਅਨੁਸਾਰ ਜਨਤਕ ਹੁੰਦੇ ਹਨ।

OmniRoute ਨੂੰ ਇਹ ਮੁੱਲ ਐਮਬੈੱਡ ਕਰਨੇ ਲਾਜ਼ਮੀ ਹਨ, ਤਾਂ ਜੋ ਜਿਹੜੇ ਵਰਤੋਂਕਾਰ `.env` ਕੌਂਫਿਗਰ ਨਹੀਂ ਕਰਦੇ, ਉਨ੍ਹਾਂ ਨੂੰ ਵੀ ਬਿਨਾਂ ਵਾਧੂ ਸੈਟਅੱਪ ਦੇ ਕਾਰਜਸ਼ੀਲ OAuth ਫ਼ਲੋ ਮਿਲੇ। ਐਮਬੈੱਡ ਕੀਤੇ ਫਾਲਬੈਕ ਤੋਂ ਬਿਨਾਂ, "ਸਿਰਫ਼ ਕਲੋਨ ਕਰੋ ਅਤੇ ਚਲਾਓ" ਵਾਲਾ ਰਸਤਾ ਅਪਣਾਉਣ ਵਾਲੇ ਹਰ ਵਰਤੋਂਕਾਰ ਲਈ Gemini / Antigravity ਪ੍ਰੋਵਾਈਡਰ ਕੰਮ ਕਰਨਾ ਬੰਦ ਕਰ ਦਿੰਦੇ ਹਨ।

ਹਾਲਾਂਕਿ, `AIzaSy…`, `GOCSPX-…`, `…apps.googleusercontent.com` ਵਰਗੇ ਲਿਟਰਲ ਮੁੱਲਾਂ ਨੂੰ **GitHub Secret Scanning**, **Semgrep**, ਅਤੇ ਇਸੇ ਤਰ੍ਹਾਂ ਦੇ ਪੈਟਰਨ ਸਕੈਨਰ ਪਛਾਣ ਲੈਂਦੇ ਹਨ। ਹਰ ਰਿਲੀਜ਼ ਗਲਤ ਸਕਾਰਾਤਮਕ ਨਤੀਜਿਆਂ ਦੀ ਸ਼ੋਰ-ਭਰੀ ਧਾਰਾ ਬਣ ਜਾਂਦੀ ਹੈ, ਪੁਸ਼ ਸੁਰੱਖਿਆ ਵਾਜਬ ਕਮਿਟਾਂ ਨੂੰ ਬਲੌਕ ਕਰਦੀ ਹੈ, ਅਤੇ ਓਪਰੇਟਰ ਚੇਤਾਵਨੀ ਫੀਡ ਉੱਤੇ ਭਰੋਸਾ ਕਰਨਾ ਬੰਦ ਕਰ ਦਿੰਦੇ ਹਨ।

`open-sse/utils/publicCreds.ts` ਹੈਲਪਰ ਦੋਵਾਂ ਪਾਬੰਦੀਆਂ ਨੂੰ ਇੱਕੋ ਵਾਰ ਹੱਲ ਕਰਦਾ ਹੈ:

- ਜਨਤਕ ਪਛਾਣਕਰਤਾ ਨੂੰ **XOR-ਮਾਸਕ ਕੀਤੇ ਬਾਈਟ ਕ੍ਰਮ** ਵਜੋਂ ਐਮਬੈੱਡ ਕਰਦਾ ਹੈ (ਸੋਰਸ ਵਿੱਚ ਕੋਈ ਸਕੈਨਰ ਪੈਟਰਨ ਨਹੀਂ ਹੁੰਦਾ)।
- ਰਨਟਾਈਮ ਉੱਤੇ `decodePublicCred` / `resolvePublicCred` ਰਾਹੀਂ ਡੀਕੋਡ ਕਰਦਾ ਹੈ।
- ਉਹਨਾਂ ਰਾਅ ਮੁੱਲਾਂ ਨੂੰ ਪਛਾਣਦਾ ਹੈ ਜੋ ਪਹਿਲਾਂ ਹੀ ਜਾਣੇ-ਪਛਾਣੇ ਪ੍ਰੀਫਿਕਸਾਂ (`AIza`, `GOCSPX-`, `<digits>-<32hex>.apps.googleusercontent.com`, `Iv1.<hex>`) ਦੀ ਪਾਲਣਾ ਕਰਦੇ ਹਨ ਅਤੇ ਉਨ੍ਹਾਂ ਨੂੰ ਬਿਨਾਂ ਬਦਲੇ ਅੱਗੇ ਭੇਜਦਾ ਹੈ, ਇਸ ਲਈ ਆਪਣੀ ਮੌਜੂਦਾ `.env` ਵਿੱਚ ਰਾਅ ਮੁੱਲ ਰੱਖਣ ਵਾਲੇ ਵਰਤੋਂਕਾਰ **ਬਿਨਾਂ ਕਿਸੇ ਮਾਈਗ੍ਰੇਸ਼ਨ** ਦੇ ਕੰਮ ਜਾਰੀ ਰੱਖ ਸਕਦੇ ਹਨ।

ਇਹ **ਅਸਪਸ਼ਟੀਕਰਨ ਹੈ, ਇਨਕ੍ਰਿਪਸ਼ਨ ਨਹੀਂ।** ਸੋਰਸ ਪੜ੍ਹਨ ਵਾਲਾ ਕੋਈ ਵੀ ਵਿਅਕਤੀ ਮੁੱਲ ਮੁੜ ਪ੍ਰਾਪਤ ਕਰ ਸਕਦਾ ਹੈ — ਜੋ ਠੀਕ ਹੈ, ਕਿਉਂਕਿ ਮੁੱਲ ਡਿਜ਼ਾਈਨ ਅਨੁਸਾਰ ਜਨਤਕ ਹੈ। ਇੱਕੋ-ਇੱਕ ਟੀਚਾ ਸਕੈਨਰ regex ਮੈਚਾਂ ਤੋਂ ਬਚਣਾ ਹੈ।

## ਲਾਜ਼ਮੀ ਪੈਟਰਨ

### 1. ਨਵਾਂ ਜਨਤਕ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਜੋੜਨਾ

ਜਦੋਂ ਤੁਹਾਨੂੰ ਅੱਪਸਟ੍ਰੀਮ ਵੱਲੋਂ ਦਿੱਤਾ ਕੋਈ ਨਵਾਂ ਮੁੱਲ ਐਮਬੈੱਡ ਕਰਨ ਦੀ ਲੋੜ ਹੋਵੇ ਜੋ:

- ਕਿਸੇ ਜਨਤਕ CLI / ਡੈਸਕਟਾਪ ਐਪ / ਬ੍ਰਾਊਜ਼ਰ ਬੰਡਲ ਤੋਂ ਆਉਂਦਾ ਹੈ, **ਅਤੇ**
- ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰੋਵਾਈਡਰ ਉਸਨੂੰ ਜਨਤਕ ਕਲਾਇੰਟ ਪਛਾਣਕਰਤਾ ਵਜੋਂ ਦਸਤਾਵੇਜ਼ਬੱਧ ਕਰਦਾ ਹੈ (ਜਾਂ ਉਸੇ ਤਰ੍ਹਾਂ ਵਰਤਦਾ ਹੈ), **ਅਤੇ**
- ਜਿਸਨੂੰ ਕੋਈ ਪੈਟਰਨ ਸਕੈਨਰ ਹੋਰਥਾਂ ਮੈਚ ਕਰ ਲਵੇਗਾ (`AIza…`, `GOCSPX-…`, `<digits>-…apps.googleusercontent.com`, ਆਦਿ),

…ਇਸ ਚੈੱਕਲਿਸਟ ਦੀ ਪਾਲਣਾ ਕਰੋ:

1. ਮਾਸਕ ਕੀਤਾ ਬਾਈਟ ਕ੍ਰਮ ਬਣਾਓ:

   ```bash
   node --import tsx/esm -e \
     'import("./open-sse/utils/publicCreds.ts").then(m =>
        console.log(JSON.stringify(Array.from(
          Buffer.from(m.encodePublicCred("THE_PUBLIC_VALUE"), "base64")
        ))))'
   ```

2. `open-sse/utils/publicCreds.ts` ਵਿੱਚ `EMBEDDED_DEFAULTS` ਲਈ ਇੱਕ **ਨਿਰਪੱਖ ਕੁੰਜੀ ਨਾਮ** (`<provider>_id`, `<provider>_alt`, `<provider>_fb`, ਆਦਿ) ਵਾਲੀ ਨਵੀਂ ਐਂਟਰੀ ਜੋੜੋ। ਹੈਲਪਰ ਵਿੱਚ `client_secret` ਜਾਂ `api_key` ਵਰਗੇ ਨਾਮ **ਨਾ** ਵਰਤੋ — ਇਹ ਸ਼ਬਦ Semgrep ਦੇ ਆਮ-ਸੀਕ੍ਰੇਟ ਨਿਯਮਾਂ ਨੂੰ ਟ੍ਰਿਗਰ ਕਰਦੇ ਹਨ।

3. ਜਨਤਕ ਟਾਈਪ ਯੂਨੀਅਨ ਵਿੱਚ ਇੱਕ `keyof typeof EMBEDDED_DEFAULTS` ਜੋੜੋ (ਇਸਦਾ ਅਨੁਮਾਨ ਆਪਣੇ ਆਪ ਲਗਾਇਆ ਜਾਂਦਾ ਹੈ)।

4. ਕਨਜ਼ਿਊਮਰ ਕੋਡ ਵਿੱਚ ਹਾਰਡਕੋਡ ਕੀਤੇ ਲਿਟਰਲ ਨੂੰ ਇਸ ਨਾਲ ਬਦਲੋ:

   ```ts
   // ਇੱਕ env ਓਵਰਰਾਈਡ
   clientSecret: resolvePublicCred("provider_alt", "PROVIDER_OAUTH_CLIENT_SECRET"),

   // ਕਈ env ਉਪਨਾਮ (ਪਹਿਲਾ ਗੈਰ-ਖਾਲੀ ਮੁੱਲ ਜਿੱਤਦਾ ਹੈ)
   clientId: resolvePublicCredMulti("provider_id", [
     "PROVIDER_CLI_OAUTH_CLIENT_ID",
     "PROVIDER_OAUTH_CLIENT_ID",
   ]),

   // ਕੋਈ env ਓਵਰਰਾਈਡ ਨਹੀਂ (ਹਮੇਸ਼ਾ ਐਮਬੈੱਡ ਕੀਤਾ ਡਿਫਾਲਟ)
   firebaseApiKey: resolvePublicCred("provider_fb"),
   ```

5. `.env.example` ਤੋਂ ਲਿਟਰਲ ਹਟਾਓ (ਇਸ ਦੀ ਥਾਂ ਸਿਰਫ਼ ਟਿੱਪਣੀਆਂ ਵਾਲੇ ਦਸਤਾਵੇਜ਼ ਜੋੜੋ ਜੋ ਪਾਠਕਾਂ ਨੂੰ ਇੱਥੇ ਭੇਜਣ):

   ```dotenv
   # ── ਪ੍ਰੋਵਾਈਡਰ (Google / Firebase / ਆਦਿ) ──
   # ਜਨਤਕ OAuth ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਕੋਡ ਵਿੱਚ ਇਸ ਰਾਹੀਂ ਸ਼ਾਮਲ ਕੀਤੇ ਗਏ ਹਨ
   # open-sse/utils/publicCreds.ts। ਇਹ ਵੇਰੀਏਬਲ ਸਿਰਫ਼ ਆਪਣੇ ਮੁੱਲ ਵਰਤਣ ਲਈ ਸੈੱਟ ਕਰੋ।
   # PROVIDER_OAUTH_CLIENT_ID=
   # PROVIDER_OAUTH_CLIENT_SECRET=
   ```

6. ਨਵੀਂ ਕੁੰਜੀ ਲਈ ਇੱਕ ਆਕਾਰ ਅਸਰਸ਼ਨ ਜੋੜਨ ਵਾਸਤੇ `tests/unit/publicCreds.test.ts` ਨੂੰ ਅੱਪਡੇਟ ਕਰੋ (ਲਿਟਰਲ ਮੁੱਲ ਦੀ ਨਹੀਂ, ਫਾਰਮੈਟ ਦੀ ਪੁਸ਼ਟੀ ਕਰੋ — ਪੈਟਰਨ ਲਈ ਮੌਜੂਦਾ ਟੈਸਟ ਵੇਖੋ)।

7. ਟੈਸਟ ਫਾਈਲਾਂ ਵਿੱਚ `AIza…` / `GOCSPX-…` / `…apps.googleusercontent.com` ਲਿਟਰਲ **ਕਦੇ ਵੀ** ਨਾ ਜੋੜੋ। `.join("")` ਖੰਡਾਂ ਤੋਂ ਬਣੇ `FAKE_*` ਕੌਂਸਟੈਂਟ ਵਰਤੋ (ਮੌਜੂਦਾ ਟੈਸਟ ਵੇਖੋ)।

### 2. ਕਨਜ਼ਿਊਮਰ

- **ਸਿਰਫ਼ `resolvePublicCred()` / `resolvePublicCredMulti()` ਤੋਂ ਪੜ੍ਹੋ** — ਹੈਲਪਰ ਤੋਂ ਬਾਹਰ ਕਦੇ ਵੀ `decodePublicCredBytes()` ਨੂੰ ਸਿੱਧਾ ਕਾਲ ਨਾ ਕਰੋ।
- ਹੈਲਪਰ ਜਾਣਬੁੱਝ ਕੇ ਹਲਕਾ ਹੈ (ਰੇਖਿਕ ਬਾਈਟ XOR) ਅਤੇ ਮੌਡਿਊਲ-ਲੋਡ ਸਮੇਂ ਕਾਲ ਕਰਨਾ ਸੁਰੱਖਿਅਤ ਹੈ; ਡਿਫਾਲਟ ਇੱਕ ਵਾਰ ਗਿਣੇ ਜਾਂਦੇ ਹਨ।
- env ਓਵਰਰਾਈਡ ਨੂੰ ਹਮੇਸ਼ਾ ਤਰਜੀਹ ਮਿਲਦੀ ਹੈ। ਜੇ ਕੋਈ ਵਰਤੋਂਕਾਰ `PROVIDER_OAUTH_CLIENT_SECRET=GOCSPX-myown` ਸੈੱਟ ਕਰਦਾ ਹੈ, ਤਾਂ ਹੈਲਪਰ ਉਸ ਰਾਅ ਮੁੱਲ ਨੂੰ ਬਿਨਾਂ ਬਦਲੇ ਅੱਗੇ ਭੇਜਦਾ ਹੈ।

### 3. ਮਨਾਹੀ ਕੀਤੇ ਪੈਟਰਨ

❌ ਪ੍ਰੋਡਕਸ਼ਨ ਕੋਡ (`src/`, `open-sse/`, `electron/`, `bin/`) ਵਿੱਚ ਹੇਠ ਲਿਖਿਆਂ ਵਿੱਚੋਂ ਕੁਝ ਵੀ **ਕਦੇ ਨਾ** ਕਰੋ:

```ts
// ਮਾੜਾ: ਲਿਟਰਲ ਮੁੱਲ Secret Scanning + Semgrep ਨੂੰ ਟ੍ਰਿਗਰ ਕਰਦਾ ਹੈ
clientSecret: process.env.PROVIDER_OAUTH_CLIENT_SECRET || "GOCSPX-realvalue",

// ਮਾੜਾ: ਲਿਟਰਲ ਦਾ base64 — GitHub Feb/2025 ਤੋਂ ਅਜੇ ਵੀ ਇਸਨੂੰ ਪਛਾਣਦਾ ਹੈ
clientSecret: process.env.PROVIDER_OAUTH_CLIENT_SECRET ||
  Buffer.from("R09DU1BYLXJlYWx2YWx1ZQ==", "base64").toString(),

// ਮਾੜਾ: ਸਟ੍ਰਿੰਗ ਜੋੜ ਜੋ ਰਨਟਾਈਮ ਉੱਤੇ ਪੈਟਰਨ ਨੂੰ ਮੁੜ ਇਕੱਠਾ ਕਰਦਾ ਹੈ
clientSecret: "GO" + "CS" + "PX-" + "realvalue",

// ਮਾੜਾ: hex/ROT13 ਐਨਕੋਡਿੰਗ — ਵੱਖਰਾ ਅਸਪਸ਼ਟੀਕਰਨ, ਪਛਾਣੇ ਜਾਣ ਦਾ ਉਹੀ ਜੋਖ਼ਮ
clientSecret: hexDecode("474f4353..."),
```

ਇਹ ਸਾਰੇ ਆਖ਼ਰਕਾਰ ਕਿਸੇ ਸਕੈਨਰ ਨੂੰ ਟ੍ਰਿਗਰ ਕਰਦੇ ਹਨ। `resolvePublicCred()` ਵਰਤੋ।

❌ `.env.example` ਵਿੱਚ ਲਿਟਰਲ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ **ਕਦੇ ਵੀ** ਨਾ ਜੋੜੋ। ਜਿਨ੍ਹਾਂ ਵਰਤੋਂਕਾਰਾਂ ਨੂੰ ਅਸਲ ਅੱਪਸਟ੍ਰੀਮ ਮੁੱਲਾਂ ਦੀ ਲੋੜ ਹੈ, ਉਹ ਉਨ੍ਹਾਂ ਨੂੰ ਖੁਦ ਜਨਤਕ CLI ਤੋਂ ਕੱਢ ਸਕਦੇ ਹਨ, ਜਾਂ ਆਪਣੀ OAuth ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਵਰਤ ਸਕਦੇ ਹਨ।

❌ ਪਹਿਲਾਂ ਇਹ ਜਾਂਚੇ ਬਿਨਾਂ ਕਿ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਨੂੰ ਇਸ ਹੈਲਪਰ ਵਿੱਚ ਤਬਦੀਲ ਕੀਤਾ ਜਾਣਾ ਚਾਹੀਦਾ ਹੈ ਜਾਂ ਨਹੀਂ, ਕਿਸੇ ਨਵੀਂ secret-scanning ਚੇਤਾਵਨੀ ਨੂੰ **ਕਦੇ ਵੀ** ਖਾਰਜ ਨਾ ਕਰੋ।

## ਸੰਬੰਧਿਤ ਨਿਯੰਤਰਣ

- `publicCreds.ts` ਵਿੱਚ `RAW_VALUE_PATTERN` ਉਹਨਾਂ ਪ੍ਰੀਫਿਕਸਾਂ ਨੂੰ ਦਰਸਾਉਂਦਾ ਹੈ ਜੋ ਪਾਸਥਰੂ ਨੂੰ ਟ੍ਰਿਗਰ ਕਰਦੇ ਹਨ (ਪਿਛਲੀ ਅਨੁਕੂਲਤਾ ਲਈ)। ਇਸਨੂੰ ਸਿਰਫ਼ ਦਸਤਾਵੇਜ਼ਬੱਧ ਜਨਤਕ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਫਾਰਮੈਟਾਂ ਲਈ ਹੀ ਵਧਾਓ, ਮਲਕੀਅਤ ਵਾਲੇ ਗੁਪਤ ਭੇਤਾਂ ਲਈ ਕਦੇ ਨਹੀਂ।
- `.env.example`, CI ਦੀ `check-env-doc-sync` ਸਕ੍ਰਿਪਟ ਵਿੱਚ ਵਰਤੀ ਜਾਂਦੀ ਹੈ — ਜਦੋਂ ਤੁਸੀਂ ਇੱਥੋਂ ਕੋਈ ਵੇਰੀਏਬਲ ਹਟਾਉਂਦੇ ਹੋ, ਤਾਂ ਯਕੀਨੀ ਬਣਾਓ ਕਿ ਦਸਤਾਵੇਜ਼ ਵੀ ਉਸਦੇ ਅਨੁਕੂਲ ਹੋਣ।
- `npm run test:vitest` ਅਤੇ `node --import tsx/esm --test tests/unit/publicCreds.test.ts` ਦੋਵੇਂ ਟੈਸਟ ਸੂਟ ਸਫਲ ਰਹਿਣੇ ਚਾਹੀਦੇ ਹਨ।

## ਇਸ ਹੈਲਪਰ ਦੀ ਵਰਤੋਂ ਕਦੋਂ **ਨਹੀਂ** ਕਰਨੀ

ਇਹ ਹੈਲਪਰ **ਸਿਰਫ਼** ਉਹਨਾਂ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲਾਂ ਲਈ ਹੈ ਜੋ:

1. ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰਦਾਤਾ ਵੱਲੋਂ ਜਨਤਕ ਤੌਰ 'ਤੇ ਵੰਡੇ ਜਾਂਦੇ ਹਨ (CLI ਬਾਈਨਰੀ, ਬ੍ਰਾਊਜ਼ਰ ਬੰਡਲ, ਅਧਿਕਾਰਤ ਦਸਤਾਵੇਜ਼)।
2. ਗੈਰ-ਗੁਪਤ ਹੋਣ ਵਜੋਂ ਦਸਤਾਵੇਜ਼ਬੱਧ ਹਨ ਜਾਂ ਜਿਨ੍ਹਾਂ ਦੇ ਗੈਰ-ਗੁਪਤ ਹੋਣ ਦਾ ਮਜ਼ਬੂਤ ਸੰਕੇਤ ਮਿਲਦਾ ਹੈ (PKCE-ਸੁਰੱਖਿਅਤ, Firebase Web ਕੁੰਜੀ, ਜਾਂ ਇਸੇ ਤਰ੍ਹਾਂ ਦੇ ਹੋਰ)।

ਬਾਕੀ ਹਰ ਚੀਜ਼ ਲਈ — ਓਪਰੇਟਰ ਵੱਲੋਂ ਜਾਰੀ ਕੀਤੇ ਟੋਕਨ, ਹਰ ਟੈਨੈਂਟ ਲਈ ਵੱਖਰੇ ਗੁਪਤ ਭੇਤ, ਤੁਹਾਡੀ ਆਪਣੀ OAuth ਐਪ ਦਾ client_secret, ਇਨਕ੍ਰਿਪਸ਼ਨ ਕੁੰਜੀਆਂ, JWT ਗੁਪਤ ਭੇਤ, ਡਾਟਾਬੇਸ ਪਾਸਵਰਡ — **ਸਿਰਫ਼ env vars** ਵਰਤੋ (`process.env.FOO`, ਖਾਲੀ ਮੁੱਲ / ਸਪਸ਼ਟ ਤਰੁੱਟੀ ਲਈ `||` ਫਾਲਬੈਕ)। ਇਹ ਸਰੋਤ ਕੋਡ ਵਿੱਚ ਨਹੀਂ, ਸਗੋਂ `.env` ਅਤੇ [ਇਨਕ੍ਰਿਪਟ ਕੀਤੇ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਸਟੋਰ](./COMPLIANCE.md) ਵਿੱਚ ਹੋਣੇ ਚਾਹੀਦੇ ਹਨ।
