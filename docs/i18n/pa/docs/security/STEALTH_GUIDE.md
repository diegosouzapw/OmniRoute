OmniRoute ਉਹਨਾਂ ਪ੍ਰਦਾਤਾਵਾਂ ਨਾਲ ਏਕੀਕ੍ਰਿਤ ਹੁੰਦਾ ਹੈ ਜਿਨ੍ਹਾਂ ਦੇ ਐਜ ਗੈਰ-ਅਧਿਕਾਰਤ ਕਲਾਇੰਟਾਂ ਦੀ ਸਰਗਰਮੀ ਨਾਲ ਫਿੰਗਰਪ੍ਰਿੰਟਿੰਗ ਕਰਦੇ ਹਨ (TLS JA3/JA4, ਹੈਡਰ ਕ੍ਰਮ, JSON ਬਾਡੀ ਆਕਾਰ, ਇੰਟੀਗ੍ਰਿਟੀ ਟੋਕਨ)। ਇਹ ਪੰਨਾ ਉਹਨਾਂ ਸਟੀਲਥ ਸਤਹਾਂ ਦਾ ਦਸਤਾਵੇਜ਼ੀਕਰਨ ਕਰਦਾ ਹੈ ਜੋ OmniRoute ਉਪਲਬਧ ਕਰਵਾਉਂਦਾ ਹੈ ਅਤੇ ਦੱਸਦਾ ਹੈ ਕਿ ਉਹ ਕਿੱਥੇ ਲਾਗੂ ਕੀਤੀਆਂ ਗਈਆਂ ਹਨ।

## ਕਾਨੂੰਨੀ ਅਤੇ ਨੈਤਿਕ ਸੂਚਨਾ

ਸਟੀਲਥ ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ ਇਸ ਲਈ ਮੌਜੂਦ ਹਨ ਤਾਂ ਜੋ OmniRoute ਵਰਤੋਂਕਾਰ ਦੀ ਮਲਕੀਅਤ ਵਾਲੇ ਅਧਿਕਾਰਤ ਖਾਤਿਆਂ (Claude Code CLI, Codex, Antigravity, Cursor, ਆਦਿ) ਅਤੇ OmniRoute ਦੀ ਏਕੀਕ੍ਰਿਤ API ਵਿਚਕਾਰ ਅਨੁਕੂਲਤਾ ਪਰਤ ਵਜੋਂ ਕੰਮ ਕਰ ਸਕੇ। ਇਹ ਧੋਖਾਧੜੀ ਖੋਜ ਤੋਂ ਬਚਣ, ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਸਾਂਝੇ ਕਰਨ, ਜਾਂ ਪ੍ਰਦਾਤਾ ਦੀਆਂ ਸੇਵਾ ਸ਼ਰਤਾਂ ਦੀ ਉਲੰਘਣਾ ਕਰਨ ਲਈ **ਨਹੀਂ** ਹਨ। ਸੰਭਾਲਕਾਂ ਦੀ ਉਮੀਦ ਹੈ ਕਿ ਆਪਰੇਟਰ ਖਾਤੇ ਬਣਾਉਂਦੇ ਸਮੇਂ ਸਵੀਕਾਰ ਕੀਤੀਆਂ ਅੱਪਸਟ੍ਰੀਮ ToS ਦੀ ਪਾਲਣਾ ਕਰਨਗੇ।

## TLS ਫਿੰਗਰਪ੍ਰਿੰਟਿੰਗ ਪਰਤ

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

ਸਥਾਈ `wreq-js` ਸੈਸ਼ਨ ਹਰ ਖਾਤਾ ਸਕੋਪ ਅਤੇ ਰਿਜ਼ਾਲਵ ਕੀਤੀ ਪ੍ਰੌਕਸੀ ਲਈ ਲੋੜ ਪੈਣ 'ਤੇ ਬਣਾਏ ਜਾਂਦੇ ਹਨ। ਪ੍ਰਕਿਰਿਆ-ਵਿਆਪੀ `TlsClient` ਵੱਧ ਤੋਂ ਵੱਧ 128 ਸੈਸ਼ਨਾਂ ਨੂੰ ਪੂਲ ਕਰਦਾ ਹੈ, ਜੋ Cloudflare ਦੇ ਪਿੱਛੇ ਮੌਜੂਦ ਅੱਪਸਟ੍ਰੀਮਾਂ ਲਈ **macOS ਉੱਤੇ Chrome 124** ਦੀ ਨਕਲ ਕਰਦੇ ਹਨ। ਜਦੋਂ ਨੇਟਿਵ ਰਨਟਾਈਮ ਉਪਲਬਧ ਨਾ ਹੋਵੇ ਤਾਂ `TlsClient.fetch()` ਫੇਲ-ਕਲੋਜ਼ਡ ਹੁੰਦਾ ਹੈ; ਕਾਲਰ ਇਸ ਰੈਪਰ ਤੋਂ ਬਾਹਰ ਸਪਸ਼ਟ ਤੌਰ 'ਤੇ ਫਾਲਬੈਕ ਚੁਣ ਸਕਦਾ ਹੈ।

- ਸੈਸ਼ਨ ਪ੍ਰੋਫਾਈਲ: `browser: "chrome_124", os: "macos"`
- ਪ੍ਰੌਕਸੀ ਰਿਜ਼ੋਲਿਊਸ਼ਨ (ਤਰਜੀਹ): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (ਲੋਅਰ-ਕੇਸ ਵੀ)
- ਟਾਈਮਆਉਟ: `TLS_CLIENT_TIMEOUT_MS` (`FETCH_TIMEOUT_MS` ਤੋਂ ਵਿਰਾਸਤ ਵਿੱਚ ਮਿਲਦਾ ਹੈ, ਡਿਫਾਲਟ 600000)
- `wreq-js` Response fetch-ਅਨੁਕੂਲ ਹੈ (`headers`, `text()`, `json()`, `clone()`, `body`)।
- ਪਹਿਲੀ-ਬਾਈਟ ਵਾਚਡੌਗ (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656): `TlsClient.fetch()`
  ਅੱਪਸਟ੍ਰੀਮ ਹੈਡਰ ਪਹੁੰਚਦੇ ਹੀ ਰਿਜ਼ਾਲਵ ਹੋ ਜਾਂਦਾ ਹੈ, ਇਸ ਲਈ ਇਕੱਲਾ `TLS_CLIENT_TIMEOUT_MS` ਅਜਿਹੀ
  ਬਾਡੀ ਨੂੰ ਸੀਮਿਤ ਨਹੀਂ ਕਰ ਸਕਦਾ ਜੋ ਕਦੇ ਪਹਿਲੀ ਬਾਈਟ ਨਾ ਦੇਵੇ। `guardTlsFirstByte()` ਬਾਡੀ ਦੇ ਪਹਿਲੇ `read()`
  ਦਾ `TLS_FIRST_BYTE_WATCHDOG_MS` (ਡਿਫਾਲਟ `10000`, `0` ਇਸਨੂੰ ਅਯੋਗ ਕਰਦਾ ਹੈ) ਨਾਲ ਰੇਸ ਕਰਵਾਉਂਦਾ ਹੈ; ਇੱਕ ਸਿਹਤਮੰਦ ਬਾਡੀ
  ਪ੍ਰਭਾਵਿਤ ਨਹੀਂ ਹੁੰਦੀ, ਜਦਕਿ ਰੁਕੀ ਹੋਈ ਬਾਡੀ wreq ਰੀਡਰ ਨੂੰ ਰੱਦ ਕਰਦੀ ਹੈ ਅਤੇ `proxyFetch` ਦੇ ਮੌਜੂਦਾ
  TLS-ਫਾਲਬੈਕ ਤਰਕ ਨੂੰ ਡਾਇਰੈਕਟ/ਪ੍ਰੌਕਸੀ ਡਿਸਪੈਚਰ ਤੱਕ ਅੱਗੇ ਵਧਣ ਦਿੰਦੀ ਹੈ (ਇੱਕ ਗੈਰ-ਰੀਪਲੇ-ਸੁਰੱਖਿਅਤ ਬੇਨਤੀ, ਜਿਵੇਂ
  ਬਾਡੀ ਵਾਲੀ POST, ਚੁੱਪਚਾਪ ਮੁੜ ਕੋਸ਼ਿਸ਼ ਕੀਤੇ ਜਾਣ ਦੀ ਬਜਾਏ ਫਿਰ ਵੀ ਤਰੁੱਟੀ ਦਿੰਦੀ ਹੈ)।

### ਵੈੱਬ-ਕੁਕੀ ਪ੍ਰਦਾਤਾ ਟ੍ਰਾਂਸਪੋਰਟ — wreq-js 3.2.0

`open-sse/services/tlsClientBase.ts` ਹੇਠਾਂ ਦਿੱਤੇ ਪੰਜ ਵਿਸ਼ੇਸ਼
ਵੈੱਬ-ਕੁਕੀ ਟ੍ਰਾਂਸਪੋਰਟਾਂ ਲਈ ਸਾਂਝਾ ਅਡੈਪਟਰ ਹੈ। ਹਰ ਪਤਲਾ ਪ੍ਰਦਾਤਾ ਰੈਪਰ ਇੱਕ ਬ੍ਰਾਊਜ਼ਰ/OS ਪ੍ਰੋਫਾਈਲ ਚੁਣਦਾ ਹੈ। ਅਡੈਪਟਰ
`open-sse/utils/tlsClient.ts` ਵਿੱਚ ਮੌਜੂਦ ਇਕੱਲੇ wreq ਰਨਟਾਈਮ ਲੋਡਰ ਅਤੇ ਟ੍ਰਾਂਸਪੋਰਟ ਪੂਲ ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ, ਜਿਸਨੂੰ
ਪ੍ਰੋਫਾਈਲ + OS + ਰਿਜ਼ਾਲਵ ਕੀਤੀ ਪ੍ਰੌਕਸੀ ਅਨੁਸਾਰ ਕੀ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਜਦਕਿ ਹਰ ਬੇਨਤੀ `cookieMode: "ephemeral"` ਵਰਤਦੀ ਹੈ। ਇਸ ਲਈ ਖਾਤੇ ਅਤੇ
ਬੇਨਤੀਆਂ ਟ੍ਰਾਂਸਪੋਰਟ-ਪੱਧਰੀ ਕਨੈਕਸ਼ਨ ਸਾਂਝੇ ਕਰਦੇ ਹਨ, ਪਰ ਕਦੇ ਵੀ wreq ਸੈਸ਼ਨ ਜਾਂ ਕੁਕੀ ਜਾਰ ਸਾਂਝਾ ਨਹੀਂ ਕਰਦੇ।

| ਪ੍ਰਦਾਤਾ    | ਪ੍ਰੋਫਾਈਲ      | ਇਮੂਲੇਟ ਕੀਤਾ OS | ਸਟ੍ਰੀਮ EOF ਨੀਤੀ                         |
| ---------- | ------------- | -------------- | --------------------------------------- |
| Claude     | `chrome_146`  | Linux          | `[DONE]` ਸ਼ਾਮਲ ਕਰੋ                      |
| Perplexity | `firefox_148` | macOS          | `event: end_of_stream` ਸ਼ਾਮਲ ਕਰੋ        |
| Grok       | `chrome_146`  | Linux          | `[DONE]` ਨੂੰ ਬਾਹਰ ਰੱਖੋ                  |
| Notion     | `chrome_146`  | Windows        | `[DONE]` ਸ਼ਾਮਲ ਕਰੋ                      |
| LMArena    | `chrome_146`  | Windows        | ਕੋਈ ਸੈਂਟੀਨਲ ਨਹੀਂ; ਨੇਟਿਵ EOF 'ਤੇ ਬੰਦ ਕਰੋ |

- ਸਟ੍ਰੀਮਿੰਗ ਨੇਟਿਵ ਰਿਸਪਾਂਸ `ReadableStream` ਨੂੰ ਸਿੱਧੇ ਵਰਤਦੀ ਹੈ; ਕੋਈ ਟੈਂਪ ਫਾਈਲ ਜਾਂ ਸਾਈਡਕਾਰ
  ਨਹੀਂ ਬਣਾਇਆ ਜਾਂਦਾ।
- ਸਟ੍ਰੀਮ ਉਪਲਬਧ ਕਰਵਾਉਣ ਤੋਂ ਪਹਿਲਾਂ ਸ਼ੁਰੂਆਤੀ 256 ਬਾਈਟਾਂ ਤੱਕ ਦੀ ਜਾਂਚ ਕੀਤੀ ਜਾਂਦੀ ਹੈ। SSE ਪ੍ਰਦਾਤਾ ਗੈਰ-SSE
  ਤਰੁੱਟੀਆਂ ਨੂੰ ਬਫਰ ਕਰਦੇ ਹਨ; Grok/LMArena Cloudflare ਚੁਣੌਤੀਆਂ ਨੂੰ `403` ਅਤੇ HTML ਇੰਟਰਸਟਿਸ਼ਲਾਂ ਨੂੰ `502` ਨਾਲ ਮੈਪ ਕਰਦੇ ਹਨ।
- ਨੇਟਿਵ ਬੇਨਤੀ ਟਾਈਮਆਉਟ ਨੂੰ ਇੱਕ ਪੂਰਨ JS ਹਾਰਡ ਡੈੱਡਲਾਈਨ ਨਾਲ ਰੈਪ ਕਰਨਾ ਜਾਰੀ ਰਹਿੰਦਾ ਹੈ। ਹੈਂਗ ਹੋਣ 'ਤੇ
  ਕੇਵਲ ਪ੍ਰਭਾਵਿਤ ਪ੍ਰੋਫਾਈਲ/OS/ਪ੍ਰੌਕਸੀ ਟ੍ਰਾਂਸਪੋਰਟ ਅਵੈਧ ਅਤੇ ਬੰਦ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਜਿਸਨੂੰ ਅਗਲੀ ਬੇਨਤੀ ਮੁੜ ਬਣਾਉਂਦੀ ਹੈ।
- ਪ੍ਰੌਕਸੀ ਰਿਜ਼ੋਲਿਊਸ਼ਨ ਤਰਜੀਹ ਪ੍ਰਤੀ-ਕਾਲ `proxyUrl` → ਬੇਨਤੀ-ਸਕੋਪ ਖਾਤਾ/ਡੈਸ਼ਬੋਰਡ ਸੰਦਰਭ →
  `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (ਲੋਅਰਕੇਸ ਰੂਪਾਂ ਸਮੇਤ) ਹੈ। ਰਿਜ਼ੋਲਿਊਸ਼ਨ ਤਰੁੱਟੀਆਂ ਡਾਇਰੈਕਟ ਕਨੈਕਸ਼ਨ ਲੀਕ ਕਰਨ ਦੀ ਬਜਾਏ
  ਫੇਲ-ਕਲੋਜ਼ਡ ਹੁੰਦੀਆਂ ਹਨ। LMArena ਜਾਣ-ਬੁੱਝ ਕੇ `arena.ai` ਦੇ ਵਿਰੁੱਧ ਰਿਜ਼ਾਲਵ ਕਰਦਾ ਹੈ।
- `byteResponse` UTF-8 ਕਰਪਸ਼ਨ ਤੋਂ ਬਿਨਾਂ ਕੰਟੈਂਟ-ਟਾਈਪ ਕੀਤਾ `data:` URL ਵਾਪਸ ਕਰਦਾ ਹੈ।
- ਤਰੁੱਟੀਆਂ `TlsClientUnavailableError` (ਪੈਕੇਜ/ਐਡਆਨ ਅਣਉਪਲਬਧ), `TlsClientHangError`
  (ਡੈੱਡਲਾਈਨ ਪਾਰ ਹੋਈ), ਅਤੇ `WreqTransportCapacityError` (ਸਾਂਝਾ ਸੈਸ਼ਨ-ਸਮਰੱਥਾ ਤਰੁੱਟੀ ਕੋਡ)
  ਹੁੰਦੀਆਂ ਹਨ, ਜਦੋਂ ਸਾਰੇ 128 ਸੀਮਿਤ ਪ੍ਰੋਫਾਈਲ/OS/ਪ੍ਰੌਕਸੀ ਸਲਾਟ ਸਰਗਰਮ ਜਾਂ ਬੰਦ ਹੋ ਰਹੇ ਹੋਣ।

ਉੱਪਰਲਾ ਆਮ `TlsClient` ਸੈਸ਼ਨ ਸਥਾਈ ਬ੍ਰਾਊਜ਼ਰ-ਸਮਰਥਿਤ ਕੁਕੀ
ਸਥਿਤੀ ਲਈ ਵਿਸ਼ੇਸ਼ ਬਣਿਆ ਰਹਿੰਦਾ ਹੈ। ਦੋਵੇਂ ਮਾਰਗ ਇੱਕ ਕੈਸ਼ ਕੀਤਾ wreq ਮੋਡੀਊਲ ਲੋਡਰ ਅਤੇ ਪ੍ਰਕਿਰਿਆ ਲਾਈਫਸਾਈਕਲ ਹੁੱਕ ਮੁੜ ਵਰਤਦੇ ਹਨ; ਉਨ੍ਹਾਂ ਦੇ ਪੂਲ
ਵੱਖਰੇ ਰਹਿੰਦੇ ਹਨ ਕਿਉਂਕਿ ਉਨ੍ਹਾਂ ਦੀਆਂ ਕੁਕੀ ਆਯੂਆਂ ਜਾਣ-ਬੁੱਝ ਕੇ ਵੱਖਰੀਆਂ ਹਨ।

ਪ੍ਰੋਫਾਈਲਾਂ ਨੂੰ ਪਿੰਨ ਕੀਤੇ ਪੈਕੇਜ ਵੱਲੋਂ ਸਮਰਥਨ ਪ੍ਰਾਪਤ ਹੈ, ਪਰ ਅਸਲ WAF ਸਵੀਕ੍ਰਿਤੀ ਸਥਾਨਕ
ਕਾਂਟ੍ਰੈਕਟ ਟੈਸਟਾਂ ਤੋਂ ਸੁਤੰਤਰ ਤੌਰ 'ਤੇ ਬਦਲ ਸਕਦੀ ਹੈ। ਅੱਪਸਟ੍ਰੀਮ ਬ੍ਰਾਊਜ਼ਰ ਨਾਲ ਸਮਾਨਤਾ ਦਾ ਦਾਅਵਾ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ
ਸਪਸ਼ਟ ਤੌਰ 'ਤੇ ਅਧਿਕਾਰਤ ਲਾਈਵ ਖਾਤੇ ਨਾਲ ਫਿੰਗਰਪ੍ਰਿੰਟ ਬਦਲਾਵਾਂ ਦੀ ਪੁਸ਼ਟੀ ਕਰੋ।

## Claude Code ਸਟੀਲਥ ਬੰਡਲ

ਜਦੋਂ `cliCompatMode` ਚਾਲੂ ਹੁੰਦਾ ਹੈ, ਤਾਂ OmniRoute ਬਾਹਰ ਜਾਣ ਵਾਲੀਆਂ Claude ਬੇਨਤੀਆਂ ਨੂੰ ਇਸ ਤਰ੍ਹਾਂ ਮੁੜ-ਆਕਾਰ ਦਿੰਦਾ ਹੈ ਕਿ ਉਹ `claude-cli` ਟ੍ਰੈਫਿਕ ਤੋਂ ਵੱਖਰੀਆਂ ਨਹੀਂ ਲੱਗਦੀਆਂ। ਤਿੰਨ ਮੋਡੀਊਲ ਮਿਲ ਕੇ ਕੰਮ ਕਰਦੇ ਹਨ:

### `claudeCodeFingerprint.ts`

ਬਿਲਿੰਗ ਹੈਡਰ ਵਿੱਚ ਸ਼ਾਮਲ 3-ਅੱਖਰੀ `cc_version` ਫਿੰਗਰਪ੍ਰਿੰਟ ਦੀ ਗਣਨਾ ਕਰਦਾ ਹੈ:

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (ਹਾਰਡਕੋਡ ਕੀਤਾ ਹੋਇਆ; ਅਧਿਕਾਰਤ ਕਲਾਇੰਟ ਨਾਲ ਮੇਲ ਖਾਂਦਾ ਹੈ)
- ਇਨਪੁੱਟ: ਪਹਿਲੇ ਯੂਜ਼ਰ ਸੁਨੇਹੇ ਦੇ ਟੈਕਸਟ ਦੇ ਇੰਡੈਕਸ 4, 7, 20 ਉੱਤੇ ਮੌਜੂਦ ਅੱਖਰ + ਵਰਜ਼ਨ ਸਟਰਿੰਗ
- ਆਉਟਪੁੱਟ: 3-ਅੱਖਰੀ hex ਪ੍ਰੀਫਿਕਸ

### `claudeCodeCCH.ts` (ਕਲਾਇੰਟ ਸਮੱਗਰੀ ਹੈਸ਼)

ਸਰਵਰ-ਸਾਈਡ ਅਖੰਡਤਾ ਜਾਂਚ, ਜਿਸ ਦੀ ਗਣਨਾ ਅਧਿਕਾਰਤ Claude Code CLI ਵੱਲੋਂ Bun/Zig ਰਾਹੀਂ ਕੀਤੀ ਜਾਂਦੀ ਹੈ। OmniRoute ਇਸਨੂੰ `xxhash-wasm` ਨਾਲ ਮੁੜ ਲਾਗੂ ਕਰਦਾ ਹੈ:

1. ਬਾਡੀ ਨੂੰ `cch=00000;` ਪਲੇਸਹੋਲਡਰ ਨਾਲ ਸੀਰੀਅਲਾਈਜ਼ ਕਰੋ
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. ਸਿਫ਼ਰ ਨਾਲ ਪੈਡ ਕੀਤਾ 5-ਅੱਖਰੀ lowercase hex
4. `cch=00000;` ਨੂੰ ਗਣਨਾ ਕੀਤੇ ਟੋਕਨ ਨਾਲ ਬਦਲੋ

ਸਥਿਰਾਂਕ:

- ਸੀਡ: `0x6e52736ac806831e`
- ਪੈਟਰਨ: `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

"ਸੰਵੇਦਨਸ਼ੀਲ" ਕਲਾਇੰਟ ਨਾਵਾਂ ਦੇ ਪਹਿਲੇ ਅੱਖਰ ਤੋਂ ਬਾਅਦ ਇੱਕ Unicode **ਜ਼ੀਰੋ-ਵਿਡਥ ਜੌਇਨਰ** (`U+200D`) ਸ਼ਾਮਲ ਕਰਦਾ ਹੈ, ਤਾਂ ਜੋ ਅੱਪਸਟ੍ਰੀਮ ਫਿਲਟਰ ਉਨ੍ਹਾਂ ਨੂੰ grep ਨਾ ਕਰ ਸਕਣ। ਮੂਲ ਸ਼ਬਦ-ਸੂਚੀ:

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

ਇਨ੍ਹਾਂ ਉੱਤੇ ਲਾਗੂ ਹੁੰਦਾ ਹੈ: `system` ਬਲਾਕ, ਸਾਰੀ `messages[].content`, ਅਤੇ `tools[].description` / `tools[].function.description`। ਓਪਰੇਟਰ ਵੱਲੋਂ `setSensitiveWords()` ਰਾਹੀਂ ਬਦਲਿਆ ਜਾ ਸਕਦਾ ਹੈ।

### `claudeCodeCompatible.ts` — `anthropic-compatible-cc-*` ਪ੍ਰਦਾਤਾ

ਤੀਜੀ-ਧਿਰ ਦੇ ਉਨ੍ਹਾਂ Anthropic ਰੀਲੇਆਂ ਲਈ, ਜੋ ਕੇਵਲ "ਅਸਲੀ Claude Code" ਟ੍ਰੈਫਿਕ ਸਵੀਕਾਰਦੇ ਹਨ:

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.258 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- ਮੂਲ ਰੂਪ ਵਿੱਚ `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"`
- ਪ੍ਰਤੀ-ਕਨੈਕਸ਼ਨ "Redact-thinking beta ਸਮਰੱਥ ਕਰੋ" ਟੌਗਲ `redact-thinking-2026-02-12` ਨੂੰ ਉਦੋਂ ਸ਼ਾਮਲ ਕਰਦਾ ਹੈ, ਜਦੋਂ ਕਿਸੇ CC Compatible ਅੱਪਸਟ੍ਰੀਮ ਨੂੰ ਖ਼ਾਸ ਤੌਰ 'ਤੇ ਰੀਡੈਕਟ ਕੀਤੀਆਂ ਥਿੰਕਿੰਗ ਸਟ੍ਰੀਮਾਂ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ
- ਪ੍ਰਤੀ-ਕਨੈਕਸ਼ਨ "ਸੰਖੇਪ ਥਿੰਕਿੰਗ ਡਿਸਪਲੇ ਸਮਰੱਥ ਕਰੋ" ਟੌਗਲ `providerSpecificData.requestDefaults.summarizeThinking` ਨੂੰ ਸਟੋਰ ਕਰਦਾ ਹੈ ਅਤੇ ਉਨ੍ਹਾਂ CC Compatible ਥਿੰਕਿੰਗ ਬੇਨਤੀਆਂ ਵਿੱਚ `display: "summarized"` ਸ਼ਾਮਲ ਕਰਦਾ ਹੈ, ਜਿਨ੍ਹਾਂ ਨੇ ਪਹਿਲਾਂ ਹੀ ਕੋਈ ਡਿਸਪਲੇ ਮੋਡ ਸੈੱਟ ਨਹੀਂ ਕੀਤਾ
- `CONTEXT_1M_BETA_HEADER = "context-1m-2025-08-07"` (Opus/Sonnet 4.x ਪਰਿਵਾਰ)
- ਮੂਲ ਪਾਥ: `/v1/messages?beta=true`

ਇਸੇ ਬੰਡਲ ਵਿੱਚ ਸਹਿਯੋਗੀ ਮੋਡੀਊਲ:

- `claudeCodeConstraints.ts` — ਤਾਪਮਾਨ + ਕੈਸ਼-ਕੰਟਰੋਲ ਨਿਯਮ
- `claudeCodeToolRemapper.ts` — ਟੂਲ-ਨਾਮ ਰੀਮੈਪਿੰਗ
- `claudeCodeExtraRemap.ts` — ਵਾਧੂ ਪੇਲੋਡ ਨਾਰਮਲਾਈਜ਼ੇਸ਼ਨ

## Antigravity ਸਟੀਲਥ

Antigravity ਬੇਨਤੀਆਂ ਕਾਲਰ ਦੇ ਟੈਕਸਟ ਨੂੰ ਬਾਈਟ-ਦਰ-ਬਾਈਟ ਜਿਉਂ ਦਾ ਤਿਉਂ ਰੱਖਦੀਆਂ ਹਨ। OmniRoute ਪ੍ਰੌਮਪਟਾਂ ਵਿੱਚ ਜ਼ੀਰੋ-ਵਿਡਥ ਅੱਖਰ ਸ਼ਾਮਲ ਨਹੀਂ ਕਰਦਾ ਜਾਂ ਕਿਸੇ IDE ਕਲਾਇੰਟ ਦੀ ਨਕਲ ਕਰਨ ਲਈ ਟੂਲਾਂ ਦੇ ਨਾਮ ਨਹੀਂ ਬਦਲਦਾ/ਉਨ੍ਹਾਂ ਨੂੰ ਇੰਜੈਕਟ ਨਹੀਂ ਕਰਦਾ।

### `antigravityHeaderScrub.ts`

ਫਾਰਵਰਡ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ Stainless SDK ਮਾਰਕਰਾਂ (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`) ਨੂੰ ਹਟਾਉਂਦਾ ਹੈ।

### ⚠️ ਜੋਖਮ: `ANTIGRAVITY_CREDITS=always` (ਖਾਤਾ-ਪਾਬੰਦੀ ਦਾ ਸੰਵੇਦਨਸ਼ੀਲ ਬਿੰਦੂ)

`ANTIGRAVITY_CREDITS=always` (`open-sse/executors/antigravity.ts` ਵੱਲੋਂ ਵਰਤਿਆ ਜਾਂਦਾ ਹੈ) **ਹਰੇਕ** ਬੇਨਤੀ ਨੂੰ Antigravity AI Credit Overages (ਭੁਗਤਾਨਸ਼ੁਦਾ Google ਕ੍ਰੈਡਿਟ) ਰਾਹੀਂ ਰੂਟ ਕਰਦਾ ਹੈ, ਬਜਾਏ ਇਸਦੇ ਕਿ Google ਦਾ ਮੁਫ਼ਤ-ਟੀਅਰ ਕੋਟਾ ਬੇਨਤੀਆਂ ਨੂੰ ਸੀਮਿਤ ਕਰੇ। ਇਸਨੂੰ ਇੱਕ ਵਿਸ਼ੇਸ਼ਤਾ ਵਜੋਂ ਦਸਤਾਵੇਜ਼ਬੱਧ ਕੀਤਾ ਗਿਆ ਹੈ, ਪਰ ਇਹ **ਸਾਨੂੰ ਮਿਲਣ ਵਾਲੀ ToS ਉਲੰਘਣਾ ਦੀ ਸਭ ਤੋਂ ਆਮ ਰਿਪੋਰਟ ਹੈ** — `=always` ਨਾਲ ਕੁਝ ਘੰਟੇ ਚੱਲਣ ਤੋਂ ਬਾਅਦ ਕਈ Google Ultra ਖਾਤਿਆਂ ਉੱਤੇ `403 / "service disabled for ToS violation" / insufficient_quota` ਨਾਲ ਪਾਬੰਦੀ ਲੱਗੀ ਹੈ।

ਅੱਪਸਟ੍ਰੀਮ ਲਾਗੂਕਰਨ **Google ਦੇ ਪਾਸੇ** ਹੁੰਦਾ ਹੈ; ਇਹ ਅਜਿਹੀ ਚੀਜ਼ ਨਹੀਂ ਹੈ ਜਿਸਨੂੰ OmniRoute ਰੋਕ ਸਕੇ। env var ਦਾ ਨਾਮ ਅਤੇ ਮੌਜੂਦਾ ਦਸਤਾਵੇਜ਼ ਇਸਨੂੰ ਚਾਲੂ ਕਰਨ ਲਈ ਇੱਕ ਸੁਰੱਖਿਅਤ ਵਿਕਲਪ ਵਾਂਗ ਪੇਸ਼ ਕਰਦੇ ਹਨ; ਪਰ ਇਹ ਸੁਰੱਖਿਅਤ ਨਹੀਂ ਹੈ।

**ਇਹ ਕੇਵਲ ਮੁਫ਼ਤ-ਟੀਅਰ ਵਰਤੋਂ ਦੇ ਮੁਕਾਬਲੇ ਦੁਰਵਰਤੋਂ ਪਛਾਣ ਨੂੰ ਹੋਰ ਆਕਰਮਕ ਢੰਗ ਨਾਲ ਕਿਉਂ ਸਰਗਰਮ ਕਰਦਾ ਹੈ:**

- ਕਿਸੇ ਇੱਕ Google ਖਾਤੇ ਉੱਤੇ ਲਗਾਤਾਰ ਸਵੈਚਾਲਿਤ ਖਰਚ ਨੂੰ ਮੁਫ਼ਤ-ਟੀਅਰ ਦੇ ਕੋਟਾ ਪੂਰਾ ਹੋਣ ਅਤੇ ਫਿਰ ਰੁਕ ਜਾਣ ਵਾਲੇ ਵਿਹਾਰ ਤੋਂ ਵੱਖਰੇ ਢੰਗ ਨਾਲ ਫਲੈਗ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।
- ਕ੍ਰੈਡਿਟ ਓਵਰੇਜ ਲਈ ਕੋਈ ਦਰ ਸੀਮਾ ਨਹੀਂ ਹੁੰਦੀ, ਇਸ ਲਈ ਗਲਤ ਕਾਨਫ਼ਿਗਰ ਕੀਤਾ ਕਲਾਇੰਟ ਕੁਝ ਮਿੰਟਾਂ ਵਿੱਚ ਕਈ ਸੌ USD ਖਰਚ ਸਕਦਾ ਹੈ ਅਤੇ API-key ਦੀ ਮੁੜ-ਵਿਕਰੀ ਜਾਂ ਬੌਟ ਟ੍ਰੈਫਿਕ ਵਰਗਾ ਲੱਗ ਸਕਦਾ ਹੈ।
- ਇੱਕੋ ਬਾਹਰੀ IP ਤੋਂ ਸਮਾਂਤਰ ਰੂਪ ਵਿੱਚ ਓਵਰੇਜ ਕ੍ਰੈਡਿਟ ਵਰਤ ਰਹੇ ਕਈ OmniRoute ਯੂਜ਼ਰ ਸੰਕੇਤ ਨੂੰ ਹੋਰ ਮਜ਼ਬੂਤ ਕਰਦੇ ਹਨ।

**ਸਿਫ਼ਾਰਸ਼ੀ ਰਵੱਈਆ:**

1. ਮੂਲ `ANTIGRAVITY_CREDITS=off` ਨੂੰ ਕਾਇਮ ਰੱਖੋ, ਜਦੋਂ ਤੱਕ ਓਪਰੇਟਰ ਸਪਸ਼ਟ ਤੌਰ 'ਤੇ ਭੁਗਤਾਨਸ਼ੁਦਾ ਕ੍ਰੈਡਿਟ ਅਤੇ ਖਾਤਾ-ਲਾਗੂਕਰਨ ਦੇ ਜੋਖਮ ਨੂੰ ਸਵੀਕਾਰ ਨਹੀਂ ਕਰਦਾ। `retry` ਪਹਿਲਾਂ ਸਧਾਰਨ ਬੇਨਤੀ ਭੇਜਦਾ ਹੈ ਅਤੇ ਕਿਸੇ ਯੋਗ ਕੋਟਾ 429 ਤੋਂ ਬਾਅਦ ਵੱਧ ਤੋਂ ਵੱਧ ਇੱਕ ਵਾਰ ਕ੍ਰੈਡਿਟ ਇੰਜੈਕਟ ਕਰਦਾ ਹੈ; `always` ਪਹਿਲੀ ਬੇਨਤੀ ਵਿੱਚ ਹੀ ਕ੍ਰੈਡਿਟ ਇੰਜੈਕਟ ਕਰਦਾ ਹੈ।
2. **ਇੱਕੋ Antigravity ਖਾਤੇ ਨੂੰ ਅਧਿਕ ਭਾਰ ਦੇਣ ਦੀ ਬਜਾਏ Auto-Combo ਰਾਹੀਂ ਪ੍ਰਦਾਤਾਵਾਂ ਵਿੱਚ ਲੋਡ ਵੰਡੋ** (`model: "auto"` ਜਾਂ `kr/glm/etc`-combo)।
3. **ਪ੍ਰਤੀ-ਕਨੈਕਸ਼ਨ RPM ਸੀਮਾਵਾਂ ਸੈੱਟ ਕਰੋ** Antigravity ਪ੍ਰਦਾਤਾ ਦੇ ਸੰਪਾਦਨ ਪੰਨੇ ਵਿੱਚ (Dashboard → Providers → Antigravity → connection → rate limit)। ਲਗਾਤਾਰ ਵਰਤੋਂ ਲਈ 30–60 RPM ਇੱਕ ਤਰਕਸੰਗਤ ਉੱਪਰੀ ਹੱਦ ਹੈ।
4. **ਸਥਿਰ, ਓਪਰੇਟਰ-ਨਿਯੰਤਰਿਤ ਅੱਪਸਟ੍ਰੀਮ ਨੈੱਟਵਰਕਿੰਗ ਵਰਤੋ** ਅਤੇ ਇੱਕ ਖਾਤੇ ਨੂੰ ਅਸੰਬੰਧਿਤ ਯੂਜ਼ਰਾਂ ਜਾਂ ਵਰਕਲੋਡਾਂ ਵਿਚਕਾਰ ਸਾਂਝਾ ਕਰਨ ਤੋਂ ਬਚੋ।
5. **ਜੇ ਪਾਬੰਦੀ ਲੱਗ ਜਾਵੇ**: Google ਵੱਲੋਂ ਭੇਜੇ ਗਏ ਸਟੀਕ `quota_exceeded` / `service disabled` ਜਵਾਬੀ ਬਾਡੀ ਨਾਲ `support.google.com` → "Restore Workspace/Account access" ਰਾਹੀਂ ਅਪੀਲ ਕਰੋ। ਬਹਾਲੀ ਦੀ ਗਾਰੰਟੀ ਨਹੀਂ ਹੈ।

ਵਾਤਾਵਰਣ ਹਵਾਲਾ ਹਰੇਕ ਕ੍ਰੈਡਿਟ ਮੋਡ ਦੇ ਖਾਤੇ ਅਤੇ ਖਰਚ ਸੰਬੰਧੀ ਪ੍ਰਭਾਵਾਂ ਨੂੰ ਦਸਤਾਵੇਜ਼ਬੱਧ ਕਰਦਾ ਹੈ।

## CLI ਫਿੰਗਰਪ੍ਰਿੰਟ ਰਜਿਸਟਰੀ — `open-sse/config/cliFingerprints.ts`

ਪ੍ਰਤੀ-ਪ੍ਰਦਾਤਾ ਸਾਰਣੀ, ਜੋ ਅਧਿਕਾਰਤ CLIਆਂ ਦੇ mitmproxy ਟ੍ਰੇਸਾਂ ਤੋਂ ਕੈਪਚਰ ਕੀਤੇ **ਬਿਲਕੁਲ ਸਹੀ** ਹੈਡਰ ਕ੍ਰਮ ਅਤੇ JSON ਬਾਡੀ ਫੀਲਡ ਕ੍ਰਮ ਨੂੰ ਨਿਰਧਾਰਤ ਕਰਦੀ ਹੈ। ਇਸ ਵੇਲੇ ਰਜਿਸਟਰ ਕੀਤੇ ਗਏ: `codex`, `claude`, ਅਤੇ `antigravity` ਤੇ `github` ਲਈ `providerHeaderProfiles.ts` ਵਿੱਚ ਰਨਟਾਈਮ ਤੋਂ ਪ੍ਰਾਪਤ ਪ੍ਰੋਫ਼ਾਈਲਾਂ।

```ts
interface CliFingerprint {
  headerOrder: string[]; // ਕੇਸ-ਸੰਵੇਦਨਸ਼ੀਲ
  bodyFieldOrder: string[]; // ਸਿਖਰਲੇ-ਪੱਧਰ ਦੀਆਂ JSON ਕੁੰਜੀਆਂ
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

ਹਰੇਕ ਪ੍ਰਦਾਤਾ ਲਈ env ਰਾਹੀਂ ਟੌਗਲ ਕਰੋ (ਹੇਠਾਂ ਵੇਖੋ)। ਅਸਮਰੱਥ ਹੋਣ 'ਤੇ, ਹੈਡਰ/ਬਾਡੀ ਕੁੰਜੀਆਂ ਉਸੇ ਕ੍ਰਮ ਵਿੱਚ ਦਿਖਾਈ ਦਿੰਦੀਆਂ ਹਨ ਜੋ Node/JSON ਨੇ ਦਿੱਤਾ ਸੀ — ਫਿੰਗਰਪ੍ਰਿੰਟ ਕਰਨਾ ਆਸਾਨ।

## MITM ਪ੍ਰਾਕਸੀ (Antigravity, Linux/macOS/Windows)

ਉਨ੍ਹਾਂ CLIਆਂ ਲਈ ਜਿਨ੍ਹਾਂ ਦੀਆਂ ਬਾਈਨਰੀਆਂ ਨੂੰ `OPENAI_BASE_URL` ਰਾਹੀਂ ਰੀਡਾਇਰੈਕਟ ਨਹੀਂ ਕੀਤਾ ਜਾ ਸਕਦਾ, OmniRoute ਇੱਕ ਸਥਾਨਕ TLS-ਟਰਮੀਨੇਟਿੰਗ ਪ੍ਰਾਕਸੀ ਚਲਾਉਂਦਾ ਹੈ। ਐਂਡਪੌਇੰਟ `src/app/api/cli-tools/antigravity-mitm/` ਦੇ ਅਧੀਨ ਹਨ।

| ਵਿਧੀ   | ਐਂਡਪੌਇੰਟ                                | ਉਦੇਸ਼                                                 |
| ------ | --------------------------------------- | ----------------------------------------------------- |
| GET    | `/api/cli-tools/antigravity-mitm`       | ਸਥਿਤੀ — ਚੱਲ ਰਿਹਾ, pid, dnsConfigured, certExists      |
| POST   | `/api/cli-tools/antigravity-mitm`       | MITM ਸ਼ੁਰੂ ਕਰੋ (`apiKey` + `sudoPassword` ਲੋੜੀਂਦੇ ਹਨ) |
| DELETE | `/api/cli-tools/antigravity-mitm`       | MITM ਰੋਕੋ                                             |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | ਮਾਡਲ ਉਪਨਾਮਾਂ ਦੀ ਸੂਚੀ                                  |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | ਕਿਸੇ ਟੂਲ ਲਈ ਮਾਡਲ ਉਪਨਾਮ ਸੰਭਾਲੋ                         |

ਇੰਟਰਸੈਪਟ ਕੀਤਾ ਜਾਣ ਵਾਲਾ ਟੀਚਾ ਹੋਸਟ: **`daily-cloudcode-pa.googleapis.com`** (Antigravity ਦਾ ਅੱਪਸਟ੍ਰੀਮ)।

### ਸ਼ੁਰੂਆਤੀ ਕ੍ਰਮ (`src/mitm/manager.ts::startMitm`)

1. `selfsigned` ਰਾਹੀਂ ਸਵੈ-ਦਸਤਖਤ ਕੀਤਾ ਸਰਟੀਫਿਕੇਟ ਬਣਾਓ (RSA-2048, SHA-256, 1y) — `cert/generate.ts`
2. ਸਰਟੀਫਿਕੇਟ ਨੂੰ ਸਿਸਟਮ ਟਰੱਸਟ ਸਟੋਰ ਵਿੱਚ ਇੰਸਟਾਲ ਕਰੋ — `cert/install.ts`
3. ਹੋਸਟਸ ਐਂਟਰੀ `127.0.0.1 daily-cloudcode-pa.googleapis.com` ਸ਼ਾਮਲ ਕਰੋ — `dns/dnsConfig.ts`
4. `ROUTER_API_KEY` + `MITM_LOCAL_PORT` (ਡਿਫੌਲਟ `443`) ਨਾਲ `src/mitm/server.cjs` ਸਪੌਨ ਕਰੋ
5. PID ਨੂੰ `<DATA_DIR>/mitm/.mitm.pid` ਵਿੱਚ ਸਥਾਈ ਤੌਰ 'ਤੇ ਸੰਭਾਲੋ

### Linux ਡਾਇਨਾਮਿਕ ਟਰੱਸਟ-ਸਟੋਰ ਖੋਜ — `cert/install.ts`

`getLinuxCertConfig()` ਤਰਜੀਹੀ ਸੂਚੀ ਵਿੱਚੋਂ ਲੰਘਦਾ ਹੈ ਅਤੇ ਪਹਿਲੀ ਮੌਜੂਦਾ ਡਾਇਰੈਕਟਰੀ ਚੁਣਦਾ ਹੈ:

| ਡਿਸਟ੍ਰੋ ਪਰਿਵਾਰ           | ਡਾਇਰੈਕਟਰੀ                                   | ਅੱਪਡੇਟ ਕਮਾਂਡ             |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

ਸਰਟੀਫਿਕੇਟ ਫ਼ਾਈਲ ਨਾਮ: `omniroute-mitm.crt`। `getCertFingerprint()` ਰਾਹੀਂ ਫਿੰਗਰਪ੍ਰਿੰਟ ਮਿਲਾਨ (DER ਦਾ SHA-1)।

ਇਸ ਤੋਂ ਇਲਾਵਾ, ਜਦੋਂ `certutil` ਉਪਲਬਧ ਹੋਵੇ, ਤਾਂ `updateNssDatabases()` ਪ੍ਰਤੀ-ਉਪਭੋਗਤਾ NSS DBਆਂ ਵਿੱਚ ਇੰਸਟਾਲ ਕਰਦਾ ਹੈ: `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, ਸਾਰੇ Firefox ਪ੍ਰੋਫ਼ਾਈਲ (snap ਸਮੇਤ), **`OmniRoute MITM Root CA`** ਉਪਨਾਮ ਹੇਠ।

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** ਉੱਚ ਅਧਿਕਾਰਾਂ ਵਾਲਾ PowerShell → `certutil -addstore Root`

### ਪ੍ਰਮਾਣੀਕਰਨ

ਸਾਰੇ MITM ਐਂਡਪੌਇੰਟਾਂ ਲਈ ਪ੍ਰਬੰਧਨ ਪ੍ਰਮਾਣੀਕਰਨ (`requireCliToolsAuth`) ਲੋੜੀਂਦਾ ਹੈ। sudo ਪਾਸਵਰਡ ਮੋਡੀਊਲ ਸਕੋਪ ਵਿੱਚ ਕੈਸ਼ ਕੀਤਾ ਜਾਂਦਾ ਹੈ (`globalThis` ਵਿੱਚ ਕਦੇ ਨਹੀਂ) ਅਤੇ `stopMitm()` 'ਤੇ ਸਾਫ਼ ਕਰ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ।

## ਜਦੋਂ ਕੋਈ ਪ੍ਰਦਾਤਾ ਫਿੰਗਰਪ੍ਰਿੰਟ ਬਦਲੇ, ਤਾਂ ਅੱਪਡੇਟ ਕਰਨਾ

1. `mitmproxy` ਨਾਲ ਅਧਿਕਾਰਤ CLI ਟ੍ਰੈਫਿਕ ਕੈਪਚਰ ਕਰੋ (TLS ਇੰਟਰਸੈਪਸ਼ਨ + ਡੰਪ)
2. JA3/JA4 ਅਤੇ ਸ਼ਾਬਦਿਕ ਹੈਡਰ ਕ੍ਰਮ ਐਕਸਟ੍ਰੈਕਟ ਕਰੋ
3. ਸੰਬੰਧਿਤ `CLI_FINGERPRINTS[...]` ਐਂਟਰੀ ਅੱਪਡੇਟ ਕਰੋ
4. `.env.example` ਵਿੱਚ ਮੇਲ ਖਾਂਦਾ `*_USER_AGENT` ਡਿਫੌਲਟ ਅੱਪਡੇਟ ਕਰੋ
5. ਜੇ TLS ਹੈਂਡਸ਼ੇਕ ਖੁਦ ਬਦਲ ਗਿਆ ਹੈ, ਤਾਂ ਸੰਬੰਧਿਤ ਪ੍ਰਦਾਤਾ ਰੈਪਰ ਜਾਂ wreq-js `browser:` ਵਿਕਲਪ ਅੱਪਡੇਟ ਕਰੋ
6. ਪ੍ਰਦਾਤਾ-ਵਿਸ਼ੇਸ਼ TLS ਟੈਸਟ ਅਤੇ ਲਾਈਵ ਪ੍ਰਦਾਤਾ ਦੇ ਵਿਰੁੱਧ ਇੱਕ ਮੈਨੁਅਲ ਕੈਨਰੀ ਚਲਾਓ
7. ਪੈਚ ਰਿਲੀਜ਼ ਵਿੱਚ ਜਾਰੀ ਕਰੋ; `CHANGELOG.md` ਵਿੱਚ ਦਸਤਾਵੇਜ਼ਬੱਧ ਕਰੋ
