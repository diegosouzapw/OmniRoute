OmniRoute npm + Docker ਆਰਟੀਫੈਕਟ ਪ੍ਰਕਾਸ਼ਿਤ ਕਰਦਾ ਹੈ। ਇਹ ਗੇਟ ਮੂਲ-ਸਰੋਤ ਪ੍ਰਮਾਣ,
ਇਨਵੈਂਟਰੀ (SBOM) ਅਤੇ CVE ਸਕੈਨਿੰਗ ਪ੍ਰਦਾਨ ਕਰਦੇ ਹਨ; ਇਹ ਸਾਰੇ OSS ਹਨ ਅਤੇ ਰਿਲੀਜ਼ ਵਰਕਫ਼ਲੋਜ਼ ਨਾਲ ਜੁੜੇ ਹੋਏ ਹਨ।
**ਪਹਿਲਾਂ-ਸਲਾਹਕਾਰੀ** ਰੁਖ਼ — ਫ਼ਿਲਹਾਲ ਇਹ ਰਿਪੋਰਟ ਕਰਦੇ ਹਨ ਅਤੇ ਪਹਿਲੀ
ਸਫਲ ਰਿਲੀਜ਼ ਤੋਂ ਬਾਅਦ ਬਲੌਕਿੰਗ ਵਜੋਂ ਉੱਨਤ ਕੀਤੇ ਜਾਣਗੇ।

| ਗੇਟ                        | ਟੂਲ                                            | ਕਿੱਥੇ                         | ਬਲੌਕ ਕਰਦਾ ਹੈ?                | ਆਉਟਪੁੱਟ                                                  |
| -------------------------- | ---------------------------------------------- | ----------------------------- | ---------------------------- | -------------------------------------------------------- |
| SLSA ਮੂਲ-ਸਰੋਤ ਪ੍ਰਮਾਣ (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | ਸਿਰਫ਼ ਜੇ ਪ੍ਰਕਾਸ਼ਨ ਅਸਫਲ ਹੋਵੇ  | npmjs ਬੈਜ / `npm audit signatures`                       |
| SBOM npm                   | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | ਸਿਰਫ਼ ਜੇ ਤਿਆਰ ਕਰਨਾ ਅਸਫਲ ਹੋਵੇ | ਰਿਲੀਜ਼ ਐਸੈੱਟ + ਆਰਟੀਫੈਕਟ                                  |
| SBOM ਇਮੇਜ                  | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (ਮਰਜ)    | ਸਲਾਹਕਾਰੀ                     | CycloneDX ਆਰਟੀਫੈਕਟ                                       |
| Trivy CVE (SARIF)          | `aquasecurity/trivy-action`                    | `docker-publish.yml` (ਮਰਜ)    | ਸਲਾਹਕਾਰੀ                     | SARIF (HIGH+CRITICAL) → ਸੁਰੱਖਿਆ ਟੈਬ                      |
| Trivy CRITICAL ਗੇਟ         | `aquasecurity/trivy-action`                    | `docker-publish.yml` (ਮਰਜ)    | **ਬਲੌਕਿੰਗ**                  | ਠੀਕ ਕੀਤੇ ਜਾ ਸਕਣ ਵਾਲੇ CRITICAL ਉੱਤੇ `exit-code: '1'`      |
| osv vulnCount              | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **ਬਲੌਕਿੰਗ**                  | `metrics.vulnCount` ਨੂੰ ਰੈਚਿਟ ਕਰਦਾ ਹੈ (`direction:down`) |
| OpenSSF Scorecard          | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | ਸਲਾਹਕਾਰੀ                     | SARIF → ਸੁਰੱਖਿਆ + ਬੈਜ                                    |

ਇਮੇਜ CVE ਰੈਚਿਟ `docker-publish.yml` ਵਿੱਚ **ਦੋ ਪੜਾਅ** ਵਰਤਦਾ ਹੈ: SARIF ਪੜਾਅ
(`HIGH,CRITICAL`, `exit-code: 0`) ਬਲੌਕ ਕੀਤੇ ਬਿਨਾਂ HIGH+CRITICAL ਨੂੰ ਸੁਰੱਖਿਆ ਟੈਬ ਵਿੱਚ
ਦ੍ਰਿਸ਼ਮਾਨ ਰੱਖਦਾ ਹੈ; _CRITICAL ਗੇਟ_ ਪੜਾਅ (`severity: CRITICAL`, `ignore-unfixed: true`,
`exit-code: 1`) ਕਿਸੇ ਅਜਿਹੇ CRITICAL CVE ਉੱਤੇ ਰਿਲੀਜ਼ ਨੂੰ ਅਸਫਲ ਕਰਦਾ ਹੈ **ਜਿਸ ਲਈ ਸੁਧਾਰ ਉਪਲਬਧ ਹੋਵੇ**। `ignore-unfixed`
ਕਿਸੇ ਅਪਸਟ੍ਰੀਮ ਪੈਚ ਤੋਂ ਬਿਨਾਂ ਬੇਸ-ਇਮੇਜ CVE ਕਾਰਨ ਰਿਲੀਜ਼ ਨੂੰ ਬਲੌਕ ਹੋਣ ਤੋਂ ਰੋਕਦਾ ਹੈ।

## ⚠️ CVE ਵਖਰੇਵਾਂ (ਬਲੌਕਿੰਗ osv/Trivy ਗੇਟ)

osv ਅਤੇ Trivy ਨਿਰਭਰਤਾਵਾਂ ਦੀ ਤੁਲਨਾ ਉਹਨਾਂ CVE ਡਾਟਾਬੇਸਾਂ ਨਾਲ ਕਰਦੇ ਹਨ ਜੋ **ਲਗਾਤਾਰ ਵਧਦੇ ਰਹਿੰਦੇ ਹਨ**। ਇੱਕ PR
ਜੋ **ਕਿਸੇ ਨਿਰਭਰਤਾ ਨੂੰ ਨਹੀਂ ਛੂੰਹਦਾ**, ਅਚਾਨਕ ਲਾਲ ਹੋ ਸਕਦਾ ਹੈ ਕਿਉਂਕਿ ਕਿਸੇ ਮੌਜੂਦਾ ਨਿਰਭਰਤਾ ਵਿੱਚ
ਇੱਕ ਨਵਾਂ CVE ਪ੍ਰਗਟ ਕੀਤਾ ਗਿਆ ਹੈ (osv: ਮਾਪਿਆ ਗਿਆ `vulnCount` > ਬੇਸਲਾਈਨ; Trivy: ਇਮੇਜ ਵਿੱਚ
ਇੱਕ ਨਵਾਂ, ਠੀਕ ਕੀਤੇ ਜਾ ਸਕਣ ਵਾਲਾ CRITICAL)। **ਇਹ ਬਲੌਕਿੰਗ CVE ਗੇਟ ਦਾ ਉਮੀਦ ਕੀਤਾ ਜਾਣ ਵਾਲਾ
ਕਾਰਜਕਾਰੀ ਵਿਹਾਰ ਹੈ, ਉਤਪਾਦ ਵਿੱਚ ਕੋਈ ਪਿਛੜਾਅ ਨਹੀਂ।**

ਜਦੋਂ ਕਿਸੇ ਨਵੇਂ ਪ੍ਰਗਟ ਕੀਤੇ CVE ਕਾਰਨ osv ਜਾਂ Trivy ਲਾਲ ਹੋ ਜਾਣ, ਤਾਂ ਉਪਾਅ ਇਹ ਹੈ:

1. **ਪ੍ਰਭਾਵਿਤ ਨਿਰਭਰਤਾ ਦਾ ਵਰਜਨ ਵਧਾਓ** (ਤਰਜੀਹੀ) — `package.json`
   `overrides` (ਅਸਿੱਧੀਆਂ ਨਿਰਭਰਤਾਵਾਂ) ਰਾਹੀਂ ਪੈਚ ਕੀਤੇ ਵਰਜਨ ਵਿੱਚ ਅੱਪਗ੍ਰੇਡ ਕਰੋ ਜਾਂ ਪੈਚ ਕੀਤੇ ਬੇਸ ਉੱਤੇ ਇਮੇਜ ਦੁਬਾਰਾ ਬਣਾਓ।
2. **ਜੇ ਕੋਈ ਅਪਸਟ੍ਰੀਮ ਸੁਧਾਰ ਨਹੀਂ ਹੈ:**
   - **osv:** `config/quality/quality-baseline.json` ਵਿੱਚ `metrics.vulnCount` ਨੂੰ ਦੁਬਾਰਾ ਬੇਸਲਾਈਨ ਕਰੋ
     (`npm run quality:ratchet -- --update` ਸਮਰਪਿਤ ਗੇਟਾਂ ਨੂੰ ਕਵਰ ਨਹੀਂ ਕਰਦਾ — ਮੁੱਲ ਨੂੰ
     ਹੱਥੀਂ ਸੋਧੋ, `direction:down`) ਅਤੇ ਨਾਲ ਇੱਕ ਤਰਕਸੰਗਤ ਨੋਟ + ਟ੍ਰੈਕਿੰਗ ਇਸ਼ੂ ਸ਼ਾਮਲ ਕਰੋ।
   - **Trivy:** `.trivyignore` ਵਿੱਚ ਇੱਕ ਐਂਟਰੀ ਜੋੜੋ (ਹਰੇਕ ਲਾਈਨ ਉੱਤੇ ਇੱਕ CVE-ID), ਨਾਲ ਇੱਕ ਤਰਕਸੰਗਤ
     ਟਿੱਪਣੀ + ਟ੍ਰੈਕਿੰਗ ਇਸ਼ੂ। `ignore-unfixed: true` ਪਹਿਲਾਂ ਹੀ ਬਿਨਾਂ
     ਪੈਚਾਂ ਵਾਲੇ CVE ਨੂੰ ਆਪਣੇ ਆਪ ਕਵਰ ਕਰਦਾ ਹੈ।

ਜਦੋਂ ਟੂਲ ਮੌਜੂਦ ਨਾ ਹੋਵੇ ਜਾਂ ਮਾਪ ਅਸਫਲ ਹੋਵੇ, ਦੋਵੇਂ ਗੇਟ **ਸੁਰੱਖਿਅਤ ਢੰਗ ਨਾਲ ਛੱਡ ਦਿੱਤੇ ਜਾਂਦੇ ਹਨ**
(exit 0) (osv-scanner ਦਾ PATH ਵਿੱਚ ਨਾ ਹੋਣਾ, osv.dev/ਨੈੱਟਵਰਕ ਤੱਕ ਪਹੁੰਚ ਨਾ ਹੋਣਾ, ਅਵੈਧ JSON) — ਇੱਕ
**ਮਾਪਣ** ਅਸਫਲਤਾ ਕਦੇ ਵੀ ਬਲੌਕ ਨਹੀਂ ਕਰਦੀ; ਸਿਰਫ਼ ਇੱਕ **ਮਾਪਿਆ ਗਿਆ** ਪਿਛੜਾਅ ਬਲੌਕ ਕਰਦਾ ਹੈ।

## ਬੈਕਲਾਗ: Scorecard ਸਲਾਹਕਾਰੀ → ਬਲੌਕਿੰਗ

Scorecard ਰਿਪੋਰਟਿੰਗ ਵਾਲੀ ਪਹਿਲੀ ਸਫਲ ਰਿਲੀਜ਼ ਤੋਂ ਬਾਅਦ:

- Scorecard: ਸਕੋਰ ਰੈਚਿਟ (ਮਾਪੇ ਗਏ ਸਕੋਰ ਨੂੰ ਸਥਿਰ ਕਰਦਾ ਹੈ; ਇਹ ਘਟ ਨਹੀਂ ਸਕਦਾ)।

ਇਹ Phase 7 ਗੇਟਾਂ (osv-scanner, gitleaks, actionlint+zizmor) ਨੂੰ ਪੂਰਾ ਕਰਦਾ ਹੈ: zizmor
ਵਰਕਫ਼ਲੋਜ਼ ਦਾ ਖ਼ੁਦ ਆਡਿਟ ਕਰਦਾ ਹੈ; Scorecard ਸਮੁੱਚੇ ਰੂਪ ਵਿੱਚ ਰਿਪੋ ਦੀ ਸਥਿਤੀ ਨੂੰ ਮਾਪਦਾ ਹੈ।
