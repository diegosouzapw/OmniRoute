OmniRoute npm + Docker ਆਰਟੀਫੈਕਟਸ ਪ੍ਰਕਾਸ਼ਿਤ ਕਰਦਾ ਹੈ। ਇਹ ਗੇਟ ਪ੍ਰੋਵੈਨੈਂਸ, ਇਨਵੈਂਟਰੀ (SBOM) ਅਤੇ CVE ਸਕੈਨਿੰਗ ਪ੍ਰਦਾਨ ਕਰਦੇ ਹਨ, ਸਾਰੇ OSS ਹਨ, ਜੋ ਰਿਲੀਜ਼ ਵਰਕਫਲੋ ਵਿੱਚ ਸ਼ਾਮਲ ਕੀਤੇ ਗਏ ਹਨ। **ਸਲਾਹ-ਪਹਿਲਾਂ** ਪਹੁੰਚ — ਉਹ ਹੁਣ ਰਿਪੋਰਟ ਕਰਦੇ ਹਨ, ਪਹਿਲੀ ਸਫਲ ਰਿਲੀਜ਼ ਤੋਂ ਬਾਅਦ ਬਲੌਕਿੰਗ ਵਿੱਚ ਤਰੱਕੀ ਦਿੰਦੇ ਹਨ।

| ਗੇਟ                   | ਟੂਲ                                            | ਕਿੱਥੇ                         | ਬਲੌਕ ਕਰਦਾ ਹੈ?                   | ਆਉਟਪੁੱਟ                                              |
| :-------------------- | :--------------------------------------------- | :---------------------------- | :------------------------------ | :--------------------------------------------------- |
| SLSA ਪ੍ਰੋਵੈਨੈਂਸ (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | ਸਿਰਫ਼ ਜੇ ਪ੍ਰਕਾਸ਼ਨ ਅਸਫਲ ਹੁੰਦਾ ਹੈ | ਬੈਜ npmjs / `npm audit signatures`                   |
| SBOM npm              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | ਸਿਰਫ਼ ਜੇ ਜਨਰੇਸ਼ਨ ਅਸਫਲ ਹੁੰਦੀ ਹੈ  | ਰਿਲੀਜ਼ ਐਸੇਟ + ਆਰਟੀਫੈਕਟ                               |
| SBOM ਚਿੱਤਰ            | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | ਸਲਾਹਕਾਰੀ                        | CycloneDX ਆਰਟੀਫੈਕਟ                                   |
| Trivy CVE (SARIF)     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | ਸਲਾਹਕਾਰੀ                        | SARIF (HIGH+CRITICAL) → ਸੁਰੱਖਿਆ ਟੈਬ                  |
| Trivy CRITICAL ਗੇਟ    | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | **ਬਲੌਕਿੰਗ**                     | ਠੀਕ ਹੋਣ ਯੋਗ CRITICAL 'ਤੇ `exit-code: '1'`            |
| osv vulnCount         | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **ਬਲੌਕਿੰਗ**                     | `metrics.vulnCount` ਨੂੰ ਰੈਚੇਟ ਕਰਦਾ ਹੈ (ਦਿਸ਼ਾ: ਹੇਠਾਂ) |
| OpenSSF ਸਕੋਰਕਾਰਡ      | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | ਸਲਾਹਕਾਰੀ                        | SARIF → ਸੁਰੱਖਿਆ + ਬੈਜ                                |

ਚਿੱਤਰ CVE ਰੈਚੇਟ `docker-publish.yml` ਵਿੱਚ **ਦੋ ਕਦਮਾਂ** ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ: SARIF ਕਦਮ (`HIGH,CRITICAL`, `exit-code: 0`) ਬਲੌਕ ਕੀਤੇ ਬਿਨਾਂ HIGH+CRITICAL ਨੂੰ ਸੁਰੱਖਿਆ ਟੈਬ ਵਿੱਚ ਦਿਖਾਈ ਦਿੰਦਾ ਰੱਖਦਾ ਹੈ; _CRITICAL ਗੇਟ_ ਕਦਮ (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) ਇੱਕ CRITICAL CVE **ਉਪਲਬਧ ਫਿਕਸ ਦੇ ਨਾਲ** ਰਿਲੀਜ਼ ਨੂੰ ਅਸਫਲ ਕਰਦਾ ਹੈ। `ignore-unfixed` ਇੱਕ ਅੱਪਸਟ੍ਰੀਮ ਪੈਚ ਤੋਂ ਬਿਨਾਂ ਬੇਸ-ਇਮੇਜ CVE ਲਈ ਰਿਲੀਜ਼ ਨੂੰ ਬਲੌਕ ਕਰਨ ਤੋਂ ਰੋਕਦਾ ਹੈ।

## ⚠️ CVE ਪਰਿਵਰਤਨ (osv/Trivy ਗੇਟਾਂ ਨੂੰ ਬਲੌਕ ਕਰਨਾ)

osv ਅਤੇ Trivy deps ਦੀ ਤੁਲਨਾ CVE ਡੇਟਾਬੇਸਾਂ ਨਾਲ ਕਰਦੇ ਹਨ ਜੋ **ਲਗਾਤਾਰ ਵਧਦੇ** ਹਨ। ਇੱਕ PR ਜੋ **ਕਿਸੇ ਵੀ ਨਿਰਭਰਤਾ ਨੂੰ ਨਹੀਂ ਛੂਹਦਾ** ਅਚਾਨਕ ਲਾਲ ਹੋ ਸਕਦਾ ਹੈ ਕਿਉਂਕਿ ਇੱਕ ਮੌਜੂਦਾ dep ਵਿੱਚ ਇੱਕ ਨਵਾਂ CVE ਪ੍ਰਗਟ ਹੋਇਆ ਸੀ (osv: ਮਾਪਿਆ `vulnCount` > ਬੇਸਲਾਈਨ; Trivy: ਚਿੱਤਰ ਵਿੱਚ ਇੱਕ ਨਵਾਂ ਠੀਕ ਹੋਣ ਯੋਗ CRITICAL)। **ਇਹ ਇੱਕ ਬਲੌਕਿੰਗ CVE ਗੇਟ ਦਾ ਅਨੁਮਾਨਿਤ ਸੰਚਾਲਨ ਵਿਵਹਾਰ ਹੈ, ਨਾ ਕਿ ਇੱਕ ਉਤਪਾਦ ਰਿਗਰੈਸ਼ਨ।**

ਜਦੋਂ ਇੱਕ ਨਵੇਂ ਪ੍ਰਗਟ ਹੋਏ CVE ਕਾਰਨ osv ਜਾਂ Trivy ਲਾਲ ਹੋ ਜਾਂਦੇ ਹਨ, ਤਾਂ ਉਪਾਅ ਇਹ ਹੈ:

1.  **ਪ੍ਰਭਾਵਿਤ dep ਨੂੰ ਅੱਪਗ੍ਰੇਡ ਕਰੋ** (ਤਰਜੀਹੀ) — `package.json` `overrides` (ਟ੍ਰਾਂਜ਼ਿਟਿਵ deps) ਰਾਹੀਂ ਪੈਚ ਕੀਤੇ ਸੰਸਕਰਣ ਵਿੱਚ ਅੱਪਗ੍ਰੇਡ ਕਰੋ ਜਾਂ ਇੱਕ ਪੈਚ ਕੀਤੇ ਬੇਸ 'ਤੇ ਚਿੱਤਰ ਨੂੰ ਦੁਬਾਰਾ ਬਣਾਓ।
2.  **ਜੇਕਰ ਕੋਈ ਅੱਪਸਟ੍ਰੀਮ ਫਿਕਸ ਨਹੀਂ ਹੈ:**
    - **osv:** `config/quality/quality-baseline.json` ਵਿੱਚ `metrics.vulnCount` ਨੂੰ ਦੁਬਾਰਾ ਬੇਸਲਾਈਨ ਕਰੋ (`npm run quality:ratchet -- --update` ਸਮਰਪਿਤ ਗੇਟਾਂ ਨੂੰ ਕਵਰ ਨਹੀਂ ਕਰਦਾ — ਮੁੱਲ ਨੂੰ ਹੱਥੀਂ ਸੰਪਾਦਿਤ ਕਰੋ, `direction:down`) ਇੱਕ ਜਾਇਜ਼ ਨੋਟ + ਟਰੈਕਿੰਗ ਮੁੱਦੇ ਦੇ ਨਾਲ।
    - **Trivy:** `.trivyignore` ਵਿੱਚ ਇੱਕ ਐਂਟਰੀ ਸ਼ਾਮਲ ਕਰੋ (ਪ੍ਰਤੀ ਲਾਈਨ CVE-ID) ਇੱਕ ਜਾਇਜ਼ ਟਿੱਪਣੀ + ਟਰੈਕਿੰਗ ਮੁੱਦੇ ਦੇ ਨਾਲ। `ignore-unfixed: true` ਪੈਚਾਂ ਤੋਂ ਬਿਨਾਂ CVEs ਨੂੰ ਆਪਣੇ ਆਪ ਕਵਰ ਕਰਦਾ ਹੈ।

ਦੋਵੇਂ ਗੇਟ **ਨਰਮੀ ਨਾਲ ਛੱਡ ਦਿੰਦੇ ਹਨ** (exit 0) ਜਦੋਂ ਟੂਲ ਗੈਰਹਾਜ਼ਰ ਹੁੰਦਾ ਹੈ ਜਾਂ ਮਾਪ ਅਸਫਲ ਹੋ ਜਾਂਦਾ ਹੈ (osv-scanner PATH ਵਿੱਚ ਨਹੀਂ, osv.dev/ਨੈੱਟਵਰਕ ਪਹੁੰਚਯੋਗ ਨਹੀਂ, ਅਵੈਧ JSON) — ਇੱਕ **ਮਾਪ** ਅਸਫਲਤਾ ਕਦੇ ਵੀ ਬਲੌਕ ਨਹੀਂ ਕਰਦੀ, ਸਿਰਫ਼ ਇੱਕ **ਮਾਪਿਆ** ਰਿਗਰੈਸ਼ਨ ਬਲੌਕ ਕਰਦਾ ਹੈ।

## ਜਾਣੇ-ਪਛਾਣੇ ਸਵੀਕਾਰ ਕੀਤੇ ਜੋਖਮ

### extract-zip 2.0.1 — GHSA-7pqw-9j4j-h8q3 / GHSA-jmr9-qjv8-65gv (#14482)

`extract-zip@2.0.1` ਵਿੱਚ ਦੋ ਅਣਪੈਚਡ ਉੱਚ-ਗੰਭੀਰਤਾ ਵਾਲੀਆਂ ਸਿੰਮਲਿੰਕ-ਟ੍ਰੈਵਰਸਲ ਸਲਾਹਾਂ ਹਨ।
ਉਪਰੋਕਤ CVE ਵੇਰੀਐਂਸ ਉਪਾਅ ਦੀ "ਕੋਈ ਅੱਪਸਟ੍ਰੀਮ ਫਿਕਸ ਨਹੀਂ" ਸ਼ਾਖਾ ਦੇ ਅਨੁਸਾਰ, ਇਹ ਇੱਕ
**ਸਵੀਕਾਰ ਕੀਤਾ ਜੋਖਮ** ਹੈ, ਨਾ ਕਿ ਇੱਕ ਬੰਪ:

- **ਚੇਨ:** `promptfoo` (devDependency) → `@openai/codex-security` → `extract-zip@2.0.1`।
  `package-lock.json` ਰਾਹੀਂ ਪੁਸ਼ਟੀ ਕੀਤੀ ਗਈ — ਪੂਰੇ ਡਿਪੈਂਡੈਂਸੀ
  ਟ੍ਰੀ ਵਿੱਚ ਸਿਰਫ਼ ਇੱਕ ਪੈਕੇਜ (`@openai/codex-security`) `extract-zip` ਨੂੰ ਘੋਸ਼ਿਤ ਕਰਦਾ ਹੈ, ਅਤੇ ਸਿਰਫ਼ ਇੱਕ ਪੈਕੇਜ
  (`promptfoo`) `@openai/codex-security` ਨੂੰ ਘੋਸ਼ਿਤ ਕਰਦਾ ਹੈ।
- **ਚੇਨ ਵਿੱਚ ਕਿਤੇ ਵੀ ਕੋਈ ਨਿਸ਼ਚਿਤ ਰੀਲੀਜ਼ ਮੌਜੂਦ ਨਹੀਂ ਹੈ।** `extract-zip@2.0.1` (2020 ਵਿੱਚ ਪ੍ਰਕਾਸ਼ਿਤ) ਪੈਕੇਜ ਦੀ ਅੰਤਿਮ ਰੀਲੀਜ਼ ਹੈ — ਇਸਨੂੰ ਬਰਕਰਾਰ ਨਹੀਂ ਰੱਖਿਆ ਗਿਆ ਹੈ। `@openai/codex-security` ਦਾ
  ਮੌਜੂਦਾ npm-latest (`0.1.29`) ਅਜੇ ਵੀ `extract-zip@2.0.1` ਨੂੰ ਖਿੱਚਦਾ ਹੈ।
- **ਉਤਪਾਦਨ ਤੋਂ ਅਪਹੁੰਚਯੋਗ।** `promptfoo` ਸਿਰਫ਼ devDependency ਹੈ (ਕਦੇ ਵੀ `dependencies`
  ਦੇ ਅਧੀਨ ਸੂਚੀਬੱਧ ਨਹੀਂ), ਅਤੇ `src/`, `open-sse/`, ਜਾਂ `bin/` ਦੇ ਅਧੀਨ ਕੋਈ ਵੀ ਫਾਈਲ
  `extract-zip` npm ਪੈਕੇਜ ਨੂੰ ਆਯਾਤ ਨਹੀਂ ਕਰਦੀ — OmniRoute ਦਾ ਆਪਣਾ `extractZip()` ਹੈਲਪਰ
  (`src/lib/versionManager/binaryManager.ts:93`) ਮੂਲ `unzip`/`tar` ਨੂੰ ਸ਼ੈੱਲ ਕਰਦਾ ਹੈ
  ਅਤੇ ਅਸੰਬੰਧਿਤ ਹੈ। `@openai/codex-security` ਵੀ extract-zip ਦੇ onEntry ਕਾਲਬੈਕ ਦੇ ਸਿਖਰ 'ਤੇ ਆਪਣਾ ਸਿੰਮਲਿੰਕ-ਟ੍ਰੈਵਰਸਲ
  ਗਾਰਡ ਭੇਜਦਾ ਹੈ।
- **`package.json` `overrides` ਰਾਹੀਂ `extract-zip` ਨੂੰ ਉਪਨਾਮ ਨਾ ਦਿਓ** — ਇੱਕੋ ਇੱਕ ਵਿਹਾਰਕ
  ਡ੍ਰੌਪ-ਇਨ ਬਦਲ ਇਲੈਕਟ੍ਰੋਨ-ਆਰਗ-ਅੰਦਰੂਨੀ ਹੈ ਅਤੇ `@openai/codex-security` ਦੇ ਆਪਣੇ onEntry/defaultDirMode/defaultFileMode ਜਾਂਚਾਂ ਨਾਲ API-ਅਸੰਗਤ ਹੈ;
  ਇਸਨੂੰ ਓਵਰਰਾਈਡ ਕਰਨ ਨਾਲ ਉਸ ਪੈਕੇਜ ਦੀਆਂ ਸੁਰੱਖਿਆ ਜਾਂਚਾਂ ਚੁੱਪਚਾਪ ਟੁੱਟ ਜਾਣਗੀਆਂ।
- **ਬੇਸਲਾਈਨ:** ਮਾਪਿਆ ਗਿਆ osv `vulnCount` (3) ਪਹਿਲਾਂ ਹੀ ਫ੍ਰੋਜ਼ਨ
  `config/quality/quality-baseline.json` ਬੇਸਲਾਈਨ (27) ਤੋਂ ਬਹੁਤ ਘੱਟ ਹੈ — ਕਿਸੇ ਰੈਚੇਟ ਤਬਦੀਲੀ ਦੀ ਲੋੜ ਨਹੀਂ ਹੈ।
