OmniRoute ਪ੍ਰਸ਼ਾਸਕੀ ਕਾਰਵਾਈਆਂ, ਪ੍ਰਮਾਣੀਕਰਨ ਇਵੈਂਟਾਂ, ਪ੍ਰਦਾਤਾ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਜੀਵਨ-ਚੱਕਰ ਵਿੱਚ ਤਬਦੀਲੀਆਂ ਅਤੇ MCP ਟੂਲ ਇਨਵੋਕੇਸ਼ਨਾਂ ਨੂੰ SQLite-ਸਮਰਥਿਤ ਆਡਿਟ ਟੇਬਲਾਂ ਵਿੱਚ ਰਿਕਾਰਡ ਕਰਦਾ ਹੈ। ਇਹ ਪੰਨਾ ਦੱਸਦਾ ਹੈ ਕਿ ਕੀ ਲੌਗ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਇਹ ਕਿੱਥੇ ਸਟੋਰ ਹੁੰਦਾ ਹੈ, ਇਸਨੂੰ ਕਿੰਨੇ ਸਮੇਂ ਲਈ ਰੱਖਿਆ ਜਾਂਦਾ ਹੈ, API ਕੁੰਜੀਆਂ ਇਸ ਤੋਂ ਕਿਵੇਂ ਬਾਹਰ ਰਹਿਣ ਦੀ ਚੋਣ ਕਰ ਸਕਦੀਆਂ ਹਨ ਅਤੇ ਡੇਟਾ ਨੂੰ ਕਿਵੇਂ ਕਵੇਰੀ ਕਰਨਾ ਹੈ।

ਇਸਦਾ ਇੰਪਲੀਮੈਂਟੇਸ਼ਨ `src/lib/compliance/index.ts` (T-43 — "ਅਨੁਕੂਲਤਾ ਨਿਯੰਤਰਣ") ਅਤੇ `src/lib/compliance/providerAudit.ts` ਵਿੱਚ ਮੌਜੂਦ ਹੈ। ਆਡਿਟ ਲਿਖਤਾਂ ਕਦੇ ਵੀ ਐਰਰ ਨਹੀਂ ਸੁੱਟਦੀਆਂ: ਕਿਸੇ ਵੀ ਅਸਫਲਤਾ ਦੀ ਸਥਿਤੀ ਵਿੱਚ ਕਾਲ ਨੂੰ ਚੁੱਪਚਾਪ ਨਜ਼ਰਅੰਦਾਜ਼ ਕਰ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ, ਤਾਂ ਜੋ ਆਡਿਟ ਲੌਗਿੰਗ ਮੁੱਖ ਬੇਨਤੀ ਪ੍ਰਵਾਹ ਵਿੱਚ ਵਿਘਨ ਨਾ ਪਾ ਸਕੇ।

## ਕੀ ਲੌਗ ਕੀਤਾ ਜਾਂਦਾ ਹੈ

### ਪ੍ਰਸ਼ਾਸਕੀ ਆਡਿਟ ਇਵੈਂਟ (`audit_log`)

`logAuditEvent({ action, actor, target, details, ... })` ਲਈ ਹਰ ਕਾਲ ਇੱਕ ਕਤਾਰ ਬਣਾਉਂਦੀ ਹੈ। ਐਕਸ਼ਨ ਸਟ੍ਰਿੰਗਾਂ `domain.verb` (ਜਾਂ `domain.verb.outcome`) ਪੈਟਰਨ ਦੀ ਪਾਲਣਾ ਕਰਦੀਆਂ ਹਨ। ਕੋਡ-ਟ੍ਰੀ ਵਿੱਚ ਪੁਸ਼ਟੀ ਕੀਤੀਆਂ ਐਕਸ਼ਨ ਕਿਸਮਾਂ ਵਿੱਚ ਇਹ ਸ਼ਾਮਲ ਹਨ:

| ਐਕਸ਼ਨ                                | ਸਰੋਤ                                    |
| ------------------------------------ | --------------------------------------- |
| `auth.login.success`                 | `src/app/api/auth/login/route.ts`       |
| `auth.login.failed`                  | `src/app/api/auth/login/route.ts`       |
| `auth.login.locked`                  | `src/app/api/auth/login/route.ts`       |
| `auth.login.error`                   | `src/app/api/auth/login/route.ts`       |
| `auth.login.misconfigured`           | `src/app/api/auth/login/route.ts`       |
| `auth.login.setup_required`          | `src/app/api/auth/login/route.ts`       |
| `auth.logout.success`                | `src/app/api/auth/logout/route.ts`      |
| `provider.credentials.created`       | `src/app/api/providers/route.ts`        |
| `provider.credentials.updated`       | `src/app/api/providers/[id]/route.ts`   |
| `provider.credentials.revoked`       | `src/app/api/providers/[id]/route.ts`   |
| `provider.credentials.batch_revoked` | `src/app/api/providers/route.ts`        |
| `sync.token.created`                 | `src/app/api/sync/tokens/route.ts`      |
| `sync.token.revoked`                 | `src/app/api/sync/tokens/[id]/route.ts` |
| `compliance.cleanup`                 | `src/lib/compliance/index.ts`           |

ਹਰ ਐਂਟਰੀ `action`, `actor` (ਡਿਫਾਲਟ ਰੂਪ ਵਿੱਚ `"system"`), `target`, `details`/`metadata` (JSON), `ip_address`, `resource_type`, `status`, `request_id` ਅਤੇ `timestamp` ਨੂੰ ਕੈਪਚਰ ਕਰਦੀ ਹੈ। ਸੰਵੇਦਨਸ਼ੀਲ ਕੁੰਜੀਆਂ (`apiKey`, `accessToken`, `refreshToken`, `password`, `*token`/`*secret`/`*apikey` ਨਾਲ ਮੇਲ ਖਾਂਦੀ ਕੋਈ ਵੀ ਚੀਜ਼, ਆਦਿ) ਨੂੰ ਕਤਾਰ ਲਿਖੇ ਜਾਣ ਤੋਂ ਪਹਿਲਾਂ ਰਿਕਰਸਿਵ ਢੰਗ ਨਾਲ `"[redacted]"` ਵਿੱਚ ਰੀਡੈਕਟ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।

### ਬੇਨਤੀ / ਵਰਤੋਂ ਲੌਗ

ਇਹ ਸੰਚਾਲਨਾਤਮਕ ਟੈਲੀਮੀਟਰੀ ਹਨ (ਸਖ਼ਤੀ ਨਾਲ ਪ੍ਰਸ਼ਾਸਕੀ ਆਡਿਟ ਨਹੀਂ), ਪਰ ਇੱਕੋ ਰਿਟੇਨਸ਼ਨ ਪਾਈਪਲਾਈਨ ਸਾਂਝੀ ਕਰਦੇ ਹਨ:

- `usage_history` — ਹਰ ਬੇਨਤੀ ਲਈ ਵਰਤੋਂ ਦਾ ਇਕੱਠਾ ਸਾਰ
- `call_logs` — ਹਰ ਬੇਨਤੀ ਦਾ ਪੂਰਾ ਲੌਗ (ਕਤਾਰ ਸੀਮਾ ਦੇ ਅਧੀਨ, ਹੇਠਾਂ ਵੇਖੋ)
- `proxy_logs` — ਪ੍ਰੌਕਸੀ ਟ੍ਰੈਫਿਕ ਲੌਗ (ਕਤਾਰ ਸੀਮਾ ਦੇ ਅਧੀਨ)
- `request_detail_logs` — ਵਿਰਾਸਤੀ ਵਿਸਤ੍ਰਿਤ ਬੇਨਤੀ ਲੌਗ (ਮੌਜੂਦ ਹੋਣ 'ਤੇ ਅਜੇ ਵੀ ਛਾਂਟਿਆ ਜਾਂਦਾ ਹੈ)

## ਸਟੋਰੇਜ ਸਕੀਮਾ

ਪਹਿਲੀ ਵਰਤੋਂ ਵੇਲੇ `audit_log` ਨੂੰ `ensureAuditLogSchema()` ਦੁਆਰਾ ਲੋੜ ਅਨੁਸਾਰ ਬਣਾਇਆ ਜਾਂਦਾ ਹੈ:

```sql
CREATE TABLE IF NOT EXISTS audit_log (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  timestamp     TEXT NOT NULL DEFAULT (datetime('now')),
  action        TEXT NOT NULL,
  actor         TEXT NOT NULL DEFAULT 'system',
  target        TEXT,
  details       TEXT,
  ip_address    TEXT,
  resource_type TEXT,
  status        TEXT,
  request_id    TEXT,
  metadata      TEXT
);
```

ਇੰਡੈਕਸ `timestamp`, `action`, `actor`, `resource_type`, `status`, ਅਤੇ `request_id` ਉੱਤੇ ਬਣਾਏ ਜਾਂਦੇ ਹਨ। ਪੁਰਾਣੇ DBs ਵਿੱਚ ਗੁੰਮ ਕਾਲਮ ਲੋੜ ਪੈਣ 'ਤੇ `ALTER TABLE` ਰਾਹੀਂ ਜੋੜੇ ਜਾਂਦੇ ਹਨ।

## ਰਿਟੈਂਸ਼ਨ ਅਤੇ ਸਫ਼ਾਈ

ਦੋ ਵੱਖ-ਵੱਖ ਰਿਟੈਂਸ਼ਨ ਮਿਆਦਾਂ ਦੀ ਪਾਲਣਾ ਕੀਤੀ ਜਾਂਦੀ ਹੈ:

| ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲ             | ਡਿਫਾਲਟ   | ਇਸ ਉੱਤੇ ਲਾਗੂ ਹੁੰਦਾ ਹੈ                                             |
| --------------------------- | -------- | ----------------------------------------------------------------- |
| `APP_LOG_RETENTION_DAYS`    | `7`      | `audit_log`, `mcp_tool_audit`                                     |
| `CALL_LOG_RETENTION_DAYS`   | `7`      | `usage_history`, `call_logs`, `proxy_logs`, `request_detail_logs` |
| `CALL_LOGS_TABLE_MAX_ROWS`  | `100000` | `call_logs` ਲਈ ਕਤਾਰ-ਸੀਮਾ ਅਨੁਸਾਰ ਛਾਂਟੀ                             |
| `PROXY_LOGS_TABLE_MAX_ROWS` | `100000` | `proxy_logs` ਲਈ ਕਤਾਰ-ਸੀਮਾ ਅਨੁਸਾਰ ਛਾਂਟੀ                            |

`cleanupExpiredLogs()` ਰਿਟੈਂਸ਼ਨ ਪਾਸ ਚਲਾਉਂਦਾ ਹੈ। ਇਸਨੂੰ ਸਰਵਰ ਸਟਾਰਟਅੱਪ ਵੇਲੇ `src/instrumentation-node.ts` ਤੋਂ ਚਲਾਇਆ ਜਾਂਦਾ ਹੈ। ਹਰ ਰਨ ਪ੍ਰਤੀ-ਟੇਬਲ ਮਿਟਾਉਣ ਦੀ ਗਿਣਤੀ ਸਮੇਤ ਇੱਕ `compliance.cleanup` ਆਡਿਟ ਇਵੈਂਟ ਲੌਗ ਕਰਦਾ ਹੈ। ਲੰਬੇ ਰਾਈਟ ਲੌਕਾਂ ਤੋਂ ਬਚਣ ਲਈ ਪ੍ਰੌਕਸੀ/ਕਾਲ ਲੌਗ ਦੀ ਛਾਂਟੀ ਬੈਚਾਂ ਵਿੱਚ ਕੀਤੀ ਜਾਂਦੀ ਹੈ (`BATCH_SIZE = 5000`)।

ਦਸਤੀ ਰਿਕਵੇਸਟ-ਹਿਸਟਰੀ ਸਫ਼ਾਈ ਰਿਟੈਂਸ਼ਨ ਤੋਂ ਵੱਖਰੀ ਹੈ। Request Logs ਪੰਨਾ `POST /api/settings/purge-request-history` ਨੂੰ ਕਾਲ ਕਰਦਾ ਹੈ, ਜੋ `call_logs`, ਪੁਰਾਣੇ `request_detail_logs`, ਅਤੇ `${DATA_DIR}/call_logs/` ਅਧੀਨ ਸਥਾਨਕ ਰਿਕਵੇਸਟ ਆਰਟੀਫੈਕਟ ਮਿਟਾਉਂਦਾ ਹੈ।

ਡਿਫਾਲਟ `src/lib/logEnv.ts` ਵਿੱਚ ਪਰਿਭਾਸ਼ਿਤ ਹਨ
(`DEFAULT_APP_LOG_RETENTION_DAYS = 7`, `DEFAULT_CALL_LOG_RETENTION_DAYS = 7`)।

## `noLog` ਔਪਟ-ਆਉਟ (ਪ੍ਰਤੀ API ਕੁੰਜੀ)

API ਕੁੰਜੀਆਂ ਨੂੰ ਇਸ ਤਰ੍ਹਾਂ ਫਲੈਗ ਕੀਤਾ ਜਾ ਸਕਦਾ ਹੈ ਕਿ ਉਨ੍ਹਾਂ ਦਾ ਡਾਊਨਸਟ੍ਰੀਮ ਕਾਲ ਟ੍ਰੈਫਿਕ ਲੌਗ ਨਾ ਕੀਤਾ ਜਾਵੇ। ਇਹ ਫਲੈਗ `api_keys` ਟੇਬਲ (`no_log INTEGER DEFAULT 0`) ਵਿੱਚ ਰਹਿੰਦਾ ਹੈ ਅਤੇ ਤੇਜ਼-ਪਾਥ ਲੁੱਕਅੱਪਾਂ ਲਈ ਇੱਕ ਇਨ-ਮੈਮੋਰੀ ਸੈੱਟ ਵਿੱਚ ਵੀ ਪ੍ਰਤੀਬਿੰਬਿਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।

```bash
# ਇੱਕ ਨੋ-ਲੌਗ ਕੁੰਜੀ ਬਣਾਓ (ਪ੍ਰਬੰਧਨ ਪ੍ਰਮਾਣੀਕਰਨ ਲੋੜੀਂਦਾ ਹੈ)
curl -X POST http://localhost:20128/api/keys \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"name": "Privacy key", "noLog": true}'
```

ਸਹਾਇਕ (`src/lib/compliance/index.ts`):

- `setNoLog(apiKeyId, true|false)` — ਇਨ-ਮੈਮੋਰੀ ਐਂਟਰੀ ਨੂੰ ਟੌਗਲ ਕਰੋ
- `isNoLog(apiKeyId)` — ਰਿਕਵੇਸਟ ਪਾਥ ਉੱਤੇ ਜਾਂਚਿਆ ਜਾਂਦਾ ਹੈ; `api_keys.no_log` ਤੋਂ 30 s ਲਈ ਕੈਸ਼ ਕੀਤੀ ਰੀਡ ਨੂੰ ਫਾਲਬੈਕ ਵਜੋਂ ਵਰਤਦਾ ਹੈ
- `NO_LOG_API_KEY_IDS` (ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲ, ਕੌਮੇ ਨਾਲ ਵੱਖ ਕੀਤੇ) — ਬੂਟ ਵੇਲੇ ਇਨ-ਮੈਮੋਰੀ ਸੈੱਟ ਵਿੱਚ ਪਹਿਲਾਂ ਤੋਂ ਲੋਡ ਕੀਤੇ ਜਾਂਦੇ ਹਨ; ਇਹ ਉਦੋਂ ਲਾਭਦਾਇਕ ਹੈ ਜਦੋਂ ਤੁਸੀਂ ਕਾਲਮ ਨੂੰ ਸਿੱਧੇ ਟੌਗਲ ਨਹੀਂ ਕਰ ਸਕਦੇ

ਪ੍ਰਸ਼ਾਸਕੀ ਆਡਿਟ ਇਵੈਂਟ (ਲੌਗਇਨ, ਪ੍ਰਦਾਤਾ ਬਦਲਾਅ, MCP ਟੂਲ ਕਾਲਾਂ, ਆਦਿ) `noLog` ਤੋਂ ਪ੍ਰਭਾਵਿਤ **ਨਹੀਂ** ਹੁੰਦੇ — ਸਿਰਫ਼ ਪ੍ਰਤੀ-ਰਿਕਵੇਸਟ ਟ੍ਰੈਫਿਕ ਲੌਗਿੰਗ ਤੋਂ ਔਪਟ-ਆਉਟ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।

ਇਸ ਵੇਲੇ ਕੋਈ CSV ਐਕਸਪੋਰਟ ਐਂਡਪੌਇੰਟ ਉਪਲਬਧ ਨਹੀਂ ਹੈ — ਡੈਸ਼ਬੋਰਡ ਤੋਂ ਐਕਸਪੋਰਟ ਕਰੋ ਜਾਂ
SQLite ਡੇਟਾਬੇਸ ਨੂੰ ਸਿੱਧਾ ਕਵੇਰੀ ਕਰੋ।

### `/api/compliance/audit-log` ਨੂੰ ਕਵੇਰੀ ਕਰਨਾ

ਸਮਰਥਿਤ ਕਵੇਰੀ ਪੈਰਾਮੀਟਰ (ਸਾਰੇ ਵਿਕਲਪਿਕ ਹਨ, ਸਾਰੇ ਟੈਕਸਟ ਫ਼ਿਲਟਰਾਂ ਲਈ
`LIKE %value%` ਮਿਲਾਨ ਵਰਤਦੇ ਹਨ):

- `action`, `actor`, `target`, `resourceType` (ਜਾਂ `resource_type`),
  `status`, `requestId` (ਜਾਂ `request_id`)
- `from` / `since`, `to` / `until` — ISO ਟਾਈਮਸਟੈਂਪ
- `limit` (ਡਿਫਾਲਟ `50`, ਘੱਟੋ-ਘੱਟ `1`, ਵੱਧ ਤੋਂ ਵੱਧ `500`)
- `offset` (ਡਿਫਾਲਟ `0`, ਵੱਧ ਤੋਂ ਵੱਧ `10_000`)

ਜਵਾਬ ਇੱਕ JSON ਐਰੇ ਹੁੰਦਾ ਹੈ। ਪੰਨਾਬੰਦੀ ਮੈਟਾਡੇਟਾ ਹੈਡਰਾਂ ਵਿੱਚ ਵਾਪਸ ਕੀਤਾ ਜਾਂਦਾ ਹੈ:
`x-total-count`, `x-page-limit`, `x-page-offset`।

```bash
curl "http://localhost:20128/api/compliance/audit-log?action=provider.credentials&from=2026-05-01" \
  -H "Cookie: auth_token=..."
```

## ਡੈਸ਼ਬੋਰਡ

ਡੈਸ਼ਬੋਰਡ ਆਡਿਟ ਡੇਟਾ ਨੂੰ **`/dashboard/audit`**
(`src/app/(dashboard)/dashboard/audit/page.tsx`) ਉੱਤੇ ਉਪਲਬਧ ਕਰਵਾਉਂਦਾ ਹੈ। ਪੰਨੇ ਵਿੱਚ ਦੋ ਟੈਬਾਂ ਹਨ:

- **ਅਨੁਪਾਲਨਾ** (`ComplianceTab.tsx`) — `/api/compliance/audit-log` ਤੋਂ ਐਡਮਿਨ ਆਡਿਟ ਇਵੈਂਟ।
  ਇਵੈਂਟ ਕਿਸਮ, ਗੰਭੀਰਤਾ (ਜਾਣਕਾਰੀ / ਚੇਤਾਵਨੀ / ਗੰਭੀਰ, ਜੋ ਐਕਸ਼ਨ + ਸਥਿਤੀ ਤੋਂ
  ਪ੍ਰਾਪਤ ਕੀਤੀ ਜਾਂਦੀ ਹੈ), ਅਤੇ ਮਿਤੀ ਸੀਮਾ ਮੁਤਾਬਕ ਫ਼ਿਲਟਰ। ਗੰਭੀਰਤਾ ਦੀ ਗਣਨਾ
  ਐਕਸ਼ਨ/ਸਥਿਤੀ ਸਟ੍ਰਿੰਗਾਂ ਤੋਂ ਕਲਾਇੰਟ ਪਾਸੇ ਕੀਤੀ ਜਾਂਦੀ ਹੈ।
- **MCP** (`McpAuditTab.tsx`) — `/api/mcp/audit` ਤੋਂ MCP ਟੂਲ ਆਡਿਟ, ਜਿਸ ਵਿੱਚ
  ਟੂਲ ਦੇ ਨਾਮ ਅਤੇ ਸਫਲਤਾ/ਅਸਫਲਤਾ ਮੁਤਾਬਕ ਫ਼ਿਲਟਰ ਹਨ।

ਦੋਵੇਂ ਟੈਬਾਂ ਕ੍ਰਮਵਾਰ `50` (ਅਨੁਪਾਲਨਾ) ਅਤੇ `25` (MCP) ਦੇ ਪੰਨਾ ਆਕਾਰਾਂ ਨਾਲ ਪੰਨਾਬੰਦੀ ਕਰਦੀਆਂ ਹਨ।

## ਪ੍ਰੋਵਾਈਡਰ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਸਹਾਇਕ

`src/lib/compliance/providerAudit.ts` ਪ੍ਰੋਵਾਈਡਰ-ਪ੍ਰਬੰਧਨ ਰੂਟਾਂ ਵੱਲੋਂ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ
ਇਵੈਂਟ ਜਾਰੀ ਕਰਨ ਵੇਲੇ ਵਰਤੇ ਜਾਣ ਵਾਲੇ ਰੂਪ-ਨਿਰਧਾਰਣ ਸਹਾਇਕ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ:

- `summarizeProviderConnectionForAudit(connection)` — ਕਨੈਕਸ਼ਨ ਸਨੈਪਸ਼ਾਟ ਨੂੰ
  `details` ਵਿੱਚ ਲਿਖੇ ਜਾਣ ਤੋਂ ਪਹਿਲਾਂ `apiKey`, `accessToken`, `refreshToken`,
  `idToken`, ਅਤੇ `providerSpecificData.consoleApiKey` ਨੂੰ ਹਟਾਉਂਦਾ ਹੈ।
- `getProviderAuditTarget(connection)` — `target` ਫ਼ੀਲਡ ਲਈ ਇੱਕ ਸਥਿਰ
  `"<provider>:<name|id>"` ਸਟ੍ਰਿੰਗ ਬਣਾਉਂਦਾ ਹੈ।
- `extractProviderWarnings(...payloads)` — ਨੀਤੀ/ਸੁਰੱਖਿਆ ਚੇਤਾਵਨੀਆਂ
  (`[sanitizer]`, `prompt injection detected`, `content has been filtered`,
  `safety filter`, `policy violation`) ਲਈ ਪ੍ਰੋਵਾਈਡਰ ਜਵਾਬਾਂ ਨੂੰ ਸਕੈਨ ਕਰਦਾ ਹੈ ਅਤੇ
  ਵੱਧ ਤੋਂ ਵੱਧ 5 ਮਿਲਾਨ ਸਾਹਮਣੇ ਲਿਆਉਂਦਾ ਹੈ, ਜਿਨ੍ਹਾਂ ਵਿੱਚੋਂ ਹਰ ਇੱਕ ਨੂੰ 400 ਅੱਖਰਾਂ ਤੱਕ ਕੱਟਿਆ ਜਾਂਦਾ ਹੈ।

## ਸਰਵੋਤਮ ਅਭਿਆਸ

- PII (ਕਾਨੂੰਨੀ, ਮੈਡੀਕਲ ਆਦਿ) ਸੰਭਾਲਣ ਵਾਲੀਆਂ API ਕੁੰਜੀਆਂ ਨੂੰ `noLog: true` ਨਾਲ ਨਿਸ਼ਾਨਬੱਧ ਕਰੋ।
- ਆਪਣੀ ਡੇਟਾ-ਰੱਖਿਆ ਨੀਤੀ ਪੂਰੀ ਕਰਨ ਲਈ `APP_LOG_RETENTION_DAYS` /
  `CALL_LOG_RETENTION_DAYS` ਨੂੰ ਅਨੁਕੂਲ ਕਰੋ। 7-ਦਿਨਾਂ ਦੇ ਡਿਫਾਲਟ ਸੰਭਲ ਕੇ ਰੱਖੇ ਗਏ ਹਨ।
- ਆਪਣੇ ਅਨੁਪਾਲਨਾ ਪ੍ਰੋਗਰਾਮ ਵੱਲੋਂ ਲੋੜੀਂਦੀ ਸਮਾਂ-ਸਾਰਣੀ ਅਨੁਸਾਰ ਆਡਿਟ ਟੇਬਲ ਨੂੰ
  ਪਲੇਟਫਾਰਮ ਤੋਂ ਬਾਹਰ (`sqlite3 dump`) ਐਕਸਪੋਰਟ ਕਰੋ — ਕੋਈ ਬਿਲਟ-ਇਨ ਆਰਕਾਈਵਿੰਗ ਮੌਜੂਦ ਨਹੀਂ ਹੈ।
- ਬਰੂਟ-ਫੋਰਸ ਪਛਾਣ ਲਈ `auth.login.failed` ਅਤੇ `auth.login.locked` ਦੀਆਂ ਗਿਣਤੀਆਂ ਨੂੰ ਟਰੈਕ ਕਰੋ।
- ਨਵੇਂ ਐਡਮਿਨ ਐਂਡਪੌਇੰਟ ਜੋੜਦੇ ਸਮੇਂ, ਇੱਕ ਸਥਿਰ `domain.verb.outcome` ਐਕਸ਼ਨ ਸਟ੍ਰਿੰਗ ਨਾਲ
  `logAuditEvent({ ... })` ਨੂੰ ਕਾਲ ਕਰੋ ਅਤੇ ਬੇਨਤੀ ਸੰਦਰਭ ਨੂੰ
  `getAuditRequestContext(request)` ਰਾਹੀਂ ਪਾਸ ਕਰੋ, ਤਾਂ ਜੋ IP ਅਤੇ `requestId`
  ਆਪਣੇ-ਆਪ ਕੈਪਚਰ ਹੋ ਜਾਣ।
