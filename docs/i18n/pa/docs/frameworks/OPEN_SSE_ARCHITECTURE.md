> **ਸੰਖੇਪ ਵਿੱਚ**: `open-sse/` ਮੁੱਖ ਸਟ੍ਰੀਮਿੰਗ ਇੰਜਣ ਹੈ ਜੋ OmniRoute ਵਿੱਚ ਹਰ LLM ਬੇਨਤੀ ਨੂੰ ਚਲਾਉਂਦਾ ਹੈ। ਇਸ ਵਿੱਚ ਬੇਨਤੀ ਪਾਈਪਲਾਈਨ, ਐਗਜ਼ਿਕਿਊਟਰਾਂ, ਸੇਵਾਵਾਂ, MCP ਸਰਵਰ ਅਤੇ ਅਨੁਵਾਦ ਪਰਤ ਨੂੰ ਲਾਗੂ ਕਰਨ ਵਾਲੀਆਂ ~1,400 ਫਾਈਲਾਂ ਹਨ। ਇਹ ਗਾਈਡ ਸਮਝਾਉਂਦੀ ਹੈ ਕਿ ਇਹ ਹਿੱਸੇ ਆਪਸ ਵਿੱਚ ਕਿਵੇਂ ਜੁੜਦੇ ਹਨ।

**ਸਰੋਤ:** `open-sse/` (ਵਰਕਸਪੇਸ ਪੈਕੇਜ, ~1,440 ਗੈਰ-ਟੈਸਟ `.ts` ਫਾਈਲਾਂ)

## ਵੱਖਰਾ ਵਰਕਸਪੇਸ ਪੈਕੇਜ ਕਿਉਂ?

`open-sse/` ਕਈ ਕਾਰਨਾਂ ਕਰਕੇ OmniRoute monorepo ਵਿੱਚ ਇੱਕ **ਸੁਤੰਤਰ ਵਰਕਸਪੇਸ** ਹੈ:

1. **ਮੁੜ ਵਰਤੋਂਯੋਗਤਾ** — `open-sse` ਨੂੰ npm ਉੱਤੇ `@omniroute/open-sse` ਵਜੋਂ ਪ੍ਰਕਾਸ਼ਿਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਇਸ ਲਈ ਹੋਰ ਪ੍ਰੋਜੈਕਟ ਇਸਨੂੰ ਸੁਤੰਤਰ ਤੌਰ 'ਤੇ ਵਰਤ ਸਕਦੇ ਹਨ
2. **ਸਪਸ਼ਟ ਹੱਦਾਂ** — ਸਟ੍ਰੀਮਿੰਗ ਇੰਜਣ ਨੂੰ OmniRoute-ਵਿਸ਼ੇਸ਼ UI/DB ਪਰਤ ਤੋਂ ਅਲੱਗ ਰੱਖਿਆ ਗਿਆ ਹੈ
3. **ਕਾਰਗੁਜ਼ਾਰੀ** — ਇੰਜਣ ਦੀਆਂ ਕੋਈ Next.js ਨਿਰਭਰਤਾਵਾਂ ਨਹੀਂ ਹਨ, ਜਿਸ ਨਾਲ CLI/serverless ਸੰਦਰਭਾਂ ਵਿੱਚ ਕੋਲਡ ਸਟਾਰਟ ਤੇਜ਼ ਹੁੰਦੇ ਹਨ
4. **ਵਰਜ਼ਨਿੰਗ** — `open-sse` ਆਪਣੀ ਸਮਾਂ-ਸਾਰਣੀ ਅਨੁਸਾਰ ਰਿਲੀਜ਼ ਕਰ ਸਕਦਾ ਹੈ

```json
// package.json
"workspaces": ["open-sse"]
```

```

   HTTP ਬੇਨਤੀ                 │  1. ਰਾਊਟ     │   ਕੌਂਬੋ ਹੱਲ ਕਰਨਾ, ਮਾਡਲ ਚੋਣ
   (Next.js ਰੂਟ)              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  2. ਅਨੁਵਾਦ   │   ਫਾਰਮੈਟ ਰੂਪਾਂਤਰਨ (OpenAI ↔ Claude ↔ Gemini)
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  3. ਚਲਾਓ     │   ਪ੍ਰਦਾਤਾ ਐਗਜ਼ਿਕਿਊਟਰ, HTTP, ਮੁੜ ਕੋਸ਼ਿਸ਼, ਬ੍ਰੇਕਰ
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  4. ਸਟ੍ਰੀਮ    │   SSE ਰੂਪਾਂਤਰਨ, ਬੈਕਪ੍ਰੈਸ਼ਰ
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  5. ਦਰਜ ਕਰੋ  │   ਵਰਤੋਂ ਟ੍ਰੈਕਿੰਗ, ਕਾਲ ਲੌਗ, ਗਲਤੀ ਵਰਗੀਕਰਨ
                              └──────┬───────┘
                                     │
                                     ▼
                              HTTP ਜਵਾਬ (SSE ਜਾਂ JSON)
```

### ਪੜਾਅ 1: ਰਾਊਟ (services/combo.ts)

**ਐਂਟਰੀ ਪੁਆਇੰਟ**: `services/combo.ts` ਵਿੱਚ `handleComboChat()`

ਬੇਨਤੀ ਨੂੰ ਇੱਕ ਠੋਸ `(provider, model, account, credentials)` ਟਿਊਪਲ ਨਾਲ ਮਿਲਾਉਂਦਾ ਹੈ:

- ID ਰਾਹੀਂ ਕੌਂਬੋ ਲੱਭੋ (ਜਾਂ `auto/*` ਮਾਡਲਾਂ ਲਈ ਇੱਕ ਵਰਚੁਅਲ ਕੌਂਬੋ ਬਣਾਓ)
- ਰਾਊਟਿੰਗ ਰਣਨੀਤੀ ਲਾਗੂ ਕਰੋ (ਤਰਜੀਹ, ਭਾਰਿਤ, ਰਾਊਂਡ-ਰੌਬਿਨ, ਆਦਿ)
- ਅਸਿਹਤਮੰਦ ਪ੍ਰਦਾਤਾਵਾਂ ਨੂੰ ਫਿਲਟਰ ਕਰੋ (ਸਰਕਿਟ ਬ੍ਰੇਕਰ)
- ਅਗਲਾ ਵਿਹਾਰਯੋਗ ਟਾਰਗੇਟ ਚੁਣੋ

`auto/*` ਮਾਡਲਾਂ ਲਈ, ਇਹ ਪੜਾਅ ਇਹ ਵੀ ਕਰਦਾ ਹੈ:

- **16-ਕਾਰਕ ਸਕੋਰਿੰਗ** ਐਲਗੋਰਿਦਮ (`services/autoCombo/`) ਚਲਾਉਂਦਾ ਹੈ
- ਸਿਹਤ, ਲਾਗਤ, ਲੇਟੈਂਸੀ ਆਦਿ ਦੇ ਆਧਾਰ 'ਤੇ ਇੱਕ `provider+model` ਜੋੜਾ ਚੁਣਦਾ ਹੈ

### ਪੜਾਅ 2: ਅਨੁਵਾਦ (translator/)

ਜੇ ਸਰੋਤ ਫਾਰਮੈਟ (ਉਦਾਹਰਨ ਲਈ, OpenAI) ਟਾਰਗੇਟ ਫਾਰਮੈਟ (ਉਦਾਹਰਨ ਲਈ, Claude) ਤੋਂ ਵੱਖਰਾ ਹੈ, ਤਾਂ ਬੇਨਤੀ ਦਾ **ਅਨੁਵਾਦ** ਕੀਤਾ ਜਾਂਦਾ ਹੈ:

- ਸਿਸਟਮ ਪ੍ਰੌਂਪਟ → ਸਿਸਟਮ ਸੁਨੇਹਾ
- ਟੂਲ ਪਰਿਭਾਸ਼ਾਵਾਂ → ਪ੍ਰਦਾਤਾ-ਵਿਸ਼ੇਸ਼ ਟੂਲ ਫਾਰਮੈਟ
- ਰੀਜ਼ਨਿੰਗ/ਥਿੰਕਿੰਗ ਪੈਰਾਮੀਟਰ → ਪ੍ਰਦਾਤਾ-ਵਿਸ਼ੇਸ਼ ਸਮਤੁੱਲ
- ਸੁਨੇਹਾ ਭੂਮਿਕਾ ਸਧਾਰਨੀਕਰਨ (ਗੈਰ-OpenAI ਲਈ `developer` → `system`)

`translator/index.ts` ਇਹ ਉਪਲਬਧ ਕਰਦਾ ਹੈ:

```ts
translateRequest(body, sourceFormat, targetFormat): TranslatedRequest
needsTranslation(source, target): boolean
```

### ਪੜਾਅ 3: ਚਲਾਉਣਾ (executors/)

**ਐਂਟਰੀ ਪੁਆਇੰਟ**: `getExecutor(providerId).execute(request, options)`

ਸਾਰੇ ਪ੍ਰਦਾਤਾ `getExecutor()` ਫੈਕਟਰੀ ਫਾਲਬੈਕ ਰਾਹੀਂ `DefaultExecutor` (`executors/default.ts`) ਦੀ ਵਰਤੋਂ ਕਰਦੇ ਹਨ। ਐਗਜ਼ਿਕਿਊਟਰ:

- ਅੱਪਸਟ੍ਰੀਮ URL ਬਣਾਉਂਦਾ ਹੈ (`buildUrl()`)
- ਪ੍ਰਦਾਤਾ-ਵਿਸ਼ੇਸ਼ ਹੈਡਰ ਜੋੜਦਾ ਹੈ (`buildHeaders()`)
- ਬੇਨਤੀ ਬਾਡੀ ਨੂੰ ਰੂਪਾਂਤਰਿਤ ਕਰਦਾ ਹੈ (`transformRequest()`)
- ਮੁੜ ਕੋਸ਼ਿਸ਼ + ਐਕਸਪੋਨੇਨਸ਼ੀਅਲ ਬੈਕਆਫ਼ ਨਾਲ HTTP ਬੇਨਤੀ ਭੇਜਦਾ ਹੈ
- ਲੋੜ ਪੈਣ 'ਤੇ ਪ੍ਰਮਾਣੀਕਰਨ ਰਿਫ੍ਰੈਸ਼ ਸੰਭਾਲਦਾ ਹੈ (OAuth ਪ੍ਰਦਾਤਾ)

ਸਾਰੇ ਐਗਜ਼ਿਕਿਊਟਰ `BaseExecutor` (`executors/base.ts`, 1170 LOC) ਨੂੰ ਵਿਸਤਾਰਦੇ ਹਨ, ਜੋ ਇਹ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ:

- ਸਾਂਝਾ ਮੁੜ-ਕੋਸ਼ਿਸ਼ ਤਰਕ
- ਪ੍ਰੌਕਸੀ ਏਕੀਕਰਨ
- ਸਰਕਿਟ ਬ੍ਰੇਕਰ ਏਕੀਕਰਨ
- ਵਰਤੋਂ ਦਰਜ ਕਰਨ ਵਾਲੇ ਹੁੱਕ

### ਪੜਾਅ 4: ਸਟ੍ਰੀਮ (utils/stream.ts)

ਸਟ੍ਰੀਮਿੰਗ ਜਵਾਬਾਂ ਲਈ, ਐਗਜ਼ਿਕਿਊਟਰ ਇੱਕ **ReadableStream** ਵਾਪਸ ਕਰਦਾ ਹੈ। ਹੈਂਡਲਰ:

- ਇੱਕ SSE ਟ੍ਰਾਂਸਫਾਰਮ (`createSSETransformStreamWithLogger`) ਵਿੱਚੋਂ ਪਾਈਪ ਕਰਦਾ ਹੈ
- ਨਿਸ਼ਕ੍ਰਿਆ ਕਨੈਕਸ਼ਨਾਂ ਦਾ ਪਤਾ ਲਗਾਉਣ ਲਈ ਹਾਰਟਬੀਟ ਪਿੰਗ ਲਾਗੂ ਕਰਦਾ ਹੈ

### chatCore.ts (5977 ਲਾਈਨਾਂ)

**ਮੁੱਖ ਬੇਨਤੀ ਹੈਂਡਲਰ**। ਆਪਣੇ ਆਕਾਰ ਦੇ ਬਾਵਜੂਦ, ਇਸਦੀ ਇੱਕ ਸਪਸ਼ਟ ਬਣਤਰ ਹੈ:

```ts
// chatCore.ts ਦੀ ਛਦਮ-ਬਣਤਰ
export async function handleChat(request: NextRequest) {
  // 1. ਪ੍ਰਮਾਣਿਕਤਾ + CORS
  await authenticateRequest(request);
  applyCorsHeaders(response);

  // 2. ਬਾਡੀ ਪ੍ਰਮਾਣੀਕਰਨ
  const body = await parseRequestBody(request);

  // 3. ਫਾਰਮੈਟ ਖੋਜ + ਅਨੁਵਾਦ
  const sourceFormat = detectFormat(request);
  const targetFormat = getTargetFormat(providerId);
  if (needsTranslation(sourceFormat, targetFormat)) {
    body = translateRequest(body, sourceFormat, targetFormat);
  }

  // 4. ਕੰਬੋ ਰੂਟਿੰਗ
  const targets = await resolveComboTargets(comboId, body);
  for (const target of targets) {
    try {
      const result = await executeOnTarget(target, body);
      await recordUsage(result);
      return result;
    } catch (err) {
      // ਅਗਲੇ ਟਾਰਗਿਟ 'ਤੇ ਜਾਰੀ ਰੱਖੋ
    }
  }

  // 5. ਐਮਰਜੈਂਸੀ ਫਾਲਬੈਕ
  return await emergencyFallback(body);
}
```

## ਐਗਜ਼ੀਕਿਊਟਰ (150 ਮੋਡੀਊਲ)

ਜ਼ਿਆਦਾਤਰ ਹਰ ਪ੍ਰਦਾਤਾ ਲਈ ਇੱਕ ਫਾਈਲ। ਸਾਰੀਆਂ ਐਗਜ਼ੀਕਿਊਟਰ ਕਲਾਸਾਂ `BaseExecutor` ਤੋਂ ਵਿਸਤਾਰਿਤ ਹੁੰਦੀਆਂ ਹਨ ਅਤੇ ਜੋ ਵੱਖਰਾ ਹੈ ਉਸਨੂੰ ਓਵਰਰਾਈਡ ਕਰਦੀਆਂ ਹਨ; ਬਾਕੀ ਮੋਡੀਊਲ ਪ੍ਰਤੀ-ਪ੍ਰਦਾਤਾ ਹੈਲਪਰ ਹਨ (ਟੂਲ ਸਕੀਮਾ, fetch/TTS ਅਡਾਪਟਰ, ਕੁਇਰਕ ਹੈਂਡਲਰ)।

### ਆਮ ਪੈਟਰਨ

ਪ੍ਰਦਾਤਾਵਾਂ ਨੂੰ `getExecutor(providerId)` ਰਾਹੀਂ ਹੱਲ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਜੋ ਕੌਂਫਿਗਰ ਕੀਤਾ ਐਗਜ਼ੀਕਿਊਟਰ ਵਾਪਸ ਕਰਦਾ ਹੈ। OpenAI/Anthropic-ਅਨੁਕੂਲ ਪ੍ਰਦਾਤਾ `DefaultExecutor` ਵਰਤਦੇ ਹਨ (`executors/default.ts`)। ਪ੍ਰਦਾਤਾ-ਵਿਸ਼ੇਸ਼ ਵਿਵਹਾਰ (ਬੇਸ URL, ਔਥ ਹੈਡਰ, API ਵਰਜ਼ਨ) `open-sse/config/providers/` ਵਿੱਚ ਕੌਂਫਿਗਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਜਦਕਿ ਬੇਨਤੀ ਬਾਡੀ ਟ੍ਰਾਂਸਫਾਰਮੇਸ਼ਨ `open-sse/translator/` ਵਿੱਚ ਸੰਭਾਲੀਆਂ ਜਾਂਦੀਆਂ ਹਨ।

**ਕਸਟਮ URL** ਪ੍ਰਦਾਤਾ ਕੌਂਫਿਗਰੇਸ਼ਨ ਰਾਹੀਂ ਸੈੱਟ ਕੀਤਾ ਜਾਂਦਾ ਹੈ:

```ts
// open-sse/config/providers/ ਵਿੱਚ ਪ੍ਰਦਾਤਾ ਕੌਂਫਿਗ
export default {
  id: "together",
  baseURL: "https://api.together.xyz/v1/chat/completions",
}
````

**ਕਸਟਮ ਔਥ** ਪ੍ਰਦਾਤਾ ਰਜਿਸਟਰੀ ਦੀ ਔਥ ਕੌਂਫਿਗਰੇਸ਼ਨ (API ਕੁੰਜੀ, OAuth, ਹੈਡਰ ਪ੍ਰੋਫਾਈਲ) ਰਾਹੀਂ ਸੰਭਾਲਿਆ ਜਾਂਦਾ ਹੈ।

**ਕਸਟਮ ਬੇਨਤੀ ਬਾਡੀ** ਟ੍ਰਾਂਸਫਾਰਮੇਸ਼ਨਾਂ (ਉਦਾਹਰਣ ਵਜੋਂ, Anthropic ਵੱਲੋਂ `system` ਨੂੰ `messages` ਤੋਂ ਵੱਖ ਕਰਨਾ) `open-sse/translator/` ਵਿੱਚ ਪ੍ਰਤੀ-ਪ੍ਰਦਾਤਾ ਰਜਿਸਟਰ ਕੀਤੀਆਂ ਜਾਂਦੀਆਂ ਹਨ।

````

### ਐਗਜ਼ੀਕਿਊਟਰ ਫੈਕਟਰੀ

`executors/index.ts` `getExecutor(providerId)` ਐਕਸਪੋਰਟ ਕਰਦਾ ਹੈ:

```ts
import { getExecutor } from "@omniroute/open-sse/executors";

const executor = getExecutor("anthropic");
const result = await executor.execute({
  model: "claude-sonnet-4-5",
  messages: [...],
});
````

ਰੈਜ਼ੋਲੂਸ਼ਨ `ExecutorRegistry` (`executors/registry.ts`) ਰਾਹੀਂ ਹੁੰਦਾ ਹੈ: ਹਰ ਵਿਸ਼ੇਸ਼ ਐਗਜ਼ੀਕਿਊਟਰ `executors/index.ts` ਦੀ ਬਿਲਟ-ਇਨ ਟੇਬਲ ਵਿੱਚ ਘੋਸ਼ਿਤ ਹੁੰਦਾ ਹੈ ਅਤੇ ਮੋਡੀਊਲ ਲੋਡ ਸਮੇਂ `registerExecutor(alias, instance)` ਰਾਹੀਂ ਰਜਿਸਟਰ ਹੁੰਦਾ ਹੈ; `getExecutor()` ਰਜਿਸਟਰੀ ਨਾਲ ਸਲਾਹ ਕਰਦਾ ਹੈ ਅਤੇ ਬਿਨਾਂ ਵਿਸ਼ੇਸ਼ ਐਂਟਰੀ ਵਾਲੇ ਕਿਸੇ ਵੀ ਪ੍ਰਦਾਤਾ ਲਈ ਮੈਮੋਆਈਜ਼ਡ `DefaultExecutor` ਵੱਲ ਫਾਲਬੈਕ ਕਰਦਾ ਹੈ। ਪੂਰੀ alias → ਐਗਜ਼ੀਕਿਊਟਰ ਮੈਪਿੰਗ ਗੋਲਡਨ ਟੈਸਟ `tests/unit/executor-map-golden.test.ts` ਰਾਹੀਂ ਵਰਣਿਤ ਹੈ।

## ਅਨੁਵਾਦਕ

**3 ਫਾਰਮੈਟਾਂ** ਵਿਚਕਾਰ ਅਨੁਵਾਦ ਕਰੋ: OpenAI, Anthropic, Gemini, ਅਤੇ ਨਾਲ ਹੀ ਨਵਾਂ Responses API।

### ਅਨੁਵਾਦ ਕਦੋਂ ਹੁੰਦਾ ਹੈ

```ts
import { needsTranslation, translateRequest } from "@omniroute/open-sse/translator";

if (needsTranslation(sourceFormat, targetFormat)) {
  body = translateRequest(body, sourceFormat, targetFormat);
}
```

ਆਮ ਅਨੁਵਾਦ:

- `OpenAI → Anthropic`: ਵੱਖਰਾ `system` ਫੀਲਡ, `x-api-key` ਹੈਡਰ
- `OpenAI → Gemini`: `messages` ਦੀ ਬਜਾਏ `contents`, `systemInstruction`
- `OpenAI → Responses API`: `input` ਐਰੇ, `previous_response_id` ਸਥਿਤੀ

### ਸੰਭਾਲੇ ਗਏ ਵਿਸ਼ੇਸ਼ ਮਾਮਲੇ

- `developer` ਭੂਮਿਕਾ → ਗੈਰ-OpenAI ਲਈ `system`
- `system` ਭੂਮਿਕਾ → GLM/ERNIE ਲਈ ਪਹਿਲੇ ਵਰਤੋਂਕਾਰ ਸੁਨੇਹੇ ਵਿੱਚ ਮਿਲਾਈ ਜਾਂਦੀ ਹੈ
- `json_schema` → Gemini ਦਾ `responseMimeType` + `responseSchema`
- `tools` → ਪ੍ਰਦਾਤਾ-ਵਿਸ਼ੇਸ਼ ਟੂਲ ਫਾਰਮੈਟ
- ਸੋਚਣ ਦੇ ਪੈਰਾਮੀਟਰ (o1, Claude) → ਪ੍ਰਦਾਤਾ-ਵਿਸ਼ੇਸ਼ ਸਮਕੱਖ

## MCP ਸਰਵਰ

`open-sse/mcp-server/` **Model Context Protocol** ਸਰਵਰ ਨੂੰ ਲਾਗੂ ਕਰਦਾ ਹੈ:

- **110 ਟੂਲ** (ਪ੍ਰਦਾਤਾ ਪ੍ਰਬੰਧਨ, ਕੌਂਬੋ, ਮੈਮੋਰੀ, ਕੈਸ਼, ਕੰਪ੍ਰੈਸ਼ਨ, ਪ੍ਰੌਕਸੀ, ਹੁਨਰ, ਗੇਮੀਫਿਕੇਸ਼ਨ, ਪਲੱਗਇਨ, Notion, Obsidian, ਸਥਾਨਕ ਕੋਰਪਸ)
- **3 ਟ੍ਰਾਂਸਪੋਰਟ**: stdio, SSE, Streamable HTTP
- ਸੁਖਮ ਅਧਿਕਾਰ-ਨਿਯੰਤਰਣ ਲਈ **33 ਸਕੋਪ**

### ਟੂਲ ਰਜਿਸਟ੍ਰੇਸ਼ਨ

ਟੂਲਾਂ ਨੂੰ `open-sse/mcp-server/tools/` ਵਿੱਚ ਸੁਤੰਤਰ ਫਾਈਲਾਂ ਵਜੋਂ ਰਜਿਸਟਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਜਿਨ੍ਹਾਂ ਵਿੱਚੋਂ ਹਰ ਇੱਕ ਨਾਮ, ਸਕੀਮਾ, ਹੈਂਡਲਰ ਅਤੇ ਸਕੋਪ ਐਕਸਪੋਰਟ ਕਰਦੀ ਹੈ:

```ts
// open-sse/mcp-server/tools/getHealth.ts
import { z } from "zod";
export default {
  name: "omniroute_get_health",
  description: "ਸਿਸਟਮ ਦੀ ਸਿਹਤ ਦਾ ਸਨੈਪਸ਼ਾਟ ਪ੍ਰਾਪਤ ਕਰੋ",
  scope: "read:health",
  inputSchema: z.object({}),
  handler: async (_args, ctx) => {
    return await getSystemHealth();
  },
};
```

### ਟ੍ਰਾਂਸਪੋਰਟ

```ts
// stdio (CLI ਵਰਤੋਂ)
startMcpStdio(server);

// SSE (HTTP-ਅਧਾਰਿਤ ਸਟ੍ਰੀਮਿੰਗ)
startMcpSse(server, port);

// Streamable HTTP (ਆਧੁਨਿਕ MCP)
startMcpStreamable(server, port);
```

### ਅਧਿਕਾਰ-ਪ੍ਰਮਾਣੀਕਰਨ

ਹਰ ਟੂਲ ਕਾਲ ਸਕੋਪ ਜਾਂਚਾਂ (`open-sse/mcp-server/auth/`) ਵਿੱਚੋਂ ਲੰਘਦੀ ਹੈ:

```ts
if (!hasScope(apiKey, "providers:read")) {
  throw new Error("ਨਾਕਾਫ਼ੀ ਸਕੋਪ");
}
```

## ਟ੍ਰਾਂਸਫਾਰਮਰ

`open-sse/transformer/`, **Chat Completions** ਅਤੇ **Responses API** ਫਾਰਮੈਟਾਂ ਵਿਚਕਾਰ ਰੂਪਾਂਤਰਨ ਕਰਦਾ ਹੈ।

### ਵੱਖਰਾ ਟ੍ਰਾਂਸਫਾਰਮਰ ਕਿਉਂ?

Responses API, **ਸਥਿਤੀ-ਯੁਕਤ ਗੱਲਬਾਤਾਂ** (`previous_response_id`) ਵਾਲਾ OpenAI ਦਾ ਨਵਾਂ ਫਾਰਮੈਟ ਹੈ। ਜਦੋਂ ਕੋਈ ਕਲਾਇੰਟ Responses ਬੇਨਤੀ ਭੇਜਦਾ ਹੈ, ਤਾਂ OmniRoute:

1. ਅੰਦਰੂਨੀ ਤੌਰ 'ਤੇ Responses → Chat Completions ਵਿੱਚ ਰੂਪਾਂਤਰਿਤ ਕਰਦਾ ਹੈ
2. ਪ੍ਰਦਾਤਾ ਨੂੰ ਭੇਜਦਾ ਹੈ (ਕੋਈ ਵੀ ਪ੍ਰਦਾਤਾ ਜੋ Chat Completions ਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈ)
3. ਜਵਾਬ ਨੂੰ ਮੁੜ Responses ਫਾਰਮੈਟ ਵਿੱਚ ਰੂਪਾਂਤਰਿਤ ਕਰਦਾ ਹੈ
4. ਰੂਪਾਂਤਰਿਤ ਜਵਾਬ ਨੂੰ ਕਲਾਇੰਟ ਤੱਕ ਸਟ੍ਰੀਮ ਕਰਦਾ ਹੈ

ਟ੍ਰਾਂਸਫਾਰਮਰ (`transformer/responsesTransformer.ts`) ਇਹ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ:

```ts
createResponsesApiTransformStream(): TransformStream
```

ਇਹ ਹੇਠ ਲਿਖਿਆਂ ਨੂੰ ਸੰਭਾਲਦਾ ਹੈ:

- `response.output_item.added` ਇਵੈਂਟ
- `response.output_text.delta` ਇਵੈਂਟ
- `response.completed` ਇਵੈਂਟ
- ਟੂਲ ਕਾਲ ਮੈਪਿੰਗ (`function_call` ↔ `tool_calls`)

## ਨਵਾਂ ਕੰਪੋਨੈਂਟ ਸ਼ਾਮਲ ਕਰਨਾ

### ਨਵੀਂ ਸਰਵਿਸ ਸ਼ਾਮਲ ਕਰਨਾ

1. ਕੇਂਦ੍ਰਿਤ ਜ਼ਿੰਮੇਵਾਰੀ ਨਾਲ `open-sse/services/[serviceName].ts` ਬਣਾਓ
2. ਮੁੱਖ ਹੈਂਡਲਰ ਫੰਕਸ਼ਨ ਅਤੇ ਸਾਰੇ ਕਾਂਸਟੈਂਟ ਐਕਸਪੋਰਟ ਕਰੋ
3. `tests/unit/services/[serviceName].test.mjs` ਵਿੱਚ ਯੂਨਿਟ ਟੈਸਟ ਸ਼ਾਮਲ ਕਰੋ
4. ਬੇਨਤੀ ਪਾਈਪਲਾਈਨ ਵਿੱਚ `handlers/chatCore.ts` ਰਾਹੀਂ ਏਕੀਕ੍ਰਿਤ ਕਰੋ (ਜੇ ਰਾਊਟਿੰਗ ਨਾਲ ਸੰਬੰਧਿਤ ਹੋਵੇ)
5. ਜੇ ਸਰਵਿਸ ਟਾਰਗੇਟ ਚੋਣ ਨੂੰ ਪ੍ਰਭਾਵਿਤ ਕਰਦੀ ਹੈ ਤਾਂ `combo.ts` ਵਿੱਚ ਰਾਊਟਿੰਗ ਲੌਜਿਕ ਅੱਪਡੇਟ ਕਰੋ
6. ਇਸ ਫਾਈਲ ਵਿੱਚ ਦਸਤਾਵੇਜ਼ੀਕਰਨ ਕਰੋ

### ਨਵਾਂ ਐਗਜ਼ੀਕਿਊਟਰ ਸ਼ਾਮਲ ਕਰਨਾ

1. `BaseExecutor` ਨੂੰ ਐਕਸਟੈਂਡ ਕਰਦਿਆਂ `open-sse/executors/[provider].ts` ਬਣਾਓ
2. `config/providerRegistry.ts` ਵਿੱਚ ਰਜਿਸਟਰ ਕਰੋ
3. `executors/index.ts` ਫੈਕਟਰੀ ਵਿੱਚ ਸ਼ਾਮਲ ਕਰੋ
4. ਐਗਜ਼ੀਕਿਊਟਰ ਲਈ ਯੂਨਿਟ ਟੈਸਟ ਸ਼ਾਮਲ ਕਰੋ
5. `docs/architecture/ARCHITECTURE.md` ਵਿੱਚ ਦਸਤਾਵੇਜ਼ੀਕਰਨ ਕਰੋ

### ਨਵਾਂ MCP ਟੂਲ ਸ਼ਾਮਲ ਕਰਨਾ

1. `open-sse/mcp-server/tools/[category]Tools.ts` ਬਣਾਓ ਜਾਂ ਅੱਪਡੇਟ ਕਰੋ
2. ਇਨਪੁੱਟਾਂ ਲਈ Zod ਸਕੀਮਾ ਪਰਿਭਾਸ਼ਿਤ ਕਰੋ
3. ਟੂਲ ਨੂੰ `mcp-server/index.ts` ਵਿੱਚ ਰਜਿਸਟਰ ਕਰੋ
4. `mcp-server/auth/` ਵਿੱਚ ਸਕੋਪ ਮੈਟ੍ਰਿਕਸ ਵਿੱਚ ਸ਼ਾਮਲ ਕਰੋ
5. ਯੂਨਿਟ ਟੈਸਟ ਸ਼ਾਮਲ ਕਰੋ
