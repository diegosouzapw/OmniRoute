OmniRoute **CLI ਖੋਜ**, **ਮੂਲ Agent Client Protocol**, ਅਤੇ
**ਪੁਰਾਣੇ stdio ਅਡੈਪਟਰਾਂ** ਨੂੰ ਵੱਖ ਕਰਦਾ ਹੈ। ਕਿਸੇ ਇੰਸਟਾਲ ਕੀਤੀ ਬਾਈਨਰੀ ਦਾ ਮਿਲਣਾ ਉਸਦੀ
ਪ੍ਰਮਾਣਿਕਤਾ, ਮਾਡਲ ਅਨੁਕੂਲਤਾ, ਜਾਂ ਪ੍ਰੌਂਪਟ ਸੰਭਾਲਣ ਦੀ ਤਿਆਰੀ ਨੂੰ ਸਾਬਤ ਨਹੀਂ ਕਰਦਾ।

ਡੈਸ਼ਬੋਰਡ ਇਨਵੈਂਟਰੀ ਅਤੇ ਕਸਟਮ-ਏਜੰਟ ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਲਈ `GET /api/acp/agents` ਅਤੇ
`POST /api/acp/agents` ਵਰਤਦਾ ਹੈ। ਇਹ ਸਿਰਫ਼ ਸਥਾਨਕ ਪ੍ਰਬੰਧਨ ਰੂਟ ਹਨ, ਪ੍ਰਕਿਰਿਆਵਾਂ
ਸ਼ੁਰੂ ਕਰਨ ਜਾਂ ਪ੍ਰੌਂਪਟ ਜਮ੍ਹਾਂ ਕਰਨ ਲਈ ਜਨਤਕ API ਨਹੀਂ। ਅੰਦਰੂਨੀ
`AcpManager` ਆਪਣੇ ਆਪ HTTP ਪ੍ਰਦਾਤਾ ਫਾਲਬੈਕ ਨਹੀਂ ਬਣਦਾ।

## ਰਜਿਸਟਰਡ ਇਕਰਾਰਨਾਮੇ

`config/cli-tools-manifest.json` ਬਿਲਟ-ਇਨ ਲਾਂਚ ਬਾਈਨਰੀਆਂ, ਆਰਗੂਮੈਂਟਾਂ, ਅਤੇ ਬੈਕਐਂਡ
ਮੋਡਾਂ ਲਈ ਪ੍ਰਮਾਣਿਕ ਸਰੋਤ ਹੈ। ਰਜਿਸਟਰੀ ਆਪਣੀਆਂ ਪਰਿਭਾਸ਼ਾਵਾਂ ਉਸ ਮੈਨੀਫੈਸਟ ਤੋਂ
ਲੈਂਦੀ ਹੈ। ਖੋਜ ਨੂੰ 60 ਸਕਿੰਟਾਂ ਲਈ ਕੈਸ਼ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।

- `acp`: Gemini ਇਕਰਾਰਨਾਮਾ `gemini --experimental-acp` ਲਾਂਚ ਕਰਦਾ ਹੈ ਅਤੇ ਅਧਿਕਾਰਤ
  TypeScript SDK ਰਾਹੀਂ ਨਵੀਂ-ਲਾਈਨ ਨਾਲ ਵੱਖ ਕੀਤਾ ACP JSON-RPC ਵਰਤਦਾ ਹੈ।
- `stdio-adapter`: ਹੋਰ ਰਜਿਸਟਰਡ ਇਕਰਾਰਨਾਮੇ ਪੁਰਾਣੇ ਨਵੀਂ-ਲਾਈਨ-ਇਨਪੁੱਟ,
  stdout-ਆਉਟਪੁੱਟ ਅਡੈਪਟਰ ਨੂੰ ਬਰਕਰਾਰ ਰੱਖਦੇ ਹਨ। ਆਉਟਪੁੱਟ ਵਿੱਚ ਦੋ ਸਕਿੰਟਾਂ ਦੀ ਨਿਸ਼ਕਿਰਿਆ
  ਮਿਆਦ ਇਸਦਾ ਜਵਾਬ ਸਮਾਪਤ ਕਰਦੀ ਹੈ। ਇਹ ਅਡੈਪਟਰ ਉਨ੍ਹਾਂ CLIs ਲਈ ਮੂਲ ACP ਸਮਰਥਨ ਨੂੰ
  **ਪ੍ਰਮਾਣਿਤ ਨਹੀਂ** ਕਰਦਾ।

Gemini ਆਪਣੇ [CLI ਹਵਾਲੇ](https://geminicli.com/docs/cli/cli-reference/) ਵਿੱਚ ਲਾਂਚ ਫਲੈਗ ਦਾ ਦਸਤਾਵੇਜ਼ੀਕਰਨ ਕਰਦਾ ਹੈ।
ਕਲਾਇੰਟ ਸ਼ੁਰੂਆਤ, ਸੈਸ਼ਨ ਬਣਾਉਣ, ਪ੍ਰੌਂਪਟ ਬੇਨਤੀਆਂ, ਸੂਚਨਾਵਾਂ, ਅਤੇ ਰੱਦ ਕਰਨ ਲਈ
[ਅਧਿਕਾਰਤ ACP SDK](https://github.com/agentclientprotocol/typescript-sdk) ਵਰਤਦਾ ਹੈ।

ਕਸਟਮ-ਏਜੰਟ ਪਰਿਭਾਸ਼ਾਵਾਂ ਪ੍ਰਸ਼ਾਸਕ-ਨਿਯੰਤਰਿਤ ਲਾਂਚ ਇਕਰਾਰਨਾਮੇ ਹੀ ਰਹਿੰਦੀਆਂ ਹਨ।
ਕਿਸੇ ਬਾਈਨਰੀ ਅਤੇ ਆਰਗੂਮੈਂਟਾਂ ਨੂੰ ਰਜਿਸਟਰ ਕਰਨ ਨਾਲ ਉਸ ਪ੍ਰਕਿਰਿਆ ਨੂੰ ਸਰਵਰ ਉਪਭੋਗਤਾ ਦੇ
ਸਥਾਨਕ ਚਲਾਉਣ ਵਾਲੇ ਅਧਿਕਾਰ ਮਿਲ ਜਾਂਦੇ ਹਨ; ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਕੋਈ ਸੈਂਡਬਾਕਸ ਨਹੀਂ ਹੈ। ਵਰਜਨ ਜਾਂਚਾਂ
ਕੇਵਲ ਰਜਿਸਟਰਡ ਚਲਾਉਣਯੋਗ ਫਾਈਲ ਅਤੇ ਕਿਸੇ ਮਾਨਤਾ-ਪ੍ਰਾਪਤ ਵਰਜਨ ਫਲੈਗ ਨੂੰ ਸਵੀਕਾਰ ਕਰਦੀਆਂ ਹਨ।

## ਅੰਦਰੂਨੀ ਲਾਂਚ API

```typescript
import { acpManager } from "@/lib/acp";

const session = acpManager.spawn("gemini", {
  cwd: process.cwd(),
  // ਕੇਵਲ ਉਹੀ ਪ੍ਰਦਾਤਾ ਵੇਰੀਏਬਲ ਪਾਸ ਕਰੋ ਜੋ ਜਾਣਬੁੱਝ ਕੇ ਇਸ ਏਜੰਟ ਨੂੰ ਨਿਰਧਾਰਤ ਕੀਤੇ ਗਏ ਹਨ।
  env: {
    GEMINI_API_KEY: process.env.GEMINI_API_KEY,
  },
});

try {
  const response = await acpManager.sendPrompt(session.id, "Explain this project", 120_000);
  // ਕਾਲ ਕਰਨ ਵਾਲੀ ਐਪਲੀਕੇਸ਼ਨ ਵਿੱਚ ਜਵਾਬ ਦੀ ਵਰਤੋਂ ਕਰੋ।
} finally {
  acpManager.kill(session.id);
}
```

`spawn(agentId, options)` ਰਜਿਸਟਰਡ ਪਰਿਭਾਸ਼ਾ ਤੋਂ ਚਲਾਉਣਯੋਗ ਫਾਈਲ ਅਤੇ ਆਰਗੂਮੈਂਟਾਂ ਨੂੰ
ਹੱਲ ਕਰਦਾ ਹੈ। ਕਾਲਰ ਦੇ ਇੱਕੋ-ਇੱਕ ਵਿਕਲਪ `cwd` ਅਤੇ `env` ਹਨ; ਪੁਰਾਣੇ
`spawn(agentId, binary, args, env)` ਸਿਗਨੇਚਰ ਅਤੇ ਚਲਾਉਣਯੋਗ ਫਾਈਲ ਦੇ ਓਵਰਰਾਈਡ
ਰੱਦ ਕੀਤੇ ਜਾਂਦੇ ਹਨ। ਇਹ ਮੈਨੇਜਰ HTTP ਲਾਂਚ ਇਕਰਾਰਨਾਮਿਆਂ ਦਾ ਸਮਰਥਨ ਨਹੀਂ ਕਰਦਾ।

ਚਾਈਲਡ ਨੂੰ CLI ਲਾਂਚਰਾਂ ਵਾਂਗ ਉਹੀ ਓਪਰੇਟਿੰਗ-ਸਿਸਟਮ, ਟਰਮੀਨਲ, ਲੋਕੇਲ, ਅਤੇ ਸਰਟੀਫਿਕੇਟ
ਮਨਜ਼ੂਰ-ਸੂਚੀ ਵਿਰਾਸਤ ਵਿੱਚ ਮਿਲਦੀ ਹੈ। ਸਰਵਰ/ਪ੍ਰਦਾਤਾ ਦੇ ਗੁਪਤ ਮੁੱਲ ਪੇਰੈਂਟ
ਇਨਵਾਇਰਨਮੈਂਟ ਤੋਂ ਕਾਪੀ ਨਹੀਂ ਕੀਤੇ ਜਾਂਦੇ। ਚੁਣੀ ਗਈ CLI ਲਈ ਲੋੜੀਂਦੇ ਪ੍ਰਮਾਣ-ਪੱਤਰ
ਸਪਸ਼ਟ ਤੌਰ 'ਤੇ ਪਾਸ ਕੀਤੇ ਜਾਣੇ ਚਾਹੀਦੇ ਹਨ ਜਾਂ ਉਸ CLI ਦੀ ਆਪਣੀ ਸਥਾਨਕ ਪ੍ਰਮਾਣਿਕਤਾ ਰਾਹੀਂ
ਮੁਹੱਈਆ ਕੀਤੇ ਜਾਣੇ ਚਾਹੀਦੇ ਹਨ। ਚਾਈਲਡ ਕੋਲ ਫਿਰ ਵੀ ਸਥਾਨਕ ਉਪਭੋਗਤਾ ਦੀਆਂ ਫਾਈਲ-ਸਿਸਟਮ
ਇਜਾਜ਼ਤਾਂ ਹੁੰਦੀਆਂ ਹਨ ਅਤੇ ਉਹ ਆਪਣੀ ਕੌਂਫਿਗ ਪੜ੍ਹ ਸਕਦੀ ਹੈ।

## ਮੂਲ ਜੀਵਨ-ਚੱਕਰ ਅਤੇ ਸੀਮਾਵਾਂ

1. ਰਜਿਸਟਰਡ ਬਾਈਨਰੀ ਸ਼ੁਰੂ ਕਰੋ, ACP ਨੂੰ ਸ਼ੁਰੂ ਕਰੋ, ਅਤੇ ਚੁਣੀ ਗਈ ਕਾਰਜਕਾਰੀ ਡਾਇਰੈਕਟਰੀ
   'ਤੇ ਆਧਾਰਿਤ ਸੈਸ਼ਨ ਬਣਾਓ। ਸ਼ੁਰੂਆਤ ਲਈ ਦਸ ਸਕਿੰਟ ਦੀ ਸੀਮਾ ਹੈ।
2. ਪ੍ਰੌਂਪਟ ਜਮ੍ਹਾਂ ਕਰੋ ਅਤੇ ਕੇਵਲ ਉਸ ਸੈਸ਼ਨ ਲਈ ਟੈਕਸਟ ਸੂਚਨਾਵਾਂ ਇਕੱਠੀਆਂ ਕਰੋ।
   ਪੂਰਨਤਾ ਪ੍ਰੌਂਪਟ RPC ਜਵਾਬ ਹੈ, ਨਾ ਕਿ stdout ਦੀ ਚੁੱਪੀ ਦੀ ਕੋਈ ਮਿਆਦ।
3. ਇੱਕ ਪ੍ਰੌਂਪਟ ਸਮਾਂ-ਸੀਮਾ ਵਰਤੋ, ਜਿਸ ਵਿੱਚ ਕੋਈ ਵੀ ਅਧੂਰੀ ਸ਼ੁਰੂਆਤ ਸ਼ਾਮਲ ਹੋਵੇ; ਮੂਲ
   ਸੀਮਾ 120 ਸਕਿੰਟ ਹੈ। ਇੱਕੋ ਪ੍ਰਕਿਰਿਆ ਵਿੱਚ ਸਮਕਾਲੀ ਪ੍ਰੌਂਪਟ ਰੱਦ ਕੀਤੇ ਜਾਂਦੇ ਹਨ।
4. ਮੂਲ ਟਾਈਮਆਉਟ ਹੋਣ 'ਤੇ, `session/cancel` ਦੀ ਕੋਸ਼ਿਸ਼ ਕਰੋ ਅਤੇ ਪ੍ਰਕਿਰਿਆ ਸਮਾਪਤ ਕਰੋ।
   ਸਮਾਪਤੀ ਤੋਂ ਪਹਿਲਾਂ 100 ms ਦੀ ਸੀਮਿਤ ਵਿੰਡੋ ਸੂਚਨਾ ਨੂੰ ਫਲਸ਼ ਹੋਣ ਦਿੰਦੀ ਹੈ।
5. ਜਦੋਂ ਸ਼ੁਰੂਆਤ ਅਸਫਲ ਹੁੰਦੀ ਹੈ, ਕਨੈਕਸ਼ਨ ਬੰਦ ਹੁੰਦਾ ਹੈ, ਪ੍ਰਕਿਰਿਆ ਬਾਹਰ ਨਿਕਲਦੀ ਹੈ,
   ਜਾਂ ਕਾਲਰ ਇਸਨੂੰ ਬੰਦ ਕਰਦਾ ਹੈ, ਤਾਂ ਟ੍ਰਾਂਸਪੋਰਟ ਸਥਿਤੀ ਬੰਦ ਕਰੋ ਅਤੇ ਸੈਸ਼ਨ ਹਟਾਓ।

ਟੂਲ ਇਜਾਜ਼ਤ ਬੇਨਤੀਆਂ ਰੱਦ ਕੀਤੀਆਂ ਜਾਂਦੀਆਂ ਹਨ। ਕਿਸੇ ਫਾਈਲ-ਸਿਸਟਮ ਜਾਂ ਟਰਮੀਨਲ ਕਲਾਇੰਟ
ਸਮਰੱਥਾ ਦਾ ਇਸ਼ਤਿਹਾਰ ਨਹੀਂ ਦਿੱਤਾ ਜਾਂਦਾ। ਇਹ ਪਾਬੰਦੀਆਂ ਖੁਦ ਚਾਈਲਡ ਬਾਈਨਰੀ ਨੂੰ ਸੈਂਡਬਾਕਸ
ਨਹੀਂ ਕਰਦੀਆਂ ਅਤੇ ਨਾ ਹੀ ਕਿਸੇ CLI ਦੀਆਂ ਆਪਣੀਆਂ ਅਧਿਕਾਰਕਰਨ ਸੈਟਿੰਗਾਂ ਦੀ ਥਾਂ ਲੈਂਦੀਆਂ ਹਨ।

ਮੂਲ ਟੈਕਸਟ ਅਤੇ ਪੁਰਾਣੇ stdout/stderr ਦੋਵੇਂ ਵੱਧ ਤੋਂ ਵੱਧ 1 MiB ਅੱਖਰ ਰੱਖਦੇ ਹਨ,
ਜਿਸ ਵਿੱਚ ਕਟੌਤੀ ਸੂਚਨਾ ਸਮੇਤ ਸਭ ਤੋਂ ਨਵਾਂ ਆਉਟਪੁੱਟ ਸੰਭਾਲਿਆ ਜਾਂਦਾ ਹੈ। SDK ਪਾਰਸਿੰਗ ਤੋਂ
ਪਹਿਲਾਂ ਇੱਕ ਵਿਅਕਤੀਗਤ ਮੂਲ ਵਾਇਰ ਫਰੇਮ 2 MiB ਬਾਈਟਾਂ ਤੱਕ ਸੀਮਿਤ ਹੈ। ਬਫ਼ਰ ਹਰ ਪ੍ਰੌਂਪਟ
ਲਈ ਰੀਸੈੱਟ ਹੁੰਦੇ ਹਨ।

`kill(sessionId)` SIGTERM ਭੇਜਦਾ ਹੈ, ਫਿਰ ਜੇਕਰ ਪ੍ਰਕਿਰਿਆ ਬੰਦ ਨਹੀਂ ਹੋਈ ਤਾਂ ਪੰਜ
ਸਕਿੰਟਾਂ ਬਾਅਦ SIGKILL ਭੇਜਦਾ ਹੈ। ਪੁਰਾਣੇ ਪ੍ਰੌਂਪਟ ਟਾਈਮਆਉਟ ਲਿਸਨਰਾਂ ਅਤੇ ਟਾਈਮਰਾਂ ਨੂੰ
ਰਿਲੀਜ਼ ਕਰਦੇ ਹਨ ਪਰ ਸੈਸ਼ਨ ਨੂੰ ਕਿਸੇ ਹੋਰ ਪ੍ਰੌਂਪਟ ਲਈ ਉਪਲਬਧ ਛੱਡ ਦਿੰਦੇ ਹਨ; ਕੰਮ ਮੁਕੰਮਲ
ਹੋਣ 'ਤੇ ਕਾਲਰ `kill()` ਜਾਂ `killAll()` ਲਈ ਜ਼ਿੰਮੇਵਾਰ ਰਹਿੰਦੇ ਹਨ।

## ਇਵੈਂਟ ਅਤੇ ਨਿਰੀਖਣ

ਮੈਨੇਜਰ `stdout`, `stderr`, ਅਤੇ `exit` ਇਵੈਂਟ ਛੱਡਦਾ ਹੈ, ਜਿਨ੍ਹਾਂ ਵਿੱਚੋਂ ਹਰੇਕ ਨਾਲ
`sessionId` ਹੁੰਦਾ ਹੈ। `sessionError` ਇੱਕ ਸਾਫ਼ ਕੀਤਾ ਹੋਇਆ ਟ੍ਰਾਂਸਪੋਰਟ ਗਲਤੀ ਸੁਨੇਹਾ
ਦਿੰਦਾ ਹੈ। ਅਨੁਕੂਲਤਾ `error` ਇਵੈਂਟ ਕੇਵਲ ਉਦੋਂ ਛੱਡਿਆ ਜਾਂਦਾ ਹੈ ਜਦੋਂ ਉਸਦਾ ਕੋਈ
ਸਬਸਕ੍ਰਾਈਬਰ ਹੋਵੇ, ਤਾਂ ਜੋ ਗੁੰਮ ਬਾਈਨਰੀ ਕਿਸੇ ਅਣਸੰਭਾਲੀ EventEmitter ਗਲਤੀ ਦਾ ਕਾਰਨ
ਨਾ ਬਣ ਸਕੇ।

- `getSession(sessionId)` ਇੱਕ ਪ੍ਰਬੰਧਿਤ ਸੈਸ਼ਨ ਜਾਂ `undefined` ਵਾਪਸ ਕਰਦਾ ਹੈ।
- `getActiveSessions()` ਰੁਕੇ ਹੋਏ ਜਾਂ ਰੁਕ ਰਹੇ ਸੈਸ਼ਨਾਂ ਨੂੰ ਸ਼ਾਮਲ ਨਹੀਂ ਕਰਦਾ।
- `sendInput(sessionId, input)` ਕੇਵਲ ਚੱਲ ਰਹੇ ਪੁਰਾਣੇ ਅਡੈਪਟਰ ਲਈ ਉਪਲਬਧ ਹੈ;
  ਮੂਲ ACP ਆਪਣੀ JSON-RPC ਸਟ੍ਰੀਮ ਦੀ ਰੱਖਿਆ ਲਈ ਕੱਚੇ ਇਨਪੁੱਟ ਨੂੰ ਰੱਦ ਕਰਦਾ ਹੈ।
- `killAll()` ਉਸ ਇੰਸਟੈਂਸ ਦੁਆਰਾ ਪ੍ਰਬੰਧਿਤ ਹਰ ਸੈਸ਼ਨ ਨੂੰ ਸਮਾਪਤ ਕਰਦਾ ਹੈ।

## ਪ੍ਰਮਾਣਿਕਤਾ ਦੀਆਂ ਹੱਦਾਂ

ਨਿਰਧਾਰਤ ਫਿਕਸਚਰ ਮੂਲ ਹੈਂਡਸ਼ੇਕ, ਟੈਕਸਟ ਆਉਟਪੁੱਟ, ਰੱਦ ਕੀਤੀਆਂ ਇਜਾਜ਼ਤਾਂ,
ਰੱਦੀਕਰਨ, ਸਮਕਾਲੀ ਪ੍ਰੌਂਪਟਾਂ, ਅਸਫਲ ਸ਼ੁਰੂਆਤ, ਪ੍ਰਕਿਰਿਆ ਦੇ ਬਾਹਰ ਨਿਕਲਣ, ਆਉਟਪੁੱਟ
ਸੀਮਾਵਾਂ, ਅਤੇ ਗੁਪਤ ਮੁੱਲਾਂ ਦੀ ਅਲੱਗਤਾ ਨੂੰ ਕਵਰ ਕਰਦੇ ਹਨ। ਮੌਜੂਦਾ ਪੁਰਾਣੇ
ਬਫ਼ਰ/ਲਿਸਨਰ ਰਿਗ੍ਰੈਸ਼ਨ ਵੀ ਕਵਰ ਰਹਿੰਦੇ ਹਨ। ਇਹ ਟੈਸਟ ਚਾਲੂ Gemini ਲੌਗਇਨ ਜਾਂ ਸਫਲ
ਪ੍ਰਦਾਤਾ ਅਨੁਮਾਨ ਨੂੰ ਪ੍ਰਦਰਸ਼ਿਤ ਨਹੀਂ ਕਰਦੇ; ਉਨ੍ਹਾਂ ਲਈ ਟੀਚਾ ਇਨਵਾਇਰਨਮੈਂਟ ਵਿੱਚ ਵੱਖਰੇ
ਤੌਰ 'ਤੇ ਅਧਿਕਾਰਤ ਸਮੋਕ ਟੈਸਟ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ।
