> **ਸੱਚਾਈ ਦਾ ਸਰੋਤ:** `src/lib/cloudAgent/` ਅਤੇ `src/app/api/v1/agents/tasks/`
> **ਆਖਰੀ ਵਾਰ ਅੱਪਡੇਟ ਕੀਤਾ:** 2026-06-28 — v3.8.40 (ਫਰੰਟਮੈਟਰ ਤਾਜ਼ਾ ਕੀਤਾ; cursor-cloud ਸਮੇਤ 4 ਏਜੰਟ)

OmniRoute ਤੀਜੀ-ਧਿਰ ਦੇ ਕਲਾਉਡ-ਹੋਸਟ ਕੀਤੇ ਕੋਡਿੰਗ ਏਜੰਟਾਂ (Codex Cloud, Cursor,
Devin, Jules) ਨੂੰ ਲੰਮੇ ਸਮੇਂ ਤੱਕ ਚੱਲਣ ਵਾਲੇ ਟਾਸਕਾਂ ਵਜੋਂ ਆਰਕੇਸਟ੍ਰੇਟ ਕਰਦਾ ਹੈ। ਹਰੇਕ ਏਜੰਟ ਨੂੰ ਇੱਕ ਸਮਾਨ ਇੰਟਰਫੇਸ ਦੇ ਪਿੱਛੇ ਰੈਪ ਕੀਤਾ ਗਿਆ ਹੈ, ਤਾਂ ਜੋ
ਕਲਾਇੰਟ ਪ੍ਰਦਾਤਾ-ਵਿਸ਼ੇਸ਼ APIs ਨਾਲ ਨਜਿੱਠੇ ਬਿਨਾਂ ਇੱਕ ਪ੍ਰੌਂਪਟ + ਰਿਪੋਜ਼ਟਰੀ URL ਸਪੁਰਦ ਕਰ ਸਕਣ ਅਤੇ ਨਤੀਜੇ ਪ੍ਰਾਪਤ ਕਰ ਸਕਣ।

Cloud Agent ਟਾਸਕ ਇੱਕ ਆਮ ਚੈਟ ਕੰਪਲੀਸ਼ਨ **ਨਹੀਂ** ਹੈ। ਇਹ ਕੰਮ ਦੀ ਇੱਕ ਟਿਕਾਊ, ਬਹੁ-ਪੜਾਵੀ
ਇਕਾਈ ਹੈ, ਜਿਸਨੂੰ ਪੂਰਾ ਹੋਣ ਵਿੱਚ ਮਿੰਟਾਂ ਤੋਂ ਘੰਟਿਆਂ ਤੱਕ ਦਾ ਸਮਾਂ ਲੱਗ ਸਕਦਾ ਹੈ, ਜੋ ਆਪਣੀ
ਆਰਟੀਫੈਕਟ ਵਜੋਂ Pull Request ਤਿਆਰ ਕਰ ਸਕਦੀ ਹੈ, ਅਤੇ ਫਾਲੋ-ਅੱਪ ਸੁਨੇਹਿਆਂ ਅਤੇ (ਕੁਝ ਪ੍ਰਦਾਤਾਵਾਂ ਵਿੱਚ) ਯੋਜਨਾ ਮਨਜ਼ੂਰੀ ਗੇਟਾਂ ਦਾ ਸਮਰਥਨ ਕਰਦੀ ਹੈ।

| -------------- | ------------------ | ------------------------------------- | --------------------------------------- | --------------- |

| `devin`        | `DevinAgent`       | `src/lib/cloudAgent/agents/devin.ts`  | `https://api.devin.ai/v1`               | ਹਾਂ             |
| `codex-cloud`  | `CodexCloudAgent`  | `src/lib/cloudAgent/agents/codex.ts`  | `https://api.openai.com/v1/codex/cloud` | ਨਹੀਂ (ਸਵੈਚਾਲਿਤ) |
| `cursor-cloud` | `CursorCloudAgent` | `src/lib/cloudAgent/agents/cursor.ts` | `https://api.cursor.com/v0`             | ਨਹੀਂ (ਸਵੈਚਾਲਿਤ) |

ਰਜਿਸਟਰੀ: `src/lib/cloudAgent/registry.ts` — `getAgent(providerId)`,
`getAvailableAgents()`, ਅਤੇ `isCloudAgentProvider(providerId)` ਨੂੰ ਐਕਸਪੋਰਟ ਕਰਦੀ ਹੈ। ਰਜਿਸਟਰੀ ਇੱਕ
ਸਧਾਰਨ ਇਨ-ਮੈਮੋਰੀ `Record<string, CloudAgentBase>` ਹੈ, ਜੋ ਮੋਡੀਊਲ ਲੋਡ ਹੋਣ ਸਮੇਂ ਭਰੀ ਜਾਂਦੀ ਹੈ।

## ਆਰਕੀਟੈਕਚਰ

```
ਕਲਾਇੰਟ (ਡੈਸ਼ਬੋਰਡ / CLI / API)
  → POST /api/v1/agents/tasks (ਪ੍ਰਬੰਧਨ ਪ੍ਰਮਾਣੀਕਰਨ ਲੋੜੀਂਦਾ ਹੈ)
    → CreateCloudAgentTaskSchema ਪ੍ਰਮਾਣਿਕਤਾ (Zod)
    → registry.getAgent(providerId)
    → getCloudAgentCredentials(providerId)
      └─ getProviderConnections({ provider, isActive: true }) ਤੋਂ ਪ੍ਰਾਪਤ ਕਰਦਾ ਹੈ
         (ਪਹਿਲਾਂ apiKey, ਫਿਰ accessToken ਨੂੰ ਫਾਲਬੈਕ ਵਜੋਂ ਵਰਤਦਾ ਹੈ)
    → agent.createTask({ prompt, source, options }, credentials)
      └─ ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰਦਾਤਾ API ਨੂੰ HTTP POST
      └─ ਅੰਦਰੂਨੀ id + externalId ਵਾਲਾ CloudAgentTask ਵਾਪਸ ਕਰਦਾ ਹੈ
    → cloud_agent_tasks (SQLite) ਵਿੱਚ insertCloudAgentTask(...)

ਪੋਲਿੰਗ (ਪੜ੍ਹਨ ਵੇਲੇ ਆਲਸੀ ਸਿੰਕ):
  GET /api/v1/agents/tasks/[id]
    → getCloudAgentTaskById(id)
    → agent.getStatus(externalId, credentials)  // ਸਥਿਤੀ + ਸਰਗਰਮੀਆਂ ਨੂੰ ਤਾਜ਼ਾ ਕਰਦਾ ਹੈ
    → ਨਵੀਂ ਸਥਿਤੀ, ਨਤੀਜੇ, completed_at ਨਾਲ updateCloudAgentTask(...)
    → ਸੀਰੀਅਲਾਈਜ਼ ਕੀਤਾ ਟਾਸਕ ਵਾਪਸ ਕਰਦਾ ਹੈ

ਅੰਤਰਕਿਰਿਆਵਾਂ:
  POST /api/v1/agents/tasks/[id]  ਬਾਡੀ: { action: "approve" | "message" | "cancel" }
    → agent.approvePlan(externalId, credentials)        "approve" ਲਈ
    → agent.sendMessage(externalId, message, credentials) "message" ਲਈ
    → ਸਥਿਤੀ "cancelled" ਵਿੱਚ ਬਦਲ ਜਾਂਦੀ ਹੈ               "cancel" ਲਈ (ਕੇਵਲ ਸਥਾਨਕ)
```

ਸਿੰਕ **ਆਲਸੀ** ਹੈ: ਹਰ `GET /tasks/[id]` ਉੱਤੇ ਸਥਿਤੀ ਨੂੰ ਅੱਪਸਟ੍ਰੀਮ ਤੋਂ ਤਾਜ਼ਾ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।
ਕੋਈ ਬੈਕਗ੍ਰਾਊਂਡ ਪੋਲਰ ਨਹੀਂ ਹੈ। ਜਿਨ੍ਹਾਂ ਡੈਸ਼ਬੋਰਡਾਂ ਨੂੰ ਤਾਜ਼ਾ ਸਥਿਤੀ ਦੀ ਲੋੜ ਹੈ, ਉਨ੍ਹਾਂ ਨੂੰ GET
ਐਂਡਪੌਇੰਟ ਨੂੰ ਇੱਕ ਉਚਿਤ ਅੰਤਰਾਲ 'ਤੇ ਪੋਲ ਕਰਨਾ ਚਾਹੀਦਾ ਹੈ।

## `CloudAgentBase` ਇੰਟਰਫੇਸ

ਸਰੋਤ: `src/lib/cloudAgent/baseAgent.ts`

```typescript
export interface AgentCredentials {
  apiKey: string;
  baseUrl?: string;
}

export interface CreateTaskParams {
  prompt: string;
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
}

export interface GetStatusResult {
  status: CloudAgentStatus;
  externalId?: string;
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
}

export abstract class CloudAgentBase {
  abstract readonly providerId: string;
  abstract readonly baseUrl: string;

  abstract createTask(p: CreateTaskParams, c: AgentCredentials): Promise<CloudAgentTask>;
  abstract getStatus(externalId: string, c: AgentCredentials): Promise<GetStatusResult>;
  abstract approvePlan(externalId: string, c: AgentCredentials): Promise<void>;
  abstract sendMessage(
    externalId: string,
    message: string,
    c: AgentCredentials
  ): Promise<CloudAgentActivity>;
  abstract listSources(
    c: AgentCredentials
  ): Promise<{ name: string; url: string; branch?: string }[]>;

  protected mapStatus(raw: string): CloudAgentStatus; // ਅਨੁਮਾਨ-ਆਧਾਰਿਤ ਅੱਪਸਟ੍ਰੀਮ ਸਟ੍ਰਿੰਗ → enum
  protected generateTaskId(): string; // `task_<ts>_<rand>`
  protected generateActivityId(): string; // `act_<ts>_<rand>`
}
```

`CodexCloudAgent.approvePlan` ਜਾਣਬੁੱਝ ਕੇ ਤਰੁੱਟੀ ਸੁੱਟਦਾ ਹੈ — Codex Cloud ਆਪਣੇ-ਆਪ ਯੋਜਨਾ ਬਣਾਉਂਦਾ ਹੈ ਅਤੇ ਇਸ ਵਿੱਚ ਕੋਈ ਮਨਜ਼ੂਰੀ ਗੇਟ ਨਹੀਂ ਹੈ। `CodexCloudAgent.listSources`, `[]` ਵਾਪਸ ਕਰਦਾ ਹੈ।

`CursorCloudAgent`, **ਵਰਤੋਂਕਾਰ ਜਾਂ ਸਰਵਿਸ-ਅਕਾਊਂਟ API ਕੁੰਜੀ** ਰਾਹੀਂ Cursor ਦੀ ਅਧਿਕਾਰਤ REST API (`api.cursor.com/v0`) ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਉਸਦੇ Background / Cloud Agents ਨੂੰ ਚਲਾਉਂਦਾ ਹੈ — ਇਹ Cursor IDE ਦੇ OAuth ਸੈਸ਼ਨ (ਪ੍ਰਦਾਤਾ `cursor`, ਜਿਸ ਨਾਲ ਪਾਬੰਦੀ ਲੱਗਣ ਦੇ ਜੋਖ਼ਮ ਦੀ ਚੇਤਾਵਨੀ ਜੁੜੀ ਹੈ) ਨੂੰ ਮੁੜ ਵਰਤਣ ਦੇ ਮੁਕਾਬਲੇ ਵਧੇਰੇ ਸੁਰੱਖਿਅਤ, ਪਹਿਲੀ-ਧਿਰ ਵਾਲਾ ਵਿਕਲਪ ਹੈ। ਇਹ ਇੱਕ ਸਧਾਰਨ REST ਅਡੈਪਟਰ ਹੈ (ਕੋਈ `@cursor/sdk` ਮੂਲ ਡਿਪੈਂਡੈਂਸੀ ਨਹੀਂ)। `approvePlan` ਤਰੁੱਟੀ ਸੁੱਟਦਾ ਹੈ (Cursor ਏਜੰਟ ਖੁਦਮੁਖਤਿਆਰੀ ਨਾਲ ਚੱਲਦੇ ਹਨ); `listSources` ਕੁੰਜੀ ਰਾਹੀਂ ਪਹੁੰਚਯੋਗ ਰਿਪੋਜ਼ਟਰੀਆਂ ਦੀ ਸੂਚੀ ਦਿੰਦਾ ਹੈ। Cursor ਵੱਡੇ ਅੱਖਰਾਂ ਵਾਲੇ ਸਥਿਤੀ enum (`CREATING`/`RUNNING`/`FINISHED`/`ERROR`) ਵਾਪਸ ਕਰਦਾ ਹੈ, ਜਿਨ੍ਹਾਂ ਨੂੰ ਸਪਸ਼ਟ ਤੌਰ 'ਤੇ ਸਾਂਝੇ `CloudAgentStatus` ਨਾਲ ਮੈਪ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। `baseUrl` ਨੂੰ ਹਰ ਕ੍ਰੀਡੈਂਸ਼ਲ ਲਈ ਓਵਰਰਾਈਡ ਕੀਤਾ ਜਾ ਸਕਦਾ ਹੈ, ਤਾਂ ਜੋ API ਵਰਜਨ/ਪਾਥ ਨੂੰ ਕੋਡ ਬਦਲੇ ਬਿਨਾਂ ਠੀਕ ਕੀਤਾ ਜਾ ਸਕੇ।

## ਡੋਮੇਨ ਕਿਸਮਾਂ

ਸਰੋਤ: `src/lib/cloudAgent/types.ts`

```typescript
export const CLOUD_AGENT_STATUS = {
  QUEUED: "queued",
  RUNNING: "running",
  AWAITING_APPROVAL: "awaiting_approval",
  COMPLETED: "completed",
  FAILED: "failed",
  CANCELLED: "cancelled",
} as const;

export interface CloudAgentSource {
  repoName: string;
  repoUrl: string; // ਇੱਕ ਵੈਧ URL ਹੋਣਾ ਲਾਜ਼ਮੀ ਹੈ
  branch?: string;
}

export interface CloudAgentResult {
  prUrl?: string;
  prNumber?: number;
  commitMessage?: string;
  diffUrl?: string;
  summary?: string;
  duration?: number; // ਸਕਿੰਟ, ਧਨਾਤਮਕ ਪੂਰਨ ਅੰਕ
  cost?: number; // ਧਨਾਤਮਕ ਫਲੋਟ
}

export interface CloudAgentActivity {
  id: string;
  type: "plan" | "command" | "code_change" | "message" | "error" | "completion";
  content: string;
  timestamp: string; // ISO 8601
  metadata?: Record<string, unknown>;
}

export interface CloudAgentTask {
  id: string; // ਅੰਦਰੂਨੀ `task_...` id
  providerId: "jules" | "devin" | "codex-cloud" | "cursor-cloud";
  externalId?: string; // ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰਦਾਤਾ ਦਾ id
  status: CloudAgentStatus;
  prompt: string; // 1..10000 ਅੱਖਰ
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
  createdAt: string;
  updatedAt: string;
  completedAt?: string;
}
```

ਪ੍ਰਮਾਣਿਕਤਾ ਸਕੀਮਾਂ (`CreateCloudAgentTaskSchema`, `UpdateCloudAgentTaskSchema`) ਕਿਸਮਾਂ ਦੇ ਨਾਲ ਹੀ ਐਕਸਪੋਰਟ ਕੀਤੀਆਂ ਜਾਂਦੀਆਂ ਹਨ ਅਤੇ ਰੂਟ ਹੈਂਡਲਰਾਂ ਵੱਲੋਂ ਵਰਤੀਆਂ ਜਾਂਦੀਆਂ ਹਨ।

## ਡਾਟਾਬੇਸ

ਸਰੋਤ: `src/lib/cloudAgent/db.ts` — ਟੇਬਲ ਨੂੰ
`createCloudAgentTaskTable()` ਰਾਹੀਂ ਲੋੜ ਪੈਣ 'ਤੇ ਬਣਾਇਆ ਜਾਂਦਾ ਹੈ (`src/lib/cloudAgent/index.ts` ਤੋਂ
ਮੋਡੀਊਲ ਇੰਪੋਰਟ ਵੇਲੇ ਵੀ ਕਾਲ ਕੀਤਾ ਜਾਂਦਾ ਹੈ)।

```sql
CREATE TABLE IF NOT EXISTS cloud_agent_tasks (
  id           TEXT PRIMARY KEY,
  provider_id  TEXT NOT NULL,
  external_id  TEXT,
  status       TEXT NOT NULL DEFAULT 'queued',
  prompt       TEXT NOT NULL,
  source       TEXT NOT NULL,             -- JSON
  options      TEXT DEFAULT '{}',         -- JSON
  result       TEXT,                       -- JSON
  activities   TEXT DEFAULT '[]',          -- JSON
  error        TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_provider ON cloud_agent_tasks(provider_id);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_status   ON cloud_agent_tasks(status);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_created  ON cloud_agent_tasks(created_at DESC);
```

SQL ਇੰਜੈਕਸ਼ਨ ਨੂੰ ਰੋਕਣ ਲਈ `updateCloudAgentTask` ਇੱਕ **ਕਾਲਮ ਵ੍ਹਾਈਟਲਿਸਟ** ਲਾਗੂ ਕਰਦਾ ਹੈ:
`status`, `prompt`, `source`, `options`, `result`, `activities`, `error`,
`completed_at`। ਅੰਸ਼ਕ ਅੱਪਡੇਟ ਵਿੱਚ ਮੌਜੂਦ ਕਿਸੇ ਵੀ ਹੋਰ ਕੁੰਜੀ ਨੂੰ ਬਿਨਾਂ ਕੋਈ ਸੂਚਨਾ ਦਿੱਤੇ ਹਟਾ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ।

## REST API — ਟਾਸਕ ਜੀਵਨ-ਚੱਕਰ

**ਪ੍ਰਮਾਣੀਕਰਨ:** ਸਾਰੇ `/api/v1/agents/tasks*` ਐਂਡਪੌਇੰਟਾਂ ਲਈ **ਮੈਨੇਜਮੈਂਟ ਪ੍ਰਮਾਣੀਕਰਨ**
ਦੀ ਲੋੜ ਹੈ (`requireCloudAgentManagementAuth`, `src/lib/api/requireManagementAuth` ਤੋਂ
`requireManagementAuth` ਨੂੰ ਰੈਪ ਕਰਦਾ ਹੈ)। ਇਹ commit `588a0333`
(_"fix(auth): ਏਜੰਟ ਅਤੇ ਕੂਲਡਾਊਨ APIs ਲਈ ਮੈਨੇਜਮੈਂਟ ਪ੍ਰਮਾਣੀਕਰਨ ਲਾਜ਼ਮੀ ਬਣਾਓ"_) ਤੋਂ ਬਾਅਦ ਲਾਗੂ ਕੀਤਾ ਗਿਆ ਹੈ।

ਬਿਲਿੰਗ ਰੋਕਣ ਲਈ, ਪ੍ਰਦਾਤਾ ਦੇ ਆਪਣੇ ਕੰਸੋਲ ਵਿੱਚ ਟਾਸਕ ਨੂੰ ਸਮਾਪਤ ਕਰੋ।

## REST API — ਕਲਾਉਡ ਪ੍ਰੋਵਾਈਡਰ ਪਲੰਬਿੰਗ

`src/app/api/cloud/` ਅਧੀਨ ਇਹ ਸਹਾਇਕ ਐਂਡਪੌਇੰਟ ਰਿਮੋਟ ਕਲਾਇੰਟਾਂ
(CLI, Electron ਐਪ, ਜਾਂ ਸਿੰਕ ਵਰਕਰਾਂ) ਵੱਲੋਂ ਪ੍ਰੋਵਾਈਡਰ ਕਨੈਕਸ਼ਨ ਮੈਟਾਡਾਟਾ ਪੜ੍ਹਨ
ਅਤੇ ਮਾਡਲ ਉਪਨਾਮਾਂ ਨੂੰ ਰਿਜ਼ਾਲਵ ਕਰਨ ਲਈ ਵਰਤੇ ਜਾਂਦੇ ਹਨ। ਇਨ੍ਹਾਂ ਨੂੰ ਟਾਸਕ ਐਂਡਪੌਇੰਟਾਂ ਵੱਲੋਂ ਵਰਤੀ ਜਾਂਦੀ ਮੈਨੇਜਮੈਂਟ ਪ੍ਰਮਾਣਿਕਤਾ ਦੀ ਬਜਾਏ ਇੱਕ **ਨਿਯਮਤ API ਕੁੰਜੀ**
(`validateApiKey` ਰਾਹੀਂ) ਨਾਲ ਪ੍ਰਮਾਣਿਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।

| ਵਿਧੀ | ਪਾਥ                             | ਉਦੇਸ਼                                                                    |
| ---- | ------------------------------- | ------------------------------------------------------------------------ |
| POST | `/api/cloud/auth`               | API ਕੁੰਜੀ ਪ੍ਰਮਾਣਿਤ ਕਰੋ, ਮਾਸਕ ਕੀਤਾ ਕਨੈਕਸ਼ਨ ਮੈਟਾਡਾਟਾ + ਮਾਡਲ ਉਪਨਾਮ ਵਾਪਸ ਕਰੋ |
| PUT  | `/api/cloud/credentials/update` | `accessToken` / `refreshToken` / `expiresAt` ਨੂੰ ਰਿਫ੍ਰੈਸ਼ ਕਰੋ            |
| POST | `/api/cloud/model/resolve`      | ਮਾਡਲ ਉਪਨਾਮ ਨੂੰ `{ provider, model }` ਵਿੱਚ ਰਿਜ਼ਾਲਵ ਕਰੋ                    |
| GET  | `/api/cloud/models/alias`       | ਸਾਰੇ ਮਾਡਲ ਉਪਨਾਮਾਂ ਦੀ ਸੂਚੀ ਦਿਓ                                            |
| PUT  | `/api/cloud/models/alias`       | ਮਾਡਲ ਉਪਨਾਮ ਸੈੱਟ ਕਰੋ (ਅਤੇ ਸਮਰੱਥ ਹੋਣ 'ਤੇ Cloud ਨਾਲ ਆਪਣੇ ਆਪ ਸਿੰਕ ਕਰੋ)       |

`/api/cloud/auth` ਕਦੇ ਵੀ ਕੱਚੇ `apiKey` / `accessToken` / `refreshToken` ਵਾਪਸ ਨਹੀਂ ਕਰਦਾ। ਇਹ
`hasApiKey`, `hasAccessToken`, `hasRefreshToken`, ਅਤੇ ਇੱਕ ਮਾਸਕ ਕੀਤਾ ਪੂਰਵਦਰਸ਼ਨ
(`maskedApiKey`: ਪਹਿਲੇ 4 + `****` + ਆਖਰੀ 4) ਵਾਪਸ ਕਰਦਾ ਹੈ।

## ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਰਿਜ਼ੋਲਿਊਸ਼ਨ

`src/lib/cloudAgent/api.ts` ਵਿੱਚ `getCloudAgentCredentials(providerId)`:

1. `getProviderConnections({ provider: providerId, isActive: true })` ਰਾਹੀਂ ਸਰਗਰਮ ਪ੍ਰੋਵਾਈਡਰ ਕਨੈਕਸ਼ਨ ਲੋਡ ਕਰਦਾ ਹੈ।
2. ਹਰ ਕਨੈਕਸ਼ਨ ਲਈ, `apiKey` (ਟ੍ਰਿਮ ਕੀਤੀ ਹੋਈ) ਨੂੰ ਤਰਜੀਹ ਦਿੰਦਾ ਹੈ। ਉਪਲਬਧ ਨਾ ਹੋਣ 'ਤੇ `accessToken` ਵਰਤਦਾ ਹੈ।
3. ਪਹਿਲਾ ਗੈਰ-ਖਾਲੀ ਟੋਕਨ `{ apiKey: token }` ਵਜੋਂ ਰੈਪ ਕਰਕੇ ਵਾਪਸ ਕਰਦਾ ਹੈ।
4. ਜੇ ਕੋਈ ਵਰਤੋਂਯੋਗ ਟੋਕਨ ਨਾ ਮਿਲੇ ਤਾਂ `null` ਵਾਪਸ ਕਰਦਾ ਹੈ — API `400` ਨਾਲ
   `"ਕਲਾਉਡ ਏਜੰਟ ਪ੍ਰੋਵਾਈਡਰ ਲਈ ਕੋਈ ਸਰਗਰਮ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਕੌਂਫਿਗਰ ਨਹੀਂ ਹਨ: <id>"` ਜਵਾਬ ਦਿੰਦਾ ਹੈ।

ਇਸਦਾ ਮਤਲਬ ਹੈ ਕਿ Cloud Agents ਨਿਯਮਤ LLM ਪ੍ਰੋਵਾਈਡਰਾਂ ਵਾਲੀ ਹੀ Provider Connection ਟੇਬਲ ਦੀ ਮੁੜ ਵਰਤੋਂ ਕਰਦੇ ਹਨ।
Jules ਨੂੰ ਸਮਰੱਥ ਕਰਨ ਲਈ, `provider: "jules"` ਅਤੇ ਭਰੀ ਹੋਈ `apiKey` ਨਾਲ ਇੱਕ ਸਰਗਰਮ ਕਨੈਕਸ਼ਨ ਬਣਾਓ।

## ਡੈਸ਼ਬੋਰਡ

ਸਰੋਤ: `src/app/(dashboard)/dashboard/cloud-agents/page.tsx`

ਇੱਕ `"use client"` React ਪੇਜ ਜੋ:

- ਟਾਸਕਾਂ ਦੀ ਸੂਚੀ ਦਿਖਾਉਂਦਾ ਹੈ (`GET /api/v1/agents/tasks` ਰਾਹੀਂ ਪੋਲ ਕੀਤੀ ਜਾਂਦੀ ਹੈ)।
- `CreateCloudAgentTaskSchema` ਨਾਲ ਮੈਪ ਹੋਣ ਵਾਲੇ ਫਾਰਮ ਰਾਹੀਂ ਨਵੇਂ ਟਾਸਕ ਸਬਮਿਟ ਕਰਦਾ ਹੈ।
- ਸਥਿਤੀ ਬੈਜ (`queued`, `running`, `awaiting_approval`, `completed`,
  `failed`, `cancelled`) ਦਿਖਾਉਂਦਾ ਹੈ ਅਤੇ `activities[]` ਟਾਈਮਲਾਈਨ ਰੈਂਡਰ ਕਰਦਾ ਹੈ।
- ਜਦੋਂ `status === "completed"` ਹੋਵੇ ਤਾਂ `result.prUrl` / `commitMessage` / `summary` ਨੂੰ ਪ੍ਰਦਰਸ਼ਿਤ ਕਰਦਾ ਹੈ।

## A2A ਨਾਲ ਏਕੀਕਰਨ

Cloud Agents ਨੂੰ ਇੱਕ ਅਜਿਹਾ A2A ਸਕਿੱਲ ਰਜਿਸਟਰ ਕਰਕੇ A2A ਸਕਿੱਲਾਂ ਵਜੋਂ ਉਪਲਬਧ ਕਰਵਾਇਆ ਜਾ ਸਕਦਾ ਹੈ ਜੋ
ਆਪਣੇ `tasks/send` ਹੈਂਡਲਰ ਨੂੰ `getAgent(...).createTask(...)` ਵੱਲ ਡੈਲੀਗੇਟ ਕਰਦਾ ਹੈ ਅਤੇ A2A ਟਾਸਕ
ਸਥਿਤੀ ਇਵੈਂਟਾਂ ਨੂੰ JSON-RPC 2.0 ਪ੍ਰੋਟੋਕੋਲ ਵਿੱਚ ਅਨੁਵਾਦ ਕਰਦਾ ਹੈ। [A2A-SERVER.md](./A2A-SERVER.md) ਵੇਖੋ।

## ਨਵਾਂ Cloud Agent ਸ਼ਾਮਲ ਕਰਨਾ

1. `CloudAgentBase` ਨੂੰ ਐਕਸਟੈਂਡ ਕਰਦੀ `src/lib/cloudAgent/agents/<name>.ts` ਬਣਾਓ।
2. `createTask`, `getStatus`, `approvePlan` (ਜਾਂ ਲਾਗੂ ਨਾ ਹੋਣ 'ਤੇ ਐਰਰ ਥ੍ਰੋ ਕਰੋ),
   `sendMessage`, `listSources` ਇੰਪਲੀਮੈਂਟ ਕਰੋ। ਸਥਿਤੀ ਸਧਾਰਨੀਕਰਨ ਲਈ `this.mapStatus(...)` ਵਰਤੋ।
3. ਇੱਕ ਸਥਿਰ `providerId` ਅਧੀਨ `src/lib/cloudAgent/registry.ts` ਵਿੱਚ ਰਜਿਸਟਰ ਕਰੋ।
4. `src/lib/cloudAgent/types.ts` ਵਿੱਚ `providerId` ਲਿਟਰਲ ਯੂਨੀਅਨ ਨੂੰ ਵਧਾਓ
   (`CloudAgentTask.providerId` ਅਤੇ `CreateCloudAgentTaskSchema`)।
5. ਜੇ ਪ੍ਰੋਵਾਈਡਰ ਨੂੰ ਕਨੈਕਸ਼ਨ ਰਿਕਾਰਡ ਦੀ ਲੋੜ ਹੈ ਤਾਂ ਉਸਨੂੰ `src/shared/constants/providers.ts` ਵਿੱਚ ਸ਼ਾਮਲ ਕਰੋ।
   OAuth-ਆਧਾਰਿਤ ਪ੍ਰੋਵਾਈਡਰਾਂ ਨੂੰ `src/lib/oauth/providers/` ਦੀ ਵੀ ਲੋੜ ਹੁੰਦੀ ਹੈ।
6. `tests/unit/cloud-agent-*.test.ts` ਅਧੀਨ ਟੈਸਟ ਸ਼ਾਮਲ ਕਰੋ।
7. ਇਸ ਦਸਤਾਵੇਜ਼ ਅਤੇ ਡੈਸ਼ਬੋਰਡ ਦੇ `CLOUD_AGENTS` ਕਾਂਸਟੈਂਟ ਨੂੰ ਅੱਪਡੇਟ ਕਰੋ।
