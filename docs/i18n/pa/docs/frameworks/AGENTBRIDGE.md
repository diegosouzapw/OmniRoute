AgentBridge, OmniRoute ਦਾ MITM (Man-in-the-Middle) ਪ੍ਰਾਕਸੀ ਹੈ ਜੋ IDE AI ਏਜੰਟਾਂ ਤੋਂ ਆਉਣ ਵਾਲੇ HTTPS ਟ੍ਰੈਫ਼ਿਕ ਨੂੰ ਇੰਟਰਸੈਪਟ ਕਰਦਾ ਹੈ ਅਤੇ ਇਸਨੂੰ OmniRoute ਦੇ ਏਕੀਕ੍ਰਿਤ ਰਾਊਟਿੰਗ ਇੰਜਣ ਰਾਹੀਂ ਮੁੜ ਰੂਟ ਕਰਦਾ ਹੈ। ਇਹ **10 IDE ਏਜੰਟਾਂ** ਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈ — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code, ਅਤੇ Trae (ਜਾਂਚ ਅਧੀਨ) — ਜਿਸ ਨਾਲ OmniRoute ਬਾਜ਼ਾਰ ਵਿੱਚ AI ਕੋਡਿੰਗ ਸਹਾਇਕਾਂ ਲਈ ਸਭ ਤੋਂ ਵਿਆਪਕ ਕਵਰੇਜ ਵਾਲਾ MITM ਪ੍ਰਾਕਸੀ ਬਣ ਜਾਂਦਾ ਹੈ।

**ਡੈਸ਼ਬੋਰਡ ਟਿਕਾਣਾ:** `/dashboard/tools/agent-bridge`
**ਸਾਈਡਬਾਰ ਸਮੂਹ:** ਟੂਲਜ਼ (Cloud Agents ਤੋਂ ਬਾਅਦ)
**ਇਹ ਵੀ ਵੇਖੋ:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — ਸਾਰੇ ਇੰਟਰਸੈਪਟ ਕੀਤੇ ਟ੍ਰੈਫ਼ਿਕ ਦੀ ਰੀਅਲ-ਟਾਈਮ ਵਿੱਚ ਨਿਗਰਾਨੀ ਕਰੋ; `docs/security/MITM-TPROXY-DECRYPT.md` (git; `/docs` ਵਿੱਚ ਕੰਪਾਇਲ ਨਹੀਂ ਕੀਤਾ ਗਿਆ) — `/api/tools/agent-bridge/tproxy` ਰੂਟ ਦੁਆਰਾ ਚਲਾਇਆ ਜਾਣ ਵਾਲਾ Linux TPROXY ਪਾਰਦਰਸ਼ੀ-ਡੀਕ੍ਰਿਪਟ ਕੈਪਚਰ ਮੋਡ।

## §1 ਸੰਖੇਪ ਜਾਣਕਾਰੀ

### AgentBridge ਕੀ ਹੈ?

ਜਦੋਂ ਕੋਈ IDE ਏਜੰਟ (ਜਿਵੇਂ ਕਿ GitHub Copilot, Cursor, Claude Code) API ਕਾਲ ਕਰਦਾ ਹੈ, ਤਾਂ ਉਹ ਸਿੱਧਾ ਅੱਪਸਟ੍ਰੀਮ AI ਪ੍ਰਦਾਤਾ (OpenAI, Anthropic, ਆਦਿ) ਨਾਲ ਕਨੈਕਟ ਹੁੰਦਾ ਹੈ। AgentBridge ਉਸ ਕਨੈਕਸ਼ਨ ਨੂੰ TLS ਪੱਧਰ 'ਤੇ ਪਾਰਦਰਸ਼ੀ ਢੰਗ ਨਾਲ ਇੰਟਰਸੈਪਟ ਕਰਦਾ ਹੈ — ਏਜੰਟ ਦੀ ਸੰਰਚਨਾ ਵਿੱਚ ਕਿਸੇ ਵੀ ਤਬਦੀਲੀ ਦੀ ਲੋੜ ਤੋਂ ਬਿਨਾਂ — ਅਤੇ ਬੇਨਤੀ ਨੂੰ OmniRoute ਰਾਹੀਂ ਮੁੜ ਲਿਖਦਾ ਹੈ।

ਇਸਦਾ ਮਤਲਬ ਹੈ ਕਿ ਤੁਸੀਂ ਇਹ ਕਰ ਸਕਦੇ ਹੋ:

- **ਕਿਸੇ ਵੀ ਏਜੰਟ ਨੂੰ ਕਿਸੇ ਵੀ ਪ੍ਰਦਾਤਾ ਵੱਲ ਮੁੜ ਰੂਟ ਕਰੋ**: Copilot OpenAI ਨਾਲ ਸੰਚਾਰ ਕਰ ਰਿਹਾ ਹੈ? ਇਸਨੂੰ Anthropic Claude, Gemini, ਜਾਂ OmniRoute ਦੇ 352 ਪ੍ਰਦਾਤਾਵਾਂ ਵਿੱਚੋਂ ਕਿਸੇ ਵੱਲ ਵੀ ਰੀਡਾਇਰੈਕਟ ਕਰੋ।
- **ਮਾਡਲ ਮੈਪਿੰਗ ਲਾਗੂ ਕਰੋ**: `gemini-3-flash` → `claude-sonnet-4.7` ਨੂੰ ਹੈਂਡਲਰ ਪੱਧਰ 'ਤੇ ਪਾਰਦਰਸ਼ੀ ਢੰਗ ਨਾਲ ਮੈਪ ਕਰੋ।
- **ਸਾਰੇ ਏਜੰਟ ਟ੍ਰੈਫ਼ਿਕ ਦੀ ਨਿਗਰਾਨੀ ਕਰੋ**: ਹਰ ਇੰਟਰਸੈਪਟ ਕੀਤੀ ਬੇਨਤੀ [Traffic Inspector](./TRAFFIC_INSPECTOR.md) ਵਿੱਚ ਪ੍ਰਕਾਸ਼ਿਤ ਕੀਤੀ ਜਾਂਦੀ ਹੈ।
- **OmniRoute ਦੀ ਲਚਕੀਲੇਪਣ ਸਮਰੱਥਾ ਲਾਗੂ ਕਰੋ**: ਕੰਬੋ ਰਾਊਟਿੰਗ, ਸਰਕਿਟ ਬ੍ਰੇਕਰ, ਫਾਲਬੈਕ, ਅਤੇ ਲਾਗਤ ਟ੍ਰੈਕਿੰਗ IDE ਏਜੰਟ ਟ੍ਰੈਫ਼ਿਕ ਲਈ ਵੀ ਕੰਮ ਕਰਦੇ ਹਨ।

## §2 ਆਰਕੀਟੈਕਚਰ

### 2.1 ਕੰਪੋਨੈਂਟਾਂ ਦੀ ਸੰਖੇਪ ਜਾਣਕਾਰੀ

```
IDE ਏਜੰਟ (VS Code / Cursor / ਆਦਿ)
    │  HTTPS (ਪੋਰਟ 443)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← DNS ਰੀਡਾਇਰੈਕਟ
    │
    ▼
src/mitm/server.cjs  (ਪੋਰਟ 443, CJS ਚਾਈਲਡ ਪ੍ਰੋਸੈਸ)
    │  Host ਹੈਡਰ SNI ਰਾਹੀਂ ਟਾਰਗੇਟ ਨੂੰ ਰਿਜ਼ਾਲਵ ਕਰਦਾ ਹੈ
    │  AgentBridge CA ਦੁਆਰਾ ਸਾਈਨ ਕੀਤਾ ਪ੍ਰਤੀ-SNI TLS ਸਰਟੀਫਿਕੇਟ ਬਣਾਉਂਦਾ ਹੈ
    ├── ਬਾਈਪਾਸ ਸੂਚੀ ਨਾਲ ਮੇਲ? → TCP ਪਾਸਥਰੂ (ਕੋਈ ਡਿਕ੍ਰਿਪਸ਼ਨ ਨਹੀਂ)
    ├── ਟਾਰਗੇਟ ਨਾਲ ਮੇਲ? → fetch → OmniRoute ਰਾਊਟਰ (ਪੋਰਟ 20128)
    │       └── handler.intercept() — TypeScript
    │               ├── ਬੇਨਤੀ ਦੀ ਬਾਡੀ/ਹੈਡਰਾਂ ਉੱਤੇ maskSecrets()
    │               ├── TrafficBuffer.push() — Traffic Inspector ਨੂੰ ਪ੍ਰਕਾਸ਼ਿਤ ਕਰਦਾ ਹੈ
    │               └── fetchRouter() → /v1/chat/completions
    └── ਕੋਈ ਮੇਲ ਨਹੀਂ? → TCP ਪਾਸਥਰੂ (ਕੋਈ ਡਿਕ੍ਰਿਪਸ਼ਨ ਨਹੀਂ)
```

### 2.2 MITM ਸਰਵਰ (`src/mitm/server.cjs`)

ਮੁੱਖ MITM ਸਰਵਰ ਇੱਕ Node.js CJS ਚਾਈਲਡ ਪ੍ਰੋਸੈਸ ਵਜੋਂ ਚੱਲਦਾ ਹੈ (ਮੌਜੂਦਾ CJS ਕੋਡਬੇਸ ਨੂੰ ਮੁੜ ਲਿਖਣ ਤੋਂ ਬਚਣ ਲਈ)। ਇਹ:

- ਪੋਰਟ 443 ਉੱਤੇ ਸੁਣਦਾ ਹੈ (ਵਿਸ਼ੇਸ਼ ਅਧਿਕਾਰ ਜਾਂ `authbind`/`setcap` ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ)
- OS ਤੋਂ CONNECT ਟਨਲ ਪ੍ਰਾਪਤ ਕਰਦਾ ਹੈ (`/etc/hosts` DNS ਰੀਡਾਇਰੈਕਟ ਰਾਹੀਂ)
- AgentBridge CA (`DATA_DIR/mitm/ca.crt`) ਦੁਆਰਾ ਸਾਈਨ ਕੀਤੇ ਪ੍ਰਤੀ-SNI TLS ਸਰਟੀਫਿਕੇਟ ਬਣਾਉਂਦਾ ਹੈ
- `targets/index.ts` ਰਜਿਸਟਰੀ ਰਾਹੀਂ Host ਹੈਡਰ ਦੇ ਆਧਾਰ ਉੱਤੇ ਟਾਰਗੇਟ ਏਜੰਟ ਨੂੰ ਰਿਜ਼ਾਲਵ ਕਰਦਾ ਹੈ
- HTTP ਰਾਹੀਂ `http://127.0.0.1:20128` ਉੱਤੇ TypeScript ਹੈਂਡਲਰ ਪਰਤ ਨੂੰ ਡਿਸਪੈਚ ਕਰਦਾ ਹੈ

`TARGET_HOSTS` ਨੂੰ `DATA_DIR/mitm/targets.json` ਤੋਂ ਲੋਡ ਕੀਤਾ ਜਾਂਦਾ ਹੈ (ਜਿਸਨੂੰ ਬੂਟ ਵੇਲੇ `targets/index.ts` ਦੁਆਰਾ ਲਿਖਿਆ ਜਾਂਦਾ ਹੈ), ਜਿਸ ਨਾਲ CJS ਸਰਵਰ ਨੂੰ ਮੁੜ ਚਾਲੂ ਕੀਤੇ ਬਿਨਾਂ ਡਾਇਨਾਮਿਕ ਅੱਪਡੇਟ ਸੰਭਵ ਹੁੰਦੇ ਹਨ।

> **ਰੂਟ-CA ਮਾਡਲ (#6684)।** ਉੱਪਰ ਦਿੱਤਾ ਪ੍ਰਤੀ-SNI-ਸਰਟੀਫਿਕੇਟ-ਜਿਸਨੂੰ-ਇੱਕ-CA-ਦੁਆਰਾ-ਸਾਈਨ-ਕੀਤਾ-ਗਿਆ ਹੈ ਵਰਣਨ
> #6684 ਵਿੱਚ ਜੋੜਿਆ ਗਿਆ ਸਥਾਈ ਰੂਟ-CA ਮਾਡਲ ਹੈ (`src/mitm/cert/rootCa.ts` +
> `src/mitm/_internal/rootCaShim.cjs`, ਜੋ `src/mitm/tproxy/dynamicCert.ts` ਵਿੱਚ TPROXY ਲਈ
> ਪਹਿਲਾਂ ਹੀ ਸਾਬਤ ਹੋਈ CA/ਲੀਫ਼ ਕ੍ਰਿਪਟੋਗ੍ਰਾਫੀ ਨੂੰ ਮੁੜ ਵਰਤਦਾ ਹੈ) — ਇਹ ਪੁਰਾਣੇ ਇਕੱਲੇ ਸਥਿਰ
> ਸਵੈ-ਸਾਈਨ ਕੀਤੇ ਲੀਫ਼ (`src/mitm/cert/generate.ts`, ਜੋ ਅਜੇ ਵੀ ਸਿਰਫ਼ antigravity ਹੋਸਟਾਂ ਤੱਕ
> ਸੀਮਿਤ ਹੈ) ਨੂੰ ਬਦਲਦਾ ਹੈ, ਜਿਸਦੀ ਮੌਜੂਦਗੀ ਡਿਸਕ ਉੱਤੇ ਸਿਰਫ਼ `server.crt`/`server.key`
> ਜੋੜਾ ਦਰਸਾਉਂਦਾ ਹੈ। **ਮਾਈਗ੍ਰੇਸ਼ਨ ਵਿਵਹਾਰ**: ਇੱਕ ਨਵੀਂ ਇੰਸਟਾਲੇਸ਼ਨ (ਕੋਈ ਪਹਿਲਾਂ ਵਾਲਾ
> `server.crt` ਨਹੀਂ) ਨੂੰ ਰੂਟ-CA ਮਾਡਲ ਆਪਣੇ ਆਪ ਮਿਲ ਜਾਂਦਾ ਹੈ; ਜਿਸ ਇੰਸਟਾਲੇਸ਼ਨ ਨੇ ਪੁਰਾਣੇ
> ਸਥਿਰ ਲੀਫ਼ ਉੱਤੇ ਪਹਿਲਾਂ ਹੀ ਭਰੋਸਾ ਕੀਤਾ ਹੋਇਆ ਹੈ, ਉਹ ਉਸਦੀ ਵਰਤੋਂ ਉਦੋਂ ਤੱਕ ਜਾਰੀ ਰੱਖਦੀ ਹੈ
> ਜਦੋਂ ਤੱਕ ਆਪਰੇਟਰ `MITM_ROOT_CA_ENABLED=true` ਸੈੱਟ ਕਰਕੇ ਬ੍ਰਿਜ ਨੂੰ ਮੁੜ ਚਾਲੂ ਨਹੀਂ ਕਰਦਾ
> (`src/mitm/cert/migration.ts` ਸ਼ੁੱਧ ਫ਼ੈਸਲਾ ਫੰਕਸ਼ਨ ਹੈ — ਇੱਕ ਭਰੋਸੇਯੋਗ MITM CA ਜੋ
> **ਕਿਸੇ ਵੀ** ਹੋਸਟ ਲਈ ਲੀਫ਼ ਸਾਈਨ ਕਰ ਸਕਦਾ ਹੈ, ਪੁਰਾਣੇ ਸਥਿਰ-SAN ਲੀਫ਼ ਨਾਲੋਂ ਕਾਫ਼ੀ ਵੱਧ
> ਸ਼ਕਤੀਸ਼ਾਲੀ ਹੈ, ਇਸ ਲਈ ਪਹਿਲਾਂ ਤੋਂ ਭਰੋਸੇਯੋਗ ਇੰਸਟਾਲੇਸ਼ਨ ਲਈ ਇਹ ਤਬਦੀਲੀ ਕਦੇ ਵੀ ਚੁੱਪਚਾਪ
> ਨਹੀਂ ਹੁੰਦੀ)। CA ਸਰਟੀਫਿਕੇਟ ਉਸੇ `omniroute-mitm.crt` ਟਰੱਸਟ-ਸਟੋਰ ਸਲਾਟ ਵਿੱਚ ਇੰਸਟਾਲ
> ਹੁੰਦਾ ਹੈ ਜਿਸਨੂੰ ਪੁਰਾਣਾ ਲੀਫ਼ ਵਰਤਦਾ ਸੀ (`cert/install.ts::installCaCert`) — ਦੋਹਰੇ-ਭਰੋਸੇ
> ਦੀ ਸਫ਼ਾਈ ਦੀ ਕੋਈ ਲੋੜ ਨਹੀਂ।

### 2.3 ਹੈਂਡਲਰ ਬੇਸ (`src/mitm/handlers/base.ts`)

ਸਾਰੇ ਏਜੰਟ ਹੈਂਡਲਰ `MitmHandlerBase` ਨੂੰ ਐਕਸਟੈਂਡ ਕਰਦੇ ਹਨ:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // ਸੁਰੱਖਿਅਤ ਸਹਾਇਕ: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

ਹਰੇਕ ਹੈਂਡਲਰ ਪ੍ਰਾਕਸੀ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ `hookBufferStart()` ਅਤੇ ਪੂਰਾ ਹੋਣ ਉੱਤੇ `hookBufferUpdate()` ਨੂੰ ਕਾਲ ਕਰਦਾ ਹੈ। ਇਹ `InterceptedRequest` ਐਂਟਰੀਆਂ ਨੂੰ `globalTrafficBuffer` ਵਿੱਚ ਪੁਸ਼ ਕਰਦੇ ਹਨ ([Traffic Inspector](./TRAFFIC_INSPECTOR.md) §4 ਵੇਖੋ)।

### 2.4 ਟਾਰਗੇਟ ਰਜਿਸਟਰੀ (`src/mitm/targets/`)

ਹਰੇਕ ਏਜੰਟ ਦੀ ਇੱਕ ਘੋਸ਼ਣਾਤਮਕ ਟਾਰਗੇਟ ਫ਼ਾਈਲ ਹੁੰਦੀ ਹੈ:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

ਰਜਿਸਟਰੀ (`targets/index.ts`) `ALL_TARGETS` ਨੂੰ ਐਕਸਪੋਰਟ ਕਰਦੀ ਹੈ ਅਤੇ ਬੂਟ ਵੇਲੇ `DATA_DIR/mitm/targets.json` ਬਣਾਉਂਦੀ ਹੈ।

### 2.5 ਪਾਸਥਰੂ ਅਤੇ ਬਾਈਪਾਸ ਸੂਚੀ (`src/mitm/passthrough.ts`)

**ਬਾਈਪਾਸ ਸੂਚੀ** (ਸਭ ਤੋਂ ਪਹਿਲਾਂ ਜਾਂਚੀ ਜਾਂਦੀ ਹੈ ਅਤੇ ਟਾਰਗੇਟ ਮੇਲ ਉੱਤੇ ਤਰਜੀਹ ਰੱਖਦੀ ਹੈ):

- ਡਿਫਾਲਟ ਪੈਟਰਨ: ਬੈਂਕਿੰਗ ਹੋਸਟ, `.gov.`, OAuth/SSO ਪ੍ਰਦਾਤਾ (Okta, Auth0), ਆਦਿ
- ਵਰਤੋਂਕਾਰ ਪੈਟਰਨ: DB ਟੇਬਲ `agent_bridge_bypass` ਵਿੱਚ ਸਟੋਰ ਕੀਤੇ ਜਾਂਦੇ ਹਨ
- ਬਾਈਪਾਸ ਕੀਤੇ ਹੋਸਟਾਂ ਨੂੰ ਇੱਕ ਪਾਰਦਰਸ਼ੀ TCP ਟਨਲ ਮਿਲਦੀ ਹੈ — TLS ਨੂੰ **ਕਦੇ ਵੀ ਡਿਕ੍ਰਿਪਟ ਨਹੀਂ ਕੀਤਾ ਜਾਂਦਾ**

**ਪਾਸਥਰੂ ਡਿਫਾਲਟ** (ਟਾਰਗੇਟ ਨਾਲ ਕੋਈ ਮੇਲ ਨਹੀਂ ਅਤੇ ਬਾਈਪਾਸ ਵਿੱਚ ਵੀ ਨਹੀਂ):

- ਇਸਨੂੰ ਵੀ ਇੱਕ TCP ਟਨਲ ਮਿਲਦੀ ਹੈ — ਕਨੈਕਸ਼ਨ ਕਦੇ ਵੀ ਤੋੜੇ ਨਹੀਂ ਜਾਂਦੇ
- AgentBridge ਨੂੰ ਸਿਸਟਮ ਦੇ ਆਮ HTTPS ਟ੍ਰੈਫ਼ਿਕ ਵਿੱਚ ਵਿਘਨ ਪਾਉਣ ਤੋਂ ਰੋਕਦਾ ਹੈ

ਰਾਊਟਿੰਗ ਤਰਜੀਹ:

```
ਬਾਈਪਾਸ ਸੂਚੀ → ਟਾਰਗੇਟ ਨਾਲ ਮੇਲ → ਪਾਸਥਰੂ
```

### 2.6 ਅੱਪਸਟ੍ਰੀਮ CA ਸਰਟੀਫਿਕੇਟ (`src/mitm/upstreamTrust.ts`)

ਕਸਟਮ CA ਵਾਲੇ ਕਾਰਪੋਰੇਟ ਨੈੱਟਵਰਕ ਵਾਤਾਵਰਣਾਂ ਲਈ:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

ਸੈੱਟ ਹੋਣ ਉੱਤੇ, ਇਹ ਵਾਧੂ CA ਸਰਟੀਫਿਕੇਟ ਨਾਲ `undici` ਦੇ ਗਲੋਬਲ ਡਿਸਪੈਚਰ ਨੂੰ ਸੰਰਚਿਤ ਕਰਦਾ ਹੈ, ਜਿਸ ਨਾਲ AgentBridge ਕਾਰਪੋਰੇਟ TLS ਟਰਮੀਨੇਸ਼ਨ ਪ੍ਰਾਕਸੀਆਂ ਰਾਹੀਂ ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰਦਾਤਾਵਾਂ ਤੱਕ ਪਹੁੰਚ ਸਕਦਾ ਹੈ।

### 2.7 ਗੁਪਤ ਜਾਣਕਾਰੀ ਨੂੰ ਮਾਸਕ ਕਰਨਾ (`src/mitm/maskSecrets.ts`)

ਸੁਤੰਤਰ ਕਲੀਨ-ਰੂਮ ਸਕੈਨਰ ਨੂੰ ਬੇਨਤੀ ਦੀਆਂ ਬਾਡੀਆਂ ਅਤੇ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਹੈਡਰਾਂ ਉੱਤੇ
Traffic Inspector ਬਫ਼ਰ ਜਾਂ ਕਿਸੇ ਵੀ ਲੌਗ ਵਿੱਚ ਜਾਣ ਤੋਂ **ਪਹਿਲਾਂ** ਲਾਗੂ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। ਇਹ ਇੱਕੋ ਲੀਨੀਅਰ ਪਾਸ ਕਰਦਾ ਹੈ:

- `sk-` / `ak-` / `pk-` ਪ੍ਰੀਫਿਕਸ ਵਾਲੇ ਟੋਕਨ (OpenAI/Anthropic-ਸ਼ੈਲੀ)
- RFC 6750 `Authorization: Bearer <token>` ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ, ਪੂਰੇ-ਟੋਕਨ ਦੀ ਤਰਜੀਹ ਨਾਲ
- ਆਮ ਲੰਮੇ ਅਪਾਰਦਰਸ਼ੀ ਟੋਕਨ (≥40 ਅੱਖਰ), ਜਿਨ੍ਹਾਂ ਵਿੱਚ ਡੌਟ ਵਾਲੇ ਅਤੇ ਪੈਡ ਕੀਤੇ ਰੂਪ ਸ਼ਾਮਲ ਹਨ

`sanitizeHeaders()` ਰੱਖੇ ਗਏ ਨਾਮਾਂ ਨੂੰ ਛੋਟੇ ਅੱਖਰਾਂ ਵਿੱਚ ਬਦਲਦਾ ਹੈ, ਐਰੇ ਮੁੱਲਾਂ ਨੂੰ ਨਿਰਧਾਰਤ ਢੰਗ ਨਾਲ ਜੋੜਦਾ ਹੈ,
ਸਾਂਝੀ ਹੌਪ-ਬਾਈ-ਹੌਪ/ਫ੍ਰੇਮਿੰਗ ਅਸਵੀਕਾਰ ਸੂਚੀ (ਪ੍ਰਾਕਸੀ ਪ੍ਰਮਾਣਿਕਤਾ ਸਮੇਤ) ਨੂੰ ਹਟਾਉਂਦਾ ਹੈ, `cookie` ਅਤੇ
`set-cookie` ਨੂੰ ਪੂਰੀ ਤਰ੍ਹਾਂ ਰੀਡੈਕਟ ਕਰਦਾ ਹੈ ਅਤੇ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਮੁੱਲਾਂ ਨੂੰ ਸਕੈਨਰ ਦੇ ਹਵਾਲੇ ਕਰਦਾ ਹੈ।

| ----------------------- | ---------------------------------------------------------------------------------- |
| ਸਰਵਰ ਸ਼ੁਰੂ ਕਰੋ          | ਪੋਰਟ 443 ਉੱਤੇ `src/mitm/server.cjs` ਸ਼ੁਰੂ ਕਰਦਾ ਹੈ                                  |
| ਸਰਵਰ ਬੰਦ ਕਰੋ            | ਚਾਈਲਡ ਪ੍ਰੋਸੈੱਸ ਨੂੰ ਸੁਚੱਜੇ ਢੰਗ ਨਾਲ ਬੰਦ ਕਰਦਾ ਹੈ                                      |
| ਸਰਵਰ ਮੁੜ-ਸ਼ੁਰੂ ਕਰੋ      | ਬੰਦ + ਸ਼ੁਰੂ ਕਰਦਾ ਹੈ (ਟਾਰਗੇਟ ਤਬਦੀਲੀਆਂ ਲਾਗੂ ਕਰਦਾ ਹੈ)                                 |

| ਸਰਟੀਫਿਕੇਟ ਡਾਊਨਲੋਡ ਕਰੋ   | ਹੱਥੀਂ ਇੰਸਟਾਲੇਸ਼ਨ ਲਈ `ca.crt` ਡਾਊਨਲੋਡ ਕਰਦਾ ਹੈ                                       |
| ਸਰਟੀਫਿਕੇਟ ਮੁੜ-ਤਿਆਰ ਕਰੋ  | ਇੱਕ ਨਵਾਂ CA ਕੀ-ਪੇਅਰ ਬਣਾਉਂਦਾ ਹੈ (ਸਾਰੇ ਮੌਜੂਦਾ ਪ੍ਰਤੀ-ਏਜੰਟ ਸਰਟੀਫਿਕੇਟ ਅਵੈਧ ਹੋ ਜਾਂਦੇ ਹਨ) |

### 3.2 ਸਰਟੀਫਿਕੇਟ 'ਤੇ ਭਰੋਸਾ ਕਰੋ

IDE ਵੱਲੋਂ MITM ਕਨੈਕਸ਼ਨ ਸਵੀਕਾਰ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ OS ਨੂੰ AgentBridge CA ਸਰਟੀਫਿਕੇਟ 'ਤੇ ਭਰੋਸਾ ਹੋਣਾ ਲਾਜ਼ਮੀ ਹੈ।

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Keychain):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

ਜਾਂ ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ "ਸਰਟੀਫਿਕੇਟ 'ਤੇ ਭਰੋਸਾ ਕਰੋ" ਬਟਨ ਦੀ ਵਰਤੋਂ ਕਰੋ (ਇਹ ਤੁਹਾਡੇ OS ਲਈ ਢੁਕਵੀਂ ਕਮਾਂਡ ਚਲਾਉਂਦਾ ਹੈ ਅਤੇ ਲੋੜ ਪੈਣ 'ਤੇ sudo ਪ੍ਰੌਂਪਟ ਦਿਖਾਉਂਦਾ ਹੈ)।

#### Electron-ਅਧਾਰਿਤ IDE, OS ਟਰੱਸਟ ਸਟੋਰ ਨੂੰ ਅਣਡਿੱਠਾ ਕਰਦੇ ਹਨ (`NODE_EXTRA_CA_CERTS`)

ਕੁਝ IDE — ਖ਼ਾਸ ਤੌਰ 'ਤੇ **Antigravity IDE**, ਅਤੇ ਹੋਰ Electron / VS Code ਤੋਂ ਬਣੀਆਂ ਐਪਾਂ — ਆਪਣੇ
ਨਾਲ ਆਪਣਾ Node.js ਰਨਟਾਈਮ ਸ਼ਾਮਲ ਕਰਦੇ ਹਨ ਜੋ ਬਾਹਰ ਜਾਣ ਵਾਲੇ `fetch`/HTTPS ਲਈ **OS ਟਰੱਸਟ ਸਟੋਰ ਦੀ ਵਰਤੋਂ ਨਹੀਂ ਕਰਦਾ**।
OS/NSS ਪੱਧਰ 'ਤੇ CA ਉੱਤੇ ਭਰੋਸਾ ਕਰਨਾ IDE ਦੇ ਮੂਲ **ਬੈਕਐਂਡ**
(ਉਦਾਹਰਨ ਲਈ, ਇੱਕ Go ਲੈਂਗਵੇਜ ਸਰਵਰ, ਜੋ OS CA ਬੰਡਲ ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ) ਲਈ ਕਾਫ਼ੀ ਹੈ, ਪਰ **Electron ਫਰੰਟਐਂਡ**
ਵਿੱਚ ਫਿਰ ਵੀ TLS ਅਸਫਲ ਰਹੇਗਾ — ਇਹ ਐਪ ਵਿੱਚੋਂ _ਲੌਗ ਆਉਟ_ ਹੋਣ ਜਾਂ _"ਕਨੈਕਸ਼ਨ ਗਲਤੀ"_
ਦਿਖਾਈ ਦੇਣ ਦੇ ਰੂਪ ਵਿੱਚ ਸਾਹਮਣੇ ਆਉਂਦਾ ਹੈ, ਭਾਵੇਂ MITM ਲੌਗ ਬੈਕਐਂਡ ਦੀਆਂ ਬੂਟਸਟਰੈਪ ਕਾਲਾਂ ਨੂੰ `200` ਵਾਪਸ ਕਰਦੀਆਂ ਦਿਖਾਉਂਦਾ ਹੋਵੇ। ਦੋ ਕਦਮ
ਲਾਜ਼ਮੀ ਹਨ, ਅਤੇ ਦੋਵੇਂ ਮਹੱਤਵਪੂਰਨ ਹਨ:

1. ਰਨਟਾਈਮ ਨੂੰ ਸਪਸ਼ਟ ਤੌਰ 'ਤੇ CA ਵੱਲ ਇਸ਼ਾਰਾ ਕਰਵਾਓ:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **ਉਸੇ ਸ਼ੈੱਲ ਤੋਂ IDE ਲਾਂਚ ਕਰੋ।** ਇਸਨੂੰ ਡੈਸਕਟਾਪ ਆਈਕਨ / Dock / Start ਮੀਨੂ ਤੋਂ ਸ਼ੁਰੂ ਕਰਨ ਨਾਲ
   ਸ਼ੈੱਲ ਐਕਸਪੋਰਟ ਵਿਰਾਸਤ ਵਿੱਚ **ਨਹੀਂ** ਮਿਲਦੇ, ਅਤੇ `~/.config/environment.d/*.conf` ਸਿਰਫ਼
   ਨਵੇਂ ਗ੍ਰਾਫ਼ਿਕਲ ਲੌਗਇਨ ਤੋਂ ਬਾਅਦ ਲਾਗੂ ਹੁੰਦਾ ਹੈ। ਪਹਿਲਾਂ IDE ਨੂੰ ਪੂਰੀ ਤਰ੍ਹਾਂ ਬੰਦ ਕਰੋ — Electron ਦੇ ਸਿੰਗਲਟਨ ਲੌਕ ਕਾਰਨ ਦੂਜੀ
   ਲਾਂਚ ਸਿਰਫ਼ ਮੌਜੂਦਾ ਪ੍ਰੋਸੈੱਸ ਉੱਤੇ ਫੋਕਸ ਕਰਦੀ ਹੈ ਅਤੇ ਨਵੇਂ ਇਨਵਾਇਰਨਮੈਂਟ ਨੂੰ ਅਣਡਿੱਠਾ ਕਰ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ।

ਉੱਪਰ ਦਿੱਤਾ OS-ਟਰੱਸਟ + NSS ਕਦਮ ਫਿਰ ਵੀ ਲਾਜ਼ਮੀ ਹੈ (ਕੁਝ ਪ੍ਰਮਾਣੀਕਰਨ
ਫ਼ਲੋਜ਼ ਵੱਲੋਂ ਵਰਤਿਆ ਜਾਂਦਾ Chromium ਨੈੱਟਵਰਕ ਸਟੈਕ ਪ੍ਰਤੀ-ਉਪਭੋਗਤਾ NSS ਸਟੋਰ ਨੂੰ ਪੜ੍ਹਦਾ ਹੈ, ਅਤੇ ਇਸ ਵਿੱਚ `*.googleapis.com` ਲਈ ਆਪਣੇ ਸਥਿਰ ਪਿੰਨ ਹਨ, ਜਿਨ੍ਹਾਂ ਨੂੰ
ਸਥਾਨਕ ਤੌਰ 'ਤੇ ਭਰੋਸੇਯੋਗ CA ਓਵਰਰਾਈਡ ਕਰਦਾ ਹੈ)। ਇਸ ਤੋਂ ਇਲਾਵਾ, `NODE_EXTRA_CA_CERTS` Node ਦੇ `fetch` ਪਾਥ ਨੂੰ ਕਵਰ ਕਰਦਾ ਹੈ।

### 3.3 DNS ਰੂਟਿੰਗ

ਹਰ ਉਸ ਏਜੰਟ ਲਈ ਜਿਸਨੂੰ ਤੁਸੀਂ ਇੰਟਰਸੈਪਟ ਕਰਨਾ ਚਾਹੁੰਦੇ ਹੋ, ਉਸਦੇ API ਹੋਸਟ ਨੂੰ `127.0.0.1` 'ਤੇ ਰਿਜ਼ਾਲਵ ਹੋਣਾ ਲਾਜ਼ਮੀ ਹੈ। ਜਦੋਂ ਤੁਸੀਂ ਸੈੱਟਅੱਪ ਵਿਜ਼ਾਰਡ ਵਿੱਚ ਕਿਸੇ ਏਜੰਟ ਲਈ DNS ਟੌਗਲ ਕਰਦੇ ਹੋ, ਤਾਂ AgentBridge ਆਪਣੇ-ਆਪ `/etc/hosts` ਐਂਟਰੀਆਂ ਦਾ ਪ੍ਰਬੰਧ ਕਰਦਾ ਹੈ।

GitHub Copilot ਲਈ `/etc/hosts` ਐਂਟਰੀਆਂ ਦੀ ਉਦਾਹਰਨ:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 ਮਾਡਲ ਮੈਪਿੰਗ

ਸਰੋਤ → ਟਾਰਗੇਟ ਮੈਪਿੰਗਾਂ ਪਰਿਭਾਸ਼ਿਤ ਕਰਨ ਲਈ ਹਰੇਕ ਏਜੰਟ ਕਾਰਡ ਵਿੱਚ ਮਾਡਲ ਮੈਪਿੰਗ ਸਾਰਣੀ ਦੀ ਵਰਤੋਂ ਕਰੋ:

| ਸਰੋਤ ਮਾਡਲ (ਏਜੰਟ ਦਾ ਮੂਲ) | ਟਾਰਗੇਟ ਮਾਡਲ (OmniRoute) |
| ----------------------- | ----------------------- |
| `gpt-4o`                | `claude-sonnet-4.7`     |
| `*` (ਵਾਈਲਡਕਾਰਡ)         | `claude-haiku-4.7`      |

ਵਾਈਲਡਕਾਰਡ `*` ਕਿਸੇ ਵੀ ਅਣਪਛਾਤੇ ਮਾਡਲ ਨੂੰ ਨਿਰਧਾਰਤ ਟਾਰਗੇਟ ਨਾਲ ਮੈਪ ਕਰਦਾ ਹੈ। ਇਹ `agent_bridge_mappings` ਸਾਰਣੀ ਵਿੱਚ ਸਥਾਈ ਤੌਰ 'ਤੇ ਸੰਭਾਲਿਆ ਜਾਂਦਾ ਹੈ।

> **ਸੁਝਾਅ — ਏਜੰਟ ਦੀਆਂ ਅਸਲ ਮਾਡਲ ID ਖੋਜੋ।** ਇੱਕ IDE ਅਜਿਹੇ ਮਾਡਲ ਨਾਮ ਭੇਜ ਸਕਦਾ ਹੈ ਜੋ
> ਉਸਦੇ UI ਲੇਬਲਾਂ ਤੋਂ ਵੱਖਰੇ ਹੁੰਦੇ ਹਨ ਅਤੇ ਵੱਡੇ ਵਰਜਨਾਂ ਵਿਚਕਾਰ ਬਦਲਦੇ ਹਨ। ਉਦਾਹਰਨ ਲਈ, **Antigravity 2**
> ਨੈੱਟਵਰਕ ਰਾਹੀਂ `gemini-3.1-pro-low`, `gemini-pro-agent`, ਅਤੇ `gemini-3.1-flash-lite` ਭੇਜਦਾ ਹੈ — ਪੁਰਾਣੇ
> ਦਸਤਾਵੇਜ਼ਾਂ ਵਿੱਚ ਦਿਖਾਇਆ `gemini-2.5-pro` ਨਹੀਂ। ਬਿਨਾਂ ਕਿਸੇ ਮੇਲ ਖਾਂਦੀ ਮੈਪਿੰਗ ਦੇ ਇੱਕ ਚੈਟ ਭੇਜੋ: MITM
> ਆਉਣ ਵਾਲੇ ਸਟੀਕ `model:` ਨੂੰ ਲੌਗ ਕਰਦਾ ਹੈ ਅਤੇ ਬੇਨਤੀ ਨੂੰ ਅੱਗੇ ਭੇਜ ਦਿੰਦਾ ਹੈ। ਉਸ ਸ਼ਾਬਦਿਕ ਮੁੱਲ ਨੂੰ ਮੈਪ ਕਰੋ, ਫਿਰ
> ਅਗਲੀ ਬੇਨਤੀ ਇੰਟਰਸੈਪਟ ਹੋ ਕੇ ਤੁਹਾਡੇ ਟਾਰਗੇਟ ਵੱਲ ਰੂਟ ਹੋ ਜਾਂਦੀ ਹੈ।

### 3.5 ਜੋਖਮ ਸੂਚਨਾ

AgentBridge ਉਹ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ (OAuth ਟੋਕਨ, API ਕੁੰਜੀਆਂ) ਇੰਟਰਸੈਪਟ ਕਰਦਾ ਹੈ, ਜਿਨ੍ਹਾਂ ਨੂੰ IDE ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰਦਾਤਾਵਾਂ ਨਾਲ ਪ੍ਰਮਾਣੀਕਰਨ ਲਈ ਵਰਤਦਾ ਹੈ। ਇਹ **ਲੌਗਿੰਗ ਤੋਂ ਪਹਿਲਾਂ ਮਾਸਕ ਕੀਤੇ ਜਾਂਦੇ ਹਨ** (§2.7 ਵੇਖੋ), ਪਰ OmniRoute ਦੀ MITM ਲੇਅਰ ਨੂੰ ਦਿਸਦੇ ਹਨ। ਹਰੇਕ ਏਜੰਟ ਦੀ ਪਹਿਲੀ ਐਕਟੀਵੇਸ਼ਨ ਇੱਕ ਖਾਰਜ ਕੀਤੀ ਜਾ ਸਕਣ ਵਾਲੀ ਜੋਖਮ ਸੂਚਨਾ ਮੋਡਲ ਦਿਖਾਉਂਦੀ ਹੈ।

> ਵਾਰ-ਵਾਰ sudo ਪ੍ਰੌਂਪਟਾਂ ਤੋਂ ਬਚਣ ਲਈ MITM ਰੂਟ CA ਨੂੰ ਰੋਕਣ/ਸ਼ੁਰੂ ਕਰਨ ਦੇ ਦੌਰਾਨ ਇੰਸਟਾਲ ਰੱਖਿਆ ਜਾਂਦਾ ਹੈ
> (mitmproxy/Charles ਵਰਗਾ ਹੀ ਵਿਹਾਰ), ਇਸ ਲਈ ਇਸਨੂੰ ਹਟਾਉਣਾ ਇੱਕ ਸਪਸ਼ਟ
> **CA ਹਟਾਓ** ਕਾਰਵਾਈ ਹੈ, ਨਾ ਕਿ ਰੋਕਣ ਵੇਲੇ ਆਪਣੇ-ਆਪ ਵਾਪਰਨ ਵਾਲੀ ਕੋਈ ਚੀਜ਼।

### 3.7 ਪੋਰਟੇਬਲ ਕੌਂਫਿਗ ਇੰਪੋਰਟ/ਐਕਸਪੋਰਟ

AgentBridge **ਓਪਰੇਟਰ ਵੱਲੋਂ ਟਿਊਨ ਕੀਤੀ ਜਾ ਸਕਣ ਵਾਲੀ** ਸਥਿਤੀ ਨੂੰ ਵਰਜਨ ਵਾਲੇ JSON ਬਲੌਬ ਵਿੱਚ ਸੀਰੀਅਲਾਈਜ਼ ਕਰ ਸਕਦਾ ਹੈ, ਤਾਂ ਜੋ ਇੱਕ ਸੈੱਟਅੱਪ ਨੂੰ ਕਈ ਮਸ਼ੀਨਾਂ ਉੱਤੇ ਦੁਹਰਾਇਆ ਜਾ ਸਕੇ। ਸੀਰੀਅਲਾਈਜ਼ਰ `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`) ਹੈ, ਜਿਸਨੂੰ `AgentBridgeConfigSchema` ਵੱਲੋਂ ਪ੍ਰਮਾਣਿਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।

ਐਕਸਪੋਰਟ ਵਿੱਚ ਬਿਲਕੁਲ ਤਿੰਨ ਭਾਗ ਸ਼ਾਮਲ ਹੁੰਦੇ ਹਨ (ਬਿਲਟ-ਇਨ ਡਿਫੌਲਟ ਜਾਣਬੁੱਝ ਕੇ ਐਕਸਪੋਰਟ **ਨਹੀਂ** ਕੀਤੇ ਜਾਂਦੇ, ਤਾਂ ਜੋ ਇੰਪੋਰਟ ਕਰਨ ਨਾਲ ਉਹ ਕਦੇ ਵੀ ਡੁਪਲੀਕੇਟ ਨਾ ਹੋਣ ਜਾਂ ਆਪਸ ਵਿੱਚ ਟਕਰਾਉਣ ਨਾ):

| ਫ਼ੀਲਡ            | ਸਰੋਤ                                                    | ਨੋਟ                                                            |
| ---------------- | ------------------------------------------------------- | -------------------------------------------------------------- |
| `bypassPatterns` | ਵਰਤੋਂਕਾਰ-ਪਰਿਭਾਸ਼ਿਤ ਬਾਈਪਾਸ ਪੈਟਰਨ (`agent_bridge_bypass`) | ਡਿਫੌਲਟ ਬੈਂਕ/gov/okta ਪੈਟਰਨ ਸ਼ਾਮਲ ਨਹੀਂ ਕੀਤੇ ਜਾਂਦੇ               |
| `customHosts`    | Traffic Inspector ਕਸਟਮ ਹੋਸਟ (`inspector_custom_hosts`)  | ਹਰੇਕ: `{ host, kind: "llm"\|"app"\|"custom", label? }`         |
| `agentMappings`  | ਹਰੇਕ ਏਜੰਟ ਲਈ ਮਾਡਲ ਮੈਪਿੰਗ (`agent_bridge_mappings`)      | ਮੈਪਿੰਗ ਵਾਲੇ ਹਰੇਕ ਏਜੰਟ ਲਈ `{ [agentId]: [{ source, target }] }` |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**ਇੰਪੋਰਟ ਵਿਹਾਰ** (`POST /api/tools/agent-bridge/config`): ਬਾਈਪਾਸ ਪੈਟਰਨ ਅਤੇ ਹਰੇਕ ਏਜੰਟ ਦੀਆਂ ਮੈਪਿੰਗਾਂ ਨੂੰ **ਪੂਰੀ ਤਰ੍ਹਾਂ ਬਦਲਿਆ ਜਾਂਦਾ ਹੈ**; ਕਸਟਮ ਹੋਸਟ **ਆਈਡੈਂਪੋਟੈਂਟ ਢੰਗ ਨਾਲ** ਜੋੜੇ ਜਾਂਦੇ ਹਨ (`INSERT OR IGNORE`)। ਜਵਾਬ ਰਿਪੋਰਟ ਕਰਦਾ ਹੈ ਕਿ ਹਰੇਕ ਵਿੱਚੋਂ ਕਿੰਨੇ ਲਾਗੂ ਕੀਤੇ ਗਏ:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

ਸੰਰਚਨਾ ਵਿੱਚ ਕੀ **ਨਹੀਂ** ਹੈ: ਸਰਵਰ ਦੀ ਚੱਲ ਰਹੀ ਸਥਿਤੀ, ਸਰਟੀਫਿਕੇਟ ਪਾਥ, ਪ੍ਰਤੀ-ਏਜੰਟ DNS ਸਥਿਤੀ, ਅੱਪਸਟ੍ਰੀਮ CA ਪਾਥ, ਅਤੇ TPROXY ਸੈਟਿੰਗਾਂ — ਇਹ ਹੋਸਟ/ਰਨਟਾਈਮ ਸਥਿਤੀ ਹਨ, ਪੋਰਟੇਬਲ ਤਰਜੀਹਾਂ ਨਹੀਂ।

### ਸੰਵੇਦਨਸ਼ੀਲ ਹੋਸਟਾਂ ਲਈ ਬਾਈਪਾਸ ਸੂਚੀ

ਬਾਈਪਾਸ ਸੂਚੀ ਇਹ ਯਕੀਨੀ ਬਣਾਉਂਦੀ ਹੈ ਕਿ ਵਿੱਤੀ ਸੰਸਥਾਵਾਂ, OAuth/SSO ਪ੍ਰਦਾਤਾਵਾਂ ਅਤੇ ਹੋਰ ਸੰਵੇਦਨਸ਼ੀਲ ਹੋਸਟਾਂ ਨੂੰ **ਕਦੇ ਵੀ ਡਿਕ੍ਰਿਪਟ ਨਹੀਂ ਕੀਤਾ ਜਾਂਦਾ**। ਉਨ੍ਹਾਂ ਦਾ TLS ਟ੍ਰੈਫ਼ਿਕ ਇੱਕ ਪਾਰਦਰਸ਼ੀ TCP ਟਨਲ ਵਜੋਂ ਲੰਘਦਾ ਹੈ — OmniRoute ਕਦੇ ਵੀ ਪਲੇਨਟੈਕਸਟ ਨਹੀਂ ਵੇਖਦਾ।

ਮੂਲ ਬਾਈਪਾਸ ਪੈਟਰਨਾਂ ਵਿੱਚ ਸ਼ਾਮਲ ਹਨ:

- `*.bank.*`, `*.gov.*` (ਵਿੱਤੀ/ਸਰਕਾਰੀ)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/ਪਛਾਣ)
- `*.apple.com`, `*.icloud.com` (Apple ਸਿਸਟਮ ਸੇਵਾਵਾਂ)

ਵਰਤੋਂਕਾਰ ਵੱਲੋਂ ਜੋੜੇ ਬਾਈਪਾਸ ਪੈਟਰਨ `agent_bridge_bypass` ਸਾਰਣੀ ਵਿੱਚ ਸਟੋਰ ਕੀਤੇ ਜਾਂਦੇ ਹਨ ਅਤੇ ਹਰ ਚੀਜ਼ ਉੱਤੇ ਤਰਜੀਹ ਰੱਖਦੇ ਹਨ।

### ਗੁਪਤ ਜਾਣਕਾਰੀ ਨੂੰ ਲੁਕਾਉਣਾ

`src/mitm/maskSecrets.ts` ਤੋਂ `maskSecrets()` ਲਾਗੂ ਕੀਤਾ ਜਾਂਦਾ ਹੈ:

- `TrafficBuffer.push()` ਤੋਂ ਪਹਿਲਾਂ ਹਰੇਕ ਬੇਨਤੀ ਬਾਡੀ ਉੱਤੇ
- ਲੌਗ ਕਰਨ ਜਾਂ ਬ੍ਰਾਡਕਾਸਟ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਹਰੇਕ ਹੈਡਰ ਉੱਤੇ

ਪੈਟਰਨ: `sk-`/`ak-`/`pk-` ਪ੍ਰੀਫਿਕਸ ਟੋਕਨ, `Bearer` ਟੋਕਨ, ਅਤੇ ≥40 ਅੱਖਰਾਂ ਵਾਲੇ ਆਮ ਟੋਕਨ।

### ਅੱਪਸਟ੍ਰੀਮ CA ਸਰਟੀਫਿਕੇਟ

ਜਦੋਂ `AGENTBRIDGE_UPSTREAM_CA_CERT` ਸੈੱਟ ਹੁੰਦਾ ਹੈ, ਤਾਂ ਫ਼ਾਈਲ ਨੂੰ ਸਟਾਰਟਅੱਪ ਵੇਲੇ ਪੜ੍ਹਿਆ ਜਾਂਦਾ ਹੈ। ਜੇ ਪਾਥ ਮੌਜੂਦ ਹੈ ਪਰ ਫ਼ਾਈਲ ਪੜ੍ਹੀ ਨਹੀਂ ਜਾ ਸਕਦੀ, ਤਾਂ AgentBridge ਇੱਕ ਸਪਸ਼ਟ ਗਲਤੀ ਲੌਗ ਕਰਦਾ ਹੈ ਅਤੇ ਸ਼ੁਰੂ ਹੋਣ ਤੋਂ ਇਨਕਾਰ ਕਰਦਾ ਹੈ (ਕਾਰਪੋਰੇਟ ਵਾਤਾਵਰਣਾਂ ਵਿੱਚ ਬਿਨਾਂ ਸੂਚਨਾ ਵਾਲੀਆਂ TLS ਅਸਫਲਤਾਵਾਂ ਨੂੰ ਰੋਕਦਾ ਹੈ)।

### ਜਾਣੀਆਂ-ਪਛਾਣੀਆਂ ਸੀਮਾਵਾਂ

- **ਪੋਰਟ 443 ਲਈ ਵਿਸ਼ੇਸ਼ ਅਧਿਕਾਰ ਲੋੜੀਂਦਾ ਹੈ**: Linux ਉੱਤੇ, AgentBridge ਨੂੰ Node ਬਾਈਨਰੀ ਉੱਤੇ `setcap 'cap_net_bind_service=+ep'` ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ, ਜਾਂ ਇਸ ਨੂੰ `authbind` ਰਾਹੀਂ ਚਲਾਓ। ਸੈੱਟਅੱਪ ਵਿਜ਼ਾਰਡ OS-ਵਿਸ਼ੇਸ਼ ਹਦਾਇਤਾਂ ਦਿਖਾਉਂਦਾ ਹੈ।
- **IDE ਨੂੰ ਮੁੜ-ਚਾਲੂ ਕਰਨਾ ਲਾਜ਼ਮੀ ਹੈ**: DNS ਰੀਡਾਇਰੈਕਟ ਤੋਂ ਬਾਅਦ, ਨਵੀਂ ਹੋਸਟ ਰਿਜ਼ੋਲਿਊਸ਼ਨ ਲਾਗੂ ਹੋਣ ਲਈ IDE ਨੂੰ ਮੁੜ-ਚਾਲੂ ਕਰਨਾ ਲਾਜ਼ਮੀ ਹੈ।
- **ਹਾਰਡਕੋਡ ਕੀਤੇ OAuth ਟੋਕਨ**: ਕੁਝ ਏਜੰਟ (Kiro, Antigravity) OAuth ਰਿਫ਼੍ਰੈਸ਼ ਟੋਕਨ ਸਥਾਨਕ ਤੌਰ ਉੱਤੇ ਸਟੋਰ ਕਰਦੇ ਹਨ। ਇਹ AgentBridge ਲਈ ਪਾਰਦਰਸ਼ੀ ਹਨ — ਇਹ ਹਰੇਕ ਬੇਨਤੀ ਵਿੱਚ Bearer ਟੋਕਨ ਵੇਖਦਾ ਹੈ, ਜਿਸ ਨੂੰ ਲੌਗ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਲੁਕਾਇਆ ਜਾਂਦਾ ਹੈ।
- **Electron ਫਰੰਟਐਂਡਾਂ ਨੂੰ `NODE_EXTRA_CA_CERTS` ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ**: ਉਹ IDE ਜਿਨ੍ਹਾਂ ਦਾ ਫਰੰਟਐਂਡ ਬੰਡਲ ਕੀਤੇ Node/Electron ਰਨਟਾਈਮ ਉੱਤੇ ਚੱਲਦਾ ਹੈ, OS/NSS ਟਰੱਸਟ ਸਟੋਰ ਨੂੰ ਅਣਡਿੱਠਾ ਕਰਦੇ ਹਨ ਅਤੇ ਉਨ੍ਹਾਂ ਨੂੰ ਅਜਿਹੇ ਸ਼ੈੱਲ ਤੋਂ ਲਾਂਚ ਕਰਨਾ ਲਾਜ਼ਮੀ ਹੈ ਜਿਸ ਵਿੱਚ `NODE_EXTRA_CA_CERTS` ਸੈੱਟ ਹੋਵੇ (§3.2 ਵੇਖੋ)। ਨਾ ਹੋਣ ਦਾ ਲੱਛਣ: IDE ਬੈਕਐਂਡ ਪ੍ਰਮਾਣਿਤ ਹੋ ਜਾਂਦਾ ਹੈ (MITM `200` ਦਿਖਾਉਂਦਾ ਹੈ), ਪਰ UI ਲੌਗ ਆਉਟ ਰਹਿੰਦਾ ਹੈ।
- **ਇੱਕੋ IDE ਦੀਆਂ ਕਈ ਇੰਸਟਾਲੇਸ਼ਨਾਂ ਸੁਤੰਤਰ ਹੁੰਦੀਆਂ ਹਨ**: ਇੱਕ ਸਿਸਟਮ ਇੰਸਟਾਲੇਸ਼ਨ (ਜਿਵੇਂ `/usr/share/antigravity/antigravity`) ਅਤੇ ਵਰਤੋਂਕਾਰ-ਸਥਾਨਕ "Full" ਇੰਸਟਾਲੇਸ਼ਨ (ਜਿਵੇਂ `~/AntigravityIDE_Full/antigravity-ide`) ਆਪਣੇ-ਆਪਣੇ ਰਨਟਾਈਮਾਂ ਵਾਲੀਆਂ ਵੱਖਰੀਆਂ ਪ੍ਰਕਿਰਿਆਵਾਂ ਹਨ — ਹਰੇਕ ਨੂੰ CA ਇੰਜੈਕਟ ਕਰਕੇ ਮੁੜ ਲਾਂਚ ਕਰਨਾ ਲਾਜ਼ਮੀ ਹੈ। ਮੁੜ ਲਾਂਚ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਇਸ ਦੇ ਬਾਈਨਰੀ ਪਾਥ ਰਾਹੀਂ ਪਛਾਣੋ ਕਿ ਕਿਹੜੀ ਚੱਲ ਰਹੀ ਹੈ।
- **ਪਛਾਣ ਏਜੰਟ ਦੇ ਸਿਸਟਮ ਪ੍ਰੌਮਪਟ ਦੁਆਰਾ ਸੈੱਟ ਹੁੰਦੀ ਹੈ, ਰੂਟ ਕੀਤੇ ਮਾਡਲ ਦੁਆਰਾ ਨਹੀਂ**: ਜਦੋਂ ਤੁਸੀਂ ਕਿਸੇ ਏਜੰਟ ਦੇ ਮਾਡਲ ਨੂੰ ਕਿਸੇ ਵੱਖਰੇ ਪ੍ਰਦਾਤਾ ਨਾਲ ਮੁੜ ਮੈਪ ਕਰਦੇ ਹੋ, ਤਾਂ ਜਵਾਬ ਫਿਰ ਵੀ ਏਜੰਟ ਦੀ ਮੂਲ ਪਛਾਣ ਦਾ ਦਾਅਵਾ ਕਰਦਾ ਹੈ (ਜਿਵੇਂ Antigravity ਜਵਾਬ ਦਿੰਦਾ ਹੈ "ਮੈਂ Gemini ਦੁਆਰਾ ਸੰਚਾਲਿਤ ਹਾਂ") ਕਿਉਂਕਿ IDE ਇਸ ਨੂੰ ਸਿਸਟਮ ਪ੍ਰੌਮਪਟ ਵਿੱਚ ਇੰਜੈਕਟ ਕਰਦਾ ਹੈ। ਅਸਲ ਬੈਕਐਂਡ ਦੀ ਪੁਸ਼ਟੀ `call_logs` / `proxy_logs` (`provider`, `model`, `target_format`) ਵਿੱਚ ਕਰੋ, ਮਾਡਲ ਨੂੰ ਇਹ ਪੁੱਛ ਕੇ ਨਹੀਂ ਕਿ ਉਹ ਕੌਣ ਹੈ।

## §6 ਸਮੱਸਿਆ-ਨਿਵਾਰਣ

### ਪੋਰਟ 443 ਟਕਰਾਅ

ਜੇ ਕੋਈ ਹੋਰ ਪ੍ਰਕਿਰਿਆ ਪਹਿਲਾਂ ਹੀ ਪੋਰਟ 443 (ਵੈੱਬ ਸਰਵਰ, VPN ਆਦਿ) 'ਤੇ ਸੁਣ ਰਹੀ ਹੈ:

```bash
lsof -i :443          # ਪ੍ਰਕਿਰਿਆ ਲੱਭੋ
sudo fuser -k 443/tcp  # ਜ਼ਬਰਦਸਤੀ ਬੰਦ ਕਰੋ (ਸਾਵਧਾਨੀ ਨਾਲ ਵਰਤੋ)
```

ਵਿਕਲਪਕ ਤੌਰ 'ਤੇ, AgentBridge ਸੈਟਿੰਗਾਂ ਵਿੱਚ ਇੱਕ ਗੈਰ-ਵਿਸ਼ੇਸ਼ ਅਧਿਕਾਰ ਵਾਲੀ ਪੋਰਟ ਸੰਰਚਿਤ ਕਰੋ ਅਤੇ `iptables` / `pf` ਰੀਡਾਇਰੈਕਟ ਨਿਯਮ ਸੈੱਟ ਅੱਪ ਕਰੋ।

### ਸਰਟੀਫਿਕੇਟ ਭਰੋਸੇਯੋਗ ਨਹੀਂ ਹੈ

ਜੇ AgentBridge ਸ਼ੁਰੂ ਕਰਨ ਤੋਂ ਬਾਅਦ IDE TLS ਤਰੁੱਟੀਆਂ ਦਿਖਾਉਂਦਾ ਹੈ:

1. ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਸਰਟੀਫਿਕੇਟ ਇੰਸਟਾਲ ਹੋਇਆ ਸੀ: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) ਜਾਂ `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. ਕੁਝ ਐਪਾਂ ਆਪਣਾ ਵੱਖਰਾ ਟਰੱਸਟ ਸਟੋਰ ਰੱਖਦੀਆਂ ਹਨ (Firefox, Linux ਉੱਤੇ Chrome)। "Trust Cert" ਮੁੜ ਚਲਾਓ ਅਤੇ NSS/Firefox-ਵਿਸ਼ੇਸ਼ ਸਰਟੀਫਿਕੇਟ ਸਟੋਰ ਦੀ ਜਾਂਚ ਕਰੋ।
3. ਭਰੋਸਾ ਦੇਣ ਤੋਂ ਬਾਅਦ IDE ਨੂੰ ਮੁੜ ਸ਼ੁਰੂ ਕਰੋ — ਚੱਲ ਰਹੇ TLS ਸੈਸ਼ਨ ਪੁਰਾਣੀ ਭਰੋਸਾ ਸਥਿਤੀ ਵਰਤਦੇ ਹਨ।

### ਭਰੋਸੇਯੋਗ CA ਦੇ ਬਾਵਜੂਦ IDE ਲੌਗ ਆਊਟ / "ਕਨੈਕਸ਼ਨ ਤਰੁੱਟੀ"

ਲੱਛਣ: DNS ਨੂੰ ਰੀਡਾਇਰੈਕਟ ਕਰਨ ਅਤੇ CA 'ਤੇ ਭਰੋਸਾ ਕਰਨ ਤੋਂ ਬਾਅਦ, Electron-ਆਧਾਰਿਤ IDE (ਜਿਵੇਂ Antigravity)
**ਲੌਗ ਆਊਟ** ਹਾਲਤ ਵਿੱਚ ਖੁੱਲ੍ਹਦਾ ਹੈ ਜਾਂ ਪ੍ਰਮਾਣੀਕਰਨ/ਕਨੈਕਸ਼ਨ ਤਰੁੱਟੀ ਦਿਖਾਉਂਦਾ ਹੈ, ਜਦਕਿ MITM ਲੌਗ
ਬੂਟਸਟਰੈਪ ਕਾਲਾਂ (`loadCodeAssist`, `fetchAvailableModels`, …) ਨੂੰ `200` ਵਾਪਸ ਕਰਦਿਆਂ ਦਿਖਾਉਂਦਾ ਹੈ।

ਕਾਰਨ: IDE ਦਾ **ਬੰਡਲ ਕੀਤਾ Node/Electron ਰਨਟਾਈਮ OS ਟਰੱਸਟ ਸਟੋਰ ਨੂੰ ਅਣਡਿੱਠਾ ਕਰਦਾ ਹੈ**। ਮੂਲ
ਬੈਕਐਂਡ (ਇੱਕ Go ਭਾਸ਼ਾ ਸਰਵਰ) OS CA 'ਤੇ ਭਰੋਸਾ ਕਰਦਾ ਹੈ ਅਤੇ ਪ੍ਰਮਾਣੀਕਰਨ ਕਰ ਲੈਂਦਾ ਹੈ, ਪਰ Electron ਫਰੰਟਐਂਡ
ਅਜਿਹਾ ਨਹੀਂ ਕਰਦਾ — ਇਸ ਲਈ UI ਸਮਝਦਾ ਹੈ ਕਿ ਇਹ ਆਫ਼ਲਾਈਨ ਹੈ।

ਹੱਲ (ਦੋਵੇਂ ਕਦਮ): `NODE_EXTRA_CA_CERTS=<ca.crt>` ਨੂੰ ਐਕਸਪੋਰਟ ਕਰੋ **ਅਤੇ IDE ਨੂੰ ਉਸੇ
ਸ਼ੈੱਲ ਤੋਂ ਮੁੜ ਚਲਾਓ**, ਡੈਸਕਟਾਪ ਆਈਕਨ ਤੋਂ ਨਹੀਂ। ਪਹਿਲਾਂ IDE ਨੂੰ ਪੂਰੀ ਤਰ੍ਹਾਂ ਬੰਦ ਕਰੋ — Electron ਦੇ ਸਿੰਗਲਟਨ ਲੌਕ ਕਾਰਨ
ਦੂਜੀ ਵਾਰ ਚਲਾਉਣ ਨਾਲ ਸਿਰਫ਼ ਮੌਜੂਦਾ ਪ੍ਰਕਿਰਿਆ ਫੋਕਸ ਹੁੰਦੀ ਹੈ ਅਤੇ ਨਵਾਂ ਵਾਤਾਵਰਣ ਅਣਡਿੱਠਾ ਕਰ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ। §3.2 ਵੇਖੋ।
ਇਹ ਇੱਕ ਖੁੱਲ੍ਹੀ ਅੱਪਸਟ੍ਰੀਮ ਰਿਪੋਰਟ ਨਾਲ ਮੇਲ ਖਾਂਦਾ ਹੈ, ਜਿਸ ਵਿੱਚ ਇੱਕ ਸਟੈਂਡਅਲੋਨ ਏਜੰਟ MITM ਰਾਹੀਂ ਕੰਮ ਕਰਦਾ ਹੈ ਪਰ IDE
ਰੂਪ ਉਸੇ ਸੈੱਟਅੱਪ ਅਧੀਨ ਅਸਫਲ ਹੁੰਦਾ ਹੈ।

### DNS ਪ੍ਰਸਾਰਿਤ ਨਹੀਂ ਹੋਇਆ

ਜਾਂਚ ਕਰੋ ਕਿ `/etc/hosts` ਅੱਪਡੇਟ ਹੋਇਆ ਸੀ:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

DNS ਕੈਸ਼ ਸਾਫ਼ ਕਰੋ:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### IDE ਦੀ ਪਛਾਣ ਨਹੀਂ ਹੋਈ

ਸਵੈਚਲਿਤ ਪਛਾਣ ਆਮ ਇੰਸਟਾਲੇਸ਼ਨ ਪਾਥ ਵਰਤਦੀ ਹੈ। ਜੇ ਪਛਾਣ ਅਸਫਲ ਹੁੰਦੀ ਹੈ ਪਰ IDE ਇੰਸਟਾਲ ਹੈ:

- ਜਾਂਚ ਕਰੋ ਕਿ ਕੀ IDE ਬਾਈਨਰੀ ਕਿਸੇ ਗੈਰ-ਮਿਆਰੀ ਸਥਾਨ 'ਤੇ ਹੈ
- Setup Wizard ਫਿਰ ਵੀ ਕੰਮ ਕਰਦਾ ਹੈ — ਪਛਾਣ ਅਸਫਲ ਹੋਣ ਦਾ ਸਿਰਫ਼ ਇਹ ਮਤਲਬ ਹੈ ਕਿ ਬੈਜ ਇੰਸਟਾਲੇਸ਼ਨ ਪਾਥ ਨਹੀਂ ਦਿਖਾਏਗਾ

### ਹੈਂਡਲਰ ਤਰੁੱਟੀਆਂ (ਅੱਪਸਟ੍ਰੀਮ ਫੈਚ ਅਸਫਲ)

ਜੇ AgentBridge ਇੰਟਰਸੈਪਟ ਕਰਦਾ ਹੈ ਪਰ ਸਾਰੀਆਂ ਬੇਨਤੀਆਂ ਅਸਫਲ ਹੁੰਦੀਆਂ ਹਨ:

1. ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ `/dashboard/providers` ਉੱਤੇ ਘੱਟੋ-ਘੱਟ ਇੱਕ ਪ੍ਰਦਾਤਾ ਕਨੈਕਟ ਹੈ
2. OmniRoute ਸਰਵਰ ਲੌਗ ਜਾਂਚੋ: `.env` ਵਿੱਚ `APP_LOG_LEVEL=debug`
3. ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ `OMNIROUTE_BASE_URL` ਸਹੀ ਰਾਊਟਰ ਐਂਡਪੌਇੰਟ ਵੱਲ ਇਸ਼ਾਰਾ ਕਰਦਾ ਹੈ (ਡਿਫੌਲਟ: `http://127.0.0.1:20128`)

## §8 ਰੋਡਮੈਪ

### Trae ਦੀ ਜਾਂਚ

Trae ਇੱਕ ਮੁਕਾਬਲਤਨ ਨਵਾਂ AI ਕੋਡਿੰਗ ਸਹਾਇਕ ਹੈ। ਹੈਂਡਲਰ ਲਾਗੂ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ:

1. VS Code / JetBrains ਮਾਰਕੀਟਪਲੇਸਾਂ ਵਿੱਚ ਜਾਂ ਇੱਕ ਸਟੈਂਡਅਲੋਨ ਐਪ ਵਜੋਂ ਬਾਈਨਰੀ/ਐਕਸਟੈਂਸ਼ਨ ਦੀ ਪਛਾਣ ਕਰੋ
2. API ਹੋਸਟਾਂ ਅਤੇ ਐਂਡਪੌਇੰਟ ਦੇ ਸਰੂਪਾਂ ਦਾ ਪਤਾ ਲਗਾਉਣ ਲਈ mitmproxy ਨਾਲ ਟ੍ਰੈਫਿਕ ਕੈਪਚਰ ਕਰੋ
3. ਪ੍ਰਮਾਣੀਕਰਨ ਵਿਧੀ ਨਿਰਧਾਰਤ ਕਰੋ
4. TOS ਅਤੇ API ਦੀ ਖੋਜਯੋਗਤਾ ਦੇ ਆਧਾਰ 'ਤੇ ਅੱਗੇ ਵਧਣ ਜਾਂ ਨਾ ਵਧਣ ਦਾ ਮੁਲਾਂਕਣ ਕਰੋ

ਜਾਂਚ ਪੂਰੀ ਹੋਣ ਤੱਕ, ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ Trae ਕਾਰਡ ਇੱਕ "ਜਾਂਚ ਅਧੀਨ" ਬੈਜ ਅਤੇ "ਵਿਹਾਰਯੋਗਤਾ ਦੀ ਰਿਪੋਰਟ ਕਰੋ" ਲਿੰਕ ਦਿਖਾਉਂਦਾ ਹੈ। `src/mitm/handlers/trae.ts` ਵਿੱਚ ਹੈਂਡਲਰ ਸਟਬ ਇੱਕ ਸੰਰਚਿਤ `ਹਾਲੇ ਲਾਗੂ ਨਹੀਂ ਕੀਤਾ ਗਿਆ` ਗਲਤੀ ਦਿੰਦਾ ਹੈ।

### ਬੈਕਲੌਗ ਏਜੰਟ (MITM ਲਾਜ਼ਮੀ — ਕਸਟਮ ਬੇਸ URL ਲਈ ਕੋਈ ਸਮਰਥਨ ਨਹੀਂ)
