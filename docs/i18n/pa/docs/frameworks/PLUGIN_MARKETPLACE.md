> **ਸੱਚਾਈ ਦਾ ਸਰੋਤ:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/`, ਅਤੇ
> `src/app/(dashboard)/dashboard/plugins/`
> **ਆਖਰੀ ਅੱਪਡੇਟ:** 2026-06-28 — v3.8.40

OmniRoute ਵਿੱਚ WordPress-ਸ਼ੈਲੀ ਦਾ ਪਲੱਗਇਨ ਸਿਸਟਮ ਸ਼ਾਮਲ ਹੈ। ਪਲੱਗਇਨ ਸਵੈ-ਨਿਰਭਰ
ਡਾਇਰੈਕਟਰੀਆਂ ਹਨ — ਹਰ ਇੱਕ ਵਿੱਚ ਇੱਕ `plugin.json` ਮੈਨੀਫੈਸਟ ਅਤੇ ਇੱਕ ਐਂਟਰੀ ਫ਼ਾਈਲ ਹੁੰਦੀ ਹੈ — ਜੋ
ਬੇਨਤੀ ਪਾਈਪਲਾਈਨ (`onRequest` / `onResponse` / `onError`) ਅਤੇ
ਲਾਈਫਸਾਈਕਲ ਇਵੈਂਟਾਂ (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`) ਨਾਲ ਜੁੜਦੀਆਂ ਹਨ।

**ਪਲੱਗਇਨ ਮਾਰਕੀਟਪਲੇਸ** ਉਸ ਸਿਸਟਮ ਦੇ ਉੱਪਰ ਬਣੀ ਖੋਜ ਪਰਤ ਹੈ। ਇਹ
ਇੰਸਟਾਲ ਕੀਤੇ ਜਾ ਸਕਣ ਵਾਲੇ ਪਲੱਗਇਨਾਂ ਦਾ ਬ੍ਰਾਊਜ਼ ਕਰਨ ਯੋਗ ਕੈਟਾਲਾਗ ਉਪਲਬਧ ਕਰਵਾਉਂਦੀ ਹੈ। ਮੂਲ ਰੂਪ ਵਿੱਚ ਕੈਟਾਲਾਗ ਇੱਕ
ਛੋਟੀ ਬਿਲਟ-ਇਨ ਸੀਡ ਰਜਿਸਟਰੀ ਹੁੰਦਾ ਹੈ; ਕੋਈ ਓਪਰੇਟਰ ਇਸਨੂੰ ਇੱਕ ਕਸਟਮ ਰਿਮੋਟ
ਰਜਿਸਟਰੀ URL ਵੱਲ ਨਿਰਦੇਸ਼ਿਤ ਕਰ ਸਕਦਾ ਹੈ, ਜਿਸ ਸਥਿਤੀ ਵਿੱਚ ਫੈਚ ਨੂੰ DNS-ਰਿਜ਼ਾਲਵਿੰਗ SSRF ਗਾਰਡ ਰਾਹੀਂ
ਸੁਰੱਖਿਅਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ ([ਸੁਰੱਖਿਆ](#security) ਵੇਖੋ)।

ਹਰ ਪਲੱਗਇਨ ਰੂਟ **ਕੇਵਲ ਲੂਪਬੈਕ** ਹੈ (ਟੀਅਰ 1 — `LOCAL_ONLY`): ਪਲੱਗਇਨ ਚਾਈਲਡ ਪ੍ਰੋਸੈਸਾਂ ਵਿੱਚ
ਕੋਡ ਲੋਡ ਅਤੇ ਚਲਾਉਂਦੇ ਹਨ, ਇਸ ਲਈ ਪ੍ਰਮਾਣੀਕਰਨ ਦੀ ਪਰਵਾਹ ਕੀਤੇ ਬਿਨਾਂ ਰੂਟਾਂ ਤੱਕ
ਕਿਸੇ ਗੈਰ-ਲੂਪਬੈਕ ਮੂਲ ਤੋਂ ਪਹੁੰਚ ਨਹੀਂ ਕੀਤੀ ਜਾ ਸਕਦੀ। ਵੇਖੋ
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md)।

## ਇਹ ਸਭ ਇਕੱਠੇ ਕਿਵੇਂ ਕੰਮ ਕਰਦਾ ਹੈ

```
ਡੈਸ਼ਬੋਰਡ (/dashboard/plugins)
  ├─ "ਇੰਸਟਾਲ ਕੀਤੇ" ਟੈਬ → GET /api/plugins            (listPlugins)
  │                       POST /api/plugins/scan      (pluginManager.scan)
  │                       POST /api/plugins/{name}/activate|deactivate
  │                       DELETE /api/plugins/{name}   (ਅਣਇੰਸਟਾਲ)
  └─ "ਮਾਰਕੀਟਪਲੇਸ" ਟੈਬ   → GET /api/plugins/marketplace
                            → listMarketplacePlugins()
                              ├─ ਕੋਈ ਕਸਟਮ URL ਨਹੀਂ → ਬਿਲਟ-ਇਨ SEED_REGISTRY
                              └─ ਕਸਟਮ URL → isSafeMarketplaceUrl() SSRF ਗਾਰਡ
                                            → safeOutboundFetch(guard:"public-only")
```

- **ਰਜਿਸਟਰੀ ਪਰਤ** — `src/lib/plugins/marketplace.ts`: ਕੈਟਾਲਾਗ ਨੂੰ ਸੂਚੀਬੱਧ ਕਰਦੀ / ਖੋਜਦੀ ਹੈ,
  ਅਤੇ ਕਿਸੇ ਵੀ ਅਸਫਲਤਾ ਉੱਤੇ ਸੀਡ ਰਜਿਸਟਰੀ ਵਰਤਦੀ ਹੈ।
- **ਲਾਈਫਸਾਈਕਲ ਪਰਤ** — `src/lib/plugins/manager.ts` (`pluginManager` ਸਿੰਗਲਟਨ):
  ਇੰਸਟਾਲ, ਅੱਪਗ੍ਰੇਡ, ਸਰਗਰਮ, ਨਿਸ਼ਕਿਰਿਆ, ਅਣਇੰਸਟਾਲ, ਸਕੈਨ, ਸਟਾਰਟਅੱਪ ਲੋਡ।
- **ਮੈਨੀਫੈਸਟ ਪਰਤ** — `src/lib/plugins/manifest.ts`: `plugin.json` ਲਈ Zod ਸਕੀਮਾ + ਮੂਲ ਮੁੱਲ।
- **ਸਕੈਨਰ** — `src/lib/plugins/scanner.ts`: ਪਲੱਗਇਨ ਡਾਇਰੈਕਟਰੀ ਦੇ ਅਧੀਨ ਡਿਸਕ ਉੱਤੇ
  ਪਲੱਗਇਨ ਲੱਭਦਾ ਹੈ।
- **ਲੋਡਰ** — `src/lib/plugins/loader.ts`: ਹਰ ਪਲੱਗਇਨ ਨੂੰ ਇੱਕ ਅਲੱਗ
  ਚਾਈਲਡ ਪ੍ਰੋਸੈਸ ਵਿੱਚ ਸ਼ੁਰੂ ਕਰਦਾ ਹੈ ਅਤੇ IPC ਰਾਹੀਂ ਹੁੱਕ ਕਾਲਾਂ ਦੀ ਦਲਾਲੀ ਕਰਦਾ ਹੈ।

## ਮਾਰਕੀਟਪਲੇਸ ਕੈਟਾਲਾਗ

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`)
`MarketplaceEntry` ਆਬਜੈਕਟਾਂ ਦੀ ਇੱਕ ਸੂਚੀ ਵਾਪਸ ਕਰਦਾ ਹੈ:

| ਫ਼ੀਲਡ         | ਕਿਸਮ     | ਨੋਟਸ                                              |
| ------------- | -------- | ------------------------------------------------- |
| `name`        | string   | kebab-case ਪਲੱਗਇਨ ਨਾਮ                             |
| `version`     | string   | semver                                            |
| `description` | string   | ਸੰਖੇਪ ਵੇਰਵਾ                                       |
| `author`      | string   | ਲੇਖਕ / ਸੰਗਠਨ                                      |
| `license`     | string   | SPDX-ਸ਼ੈਲੀ ਲਾਇਸੈਂਸ id                             |
| `downloadUrl` | string   | ਸਰੋਤ ਡਾਊਨਲੋਡ URL (ਖਾਲੀ ਹੋ ਸਕਦਾ ਹੈ)                |
| `repository`  | string?  | ਵਿਕਲਪਿਕ ਰਿਪੋਜ਼ਟਰੀ URL                             |
| `tags`        | string[] | ਖੋਜ/ਫਿਲਟਰ ਟੈਗ                                     |
| `downloads`   | number   | ਡਾਊਨਲੋਡ ਗਿਣਤੀ                                     |
| `rating`      | number   | 0–5                                               |
| `verified`    | boolean  | ਕੀ ਐਂਟਰੀ ਨੂੰ ਤਸਦੀਕਸ਼ੁਦਾ ਵਜੋਂ ਚਿੰਨ੍ਹਿਤ ਕੀਤਾ ਗਿਆ ਹੈ |
| `lastUpdated` | string   | ISO-ਵਰਗੀ ਮਿਤੀ ਸਟ੍ਰਿੰਗ                             |

ਜਦੋਂ ਕੋਈ ਕਸਟਮ ਰਜਿਸਟਰੀ URL ਕਨਫਿਗਰ ਨਹੀਂ ਕੀਤਾ ਜਾਂਦਾ, ਤਾਂ ਕੈਟਾਲਾਗ ਬਿਲਟ-ਇਨ
`SEED_REGISTRY` ਹੁੰਦਾ ਹੈ (ਵਰਤਮਾਨ ਵਿੱਚ `request-logger`, `rate-limiter`, `cost-tracker`, ਅਤੇ
`theme-manager`)। ਸੀਡ ਰਜਿਸਟਰੀ ਹਮੇਸ਼ਾ ਉਪਲਬਧ ਰਹਿੰਦੀ ਹੈ — ਜੇ ਕੋਈ ਕਨਫਿਗਰ ਕੀਤੀ ਰਿਮੋਟ
ਰਜਿਸਟਰੀ ਪਹੁੰਚ ਤੋਂ ਬਾਹਰ ਹੋਵੇ, ਗੈਰ-`200` ਸਥਿਤੀ ਵਾਪਸ ਕਰੇ, ਜਾਂ ਅਣਪਛਾਤੀ
ਬਾਡੀ ਵਾਪਸ ਕਰੇ, ਤਾਂ `listMarketplacePlugins()` ਇੱਕ ਚੇਤਾਵਨੀ ਲੌਗ ਕਰਦਾ ਹੈ ਅਤੇ ਸੀਡ ਸੂਚੀ
ਵਰਤਦਾ ਹੈ।

> ਨੋਟ: ਮਾਰਕੀਟਪਲੇਸ **ਕੈਟਾਲਾਗ** (ਬ੍ਰਾਊਜ਼/ਖੋਜ) ਸ਼ੁਰੂ ਤੋਂ ਅੰਤ ਤੱਕ ਜੁੜਿਆ ਹੋਇਆ ਹੈ, ਪਰ
> ਕੈਟਾਲਾਗ ਤੋਂ ਇੱਕ-ਕਲਿੱਕ ਮਾਰਕੀਟਪਲੇਸ **ਇੰਸਟਾਲ** ਅਜੇ ਲਾਗੂ ਨਹੀਂ ਕੀਤਾ ਗਿਆ — ਕਿਸੇ ਮਾਰਕੀਟਪਲੇਸ ਐਂਟਰੀ ਉੱਤੇ
> ਡੈਸ਼ਬੋਰਡ ਦਾ "ਇੰਸਟਾਲ" ਬਟਨ ਵਰਤਮਾਨ ਵਿੱਚ "ਜਲਦੀ ਆ ਰਿਹਾ ਹੈ" ਸੂਚਨਾ ਦਿਖਾਉਂਦਾ ਹੈ।
> ਅੱਜ ਇੰਸਟਾਲੇਸ਼ਨ ਲੋਕਲ-ਪਾਥ ਇੰਸਟਾਲ ਫ਼ਲੋ (`POST /api/plugins`) ਅਤੇ ਡਿਸਕ ਉੱਤੇ ਖੋਜ
> (`POST /api/plugins/scan`) ਰਾਹੀਂ ਹੁੰਦੀ ਹੈ।

## REST API

ਸਾਰੇ endpoints ਲਈ management auth (`requireManagementAuth`) ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ **ਅਤੇ** ਇਹ
ਕੇਵਲ loopback ਲਈ ਉਪਲਬਧ ਹਨ — `/api/plugins` ਅਤੇ `/api/plugins/` ਨੂੰ
`LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`) ਵਿੱਚ ਸੂਚੀਬੱਧ ਕੀਤਾ ਗਿਆ ਹੈ।

| Endpoint                         | ਵਿਧੀ   | ਵੇਰਵਾ                                                    |
| -------------------------------- | ------ | -------------------------------------------------------- |
| `/api/plugins`                   | GET    | ਇੰਸਟਾਲ ਕੀਤੇ plugins ਦੀ ਸੂਚੀ (ਵਿਕਲਪਿਕ `?status=` ਫਿਲਟਰ)   |
| `/api/plugins`                   | POST   | ਕਿਸੇ absolute local path ਤੋਂ plugin ਇੰਸਟਾਲ ਕਰੋ           |
| `/api/plugins/scan`              | POST   | plugin directory ਨੂੰ ਸਕੈਨ ਕਰਕੇ ਨਵੇਂ plugins ਰਜਿਸਟਰ ਕਰੋ   |
| `/api/plugins/marketplace`       | GET    | marketplace catalog entries ਦੀ ਸੂਚੀ ਦਿਓ                  |
| `/api/plugins/[name]`            | GET    | ਇੰਸਟਾਲ ਕੀਤੇ plugin ਦੇ ਵੇਰਵੇ ਪ੍ਰਾਪਤ ਕਰੋ                   |
| `/api/plugins/[name]`            | DELETE | plugin ਨੂੰ ਅਣਇੰਸਟਾਲ ਕਰੋ                                  |
| `/api/plugins/[name]/activate`   | POST   | ਸਰਗਰਮ ਕਰੋ (ਲੋਡ + hooks ਰਜਿਸਟਰ ਕਰੋ)                       |
| `/api/plugins/[name]/deactivate` | POST   | ਅਸਰਗਰਮ ਕਰੋ (`onDeactivate` ਚਲਾਓ, hooks ਨੂੰ ਅਣਰਜਿਸਟਰ ਕਰੋ) |
| `/api/plugins/[name]/config`     | GET    | plugin config + config schema ਪ੍ਰਾਪਤ ਕਰੋ                 |
| `/api/plugins/[name]/config`     | PUT    | plugin config ਅੱਪਡੇਟ ਕਰੋ (schema ਦੇ ਮੁਤਾਬਕ ਪ੍ਰਮਾਣਿਤ)     |

`GET /api/plugins` ਦਾ `status` ਫਿਲਟਰ
`installed` / `active` / `inactive` / `error` ਵਿੱਚੋਂ ਇੱਕ ਮੁੱਲ ਸਵੀਕਾਰ ਕਰਦਾ ਹੈ। ਇੱਕ ਅਵੈਧ ਮੁੱਲ `400` ਵਾਪਸ ਕਰਦਾ ਹੈ।

### ਇੰਸਟਾਲ ਕੀਤੇ plugins ਦੀ ਸੂਚੀ

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### ਕਿਸੇ local path ਤੋਂ ਇੰਸਟਾਲ ਕਰੋ

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` **absolute** ਹੋਣਾ ਚਾਹੀਦਾ ਹੈ ਅਤੇ ਇਸ ਵਿੱਚ `..` traversal segments ਜਾਂ
null bytes ਨਹੀਂ ਹੋ ਸਕਦੇ (Zod ਦੁਆਰਾ ਲਾਗੂ ਕੀਤਾ ਜਾਂਦਾ ਹੈ)। source directory ਵਿੱਚ ਇੱਕ ਵੈਧ
`plugin.json` ਹੋਣਾ ਚਾਹੀਦਾ ਹੈ (ਜਾਂ ਇਹ ਉਸਦੀ parent directory ਹੋਣੀ ਚਾਹੀਦੀ ਹੈ)। ਸਫਲਤਾ ਉੱਤੇ response ਇੰਸਟਾਲ ਕੀਤੇ
plugin row ਸਮੇਤ `201` ਹੁੰਦਾ ਹੈ।

### Marketplace ਬ੍ਰਾਊਜ਼ ਕਰੋ

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### Plugin config ਅੱਪਡੇਟ ਕਰੋ

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` ਦਿੱਤੇ ਗਏ ਹਰੇਕ ਮੁੱਲ ਨੂੰ plugin ਦੇ
`configSchema` (manifest ਵਿੱਚ ਘੋਸ਼ਿਤ) ਦੇ ਮੁਤਾਬਕ ਪ੍ਰਮਾਣਿਤ ਕਰਦਾ ਹੈ: `number` fields `min`/`max` ਦੀ ਪਾਲਣਾ ਕਰਦੇ ਹਨ,
ਅਤੇ `select` fields ਘੋਸ਼ਿਤ `enum` ਨਾਲ ਮੇਲ ਖਾਣੇ ਚਾਹੀਦੇ ਹਨ। schema ਵਿੱਚ ਮੌਜੂਦ ਨਾ ਹੋਣ ਵਾਲੀਆਂ keys
ਨੂੰ ਲੰਘਣ ਦੀ ਆਗਿਆ ਹੁੰਦੀ ਹੈ।

## ਸੰਰਚਨਾ

### Plugin directory

Plugins OmniRoute data directory ਦੇ ਅਧੀਨ ਰਹਿੰਦੇ ਹਨ:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (ਜਾਂ ਉਹ ਜੋ manifest.main ਦਰਸਾਉਂਦਾ ਹੈ)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) ਉਸ directory ਨੂੰ
ਤਿੰਨ ਪੜਾਵਾਂ ਵਿੱਚ resolve ਕਰਦਾ ਹੈ:

1. **`OMNIROUTE_PLUGINS_DIR`**, ਜਦੋਂ ਸੈੱਟ ਹੋਵੇ — `HOME` ਦਾ ਮੁੱਲ ਭਾਵੇਂ ਜੋ ਵੀ ਹੋਵੇ, ਇਸਨੂੰ ਜਿਵੇਂ ਦਾ ਤਿਵੇਂ ਵਰਤਿਆ ਜਾਂਦਾ ਹੈ। ਇਹ
   Docker/K8s ਲਈ ਸਪਸ਼ਟ ਨਿਯੰਤਰਣ ਹੈ, ਜਿੱਥੇ plugin tree ਨੂੰ ਅਜਿਹੇ path ਉੱਤੇ bind-mount ਕੀਤਾ ਜਾਂਦਾ ਹੈ
   ਜਿਸਦਾ ਆਮ ਤੌਰ ਉੱਤੇ container ਦੀ home directory ਨਾਲ ਕੋਈ ਸੰਬੰਧ ਨਹੀਂ ਹੁੰਦਾ (#11827)।
2. `<home>/.omniroute/plugins`, ਜਿੱਥੇ `<home>` `HOME` / `USERPROFILE`
   environment variables ਤੋਂ ਆਉਂਦਾ ਹੈ।
3. `/tmp/.omniroute/plugins`, ਜਦੋਂ process ਕੋਈ home ਬਿਲਕੁਲ ਵੀ export ਨਹੀਂ ਕਰਦਾ।

resolve ਕੀਤੀ directory ਨੂੰ startup ਵੇਲੇ ਇੱਕ ਵਾਰ `scanner.dir_resolved` ਵਜੋਂ log ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਜਿਸ ਵਿੱਚ
ਵਰਤੇ ਗਏ input (`OMNIROUTE_PLUGINS_DIR`, `home`, ਜਾਂ `no-home-fallback`) ਦਾ ਨਾਮ ਹੁੰਦਾ ਹੈ — ਇਸ ਤਰ੍ਹਾਂ ਕੋਈ image
ਜੋ ਬਿਨਾਂ ਦੱਸੇ ਪੜਾਅ 3 ਉੱਤੇ ਪਹੁੰਚਦੀ ਹੈ, ਸਿਰਫ਼ ਖਾਲੀ plugin ਸੂਚੀ report ਕਰਨ ਦੀ ਬਜਾਏ ਇਸ ਬਾਰੇ ਦੱਸਦੀ ਹੈ।
`POST /api/plugins/scan` ਉੱਥੇ ਮੌਜੂਦ ਕਿਸੇ ਵੀ ਅਜਿਹੀ subdirectory ਨੂੰ ਲੱਭ ਕੇ ਰਜਿਸਟਰ ਕਰਦਾ ਹੈ ਜਿਸ ਵਿੱਚ ਇੱਕ ਵੈਧ
`plugin.json` ਹੋਵੇ; ਇਹੋ directory ਉਹ root ਵੀ ਹੈ ਜਿਸ ਵਿੱਚ
`pluginManager.install()` plugins ਨੂੰ copy ਕਰਦਾ ਹੈ, ਇਸ ਲਈ override discovery ਅਤੇ
installation ਦੋਵਾਂ ਨੂੰ ਇਕੱਠੇ ਤਬਦੀਲ ਕਰਦਾ ਹੈ।

> **`OMNIROUTE_PLUGINS_DIR`, `OMNIROUTE_PLUGIN_PATH` ਨਹੀਂ ਹੈ।** ਦੂਜੇ ਵਾਲੇ ਨੂੰ ਕੇਵਲ
> CLI command-plugin loader (`bin/cli/plugins.mjs`) ਵੱਲੋਂ `omniroute-cmd-*` npm
> packages ਲੱਭਣ ਲਈ ਪੜ੍ਹਿਆ ਜਾਂਦਾ ਹੈ, ਜੋ `omniroute` subcommands ਜੋੜਦੇ ਹਨ — ਇੱਥੇ ਵਰਣਿਤ runtime scanner ਉੱਤੇ
> ਇਸਦਾ ਕੋਈ ਪ੍ਰਭਾਵ ਨਹੀਂ ਹੈ। ਉਸ ਪੱਖ ਲਈ [PLUGINS.md](./PLUGINS.md) ਵੇਖੋ।

### ਕਸਟਮ marketplace registry URL

marketplace catalog ਦਾ source `pluginMarketplaceUrl` setting ਤੋਂ ਪੜ੍ਹਿਆ ਜਾਂਦਾ ਹੈ
(`src/lib/plugins/marketplace.ts`, `settings.pluginMarketplaceUrl` ਨੂੰ ਪੜ੍ਹਦਾ ਹੈ)। ਜਦੋਂ
ਇਸਨੂੰ ਇੱਕ `http(s)` URL ਉੱਤੇ ਸੈੱਟ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਤਾਂ `listMarketplacePlugins()` ਉਸ URL ਨੂੰ fetch ਕਰਦਾ ਹੈ ਅਤੇ
ਜਾਂ ਤਾਂ entries ਦੀ top-level JSON array ਜਾਂ `plugins` array ਵਾਲਾ object ਸਵੀਕਾਰ ਕਰਦਾ ਹੈ;
string `name` ਤੋਂ ਬਿਨਾਂ entries ਨੂੰ filter ਕਰ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ। ਜਦੋਂ ਇਹ ਸੈੱਟ ਨਾ ਹੋਵੇ (ਜਾਂ ਜਦੋਂ fetch
SSRF guard ਵਿੱਚ ਅਸਫਲ ਹੋ ਜਾਵੇ / ਖਰਾਬ response ਵਾਪਸ ਕਰੇ), ਤਾਂ built-in seed registry
ਵਰਤੀ ਜਾਂਦੀ ਹੈ।

dashboard ਦੀ "Marketplace" tab ਇਸ URL ਲਈ ਇੱਕ field ਦਿਖਾਉਂਦੀ ਹੈ (ਇਸਨੂੰ
`GET /api/settings` ਤੋਂ ਵਾਪਸ ਪੜ੍ਹਿਆ ਜਾਂਦਾ ਹੈ)।

> ਲਾਗੂਕਰਨ ਨੋਟ: dashboard ਦੀ "ਸੰਭਾਲੋ" ਕਾਰਵਾਈ
> `pluginMarketplaceUrl` ਨੂੰ `PATCH /api/settings` ਵੱਲ ਭੇਜਦੀ ਹੈ। ਇਹ ਲਿਖੇ ਜਾਣ ਵੇਲੇ ਇਹ
> key `updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`) ਵਿੱਚ ਘੋਸ਼ਿਤ ਨਹੀਂ ਹੈ, ਇਸ ਲਈ ਇਸ ਉੱਤੇ ਨਿਰਭਰ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਆਪਣੀ
> release ਵਿੱਚ persistence ਦੀ ਪੁਸ਼ਟੀ ਕਰੋ — **read** path (`getSettings()` →
> `listMarketplacePlugins()`) settings store ਵਿੱਚ key ਮੌਜੂਦ ਹੋਣ ਤੋਂ ਬਾਅਦ ਇਸਦੀ ਪਾਲਣਾ ਕਰਦਾ ਹੈ।

## ਸੁਰੱਖਿਆ

### ਰੂਟ ਟੀਅਰ — ਸਿਰਫ਼ ਲੂਪਬੈਕ

ਪਲੱਗਇਨ ਬਣਾਈਆਂ ਗਈਆਂ ਚਾਈਲਡ ਪ੍ਰੋਸੈੱਸਾਂ ਵਿੱਚ ਕੋਡ ਚਲਾਉਂਦੇ ਹਨ, ਇਸ ਲਈ ਪੂਰੀ `/api/plugins`
ਸਤਹ ਨੂੰ `LOCAL_ONLY` (ਟੀਅਰ 1) ਵਜੋਂ ਵਰਗੀਕ੍ਰਿਤ ਕੀਤਾ ਗਿਆ ਹੈ। ਲੂਪਬੈਕ ਲਾਗੂਕਰਨ ਕਿਸੇ ਵੀ
ਪ੍ਰਮਾਣੀਕਰਨ ਜਾਂਚ ਤੋਂ **ਪਹਿਲਾਂ** ਬਿਨਾਂ ਕਿਸੇ ਸ਼ਰਤ ਦੇ ਚਲਦਾ ਹੈ, ਇਸ ਲਈ ਟਨਲ ਰਾਹੀਂ ਬਾਕਸ ਤੱਕ
ਪਹੁੰਚਣ ਵਾਲਾ ਲੀਕ ਹੋਇਆ ਮੈਨੇਜਮੈਂਟ ਟੋਕਨ ਵੀ ਕਿਸੇ ਪਲੱਗਇਨ ਨੂੰ ਇੰਸਟਾਲ, ਸਰਗਰਮ ਜਾਂ ਅਣਇੰਸਟਾਲ
ਨਹੀਂ ਕਰ ਸਕਦਾ। [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md)
ਅਤੇ ਸਖ਼ਤ ਨਿਯਮ #15 / #17 ਵੇਖੋ।

### ਮਾਰਕੀਟਪਲੇਸ ਰਜਿਸਟਰੀ SSRF ਗਾਰਡ

ਇੱਕ ਕਸਟਮ ਰਜਿਸਟਰੀ URL ਹਮਲਾਵਰ ਦੁਆਰਾ ਪ੍ਰਭਾਵਿਤ ਕੀਤੀ ਜਾ ਸਕਣ ਵਾਲੀ ਸੰਰਚਨਾ ਹੈ, ਇਸ ਲਈ
ਇਸ ਨੂੰ ਪ੍ਰਾਪਤ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ `listMarketplacePlugins()` ਇਸ ਨੂੰ ਦੋ ਪਰਤਾਂ ਵਿੱਚੋਂ
ਲੰਘਾਉਂਦਾ ਹੈ:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - `http:` / `https:` ਤੋਂ ਇਲਾਵਾ ਹਰ ਚੀਜ਼ ਨੂੰ ਅਸਵੀਕਾਰ ਕਰਦਾ ਹੈ।
   - ਕੈਨੋਨੀਕਲ `isPrivateHost`
     (`src/shared/network/outboundUrlGuard.ts`) ਰਾਹੀਂ ਲਿਟਰਲ ਪ੍ਰਾਈਵੇਟ/ਲੂਪਬੈਕ/ਲਿੰਕ-ਲੋਕਲ/ULA
     ਹੋਸਟਾਂ (IPv4 **ਅਤੇ** IPv6, IPv4-ਮੈਪ ਕੀਤੇ ਪਤਿਆਂ ਸਮੇਤ) ਨੂੰ ਅਸਵੀਕਾਰ ਕਰਦਾ ਹੈ।
   - **ਦੋਵੇਂ** `A` ਅਤੇ `AAAA` ਰਿਕਾਰਡ ਰਿਜ਼ਾਲਵ ਕਰਦਾ ਹੈ ਅਤੇ ਜੇ ਰਿਜ਼ਾਲਵ ਹੋਇਆ **ਕੋਈ ਵੀ**
     ਪਤਾ ਪ੍ਰਾਈਵੇਟ ਹੋਵੇ ਤਾਂ ਅਸਵੀਕਾਰ ਕਰਦਾ ਹੈ — ਇਸ ਤਰ੍ਹਾਂ ਪਬਲਿਕ-ਹੋਸਟਨੇਮ → ਪ੍ਰਾਈਵੇਟ-IP
     ਬਾਈਪਾਸ ਬੰਦ ਹੋ ਜਾਂਦਾ ਹੈ।
   - **ਅਸਫਲ ਹੋਣ ’ਤੇ ਬੰਦ ਰਹਿੰਦਾ ਹੈ**: DNS ਰਿਜ਼ੋਲਿਊਸ਼ਨ ਦੀ ਅਸਫਲਤਾ URL ਨੂੰ ਅਸਵੀਕਾਰ
     ਕਰ ਦਿੰਦੀ ਹੈ।
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`**
   (`src/shared/network/safeOutboundFetch.ts`): ਫੈਚ ਸਮੇਂ ਸਿਰਫ਼-ਪਬਲਿਕ URL ਗਾਰਡ ਨੂੰ
   ਮੁੜ ਲਾਗੂ ਕਰਦਾ ਹੈ ਅਤੇ **ਰੀਡਾਇਰੈਕਟਾਂ ਨੂੰ ਬਲੌਕ ਕਰਦਾ ਹੈ** (ਕੋਈ ਪਬਲਿਕ → ਪ੍ਰਾਈਵੇਟ
   `30x` ਪਿਵਟ ਨਹੀਂ)।

ਕਿਸੇ ਵੀ ਪਰਤ ਵਿੱਚ ਅਸਫਲ ਹੋਣ ਵਾਲਾ URL ਬੇਨਤੀ ਨੂੰ ਰੱਦ ਨਹੀਂ ਕਰਦਾ — ਮਾਰਕੀਟਪਲੇਸ ਚੁੱਪਚਾਪ
ਬਿਲਟ-ਇਨ ਸੀਡ ਰਜਿਸਟਰੀ ਵੱਲ ਮੁੜ ਜਾਂਦਾ ਹੈ ਅਤੇ ਇੱਕ ਚੇਤਾਵਨੀ ਲੌਗ ਕਰਦਾ ਹੈ।

> ਇਸ ਗਾਰਡ ਨੂੰ PR #3774 ਵਿੱਚ ਖ਼ਾਸ ਤੌਰ ’ਤੇ A + AAAA ਰਿਜ਼ਾਲਵ ਕਰਨ ਅਤੇ ਸਿਰਫ਼-IPv4
> ਜਾਂਚ ਦੀ ਬਜਾਏ ਕੈਨੋਨੀਕਲ `isPrivateHost` ਵਰਤਣ ਲਈ ਮਜ਼ਬੂਤ ਕੀਤਾ ਗਿਆ ਸੀ।

### ਪਲੱਗਇਨ ਐਗਜ਼ੀਕਿਊਸ਼ਨ ਆਈਸੋਲੇਸ਼ਨ

- **ਪ੍ਰੋਸੈੱਸ ਆਈਸੋਲੇਸ਼ਨ** — `loadPlugin()` (`src/lib/plugins/loader.ts`) ਹਰ
  ਪਲੱਗਇਨ ਨੂੰ ਇੱਕ ਵੱਖਰੀ Node.js ਚਾਈਲਡ ਪ੍ਰੋਸੈੱਸ ਵਿੱਚ ਸਪੌਨ ਕਰਦਾ ਹੈ ਅਤੇ IPC ਰਾਹੀਂ
  ਸੰਚਾਰ ਕਰਦਾ ਹੈ। ਹੁੱਕ ਕਾਲਾਂ ਲਈ `SIGTERM` → `SIGKILL` ਐਸਕਲੇਸ਼ਨ ਸਮੇਤ ਟਾਈਮਆਉਟ ਹੈ।
- **Env ਅਲਾਊਲਿਸਟ** — ਚਾਈਲਡ ਨੂੰ ਸਿਰਫ਼ ਅਲਾਊਲਿਸਟ ਕੀਤੀਆਂ ਇਨਵਾਇਰਨਮੈਂਟ ਵੇਰੀਏਬਲਾਂ ਦਾ
  ਸੈੱਟ ਮਿਲਦਾ ਹੈ; ਵੱਡਾ ਸੈੱਟ ਕੇਵਲ ਉਦੋਂ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ ਜਦੋਂ ਮੈਨੀਫੈਸਟ `env`
  ਅਨੁਮਤੀ ਦੀ ਬੇਨਤੀ ਕਰਦਾ ਹੈ।
- **ਪਾਥ ਕੰਟੇਨਮੈਂਟ** — ਇੰਸਟਾਲ/ਅੱਪਗ੍ਰੇਡ/ਅਣਇੰਸਟਾਲ ਇਹ ਯਕੀਨੀ ਬਣਾਉਂਦੇ ਹਨ ਕਿ ਕਿਸੇ ਵੀ
  ਕਾਪੀ ਜਾਂ ਰਿਕਰਸਿਵ ਡਿਲੀਟ ਤੋਂ ਪਹਿਲਾਂ ਪਲੱਗਇਨ ਡਾਇਰੈਕਟਰੀ ਅਤੇ `manifest.main` ਮੈਨੇਜਡ
  ਪਲੱਗਇਨ ਰੂਟ ਦੇ **ਅੰਦਰ** ਰਿਜ਼ਾਲਵ ਹੁੰਦੇ ਹਨ (ਛੇੜਛਾੜ ਕੀਤੇ DB ਪਾਥਾਂ ਅਤੇ
  `manifest.main` ਵਿੱਚ `../` ਟ੍ਰੈਵਰਸਲ ਤੋਂ ਸੁਰੱਖਿਆ)। ਸਰਗਰਮੀ `realpath` ਰਾਹੀਂ
  ਸਿੰਬੋਲਿਕ ਲਿੰਕਾਂ ਨੂੰ ਰਿਜ਼ਾਲਵ ਕਰਦੀ ਹੈ ਅਤੇ ਪਲੱਗਇਨ ਡਾਇਰੈਕਟਰੀ ਤੋਂ ਬਾਹਰ ਜਾਣ ਵਾਲੇ
  ਐਂਟਰੀ ਪੁਆਇੰਟ ਨੂੰ ਲੋਡ ਕਰਨ ਤੋਂ ਇਨਕਾਰ ਕਰਦੀ ਹੈ।
- **ਵਿਕਲਪਿਕ ਇੰਟੀਗ੍ਰਿਟੀ ਪਿਨ** — ਮੈਨੀਫੈਸਟ ਇੱਕ `integrity`
  (`sha256-<base64>`, SRI ਫਾਰਮੈਟ) ਫੀਲਡ ਘੋਸ਼ਿਤ ਕਰ ਸਕਦਾ ਹੈ। ਇਸ ਦੇ ਮੌਜੂਦ ਹੋਣ ’ਤੇ,
  ਲੋਡਰ ਲੋਡ ਸਮੇਂ ਐਂਟਰੀ ਫਾਈਲ ਹੈਸ਼ ਦੀ ਪੁਸ਼ਟੀ ਕਰਦਾ ਹੈ ਅਤੇ ਮੇਲ ਨਾ ਹੋਣ ’ਤੇ ਸਰਗਰਮ
  ਕਰਨ ਤੋਂ ਇਨਕਾਰ ਕਰਦਾ ਹੈ। ਇਹ ਆਪਟ-ਇਨ ਛੇੜਛਾੜ-ਖੋਜ ਹੈ, ਕੋਈ **ਸੁਰੱਖਿਆ ਸੀਮਾ ਨਹੀਂ** —
  ਸਿਰਫ਼-ਲੂਪਬੈਕ ਰੂਟਿੰਗ ਅਤੇ ਅਨੁਮਤੀ ਮਾਡਲ ਹੀ ਅਸਲ ਸੀਮਾਵਾਂ ਹਨ।

## ਮੈਨੀਫੈਸਟ (`plugin.json`)

`PluginManifestSchema` (`src/lib/plugins/manifest.ts`) ਦੁਆਰਾ ਪ੍ਰਮਾਣਿਤ:

| ਫੀਲਡ               | ਕਿਸਮ      | ਨੋਟਸ                                                        |
| ------------------ | --------- | ----------------------------------------------------------- |
| `name`             | string    | ਲਾਜ਼ਮੀ; kebab-case (`^[a-z0-9-]+$`), 1–100 ਅੱਖਰ             |
| `version`          | string    | ਲਾਜ਼ਮੀ; semver (`MAJOR.MINOR.PATCH`)                        |
| `description`      | string?   | ≤ 500 ਅੱਖਰ                                                  |
| `author`           | string?   | ≤ 200 ਅੱਖਰ                                                  |
| `license`          | string?   | ਮੂਲ ਮੁੱਲ `MIT` ਹੈ                                           |
| `main`             | string?   | ਐਂਟਰੀ ਫਾਈਲ; ਮੂਲ ਮੁੱਲ `index.js` ਹੈ                          |
| `source`           | enum?     | `local` \| `marketplace` (ਮੂਲ ਮੁੱਲ `local`)                 |
| `tags`             | string[]? | ਖੋਜ ਟੈਗ                                                     |
| `requires`         | object?   | `{ omniroute?, permissions[] }`                             |
| `hooks`            | object?   | ਬੂਲੀਅਨ ਜੋ ਘੋਸ਼ਿਤ ਕਰਦੇ ਹਨ ਕਿ ਪਲੱਗਇਨ ਕਿਹੜੇ ਹੁੱਕ ਲਾਗੂ ਕਰਦਾ ਹੈ  |
| `skills`           | object[]? | ਵਿਕਲਪਿਕ ਸਕਿੱਲ ਪਰਿਭਾਸ਼ਾਵਾਂ                                   |
| `enabledByDefault` | boolean?  | ਇੰਸਟਾਲੇਸ਼ਨ ’ਤੇ ਆਪਣੇ-ਆਪ ਸਰਗਰਮ ਕਰੋ                            |
| `configSchema`     | object?   | ਸੰਰਚਨਾ ਫੀਲਡਾਂ ਦਾ ਮੈਪ (`string`/`number`/`boolean`/`select`) |
| `integrity`        | string?   | ਵਿਕਲਪਿਕ `sha256-<base64>` ਐਂਟਰੀ-ਫਾਈਲ ਪਿਨ                    |

ਅਨੁਮਤੀਆਂ enum
`network` / `file-read` / `file-write` / `env` / `exec` ਵਿੱਚੋਂ ਲਈਆਂ ਜਾਂਦੀਆਂ ਹਨ।

## ਜੀਵਨ-ਚੱਕਰ ਪ੍ਰਵਾਹ

```
ਇੰਸਟਾਲ (POST /api/plugins, ਪਾਥ)
  → ਮੈਨਿਫੈਸਟ ਸਕੈਨ/ਪ੍ਰਮਾਣਿਤ ਕਰੋ → ਸਟੇਜਿੰਗ ਵਿੱਚ ਕਾਪੀ ਕਰੋ → ਯਕੀਨੀ ਬਣਾਓ ਕਿ main ਡਾਇਰੈਕਟਰੀ ਦੇ ਅੰਦਰ ਹੈ
  → ~/.omniroute/plugins/<name> ਵਿੱਚ ਐਟਾਮਿਕ ਰੀਨੇਮ ਕਰੋ → DB ਕਤਾਰ ਸ਼ਾਮਲ ਕਰੋ
  → onInstall ਚਲਾਓ → ਜੇ enabledByDefault ਹੈ: ਐਕਟੀਵੇਟ ਕਰੋ

ਐਕਟੀਵੇਟ (POST /api/plugins/{name}/activate)
  → realpath ਕੰਟੇਨਮੈਂਟ ਜਾਂਚ → loadPlugin() (ਚਾਇਲਡ ਪ੍ਰੋਸੈੱਸ ਸ਼ੁਰੂ ਕਰੋ)
  → ਘੋਸ਼ਿਤ ਹੁੱਕ ਰਜਿਸਟਰ ਕਰੋ → status = "active" → onActivate ਚਲਾਓ

ਡੀਐਕਟੀਵੇਟ (POST /api/plugins/{name}/deactivate)
  → onDeactivate ਚਲਾਓ (ਅਨਰਜਿਸਟਰ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ) → ਹੁੱਕ ਅਨਰਜਿਸਟਰ ਕਰੋ
  → ਚਾਇਲਡ ਪ੍ਰੋਸੈੱਸ ਸਮਾਪਤ ਕਰੋ → status = "inactive"

ਅਨਇੰਸਟਾਲ (DELETE /api/plugins/{name})
  → ਜੇ ਐਕਟਿਵ ਹੈ ਤਾਂ ਡੀਐਕਟੀਵੇਟ ਕਰੋ → onUninstall ਚਲਾਓ
  → ਕੰਟੇਨਮੈਂਟ-ਜਾਂਚ ਨਾਲ ਪਲੱਗਇਨ ਡਾਇਰੈਕਟਰੀ ਨੂੰ ਰਿਕਰਸਿਵ ਤੌਰ 'ਤੇ ਮਿਟਾਓ → DB ਕਤਾਰ ਮਿਟਾਓ
```

ਉਸ ਡਾਇਰੈਕਟਰੀ ਉੱਤੇ `install` ਨੂੰ ਮੁੜ ਚਲਾਉਣਾ, ਜਿਸ ਦਾ ਮੈਨਿਫੈਸਟ ਵਰਜਨ ਇੰਸਟਾਲ ਕੀਤੇ ਵਰਜਨ ਨਾਲੋਂ **ਸਖ਼ਤੀ ਨਾਲ
ਨਵਾਂ** ਹੈ, ਆਪਣੇ ਆਪ ਅੱਪਗ੍ਰੇਡ ਕਰਦਾ ਹੈ (ਸਾਫ਼ ਮੁੜ-ਇੰਸਟਾਲੇਸ਼ਨ; ਸੰਰਚਨਾ ਡਿਫਾਲਟ ਮੁੱਲਾਂ 'ਤੇ ਰੀਸੈੱਟ
ਹੁੰਦੀ ਹੈ)। ਸਮਾਨ ਜਾਂ ਪੁਰਾਣਾ ਵਰਜਨ ਅਸਵੀਕਾਰ ਕਰ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ।

## ਡੈਸ਼ਬੋਰਡ

`/dashboard/plugins` ਉੱਤੇ ਡੈਸ਼ਬੋਰਡ ਪੰਨਾ
(`src/app/(dashboard)/dashboard/plugins/page.tsx`) ਦੋ ਟੈਬਾਂ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ:

- **ਇੰਸਟਾਲ ਕੀਤੇ** — ਇੰਸਟਾਲ ਕੀਤੇ ਪਲੱਗਇਨਾਂ ਨੂੰ ਉਨ੍ਹਾਂ ਦੇ ਘੋਸ਼ਿਤ ਹੁੱਕਾਂ, ਇੱਕ
  ਐਕਟੀਵੇਟ/ਡੀਐਕਟੀਵੇਟ ਟੌਗਲ, ਇੱਕ ਅਨਇੰਸਟਾਲ ਬਟਨ ਅਤੇ "ਪਲੱਗਇਨਾਂ ਲਈ ਸਕੈਨ ਕਰੋ"
  ਕਾਰਵਾਈ (`POST /api/plugins/scan`) ਸਮੇਤ ਸੂਚੀਬੱਧ ਕਰਦਾ ਹੈ।
- **ਮਾਰਕੀਟਪਲੇਸ** — ਕਸਟਮ ਰਜਿਸਟਰੀ URL ਸੈੱਟ ਕਰਨ ਲਈ ਇੱਕ
  ਫ਼ੀਲਡ ਦੇ ਨਾਲ `GET /api/plugins/marketplace` ਤੋਂ ਕੈਟਾਲਾਗ ਦਿਖਾਉਂਦਾ ਹੈ।

ਹਰੇਕ ਪਲੱਗਇਨ ਲਈ ਸੰਰਚਨਾ ਪੰਨਾ `/dashboard/plugins/[name]/config` ਉੱਤੇ ਮੌਜੂਦ ਹੈ
(`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`)।
