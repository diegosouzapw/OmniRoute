## ਇੰਸਟਾਲੇਸ਼ਨ

OmniRoute MCP ਅੰਦਰੂਨੀ ਤੌਰ 'ਤੇ ਸ਼ਾਮਲ ਹੈ। ਇਸਨੂੰ ਇਸ ਤਰ੍ਹਾਂ ਸ਼ੁਰੂ ਕਰੋ:

```bash
omniroute --mcp
```

ਜਾਂ open-sse ਟ੍ਰਾਂਸਪੋਰਟ ਰਾਹੀਂ:

```bash
# HTTP ਸਟ੍ਰੀਮਯੋਗ ਟ੍ਰਾਂਸਪੋਰਟ (ਪੋਰਟ 20130)
omniroute --dev  # MCP /mcp ਐਂਡਪੌਇੰਟ 'ਤੇ ਆਪਣੇ ਆਪ ਸ਼ੁਰੂ ਹੁੰਦਾ ਹੈ
```

HTTP ਟ੍ਰਾਂਸਪੋਰਟ (`sse` / `streamable-http`, ਜੋ ਡੈਸ਼ਬੋਰਡ ਸਰਵਰ ਦੁਆਰਾ ਉਸੇ ਪ੍ਰੋਸੈੱਸ ਵਿੱਚ ਸਰਵ ਕੀਤੇ ਜਾਂਦੇ ਹਨ)
ਮੂਲ ਰੂਪ ਵਿੱਚ ਬੰਦ ਹੁੰਦੇ ਹਨ ਅਤੇ ਪਹਿਲਾਂ ਸਿਰਫ਼ `/dashboard/mcp` ਪੰਨੇ ਤੋਂ ਹੀ ਚਾਲੂ ਜਾਂ ਬੰਦ ਕੀਤੇ ਜਾ ਸਕਦੇ ਸਨ। v3.8.51
ਤੋਂ CLI ਵਿੱਚ ਵੀ ਬਰਾਬਰ ਦੀ ਕਾਰਜਸ਼ੀਲਤਾ ਹੈ:

```bash
omniroute mcp status                                  # ਸਮਰੱਥ/ਔਨਲਾਈਨ, ਟ੍ਰਾਂਸਪੋਰਟ, ਟੂਲਾਂ ਦੀ ਗਿਣਤੀ
omniroute mcp enable [--transport stdio|sse|streamable-http]
omniroute mcp disable
omniroute mcp restart                                 # ਸਰਗਰਮ sse/streamable-http ਸੈਸ਼ਨਾਂ ਨੂੰ ਰੀਸੈੱਟ ਕਰਦਾ ਹੈ
```

`mcp enable`/`mcp disable`, `/api/settings` ਰਾਹੀਂ ਉਸੇ `mcpEnabled` (ਅਤੇ ਵਿਕਲਪਿਕ ਤੌਰ 'ਤੇ `mcpTransport`) ਸੈਟਿੰਗ ਨੂੰ
PATCH ਕਰਦੇ ਹਨ ਜਿਸਨੂੰ ਡੈਸ਼ਬੋਰਡ ਚਾਲੂ ਜਾਂ ਬੰਦ ਕਰਦਾ ਹੈ। `mcp restart`, `POST /api/mcp/restart` ਨੂੰ ਕਾਲ ਕਰਦਾ ਹੈ: ਇਹ
ਸਰਗਰਮ `sse`/`streamable-http` ਸੈਸ਼ਨਾਂ ਨੂੰ ਬੰਦ ਕਰ ਦਿੰਦਾ ਹੈ ਤਾਂ ਜੋ ਅਗਲੀ ਬੇਨਤੀ ਸਾਫ਼ ਢੰਗ ਨਾਲ ਮੁੜ ਸ਼ੁਰੂ ਹੋਵੇ, MCP ਅਸਮਰੱਥ ਹੋਣ 'ਤੇ
`409`, ਅਤੇ `stdio` ਟ੍ਰਾਂਸਪੋਰਟ ਲਈ `501` ਵਾਪਸ ਕਰਦਾ ਹੈ (stdio ਕਲਾਇੰਟ ਆਪਣੇ ਸਬਪ੍ਰੋਸੈੱਸ ਦੇ ਖੁਦ ਮਾਲਕ ਹੁੰਦੇ ਹਨ —
ਮੁੜ ਸ਼ੁਰੂ ਕਰਨ ਲਈ ਉਸੇ ਪ੍ਰੋਸੈੱਸ ਵਿੱਚ ਕੋਈ ਹੈਂਡਲ ਉਪਲਬਧ ਨਹੀਂ ਹੁੰਦਾ)।

## ਟ੍ਰਾਂਸਪੋਰਟ

MCP ਸਰਵਰ ਤਿੰਨ ਟ੍ਰਾਂਸਪੋਰਟ ਉਪਲਬਧ ਕਰਦਾ ਹੈ, ਜਿਨ੍ਹਾਂ ਸਭ ਦਾ ਆਧਾਰ ਇੱਕੋ `createMcpServer()` ਫੈਕਟਰੀ ਹੈ:

| ਟ੍ਰਾਂਸਪੋਰਟ        | ਕਿੱਥੇ                                       | ਕਦੋਂ ਵਰਤਣਾ ਹੈ                                                      |
| :---------------- | :------------------------------------------ | :----------------------------------------------------------------- |
| `stdio`           | `open-sse/mcp-server/server.ts`             | IDE ਏਕੀਕਰਨਾਂ ਲਈ (Claude Desktop, Cursor ਆਦਿ)                       |
| `sse`             | `POST/GET /api/mcp/sse` via `httpTransport` | ਉਹਨਾਂ ਬ੍ਰਾਊਜ਼ਰ/ਏਜੰਟ ਕਲਾਇੰਟਾਂ ਲਈ ਜਿਨ੍ਹਾਂ ਨੂੰ ਇਵੈਂਟ ਸਟ੍ਰੀਮ ਦੀ ਲੋੜ ਹੈ |
| `streamable-http` | `POST/GET/DELETE /api/mcp/stream`           | ਬਹੁ-ਸੈਸ਼ਨ HTTP ਕਲਾਇੰਟਾਂ ਲਈ (`mcp-session-id` ਹੈਡਰ)                 |

ਸਰਗਰਮ HTTP ਟ੍ਰਾਂਸਪੋਰਟ (`sse` ਜਾਂ `streamable-http`) ਦੀ ਚੋਣ `mcpTransport` ਸੈਟਿੰਗ ਦੁਆਰਾ ਕੀਤੀ ਜਾਂਦੀ ਹੈ। ਟ੍ਰਾਂਸਪੋਰਟ ਬਦਲਣ ਨਾਲ ਦੂਜੇ ਟ੍ਰਾਂਸਪੋਰਟ ਉੱਤੇ ਮੌਜੂਦਾ ਸੈਸ਼ਨ ਬੰਦ ਹੋ ਜਾਂਦੇ ਹਨ।

### ਰਿਮੋਟ ਪਹੁੰਚ (manage-ਸਕੋਪ ਬਾਈਪਾਸ)

`/api/mcp/*`, LOCAL_ONLY ਪੱਧਰ (`src/server/authz/routeGuard.ts`) ਵਿੱਚ ਹੈ—ਮੂਲ ਰੂਪ ਵਿੱਚ ਸਿਰਫ਼ ਲੂਪਬੈਕ ਹੋਸਟ (`localhost`, `127.0.0.1`, `::1`) ਹੀ ਇਸ ਤੱਕ ਪਹੁੰਚ ਸਕਦੇ ਹਨ। v3.8.2 ਤੋਂ, ਗੈਰ-ਲੂਪਬੈਕ ਕਲਾਇੰਟ ਕਨੈਕਟ ਕਰ ਸਕਦੇ ਹਨ ਜੇ ਉਹ ਅਜਿਹਾ `Authorization: Bearer <api-key>` ਪੇਸ਼ ਕਰਨ ਜਿਸ ਦੀ ਕੁੰਜੀ ਕੋਲ `manage` ਸਕੋਪ ਹੋਵੇ। ਕਿਸੇ ਟਨਲ, ਰਿਵਰਸ ਪ੍ਰਾਕਸੀ ਜਾਂ ਪਬਲਿਕ ਹੋਸਟਨੇਮ ਰਾਹੀਂ ਰਿਮੋਟ MCP ਸਰਵਰ ਤੱਕ ਪਹੁੰਚਣ ਦਾ ਇਹੀ ਇਕਲੌਤਾ ਤਰੀਕਾ ਹੈ।

```bash
# manage ਸਕੋਪ ਦਿਓ: ਡੈਸ਼ਬੋਰਡ ਦਾ API Keys ਸਫ਼ਾ ਖੋਲ੍ਹੋ ਅਤੇ ਕੁੰਜੀ ਉੱਤੇ
# "Management Access" ਨੂੰ ਟੌਗਲ ਕਰੋ, ਜਾਂ ਬਣਾਉਂਦੇ ਸਮੇਂ POST scopes:["manage"] ਕਰੋ।

# ਫਿਰ ਕਿਸੇ ਰਿਮੋਟ MCP ਕਲਾਇੰਟ ਤੋਂ ਕਨੈਕਟ ਕਰੋ:
curl -i \
  -H "Host: your-public-host.example" \
  -H "Authorization: Bearer sk-…" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"my-client","version":"0"}}}' \
  https://your-public-host.example/api/mcp/stream
```

ਕੋਈ ਗੈਰ-`manage` ਕੁੰਜੀ (ਜਾਂ Bearer ਨਾ ਹੋਣਾ) `403 LOCAL_ONLY` ਵਾਪਸ ਕਰਦੀ ਹੈ। ਨਾਲ ਵਾਲੇ ਪ੍ਰੀਫਿਕਸ `/api/cli-tools/runtime/*` ਨੂੰ ਜਾਣ-ਬੁੱਝ ਕੇ ਬਾਈਪਾਸਯੋਗ ਨਹੀਂ ਬਣਾਇਆ ਗਿਆ—[Route Guard ਪੱਧਰ—Manage-ਸਕੋਪ ਛੋਟ](../security/ROUTE_GUARD_TIERS.md#manage-scope-carve-out) ਵੇਖੋ।

ਪ੍ਰਿੰਸੀਪਲ 16 MiB ਤੱਕ ਅਤੇ ਗਲੋਬਲ ਸਟੋਰ 64 MiB ਤੱਕ ਸੀਮਿਤ ਹੈ। ਐਂਟਰੀਆਂ ਲਈ ਡਿਫੌਲਟ TTL 24 ਘੰਟੇ ਹੈ (ਵੱਧ ਤੋਂ ਵੱਧ
ਸੱਤ ਦਿਨ)। ਪੂਰੀ MCP ਪ੍ਰਾਪਤੀ 256 KiB ਤੱਕ ਸੀਮਿਤ ਹੈ; ਵੱਡੇ ਬਲਾਕ ਰੇਂਜਡ ਅਤੇ grep ਮੋਡਾਂ ਰਾਹੀਂ
ਉਪਲਬਧ ਰਹਿੰਦੇ ਹਨ। ਸਟੋਰੇਜ, ਪ੍ਰਾਪਤੀ, ਸੂਚੀਕਰਨ, ਜਾਂਚ, ਮਿਟਾਉਣਾ ਅਤੇ ਅੰਕੜੇ ਪ੍ਰਮਾਣਿਤ
API-ਕੁੰਜੀ ਪ੍ਰਿੰਸੀਪਲ ਅਨੁਸਾਰ ਅਲੱਗ ਰੱਖੇ ਜਾਂਦੇ ਹਨ। ਆਡਿਟ ਰਿਕਾਰਡਾਂ ਵਿੱਚ ਹੈਸ਼ ਅਤੇ ਆਕਾਰ ਦਾ ਮੈਟਾਡੇਟਾ ਹੁੰਦਾ ਹੈ, ਸਮੱਗਰੀ ਕਦੇ ਨਹੀਂ।

`omniroute_compression_status`, `analytics.mcpDescriptionCompression` ਦੇ ਅਧੀਨ MCP ਵਰਣਨ ਕੰਪਰੈਸ਼ਨ ਦੀ ਵੱਖਰੇ ਤੌਰ 'ਤੇ ਰਿਪੋਰਟ ਕਰਦਾ ਹੈ। ਇਹ ਮੁੱਲ MCP ਦੀਆਂ ਸੂਚੀਬੱਧ ਕੀਤੀਆਂ ਜਾ ਸਕਣ ਵਾਲੀਆਂ ਵਰਣਨਾਵਾਂ (`tools`, `prompts`, `resources`, ਅਤੇ `resourceTemplates`) ਲਈ ਮੈਟਾਡੇਟਾ-ਆਕਾਰ ਦੇ ਅਨੁਮਾਨ ਹਨ; ਇਹ ਪ੍ਰਦਾਤਾ ਵਰਤੋਂ ਦੀਆਂ ਰਸੀਦਾਂ ਨਹੀਂ ਹਨ ਅਤੇ ਇਨ੍ਹਾਂ ਨੂੰ `source: "mcp_metadata_estimate"` ਨਾਲ ਚਿੰਨ੍ਹਿਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।

### MCP ਐਕਸੈਸਿਬਿਲਿਟੀ ਟ੍ਰੀ ਫਿਲਟਰ (v3.8.0)

ਉਪਰੋਕਤ ਕੰਪਰੈਸ਼ਨ ਟੂਲਾਂ ਤੋਂ ਵੱਖਰੇ ਤੌਰ 'ਤੇ, OmniRoute ਵਿੱਚ ਇੱਕ ਪੋਸਟ-ਐਗਜ਼ੀਕਿਊਸ਼ਨ ਫਿਲਟਰ ਸ਼ਾਮਲ ਹੈ ਜੋ MCP ਬ੍ਰਾਊਜ਼ਰ/ਐਕਸੈਸਿਬਿਲਿਟੀ ਟੂਲਾਂ ਦੇ **ਟੂਲ ਨਤੀਜਿਆਂ** ਨੂੰ ਏਜੰਟ ਕੋਲ ਵਾਪਸ ਭੇਜਣ ਤੋਂ ਪਹਿਲਾਂ ਕੰਪ੍ਰੈੱਸ ਕਰਦਾ ਹੈ। ਇਹ ਫਿਲਟਰ ਆਪਣੇ ਆਪ ਵਿੱਚ ਕੋਈ ਟੂਲ ਨਹੀਂ ਹੈ — ਇਹ ਅਜਿਹੇ ਕਿਸੇ ਵੀ ਟੂਲ ਨਤੀਜੇ ਉੱਤੇ ਪਾਰਦਰਸ਼ੀ ਢੰਗ ਨਾਲ ਚੱਲਦਾ ਹੈ ਜਿਸ ਵਿੱਚ ਵਿਸਤ੍ਰਿਤ ਐਕਸੈਸਿਬਿਲਿਟੀ-ਟ੍ਰੀ ਜਾਂ ਬ੍ਰਾਊਜ਼ਰ-ਸਨੈਪਸ਼ਾਟ ਟੈਕਸਟ (≥2000 ਅੱਖਰ) ਸ਼ਾਮਲ ਹੋਵੇ।

ਮੁੱਖ ਵਿਹਾਰ:

- ≥30 ਲਗਾਤਾਰ ਦੁਹਰਾਈਆਂ ਗਈਆਂ ਸਿਬਲਿੰਗ ਲਾਈਨਾਂ ਨੂੰ ਸ਼ੁਰੂਆਤੀ + ਅੰਤਿਮ ਸੰਖੇਪ ਵਿੱਚ ਸਮੇਟਦਾ ਹੈ
- Playwright/ਕੰਪਿਊਟਰ-ਵਰਤੋਂ ਲਈ ਲੋੜੀਂਦੇ `[ref=eXX]` ਐਂਕਰਾਂ ਨੂੰ ਸੁਰੱਖਿਅਤ ਰੱਖਦਾ ਹੈ
- ਬਹੁਤ ਵੱਡੇ ਟੈਕਸਟ (>50,000 ਅੱਖਰ) ਨੂੰ ਨੈਵੀਗੇਸ਼ਨ ਸੰਕੇਤ ਦੇ ਨਾਲ ਨਿਰਧਾਰਤ ਸੀਮਾ 'ਤੇ ਕੱਟਦਾ ਹੈ
- ਉਮੀਦ ਕੀਤੀ ਬਚਤ: ਬ੍ਰਾਊਜ਼ਰ ਸਨੈਪਸ਼ਾਟ ਪੇਲੋਡਾਂ ਉੱਤੇ **60–80%**

ਸੰਰਚਨਾ: ਗਲੋਬਲ ਸੈਟਿੰਗਾਂ ਵਿੱਚ `compression.mcpAccessibility` (ਮਾਈਗ੍ਰੇਸ਼ਨ 056)।
ਲਾਗੂਕਰਨ: `open-sse/services/compression/engines/mcpAccessibility/`।
ਪੂਰੇ ਦਸਤਾਵੇਜ਼: [ਕੰਪਰੈਸ਼ਨ ਇੰਜਣ — MCP ਐਕਸੈਸਿਬਿਲਿਟੀ ਟ੍ਰੀ ਫਿਲਟਰ](../compression/COMPRESSION_ENGINES.md#mcp-accessibility-tree-filter)।

ਇਨ੍ਹਾਂ ਟੂਲਾਂ ਦੇ ਪਿੱਛੇ ਮੌਜੂਦ ਰਨਟਾਈਮ ਕੰਪਰੈਸ਼ਨ ਮਾਡਲ ਲਈ [ਕੰਪਰੈਸ਼ਨ ਇੰਜਣ](../compression/COMPRESSION_ENGINES.md) ਅਤੇ [RTK ਕੰਪਰੈਸ਼ਨ](../compression/RTK_COMPRESSION.md) ਵੇਖੋ।

## ਸੰਬੰਧਿਤ ਫਰੇਮਵਰਕ (v3.8.0)

ਉੱਪਰ ਦਿੱਤੀ MCP ਟੂਲ ਸੂਚੀ (110 ਵਿਲੱਖਣ ਟੂਲ, `countUniqueMcpTools()` ਦੁਆਰਾ ਗਿਣੇ ਗਏ) ਨੂੰ ਜਾਣ-ਬੁੱਝ ਕੇ
ਰਨਟਾਈਮ ਰਾਊਟਿੰਗ/ਕੈਸ਼/ਕੰਪ੍ਰੈਸ਼ਨ/ਮੈਮੋਰੀ/ਸਕਿੱਲ/ਪ੍ਰੌਕਸੀ/ਕਾਂਟੈਕਸਟ-ਸਰੋਤ ਕਾਰਵਾਈਆਂ ਤੱਕ ਸੀਮਿਤ ਰੱਖਿਆ ਗਿਆ ਹੈ। v3.8.0 ਵਿੱਚ MCP ਸਰਵਰ ਦੇ ਨਾਲ ਦੋ ਨਜ਼ਦੀਕੀ
ਫਰੇਮਵਰਕ ਵੀ ਸ਼ਾਮਲ ਹਨ ਅਤੇ ਉਨ੍ਹਾਂ ਨੂੰ ਵੱਖਰੇ ਤੌਰ 'ਤੇ ਦਸਤਾਵੇਜ਼ਬੱਧ ਕੀਤਾ ਗਿਆ ਹੈ:

### ਕਲਾਊਡ ਏਜੰਟ

ਕਲਾਊਡ ਏਜੰਟ ਵੱਖਰੀ ਪ੍ਰਕਿਰਿਆ ਵਿੱਚ ਚੱਲਣ ਵਾਲੇ AI ਕੋਡਿੰਗ ਏਜੰਟ (codex-cloud, cursor-cloud, devin, jules) ਹਨ, ਜੋ
LLM ਪ੍ਰਦਾਤਾਵਾਂ ਲਈ ਵਰਤੇ ਜਾਂਦੇ ਉਸੇ ਕਨੈਕਸ਼ਨ ਮਾਡਲ ਰਾਹੀਂ OmniRoute ਨਾਲ ਜੋੜੇ ਗਏ ਹਨ। ਉਹ
ਆਪਣੇ REST ਇੰਟਰਫੇਸ (`/api/v1/agents/*`) ਰਾਹੀਂ ਉਪਲਬਧ ਹਨ ਅਤੇ MCP ਟੂਲ ਕੈਟਾਲਾਗ ਦਾ ਹਿੱਸਾ **ਨਹੀਂ** ਹਨ
— ਕਿਸੇ ਕਲਾਊਡ ਏਜੰਟ ਨੂੰ ਕਾਲ ਕਰਨ ਨਾਲ ਕੋਈ MCP ਸਕੋਪ ਵਰਤਿਆ ਨਹੀਂ ਜਾਂਦਾ।

- ਇੰਪਲੀਮੈਂਟੇਸ਼ਨ: `src/lib/cloudAgent/` (`registry.ts`, `agents/codex.ts`, `agents/cursor.ts`, `agents/devin.ts`, `agents/jules.ts`)।
- ਜੀਵਨ-ਚੱਕਰ: `createTask`, `getStatus`, `approvePlan`, `sendMessage`, `listSources`।
- ਦਸਤਾਵੇਜ਼: [docs/frameworks/CLOUD_AGENT.md](./CLOUD_AGENT.md)।

### ਗਾਰਡਰੇਲ

ਗਾਰਡਰੇਲ ਚਲਾਉਣ ਤੋਂ ਪਹਿਲਾਂ/ਬਾਅਦ ਦੇ ਫਿਲਟਰ (vision-bridge, pii-masker, prompt-injection) ਹਨ,
ਜੋ ਚੈਟ ਪਾਈਪਲਾਈਨ ਦੇ ਅੰਦਰ ਲਾਗੂ ਹੁੰਦੇ ਹਨ। ਇਹ MCP ਟੂਲ/ਰੂਟ ਪਰਤ ਤੱਕ ਪਹੁੰਚਣ ਤੋਂ ਪਹਿਲਾਂ ਚੱਲਦੇ ਹਨ
ਅਤੇ ਆਡਿਟ ਪਾਈਪਲਾਈਨ ਨੂੰ ਸੰਰਚਿਤ ਉਲੰਘਣਾਵਾਂ ਭੇਜਦੇ ਹਨ; ਇਨ੍ਹਾਂ ਨੂੰ MCP ਟੂਲਾਂ ਵਜੋਂ ਨਹੀਂ ਬੁਲਾਇਆ ਜਾਂਦਾ।

- ਇੰਪਲੀਮੈਂਟੇਸ਼ਨ: `src/lib/guardrails/`।
- ਦਸਤਾਵੇਜ਼: [docs/security/GUARDRAILS.md](../security/GUARDRAILS.md)।

ਜਦੋਂ ਬਲੌਕ ਹੋਈ ਦਿਸਣ ਵਾਲੀ ਕਿਸੇ MCP ਕਾਲ ਨੂੰ ਡੀਬੱਗ ਕਰ ਰਹੇ ਹੋਵੋ, ਤਾਂ MCP ਆਡਿਟ ਲੌਗ
(`scope_denied:*` ਐਂਟਰੀਆਂ) ਅਤੇ ਗਾਰਡਰੇਲ ਆਡਿਟ ਟ੍ਰੇਲ—ਦੋਵੇਂ ਦੀ ਜਾਂਚ ਕਰੋ—ਕੋਈ ਬੇਨਤੀ MCP ਸਕੋਪ ਲਾਗੂਕਰਨ ਪਰਤ ਤੱਕ ਪਹੁੰਚਣ ਤੋਂ **ਪਹਿਲਾਂ** ਹੀ
ਕਿਸੇ ਗਾਰਡਰੇਲ ਦੁਆਰਾ ਰੱਦ ਕੀਤੀ ਜਾ ਸਕਦੀ ਹੈ।

### `mcp:connect` — ਸੀਮਿਤ ਰੂਟ ਸਮਰੱਥਾ (#7895)

ਗੈਰ-ਲੂਪਬੈਕ ਤੋਂ HTTP/SSE MCP ਟ੍ਰਾਂਸਪੋਰਟ (`/api/mcp/*`) ਤੱਕ ਪਹੁੰਚਣ ਲਈ
`/api/mcp/` LOCAL_ONLY ਛੋਟ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ (`docs/security/ROUTE_GUARD_TIERS.md` ਵੇਖੋ)। ਇਤਿਹਾਸਕ ਤੌਰ 'ਤੇ
ਇਹ ਛੋਟ ਸਿਰਫ਼ ਪੂਰੇ `manage`/`admin`-ਸਕੋਪ ਵਾਲੀ API ਕੁੰਜੀ ਨੂੰ ਸਵੀਕਾਰ ਕਰਦੀ ਸੀ — ਅਜਿਹੇ
ਕਾਲਰ ਲਈ ਇਹ ਬਹੁਤ ਵਿਆਪਕ ਸੀ ਜਿਸਨੂੰ ਸਿਰਫ਼ MCP ਨਾਲ ਸੰਚਾਰ ਕਰਨ ਦੀ ਲੋੜ ਹੈ। `src/shared/constants/managementScopes.ts` ਹੁਣ
`MCP_CONNECT_SCOPE = "mcp:connect"` ਐਕਸਪੋਰਟ ਕਰਦਾ ਹੈ: ਇੱਕ ਵਾਧੂ, ਸੀਮਿਤ ਸਕੋਪ (`SELF_USAGE_SCOPE`
ਵਾਲੀ ਹੀ ਮਿਸਾਲ), ਜੋ `src/server/authz/policies/management.ts` ਵਿੱਚ ਸਿਰਫ਼ `/api/mcp/` ਬਾਈਪਾਸ ਨੂੰ
ਅਧਿਕਾਰਤ ਕਰਦਾ ਹੈ — ਇਹ ਕਿਸੇ ਹੋਰ ਮੈਨੇਜਮੈਂਟ-ਰੂਟ ਲਈ ਪਹੁੰਚ ਨਹੀਂ ਦਿੰਦਾ
ਅਤੇ ਇਸਨੂੰ ਜਾਣ-ਬੁੱਝ ਕੇ `MANAGEMENT_API_KEY_SCOPES` ਤੋਂ ਬਾਹਰ ਰੱਖਿਆ ਗਿਆ ਹੈ। `manage`/`admin` ਵਾਲੀ ਕੁੰਜੀ
ਹਾਲੇ ਵੀ ਇਸ ਛੋਟ ਵਿੱਚੋਂ ਬਿਨਾਂ ਕਿਸੇ ਬਦਲਾਅ ਦੇ ਲੰਘਦੀ ਹੈ; `mcp:connect` ਸਿਰਫ਼
ਦੂਰਵਰਤੀ MCP ਕਾਲਰਾਂ ਲਈ ਘੱਟ-ਵਿਸ਼ੇਸ਼ ਅਧਿਕਾਰ ਵਾਲਾ ਵਿਕਲਪ ਹੈ, ਜਿਸਦੀ ਜਾਂਚ `hasMcpConnectOrManageScope()` ਰਾਹੀਂ ਕੀਤੀ ਜਾਂਦੀ ਹੈ।

### ਪ੍ਰਤੀ-ਕੁੰਜੀ HTTP ਸਕੋਪ ਬਾਈਂਡਿੰਗ (#7895)

HTTP/SSE ਉੱਤੇ, `open-sse/mcp-server/httpTransport.ts` ਹੁਣ ਕਾਲਰ ਦੇ ਅਸਲ
`api_keys.scopes` ਨੂੰ `resolveMcpCallerAuthInfo()` (`open-sse/mcp-server/httpAuthContext.ts`)
ਰਾਹੀਂ ਹੱਲ ਕਰਦਾ ਹੈ ਅਤੇ ਇਸਨੂੰ MCP SDK ਦੇ `transport.handleRequest(req, { authInfo })` ਨੂੰ ਪਾਸ ਕਰਦਾ ਹੈ, ਤਾਂ ਜੋ
ਹਰ ਟੂਲ ਕਾਲ ਤੱਕ ਪਹੁੰਚਣ ਵਾਲਾ `extra.authInfo.scopes`, Bearer ਕੁੰਜੀ ਦੇ ਆਪਣੇ ਸਕੋਪਾਂ ਨੂੰ ਦਰਸਾਏ।
`scopeEnforcement.ts` ਦਾ `resolveCallerScopeContext()` ਪਹਿਲਾਂ ਹੀ `_meta`
ਅਤੇ `OMNIROUTE_MCP_SCOPES` env ਫਾਲਬੈਕ ਨਾਲੋਂ `authInfo` ਨੂੰ ਤਰਜੀਹ ਦਿੰਦਾ ਸੀ — ਇਹ ਸਿਰਫ਼ ਉਸ ਪਹਿਲੇ,
ਸਭ ਤੋਂ ਉੱਚ-ਤਰਜੀਹ ਵਾਲੇ ਸਰੋਤ ਨੂੰ ਭਰਦਾ ਹੈ, ਜਿਸਨੂੰ ਪਹਿਲਾਂ HTTP ਉੱਤੇ ਡਾਟਾ ਨਹੀਂ ਮਿਲਦਾ ਸੀ। ਜਦੋਂ ਕੋਈ API ਕੁੰਜੀ ਹੱਲ ਨਹੀਂ ਹੁੰਦੀ
(ਕੋਈ ਹੈਡਰ ਨਹੀਂ, ਅਵੈਧ ਕੁੰਜੀ), `authInfo` `undefined` ਹੀ ਰਹਿੰਦਾ ਹੈ ਅਤੇ ਰੈਜ਼ੋਲਿਊਸ਼ਨ ਬਿਨਾਂ ਬਦਲਾਅ ਮੌਜੂਦਾ
`meta`/env ਲੜੀ ਵੱਲ ਚਲਾ ਜਾਂਦਾ ਹੈ। ਇਹ `OMNIROUTE_MCP_ENFORCE_SCOPES` ਦੇ
ਡਿਫਾਲਟ ਨੂੰ ਨਹੀਂ ਬਦਲਦਾ — ਇਨਫੋਰਸਮੈਂਟ ਨੂੰ ਹਾਲੇ ਵੀ ਸਪਸ਼ਟ ਤੌਰ 'ਤੇ ਸਮਰੱਥ ਕਰਨਾ ਪੈਂਦਾ ਹੈ; ਇਹ ਬਦਲਾਅ ਸਿਰਫ਼
ਸਮਰੱਥ ਹੋਣ ਤੋਂ ਬਾਅਦ ਪ੍ਰਤੀ-ਕੁੰਜੀ ਪਾਥ ਨੂੰ ਤਰਜੀਹ ਦਿੰਦਾ ਹੈ। stdio ਦੀ ਕੋਈ ਪ੍ਰਤੀ-ਕਾਲਰ ਪਛਾਣ ਨਹੀਂ ਹੈ
(`mcpCallerIdentity.ts` ਵੇਖੋ) ਅਤੇ ਇਸ 'ਤੇ ਕੋਈ ਅਸਰ ਨਹੀਂ ਪੈਂਦਾ — ਇਹ `_meta`/env ਫਾਲਬੈਕ ਲੜੀ ਉੱਤੇ ਹੀ ਰਹਿੰਦਾ ਹੈ।

## ਵਰਣਨ ਕੰਪ੍ਰੈਸ਼ਨ

MCP ਟੂਲ, ਪ੍ਰੌਂਪਟ ਅਤੇ ਸਰੋਤ ਰਜਿਸਟਰੀਆਂ ਕਲਾਇੰਟਾਂ ਸਾਹਮਣੇ ਆਉਣ ਵਾਲੇ ਮੈਟਾਡੇਟਾ ਫੁੱਟਪ੍ਰਿੰਟ (ਅਤੇ ਇਸ ਕਰਕੇ ਪ੍ਰੌਂਪਟ ਸੰਦਰਭ ਲਾਗਤ) ਨੂੰ ਘਟਾਉਣ ਲਈ ਰਜਿਸਟ੍ਰੇਸ਼ਨ/ਸੂਚੀਕਰਨ ਵੇਲੇ ਵਰਣਨਾਂ ਨੂੰ ਕੰਪ੍ਰੈੱਸ ਕਰ ਸਕਦੀਆਂ ਹਨ। ਇਸਦੀ ਇੰਪਲੀਮੈਂਟੇਸ਼ਨ `open-sse/mcp-server/descriptionCompressor.ts` ਵਿੱਚ ਹੈ ਅਤੇ `createMcpServer()` ਦੇ ਅੰਦਰ `compressMcpRegistryMetadata` ਰਾਹੀਂ MCP ਸਰਵਰ ਨਾਲ ਜੋੜੀ ਗਈ ਹੈ।

- ਕੰਪ੍ਰੈਸ਼ਨ ਸੰਭਾਲੇ-ਬਲੌਕ ਐਕਸਟ੍ਰੈਕਸ਼ਨ (ਕੋਡ ਸਪੈਨ, ਫੈਂਸ ਕੀਤੇ ਬਲੌਕ ਆਦਿ) ਸਮੇਤ Caveman ਨਿਯਮ-ਸਮੂਹ (`getRulesForContext("all", "full")`) ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਵਰਣਨ ਟੈਕਸਟ 'ਤੇ ਚੱਲਦੀ ਹੈ, ਤਾਂ ਜੋ ਸੰਰਚਨਾਤਮਕ ਸਮੱਗਰੀ ਵਿੱਚ ਤਬਦੀਲੀ ਨਾ ਹੋਵੇ।
- `key_value` ਸੈਟਿੰਗਾਂ ਟੇਬਲ ਵਿੱਚ `compression.mcpDescriptionCompressionEnabled` ਮੁੱਲ ਰਾਹੀਂ ਹਰੇਕ ਡਿਪਲੌਇਮੈਂਟ ਲਈ ਟੌਗਲ ਕਰੋ (ਡਿਫਾਲਟ: ਸਮਰੱਥ) — UI ਵਿੱਚ **Analytics → MCP ਵਰਣਨ ਕੰਪ੍ਰੈਸ਼ਨ** ਵਜੋਂ ਉਪਲਬਧ।
- `OMNIROUTE_MCP_COMPRESS_DESCRIPTIONS=false` ਜਾਂ `OMNIROUTE_MCP_DESCRIPTION_COMPRESSION=false` ਵਿੱਚੋਂ ਕਿਸੇ ਇੱਕ ਰਾਹੀਂ ਪੂਰੀ ਪ੍ਰਕਿਰਿਆ ਲਈ ਟੌਗਲ ਕਰੋ।
- ਰੀਅਲਟਾਈਮ ਅੰਕੜੇ `analytics.mcpDescriptionCompression` ਦੇ ਅਧੀਨ `omniroute_compression_status` ਰਾਹੀਂ ਦਿਖਾਏ ਜਾਂਦੇ ਹਨ ਅਤੇ ਅਸਲ ਪ੍ਰਦਾਤਾ ਵਰਤੋਂ ਰਸੀਦਾਂ ਤੋਂ ਵੱਖ ਕਰਨ ਲਈ `source: "mcp_metadata_estimate"` ਨਾਲ ਟੈਗ ਕੀਤੇ ਜਾਂਦੇ ਹਨ।

## ਟੂਲ ਕਾਰਡੀਨੈਲਿਟੀ ਘਟਾਉਣਾ (F4.3)

ਵਰਣਨ ਸੰਕੁਚਨ ਹਰ ਟੂਲ ਦੇ ਮੈਟਾਡੇਟਾ ਨੂੰ ਘਟਾਉਂਦਾ ਹੈ; **ਟੂਲ-ਕਾਰਡੀਨੈਲਿਟੀ ਘਟਾਉਣਾ** ਇਸ ਤੋਂ ਇੱਕ ਕਦਮ ਅੱਗੇ ਜਾਂਦਾ ਹੈ ਅਤੇ _ਐਲਾਨ ਕੀਤੇ ਜਾਣ ਵਾਲੇ_ ਟੂਲਾਂ ਦੀ ਗਿਣਤੀ ਹੀ ਘਟਾ ਦਿੰਦਾ ਹੈ। `tools/list` ਮੈਨੀਫੈਸਟ ਵਿੱਚ ਘੱਟ ਟੂਲ ਦਰਸਾਉਣ ਨਾਲ ਟੂਲ ਕੈਟਾਲਾਗ ਲਈ ਕਲਾਇੰਟ ਦੇ ਮਾਡਲ ਵੱਲੋਂ ਅਦਾ ਕੀਤੀ ਜਾਣ ਵਾਲੀ ਪ੍ਰਤੀ-ਬੇਨਤੀ ਟੋਕਨ ਲਾਗਤ ਘਟਦੀ ਹੈ ("ਲੇਅਰ 5" ਸੰਕੁਚਨ)। ਲਾਗੂਕਰਨ `open-sse/mcp-server/toolCardinality.ts` (`reduceToolManifest`) ਵਿੱਚ ਇੱਕ ਸ਼ੁੱਧ, ਸਟੇਟਲੈੱਸ ਫਿਲਟਰ ਹੈ, ਜਿਸ ਨੂੰ `createMcpServer()` (`open-sse/mcp-server/server.ts`) ਵਿੱਚ ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਲੂਪ ਨਾਲ ਜੋੜਿਆ ਗਿਆ ਹੈ।

**ਆਪਣੀ ਮਰਜ਼ੀ ਨਾਲ ਚਾਲੂ ਕਰਨ ਯੋਗ, ਮੂਲ ਰੂਪ ਵਿੱਚ ਬੰਦ।** ਫਿਲਟਰ ਸਿਰਫ਼ ਉਦੋਂ ਚੱਲਦਾ ਹੈ ਜਦੋਂ ਦੋ ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲਾਂ ਵਿੱਚੋਂ ਘੱਟੋ-ਘੱਟ ਇੱਕ ਸੈੱਟ ਹੋਵੇ; ਜੇ ਦੋਵਾਂ ਵਿੱਚੋਂ ਕੋਈ ਵੀ ਸੈੱਟ ਨਾ ਹੋਵੇ, ਤਾਂ ਸਾਰੇ 110 ਟੂਲ ਬਿਨਾਂ ਕਿਸੇ ਬਦਲਾਅ ਦੇ ਐਲਾਨੇ ਜਾਂਦੇ ਹਨ।

| `MCP_TOOL_DENY`  | ਬਲੈਕਲਿਸਟ — ਕੌਮੇ ਨਾਲ ਵੱਖ ਕੀਤੇ ਟੂਲ ਨਾਮ, ਜਿਨ੍ਹਾਂ ਨੂੰ ਹਮੇਸ਼ਾ `tools/list` ਵਿੱਚੋਂ ਹਟਾ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ |
| `MCP_TOOL_ALLOW` | ਅਲਾਊ-ਲਿਸਟ — ਕੌਮੇ ਨਾਲ ਵੱਖ ਕੀਤੇ ਟੂਲ ਨਾਮ; ਸਿਰਫ਼ ਇਹੀ ਬਚਦੇ ਹਨ, ਬਾਕੀ ਸਭ ਹਟਾ ਦਿੱਤੇ ਜਾਂਦੇ ਹਨ            |

`deny`, `allow` ਨਾਲੋਂ ਤਰਜੀਹ ਰੱਖਦਾ ਹੈ। ਨਾਮ ਕੌਮਿਆਂ ਨਾਲ ਵੱਖ ਕੀਤੇ ਜਾਂਦੇ ਹਨ, ਉਨ੍ਹਾਂ ਦੇ ਅੱਗੇ-ਪਿੱਛੇ ਦੀਆਂ ਖਾਲੀ ਥਾਵਾਂ ਹਟਾਈਆਂ ਜਾਂਦੀਆਂ ਹਨ ਅਤੇ ਖਾਲੀ ਐਂਟਰੀਆਂ ਨੂੰ ਅਣਡਿੱਠਾ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। ਉਦਾਹਰਨਾਂ:

```bash
# ਕੈਟਾਲਾਗ ਵਿੱਚੋਂ ਦੋ ਟੂਲ ਹਟਾਓ
MCP_TOOL_DENY="omniroute_get_health,omniroute_list_combos" omniroute --mcp

# ਸਿਰਫ਼ ਰੂਟਿੰਗ + ਕੋਟਾ ਟੂਲਾਂ ਦਾ ਐਲਾਨ ਕਰੋ (ਅਲਾਊ-ਲਿਸਟ ਮੋਡ)
MCP_TOOL_ALLOW="omniroute_route_request,omniroute_check_quota" omniroute --mcp
```

**ਫਿਲਟਰ ਕੀਤੇ ਟੂਲ ਕਿਵੇਂ ਹਟਾਏ ਜਾਂਦੇ ਹਨ:** ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਹਮੇਸ਼ਾ ਸਫਲ ਹੁੰਦੀ ਹੈ; ਪ੍ਰੋਫ਼ਾਈਲ ਵੱਲੋਂ ਰੱਦ ਕੀਤੇ ਟੂਲ ਨੂੰ ਫਿਰ MCP SDK ਹੈਂਡਲ ਉੱਤੇ `.disable()` ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਇਸ ਲਈ ਉਹ ਕਦੇ ਵੀ `tools/list` ਵਿੱਚ ਦਿਖਾਈ ਨਹੀਂ ਦਿੰਦਾ, ਪਰ ਵਾਇਰਿੰਗ ਬਰਕਰਾਰ ਰਹਿੰਦੀ ਹੈ (ਸਾਫ਼-ਸੁਥਰਾ ਚਾਲੂ/ਬੰਦ ਕਰਨਾ, ਮੁੜ-ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਨਹੀਂ)। ਪ੍ਰੋਫ਼ਾਈਲ ਪਾਰਸਰ `readMcpToolProfileFromEnv(process.env)` ਹੈ, ਜੋ ਦੋਵੇਂ ਵੇਰੀਏਬਲ ਖਾਲੀ ਹੋਣ 'ਤੇ `null` (ਕੋਈ ਫਿਲਟਰਿੰਗ ਨਹੀਂ) ਵਾਪਸ ਕਰਦਾ ਹੈ।

`reduceToolManifest` ਦੇ ਪਿੱਛੇ ਮੌਜੂਦ ਵਧੇਰੇ ਸਮਰੱਥ `ToolProfile` ਸੰਰਚਨਾ ਸਕੋਪ-ਇੰਟਰਸੈਕਸ਼ਨ ਫਿਲਟਰਿੰਗ (`allowScopes`, `read:*`-ਸ਼ੈਲੀ ਵਾਇਲਡਕਾਰਡ ਮੇਲ ਨਾਲ) ਅਤੇ ਇੱਕ ਨਿਰਧਾਰਤ `maxTools` ਸੀਮਾ ਦਾ ਵੀ ਸਮਰਥਨ ਕਰਦੀ ਹੈ, ਪਰ ਇਨ੍ਹਾਂ ਦੋਵਾਂ ਨਿਯੰਤਰਣਾਂ ਨੂੰ ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਵੇਲੇ ਪੂਰੇ ਮੈਨੀਫੈਸਟ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ ਅਤੇ ਅੱਜ ਇਹ ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲਾਂ ਰਾਹੀਂ **ਉਪਲਬਧ ਨਹੀਂ** ਹਨ (ਇੱਕ `tools/list`-ਪੱਧਰੀ ਹੁੱਕ ਟ੍ਰੈਕ ਕੀਤਾ ਹੋਇਆ ਅਗਲਾ ਕੰਮ ਹੈ)। ਘਟਾਉਣ ਤੋਂ ਪਹਿਲਾਂ ਅਤੇ ਬਾਅਦ ਮੈਨੀਫੈਸਟ ਦੀ ਟੋਕਨ ਲਾਗਤ ਦੀ ਤੁਲਨਾ ਕਰਨ ਲਈ `estimateManifestTokens()` ਉਪਲਬਧ ਹੈ।

## ਰਨਟਾਈਮ ਹਾਰਟਬੀਟ

stdio ਟ੍ਰਾਂਸਪੋਰਟ ਹਰ 5 ਸਕਿੰਟਾਂ ਬਾਅਦ ਲਾਈਵਨੈੱਸ ਨੂੰ `${DATA_DIR}/runtime/mcp-heartbeat.json` ਵਿੱਚ ਸੰਭਾਲਦਾ ਹੈ। ਡੈਸ਼ਬੋਰਡ (`/api/mcp/status`) `online` ਨਿਰਧਾਰਤ ਕਰਨ ਲਈ ਇਸ ਫ਼ਾਈਲ ਦੇ ਨਾਲ PID ਲਾਈਵਨੈੱਸ ਨੂੰ ਪੜ੍ਹਦਾ ਹੈ। ਇਸ ਦੀ ਬਜਾਏ HTTP ਟ੍ਰਾਂਸਪੋਰਟ ਇਨ-ਪ੍ਰੋਸੈਸ `getMcpHttpStatus()` ਤੋਂ ਸਥਿਤੀ ਦੀ ਰਿਪੋਰਟ ਕਰਦੇ ਹਨ (ਕੋਈ ਫ਼ਾਈਲ ਨਹੀਂ ਲਿਖੀ ਜਾਂਦੀ)।

ਹਾਰਟਬੀਟ ਸਨੈਪਸ਼ਾਟ ਵਿੱਚ ਇਹ ਸ਼ਾਮਲ ਹੁੰਦਾ ਹੈ:

```json
{
  "pid": 12345,
  "startedAt": "2026-05-13T12:34:56.000Z",
  "lastHeartbeatAt": "2026-05-13T12:35:01.000Z",
  "version": "1.8.1",
  "transport": "stdio",
  "scopesEnforced": false,
  "allowedScopes": [],
  "toolCount": 110
}
```

## ਆਡਿਟ ਲੌਗਿੰਗ

ਹਰ ਟੂਲ ਕਾਲ ਨੂੰ `open-sse/mcp-server/audit.ts` ਵੱਲੋਂ SQLite ਦੀ `mcp_tool_audit` ਟੇਬਲ ਵਿੱਚ ਲੌਗ ਕੀਤਾ ਜਾਂਦਾ ਹੈ:

- ਟੂਲ ਦਾ ਨਾਮ, ਆਰਗੂਮੈਂਟ (ਹਰ ਟੂਲ ਦੇ `auditLevel` ਅਨੁਸਾਰ ਹੈਸ਼ ਕੀਤੇ/ਛੋਟੇ ਕੀਤੇ), ਨਤੀਜਾ
- ms ਵਿੱਚ ਮਿਆਦ, ਸਫਲਤਾ/ਅਸਫਲਤਾ ਫਲੈਗ, ਗਲਤੀ ਸੁਨੇਹਾ (ਜਦੋਂ ਲਾਗੂ ਹੋਵੇ)
- API ਕੁੰਜੀ ਹੈਸ਼, ਟਾਈਮਸਟੈਂਪ
- ਸਕੋਪ ਇਨਕਾਰਾਂ ਨੂੰ ਗੁੰਮ ਸਕੋਪਾਂ ਦੀ ਸੂਚੀ ਸਮੇਤ `scope_denied:<reason>` ਵਜੋਂ ਲੌਗ ਕੀਤਾ ਜਾਂਦਾ ਹੈ

ਹਾਲੀਆ ਕਾਲਾਂ ਦੀ ਜਾਂਚ ਕਰਨ ਲਈ ਡੈਸ਼ਬੋਰਡ ਜਾਂ `/api/mcp/audit` ਅਤੇ `/api/mcp/audit/stats` REST ਐਂਡਪੌਇੰਟ ਵਰਤੋ।
