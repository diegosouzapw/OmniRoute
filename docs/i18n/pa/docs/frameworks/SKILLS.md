> **ਅਧਿਕਾਰਤ ਸਰੋਤ:** `src/lib/skills/` ਅਤੇ `src/app/api/skills/`
> **ਆਖਰੀ ਅੱਪਡੇਟ:** 2026-06-28 — v3.8.40

OmniRoute ਇੱਕ ਵਿਸਤਾਰਯੋਗ Skills ਫ੍ਰੇਮਵਰਕ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ, ਜੋ ਭਾਸ਼ਾ ਮਾਡਲਾਂ (ਅਤੇ ਓਪਰੇਟਰਾਂ) ਨੂੰ ਮੁੜ ਵਰਤੋਂਯੋਗ ਸਮਰੱਥਾਵਾਂ ਜੋੜਨ ਦਿੰਦਾ ਹੈ — ਫ਼ਾਈਲ ਸਿਸਟਮ ਪੜ੍ਹਨ ਅਤੇ HTTP ਬੇਨਤੀਆਂ ਤੋਂ ਲੈ ਕੇ ਸੈਂਡਬਾਕਸ ਕੀਤੇ ਕੋਡ ਦੇ ਚਲਾਓ ਅਤੇ ਚੁਣਿੰਦੇ ਮਾਰਕੀਟਪਲੇਸ ਸਕਿਲਾਂ ਤੱਕ।

ਇੱਕ ਸਕਿਲ ਕੰਮ ਦੀ ਵਰਜਨਬੱਧ, ਸਕੀਮਾ-ਪਰਿਭਾਸ਼ਿਤ ਇਕਾਈ ਹੁੰਦੀ ਹੈ। OmniRoute ਸਕਿਲਾਂ ਨੂੰ ਟੂਲ ਪਰਿਭਾਸ਼ਾਵਾਂ ਵਜੋਂ ਬਾਹਰ ਜਾਣ ਵਾਲੀਆਂ ਬੇਨਤੀਆਂ ਵਿੱਚ ਸ਼ਾਮਲ ਕਰ ਸਕਦਾ ਹੈ, ਮਾਡਲ ਤੋਂ ਵਾਪਸ ਆਉਣ ਵਾਲੀਆਂ ਟੂਲ ਕਾਲਾਂ ਨੂੰ ਇੰਟਰਸੈਪਟ ਕਰ ਸਕਦਾ ਹੈ, ਮੇਲ ਖਾਂਦਾ ਹੈਂਡਲਰ ਚਲਾ ਸਕਦਾ ਹੈ, ਅਤੇ ਨਤੀਜਾ ਮਾਡਲ ਨੂੰ ਵਾਪਸ ਦੇ ਸਕਦਾ ਹੈ ਤਾਂ ਜੋ ਗੱਲਬਾਤ ਜਾਰੀ ਰਹੇ। ਮਾਡਲ ਕਦੇ ਵੀ ਇੰਪਲੀਮੈਂਟੇਸ਼ਨ ਨਹੀਂ ਵੇਖਦਾ — ਸਿਰਫ਼ ਟੂਲ ਇੰਟਰਫੇਸ ਵੇਖਦਾ ਹੈ।

Agent Skills ਕੈਟਾਲਾਗ, ਜਨਰੇਟਰ, MCP ਟੂਲਾਂ ਅਤੇ A2A ਸਕਿਲ ਲਈ, [docs/frameworks/AGENT-SKILLS.md](./AGENT-SKILLS.md) ਵੇਖੋ।

## ਧਾਰਨਾਵਾਂ

### ਸਕਿਲ ਸਰੋਤ

ਇੱਕੋ ਰਜਿਸਟਰੀ ਵਿੱਚ ਸਕਿਲਾਂ ਦੇ ਤਿੰਨ ਸਰੋਤ ਇਕੱਠੇ ਮੌਜੂਦ ਹਨ:

1. **ਬਿਲਟ-ਇਨ ਸਕਿਲਾਂ** (`src/lib/skills/builtins.ts`) — OmniRoute ਨਾਲ ਹੀ ਦਿੱਤੀਆਂ ਜਾਂਦੀਆਂ ਹਨ। ਆਮ ਵਰਤੋਂ ਦੇ ਮਾਮਲਿਆਂ ਨੂੰ ਕਵਰ ਕਰਦੀਆਂ ਹਨ:
   - `file_read`, `file_write` — `<DATA_DIR>/skills/workspaces/<hashed-key>/` ਹੇਠ ਪ੍ਰਤੀ-API-ਕੀ ਸੈਂਡਬਾਕਸ ਵਰਕਸਪੇਸ
   - `http_request` — `guard: "public-only"` ਨਾਲ `safeOutboundFetch` ਰਾਹੀਂ ਬਾਹਰ ਜਾਣ ਵਾਲਾ HTTP
   - `web_search` — ਕੈਸ਼ਿੰਗ (`executeWebSearch`) ਵਾਲਾ ਪਲੱਗ ਕਰਨ ਯੋਗ ਖੋਜ ਪ੍ਰਦਾਤਾ
   - `eval_code` — Docker-ਸੈਂਡਬਾਕਸ ਕੀਤਾ `node` ਜਾਂ `python` ਚਲਾਓ
   - `execute_command` — Docker-ਸੈਂਡਬਾਕਸ ਕੀਤੀ ਸ਼ੈੱਲ ਕਮਾਂਡ
   - `browser` — Playwright-ਅਧਾਰਿਤ ਸਕੈਫੋਲਡਿੰਗ, ਮੂਲ ਰੂਪ ਵਿੱਚ ਅਯੋਗ (`builtin/browser.ts`)
2. **SkillsMP** (OmniRoute ਮਾਰਕੀਟਪਲੇਸ) — `https://skillsmp.com/api/v1/skills/search` ਤੋਂ ਪ੍ਰਾਪਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। Settings ਵਿੱਚ `skillsmpApiKey` ਦੀ ਲੋੜ ਹੈ।
3. **SkillsSH** (`skills.sh` ਕਮਿਊਨਿਟੀ ਕੈਟਾਲਾਗ) — `https://skills.sh/api/search` ਤੋਂ ਪ੍ਰਾਪਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। ਕਿਸੇ ਪ੍ਰਮਾਣੀਕਰਨ ਦੀ ਲੋੜ ਨਹੀਂ; SKILL.md ਸਮੱਗਰੀ GitHub raw ਤੋਂ ਲਈ ਜਾਂਦੀ ਹੈ।

ਇੱਕੋ "ਸਰਗਰਮ ਪ੍ਰਦਾਤਾ" ਨਿਯੰਤਰਿਤ ਕਰਦਾ ਹੈ ਕਿ ਡੈਸ਼ਬੋਰਡ ਕਿਸ ਕੈਟਾਲਾਗ ਤੋਂ ਇੰਸਟਾਲ ਕਰਦਾ ਹੈ (`src/lib/skills/providerSettings.ts`)। ਇਸਨੂੰ **Settings → Memory & Skills** ਹੇਠ ਬਦਲੋ। ਮੂਲ: `skillsmp`।

### ਸਕਿਲ ਪਛਾਣ

ਇਨ-ਮੈਮੋਰੀ ਰਜਿਸਟਰੀ (`src/lib/skills/registry.ts`) ਵਿੱਚ ਸਕਿਲਾਂ ਦੀ ਕੁੰਜੀ `name@version` ਹੁੰਦੀ ਹੈ। ਵਰਜਨ semver (`^\d+\.\d+\.\d+$`) ਹੋਣਾ ਲਾਜ਼ਮੀ ਹੈ। `resolveVersion()` ਨੂੰ `^`, `~`, `>`, `>=`, `<`, `<=`, `==`, ਅਤੇ ਬਿਲਕੁਲ ਮੇਲ ਖਾਂਦੀਆਂ ਪਾਬੰਦੀਆਂ ਦੀ ਸਮਝ ਹੈ।

### ਸਕਿਲ ਮੋਡ

ਹਰੇਕ ਸਕਿਲ ਦਾ ਇੱਕ ਰਨਟਾਈਮ ਮੋਡ ਹੁੰਦਾ ਹੈ, ਜੋ ਇਹ ਨਿਯੰਤਰਿਤ ਕਰਦਾ ਹੈ ਕਿ ਇਸਨੂੰ ਕਦੋਂ ਸ਼ਾਮਲ ਕੀਤਾ ਜਾਵੇ:

| ਮੋਡ    | ਵਿਹਾਰ                                                                                                            |
| ------ | ---------------------------------------------------------------------------------------------------------------- |
| `on`   | ਹਮੇਸ਼ਾ ਟੂਲ ਪਰਿਭਾਸ਼ਾ ਵਜੋਂ ਸ਼ਾਮਲ ਕੀਤਾ ਜਾਂਦਾ ਹੈ                                                                     |
| `off`  | ਕਦੇ ਵੀ ਸ਼ਾਮਲ ਨਹੀਂ ਕੀਤਾ ਜਾਂਦਾ, ਕਦੇ ਵੀ ਚਲਾਇਆ ਨਹੀਂ ਜਾ ਸਕਦਾ                                                          |
| `auto` | ਆਉਣ ਵਾਲੀ ਬੇਨਤੀ ਦੇ ਮੁਕਾਬਲੇ ਸਕੋਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ; ਕੇਵਲ ਤਾਂ ਹੀ ਸ਼ਾਮਲ ਕੀਤਾ ਜਾਂਦਾ ਹੈ ਜੇ ਸਕੋਰ ≥ `AUTO_MIN_SCORE` (ਮੂਲ 3) |

ਮਾਰਕੀਟਪਲੇਸ ਤੋਂ ਇੰਸਟਾਲ ਕੀਤੀਆਂ ਸਕਿਲਾਂ ਲਈ `auto` ਮੂਲ ਮੋਡ ਹੈ। `enabled=true` ਅਤੇ `mode="off"` ਦਾ ਇਕੱਠੇ ਅਰਥ "ਰਜਿਸਟਰ ਕੀਤਾ ਹੋਇਆ ਪਰ ਨਿਸ਼ਕ੍ਰਿਆ" ਹੈ — ਪੁਰਾਤਨ ਕਾਲਮ ਰਾਹੀਂ `enabled` ਨੂੰ ਟੌਗਲ ਕਰਨ ਨਾਲ `mode` ਵੀ ਅੱਪਡੇਟ ਹੁੰਦਾ ਹੈ, ਤਾਂ ਜੋ ਪੁਰਾਣੇ ਕੋਡ-ਪਥ ਇਕਸਾਰ ਰਹਿਣ (`src/app/api/skills/[id]/route.ts`)।

### ਸਥਿਤੀ (ਚਲਾਓ)

ਸਕਿਲ ਚਲਾਵਾਂ ਨੂੰ `skill_executions` ਟੇਬਲ ਵਿੱਚ ਹੇਠ ਲਿਖੀਆਂ ਸਥਿਤੀਆਂ ਨਾਲ ਟਰੈਕ ਕੀਤਾ ਜਾਂਦਾ ਹੈ (`src/lib/skills/types.ts`):

```ts
enum SkillStatus {
  PENDING = "pending",
  RUNNING = "running",
  SUCCESS = "success",
  ERROR = "error",
  TIMEOUT = "timeout",
}
```

### ਰਜਿਸਟਰੀ ਕੈਸ਼

`SkillRegistry`, 60-ਸਕਿੰਟ TTL ਕੈਸ਼ (`registry.ts:14`) ਵਾਲਾ ਇੱਕ ਸਿੰਗਲਟਨ ਹੈ। `loadFromDatabase()` ਇਡੈਂਪੋਟੈਂਟ ਹੈ ਅਤੇ `pendingLoad` ਰਾਹੀਂ ਇੱਕੋ ਸਮੇਂ ਹੋਣ ਵਾਲੀਆਂ ਕਾਲਾਂ ਦੀਆਂ ਨਕਲਾਂ ਹਟਾਉਂਦਾ ਹੈ। ਕੋਈ ਵੀ ਲਿਖਤ ਕਾਰਵਾਈ (`register`/`unregister`/`unregisterById`) ਕੈਸ਼ ਨੂੰ ਅਵੈਧ ਕਰ ਦਿੰਦੀ ਹੈ। ਵਰਜਨਾਂ ਨੂੰ `getSkillVersions(name)` ਅਤੇ `resolveVersion(name, constraint)` ਰਾਹੀਂ ਲੱਭੋ।

### ਪ੍ਰਦਾਤਾ-ਅਨੁਕੂਲ ਇੰਜੈਕਸ਼ਨ

`src/lib/skills/injection.ts` ਵਿੱਚ `injectSkills()` ਉਹ ਪ੍ਰਵੇਸ਼ ਬਿੰਦੂ ਹੈ ਜੋ ਰਜਿਸਟਰ ਕੀਤੀਆਂ ਸਕਿਲਾਂ ਨੂੰ ਪ੍ਰਦਾਤਾ-ਵਿਸ਼ੇਸ਼ ਟੂਲ ਪਰਿਭਾਸ਼ਾਵਾਂ ਵਿੱਚ ਬਦਲਦਾ ਹੈ:

- **OpenAI** — `{ type: "function", function: { name, description, parameters } }`
- **Anthropic** — `{ name, description, input_schema }`
- **Google (Gemini)** — `{ name, description, parameters }`

ਟੂਲ ਦਾ ਨਾਮ `name@version` ਵਜੋਂ ਐਨਕੋਡ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਤਾਂ ਜੋ ਜਦੋਂ ਮਾਡਲ ਇਸਨੂੰ ਵਾਪਸ ਕਾਲ ਕਰੇ, ਹੈਂਡਲਰ ਸਹੀ ਵਰਜਨ ਚੁਣ ਸਕੇ।

### AUTO ਸਕੋਰਿੰਗ

ਜਦੋਂ `mode="auto"` ਹੁੰਦਾ ਹੈ, ਤਾਂ ਹਰ ਉਮੀਦਵਾਰ ਸਕਿੱਲ ਨੂੰ ਬੇਨਤੀ ਦੇ ਸੰਦਰਭ ਦੇ ਮੁਕਾਬਲੇ ਸਕੋਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ (`injection.ts` ਵਿੱਚ `scoreAutoSkill()`):

| ਸੰਕੇਤ                                                      | ਅੰਕ           |
| ---------------------------------------------------------- | ------------- |
| ਸਕਿੱਲ ਦਾ ਨਾਮ ਸੰਦਰਭ ਵਿੱਚ ਹੂ-ਬ-ਹੂ ਦਿਖਾਈ ਦਿੰਦਾ ਹੈ             | +6            |
| ਨਾਮ ਦਾ ਹਰੇਕ ਟੋਕਨ ਕਿਸੇ ਸੰਦਰਭ ਟੋਕਨ ਨਾਲ ਮੇਲ ਖਾਂਦਾ ਹੈ          | +2            |
| ਹਰੇਕ ਟੈਗ ਸਬਸਟਰਿੰਗ ਸੰਦਰਭ ਨਾਲ ਮੇਲ ਖਾਂਦੀ ਹੈ                   | +3            |
| ਵਰਣਨ ਦਾ ਹਰੇਕ ਟੋਕਨ ਸੰਦਰਭ ਨਾਲ ਮੇਲ ਖਾਂਦਾ ਹੈ                   | +1            |
| ਪਿਛੋਕੜ ਦਾ ਕਾਰਨ ਕਿਸੇ ਨਾਮ ਟੋਕਨ ਨਾਲ ਮੇਲ ਖਾਂਦਾ ਹੈ              | ਪ੍ਰਤੀ ਟੋਕਨ +2 |
| ਪਿਛੋਕੜ ਦਾ ਕਾਰਨ ਕਿਸੇ ਟੈਗ ਨਾਲ ਮੇਲ ਖਾਂਦਾ ਹੈ                   | ਪ੍ਰਤੀ ਟੋਕਨ +2 |
| ਟੈਗਾਂ ਵਿੱਚ ਪ੍ਰਦਾਤਾ ਸੰਕੇਤ ਬੇਨਤੀ ਦੇ ਪ੍ਰਦਾਤਾ ਨਾਲ ਮੇਲ ਖਾਂਦਾ ਹੈ | +2 / −2       |

`score >= AUTO_MIN_SCORE = 3` ਵਾਲੀਆਂ ਸਿਖਰਲੀਆਂ `AUTO_MAX_SKILLS = 5` ਸਕਿੱਲਾਂ ਇੰਜੈਕਟ ਕੀਤੀਆਂ ਜਾਂਦੀਆਂ ਹਨ। ਬਰਾਬਰੀ ਹੋਣ ’ਤੇ ਪਹਿਲਾਂ `installCount` (ਘਟਦੇ ਕ੍ਰਮ ਵਿੱਚ), ਫਿਰ ਵਰਣਮਾਲਾ ਅਨੁਸਾਰ ਨਾਮ ਰਾਹੀਂ ਫ਼ੈਸਲਾ ਕੀਤਾ ਜਾਂਦਾ ਹੈ (`injection.ts:225-235`)।

### ਟੂਲ ਕਾਲ ਇੰਟਰਸੈਪਸ਼ਨ

ਅੱਪਸਟ੍ਰੀਮ ਵੱਲੋਂ ਟੂਲ-ਕਾਲਿੰਗ ਜਵਾਬ ਵਾਪਸ ਕਰਨ ਤੋਂ ਬਾਅਦ, ਚੈਟ ਹੈਂਡਲਰ ਵੱਲੋਂ `src/lib/skills/interception.ts` ਵਿੱਚ `handleToolCallExecution()` ਨੂੰ ਕਾਲ ਕੀਤਾ ਜਾਂਦਾ ਹੈ:

1. `extractToolCalls()` ਪ੍ਰਦਾਤਾ-ਵਿਸ਼ੇਸ਼ ਬਣਤਰਾਂ ਨੂੰ ਪੜ੍ਹਦਾ ਹੈ (OpenAI `tool_calls` / Responses `function_call`, Anthropic `tool_use`, Gemini `functionCalls`)।
2. ਬਿਲਟ-ਇਨ ਟੂਲ ਉਪਨਾਮਾਂ (ਉਦਾਹਰਨ ਲਈ, `omniroute_web_search` → `web_search`) ਨੂੰ ਪਹਿਲਾਂ ਹੱਲ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। ਬਿਲਟ-ਇਨ ਹੈਂਡਲਰ ਇਨਲਾਈਨ ਚੱਲਦੇ ਹਨ।
3. ਹੋਰ ਹਰ ਚੀਜ਼ ਨੂੰ `skillExecutor.execute(name@version, args, { apiKeyId, sessionId })` ਰਾਹੀਂ ਰੂਟ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।
4. ਨਤੀਜਿਆਂ ਨੂੰ ਵਾਪਸ ਜਵਾਬ ਵਿੱਚ ਜੋੜ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ — ਜਿਵੇਂ ਉਚਿਤ ਹੋਵੇ, `tool_results`, `function_call_output` ਆਈਟਮਾਂ, ਜਾਂ Anthropic `tool_result` ਬਲਾਕ।

ਐਗਜ਼ੀਕਿਊਸ਼ਨ ਸੰਦਰਭ ਵਿੱਚ `customSkillExecutionEnabled` ਨੂੰ `false` ਸੈੱਟ ਕੀਤਾ ਜਾ ਸਕਦਾ ਹੈ, ਤਾਂ ਜੋ ਸਿਰਫ਼ ਬਿਲਟ-ਇਨ ਇੰਟਰਸੈਪਸ਼ਨ ਦੀ ਇਜਾਜ਼ਤ ਹੋਵੇ (ਇਸਦੀ ਵਰਤੋਂ ਉਹਨਾਂ ਬੇਨਤੀ ਪਾਥਾਂ ਵੱਲੋਂ ਕੀਤੀ ਜਾਂਦੀ ਹੈ ਜੋ ਯੂਜ਼ਰ-ਪਰਿਭਾਸ਼ਿਤ ਹੈਂਡਲਰਾਂ ਨੂੰ ਸਪਸ਼ਟ ਤੌਰ ’ਤੇ ਅਸਮਰੱਥ ਕਰਦੇ ਹਨ)।

## Docker ਸੈਂਡਬਾਕਸ

ਗੈਰ-ਬਿਲਟ-ਇਨ ਕੋਡ ਪਾਥ (`eval_code`, `execute_command`) `SandboxRunner` (`src/lib/skills/sandbox.ts`) ਰਾਹੀਂ Docker ਦੇ ਅੰਦਰ ਚੱਲਦੇ ਹਨ। ਹਰ ਕੰਟੇਨਰ ਨੂੰ ਹੇਠ ਲਿਖੇ ਵਿਕਲਪਾਂ ਨਾਲ ਲਾਂਚ ਕੀਤਾ ਜਾਂਦਾ ਹੈ:

```
--rm --network none|bridge --cap-drop ALL
--security-opt no-new-privileges --pids-limit 100
--cpus <cpuLimit/1000> --memory <memoryLimit>m
--tmpfs /tmp:rw,noexec,nosuid,size=64m
--tmpfs /workspace:rw,noexec,nosuid,size=64m
--read-only (ਜਦੋਂ readOnly=true ਹੋਵੇ)
```

ਡਿਫਾਲਟ (`SandboxRunner.DEFAULT_CONFIG`):

| ਫੀਲਡ             | ਡਿਫਾਲਟ          | ਨੋਟਸ                                                        |
| ---------------- | --------------- | ----------------------------------------------------------- |
| `cpuLimit`       | 100 (= 0.1 CPU) | `--cpus` ਨੂੰ ਪਾਸ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ 1000 ਨਾਲ ਭਾਗ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ |
| `memoryLimit`    | 256 MB          | ਸਖ਼ਤ ਸੀਮਾ                                                   |
| `timeout`        | 30000 ms        | `SIGTERM` + `docker kill` ਰਾਹੀਂ ਸੌਫਟ ਕਿਲ                    |
| `networkEnabled` | `false`         | `--network none` ਬਣ ਜਾਂਦਾ ਹੈ                                |
| `readOnly`       | `true`          | ਰੂਟ FS ਸਿਰਫ਼ ਪੜ੍ਹਨਯੋਗ; `/tmp` ਅਤੇ `/workspace` tmpfs ਹਨ     |

`SandboxRunner.kill(id)` ਅਤੇ `killAll()` ਨੂੰ ਸ਼ਟਡਾਊਨ ਲਈ ਉਪਲਬਧ ਕਰਵਾਇਆ ਗਿਆ ਹੈ; ਚੱਲ ਰਹੇ ਕੰਟੇਨਰਾਂ ਨੂੰ `runningContainers: Map<string, ChildProcess>` ਵਿੱਚ ਟ੍ਰੈਕ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।

### ਸੈਂਡਬਾਕਸ ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲ

`src/lib/skills/builtins.ts` ਵਿੱਚ `process.env` ਰਾਹੀਂ ਕੌਂਫਿਗਰ ਕੀਤੇ ਜਾਂਦੇ ਹਨ:

| ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲ                   | ਡਿਫਾਲਟ           | ਉਦੇਸ਼                                                                        |
| --------------------------------- | ---------------- | ---------------------------------------------------------------------------- |
| `SKILLS_MAX_FILE_BYTES`           | `1048576` (1 MB) | `file_read` ਅਤੇ `file_write` ਲਈ ਸੀਮਾ                                         |
| `SKILLS_MAX_HTTP_RESPONSE_BYTES`  | `256000`         | `http_request` ਰਿਸਪਾਂਸ ਬੌਡੀ ਲਈ ਸੀਮਾ                                          |
| `SKILLS_MAX_SANDBOX_OUTPUT_CHARS` | `100000`         | ਕਾਲਰ ਨੂੰ ਵਾਪਸ ਕੀਤੇ stdout/stderr ਲਈ ਸੀਮਾ                                     |
| `SKILLS_SANDBOX_TIMEOUT_MS`       | `10000`          | ਸੈਂਡਬਾਕਸ ਕੀਤੀਆਂ ਕਮਾਂਡਾਂ ਲਈ ਡਿਫਾਲਟ ਟਾਈਮਆਉਟ; ਵੱਧ ਤੋਂ ਵੱਧ 60 s ਤੱਕ ਸੀਮਿਤ        |
| `SKILLS_SANDBOX_NETWORK_ENABLED`  | `false`          | ਇਗ੍ਰੈੱਸ ਲਈ ਮੁੱਖ ਗੇਟ। ਪ੍ਰਤੀ-ਕਾਲ ਔਪਟ-ਇਨ ਦੀ ਆਗਿਆ ਦੇਣ ਲਈ `1` ਜਾਂ `true` ਸੈੱਟ ਕਰੋ |
| `SKILLS_ALLOWED_SANDBOX_IMAGES`   | (ਹੇਠਾਂ ਦੇਖੋ)     | Docker ਇਮੇਜਾਂ ਦੀ ਕਾਮਾ ਨਾਲ ਵੱਖ ਕੀਤੀ ਅਨੁਮਤੀ-ਸੂਚੀ                               |

ਡਿਫਾਲਟ ਮਨਜ਼ੂਰਸ਼ੁਦਾ ਇਮੇਜ: `alpine:3.20`, `node:22-alpine`, `python:3.12-alpine`। `SKILLS_ALLOWED_SANDBOX_IMAGES` ਰਾਹੀਂ ਕੀਤੇ ਗਏ ਸਾਰੇ ਵਾਧੇ ਡਿਫਾਲਟਾਂ ਨਾਲ ਮਿਲਾ ਦਿੱਤੇ ਜਾਂਦੇ ਹਨ; ਅਣਜਾਣ ਇਮੇਜਾਂ ਨੂੰ `normalizeImage()` ਵੱਲੋਂ ਰੱਦ ਕਰ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ।

> ਨੋਟ: ਕੋਈ ਵੱਖਰਾ `SKILLS_EXECUTION_TIMEOUT_MS` ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲ ਨਹੀਂ ਹੈ। ਗੈਰ-ਸੈਂਡਬਾਕਸ ਹੈਂਡਲਰ ਟਾਈਮਆਉਟ `SkillExecutor` (`executor.ts:13`) ਵਿੱਚ 30 s ਲਈ ਹਾਰਡ-ਕੋਡ ਕੀਤਾ ਹੋਇਆ ਹੈ, ਪਰ ਇਸ ਨੂੰ ਰਨਟਾਈਮ ਦੌਰਾਨ `skillExecutor.setTimeout(ms)` ਰਾਹੀਂ ਓਵਰਰਾਈਡ ਕੀਤਾ ਜਾ ਸਕਦਾ ਹੈ।

### ਵਰਕਸਪੇਸ ਆਈਸੋਲੇਸ਼ਨ

`file_read` ਅਤੇ `file_write` ਹਰ ਪਾਥ ਨੂੰ `<DATA_DIR>/skills/workspaces/<sha256(apiKeyId).slice(0,24)>/` ਉੱਤੇ ਸਥਿਤ ਪ੍ਰਤੀ-API-ਕੁੰਜੀ ਵਰਕਸਪੇਸ ਦੇ ਸਾਪੇਖ ਰਿਜ਼ੌਲਵ ਕਰਦੇ ਹਨ। ਪਾਥ ਟ੍ਰੈਵਰਸਲ (`..`) ਅਤੇ ਮਨਾਹੀ ਕੀਤੇ ਸੈਗਮੈਂਟ (`.env`, `.git`, `.ssh`, `.omniroute`, `.codex`, `secrets`) ਕਿਸੇ ਵੀ ਡਿਸਕ I/O ਤੋਂ ਪਹਿਲਾਂ ਰੱਦ ਕਰ ਦਿੱਤੇ ਜਾਂਦੇ ਹਨ।

### HTTP ਸਖ਼ਤੀਕਰਨ

`http_request` (`builtins.ts:257`):

- ਮੈਥਡ ਅਨੁਮਤੀ-ਸੂਚੀ: `GET, HEAD, POST, PUT, PATCH, DELETE`
- ਬਲੌਕ ਕੀਤੇ ਆਊਟਬਾਊਂਡ ਹੈਡਰ: `host, connection, content-length, cookie, set-cookie, authorization, proxy-authorization`
- ਰੀਡਾਇਰੈਕਟ ਅਸਮਰੱਥ (`allowRedirect: false`)
- `guard: "public-only"` ਨਾਲ `safeOutboundFetch` ਰਾਹੀਂ ਰੂਟ ਕੀਤਾ ਜਾਂਦਾ ਹੈ (ਪ੍ਰਾਈਵੇਟ/ਲੂਪਬੈਕ ਰੇਂਜਾਂ ਬਲੌਕ ਕੀਤੀਆਂ ਜਾਂਦੀਆਂ ਹਨ)
- ਰਿਸਪਾਂਸ ਨੂੰ `SKILLS_MAX_HTTP_RESPONSE_BYTES` ਉੱਤੇ ਕੱਟ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ; ਕਲਾਇੰਟ ਨੂੰ `truncated: true` ਦਿਖਾਈ ਦਿੰਦਾ ਹੈ

## ਹਾਈਬ੍ਰਿਡ ਐਗਜ਼ੀਕਿਊਟਰ (ਪ੍ਰੀਵਿਊ)

`src/lib/skills/hybrid.ts` ਇੱਕ `HybridExecutor` ਪਰਿਭਾਸ਼ਿਤ ਕਰਦਾ ਹੈ, ਜੋ ਹਰ ਕਾਲ ਲਈ `direct` (ਇਨ-ਪ੍ਰੋਸੈਸ) ਅਤੇ `sandbox` ਐਗਜ਼ੀਕਿਊਸ਼ਨ ਵਿਚਕਾਰ ਫ਼ੈਸਲਾ ਕਰਦਾ ਹੈ, ਅਤੇ ਟਾਈਮਆਉਟ/ਮੈਮੋਰੀ ਗਲਤੀਆਂ ਦੀ ਸਥਿਤੀ ਵਿੱਚ `autoUpgrade` ਰੀਟ੍ਰਾਈ ਪਾਥ ਵਰਤਦਾ ਹੈ। ਵਾਇਰ ਕੀਤੀਆਂ `directExecutor` / `sandboxRunner` ਇੰਪਲੀਮੈਂਟੇਸ਼ਨਾਂ ਸਟੱਬ ਹਨ (`executeDirect`, `executeInSandbox` ਪਲੇਸਹੋਲਡਰ ਆਬਜੈਕਟ ਵਾਪਸ ਕਰਦੇ ਹਨ) — ਇਸ ਮੋਡੀਊਲ ਨੂੰ ਨਿਰਮਾਣ ਅਧੀਨ ਕਾਂਟ੍ਰੈਕਟ ਵਜੋਂ ਮੰਨੋ। ਅਸਲ ਐਗਜ਼ੀਕਿਊਸ਼ਨ ਅਜੇ ਵੀ `skillExecutor` + `SandboxRunner` ਰਾਹੀਂ ਹੁੰਦਾ ਹੈ।

| `/api/skills/marketplace` | GET | SkillsMP ਕੈਟਾਲਾਗ ਵਿੱਚ ਖੋਜ ਕਰੋ (`q` ਖਾਲੀ ਹੋਣ ਉੱਤੇ ਪ੍ਰਸਿੱਧ ਡਿਫਾਲਟ ਵਾਪਸ ਕਰਦਾ ਹੈ) |
| `/api/skills/marketplace/install` | POST | ਇੱਕ SkillsMP ਸਕਿੱਲ ਇੰਸਟਾਲ ਕਰੋ (ਸਰਗਰਮ ਪ੍ਰਦਾਤਾ = `skillsmp` ਹੋਣਾ ਲਾਜ਼ਮੀ ਹੈ) |
| `/api/skills/skillssh` | GET | skills.sh ਕੈਟਾਲਾਗ ਵਿੱਚ ਖੋਜ ਕਰੋ (`?q=&limit=`, ਵੱਧ ਤੋਂ ਵੱਧ 100) |
| `/api/skills/skillssh/install` | POST | ਇੱਕ skills.sh ਸਕਿੱਲ ਇੰਸਟਾਲ ਕਰੋ (ਸਰਗਰਮ ਪ੍ਰਦਾਤਾ = `skillssh` ਹੋਣਾ ਲਾਜ਼ਮੀ ਹੈ) |
| `/api/skills/executions` | GET | ਪੇਜੀਨੇਟ ਕੀਤਾ ਐਗਜ਼ੀਕਿਊਸ਼ਨ ਇਤਿਹਾਸ (`?apiKeyId=`) |
| `/api/skills/executions` | POST | ਇੱਕ ਰਜਿਸਟਰ ਕੀਤੀ ਸਕਿੱਲ ਨੂੰ ਐਡ-ਹੌਕ ਢੰਗ ਨਾਲ ਚਲਾਓ |

ਜਦੋਂ `settings.skillsEnabled === false` ਹੁੰਦਾ ਹੈ, ਤਾਂ `POST /api/skills/executions` ਐਂਡਪੌਇੰਟ HTTP `503` ਦੇ ਨਾਲ `{ error: "ਸਕਿੱਲ ਐਗਜ਼ੀਕਿਊਸ਼ਨ ਅਸਮਰੱਥ ਹੈ..." }` ਵਾਪਸ ਕਰਦਾ ਹੈ (`executor.ts:42-45`)। ਓਪਰੇਟਰ **ਸੈਟਿੰਗਾਂ → AI** ਤੋਂ ਮਾਸਟਰ ਸਵਿੱਚ ਬਦਲ ਸਕਦੇ ਹਨ।

### ਉਦਾਹਰਨ: ਇੱਕ ਕਸਟਮ ਸਕਿੱਲ ਇੰਸਟਾਲ ਕਰੋ

```bash
curl -X POST http://localhost:20128/api/skills/install \
  -H "Authorization: Bearer $OMNIROUTE_MGMT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "reverse-text",
    "version": "1.0.0",
    "description": "ਇੱਕ ਸਟ੍ਰਿੰਗ ਨੂੰ ਉਲਟਾਉਂਦਾ ਹੈ",
    "schema": {
      "input":  { "type": "object", "properties": { "text": { "type": "string" } }, "required": ["text"] },
      "output": { "type": "object", "properties": { "reversed": { "type": "string" } } }
    },
    "handlerCode": "echo-handler",
    "apiKeyId": "your-api-key-id"
  }'
```

`handlerCode` ਸਟ੍ਰਿੰਗ ਇੱਕ **ਹੈਂਡਲਰ ਨਾਮ ਲੁੱਕਅੱਪ** ਹੈ — ਚਲਾਇਆ ਜਾ ਸਕਣ ਵਾਲਾ ਕੋਡ ਨਹੀਂ। ਐਗਜ਼ੀਕਿਊਟਰ ਇਸਨੂੰ `skillExecutor.registerHandler(name, fn)` (`executor.ts:25`) ਰਾਹੀਂ ਮੈਪ ਕਰਦਾ ਹੈ। ਮਾਰਕੀਟਪਲੇਸ ਇੰਸਟਾਲ ਇਸ ਫ਼ੀਲਡ ਵਿੱਚ SKILL.md ਟੈਕਸਟ ਨੂੰ ਦਸਤਾਵੇਜ਼ੀਕਰਨ ਵਜੋਂ ਸਟੋਰ ਕਰਦੇ ਹਨ ਅਤੇ ਐਗਜ਼ੀਕਿਊਸ਼ਨ ਨੂੰ ਮਾਡਲ ਦੁਆਰਾ ਤਿਆਰ ਕੀਤੀਆਂ ਟੂਲ ਕਾਲਾਂ ਰਾਹੀਂ ਰੂਟ ਕਰਦੇ ਹਨ। ਯੂਜ਼ਰ ਵੱਲੋਂ ਦਿੱਤੇ ਕਿਸੇ ਵੀ ਮਨਮਾਨੇ ਸੋਰਸ ਨੂੰ eval ਨਹੀਂ ਕੀਤਾ ਜਾਂਦਾ।

## ਨਵੀਂ ਬਿਲਟ-ਇਨ ਸਕਿੱਲ ਸ਼ਾਮਲ ਕਰਨਾ

4. **ਨੈੱਟਵਰਕ ਕਾਲ?** `guard: "public-only"` ਨਾਲ `safeOutboundFetch` ਵਰਤੋ; `sanitizeHeaders()` ਰਾਹੀਂ ਹੈਡਰ ਸੈਨਿਟਾਈਜ਼ ਕਰੋ।
5. **ਰਜਿਸਟਰ ਕਰੋ** `builtinSkills` ਵਿੱਚ ਐਂਟਰੀ ਜੋੜ ਕੇ (ਜਾਂ ਬੂਟ ਵੇਲੇ `registerBrowserSkill(executor)`-ਸ਼ੈਲੀ ਵਿੱਚ ਕਾਲ ਕਰਕੇ)।
6. **ਬਿਲਟ-ਇਨ ਟੂਲ ਉਪਨਾਮ ਵਾਇਰ ਕਰੋ** (ਵਿਕਲਪਿਕ) `BUILTIN_TOOL_ALIASES` (`interception.ts:23`) ਵਿੱਚ, ਜੇ ਅੱਪਸਟ੍ਰੀਮ ਮਾਡਲ ਕੋਈ ਵੱਖਰਾ ਨਾਮ ਨਿਕਲਦਾ ਹੈ।
7. **ਟੈਸਟ** `src/lib/skills/__tests__/` ਵਿੱਚ (Vitest)।

## ਕਾਰਜਕਾਰੀ ਸੁਝਾਅ

- **ਮਾਸਟਰ ਸਵਿੱਚ:** `settings.skillsEnabled = false` ਸਾਰੇ ਐਗਜ਼ੀਕਿਊਸ਼ਨ ਰੋਕਦਾ ਹੈ ਅਤੇ `/api/skills/executions` ਉੱਤੇ HTTP `503` ਵਾਪਸ ਕਰਦਾ ਹੈ। ਰਜਿਸਟਰੀ ਲੋਡ ਹੁੰਦੀ ਰਹਿੰਦੀ ਹੈ।
- **ਇਗ੍ਰੈੱਸ ਨੂੰ ਲੌਕ ਡਾਊਨ ਕਰੋ:** ਪੂਰੀ ਤਰ੍ਹਾਂ ਏਅਰ-ਗੈਪਡ ਸੈਂਡਬਾਕਸਿੰਗ ਲਈ `SKILLS_SANDBOX_NETWORK_ENABLED` ਨੂੰ ਅਣਸੈੱਟ (ਡਿਫਾਲਟ) ਰੱਖੋ। ਪ੍ਰਤੀ-ਕਾਲ `networkEnabled: true` ਲਈ ਵੀ ਮਾਸਟਰ ਗੇਟ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ।
- **ਖਾਸ ਇਮੇਜਾਂ ਦੀ ਆਗਿਆ ਦਿਓ:** ਅਲਾਊਲਿਸਟ ਨੂੰ ਵਧਾਉਣ ਲਈ `SKILLS_ALLOWED_SANDBOX_IMAGES="myorg/sandbox:1.0,node:22-alpine"` ਸੈੱਟ ਕਰੋ।
- **ਐਗਜ਼ੀਕਿਊਸ਼ਨਾਂ ਦਾ ਆਡਿਟ ਕਰੋ:** `/dashboard/skills/executions` ਅਤੇ `omniroute_skills_executions` ਦੋਵੇਂ `skill_executions` ਨੂੰ ਕਵੇਰੀ ਕਰਦੇ ਹਨ। ਸਫਲ ਰਨਾਂ ਵਿੱਚ `durationMs` ਸ਼ਾਮਲ ਹੁੰਦਾ ਹੈ; ਅਸਫਲਤਾਵਾਂ ਵਿੱਚ `errorMessage` ਸ਼ਾਮਲ ਹੁੰਦਾ ਹੈ।
- **ਕੈਸ਼ ਇਨਵੈਲੀਡੇਸ਼ਨ:** ਮੈਨੁਅਲ DB ਸੋਧਾਂ ਤੋਂ ਬਾਅਦ `skillRegistry.invalidateCache()` ਕਾਲ ਕਰੋ; ਨਹੀਂ ਤਾਂ 60 s ਉਡੀਕ ਕਰੋ।
- **ਅਗਿਆਤ ਵਰਕਸਪੇਸ:** ਜਦੋਂ `apiKeyId` ਖਾਲੀ ਹੋਵੇ, ਸਾਰੀਆਂ ਕਾਲਾਂ ਇੱਕੋ `"anonymous"` ਵਰਕਸਪੇਸ ਵਿੱਚ ਹੈਸ਼ ਹੁੰਦੀਆਂ ਹਨ — ਸ਼ੇਅਰ-ਅਵੇਅਰ ਕੋਡ ਨੂੰ ਹਮੇਸ਼ਾ ਇੱਕ ਅਸਲੀ ਕੀ ਪਾਸ ਕਰਨੀ ਚਾਹੀਦੀ ਹੈ।

## ਐਗਜ਼ਿਕਿਊਸ਼ਨ ਲਾਈਫਸਾਈਕਲ (v3.8.16+)

`SkillExecutor` (`src/lib/skills/executor.ts`) ਇੱਕ **ਸਿੰਗਲਟਨ** ਹੈ ਜੋ ਹਰ ਸਕਿੱਲ ਇਨਵੋਕੇਸ਼ਨ ਦਾ ਪ੍ਰਬੰਧਨ ਕਰਦਾ ਹੈ। ਟਾਈਮਆਉਟਾਂ, ਮੁੜ-ਕੋਸ਼ਿਸ਼ਾਂ ਅਤੇ ਐਗਜ਼ਿਕਿਊਸ਼ਨ ਸਥਿਤੀ ਨੂੰ ਡੀਬੱਗ ਕਰਨ ਲਈ ਇਸਦੇ ਲਾਈਫਸਾਈਕਲ ਨੂੰ ਸਮਝਣਾ ਬਹੁਤ ਮਹੱਤਵਪੂਰਨ ਹੈ।

### 5-ਪੜਾਅ ਵਾਲਾ ਲਾਈਫਸਾਈਕਲ

```
   execute() ਨੂੰ ਕਾਲ ਕੀਤਾ ਗਿਆ
        │
        ▼
  ┌─────────────┐
  │  PENDING    │  ← ਕਤਾਰ ਵਿੱਚ, ਹਾਲੇ ਸ਼ੁਰੂ ਨਹੀਂ ਹੋਇਆ (DB ਕਤਾਰ ਬਣਾਈ ਗਈ)
  └──────┬──────┘
         │ ਹੈਂਡਲਰ ਸ਼ੁਰੂ ਕਰੋ
         ▼
  ┌─────────────┐
  │  RUNNING    │  ← ਹੈਂਡਲਰ ਨੂੰ ਟਾਈਮਆਉਟ ਨਾਲ ਇਨਵੋਕ ਕੀਤਾ ਗਿਆ
  └──────┬──────┘
         │
    ┌────┴────┬──────────┬──────────┐
    │         │          │          │
    ▼         ▼          ▼          ▼
  SUCCESS   ERROR     TIMEOUT   (ਕੋਈ ਹੋਰ ਮਾਰਗ ਨਹੀਂ — ਪੇਰੈਂਟ ਵੱਲੋਂ ਬੰਦ ਕੀਤਾ ਗਿਆ)
    │         │          │
    └────┬────┴──────────┘
         │
         ▼
   DB ਕਤਾਰ ਨੂੰ ਸਥਿਤੀ, ਆਉਟਪੁੱਟ, durationMs ਨਾਲ ਅੱਪਡੇਟ ਕੀਤਾ ਗਿਆ
```

### ਡਿਫਾਲਟ ਸੰਰਚਨਾ

| ਸੈਟਿੰਗ       | ਡਿਫਾਲਟ        | ਇਸ ਰਾਹੀਂ ਸੰਰਚਨਾਯੋਗ                   |
| ------------ | ------------- | ------------------------------------ |
| `timeout`    | `30000` (30s) | `skillExecutor.setTimeout(ms)`       |
| `maxRetries` | `3`           | `skillExecutor.setMaxRetries(count)` |

> **ਮਹੱਤਵਪੂਰਨ**: ਐਗਜ਼ਿਕਿਊਟਰ ਇੱਕ ਸਿੰਗਲਟਨ ਹੈ — `setTimeout()` ਨੂੰ ਕਾਲ ਕਰਨਾ ਗਲੋਬਲ ਤੌਰ 'ਤੇ ਬਾਅਦ ਦੀਆਂ ਸਾਰੀਆਂ ਇਨਵੋਕੇਸ਼ਨਾਂ ਨੂੰ ਪ੍ਰਭਾਵਿਤ ਕਰਦਾ ਹੈ। ਪ੍ਰਤੀ-ਸਕਿੱਲ ਟਾਈਮਆਉਟ ਇਸ ਵੇਲੇ ਸਮਰਥਿਤ ਨਹੀਂ ਹਨ; ਜੇ ਤੁਹਾਨੂੰ ਹਰ ਸਕਿੱਲ ਲਈ ਵੱਖਰੇ ਟਾਈਮਆਉਟਾਂ ਦੀ ਲੋੜ ਹੈ, ਤਾਂ ਵੱਖਰੀਆਂ ਪ੍ਰਕਿਰਿਆਵਾਂ ਸਬਮਿਟ ਕਰੋ ਜਾਂ ਐਗਜ਼ਿਕਿਊਟਰ ਨੂੰ ਫੋਰਕ ਕਰੋ।

### ਸਥਿਤੀ ਮੁੱਲ

`src/lib/skills/types.ts` ਤੋਂ:

```ts
enum SkillStatus {
  PENDING = "pending", // ਕਤਾਰ ਵਿੱਚ, ਹਾਲੇ ਸ਼ੁਰੂ ਨਹੀਂ ਹੋਇਆ
  RUNNING = "running", // ਹੈਂਡਲਰ ਨੂੰ ਇਨਵੋਕ ਕੀਤਾ ਗਿਆ
  SUCCESS = "success", // ਹੈਂਡਲਰ ਨੇ ਵੈਧ ਆਉਟਪੁੱਟ ਵਾਪਸ ਕੀਤਾ
  ERROR = "error", // ਹੈਂਡਲਰ ਨੇ ਇੱਕ ਐਕਸੈਪਸ਼ਨ ਥ੍ਰੋ ਕੀਤਾ
  TIMEOUT = "timeout", // ਐਗਜ਼ਿਕਿਊਟਰ ਦਾ ਟਾਈਮਆਉਟ ਪਾਰ ਹੋ ਗਿਆ
}
```

> **ਨੋਟ**: `TIMEOUT` ਸਥਿਤੀ ਨੂੰ enum ਵਿੱਚ ਪਰਿਭਾਸ਼ਿਤ ਕੀਤਾ ਗਿਆ ਹੈ, ਪਰ ਮੌਜੂਦਾ ਐਗਜ਼ਿਕਿਊਟਰ ਇੰਪਲੀਮੈਂਟੇਸ਼ਨ ਦੁਆਰਾ ਇਸਨੂੰ **ਅਸਲ ਵਿੱਚ DB ਵਿੱਚ ਨਹੀਂ ਲਿਖਿਆ ਜਾਂਦਾ** — ਟਾਈਮਆਉਟ `"Skill execution timed out"` ਸੁਨੇਹੇ ਨਾਲ `ERROR` ਵਜੋਂ ਸਾਹਮਣੇ ਆਉਂਦੇ ਹਨ। ਸਥਿਤੀ enum ਭਵਿੱਖੀ ਵਰਤੋਂ ਲਈ ਰਾਖਵਾਂ ਹੈ।

### ਐਗਜ਼ਿਕਿਊਸ਼ਨਾਂ ਦੀ ਜਾਂਚ ਕਰਨਾ

```ts
import { skillExecutor } from "omniroute/skills/executor";

// ID ਰਾਹੀਂ ਇੱਕ ਖਾਸ ਐਗਜ਼ਿਕਿਊਸ਼ਨ ਪ੍ਰਾਪਤ ਕਰੋ
const exec = skillExecutor.getExecution("exec-uuid-123");
if (exec) {
  console.log(`${exec.skillName}: ${exec.status} in ${exec.durationMs}ms`);
}

// ਇੱਕ API ਕੁੰਜੀ ਲਈ ਹਾਲੀਆ ਐਗਜ਼ਿਕਿਊਸ਼ਨਾਂ ਦੀ ਸੂਚੀ ਪ੍ਰਾਪਤ ਕਰੋ
const recent = skillExecutor.listExecutions("api-key-id", 50, 0);
for (const e of recent) {
  console.log(`${e.skillName} → ${e.status} (${e.durationMs}ms)`);
}

// ਕੁੱਲ ਐਗਜ਼ਿਕਿਊਸ਼ਨਾਂ ਦੀ ਗਿਣਤੀ ਕਰੋ
const total = skillExecutor.countExecutions("api-key-id");
```

### ਮੁੜ-ਕੋਸ਼ਿਸ਼ ਦਾ ਵਿਵਹਾਰ

`maxRetries` ਸੈਟਿੰਗ ਨੂੰ ਸਟੋਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਪਰ ਐਗਜ਼ਿਕਿਊਟਰ ਦੀ `execute()` ਵਿਧੀ ਇਸ ਵੇਲੇ ਇਸਦੀ **ਵਰਤੋਂ ਨਹੀਂ ਕਰਦੀ** — ਇਹ ਸਿਰਫ਼ ਇੱਕ ਹੀ ਕੋਸ਼ਿਸ਼ ਕਰਦੀ ਹੈ। `maxRetries` ਮੁੱਲ ਨੂੰ ਭਵਿੱਖੀ ਇੰਪਲੀਮੈਂਟੇਸ਼ਨ ਅਤੇ ਇਸਨੂੰ ਪੜ੍ਹਨ ਵਾਲੇ ਹੁੱਕਾਂ ਲਈ ਉਪਲਬਧ ਕਰਵਾਇਆ ਗਿਆ ਹੈ।

ਫਿਲਹਾਲ, ਮੁੜ-ਕੋਸ਼ਿਸ਼ਾਂ ਨੂੰ ਸਕਿੱਲ ਹੈਂਡਲਰ ਦੇ ਅੰਦਰ ਹੀ ਇੰਪਲੀਮੈਂਟ ਕਰਨਾ ਲਾਜ਼ਮੀ ਹੈ। ਬਿਲਟ-ਇਨ
ਸਕਿੱਲਾਂ ਨੂੰ ਐਗਜ਼ਿਕਿਊਟਰ ਨਾਲ ਰਜਿਸਟਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ (ਜਿਵੇਂ ਕਿ `registerBuiltinSkills(executor)`
/ `registerBrowserSkill(executor)` `src/lib/skills/builtin/` ਵਿੱਚ); ਤੁਸੀਂ ਜੋ ਵੀ ਹੈਂਡਲਰ
ਰਜਿਸਟਰ ਕਰਦੇ ਹੋ, ਉਹ ਆਪਣੇ ਮੁੜ-ਕੋਸ਼ਿਸ਼ ਲੂਪ ਨੂੰ ਰੈਪ ਕਰ ਸਕਦਾ ਹੈ:

```ts
// ਇੱਕ ਸਕਿੱਲ ਹੈਂਡਲਰ ਦੇ ਅੰਦਰ
async function handler(input, ctx) {
  const maxRetries = 3;
  let lastError: Error | null = null;

  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      return await fetchSomething(input);
    } catch (err) {
      lastError = err as Error;
      if (attempt < maxRetries) {
        await new Promise((r) => setTimeout(r, 1000 * attempt));
      }
    }
  }
  throw lastError;
}
```

## SkillMode ਦਾ ਵਿਸਤ੍ਰਿਤ ਵੇਰਵਾ

`SkillMode` enum (`src/lib/skills/types.ts`) ਇਹ ਨਿਯੰਤਰਿਤ ਕਰਦਾ ਹੈ ਕਿ ਹੁਨਰਾਂ ਨੂੰ **ਕਦੋਂ ਅਤੇ ਕਿਵੇਂ** ਸੱਦਿਆ ਜਾਂਦਾ ਹੈ:

```ts
enum SkillMode {
  AUTO = "auto", // LLM ਫ਼ੈਸਲਾ ਕਰਦਾ ਹੈ ਕਿ ਹੁਨਰ ਨੂੰ ਕਦੋਂ ਸੱਦਣਾ ਹੈ
  MANUAL = "manual", // ਸਿਰਫ਼ ਵਰਤੋਂਕਾਰ ਦੀ ਸਪਸ਼ਟ ਬੇਨਤੀ ਦੁਆਰਾ ਸੱਦਿਆ ਜਾਂਦਾ ਹੈ
  HYBRID = "hybrid", // AUTO ਸਕੋਰਿੰਗ + ਮੈਨੂਅਲ ਓਵਰਰਾਈਡ
}
```

> **ਨੋਟ**: ਕੋਡਬੇਸ `SkillMode` (AUTO/MANUAL/HYBRID) ਨੂੰ ਪਰਿਭਾਸ਼ਿਤ ਕਰਦਾ ਹੈ, ਜਦਕਿ `Skill.mode` ਫ਼ੀਲਡ ਇੱਕ ਵੱਖਰੀ ਬਣਤਰ (`"on" | "off" | "auto"`) ਵਰਤਦੀ ਹੈ। ਇਹ ਆਪਸ ਵਿੱਚ ਸੰਬੰਧਿਤ ਹਨ ਪਰ ਇੱਕੋ ਜਿਹੇ ਨਹੀਂ ਹਨ — `SkillMode` ਐਗਜ਼ੀਕਿਊਟਰ ਨੀਤੀ ਲਈ ਹੈ, ਜਦਕਿ `Skill.mode` ਹਰ ਹੁਨਰ ਨੂੰ ਵੱਖਰੇ ਤੌਰ 'ਤੇ ਸਮਰੱਥ ਕਰਨ ਲਈ ਹੈ।

### ਹਰੇਕ ਮੋਡ ਕਦੋਂ ਵਰਤਣਾ ਹੈ

| ਮੋਡ      | LLM ਦਾ ਵਿਹਾਰ                                                                         | ਵਰਤੋਂ ਦਾ ਮਾਮਲਾ                                            |
| -------- | ------------------------------------------------------------------------------------ | --------------------------------------------------------- |
| `AUTO`   | ਜਦੋਂ LLM ਲੋੜੀਂਦਾ ਸਮਝੇ, ਤਾਂ ਉਹ ਹੁਨਰ ਨੂੰ ਸੱਦ ਸਕਦਾ ਹੈ                                   | ਆਮ-ਮਕਸਦ ਵਾਲੇ ਹੁਨਰ (ਫ਼ਾਈਲ ਪੜ੍ਹਨਾ, HTTP ਬੇਨਤੀਆਂ)            |
| `MANUAL` | LLM ਹੁਨਰ ਨੂੰ ਨਹੀਂ ਸੱਦ ਸਕਦਾ; ਸਿਰਫ਼ ਇੱਕ ਸਪਸ਼ਟ `executeSkill` API ਕਾਲ ਹੀ ਇਸਨੂੰ ਸੱਦਦੀ ਹੈ | ਸੰਵੇਦਨਸ਼ੀਲ ਕਾਰਵਾਈਆਂ (ਡਾਟਾਬੇਸ ਵਿੱਚ ਲਿਖਣਾ, ਭੁਗਤਾਨ)          |
| `HYBRID` | LLM ਹੁਨਰ ਦਾ ਸੁਝਾਅ ਦੇ ਸਕਦਾ ਹੈ; ਵਰਤੋਂਕਾਰ ਨੂੰ ਪੁਸ਼ਟੀ ਕਰਨੀ ਲਾਜ਼ਮੀ ਹੈ                     | ਅਜਿਹੇ ਹੁਨਰ ਜਿਨ੍ਹਾਂ ਦੇ ਸਾਈਡ ਇਫੈਕਟ ਹਨ ਪਰ ਉਹ ਖ਼ਤਰਨਾਕ ਨਹੀਂ ਹਨ |

### AUTO ਸਕੋਰਿੰਗ

ਜਦੋਂ `AUTO` ਮੋਡ ਸਰਗਰਮ ਹੁੰਦਾ ਹੈ, ਤਾਂ ਹਰੇਕ ਉਮੀਦਵਾਰ ਹੁਨਰ ਨੂੰ ਬੇਨਤੀ ਦੇ ਸੰਦਰਭ ਦੇ ਮੁਕਾਬਲੇ
`src/lib/skills/injection.ts` ਵਿੱਚ ਮੌਜੂਦ `scoreAutoSkill()` ਦੁਆਰਾ ਸਕੋਰ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ — ਇਹ ਇੱਕ ਜੋੜਾਤਮਕ,
ਪੂਰਨ-ਅੰਕ ਪ੍ਰਣਾਲੀ ਹੈ (ਹੁਨਰ-ਨਾਮ ਮਿਲਾਨ, ਨਾਮ/ਟੈਗ/ਵੇਰਵਾ ਟੋਕਨ ਓਵਰਲੈਪ,
ਬੈਕਗ੍ਰਾਊਂਡ-ਕਾਰਨ ਸੰਕੇਤ, ਪ੍ਰੋਵਾਈਡਰ-ਸੰਕੇਤ ਬੋਨਸ/ਜੁਰਮਾਨਾ)। ਸਭ ਤੋਂ ਵੱਧ ਸਕੋਰ ਵਾਲੇ
`AUTO_MAX_SKILLS = 5` ਹੁਨਰ, ਜਿਨ੍ਹਾਂ ਦਾ `score >= AUTO_MIN_SCORE = 3` ਹੈ, ਕਾਲ ਕੀਤੇ ਜਾ ਸਕਣ ਵਾਲੇ
ਟੂਲਾਂ ਵਜੋਂ ਇੰਜੈਕਟ ਕੀਤੇ ਜਾਂਦੇ ਹਨ; ਬਰਾਬਰ ਸਕੋਰ ਹੋਣ 'ਤੇ ਪਹਿਲਾਂ `installCount` ਅਤੇ ਫਿਰ ਨਾਮ ਅਨੁਸਾਰ ਫ਼ੈਸਲਾ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। ਪੂਰੀ ਅੰਕ ਸਾਰਣੀ ਲਈ ਇਸ
ਦਸਤਾਵੇਜ਼ ਵਿੱਚ ਪਹਿਲਾਂ ਦਿੱਤਾ [**ਟੂਲ ਸਕੀਮਾ ਜਨਰੇਸ਼ਨ → AUTO ਸਕੋਰਿੰਗ**](#auto-scoring)
ਵੇਖੋ; ਇੱਥੇ ਕੋਈ ਫ਼ਲੋਟ `0.6`-ਸ਼ੈਲੀ ਥ੍ਰੈਸ਼ਹੋਲਡ ਅਤੇ ਕੋਈ `registry.ts` ਸਕੋਰਿੰਗ ਨਹੀਂ ਹੈ।

## ਬਿਲਟ-ਇਨ ਹੁਨਰਾਂ ਦਾ ਕੈਟਾਲਾਗ

OmniRoute ਵਿੱਚ `src/lib/skills/builtin/` ਦੇ ਅੰਦਰ ਬਿਲਟ-ਇਨ ਹੁਨਰਾਂ ਦਾ ਇੱਕ ਚੁਣਿਆ ਹੋਇਆ ਸੈੱਟ ਸ਼ਾਮਲ ਹੈ। ਸਭ ਤੋਂ ਆਮ ਇਹ ਹਨ:

### ਬ੍ਰਾਊਜ਼ਰ ਆਟੋਮੇਸ਼ਨ ਹੁਨਰ

ਬ੍ਰਾਊਜ਼ਰ ਹੁਨਰ (`src/lib/skills/builtin/browser.ts`) Playwright/Puppeteer ਰਾਹੀਂ ਹੈੱਡਲੈੱਸ ਬ੍ਰਾਊਜ਼ਰ ਆਟੋਮੇਸ਼ਨ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ। **ਇਸਨੂੰ ਲਾਗੂ ਕੀਤਾ ਗਿਆ ਹੈ, ਪਰ ਇਹ ਡਿਫ਼ਾਲਟ ਹੁਨਰ ਕੈਟਾਲਾਗ ਵਿੱਚ ਸ਼ਾਮਲ ਨਹੀਂ ਹੈ** — ਇਸਦੀ ਵਰਤੋਂ ਕਰਨ ਲਈ, ਬ੍ਰਾਊਜ਼ਰ ਐਕਸਟੈਂਸ਼ਨ ਪਲੱਗਇਨ ਨੂੰ ਵੱਖਰੇ ਤੌਰ 'ਤੇ ਇੰਸਟਾਲ ਕਰੋ।

```ts
// ਆਪਣੀ ਸੰਰਚਨਾ ਵਿੱਚ ਸਮਰੱਥ ਕਰੋ
const config: SkillConfig = {
  enabled: true,
  mode: SkillMode.MANUAL, // ਹਮੇਸ਼ਾ ਸਪਸ਼ਟ ਇਨਵੋਕੇਸ਼ਨ ਦੀ ਲੋੜ ਰੱਖੋ
  allowedSkills: ["browser"],
  timeout: 60000, // ਪੰਨਾ ਲੋਡ ਹੋਣ ਲਈ 60s
  maxRetries: 1,
};
```

### ਹੋਰ ਬਿਲਟ-ਇਨ ਸ਼੍ਰੇਣੀਆਂ

| ਸ਼੍ਰੇਣੀ         | ਹੁਨਰ                                              | ਮੋਡ    |
| --------------- | ------------------------------------------------- | ------ |
| ਫ਼ਾਈਲ I/O       | `file_read`, `file_write`                         | AUTO   |
| HTTP            | `http_request`                                    | AUTO   |
| ਖੋਜ             | `web_search`                                      | AUTO   |
| ਕੋਡ ਐਗਜ਼ੀਕਿਊਸ਼ਨ | `eval_code` (ਸੈਂਡਬਾਕਸ ਕੀਤਾ JavaScript/Python)     | HYBRID |
| ਸਿਸਟਮ           | `execute_command` (ਸੈਂਡਬਾਕਸ ਕੀਤਾ CLI ਐਗਜ਼ੀਕਿਊਸ਼ਨ) | MANUAL |

### ਇੱਕ ਕਸਟਮ ਹੁਨਰ ਸ਼ਾਮਲ ਕਰਨਾ

ਪਲੱਗਇਨ ਸਿਸਟਮ ਰਾਹੀਂ ਕਸਟਮ ਹੁਨਰ ਸ਼ਾਮਲ ਕਰਨ ਦੇ ਤਰੀਕੇ ਲਈ [ਪਲੱਗਇਨ SDK ਅਤੇ ਹੁਨਰ ਇੰਟੀਗ੍ਰੇਸ਼ਨ](./PLUGIN_SDK.md) ਵੇਖੋ।
