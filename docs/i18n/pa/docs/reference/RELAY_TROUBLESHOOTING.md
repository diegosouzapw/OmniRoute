ਰੀਲੇ (Vercel, Deno, Cloudflare) ਸਰਵਰਲੈੱਸ ਬੈਕਐਂਡ ਉੱਤੇ ਅੱਪਸਟ੍ਰੀਮ ਕਨੈਕਸ਼ਨ ਨੂੰ ਸਮਾਪਤ ਕਰਦੇ ਹਨ, ਤਾਂ ਜੋ OmniRoute ਪ੍ਰਦਾਤਾ API ਕੁੰਜੀ ਨੂੰ ਸਰਵਰ-ਸਾਈਡ ਰੱਖਦਿਆਂ ਇੱਕ ਸਥਿਰ ਖੇਤਰ ਤੋਂ ਆਊਟਬਾਊਂਡ ਟ੍ਰੈਫਿਕ ਭੇਜ ਸਕੇ। ਇਹ ਦਸਤਾਵੇਜ਼ ਉਹਨਾਂ ਦੋ ਅਸਫਲਤਾ ਮੋਡਾਂ ਅਤੇ ਹਰੇਕ ਲਈ OmniRoute ਵੱਲੋਂ ਦਿੱਤੇ ਰਿਕਵਰੀ ਮਾਰਗਾਂ ਨੂੰ ਕਵਰ ਕਰਦਾ ਹੈ, ਜਿਨ੍ਹਾਂ ਦਾ ਓਪਰੇਟਰਾਂ ਨੂੰ ਪ੍ਰੋਡਕਸ਼ਨ ਵਿੱਚ ਸਾਹਮਣਾ ਕਰਨਾ ਪੈਂਦਾ ਹੈ।

## ਰੀਲੇ ਪ੍ਰਮਾਣੀਕਰਨ ਕਿਵੇਂ ਸਟੋਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ

ਜਦੋਂ ਤੁਸੀਂ **Settings → Proxy Pool → Deploy Relay** ਤੋਂ ਕੋਈ ਰੀਲੇ ਡਿਪਲੌਇ ਕਰਦੇ ਹੋ, ਤਾਂ ਡਿਪਲੌਇ ਪ੍ਰਵਾਹ ਰੀਲੇ ਦੇ ਪ੍ਰਮਾਣੀਕਰਨ ਟੋਕਨ ਨੂੰ ਪ੍ਰੌਕਸੀ ਦੇ `notes` JSON ਫ਼ੀਲਡ ਵਿੱਚ ਸਟੋਰ ਕਰਦਾ ਹੈ:

- ਜੇ `STORAGE_ENCRYPTION_KEY` ਸੈੱਟ ਹੈ, ਤਾਂ ਟੋਕਨ ਨੂੰ `relayAuthEnc` ਵਜੋਂ ਲਿਖਿਆ ਜਾਂਦਾ ਹੈ
  (ਸਟੋਰੇਜ ਵਿੱਚ AES ਨਾਲ ਇਨਕ੍ਰਿਪਟ ਕੀਤਾ ਹੋਇਆ)।
- ਨਹੀਂ ਤਾਂ ਇਸਨੂੰ ਪਲੇਨਟੈਕਸਟ `relayAuth` ਵਜੋਂ ਲਿਖਿਆ ਜਾਂਦਾ ਹੈ।

ਬੇਨਤੀ ਦੇ ਸਮੇਂ `extractRelayAuth(notes)` ਮੌਜੂਦ ਰੂਪ ਵਿੱਚੋਂ ਜੋ ਵੀ ਉਪਲਬਧ ਹੋਵੇ, ਉਹ ਵਾਪਸ ਕਰਦਾ ਹੈ, ਇਸ ਲਈ ਰੀਲੇ ਰੀਸਟਾਰਟਾਂ ਤੋਂ ਬਾਅਦ ਵੀ ਕੰਮ ਕਰਦਾ ਰਹਿੰਦਾ ਹੈ।

## ਅਸਫਲਤਾ ਮੋਡ 1 — ਕੁੰਜੀ ਰੋਟੇਸ਼ਨ ਤੋਂ ਬਾਅਦ ਡਿਕ੍ਰਿਪਟ ਨਾ ਹੋ ਸਕਣ ਵਾਲਾ ਟੋਕਨ

**ਲੱਛਣ:** ਜੋ ਰੀਲੇ ਪਹਿਲਾਂ ਕੰਮ ਕਰਦੇ ਸਨ, ਹੁਣ `STORAGE_ENCRYPTION_KEY` ਦੀ ਇਨਵਾਇਰਨਮੈਂਟ ਜਾਂ ਸੀਕ੍ਰੇਟ-ਮੈਨੇਜਰ ਰੋਟੇਸ਼ਨ ਤੋਂ ਬਾਅਦ ਅੱਪਸਟ੍ਰੀਮ `401`/ਪ੍ਰਮਾਣੀਕਰਨ ਗਲਤੀਆਂ ਵਾਪਸ ਕਰਦੇ ਹਨ। ਸਟੋਰ ਕੀਤੇ `relayAuthEnc` ਬਲੌਬ ਨੂੰ ਹੁਣ ਡਿਕ੍ਰਿਪਟ ਨਹੀਂ ਕੀਤਾ ਜਾ ਸਕਦਾ, ਇਸ ਲਈ `extractRelayAuth` ਖਾਲੀ ਸਤਰ ਵਾਪਸ ਕਰਦਾ ਹੈ ਅਤੇ ਰੀਲੇ ਕੋਈ ਪ੍ਰਮਾਣੀਕਰਨ ਨਹੀਂ ਭੇਜਦਾ।

**ਰਿਕਵਰੀ — ਉਸੇ ਥਾਂ ਮੁਰੰਮਤ ਕਰੋ (ਮੁੜ ਡਿਪਲੌਇ ਕੀਤੇ ਬਿਨਾਂ):**

1. **Settings → Proxy Pool** ਖੋਲ੍ਹੋ।
2. ਜਿਨ੍ਹਾਂ ਰੀਲੇ ਕਤਾਰਾਂ ਵਿੱਚ ਪ੍ਰਮਾਣੀਕਰਨ ਗੁੰਮ ਹੈ, ਉਹ ਪੀਲਾ `auth missing` ਬੈਜ ਅਤੇ ਇੱਕ
   **Repair** ਬਟਨ ਦਿਖਾਉਂਦੀਆਂ ਹਨ।
3. **Repair** ਉੱਤੇ ਕਲਿੱਕ ਕਰੋ। OmniRoute
   `POST /api/settings/proxies/[id]/repair-relay` ਨੂੰ ਕਾਲ ਕਰਦਾ ਹੈ, ਜੋ:
   - **ਮੌਜੂਦਾ** ਕੁੰਜੀ ਨਾਲ `relayAuthEnc` ਨੂੰ ਡਿਕ੍ਰਿਪਟ ਕਰਦਾ ਹੈ,
   - ਪਲੇਨਟੈਕਸਟ `relayAuth` ਨੂੰ ਮੁੜ `notes` ਵਿੱਚ ਲਿਖਦਾ ਹੈ,
   - `{ repaired: true, mode: "recovered" }` ਵਾਪਸ ਕਰਦਾ ਹੈ।

ਕਿਸੇ ਵੀ ਡਿਪਲੌਇ ਕ੍ਰੈਡੈਂਸ਼ਲ ਨੂੰ ਮੁੜ ਦਰਜ ਕੀਤੇ ਬਿਨਾਂ ਰੀਲੇ ਸੇਵਾ ਦੇਣੀ ਮੁੜ ਸ਼ੁਰੂ ਕਰ ਦਿੰਦਾ ਹੈ।

ਇਹ ਸਿਰਫ਼ ਤਾਂ ਹੀ ਕੰਮ ਕਰਦਾ ਹੈ ਜੇ ਮੌਜੂਦਾ `STORAGE_ENCRYPTION_KEY` ਅਜੇ ਵੀ ਬਲੌਬ ਨੂੰ ਡਿਕ੍ਰਿਪਟ ਕਰ ਸਕਦਾ ਹੋਵੇ। ਜੇ ਤੁਸੀਂ ਮਾਈਗ੍ਰੇਸ਼ਨ **ਤੋਂ ਬਿਨਾਂ** ਕੁੰਜੀ ਰੋਟੇਟ ਕੀਤੀ ਸੀ, ਤਾਂ ਬਲੌਬ ਨੂੰ ਰਿਕਵਰ ਨਹੀਂ ਕੀਤਾ ਜਾ ਸਕਦਾ।

## ਅਸਫਲਤਾ ਮੋਡ 2 — ਰਿਕਵਰ ਨਾ ਹੋ ਸਕਣ ਵਾਲਾ ਟੋਕਨ (ਪੁਰਾਣੀ ਕੁੰਜੀ ਹੁਣ ਉਪਲਬਧ ਨਹੀਂ)

**ਲੱਛਣ:** ਤੁਸੀਂ **Repair** ਉੱਤੇ ਕਲਿੱਕ ਕੀਤਾ ਅਤੇ
`{ repaired: false, mode: "redeploy", status: 409 }` ਪ੍ਰਾਪਤ ਹੋਇਆ।

**ਰਿਕਵਰੀ — ਮੁੜ ਡਿਪਲੌਇ ਕਰੋ:**

ਸਟੋਰ ਕੀਤੇ ਟੋਕਨ ਨੂੰ ਮੌਜੂਦਾ ਕੁੰਜੀ ਨਾਲ ਰਿਕਵਰ ਨਹੀਂ ਕੀਤਾ ਜਾ ਸਕਦਾ। ਰੀਲੇ ਨੂੰ ਉਸੇ ਮੋਡਲ ਤੋਂ ਮੁੜ ਡਿਪਲੌਇ ਕਰੋ ਜੋ ਤੁਸੀਂ ਮੂਲ ਰੂਪ ਵਿੱਚ ਵਰਤਿਆ ਸੀ (**Deploy Relay** ਮੀਨੂ → Vercel / Deno
/ Cloudflare)। ਡਿਪਲੌਇ ਪ੍ਰਵਾਹ ਇੱਕ ਨਵਾਂ ਟੋਕਨ ਲਿਖਦਾ ਹੈ (ਮੌਜੂਦਾ ਕੁੰਜੀ ਨਾਲ ਇਨਕ੍ਰਿਪਟ ਕੀਤਾ ਹੋਇਆ) ਅਤੇ ਕਤਾਰ ਦਾ `auth missing` ਬੈਜ ਹਟ ਜਾਂਦਾ ਹੈ।

UI ਵਿੱਚ, ਜਦੋਂ ਟੋਕਨ ਨੂੰ ਰਿਕਵਰ ਨਹੀਂ ਕੀਤਾ ਜਾ ਸਕਦਾ, ਤਾਂ **Repair** ਬਟਨ ਖੁਦ ਹੀ ਮੁੜ-ਡਿਪਲੌਇ ਮੋਡਲ ਖੋਲ੍ਹ ਦਿੰਦਾ ਹੈ, ਇਸ ਲਈ ਤੁਹਾਨੂੰ ਇਸਨੂੰ ਕਦੇ ਵੀ ਹੱਥੀਂ ਲੱਭਣ ਦੀ ਲੋੜ ਨਹੀਂ ਪੈਂਦੀ।

## ਅਸਫਲਤਾ ਮੋਡ 3 — ਰੀਲੇ ਤੱਕ ਪਹੁੰਚ ਸੰਭਵ ਹੈ ਪਰ ਉਹ ਸਿਹਤਮੰਦ ਨਹੀਂ ਹੈ

**ਲੱਛਣ:** ਪ੍ਰੌਕਸੀ ਟੈਸਟ (`speed` ਬਟਨ) ਰੀਲੇ ਨੂੰ ਚਾਲੂ ਦਿਖਾਉਂਦਾ ਹੈ, ਪਰ ਬੇਨਤੀਆਂ ਫਿਰ ਵੀ ਰੁਕ-ਰੁਕ ਕੇ ਅਸਫਲ ਹੁੰਦੀਆਂ ਹਨ।

OmniRoute ਦੀ ਆਟੋ-ਟੈਸਟ ਪ੍ਰੋਬ ਵੱਲੋਂ ਵਾਪਸ ਕੀਤੇ ਰੀਲੇ ਸਥਿਤੀ ਹੈਡਰਾਂ ਦੀ ਜਾਂਚ ਕਰੋ
(**Settings → Proxy Pool** ਅਤੇ `relayTested` / `relayAlive` ਕਾਊਂਟਰ ਵੇਖੋ):

- `x-relay-url` — ਕਿਸ ਰੀਲੇ ਬੈਕਐਂਡ ਨੇ ਜਵਾਬ ਦਿੱਤਾ।
- `x-relay-mode` — ਉਸ ਬੇਨਤੀ ਲਈ `ts` | `bifrost` | `auto`।
- `x-relay-attempts` — ਸਫਲਤਾ ਤੋਂ ਪਹਿਲਾਂ ਕਿੰਨੇ ਰੀਲੇ ਹੌਪ ਅਜ਼ਮਾਏ ਗਏ।
- `x-relay-fallback` — ਜਦੋਂ ਬੇਨਤੀ ਤਰਜੀਹੀ ਬੈਕਐਂਡ ਤੋਂ TypeScript ਰੀਲੇ ਉੱਤੇ ਵਾਪਸ ਗਈ ਹੋਵੇ ਤਾਂ `true`।

ਘੱਟ `relayAlive` ਦੇ ਨਾਲ ਉੱਚੀ `x-relay-fallback` ਦਰ ਦਾ ਮਤਲਬ ਹੈ ਕਿ ਸਾਈਡਕਾਰ ਬੈਕਐਂਡ ਸਿਹਤਮੰਦ ਨਹੀਂ ਹੈ ਅਤੇ ਤੁਹਾਨੂੰ ਜਾਂ ਤਾਂ ਇਸਨੂੰ ਠੀਕ ਕਰਨਾ ਚਾਹੀਦਾ ਹੈ ਜਾਂ ਰੀਲੇ ਬੈਕਐਂਡ ਰਣਨੀਤੀ ਨੂੰ `ts` ਉੱਤੇ ਬਦਲਣਾ ਚਾਹੀਦਾ ਹੈ (`RELAY_BACKEND_STRATEGY.md` ਵੇਖੋ)।

## API ਹਵਾਲਾ

| ਢੰਗ    | ਪਾਥ                                       | ਬਾਡੀ                    | ਸਫਲਤਾ                                                                                                                                       | ਅਸਫਲਤਾ                                                                                |
| ------ | ----------------------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `POST` | `/api/settings/proxies/[id]/repair-relay` | `{ "id": "<proxyId>" }` | ਮੁੜ ਪ੍ਰਾਪਤ ਹੋਣ ਉੱਤੇ `200 { repaired: true, mode: "recovered" }`; ਪਲੇਨਟੈਕਸਟ ਪਹਿਲਾਂ ਹੀ ਮੌਜੂਦ ਹੋਣ ਉੱਤੇ `200 { repaired: false, mode: "noop" }` | `409 { mode: "redeploy" }` ਰਿਕਵਰ ਨਾ ਹੋਣਯੋਗ; `400` ਰੀਲੇ ਕਿਸਮ ਨਹੀਂ ਹੈ; `404` ਨਹੀਂ ਮਿਲਿਆ |

ਸੂਚੀ ਰੂਟ `GET /api/settings/proxies` ਹਰ ਆਈਟਮ ਨਾਲ ਇੱਕ ਸੀਕ੍ਰੇਟ-ਰਹਿਤ
`relayInfo: { isRelay, authMissing, repairMode }` ਜੋੜਦਾ ਹੈ, ਤਾਂ ਜੋ ਡੈਸ਼ਬੋਰਡ ਟੋਕਨ ਨੂੰ ਕਦੇ ਵੀ ਉਜਾਗਰ ਕੀਤੇ ਬਿਨਾਂ ਮੁਰੰਮਤ ਵਿਕਲਪ ਦਿਖਾ ਸਕੇ।
