> ਉਸ ਫਾਈਲ ਤੋਂ ਪੜ੍ਹਦੇ ਹਨ, ਇਸਲਈ ਹੇਠਾਂ ਦਿੱਤੀ ਸਾਰਣੀ ਇਸ ਨਾਲ 1:1 ਮੇਲ ਕਰਨ ਲਈ ਤਿਆਰ ਕੀਤੀ

## ਫੀਚਰ ਫਲੈਗ ਕੀ ਹਨ

ਇੱਕ ਫੀਚਰ ਫਲੈਗ ਇੱਕ ਨਾਮੀ ਟੌਗਲ (ਬੂਲੀਅਨ ਜਾਂ ਐਨਮ) ਹੈ ਜਿਸਦਾ ਮੁੱਲ ਰਨਟਾਈਮ 'ਤੇ ਬਦਲਿਆ
ਜਾ ਸਕਦਾ ਹੈ ਅਤੇ ਡੇਟਾਬੇਸ ਵਿੱਚ ਸਥਾਈ ਕੀਤਾ ਜਾ ਸਕਦਾ ਹੈ, ਜਿਸ ਲਈ ਕਿਸੇ ਪ੍ਰਕਿਰਿਆ ਨੂੰ
ਮੁੜ-ਤੈਨਾਤ ਕਰਨ ਦੀ ਲੋੜ ਨਹੀਂ ਹੈ। ਹਰੇਕ ਫਲੈਗ ਨੂੰ ਇੱਕ `FeatureFlagDefinition` ਦੁਆਰਾ
ਵਰਣਨ ਕੀਤਾ ਗਿਆ ਹੈ ਜਿਸ ਵਿੱਚ ਇੱਕ `key`, `label`, `description`, `category`,
`defaultValue`, `type`, ਅਤੇ ਇੱਕ `requiresRestart` ਸੰਕੇਤ ਸ਼ਾਮਲ ਹਨ।

### ਰੈਜ਼ੋਲੂਸ਼ਨ ਆਰਡਰ

ਇੱਕ ਫਲੈਗ ਦਾ **ਪ੍ਰਭਾਵੀ ਮੁੱਲ** [`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts)
ਦੁਆਰਾ ਇਸ ਤਰਜੀਹ (ਸਭ ਤੋਂ ਉੱਚਾ ਜਿੱਤਦਾ ਹੈ) ਨਾਲ ਹੱਲ ਕੀਤਾ ਜਾਂਦਾ ਹੈ:

1. **DB ਓਵਰਰਾਈਡ** — `key_value` ਸਾਰਣੀ ਵਿੱਚ `feature_flags` ਨਾਮਸਪੇਸ ਦੇ ਅਧੀਨ
   ਸਟੋਰ ਕੀਤਾ ਗਿਆ ਇੱਕ ਮੁੱਲ (ਡੈਸ਼ਬੋਰਡ ਜਾਂ REST API ਰਾਹੀਂ ਸੈੱਟ ਕੀਤਾ ਗਿਆ)।
2. **ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲ** — `process.env[<KEY>]`, ਜੇਕਰ ਸੈੱਟ ਕੀਤਾ ਗਿਆ ਹੈ ਅਤੇ ਖਾਲੀ
   ਨਹੀਂ ਹੈ।
3. **ਪਰਿਭਾਸ਼ਾ ਡਿਫੌਲਟ** — `featureFlagDefinitions.ts` ਤੋਂ `defaultValue`।

ਇੱਕ ਬੂਲੀਅਨ ਫਲੈਗ ਨੂੰ **ਸਮਰੱਥ** ਮੰਨਿਆ ਜਾਂਦਾ ਹੈ ਜਦੋਂ ਇਸਦਾ ਪ੍ਰਭਾਵੀ ਮੁੱਲ `"true"`,
`"1"`, ਜਾਂ `"yes"` ਹੁੰਦਾ ਹੈ (ਦੇਖੋ `isFeatureFlagEnabled()`)।

> [!NOTE]
> ਜ਼ਿਆਦਾਤਰ ਫਲੈਗਾਂ ਵਿੱਚ [`ENVIRONMENT.md`](./ENVIRONMENT.md) ਵਿੱਚ ਦਸਤਾਵੇਜ਼ੀ
> **ਉਸੇ ਨਾਮ** ਦਾ ਇੱਕ ਮੇਲ ਖਾਂਦਾ ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲ ਵੀ ਹੁੰਦਾ ਹੈ। ਫਲੈਗ ਦਾ DB
> ਓਵਰਰਾਈਡ ਉਸ ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲ 'ਤੇ ਤਰਜੀਹ ਲੈਂਦਾ ਹੈ। `requiresRestart: true` ਵਾਲਾ
> ਇੱਕ ਫਲੈਗ ਤੁਰੰਤ ਸਥਾਈ ਹੋ ਜਾਂਦਾ ਹੈ ਪਰ ਸਿਰਫ ਪ੍ਰਕਿਰਿਆ ਸ਼ੁਰੂ ਹੋਣ 'ਤੇ ਮੁੜ-ਪੜ੍ਹਿਆ
> ਜਾਂਦਾ ਹੈ — ਇਸਨੂੰ ਟੌਗਲ ਕਰਨ ਨਾਲ ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ ਇੱਕ **"ਸਰਵਰ ਮੁੜ-ਚਾਲੂ ਕਰੋ"** ਬੈਨਰ
> ਦਿਖਾਈ ਦਿੰਦਾ ਹੈ।

- ਕੁੰਜੀ ਜਾਂ ਵੇਰਵੇ ਦੁਆਰਾ **ਖੋਜ** ਅਤੇ ਸ਼੍ਰੇਣੀ ਦੁਆਰਾ **ਫਿਲਟਰ** (ਇੱਕ ਸਿੰਥੈਟਿਕ **ਰੀਸਟਾਰਟ ਦੀ ਲੋੜ ਹੈ** ਦ੍ਰਿਸ਼ ਸਮੇਤ)।
- ਬੂਲੀਅਨ ਫਲੈਗਾਂ ਲਈ ਇੱਕ **ਟੌਗਲ** ਅਤੇ ਐਨਮ ਫਲੈਗਾਂ ਲਈ ਇੱਕ **ਡ੍ਰੌਪਡਾਊਨ**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`)।
- ਪ੍ਰਤੀ ਫਲੈਗ ਇੱਕ **ਸਰੋਤ ਬੈਜ** — `DB`, `ENV`, ਜਾਂ `DEF` — ਇਹ ਦਰਸਾਉਂਦਾ ਹੈ ਕਿ ਪ੍ਰਭਾਵੀ ਮੁੱਲ ਕਿੱਥੋਂ ਆਇਆ ਹੈ।
- ਓਵਰਰਾਈਡ ਨੂੰ ਛੱਡਣ ਲਈ ਇੱਕ **ਰੀਸੈਟ** ਬਟਨ (`DB`-ਸਰੋਤ ਵਾਲੇ ਫਲੈਗਾਂ ਲਈ ਹੀ ਦਿਖਾਇਆ ਗਿਆ ਹੈ), ਅਤੇ ਹੇਠਾਂ ਇੱਕ **ਸਾਰੇ ਓਵਰਰਾਈਡਸ ਰੀਸੈਟ ਕਰੋ** ਬਟਨ।
- ਜਦੋਂ `requiresRestart` ਫਲੈਗ ਬਦਲਿਆ ਜਾਂਦਾ ਹੈ ਤਾਂ ਇੱਕ **ਸਰਵਰ ਰੀਸਟਾਰਟ ਕਰੋ** ਬੈਨਰ।

### REST API

ਸਾਰੀਆਂ ਕਾਰਵਾਈਆਂ ਇੱਕ ਸਿੰਗਲ ਰੂਟ ਰਾਹੀਂ ਹੁੰਦੀਆਂ ਹਨ:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts)।
ਹਰੇਕ ਵਿਧੀ ਲਈ ਇੱਕ ਪ੍ਰਮਾਣਿਤ ਡੈਸ਼ਬੋਰਡ ਸੈਸ਼ਨ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ (ਨਹੀਂ ਤਾਂ `401`)।

#### `GET /api/settings/feature-flags`

ਹਰੇਕ ਫਲੈਗ ਨੂੰ ਇਸਦੇ ਪ੍ਰਭਾਵੀ ਮੁੱਲ, ਸਰੋਤ ਅਤੇ ਇੱਕ ਸੰਖੇਪ ਜਾਣਕਾਰੀ ਨਾਲ ਵਾਪਸ ਕਰਦਾ ਹੈ।

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... all 77 flags
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

ਇੱਕ ਸਿੰਗਲ ਓਵਰਰਾਈਡ ਸੈੱਟ ਕਰੋ ਜਾਂ ਹਟਾਓ। ਬਾਡੀ: `{ key: string; value?: string }`।
`value` ਨੂੰ ਛੱਡਣ ਨਾਲ ਓਵਰਰਾਈਡ ਹਟ ਜਾਂਦਾ ਹੈ (env / ਡਿਫੌਲਟ ਨੂੰ ਬਹਾਲ ਕਰਦਾ ਹੈ)।

```bash
# Set a DB override
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Remove the override (no "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

ਜਵਾਬ ਨਵੇਂ `effectiveValue`/`source`, `previousValue`/
`previousSource`, ਅਤੇ `requiresRestart` ਨੂੰ ਦਰਸਾਉਂਦਾ ਹੈ। ਅਣਜਾਣ ਕੁੰਜੀਆਂ ਅਤੇ ਸੀਮਾ ਤੋਂ ਬਾਹਰ ਐਨਮ
ਮੁੱਲਾਂ ਨੂੰ `400` ਨਾਲ ਰੱਦ ਕਰ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ।

#### `DELETE /api/settings/feature-flags`

ਇੱਕੋ ਵਾਰ **ਸਾਰੇ** DB ਓਵਰਰਾਈਡਸ ਨੂੰ ਸਾਫ਼ ਕਰਦਾ ਹੈ, ਹਰੇਕ ਫਲੈਗ ਨੂੰ ਇਸਦੇ env / ਡਿਫੌਲਟ
ਮੁੱਲ 'ਤੇ ਬਹਾਲ ਕਰਦਾ ਹੈ। `{ cleared: <count>, message: "..." }` ਵਾਪਸ ਕਰਦਾ ਹੈ।

> [!NOTE]
> `requiresRestart: true` ਵਾਲੇ ਫਲੈਗ ਸਿਰਫ਼ ਇੱਕ ਪ੍ਰਕਿਰਿਆ ਰੀਲੋਡ ਤੋਂ ਬਾਅਦ ਹੀ ਪ੍ਰਭਾਵੀ ਹੁੰਦੇ ਹਨ।
> ਡੈਸ਼ਬੋਰਡ ਦਾ ਰੀਸਟਾਰਟ ਫਲੋ `POST /api/restart` ਨੂੰ ਕਾਲ ਕਰਦਾ ਹੈ ਅਤੇ ਫਿਰ
> `GET /api/health/ping` ਨੂੰ ਪੋਲ ਕਰਦਾ ਹੈ ਜਦੋਂ ਤੱਕ ਸਰਵਰ ਦੁਬਾਰਾ ਚਾਲੂ ਨਹੀਂ ਹੋ ਜਾਂਦਾ।

## ਐਮਰਜੈਂਸੀ ਬਜਟ ਫਾਲਬੈਕ

`OMNIROUTE_EMERGENCY_FALLBACK` (ਸ਼੍ਰੇਣੀ `runtime`, ਡਿਫੌਲਟ `true`)
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts) ਵਿੱਚ
ਐਮਰਜੈਂਸੀ ਫ੍ਰੀ-ਫਾਲਬੈਕ ਪਾਥ ਨੂੰ ਨਿਯੰਤਰਿਤ ਕਰਦਾ ਹੈ। ਜਦੋਂ ਸਮਰੱਥ ਹੁੰਦਾ ਹੈ, ਤਾਂ ਉਹ ਬੇਨਤੀਆਂ ਜੋ ਆਪਣਾ ਬਜਟ ਖਤਮ ਕਰ ਦਿੰਦੀਆਂ ਹਨ,
ਸਿੱਧੇ ਅਸਫਲ ਹੋਣ ਦੀ ਬਜਾਏ ਇੱਕ ਮੁਫਤ ਫਾਲਬੈਕ ਪ੍ਰਦਾਤਾ/ਮਾਡਲ 'ਤੇ ਰੂਟ ਕੀਤੀਆਂ ਜਾਂਦੀਆਂ ਹਨ।
ਇਸ ਵਿਵਹਾਰ ਨੂੰ ਅਯੋਗ ਕਰਨ ਲਈ ਇਸਨੂੰ `false` (ਜਾਂ `0`) 'ਤੇ ਸੈੱਟ ਕਰੋ — ਡੈਸ਼ਬੋਰਡ ਟੌਗਲ, ਇੱਕ DB ਓਵਰਰਾਈਡ,
ਜਾਂ `OMNIROUTE_EMERGENCY_FALLBACK` ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲ ਰਾਹੀਂ — ਅਤੇ ਬਜਟ-ਖਤਮ ਹੋਈਆਂ ਬੇਨਤੀਆਂ ਨੂੰ ਅਸਫਲ ਹੋਣ ਦਿਓ।
(PRs #3741 / #3752 ਵਿੱਚ ਇੱਕ ਡੈਸ਼ਬੋਰਡ ਟੌਗਲ ਵਜੋਂ ਪ੍ਰਗਟ ਕੀਤਾ ਗਿਆ।)
