> **ਸੱਚਾਈ ਦਾ ਸਰੋਤ:** `src/lib/{cloudflaredTunnel,ngrokTunnel,tailscaleTunnel}.ts`, `src/app/api/tunnels/`
> **ਆਖਰੀ ਅੱਪਡੇਟ:** 2026-06-28 — v3.8.40

OmniRoute ਆਪਣੇ ਲੋਕਲ ਸਰਵਰ (`http://localhost:20128`) ਨੂੰ ਤਿੰਨ ਟਨਲ ਬੈਕਐਂਡਾਂ ਰਾਹੀਂ ਜਨਤਕ
ਇੰਟਰਨੈੱਟ ਲਈ ਉਪਲਬਧ ਕਰਵਾ ਸਕਦਾ ਹੈ। ਇਹ ਹੇਠ ਲਿਖਿਆਂ ਲਈ ਲਾਭਦਾਇਕ ਹੈ:

- ਕਲਾਉਡ ਪ੍ਰਦਾਤਾਵਾਂ (Antigravity, Gemini, Cursor) ਤੋਂ OAuth ਕਾਲਬੈਕ, ਜਿਨ੍ਹਾਂ ਨੂੰ
  ਜਨਤਕ ਤੌਰ 'ਤੇ ਪਹੁੰਚਯੋਗ ਰੀਡਾਇਰੈਕਟ URL ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ।
- VM ਡਿਪਲੌਇ ਕੀਤੇ ਬਿਨਾਂ ਆਪਣੀ ਲੋਕਲ ਇੰਸਟੈਂਸ ਨੂੰ ਟੀਮ ਦੇ ਮੈਂਬਰਾਂ ਨਾਲ ਸਾਂਝਾ ਕਰਨਾ।
- ਮੋਬਾਈਲ, ਰਿਮੋਟ, ਜਾਂ ਵੱਖ-ਵੱਖ ਨੈੱਟਵਰਕਾਂ ਵਿਚਕਾਰ ਟੈਸਟਿੰਗ।

ਸਾਰੇ ਤਿੰਨ ਬੈਕਐਂਡ ਪ੍ਰਕਿਰਿਆ ਦੇ ਅੰਦਰ ਹੀ ਪ੍ਰਬੰਧਿਤ ਕੀਤੇ ਜਾਂਦੇ ਹਨ — OmniRoute ਡੈਸ਼ਬੋਰਡ
ਜਾਂ REST API ਤੋਂ ਅਧਾਰਭੂਤ ਬਾਈਨਰੀ ਜਾਂ SDK ਨੂੰ ਸ਼ੁਰੂ/ਬੰਦ ਕਰਦਾ ਹੈ। ਕਿਸੇ reverse-proxy
ਜਾਂ systemd ਸੈੱਟਅੱਪ ਦੀ ਲੋੜ ਨਹੀਂ ਹੈ।

## ਬੈਕਐਂਡਾਂ ਦੀ ਇੱਕ ਝਲਕ

| ਬੈਕਐਂਡ                      | ਸਥਿਰਤਾ                                                  | ਲਾਗਤ                     | ਸੈੱਟਅੱਪ                                              |
| --------------------------- | ------------------------------------------------------- | ------------------------ | ---------------------------------------------------- |
| **Cloudflare Quick Tunnel** | ਅਸਥਾਈ (ਹਰੇਕ ਰੀਸਟਾਰਟ 'ਤੇ URL ਬਦਲਦਾ ਹੈ)                   | ਮੁਫ਼ਤ                    | ਕੁਝ ਨਹੀਂ — `cloudflared` ਆਪਣੇ ਆਪ ਇੰਸਟਾਲ ਹੁੰਦਾ ਹੈ     |
| **ngrok**                   | ਭੁਗਤਾਨਸ਼ੁਦਾ ਪਲਾਨ ਜਾਂ ਨਿਸ਼ਚਿਤ ਡੋਮੇਨ ਕੌਂਫਿਗਰ ਹੋਣ ਤੱਕ ਸਥਿਰ | ਮੁਫ਼ਤ ਟੀਅਰ + ਭੁਗਤਾਨਸ਼ੁਦਾ | ngrok ਖਾਤਾ + authtoken ਲੋੜੀਂਦਾ ਹੈ                    |
| **Tailscale Funnel**        | ਤੁਹਾਡੇ tailnet ਅੰਦਰ ਪ੍ਰਤੀ ਨੋਡ ਸਥਿਰ                      | ਨਿੱਜੀ ਵਰਤੋਂ ਲਈ ਮੁਫ਼ਤ     | Tailscale ਇੰਸਟਾਲੇਸ਼ਨ + ਲੌਗਇਨ + Funnel ACL ਲੋੜੀਂਦਾ ਹੈ |

ਇੰਪਲੀਮੈਂਟੇਸ਼ਨ `src/lib/cloudflaredTunnel.ts`,
`src/lib/ngrokTunnel.ts`, ਅਤੇ `src/lib/tailscaleTunnel.ts` ਵਿੱਚ ਮੌਜੂਦ ਹਨ। ਇਹ ਤਿੰਨੇ
`phase`, `running`, `publicUrl`, `apiUrl`,
`targetUrl`, ਅਤੇ `lastError` ਫੀਲਡਾਂ ਵਾਲਾ ਇੱਕੋ ਜਿਹੇ ਰੂਪ ਦਾ `status` ਆਬਜੈਕਟ ਵਾਪਸ ਕਰਦੇ ਹਨ, ਤਾਂ ਜੋ ਡੈਸ਼ਬੋਰਡ ਉਨ੍ਹਾਂ ਨੂੰ ਇੱਕਸਾਰ ਢੰਗ ਨਾਲ ਦਿਖਾ ਸਕੇ।

## 1. Cloudflare Tunnel (Quick Tunnel + Named Tunnel)

`src/lib/cloudflaredTunnel.ts`, `cloudflared` ਨੂੰ ਇੱਕ ਚਾਈਲਡ ਪ੍ਰੋਸੈੱਸ ਵਜੋਂ ਚਲਾਉਂਦਾ ਹੈ। ਇਹ
ਦੋ ਮੋਡਾਂ ਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈ, ਜਿਨ੍ਹਾਂ ਦੀ ਚੋਣ ਇਸ ਅਧਾਰ 'ਤੇ ਹੁੰਦੀ ਹੈ ਕਿ named-tunnel ਕੌਂਫਿਗ ਦਿੱਤਾ ਗਿਆ ਹੈ ਜਾਂ ਨਹੀਂ:

- **Quick tunnel (ਡਿਫੌਲਟ)।** `cloudflared tunnel --url
http://localhost:<apiPort>` ਚਲਾਉਂਦਾ ਹੈ ਅਤੇ stdout ਤੋਂ ਨਿਰਧਾਰਤ ਕੀਤਾ `*.trycloudflare.com` URL
  ਪਾਰਸ ਕਰਦਾ ਹੈ। URL ਅਸਥਾਈ ਹੁੰਦੇ ਹਨ ਅਤੇ ਹਰੇਕ ਰੀਸਟਾਰਟ 'ਤੇ ਬਦਲ ਜਾਂਦੇ ਹਨ।
- **Named tunnel (ਚੋਣਵਾਂ)।** ਜਦੋਂ `CLOUDFLARED_CONFIG` ਲੋਕਲ ਤੌਰ 'ਤੇ ਪ੍ਰਬੰਧਿਤ
  cloudflared `config.yml` ਵੱਲ ਸੰਕੇਤ ਕਰਦਾ ਹੈ, ਤਾਂ OmniRoute `cloudflared tunnel --no-autoupdate
--config <path> run` ਚਲਾਉਂਦਾ ਹੈ, ਜਿਸ ਨਾਲ ਤੁਹਾਨੂੰ ਇੱਕ **ਸਥਿਰ, ਨਾਮਿਤ ਹੋਸਟਨੇਮ** ਮਿਲਦਾ ਹੈ। ਕੌਂਫਿਗ
  ਟਨਲ UUID, `credentials-file`, ਅਤੇ `ingress` ਰੂਟਿੰਗ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ, ਇਸ ਲਈ ਕੋਈ
  `--url` ਪਾਸ ਨਹੀਂ ਕੀਤਾ ਜਾਂਦਾ ਅਤੇ ਕਿਸੇ Zero Trust ਡੈਸ਼ਬੋਰਡ ਟੋਕਨ ਦੀ ਲੋੜ ਨਹੀਂ ਹੁੰਦੀ। `run`,
  ਕੌਂਫਿਗ ਦੇ ਐਬਸੋਲਿਊਟ `credentials-file` ਪਾਥ ਤੋਂ ਕ੍ਰੀਡੈਂਸ਼ਲ ਪੜ੍ਹਦਾ ਹੈ — ਕਿਸੇ `cert.pem`
  ਦੀ ਲੋੜ ਨਹੀਂ ਹੁੰਦੀ (ਇਹ ਸਿਰਫ਼ ਟਨਲ ਲਾਈਫਸਾਈਕਲ ਪ੍ਰਬੰਧਨ ਲਈ ਵਰਤਿਆ ਜਾਂਦਾ ਹੈ)।

ਮੁੱਖ ਵਿਵਹਾਰ:

- **ਆਟੋ-ਇੰਸਟਾਲ।** ਪਹਿਲੀ ਵਰਤੋਂ 'ਤੇ, OmniRoute ਅਧਿਕਾਰਤ GitHub ਰਿਲੀਜ਼ਾਂ ਤੋਂ ਨਵੀਨਤਮ `cloudflared`
  ਬਾਈਨਰੀ ਡਾਊਨਲੋਡ ਕਰਦਾ ਹੈ (ਪ੍ਰਬੰਧਿਤ ਇੰਸਟਾਲੇਸ਼ਨ `DATA_DIR/cloudflared/` ਦੇ ਅਧੀਨ ਰਹਿੰਦੀ ਹੈ)।
  ਚਲਾਉਣ ਤੋਂ ਪਹਿਲਾਂ ਡਾਊਨਲੋਡ ਕੀਤੇ ਐਸੈੱਟ ਦੇ SHA256 ਦੀ ਰਿਲੀਜ਼ ਮੈਨਿਫੈਸਟ ਨਾਲ ਪੁਸ਼ਟੀ ਕੀਤੀ ਜਾਂਦੀ ਹੈ।
- **ਪ੍ਰੋਸੈੱਸ ਨਿਗਰਾਨੀ।** cloudflared PID ਅਤੇ ਰਿਜ਼ਾਲਵ ਕੀਤਾ URL
  `quick-tunnel-state.json` ਵਿੱਚ ਸਥਾਈ ਤੌਰ 'ਤੇ ਸੰਭਾਲੇ ਜਾਂਦੇ ਹਨ, ਤਾਂ ਜੋ ਡੈਸ਼ਬੋਰਡ ਰੀਲੋਡਾਂ ਤੋਂ ਬਾਅਦ ਸਥਿਤੀ ਮੁੜ ਪ੍ਰਾਪਤ ਕਰ ਸਕੇ।

### Named tunnel ਸੈੱਟਅੱਪ (ਸਥਿਰ ਹੋਸਟਨੇਮ)

1. cloudflared CLI ਨਾਲ ਇੱਕ ਲੋਕਲ ਤੌਰ 'ਤੇ ਪ੍ਰਬੰਧਿਤ ਟਨਲ ਬਣਾਓ (ਇੱਕ ਵਾਰ):

   ```bash
   cloudflared tunnel login
   cloudflared tunnel create omniroute
   cloudflared tunnel route dns omniroute ai.example.com
   ```

2. ਇੱਕ `~/.cloudflared/config.yml` ਲਿਖੋ, ਜੋ ਤੁਹਾਡੇ ਹੋਸਟਨੇਮ ਨੂੰ OmniRoute ਦੇ ਲੋਕਲ
   API ਪੋਰਟ ਵੱਲ ਰੂਟ ਕਰੇ (ਡਿਫੌਲਟ 20128):

   ```yaml
   tunnel: <UUID-from-create>
   credentials-file: /home/you/.cloudflared/<UUID>.json
   ingress:
     - hostname: ai.example.com
       service: http://127.0.0.1:20128
     - service: http_status:404
   ```

3. OmniRoute ਨੂੰ ਕੌਂਫਿਗ ਵੱਲ ਸੰਕੇਤ ਕਰੋ ਅਤੇ ਟਨਲ ਨੂੰ (ਮੁੜ) ਸ਼ੁਰੂ ਕਰੋ:

   ```bash
   export CLOUDFLARED_CONFIG="/home/you/.cloudflared/config.yml"
   # ਚੋਣਵਾਂ — OmniRoute ਵੱਲੋਂ ਰਿਪੋਰਟ ਕੀਤੇ ਹੋਸਟਨੇਮ ਨੂੰ ਓਵਰਰਾਈਡ ਕਰਦਾ ਹੈ; ਨਹੀਂ ਤਾਂ ਇਸਨੂੰ
   # ਕੌਂਫਿਗ ਦੇ ਪਹਿਲੇ ingress ਨਿਯਮ ਤੋਂ ਪੜ੍ਹਿਆ ਜਾਂਦਾ ਹੈ:
   # export CLOUDFLARED_HOSTNAME="ai.example.com"
   ```

   ਟਨਲ ਨੂੰ Quick tunnel ਵਾਂਗ ਹੀ ਸਮਰੱਥ ਕਰੋ (REST / ਡੈਸ਼ਬੋਰਡ / ਹੇਠਾਂ ਦਿੱਤਾ CLI)।
   Named tunnel ਸਕ੍ਰੇਪ ਕਰਨ ਲਈ ਕੋਈ ਜਨਤਕ URL ਨਹੀਂ ਦਿੰਦਾ, ਇਸ ਲਈ ਤਿਆਰੀ ਦੀ ਸਥਿਤੀ cloudflared ਦੇ
   ਰਜਿਸਟਰ ਕੀਤੇ edge ਕਨੈਕਸ਼ਨ ਤੋਂ ਪਛਾਣੀ ਜਾਂਦੀ ਹੈ, ਅਤੇ `publicUrl`/`apiUrl` ਨੂੰ
   `CLOUDFLARED_HOSTNAME` (ਜਾਂ ਕੌਂਫਿਗ ਦੇ ਪਹਿਲੇ ingress ਹੋਸਟਨੇਮ) ਤੋਂ ਰਿਪੋਰਟ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।

### REST ਰਾਹੀਂ ਸਮਰੱਥ / ਅਸਮਰੱਥ ਕਰੋ

ਇਹ ਐਂਡਪੌਇੰਟ ਵੱਖਰੇ `start`/`stop` ਪਾਥਾਂ ਦੀ ਬਜਾਏ
`{action: "enable" | "disable"}` ਬੌਡੀ ਵਰਤਦਾ ਹੈ। ਪ੍ਰਬੰਧਨ ਪ੍ਰਮਾਣੀਕਰਨ (ਐਡਮਿਨ ਸੈਸ਼ਨ ਜਾਂ ਐਡਮਿਨ API ਕੁੰਜੀ)
ਲੋੜੀਂਦਾ ਹੈ।

```bash
# ਸਮਰੱਥ ਕਰੋ
curl -X POST http://localhost:20128/api/tunnels/cloudflared \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"enable"}'

# ਸਥਿਤੀ
curl http://localhost:20128/api/tunnels/cloudflared \
  -H "Cookie: auth_token=..."

# ਅਸਮਰੱਥ ਕਰੋ
curl -X POST http://localhost:20128/api/tunnels/cloudflared \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"disable"}'
```

ਜਾਂ ਡੈਸ਼ਬੋਰਡ ਰਾਹੀਂ: **Settings → Tunnels → Cloudflare**।

| `CLOUDFLARED_BIN`                                    | ਬਾਈਨਰੀ ਪਾਥ ਨੂੰ ਓਵਰਰਾਈਡ ਕਰਦਾ ਹੈ। ਜੇ ਇਹ ਸੈੱਟ ਅਤੇ ਵੈਧ ਹੋਵੇ, ਤਾਂ OmniRoute ਡਾਊਨਲੋਡ ਕਰਨ ਦੀ ਬਜਾਏ ਇਸਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ।                                                       |
| `CLOUDFLARED_PROTOCOL` / `TUNNEL_TRANSPORT_PROTOCOL` | ਟ੍ਰਾਂਸਪੋਰਟ ਪ੍ਰੋਟੋਕੋਲ (ਡਿਫੌਲਟ `http2`; `quic`, `auto` ਵੀ)।                                                                                                            |
| `CLOUDFLARED_CONFIG`                                 | ਸਥਾਨਕ ਤੌਰ 'ਤੇ ਪ੍ਰਬੰਧਿਤ cloudflared `config.yml` ਦਾ ਪਾਥ। ਸੈੱਟ ਹੋਣ 'ਤੇ, OmniRoute ਇੱਕ ਤੁਰੰਤ ਟਨਲ ਦੀ ਬਜਾਏ **ਨਾਮਿਤ/ਸਥਾਈ** ਟਨਲ (`tunnel --config <path> run`) ਚਲਾਉਂਦਾ ਹੈ।  |
| `CLOUDFLARED_HOSTNAME`                               | ਨਾਮਿਤ ਟਨਲ ਵੱਲੋਂ ਰਿਪੋਰਟ ਕੀਤੇ ਜਨਤਕ ਹੋਸਟਨੇਮ ਨੂੰ ਓਵਰਰਾਈਡ ਕਰਦਾ ਹੈ (ਜਿਵੇਂ `ai.example.com`)। ਸੈੱਟ ਨਾ ਹੋਣ 'ਤੇ, ਇਸਨੂੰ ਕੌਂਫਿਗ ਦੇ ਪਹਿਲੇ `ingress` ਹੋਸਟਨੇਮ ਤੋਂ ਪੜ੍ਹਿਆ ਜਾਂਦਾ ਹੈ। |

## 2. ngrok

`src/lib/ngrokTunnel.ts` **`@ngrok/ngrok` SDK** ਦੀ ਵਰਤੋਂ ਕਰਦੀ ਹੈ (ਪ੍ਰਕਿਰਿਆ ਦੇ ਅੰਦਰ, ਕੋਈ CLI
ਉਪ-ਪ੍ਰਕਿਰਿਆ ਨਹੀਂ)। ਨੇਟਿਵ ਮੋਡੀਊਲ ਨੂੰ ਪਹਿਲੀ ਵਾਰ ਸ਼ੁਰੂ ਕਰਨ ਵੇਲੇ ਆਲਸੀ ਢੰਗ ਨਾਲ ਇੰਪੋਰਟ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਤਾਂ ਜੋ
ਪਹਿਲਾਂ ਤੋਂ ਬਣੀਆਂ ਬਾਈਨਰੀਆਂ ਤੋਂ ਬਿਨਾਂ ਪਲੇਟਫਾਰਮ ਬੂਟ ਸਮੇਂ ਐਪ ਨੂੰ ਖ਼ਰਾਬ ਨਾ ਕਰਨ।

### ਪੂਰਵ-ਸ਼ਰਤਾਂ

1. <https://ngrok.com> 'ਤੇ ਸਾਈਨ ਅੱਪ ਕਰੋ।
2. ngrok ਡੈਸ਼ਬੋਰਡ ਤੋਂ ਆਪਣਾ authtoken ਕਾਪੀ ਕਰੋ।
3. ਇਸਨੂੰ ਹੇਠ ਲਿਖੇ ਕਿਸੇ ਇੱਕ ਤਰੀਕੇ ਰਾਹੀਂ ਦਿਓ:
   - `.env`: `NGROK_AUTHTOKEN=<token>`, ਜਾਂ
   - ਡੈਸ਼ਬੋਰਡ: **Settings → Tunnels → ngrok**, ਜਾਂ
   - REST ਬਾਡੀ (ਇੱਕ ਵਾਰ ਲਈ): `{"action":"enable","authToken":"<token>"}`।

ਜੇ ਦੋਵਾਂ ਵਿੱਚੋਂ ਕੋਈ ਵੀ ਸੰਰਚਿਤ ਨਹੀਂ ਹੈ, ਤਾਂ ਸਥਿਤੀ `phase: "needs_auth"` ਵਾਪਸ ਕਰਦੀ ਹੈ।

### REST ਰਾਹੀਂ ਸਮਰੱਥ / ਅਸਮਰੱਥ ਕਰੋ

```bash
# ਸਮਰੱਥ ਕਰੋ (env ਤੋਂ NGROK_AUTHTOKEN ਵਰਤਦਾ ਹੈ)
curl -X POST http://localhost:20128/api/tunnels/ngrok \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"enable"}'

# ਇਨਲਾਈਨ ਟੋਕਨ ਨਾਲ ਸਮਰੱਥ ਕਰੋ
curl -X POST http://localhost:20128/api/tunnels/ngrok \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"enable","authToken":"2abc..."}'

# ਸਥਿਤੀ
curl http://localhost:20128/api/tunnels/ngrok \
  -H "Cookie: auth_token=..."

# ਅਸਮਰੱਥ ਕਰੋ
curl -X POST http://localhost:20128/api/tunnels/ngrok \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"disable"}'
```

ਜਵਾਬ ਵਿੱਚ ਨਿਰਧਾਰਤ ਕੀਤਾ ਗਿਆ `publicUrl` ਸ਼ਾਮਲ ਹੁੰਦਾ ਹੈ (ਉਦਾਹਰਨ ਲਈ
`https://abcd-1234.ngrok-free.app`)। ਕਸਟਮ ਡੋਮੇਨ, ਖੇਤਰ ਅਤੇ ਨੀਤੀ ਨਿਯਮ
ngrok ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ ਸੰਰਚਿਤ ਕੀਤੇ ਜਾਣੇ ਚਾਹੀਦੇ ਹਨ — OmniRoute ਖੁਦ ਸਿਰਫ਼
ਸਥਾਨਕ ਟਾਰਗੇਟ URL ਨੂੰ SDK ਵੱਲ ਅੱਗੇ ਭੇਜਦਾ ਹੈ।

## 3. Tailscale Funnel

`src/lib/tailscaleTunnel.ts` ਸਥਾਨਕ API ਪੋਰਟ ਨੂੰ **Funnel** (serve ਲਈ Tailscale ਦਾ
ਜਨਤਕ-ਇੰਟਰਨੈੱਟ ਨਿਕਾਸ) ਰਾਹੀਂ ਉਪਲਬਧ ਕਰਵਾਉਣ ਲਈ ਸਿਸਟਮ `tailscale` CLI ਦਾ ਸੰਚਾਲਨ ਕਰਦੀ ਹੈ।
ਇਹ ਪੂਰੇ ਜੀਵਨ-ਚੱਕਰ ਦਾ ਸਮਰਥਨ ਕਰਦੀ ਹੈ: ਇੰਸਟਾਲੇਸ਼ਨ, ਲਾਗਇਨ, ਡੀਮਨ ਸ਼ੁਰੂ ਕਰਨਾ, ਸਮਰੱਥ ਕਰਨਾ, ਅਸਮਰੱਥ ਕਰਨਾ।

ਲਾਗੂਕਰਨ `tailscale funnel --bg <port>` (ਬੈਕਗ੍ਰਾਊਂਡ ਮੋਡ) ਨੂੰ ਚਲਾਉਂਦਾ ਹੈ। ਜਨਤਕ
URL ਦਾ ਰੂਪ `https://<machine>.<tailnet>.ts.net/` ਹੁੰਦਾ ਹੈ।

### ਪੂਰਵ-ਸ਼ਰਤਾਂ

1. Tailscale ਇੰਸਟਾਲ ਕਰੋ (ਜਾਂ OmniRoute ਨੂੰ ਇਹ ਕਰਨ ਦਿਓ — ਹੇਠਾਂ ਦਿੱਤਾ `install` ਐਂਡਪੌਇੰਟ ਵੇਖੋ)।
2. ਸਾਈਨ ਇਨ ਕਰੋ (`tailscale login` ਜਾਂ OmniRoute ਦੇ `login` ਐਂਡਪੌਇੰਟ ਰਾਹੀਂ)।
3. Tailscale ਐਡਮਿਨ ਕਨਸੋਲ ਵਿੱਚ ਆਪਣੇ tailnet ਲਈ Funnel ਸਮਰੱਥ ਕਰੋ:
   <https://login.tailscale.com/admin/settings/features>।

Linux ਅਤੇ macOS ਉੱਤੇ ਡੀਮਨ (`tailscaled`) ਨੂੰ ਕੰਟਰੋਲ ਕਰਨ ਲਈ `sudo` ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ।
POST ਐਂਡਪੌਇੰਟ ਇੱਕ ਵਿਕਲਪਿਕ `sudoPassword` ਫ਼ੀਲਡ ਸਵੀਕਾਰ ਕਰਦੇ ਹਨ, ਜਿਸਨੂੰ ਕਾਲ ਦੀ
ਮਿਆਦ ਲਈ OmniRoute ਦੇ MITM ਪਾਸਵਰਡ ਕੈਸ਼ (`getCachedPassword` / `setCachedPassword`) ਵੱਲ
ਅੱਗੇ ਭੇਜਿਆ ਜਾਂਦਾ ਹੈ। Windows ਇੱਥੇ ਡਿਫਾਲਟ ਸਰਵਿਸ ਇੰਸਟਾਲੇਸ਼ਨ ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ:
`C:\Program Files\Tailscale\tailscale.exe`।

### REST ਐਂਡਪੌਇੰਟ

Tailscale ਦੀ ਸਤ੍ਹਾ ਹੋਰ ਬੈਕਐਂਡਾਂ ਨਾਲੋਂ ਵਧੇਰੇ ਵਿਸਤ੍ਰਿਤ ਹੈ, ਕਿਉਂਕਿ ਇੰਸਟਾਲੇਸ਼ਨ,
ਲਾਗਇਨ, ਡੀਮਨ ਅਤੇ ਟਨਲ ਵੱਖ-ਵੱਖ ਪਹਿਲੂ ਹਨ।

| ਐਂਡਪੌਇੰਟ                              | ਵਿਧੀ   | ਉਦੇਸ਼                                                                   |
| ------------------------------------- | ------ | ----------------------------------------------------------------------- |
| `/api/tunnels/tailscale`              | `GET`  | ਇਕੱਤਰਿਤ ਟਨਲ ਸਥਿਤੀ (`phase`, `tunnelUrl`, `apiUrl`, ਆਦਿ)                 |
| `/api/tunnels/tailscale/check`        | `GET`  | ਹੇਠਲੇ-ਪੱਧਰ ਦੀ ਜਾਂਚ: ਇੰਸਟਾਲ ਹੈ? ਲਾਗਇਨ ਹੈ? ਡੀਮਨ ਚੱਲ ਰਿਹਾ ਹੈ?              |
| `/api/tunnels/tailscale/install`      | `POST` | Tailscale ਇੰਸਟਾਲ ਕਰੋ (SSE ਰਾਹੀਂ ਸਟ੍ਰੀਮ ਕੀਤੇ ਪ੍ਰਗਤੀ ਇਵੈਂਟ) — Linux/macOS |
| `/api/tunnels/tailscale/start-daemon` | `POST` | Linux/macOS ਉੱਤੇ `tailscaled` ਸ਼ੁਰੂ ਕਰੋ                                 |
| `/api/tunnels/tailscale/login`        | `POST` | ਲਾਗਇਨ ਪ੍ਰਵਾਹ ਸ਼ੁਰੂ ਕਰੋ; ਬ੍ਰਾਊਜ਼ਰ ਵਿੱਚ ਖੋਲ੍ਹਣ ਲਈ `authUrl` ਵਾਪਸ ਕਰਦਾ ਹੈ  |
| `/api/tunnels/tailscale/enable`       | `POST` | API ਪੋਰਟ ਲਈ Funnel ਸ਼ੁਰੂ ਕਰੋ                                            |
| `/api/tunnels/tailscale/disable`      | `POST` | Funnel ਬੰਦ ਕਰੋ                                                          |

ਸਾਰੇ Tailscale ਐਂਡਪੌਇੰਟਾਂ ਲਈ ਪ੍ਰਬੰਧਨ ਪ੍ਰਮਾਣੀਕਰਨ ਲੋੜੀਂਦਾ ਹੈ (`routeUtils.ts ::
requireTailscaleAuth` ਵੇਖੋ)।

ਸਮਰੱਥ ਕਰਨ ਦੀ ਉਦਾਹਰਨ:

```bash
curl -X POST http://localhost:20128/api/tunnels/tailscale/enable \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"sudoPassword":"<linux-pwd>","port":20128}'
```

ਜੇ Funnel ਐਡਮਿਨ ਕਨਸੋਲ ਵਿੱਚ ਸਮਰੱਥ ਨਹੀਂ ਹੈ, ਤਾਂ ਜਵਾਬ ਵਿੱਚ
`funnelNotEnabled: true` ਦੇ ਨਾਲ ਬ੍ਰਾਊਜ਼ਰ ਵਿੱਚ ਖੋਲ੍ਹਣ ਲਈ ਇੱਕ `enableUrl` ਸ਼ਾਮਲ ਹੁੰਦਾ ਹੈ।

## OAuth ਕਾਲਬੈਕ ਸੰਬੰਧੀ ਵਿਚਾਰ

ਜਦੋਂ ਤੁਸੀਂ OmniRoute ਨੂੰ ਕਿਸੇ ਟਨਲ ਰਾਹੀਂ ਉਪਲਬਧ ਕਰਵਾਉਂਦੇ ਹੋ, ਤਾਂ ਡੈਸ਼ਬੋਰਡ ਅਤੇ OAuth ਫ਼ਲੋਜ਼ ਨੂੰ
ਕਾਲਬੈਕ URL **ਜਨਤਕ** ਹੋਸਟਨੇਮ ਦੇ ਆਧਾਰ 'ਤੇ ਬਣਾਉਣੇ ਚਾਹੀਦੇ ਹਨ, ਨਾ ਕਿ `localhost` ਦੇ ਆਧਾਰ 'ਤੇ। ਨਹੀਂ ਤਾਂ
OAuth ਪ੍ਰਦਾਤਾ ਵਰਤੋਂਕਾਰ ਨੂੰ ਵਾਪਸ ਅਜਿਹੇ URL 'ਤੇ ਰੀਡਾਇਰੈਕਟ ਕਰਦਾ ਹੈ ਜਿਸ ਤੱਕ ਉਸਦੇ ਸਰਵਰ ਨਹੀਂ ਪਹੁੰਚ ਸਕਦੇ,
ਅਤੇ ਹੈਂਡਸ਼ੇਕ ਅਸਫਲ ਹੋ ਜਾਂਦਾ ਹੈ।

ਡੈਸ਼ਬੋਰਡ ਸੰਪਾਦਨਾਂ ਅਤੇ ਸੈਟਿੰਗਾਂ ਨੂੰ ਸੇਵ ਕਰਨ ਲਈ ਟਨਲ ਹੋਸਟਨੇਮ ਨੂੰ
`NEXT_PUBLIC_BASE_URL` ਵਿੱਚ ਪਿੰਨ ਕਰਨ ਦੀ ਲੋੜ ਨਹੀਂ ਹੁੰਦੀ। ਪ੍ਰਮਾਣਿਤ ਡੈਸ਼ਬੋਰਡ ਉਸੇ ਓਰਿਜਿਨ ਵਾਲੀਆਂ ਅਸੁਰੱਖਿਅਤ
ਬੇਨਤੀਆਂ ਨੂੰ ਸੈਸ਼ਨ ਨਾਲ ਜੁੜੇ CSRF ਟੋਕਨ ਸਮੇਤ ਭੇਜਦਾ ਹੈ, ਇਸ ਲਈ ਲੌਗ ਇਨ ਕਰਨ ਤੋਂ ਬਾਅਦ ਅਸਥਾਈ Cloudflare Quick Tunnel
ਹੋਸਟਾਂ ਨੂੰ ਵੀ ਆਮ UI ਪ੍ਰਬੰਧਨ ਲਈ ਵਰਤਿਆ ਜਾ ਸਕਦਾ ਹੈ।

ਇਹ ਸੈੱਟ ਕਰੋ:

```bash
NEXT_PUBLIC_BASE_URL=https://<your-tunnel-host>
```

ਅਤੇ OAuth ਸ਼ੁਰੂ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ OmniRoute ਨੂੰ ਰੀਸਟਾਰਟ ਕਰੋ। ਅਸਥਾਈ Cloudflare Quick
Tunnels ਲਈ URL ਹਰ ਰੀਸਟਾਰਟ ਤੋਂ ਬਾਅਦ ਬਦਲ ਜਾਂਦਾ ਹੈ, ਇਸ ਲਈ ਪ੍ਰੋਡਕਸ਼ਨ OAuth ਵਰਤੋਂ ਵਾਸਤੇ ਰਾਖਵੇਂ
ਡੋਮੇਨ ਵਾਲੇ ngrok ਜਾਂ Tailscale Funnel ਨੂੰ ਤਰਜੀਹ ਦਿਓ।

## ਸਿਹਤ ਅਤੇ ਨਿਗਰਾਨੀ

ਡੈਸ਼ਬੋਰਡ **Settings → Tunnels** ਦੇ ਅਧੀਨ ਟਨਲ ਦੀ ਸਥਿਤੀ ਦਿਖਾਉਂਦਾ ਹੈ:

- ਸਰਗਰਮ ਬੈਕਐਂਡ ਅਤੇ ਮੌਜੂਦਾ `phase` (`stopped`, `starting`, `running`,
  `needs_auth`, `error`)।
- ਮੌਜੂਦਾ ਜਨਤਕ URL ਅਤੇ ਉਸ ਤੋਂ ਪ੍ਰਾਪਤ API URL (`<publicUrl>/v1`)।
- ਉਹ ਲੋਕਲ ਟਾਰਗੇਟ URL ਜਿਸ ਵੱਲ ਟਨਲ ਫਾਰਵਰਡ ਕਰ ਰਹੀ ਹੈ।
- ਆਖਰੀ ਗਲਤੀ ਸੁਨੇਹਾ, ਜੇ ਕੋਈ ਹੋਵੇ।

ਪ੍ਰੋਗਰਾਮ ਰਾਹੀਂ ਨਿਗਰਾਨੀ ਲਈ ਹਰੇਕ ਬੈਕਐਂਡ ਦੇ `GET` ਐਂਡਪੌਇੰਟ ਨੂੰ ਨਿਯਮਿਤ ਤੌਰ 'ਤੇ ਪੋਲ ਕਰੋ। ਇੱਕੋ ਸਮੇਂ ਇੱਕ ਤੋਂ ਵੱਧ
ਬੈਕਐਂਡ ਚਲਾਉਣ ਦੀ ਇਜਾਜ਼ਤ ਹੈ; OmniRoute ਹਰੇਕ ਨੂੰ
ਸੁਤੰਤਰ ਤੌਰ 'ਤੇ ਟ੍ਰੈਕ ਕਰੇਗਾ।

## ਸਮੱਸਿਆ-ਨਿਵਾਰਣ

### "cloudflared binary not found"

OmniRoute ਪਹਿਲੀ ਵਰਤੋਂ 'ਤੇ ਆਪਣੇ ਆਪ ਇੰਸਟਾਲ ਕਰਨ ਦੀ ਕੋਸ਼ਿਸ਼ ਕਰਦਾ ਹੈ। ਜੇ ਇੰਸਟਾਲੇਸ਼ਨ ਬਲੌਕ ਹੋਵੇ
(ਪਾਬੰਦੀਸ਼ੁਦਾ ਨੈੱਟਵਰਕ, GitHub ਤੱਕ ਪਹੁੰਚ ਨਹੀਂ), ਤਾਂ `cloudflared` ਨੂੰ
<https://github.com/cloudflare/cloudflared/releases> ਤੋਂ ਹੱਥੀਂ ਡਾਊਨਲੋਡ ਕਰੋ ਅਤੇ
`CLOUDFLARED_BIN=/path/to/cloudflared` ਸੈੱਟ ਕਰੋ।

### "ngrok: authtoken required"

`phase: "needs_auth"` ਦਾ ਅਰਥ ਹੈ ਕਿ ਕੋਈ authtoken ਨਹੀਂ ਮਿਲਿਆ। `.env` ਵਿੱਚ
`NGROK_AUTHTOKEN` ਸੈੱਟ ਕਰੋ, ਇਸਨੂੰ ਡੈਸ਼ਬੋਰਡ ਰਾਹੀਂ ਕੌਂਫਿਗਰ ਕਰੋ, ਜਾਂ enable POST
ਬਾਡੀ ਵਿੱਚ `authToken` ਪਾਸ ਕਰੋ।

### "tailscale: funnel not enabled"

ਜਦੋਂ enable ਜਵਾਬ ਵਿੱਚ `funnelNotEnabled: true` ਸ਼ਾਮਲ ਹੋਵੇ, ਤਾਂ ਤੁਹਾਡੇ tailnet ਲਈ Funnel ਅਸਮਰੱਥ
ਹੈ। ਵਾਪਸ ਮਿਲਿਆ `enableUrl` (ਜਾਂ ਐਡਮਿਨ ਕਨਸੋਲ ਦਾ ਫੀਚਰ
ਪੰਨਾ) ਖੋਲ੍ਹੋ ਅਤੇ Funnel ਨੂੰ ਚਾਲੂ ਕਰੋ।

### ਟਨਲ URL ਵਿੱਚ ਬਦਲਾਅ OAuth ਨੂੰ ਤੋੜ ਦਿੰਦੇ ਹਨ

ਰਾਖਵੇਂ ਡੋਮੇਨ ਵਾਲਾ ngrok ਜਾਂ Tailscale Funnel ਵਰਤੋ (ਦੋਵੇਂ ਪ੍ਰਤੀ-ਨੋਡ ਸਥਿਰ ਹਨ)।
Cloudflare Quick Tunnels ਡਿਜ਼ਾਈਨ ਅਨੁਸਾਰ ਅਸਥਾਈ ਹਨ ਅਤੇ ਲੰਬੇ ਸਮੇਂ ਤੱਕ ਚੱਲਣ ਵਾਲੇ
OAuth ਕਾਲਬੈਕਾਂ ਲਈ ਸਿਫ਼ਾਰਸ਼ੀ ਨਹੀਂ ਹਨ।

### Tailscale ਲਈ Linux/macOS ਉੱਤੇ ਇਜਾਜ਼ਤ ਨਾਮਨਜ਼ੂਰ

`tailscaled` ਨੂੰ root ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ। ਸੰਬੰਧਿਤ POST ਐਂਡਪੌਇੰਟ ਨੂੰ `sudoPassword` ਦਿਓ,
ਜਾਂ ਡੀਮਨ ਨੂੰ ਖੁਦ ਚਲਾਓ (`sudo systemctl start tailscaled`)।
