> **ਭੂਗੋਲਿਕ ਪਾਬੰਦੀਆਂ ਨੂੰ ਬਾਈਪਾਸ ਕਰੋ, ਆਪਣੀ ਪਛਾਣ ਸੁਰੱਖਿਅਤ ਰੱਖੋ, ਅਤੇ AI ਟ੍ਰੈਫਿਕ ਨੂੰ ਕਿਸੇ ਵੀ ਪ੍ਰੌਕਸੀ ਰਾਹੀਂ ਰੂਟ ਕਰੋ — ਬਿਨਾਂ ਕਿਸੇ ਜਟਿਲ ਕੌਂਫਿਗਰੇਸ਼ਨ ਦੇ।**

OmniRoute ਵਿੱਚ ਇੱਕ ਪੂਰੀਆਂ ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ ਵਾਲਾ ਪ੍ਰੌਕਸੀ ਪ੍ਰਬੰਧਨ ਸਿਸਟਮ ਸ਼ਾਮਲ ਹੈ, ਜੋ ਤੁਹਾਨੂੰ ਅੱਪਸਟ੍ਰੀਮ AI ਪ੍ਰਦਾਤਾ ਟ੍ਰੈਫਿਕ ਨੂੰ HTTP, HTTPS, ਜਾਂ SOCKS5 ਪ੍ਰੌਕਸੀਆਂ ਰਾਹੀਂ ਰੂਟ ਕਰਨ ਦਿੰਦਾ ਹੈ। ਭਾਵੇਂ ਤੁਸੀਂ ਕਿਸੇ ਪਾਬੰਦੀਸ਼ੁਦਾ ਖੇਤਰ ਵਿੱਚ ਹੋ, ਤੁਹਾਨੂੰ IP ਰੋਟੇਸ਼ਨ ਦੀ ਲੋੜ ਹੈ, ਜਾਂ ਤੁਸੀਂ ਗੁਪਤ ਫਿੰਗਰਪ੍ਰਿੰਟਿੰਗ ਚਾਹੁੰਦੇ ਹੋ — ਇਹ ਗਾਈਡ ਹਰ ਚੀਜ਼ ਨੂੰ ਕਵਰ ਕਰਦੀ ਹੈ।

## ਪ੍ਰੌਕਸੀਆਂ ਕਿਉਂ ਵਰਤੀਏ?

ਕਈ AI ਪ੍ਰਦਾਤਾ ਭੂਗੋਲਿਕ ਖੇਤਰ ਦੇ ਆਧਾਰ 'ਤੇ ਪਹੁੰਚ ਨੂੰ ਸੀਮਤ ਕਰਦੇ ਹਨ। **ਰੂਸ, ਚੀਨ, ਇਰਾਨ, ਕਿਊਬਾ, ਤੁਰਕੀ**, ਅਤੇ ਹੋਰ ਦੇਸ਼ਾਂ ਦੇ ਡਿਵੈਲਪਰਾਂ ਨੂੰ ਇਸ ਤਰ੍ਹਾਂ ਦੀਆਂ ਗਲਤੀਆਂ ਦਾ ਸਾਹਮਣਾ ਕਰਨਾ ਪੈਂਦਾ ਹੈ:

```
unsupported_country_region_territory
```

ਪਾਬੰਦੀਸ਼ੁਦਾ ਖੇਤਰਾਂ ਤੋਂ ਬਾਹਰ ਵੀ, ਪ੍ਰੌਕਸੀਆਂ ਹੇਠ ਲਿਖੇ ਕੰਮਾਂ ਲਈ ਲਾਭਦਾਇਕ ਹਨ:

| ਵਰਤੋਂ ਦਾ ਮਾਮਲਾ     | ਵੇਰਵਾ                                                                  |
| ------------------ | ---------------------------------------------------------------------- |
| **ਭੂਗੋਲਿਕ ਬਾਈਪਾਸ** | ਪਾਬੰਦੀਸ਼ੁਦਾ ਦੇਸ਼ਾਂ ਤੋਂ OpenAI, Anthropic, Codex, Copilot ਤੱਕ ਪਹੁੰਚ ਕਰੋ |
| **IP ਰੋਟੇਸ਼ਨ**     | ਦਰ ਸੀਮਾਬੰਦੀ ਤੋਂ ਬਚਣ ਲਈ ਬੇਨਤੀਆਂ ਨੂੰ ਕਈ IPs ਵਿੱਚ ਵੰਡੋ                    |
| **ਪਰਦੇਦਾਰੀ**       | ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰਦਾਤਾਵਾਂ ਤੋਂ ਆਪਣਾ ਅਸਲੀ IP ਲੁਕਾਓ                            |
| **ਅਨੁਪਾਲਣਾ**       | ਟ੍ਰੈਫਿਕ ਨੂੰ ਖਾਸ ਅਧਿਕਾਰ-ਖੇਤਰਾਂ ਰਾਹੀਂ ਰੂਟ ਕਰੋ                            |
| **ਟੈਸਟਿੰਗ**        | ਵੱਖ-ਵੱਖ ਖੇਤਰਾਂ ਤੋਂ ਆਉਣ ਵਾਲੀਆਂ ਬੇਨਤੀਆਂ ਦੀ ਨਕਲ ਕਰੋ                       |

## 4-ਪੱਧਰੀ ਪ੍ਰੌਕਸੀ ਸਿਸਟਮ

OmniRoute **ਚਾਰ ਸੁਤੰਤਰ ਸਕੋਪਾਂ** 'ਤੇ ਪ੍ਰੌਕਸੀ ਸੰਰਚਨਾ ਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈ, ਜਿਨ੍ਹਾਂ ਨੂੰ ਤਰਜੀਹੀ ਕ੍ਰਮ ਅਨੁਸਾਰ ਹੱਲ ਕੀਤਾ ਜਾਂਦਾ ਹੈ:

```
ਤਰਜੀਹ ਹੱਲ ਕ੍ਰਮ (ਸਭ ਤੋਂ ਉੱਚਾ → ਸਭ ਤੋਂ ਨੀਵਾਂ):

  1. 🔵 ਖਾਤਾ/ਕਨੈਕਸ਼ਨ ਪ੍ਰੌਕਸੀ  →  ਪ੍ਰਤੀ API ਕੁੰਜੀ / OAuth ਕਨੈਕਸ਼ਨ
  2. 🟡 ਪ੍ਰਦਾਤਾ ਪ੍ਰੌਕਸੀ         →  ਪ੍ਰਤੀ ਪ੍ਰਦਾਤਾ (ਉਦਾਹਰਨ ਲਈ, ਸਾਰਾ OpenAI ਟ੍ਰੈਫਿਕ)
  3. 🟠 ਕੌਂਬੋ ਪ੍ਰੌਕਸੀ           →  ਪ੍ਰਤੀ ਕੌਂਬੋ/ਰਾਊਟਿੰਗ ਸੰਰਚਨਾ
  4. 🟢 ਗਲੋਬਲ ਪ੍ਰੌਕਸੀ          →  ਸਾਰਾ ਟ੍ਰੈਫਿਕ, ਸਾਰੇ ਪ੍ਰਦਾਤਾ
```

### ਹੱਲ ਕਿਵੇਂ ਕੰਮ ਕਰਦਾ ਹੈ

ਜਦੋਂ OmniRoute ਕਿਸੇ ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰਦਾਤਾ ਨੂੰ ਬੇਨਤੀ ਭੇਜਦਾ ਹੈ, ਤਾਂ ਇਹ `resolveProxyForConnectionFromRegistry()` ਨੂੰ ਕਾਲ ਕਰਦਾ ਹੈ, ਜੋ ਹਰ ਪੱਧਰ ਦੀ ਕ੍ਰਮਵਾਰ ਜਾਂਚ ਕਰਦਾ ਹੈ:

1. **ਖਾਤਾ-ਪੱਧਰ** — ਕੀ ਇਸ ਖ਼ਾਸ ਕਨੈਕਸ਼ਨ ID ਨੂੰ ਕੋਈ ਪ੍ਰੌਕਸੀ ਨਿਰਧਾਰਤ ਕੀਤੀ ਗਈ ਹੈ?
2. **ਪ੍ਰਦਾਤਾ-ਪੱਧਰ** — ਕੀ ਇਸ ਪ੍ਰਦਾਤਾ (ਉਦਾਹਰਨ ਲਈ, `openai`) ਨੂੰ ਕੋਈ ਪ੍ਰੌਕਸੀ ਨਿਰਧਾਰਤ ਕੀਤੀ ਗਈ ਹੈ?
3. **ਗਲੋਬਲ-ਪੱਧਰ** — ਕੀ ਕੋਈ ਗਲੋਬਲ ਪ੍ਰੌਕਸੀ ਸੰਰਚਿਤ ਕੀਤੀ ਗਈ ਹੈ?
4. **ਕੋਈ ਪ੍ਰੌਕਸੀ ਨਹੀਂ** — ਪ੍ਰਦਾਤਾ ਨਾਲ ਸਿੱਧਾ ਕਨੈਕਸ਼ਨ।

ਪਹਿਲਾ ਮੇਲ ਜਿੱਤਦਾ ਹੈ। ਇਸਦਾ ਮਤਲਬ ਹੈ ਕਿ ਤੁਸੀਂ ਗਲੋਬਲ ਪ੍ਰੌਕਸੀ ਨੂੰ ਫਾਲਬੈਕ ਵਜੋਂ ਸੈੱਟ ਕਰ ਸਕਦੇ ਹੋ, ਪਰ ਖ਼ਾਸ ਪ੍ਰਦਾਤਾਵਾਂ ਜਾਂ ਕਨੈਕਸ਼ਨਾਂ ਲਈ ਇਸਨੂੰ ਓਵਰਰਾਈਡ ਕਰ ਸਕਦੇ ਹੋ।

### ਕਿਹੜੇ ਟ੍ਰੈਫਿਕ ਨੂੰ ਪ੍ਰੌਕਸੀ ਕੀਤਾ ਜਾਂਦਾ ਹੈ

| ਟ੍ਰੈਫਿਕ ਦੀ ਕਿਸਮ      | ਪ੍ਰੌਕਸੀ ਕੀਤਾ ਜਾਂਦਾ ਹੈ? | ਟਿੱਪਣੀਆਂ                                              |

## ਪ੍ਰੌਕਸੀ ਰਜਿਸਟਰੀ (CRUD)

ਪ੍ਰੌਕਸੀ ਰਜਿਸਟਰੀ ਇੱਕ SQLite ਟੇਬਲ (`proxy_registry`) ਹੈ ਜੋ ਤੁਹਾਡੀਆਂ ਸਾਰੀਆਂ ਪ੍ਰੌਕਸੀਆਂ ਨੂੰ ਸਟੋਰ ਕਰਦੀ ਹੈ। ਹਰ ਪ੍ਰੌਕਸੀ ਵਿੱਚ ਇਹ ਹੁੰਦਾ ਹੈ:

| ਫ਼ੀਲਡ      | ਕਿਸਮ     | ਵੇਰਵਾ                                             |
| ---------- | -------- | ------------------------------------------------- |
| `id`       | UUID     | ਵਿਲੱਖਣ ਪਛਾਣਕਰਤਾ                                   |
| `name`     | ਸਟ੍ਰਿੰਗ  | ਮਨੁੱਖਾਂ ਲਈ ਪੜ੍ਹਨਯੋਗ ਲੇਬਲ                          |
| `type`     | ਸਟ੍ਰਿੰਗ  | ਪ੍ਰੋਟੋਕੋਲ: `http`, `https`, `socks5`              |
| `host`     | ਸਟ੍ਰਿੰਗ  | ਪ੍ਰੌਕਸੀ ਹੋਸਟਨੇਮ ਜਾਂ IP                            |
| `port`     | ਪੂਰਨ ਅੰਕ | ਪੋਰਟ ਨੰਬਰ                                         |
| `username` | ਸਟ੍ਰਿੰਗ  | ਪ੍ਰਮਾਣੀਕਰਨ ਯੂਜ਼ਰਨੇਮ (ਸਟੋਰ ਹੋਣ ਸਮੇਂ ਇਨਕ੍ਰਿਪਟ ਕੀਤਾ) |
| `password` | ਸਟ੍ਰਿੰਗ  | ਪ੍ਰਮਾਣੀਕਰਨ ਪਾਸਵਰਡ (ਸਟੋਰ ਹੋਣ ਸਮੇਂ ਇਨਕ੍ਰਿਪਟ ਕੀਤਾ)   |
| `region`   | ਸਟ੍ਰਿੰਗ  | ਭੂਗੋਲਿਕ ਖੇਤਰ ਲੇਬਲ                                 |
| `notes`    | ਸਟ੍ਰਿੰਗ  | ਮੁਕਤ-ਲਿਖਤ ਟਿੱਪਣੀਆਂ                                |
| `status`   | ਸਟ੍ਰਿੰਗ  | `active` ਜਾਂ `inactive`                           |
| `source`   | ਸਟ੍ਰਿੰਗ  | `manual` ਜਾਂ `oneproxy`                           |

### ਪ੍ਰੌਕਸੀ ਬਣਾਉਣਾ

**ਡੈਸ਼ਬੋਰਡ ਰਾਹੀਂ:**

1. **ਸੈਟਿੰਗਾਂ → ਪ੍ਰੌਕਸੀ** 'ਤੇ ਜਾਓ
2. **ਪ੍ਰੌਕਸੀ ਸ਼ਾਮਲ ਕਰੋ** 'ਤੇ ਕਲਿੱਕ ਕਰੋ
3. ਕਿਸਮ, ਹੋਸਟ, ਪੋਰਟ ਅਤੇ ਵਿਕਲਪਿਕ ਪ੍ਰਮਾਣੀਕਰਨ ਵੇਰਵੇ ਭਰੋ
4. ਸੇਵ ਕਰੋ

**API ਰਾਹੀਂ:**

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "US Proxy",
    "type": "http",
    "host": "proxy.example.com",
    "port": 8080,
    "username": "user",
    "password": "pass",
    "region": "US"
  }'
```

### ਪ੍ਰੌਕਸੀ ਅੱਪਡੇਟ ਕਰਨਾ

```bash
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "id": "proxy-uuid-here",
    "host": "new-proxy.example.com",
    "port": 9090
  }'
```

> **ਨੋਟ:** ਪ੍ਰਮਾਣੀਕਰਨ ਵੇਰਵੇ ਉਦੋਂ ਤੱਕ ਸੁਰੱਖਿਅਤ ਰਹਿੰਦੇ ਹਨ ਜਦੋਂ ਤੱਕ ਤੁਸੀਂ ਸਪਸ਼ਟ ਤੌਰ 'ਤੇ ਗ਼ੈਰ-ਖ਼ਾਲੀ ਬਦਲ ਭੇਜਦੇ ਨਹੀਂ ਹੋ। `username`/`password` ਲਈ ਖ਼ਾਲੀ ਸਟ੍ਰਿੰਗਾਂ ਭੇਜਣ ਨਾਲ ਸਟੋਰ ਕੀਤੇ ਮੁੱਲ ਕਾਇਮ ਰਹਿਣਗੇ।

### ਪ੍ਰੌਕਸੀ ਮਿਟਾਉਣਾ

```bash
# ਜੇ ਪ੍ਰੌਕਸੀ ਕਿਸੇ ਵੀ ਸਕੋਪ ਨੂੰ ਨਿਰਧਾਰਤ ਕੀਤੀ ਗਈ ਹੈ ਤਾਂ ਇਹ ਅਸਫਲ ਹੁੰਦਾ ਹੈ
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid"

# ਜ਼ਬਰਦਸਤੀ ਮਿਟਾਓ (ਨਿਰਧਾਰਨ ਵੀ ਹਟਾਉਂਦਾ ਹੈ)
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid&force=1"
```

### ਪ੍ਰੌਕਸੀਆਂ ਦੀ ਸੂਚੀ ਬਣਾਉਣਾ

```bash
curl "http://localhost:20128/api/v1/management/proxies?limit=50&offset=0"
```

### ਸਕੋਪਾਂ ਨੂੰ ਪ੍ਰੌਕਸੀਆਂ ਨਿਰਧਾਰਤ ਕਰਨਾ

```bash
# ਗਲੋਬਲ ਸਕੋਪ ਨੂੰ ਨਿਰਧਾਰਤ ਕਰੋ
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "global", "proxy": {"type":"http","host":"proxy.example.com","port":8080}}'

# ਕਿਸੇ ਖ਼ਾਸ ਪ੍ਰਦਾਤਾ ਨੂੰ ਨਿਰਧਾਰਤ ਕਰੋ
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "provider", "id": "openai", "proxy": {"type":"socks5","host":"socks.example.com","port":1080}}'

# ਕਿਸੇ ਖ਼ਾਸ ਕਨੈਕਸ਼ਨ/ਕੁੰਜੀ ਨੂੰ ਨਿਰਧਾਰਤ ਕਰੋ
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "key", "id": "connection-uuid", "proxy": {"type":"http","host":"key-proxy.com","port":3128}}'
```

### ਪ੍ਰਭਾਵੀ ਪ੍ਰੌਕਸੀ ਹੱਲ ਕਰਨਾ

ਜਾਂਚੋ ਕਿ ਦਿੱਤੇ ਕਨੈਕਸ਼ਨ ਲਈ ਕਿਹੜੀ ਪ੍ਰੌਕਸੀ ਵਰਤੀ ਜਾਵੇਗੀ:

```bash
curl "http://localhost:20128/api/settings/proxy?resolve=connection-uuid"
```

ਇਹ ਹੱਲ ਕੀਤੀ ਪ੍ਰੌਕਸੀ ਨੂੰ ਉਸਦੇ ਪੱਧਰ (`account`, `provider`, ਜਾਂ `global`) ਅਤੇ ਸਰੋਤ ਸਮੇਤ ਵਾਪਸ ਕਰਦਾ ਹੈ।

### ਬਲਕ ਨਿਰਧਾਰਨ

ਇੱਕ ਪ੍ਰੌਕਸੀ ਨੂੰ ਇੱਕੋ ਵਾਰ ਕਈ ਪ੍ਰਦਾਤਾਵਾਂ ਜਾਂ ਕਨੈਕਸ਼ਨਾਂ ਨੂੰ ਨਿਰਧਾਰਤ ਕਰੋ:

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies/bulk-assign \
  -H "Content-Type: application/json" \
  -d '{
    "scope": "provider",
    "scopeIds": ["openai", "anthropic", "codex"],
    "proxyId": "proxy-uuid"
  }'
```

### ਆਯਾਤ/ਨਿਰਯਾਤ

ਪ੍ਰੌਕਸੀਆਂ **ਬੈਕਅੱਪ/ਰੀਸਟੋਰ** ਸਿਸਟਮ ਵਿੱਚ ਸ਼ਾਮਲ ਹੁੰਦੀਆਂ ਹਨ। ਜਦੋਂ ਤੁਸੀਂ ਆਪਣੀ OmniRoute ਸੰਰਚਨਾ ਨਿਰਯਾਤ ਕਰਦੇ ਹੋ:

1. **ਡੈਸ਼ਬੋਰਡ → ਸੈਟਿੰਗਾਂ → ਬੈਕਅੱਪ** 'ਤੇ ਜਾਓ
2. **ਨਿਰਯਾਤ** 'ਤੇ ਕਲਿੱਕ ਕਰੋ — ਪ੍ਰੌਕਸੀ ਰਜਿਸਟਰੀ ਅਤੇ ਨਿਰਧਾਰਨ ਸ਼ਾਮਲ ਹੁੰਦੇ ਹਨ
3. ਰੀਸਟੋਰ ਕਰਨ ਲਈ, **ਆਯਾਤ** 'ਤੇ ਕਲਿੱਕ ਕਰੋ ਅਤੇ ਬੈਕਅੱਪ ਫ਼ਾਈਲ ਅੱਪਲੋਡ ਕਰੋ

ਪ੍ਰੌਕਸੀ ਰਜਿਸਟਰੀ **host+port ਦੁਆਰਾ upsert** ਦਾ ਵੀ ਸਮਰਥਨ ਕਰਦੀ ਹੈ — ਜੇ ਤੁਸੀਂ ਪਹਿਲਾਂ ਤੋਂ ਮੌਜੂਦ ਪ੍ਰੌਕਸੀ (ਇੱਕੋ ਹੋਸਟ ਅਤੇ ਪੋਰਟ ਵਾਲੀ) ਆਯਾਤ ਕਰਦੇ ਹੋ, ਤਾਂ ਡੁਪਲੀਕੇਟ ਬਣਾਉਣ ਦੀ ਬਜਾਏ ਇਸਨੂੰ ਅੱਪਡੇਟ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।

### ਲੈਗੇਸੀ ਮਾਈਗ੍ਰੇਸ਼ਨ

ਜੇ ਤੁਸੀਂ ਕਿਸੇ ਪੁਰਾਣੇ ਵਰਜਨ (ਰਜਿਸਟਰੀ ਤੋਂ ਪਹਿਲਾਂ ਵਾਲੇ) ਵਿੱਚ ਪ੍ਰਾਕਸੀਆਂ ਕੌਂਫਿਗਰ ਕੀਤੀਆਂ ਸਨ, ਤਾਂ OmniRoute ਉਹਨਾਂ ਨੂੰ ਆਪਣੇ-ਆਪ ਮਾਈਗ੍ਰੇਟ ਕਰਦਾ ਹੈ:

```
ਪੁਰਾਣਾ key_value ਸਟੋਰ → proxy_registry + proxy_assignments
```

ਇਹ ਅੱਪਗ੍ਰੇਡ ਤੋਂ ਬਾਅਦ ਪਹਿਲੀ ਵਾਰ ਸਟਾਰਟ ਹੋਣ 'ਤੇ ਇੱਕ ਵਾਰ ਹੁੰਦਾ ਹੈ। ਦੁਬਾਰਾ ਚਲਾਉਣ ਲਈ `migrateLegacyProxyConfigToRegistry({ force: true })` ਦੀ ਵਰਤੋਂ ਕਰੋ।

## 1proxy ਮੁਫ਼ਤ ਪ੍ਰਾਕਸੀ ਮਾਰਕੀਟਪਲੇਸ

> 🆕 **[@oyi77](https://github.com/oyi77) ਵੱਲੋਂ ਯੋਗਦਾਨ** — PR [#1847](https://github.com/diegosouzapw/OmniRoute/pull/1847) (ਮੁੱਦਾ [#1788](https://github.com/diegosouzapw/OmniRoute/issues/1788))

OmniRoute ਦੁਨੀਆ ਭਰ ਦੀਆਂ **ਸੈਂਕੜੇ ਮੁਫ਼ਤ, ਪ੍ਰਮਾਣਿਤ ਪ੍ਰਾਕਸੀਆਂ** ਤੱਕ ਪਹੁੰਚ ਪ੍ਰਦਾਨ ਕਰਨ ਲਈ **[1proxy](https://1proxy-api.aitradepulse.com)** ਕਮਿਊਨਿਟੀ ਪਲੇਟਫਾਰਮ ਨਾਲ ਏਕੀਕ੍ਰਿਤ ਹੁੰਦਾ ਹੈ। ਇਹ ਉਹਨਾਂ ਵਰਤੋਂਕਾਰਾਂ ਲਈ ਉੱਤਮ ਹੈ ਜਿਨ੍ਹਾਂ ਕੋਲ ਆਪਣਾ ਪ੍ਰਾਕਸੀ ਬੁਨਿਆਦੀ ਢਾਂਚਾ ਨਹੀਂ ਹੈ।

### ਇਹ ਕਿਵੇਂ ਕੰਮ ਕਰਦਾ ਹੈ

```
┌─────────────┐     ਸਿੰਕ      ┌─────────────────┐    ਰੋਟੇਟ     ┌──────────┐
│  1proxy API │ ────────────▶ │  proxy_registry  │ ────────────▶ │ ਪ੍ਰਦਾਤਾ  │
│   (ਬਾਹਰੀ)   │    500 ਤੱਕ    │  source=oneproxy │ ਗੁਣਵੱਤਾ ਅਨੁਸਾਰ │   API    │
└─────────────┘   ਪ੍ਰਾਕਸੀਆਂ   └─────────────────┘               └──────────┘
```

1. **ਸਿੰਕ** — OmniRoute, 1proxy API ਤੋਂ ਪ੍ਰਮਾਣਿਤ ਪ੍ਰਾਕਸੀਆਂ ਪ੍ਰਾਪਤ ਕਰਦਾ ਹੈ
2. **ਸਟੋਰ** — ਪ੍ਰਾਕਸੀਆਂ ਉਸੇ `proxy_registry` ਟੇਬਲ ਵਿੱਚ `source = 'oneproxy'` ਨਾਲ ਸੰਭਾਲੀਆਂ ਜਾਂਦੀਆਂ ਹਨ
3. **ਫਿਲਟਰ** — ਪ੍ਰੋਟੋਕੋਲ, ਦੇਸ਼ ਅਤੇ ਗੁਣਵੱਤਾ ਸਕੋਰ ਅਨੁਸਾਰ ਫਿਲਟਰ ਕਰੋ
4. **ਰੋਟੇਟ** — ਗੁਣਵੱਤਾ, ਬੇਤਰਤੀਬ ਜਾਂ ਕ੍ਰਮਵਾਰ ਰਣਨੀਤੀਆਂ ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਸਭ ਤੋਂ ਵਧੀਆ ਪ੍ਰਾਕਸੀ ਚੁਣੋ
5. **ਆਟੋ-ਡੀਗ੍ਰੇਡ** — ਅਸਫਲ ਪ੍ਰਾਕਸੀਆਂ ਦਾ ਗੁਣਵੱਤਾ ਸਕੋਰ ਘਟਾਇਆ ਜਾਂਦਾ ਹੈ; ਥ੍ਰੈਸ਼ਹੋਲਡ ਤੋਂ ਹੇਠਾਂ → ਅਕਿਰਿਆਸ਼ੀਲ ਵਜੋਂ ਚਿੰਨ੍ਹਿਤ

### ਪ੍ਰਾਕਸੀਆਂ ਨੂੰ ਸਿੰਕ ਕਰਨਾ

**ਡੈਸ਼ਬੋਰਡ ਰਾਹੀਂ:**

1. **ਸੈਟਿੰਗਾਂ → 1proxy** ਟੈਬ 'ਤੇ ਜਾਓ
2. **"ਹੁਣੇ ਸਿੰਕ ਕਰੋ"** 'ਤੇ ਕਲਿੱਕ ਕਰੋ
3. ਅੰਕੜੇ ਵੇਖੋ: ਕੁੱਲ ਪ੍ਰਾਕਸੀਆਂ, ਕਿਰਿਆਸ਼ੀਲ ਗਿਣਤੀ, ਔਸਤ ਗੁਣਵੱਤਾ ਅਤੇ ਦੇਸ਼-ਅਨੁਸਾਰ ਵੇਰਵਾ

**API ਰਾਹੀਂ:**

```bash
# ਸਿੰਕ ਸ਼ੁਰੂ ਕਰੋ
curl -X POST http://localhost:20128/api/settings/oneproxy \
  -H "Content-Type: application/json" \
  -d '{}'

# ਜਵਾਬ:
# { "success": true, "added": 127, "updated": 45, "failed": 2, "total": 172 }
```

### ਪ੍ਰਾਕਸੀਆਂ ਨੂੰ ਫਿਲਟਰ ਕਰਨਾ

```bash
# ਪ੍ਰੋਟੋਕੋਲ ਅਨੁਸਾਰ ਫਿਲਟਰ ਕਰੋ
curl "http://localhost:20128/api/settings/oneproxy?protocol=socks5"

# ਦੇਸ਼ ਅਨੁਸਾਰ ਫਿਲਟਰ ਕਰੋ
curl "http://localhost:20128/api/settings/oneproxy?countryCode=US"

# ਘੱਟੋ-ਘੱਟ ਗੁਣਵੱਤਾ ਸਕੋਰ ਅਨੁਸਾਰ ਫਿਲਟਰ ਕਰੋ
curl "http://localhost:20128/api/settings/oneproxy?minQuality=80"

# ਫਿਲਟਰਾਂ ਨੂੰ ਜੋੜੋ
curl "http://localhost:20128/api/settings/oneproxy?protocol=http&countryCode=DE&minQuality=70"
```

### ਪ੍ਰਾਕਸੀ ਗੁਣਵੱਤਾ ਸਕੋਰ

ਹਰੇਕ 1proxy ਪ੍ਰਾਕਸੀ ਨਾਲ ਮੈਟਾਡੇਟਾ ਆਉਂਦਾ ਹੈ:

| ਫੀਲਡ            | ਵੇਰਵਾ                                          |
| --------------- | ---------------------------------------------- |
| `qualityScore`  | 1proxy ਪ੍ਰਮਾਣਿਕਤਾ ਤੋਂ ਮਿਲੀ 0-100 ਰੇਟਿੰਗ        |
| `latencyMs`     | ਮਾਪੀ ਗਈ ਨੈੱਟਵਰਕ ਲੇਟੈਂਸੀ                        |
| `anonymity`     | `transparent`, `anonymous`, ਜਾਂ `elite`        |
| `googleAccess`  | ਕੀ ਪ੍ਰਾਕਸੀ Google ਸੇਵਾਵਾਂ ਤੱਕ ਪਹੁੰਚ ਕਰ ਸਕਦੀ ਹੈ |
| `countryCode`   | ਦੋ-ਅੱਖਰੀ ISO ਦੇਸ਼ ਕੋਡ                          |
| `lastValidated` | ਆਖਰੀ ਪ੍ਰਮਾਣਿਕਤਾ ਦਾ ਟਾਈਮਸਟੈਂਪ                   |

ਗੁਣਵੱਤਾ ਸਕੋਰ ਗਤੀਸ਼ੀਲ ਢੰਗ ਨਾਲ ਵਿਵਸਥਿਤ ਕੀਤੇ ਜਾਂਦੇ ਹਨ:

- **ਅਸਫਲ ਬੇਨਤੀਆਂ** ਸਕੋਰ ਨੂੰ 10 ਅੰਕ ਘਟਾਉਂਦੀਆਂ ਹਨ
- **ਸਕੋਰ ≤10 ਤੱਕ ਡਿੱਗਦਾ ਹੈ** → ਪ੍ਰਾਕਸੀ ਨੂੰ `inactive` ਵਜੋਂ ਚਿੰਨ੍ਹਿਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ
- ਅਕਿਰਿਆਸ਼ੀਲ ਪ੍ਰਾਕਸੀਆਂ ਨੂੰ ਰੋਟੇਸ਼ਨ ਵਿੱਚੋਂ ਬਾਹਰ ਰੱਖਿਆ ਜਾਂਦਾ ਹੈ

### ਰੋਟੇਸ਼ਨ ਰਣਨੀਤੀਆਂ

```bash
# ਗੁਣਵੱਤਾ ਅਨੁਸਾਰ ਰੋਟੇਟ ਕਰੋ (ਸਭ ਤੋਂ ਵਧੀਆ ਪ੍ਰਾਕਸੀ ਪਹਿਲਾਂ) — ਡਿਫਾਲਟ
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -H "Content-Type: application/json" \
  -d '{"strategy": "quality"}'

# ਬੇਤਰਤੀਬ ਰੋਟੇਸ਼ਨ
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -d '{"strategy": "random"}'

# ਕ੍ਰਮਵਾਰ (ਸਭ ਤੋਂ ਪਹਿਲਾਂ ਉਹ ਜੋ ਸਭ ਤੋਂ ਲੰਮੇ ਸਮੇਂ ਤੋਂ ਪ੍ਰਮਾਣਿਤ ਨਹੀਂ ਹੋਈ)
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -d '{"strategy": "sequential"}'
```

### ਸਰਕਿਟ ਬ੍ਰੇਕਰ

1proxy ਸਿੰਕ ਵਿੱਚ ਇੱਕ ਬਿਲਟ-ਇਨ ਸਰਕਿਟ ਬ੍ਰੇਕਰ ਹੈ:

- **ਲਗਾਤਾਰ 5 ਸਿੰਕ ਅਸਫਲਤਾਵਾਂ** ਤੋਂ ਬਾਅਦ, ਅਗਲੀਆਂ ਸਿੰਕ ਕੋਸ਼ਿਸ਼ਾਂ ਨੂੰ ਬਲੌਕ ਕਰ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ
- ਇਸ ਨਾਲ ਰੀਸੈੱਟ ਕਰੋ: `resetOneproxyCircuitBreaker()` ਜਾਂ ਸਰਵਰ ਨੂੰ ਮੁੜ ਚਾਲੂ ਕਰੋ
- ਸਿੰਕ ਸਥਿਤੀ `GET /api/settings/oneproxy?action=status` 'ਤੇ ਉਪਲਬਧ ਹੈ

### 1proxy ਪ੍ਰਾਕਸੀਆਂ ਨੂੰ ਸਾਫ਼ ਕਰਨਾ

```bash
# ਇੱਕ 1proxy ਪ੍ਰਾਕਸੀ ਮਿਟਾਓ

curl -X DELETE "http://localhost:20128/api/settings/oneproxy?clearAll=1"
```

## ਐਂਟੀ-ਡਿਟੈਕਸ਼ਨ ਅਤੇ ਸਟੀਲਥ

OmniRoute ਸਿਰਫ਼ ਟ੍ਰੈਫਿਕ ਨੂੰ ਪ੍ਰੌਕਸੀ ਰਾਹੀਂ ਰੂਟ ਹੀ ਨਹੀਂ ਕਰਦਾ — ਇਹ ਟ੍ਰੈਫਿਕ ਨੂੰ ਵੈਧ ਵੀ ਦਿਖਾਉਂਦਾ ਹੈ:

### TLS ਫਿੰਗਰਪ੍ਰਿੰਟ ਸਪੂਫ਼ਿੰਗ

ਬ੍ਰਾਊਜ਼ਰ ਵਰਗੇ TLS ਫਿੰਗਰਪ੍ਰਿੰਟ ਬਣਾਉਣ ਲਈ `wreq-js` ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ, ਜਿਸ ਨਾਲ ਗੈਰ-ਬ੍ਰਾਊਜ਼ਰ TLS ਹੈਂਡਸ਼ੇਕਾਂ ਨੂੰ ਫਲੈਗ ਕਰਨ ਵਾਲੀਆਂ ਬੌਟ ਡਿਟੈਕਸ਼ਨ ਪ੍ਰਣਾਲੀਆਂ ਨੂੰ ਬਾਈਪਾਸ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।

### CLI ਫਿੰਗਰਪ੍ਰਿੰਟ ਮੈਚਿੰਗ

**CLI ਫਿੰਗਰਪ੍ਰਿੰਟ ਟੌਗਲ** (`Settings → Security`) HTTP ਹੈਡਰਾਂ ਅਤੇ JSON ਬਾਡੀ ਫੀਲਡਾਂ ਨੂੰ ਮੁੜ ਕ੍ਰਮਬੱਧ ਕਰਦਾ ਹੈ, ਤਾਂ ਜੋ ਉਹ ਨੇਟਿਵ CLI ਬਾਈਨਰੀਆਂ (Claude Code, Codex, ਆਦਿ) ਦੇ ਬਿਲਕੁਲ ਸਹੀ ਸਿਗਨੇਚਰ ਨਾਲ ਮੇਲ ਖਾਣ। ਇਹ ਪ੍ਰੌਕਸੀ ਦੇ **ਉੱਪਰ ਵਾਧੂ ਪਰਤ ਵਜੋਂ** ਕੰਮ ਕਰਦਾ ਹੈ:

```
ਤੁਹਾਡਾ IP (ਬਲੌਕ ਕੀਤਾ) → ਪ੍ਰੌਕਸੀ IP (US) → ਪ੍ਰਦਾਤਾ API
                          + TLS ਸਪੂਫ਼
                          + CLI ਫਿੰਗਰਪ੍ਰਿੰਟ
```

ਤੁਹਾਨੂੰ ਇੱਕੋ ਸਮੇਂ **IP ਮਾਸਕਿੰਗ** ਅਤੇ **ਬੇਨਤੀ ਦੀ ਪ੍ਰਮਾਣਿਕਤਾ** ਦੋਵੇਂ ਮਿਲਦੇ ਹਨ।

### ਪ੍ਰੌਕਸੀ IP ਦੀ ਸੰਭਾਲ

ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ ਰੰਗ-ਕੋਡ ਕੀਤੇ ਬੈਜ ਦਿਖਾਉਂਦੇ ਹਨ ਕਿ ਕਿਹੜਾ ਪ੍ਰੌਕਸੀ ਪੱਧਰ ਸਰਗਰਮ ਹੈ:

| ਬੈਜ | ਪੱਧਰ    | ਅਰਥ                                            |
| --- | ------- | ---------------------------------------------- |
| 🟢  | ਗਲੋਬਲ   | ਸਾਰਾ ਟ੍ਰੈਫਿਕ ਇਸ ਪ੍ਰੌਕਸੀ ਰਾਹੀਂ ਜਾਂਦਾ ਹੈ         |
| 🟡  | ਪ੍ਰਦਾਤਾ | ਸਿਰਫ਼ ਇਸ ਪ੍ਰਦਾਤਾ ਦਾ ਟ੍ਰੈਫਿਕ ਪ੍ਰੌਕਸੀ ਹੁੰਦਾ ਹੈ   |
| 🔵  | ਕਨੈਕਸ਼ਨ | ਇਹ ਖ਼ਾਸ ਕੁੰਜੀ/ਖਾਤਾ ਇਸ ਪ੍ਰੌਕਸੀ ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ |

ਬੈਜ ਪੁਸ਼ਟੀ ਲਈ ਰਿਜ਼ੌਲਵ ਕੀਤਾ ਪ੍ਰੌਕਸੀ IP ਵੀ ਦਿਖਾਉਂਦਾ ਹੈ।

## ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰੌਕਸੀ ਮੋਡ

CLIProxyAPI ਪੈਟਰਨ ਦੀ ਵਰਤੋਂ ਕਰਨ ਵਾਲੇ ਪ੍ਰਦਾਤਾਵਾਂ ਲਈ, OmniRoute ਤਿੰਨ ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰੌਕਸੀ ਮੋਡਾਂ ਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈ:

| ਮੋਡ           | ਵੇਰਵਾ                                                      |
| ------------- | ---------------------------------------------------------- |
| `native`      | OmniRoute ਸਿੱਧੇ ਤੌਰ 'ਤੇ ਪ੍ਰੌਕਸੀ ਰੂਟਿੰਗ ਸੰਭਾਲਦਾ ਹੈ (ਡਿਫੌਲਟ) |
| `cliproxyapi` | ਕਿਸੇ ਬਾਹਰੀ CLIProxyAPI ਇੰਸਟੈਂਸ ਨੂੰ ਸੌਂਪਦਾ ਹੈ               |
| `fallback`    | ਪਹਿਲਾਂ ਨੇਟਿਵ ਦੀ ਕੋਸ਼ਿਸ਼ ਕਰਦਾ ਹੈ, ਫਿਰ CLIProxyAPI ਵਰਤਦਾ ਹੈ  |

ਹਰੇਕ ਪ੍ਰਦਾਤਾ ਲਈ ਸੰਰਚਿਤ ਕਰੋ:

```bash
curl -X PUT "http://localhost:20128/api/upstream-proxy/openai" \
  -H "Content-Type: application/json" \
  -d '{"mode": "native", "enabled": true}'
```

## ਸਮੱਸਿਆ-ਨਿਵਾਰਣ

### "SOCKS5 ਪ੍ਰਾਕਸੀ ਅਸਮਰੱਥ ਹੈ"

ਆਪਣੀ `.env` ਫ਼ਾਈਲ ਵਿੱਚ `ENABLE_SOCKS5_PROXY=true` ਸੈੱਟ ਕਰੋ ਅਤੇ ਮੁੜ-ਚਾਲੂ ਕਰੋ।

### ਪ੍ਰਾਕਸੀ ਰਾਹੀਂ "socket hang up" ਤਰੁੱਟੀਆਂ

ਇਹ ਸਸਤੀਆਂ ਪ੍ਰਾਕਸੀਆਂ ਨਾਲ ਆਮ ਗੱਲ ਹੈ ਜੋ ਨਿਸ਼ਕਿਰਿਆ ਕਨੈਕਸ਼ਨਾਂ ਨੂੰ ਬੰਦ ਕਰ ਦਿੰਦੀਆਂ ਹਨ। OmniRoute ਪਹਿਲਾਂ ਹੀ ਇਸਨੂੰ ਇਸ ਤਰ੍ਹਾਂ ਸੰਭਾਲਦਾ ਹੈ:

- ਪ੍ਰਾਕਸੀ ਕਨੈਕਸ਼ਨਾਂ ਉੱਤੇ keep-alive ਨੂੰ ਅਸਮਰੱਥ ਕਰਕੇ (`keepAliveTimeout: 1`)
- ਪਾਈਪਲਾਈਨਿੰਗ ਨੂੰ ਅਸਮਰੱਥ ਕਰਕੇ (`pipelining: 0`)
- ਵਾਰ-ਵਾਰ ਹੋਣ ਵਾਲੇ ਹੈਂਡਸ਼ੇਕਾਂ ਤੋਂ ਬਚਣ ਲਈ ਡਿਸਪੈਚਰਾਂ ਨੂੰ ਕੈਸ਼ ਕਰਕੇ

ਜੇ ਇਹ ਸਮੱਸਿਆ ਜਾਰੀ ਰਹਿੰਦੀ ਹੈ, ਤਾਂ ਕੋਈ ਹੋਰ ਪ੍ਰਾਕਸੀ ਅਜ਼ਮਾਓ ਜਾਂ 1proxy ਰੋਟੇਸ਼ਨ ਵਿਸ਼ੇਸ਼ਤਾ ਵਰਤੋ।

### OAuth ਦੌਰਾਨ "unsupported_country_region_territory"

ਯਕੀਨੀ ਬਣਾਓ ਕਿ OAuth ਪ੍ਰਵਾਹ ਸ਼ੁਰੂ ਕਰਨ ਤੋਂ **ਪਹਿਲਾਂ** ਪ੍ਰਾਕਸੀ ਕੌਂਫਿਗਰ ਕੀਤੀ ਗਈ ਹੈ। OmniRoute OAuth ਟੋਕਨ ਐਕਸਚੇਂਜ ਨੂੰ ਕੌਂਫਿਗਰ ਕੀਤੀ ਪ੍ਰਾਕਸੀ ਰਾਹੀਂ ਰੂਟ ਕਰਦਾ ਹੈ। ਪਹਿਲਾਂ ਗਲੋਬਲ ਜਾਂ ਪ੍ਰਦਾਤਾ-ਪੱਧਰ ਦੀ ਪ੍ਰਾਕਸੀ ਸੈੱਟ ਕਰੋ, ਫਿਰ ਕਨੈਕਟ ਕਰੋ।

### ਪ੍ਰਾਕਸੀ ਦੀ ਵਰਤੋਂ ਨਹੀਂ ਹੋ ਰਹੀ

ਰਿਜ਼ੋਲਿਊਸ਼ਨ ਕ੍ਰਮ ਦੀ ਜਾਂਚ ਕਰੋ:

1. `GET /api/settings/proxy?resolve=your-connection-id` ਨਾਲ ਪੁਸ਼ਟੀ ਕਰੋ
2. ਜਾਂਚੋ ਕਿ ਪ੍ਰਾਕਸੀ ਦਾ `status`, `active` ਹੈ (`inactive` ਨਹੀਂ)
3. ਯਕੀਨੀ ਬਣਾਓ ਕਿ ਪ੍ਰਾਕਸੀ ਅਸਾਈਨਮੈਂਟ ਦਾ ਸਕੋਪ ਤੁਹਾਡੇ ਕਨੈਕਸ਼ਨ ਨਾਲ ਮੇਲ ਖਾਂਦਾ ਹੈ

### 1proxy ਸਿੰਕ ਅਸਫਲ ਹੋ ਰਿਹਾ ਹੈ

ਸਿੰਕ ਸਥਿਤੀ ਦੀ ਜਾਂਚ ਕਰੋ:

```bash
curl "http://localhost:20128/api/settings/oneproxy?action=status"
```

ਜੇ `consecutiveFailures >= 5` ਹੈ, ਤਾਂ ਸਰਕਿਟ ਬ੍ਰੇਕਰ ਟ੍ਰਿਪ ਹੋ ਗਿਆ ਹੈ। ਰੀਸੈੱਟ ਕਰਨ ਲਈ ਸਰਵਰ ਨੂੰ ਮੁੜ-ਚਾਲੂ ਕਰੋ, ਜਾਂ ਮੈਨੁਅਲ ਰੀਸੈੱਟ ਦੀ ਉਡੀਕ ਕਰੋ।

## ਪ੍ਰਾਕਸੀ ਸਿਹਤ ਜਾਂਚ (v3.8.16+)

OmniRoute ਦਾ **ਪ੍ਰਾਕਸੀ ਫਾਸਟ-ਫੇਲ** ਤੰਤਰ (`src/lib/proxyHealth.ts`) ਇੱਕ ਤੇਜ਼ TCP ਕਨੈਕਸ਼ਨ ਜਾਂਚ ਰਾਹੀਂ <2s ਵਿੱਚ ਬੰਦ ਪ੍ਰਾਕਸੀਆਂ ਦਾ ਪਤਾ ਲਗਾਉਂਦਾ ਹੈ, ਫਿਰ ਹਰ ਬੇਨਤੀ ਦੇ ਵਾਧੂ ਖ਼ਰਚ ਤੋਂ ਬਚਣ ਲਈ **ਨਤੀਜੇ ਨੂੰ ਕੈਸ਼ ਕਰਦਾ ਹੈ**।

### ਇਹ ਕਿਵੇਂ ਕੰਮ ਕਰਦਾ ਹੈ

```
ਬੇਨਤੀ ──▶ ProxyHealthCache.get(url)
             │
             ├─ ਕੈਸ਼ ਹਿੱਟ + ਤਾਜ਼ਾ?  ──▶ ਕੈਸ਼ ਕੀਤੀ ਸਥਿਤੀ ਵਾਪਸ ਕਰੋ
             │
             └─ ਕੈਸ਼ ਮਿਸ / ਪੁਰਾਣਾ?  ──▶ host:port ਨਾਲ TCP ਕਨੈਕਟ ਕਰੋ
                                          (ਟਾਈਮਆਉਟ: FAST_FAIL_TIMEOUT_MS)
                                          ──▶ HEALTH_CACHE_TTL_MS ਲਈ ਕੈਸ਼ ਕਰੋ
                                          ──▶ ਨਤੀਜਾ ਵਾਪਸ ਕਰੋ
```

ਇਸ ਤੋਂ ਬਿਨਾਂ, ਕੋਈ ਬੰਦ ਪ੍ਰਾਕਸੀ ਅਸਫਲ ਹੋਣ ਤੋਂ ਪਹਿਲਾਂ ਹਰ ਬੇਨਤੀ ਨੂੰ ਪੂਰੇ `PROXY_TIMEOUT_MS` (ਡਿਫੌਲਟ 30s) ਲਈ ਰੋਕ ਦੇਵੇਗੀ।

### ਬਦਲਣਯੋਗ ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲ

| ਵੇਰੀਏਬਲ                      | ਡਿਫੌਲਟ  | ਉਦੇਸ਼                                     |
| ---------------------------- | ------- | ----------------------------------------- |
| `PROXY_FAST_FAIL_TIMEOUT_MS` | `2000`  | ਪ੍ਰਤੀ ਸਿਹਤ ਜਾਂਚ TCP ਕਨੈਕਸ਼ਨ ਟਾਈਮਆਉਟ       |
| `PROXY_HEALTH_CACHE_TTL_MS`  | `30000` | ਸਿਹਤ ਨਤੀਜੇ ਨੂੰ ਕਿੰਨੇ ਸਮੇਂ ਲਈ ਕੈਸ਼ ਕਰਨਾ ਹੈ |

**ਸਿਫ਼ਾਰਸ਼ੀ ਮੁੱਲ:**

| ਸਥਿਤੀ                    | ਫਾਸਟ-ਫੇਲ ਟਾਈਮਆਉਟ | ਕੈਸ਼ TTL | ਤਰਕ                                                               |
| ------------------------ | ---------------- | -------- | ----------------------------------------------------------------- |
| ਉੱਚ-ਥਰੂਪੁੱਟ API ਗੇਟਵੇ    | 1500ms           | 60000ms  | ਹਮਲਾਵਰ ਢੰਗ ਨਾਲ ਜਲਦੀ ਅਸਫਲ ਹੋਣਾ, ਜਾਂਚਾਂ ਘਟਾਉਣ ਲਈ ਲੰਮਾ ਕੈਸ਼          |
| ਭੂਗੋਲਿਕ ਤੌਰ 'ਤੇ ਵੰਡੇ ਨੋਡ | 3000ms           | 15000ms  | ਹੌਲੀ ਨੈੱਟਵਰਕਾਂ ਨੂੰ ਵਧੇਰੇ ਸਮਾਂ ਚਾਹੀਦਾ ਹੈ; ਤੇਜ਼ ਫੇਲਓਵਰ ਲਈ ਛੋਟਾ ਕੈਸ਼ |
| ਵਿਕਾਸ / ਟੈਸਟਿੰਗ          | 1000ms           | 10000ms  | ਸਥਾਨਕ ਪ੍ਰਾਕਸੀਆਂ ਉੱਤੇ ਤੇਜ਼ ਦੁਹਰਾਅ                                  |
| ਗੁਪਤ / ਐਂਟੀ-ਡਿਟੈਕਸ਼ਨ     | 2500ms           | 45000ms  | ਤੇਜ਼ ਪ੍ਰੋਬਿੰਗ ਤੋਂ ਬਚੋ ਜੋ ਦਰ ਸੀਮਾਵਾਂ ਨੂੰ ਟ੍ਰਿਗਰ ਕਰ ਸਕਦੀ ਹੈ         |

### ਪ੍ਰਾਕਸੀ ਸਿਹਤ ਦੀ ਜਾਂਚ ਕਰਨਾ

```ts
import { getAllProxyHealthStatuses, invalidateProxyHealth } from "omniroute/proxyHealth";

const statuses = getAllProxyHealthStatuses();
for (const s of statuses) {
  console.log(`${s.proxyUrl} → healthy=${s.healthy}, stale=${s.stale}`);
}

// ਕਿਸੇ ਖ਼ਾਸ ਪ੍ਰਾਕਸੀ ਦੀ ਮੁੜ-ਜਾਂਚ ਲਈ ਮਜਬੂਰ ਕਰੋ
invalidateProxyHealth("http://user:pass@203.0.113.7:8080");
```

ਜਦੋਂ ਕੈਸ਼ ਐਂਟਰੀ `HEALTH_CACHE_TTL_MS` ਤੋਂ ਵੱਧ ਪੁਰਾਣੀ ਹੋ ਜਾਂਦੀ ਹੈ ਅਤੇ ਅਗਲੀ ਬੇਨਤੀ ਇੱਕ ਨਵੀਂ ਜਾਂਚ ਨੂੰ ਟ੍ਰਿਗਰ ਕਰੇਗੀ, ਤਾਂ `stale` ਫਲੈਗ `true` ਹੁੰਦਾ ਹੈ।

### ਪ੍ਰਤੀ-ਪ੍ਰਾਕਸੀ ਕਿਸਮ ਦੇ ਡਿਫੌਲਟ

ਸਿਹਤ ਜਾਂਚ URL ਸਕੀਮ ਦੇ ਆਧਾਰ 'ਤੇ ਉਚਿਤ ਡਿਫੌਲਟ ਵਰਤਦੀ ਹੈ:

| ਸਕੀਮ                       | ਡਿਫੌਲਟ ਪੋਰਟ |
| -------------------------- | ----------- |
| `http://`                  | 8080        |
| `https://`                 | 443         |
| `socks5://` / `socks5h://` | 1080        |

URL ਵਿੱਚ ਕਸਟਮ ਪੋਰਟ (`http://host:9999`) ਹਮੇਸ਼ਾ ਸਕੀਮ ਡਿਫੌਲਟ ਨਾਲੋਂ ਤਰਜੀਹ ਲੈਂਦੀਆਂ ਹਨ।

## ਪ੍ਰਾਕਸੀ ਵਿਸ਼ਲੇਸ਼ਣ ਅਤੇ ਨਿਰੀਖਣਯੋਗਤਾ

OmniRoute ਹਰ ਪ੍ਰਾਕਸੀ ਦੀ ਵਰਤੋਂ ਨੂੰ ਟ੍ਰੈਕ ਕਰਦਾ ਹੈ, ਤਾਂ ਜੋ ਓਪਰੇਟਰਾਂ ਨੂੰ ਰੂਟਿੰਗ ਪੈਟਰਨਾਂ, ਲੇਟੈਂਸੀ ਵਿੱਚ ਅਚਾਨਕ ਵਾਧੇ ਅਤੇ ਵਾਰ-ਵਾਰ ਹੋਣ ਵਾਲੀਆਂ ਅਸਫਲਤਾਵਾਂ ਦਾ ਨਿਦਾਨ ਕਰਨ ਵਿੱਚ ਮਦਦ ਮਿਲ ਸਕੇ।

### ਕੀ ਟ੍ਰੈਕ ਕੀਤਾ ਜਾਂਦਾ ਹੈ

ਕਿਸੇ ਸੰਰਚਿਤ ਪ੍ਰਾਕਸੀ ਰਾਹੀਂ ਜਾਣ ਵਾਲੀ ਹਰ ਬੇਨਤੀ ਲਈ, OmniRoute ਹੇਠਾਂ ਦਿੱਤੀ ਜਾਣਕਾਰੀ ਰਿਕਾਰਡ ਕਰਦਾ ਹੈ:

| ਮੈਟ੍ਰਿਕ      | ਵੇਰਵਾ                                              |
| ------------ | -------------------------------------------------- |
| `proxy_url`  | ਪੂਰਾ ਪ੍ਰਾਕਸੀ URL (ਪ੍ਰਮਾਣੀਕਰਨ ਕ੍ਰੈਡੈਂਸ਼ਲ ਲੁਕਾਏ ਹੋਏ) |
| `provider`   | ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰਦਾਤਾ ID (openai, anthropic, ਆਦਿ)      |
| `latency_ms` | ਪ੍ਰਾਕਸੀ ਹੈਂਡਸ਼ੇਕ ਸਮੇਤ ਕੁੱਲ ਆਉਣ-ਜਾਣ ਸਮਾਂ            |
| `connect_ms` | ਸਿਰਫ਼ TCP ਕਨੈਕਟ ਸਮਾਂ                               |
| `status`     | ਅੱਪਸਟ੍ਰੀਮ ਤੋਂ ਮਿਲਿਆ HTTP ਸਥਿਤੀ ਕੋਡ                 |
| `error`      | ਬੇਨਤੀ ਅਸਫਲ ਹੋਣ 'ਤੇ ਤਰੁੱਟੀ ਵਰਗ                      |
| `timestamp`  | ISO 8601 UTC                                       |

### ਡਾਟਾ ਤੱਕ ਪਹੁੰਚ

```bash
# ਹਾਲੀਆ ਪ੍ਰਾਕਸੀ ਘਟਨਾਵਾਂ
curl -H "Authorization: Bearer $OMNIROUTE_KEY" \
  "http://localhost:20128/api/usage/proxy-logs?limit=100"
```

ਅਸਲ ਐਂਡਪੌਇੰਟ `/api/usage/proxy-logs` ਹੈ (`src/app/api/usage/proxy-logs/route.ts` ਵੇਖੋ)। ਇਹ ਐਂਡਪੌਇੰਟ ਹੇਠ ਲਿਖਿਆਂ ਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈ:

- `GET /api/usage/proxy-logs` — ਪ੍ਰਾਕਸੀ ਲੌਗ ਪ੍ਰਾਪਤ ਕਰੋ
- `DELETE /api/usage/proxy-logs` — ਸਾਰੇ ਪ੍ਰਾਕਸੀ ਲੌਗ ਸਾਫ਼ ਕਰੋ

ਜੇ ਲੋੜ ਹੋਵੇ, ਤਾਂ ਸਮੁੱਚੇ ਅੰਕੜਿਆਂ ਲਈ SQL ਰਾਹੀਂ ਸਿੱਧੇ `proxy_logs` ਟੇਬਲ ਤੋਂ ਪੁੱਛਗਿੱਛ ਕੀਤੀ ਜਾ ਸਕਦੀ ਹੈ। ਡੈਸ਼ਬੋਰਡ UI ਸਮੁੱਚੇ ਦ੍ਰਿਸ਼ ਵੀ ਪੇਸ਼ ਕਰ ਸਕਦਾ ਹੈ।

### ਆਮ ਪੈਟਰਨ

**ਅਸਥਿਰ ਪ੍ਰਾਕਸੀ ਦਾ ਪਤਾ ਲਗਾਓ** (ਸਫਲਤਾ ਅਤੇ ਅਸਫਲਤਾ ਵਿਚਕਾਰ ਬਦਲਦੀ ਰਹਿੰਦੀ ਹੈ):

```sql
SELECT proxy_url,
       COUNT(*) AS total,
       SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) AS errors,
       ROUND(100.0 * SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) / COUNT(*), 1) AS error_pct
FROM proxy_logs
WHERE timestamp > datetime('now', '-1 hour')
GROUP BY proxy_url
HAVING error_pct > 5
ORDER BY error_pct DESC;
```

**ਹੌਲੀਆਂ ਪ੍ਰਾਕਸੀਆਂ ਲੱਭੋ** (p95 ਲੇਟੈਂਸੀ > 2s):

```sql
WITH ranked AS (
  SELECT proxy_url, latency_ms,
         PERCENT_RANK() OVER (PARTITION BY proxy_url ORDER BY latency_ms) AS pct
  FROM proxy_logs
  WHERE timestamp > datetime('now', '-24 hour')
)
SELECT proxy_url, latency_ms
FROM ranked
WHERE pct >= 0.95
ORDER BY latency_ms DESC;
```

## ਰੋਟੇਸ਼ਨ ਰਣਨੀਤੀ ਫ਼ੈਸਲਾ-ਰੁੱਖ

ਜਦੋਂ ਇੱਕ ਸਕੋਪ ਨੂੰ ਕਈ ਪ੍ਰਾਕਸੀਆਂ ਨਿਰਧਾਰਤ ਕੀਤੀਆਂ ਜਾਂਦੀਆਂ ਹਨ, ਤਾਂ OmniRoute ਹਰੇਕ ਬੇਨਤੀ ਲਈ ਵਰਤੀ ਜਾਣ ਵਾਲੀ ਪ੍ਰਾਕਸੀ ਚੁਣਨ ਵਾਸਤੇ ਇੱਕ **ਰੋਟੇਸ਼ਨ ਰਣਨੀਤੀ** ਵਰਤਦਾ ਹੈ। ਰਣਨੀਤੀ ਨੂੰ ਸਕੋਪ ਪੱਧਰ 'ਤੇ ਸੰਰਚਿਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ (ਗਲੋਬਲ, ਪ੍ਰਤੀ-ਪ੍ਰਦਾਤਾ, ਪ੍ਰਤੀ-ਖਾਤਾ, ਪ੍ਰਤੀ-ਕੌਂਬੋ)।

```
   │         │              (ਸਮਾਨ ਵੰਡ
   │         │              ਸਮੇਂ ਦੇ ਨਾਲ
   │         │              ਗੁਣਵੱਤਾ ਡਾਟਾ ਬਣਾਉਂਦੀ ਹੈ)
   │         │
   │    `quality` ਵਰਤੋ
   │    (ਵੱਖ-ਵੱਖ ਗੁਣਵੱਤਾ ਲਈ
   │    ਸਭ ਤੋਂ ਵਧੀਆ)
   │
`random` ਵਰਤੋ
(ਲੋਡ ਨੂੰ
ਸਮਾਨ ਰੂਪ ਵਿੱਚ ਵੰਡੋ)
```

## ਤੁਹਾਡੇ ਆਪਣੇ ਪ੍ਰਾਕਸੀਆਂ ਲਈ ਆਟੋਮੈਟਿਕ ਅਸਫਲਤਾ ਬਹਿਸ਼ਕਰਨ

1proxy ਮਾਰਕੀਟਪਲੇਸ ਪੂਲ ਪਹਿਲਾਂ ਹੀ ਅਸਫਲ ਪ੍ਰਾਕਸੀਆਂ ਦੀ ਗੁਣਵੱਤਾ ਆਪਣੇ-ਆਪ ਘਟਾਉਂਦਾ ਹੈ (ਵੇਖੋ
[ਪ੍ਰਾਕਸੀ ਗੁਣਵੱਤਾ ਸਕੋਰ](#proxy-quality-scores))। ਉਹਨਾਂ ਪ੍ਰਾਕਸੀਆਂ ਲਈ ਜੋ **ਤੁਸੀਂ**
ਰਜਿਸਟਰੀ ਵਿੱਚ ਜੋੜੀਆਂ ਹਨ, ਬੈਕਗ੍ਰਾਊਂਡ ਹੈਲਥ ਸ਼ੈਡਿਊਲਰ
(`src/lib/proxyHealth/scheduler.ts`) ਬਿਨਾਂ ਕੁਝ ਮਿਟਾਏ, ਉਹੀ "ਡੈੱਡ ਮੈਂਬਰ ਨੂੰ ਚੇਨ
ਵਿੱਚੋਂ ਆਪਣੇ-ਆਪ ਬਾਹਰ ਰੱਖੋ" ਵਿਹਾਰ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ:

```bash
# .env — ਲਗਾਤਾਰ 3 ਅਸਫਲ ਪ੍ਰੋਬਾਂ ਤੋਂ ਬਾਅਦ ਪ੍ਰਾਕਸੀ ਨੂੰ ਸੌਫਟ-ਡਿਸੇਬਲ ਕਰੋ ਅਤੇ ਜਦੋਂ ਇਹ
# ਮੁੜ ਪ੍ਰੋਬਾਂ ਦਾ ਜਵਾਬ ਦੇਣਾ ਸ਼ੁਰੂ ਕਰੇ ਤਾਂ ਇਸਨੂੰ ਆਪਣੇ-ਆਪ ਦੁਬਾਰਾ ਸਮਰੱਥ ਕਰੋ।
PROXY_AUTO_DISABLE=true
PROXY_AUTO_REMOVE_AFTER=3
```

ਇਹ ਮਲਟੀ-ਪ੍ਰਾਕਸੀ ਚੇਨ ਵਿੱਚ ਇਸ ਤਰ੍ਹਾਂ ਕੰਮ ਕਰਦਾ ਹੈ:

1. ਸ਼ੈਡਿਊਲਰ ਹਰ ਰਜਿਸਟਰ ਕੀਤੀ ਪ੍ਰਾਕਸੀ ਨੂੰ ਹਰ `PROXY_HEALTH_INTERVAL_MS` ਬਾਅਦ
   ਪ੍ਰੋਬ ਕਰਦਾ ਹੈ (ਡਿਫਾਲਟ 10 ਮਿੰਟ; ਘੱਟੋ-ਘੱਟ 1 ਮਿੰਟ)।
2. ਲਗਾਤਾਰ `PROXY_AUTO_REMOVE_AFTER` **ਨਿਰਣਾਇਕ** ਅਸਫਲਤਾਵਾਂ ਤੋਂ ਬਾਅਦ (ਇੱਕ ਅਸਲੀ
   ਕਨੈਕਸ਼ਨ ਅਸਫਲਤਾ — ਟਾਈਮਆਉਟ ਜਾਂ ਪ੍ਰੋਬ ਟਾਰਗੇਟ ਦਾ ਆਪਣਾ 5xx ਕਦੇ ਨਹੀਂ ਗਿਣਿਆ ਜਾਂਦਾ,
   ਵੇਖੋ [ਪ੍ਰਾਕਸੀ ਹੈਲਥ ਜਾਂਚ](#proxy-health-checking-v3816)), ਪ੍ਰਾਕਸੀ ਦਾ `status`
   `dead` 'ਤੇ ਸੈੱਟ ਕਰ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ।
3. `dead` ਉਹਨਾਂ ਸਥਿਤੀਆਂ ਵਿੱਚੋਂ ਇੱਕ ਹੈ ਜਿਨ੍ਹਾਂ ਨੂੰ ਪੂਲ/ਰੋਟੇਸ਼ਨ ਰਿਜ਼ੋਲਿਊਸ਼ਨ ਦੁਆਰਾ
   ਵਰਤਿਆ ਜਾਣ ਵਾਲਾ ਐਕਟਿਵ-ਸਟੇਟਸ ਫਿਲਟਰ ਬਾਹਰ ਰੱਖਦਾ ਹੈ, ਇਸ ਲਈ ਕਿਸੇ ਸਕੋਪ ਦੀ ਰੋਟੇਸ਼ਨ
   (ਰਾਊਂਡ-ਰੌਬਿਨ / ਰੈਂਡਮ / ਸਟਿੱਕੀ / ਲੇਟੈਂਸੀ — ਵੇਖੋ
   [ਰੋਟੇਸ਼ਨ ਰਣਨੀਤੀ ਫ਼ੈਸਲਾ ਟ੍ਰੀ](#rotation-strategy-decision-tree)) ਨਵੀਆਂ ਬੇਨਤੀਆਂ ਨੂੰ
   ਤੁਰੰਤ ਉਹ ਪ੍ਰਾਕਸੀ ਦੇਣੀ ਬੰਦ ਕਰ ਦਿੰਦੀ ਹੈ। ਪੂਲ ਵਿੱਚ ਮੌਜੂਦ ਹੋਰ ਕੋਈ ਵੀ ਪ੍ਰਾਕਸੀ
   ਪ੍ਰਭਾਵਿਤ ਨਹੀਂ ਹੁੰਦੀ, ਅਤੇ ਪੂਰਾ ਪੂਲ ਕਦੇ ਵੀ ਚੁੱਪਚਾਪ ਸਿੱਧੇ ਕਨੈਕਸ਼ਨ ਵੱਲ ਫਾਲਬੈਕ
   ਨਹੀਂ ਕਰਦਾ — ਫੇਲ-ਕਲੋਜ਼ਡ ਗਾਰਡ ਲਈ [4-ਪੱਧਰੀ ਪ੍ਰਾਕਸੀ ਸਿਸਟਮ](#4-level-proxy-system)
   ਵੇਖੋ।
4. ਸ਼ੈਡਿਊਲਰ ਉਸੇ ਅੰਤਰਾਲ 'ਤੇ `dead` ਪ੍ਰਾਕਸੀਆਂ ਨੂੰ ਪ੍ਰੋਬ ਕਰਨਾ ਜਾਰੀ ਰੱਖਦਾ ਹੈ। ਅਗਲੀ
   ਸਫਲ ਪ੍ਰੋਬ `status` ਨੂੰ ਵਾਪਸ `active` ਵਿੱਚ ਬਦਲ ਦਿੰਦੀ ਹੈ ਅਤੇ ਪ੍ਰਾਕਸੀ ਮੁੜ ਰੋਟੇਸ਼ਨ
   ਵਿੱਚ ਸ਼ਾਮਲ ਹੋ ਜਾਂਦੀ ਹੈ — ਹੱਥੀਂ ਦੁਬਾਰਾ ਜੋੜਨ ਦੀ ਲੋੜ ਨਹੀਂ ਹੁੰਦੀ।

ਇਹ ਜਾਣਬੁੱਝ ਕੇ **ਆਪਟ-ਇਨ ਅਤੇ ਗੈਰ-ਵਿਨਾਸ਼ਕਾਰੀ** ਹੈ: ਡਿਫਾਲਟ ਤੌਰ 'ਤੇ ਸ਼ੈਡਿਊਲਰ ਸਿਰਫ਼
ਅਸਫਲਤਾਵਾਂ ਨੂੰ ਗਿਣਦਾ ਅਤੇ ਲੌਗ ਕਰਦਾ ਹੈ (`decision.ts` ਵਿੱਚ ਨੀਤੀ C ਵੇਖੋ), ਅਤੇ
`PROXY_AUTO_DISABLE` ਕਦੇ ਵੀ ਕੋਈ ਰੋਅ ਨਹੀਂ ਮਿਟਾਉਂਦਾ — ਇਸ ਕੰਮ ਲਈ ਵੱਖਰਾ ਅਤੇ ਵਧੇਰੇ
ਆਕਰਮਕ `PROXY_AUTO_REMOVE` ਫਲੈਗ ਹੈ। ਜੇ ਦੋਵੇਂ `true` 'ਤੇ ਸੈੱਟ ਹਨ, ਤਾਂ
`PROXY_AUTO_REMOVE` ਨੂੰ ਤਰਜੀਹ ਮਿਲਦੀ ਹੈ (ਜਿਹੜੀ ਪ੍ਰਾਕਸੀ ਮਿਟਾਈ ਜਾਣ ਵਾਲੀ ਹੈ, ਉਸਨੂੰ
ਵਿਚਕਾਰ ਸੌਫਟ-ਡਿਸੇਬਲ ਕਰਨ ਦਾ ਕੋਈ ਲਾਭ ਨਹੀਂ)। ਵੇਰੀਏਬਲਾਂ ਦੀ ਪੂਰੀ ਸੂਚੀ ਲਈ
[ਇਨਵਾਇਰਨਮੈਂਟ ਸੰਰਚਨਾ](../reference/ENVIRONMENT.md) ਹਵਾਲਾ ਵੇਖੋ।
