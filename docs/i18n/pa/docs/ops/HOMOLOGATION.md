ਹੋਮੋਲੋਗੇਸ਼ਨ VPS ਉੱਤੇ ਚੱਲ ਰਹੇ OmniRoute ਡਿਪਲੌਇ ਦੀ ਅਸਲ-ਵਾਤਾਵਰਣ E2E ਪ੍ਰਮਾਣਿਕਤਾ
(`HOMOLOG_BASE_URL`, ਉਦਾਹਰਨ ਲਈ `http://192.168.0.15:20128`)। ਇੱਕ ਕਮਾਂਡ ਮੈਨੁਅਲ
ਰਿਲੀਜ਼ STOP #2 ਚੈੱਕਲਿਸਟ ਦੀ ਥਾਂ ਇੱਕ ਸਵੈਚਾਲਿਤ, ਸਬੂਤ ਪੈਦਾ ਕਰਨ ਵਾਲੀ ਰਨ ਲੈਂਦੀ ਹੈ।

## ਪੂਰਵ-ਸ਼ਰਤਾਂ

1. `.env.homolog.example` ਨੂੰ `.env.homolog` ਵਿੱਚ ਕਾਪੀ ਕਰੋ (gitignored — ਇਸਨੂੰ ਕਦੇ ਵੀ commit ਨਾ ਕਰੋ) ਅਤੇ ਇਹ ਮੁੱਲ ਭਰੋ:
   - `HOMOLOG_BASE_URL` — ਟਾਰਗੇਟ deploy, ਉਦਾਹਰਨ ਲਈ `http://192.168.0.15:20128`।
   - `HOMOLOG_ADMIN_PASSWORD` — ਉਸ deploy ਲਈ dashboard ਪ੍ਰਬੰਧਨ password।
   - `HOMOLOG_CRITICAL_PROVIDERS` — comma-separated provider prefixes ਜਿਨ੍ਹਾਂ ਨੂੰ ਅਸਲ
     smoke chat request ਮਿਲਦੀ ਹੈ (ਉਦਾਹਰਨ ਲਈ `openai,anthropic,gemini,codex,grok,glm,deepseek,openrouter`)।
   - `HOMOLOG_API_KEY` — ਆਮ runs ਵਿੱਚ ਖਾਲੀ ਛੱਡੋ; suite ਆਪਣੀ
     ephemeral key ਬਣਾਉਂਦੀ ਅਤੇ revoke ਕਰਦੀ ਹੈ। ਇਸਨੂੰ ਕੇਵਲ ਇਕੱਲੀ layer ਨੂੰ ਅਲੱਗ ਤੌਰ 'ਤੇ debug ਕਰਨ ਲਈ ਸੈੱਟ ਕਰੋ।
2. repo ਵਿੱਚ `npm install` ਚਲਾਓ (suite ਦੀਆਂ dependencies — `httpyac`, `promptfoo`,
   `playwright-ctrf-json-reporter`, `junit-to-ctrf`, `ctrf` — ਆਮ devDependencies ਹਨ)।
3. ਜੇ browser binaries ਪਹਿਲਾਂ ਤੋਂ ਮੌਜੂਦ ਨਹੀਂ ਹਨ ਤਾਂ `npx playwright install` ਚਲਾਓ।

## ਕਿਵੇਂ ਚਲਾਉਣਾ ਹੈ

```bash
npm run homolog
```

ਅਜਿਹੇ deploy ਦੇ ਵਿਰੁੱਧ validate ਕਰਨ ਲਈ, ਜਿਸਦਾ version ਸਥਾਨਕ `package.json` ਨਾਲ ਮੇਲ ਨਹੀਂ ਖਾਂਦਾ
(ਉਦਾਹਰਨ ਲਈ, homologation box ਹਾਲੇ ਵੀ ਪਿਛਲੀ patch release 'ਤੇ ਹੈ), expected
version ਨੂੰ ਸਪਸ਼ਟ ਤੌਰ 'ਤੇ override ਕਰੋ:

```bash
HOMOLOG_EXPECT_VERSION=3.8.47 npm run homolog
```

ਜੇ ਕੋਈ ਵੀ layer ਅਸਫਲ ਹੁੰਦੀ ਹੈ ਤਾਂ run non-zero ਨਾਲ ਬੰਦ ਹੁੰਦਾ ਹੈ, ਅਤੇ ਅਸਫਲਤਾ ਹੋਣ 'ਤੇ ਵੀ
ਇਹ ਹਮੇਸ਼ਾ ਆਪਣੀ ਬਣਾਈ ephemeral API key ਨੂੰ revoke ਕਰਨ ਦੀ ਕੋਸ਼ਿਸ਼ ਕਰਦਾ ਹੈ
(`scripts/homolog/run.mjs` ਵਿੱਚ `finally` block)।

## ਰਿਪੋਰਟ ਪੜ੍ਹਨਾ

ਸਾਰਾ output `homolog-report/` ਵਿੱਚ ਜਾਂਦਾ ਹੈ (gitignored):

- `summary.md` — ਉਹੀ table ਜੋ stdout 'ਤੇ print ਹੁੰਦੀ ਹੈ, ਹਰ layer ਲਈ ਇੱਕ row (✅/❌ + ਵੇਰਵਾ)।
- `homolog-ctrf.json` — ਇਕੱਠੀ ਕੀਤੀ CTRF report (API/SSE, provider-smoke, ਅਤੇ
  UI results ਦਾ merge) — ਇਹ ਉਹ artifact ਹੈ ਜੋ release STOP #2 checklist ਨਾਲ attach ਕਰਨਾ ਹੈ।
- `httpyac-junit.xml`, `api-ctrf.json`, `providers-ctrf.json`, `ui-ctrf.json` — ਹਰ
  layer ਦੀਆਂ raw/intermediate reports।
- `promptfooconfig.yaml`, `provider-misses.json` — ਮੌਜੂਦਾ run ਲਈ generate ਕੀਤੀ promptfoo config
  ਅਤੇ ਉਹ critical providers ਜੋ live catalog ਵਿੱਚੋਂ ਗਾਇਬ ਸਨ।

ਅਸਫਲ L0 ਤੁਰੰਤ abort ਕਰਦਾ ਹੈ (ਕੋਈ ephemeral key ਨਹੀਂ ਬਣਾਈ ਜਾਂਦੀ), ਕਿਉਂਕਿ version/health
mismatch ਦਾ ਅਰਥ ਹੈ ਕਿ ਹਰ downstream layer ਗਲਤ deploy ਨੂੰ validate ਕਰ ਰਹੀ ਹੋਵੇਗੀ।

## ਜਦੋਂ UI ਵਾਜਬ ਤੌਰ 'ਤੇ ਬਦਲੇ ਤਾਂ baseline ਮੁੜ ਸੈੱਟ ਕਰਨਾ

L4b (route smoke) ਅਤੇ L4c (API-key UI flow) ਅਸਲ DOM locators ਦੁਆਰਾ ਚਲਾਏ ਜਾਂਦੇ ਹਨ, ਨਾ ਕਿ
snapshots ਦੁਆਰਾ, ਇਸ ਲਈ ਜ਼ਿਆਦਾਤਰ ਵਾਜਬ UI ਬਦਲਾਵਾਂ ਲਈ suite update ਦੀ ਲੋੜ ਨਹੀਂ ਹੁੰਦੀ। ਜਦੋਂ ਕੋਈ ਬਦਲਾਅ
locator ਨੂੰ ਤੋੜ ਦਿੰਦਾ ਹੈ (ਉਦਾਹਰਨ ਲਈ, ਬਦਲਿਆ ਹੋਇਆ button label ਜਾਂ ਸਥਾਨ ਬਦਲਿਆ settings page):

1. ਮੌਜੂਦਾ source ਦੇ ਵਿਰੁੱਧ locator ਦੀ ਮੁੜ ਪੁਸ਼ਟੀ ਕਰੋ (specs ਪਹਿਲਾਂ ਹੀ ਦਰਜ ਕਰਦੇ ਹਨ ਕਿ ਹਰ
   locator ਦੀ ਕਿਹੜੀ file/line ਦੇ ਵਿਰੁੱਧ ਪੁਸ਼ਟੀ ਕੀਤੀ ਗਈ ਸੀ — ਉਸੇ pattern ਦੀ ਪਾਲਣਾ ਕਰੋ, ਅੰਦਾਜ਼ਾ ਨਾ ਲਗਾਓ)।
2. `tests/homolog/ui/` ਵਿੱਚ spec ਨੂੰ update ਕਰੋ।
3. fix ਦੀ ਪੁਸ਼ਟੀ ਕਰਨ ਲਈ VPS ਦੇ ਵਿਰੁੱਧ `npm run homolog` (ਜਾਂ ਸਿਰਫ਼ ਪ੍ਰਭਾਵਿਤ Playwright spec) ਮੁੜ ਚਲਾਓ,
   ਫਿਰ commit ਕਰੋ।

ਇਸ suite (F1) ਵਿੱਚ ਕੋਈ visual/pixel baseline ਨਹੀਂ ਹੈ — ਇਸ ਲਈ Roadmap ਵੇਖੋ।

## ਰੋਡਮੈਪ (F2 / F3)

Design ਅਤੇ phased rollout ਦੀ ਜਾਣਕਾਰੀ internal planning spec
`_tasks/superpowers/specs/2026-07-13-homolog-e2e-suite-design.md` ਵਿੱਚ ਹੈ (linked ਨਹੀਂ — internal
`_tasks/` artifact, ਇਸ repo ਦੇ tracked docs ਦਾ ਹਿੱਸਾ ਨਹੀਂ)। ਸਾਰ:

- **F2** — ਪੂਰੀ walkthrough recording → Playwright Test Agents (`planner`/`generator`)
  ਇਸਨੂੰ flow specs (combo ਬਣਾਉਣਾ, provider ਨੂੰ test ਕਰਨਾ, settings ਨੂੰ edit ਕਰਨਾ, MCP tools) +
  dynamic data (metrics, timestamps, logs) ਉੱਤੇ masks ਵਾਲੇ visual regression baseline (Lost Pixel) +
  ਹਰ release ਲਈ `healer` maintenance routine ਵਿੱਚ ਬਦਲਦੇ ਹਨ।
- **F3** — resilience/contract/wiring coverage: devbox ਉੱਤੇ toxiproxy + ਇੱਕ ਨਕਲੀ OpenAI-compatible
  provider, VPS ਉੱਤੇ ਉਸ ਵੱਲ point ਕਰਦਾ ਇੱਕ `homolog-resilience` combo
  (injected timeout → fallback assert ਕਰੋ + `/api/monitoring/health` ਰਾਹੀਂ circuit breaker open/close);
  `docs/openapi.yaml` ਦੇ ਵਿਰੁੱਧ gated Schemathesis contract testing
  (ਘੱਟ `--max-examples`, ਨਿਸ਼ਚਿਤ seeds, ਸਿਰਫ਼ non-LLM endpoints); ਅਤੇ
  `npm run homolog` + ਇਸਦੀ `summary.md` ਨੂੰ `/generate-release` STOP #2 phase ਵਿੱਚ ਜੋੜਨਾ।
