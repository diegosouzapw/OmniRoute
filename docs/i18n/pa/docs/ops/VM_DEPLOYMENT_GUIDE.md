## 1. VM ਨੂੰ ਕੌਂਫਿਗਰ ਕਰੋ

### 1.1 ਇੰਸਟੈਂਸ ਬਣਾਓ

ਆਪਣੇ ਪਸੰਦੀਦਾ VPS ਪ੍ਰਦਾਤਾ 'ਤੇ:

- Ubuntu 24.04 LTS ਚੁਣੋ
- ਘੱਟੋ-ਘੱਟ ਪਲਾਨ (1 vCPU / 1 GB RAM) ਚੁਣੋ
- ਇੱਕ ਮਜ਼ਬੂਤ root ਪਾਸਵਰਡ ਸੈੱਟ ਕਰੋ ਜਾਂ SSH ਕੁੰਜੀ ਕੌਂਫਿਗਰ ਕਰੋ
- **ਪਬਲਿਕ IP** ਨੋਟ ਕਰੋ (ਉਦਾਹਰਨ ਲਈ, `203.0.113.10`)

### 1.2 SSH ਰਾਹੀਂ ਕਨੈਕਟ ਕਰੋ

```bash
ssh root@203.0.113.10
```

### 1.3 ਸਿਸਟਮ ਨੂੰ ਅੱਪਡੇਟ ਕਰੋ

```bash
apt update && apt upgrade -y
```

### 1.4 Docker ਇੰਸਟਾਲ ਕਰੋ

```bash
# ਨਿਰਭਰਤਾਵਾਂ ਇੰਸਟਾਲ ਕਰੋ
apt install -y ca-certificates curl gnupg

# ਅਧਿਕਾਰਤ Docker ਰਿਪੋਜ਼ਟਰੀ ਸ਼ਾਮਲ ਕਰੋ
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
chmod a+r /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $ (. /etc/os-release && echo "$VERSION_CODENAME") stable" | tee /etc/apt/sources.list.d/docker.list > /dev/null
apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

### 1.5 nginx ਇੰਸਟਾਲ ਕਰੋ

```bash
apt install -y nginx
```

### 1.6 ਫਾਇਰਵਾਲ (UFW) ਕੌਂਫਿਗਰ ਕਰੋ

```bash
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp    # SSH
ufw allow 80/tcp    # HTTP (ਰੀਡਾਇਰੈਕਟ)
ufw allow 443/tcp   # HTTPS
ufw enable
```

> **ਸੁਝਾਅ**: ਵੱਧ ਤੋਂ ਵੱਧ ਸੁਰੱਖਿਆ ਲਈ, ਪੋਰਟ 80 ਅਤੇ 443 ਨੂੰ ਸਿਰਫ਼ Cloudflare IPs ਤੱਕ ਸੀਮਤ ਕਰੋ। [ਉੱਨਤ ਸੁਰੱਖਿਆ](#advanced-security) ਭਾਗ ਵੇਖੋ।

## 2. OmniRoute ਇੰਸਟਾਲ ਕਰੋ

### 2.1 ਕੌਂਫਿਗਰੇਸ਼ਨ ਡਾਇਰੈਕਟਰੀ ਬਣਾਓ

```bash
mkdir -p /opt/omniroute
```

### 2.2 ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲਾਂ ਦੀ ਫ਼ਾਈਲ ਬਣਾਓ

```bash
cat > /opt/omniroute/.env << 'EOF'
# === ਸੁਰੱਖਿਆ ===
JWT_SECRET=CHANGE-TO-A-UNIQUE-64-CHAR-SECRET-KEY
INITIAL_PASSWORD=YourSecurePassword123!
API_KEY_SECRET=REPLACE-WITH-ANOTHER-SECRET-KEY
STORAGE_ENCRYPTION_KEY=REPLACE-WITH-THIRD-SECRET-KEY
STORAGE_ENCRYPTION_KEY_VERSION=v1
MACHINE_ID_SALT=CHANGE-TO-A-UNIQUE-SALT
OMNIROUTE_WS_BRIDGE_SECRET=REPLACE-WITH-WS-BRIDGE-SECRET  # ਪ੍ਰੋਡਕਸ਼ਨ ਵਿੱਚ ਲਾਜ਼ਮੀ: Codex Responses WS bridge ਦੁਆਰਾ ਵਰਤਿਆ ਜਾਂਦਾ ਹੈ

# === ਐਪ ===
PORT=20128
NODE_ENV=production
HOSTNAME=0.0.0.0
DATA_DIR=/app/data
APP_LOG_TO_FILE=true
AUTH_COOKIE_SECURE=true
REQUIRE_API_KEY=false

# === URLs (ਆਪਣੇ ਡੋਮੇਨ ਅਨੁਸਾਰ ਬਦਲੋ) ===
# ਤਹਿ ਕੀਤੇ ਕੰਮਾਂ / ਸਵੈ-fetches ਲਈ ਅੰਦਰੂਨੀ ਸਰਵਰ-ਤੋਂ-ਸਰਵਰ ਬੇਸ URL।
BASE_URL=http://127.0.0.1:20128
# OAuth callbacks, dashboard links ਅਤੇ ਤਿਆਰ ਕੀਤੇ ਪਬਲਿਕ URLs ਲਈ ਵਰਤਿਆ ਜਾਣ ਵਾਲਾ ਬ੍ਰਾਊਜ਼ਰ-ਸਾਹਮਣੇ ਵਾਲਾ URL।
NEXT_PUBLIC_BASE_URL=https://llms.seudominio.com
# ਤਿਆਰ ਕੀਤੇ ਪਬਲਿਕ ਐਸੈੱਟ URLs ਲਈ ਵਿਕਲਪਿਕ ਸਪਸ਼ਟ ਪਬਲਿਕ ਓਰਿਜਨ ਓਵਰਰਾਈਡ।
# OMNIROUTE_PUBLIC_BASE_URL=https://llms.seudominio.com

# === ਕਲਾਉਡ ਸਿੰਕ (ਵਿਕਲਪਿਕ) ===
# CLOUD_URL=https://cloud.omniroute.online
# NEXT_PUBLIC_CLOUD_URL=https://cloud.omniroute.online
EOF
```

> ⚠️ **ਮਹੱਤਵਪੂਰਨ**: ਵਿਲੱਖਣ ਗੁਪਤ ਕੁੰਜੀਆਂ ਬਣਾਓ! ਹਰੇਕ ਕੁੰਜੀ ਲਈ `openssl rand -hex 32` ਵਰਤੋ।

### 2.3 ਕੰਟੇਨਰ ਸ਼ੁਰੂ ਕਰੋ

```bash
docker pull diegosouzapw/omniroute:latest

docker run -d \
  --name omniroute \
  --restart unless-stopped \
  --env-file /opt/omniroute/.env \
  -p 20128:20128 \
  -v omniroute-data:/app/data \
  diegosouzapw/omniroute:latest
```

### 2.4 ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਇਹ ਚੱਲ ਰਿਹਾ ਹੈ

```bash
docker ps | grep omniroute

```

ਇਸ ਵਿੱਚ ਇਹ ਦਿਖਾਈ ਦੇਣਾ ਚਾਹੀਦਾ ਹੈ: `[DB] SQLite database ready` ਅਤੇ `listening on port 20128`।

## 3. nginx ਨੂੰ ਕੌਂਫਿਗਰ ਕਰੋ (ਰਿਵਰਸ ਪ੍ਰੌਕਸੀ)

### 3.1 SSL ਸਰਟੀਫਿਕੇਟ ਤਿਆਰ ਕਰੋ (Cloudflare Origin)

Cloudflare ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ:

1. **SSL/TLS → Origin Server** 'ਤੇ ਜਾਓ
2. **Create Certificate** 'ਤੇ ਕਲਿੱਕ ਕਰੋ
3. ਡਿਫਾਲਟ ਸੈਟਿੰਗਾਂ ਹੀ ਰੱਖੋ (15 ਸਾਲ, \*.yourdomain.com)
4. **Origin Certificate** ਅਤੇ **Private Key** ਨੂੰ ਕਾਪੀ ਕਰੋ

```bash
mkdir -p /etc/nginx/ssl

# ਸਰਟੀਫਿਕੇਟ ਪੇਸਟ ਕਰੋ
nano /etc/nginx/ssl/origin.crt

# ਪ੍ਰਾਈਵੇਟ ਕੀ ਪੇਸਟ ਕਰੋ
nano /etc/nginx/ssl/origin.key

chmod 600 /etc/nginx/ssl/origin.key
```

### 3.2 Nginx ਕੌਂਫਿਗਰੇਸ਼ਨ

```bash
cat > /etc/nginx/sites-available/omniroute << 'NGINX'
# ਡਿਫਾਲਟ ਸਰਵਰ — IP ਰਾਹੀਂ ਸਿੱਧੀ ਪਹੁੰਚ ਨੂੰ ਬਲੌਕ ਕਰਦਾ ਹੈ
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    listen 443 ssl default_server;
    listen [::]:443 ssl default_server;
    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    server_name _;
    return 444;
}

# OmniRoute — HTTPS
server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name llms.yourdomain.com;  # ਆਪਣੇ ਡੋਮੇਨ ਨਾਲ ਬਦਲੋ

    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    client_max_body_size 100M;

    location / {
        proxy_pass http://127.0.0.1:20128;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket ਸਹਾਇਤਾ
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # SSE (ਸਰਵਰ ਵੱਲੋਂ ਭੇਜੇ ਇਵੈਂਟ) — AI ਜਵਾਬਾਂ ਦੀ ਸਟ੍ਰੀਮਿੰਗ
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }
}

# HTTP → HTTPS ਰੀਡਾਇਰੈਕਟ
server {
    listen 80;
    listen [::]:80;
    server_name llms.yourdomain.com;
    return 301 https://$server_name$request_uri;
}
NGINX
```

ਰਿਵਰਸ-ਪ੍ਰੌਕਸੀ ਸਟ੍ਰੀਮ ਟਾਈਮਆਉਟਾਂ ਨੂੰ ਆਪਣੇ OmniRoute ਟਾਈਮਆਉਟ env vars ਨਾਲ ਇਕਸਾਰ ਰੱਖੋ। ਜੇ ਤੁਸੀਂ
`FETCH_TIMEOUT_MS` / `STREAM_IDLE_TIMEOUT_MS` ਵਧਾਉਂਦੇ ਹੋ, ਤਾਂ `proxy_read_timeout` / `proxy_send_timeout`
ਨੂੰ ਵੀ ਉਸੇ ਸੀਮਾ ਤੋਂ ਵੱਧ ਵਧਾਓ।

OmniRoute, OAuth ਕਾਲਬੈਕਾਂ ਅਤੇ ਤਿਆਰ ਕੀਤੇ ਜਨਤਕ ਲਿੰਕਾਂ ਲਈ ਬ੍ਰਾਊਜ਼ਰ ਨੂੰ ਦਿਖਾਈ ਦੇਣ ਵਾਲੇ ਪ੍ਰਮਾਣਿਕ ਓਰਿਜਿਨ ਵਜੋਂ `NEXT_PUBLIC_BASE_URL` ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ। ਪ੍ਰਮਾਣਿਤ ਡੈਸ਼ਬੋਰਡ ਲਿਖਤਾਂ ਇੱਕੋ-ਓਰਿਜਿਨ ਬੇਨਤੀਆਂ
ਦੇ ਨਾਲ ਸੈਸ਼ਨ-ਬੱਧ CSRF ਸੁਰੱਖਿਆ ਦੀ ਵਰਤੋਂ ਕਰਦੀਆਂ ਹਨ, ਇਸ ਲਈ ਉਹਨਾਂ ਨੂੰ ਕਿਸੇ ਸਥਿਰ ਜਨਤਕ ਬੇਸ URL ਦੀ ਲੋੜ ਨਹੀਂ ਹੁੰਦੀ। ਉਪਰੋਕਤ
`X-Forwarded-*` ਹੈਡਰ ਫਿਰ ਵੀ ਲਾਭਦਾਇਕ ਰੂਟਿੰਗ ਮੈਟਾਡਾਟਾ ਹਨ, ਪਰ ਜਦੋਂ OAuth ਜਾਂ ਤਿਆਰ ਕੀਤੇ ਬ੍ਰਾਊਜ਼ਰ ਲਿੰਕਾਂ ਨੂੰ ਇਸਦੀ ਲੋੜ ਹੋਵੇ, ਤਾਂ ਇਹ ਸਪਸ਼ਟ ਜਨਤਕ URL ਸੈੱਟ ਕਰਨ ਦਾ ਬਦਲ
ਨਹੀਂ ਹਨ। `OMNIROUTE_TRUST_PROXY` ਨੂੰ ਕੇਵਲ ਉਦੋਂ ਹੀ ਸਮਰੱਥ ਕਰੋ ਜੇ ਕਲਾਇੰਟ OmniRoute ਤੱਕ ਸਿੱਧੇ ਨਹੀਂ ਪਹੁੰਚ ਸਕਦੇ ਅਤੇ ਤੁਹਾਡੀ ਪ੍ਰੌਕਸੀ
ਆਉਣ ਵਾਲੇ ਫਾਰਵਰਡ ਕੀਤੇ ਹੈਡਰਾਂ ਨੂੰ ਹਟਾ ਕੇ/ਮੁੜ ਬਣਾਉਂਦੀ ਹੈ।

### 3.3 ਸਮਰੱਥ ਕਰੋ ਅਤੇ ਟੈਸਟ ਕਰੋ

## ਘੱਟ ਮੈਮੋਰੀ / ਛੋਟੇ VPS ਲਈ ਅਨੁਕੂਲਨ

ਛੋਟੇ VPS ਇੰਸਟੈਂਸਾਂ (1 GB RAM ਜਾਂ ਘੱਟ) ਉੱਤੇ ਡਿਪਲੌਇਮੈਂਟਾਂ ਲਈ:

- **ਬੈਕਗ੍ਰਾਊਂਡ ਸੇਵਾਵਾਂ ਅਸਮਰੱਥ ਕਰੋ** — ਸ਼ੈਡਿਊਲਰ, MCP ਸਰਵਰ ਅਤੇ ਸਮੇਂ-ਸਮੇਂ ਦੀਆਂ ਰੱਖ-ਰਖਾਅ ਕਾਰਵਾਈਆਂ ਨੂੰ ਛੱਡਣ ਲਈ `OMNIROUTE_DISABLE_BACKGROUND_SERVICES=1` ਸੈੱਟ ਕਰੋ। `docs/reference/ENVIRONMENT.md` ਵੇਖੋ।
- **SQLite WAL ਮੋਡ ਵਰਤੋ** — ਇਹ ਮੂਲ ਰੂਪ ਵਿੱਚ ਸਮਰੱਥ ਹੈ ਅਤੇ ਸਮਕਾਲੀ ਰੀਡਾਂ ਦੌਰਾਨ ਸਿਖਰਲੀ ਮੈਮੋਰੀ ਵਰਤੋਂ ਘਟਾਉਂਦਾ ਹੈ।
- **V8 ਹੀਪ ਨੂੰ ਸੀਮਿਤ ਕਰੋ** — `OMNIROUTE_MEMORY_MB` (ਉਦਾਹਰਨ ਲਈ, `512`) ਸੈੱਟ ਕਰੋ, ਤਾਂ ਜੋ ਰਨਟਾਈਮ VM ਤੋਂ ਵੱਡੀ ਉੱਪਰੀ ਸੀਮਾ ਕੈਲੀਬ੍ਰੇਟ ਨਾ ਕਰੇ। `docs/reference/ENVIRONMENT.md` ਵੇਖੋ।
- **ਵੱਧ-ਸਰੋਤ ਵਾਲੀਆਂ ਬੇਨਤੀਆਂ ਦੀ ਸਵੀਕ੍ਰਿਤੀ ਹੀਪ ਸੀਮਾ ਅਨੁਸਾਰ ਆਪਣੇ-ਆਪ ਸਕੇਲ ਹੁੰਦੀ ਹੈ** -- ਜਦੋਂ ਉੱਪਰ `OMNIROUTE_MEMORY_MB` ਸੈੱਟ ਕਰ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ, ਤਾਂ ਇਨਜੈਸਟ ਬਾਈਟ ਬਜਟ (`OMNIROUTE_CHAT_MAX_INFLIGHT_BYTES`) ਉਸੇ ਸੀਮਾ ਤੋਂ ਆਪਣੇ-ਆਪ ਨਿਰਧਾਰਤ ਹੁੰਦਾ ਹੈ। ਇਸ ਕਰਕੇ ਮੈਮੋਰੀ-ਸੀਮਿਤ VM ਨੂੰ ਬਿਨਾਂ ਕਿਸੇ ਵਾਧੂ ਟਿਊਨਿੰਗ ਦੇ ਸਮਕਾਲੀ ਬੇਨਤੀਆਂ ਲਈ ਛੋਟਾ ਬਜਟ ਮਿਲ ਜਾਂਦਾ ਹੈ; ਵਾਧੂ ਬੇਨਤੀਆਂ ਨੂੰ ਮੈਮੋਰੀ ਲਈ ਮੁਕਾਬਲਾ ਕਰਨ ਦੀ ਬਜਾਏ `Retry-After` ਦੇ ਨਾਲ ਮੁੜ ਕੋਸ਼ਿਸ਼ਯੋਗ `503` ਜਵਾਬ ਮਿਲਦਾ ਹੈ। ਪੁਰਾਣੀ `OMNIROUTE_CHAT_MAX_HEAVY_IN_FLIGHT` ਬੇਨਤੀ-ਗਿਣਤੀ ਸੀਮਾ ਸਿਰਫ਼ ਉਦੋਂ ਸੈੱਟ ਕਰੋ ਜਦੋਂ ਤੁਹਾਨੂੰ ਇਸ ਤੋਂ ਇਲਾਵਾ ਇੱਕ ਸਖ਼ਤ ਉੱਪਰੀ ਸੀਮਾ ਦੀ ਲੋੜ ਹੋਵੇ।
- **VPS ਉੱਤੇ `next build` ਤੋਂ ਬਚੋ** — ਸਥਾਨਕ ਤੌਰ ਉੱਤੇ ਬਿਲਡ ਕਰੋ ਅਤੇ ਸਟੈਂਡਅਲੋਨ ਆਉਟਪੁੱਟ (`.next/standalone/`) ਡਿਪਲੌਇ ਕਰੋ।
- **`top` / `free -m` ਨਾਲ ਨਿਗਰਾਨੀ ਕਰੋ** — OmniRoute ਆਮ ਤੌਰ ਉੱਤੇ 1 GB VM ਵਿੱਚ ਨਿਸ਼ਕ੍ਰਿਆ ਹੋਣ ਵੇਲੇ 200-400 MB RSS ਵਰਤਦਾ ਹੈ।
