1. ਮੌਜੂਦਾ ਸਿੰਗਲ-ਕੀ ਸੈਮਾਫੋਰ ਇਕਰਾਰਨਾਮੇ ਅਤੇ ਨਵੇਂ ਐਟਾਮਿਕ ਮਲਟੀ-ਕੀ
   ਇਕਰਾਰਨਾਮੇ ਨੂੰ ਕੇਂਦ੍ਰਿਤ ਟੈਸਟਾਂ ਨਾਲ ਪੱਕਾ ਕਰੋ: ਕੋਈ ਅੰਸ਼ਕ ਰਿਜ਼ਰਵੇਸ਼ਨ ਨਹੀਂ, FIFO ਕਤਾਰਬੰਦੀ, ਰੱਦ ਕਰਨਾ,
   ਸਮਾਂ-ਸੀਮਾ, ਕਤਾਰ-ਭਰੀ ਹੋਣਾ, ਆਈਡੈਂਪੋਟੈਂਟ ਰਿਲੀਜ਼, ਅੰਕੜੇ, ਅਤੇ ਸਫ਼ਾਈ।
2. ਮੌਜੂਦਾ ਖਾਤਾ ਸੈਮਾਫੋਰ ਨੂੰ ਉਸੇ ਥਾਂ ਸਧਾਰਨੀਕ੍ਰਿਤ ਕਰੋ। `acquire()` ਨੂੰ
   `acquireMany()` ਦੇ ਆਲੇ-ਦੁਆਲੇ ਇੱਕ ਅਨੁਕੂਲਤਾ ਰੈਪਰ ਵਜੋਂ ਰੱਖੋ; ਕੋਈ ਦੂਜਾ ਸ਼ਡਿਊਲਰ
   ਜਾਂ ਨਿਰਭਰਤਾ ਨਾ ਜੋੜੋ।
3. `chatCore` ਵਿੱਚ ਸਿਰਫ਼-ਖਾਤਾ ਪ੍ਰਾਪਤੀ ਨੂੰ `withRateLimit` ਤੋਂ ਬਿਲਕੁਲ ਪਹਿਲਾਂ ਇੱਕ ਸੰਚਿਤ
   ਗਲੋਬਲ/ਪ੍ਰਦਾਤਾ/ਖਾਤਾ ਪ੍ਰਾਪਤੀ ਨਾਲ ਬਦਲੋ।
   ਜਦੋਂ ਵੀ ਖਾਤਾ ਰੋਟੇਸ਼ਨ ਕਨੈਕਸ਼ਨ ਨੂੰ ਬਦਲੇ, ਪੂਰੇ ਸੈੱਟ ਨੂੰ ਮੁੜ ਪ੍ਰਾਪਤ ਕਰੋ,
   ਅਤੇ ਸਟ੍ਰੀਮਿੰਗ ਪੂਰੀ ਹੋਣ ਤੱਕ ਰਿਲੀਜ਼ ਨੂੰ ਕਾਇਮ ਰੱਖੋ।
4. ਮੌਜੂਦਾ ਲਚੀਲਾਪਣ ਸੈਟਿੰਗਾਂ ਦੀ ਪਾਈਪਲਾਈਨ (ਕਿਸਮਾਂ, ਮੂਲ ਮੁੱਲ,
   ਨਾਰਮਲਾਈਜ਼ੇਸ਼ਨ, ਸਕੀਮਾ, API ਜਵਾਬ, UI, ਅਤੇ ਅਨੁਵਾਦ) ਨੂੰ ਗਲੋਬਲ
   ਅਤੇ ਪ੍ਰਦਾਤਾ ਸੀਮਾਵਾਂ ਨਾਲ ਵਿਸਤਾਰੋ। ਪੁਰਾਣੇ Bottleneck ਸਮਕਾਲਤਾ ਨਿਯੰਤਰਣ ਨੂੰ
   ਕਨੈਕਸ਼ਨ/ਕੋਟਾ-ਸਕੋਪ ਸਮਕਾਲਤਾ ਵਜੋਂ ਮੁੜ ਲੇਬਲ ਕਰੋ ਤਾਂ ਜੋ ਇਸਦਾ ਅਸਲ ਸਕੋਪ ਸਪਸ਼ਟ ਹੋਵੇ।
5. ਕੇਂਦ੍ਰਿਤ ਟੈਸਟ, lint, typecheck, ਸਥਿਰ ਜਾਂਚਾਂ, ਅਤੇ ਪੂਰਾ ਟੈਸਟ ਸੂਟ ਚਲਾਓ;
   changelog ਵਿੱਚ ਵਿਵਹਾਰਕ ਤਬਦੀਲੀ ਦਾ ਦਸਤਾਵੇਜ਼ੀਕਰਨ ਕਰੋ।

ਜਾਣਬੁੱਝ ਕੇ ਬਰਕਰਾਰ ਰੱਖਿਆ ਗਿਆ ਵਿਵਹਾਰ: ਸਿਫ਼ਰ/null ਸਮਕਾਲਤਾ ਇੱਕ ਗੇਟ ਨੂੰ ਬਾਈਪਾਸ ਕਰਦੀ ਹੈ,
ਸਿਰਫ਼-ਖਾਤਾ ਕਾਲਰ `acquire()` ਦੀ ਵਰਤੋਂ ਜਾਰੀ ਰੱਖਦੇ ਹਨ, ਬਲੌਕ ਕੀਤੇ ਖਾਤਿਆਂ ਦੇ ਨਿਯੰਤਰਣ
ਆਪਣਾ ਕੀ ਫਾਰਮੈਟ ਅਤੇ API ਬਰਕਰਾਰ ਰੱਖਦੇ ਹਨ, ਅਤੇ ਪ੍ਰਦਾਤਾ ਦਰ-ਸੀਮਾ ਕਤਾਰ ਦਾ ਵਿਵਹਾਰ
ਅਣਬਦਲਿਆ ਰਹਿੰਦਾ ਹੈ।
