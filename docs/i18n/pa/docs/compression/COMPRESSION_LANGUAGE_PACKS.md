Caveman ਕੰਪ੍ਰੈਸ਼ਨ, ਅੰਦਰੂਨੀ English ਨਿਯਮਾਂ ਤੋਂ ਇਲਾਵਾ, ਭਾਸ਼ਾ-ਵਿਸ਼ੇਸ਼ ਨਿਯਮ ਪੈਕ ਵੀ ਲੋਡ ਕਰ ਸਕਦਾ ਹੈ।
ਇਸ ਨਾਲ ਮੁੱਖ ਇੰਜਣ ਸਥਿਰ ਰਹਿੰਦਾ ਹੈ, ਜਦਕਿ Portuguese, Spanish, German, French, Italian, Japanese ਅਤੇ
ਭਵਿੱਖ ਦੇ ਭਾਸ਼ਾ ਪੈਕ ਸੁਤੰਤਰ ਤੌਰ 'ਤੇ ਵਿਕਸਿਤ ਹੋ ਸਕਦੇ ਹਨ।

## ਟਿਕਾਣਾ

ਭਾਸ਼ਾ ਪੈਕ ਇੱਥੇ ਸਥਿਤ ਹਨ:

```txt
open-sse/services/compression/rules/<language>/
```

ਮੌਜੂਦਾ ਸ਼ਾਮਲ ਪੈਕ (`rules/` ਡਾਇਰੈਕਟਰੀ ਦੀ ਸਮੱਗਰੀ ਨਾਲ ਤਸਦੀਕ ਕੀਤੇ ਗਏ):

| ਭਾਸ਼ਾ               | ਡਾਇਰੈਕਟਰੀ      | ਮੌਜੂਦ ਨਿਯਮ ਸ਼੍ਰੇਣੀਆਂ                                |
| ------------------- | -------------- | --------------------------------------------------- |
| English             | `rules/en/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Spanish             | `rules/es/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Portuguese (Brazil) | `rules/pt-BR/` | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Indonesian          | `rules/id/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Italian             | `rules/it/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| German              | `rules/de/`    | `context`, `filler`, `structural`                   |
| French              | `rules/fr/`    | `context`, `filler`, `structural`                   |
| Japanese            | `rules/ja/`    | `context`, `filler`, `structural`                   |

> **ਸਮਾਨਤਾ ਸੰਬੰਧੀ ਨੋਟ:** `en`, `es`, `pt-BR`, `id`, ਅਤੇ `it` ਪੈਕਾਂ ਵਿੱਚ ਸਾਰੀਆਂ 5 ਸ਼੍ਰੇਣੀਆਂ ਹਨ; `de`, `fr`, `ja` ਵਿੱਚ 3 ਸ਼੍ਰੇਣੀਆਂ ਸ਼ਾਮਲ ਹਨ। ਗੈਰ-ਮੌਜੂਦ `dedup` ਅਤੇ `ultra` ਸ਼੍ਰੇਣੀਆਂ ਬਿਨਾਂ ਕਿਸੇ ਸੂਚਨਾ ਦੇ ਅੰਦਰੂਨੀ English ਨਿਯਮਾਂ 'ਤੇ ਵਾਪਸ ਚਲੀਆਂ ਜਾਂਦੀਆਂ ਹਨ। ਛੋਟੇ ਪੈਕਾਂ ਲਈ `dedup.json` ਅਤੇ `ultra.json` ਜੋੜਨ ਵਾਸਤੇ ਯੋਗਦਾਨਾਂ ਦਾ ਸਵਾਗਤ ਹੈ।
>
> `pt-BR` ਪੈਕ Lenine Júnior ਦੇ **[Troglodita](https://github.com/leninejunior/troglodita)** 'ਤੇ ਆਧਾਰਿਤ ਹੈ — ਇੱਕ ਕੰਪ੍ਰੈਸ਼ਨ ਸਿਸਟਮ ਜੋ Brazilian Portuguese ਵਿਆਕਰਣ ਲਈ ਸ਼ੁਰੂ ਤੋਂ ਤਿਆਰ ਕੀਤਾ ਗਿਆ ਹੈ (ਫ਼ਜ਼ੂਲ ਦੁਹਰਾਅ ਘਟਾਉਣਾ, PT-BR ਦੇ ਬੇਲੋੜੇ ਭਰਾਵੀ ਸ਼ਬਦ ਹਟਾਉਣਾ, dev BR ਭਾਈਚਾਰੇ ਲਈ ਤਕਨੀਕੀ ਸੰਖੇਪ ਰੂਪ)।
>
> ਪ੍ਰਮਾਣਿਕ ਸ਼੍ਰੇਣੀ ਸੂਚੀ ਅਤੇ ਹਰ ਸ਼੍ਰੇਣੀ ਲਈ ਸਕੀਮਾ [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) (JSON Schema draft 2020-12) ਵਿੱਚ ਮੌਜੂਦ ਹਨ।

## ਭਾਸ਼ਾ ਪਛਾਣ

`languageDetector.ts` ਪ੍ਰੌਮਪਟ ਟੈਕਸਟ ਤੋਂ ਭਾਸ਼ਾ ਦਾ ਅਨੁਮਾਨ ਲਗਾਉਣ ਲਈ ਹਲਕੇ heuristics ਵਰਤਦਾ ਹੈ।
ਕੌਂਫਿਗਰ ਕੀਤੀ ਮੂਲ ਭਾਸ਼ਾ ਦਾ ਫਿਰ ਵੀ ਸਤਿਕਾਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਅਤੇ ਜਦੋਂ ਸਟੀਕ ਨਿਯੰਤਰਣ ਦੀ ਲੋੜ ਹੋਵੇ ਤਾਂ
ਕੌਂਫਿਗ ਰਾਹੀਂ ਪਛਾਣ ਨੂੰ ਅਯੋਗ ਕੀਤਾ ਜਾ ਸਕਦਾ ਹੈ।

ਪਛਾਣ ਦੇ ਆਉਟਪੁੱਟ ਦੀ ਵਰਤੋਂ ਸਿਰਫ਼ ਨਿਯਮ ਪੈਕ ਚੁਣਨ ਲਈ ਕੀਤੀ ਜਾਂਦੀ ਹੈ। ਇਹ provider routing, locale
ਚੋਣ ਜਾਂ UI ਦੀ ਭਾਸ਼ਾ ਨੂੰ ਨਹੀਂ ਬਦਲਦਾ।

## ਕੌਂਫਿਗ ਦੀ ਬਣਤਰ

ਕੰਪ੍ਰੈਸ਼ਨ ਸੈਟਿੰਗਾਂ ਵਿੱਚ ਇਹ ਸ਼ਾਮਲ ਹੋ ਸਕਦਾ ਹੈ:

```json
{
  "languageConfig": {
    "enabled": true,
    "defaultLanguage": "en",
    "autoDetect": true,
    "enabledPacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  },
  "cavemanConfig": {
    "language": "en",
    "autoDetectLanguage": true,
    "enabledLanguagePacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  }
}
```

`languageConfig` ਡੈਸ਼ਬੋਰਡ/ਪ੍ਰੀਵਿਊ ਦੇ ਮੂਲ ਮੁੱਲਾਂ ਨੂੰ ਨਿਯੰਤਰਿਤ ਕਰਦਾ ਹੈ। `cavemanConfig` ਰਨਟਾਈਮ ਇੰਜਣ ਕੌਂਫਿਗ ਹੈ,
ਜਿਸਦੀ ਵਰਤੋਂ Caveman ਵੱਲੋਂ ਸੁਨੇਹੇ ਦੇ ਟੈਕਸਟ ਨੂੰ ਕੰਪ੍ਰੈੱਸ ਕਰਨ ਵੇਲੇ ਕੀਤੀ ਜਾਂਦੀ ਹੈ।

## ਭਾਸ਼ਾ ਪੈਕ ਸ਼ਾਮਲ ਕਰਨਾ

1. `open-sse/services/compression/rules/<language>/<pack>.json` ਬਣਾਓ।
2. `docs/compression/COMPRESSION_RULES_FORMAT.md` ਵਿੱਚ ਦਿੱਤੇ Caveman ਨਿਯਮ ਫਾਰਮੈਟ ਦੀ ਵਰਤੋਂ ਕਰੋ।
3. ਤਬਦੀਲੀਆਂ ਨੂੰ ਸੀਮਤ ਰੱਖੋ ਅਤੇ ਕੋਡ, ਪਛਾਣਕਰਤਾਵਾਂ, URLs ਜਾਂ JSON ਨੂੰ ਬਦਲਣ ਤੋਂ ਬਚੋ।
4. ਭਾਸ਼ਾ ਚੋਣ ਅਤੇ ਤਬਦੀਲੀ ਦੇ ਵਿਹਾਰ ਲਈ ਟੈਸਟ ਸ਼ਾਮਲ ਜਾਂ ਅੱਪਡੇਟ ਕਰੋ।
5. ਜੇ ਭਾਸ਼ਾ UI ਚੋਣਕਾਰਾਂ ਵਿੱਚ ਦਿਖਾਈ ਦਿੰਦੀ ਹੈ, ਤਾਂ ਨਵੇਂ dashboard/i18n ਲੇਬਲ ਉਪਲਬਧ ਕਰਵਾਓ।

## API

ਉਪਲਬਧ ਪੈਕਾਂ ਬਾਰੇ ਇਸ ਤਰ੍ਹਾਂ ਪੁੱਛਗਿੱਛ ਕੀਤੀ ਜਾ ਸਕਦੀ ਹੈ:

```bash
curl http://localhost:20128/api/compression/language-packs
```

ਪੂਰਵਦਰਸ਼ਨ endpoint ਭਾਸ਼ਾ ਸੰਰਚਨਾ ਦੇ overrides ਸਵੀਕਾਰ ਕਰਦਾ ਹੈ:

```bash
curl -X POST http://localhost:20128/api/compression/preview \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "standard",
    "text": "Por favor, eu gostaria que voce basicamente resumisse isso.",
    "config": {
      "languageConfig": {
        "defaultLanguage": "pt-BR",
        "autoDetect": true
      }
    }
  }'
```

## SHARED_BOUNDARIES (v3.8.0)

ਸਾਰੇ 6 ਭਾਸ਼ਾ ਪੈਕਾਂ ਨੂੰ v3.8.0 ਵਿੱਚ ਇੱਕ `SHARED_BOUNDARIES` ਕਲੌਜ਼ ਪ੍ਰਾਪਤ ਹੋਇਆ, ਜੋ ਹਰ
Caveman ਤੀਬਰਤਾ (LITE, FULL, ULTRA) ਉੱਤੇ ਲਾਗੂ ਹੁੰਦਾ ਹੈ। ਇਹ ਇੰਜਣ ਨੂੰ ਆਲੇ-ਦੁਆਲੇ ਦੇ ਫ਼ਜ਼ੂਲ ਸ਼ਬਦ ਹਟਾਉਣ ਦੀ ਪ੍ਰਕਿਰਿਆ ਤੋਂ ਬੇਪਰਵਾਹ ਹੋ ਕੇ,
ਇਨ੍ਹਾਂ ਪੈਟਰਨਾਂ ਨੂੰ ਬਿਲਕੁਲ ਉਸੇ ਤਰ੍ਹਾਂ ਸੁਰੱਖਿਅਤ ਰੱਖਣ ਦਾ ਨਿਰਦੇਸ਼ ਦਿੰਦਾ ਹੈ:

| ਪੈਟਰਨ ਦੀ ਕਿਸਮ                   | ਉਦਾਹਰਨ                                 |
| ------------------------------- | -------------------------------------- |
| Fenced ਕੋਡ ਬਲਾਕ                 | ` ```python\n...\n``` `                |
| Inline ਕੋਡ                      | `` `my_var` ``                         |
| URLs                            | `https://example.com/path`             |
| ਫ਼ਾਈਲ ਪਾਥ (absolute + relative) | `/etc/hosts`, `./src/index.ts`         |
| ਤਰੁੱਟੀ ਹੈਡਰ                     | `Error:`, `TypeError:`, `SyntaxError:` |
| Stack trace ਲਾਈਨਾਂ              | `  at functionName (file.ts:12:3)`     |

ਇਹ ਪੈਟਰਨ `DEFAULT_CAVEMAN_CONFIG.preservePatterns` (ਪਹਿਲਾਂ `[]`) ਵਿੱਚ ਭਰੇ ਜਾਂਦੇ ਹਨ।
constant `open-sse/services/compression/types.ts` ਵਿੱਚ ਮੌਜੂਦ ਹੈ।

### ਇਹ ਮਹੱਤਵਪੂਰਨ ਕਿਉਂ ਹੈ

SHARED_BOUNDARIES ਤੋਂ ਬਿਨਾਂ, ਆਕਰਮਕ Caveman ਮੋਡ ਅਜਿਹੀ ਸਮੱਗਰੀ ਹਟਾ ਸਕਦੇ ਸਨ ਜੋ ਦੁਹਰਾਈ ਜਾਣ ਵਾਲੀ
ਵਾਰਤਕ ਵਰਗੀ ਲੱਗਦੀ ਸੀ, ਪਰ ਅਸਲ ਵਿੱਚ ਇੱਕ ਕੋਡ ਸਨਿੱਪਟ, ਫ਼ਾਈਲ ਪਾਥ ਜਾਂ ਤਰੁੱਟੀ stack ਸੀ। SHARED_BOUNDARIES ਇੱਕ
ਭਾਸ਼ਾ-ਨਿਰਪੱਖ ਸੁਰੱਖਿਆ ਜਾਲ ਵਜੋਂ ਕੰਮ ਕਰਦਾ ਹੈ, ਜੋ ਫ਼ਜ਼ੂਲ ਸ਼ਬਦਾਂ ਦੇ ਨਿਯਮ ਚੱਲਣ ਤੋਂ ਪਹਿਲਾਂ ਲਾਗੂ ਹੁੰਦਾ ਹੈ।

### preservePatterns ਨੂੰ ਅਨੁਕੂਲਿਤ ਕਰਨਾ

compression ਸੈਟਿੰਗਾਂ ਰਾਹੀਂ runtime ਉੱਤੇ ਵਾਧੂ ਪੈਟਰਨ ਸ਼ਾਮਲ ਕੀਤੇ ਜਾ ਸਕਦੇ ਹਨ:

````json
{
  "cavemanConfig": {
    "preservePatterns": [
      "```[\\s\\S]*?```",
      "`[^`]+`",
      "https?://\\S+",
      "(?:/|\\./)[^\\s]+",
      "\\b(?:Error|TypeError|SyntaxError|RangeError):",
      "\\s+at\\s+\\S+\\s+\\(\\S+:\\d+:\\d+\\)"
    ]
  }
}
````

ਕਸਟਮ ਪੈਟਰਨ 6 ਮੂਲ ਪੈਟਰਨਾਂ ਨੂੰ ਵਧਾਉਂਦੇ ਹਨ (ਉਨ੍ਹਾਂ ਨੂੰ ਬਦਲਦੇ ਨਹੀਂ)।

## ਸੰਚਾਲਨ ਸੰਬੰਧੀ ਨੋਟਸ

- ਜਦੋਂ ਕੋਈ ਭਾਸ਼ਾ ਪੈਕ ਮੌਜੂਦ ਨਾ ਹੋਵੇ, ਤਾਂ English ਦੇ built-in ਨਿਯਮ fallback ਵਜੋਂ ਵਰਤੇ ਜਾਂਦੇ ਹਨ।
