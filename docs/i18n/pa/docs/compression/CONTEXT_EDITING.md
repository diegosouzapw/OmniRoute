ਡੈਲੀਗੇਟ ਕੀਤੀ **ਕੰਟੈਕਸਟ ਐਡਿਟਿੰਗ** ਸਿਰਫ਼ Claude ਲਈ ਉਪਲਬਧ ਇੱਕ ਕੰਟੈਕਸਟ-ਪ੍ਰਬੰਧਨ ਵਿਸ਼ੇਸ਼ਤਾ ਹੈ। OmniRoute ਦੇ ਸਥਾਨਕ
ਕੰਪ੍ਰੈਸ਼ਨ ਇੰਜਣਾਂ (Caveman, RTK, LLMLingua, ਸਟੈਕ ਕੀਤੀਆਂ ਪਾਈਪਲਾਈਨਾਂ) ਦੇ ਉਲਟ — ਜੋ ਬੇਨਤੀ ਬਾਡੀ ਨੂੰ
ਪ੍ਰਾਕਸੀ ਤੋਂ ਬਾਹਰ ਜਾਣ _ਤੋਂ ਪਹਿਲਾਂ_ ਮੁੜ ਲਿਖਦੇ ਹਨ — ਕੰਟੈਕਸਟ ਐਡਿਟਿੰਗ **ਪ੍ਰਦਾਤਾ** ਨੂੰ ਆਪਣੇ ਚੱਲ ਰਹੇ ਕੰਟੈਕਸਟ ਵਿੰਡੋ ਵਿੱਚੋਂ ਪੁਰਾਣੇ
ਟੂਲ-ਵਰਤੋਂ / ਟੂਲ-ਨਤੀਜਾ ਬਲਾਕ ਸਾਫ਼ ਕਰਨ ਲਈ ਕਹਿੰਦੀ ਹੈ। OmniRoute ਸਿਰਫ਼ ਇੱਕ ਬਾਡੀ
ਪੈਰਾਮੀਟਰ (`context_management.edits[]`) ਜੋੜਦਾ ਹੈ; ਅਸਲ ਸਫ਼ਾਈ Claude ਆਪਣੇ ਟੋਕਨਾਈਜ਼ਰ ਦੇ ਅਨੁਸਾਰ ਕਰਦਾ ਹੈ।

ਇਹ ਆਪਣੀ ਪ੍ਰਕਿਰਤੀ ਅਨੁਸਾਰ ਇੱਕ ਡੈਲੀਗੇਟ ਕੀਤੀ ਸਮਰੱਥਾ ਹੈ: ਹੋਰ ਪ੍ਰਦਾਤਾ ਇਸ ਪੈਰਾਮੀਟਰ ਨੂੰ ਅਸਵੀਕਾਰ ਕਰਦੇ ਹਨ, ਇਸ ਲਈ OmniRoute ਇਸਨੂੰ
ਸਖ਼ਤੀ ਨਾਲ Claude ਅਤੇ Claude-Code-ਅਨੁਕੂਲ ਰੀਲੇਜ਼ ਤੱਕ ਸੀਮਿਤ ਰੱਖਦਾ ਹੈ।

ਸੱਚਾਈ ਦਾ ਸਰੋਤ: `open-sse/config/contextEditing.ts` (ਰਣਨੀਤੀ ਆਈਡੀਆਂ, ਬਾਡੀ ਇੰਜੈਕਸ਼ਨ, ਟੈਲੀਮੀਟਰੀ
ਐਕਸਟ੍ਰੈਕਸ਼ਨ), `open-sse/executors/base.ts` (ਇੰਜੈਕਸ਼ਨ ਗੇਟ + 400-ਫਾਲਬੈਕ), ਅਤੇ
`open-sse/services/compression/types.ts` (ਕੰਫਿਗ ਬਣਤਰ + ਡਿਫਾਲਟ)।

## `clear_tool_uses` ਕੀ ਕਰਦਾ ਹੈ

OmniRoute ਬਾਹਰ ਭੇਜੀ ਜਾਣ ਵਾਲੀ Anthropic Messages ਬਾਡੀ ਵਿੱਚ ਇੱਕੋ ਐਡਿਟ ਇੰਜੈਕਟ ਕਰਦਾ ਹੈ:

```json
{
  "context_management": {
    "edits": [
      {
        "type": "clear_tool_uses_20250919",
        "trigger": { "type": "input_tokens", "value": 100000 },
        "keep": { "type": "tool_uses", "value": 3 }
      }
    ]
  }
}
```

- `type: "clear_tool_uses_20250919"` — ਮਿਤੀ-ਅੰਕਿਤ Anthropic ਰਣਨੀਤੀ ਆਈਡੀ (`CLEAR_TOOL_USES_STRATEGY`)।
- `trigger.value: 100000` — ਜਦੋਂ ਬੇਨਤੀ ਦੇ ਇਨਪੁੱਟ ਟੋਕਨ ਇਸ ਸੀਮਾ ਤੋਂ ਵੱਧ ਜਾਂਦੇ ਹਨ, Claude ਪੁਰਾਣੇ
  ਟੂਲ-ਵਰਤੋਂ/ਨਤੀਜਾ ਜੋੜਿਆਂ ਨੂੰ ਸਾਫ਼ ਕਰਨਾ ਸ਼ੁਰੂ ਕਰਦਾ ਹੈ (`CONTEXT_EDITING_DEFAULT_TRIGGER_TOKENS`, Anthropic ਦਾ ਡਿਫਾਲਟ)।
- `keep.value: 3` — ਸਭ ਤੋਂ ਹਾਲੀਆ N ਟੂਲ-ਵਰਤੋਂ/ਨਤੀਜਾ ਜੋੜਿਆਂ ਨੂੰ ਬਿਨਾਂ ਛੇੜੇ ਰੱਖਿਆ ਜਾਂਦਾ ਹੈ
  (`CONTEXT_EDITING_DEFAULT_KEEP_TOOL_USES`)।

ਬੀਟਾ ਦੀ ਘੋਸ਼ਣਾ `anthropic-beta: context-management-2025-06-27` ਹੈਡਰ ਰਾਹੀਂ ਕੀਤੀ ਜਾਂਦੀ ਹੈ, ਜਿਸਨੂੰ
OmniRoute ਪਹਿਲਾਂ ਹੀ Claude ਬੇਨਤੀਆਂ ਵਿੱਚ ਭੇਜਦਾ ਹੈ।

ਇੰਜੈਕਸ਼ਨ `applyContextEditingToBody()` ਦੁਆਰਾ ਕੀਤਾ ਜਾਂਦਾ ਹੈ ਅਤੇ ਇਹ **ਆਈਡੈਂਪੋਟੈਂਟ** ਹੈ: ਜੇ ਬਾਡੀ ਉੱਤੇ ਪਹਿਲਾਂ ਹੀ ਕੋਈ `clear_tool_uses`
ਐਡਿਟ ਮੌਜੂਦ ਹੈ (ਕਿਸੇ ਪਿਛਲੀ ਕਾਲ ਦੁਆਰਾ ਜੋੜਿਆ ਗਿਆ ਜਾਂ ਕਲਾਇੰਟ ਵੱਲੋਂ ਦਿੱਤਾ ਗਿਆ), ਤਾਂ ਬਾਡੀ ਨੂੰ
ਜਿਵੇਂ ਦਾ ਤਿਵੇਂ ਛੱਡ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ। ਜੇ ਇੱਕ `clear_thinking_20251015` ਐਡਿਟ ਵੀ ਮੌਜੂਦ ਹੋਵੇ, ਤਾਂ OmniRoute ਸਥਿਰ ਢੰਗ ਨਾਲ
`clear_thinking` ਐਡਿਟ ਨੂੰ ਸਭ ਤੋਂ ਅੱਗੇ ਸੋਰਟ ਕਰਦਾ ਹੈ, ਕਿਉਂਕਿ Anthropic ਦੀ ਲੋੜ ਅਨੁਸਾਰ `edits[]` ਐਰੇ ਵਿੱਚ
`clear_thinking`, `clear_tool_uses` ਤੋਂ ਪਹਿਲਾਂ ਹੋਣਾ ਚਾਹੀਦਾ ਹੈ।

## ਹਰ ਕੌਂਬੋ ਲਈ ਸਮਰੱਥਕ ਟੌਗਲ

ਕੰਟੈਕਸਟ ਐਡਿਟਿੰਗ ਡਿਫਾਲਟ ਤੌਰ 'ਤੇ **ਬੰਦ** ਹੁੰਦੀ ਹੈ ਅਤੇ ਇਸਨੂੰ ਚੋਣ ਰਾਹੀਂ ਸਮਰੱਥ ਕਰਨਾ ਪੈਂਦਾ ਹੈ। ਟੌਗਲ ਇੱਕ ਬੂਲੀਅਨ ਹੈ ਜੋ
ਕੰਪ੍ਰੈਸ਼ਨ ਕੰਫਿਗ ਵਿੱਚ ਰੱਖਿਆ ਜਾਂਦਾ ਹੈ:

- ਸੈਟਿੰਗ ਕੁੰਜੀ: `contextEditing.enabled` (camelCase — `context_editing` / `context-editing` **ਨਹੀਂ**)।
- ਕਿਸਮ: `open-sse/services/compression/types.ts` ਵਿੱਚ
  `ContextEditingConfig { enabled: boolean }`।
- ਡਿਫਾਲਟ: `DEFAULT_CONTEXT_EDITING_CONFIG = { enabled: false }`।
- Zod ਸਕੀਮਾ: `src/shared/validation/compressionConfigSchemas.ts` ਵਿੱਚ `contextEditingConfigSchema`।
- ਸਟੋਰੇਜ: ਬਾਕੀ ਕੰਪ੍ਰੈਸ਼ਨ ਸੈਟਿੰਗਾਂ ਦੇ ਨਾਲ ਸਥਾਈ ਤੌਰ 'ਤੇ ਸੰਭਾਲਿਆ ਜਾਂਦਾ ਹੈ
  (`src/lib/db/compression.ts` ਵਿੱਚ ਨਾਰਮਲਾਈਜ਼ ਕੀਤਾ ਜਾਂਦਾ ਹੈ)।

ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ ਟੌਗਲ ਕੰਪ੍ਰੈਸ਼ਨ ਹੱਬ
(`src/app/(dashboard)/dashboard/context/combos/CompressionHub.tsx`) ਵਿੱਚ ਹੁੰਦਾ ਹੈ ਅਤੇ
`saveSettings()` ਰਾਹੀਂ `{ contextEditing: { enabled: … } }` ਵਾਪਸ ਲਿਖਦਾ ਹੈ। ਕਿਉਂਕਿ ਇਹ
ਕੰਪ੍ਰੈਸ਼ਨ-ਸੈਟਿੰਗਜ਼ ਆਬਜੈਕਟ ਰਾਹੀਂ ਚਲਦਾ ਹੈ, ਇਸ ਲਈ ਇਹ ਪੂਰੀ ਤਰ੍ਹਾਂ ਸੁਤੰਤਰ ਸਤ੍ਹਾ ਹੋਣ ਦੀ ਬਜਾਏ ਹਰ ਕੌਂਬੋ ਦੇ ਕੰਪ੍ਰੈਸ਼ਨ ਪ੍ਰੋਫਾਈਲ ਨਾਲ
ਸੰਯੋਜਿਤ ਹੁੰਦਾ ਹੈ — ਕੰਫਿਗ ਵਿੱਚ ਸਿਰਫ਼ ਚਾਲੂ/ਬੰਦ ਫਲੈਗ ਹੁੰਦਾ ਹੈ; ਸਾਰੀਆਂ ਸੀਮਾਵਾਂ (`trigger`,
`keep`) ਉੱਪਰ ਦਸਤਾਵੇਜ਼ਬੱਧ ਕੀਤੇ ਕਾਂਸਟੈਂਟ ਹਨ।

## ਸਿਰਫ਼ Claude ਲਈ ਗੇਟਿੰਗ

ਇੰਜੈਕਸ਼ਨ ਕੇਵਲ ਅਸਲ Claude ਜਾਂ Claude-Code-ਅਨੁਕੂਲ ਰੀਲੇਅ ਲਈ ਹੀ ਹੁੰਦਾ ਹੈ। `open-sse/executors/base.ts` ਵਿੱਚ ਗੇਟ ਇਹ ਹੈ:

```ts
if (
  (this.provider === "claude" || isClaudeCodeCompatible(this.provider)) &&
  contextEditing?.enabled &&
  !contextEditingDisabled
) {
  applyContextEditingToBody(transformedBody, { enabled: true });
}
```

- `this.provider === "claude"` — ਅਸਲ Anthropic ਕੁੰਜੀ/OAuth।
- `isClaudeCodeCompatible(this.provider)` — ਉਹ ਰੀਲੇਅ ਜਿਨ੍ਹਾਂ ਦੀ ਪ੍ਰਦਾਤਾ ID `anthropic-compatible-cc-` ਪ੍ਰੀਫਿਕਸ ਨਾਲ ਸ਼ੁਰੂ ਹੁੰਦੀ ਹੈ (ਉਹ Claude Code ਅਨੁਕੂਲਤਾ ਦਾ ਦਾਅਵਾ ਕਰਦੇ ਹਨ, ਇਸ ਲਈ ਇਹ ਉਹ ਰੀਲੇਅ ਹਨ ਜਿਨ੍ਹਾਂ ਵੱਲੋਂ ਬੀਟਾ ਸਵੀਕਾਰ ਕੀਤੇ ਜਾਣ ਦੀ ਸਭ ਤੋਂ ਵੱਧ ਸੰਭਾਵਨਾ ਹੈ)। `open-sse/services/provider.ts` ਵੇਖੋ।

ਜਾਣ-ਬੁੱਝ ਕੇ **ਸ਼ਾਮਲ ਨਹੀਂ ਕੀਤੇ ਗਏ**:

- `claude-web` — `create_conversation_params` ਬੇਨਤੀ ਬਣਤਰ ਵਾਲਾ ਇੱਕ ਬ੍ਰਾਊਜ਼ਰ ਰੀਲੇਅ, ਜਿਸ ਨੂੰ ਕਦੇ ਵੀ `context_management` ਨਹੀਂ ਮਿਲਦਾ।
- ਆਮ `anthropic-compatible-*` ਰੀਲੇਅ (`-cc-` ਪ੍ਰੀਫਿਕਸ ਤੋਂ ਬਿਨਾਂ) — ਅਨਿਸ਼ਚਿਤ ਬੀਟਾ ਸਮਰਥਨ ਵਾਲੇ ਤੀਜੀ-ਧਿਰ ਐਂਡਪੁਆਇੰਟ।

ਟੌਗਲ ਚਾਲੂ ਹੋਣ ਦੇ ਬਾਵਜੂਦ, ਗੈਰ-Claude ਪ੍ਰਦਾਤਾਵਾਂ ਨੂੰ ਕਦੇ ਵੀ `context_management` ਪੈਰਾਮੀਟਰ ਨਹੀਂ ਮਿਲਦਾ।

## 400-ਫਾਲਬੈਕ / ਰੀਲੇਅ ਕਵਰੇਜ

ਕੋਈ Claude-ਅਨੁਕੂਲ ਰੀਲੇਅ ਬੀਟਾ ਦਾ ਦਾਅਵਾ ਕਰ ਸਕਦਾ ਹੈ, ਪਰ ਫਿਰ ਵੀ HTTP 400 ਨਾਲ `context_management` ਪੈਰਾਮੀਟਰ ਨੂੰ ਅਸਵੀਕਾਰ ਕਰ ਸਕਦਾ ਹੈ। ਬੇਨਤੀ ਨੂੰ ਅਸਫਲ ਕਰਨ ਦੀ ਬਜਾਏ ਸੁਚਾਰੂ ਢੰਗ ਨਾਲ ਪਿੱਛੇ ਹਟਣ ਲਈ, ਐਗਜ਼ੀਕਿਊਟਰ ਪੈਰਾਮੀਟਰ ਨੂੰ ਹਟਾ ਦਿੰਦਾ ਹੈ ਅਤੇ ਉਸੇ URL ਲਈ **ਇੱਕ ਵਾਰ** ਮੁੜ ਕੋਸ਼ਿਸ਼ ਕਰਦਾ ਹੈ:

```ts
if (
  response.status === HTTP_STATUS.BAD_REQUEST &&
  contextEditing?.enabled &&
  !contextEditingDisabled &&
  transformedBody?.context_management !== undefined
) {
  const errText = await response
    .clone()
    .text()
    .catch(() => "");
  if (/context[_-]management|context editing/i.test(errText)) {
    contextEditingDisabled = true;
    delete transformedBody.context_management;
    let retryBody = JSON.stringify(transformedBody);
    if (isClaudeCodeCompatible(this.provider) || this.provider === "claude") {
      retryBody = await signRequestBody(retryBody);
    }
    response = await fetch(url, { ...fetchOptions, body: retryBody });
  }
}
```

ਵਿਵਹਾਰ:

1. ਇਹ ਕੇਵਲ `400` ਉੱਤੇ ਉਦੋਂ ਸਰਗਰਮ ਹੁੰਦਾ ਹੈ ਜਦੋਂ ਸੰਦਰਭ ਸੰਪਾਦਨ ਸਮਰੱਥ ਹੋਵੇ ਅਤੇ ਬਾਡੀ ਵਿੱਚ ਅਸਲ ਵਿੱਚ `context_management` ਮੌਜੂਦ ਹੋਵੇ।
2. 400 ਬਾਡੀ ਨੂੰ `clone()` ਰਾਹੀਂ ਪੜ੍ਹਿਆ ਜਾਂਦਾ ਹੈ, ਤਾਂ ਜੋ ਮੇਲ ਨਾ ਖਾਣ ਵਾਲੇ ਮਾਰਗ ਲਈ ਮੂਲ ਜਵਾਬ ਜਿਉਂ ਦਾ ਤਿਉਂ ਰਹੇ।
3. ਗਲਤੀ ਦਾ ਟੈਕਸਟ `/context[_-]management|context editing/i` ਨਾਲ ਮੇਲ ਖਾਣਾ ਲਾਜ਼ਮੀ ਹੈ — ਕੋਈ ਗੈਰ-ਸੰਬੰਧਿਤ 400 (ਉਦਾਹਰਨ ਵਜੋਂ `max_tokens must be >= 1`) ਫਾਲਬੈਕ ਨੂੰ ਸਰਗਰਮ **ਨਹੀਂ** ਕਰਦਾ; ਮੂਲ ਗਲਤੀ ਅੱਗੇ ਭੇਜੀ ਜਾਂਦੀ ਹੈ।
4. ਮੇਲ ਹੋਣ ਉੱਤੇ ਇਹ `contextEditingDisabled = true` ਸੈੱਟ ਕਰਦਾ ਹੈ (ਜੇ ਮੁੜ ਕੋਸ਼ਿਸ਼/ਫਾਲਬੈਕ URL ਲਈ ਬਾਅਦ ਵਿੱਚ ਨਵਾਂ `transformedBody` ਬਣਾਇਆ ਜਾਂਦਾ ਹੈ, ਤਾਂ ਇਹ ਦੁਬਾਰਾ ਇੰਜੈਕਸ਼ਨ ਨੂੰ ਰੋਕਦਾ ਹੈ), `context_management` ਨੂੰ ਮਿਟਾਉਂਦਾ ਹੈ, Claude / Claude-Code-ਅਨੁਕੂਲ ਰੀਲੇਅ ਲਈ ਬਾਡੀ ਉੱਤੇ ਮੁੜ ਦਸਤਖ਼ਤ ਕਰਦਾ ਹੈ (`signRequestBody`), ਅਤੇ ਉਸੇ URL ਲਈ ਇੱਕ ਵਾਰ ਮੁੜ ਕੋਸ਼ਿਸ਼ ਕਰਦਾ ਹੈ।

ਅਸਲ Claude ਬੀਟਾ ਨੂੰ `ANTHROPIC_BETA_BASE` ਵਿੱਚ ਲੈ ਕੇ ਚਲਦਾ ਹੈ ਅਤੇ ਇਸ ਫਾਲਬੈਕ ਮਾਰਗ ਤੱਕ ਨਹੀਂ ਪਹੁੰਚਦਾ।

## `applied_edits` ਟੈਲੀਮੈਟਰੀ

Claude ਤੋਂ ਜਵਾਬ ਮਿਲਣ ਤੋਂ ਬਾਅਦ, OmniRoute ਦਰਜ ਕਰਦਾ ਹੈ ਕਿ ਪ੍ਰਦਾਤਾ ਨੇ ਅਸਲ ਵਿੱਚ ਕਿੰਨਾ ਸੰਦਰਭ ਸਾਫ਼ ਕੀਤਾ। ਇਹ **ਸਟ੍ਰੀਮ ਨਹੀਂ ਕੀਤਾ ਜਾਂਦਾ** — ਇਸਨੂੰ ਗੈਰ-ਸਟ੍ਰੀਮਿੰਗ ਜਵਾਬ ਬਾਡੀ ਤੋਂ ਸਰਵੋਤਮ-ਯਤਨ ਦੇ ਆਧਾਰ ਉੱਤੇ ਕੱਢਿਆ ਜਾਂਦਾ ਹੈ ਅਤੇ ਇਹ ਕਦੇ ਵੀ ਜਵਾਬ ਨੂੰ ਪ੍ਰਭਾਵਿਤ ਨਹੀਂ ਕਰਦਾ (ਟੈਲੀਮੈਟਰੀ ਦੀਆਂ ਅਸਫਲਤਾਵਾਂ ਨੂੰ ਅਣਡਿੱਠਾ ਕਰ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ)।

- ਐਕਸਟ੍ਰੈਕਸ਼ਨ: `open-sse/config/contextEditing.ts` ਵਿੱਚ `extractContextEditingTelemetry(responseBody)`। ਇਹ ਜਵਾਬ ਦੀ ਬਣਤਰ ਪ੍ਰਤੀ ਰੱਖਿਆਤਮਕ ਢੰਗ ਨਾਲ ਤਿੰਨ ਸਥਾਨਾਂ ਵਿੱਚ `applied_edits` ਦੀ ਜਾਂਚ ਕਰਦਾ ਹੈ:
  - `context_management.applied_edits`
  - `usage.context_management.applied_edits`
  - `usage.applied_edits`
- ਹਰ ਐਂਟਰੀ ਤੋਂ ਪੜ੍ਹੇ ਜਾਣ ਵਾਲੇ ਪ੍ਰਤੀ-ਸੰਪਾਦਨ ਖੇਤਰ: `cleared_input_tokens` ਅਤੇ `cleared_tool_uses` (snake_case, Anthropic-ਮੂਲ), ਅਤੇ ਫਾਲਬੈਕ ਵਜੋਂ `clearedInputTokens` / `clearedToolUses` camelCase।
- ਜਦੋਂ ਕੋਈ `applied_edits` ਐਰੇ ਨਹੀਂ ਮਿਲਦਾ ਜਾਂ ਅਸਲ ਵਿੱਚ ਕੁਝ ਵੀ ਸਾਫ਼ ਨਹੀਂ ਕੀਤਾ ਗਿਆ ਹੁੰਦਾ, ਤਾਂ `null` ਵਾਪਸ ਕਰਦਾ ਹੈ।

ਰਸੀਦ ਦੀ ਬਣਤਰ `ContextEditingTelemetry { editCount, clearedInputTokens, clearedToolUses }` ਹੈ। ਰਿਕਾਰਡਿੰਗ `open-sse/handlers/chatCore.ts` ਵਿੱਚ (`provider === "claude"` ਤੱਕ ਸੀਮਿਤ) `recordContextEditingTelemetry()` (`src/lib/db/compressionAnalytics.ts`) ਰਾਹੀਂ ਹੁੰਦੀ ਹੈ, ਜੋ ਇਹਨਾਂ ਟੈਗਾਂ ਵਾਲੀ ਕੰਪ੍ਰੈਸ਼ਨ ਐਨਾਲਿਟਿਕਸ ਕਤਾਰ ਲਿਖਦਾ ਹੈ:

- `mode: "context-editing"`
- `engine: "context-editing"`
- `tokens_saved` / `original_tokens` = ਸਾਫ਼ ਕੀਤੇ ਇਨਪੁੱਟ-ਟੋਕਨਾਂ ਦੀ ਗਿਣਤੀ
- `request_id` ਦੇ ਅੰਤ ਵਿੱਚ `::context-editing`

ਇਸ ਤਰ੍ਹਾਂ ਸੌਂਪੀ ਗਈ ਸਫ਼ਾਈ ਸਥਾਨਕ ਇੰਜਣਾਂ ਦੇ ਨਾਲ ਕੰਪ੍ਰੈਸ਼ਨ ਐਨਾਲਿਟਿਕਸ ਵਿੱਚ `context-editing` ਇੰਜਣ ਲੇਬਲ ਹੇਠ ਦਿਖਾਈ ਦਿੰਦੀ ਹੈ ਅਤੇ RTK/Caveman/LLMLingua ਬਚਤਾਂ ਤੋਂ ਵੱਖਰੀ ਪਛਾਣੀ ਜਾ ਸਕਦੀ ਹੈ।
