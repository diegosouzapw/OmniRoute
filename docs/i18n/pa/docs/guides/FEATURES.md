## ✨ v3.8.0 ਦੀਆਂ ਮੁੱਖ ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ

v3.7.x → v3.8.0 ਚੱਕਰ ਵਿੱਚ ਜ਼ੀਰੋ-ਕਨਫਿਗ ਆਟੋ ਰਾਊਟਿੰਗ, ਨਵੇਂ ਪ੍ਰਦਾਤਾ, OAuth ਫਲੋ, ਵਧੇਰੇ ਡੂੰਘੀ ਲਚਕਤਾ ਅਤੇ ਕਾਫ਼ੀ ਬਿਹਤਰ CLI ਅਨੁਭਵ ਸ਼ਾਮਲ ਕੀਤੇ ਗਏ ਹਨ। ਮੁੱਖ ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ ਹੇਠਾਂ ਹਨ — ਪੂਰੇ ਵੇਰਵੇ ਇਸ ਦਸਤਾਵੇਜ਼ ਵਿੱਚ ਅੱਗੇ ਅਤੇ ਲਿੰਕ ਕੀਤੀਆਂ ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ ਵਿੱਚ ਦਿੱਤੇ ਗਏ ਹਨ।

- 🤖 **ਆਟੋ ਕੌਂਬੋ / ਜ਼ੀਰੋ-ਕਨਫਿਗ ਆਟੋ-ਰਾਊਟਿੰਗ** — `auto/coding`, `auto/fast`, `auto/cheap`, `auto/offline`, `auto/smart`, `auto/lkgp`, `auto/chaos` ਪ੍ਰੀਫਿਕਸ ਵਰਤੋ। ਇਹ 16-ਕਾਰਕ ਸਕੋਰਿੰਗ ਇੰਜਣ ਅਤੇ 6 ਚੁਣੇ ਹੋਏ **ਮੋਡ ਪੈਕਾਂ** (ship-fast, cost-saver, quality-first, offline-friendly, reliability-first, chaos-mode) ਦੁਆਰਾ ਸਮਰਥਿਤ ਹੈ
- 🆕 **Command Code ਪ੍ਰਦਾਤਾ** (#2199) — ਮਾਡਲ ਕੈਟਾਲੌਗ ਅਤੇ ਕੋਟਾ ਟ੍ਰੈਕਿੰਗ ਨਾਲ ਪ੍ਰਥਮ-ਸ਼੍ਰੇਣੀ ਰਜਿਸਟ੍ਰੇਸ਼ਨ
- 🆕 **Z.AI ਪ੍ਰਦਾਤਾ** — ਕੋਟਾ ਲੇਬਲਾਂ ਵਾਲਾ ਨਵਾਂ ਮੁਫ਼ਤ-ਟੀਅਰ ਪ੍ਰਦਾਤਾ
- 🎬 **KIE ਮੀਡੀਆ ਵਿਸਤਾਰ** — ਵੀਡੀਓ ਜਨਰੇਸ਼ਨ ਮਾਡਲਾਂ ਸਮੇਤ ਵਿਸਤ੍ਰਿਤ ਕੈਟਾਲੌਗ
- 🔐 **Devin ਪ੍ਰਮਾਣੀਕਰਨ** — Desktop ਇੱਕ ਮੌਜੂਦਾ Devin API ਕੁੰਜੀ ਆਯਾਤ ਕਰਦਾ ਹੈ; CLI ਸਥਾਨਕ `devin auth login` ਕ੍ਰੈਡੈਂਸ਼ਲ ਵਰਤਦਾ ਹੈ
- 🆓 **8 ਨਵੇਂ ਮੁਫ਼ਤ ਪ੍ਰਦਾਤਾ** — LLM7, Lepton, UncloseAI, BazaarLink, Completions, Enally, FreeTheAi, Command Code
- 🎯 **ਮੈਨੀਫੈਸਟ-ਅਵੇਅਰ ਟੀਅਰ ਰਾਊਟਿੰਗ W1–W4** — ਪ੍ਰਦਾਤਾ ਮੈਨੀਫੈਸਟ ਭਾਰਿਤ ਟੀਅਰ ਚੋਣ ਨੂੰ ਚਲਾਉਂਦੇ ਹਨ

AI ਪ੍ਰਦਾਤਾ ਕਨੈਕਸ਼ਨਾਂ ਦਾ ਪ੍ਰਬੰਧਨ ਕਰੋ: OAuth ਪ੍ਰਦਾਤਾ (Claude Code, Codex), API ਕੁੰਜੀ ਪ੍ਰਦਾਤਾ (Groq, DeepSeek, OpenRouter), ਅਤੇ ਮੁਫ਼ਤ ਪ੍ਰਦਾਤਾ (Qoder, Kiro)। Kiro ਖਾਤਿਆਂ ਵਿੱਚ ਕ੍ਰੈਡਿਟ ਬਕਾਇਆ ਟ੍ਰੈਕਿੰਗ ਸ਼ਾਮਲ ਹੈ — ਬਾਕੀ ਕ੍ਰੈਡਿਟ, ਕੁੱਲ ਮਨਜ਼ੂਰਸ਼ੁਦਾ ਮਾਤਰਾ, ਅਤੇ ਨਵੀਨੀਕਰਨ ਦੀ ਮਿਤੀ Dashboard → Usage ਵਿੱਚ ਦਿਖਾਈ ਦਿੰਦੀ ਹੈ।

OpenRouter ਕਨੈਕਸ਼ਨ Advanced Settings ਵਿੱਚ ਪ੍ਰਤੀ-ਕਨੈਕਸ਼ਨ `preset` ਸਟੋਰ ਕਰ ਸਕਦੇ ਹਨ। ਜਦੋਂ ਇਹ ਸੈੱਟ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਤਾਂ OmniRoute ਇਸਨੂੰ OpenRouter ਦੇ ਸਿਖਰਲੇ-ਪੱਧਰ ਦੇ ਬੇਨਤੀ ਫ਼ੀਲਡ ਵਜੋਂ ਭੇਜਦਾ ਹੈ, ਉਦਾਹਰਨ ਲਈ `"preset": "email-copywriter"`, ਜਦੋਂ ਤੱਕ ਕਲਾਇੰਟ ਬੇਨਤੀ ਨੇ ਪਹਿਲਾਂ ਹੀ ਆਪਣਾ `preset` ਨਾ ਦਿੱਤਾ ਹੋਵੇ।

## 🎨 ਕੌਂਬੋ

19 ਜਨਤਕ ਰਣਨੀਤੀਆਂ ਨਾਲ ਮਾਡਲ ਰੂਟਿੰਗ ਕੌਂਬੋ ਬਣਾਓ: ਤਰਜੀਹ, ਭਾਰਿਤ, ਰਾਊਂਡ-ਰੌਬਿਨ, ਸੰਦਰਭ-ਰੀਲੇ, ਪਹਿਲਾਂ-ਭਰੋ, p2c (ਦੋ ਵਿਕਲਪਾਂ ਦੀ ਸ਼ਕਤੀ), ਬੇਤਰਤੀਬ, ਸਭ ਤੋਂ-ਘੱਟ-ਵਰਤਿਆ, ਲਾਗਤ-ਅਨੁਕੂਲਿਤ, ਰੀਸੈੱਟ-ਸਚੇਤ, ਰੀਸੈੱਟ-ਵਿੰਡੋ, ਹੈੱਡਰੂਮ, ਸਖ਼ਤ-ਬੇਤਰਤੀਬ, ਆਟੋ, lkgp (ਆਖਰੀ-ਜਾਣਿਆ-ਚੰਗਾ-ਪ੍ਰਦਾਤਾ), ਸੰਦਰਭ-ਅਨੁਕੂਲਿਤ, ਕੈਸ਼-ਅਨੁਕੂਲਿਤ, **ਫਿਊਜ਼ਨ** (ਮਾਡਲਾਂ ਦੇ ਇੱਕ ਪੈਨਲ ਨੂੰ ਸਮਾਂਤਰ ਤੌਰ 'ਤੇ ਬੇਨਤੀ ਭੇਜੋ, ਫਿਰ ਇੱਕ ਨਿਰਣਾਇਕ ਰਾਹੀਂ ਇੱਕ ਜਵਾਬ ਦਾ ਸੰਸ਼ਲੇਸ਼ਣ ਕਰੋ), ਅਤੇ **ਪਾਈਪਲਾਈਨ**। ਹਰ ਕੌਂਬੋ ਆਟੋਮੈਟਿਕ ਫਾਲਬੈਕ ਨਾਲ ਕਈ ਮਾਡਲਾਂ ਨੂੰ ਲੜੀਬੱਧ ਕਰਦਾ ਹੈ ਅਤੇ ਇਸ ਵਿੱਚ ਤੁਰੰਤ ਟੈਂਪਲੇਟ ਅਤੇ ਤਿਆਰੀ ਜਾਂਚਾਂ ਸ਼ਾਮਲ ਹੁੰਦੀਆਂ ਹਨ।

ਕੌਂਬੋ ਵਿੱਚ ਹਾਲੀਆ ਸੁਧਾਰ:

- **ਸੰਰਚਿਤ ਕੌਂਬੋ ਬਿਲਡਰ** — ਪ੍ਰਦਾਤਾ, ਮਾਡਲ, ਅਤੇ ਸਟੀਕ ਖਾਤਾ/ਕਨੈਕਸ਼ਨ ਚੁਣ ਕੇ ਹਰ ਪੜਾਅ ਬਣਾਓ
- **ਦੁਹਰਾਏ ਗਏ ਪ੍ਰਦਾਤਾ ਲਈ ਸਮਰਥਨ** — ਇੱਕੋ ਕੌਂਬੋ ਵਿੱਚ ਇੱਕੋ ਪ੍ਰਦਾਤਾ ਨੂੰ ਕਈ ਵਾਰ ਮੁੜ ਵਰਤੋ, ਬਸ਼ਰਤੇ `(provider, model, connection)` ਟਿਊਪਲ ਵਿਲੱਖਣ ਹੋਵੇ
- **ਕੌਂਬੋ ਟਾਰਗੇਟ ਦੀ ਸਿਹਤ** — ਵਿਸ਼ਲੇਸ਼ਣ ਅਤੇ ਸਿਹਤ ਸਤ੍ਹਾਂ ਹੁਣ ਹਰ ਚੀਜ਼ ਨੂੰ ਮਾਡਲ ਸਟ੍ਰਿੰਗਾਂ ਵਿੱਚ ਇਕੱਠਾ ਕਰਨ ਦੀ ਬਜਾਏ ਵਿਅਕਤੀਗਤ ਕੌਂਬੋ ਟਾਰਗੇਟਾਂ/ਪੜਾਵਾਂ ਵਿੱਚ ਫ਼ਰਕ ਕਰਦੀਆਂ ਹਨ
- **ਸੰਯੁਕਤ ਟੀਅਰ ਕ੍ਰਮ** — `defaultTier -> fallbackTier` ਹੁਣ ਸਿਖਰਲੇ-ਪੱਧਰ ਦੇ ਕੌਂਬੋ ਪੜਾਵਾਂ ਲਈ ਰਨਟਾਈਮ ਐਗਜ਼ੀਕਿਊਸ਼ਨ/ਫਾਲਬੈਕ ਕ੍ਰਮ ਨੂੰ ਪ੍ਰਭਾਵਿਤ ਕਰਦਾ ਹੈ
- **ਸਿਸਟਮ ਪ੍ਰੌਂਪਟ ਟੈਂਪਲੇਟ** — ਕੌਂਬੋ `system_message` ਸਰਵਰ-ਪਾਸੇ
  `{{MODEL_ID}}`, `{{PROVIDER_ID}}`, `{{ACCOUNT}}` ਅਤੇ `{{FINGERPRINT}}`
  ਪਲੇਸਹੋਲਡਰਾਂ ਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈ, ਜਿਨ੍ਹਾਂ ਨੂੰ ਡਿਸਪੈਚ ਤੋਂ ਐਨ ਪਹਿਲਾਂ ਅਸਲ ਵਿੱਚ ਰੂਟ ਕੀਤੇ ਟਾਰਗੇਟ ਤੋਂ ਵਿਸਤਾਰਿਆ ਜਾਂਦਾ ਹੈ।
  ਇਹ ਮਨਜ਼ੂਰਸ਼ੁਦਾ-ਸੂਚੀਬੱਧ ਅਤੇ ਗੈਰ-ਆਵਰਤੀ ਹਨ; ਅਣਜਾਣ ਪਲੇਸਹੋਲਡਰ ਜਿਉਂ ਦੇ ਤਿਉਂ ਰਹਿੰਦੇ ਹਨ; ਖਾਲੀ ਮੁੱਲ
  ਖਾਲੀ ਵਜੋਂ ਵਿਸਤਾਰਦੇ ਹਨ; ਕਲਾਇੰਟ ਸਿਸਟਮ ਪ੍ਰੌਂਪਟ ਕਦੇ ਵੀ ਮੁੜ ਨਹੀਂ ਲਿਖੇ ਜਾਂਦੇ। `{{FINGERPRINT}}`
  ਕੇਵਲ ਪਿੰਨ ਕੀਤੇ ਜਾਂ ਆਟੋ-ਰੋਟੇਟ ਕੀਤੇ ਫਿੰਗਰਪ੍ਰਿੰਟ ਵਾਲੇ ਫਿੰਗਰਪ੍ਰਿੰਟ-ਆਧਾਰਿਤ ਮੁਫ਼ਤ ਪ੍ਰਦਾਤਾਵਾਂ ਲਈ ਹੀ ਰਿਜ਼ਾਲਵ ਹੁੰਦਾ ਹੈ — ਹੋਰ ਥਾਵਾਂ 'ਤੇ ਇਹ ਖਾਲੀ ਵਜੋਂ ਵਿਸਤਾਰਦਾ ਹੈ (ਉਦਾਹਰਨ ਲਈ
  ਇਕੱਲੇ-ਫਿੰਗਰਪ੍ਰਿੰਟ ਵਾਲੇ ਕਨੈਕਸ਼ਨ, ਗੈਰ-fp ਪ੍ਰਦਾਤਾ)। ਵਿਸਤਾਰ ਮਿਆਰੀ
  ਡਿਸਪੈਚ ਲੂਪ, ਰਾਊਂਡ-ਰੌਬਿਨ, ਅਤੇ ਪਿੰਨ ਕੀਤੇ ਸੰਦਰਭ-ਕੈਸ਼ ਸੈਸ਼ਨਾਂ ਨੂੰ ਕਵਰ ਕਰਦਾ ਹੈ;

  ਪਲੇਸਹੋਲਡਰਾਂ ਦਾ ਵਿਸਤਾਰ ਨਹੀਂ ਕਰਦੀਆਂ।

**7 ਟੈਬਾਂ** ਵਾਲਾ ਵਿਸਤ੍ਰਿਤ ਸੈਟਿੰਗ ਪੈਨਲ:

- **AI** — AI ਸਹਾਇਕ ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ, ਡਿਫੌਲਟ ਰੂਟਿੰਗ ਪ੍ਰੀਸੈੱਟ (ਆਟੋ ਕੰਬੋ `auto/coding`, `auto/fast`, `auto/cheap`, `auto/smart`), ਰੀਜ਼ਨਿੰਗ ਰੀਪਲੇ ਕੈਸ਼ ਅਤੇ ਹੁਨਰ/ਮੈਮੋਰੀ ਟੌਗਲ
- **ਸੁਰੱਖਿਆ** — API ਐਂਡਪੌਇੰਟ ਸੁਰੱਖਿਆ, ਕਸਟਮ ਪ੍ਰਦਾਤਾ ਬਲੌਕਿੰਗ, IP ਫਿਲਟਰਿੰਗ, ਸੈਸ਼ਨ ਜਾਣਕਾਰੀ
- **ਰੂਟਿੰਗ** — ਮਾਡਲ ਉਪਨਾਮ, ਬੈਕਗ੍ਰਾਊਂਡ ਟਾਸਕ ਡਿਗ੍ਰੇਡੇਸ਼ਨ, ਮੈਨੀਫੈਸਟ-ਅਵੇਅਰ ਟੀਅਰ ਰੂਟਿੰਗ (W1–W4), `fallbackDelayMs`, ਪ੍ਰਤੀ-ਸੈਸ਼ਨ ਸਟਿੱਕੀ ਰੂਟਿੰਗ
- **ਲਚਕੀਲਾਪਣ** — ਰੇਟ ਲਿਮਿਟ ਸਥਿਰਤਾ, ਸਰਕਿਟ ਬ੍ਰੇਕਰ ਟਿਊਨਿੰਗ, ਪਾਬੰਦੀਸ਼ੁਦਾ ਖਾਤਿਆਂ ਨੂੰ ਆਪਣੇ-ਆਪ ਅਯੋਗ ਕਰਨਾ, ਪ੍ਰਦਾਤਾ ਮਿਆਦ ਸਮਾਪਤੀ ਦੀ ਨਿਗਰਾਨੀ, **ਕੰਟੈਕਸਟ ਰੀਲੇ** ਹੈਂਡਆਫ਼ ਥ੍ਰੈਸ਼ਹੋਲਡ ਅਤੇ ਸੰਖੇਪ ਮਾਡਲ ਸੰਰਚਨਾ, ਪ੍ਰਤੀ-ਪ੍ਰਦਾਤਾ 429 ਵਰਗੀਕਰਨ ਅਤੇ `useUpstream429BreakerHints` ਟੌਗਲ, ਮਾਡਲ ਕੂਲਡਾਊਨ

## 🔗 ਸੰਦਰਭ ਰੀਲੇ _(v3.5.5+)_

ਇੱਕ ਸੰਯੁਕਤ ਰਣਨੀਤੀ ਜੋ ਗੱਲਬਾਤ ਦੇ ਵਿਚਕਾਰ ਖਾਤਾ ਬਦਲਣ ਵੇਲੇ ਸੈਸ਼ਨ ਦੀ ਨਿਰੰਤਰਤਾ ਨੂੰ ਬਰਕਰਾਰ ਰੱਖਦੀ ਹੈ। ਸਰਗਰਮ ਖਾਤੇ ਦਾ ਕੋਟਾ ਖ਼ਤਮ ਹੋਣ ਤੋਂ ਪਹਿਲਾਂ, OmniRoute ਬੈਕਗ੍ਰਾਊਂਡ ਵਿੱਚ ਇੱਕ ਸੰਰਚਿਤ ਹਵਾਲਗੀ ਸਾਰ ਤਿਆਰ ਕਰਦਾ ਹੈ। ਜਦੋਂ ਅਗਲੀ ਬੇਨਤੀ ਕਿਸੇ ਵੱਖਰੇ ਖਾਤੇ ਰਾਹੀਂ ਪੂਰੀ ਹੁੰਦੀ ਹੈ, ਤਾਂ ਸਾਰ ਨੂੰ ਸਿਸਟਮ ਸੁਨੇਹੇ ਵਜੋਂ ਸ਼ਾਮਲ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਤਾਂ ਜੋ ਨਵਾਂ ਖਾਤਾ ਪੂਰੇ ਸੰਦਰਭ ਨਾਲ ਜਾਰੀ ਰੱਖ ਸਕੇ।

ਕੌਂਬੋ-ਪੱਧਰੀ ਜਾਂ ਗਲੋਬਲ ਸੈਟਿੰਗਾਂ ਰਾਹੀਂ ਸੰਰਚਨਾਯੋਗ:

- **ਹਵਾਲਗੀ ਥ੍ਰੈਸ਼ਹੋਲਡ** — ਕੋਟਾ ਵਰਤੋਂ ਦੀ ਉਹ ਪ੍ਰਤੀਸ਼ਤਤਾ ਜੋ ਸਾਰ ਤਿਆਰ ਕਰਨ ਦੀ ਪ੍ਰਕਿਰਿਆ ਸ਼ੁਰੂ ਕਰਦੀ ਹੈ (ਮੂਲ 85%)
- **ਸਾਰ ਲਈ ਵੱਧ ਤੋਂ ਵੱਧ ਸੁਨੇਹੇ** — ਹਾਲੀਆ ਇਤਿਹਾਸ ਦਾ ਕਿੰਨਾ ਹਿੱਸਾ ਸੰਖੇਪ ਕਰਨਾ ਹੈ
- **ਸਾਰ ਮਾਡਲ** — ਹਵਾਲਗੀ ਸਾਰ ਤਿਆਰ ਕਰਨ ਲਈ ਵਿਕਲਪਿਕ ਓਵਰਰਾਈਡ ਮਾਡਲ

ਵਰਤਮਾਨ ਵਿੱਚ Codex ਖਾਤਾ ਰੋਟੇਸ਼ਨ ਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈ। [ਸੰਦਰਭ ਰੀਲੇ ਦਸਤਾਵੇਜ਼](../architecture/ARCHITECTURE.md) ਵੇਖੋ।

ਪੂਰੀ ਬੇਨਤੀ ਪਾਈਪਲਾਈਨ ਵਿੱਚ ਵਿਆਪਕ ਪ੍ਰੌਕਸੀ ਸੰਰਚਨਾ ਲਾਗੂਕਰਨ:

- **ਟੋਕਨ ਸਿਹਤ ਜਾਂਚ** — ਬੈਕਗ੍ਰਾਊਂਡ OAuth ਰਿਫ੍ਰੈਸ਼ ਹੁਣ ਹਰ ਕਨੈਕਸ਼ਨ ਲਈ ਪ੍ਰੌਕਸੀ ਸੰਰਚਨਾ ਹੱਲ ਕਰਦਾ ਹੈ, ਜਿਸ ਨਾਲ ਪ੍ਰੌਕਸੀ-ਲਾਜ਼ਮੀ ਵਾਤਾਵਰਣਾਂ ਵਿੱਚ ਅਸਫਲਤਾਵਾਂ ਰੁਕਦੀਆਂ ਹਨ
- **API ਕੁੰਜੀ ਪ੍ਰਮਾਣਿਕਤਾ** — ਪ੍ਰਦਾਤਾ ਕੁੰਜੀ ਪ੍ਰਮਾਣਿਕਤਾ (`POST /api/providers/validate`), ਪ੍ਰਦਾਤਾ-ਪੱਧਰੀ ਅਤੇ ਗਲੋਬਲ ਪ੍ਰੌਕਸੀ ਸੈਟਿੰਗਾਂ ਦਾ ਸਤਿਕਾਰ ਕਰਦੇ ਹੋਏ, `runWithProxyContext` ਰਾਹੀਂ ਰੂਟ ਹੁੰਦੀ ਹੈ
- **undici ਡਿਸਪੈਚਰ ਸੁਧਾਰ** — ਪ੍ਰੌਕਸੀ ਡਿਸਪੈਚਰ Node ਦੇ ਅੰਦਰੂਨੀ fetch ਦੀ ਬਜਾਏ undici ਦੇ ਆਪਣੇ fetch ਲਾਗੂਕਰਨ ਦੀ ਵਰਤੋਂ ਕਰਦੇ ਹਨ, ਜਿਸ ਨਾਲ Node.js 22 ਉੱਤੇ `invalid onRequestStart method` ਤਰੁੱਟੀਆਂ ਹੱਲ ਹੁੰਦੀਆਂ ਹਨ
- **Node.js ਵਰਜਨ ਪਛਾਣ** — ਲੌਗਇਨ ਪੰਨਾ ਅਸੰਗਤ Node.js ਵਰਜਨਾਂ (24+) ਦੀ ਪਹਿਲਾਂ ਹੀ ਪਛਾਣ ਕਰਦਾ ਹੈ ਅਤੇ Node 22 LTS ਵਰਤਣ ਦੀਆਂ ਹਦਾਇਤਾਂ ਵਾਲਾ ਚੇਤਾਵਨੀ ਬੈਨਰ ਦਿਖਾਉਂਦਾ ਹੈ

- ਇਕਹਿਰੀ-ਇੰਸਟੈਂਸ ਲੌਕ
- ਮੁੜ-ਚਾਲੂ ਕਰਨ 'ਤੇ ਆਟੋ-ਅੱਪਡੇਟ
- ਪਲੇਟਫਾਰਮ-ਸ਼ਰਤੀਆ UI (macOS ਟ੍ਰੈਫਿਕ ਲਾਈਟਾਂ, Windows/Linux ਡਿਫਾਲਟ ਟਾਈਟਲਬਾਰ)
- ਮਜ਼ਬੂਤ Electron ਬਿਲਡ ਪੈਕੇਜਿੰਗ — ਸੁਤੰਤਰ ਬੰਡਲ ਵਿੱਚ ਸਿਮਲਿੰਕ ਕੀਤਾ `node_modules` ਪੈਕੇਜਿੰਗ ਤੋਂ ਪਹਿਲਾਂ ਪਛਾਣਿਆ ਅਤੇ ਰੱਦ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਜਿਸ ਨਾਲ ਬਿਲਡ ਮਸ਼ੀਨ ਉੱਤੇ ਰਨਟਾਈਮ ਨਿਰਭਰਤਾ ਰੋਕੀ ਜਾਂਦੀ ਹੈ (v2.5.5+)
- **ਸੁਚਾਰੂ ਸ਼ਟਡਾਊਨ** — Electron `before-quit`, Next.js ਨੂੰ ਸਹੀ ਢੰਗ ਨਾਲ ਬੰਦ ਕਰਦਾ ਹੈ, ਜਿਸ ਨਾਲ SQLite WAL ਡੇਟਾਬੇਸ ਲੌਕਾਂ ਤੋਂ ਬਚਾਅ ਹੁੰਦਾ ਹੈ (v3.6.2+)

## 🌐 V1 WebSocket ਬ੍ਰਿਜ _(v3.6.6+)_

OmniRoute ਹੁਣ `/v1/ws` ਅੱਪਗ੍ਰੇਡ ਐਂਡਪੌਇੰਟ ਰਾਹੀਂ **OpenAI-ਅਨੁਕੂਲ WebSocket ਕਲਾਇੰਟਾਂ** ਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈ। ਕਸਟਮ `scripts/dev/v1-ws-bridge.mjs` ਸਰਵਰ Next.js ਨੂੰ ਰੈਪ ਕਰਦਾ ਹੈ ਅਤੇ WS ਕਨੈਕਸ਼ਨਾਂ ਨੂੰ ਪੂਰੇ ਦੋ-ਦਿਸ਼ਾਵੀ ਸਟ੍ਰੀਮਿੰਗ ਸੈਸ਼ਨਾਂ ਵਿੱਚ ਅੱਪਗ੍ਰੇਡ ਕਰਦਾ ਹੈ। ਪ੍ਰਮਾਣੀਕਰਨ HTTP ਬੇਨਤੀਆਂ ਵਾਲੀ ਉਹੀ API ਕੁੰਜੀ ਜਾਂ ਸੈਸ਼ਨ ਕੁਕੀ ਵਰਤਦਾ ਹੈ।

ਮੁੱਖ ਵਿਹਾਰ:

- ਕਨੈਕਸ਼ਨ ਸਥਾਪਿਤ ਹੋਣ ਤੋਂ ਪਹਿਲਾਂ `src/lib/ws/handshake.ts` ਦੁਆਰਾ WS ਅੱਪਗ੍ਰੇਡ ਦੀ ਪੁਸ਼ਟੀ ਕੀਤੀ ਜਾਂਦੀ ਹੈ
- ਸੈਸ਼ਨ ਬੰਦ ਹੋਣ ਜਾਂ ਅੱਪਸਟ੍ਰੀਮ ਗਲਤੀ ਆਉਣ 'ਤੇ ਸਟ੍ਰੀਮਾਂ ਨੂੰ ਸਹੀ ਢੰਗ ਨਾਲ ਸਮਾਪਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ
- ਮੌਜੂਦਾ HTTP+SSE ਸਟ੍ਰੀਮਿੰਗ ਪਾਥ ਦੇ ਨਾਲ-ਨਾਲ ਇੱਕੋ ਸਮੇਂ ਕੰਮ ਕਰਦਾ ਹੈ

## 🔑 ਸਿੰਕ ਟੋਕਨ ਅਤੇ ਕਨਫਿਗ ਬੰਡਲ _(v3.6.6+)_

ਹੁਣ **ਸਕੋਪ ਕੀਤੇ ਸਿੰਕ ਟੋਕਨਾਂ** ਰਾਹੀਂ ਕਈ ਡਿਵਾਈਸਾਂ ਅਤੇ ਬਾਹਰੀ ਓਪਰੇਟਰਾਂ ਲਈ ਪਹੁੰਚ ਸੰਭਵ ਹੈ:

- **`POST /api/sync/tokens`** — ਨਵਾਂ ਸਿੰਕ ਟੋਕਨ ਜਾਰੀ ਕਰੋ (ਸਕੋਪ ਕੀਤਾ ਹੋਇਆ, ਵਿਕਲਪਿਕ ਮਿਆਦ ਸਮਾਪਤੀ ਸਮੇਤ)
- **`DELETE /api/sync/tokens/:id`** — ਟੋਕਨ ਰੱਦ ਕਰੋ
- **`GET /api/sync/bundle`** — ਸਾਰੀਆਂ ਗੈਰ-ਸੰਵੇਦਨਸ਼ੀਲ ਸੈਟਿੰਗਾਂ ਦਾ ਵਰਜਨਯੁਕਤ, ETag-ਕੁੰਜੀਬੱਧ JSON ਸਨੈਪਸ਼ਾਟ ਡਾਊਨਲੋਡ ਕਰੋ (ਪਾਸਵਰਡ ਲੁਕਾਏ ਹੋਏ)

ਕਨਫਿਗ ਬੰਡਲ `src/lib/sync/bundle.ts` ਦੁਆਰਾ ਬਣਾਇਆ ਜਾਂਦਾ ਹੈ। ਪੂਰਾ ਪੇਲੋਡ ਮੁੜ ਡਾਊਨਲੋਡ ਕੀਤੇ ਬਿਨਾਂ ਤਬਦੀਲੀਆਂ ਦਾ ਪਤਾ ਲਗਾਉਣ ਲਈ ਉਪਭੋਗਤਾ `ETag` ਜਵਾਬ ਹੈਡਰ ਦੀ ਤੁਲਨਾ ਕਰਦੇ ਹਨ।

## 🛡️ ਸੁਰੱਖਿਅਤ ਆਊਟਬਾਊਂਡ ਫੈਚ ਅਤੇ SSRF ਗਾਰਡ _(v3.6.6+)_

ਹੁਣ ਸਾਰੀਆਂ ਪ੍ਰਦਾਤਾ ਪ੍ਰਮਾਣਿਕਤਾ ਅਤੇ ਮਾਡਲ ਖੋਜ ਕਾਲਾਂ ਦੋ-ਪਰਤੀ ਆਊਟਬਾਊਂਡ ਗਾਰਡ ਰਾਹੀਂ ਜਾਂਦੀਆਂ ਹਨ:

1. **URL ਗਾਰਡ** (`src/shared/network/outboundUrlGuard.ts`) — ਸਾਕਟ ਖੋਲ੍ਹੇ ਜਾਣ ਤੋਂ ਪਹਿਲਾਂ ਪ੍ਰਾਈਵੇਟ/ਲੂਪਬੈਕ/ਲਿੰਕ-ਲੋਕਲ IP ਰੇਂਜਾਂ ਨੂੰ ਬਲੌਕ ਕਰਦਾ ਹੈ।
2. **ਸੁਰੱਖਿਅਤ ਫੈਚ ਰੈਪਰ** (`src/shared/network/safeOutboundFetch.ts`) — URL ਗਾਰਡ ਲਾਗੂ ਕਰਦਾ ਹੈ, ਟਾਈਮਆਉਟਾਂ ਨੂੰ ਸਧਾਰਨ ਬਣਾਉਂਦਾ ਹੈ, ਅਤੇ ਅਸਥਾਈ ਗਲਤੀਆਂ ਉੱਤੇ ਐਕਸਪੋਨੇਨਸ਼ੀਅਲ ਬੈਕਆਫ਼ ਨਾਲ ਮੁੜ ਕੋਸ਼ਿਸ਼ ਕਰਦਾ ਹੈ।

ਗਾਰਡ ਉਲੰਘਣਾਵਾਂ HTTP 422 (`URL_GUARD_BLOCKED`) ਵਜੋਂ ਸਾਹਮਣੇ ਆਉਂਦੀਆਂ ਹਨ ਅਤੇ `providerAudit.ts` ਰਾਹੀਂ ਅਨੁਪਾਲਨਾ ਆਡਿਟ ਲੌਗ ਵਿੱਚ ਲਿਖੀਆਂ ਜਾਂਦੀਆਂ ਹਨ।

## 🔄 ਕੂਲਡਾਊਨ-ਸਚੇਤ ਮੁੜ ਕੋਸ਼ਿਸ਼ਾਂ _(v3.6.6+)_

ਜਦੋਂ ਕੋਈ ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰਦਾਤਾ ਮਾਡਲ-ਸਕੋਪਡ ਕੂਲਡਾਊਨ ਵਾਪਸ ਕਰਦਾ ਹੈ, ਤਾਂ ਹੁਣ ਚੈਟ ਬੇਨਤੀਆਂ **ਆਪਣੇ-ਆਪ ਮੁੜ ਕੋਸ਼ਿਸ਼ ਕਰਦੀਆਂ ਹਨ**। ਇਸਨੂੰ `REQUEST_RETRY` (ਡਿਫਾਲਟ: 2) ਅਤੇ `MAX_RETRY_INTERVAL_SEC` (ਡਿਫਾਲਟ: 30 s) ਰਾਹੀਂ ਸੰਰਚਿਤ ਕੀਤਾ ਜਾ ਸਕਦਾ ਹੈ। `x-ratelimit-reset-requests`, `x-ratelimit-reset-tokens`, ਅਤੇ `Retry-After` ਵਿੱਚ ਰੇਟ-ਲਿਮਿਟ ਹੈਡਰ ਲਰਨਿੰਗ ਨੂੰ ਬਿਹਤਰ ਬਣਾਇਆ ਗਿਆ ਹੈ — ਪ੍ਰਤੀ-ਮਾਡਲ ਕੂਲਡਾਊਨ ਸਥਿਤੀ Resilience ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ ਦਿਖਾਈ ਦਿੰਦੀ ਹੈ।

ਆਡਿਟ ਲੌਗ ਨੂੰ ਕਰਸਰ-ਅਧਾਰਿਤ ਪੇਜੀਨੇਸ਼ਨ, ਬੇਨਤੀ ਸੰਦਰਭ ਸੰਵਰਧਨ (ਬੇਨਤੀ ID, ਯੂਜ਼ਰ ਏਜੰਟ, IP), ਸੰਰਚਿਤ ਪ੍ਰਮਾਣੀਕਰਨ ਇਵੈਂਟਾਂ, ਅੰਤਰ ਸੰਦਰਭ ਸਮੇਤ ਪ੍ਰਦਾਤਾ CRUD ਇਵੈਂਟਾਂ, ਅਤੇ SSRF-ਬਲੌਕ ਕੀਤੀ ਪ੍ਰਮਾਣਿਕਤਾ ਲੌਗਿੰਗ ਨਾਲ ਵਿਸਤਾਰਿਆ ਗਿਆ ਹੈ। ਨਵੇਂ ਇਵੈਂਟ `src/lib/compliance/providerAudit.ts` ਦੁਆਰਾ ਜਾਰੀ ਕੀਤੇ ਜਾਂਦੇ ਹਨ।
