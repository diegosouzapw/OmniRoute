> (LMArena-ਸ਼ੈਲੀ) ELO ਸਕੋਰਾਂ** ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਰੈਂਕ ਕਰਦਾ ਹੈ। ਇਹ ਦੇਖਣ ਲਈ ਕਿ ਕਿਹੜੇ ਮੁਫ਼ਤ ਪ੍ਰਦਾਤਾ ਤੁਹਾਡੇ ਕੰਮ ਲਈ ਸਭ ਤੋਂ ਮਜ਼ਬੂਤ ਮਾਡਲ ਪ੍ਰਦਾਨ ਕਰਦੇ ਹਨ —
> ਸਮੁੱਚੇ ਤੌਰ 'ਤੇ, ਜਾਂ ਸ਼੍ਰੇਣੀ (ਕੋਡਿੰਗ, ਸਮੀਖਿਆ, ਦਸਤਾਵੇਜ਼ੀਕਰਨ, ਡੀਬੱਗਿੰਗ) ਅਨੁਸਾਰ ਫਿਲਟਰ ਕਰਕੇ — ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ **ਮੁਫ਼ਤ ਪ੍ਰਦਾਤਾ ਰੈਂਕਿੰਗਾਂ** ਪੰਨਾ ਖੋਲ੍ਹੋ।

## ਇਹ ਕੀ ਹੈ

OmniRoute 329 ਪ੍ਰਦਾਤਾਵਾਂ ਨੂੰ ਰਜਿਸਟਰ ਕਰਦਾ ਹੈ, ਜਿਨ੍ਹਾਂ ਵਿੱਚ **ਮੁਫ਼ਤ/ਬਿਨਾਂ-ਪ੍ਰਮਾਣੀਕਰਨ**
ਵਜੋਂ ਨਿਸ਼ਾਨਬੱਧ 155 ਕੈਟਾਲਾਗ ਐਂਟਰੀਆਂ ਸ਼ਾਮਲ ਹਨ
(ਬਿਨਾਂ-ਪ੍ਰਮਾਣੀਕਰਨ,
ਮੁਫ਼ਤ-ਟੀਅਰ OAuth, ਜਾਂ ਮੁਫ਼ਤ-ਟੀਅਰ API ਕੁੰਜੀ —
[ਮੁਫ਼ਤ ਟੀਅਰ ਗਾਈਡ](../getting-started/FREE-TIERS-GUIDE.md) ਅਤੇ ਪੂਰੀ
[ਮੁਫ਼ਤ ਟੀਅਰ ਡਾਇਰੈਕਟਰੀ](../reference/FREE_TIERS.md) ਵੇਖੋ)। ਪਰ ਇੱਕ ਸਮੱਸਿਆ ਹੈ: ਮੁਫ਼ਤ ਪ੍ਰਦਾਤਾਵਾਂ ਦੀ
ਮਾਡਲ ਗੁਣਵੱਤਾ ਵਿੱਚ ਬਹੁਤ ਵੱਡਾ ਅੰਤਰ ਹੁੰਦਾ ਹੈ। ਕਿਸੇ ਅਗਲੀ ਪੀੜ੍ਹੀ ਦੇ ਮਾਡਲ ਦੀ ਸੇਵਾ ਦੇਣ ਵਾਲਾ ਬਿਨਾਂ-ਪ੍ਰਮਾਣੀਕਰਨ ਪ੍ਰਦਾਤਾ,
ਛੋਟੇ ਪੁਰਾਣੇ ਮਾਡਲ ਦੀ ਸੇਵਾ ਦੇਣ ਵਾਲੇ ਪ੍ਰਦਾਤਾ ਨਾਲੋਂ ਕਿਤੇ ਵੱਧ ਲਾਭਦਾਇਕ ਹੁੰਦਾ ਹੈ।

**ਮੁਫ਼ਤ ਪ੍ਰਦਾਤਾ ਰੈਂਕਿੰਗਾਂ**, ਹਰ ਮੁਫ਼ਤ ਪ੍ਰਦਾਤਾ ਦੇ ਕੈਟਾਲਾਗ ਨੂੰ
**Arena AI ਲੀਡਰਬੋਰਡ** ਦੇ **ਭੀੜ-ਸਰੋਤ ਗੁਣਵੱਤਾ ਸਕੋਰਾਂ** ਨਾਲ ਜੋੜ ਕੇ, ਇਸ ਸਵਾਲ ਦਾ ਜਵਾਬ ਦਿੰਦੀਆਂ ਹਨ ਕਿ
"**ਕਿਹੜਾ ਮੁਫ਼ਤ ਪ੍ਰਦਾਤਾ ਮੈਨੂੰ ਸਭ ਤੋਂ ਵਧੀਆ ਮਾਡਲ ਦਿੰਦਾ ਹੈ?**"
(ਮਨੁੱਖੀ-ਤਰਜੀਹ ELO, ਉਹੀ ਵਿਚਾਰ ਜਿਸ 'ਤੇ LMArena
ਚੈਟਬੋਟ ਅਰੀਨਾ ਆਧਾਰਿਤ ਹੈ)। ਫਿਰ ਪ੍ਰਦਾਤਾਵਾਂ ਨੂੰ ਉਨ੍ਹਾਂ ਦੇ **ਸਭ ਤੋਂ ਵਧੀਆ ਮੁਫ਼ਤ ਮਾਡਲ** ਦੀ ਸਮਰੱਥਾ ਦੇ ਆਧਾਰ 'ਤੇ ਰੈਂਕ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।

ਰੈਂਕਿੰਗ ਦੀ ਗਣਨਾ ਤਿੰਨ ਅਸਲ ਸਰੋਤਾਂ ਤੋਂ ਕੀਤੀ ਜਾਂਦੀ ਹੈ:

1. ਮੁਫ਼ਤ-ਪ੍ਰਦਾਤਾ ਸੂਚੀਆਂ — `NOAUTH_PROVIDERS`, ਅਤੇ `hasFree` ਨਾਲ ਨਿਸ਼ਾਨਬੱਧ `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` ਐਂਟਰੀਆਂ
   (`src/shared/constants/providers.ts`)।
2. ਪ੍ਰਦਾਤਾ ਰਜਿਸਟਰੀ ਤੋਂ ਹਰ ਪ੍ਰਦਾਤਾ ਦਾ ਮਾਡਲ ਕੈਟਾਲਾਗ
   (`open-sse/config/providerRegistry.ts`)।
3. Arena ELO ਸਿੰਕ ਇੰਜਣ (`src/lib/arenaEloSync.ts`) ਵੱਲੋਂ `model_intelligence` DB ਟੇਬਲ ਵਿੱਚ ਸਟੋਰ ਕੀਤੇ
   ELO-ਆਧਾਰਿਤ ਕਾਰਜ-ਅਨੁਕੂਲਤਾ ਸਕੋਰ।

ਜੋੜਨ ਦਾ ਤਰਕ `src/lib/freeProviderRankings.ts` ਵਿੱਚ ਮੌਜੂਦ ਹੈ।

## ਪਹੁੰਚ ਕਿਵੇਂ ਕਰਨੀ ਹੈ

### ਡੈਸ਼ਬੋਰਡ ਪੰਨਾ

ਡੈਸ਼ਬੋਰਡ ਖੋਲ੍ਹੋ ਅਤੇ **ਲਾਗਤਾਂ → ਮੁਫ਼ਤ ਪ੍ਰਦਾਤਾ ਰੈਂਕਿੰਗਾਂ** 'ਤੇ ਜਾਓ, ਜਾਂ ਸਿੱਧਾ ਇੱਥੇ ਜਾਓ:

```
/dashboard/free-provider-rankings
```

ਇਹ ਪੰਨਾ (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) ਹੇਠਾਂ ਦਿੱਤੀਆਂ ਚੀਜ਼ਾਂ ਦਿਖਾਉਂਦਾ ਹੈ:

- ਸਭ ਤੋਂ ਉੱਚੀ ਰੈਂਕਿੰਗ ਵਾਲੇ ਮੁਫ਼ਤ ਪ੍ਰਦਾਤਾਵਾਂ ਦਾ **ਸਿਖਰਲੇ-3 ਦਾ ਮੰਚ** (🥇 🥈 🥉)।
- ਇਨ੍ਹਾਂ ਕਾਲਮਾਂ ਵਾਲੀ ਪੂਰੀ **ਰੈਂਕਿੰਗ ਸਾਰਣੀ**: **ਰੈਂਕ**, **ਪ੍ਰਦਾਤਾ**, **ਸਿਖਰਲਾ ਮਾਡਲ**,
  **ਸਕੋਰ**, **ਔਸਤ ਸਕੋਰ**, **ਮਾਡਲ**, **ਕਿਸਮ**।
- **ਸ਼੍ਰੇਣੀ ਫਿਲਟਰ ਬਟਨ**: _ਸਾਰੀਆਂ ਸ਼੍ਰੇਣੀਆਂ_, _ਮੂਲ_, _ਕੋਡਿੰਗ_, _ਸਮੀਖਿਆ_,
  _ਦਸਤਾਵੇਜ਼ੀਕਰਨ_, _ਡੀਬੱਗਿੰਗ_।

ਹਰ ਪ੍ਰਦਾਤਾ ਦਾ **ਕਿਸਮ** ਬੈਜ ਦੱਸਦਾ ਹੈ ਕਿ ਉਹ ਕਿਵੇਂ ਮੁਫ਼ਤ ਹੈ:

| ਬੈਜ      | ਅਰਥ                                           |
| -------- | --------------------------------------------- |
| `NOAUTH` | ਹਮੇਸ਼ਾ ਮੁਫ਼ਤ, ਕਿਸੇ ਪ੍ਰਮਾਣ-ਪੱਤਰ ਦੀ ਲੋੜ ਨਹੀਂ    |
| `OAUTH`  | ਮੁਫ਼ਤ ਟੀਅਰ (`hasFree`) ਵਾਲਾ OAuth ਪ੍ਰਦਾਤਾ     |
| `APIKEY` | ਮੁਫ਼ਤ ਟੀਅਰ (`hasFree`) ਵਾਲਾ API-ਕੁੰਜੀ ਪ੍ਰਦਾਤਾ |

ਸਕੋਰ ਕੱਚੇ ਅੰਕਾਂ ਦੀ ਬਜਾਏ ਮਨੁੱਖਾਂ ਲਈ ਪੜ੍ਹਨਯੋਗ ਲੇਬਲਾਂ (ਉਦਾਹਰਨ ਲਈ _ਸਰਵੋਤਮ_, _ਸ਼ਾਨਦਾਰ_, _ਬਹੁਤ ਵਧੀਆ_,
_ਵਧੀਆ_, _ਔਸਤ_) ਦੇ ਰੂਪ ਵਿੱਚ ਦਿਖਾਏ ਜਾਂਦੇ ਹਨ, ਕਿਉਂਕਿ ਅਧਾਰਭੂਤ ਮੁੱਲ ਇੱਕ ਸਾਪੇਖ
ਰੈਂਕਿੰਗ ਗੁਣਵੱਤਾ ਹੈ, ਪ੍ਰਤੀਸ਼ਤ ਨਹੀਂ।

### API ਐਂਡਪੌਇੰਟ

ਇਹ ਪੰਨਾ ਇੱਕ ਜਨਤਕ ਰੀਡ ਐਂਡਪੌਇੰਟ
(`src/app/api/free-provider-rankings/route.ts`) ਦੁਆਰਾ ਸਮਰਥਿਤ ਹੈ:

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

ਕੁਐਰੀ ਪੈਰਾਮੀਟਰ (Zod ਨਾਲ ਪ੍ਰਮਾਣਿਤ):

| ਪੈਰਾਮੀਟਰ   | ਕਿਸਮ   | ਮੂਲ ਮੁੱਲ   | ਨੋਟਸ                                                                                                     |
| ---------- | ------ | ---------- | -------------------------------------------------------------------------------------------------------- |
| `category` | string | (ਕੋਈ ਨਹੀਂ) | `default`, `coding`, `review`, `documentation`, `debugging` ਵਿੱਚੋਂ ਇੱਕ। ਸੰਯੁਕਤ ਰੈਂਕਿੰਗ ਲਈ ਇਸਨੂੰ ਛੱਡ ਦਿਓ। |
| `limit`    | number | `50`       | `1–100` ਦੀ ਰੇਂਜ ਤੱਕ ਸੀਮਿਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।                                                                 |

ਜਵਾਬ ਦੀ ਬਣਤਰ:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` ਮੂਲ Arena ELO ਮੁੱਲ ਹੈ; `score` ਸਧਾਰਨਕ੍ਰਿਤ ਕਾਰਜ-ਅਨੁਕੂਲਤਾ ਮੁੱਲ ਹੈ
(ਹੇਠਾਂ ਵੇਖੋ)। ਜਿਨ੍ਹਾਂ ਪ੍ਰਦਾਤਾਵਾਂ ਕੋਲ ਕੋਈ ਸਕੋਰ ਕੀਤਾ ਮਾਡਲ ਨਹੀਂ ਹੈ, ਉਨ੍ਹਾਂ ਨੂੰ ਜਵਾਬ ਵਿੱਚੋਂ ਹਟਾ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ।

## ਸਕੋਰ ਕਿਵੇਂ ਕੰਮ ਕਰਦੇ ਹਨ

### ਸਰੋਤ: Arena AI ਲੀਡਰਬੋਰਡ

Arena ELO ਸਿੰਕ ਇੰਜਣ (`src/lib/arenaEloSync.ts`) Arena AI ਲੀਡਰਬੋਰਡ API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) ਤੋਂ ਦੋ ਲੀਡਰਬੋਰਡ — `text`
ਅਤੇ `code` — ਪ੍ਰਾਪਤ ਕਰਦਾ ਹੈ। ਹਰ ਲੀਡਰਬੋਰਡ ਐਂਟਰੀ ਵਿੱਚ ਇੱਕ ਮਾਡਲ ਨਾਮ, ਵਿਕਰੇਤਾ, ELO `score`, ਭਰੋਸੇਯੋਗਤਾ ਅੰਤਰਾਲ ਅਤੇ ਵੋਟਾਂ ਦੀ ਗਿਣਤੀ ਹੁੰਦੀ ਹੈ।

ਲੀਡਰਬੋਰਡ ਸ਼੍ਰੇਣੀਆਂ ਨੂੰ OmniRoute ਟਾਸਕ ਸ਼੍ਰੇਣੀਆਂ ਨਾਲ ਇਸ ਤਰ੍ਹਾਂ ਮੈਪ ਕੀਤਾ ਜਾਂਦਾ ਹੈ:

| Arena ਲੀਡਰਬੋਰਡ | OmniRoute ਟਾਸਕ ਸ਼੍ਰੇਣੀਆਂ                          |
| -------------- | ------------------------------------------------- |
| `text`         | `default`, `review`, `documentation`, `debugging` |
| `code`         | `coding`                                          |

### ਨਾਰਮਲਾਈਜ਼ੇਸ਼ਨ (ਟਾਸਕ-ਫਿੱਟ ਸਕੋਰ)

ਕੱਚੇ ELO ਸਕੋਰਾਂ ਨੂੰ ਹਰੇਕ ਲੀਡਰਬੋਰਡ ਲਈ ਇੱਕ **`[0.4, 0.98]` ਵਿਚਲੇ ਟਾਸਕ-ਫਿੱਟ ਮੁੱਲ** ਵਿੱਚ ਨਾਰਮਲਾਈਜ਼ ਕੀਤਾ ਜਾਂਦਾ ਹੈ:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

ਸਕੋਰ ਕਦੇ ਵੀ `0` ਜਾਂ `1` ਤੱਕ ਨਹੀਂ ਪਹੁੰਚਦਾ, ਜਿਸ ਨਾਲ ਵਰਤੋਂਕਾਰ ਓਵਰਰਾਈਡਾਂ ਲਈ ਗੁੰਜਾਇਸ਼ ਬਚੀ ਰਹਿੰਦੀ ਹੈ। ਇਹ ਉਹੀ `score` ਫੀਲਡ ਹੈ ਜੋ ਤੁਸੀਂ API ਜਵਾਬ ਵਿੱਚ ਦੇਖਦੇ ਹੋ ਅਤੇ ਉਹੀ ਲੇਬਲ ਹੈ ਜੋ ਡੈਸ਼ਬੋਰਡ ਉੱਤੇ ਦਿਖਾਇਆ ਜਾਂਦਾ ਹੈ।

### ਭਰੋਸੇਯੋਗਤਾ

ਹਰ ਐਂਟਰੀ ਨੂੰ Arena ਵੋਟਾਂ ਦੀ ਗਿਣਤੀ ਦੇ ਆਧਾਰ ਉੱਤੇ ਭਰੋਸੇਯੋਗਤਾ ਪੱਧਰ ਮਿਲਦਾ ਹੈ:

| ਭਰੋਸੇਯੋਗਤਾ | ਵੋਟਾਂ   |
| ---------- | ------- |
| `high`     | ≥ 5,000 |
| `medium`   | ≥ 1,000 |
| `low`      | < 1,000 |

### ਸਟੋਰੇਜ ਅਤੇ ਤਾਜ਼ਗੀ

ਨਾਰਮਲਾਈਜ਼ ਕੀਤੀਆਂ ਐਂਟਰੀਆਂ ਨੂੰ `source = "arena_elo"` ਨਾਲ `model_intelligence` DB ਟੇਬਲ ਵਿੱਚ ਲਿਖਿਆ ਜਾਂਦਾ ਹੈ (`src/lib/db/modelIntelligence.ts`)। ਐਂਟਰੀਆਂ ਦੀ ਮਿਆਦ **7 ਦਿਨਾਂ ਬਾਅਦ ਖ਼ਤਮ ਹੋ ਜਾਂਦੀ ਹੈ**, ਇਸ ਲਈ ਸਿੰਕ ਕਰਨਾ ਬੰਦ ਕਰਨ ਵਾਲਾ ਪ੍ਰਦਾਤਾ ਪੁਰਾਣਾ ਡਾਟਾ ਪਰੋਸਣ ਦੀ ਬਜਾਏ ਆਖ਼ਰਕਾਰ ਸੂਚੀ ਵਿੱਚੋਂ ਹਟ ਜਾਂਦਾ ਹੈ।

ਸਿੰਕ **ਮੂਲ ਰੂਪ ਵਿੱਚ ਚਾਲੂ** ਹੁੰਦਾ ਹੈ:

- ਇਹ ਸਰਵਰ ਸ਼ੁਰੂ ਹੋਣ ਵੇਲੇ ਇੱਕ ਵਾਰ ਅਤੇ ਫਿਰ ਸਮੇਂ-ਸਮੇਂ ਉੱਤੇ ਟਾਈਮਰ ਰਾਹੀਂ ਚੱਲਦਾ ਹੈ
  (`src/lib/arenaEloSync.ts`, `src/instrumentation-node.ts` ਤੋਂ ਜੋੜਿਆ ਗਿਆ)।
- ਇਹ **ਨਾਨ-ਬਲਾਕਿੰਗ ਹੈ ਅਤੇ ਕਦੇ ਵੀ ਘਾਤਕ ਨਹੀਂ ਹੁੰਦਾ** — ਜੇ ਅੱਪਸਟ੍ਰੀਮ ਫੈਚ ਅਸਫਲ ਹੋ ਜਾਂਦਾ ਹੈ, ਤਾਂ OmniRoute ਚੱਲਦਾ ਰਹਿੰਦਾ ਹੈ ਅਤੇ ਰੈਂਕਿੰਗਾਂ ਸਿਰਫ਼ ਆਖ਼ਰੀ ਸਹੀ ਡਾਟਾ (ਜਾਂ ਇੱਕ ਖਾਲੀ ਸਥਿਤੀ) ਦਿਖਾਉਂਦੀਆਂ ਹਨ।

ਦੋ ਵਾਤਾਵਰਣ ਵੇਰੀਏਬਲ ਇਸ ਨੂੰ ਨਿਯੰਤਰਿਤ ਕਰਦੇ ਹਨ ([`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md) ਵਿੱਚ ਦਸਤਾਵੇਜ਼ਬੱਧ):

| ਵੇਰੀਏਬਲ                   | ਮੂਲ ਮੁੱਲ      | ਉਦੇਸ਼                                            |
| ------------------------- | ------------- | ------------------------------------------------ |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | ਆਊਟਬਾਊਂਡ ਸਿੰਕ ਤੋਂ ਬਾਹਰ ਰਹਿਣ ਲਈ `false` ਸੈੱਟ ਕਰੋ। |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | ਸਿੰਕ ਅੰਤਰਾਲ, ਸਕਿੰਟਾਂ ਵਿੱਚ।                       |

### ਮੈਨੁਅਲ ਸਿੰਕ / ਸਥਿਤੀ / ਸਾਫ਼ ਕਰਨਾ

ਓਪਰੇਟਰਾਂ ਲਈ, ਇੱਕ ਪ੍ਰਮਾਣਿਤ ਪ੍ਰਬੰਧਨ ਐਂਡਪੌਇੰਟ ਮੈਨੁਅਲ ਨਿਯੰਤਰਣ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ
(`src/app/api/intelligence/sync/route.ts` — ਪ੍ਰਬੰਧਨ ਪ੍ਰਮਾਣੀਕਰਨ ਲੋੜੀਂਦਾ ਹੈ):

```
GET    /api/intelligence/sync          # ਮੌਜੂਦਾ ਸਿੰਕ ਸਥਿਤੀ (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # ਮੈਨੁਅਲ ਸਿੰਕ ਸ਼ੁਰੂ ਕਰੋ; ਬਿਨਾਂ ਲਿਖੇ ਪੂਰਵਦਰਸ਼ਨ ਲਈ ਬਾਡੀ: { "dryRun": true }
DELETE /api/intelligence/sync          # ਸਾਰੀਆਂ ਸਿੰਕ ਕੀਤੀਆਂ arena_elo ਇੰਟੈਲੀਜੈਂਸ ਐਂਟਰੀਆਂ ਸਾਫ਼ ਕਰੋ
```

ਜੇ ਰੈਂਕਿੰਗਾਂ ਵਾਲਾ ਪੰਨਾ ਖਾਲੀ ਹੈ, ਤਾਂ ਮੈਨੁਅਲ `POST /api/intelligence/sync` (ਜਾਂ ਸਿਰਫ਼ ਸਰਵਰ ਨੂੰ ਮੁੜ ਚਾਲੂ ਕਰਨਾ) ਇਸ ਨੂੰ ਦੁਬਾਰਾ ਭਰ ਦਿੰਦਾ ਹੈ।

### ਮਾਡਲਾਂ ਨੂੰ ਲੀਡਰਬੋਰਡ ਨਾਲ ਮਿਲਾਉਣਾ

ਰਜਿਸਟਰੀ ਮਾਡਲ IDs ਅਤੇ Arena ਮਾਡਲ ਨਾਮ ਹਮੇਸ਼ਾ ਬਿਲਕੁਲ ਮੇਲ ਨਹੀਂ ਖਾਂਦੇ। ਰੈਂਕਿੰਗ ਲਚਕਦਾਰ ਮਿਲਾਨ ਦੀ ਵਰਤੋਂ ਕਰਦੀ ਹੈ (`src/lib/freeProviderRankings.ts` ਵਿੱਚ `findMatchingIntelligence`):

1. ਨਾਰਮਲਾਈਜ਼ ਕੀਤੀ ਮਾਡਲ ID ਨਾਲ ਬਿਲਕੁਲ ਸਹੀ ਮੇਲ।
2. ਅੰਤ ਵਿੱਚ ਲੱਗਿਆ ਵਰਜਨ ਸਫ਼ਿਕਸ ਹਟਾਉਣ ਤੋਂ ਬਾਅਦ ਮੇਲ (ਉਦਾਹਰਨ ਲਈ `kimi-k2.6` → `kimi-k2`)।
3. ਪ੍ਰੀਫਿਕਸ ਮੇਲ (ਲੀਡਰਬੋਰਡ ਮਾਡਲ ਨਾਮ ਰਜਿਸਟਰੀ ID ਦਾ ਪ੍ਰੀਫਿਕਸ ਹੋਵੇ)।

ਸਿੰਕ ਵਾਲੇ ਪਾਸੇ, ਜਾਣੇ-ਪਛਾਣੇ ਵਿਕਰੇਤਾ ਪ੍ਰੀਫਿਕਸ (`anthropic/`, `openai/`, `google/`, …) ਹਟਾਏ ਜਾਂਦੇ ਹਨ ਅਤੇ ਇੱਕ ਛੋਟਾ ਐਲਿਅਸ ਮੈਪ ਕੈਨੋਨਿਕਲ ਨਾਮਾਂ ਨੂੰ ਉਹਨਾਂ ਰੂਪਾਂ ਵਿੱਚ ਵਿਸਤਾਰਦਾ ਹੈ ਜੋ OmniRoute ਅੰਦਰੂਨੀ ਤੌਰ ਉੱਤੇ ਵਰਤਦਾ ਹੈ, ਤਾਂ ਜੋ ਮਾਡਲ ਕਿਸੇ ਵੀ ਨਾਮ ਹੇਠ ਲੱਭੇ ਜਾ ਸਕਣ।

### ਪ੍ਰਦਾਤਾ ਨੂੰ ਕਿਵੇਂ ਰੈਂਕ ਕੀਤਾ ਜਾਂਦਾ ਹੈ

ਹਰ ਮੁਫ਼ਤ ਪ੍ਰਦਾਤਾ ਲਈ, ਇੰਜਣ ਉਸਦੇ ਕੈਟਾਲੌਗ ਦੇ ਹਰ ਮਾਡਲ ਨੂੰ ਸਕੋਰ ਦਿੰਦਾ ਹੈ, ਫਿਰ:

- **ਸਿਖਰਲਾ ਮਾਡਲ** = ਪ੍ਰਦਾਤਾ ਦਾ ਸਭ ਤੋਂ ਵੱਧ ਸਕੋਰ ਵਾਲਾ ਮਾਡਲ।
- **ਔਸਤ ਸਕੋਰ** = ਉਸ ਪ੍ਰਦਾਤਾ ਦੇ ਸਾਰੇ ਸਕੋਰ ਕੀਤੇ ਮਾਡਲਾਂ ਦਾ ਔਸਤ ਸਕੋਰ।
- **ਮਾਡਲ** = ਪ੍ਰਦਾਤਾ ਦੇ ਕਿੰਨੇ ਮਾਡਲਾਂ ਕੋਲ Arena ਸਕੋਰ ਸੀ।

ਪ੍ਰਦਾਤਿਆਂ ਨੂੰ ਪਹਿਲਾਂ **ਸਿਖਰਲੇ-ਮਾਡਲ ਦੇ ਸਕੋਰ** ਅਤੇ ਫਿਰ ਔਸਤ ਸਕੋਰ ਅਨੁਸਾਰ ਕ੍ਰਮਬੱਧ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। ਇਹ ਉਸ ਪ੍ਰਦਾਤਾ ਨੂੰ ਇਨਾਮ ਦਿੰਦਾ ਹੈ ਜੋ ਘੱਟੋ-ਘੱਟ ਇੱਕ ਮਜ਼ਬੂਤ ਮੁਫ਼ਤ ਮਾਡਲ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ।

## ਮੁਫ਼ਤ ਪ੍ਰਦਾਤਾ ਚੁਣਨ ਲਈ ਇਸਦੀ ਵਰਤੋਂ

1. **ਸਹੀ ਸ਼੍ਰੇਣੀ ਚੁਣੋ।** ਏਜੰਟਿਕ/ਕੋਡ ਵਰਕਲੋਡਾਂ ਲਈ **Coding** ਫਿਲਟਰ ਵਰਤੋ, ਜਾਂ
   ਆਮ ਚੈਟ ਲਈ ਇਸਨੂੰ **All Categories** / **Default** 'ਤੇ ਹੀ ਰਹਿਣ ਦਿਓ। ਇੱਕੋ ਪ੍ਰਦਾਤਾ
   ਵੱਖ-ਵੱਖ ਸ਼੍ਰੇਣੀਆਂ ਵਿੱਚ ਵੱਖਰੀ ਰੈਂਕਿੰਗ ਪ੍ਰਾਪਤ ਕਰ ਸਕਦਾ ਹੈ, ਕਿਉਂਕਿ ਹਰ ਲੀਡਰਬੋਰਡ ਅਨੁਸਾਰ ਇਸਦਾ ਸਿਖਰਲਾ ਮਾਡਲ ਵੱਖਰਾ ਹੁੰਦਾ ਹੈ।
2. **ਇੱਕ-ਵਾਰੀ ਸੈੱਟਅੱਪਾਂ ਲਈ ਪੋਡੀਅਮ ਨੂੰ ਤਰਜੀਹ ਦਿਓ।** ਜੇ ਤੁਸੀਂ ਸਿਰਫ਼ ਇੱਕ ਜਾਂ ਦੋ ਮੁਫ਼ਤ
   ਪ੍ਰਦਾਤਾਵਾਂ ਨੂੰ ਕਨੈਕਟ ਕਰਨਾ ਚਾਹੁੰਦੇ ਹੋ, ਤਾਂ ਆਪਣੀ ਸ਼੍ਰੇਣੀ ਲਈ ਸਭ ਤੋਂ ਉੱਚੀ ਰੈਂਕਿੰਗ ਵਾਲਿਆਂ ਤੋਂ ਸ਼ੁਰੂ ਕਰੋ।
3. **Type ਬੈਜ ਦੀ ਜਾਂਚ ਕਰੋ।** `NOAUTH` ਪ੍ਰਦਾਤਾ ਸਭ ਤੋਂ ਤੇਜ਼ੀ ਨਾਲ ਕਨੈਕਟ ਹੁੰਦੇ ਹਨ (ਕੋਈ
   ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਨਹੀਂ)। `OAUTH` / `APIKEY` ਮੁਫ਼ਤ ਟੀਅਰਾਂ ਲਈ ਤੁਰੰਤ ਸਾਈਨ-ਅੱਪ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ, ਪਰ ਉਹ ਅਕਸਰ
   ਵਧੇਰੇ ਸਮਰੱਥ ਮਾਡਲ ਉਪਲਬਧ ਕਰਵਾਉਂਦੇ ਹਨ। ਕਨੈਕਸ਼ਨ ਦੇ ਕਦਮਾਂ ਲਈ [ਮੁਫ਼ਤ ਟੀਅਰ ਗਾਈਡ](../getting-started/FREE-TIERS-GUIDE.md) ਵੇਖੋ।
4. **ਕਈਆਂ ਨੂੰ ਕਨੈਕਟ ਕਰੋ ਅਤੇ Auto-Combo ਨੂੰ ਫ਼ੈਸਲਾ ਕਰਨ ਦਿਓ।** ਉਹੀ Arena ELO ਡਾਟਾ ਜੋ
   ਇਸ ਪੰਨੇ ਨੂੰ ਸੰਚਾਲਿਤ ਕਰਦਾ ਹੈ, Auto-Combo ਸਕੋਰਿੰਗ ਇੰਜਣ ਦੇ **ਟਾਸਕ-ਅਨੁਕੂਲਤਾ ਕਾਰਕ** ਨੂੰ ਵੀ ਡਾਟਾ ਦਿੰਦਾ ਹੈ
   (`open-sse/services/autoCombo/taskFitness.ts`, ਨਿਰਧਾਰਨ ਕ੍ਰਮ
   `user_override → arena_elo → models_dev_tier → static table`)। ਇਸ ਲਈ, ਸਿਖਰਲੇ ਮੁਫ਼ਤ ਪ੍ਰਦਾਤਾਵਾਂ ਨੂੰ ਕਨੈਕਟ ਕਰਨ ਤੋਂ ਬਾਅਦ,
   `model: "auto"` (ਉਦਾਹਰਨ ਲਈ `auto/coding`) ਨਾਲ ਰਾਊਟਿੰਗ ਹਰ ਬੇਨਤੀ ਲਈ
   ਉੱਚ-ਗੁਣਵੱਤਾ ਵਾਲੇ ਮੁਫ਼ਤ ਮਾਡਲਾਂ ਨੂੰ ਆਪਣੇ-ਆਪ ਤਰਜੀਹ ਦੇਵੇਗੀ। ਪੂਰੀ 16-ਕਾਰਕ ਸਕੋਰਿੰਗ ਲਈ
   [Auto-Combo](../routing/AUTO-COMBO.md) ਵੇਖੋ।
