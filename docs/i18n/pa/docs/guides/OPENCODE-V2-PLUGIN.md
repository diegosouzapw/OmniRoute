`@omniroute/opencode-plugin-v2` ਤੁਹਾਡੇ ਪੂਰੇ OmniRoute ਕੈਟਾਲਾਗ — ਮਾਡਲਾਂ, ਕੌਂਬੋਆਂ ਅਤੇ
ਆਟੋ-ਕੌਂਬੋਆਂ — ਨੂੰ ਡਿਸਪਲੇ ਨਾਮਾਂ, ਕੀਮਤਾਂ ਅਤੇ ਮੁਫ਼ਤ-ਟੀਅਰ
ਬਜਟਾਂ ਸਮੇਤ OpenCode v2 ਦੇ ਮਾਡਲ ਚੋਣਕਾਰ ਵਿੱਚ ਸ਼ਾਮਲ ਕਰਦਾ ਹੈ।

ਇਹ `@omniroute/opencode-plugin` ਤੋਂ ਇੱਕ ਵੱਖਰਾ ਪੈਕੇਜ ਹੈ ਕਿਉਂਕਿ OpenCode v1 ਅਤੇ v2
ਪਲੱਗਇਨਾਂ ਨੂੰ ਵੱਖ-ਵੱਖ ਕਾਂਟ੍ਰੈਕਟਾਂ ਰਾਹੀਂ ਲੋਡ ਕਰਦੇ ਹਨ। ਆਪਣੇ OpenCode ਦੇ ਮੁੱਖ ਵਰਜਨ ਨਾਲ ਮੇਲ ਖਾਂਦਾ ਪੈਕੇਜ ਚੁਣੋ; ਇਨ੍ਹਾਂ ਵਿਚਕਾਰ
ਕੁਝ ਵੀ ਸਾਂਝਾ ਨਹੀਂ ਹੈ, ਇਸ ਲਈ ਇੱਕ ਨੂੰ ਅੱਪਗ੍ਰੇਡ ਕਰਨ ਨਾਲ ਦੂਜੇ ਨੂੰ ਕਦੇ ਵੀ ਅੱਪਗ੍ਰੇਡ ਕਰਨ ਦੀ ਲੋੜ ਨਹੀਂ ਪੈਂਦੀ।

## ਲੋੜਾਂ

- OpenCode v2।
- ਪਹੁੰਚਯੋਗ OmniRoute ਗੇਟਵੇ (ਮੂਲ ਰੂਪ ਵਿੱਚ `http://localhost:20128`)।
- Node.js 22 ਜਾਂ 24।

## ਇੰਸਟਾਲੇਸ਼ਨ

ਪਲੱਗਇਨ ਨੂੰ `opencode.json` ਵਿੱਚ ਸ਼ਾਮਲ ਕਰੋ:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

ਇਸ ਤੋਂ ਬਾਅਦ ਮਾਡਲ `omniroute/<provider>/<model>` ਦੇ ਰੂਪ ਵਿੱਚ ਦਿਖਾਈ ਦਿੰਦੇ ਹਨ; `providerId` ਉਸ ਅਗੇਤਰ ਅਤੇ
ਉਸ ਇੰਟੀਗ੍ਰੇਸ਼ਨ ਦੀ id ਨਿਰਧਾਰਤ ਕਰਦਾ ਹੈ ਜਿਸ ਦੇ ਅਧੀਨ OpenCode ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਸਟੋਰ ਕਰਦਾ ਹੈ।

## ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ

ਪਲੱਗਇਨ ਹੇਠਾਂ ਦਿੱਤੀਆਂ ਤਿੰਨ ਥਾਵਾਂ 'ਤੇ, ਇਸੇ ਕ੍ਰਮ ਵਿੱਚ, ਗੇਟਵੇ ਕੁੰਜੀ ਲੱਭਦਾ ਹੈ:

1. **ਉਹ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਜੋ ਤੁਸੀਂ OpenCode ਵਿੱਚ ਕਨੈਕਟ ਕੀਤਾ ਹੈ।** ਪਲੱਗਇਨ ਇੱਕ ਇੰਟੀਗ੍ਰੇਸ਼ਨ ਰਜਿਸਟਰ ਕਰਦਾ ਹੈ, ਇਸ ਲਈ
   OpenCode ਦਾ ਆਪਣਾ ਪ੍ਰਮਾਣੀਕਰਨ ਪ੍ਰਵਾਹ ਕੁੰਜੀ ਨੂੰ ਸਟੋਰ ਕਰ ਸਕਦਾ ਹੈ। `opencode.json` ਵਿੱਚ ਕੁਝ ਵੀ ਨਹੀਂ ਜਾਂਦਾ — ਇਸ ਨੂੰ ਤਰਜੀਹ ਦਿਓ।
2. ਪ੍ਰਤੀ-ਪ੍ਰੋਜੈਕਟ ਓਵਰਰਾਈਡ ਲਈ ਪਲੱਗਇਨ ਵਿਕਲਪਾਂ ਵਿੱਚ `apiKey`। ਇਹ ਕੁੰਜੀ ਨੂੰ ਉਸ ਫ਼ਾਈਲ ਵਿੱਚ ਰੱਖਦਾ ਹੈ
   ਜਿਸ ਨੂੰ ਤੁਸੀਂ ਸ਼ਾਇਦ ਕਮਿਟ ਕਰ ਰਹੇ ਹੋਵੋ।
3. ਵਾਤਾਵਰਨ ਵਿੱਚ `OMNIROUTE_API_KEY`।

ਇਨ੍ਹਾਂ ਤਿੰਨਾਂ ਵਿੱਚੋਂ ਕੋਈ ਵੀ ਨਾ ਹੋਣ 'ਤੇ, ਕੈਟਾਲਾਗ ਖਾਲੀ ਰਹਿੰਦਾ ਹੈ ਅਤੇ ਪਲੱਗਇਨ ਤੁਹਾਨੂੰ ਇੱਕ ਚੁੱਪਚਾਪ ਖਾਲੀ ਚੋਣਕਾਰ ਨਾਲ
ਛੱਡਣ ਦੀ ਬਜਾਏ ਸਟਾਰਟਅੱਪ ਵੇਲੇ ਇੱਕ ਵਾਰ ਇਸ ਬਾਰੇ ਦੱਸਦਾ ਹੈ।

### ਪ੍ਰਬੰਧਨ ਟੋਕਨ ਇੱਕ ਵੱਖਰੀ ਕੁੰਜੀ ਹੈ

ਕੌਂਬੋਆਂ, ਪ੍ਰਦਾਤਾ ਦੀ ਸਿਹਤ ਅਤੇ ਸੰਵਰਧਨ (ਡਿਸਪਲੇ ਨਾਮ, ਕੀਮਤਾਂ, ਮੁਫ਼ਤ-ਟੀਅਰ ਬਜਟ) ਗੇਟਵੇ ਦੇ
`/api/*` ਐਂਡਪੌਇੰਟਾਂ ਤੋਂ ਆਉਂਦੇ ਹਨ, ਜਿਨ੍ਹਾਂ ਨੂੰ ਜ਼ਿਆਦਾਤਰ ਡਿਪਲੌਇਮੈਂਟ ਇਨਫ਼ਰੈਂਸ ਕੁੰਜੀ ਦੀ ਬਜਾਏ ਇੱਕ **ਪ੍ਰਬੰਧਨ** ਟੋਕਨ ਦੇ
ਪਿੱਛੇ ਰੱਖਦੇ ਹਨ:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<ਪ੍ਰਬੰਧਨ ਰੀਡ ਟੋਕਨ>"
}
```

ਜੇ ਸੈੱਟ ਨਾ ਕੀਤਾ ਜਾਵੇ, ਤਾਂ `managementReadToken`, `apiKey` 'ਤੇ ਵਾਪਸ ਆ ਜਾਂਦਾ ਹੈ। ਜਦੋਂ ਕੋਈ ਗੇਟਵੇ ਉਸ ਫ਼ਾਲਬੈਕ ਨੂੰ
ਅਸਵੀਕਾਰ ਕਰਦਾ ਹੈ, ਤਾਂ ਵੀ ਕੈਟਾਲਾਗ ਪ੍ਰਕਾਸ਼ਿਤ ਹੁੰਦਾ ਹੈ, ਪਰ ਡਿਸਪਲੇ ਨਾਮਾਂ ਦੀ ਬਜਾਏ ਕੱਚੀਆਂ ਮਾਡਲ idਆਂ ਨਾਲ, ਬਿਨਾਂ ਕੈਨੋਨਿਕਲ
ਉਪਨਾਮ ਡੀਡੂਪ, ਬਿਨਾਂ ਕੀਮਤਾਂ ਅਤੇ ਬਿਨਾਂ ਕੌਂਬੋਆਂ ਦੇ। ਅਜਿਹਾ ਹੋਣ 'ਤੇ ਪਲੱਗਇਨ ਹਰ ਐਂਡਪੌਇੰਟ ਲਈ ਇੱਕ ਵਾਰ ਚੇਤਾਵਨੀ ਦਿੰਦਾ ਹੈ,
ਜਿਸ ਵਿੱਚ ਐਂਡਪੌਇੰਟ ਅਤੇ ਗੁਆਚੀ ਜਾਣਕਾਰੀ ਦਾ ਨਾਮ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ — ਇਸ ਲਈ ਘਟੀਆ ਹੋਇਆ ਚੋਣਕਾਰ ਕਦੇ ਵੀ ਰਹੱਸ ਨਹੀਂ ਰਹਿੰਦਾ।

| `geminiSanitization`             | `true`                                         | ਟੂਲ ਸਕੀਮਾਵਾਂ ਵਿੱਚੋਂ ਉਹ JSON-Schema ਕੀਵਰਡ ਹਟਾਓ ਜਿਨ੍ਹਾਂ ਨੂੰ Gemini ਰੱਦ ਕਰਦਾ ਹੈ (`$ref` ਟੂਲ ਬਿਨਾਂ ਤਬਦੀਲੀ ਅੱਗੇ ਭੇਜੇ ਜਾਂਦੇ ਹਨ) |
| `apiFormat.allowAnthropic`       | `false`                                        | ਅਨੁਮਤੀ-ਸੂਚੀਬੱਧ ids ਨੂੰ Anthropic API ਬਲਾਕ ਰਾਹੀਂ ਰੂਟ ਕਰੋ                                                                   |
| `apiFormat.anthropicModels`      | `[]`                                           | Anthropic ਵੱਲ ਰੂਟ ਕੀਤੇ ਪੂਰੇ ਮਾਡਲ ids                                                                                      |
| `logLevel` / `startupDebug`      | `warn` / `false`                               | ਲੌਗਰ ਵੇਰਵਾ-ਪੱਧਰ                                                                                                           |

ਵਰਤੋਂ ਮੈਮੋਰੀ ਡਿਫਾਲਟ ਤੌਰ 'ਤੇ ਚਾਲੂ ਹੁੰਦੀ ਹੈ। ਮੈਨੇਜਮੈਂਟ ਟੋਕਨ ਤੋਂ ਬਿਨਾਂ ਇਹ ਨਿਸ਼ਕ੍ਰਿਆ ਰਹਿੰਦੀ ਹੈ
(ਸਟਾਰਟਅੱਪ ਸੂਚਨਾ ਲੌਗ ਕੀਤੀ ਜਾਂਦੀ ਹੈ) ਅਤੇ ਕੁਝ ਵੀ ਮੁੜ-ਬਹਾਲ ਨਹੀਂ ਹੁੰਦਾ।

## ਕੈਟਾਲਾਗ ਕਿਵੇਂ ਤਾਜ਼ਾ ਰਹਿੰਦਾ ਹੈ

ਕੈਟਾਲਾਗ ਨੂੰ ਲੋੜ ਪੈਣ 'ਤੇ ਪ੍ਰਾਪਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ ਅਤੇ `modelCacheTtlMs` ਲਈ ਕੈਸ਼ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਅਤੇ ਡਿਸਕ ਸਨੈਪਸ਼ਾਟ ਗੇਟਵੇ ਤੱਕ ਪਹੁੰਚ ਨਾ ਹੋਣ 'ਤੇ ਆਖਰੀ ਜਾਣਿਆ ਕੈਟਾਲਾਗ ਉਪਲਬਧ ਰੱਖਦਾ ਹੈ — ਆਊਟੇਜ ਕਾਰਨ ਤੁਹਾਨੂੰ ਤਾਜ਼ਗੀ ਤੋਂ ਇਲਾਵਾ ਹੋਰ ਕੁਝ ਨਹੀਂ ਗੁਆਉਣਾ ਪੈਂਦਾ। ਮਾਡਲ ਅਤੇ ਕੰਬੋ ਆਉਂਦੇ ਹੀ ਪ੍ਰਕਾਸ਼ਿਤ ਕਰ ਦਿੱਤੇ ਜਾਂਦੇ ਹਨ; ਆਟੋ-ਕੰਬੋ, ਪ੍ਰੋਵਾਈਡਰ ਸੂਚੀ ਅਤੇ ਸੰਵਰਧਨ ਓਵਰਲੇਅ ਉਪਲਬਧ ਹੁੰਦੇ ਹੀ ਸ਼ਾਮਲ ਹੋ ਜਾਂਦੇ ਹਨ, ਇਸ ਲਈ ਇੱਕ ਹੌਲਾ ਐਂਡਪੌਇੰਟ ਪੂਰੇ ਚੋਣਕਾਰ ਨੂੰ ਰੋਕ ਨਹੀਂ ਸਕਦਾ।

ਨਾਂਵਾਂ ਵਿੱਚ ਗੇਟਵੇ ਨੂੰ ਪਤਾ ਜਾਣਕਾਰੀ ਸ਼ਾਮਲ ਹੁੰਦੀ ਹੈ: ਉਹ ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰੋਵਾਈਡਰ ਜਿਸ ਵੱਲ ਮਾਡਲ ਰੂਟ ਹੁੰਦਾ ਹੈ, ਇੱਕ `[Free]` ਚਿੰਨ੍ਹ ਅਤੇ ਉਸ ਨਾਲ ਮਿਲਣ ਵਾਲਾ ਬਜਟ — ਇਸ ਲਈ ਇੱਕੋ ਮਾਡਲ ਵੇਚਣ ਵਾਲੇ ਦੋ ਕਨੈਕਸ਼ਨ ਵੱਖਰੇ ਪਛਾਣੇ ਜਾ ਸਕਦੇ ਹਨ। `"providerTag": false` ਨਾਲ ਪ੍ਰੀਫਿਕਸ ਬੰਦ ਕਰੋ।

ਕੋਈ ਮੈਨੂਅਲ ਰਿਫ੍ਰੈਸ਼ ਕਮਾਂਡ ਨਹੀਂ ਹੈ: OpenCode v2 ਕਮਾਂਡਾਂ ਪ੍ਰੌਂਪਟ ਟੈਂਪਲੇਟ ਹਨ, ਕਾਲਬੈਕ ਨਹੀਂ, ਇਸ ਲਈ ਕੋਈ ਪਲੱਗਇਨ ਅਜਿਹੀ ਕਮਾਂਡ ਉਪਲਬਧ ਨਹੀਂ ਕਰਵਾ ਸਕਦੀ। ਰਿਫ੍ਰੈਸ਼ TTL ਦੀ ਪਾਲਣਾ ਕਰਦੇ ਹਨ; ਹੋਸਟ ਨੂੰ ਸਿਰਫ਼ ਉਦੋਂ ਹੀ ਮੁੜ ਲੋਡ ਕਰਨ ਲਈ ਕਿਹਾ ਜਾਂਦਾ ਹੈ ਜਦੋਂ ਕੈਟਾਲਾਗ ਜਾਂ ਓਵਰਲੇਅ ਵਾਸਤਵ ਵਿੱਚ ਬਦਲਿਆ ਹੋਵੇ, ਹਰ ਰਿਫ੍ਰੈਸ਼ 'ਤੇ ਨਹੀਂ।

## Gemini ਉੱਤੇ ਟੂਲ ਕਾਲਿੰਗ

Gemini ਉਸ ਪੂਰੀ ਬੇਨਤੀ ਨੂੰ ਅਸਵੀਕਾਰ ਕਰ ਦਿੰਦਾ ਹੈ ਜਿਸ ਦੀਆਂ ਟੂਲ ਘੋਸ਼ਣਾਵਾਂ ਵਿੱਚ `$schema` ਜਾਂ `additionalProperties` ਸ਼ਾਮਲ ਹੋਣ, ਅਤੇ ਜਵਾਬ ਵਿੱਚ `400 INVALID_ARGUMENT` ਦਿੰਦਾ ਹੈ। ਪਲੱਗਇਨ ਇਸ ਪ੍ਰੋਵਾਈਡਰ ਦੇ Gemini ਮਾਡਲ ਵੱਲ ਜਾਣ ਵਾਲੀਆਂ ਟੂਲ ਸਕੀਮਾਂ ਵਿੱਚੋਂ ਉਹ ਕੀਵਰਡ ਹਟਾ ਦਿੰਦੀ ਹੈ ਅਤੇ ਹਰ ਹੋਰ ਬੇਨਤੀ ਨੂੰ ਬਿਨਾਂ ਬਦਲਾਅ ਛੱਡਦੀ ਹੈ। `$ref` ਵਾਲੇ ਟੂਲ ਨੂੰ ਕੀਵਰਡ ਹਟਾਏ ਬਿਨਾਂ ਅੱਗੇ ਭੇਜਿਆ ਜਾਂਦਾ ਹੈ, ਕਿਉਂਕਿ ਰੈਫਰੈਂਸ ਹਟਾਉਣ ਨਾਲ ਸਕੀਮਾ ਦਾ ਦਾਇਰਾ "ਕੁਝ ਵੀ ਸਵੀਕਾਰ ਕਰੋ" ਤੱਕ ਵਧ ਜਾਵੇਗਾ।
ਇਸਨੂੰ ਬੰਦ ਕਰਨ ਲਈ `"geminiSanitization": false` ਸੈੱਟ ਕਰੋ।
