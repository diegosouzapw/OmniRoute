> **ਸੱਚਾਈ ਦਾ ਸਰੋਤ:** `electron/` ਵਰਕਸਪੇਸ
> **ਆਖਰੀ ਵਾਰ ਅੱਪਡੇਟ ਕੀਤਾ:** 2026-06-28 — v3.8.40

OmniRoute ਇੱਕ ਕ੍ਰਾਸ-ਪਲੇਟਫਾਰਮ ਡੈਸਕਟਾਪ ਐਪ (Windows / macOS / Linux) ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ, ਜੋ
**Electron 41** + **electron-builder 26.10** ਉੱਤੇ ਬਣੀ ਹੈ। ਡੈਸਕਟਾਪ ਐਪ Next.js
ਸਟੈਂਡਅਲੋਨ ਸਰਵਰ ਨੂੰ ਇੱਕ ਚਾਈਲਡ ਪ੍ਰਕਿਰਿਆ ਵਜੋਂ ਚਲਾਉਂਦੀ ਹੈ, ਇੱਕ `BrowserWindow` ਨੂੰ ਉਸ ਵੱਲ ਨਿਰਦੇਸ਼ਿਤ ਕਰਦੀ ਹੈ, ਅਤੇ
ਇੱਕ ਸਿਸਟਮ ਟ੍ਰੇ, ਆਟੋ-ਅੱਪਡੇਟਰ, IPC ਬ੍ਰਿਜ ਅਤੇ ਜ਼ੀਰੋ-ਕੌਂਫਿਗ ਸੀਕ੍ਰੇਟ ਬੂਟਸਟਰੈਪ ਜੋੜਦੀ ਹੈ।

## ਆਰਕੀਟੈਕਚਰ

```
┌──────────────────────────────────────────────┐
│ Electron ਮੁੱਖ ਪ੍ਰਕਿਰਿਆ (electron/main.js)    │
│ ├─ ਸਿੰਗਲ-ਇੰਸਟੈਂਸ ਲੌਕ                        │
│ ├─ ਚਾਈਲਡ ਪ੍ਰਕਿਰਿਆ: Next.js ਸਟੈਂਡਅਲੋਨ ਸਰਵਰ   │
│ │   (Electron ਦੇ Node ਰਨਟਾਈਮ ਨਾਲ ਚਲਾਇਆ ਗਿਆ) │
│ ├─ BrowserWindow → http://localhost:PORT     │
│ ├─ ਸਿਸਟਮ ਟ੍ਰੇ + ਸੰਦਰਭ ਮੀਨੂ                  │
│ ├─ electron-updater ਰਾਹੀਂ ਆਟੋ-ਅੱਪਡੇਟ        │
│ ├─ ਸਮੱਗਰੀ ਸੁਰੱਖਿਆ ਨੀਤੀ (ਸੈਸ਼ਨ ਹੈਡਰ)         │
│ └─ ਸੀਕ੍ਰੇਟ ਬੂਟਸਟਰੈਪ (JWT / API_KEY_SECRET)   │
└──────────────────────────────────────────────┘
            ↕ IPC ਬ੍ਰਿਜ (electron/preload.js)
┌──────────────────────────────────────────────┐
│ ਰੈਂਡਰਰ (Next.js ਡੈਸ਼ਬੋਰਡ)                    │
│   window.electronAPI.* (contextIsolation)     │
└──────────────────────────────────────────────┘
```

## ਸਕ੍ਰਿਪਟਾਂ (ਰੂਟ `package.json`)

| ਸਕ੍ਰਿਪਟ                           | ਉਦੇਸ਼                                                                                        |
| --------------------------------- | -------------------------------------------------------------------------------------------- |
| `npm run electron:dev`            | `npm run dev` ਸ਼ੁਰੂ ਕਰਦੀ ਹੈ + `localhost:20128` ਦੀ ਉਡੀਕ ਕਰਦੀ ਹੈ + Electron ਲਾਂਚ ਕਰਦੀ ਹੈ      |
| `npm run electron:build`          | Next.js ਬਿਲਡ ਕਰਦੀ ਹੈ, ਫਿਰ ਮੌਜੂਦਾ OS ਲਈ `electron-builder` ਚਲਾਉਂਦੀ ਹੈ                         |
| `npm run electron:build:win`      | Windows NSIS ਇੰਸਟਾਲਰ + ਪੋਰਟੇਬਲ (x64) ਬਿਲਡ ਕਰਦੀ ਹੈ                                            |
| `npm run electron:build:mac`      | macOS DMG (Intel + Apple Silicon) ਬਿਲਡ ਕਰਦੀ ਹੈ                                               |
| `npm run electron:build:linux`    | Linux AppImage + DEB (x64 + arm64) ਬਿਲਡ ਕਰਦੀ ਹੈ                                              |
| `npm run electron:smoke:packaged` | ਪੈਕੇਜ ਕੀਤੀ ਬਾਈਨਰੀ ਲਾਂਚ ਕਰਦੀ ਹੈ ਅਤੇ HTTP 200 ਲਈ `/login` ਦੀ ਜਾਂਚ ਕਰਦੀ ਹੈ, ਫਿਰ ਬੰਦ ਹੋ ਜਾਂਦੀ ਹੈ |

`electron/` ਵਰਕਸਪੇਸ ਇਹ ਵੀ ਉਪਲਬਧ ਕਰਵਾਉਂਦੀ ਹੈ:

- `npm run prepare:bundle` — `scripts/build/prepare-electron-standalone.mjs` ਚਲਾਉਂਦੀ ਹੈ
- `npm run build:mac-x64` / `build:mac-arm64` — ਸਿੰਗਲ-ਆਰਕੀਟੈਕਚਰ macOS ਬਿਲਡ
- `npm run pack` — ਸਥਾਨਕ ਟੈਸਟਿੰਗ ਲਈ ਸਿਰਫ਼ ਡਾਇਰੈਕਟਰੀ ਬਿਲਡ (ਕੋਈ ਇੰਸਟਾਲਰ ਨਹੀਂ)

    └── smoke-electron-packaged.mjs       # ਬਿਲਡ ਤੋਂ ਬਾਅਦ ਦਾ ਸਮੋਕ ਟੈਸਟ

ਰੈਂਡਰਰ-ਪਾਸੇ ਦੀਆਂ ਟਾਈਪਿੰਗਾਂ `electron/types.d.ts` ਵਿੱਚ ਮੌਜੂਦ ਹਨ।

## IPC ਬ੍ਰਿਜ (`preload.js`)

ਪ੍ਰੀਲੋਡ `contextIsolation: true` ਅਤੇ `nodeIntegration: false` ਨਾਲ `contextBridge`
ਦੀ ਵਰਤੋਂ ਕਰਕੇ `window.electronAPI` ਉੱਤੇ ਇੱਕ ਮਨਜ਼ੂਰਸ਼ੁਦਾ API ਉਪਲਬਧ ਕਰਵਾਉਂਦਾ ਹੈ।

```javascript
const VALID_CHANNELS = {
  invoke: [
    "get-app-info",
    "open-external",
    "get-data-dir",
    "restart-server",
    "check-for-updates",
    "download-update",
    "install-update",
    "get-app-version",
  ],
  send: ["window-minimize", "window-maximize", "window-close"],
  receive: ["server-status", "port-changed", "update-status"],
};
```

ਉਪਲਬਧ ਕਰਵਾਏ ਗਏ ਢੰਗ:

| ਰੈਂਡਰਰ ਕਾਲ                                                        | ਕਿਸਮ                            |
| ----------------------------------------------------------------- | ------------------------------- |
| `getAppInfo()` → `{ name, version, platform, isDev, port }`       | invoke                          |
| `openExternal(url)`                                               | invoke                          |
| `getDataDir()`                                                    | invoke                          |
| `restartServer()`                                                 | invoke                          |
| `getAppVersion()`                                                 | invoke                          |
| `checkForUpdates()` / `downloadUpdate()` / `installUpdate()`      | invoke                          |
| `minimizeWindow()` / `maximizeWindow()` / `closeWindow()`         | send                            |
| `onServerStatus(cb)` / `onPortChanged(cb)` / `onUpdateStatus(cb)` | receive (ਡਿਸਪੋਜ਼ਰ ਵਾਪਸ ਕਰਦਾ ਹੈ) |

ਰਿਸੀਵ ਹੈਲਪਰ `removeAllListeners` ਉੱਤੇ ਨਿਰਭਰ ਰਹਿਣ ਦੀ ਬਜਾਏ ਇੱਕ **ਡਿਸਪੋਜ਼ਰ ਫੰਕਸ਼ਨ**
ਵਾਪਸ ਕਰਦੇ ਹਨ — ਇਸ ਨਾਲ React ਕੰਪੋਨੈਂਟਾਂ ਦੇ ਮੁੜ ਮਾਊਂਟ ਹੋਣ ਵੇਲੇ ਲਿਸਨਰ ਇਕੱਠੇ ਨਹੀਂ ਹੁੰਦੇ।

## ਸਰਵਰ ਜੀਵਨ-ਚੱਕਰ

ਸਿਸਟਮ Node ਨਾਲ ਨੇਟਿਵ-ਮੋਡੀਊਲ ABI ਅਸੰਗਤਤਾ ਤੋਂ ਬਚਣ ਲਈ `main.js`, Electron Node
ਰਨਟਾਈਮ ਨਾਲ Next.js ਸਟੈਂਡਅਲੋਨ ਬੰਡਲ ਨੂੰ ਸਿੱਧਾ ਸ਼ੁਰੂ ਕਰਦਾ ਹੈ:

```js
spawn(process.execPath, [serverScript], {
  cwd: NEXT_SERVER_PATH,
  env: {
    ...serverEnv,
    PORT,
    NODE_ENV: "production",
    ELECTRON_RUN_AS_NODE: "1",
    NODE_PATH,
  },
  stdio: "pipe",
});
```

ਮੁੱਖ ਬਿੰਦੂ:

- ਵਿੰਡੋ ਦਿਖਾਉਣ ਤੋਂ ਪਹਿਲਾਂ `waitForServer()` ਵੱਧ ਤੋਂ ਵੱਧ 30 s ਤੱਕ URL ਨੂੰ ਪੋਲ ਕਰਦਾ ਹੈ (ਕੋਲਡ ਸਟਾਰਟ ਉੱਤੇ ਕੋਈ ਖਾਲੀ ਸਕ੍ਰੀਨ ਨਹੀਂ)।
- `stdio: "pipe"` stdout/stderr ਨੂੰ ਕੈਪਚਰ ਕਰਦਾ ਹੈ; ਤਿਆਰੀ ਦਰਸਾਉਣ ਵਾਲੇ ਵਾਕਾਂਸ਼ (`Ready` / `listening`) IPC ਰਾਹੀਂ `server-status: running` ਉਤਸਰਜਿਤ ਕਰਦੇ ਹਨ।
- `before-quit` ਸੁਚਾਰੂ SIGTERM (WAL ਚੈੱਕਪੁਆਇੰਟ) ਲਈ ਵੱਧ ਤੋਂ ਵੱਧ 5 s ਉਡੀਕ ਕਰਦਾ ਹੈ, ਫਿਰ SIGKILL ਭੇਜਦਾ ਹੈ।
- ਟਰੇ ਵਿੱਚ ਪੋਰਟ ਸਵਿੱਚਰ (`20128`, `3000`, `8080`) ਸਰਵਰ ਨੂੰ ਰੋਕ ਕੇ ਮੁੜ ਚਾਲੂ ਕਰਦਾ ਹੈ ਅਤੇ ਫਿਰ BrowserWindow ਨੂੰ ਰੀਲੋਡ ਕਰਦਾ ਹੈ।

## ਜ਼ੀਰੋ-ਕਾਨਫਿਗ ਸੀਕ੍ਰੇਟ ਬੂਟਸਟਰੈਪ

ਪਹਿਲੀ ਵਾਰ ਲਾਂਚ ਹੋਣ 'ਤੇ, ਮੁੱਖ ਪ੍ਰੋਸੈਸ ਗੁੰਮ ਸੀਕ੍ਰੇਟ ਆਪਣੇ-ਆਪ ਬਣਾਉਂਦਾ ਅਤੇ ਸਥਾਈ ਤੌਰ 'ਤੇ ਸੰਭਾਲਦਾ ਹੈ:

| ਸੀਕ੍ਰੇਟ                  | ਸਰੋਤ                                                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------------------ |
| `JWT_SECRET`             | `crypto.randomBytes(64).toString("hex")`                                                                     |
| `STORAGE_ENCRYPTION_KEY` | `crypto.randomBytes(32).toString("hex")` (ਜੇ ਇਨਕ੍ਰਿਪਟ ਕੀਤੇ ਕ੍ਰੈਡੈਂਸ਼ਲ ਪਹਿਲਾਂ ਹੀ ਮੌਜੂਦ ਹੋਣ ਤਾਂ ਇਨਕਾਰ ਕਰਦਾ ਹੈ) |
| `API_KEY_SECRET`         | `crypto.randomBytes(32).toString("hex")`                                                                     |

`<DATA_DIR>/server.env` ਵਿੱਚ ਸਥਾਈ ਤੌਰ 'ਤੇ ਸੰਭਾਲਿਆ ਜਾਂਦਾ ਹੈ। `DATA_DIR` ਦਾ ਹੱਲ ਇਸ ਤਰ੍ਹਾਂ ਹੁੰਦਾ ਹੈ:

- Windows: `%APPDATA%\omniroute`
- Linux: `$XDG_CONFIG_HOME/omniroute` ਜਾਂ `~/.omniroute`
- macOS: `~/.omniroute`

## ਵਿੰਡੋ ਅਤੇ ਟ੍ਰੇ

- `BrowserWindow`: 1400×900 (ਘੱਟੋ-ਘੱਟ 1024×700), `backgroundColor: "#0a0a0a"`।
- macOS: `titleBarStyle: "hiddenInset"`, ਟ੍ਰੈਫਿਕ-ਲਾਈਟ `{ x: 16, y: 16 }` 'ਤੇ।
- Windows/Linux: ਮੂਲ ਟਾਈਟਲ ਬਾਰ।
- ਬੰਦ ਕਰਨ ਵਾਲਾ ਬਟਨ ਐਪ ਨੂੰ ਟ੍ਰੇ ਵਿੱਚ ਮਿਨੀਮਾਈਜ਼ ਕਰਦਾ ਹੈ; ਟ੍ਰੇ ਮੀਨੂ ਵਿੱਚ **OmniRoute ਖੋਲ੍ਹੋ**, **ਡੈਸ਼ਬੋਰਡ ਖੋਲ੍ਹੋ** (ਬਾਹਰੀ ਬ੍ਰਾਊਜ਼ਰ), **ਸਰਵਰ ਪੋਰਟ** ਸਬਮੀਨੂ, **ਅੱਪਡੇਟਾਂ ਦੀ ਜਾਂਚ ਕਰੋ**, **ਬਾਹਰ ਨਿਕਲੋ** ਸ਼ਾਮਲ ਹਨ।

## ਸਮੱਗਰੀ ਸੁਰੱਖਿਆ ਨੀਤੀ

`session.defaultSession.webRequest.onHeadersReceived` ਰਾਹੀਂ ਸੈੱਟ ਕੀਤੀ ਜਾਂਦੀ ਹੈ। ਧਿਆਨਯੋਗ ਡਾਇਰੈਕਟਿਵ:

- `frame-ancestors 'none'`, `object-src 'none'`, `child-src 'none'`
- `connect-src 'self' http://localhost:* http://127.0.0.1:* ws://localhost:* ws://127.0.0.1:* https://*.omniroute.online https://*.omniroute.dev`
- ਡਿਵੈਲਪਮੈਂਟ ਮੋਡ ਸਿਰਫ਼ `script-src` ਵਿੱਚ `'unsafe-eval'` ਜੋੜਦਾ ਹੈ

## ਆਟੋ-ਅੱਪਡੇਟ

GitHub ਪ੍ਰੋਵਾਈਡਰ (`diegosouzapw/OmniRoute`) ਨਾਲ `electron-updater` ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ।

- `autoDownload = false`, `autoInstallOnAppQuit = true`
- ਇਵੈਂਟ `update-status` IPC ਰਾਹੀਂ ਰੈਂਡਰਰ ਨੂੰ ਅੱਗੇ ਭੇਜੇ ਜਾਂਦੇ ਹਨ:
  `checking`, `available`, `not-available`, `downloading` (`percent` ਸਮੇਤ), `downloaded`, `error`
- `installUpdate()` ਸਰਵਰ ਨੂੰ ਬੰਦ ਕਰਦਾ ਹੈ ਅਤੇ ਫਿਰ `autoUpdater.quitAndInstall()` ਨੂੰ ਕਾਲ ਕਰਦਾ ਹੈ
- ਡਿਵੈਲਪਮੈਂਟ ਮੋਡ (`!app.isPackaged`) ਵਿੱਚ ਛੱਡ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ

## ਬਿਲਡ ਪਾਈਪਲਾਈਨ

1. `npm run build` → `.next/standalone` ਵਿੱਚ Next.js ਸਟੈਂਡਅਲੋਨ।
2. `prepare-electron-standalone.mjs` → `.next/electron-standalone` ਵਿੱਚ ਮੁੜ ਸਟੇਜ ਕਰਦਾ ਹੈ ਅਤੇ `server.js` + `required-server-files.json` ਅੰਦਰਲੇ ਐਬਸੋਲਿਊਟ ਪਾਥਾਂ ਨੂੰ ਮੁੜ ਲਿਖਦਾ ਹੈ, ਤਾਂ ਜੋ ਬੰਡਲ ਨੂੰ ਦੂਜੀ ਥਾਂ ਲਿਜਾਇਆ ਜਾ ਸਕੇ।
3. `electron-builder`, `main.js`, `preload.js`, `node_modules`, ਅਤੇ `extraResources: { ../.next/electron-standalone → app }` ਨੂੰ ਪੈਕੇਜ ਕਰਦਾ ਹੈ।

### ਬਿਲਡ ਟਾਰਗੇਟ

| OS      | ਟਾਰਗੇਟ                                              |
| ------- | --------------------------------------------------- |
| Windows | NSIS ਇੰਸਟਾਲਰ + ਪੋਰਟੇਬਲ (x64)                        |
| macOS   | DMG (Intel + arm64, ਖਿੱਚ ਕੇ Applications ਵਿੱਚ ਛੱਡੋ) |
| Linux   | AppImage + DEB (x64 + arm64)                        |

NSIS ਸੈਟਿੰਗਾਂ: `oneClick: false`, ਵਰਤੋਂਕਾਰ ਨੂੰ ਇੰਸਟਾਲ ਡਾਇਰੈਕਟਰੀ ਚੁਣਨ ਦਿੰਦੀਆਂ ਹਨ ਅਤੇ Desktop ਅਤੇ Start-Menu ਸ਼ਾਰਟਕੱਟ ਬਣਾਉਂਦੀਆਂ ਹਨ।

## ਪੈਕੇਜ ਕੀਤੇ ਬਿਲਡ ਦੀ ਸਮੋਕ ਟੈਸਟਿੰਗ

```bash
npm run electron:smoke:packaged
```

`scripts/dev/smoke-electron-packaged.mjs`:

- ਮੌਜੂਦਾ ਪਲੇਟਫਾਰਮ ਲਈ `electron/dist-electron/` ਵਿੱਚ ਪੈਕੇਜ ਕੀਤੀ ਬਾਈਨਰੀ ਨੂੰ ਆਪਣੇ-ਆਪ ਲੱਭਦਾ ਹੈ।
- ਅਲੱਗ ਕੀਤੀਆਂ `HOME`/`APPDATA`/`XDG_*` ਡਾਇਰੈਕਟਰੀਆਂ ਨਾਲ ਲਾਂਚ ਕਰਦਾ ਹੈ, ਤਾਂ ਜੋ ਇਹ ਡਿਵੈਲਪਰ ਡਾਟਾ ਨੂੰ ਨਾ ਛੂਹੇ।
- 45 s ਦੇ ਅੰਦਰ HTTP 200 ਲਈ `http://127.0.0.1:20128/login` ਨੂੰ ਵਾਰ-ਵਾਰ ਪੋਲ ਕਰਦਾ ਹੈ।
- ਘਾਤਕ ਪੈਟਰਨਾਂ (`Cannot find module`, `MODULE_NOT_FOUND`, `ERR_DLOPEN_FAILED`, `Failed to start server`, ਆਦਿ) ਲਈ stderr/stdout ਦੀ ਨਿਗਰਾਨੀ ਕਰਦਾ ਹੈ।
- ਤਿਆਰ ਹੋਣ ਤੋਂ ਬਾਅਦ 2 s ਦੇ ਸਥਿਰ ਰਨਟਾਈਮ ਦੀ ਉਡੀਕ ਕਰਦਾ ਹੈ, ਫਿਰ SIGTERM ਭੇਜਦਾ ਹੈ ਅਤੇ ਪੋਰਟ ਦੇ ਖਾਲੀ ਹੋਣ ਦੀ ਉਡੀਕ ਕਰਦਾ ਹੈ।
- CI ਵਿੱਚ, ਆਪਣੇ-ਆਪ `--no-sandbox --disable-gpu` (ਅਤੇ Linux ਉੱਤੇ `--disable-dev-shm-usage`) ਪਾਸ ਕਰਦਾ ਹੈ।

Env ਓਵਰਰਾਈਡ: `ELECTRON_SMOKE_APP_EXECUTABLE`, `ELECTRON_SMOKE_URL`, `ELECTRON_SMOKE_TIMEOUT_MS`, `ELECTRON_SMOKE_SETTLE_MS`, `ELECTRON_SMOKE_DATA_DIR`, `ELECTRON_SMOKE_KEEP_DATA`, `ELECTRON_SMOKE_STREAM_LOGS`।

## ਕੋਡ ਸਾਈਨਿੰਗ

`electron/package.json` ਸਾਈਨਿੰਗ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲਾਂ ਨੂੰ ਸਿੱਧੇ ਤੌਰ 'ਤੇ ਸੰਰਚਿਤ **ਨਹੀਂ** ਕਰਦਾ। ਉਹਨਾਂ ਨੂੰ env vars ਰਾਹੀਂ `electron-builder` ਨੂੰ ਦਿਓ:

### macOS

```bash
export APPLE_ID=<email>
export APPLE_APP_SPECIFIC_PASSWORD=<password>
export APPLE_TEAM_ID=<id>
export CSC_LINK=path/to/cert.p12
export CSC_KEY_PASSWORD=<cert-password>
npm run electron:build:mac
```

### Windows

```bash
export CSC_LINK=path/to/cert.pfx
export CSC_KEY_PASSWORD=<cert-password>
npm run electron:build:win
```

### Linux

AppImage ਸਾਈਨਿੰਗ ਵਿਕਲਪਿਕ ਹੈ — ਸਾਈਨਿੰਗ ਲਈ `LINUX_GPG_KEY` ਸੈੱਟ ਕਰੋ।
