## 🎯 ਵਰਤੋਂ ਦੇ ਮਾਮਲੇ

### ਮਾਮਲਾ 1: "ਮੇਰੇ ਕੋਲ Claude Pro ਸਬਸਕ੍ਰਿਪਸ਼ਨ ਹੈ"

**ਸਮੱਸਿਆ:** ਕੋਟਾ ਬਿਨਾਂ ਵਰਤੋਂ ਦੇ ਖ਼ਤਮ ਹੋ ਜਾਂਦਾ ਹੈ, ਭਾਰੀ ਕੋਡਿੰਗ ਦੌਰਾਨ ਦਰ ਸੀਮਾਵਾਂ ਲੱਗ ਜਾਂਦੀਆਂ ਹਨ

```
ਕੌਂਬੋ: "maximize-claude"
  1. cc/claude-opus-4-7        (ਸਬਸਕ੍ਰਿਪਸ਼ਨ ਦੀ ਪੂਰੀ ਵਰਤੋਂ ਕਰੋ)
  2. glm/glm-4.7               (ਕੋਟਾ ਮੁੱਕਣ 'ਤੇ ਸਸਤਾ ਬੈਕਅੱਪ)
  3. if/qwen3.8-max-preview       (ਐਮਰਜੈਂਸੀ ਲਈ ਮੁਫ਼ਤ ਵਿਕਲਪ)

ਮਹੀਨਾਵਾਰ ਲਾਗਤ: $20 (ਸਬਸਕ੍ਰਿਪਸ਼ਨ) + ~$5 (ਬੈਕਅੱਪ) = ਕੁੱਲ $25
ਬਨਾਮ $20 + ਸੀਮਾਵਾਂ ਤੱਕ ਪਹੁੰਚਣਾ = ਨਿਰਾਸ਼ਾ
```

### ਮਾਮਲਾ 2: "ਮੈਂ ਸਿਫ਼ਰ ਲਾਗਤ ਚਾਹੁੰਦਾ ਹਾਂ"

**ਸਮੱਸਿਆ:** ਸਬਸਕ੍ਰਿਪਸ਼ਨਾਂ ਦਾ ਖ਼ਰਚ ਨਹੀਂ ਝੱਲ ਸਕਦਾ, ਭਰੋਸੇਯੋਗ AI ਕੋਡਿੰਗ ਦੀ ਲੋੜ ਹੈ

```
ਕੌਂਬੋ: "zero-cost"
  1. if/kimi-k2.7-code          (ਸੂਚੀਬੱਧ ਮੁਫ਼ਤ ਪਹੁੰਚ; ਦਰ ਸੀਮਾਵਾਂ ਲਾਗੂ ਹੋ ਸਕਦੀਆਂ ਹਨ)
  2. kr/qwen3-coder-next        (Kiro ਦਾ ਮੁਫ਼ਤ ਵਿਕਲਪ)

ਮਹੀਨਾਵਾਰ ਲਾਗਤ: $0
ਗੁਣਵੱਤਾ: ਆਪਣੇ ਵਰਕਲੋਡ ਲਈ ਮਾਡਲ, ਸੀਮਾਵਾਂ, ਪਰਦੇਦਾਰੀ ਅਤੇ SLA ਦੀ ਪੁਸ਼ਟੀ ਕਰੋ
```

### ਮਾਮਲਾ 3: "ਮੈਨੂੰ ਬਿਨਾਂ ਕਿਸੇ ਰੁਕਾਵਟ ਦੇ 24/7 ਕੋਡਿੰਗ ਚਾਹੀਦੀ ਹੈ"

ਸਰਵਰ ਅਤੇ ਟਰੇ ਤਿਆਰ ਹੋਣ ਤੋਂ ਬਾਅਦ ਕਮਾਂਡ ਵਾਪਸ ਆ ਜਾਂਦੀ ਹੈ।

ਸਰਵਰ ਟਰਮੀਨਲ ਤੋਂ ਬਿਨਾਂ ਚੱਲਦਾ ਰਹਿੰਦਾ ਹੈ।

ਟਰੇ ਮੋਡ macOS, Windows ਅਤੇ ਗ੍ਰਾਫ਼ਿਕਲ Linux ਸੈਸ਼ਨਾਂ ਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈ। ਟਰੇ ਮੋਡ ਡੈਸ਼ਬੋਰਡ ਨੂੰ ਆਪਣੇ-ਆਪ ਨਹੀਂ ਖੋਲ੍ਹਦਾ।

ਇਨ੍ਹਾਂ ਕਾਰਵਾਈਆਂ ਲਈ ਟਰੇ ਮੀਨੂ ਵਰਤੋ:

- ਡੈਸ਼ਬੋਰਡ ਖੋਲ੍ਹੋ।
- `/dashboard/logs` ਖੋਲ੍ਹੋ।
- ਆਟੋ-ਸਟਾਰਟ ਬਦਲੋ।
- OmniRoute ਨੂੰ ਰੋਕੋ।

`--tray` ਨੂੰ ਇਨ੍ਹਾਂ ਵਿਕਲਪਾਂ ਨਾਲ ਇਕੱਠੇ ਨਾ ਵਰਤੋ:

- `--daemon`
- `--log`
- `--no-recovery`

ਇਨ੍ਹਾਂ ਮੋਡਾਂ ਲਈ ਵੱਖਰੀ ਪ੍ਰਕਿਰਿਆ ਮਾਲਕੀ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ।

ਮਸ਼ੀਨ ਵਿੱਚ ਅਗਲੇ ਲੌਗਇਨ ਸਮੇਂ ਸਟਾਰਟਅੱਪ ਸਮਰੱਥ ਕਰੋ:

```bash
omniroute autostart enable
```

ਆਟੋ-ਸਟਾਰਟ macOS, Windows ਅਤੇ ਗ੍ਰਾਫ਼ਿਕਲ Linux ਸੈਸ਼ਨਾਂ ਉੱਤੇ ਟਰੇ ਮੋਡ ਵਰਤਦਾ ਹੈ। ਹੈੱਡਲੈੱਸ Linux ਮੌਜੂਦਾ systemd ਯੂਜ਼ਰ ਸਰਵਿਸ ਵਰਤਦਾ ਹੈ।

ਲੌਗਇਨ ਸਮੇਂ ਸਟਾਰਟਅੱਪ ਨੂੰ ਅਸਮਰੱਥ ਕਰੋ:

```bash
omniroute autostart disable
```

### ਅਣਇੰਸਟਾਲ ਕਰਨਾ

ਜਦੋਂ ਤੁਹਾਨੂੰ OmniRoute ਦੀ ਹੋਰ ਲੋੜ ਨਾ ਰਹੇ, ਤਾਂ ਅਸੀਂ ਸਾਫ਼ ਤਰੀਕੇ ਨਾਲ ਹਟਾਉਣ ਲਈ ਦੋ ਤੇਜ਼ ਸਕ੍ਰਿਪਟਾਂ ਦਿੰਦੇ ਹਾਂ:

| ਕਮਾਂਡ                    | ਕਾਰਵਾਈ                                                                                      |
| ------------------------ | ------------------------------------------------------------------------------------------- |
| `npm run uninstall`      | ਸਿਸਟਮ ਐਪ ਨੂੰ ਹਟਾਉਂਦੀ ਹੈ, ਪਰ `~/.omniroute` ਵਿੱਚ **ਤੁਹਾਡਾ DB ਅਤੇ ਸੰਰਚਨਾਵਾਂ ਰੱਖਦੀ ਹੈ**।       |
| `npm run uninstall:full` | ਐਪ ਨੂੰ ਹਟਾਉਂਦੀ ਹੈ ਅਤੇ **ਸਾਰੀਆਂ ਸੰਰਚਨਾਵਾਂ, ਕੁੰਜੀਆਂ ਅਤੇ ਡਾਟਾਬੇਸ ਸਥਾਈ ਤੌਰ ’ਤੇ ਮਿਟਾ ਦਿੰਦੀ ਹੈ**। |

> ਨੋਟ: ਇਹ ਕਮਾਂਡਾਂ ਚਲਾਉਣ ਲਈ OmniRoute ਪ੍ਰੋਜੈਕਟ ਫੋਲਡਰ ਵਿੱਚ ਜਾਓ (ਜੇ ਤੁਸੀਂ ਇਸਨੂੰ ਕਲੋਨ ਕੀਤਾ ਸੀ) ਅਤੇ ਉਨ੍ਹਾਂ ਨੂੰ ਚਲਾਓ। ਵਿਕਲਪਕ ਤੌਰ ’ਤੇ, ਜੇ ਇਹ ਗਲੋਬਲ ਤੌਰ ’ਤੇ ਇੰਸਟਾਲ ਹੈ, ਤਾਂ ਤੁਸੀਂ ਸਿਰਫ਼ `npm uninstall -g omniroute` ਚਲਾ ਸਕਦੇ ਹੋ।

### Void Linux (xbps-src)

Void Linux ਵਰਤੋਂਕਾਰ `xbps-src` ਕ੍ਰਾਸ-ਕੰਪਾਇਲੇਸ਼ਨ ਫਰੇਮਵਰਕ ਦੀ ਵਰਤੋਂ ਕਰਕੇ OmniRoute ਨੂੰ ਮੂਲ ਰੂਪ ਵਿੱਚ ਪੈਕੇਜ ਅਤੇ ਇੰਸਟਾਲ ਕਰ ਸਕਦੇ ਹਨ। ਇਹ ਲੋੜੀਂਦੀਆਂ `better-sqlite3` ਨੇਟਿਵ ਬਾਈਂਡਿੰਗਾਂ ਸਮੇਤ Node.js ਸਟੈਂਡਅਲੋਨ ਬਿਲਡ ਨੂੰ ਸਵੈਚਾਲਿਤ ਕਰਦਾ ਹੈ।

<summary><b>xbps-src ਟੈਂਪਲੇਟ ਵੇਖੋ</b></summary>

```bash

export NODE_ENV=production

	# node-gyp ਲਈ ਟਾਰਗੇਟ CPU ਆਰਕੀਟੈਕਚਰ ਨਿਰਧਾਰਤ ਕਰੋ
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	# 1) ਸਾਰੀਆਂ ਡਿਪੈਂਡੈਂਸੀਆਂ ਇੰਸਟਾਲ ਕਰੋ – ਸਕ੍ਰਿਪਟਾਂ ਛੱਡੋ
	NODE_ENV=development npm ci --ignore-scripts

	# 2) Next.js ਸਟੈਂਡਅਲੋਨ ਬੰਡਲ ਬਿਲਡ ਕਰੋ
	npm run build

	# 3) ਸਟੈਟਿਕ ਐਸੈੱਟਾਂ ਨੂੰ ਸਟੈਂਡਅਲੋਨ ਵਿੱਚ ਕਾਪੀ ਕਰੋ
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	# 5) ਕੰਪਾਇਲ ਕੀਤੀ ਬਾਈਂਡਿੰਗ ਨੂੰ ਸਟੈਂਡਅਲੋਨ ਬੰਡਲ ਵਿੱਚ ਰੱਖੋ
	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	# 6) ਆਰਕੀਟੈਕਚਰ-ਵਿਸ਼ੇਸ਼ sharp ਬੰਡਲ ਹਟਾਓ
	rm -rf .next/standalone/node_modules/@img

	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	# ਪੋਸਟ-ਇੰਸਟਾਲ ਹੁੱਕ ਦੁਆਰਾ ਖ਼ਾਲੀ Next.js ਐਪ ਰਾਊਟਰ ਡਾਇਰੈਕਟਰੀਆਂ ਨੂੰ ਹਟਾਏ ਜਾਣ ਤੋਂ ਰੋਕੋ
	for _d in \

export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"

exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```

### ਕਸਟਮ ਮਾਡਲ

ਐਪ ਅੱਪਡੇਟ ਦੀ ਉਡੀਕ ਕੀਤੇ ਬਿਨਾਂ ਕਿਸੇ ਵੀ ਪ੍ਰੋਵਾਈਡਰ ਵਿੱਚ ਕੋਈ ਵੀ ਮਾਡਲ ID ਸ਼ਾਮਲ ਕਰੋ:

```bash
# API ਰਾਹੀਂ
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# ਸੂਚੀ: curl http://localhost:20128/api/provider-models?provider=openai
# ਹਟਾਓ: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

ਜਾਂ ਡੈਸ਼ਬੋਰਡ ਵਰਤੋ: **ਪ੍ਰੋਵਾਈਡਰ → [ਪ੍ਰੋਵਾਈਡਰ] → ਕਸਟਮ ਮਾਡਲ**।

ਨੋਟ:

- OpenRouter ਅਤੇ OpenAI/Anthropic-ਅਨੁਕੂਲ ਪ੍ਰੋਵਾਈਡਰ ਸਿਰਫ਼ **ਉਪਲਬਧ ਮਾਡਲ** ਤੋਂ ਪ੍ਰਬੰਧਿਤ ਕੀਤੇ ਜਾਂਦੇ ਹਨ। ਹੱਥੀਂ ਜੋੜਨਾ, ਇੰਪੋਰਟ ਅਤੇ ਆਟੋ-ਸਿੰਕ—ਸਾਰੇ ਇੱਕੋ ਉਪਲਬਧ-ਮਾਡਲ ਸੂਚੀ ਵਿੱਚ ਸ਼ਾਮਲ ਹੁੰਦੇ ਹਨ, ਇਸ ਲਈ ਉਨ੍ਹਾਂ ਪ੍ਰੋਵਾਈਡਰਾਂ ਲਈ ਵੱਖਰਾ ਕਸਟਮ ਮਾਡਲ ਭਾਗ ਨਹੀਂ ਹੈ।
- **ਕਸਟਮ ਮਾਡਲ** ਭਾਗ ਉਨ੍ਹਾਂ ਪ੍ਰੋਵਾਈਡਰਾਂ ਲਈ ਹੈ ਜੋ ਪ੍ਰਬੰਧਿਤ ਉਪਲਬਧ-ਮਾਡਲ ਇੰਪੋਰਟ ਉਪਲਬਧ ਨਹੀਂ ਕਰਵਾਉਂਦੇ।

### OmniRoute ਪੀਅਰਾਂ ਦੀ ਚੇਨ ਬਣਾਉਣਾ

ਇੱਕ ਹੋਰ OmniRoute ਗੇਟਵੇ ਨੂੰ **ਕਸਟਮ OpenAI-ਅਨੁਕੂਲ** ਪ੍ਰੋਵਾਈਡਰ ਵਜੋਂ ਜੋੜਿਆ ਜਾ ਸਕਦਾ ਹੈ। ਪੀਅਰ ਦਾ `/v1` ਬੇਸ URL ਅਤੇ ਉਸ ਪੀਅਰ ਵੱਲੋਂ ਜਾਰੀ ਕੀਤੀ ਇੱਕ ਸਮਰਪਿਤ, ਘੱਟੋ-ਘੱਟ ਅਧਿਕਾਰਾਂ ਵਾਲੀ API ਕੁੰਜੀ ਵਰਤੋ।

ਪਰਸਪਰ ਜਾਂ ਮਲਟੀ-ਹੌਪ ਚੇਨਾਂ ਲਈ, ਹਰ ਗੇਟਵੇ ਉੱਤੇ ਆਪਟ-ਇਨ ਲੂਪ ਗਾਰਡ ਸਮਰੱਥ ਕਰੋ:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

ਸਿਰਫ਼ ਸਪਸ਼ਟ ਤੌਰ 'ਤੇ ਮਨਜ਼ੂਰਸ਼ੁਦਾ ਸੂਚੀ ਵਿੱਚ ਸ਼ਾਮਲ ਪੀਅਰ URL ਨੂੰ ਭੇਜੀਆਂ ਬੇਨਤੀਆਂ ਨੂੰ ਹੀ `X-OmniRoute-Peer-Trace` ਹੈਡਰ ਮਿਲਦਾ ਹੈ। ਗੇਟਵੇ ਦੁਹਰਾਈ ਗਈ ਇੰਸਟੈਂਸ ID ਜਾਂ ਸਮਾਪਤ ਹੋ ਚੁੱਕੇ ਹੌਪ ਬਜਟ ਨੂੰ HTTP `508 Loop Detected` ਨਾਲ ਅਸਵੀਕਾਰ ਕਰਦਾ ਹੈ; ਆਮ ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰੋਵਾਈਡਰਾਂ ਨੂੰ ਕੋਈ ਪੀਅਰ ਮੈਟਾਡਾਟਾ ਨਹੀਂ ਮਿਲਦਾ।

ਪੀਅਰ ਚੇਨਿੰਗ ਡਾਟਾਬੇਸ ਰੈਪਲੀਕੇਸ਼ਨ ਜਾਂ ਹੋਸਟ ਫੇਲਓਵਰ ਨਹੀਂ ਹੈ। ਹਰ ਗੇਟਵੇ ਆਪਣੀ ਸੁਤੰਤਰ SQLite ਸਥਿਤੀ, ਕੈਸ਼, ਰੇਟ ਕਾਊਂਟਰ ਅਤੇ ਸੈਸ਼ਨ ਰੱਖਦਾ ਹੈ। ਐਕਟਿਵ/ਪੈਸਿਵ ਜਾਂ ਐਕਟਿਵ/ਐਕਟਿਵ ਉਪਲਬਧਤਾ ਲਈ ਹੈਲਥ-ਚੈੱਕ ਵਾਲਾ ਰਿਵਰਸ ਪ੍ਰਾਕਸੀ ਜਾਂ ਕਲਾਇੰਟ ਫੇਲਓਵਰ ਵਰਤੋ, ਅਤੇ ਇੱਕ SQLite ਡਾਟਾਬੇਸ ਨੂੰ ਕਦੇ ਵੀ ਕਈ ਚੱਲ ਰਹੀਆਂ OmniRoute ਇੰਸਟੈਂਸਾਂ ਵਿੱਚ ਮਾਊਂਟ ਨਾ ਕਰੋ।

### ਕਲਾਉਡ ਸਿੰਕ

- ਪ੍ਰੋਵਾਈਡਰਾਂ, ਕੌਂਬੋਜ਼ ਅਤੇ ਸੈਟਿੰਗਾਂ ਨੂੰ ਡਿਵਾਈਸਾਂ ਵਿੱਚ ਸਿੰਕ ਕਰੋ
- ਟਾਈਮਆਉਟ + ਫੇਲ-ਫਾਸਟ ਨਾਲ ਆਟੋਮੈਟਿਕ ਬੈਕਗ੍ਰਾਊਂਡ ਸਿੰਕ
- ਪ੍ਰੋਡਕਸ਼ਨ ਵਿੱਚ ਸਰਵਰ-ਸਾਈਡ `NEXT_PUBLIC_BASE_URL`/`NEXT_PUBLIC_CLOUD_URL` ਨੂੰ ਤਰਜੀਹ ਦਿਓ

### Cloudflare ਕਵਿਕ ਟਨਲ

- Docker ਅਤੇ ਹੋਰ ਸਵੈ-ਹੋਸਟਡ ਡਿਪਲੌਇਮੈਂਟਾਂ ਲਈ **ਡੈਸ਼ਬੋਰਡ → ਐਂਡਪੌਇੰਟਸ** ਵਿੱਚ ਉਪਲਬਧ
- ਇੱਕ ਅਸਥਾਈ `https://*.trycloudflare.com` URL ਬਣਾਉਂਦਾ ਹੈ, ਜੋ ਤੁਹਾਡੇ ਮੌਜੂਦਾ OpenAI-ਅਨੁਕੂਲ `/v1` ਐਂਡਪੌਇੰਟ ਵੱਲ ਫਾਰਵਰਡ ਕਰਦਾ ਹੈ
- ਪਹਿਲੀ ਵਾਰ ਸਮਰੱਥ ਕਰਨ 'ਤੇ ਸਿਰਫ਼ ਲੋੜ ਪੈਣ ਵੇਲੇ `cloudflared` ਇੰਸਟਾਲ ਹੁੰਦਾ ਹੈ; ਬਾਅਦ ਦੇ ਰੀਸਟਾਰਟ ਉਸੇ ਪ੍ਰਬੰਧਿਤ ਬਾਈਨਰੀ ਨੂੰ ਮੁੜ ਵਰਤਦੇ ਹਨ
- OmniRoute ਜਾਂ ਕੰਟੇਨਰ ਰੀਸਟਾਰਟ ਹੋਣ ਤੋਂ ਬਾਅਦ ਕਵਿਕ ਟਨਲ ਆਪਣੇ ਆਪ ਮੁੜ-ਸਥਾਪਿਤ ਨਹੀਂ ਹੁੰਦੇ; ਲੋੜ ਪੈਣ 'ਤੇ ਉਨ੍ਹਾਂ ਨੂੰ ਡੈਸ਼ਬੋਰਡ ਤੋਂ ਮੁੜ ਸਮਰੱਥ ਕਰੋ
- ਟਨਲ URL ਅਸਥਾਈ ਹੁੰਦੇ ਹਨ ਅਤੇ ਹਰ ਵਾਰ ਟਨਲ ਨੂੰ ਰੋਕਣ/ਸ਼ੁਰੂ ਕਰਨ 'ਤੇ ਬਦਲ ਜਾਂਦੇ ਹਨ
- ਸੀਮਤ ਕੰਟੇਨਰਾਂ ਵਿੱਚ ਸ਼ੋਰ ਵਾਲੀਆਂ QUIC UDP ਬਫ਼ਰ ਚੇਤਾਵਨੀਆਂ ਤੋਂ ਬਚਣ ਲਈ ਪ੍ਰਬੰਧਿਤ ਕਵਿਕ ਟਨਲ ਮੂਲ ਰੂਪ ਵਿੱਚ HTTP/2 ਟ੍ਰਾਂਸਪੋਰਟ ਵਰਤਦੇ ਹਨ
- ਜੇ ਤੁਸੀਂ ਪ੍ਰਬੰਧਿਤ ਟ੍ਰਾਂਸਪੋਰਟ ਚੋਣ ਨੂੰ ਓਵਰਰਾਈਡ ਕਰਨਾ ਚਾਹੁੰਦੇ ਹੋ, ਤਾਂ `CLOUDFLARED_PROTOCOL=quic` ਜਾਂ `auto` ਸੈੱਟ ਕਰੋ
- ਜੇ ਤੁਸੀਂ ਪ੍ਰਬੰਧਿਤ ਡਾਊਨਲੋਡ ਦੀ ਬਜਾਏ ਪਹਿਲਾਂ ਤੋਂ ਇੰਸਟਾਲ ਕੀਤੀ `cloudflared` ਬਾਈਨਰੀ ਵਰਤਣਾ ਪਸੰਦ ਕਰਦੇ ਹੋ, ਤਾਂ `CLOUDFLARED_BIN` ਸੈੱਟ ਕਰੋ
- Cloudflare ਕਵਿਕ ਟਨਲ, Tailscale Funnel ਅਤੇ ngrok Tunnel ਪੈਨਲਾਂ ਨੂੰ **ਸੈਟਿੰਗਾਂ → ਦਿੱਖ** ਵਿੱਚ ਦਿਖਾਇਆ ਜਾਂ ਲੁਕਾਇਆ ਜਾ ਸਕਦਾ ਹੈ। ਕਿਸੇ ਪੈਨਲ ਨੂੰ ਲੁਕਾਉਣ ਨਾਲ ਚੱਲ ਰਹੀ ਟਨਲ ਬੰਦ ਨਹੀਂ ਹੁੰਦੀ।

### LLM ਗੇਟਵੇ ਇੰਟੈਲੀਜੈਂਸ (ਪੜਾਅ 9)

- **ਸੈਮੈਂਟਿਕ ਕੈਸ਼** — ਗੈਰ-ਸਟ੍ਰੀਮਿੰਗ, temperature=0 ਜਵਾਬਾਂ ਨੂੰ ਆਪਣੇ ਆਪ ਕੈਸ਼ ਕਰਦਾ ਹੈ (`X-OmniRoute-No-Cache: true` ਨਾਲ ਬਾਈਪਾਸ ਕਰੋ)
- **ਬੇਨਤੀ ਆਈਡੈਂਪੋਟੈਂਸੀ** — `Idempotency-Key` ਜਾਂ `X-Request-Id` ਹੈਡਰ ਰਾਹੀਂ 5s ਦੇ ਅੰਦਰ ਬੇਨਤੀਆਂ ਦੇ ਡੁਪਲੀਕੇਟ ਹਟਾਉਂਦੀ ਹੈ
- **ਪ੍ਰਗਤੀ ਟ੍ਰੈਕਿੰਗ** — `X-OmniRoute-Progress: true` ਹੈਡਰ ਰਾਹੀਂ ਆਪਟ-ਇਨ SSE `event: progress` ਇਵੈਂਟ

### ਅਨੁਵਾਦਕ ਪਲੇਗ੍ਰਾਊਂਡ

**ਡੈਸ਼ਬੋਰਡ → ਅਨੁਵਾਦਕ** ਰਾਹੀਂ ਪਹੁੰਚੋ। ਡੀਬੱਗ ਕਰੋ ਅਤੇ ਦ੍ਰਿਸ਼ਟੀਗਤ ਢੰਗ ਨਾਲ ਵੇਖੋ ਕਿ OmniRoute ਪ੍ਰੋਵਾਈਡਰਾਂ ਵਿਚਕਾਰ API ਬੇਨਤੀਆਂ ਦਾ ਅਨੁਵਾਦ ਕਿਵੇਂ ਕਰਦਾ ਹੈ।

| ਮੋਡ             | ਉਦੇਸ਼                                                                    |
| --------------- | ------------------------------------------------------------------------ |
| **ਪਲੇਗ੍ਰਾਊਂਡ**  | ਸਰੋਤ/ਟੀਚਾ ਫਾਰਮੈਟ ਚੁਣੋ, ਬੇਨਤੀ ਪੇਸਟ ਕਰੋ ਅਤੇ ਅਨੁਵਾਦਿਤ ਆਉਟਪੁੱਟ ਤੁਰੰਤ ਵੇਖੋ    |
| **ਚੈਟ ਟੈਸਟਰ**   | ਪ੍ਰਾਕਸੀ ਰਾਹੀਂ ਲਾਈਵ ਚੈਟ ਸੁਨੇਹੇ ਭੇਜੋ ਅਤੇ ਪੂਰੇ ਬੇਨਤੀ/ਜਵਾਬ ਚੱਕਰ ਦੀ ਜਾਂਚ ਕਰੋ  |
| **ਟੈਸਟ ਬੈਂਚ**   | ਅਨੁਵਾਦ ਦੀ ਸ਼ੁੱਧਤਾ ਦੀ ਪੁਸ਼ਟੀ ਕਰਨ ਲਈ ਕਈ ਫਾਰਮੈਟ ਸੰਯੋਜਨਾਂ ਵਿੱਚ ਬੈਚ ਟੈਸਟ ਚਲਾਓ |
| **ਲਾਈਵ ਮਾਨੀਟਰ** | ਜਦੋਂ ਬੇਨਤੀਆਂ ਪ੍ਰਾਕਸੀ ਵਿੱਚੋਂ ਲੰਘਦੀਆਂ ਹਨ, ਤਾਂ ਰੀਅਲ-ਟਾਈਮ ਅਨੁਵਾਦ ਵੇਖੋ        |

**ਵਰਤੋਂ ਦੇ ਮਾਮਲੇ:**

- ਡੀਬੱਗ ਕਰੋ ਕਿ ਕੋਈ ਖਾਸ ਕਲਾਇੰਟ/ਪ੍ਰੋਵਾਈਡਰ ਸੰਯੋਜਨ ਕਿਉਂ ਅਸਫਲ ਹੁੰਦਾ ਹੈ
- ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਥਿੰਕਿੰਗ ਟੈਗ, ਟੂਲ ਕਾਲਾਂ ਅਤੇ ਸਿਸਟਮ ਪ੍ਰੌਂਪਟ ਸਹੀ ਤਰ੍ਹਾਂ ਅਨੁਵਾਦ ਹੁੰਦੇ ਹਨ
- OpenAI, Claude, Gemini ਅਤੇ Responses API ਫਾਰਮੈਟਾਂ ਵਿਚਕਾਰ ਫਾਰਮੈਟ ਅੰਤਰਾਂ ਦੀ ਤੁਲਨਾ ਕਰੋ

### ਰੂਟਿੰਗ ਰਣਨੀਤੀਆਂ

**Dashboard → Settings → Routing** ਰਾਹੀਂ ਸੰਰਚਨਾ ਕਰੋ। ਡੈਸ਼ਬੋਰਡ ਸਭ ਤੋਂ ਵੱਧ ਵਰਤੀਆਂ ਜਾਣ ਵਾਲੀਆਂ ਛੇ ਰਣਨੀਤੀਆਂ ਦਿਖਾਉਂਦਾ ਹੈ; ਕੌਂਬੋ ਅਤੇ ਆਟੋ-ਰਾਊਟਰ ਅੰਦਰੂਨੀ ਤੌਰ 'ਤੇ ਹੋਰ ਵਿਆਪਕ ਸਮੂਹ ਦਾ ਸਮਰਥਨ ਕਰਦੇ ਹਨ।

**ਡੈਸ਼ਬੋਰਡ 'ਤੇ ਦਿਖਾਈ ਦੇਣ ਵਾਲੀਆਂ ਰਣਨੀਤੀਆਂ (ਖਾਤਾ-ਪੱਧਰੀ ਰਾਊਟਿੰਗ):**

| ਰਣਨੀਤੀ                      | ਵੇਰਵਾ                                                                                                            |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| **ਪਹਿਲਾਂ ਭਰੋ**              | ਖਾਤਿਆਂ ਨੂੰ ਤਰਜੀਹੀ ਕ੍ਰਮ ਵਿੱਚ ਵਰਤਦਾ ਹੈ — ਮੁੱਖ ਖਾਤਾ ਉਪਲਬਧ ਨਾ ਰਹਿਣ ਤੱਕ ਸਾਰੀਆਂ ਬੇਨਤੀਆਂ ਸੰਭਾਲਦਾ ਹੈ                     |
| **ਰਾਊਂਡ ਰੌਬਿਨ**             | ਸੰਰਚਨਾਯੋਗ ਸਟਿੱਕੀ ਸੀਮਾ ਨਾਲ ਸਾਰੇ ਖਾਤਿਆਂ ਨੂੰ ਵਾਰੀ-ਵਾਰੀ ਵਰਤਦਾ ਹੈ (ਮੂਲ: ਪ੍ਰਤੀ ਖਾਤਾ 3 ਕਾਲਾਂ)                           |
| **P2C (ਦੋ ਚੋਣਾਂ ਦੀ ਸ਼ਕਤੀ)** | 2 ਬੇਤਰਤੀਬ ਖਾਤੇ ਚੁਣਦਾ ਹੈ ਅਤੇ ਵਧੇਰੇ ਸਿਹਤਮੰਦ ਖਾਤੇ ਵੱਲ ਰਾਊਟ ਕਰਦਾ ਹੈ — ਸਿਹਤ ਨੂੰ ਧਿਆਨ ਵਿੱਚ ਰੱਖਦਿਆਂ ਲੋਡ ਸੰਤੁਲਿਤ ਕਰਦਾ ਹੈ |
| **ਬੇਤਰਤੀਬ**                 | Fisher-Yates ਸ਼ਫ਼ਲ ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਹਰੇਕ ਬੇਨਤੀ ਲਈ ਬੇਤਰਤੀਬ ਢੰਗ ਨਾਲ ਇੱਕ ਖਾਤਾ ਚੁਣਦਾ ਹੈ                                 |
| **ਸਭ ਤੋਂ ਘੱਟ ਵਰਤਿਆ**        | ਸਭ ਤੋਂ ਪੁਰਾਣੇ `lastUsedAt` ਟਾਈਮਸਟੈਂਪ ਵਾਲੇ ਖਾਤੇ ਵੱਲ ਰਾਊਟ ਕਰਦਾ ਹੈ, ਜਿਸ ਨਾਲ ਟ੍ਰੈਫ਼ਿਕ ਸਮਾਨ ਰੂਪ ਵਿੱਚ ਵੰਡਿਆ ਜਾਂਦਾ ਹੈ   |
| **ਲਾਗਤ ਅਨੁਕੂਲਿਤ**           | ਸਭ ਤੋਂ ਘੱਟ ਤਰਜੀਹ ਮੁੱਲ ਵਾਲੇ ਖਾਤੇ ਵੱਲ ਰਾਊਟ ਕਰਦਾ ਹੈ, ਜਿਸ ਨਾਲ ਸਭ ਤੋਂ ਘੱਟ ਲਾਗਤ ਵਾਲੇ ਪ੍ਰਦਾਤਾਵਾਂ ਲਈ ਅਨੁਕੂਲਨ ਹੁੰਦਾ ਹੈ    |

**ਉੱਨਤ ਕੌਂਬੋ ਅਤੇ ਆਟੋ ਰਣਨੀਤੀਆਂ** (ਹਰੇਕ ਕੌਂਬੋ ਲਈ ਜਾਂ `auto/*` ਪ੍ਰੀਫਿਕਸਾਂ ਰਾਹੀਂ ਸੰਰਚਨਾਯੋਗ — [AUTO-COMBO.md](../routing/AUTO-COMBO.md) ਵੇਖੋ):

- `priority` — ਸਖ਼ਤ ਕ੍ਰਮ, ਕਦੇ ਵੀ ਰਾਊਂਡ-ਰੌਬਿਨ ਨਹੀਂ ਕਰਦਾ
- `weighted` — ਪ੍ਰਤੀ-ਮਾਡਲ ਭਾਰਾਂ ਅਨੁਸਾਰ ਅਨੁਪਾਤਕ ਟ੍ਰੈਫ਼ਿਕ ਵੰਡ
- `fill-first` — ਸੀਮਾਵਾਂ ਪੂਰੀਆਂ ਹੋਣ ਤੱਕ ਪਹਿਲੇ ਮਾਡਲ ਨੂੰ ਵਰਤਦਾ ਹੈ
- `round-robin` / `strict-random` / `random`
- `p2c` (ਦੋ ਚੋਣਾਂ ਦੀ ਸ਼ਕਤੀ)
- `least-used` ਅਤੇ `cost-optimized`
- `auto` — ਸਾਰੇ ਉਮੀਦਵਾਰਾਂ ਵਿੱਚ ਸਕੋਰ-ਅਧਾਰਿਤ ਚੋਣ
- `lkgp` (ਆਖਰੀ ਜਾਣਿਆ ਚੰਗਾ ਪ੍ਰਦਾਤਾ) — ਆਖਰੀ ਸਫਲ ਪ੍ਰਦਾਤਾ ਨਾਲ ਜੁੜਿਆ ਰਹਿੰਦਾ ਹੈ, ਫਿਰ ਨਿਯਮਾਂ ਅਨੁਸਾਰ ਫਾਲਬੈਕ ਕਰਦਾ ਹੈ
- `context-optimized` — ਸਭ ਤੋਂ ਵੱਡੀ ਖਾਲੀ ਕਾਂਟੈਕਸਟ ਵਿੰਡੋ ਵਾਲਾ ਮਾਡਲ ਚੁਣਦਾ ਹੈ
- `context-relay` — ਫਾਲੋ-ਅੱਪ ਵਾਰੀਆਂ ਲਈ ਲੰਬੇ-ਕਾਂਟੈਕਸਟ ਵਾਲੇ ਮਾਡਲਾਂ ਨੂੰ ਲੜੀਬੱਧ ਕਰਦਾ ਹੈ

#### ਬਾਹਰੀ ਸਟਿੱਕੀ ਸੈਸ਼ਨ ਹੈਡਰ

ਬਾਹਰੀ ਸੈਸ਼ਨ ਅਫ਼ਿਨਿਟੀ ਲਈ (ਉਦਾਹਰਨ ਵਜੋਂ, ਰਿਵਰਸ ਪ੍ਰੌਕਸੀਆਂ ਦੇ ਪਿੱਛੇ Claude Code/Codex ਏਜੰਟ), ਇਹ ਭੇਜੋ:

```http
X-Session-Id: your-session-key
```

OmniRoute `x_session_id` ਨੂੰ ਵੀ ਸਵੀਕਾਰ ਕਰਦਾ ਹੈ ਅਤੇ ਪ੍ਰਭਾਵੀ ਸੈਸ਼ਨ ਕੁੰਜੀ `X-OmniRoute-Session-Id` ਵਿੱਚ ਵਾਪਸ ਕਰਦਾ ਹੈ।

ਜੇ ਤੁਸੀਂ Nginx ਵਰਤਦੇ ਹੋ ਅਤੇ ਅੰਡਰਸਕੋਰ-ਰੂਪ ਵਾਲੇ ਹੈਡਰ ਭੇਜਦੇ ਹੋ, ਤਾਂ ਇਹ ਸਮਰੱਥ ਕਰੋ:

```nginx
underscores_in_headers on;
```

#### ਵਾਇਲਡਕਾਰਡ ਮਾਡਲ ਉਪਨਾਮ

ਮਾਡਲ ਨਾਮਾਂ ਨੂੰ ਦੁਬਾਰਾ ਮੈਪ ਕਰਨ ਲਈ ਵਾਇਲਡਕਾਰਡ ਪੈਟਰਨ ਬਣਾਓ:

```
ਪੈਟਰਨ: claude-sonnet-*     →  ਟਾਰਗੇਟ: cc/claude-sonnet-4-6
ਪੈਟਰਨ: gpt-*               →  ਟਾਰਗੇਟ: gh/gpt-5.3-codex
```

ਵਾਇਲਡਕਾਰਡ `*` (ਕੋਈ ਵੀ ਅੱਖਰ) ਅਤੇ `?` (ਇੱਕ ਅੱਖਰ) ਦਾ ਸਮਰਥਨ ਕਰਦੇ ਹਨ।

#### ਫਾਲਬੈਕ ਲੜੀਆਂ

ਉਹ ਗਲੋਬਲ ਫਾਲਬੈਕ ਲੜੀਆਂ ਪਰਿਭਾਸ਼ਿਤ ਕਰੋ ਜੋ ਸਾਰੀਆਂ ਬੇਨਤੀਆਂ 'ਤੇ ਲਾਗੂ ਹੁੰਦੀਆਂ ਹਨ:

```
ਲੜੀ: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### ਲਚੀਲਾਪਣ ਅਤੇ ਸਰਕਿਟ ਬ੍ਰੇਕਰ

**Dashboard → Settings → Resilience** ਰਾਹੀਂ ਸੰਰਚਨਾ ਕਰੋ।

OmniRoute ਪੰਜ ਭਾਗਾਂ ਨਾਲ ਪ੍ਰਦਾਤਾ-ਪੱਧਰੀ ਲਚੀਲਾਪਣ ਲਾਗੂ ਕਰਦਾ ਹੈ:

1. **ਬੇਨਤੀ ਕਤਾਰ ਅਤੇ ਗਤੀ ਨਿਯੰਤਰਣ** — ਸਿਸਟਮ-ਪੱਧਰੀ ਬੇਨਤੀ ਆਕਾਰ-ਨਿਰਧਾਰਨ:
   - **ਪ੍ਰਤੀ ਮਿੰਟ ਬੇਨਤੀਆਂ (RPM)** — ਪ੍ਰਤੀ ਖਾਤਾ ਪ੍ਰਤੀ ਮਿੰਟ ਵੱਧ ਤੋਂ ਵੱਧ ਬੇਨਤੀਆਂ
   - **ਬੇਨਤੀਆਂ ਵਿਚਕਾਰ ਘੱਟੋ-ਘੱਟ ਸਮਾਂ** — ਬੇਨਤੀਆਂ ਵਿਚਕਾਰ ਮਿਲੀਸਕਿੰਟਾਂ ਵਿੱਚ ਘੱਟੋ-ਘੱਟ ਅੰਤਰ
   - **ਵੱਧ ਤੋਂ ਵੱਧ ਸਮਕਾਲੀ ਬੇਨਤੀਆਂ** — ਪ੍ਰਤੀ ਖਾਤਾ ਵੱਧ ਤੋਂ ਵੱਧ ਇੱਕੋ ਸਮੇਂ ਦੀਆਂ ਬੇਨਤੀਆਂ

2. **ਕਨੈਕਸ਼ਨ ਕੂਲਡਾਊਨ** — ਮੁੜ-ਕੋਸ਼ਿਸ਼ਯੋਗ ਅਸਫਲਤਾਵਾਂ ਤੋਂ ਬਾਅਦ ਇੱਕ ਕਨੈਕਸ਼ਨ ਲਈ ਪ੍ਰਤੀ-ਪ੍ਰਮਾਣੀਕਰਨ-ਕਿਸਮ ਸੰਰਚਨਾ:
   - **ਮੂਲ ਕੂਲਡਾਊਨ** — ਮੁੜ-ਕੋਸ਼ਿਸ਼ਯੋਗ ਅੱਪਸਟ੍ਰੀਮ ਅਸਫਲਤਾਵਾਂ ਲਈ ਮੂਲ ਕੂਲਡਾਊਨ ਵਿੰਡੋ
   - **ਅੱਪਸਟ੍ਰੀਮ ਮੁੜ-ਕੋਸ਼ਿਸ਼ ਸੰਕੇਤ ਵਰਤੋ** — ਉਪਲਬਧ ਹੋਣ 'ਤੇ ਅਧਿਕਾਰਤ `Retry-After` ਜਾਂ ਰੀਸੈੱਟ ਸੰਕੇਤਾਂ ਦਾ ਪਾਲਣ ਕਰਦਾ ਹੈ
   - **ਵੱਧ ਤੋਂ ਵੱਧ ਬੈਕਆਫ਼ ਪੜਾਅ** — ਦੁਹਰਾਈਆਂ ਅਸਫਲਤਾਵਾਂ ਲਈ ਵੱਧ ਤੋਂ ਵੱਧ ਐਕਸਪੋਨੇੰਸ਼ੀਅਲ ਬੈਕਆਫ਼ ਪੱਧਰ

3. **ਪ੍ਰਦਾਤਾ ਸਰਕਿਟ ਬ੍ਰੇਕਰ** — ਸ਼ੁਰੂ ਤੋਂ ਅੰਤ ਤੱਕ ਦੀਆਂ ਪ੍ਰਦਾਤਾ ਅਸਫਲਤਾਵਾਂ ਨੂੰ ਟ੍ਰੈਕ ਕਰਦਾ ਹੈ, ਸੰਰਚਿਤ ਚੇਤਾਵਨੀ ਸੀਮਾ 'ਤੇ ਪ੍ਰਦਾਤਾ ਨੂੰ ਕਮਜ਼ੋਰ ਵਜੋਂ ਚਿੰਨ੍ਹਿਤ ਕਰਦਾ ਹੈ ਅਤੇ ਸੰਰਚਿਤ ਅਸਫਲਤਾ ਸੀਮਾ ਪੂਰੀ ਹੋਣ 'ਤੇ ਬ੍ਰੇਕਰ ਖੋਲ੍ਹਦਾ ਹੈ:
   - **ਕਮਜ਼ੋਰੀ ਸੀਮਾ** — `DEGRADED` ਵਿੱਚ ਦਾਖ਼ਲ ਹੋਣ ਤੋਂ ਪਹਿਲਾਂ ਲਗਾਤਾਰ ਪ੍ਰਦਾਤਾ ਅਸਫਲਤਾਵਾਂ
   - **ਅਸਫਲਤਾ ਸੀਮਾ** — `OPEN` ਵਿੱਚ ਦਾਖ਼ਲ ਹੋਣ ਤੋਂ ਪਹਿਲਾਂ ਲਗਾਤਾਰ ਪ੍ਰਦਾਤਾ ਅਸਫਲਤਾਵਾਂ
   - **ਰੀਸੈੱਟ ਟਾਈਮਆਉਟ** — ਪ੍ਰਦਾਤਾ ਦੀ ਦੁਬਾਰਾ ਜਾਂਚ ਤੋਂ ਪਹਿਲਾਂ ਦੀ ਸਮਾਂ ਵਿੰਡੋ
   - **CLOSED** (ਸਿਹਤਮੰਦ) — ਬੇਨਤੀਆਂ ਆਮ ਤੌਰ 'ਤੇ ਪ੍ਰਵਾਹਿਤ ਹੁੰਦੀਆਂ ਹਨ
   - **DEGRADED** — ਵਧੀਆਂ ਅਸਫਲਤਾਵਾਂ ਨੂੰ ਟ੍ਰੈਕ ਕਰਦਿਆਂ ਬੇਨਤੀਆਂ ਹਾਲੇ ਵੀ ਪ੍ਰਵਾਹਿਤ ਹੁੰਦੀਆਂ ਹਨ
   - **OPEN** — ਦੁਹਰਾਈਆਂ ਅਸਫਲਤਾਵਾਂ ਤੋਂ ਬਾਅਦ ਪ੍ਰਦਾਤਾ ਅਸਥਾਈ ਤੌਰ 'ਤੇ ਬਲੌਕ ਹੁੰਦਾ ਹੈ
   - **HALF_OPEN** — ਜਾਂਚ ਕਰ ਰਿਹਾ ਹੈ ਕਿ ਪ੍ਰਦਾਤਾ ਮੁੜ ਠੀਕ ਹੋ ਗਿਆ ਹੈ ਜਾਂ ਨਹੀਂ

   ਕਨੈਕਸ਼ਨ-ਸੀਮਿਤ `429` ਦਰ ਸੀਮਾਵਾਂ **ਕਨੈਕਸ਼ਨ ਕੂਲਡਾਊਨ** ਵਿੱਚ ਰਹਿੰਦੀਆਂ ਹਨ ਅਤੇ ਪ੍ਰਦਾਤਾ ਬ੍ਰੇਕਰ ਵਿੱਚ ਨਹੀਂ ਗਿਣੀਆਂ ਜਾਂਦੀਆਂ।

   ਪ੍ਰਦਾਤਾ ਬ੍ਰੇਕਰ ਦੀ ਰਨਟਾਈਮ ਸਥਿਤੀ ਸਿਰਫ਼ **Dashboard → Health** 'ਤੇ ਦਿਖਾਈ ਜਾਂਦੀ ਹੈ।

4. **ਕੂਲਡਾਊਨ ਦੀ ਉਡੀਕ ਕਰੋ** — ਜੇ ਹਰੇਕ ਉਮੀਦਵਾਰ ਕਨੈਕਸ਼ਨ ਪਹਿਲਾਂ ਹੀ ਕੂਲਡਾਊਨ ਵਿੱਚ ਹੈ, ਤਾਂ OmniRoute ਸਭ ਤੋਂ ਪਹਿਲਾਂ ਖ਼ਤਮ ਹੋਣ ਵਾਲੇ ਕੂਲਡਾਊਨ ਦੀ ਉਡੀਕ ਕਰ ਸਕਦਾ ਹੈ ਅਤੇ ਉਸੇ ਕਲਾਇੰਟ ਬੇਨਤੀ ਦੀ ਆਪਣੇ ਆਪ ਮੁੜ ਕੋਸ਼ਿਸ਼ ਕਰ ਸਕਦਾ ਹੈ।

5. **ਦਰ ਸੀਮਾ ਦੀ ਸਵੈਚਲਿਤ ਪਛਾਣ** — ਜਦੋਂ ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰਦਾਤਾ ਸਪਸ਼ਟ ਉਡੀਕ ਵਿੰਡੋ ਵਾਪਸ ਕਰਦੇ ਹਨ, ਤਾਂ ਸੈਟਿੰਗ ਸਮਰੱਥ ਹੋਣ 'ਤੇ ਉਹ ਸੰਕੇਤ ਸਥਾਨਕ ਕਨੈਕਸ਼ਨ ਕੂਲਡਾਊਨ ਨੂੰ ਓਵਰਰਾਈਡ ਕਰਦੇ ਹਨ।

**ਮਾਹਰ ਸੁਝਾਅ:** ਆਊਟੇਜ ਤੋਂ ਬਾਅਦ ਲਾਈਵ ਪ੍ਰਦਾਤਾ ਬ੍ਰੇਕਰਾਂ ਦੀ ਜਾਂਚ ਅਤੇ ਰੀਸੈੱਟ ਕਰਨ ਲਈ **Health** ਪੰਨਾ ਵਰਤੋ। Resilience ਪੰਨਾ ਸਿਰਫ਼ ਸੰਰਚਨਾ ਬਦਲਦਾ ਹੈ।

### ਡਾਟਾਬੇਸ ਐਕਸਪੋਰਟ / ਇੰਪੋਰਟ

**Dashboard → Settings → System & Storage** ਵਿੱਚ ਡਾਟਾਬੇਸ ਬੈਕਅੱਪਾਂ ਦਾ ਪ੍ਰਬੰਧਨ ਕਰੋ।

| ਕਾਰਵਾਈ                           | ਵੇਰਵਾ                                                                                                                                                              |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **ਡਾਟਾਬੇਸ ਐਕਸਪੋਰਟ ਕਰੋ**          | ਮੌਜੂਦਾ SQLite ਡਾਟਾਬੇਸ ਨੂੰ `.sqlite` ਫ਼ਾਈਲ ਵਜੋਂ ਡਾਊਨਲੋਡ ਕਰਦਾ ਹੈ                                                                                                     |
| **ਸਭ ਕੁਝ ਐਕਸਪੋਰਟ ਕਰੋ (.tar.gz)** | ਇੱਕ ਪੂਰਾ ਬੈਕਅੱਪ ਆਰਕਾਈਵ ਡਾਊਨਲੋਡ ਕਰਦਾ ਹੈ, ਜਿਸ ਵਿੱਚ ਸ਼ਾਮਲ ਹਨ: ਡਾਟਾਬੇਸ, ਸੈਟਿੰਗਾਂ, ਕੌਂਬੋ, ਪ੍ਰਦਾਤਾ ਕਨੈਕਸ਼ਨ (ਕ੍ਰੈਡੈਂਸ਼ੀਅਲਾਂ ਤੋਂ ਬਿਨਾਂ), API ਕੁੰਜੀ ਮੈਟਾਡੇਟਾ                |
| **ਡਾਟਾਬੇਸ ਇੰਪੋਰਟ ਕਰੋ**           | ਮੌਜੂਦਾ ਡਾਟਾਬੇਸ ਨੂੰ ਬਦਲਣ ਲਈ ਇੱਕ `.sqlite` ਫ਼ਾਈਲ ਅੱਪਲੋਡ ਕਰਦਾ ਹੈ। ਜਦੋਂ ਤੱਕ `DISABLE_SQLITE_AUTO_BACKUP=true` ਨਾ ਹੋਵੇ, ਇੰਪੋਰਟ ਤੋਂ ਪਹਿਲਾਂ ਬੈਕਅੱਪ ਆਪਣੇ-ਆਪ ਬਣਾਇਆ ਜਾਂਦਾ ਹੈ |

```bash
# API: ਡਾਟਾਬੇਸ ਐਕਸਪੋਰਟ ਕਰੋ
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: ਸਭ ਕੁਝ ਐਕਸਪੋਰਟ ਕਰੋ (ਪੂਰਾ ਆਰਕਾਈਵ)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: ਡਾਟਾਬੇਸ ਇੰਪੋਰਟ ਕਰੋ
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**ਇੰਪੋਰਟ ਪ੍ਰਮਾਣਿਕਤਾ:** ਇੰਪੋਰਟ ਕੀਤੀ ਫ਼ਾਈਲ ਦੀ ਅਖੰਡਤਾ (SQLite pragma ਜਾਂਚ), ਲੋੜੀਂਦੀਆਂ ਟੇਬਲਾਂ (`provider_connections`, `provider_nodes`, `combos`, `api_keys`) ਅਤੇ ਆਕਾਰ (ਵੱਧ ਤੋਂ ਵੱਧ 100MB) ਦੀ ਜਾਂਚ ਕੀਤੀ ਜਾਂਦੀ ਹੈ।

**ਵਰਤੋਂ ਦੇ ਮਾਮਲੇ:**

- OmniRoute ਨੂੰ ਮਸ਼ੀਨਾਂ ਵਿਚਕਾਰ ਮਾਈਗਰੇਟ ਕਰੋ
- ਆਫ਼ਤ ਤੋਂ ਬਹਾਲੀ ਲਈ ਬਾਹਰੀ ਬੈਕਅੱਪ ਬਣਾਓ
- ਟੀਮ ਮੈਂਬਰਾਂ ਵਿਚਕਾਰ ਸੰਰਚਨਾਵਾਂ ਸਾਂਝੀਆਂ ਕਰੋ (ਸਭ ਕੁਝ ਐਕਸਪੋਰਟ ਕਰੋ → ਆਰਕਾਈਵ ਸਾਂਝਾ ਕਰੋ)

### ਸੈਟਿੰਗਾਂ ਡੈਸ਼ਬੋਰਡ

ਆਸਾਨ ਨੈਵੀਗੇਸ਼ਨ ਲਈ ਸੈਟਿੰਗਾਂ ਪੰਨੇ ਨੂੰ **7 ਟੈਬਾਂ** ਵਿੱਚ ਵਿਵਸਥਿਤ ਕੀਤਾ ਗਿਆ ਹੈ:

| ਟੈਬ         | ਸਮੱਗਰੀ                                                                                                                                                 |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |

| **ਦਿੱਖ**    | ਥੀਮ ਕੰਟਰੋਲ (ਹਲਕਾ/ਗੂੜ੍ਹਾ/ਸਿਸਟਮ), ਸਾਈਡਬਾਰ ਦੀ ਦਿੱਖ, Cloudflare/Tailscale/ngrok ਟਨਲ ਕਾਰਡਾਂ ਲਈ ਪੈਨਲ ਟੌਗਲ                                                    |
| **AI**      | ਸੋਚਣ ਦਾ ਬਜਟ (ਜਿਉਂ-ਦਾ-ਤਿਉਂ / ਆਪਣੇ-ਆਪ ਹਟਾਓ / ਕਸਟਮ / ਅਨੁਕੂਲ — [THINKING_BUDGET.md](./THINKING_BUDGET.md) ਵੇਖੋ), ਗਲੋਬਲ ਸਿਸਟਮ ਪ੍ਰੌਂਪਟ, ਪ੍ਰੌਂਪਟ ਕੈਸ਼ ਅੰਕੜੇ   |
| **ਸੁਰੱਖਿਆ** | ਲੌਗਇਨ/ਪਾਸਵਰਡ ਸੈਟਿੰਗਾਂ, IP ਪਹੁੰਚ ਕੰਟਰੋਲ, `/models` ਲਈ API ਪ੍ਰਮਾਣੀਕਰਨ, ਪ੍ਰਦਾਤਾ ਬਲੌਕਿੰਗ, ਪ੍ਰੌਂਪਟ-ਇੰਜੈਕਸ਼ਨ ਸੁਰੱਖਿਆ                                         |
| **ਰਾਊਟਿੰਗ** | ਗਲੋਬਲ ਰਾਊਟਿੰਗ ਰਣਨੀਤੀ (ਪਹਿਲਾਂ ਭਰੋ / ਰਾਊਂਡ ਰੌਬਿਨ / P2C / ਬੇਤਰਤੀਬ / ਸਭ ਤੋਂ ਘੱਟ ਵਰਤਿਆ / ਲਾਗਤ ਅਨੁਕੂਲਿਤ), ਵਾਇਲਡਕਾਰਡ ਮਾਡਲ ਉਪਨਾਮ, ਫ਼ਾਲਬੈਕ ਲੜੀਆਂ, ਕੌਂਬੋ ਡਿਫ਼ਾਲਟ |
| **ਲਚੀਲਾਪਣ** | ਬੇਨਤੀ ਕਤਾਰ, ਕਨੈਕਸ਼ਨ ਕੂਲਡਾਊਨ, ਪ੍ਰਦਾਤਾ ਬ੍ਰੇਕਰ ਸੰਰਚਨਾ ਅਤੇ ਕੂਲਡਾਊਨ ਦੀ ਉਡੀਕ ਕਰਨ ਦਾ ਵਿਹਾਰ                                                                    |
| **ਉੱਨਤ**    | ਗਲੋਬਲ ਪ੍ਰੌਕਸੀ ਸੰਰਚਨਾ (HTTP/SOCKS5), ਹਰ ਪ੍ਰਦਾਤਾ ਲਈ ਪ੍ਰੌਕਸੀ ਓਵਰਰਾਈਡ                                                                                      |

ਆਮ ਟੈਬ ਵਿੱਚ ਹੁਣ ਸਿਰਫ਼-ਪੜ੍ਹਨਯੋਗ ਲੌਗਿੰਗ ਅਤੇ ਕੈਸ਼ ਨੋਟਾਂ ਦੀ ਨਕਲ ਨਹੀਂ ਹੁੰਦੀ। ਡਾਟਾਬੇਸ ਰਿਟੇਨਸ਼ਨ ਅਤੇ
ਅਨੁਕੂਲਨ ਸੈਟਿੰਗਾਂ `/api/settings/database` ਰਾਹੀਂ ਸਥਾਈ ਤੌਰ 'ਤੇ ਸੰਭਾਲੀਆਂ ਜਾਂਦੀਆਂ ਹਨ; ਕੈਸ਼ ਨੂੰ ਹੱਥੀਂ ਸਾਫ਼ ਕਰਨ ਲਈ
`DELETE /api/cache` ਵਰਤਿਆ ਜਾਂਦਾ ਹੈ। ਬੇਨਤੀ ਅਤੇ ਪ੍ਰੌਕਸੀ ਲੌਗ ਕਤਾਰ ਸੀਮਾਵਾਂ ਨੂੰ
`CALL_LOGS_TABLE_MAX_ROWS` ਅਤੇ `PROXY_LOGS_TABLE_MAX_ROWS` ਦੁਆਰਾ ਨਿਯੰਤਰਿਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।

### ਲਾਗਤਾਂ ਅਤੇ ਬਜਟ ਪ੍ਰਬੰਧਨ

**ਡੈਸ਼ਬੋਰਡ → ਲਾਗਤਾਂ** ਰਾਹੀਂ ਪਹੁੰਚ ਕਰੋ।

| ਟੈਬ        | ਉਦੇਸ਼                                                                                             |
| ---------- | ------------------------------------------------------------------------------------------------- |
| **ਬਜਟ**    | ਰੋਜ਼ਾਨਾ/ਹਫ਼ਤਾਵਾਰੀ/ਮਾਸਿਕ ਬਜਟਾਂ ਅਤੇ ਰੀਅਲ-ਟਾਈਮ ਟ੍ਰੈਕਿੰਗ ਨਾਲ ਹਰ API ਕੁੰਜੀ ਲਈ ਖ਼ਰਚ ਸੀਮਾਵਾਂ ਨਿਰਧਾਰਤ ਕਰੋ |
| **ਕੀਮਤਾਂ** | ਮਾਡਲ ਕੀਮਤ ਐਂਟਰੀਆਂ ਵੇਖੋ ਅਤੇ ਸੋਧੋ — ਹਰ ਪ੍ਰਦਾਤਾ ਲਈ ਪ੍ਰਤੀ 1K ਇਨਪੁੱਟ/ਆਉਟਪੁੱਟ ਟੋਕਨਾਂ ਦੀ ਲਾਗਤ            |

```bash
# API: ਬਜਟ ਨਿਰਧਾਰਤ ਕਰੋ
curl -X POST http://localhost:20128/api/usage/budget \
  -H "Content-Type: application/json" \
  -d '{"keyId": "key-123", "limit": 50.00, "period": "monthly"}'

# API: ਮੌਜੂਦਾ ਬਜਟ ਸਥਿਤੀ ਪ੍ਰਾਪਤ ਕਰੋ
curl http://localhost:20128/api/usage/budget
```

**ਲਾਗਤ ਟ੍ਰੈਕਿੰਗ:** ਹਰ ਬੇਨਤੀ ਟੋਕਨ ਵਰਤੋਂ ਨੂੰ ਲੌਗ ਕਰਦੀ ਹੈ ਅਤੇ ਕੀਮਤ ਸਾਰਣੀ ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਲਾਗਤ ਦੀ ਗਣਨਾ ਕਰਦੀ ਹੈ। ਪ੍ਰਦਾਤਾ, ਮਾਡਲ ਅਤੇ API ਕੁੰਜੀ ਅਨੁਸਾਰ ਵੇਰਵੇ **ਡੈਸ਼ਬੋਰਡ → ਵਰਤੋਂ** ਵਿੱਚ ਵੇਖੋ।

### ਆਡੀਓ ਟ੍ਰਾਂਸਕ੍ਰਿਪਸ਼ਨ

OmniRoute, OpenAI-ਅਨੁਕੂਲ ਐਂਡਪੌਇੰਟ ਰਾਹੀਂ ਆਡੀਓ ਟ੍ਰਾਂਸਕ੍ਰਿਪਸ਼ਨ ਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈ:

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data

# curl ਨਾਲ ਉਦਾਹਰਨ
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@audio.mp3" \
  -F "model=openai/whisper-1"
```

`deepgram/nova-3` ਮੂਲ Deepgram ਰੂਟ ਹੈ ਅਤੇ ਇਸ ਲਈ Deepgram API ਕੁੰਜੀ ਦੀ ਲੋੜ ਹੈ।
ਜੇ ਸਿਰਫ਼ OpenRouter ਸੰਰਚਿਤ ਹੈ, ਤਾਂ `openrouter/deepgram/nova-3` ਵਰਤੋ।

**ਬੋਲੀ-ਤੋਂ-ਲਿਖਤ (ਟ੍ਰਾਂਸਕ੍ਰਿਪਸ਼ਨ)** ਪ੍ਰਦਾਤਾ:

- `openai/` (whisper-ਅਨੁਕੂਲ)
- `groq/` (Groq Whisper Turbo)
- `deepgram/` (Nova ਪਰਿਵਾਰ)
- `assemblyai/`
- `nvidia/` (Parakeet, Canary)
- `huggingface/` (whisper ਰੂਪ)
- `qwen/`

**ਲਿਖਤ-ਤੋਂ-ਬੋਲੀ (`POST /v1/audio/speech`)** ਪ੍ਰਦਾਤਾ:

- `openai/` (tts-1, tts-1-hd)
- `hyperbolic/`
- `deepgram/` (Aura)
- `nvidia/` (Magpie TTS)
- `elevenlabs/`
- `huggingface/`
- `inworld/`
- `cartesia/`
- `playht/`
- `kie/`
- `aws-polly/`
- `xiaomi-mimo/`
- `coqui/`, `tortoise/`
- `qwen/`

ਟ੍ਰਾਂਸਕ੍ਰਿਪਸ਼ਨ ਲਈ ਸਮਰਥਿਤ ਆਡੀਓ ਫ਼ਾਰਮੈਟ: `mp3`, `wav`, `m4a`, `flac`, `ogg`, `webm`। TTS ਆਉਟਪੁੱਟ ਫ਼ਾਰਮੈਟ ਪ੍ਰਦਾਤਾ 'ਤੇ ਨਿਰਭਰ ਕਰਦੇ ਹਨ (mp3, wav, opus, pcm, mulaw)।

### ਕੌਂਬੋ ਸੰਤੁਲਨ ਰਣਨੀਤੀਆਂ

ਹਰ ਕੌਂਬੋ ਲਈ ਸੰਤੁਲਨ ਨੂੰ **ਡੈਸ਼ਬੋਰਡ → ਕੌਂਬੋ → ਬਣਾਓ/ਸੋਧੋ → ਰਣਨੀਤੀ** ਵਿੱਚ ਸੰਰਚਿਤ ਕਰੋ।

| ਰਣਨੀਤੀ               | ਵੇਰਵਾ                                                                        |
| -------------------- | ---------------------------------------------------------------------------- |
| **ਰਾਊਂਡ-ਰੌਬਿਨ**      | ਮਾਡਲਾਂ ਨੂੰ ਕ੍ਰਮਵਾਰ ਬਦਲਦਾ ਰਹਿੰਦਾ ਹੈ                                           |
| **ਤਰਜੀਹ**            | ਹਮੇਸ਼ਾ ਪਹਿਲੇ ਮਾਡਲ ਨੂੰ ਅਜ਼ਮਾਉਂਦਾ ਹੈ; ਸਿਰਫ਼ ਗਲਤੀ ਹੋਣ 'ਤੇ ਹੀ ਫਾਲਬੈਕ ਕਰਦਾ ਹੈ     |
| **ਬੇਤਰਤੀਬ**          | ਹਰ ਬੇਨਤੀ ਲਈ ਕੌਂਬੋ ਵਿੱਚੋਂ ਇੱਕ ਬੇਤਰਤੀਬ ਮਾਡਲ ਚੁਣਦਾ ਹੈ                           |
| **ਭਾਰਿਤ**            | ਹਰੇਕ ਮਾਡਲ ਲਈ ਨਿਰਧਾਰਤ ਭਾਰਾਂ ਦੇ ਆਧਾਰ 'ਤੇ ਅਨੁਪਾਤਕ ਤੌਰ 'ਤੇ ਰੂਟ ਕਰਦਾ ਹੈ           |
| **ਸਭ ਤੋਂ ਘੱਟ ਵਰਤਿਆ** | ਸਭ ਤੋਂ ਘੱਟ ਹਾਲੀਆ ਬੇਨਤੀਆਂ ਵਾਲੇ ਮਾਡਲ ਵੱਲ ਰੂਟ ਕਰਦਾ ਹੈ (ਕੌਂਬੋ ਮੈਟ੍ਰਿਕਸ ਵਰਤਦਾ ਹੈ) |
| **ਲਾਗਤ-ਅਨੁਕੂਲਿਤ**    | ਸਭ ਤੋਂ ਸਸਤੇ ਉਪਲਬਧ ਮਾਡਲ ਵੱਲ ਰੂਟ ਕਰਦਾ ਹੈ (ਕੀਮਤ ਸਾਰਣੀ ਵਰਤਦਾ ਹੈ)                 |

ਗਲੋਬਲ ਕੌਂਬੋ ਡਿਫਾਲਟ **ਡੈਸ਼ਬੋਰਡ → ਸੈਟਿੰਗਾਂ → ਰੂਟਿੰਗ → ਕੌਂਬੋ ਡਿਫਾਲਟ** ਵਿੱਚ ਸੈੱਟ ਕੀਤੇ ਜਾ ਸਕਦੇ ਹਨ।
ਕੌਂਬੋ ਟਾਰਗੇਟ ਟਾਈਮਆਉਟ ਮੂਲ ਰੂਪ ਵਿੱਚ ਮੌਜੂਦਾ ਬੇਨਤੀ ਟਾਈਮਆਉਟ ਨੂੰ ਵਿਰਾਸਤ ਵਿੱਚ ਲੈਂਦੇ ਹਨ। ਕੌਂਬੋ ਡਿਫਾਲਟਾਂ ਜਾਂ ਕਿਸੇ ਵਿਅਕਤੀਗਤ ਕੌਂਬੋ 'ਤੇ **ਟਾਰਗੇਟ ਟਾਈਮਆਉਟ
(ਸਕਿੰਟ)** ਦੀ ਵਰਤੋਂ ਸਿਰਫ਼ ਉਦੋਂ ਕਰੋ ਜਦੋਂ ਪ੍ਰਤੀ-ਟਾਰਗੇਟ ਛੋਟੀ ਸੀਮਾ ਨਾਲ
ਤੇਜ਼ ਫਾਲਬੈਕ ਟ੍ਰਿਗਰ ਕਰਨਾ ਹੋਵੇ।

ਜ਼ੀਰੋ-ਲੇਟੈਂਸੀ ਕੌਂਬੋ ਅਨੁਕੂਲਨ ਚੋਣਵਾਂ ਹਨ। ਇਨ੍ਹਾਂ ਲੇਟੈਂਸੀ ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ ਨੂੰ ਫਾਲਬੈਕ ਟਾਰਗੇਟਾਂ ਨਾਲ ਮੁਕਾਬਲਾ ਕਰਨ, TTFT
ਇਤਿਹਾਸ ਦੇ ਆਧਾਰ 'ਤੇ ਟਾਰਗੇਟਾਂ ਨੂੰ ਛੱਡਣ, ਜਾਂ ਫਾਲਬੈਕ ਬੇਨਤੀਆਂ ਨੂੰ ਸੰਕੁਚਿਤ ਕਰਨ ਤੋਂ ਰੋਕਣ ਲਈ **ਜ਼ੀਰੋ-ਲੇਟੈਂਸੀ ਅਨੁਕੂਲਨ** ਨੂੰ ਅਸਮਰੱਥ ਛੱਡੋ; ਇਸਨੂੰ ਸਮਰੱਥ ਕਰਨ ਨਾਲ ਸੰਰਚਿਤ ਹੈਜਿੰਗ, ਪੂਰਵ-ਅਨੁਮਾਨਿਤ TTFT
ਸਕਿੱਪ ਅਤੇ ਸਰਗਰਮ ਫਾਲਬੈਕ ਸੰਕੁਚਨ ਨੂੰ ਘੱਟ ਟੇਲ
ਲੇਟੈਂਸੀ ਦੇ ਬਦਲੇ ਰੂਟਿੰਗ/ਬੇਨਤੀ ਦੀ ਯਥਾਰਥਤਾ ਨਾਲ ਸਮਝੌਤਾ ਕਰਨ ਦੀ ਆਗਿਆ ਮਿਲਦੀ ਹੈ।

ਜਦੋਂ ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰਦਾਤਿਆਂ ਨੂੰ ਸਖ਼ਤ
`max_tokens` / `maxOutputTokens` ਸੀਮਾਵਾਂ ਦੀ ਲੋੜ ਹੋਵੇ ਤਾਂ **ਰੀਜ਼ਨਿੰਗ ਟੋਕਨ ਬਫ਼ਰ** ਨੂੰ ਅਸਮਰੱਥ ਕਰੋ। ਸਮਰੱਥ ਹੋਣ 'ਤੇ, ਕੌਂਬੋ ਰੂਟਿੰਗ ਸਿਰਫ਼ ਜਾਣੀ-ਪਛਾਣੀ ਆਉਟਪੁੱਟ ਸੀਮਾ ਵਾਲੇ ਮਾਡਲਾਂ ਲਈ ਰੀਜ਼ਨਿੰਗ-ਮਾਡਲ
ਵਾਧੂ ਗੁੰਜਾਇਸ਼ ਜੋੜਦੀ ਹੈ ਅਤੇ ਜਦੋਂ ਸੁਰੱਖਿਅਤ ਬਫ਼ਰ ਕੀਤਾ ਮੁੱਲ ਉਸ ਸੀਮਾ ਤੋਂ ਵੱਧ ਜਾਂਦਾ ਹੋਵੇ ਤਾਂ ਕਲਾਇੰਟ ਟੋਕਨ ਸੀਮਾ ਨੂੰ ਬਦਲੇ ਬਿਨਾਂ ਛੱਡ ਦਿੰਦੀ ਹੈ। ਜੇ ਕਲਾਇੰਟ ਸੀਮਾ ਪਹਿਲਾਂ ਹੀ ਕਿਸੇ ਜਾਣੀ-ਪਛਾਣੀ ਸੀਮਾ ਤੋਂ ਵੱਧ ਹੈ,
ਤਾਂ OmniRoute ਅੱਪਸਟ੍ਰੀਮ ਬੇਨਤੀ ਭੇਜਣ ਤੋਂ ਪਹਿਲਾਂ ਇਸਨੂੰ ਘਟਾ ਕੇ ਉਸ ਸੀਮਾ ਤੱਕ ਕਰ ਦਿੰਦਾ ਹੈ।

## 🤖 ਆਟੋ-ਰਾਊਟਿੰਗ (ਜ਼ੀਰੋ-ਕਨਫਿਗ)

OmniRoute ਇੱਕ **ਸਕੋਰ-ਅਧਾਰਿਤ ਆਟੋ-ਰਾਊਟਰ** ਨਾਲ ਆਉਂਦਾ ਹੈ, ਜੋ ਹਰੇਕ ਕਨੈਕਟ ਕੀਤੇ ਪ੍ਰਦਾਤਾ ਵਿੱਚੋਂ ਹਰ ਬੇਨਤੀ ਲਈ ਸਭ ਤੋਂ ਵਧੀਆ ਮਾਡਲ ਚੁਣਦਾ ਹੈ — ਸੰਭਾਲਣ ਲਈ ਕੋਈ ਕੌਂਬੋ ਨਹੀਂ। ਸਿਰਫ਼ `auto/*` ਪ੍ਰੀਫਿਕਸਾਂ ਵਿੱਚੋਂ ਕਿਸੇ ਇੱਕ ਨਾਲ ਬੇਨਤੀ ਭੇਜੋ ਅਤੇ OmniRoute ਤੁਰੰਤ ਇੱਕ ਵਰਚੁਅਲ ਕੌਂਬੋ ਤਿਆਰ ਕਰੇਗਾ, ਜੋ ਲੇਟੈਂਸੀ, ਲਾਗਤ, ਸਫਲਤਾ ਦਰ, ਕਾਂਟੈਕਸਟ ਅਨੁਕੂਲਤਾ, ਕੰਮ ਲਈ ਮਾਡਲ ਦੀ ਯੋਗਤਾ, ਹਾਲੀਆ ਅਸਫਲਤਾਵਾਂ, ਕੋਟਾ ਅਤੇ ਸਰਕਿਟ-ਬ੍ਰੇਕਰ ਸਥਿਤੀ ਦੇ ਆਧਾਰ 'ਤੇ ਉਮੀਦਵਾਰਾਂ ਨੂੰ ਸਕੋਰ ਕਰੇਗਾ।

| ਪ੍ਰੀਫਿਕਸ       | ਕਿਸ ਲਈ ਅਨੁਕੂਲਿਤ ਕਰਦਾ ਹੈ                                                                      |
| -------------- | -------------------------------------------------------------------------------------------- |
| `auto`         | ਸੰਤੁਲਿਤ ਡਿਫਾਲਟ (ਲੇਟੈਂਸੀ × ਲਾਗਤ × ਸਫਲਤਾ ਦਰ)                                                   |
| `auto/coding`  | ਕੋਡਿੰਗ ਕੰਮ: Claude, GPT-5, GLM, Kimi, Qwen Coder, DeepSeek ਕੋਡਰਾਂ ਨੂੰ ਤਰਜੀਹ ਦਿੰਦਾ ਹੈ         |
| `auto/cheap`   | ਸਭ ਤੋਂ ਘੱਟ $/token, ਵੱਧ ਲੇਟੈਂਸੀ ਸਵੀਕਾਰ ਕਰਦਾ ਹੈ                                               |
| `auto/fast`    | ਸਭ ਤੋਂ ਘੱਟ ਲੇਟੈਂਸੀ, ਲਾਗਤ ਨੂੰ ਨਜ਼ਰਅੰਦਾਜ਼ ਕਰਦਾ ਹੈ                                              |
| `auto/offline` | ਸਿਰਫ਼ ਸਥਾਨਕ ਪ੍ਰਦਾਤਾ (Ollama, vLLM, llama.cpp) — ਏਅਰ-ਗੈਪਡ ਸੈੱਟਅੱਪਾਂ ਲਈ ਲਾਭਦਾਇਕ                |
| `auto/smart`   | ਤਰਕ ਦੀ ਗੁਣਵੱਤਾ ਪਹਿਲਾਂ (Opus, GPT-5 xhigh, R1, GLM 5.1 reasoning)                             |
| `auto/lkgp`    | "ਆਖਰੀ ਜਾਣਿਆ ਚੰਗਾ ਪ੍ਰਦਾਤਾ" — ਆਖਰੀ ਸਫਲ ਪ੍ਰਦਾਤਾ ਨਾਲ ਪਿੰਨ ਕਰਦਾ ਹੈ, ਫਿਰ ਨਿਯਮਾਂ 'ਤੇ ਫਾਲਬੈਕ ਕਰਦਾ ਹੈ |

ਉਦਾਹਰਨ:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Refactor this Python function" }],
    "stream": true
  }'
```

ਆਟੋ-ਰਾਊਟਰ ਦਾ ਪੂਰਾ ਵੇਰਵਾ [AUTO-COMBO.md](../routing/AUTO-COMBO.md) ਵਿੱਚ ਦਿੱਤਾ ਗਿਆ ਹੈ — ਇਸ ਵਿੱਚ ਸਕੋਰਿੰਗ ਵੇਟਾਂ ਨੂੰ ਕਿਵੇਂ ਟਿਊਨ ਕਰਨਾ ਹੈ, ਪ੍ਰਦਾਤਾਵਾਂ ਨੂੰ ਬਲੈਕਲਿਸਟ ਕਿਵੇਂ ਕਰਨਾ ਹੈ ਅਤੇ **Dashboard → Auto Combo** ਵਿੱਚ ਰਾਊਟਿੰਗ ਫੈਸਲਿਆਂ ਦੀ ਜਾਂਚ ਕਿਵੇਂ ਕਰਨੀ ਹੈ, ਸ਼ਾਮਲ ਹੈ।

## 🔌 MCP ਅਤੇ A2A ਇੰਟੀਗ੍ਰੇਸ਼ਨ

OmniRoute ਇੱਕ **MCP ਸਰਵਰ** (Model Context Protocol) ਅਤੇ ਇੱਕ **A2A ਸਰਵਰ** (Agent-to-Agent JSON-RPC 2.0) ਦੋਵੇਂ ਹੈ। ਕੋਈ ਵੀ MCP-ਅਨੁਕੂਲ IDE ਜਾਂ ਏਜੰਟ ਹੋਸਟ OmniRoute ਟੂਲਾਂ ਨੂੰ ਸਿੱਧਾ ਕਾਲ ਕਰ ਸਕਦਾ ਹੈ — ਕਿਸੇ ਵਾਧੂ ਰੈਪਰ ਦੀ ਲੋੜ ਨਹੀਂ।

### MCP ਟ੍ਰਾਂਸਪੋਰਟ

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **ਸਟ੍ਰੀਮੇਬਲ HTTP**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (ਉਨ੍ਹਾਂ IDE ਪਲੱਗਇਨਾਂ ਲਈ ਜੋ stdio ਨੂੰ ਤਰਜੀਹ ਦਿੰਦੇ ਹਨ)

### Claude Desktop ਨੂੰ ਕਨੈਕਟ ਕਰੋ

`~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) ਜਾਂ Windows/Linux ਉੱਤੇ ਇਸਦੇ ਬਰਾਬਰ ਦੀ ਫ਼ਾਈਲ ਨੂੰ ਸੰਪਾਦਿਤ ਕਰੋ:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Cursor / Continue / VS Code MCP ਨੂੰ ਕਨੈਕਟ ਕਰੋ

SSE URL `http://localhost:20128/api/mcp/sse` ਅਤੇ **Dashboard → API Keys** ਵਿੱਚ ਬਣਾਈ ਗਈ ਇੱਕ Bearer API ਕੁੰਜੀ ਵਰਤੋ।

### ਸਕੋਪ

MCP ਇਸ ਵੇਲੇ 32 ਨਾਮਿਤ ਸਕੋਪ ਪਰਿਭਾਸ਼ਿਤ ਕਰਦਾ ਹੈ। ਹਰੇਕ Bearer ਕੁੰਜੀ ਨੂੰ ਖਾਸ ਸਕੋਪਾਂ ਤੱਕ ਸੀਮਿਤ ਕੀਤਾ ਜਾ ਸਕਦਾ ਹੈ — ਅਧਿਕਾਰਤ ਸਕੋਪ ਅਤੇ ਟੂਲ ਸੂਚੀ ਲਈ [MCP-SERVER.md](../frameworks/MCP-SERVER.md) ਅਤੇ JSON-RPC ਸਕੀਮਾ ਲਈ [A2A-SERVER.md](../frameworks/A2A-SERVER.md) ਵੇਖੋ।

## 💾 ਮੈਮੋਰੀ ਪ੍ਰਣਾਲੀ

OmniRoute ਹਾਈਬ੍ਰਿਡ ਪ੍ਰਾਪਤੀ ਨਾਲ **ਲੰਬੇ ਸਮੇਂ ਦੀ ਗੱਲਬਾਤੀ ਮੈਮੋਰੀ** ਸੰਭਾਲਦਾ ਹੈ:

- ਪਿਛਲੀਆਂ ਗੱਲਬਾਤਾਂ ਵਿੱਚ ਕੀਵਰਡ ਖੋਜ ਲਈ **SQLite FTS5**
- ਅਰਥ-ਆਧਾਰਿਤ ਯਾਦ ਲਈ **Qdrant vector store** (ਵਿਕਲਪਿਕ)
- **ਆਟੋਮੈਟਿਕ ਤੱਥ ਕੱਢਣਾ** — ਹਰ ਸੈਸ਼ਨ ਤੋਂ ਬਾਅਦ ਇਕਾਈਆਂ, ਤਰਜੀਹਾਂ ਅਤੇ ਫ਼ੈਸਲਿਆਂ ਦਾ ਸਾਰ ਬਣਾਇਆ ਜਾਂਦਾ ਹੈ ਅਤੇ `memory_facts` ਟੇਬਲ ਵਿੱਚ ਸਟੋਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ
- ਮੈਮੋਰੀਆਂ ਨੂੰ ਪ੍ਰਤੀ API ਕੁੰਜੀ ਅਤੇ ਪ੍ਰਤੀ ਸੈਸ਼ਨ ਸਕੋਪ ਕੀਤਾ ਜਾਂਦਾ ਹੈ

**Dashboard → Memory** ਵਿੱਚ ਮੈਮੋਰੀਆਂ ਦਾ ਪ੍ਰਬੰਧਨ ਕਰੋ (ਖੋਜੋ, ਸੰਪਾਦਿਤ ਕਰੋ, ਨਿਰਯਾਤ ਕਰੋ, ਮਿਟਾਓ)। HTTP ਇੰਟਰਫੇਸ (`/api/memory/*`) ਏਜੰਟਾਂ ਨੂੰ ਪ੍ਰੋਗਰਾਮ ਰਾਹੀਂ ਤੱਥ ਭੇਜਣ ਅਤੇ ਪੁੱਛਗਿੱਛ ਕਰਨ ਦਿੰਦਾ ਹੈ — [MEMORY.md](../frameworks/MEMORY.md) ਵੇਖੋ।

## 🔔 ਵੈੱਬਹੁੱਕ

ਰੀਅਲ-ਟਾਈਮ ਨਿਗਰਾਨੀ ਅਤੇ ਆਟੋਮੇਸ਼ਨ ਲਈ OmniRoute ਇਵੈਂਟਾਂ ਦੀ ਸਬਸਕ੍ਰਿਪਸ਼ਨ ਲਓ।

- ਟਾਰਗੇਟ URL ਅਤੇ HMAC ਸਾਈਨਿੰਗ ਸੀਕ੍ਰੇਟ ਨਾਲ **Dashboard → Webhooks** ਵਿੱਚ ਇੱਕ ਵੈੱਬਹੁੱਕ ਬਣਾਓ
- ਉਪਲਬਧ ਇਵੈਂਟ: `request.completed`, `request.failed`, `provider.unavailable`, `budget.exceeded`, `combo.switched`, `circuit_breaker.opened`, `circuit_breaker.closed`
- ਤਸਦੀਕ ਲਈ ਹਰੇਕ ਪੇਲੋਡ ਵਿੱਚ `X-OmniRoute-Signature` (HMAC-SHA256) ਸ਼ਾਮਲ ਹੁੰਦਾ ਹੈ
- ਮੁੜ ਕੋਸ਼ਿਸ਼ਾਂ: ਐਕਸਪੋਨੇਨਸ਼ੀਅਲ ਬੈਕਆਫ਼ ਨਾਲ 3 ਕੋਸ਼ਿਸ਼ਾਂ, ਫਿਰ ਡੈੱਡ-ਲੈਟਰ ਕਤਾਰ

ਪੂਰੀ ਸਕੀਮਾ [WEBHOOKS.md](../frameworks/WEBHOOKS.md) ਵਿੱਚ ਹੈ।

## 🛠️ ਪ੍ਰੋਗਰਾਮ ਰਾਹੀਂ ਪ੍ਰਬੰਧਨ

ਤੁਸੀਂ **`manage` ਸਕੋਪ ਵਾਲੀ Bearer ਕੁੰਜੀ** ਦੀ ਵਰਤੋਂ ਕਰਕੇ HTTP ਰਾਹੀਂ ਹਰੇਕ OmniRoute ਸਰੋਤ (ਪ੍ਰਦਾਤਾ, ਕੰਬੋ, ਕੁੰਜੀਆਂ, ਸੈਟਿੰਗਾਂ) ਦਾ ਪ੍ਰਬੰਧਨ ਕਰ ਸਕਦੇ ਹੋ।

**Dashboard → API Keys → New Key → Scope: manage** ਵਿੱਚ ਕੁੰਜੀ ਬਣਾਓ, ਫਿਰ:

```bash
# ਪ੍ਰਦਾਤਾਵਾਂ ਦੀ ਸੂਚੀ ਦਿਖਾਓ
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# ਪ੍ਰਦਾਤਾ ਕਨੈਕਸ਼ਨ ਜੋੜੋ
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# ਕੰਬੋ ਬਣਾਓ
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# API ਕੁੰਜੀਆਂ ਦੀ ਸੂਚੀ ਦਿਖਾਓ/ਬਣਾਓ
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

ਪੂਰੇ ਐਂਡਪੌਇੰਟ ਕੈਟਾਲੌਗ ਅਤੇ ਬੇਨਤੀ/ਜਵਾਬ ਸਕੀਮਾਵਾਂ ਲਈ [API_REFERENCE.md](../reference/API_REFERENCE.md) ਵੇਖੋ।

## 💻 ਅੰਦਰੂਨੀ CLI

OmniRoute ਸੈੱਟਅੱਪ, ਡਾਇਗਨੌਸਟਿਕਸ ਅਤੇ ਰਨਟਾਈਮ ਕੰਟਰੋਲ ਲਈ ਇੱਕ ਅੰਦਰੂਨੀ CLI (`omniroute …`) ਨਾਲ ਆਉਂਦਾ ਹੈ। ਇਹ **ਡੈਸ਼ਬੋਰਡ ਵਿਚਲੇ "CLI ਟੂਲਜ਼" ਪੰਨੇ ਤੋਂ ਵੱਖਰਾ ਹੈ**, ਜੋ ਤੀਜੀ-ਧਿਰ ਦੇ CLIs (Claude Code, Cursor, Codex, Cline, …) ਨੂੰ ਕੌਂਫਿਗਰ ਕਰਦਾ ਹੈ ਤਾਂ ਜੋ ਉਹ OmniRoute ਨਾਲ ਸੰਚਾਰ ਕਰ ਸਕਣ।

```bash
omniroute setup                    # ਇੰਟਰਐਕਟਿਵ ਵਿਜ਼ਾਰਡ (ਪਾਸਵਰਡ, ਪ੍ਰਦਾਤਾ, ਕਾਂਬੋ)
omniroute setup --non-interactive  # CI-ਅਨੁਕੂਲ
omniroute doctor                   # ਸਿਹਤ ਡਾਇਗਨੌਸਟਿਕਸ (ਡਾਟਾ ਡਾਇਰੈਕਟਰੀ, DB, ਪ੍ਰਦਾਤਾ, ਪੋਰਟ)
omniroute providers available      # ਸਮਰਥਿਤ ਪ੍ਰਦਾਤਾਵਾਂ ਦੀ ਸੂਚੀ
omniroute providers list           # ਕੌਂਫਿਗਰ ਕੀਤੇ ਕਨੈਕਸ਼ਨਾਂ ਦੀ ਸੂਚੀ
omniroute providers test <id>      # ਕਿਸੇ ਪ੍ਰਦਾਤਾ ਕਨੈਕਸ਼ਨ ਦੀ ਲਾਈਵ ਜਾਂਚ
omniroute combos list              # ਕਾਂਬੋਆਂ ਦੀ ਸੂਚੀ
omniroute combos switch <name>     # ਡਿਫਾਲਟ ਕਾਂਬੋ ਸੈੱਟ ਕਰੋ
omniroute models                   # ਉਪਲਬਧ ਮਾਡਲਾਂ ਦੀ ਸੂਚੀ (--json, --search)
omniroute keys add | list | remove # ਟਰਮੀਨਲ ਤੋਂ API ਕੁੰਜੀਆਂ ਦਾ ਪ੍ਰਬੰਧਨ ਕਰੋ
omniroute backup                   # ਕੌਂਫਿਗ + DB ਦਾ ਸਨੈਪਸ਼ਾਟ
omniroute restore [<timestamp>]    # ਸਨੈਪਸ਼ਾਟ ਤੋਂ ਰੀਸਟੋਰ ਕਰੋ
omniroute health                   # ਵਿਸਤ੍ਰਿਤ ਸਿਹਤ ਜਾਣਕਾਰੀ (ਬ੍ਰੇਕਰ, ਕੈਸ਼, ਮੈਮੋਰੀ)
omniroute quota                    # ਪ੍ਰਦਾਤਾ ਕੋਟੇ ਦੀ ਵਰਤੋਂ
omniroute mcp status               # MCP ਸਰਵਰ ਦੀ ਸਥਿਤੀ
omniroute a2a status               # A2A ਸਰਵਰ ਦੀ ਸਥਿਤੀ
omniroute tunnel list|create|stop  # Cloudflare/Tailscale/ngrok ਟਨਲਾਂ
omniroute reset-password           # ਐਡਮਿਨ ਪਾਸਵਰਡ ਰੀਸੈੱਟ ਕਰੋ
omniroute --mcp                    # stdio ਉੱਤੇ MCP ਸਰਵਰ ਸ਼ੁਰੂ ਕਰੋ
omniroute --port 3000              # ਸਰਵਰ ਨੂੰ ਕਸਟਮ ਪੋਰਟ ਉੱਤੇ ਸ਼ੁਰੂ ਕਰੋ
```

ਸੁਝਾਅ: ਅਸਿਹਤਮੰਦ ਪ੍ਰਦਾਤਾ ਕਨੈਕਸ਼ਨਾਂ ਬਾਰੇ ਚੇਤਾਵਨੀਆਂ ਪ੍ਰਾਪਤ ਕਰਨ ਲਈ `omniroute doctor --json` ਨੂੰ ਆਪਣੇ ਮਾਨੀਟਰਿੰਗ ਟੂਲ ਨਾਲ ਜੋੜੋ।
