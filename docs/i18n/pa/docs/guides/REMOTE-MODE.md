ਆਪਣੇ ਲੈਪਟਾਪ ਉੱਤੇ `omniroute` CLI ਚਲਾਓ, ਜਦੋਂ ਕਿ OmniRoute ਖੁਦ ਕਿਸੇ ਹੋਰ ਥਾਂ ਚੱਲ ਰਿਹਾ ਹੋਵੇ
(ਇੱਕ VPS, ਘਰੇਲੂ ਸਰਵਰ, ਜਾਂ ਤੁਹਾਡੇ Tailnet ਉੱਤੇ ਕੋਈ ਹੋਰ ਮਸ਼ੀਨ)। ਤੁਸੀਂ ਇੱਕ ਵਾਰ
`omniroute connect` ਨਾਲ ਲੌਗ ਇਨ ਕਰਦੇ ਹੋ, ਅਤੇ ਉਸ ਤੋਂ ਬਾਅਦ **ਹਰੇਕ** CLI ਕਮਾਂਡ ਉਸ ਰਿਮੋਟ
ਸਰਵਰ ਨੂੰ ਨਿਸ਼ਾਨਾ ਬਣਾਉਂਦੀ ਹੈ — ਉਹੀ ਕਮਾਂਡਾਂ, ਉਹੀ ਆਉਟਪੁੱਟ, ਬਸ ਰਿਮੋਟ ਉੱਤੇ ਚਲਾਈਆਂ ਜਾਂਦੀਆਂ ਹਨ।

ਇੰਸਟਾਲ ਕਰਨ ਲਈ ਕੋਈ ਦੂਜਾ ਟੂਲ ਨਹੀਂ ਹੈ: ਰਿਮੋਟ ਮੋਡ ਨਿਯਮਤ `omniroute` CLI
ਦੇ ਨਾਲ ਸਕੋਪ ਵਾਲੇ **ਐਕਸੈੱਸ ਟੋਕਨ** ਵਰਤਦਾ ਹੈ।

```bash
npm install -g omniroute                 # ਆਮ CLI
omniroute connect 192.168.0.15           # ਲੌਗ ਇਨ ਕਰੋ (ਪਾਸਵਰਡ → ਸਕੋਪ ਵਾਲਾ ਟੋਕਨ)
omniroute models list                    # ← ਹੁਣ ਰਿਮੋਟ ਸਰਵਰ ਦੇ ਮਾਡਲਾਂ ਦੀ ਸੂਚੀ ਦਿਖਾਉਂਦਾ ਹੈ
omniroute configure codex                # ← ਰਿਮੋਟ ਕੈਟਾਲੌਗ ਤੋਂ ਸਥਾਨਕ Codex ਪ੍ਰੋਫ਼ਾਈਲ ਲਿਖਦਾ ਹੈ
```

## ਇਹ ਕਿਵੇਂ ਕੰਮ ਕਰਦਾ ਹੈ

```
ਤੁਹਾਡਾ ਲੈਪਟਾਪ                          ਰਿਮੋਟ OmniRoute (VPS)
┌────────────────────┐                   ┌───────────────────────────────┐
│ omniroute CLI      │  POST /api/cli/connect  (ਪਾਸਵਰਡ → ਟੋਕਨ)            │
│  ਸੰਦਰਭ: vps       │ ───────────────►  │ ਸਕੋਪ ਵਾਲਾ ਐਕਸੈੱਸ ਟੋਕਨ ਬਣਾਉਂਦਾ ਹੈ │
│  baseUrl, token    │  Authorization: Bearer oma_live_…                  │
│                    │ ───────────────►  │ ਹਰ ਪ੍ਰਬੰਧਨ ਰੂਟ, ਟੋਕਨ ਦੇ ਸਕੋਪ     │
│ ਸੰਰਚਨਾਵਾਂ ਨੂੰ      │ ◄───────────────  │ ਅਨੁਸਾਰ ਜਾਂਚਿਆ ਜਾਂਦਾ ਹੈ           │
│ ਸਥਾਨਕ ਤੌਰ 'ਤੇ ਲਿਖਦਾ ਹੈ │              └───────────────────────────────┘
└────────────────────┘
```

- **ਸੰਦਰਭ** ਹਰੇਕ ਵਿੱਚ ਇੱਕ ਸਰਵਰ ਸਟੋਰ ਕਰਦੇ ਹਨ (`~/.omniroute/config.json`, `chmod 600`)।
  `omniroute contexts use <name>` ਸਰਗਰਮ ਸਰਵਰ ਬਦਲਦਾ ਹੈ; `default` ਸਥਾਨਕ ਹੁੰਦਾ ਹੈ।
- **ਐਕਸੈੱਸ ਟੋਕਨ** (`oma_live_…`) ਪ੍ਰਬੰਧਨ ਕਮਾਂਡਾਂ ਨੂੰ ਅਧਿਕਾਰਤ ਕਰਦੇ ਹਨ। ਇਹ
  ਇਨਫਰੈਂਸ API ਕੁੰਜੀਆਂ (`sk-…`, ਜੋ `/v1/chat/completions` ਲਈ ਵਰਤੀਆਂ ਜਾਂਦੀਆਂ ਹਨ) ਤੋਂ ਵੱਖਰੇ ਹਨ।
- ਟੋਕਨ ਦਾ ਸਿਰਫ਼ SHA-256 ਹੈਸ਼ ਹੀ ਸਰਵਰ ਪਾਸੇ ਸਟੋਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। ਸਾਦਾ ਟੈਕਸਟ
  ਬਣਾਉਣ ਵੇਲੇ **ਸਿਰਫ਼ ਇੱਕ ਵਾਰ** ਦਿਖਾਇਆ ਜਾਂਦਾ ਹੈ।

## ਕਨੈਕਟ ਕਰਨਾ

### ਪ੍ਰਬੰਧਨ ਪਾਸਵਰਡ ਨਾਲ (ਬੂਟਸਟਰੈਪ)

```bash
omniroute connect 192.168.0.15
# http://192.168.0.15:20128 ਲਈ ਪ੍ਰਬੰਧਨ ਪਾਸਵਰਡ: ********
# ✔ http://192.168.0.15:20128 ਨਾਲ ਕਨੈਕਟ ਹੋਇਆ — ਸੰਦਰਭ '192.168.0.15' (ਸਕੋਪ: admin)
```

ਪਾਸਵਰਡ ਪ੍ਰਵਾਹ ਮੂਲ ਰੂਪ ਵਿੱਚ ਇੱਕ **admin** ਟੋਕਨ ਬਣਾਉਂਦਾ ਹੈ (ਪਾਸਵਰਡ ਤੁਹਾਡੇ ਕੋਲ ਹੈ, ਇਸ ਲਈ
ਤੁਹਾਡੇ ਕੋਲ ਪਹਿਲਾਂ ਹੀ ਪੂਰਾ ਕੰਟਰੋਲ ਹੈ)। `--scope` ਨਾਲ ਸਕੋਪ ਘਟਾਓ:

```bash
omniroute connect 192.168.0.15 --scope write
```

ਵਿਕਲਪ: `--port <p>` (ਜਦੋਂ ਹੋਸਟ ਵਿੱਚ ਪੋਰਟ ਨਾ ਹੋਵੇ), `--name <ctx>` (ਸੰਦਰਭ ਦਾ ਨਾਮ),
`--scope read|write|admin`। ਪੂਰਾ URL ਜਿਵੇਂ ਦਿੱਤਾ ਗਿਆ ਹੈ, ਉਸੇ ਤਰ੍ਹਾਂ ਵਰਤਿਆ ਜਾਂਦਾ ਹੈ:
`omniroute connect https://omni.example.com`।

### ਪਹਿਲਾਂ ਤੋਂ ਬਣਾਏ ਟੋਕਨ ਨਾਲ

ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ (ਜਾਂ `omniroute tokens create` ਨਾਲ) ਸਕੋਪ ਵਾਲਾ ਟੋਕਨ ਬਣਾਓ ਅਤੇ
ਇਸਨੂੰ ਪੇਸਟ ਕਰੋ — ਪਾਸਵਰਡ ਦੀ ਲੋੜ ਨਹੀਂ:

```bash
omniroute connect 192.168.0.15 --key oma_live_xxxxxxxx
```

CLI ਇਸਨੂੰ `GET /api/cli/whoami` ਰਾਹੀਂ ਪ੍ਰਮਾਣਿਤ ਕਰਦਾ ਹੈ ਅਤੇ ਸਰਗਰਮ ਸੰਦਰਭ ਵਜੋਂ ਸੰਭਾਲਦਾ ਹੈ।

## ਸਕੋਪ

ਤਿੰਨ ਪੱਧਰ, ਲੜੀਵਾਰ (`admin ⊃ write ⊃ read`):

| ਸਕੋਪ    | ਕੀ ਕਰ ਸਕਦਾ ਹੈ                                                                 |
| ------- | ----------------------------------------------------------------------------- |
| `read`  | ਸੂਚੀ/ਜਾਂਚ — `models list`, `providers status`, `logs`, `usage`, `cost`        |
| `write` | read **+** ਸੰਰਚਨਾ/ਲਾਗੂ ਕਰਨਾ — `setup-codex`, `keys add`, `config set`, combos |
| `admin` | write **+** ਪ੍ਰਬੰਧਨ — `tokens` CRUD, ਪ੍ਰਦਾਤਾ ਜੋੜਨਾ, ਸੇਵਾਵਾਂ, ਨੀਤੀ, oauth      |

ਸਰਵਰ HTTP ਵਿਧੀ ਤੋਂ ਹਰੇਕ ਰੂਟ ਲਈ ਲੋੜੀਂਦਾ ਸਕੋਪ ਨਿਰਧਾਰਤ ਕਰਦਾ ਹੈ
(`GET`→read, ਤਬਦੀਲੀਆਂ→write), ਅਤੇ ਸੰਵੇਦਨਸ਼ੀਲ ਸਤਹਾਂ ਲਈ ਇੱਕ admin ਆਗਿਆ-ਸੂਚੀ ਵੀ ਵਰਤਦਾ ਹੈ
(`/api/cli/tokens`, `/api/providers` ਤਬਦੀਲੀਆਂ, `/api/oauth`, `/api/services`, …)।
ਨਾਕਾਫ਼ੀ ਸਕੋਪ ਵਾਲੇ ਟੋਕਨ ਨੂੰ ਸਪਸ਼ਟ ਸੁਨੇਹੇ ਨਾਲ `403` ਮਿਲਦਾ ਹੈ।

> ਪ੍ਰਕਿਰਿਆਵਾਂ ਸ਼ੁਰੂ ਕਰਨ ਵਾਲੇ ਰੂਟ (`/api/services/*`, `/api/mcp/*`, …)
> **ਸਿਰਫ਼ loopback** ਰਹਿੰਦੇ ਹਨ — ਸਕੋਪ ਭਾਵੇਂ ਕੋਈ ਵੀ ਹੋਵੇ, ਰਿਮੋਟ ਟੋਕਨ ਕਦੇ ਵੀ ਉਨ੍ਹਾਂ ਤੱਕ ਨਹੀਂ ਪਹੁੰਚ ਸਕਦਾ।

## ਰਿਮੋਟ ਇੰਸਟਾਲੇਸ਼ਨ 'ਤੇ Antigravity ਨੂੰ ਕਨੈਕਟ ਕਰਨਾ

Antigravity, Google ਦੀ firstparty/nativeapp ਸਹਿਮਤੀ ਸਕ੍ਰੀਨ ਵਰਤਦਾ ਹੈ। Google ਅਧਿਕਾਰ ਕੋਡ ਸਿਰਫ਼ ਉਦੋਂ
ਜਾਰੀ ਕਰਦਾ ਹੈ ਜਦੋਂ **ਲੂਪਬੈਕ ਰੀਡਾਇਰੈਕਟ**
(`http://127.0.0.1:<port>/callback`) ਉਸ **ਬ੍ਰਾਊਜ਼ਰ ਤੋਂ ਪਹੁੰਚਯੋਗ ਹੋਵੇ ਜੋ
ਸਾਈਨ-ਇਨ ਨੂੰ ਮਨਜ਼ੂਰੀ ਦਿੰਦਾ ਹੈ**। ਰਿਮੋਟ VPS ਇੰਸਟਾਲੇਸ਼ਨ 'ਤੇ ਉਹ ਲੂਪਬੈਕ ਤੁਹਾਡੀ
ਮਸ਼ੀਨ ਦੀ ਬਜਾਏ ਸਰਵਰ 'ਤੇ ਹੁੰਦਾ ਹੈ, ਇਸ ਲਈ ਸਹਿਮਤੀ ਸਕ੍ਰੀਨ **ਹਮੇਸ਼ਾ ਲਈ ਅਟਕ ਜਾਂਦੀ ਹੈ ਅਤੇ
ਕਦੇ ਵੀ ਕੋਡ ਜਾਰੀ ਨਹੀਂ ਕਰਦੀ** — ਆਮ "ਕਾਲਬੈਕ URL ਪੇਸਟ ਕਰੋ" ਫਾਲਬੈਕ ਕੋਲ ਪੇਸਟ ਕਰਨ ਲਈ
ਕੁਝ ਨਹੀਂ ਹੁੰਦਾ। (ਇਹ Google ਵੱਲੋਂ ਲਗਾਈ ਪਾਬੰਦੀ ਹੈ: ਇਹੀ ਸਮੱਸਿਆ bundled Antigravity
ਡੈਸਕਟਾਪ ਕਲਾਇੰਟ ਵਰਤਣ ਵਾਲੀ ਕਿਸੇ ਵੀ ਪ੍ਰੌਕਸੀ ਵਿੱਚ ਆਉਂਦੀ ਹੈ, ਸਿਰਫ਼ OmniRoute ਵਿੱਚ ਨਹੀਂ।)

ਤੁਹਾਡੇ ਅਟਕਣ ਤੋਂ ਪਹਿਲਾਂ ਹੀ ਡੈਸ਼ਬੋਰਡ ਇਸਦਾ ਪਤਾ ਲਗਾ ਲੈਂਦਾ ਹੈ: ਕਿਸੇ non-localhost ਪਤੇ ਤੋਂ **Providers → Antigravity →
Connect** ਖੋਲ੍ਹਣ 'ਤੇ ਆਮ "ਕਾਲਬੈਕ URL ਕਾਪੀ ਕਰੋ"
ਸੂਚਨਾ ਦੀ ਥਾਂ ਹੇਠਾਂ ਦਿੱਤੇ ਦੋ ਹੱਲ ਦਿਖਾਏ ਜਾਂਦੇ ਹਨ, ਜਿਨ੍ਹਾਂ ਵਿੱਚ ਤੁਹਾਡਾ ਹੋਸਟ ਅਤੇ ਪੋਰਟ ਪਹਿਲਾਂ ਹੀ ਭਰੇ ਹੁੰਦੇ ਹਨ।
(LAN ਪਤਾ ਵੀ ਇਸ ਵਿੱਚ ਆਉਂਦਾ ਹੈ — ਇਸ ਕਾਲਬੈਕ ਦੇ ਸੰਦਰਭ ਵਿੱਚ `192.168.x.x` localhost ਨਹੀਂ ਹੈ।)

ਰਿਮੋਟ OmniRoute ਨਾਲ Antigravity ਨੂੰ ਕਨੈਕਟ ਕਰਨ ਦੇ ਦੋ ਸਮਰਥਿਤ ਤਰੀਕੇ ਹਨ।

### ਵਿਕਲਪ A — ਲੋਕਲ ਲੌਗਇਨ ਹੈਲਪਰ (ਸਿਫ਼ਾਰਸ਼ੀ)

OAuth ਨੂੰ **ਆਪਣੇ ਕੰਪਿਊਟਰ 'ਤੇ** ਚਲਾਓ, ਜਿੱਥੇ `127.0.0.1` ਪਹੁੰਚਯੋਗ ਹੈ। ਹੈਲਪਰ
Google ਨਾਲ ਸਿੱਧਾ ਸੰਚਾਰ ਕਰਦਾ ਹੈ, ਇਸ ਲਈ ਸਹਿਮਤੀ ਉੱਥੇ ਪੂਰੀ ਹੋ ਜਾਂਦੀ ਹੈ ਜਿੱਥੇ ਡੈਸ਼ਬੋਰਡ ਦਾ ਵਰਜਨ
ਇਸਨੂੰ ਪੂਰਾ ਨਹੀਂ ਕਰ ਸਕਦਾ।

**ਜੇ ਤੁਸੀਂ ਪਹਿਲਾਂ ਹੀ ਕਨੈਕਟ ਹੋ** (`omniroute connect <host>`), ਤਾਂ ਕਾਪੀ ਕਰਨ ਲਈ ਕੁਝ ਨਹੀਂ ਹੈ —
ਹੈਲਪਰ ਤੁਹਾਡੇ ਲਈ ਕ੍ਰੈਡੈਂਸ਼ਲ ਉਸ ਇੰਸਟਾਲੇਸ਼ਨ ਤੱਕ ਪਹੁੰਚਾ ਦਿੰਦਾ ਹੈ:

```bash
# ਆਪਣੀ LOCAL ਮਸ਼ੀਨ 'ਤੇ (Node.js + ਇੱਕ ਬ੍ਰਾਊਜ਼ਰ ਦੀ ਲੋੜ ਹੈ):
omniroute connect 192.168.0.15        # ਇੱਕ ਵਾਰ — admin-scoped context token ਬਣਾਉਂਦਾ ਹੈ
npx omniroute login antigravity
#   ↳ Google ਸਹਿਮਤੀ ਖੋਲ੍ਹਦਾ ਹੈ, ਲੋਕਲ ਲੂਪਬੈਕ ਪੋਰਟ 'ਤੇ ਕਾਲਬੈਕ ਕੈਪਚਰ ਕਰਦਾ ਹੈ,
#     ਇਸਦਾ ਅਦਾਨ-ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ ਅਤੇ ਕ੍ਰੈਡੈਂਸ਼ਲ ਨੂੰ ਸਰਗਰਮ ਕੌਂਟੈਕਸਟ 'ਤੇ POST ਕਰਦਾ ਹੈ:
#
#   Antigravity http://192.168.0.15:20128 'ਤੇ ਕਨੈਕਟ ਹੋ ਗਿਆ (ਕਨੈਕਸ਼ਨ abc123)।
#   ਪੇਸਟ ਕਰਨ ਲਈ ਕੁਝ ਨਹੀਂ — ਤੁਸੀਂ ਇਹ ਟਰਮੀਨਲ ਬੰਦ ਕਰ ਸਕਦੇ ਹੋ।
```

ਜਦੋਂ ਵੀ ਸਰਗਰਮ ਕੌਂਟੈਕਸਟ ਕਿਸੇ ਹੋਰ
ਮਸ਼ੀਨ ਵੱਲ ਇਸ਼ਾਰਾ ਕਰਦਾ ਹੈ, ਪੁਸ਼ ਆਪਣੇ ਆਪ ਹੁੰਦਾ ਹੈ। ਇਸਨੂੰ ਕਿਸੇ ਵੀ ਤਰੀਕੇ ਨਾਲ ਮਜਬੂਰ ਕਰਨ ਲਈ `--push` / `--no-push` ਵਰਤੋ, ਜਾਂ ਕਿਸੇ ਖ਼ਾਸ
ਕੌਂਟੈਕਸਟ ਨੂੰ ਨਿਸ਼ਾਨਾ ਬਣਾਉਣ ਲਈ `--context <name>` ਵਰਤੋ।

**ਜੇ ਤੁਹਾਡੀ ਮਸ਼ੀਨ VPS ਤੱਕ ਨਹੀਂ ਪਹੁੰਚ ਸਕਦੀ** (ਫਾਇਰਵਾਲ ਲੱਗੀ ਹੋਈ, SSH ਨਹੀਂ, air-gapped ਡੈਸਕ), ਤਾਂ
ਹੈਲਪਰ ਫਿਰ ਵੀ ਕੰਮ ਕਰਦਾ ਹੈ — ਇਸਨੂੰ ਅਸਲ ਵਿੱਚ ਸਿਰਫ਼ Google ਦੀ _ਲੋੜ_ ਹੁੰਦੀ ਹੈ। `--no-push` ਵਰਤੋ, ਜਾਂ
ਪੁਸ਼ ਨੂੰ ਅਸਫਲ ਹੋਣ ਦਿਓ: ਇਹ ਤੁਹਾਡੇ ਵੱਲੋਂ ਪਹਿਲਾਂ ਹੀ ਪੂਰੀ ਕੀਤੀ ਅਧਿਕਾਰ ਪ੍ਰਕਿਰਿਆ ਨੂੰ
ਰੱਦ ਕਰਨ ਦੀ ਬਜਾਏ ਬਲੌਬ ਪ੍ਰਿੰਟ ਕਰਨ ਵੱਲ ਫਾਲਬੈਕ ਕਰਦਾ ਹੈ।

```bash
npx omniroute login antigravity --no-push
#   omniroute-cred-v1.eyJ2IjoxLCJ...
```

ਫਿਰ, **ਰਿਮੋਟ** ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ: **Providers → Antigravity → Connect**, ਅਤੇ
`omniroute-cred-v1.…` ਬਲੌਬ ਨੂੰ **Step 2** ਫੀਲਡ ਵਿੱਚ ਪੇਸਟ ਕਰੋ (ਇਹ ਕਾਲਬੈਕ URL ਜਾਂ ਕ੍ਰੈਡੈਂਸ਼ਲ ਬਲੌਬ,
ਦੋਵਾਂ ਵਿੱਚੋਂ ਕਿਸੇ ਨੂੰ ਵੀ ਸਵੀਕਾਰ ਕਰਦਾ ਹੈ)। OmniRoute ਇਸਨੂੰ ਡੀਕੋਡ ਕਰਦਾ ਹੈ, ਸਰਵਰ-ਸਾਈਡ Cloud Code
ਆਨਬੋਰਡਿੰਗ ਚਲਾਉਂਦਾ ਹੈ ਅਤੇ ਕਨੈਕਸ਼ਨ ਨੂੰ ਸਥਾਈ ਤੌਰ 'ਤੇ ਸੰਭਾਲਦਾ ਹੈ।

> ਬਲੌਬ ਵਿੱਚ refresh token ਹੁੰਦਾ ਹੈ — ਇਸਨੂੰ ਪਾਸਵਰਡ ਵਾਂਗ ਸੰਭਾਲੋ। ਪੁਸ਼ ਮਾਰਗ 'ਤੇ ਇਹ
> ਤੁਹਾਡੇ ਕੌਂਟੈਕਸਟ ਦੇ ਪ੍ਰਮਾਣਿਤ ਕਨੈਕਸ਼ਨ ਰਾਹੀਂ ਇੱਕ ਵਾਰ ਭੇਜਿਆ ਜਾਂਦਾ ਹੈ; ਪੇਸਟ ਮਾਰਗ 'ਤੇ,
> ਤੁਹਾਡੇ ਡੈਸ਼ਬੋਰਡ ਕਨੈਕਸ਼ਨ ਰਾਹੀਂ। ਦੋਵਾਂ ਹਾਲਤਾਂ ਵਿੱਚ ਇਸਨੂੰ ਸਟੋਰੇਜ ਵਿੱਚ ਇਨਕ੍ਰਿਪਟ ਕਰਕੇ ਰੱਖਿਆ ਜਾਂਦਾ ਹੈ, ਅਤੇ
> ਸਫਲ ਪੁਸ਼ ਇਸਨੂੰ ਕਦੇ ਵੀ ਤੁਹਾਡੇ ਟਰਮੀਨਲ ਵਿੱਚ ਪ੍ਰਿੰਟ ਨਹੀਂ ਕਰਦਾ।

ਫਲੈਗ: `--no-browser` (ਆਪਣੇ ਆਪ ਖੋਲ੍ਹਣ ਦੀ ਬਜਾਏ URL ਪ੍ਰਿੰਟ ਕਰੋ), `--port <n>`
(ਲੂਪਬੈਕ ਪੋਰਟ ਨਿਰਧਾਰਤ ਕਰੋ), `--timeout <ms>`, `--push` / `--no-push` (ਆਟੋਮੈਟਿਕ
ਡਿਲਿਵਰੀ ਨੂੰ ਓਵਰਰਾਈਡ ਕਰੋ), `--context <name>` (ਕਿਸੇ ਖ਼ਾਸ ਕੌਂਟੈਕਸਟ ਨੂੰ ਨਿਸ਼ਾਨਾ ਬਣਾਓ)।

### ਵਿਕਲਪ B — SSH ਲੋਕਲ-ਫਾਰਵਰਡ ਟਨਲ

ਜੇ ਤੁਹਾਡੇ ਕੋਲ VPS ਲਈ SSH ਪਹੁੰਚ ਹੈ, ਤਾਂ ਡੈਸ਼ਬੋਰਡ ਪੋਰਟ ਨੂੰ ਫਾਰਵਰਡ ਕਰੋ ਤਾਂ ਜੋ
ਲੂਪਬੈਕ ਕਾਲਬੈਕ ਟਨਲ ਰਾਹੀਂ ਵਾਪਸ ਸਰਵਰ ਤੱਕ ਪਹੁੰਚੇ:

```bash
# ਆਪਣੀ LOCAL ਮਸ਼ੀਨ 'ਤੇ:
ssh -L 20128:127.0.0.1:20128 user@your-vps
# ਫਿਰ ਆਪਣੇ LOCAL ਬ੍ਰਾਊਜ਼ਰ ਵਿੱਚ http://localhost:20128 ਖੋਲ੍ਹੋ ਅਤੇ Antigravity ਨੂੰ ਆਮ ਤਰੀਕੇ ਨਾਲ ਕਨੈਕਟ ਕਰੋ
# — ਹੁਣ 127.0.0.1:20128/callback ਰੀਡਾਇਰੈਕਟ SSH ਰਾਹੀਂ VPS ਤੱਕ ਪਹੁੰਚਦਾ ਹੈ।
```

ਕਿਉਂਕਿ ਤੁਸੀਂ ਡੈਸ਼ਬੋਰਡ ਤੱਕ `localhost:20128` ਵਜੋਂ ਪਹੁੰਚਦੇ ਹੋ, Google ਸਹਿਮਤੀ
ਪੂਰੀ ਹੋ ਜਾਂਦੀ ਹੈ ਅਤੇ ਕਾਲਬੈਕ ਉਸੇ ਟਨਲ ਰਾਹੀਂ ਸਰਵਰ ਤੱਕ ਪਹੁੰਚਾਇਆ ਜਾਂਦਾ ਹੈ —
ਕਿਸੇ ਬਲੌਬ ਦੀ ਲੋੜ ਨਹੀਂ। ਜਦੋਂ ਤੱਕ ਕਨੈਕਸ਼ਨ ਸਰਗਰਮ ਨਾ ਦਿਖਾਈ ਦੇਵੇ, ਟਨਲ ਖੁੱਲ੍ਹੀ ਰੱਖੋ।

ਹੇਠਾਂ ਦਿੱਤੇ fixed-loopback ਪ੍ਰੋਵਾਈਡਰਾਂ ਤੋਂ ਵੱਖਰੇ ਤੌਰ 'ਤੇ, ਇੱਥੇ **ਇੱਕ ਫਾਰਵਰਡ ਹੀ ਕਾਫ਼ੀ ਹੈ**:
Antigravity ਕਾਲਬੈਕ ਖੁਦ ਡੈਸ਼ਬੋਰਡ ਪੋਰਟ ਰਾਹੀਂ ਜਾਂਦਾ ਹੈ, ਇਸ ਲਈ ਟਨਲ ਕਰਨ ਵਾਸਤੇ ਕੋਈ ਦੂਜਾ
provider-specific ਪੋਰਟ ਨਹੀਂ ਹੈ।

> ਇੱਕ ਪੂਰੀ ਤਰ੍ਹਾਂ headless ਵਿਕਲਪ (ਕੋਈ ਹੈਲਪਰ ਨਹੀਂ, ਕੋਈ ਟਨਲ ਨਹੀਂ) ਹੈ ਕਿ ਆਪਣੇ **ਖੁਦ ਦੇ**
> Google OAuth ਵੈੱਬ ਕ੍ਰੈਡੈਂਸ਼ਲ + ਇੱਕ ਪਬਲਿਕ ਬੇਸ URL ਕੌਂਫਿਗਰ ਕਰੋ; ਪ੍ਰੋਵਾਈਡਰ ਦੇ OAuth
> environment variables ਵੇਖੋ। ਉੱਪਰ ਦਿੱਤੇ ਦੋ ਵਿਕਲਪਾਂ ਲਈ ਕਿਸੇ ਵਾਧੂ Google ਸੈੱਟਅੱਪ ਦੀ ਲੋੜ ਨਹੀਂ ਹੈ।

## ਰਿਮੋਟ ਇੰਸਟਾਲੇਸ਼ਨ ਉੱਤੇ Codex / Grok ਨੂੰ ਕਨੈਕਟ ਕਰਨਾ (ਸਥਿਰ-loopback ਪ੍ਰਦਾਤਾ)

Codex, xAI (`xai-oauth`) ਅਤੇ Grok CLI (`grok-cli`) ਆਪਣੀ upstream OAuth ਐਪ ਨਾਲ ਇੱਕ **ਸਥਿਰ** loopback
`redirect_uri` ਰਜਿਸਟਰ ਕਰਦੇ ਹਨ। OmniRoute ਇਸਨੂੰ ਬਦਲ ਨਹੀਂ ਸਕਦਾ — ਪ੍ਰਦਾਤਾ ਹਮੇਸ਼ਾ ਬ੍ਰਾਊਜ਼ਰ ਨੂੰ ਉਸੇ hardcoded ਪਤੇ ਉੱਤੇ ਵਾਪਸ ਭੇਜਦਾ ਹੈ:

| ਪ੍ਰਦਾਤਾ     | ਉਹ ਸਥਿਰ callback ਜਿਸ ਵੱਲ ਪ੍ਰਦਾਤਾ redirect ਕਰਦਾ ਹੈ |
| ----------- | ------------------------------------------------- |
| `codex`     | `http://localhost:1455/auth/callback`             |
| `xai-oauth` | `http://127.0.0.1:56121/callback`                 |
| `grok-cli`  | `http://127.0.0.1:56122/callback`                 |

ਉੱਥੇ `localhost` ਦਾ ਅਰਥ ਹੈ **ਉਹ ਮਸ਼ੀਨ ਜਿਸ ਉੱਤੇ ਬ੍ਰਾਊਜ਼ਰ ਚੱਲ ਰਿਹਾ ਹੈ**, ਜਦਕਿ OmniRoute ਦਾ PKCE
callback ਸਰਵਰ **ਸਰਵਰ ਦੇ** loopback ਉੱਤੇ ਸੁਣਦਾ ਹੈ। ਡੈਸ਼ਬੋਰਡ ਨੂੰ `http://192.168.0.15:20128` ਵਰਗੇ LAN
ਪਤੇ ਉੱਤੇ ਖੋਲ੍ਹਣ ਨਾਲ ਦੋਵੇਂ ਕਦੇ ਨਹੀਂ ਮਿਲਦੇ: authorization
code ਤੁਹਾਡੇ ਆਪਣੇ ਲੈਪਟਾਪ ਦੇ `localhost:1455` ਉੱਤੇ ਭੇਜਿਆ ਜਾਂਦਾ ਹੈ, ਜਿੱਥੇ ਕੁਝ ਵੀ ਨਹੀਂ ਸੁਣ ਰਿਹਾ ਹੁੰਦਾ,
ਅਤੇ ਪ੍ਰਦਾਤਾ ਕੋਈ ਗਲਤੀ ਦਿਖਾਏ ਬਿਨਾਂ sign-in ਨੂੰ ਅਸਫਲ ਕਰ ਦਿੰਦਾ ਹੈ।

ਡੈਸ਼ਬੋਰਡ popup ਖੋਲ੍ਹਣ ਤੋਂ ਪਹਿਲਾਂ ਇਸਦਾ ਪਤਾ ਲਗਾ ਲੈਂਦਾ ਹੈ ਅਤੇ login ਨੂੰ ਚੁੱਪਚਾਪ ਅਸਫਲ ਹੋਣ ਦੇਣ ਦੀ ਬਜਾਏ tunnel command
ਦਿਖਾਉਂਦਾ ਹੈ (#8046)।

### ਹੱਲ — **ਦੋਵੇਂ** ports ਨੂੰ forward ਕਰੋ

```bash
# ਬ੍ਰਾਊਜ਼ਰ ਚਲਾਉਣ ਵਾਲੀ ਮਸ਼ੀਨ ਉੱਤੇ:
ssh -L 20128:127.0.0.1:20128 -L 1455:127.0.0.1:1455 <user>@192.168.0.15
# ਫਿਰ http://localhost:20128 ਖੋਲ੍ਹੋ ਅਤੇ ਉੱਥੋਂ Codex ਨੂੰ ਕਨੈਕਟ ਕਰੋ
```

ਦੋ forwards ਲੋੜੀਂਦੇ ਹਨ, ਅਤੇ ਸਿਰਫ਼ ਇੱਕ ਨੂੰ forward ਕਰਨ ਨਾਲ ਵੀ ਇਹ ਅਸਫਲ ਰਹਿੰਦਾ ਹੈ:

- **`20128`** (ਡੈਸ਼ਬੋਰਡ port) origin ਨੂੰ ਅਸਲ-localhost ਬਣਾਉਂਦਾ ਹੈ, ਜਿਸ ਕਾਰਨ
  OmniRoute PKCE callback ਸਰਵਰ ਸ਼ੁਰੂ ਕਰਦਾ ਹੈ — ਇੱਕ LAN origin ਕਦੇ ਵੀ
  ਉਸ branch ਤੱਕ ਨਹੀਂ ਪਹੁੰਚਦਾ।
- **`1455`** (ਪ੍ਰਦਾਤਾ ਦਾ ਸਥਿਰ callback port) ਉਹ ਥਾਂ ਹੈ ਜਿੱਥੇ ਬ੍ਰਾਊਜ਼ਰ ਨੂੰ ਵਾਪਸ ਭੇਜਿਆ ਜਾਂਦਾ ਹੈ;
  ਇਸਨੂੰ tunnel ਰਾਹੀਂ ਸਰਵਰ ਦੇ loopback ਤੱਕ ਪਹੁੰਚਣਾ ਲਾਜ਼ਮੀ ਹੈ।

xAI ਜਾਂ Grok CLI ਨੂੰ ਕਨੈਕਟ ਕਰਦੇ ਸਮੇਂ `1455` ਨੂੰ `56121`/`56122` ਨਾਲ, ਅਤੇ `20128` ਨੂੰ
ਆਪਣੇ ਅਸਲ ਡੈਸ਼ਬੋਰਡ port ਨਾਲ ਬਦਲੋ। ਕਨੈਕਸ਼ਨ active ਦਿਖਾਈ ਦੇਣ ਤੱਕ tunnel ਖੁੱਲ੍ਹਾ ਰੱਖੋ।

> **SSH access ਨਹੀਂ ਹੈ?** Codex ਅਤੇ Grok CLI paste ਕੀਤਾ token ਵੀ ਸਵੀਕਾਰ ਕਰਦੇ ਹਨ — connect dialog ਵਿੱਚ **Paste API
> Key** / **Import auth.json** tab। ਉਸ ਵਿਧੀ ਵਿੱਚ ਕੋਈ loopback
> callback ਨਹੀਂ ਹੁੰਦਾ, ਇਸ ਲਈ ਇਹ ਕਿਸੇ ਵੀ origin ਤੋਂ ਕੰਮ ਕਰਦੀ ਹੈ। Codex ਇਸ ਤੋਂ ਇਲਾਵਾ ਇੱਕ ਸਧਾਰਨ access
> token ਜਾਂ `~/.codex/auth.json` session blob ਵੀ ਸਵੀਕਾਰ ਕਰਦਾ ਹੈ।

## Tokens ਦਾ ਪ੍ਰਬੰਧਨ

```bash
omniroute tokens create --name "laptop" --scope write [--expires 30]
#   ↳ secret ਸਿਰਫ਼ ਇੱਕ ਵਾਰ ਦਿਖਾਉਂਦਾ ਹੈ — ਇਸਨੂੰ ਹੁਣੇ copy ਕਰੋ
omniroute tokens list                 # masked: id, name, scope, prefix, status, expiry
omniroute tokens revoke <id|prefix>   # ਤੁਰੰਤ revoke ਕਰੋ
omniroute tokens scopes               # ਤਿੰਨਾਂ scopes ਦੀ ਵਿਆਖਿਆ ਕਰੋ
```

`tokens` commands ਲਈ ਇੱਕ **admin** credential ਲੋੜੀਂਦਾ ਹੈ। ਤੁਸੀਂ ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ
**Settings → Access Tokens** ਹੇਠ ਵੀ tokens ਦਾ ਪ੍ਰਬੰਧਨ ਕਰ ਸਕਦੇ ਹੋ (ਬਣਾਓ, revoke ਕਰੋ, ਇੱਕ ਵਾਰ copy ਕਰੋ)।

## ਰਿਮੋਟ catalog ਤੋਂ coding CLI ਨੂੰ configure ਕਰਨਾ

`omniroute configure` **active server** ਦਾ live model catalog ਪੜ੍ਹਦਾ ਹੈ ਅਤੇ
**ਤੁਹਾਡੀ** ਮਸ਼ੀਨ ਉੱਤੇ config ਲਿਖਦਾ ਹੈ।

```bash
omniroute configure codex
#   ਪ੍ਰਦਾਤਾ: glm, kmc, ollamacloud, opencode-go, …
#   ਪ੍ਰਦਾਤਾ: glm
#   Model id: glm/glm-5.2
#   ✔ ~/.codex/glm52.config.toml ਲਿਖੀ ਗਈ
#   ਇਸਨੂੰ ਵਰਤੋ:  codex --profile glm52

# non-interactive
omniroute configure codex --provider glm --model glm/glm-5.2 --name glm52

# ਅਕਸਰ ਵਰਤੇ ਜਾਣ ਵਾਲੇ model ਨੂੰ interactive picker ਦੇ ਸਿਖਰ ਉੱਤੇ ਰੱਖੋ
omniroute configure codex --provider glm --model glm/glm-5.2 --favorite --yes
```

Picker ਸਥਾਨਕ `model-preferences.json` file ਵਿੱਚ ਸਿਰਫ਼ model IDs (ਕਦੇ ਵੀ URLs ਜਾਂ credentials ਨਹੀਂ) ਰੱਖਦਾ ਹੈ,
ਜਿਨ੍ਹਾਂ ਨੂੰ context ਅਤੇ CLI target ਅਨੁਸਾਰ scoped ਕੀਤਾ ਜਾਂਦਾ ਹੈ। Favorites ਨੂੰ
ਹਾਲੀਆ selections ਤੋਂ ਪਹਿਲਾਂ ਦਿਖਾਇਆ ਜਾਂਦਾ ਹੈ; ਚੁਣੇ ਹੋਏ model ਨੂੰ ਉਸ context/target ਸੂਚੀ ਵਿੱਚੋਂ ਹਟਾਉਣ ਲਈ
`--unfavorite` ਵਰਤੋ।

ਲਿਖੀ ਗਈ profile env var (`OMNIROUTE_API_KEY`) ਰਾਹੀਂ inference key ਨੂੰ reference ਕਰਦੀ ਹੈ — secret ਕਦੇ ਵੀ disk ਉੱਤੇ ਨਹੀਂ ਲਿਖਿਆ ਜਾਂਦਾ। ਇੱਕ ਵਾਰ ਕੀਤੇ ਜਾਣ ਵਾਲੇ
ਮੁੱਢਲੇ Codex setup (`[model_providers.omniroute]` block) ਲਈ,
[CODEX-CLI-CONFIGURATION.md](./CODEX-CLI-CONFIGURATION.md) ਵੇਖੋ।

### ਰਿਮੋਟ ਨਾਲ CLI launch ਕਰਨਾ (ਕੋਈ config ਨਹੀਂ ਲਿਖੀ ਜਾਂਦੀ)

`omniroute run <target>` active context ਦਾ ਵੀ ਆਦਰ ਕਰਦਾ ਹੈ: ਰਿਮੋਟ base URL
ਅਤੇ context credential ਨੂੰ ਸਿਰਫ਼ spawn ਕੀਤੀ process ਵਿੱਚ inject ਕੀਤਾ ਜਾਂਦਾ ਹੈ।

```bash
omniroute connect 192.168.0.15
omniroute run claude   --model openai/gpt-5.4          # Claude Code → ਰਿਮੋਟ
omniroute run gemini   --model glm/glm-5.2 -- --skip-trust -p "hello"
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"

# ਬਿਲਕੁਲ ਉਹੀ preview ਕਰੋ ਜੋ spawn ਕੀਤਾ ਜਾਵੇਗਾ (ਸਿਰਫ਼ env KEY NAMES, values ਕਦੇ ਨਹੀਂ):
omniroute run codex --dry-run --json
```

Targets: `claude`, `codex`, `aider`, `goose`, `opencode`, `qwen`, `gemini`
(ਇੱਕੋ source: `bin/cli/cli-manifest.mjs`)। Qwen ਅਤੇ Gemini ਇੱਕ
ਅਸਥਾਈ isolated home ਨਾਲ ਚੱਲਦੇ ਹਨ, ਜਿਸਨੂੰ exit ਉੱਤੇ ਹਟਾ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ, ਇਸ ਲਈ launch ਕਦੇ ਵੀ ਤੁਹਾਡੀ ਨਿੱਜੀ tool configuration ਨੂੰ ਛੁਹੰਦਾ ਨਹੀਂ —
ਨਾ ਹੀ ਉਸ ਵਿੱਚ ਕੁਝ leak ਕਰਦਾ ਹੈ।

### ਹਰੇਕ CLI ਲਈ setup commands

ਹਰੇਕ ਸਮਰਥਿਤ CLI ਕੋਲ ਇੱਕ remote-aware setup command ਹੈ (ਸਾਰੇ active
context ਦਾ ਆਦਰ ਕਰਦੇ ਹਨ, ਜਾਂ `--remote <url> --api-key <key>`):

| CLI         | ਕਮਾਂਡ                      | ਇਹ ਕੀ ਲਿਖਦਾ ਹੈ                                                                                                                                                                       |
| ----------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Codex       | `omniroute setup-codex`    | `~/.codex/<name>.config.toml` ਪ੍ਰੋਫ਼ਾਈਲਾਂ (ਹਰੇਕ ਮਾਡਲ ਲਈ)                                                                                                                             |
| Claude Code | `omniroute setup-claude`   | `~/.claude/profiles/<name>/settings.json` (ਹਰੇਕ ਮਾਡਲ ਲਈ)                                                                                                                             |
| OpenCode    | `omniroute setup-opencode` | ਹਰ ਕੈਟਾਲੌਗ ਮਾਡਲ ਵਾਲਾ `omniroute` openai-ਅਨੁਕੂਲ ਪ੍ਰਦਾਤਾ — `~/.config/opencode/opencode.json` (`opencode -m omniroute/<model>` ਚਲਾਓ)                                                   |
| Cline       | `omniroute setup-cline`    | `~/.cline/data/{globalState,secrets}.json` (CLI ਮੋਡ) + ਪੇਸਟ ਕਰਨ ਲਈ VS Code ਐਕਸਟੈਂਸ਼ਨ ਸੈਟਿੰਗਾਂ ਪ੍ਰਿੰਟ ਕਰਦਾ ਹੈ (OpenAI-ਅਨੁਕੂਲ, Base URL `/v1` **ਤੋਂ ਬਿਨਾਂ**)                           |
| Kilo Code   | `omniroute setup-kilo`     | `~/.local/share/kilo/auth.json` (CLI) + VS Code `kilocode.*` ਸੈਟਿੰਗਾਂ — OpenAI-ਅਨੁਕੂਲ, Base URL `/v1` **ਦੇ ਨਾਲ**                                                                     |
| Continue    | `omniroute setup-continue` | `~/.continue/config.yaml` (VS Code/JetBrains + `cn` CLI) — `provider: openai`, `apiBase` `/v1` **ਦੇ ਨਾਲ**, ਕੁੰਜੀ `${{ secrets.OMNIROUTE_API_KEY }}` ਰਾਹੀਂ                            |
| Cursor      | `omniroute setup-cursor`   | ਐਪ ਅੰਦਰਲੇ ਕਦਮ ਪ੍ਰਿੰਟ ਕਰਦਾ ਹੈ (Settings → Models → Override OpenAI Base URL `/v1` **ਦੇ ਨਾਲ** + ਕੁੰਜੀ + ਮਾਡਲ)। Cursor ਸੰਰਚਨਾ ਅਪਾਰਦਰਸ਼ੀ SQLite ਹੈ — ਸਿਰਫ਼ ਚੈਟ ਪੈਨਲ                      |
| Roo Code    | `omniroute setup-roo`      | ਇੱਕ Roo ਇੰਪੋਰਟ JSON (`~/.omniroute/roo-settings.json`) ਲਿਖਦਾ ਹੈ + `roo-cline.autoImportSettingsPath` ਸੈੱਟ ਕਰਦਾ ਹੈ + UI ਕਦਮ ਪ੍ਰਿੰਟ ਕਰਦਾ ਹੈ (OpenAI-ਅਨੁਕੂਲ, Base URL `/v1` **ਦੇ ਨਾਲ**) |
| Crush       | `omniroute setup-crush`    | `~/.config/crush/crush.json` — `openai-compat` ਪ੍ਰਦਾਤਾ, `base_url` `/v1` **ਦੇ ਨਾਲ**, ਕੁੰਜੀ `$OMNIROUTE_API_KEY` ਰਾਹੀਂ                                                                |
| Goose       | `omniroute setup-goose`    | `~/.config/goose/config.yaml` (`GOOSE_PROVIDER=openai` + `OPENAI_HOST` `/v1` **ਤੋਂ ਬਿਨਾਂ** + `GOOSE_MODEL`) + env ਵਿਧੀ                                                               |
| Aider       | `omniroute setup-aider`    | `~/.aider.conf.yml` (`openai-api-base` `/v1` **ਤੋਂ ਬਿਨਾਂ** + `model: openai/<id>`) + env ਵਿਧੀ (`aider --message --yes`)                                                              |
| Qwen Code   | `omniroute setup-qwen`     | `~/.qwen/settings.json` ਵਿੱਚ V4 `modelProviders.openai` ਐਂਟਰੀ + `~/.qwen/.env` ਵਿੱਚ `OMNIROUTE_API_KEY`                                                                              |

```bash
# OpenCode (openai-ਅਨੁਕੂਲ ਪ੍ਰਦਾਤਾ, ਸਾਰੇ ਕੈਟਾਲੌਗ ਮਾਡਲ, ਰਿਮੋਟ VPS)
omniroute setup-opencode --remote http://192.168.0.15:20128 --api-key oma_live_xxx
omniroute setup-opencode --only glm,kimi        # ਸਿਰਫ਼ ਮੇਲ ਖਾਂਦੇ ਮਾਡਲ ਰੱਖੋ
opencode -m omniroute/glm/glm-5.2 "..."          # ਪਹਿਲਾਂ OMNIROUTE_API_KEY ਐਕਸਪੋਰਟ ਕਰੋ
```

> OpenCode ਕੋਲ ਇੱਕ ਹੋਰ ਸਮਰੱਥ **ਪਲੱਗਇਨ** ਏਕੀਕਰਨ ਵੀ ਹੈ: `omniroute setup opencode`
> (ਹੁਣ `--remote` ਰਾਹੀਂ ਰਿਮੋਟ-ਅਵੇਅਰ) `@omniroute/opencode-plugin` ਨੂੰ ਇੰਸਟਾਲ ਕਰਦਾ ਹੈ।
> `setup-opencode` ਹਲਕਾ openai-ਅਨੁਕੂਲ ਵਿਕਲਪ ਹੈ। API ਕੁੰਜੀ ਦਾ ਹਵਾਲਾ
> `{env:OMNIROUTE_API_KEY}` ਰਾਹੀਂ ਦਿੱਤਾ ਜਾਂਦਾ ਹੈ — ਇਸਨੂੰ ਕਦੇ ਵੀ ਡਿਸਕ 'ਤੇ ਨਹੀਂ ਲਿਖਿਆ ਜਾਂਦਾ।
>
> OpenCode v2 ਉੱਤੇ ਇਸਦੀ ਬਜਾਏ `@omniroute/opencode-plugin-v2` ਵਰਤੋ: ਉਹੀ ਕੈਟਾਲੌਗ,
> ਵੱਖਰਾ ਲੋਡਰ ਇਕਰਾਰਨਾਮਾ। ਏਕੀਕਰਨ ਕਨੈਕਟ ਹੋਣ 'ਤੇ ਇਹ OpenCode ਦੇ ਆਪਣੇ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ
> ਸਟੋਰ ਤੋਂ ਕੁੰਜੀ ਪੜ੍ਹਦਾ ਹੈ, ਇਸ ਲਈ ਕਿਸੇ ਰਿਮੋਟ ਗੇਟਵੇ ਨੂੰ `opencode.json` ਵਿੱਚ ਕਿਸੇ ਕੁੰਜੀ ਦੀ
> ਬਿਲਕੁਲ ਲੋੜ ਨਹੀਂ ਹੁੰਦੀ।

## ਕਾਂਟੈਕਸਟਾਂ ਦਾ ਪ੍ਰਬੰਧਨ (ਸਰਵਰਾਂ ਵਿਚਕਾਰ ਬਦਲੋ)

ਇੱਕ **ਕਾਂਟੈਕਸਟ** ਇੱਕ ਸੰਭਾਲਿਆ ਹੋਇਆ ਸਰਵਰ (baseUrl + ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ + ਸਕੋਪ) ਹੁੰਦਾ ਹੈ। `omniroute connect`
ਇੱਕ ਕਾਂਟੈਕਸਟ ਬਣਾਉਂਦਾ ਹੈ ਅਤੇ ਉਸਨੂੰ ਸਰਗਰਮ ਕਰਦਾ ਹੈ; ਇਸ ਤੋਂ ਬਾਅਦ ਹਰ ਕਮਾਂਡ ਉਸੇ ਨੂੰ ਨਿਸ਼ਾਨਾ ਬਣਾਉਂਦੀ ਹੈ। `omniroute contexts`
ਨਾਲ ਉਹਨਾਂ ਦਾ ਪ੍ਰਬੰਧਨ ਕਰੋ ਅਤੇ ਉਹਨਾਂ ਵਿਚਕਾਰ ਬਦਲੋ:

```bash
omniroute contexts list            # ਸਾਰੇ ਕਾਂਟੈਕਸਟ; ਸਰਗਰਮ ਕਾਂਟੈਕਸਟ ਨੂੰ ● ਨਾਲ ਦਰਸਾਇਆ ਗਿਆ ਹੈ
omniroute contexts current         # ਸਰਗਰਮ ਸਰਵਰ, ਪ੍ਰਮਾਣੀਕਰਨ ਸਥਿਤੀ, ਸਕੋਪ
```

```text
  | ਨਾਮ     | ਬੇਸ URL                   | ਪ੍ਰਮਾਣੀਕਰਨ | ਸਕੋਪ | ਵੇਰਵਾ
● | vps     | http://100.67.86.91:20128 | token       | admin | ਰਿਮੋਟ OmniRoute (…)
  | default | http://localhost:20128    | ✗           |       |
```

**ਸਰਵਰ ਬਦਲੋ** — ਇਸ ਤੋਂ ਬਾਅਦ ਦੀ ਹਰ ਕਮਾਂਡ ਸਰਗਰਮ ਕਾਂਟੈਕਸਟ ਦੀ ਵਰਤੋਂ ਕਰਦੀ ਹੈ:

```bash
omniroute contexts use vps         # → ਹੁਣ ਸਾਰੀਆਂ ਕਮਾਂਡਾਂ ਰਿਮੋਟ VPS ਨੂੰ ਭੇਜੀਆਂ ਜਾਂਦੀਆਂ ਹਨ
omniroute tokens list              #   (VPS ਵਿਰੁੱਧ ਚੱਲਦੀ ਹੈ)

omniroute contexts use default     # → ਵਾਪਸ localhost ਉੱਤੇ
omniroute tokens list              #   (ਸਥਾਨਕ ਸਰਵਰ ਵਿਰੁੱਧ ਚੱਲਦੀ ਹੈ)
```

**ਹੱਥੀਂ ਕਾਂਟੈਕਸਟ ਸ਼ਾਮਲ ਕਰੋ** (`connect` ਦੀ ਬਜਾਏ), ਜਾਂਚੋ ਜਾਂ ਨਾਮ ਬਦਲੋ:

```bash
omniroute contexts add staging --url https://staging.example.com:20128 \
  --access-token oma_live_xxxx --scope write --description "staging box"
omniroute contexts show staging    # ਇੱਕ ਕਾਂਟੈਕਸਟ ਦੇ ਪੂਰੇ ਵੇਰਵੇ
omniroute contexts rename staging stg
```

**ਕਾਂਟੈਕਸਟ ਹਟਾਓ** — ਪੁਸ਼ਟੀ ਲਈ ਪੁੱਛਿਆ ਜਾਂਦਾ ਹੈ; ਇਸਨੂੰ ਛੱਡਣ ਲਈ `--yes` ਦਿਓ
(ਸਕ੍ਰਿਪਟਾਂ / ਗੈਰ-ਇੰਟਰਐਕਟਿਵ ਸ਼ੈੱਲਾਂ ਲਈ ਲੋੜੀਂਦਾ ਹੈ, ਜੋ ਨਹੀਂ ਤਾਂ ਸੁਰੱਖਿਅਤ ਢੰਗ ਨਾਲ ਇਨਕਾਰ ਕਰਦੇ ਹਨ):

```bash
omniroute contexts remove stg --yes
```

> `default` (localhost) ਨੂੰ ਹਟਾਇਆ ਨਹੀਂ ਜਾ ਸਕਦਾ। ਸਰਗਰਮ ਕਾਂਟੈਕਸਟ ਹਟਾਉਣ ਉੱਤੇ
> `default` ਵਰਤਿਆ ਜਾਂਦਾ ਹੈ। ਸੁਝਾਅ: ਕਿਸੇ ਕਾਂਟੈਕਸਟ ਨੂੰ ਹਟਾਉਣ ਨਾਲ ਸਿਰਫ਼ **ਸਥਾਨਕ** ਤੌਰ ਉੱਤੇ ਸੰਭਾਲਿਆ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਹਟਦਾ ਹੈ —
> ਐਕਸੈੱਸ ਨੂੰ ਅਸਲ ਵਿੱਚ ਖ਼ਤਮ ਕਰਨ ਲਈ `omniroute tokens revoke <id>` ਨਾਲ ਸਰਵਰ ਉੱਤੇ ਟੋਕਨ ਰੱਦ ਕਰੋ।

ਕਾਂਟੈਕਸਟਾਂ ਨੂੰ **ਐਕਸਪੋਰਟ / ਇੰਪੋਰਟ** ਕਰੋ (ਜਿਵੇਂ ਕਿ ਉਹਨਾਂ ਨੂੰ ਮਸ਼ੀਨਾਂ ਵਿਚਕਾਰ ਤਬਦੀਲ ਕਰਨ ਲਈ)। ਨਵੇਂ ਕਾਂਟੈਕਸਟ
ਸਿਰਫ਼ ਇੱਕ ਕੀਚੇਨ ਹਵਾਲਾ ਸੰਭਾਲਦੇ ਹਨ; ਜਦੋਂ OS ਕੀਚੇਨ ਉਪਲਬਧ ਹੋਵੇ, ਤਾਂ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਐਕਸਪੋਰਟ ਵਿੱਚ ਕਾਪੀ ਨਹੀਂ ਕੀਤੇ ਜਾਂਦੇ:

```bash
omniroute contexts export --out contexts.json     # ਮੂਲ: stdout
omniroute contexts import contexts.json            # ਓਵਰਰਾਈਟ ਕਰੋ; ਮੌਜੂਦਾ ਨੂੰ ਰੱਖਣ ਲਈ --merge
omniroute contexts migrate --yes                  # ਪੁਰਾਣੇ ਪਲੇਨਟੈਕਸਟ ਟੋਕਨਾਂ ਨੂੰ ਕੀਚੇਨ ਵਿੱਚ ਭੇਜੋ
```

ਵਰਤੋਂਯੋਗ OS ਕੀਚੇਨ ਤੋਂ ਬਿਨਾਂ ਹੈੱਡਲੈੱਸ ਸਿਸਟਮਾਂ ਉੱਤੇ, CLI
`0600` ਮੋਡ ਵਾਲੀ `config.json` ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ ਅਤੇ ਇੱਕ ਵਾਰ ਦੀ ਚੇਤਾਵਨੀ ਦਿਖਾਉਂਦਾ ਹੈ। ਇਸ
ਫਾਲਬੈਕ ਤੋਂ ਕੀਤੇ ਐਕਸਪੋਰਟਾਂ (ਅਤੇ ਮਾਈਗ੍ਰੇਸ਼ਨ ਤੋਂ ਪਹਿਲਾਂ ਦੀ ਕਿਸੇ ਵੀ ਪੁਰਾਣੀ ਕਨਫਿਗਰੇਸ਼ਨ) ਨੂੰ ਗੁਪਤ ਸਮੱਗਰੀ ਸਮਝੋ।

## ਤੁਰੰਤ ਸ਼ੁਰੂ-ਤੋਂ-ਅੰਤ ਜਾਂਚ

ਰਿਮੋਟ ਸੈੱਟਅੱਪ ਨੂੰ ਸ਼ੁਰੂ ਤੋਂ ਜਾਂਚਣ ਲਈ ਕਾਪੀ-ਪੇਸਟ ਕਰਨ ਯੋਗ ਜੀਵਨ-ਚੱਕਰ — ਕਨੈਕਟ ਕਰੋ, ਸੀਮਿਤ
ਸਕੋਪ ਵਾਲਾ ਟੋਕਨ ਬਣਾਓ, ਕਮਾਂਡ ਰੂਟ ਕਰੋ, ਵਾਪਸ ਬਦਲੋ ਅਤੇ ਸੈੱਟਅੱਪ ਹਟਾਓ।
`192.168.0.15` ਨੂੰ ਆਪਣੇ ਸਰਵਰ ਦੇ ਹੋਸਟ/IP (Tailscale, LAN ਜਾਂ ਜਨਤਕ
`https://…` URL) ਨਾਲ ਬਦਲੋ।

```bash
# 1. ਕਨੈਕਟ ਕਰੋ (ਪਾਸਵਰਡ → ਐਡਮਿਨ ਟੋਕਨ, ਇੱਕ ਕਾਂਟੈਕਸਟ ਵਜੋਂ ਸੰਭਾਲਿਆ ਜਾਂਦਾ ਹੈ ਜੋ ਸਰਗਰਮ ਹੋ ਜਾਂਦਾ ਹੈ)
omniroute connect 192.168.0.15                 # ਜਾਂ: --key oma_live_xxxx  (ਕੋਈ ਪਾਸਵਰਡ ਨਹੀਂ)
omniroute contexts current                     # ਰਿਮੋਟ ਸਰਵਰ + ਸਕੋਪ ਦਿਖਾਉਂਦਾ ਹੈ

# 2. ਇਸਦੀ ਵਰਤੋਂ ਕਰੋ — ਪ੍ਰਬੰਧਨ ਕਮਾਂਡਾਂ ਹੁਣ ਰਿਮੋਟ ਸਰਵਰ ਵਿਰੁੱਧ ਚੱਲਦੀਆਂ ਹਨ
omniroute tokens create --name laptop --scope read   # ਵਧੇਰੇ ਸੀਮਿਤ ਟੋਕਨ ਬਣਾਓ
omniroute tokens list                                 # ਰਿਮੋਟ ਤੋਂ ਮਾਸਕ ਕੀਤੀ ਸੂਚੀ

# 3. ਅੱਗੇ-ਪਿੱਛੇ ਬਦਲੋ
omniroute contexts use default                 # → ਸਥਾਨਕ
omniroute contexts use 192-168-0-15            # → ਮੁੜ ਰਿਮੋਟ (`contexts list` ਤੋਂ ਨਾਮ)

# 4. ਸੈੱਟਅੱਪ ਹਟਾਓ। ਧਿਆਨ ਦਿਓ: `contexts remove` ਸਿਰਫ਼ ਸਥਾਨਕ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਮਿਟਾਉਂਦਾ ਹੈ —
#    ਇਹ ਸਰਵਰ ਉੱਤੇ ਟੋਕਨ ਨੂੰ ਰੱਦ ਨਹੀਂ ਕਰਦਾ। ਜੇ ਤੁਸੀਂ
#    ਐਕਸੈੱਸ ਨੂੰ ਅਸਲ ਵਿੱਚ ਖ਼ਤਮ ਕਰਨਾ ਚਾਹੁੰਦੇ ਹੋ, ਤਾਂ ਪਹਿਲਾਂ ਸਰਵਰ ਉੱਤੇ ਇਸਨੂੰ ਰੱਦ ਕਰੋ।
omniroute tokens revoke <id|prefix>            # ਸਰਵਰ ਉੱਤੇ ਐਕਸੈੱਸ ਖ਼ਤਮ ਕਰਦਾ ਹੈ
omniroute contexts remove 192-168-0-15 --yes   # ਸਥਾਨਕ ਕਾਂਟੈਕਸਟ ਹਟਾਓ (ਭਾਵੇਂ ਸਰਗਰਮ ਹੋਵੇ → default ਵਰਤਿਆ ਜਾਂਦਾ ਹੈ), ਕੋਈ ਪੁਸ਼ਟੀ ਨਹੀਂ
```

> `--yes`, `contexts remove` ਨੂੰ ਗੈਰ-ਇੰਟਰਐਕਟਿਵ ਬਣਾਉਂਦਾ ਹੈ (ਸਕ੍ਰਿਪਟਾਂ/CI ਵਿੱਚ ਲੋੜੀਂਦਾ; ਇਸ ਤੋਂ ਬਿਨਾਂ
> ਗੈਰ-ਇੰਟਰਐਕਟਿਵ ਸ਼ੈੱਲ ਅਟਕਣ ਦੀ ਬਜਾਏ ਸੁਰੱਖਿਅਤ ਢੰਗ ਨਾਲ ਇਨਕਾਰ ਕਰਦਾ ਹੈ)। **ਸਰਗਰਮ**
> ਕਾਂਟੈਕਸਟ ਹਟਾਉਣ ਉੱਤੇ ਆਪਣੇ ਆਪ `default` ਵਰਤਿਆ ਜਾਂਦਾ ਹੈ।

## ਸੁਰੱਖਿਆ ਸੰਬੰਧੀ ਨੋਟਸ

- ਟੋਕਨ ਦਾ ਪਲੇਨਟੈਕਸਟ ਸਿਰਫ਼ ਇੱਕ ਵਾਰ ਦਿਖਾਇਆ ਜਾਂਦਾ ਹੈ; ਕੇਵਲ SHA-256 ਹੈਸ਼ ਹੀ ਸਥਾਈ ਤੌਰ 'ਤੇ ਸੰਭਾਲਿਆ ਜਾਂਦਾ ਹੈ (API ਕੁੰਜੀਆਂ ਵਾਂਗ ਹੀ)।
- `omniroute connect` ਲੌਗਇਨ ਬਰੂਟ-ਫੋਰਸ ਲੌਕਆਉਟ + ਆਡਿਟ ਲੌਗਿੰਗ ਨੂੰ ਮੁੜ ਵਰਤਦਾ ਹੈ।
- ਟ੍ਰਾਂਸਪੋਰਟ ਲਈ HTTPS ਜਾਂ Tailnet ਨੂੰ ਤਰਜੀਹ ਦਿਓ; LAN/Tailscale ਦੀ ਸਹੂਲਤ ਲਈ ਸਿਰਫ਼ ਹੋਸਟ ਦੇਣ 'ਤੇ ਮੂਲ ਰੂਪ ਵਿੱਚ `http://`
  ਵਰਤਿਆ ਜਾਂਦਾ ਹੈ — TLS ਲਈ ਪੂਰਾ `https://…` URL ਦਿਓ।
- ਤਰਜੀਹੀ ਸਥਾਨਕ ਕਾਂਟੈਕਸਟ ਫ਼ਾਈਲ `~/.omniroute/config.json` (`chmod 600`)
  ਹੈ, ਜਿਸ ਵਿੱਚ ਕੇਵਲ ਇੱਕ `credentialRef` ਹੁੰਦਾ ਹੈ; ਟੋਕਨ ਖੁਦ OS
  ਕੀਚੇਨ (`keytar`) ਵਿੱਚ ਸਟੋਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ ਅਤੇ ਲੌਗਾਂ ਵਿੱਚ ਕਦੇ ਵੀ ਪ੍ਰਿੰਟ ਨਹੀਂ ਹੁੰਦਾ। ਕਾਰਜਸ਼ੀਲ
  ਨੇਟਿਵ ਕੀਚੇਨ ਤੋਂ ਬਿਨਾਂ ਹੈਡਲੈੱਸ ਇੰਸਟਾਲੇਸ਼ਨਾਂ ਵਿੱਚ ਉਸੇ `0600` ਫ਼ਾਈਲ ਨੂੰ ਸਪਸ਼ਟ ਫ਼ਾਲਬੈਕ ਵਜੋਂ ਵਰਤਿਆ ਜਾਂਦਾ ਹੈ ਅਤੇ
  ਇੱਕ ਵਾਰ ਚੇਤਾਵਨੀ ਜਾਰੀ ਕੀਤੀ ਜਾਂਦੀ ਹੈ। ਕੀਚੇਨ ਬੈਕਐਂਡ ਇੰਸਟਾਲ ਕਰਨ ਤੋਂ ਬਾਅਦ
  `omniroute contexts migrate --yes` ਵਰਤੋ।
