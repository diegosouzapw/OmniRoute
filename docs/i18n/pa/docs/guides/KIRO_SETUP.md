ਇਹ ਗਾਈਡ OmniRoute ਵਿੱਚ Kiro (AWS ਵੱਲੋਂ ਹੋਸਟ ਕੀਤਾ ਗਿਆ AI ਕੋਡਿੰਗ ਸਹਾਇਕ) ਖਾਤੇ ਸ਼ਾਮਲ ਕਰਨ ਬਾਰੇ ਹੈ,
ਜਿਸ ਵਿੱਚ ਸੈਸ਼ਨ ਟਕਰਾਵਾਂ ਤੋਂ ਬਿਨਾਂ ਇੱਕੋ ਸਮੇਂ ਕਈ ਖਾਤੇ ਚਲਾਉਣ ਉੱਤੇ ਧਿਆਨ ਦਿੱਤਾ ਗਿਆ ਹੈ।

## ਪਿਛੋਕੜ: Kiro ਖਾਤਿਆਂ ਵਿੱਚ ਟਕਰਾਅ ਕਿਉਂ ਹੋ ਸਕਦਾ ਹੈ

Kiro ਦਾ ਬੈਕਐਂਡ ਸਰਗਰਮ ਸੈਸ਼ਨਾਂ ਨੂੰ ਟਰੈਕ ਕਰਨ ਲਈ AWS SSO OIDC ਕਲਾਇੰਟ ਰਜਿਸਟ੍ਰੇਸ਼ਨਾਂ ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ।
ਮਹੱਤਵਪੂਰਨ ਪਾਬੰਦੀ: **ਹਰੇਕ OIDC ਕਲਾਇੰਟ ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਇੱਕ ਸਮੇਂ ਸਿਰਫ਼ ਇੱਕ ਸਰਗਰਮ
ਸੈਸ਼ਨ ਦਾ ਸਮਰਥਨ ਕਰਦੀ ਹੈ**। ਜਦੋਂ ਕੋਈ ਦੂਜੀ ਡਿਵਾਈਸ ਜਾਂ ਵਰਤੋਂਕਾਰ ਉਸੇ
ਰਜਿਸਟਰ ਕੀਤੇ ਕਲਾਇੰਟ ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਪ੍ਰਮਾਣਿਤ ਹੁੰਦਾ ਹੈ, ਤਾਂ ਬੈਕਐਂਡ ਪਹਿਲੇ ਖਾਤੇ ਦੇ ਰਿਫ੍ਰੈਸ਼ ਟੋਕਨ ਨੂੰ ਅਵੈਧ ਕਰ ਦਿੰਦਾ ਹੈ।

ਇਹ ਉਹੀ ਵਿਧੀ ਹੈ ਜੋ ਉਸ ਮਸ਼ੀਨ ਉੱਤੇ `kiro-cli login` ਚਲਾਉਣ ਵੇਲੇ ਸਮੱਸਿਆਵਾਂ ਪੈਦਾ ਕਰਦੀ ਹੈ
ਜਿੱਥੇ ਕੋਈ ਹੋਰ Kiro ਖਾਤਾ ਪਹਿਲਾਂ ਹੀ ਸਾਈਨ ਇਨ ਹੈ — ਨਵਾਂ ਲੌਗਇਨ
ਪਹਿਲੇ ਖਾਤੇ ਦੇ ਟੋਕਨ ਨੂੰ ਰੱਦ ਕਰ ਦਿੰਦਾ ਹੈ।

## OmniRoute ਇਸਦਾ ਹੱਲ ਕਿਵੇਂ ਕਰਦਾ ਹੈ (v3.8.0+)

v3.8.0 ਤੋਂ ਸ਼ੁਰੂ ਕਰਦੇ ਹੋਏ, OmniRoute ਹਰੇਕ
Kiro ਕਨੈਕਸ਼ਨ ਇੰਪੋਰਟ ਦੌਰਾਨ `registerClient()` (AWS SSO OIDC) ਨੂੰ ਕਾਲ ਕਰਦਾ ਹੈ। ਇਸ ਨਾਲ ਹਰੇਕ OmniRoute ਕਨੈਕਸ਼ਨ ਨੂੰ ਆਪਣੀ ਸਮਰਪਿਤ OIDC
ਕਲਾਇੰਟ ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਮਿਲਦੀ ਹੈ। ਕਿਉਂਕਿ ਹਰੇਕ ਕਲਾਇੰਟ ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਸੁਤੰਤਰ ਹੁੰਦੀ ਹੈ, ਇਸ ਲਈ ਇੱਕ ਖਾਤੇ ਨੂੰ ਰਿਫ੍ਰੈਸ਼ ਜਾਂ
ਮੁੜ ਪ੍ਰਮਾਣਿਤ ਕਰਨ ਨਾਲ ਕਿਸੇ ਹੋਰ ਖਾਤੇ ਦਾ ਰਿਫ੍ਰੈਸ਼ ਟੋਕਨ ਪ੍ਰਭਾਵਿਤ ਨਹੀਂ ਹੁੰਦਾ।

ਇਹ ਅਲੱਗਾਵ ਰਿਫ੍ਰੈਸ਼-ਟੋਕਨ ਇੰਪੋਰਟ ਵਿਧੀਆਂ ਉੱਤੇ ਲਾਗੂ ਹੁੰਦਾ ਹੈ, ਅਤੇ API-key ਪ੍ਰਮਾਣੀਕਰਨ
OIDC ਰਿਫ੍ਰੈਸ਼ ਸੈਸ਼ਨਾਂ ਤੋਂ ਪੂਰੀ ਤਰ੍ਹਾਂ ਬਚਦਾ ਹੈ:

| ਇੰਪੋਰਟ ਵਿਧੀ                                             | ਅਲੱਗਾਵ ਦੀ ਸਥਿਤੀ                                                                                           |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| AWS Builder ID / IDC ਡਿਵਾਈਸ-ਕੋਡ ਪ੍ਰਵਾਹ                  | ਡਿਵਾਈਸ-ਕੋਡ ਪ੍ਰਵਾਹ ਪੇਸ਼ ਕੀਤੇ ਜਾਣ ਤੋਂ ਅਲੱਗ ਹੈ                                                               |
| **ਟੋਕਨ ਇੰਪੋਰਟ ਕਰੋ** (ਰਿਫ੍ਰੈਸ਼ ਟੋਕਨ ਨੂੰ ਹੱਥੀਂ ਪੇਸਟ ਕਰਨਾ) | v3.8.0 ਤੋਂ ਅਲੱਗ                                                                                           |
| **Google / GitHub ਸੋਸ਼ਲ ਲੌਗਇਨ**                         | v3.8.0 ਤੋਂ ਅਲੱਗ                                                                                           |
| **ਆਟੋ-ਇੰਪੋਰਟ** (kiro-cli SQLite)                        | v3.8.0 ਤੋਂ ਅਲੱਗ (SQLite ਪਾਥ ਪਹਿਲਾਂ ਹੀ ਅਲੱਗ ਸੀ; SSO-cache ਫਾਲਬੈਕ ਹੁਣ ਵੀ ਅਲੱਗ ਹੈ)                           |
| **API ਕੁੰਜੀ** (ਲੰਬੀ ਮਿਆਦ ਵਾਲੀ CodeWhisperer ਕੁੰਜੀ)      | ਕੋਈ ਰਿਫ੍ਰੈਸ਼ ਸੈਸ਼ਨ ਨਹੀਂ; ਕੁੰਜੀ ਦੀ ਪੁਸ਼ਟੀ ਕੀਤੀ ਜਾਂਦੀ ਹੈ ਅਤੇ ਇਸਨੂੰ ਬੇਅਰਰ ਕ੍ਰੈਡੈਂਸ਼ਲ ਵਜੋਂ ਸਟੋਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ |

## v3.8.0 ਤੋਂ ਪਹਿਲਾਂ ਬਣਾਏ ਗਏ ਕਨੈਕਸ਼ਨਾਂ ਲਈ ਮਾਈਗ੍ਰੇਸ਼ਨ ਨੋਟ

v3.8.0 ਤੋਂ ਪਹਿਲਾਂ ਇੰਪੋਰਟ ਕੀਤੇ ਗਏ ਕਨੈਕਸ਼ਨਾਂ ਕੋਲ `providerSpecificData` ਵਿੱਚ ਸਟੋਰ ਕੀਤੀ ਗਈ ਕੋਈ ਸਮਰਪਿਤ OIDC ਕਲਾਇੰਟ ਰਜਿਸਟ੍ਰੇਸ਼ਨ
ਨਹੀਂ ਹੁੰਦੀ। ਇਹ ਕਨੈਕਸ਼ਨ ਕੰਮ ਕਰਨਾ ਜਾਰੀ ਰੱਖਦੇ ਹਨ, ਪਰ ਸਾਂਝੇ
ਸੋਸ਼ਲ-ਪ੍ਰਮਾਣੀਕਰਨ ਰਿਫ੍ਰੈਸ਼ ਐਂਡਪੌਇੰਟ ਦੀ ਵਰਤੋਂ ਕਰਦੇ ਹਨ, ਜਿਸਦਾ ਮਤਲਬ ਹੈ ਕਿ ਅਜਿਹੇ ਦੋ ਕਨੈਕਸ਼ਨ ਹਾਲੇ ਵੀ ਇੱਕ-ਦੂਜੇ ਨੂੰ ਅਵੈਧ ਕਰ ਸਕਦੇ
ਹਨ।

**ਅਲੱਗਾਵ ਪ੍ਰਾਪਤ ਕਰਨ ਲਈ:** **ਡੈਸ਼ਬੋਰਡ → ਪ੍ਰਦਾਤਾ** ਤੋਂ ਪੁਰਾਣਾ ਕਨੈਕਸ਼ਨ ਮਿਟਾਓ ਅਤੇ
ਸਮਰਥਿਤ ਇੰਪੋਰਟ ਪ੍ਰਵਾਹਾਂ ਵਿੱਚੋਂ ਕਿਸੇ ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਇਸਨੂੰ ਮੁੜ ਇੰਪੋਰਟ ਕਰੋ। ਨਵੇਂ ਬਣਾਏ ਗਏ ਸਾਰੇ ਕਨੈਕਸ਼ਨਾਂ ਨੂੰ
ਆਪਣੀ ਕਲਾਇੰਟ ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਆਪਣੇ-ਆਪ ਮਿਲੇਗੀ।

## ਦੋ Kiro ਖਾਤਿਆਂ ਨੂੰ ਨਾਲ-ਨਾਲ ਸ਼ਾਮਲ ਕਰਨਾ

### ਪੂਰਵ-ਲੋੜਾਂ

- OmniRoute v3.8.0 ਜਾਂ ਇਸ ਤੋਂ ਬਾਅਦ ਦਾ ਵਰਜਨ।
- ਇੱਕ ਕਾਰਜਸ਼ੀਲ Kiro ਖਾਤਾ (ਈਮੇਲ + ਪਾਸਵਰਡ, Google, ਜਾਂ GitHub ਲੌਗਇਨ)।
- ਵਿਕਲਪਿਕ ਤੌਰ ਉੱਤੇ ਇੱਕ ਦੂਜਾ Kiro ਖਾਤਾ।

### ਕਦਮ 1: ਪਹਿਲਾ ਖਾਤਾ ਇੰਪੋਰਟ ਕਰੋ

1. **ਡੈਸ਼ਬੋਰਡ → ਪ੍ਰਦਾਤਾ → ਪ੍ਰਦਾਤਾ ਸ਼ਾਮਲ ਕਰੋ → Kiro** ਖੋਲ੍ਹੋ।
2. ਇਹਨਾਂ ਵਿੱਚੋਂ ਇੱਕ ਚੁਣੋ:
   - **ਟੋਕਨ ਇੰਪੋਰਟ ਕਰੋ** — `aorAAAAAG` ਨਾਲ ਸ਼ੁਰੂ ਹੋਣ ਵਾਲਾ ਰਿਫ੍ਰੈਸ਼ ਟੋਕਨ ਪੇਸਟ ਕਰੋ।
   - **API ਕੁੰਜੀ** — ਲੰਬੀ ਮਿਆਦ ਵਾਲੀ Kiro / CodeWhisperer API ਕੁੰਜੀ ਪੇਸਟ ਕਰੋ।
   - **Google / GitHub ਲੌਗਇਨ** — ਬ੍ਰਾਊਜ਼ਰ ਵਿੱਚ OAuth ਪ੍ਰਵਾਹ ਪੂਰਾ ਕਰੋ।
   - **ਆਟੋ-ਇੰਪੋਰਟ** — ਬਟਨ ਉੱਤੇ ਕਲਿੱਕ ਕਰੋ; OmniRoute ਲੋਕਲ kiro-cli ਡਾਟਾਬੇਸ ਜਾਂ `~/.aws/sso/cache` ਤੋਂ ਕ੍ਰੈਡੈਂਸ਼ਲ ਪੜ੍ਹਦਾ ਹੈ।
3. ਕਨੈਕਸ਼ਨ ਸੁਰੱਖਿਅਤ ਹੋ ਜਾਂਦਾ ਹੈ। ਰਿਫ੍ਰੈਸ਼-ਟੋਕਨ ਪ੍ਰਵਾਹ ਆਪਣੇ-ਆਪ ਇੱਕ ਸਮਰਪਿਤ
   OIDC ਕਲਾਇੰਟ ਰਜਿਸਟਰ ਕਰਦੇ ਹਨ। API-key ਪ੍ਰਵਾਹ AWS ਨਾਲ ਕੁੰਜੀ ਦੀ ਪੁਸ਼ਟੀ ਕਰਦੇ ਹਨ ਅਤੇ ਰਿਫ੍ਰੈਸ਼ ਟੋਕਨ ਸਟੋਰ ਨਹੀਂ ਕਰਦੇ।

### ਕਦਮ 2: ਦੂਜਾ ਖਾਤਾ ਇੰਪੋਰਟ ਕਰੋ

ਦੂਜੇ ਖਾਤੇ ਲਈ ਕਦਮ 1 ਦੁਹਰਾਓ। ਕਿਉਂਕਿ ਹਰੇਕ ਇੰਪੋਰਟ ਇੱਕ ਵੱਖਰੀ OIDC
ਕਲਾਇੰਟ ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਬਣਾਉਂਦਾ ਹੈ, ਦੋਵੇਂ ਕਨੈਕਸ਼ਨ ਪੂਰੀ ਤਰ੍ਹਾਂ ਅਲੱਗ ਰਹਿੰਦੇ ਹਨ।

### ਕਦਮ 3: ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਦੋਵੇਂ ਕਨੈਕਸ਼ਨ ਸਰਗਰਮ ਹਨ

1. **ਡੈਸ਼ਬੋਰਡ → ਪ੍ਰਦਾਤਾ** — ਦੋਵੇਂ Kiro ਕਨੈਕਸ਼ਨਾਂ ਦੀ ਸਥਿਤੀ **ਸਰਗਰਮ** ਦਿਖਾਈ ਦੇਣੀ ਚਾਹੀਦੀ ਹੈ।
2. **ਡੈਸ਼ਬੋਰਡ → ਸਿਹਤ** — ਦੋਵੇਂ ਕਨੈਕਸ਼ਨਾਂ ਨੂੰ ਆਪਣੀ ਟੋਕਨ ਸਿਹਤ ਜਾਂਚ ਪਾਸ ਕਰਨੀ ਚਾਹੀਦੀ ਹੈ।

### ਕਦਮ 4: ਖਾਤਿਆਂ ਵਿਚਕਾਰ ਰੂਟ ਕਰਨ ਲਈ ਇੱਕ ਕੌਂਬੋ ਵਰਤੋ

ਉਹਨਾਂ ਵਿਚਕਾਰ ਲੋਡ-ਬੈਲੈਂਸ ਜਾਂ ਫਾਲਬੈਕ ਕਰਨ ਲਈ ਦੋਵੇਂ ਕਨੈਕਸ਼ਨਾਂ ਨੂੰ ਟਾਰਗੇਟਾਂ ਵਜੋਂ ਰੱਖ ਕੇ ਇੱਕ ਕੌਂਬੋ ਬਣਾਓ:

```
kiro/kiro-dev → kiro/kiro-pro
```

ਕੌਂਬੋ ਸੰਰਚਨਾ ਲਈ [FEATURES.md](./FEATURES.md) ਅਤੇ ਰੂਟਿੰਗ ਦਸਤਾਵੇਜ਼ ਵੇਖੋ।

## ਐਂਟਰਪ੍ਰਾਈਜ਼ / IDC ਵਰਤੋਂਕਾਰ

AWS IAM Identity Center (IDC) ਖਾਤਿਆਂ ਲਈ, **Dashboard → Providers → Kiro → Device Code** ਤੋਂ **AWS Builder ID / IDC ਡਿਵਾਈਸ-ਕੋਡ** ਪ੍ਰਵਾਹ ਵਰਤੋ। ਡਿਵਾਈਸ-ਕੋਡ ਪ੍ਰਵਾਹ ਹਮੇਸ਼ਾ ਤੋਂ ਪੂਰੀ ਤਰ੍ਹਾਂ ਅਲੱਗ ਰਿਹਾ ਹੈ। ਇਨ੍ਹਾਂ ਕਨੈਕਸ਼ਨਾਂ ਲਈ ਮੁੜ-ਇੰਪੋਰਟ ਕਰਨ ਦੀ ਲੋੜ ਨਹੀਂ ਹੈ।

ਉਹ ਐਂਟਰਪ੍ਰਾਈਜ਼ ਵਰਤੋਂਕਾਰ, ਜੋ ਕਿਸੇ ਗੈਰ-ਡਿਫਾਲਟ AWS ਖੇਤਰ ਵਿੱਚ ਕੰਮ ਕਰਦੇ ਹਨ, Import Token API ਰਾਹੀਂ ਇੰਪੋਰਟ ਕਰਦੇ ਸਮੇਂ ਖੇਤਰ ਨਿਰਧਾਰਤ ਕਰ ਸਕਦੇ ਹਨ:

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/import \
  -H "Content-Type: application/json" \
  -d '{"refreshToken": "aorAAAAAG...", "region": "eu-west-1"}'
```

ਜੇ `region` ਫੀਲਡ ਛੱਡ ਦਿੱਤਾ ਜਾਵੇ, ਤਾਂ ਇਹ ਡਿਫਾਲਟ ਰੂਪ ਵਿੱਚ `us-east-1` ਹੁੰਦਾ ਹੈ।

## API-ਕੁੰਜੀ ਇੰਪੋਰਟ ਪ੍ਰਵਾਹ

API-ਕੁੰਜੀ ਪ੍ਰਮਾਣੀਕਰਨ ਲੰਬੇ ਸਮੇਂ ਲਈ ਵਰਤੇ ਜਾਣ ਵਾਲੇ Kiro / AWS CodeWhisperer ਬੇਅਰਰ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲਾਂ ਲਈ ਹੈ। ਇਹ OAuth ਰਿਫ੍ਰੈਸ਼ ਨਹੀਂ ਵਰਤਦਾ, ਇਸ ਲਈ ਸਾਂਝੇ OIDC ਸੈਸ਼ਨ ਦੇ ਅਵੈਧ ਹੋਣ ਤੋਂ ਬਚਦਾ ਹੈ।

### ਡੈਸ਼ਬੋਰਡ

1. **Dashboard -> Providers -> Kiro** ਖੋਲ੍ਹੋ।
2. **API Key** ਚੁਣੋ।
3. API ਕੁੰਜੀ ਅਤੇ ਵਿਕਲਪਿਕ AWS ਖੇਤਰ ਪੇਸਟ ਕਰੋ (ਡਿਫਾਲਟ ਰੂਪ ਵਿੱਚ `us-east-1`)।
4. OmniRoute ਕੁੰਜੀ ਨੂੰ ਪ੍ਰਮਾਣਿਤ ਕਰਦਾ ਹੈ ਅਤੇ ਕਨੈਕਸ਼ਨ ਸੰਭਾਲਦਾ ਹੈ।

### API

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/api-key \
  -H "Content-Type: application/json" \
  -d '{"apiKey": "kiro_or_codewhisperer_key", "region": "us-east-1"}'
```

### ਅੰਦਰੂਨੀ ਇਕਰਾਰਨਾਮਾ

API ਰੂਟ `KiroService.validateApiKey()` ਨੂੰ ਕਾਲ ਕਰਕੇ ਕੁੰਜੀ ਨੂੰ ਪ੍ਰਮਾਣਿਤ ਕਰਦਾ ਹੈ, ਜੋ ਖੇਤਰ ਨਾਲ ਮੇਲ ਖਾਂਦੇ CodeWhisperer/Amazon Q ਐਂਡਪੌਇੰਟ ਦੇ ਵਿਰੁੱਧ `ListAvailableProfiles` ਵਰਤਦਾ ਹੈ ਅਤੇ ਇੱਕ `profileArn` ਨਿਰਧਾਰਤ ਕਰਦਾ ਹੈ।

ਸੰਭਾਲਿਆ ਗਿਆ ਕਨੈਕਸ਼ਨ ਇਹ ਵਰਤਦਾ ਹੈ:

```json
{
  "authType": "apikey",
  "providerSpecificData": {
    "authMethod": "api_key",
    "region": "us-east-1",
    "profileArn": "arn:aws:codewhisperer:..."
  }
}
```

ਰਨਟਾਈਮ ਦੌਰਾਨ, `KiroExecutor.buildHeaders()` ਕੁੰਜੀ ਨੂੰ `Authorization: Bearer <key>` ਵਜੋਂ ਭੇਜਦਾ ਹੈ ਅਤੇ `tokentype: API_KEY` ਜੋੜਦਾ ਹੈ। ਕੋਟਾ/ਪ੍ਰੋਫਾਈਲ ਕਾਲਾਂ ਵੀ ਇਹੀ ਮਾਰਕਰ ਵਰਤਦੀਆਂ ਹਨ, ਤਾਂ ਜੋ AWS ਬੇਅਰਰ ਨੂੰ OIDC ਜਾਂ ਸੋਸ਼ਲ ਐਕਸੈੱਸ ਟੋਕਨ ਦੀ ਬਜਾਏ ਲੰਬੇ ਸਮੇਂ ਲਈ ਵਰਤੀ ਜਾਣ ਵਾਲੀ API ਕੁੰਜੀ ਮੰਨੇ।

## OIDC ਕਲਾਇੰਟ ਦੀ ਮਿਆਦ ਸਮਾਪਤੀ

AWS SSO OIDC ਪਬਲਿਕ ਕਲਾਇੰਟਾਂ ਦੀ ਮਿਆਦ ਆਮ ਤੌਰ 'ਤੇ 90 ਦਿਨਾਂ ਬਾਅਦ ਸਮਾਪਤ ਹੋ ਜਾਂਦੀ ਹੈ (`clientSecretExpiresAt`)। ਨਿਗਰਾਨੀਯੋਗਤਾ ਲਈ OmniRoute ਇਸ ਟਾਈਮਸਟੈਂਪ ਨੂੰ `providerSpecificData` ਵਿੱਚ ਸਟੋਰ ਕਰਦਾ ਹੈ। ਜੇ ਕੋਈ ਕਨੈਕਸ਼ਨ ~90 ਦਿਨਾਂ ਬਾਅਦ ਰਿਫ੍ਰੈਸ਼ ਹੋਣਾ ਬੰਦ ਕਰ ਦੇਵੇ, ਤਾਂ ਨਵੀਂ OIDC ਕਲਾਇੰਟ ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਪ੍ਰਾਪਤ ਕਰਨ ਲਈ ਕਨੈਕਸ਼ਨ ਨੂੰ ਮੁੜ-ਇੰਪੋਰਟ ਕਰੋ। ਮਿਆਦ ਸਮਾਪਤ ਹੋਣ 'ਤੇ ਆਟੋਮੈਟਿਕ ਮੁੜ-ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਨੂੰ ਭਵਿੱਖੀ ਸੁਧਾਰ ਵਜੋਂ ਟ੍ਰੈਕ ਕੀਤਾ ਜਾ ਰਿਹਾ ਹੈ।

API-ਕੁੰਜੀ ਕਨੈਕਸ਼ਨਾਂ ਵਿੱਚ OIDC ਕਲਾਇੰਟ ਮਿਆਦ ਸਮਾਪਤੀ ਨਹੀਂ ਹੁੰਦੀ, ਕਿਉਂਕਿ ਉਹ AWS SSO OIDC ਰਾਹੀਂ ਰਿਫ੍ਰੈਸ਼ ਨਹੀਂ ਹੁੰਦੇ।

## ਸਮੱਸਿਆ-ਨਿਵਾਰਣ

### ਦੂਜਾ ਖਾਤਾ ਵਾਰ-ਵਾਰ ਲੌਗ ਆਉਟ ਹੋ ਰਿਹਾ ਹੈ

- **Dashboard → Providers** ਵਿੱਚ ਦੋਵੇਂ ਕਨੈਕਸ਼ਨਾਂ ਦੀ ਜਾਂਚ ਕਰੋ ਅਤੇ ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਹਰੇਕ ਆਪਣੇ ਰਾਅ JSON ਵਿੱਚ ਇੱਕ ਗੈਰ-null `clientId` ਦਿਖਾਉਂਦਾ ਹੈ (ਜਾਣਕਾਰੀ ਆਈਕਨ ਰਾਹੀਂ ਵੇਖਣਯੋਗ)। ਜੇ ਕਿਸੇ ਵੀ ਕਨੈਕਸ਼ਨ ਵਿੱਚ `clientId` ਮੌਜੂਦ ਨਹੀਂ ਹੈ, ਤਾਂ ਉਹ v3.8.0 ਤੋਂ ਪਹਿਲਾਂ ਇੰਪੋਰਟ ਕੀਤਾ ਗਿਆ ਸੀ — ਉਸਨੂੰ ਮੁੜ-ਇੰਪੋਰਟ ਕਰੋ।

### "Token validation failed" ਨਾਲ ਇੰਪੋਰਟ ਅਸਫਲ ਹੁੰਦਾ ਹੈ

- ਯਕੀਨੀ ਬਣਾਓ ਕਿ ਰਿਫ੍ਰੈਸ਼ ਟੋਕਨ `aorAAAAAG` ਨਾਲ ਸ਼ੁਰੂ ਹੁੰਦਾ ਹੈ।
- ਯਕੀਨੀ ਬਣਾਓ ਕਿ OmniRoute `https://oidc.us-east-1.amazonaws.com` (ਜਾਂ ਸੰਰਚਿਤ ਖੇਤਰ) ਤੱਕ ਪਹੁੰਚ ਸਕਦਾ ਹੈ। ਜੇ ਤੁਸੀਂ ਕਿਸੇ ਕਾਰਪੋਰੇਟ ਪ੍ਰੌਕਸੀ ਦੇ ਪਿੱਛੇ ਹੋ, ਤਾਂ **Dashboard → Settings → Proxies** ਵਿੱਚ ਪ੍ਰੋਵਾਈਡਰ-ਪੱਧਰੀ ਪ੍ਰੌਕਸੀ ਸੈੱਟ ਕਰੋ।

### API-ਕੁੰਜੀ ਇੰਪੋਰਟ ਅਸਫਲ ਹੁੰਦਾ ਹੈ

- ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਕੁੰਜੀ ਇੱਕ Kiro / CodeWhisperer API ਕੁੰਜੀ ਹੈ, ਰਿਫ੍ਰੈਸ਼ ਟੋਕਨ ਨਹੀਂ।
- ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ AWS ਖੇਤਰ ਕੁੰਜੀ/ਖਾਤੇ ਨਾਲ ਮੇਲ ਖਾਂਦਾ ਹੈ। `us-east-1` ਡਿਫਾਲਟ ਹੈ।
- ਕੁੰਜੀ `ListAvailableProfiles` ਨੂੰ ਕਾਲ ਕਰਨ ਦੇ ਯੋਗ ਹੋਣੀ ਚਾਹੀਦੀ ਹੈ; ਨਹੀਂ ਤਾਂ OmniRoute ਲੋੜੀਂਦਾ `profileArn` ਨਿਰਧਾਰਤ ਨਹੀਂ ਕਰ ਸਕਦਾ।

ਹੋਰ ਸਮੱਸਿਆਵਾਂ ਲਈ, ਮੁੱਖ [TROUBLESHOOTING.md](./TROUBLESHOOTING.md) ਵੇਖੋ।
