OmniRoute ਨੂੰ Termux ਰਾਹੀਂ Android ਉੱਤੇ ਇੱਕ ਹੈੱਡਲੈੱਸ ਸਰਵਰ ਵਜੋਂ ਚਲਾਇਆ ਜਾ ਸਕਦਾ ਹੈ। Electron ਡੈਸਕਟਾਪ ਐਪ Termux ਵਿੱਚ ਸਮਰਥਿਤ ਨਹੀਂ ਹੈ, ਪਰ ਵੈੱਬ ਡੈਸ਼ਬੋਰਡ ਅਤੇ OpenAI-ਅਨੁਕੂਲ API ਸਥਾਨਕ ਬ੍ਰਾਊਜ਼ਰ ਜਾਂ ਉਸੇ ਨੈੱਟਵਰਕ ਉੱਤੇ ਮੌਜੂਦ ਹੋਰ ਡਿਵਾਈਸਾਂ ਤੋਂ ਕੰਮ ਕਰਦੇ ਹਨ।

## ਪੂਰਵ-ਲੋੜਾਂ

F-Droid ਜਾਂ GitHub ਰਿਲੀਜ਼ਾਂ ਤੋਂ Termux ਇੰਸਟਾਲ ਕਰੋ, ਫਿਰ ਪੈਕੇਜ ਅੱਪਡੇਟ ਕਰੋ ਅਤੇ `better-sqlite3` ਵਰਗੀਆਂ ਨੇਟਿਵ ਡਿਪੈਂਡੈਂਸੀਆਂ ਲਈ ਲੋੜੀਂਦੇ ਬਿਲਡ ਟੂਲ ਇੰਸਟਾਲ ਕਰੋ।

```bash
pkg update
pkg upgrade
pkg install nodejs python build-essential git
```

> **Node.js ਵਰਜਨ:** OmniRoute ਲਈ Node `>=22.22.2 <23 || >=24.0.0 <27` ਲੋੜੀਂਦਾ ਹੈ (`package.json` / `SUPPORTED_NODE_RANGE` ਵਿੱਚ ਦਿੱਤੇ `engines` ਨਾਲ ਮੇਲ ਖਾਂਦਾ ਹੈ)। Termux ਦਾ `nodejs-lts` ਆਮ ਤੌਰ 'ਤੇ Node 20 LTS ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ, ਜੋ **ਹੁਣ ਸਮਰਥਿਤ ਨਹੀਂ ਹੈ** — ਇਸ ਦੀ ਬਜਾਏ `pkg install nodejs` (ਮੌਜੂਦਾ) ਇੰਸਟਾਲ ਕਰੋ ਅਤੇ ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ `node --version` 22.x/24.x+ ਲੜੀ ਦਿਖਾਉਂਦਾ ਹੈ।

ਜੇ ਨੇਟਿਵ ਪੈਕੇਜ ਕੰਪਾਇਲੇਸ਼ਨ ਅਸਫਲ ਹੁੰਦੀ ਹੈ, ਤਾਂ ਉੱਪਰ ਦਿੱਤੀ `pkg install` ਕਮਾਂਡ ਦੁਬਾਰਾ ਚਲਾਓ ਅਤੇ ਫਿਰ OmniRoute ਦੀ ਇੰਸਟਾਲੇਸ਼ਨ ਮੁੜ ਅਜ਼ਮਾਓ।

## ਇੰਸਟਾਲੇਸ਼ਨ

ਸਭ ਤੋਂ ਨਵਾਂ ਪ੍ਰਕਾਸ਼ਿਤ ਪੈਕੇਜ ਸਿੱਧਾ ਚਲਾਓ:

```bash
npx -y omniroute@latest
```

ਤੁਸੀਂ ਇਸਨੂੰ ਗਲੋਬਲ ਤੌਰ 'ਤੇ ਵੀ ਇੰਸਟਾਲ ਕਰ ਸਕਦੇ ਹੋ:

```bash
npm install -g omniroute
omniroute
```

## ਚਲਾਉਣਾ

OmniRoute ਨੂੰ ਹੈੱਡਲੈੱਸ ਸਰਵਰ ਮੋਡ ਵਿੱਚ ਸ਼ੁਰੂ ਕਰੋ:

```bash
omniroute
```

ਜਾਂ:

```bash
npx omniroute
```

ਡੈਸ਼ਬੋਰਡ ਇੱਥੇ ਸੁਣਦਾ ਹੈ:

```text
http://localhost:20128
```

ਉਸ URL ਨੂੰ Android ਬ੍ਰਾਊਜ਼ਰ ਵਿੱਚ ਖੋਲ੍ਹੋ। ਜੇ ਤੁਸੀਂ Termux ਦੇ ਅੰਦਰ ਕਲਾਇੰਟ ਚਲਾਉਂਦੇ ਹੋ, ਤਾਂ OpenAI-ਅਨੁਕੂਲ ਬੇਸ URL ਵਜੋਂ ਉਹੀ ਹੋਸਟ ਅਤੇ ਪੋਰਟ ਵਰਤੋ।

## ਬੈਕਗ੍ਰਾਊਂਡ ਵਿੱਚ ਚਲਾਉਣਾ

ਇੱਕ ਸਧਾਰਨ ਬੈਕਗ੍ਰਾਊਂਡ ਪ੍ਰਕਿਰਿਆ ਲਈ:

```bash
nohup omniroute > omniroute.log 2>&1 &
```

ਇਸਨੂੰ ਰੋਕਣ ਲਈ:

```bash
pkill -f omniroute
```

ਡਿਵਾਈਸ ਬੂਟ ਹੋਣ ਤੋਂ ਬਾਅਦ ਆਪਣੇ ਆਪ ਸ਼ੁਰੂ ਕਰਨ ਲਈ, Termux:Boot ਐਡ-ਆਨ ਇੰਸਟਾਲ ਕਰੋ ਅਤੇ ਇੱਕ ਬੂਟ ਸਕ੍ਰਿਪਟ ਬਣਾਓ:

```bash
mkdir -p ~/.termux/boot
cat > ~/.termux/boot/omniroute.sh <<'EOF'
#!/data/data/com.termux/files/usr/bin/sh
cd "$HOME"
nohup omniroute > "$HOME/omniroute.log" 2>&1 &
EOF
chmod +x ~/.termux/boot/omniroute.sh
```

Android ਦੀ ਬੈਟਰੀ ਆਪਟੀਮਾਈਜ਼ੇਸ਼ਨ ਲੰਬੇ ਸਮੇਂ ਤੱਕ ਚੱਲਣ ਵਾਲੀਆਂ ਬੈਕਗ੍ਰਾਊਂਡ ਪ੍ਰਕਿਰਿਆਵਾਂ ਨੂੰ ਰੋਕ ਸਕਦੀ ਹੈ। ਜੇ ਸਰਵਰ ਨੂੰ ਆਨਲਾਈਨ ਰੱਖਣਾ ਹੈ, ਤਾਂ Termux ਲਈ ਬੈਟਰੀ ਆਪਟੀਮਾਈਜ਼ੇਸ਼ਨ ਅਯੋਗ ਕਰੋ।

## ਹੋਰ ਡਿਵਾਈਸਾਂ ਤੋਂ ਪਹੁੰਚ

WiFi ਨੈੱਟਵਰਕ ਉੱਤੇ ਫ਼ੋਨ ਦਾ IP ਪਤਾ ਲੱਭੋ:

```bash
ip addr show wlan0
```

ਫਿਰ ਕਿਸੇ ਹੋਰ ਡਿਵਾਈਸ ਤੋਂ ਡੈਸ਼ਬੋਰਡ ਖੋਲ੍ਹੋ:

```text
http://PHONE_IP:20128
```

ਉਦਾਹਰਨ ਲਈ:

```text
http://192.168.1.50:20128
```

ਫ਼ੋਨ ਅਤੇ ਕਲਾਇੰਟ ਨੂੰ ਇੱਕੋ ਭਰੋਸੇਯੋਗ ਨੈੱਟਵਰਕ ਉੱਤੇ ਰੱਖੋ। ਜੇ ਤੁਸੀਂ OmniRoute ਨੂੰ ਫ਼ੋਨ ਤੋਂ ਬਾਹਰ ਉਪਲਬਧ ਕਰਵਾਉਂਦੇ ਹੋ, ਤਾਂ API ਕੁੰਜੀਆਂ ਅਤੇ ਡੈਸ਼ਬੋਰਡ ਪ੍ਰਮਾਣੀਕਰਨ ਸਮਰੱਥ ਕਰੋ।

## ਡਾਟਾ ਡਾਇਰੈਕਟਰੀ

ਮੂਲ ਰੂਪ ਵਿੱਚ OmniRoute, Linux ਉੱਤੇ ਵਰਤੇ ਜਾਂਦੇ ਉਸੇ ਸਰਵਰ-ਸਾਈਡ ਡਾਟਾ ਪਾਥ ਵਿਵਹਾਰ ਦੀ ਪਾਲਣਾ ਕਰਦੇ ਹੋਏ, ਡਾਟਾ ਨੂੰ Termux ਹੋਮ ਡਾਇਰੈਕਟਰੀ ਹੇਠ ਸਟੋਰ ਕਰਦਾ ਹੈ। ਡਾਟਾਬੇਸ ਨੂੰ ਕਿਸੇ ਸਪਸ਼ਟ ਟਿਕਾਣੇ ਉੱਤੇ ਰੱਖਣ ਲਈ:

```bash
export DATA_DIR="$HOME/.omniroute"
omniroute
```

## ਸੀਮਾਵਾਂ

- Electron, Termux ਵਿੱਚ ਨਹੀਂ ਚੱਲਦਾ।
- ਕੋਈ ਸਿਸਟਮ ਟਰੇ ਜਾਂ ਡੈਸਕਟਾਪ ਏਕੀਕਰਨ ਨਹੀਂ ਹੈ।
- ਇਹ ਸੈੱਟਅੱਪ ਕੇਵਲ ਸਰਵਰ ਲਈ ਹੈ: ਬ੍ਰਾਊਜ਼ਰ ਡੈਸ਼ਬੋਰਡ ਵਰਤੋ।
- ਨੇਟਿਵ ਡਿਪੈਂਡੈਂਸੀਆਂ ਨੂੰ ਸਥਾਨਕ ਕੰਪਾਇਲੇਸ਼ਨ ਦੀ ਲੋੜ ਪੈ ਸਕਦੀ ਹੈ।
- ਘੱਟ ਮੈਮੋਰੀ ਵਾਲੇ Android ਡਿਵਾਈਸਾਂ ਉੱਤੇ ਘੱਟ ਸਮਕਾਲੀ ਬੇਨਤੀਆਂ ਦੀ ਲੋੜ ਪੈ ਸਕਦੀ ਹੈ।
- MITM/ਸਿਸਟਮ ਸਰਟੀਫਿਕੇਟ ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ ਲਈ Termux ਤੋਂ ਬਾਹਰ Android-ਪੱਧਰੀ ਟਰੱਸਟ-ਸਟੋਰ ਸੰਬੰਧੀ ਕੰਮ ਦੀ ਲੋੜ ਪੈ ਸਕਦੀ ਹੈ।

## ਸਮੱਸਿਆ-ਨਿਵਾਰਣ

### ਅਸਮਰਥਿਤ ਪਲੇਟਫਾਰਮ: android (ਹਰ ਬੇਨਤੀ HTTP 500 ਵਾਪਸ ਕਰਦੀ ਹੈ)

**ਲੱਛਣ:** `omniroute` / `omniroute serve`, `✔ OmniRoute is running!` ਪ੍ਰਿੰਟ ਕਰਦਾ ਹੈ, ਪਰ ਹਰ ਡੈਸ਼ਬੋਰਡ ਜਾਂ API ਬੇਨਤੀ ਇੱਕ ਸਧਾਰਨ `500 Internal Server Error` ਵਾਪਸ ਕਰਦੀ ਹੈ। `~/.omniroute/logs/application/app.log` ਖਾਲੀ ਰਹਿੰਦੀ ਹੈ, `APP_LOG_LEVEL=debug` ਕੁਝ ਵੀ ਲਾਭਦਾਇਕ ਪ੍ਰਿੰਟ ਨਹੀਂ ਕਰਦਾ, ਅਤੇ ਜਵਾਬ ਦਾ ਮੁੱਖ ਭਾਗ ਬਿਨਾਂ ਕਿਸੇ JSON ਵੇਰਵੇ ਦੇ ਸਧਾਰਨ ਟੈਕਸਟ (`Internal Server Error`) ਹੁੰਦਾ ਹੈ।

**ਕਾਰਨ:** ਕੁਝ Termux/Node ਬਿਲਡ `process.platform === "android"` ਰਿਪੋਰਟ ਕਰਦੇ ਹਨ। Next.js ਦਾ `getCacheDirectory()` ਉਸ ਪਲੇਟਫਾਰਮ ਨੂੰ ਸੰਭਾਲਦਾ ਨਹੀਂ ਹੈ: ਇਸ ਲਈ `~/.cache` (ਜਾਂ ਕੋਈ ਆਮ tmp ਡਾਇਰੈਕਟਰੀ) ਦਾ _ਪਹਿਲਾਂ ਤੋਂ_ ਮੌਜੂਦ ਹੋਣਾ ਲਾਜ਼ਮੀ ਹੈ, ਨਹੀਂ ਤਾਂ ਇੰਸਟਰੂਮੈਂਟੇਸ਼ਨ ਹੁੱਕ ਲੋਡ ਕਰਦੇ ਸਮੇਂ ਇਹ ਹੇਠਾਂ ਦਿੱਤੀ ਗਲਤੀ ਨਾਲ ਅਸਫਲ ਹੋ ਜਾਂਦਾ ਹੈ:

```text
Error: An error occurred while loading instrumentation hook: Unsupported platform: android
```

ਕਿਉਂਕਿ ਹੁੱਕ ਕਦੇ ਲੋਡ ਨਹੀਂ ਹੁੰਦਾ, ਲੌਗਿੰਗ ਕਦੇ ਸ਼ੁਰੂ ਨਹੀਂ ਹੁੰਦੀ — ਇਸ ਲਈ 500 ਗਲਤੀ ਦਾ ਕਾਰਨ ਪਤਾ ਲਗਾਉਣਾ ਬਿਲਕੁਲ ਅਸੰਭਵ ਜਾਪਦਾ ਹੈ। Next.js ਦੇ ਸ਼ੁਰੂ ਹੋਣ ਤੋਂ ਪਹਿਲਾਂ OmniRoute, CLI ਐਂਟਰੀਪੁਆਇੰਟ ਵਿੱਚ `~/.cache` ਬਣਾਉਂਦਾ ਹੈ (ਅਤੇ ਜਦੋਂ `XDG_CACHE_HOME` ਸੈੱਟ ਨਾ ਹੋਵੇ ਤਾਂ ਉਸਨੂੰ ਸੈੱਟ ਕਰਦਾ ਹੈ), ਤਾਂ ਜੋ ਇਹ ਜਾਂਚ Android/Termux ਉੱਤੇ ਸਫਲ ਹੋ ਸਕੇ।

**ਸਮਰਥਿਤ ਹੱਲ (ਪੈਕੇਜ ਵਿੱਚ ਸੋਧ ਕੀਤੇ ਬਿਨਾਂ):**

```bash
mkdir -p ~/.cache
omniroute serve
```

OmniRoute ਦੇ ਮੌਜੂਦਾ ਬਿਲਡਾਂ ਵਿੱਚ CLI ਇਹ ਕੰਮ Android/Termux ਉੱਤੇ ਆਪਣੇ ਆਪ ਕਰਦਾ ਹੈ — ਇੱਕ ਨਵੀਂ `npx -y omniroute@latest` / ਗਲੋਬਲ ਇੰਸਟਾਲੇਸ਼ਨ ਲਈ ਇਸ ਹੱਥੀਂ ਕਦਮ ਦੀ ਲੋੜ ਨਹੀਂ ਹੋਣੀ ਚਾਹੀਦੀ। ਜੇ ਅੱਪਗ੍ਰੇਡ ਕਰਨ ਤੋਂ ਬਾਅਦ ਵੀ ਤੁਹਾਨੂੰ ਇਹ ਗਲਤੀ ਦਿਖਾਈ ਦਿੰਦੀ ਹੈ, ਤਾਂ ਉੱਪਰ ਦਿੱਤੇ ਅਨੁਸਾਰ ਇੱਕ ਵਾਰ `~/.cache` ਬਣਾਓ ਅਤੇ ਮੁੜ ਸ਼ੁਰੂ ਕਰੋ।

`process.platform = "linux"` ਨੂੰ ਜ਼ਬਰਦਸਤੀ ਸੈੱਟ ਕਰਨ ਲਈ `dist/server.js` ਵਿੱਚ ਸੋਧ **ਨਾ ਕਰੋ**। ਇਸ ਕਿਸਮ ਦੀ ਪੈਕੇਜ ਸੋਧ ਹਰ ਮੁੜ-ਇੰਸਟਾਲੇਸ਼ਨ/ਅੱਪਗ੍ਰੇਡ ਉੱਤੇ ਓਵਰਰਾਈਟ ਹੋ ਜਾਂਦੀ ਹੈ ਅਤੇ ਕੈਸ਼ ਡਾਇਰੈਕਟਰੀ ਮੌਜੂਦ ਹੋਣ ਤੋਂ ਬਾਅਦ ਇਸਦੀ ਲੋੜ ਨਹੀਂ ਰਹਿੰਦੀ।

### better-sqlite3 ਬਿਲਡ ਗਲਤੀਆਂ

Termux ਬਿਲਡ ਟੂਲਚੇਨ ਇੰਸਟਾਲ ਕਰੋ:

```bash
pkg install nodejs python build-essential
```

ਫਿਰ ਮੁੜ ਚਲਾਓ:

```bash
npx -y omniroute@latest
```

### ਪੋਰਟ ਪਹਿਲਾਂ ਹੀ ਵਰਤੋਂ ਵਿੱਚ ਹੈ

ਜਾਂਚ ਕਰੋ ਕਿ ਡਿਫਾਲਟ ਪੋਰਟ ਉੱਤੇ ਕੀ ਸੁਣ ਰਿਹਾ ਹੈ:

```bash
ss -ltnp | grep 20128
```

ਪੁਰਾਣੀ ਪ੍ਰਕਿਰਿਆ ਰੋਕੋ:

```bash
pkill -f omniroute
```

### ਡੈਸ਼ਬੋਰਡ ਕਿਸੇ ਹੋਰ ਡਿਵਾਈਸ ਤੋਂ ਪਹੁੰਚਯੋਗ ਨਹੀਂ ਹੈ

ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਦੋਵੇਂ ਡਿਵਾਈਸ ਇੱਕੋ WiFi ਨੈੱਟਵਰਕ ਉੱਤੇ ਹਨ, ਫਿਰ Termux ਤੋਂ ਜਾਂਚ ਕਰੋ:

```bash
curl http://localhost:20128
```

ਜੇ ਸਥਾਨਕ ਪਹੁੰਚ ਕੰਮ ਕਰਦੀ ਹੈ ਪਰ LAN ਪਹੁੰਚ ਨਹੀਂ ਕਰਦੀ, ਤਾਂ Android ਹੌਟਸਪੌਟ/WiFi ਆਈਸੋਲੇਸ਼ਨ ਅਤੇ ਫ਼ੋਨ ਉੱਤੇ ਕਿਸੇ ਵੀ ਫਾਇਰਵਾਲ ਜਾਂ VPN ਪ੍ਰੋਫ਼ਾਈਲ ਦੀ ਜਾਂਚ ਕਰੋ।
