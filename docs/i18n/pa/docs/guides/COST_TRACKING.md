## ਇਹ ਕੀ ਹੈ (ਅਤੇ ਕੀ ਨਹੀਂ ਹੈ)

OmniRoute ਟੋਕਨਾਂ ਦੀ ਗਿਣਤੀ ਨੂੰ ਮਾਡਲ ਦੀਆਂ ਕੀਮਤ ਦਰਾਂ ਨਾਲ ਗੁਣਾ ਕਰਕੇ ਹਰ ਕੰਪਲੀਸ਼ਨ ਲਈ
ਪ੍ਰਤੀ-ਬੇਨਤੀ USD ਲਾਗਤ ਨਿਰਧਾਰਤ ਕਰਦਾ ਹੈ। ਇਹ ਸੰਖਿਆਵਾਂ **ਲਾਗਤਾਂ** ਡੈਸ਼ਬੋਰਡ,
`omniroute cost` / `omniroute usage` CLI, CSV/JSON ਐਕਸਪੋਰਟਾਂ ਅਤੇ ਪ੍ਰਤੀ-API-ਕੁੰਜੀ ਬਜਟਾਂ ਨੂੰ ਚਲਾਉਂਦੀਆਂ ਹਨ।

> **ਡੈਸ਼ਬੋਰਡ ਦੀ "ਲਾਗਤ" ਇੱਕ ਬੱਚਤ ਟਰੈਕਰ ਹੈ, ਬਿੱਲ ਨਹੀਂ।** OmniRoute ਕਦੇ ਵੀ ਤੁਹਾਡੇ ਤੋਂ
> ਫੀਸ ਨਹੀਂ ਲੈਂਦਾ — ਇਹ ਤੁਹਾਡੀਆਂ ਬੇਨਤੀਆਂ ਨੂੰ ਉਹਨਾਂ ਪ੍ਰਦਾਤਾਵਾਂ ਵੱਲ ਰੂਟ ਕਰਦਾ ਹੈ ਜਿਨ੍ਹਾਂ ਨੂੰ ਤੁਸੀਂ ਪਹਿਲਾਂ ਹੀ
> ਕਨੈਕਟ ਕੀਤਾ ਹੋਇਆ ਹੈ (ਤੁਹਾਡੀਆਂ ਆਪਣੀਆਂ ਸਬਸਕ੍ਰਿਪਸ਼ਨਾਂ, ਮੁਫ਼ਤ ਟੀਅਰਾਂ ਅਤੇ API ਕੁੰਜੀਆਂ)। ਪੂਰੀ ਤਰ੍ਹਾਂ ਮੁਫ਼ਤ
> ਮਾਡਲਾਂ ਉੱਤੇ ਇਕੱਠੀ ਹੋਈ "$290 ਕੁੱਲ ਲਾਗਤ" ਦਾ ਅਰਥ ਹੈ ਕਿ ਤੁਸੀਂ ਕਿਸੇ ਭੁਗਤਾਨਯੋਗ API ਨੂੰ ਲਗਭਗ
> **$290 ਦਾ ਭੁਗਤਾਨ _ਨਹੀਂ_ ਕੀਤਾ**। ਇਹ ਅੰਕੜਾ ਇਸ ਗੱਲ ਦਾ _ਅਨੁਮਾਨ_ ਹੈ ਕਿ ਮਿਆਰੀ ਸੂਚੀ ਕੀਮਤਾਂ ਉੱਤੇ
> ਇਸੇ ਟ੍ਰੈਫ਼ਿਕ ਦੀ ਕਿੰਨੀ ਲਾਗਤ ਹੋਣੀ ਸੀ, ਤਾਂ ਜੋ ਤੁਸੀਂ ਦੇਖ ਸਕੋ ਕਿ ਤੁਹਾਡੀ ਵਰਤੋਂ ਕਿੱਥੇ ਕੇਂਦ੍ਰਿਤ ਹੈ ਅਤੇ
> ਸਸਤੇ/ਮੁਫ਼ਤ ਪ੍ਰਦਾਤਾਵਾਂ ਵੱਲ ਰੂਟਿੰਗ ਕਰਕੇ ਤੁਸੀਂ ਕਿੰਨੀ ਬੱਚਤ ਕਰ ਰਹੇ ਹੋ।

ਇਹ ਵਿਆਖਿਆ ਪ੍ਰੋਜੈਕਟ [README](../../README.md) ਵਿੱਚ ਸਿੱਧੇ ਤੌਰ ਉੱਤੇ ਦਿੱਤੀ ਗਈ ਹੈ ("ਡੈਸ਼ਬੋਰਡ ਦੀ
'ਲਾਗਤ' ਇੱਕ ਬੱਚਤ ਟਰੈਕਰ ਹੈ, ਬਿੱਲ ਨਹੀਂ")।

ਕਿਉਂਕਿ ਇਹ ਸੰਖਿਆ ਇੱਕ ਅਨੁਮਾਨ ਹੈ:

- ਇਹ ਹਰ ਮਾਡਲ ਲਈ OmniRoute ਕੋਲ ਮੌਜੂਦ ਕੀਮਤ ਸਾਰਣੀ ਉੱਤੇ ਨਿਰਭਰ ਕਰਦੀ ਹੈ। ਜਿਸ ਮਾਡਲ ਲਈ ਕੋਈ ਕੀਮਤ
  ਐਂਟਰੀ ਨਹੀਂ ਹੈ, ਉਹ `0` ਲਾਗਤ ਜੋੜਦਾ ਹੈ (ਐਕਸਪਲੋਰਰ ਵਿੱਚ ਇਹ "ਪੁਰਾਣਾ / ਮੁਫ਼ਤ" ਕਤਾਰ ਵਜੋਂ ਦਿਖਾਈ ਦਿੰਦਾ ਹੈ)।
- ਮੁਫ਼ਤ-ਟੀਅਰ ਅਤੇ ਸਬਸਕ੍ਰਿਪਸ਼ਨ ਟ੍ਰੈਫ਼ਿਕ ਲਈ ਵੀ ਇੱਕ _ਅਨੁਮਾਨਿਤ_ ਲਾਗਤ ਇਕੱਠੀ ਹੁੰਦੀ ਹੈ — ਇਹ ਉਹ
  ਰਕਮ ਹੈ ਜੋ ਤੁਸੀਂ ਬਚਾ ਰਹੇ ਹੋ, ਨਾ ਕਿ ਉਹ ਰਕਮ ਜੋ ਤੁਹਾਨੂੰ ਦੇਣੀ ਹੈ।

## ਲਾਗਤਾਂ ਦਾ ਅਨੁਮਾਨ ਕਿਵੇਂ ਲਗਾਇਆ ਜਾਂਦਾ ਹੈ

### ਕੀਮਤਾਂ ਦਾ ਸਰੋਤ

ਲਾਗਤਾਂ ਇੱਕ ਕੀਮਤ ਸਾਰਣੀ ਤੋਂ ਆਉਂਦੀਆਂ ਹਨ, ਜਿਸਨੂੰ ਹੇਠਾਂ ਦਿੱਤੇ ਤਰਜੀਹੀ ਕ੍ਰਮ ਵਿੱਚ ਹੱਲ ਕੀਤਾ ਜਾਂਦਾ ਹੈ
([`src/lib/pricingSync.ts`](../../src/lib/pricingSync.ts)):

1. **ਵਰਤੋਂਕਾਰ ਓਵਰਰਾਈਡ** — ਉਹ ਕੀਮਤਾਂ ਜੋ ਤੁਸੀਂ ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ / `PATCH /api/pricing` ਰਾਹੀਂ ਸੈੱਟ ਕਰਦੇ ਹੋ।
2. **ਸਿੰਕ ਕੀਤੀਆਂ ਬਾਹਰੀ ਕੀਮਤਾਂ** — ਜਦੋਂ ਸਿੰਕ ਸਮਰੱਥ ਹੁੰਦਾ ਹੈ ਤਾਂ LiteLLM ਦੀ ਜਨਤਕ
   `model_prices_and_context_window.json` ਤੋਂ ਪ੍ਰਾਪਤ ਕੀਤੀਆਂ ਜਾਂਦੀਆਂ ਹਨ (ਇੱਕ ਵੱਖਰੇ
   `pricing_synced` ਨੇਮਸਪੇਸ ਵਿੱਚ ਸਟੋਰ ਹੁੰਦੀਆਂ ਹਨ, ਤਾਂ ਜੋ ਇਹ ਤੁਹਾਡੇ ਓਵਰਰਾਈਡਾਂ ਨੂੰ ਕਦੇ ਨਾ ਬਦਲੇ)।
3. **ਹਾਰਡਕੋਡ ਕੀਤੇ ਡਿਫੌਲਟ** — OmniRoute ਨਾਲ ਸ਼ਾਮਲ ਹੁੰਦੇ ਹਨ।

ਬਾਹਰੀ ਕੀਮਤ ਸਿੰਕ **ਚੋਣਵੀਂ** ਹੈ ਅਤੇ ਮੂਲ ਰੂਪ ਵਿੱਚ ਅਸਮਰੱਥ ਹੈ। ਸੰਬੰਧਿਤ env vars
([`.env.example`](../../.env.example) ਵੇਖੋ):

| Env var                 | ਡਿਫੌਲਟ    | ਉਦੇਸ਼                                                              |
| ----------------------- | --------- | ------------------------------------------------------------------ |
| `PRICING_SYNC_ENABLED`  | `false`   | ਸਟਾਰਟਅੱਪ ਵੇਲੇ ਬੈਕਗ੍ਰਾਊਂਡ LiteLLM ਕੀਮਤ ਸਿੰਕ ਸਮਰੱਥ ਕਰੋ।              |
| `PRICING_SYNC_INTERVAL` | `86400`   | ਸਿੰਕ ਅੰਤਰਾਲ **ਸਕਿੰਟਾਂ** ਵਿੱਚ (ਮੂਲ ਰੂਪ ਵਿੱਚ ਰੋਜ਼ਾਨਾ)।               |
| `PRICING_SYNC_SOURCES`  | `litellm` | ਕਾਮਿਆਂ ਨਾਲ ਵੱਖ ਕੀਤੀ ਸਰੋਤ ਸੂਚੀ (ਇਸ ਵੇਲੇ ਸਿਰਫ਼ `litellm` ਸਮਰਥਿਤ ਹੈ)। |

### ਲਾਗਤ ਦਾ ਫ਼ਾਰਮੂਲਾ

ਲਾਗਤ ਦੀ ਗਣਨਾ ਟੋਕਨਾਂ ਦੀ ਗਿਣਤੀ ਅਤੇ ਪ੍ਰਤੀ-ਮਿਲੀਅਨ-ਟੋਕਨ ਦਰਾਂ ਤੋਂ ਹਰ ਬੇਨਤੀ ਲਈ
[`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts)
(`computeCostFromPricing` / `calculateCost`) ਵਿੱਚ ਕੀਤੀ ਜਾਂਦੀ ਹੈ:

- **ਇਨਪੁੱਟ ਟੋਕਨ** (ਕੈਸ਼ ਰੀਡ ਅਤੇ ਕੈਸ਼-ਬਣਾਉਣ ਵਾਲੇ ਟੋਕਨਾਂ ਨੂੰ ਘਟਾ ਕੇ) × `input` ਦਰ।
- **ਕੈਸ਼-ਰੀਡ ਟੋਕਨ** × `cached` ਦਰ (ਨਾ ਹੋਣ ਉੱਤੇ ਇਨਪੁੱਟ ਦਰ ਵਰਤੀ ਜਾਂਦੀ ਹੈ)।
- **ਕੈਸ਼-ਬਣਾਉਣ ਵਾਲੇ ਟੋਕਨ** × `cache_creation` ਦਰ (ਨਾ ਹੋਣ ਉੱਤੇ ਇਨਪੁੱਟ ਦਰ ਵਰਤੀ ਜਾਂਦੀ ਹੈ)।
- **ਆਉਟਪੁੱਟ ਟੋਕਨ** × `output` ਦਰ।
- **ਰੀਜ਼ਨਿੰਗ ਟੋਕਨ** × `reasoning` ਦਰ (ਨਾ ਹੋਣ ਉੱਤੇ ਆਉਟਪੁੱਟ ਦਰ ਵਰਤੀ ਜਾਂਦੀ ਹੈ)।

ਸਾਰੀਆਂ ਦਰਾਂ ਨੂੰ ਪ੍ਰਤੀ 1,000,000 ਟੋਕਨ USD ਵਜੋਂ ਸਮਝਿਆ ਜਾਂਦਾ ਹੈ। Codex "fast"/"priority" ਜਾਂ
"flex" ਸਰਵਿਸ ਟੀਅਰ ਇੱਕ ਲਾਗਤ ਗੁਣਕ (`getCodexFastCostMultiplier`) ਲਾਗੂ ਕਰਦਾ ਹੈ — ਉਦਾਹਰਨ ਵਜੋਂ, flex
ਨੂੰ ਟੋਕਨਾਂ ਉੱਤੇ 50% ਛੋਟ ਨਾਲ ਬਿਲ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਜੋ ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ **flex ਬੱਚਤਾਂ** ਵਜੋਂ ਦਿਖਾਈ ਜਾਂਦੀ ਹੈ।

ਮਾਡਲ ਨਾਮਾਂ ਨੂੰ ਪਹਿਲਾਂ ਮਿਆਰੀ ਬਣਾਇਆ ਜਾਂਦਾ ਹੈ (ਪ੍ਰਦਾਤਾ-ਪਾਥ ਪ੍ਰੀਫਿਕਸ, ਜਿਵੇਂ `openai/` ਜਾਂ
`accounts/fireworks/models/`, ਹਟਾਏ ਜਾਂਦੇ ਹਨ), ਤਾਂ ਜੋ ਇਤਿਹਾਸਕ ਕਤਾਰਾਂ ਅਜੇ ਵੀ ਕਿਸੇ ਕੀਮਤ ਨਾਲ ਮੇਲ ਖਾ ਸਕਣ।

### ਖਰਚ ਕਿਵੇਂ ਰਿਕਾਰਡ ਕੀਤਾ ਜਾਂਦਾ ਹੈ

- ਪ੍ਰਤੀ-ਬੇਨਤੀ ਲਾਗਤ ਦੀ ਗਣਨਾ ਜਵਾਬ ਤੋਂ ਬਾਅਦ ਕੀਤੀ ਜਾਂਦੀ ਹੈ ਅਤੇ ਫਾਇਰ-ਐਂਡ-ਫਰਗੈਟ ਢੰਗ ਨਾਲ ਰਿਕਾਰਡ ਕੀਤੀ ਜਾਂਦੀ ਹੈ, ਤਾਂ ਜੋ ਇਹ
  ਕਲਾਇੰਟ ਲਈ ਕਦੇ ਵੀ ਲੇਟੈਂਸੀ ਨਾ ਵਧਾਏ। ਸਾਂਝੇ-ਕੋਟੇ ਦੀ ਖਪਤ ਨੂੰ ਅਗਲੇ
  ਇਵੈਂਟ-ਲੂਪ ਟਿਕ ਉੱਤੇ [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts) ਰਾਹੀਂ ਤਹਿ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।
- API-ਕੁੰਜੀ ਖਰਚ ਨੂੰ ਬਫ਼ਰ ਕੀਤਾ ਜਾਂਦਾ ਹੈ ਅਤੇ
  [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) ਦੁਆਰਾ ਬੈਚਾਂ ਵਿੱਚ ਫਲਸ਼ ਕੀਤਾ ਜਾਂਦਾ ਹੈ (ਡਿਫੌਲਟ 60s ਫਲਸ਼ ਅੰਤਰਾਲ,
  1,000-ਐਂਟਰੀ ਬਫ਼ਰ)। ਇਹਨਾਂ ਰਾਹੀਂ ਬਦਲਿਆ ਜਾ ਸਕਦਾ ਹੈ:

  | Env var                             | ਡਿਫੌਲਟ  | ਉਦੇਸ਼                                            |
  | ----------------------------------- | ------- | ------------------------------------------------ |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000` | ਮਿਲੀਸਕਿੰਟਾਂ ਵਿੱਚ ਫਲਸ਼ ਅੰਤਰਾਲ।                    |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`  | ਫਲਸ਼ ਤੋਂ ਪਹਿਲਾਂ ਵੱਧ ਤੋਂ ਵੱਧ ਬਫ਼ਰ ਕੀਤੀਆਂ ਐਂਟਰੀਆਂ। |

ਡੈਸ਼ਬੋਰਡ ਦੇ ਲਾਗਤ ਅੰਕੜੇ ਸਟੋਰ ਕੀਤੀ ਪ੍ਰਤੀ-ਕਤਾਰ ਡਾਲਰ ਰਕਮ ਤੋਂ **ਨਹੀਂ** ਪੜ੍ਹੇ ਜਾਂਦੇ — ਹਰ ਵਾਰ
ਐਨਾਲਿਟਿਕਸ ਐਂਡਪੌਇੰਟ ਚੱਲਣ ਉੱਤੇ ਉਹਨਾਂ ਦੀ ਟੋਕਨ ਗਿਣਤੀਆਂ ਅਤੇ ਮੌਜੂਦਾ ਕੀਮਤ ਸਾਰਣੀ ਤੋਂ ਤੁਰੰਤ
ਮੁੜ ਗਣਨਾ ਕੀਤੀ ਜਾਂਦੀ ਹੈ। ਇਸਦਾ ਮਤਲਬ ਹੈ ਕਿ ਕਿਸੇ ਗਲਤ ਕੀਮਤ ਨੂੰ ਠੀਕ ਕਰਨ (ਅਤੇ ਮੁੜ ਸਿੰਕ ਕਰਨ) ਨਾਲ
ਇਤਿਹਾਸਕ ਲਾਗਤ ਅਨੁਮਾਨ ਪਿਛਲੇ ਸਮੇਂ ਲਈ ਵੀ ਅੱਪਡੇਟ ਹੋ ਜਾਂਦੇ ਹਨ।

## ਡੈਸ਼ਬੋਰਡ: ਲਾਗਤਾਂ ਪੰਨਾ

**ਲਾਗਤਾਂ** ਪੰਨਾ `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`) 'ਤੇ ਮੌਜੂਦ ਹੈ।
ਇਸਦਾ ਮੁੱਖ ਦ੍ਰਿਸ਼ **ਲਾਗਤ ਸੰਖੇਪ** ਟੈਬ
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`) ਹੈ,
ਜੋ `GET /api/usage/analytics` ਤੋਂ ਸਾਰਾ ਡਾਟਾ ਲੋਡ ਕਰਦੀ ਹੈ।

ਇਹ ਕੀ ਦਿਖਾਉਂਦਾ ਹੈ:

- **ਖਰਚ ਟਾਈਲਾਂ** — _ਅੱਜ (1d)_, _7d_, _30d_, ਅਤੇ ਚੁਣੀ ਹੋਈ
  ਮਿਆਦ ਲਈ ਅਨੁਮਾਨਿਤ ਖਰਚ। ਮਿਆਦ ਚੋਣਕਾਰ: `7d`, `30d`, `90d`, `all`।
- **ਮੁੱਖ ਮੈਟ੍ਰਿਕਸ** — ਮਿਆਦ ਅੰਦਰ ਬੇਨਤੀਆਂ, ਸਰਗਰਮ ਪ੍ਰਦਾਤਾ, ਸਰਗਰਮ ਮਾਡਲ, ਪ੍ਰਤੀ
  ਬੇਨਤੀ ਔਸਤ ਲਾਗਤ।
- **ਲਾਗਤ ਐਕਸਪਲੋਰਰ** — ਇੱਕ ਕ੍ਰਮਬੱਧ/ਫਿਲਟਰ ਕਰਨਯੋਗ ਸਾਰਣੀ, ਜਿਸਨੂੰ **ਪ੍ਰਦਾਤਾ**, **ਮਾਡਲ**,
  **API ਕੁੰਜੀ**, **ਖਾਤਾ**, ਜਾਂ **ਸੇਵਾ ਟੀਅਰ** ਮੁਤਾਬਕ ਸਮੂਹਬੱਧ ਕੀਤਾ ਜਾਂਦਾ ਹੈ ਅਤੇ ਜਿਸ ਵਿੱਚ ਲਾਗਤ, ਬੇਨਤੀਆਂ, ਟੋਕਨ, ਔਸਤ
  ਲਾਗਤ/ਬੇਨਤੀ ਅਤੇ ਕੁੱਲ ਹਿੱਸੇਦਾਰੀ % ਸ਼ਾਮਲ ਹਨ।
- **ਟੋਕਨ ਵਰਤੋਂ** — ਕੁੱਲ / ਇਨਪੁੱਟ / ਆਉਟਪੁੱਟ ਟੋਕਨ ਅਤੇ ਇਨਪੁੱਟ:ਆਉਟਪੁੱਟ ਅਨੁਪਾਤ।
- **ਰੂਟਿੰਗ ਕੁਸ਼ਲਤਾ** — ਫਾਲਬੈਕ ਗਿਣਤੀ, ਫਾਲਬੈਕ ਦਰ ਅਤੇ ਬੇਨਤੀ ਕੀਤੇ ਮਾਡਲ ਦੀ ਕਵਰੇਜ।
- **ਮਾਸਿਕ ਪੂਰਵ-ਅਨੁਮਾਨ** — ਹਾਲੀਆ ਰੋਜ਼ਾਨਾ ਔਸਤ ਤੋਂ ਮਹੀਨੇ ਦੇ ਅੰਤ ਤੱਕ ਦੇ ਖਰਚ ਦਾ ਅਨੁਮਾਨ ਲਗਾਉਂਦਾ ਹੈ।
- **ਮਿਆਦ ਦੀ ਤੁਲਨਾ** — ਮਿਆਦ ਦੇ ਪਹਿਲੇ ਅਤੇ ਦੂਜੇ ਅੱਧ ਵਿਚਕਾਰ % ਤਬਦੀਲੀ।
- **ਚਾਰਟ** — ਰੋਜ਼ਾਨਾ ਲਾਗਤ ਰੁਝਾਨ, ਪ੍ਰਦਾਤਾ ਹਿੱਸੇਦਾਰੀ (ਪਾਈ), ਸਿਖਰਲੇ ਪ੍ਰਦਾਤਾ, ਸਿਖਰਲੇ ਮਾਡਲ, API ਕੁੰਜੀ
  ਮੁਤਾਬਕ ਲਾਗਤ, ਖਾਤੇ ਮੁਤਾਬਕ ਲਾਗਤ, ਹਫ਼ਤਾਵਾਰੀ ਵਰਤੋਂ ਪੈਟਰਨ ਅਤੇ ਗਤੀਵਿਧੀ ਹੀਟਮੈਪ।
- **ਨਿਰਯਾਤ** — ਮੌਜੂਦਾ ਮਿਆਦ ਨੂੰ **CSV** ਜਾਂ **JSON** ਵਜੋਂ ਡਾਊਨਲੋਡ ਕਰੋ (ਬਟਨ
  ਉਦੋਂ ਦਿਖਾਈ ਦਿੰਦੇ ਹਨ ਜਦੋਂ ਗੈਰ-ਸਿਫ਼ਰ ਲਾਗਤ ਡਾਟਾ ਮੌਜੂਦ ਹੋਵੇ)।

ਜਦੋਂ ਕੋਈ ਕੀਮਤਬੱਧ ਟ੍ਰੈਫਿਕ ਨਹੀਂ ਹੁੰਦਾ, ਤਾਂ ਕਤਾਰਾਂ `$0` ਦੀ ਬਜਾਏ "ਪੁਰਾਤਨ / ਮੁਫ਼ਤ" ਲੇਬਲ ਵਜੋਂ ਰੈਂਡਰ ਹੁੰਦੀਆਂ ਹਨ,
ਜੋ ਬੱਚਤ-ਟਰੈਕਰ ਮਾਡਲ ਨੂੰ ਦਰਸਾਉਂਦਾ ਹੈ।

### ਲਾਗਤਾਂ ਨਾਲ ਸੰਬੰਧਿਤ ਉਪ-ਪੰਨੇ

ਲਾਗਤਾਂ ਖੇਤਰ ਵਿੱਚ ਇਹ ਵੀ ਸ਼ਾਮਲ ਹਨ (ਸਾਰੇ `/dashboard/costs/` ਦੇ ਅਧੀਨ):

- **ਕੀਮਤ ਨਿਰਧਾਰਨ** (`/dashboard/costs/pricing`) — ਪ੍ਰਤੀ-ਮਾਡਲ ਕੀਮਤਾਂ ਵੇਖੋ ਅਤੇ ਓਵਰਰਾਈਡ ਕਰੋ (ਸਾਂਝੀ
  ਕੀਮਤ ਨਿਰਧਾਰਨ ਟੈਬ ਨੂੰ ਰੈਂਡਰ ਕਰਦਾ ਹੈ)।
- **ਬਜਟ** (`/dashboard/costs/budget`) — ਪ੍ਰਤੀ-ਸਕੋਪ ਖਰਚ ਸੀਮਾਵਾਂ ਸੈੱਟ ਕਰੋ (ਸਾਂਝੀ
  ਬਜਟ ਟੈਬ ਨੂੰ ਰੈਂਡਰ ਕਰਦਾ ਹੈ)।
- **ਕੋਟਾ ਹਿੱਸੇਦਾਰੀ** (`/dashboard/costs/quota-share`) — ਸਾਂਝੇ-ਕੋਟੇ ਦੇ ਪੂਲ ਅਤੇ ਬਰਨ-ਰੇਟ
  ਦ੍ਰਿਸ਼।

## CLI

OmniRoute ਦਾ CLI ਲਾਗਤ, ਵਰਤੋਂ ਅਤੇ ਕੀਮਤ-ਨਿਰਧਾਰਨ ਕਮਾਂਡਾਂ ਉਪਲਬਧ ਕਰਵਾਉਂਦਾ ਹੈ (ਜੋ
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs) ਵਿੱਚ ਰਜਿਸਟਰ ਕੀਤੀਆਂ ਗਈਆਂ ਹਨ)।

### `omniroute cost`

`/api/usage/analytics` ਤੋਂ ਇਕੱਤਰ ਕੀਤੀ ਲਾਗਤ ਰਿਪੋਰਟ।

```bash
omniroute cost                          # ਪਿਛਲੇ 30d, ਪ੍ਰਦਾਤਾ ਅਨੁਸਾਰ ਸਮੂਹਬੱਧ
omniroute cost --period 7d              # ਪਿਛਲੇ 7 ਦਿਨ
omniroute cost --group-by model         # provider | model | combo | api-key | day ਅਨੁਸਾਰ ਸਮੂਹਬੱਧ ਕਰੋ
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

ਕਾਲਮ: ਸਮੂਹ, ਬੇਨਤੀਆਂ, ਇਨਪੁੱਟ/ਆਉਟਪੁੱਟ ਟੋਕਨ, ਲਾਗਤ (USD), ਅਤੇ ਕੁੱਲ ਦਾ ਪ੍ਰਤੀਸ਼ਤ। ਅੰਤ ਵਿੱਚ
ਸਮੁੱਚੇ ਕੁੱਲ ਦੀ ਇੱਕ ਲਾਈਨ ਦਿਖਾਈ ਜਾਂਦੀ ਹੈ (`--quiet` ਜਾਂ `--output json` ਨਾਲ ਇਸ ਨੂੰ ਲੁਕਾਇਆ ਜਾਂਦਾ ਹੈ)।

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # ਪ੍ਰਤੀ-ਪ੍ਰਦਾਤਾ ਲਾਗਤ ਸੰਖੇਪ
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# ਬਜਟ
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show`, `GET /api/pricing/defaults` ਤੋਂ ਡਾਟਾ ਪੜ੍ਹਦਾ ਹੈ। ਇਸ ਦੀ ਬਜਾਏ ਵੱਖ-ਵੱਖ ਮਾਡਲਾਂ
> ਦੀਆਂ ਕੀਮਤਾਂ ਸੋਧਣ ਲਈ, **ਕੀਮਤ-ਨਿਰਧਾਰਨ** ਡੈਸ਼ਬੋਰਡ ਪੰਨਾ ਜਾਂ `PATCH /api/pricing` ਵਰਤੋ।

## ਸਮੱਸਿਆ-ਨਿਵਾਰਨ

- **ਸਾਰੀਆਂ ਲਾਗਤਾਂ $0 / "ਪੁਰਾਤਨ / ਮੁਫ਼ਤ" ਦਿਖਾਉਂਦੀਆਂ ਹਨ।** ਵਰਤੋਂ ਅਧੀਨ ਮਾਡਲਾਂ ਲਈ ਕੋਈ ਕੀਮਤ ਐਂਟਰੀ ਨਹੀਂ ਹੈ।
  ਬਾਹਰੀ ਸਿੰਕ ਚਾਲੂ ਕਰੋ (`PRICING_SYNC_ENABLED=true`) ਅਤੇ `omniroute pricing sync` ਚਲਾਓ, ਜਾਂ
  ਕੀਮਤ-ਨਿਰਧਾਰਨ ਪੰਨੇ / `PATCH /api/pricing` ਰਾਹੀਂ ਕੀਮਤਾਂ ਹੱਥੀਂ ਸੈੱਟ ਕਰੋ।
- **ਕਿਸੇ ਪੁਰਾਣੇ ਮਾਡਲ ਦੀ ਕੀਮਤ ਗਲਤ ਹੈ।** ਕੀਮਤ ਠੀਕ ਕਰੋ (ਓਵਰਰਾਈਡ ਜਾਂ ਮੁੜ-ਸਿੰਕ ਕਰੋ)—ਹਰ ਵਿਸ਼ਲੇਸ਼ਣ ਰੀਡ ਸਮੇਂ
  ਟੋਕਨ ਗਿਣਤੀਆਂ ਤੋਂ ਲਾਗਤ ਮੁੜ ਗਿਣੀ ਜਾਂਦੀ ਹੈ, ਇਸ ਲਈ ਅਨੁਮਾਨ ਪਿਛਲੀ ਮਿਆਦ ਲਈ ਵੀ ਅੱਪਡੇਟ ਹੋ ਜਾਂਦੇ ਹਨ।
- **ਖਰਚ ਅਸਲ ਸਮੇਂ ਤੋਂ ਪਿੱਛੇ ਰਹਿੰਦਾ ਹੈ।** ਪ੍ਰਤੀ-ਕੁੰਜੀ ਖਰਚ ਨੂੰ ਬੈਚਾਂ ਵਿੱਚ ਸੰਸਾਧਿਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ; ਜੇ ਤੁਹਾਨੂੰ
  ਵਧੇਰੇ ਤਾਜ਼ਾ ਅੰਕੜਿਆਂ ਦੀ ਲੋੜ ਹੈ ਤਾਂ `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` ਘਟਾਓ।
