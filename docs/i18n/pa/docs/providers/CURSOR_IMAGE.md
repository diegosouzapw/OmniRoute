OmniRoute ਉਸੇ provider id ਰਾਹੀਂ, ਜਿਸਦੀ ਵਰਤੋਂ chat ਲਈ ਹੁੰਦੀ ਹੈ, `POST /v1/images/generations` ਉੱਤੇ Cursor plan **ਚਿੱਤਰ ਜਨਰੇਸ਼ਨ** ਉਪਲਬਧ ਕਰਦਾ ਹੈ: `cursor` (alias `cu`)।

| ਫ਼ੀਲਡ                | ਮੁੱਲ                                                                              |
| -------------------- | --------------------------------------------------------------------------------- |
| `IMAGE_PROVIDERS` id | `cursor`                                                                          |
| ਫਾਰਮੈਟ               | `cursor-agent-image`                                                              |
| ਪ੍ਰਮਾਣੀਕਰਨ           | chat ਵਾਲਾ ਹੀ OAuth / API-key ਕਨੈਕਸ਼ਨ (`provider_connections.provider = "cursor"`) |
| ਮਾਡਲ                 | `cursor/auto`, `cursor/composer-2`, `cursor/composer-2.5`                         |

## Agent CLI ਕਿਉਂ

OmniRoute ਵਿੱਚ Cursor chat `agent.v1.AgentService/Run` (protobuf) ਦੀ ਵਰਤੋਂ ਕਰਦੀ ਹੈ। ਉਹ ਪਾਥ ਬਿਲਟ-ਇਨ ਕਲਾਇੰਟ ਟੂਲਾਂ (shell, write, …) ਨੂੰ **ਅਸਵੀਕਾਰ ਕਰਦਾ ਹੈ**। ਚਿੱਤਰ ਜਨਰੇਸ਼ਨ ਇੱਕ Cursor-ਨੇਟਿਵ ਟੂਲ ਹੈ, ਜਿਸਨੂੰ ਸੀਟ ਦੇ ਵਿਰੁੱਧ **`agent` CLI** ਵੱਲੋਂ ਚਲਾਇਆ ਜਾਂਦਾ ਹੈ। ਇਸ ਲਈ image handler ਇੱਕ ਲੌਕ ਕੀਤੇ prompt ਅਤੇ ਹਰ ਬੇਨਤੀ ਲਈ ਅਸਥਾਈ workspace (community seat bridges ਵਰਗੀ ਹੀ ਬਣਤਰ) ਨਾਲ `agent` ਨੂੰ ਸਪੌਨ ਕਰਦਾ ਹੈ, ਫਿਰ OpenAI-ਅਨੁਕੂਲ `b64_json` ਵਾਪਸ ਕਰਦਾ ਹੈ।

## ਪਹੁੰਚ ਪਾਬੰਦੀ (Hard Rules #15 + #17)

ਇਹ ਇਕੱਲਾ `IMAGE_PROVIDERS` ਫਾਰਮੈਟ ਹੈ ਜੋ ਇੱਕ child process (`agent`
binary) ਸਪੌਨ ਕਰਦਾ ਹੈ। ਕਿਉਂਕਿ `POST /v1/images/generations` ਲਗਭਗ 40 ਹੋਰ, ਨਾ-ਸਪੌਨ ਕਰਨ
ਵਾਲੇ image providers ਨਾਲ ਸਾਂਝਾ ਹੈ, ਜਿਨ੍ਹਾਂ ਦੀ remote callers ਵਾਜਬ ਤੌਰ 'ਤੇ ਵਰਤੋਂ ਕਰਦੇ ਹਨ, ਇਸ ਲਈ ਪੂਰੇ route ਨੂੰ
`LOCAL_ONLY` ਵਜੋਂ ਵਰਗੀਕ੍ਰਿਤ **ਨਹੀਂ** ਕੀਤਾ ਗਿਆ — ਇਸਦੀ ਬਜਾਏ `handleCursorAgentImageGeneration` ਭਰੋਸੇਯੋਗ
`AUTHZ_HEADER_PEER_LOCALITY` ਫ਼ੈਸਲੇ ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਆਪਣਾ gate ਲਾਗੂ ਕਰਦਾ ਹੈ, ਜਿਸਨੂੰ authz pipeline
ਹਰ ਬੇਨਤੀ ਉੱਤੇ ਮੋਹਰਬੱਧ ਕਰਦੀ ਹੈ (ਅਸਲੀ TCP peer ਤੋਂ, ਕਦੇ ਵੀ spoof ਕੀਤੇ ਜਾ ਸਕਣ ਵਾਲੇ `Host` header ਤੋਂ ਨਹੀਂ): ਸਿਰਫ਼
`loopback` ਅਤੇ `lan` callers ਹੀ spawn ਤੱਕ ਪਹੁੰਚ ਸਕਦੇ ਹਨ; ਬਾਕੀ ਸਭ ਨੂੰ (ਇਸ ਵਿੱਚ public tunnel ਰਾਹੀਂ ਮੁੜ ਵਰਤੀ ਗਈ
ਲੀਕ API key ਵੀ ਸ਼ਾਮਲ ਹੈ) ਕਿਸੇ ਵੀ credential lookup ਜਾਂ
process spawn ਤੋਂ ਪਹਿਲਾਂ `403` ਮਿਲਦਾ ਹੈ। ਬਾਕੀ `LOCAL_ONLY` tier ਉੱਤੇ ਲਾਗੂ ਇਸੇ
policy ਲਈ `src/server/authz/policies/management.ts` ਵੇਖੋ।

## Concurrency gate module-level ਹੈ (single-instance ਸੀਮਾ)

`CURSOR_IMG_MAX_CONCURRENT` ਨੂੰ
Node module instance (`open-sse/handlers/imageGeneration/providers/cursorAgentImage.ts`) ਦੇ ਦਾਇਰੇ ਵਾਲੇ
ਇੱਕ in-memory counter/queue ਰਾਹੀਂ ਲਾਗੂ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।
ਇਹ ਇੱਕ OmniRoute process ਦੇ ਅੰਦਰ ਸਮਕਾਲੀ `agent` spawns ਨੂੰ ਠੀਕ ਤਰ੍ਹਾਂ ਸੀਮਿਤ ਕਰਦਾ ਹੈ, ਪਰ
ਇੱਕੋ Cursor seat ਸਾਂਝੀ ਕਰਨ ਵਾਲੀਆਂ ਕਈ processes/instances ਵਿਚਕਾਰ ਤਾਲਮੇਲ
**ਨਹੀਂ** ਕਰਦਾ (ਉਦਾਹਰਨ ਲਈ, multi-replica deployment) — ਹਰ instance ਆਪਣੀ ਸੁਤੰਤਰ ਸੀਮਾ ਲਾਗੂ ਕਰਦਾ ਹੈ।
ਇੱਕ single-instance deployment (ਡਿਫਾਲਟ) ਲਈ ਇਹ ਸਟੀਕ ਹੈ; horizontally scaled
deployments ਨੂੰ ਹਰ instance ਲਈ `CURSOR_IMG_MAX_CONCURRENT` ਸੰਭਲ ਕੇ ਰੱਖਣਾ ਚਾਹੀਦਾ ਹੈ ਜਾਂ
Cursor image traffic ਨੂੰ ਇੱਕੋ instance ਵੱਲ route ਕਰਨਾ ਚਾਹੀਦਾ ਹੈ।

## ਲੋੜਾਂ

1. dashboard ਵਿੱਚ ਕਨੈਕਟ ਕੀਤਾ ਹੋਇਆ Cursor ਖਾਤਾ (OAuth ਜਾਂ `crsr_…` API key)।
2. OmniRoute process ਲਈ ਉਪਲਬਧ Cursor Agent binary:
   - env `CURSOR_AGENT_BIN=/path/to/agent`, ਜਾਂ
   - `~/.local/bin/agent`, ਜਾਂ
   - Cursor connection ਉੱਤੇ `providerSpecificData.agentBin`।

ਵਿਕਲਪਿਕ ਟਿਊਨਿੰਗ:

| Env                         | ਡਿਫਾਲਟ                    | ਅਰਥ                            |
| --------------------------- | ------------------------- | ------------------------------ |
| `CURSOR_IMG_TIMEOUT_MS`     | `210000`                  | ਹਰ ਚਿੱਤਰ ਲਈ wall clock         |
| `CURSOR_IMG_MAX_CONCURRENT` | `2`                       | shared-seat concurrency gate   |
| `CURSOR_IMG_MODEL`          | (ਬੇਨਤੀ ਦਾ model / `auto`) | CLI `--model` ਨੂੰ override ਕਰੋ |

## ਉਦਾਹਰਨ

```bash
curl -sS https://<host>/v1/images/generations \
  -H "Authorization: Bearer <omni-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor/auto","prompt":"a lantern in fog","size":"1024x1024"}'
```

ਜਨਰੇਸ਼ਨ ਵਿੱਚ ਆਮ ਤੌਰ 'ਤੇ 1–2 ਮਿੰਟ ਲੱਗਦੇ ਹਨ। ਅੰਦਰੂਨੀ network path ਨੂੰ ਤਰਜੀਹ ਦਿਓ; ਲਗਭਗ 100s timeouts ਵਾਲੇ edge proxies ਅਸਫਲ ਹੋ ਜਾਣਗੇ।

## LiteLLM

ਇੱਕ image model ਨੂੰ `mode: image_generation`, `api_base: http://omniroute:20128/v1`, ਅਤੇ `model: openai/cursor/auto` (ਜਾਂ ਤੁਹਾਡੇ LiteLLM version ਦੇ ਅਨੁਸਾਰ ਸਿਰਫ਼ `cursor/auto`) ਨਾਲ ਰਜਿਸਟਰ ਕਰੋ।
