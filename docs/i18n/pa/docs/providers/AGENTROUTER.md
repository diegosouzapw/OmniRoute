[AgentRouter](https://agentrouter.org) ਇੱਕ Anthropic-ਅਨੁਕੂਲ ਰੀਲੇ ਹੈ ਜੋ Claude ਅਤੇ ਹੋਰ ਮਾਡਲਾਂ ਨੂੰ ਮੁੜ ਵੇਚਦਾ ਹੈ, ਅਕਸਰ ਸਿੱਧੀ Anthropic API ਨਾਲੋਂ ਘੱਟ ਕੀਮਤਾਂ 'ਤੇ। ਇਸਨੂੰ ਅਧਿਕਾਰਤ Claude Code ਕਲਾਇੰਟ ਲਈ ਡ੍ਰੌਪ-ਇਨ `ANTHROPIC_BASE_URL` ਬਦਲ ਵਜੋਂ ਤਿਆਰ ਕੀਤਾ ਗਿਆ ਹੈ, ਇਸ ਲਈ ਇਹ ਸਿਰਫ਼ ਉਸ ਟ੍ਰੈਫ਼ਿਕ ਨੂੰ ਸਵੀਕਾਰਦਾ ਹੈ ਜੋ Claude Code ਵਾਇਰ ਇਮੇਜ (ਖ਼ਾਸ User-Agent, `anthropic-beta` ਫਲੈਗ, Stainless SDK ਹੈਡਰ ਆਦਿ) ਨਾਲ ਮੇਲ ਖਾਂਦਾ ਹੋਵੇ।

## ਤੁਰੰਤ ਸ਼ੁਰੂਆਤ — ਮੂਲ `agentrouter` ਪ੍ਰਦਾਤਾ ਦੀ ਵਰਤੋਂ ਕਰੋ (ਸਿਫ਼ਾਰਸ਼ੀ)

ਜ਼ਿਆਦਾਤਰ ਵਰਤੋਂਕਾਰਾਂ ਲਈ, **ਕਿਸੇ ਖ਼ਾਸ ਸੈੱਟਅੱਪ ਦੀ ਲੋੜ ਨਹੀਂ ਹੈ**। OmniRoute ਵਿੱਚ ਇੱਕ ਅੰਦਰੂਨੀ `agentrouter` ਪ੍ਰਦਾਤਾ ਸ਼ਾਮਲ ਹੈ, ਜਿਸ ਵਿੱਚ ਪੂਰਾ Claude Code ਵਾਇਰ ਇਮੇਜ ਪਹਿਲਾਂ ਤੋਂ ਹੀ ਮੌਜੂਦ ਹੈ (`open-sse/config/providerRegistry.ts` → `agentrouter` ਵੇਖੋ)। ਇਸਦੀ ਵਰਤੋਂ ਕਰਨ ਲਈ:

1. **ਡੈਸ਼ਬੋਰਡ → ਪ੍ਰਦਾਤਾ → ਪ੍ਰਦਾਤਾ ਸ਼ਾਮਲ ਕਰੋ** ਖੋਲ੍ਹੋ।
2. ਸੂਚੀ ਵਿੱਚੋਂ **AgentRouter** ਚੁਣੋ।
3. ਆਪਣੀ `sk-...` API ਕੁੰਜੀ ਪੇਸਟ ਕਰੋ ਅਤੇ ਸੁਰੱਖਿਅਤ ਕਰੋ।

ਬਸ ਇੰਨਾ ਹੀ — ਕਿਸੇ ਇਨਵਾਇਰਨਮੈਂਟ ਵੇਰੀਏਬਲ ਜਾਂ ਕਸਟਮ ਪ੍ਰਦਾਤਾ ਕਿਸਮ ਦੀ ਲੋੜ ਨਹੀਂ। ਅੰਦਰੂਨੀ ਮਾਡਲਾਂ ਵਿੱਚ `claude-opus-4-6`, `claude-haiku-4-5-20251001`, `glm-5.1`, ਅਤੇ `deepseek-v3.2` ਸ਼ਾਮਲ ਹਨ।

ਇਸ ਗਾਈਡ ਦਾ ਬਾਕੀ ਹਿੱਸਾ **ਉੱਨਤ ਤਰੀਕੇ** ਬਾਰੇ ਹੈ: `anthropic-compatible-cc-*` ਪ੍ਰਦਾਤਾ ਕਿਸਮ ਦੀ ਵਰਤੋਂ ਕਰਨਾ। ਇਸਦੀ ਵਰਤੋਂ ਉਦੋਂ ਕਰੋ ਜਦੋਂ ਤੁਹਾਨੂੰ ਵਾਇਰ ਇਮੇਜ 'ਤੇ ਵਧੇਰੇ ਨਿਯੰਤਰਣ ਦੀ ਲੋੜ ਹੋਵੇ — ਉਦਾਹਰਨ ਵਜੋਂ, ਹੋਰ AgentRouter-ਸ਼ੈਲੀ ਦੇ ਰੀਲੇਆਂ ਨਾਲ ਕਨੈਕਟ ਕਰਦੇ ਸਮੇਂ ਜੋ ਹਾਲੇ ਮੂਲ ਪ੍ਰਦਾਤਾ ਰਜਿਸਟਰੀ ਵਿੱਚ ਨਹੀਂ ਹਨ, ਜਾਂ ਬੇਸ URL, ਚੈਟ ਪਾਥ, ਜਾਂ ਹੈਡਰ ਸੈੱਟ ਨੂੰ ਓਵਰਰਾਈਡ ਕਰਦੇ ਸਮੇਂ।

## ਉੱਨਤ: Claude Code ਅਨੁਕੂਲ ਪ੍ਰਦਾਤਾ ਕਿਸਮ ਰਾਹੀਂ ਕਨੈਕਟ ਕਰਨਾ

OmniRoute **Claude Code ਅਨੁਕੂਲ** ਪ੍ਰਦਾਤਾ ਕਿਸਮ (`anthropic-compatible-cc-*`) ਰਾਹੀਂ AgentRouter (ਅਤੇ ਇਸੇ ਤਰ੍ਹਾਂ ਦੇ ਰੀਲੇਆਂ) ਦਾ ਵੀ ਸਮਰਥਨ ਕਰਦਾ ਹੈ, ਜੋ ਸਹੀ ਵਾਇਰ ਇਮੇਜ ਨਾਲ Anthropic Messages API ਦੀ ਵਰਤੋਂ ਕਰਦੀ ਹੈ। `https://agentrouter.org` ਵੱਲ ਸੰਕੇਤ ਕਰਨ ਵਾਲਾ ਇੱਕ ਆਮ `openai-compatible-chat` ਪ੍ਰਦਾਤਾ **ਕੰਮ ਨਹੀਂ ਕਰੇਗਾ** — ਅੱਪਸਟ੍ਰੀਮ WAF ਉਹਨਾਂ ਬੇਨਤੀਆਂ ਨੂੰ ਰੱਦ ਕਰ ਦਿੰਦਾ ਹੈ ਜੋ Claude Code ਵਰਗੀਆਂ ਨਹੀਂ ਲੱਗਦੀਆਂ।

## ਪੂਰਵ-ਲੋੜਾਂ

- ਇੱਕ AgentRouter ਖਾਤਾ ਅਤੇ API ਕੁੰਜੀ। ਨਵੇਂ ਸਾਈਨਅੱਪਾਂ ਨੂੰ ਪ੍ਰੋਜੈਕਟ [README](../README.md) ਵਿੱਚ ਦਿੱਤੇ ਐਫ਼ਿਲੀਏਟ ਲਿੰਕ ਰਾਹੀਂ ਮੁਫ਼ਤ ਕ੍ਰੈਡਿਟ ਮਿਲਦੇ ਹਨ।
- OmniRoute ਨੂੰ `ENABLE_CC_COMPATIBLE_PROVIDER` ਫੀਚਰ ਫਲੈਗ ਸਮਰੱਥ ਕਰਕੇ ਚਲਾਇਆ ਗਿਆ ਹੋਵੇ (ਹੇਠਾਂ ਵੇਖੋ)।

## 1. CC-ਅਨੁਕੂਲ ਪ੍ਰਦਾਤਾ ਕਿਸਮ ਨੂੰ ਸਮਰੱਥ ਕਰੋ

Claude Code ਅਨੁਕੂਲ ਪ੍ਰਦਾਤਾ ਕਿਸਮ ਨੂੰ ਇੱਕ ਫੀਚਰ ਫਲੈਗ ਦੇ ਪਿੱਛੇ ਰੱਖਿਆ ਗਿਆ ਹੈ, ਕਿਉਂਕਿ ਇਹ ਅਜਿਹਾ ਟ੍ਰੈਫ਼ਿਕ ਭੇਜਦੀ ਹੈ ਜੋ ਅਧਿਕਾਰਤ Claude Code ਕਲਾਇੰਟ ਨਾਲ ਬਹੁਤ ਮਿਲਦਾ-ਜੁਲਦਾ ਹੈ। OmniRoute ਸ਼ੁਰੂ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਇੱਕ ਇਨਵਾਇਰਨਮੈਂਟ ਵੇਰੀਏਬਲ ਸੈੱਟ ਕਰਕੇ ਇਸਨੂੰ ਸਮਰੱਥ ਕਰੋ:

```bash
ENABLE_CC_COMPATIBLE_PROVIDER=true
```

Docker ਉਦਾਹਰਨ:

```bash
docker run -d --name omniroute \
  --restart unless-stopped \
  -p 20128:20128 \
  -v omniroute-data:/app/data \
  -e ENABLE_CC_COMPATIBLE_PROVIDER=true \
  diegosouzapw/omniroute:latest
```

ਮੁੜ-ਚਾਲੂ ਕਰਨ ਤੋਂ ਬਾਅਦ, ਡੈਸ਼ਬੋਰਡ ਮੌਜੂਦਾ OpenAI-ਅਨੁਕੂਲ ਅਤੇ Anthropic-ਅਨੁਕੂਲ ਪ੍ਰਵਾਹਾਂ ਤੋਂ ਇਲਾਵਾ **Claude Code ਅਨੁਕੂਲ ਸ਼ਾਮਲ ਕਰੋ** ਵਿਕਲਪ ਦਿਖਾਉਂਦਾ ਹੈ।

## 2. ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ ਪ੍ਰਦਾਤਾ ਬਣਾਓ

1. **ਡੈਸ਼ਬੋਰਡ → ਪ੍ਰਦਾਤਾ → ਪ੍ਰਦਾਤਾ ਸ਼ਾਮਲ ਕਰੋ** ਖੋਲ੍ਹੋ।
2. **Claude Code ਅਨੁਕੂਲ ਸ਼ਾਮਲ ਕਰੋ** ਚੁਣੋ (ਇਹ ਸਿਰਫ਼ ਉਦੋਂ ਦਿਖਾਈ ਦਿੰਦਾ ਹੈ ਜਦੋਂ ਉੱਪਰ ਦਿੱਤਾ ਫਲੈਗ ਸੈੱਟ ਹੋਵੇ)।
3. ਖੇਤਰ ਭਰੋ:

| ਖੇਤਰ     | ਮੁੱਲ                                                                    |
| -------- | ----------------------------------------------------------------------- |
| ਨਾਮ      | `AgentRouter` (ਜਾਂ ਕੋਈ ਵੀ ਲੇਬਲ)                                         |
| ਪ੍ਰੀਫਿਕਸ | `agentrouter` (ਲੌਗਾਂ ਅਤੇ ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ ਦਿਖਾਇਆ ਜਾਣ ਵਾਲਾ ਸੁਵਿਧਾਜਨਕ ਉਪਨਾਮ) |
| ਬੇਸ URL  | `https://agentrouter.org`                                               |
| ਚੈਟ ਪਾਥ  | `/v1/messages?beta=true` (ਡਿਫ਼ਾਲਟ — ਇਸੇ ਤਰ੍ਹਾਂ ਰਹਿਣ ਦਿਓ)                |

> ਪ੍ਰਮਾਣਿਕ ਮਾਡਲ ਪਛਾਣਕਰਤਾ ਅਜੇ ਵੀ ਪੂਰੇ ਪ੍ਰਦਾਤਾ ਨੋਡ ID
> (`anthropic-compatible-cc-{uuid}/{model}`) ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ। **ਪ੍ਰੀਫਿਕਸ** ਸਿਰਫ਼ ਇੱਕ ਡਿਸਪਲੇਅ
> ਉਪਨਾਮ ਹੈ, ਜਿਸਨੂੰ ਵਧੇਰੇ ਸੁਵਿਧਾਜਨਕ ਲੌਗ ਆਉਟਪੁੱਟ ਲਈ `src/lib/usage/callLogs.ts` ਦੁਆਰਾ ਰਿਜ਼ੌਲਵ ਕੀਤਾ ਜਾਂਦਾ ਹੈ।

4. (ਵਿਕਲਪਿਕ) ਆਪਣੀ API ਕੁੰਜੀ **ਪ੍ਰਮਾਣਿਤ ਕਰੋ** ਖੇਤਰ ਵਿੱਚ ਪੇਸਟ ਕਰੋ ਅਤੇ ਸੁਰੱਖਿਅਤ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਕਨੈਕਟਿਵਿਟੀ ਦੀ ਪੁਸ਼ਟੀ ਕਰਨ ਲਈ **ਜਾਂਚੋ** 'ਤੇ ਕਲਿੱਕ ਕਰੋ।
5. **ਸ਼ਾਮਲ ਕਰੋ** 'ਤੇ ਕਲਿੱਕ ਕਰੋ।

ਇੱਕ ਵਾਰ ਬਣ ਜਾਣ ਤੋਂ ਬਾਅਦ, ਪ੍ਰਦਾਤਾ ਨੂੰ ਖੋਲ੍ਹੋ ਅਤੇ ਆਪਣੀ AgentRouter API ਕੁੰਜੀ (`sk-...`) ਨਾਲ ਇੱਕ **ਕਨੈਕਸ਼ਨ** ਸ਼ਾਮਲ ਕਰੋ। ਕਨੈਕਸ਼ਨ ਦਾ `test_status` `active` ਹੋ ਜਾਣਾ ਚਾਹੀਦਾ ਹੈ।

## 3. ਇਸਨੂੰ ਕੌਂਬੋ ਰਾਹੀਂ ਜਾਂ ਸਿੱਧੇ ਵਰਤੋ

ਆਪਣੇ ਪ੍ਰਦਾਤਾ ਦੇ ਪ੍ਰੀਫਿਕਸ ਨੂੰ ਨੇਮਸਪੇਸ ਵਜੋਂ ਵਰਤ ਕੇ ਮਾਡਲ ਦਾ ਹਵਾਲਾ ਦਿਓ:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "agentrouter/claude-opus-4-6",
    "messages": [{"role": "user", "content": "hello"}],
    "max_tokens": 100
  }'
```

ਕੈਨੋਨਿਕਲ ਮਾਡਲ ID `anthropic-compatible-cc-{uuid}/claude-opus-4-6` ਵੀ ਕੰਮ ਕਰਦੀ ਹੈ
ਅਤੇ ਇਹੀ ਡਾਟਾਬੇਸ ਅਤੇ ਕੌਂਬੋ ਸੰਰਚਨਾ ਵਿੱਚ ਦਿਖਾਈ ਦਿੰਦੀ ਹੈ।

ਜਾਂ ਰੂਟਿੰਗ, ਫਾਲਬੈਕ ਅਤੇ ਕੋਟਾ ਪ੍ਰਬੰਧਨ ਲਈ ਇਸਨੂੰ ਕਿਸੇ ਹੋਰ
ਪ੍ਰਦਾਤਾ ਵਾਂਗ ਕੌਂਬੋ ਵਿੱਚ ਸ਼ਾਮਲ ਕਰੋ।

ਬੇਨਤੀ ਨਾਲ ਹੇਠ ਲਿਖੀਆਂ ਚੀਜ਼ਾਂ ਭੇਜਦਾ ਹੈ (`open-sse/services/claudeCodeCompatible.ts` ਵੇਖੋ):

| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |

| `anthropic-version`                         | `2023-06-01`                                                                                                             |

## ਸਮੱਸਿਆ-ਨਿਵਾਰਣ

**`{"error":{"message":"unauthorized client detected, ..."}}`** — ਤੁਹਾਡੀ ਬੇਨਤੀ
Claude Code ਵਾਇਰ ਇਮੇਜ ਨਾਲ ਮੇਲ ਨਹੀਂ ਖਾਂਦੀ ਸੀ। ਇਹ ਉਦੋਂ ਹੁੰਦਾ ਹੈ ਜਦੋਂ ਪ੍ਰਦਾਤਾ ਨੂੰ
`anthropic-compatible-cc` ਦੀ ਬਜਾਏ `openai-compatible-chat` ਵਜੋਂ ਸੰਰਚਿਤ ਕੀਤਾ ਗਿਆ ਹੋਵੇ, ਜਾਂ ਜਦੋਂ
ਸਟਾਰਟਅੱਪ ਵੇਲੇ `ENABLE_CC_COMPATIBLE_PROVIDER=true` ਫਲੈਗ ਸੈੱਟ ਨਾ ਕੀਤਾ ਗਿਆ ਹੋਵੇ।

**`{"error":{"message":"无效的令牌","type":"new_api_error"}}` (HTTP 401)** —
"ਅਵੈਧ ਟੋਕਨ"। ਵਾਇਰ ਇਮੇਜ ਸਹੀ ਹੈ ਪਰ API ਕੁੰਜੀ ਰੱਦ ਕੀਤੀ ਗਈ ਹੈ। AgentRouter
ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ ਨਵੀਂ ਕੁੰਜੀ ਬਣਾਓ ਅਤੇ ਕਨੈਕਸ਼ਨ ਨੂੰ ਅੱਪਡੇਟ ਕਰੋ।

**`{"error":{"code":"content-blocked","type":"agent_router_api_error"}}`
(HTTP 400)** — AgentRouter ਦੇ ਮਾਡਰੇਸ਼ਨ ਹੁੱਕ ਨੇ ਬੇਨਤੀ ਦੀ ਸਮੱਗਰੀ ਨੂੰ ਰੱਦ ਕਰ ਦਿੱਤਾ, ਜਾਂ
ਕੁੰਜੀ ਦਾ ਪਲਾਨ ਬੇਨਤੀ ਕੀਤੇ ਮਾਡਲ ਦੀ ਇਜਾਜ਼ਤ ਨਹੀਂ ਦਿੰਦਾ। ਕੋਈ ਵੱਖਰਾ ਪ੍ਰੌਂਪਟ ਜਾਂ ਮਾਡਲ ਅਜ਼ਮਾਓ;
ਜੇ ਕੋਈ ਨਿਰਦੋਸ਼ ਪ੍ਰੌਂਪਟ ਲਗਾਤਾਰ ਬਲੌਕ ਹੁੰਦਾ ਹੈ ਤਾਂ AgentRouter ਸਹਾਇਤਾ ਨਾਲ ਸੰਪਰਕ ਕਰੋ।

**ਸਿਰਫ਼ ਖ਼ਾਸ ਮਾਡਲਾਂ ਉੱਤੇ `[400]: content-blocked`** — ਜ਼ਿਆਦਾਤਰ AgentRouter ਪਲਾਨ ਸਿਰਫ਼
ਮਾਡਲਾਂ ਦੇ ਇੱਕ ਉਪ-ਸਮੂਹ (ਉਦਾਹਰਨ ਵਜੋਂ `claude-opus-4-6`) ਦੀ ਇਜਾਜ਼ਤ ਦਿੰਦੇ ਹਨ। ਹੋਰ ਮਾਡਲ ID
ਕੁੰਜੀ ਵੈਧ ਹੋਣ ਦੇ ਬਾਵਜੂਦ `unauthorized_client_error` ਵਾਪਸ ਕਰਦੀਆਂ ਹਨ। AgentRouter
ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ ਜਾਂਚੋ ਕਿ ਤੁਹਾਡਾ ਪਲਾਨ ਕਿਹੜੇ ਮਾਡਲਾਂ ਨੂੰ ਕਵਰ ਕਰਦਾ ਹੈ।

**omniroute ਲੌਗਾਂ ਤੋਂ `Invalid JSON response from provider (reset after Ns)`** —
ਅੱਪਸਟ੍ਰੀਮ ਨੇ ਇੱਕ ਗੈਰ-JSON ਬਾਡੀ ਵਾਪਸ ਕੀਤੀ (ਆਮ ਤੌਰ 'ਤੇ WAF ਵੱਲੋਂ ਇੱਕ HTML ਤਰੁੱਟੀ ਪੰਨਾ)।
ਇਸਦਾ ਆਮ ਤੌਰ 'ਤੇ ਮਤਲਬ ਹੁੰਦਾ ਹੈ ਕਿ ਬੇਨਤੀ ਕਦੇ ਵੀ AgentRouter ਬੈਕਐਂਡ ਤੱਕ ਨਹੀਂ ਪਹੁੰਚੀ — ਮੁੜ ਜਾਂਚੋ ਕਿ
ਪ੍ਰਦਾਤਾ ID `anthropic-compatible-cc-` ਨਾਲ ਸ਼ੁਰੂ ਹੁੰਦੀ ਹੈ (ਅੰਤ ਵਾਲੇ ਡੈਸ਼ ਵੱਲ ਧਿਆਨ ਦਿਓ —
`open-sse/services/claudeCodeCompatible.ts` ਵਿੱਚ `CLAUDE_CODE_COMPATIBLE_PREFIX` ਵੇਖੋ)
ਅਤੇ ਫੀਚਰ ਫਲੈਗ ਸਮਰੱਥ ਹੈ।

**`unauthorized client detected` / HTML ਤਰੁੱਟੀ ਪੰਨਾ, ਭਾਵੇਂ ਇੱਕ AgentRouter
ਪ੍ਰਦਾਤਾ ਪਹਿਲਾਂ ਹੀ ਮੌਜੂਦ ਹੈ** — ਸੰਭਾਵਨਾ ਹੈ ਕਿ ਤੁਹਾਡੇ ਕੋਲ **ਇੱਕ ਤੋਂ ਵੱਧ** AgentRouter ਪ੍ਰਦਾਤਾ
ਹਨ ਅਤੇ ਤੁਹਾਡੀ ਬੇਨਤੀ ਗਲਤ ਪ੍ਰਦਾਤਾ ਤੱਕ ਪਹੁੰਚ ਰਹੀ ਹੈ। ਜੇ `agentrouter` ਪ੍ਰੀਫਿਕਸ ਨਾਲ ਕੋਈ ਬਚਿਆ ਹੋਇਆ ਹੱਥੀਂ ਬਣਾਇਆ
`anthropic-compatible-*` (ਗੈਰ-`cc`) ਜਾਂ `openai-compatible-chat-*` ਪ੍ਰਦਾਤਾ
ਬਣਾਇਆ ਗਿਆ ਸੀ, ਤਾਂ ਉਹ `agentrouter/<model>` ਮਾਡਲ ID ਦਾ ਮਾਲਕ ਹੋ ਸਕਦਾ ਹੈ
(ਅਤੇ ਕੌਂਬੋ ਉਸਨੂੰ ਨੋਡ ID ਰਾਹੀਂ ਹਵਾਲਾ ਦੇ ਸਕਦੇ ਹਨ), ਇਸ ਲਈ ਟ੍ਰੈਫਿਕ ਉਸ ਪ੍ਰਦਾਤਾ ਵੱਲ ਰੂਟ ਹੁੰਦਾ ਹੈ —
ਜੋ ਇੱਕ ਆਮ User-Agent ਭੇਜਦਾ ਹੈ ਅਤੇ ਰੱਦ ਹੋ ਜਾਂਦਾ ਹੈ — ਨਾ ਕਿ ਪਹਿਲਾਂ ਤੋਂ ਸਹੀ ਵਾਇਰ ਇਮੇਜ ਨਾਲ ਆਉਣ ਵਾਲੇ
ਬਿਲਟ-ਇਨ `agentrouter` ਪ੍ਰਦਾਤਾ ਵੱਲ। ਜਾਂਚੋ ਕਿ ਮਾਡਲ ਅਸਲ ਵਿੱਚ
omniroute ਲੌਗਾਂ ਵਿੱਚ ਕਿੱਥੇ ਰਿਜ਼ੌਲਵ ਹੁੰਦਾ ਹੈ (`ROUTING` ਟੈਗ
`agentrouter/<model> → <providerId>/<model>` ਦਿਖਾਉਂਦਾ ਹੈ); ਜੇ `<providerId>`
`agentrouter` ਨਹੀਂ ਹੈ, ਤਾਂ ਨੇਟਿਵ ਪ੍ਰਦਾਤਾ ਉੱਤੇ ਇਕਸਾਰ ਕਰੋ: ਕੌਂਬੋ ਨੂੰ
`agentrouter/<model>` (providerId `agentrouter`) ਵੱਲ ਪੁਆਇੰਟ ਕਰੋ ਅਤੇ ਡੁਪਲੀਕੇਟ
compatible ਪ੍ਰਦਾਤਿਆਂ ਨੂੰ ਮਿਟਾਓ। ਨੇਟਿਵ ਪ੍ਰਦਾਤਾ ਨੂੰ ਕਿਸੇ ਵਾਇਰ-ਇਮੇਜ ਸੰਰਚਨਾ ਜਾਂ
`customUserAgent` ਦੀ ਲੋੜ ਨਹੀਂ ਹੈ।
