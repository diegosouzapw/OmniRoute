`copilot-m365-web` (ਉਪਨਾਮ `m365copilot`) `m365.cloud.microsoft/chat` ਉੱਤੇ ਇੱਕ ਪ੍ਰਮਾਣਿਤ Microsoft 365 Copilot BizChat ਬ੍ਰਾਊਜ਼ਰ ਸੈਸ਼ਨ ਰਾਹੀਂ OpenAI-ਫਾਰਮੈਟ ਚੈਟ ਬੇਨਤੀਆਂ ਭੇਜਦਾ ਹੈ। ਇਹ ਇੱਕ ਗੈਰ-ਅਧਿਕਾਰਤ ਏਕੀਕਰਨ ਹੈ।

> **Web Cookie ਪ੍ਰਦਾਤਾਵਾਂ ਲਈ ਨਵੇਂ ਹੋ?**
>
> ਇਸ ਪ੍ਰਦਾਤਾ-ਵਿਸ਼ੇਸ਼ ਗਾਈਡ ਦੀ ਪਾਲਣਾ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਆਮ ਸੈੱਟਅੱਪ ਪ੍ਰਕਿਰਿਆ, ਪ੍ਰਮਾਣੀਕਰਨ ਮਾਰਗਦਰਸ਼ਨ, ਸੀਮਾਵਾਂ ਅਤੇ ਸਮੱਸਿਆ-ਨਿਵਾਰਣ ਲਈ **`docs/getting-started/WEB-COOKIE-GUIDE.md`** ਪੜ੍ਹੋ।
>
> **ਮਹੱਤਵਪੂਰਨ:** ਇਸ ਪ੍ਰਦਾਤਾ ਲਈ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ **ਕੁਕੀ ਨਹੀਂ ਹੈ**। `m365.cloud.microsoft` ਤੋਂ ਕੁਕੀਆਂ ਕਾਪੀ ਨਾ ਕਰੋ। ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਇੱਕ WebSocket URL ਕਵੇਰੀ ਪੈਰਾਮੀਟਰ ਅਤੇ ਪਾਥ ਸੈਗਮੈਂਟ ਹੈ, ਜਿਨ੍ਹਾਂ ਦੋਵਾਂ ਨੂੰ DevTools ਦੇ Network ਟੈਬ ਤੋਂ ਪੜ੍ਹਿਆ ਜਾਂਦਾ ਹੈ।

## ਪੂਰਵ-ਲੋੜਾਂ

- `m365.cloud.microsoft/chat` ਉੱਤੇ BizChat ਤੱਕ ਪਹੁੰਚ ਵਾਲਾ Microsoft 365 ਖਾਤਾ
- DevTools ਵਿੱਚ WebSocket ਦੀ ਜਾਂਚ ਲਈ Chromium-ਅਧਾਰਿਤ ਬ੍ਰਾਊਜ਼ਰ (Chrome, Edge)
- ਇੱਕ M365 Copilot ਲਾਇਸੈਂਸ (ਕਈ Microsoft 365 Business/Enterprise ਯੋਜਨਾਵਾਂ ਵਿੱਚ ਸ਼ਾਮਲ)

## ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਕੈਪਚਰ (WebSocket ਵਿਧੀ)

1. `https://m365.cloud.microsoft/chat` ਉੱਤੇ ਸਾਈਨ ਇਨ ਕਰੋ ਅਤੇ ਗੱਲਬਾਤ ਸ਼ੁਰੂ ਕਰੋ।
2. **DevTools → Network** ਖੋਲ੍ਹੋ।
3. **WS** (WebSocket) ਮੁਤਾਬਕ ਫਿਲਟਰ ਕਰੋ।
4. Chathub WebSocket ਕਨੈਕਸ਼ਨ ਉੱਤੇ ਕਲਿੱਕ ਕਰੋ। `wss://substrate.office.com/m365Copilot/Chathub/` ਨਾਲ ਸ਼ੁਰੂ ਹੋਣ ਵਾਲਾ URL ਲੱਭੋ।
5. ਇਸਦੇ **Request URL** ਵਿੱਚੋਂ ਇਹ ਕਾਪੀ ਕਰੋ:
   - `access_token` ਕਵੇਰੀ ਪੈਰਾਮੀਟਰ ਦਾ ਮੁੱਲ (ਇੱਕ ਥੋੜ੍ਹੇ ਸਮੇਂ ਲਈ ਵੈਧ JWT)।
   - `/Chathub/` ਤੋਂ ਬਾਅਦ ਵਾਲਾ Chathub ਪਾਥ ਸੈਗਮੈਂਟ (ਉਦਾਹਰਨ ਲਈ `<oid>@<tenant>`)।

ਪੂਰੇ URL ਦਾ ਰੂਪ ਇਹ ਹੈ:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute ਵਿੱਚ **Providers → Add Provider** ਉੱਤੇ ਜਾਓ, **Microsoft 365 Copilot
   (BizChat)** ਚੁਣੋ ਅਤੇ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਨੂੰ ਇਸ ਫਾਰਮੈਟ ਵਿੱਚ ਪੇਸਟ ਕਰੋ:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. **Test Connection** ਅਤੇ **Save** ਉੱਤੇ ਕਲਿੱਕ ਕਰੋ।

## ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਕੈਪਚਰ (HAR ਇੰਪੋਰਟ)

WebSocket URL ਤੋਂ ਮੁੱਲ ਹੱਥੀਂ ਕਾਪੀ ਕਰਨ ਦੀ ਬਜਾਏ, ਤੁਸੀਂ ਇੱਕ DevTools HAR ਫਾਈਲ ਐਕਸਪੋਰਟ ਕਰ ਸਕਦੇ ਹੋ:

1. **DevTools → Network** ਖੋਲ੍ਹੋ।
2. ਇੱਕ BizChat ਗੱਲਬਾਤ ਸ਼ੁਰੂ ਕਰੋ ਜਾਂ ਜਾਰੀ ਰੱਖੋ (ਇਸ ਨਾਲ WebSocket ਕਨੈਕਸ਼ਨ ਚਾਲੂ ਹੁੰਦਾ ਹੈ)।
3. Network ਪੈਨਲ ਵਿੱਚ ਸੱਜਾ-ਕਲਿੱਕ ਕਰੋ ਅਤੇ **Save all as HAR with content** ਚੁਣੋ।
4. OmniRoute ਵਿੱਚ, ਪ੍ਰਦਾਤਾ ਕਨੈਕਸ਼ਨ ਡਾਇਲਾਗ ਉੱਤੇ **Import .har file** ਬਟਨ ਦੀ ਵਰਤੋਂ ਕਰੋ।

OmniRoute Chathub WebSocket URL ਲਈ HAR ਨੂੰ ਸਕੈਨ ਕਰਦਾ ਹੈ, `access_token` ਅਤੇ `chathubPath` ਕੱਢਦਾ ਹੈ ਅਤੇ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਫੀਲਡਾਂ ਨੂੰ ਆਪਣੇ ਆਪ ਭਰ ਦਿੰਦਾ ਹੈ। HAR ਇੰਪੋਰਟ JWT ਦੀ ਮਿਆਦ-ਸਮਾਪਤੀ ਨੂੰ ਡੀਕੋਡ ਕਰਦਾ ਹੈ ਅਤੇ ਟੋਕਨ ਦੀ ਬਾਕੀ ਮਿਆਦ ਦਿਖਾਉਂਦਾ ਹੈ।

> **ਕਿਸੇ ਅਸਲੀ HAR ਐਕਸਪੋਰਟ, ਐਕਸੈੱਸ ਟੋਕਨ ਜਾਂ ਰਿਫ੍ਰੈਸ਼ ਟੋਕਨ ਨੂੰ ਕਦੇ ਵੀ ਕਮਿਟ ਨਾ ਕਰੋ।** ਟੈਸਟ ਅਤੇ ਦਸਤਾਵੇਜ਼ੀ ਮੁੱਲ ਹਮੇਸ਼ਾ ਪਲੇਸਹੋਲਡਰ ਹੋਣੇ ਚਾਹੀਦੇ ਹਨ।

## ਟੋਕਨ ਦੀ ਮਿਆਦ ਅਤੇ ਰਿਫ੍ਰੈਸ਼

`access_token` ਥੋੜ੍ਹੇ ਸਮੇਂ ਲਈ ਵੈਧ ਹੁੰਦਾ ਹੈ (ਆਮ ਤੌਰ ਉੱਤੇ **~75 ਮਿੰਟ**)। ਮਿਆਦ ਖ਼ਤਮ ਹੋਣ ਤੋਂ ਬਾਅਦ, ਪ੍ਰਦਾਤਾ ਇੱਕ ਕਨੈਕਸ਼ਨ ਤਰੁੱਟੀ ਰਿਪੋਰਟ ਕਰਦਾ ਹੈ ਅਤੇ ਤੁਹਾਨੂੰ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਮੁੜ ਕੈਪਚਰ ਕਰਨਾ ਪਵੇਗਾ।

### `refreshToken` ਨਾਲ ਆਟੋਮੈਟਿਕ ਰਿਫ੍ਰੈਸ਼

ਹੱਥੀਂ ਮੁੜ ਕੈਪਚਰ ਕਰਨ ਤੋਂ ਬਚਣ ਲਈ, ਤੁਸੀਂ ਕਨੈਕਸ਼ਨ ਦੀਆਂ **Advanced Settings → providerSpecificData** ਵਿੱਚ ਇੱਕ Microsoft ਰਿਫ੍ਰੈਸ਼ ਟੋਕਨ ਸਟੋਰ ਕਰ ਸਕਦੇ ਹੋ:

| ਫੀਲਡ           | ਵੇਰਵਾ                                                               |
| -------------- | ------------------------------------------------------------------- |
| `refreshToken` | `substrate.office.com/sydney` ਸਕੋਪ ਲਈ Microsoft OAuth ਰਿਫ੍ਰੈਸ਼ ਟੋਕਨ |
| `tier`         | `individual` (ਡਿਫਾਲਟ), `edu`, ਜਾਂ `enterprise`                      |

`substrate.office.com/sydney` ਲਈ ਸਕੋਪ ਕੀਤੇ Microsoft device-code ਜਾਂ authorization-code ਫਲੋ ਤੋਂ ਰਿਫ੍ਰੈਸ਼ ਟੋਕਨ ਪ੍ਰਾਪਤ ਕਰੋ। `refreshToken` ਸੈੱਟ ਹੋਣ ਉੱਤੇ, OmniRoute ਹਰ ਬੇਨਤੀ ਤੋਂ ਪਹਿਲਾਂ `access_token` ਨੂੰ ਪ੍ਰੀ-ਫਲਾਈਟ ਰਿਫ੍ਰੈਸ਼ ਕਰਦਾ ਹੈ, ਇਸ ਲਈ ਤੁਹਾਨੂੰ ਹਰ ~75-ਮਿੰਟ ਦੀ ਮਿਆਦ-ਸਮਾਪਤੀ ਤੋਂ ਬਾਅਦ ਇਸਨੂੰ ਮੁੜ ਕੈਪਚਰ ਕਰਨ ਦੀ ਲੋੜ ਨਹੀਂ ਹੁੰਦੀ।

ਜੇ `refreshToken` ਸੈੱਟ ਨਹੀਂ ਹੈ, ਤਾਂ ਤੁਹਾਨੂੰ ਹਰ ਮਿਆਦ-ਸਮਾਪਤੀ ਤੋਂ ਬਾਅਦ WebSocket ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਹੱਥੀਂ ਮੁੜ ਕੈਪਚਰ ਕਰਨਾ ਪਵੇਗਾ।

### ਟੀਅਰ ਦੀ ਚੋਣ

| ਟੀਅਰ         | ਉਪਨਾਮ      | ਸਰਫੇਸ                |
| ------------ | ---------- | -------------------- |
| `individual` | _(ਡਿਫਾਲਟ)_ | ਉਪਭੋਗਤਾ M365 Copilot |
| `edu`        | `included` | ਸਿੱਖਿਆ M365 Copilot  |
| `enterprise` | `work`     | ਕੰਮ ਲਈ M365 Copilot  |

ਟੀਅਰ ਨੂੰ **Advanced Settings → providerSpecificData → tier** ਵਿੱਚ ਸੈੱਟ ਕਰੋ। ਟੀਅਰ BizChat ਰੂਟਿੰਗ ਅਤੇ ਮਾਡਲ ਪਹੁੰਚ ਨੂੰ ਪ੍ਰਭਾਵਿਤ ਕਰਦਾ ਹੈ।

## ਸੁਰੱਖਿਆ ਮਾਡਲ

- **ਗੈਰ-ਅਧਿਕਾਰਤ ਇੰਟੀਗ੍ਰੇਸ਼ਨ।** ਇਹ ਪ੍ਰਦਾਤਾ BizChat WebSocket
  ਪ੍ਰੋਟੋਕੋਲ ਦੀ ਰਿਵਰਸ-ਇੰਜੀਨੀਅਰਿੰਗ ਕਰਦਾ ਹੈ। Microsoft ਵੱਲੋਂ ਐਂਡਪੌਇੰਟ ਬਦਲਣ 'ਤੇ ਇਹ ਬਿਨਾਂ ਕਿਸੇ ਸੂਚਨਾ ਦੇ ਕੰਮ ਕਰਨਾ ਬੰਦ ਕਰ ਸਕਦਾ ਹੈ।
- `subscriptionRisk: true` ਫਲੈਗ ਦਰਸਾਉਂਦਾ ਹੈ ਕਿ ਇਹ ਇੰਟੀਗ੍ਰੇਸ਼ਨ ਇੱਕ
  ਗੈਰ-ਦਸਤਾਵੇਜ਼ੀ ਐਂਡਪੌਇੰਟ 'ਤੇ ਨਿਰਭਰ ਕਰਦਾ ਹੈ। ਖਾਤੇ 'ਤੇ ਪਾਬੰਦੀਆਂ ਲੱਗਣ ਦੀ ਸੰਭਾਵਨਾ ਹੈ, ਪਰ ਇਸਦੀ ਪੁਸ਼ਟੀ ਨਹੀਂ ਹੋਈ।
- ਐਕਸੈੱਸ ਟੋਕਨ ਇੱਕ ਥੋੜ੍ਹੇ ਸਮੇਂ ਲਈ ਵੈਧ JWT ਹੈ। ਇਸਨੂੰ ਪਾਸਵਰਡ ਵਾਂਗ ਸੰਭਾਲੋ: ਇਸਨੂੰ ਕਮਿਟ,
  ਲੌਗ ਜਾਂ ਸਾਂਝਾ ਨਾ ਕਰੋ।
- ਰਿਫ੍ਰੈਸ਼ ਟੋਕਨ BizChat ਸਤਹ ਤੱਕ ਲੰਬੇ ਸਮੇਂ ਦੀ ਪਹੁੰਚ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ। ਇਸਨੂੰ
  API ਕੁੰਜੀ ਜਿੰਨੀ ਹੀ ਸਾਵਧਾਨੀ ਨਾਲ ਸਟੋਰ ਕਰੋ।

## ਸਮੱਸਿਆ-ਨਿਵਾਰਣ

### ਪ੍ਰਮਾਣੀਕਰਨ ਤੁਰੰਤ ਅਸਫਲ ਹੋ ਜਾਂਦਾ ਹੈ

- ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਤੁਸੀਂ **WebSocket URL** ਤੋਂ ਕਾਪੀ ਕੀਤਾ ਹੈ, ਨਾ ਕਿ ਕਿਸੇ XHR/Fetch ਬੇਨਤੀ ਤੋਂ। ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ
  Chathub WebSocket ਕਨੈਕਸ਼ਨ ਦੇ `access_token` ਕਵੇਰੀ ਪੈਰਾਮੀਟਰ ਵਿੱਚ ਹੁੰਦਾ ਹੈ —
  `Authorization: Bearer` ਹੈਡਰ ਵਿੱਚ ਨਹੀਂ।
- ਯਕੀਨੀ ਬਣਾਓ ਕਿ `chathubPath` ਵਿੱਚ URL
  ਪਾਥ ਤੋਂ ਪੂਰਾ `<oid>@<tenant>` ਭਾਗ ਸ਼ਾਮਲ ਹੈ।

### ਟੋਕਨ ਦੀ ਮਿਆਦ ~75 ਮਿੰਟਾਂ ਬਾਅਦ ਖ਼ਤਮ ਹੋ ਜਾਂਦੀ ਹੈ

ਇਹ ਉਮੀਦ ਅਨੁਸਾਰ ਹੈ। `refreshToken` ਤੋਂ ਬਿਨਾਂ, ਐਕਸੈੱਸ ਟੋਕਨ ਥੋੜ੍ਹੇ ਸਮੇਂ ਲਈ ਹੀ ਵੈਧ ਰਹਿੰਦਾ ਹੈ। ਇਨ੍ਹਾਂ ਵਿੱਚੋਂ ਕੋਈ ਇੱਕ ਕਰੋ:

- DevTools ਤੋਂ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਦੁਬਾਰਾ ਕੈਪਚਰ ਕਰੋ, ਜਾਂ
- ਆਟੋਮੈਟਿਕ ਰਿਫ੍ਰੈਸ਼ ਲਈ Advanced Settings ਵਿੱਚ `refreshToken` ਕੌਂਫਿਗਰ ਕਰੋ।

### Test Connection ਸਫਲ ਹੁੰਦਾ ਹੈ ਪਰ ਚੈਟ 401 ਵਾਪਸ ਕਰਦੀ ਹੈ

ਸੰਭਵ ਹੈ ਕਿ ਪ੍ਰਮਾਣਿਕਤਾ ਜਾਂਚ ਅਤੇ ਪਹਿਲੀ ਬੇਨਤੀ ਦੇ ਵਿਚਕਾਰ ਟੋਕਨ ਦੀ ਮਿਆਦ ਖ਼ਤਮ ਹੋ ਗਈ ਹੋਵੇ। ਇੱਕ
ਨਵਾਂ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਦੁਬਾਰਾ ਕੈਪਚਰ ਕਰੋ।

### Copilot ਪ੍ਰਦਾਤਾ ਸੂਚੀ ਵਿੱਚ ਦਿਖਾਈ ਨਹੀਂ ਦਿੰਦਾ

ਯਕੀਨੀ ਬਣਾਓ ਕਿ **Dashboard → Providers** ਵਿੱਚ `copilot-m365-web` ਸਮਰੱਥ ਹੈ। ਕੁਝ ਟੀਅਰਾਂ ਵਿੱਚ ਪ੍ਰਦਾਤਾ
ਮੂਲ ਰੂਪ ਵਿੱਚ ਲੁਕਿਆ ਹੋ ਸਕਦਾ ਹੈ।
