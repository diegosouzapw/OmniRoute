本文档记录了针对
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854) 的实现决策。面向公众的产品被划分为四个提供商系列。区域属于连接数据，而不是独立产品。

## 决策

| 提供商系列                             | OmniRoute ID            | 全球区域 | 中国区域 |
| -------------------------------------- | ----------------------- | -------- | -------- |
| Alibaba Cloud Model Studio（按量付费） | `alibaba`               | 新加坡   | 北京     |
| Alibaba Cloud Token Plan               | `bailian-coding-plan`   | 新加坡   | 北京     |
| Qwen Cloud（按量付费）                 | `qwen-cloud`            | 全球     | 北京     |
| Qwen Cloud Token Plan                  | `qwen-cloud-token-plan` | 新加坡   | 北京     |

现有的 `alibaba-cn` ID 继续作为运行时兼容性别名，用于已保存的连接、模型路由、组合以及历史使用记录。其仪表板卡片会合并到 `alibaba` 中；无需重写数据库。

Qwen Cloud 按量付费产品和 Alibaba Cloud Model Studio 目前共用与 DashScope 兼容的运行时主机，但它们仍然保留为不同的提供商身份，因为用户通过不同的产品界面获取密钥和管理账户。Alibaba 和 Qwen Cloud Token Plan 产品使用不同的端点系列，因此所有四种产品仍分别使用独立的提供商 ID。

## 端点矩阵

| 提供商系列              | `global-sg`                                                              | `china-beijing`                                                      | 传输格式  |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | --------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI    |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI    |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI    |

API 密钥和端点必须属于同一产品和区域。选择区域会更改验证请求和常规请求所使用的预设端点。

## 连接约定

新连接会将稳定的区域键存储在 `providerSpecificData` 中：

```json
{
  "region": "global-sg"
}
```

允许的值为 `global-sg` 和 `china-beijing`。端点由提供商 ID 和区域集中推导得出。非预设的 `providerSpecificData.baseUrl` 仍作为操作人员的显式覆盖设置，并具有更高优先级；而旧有已保存的预设 URL 会被规范化回区域矩阵。

这样可以保持连接架构的可扩展性：无需创建新的提供商卡片或更改已保存的提供商 ID，即可向解析器添加其他区域。

## ਅਨੁਕੂਲਤਾ ਅਤੇ ਰੋਲਆਉਟ

1. ਖੇਤਰੀ endpoint resolver ਸ਼ਾਮਲ ਕਰੋ ਅਤੇ ਮੌਜੂਦਾ global defaults ਨੂੰ ਬਰਕਰਾਰ ਰੱਖੋ।
2. `alibaba`, ਇਸ ਦੀ `alibaba-cn` compatibility ID, ਅਤੇ `qwen-cloud` ਲਈ live regional DashScope `/models` discovery ਵਰਤੋ। ਇਨ੍ਹਾਂ ਦੇ responses ਪਹਿਲਾਂ ਇੱਕ text-generation filter ਵਿੱਚੋਂ ਲੰਘਦੇ ਹਨ, ਕਿਉਂਕਿ generic endpoint image, video, audio, embedding ਅਤੇ ਹੋਰ non-chat models ਵੀ ਵਾਪਸ ਕਰਦਾ ਹੈ। ਇਸ ਤੋਂ ਬਾਅਦ `qwen-cloud` ਆਪਣੀ provider registry ਵਿੱਚ ਘੋਸ਼ਿਤ ਅਤੇ ਸੰਭਾਲੀ ਹੋਈ allowlist ਲਾਗੂ ਕਰਦਾ ਹੈ। Alibaba Model Studio ਅਤੇ Qwen Cloud ਵੱਖ-ਵੱਖ curated catalogs ਰੱਖਦੇ ਹਨ, ਭਾਵੇਂ ਉਹ ਇਸ ਵੇਲੇ ਇੱਕੋ runtime hosts ਵਰਤਦੇ ਹਨ।
3. ਮੌਜੂਦਾ Token Plan text-model allowlist ਨਾਲ `qwen-cloud-token-plan` ਨੂੰ register ਕਰੋ।
4. connection ਜੋੜਨ/ਸੰਪਾਦਿਤ ਕਰਨ ਵਾਲੇ dialogs ਵਿੱਚ typed region selector ਸ਼ਾਮਲ ਕਰੋ।
5. duplicate `alibaba-cn` card ਨੂੰ ਲੁਕਾਓ ਅਤੇ ਇਸ ਦੀਆਂ ਮੌਜੂਦਾ connections ਨੂੰ `alibaba` provider page ਉੱਤੇ ਸ਼ਾਮਲ ਕਰੋ।
6. advanced ਅਤੇ workspace-specific deployments ਲਈ custom endpoint overrides ਉਪਲਬਧ ਰੱਖੋ।

Token Plan media models chat catalog ਤੋਂ ਬਾਹਰ ਰਹਿੰਦੇ ਹਨ, ਕਿਉਂਕਿ ਉਹ dedicated endpoints ਵਰਤਦੇ ਹਨ।
`wan2.7-image` ਅਤੇ `wan2.7-image-pro` `open-sse/config/imageRegistry.ts` ਵਿੱਚ register ਕੀਤੇ ਗਏ ਹਨ;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, ਅਤੇ `happyhorse-1.1-r2v`
`open-sse/config/videoRegistry.ts` ਵਿੱਚ register ਕੀਤੇ ਗਏ ਹਨ। ਦੋਵੇਂ registries
`qwen-cloud-token-plan` connection identity ਅਤੇ ਇਸ ਦੇ region-specific credentials ਨੂੰ ਮੁੜ ਵਰਤਦੀਆਂ ਹਨ।

Regular Qwen Cloud ਦੇ `qwen-cloud` identity ਅਧੀਨ ਵੱਖਰੇ pay-as-you-go image ਅਤੇ video catalogs ਹਨ।
ਇਸ ਦੇ image models `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03`, ਅਤੇ `z-image-turbo` ਹਨ। ਇਸ ਦੇ video
models `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12`, ਅਤੇ
`wan2.7-videoedit` ਹਨ। ਇਹ models ਸਿਰਫ਼ regular `qwen-cloud` connection ਅਤੇ regional
DashScope media endpoint ਨੂੰ ਮੁੜ ਵਰਤਦੇ ਹਨ। Token Plan ਅਤੇ pay-as-you-go registries ਇੱਕ-ਦੂਜੇ ਦੀਆਂ
model lists ਨੂੰ ਨਾ inherit ਕਰਦੀਆਂ ਹਨ ਅਤੇ ਨਾ ਹੀ merge ਕਰਦੀਆਂ ਹਨ।

`bailian-coding-plan` identity ਦੀਆਂ ਆਪਣੀਆਂ media allowlists ਵੀ ਹਨ:
image generation ਲਈ `wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0`, ਅਤੇ
`qwen-image-2.0-pro`, ਨਾਲ ਹੀ video generation ਲਈ
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, ਅਤੇ `happyhorse-1.1-r2v`।
ਇਹ ਸਿਰਫ਼ Bailian Coding Plan connection ਅਤੇ regional Coding Plan endpoint ਵਰਤਦੀ ਹੈ।
ਇਸ ਦੀਆਂ image ਅਤੇ video registries ਕਿਸੇ ਵੀ Qwen Cloud provider ਤੋਂ ਨਾ inherit ਕਰਦੀਆਂ ਹਨ ਅਤੇ ਨਾ ਹੀ
ਉਸ ਨਾਲ merge ਹੁੰਦੀਆਂ ਹਨ।

Regular `alibaba` identity ਦੀਆਂ ਵੱਖਰੀਆਂ image ਅਤੇ video allowlists ਹਨ। ਇਸ ਦੇ image models
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo`, ਅਤੇ `wan2.6-t2i` ਹਨ। ਇਸ ਦੇ ਸ਼ਾਮਲ ਕੀਤੇ video models `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12`, ਅਤੇ `wan2.7-videoedit` ਹਨ। ਇਹ models ਸਿਰਫ਼ Alibaba Model Studio
connection ਅਤੇ ਇਸ ਦੇ ਚੁਣੇ ਹੋਏ regional media endpoint ਦੀ ਵਰਤੋਂ ਕਰਦੇ ਹਨ; ਇਨ੍ਹਾਂ ਨੂੰ ਕਿਸੇ ਵੀ Coding Plan ਜਾਂ Qwen
Cloud registry ਵਿੱਚ ਸ਼ਾਮਲ ਨਹੀਂ ਕੀਤਾ ਜਾਂਦਾ।

Qwen Cloud Token Plan chat catalog Individual plan ਦੀ exact-string text allowlist ਦੀ ਪਾਲਣਾ ਕਰਦਾ ਹੈ:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2`, ਅਤੇ
`deepseek-v4-pro`। Wan ਅਤੇ HappyHorse entries ਵੱਖਰੀਆਂ image/video generation APIs ਨਾਲ ਸੰਬੰਧਿਤ ਹਨ।

Alibaba Token Plan ਆਪਣੇ Anthropic-compatible endpoint ਰਾਹੀਂ ਇਹੀ ਛੇ ਮੌਜੂਦਾ text-generation model IDs
ਉਪਲਬਧ ਕਰਦਾ ਹੈ। ਇਸ ਦਾ Singapore option ਮੌਜੂਦਾ `global-sg` region key ਨੂੰ store ਕਰਦਾ ਹੈ;
ਸਿਰਫ਼ user-facing label ਉਹਨਾਂ provider families ਤੋਂ ਵੱਖਰਾ ਹੈ ਜੋ region ਨੂੰ Global ਕਹਿੰਦੀਆਂ ਹਨ।

Regular Qwen Cloud chat catalog ਨੂੰ ਜਾਣਬੁੱਝ ਕੇ ਪੂਰੇ live text response ਨਾਲੋਂ ਵਧੇਰੇ ਸੀਮਿਤ ਰੱਖਿਆ ਗਿਆ ਹੈ। ਇਸ ਦੀ
ਸੰਭਾਲੀ ਹੋਈ allowlist `open-sse/config/providers/registry/qwen-cloud/index.ts` ਵਿੱਚ ਹੈ; live
discovery ਸਿਰਫ਼ ਉਹ IDs ਵਾਪਸ ਕਰਦੀ ਹੈ ਜੋ upstream response ਅਤੇ ਉਸ registry list ਦੋਵਾਂ ਵਿੱਚ ਮੌਜੂਦ ਹਨ।

Alibaba Model Studio ਆਪਣੀ ਸੁਤੰਤਰ ਤੌਰ 'ਤੇ ਸੰਭਾਲੀ ਹੋਈ allowlist ਨਾਲ ਇਹੀ live-intersection ਨਿਯਮ ਅਪਣਾਉਂਦਾ ਹੈ,
ਜੋ `open-sse/config/providers/registry/alibaba/index.ts` ਵਿੱਚ ਹੈ। `alibaba-cn` compatibility
provider Beijing endpoint ਦੇ ਮੁਕਾਬਲੇ discovery resolve ਕਰਦੇ ਹੋਏ ਉਸੇ catalog ਨੂੰ ਮੁੜ ਵਰਤਦਾ ਹੈ।
