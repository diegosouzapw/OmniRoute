`chatgpt-web-codex` (ਉਪਨਾਮ `cgpt-codex`) ਇੱਕ ਪ੍ਰਮਾਣਿਤ ChatGPT ਬ੍ਰਾਊਜ਼ਰ ਸੈਸ਼ਨ ਰਾਹੀਂ Codex Responses ਟਰਨਾਂ ਨੂੰ ਜੋੜਦਾ ਹੈ। ਇਹ ਸੇਵਾਮੁਕਤ ਕੀਤੇ ਗਏ ਸਾਂਝੇ
`chatgpt-web` ਪ੍ਰੋਵਾਈਡਰ ਤੋਂ ਸੁਤੰਤਰ ਹੈ ਅਤੇ
`open-sse/vendor/codex-chatgpt-web/` ਅਧੀਨ MIT-ਨੋਟਿਸ ਵਾਲੇ ਇੰਪਲੀਮੈਂਟੇਸ਼ਨ ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ, ਜਿਸਨੂੰ upstream v4.0.7 ਕਮਿਟ
`b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494` ਰਾਹੀਂ ਅੱਪਡੇਟ ਕੀਤਾ ਗਿਆ ਹੈ।

## ਸਾਂਝੇ ਪ੍ਰੋਵਾਈਡਰ ਦੀ ਸੇਵਾਮੁਕਤੀ

ਪੁਰਾਣੇ ਸਾਂਝੇ ਪ੍ਰੋਵਾਈਡਰ ID `chatgpt-web` ਅਤੇ `cgpt-web` ਹੁਣ ਸ਼ਾਮਲ ਨਹੀਂ ਕੀਤੇ ਜਾਂਦੇ ਕਿਉਂਕਿ ਉਨ੍ਹਾਂ ਦੇ
pre-key/proof-of-work ਇੰਪਲੀਮੈਂਟੇਸ਼ਨ ਦਾ ਮੂਲ ਸਪਸ਼ਟ ਨਹੀਂ ਕੀਤਾ ਜਾ ਸਕਿਆ। ਕਿਸੇ ਵੀ ID ਲਈ ਸਪਸ਼ਟ
ਬੇਨਤੀਆਂ, ਜਿਨ੍ਹਾਂ ਵਿੱਚ ਸਲੈਸ਼-ਅਗੇਤਰ ਵਾਲੇ ਮਾਡਲ ID ਅਤੇ ਸੁਰੱਖਿਅਤ ਉਪਨਾਮ ਸ਼ਾਮਲ ਹਨ, ਕਿਸੇ ਵੀ upstream ਬੇਨਤੀ ਤੋਂ ਪਹਿਲਾਂ
HTTP `410` ਅਤੇ ਕੋਡ **PROVIDER_RETIRED** ਨਾਲ ਬੰਦ ਹੋ ਕੇ ਅਸਫਲ ਹੁੰਦੀਆਂ ਹਨ।

ਮਾਈਗ੍ਰੇਸ਼ਨ `168_retire_chatgpt_web.sql` ਮੇਲ ਖਾਂਦੇ ਪ੍ਰੋਵਾਈਡਰ ਕਨੈਕਸ਼ਨਾਂ ਨੂੰ tombstone ਕਰਦੀ ਹੈ ਅਤੇ
ਉਨ੍ਹਾਂ ਦੀਆਂ ਸਰਗਰਮ ਸੈਸ਼ਨ ਲੀਜ਼ਾਂ ਨੂੰ ਅਵੈਧ ਕਰਦੀ ਹੈ। ਇਹ ਕਨੈਕਸ਼ਨ ਇਤਿਹਾਸ ਅਤੇ API-key
allowlists ਨੂੰ ਸੁਰੱਖਿਅਤ ਰੱਖਦੀ ਹੈ; ਇਹ ਕਿਸੇ allowlist ਵਿੱਚ ਬਦਲਵੀਂ ਪਹੁੰਚ ਨਹੀਂ ਜੋੜਦੀ। Codex ਪ੍ਰੋਵਾਈਡਰ ਅਤੇ
ਇਸਦੇ ਕਨੈਕਸ਼ਨ ਇਸ ਸੇਵਾਮੁਕਤੀ ਨਾਲ ਮੇਲ ਨਹੀਂ ਖਾਂਦੇ।

## ਪੂਰਵ-ਲੋੜਾਂ

- ਸਾਈਨ-ਇਨ ਕੀਤੇ ChatGPT ਸੈਸ਼ਨ ਤੋਂ ਇੱਕ ਪੂਰਾ Cookie ਹੈਡਰ;
- npm, systemd, ਅਤੇ PM2 ਇੰਸਟਾਲੇਸ਼ਨਾਂ ਲਈ Chrome ਜਾਂ Chromium ਦੇ ਨਾਲ ਇੱਕ ਗ੍ਰਾਫ਼ਿਕਲ ਸੈਸ਼ਨ ਜਾਂ Xvfb ਡਿਸਪਲੇ;
- Docker `web` ਪ੍ਰੋਫ਼ਾਈਲ ਨਾਲ, `docker-compose.yml` ਤੋਂ ਅੰਦਰੂਨੀ Chromium ਸੇਵਾ;
- ਸਥਾਨਕ Codex ਟੂਲਾਂ ਲਈ OpenAI `tunnel-client` v0.0.13 ਅਤੇ ਇੱਕ ChatGPT ਕਸਟਮ ਕਨੈਕਟਰ।

ਟਨਲ ਦੀ ਲੋੜ ਸਿਰਫ਼ ਟੂਲ ਟਰਨਾਂ ਲਈ ਹੁੰਦੀ ਹੈ। `pro` ਸਮੇਤ ਸੂਚੀਬੱਧ ਹਰ ਰੂਟ, ਟਨਲ ਅਤੇ ਕਨੈਕਟਰ ਕੌਂਫਿਗਰ ਹੋਣ 'ਤੇ
ਉਸੇ ਟਰਨ-ਬਾਊਂਡ ਸਥਾਨਕ ਟੂਲ ਸਮਰੱਥਾ ਦੀ ਵਰਤੋਂ ਕਰ ਸਕਦਾ ਹੈ।

## ਡੈਸ਼ਬੋਰਡ ਸੈੱਟਅੱਪ

1. **ChatGPT Web (Codex)** ਪ੍ਰੋਵਾਈਡਰ ਖੋਲ੍ਹੋ ਅਤੇ ਇੱਕ ਕਨੈਕਸ਼ਨ ਜੋੜੋ।
2. ਪੂਰਾ ChatGPT Cookie ਹੈਡਰ, ਟਨਲ ID, ਰਨਟਾਈਮ ਕੁੰਜੀ, ਅਤੇ ਕਸਟਮ ਕਨੈਕਟਰ
   ਨਾਮ ਪੇਸਟ ਕਰੋ। ਨਵੇਂ ਟੂਲ-ਸਮਰੱਥ ਸੈੱਟਅੱਪਾਂ ਨੂੰ ਬਿਲਕੁਲ
   `OmniRoute Codex v2` ਨਾਮ ਵਾਲੇ ਨਵੇਂ ਬਣਾਏ ਕਨੈਕਟਰ ਦੀ ਵਰਤੋਂ ਕਰਨੀ ਚਾਹੀਦੀ ਹੈ, ਜਿਸ ਵਿੱਚ Authentication ਨੂੰ None ਅਤੇ Permissions ਨੂੰ Allow all
   actions 'ਤੇ ਸੈੱਟ ਕੀਤਾ ਗਿਆ ਹੋਵੇ।
3. ਕਨੈਕਸ਼ਨ ਜਾਂਚ ਚਲਾਓ। OmniRoute ਬ੍ਰਾਊਜ਼ਰ-ਬੈਕਡ Temporary Chat ਖੋਲ੍ਹਦਾ ਹੈ ਅਤੇ ਪਤਾ ਲਗਾਉਂਦਾ ਹੈ
   ਕਿ ਖਾਤੇ ਲਈ Sol ਅਤੇ Pro ਉਪਲਬਧ ਹਨ ਜਾਂ ਨਹੀਂ।
4. ਕਨੈਕਸ਼ਨ ਸੁਰੱਖਿਅਤ ਕਰੋ। OmniRoute ਪੇਸਟ ਕੀਤੀ cookie ਨੂੰ ਤਸਦੀਕਸ਼ੁਦਾ
   Playwright ਸਟੋਰੇਜ ਸਟੇਟ ਨਾਲ ਬਦਲ ਦਿੰਦਾ ਹੈ ਅਤੇ ਇਸਨੂੰ ਇਨਕ੍ਰਿਪਟਡ
   ਕ੍ਰੀਡੈਂਸ਼ਲ ਐਬਸਟਰੈਕਸ਼ਨ ਰਾਹੀਂ ਰਨਟਾਈਮ ਕੁੰਜੀ ਦੇ ਨਾਲ ਸਟੋਰ ਕਰਦਾ ਹੈ।

ਸਫਲਤਾਪੂਰਵਕ ਸੁਰੱਖਿਅਤ ਕਰਨ ਤੋਂ ਬਾਅਦ ਕੱਚੀ cookie ਬਰਕਰਾਰ ਨਹੀਂ ਰੱਖੀ ਜਾਂਦੀ। ਜਦੋਂ ਸੈਸ਼ਨ ਦੀ ਮਿਆਦ ਪੁੱਗ ਜਾਵੇ, ਤਾਂ
ਕਨੈਕਸ਼ਨ ਖੋਲ੍ਹੋ, ਇੱਕ ਤਾਜ਼ਾ ਪੂਰਾ Cookie ਹੈਡਰ ਪੇਸਟ ਕਰੋ, ਅਤੇ ਜਾਂਚ ਦੁਬਾਰਾ ਚਲਾਓ। ਸੰਪਾਦਨ ਡਾਇਲਾਗ ਵਿੱਚ doctor ਸਥਿਤੀ
ਬ੍ਰਾਊਜ਼ਰ, ਸਟੋਰੇਜ ਸਟੇਟ, ਸਾਈਨ-ਇਨ, Temporary Chat, ਟਨਲ,
ਕਨੈਕਟਰ, ਅਤੇ ਟੂਲ ਰਾਊਂਡ-ਟ੍ਰਿਪ ਦੀ ਵੱਖ-ਵੱਖ ਰਿਪੋਰਟ ਕਰਦੀ ਹੈ।

> ਕਦੇ ਵੀ ਅਸਲੀ cookie, ਰਨਟਾਈਮ ਕੁੰਜੀ, ਸਟੋਰੇਜ ਸਟੇਟ, ਜਾਂ capability token ਨੂੰ ਕਮਿਟ ਨਾ ਕਰੋ। ਟੈਸਟ ਅਤੇ
> ਦਸਤਾਵੇਜ਼ੀ ਮੁੱਲ ਹਮੇਸ਼ਾ placeholders ਹੋਣੇ ਚਾਹੀਦੇ ਹਨ।

## ਮਾਡਲ ਅਤੇ ਕੌਂਬੋ

ਨਿਸ਼ਚਿਤ ਮਾਡਲ ਰੂਟ ਇਹ ਹਨ:

- `chatgpt-web-codex/luna` — GPT-5.6 Luna, ਘੱਟ ਕੋਸ਼ਿਸ਼
- `chatgpt-web-codex/think` — GPT-5.6 Luna, ਦਰਮਿਆਨੀ ਕੋਸ਼ਿਸ਼
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

ਇਨ੍ਹਾਂ ਵਿੱਚੋਂ ਕਿਸੇ ਇੱਕ ਨੂੰ ਕਿਸੇ ਵੀ ਹੋਰ ਮਾਡਲ ਵਾਂਗ ਕੌਂਬੋ ਵਿੱਚ ਜੋੜੋ। Codex ਐਪ ਕੌਂਬੋ ਨਾਮ ਨੂੰ
`model` ਵਜੋਂ ਨਿਯਮਤ Responses endpoint, `/v1/responses`, ਨੂੰ ਭੇਜਦੀ ਹੈ; ਕੋਈ ਵੱਖਰਾ Codex
endpoint ਜਾਂ mode switch ਨਹੀਂ ਹੈ।

Free/Go ਖਾਤੇ Luna ਰੂਟ ਉਪਲਬਧ ਕਰਵਾਉਂਦੇ ਹਨ। Sol-ਸਮਰੱਥ ਖਾਤੇ Instant ਤੋਂ
High ਤੱਕ ਉਪਲਬਧ ਕਰਵਾਉਂਦੇ ਹਨ, ਅਤੇ Pro-ਸਮਰੱਥ ਖਾਤੇ ਇਸ ਤੋਂ ਇਲਾਵਾ Extra High ਅਤੇ Pro ਵੀ ਉਪਲਬਧ ਕਰਵਾਉਂਦੇ ਹਨ। ਹਰੇਕ ਰੂਟ ਦਾ ਇੱਕ
ਨਿਸ਼ਚਿਤ backend ਮਾਡਲ ਅਤੇ reasoning effort ਹੁੰਦਾ ਹੈ; ਟਕਰਾਅ ਵਾਲਾ ਸਪਸ਼ਟ Responses effort
ਚੁਣੇ ਗਏ ਬ੍ਰਾਊਜ਼ਰ ਮੋਡ ਨੂੰ ਚੁੱਪਚਾਪ ਬਦਲਣ ਦੀ ਬਜਾਏ ਬੰਦ ਹੋ ਕੇ ਅਸਫਲ ਹੁੰਦਾ ਹੈ।

ਕਿਸੇ ਪੁਰਾਣੇ `Codex Native` ਜਾਂ `OmniRoute Codex` ਕਨੈਕਟਰ ਦਾ ਨਾਮ ਨਾ ਬਦਲੋ ਜਾਂ ਉਸਦੀ ਮੁੜ ਵਰਤੋਂ ਨਾ ਕਰੋ। ChatGPT
ਕਨੈਕਟਰ ਪਛਾਣ ਦੇ ਆਧਾਰ 'ਤੇ ਜਨਤਕ MCP contract ਨੂੰ cache ਕਰਦਾ ਹੈ, ਜਦਕਿ ਅੱਪਡੇਟ ਕੀਤਾ bridge ਇੱਕ
ਨਵਾਂ ਸਿੱਧਾ turn-token contract ਵਰਤਦਾ ਹੈ। ਰਨਟਾਈਮ ਉਨ੍ਹਾਂ legacy identities ਨੂੰ ਅਸਵੀਕਾਰ ਕਰਦਾ ਹੈ ਅਤੇ
ਇੱਕ ਨਵੇਂ `OmniRoute Codex v2` ਕਨੈਕਟਰ ਦੀ ਲੋੜ ਰੱਖਦਾ ਹੈ।

## ਸੁਰੱਖਿਆ ਮਾਡਲ

- ਨੇਟਿਵ ਪਾਥ ਲਈ ਇੱਕ Responses ਬੇਨਤੀ, ਇੱਕ ਮਾਨਤਾ-ਪ੍ਰਾਪਤ Codex ਕਲਾਇੰਟ, ਅਤੇ ਮੇਲ ਖਾਂਦੀਆਂ
  ਥ੍ਰੈੱਡ ਅਤੇ ਟਰਨ ਪਛਾਣਾਂ ਲੋੜੀਂਦੀਆਂ ਹਨ।
- ਵਰਕਸਪੇਸ, ਸੈਂਡਬਾਕਸ, ਮਨਜ਼ੂਰੀ ਨੀਤੀ, ਅਤੇ ਟੂਲ ਕੈਟਾਲਾਗ ਨੇਟਿਵ Codex ਸ਼ੈੱਲ ਤੋਂ ਆਉਂਦੇ ਹਨ;
  ਮੁਕਤ-ਰੂਪ ਪ੍ਰੌਮਪਟ ਟੈਕਸਟ ਇਨ੍ਹਾਂ ਲਈ ਅਧਿਕਾਰਤ ਸਰੋਤ ਨਹੀਂ ਹੈ।
- ChatGPT ਨੂੰ ਹਰ ਟਰਨ ਲਈ ਸਿਰਫ਼ ਇੱਕ ਛੋਟੀ ਮਿਆਦ ਵਾਲੀ ਸਮਰੱਥਾ ਮਿਲਦੀ ਹੈ। MCP ਬ੍ਰੋਕਰ ਸਿਰਫ਼
  ਉਹੀ ਟੂਲ ਸਵੀਕਾਰ ਕਰਦਾ ਹੈ ਜੋ Codex ਨੇ ਉਸੇ ਟਰਨ ਵਿੱਚ ਪੇਸ਼ ਕੀਤੇ ਸਨ।
- **Allow once** ਦੀ ਸਵੈਚਲਿਤ ਪੁਸ਼ਟੀ ਸਿਰਫ਼ ਟੂਲ ਬੇਨਤੀ ਨੂੰ Codex ਕੋਲ ਵਾਪਸ ਭੇਜਦੀ ਹੈ। ਮਨਜ਼ੂਰੀ ਅਤੇ
  ਐਗਜ਼ੀਕਿਊਸ਼ਨ ਬਾਰੇ ਫ਼ੈਸਲਾ ਸਿਰਫ਼ Codex ਹੀ ਕਰਦਾ ਹੈ।
- ਪਹਿਲੀ ਆਉਟਪੁੱਟ ਤੋਂ ਪਹਿਲਾਂ, ਕੋਈ ਕੰਬੋ ਕਿਸੇ ਹੋਰ ਅਨੁਕੂਲ ਟਾਰਗੇਟ 'ਤੇ ਫਾਲਬੈਕ ਕਰ ਸਕਦਾ ਹੈ। ਆਉਟਪੁੱਟ
  ਸ਼ੁਰੂ ਹੋਣ ਤੋਂ ਬਾਅਦ, ਟਰਨ ਪੂਰਾ ਹੋਣ ਤੱਕ ਪ੍ਰਦਾਤਾ, ਮਾਡਲ, ਕਨੈਕਸ਼ਨ, ਅਤੇ ਬ੍ਰਾਊਜ਼ਰ ਟਰਨ ਪਿੰਨ ਰਹਿੰਦੇ ਹਨ।
- ਕੁਕੀਜ਼, ਰਨਟਾਈਮ ਕੁੰਜੀਆਂ, ਸਟੋਰੇਜ ਸਥਿਤੀ, ਅਤੇ ਸਮਰੱਥਾ ਟੋਕਨ ਪ੍ਰਦਾਤਾ ਦੇ
  ਜਵਾਬਾਂ ਜਾਂ ਬੇਨਤੀ ਲੌਗਾਂ ਵਿੱਚ ਦਿਖਾਈ ਨਹੀਂ ਦਿੰਦੇ।

## ਡਿਸਪਲੇ-ਰਹਿਤ VPS ਅਤੇ Docker

npm, systemd, ਅਤੇ PM2 ਇੰਸਟਾਲੇਸ਼ਨਾਂ ਲਈ, OmniRoute ਆਮ Chrome ਅਤੇ Chromium ਪਾਥਾਂ ਦਾ ਪਤਾ ਲਗਾਉਂਦਾ ਹੈ।
ਵਿਕਲਪਕ ਤੌਰ 'ਤੇ, `CHATGPT_WEB_CODEX_CHROME_PATH` ਸੈੱਟ ਕਰੋ। ਰਨਟਾਈਮ ਟਰਨ ਜਾਣ-ਬੁੱਝ ਕੇ ਹੈੱਡਡ
Chrome ਵਰਤਦੇ ਹਨ ਕਿਉਂਕਿ ChatGPT ਅਸਲ ਹੈੱਡਲੈੱਸ ਬ੍ਰਾਊਜ਼ਰ ਬਣਤਰ ਨੂੰ ਰੱਦ ਕਰਦਾ ਹੈ। ਇਸ ਲਈ ਡਿਸਪਲੇ-ਰਹਿਤ ਹੋਸਟ ਨੂੰ
OmniRoute ਨੂੰ ਇੱਕ ਨਿੱਜੀ Xvfb ਡਿਸਪਲੇ ਨਾਲ ਚਲਾਉਣਾ ਲਾਜ਼ਮੀ ਹੈ; ਸਿਰਫ਼ Chrome ਪਾਥ ਸੈੱਟ ਕਰਨ ਨਾਲ ਡਿਸਪਲੇ ਉਪਲਬਧ ਨਹੀਂ ਹੁੰਦਾ।

Docker `web` ਪ੍ਰੋਫ਼ਾਈਲ ਅੰਦਰੂਨੀ Compose
ਨੈੱਟਵਰਕ 'ਤੇ `chatgpt-web-codex-browser` ਸ਼ੁਰੂ ਕਰਦਾ ਹੈ। ਸਾਈਡਕਾਰ Xvfb ਦੇ ਅੰਦਰ ਹੈੱਡਡ Chrome ਚਲਾਉਂਦਾ ਹੈ, ਇਸ ਲਈ ਕਿਸੇ ਭੌਤਿਕ ਡਿਸਪਲੇ ਦੀ ਲੋੜ ਨਹੀਂ ਹੈ। ਇਸਦਾ CDP
ਪੋਰਟ ਹੋਸਟ 'ਤੇ ਪ੍ਰਕਾਸ਼ਿਤ ਨਹੀਂ ਕੀਤਾ ਜਾਂਦਾ। ਸੁਰੱਖਿਅਤ ਬ੍ਰਾਊਜ਼ਰ ਪ੍ਰੋਫ਼ਾਈਲ ਵਾਲਿਊਮ
OmniRoute ਡਾਟਾ ਵਾਲਿਊਮ ਤੋਂ ਵੱਖਰਾ ਹੈ, ਅਤੇ ਬ੍ਰਾਊਜ਼ਰ ਨੂੰ ਲੋੜੀਂਦੀ ਸਾਂਝੀ ਮੈਮੋਰੀ ਮਿਲਦੀ ਹੈ। ਅੰਦਰੂਨੀ CDP ਪ੍ਰੌਕਸੀ
Compose ਨੈੱਟਵਰਕ ਦੇ ਅੰਦਰ ਸਿਰਫ਼ ਪੋਰਟ `9223` 'ਤੇ ਸੁਣਦੀ ਹੈ; Chrome ਸਾਈਡਕਾਰ ਵਿੱਚ ਲੂਪਬੈਕ ਨਾਲ ਹੀ ਬੱਝਿਆ ਰਹਿੰਦਾ ਹੈ।

`DATA_DIR` ਦੇ ਅਧੀਨ ਇੱਕ ਸੁਪਰਵਾਈਜ਼ਰ ਲੀਜ਼ ਕਈ OmniRoute ਪ੍ਰਕਿਰਿਆਵਾਂ ਨੂੰ
ਇੱਕੋ ਟਨਲ ਅਤੇ ਬ੍ਰੋਕਰ ਸਥਿਤੀ ਦੀ ਮਾਲਕੀ ਲੈਣ ਤੋਂ ਰੋਕਦੀ ਹੈ। ਕਿਸੇ ਟਕਰਾਅ ਦੀ ਰਿਪੋਰਟ ਡਾਕਟਰ ਵੱਲੋਂ ਕੀਤੀ ਜਾਂਦੀ ਹੈ।

## ਇੰਟਰਐਕਟਿਵ ਰਿਕਵਰੀ

ਸਵੈਚਲਿਤ Docker ਪਾਥ ਵਿੱਚ ਹੋਸਟ ਨੂੰ ਦਿਸਣ ਵਾਲੀ ਕੋਈ ਵਿੰਡੋ ਨਹੀਂ ਹੁੰਦੀ, ਪਰ Chrome ਖੁਦ ਨਿੱਜੀ
Xvfb ਡਿਸਪਲੇ ਦੇ ਅੰਦਰ ਹੈੱਡਡ ਹੁੰਦਾ ਹੈ। ਜਦੋਂ ChatGPT ਨੂੰ ਇੰਟਰਐਕਟਿਵ ਸਾਈਨ-ਇਨ ਜਾਂ ਚੁਣੌਤੀ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ, ਤਾਂ ਰਿਕਵਰੀ ਲਈ ਮੌਜੂਦਾ VNC
ਬ੍ਰਾਊਜ਼ਰ ਬੁਨਿਆਦੀ ਢਾਂਚਾ ਵਰਤਿਆ ਜਾ ਸਕਦਾ ਹੈ। ਬ੍ਰਾਊਜ਼ਰ UI ਅਤੇ CDP ਸਿਰਫ਼
ਲੂਪਬੈਕ, ਪ੍ਰਮਾਣਿਤ ਪ੍ਰਬੰਧਨ ਕਨੈਕਸ਼ਨ, ਜਾਂ SSH ਟਨਲ ਰਾਹੀਂ ਹੀ ਪਹੁੰਚਯੋਗ ਰਹਿਣੇ ਚਾਹੀਦੇ ਹਨ; ਆਮ ਕਾਰਵਾਈ ਦੌਰਾਨ noVNC ਅਯੋਗ ਰਹਿੰਦਾ ਹੈ।

## WebSocket ਫਾਲਬੈਕ

ਜਦੋਂ ਕਿਸੇ ਕੰਬੋ ਵਿੱਚ ChatGPT Web (Codex) ਸ਼ਾਮਲ ਹੁੰਦਾ ਹੈ, ਤਾਂ Responses WebSocket ਬ੍ਰਿਜ ਅੱਪਸਟ੍ਰੀਮ ਨਾਲ ਜੁੜਨ ਤੋਂ ਪਹਿਲਾਂ
HTTP/SSE ਫਾਲਬੈਕ ਦੀ ਬੇਨਤੀ ਕਰਦਾ ਹੈ। ਫਿਰ ਟ੍ਰਾਂਸਫਰ
`/v1/responses` ਰਾਹੀਂ ਹੁੰਦਾ ਹੈ।
