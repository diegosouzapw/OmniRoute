IDE ਸੈਸ਼ਨ ਤੋਂ ਬਿਨਾਂ Cursor ਨੂੰ OmniRoute ਦੇ ਪਿੱਛੇ ਰੱਖਣ ਦੇ ਦੋ ਤਰੀਕੇ:

1. **`cursor-api` ਪ੍ਰਦਾਤਾ** (ਕਾਰਡ "Cursor API", ਉਪਨਾਮ `cua`): ਇੱਕ API-ਕੁੰਜੀ
   ਪ੍ਰਦਾਤਾ ਜੋ Cursor ਵਰਤੋਂਕਾਰ API ਕੁੰਜੀ (`crsr_…`, ਜੋ
   `https://cursor.com/dashboard/api` ਉੱਤੇ ਬਣਾਈ ਜਾਂਦੀ ਹੈ) ਸੰਭਾਲਦਾ ਹੈ। ਫਿਰ ਕੋਈ ਵੀ OmniRoute ਕਲਾਇੰਟ
   ਆਮ ਕੋਟਾ, ਫਾਲਬੈਕ ਅਤੇ ਲੌਗਿੰਗ ਪਰਤਾਂ ਸਮੇਤ `/v1/chat/completions` ਰਾਹੀਂ
   `cursor-api/<model>` ਜਾਂ `cua/<model>` ਵਜੋਂ Cursor ਮਾਡਲਾਂ ਤੱਕ ਪਹੁੰਚਦਾ ਹੈ। IDE
   ਪ੍ਰਦਾਤਾ (`cursor`, OAuth/IDE ਸੈਸ਼ਨ) ਵਿੱਚ ਕੋਈ ਤਬਦੀਲੀ ਨਹੀਂ ਕੀਤੀ ਗਈ।
2. **Cursor CLI ਪਾਸਥਰੂ**: Cursor CLI (`agent`) ਨੂੰ OmniRoute ਵੱਲ ਇਸ਼ਾਰਾ ਕਰਵਾਓ ਤਾਂ ਜੋ
   CLI ਵੱਲੋਂ ਕੀਤੀ ਹਰ RPC ਨੂੰ OmniRoute API ਕੁੰਜੀ ਨਾਲ ਪ੍ਰਮਾਣਿਤ ਕੀਤਾ ਜਾਵੇ,
   `cursor-api` ਕਨੈਕਸ਼ਨ ਦੇ ਕ੍ਰੈਡੈਂਸ਼ਲ ਨਾਲ Cursor ਨੂੰ ਅੱਗੇ ਭੇਜਿਆ ਜਾਵੇ ਅਤੇ
   ਲੌਗ ਪੰਨੇ ਵਿੱਚ ਦਰਜ ਕੀਤਾ ਜਾਵੇ।

## ਕੁੰਜੀ ਦਾ ਵਟਾਂਦਰਾ ਕਿਉਂ ਕੀਤਾ ਜਾਂਦਾ ਹੈ

`api2.cursor.sh` ਇੱਕ ਕੱਚੀ `crsr_…` ਕੁੰਜੀ ਨੂੰ Bearer ਟੋਕਨ ਵਜੋਂ ਅਸਵੀਕਾਰ ਕਰਦਾ ਹੈ (401)। Cursor
CLI ਪਹਿਲਾਂ ਕੁੰਜੀ ਨੂੰ `/auth/exchange_user_api_key` ਉੱਤੇ POST ਕਰਦਾ ਹੈ ਅਤੇ ਇੱਕ ਸੈਸ਼ਨ
JWT ਪ੍ਰਾਪਤ ਕਰਦਾ ਹੈ ਜੋ ਇੱਕ ਘੰਟੇ ਬਾਅਦ ਮਿਆਦ ਪੁੱਗ ਜਾਂਦਾ ਹੈ; ਵਾਪਸ ਮਿਲੇ `refreshToken` ਵਿੱਚ ਵੀ ਉਹੀ
`exp` ਹੁੰਦਾ ਹੈ, ਇਸ ਲਈ ਰਿਫ੍ਰੈਸ਼ ਕਰਨ ਦਾ ਅਰਥ ਕੁੰਜੀ ਦਾ ਮੁੜ ਵਟਾਂਦਰਾ ਕਰਨਾ ਹੈ।
`open-sse/services/cursorApiKeyAuth.ts` ਇਹ ਵਟਾਂਦਰਾ ਕਰਦਾ ਹੈ, ਹਰ ਕੁੰਜੀ ਲਈ ਇੱਕ ਸੈਸ਼ਨ
ਟੋਕਨ ਕੈਸ਼ ਕਰਦਾ ਹੈ, ਮਿਆਦ ਪੁੱਗਣ ਤੋਂ ਪੰਜ ਮਿੰਟ ਪਹਿਲਾਂ ਮੁੜ ਵਟਾਂਦਰਾ ਕਰਦਾ ਹੈ ਅਤੇ Cursor ਵੱਲੋਂ
401 ਜਵਾਬ ਆਉਣ ਉੱਤੇ ਕੈਸ਼ ਕੀਤਾ ਟੋਕਨ ਹਟਾ ਦਿੰਦਾ ਹੈ। `CursorExecutor`, `cursor-api`
ਕਨੈਕਸ਼ਨਾਂ ਲਈ ਅੱਪਸਟ੍ਰੀਮ ਸਟ੍ਰੀਮ ਖੋਲ੍ਹਣ ਤੋਂ ਬਿਲਕੁਲ ਪਹਿਲਾਂ ਇਸਨੂੰ ਕਾਲ ਕਰਦਾ ਹੈ।

## `cursor-api` ਪ੍ਰਦਾਤਾ

ਰਜਿਸਟਰੀ: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, ਉਹੀ `format`, `baseUrl` ਅਤੇ
`models` ਜੋ `cursor` ਦੇ ਹਨ)। ਕੈਟਾਲੌਗ ਕਾਰਡ:
`src/shared/constants/providers/apikey/specialty-media.ts`। ਐਗਜ਼ਿਕਿਊਟਰ ਮੈਪ:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`)।

ਡੈਸ਼ਬੋਰਡ: ਪ੍ਰਦਾਤਾ → Cursor API → API ਕੁੰਜੀ ਸ਼ਾਮਲ ਕਰੋ।

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

ਫਿਰ:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

ਨੋਟ:

- `cursor-api` ਲਈ ਮਾਡਲ ਸੂਚੀ ਸਥਿਰ Cursor ਰਜਿਸਟਰੀ ਤੋਂ ਆਉਂਦੀ ਹੈ (ਉਹੀ
  ਸੂਚੀ ਜਿਸਨੂੰ IDE ਪ੍ਰਦਾਤਾ ਫਾਲਬੈਕ ਵਜੋਂ ਵਰਤਦਾ ਹੈ); OmniRoute ਹੋਸਟ ਉੱਤੇ
  `cursor-agent` ਇੰਸਟਾਲ ਕਰਨ ਦੀ ਲੋੜ ਨਹੀਂ ਹੈ।
- `POST /api/providers/{id}/refresh-cursor` ਸਿਰਫ਼ `cursor` IDE ਪ੍ਰਦਾਤਾ
  ਲਈ ਹੈ; `cursor-api` ਕਨੈਕਸ਼ਨਾਂ ਕੋਲ ਨਵਿਆਉਣ ਲਈ ਕੋਈ IDE ਸੈਸ਼ਨ ਨਹੀਂ ਹੁੰਦਾ।

## Cursor CLI ਪਾਸਥਰੂ

ਰੂਟ: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`। ਪ੍ਰੀਫਿਕਸ `/api/cursor-cli/` ਨੂੰ
`src/shared/constants/publicApiRoutes.ts` ਵਿੱਚ ਰਜਿਸਟਰ ਕੀਤਾ ਗਿਆ ਹੈ ਕਿਉਂਕਿ ਹੈਂਡਲਰ
ਆਪਣਾ ਪ੍ਰਮਾਣੀਕਰਨ ਖੁਦ ਲਾਗੂ ਕਰਦਾ ਹੈ:

| ਪਾਥ                                                                                                                    | CLI ਤੋਂ ਉਮੀਦ ਕੀਤਾ ਪ੍ਰਮਾਣੀਕਰਨ | OmniRoute ਕੀ ਕਰਦਾ ਹੈ                                                                                                                                                          |
| ---------------------------------------------------------------------------------------------------------------------- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                     | `Bearer <OmniRoute API key>` | ਕੁੰਜੀ ਨੂੰ ਪ੍ਰਮਾਣਿਤ ਕਰਦਾ ਹੈ, 1 ਘੰਟੇ ਦਾ HS256 JWT (`JWT_SECRET` ਨਾਲ ਦਸਤਖ਼ਤ ਕੀਤਾ) ਬਣਾਉਂਦਾ ਹੈ ਅਤੇ ਇਸਨੂੰ ਵਾਪਸ ਕਰਦਾ ਹੈ                                                              |
| ਹਰ ਹੋਰ ਪਾਥ (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`          | ਜਾਰੀਕਰਤਾ/ਦਰਸ਼ਕ/ਮਿਆਦ ਦੀ ਪੁਸ਼ਟੀ ਕਰਦਾ ਹੈ, ਇੱਕ ਸਰਗਰਮ `cursor-api` ਕਨੈਕਸ਼ਨ ਚੁਣਦਾ ਹੈ, Authorization ਹੈਡਰ ਨੂੰ ਵਟਾਂਦਰਾ ਕੀਤੇ Cursor ਟੋਕਨ ਨਾਲ ਬਦਲਦਾ ਹੈ ਅਤੇ ਜਵਾਬ ਨੂੰ ਵਾਪਸ ਸਟ੍ਰੀਮ ਕਰਦਾ ਹੈ |

CLI ਪ੍ਰਾਪਤ ਹੋਣ ਵਾਲੇ ਕਿਸੇ ਵੀ ਟੋਕਨ ਤੋਂ `exp` ਡੀਕੋਡ ਕਰਦਾ ਹੈ, ਇਸ ਲਈ ਇਸਨੂੰ ਇੱਕ ਅਪਾਰਦਰਸ਼ੀ
ਟੋਕਨ ਦੇਣ ਨਾਲ ਇਹ ਲਗਭਗ ਹਰ ਬੇਨਤੀ ਤੋਂ ਪਹਿਲਾਂ ਮੁੜ ਵਟਾਂਦਰਾ ਕਰਦਾ ਹੈ; ਬਣਾਇਆ ਗਿਆ JWT ਇਸ ਤੋਂ
ਬਚਾਉਂਦਾ ਹੈ। OmniRoute ਤੋਂ 401 ਮਿਲਣ ਉੱਤੇ CLI ਦੁਬਾਰਾ ਵਟਾਂਦਰਾ ਕਰਦਾ ਹੈ।

### ਸੈਟਅੱਪ

1. ਇੱਕ OmniRoute API ਕੁੰਜੀ (ਡੈਸ਼ਬੋਰਡ → API ਕੁੰਜੀਆਂ) ਅਤੇ ਇੱਕ `cursor-api`
   ਕਨੈਕਸ਼ਨ ਬਣਾਓ।
2. CLI ਨੂੰ ਏਜੰਟ ਸਟ੍ਰੀਮ ਲਈ HTTP/1.1 ਵਰਤਣ ਲਈ ਕਹੋ।
   `~/.cursor/cli-config.json` ਵਿੱਚ:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   ਇਸ ਤੋਂ ਬਿਨਾਂ CLI, ਵੱਖਰੇ ਤੌਰ ਉੱਤੇ ਸੰਰਚਿਤ ਏਜੰਟ ਹੋਸਟ ਵੱਲ HTTP/2 ਰਾਹੀਂ ਏਜੰਟ ਟਰਨ
   ਖੋਲ੍ਹਦਾ ਹੈ ਅਤੇ ਸਿਰਫ਼ ਕੰਟਰੋਲ-ਪਲੇਨ RPCs ਹੀ ਐਂਡਪੌਇੰਟ ਰਾਹੀਂ ਜਾਂਦੀਆਂ ਹਨ।

3. CLI ਨੂੰ OmniRoute ਦੇ ਵਿਰੁੱਧ ਚਲਾਓ:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

ਹਰ ਹੌਪ ਲੌਗਾਂ ਵਿੱਚ ਪ੍ਰਦਾਤਾ `cursor-api`, ਬੇਨਤੀ ਕਿਸਮ `cursor-cli`,
ਪਾਥ `/api/cursor-cli/<rpc>` ਵਜੋਂ ਦਰਜ ਹੁੰਦਾ ਹੈ ਅਤੇ OmniRoute API ਕੁੰਜੀ ਅਤੇ
ਇਸਨੂੰ ਸੇਵਾ ਦੇਣ ਵਾਲੇ ਕਨੈਕਸ਼ਨ ਨਾਲ ਜੋੜਿਆ ਜਾਂਦਾ ਹੈ।

### ਅਸਫਲਤਾ ਦੀਆਂ ਸਥਿਤੀਆਂ

| ਸਥਿਤੀ                                            | CLI ਲਈ ਜਵਾਬ                                           |
| ------------------------------------------------ | ----------------------------------------------------- |
| ਅਣਜਾਣ OmniRoute ਕੁੰਜੀ ਅਤੇ `REQUIRE_API_KEY=true` | ਐਕਸਚੇਂਜ ਦੌਰਾਨ 401 `unauthenticated`                   |
| `REQUIRE_API_KEY=false`                          | ਅਗਿਆਤ ਸੈਸ਼ਨ (`/v1/*` ਦੇ ਵਿਹਾਰ ਨੂੰ ਦਰਸਾਉਂਦਾ ਹੈ)        |
| ਮਿਆਦ ਪੁੱਗਿਆ / ਵਿਦੇਸ਼ੀ / ਛੇੜਛਾੜ ਕੀਤਾ ਸੈਸ਼ਨ JWT    | 401, CLI ਮੁੜ ਐਕਸਚੇਂਜ ਕਰਦਾ ਹੈ                          |
| ਐਕਸਚੇਂਜ ਤੋਂ ਬਾਅਦ OmniRoute API ਕੁੰਜੀ ਰੱਦ ਕੀਤੀ ਗਈ | ਅਗਲੀ RPC 'ਤੇ 401                                      |
| ਕੋਈ ਸਰਗਰਮ `cursor-api` ਕਨੈਕਸ਼ਨ ਨਹੀਂ              | 503 `unavailable`                                     |
| Cursor ਕਨੈਕਸ਼ਨ ਦੀ ਕੁੰਜੀ ਨੂੰ ਅਸਵੀਕਾਰ ਕਰਦਾ ਹੈ      | 401 `unauthenticated`, ਕੈਸ਼ ਕੀਤਾ ਸੈਸ਼ਨ ਹਟਾਇਆ ਜਾਂਦਾ ਹੈ |
| ਅੱਪਸਟ੍ਰੀਮ ਤੱਕ ਪਹੁੰਚ ਨਹੀਂ                         | 502 `unavailable` (ਸਾਫ਼ ਕੀਤਾ ਸੁਨੇਹਾ)                  |
| `JWT_SECRET` ਸੈੱਟ ਨਹੀਂ ਹੈ                        | ਐਕਸਚੇਂਜ ਦੌਰਾਨ 503                                     |
