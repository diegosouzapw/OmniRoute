Web Cookie ਪ੍ਰਦਾਤਾ OmniRoute ਨੂੰ API key ਦੀ ਬਜਾਏ ਤੁਹਾਡੇ ਮੌਜੂਦਾ ਬ੍ਰਾਊਜ਼ਰ ਸੈਸ਼ਨ ਰਾਹੀਂ ਕਿਸੇ AI ਸੇਵਾ ਦੀ ਵਰਤੋਂ ਕਰਨ ਦਿੰਦੇ ਹਨ। ਇਹ ਉਦੋਂ ਲਾਭਦਾਇਕ ਹੁੰਦੇ ਹਨ ਜਦੋਂ ਤੁਹਾਡੇ ਕੋਲ ਪਹਿਲਾਂ ਹੀ ਕਿਸੇ ਸੇਵਾ ਦੀ ਵੈੱਬਸਾਈਟ ਰਾਹੀਂ ਪਹੁੰਚ ਹੋਵੇ ਅਤੇ ਤੁਸੀਂ ਚਾਹੁੰਦੇ ਹੋ ਕਿ OmniRoute ਉਸੇ ਪ੍ਰਮਾਣਿਤ ਸੈਸ਼ਨ ਦੀ ਵਰਤੋਂ ਕਰੇ।

API-key ਪ੍ਰਦਾਤਾਵਾਂ ਤੋਂ ਵੱਖਰੇ ਤੌਰ 'ਤੇ, Web Cookie ਪ੍ਰਦਾਤਾ ਉਹਨਾਂ ਪ੍ਰਮਾਣ-ਪੱਤਰਾਂ ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਪ੍ਰਮਾਣੀਕਰਨ ਕਰਦੇ ਹਨ ਜੋ ਤੁਹਾਡਾ ਬ੍ਰਾਊਜ਼ਰ ਵੈੱਬਸਾਈਟ ਨੂੰ ਭੇਜਦਾ ਹੈ।

# ਸ਼ੁਰੂ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ

> **ਮਹੱਤਵਪੂਰਨ:** ਪ੍ਰਮਾਣ-ਪੱਤਰ ਹਮੇਸ਼ਾ ਕਿਸੇ **ਲਾਈਵ ਨੈੱਟਵਰਕ ਬੇਨਤੀ** ਤੋਂ ਕਾਪੀ ਕਰੋ, ਆਪਣੇ ਬ੍ਰਾਊਜ਼ਰ ਦੀ cookie ਸਟੋਰੇਜ ਤੋਂ **ਨਹੀਂ**।

ਪ੍ਰਮਾਣੀਕਰਨ ਦੀਆਂ ਬਹੁਤ ਸਾਰੀਆਂ ਸਮੱਸਿਆਵਾਂ cookies ਨੂੰ ਗਲਤ ਥਾਂ ਤੋਂ ਕਾਪੀ ਕਰਨ ਕਾਰਨ ਪੈਦਾ ਹੁੰਦੀਆਂ ਹਨ।

## Cookie ਸਟੋਰੇਜ ਤੋਂ ਕਾਪੀ ਨਾ ਕਰੋ

ਜ਼ਿਆਦਾਤਰ ਬ੍ਰਾਊਜ਼ਰ ਸਟੋਰ ਕੀਤੀਆਂ cookies ਨੂੰ ਇਸ ਰਾਹੀਂ ਦਿਖਾਉਂਦੇ ਹਨ:

```
DevTools
→ Application (ਜਾਂ Storage)
→ Cookies
```

ਭਾਵੇਂ ਇਹ cookies ਸਹੀ ਦਿਖਾਈ ਦਿੰਦੀਆਂ ਹਨ, ਪਰ ਇਹ ਹੋ ਸਕਦੀਆਂ ਹਨ:

- ਪੁਰਾਣੀਆਂ
- ਅਧੂਰੀਆਂ
- ਉਹਨਾਂ cookies ਤੋਂ ਰਹਿਤ ਜੋ ਸਿਰਫ਼ ਪ੍ਰਮਾਣਿਤ ਬੇਨਤੀਆਂ 'ਤੇ ਭੇਜੀਆਂ ਜਾਂਦੀਆਂ ਹਨ

ਇਹਨਾਂ ਮੁੱਲਾਂ ਦੀ ਵਰਤੋਂ ਕਰਨ ਨਾਲ ਪ੍ਰਮਾਣੀਕਰਨ ਅਸਫਲ ਹੋ ਸਕਦਾ ਹੈ, ਭਾਵੇਂ ਇਹ ਵੈਧ ਦਿਖਾਈ ਦੇਣ।

## ਲਾਈਵ ਬੇਨਤੀ ਤੋਂ ਕਾਪੀ ਕਰੋ

ਇਸ ਦੀ ਬਜਾਏ, ਕਿਸੇ ਸਫਲ ਬੇਨਤੀ ਤੋਂ cookies ਦੀ ਵਰਤੋਂ ਕਰੋ:

```
DevTools
→ Network
→ ਪੰਨੇ ਨੂੰ ਤਾਜ਼ਾ ਕਰੋ
→ ਕੋਈ chat ਜਾਂ conversation ਬੇਨਤੀ ਖੋਲ੍ਹੋ
→ Request Headers
→ Cookie
```

`Cookie` ਬੇਨਤੀ ਹੈਡਰ ਵਿੱਚ ਉਹ ਸਟੀਕ ਪ੍ਰਮਾਣੀਕਰਨ ਜਾਣਕਾਰੀ ਹੁੰਦੀ ਹੈ ਜਿਸਦੀ ਤੁਹਾਡੇ ਬ੍ਰਾਊਜ਼ਰ ਨੇ ਸਫਲਤਾਪੂਰਵਕ ਵਰਤੋਂ ਕੀਤੀ ਸੀ।

ਜ਼ਿਆਦਾਤਰ Web Cookie ਪ੍ਰਦਾਤਾਵਾਂ ਲਈ, ਇਹੀ ਉਹ ਮੁੱਲ ਹੈ ਜੋ OmniRoute ਵਿੱਚ ਪੇਸਟ ਕੀਤਾ ਜਾਣਾ ਚਾਹੀਦਾ ਹੈ।

# ਆਮ ਸੈੱਟਅੱਪ

ਜ਼ਿਆਦਾਤਰ Web Cookie ਪ੍ਰਦਾਤਾਵਾਂ ਲਈ ਸੈੱਟਅੱਪ ਪ੍ਰਕਿਰਿਆ ਇੱਕੋ ਜਿਹੀ ਹੈ।

1. ਪ੍ਰਦਾਤਾ ਦੀ ਵੈੱਬਸਾਈਟ 'ਤੇ ਸਾਈਨ ਇਨ ਕਰੋ।
2. ਬ੍ਰਾਊਜ਼ਰ ਦੇ Developer Tools ਖੋਲ੍ਹੋ।
3. **Network** ਟੈਬ ਖੋਲ੍ਹੋ।
4. ਪੰਨੇ ਨੂੰ ਤਾਜ਼ਾ ਕਰੋ।
5. ਕੋਈ ਪ੍ਰਮਾਣਿਤ chat ਜਾਂ conversation ਬੇਨਤੀ ਖੋਲ੍ਹੋ।
6. ਲੋੜੀਂਦੇ ਪ੍ਰਮਾਣੀਕਰਨ ਪ੍ਰਮਾਣ-ਪੱਤਰ ਕਾਪੀ ਕਰੋ।
7. OmniRoute ਖੋਲ੍ਹੋ।
8. **Providers → Add Provider** 'ਤੇ ਜਾਓ।
9. ਆਪਣਾ Web Cookie ਪ੍ਰਦਾਤਾ ਚੁਣੋ।
10. ਪ੍ਰਮਾਣ-ਪੱਤਰ ਪੇਸਟ ਕਰੋ।
11. **Test Connection** 'ਤੇ ਕਲਿੱਕ ਕਰੋ।
12. ਪ੍ਰਦਾਤਾ ਨੂੰ ਸੇਵ ਕਰੋ।

ਲੋੜੀਂਦੇ ਸਟੀਕ ਪ੍ਰਮਾਣ-ਪੱਤਰ ਪ੍ਰਦਾਤਾ 'ਤੇ ਨਿਰਭਰ ਕਰਦੇ ਹਨ।

# Web Cookie ਪ੍ਰਦਾਤਾ ਕੀ ਕਰ ਸਕਦੇ ਹਨ ਅਤੇ ਕੀ ਨਹੀਂ

Web Cookie ਪ੍ਰਦਾਤਾ ਕਿਸੇ ਵੈੱਬਸਾਈਟ ਦੇ chat ਇੰਟਰਫੇਸ ਨੂੰ ਮੁੜ ਵਰਤਦੇ ਹਨ। ਇਹ ਅਧਿਕਾਰਤ APIs ਵਰਗੀਆਂ ਸਮਰੱਥਾਵਾਂ ਪ੍ਰਦਾਨ **ਨਹੀਂ** ਕਰਦੇ।

## ਸਮਰਥਿਤ

- ਆਪਣੇ ਮੌਜੂਦਾ ਬ੍ਰਾਊਜ਼ਰ ਸੈਸ਼ਨ ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਪ੍ਰਮਾਣੀਕਰਨ ਕਰਨਾ
- ਆਪਣੇ ਖਾਤੇ ਰਾਹੀਂ ਉਪਲਬਧ models ਤੱਕ ਪਹੁੰਚ ਕਰਨਾ
- chat ਜਵਾਬਾਂ ਨੂੰ stream ਕਰਨਾ
- API key ਦੀ ਲੋੜ ਨਹੀਂ

## ਸਮਰਥਿਤ ਨਹੀਂ

- Function calling
- Tool calling
- ਆਟੋਮੈਟਿਕ ਫ਼ਾਈਲ ਸੰਪਾਦਨ
- Agentic IDE workflows
- ਸਿਰਫ਼ API ਲਈ ਉਪਲਬਧ ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ

ਇਹ ਉਮੀਦ ਕੀਤਾ ਗਿਆ ਵਿਵਹਾਰ ਹੈ ਅਤੇ ਕੋਈ bug **ਨਹੀਂ** ਹੈ।

ਜੇ ਤੁਹਾਨੂੰ tool execution, ਆਟੋਮੈਟਿਕ ਫ਼ਾਈਲ ਸੰਪਾਦਨ, ਜਾਂ ਹੋਰ agent workflows ਦੀ ਲੋੜ ਹੈ, ਤਾਂ Web Cookie ਪ੍ਰਦਾਤਾ ਦੀ ਬਜਾਏ ਕਿਸੇ **API-key ਪ੍ਰਦਾਤਾ** ਦੀ ਵਰਤੋਂ ਕਰੋ।

# ਪ੍ਰਮਾਣਿਕਤਾ ਸੰਬੰਧੀ ਸਾਵਧਾਨੀ

Issue #7857 ਦੇ ਹੱਲ ਹੋਣ ਤੱਕ, ਸਫਲ ਪ੍ਰਮਾਣਿਕਤਾ ਇਸ ਗੱਲ ਦੀ **ਗਾਰੰਟੀ ਨਹੀਂ ਦਿੰਦੀ** ਕਿ ਪ੍ਰਦਾਤਾ ਸਫਲਤਾਪੂਰਵਕ ਪ੍ਰਮਾਣੀਕਰਨ ਕਰੇਗਾ।

ਜੇ ਪ੍ਰਮਾਣੀਕਰਨ ਫਿਰ ਵੀ ਅਸਫਲ ਹੁੰਦਾ ਹੈ, ਤਾਂ ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਤੁਸੀਂ ਪ੍ਰਮਾਣ-ਪੱਤਰ ਬ੍ਰਾਊਜ਼ਰ cookie ਸਟੋਰੇਜ ਦੀ ਬਜਾਏ ਕਿਸੇ ਲਾਈਵ ਨੈੱਟਵਰਕ ਬੇਨਤੀ ਤੋਂ ਕਾਪੀ ਕੀਤੇ ਸਨ।

## Cookie ਬ੍ਰਾਊਜ਼ਰ ਵਿੱਚ ਕੰਮ ਕਰਦੀ ਹੈ ਪਰ OmniRoute ਵਿੱਚ ਨਹੀਂ

ਕੁਝ ਪ੍ਰਦਾਤਾ ਅਜਿਹੀਆਂ cookies ਸ਼ਾਮਲ ਕਰਦੇ ਹਨ ਜੋ ਸਿਰਫ਼ ਪ੍ਰਮਾਣਿਤ ਬੇਨਤੀਆਂ ਦੌਰਾਨ ਭੇਜੀਆਂ ਜਾਂਦੀਆਂ ਹਨ।

ਕੋਈ conversation ਸਫਲਤਾਪੂਰਵਕ ਖੋਲ੍ਹਣ ਤੋਂ ਬਾਅਦ, ਕਿਸੇ ਨਵੀਂ ਨੈੱਟਵਰਕ ਬੇਨਤੀ ਤੋਂ ਪ੍ਰਮਾਣ-ਪੱਤਰ ਦੁਬਾਰਾ ਕਾਪੀ ਕਰੋ।

## ਸੈਸ਼ਨ ਦੀ ਮਿਆਦ ਸਮਾਪਤ ਹੋ ਗਈ

Web Cookie ਪ੍ਰਦਾਤਾ ਤੁਹਾਡੇ ਮੌਜੂਦਾ ਬ੍ਰਾਊਜ਼ਰ ਸੈਸ਼ਨ ਦੀ ਵਰਤੋਂ ਕਰਦੇ ਹਨ।

ਜੇ ਤੁਹਾਡੇ ਬ੍ਰਾਊਜ਼ਰ ਸੈਸ਼ਨ ਦੀ ਮਿਆਦ ਸਮਾਪਤ ਹੋ ਜਾਂਦੀ ਹੈ ਜਾਂ ਤੁਸੀਂ ਸਾਈਨ ਆਉਟ ਕਰਦੇ ਹੋ, ਤਾਂ ਤੁਹਾਨੂੰ ਪ੍ਰਮਾਣ-ਪੱਤਰਾਂ ਦਾ ਨਵਾਂ ਸੈੱਟ ਕਾਪੀ ਕਰਨਾ ਪਵੇਗਾ।

# ਸਰਵੋਤਮ ਅਭਿਆਸ

- ਕਿਸੇ ਨਵੀਂ ਪ੍ਰਮਾਣਿਤ ਬੇਨਤੀ ਤੋਂ ਪ੍ਰਮਾਣ-ਪੱਤਰ ਕਾਪੀ ਕਰੋ।
- ਪੁਰਾਣੀਆਂ cookies ਨੂੰ ਮੁੜ ਵਰਤਣ ਤੋਂ ਬਚੋ।
- Web Cookie ਪ੍ਰਦਾਤਾਵਾਂ ਦੀ ਵਰਤੋਂ ਕਰਦੇ ਸਮੇਂ ਆਪਣੇ ਬ੍ਰਾਊਜ਼ਰ ਸੈਸ਼ਨ ਨੂੰ ਸਰਗਰਮ ਰੱਖੋ।
- ਕਾਪੀ ਕੀਤੀਆਂ cookies ਨੂੰ ਸੰਵੇਦਨਸ਼ੀਲ ਪ੍ਰਮਾਣ-ਪੱਤਰ ਮੰਨੋ।
- ਜਦੋਂ ਤੁਹਾਨੂੰ function calling ਜਾਂ agent workflows ਦੀ ਲੋੜ ਹੋਵੇ, ਤਾਂ API-key ਪ੍ਰਦਾਤਾਵਾਂ ਦੀ ਵਰਤੋਂ ਕਰੋ।
