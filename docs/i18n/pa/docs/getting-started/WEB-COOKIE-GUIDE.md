Web Cookie ਪ੍ਰਦਾਤਾ OmniRoute ਨੂੰ API key ਦੀ ਬਜਾਏ ਤੁਹਾਡੇ ਮੌਜੂਦਾ ਬ੍ਰਾਊਜ਼ਰ ਸੈਸ਼ਨ ਰਾਹੀਂ AI ਸੇਵਾ ਵਰਤਣ ਦੀ ਆਗਿਆ ਦਿੰਦੇ ਹਨ। ਇਹ ਉਸ ਵੇਲੇ ਲਾਭਦਾਇਕ ਹੁੰਦੇ ਹਨ ਜਦੋਂ ਤੁਹਾਡੇ ਕੋਲ ਪਹਿਲਾਂ ਹੀ ਕਿਸੇ ਸੇਵਾ ਦੀ ਵੈੱਬਸਾਈਟ ਰਾਹੀਂ ਪਹੁੰਚ ਹੁੰਦੀ ਹੈ ਅਤੇ ਤੁਸੀਂ ਚਾਹੁੰਦੇ ਹੋ ਕਿ OmniRoute ਉਸੇ ਪ੍ਰਮਾਣਿਤ ਸੈਸ਼ਨ ਦੀ ਵਰਤੋਂ ਕਰੇ।

API-key ਪ੍ਰਦਾਤਾਵਾਂ ਤੋਂ ਵੱਖਰੇ, Web Cookie ਪ੍ਰਦਾਤਾ ਉਹਨਾਂ ਪ੍ਰਮਾਣ-ਪੱਤਰਾਂ ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਪ੍ਰਮਾਣੀਕਰਨ ਕਰਦੇ ਹਨ ਜੋ ਤੁਹਾਡਾ ਬ੍ਰਾਊਜ਼ਰ ਵੈੱਬਸਾਈਟ ਨੂੰ ਭੇਜਦਾ ਹੈ।

# ਸ਼ੁਰੂ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ

> **ਮਹੱਤਵਪੂਰਨ:** ਪ੍ਰਮਾਣ-ਪੱਤਰ ਹਮੇਸ਼ਾ ਕਿਸੇ **ਲਾਈਵ ਨੈੱਟਵਰਕ ਬੇਨਤੀ** ਤੋਂ ਕਾਪੀ ਕਰੋ, ਆਪਣੇ ਬ੍ਰਾਊਜ਼ਰ ਦੀ cookie storage ਤੋਂ **ਨਹੀਂ**।

ਬਹੁਤ ਸਾਰੀਆਂ ਪ੍ਰਮਾਣੀਕਰਨ ਸਮੱਸਿਆਵਾਂ ਗਲਤ ਥਾਂ ਤੋਂ cookies ਕਾਪੀ ਕਰਨ ਕਰਕੇ ਹੁੰਦੀਆਂ ਹਨ।

## Cookie Storage ਤੋਂ ਕਾਪੀ ਨਾ ਕਰੋ

ਜ਼ਿਆਦਾਤਰ ਬ੍ਰਾਊਜ਼ਰ ਸਟੋਰ ਕੀਤੀਆਂ cookies ਨੂੰ ਇਸ ਰਾਹੀਂ ਦਿਖਾਉਂਦੇ ਹਨ:

```
DevTools
→ Application (ਜਾਂ Storage)
→ Cookies
```

ਭਾਵੇਂ ਇਹ cookies ਸਹੀ ਦਿਖਾਈ ਦਿੰਦੀਆਂ ਹਨ, ਪਰ ਇਹ ਹੋ ਸਕਦੀਆਂ ਹਨ:

- ਪੁਰਾਣੀਆਂ
- ਅਧੂਰੀਆਂ
- ਉਹਨਾਂ cookies ਤੋਂ ਬਿਨਾਂ ਜੋ ਸਿਰਫ਼ ਪ੍ਰਮਾਣਿਤ ਬੇਨਤੀਆਂ ਨਾਲ ਭੇਜੀਆਂ ਜਾਂਦੀਆਂ ਹਨ

ਇਹ ਮੁੱਲ ਵਰਤਣ ਨਾਲ ਪ੍ਰਮਾਣੀਕਰਨ ਅਸਫਲ ਹੋ ਸਕਦਾ ਹੈ, ਭਾਵੇਂ ਇਹ ਵੈਧ ਦਿਖਾਈ ਦੇਣ।

## ਲਾਈਵ ਬੇਨਤੀ ਤੋਂ ਕਾਪੀ ਕਰੋ

ਇਸਦੀ ਬਜਾਏ, ਕਿਸੇ ਸਫਲ ਬੇਨਤੀ ਤੋਂ cookies ਵਰਤੋ:

```
DevTools
→ Network
→ ਪੰਨਾ ਰਿਫ੍ਰੈਸ਼ ਕਰੋ
→ ਕੋਈ chat ਜਾਂ conversation ਬੇਨਤੀ ਖੋਲ੍ਹੋ
→ Request Headers
→ Cookie
```

`Cookie` ਬੇਨਤੀ header ਵਿੱਚ ਉਹ ਬਿਲਕੁਲ ਸਹੀ ਪ੍ਰਮਾਣੀਕਰਨ ਜਾਣਕਾਰੀ ਹੁੰਦੀ ਹੈ ਜੋ ਤੁਹਾਡੇ ਬ੍ਰਾਊਜ਼ਰ ਨੇ ਸਫਲਤਾਪੂਰਵਕ ਵਰਤੀ ਸੀ।

ਜ਼ਿਆਦਾਤਰ Web Cookie ਪ੍ਰਦਾਤਾਵਾਂ ਲਈ, ਇਹੀ ਉਹ ਮੁੱਲ ਹੈ ਜੋ OmniRoute ਵਿੱਚ ਪੇਸਟ ਕੀਤਾ ਜਾਣਾ ਚਾਹੀਦਾ ਹੈ।

# ਆਮ ਸੈੱਟਅੱਪ

ਜ਼ਿਆਦਾਤਰ Web Cookie ਪ੍ਰਦਾਤਾਵਾਂ ਲਈ ਸੈੱਟਅੱਪ ਪ੍ਰਕਿਰਿਆ ਇੱਕੋ ਜਿਹੀ ਹੁੰਦੀ ਹੈ।

1. ਪ੍ਰਦਾਤਾ ਦੀ ਵੈੱਬਸਾਈਟ 'ਤੇ ਸਾਈਨ ਇਨ ਕਰੋ।
2. ਬ੍ਰਾਊਜ਼ਰ ਦੇ Developer Tools ਖੋਲ੍ਹੋ।
3. **Network** ਟੈਬ ਖੋਲ੍ਹੋ।
4. ਪੰਨਾ ਰਿਫ੍ਰੈਸ਼ ਕਰੋ।
5. ਕੋਈ ਪ੍ਰਮਾਣਿਤ chat ਜਾਂ conversation ਬੇਨਤੀ ਖੋਲ੍ਹੋ।
6. ਲੋੜੀਂਦੇ ਪ੍ਰਮਾਣੀਕਰਨ ਪ੍ਰਮਾਣ-ਪੱਤਰ ਕਾਪੀ ਕਰੋ।
7. OmniRoute ਖੋਲ੍ਹੋ।
8. **Providers → Add Provider** 'ਤੇ ਜਾਓ।
9. ਆਪਣਾ Web Cookie ਪ੍ਰਦਾਤਾ ਚੁਣੋ।
10. ਪ੍ਰਮਾਣ-ਪੱਤਰ ਪੇਸਟ ਕਰੋ।
11. **Test Connection** 'ਤੇ ਕਲਿੱਕ ਕਰੋ।
12. ਪ੍ਰਦਾਤਾ ਨੂੰ ਸੇਵ ਕਰੋ।

ਲੋੜੀਂਦੇ ਸਟੀਕ ਪ੍ਰਮਾਣ-ਪੱਤਰ ਪ੍ਰਦਾਤਾ 'ਤੇ ਨਿਰਭਰ ਕਰਦੇ ਹਨ।

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) ਇੱਕ ਮੁਫ਼ਤ ਉਪਭੋਗਤਾ ਚੈਟ ਪਲੇਟਫਾਰਮ ਹੈ ਜਿਸ ਲਈ ਸਾਈਨ ਅੱਪ ਕਰਨ ਦੀ ਲੋੜ ਨਹੀਂ ਹੈ — ਪਹਿਲੀ ਵਾਰ ਵੈੱਬਸਾਈਟ ਖੋਲ੍ਹਣ 'ਤੇ ਸੈਸ਼ਨ ਗੁਮਨਾਮ ਤੌਰ 'ਤੇ ਬਣਾਇਆ ਜਾਂਦਾ ਹੈ ਅਤੇ ਤਿੰਨ ਕੂਕੀਜ਼ ਰਾਹੀਂ ਕਾਇਮ ਰਹਿੰਦਾ ਹੈ: `uid`, `si_usr_id`, ਅਤੇ `si_ses_id`। OmniRoute ਇੱਕੋ ਮਾਡਲ id (`notrack-c`, ਉਪਨਾਮ `ntw`) ਰਾਹੀਂ ਉਸੇ `/api/dispatch` ਐਂਡਪੌਇੰਟ ਨੂੰ ਪ੍ਰੌਕਸੀ ਕਰਦਾ ਹੈ।

### ਕਨੈਕਟ ਕਰਨ ਦੇ ਕਦਮ

1. ਆਪਣੇ ਬ੍ਰਾਊਜ਼ਰ ਵਿੱਚ [notrack.ai](https://notrack.ai) ਖੋਲ੍ਹੋ ਅਤੇ ਗੁਮਨਾਮ ਸੈਸ਼ਨ ਕੂਕੀ ਨੂੰ ਸੈੱਟ ਹੋਣ ਦਿਓ।
2. **DevTools → Network** ਖੋਲ੍ਹੋ, ਪੰਨੇ ਨੂੰ ਰਿਫ੍ਰੈਸ਼ ਕਰੋ, ਅਤੇ ਕਿਸੇ ਵੀ `/api` ਬੇਨਤੀ 'ਤੇ ਕਲਿੱਕ ਕਰੋ।
3. **Request Headers** ਵਿੱਚ, ਪੂਰੇ `Cookie` ਹੈਡਰ ਦਾ ਮੁੱਲ ਕਾਪੀ ਕਰੋ।
4. OmniRoute ਵਿੱਚ, **Providers → Add Provider → NoTrack Web (Free)** 'ਤੇ ਜਾਓ।
5. ਕੂਕੀ ਸਟ੍ਰਿੰਗ ਨੂੰ `apiKey` ਫ਼ੀਲਡ ਵਿੱਚ ਪੇਸਟ ਕਰੋ ਅਤੇ **Save** ਕਰੋ।

OmniRoute ਪੇਸਟ ਕੀਤੀ ਸਟ੍ਰਿੰਗ ਵਿੱਚੋਂ `uid`, `si_usr_id`, ਅਤੇ `si_ses_id` ਕੱਢਦਾ ਹੈ ਅਤੇ ਸਿਰਫ਼ ਉਹਨਾਂ ਜੋੜਿਆਂ ਨਾਲ ਇੱਕ ਸਾਫ਼ `Cookie` ਹੈਡਰ ਦੁਬਾਰਾ ਬਣਾਉਂਦਾ ਹੈ — ਨਾਲ ਹੀ, ਮੌਜੂਦ ਹੋਣ 'ਤੇ `nt_session` (ਲੌਗ-ਇਨ ਖਾਤਿਆਂ ਲਈ ਸੈੱਟ ਕੀਤਾ `ntk_…` ਟੋਕਨ) ਵੀ ਸ਼ਾਮਲ ਕਰਦਾ ਹੈ। ਜੇਕਰ ਤਿੰਨਾਂ ਵਿੱਚੋਂ ਕੋਈ ਵੀ ਗੁੰਮ ਹੋਵੇ, ਤਾਂ ਮੂਲ ਪੇਸਟ ਕੀਤੀ ਸਟ੍ਰਿੰਗ ਨੂੰ ਬਿਨਾਂ ਬਦਲਾਅ ਅੱਗੇ ਭੇਜਿਆ ਜਾਂਦਾ ਹੈ, ਤਾਂ ਜੋ ਓਪਰੇਟਰ ਵਿਕਲਪਿਕ ਬਣਤਰਾਂ ਨਾਲ ਪ੍ਰਯੋਗ ਕਰ ਸਕਣ।

### ਮਾਡਲ ids

| ਮਾਡਲ id     | ਦਿਖਾਇਆ ਜਾਣ ਵਾਲਾ ਨਾਮ | ਟਿੱਪਣੀਆਂ                                         |
| ----------- | ------------------- | ------------------------------------------------ |
| `notrack-c` | NoTrack C           | ਡਿਫੌਲਟ — ਅੱਪਸਟ੍ਰੀਮ ਡਿਸਪੈਚ ਮਾਡਲ `C`।              |
| `C`         | NoTrack C           | `notrack-c` ਲਈ ਉਪਨਾਮ (ਮੂਲ ਅੱਪਸਟ੍ਰੀਮ ਡਿਸਪੈਚ ਕੋਡ)। |
| `notrack`   | NoTrack C           | `notrack-c` ਲਈ ਉਪਨਾਮ।                            |
| `ntw`       | NoTrack C           | `notrack-c` ਲਈ ਛੋਟਾ ਉਪਨਾਮ।                       |

ਸਾਰੇ ਚਾਰ ਮਾਡਲ ids ਇੱਕੋ ਅੱਪਸਟ੍ਰੀਮ ਡਿਸਪੈਚ ਮਾਡਲ (`C`) ਨਾਲ ਮੈਪ ਹੁੰਦੇ ਹਨ।

### ਬੇਨਤੀ ਵਿਕਲਪ

ਐਗਜ਼ੀਕਿਊਟਰ ਬੇਨਤੀ ਬੌਡੀ ਵਿੱਚ ਇਹ ਵਿਕਲਪਿਕ ਫ਼ੀਲਡਾਂ ਸਵੀਕਾਰ ਕਰਦਾ ਹੈ:

| ਬੌਡੀ ਫ਼ੀਲਡ            | ਡਿਫੌਲਟ  | ਉਦੇਸ਼                                                                      |
| --------------------- | ------- | -------------------------------------------------------------------------- |
| `notrack_mode`        | `usual` | ਡਿਸਪੈਚ ਮੋਡ (ਮੁਕਤ-ਰੂਪ ਸਟ੍ਰਿੰਗ; ਅੱਪਸਟ੍ਰੀਮ `usual`, … ਸਵੀਕਾਰ ਕਰਦਾ ਹੈ)         |
| `notrack_max_turns`   | `6`     | ਜਵਾਬ ਦੇਣ ਤੋਂ ਪਹਿਲਾਂ ਅੱਪਸਟ੍ਰੀਮ ਵੱਲੋਂ ਲਏ ਜਾ ਸਕਣ ਵਾਲੇ ਅੰਦਰੂਨੀ ਟਰਨਾਂ ਦੀ ਗਿਣਤੀ। |
| `notrack_chat_id`     | `null`  | ਮੌਜੂਦਾ ਅੱਪਸਟ੍ਰੀਮ ਚੈਟ ਮੁੜ ਸ਼ੁਰੂ ਕਰੋ (ਨਵੀਂ ਚੈਟ ਲਈ ਇਸਨੂੰ ਛੱਡ ਦਿਓ)।            |
| `notrack_attachments` | `[]`    | ਅੱਪਸਟ੍ਰੀਮ ਅਟੈਚਮੈਂਟ ਡਿਸਕ੍ਰਿਪਟਰਾਂ ਦੀ ਪਾਸ-ਥਰੂ ਐਰੇ।                            |
| `notrack_regenerate`  | `false` | ਪਿਛਲੇ ਟਰਨ ਲਈ ਦੁਬਾਰਾ ਤਿਆਰ ਕੀਤਾ ਜਵਾਬ ਮੰਗਣ ਵਾਸਤੇ `true` ਸੈੱਟ ਕਰੋ।             |

### ਸਮਰੱਥਾਵਾਂ

- **ਸਟ੍ਰੀਮਿੰਗ ਅਤੇ ਗੈਰ-ਸਟ੍ਰੀਮਿੰਗ** ਚੈਟ ਕੰਪਲੀਸ਼ਨਾਂ।
- **ਟੂਲ ਕਾਲਿੰਗ** — ਬੇਨਤੀ ਵਿੱਚ `tools: [...]` ਸੈੱਟ ਕਰੋ; ਐਗਜ਼ੀਕਿਊਟਰ ਉਹਨਾਂ ਨੂੰ ਟੂਲ-ਕਾਲ ਐਨਵਲਪ ਕਾਂਟ੍ਰੈਕਟ ਵਿੱਚ ਸੀਰੀਅਲਾਈਜ਼ ਕਰਦਾ ਹੈ ਅਤੇ ਮਾਡਲ ਦੇ ਜਵਾਬਾਂ ਨੂੰ ਵਾਪਸ OpenAI `tool_calls` ਵਿੱਚ ਪਾਰਸ ਕਰਦਾ ਹੈ।
- **`response_format`** — `json_object` ਅਤੇ `json_schema` ਸਮਰਥਿਤ ਹਨ। ਐਗਜ਼ੀਕਿਊਟਰ ਮਾਡਲ ਦੇ ਜਵਾਬ ਵਿੱਚੋਂ ਪਹਿਲਾ JSON ਆਬਜੈਕਟ ਕੱਢਦਾ ਹੈ ਅਤੇ ਵਾਪਸ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਉਸਨੂੰ ਸਟ੍ਰਿੰਗ ਵਿੱਚ ਬਦਲਦਾ ਹੈ।
- **ਰੀਜ਼ਨਿੰਗ ਸੰਕੇਤ** — ਜਦੋਂ ਅੱਪਸਟ੍ਰੀਮ ਇੱਕ `thinking` ਇਵੈਂਟ ਭੇਜਦਾ ਹੈ, ਤਾਂ ਐਗਜ਼ੀਕਿਊਟਰ ਇੱਕ `reasoning` ਡੈਲਟਾ ਉਤਪੰਨ ਕਰਦਾ ਹੈ।

### ਸੀਮਾਵਾਂ

- ਅੱਪਸਟ੍ਰੀਮ ਗੁਮਨਾਮ ਵਰਤੋਂ ਕੋਟੇ ਲਾਗੂ ਕਰਦਾ ਹੈ — ਕੋਟਾ ਪਾਰ ਹੋਣ 'ਤੇ ਐਗਜ਼ੀਕਿਊਟਰ ਇੱਕ ਵਰਤੋਂਕਾਰ-ਅਨੁਕੂਲ ਸੁਨੇਹੇ ਨਾਲ 429 ਦਿਖਾਉਂਦਾ ਹੈ।
- ਸਾਰੇ ਮਾਡਲ ids ਇੱਕੋ ਅੱਪਸਟ੍ਰੀਮ ਡਿਸਪੈਚ ਮਾਡਲ ਨਾਲ ਰਿਜ਼ੌਲਵ ਹੁੰਦੇ ਹਨ; ਹਰ ਮਾਡਲ ਲਈ ਵੱਖਰਾ ਸਵਿੱਚ ਨਹੀਂ ਹੈ।
- ਐਗਜ਼ੀਕਿਊਟਰ ਅੱਪਸਟ੍ਰੀਮ ਦੇ `/api/chats` ਐਂਡਪੌਇੰਟ ਨੂੰ ਕਾਲ ਨਹੀਂ ਕਰਦਾ, ਇਸ ਲਈ ਚੈਟ ਇਤਿਹਾਸ / ਸੈਸ਼ਨਾਂ ਦਾ ਸਵੈਚਾਲਿਤ ਤੌਰ 'ਤੇ ਪ੍ਰਬੰਧਨ ਨਹੀਂ ਹੁੰਦਾ। ਮੌਜੂਦਾ ਅੱਪਸਟ੍ਰੀਮ ਚੈਟ ਨੂੰ ਮੁੜ ਸ਼ੁਰੂ ਕਰਨ ਲਈ `notrack_chat_id` ਵਰਤੋ।

# ਵੈੱਬ ਕੂਕੀ ਪ੍ਰੋਵਾਈਡਰ ਕੀ ਕਰ ਸਕਦੇ ਹਨ ਅਤੇ ਕੀ ਨਹੀਂ ਕਰ ਸਕਦੇ

ਵੈੱਬ ਕੂਕੀ ਪ੍ਰੋਵਾਈਡਰ ਕਿਸੇ ਵੈੱਬਸਾਈਟ ਦੇ ਚੈਟ ਇੰਟਰਫੇਸ ਨੂੰ ਮੁੜ ਵਰਤਦੇ ਹਨ। ਉਹ ਅਧਿਕਾਰਤ APIs ਵਰਗੀਆਂ ਸਮਰੱਥਾਵਾਂ **ਪ੍ਰਦਾਨ ਨਹੀਂ** ਕਰਦੇ।

## ਸਮਰਥਿਤ

- ਆਪਣੇ ਮੌਜੂਦਾ ਬ੍ਰਾਊਜ਼ਰ ਸੈਸ਼ਨ ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਪ੍ਰਮਾਣਿਕਤਾ ਕਰੋ
- ਆਪਣੇ ਖਾਤੇ ਰਾਹੀਂ ਉਪਲਬਧ ਮਾਡਲਾਂ ਤੱਕ ਪਹੁੰਚ ਕਰੋ
- ਚੈਟ ਜਵਾਬਾਂ ਨੂੰ ਸਟ੍ਰੀਮ ਕਰੋ
- ਕਿਸੇ API ਕੁੰਜੀ ਦੀ ਲੋੜ ਨਹੀਂ ਹੈ

## ਸਮਰਥਿਤ ਨਹੀਂ

- ਫੰਕਸ਼ਨ ਕਾਲਿੰਗ
- ਟੂਲ ਕਾਲਿੰਗ
- ਆਟੋਮੈਟਿਕ ਫ਼ਾਈਲ ਸੰਪਾਦਨ
- ਏਜੰਟ-ਆਧਾਰਿਤ IDE ਵਰਕਫ਼ਲੋ
- ਸਿਰਫ਼ API ਲਈ ਉਪਲਬਧ ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ

ਇਹ ਉਮੀਦ ਕੀਤਾ ਗਿਆ ਵਿਹਾਰ ਹੈ ਅਤੇ **ਕੋਈ** ਬੱਗ ਨਹੀਂ ਹੈ।

ਜੇ ਤੁਹਾਨੂੰ ਟੂਲ ਚਲਾਉਣ, ਆਟੋਮੈਟਿਕ ਫ਼ਾਈਲ ਸੰਪਾਦਨ, ਜਾਂ ਹੋਰ ਏਜੰਟ ਵਰਕਫ਼ਲੋ ਦੀ ਲੋੜ ਹੈ, ਤਾਂ Web Cookie ਪ੍ਰਦਾਤਾ ਦੀ ਬਜਾਏ ਕਿਸੇ **API-key ਪ੍ਰਦਾਤਾ** ਦੀ ਵਰਤੋਂ ਕਰੋ।

# ਪ੍ਰਮਾਣਿਕਤਾ ਸੰਬੰਧੀ ਸੀਮਾ

ਸਫਲ **Test Connection** ਜਾਂ ਕੂਕੀ ਪ੍ਰਮਾਣਿਕਤਾ ਸਿਰਫ਼ ਇਹ ਪੁਸ਼ਟੀ ਕਰਦੀ ਹੈ ਕਿ ਦਿੱਤੇ ਗਏ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਉਮੀਦ ਕੀਤੇ ਫਾਰਮੈਟ ਵਿੱਚ ਜਾਪਦੇ ਹਨ।

ਜਦੋਂ ਤੱਕ Issue #7857 ਹੱਲ ਨਹੀਂ ਹੁੰਦਾ, ਸਫਲ ਪ੍ਰਮਾਣਿਕਤਾ ਇਸ ਗੱਲ ਦੀ **ਗਾਰੰਟੀ ਨਹੀਂ ਦਿੰਦੀ** ਕਿ ਪ੍ਰਦਾਤਾ ਸਫਲਤਾਪੂਰਵਕ ਪ੍ਰਮਾਣਿਤ ਕਰੇਗਾ।

ਜੇ ਪ੍ਰਮਾਣਿਕਤਾ ਫਿਰ ਵੀ ਅਸਫਲ ਰਹਿੰਦੀ ਹੈ, ਤਾਂ ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਤੁਸੀਂ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਬ੍ਰਾਊਜ਼ਰ ਦੀ ਕੂਕੀ ਸਟੋਰੇਜ ਦੀ ਬਜਾਏ ਕਿਸੇ ਸਰਗਰਮ ਨੈੱਟਵਰਕ ਬੇਨਤੀ ਤੋਂ ਕਾਪੀ ਕੀਤੇ ਹਨ।

# ਸਮੱਸਿਆ-ਨਿਪਟਾਰਾ

## ਪ੍ਰਮਾਣਿਕਤਾ ਅਸਫਲ ਹੁੰਦੀ ਹੈ

ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਇੱਥੋਂ ਕਾਪੀ ਕੀਤੇ ਗਏ ਸਨ:

```
Network
→ Request Headers
→ Cookie
```

ਅਤੇ ਇੱਥੋਂ **ਨਹੀਂ**:

```
Application
→ Cookies
```

---

## ਕੂਕੀ ਬ੍ਰਾਊਜ਼ਰ ਵਿੱਚ ਕੰਮ ਕਰਦੀ ਹੈ ਪਰ OmniRoute ਵਿੱਚ ਨਹੀਂ

ਕੁਝ ਪ੍ਰਦਾਤਾ ਅਜਿਹੀਆਂ ਕੂਕੀਜ਼ ਸ਼ਾਮਲ ਕਰਦੇ ਹਨ ਜੋ ਸਿਰਫ਼ ਪ੍ਰਮਾਣਿਤ ਬੇਨਤੀਆਂ ਦੌਰਾਨ ਭੇਜੀਆਂ ਜਾਂਦੀਆਂ ਹਨ।

ਕਿਸੇ ਗੱਲਬਾਤ ਨੂੰ ਸਫਲਤਾਪੂਰਵਕ ਖੋਲ੍ਹਣ ਤੋਂ ਬਾਅਦ, ਇੱਕ ਨਵੀਂ ਨੈੱਟਵਰਕ ਬੇਨਤੀ ਤੋਂ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਦੁਬਾਰਾ ਕਾਪੀ ਕਰੋ।

---

## ਸੈਸ਼ਨ ਦੀ ਮਿਆਦ ਖ਼ਤਮ ਹੋ ਗਈ

Web Cookie ਪ੍ਰਦਾਤਾ ਤੁਹਾਡੇ ਮੌਜੂਦਾ ਬ੍ਰਾਊਜ਼ਰ ਸੈਸ਼ਨ ਦੀ ਵਰਤੋਂ ਕਰਦੇ ਹਨ।

ਜੇ ਤੁਹਾਡੇ ਬ੍ਰਾਊਜ਼ਰ ਸੈਸ਼ਨ ਦੀ ਮਿਆਦ ਖ਼ਤਮ ਹੋ ਜਾਂਦੀ ਹੈ ਜਾਂ ਤੁਸੀਂ ਸਾਈਨ ਆਉਟ ਕਰਦੇ ਹੋ, ਤਾਂ ਤੁਹਾਨੂੰ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਦਾ ਨਵਾਂ ਸੈੱਟ ਕਾਪੀ ਕਰਨਾ ਪਵੇਗਾ। ਸਮਰਥਿਤ ਵੈੱਬ ਪ੍ਰਦਾਤਾਵਾਂ ਲਈ ਕੂਕੀ ਨਵੀਨੀਕਰਨ ਨੂੰ ਸਵੈਚਾਲਿਤ ਕਰਨ ਵਾਸਤੇ, ਸਹਾਇਕ ਟੂਲ [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md) ਦੇਖੋ।

ਜਦੋਂ ਤੱਕ Issue #7857 ਹੱਲ ਨਹੀਂ ਹੁੰਦਾ, ਪ੍ਰਮਾਣਿਕਤਾ ਪਾਸ ਹੋਣਾ ਇਸ ਗੱਲ ਦੀ ਗਾਰੰਟੀ ਨਹੀਂ ਦਿੰਦਾ ਕਿ ਪ੍ਰਮਾਣੀਕਰਨ ਬੇਨਤੀ ਸਫਲ ਹੋਵੇਗੀ।

ਅੱਗੇ ਸਮੱਸਿਆ-ਨਿਪਟਾਰਾ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ, ਇੱਕ ਨਵੀਂ ਪ੍ਰਮਾਣਿਤ ਬੇਨਤੀ ਤੋਂ ਆਪਣੇ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਦੁਬਾਰਾ ਕਾਪੀ ਕਰੋ।

# ਸਰਵੋਤਮ ਅਭਿਆਸ

- ਇੱਕ ਨਵੀਂ ਪ੍ਰਮਾਣਿਤ ਬੇਨਤੀ ਤੋਂ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਕਾਪੀ ਕਰੋ।
- ਪੁਰਾਣੀਆਂ ਕੂਕੀਜ਼ ਦੀ ਮੁੜ ਵਰਤੋਂ ਕਰਨ ਤੋਂ ਬਚੋ।
- Web Cookie ਪ੍ਰਦਾਤਾਵਾਂ ਦੀ ਵਰਤੋਂ ਕਰਦੇ ਸਮੇਂ ਆਪਣੇ ਬ੍ਰਾਊਜ਼ਰ ਸੈਸ਼ਨ ਨੂੰ ਸਰਗਰਮ ਰੱਖੋ।
- ਕਾਪੀ ਕੀਤੀਆਂ ਕੂਕੀਜ਼ ਨੂੰ ਸੰਵੇਦਨਸ਼ੀਲ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਵਜੋਂ ਸੰਭਾਲੋ।
- ਜਦੋਂ ਤੁਹਾਨੂੰ ਫੰਕਸ਼ਨ ਕਾਲਿੰਗ ਜਾਂ ਏਜੰਟ ਵਰਕਫ਼ਲੋ ਦੀ ਲੋੜ ਹੋਵੇ ਤਾਂ API-key ਪ੍ਰਦਾਤਾਵਾਂ ਦੀ ਵਰਤੋਂ ਕਰੋ।
