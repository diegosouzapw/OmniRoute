## Automatsko usmjeravanje bez konfiguracije (prefiks `auto/`)

> **NOVO:** Nije potrebno stvarati kombinaciju. Upotrijebite prefiks `auto/` izravno u bilo kojem klijentu.

### Brzi primjeri

| ID modela      | Varijanta | Ponašanje                                                                            |
| -------------- | --------- | ------------------------------------------------------------------------------------ |
| `auto`         | zadano    | Svi povezani pružatelji, strategija LKGP, uravnotežene težine                        |
| `auto/coding`  | coding    | Težine usmjerene na kvalitetu, prikladno za generiranje koda                         |
| `auto/fast`    | fast      | Ponderirani odabir s malom latencijom                                                |
| `auto/cheap`   | cheap     | Usmjeravanje optimizirano prema trošku (najniži trošak prvi)                         |
| `auto/offline` | offline   | Daje prednost pružateljima s najvećom dostupnošću kvote                              |
| `auto/smart`   | smart     | Kvaliteta na prvom mjestu + viša stopa istraživanja (10%) za bolje otkrivanje modela |
| `auto/lkgp`    | lkgp      | Izričiti LKGP (isto kao zadani `auto`)                                               |
| `auto/chaos`   | chaos     | Paralelno slanje, jedan model po pružatelju (nije ubacivanje pogrešaka)              |

### Kombiniranje kategorije i razine (`auto/<category>:<tier>`)

Sufiksi u stilu OpenRoutera razdvajaju **kakva je vrsta rute** (kategorija) od toga **kako je optimizirati** (razina), pa ih možete slobodno kombinirati (#4235, faza B, `open-sse/services/autoCombo/suffixComposition.ts`):

- **Kategorije** (filtriraju skup kandidata prema mogućnostima): `coding` · `reasoning` · `vision` · `chat` · `multimodal`. `vision`/`multimodal` zadržavaju modele s podrškom za vizualni sadržaj; `reasoning` zadržava modele za zaključivanje/promišljanje.
- **Razine** (odabiru težine bodovanja / filtar skupa): `fast` (brza isporuka) · `cheap` (alias `floor`, ušteda troškova) · `reliable` (stanje prekidača strujnog kruga + stabilnost latencije) · `free` / `pro` (filtriraju skup prema razini modela putem `classifyTier` — besplatna naspram premium razine).

| Primjer                | Razrješava se u                                                          |
| ---------------------- | ------------------------------------------------------------------------ |
| `auto/coding:fast`     | skup za kodiranje, težine za malu latenciju                              |
| `auto/coding:cheap`    | skup za kodiranje, optimiziran prema trošku (alias `auto/coding:floor`)  |
| `auto/reasoning:pro`   | samo modeli za zaključivanje/promišljanje, premium razina                |
| `auto/vision`          | modeli s podrškom za vizualni sadržaj (bez razine → uravnotežene težine) |
| `auto/multimodal:free` | modeli s podrškom za multimodalnost, samo besplatna razina               |

Svaki valjani `auto/<category>[:<tier>]` razrješava se na zahtjev; odabrani podskup oglašava se u `/v1/models` i na nadzornoj ploči (`AUTO_SUFFIX_VARIANTS` u `open-sse/services/autoCombo/builtinCatalog.ts`). Filtriranje je **otvoreno u slučaju pogreške** — ako nijedan povezani model ne odgovara ograničenju, upotrebljava se cijeli skup kako se usmjeravanje nikada ne bi prekinulo. Osnovni sustav bodovanja (`combo.ts`) nije promijenjen; filtar kategorije/razine primjenjuje se u `buildAutoCandidates`.

> **Aktualni podaci o modelima:** prikladnost automatskog usmjeravanja temelji se na aktualnim ljestvicama **Arena ELO** + podacima o razinama iz **models.dev** kada je uključena zastavica `ARENA_ELO_SYNC_ENABLED` (u suprotnom se upotrebljava statička karta prikladnosti).

**Kako upotrebljavati:**

```bash
# Bilo koji IDE ili CLI alat koji podržava format OpenAI
Osnovni URL: http://localhost:20128/v1
API ključ:   <ključ-vaše-krajnje-točke>

# U svojem kodu/konfiguraciji postavite model na:
model: "auto"                 # uravnotežena zadana postavka
model: "auto/coding"          # najbolje za zadatke kodiranja
model: "auto/fast"            # najbrži dostupni
model: "auto/cheap"           # najjeftiniji po tokenu
```

**Što se događa:**

1. OmniRoute otkriva prefiks `auto/` u `src/sse/handlers/chat.ts`
2. Dohvaća sve **aktivne veze s pružateljima** iz baze podataka
3. Filtrira ih na one s valjanim vjerodajnicama (API ključ ili OAuth token)
4. Određuje model za svaku vezu (`connection.defaultModel` ili prvi model pružatelja)
5. Izrađuje **virtualnu kombinaciju** u memoriji (ne pohranjuje se u bazu podataka)
6. Usmjerava s pomoću profila težina odabrane varijante + strategije LKGP

**Ključna svojstva:**

- ✅ **Uvijek aktivno:** Nisu potrebni prekidač, stvaranje kombinacije ni konfiguracija
- ✅ **Dinamično:** Automatski odražava trenutačno povezane pružatelje
- ✅ **Postojanost sesije:** LKGP osigurava davanje prednosti posljednjem uspješnom pružatelju
- ✅ **Podrška za više računa:** Svaka veza s pružateljem postaje zaseban kandidat
- ✅ **Bez pisanja u bazu podataka:** Virtualna kombinacija postoji samo tijekom zahtjeva, bez troška trajne pohrane

### Upravljanje kandidatima po ključu (#7819, razina 1+2)

`GET /v1/auto-combo/{channel}/candidates` (`{channel}` = sufiks nakon `auto/` ili
doslovni `auto` za osnovni kanal) krajnja je točka **samo za čitanje** koja navodi
trenutačni skup kandidata kanala `auto/*`, obogaćen aktualnim podacima o dostupnosti,
uz ponovnu uporabu postojećih očitanja otpornosti (nikada sirovog `state` prekidača):

- prekidač strujnog kruga pružatelja — `getCircuitBreaker(provider).getStatus()` / `.canExecute()`
- razdoblje čekanja veze — `rateLimitedUntil` / `testStatus` u razriješenom retku
  `provider_connections`
- blokada modela — `isModelLocked(provider, connectionId, model)`

Svaki kandidat također sadrži zastavicu `excluded` za ovaj API ključ. Izuzeća se
pohranjuju po API ključu (tablica `auto_candidate_overrides`, migracija `128`) —
OmniRoute je namijenjen jednom zakupcu i nema tablicu `users`, pa je `apiKeyId`
najbliži stvarni identitet pojedinačnog pozivatelja — te se primjenjuju na središnjoj
točki skupa kandidata u `open-sse/services/autoCombo/virtualFactory.ts` putem čiste,
jedinično testirane funkcije `filterExcludedCandidates()`
(`open-sse/services/autoCombo/candidateOverrides.ts`). Filtar je **otvoren u slučaju
pogreške**: nepostavljen apiKeyId/kanal ili neuspjelo pretraživanje baze podataka
ostavljaju skup nefiltriranim, pa operator bez konfiguriranih nadjačavanja dobiva
usmjeravanje koje je na razini bajtova identično onome prije ove značajke.

**Odgođeno za naknadni issue:** težine po kandidatu + eksplicitno određivanje redoslijeda (razina 3
— integrira se u postojeće putanje strategija ponderiranja/prioriteta) i prikvačivanje određene
strategije iz datoteke `combo.ts` za svaki kanal `auto/*` (razina 4). Pogledajte plan za #7819 radi otvorenog
pitanja trebaju li nadjačavanja ostati zasebna za svaki API ključ ili postati globalna s obzirom na
model jednog korisnika.

**U pozadini:**

```txt
Zahtjev: { model: "auto/coding" }
   ↓
src/sse/handlers/chat.ts otkriva prefiks
   ↓
createVirtualAutoCombo('coding') → candidatePool iz aktivnih veza
   ↓
handleComboChat (isti mehanizam kao za trajno pohranjene kombinacije)
   ↓
Automatsko bodovanje odabire najboljeg pružatelja/model za svaki zahtjev
```

**Datoteke implementacije:**

| Datoteka                                                  | Svrha                                                    |
| --------------------------------------------------------- | -------------------------------------------------------- |
| `open-sse/services/autoCombo/autoPrefix.ts`               | Parser prefiksa (`parseAutoPrefix`)                      |
| `open-sse/services/autoCombo/virtualFactory.ts`           | Stvara virtualne objekte `AutoComboConfig`               |
| `open-sse/services/autoCombo/providerRegistryAccessor.ts` | Testna pristupna točka za imitiranje registra pružatelja |
| `src/sse/handlers/chat.ts`                                | Integracija: prečac za automatski prefiks                |
| `src/shared/constants/providers.ts`                       | Sistemski unos `SYSTEM_PROVIDERS.auto`                   |

## Nazivi Kombija Koji Se Podudaraju s Pravim ID-om Modela

Kombij čiji je `name` identičan golom ID-u modela (npr. kombij nazvan
`gpt-5.5`) je **namjerni, podržani obrazac**, a ne greška: to je
mehanizam za rezervni odabir pružatelja usluge po ID-u modela dokumentiran u
[#6940](https://github.com/diegosouzapw/OmniRoute/issues/6940). Budući da se
razrješavanje kombija provjerava prije razrješavanja golog ID-a modela
(`getComboForModel()` u `src/sse/services/model.ts`), zahtjev za goli
id `gpt-5.5` usmjerava se kroz ciljeve kombija (npr.
`acme-responses/gpt-5.5`, `backup-responses/gpt-5.5`) umjesto izravno prema
jednom pružatelju usluge — ovo ponovno koristi prednost kombija-prije-prepisa izgrađenu za
[#3227/#3233](https://github.com/diegosouzapw/OmniRoute/issues/3227) i
regresijski je testirana s `tests/unit/responses-combo-resolution-3227.test.ts` i
`tests/unit/combo-name-codex-responses-rewrite.test.ts`.

Stvaranje ili preimenovanje kombija u naziv koji zasjenjuje pravi ID modela
**nikada se ne odbija** — to bi narušilo ovaj dokumentirani tijek rada. Umjesto toga
(#8530), `POST /api/combos` i `PUT /api/combos/[id]` prilaže neblokizirajuće
polje `warning` odgovoru kada se (novi) naziv sudari s pravim
ID-om modela:

```json
{
  "warning": {
    "code": "COMBO_NAME_SHADOWS_MODEL",
    "modelId": "gpt-5.5",
    "providerId": "openai"
  }
}
```

Pri pokretanju, `scanComboModelNameCollisionsAtBoot()`
(`src/instrumentation-node.ts`) također bilježi jednoredno upozorenje `[STARTUP]`
koje nabraja svaki postojeći kombij koji zasjenjuje ID modela, kako bi operatori koji
na ovo naiđu slučajno (a ne namjerno, prema #6940) imali signal.
Pomoćnik za detekciju nalazi se u `src/lib/combos/modelNameCollision.ts`.

## Pozivanje Prilagođenog Kombija iz Klijenta

Pohranjeni kombiji (Postavke → Kombiji) koriste se samo kada klijent pošalje **točan naziv** kombija u polju `model` — ne postoji nejasno ili djelomično podudaranje naziva kombija, niti je uključen prefiks `auto/`. Redoslijed razrješavanja (`getComboForModel()` u `src/sse/services/model.ts`):

1. točno podudaranje naziva kombija (`model: "my-combo"`),
2. prefiks `combo/<name>` (`model: "combo/my-combo"`),
3. glob mapiranja modela na kombij (`/api/model-combo-mappings`).

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"my-combo","messages":[{"role":"user","content":"Hello"}]}'
```

Dvije uobičajene zamke:

- **`auto` ne koristi vaše kombije.** `auto`/`auto/*` gradi vlastiti skup kandidata bez konfiguracije i savjetuje se s pohranjenim kombijima samo ako je kombij doslovno nazvan `auto` (nije preporučeno). Za usmjeravanje kroz kombij, pošaljite njegov točan naziv — ne `auto`.
- **`openrouter/auto` je pravi plaćeni OpenRouter proizvod** ("Auto Best Available"), a ne OmniRoute alias. To je jedini statični unos modela u registru OpenRoutera (`open-sse/config/providers/registry/openrouter/index.ts`) i naplaćuje se zasebno. Koristite Postavke → Usmjeravanje → Sakrij plaćene modele kako biste ga isključili iz `auto` skupova.

Pogledajte [#7992](https://github.com/diegosouzapw/OmniRoute/issues/7992) i [#7111](https://github.com/diegosouzapw/OmniRoute/issues/7111) za izvorne nejasnoće koje ovaj tekst dokumentira.

## Kako funkcionira (trajne automatske kombinacije)

Mehanizam automatskih kombinacija dinamički odabire najboljeg pružatelja/model za svaki zahtjev pomoću **funkcije bodovanja sa 16 čimbenika** (definirane u `open-sse/services/autoCombo/scoring.ts` → `DEFAULT_WEIGHTS`). Zbroj zadanih težina iznosi `1.0`; prilagođene težine ponovno se normaliziraju funkcijom `normalizeScoringWeights()`. Dva od šesnaest čimbenika — `cacheAffinity` i `resetWindowAffinity` — imaju zadanu težinu `0`; `reliability` ima vrijednost `0` u `DEFAULT_WEIGHTS`, ali `0.03` u generičkim paketima i `0.04` u paketu `reliability-first`, dok `quality` u paketima ima vrijednost `0.02` (`0.03` u paketu `quality-first`): oni se i dalje izračunavaju za svakog kandidata, a `cacheAffinity` uvjetuje deduplikaciju predmemorije upita izvan bodovanja, pa čimbenici sa zadanom težinom nula prema zadanim postavkama jednostavno ne utječu na rezultat, dok u paketima utječu.

**Zbroj:** `0.1429 + 0.1605 + 0.1429 + 0.1143 + 0.0762 + (7 × 0.0476) + 0.00 + 0.00 + 0.03 + 0.00 = 1.0`, kako je deklarirano u `DEFAULT_WEIGHTS`; prije bodovanja korisnički konfigurirane težine ponovno se normaliziraju u distribuciju funkcijom `normalizeScoringWeights()`.

### Semantika strategije `weighted`

`weighted` je **proporcionalni slučajni odabir za svaki zahtjev**
(`open-sse/services/combo/targetSorters.ts` → `selectWeightedTarget`), a ne mehanizam za izjednačavanje:

- Za svaki se zahtjev odabire **jedan** korak s vjerojatnošću `weight / totalWeight`; preostali koraci
  poredani su prema silaznoj težini kao rezervni lanac za taj zahtjev.
- Korak čija je težina `0` (ili nedostaje) **nikada se ne odabire** dok bilo koji drugi korak ima
  težinu > 0 — može poslužiti samo kao rezerva nakon neuspjeha odabranog koraka. Odabir postaje
  ravnomjeran samo kada su **sve** težine 0.
- Koraci čija su sva odredišta nedostupna — prekidač strujnog kruga pružatelja u stanju `OPEN`, razdoblje
  mirovanja veze, blokada modela — uklanjaju se iz skupa prije odabira
  (`open-sse/services/combo/targetResolution.ts`), pa jedno zdravo odredište može privremeno
  biti odabrano za svaki zahtjev.
- `stickyWeightedLimit` (konfiguracija kombinacije, zadano `1` = isključeno) prikvačuje odabrani korak za toliko
  uzastopnih uspješnih pokušaja prije ponovnog odabira.

Za strogu rotaciju koristite `round-robin`; jednaki ponderi uz `weighted` daju statističku — ne
strogu — ravnotežu.

### Način rada agentnog cjevovoda

Kombinacija `pipeline` s najmanje dva modela može uključiti usmjeravanje planera/izvršitelja putem
`config.agenticOrchestration.enabled`. Prvi cilj zadužen je za planiranje i konačne odgovore;
drugi cilj generira pozive alata u izvornom formatu klijenta. OmniRoute otkriva nastavke
s rezultatima alata iz protokola zahtjeva, pita planer je li potreban još jedan krug alata
te dinamički određuje hoće li završni korak okrenut klijentu izvršiti izvršitelj ili planer.

Dodatni modeli nakon drugog cilja predstavljaju redom poredane pričuvne izvršitelje. Neuspješan
HTTP odgovor ili iznimka pri prijenosu prebacuje obradu na sljedećeg izvršitelja, uz zadržavanje
iste odluke planera i izvornih alata, ali uz korištenje vlastitog upita za korak tog izvršitelja i
razriješene veze. Prvi uspješan odgovor vraća se neizmijenjen, uključujući
SSE strujanje; neuspjesi nakon početka uspješnog strujanja ovdje se ne mogu ponovno pokušati.
Ako svi izvršitelji ne uspiju, vraća se posljednja pogreška. Klijentski prekidi zaustavljaju slanje.

```json
{
  "strategy": "pipeline",
  "models": [{ "model": "provider/planner" }, { "model": "provider/executor" }],
  "config": {
    "agenticOrchestration": { "enabled": true, "maxToolRounds": 8 }
  }
}
```

Izvršitelj može generirati više neovisnih poziva u jednom odgovoru. Ovisni pozivi
obrađuju se u kasnijim klijentskim krugovima s rezultatima alata, pri čemu planer pregledava svaki rezultat.
Zadana vrijednost za `maxToolRounds` jest `8`, a prihvaćene su vrijednosti `1`–`32`; nakon dosezanja te vrijednosti planer mora
generirati najbolji dostupan konačni odgovor. Interne odluke planera pohranjuju se u međuspremnik, dok
odabrani odgovor okrenut klijentu zadržava izvornu postavku strujanja.

### Ljepljiva serija i proširenje računa za `round-robin`

Round-robin radi u serijama, a ne po principu jedan zahtjev po koraku:

- `stickyRoundRobinLimit` (konfiguracija kombinacije, zatim `comboStickyRoundRobinLimit`, pa
  `settings.stickyRoundRobinLimit`, zadano **3**) zadržava isti cilj tijekom toliko
  uzastopnih uspješnih izvršavanja prije rotacije. Postavite nadjačavanje kombinacije na `1` za rotaciju
  po svakom zahtjevu. Uređivač kombinacija prikazuje efektivnu vrijednost i sloj iz kojeg potječe.
- `connectionAwareExpansion` (konfiguracija kombinacije, zatim postavke, zadano **false**) proširuje
  svaki korak na razini pružatelja usluge u ciljeve po računu prije rotacije. Strategije skupine B
  (priority, weighted, round-robin, random, p2c, least-used, cost-optimized, lkgp,
  fill-first, strict-random, context-optimized, cache-optimized, context-relay, fusion,
  pipeline) zadržavaju prikaz na razini pružatelja usluge dok se ova opcija ne uključi. Uređivač kombinacija nudi
  nasljeđivanje / uključeno / isključeno; nasljeđivanje koristi globalnu zadanu vrijednost (isključeno).
- Usmjeravanje prema lokalnosti predmemorije upita (`promptCacheAffinityEnabled`, zadano **true**) mijenja redoslijed
  prikvačenih veza kako bi podudarni ključevi predmemorije ostali na jednom računu. Ima prednost pred
  round-robin i ponderiranom rotacijom između prikvačenih koraka po računu. Isključite ga u odjeljku
  Settings → Combo defaults ako vam je potrebna stroga rotacija. Ne postoji nadjačavanje po kombinaciji.

Za rotaciju između više računa na jednom modelu preporučuje se **jedan korak s dinamičkim računom** (prazan
`connectionId`, cijeli skup) s ljepljivim ograničenjem `1`, umjesto tri prikvačena `connectionId`-a.
Prikvačeni koraci uz afinitet svode se na isti račun čak i dok se RR brojač
povećava.

## Strategija Fusion

`fusion` je jedina strategija koja **ne** odabire jedan ciljni model. Ona šalje prompt
**svim panel modelima paralelno**, a zatim konfigurabilan **model suca** sintetizira
jedan konačni odgovor iz svih odgovora panela. Preneseno iz upstream repozitorija `decolua/9router`
(OpenRouterov Fusion dizajn); implementacija u `open-sse/services/fusion.ts`.

Kako radi:

0. **Zaobilaženje za zahtjeve s alatima** — zahtjev koji sadrži neprazan niz `tools` s
   `tool_choice` koji nije eksplicitno `"none"` potpuno preskače panel: usmjerava se izravno na
   jedan model (konfigurirani sudac, ili `panel[0]`) s `tools`/`tool_choice`
   proslijeđenima bez izmjena. Članovi panela nemaju pristup alatima, a sudčeva
   direktiva sinteze ne potiče emisiju poziva alata, pa agentski/klijenti koji koriste alate
   dobivaju pravu odluku o pozivu alata umjesto sintetiziranog teksta (#6771).
1. **Fan-out** (samo za zahtjeve bez alata) — prompt se šalje svim panel
   modelima odjednom, prisilno nestreaming s uklonjenim alatima (sucu trebaju potpuni
   tekstovi za sintezu).
2. **Prikupljanje s kvorumskom grejs-periodom** — čim pristigne `minPanel` odgovora, pokreće se kratki tajmer
   grejs-perioda za zaostale modele, a zatim fusion nastavlja s onim što je prikupljeno.
   Time se ograničava kazna najsporijeg modela na ukupno vrijeme, uz tvrdi vremenski limit.
3. **Sudačka sinteza** — odgovori panela se anonimiziraju (`Source 1`, `Source 2`, … — kako
   bi sudac vagao sadržaj, a ne naziv modela) i predaju sucu, koji analizira
   konsenzus / kontradikcije / djelomičnu pokrivenost / jedinstvene uvide / slijepe točke, a zatim
   piše **jedan** autoritativan odgovor. Sudački poziv zadržava originalni
   `stream` flag klijenta + alate, tako da streaming i downstream korištenje alata još uvijek rade.
4. **Postupna degradacija** — 0 odgovora panela → `503`; točno 1 preživjeli → taj odgovor
   se vraća izravno (nema što fuzionirati); panel s jednim modelom odgovara izravno.

Član panela može biti i korak `combo-ref` (`{kind: "combo-ref", comboName: "..."}`) koji referencira
drugi combo — razrješava se kao **jedan black-box glas panela** (potpuni rekurzivni dispatch u
referencirani combo, a ne fan-out vlastitih ciljeva tog comba), s istom zaštitom od dubine/ciklusa
koju već koriste sve ostale strategije koje konzumiraju combo-ref (#6764).

## Virtualna Tvornica Auto-Kombinacija

Engine za automatske kombinacije ne zahtijeva unaprijed definirane kombinacije. Umjesto toga, `open-sse/services/autoCombo/virtualFactory.ts` gradi kandidate u hodu:

1. Dohvaća `getProviderConnections({ isActive: true })` (sve aktivne veze)
2. Filtrira one s važećim vjerodajnicama (API ključ ili neistekli OAuth token putem `hasUsableOAuthToken()`)
3. Unakrsno provjerava s `getProviderRegistry()` za dostupnost modela i cijene
4. Za svaki skup `(provider, model, connection)`, gradi `VirtualAutoComboCandidate`
5. Odabire `connection.defaultModel` (ili prvi model iz registra) kao odredište slanja
6. Ocjenjuje svakog kandidata koristeći 16-faktorski `scorePool()` i paket težina varijante
7. Vraća rezultirajući `AutoComboConfig` u memoriji za `handleComboChat()` — nikada se ne pohranjuje u bazu podataka

To znači da **dodavanje novog pružatelja s omogućenim `auto/*` automatski proširuje skup kandidata** — nije potrebno ručno uređivanje kombinacija. Virtualna kombinacija se gradi iznova za svaki zahtjev, pa se novododane ili novozdrave veze odmah preuzimaju.

## Samo-oporavak

- **Privremeno isključenje**: Ocjena < 0.2 → isključeno na 5 min (progresivni backoff, maksimalno 30 min)
- **Svjesnost prekidača strujnog kruga**: OPEN → automatski isključen; HALF_OPEN → probe zahtjevi
- **Način incidenta**: >50% OPEN → onemogući istraživanje, maksimiziraj stabilnost
- **Oporavak nakon hlađenja**: Nakon isključenja, prvi zahtjev je "probe" sa smanjenim vremenskim ograničenjem

## Banditsko Istraživanje

5% zahtjeva (konfigurabilno) usmjerava se nasumičnim pružateljima radi istraživanja. Onemogućeno u načinu incidenta.

## API

**Ne postoji namjenska krajnja točka `POST /api/combos/auto`** — Auto-Combo koristi se na dva načina:

1. **Bez konfiguracije (preporučeno):** Pošaljite bilo koji zahtjev za dovršavanje razgovora s `model: "auto"` ili `model: "auto/<variant>"`. Virtualna tvornica izrađuje kombinaciju za svaki zahtjev — bez trajne pohrane i bez potrebnih API poziva.

2. **Trajno pohranjena kombinacija sa `strategy: "auto"`:** Izradite običnu kombinaciju putem `POST /api/combos` i postavite `strategy: "auto"` zajedno s `config.auto.weights` / `config.auto.candidatePool`. Koristi se isti mehanizam bodovanja; kombinacija se pohranjuje u `combos` i može se ponovno upotrebljavati prema ID-u.

Za otkrivanje, `GET /api/combos/auto` navodi svaku varijantu s njezinim razriješenim skupom kandidata te vrijednostima `context_length` / `max_output_tokens` — MAKSIMUMOM među prozorima skupa kandidata. Klijenti (npr. dodatak opencode) moraju oglašavati te vrijednosti umjesto `0`: nulti kontekst potpuno onemogućuje automatsku kompakciju u opencodeu, dopuštajući sesijama da rastu sve dok čišćenje povijesti na pristupniku ne uništi kontekst. Sigurno je oglašavati MAKSIMUM jer predfiltar konteksta automatske kombinacije usmjerava prevelike zahtjeve kandidatima s velikim prozorom.

```bash
# Upotreba bez konfiguracije (bez izrade kombinacije)
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/coding","messages":[{"role":"user","content":"Hello"}]}'

# Trajno pohranjena automatska kombinacija putem uobičajene krajnje točke za kombinacije
curl -X POST http://localhost:20128/api/combos \
  -H "Content-Type: application/json" \
  -d '{"id":"my-auto","name":"Auto Coder","strategy":"auto","config":{"auto":{"candidatePool":["anthropic","google","openai"],"weights":{"quota":0.15,"health":0.3,"costInv":0.05,"latencyInv":0.35,"taskFit":0.1,"stability":0,"tierPriority":0.05}}}}'
```

### Strategije automatskog usmjerivača

Trajno pohranjene kombinacije sa `strategy: "auto"` mogu postaviti `config.routerStrategy` (ili zastarjeli
`config.auto.routerStrategy`) na jednu od sljedećih vrijednosti:

- `rules` — zadano ponderirano bodovanje
- `score` — odabire najviši konfigurirani ponderirani rezultat. Potpuno jednaki rezultati zadržavaju konfigurirani
  redoslijed kandidata; postojeći `explorationRate` uzorkuje iz cijelog rangiranog skupa.
- `cost` / `eco` — najjeftiniji ispravan pružatelj usluge
- `latency` / `fast` — najniža latencija p95 uz penalizaciju nepouzdanosti
- `sla-aware` / `sla` — daje prednost kandidatima koji zadovoljavaju SLO-ove za latenciju p95, stopu pogrešaka i opcionalno
  trošak
- `lkgp` — prvo posljednji poznati ispravan pružatelj usluge
- `nadir` — pita API za odlučivanje sustava [Nadir](https://getnadir.com) koji je model iz skupa
  potreban upitu; uz izričito uključivanje i povratak na `rules` u slučaju neuspjeha

### Detaljan opis strategija usmjerivača

Mehanizam automatske kombinacije pruža 7 izmjenjivih implementacija **RouterStrategy**
koje možete zamijeniti putem `config.routerStrategy` (ili zastarjelog `config.auto.routerStrategy`).
Svaka strategija odabire jednog pružatelja usluge iz skupa kandidata na temelju objekta `RoutingContext`
(vrsta zadatka, naznake alata/vizualnog sadržaja, procjena broja tokena, opcionalna SLA pravila, opcionalni
posljednji poznati ispravan pružatelj usluge).

#### 1. `rules` (zadano) — ponderirano bodovanje prema 16 čimbenika

Obuhvaća postojeći mehanizam bodovanja. Filtrira kandidate prekidača strujnog kruga
sa stanjem `OPEN`, a zatim pokreće `scorePool()` s trenutačnom vrstom zadatka i funkcijom `getTaskFitness()`,
odabirući pružatelja usluge s najvišim rezultatom.

```ts
class RulesStrategyImpl implements RouterStrategy {
  readonly name = "rules";
  readonly description = "16-factor weighted scoring (see DEFAULT_WEIGHTS)";

  select(pool, context) {
    const eligible = pool.filter((c) => c.circuitBreakerState !== "OPEN");
    const ranked = scorePool(
      eligible.length > 0 ? eligible : pool,
      context.taskType,
      undefined,
      getTaskFitness
    );
    return { provider: ranked[0].provider /* ... */ };
  }
}
```

**Kada upotrebljavati**: Zadano. Upotrebljavajte kada želite uravnotežen kompromis između svih signala.

**Pseudonim**: `rules` (nema pseudonima)

---

#### 2. `cost` / `eco` — najjeftiniji ispravan pružatelj usluge

Sortira skup kandidata prema `costPer1MTokens` (uzlazno) i odabire najjeftinijeg.
Najprije filtrira kandidate sa stanjem `OPEN`.

```ts
class CostStrategyImpl implements RouterStrategy {
  readonly name = "cost";
  readonly description = "Always selects cheapest available provider";

  select(pool, context) {
    const healthy = pool.filter((c) => c.circuitBreakerState !== "OPEN");
    const sorted = [...healthy].sort((a, b) => a.costPer1MTokens - b.costPer1MTokens);
    return { provider: sorted[0].provider /* ... */ };
  }
}
```

**Kada upotrebljavati**: Radna opterećenja osjetljiva na troškove, skupna obrada ili pozadinski poslovi.

**Pseudonimi**: `cost`, `eco`

---

#### 3. `latency` / `fast` — najniža latencija p95 uz penalizaciju nepouzdanosti

Sortira prema `p95LatencyMs + (errorRate * 1000)`. Penalizacija stope pogrešaka osigurava
da se nepouzdani pružatelji usluge rangiraju niže čak i ako im je nominalna latencija niska.

```ts
class LatencyStrategyImpl implements RouterStrategy {
  readonly name = "latency";
  readonly description = "Prioritizes lowest p95 latency with reliability weighting";

  select(pool, context) {
    const healthy = pool.filter((c) => c.circuitBreakerState !== "OPEN");
    const sorted = [...healthy].sort(
      (a, b) => a.p95LatencyMs + a.errorRate * 1000 - (b.p95LatencyMs + b.errorRate * 1000)
    );
    return { provider: sorted[0].provider /* ... */ };
  }
}
```

**Kada upotrebljavati**: Radna opterećenja osjetljiva na latenciju, poput razgovora u stvarnom vremenu, automatskog dovršavanja ili
interaktivnih pomoćnika za programiranje.

**Pseudonimi**: `latency`, `fast`

---

#### 4. `sla-aware` / `sla` — usklađenost SLO-a za latenciju/pogreške/trošak

Boduje svakog kandidata prema tome koliko dobro zadovoljava konfigurirana pravila SLO-a:

| Faktor             | Težina | Formula                                               |
| ------------------ | ------ | ----------------------------------------------------- |
| Ocjena latencije   | 35%    | `threshold / max(value, ε)`                           |
| Ocjena pogrešaka   | 35%    | `threshold / max(value, ε)`                           |
| Ocjena zdravlja    | 15%    | `1.0` (CLOSED) / `0.5` (HALF_OPEN) / `0.0` (OPEN)     |
| Ocjena troška      | 10%    | `threshold / max(value, ε)` ili obrnuto normalizirano |
| Ocjena stabilnosti | 5%     | obrnuto normalizirana standardna devijacija latencije |

Kada je `hardConstraints: true`, kandidati se prvenstveno sortiraju prema **ocjeni prekoračenja**
(koliko premašuju bilo koji SLO), a zatim prema kompozitnoj ocjeni. U suprotnom se koristi samo
kompozitna ocjena.

```ts
class SLAStrategyImpl implements RouterStrategy {
  readonly name = "sla-aware";
  readonly description =
    "Selects the provider most likely to satisfy latency, error-rate, and cost SLOs";

  select(pool, context) {
    // ... ocjenjuje svakog kandidata prema pravilima: { targetP95Ms, maxErrorRate, maxCostPer1MTokens, hardConstraints }
  }
}
```

**SLA polja** (postavljaju se u konfiguraciji kombinacije):

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "sla-aware",
    "slaTargetP95Ms": 1500,
    "slaMaxErrorRate": 0.05,
    "slaMaxCostPer1MTokens": 5,
    "slaHardConstraints": true
  }
}
```

**Kada upotrebljavati**: Produkcijska radna opterećenja sa strogim ograničenjima latencije, stope pogrešaka ili troškova.

**Aliasi**: `sla-aware`, `sla`

---

#### 5. `lkgp` — prvo posljednji poznati dobar pružatelj usluge

Najprije pokušava upotrijebiti **posljednjeg poznatog dobrog pružatelja usluge** (ako je postavljen), a zatim se vraća na
strategiju `rules`. Korisno za održavanje povezanosti sesije — isti pružatelj usluge obrađuje
naknadne zahtjeve u razgovoru.

```ts
class LKGPStrategyImpl implements RouterStrategy {
  readonly name = "lkgp";
  readonly description = "Tries last known good provider first, then falls back to rules";

  select(pool, context) {
    if (context.lkgpEnabled === false) {
      return getStrategy("rules").select(pool, context);
    }

    if (context.lastKnownGoodProvider) {
      const candidates = pool.filter(
        (c) => c.provider === context.lastKnownGoodProvider && c.circuitBreakerState !== "OPEN"
      );
      if (candidates.length > 0) {
        return { provider: candidates[0].provider /* ... */ };
      }
    }

    // Povratak na strategiju rules
    return getStrategy("rules").select(pool, context);
  }
}
```

**Kada upotrebljavati**: Razgovori u više koraka u kojima želite da isti pružatelj usluge obrađuje
naknadne zahtjeve (npr. radi predmemoriranja, kontinuiteta konteksta ili dosljednosti cijena).

**Alias**: `lkgp` (bez aliasa)

---

#### 6. `nadir` — odabir modela putem Nadira uzimajući u obzir upit

Svaka od prethodnih strategija rangira kandidate prema vlastitoj telemetriji; nijedna od njih ne čita
zahtjev. `nadir` šalje posljednju korisnikovu poruku zajedno s ID-jevima modela iz skupa
[Nadir](https://getnadir.com) API-ju za donošenje odluka (`POST /v1/bucket`) i usmjerava zahtjev na model
koji Nadir odabere iz tog izbornika (`simple` → najjeftiniji model s potrebnim mogućnostima, `complex` →
najnapredniji model). Vezu koja poslužuje taj model i dalje odabire `rules`, pa kvota,
zdravlje i trošak i dalje određuju koji će se račun upotrijebiti.

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "nadir",
    "nadir": {
      "apiKey": "ndr_...",
      "baseUrl": "https://api.getnadir.com",
      "timeoutMs": 2000
    }
  }
}
```

`OMNIROUTE_NADIR_API_KEY` i `OMNIROUTE_NADIR_BASE_URL` zamjenske su varijable okruženja za ta dva
niza. `baseUrl` je potreban samo za Nadir koji sami hostirate (završni `/v1` je dopušten).
Pozivi bez ključa usmjeravaju se na Nadirovu anonimnu razinu, na kojoj je broj zahtjeva ograničen po IP adresi.

Što napušta sustav: tekst posljednje korisnikove poruke (prvih 16 tisuća znakova), ID-jevi modela
kandidata i oznaka kanala `source: "omniroute"`. Ne šalju se sistemski upit, povijest, alati ni
zaglavlja.

Ponašanje u slučaju neuspjeha jest fail-open: istek vremena (zadano 2000 ms), odgovor koji nije 2xx, nedostupan
host, neispravan odgovor ili odabir izvan skupa rezultira odlukom strategije `rules`,
a razlog dobiva prefiks `NadirStrategy: fallback (…)`. Nakon neuspjelog poziva
strategija preskače mrežni pristup 30 s, tako da prekid rada uzrokuje jedan istek vremena svakih 30 s umjesto
jednog po zahtjevu. Događaji usmjeravanja prijavljuju `strategy: "nadir"` samo kada je Nadir doista donio
odluku.

**Kada upotrebljavati**: promet mješovite složenosti u skupu koji obuhvaća više razina modela (mali, srednji
i najnapredniji model), kada želite smanjiti trošak stalne uporabe najnaprednijeg modela.

**Alias**: `nadir` (bez aliasa)

### Prilagođene strategije usmjerivača

Možete registrirati vlastitu implementaciju sučelja `RouterStrategy` putem javnog API-ja:

```ts
import {
  registerStrategy,
  type RouterStrategy,
} from "@omniroute/open-sse/services/autoCombo/routerStrategy";

class MyCustomStrategy implements RouterStrategy {
  readonly name = "my-custom";
  readonly description = "My custom routing strategy";

  select(pool, context) {
    // Ovdje unesite vlastitu logiku usmjeravanja
    return {
      provider: pool[0].provider,
      model: pool[0].model,
      strategy: this.name,
      reason: "MyCustomStrategy: ...",
      candidatesConsidered: pool.length,
      finalScore: 1.0,
    };
  }
}

registerStrategy("my-custom", new MyCustomStrategy());
```

Zatim je upotrijebite:

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "my-custom"
  }
}
```

Uključujući goli `auto` (zadano) i 6 `AutoVariant` vrijednosti deklariranih u `autoPrefix.ts`, postoji **7 pozivnih ID-ova modela**:

## Kako se razine uklapaju u Auto-Combo

Funkcija bodovanja sa 16 faktora (`open-sse/services/autoCombo/scoring.ts`) tretira pripadnost razini kao dva signala: `tierPriority` (0.0476) i `tierAffinity` (0.0476). Pogledajte prethodno navedenu kanonsku [tablicu faktora bodovanja](#how-it-works-persisted-auto-combos) za cijeli skup `DEFAULT_WEIGHTS` — nadjačavanja po paketu (ship-fast/cost-saver/quality-first/offline-friendly) navedena su u tablici „Profili težina po paketu”.

Sama razina **ne** daje automatski prednost Razini 1 — ako je latencija Razine 1 loša ili je omjer troška i kvalitete neoptimalan, pobjeđuje Razina 2. Kako biste nametnuli redoslijed razina, upotrijebite strategiju kombinacije `priority` i rasporedite pružatelje usluga prema razini.

Kako biste dali veliku prednost Razini 1 (pretplata), povećajte težinu `tierPriority`:

```json
{
  "strategy": "auto",
  "config": { "auto": { "weights": { "tierPriority": 0.3, "costInv": 0.05 } } }
}
```

Definicije razina i klasifikaciju pružatelja usluga potražite u dokumentu [`docs/guides/TIERS.md`](../guides/TIERS.md).

## Testiranje i pokrivenost

### Deterministička matrica odluka usmjeravanja (`npm run test:combo:matrix`)

`tests/integration/combo-matrix/*.test.ts` dokazuje **odluku** usmjeravanja svih 19
javnih strategija od kraja do kraja kroz pravi combo cjevovod s lažnim upstream-om.
Pokrivenost uključuje:

- Svih 19 strategija `ROUTING_STRATEGY_VALUES` (naručene, ponderirane, troškovna, kontekstualna, fuzijska, …).

  `__setHeadroomSaturationFetcherForTests`).
- Pokrivenost univerzalnog prijenosa `context-relay` za svaki broj ciljeva.

Ovaj skup testova izvodi se u CI (`test:integration` posao) s `--test-concurrency=1` i
`--test-force-exit` kako bi bio deterministički i ne zahtijeva stvarne vjerodajnice.
