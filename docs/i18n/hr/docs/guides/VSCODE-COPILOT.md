**OmniCopilot** stavlja svaki model koji poslužuje vaš OmniRoute u _izvorni_ birač modela za GitHub Copilot Chat.
Nema dodatne bočne trake ni zasebnog sučelja za razgovor — Copilotov agentski način rada, pozivanje alata,
MCP poslužitelji i prilagođene upute nastavljaju raditi, samo na modelu koji odaberete.

|                            |                                                                                                                                                 |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Instalacija (VS Code)**  | [Marketplace → `diegosouzapw.omnicopilot`](https://marketplace.visualstudio.com/items?itemName=diegosouzapw.omnicopilot)                        |
| **Instalacija (forkovi)**  | [Open VSX](https://open-vsx.org/extension/diegosouzapw/omnicopilot) — Cursor, Windsurf, VSCodium, Theia, code-server, Gitpod, Antigravity, Kiro |
| **Izvorni kod / problemi** | [github.com/diegosouzapw/OmniCopilot](https://github.com/diegosouzapw/OmniCopilot) (MIT)                                                        |
| **Zahtijeva**              | VS Code 1.104+                                                                                                                                  |

> **Pretplata na Copilot nije potrebna.** Od verzije VS Code 1.122 pružatelj jezičnih modela radi
> bez prijave na GitHub i bez ikakvog Copilot plana. Dovršavanje koda u retku i
> značajke temeljene na ugradnjama nisu dio API-ja pružatelja i još uvijek zahtijevaju Copilot.

## Postavljanje

1. **Pokrenite OmniRoute** — `npm install -g omniroute && omniroute` (nadzorna ploča na `http://localhost:20128`).
2. **Instalirajte proširenje** — potražite "OmniRoute" u prikazu Proširenja.
3. **Odaberite model** — Copilot Chat → birač modela → **Upravljanje modelima…** → **OmniRoute**, a zatim označite
   modele koje želite.

Nije potrebno ništa konfigurirati kada OmniRoute radi na zadanom priključku. Za udaljenu instancu otvorite
**ikonu OmniRoute na traci aktivnosti** (ili pokrenite `OmniRoute: Manage Connection`) i postavite:

- **URL poslužitelja** — korijenska adresa poslužitelja, npr. `http://192.168.0.15:20128`. Proširenje
  dodaje sufiks `/v1`; nemojte ga uključiti.
- **API ključ** — samo kada poslužitelj postavi `REQUIRE_API_KEY`. Pohranjuje se u privjesku ključeva OS-a putem
  VS Code SecretStorage, nikada u `settings.json`.

## Što će birač prikazati

Proširenje ne prikazuje sirovi sadržaj odgovora `GET /v1/models` — ono ga oblikuje, a broj koji
vidite manji je od veličine kataloga iz dva namjerna razloga.

### Za svaki model traži jedan ID

`MODELS_CATALOG_PREFIX_MODE` zadano je postavljen na **`dual`**, što svaki model oglašava dvaput — jednom
s prefiksom kratkog aliasa i jednom s kanonskim prefiksom pružatelja — kako bi starije konfiguracije
klijenata mogle nastaviti razrješavati oba oblika:

```
cc/claude-sonnet-4-6        ← prefiks aliasa
claude/claude-sonnet-4-6    ← kanonski prefiks, isti model
```

Proširenje šalje zahtjev **`GET /v1/models?prefix=alias`** kako bi za svaki model stigao jedan ID, bez
promjene postavke za cijeli poslužitelj za vaše ostale klijente. Na referentnoj instanci time je broj
smanjen s **2345 unosa na 1396 — 949 duplikata, bez gubitka modela.**

Ako biste to radije ispravili na razini poslužitelja za _svakog_ klijenta, postavite zastavicu značajke
`MODELS_CATALOG_PREFIX_MODE` na `alias` na nadzornoj ploči. Pogledajte
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) za
parametar upita i tablicu za svaki način rada.

### Skriva modele koji ne podržavaju razgovor

Katalog također navodi modele za slike, videozapise, zvuk, ponovno rangiranje, ugradnje i moderiranje. Oni se
ionako odbijaju pri zahtjevu za razgovor:

```
HTTP 400 — Model '<id>' model je za generiranje slika i ne može se upotrebljavati na
/v1/chat/completions. Umjesto toga upotrijebite POST /v1/images/generations.
```

stoga se filtriraju prema svojem polju `type` prije nego što dođu do birača. **Modeli Responses API-ja
zadržavaju se** — svaki unos Codex / GPT-5.x oglašava `supported_endpoints: ["responses"]`,
a OmniRoute ih prevodi za `/v1/chat/completions`, pa su potpuno upotrebljivi.

### Pružatelji koje nikada niste konfigurirali

Katalog navodi modele pružatelja s **aktivnom vezom** _te_ svakog pružatelja **noAuth** —
onih bez ključa koji čine velik dio besplatne razine. To je namjerno. Da biste ih sakrili,
dodajte ih u `blockedProviders` u postavkama nadzorne ploče; u proširenju se ništa ne mijenja.

## Nadzorna ploča unutar kartice VS Codea

`omnicopilot.dashboardOpen: "editor"` prikazuje nadzornu ploču OmniRoutea u kartici uređivača putem
Simple Browsera umjesto u vanjskom pregledniku. Ugrađivanje se **mora izričito omogućiti na poslužitelju** putem
`DASHBOARD_ALLOW_EMBED=vscode`, čime se HTML stranice poslužuju sa zaglavljem
`frame-ancestors 'self' vscode-webview:` umjesto zadanog `frame-ancestors 'none'` +
`X-Frame-Options: DENY`. API površina (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) u oba slučaja zadržava
stroga zaglavlja.

> ⚠️ **To je opcija za vrijeme izgradnje, a ne za vrijeme izvođenja.** Next.js ugrađuje `headers()` u manifest
> ruta, pa `next.config.mjs` čita varijablu tijekom izgradnje paketa
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> Izvoz varijable prije pokretanja već izgrađenog poslužitelja ne mijenja ništa — zaglavlja su već ugrađena.

```bash
# varijabla mora biti prisutna u naredbi za IZGRADNJU
DASHBOARD_ALLOW_EMBED=vscode npm run build        # ili npm run build:release
npm start
```

| Način instalacije          | Možete li omogućiti ugrađivanje?                                                                                                                   |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Iz izvornog koda           | ✅ postavite varijablu u naredbi za izgradnju, kao što je prikazano iznad                                                                          |
| `npm install -g omniroute` | ❌ objavljeni paket sadrži unaprijed izgrađeni paket — umjesto toga izgradite iz izvornog koda                                                     |
| Docker slika               | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — unaprijed izgrađena slika na Docker Hubu ne podržava ugrađivanje |

Bez izgradnje koja podržava ugrađivanje stranica odbija prikazivanje u okviru, proširenje to otkriva iz
zaglavlja odgovora i vraća se na vanjski preglednik — ništa se ne prekida, a o tome se prikazuje jednokratna obavijest.
Pogledajte [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) i problem
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273).

## Konfiguriranje drugih alata unutar VS Codea

**`OmniRoute: Configure Coding CLI`** koristi `omniroute` CLI za zapisivanje profila spremnih za uporabu
za Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code,
Kilo i Roo — istih konfiguracija koje su opisane u
[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md). API ključ prosljeđuje se CLI-ju putem
varijable okruženja `OMNIROUTE_API_KEY`, nikada putem naredbenog retka.

## Rješavanje problema

| Simptom                                                       | Uzrok / rješenje                                                                                                                                                                                                                                                               |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| U biraču nema modela OmniRoutea                               | Poslužitelj nije dostupan. Točka na statusnoj traci postaje siva; pokrenite `OmniRoute: Check Connection`. Otkrivanje je namjerno neprimjetno i ne dodaje modele umjesto prikazivanja upita.                                                                                   |
| Svaki se model pojavljuje dvaput                              | Upotrebljavate verziju OmniCopilota stariju od 1.0.1 — ažurirajte je. Proširenje sada šalje zahtjev s `?prefix=alias`.                                                                                                                                                         |
| Model za slike/zvuk prije je bio naveden, ali više nije       | Namjerno od verzije 1.0.1 — takav model nikada nije mogao odgovoriti na zahtjev za razgovor.                                                                                                                                                                                   |
| Ploča nedostaje na traci aktivnosti                           | VS Code premješta dodatne spremnike prikaza u izbornik viška **"…"** pri dnu trake aktivnosti, a spremnik skriven desnim klikom ostaje skriven. Desnom tipkom miša kliknite traku aktivnosti → označite **OmniRoute** ili ga otvorite naredbom `OmniRoute: Manage Connection`. |
| Nadzorna ploča otvara se u pregledniku unatoč načinu `editor` | Poslužitelj nije **izgrađen** s `DASHBOARD_ALLOW_EMBED=vscode` (pogledajte iznad) — postavljanje te varijable pri pokretanju unaprijed izgrađene instalacije ne čini ništa. Povratak na preglednik namjeran je.                                                                |
| Popis modela zastario je nakon promjene pružatelja            | `OmniRoute: Refresh Models` ili poveznica ↻ na ploči.                                                                                                                                                                                                                          |
