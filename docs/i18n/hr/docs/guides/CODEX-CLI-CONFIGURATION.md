Potpuni vodič za korištenje Codex CLI-ja usmjerenog na OmniRoute kao pozadinski sustav kompatibilan s OpenAI-jem.

---

> **TOML je jedini djelotvoran format.** Moderni Codex čita isključivo
> `~/.codex/config.toml` (provjereno s codex-cli 0.147.0: `codex --help`
> navodi da nadjačavanja `-c/--config` "loaded from `~/.codex/config.toml`").
> Stari `~/.codex/config.yaml` pripadao je zastarjelom npm CLI-ju i tiho se
> zanemaruje. Generator na nadzornoj ploči (`/api/cli-tools/apply`, alat `codex`)
> zapisuje TOML uz konzervativno spajanje — postojeći ključevi i drugi blokovi
> pružatelja ostaju sačuvani, API ključ ostaje u `OMNIROUTE_API_KEY` (nikada u
> datoteci), a preostali zastarjeli `config.yaml` prijavljuje se kao napomena o
> migraciji bez ikakvih izmjena.

## config.toml spreman za lijepljenje

Zamijenite `<YOUR_HOST>` i `<YOUR_KEY>` svojim vrijednostima:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # ograničenje pohrane povijesti po pozivu alata

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc ili ~/.zshrc — stvarna vrijednost ključa, nikada u config.toml
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: Codex uključen u aplikaciju ChatGPT

Ako ste Codex instalirali putem desktop aplikacije ChatGPT, binarna datoteka
`codex` možda postoji samo unutar paketa aplikacije i još nije dostupna u
varijabli `PATH` vaše ljuske. Dodajte direktorij resursa u datoteku za
pokretanje ljuske:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

Otvorite novu ljusku, a zatim provjerite:

```bash
command -v codex
codex --version
```

### Lokalni OmniRoute bez autentifikacije: dovoljan je zamjenski ključ

Codex provjerava postoji li varijabla okruženja navedena u `env_key`
**prije** nego što prvi zahtjev napusti CLI. Ako vaša **lokalna** instanca
OmniRoutea ne zahtijeva autentifikaciju, dovoljna je bilo koja neprazna
zamjenska vrijednost:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

Umjesto nje upotrijebite stvarni ključ kada je vaš poslužitelj OmniRoute
zaštićen ili udaljen.

> **Uobičajene opcije glavnog računala**
>
> | Pristup         | URL                           |
> | --------------- | ----------------------------- |
> | Lokalna mreža   | `http://192.168.0.1:20128/v1` |
> | Tailscale       | `http://100.x.x.x:20128/v1`   |
> | Povratna petlja | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — zašto radi sa svim modelima

Codex CLI ukinuo je podršku za `wire_api = "chat"` (Chat Completions) u veljači 2026. i sada **zahtijeva** `wire_api = "responses"` (OpenAI Responses API). Postavljanje vrijednosti `wire_api = "chat"` uzrokuje trenutačno rušenje pri pokretanju od verzije v0.138.

Mnogi pružatelji, uključujući GLM i Kimi, još uvijek nude samo krajnju točku Chat Completions. DeepSeek V4 sada nudi i izvorni Responses API, kao i krajnju točku kompatibilnu s Anthropicem; OmniRoute prema zadanim postavkama koristi Responses i omogućuje da svaka veza s DeepSeekom odabere kompatibilnost s Anthropicem.

**OmniRoute to rješava transparentno:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute odabire izvorni protokol pružatelja i po potrebi prevodi
    → POST /responses (DeepSeek V4) ili /chat/completions (Mistral / GLM / Kimi / ostali)
```

Kada koristite OmniRoute, nikada vam nije potreban zaseban proxy za prevođenje. **Svi modeli koriste `wire_api = "responses"`** — OmniRoute obavlja sve ostalo.

> **`wire_api` je zadana vrijednost** — polje prema zadanim postavkama ima vrijednost `"responses"` i može se u potpunosti izostaviti iz datoteke `config.toml`. Izričito ga postavite samo ako dokumentirate namjeru.

## Kontekstni prozor i sažimanje

### Polja konfiguracije tokena

| Polje                            | Opis                                                                                                                                                                                                       |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model_context_window`           | Ukupan budžet tokena za aktivni model. Postavite na deklarirano ograničenje modela.                                                                                                                        |
| `model_auto_compact_token_limit` | Prag koji pokreće automatsko sažimanje povijesti. **Maksimalno: 90% vrijednosti `model_context_window`** — vrijednosti iznad 90% zanemaruju se bez upozorenja.                                             |
| `tool_output_token_limit`        | Ograničenje broja tokena pohranjenih u povijesti za svaki izlaz poziva alata. Sprječava da jedan velik odgovor alata ispuni prozor. **Ovo nije maksimalni izlaz** — to je ograničenje pohrane u povijesti. |
| `compact_prompt`                 | Ugrađena zamjena za sistemski prompt koji se koristi tijekom sažimanja (v0.138+).                                                                                                                          |

> **Napomena o `model_max_output_tokens`**: Ovo polje **nije dio konfiguracijske sheme Codex CLI-ja** (ne postoji u Codexovoj bazi koda u Rustu). Ako se postavi, zanemaruje se bez upozorenja. Nemojte se oslanjati na njega — upotrijebite `tool_output_token_limit` kako biste odredili koliko se izlaza alata pohranjuje u povijesti.

## Intenzitet zaključivanja

Određuje koliko model „razmišlja” prije odgovora.

| Vrijednost | Koristite za                                                      |
| ---------- | ----------------------------------------------------------------- |
| `none`     | Bez zaključivanja — izravan odgovor                               |
| `low`      | Trivijalne zadatke (preimenovanje, formatiranje)                  |
| `medium`   | **Zadana postavka poslužitelja** ako nije navedeno                |
| `high`     | Srednje zahtjevne zadatke (refaktoriranje, otklanjanje pogrešaka) |
| `xhigh`    | Arhitekturu, dubinsku analizu, složene probleme                   |

```bash
# Nadjačavanje za pojedinačno pokretanje
codex -c model_reasoning_effort=low "rename variable x to count"
codex -c model_reasoning_effort=xhigh "design the auth module"
```

Postavite i **sažetak** zaključivanja kako bi Desktop mogao prikazati tekst razmišljanja (a ne samo šifrirane blokove):

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # ili ultra kada je podržan
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### OmniRouteov proračun razmišljanja (postavka poslužitelja)

Na OmniRoute hostu, **Settings → AI → Thinking Budget** mora biti postavljen na **`passthrough`** kako bi Codexov intenzitet/sažetak stigao do uzvodne usluge. Način rada **`auto` uklanja** sva klijentska polja `reasoning` / `reasoning_effort` i ostavit će ploče razmišljanja praznima čak i kada je Codex ispravno konfiguriran.

Cijeli vodič: [THINKING_BUDGET.md](./THINKING_BUDGET.md).

Sažimanje i predmemorija upita neovisni su i nastavljaju raditi uz `passthrough`.

## Profili — imenovane konfiguracije po modelu/tijeku rada

Profili vam omogućuju promjenu modela i kontekstnog prozora jednom zastavicom. Svaki je profil zasebna datoteka
`~/.codex/<name>.config.toml` koja se primjenjuje povrh osnovnog `config.toml`.

> **Pravilo imenovanja (Codex CLI v0.137+):** datoteka mora biti `~/.codex/<name>.config.toml` — **bez prefiksa `profile-`**.
> CLI razrješava `-p kimi-k27` → `~/.codex/kimi-k27.config.toml`. Ako datoteka nije pronađena, zadana se postavka primjenjuje bez upozorenja.

```bash
codex --profile kimi-k27 "analyze 10k lines of this codebase"
codex -p glm52 "architecture review"
codex --profile deepseek-flash "rename variable"   # brzo, jeftino
```

### Profili intenziteta (isti model, različit intenzitet)

```bash
codex -p low      # cx/gpt-5.5, intenzitet=low
codex -p medium   # cx/gpt-5.5, intenzitet=medium
codex -p high     # cx/gpt-5.5, intenzitet=high
codex -p xhigh    # cx/gpt-5.5, intenzitet=xhigh (zadano)
codex -p chat     # cx/gpt-5.5, intenzitet nije postavljen (zadano na poslužitelju)
```

## Automatsko generiranje profila pomoću naredbe `omniroute setup-codex`

Ako pokrećete OmniRoute na VPS-u, možete automatski generirati datoteke profila iz aktualnog kataloga modela:

```bash
# S VPS-a (koristi lokalni OmniRoute na priključku 20128)
omniroute setup-codex

# S bilo kojeg računala — navedite svoj VPS
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# Pregled bez zapisivanja datoteka
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# Generiraj samo GLM i Kimi profile
omniroute setup-codex --only glm,kimi

# Zapiši u prilagođeni direktorij
omniroute setup-codex --codex-home /path/to/.codex
```

Naredba dohvaća `/v1/models`, koristi optimizirane profile za poznate modele, za ostale kompatibilne tekstualne modele koristi metapodatke kataloga kao pričuvno rješenje te za svaki zapisuje `~/.codex/<name>.config.toml`. Idempotentna je — može se sigurno ponovno pokrenuti.

OmniRoute također može **automatski sinkronizirati** iste datoteke profila nakon što uspješno otkrivanje/uvoz modela davatelja usluge promijeni aktualni katalog. Ova se značajka **mora izričito uključiti i prema zadanim je postavkama isključena**: uključite je na **nadzornoj ploči CLI Code** ("Automatska sinkronizacija CLI profila" → Codex) ili postavite `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` (također poštuje `CLI_ALLOW_CONFIG_WRITES`, koji je prema zadanim postavkama uključen). Kada je omogućena, zapisuje samo zasebne datoteke profila `~/.codex/*.config.toml`; nikada ne mijenja aktivnu/zadanu datoteku `~/.codex/config.toml`, postavke Codex-lb, autentifikaciju ni odabir davatelja usluge.

## Dugotrajni zadaci

Dvije zadane postavke OmniRoutea mogu neprimjetno sabotirati višesatne sesije Codex CLI-ja. Nijedna nije postavka Codex CLI-ja — obje se nalaze na strani OmniRoutea. Korisnici koji prenose konfiguraciju s nadređenih proxy poslužitelja koji vežu sesije uz račune i onemogućuju prekide zbog neaktivnosti često naiđu na oba problema i zaključe da OmniRoute „ne može održavati dugu sesiju”.

| Simptom                                                                              | Vjerojatni uzrok                                                                                | Postavka                 |
| ------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------- | ------------------------ |
| Sesija stalno mijenja račune / kontinuitet predmemorije upita gubi se između krugova | TTL afiniteta sesije iznosi `0` (onemogućeno)                                                   | `sessionAffinityTtlMs`   |
| Veza se prekida usred zaključivanja bez obavijesti vidljive klijentu                 | Nadzornik neaktivnosti toka aktivirao se nakon 10 minuta bez segmenta s nadređenog poslužitelja | `STREAM_IDLE_TIMEOUT_MS` |

Povezane rasprave: [#7126](https://github.com/diegosouzapw/OmniRoute/discussions/7126) (prekidi dugih zadataka), [#5718](https://github.com/diegosouzapw/OmniRoute/discussions/5718) (zašto je afinitet prema zadanim postavkama isključen). Praćenje: [#7287](https://github.com/diegosouzapw/OmniRoute/issues/7287).

### 1. Afinitet sesije — vežite jedan razgovor uz jedan račun

**Zadano:** `sessionAffinityTtlMs = 0` (onemogućeno).

**Gdje ga postaviti**

- Nadzorna ploča → **Postavke → Usmjeravanje** → **Afinitet sesije** → **TTL afiniteta (sekunde)** (`ComboDefaultsTab`)
- Ili PATCH metodom ažurirajte postavke s `sessionAffinityTtlMs` u **milisekundama** (Zod raspon `0`–`86_400_000`, tj. do 24 sata)

> Preimenovano u #7274 iz `codexSessionAffinityTtlMs`, koji se odnosio samo na Codex. Naslijeđeni ključ i dalje se prihvaća kao pseudonim samo za čitanje; nove konfiguracije trebaju upotrebljavati `sessionAffinityTtlMs`. Afinitet se sada primjenjuje na **bilo kojeg** pružatelja nakon što TTL bude veći od `0`, a ne samo na Codex — pogledajte [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → Afinitet sesije.

**Što prestaje raditi kada ostane na 0**

Svaki krug višekružnog Codex razgovora usmjerava se neovisno prema aktivnoj kombiniranoj strategiji i može završiti na **drugom računu u svakom krugu**. Time se prekida kontinuitet nadređene sesije / predmemorije upita. OmniRoute provjerava zaglavlja Codex sesije (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) i polja tijela poput `prompt_cache_key` / `session_id` samo kada je TTL veći od `0` (`extractSessionAffinityKey` u `src/sse/services/auth.ts`).

**Preporučeno za jedan višesatni zadatak**

Postavite TTL **iznad očekivanog stvarnog trajanja zadatka** (maksimum u korisničkom sučelju iznosi **86400 sekundi** = 24 sata):

| Očekivano trajanje zadatka | TTL afiniteta (sučelje, sekunde) | `sessionAffinityTtlMs` |
| -------------------------- | -------------------------------- | ---------------------- |
| Nekoliko sati              | `14400` (4 h)                    | `14400000`             |
| Preko noći / ~12 h         | `43200` (12 h)                   | `43200000`             |
| Cijeli dan                 | `86400` (24 h, maksimum)         | `86400000`             |

Uključivanje je namjerno: onemogućavanje afiniteta pogoduje uravnoteženju opterećenja između računa; njegovo omogućavanje pogoduje kontinuitetu jedne duge agentske sesije. Ovaj vodič **ne** mijenja zadanu postavku — operateri koji izvršavaju duge Codex zadatke moraju je sami omogućiti.

### 2. Vremensko ograničenje neaktivnosti toka — nemojte prekidati tihe krugove zaključivanja

**Zadano:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 minuta). Ako nije postavljeno, nasljeđuje vrijednost iz `REQUEST_TIMEOUT_MS`; zajednička osnovna vrijednost također je 600000. Pogledajte [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → Vremenska ograničenja.

**Što prestaje raditi uz zadanu postavku**

Codexov korak zaključivanja / korištenja alata koji ostane neaktivan dulje od 10 minuta bez **ijednog stvarnog uzvodnog dijela podataka** prisilno zatvara SSE nadzornik neaktivnosti (`open-sse/utils/stream.ts`). Klijent često vidi samo prekid veze — što odgovara opisu „automatski se zaustavilo bez ikakve obavijesti”.

Ključan detalj: OmniRouteov sintetički SSE **signal aktivnosti ne poništava** mjerač neaktivnosti. Samo stvarni dio uzvodnog tijela odgovora ažurira `lastChunkTime`. Tih model koji još uvijek „razmišlja” iz perspektive nadzornika izgleda jednako kao uzvodna veza koja je zastala.

Povezana neaktivnost tijela u Undiciju: `FETCH_BODY_TIMEOUT_MS` (također se zadano postavlja na istu osnovnu vrijednost od 10 minuta; `0` je onemogućuje). Za strujanje `FETCH_TIMEOUT_MS` pokriva samo uspostavljanje veze / prva zaglavlja — nakon što je tok aktivan, zastoji se reguliraju postavkama `STREAM_IDLE_TIMEOUT_MS` i `FETCH_BODY_TIMEOUT_MS`.

**Preporuka za jedan višesatni zadatak**

U okruženju procesa OmniRoute (`.env` / compose / systemd):

```bash
# Onemogućite ograničenja neaktivnosti toka i tijela za duge korake zaključivanja
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

Ili ih povećajte iznad najduljeg očekivanog razdoblja bez aktivnosti (vrijednosti su u milisekundama):

```bash
# Primjer: dopustite do 2 sata tišine između uzvodnih dijelova podataka
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

Ponovno pokrenite OmniRoute nakon promjene tih varijabli okruženja.

### Konkretan postupak — višesatni Codexov zadatak

1. **Fiksirajte račun:** Nadzorna ploča → Postavke → Usmjeravanje → Afinitet sesije → TTL afiniteta = `43200` (12 h) ili `86400` (maksimalno 24 h).
2. **Povećajte / onemogućite ograničenja neaktivnosti** u OmniRouteovu okruženju:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. Zadržite uobičajeni Codexov `config.toml` (`wire_api = "responses"`, ispravan `base_url`, `OMNIROUTE_API_KEY`) — na strani Codexa ne postoje postavke afiniteta/neaktivnosti za ta dva ponašanja.
4. Ponovno pokrenite OmniRoute, a zatim pokrenite dugi Codexov zadatak.

### Odluka o zadanim vrijednostima (#7287)

| Postavka                 | Zadana vrijednost | Promijeniti u ovom vodiču?                                                                                      |
| ------------------------ | ----------------- | --------------------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (isključeno)  | **Ne** — ostaje opcionalno (uravnoteženje opterećenja nasuprot kontinuitetu; pogledajte Raspravu #5718)         |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 min) | **Ne** — ostaje 10 minuta za opći promet; administratori dugih Codexovih zadataka povećavaju je ili onemogućuju |

Globalna promjena bilo koje zadane vrijednosti promijenila bi ponašanje za svakog klijenta instance, a ne samo za Codex. Dokumentirajte postavke; ostavite zadane vrijednosti nepromijenjenima dok izričita odluka administratora ne odredi drukčije.

### Dijagnosticiranje prekida zbog neaktivnosti

Kada se aktivira nadzornik neaktivnosti, OmniRoute zapisuje redak ovog oblika:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

Pretražite zapise za `Idle timeout: no data from` (ili kod `stream_idle_timeout` / naziv pogreške `StreamIdleTimeoutError`). Segment pružatelja predstavlja ono što je OmniRoute upotrijebio za taj zahtjev (`codex`, drugi ID pružatelja ili `provider` ako je nepoznat) — nije uvijek doslovni niz `codex`.

## Rješavanje problema

**`Error: wire_api = "chat" više nije podržan`**
Uklonite `wire_api = "chat"` iz konfiguracije. Postavite `wire_api = "responses"` ili izostavite polje (od v0.138 zadana je vrijednost `"responses"`).

**`Error: model nije pronađen`**
Provjerite postoji li model u OmniRouteu s ispravnim prefiksom. Upotrijebite `omniroute models list` ili otvorite `/dashboard/providers/<provider>`.

**`Pogreška autentifikacije`**
Provjerite je li `OMNIROUTE_API_KEY` izvezen: `echo $OMNIROUTE_API_KEY`.

**`ERROR: Nedostaje varijabla okruženja: OMNIROUTE_API_KEY`**
Codex prije slanja prvog zahtjeva provjerava postoji li varijabla okruženja. Izvezite
stvarni ključ za zaštićene poslužitelje ili nepraznu zamjensku vrijednost, primjerice
`OMNIROUTE_API_KEY=local`, kada vaša **lokalna** instanca OmniRoutea ne
zahtijeva autentifikaciju. Ponovno pokrenite ljusku ako ste je dodali u `~/.bashrc` ili `~/.zshrc`.

**`Veza je odbijena`**
Provjerite je li OmniRoute pokrenut te jesu li glavno računalo i priključak u `base_url` ispravni za vašu mrežu (lokalna u odnosu na Tailscale ili VPS).

**Sesija se ruši blizu ograničenja konteksta**
Izričito postavite `model_context_window` i `model_auto_compact_token_limit`. Pogledajte prethodnu tablicu prozora konteksta.

**Sažimanje se pokreće prekasno**
Smanjite `model_auto_compact_token_limit` na 80–85 % prozora. Nikada ga nemojte postaviti iznad 90 %.

**Profil se ne učitava (`-p <name>` se bez upozorenja zanemaruje)**
Provjerite postoji li datoteka na lokaciji `~/.codex/<name>.config.toml` (bez prefiksa `profile-`). Pokrenite `ls ~/.codex/*.config.toml`.

**Dugotrajni zadatak u Codexu prekida se tijekom izvođenja / prebacuje račune između poteza**
Pogledajte [Dugotrajni zadaci](#long-running-tasks). Omogućite afinitet sesije (TTL dulji od trajanja zadatka) te povećajte ili onemogućite `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS`. Pretražite zapisnike OmniRoutea pomoću grepa za `Idle timeout: no data from`.
