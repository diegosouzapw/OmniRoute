OmniRoute nudi **dva** načina upotrebe OpenAI Codexa:

| Pružatelj              | Kako komunicira s OpenAI-jem                                                                                                                                                                                              | Ograničenje upotrebe                                                         |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| **`codex`**            | Izravno ponovno šalje vaš ChatGPT/OpenAI OAuth token API-ju Responses                                                                                                                                                     | **Da** — službena sesija nije odobrena za upotrebu putem proxyja/usmjerivača |
| **`codex-app-server`** | Upravlja **vlastitim `codex app-server` procesom Codex CLI-ja** putem JSON-RPC-a/WebSocketa; CLI posjeduje i samostalno osvježava svoj OAuth (`~/.codex/auth.json`) na potpuno isti način kao interaktivna `codex` sesija | **Ne** — OmniRoute nikada ponovno ne šalje token API-ju                      |

Budući da `codex-app-server` nikada ponovno ne šalje token, na njega se ne
odnosi ograničenje upotrebe povezano s ponovnim slanjem sesije. Zahtijeva
**Codex CLI dostupan na konfiguriranom URL-u app-servera**, a taj CLI mora biti
**prijavljen**.

---

## 1. Arhitektura

```
┌─ Aplikacija OmniRoute ───────────┐        ┌─ Pomoćni codex-app-server ──────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ token mogućnosti)            │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  samostalno upravlja OpenAI OAuthom │
└──────────────────────────────────┘        │  (~/.codex/auth.json, auto-refresh) │
        │ dijeli (compose volumeni)          └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → WS token mogućnosti (oba ga montiraju)
  codex-appserver-home    → ~/.codex (auth.json zapisuje nadzorna ploča,
                             a čita ga pomoćni codex app-server)
```

- Pomoćni servis sluša **samo** na internoj compose mreži
  (`ws://codex-app-server:1456`), zaštićen tokenom mogućnosti. **Nikada** se ne
  objavljuje na glavnom računalu ni internetu.
- Codex CLI ugrađen je u `omniroute:base`, pa pri pokretanju pomoćnog servisa
  nije potrebno instalirati codex na glavnom ili korisnikovu računalu.

## 2. Pokretanje

```bash
# Pokrenite stog S profilom pomoćnog codex app-servera:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

Pomoćni servis pri prvom pokretanju generira svoj WS token mogućnosti (u
dijeljenom volumenu `codex-appserver-token`), a aplikacija čita isti token putem
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE`. Ručno povezivanje tokena nije
potrebno.

## 3. Povezivanje i prijava

1. Na nadzornoj ploči dodajte vezu za **OpenAI Codex (App-Server)**. API ključ
   ni token nisu potrebni (to je pružatelj bez autentifikacije — pomoćni servis
   upravlja autentifikacijom).
2. Ako Codex CLI pomoćnog servisa **još nije prijavljen**, provjera stanja veze
   prikazuje _„pokrenut, ali nije prijavljen”_ (a ne crvenu pogrešku
   autentifikacije). Upotrijebite **Prijava putem ChatGPT-a**: time se u vašem
   pregledniku pokreće standardni Codexov OAuth za uređaje, a zatim se putem
   opcije **Primijeni autentifikaciju** zapisuje `~/.codex/auth.json` u dijeljeni
   volumen (ista prijava služi i pružatelju `codex` i pružatelju
   `codex-app-server`).
3. Nakon prijave provjera stanja postaje zelena (provjerava i `/readyz` **i**
   `account/read` — odnosno je li servis pokrenut _i_ autentificiran) te počinje
   obrađivati zadatke.

Nadzorna ploča nikada ne prepisuje postojeću ispravnu datoteku
`~/.codex/auth.json` — zapisuje je samo kada datoteka ne postoji ili je njezin
token zastario (uvijek se izrađuje sigurnosna kopija).

## 4. Scenariji implementacije

- **Operator s već autentificiranim Codex CLI-jem** — montirajte svoj
  `~/.codex` s glavnog računala u pomoćni servis (`codex-appserver-home`) i
  preskočite korak prijave.
- **Javni korisnik bez lokalno instaliranog codexa** — nije važno: pomoćni
  servis sadrži CLI. Korisnik se autentificira samo putem nadzorne ploče.
- **OmniRoute izravno na poslužitelju (bez pomoćnog servisa, codex na glavnom računalu)** — usmjerite
  `OMNIROUTE_CODEX_APPSERVER_WS` na vlastiti `codex app-server` i provjerite je
  li codex na glavnom računalu prijavljen; savjet „codex nije instaliran”
  prikazuje se ako izvršna datoteka nedostaje.

## 5. Rezidencijalni / UDP izlazni promet (dodatak operatora, ne isporučuje se)

Gore opisani generički pomoćni servis šalje izlazni promet putem uobičajene
mreže spremnika. Operator kojem je potrebno da Codexov promet izlazi putem
**rezidencijalne izlazne točke** (npr. TUN pomoćnog servisa tailscale koji
prenosi TCP + UDP/QUIC) pokreće je kao zasebnu compose nadopunu; ona namjerno
**nije** dio isporučenog profila `codex-app-server`. Upute za to postavljanje
potražite u internom operativnom priručniku.
