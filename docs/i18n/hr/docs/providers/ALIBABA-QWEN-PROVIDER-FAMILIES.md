Ovaj dokument bilježi odluku o implementaciji za
[Problem #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854). Javni proizvodi
predstavljeni su kao četiri obitelji pružatelja usluga. Regija je podatak o vezi, a ne zaseban proizvod.

## Odluka

| Obitelj pružatelja usluga                             | OmniRoute ID            | Globalna regija | Regija u Kini |
| ----------------------------------------------------- | ----------------------- | --------------- | ------------- |
| Alibaba Cloud Model Studio (plaćanje prema potrošnji) | `alibaba`               | Singapur        | Peking        |
| Alibaba Cloud Token Plan                              | `bailian-coding-plan`   | Singapur        | Peking        |
| Qwen Cloud (plaćanje prema potrošnji)                 | `qwen-cloud`            | Globalno        | Peking        |
| Qwen Cloud Token Plan                                 | `qwen-cloud-token-plan` | Singapur        | Peking        |

Postojeći ID `alibaba-cn` ostaje pseudonim za kompatibilnost tijekom izvođenja za spremljene veze, rute
modela, kombinacije i povijesnu upotrebu. Njegova kartica na nadzornoj ploči objedinjena je s karticom
`alibaba`; nije potrebno prepisivanje baze podataka.

Qwen Cloud s plaćanjem prema potrošnji i Alibaba Cloud Model Studio trenutačno dijele izvršne hostove
kompatibilne s DashScopeom, ali ostaju zasebni identiteti pružatelja usluga jer korisnici dobivaju ključeve
i upravljaju računima putem različitih sučelja proizvoda. Proizvodi Alibaba i Qwen Cloud Token Plan
koriste različite obitelji krajnjih točaka, stoga sva četiri proizvoda ostaju zasebni ID-ovi pružatelja usluga.

## Matrica krajnjih točaka

| Obitelj pružatelja usluga | `global-sg`                                                              | `china-beijing`                                                      | Format prijenosa |
| ------------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ---------------- |
| `alibaba`                 | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI           |
| `bailian-coding-plan`     | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic        |
| `qwen-cloud`              | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI           |
| `qwen-cloud-token-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI           |

API ključ i krajnja točka moraju pripadati istom proizvodu i regiji. Odabirom regije mijenja se
unaprijed postavljena krajnja točka koja se koristi za provjeru valjanosti i uobičajene zahtjeve.

## Ugovor veze

Nove veze pohranjuju stabilni ključ regije u `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

Dopuštene vrijednosti su `global-sg` i `china-beijing`. Krajnja točka izvodi se centralno iz
ID-a pružatelja usluga i regije. Vrijednost `providerSpecificData.baseUrl` koja nije unaprijed postavljena
ostaje izričito nadjačavanje koje je zadao operater i ima prednost, dok se stari spremljeni unaprijed
postavljeni URL-ovi normaliziraju natrag prema regionalnoj matrici.

Time shema veze ostaje proširiva: još jedna regija može se dodati u razrješivač bez
stvaranja nove kartice pružatelja usluga ili promjene spremljenih ID-ova pružatelja usluga.

## Kompatibilnost i uvođenje

1. Dodajte razrješivač regionalnih krajnjih točaka i zadržite trenutačne globalne zadane postavke.
2. Upotrijebite dohvaćanje uživo regionalnog DashScope popisa `/models` za `alibaba`, njegov kompatibilni
   ID `alibaba-cn` i `qwen-cloud`. Njihovi odgovori najprije prolaze kroz filtar za generiranje teksta jer generička
   krajnja točka vraća i slikovne, video, audijske, ugradbene i druge modele koji nisu namijenjeni čavrljanju. `qwen-cloud`
   zatim primjenjuje održavani popis dopuštenih modela deklariran u svojem registru pružatelja. Alibaba Model Studio
   i Qwen Cloud zadržavaju zasebne uređene kataloge iako trenutačno dijele izvršne hostove.
3. Registrirajte `qwen-cloud-token-plan` s trenutačnim popisom dopuštenih tekstualnih modela za Token Plan.
4. Dodajte tipizirani odabir regije u dijaloške okvire za dodavanje/uređivanje veze.
5. Sakrijte dupliciranu karticu `alibaba-cn` i uključite njezine postojeće veze na stranicu pružatelja `alibaba`.
6. Zadržite mogućnost prilagođene zamjene krajnjih točaka za napredne implementacije i implementacije specifične za radni prostor.

Medijski modeli za Token Plan ostaju izvan kataloga za čavrljanje jer upotrebljavaju namjenske krajnje točke.
`wan2.7-image` i `wan2.7-image-pro` registrirani su u `open-sse/config/imageRegistry.ts`;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` i `happyhorse-1.1-r2v` registrirani su u
`open-sse/config/videoRegistry.ts`. Oba registra ponovno upotrebljavaju identitet veze
`qwen-cloud-token-plan` i njegove vjerodajnice specifične za regiju.

Standardni Qwen Cloud ima zasebne slikovne i video kataloge s naplatom prema potrošnji pod identitetom
`qwen-cloud`. Njegovi slikovni modeli su `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` i `z-image-turbo`. Njegovi video
modeli su `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` i
`wan2.7-videoedit`. Ti modeli ponovno upotrebljavaju samo standardnu vezu `qwen-cloud` i regionalnu
medijsku krajnju točku DashScope. Registri za Token Plan i naplatu prema potrošnji ne nasljeđuju niti spajaju
međusobne popise modela.

Identitet `bailian-coding-plan` također ima vlastite popise dopuštenih medijskih modela:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` i `qwen-image-2.0-pro` za generiranje
slika, kao i
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` i `happyhorse-1.1-r2v` za generiranje
videozapisa. Upotrebljava samo vezu Bailian Coding Plan i regionalnu krajnju točku Coding Plan.
Njegovi registri slika i videozapisa ne nasljeđuju niti se spajaju s bilo kojim pružateljem Qwen Cloud.

Standardni identitet `alibaba` ima zasebne popise dopuštenih slikovnih i video modela. Njegovi slikovni modeli su
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` i `wan2.6-t2i`. Njegovi dodani video modeli su `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` i `wan2.7-videoedit`. Ti modeli upotrebljavaju samo vezu Alibaba Model Studio
i njezinu odabranu regionalnu medijsku krajnju točku; ne dodaju se ni u jedan registar Coding Plan ili Qwen
Cloud.

Katalog za čavrljanje Qwen Cloud Token Plan slijedi popis dopuštenih tekstualnih modela plana Individual s potpuno podudarnim nizovima:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` i
`deepseek-v4-pro`. Stavke Wan i HappyHorse pripadaju zasebnim API-jima za generiranje slika/videozapisa.

Alibaba Token Plan izlaže istih šest trenutačnih ID-ova modela za generiranje teksta putem svoje krajnje točke
kompatibilne s Anthropicem. Njegova opcija Singapur pohranjuje postojeći ključ regije `global-sg`;
samo se oznaka prikazana korisniku razlikuje od obitelji pružatelja koje regiju nazivaju Global.

Standardni katalog za čavrljanje Qwen Cloud namjerno je uži od cjelovitog odgovora s tekstualnim modelima uživo. Njegov
održavani popis dopuštenih modela nalazi se u `open-sse/config/providers/registry/qwen-cloud/index.ts`; dohvaćanje
uživo vraća samo ID-ove prisutne i u odgovoru izvornog poslužitelja i na tom popisu registra.

Alibaba Model Studio slijedi isto pravilo presjeka uživo sa svojim neovisno održavanim
popisom dopuštenih modela u `open-sse/config/providers/registry/alibaba/index.ts`. Kompatibilni
pružatelj `alibaba-cn` ponovno upotrebljava taj katalog, dok dohvaćanje razrješava prema pekinškoj krajnjoj točki.
