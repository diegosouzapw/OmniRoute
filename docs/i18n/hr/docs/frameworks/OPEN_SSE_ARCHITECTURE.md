> **Ukratko**: `open-sse/` je temeljni mehanizam za strujanje koji pokreće svaki LLM zahtjev u OmniRouteu. Sadrži oko 1.400 datoteka koje implementiraju tijek obrade zahtjeva, izvršitelje, usluge, MCP poslužitelj i sloj za prevođenje formata. Ovaj vodič objašnjava kako se svi dijelovi međusobno povezuju.

**Izvor:** `open-sse/` (paket radnog prostora, oko 1.440 `.ts` datoteka koje nisu testne)

---

## Zašto zaseban paket radnog prostora?

`open-sse/` je **samostalan radni prostor** u OmniRoute monorepozitoriju iz nekoliko razloga:

1. **Ponovna upotrebljivost** — `open-sse` se objavljuje kao `@omniroute/open-sse` na npm-u, pa ga drugi projekti mogu koristiti neovisno
2. **Jasne granice** — mehanizam za strujanje odvojen je od sloja korisničkog sučelja i baze podataka specifičnog za OmniRoute
3. **Performanse** — mehanizam nema ovisnosti o Next.js-u, što omogućuje brže hladno pokretanje u CLI i serverless okruženjima
4. **Verzioniranje** — `open-sse` može objavljivati izdanja vlastitim tempom

```json
// package.json
"workspaces": ["open-sse"]
```

## Tijek obrade zahtjeva

Svaki LLM zahtjev prolazi kroz **tijek obrade od 5 faza**:

```
                              ┌──────────────┐
   HTTP zahtjev                │  1. USMJERI  │   razrješavanje kombinacije, odabir modela
   (Next.js ruta)              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  2. PREVEDI  │   pretvorba formata (OpenAI ↔ Claude ↔ Gemini)
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  3. IZVRŠI   │   izvršitelj pružatelja, HTTP, ponovni pokušaj, prekidač
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  4. STRUJANJE│   SSE transformacija, povratni pritisak
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  5. ZABILJEŽI│   praćenje upotrebe, zapisnik poziva, klasifikacija pogrešaka
                              └──────┬───────┘
                                     │
                                     ▼
                              HTTP odgovor (SSE ili JSON)
```

### Faza 1: Usmjeravanje (services/combo.ts)

**Ulazna točka**: `handleComboChat()` u `services/combo.ts`

Razrješava zahtjev u konkretan skup `(provider, model, account, credentials)`:

- Pronalazi kombinaciju prema ID-u (ili izrađuje virtualnu kombinaciju za modele `auto/*`)
- Primjenjuje strategiju usmjeravanja (prioritetnu, ponderiranu, kružnu itd.)
- Filtrira pružatelje koji nisu ispravni (prekidač strujnog kruga)
- Odabire sljedeće dostupno odredište

Za modele `auto/*` ova faza također:

- Pokreće algoritam **bodovanja prema 16 čimbenika** (`services/autoCombo/`)
- Odabire par `provider+model` na temelju ispravnosti, cijene, latencije itd.

### Faza 2: Prevođenje (translator/)

Ako se izvorni format (npr. OpenAI) razlikuje od ciljnog formata (npr. Claude), zahtjev se **prevodi**:

- Sistemski prompt → sistemska poruka
- Definicije alata → format alata specifičan za pružatelja
- Parametri zaključivanja/razmišljanja → ekvivalenti specifični za pružatelja
- Normalizacija uloga poruka (`developer` → `system` za sustave koji nisu OpenAI)

`translator/index.ts` izlaže:

```ts
translateRequest(body, sourceFormat, targetFormat): TranslatedRequest
needsTranslation(source, target): boolean
```

### Faza 3: Izvršavanje (executors/)

**Ulazna točka**: `getExecutor(providerId).execute(request, options)`

Svi pružatelji koriste `DefaultExecutor` (`executors/default.ts`) putem pričuvnog mehanizma tvornice `getExecutor()`. Izvršitelj:

- Izrađuje URL nadređene usluge (`buildUrl()`)
- Dodaje zaglavlja specifična za pružatelja (`buildHeaders()`)
- Transformira tijelo zahtjeva (`transformRequest()`)
- Šalje HTTP zahtjev uz ponovne pokušaje i eksponencijalno povećavanje razmaka
- Po potrebi upravlja osvježavanjem autentikacije (OAuth pružatelji)

Svi izvršitelji proširuju `BaseExecutor` (`executors/base.ts`, 1170 redaka koda), koji pruža:

- Zajedničku logiku ponovnih pokušaja
- Integraciju s proxyjem
- Integraciju s prekidačem strujnog kruga
- Priključke za bilježenje upotrebe

### Faza 4: Strujanje (utils/stream.ts)

Za strujane odgovore izvršitelj vraća **ReadableStream**. Rukovatelj:

- Prosljeđuje podatke kroz SSE transformaciju (`createSSETransformStreamWithLogger`)
- Primjenjuje periodične signalne poruke radi otkrivanja prekinutih veza
- Elegantno obrađuje prekid veze klijenta (`pipeWithDisconnect`)
- Transformira SSE → JSON za klijente koji ne upotrebljavaju strujanje

Za odgovore bez strujanja izvršitelj vraća raščlanjeni JSON objekt koji se prosljeđuje bez promjena.

### Faza 5: Bilježenje (services/usage.ts)

Nakon odgovora (uspješnog ili neuspješnog) bilježi se upotreba:

- `prompt_tokens`, `completion_tokens`, `cached_tokens` iz odgovora
- `cost_usd` izračunat iz podataka o cijenama
- `latency_ms`, `status`, `error_class` u slučaju neuspjeha
- Spremljeno u tablicu `usage_history`

Artefakti zapisnika poziva (ako su omogućeni) zapisuju se u `${DATA_DIR}/call_logs/`.

## Dubinski uvid u ključne datoteke

### chatCore.ts (5977 redaka)

**Glavni rukovatelj zahtjevima**. Unatoč svojoj veličini, ima jasnu strukturu:

```ts
// Pseudo-struktura datoteke chatCore.ts
export async function handleChat(request: NextRequest) {
  // 1. Autentifikacija + CORS
  await authenticateRequest(request);
  applyCorsHeaders(response);

  // 2. Validacija tijela zahtjeva
  const body = await parseRequestBody(request);

  // 3. Otkrivanje formata + prevođenje
  const sourceFormat = detectFormat(request);
  const targetFormat = getTargetFormat(providerId);
  if (needsTranslation(sourceFormat, targetFormat)) {
    body = translateRequest(body, sourceFormat, targetFormat);
  }

  // 4. Combo usmjeravanje
  const targets = await resolveComboTargets(comboId, body);
  for (const target of targets) {
    try {
      const result = await executeOnTarget(target, body);
      await recordUsage(result);
      return result;
    } catch (err) {
      // Nastavi na sljedeći cilj
    }
  }

  // 5. Hitan rezervni mehanizam
  return await emergencyFallback(body);
}
```

Iako je jedna ogromna funkcija, organizirana je u **komentirane sekcije** koje odgovaraju cjevovodu od 5 faza.

### combo.ts (4456 redaka koda)

**Mehanizam usmjeravanja** koji razrješava combo u poredane ciljeve.

```ts
// services/combo.ts
export async function handleComboChat(body, comboId): Promise<ChatResult> {
  const targets = await resolveComboTargets(comboId, body);
  for (const target of targets) {
    try {
      return await handleSingleModel(target, body);
    } catch (err) {
      log.warn("target failed, trying next", { target, err });
    }

  throw new ComboExhaustedError("All targets failed");
}
```

````
## Izvršitelji (150 modula)

Uglavnom jedna datoteka po pružatelju. Sve klase izvršitelja nasljeđuju `BaseExecutor` i nadjačavaju ono što se razlikuje; ostali moduli su pomoćnici po pružatelju (sheme alata, fetch/TTS adapteri, rukovatelji posebnostima).

### Uobičajeni obrasci

Pružatelji se razrješavaju putem `getExecutor(providerId)`, koji vraća konfiguriranog izvršitelja. Pružatelji kompatibilni s OpenAI/Anthropic koriste `DefaultExecutor` (`executors/default.ts`). Ponašanje specifično za pružatelja (osnovni URL, zaglavlja autentikacije, verzija API-ja) konfigurira se u `open-sse/config/providers/`, dok se transformacije tijela zahtjeva obrađuju u `open-sse/translator/`.

**Prilagođeni URL** postavlja se kroz konfiguraciju pružatelja:

```ts
// Konfiguracija pružatelja u open-sse/config/providers/
export default {
  id: "together",
  baseURL: "https://api.together.xyz/v1/chat/completions",
}
````

**Prilagođena autentikacija** obrađuje se kroz konfiguraciju autentikacije registra pružatelja (API ključ, OAuth, profili zaglavlja).

Transformacije **prilagođenog tijela zahtjeva** (npr. Anthropic koji odvaja `system` od `messages`) registriraju se po pružatelju u `open-sse/translator/`.

````

### Tvornica izvršitelja

`executors/index.ts` izvozi `getExecutor(providerId)`:

```ts
import { getExecutor } from "@omniroute/open-sse/executors";

const executor = getExecutor("anthropic");
const result = await executor.execute({
  model: "claude-sonnet-4-5",
  messages: [...],
});
````

Razrješavanje ide kroz `ExecutorRegistry` (`executors/registry.ts`): svaki specijalizirani izvršitelj deklariran je u ugrađenoj tablici `executors/index.ts` i registriran putem `registerExecutor(alias, instance)` pri učitavanju modula; `getExecutor()` konzultira registar i vraća se na memoiziranog `DefaultExecutor` za svakog pružatelja bez specijaliziranog unosa. Potpuno mapiranje alias → izvršitelj karakterizira golden test `tests/unit/executor-map-golden.test.ts`.

## Prevoditelji

Prevodite između **3 formata**: OpenAI, Anthropic, Gemini te novog Responses API-ja.

### Kada se izvodi prevođenje

```ts
import { needsTranslation, translateRequest } from "@omniroute/open-sse/translator";

if (needsTranslation(sourceFormat, targetFormat)) {
  body = translateRequest(body, sourceFormat, targetFormat);
}
```

Uobičajena prevođenja:

- `OpenAI → Anthropic`: zasebno polje `system`, zaglavlje `x-api-key`
- `OpenAI → Gemini`: `contents` umjesto `messages`, `systemInstruction`
- `OpenAI → Responses API`: polje `input`, stanje `previous_response_id`

### Obrađeni rubni slučajevi

- Uloga `developer` → `system` za sustave koji nisu OpenAI
- Uloga `system` → spaja se s prvom korisničkom porukom za GLM/ERNIE
- `json_schema` → Geminijevi `responseMimeType` + `responseSchema`
- `tools` → format alata specifičan za pružatelja
- Parametri razmišljanja (o1, Claude) → ekvivalenti specifični za pružatelja

## MCP poslužitelj

`open-sse/mcp-server/` implementira poslužitelj za **Model Context Protocol**:

- **110 alata** (upravljanje pružateljima, kombinacije, memorija, predmemorija, kompresija, proxy, vještine, gamifikacija, dodaci, Notion, Obsidian, lokalni korpus)
- **3 prijenosna mehanizma**: stdio, SSE, Streamable HTTP
- **33 opsega** za preciznu autorizaciju

### Registracija alata

Alati se registriraju kao samostalne datoteke u `open-sse/mcp-server/tools/`, a svaka izvozi naziv, shemu, rukovatelja i opseg:

```ts
// open-sse/mcp-server/tools/getHealth.ts
import { z } from "zod";
export default {
  name: "omniroute_get_health",
  description: "Dohvati snimku stanja sustava",
  scope: "read:health",
  inputSchema: z.object({}),
  handler: async (_args, ctx) => {
    return await getSystemHealth();
  },
};
```

### Prijenosni mehanizmi

```ts
// stdio (uporaba putem CLI-ja)
startMcpStdio(server);

// SSE (strujanje temeljeno na HTTP-u)
startMcpSse(server, port);

// Streamable HTTP (suvremeni MCP)
startMcpStreamable(server, port);
```

### Autorizacija

Svaki poziv alata prolazi kroz provjere opsega (`open-sse/mcp-server/auth/`):

```ts
if (!hasScope(apiKey, "providers:read")) {
  throw new Error("Nedovoljan opseg");
}
```

## Transformatori

`open-sse/transformer/` pretvara između formata **Chat Completions** i **Responses API**.

### Zašto zaseban transformator?

Responses API novi je OpenAI-jev format s **razgovorima koji čuvaju stanje** (`previous_response_id`). Kada klijent pošalje Responses zahtjev, OmniRoute:

1. Interno pretvara Responses → Chat Completions
2. Šalje pružatelju (bilo kojem pružatelju koji podržava Chat Completions)
3. Pretvara odgovor natrag u Responses format
4. Strujanjem šalje pretvoreni odgovor klijentu

Transformator (`transformer/responsesTransformer.ts`) pruža:

```ts
createResponsesApiTransformStream(): TransformStream
```

Time se obrađuju:

- Događaji `response.output_item.added`
- Događaji `response.output_text.delta`
- Događaj `response.completed`
- Mapiranje poziva alata (`function_call` ↔ `tool_calls`)

```ts
interface ProviderConfig {
```

## Ograničenja performansi

Mehanizam usmjeravanja ima strogo definirane ciljeve performansi:

| Operacija                                                   | Cilj  | Mjerenje                           |
| ----------------------------------------------------------- | ----- | ---------------------------------- |
| Razrješavanje kombinacije                                   | <10ms | Za 50 ciljeva                      |
| Provjera ograničenja stope                                  | <1ms  | Spremnik tokena u memoriji         |
| Zamjenski model iz porodice                                 | <5ms  | Predmemorirane definicije porodica |
| Prosljeđivanje zahtjeva za usmjeravanje                     | <2ms  | Kritična putanja                   |
| **Bez blokirajućeg I/O-a u kritičnoj putanji usmjeravanja** | —     | Sve je asinkrono                   |

## Antipatterni

❌ **Sinkroni pozivi bazi podataka u `combo.ts`** — unaprijed izračunajte i predmemorirajte
❌ **Logika ponovnih pokušaja u rukovateljima** — koristite `retry()` iz usluge otpornosti
❌ **Izravan pristup konfiguraciji pružatelja** — koristite gettere registra `providerRegistry`
❌ **Fiksno kodirani lanci zamjenskih opcija** — definirajte ih u `modelFamilyFallback.ts`
❌ **Promjene stanja između istodobnih zahtjeva** — koristite samo kontekst ograničen na zahtjev

## Dodavanje nove komponente

### Dodavanje nove usluge

1. Izradite `open-sse/services/[serviceName].ts` s jasno usmjerenom odgovornošću
2. Izvezite glavnu funkciju rukovatelja i sve konstante
3. Dodajte jedinične testove u `tests/unit/services/[serviceName].test.mjs`
4. Integrirajte u cjevovod zahtjeva u `handlers/chatCore.ts` (ako je povezano s usmjeravanjem)
5. Ažurirajte logiku usmjeravanja u `combo.ts` ako usluga utječe na odabir cilja
6. Dokumentirajte u ovoj datoteci

### Dodavanje novog izvršitelja

1. Izradite `open-sse/executors/[provider].ts` koji proširuje `BaseExecutor`
2. Registrirajte ga u `config/providerRegistry.ts`
3. Dodajte ga u tvornicu `executors/index.ts`
4. Dodajte jedinične testove za izvršitelja
5. Dokumentirajte u `docs/architecture/ARCHITECTURE.md`

### Dodavanje novog MCP alata

1. Izradite ili ažurirajte `open-sse/mcp-server/tools/[category]Tools.ts`
2. Definirajte Zod shemu za ulazne podatke
3. Registrirajte alat u `mcp-server/index.ts`
4. Dodajte ga u matricu opsega u `mcp-server/auth/`
5. Dodajte jedinične testove
