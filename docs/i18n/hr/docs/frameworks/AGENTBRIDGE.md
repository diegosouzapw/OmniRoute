AgentBridge je MITM (Man-in-the-Middle, „čovjek u sredini”) proxy poslužitelj OmniRoutea koji presreće HTTPS promet IDE AI agenata i preusmjerava ga kroz objedinjeni mehanizam usmjeravanja OmniRoutea. Podržava **10 IDE agenata** — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code i Trae (u fazi istraživanja) — što AgentBridge čini MITM proxy poslužiteljem s najširom podrškom za AI pomoćnike za programiranje na tržištu.

**Lokacija nadzorne ploče:** `/dashboard/tools/agent-bridge`
**Grupa na bočnoj traci:** Alati (nakon Cloud Agents)
**Pogledajte i:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — pratite sav presretnuti promet u stvarnom vremenu; `docs/security/MITM-TPROXY-DECRYPT.md` (git; ne kompilira se u `/docs`) — način transparentnog presretanja i dešifriranja Linux TPROXY kojim upravlja ruta `/api/tools/agent-bridge/tproxy`.

## §1 Pregled

### Što je AgentBridge?

Kada IDE agent (npr. GitHub Copilot, Cursor, Claude Code) uputi API poziv, izravno se povezuje s nadređenim AI pružateljem usluge (OpenAI, Anthropic itd.). AgentBridge transparentno presreće tu vezu na TLS razini — bez potrebe za bilo kakvom promjenom konfiguracije agenta — i preusmjerava zahtjev kroz OmniRoute.

To znači da možete:

- **Preusmjeriti bilo kojeg agenta prema bilo kojem pružatelju usluge**: Copilot komunicira s OpenAI-jem? Preusmjerite ga na Anthropic Claude, Gemini ili bilo kojeg od 352 pružatelja usluge dostupna u OmniRouteu.
- **Primijeniti mapiranja modela**: `gemini-3-flash` → `claude-sonnet-4.7` transparentno na razini rukovatelja.
- **Promatrati sav promet agenata**: svaki presretnuti zahtjev objavljuje se u [Inspektoru prometa](./TRAFFIC_INSPECTOR.md).
- **Primijeniti otpornost OmniRoutea**: kombinirano usmjeravanje, prekidači strujnog kruga, pričuvni mehanizmi i praćenje troškova funkcioniraju i za promet IDE agenata.

## §2 Arhitektura

### 2.1 Pregled komponenti

```
IDE agent (VS Code / Cursor / itd.)
    │  HTTPS (priključak 443)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← DNS preusmjeravanje
    │
    ▼
src/mitm/server.cjs  (priključak 443, podređeni CJS proces)
    │  razrješava odredište prema SNI zaglavlja Host
    │  generira TLS certifikat za svaki SNI, potpisan AgentBridge CA-om
    ├── Podudaranje s popisom zaobilaženja? → TCP prosljeđivanje (bez dešifriranja)
    ├── Podudaranje s odredištem? → fetch → usmjerivač OmniRoute (priključak 20128)
    │       └── handler.intercept() — TypeScript
    │               ├── maskSecrets() nad tijelom/zaglavljima zahtjeva
    │               ├── TrafficBuffer.push() — objavljuje u Inspektoru prometa
    │               └── fetchRouter() → /v1/chat/completions
    └── Nema podudaranja? → TCP prosljeđivanje (bez dešifriranja)
```

### 2.2 MITM poslužitelj (`src/mitm/server.cjs`)

Temeljni MITM poslužitelj izvodi se kao podređeni Node.js CJS proces (kako bi se izbjeglo prepisivanje postojeće CJS baze koda). On:

- Osluškuje na priključku 443 (zahtijeva ovlasti ili `authbind`/`setcap`)
- Prima CONNECT tunele od operacijskog sustava (putem DNS preusmjeravanja u `/etc/hosts`)
- Generira TLS certifikate za svaki SNI, potpisane AgentBridge CA-om (`DATA_DIR/mitm/ca.crt`)
- Razrješava ciljnog agenta prema zaglavlju Host putem registra `targets/index.ts`
- Prosljeđuje sloju rukovatelja u TypeScriptu putem HTTP-a na `http://127.0.0.1:20128`

`TARGET_HOSTS` učitava se iz `DATA_DIR/mitm/targets.json` (koji `targets/index.ts` zapisuje pri pokretanju), čime se omogućuju dinamička ažuriranja bez ponovnog pokretanja CJS poslužitelja.

> **Model korijenskog CA-a (#6684).** Prethodno opisani model s certifikatom za svaki SNI,
> potpisanim CA-om, trajno je pohranjeni model korijenskog CA-a dodan u #6684 (`src/mitm/cert/rootCa.ts` +
> `src/mitm/_internal/rootCaShim.cjs`, koji ponovno upotrebljava kriptografiju CA-a i krajnjih certifikata već
> dokazanu za TPROXY u `src/mitm/tproxy/dynamicCert.ts`) — on zamjenjuje
> stariji pojedinačni statički samopotpisani krajnji certifikat (`src/mitm/cert/generate.ts`, koji je i dalje
> ograničen samo na antigravity hostove) na koji upućuje sam par `server.crt`/`server.key`
> na disku. **Ponašanje migracije**: nova instalacija (bez prethodnog
> `server.crt`) automatski dobiva model korijenskog CA-a; instalacija koja već
> vjeruje starom statičkom krajnjem certifikatu nastavlja ga upotrebljavati sve dok operater ne postavi
> `MITM_ROOT_CA_ENABLED=true` i ponovno pokrene most (`src/mitm/cert/migration.ts`
> čista je funkcija odlučivanja — pouzdani MITM CA koji može potpisati krajnji certifikat za
> **bilo koji** host znatno je moćniji od starog krajnjeg certifikata s fiksnim SAN-om, pa
> prelazak nikada nije tih za instalaciju koja mu već vjeruje). CA certifikat instalira se
> u isti utor `omniroute-mitm.crt` spremišta pouzdanih certifikata koji je upotrebljavao stari krajnji certifikat
> (`cert/install.ts::installCaCert`) — nije potrebno čišćenje dvostrukog povjerenja.

### 2.3 Osnovni rukovatelj (`src/mitm/handlers/base.ts`)

Svi rukovatelji agenata proširuju `MitmHandlerBase`:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // Zaštićene pomoćne metode: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

Svaki rukovatelj poziva `hookBufferStart()` prije prosljeđivanja i `hookBufferUpdate()` nakon dovršetka. Time se unosi `InterceptedRequest` zapise u `globalTrafficBuffer` (pogledajte [Inspektor prometa](./TRAFFIC_INSPECTOR.md) §4).

### 2.4 Registar odredišta (`src/mitm/targets/`)

Svaki agent ima deklarativnu datoteku odredišta:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

Registar (`targets/index.ts`) izvozi `ALL_TARGETS` i pri pokretanju generira `DATA_DIR/mitm/targets.json`.

### 2.5 Prosljeđivanje i popis zaobilaženja (`src/mitm/passthrough.ts`)

**Popis zaobilaženja** (provjerava se prvi i ima prednost pred podudaranjem s odredištem):

- Zadani uzorci: bankovni hostovi, `.gov.`, pružatelji OAuth/SSO usluga (Okta, Auth0) itd.
- Korisnički uzorci: pohranjeni u tablici baze podataka `agent_bridge_bypass`
- Zaobiđeni hostovi dobivaju transparentni TCP tunel — TLS se **nikada ne dešifrira**

**Zadano prosljeđivanje** (nema podudaranja s odredištem i nije na popisu zaobilaženja):

- Također dobiva TCP tunel — veze se nikada ne prekidaju
- Sprječava AgentBridge da ometa opći sistemski HTTPS promet

Redoslijed prioriteta usmjeravanja:

```
popis zaobilaženja → podudaranje s odredištem → prosljeđivanje
```

### 2.6 Uzvodni CA certifikat (`src/mitm/upstreamTrust.ts`)

Za poslovna mrežna okruženja s prilagođenim CA-om:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

Kada je postavljeno, konfigurira globalni dispečer paketa `undici` dodatnim CA certifikatom, čime se AgentBridgeu omogućuje pristup uzvodnim pružateljima putem poslovnih proxy poslužitelja za TLS terminaciju.

### 2.7 Maskiranje tajni (`src/mitm/maskSecrets.ts`)

Neovisni clean-room skener primjenjuje se na tijela zahtjeva i zaglavlja s vjerodajnicama
**prije** nego što uđu u međuspremnik Inspektora prometa ili bilo koji zapisnik. Izvodi jedan linearni prolaz:

- Tokeni s prefiksom `sk-` / `ak-` / `pk-` (u stilu OpenAI-ja/Anthropica)
- Vjerodajnice RFC 6750 `Authorization: Bearer <token>`, uz prioritet cijelog tokena
- Generički dugi neprozirni tokeni (≥40 znakova), uključujući oblike s točkama i dopunom

`sanitizeHeaders()` pretvara zadržane nazive u mala slova, deterministički spaja vrijednosti polja, odbacuje
zajednički popis zabranjenih hop-by-hop/okvirnih zaglavlja (uključujući proxy autentifikaciju), u potpunosti redigira `cookie` i
`set-cookie` te vrijednosti vjerodajnica prosljeđuje skeneru.

## §3 Postavljanje

### 3.1 Pokretanje/zaustavljanje MITM poslužitelja

Upotrijebite karticu AgentBridge Server na `/dashboard/tools/agent-bridge`:

| Radnja                         | Opis                                                                             |
| ------------------------------ | -------------------------------------------------------------------------------- |
| Pokreni poslužitelj            | Pokreće `src/mitm/server.cjs` na portu 443                                       |
| Zaustavi poslužitelj           | Kontrolirano zaustavlja podređeni proces                                         |
| Ponovno pokreni poslužitelj    | Zaustavlja i ponovno pokreće poslužitelj (primjenjuje promjene ciljeva)          |
| Postavi certifikat kao pouzdan | Instalira `DATA_DIR/mitm/ca.crt` u spremište pouzdanih certifikata OS-a          |
| Preuzmi certifikat             | Preuzima `ca.crt` radi ručne instalacije                                         |
| Ponovno generiraj certifikat   | Stvara novi par CA ključeva (svi postojeći certifikati agenata postaju nevažeći) |

### 3.2 Postavljanje certifikata kao pouzdanog

OS mora smatrati AgentBridge CA certifikat pouzdanim prije nego što IDE-ovi prihvate MITM vezu.

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Keychain):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

Možete upotrijebiti i gumb „Postavi certifikat kao pouzdan” na nadzornoj ploči (pokreće odgovarajuću naredbu za vaš OS, uz upit za sudo ako je potreban).

#### IDE-ovi temeljeni na Electronu zanemaruju spremište pouzdanih certifikata OS-a (`NODE_EXTRA_CA_CERTS`)

Neki IDE-ovi — osobito **Antigravity IDE** i druge aplikacije izvedene iz Electrona / VS Codea — uključuju
vlastito Node.js izvršno okruženje koje **ne provjerava spremište pouzdanih certifikata OS-a** za odlazne
`fetch`/HTTPS zahtjeve. Postavljanje CA certifikata kao pouzdanog na razini OS-a/NSS-a dovoljno je za izvorni **pozadinski sustav**
IDE-a (npr. Go jezični poslužitelj, koji upotrebljava paket CA certifikata OS-a), ali će
**Electron sučelje** i dalje imati TLS pogrešku — to se očituje kao da je korisnik _odjavljen_ ili se prikazuje
_"pogreška veze"_, iako MITM zapisnik pokazuje da inicijalizacijski pozivi pozadinskog sustava vraćaju `200`. Potrebna su
dva koraka i oba su važna:

1. Izričito usmjerite izvršno okruženje na CA certifikat:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **Pokrenite IDE iz te ljuske.** Pokretanje s ikone na radnoj površini / Docka / izbornika Start
   **ne** nasljeđuje varijable izvezene u ljusci, a `~/.config/environment.d/*.conf` primjenjuje se tek nakon
   nove prijave u grafičko okruženje. Najprije potpuno zatvorite IDE — Electronovo zaključavanje jedne instance znači da drugo
   pokretanje samo prebacuje fokus na postojeći proces, a novo se okruženje zanemaruje.

Prethodni korak postavljanja pouzdanosti na razini OS-a + NSS-a i dalje je potreban (Chromiumov mrežni stog, koji se upotrebljava u nekim
postupcima autentikacije, čita korisničko NSS spremište i ima vlastita statična sidra za `*.googleapis.com` koja
lokalno pouzdani CA nadjačava). `NODE_EXTRA_CA_CERTS` dodatno pokriva Nodeov put `fetch` zahtjeva.

### 3.3 DNS usmjeravanje

Za svakog agenta čiji promet želite presretati njegovi API hostovi moraju se razrješavati na `127.0.0.1`. AgentBridge automatski upravlja unosima u `/etc/hosts` kada u Čarobnjaku za postavljanje uključite ili isključite DNS za agenta.

Primjeri unosa u `/etc/hosts` za GitHub Copilot:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 Mapiranje modela

Upotrijebite tablicu mapiranja modela na kartici svakog agenta kako biste definirali mapiranja izvornog → ciljnog modela:

| Izvorni model (izvorni za agenta) | Ciljni model (OmniRoute) |
| --------------------------------- | ------------------------ |
| `gpt-4o`                          | `claude-sonnet-4.7`      |
| `*` (zamjenski znak)              | `claude-haiku-4.7`       |

Zamjenski znak `*` mapira svaki neprepoznati model na navedeni cilj. Sprema se u tablicu `agent_bridge_mappings`.

> **Savjet — otkrijte stvarne ID-ove modela agenta.** IDE može slati nazive modela koji se razlikuju od
> oznaka u njegovu korisničkom sučelju i koji se mijenjaju između glavnih verzija. Primjerice, **Antigravity 2** šalje
> `gemini-3.1-pro-low`, `gemini-pro-agent` i `gemini-3.1-flash-lite` putem mreže — a ne
> `gemini-2.5-pro` prikazan u starijoj dokumentaciji. Pošaljite jednu poruku u razgovoru bez odgovarajućeg mapiranja: MITM
> će u zapisnik zabilježiti točnu dolaznu vrijednost `model:` i propustiti zahtjev. Mapirajte tu doslovnu vrijednost, nakon čega
> će sljedeći zahtjev biti presretnut i usmjeren na vaš cilj.

### 3.5 Obavijest o riziku

AgentBridge presreće vjerodajnice (OAuth tokene, API ključeve) koje IDE upotrebljava za autentikaciju kod nadređenih pružatelja usluga. One su **maskirane prije zapisivanja u zapisnik** (pogledajte §2.7), ali su vidljive MITM sloju OmniRoutea. Pri prvoj aktivaciji svakog agenta prikazuje se modalni prozor s obavijesti o riziku koji se može odbaciti.

### 3.6 Održavanje i dijagnostika

Nadzorna ploča sadrži karticu **Održavanje i dijagnostika** (`AgentBridgeMaintenanceCard`, u `src/app/(dashboard)/dashboard/tools/agent-bridge/components/`) koja prikazuje operativne MITM rute koje prethodno nisu imale korisničko sučelje. > **Ukloni CA**, umjesto da se automatski izvršava pri zaustavljanju.

### 3.7 Uvoz/izvoz prijenosne konfiguracije

AgentBridge može serijalizirati stanje koje **operater može prilagoditi** u verzionirani JSON objekt kako bi se postava mogla replicirati na više računala. Serijalizator je `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`), a validira ga `AgentBridgeConfigSchema`.

Izvoz uključuje točno tri dijela (ugrađene zadane vrijednosti namjerno se **NE** izvoze kako ih uvoz nikada ne bi duplicirao niti bio u sukobu s njima):

| Polje            | Izvor                                                                     | Napomene                                                                  |
| ---------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `bypassPatterns` | korisnički definirani obrasci zaobilaženja (`agent_bridge_bypass`)        | zadani obrasci bank/gov/okta nisu uključeni                               |
| `customHosts`    | prilagođena glavna računala Traffic Inspectora (`inspector_custom_hosts`) | svako: `{ host, kind: "llm"\|"app"\|"custom", label? }`                   |
| `agentMappings`  | mapiranja modela po agentu (`agent_bridge_mappings`)                      | `{ [agentId]: [{ source, target }] }` za svakog agenta koji ima mapiranja |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**Ponašanje pri uvozu** (`POST /api/tools/agent-bridge/config`): obrasci zaobilaženja i mapiranja po agentu **zamjenjuju se u cijelosti**; prilagođena glavna računala dodaju se **idempotentno** (`INSERT OR IGNORE`). Odgovor navodi koliko je stavki svake vrste primijenjeno:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

Što **NIJE** u konfiguraciji: stanje rada poslužitelja, putanje certifikata, DNS stanje pojedinačnih agenata, putanja nadređenog CA certifikata i postavke TPROXY-ja — to su stanja glavnog računala/izvođenja, a ne prenosive postavke.

## §5 Sigurnost

### Primijenjena stroga pravila

| Pravilo                                 | Primjena                                                                                                    |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| **#12** `sanitizeErrorMessage`          | Sve pogreške rukovatelja sanitiziraju se prije odgovora ili unosa u međuspremnik                            |

### Popis zaobilaženja za osjetljive hostove

Popis zaobilaženja osigurava da se promet financijskih institucija, pružatelja usluga OAuth/SSO i drugih osjetljivih hostova **nikada ne dešifrira**. Njihov TLS promet prolazi kao transparentni TCP tunel — OmniRoute nikada ne vidi nešifrirani sadržaj.

Zadani obrasci zaobilaženja uključuju:

- `*.bank.*`, `*.gov.*` (financije/državna uprava)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/identitet)
- `*.apple.com`, `*.icloud.com` (Appleove sistemske usluge)

Obrasci zaobilaženja koje je dodao korisnik pohranjuju se u tablici `agent_bridge_bypass` i imaju prednost pred svime ostalim.

### Maskiranje tajnih podataka

Primjenjuje se `maskSecrets()` iz `src/mitm/maskSecrets.ts`:

- Na svako tijelo zahtjeva prije `TrafficBuffer.push()`
- Na svako zaglavlje prije zapisivanja ili emitiranja

Obrasci: tokeni s prefiksom `sk-`/`ak-`/`pk-`, tokeni `Bearer` i generički tokeni duljine ≥40 znakova.

### Certifikat nadređenog CA-a

Kada je postavljen `AGENTBRIDGE_UPSTREAM_CA_CERT`, datoteka se čita pri pokretanju. Ako putanja postoji, ali datoteku nije moguće pročitati, AgentBridge zapisuje jasnu pogrešku i odbija se pokrenuti (čime se sprječavaju neprimjetni TLS kvarovi u korporativnim okruženjima).

### Poznata ograničenja

- **Port 443 zahtijeva privilegije**: Na Linuxu AgentBridge zahtijeva `setcap 'cap_net_bind_service=+ep'` na binarnoj datoteci Nodea ili pokretanje putem `authbind`. Čarobnjak za postavljanje prikazuje upute specifične za operacijski sustav.
- **Potrebno je ponovno pokretanje IDE-a**: Nakon preusmjeravanja DNS-a IDE se mora ponovno pokrenuti kako bi novo razrješavanje hosta stupilo na snagu.
- **Čvrsto kodirani OAuth tokeni**: Neki agenti (Kiro, Antigravity) lokalno pohranjuju OAuth tokene za osvježavanje. Oni su transparentni AgentBridgeu — on vidi token `Bearer` u svakom zahtjevu, koji se maskira prije zapisivanja.
- **Electron sučelja zahtijevaju `NODE_EXTRA_CA_CERTS`**: IDE-ovi čije se sučelje izvodi u ugrađenom Node/Electron izvršnom okruženju zanemaruju OS/NSS spremište pouzdanih certifikata i moraju se pokrenuti iz ljuske s postavljenim `NODE_EXTRA_CA_CERTS` (pogledajte §3.2). Simptom kada nedostaje: pozadinski sustav IDE-a autentificira se (MITM prikazuje odgovore `200`), ali korisničko sučelje ostaje odjavljeno.
- **Višestruke instalacije istog IDE-a neovisne su**: sistemska instalacija (npr. `/usr/share/antigravity/antigravity`) i korisnička lokalna instalacija „Full” (npr. `~/AntigravityIDE_Full/antigravity-ide`) zasebni su procesi s vlastitim izvršnim okruženjima — svaki se mora ponovno pokrenuti s umetnutim CA-om. Prije ponovnog pokretanja utvrdite koja je instalacija pokrenuta prema putanji njezine binarne datoteke.
- **Identitet određuje sistemski prompt agenta, a ne usmjereni model**: kada model agenta ponovno mapirate na drugog pružatelja, odgovor i dalje navodi izvorni identitet agenta (npr. Antigravity odgovara „Pokreće me Gemini”) jer IDE to umeće u sistemski prompt. Stvarni pozadinski sustav potvrdite u `call_logs` / `proxy_logs` (`provider`, `model`, `target_format`), a ne tako da pitate model tko je.

## §6 Rješavanje problema

### Sukob na priključku 443

Ako neki drugi proces već sluša na priključku 443 (web-poslužitelj, VPN itd.):

```bash
lsof -i :443          # pronađite proces
sudo fuser -k 443/tcp  # prisilno zaustavite proces (upotrebljavajte oprezno)
```

Alternativno, konfigurirajte neprivilegirani priključak u postavkama AgentBridgea i postavite pravila preusmjeravanja za `iptables` / `pf`.

### Certifikat nije pouzdan

Ako IDE prikazuje TLS pogreške nakon pokretanja AgentBridgea:

1. Provjerite je li certifikat instaliran: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) ili `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. Neke aplikacije održavaju vlastito spremište pouzdanih certifikata (Firefox, Chrome na Linuxu). Ponovno pokrenite „Trust Cert” i provjerite spremište certifikata specifično za NSS/Firefox.
3. Ponovno pokrenite IDE nakon označavanja certifikata kao pouzdanog — aktivne TLS sesije upotrebljavaju staro stanje pouzdanosti.

### IDE je odjavljen / „pogreška veze” unatoč pouzdanom CA-u

Simptom: nakon preusmjeravanja DNS-a i označavanja CA-a kao pouzdanog, IDE temeljen na Electronu (npr. Antigravity)
otvara se **odjavljen** ili prikazuje pogrešku autentifikacije/veze, iako MITM zapisnik pokazuje da
pozivi za inicijalizaciju (`loadCodeAssist`, `fetchAvailableModels`, …) vraćaju `200`.

Uzrok: **ugrađeno izvršno okruženje Node/Electron IDE-a zanemaruje spremište pouzdanih certifikata operacijskog sustava**. Izvorna
pozadinska komponenta (poslužitelj jezika Go) vjeruje CA-u operacijskog sustava i autentificira se, ali Electronovo sučelje
ne vjeruje — stoga korisničko sučelje smatra da nije povezano s mrežom.

Rješenje (oba koraka): izvezite `NODE_EXTRA_CA_CERTS=<ca.crt>` **i ponovno pokrenite IDE iz te
ljuske**, a ne putem ikone na radnoj površini. Najprije potpuno zatvorite IDE — Electronovo zaključavanje jedne instance znači
da drugo pokretanje samo prebacuje fokus na postojeći proces, a novo se okruženje zanemaruje. Pogledajte §3.2.
To odgovara otvorenoj prijavi u izvornom projektu u kojoj samostalni agent radi putem MITM-a, ali IDE
varijanta ne radi uz istu konfiguraciju.

### DNS promjene nisu propagirane

Provjerite je li `/etc/hosts` ažuriran:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

Očistite predmemoriju DNS-a:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### IDE nije otkriven

Automatsko otkrivanje upotrebljava uobičajene putanje instalacije. Ako otkrivanje ne uspije, ali je IDE instaliran:

- Provjerite nalazi li se binarna datoteka IDE-a na nestandardnoj lokaciji
- Čarobnjak za postavljanje i dalje radi — neuspjelo otkrivanje samo znači da značka neće prikazivati putanju instalacije

### Pogreške rukovatelja (dohvaćanje s nadređenog poslužitelja ne uspijeva)

Ako AgentBridge presreće zahtjeve, ali svi zahtjevi ne uspijevaju:

1. Provjerite je li barem jedan pružatelj usluga povezan na `/dashboard/providers`
2. Provjerite zapisnike poslužitelja OmniRoute: `APP_LOG_LEVEL=debug` u `.env`
3. Provjerite pokazuje li `OMNIROUTE_BASE_URL` na ispravnu krajnju točku usmjerivača (zadano: `http://127.0.0.1:20128`)
