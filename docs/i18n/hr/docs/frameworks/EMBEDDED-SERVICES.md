## 1. Pregled

### Zašto ugrađene usluge?

Ugrađeno je šest usluga:

| Usluga          | npm paket                                       | Zadani port | Svrha                                                                                                                                                                                                          |
| --------------- | ----------------------------------------------- | :---------: | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **9Router**     | `9router`                                       |    20130    | AI usmjerivač koji OmniRoute može koristiti kao podpružatelja. Modeli su izloženi kao `9router/{sub}/{model}`                                                                                                  |
| **CLIProxyAPI** | Binarna datoteka iz GitHub izdanja (`cliproxy`) |    8317     | Lokalni proxy prilagodnik za tijekove autentifikacije Anthropic CLI-ja. Omogućuje pričuvno usmjeravanje kada OAuth tokeni isteknu                                                                              |
| **Mux**         | `mux` (bez sučelja, `mux server`)               |    8322     | Lokalni daemon za orkestraciju agenata (coder/mux). Upravlja se samo životnim ciklusom — nije cilj usmjeravanja (nema posredovanja LLM zahtjeva).                                                              |
| **Bifrost**     | `@maximhq/bifrost`                              |    8080     | Pozadinski sustav releja AI pristupnika napisan u jeziku Go. Dok je pokrenut, automatski ga odabire relejna ruta (`/v1/relay/`)                                                                                |
| **Dario**       | `@askalf/dario`                                 |    3456     | Proxy za pretplatu na Claude — alternativa/pričuvna opcija za CLIProxyAPI za promet u formatu Claude Codea; umetnuti ključ postaje `DARIO_ADMIN_TOKEN` koji štiti njegovu OAuth upravljačku ravninu `/admin/*` |
| **open-wa**     | `@open-wa/wa-automate`                          |    8323     | Automatizacija WhatsApp Weba (Chromium bez sučelja putem Puppeteera). Upravlja se samo životnim ciklusom — nije cilj usmjeravanja.                                                                             |

Svih šest usluga slijedi isti model nadzora:

- OmniRoute ih instalira u `DATA_DIR/services/{name}/` (izolirano od OmniRouteove vlastite datoteke `package.json`)
- OmniRoute ih pokreće kao podređene procese i nadzire ih
- OmniRoute umeće privremeni API ključ u okruženje podređenog procesa i rotira ga bez prekida rada (gdje je primjenjivo)
- Sve upravljačke rute (`/api/services/*`) imaju oznaku **LOCAL_ONLY** — dostupne su samo preko povratne mrežne adrese (strogo pravilo br. 17)

### Ključne odluke (iz projektnog plana)

| Odluka                                    | Vrijednost                                                                                 |
| ----------------------------------------- | ------------------------------------------------------------------------------------------ |
| Pristup izvornoj nadzornoj ploči 9Routera | Obrnuti proxy na `/dashboard/providers/services/9router/embed/*`                           |
| Mehanizam instalacije                     | `npm install {package}` putem `execFile` (bez interpolacije ljuske)                        |
| Način korištenja                          | Pružatelj registriran kao `9router/{sub}/{model}` u mehanizmu usmjeravanja                 |
| Upravljanje API ključem                   | OmniRoute ga generira, šifrira pri pohrani (AES-256-GCM) i umeće putem varijabli okruženja |
| Lokacija nadzorne ploče                   | `/dashboard/providers/services` (tri kartice)                                              |
| Automatsko pokretanje                     | Prekidač za svaku uslugu, zadano ISKLJUČENO                                                |

## 3. Stroj životnog ciklusa sa stanjima

```
                    install()
  ┌─────────────┐ ──────────► ┌─────────────┐
  │ not_installed│             │   stopped   │◄──────────────────┐
  └─────────────┘             └──────┬──────┘                   │
                                     │ start()                   │
                                     ▼                           │ stop()
                               ┌──────────┐                      │
                               │ starting │                      │
                               └────┬─────┘                     │
             provjera zdravlja uspješna │      pad / SIGTERM    │
                               ┌────▼─────┐  (izlaz unutar 5 s) │
                               │ running  │──── pad ────────────►┤
                               └────┬─────┘                   ┌─▼────┐
                             stop() │                          │error │
                                    ▼                          └──────┘
                               ┌──────────┐
                               │ stopping │
                               └──────────┘
```

Stanja se pohranjuju u DB tablici `version_manager` (stupac `status`) i zrcale
u stanju u memoriji komponente `ServiceSupervisor`. Stanje u memoriji mjerodavno je za
pokrenuti proces; stanje u DB-u trajna je pričuvna vrijednost pri pokretanju sustava.

### Prijelazi stanja

| Iz              | Događaj                                    | U                      |
| --------------- | ------------------------------------------ | ---------------------- |
| `not_installed` | `install()` uspije                         | `stopped`              |
| `stopped`       | pozvan je `start()`                        | `starting`             |
| `starting`      | provjera zdravlja vraća 200                | `running`              |
| `starting`      | proces završi prije nego što postane zdrav | `error`                |
| `running`       | pozvan je `stop()`                         | `stopping` → `stopped` |
| `running`       | proces neočekivano završi (< 5 s)          | `error` (brzi pad)     |
| `running`       | proces neočekivano završi (> 5 s)          | `error`                |
| `error`         | pozvan je `start()`                        | `starting`             |
| bilo koje       | `stop()` tijekom stanja `stopping`         | bez radnje             |

### Zaključavanje operacija

`ServiceSupervisor` serijalizira operacije životnog ciklusa putem asinkronog zaključavanja operacija
(`withLock()`). Istodobni pozivi `start()` na istom nadzorniku rezultiraju točno
jednim pokretanjem procesa; drugi pozivatelj čeka i vraća postojeće stanje. Time se sprječavaju
uvjeti utrke kada se, primjerice, automatsko pokretanje i gumb u korisničkom sučelju aktiviraju istodobno.

## 4. Referenca API-ja

Sve rute pod `/api/services/` su **LOCAL_ONLY** (samo povratna petlja, strogo pravilo #17).
Zahtjevi koji ne dolaze s povratne petlje primaju `403 LOCAL_ONLY` bez obzira na autentifikacijski token.

### 4.1 Krajnje točke 9Routera (11 ruta)

#### `POST /api/services/9router/install`

Instalira 9Router iz npm-a. Stvara `DATA_DIR/services/9router/` s vlastitim datotekama
`package.json` i `node_modules/`. Nije u sukobu s vlastitim ovisnostima OmniRoutea.

**Tijelo zahtjeva** (sva su polja neobavezna):

```json
{ "version": "latest" }
```

| Polje     | Tip      | Zadano     | Opis                                         |
| --------- | -------- | ---------- | -------------------------------------------- |
| `version` | `string` | `"latest"` | npm oznaka verzije ili semver za instalaciju |

**Odgovori:**

| Status | Opis                                                                                |
| ------ | ----------------------------------------------------------------------------------- |
| `200`  | `{ ok: true, installedVersion: "x.y.z", path: "..." }`                              |
| `400`  | Nevaljano tijelo zahtjeva (neuspjela Zod validacija)                                |
| `409`  | Instalacija je već u tijeku (zaključavanje je aktivno)                              |
| `500`  | npm instalacija nije uspjela — pogledajte `message` za razumljivu poruku o pogrešci |

**Napomene:** Upotrebljava `execFile('npm', [...])` — bez ljuske i bez interpolacije (strogo pravilo #13).
Pogreške EACCES prikazuju se kao razumljive poruke.

---

#### `POST /api/services/9router/start`

Pokreće 9Router. Registrira nadzornik ako već nije registriran, a zatim poziva
`supervisor.start()`. Idempotentno ako je servis već pokrenut.

**Tijelo zahtjeva:** nema

**Odgovori:**

| Status | Opis                                                                |
| ------ | ------------------------------------------------------------------- |
| `200`  | Objekt `ServiceStatus` (pogledajte shemu u nastavku)                |
| `409`  | 9Router nije instaliran (`status: "not_installed"`)                 |
| `503`  | Pokretanje nije uspjelo (pogreška procesa — pogledajte `lastError`) |

**Shema ServiceStatus:**

```json
{
  "tool": "9router",
  "state": "running",
  "pid": 12345,
  "port": 20130,
  "health": "healthy",
  "startedAt": "2026-05-25T10:00:00.000Z",
  "lastError": null
}
```

---

#### `POST /api/services/9router/stop`

Kontrolirano zaustavlja 9Router. Šalje SIGTERM, čeka 15 s, a zatim šalje SIGKILL ako je proces još uvijek aktivan.
Idempotentno ako je servis već zaustavljen.

**Tijelo zahtjeva:** nema

**Odgovori:**

| Status | Opis                                   |
| ------ | -------------------------------------- |
| `200`  | `ServiceStatus` (state: "stopped")     |
| `503`  | Zaustavljanje je neočekivano podbacilo |

---

#### `POST /api/services/9router/restart`

Istovjetno pozivu `stop()`, a zatim `start()` pod zaključavanjem operacije.

**Tijelo zahtjeva:** nema

**Odgovori:** isti kao za `start` (vraća konačni `ServiceStatus`).

---

#### `POST /api/services/9router/update`

Ažurira 9Router na noviju npm verziju. Ako je servis pokrenut, prvo se zaustavlja,
zatim se pokreće npm instalacija (novija verzija instalira se na postojećem mjestu),
a servis se potom ponovno pokreće.

**Tijelo zahtjeva** (sva su polja neobavezna):

```json
{ "version": "latest" }
```

**Odgovori:**

| Status | Opis                                                            |
| ------ | --------------------------------------------------------------- |
| `200`  | `{ ok: true, previousVersion: "...", installedVersion: "..." }` |
| `400`  | Nevaljano tijelo                                                |
| `500`  | npm ažuriranje nije uspjelo                                     |

---

#### `POST /api/services/9router/rotate-key`

Generira novi API ključ za 9Router, šifrira ga u mirovanju i ponovno pokreće servis

### 4.7 Obrnuti proxy (ugradnja nadzorne ploče 9Router)

Nadzorna ploča ugrađuje web-sučelje 9Router unutar iframea putem internog obrnutog
proxyja na:

```
GET|POST|... /dashboard/providers/services/9router/embed/[...path]
```

Ovaj proxy:

- Prosljeđuje zahtjev na `http://127.0.0.1:{port}/{path}` (samo povratna petlja)
- Uklanja ulazna zaglavlja `cookie` i `authorization` (nema curenja sesije OmniRoute)
- Umeće `Authorization: Bearer {apiKey}` za autentifikaciju 9Router
- Iz odgovora uklanja `set-cookie`, `content-security-policy`, `x-frame-options`, `cross-origin-*`
- Prepisuje HTML odgovore kako bi umetnuo `<base href>` i normalizirao apsolutne putanje (`/foo` → `/dashboard/.../embed/foo`)

WebSocket nadogradnjama za ugrađenu nadzornu ploču upravlja prateći poslužitelj na
namjenskom portu (pogledajte `src/lib/services/embedWsProxy.ts`).

**Sigurnost:** Proxy rute za ugradnju klasificirane su pod `LOCAL_ONLY_API_PREFIXES`
i dostupne su samo s povratne petlje. Napadač koji pribavi JWT putem
Cloudflare/Ngrok tunela ne može posredovati prema ugrađenim uslugama.

## 5. Sigurnost

### Provedba LOCAL_ONLY (strogo pravilo #17)

Sve rute pod `/api/services/` i `/dashboard/providers/services/*/embed/`
klasificirane su kao LOCAL_ONLY u `src/server/authz/routeGuard.ts`. Provjera povratne petlje
izvršava se bezuvjetno prije bilo koje grane autentifikacije:

```
zahtjev stiže
  → isLocalOnlyPath(path)?
      → nije povratna petlja → 403 LOCAL_ONLY (uvijek, prije provjere autentifikacije)
      → povratna petlja      → nastavi na uobičajenu autentifikaciju
```

Time se sprječava da procurjeli JWT (npr. putem tunela) pokrene `npm install` ili
stvaranje procesa. Potpunu matricu razina pogledajte u
`docs/security/ROUTE_GUARD_TIERS.md`.

### Umetanje API ključa

9Router i Mux zahtijevaju API ključ/nositeljski token za vlastite HTTP krajnje točke.
OmniRoute:

1. Generira ključ putem `crypto.randomBytes(32).toString("base64url")` s prefiksom
   specifičnim za uslugu (`nr_` za 9Router, `mx_` za Mux).
2. Šifrira ga u mirovanju pomoću AES-256-GCM (iste šifre koja se koristi za vjerodajnice pružatelja).
3. Dešifrira ga i umeće kao varijablu okruženja pri pokretanju procesa —
   `NINEROUTER_API_KEY` za 9Router, `MUX_SERVER_AUTH_TOKEN` za Mux (nikad kao CLI
   zastavicu, tako da se token nikad ne pojavljuje u `ps`/popisima procesa).
4. Nikad ne vraća ključ u obliku običnog teksta ni u jednom HTTP odgovoru.

CLIProxyAPI prima namjenski ključ podatkovne ravnine umetnut pri pokretanju procesa
(`needsApiKey: true` — koristi se za sinkronizaciju modela s prilagodnikom).

### Zaštita od SSRF-a

Obrnuti HTTP proxy (`/dashboard/.../embed/[...path]`) čvrsto je konfiguriran za prosljeđivanje
isključivo na `http://127.0.0.1:{port}`. Nikad ne slijedi preusmjeravanja prema
odredištima izvan povratne petlje. Biblioteka `ssrf-req-filter` koristi se za odbijanje svakog nadređenog URL-a koji
se razrješava izvan raspona povratne petlje.

### Sigurnost ljuske (strogo pravilo #13)

`npm install` poziva se putem `execFile('npm', ['install', pkg, '--prefix', dir])` —
bez predložaka literala, ljuske ili interpolacije vanjskih putanja u naredbeni
niz. Vrijednosti tijekom izvođenja (portovi, API ključevi) prosljeđuju se putem objekta `env` podređenog procesa.

### Sanitizacija pogrešaka (strogo pravilo #12)

Svi odgovori o pogreškama iz `/api/services/*` prolaze kroz `buildErrorBody()` ili
`sanitizeErrorMessage()`. Neobrađeni `err.stack` i `err.message` nikad se doslovno ne vraćaju
pozivatelju.

## 7. Rješavanje problema

### Servis se ne pokreće

**Simptomi:** Gumb za pokretanje vraća 503, a stanje ostaje `"error"` ili `"starting"`.

**Kontrolni popis:**

1. Provjerite `GET /api/services/{name}/logs` (ili ploču Logs na nadzornoj ploči). Potražite
   retke poput `Error: ENOENT`, `address already in use` ili `Cannot find module`.
2. Provjerite nalazi li se `npm` u varijabli PATH: izvršite `which npm` iz istog korisničkog računa pod kojim se pokreće OmniRoute.
3. Provjerite je li servis instaliran: provjerite `GET /api/services/{name}/status` za
   `installedVersion`. Ako je vrijednost `null`, najprije pokrenite instalaciju.
4. Provjerite postoji li `DATA_DIR/services/{name}/node_modules/` i je li direktorij neprazan.
5. U odgovoru o stanju provjerite polje `lastError` radi pročišćenog razloga prekida.

---

### Hladno pokretanje je sporo (> 10 s do stanja `running`)

**Simptomi:** Stanje dugo ostaje `"starting"` prije prelaska u `"running"` ili `"error"`.

**Objašnjenje:** Hladno pokretanje 9Routera uključuje uvoz velikih stabala ovisnosti (DNS,
tunelski i MITM moduli). Zadani interval provjere ispravnosti iznosi 2 s uz 3 pokušaja prije nego što
nadzornik proglasi istek vremena (ali nastavlja provjeravati).

**Rješenje:** Vrijednosti `healthIntervalMs` i vremenskog ograničenja za `waitForHealthy`
(`healthIntervalMs * 3`) mogu se konfigurirati u datoteci `bootstrap.ts`. Za servise kojima je potrebno više
vremena za pokretanje povećajte `healthIntervalMs` na 5000, a `stopTimeoutMs` na 30 000.

---

### Sukob priključaka (`EADDRINUSE`)

**Simptomi:** Zapisi prikazuju `address already in use :::20130`.

**Uzroci:**

- Drugi proces već upotrebljava priključak 20130.
- Prethodni proces 9Routera nije potpuno zaustavljen (zombi PID).

**Rješenje:**

1. Promijenite zadani priključak putem varijable okruženja `NINEROUTER_PORT` u datoteci `.env`.
2. Pronađite i prekinite sukobljeni proces: `lsof -ti :20130 | xargs kill -9`.
3. Priključak se može konfigurirati zasebno za svaki servis u datoteci `bootstrap.ts` putem polja `port`.

**Napomena:** 9Router prema zadanim postavkama upotrebljava priključak 20130 upravo kako bi izbjegao sukob sa
zadanim priključkom 20128 sustava OmniRoute.

---

### Pristup odbijen (EACCES) tijekom instalacije

**Simptomi:** Instalacija vraća 500, a zapisi prikazuju `EACCES` ili `permission denied`.

**Uzroci:**

- Proces OmniRoute nema dopuštenje za pisanje u `DATA_DIR` ili njegov nadređeni direktorij.
- Izvršavanje unutar Docker okruženja bez root ovlasti i bez pristupa za pisanje u mapirani volumen.

**Rješenje:**

1. Provjerite `DATA_DIR` (zadano: `~/.omniroute/`): `ls -la ~/.omniroute/`
2. Pobrinite se da je korisnik procesa OmniRoute vlasnik direktorija: `chown -R $USER ~/.omniroute/`
3. U Dockeru provjerite ima li priključeni volumen odgovarajuća dopuštenja za korisnika spremnika.

---

### Ažuriranje ne uspijeva (istek vremena za `npm install` ili mrežna pogreška)

**Simptomi:** Ažuriranje vraća 500 uz `InstallError`, a zapisi prikazuju istek mrežnog vremena.

**Kontrolni popis:**

1. Provjerite je li npm registar dostupan: `npm ping`.
2. Provjerite postoji li korporacijski proxy: `npm config get proxy`, `npm config get https-proxy`.
3. Pokušajte ručno instalirati: `npm install {package}@latest --prefix ~/.omniroute/services/{name}/`.
4. Ako se nalazite iza zračno izolirane mreže, unaprijed preuzmite tarball i upotrijebite `npm install /path/to/tarball.tgz`.

---

### Servis prikazuje stanje `"error"` odmah nakon pokretanja (brzo rušenje)

**Simptomi:** Stanje prelazi iz `"starting"` u `"error"` za manje od 5 sekundi.
`lastError` prikazuje `"Fast crash (exited with code 1)"`.

**Kontrolni popis:**

1. Pročitajte cijeli završni dio zapisa: `GET /api/services/{name}/logs?tail=500`.
2. Uobičajeni uzrok: nedostaju varijable okruženja koje servis očekuje.
3. Za 9Router: provjerite jesu li `NINEROUTER_DISABLE_MITM=true` i
   `NINEROUTER_DISABLE_TUNNEL=true` prisutni u okruženju proslijeđenom pri stvaranju procesa (pogledajte
   `installers/ninerouter.ts` `resolveSpawnArgs`).

---

## 8. Često postavljana pitanja

**P: Mogu li krajnje točke ugrađenih servisa izložiti klijentima koji nisu na povratnoj petlji?**

Ne. Razina LOCAL_ONLY postoji namjerno (strogo pravilo #17). Rute koje mogu pokrenuti
`npm install` ili stvarati `node` procese ne smiju biti dostupne prometu koji ne dolazi
s povratne petlje jer bi JWT koji procuri putem tunela (Cloudflare, Ngrok, Tailscale)
inače omogućio proizvoljno stvaranje procesa. Za `/api/services/` ne postoji iznimka
koja omogućuje isključivanje tog ograničenja — za razliku od `/api/mcp/`, ta je ruta
isključena s popisa zaobilaženja opsega manage. Pogledajte
`docs/security/ROUTE_GUARD_TIERS.md`.

---

**P: Hoće li 9Router i CLIProxyAPI biti dostupni u produkcijskim implementacijama i implementacijama u oblaku?**

Da. Oba servisa slijede isti model usmjeren na lokalno okruženje kao i sam OmniRoute.
Izvode se na istom računalu i komuniciraju preko povratne petlje. „Produkcija” ovdje
označava VPS ili lokalni poslužitelj na kojem je OmniRoute implementiran, a ne
udaljenog pružatelja usluga u oblaku.

---

**P: Kako otkloniti pogreške nadzornika?**

1. Pratite SSE tok zapisnika: `curl -N http://localhost:20128/api/services/9router/logs`.
2. Provjerite strukturirane zapisnike u izlazu alata pino za OmniRoute, filtrirane
   prema prostoru naziva `service:supervisor`.
3. Pregledajte redak baze podataka: `sqlite3 ~/.omniroute/omniroute.db "SELECT * FROM version_manager WHERE tool='9router'"`.
4. Upotrijebite `GET /api/services/9router/status` kako biste u jednom pozivu vidjeli
   trenutačno stanje uživo, PID, stanje ispravnosti i `lastError`.

---

**P: Nadzornik prikazuje `health: "degraded"` ili `health: "unknown"`, ali stanje je `"running"`. Je li to problem?**

`"degraded"` znači da je provjera ispravnosti vratila odgovor koji nije 200.
`"unknown"` znači da nijedna provjera još nije dovršena (utrka s prvim ispitivanjem).
Oba su stanja privremena tijekom pokretanja. Ako stanje ispravnosti ostane
`"degraded"` dulje od `healthIntervalMs * 3` ms nakon stanja `"running"`, ugrađeni
servis radi, ali njegov HTTP API ne odgovara. Provjerite je li priključak naveden u
odgovoru o stanju ispravan i sluša li servis doista na tom priključku.

---

**P: Mogu li promijeniti API ključ za 9Router bez potpunog ponovnog pokretanja?**

Ne. API ključ prosljeđuje se servisu 9Router putem varijable okruženja u trenutku
stvaranja procesa. Varijable okruženja ne mogu se mijenjati u procesu koji je već
pokrenut. `POST .../rotate-key` automatski zaustavlja i ponovno pokreće servis kako bi
primijenio novi ključ. Rotacija ključa stupa na snagu unutar vrijednosti
`stopTimeoutMs` servisa (zadano 15 s), uvećane za vrijeme njegova pokretanja.

---

**P: Koje je ograničenje kružnog međuspremnika i što se događa kada se napuni?**

Svaki servis ima namjenski kružni međuspremnik od 5 MB. Kada se međuspremnik napuni,
najstariji se retci zapisnika uklanjaju kako bi se oslobodio prostor za nove. SSE
događaj `snapshot` vraća najnovije retke unutar ograničenja `tail`. Zapisnici se ne
pohranjuju trajno na disk osim ako je u retku baze podataka postavljen
`logsBufferPath`.
