Releji (Vercel, Deno, Cloudflare) prekidaju uzvodnu vezu na
backendu bez poslužitelja kako bi OmniRoute mogao slati izlazni promet iz stabilne regije, dok
API ključ pružatelja ostaje na strani poslužitelja. Ovaj dokument obrađuje dva načina kvara
s kojima se operateri susreću u produkciji i postupke oporavka koje OmniRoute nudi za
svaki od njih.

## Kako se pohranjuje autentifikacija releja

Kada implementirate relej putem **Postavke → Skup proxyja → Implementiraj relej**,
tijek implementacije pohranjuje autentifikacijski token releja u JSON polje `notes`
proxyja:

- Ako je postavljen `STORAGE_ENCRYPTION_KEY`, token se zapisuje kao `relayAuthEnc`
  (AES-om šifriran u mirovanju).
- U suprotnom se zapisuje kao nešifrirani tekst `relayAuth`.

U trenutku zahtjeva `extractRelayAuth(notes)` vraća oblik koji je prisutan,
pa relej nastavlja raditi i nakon ponovnih pokretanja.

## Način kvara 1 — token koji se ne može dešifrirati nakon rotacije ključa

**Simptom:** releji koji su prethodno radili sada vraćaju uzvodne pogreške
`401`/autentifikacije nakon rotacije varijable okruženja ili upravitelja tajni
`STORAGE_ENCRYPTION_KEY`. Pohranjeni blob `relayAuthEnc` više se ne može
dešifrirati, pa `extractRelayAuth` vraća prazan niz, a relej ne šalje
autentifikacijske podatke.

**Oporavak — popravak na mjestu (bez ponovne implementacije):**

1. Otvorite **Postavke → Skup proxyja**.
2. Redci releja kojima nedostaje autentifikacija prikazuju žutu oznaku `auth missing` i
   gumb **Popravi**.
3. Kliknite **Popravi**. OmniRoute poziva
   `POST /api/settings/proxies/[id]/repair-relay`, koji:
   - dešifrira `relayAuthEnc` pomoću **trenutačnog** ključa,
   - zapisuje nešifrirani `relayAuth` natrag u `notes`,
   - vraća `{ repaired: true, mode: "recovered" }`.

Relej nastavlja posluživati zahtjeve bez ponovnog unosa vjerodajnica za implementaciju.

To funkcionira samo ako trenutačni `STORAGE_ENCRYPTION_KEY` još uvijek može dešifrirati
blob. Ako ste rotirali ključ **bez** migracije, blob se
ne može oporaviti.

## Način kvara 2 — token koji se ne može oporaviti (ključ je uklonjen rotacijom)

**Simptom:** kliknuli ste **Popravi** i dobili
`{ repaired: false, mode: "redeploy", status: 409 }`.

**Oporavak — ponovna implementacija:**

Pohranjeni token ne može se oporaviti trenutačnim ključem. Ponovno implementirajte relej
iz istog modalnog prozora koji ste izvorno upotrijebili (izbornik **Implementiraj relej** → Vercel / Deno
/ Cloudflare). Tijek implementacije zapisuje novi token (šifriran trenutačnim
ključem), a oznaka `auth missing` u retku nestaje.

U korisničkom sučelju sam gumb **Popravi** otvara modalni prozor za ponovnu implementaciju kada se
token ne može oporaviti, pa ga nikada ne morate ručno tražiti.

## Način kvara 3 — relej je dostupan, ali nije ispravan

**Simptom:** test proxyja (gumb `speed`) pokazuje da je relej aktivan, ali zahtjevi
i dalje povremeno ne uspijevaju.

Provjerite zaglavlja informacija o releju koja vraća OmniRouteova sonda za automatsko testiranje
(pogledajte **Postavke → Skup proxyja** i brojače `relayTested` / `relayAlive`):

- `x-relay-url` — koji je backend releja odgovorio.
- `x-relay-mode` — `ts` | `bifrost` | `auto` za taj zahtjev.
- `x-relay-attempts` — koliko je relejnih prijelaza pokušano prije uspjeha.
- `x-relay-fallback` — `true` kada se zahtjev prebacio sa željenog
  backenda na TypeScript relej.

Visoka stopa `x-relay-fallback` uz nizak `relayAlive` znači da pomoćni
backend nije ispravan te biste ga trebali popraviti ili promijeniti strategiju backenda releja
na `ts` (pogledajte `RELAY_BACKEND_STRATEGY.md`).

## Referenca API-ja

| Metoda | Putanja                                   | Tijelo                  | Uspjeh                                                                                                                                               | Neuspjeh                                                                                        |
| ------ | ----------------------------------------- | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `POST` | `/api/settings/proxies/[id]/repair-relay` | `{ "id": "<proxyId>" }` | `200 { repaired: true, mode: "recovered" }` kada je ponovno izvedeno; `200 { repaired: false, mode: "noop" }` kada je nešifrirani tekst već prisutan | `409 { mode: "redeploy" }` nije moguće oporaviti; `400` nije vrsta releja; `404` nije pronađeno |

Ruta popisa `GET /api/settings/proxies` svakom elementu pridružuje
`relayInfo: { isRelay, authMissing, repairMode }` bez tajnih podataka kako bi nadzorna ploča
mogla prikazati mogućnost popravka bez ikakvog izlaganja tokena.
