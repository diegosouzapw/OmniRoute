> **Napomena o opsegu:** `socket.yml` konfigurira Socket.dev-ovo skeniranje npm artefakta nakon objave na strani registra (putanje za ignoriranje za sadržaj koji se ne isporučuje, kao što su `tests/`, `docs/` i izvješća o izgradnji). Ne povezuje CI/PR spojna vrata — nijedan tijek rada u `.github/workflows`, nijedna skripta `package.json` i nijedan cilj `Makefile` ne poziva Socket.dev.

Ovaj dokument je potvrda koju je autor održavatelj izdao za šest
nalaza `AI-detected potential malware` podignutih protiv `omniroute@3.8.5` i
ublažavanja primijenjenih u `omniroute@3.8.6`. Postoji kako bi:

1. Operateri sigurnosnog cjevovoda imali jednu referencu za citiranje kada trebaju
   procijeniti nalaze u odnosu na stvarni izvor.
2. Budući AI skeneri mogu preuzeti tvrdnju koju je potpisao održavatelj da je svaka
   označena putanja namjerna, opt-in i dokumentirana.
3. Imamo pisani zapis o _zašto_ je svako mjesto poziva oblikovano na način na koji jest —
   tako da buduće refaktoriranje slučajno ne ponovno uvede otisak prsta koji
   je namjerno uklonjen.

Ako upravljate skenerom koji ponovno označava bilo koje od dolje navedenih mjesta poziva nakon što su
isporučena ublažavanja v3.8.6, otvorite problem s tragom skeniranja i
proširit ćemo potvrdu ovdje.

## §1 — Instalacija korijenskog CA certifikata za MITM (`77484.js`)

**Izvorne datoteke**:

- `src/mitm/cert/install.ts` — javne funkcije `installCert()` / `uninstallCert()`,
  te `installCertWindows/Mac/Linux` specifične za pojedine platforme.
- `src/mitm/systemCommands.ts` — zajedničke pomoćne funkcije `execFile` / `spawn` / PowerShell
  koje koriste putanje instalacije.

**Okidač**: korisnik klikne „Omogući MITM proxy” na lokalnoj nadzornoj ploči na
`/dashboard/cli-tools/mitm`. Ruta je dostupna samo putem povratne petlje — pogledajte strogo pravilo #17 u
`CLAUDE.md` i `src/server/authz/routeGuard.ts::isLocalOnlyPath()`. JWT koji je
izložen putem tunela **ne može** pokrenuti ovu putanju koda.

**Izvršene privilegirane operacije (po platformi)**:

| OS                     | Naredba/naredbe                                                                                                   |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | `certutil -addstore Root <cert>` putem UAC-a                                                                      |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | ažuriranje NSS baze podataka po profilu putem `certutil -d sql:<profile>`                                         |

To su iste naredbe koje koriste `mitmproxy`, Charles Proxy, Fiddler i
Caddy. Činjenica da postoje u OmniRouteu dokumentirana je u
`docs/security/STEALTH_GUIDE.md`.

**Mjere ublažavanja u v3.8.6**:

- `runElevatedPowerShell()` više ne koristi `-EncodedCommand <base64utf16le>`.
  Sadržaj koji se izvršava s povišenim ovlastima zapisuje se u privremenu `.ps1` datoteku za svaki poziv (način rada 0o600,
  unutar privatnog direktorija `mkdtempSync`) te se na nju upućuje putem opcije `-File`. Datoteka
  se uklanja u bloku `finally`. Time se uklanja prepoznatljiv obrazac
  podizanja ovlasti putem PowerShella i base64 kodiranja koji je označio AI
  klasifikator Socket.deva.
- `installCertWindows` sadrži umetnuti blok `SECURITY-AUDITOR-NOTE:`
  koji upućuje ovamo.

**Zašto to zadržavamo**: MITM proxy dokumentirana je značajka koju koriste
`docs/security/STEALTH_GUIDE.md` i `docs/frameworks/MITM-PROXY.md`. Njegovo
uklanjanje narušilo bi skup značajki agent-bridgea.

## §2 — Uvoz vjerodajnica iz Zeda (`app/api/providers/zed/import/route.js`)

**Izvorne datoteke**:

- `src/app/api/providers/zed/discover/route.ts` _(novo u v3.8.6)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(novo u v3.8.6)_

**Okidač**: korisnik klikne „Uvezi iz Zeda” na stranici Pružatelji usluga na
lokalnoj nadzornoj ploči. Krajnja točka zaštićena je s `requireManagementAuth`.
Sam uređivač Zed zapisuje API ključeve svojih pružatelja usluga u spremište
ključeva OS-a pod dokumentiranim nazivima usluga — pogledajte
https://zed.dev/docs/ai/llm-providers.

**Ponašanje u v3.8.5 (ono koje je Socket.dev označio)**:

`POST /import` otkrivao je vjerodajnice i automatski ih spremao u lokalno
SQLite spremište u jednom povratnom prolazu. Bez potvrde za svaki račun, bez
otiska, samo „pronađeno je N tokena, svi su uvezeni.”

**Ublažavanje rizika u v3.8.6 — potvrda u 2 koraka**:

1. **`POST /api/providers/zed/discover`** vraća
   `{ candidates: [{ provider, service, account, fingerprint }] }`. Neobrađeni
   token se **nikada** ne prenosi. Otisak je
   `sha256(service|account|token).slice(0,16)`.
2. Nadzorna ploča prikazuje popis kandidata, operater odabire one koje želi
   uvesti i šalje `{ confirmedAccounts: [{ service, account, fingerprint }] }`
   na **`POST /api/providers/zed/import`**.
3. Krajnja točka za uvoz **ponovno čita spremište ključeva na poslužitelju** i
   filtrira prema `(service, account, fingerprint)`. Izmijenjeni ili ponovno
   reproducirani odgovor otkrivanja ne može navesti krajnju točku za uvoz da
   spremi nepovezani token — ako se aktivni token promijenio nakon otkrivanja,
   otisak se više ne podudara i vjerodajnica se preskače.

Varijabla okruženja `OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` zadržava
ponašanje iz v3.8.5 za operatere koji još nisu ažurirali svoju automatizaciju.
Bit će uklonjena u v3.9.

**Zašto to zadržavamo**: uvoz iz Zeda najjednostavniji je način početnog
postavljanja za korisnike koji već upotrebljavaju Zed i žele preslikati ključeve
svojih pružatelja usluga u OmniRoute bez ponovnog lijepljenja.

## §3 — `execFile` / `spawn` / PowerShell s povišenim ovlastima (`21843.js`)

**Izvorne datoteke**: `src/mitm/systemCommands.ts`.

**Zašto je označeno**: segment ponovno izvozi `execFileWithPassword`,
`runElevatedPowerShell` i zajedničku pomoćnu funkciju `quotePowerShell`.
AI klasifikator servisa Socket.dev prepoznaje ih kao generički „komplet alata
za izvršavanje na glavnom računalu + podizanje ovlasti.” Unutar OmniRoutea
upotrebljavaju se samo u putanji za instalaciju MITM certifikata (§1) te u
`execFileWithPassword` za izvršavanje naredbi putem `sudo`.

**Ublažavanje rizika u v3.8.6**:

- Refaktoriranje funkcije `runElevatedPowerShell` (pogledajte §1).
- Umetnuti blok `SECURITY-AUDITOR-NOTE:` uz `runElevatedPowerShell` i
  `execFileWithPassword` dokumentira pozivatelje na popisu dopuštenih i
  fiksirani popis izvršnih datoteka.
- Poziv `spawn()` u funkciji `execFileWithPassword` sadrži oznaku `nosemgrep`
  s popisom dopuštenih izvršnih datoteka koje pomoćna funkcija smije primiti —
  **ne postoji put od korisničkog unosa do `finalCommand`/`finalArgs`**.

## §4 / §6 — nadzornik usluge 9router (`api/services/9router/{start,restart}/route.js`)

**Izvorne datoteke**:

- `src/app/api/services/9router/_lib.ts` — tvornica nadzornika.
- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`.
- `src/lib/services/ServiceSupervisor.ts` — generičko pokretanje / provjera stanja / međuspremnik zapisnika.

**Okidač**: korisnik klikne „Instaliraj” / „Pokreni” na stranici ugrađenih
usluga na lokalnoj nadzornoj ploči.

**Već postojeće zaštite**:

- Sve rute `/api/services/*` imaju oznaku LOCAL_ONLY prema
  `src/server/authz/routeGuard.ts` (strogo pravilo #17). Ograničenje na lokalnu
  povratnu petlju provodi se prije bilo kakve provjere autentičnosti —
  kompromitirani JWT ne može im pristupiti.
- Redak baze podataka za 9router inicijalno se postavlja na
  `status='not_installed', auto_start=0` (pogledajte
  `src/lib/db/migrations/071_services.sql:19`). Usluga se **ne** pokreće pri
  prvom pokretanju aplikacije.
- `spawn()` se poziva s putanjom binarne datoteke koju vraća
  `resolveSpawnArgs(apiKey, PORT)` u datoteci
  `src/lib/services/installers/ninerouter.ts`, a koja predstavlja fiksni popis
  dopuštenih podržanih binarnih datoteka.
- Stdout/stderr sprema se u memorijski međuspremnik (ograničenje od 5 MB,
  pogledajte `_lib.ts`) — nema zapisivanja na disk osim ako korisnik omogući
  zapisivanje putem nadzorne ploče.

**Ublažavanje rizika u v3.8.6**: nema funkcionalnih promjena. Minimalni profil
izgradnje (`OMNIROUTE_BUILD_PROFILE=minimal`) zamjenjuje
`src/lib/services/installers/ninerouter.ts` zamjenskom implementacijom za
korisnike koji žele da se putanje s povišenim ovlastima fizički uklone iz
paketa.

**Zašto to zadržavamo**: 9router je izborna popratna usluga koja se može
lokalno instalirati (poput dodatka za WordPress) — isključivo uz izričit
pristanak.

## §5 — Povratni zapis vjerodajnica za OmniRoute Cloud Sync (`api/keys/[id]/route.js`)

**Izvorne datoteke**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`.
- `src/app/api/keys/[id]/route.ts` — poziva `syncKeysToCloudIfEnabled()`.

**Okidač**: `isCloudEnabled()` vraća `true` (postavlja se putem nadzorne ploče) **i**
`CLOUD_URL` je konfiguriran. Kada je oboje isključeno, ne izvršava se odlazni mrežni poziv prema
Cloud krajnjoj točki.

**Ponašanje u v3.8.5 (pogreška koju je Socket.dev ispravno otkrio)**:

`updateLocalTokens()` prebrisao je `accessToken`, `refreshToken` i
`providerSpecificData` iz Cloud odgovora kada je
`cloudUpdatedAt > localUpdatedAt`. Bez HMAC-a, potpisa ili kontrolnog zbroja.
Pogrešno konfiguriran ili zlonamjeran `CLOUD_URL` (ili MITM na kanalu) mogao je neprimjetno
zamijeniti OAuth tokene pružatelja usluge.

**Ublažavanje u v3.8.6**:

1. **HMAC provjera**: `verifyCloudSignature(rawBody, sigHeader)` provjerava
   zaglavlje `X-Cloud-Sig` (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`) prije raščlambe JSON-a. Ako je tajna postavljena, potpis je
   obavezan. Ako nije (naslijeđeni način rada), bilježi se upozorenje i odgovor se
   prihvaća — tajna će biti obavezna u v3.9.
2. **Izričito uključivanje tajnih polja**: `accessToken` / `refreshToken` /
   `providerSpecificData` prepisuju se **samo** kada je
   `OMNIROUTE_CLOUD_SYNC_SECRETS=true`. Zadani način rada sinkronizira samo
   metapodatke koji nisu vjerodajnice (`expiresAt`, `status`, `lastError*`,
   `rateLimitedUntil`, `updatedAt`). Ovo je **nekompatibilna promjena** za korisnike
   koji su se oslanjali na udaljenu sinkronizaciju tokena — moraju je izričito uključiti.

**Zašto to zadržavamo**: Cloud Sync jedini je način da korisnik usluge OmniRoute Cloud
centralizira vjerodajnice tima. Ispravak čini model prijetnji jasnim:
„poslužitelj potpisuje, klijent provjerava, operator izričito uključuje.”

## Profil izgradnje: `minimal`

Korisnici kojima je potreban artefakt kompatibilan sa Socketom mogu ga izgraditi pomoću:

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

Webpackov `NormalModuleReplacementPlugin` zamjenjuje četiri modula zamjenskim implementacijama:

| Modul                                       | Zamjenska implementacija                         |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

Svaka zamjenska implementacija izvozi isto sučelje, ali svaka funkcija tijekom izvođenja baca
`featureDisabledError(name)`. Rute koje ovise o onemogućenom
modulu vraćaju HTTP 503 s jasnom porukom umjesto aktiviranja
osjetljive putanje koda.

Dobiveni paket namijenjen je objavljivanju pod nazivom `omniroute-secure`. Recept za
objavljivanje nalazi se u `docs/ops/PUBLISHING_SECURE.md`.
