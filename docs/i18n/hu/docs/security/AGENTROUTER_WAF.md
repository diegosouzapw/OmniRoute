Az `agentrouter` upstream átjáró kulcsszóalapú tartalomszűrőt futtat a
`messages[].content` mezőn. A szűrő részben determinisztikus (bizonyos
kifejezéseket mindig blokkol), részben pedig valószínűségi (érzékeny a
kéréssorozatokra — gyors egymásutánban érkező kérések után agresszívebbé
válik, majd egy várakozási idő elteltével helyreáll).

Amikor a WAF blokkol egy kérést, a következőt adja vissza:

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## A szűrő hatóköre

A WAF kizárólag a `messages[].content` mezőt vizsgálja. **Nem** vizsgálja a következőket:

- A `system` prompt
- Strukturált tartalmi blokkok (`tool_result`, `tool_use`, `thinking`, `image`)
- Az eszközök `description` és `input_schema` mezői
- A kérés metaadatai, fejlécei vagy modellazonosítója

## Mindig blokkolt minták (kis- és nagybetűktől függetlenül)

| Minta                          | Megjegyzések                                              |
| ------------------------------ | --------------------------------------------------------- |
| Bármely `Lorem ipsum`-változat | A teljes latin lorem szókészlet blokkolva van             |
| `language model` (önmagában)   | A "the language model" és a "large language model" átmegy |
| `virtual assistant`            | Az "AI assistant" átmegy                                  |
| `I'm here to help`             | A "here to help" önmagában is blokkolást vált ki          |
| `Claude, made by Anthropic`    | Csak a teljes kifejezés                                   |

## Szinte mindig blokkolt minták

| Minta                                                     | Megjegyzések                                      |
| --------------------------------------------------------- | ------------------------------------------------- |
| `placeholder`                                             | Amikor önmagában áll (nem paraméternévként stb.)  |
| `dummy data`                                              | Tesztadatokhoz gyakran használt kezdeti kifejezés |
| `foo bar baz`                                             | Szabványos helykitöltő kifejezés                  |
| Ismétlődő rövid tokenek (`AAA BBB CCC`, `test test test`) | Kulcsszóhalmozást észlelő detektor                |

## Viselkedés terhelés alatt

Rövid időn belül körülbelül 5 gyors kérés után a WAF olyan tartalmakat is
blokkolni kezd, amelyek normál esetben átjutnának. A korlátozás körülbelül
5–10 másodpercnyi tétlenség után enyhül. Ugyanez az IP-címhez és kulcshoz
kötött sebességkorlátozó okozza az időszakos `400 content-blocked` hibákat,
amikor a Claude Code vagy a Codex CLI gyors egymásutánban több
eszközhasználati vagy üzenetküldési hívást indít.

## Az OmniRoute-ban már alkalmazott enyhítések

1. **`open-sse/services/wafRateLimit.ts`** — kéréssorozat-védelem, amely
   legalább 500 ms-os szünetet kényszerít ki a bármely `agentrouter:*`
   URL-re küldött kimenő kérések között. Ez a késleltetés jóval az emberi
   érzékelési küszöb alatt van, és megakadályozza, hogy a WAF normál
   forgalom esetén aktiválódjon.

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — amikor egy upstream szolgáltatás
   `400 content-blocked` választ ad, a végrehajtó ugyanazt az URL-t
   exponenciális késleltetéssel újrapróbálja (1,5 s, 3,0 s, legfeljebb
   2 próbálkozás). A várakozás után a WAF általában enyhít a korlátozáson,
   és az újrapróbálkozás sikeres lesz.

3. **`tests/unit/compression/harness.test.ts`** — a `longInput`
   tesztadat értéke `"lorem ipsum dolor sit amet ".repeat(40)` helyett
   `"example content for testing purposes ".repeat(40)` lett, így amikor
   a Claude Code a `Read` eszközzel beolvassa ezt a fájlt, a fájl tartalma
   nem kerül vissza egy `tool_result` blokkon keresztül, és nem aktiválja
   a WAF-ot.

## Útmutatás promptokhoz és eszközkimenetekhez

Ha egy Claude Code- vagy Codex CLI-munkamenet ismételten
`400 content-blocked` hibába ütközik, ellenőrizze a legutóbbi felhasználói
üzenetet és a legutóbbi eszközeredményt a fenti minták szempontjából, majd
fogalmazza át azokat. Gyakori kerülő megoldások:

- Cserélje le a `Lorem ipsum …` szöveget `example text …` szövegre vagy
  arra a tényleges tartalomra, amelyet a teszt vagy a tesztadat modellezni próbál.
- Cserélje le az önmagában álló `placeholder` kifejezést `example value`,
  `sample value` vagy a tényleges értékre.
- Cserélje le a `language model` kifejezést `large language model` vagy
  `the model` kifejezésre.
- Cserélje le a `dummy data` kifejezést `sample data` kifejezésre vagy
  valósághű kezdeti értékekre.
- Cserélje le az `I'm here to help` / `here to help` kifejezést egy
  konkrétabb nyitómondatra (például: "I'll review the file you mentioned").

## A téves pozitív találatok jelentése az upstream szolgáltatónak

A jelenlegi szűrő túlságosan agresszív — a "Lorem ipsum" szöveget még
`tool_result` blokkokban is blokkolja, noha az operátor nyilvánvalóan nem
akart promptot injektálni. Azoknak az üzemeltetőknek, akik szeretnék, hogy
ezt a forrásnál javítsák, érdemes kapcsolatba lépniük az `agentrouter.org`
üzemeltetőivel, és jelenteniük a téves pozitív találatokat. A fenti
tiltólista az upstream szolgáltatás 2026-08-03-án végzett vizsgálatának
empirikus eredménye.
