> **Legutóbb frissítve:** 2026-06-28 — v3.8.40

Az OmniRoute három különböző, ügynökökkel kapcsolatos felületet biztosít. Első pillantásra hasonlónak tűnnek, de eltérő problémákat oldanak meg. Ezen az oldalon kiválaszthatja a megfelelőt.

## Röviden

| Felület                       | Ideális felhasználás                                                                                                                          | Átvitel                               | Szabvány                      |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------- | ----------------------------- |
| **A2A — ügynökök között**     | Együttműködés az A2A protokollt használó partnerügynökökkel                                                                                   | JSON-RPC 2.0 HTTP-n keresztül         | A2A v0.3 (nyílt specifikáció) |
| **ACP — CLI-ügynökregiszter** | A felhasználó gépére telepített CLI kódolóügynökök (Cursor, Cline, Codex CLI, Claude Code, Aider stb.) észlelése, regisztrálása és elindítása | HTTP REST                             | OmniRoute-specifikus          |
| **Felhőügynökök**             | Hosszú ideig futó kódolási feladatok beküldése külső felhőszolgáltatásoknak (Codex Cloud, Devin, Jules, Cursor Cloud)                         | HTTP REST + adatbázis-alapú feladatok | OmniRoute-specifikus          |

A három egymástól független — bármelyik részhalmazuk használható.

## Döntési fa

```
Szüksége van egy felhőszolgáltatásra, amely ezen a gépen kívül végzi el a munkát (Codex Cloud / Cursor Cloud / Devin / Jules)?
├─ IGEN → Felhőügynökök (POST /api/v1/agents/tasks)
└─ NEM → Folytatás
    │
    Van olyan partnerügynöke, amely használja az A2A protokollt, és együtt szeretne működni?
    ├─ IGEN → A2A (POST /a2a)
    └─ NEM → Folytatás
        │
        Szüksége van a helyileg telepített CLI kódolóügynökök listázására vagy konfigurálására?
        ├─ IGEN → ACP (GET /api/acp/agents)
        └─ NEM → Használja a sima /v1/chat/completions végpontot
```

## 1. A2A — ügynökök között

**Specifikáció:** [A2A v0.3](https://a2a-protocol.org)
**OmniRoute-végpont:** `POST /a2a` (JSON-RPC 2.0)
**Ügynökkártya:** `GET /.well-known/agent.json`

### Mikor használja

- Többügynökös rendszer építésekor, amelyben az OmniRoute az egyik partner
- Az OmniRoute útválasztási intelligenciájának (intelligens útválasztás, kvótakezelés stb.) elérhetővé tétele olyan keretrendszerek ügynökei számára, mint a Google ADK, illetve általános ügynökhálózatok számára
- Az OmniRoute szabványos felderítési és meghívási felülettel történő ellátásakor

### Metódusok

- `message/send` — üzenet beküldése és szinkron válasz fogadása
- `message/stream` — üzenet beküldése és SSE-adatfolyamon továbbított előrehaladási események fogadása
- `tasks/get` — feladat lekérése azonosító alapján
- `tasks/cancel` — futó feladat megszakítása

### Beépített képességek (6)

- `smart-routing` — kérés továbbítása az optimális kombináción keresztül
- `quota-management` — szolgáltatónkénti kvótaállapot jelentése
- `provider-discovery` — a telepített szolgáltatók és képességeik listázása
- `cost-analysis` — egy kérés vagy beszélgetés költségének becslése
- `health-report` — a megszakító, lehűlési és kizárási állapot összesítése szolgáltatónként
- `list-capabilities` — az ügynök elérhető képességeinek és metaadatainak felsorolása

### Részletes ismertető

Az átviteli részleteket, az ügynökkártya felépítését, a feladatok TTL-konfigurációját és az új képességek hozzáadására szolgáló sablont az [A2A-SERVER.md](./A2A-SERVER.md) dokumentumban találja.

## 2. ACP — CLI-ügynökök nyilvántartása

**OmniRoute-végpont:** `GET /api/acp/agents`
**Forrás:** `src/lib/acp/{index,manager,registry}.ts`

### Mi ez?

Az ACP az OmniRoute **helyi CLI-ügynöknyilvántartása**. Észleli, hogy mely programozási CLI-k vannak telepítve a gazdagépen (Cursor, Cline, Claude Code, Codex CLI, Continue stb.), meghatározza a verziójukat, és megjeleníti őket az irányítópulton, hogy a felhasználó beállíthassa az egyes CLI-ket az OmniRoute használatára.

Ez NEM külső protokoll — egy belső nyilvántartás, amely a „CLI Tools” felhasználói felületet és a CLI-ujjlenyomatok követését működteti (lásd: [CLI-TOOLS.md](../reference/CLI-TOOLS.md)).

### Mit csinál?

- Ellenőrzi, hogy milyen CLI-binárisok vannak telepítve a gazdagépen (operációs rendszertől függően a `which` / `where` parancsot használja)
- Beolvassa az egyes CLI-k verzióját (meghívja a `<bin> --version` parancsot)
- Opcionálisan felhasználó által definiált egyéni ügynököket fogad el (bináris elérési útja + verziólekérdezés + indítási argumentumok)
- A beállításokban tartósan tárolja az egyéni ügynököket
- Visszaadja az egyesített listát az irányítópultnak

### REST API

| Végpont           | Metódus | Leírás                                                                               | Hitelesítés |
| ----------------- | ------- | ------------------------------------------------------------------------------------ | ----------- |
| `/api/acp/agents` | GET     | Az észlelt és egyéni ügynökök listája (telepített/összes darabszám)                  | API-kulcs   |
| `/api/acp/agents` | POST    | Egyéni ügynök hozzáadása/frissítése/eltávolítása (műveletmegkülönböztető a törzsben) | API-kulcs   |

A POST-törzs szerkezete (`customAgentBodySchema` az `src/app/api/acp/agents/route.ts` fájlban):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Használati esetek

- Az irányítópult „CLI Tools” oldala felsorolja a telepített eszközöket, és segít beállítani mindegyiket az OmniRoute használatára
- Az egyéni ügynökök lehetővé teszik a haladó felhasználók számára olyan belső/saját fejlesztésű CLI-k regisztrálását, amelyeket az OmniRoute alapértelmezetten nem ismer
- Az észlelési eredmény szolgáltatja az adatokat a `cli-tools` ujjlenyomatmátrixhoz

### Mikor NE használja az ACP-t?

- Az ACP nem _futtat_ feladatokat. Csak észleli és konfigurálja a CLI-ket. Egy CLI tényleges meghívásához Önnek kell elindítania azt az OmniRoute által biztosított környezeti változókkal (`OPENAI_BASE_URL`, `OPENAI_API_KEY` stb.).

## 3. Felhőalapú ügynökök

**OmniRoute-végpontok:** `/api/v1/agents/tasks/*` (életciklus) + `/api/cloud/*` (háttér-infrastruktúra)
**Forrás:** `src/lib/cloudAgent/`

### Mi ez?

Egységes felület külső szolgáltatók felhőalapú programozási ügynökeihez. Ön elküld egy promptot és egy adattár-URL-t, az OmniRoute továbbítja ezeket a megfelelő felhőalapú ügynöknek, lekérdezi az állapotot, majd visszaadja az eredményeket.

### Támogatott ügynökök (4, mind megerősítve az `src/lib/cloudAgent/agents/` könyvtárban)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### Életciklus

```
POST /api/v1/agents/tasks
  → BaseAgent.createTask() ügynökosztályonként
  → a külső szolgáltatás megkezdi a munkát
  → létrejön egy feladatsor az adatbázisban (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → késleltetett állapotszinkronizálás a szolgáltatótól
  → visszaadja az aktuális állapotot + tervet + tevékenységnaplót
  ↓
POST /api/v1/agents/tasks/[id]   (művelet: "approve" | "message" | "cancel")
  → továbbítja a szolgáltatónak (vagy helyileg megszakítottként jelöli meg)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → helyi megszakítás
```

### Hitelesítés

⚠️ **Minden `/api/v1/agents/tasks/*` végpont kezelői hitelesítést igényel** (`588a0333` commit). A kizárólag Bearer-hitelesítést használó hívók a v3.8.0 óta 401-es választ kapnak.

### Részletes ismertető

A `CloudAgentBase` szerződésről, az egyes ügynökök sajátosságairól, a séma részleteiről és a hitelesítő adatok kezelésére szolgáló végpontokról lásd: [CLOUD_AGENT.md](./CLOUD_AGENT.md).

## Összehasonlítás: A2A kontra Cloud Agents

Mindkettő támogat „hosszú ideig futó feladatokat”, de különböző rétegekben:

| Szempont                    | A2A                                                                                                       | Cloud Agents                                            |
| --------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| Szabvány                    | Nyílt A2A v0.3                                                                                            | OmniRoute-specifikus                                    |
| A számítás futtatási helye  | Az OmniRoute-on belül (a konfigurált kombinációkat használja)                                             | Külső (Codex / Devin / Jules szerverek)                 |
| Feladat időtartama          | Alapértelmezett TTL: 5 perc (a `TaskManager` osztályban konfigurálható)                                   | Percektől órákig                                        |
| Tároló tartalmának ismerete | Nem (csak promptokat továbbít)                                                                            | Igen (tároló URL-je + ág)                               |
| Felhasználási eset          | Ügynökök közötti együttműködés, intelligens útválasztás szolgáltatásként                                  | „Valósítsd meg az X funkciót az Y tárolóban” delegálása |
| Hitelesítés                 | Opcionális `OMNIROUTE_API_KEY` az `/a2a` számára; felügyeleti hitelesítés az `/api/a2a/*` REST-segédekhez | Mindig felügyeleti hitelesítés                          |

## Integrációs példák

### Az OmniRoute A2A-képességeinek felderítése

```bash
curl http://localhost:20128/.well-known/agent.json
```

Visszaadja az Agent Cardot mind a 6 készséggel, az átviteli módokkal és a verzióval.

### Az OmniRoute meghívása A2A-ügynökként

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Irányítsd ezt a promptot"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### Telepített CLI-ügynökök listázása ACP-n keresztül

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Egyéni CLI-ügynök hozzáadása

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "Saját egyéni CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### Cloud Agent-feladat beküldése

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Valósítsd meg az X funkciót az Y tárolóban",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### Felhőfeladat állapotának lekérdezése

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## Mikor melyiket érdemes használni?

- **Chatbot-/copilot-frontend** → `/v1/chat/completions` (OpenAI-kompatibilis — nem ügynökprotokoll)
- **Több ügynök együttműködése** → A2A
- **Helyi CLI-k listázása az irányítópulton** → ACP
- **Hosszú ideig futó programozási feladatok delegálása felhőszolgáltatásoknak** → Cloud Agents
