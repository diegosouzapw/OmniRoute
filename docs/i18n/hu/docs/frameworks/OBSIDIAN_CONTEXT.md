## Mi ez?

Az OmniRoute egy **Obsidian**-tárolóhoz kapcsolódik **kontextusforrásként** — ez egy helyi Markdown
tudásbázis, amelyet az ügynökök a beépített MCP-kiszolgálón keresztül olvasnak és írnak. Az
integráció az asztali alkalmazáson belül futó **Obsidian Local REST API** közösségi bővítménnyel
kommunikál, így az ügynökök kereshetnek a jegyzetekben, olvashatják/írhatják/módosíthatják a fájlokat,
listázhatják a tároló tartalmát, napi/heti időszakos jegyzetekkel dolgozhatnak, címkéket kezelhetnek,
Obsidian-parancsokat futtathatnak, valamint (opcionálisan) összehangolhatják a kétirányú
asztali↔mobil tárolószinkronizálást.

A kliens (`src/lib/obsidian/api.ts`) a következőkkel egészíti ki a Local REST API-t:

- **Újrapróbálkozás növekvő várakozással** az átmeneti `5xx` hibákhoz, valamint **30 másodperces időtúllépés** az `AbortController` használatával.
- **Típusos hibabesorolás** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- Egy **közérthető „az Obsidian nem érhető el” útmutatás**, amely felhívja a figyelmet a gyakori porthibára
  (HTTP a `27123` porton, **nem** az MCP-végpont a `27124` porton), valamint a Tailscale-formátumra.
- Tárolóhoz viszonyított **útvonalkódolás**, hogy a szóközöket/perjeleket tartalmazó jegyzetútvonalak is biztonságosak legyenek.

## Beállítás

Az Obsidian-tokenhez vagy az alap-URL-hez **nincs környezeti változó** — mindkettő
az SQLite `key_value` táblájában (`obsidian` névtér) van tárolva a
`src/lib/db/obsidian.ts` segítségével. A token **tárolt állapotban titkosított** (AES-256-GCM,
egyszerű szöveges visszamenőleges kompatibilitási tartalékmegoldással). A konfiguráció az Endpoint
irányítópult **Context Sources** lapján (`ObsidianSourceCard`), vagy a beállítási REST API-n keresztül végezhető el.

> [!IMPORTANT]
> Az **Obsidian Local REST API** bővítménynek telepítve kell lennie és futnia kell. A REST-
> felülete a **HTTP `127.0.0.1:27123`** címen figyel (ez az alapértelmezett alap-URL). A `27124`
> port egy _különálló_ MCP/HTTPS-végpont, amelyet a beállítási útvonal kifejezetten elutasít.
> Másik eszközről történő kapcsolódáshoz használja a `http://<tailscale-ip>:27123` címet.

### Konfigurációs kulcsok (SQLite `key_value`, `obsidian` névtér)

| Kulcs             | Rendeltetés                                                 | Titkosított |
| ----------------- | ----------------------------------------------------------- | ----------- |
| `api_key`         | Local REST API bearer token                                 | igen        |
| `base_url`        | REST alap-URL (alapértelmezett: `http://127.0.0.1:27123`)   | nem         |
| `vault_path`      | A tároló könyvtárának abszolút útvonala (szinkronizáláshoz) | nem         |
| `webdav_username` | Generált WebDAV-felhasználónév (tárolószinkronizálás)       | nem         |
| `webdav_password` | Generált WebDAV-jelszó (tárolószinkronizálás)               | igen        |
| `webdav_enabled`  | Engedélyezve van-e a WebDAV-tárolószinkronizálás            | nem         |

### Konfigurálás REST-en keresztül

```bash
# A Local REST API token mentése és ellenőrzése (a POST állapotellenőrzéssel validál)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# A kapcsolat állapotának ellenőrzése (a válasz: connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# Kapcsolat bontása (törli a tárolt tokent)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Minden metódushoz irányítópult-hitelesítés szükséges. A `POST` elutasít minden, a `27124`
portot használó URL-t, és a tartós tárolás előtt a Local REST API állapot-végpontjának meghívásával ellenőrzi a tokent.

### WebDAV-tárolószinkronizálás

A `src/app/api/settings/obsidian/webdav/route.ts` egy opcionális, WebDAV-alapú
tárolószinkronizálást kezel (amelyet a `src/lib/obsidianSync.ts` vezérel). Az engedélyezésekor az OmniRoute egy
helyi tárolókönyvtárra mutat, és létrehoz egy véletlenszerű WebDAV-felhasználónév/jelszó párost:

```bash
# WebDAV-szinkronizálás engedélyezése egy tárolókönyvtárhoz (felhasználónevet/jelszót hoz létre)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# A WebDAV-szinkronizálás állapotának lekérése (a hitelesítő adatok csak engedélyezett állapotban kerülnek visszaadásra)
curl http://localhost:20128/api/settings/obsidian/webdav

# A WebDAV-szinkronizálás letiltása (törli a hitelesítő adatokat és a kezelt .stignore fájlt)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### API-kulcsonkénti kontextusforrás (opcionális)

Az Obsidian konfigurációja **API-kulcsonként** hatókörözhető az `api_key_context_sources` táblán
(`src/lib/db/apiKeyContextSources.ts`) keresztül. Ha egy MCP-hívás hitelesített API-
kulcsazonosítót tartalmaz, a `getObsidianConfigForApiKey()` előnyben részesíti az adott kulcs saját tokenjét/alap-URL-jét/tárolóútvonalát
(`source: "api_key"`), ellenkező esetben pedig a globális konfigurációt használja tartalékként (`source: "global"`).

## MCP-eszközök (22)

Az `open-sse/mcp-server/tools/obsidianTools.ts` fájlban vannak definiálva. A token/alap-URL feloldása
hívásonként történik (először API-kulcsonkénti, majd globális). Az OmniRoute **szinkronizációs szerverét**
használó eszközökhöz (a négy `obsidian_sync_*` eszközhöz) ezenkívül szükség van az OmniRoute
beállításaiban konfigurált szinkronizációs hitelesítési tokenre.

### Olvasási eszközök (`read:obsidian`)

| Eszköz                       | Leírás                                                                                                         |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Ellenőrzi, hogy a Local REST API elérhető-e, és megtörtént-e a hitelesítés.                                    |
| `obsidian_search_simple`     | Teljes szöveges keresés a jegyzetek tartalmában; fájlelérési utakat tartalmazó részleteket ad vissza.          |
| `obsidian_search_structured` | Keresés JSON Logic-kifejezéssel (and/or/regex/path szűrők).                                                    |
| `obsidian_read_note`         | Jegyzet beolvasása tárolóhoz viszonyított elérési út alapján; opcionálisan egy adott címsor/blokk/frontmatter. |
| `obsidian_list_vault`        | A tároló fájljainak és könyvtárainak listázása (bejegyzések fája).                                             |
| `obsidian_get_document_map`  | A jegyzet címsorstruktúrájának lekérése címsorok → sorszámok leképezéseként.                                   |
| `obsidian_get_note_metadata` | Frontmatter, címkék, hivatkozások, valamint karakter- és szószám lekérése a teljes tartalom nélkül.            |
| `obsidian_get_active_file`   | Az Obsidianben jelenleg aktív fájl elérési útjának és tartalmának lekérése.                                    |
| `obsidian_get_periodic_note` | Egy dátumhoz tartozó napi/heti/havi periodikus jegyzet lekérése (kihagyás esetén a mai).                       |
| `obsidian_get_tags`          | A tároló összes címkéjének listázása az előfordulási gyakoriságukkal együtt.                                   |
| `obsidian_list_commands`     | Az elérhető Obsidian-parancsazonosítók listázása (az `obsidian_execute_command` eszközzel használható).        |
| `obsidian_sync_status`       | Az OmniRoute szinkronizációs szerverének állapota: futás, tárolónév, port, üzemidő, utolsó szinkronizáció.     |
| `obsidian_sync_conflicts`    | A feloldatlan szinkronizációs ütközések listázása (elérési út, ütközési elérési út, észlelés időpontja).       |

### Írási eszközök (`write:obsidian`)

| Eszköz                           | Leírás                                                                                                  |
| -------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Jegyzet létrehozása vagy felülírása a megadott Markdown-tartalommal.                                    |
| `obsidian_append_note`           | Tartalom hozzáfűzése egy jegyzethez; opcionálisan egy adott címsorhoz/blokkhoz.                         |
| `obsidian_patch_note`            | Célzott hozzáfűzés/eléfűzés/csere egy címsornál, blokknál vagy frontmatter-mezőnél.                     |
| `obsidian_delete_note`           | Jegyzet végleges törlése a tárolóból.                                                                   |
| `obsidian_move_note`             | Jegyzet áthelyezése vagy átnevezése a tárolón belül.                                                    |
| `obsidian_execute_command`       | Obsidian-parancs végrehajtása a parancsazonosítója alapján.                                             |
| `obsidian_open_file`             | Fájl megnyitása az Obsidianben (létrehozza, ha nem létezik).                                            |
| `obsidian_sync_trigger`          | Azonnali kétirányú asztali gép↔mobil tárolószinkronizáció indítása.                                     |
| `obsidian_sync_resolve_conflict` | Szinkronizációs ütközés feloldása: `local` (mobil), `remote` (asztali gép) vagy `keep-both` megtartása. |

> [!NOTE]
> Az `obsidian_patch_note` céljai a `heading | block | frontmatter` `targetType`
> értékeket, a műveletei pedig az `append | prepend | replace` `operation` értékeket
> fogadják el, opcionális `createTargetIfMissing` beállítással. A négy `obsidian_sync_*`
> eszköz a helyi szinkronizációs szerverrel kommunikál (alapértelmezés szerint
> `http://127.0.0.1:27781`), és szinkronizációs tokent igényel.

### Hatókörök

Az olvasási eszközökhöz `read:obsidian`, az írási eszközökhöz pedig `write:obsidian`
szükséges. A kikényszerítés megegyezik a Notionéval — ezt az
`open-sse/mcp-server/server.ts` fájlban található `withScopeEnforcement()` kezeli,
az `OMNIROUTE_MCP_ENFORCE_SCOPES=true` beállítás aktiválja, az engedélyezett hatókörök
pedig az `OMNIROUTE_MCP_SCOPES` változóból vagy az API-kulcs hatóköri kontextusából
származnak. Lásd: [MCP-SERVER.md](./MCP-SERVER.md).

## Végpontok

| Metódus  | Útvonal                         | Cél                                                                            |
| -------- | ------------------------------- | ------------------------------------------------------------------------------ |
| `GET`    | `/api/settings/obsidian`        | A következőt adja vissza: `{ connected, hasToken, baseUrl, vaultPath }`.       |
| `POST`   | `/api/settings/obsidian`        | Elmenti és ellenőrzi a tokent (a `27124` portot elutasítja).                   |
| `DELETE` | `/api/settings/obsidian`        | Leválasztás (a tárolt token törlése).                                          |
| `GET`    | `/api/settings/obsidian/webdav` | WebDAV-szinkronizálás állapota és hitelesítő adatai (amikor engedélyezve van). |
| `POST`   | `/api/settings/obsidian/webdav` | Engedélyezi a WebDAV-szinkronizálást egy vaultkönyvtárhoz.                     |
| `DELETE` | `/api/settings/obsidian/webdav` | Letiltja a WebDAV-szinkronizálást.                                             |

> Ezek az irányítópult beállítási útvonalai. Maga a vault az Obsidian
> Local REST API-n (a konfigurált `base_url` címen), valamint a fenti MCP-eszközökön keresztül érhető el —
> nincs nyilvános `/v1` Obsidian proxyvégpont.

## Felhasználási esetek

- **Vaulton alapuló válaszok** — `obsidian_search_simple` / `obsidian_search_structured`,
  majd `obsidian_read_note`, így az ügynök a tényleges jegyzeteid alapján válaszol.
- **Jegyzetírás / naplózás** — `obsidian_write_note`, `obsidian_append_note` vagy
  a célzott `obsidian_patch_note` használatával az ügynök kimenetei, összefoglalók vagy napi jegyzetek
  (`obsidian_get_periodic_note`) menthetők a vaultba.
- **Navigáció a vaultban** — `obsidian_list_vault`, `obsidian_get_document_map` és
  `obsidian_get_tags` a struktúra feltérképezéséhez olvasás vagy írás előtt.
- **Obsidian-automatizálás** — `obsidian_list_commands` + `obsidian_execute_command`
  a bővítmények/parancsok ügynökből történő vezérléséhez; `obsidian_open_file` egy jegyzet felületen való megjelenítéséhez.
- **Mobilszinkronizálás** — engedélyezd a WebDAV-szinkronizálást, majd használd az `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  eszközöket az asztali gép és a mobil közötti szinkronizálás koordinálásához és az ütközések feloldásához.
