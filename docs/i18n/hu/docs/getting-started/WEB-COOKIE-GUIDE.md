A Web Cookie szolgáltatók lehetővé teszik, hogy az OmniRoute API-kulcs helyett a meglévő böngésző-munkamenetén keresztül használjon egy AI-szolgáltatást. Akkor hasznosak, ha a szolgáltatáshoz már hozzáfér annak webhelyén keresztül, és azt szeretné, hogy az OmniRoute ugyanazt a hitelesített munkamenetet használja.

Az API-kulcsot használó szolgáltatókkal ellentétben a Web Cookie szolgáltatók a böngésző által a webhelynek küldött hitelesítő adatokkal végzik a hitelesítést.

---

# Mielőtt elkezdené

> **Fontos:** A hitelesítő adatokat mindig egy **élő hálózati kérésből** másolja ki, **ne** a böngésző cookie-tárolójából.

Sok hitelesítési problémát az okoz, hogy a cookie-kat nem a megfelelő helyről másolják ki.

## NE másolja ki a cookie-tárolóból

A legtöbb böngészőben a tárolt cookie-k az alábbi helyen érhetők el:

```
DevTools
→ Application (vagy Storage)
→ Cookies
```

Bár ezek a cookie-k megfelelőnek tűnhetnek, előfordulhat, hogy:

- elavultak
- hiányosak
- nem tartalmaznak olyan cookie-kat, amelyeket a rendszer csak hitelesített kérések során küld el

Ezen értékek használata akkor is hitelesítési hibákhoz vezethet, ha érvényesnek tűnnek.

## Másolás élő kérésből

Ehelyett egy sikeres kérés cookie-jait használja:

```
DevTools
→ Network
→ Frissítse az oldalt
→ Nyisson meg egy csevegési vagy beszélgetési kérést
→ Request Headers
→ Cookie
```

A `Cookie` kérésfejléc pontosan azokat a hitelesítési adatokat tartalmazza, amelyeket a böngésző sikeresen használt.

A legtöbb Web Cookie szolgáltató esetében ezt az értéket kell beilleszteni az OmniRoute-ba.

---

# Általános beállítás

A beállítási folyamat a legtöbb Web Cookie szolgáltatónál azonos.

1. Jelentkezzen be a szolgáltató webhelyére.
2. Nyissa meg a böngésző fejlesztői eszközeit.
3. Nyissa meg a **Network** lapot.
4. Frissítse az oldalt.
5. Nyisson meg egy hitelesített csevegési vagy beszélgetési kérést.
6. Másolja ki a szükséges hitelesítő adatokat.
7. Nyissa meg az OmniRoute-ot.
8. Lépjen a **Providers → Add Provider** menüpontra.
9. Válassza ki a kívánt Web Cookie szolgáltatót.
10. Illessze be a hitelesítő adatokat.
11. Kattintson a **Test Connection** gombra.
12. Mentse a szolgáltatót.

A szükséges hitelesítő adatok pontos köre szolgáltatónként eltérő.

# Mire képesek és mire nem képesek a Web Cookie szolgáltatók

A Web Cookie szolgáltatók egy webhely csevegési felületét használják újra. **Nem** biztosítják ugyanazokat a képességeket, mint a hivatalos API-k.

## Támogatott

- Hitelesítés a meglévő böngésző-munkamenetével
- A fiókján keresztül elérhető modellek használata
- Csevegési válaszok streamelése
- Nincs szükség API-kulcsra

## Nem támogatott

- Függvényhívás
- Eszközhívás
- Automatikus fájlszerkesztés
- Ügynökalapú IDE-munkafolyamatok
- Kizárólag API-n keresztül elérhető funkciók

Ez elvárt működés, és **nem** hiba.

Ha eszközök végrehajtására, automatikus fájlszerkesztésre vagy más ügynökalapú munkafolyamatokra van szüksége, Web Cookie szolgáltató helyett használjon **API-kulcsot használó szolgáltatót**.

---

# Az ellenőrzés korlátai

A sikeres **Test Connection** vagy cookie-ellenőrzés csak azt igazolja, hogy a megadott hitelesítő adatok formátuma várhatóan megfelelő.

Az Issue #7857 megoldásáig a sikeres ellenőrzés **nem garantálja**, hogy a szolgáltató hitelesítése sikeres lesz.

Ha a hitelesítés továbbra is sikertelen, ellenőrizze, hogy a hitelesítő adatokat élő hálózati kérésből, nem pedig a böngésző cookie-tárolójából másolta-e ki.

---

# Hibaelhárítás

## A hitelesítés sikertelen

Ellenőrizze, hogy a hitelesítő adatokat innen másolta ki:

```
Network
→ Request Headers
→ Cookie
```

és **nem** innen:

```
Application
→ Cookies
```

---

## A cookie működik a böngészőben, de az OmniRoute-ban nem

Egyes szolgáltatók olyan cookie-kat is használnak, amelyeket csak hitelesített kérések során küldenek el.

Egy beszélgetés sikeres megnyitása után másolja ki újra a hitelesítő adatokat egy friss hálózati kérésből.

---

## A munkamenet lejárt

A Web Cookie szolgáltatók a meglévő böngésző-munkamenetét használják.

Ha a böngésző-munkamenete lejár, vagy kijelentkezik, új hitelesítőadat-készletet kell kimásolnia.

---

## A Test Connection sikeres, de a kérések sikertelenek

Az Issue #7857 megoldásáig a sikeres ellenőrzés nem garantálja, hogy a hitelesítési kérés sikeres lesz.

A további hibaelhárítás előtt másolja ki újra a hitelesítő adatokat egy friss, hitelesített kérésből.

# Bevált módszerek

- A hitelesítő adatokat friss, hitelesített kérésből másolja ki.
- Kerülje a régi cookie-k újbóli felhasználását.
- Tartsa aktívan a böngésző-munkamenetét a Web Cookie szolgáltatók használata közben.
- A kimásolt cookie-kat bizalmas hitelesítő adatokként kezelje.
- Ha függvényhívásra vagy ügynökalapú munkafolyamatokra van szüksége, használjon API-kulcsot használó szolgáltatókat.
