> Futásidejű kapcsolók, amelyek **újratelepítés nélkül** módosítják az OmniRoute viselkedését.
> Az itt felsorolt összes jelző definíciója a
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> fájlban található — ez az egyetlen hiteles forrás. Az irányítópult és a REST API egyaránt
> ebből a fájlból olvas, ezért az alábbi táblázat úgy készül, hogy 1:1 arányban megfeleljen neki.

---

## Mik azok a funkciójelzők?

A funkciójelző egy névvel ellátott kapcsoló (logikai vagy felsorolási típusú), amelynek értéke
futásidőben módosítható és az adatbázisban tartósan tárolható, a folyamat újratelepítése nélkül.
Minden jelzőt egy `FeatureFlagDefinition` ír le, amely rendelkezik `key`, `label`,
`description`, `category`, `defaultValue`, `type` mezőkkel és egy `requiresRestart` jelzéssel.

### Feloldási sorrend

Egy jelző **tényleges értékét** a
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) oldja fel a következő
prioritási sorrendben (a magasabb prioritású érvényesül):

1. **Adatbázis-felülírás** — a `key_value` táblában, a `feature_flags`
   névtér alatt tárolt érték (az irányítópulton vagy a REST API-n keresztül beállítva).
2. **Környezeti változó** — `process.env[<KEY>]`, ha be van állítva és nem üres.
3. **A definíció alapértelmezése** — a `featureFlagDefinitions.ts` fájlban megadott `defaultValue`.

Egy logikai jelző akkor tekinthető **engedélyezettnek**, ha tényleges értéke `"true"`,
`"1"` vagy `"yes"` (lásd: `isFeatureFlagEnabled()`).

> [!NOTE]
> A legtöbb jelzőhöz tartozik egy **azonos nevű** környezeti változó is,
> amelynek dokumentációja az [`ENVIRONMENT.md`](./ENVIRONMENT.md) fájlban található. A jelző adatbázisban
> megadott felülírása elsőbbséget élvez ezzel a környezeti változóval szemben. A
> `requiresRestart: true` beállítású jelző azonnal tartósan mentésre kerül, de csak a folyamat
> indulásakor olvassa be újra a rendszer — az ilyen jelző átkapcsolásakor egy
> **„Kiszolgáló újraindítása”** szalag jelenik meg az irányítópulton.

## Jelzők kapcsolása

### Irányítópult

Navigáljon az **Irányítópult → Beállítások → Funkciójelzők**
(`/dashboard/settings/feature-flags`) oldalra. A rács
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
a következőket támogatja:

- **Keresés** kulcs vagy leírás alapján, valamint **szűrés** kategória szerint (továbbá egy szintetikus
  **Újraindítást igényel** nézet).
- **Kapcsoló** a logikai jelzőkhöz és **legördülő lista** az enum jelzőkhöz
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- Jelzőnként egy **forrásjelvény** — `DB`, `ENV` vagy `DEF` —, amely megmutatja, honnan
  származik a tényleges érték.
- Egy **Visszaállítás** gomb (csak a `DB` forrású jelzőknél jelenik meg) a felülbírálás
  eltávolításához, alul pedig egy **Összes felülbírálás visszaállítása** gomb.
- Egy **Kiszolgáló újraindítása** szalag, amikor egy `requiresRestart` jelző megváltozik.

### REST API

Minden művelet egyetlen útvonalon keresztül történik:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Minden metódus hitelesített irányítópult-munkamenetet igényel (ellenkező esetben `401`).

#### `GET /api/settings/feature-flags`

Visszaadja az összes jelzőt a tényleges értékével, forrásával és egy összesítéssel együtt.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... mind a 75 jelző
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Egyetlen felülbírálás beállítása vagy eltávolítása. Törzs: `{ key: string; value?: string }`.
A `value` elhagyása eltávolítja a felülbírálást (visszaállítva a környezeti változó / alapértelmezett értéket).

```bash
# DB-felülbírálás beállítása
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# A felülbírálás eltávolítása ("value" nélkül)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

A válasz visszaadja az új `effectiveValue`/`source`, a `previousValue`/
`previousSource`, valamint a `requiresRestart` értékét. Az ismeretlen kulcsokat és a tartományon
kívüli enumértékeket a rendszer `400` állapotkóddal elutasítja.

#### `DELETE /api/settings/feature-flags`

Egyszerre törli az **összes** DB-felülbírálást, minden jelzőt visszaállítva a környezeti változóból származó /
alapértelmezett értékére. A visszatérési érték: `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> A `requiresRestart: true` értékű jelzők csak a folyamat újraindítása után lépnek érvénybe.
> Az irányítópult újraindítási folyamata meghívja a `POST /api/restart` végpontot, majd ismételten lekérdezi a
> `GET /api/health/ping` végpontot, amíg a kiszolgáló ismét elérhetővé nem válik.

## Vészhelyzeti költségkeret-tartalék

Az `OMNIROUTE_EMERGENCY_FALLBACK` (kategória: `runtime`, alapértelmezett érték: `true`) vezérli a
vészhelyzeti ingyenes tartalék útvonalat az
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)
fájlban. Ha engedélyezve van, a költségkeretüket kimerítő kérések teljes meghiúsulás helyett
egy ingyenes tartalék szolgáltatóhoz/modellhez lesznek irányítva. Állítsa `false` (vagy `0`) értékre — az
irányítópult kapcsolóján, egy DB-felülíráson vagy az `OMNIROUTE_EMERGENCY_FALLBACK`
környezeti változón keresztül — a viselkedés letiltásához és annak engedélyezéséhez, hogy a költségkeretüket kimerítő kérések
meghiúsuljanak. (Irányítópult-kapcsolóként megjelenítve a #3741 / #3752 PR-ekben.)
