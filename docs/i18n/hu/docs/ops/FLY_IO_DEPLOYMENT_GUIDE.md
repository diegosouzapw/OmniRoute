Ez a dokumentum az OmniRoute Fly.io platformra történő tényleges telepítési folyamatát ismerteti, a következő forgatókönyvekre kiterjedően:

- A jelenlegi projekt első telepítése a Fly.io platformra
- Későbbi kódfrissítések közzététele
- Ugyanezt a telepítési munkafolyamatot követő új projektek

Ez az útmutató a jelenlegi projekt ellenőrzött, működő konfigurációján alapul. Az alkalmazás neve `omniroute`.

---

## 1. Telepítési célok

- Platform: Fly.io
- Telepítési módszer: Közvetlen közzététel helyi `flyctl` használatával
- Futási környezet: A tárolóban meglévő `Dockerfile` és `fly.toml` használata
- Adatmegőrzés: A `/data` könyvtárhoz csatolt Fly Volume
- Elérési URL: `https://omniroute.fly.dev/`

---

## 2. A jelenlegi projekt fő konfigurációja

A jelenlegi tárolóban található `fly.toml` fájlról megerősítést nyert, hogy az alábbi kulcsfontosságú elemeket tartalmazza:

```toml
app = 'omniroute'
primary_region = 'sin'

[[mounts]]
  source = 'data'
  destination = '/data'

[processes]
  app = 'node run-standalone.mjs'

[http_service]
  internal_port = 20128

[env]
  TZ = "Asia/Shanghai"
  HOST = "0.0.0.0"
  HOSTNAME = "0.0.0.0"
  BIND = "0.0.0.0"
```

Megjegyzések:

- Az `app = 'omniroute'` határozza meg, hogy a telepítés melyik Fly-alkalmazást célozza
- A `destination = '/data'` határozza meg az állandó kötet csatolási könyvtárát
- Ennél a projektnél be kell állítani a `DATA_DIR=/data` értéket, különben az adatbázis és a kulcsok a konténer ideiglenes könyvtárába kerülnek

## 3. Előfeltételek

### 3.1 A Fly CLI telepítése

Windows PowerShell:

```powershell
pwsh -Command "iwr https://fly.io/install.ps1 -useb | iex"
```

Ha a telepítőszkript nem működik az Ön környezetében, manuálisan is letöltheti a `flyctl` bináris fájlt, és hozzáadhatja a `PATH` környezeti változóhoz.

### 3.2 Bejelentkezés a Fly-fiókba

```powershell
flyctl auth login
```

### 3.3 A bejelentkezési állapot ellenőrzése

```powershell
flyctl auth whoami
flyctl version
```

## 4. A jelenlegi projekt első telepítése

### 4.1 A kód klónozása és belépés a könyvtárba

```powershell
git clone https://github.com/diegosouzapw/OmniRoute.git
cd OmniRoute
```

### 4.2 Az alkalmazás nevének ellenőrzése

Nyissa meg a `fly.toml` fájlt, és ellenőrizze a következő sort:

```toml
app = 'omniroute'
```

Ha egy saját, új alkalmazásba telepít, módosíthatja egy globálisan egyedi névre, például:

```toml
app = 'omniroute-yourname'
```

Megjegyzés:

- Győződjön meg arról, hogy a konzolon látható alkalmazás megegyezik a `fly.toml` fájlban szereplő `app` értékével
- Ha korábban más nevet használt, például `oroute`, ne keverje össze az `omniroute` névvel

### 4.3 Az alkalmazás létrehozása

Ha az alkalmazás még nem létezik:

```powershell
flyctl apps create omniroute
```

Ha módosította az alkalmazás nevét, cserélje le az `omniroute` nevet a választott névre.

### 4.4 Első telepítés

```powershell
flyctl deploy
```

## 5. Szükséges paraméterek

Ehhez a projekthez ajánlott legalább az alábbi paramétereket konfigurálni a Fly.io platformon.

### 5.1 Ellenőrzött paraméterek

Ezeket a paramétereket tényleges telepítések során használták a jelenlegi `omniroute` alkalmazásban:

- `API_KEY_SECRET`
- `DATA_DIR`
- `JWT_SECRET`
- `MACHINE_ID_SALT`
- `NEXT_PUBLIC_BASE_URL`
- `OMNIROUTE_WS_BRIDGE_SECRET` (éles környezetben kötelező — a WebSocket-híd hitelesítésére szolgál)
- `STORAGE_ENCRYPTION_KEY`

### 5.2 Az `INITIAL_PASSWORD` paraméterről

A jelenlegi projektben nincs beállítva az `INITIAL_PASSWORD`, mert ennél a telepítésnél nincs rá szükség.

Ha nincs beállítva:

- Az indítási napló jelzi, hogy az alapértelmezett jelszó `CHANGEME`
- A telepítés után a lehető leghamarabb módosítsa a bejelentkezési jelszót a rendszerbeállításokban

Ha felügyelet nélkül szeretné inicializálni a háttérrendszer jelszavát, később hozzáadhatja:

- `INITIAL_PASSWORD`

## 6. Ajánlott paraméterek

### 6.1 Titkos értékek konfigurációja

A következő változók használata ajánlott a Fly Secrets szolgáltatásban:

| Változó                            | Ajánlás                    | Leírás                                                          |
| ---------------------------------- | -------------------------- | --------------------------------------------------------------- |
| `API_KEY_SECRET`                   | Kötelező                   | API-kulcsok generálásához és ellenőrzéséhez használatos         |
| `JWT_SECRET`                       | Kötelező                   | Bejelentkezési munkamenetekhez és JWT-aláíráshoz használatos    |
| `OMNIROUTE_WS_BRIDGE_SECRET`       | Éles környezetben kötelező | WebSocket-híd hitelesítési titkos értéke                        |
| `STORAGE_ENCRYPTION_KEY`           | Kifejezetten ajánlott      | Titkosítja a bizalmas kapcsolati információkat a tárolás során  |
| `MACHINE_ID_SALT`                  | Ajánlott                   | Stabil gépazonosítót generál                                    |
| `INITIAL_PASSWORD`                 | Opcionális                 | Beállítja a kezdeti háttérrendszer-jelszót az első telepítéskor |
| OAuth/API privát hitelesítő adatok | Szükség szerint            | Külső platform hitelesítési konfigurációja                      |

### 6.2 A jelenlegi projekthez ajánlott értékek

| Változó                | Ajánlott érték              |
| ---------------------- | --------------------------- |
| `DATA_DIR`             | `/data`                     |
| `NEXT_PUBLIC_BASE_URL` | `https://omniroute.fly.dev` |

Megjegyzések:

- A `DATA_DIR=/data` kritikus fontosságú, és meg kell egyeznie a Fly Volume csatolási pontjával
- A `NEXT_PUBLIC_BASE_URL` értéket az ütemező, az előtérbeli visszahívások és hasonló esetek használják

### 6.3 Az OAuth visszahívási URL konfigurációja

Ha OAuth-alapú szolgáltatókat (például Antigravity, Gemini, Cursor) szeretne engedélyezni a Fly.io-telepítésen, ügyeljen a következő két pontra:

1. **Állítsa a `NEXT_PUBLIC_BASE_URL` értékét a nyilvános HTTPS-tartományára**

   ```powershell
   flyctl secrets set NEXT_PUBLIC_BASE_URL=https://omniroute.fly.dev -a omniroute
   ```

   Ha egyéni tartományt használ, cserélje le a megfelelő tartományra (például `https://omniroute.yourdomain.com`).

2. **Konfigurálja a visszahívási URL-t a szolgáltató konzolján**

   Minden OAuth-szolgáltató ugyanazt az egyetlen `/callback` visszahívási útvonalat használja — NINCS szolgáltatónként külön visszahívási útvonal:

   ```text
   <NEXT_PUBLIC_BASE_URL>/callback
   ```

   Például a Gemini, az Antigravity, a Cursor vagy a GitLab Duo esetében egyaránt:
   - `https://omniroute.fly.dev/callback`

   Ha a `NEXT_PUBLIC_BASE_URL` nem egyezik meg a szolgáltatónál regisztrált visszahívási URL-lel, az OAuth-folyamat a böngésző átirányítási lépésénél meghiúsul.

## 7. Titkos értékek beállítása egyetlen paranccsal

A következő parancsok biztonságos véletlenszerű értékeket generálnak, és egyetlen lépésben beírják a jelenlegi projekthez szükséges összes paramétert a Fly Secrets szolgáltatásba.

Megjegyzések:

- Nem tartalmazza az `INITIAL_PASSWORD` értéket
- A jelenlegi `omniroute` projekthez készült

```powershell
$apiKeySecret = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$jwtSecret = [Convert]::ToHexString((1..64 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$machineIdSalt = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$storageKey = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$wsBridgeSecret = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()

flyctl secrets set `
  API_KEY_SECRET=$apiKeySecret `
  JWT_SECRET=$jwtSecret `
  MACHINE_ID_SALT=$machineIdSalt `
  STORAGE_ENCRYPTION_KEY=$storageKey `
  OMNIROUTE_WS_BRIDGE_SECRET=$wsBridgeSecret `
  DATA_DIR=/data `
  NEXT_PUBLIC_BASE_URL=https://omniroute.fly.dev `
  -a omniroute
```

Linux / macOS rendszeren az `openssl rand -hex 32` parancsot is használhatja:

```bash
flyctl secrets set OMNIROUTE_WS_BRIDGE_SECRET=$(openssl rand -hex 32) -a omniroute
```

Megjegyzések:

- Az `OMNIROUTE_WS_BRIDGE_SECRET` éles környezetben kötelező; hiánya megszakítja a WebSocket-híd kézfogási folyamatát

Ha kezdeti jelszót is szeretne beállítani:

```powershell
flyctl secrets set INITIAL_PASSWORD=your-strong-password -a omniroute
```

## 9. Későbbi frissítések és kiadások

A kód frissítése után a kiadási folyamat egyszerű:

```powershell
git pull
flyctl deploy
```

Ha csak a paramétereket kell frissítenie a kód módosítása nélkül:

```powershell
flyctl secrets set KEY=value -a omniroute
```

A Fly automatikusan végrehajtja a gépek fokozatos frissítését.

### 9.1 A forrásrepozitórium frissítéseinek követése a fork `fly.toml` fájljának megőrzésével

Ha a jelenlegi repozitórium egy fork, és szinkronizálni szeretné a frissítéseket a `https://github.com/diegosouzapw/OmniRoute` forrásrepozitóriumból, kövesse az alábbi munkafolyamatot.

Először ellenőrizze a távoli repozitóriumokat:

```powershell
git remote -v
```

Legalább a következőket kell látnia:

- A saját forkjára mutató `origin`
- Az eredeti repozitóriumra mutató `upstream`

Ha az `upstream` nincs konfigurálva, adja hozzá:

```powershell
git remote add upstream https://github.com/diegosouzapw/OmniRoute.git
```

Az upstream repozitóriummal való szinkronizálás előtt kérje le a legújabb commitokat és címkéket:

```powershell
git fetch upstream --tags
```

Ellenőrizze az aktuális verziót és az upstream címkéket:

```powershell
git describe --tags --always
git show --no-patch --oneline v3.4.7
```

> Megjegyzés: A projekt aktuális verziója `v3.8.0`. Az alábbi `v3.4.7` hivatkozások kizárólag korábbi példaként maradtak meg. A tényleges kiadásokhoz használja a `:latest` címkét vagy az aktuális verziócímkét (például `:v3.8.0`).

Ha az upstream legújabb `main` ágát úgy szeretné beolvasztani, hogy közben kényszerítetten megőrzi a fork `fly.toml` fájlját, kövesse ezt a munkafolyamatot:

```powershell
git merge upstream/main
git checkout HEAD~1 -- fly.toml
git add -- fly.toml
git commit -m "chore(deploy): keep fork fly.toml"
git push origin main
```

Megjegyzések:

- A `git merge upstream/main` szinkronizálja a legújabb kódot az eredeti repozitóriumból
- A `git checkout HEAD~1 -- fly.toml` visszaállítja a fork saját `fly.toml` fájlját az összevonás előtti állapotból
- Ha az upstream nem módosította a `fly.toml` fájlt, ez a lépés nem eredményez eltérést
- Ha az upstream módosította a `fly.toml` fájlt, ez a lépés biztosítja, hogy a Fly-alkalmazás neve, a kötet csatolása, a régió és a forkra jellemző egyéb telepítési konfiguráció ne íródjon felül

Ha egy adott kiadási címkéhez (például `v3.4.7`) szeretne igazodni, először ellenőrizze, hogy a címke már szerepel-e az `upstream/main` ágban:

```powershell
git merge-base --is-ancestor v3.4.7 upstream/main
```

A sikeres visszatérési érték azt jelenti, hogy az `upstream/main` már tartalmazza ezt a verziót; így egyszerűen beolvaszthatja az `upstream/main` ágat.

### 9.2 Szabványos kiadási sorrend az upstream szinkronizálása után

Az eredeti repozitóriummal való szinkronizálás után kövesse ezt az ajánlott kiadási sorrendet:

1. `git fetch upstream --tags`
2. `git merge upstream/main`
3. Állítsa vissza a fork `fly.toml` fájlját
4. `git push origin main`
5. `flyctl deploy`
6. `flyctl status -a omniroute`
7. `flyctl logs --no-tail -a omniroute`

Ez a tényleges munkafolyamat, amelyet a jelenlegi projekt `v3.4.7` verzióra való frissítésekor használtak (a példa egy korábbi verzióra hivatkozik; a jelenlegi tényleges verzió `v3.8.0`).

## 11. A sikeres telepítés jelei

Sikeres telepítés után a naplókban az alábbihoz hasonló tartalomnak kell megjelennie:

```text
[bootstrap] A titkos adatok mentési helye: /data/server.env
[DB] Az SQLite-adatbázis készen áll: /data/storage.sqlite
```

Ez a két pont kritikus fontosságú:

- A `/data/server.env` megerősíti, hogy a futásidejű titkos adatok a tartós köteten vannak tárolva
- A `/data/storage.sqlite` megerősíti, hogy az adatbázis a tartós köteten van tárolva

Ha ehelyett `/app/data/...` útvonalat lát, akkor a `DATA_DIR` konfigurációja hibás, és azonnal javítani kell.

## 12. Gyakori problémák

### 12.1 A `Secrets` oldal üres

Ennek általában két oka lehet:

- Még nem futtatta a `flyctl secrets set` parancsot
- Egy másik alkalmazást tekint meg (például az `oroute` alkalmazást az `omniroute` helyett)

### 12.2 A `flyctl deploy` az `app not found` hibát jelzi

Először hozza létre az alkalmazást:

```powershell
flyctl apps create omniroute
```

### 12.3 A `fly.toml` elemzése sikertelen

Ellenőrizze a következőket:

- Vannak-e hibás vagy értelmezhetetlen karakterek a megjegyzésekben
- Helyesek-e a TOML-idézőjelek és a behúzások

### 12.4 Az adatok nem maradnak meg

Ellenőrizze mindkét alábbi feltételt:

- A `fly.toml` tartalmazza a `destination = '/data'` beállítást
- A `DATA_DIR` értéke `/data`

### 12.5 Futtatható `INITIAL_PASSWORD` nélkül?

Igen, futtatható. Ilyenkor az alapértelmezett `CHANGEME` jelszót használja. Éles környezetben ajánlott a háttérrendszer jelszavát a lehető leghamarabb megváltoztatni.

## 13. Új projektekhez való újrafelhasználás

Ha e dokumentum alapján telepít egy új projektet, csak a következőket kell módosítania:

1. Módosítsa az `app` értékét a `fly.toml` fájlban
2. Módosítsa a `NEXT_PUBLIC_BASE_URL` értékét
3. Tartsa meg a `DATA_DIR=/data` beállítást
4. Generálja újra az `API_KEY_SECRET`, `JWT_SECRET`, `MACHINE_ID_SALT` és `STORAGE_ENCRYPTION_KEY` értékeket
5. Az első telepítés után ellenőrizze, hogy a naplók a `/data` könyvtárba íródnak-e

Ne használja újra egy korábbi projekt kulcsait.

## 14. Minimális kiadási ellenőrzőlista az aktuális projekthez

A későbbi kiadásokhoz leggyakrabban használt parancsok:

```powershell
flyctl auth whoami

flyctl secrets list -a omniroute
flyctl deploy
flyctl logs --no-tail -a omniroute
```

Normál kiadás esetén az alapvető parancs egyszerűen:

```powershell
flyctl deploy
```

Új környezetben történő első telepítés esetén az alapvető lépések:

1. `flyctl auth login`
2. `flyctl apps create omniroute`
3. `flyctl secrets set ... -a omniroute`
4. `flyctl deploy`
5. `flyctl logs --no-tail -a omniroute`
