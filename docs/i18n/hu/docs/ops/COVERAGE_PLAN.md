Utolsó frissítés: 2026-06-28

> Állapot a 2026-05-13-i mérés alapján: sorok 82.58%, utasítások 82.58%, függvények 84.23%, elágazások 75.22%. Az 1–5. fázis befejeződött. Jelenleg a 6. fázis (>=85%) és a 7. fázis (>=90%) áll a középpontban.

## Kiindulási érték

A jelentés kiszámítási módjától függően több különböző lefedettségi érték létezik. A tervezéshez ezek közül csak egy használható.

| Mérőszám           | Hatókör                                                          | Utasítások / sorok | Elágazások | Függvények | Megjegyzések                                                      |
| ------------------ | ---------------------------------------------------------------- | -----------------: | ---------: | ---------: | ----------------------------------------------------------------- |
| Korábbi            | Régi `npm run test:coverage`                                     |             79.42% |     75.15% |     67.94% | Felfújt: számolja a tesztfájlokat, és kizárja az `open-sse` részt |
| Diagnosztikai      | Csak forráskód, a tesztek és az `open-sse` kizárásával           |             68.16% |     63.55% |     64.06% | Csak az `src/**` elkülönítésére használható                       |
| Ajánlott kiindulás | Csak forráskód, a tesztek kizárásával, az `open-sse` bevonásával |             82.58% |     75.22% |     84.23% | Ez a javítandó, teljes projektre vonatkozó kiindulási érték       |

Az ajánlott kiindulási értéket kell optimalizálni.

## Szabályok

- A lefedettségi célok a forrásfájlokra vonatkoznak, nem a `tests/**` fájlokra.
- Az `open-sse/**` a termék része, ezért továbbra is a hatókörben kell maradnia.
- Az új kód nem csökkentheti a lefedettséget az érintett területeken.
- A megvalósítás részletei helyett a viselkedés és az elágazások kimeneteleinek tesztelését kell előnyben részesíteni.
- Az `src/lib/db/**` esetében az átfogó mockok helyett ideiglenes SQLite-adatbázisokat és kis méretű fixture-öket kell előnyben részesíteni.

## Jelenlegi parancskészlet

- `npm run test:coverage`
  - Az egységtesztkészlet forráskód-lefedettségének fő ellenőrzési kapuja
  - `text-summary`, `html`, `json-summary` és `lcov` jelentéseket készít
- `npm run coverage:report`
  - Részletes, fájlonkénti jelentés a legutóbbi futtatásból
- `npm run test:coverage:legacy`
  - Kizárólag korábbi eredményekkel való összehasonlításhoz

## Ratchet-szabályzat

Csak akkor frissítsd az `npm run test:coverage` küszöbértékeit, ha a projekt ténylegesen, kényelmes ráhagyással meghaladja a következő mérföldkövet.

**Jelenlegi küszöb:** az `npm run test:coverage` a következő értékeket követeli meg: **60 utasítás / 60 sor / 60 függvény / 60 elágazás** (a metrika alapértékét a Quality-Gates 6A.1 fázisában módosítottuk — a korábbi 82.58%-os alapérték túl magas volt, mert beleszámította a tesztfájlokat, az `open-sse` csomagot pedig kihagyta). A `test:coverage:legacy` parancs megőrzi a régi 50/50/50-es metrikát a korábbi eredményekkel való összehasonlításhoz.

A legfrissebb jelentés küszöbértékeinek eseti ellenőrzéséhez használd a következőt:

```bash
node scripts/check/test-report-summary.mjs --threshold 75
```

Ajánlott ratchet-sorrend (a sorrend: `utasítások-sorok / elágazások / függvények`):

1. 55/60/55
2. 60/62/58
3. 65/64/62
4. 70/66/66
5. 75/70/72 <-- jelenlegi küszöb (75/70/75)
6. 80/75/78
7. 85/80/84
8. 90/85/88

A következő ratchet-célérték `80/75/78`, amint az elágazáslefedettség két egymást követő futtatás során 78% felett marad.

## Ismert hiányosság

A jelenlegi lefedettségi parancs a fő Node egységtesztkészletet méri, és az abból elért forráskódot is figyelembe veszi, beleértve az `open-sse` csomagot. A Vitest lefedettségét még nem egyesíti egyetlen egységes jelentésbe. Ezt az egyesítést később érdemes elvégezni, de nem akadálya a 60%-ról 80%-ra történő növelés megkezdésének.
