## Döntés

| Szolgáltatócsalád                           | OmniRoute ID            | Globális régió | Kínai régió |
| ------------------------------------------- | ----------------------- | -------------- | ----------- |
| Alibaba Cloud Model Studio (használatalapú) | `alibaba`               | Szingapúr      | Peking      |
| Alibaba Cloud Token Plan                    | `bailian-coding-plan`   | Szingapúr      | Peking      |
| Qwen Cloud (használatalapú)                 | `qwen-cloud`            | Globális       | Peking      |
| Qwen Cloud Token Plan                       | `qwen-cloud-token-plan` | Szingapúr      | Peking      |

A meglévő `alibaba-cn` ID futásidejű kompatibilitási aliasként továbbra is megmarad a mentett kapcsolatokhoz, modellútvonalakhoz, kombinációkhoz és előzményhasználati adatokhoz. Az irányítópulton lévő kártyája beolvad az `alibaba` kártyájába; nincs szükség az adatbázis átírására.

A használatalapú Qwen Cloud és az Alibaba Cloud Model Studio jelenleg ugyanazokat a DashScope-kompatibilis futásidejű gazdagépeket használja, de továbbra is külön szolgáltatói identitások maradnak, mivel a felhasználók eltérő termékfelületeken szereznek be kulcsokat és kezelik a fiókjaikat. Az Alibaba és a Qwen Cloud Token Plan termékek eltérő végpontcsaládokat használnak, ezért mind a négy termék külön szolgáltatói ID-val rendelkezik.

## Végpontmátrix

| Szolgáltatócsalád       | `global-sg`                                                              | `china-beijing`                                                      | Adatátviteli formátum |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | --------------------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI                |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic             |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI                |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI                |

Az API-kulcsnak és a végpontnak ugyanahhoz a termékhez és régióhoz kell tartoznia. Egy régió kiválasztása módosítja az ellenőrzéshez és a normál kérésekhez használt előre beállított végpontot.

## Kapcsolati szerződés

Az új kapcsolatok a stabil régiókulcsot a `providerSpecificData` mezőben tárolják:

```json
{
  "region": "global-sg"
}
```

Az engedélyezett értékek: `global-sg` és `china-beijing`. A végpont központilag, a szolgáltatói ID és a régió alapján származik. A nem előre beállított `providerSpecificData.baseUrl` továbbra is explicit üzemeltetői felülbírálásként működik, és elsőbbséget élvez, míg a régi, mentett, előre beállított URL-eket a rendszer visszanormalizálja a regionális mátrixra.

Ez bővíthetővé teszi a kapcsolati sémát: újabb régió adható hozzá a feloldóhoz anélkül, hogy új szolgáltatói kártyát kellene létrehozni vagy módosítani kellene a mentett szolgáltatói ID-kat.

## Kompatibilitás és bevezetés

1. Adja hozzá a regionális végpontfeloldót, és tartsa meg a jelenlegi globális alapértelmezéseket.
2. Használja az élő regionális DashScope `/models` felderítést az `alibaba`, annak `alibaba-cn` kompatibilitási
   azonosítója és a `qwen-cloud` esetében. A válaszaik először egy szöveggenerálási szűrőn haladnak át, mivel az általános
   végpont kép-, videó-, hang-, beágyazási és egyéb, nem csevegési modelleket is visszaad. A `qwen-cloud`
   ezután alkalmazza a szolgáltatói regisztrációs adatbázisában deklarált, karbantartott engedélyezési listát. Az Alibaba Model Studio
   és a Qwen Cloud külön gondozott katalógusokat tart fenn, annak ellenére, hogy jelenleg azonos futtatási gazdagépeket használnak.
3. Regisztrálja a `qwen-cloud-token-plan` szolgáltatót a Token Plan jelenlegi szövegmodell-engedélyezési listájával.
4. Adjon típusos régióválasztót a kapcsolat hozzáadására/szerkesztésére szolgáló párbeszédpanelekhez.
5. Rejtse el a duplikált `alibaba-cn` kártyát, és jelenítse meg annak meglévő kapcsolatait az `alibaba`
   szolgáltatói oldalán.
6. Tartsa elérhetően az egyéni végpont-felülbírálásokat a speciális és munkaterület-specifikus telepítésekhez.

A Token Plan médiamodelljei továbbra sem részei a csevegési katalógusnak, mivel dedikált végpontokat használnak.
A `wan2.7-image` és a `wan2.7-image-pro` az `open-sse/config/imageRegistry.ts` fájlban van regisztrálva;
a `happyhorse-1.1-i2v`, a `happyhorse-1.1-t2v` és a `happyhorse-1.1-r2v` pedig az
`open-sse/config/videoRegistry.ts` fájlban. Mindkét regisztrációs adatbázis újra felhasználja a `qwen-cloud-token-plan`
kapcsolati identitását és annak régióspecifikus hitelesítő adatait.

A normál Qwen Cloud külön használatalapú kép- és videókatalógusokkal rendelkezik a `qwen-cloud`
identitás alatt. Képmodelljei: `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` és `z-image-turbo`. Videómodelljei:
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` és
`wan2.7-videoedit`. Ezek a modellek kizárólag a normál `qwen-cloud` kapcsolatot és a regionális
DashScope médiavégpontot használják újra. A Token Plan és a használatalapú regisztrációs adatbázisok nem öröklik és nem egyesítik
egymás modelllistáit.

A `bailian-coding-plan` identitás szintén saját média-engedélyezési listákkal rendelkezik:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` és `qwen-image-2.0-pro` a kép-
generáláshoz, továbbá
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` és `happyhorse-1.1-r2v` a videó-
generáláshoz. Kizárólag a Bailian Coding Plan kapcsolatot és a regionális Coding Plan végpontot használja.
Kép- és videóregisztrációs adatbázisai egyik Qwen Cloud szolgáltatótól sem örökölnek, és azokkal nem egyesülnek.

A normál `alibaba` identitás külön kép- és videó-engedélyezési listákkal rendelkezik. Képmodelljei:
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` és `wan2.6-t2i`. Hozzáadott videómodelljei: `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` és `wan2.7-videoedit`. Ezek a modellek kizárólag az Alibaba Model Studio
kapcsolatot és annak kiválasztott regionális médiavégpontját használják; nem kerülnek be egyetlen Coding Plan- vagy Qwen
Cloud-regisztrációs adatbázisba sem.

A Qwen Cloud Token Plan csevegési katalógusa az Individual csomag pontos karakterlánc-egyezésen alapuló szöveges engedélyezési listáját követi:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` és
`deepseek-v4-pro`. A Wan- és HappyHorse-bejegyzések a különálló kép-/videógenerálási API-khoz tartoznak.

Az Alibaba Token Plan ugyanezt a hat jelenlegi szöveggenerálási modellazonosítót teszi elérhetővé az
Anthropic-kompatibilis végpontján keresztül. A szingapúri beállítása a meglévő `global-sg` régiókulcsot tárolja;
csak a felhasználónak megjelenített címke tér el azoktól a szolgáltatócsaládoktól, amelyek ezt a régiót Global néven jelölik.

A normál Qwen Cloud csevegési katalógusa szándékosan szűkebb, mint a teljes élő szöveges válasz. A
karbantartott engedélyezési listája az `open-sse/config/providers/registry/qwen-cloud/index.ts` fájlban található; az élő
felderítés csak azokat az azonosítókat adja vissza, amelyek mind a szolgáltatói válaszban, mind ebben a regisztrációs listában szerepelnek.

Az Alibaba Model Studio ugyanazt az élő metszetképzési szabályt követi az önállóan karbantartott,
`open-sse/config/providers/registry/alibaba/index.ts` fájlban található engedélyezési listájával. Az `alibaba-cn` kompatibilitási
szolgáltató újra felhasználja ezt a katalógust, miközben a felderítést a pekingi végponttal végzi.
