**Az OmniCopilot** az OmniRoute által kiszolgált összes modellt elérhetővé teszi a _natív_ GitHub Copilot Chat
modellválasztójában. Nincs második oldalsáv, nincs külön csevegőfelület — a Copilot ügynökmódja, eszközhívása,
MCP-kiszolgálói és egyéni utasításai mind tovább működnek, csak éppen az Ön által kiválasztott modellen futnak.

|                         |                                                                                                                                                 |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Telepítés (VS Code)** | [Marketplace → `diegosouzapw.omnicopilot`](https://marketplace.visualstudio.com/items?itemName=diegosouzapw.omnicopilot)                        |
| **Telepítés (forkok)**  | [Open VSX](https://open-vsx.org/extension/diegosouzapw/omnicopilot) — Cursor, Windsurf, VSCodium, Theia, code-server, Gitpod, Antigravity, Kiro |
| **Forrás / hibajegyek** | [github.com/diegosouzapw/OmniCopilot](https://github.com/diegosouzapw/OmniCopilot) (MIT)                                                        |
| **Követelmény**         | VS Code 1.104+                                                                                                                                  |

> **Nincs szükség Copilot-előfizetésre.** A VS Code 1.122 óta a nyelvimodell-szolgáltatók
> GitHub-bejelentkezés és bármilyen Copilot-csomag nélkül is működnek. A soron belüli kódkiegészítések és a
> beágyazásalapú funkciók nem tartoznak a szolgáltatói API hatókörébe, ezért továbbra is igénylik a Copilotot.

## Beállítás

1. **Indítsa el az OmniRoute-ot** — `npm install -g omniroute && omniroute` (az irányítópult címe: `http://localhost:20128`).
2. **Telepítse a bővítményt** — keressen rá az „OmniRoute” kifejezésre a Bővítmények nézetben.
3. **Válasszon modellt** — Copilot Chat → modellválasztó → **Manage Models…** → **OmniRoute**, majd jelölje be
   a kívánt modelleket.

Ha az OmniRoute az alapértelmezett porton fut, nincs szükség beállításra. Távoli példány esetén nyissa meg az
**OmniRoute ikont a Tevékenységsávon** (vagy futtassa az `OmniRoute: Manage Connection` parancsot), és állítsa be a következőket:

- **Kiszolgáló URL-címe** — a kiszolgáló gyökércíme, például `http://192.168.0.15:20128`. A `/v1` utótagot
  a bővítmény fűzi hozzá; ne adja meg.
- **API-kulcs** — csak akkor szükséges, ha a kiszolgálón be van állítva a `REQUIRE_API_KEY`. Tárolása az operációs rendszer kulcstárában történik a VS
  Code SecretStorage használatával, soha nem a `settings.json` fájlban.

## Mit jelenít meg a modellválasztó?

A bővítmény nem a nyers `GET /v1/models` választ jeleníti meg — átalakítja azt, ezért a látható
darabszám két szándékos okból is kisebb a katalógus méreténél.

### Modellenként egy azonosítót kér le

A `MODELS_CATALOG_PREFIX_MODE` alapértelmezett értéke **`dual`**, amely minden modellt kétszer tesz közzé — egyszer
a rövid álnévelőtaggal, egyszer pedig a szolgáltató kanonikus előtagjával —, így a régebbi klienskonfigurációk
mindkét formát továbbra is fel tudják oldani:

```
cc/claude-sonnet-4-6        ← álnévelőtag
claude/claude-sonnet-4-6    ← kanonikus előtag, ugyanaz a modell
```

A bővítmény a **`GET /v1/models?prefix=alias`** végpontot kéri le, így modellenként egy azonosító érkezik,
anélkül, hogy a többi kliens számára módosítaná a teljes kiszolgálóra érvényes beállítást. Egy referenciapéldányon ez
**2345 bejegyzést 1396-ra csökkentett — 949 ismétlődés, nulla elveszett modell.**

Ha inkább kiszolgálószinten, _minden_ kliens számára szeretné megoldani ezt, állítsa a
`MODELS_CATALOG_PREFIX_MODE` funkciójelzőt `alias` értékre az irányítópulton. A lekérdezési paramétert és az
egyes módok táblázatát lásd itt:
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix).

### Elrejti a csevegésre nem alkalmas modelleket

A katalógus kép-, videó- és hangmodelleket, valamint újrarangsoroló, beágyazási és moderációs modelleket is
felsorol. Ezeket a rendszer egyébként is elutasítja csevegési kérés esetén:

```
HTTP 400 — A(z) '<id>' modell képgeneráló modell, és nem használható a
/v1/chat/completions végponton. Használja helyette a POST /v1/images/generations végpontot.
```

ezért a modellválasztó elérése előtt kiszűri őket a `type` mezőjük alapján. **A Responses-API
modelljei megmaradnak** — minden Codex- és GPT-5.x-bejegyzés `supported_endpoints: ["responses"]` értéket tesz közzé,
az OmniRoute pedig lefordítja ezeket a `/v1/chat/completions` számára, így teljes mértékben használhatók.

### Soha nem konfigurált szolgáltatók

A katalógus az **aktív kapcsolattal** rendelkező szolgáltatók modelljei mellett az összes **noAuth**
szolgáltató modelljeit is felsorolja — ezek a kulcs nélküliek teszik ki az ingyenes csomag jelentős részét. Ez szándékos. Az
elrejtésükhöz adja hozzá őket az irányítópult beállításaiban található `blockedProviders` listához; a
bővítményben semmit sem kell módosítani.

## Irányítópult egy VS Code-lapon belül

Az `omnicopilot.dashboardOpen: "editor"` a külső böngésző helyett a Simple Browser használatával jeleníti meg az OmniRoute irányítópultját egy szerkesztőlapon. A beágyazás **kiszolgálóoldali engedélyezést igényel** a `DASHBOARD_ALLOW_EMBED=vscode` használatával, amelynek hatására a HTML-oldalak kiszolgálása az alapértelmezett `frame-ancestors 'none'` + `X-Frame-Options: DENY` helyett a `frame-ancestors 'self' vscode-webview:` beállítással történik. Az API-felület (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) mindkét esetben megtartja a szigorú fejléceket.

> ⚠️ **Ez fordítási idejű, nem pedig futásidejű jelző.** A Next.js a `headers()` függvényt az útvonaljegyzékbe fordítja, ezért a `next.config.mjs` a csomag összeállításakor olvassa be a változót
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> Ha egy már összeállított kiszolgáló indítása előtt exportálja, semmi sem változik — a fejlécek már be vannak építve.

```bash
# a változónak jelen kell lennie a BUILD parancs futtatásakor
DASHBOARD_ALLOW_EMBED=vscode npm run build        # vagy npm run build:release
npm start
```

| Telepítés módja            | Engedélyezhető a beágyazás?                                                                                                                                       |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Forráskódból               | ✅ állítsa be a változót a fordítási parancsban a fentiek szerint                                                                                                 |
| `npm install -g omniroute` | ❌ a közzétett csomag előre összeállított csomagot tartalmaz — ehelyett fordítsa le forráskódból                                                                  |
| Docker-rendszerkép         | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — a Docker Hub előre összeállított rendszerképében nincs engedélyezve a beágyazás |

Beágyazást támogató összeállítás nélkül az oldal megtagadja a keretben való megjelenítést. A bővítmény ezt észleli a válaszfejlécekből, és visszavált a külső böngészőre — semmi sem romlik el, és erről egyszer értesítést is küld.
Lásd az [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) dokumentumot és a
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273). számú hibajegyet.

## Más eszközök konfigurálása a VS Code-ból

Az **`OmniRoute: Configure Coding CLI`** az `omniroute` CLI használatával azonnal használható profilokat ír a Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code, Kilo és Roo számára — ugyanazokat a konfigurációkat, amelyeket a
[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md) ismertet. Az API-kulcs a
`OMNIROUTE_API_KEY` környezeti változón keresztül kerül átadásra a CLI-nek, soha nem a parancssorban.
