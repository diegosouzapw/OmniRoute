## 1. Antigravity és Antigravity CLI (agy) összehasonlítása

Mindkét szolgáltató **ugyanazt a Google-háttérrendszert** használja — azonos OAuth-klienssel, tokenfrissítéssel, végpontokkal és Google-fiókokkal. A különbség az elérhető modellekben rejlik.

> A Google hivatalos összehasonlítását lásd az [Antigravity CLI bejelentésében](https://antigravity.google/blog/introducing-google-antigravity-cli).

| Szempont                      | `antigravity` (IDE)                                  | `agy` (CLI)                                                           |
| ----------------------------- | ---------------------------------------------------- | --------------------------------------------------------------------- |
| **Google-termék**             | Antigravity 2.0 / Antigravity IDE                    | Antigravity CLI                                                       |
| **Háttérrendszer**            | Ugyanaz a Google Cloud Code API                      | Ugyanaz a Google Cloud Code API                                       |
| **OAuth / token**             | Ugyanaz a kliens, ugyanaz a frissítés                | Ugyanaz a kliens, ugyanaz a frissítés                                 |
| **Modellkatalógus**           | Statikus, válogatott lista (OmniRoute-ba kódolva)    | Élőben lekérdezve a Google-től a `:fetchAvailableModels` segítségével |
| **Claude-modellek**           | Sonnet 4.6, Opus 4.6 (egyenként 4 változat)          | Sonnet 4.6, Opus 4.6 (egyenként 4 változat)                           |
| **Gemini-elnevezések**        | Letisztult címkék (Low/Medium/High)                  | Forrásoldali azonosítók (extra-low/low/agent)                         |
| **További modellek**          | `gpt-oss-120b-medium`                                | További Google-modelleket is tartalmazhat                             |
| **Alapértelmezett használat** | IDE-integráció (VS Code, JetBrains)                  | CLI-/API-hozzáférés                                                   |
| **Kvóta**                     | Megosztva az agy szolgáltatóval (azonos Google-fiók) | Megosztva az antigravity szolgáltatóval (azonos Google-fiók)          |

**Elérhető modellek (kísérlettel ellenőrizve, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (különböző gondolkodási szintekkel)
- Claude: Sonnet 4.6, Opus 4.6 (mindegyik default/low/medium/high változatokkal)
- Egyéb: GPT-OSS 120B Medium
- **A Claude Sonnet 5 NEM érhető el** — csak a 4.6-os változatok támogatottak

**Miért különbözik a modellkatalógus?** A Google CLI-je „sebességre és alacsony többletterhelésre optimalizált”, valamint „a Gemini-modellekkel közösen optimalizált” (a Google hivatalos blogja szerint). A webes/IDE-termék „átfogó működésre optimalizált”. A CLI a `:fetchAvailableModels` használatával dinamikusan deríti fel a modelleket, míg az IDE statikus, válogatott listát használ.

**A gyakorlatban**: A Gemini-modellekhez használja az `agy/` előtagot (például `agy/gemini-3.7-flash-high`). A statikus, válogatott listához használja az `antigravity/` előtagot. Mindkettő ugyanazt a Google-háttérrendszert éri el, de eltérő modellelnevezéseket tesznek elérhetővé. A kvóta közös — bármelyik szolgáltató használata ugyanazon Google-fiók korlátaiba számít bele.

## 2. Google One AI Pro: Kvótarendszer

> A hivatalos kvótarészletekért lásd az [Antigravity dokumentációját: Csomagok](https://antigravity.google/docs/plans), a legújabb árváltozásokért pedig az [Antigravity-csomagok változásai](https://antigravity.google/blog/changes-to-antigravity-plans) című bejegyzést.

A Google Antigravity egy **kétrétegű kvótarendszert** használ, amely nem az üzenetek számán, hanem az „elvégzett munkán” (számítási súlyon) alapul.

### A két réteg

| Réteg            | Mit jelent                       | Frissítési ciklus                                                           |
| ---------------- | -------------------------------- | --------------------------------------------------------------------------- |
| **5 órás etap**  | Azonnali „elvégzett munka” keret | A munkamenet első kérésétől számított 5 óra elteltével visszaáll            |
| **7 napos alap** | Heti, szigorú felső korlát       | Elérése felülírja az 5 órás frissítést; a következő 7 napos időszakig zárol |

**Az „elvégzett munka” kiszámítása**: Az erősen ügynökalapú feladatok (pl. „Alakítsd át ezt a teljes kódtárat”) sokkal gyorsabban merítik ki a kvótát, mint az egyszerű feladatok (pl. „Javítsd ki ezt a függvényt”). Nincs a fogyasztást valós időben megjelenítő irányítópult.

### Csomagszintek

| Csomag       | Ár         | Kvóta                                    | Heti korlát                          |
| ------------ | ---------- | ---------------------------------------- | ------------------------------------ |
| Ingyenes     | $0         | Jelentős, hetente frissülő kvóta         | Igen                                 |
| AI Pro       | $19.99/hó  | Magas kvóta, 5 órás gördülő frissítéssel | Igen (elérése felülírja az 5 órásat) |
| AI Ultra 5x  | $99.99/hó  | A Pro kvótájának 5-szöröse               | Nincs heti korlát                    |
| AI Ultra 20x | $199.99/hó | A Pro kvótájának 20-szorosa              | Nincs heti korlát                    |

### Gemini- és nem Gemini-modellek

- **Gemini-modellek** (Flash + Pro): Egyetlen közös sebességkorláton osztoznak, amelynek felhasználását az API árazása határozza meg. Ha a Flash 8-szor olcsóbb a Pro modellnél, akkor 8-szor több Flash-token használható fel.
- **Nem Gemini-modellek** (Claude, GPT-OSS): **Különálló** sebességkorlátokkal rendelkeznek. Akkor is elérhetők maradhatnak, amikor a Gemini használata már zárolva van.

### AI-kreditek (túllépés)

> A kreditek működéséről lásd a [Google One AI-kreditek](https://support.google.com/googleone/answer/14534406) oldalát.

Amikor az alapkvóta kimerül:

- **Soha**: Megvárja a kvóta frissítését; az „Alapmodell kvótája elérve” üzenetet jeleníti meg
- **Mindig**: Automatikusan AI-krediteket használ; az alapkvóta frissülésekor visszavált arra

A kreditek külön vásárolhatók meg, és levonásuk a szabványos API-árazás szerint történik.

### Főbb részletek

- A kvóta **fiókszinten megosztott** — ugyanaz a Google-fiók az Antigravity IDE-ben, a CLI-ben és az OmniRoute-ban egyetlen közös kvótakeretet használ
- Minden Google-fiók saját, független kvótával rendelkezik — több fiók = több kvótakeret
- Az AI Pro felhasználói **7 napos zárolásokról** számoltak be az 5 órás visszaállítás helyett, amikor elérik a heti alapkvótát (a Google megerősítette, hogy nagy terhelés esetén ez szándékos működés)

**Amikor a fiók kvótája kimerül**: Az OmniRoute automatikusan újrapróbálkozik a kombinált útvonal következő elérhető fiókjával. Nincs szükség kézi beavatkozásra.

## 3. projectId beszerzése

Minden antigravity/agy-kapcsolathoz szükség van egy Google Cloud Code `projectId` értékre. Enélkül a `/v1internal:models` végpont 404-es hibát ad vissza.

### A módszer: Automatikus (ajánlott)

Az OmniRoute ezt automatikusan kezeli. Amikor új Google-fiókot ad hozzá az irányítópult OAuth-folyamatán keresztül:

1. Az OmniRoute frissíti a tokent
2. Meghívja a `loadCodeAssist` függvényt a projectId felderítéséhez
3. Ha még nem létezik projekt, meghívja az `onboardUser` függvényt egy projekt létrehozásához
4. Újra meghívja a `loadCodeAssist` függvényt az újonnan létrehozott projectId lekéréséhez
5. Elmenti azt az adatbázisba

**Ez a legtöbb fióknál működik** — nincs szükség kézi lépésekre.

### B módszer: Kézzel, az agy CLI használatával

Ha az automatikus felderítés sikertelen (ennek lehetséges eseteit lásd az 5. szakaszban):

```bash
# Az agy CLI telepítése (ha még nincs telepítve)
npm install -g @anthropic-ai/agy

# Bejelentkezés a Google-fiókkal
agy login

# Válassza ki a bevezetést igénylő fiókot
# Ez elindítja a Cloud Code-regisztrációt, és hozzárendel egy projectId értéket
```

Miután az `agy login` sikeresen befejeződött, frissítse a tokent az OmniRoute irányítópultján. A projectId felderítése automatikusan megtörténik.

### Ellenőrzés

Ellenőrizze az adatbázist:

```bash
# Az OmniRoute-konténeren belül
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Vagy ellenőrizze a naplókat:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. OAuth átirányítási URI

### A probléma

A Google OAuth érvényes átirányítási URI-t igényel. Az OmniRoute alapértelmezés szerint a `http://127.0.0.1:20128/callback` címet használja (loopback). Ez helyi buildek esetén működik, de **távoli telepítéseknél nem** (például LAN IP-címen keresztül elért szerver esetén).

A Google elutasítja azokat az átirányítási URI-kat, amelyek:

- IP-címet használnak (a címnek például `.com`, `.org` stb. végződésű tartománynévnek kell lennie)
- Nem egyeznek az OAuth-kliens konfigurációjában regisztrált átirányítási URI-kkal

### A megoldás

**A lehetőség: A beépített OAuth-folyamat használata (alapértelmezett)**

- Akkor működik, ha az OmniRoute-ot a `localhost` vagy a `127.0.0.1` címről éri el
- Nincs szükség konfigurációra

**B lehetőség: Egyéni OAuth-hitelesítő adatok**

- Állítsa be az `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` értéket a környezetében
- Adja meg saját Google OAuth-hitelesítő adatait:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Regisztrálja a `https://your-domain.com/callback` címet engedélyezett átirányítási URI-ként a Google Cloud Console-ban

**C lehetőség: Az agy CLI használata a kezdeti bejelentkezéshez**

- Futtassa az `agy login` parancsot azon a gépen, amelyről az OmniRoute-ot el fogja érni
- Az OAuth-folyamat helyileg fejeződik be, a tokenek pedig tárolásra kerülnek
- Importálja a kapcsolatot az OmniRoute-ba a Dashboardon keresztül

### Korlátozások

- Az egyéni OAuth-hitelesítő adatok használatához tartománynév szükséges (a Google nem fogad el IP-címeket átirányítási URI-ként)
- Ha nem rendelkezik tartománynévvel, használja inkább az A vagy a C lehetőséget

## 5. Hibaelhárítás: Ha az automatikus beállítás sikertelen

Az OmniRoute a legtöbb fiók esetében automatikusan kezeli a projectId felderítését és a kezdeti beállítást. Sikertelenség esetén a kiváltó ok általában az alábbiak egyike:

### A fiók régiója blokkolva van

**Tünet**: Az `agy login` a következő üzenetet adja vissza: „A jogosultság ellenőrzése sikertelen: jelenlegi fiókja nem jogosult az Antigravity használatára, mert az jelenleg nem érhető el az Ön tartózkodási helyén.”

**Kiváltó ok**: A Google-fiókok rendelkeznek egy háttérrendszerbeli „Country Association” mezővel, amelyet a regisztrációkor állítanak be. Az agy CLI és a Cloud Code API szigorúan ellenőrzi ezt a mezőt — ellentétben a Gemini webes verziójával, amely csak az aktuális IP-címet ellenőrzi.

> A fiókjához társított régió ellenőrzéséhez vagy módosításához keresse fel a [Google ország-hozzárendelési űrlapját](https://policies.google.com/country-association-form).

**Miért működik a Gemini webes verziója, miközben az agy nem**:

- Gemini webes verziója / Google One: csak az aktuális IP-címet ellenőrzi (proxy használatával működik)
- agy CLI / Cloud Code API: a háttérrendszerbeli Country Association mezőt olvassa be (a proxy nem segít)

**Javítás**:

1. Egyesült államokbeli IP-cím használata mellett keresse fel a [Google ország-hozzárendelési űrlapját](https://policies.google.com/country-association-form)
2. Küldjön be régiómódosítási kérelmet (válassza az „I live in a different country” lehetőséget)
3. Várjon 1–24 órát, amíg a Google feldolgozza a kérelmet és e-mailben értesítést küld
4. Ezután az `agy login` parancsnak sikeresen le kell futnia

### A fiók nem rendelkezik Cloud Code-projekttel

**Tünet**: A naplókban a `loadCodeAssist returned no project id` és az `onboardUser failed (400)` üzenet jelenik meg.

**Kiváltó ok**: A fiókot még soha nem regisztrálták a Google Cloud Code szolgáltatásban, és az automatikus kezdeti beállítás sikertelen volt.

**Javítás**: Futtassa manuálisan az `agy login` parancsot a Cloud Code-regisztráció elindításához, majd frissítse a tokent az OmniRoute Dashboardon.

### A token lejárt vagy visszavonták

**Tünet**: 401-es hibák jelennek meg a naplókban, vagy „A token lejárt” üzenetek láthatók.

**Javítás**: Frissítse a tokent a Dashboard → Providers → agy útvonalon, majd kattintson a frissítés ikonra. Ha magát a frissítési tokent vonták vissza, újra el kell végeznie a hitelesítést OAuth-on keresztül.

```
│
└─ Manuálisan: Futtassa az `agy login` parancsot a gépen
   ├─ Működik → Frissítse a tokent az irányítópulton; a projectId felderítve
   └─ Nem működik → Ellenőrizze a hibaüzenetet; valószínűleg régió- vagy előfizetési probléma
```
