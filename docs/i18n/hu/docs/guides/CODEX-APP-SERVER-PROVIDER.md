---

Az OmniRoute **kétféle** módot kínál az OpenAI Codex használatára:

| Szolgáltató            | Hogyan kommunikál az OpenAI-jal                                                                                                                                                                                                                    | Használati korlátozás                                                                |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| **`codex`**            | A ChatGPT/OpenAI OAuth-tokenjét közvetlenül továbbítja a Responses API-nak                                                                                                                                                                         | **Igen** — a hivatalos munkamenet nem használható proxykon vagy routereken keresztül |
| **`codex-app-server`** | A **Codex CLI saját `codex app-server` folyamatát** vezérli JSON-RPC/WebSocket kapcsolaton keresztül; az OAuth-hitelesítést (`~/.codex/auth.json`) a CLI kezeli és frissíti automatikusan, pontosan úgy, mint egy interaktív `codex` munkamenetben | **Nincs** — az OmniRoute soha nem továbbít tokent az API-nak                         |

Mivel a `codex-app-server` soha nem továbbít tokent, nem vonatkozik rá a
munkamenet-továbbítással kapcsolatos használati korlátozás. Ehhez azonban
szükség van egy, a **beállított app-server URL-en elérhető Codex CLI-re**,
amelybe **be kell jelentkezni**.

---

## 1. Architektúra

```
┌─ OmniRoute alkalmazás ───────────┐        ┌─ codex-app-server segédkonténer ───┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ képességtoken)               │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  önállóan kezeli az OpenAI OAuth-ot │
└──────────────────────────────────┘        │  (~/.codex/auth.json, autom. friss.)│
        │ megosztás (compose-kötetek)        └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → a WS-képességtoken (mindkettő csatolja)
  codex-appserver-home    → ~/.codex (az auth.json fájlt a vezérlőpult írja,
                             a segédkonténer codex app-server folyamata olvassa)
```

- A segédkonténer **kizárólag** a belső compose-hálózaton figyel
  (`ws://codex-app-server:1456`), egy képességtoken védelme mögött. A szolgáltatás
  **soha** nincs közzétéve a gazdagépen vagy az interneten.
- A Codex CLI az `omniroute:base` lemezkép része, így a segédkonténer futtatásakor
  sem a gazdagépen, sem a felhasználó gépén nem szükséges telepíteni a codexet.

## 2. Elindítás

```bash
# A rendszer elindítása A codex app-server segédkonténer-profillal:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

A segédkonténer az első indításkor létrehozza a saját WS-képességtokenjét
(a megosztott `codex-appserver-token` kötetben), az alkalmazás pedig ugyanezt a
tokent olvassa be az `OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE` segítségével.
Nincs szükség a token kézi bekötésére.

## 3. Csatlakozás és bejelentkezés

1. A vezérlőpulton adjon hozzá egy kapcsolatot az **OpenAI Codex (App-Server)**
   szolgáltatóhoz. Nincs szükség API-kulcsra vagy tokenre (ez egy hitelesítést
   nem igénylő szolgáltató — a hitelesítést a segédkonténer kezeli).
2. Ha a segédkonténer Codex CLI-jébe **még nincs bejelentkezve**, a kapcsolat
   állapotellenőrzése a _„fut, de nincs bejelentkezve”_ üzenetet jeleníti meg
   (nem pedig piros hitelesítési hibát). Használja a **Bejelentkezés ChatGPT-vel**
   lehetőséget: ez elindítja a szabványos Codex eszköz-OAuth-folyamatot a
   böngészőben, majd a **Hitelesítés alkalmazása** segítségével beírja a
   `~/.codex/auth.json` fájlt a megosztott kötetbe (ugyanaz a bejelentkezés
   kiszolgálja a `codex` és a `codex-app-server` szolgáltatót is).
3. A bejelentkezés után az állapotellenőrzés zöldre vált (a `/readyz` **és** az
   `account/read` végpontot is ellenőrzi — vagyis azt, hogy a szolgáltatás fut
   _és_ hitelesítve van), és működésre kész.

A vezérlőpult soha nem ír felül egy megfelelően működő, meglévő
`~/.codex/auth.json` fájlt — csak akkor írja azt, ha a fájl hiányzik, vagy a benne
lévő token elavult (mindig készül biztonsági másolat).

## 4. Telepítési forgatókönyvek

- **Már hitelesített Codex CLI-vel rendelkező üzemeltető** — csatolja a gazdagép
  `~/.codex` könyvtárát a segédkonténerbe (`codex-appserver-home`), és hagyja ki
  a bejelentkezési lépést.
- **Nyilvános felhasználó, helyileg telepített codex nélkül** — ez nem számít:
  a segédkonténer tartalmazza a CLI-t. A felhasználó csak a vezérlőpulton
  keresztül végez hitelesítést.
- **Közvetlenül a gépre telepített OmniRoute (segédkonténer nélkül, gazdagépi codexszel)** —
  állítsa az `OMNIROUTE_CODEX_APPSERVER_WS` értékét a saját `codex app-server`
  példányára, és győződjön meg arról, hogy be van jelentkezve a gazdagépi
  codexbe; ha a bináris hiányzik, megjelenik a „codex nincs telepítve” tipp.

## 5. Lakossági / UDP-kimenő forgalom (üzemeltetői kiegészítés, nincs mellékelve)

A fenti általános segédkonténer a konténer normál hálózatán keresztül bonyolítja
a kimenő forgalmat. Ha egy üzemeltetőnek arra van szüksége, hogy a Codex forgalma
**lakossági kilépési ponton** keresztül távozzon (például egy TCP- és UDP/QUIC-
forgalmat továbbító TUN tailscale segédkonténeren át), azt külön compose-
felülírásként kell futtatnia; ez szándékosan **nem** része a mellékelt
`codex-app-server` profilnak. A beállítás részleteit a belső üzemeltetési
kézikönyv ismerteti.
