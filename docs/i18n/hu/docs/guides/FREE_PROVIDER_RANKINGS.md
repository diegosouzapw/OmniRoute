> **Röviden**: Az OmniRoute a modellminőség alapján rangsorolja **ingyenes**
> szolgáltatóit az **Arena AI (LMArena-stílusú) ELO-pontszámai** segítségével.
> Nyisd meg az irányítópult **Ingyenes szolgáltatók rangsora** oldalát, hogy lásd,
> mely ingyenes szolgáltatók kínálják a feladatodhoz a legerősebb modelleket —
> összesítve vagy kategória szerint szűrve (kódolás, ellenőrzés, dokumentáció, hibakeresés).

---

## Mi ez?

Az OmniRoute 329 szolgáltatót tart nyilván, köztük 155 olyan katalógusbejegyzést,
amely **ingyenes/hitelesítés nélküli** jelölést kapott (hitelesítés nélküli,
ingyenes szintű OAuth vagy ingyenes szintű API-kulcs — lásd az
[Ingyenes szintek útmutatóját](../getting-started/FREE-TIERS-GUIDE.md) és a teljes
[Ingyenes szintek jegyzékét](../reference/FREE_TIERS.md)). A bökkenő: az ingyenes
szolgáltatók modelljeinek minősége rendkívül változó. Egy élvonalbeli modellt kínáló,
hitelesítés nélküli szolgáltató sokkal hasznosabb annál, amely egy kisméretű, elavult
modellt kínál.

Az **Ingyenes szolgáltatók rangsora** arra a kérdésre ad választ, hogy
„**melyik ingyenes szolgáltató biztosítja számomra a legjobb modellt?**”. Ehhez
összekapcsolja az egyes ingyenes szolgáltatók katalógusát az **Arena AI ranglistájának**
**közösségi forrásból származó minőségi pontszámaival** (emberi preferenciákon alapuló
ELO, ugyanaz az elv, mint a LMArena chatbotarénája mögött). A szolgáltatókat ezután a
**legjobb ingyenes modelljük** erőssége alapján rangsorolja.

A rangsor három valós forrás alapján készül:

1. Az ingyenes szolgáltatók listái — `NOAUTH_PROVIDERS`, valamint az `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` `hasFree` jelöléssel ellátott bejegyzései
   (`src/shared/constants/providers.ts`).
2. Az egyes szolgáltatók modellkatalógusa a szolgáltatói nyilvántartásból
   (`open-sse/config/providerRegistry.ts`).
3. Az ELO-ból származtatott, feladathoz való illeszkedést mérő pontszámok, amelyeket
   az Arena ELO szinkronizálási motor (`src/lib/arenaEloSync.ts`) tárol a
   `model_intelligence` adatbázistáblában.

Az összekapcsolási logika a `src/lib/freeProviderRankings.ts` fájlban található.

## Hozzáférés

### Irányítópultoldal

Nyisd meg az irányítópultot, és lépj a **Költségek → Ingyenes szolgáltatók rangsora**
menüpontra, vagy navigálj közvetlenül ide:

```
/dashboard/free-provider-rankings
```

Az oldal (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) a
következőket jeleníti meg:

- A legmagasabbra rangsorolt ingyenes szolgáltatók **háromhelyes dobogóját**
  (🥇 🥈 🥉).
- Egy teljes **rangsorolási táblázatot** a következő oszlopokkal: **Helyezés**,
  **Szolgáltató**, **Legjobb modell**, **Pontszám**, **Átlagpontszám**, **Modellek**,
  **Típus**.
- **Kategóriaszűrő gombokat**: _Minden kategória_, _Alapértelmezett_, _Kódolás_,
  _Ellenőrzés_, _Dokumentáció_, _Hibakeresés_.

Az egyes szolgáltatók **Típus** jelvénye mutatja meg, milyen módon ingyenesek:

| Jelvény  | Jelentés                                                         |
| -------- | ---------------------------------------------------------------- |
| `NOAUTH` | Mindig ingyenes, nincs szükség hitelesítő adatokra               |
| `OAUTH`  | Ingyenes szinttel (`hasFree`) rendelkező OAuth-szolgáltató       |
| `APIKEY` | Ingyenes szinttel (`hasFree`) rendelkező API-kulcsos szolgáltató |

A pontszámok nyers számok helyett könnyen érthető címkékkel jelennek meg (például
_Elit_, _Kiváló_, _Nagyon jó_, _Jó_, _Átlagos_), mivel az alapul szolgáló érték
relatív rangsorolási minőséget jelöl, nem százalékos értéket.

### API-végpont

Az oldalt egy nyilvános olvasási végpont szolgálja ki
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

Lekérdezési paraméterek (Zod segítségével ellenőrizve):

| Paraméter  | Típus  | Alapértelmezés | Megjegyzések                                                                                                          |
| ---------- | ------ | -------------- | --------------------------------------------------------------------------------------------------------------------- |
| `category` | string | (nincs)        | A következők egyike: `default`, `coding`, `review`, `documentation`, `debugging`. Az összesített rangsorhoz hagyd el. |
| `limit`    | number | `50`           | Az `1–100` tartományra korlátozva.                                                                                    |

A válasz szerkezete:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

Az `eloRaw` az eredeti Arena ELO-érték; a `score` a normalizált, feladathoz való
illeszkedést mérő érték (lásd alább). A pontozott modellekkel nem rendelkező
szolgáltatók kimaradnak a válaszból.

## A pontszámok működése

### Forrás: Arena AI ranglista

Az Arena ELO szinkronizációs motor (`src/lib/arenaEloSync.ts`) két ranglistát — `text`
és `code` — kér le az Arena AI ranglista API-jából
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`). Minden ranglistabejegyzés
tartalmazza a modell nevét, szolgáltatóját, ELO-`score` értékét, konfidenciaintervallumát és a szavazatok számát.

A ranglistakategóriák az OmniRoute feladatkategóriáihoz a következőképpen kapcsolódnak:

| Arena-ranglista | OmniRoute-feladatkategóriák                       |
| --------------- | ------------------------------------------------- |
| `text`          | `default`, `review`, `documentation`, `debugging` |
| `code`          | `coding`                                          |

### Normalizálás (feladathoz való illeszkedés pontszáma)

A nyers ELO-pontszámokat ranglistánként egy **`[0.4, 0.98]` tartományba eső feladatilleszkedési értékre** normalizálja a rendszer:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

A pontszám soha nem éri el a `0` vagy `1` értéket, így marad mozgástér a felhasználói felülbírálások számára. Ez az API-válaszban látható `score` mező, valamint az irányítópulton megjelenített címke.

### Megbízhatóság

Minden bejegyzés megbízhatósági szintet kap az Arena-szavazatok száma alapján:

| Megbízhatóság | Szavazatok |
| ------------- | ---------- |
| `high`        | ≥ 5 000    |
| `medium`      | ≥ 1 000    |
| `low`         | < 1 000    |

### Tárolás és frissesség

A normalizált bejegyzések a `model_intelligence` adatbázistáblába kerülnek
`source = "arena_elo"` értékkel (`src/lib/db/modelIntelligence.ts`). A bejegyzések **7 nap után
lejárnak**, így egy olyan szolgáltató, amelynek szinkronizálása leáll, idővel eltűnik, ahelyett, hogy
elavult adatokat szolgáltatna.

A szinkronizálás **alapértelmezés szerint be van kapcsolva**:

- Egyszer lefut a kiszolgáló indításakor, majd rendszeres időközönként újra
  (`src/lib/arenaEloSync.ts`, bekötve innen: `src/instrumentation-node.ts`).
- **Nem blokkoló, és soha nem okoz végzetes hibát** — ha a külső lekérés sikertelen, az OmniRoute tovább
  fut, a rangsorok pedig egyszerűen az utolsó helyes adatokat mutatják (vagy üres állapotot).

Két környezeti változó szabályozza (dokumentáció:
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)):

| Változó                   | Alapértelmezett érték | Cél                                                          |
| ------------------------- | --------------------- | ------------------------------------------------------------ |
| `ARENA_ELO_SYNC_ENABLED`  | `true`                | A külső szinkronizálás letiltásához állítsa `false` értékre. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h)         | Szinkronizálási időköz másodpercben.                         |

### Kézi szinkronizálás / állapot / törlés

Az üzemeltetők számára egy hitelesítést igénylő felügyeleti végpont biztosít kézi vezérlést
(`src/app/api/intelligence/sync/route.ts` — felügyeleti hitelesítést igényel):

```
GET    /api/intelligence/sync          # aktuális szinkronizálási állapot (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # kézi szinkronizálás indítása; törzs: { "dryRun": true } az írás nélküli előnézethez
DELETE /api/intelligence/sync          # az összes szinkronizált arena_elo intelligenciabejegyzés törlése
```

Ha a rangsoroldal üres, egy kézi `POST /api/intelligence/sync` kérés (vagy egyszerűen
a kiszolgáló újraindítása) újra feltölti azt.

### Modellek párosítása a ranglistával

A nyilvántartás modellazonosítói és az Arena modellnevei nem mindig egyeznek meg pontosan. A rangsorolás
rugalmas párosítást használ (`findMatchingIntelligence` a `src/lib/freeProviderRankings.ts` fájlban):

1. Pontos egyezés a normalizált modellazonosítóval.
2. Egyezés a záró verzióutótag eltávolítása után (például `kimi-k2.6` → `kimi-k2`).
3. Előtag szerinti egyezés (a ranglistán szereplő modellnév a nyilvántartási azonosító előtagja).

A szinkronizálás során az ismert szolgáltatói előtagokat (`anthropic/`, `openai/`, `google/`, …)
eltávolítja a rendszer, egy kis álnévtérkép pedig kibővíti a kanonikus neveket az OmniRoute által
belsőleg használt változatokra, így a modellek bármely név alatt megtalálhatók maradnak.

### A szolgáltatók rangsorolása

A motor minden ingyenes szolgáltató katalógusának minden modelljét pontozza, majd:

- **Legjobb modell** = a szolgáltató legmagasabb pontszámú modellje.
- **Átlagos pontszám** = a szolgáltató összes pontozott modellje pontszámának átlaga.
- **Modellek** = a szolgáltató Arena-pontszámmal rendelkező modelljeinek száma.

A szolgáltatókat először a **legjobb modell pontszáma**, majd az átlagos pontszám alapján rendezi a rendszer. Ez előnyben részesíti azokat a szolgáltatókat, amelyek legalább egy erős ingyenes modellt kínálnak.

## Használata ingyenes szolgáltatók kiválasztásához

1. **Válassza ki a megfelelő kategóriát.** Használja a **Kódolás** szűrőt az ügynökalapú/kódolási feladatokhoz, vagy
   hagyja az **Összes kategória** / **Alapértelmezett** beállításon általános csevegéshez. Ugyanaz a szolgáltató
   kategóriánként eltérő helyezést érhet el, mivel a legjobb modellje ranglistánként különbözhet.
2. **Egyszeri beállításhoz részesítse előnyben a dobogósokat.** Ha csak egy vagy két ingyenes
   szolgáltatót szeretne csatlakoztatni, kezdje a kategóriája legjobb helyezettjeivel.
3. **Ellenőrizze a Típus jelvényt.** A `NOAUTH` szolgáltatók csatlakoztathatók a leggyorsabban (nincs szükség
   hitelesítő adatokra). Az `OAUTH` / `APIKEY` ingyenes csomagjai gyors regisztrációt igényelnek, de gyakran
   erősebb modelleket tesznek elérhetővé. A csatlakoztatás lépéseit lásd az
   [Ingyenes csomagok útmutatójában](../getting-started/FREE-TIERS-GUIDE.md).
4. **Csatlakoztasson többet, és hagyja, hogy az Auto-Combo döntsön.** Az oldalt működtető
   Arena ELO-adatok az Auto-Combo pontozómotor **feladat-alkalmassági tényezőjét** is táplálják
   (`open-sse/services/autoCombo/taskFitness.ts`, feloldási sorrend:
   `user_override → arena_elo → models_dev_tier → static table`). Így a legjobb ingyenes szolgáltatók
   csatlakoztatása után a `model: "auto"` útválasztás (például `auto/coding`) kérésenként
   automatikusan előnyben részesíti a jobb minőségű ingyenes modelleket. A teljes, 16 tényezős pontozást
   lásd az [Auto-Combo](../routing/AUTO-COMBO.md) dokumentációjában.
