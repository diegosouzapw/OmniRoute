> **Irányítópult:** Beállítások → **AI** → Gondolkodási keret  
> **API:** `GET` / `PUT` `/api/settings/thinking-budget`  
> **Forrás:** `open-sse/services/thinkingBudget.ts`

A Gondolkodási keret szabályozza, hogy az OmniRoute **átírja-e a kliens gondolkodási/következtetési paramétereit** a szolgáltatók felé továbbítás során. A tömörítést, az útválasztást vagy a prompt-gyorsítótárat **nem** kapcsolja be vagy ki.

## Módok

| Mód                                 | Az OmniRoute működése                                                                                                     | Mikor használandó                                                                                                                                                                                                         |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`passthrough`** (alapértelmezett) | Változatlanul hagyja a kliens mezőit (`reasoning`, `reasoning_effort`, Claude `thinking`, Gemini `thinking_config` stb.). | **Codex / Desktop / bármely kliens, amelynek vezérelnie kell az erőfeszítési szintet és a következtetési összefoglalókat.** A látható gondolkodási panelekhez szükséges, amikor a kliens `reasoning.summary` értéket kér. |
| **`auto`**                          | A szolgáltatónak való továbbítás előtt **eltávolít minden** gondolkodási/következtetési mezőt a kérés törzséből.          | Csak akkor, ha szándékosan azt szeretné, hogy a **szolgáltató** határozza meg az alapértelmezéseket, és **nincs** szüksége kliens által vezérelt gondolkodásra. **Nem** „gondolkodás automatikus megjelenítése”.          |
| **`custom`**                        | Minden kérést felülír egy rögzített gondolkodásitoken-kerettel.                                                           | Szigorú felső korlát a gondolkodási tokenek számára a teljes forgalomban.                                                                                                                                                 |
| **`adaptive`**                      | Az üzenetek száma, az eszközök és a prompt hossza alapján méretezi a keretet egy alap-erőfeszítési szintről.              | Rugalmas tokenszabályozás a kliens szándékának teljes eltávolítása nélkül.                                                                                                                                                |

### Mit távolít el az `auto`?

`auto` módban a `stripThinkingConfig()` többek között a következőket törli:

- OpenAI / Responses: `reasoning`, `reasoning_effort`
- Claude: `thinking`, valamint az `output_config.effort`, ha jelen van
- Gemini: `generationConfig.thinking_config` / `thinkingConfig`

Ha egy kliens (például a Codex Desktop) a `reasoning: { effort: "ultra", summary: "detailed" }` értéket küldte, az **auto eldobja ezt az objektumot**. A szolgáltató továbbra is elszámolhat bizonyos következtetési tokeneket, de gyakran **üres vagy kizárólag titkosított** következtetési elemeket ad vissza — így a felhasználói felület nem jelenít meg használható gondolkodási adatfolyamot.

## Mi **nem** ez?

| Funkció                                        | Kapcsolat                                                                                                                                                  |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Tömörítés** (Caveman, RTK, stacked, …)       | Különálló feldolgozási folyamat. Minden gondolkodásikeret-módban működik.                                                                                  |
| **Prompt-/szemantikus gyorsítótár**            | Különálló funkció. A gondolkodásikeret-mód nem befolyásolja.                                                                                               |
| **Kombinált útválasztás / tartalék útvonalak** | Különálló funkció. Nem befolyásolja.                                                                                                                       |
| **API-kulcsok tokenkorlátai / költségkeretek** | Különálló funkció. Nem befolyásolja.                                                                                                                       |
| **Következtetés-visszajátszási gyorsítótár**   | Többfordulós újbóli beillesztés szigorú szolgáltatókhoz (DeepSeek, Kimi, Qwen-thinking, …). Nem azonos a Desktop „gondolkodás megjelenítése” funkciójával. |
| **Az `encrypted_content` visszafejtése**       | **Lehetetlen.** Az OpenAI/Codex privát következtetési objektumai átláthatatlanok. Az OmniRoute soha nem fejti vissza őket (#7095 / #7176 / #7304).         |

## Látható gondolkodás (Codex / Responses kliensek)

Ahhoz, hogy egy kliens megjelenítse a gondolkodási szöveget, az **alábbi feltételek mindegyikének** teljesülnie kell:

1. A Thinking Budget mód = **`passthrough`** (vagy olyan custom/adaptive mód, amely az Ön által használt útvonalhoz kellően érintetlenül hagyja az összefoglalási kéréseket).
2. A kliens összefoglalást kér, például Codex esetén `model_reasoning_summary = "detailed"` / `auto` (nem `none`).
3. A felsőbb réteg ténylegesen streameli a `response.reasoning_summary_text.*` eseményeket (vagy az elem `reasoning.summary` mezője nem üres).

Ha csak „titkosított privát gondolkodást” kap, akkor:

- a mód **`auto`** volt (a kliens kérését eltávolították), vagy
- a felsőbb réteg összefoglaló szöveg nélkül adott vissza `encrypted_content` tartalmat (szolgáltatói korlátozás; az OmniRoute csak helyőrzőt tud megjeleníteni, egyszerű szöveget nem).

## API-példák

```bash
# Lekérdezés
curl -sS https://localhost:20128/api/settings/thinking-budget \
  -H "Authorization: Bearer $OMNIROUTE_TOKEN"

# Ajánlott a gondolkodás láthatóságához Codex / Desktop esetén
curl -sS -X PUT https://localhost:20128/api/settings/thinking-budget \
  -H "Authorization: Bearer $OMNIROUTE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"mode":"passthrough","customBudget":10240,"effortLevel":"medium"}'
```

Séma (`updateThinkingBudgetSchema`): `mode` ∈ `passthrough|auto|custom|adaptive`; opcionális: `customBudget`, `effortLevel`, `baseBudget`, `complexityMultiplier`.

### Megőrzés / újraindítás

Az érték a `thinkingBudget` beállításkulcs alatt tárolódik, és a folyamat indulásakor töltődik be (`hydrateThinkingBudgetConfig`). Adatbázison vagy bizonyos, nem API-alapú útvonalakon keresztül végzett módosítás után **indítsa újra az OmniRoute folyamatot**, hogy a memóriában lévő singleton megfeleljen a lemezen tárolt értéknek.

## Üzemeltetői ellenőrzőlista

- [ ] Codex / Desktop felhasználók: mód = **passthrough**
- [ ] Hagyja bekapcsolva a tömörítést, ha tokeneket szeretne megtakarítani az **üzeneteken**, nem pedig a gondolkodás eltávolításával
- [ ] Ne várja az `auto` módtól, hogy „több gondolkodást jelenítsen meg”
- [ ] A csak titkosított összefoglalók a **szolgáltató** működéséből fakadnak; a passthrough nem tudja visszafejteni őket
