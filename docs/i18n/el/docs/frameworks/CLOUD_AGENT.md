> **Πηγή αλήθειας:** `src/lib/cloudAgent/` και `src/app/api/v1/agents/tasks/`
> **Τελευταία ενημέρωση:** 2026-06-28 — v3.8.40 (ανανέωση frontmatter· 4 agents, συμπεριλαμβανομένου του cursor-cloud)

Το OmniRoute ενορχηστρώνει agents προγραμματισμού που φιλοξενούνται στο cloud από τρίτους παρόχους (Codex Cloud, Cursor,
Devin, Jules) ως μακροχρόνιες εργασίες. Κάθε agent περιβάλλεται από μια ενιαία διεπαφή, ώστε
οι clients να μπορούν να υποβάλλουν ένα prompt + URL αποθετηρίου και να λαμβάνουν αποτελέσματα χωρίς να ασχολούνται με
API συγκεκριμένων παρόχων.

Μια εργασία Cloud Agent **δεν** είναι μια συνηθισμένη ολοκλήρωση συνομιλίας. Είναι μια ανθεκτική, πολυσταδιακή
μονάδα εργασίας που μπορεί να διαρκέσει από λεπτά έως ώρες, να δημιουργήσει ένα Pull Request ως
τεχνούργημά της και να υποστηρίζει μηνύματα παρακολούθησης και (σε ορισμένους παρόχους) πύλες έγκρισης σχεδίου.

## Υποστηριζόμενοι Agents

| Αναγνωριστικό παρόχου | Κλάση              | Πηγή                                  | Βασικό URL ανάντη υπηρεσίας             | Έγκριση σχεδίου |
| --------------------- | ------------------ | ------------------------------------- | --------------------------------------- | --------------- |
| `jules`               | `JulesAgent`       | `src/lib/cloudAgent/agents/jules.ts`  | `https://jules.googleapis.com/v1alpha`  | Ναι             |
| `devin`               | `DevinAgent`       | `src/lib/cloudAgent/agents/devin.ts`  | `https://api.devin.ai/v1`               | Ναι             |
| `codex-cloud`         | `CodexCloudAgent`  | `src/lib/cloudAgent/agents/codex.ts`  | `https://api.openai.com/v1/codex/cloud` | Όχι (αυτόματα)  |
| `cursor-cloud`        | `CursorCloudAgent` | `src/lib/cloudAgent/agents/cursor.ts` | `https://api.cursor.com/v0`             | Όχι (αυτόματα)  |

Μητρώο: `src/lib/cloudAgent/registry.ts` — εξάγει τα `getAgent(providerId)`,
`getAvailableAgents()` και `isCloudAgentProvider(providerId)`. Το μητρώο είναι ένα
απλό `Record<string, CloudAgentBase>` στη μνήμη, το οποίο συμπληρώνεται κατά τη φόρτωση του module.

## Αρχιτεκτονική

```
Client (Dashboard / CLI / API)
  → POST /api/v1/agents/tasks (απαιτείται εξουσιοδότηση διαχείρισης)
    → επικύρωση CreateCloudAgentTaskSchema (Zod)
    → registry.getAgent(providerId)
    → getCloudAgentCredentials(providerId)
      └─ ανακτά από getProviderConnections({ provider, isActive: true })
         (πρώτα apiKey, με εναλλακτική το accessToken)
    → agent.createTask({ prompt, source, options }, credentials)
      └─ HTTP POST προς το API του ανάντη παρόχου
      └─ επιστρέφει CloudAgentTask με εσωτερικό id + externalId
    → insertCloudAgentTask(...) στο cloud_agent_tasks (SQLite)

Περιοδικός έλεγχος (νωθρός συγχρονισμός κατά την ανάγνωση):
  GET /api/v1/agents/tasks/[id]
    → getCloudAgentTaskById(id)
    → agent.getStatus(externalId, credentials)  // ανανεώνει την κατάσταση + τις δραστηριότητες
    → updateCloudAgentTask(...) με νέα κατάσταση, αποτέλεσμα, completed_at
    → επιστρέφει τη σειριοποιημένη εργασία

Αλληλεπιδράσεις:
  POST /api/v1/agents/tasks/[id]  σώμα: { action: "approve" | "message" | "cancel" }
    → agent.approvePlan(externalId, credentials)        για "approve"
    → agent.sendMessage(externalId, message, credentials) για "message"
    → η κατάσταση αλλάζει σε "cancelled"                για "cancel" (μόνο τοπικά)
```

Ο συγχρονισμός είναι **νωθρός**: η κατάσταση ανανεώνεται από την ανάντη υπηρεσία σε κάθε `GET /tasks/[id]`.
Δεν υπάρχει περιοδικός ελεγκτής στο παρασκήνιο. Τα dashboards που χρειάζονται ενημερωμένη κατάσταση θα πρέπει να πραγματοποιούν περιοδικό έλεγχο του endpoint GET
σε εύλογα χρονικά διαστήματα.

## Διεπαφή `CloudAgentBase`

Πηγή: `src/lib/cloudAgent/baseAgent.ts`

```typescript
export interface AgentCredentials {
  apiKey: string;
  baseUrl?: string;
}

export interface CreateTaskParams {
  prompt: string;
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
}

export interface GetStatusResult {
  status: CloudAgentStatus;
  externalId?: string;
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
}

export abstract class CloudAgentBase {
  abstract readonly providerId: string;
  abstract readonly baseUrl: string;

  abstract createTask(p: CreateTaskParams, c: AgentCredentials): Promise<CloudAgentTask>;
  abstract getStatus(externalId: string, c: AgentCredentials): Promise<GetStatusResult>;
  abstract approvePlan(externalId: string, c: AgentCredentials): Promise<void>;
  abstract sendMessage(
    externalId: string,
    message: string,
    c: AgentCredentials
  ): Promise<CloudAgentActivity>;
  abstract listSources(
    c: AgentCredentials
  ): Promise<{ name: string; url: string; branch?: string }[]>;

  protected mapStatus(raw: string): CloudAgentStatus; // ευρετική αντιστοίχιση συμβολοσειράς upstream → enum
  protected generateTaskId(): string; // `task_<ts>_<rand>`
  protected generateActivityId(): string; // `act_<ts>_<rand>`
}
```

Η `CodexCloudAgent.approvePlan` προκαλεί σκόπιμα εξαίρεση — το Codex Cloud δημιουργεί αυτόματα σχέδια και
δεν διαθέτει πύλη έγκρισης. Η `CodexCloudAgent.listSources` επιστρέφει `[]`.

Η `CursorCloudAgent` χειρίζεται τους Background / Cloud Agents του Cursor μέσω του επίσημου REST
API του (`api.cursor.com/v0`) με ένα **κλειδί API χρήστη ή λογαριασμού υπηρεσίας** — την ασφαλέστερη,
επίσημη εναλλακτική έναντι της επαναχρησιμοποίησης της συνεδρίας OAuth του Cursor IDE (πάροχος `cursor`,
ο οποίος συνοδεύεται από προειδοποίηση κινδύνου αποκλεισμού). Είναι ένας απλός προσαρμογέας REST (χωρίς εγγενή
εξάρτηση `@cursor/sdk`). Η `approvePlan` προκαλεί εξαίρεση (οι agents του Cursor λειτουργούν αυτόνομα)· η `listSources` παραθέτει
τα αποθετήρια στα οποία έχει πρόσβαση το κλειδί. Το Cursor επιστρέφει enum καταστάσεων με ΚΕΦΑΛΑΙΑ
(`CREATING`/`RUNNING`/`FINISHED`/`ERROR`), τα οποία αντιστοιχίζονται ρητά στο κοινό
`CloudAgentStatus`. Το `baseUrl` μπορεί να παρακαμφθεί ανά διαπιστευτήριο, ώστε η έκδοση/διαδρομή του API να μπορεί
να διορθωθεί χωρίς αλλαγή στον κώδικα.

## Τύποι τομέα

Πηγή: `src/lib/cloudAgent/types.ts`

```typescript
export const CLOUD_AGENT_STATUS = {
  QUEUED: "queued",
  RUNNING: "running",
  AWAITING_APPROVAL: "awaiting_approval",
  COMPLETED: "completed",
  FAILED: "failed",
  CANCELLED: "cancelled",
} as const;

export interface CloudAgentSource {
  repoName: string;
  repoUrl: string; // πρέπει να είναι έγκυρο URL
  branch?: string;
}

export interface CloudAgentResult {
  prUrl?: string;
  prNumber?: number;
  commitMessage?: string;
  diffUrl?: string;
  summary?: string;
  duration?: number; // δευτερόλεπτα, θετικός ακέραιος
  cost?: number; // θετικός αριθμός κινητής υποδιαστολής
}

export interface CloudAgentActivity {
  id: string;
  type: "plan" | "command" | "code_change" | "message" | "error" | "completion";
  content: string;
  timestamp: string; // ISO 8601
  metadata?: Record<string, unknown>;
}

export interface CloudAgentTask {
  id: string; // εσωτερικό id `task_...`
  providerId: "jules" | "devin" | "codex-cloud" | "cursor-cloud";
  externalId?: string; // id του upstream παρόχου
  status: CloudAgentStatus;
  prompt: string; // 1..10000 χαρακτήρες
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
  createdAt: string;
  updatedAt: string;
  completedAt?: string;
}
```

Τα σχήματα επικύρωσης (`CreateCloudAgentTaskSchema`, `UpdateCloudAgentTaskSchema`)
εξάγονται μαζί με τους τύπους και χρησιμοποιούνται από τους χειριστές διαδρομών.

## Βάση δεδομένων

Πηγή: `src/lib/cloudAgent/db.ts` — ο πίνακας δημιουργείται με καθυστέρηση μέσω της
`createCloudAgentTaskTable()` (η οποία καλείται επίσης από το `src/lib/cloudAgent/index.ts` κατά
την εισαγωγή του module).

```sql
CREATE TABLE IF NOT EXISTS cloud_agent_tasks (
  id           TEXT PRIMARY KEY,
  provider_id  TEXT NOT NULL,
  external_id  TEXT,
  status       TEXT NOT NULL DEFAULT 'queued',
  prompt       TEXT NOT NULL,
  source       TEXT NOT NULL,             -- JSON
  options      TEXT DEFAULT '{}',         -- JSON
  result       TEXT,                       -- JSON
  activities   TEXT DEFAULT '[]',          -- JSON
  error        TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_provider ON cloud_agent_tasks(provider_id);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_status   ON cloud_agent_tasks(status);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_created  ON cloud_agent_tasks(created_at DESC);
```

Η `updateCloudAgentTask` επιβάλλει μια **λίστα επιτρεπόμενων στηλών** για την αποτροπή SQL injection:
`status`, `prompt`, `source`, `options`, `result`, `activities`, `error`,
`completed_at`. Οποιοδήποτε άλλο κλειδί στη μερική ενημέρωση απορρίπτεται σιωπηρά.

## REST API — Κύκλος ζωής εργασίας

**Έλεγχος ταυτότητας:** Όλα τα endpoints `/api/v1/agents/tasks*` απαιτούν **έλεγχο ταυτότητας διαχείρισης**
(η `requireCloudAgentManagementAuth` περικλείει την `requireManagementAuth` από το
`src/lib/api/requireManagementAuth`). Αυτό επιβάλλεται μετά το commit `588a0333`
(_"fix(auth): απαίτηση ελέγχου ταυτότητας διαχείρισης για τα APIs agent και cooldown"_).

| Μέθοδος | Διαδρομή                      | Σκοπός                                                           |
| ------- | ----------------------------- | ---------------------------------------------------------------- |
| OPTIONS | `/api/v1/agents/tasks`        | Προκαταρκτικό αίτημα CORS                                        |
| GET     | `/api/v1/agents/tasks`        | Λίστα εργασιών (φίλτρο: `provider`, `status`, `limit≤500`)       |
| POST    | `/api/v1/agents/tasks`        | Δημιουργία εργασίας (αποστέλλεται upstream + αποθηκεύεται)       |
| DELETE  | `/api/v1/agents/tasks?id=...` | Διαγραφή εργασίας βάσει query id (**δεν** ακυρώνεται upstream)   |
| OPTIONS | `/api/v1/agents/tasks/[id]`   | Προκαταρκτικό αίτημα CORS                                        |
| GET     | `/api/v1/agents/tasks/[id]`   | Ανάγνωση εργασίας + οκνηρός συγχρονισμός κατάστασης από upstream |
| POST    | `/api/v1/agents/tasks/[id]`   | Ενέργεια: `approve` / `message` / `cancel`                       |
| DELETE  | `/api/v1/agents/tasks/[id]`   | Διαγραφή εργασίας βάσει id διαδρομής                             |

### Δημιουργία εργασίας

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Διόρθωσε το σφάλμα στο src/foo.ts όπου ο parser επιστρέφει null",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    },
    "options": {
      "autoCreatePr": true,
      "planApprovalRequired": false
    }
  }'
```

Απόκριση `201`:

```json
{
  "data": {
    "id": "task_1731512345678_abc123def",
    "providerId": "devin",
    "externalId": "session_xyz",
    "status": "queued",
    "prompt": "...",
    "source": { "repoName": "user/repo", "repoUrl": "...", "branch": "main" },
    "options": { "autoCreatePr": true },
    "createdAt": "2026-05-13T12:34:56.789Z"
  }
}
```

### Έγκριση σχεδίου

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"action":"approve"}'
```

### Αποστολή συμπληρωματικού μηνύματος

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"message","message":"Πρόσθεσε επίσης ένα unit test για τον parser"}'
```

### Ακύρωση (μόνο τοπική κατάσταση)

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"cancel"}'
```

Η `cancel` αλλάζει το `status` σε `"cancelled"` στην τοπική βάση δεδομένων, αλλά **δεν** καλεί τον
upstream πάροχο — δεν υπάρχει RPC ακύρωσης στην `CloudAgentBase`. Για να σταματήσει η χρέωση
upstream, τερματίστε την εργασία στην κονσόλα του ίδιου του παρόχου.

## REST API — Διασύνδεση παρόχων Cloud

Αυτά τα βοηθητικά endpoints στο `src/app/api/cloud/` χρησιμοποιούνται από απομακρυσμένους clients
(το CLI, την εφαρμογή Electron ή τους workers συγχρονισμού) για την ανάγνωση μεταδεδομένων σύνδεσης
παρόχων και την επίλυση ψευδωνύμων μοντέλων. Πραγματοποιούν έλεγχο ταυτότητας με ένα **κανονικό API key**
(μέσω του `validateApiKey`) και όχι με τον έλεγχο ταυτότητας διαχείρισης που χρησιμοποιείται από τα endpoints εργασιών.

| Μέθοδος | Διαδρομή                        | Σκοπός                                                                                        |
| ------- | ------------------------------- | --------------------------------------------------------------------------------------------- |
| POST    | `/api/cloud/auth`               | Επικύρωση API key και επιστροφή καλυμμένων μεταδεδομένων σύνδεσης + ψευδωνύμων μοντέλων       |
| PUT     | `/api/cloud/credentials/update` | Ανανέωση των `accessToken` / `refreshToken` / `expiresAt`                                     |
| POST    | `/api/cloud/model/resolve`      | Επίλυση ενός ψευδωνύμου μοντέλου σε `{ provider, model }`                                     |
| GET     | `/api/cloud/models/alias`       | Παράθεση όλων των ψευδωνύμων μοντέλων                                                         |
| PUT     | `/api/cloud/models/alias`       | Ορισμός ψευδωνύμου μοντέλου (και αυτόματος συγχρονισμός στο Cloud, εάν είναι ενεργοποιημένος) |

Το `/api/cloud/auth` δεν επιστρέφει ποτέ τα μη καλυμμένα `apiKey` / `accessToken` / `refreshToken`.
Επιστρέφει τα `hasApiKey`, `hasAccessToken`, `hasRefreshToken` και μια καλυμμένη προεπισκόπηση
(`maskedApiKey`: οι πρώτοι 4 χαρακτήρες + `****` + οι τελευταίοι 4 χαρακτήρες).

## Επίλυση διαπιστευτηρίων

Το `getCloudAgentCredentials(providerId)` στο `src/lib/cloudAgent/api.ts`:

1. Φορτώνει τις ενεργές συνδέσεις παρόχων μέσω του `getProviderConnections({ provider: providerId, isActive: true })`.
2. Για κάθε σύνδεση, προτιμά το `apiKey` (με αφαίρεση κενών). Διαφορετικά, χρησιμοποιεί το `accessToken`.
3. Επιστρέφει το πρώτο μη κενό token, ενθυλακωμένο ως `{ apiKey: token }`.
4. Επιστρέφει `null` εάν δεν βρεθεί χρησιμοποιήσιμο token — το API αποκρίνεται με `400` και
   `"Δεν έχουν ρυθμιστεί ενεργά διαπιστευτήρια για τον πάροχο cloud agent: <id>"`.

Αυτό σημαίνει ότι οι Cloud Agents επαναχρησιμοποιούν τον ίδιο πίνακα Provider Connection με τους κανονικούς
παρόχους LLM. Για να ενεργοποιήσετε το Jules, δημιουργήστε μια ενεργή σύνδεση με `provider: "jules"`
και συμπληρωμένο `apiKey`.

## Πίνακας ελέγχου

Πηγή: `src/app/(dashboard)/dashboard/cloud-agents/page.tsx`

Μια σελίδα React με `"use client"` η οποία:

- Παραθέτει εργασίες (με περιοδικό έλεγχο μέσω `GET /api/v1/agents/tasks`).
- Υποβάλλει νέες εργασίες μέσω μιας φόρμας που αντιστοιχίζεται στο `CreateCloudAgentTaskSchema`.
- Εμφανίζει διακριτικά κατάστασης (`queued`, `running`, `awaiting_approval`, `completed`,
  `failed`, `cancelled`) και αποδίδει τη χρονογραμμή `activities[]`.
- Εμφανίζει τα `result.prUrl` / `commitMessage` / `summary` όταν `status === "completed"`.

## Ενσωμάτωση με το A2A

Οι Cloud Agents μπορούν να εκτεθούν ως δεξιότητες A2A, καταχωρίζοντας μια δεξιότητα A2A που αναθέτει
τον χειριστή `tasks/send` στο `getAgent(...).createTask(...)` και μεταφράζει τα συμβάντα κατάστασης
εργασιών A2A στο πρωτόκολλο JSON-RPC 2.0. Δείτε το [A2A-SERVER.md](./A2A-SERVER.md).

## Προσθήκη νέου Cloud Agent

1. Δημιουργήστε το `src/lib/cloudAgent/agents/<name>.ts` επεκτείνοντας το `CloudAgentBase`.
2. Υλοποιήστε τα `createTask`, `getStatus`, `approvePlan` (ή δημιουργήστε εξαίρεση εάν δεν εφαρμόζεται),
   `sendMessage`, `listSources`. Χρησιμοποιήστε το `this.mapStatus(...)` για την κανονικοποίηση της κατάστασης.
3. Καταχωρίστε τον στο `src/lib/cloudAgent/registry.ts` με ένα σταθερό `providerId`.
4. Επεκτείνετε την ένωση κυριολεκτικών τιμών `providerId` στο `src/lib/cloudAgent/types.ts`
   (`CloudAgentTask.providerId` και `CreateCloudAgentTaskSchema`).
5. Προσθέστε τον πάροχο στο `src/shared/constants/providers.ts` εάν χρειάζεται εγγραφή σύνδεσης.
   Οι πάροχοι που βασίζονται στο OAuth χρειάζονται επίσης το `src/lib/oauth/providers/`.
6. Προσθέστε δοκιμές στο `tests/unit/cloud-agent-*.test.ts`.
7. Ενημερώστε αυτό το έγγραφο και τη σταθερά `CLOUD_AGENTS` του πίνακα ελέγχου.

## Ρύθμιση παραμέτρων

| Μεταβλητή περιβάλλοντος | Σκοπός                                                                                       |
| ----------------------- | -------------------------------------------------------------------------------------------- |
| `DATA_DIR`              | Θέση της βάσης δεδομένων SQLite που περιέχει το `cloud_agent_tasks`                          |
| `JWT_SECRET`            | Απαιτείται για τον έλεγχο ταυτότητας διαχείρισης στα endpoints εργασιών                      |
| `API_KEY_SECRET`        | Απαιτείται για την κρυπτογράφηση των διαπιστευτηρίων σύνδεσης παρόχου σε κατάσταση αδράνειας |

Δεν υπάρχουν σήμερα μεταβλητές περιβάλλοντος ειδικές για το Cloud-Agent — κάθε μυστικό βρίσκεται στον πίνακα
`provider_connections`.
