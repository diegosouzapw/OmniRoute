Το Traffic Inspector είναι το ενσωματωμένο πρόγραμμα εντοπισμού σφαλμάτων κίνησης HTTPS του OmniRoute — ένα εργαλείο παρόμοιο με τα Charles Proxy / mitmweb / HTTP Toolkit, το οποίο έχει **επίγνωση LLM** και **επίγνωση πρακτόρων**. Βρίσκεται στη διαδρομή `/dashboard/tools/traffic-inspector` και λαμβάνει ζωντανή κίνηση από έως και 5 ταυτόχρονες πηγές καταγραφής.

**Τοποθεσία στον πίνακα ελέγχου:** `/dashboard/tools/traffic-inspector`
**Ομάδα πλευρικής γραμμής:** Εργαλεία (μετά το AgentBridge)
**Δείτε επίσης:** [`AGENTBRIDGE.md`](./AGENTBRIDGE.md) — Το AgentBridge είναι η λειτουργία καταγραφής 1.

### Η αρχιτεκτονική σε μία παράγραφο

Το `TrafficBuffer` (`src/mitm/inspector/buffer.ts`) είναι ένας κοινόχρηστος κυκλικός ενδιάμεσος αποθηκευτικός χώρος στη μνήμη (προεπιλογή 1000 καταχωρίσεις, με δυνατότητα ρύθμισης μέσω του `INSPECTOR_BUFFER_SIZE`). Όλες οι πηγές καταγραφής γράφουν σε αυτόν μέσω της `push()`. Η κλάση του ενδιάμεσου αποθηκευτικού χώρου ταξινομεί κάθε καταχώριση χρησιμοποιώντας το `kindDetector.ts` (καθορίζει αν πρόκειται για αίτημα LLM), υπολογίζει ένα `contextKey` (δακτυλικό αποτύπωμα SHA-256 της προτροπής συστήματος) και τη μεταδίδει σε όλους τους συνδρομητές WebSocket μέσω του `globalTrafficBuffer.subscribe()`. Ο πίνακας ελέγχου συνδέεται μέσω του `GET /api/tools/traffic-inspector/ws` και λαμβάνει ένα στιγμιότυπο κατά τη σύνδεση, ακολουθούμενο από συμβάντα `new`/`update`/`clear`.

## §2 Λειτουργίες καταγραφής

Το Traffic Inspector υποστηρίζει **5 ταυτόχρονες πηγές καταγραφής**. Κάθε μία μπορεί να ενεργοποιηθεί ή να απενεργοποιηθεί ανεξάρτητα. Το πεδίο `source` σε κάθε `InterceptedRequest` (`src/mitm/inspector/types.ts`) έχει μία από τις τιμές `"agent-bridge"`, `"custom-host"`, `"http-proxy"`, `"system-proxy"` ή `"tproxy"`.

### Λειτουργία 1 — AgentBridge (προεπιλεγμένη, πάντα ενεργή)

**Πηγή:** Χειριστές AgentBridge (`src/mitm/handlers/base.ts`)
**Μηχανισμός:** Κάθε κλήση `intercept()` στο `MitmHandlerBase` καλεί το `hookBufferStart()` πριν από την προώθηση και το `hookBufferUpdate()` κατά την ολοκλήρωση. Δεν απαιτείται καμία πρόσθετη ρύθμιση — λειτουργεί μόλις εκτελείται το AgentBridge.
**Εμβέλεια:** Οι 9 πράκτορες IDE που έχουν διαμορφωθεί στο AgentBridge
**Σημείωση:** Το πεδίο `source` στο `InterceptedRequest` = `"agent-bridge"`

### Λειτουργία 2 — Προσαρμοσμένοι κεντρικοί υπολογιστές (ανακατεύθυνση DNS)

**Πηγή:** Λίστα κεντρικών υπολογιστών που ορίζεται από τον χρήστη (πίνακας `inspector_custom_hosts`)
**Μηχανισμός:** Η προσθήκη ενός κεντρικού υπολογιστή μέσω του UI προσθέτει το `127.0.0.1 <host>` στο `/etc/hosts` (απαιτεί sudo). Ο υπάρχων διακομιστής MITM του AgentBridge (θύρα 443) δημιουργεί δυναμικά ένα πιστοποιητικό SNI για τον νέο κεντρικό υπολογιστή.
**Εμβέλεια:** Οποιαδήποτε εφαρμογή χρησιμοποιεί τον κεντρικό υπολογιστή που προστέθηκε — δεν απαιτείται αλλαγή στη διαμόρφωση της εφαρμογής
**Σημείωση:** `source` = `"custom-host"`

Παραδείγματα περιπτώσεων χρήσης:

- Παρακολούθηση του `api.openai.com` από δέσμες ενεργειών Python
- Εντοπισμός σφαλμάτων στο `my-internal-llm.company.com`
- Καταγραφή κίνησης από κινητές συσκευές στο ίδιο δίκτυο (μέσω πλαστογράφησης ARP — για προχωρημένους)

### Λειτουργία 3 — Ακροατής HTTP_PROXY (θύρα 8080)

**Πηγή:** Εφαρμογές που χρησιμοποιούν τις μεταβλητές περιβάλλοντος `HTTP_PROXY`/`HTTPS_PROXY`
**Μηχανισμός:** Δευτερεύων ακροατής στη θύρα 8080 (`src/mitm/inspector/httpProxyServer.ts`), ο οποίος λειτουργεί ως τυπικός ρητός διακομιστής μεσολάβησης HTTP/HTTPS. Αποδέχεται σήραγγες `CONNECT` (HTTPS) και απευθείας αιτήματα HTTP.
**Εμβέλεια:** Οποιαδήποτε εφαρμογή λαμβάνει υπόψη τη μεταβλητή περιβάλλοντος `HTTP_PROXY` — χωρίς αλλαγή DNS, χωρίς sudo
**Σημείωση:** `source` = `"http-proxy"`

```bash
# Γρήγορη καταγραφή για μία μόνο εντολή:
HTTPS_PROXY=http://127.0.0.1:8080 curl https://api.openai.com/v1/models

# Μόνιμη καταγραφή σε μια περίοδο λειτουργίας κελύφους:
export HTTP_PROXY=http://127.0.0.1:8080
export HTTPS_PROXY=http://127.0.0.1:8080
```

**Περιορισμός TLS:** Οι σήραγγες HTTPS `CONNECT` καταγράφονται μόνο ως μεταδεδομένα (κεντρικός υπολογιστής, θύρα, χρονισμός) — το σώμα TLS δεν αποκρυπτογραφείται από προεπιλογή. Ενεργοποιήστε την επιλογή "Αποκρυπτογράφηση HTTPS σε λειτουργία διακομιστή μεσολάβησης" (προαιρετική, απαιτεί το πιστοποιητικό του AgentBridge να είναι αξιόπιστο) για πλήρη επιθεώρηση του σώματος.

**Διένεξη θύρας:** Εάν η θύρα 8080 χρησιμοποιείται ήδη, το AgentBridge επιστρέφει 409 με δομημένο σφάλμα. Αλλάξτε τη θύρα μέσω της μεταβλητής περιβάλλοντος `INSPECTOR_HTTP_PROXY_PORT`.

### Λειτουργία 4 — Διακομιστής μεσολάβησης σε επίπεδο συστήματος (για προχωρημένους, προαιρετικός)

**Πηγή:** Ρυθμίσεις διακομιστή μεσολάβησης σε επίπεδο λειτουργικού συστήματος (εφαρμόζονται σε όλες τις εφαρμογές του μηχανήματος)
**Μηχανισμός:** Χρησιμοποιεί API του λειτουργικού συστήματος για την ανακατεύθυνση όλης της κίνησης HTTP/HTTPS μέσω του ακροατή HTTP_PROXY:

- **macOS:** `networksetup -setwebproxy / -setsecurewebproxy`
- **Linux:** `gsettings set org.gnome.system.proxy` + `/etc/environment`
- **Windows:** `netsh winhttp set proxy 127.0.0.1:8080`
  **Εμβέλεια:** Κάθε εφαρμογή στο μηχάνημα που λαμβάνει υπόψη τις ρυθμίσεις διακομιστή μεσολάβησης του συστήματος
  **Σημείωση:** `source` = `"system-proxy"`

**Μηχανισμοί ασφαλείας:**

- Χρονοδιακόπτης αυτόματης απενεργοποίησης (προεπιλογή 30 λεπτά, διαμορφώσιμος μέσω `INSPECTOR_SYSTEM_PROXY_GUARD_MINUTES`)
- Η προηγούμενη κατάσταση του διακομιστή μεσολάβησης συστήματος αποθηκεύεται στη βάση δεδομένων και επαναφέρεται κατά την αναίρεση
- Ο πίνακας ελέγχου εμφανίζει την προτροπή "Επαναφορά διακομιστή μεσολάβησης συστήματος" εάν ο χρήστης απομακρυνθεί από τη σελίδα ενώ είναι ενεργός
- Το UI εμφανίζει το σήμα `⚠ Για προχωρημένους` + ένα ρητό πλαίσιο ελέγχου επιβεβαίωσης

### Λειτουργία 5 — Διαφανής αποκρυπτογράφηση TPROXY (Linux, root, προαιρετική)

**Πηγή:** TPROXY πυρήνα + δρομολόγηση βάσει πολιτικής (`src/mitm/tproxy/`)
**Μηχανισμός:** Επισημαίνει τις νέες τοπικές εξερχόμενες συνδέσεις TCP προς μια θύρα προορισμού (προεπιλογή `443`) στο `mangle OUTPUT`, ένας κανόνας `ip rule` επαναδρομολογεί τα επισημασμένα πακέτα για τοπική παράδοση και ο στόχος `TPROXY` του `mangle PREROUTING` τα παραδίδει σε έναν διαφανή ακροατή (**IP_TRANSPARENT**) (προεπιλεγμένη θύρα `8443`). Ο ακροατής τερματίζει το TLS με ένα πιστοποιητικό φύλλου που εκδίδεται **κατά απαίτηση για κάθε όνομα κεντρικού υπολογιστή SNI** από μια δυναμική CA, καταγράφει την αποκρυπτογραφημένη ανταλλαγή και προωθεί το αίτημα, εκ νέου κρυπτογραφημένο, στον αρχικό προορισμό.
**Εμβέλεια:** **Οποιοιδήποτε** κεντρικοί υπολογιστές προορισμού στη θύρα-στόχο — χωρίς πλαστογράφηση `/etc/hosts`, χωρίς μεταβλητή περιβάλλοντος `HTTP_PROXY`, χωρίς τροποποίηση του διακομιστή μεσολάβησης σε επίπεδο συστήματος. Η διεργασία που αναχαιτίζεται δεν χρειάζεται καμία αλλαγή διαμόρφωσης, αλλά πρέπει να εμπιστεύεται τη δυναμική CA.
**Σημείωση:** `source` = `"tproxy"`

**Απαιτήσεις:** Μόνο Linux (το **IP_TRANSPARENT** διατίθεται αποκλειστικά στο Linux), η δυνατότητα **CAP_NET_ADMIN** (root) και ένα εγγενές πρόσθετο N-API που πρέπει να δημιουργηθεί με μια αλυσίδα εργαλείων C (`npm run build:native:tproxy`). Όταν δεν είναι διαθέσιμο, ο διακόπτης στον πίνακα ελέγχου είναι απενεργοποιημένος και εμφανίζει την επεξήγηση "Η αποκρυπτογράφηση TPROXY απαιτεί Linux + root + το εγγενές πρόσθετο". Οι κανόνες του τείχους προστασίας εφαρμόζονται/αναιρούνται συναλλακτικά (μια κατάρρευση δεν αφήνει ποτέ πίσω της κανόνα `mangle`) και εκκαθαρίζονται κατά την επανεκκίνηση. Ένας μηχανισμός αποτροπής βρόχου που βασίζεται στο SO_MARK εμποδίζει την εκ νέου αναχαίτιση της επανακρυπτογραφημένης προώθησης του ίδιου του διακομιστή μεσολάβησης.

Πρόκειται για ένα σημαντικό υποσύστημα με τον δικό του αποκλειστικό οδηγό χειριστή — ανατρέξτε στο `docs/security/MITM-TPROXY-DECRYPT.md` (git· δεν μεταγλωττίζεται στο `/docs`) για την πλήρη συνταγή του τείχους προστασίας, τη δυναμική CA ανά SNI + το πρόγραμμα εγκατάστασης στο χώρο αποθήκευσης αξιόπιστων πιστοποιητικών, την τοπική μόνο διαδρομή, τις λεπτομέρειες αποτροπής βρόχου και το σχήμα διαμόρφωσης. Ο διακόπτης ελέγχεται μέσω των `GET / POST / DELETE /api/tools/agent-bridge/tproxy` (σημείωση: η διαδρομή βρίσκεται κάτω από το πρόθεμα του AgentBridge και όχι κάτω από το πρόθεμα του Traffic Inspector).

### 3.2 Λίστα αιτημάτων (αριστερό πλαίσιο)

- **Εικονικοποιημένη** (`useVirtualList` + `ResizeObserver`): διαχειρίζεται 1000 στοιχεία χωρίς να παγώνει
- **Αυτόματη κύλιση** με διακόπτη για παύση κατά την επιθεώρηση
- **Χρωματική κωδικοποίηση κατάστασης**: πράσινο (2xx), κίτρινο (3xx), κόκκινο (4xx/5xx), γκρι (σε εξέλιξη)
- **Emoji agent**: 🔵 Antigravity, 🟢 Copilot, 🟠 Kiro, 🟣 Codex, 🔷 Cursor, 🟤 Zed, 🟡 Claude Code, ⚫ Open Code, 🌐 προσαρμοσμένος host
- **Χρωματική γραμμή περιβάλλοντος**: αριστερό περίγραμμα 1px με χρώμα βάσει του `contextKey` (SHA-256 του system prompt) — ομαδοποιεί οπτικά τις σχετικές συνομιλίες
- **Οκνηρή φόρτωση body**: μόνο το body του επιλεγμένου αιτήματος υλοποιείται στις καρτέλες λεπτομερειών (αποφεύγεται η απόδοση 1000 × 1MB bodies)

## §4 Λειτουργίες με επίγνωση LLM

### 4.1 Ανιχνευτής είδους (`src/mitm/inspector/kindDetector.ts`)

Ταξινομεί κάθε αίτημα ως `"llm"`, `"app"` ή `"unknown"` χρησιμοποιώντας 4 ενδείξεις:

1. **Μητρώο κεντρικών υπολογιστών** — ~18 γνωστά ονόματα κεντρικών υπολογιστών API για LLM (OpenAI, Anthropic, Gemini, Groq, Mistral, Together, Fireworks, Cohere, Perplexity, Hugging Face, OpenRouter, xAI, Moonshot κ.λπ.)
2. **Μοτίβα διαδρομών** — `/v1/chat/completions`, `/v1/messages`, `/generateContent`, `/v1/responses` κ.λπ.
3. **Δομή σώματος** — ανιχνεύει πεδία `messages[]` (OpenAI/Claude), `contents[]` (Gemini), `prompt`, `input`
4. **Ενδείξεις user-agent** — `codex`, `claude`, `gemini`, `antigravity`, `kiro`, `copilot`, `cursor` στη συμβολοσειρά UA

Οι προσαρμοσμένοι κεντρικοί υπολογιστές που προστίθενται μέσω της Λειτουργίας 2 κληρονομούν το `kind` τους από την είσοδο της φόρμας (προεπιλογή: `"custom"`).

### 4.2 Συγχωνευτής SSE (`src/mitm/inspector/sseMerger.ts`)

**Ανεξάρτητη υλοποίηση καθαρού χώρου.** Η ανάλυση συμβάντων ακολουθεί τον
[αλγόριθμο συμβάντων αποστελλόμενων από διακομιστή του WHATWG](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream),
ενώ η ανακατασκευή ακολουθεί τα δημόσια σχήματα ροής των [OpenAI](https://platform.openai.com/docs/api-reference/chat/create),
[Anthropic](https://platform.claude.com/docs/en/build-with-claude/streaming) και
[Gemini](https://ai.google.dev/api/generate-content#method:-models.streamgeneratecontent).

Ανακατασκευάζει το τελικό μήνυμα του βοηθού από ανεπεξέργαστα συμβάντα διαφορών SSE:

- **Anthropic**: συσσωρεύει `content_block_delta` ανά ευρετήριο· χειρίζεται `text_delta`, `input_json_delta` (κλήσεις εργαλείων), `thinking_delta`
- **OpenAI**: συσσωρεύει επιλογές/κλήσεις εργαλείων του Chat Completions και στοιχεία εξόδου του Responses API
  ανά ευρετήριο
- **Gemini**: συσσωρεύει `candidates[i].content.parts`
- **Άγνωστο**: επιστρέφει τα ανεπεξέργαστα συμβάντα ως έχουν

Η καρτέλα Απόκριση εμφανίζει έναν διακόπτη: **"Ανεπεξέργαστα συμβάντα ↔ Συγχωνευμένα"**.

### 4.3 Κανονικοποιητής συνομιλιών (`src/mitm/inspector/conversationNormalizer.ts`)

**Ανεξάρτητη υλοποίηση καθαρού χώρου.** Η κανονικοποίηση ορίζεται από τοπικά συμβόλαια
μαύρου κουτιού και τα δημόσια σχήματα μηνυμάτων των OpenAI, Anthropic και Gemini· δεν
χρησιμοποιείται πηγαίος κώδικας υλοποίησης από εξωτερικό έργο.

Μετατρέπει τις μορφές μηνυμάτων των OpenAI, Anthropic και Gemini σε ένα ενιαίο `NormalizedConversation` πριν από την απόδοση:

```ts
interface NormalizedConversation {
  request: NormalizedTurn[]; // μηνύματα / περιεχόμενα / προτροπή από το σώμα του αιτήματος
  response: NormalizedTurn[]; // απόκριση βοηθού (συγχωνευμένη μέσω του sseMerger)
  contextKey: string | null; // αποτύπωμα SHA-256 της προτροπής συστήματος
}
```

Τύποι μπλοκ: `text`, `tool_use`, `tool_result`. Η καρτέλα Συνομιλία χρησιμοποιεί αυτήν τη δομή ανεξάρτητα από τον πάροχο.

### 4.4 Χρωματισμός κλειδιού περιβάλλοντος (`src/mitm/inspector/contextKey.ts`)

- Υπολογίζει το `SHA-256` της προτροπής συστήματος (πρώτο μήνυμα `role:system`, ή πεδίο `system`, ή `systemInstruction` του Gemini)
- Επιστρέφει ένα δεκαεξαδικό πρόθεμα 12 χαρακτήρων (`"a3f9c2..."`)
- Το frontend αντιστοιχίζει το κλειδί σε ένα ντετερμινιστικό χρώμα HSL για τη γραμμή του αριστερού περιγράμματος
- **Φίλτρο "ίδιο περιβάλλον"**: κάνοντας κλικ στο chip `ctx #a3f` προστίθεται ένα φίλτρο που εμφανίζει μόνο αιτήματα με το ίδιο αποτύπωμα

Αυτό διευκολύνει την οπτική διάκριση διαφορετικών "προσωπικοτήτων" ή εργασιών που εκτελούνται στην ίδια συνεδρία πράκτορα.

### 4.5 Εξαγωγή μεταδεδομένων LLM

Για αιτήματα LLM, η καρτέλα Λεπτομέρειες LLM εξάγει:

```ts
interface LlmMetadata {
  provider: string | null; // "openai" | "anthropic" | "gemini" | ...
  apiKind: string | null; // "chat.completions" | "messages" | "embeddings" | ...
  model: string | null; // από το σώμα του αιτήματος ή την απόκριση
  messages: number; // πλήθος εναλλαγών
  tokensIn: number | null; // usage.prompt_tokens / usage.input_tokens
  tokensOut: number | null; // usage.completion_tokens / usage.output_tokens
  streamed: boolean; // true εάν πρόκειται για απόκριση SSE
  mappedTo: string | null; // κεφαλίδα x-omniroute-mapped
  costEstimateUsd: number | null; // εκτιμώμενο κόστος βάσει της τιμολόγησης του OmniRoute
}
```

### 4.6 Φίλτρο ενεργών αιτημάτων σε πραγματικό χρόνο

Το πεδίο `status` του αιτήματος είναι `number | "in-flight" | "error"` — μια καταχώριση
προστίθεται ως `"in-flight"` τη στιγμή που ξεκινά το αίτημα και **ενημερώνεται επιτόπου**
όταν φτάσει η απόκριση (ή το σφάλμα). Ο διακόπτης **"Ενεργά"** της γραμμής εργαλείων
(`liveOnly`, κλειδί i18n `trafficInspector.liveOnly`) περιορίζει τη λίστα σε καταχωρίσεις
των οποίων το `status === "in-flight"`, επιτρέποντάς σας να παρακολουθείτε ανοιχτές συνδέσεις σε πραγματικό χρόνο.

Το φίλτρο είναι ένα αμιγώς client-side κατηγόρημα στο
`src/lib/inspector/matchesTrafficFilter.ts`:

```ts
if (f.liveOnly && req.status !== "in-flight") return false;
```

Η κατάσταση του διακόπτη βρίσκεται στο `useTrafficFilters` (τα hooks του πίνακα ελέγχου του επιθεωρητή) και
συνδυάζεται με τα άλλα φίλτρα (προφίλ, κεντρικός υπολογιστής, πράκτορας, προέλευση, κατάσταση, περιβάλλον).

### 4.7 Απόδοση διεργασίας (Linux)

Στο Linux, κάθε υποκλαπέν αίτημα μπορεί να αποδοθεί στην **τοπική διεργασία
προέλευσης**. Δύο προαιρετικά πεδία προστίθενται στο `InterceptedRequest`:

```ts
pid?: number;          // αναγνωριστικό διεργασίας προέλευσης (μόνο σε Linux)
processName?: string;  // όνομα διεργασίας προέλευσης (μόνο σε Linux)
```

Το `src/mitm/inspector/processAttribution.ts` αντιστοιχίζει την προσωρινή θύρα
_πελάτη_ της σύνδεσης σε ένα PID + όνομα ως εξής:

1. Διαβάζει τα `/proc/net/tcp` και `/proc/net/tcp6` για να βρει το inode του socket για τη
   θύρα (`parseProcNetTcpForInode`, ένας αμιγής αναλυτής που μπορεί να ελεγχθεί με fixtures).
2. Σαρώνει το `/proc/<pid>/fd/` για έναν συμβολικό σύνδεσμο προς `socket:[<inode>]`.
3. Διαβάζει το όνομα της διεργασίας από το `/proc/<pid>/comm`.

Μια κρυφή μνήμη TTL 1 δευτερολέπτου περιορίζει το κόστος σάρωσης του procfs υπό φόρτο. Η απόδοση είναι
**βέλτιστης προσπάθειας** — οποιαδήποτε αποτυχία επιλύεται σε `null` και δεν εμποδίζει ποτέ την καταγραφή. Σε
macOS/Windows η συνάρτηση επιστρέφει `null` (stub· η υποστήριξη `lsof`/`GetExtendedTcpTable`
αποτελεί μελλοντική εργασία).

## §5 Συνεδρίες

### 5.1 Καταγραφή μιας συνεδρίας

1. Κάντε κλικ στο **"● Καταγραφή συνεδρίας"** στη γραμμή εργαλείων → εισαγάγετε ένα όνομα (προαιρετικά)
2. Η ζωντανή ροή συνεχίζεται κανονικά· μια κόκκινη παλλόμενη ένδειξη εμφανίζει `◉ REC · <όνομα> · 00:42 · 23 αιτήματα`
3. Κάντε κλικ στο **"⏹ Διακοπή"** → το στιγμιότυπο της συνεδρίας αποθηκεύεται στα `inspector_sessions` + `inspector_session_requests`

### 5.2 Προβολή μιας καταγεγραμμένης συνεδρίας

Το αναπτυσσόμενο μενού **Συνεδρίες** στη γραμμή εργαλείων παραθέτει τις αποθηκευμένες συνεδρίες. Επιλέγοντας μία:

- Φορτώνεται το στιγμιότυπο της συνεδρίας (παγωμένη κατάσταση)
- Ένα πλαίσιο εμφανίζει: `Προβολή καταγεγραμμένης συνεδρίας "<όνομα>" — [Επιστροφή στη ζωντανή ροή]`
- Η καρτέλα Στατιστικά γίνεται διαθέσιμη με συγκεντρωτικά στοιχεία του Recharts

### 5.3 Μορφές εξαγωγής

Κάθε συνεδρία μπορεί να εξαχθεί ως:

| Μορφή                      | Χρήση                                                                              |
| -------------------------- | ---------------------------------------------------------------------------------- |
| **HAR** (HTTP Archive 1.2) | Συμβατό με Chrome DevTools, Charles, Fiddler — εισαγωγή για ανάλυση εκτός σύνδεσης |
| **JSONL**                  | Ένα `InterceptedRequest` ανά γραμμή — συμβατό με τη μορφή του `llm-interceptor`    |

Εξαγάγετε μέσω `GET /api/tools/traffic-inspector/sessions/{id}/export.har` ή του κουμπιού ⬇ στο αναπτυσσόμενο μενού Συνεδρίες.

## §6 Ασφάλεια

Το Traffic Inspector εμφανίζει **όλη την υποκλαπείσα κίνηση HTTPS**, συμπεριλαμβανομένων των κεφαλίδων εξουσιοδότησης και των σωμάτων αιτημάτων. Εφαρμόζονται οι ακόλουθοι έλεγχοι:

| Έλεγχος                            | Λεπτομέρειες                                                                                                                                                                                                               |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LOCAL_ONLY**                     | Όλες οι διαδρομές και το τελικό σημείο WebSocket είναι προσβάσιμα μόνο μέσω loopback (επιβάλλεται στο `routeGuard.ts` πριν από τον έλεγχο ταυτότητας)                                                                      |
| **Απόκρυψη μυστικών**              | Ο γραμμικός σαρωτής `maskSecret()` αποκρύπτει διαπιστευτήρια Bearer του RFC 6750, κλειδιά με πρόθεμα παρόχου και μεγάλα αδιαφανή διακριτικά πριν από το `TrafficBuffer.push()`                                             |
| **Όριο μεγέθους σώματος**          | Σώματα > `INSPECTOR_MAX_BODY_KB` (προεπιλογή 1024 KB) περικόπτονται με την ειδοποίηση `"(περικόπηκε για λόγους απόδοσης)"`                                                                                                 |
| **Εξυγίανση κεφαλίδων**            | Τα ονόματα μετατρέπονται σε πεζά· οι κεφαλίδες πλαισίωσης/hop-by-hop και ελέγχου ταυτότητας διακομιστή μεσολάβησης απορρίπτονται· τα cookies αποκρύπτονται πλήρως· οι τιμές διαπιστευτηρίων ανατίθενται στο `maskSecret()` |
| **CSP**                            | Αυστηρή Πολιτική Ασφάλειας Περιεχομένου στις σελίδες του Traffic Inspector για την αποτροπή XSS μέσω εισαγόμενων σωμάτων αποκρίσεων                                                                                        |
| **Καμία διατήρηση από προεπιλογή** | Το `TrafficBuffer` βρίσκεται στη μνήμη και χάνεται κατά την επανεκκίνηση του διακομιστή. Οι συνεδρίες διατηρούνται μόνο όταν καταγράφονται ρητά                                                                            |

### Εφαρμοζόμενοι αυστηροί κανόνες

| Κανόνας                           | Εφαρμογή                                                                                                        |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| **#12** `sanitizeErrorMessage`    | Όλες οι αποκρίσεις σφάλματος HTTP από τις διαδρομές του Traffic Inspector εξυγιαίνονται                         |
| **#15 + #17** `isLocalOnlyPath()` | Το `/api/tools/traffic-inspector/` είναι LOCAL_ONLY + SPAWN_CAPABLE (εντολές διακομιστή μεσολάβησης συστήματος) |

### Γνωστοί περιορισμοί

- Η **λειτουργία διακομιστή μεσολάβησης σε επίπεδο συστήματος** επηρεάζει όλες τις εφαρμογές του μηχανήματος, συμπεριλαμβανομένων των προγραμμάτων-πελατών VPN και του SSO. Να χρησιμοποιείται πάντα με το χρονόμετρο αυτόματης απενεργοποίησης. Μην τη χρησιμοποιείτε σε κοινόχρηστα μηχανήματα.
- **HTTPS μέσω σήραγγας CONNECT**: Η λειτουργία 3 (HTTP_PROXY) καταγράφει μόνο τα μεταδεδομένα της σήραγγας για προορισμούς HTTPS, εκτός εάν είναι ενεργοποιημένη η υποκλοπή TLS. Αυτό είναι σκόπιμο — η διαφανής καταγραφή χωρίς να θεωρείται αξιόπιστο το πιστοποιητικό AgentBridge θα προκαλούσε αποτυχία της επαλήθευσης TLS για αυτές τις εφαρμογές.
- **Σκληρά κωδικοποιημένες συμβολοσειρές σε ορισμένα στοιχεία**: Ορισμένα στοιχεία διεπαφής χρήστη (F7/F8) περιέχουν έναν μικρό αριθμό σκληρά κωδικοποιημένων συμβολοσειρών που δεν καλύπτονται ακόμη από κλειδιά i18n. Αυτές τεκμηριώνονται ως Γνωστός Περιορισμός στην αναφορά κενών i18n· θα μεταφερθούν σε επόμενο κύκλο εργασιών. Οι επηρεαζόμενες συμβολοσειρές είναι διακοσμητικές ετικέτες της διεπαφής χρήστη που δεν απαιτούν μετάφραση για λειτουργική χρήση.

Εάν η ζωντανή παρακολούθηση εμφανίζει «Αποσυνδέθηκε»:

1. Ελέγξτε ότι ο διακομιστής εξακολουθεί να εκτελείται: `GET /api/tools/traffic-inspector/capture-modes`
2. Επαναφορτώστε τη σελίδα — το WebSocket επανασυνδέεται και λαμβάνει ένα νέο στιγμιότυπο
3. Εάν έγινε επανεκκίνηση του διακομιστή, το buffer στη μνήμη εκκαθαρίστηκε — οι παλιές καταχωρίσεις έχουν χαθεί, εκτός εάν είχε καταγραφεί μια συνεδρία

### Διένεξη στη θύρα 8080

Εάν η λειτουργία HTTP_PROXY αποτύχει να ξεκινήσει:

```bash
lsof -i :8080    # εντοπισμός της διεργασίας
```

Αλλάξτε τη θύρα:

```bash
# .env
INSPECTOR_HTTP_PROXY_PORT=8888
```

### Ο διακομιστής μεσολάβησης συστήματος δεν επανήλθε

Εάν το OmniRoute καταρρεύσει ενώ είναι ενεργή η λειτουργία διακομιστή μεσολάβησης σε όλο το σύστημα:

**macOS:**

```bash
networksetup -setwebproxystate Wi-Fi off
networksetup -setsecurewebproxystate Wi-Fi off
```

**Linux (GNOME):**

```bash
gsettings set org.gnome.system.proxy mode 'none'
```

**Windows:**

```cmd
netsh winhttp reset proxy
```

Ο πίνακας ελέγχου θα προσφέρει επίσης την επιλογή «Επαναφορά διακομιστή μεσολάβησης συστήματος» κατά την επόμενη φόρτωση, εάν εντοπίσει ότι η κατάσταση της DB υποδεικνύει πως ο διακομιστής μεσολάβησης ήταν ενεργός.

### Πλήρες buffer

Όταν το buffer φτάσει το `INSPECTOR_BUFFER_SIZE` (προεπιλογή 1000), οι νέες καταχωρίσεις αντικαθιστούν τις παλαιότερες. Εάν χάνονται σημαντικά αιτήματα:

- Αυξήστε το `INSPECTOR_BUFFER_SIZE` (π.χ. 5000) — αυξάνει τη χρήση μνήμης για μεγαλύτερη διατήρηση
- Καταγράψτε μια συνεδρία για να αποθηκεύσετε το σχετικό χρονικό διάστημα στην DB

## §8 Αναφορά API

Όλες οι διαδρομές είναι `LOCAL_ONLY` (μόνο loopback) και `SPAWN_CAPABLE` (εντολές διακομιστή μεσολάβησης συστήματος). Ανατρέξτε στο `src/server/authz/routeGuard.ts`.

Βασική διαδρομή: `/api/tools/traffic-inspector/`

### Διαχείριση αιτημάτων

| Μέθοδος | Διαδρομή                    | Περιγραφή                                                                                 |
| ------- | --------------------------- | ----------------------------------------------------------------------------------------- |
| GET     | `/requests`                 | Παραθέτει τα αιτήματα (με φίλτρα: `?profile=llm&host=&agent=&status=&source=&sessionId=`) |
| GET     | `/requests/{id}`            | Λεπτομέρειες μεμονωμένου αιτήματος                                                        |
| DELETE  | `/requests`                 | Εκκαθαρίζει το buffer στη μνήμη                                                           |
| POST    | `/requests/{id}/replay`     | Εκτελεί ξανά το ίδιο αίτημα μέσω του δρομολογητή OmniRoute                                |
| PUT     | `/requests/{id}/annotation` | Αποθηκεύει ή ενημερώνει μια σημείωση σε ένα αίτημα                                        |

### WebSocket

| Μέθοδος | Διαδρομή | Περιγραφή                                                                                            |
| ------- | -------- | ---------------------------------------------------------------------------------------------------- |
| GET     | `/ws`    | Ζωντανή ροή WebSocket. Στέλνει `snapshot` κατά τη σύνδεση και έπειτα συμβάντα `new`/`update`/`clear` |

### Εξαγωγή

| Μέθοδος | Διαδρομή      | Περιγραφή                                          |
| ------- | ------------- | -------------------------------------------------- |
| GET     | `/export.har` | Εξάγει την τρέχουσα φιλτραρισμένη λίστα ως HAR 1.2 |

### Προσαρμοσμένοι hosts

| Μέθοδος | Διαδρομή        | Περιγραφή                                               |
| ------- | --------------- | ------------------------------------------------------- |
| GET     | `/hosts`        | Παραθέτει τους προσαρμοσμένους hosts                    |
| POST    | `/hosts`        | Προσθέτει host (επεξεργάζεται αυτόματα το `/etc/hosts`) |
| DELETE  | `/hosts/{host}` | Καταργεί τον host                                       |
| PATCH   | `/hosts/{host}` | Εναλλάσσει το `enabled`                                 |

### Λειτουργίες καταγραφής

| Μέθοδος | Διαδρομή                       | Περιγραφή                                                                                                                                    |
| ------- | ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| GET     | `/capture-modes`               | Κατάσταση των λειτουργιών AgentBridge / προσαρμοσμένων hosts / HTTP_PROXY / διακομιστή μεσολάβησης συστήματος + του διακόπτη `tls-intercept` |
| POST    | `/capture-modes/http-proxy`    | Εκκινεί/διακόπτει τον listener HTTP_PROXY (`{action: "start"\|"stop"}`)                                                                      |
| POST    | `/capture-modes/system-proxy`  | Εφαρμόζει/αναιρεί τον διακομιστή μεσολάβησης σε όλο το σύστημα (`{action: "apply"\|"revert"}`)                                               |
| POST    | `/capture-modes/tls-intercept` | Εναλλάσσει την αποκρυπτογράφηση σώματος HTTPS στη λειτουργία διακομιστή μεσολάβησης (`{enabled: boolean}`)                                   |

> Η **αποκρυπτογράφηση TPROXY** (λειτουργία καταγραφής 5) ελέγχεται από μια
> **ξεχωριστή** διαδρομή κάτω από το πρόθεμα AgentBridge — `GET / POST / DELETE /api/tools/agent-bridge/tproxy` — και όχι
> κάτω από το `/api/tools/traffic-inspector/`. Ανατρέξτε στο
> `docs/security/MITM-TPROXY-DECRYPT.md` (git· δεν μεταγλωττίζεται στο `/docs`).

### Συνεδρίες
