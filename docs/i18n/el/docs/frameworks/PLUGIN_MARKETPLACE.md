> **Πηγή αλήθειας:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/` και
> `src/app/(dashboard)/dashboard/plugins/`
> **Τελευταία ενημέρωση:** 2026-06-28 — v3.8.40

Το OmniRoute περιλαμβάνει ένα σύστημα προσθηκών τύπου WordPress. Οι προσθήκες είναι αυτοτελείς
κατάλογοι — καθένας με ένα μανιφέστο `plugin.json` και ένα αρχείο εισόδου — οι οποίοι συνδέονται
στη διοχέτευση αιτημάτων (`onRequest` / `onResponse` / `onError`) και στα
συμβάντα κύκλου ζωής (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`).

Το **Marketplace προσθηκών** είναι το επίπεδο εντοπισμού πάνω από αυτό το σύστημα. Παρέχει
έναν κατάλογο διαθέσιμων προς εγκατάσταση προσθηκών, στον οποίο μπορείτε να περιηγηθείτε. Από προεπιλογή, ο κατάλογος είναι ένα
μικρό ενσωματωμένο αρχικό μητρώο· ένας διαχειριστής μπορεί να τον κατευθύνει σε μια προσαρμοσμένη απομακρυσμένη
URL μητρώου, οπότε η ανάκτηση ενισχύεται με έναν μηχανισμό προστασίας από SSRF που επιλύει DNS
(βλ. [Ασφάλεια](#security)).

Κάθε διαδρομή προσθηκών είναι **μόνο για loopback** (Βαθμίδα 1 — `LOCAL_ONLY`): οι προσθήκες φορτώνουν
και εκτελούν κώδικα σε θυγατρικές διεργασίες, επομένως οι διαδρομές δεν είναι προσβάσιμες από
προέλευση εκτός loopback, ανεξάρτητα από τον έλεγχο ταυτότητας. Βλ.
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md).

## Πώς συνδέονται όλα μεταξύ τους

```
Πίνακας ελέγχου (/dashboard/plugins)
  ├─ Καρτέλα "Εγκατεστημένα" → GET /api/plugins            (listPlugins)
  │                            POST /api/plugins/scan      (pluginManager.scan)
  │                            POST /api/plugins/{name}/activate|deactivate
  │                            DELETE /api/plugins/{name}   (απεγκατάσταση)
  └─ Καρτέλα "Marketplace"    → GET /api/plugins/marketplace
                                 → listMarketplacePlugins()
                                   ├─ χωρίς προσαρμοσμένη URL → ενσωματωμένο SEED_REGISTRY
                                   └─ προσαρμοσμένη URL → προστασία SSRF isSafeMarketplaceUrl()
                                                        → safeOutboundFetch(guard:"public-only")
```

- **Επίπεδο μητρώου** — `src/lib/plugins/marketplace.ts`: παραθέτει / αναζητά στον
  κατάλογο, επιστρέφοντας στο αρχικό μητρώο σε περίπτωση οποιασδήποτε αποτυχίας.
- **Επίπεδο κύκλου ζωής** — `src/lib/plugins/manager.ts` (singleton `pluginManager`):
  εγκατάσταση, αναβάθμιση, ενεργοποίηση, απενεργοποίηση, απεγκατάσταση, σάρωση, φόρτωση κατά την εκκίνηση.
- **Επίπεδο μανιφέστου** — `src/lib/plugins/manifest.ts`: σχήμα Zod + προεπιλεγμένες τιμές για
  το `plugin.json`.
- **Σαρωτής** — `src/lib/plugins/scanner.ts`: εντοπίζει προσθήκες στον δίσκο κάτω από
  τον κατάλογο προσθηκών.
- **Φορτωτής** — `src/lib/plugins/loader.ts`: εκκινεί κάθε προσθήκη σε μια απομονωμένη
  θυγατρική διεργασία και διαμεσολαβεί τις κλήσεις hook μέσω IPC.

## Κατάλογος Marketplace

Η `listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) επιστρέφει μια λίστα από
αντικείμενα `MarketplaceEntry`:

| Πεδίο         | Τύπος    | Σημειώσεις                                       |
| ------------- | -------- | ------------------------------------------------ |
| `name`        | string   | Όνομα προσθήκης σε μορφή kebab-case              |
| `version`     | string   | semver                                           |
| `description` | string   | Σύντομη περίληψη                                 |
| `author`      | string   | Δημιουργός / οργανισμός                          |
| `license`     | string   | Αναγνωριστικό άδειας τύπου SPDX                  |
| `downloadUrl` | string   | URL λήψης πηγής (ενδέχεται να είναι κενή)        |
| `repository`  | string?  | Προαιρετική URL αποθετηρίου                      |
| `tags`        | string[] | Ετικέτες αναζήτησης/φιλτραρίσματος               |
| `downloads`   | number   | Πλήθος λήψεων                                    |
| `rating`      | number   | 0–5                                              |
| `verified`    | boolean  | Αν η καταχώριση έχει επισημανθεί ως επαληθευμένη |
| `lastUpdated` | string   | Συμβολοσειρά ημερομηνίας τύπου ISO               |

Όταν δεν έχει διαμορφωθεί προσαρμοσμένη URL μητρώου, ο κατάλογος είναι το ενσωματωμένο
`SEED_REGISTRY` (επί του παρόντος `request-logger`, `rate-limiter`, `cost-tracker` και
`theme-manager`). Το αρχικό μητρώο είναι πάντα διαθέσιμο — εάν ένα διαμορφωμένο απομακρυσμένο
μητρώο δεν είναι προσβάσιμο, επιστρέψει κατάσταση διαφορετική από `200` ή επιστρέψει μη αναγνωρισμένο
σώμα, η `listMarketplacePlugins()` καταγράφει μια προειδοποίηση και επιστρέφει στην αρχική λίστα.

> Σημείωση: ο **κατάλογος** του marketplace (περιήγηση/αναζήτηση) είναι συνδεδεμένος από άκρο σε άκρο, αλλά
> η **εγκατάσταση** με ένα κλικ από τον κατάλογο του marketplace δεν έχει υλοποιηθεί ακόμη — το
> κουμπί "Εγκατάσταση" του πίνακα ελέγχου σε μια καταχώριση marketplace εμφανίζει προς το παρόν μια
> ειδοποίηση "προσεχώς". Σήμερα, η εγκατάσταση πραγματοποιείται μέσω της ροής εγκατάστασης από τοπική διαδρομή
> (`POST /api/plugins`) και του εντοπισμού στον δίσκο (`POST /api/plugins/scan`).

## REST API

Όλα τα endpoints απαιτούν έλεγχο ταυτότητας διαχείρισης (`requireManagementAuth`) **και** είναι
προσβάσιμα μόνο μέσω loopback — τα `/api/plugins` και `/api/plugins/` περιλαμβάνονται στο
`LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`).

| Endpoint                         | Μέθοδος | Περιγραφή                                                       |
| -------------------------------- | ------- | --------------------------------------------------------------- |
| `/api/plugins`                   | GET     | Εμφάνιση εγκατεστημένων plugins (προαιρετικό φίλτρο `?status=`) |
| `/api/plugins`                   | POST    | Εγκατάσταση plugin από απόλυτη τοπική διαδρομή                  |
| `/api/plugins/scan`              | POST    | Σάρωση του καταλόγου plugins και καταχώριση νέων plugins        |
| `/api/plugins/marketplace`       | GET     | Εμφάνιση καταχωρίσεων του καταλόγου marketplace                 |
| `/api/plugins/[name]`            | GET     | Λήψη λεπτομερειών εγκατεστημένου plugin                         |
| `/api/plugins/[name]`            | DELETE  | Απεγκατάσταση plugin                                            |
| `/api/plugins/[name]/activate`   | POST    | Ενεργοποίηση (φόρτωση + καταχώριση hooks)                       |
| `/api/plugins/[name]/deactivate` | POST    | Απενεργοποίηση (εκτέλεση `onDeactivate`, κατάργηση hooks)       |
| `/api/plugins/[name]/config`     | GET     | Λήψη ρυθμίσεων plugin + σχήματος ρυθμίσεων                      |
| `/api/plugins/[name]/config`     | PUT     | Ενημέρωση ρυθμίσεων plugin (με επικύρωση βάσει του σχήματος)    |

Το φίλτρο `status` του `GET /api/plugins` δέχεται μία από τις τιμές
`installed` / `active` / `inactive` / `error`. Μια μη έγκυρη τιμή επιστρέφει `400`.

### Εμφάνιση εγκατεστημένων plugins

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### Εγκατάσταση από τοπική διαδρομή

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

Το `path` πρέπει να είναι **απόλυτο** και δεν επιτρέπεται να περιέχει τμήματα διάσχισης `..` ή
null bytes (επιβάλλεται από το Zod). Ο κατάλογος προέλευσης πρέπει να περιέχει ένα έγκυρο
`plugin.json` (ή να είναι γονικός κατάλογος ενός τέτοιου αρχείου). Σε περίπτωση επιτυχίας, η απόκριση είναι `201` μαζί με την
εγγραφή του εγκατεστημένου plugin.

### Περιήγηση στο marketplace

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### Ενημέρωση ρυθμίσεων plugin

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

Το `PUT .../config` επικυρώνει κάθε παρεχόμενη τιμή βάσει του
`configSchema` του plugin (που δηλώνεται στο manifest): τα πεδία `number` τηρούν τα `min`/`max`,
ενώ τα πεδία `select` πρέπει να αντιστοιχούν στο δηλωμένο `enum`. Τα κλειδιά που δεν υπάρχουν στο σχήμα
επιτρέπονται χωρίς περαιτέρω έλεγχο.

## Ρύθμιση παραμέτρων

### Κατάλογος plugins

Τα plugins βρίσκονται στον κατάλογο δεδομένων του OmniRoute:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (ή οποιοδήποτε αρχείο υποδεικνύει το manifest.main)
```

Η `getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) επιλύει αυτόν τον κατάλογο σε
τρία βήματα:

1. **`OMNIROUTE_PLUGINS_DIR`**, όταν έχει οριστεί — χρησιμοποιείται αυτούσιο, ανεξάρτητα από την τιμή του `HOME`. Αυτό είναι
   το ρητό στοιχείο ελέγχου για Docker/K8s, όπου το δέντρο των plugins προσαρτάται μέσω bind mount σε μια διαδρομή
   που συνήθως δεν σχετίζεται καθόλου με τον αρχικό κατάλογο του container (#11827).
2. `<home>/.omniroute/plugins`, όπου το `<home>` προέρχεται από τις μεταβλητές περιβάλλοντος `HOME` / `USERPROFILE`.
3. `/tmp/.omniroute/plugins`, όταν η διεργασία δεν εξάγει καθόλου αρχικό κατάλογο.

Ο επιλυμένος κατάλογος καταγράφεται μία φορά κατά την εκκίνηση ως `scanner.dir_resolved`, αναφέροντας την
είσοδο που επικράτησε (`OMNIROUTE_PLUGINS_DIR`, `home` ή `no-home-fallback`) — έτσι, ένα image
που καταλήγει σιωπηρά στο βήμα 3 το αναφέρει, αντί να εμφανίζει απλώς μια κενή λίστα plugins.
Το `POST /api/plugins/scan` εντοπίζει οποιονδήποτε υποκατάλογο εκεί που περιέχει έγκυρο
`plugin.json` και τον καταχωρίζει· ο ίδιος κατάλογος αποτελεί τη ρίζα στην οποία η
`pluginManager.install()` αντιγράφει τα plugins, επομένως μια παράκαμψη μετακινεί μαζί την ανακάλυψη και
την εγκατάσταση.

> **Το `OMNIROUTE_PLUGINS_DIR` δεν είναι το `OMNIROUTE_PLUGIN_PATH`.** Το δεύτερο διαβάζεται μόνο από
> τον φορτωτή command-plugin του CLI (`bin/cli/plugins.mjs`) για την εύρεση npm πακέτων `omniroute-cmd-*`
> που προσθέτουν υποεντολές στο `omniroute` — δεν επηρεάζει τον σαρωτή χρόνου εκτέλεσης
> που περιγράφεται εδώ. Δείτε το [PLUGINS.md](./PLUGINS.md) για αυτήν την πλευρά.

### Προσαρμοσμένο URL μητρώου marketplace

Η προέλευση του καταλόγου marketplace διαβάζεται από τη ρύθμιση `pluginMarketplaceUrl`
(το `src/lib/plugins/marketplace.ts` διαβάζει το `settings.pluginMarketplaceUrl`). Όταν
ορίζεται σε ένα URL `http(s)`, η `listMarketplacePlugins()` ανακτά αυτό το URL και δέχεται
είτε έναν πίνακα JSON ανώτατου επιπέδου με καταχωρίσεις είτε ένα αντικείμενο με πίνακα `plugins`·
οι καταχωρίσεις χωρίς `name` τύπου string φιλτράρονται. Όταν δεν έχει οριστεί (ή όταν η ανάκτηση
αποτυγχάνει λόγω του ελέγχου SSRF / επιστρέφει μη έγκυρη απόκριση), χρησιμοποιείται το ενσωματωμένο αρχικό μητρώο.

Η καρτέλα "Marketplace" του dashboard παρέχει ένα πεδίο για αυτό το URL (το οποίο ανακτάται από το
`GET /api/settings`).

> Σημείωση υλοποίησης: η ενέργεια "Save" του dashboard στέλνει το
> `pluginMarketplaceUrl` στο `PATCH /api/settings`. Κατά τη σύνταξη αυτού του κειμένου, αυτό το
> κλειδί δεν δηλώνεται στο `updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`), επομένως επαληθεύστε τη διατήρησή του στη δική σας
> έκδοση προτού βασιστείτε σε αυτό — η διαδρομή **ανάγνωσης** (`getSettings()` →
> `listMarketplacePlugins()`) λαμβάνει υπόψη το κλειδί μόλις αυτό υπάρχει στον χώρο αποθήκευσης
> ρυθμίσεων.

## Ασφάλεια

### Επίπεδο διαδρομής — μόνο loopback

Τα πρόσθετα εκτελούν κώδικα σε θυγατρικές διεργασίες που δημιουργούνται δυναμικά, επομένως ολόκληρη η επιφάνεια `/api/plugins`
ταξινομείται ως `LOCAL_ONLY` (Επίπεδο 1). Η επιβολή του loopback εκτελείται
άνευ όρων **πριν** από οποιονδήποτε έλεγχο ταυτοποίησης, επομένως ακόμη και ένα διαρρεύσαν διακριτικό διαχείρισης που φτάνει
στο μηχάνημα μέσω tunnel δεν μπορεί να εγκαταστήσει, να ενεργοποιήσει ή να απεγκαταστήσει ένα πρόσθετο.
Δείτε το [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) και
τους Αυστηρούς Κανόνες #15 / #17.

### Προστασία SSRF για το μητρώο marketplace

Ένα προσαρμοσμένο URL μητρώου είναι ρύθμιση που μπορεί να επηρεαστεί από εισβολέα, επομένως πριν
από την ανάκτησή του η `listMarketplacePlugins()` το περνά από δύο επίπεδα:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - Απορρίπτει οτιδήποτε δεν είναι `http:` / `https:`.
   - Απορρίπτει κυριολεκτικές ιδιωτικές/loopback/link-local/ULA διευθύνσεις κεντρικών υπολογιστών (IPv4 **και** IPv6,
     συμπεριλαμβανομένων των αντιστοιχισμένων σε IPv4) μέσω της κανονικής `isPrivateHost`
     (`src/shared/network/outboundUrlGuard.ts`).
   - Επιλύει **και** τις εγγραφές `A` και `AAAA` και απορρίπτει εάν **οποιαδήποτε** επιλυμένη
     διεύθυνση είναι ιδιωτική — κλείνοντας την παράκαμψη δημόσιο όνομα κεντρικού υπολογιστή → ιδιωτική IP.
   - **Αποτυγχάνει με ασφαλή τρόπο**: μια αποτυχία επίλυσης DNS απορρίπτει το URL.
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`**
   (`src/shared/network/safeOutboundFetch.ts`): εφαρμόζει ξανά την προστασία URL μόνο για δημόσιες διευθύνσεις
   κατά την ανάκτηση και **αποκλείει τις ανακατευθύνσεις** (χωρίς μετάβαση δημόσια → ιδιωτική μέσω `30x`).

Ένα URL που αποτυγχάνει σε οποιοδήποτε επίπεδο δεν ματαιώνει το αίτημα — το marketplace
επιστρέφει σιωπηρά στο ενσωματωμένο αρχικό μητρώο και καταγράφει μια προειδοποίηση.

> Αυτή η προστασία ενισχύθηκε στο PR #3774 ειδικά για την επίλυση A + AAAA και τη χρήση
> της κανονικής `isPrivateHost` αντί για έναν έλεγχο αποκλειστικά για IPv4.

### Απομόνωση εκτέλεσης προσθέτων

- **Απομόνωση διεργασιών** — η `loadPlugin()` (`src/lib/plugins/loader.ts`) δημιουργεί
  κάθε πρόσθετο σε ξεχωριστή θυγατρική διεργασία Node.js και επικοινωνεί μέσω IPC.
  Οι κλήσεις hook έχουν χρονικό όριο με κλιμάκωση `SIGTERM` → `SIGKILL`.
- **Λίστα επιτρεπόμενων μεταβλητών περιβάλλοντος** — η θυγατρική διεργασία λαμβάνει μόνο ένα επιτρεπόμενο σύνολο μεταβλητών
  περιβάλλοντος· το ευρύτερο σύνολο παραχωρείται μόνο όταν το manifest ζητά την
  άδεια `env`.
- **Περιορισμός διαδρομών** — η εγκατάσταση/αναβάθμιση/απεγκατάσταση επιβεβαιώνει ότι ο κατάλογος
  του πρόσθετου και το `manifest.main` επιλύονται **εντός** της διαχειριζόμενης ρίζας προσθέτων
  πριν από οποιαδήποτε αντιγραφή ή αναδρομική διαγραφή (προστατεύει από αλλοιωμένες διαδρομές βάσης δεδομένων και
  διάσχιση `../` στο `manifest.main`). Η ενεργοποίηση επιλύει συμβολικούς συνδέσμους μέσω
  `realpath` και αρνείται να φορτώσει ένα σημείο εισόδου που διαφεύγει από τον κατάλογο
  του πρόσθετου.
- **Προαιρετική καθήλωση ακεραιότητας** — ένα manifest μπορεί να δηλώνει ένα πεδίο `integrity`
  (`sha256-<base64>`, μορφή SRI). Όταν υπάρχει, ο φορτωτής επαληθεύει το hash του
  αρχείου εισόδου κατά τη φόρτωση και αρνείται την ενεργοποίηση σε περίπτωση ασυμφωνίας. Πρόκειται
  για προαιρετικό εντοπισμό αλλοίωσης, **όχι** για όριο ασφαλείας — η δρομολόγηση μόνο μέσω loopback
  και το μοντέλο αδειών αποτελούν τα πραγματικά όρια.

## Manifest (`plugin.json`)

Επικυρώνεται από το `PluginManifestSchema` (`src/lib/plugins/manifest.ts`):

| Πεδίο              | Τύπος     | Σημειώσεις                                                           |
| ------------------ | --------- | -------------------------------------------------------------------- |
| `name`             | string    | Απαιτείται· kebab-case (`^[a-z0-9-]+$`), 1–100 χαρακτήρες            |
| `version`          | string    | Απαιτείται· semver (`MAJOR.MINOR.PATCH`)                             |
| `description`      | string?   | ≤ 500 χαρακτήρες                                                     |
| `author`           | string?   | ≤ 200 χαρακτήρες                                                     |
| `license`          | string?   | Προεπιλεγμένη τιμή `MIT`                                             |
| `main`             | string?   | Αρχείο εισόδου· προεπιλεγμένη τιμή `index.js`                        |
| `source`           | enum?     | `local` \| `marketplace` (προεπιλεγμένη τιμή `local`)                |
| `tags`             | string[]? | Ετικέτες αναζήτησης                                                  |
| `requires`         | object?   | `{ omniroute?, permissions[] }`                                      |
| `hooks`            | object?   | Λογικές τιμές που δηλώνουν ποια hook υλοποιεί το πρόσθετο            |
| `skills`           | object[]? | Προαιρετικοί ορισμοί δεξιοτήτων                                      |
| `enabledByDefault` | boolean?  | Αυτόματη ενεργοποίηση κατά την εγκατάσταση                           |
| `configSchema`     | object?   | Αντιστοίχιση πεδίων ρυθμίσεων (`string`/`number`/`boolean`/`select`) |
| `integrity`        | string?   | Προαιρετική καθήλωση αρχείου εισόδου `sha256-<base64>`               |

Οι άδειες προέρχονται από την απαρίθμηση
`network` / `file-read` / `file-write` / `env` / `exec`.

## Ροή κύκλου ζωής

```
εγκατάσταση (POST /api/plugins, διαδρομή)
  → σάρωση/επικύρωση manifest → αντιγραφή σε staging → επιβεβαίωση ότι το main βρίσκεται εντός του καταλόγου
  → ατομική μετονομασία σε ~/.omniroute/plugins/<name> → εισαγωγή εγγραφής στη βάση δεδομένων
  → ενεργοποίηση του onInstall → αν enabledByDefault: ενεργοποίηση

ενεργοποίηση (POST /api/plugins/{name}/activate)
  → έλεγχος περιορισμού realpath → loadPlugin() (εκκίνηση θυγατρικής διεργασίας)
  → καταχώριση δηλωμένων hooks → status = "active" → ενεργοποίηση του onActivate

απενεργοποίηση (POST /api/plugins/{name}/deactivate)
  → ενεργοποίηση του onDeactivate (ΠΡΙΝ από την κατάργηση καταχώρισης) → κατάργηση καταχώρισης των hooks
  → τερματισμός θυγατρικής διεργασίας → status = "inactive"

απεγκατάσταση (DELETE /api/plugins/{name})
  → απενεργοποίηση αν είναι ενεργό → ενεργοποίηση του onUninstall
  → αναδρομική διαγραφή του καταλόγου του plugin με έλεγχο περιορισμού → διαγραφή εγγραφής από τη βάση δεδομένων
```

Η εκ νέου εκτέλεση του `install` σε έναν κατάλογο του οποίου η έκδοση manifest είναι **αυστηρά
νεότερη** από την εγκατεστημένη έκδοση πραγματοποιεί αυτόματη αναβάθμιση (καθαρή επανεγκατάσταση· η διαμόρφωση επαναφέρεται
στις προεπιλογές). Μια ίδια ή παλαιότερη έκδοση απορρίπτεται.

## Πίνακας ελέγχου

Η σελίδα του πίνακα ελέγχου στη διεύθυνση `/dashboard/plugins`
(`src/app/(dashboard)/dashboard/plugins/page.tsx`) παρέχει δύο καρτέλες:

- **Εγκατεστημένα** — παραθέτει τα εγκατεστημένα plugin με τα δηλωμένα hooks τους, έναν
  διακόπτη ενεργοποίησης/απενεργοποίησης, ένα κουμπί απεγκατάστασης και μια ενέργεια "Σάρωση για plugin"
  (`POST /api/plugins/scan`).
- **Marketplace** — εμφανίζει τον κατάλογο από το `GET /api/plugins/marketplace` με ένα
  πεδίο για τον ορισμό της προσαρμοσμένης διεύθυνσης URL μητρώου.

Η σελίδα διαμόρφωσης ανά plugin βρίσκεται στη διεύθυνση `/dashboard/plugins/[name]/config`
(`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`).
