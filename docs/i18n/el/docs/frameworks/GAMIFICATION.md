> **Πηγή αλήθειας:** `src/lib/gamification/`, `src/lib/db/gamification.ts`, `src/app/api/gamification/`
> **Τελευταία ενημέρωση:** 2026-06-28 — v3.8.40

Το OmniRoute περιλαμβάνει ένα επίπεδο παιχνιδοποίησης με προτεραιότητα στην τοπική λειτουργία, το οποίο ανταμείβει τους χρήστες για την
αλληλεπίδρασή τους με την πλατφόρμα — υποβολή αιτημάτων, εναλλαγή παρόχων, δημιουργία
συνδυασμών, διαμοιρασμό token και συνεισφορά στην κοινότητα. Όλη η κατάσταση αποθηκεύεται στο
SQLite· η ομοσπονδιακή διασύνδεση με διακομιστές κοινότητας είναι προαιρετική και βασίζεται σε προώθηση δεδομένων.

Το σύστημα έχει σχεδιαστεί ώστε να παρέχει **μηδενική καθυστέρηση στην κρίσιμη διαδρομή** — τα συμβάντα παιχνιδοποίησης
αποστέλλονται χωρίς αναμονή από τη διοχέτευση αιτημάτων και δεν αποκλείουν ποτέ
μια απόκριση LLM.

## Επισκόπηση

### Σκοπός

Αύξηση της αλληλεπίδρασης και της διατήρησης των χρηστών μέσω ορατής προόδου (XP,
επίπεδα, σήματα), κοινωνικής επιβεβαίωσης (πίνακες κατάταξης) και οικονομικών κινήτρων (διαμοιρασμός
token, ανταμοιβές προσκλήσεων).

### Πεδίο εφαρμογής

| Λειτουργία              | Περιγραφή                                                                                        |
| ----------------------- | ------------------------------------------------------------------------------------------------ |
| XP & Επίπεδα            | Απόκτηση XP ανά ενέργεια· άνοδος επιπέδου βάσει πολυωνυμικής καμπύλης                            |
| Σήματα                  | 20+ επιτεύγματα σε 5 κατηγορίες με 4 βαθμίδες σπανιότητας                                        |
| Σερί                    | Παρακολούθηση καθημερινής ενεργής χρήσης με τρέχον/μεγαλύτερο σερί                               |
| Πίνακες κατάταξης       | Καθολική, εβδομαδιαία, μηνιαία κατάταξη, καθώς και κατατάξεις διαμοιρασμού token και συνεισφοράς |
| Διαμοιρασμός token      | Μεταφορά πιστώσεων μεταξύ χρηστών μέσω καθολικού διπλογραφικής λογιστικής                        |
| Πρόσκληση & Εξαργύρωση  | Κωδικοί παραπομπής με αποθήκευση κατακερματισμένη μέσω SHA-256                                   |
| Διακομιστές κοινότητας  | Ομοσπονδιακή διασύνδεση με εξωτερικά στιγμιότυπα OmniRoute                                       |
| Προστασία από εξαπάτηση | Βαθμολόγηση στην πλευρά του διακομιστή, περιορισμός ρυθμού και ανίχνευση ανωμαλιών μέσω z-score  |

### Αρχές σχεδιασμού

1. **Προτεραιότητα στην τοπική λειτουργία** — όλη η κατάσταση αποθηκεύεται στο SQLite, χωρίς να απαιτούνται εξωτερικές υπηρεσίες.
2. **Χωρίς αποκλεισμό** — τα συμβάντα αποστέλλονται χωρίς αναμονή· η διαδρομή απόκρισης του LLM
   δεν καθυστερεί ποτέ από τη λογική παιχνιδοποίησης.
3. **Ο διακομιστής αποτελεί την αυθεντική πηγή** — το XP υπολογίζεται μόνο στην πλευρά του διακομιστή· οι πελάτες δεν μπορούν
   να διογκώσουν τις βαθμολογίες.
4. **Σεβασμός του απορρήτου** — η συμμετοχή στους πίνακες κατάταξης είναι προαιρετική· οι χρήστες μπορούν
   να αποκρύψουν το προφίλ τους.
5. **Έτοιμο για ομοσπονδιακή διασύνδεση** — οι διακομιστές κοινότητας μπορούν να προωθούν βαθμολογίες μέσω υπογεγραμμένου API·
   ο συγχρονισμός γίνεται με αντικατάσταση και όχι αθροιστικά.

## Αρχιτεκτονική

### Ροή υψηλού επιπέδου

```
Αίτημα πελάτη
  → /v1/chat/completions
    → handleChatCore()                      [open-sse/handlers/chatCore.ts]
      → ... (υφιστάμενη διοχέτευση) ...
      → η απόκριση upstream αποστέλλεται στον πελάτη
      → setImmediate (χωρίς αναμονή):
        → emitGamificationEvent()           [src/lib/gamification/events.ts]
          → awardXp()                       [src/lib/gamification/xp.ts]
          → updateStreak()                  [src/lib/gamification/streaks.ts]
          → evaluateBadges()                [src/lib/gamification/badges.ts]
          → updateLeaderboard()             [src/lib/gamification/leaderboard.ts]
          → checkAnomalies()                [src/lib/gamification/antiCheat.ts]
```

Ο πομπός συμβάντων είναι το μοναδικό σημείο ενσωμάτωσης. Το `chatCore.ts` καλεί τη
`emitGamificationEvent()` μετά την αποστολή της απόκρισης· η μονάδα συμβάντων διανέμει
την επεξεργασία στα υποσυστήματα XP, σερί, σημάτων, πίνακα κατάταξης και προστασίας από εξαπάτηση.

### Γράφημα εξαρτήσεων μονάδων


## Σύστημα XP / Επιπέδων

**Αρχείο:** `src/lib/gamification/xp.ts`

### Καμπύλη Επιπέδων

Τα XP που απαιτούνται για την επίτευξη του επιπέδου `n` ακολουθούν μια πολυωνυμική καμπύλη:

```
xp_for_level(n) = floor(100 * n^1.5)
```

| Επίπεδο | XP για το Επόμενο | Συνολικά XP | Τίτλος      |
| ------- | ----------------- | ----------- | ----------- |
| 1       | 100               | 100         | Αρχάριος    |
| 5       | 1,118             | 2,415       | Αρχάριος    |
| 10      | 3,162             | 10,523      | Εξερευνητής |
| 25      | 12,500            | 86,024      | Εξερευνητής |
| 50      | 35,355            | 345,529     | Ειδικός     |
| 75      | 64,952            | 948,683     | Δάσκαλος    |
| 100     | 100,000           | 2,050,000   | Θρύλος      |

### Τίτλοι

| Εύρος Επιπέδων | Τίτλος      |
| -------------- | ----------- |
| 1 – 9          | Αρχάριος    |
| 10 – 24        | Εξερευνητής |
| 25 – 49        | Ειδικός     |
| 50 – 74        | Δάσκαλος    |
| 75 – 100       | Θρύλος      |

### Ανταμοιβές XP

| Ενέργεια          | XP  | Περιγραφή                                                         |
| ----------------- | --- | ----------------------------------------------------------------- |
| `request`         | 1   | Ανά αίτημα API που δρομολογείται μέσω του OmniRoute               |
| `provider_switch` | 5   | Εναλλαγή σε διαφορετικό πάροχο                                    |
| `model_switch`    | 3   | Εναλλαγή σε διαφορετικό μοντέλο                                   |
| `combo_create`    | 10  | Δημιουργία νέου συνδυασμού                                        |
| `combo_use`       | 2   | Χρήση συνδυασμού για ένα αίτημα                                   |
| `token_share`     | 1   | Ανά 1 000 tokens που κοινοποιούνται σε άλλον χρήστη               |
| `invite_redeem`   | 50  | Εξαργύρωση κωδικού πρόσκλησης                                     |
| `daily_login`     | 5   | Καθημερινή ενεργή χρήση (μία φορά την ημέρα)                      |
| `streak_bonus`    | 2   | Ανά συνεχόμενη ημέρα σερί (πολλαπλασιάζεται με το μήκος του σερί) |
| `badge_unlock`    | 10  | Ξεκλείδωμα σήματος                                                |

### Ροή Απονομής

```typescript
export async function awardXp(
  apiKeyId: string,
  action: XpAction,
  metadata?: Record<string, unknown>
): Promise<{ xp: number; level: number; title: string; levelUp: boolean }>;
```

1. Αναζητήστε το `XP_REWARDS[action]` για να λάβετε το ποσό XP.
2. Περάστε από το `checkRateLimit()` (προστασία κατά της εξαπάτησης: έως 1000 XP/λεπτό ανά κλειδί).
3. Ανοίξτε μια συναλλαγή:
   - Διαβάστε την τρέχουσα γραμμή `user_levels`.
   - Προσθέστε XP και υπολογίστε εκ νέου το επίπεδο μέσω του `levelFromXp(totalXp)`.
   - Αν το επίπεδο άλλαξε, ορίστε `levelUp = true`.
   - Ενημερώστε τη γραμμή `user_levels`.
   - Εισαγάγετε μια εγγραφή στο `xp_audit_log`.
4. Επιστρέψτε το αποτέλεσμα. Ο καλών χειρίζεται τις ειδοποιήσεις.

### Βοηθητική Συνάρτηση: `levelFromXp(totalXp)`

Επαναλαμβάνει τα επίπεδα 1..100, αθροίζοντας το `xp_for_level(n)` έως ότου τα συνολικά XP
υπερβούν το `totalXp`. Επιστρέφει το υψηλότερο επίπεδο του οποίου το όριο έχει επιτευχθεί.
Αυτό είναι O(100) — αποδεκτό, καθώς τα επίπεδα περιορίζονται στα 100.

## Παρακολούθηση Σερί

**Αρχείο:** `src/lib/gamification/streaks.ts`

### Μοντέλο Δεδομένων

Τα σερί αποθηκεύονται στον πίνακα `key_value` (κοινόχρηστος βοηθητικός πίνακας) με
κλειδιά που χρησιμοποιούν χώρους ονομάτων:

| Κλειδί                        | Τιμή                             | Περιγραφή             |
| ----------------------------- | -------------------------------- | --------------------- |
| `gamification:streak:{keyId}` | `{current},{longest},{lastDate}` | Δεδομένα ενεργού σερί |

### Λογική

```typescript
export async function updateStreak(
  apiKeyId: string
): Promise<{ current: number; longest: number; milestone: boolean }>;
```

1. Ανάγνωση της εγγραφής σερί από το `key_value`.
2. Ανάλυση των `{current}`, `{longest}`, `{lastDate}` (συμβολοσειρά ημερομηνίας ISO).
3. Εάν `lastDate === today` — καμία αλλαγή (έχει ήδη καταμετρηθεί σήμερα).
4. Εάν `lastDate === yesterday` — αύξηση του `current`· ενημέρωση του `longest`, εάν χρειάζεται.
5. Εάν `lastDate < yesterday` — επαναφορά του `current = 1` (το σερί διακόπηκε).
6. Εγγραφή της ενημερωμένης καταχώρισης.
7. Έλεγχος ορόσημων: 7, 14, 30, 60, 90, 180, 365 ημέρες. Εάν επιτευχθεί κάποιο,
   ορισμός του `milestone = true` (ο καλών κώδικας απονέμει XP και ελέγχει τα σήματα).

### Οριακές Περιπτώσεις

- **Ζώνη ώρας**: τα σερί χρησιμοποιούν ημερομηνίες UTC (`new Date().toISOString().slice(0, 10)`).
  Αυτό είναι σκόπιμο — μία ενιαία κανονική ζώνη ώρας αποτρέπει την εκμετάλλευση
  μέσω εναλλαγής ζωνών ώρας.
- **Νέοι χρήστες**: δεν υπάρχει εγγραφή σερί· το πρώτο αίτημα τη δημιουργεί με
  `current=1, longest=1, lastDate=today`.
- **Πολλαπλά αιτήματα ανά ημέρα**: μόνο το πρώτο αίτημα της ημέρας UTC
  αυξάνει το σερί.

### Υπολογισμός Κατάταξης

Οι θέσεις κατάταξης **υπολογίζονται κατά την ανάγνωση** και δεν αποθηκεύονται. Αυτό αποτρέπει την ύπαρξη παρωχημένων δεδομένων κατάταξης
και εξαλείφει την ανάγκη για περιοδικές εργασίες επανυπολογισμού της κατάταξης.

```typescript
export async function getLeaderboard(
  scope: LeaderboardScope,
  period: string,
  limit: number,
  offset: number
): Promise<{ entries: LeaderboardEntry[]; total: number }>;
```

Μοτίβο ερωτήματος:

```sql
SELECT api_key_id, score,
       RANK() OVER (ORDER BY score DESC) as rank
FROM leaderboard
WHERE scope = ? AND period = ?
ORDER BY score DESC
LIMIT ? OFFSET ?
```

### Εναλλαγή Περιόδου

Οι εβδομαδιαίοι και μηνιαίοι πίνακες κατάταξης εναλλάσσονται αυτόματα:

1. **Αρχειοθέτηση**: στο όριο της περιόδου, αντιγραφή των τρεχουσών εγγραφών στο
   `leaderboard_archive` με την ετικέτα της περιόδου.
2. **Επαναφορά**: διαγραφή των εγγραφών για την περίοδο που έληξε.
3. **Ενεργοποίηση**: πραγματοποιείται έλεγχος σε κάθε κλήση της `updateLeaderboard()`· το πρώτο αίτημα
   μιας νέας περιόδου ενεργοποιεί την εναλλαγή.

Αυτό διασφαλίζει ότι οι εβδομαδιαίοι πίνακες επαναφέρονται κάθε Δευτέρα στις 00:00 UTC και οι μηνιαίοι πίνακες
επαναφέρονται την 1η ημέρα κάθε μήνα.

### Ενημερώσεις Πραγματικού Χρόνου μέσω SSE

**Τελικό σημείο:** `GET /api/gamification/stream`

```
Πελάτης → GET /api/gamification/stream
  → Δημιουργείται σύνδεση SSE
  → Ο διακομιστής στέλνει αμέσως στιγμιότυπο των 10 κορυφαίων του πίνακα κατάταξης
```


Ο διαχειριστής SSE παρακολουθεί τους συνδεδεμένους πελάτες ανά εμβέλεια και στέλνει ενημερώσεις μόνο
όταν τα δεδομένα του πίνακα κατάταξης έχουν πράγματι αλλάξει από την τελευταία αποστολή.

## Κοινή Χρήση Token

**Αρχείο:** `src/lib/gamification/sharing.ts`

### Καθολικό Διπλής Εγγραφής

Κάθε μεταφορά δημιουργεί δύο γραμμές στο `token_ledger`:

| Γραμμή  | `from_key_id` | `to_key_id` | `amount` |
| ------- | ------------- | ----------- | -------- |
| Χρέωση  | αποστολέας    | παραλήπτης  | +amount  |
| Πίστωση | παραλήπτης    | αποστολέας  | -amount  |

Προσοχή — η σύμβαση είναι:

| Γραμμή   | `from_key_id` | `to_key_id` | `amount` | Σημασία                 |
| -------- | ------------- | ----------- | -------- | ----------------------- |
| Αποστολή | αποστολέας    | παραλήπτης  | +amount  | Εκροή από τον αποστολέα |
| Λήψη     | παραλήπτης    | αποστολέας  | +amount  | Εισροή στον παραλήπτη   |

Το υπόλοιπο υπολογίζεται ως εξής:

```sql
SELECT
  COALESCE(SUM(CASE WHEN to_key_id = ? THEN amount ELSE 0 END), 0)
  - COALESCE(SUM(CASE WHEN from_key_id = ? THEN amount ELSE 0 END), 0)
  AS balance
FROM token_ledger
WHERE from_key_id = ? OR to_key_id = ?
```

### Ροή Μεταφοράς

```typescript
export async function transferTokens(
  fromKeyId: string,
  toKeyId: string,
  amount: number,
  idempotencyKey: string
): Promise<{ success: boolean; balance: number }>;
```

1. **Επικύρωση**: `amount > 0`, `fromKeyId !== toKeyId`.
2. **Ιδιοδυναμία**: ελέγξτε εάν το `idempotency_key` υπάρχει ήδη στο καθολικό.
   Εάν ναι, επιστρέψτε το αποθηκευμένο αποτέλεσμα.
3. **Συναλλαγή** (μία ενιαία συναλλαγή SQLite):
   a. Υπολογίστε το υπόλοιπο του αποστολέα.
   b. Εάν `balance < amount`, ακυρώστε τη διαδικασία (ανεπαρκές υπόλοιπο).
   c. Εισαγάγετε τη γραμμή αποστολής (`from=sender,`.

### Περιορισμός Ρυθμού

- Έως 10 μεταφορές ανά λεπτό και ανά κλειδί API.
- Έως 10.000 token ανά μεμονωμένη μεταφορά.
- Έως 100.000 token που μεταφέρονται ανά ημέρα και ανά κλειδί API.

## Token Πρόσκλησης & Εξαργύρωσης

**Αρχείο:** `src/lib/gamification/invites.ts`

### Μορφή Κωδικού

- **Κωδικός**: αλφαριθμητικός 8 χαρακτήρων (π.χ. `A3K9-X7M2`), ευανάγνωστος,
  εμφανίζεται στον χρήστη.
- **Token**: τυχαίο token 32 byte, αποθηκευμένο ως hash SHA-256. Χρησιμοποιείται για
  προγραμματιστική εξαργύρωση (π.χ. σύνδεσμοι URL).

### Αποθήκευση

| Στήλη        | Τιμή                                |
| ------------ | ----------------------------------- |
| `code`       | `A3K9X7M2` (μοναδικό, με ευρετήριο) |
| `token_hash` | SHA-256(raw_token)                  |

Το ανεπεξέργαστο token επιστρέφεται στον χρήστη ακριβώς μία φορά κατά τη δημιουργία. Το OmniRoute
δεν το αποθηκεύει ούτε το εμφανίζει ξανά — διατηρείται μόνο το hash.

### Αποτροπή Αυτοπαραπομπής

Όταν ένας χρήστης εξαργυρώνει έναν κωδικό, το σύστημα ελέγχει ότι:

1. Ο κωδικός ανήκει σε διαφορετικό `api_key_id`.
2. Ο χρήστης που πραγματοποιεί την εξαργύρωση δεν έχει εξαργυρώσει προηγουμένως κανέναν κωδικό από τον ίδιο
   παραπέμποντα (συνένωση στα `invite_tokens` + αρχείο καταγραφής εξαργυρώσεων).

Εάν αποτύχει οποιοσδήποτε από τους δύο ελέγχους, η εξαργύρωση απορρίπτεται με σαφές μήνυμα σφάλματος.

### Λήξη & Όρια

- Προεπιλεγμένο `max_uses`: 10 (δυνατότητα διαμόρφωσης κατά τη δημιουργία).
- Προεπιλεγμένο `expires_at`: 30 ημέρες από τη δημιουργία.
- Οι κωδικοί που έχουν λήξει ή εξαντληθεί επιστρέφουν HTTP 410 Gone.

## Ομοσπονδία Διακομιστών Κοινότητας

**Αρχείο:** `src/lib/gamification/servers.ts`

### Σύνδεση

Ένας διακομιστής κοινότητας καταχωρίζεται μέσω ενός διακριτικού πρόσκλησης που εκδίδεται από τον απομακρυσμένο
διακομιστή. Η τοπική παρουσία:

1. Λαμβάνει το διακριτικό πρόσκλησης (π.χ. μέσω επικόλλησης στον πίνακα ελέγχου).
2. Καλεί το `POST /api/gamification/federation/leaderboard` στον απομακρυσμένο διακομιστή
   για να επικυρώσει το διακριτικό και να ανακτήσει τον τρέχοντα πίνακα κατάταξης.
3. Αποθηκεύει την εγγραφή του διακομιστή με `status: connected`.

### Μοντέλο Συγχρονισμού

Η ομοσπονδία χρησιμοποιεί **συγχρονισμό με αντικατάσταση**, όχι προσθετικό:

```
Τοπική Παρουσία               Διακομιστής Κοινότητας
     │                              │
     ├── αποστολή σκορ ────────────►│  POST /federation/score
     │   { api_key_id, score }      │  (ο διακομιστής επικυρώνει το hash του διακριτικού)
     │                              │
     ├── λήψη πίνακα κατάταξης ────►│  GET /federation/leaderboard
     │◄── κορυφαίες N εγγραφές ─────┤  (αντικαθιστούν την τοπική κρυφή μνήμη)
     │                              │
     └── έλεγχος υγείας ───────────►│  GET /federation/health
         (κάθε 60s, χρονικό όριο 5s)│
```

### Έλεγχος Ταυτότητας

Τα αιτήματα ομοσπονδίας περιλαμβάνουν:

```
Authorization: Bearer <raw_token>
X-Federation-Version: 1
```

Ο απομακρυσμένος διακομιστής κατακερματίζει το διακριτικό και αναζητά την αντίστοιχη
γραμμή `community_servers`. Έτσι αποφεύγεται η μετάδοση του αποθηκευμένου hash.

### Παρακολούθηση Υγείας

Κάθε εγγραφή διακομιστή παρακολουθεί:

| Πεδίο       | Περιγραφή                                                 |
| ----------- | --------------------------------------------------------- |
| `status`    | `connected`, `degraded`, `unreachable`                    |
| `last_sync` | Χρονική σήμανση ISO του τελευταίου επιτυχούς συγχρονισμού |
| `failures`  | Διαδοχικές αποτυχίες ελέγχου υγείας                       |

Μετά από 5 διαδοχικές αποτυχίες, η κατάσταση αλλάζει σε `unreachable` και ο συγχρονισμός
παύει έως ότου επιτύχει ένας χειροκίνητος έλεγχος υγείας.

## Προστασία από Εξαπάτηση

**Αρχείο:** `src/lib/gamification/antiCheat.ts`

### Υπολογισμός Βαθμολογίας στην Πλευρά του Διακομιστή

Όλοι οι υπολογισμοί XP πραγματοποιούνται στο `src/lib/gamification/xp.ts`. Οι πελάτες δεν
υποβάλλουν ποτέ βαθμολογία — υποβάλλουν ενέργειες και ο διακομιστής υπολογίζει τα XP. Η
στήλη `leaderboard.score` μπορεί να εγγραφεί μόνο από κώδικα στην πλευρά του διακομιστή.

### Περιορισμός Ρυθμού

| Όριο                         | Τιμή    | Εμβέλεια       |
| ---------------------------- | ------- | -------------- |
| Μέγιστα XP ανά λεπτό         | 1,000   | Ανά κλειδί API |
| Μέγιστες μεταφορές ανά λεπτό | 10      | Ανά κλειδί API |
| Μέγιστο ποσό μεταφοράς       | 10,000  | Ανά μεταφορά   |
| Μέγιστες ημερήσιες μεταφορές | 100,000 | Ανά κλειδί API |

Τα όρια ρυθμού χρησιμοποιούν ένα κυλιόμενο παράθυρο στη μνήμη (ίδιο μοτίβο με το
`RateLimitManager` στο `open-sse/services/`). Σε περίπτωση επανεκκίνησης της διεργασίας,
χρησιμοποιούνται εναλλακτικά μετρητές που υποστηρίζονται από SQLite.

### Ανίχνευση Ανωμαλιών με Z-Score

Για κάθε κλειδί API, το σύστημα διατηρεί ένα κυλιόμενο παράθυρο 7 ημερών με τα XP που αποκτήθηκαν ανά
ώρα. Σε κάθε απονομή XP:

1. Υπολογίζει τον τρέχοντα ωριαίο ρυθμό XP του χρήστη.
2. Υπολογίζει τον μέσο όρο και την τυπική απόκλιση του πληθυσμού.
3. Υπολογίζει `z = (user_rate - mean) / stddev`.
4. Εάν `z > 3.0` (3 τυπικές αποκλίσεις), επισημαίνει το συμβάν ως ανωμαλία.

Οι ανωμαλίες καταγράφονται στο `xp_audit_log` με `action = 'anomaly_detected'`
και εμφανίζονται στον πίνακα ελέγχου διαχειριστή.

### Ίχνος Ελέγχου

Κάθε απονομή XP, μεταφορά, απόκτηση διακριτικού επιτεύγματος και ανίχνευση ανωμαλίας καταγράφεται στο
`xp_audit_log` με:

| Πεδίο        | Περιγραφή                                               |
| ------------ | ------------------------------------------------------- |
| `api_key_id` | Ποιος                                                   |
| `action`     | Τι συνέβη (xp_award, transfer, anomaly, …)              |
| `xp_awarded` | Ποσό (0 για συμβάντα που δεν αφορούν XP)                |
| `metadata`   | JSON με το σχετικό πλαίσιο (τύπος ενέργειας, στόχος, …) |
| `created_at` | Πότε (ISO 8601)                                         |

Οι διαχειριστές μπορούν να υποβάλουν ερωτήματα στο πλήρες ίχνος ελέγχου μέσω του `GET /api/gamification/anomalies`.

## Σελίδες Πίνακα Ελέγχου

### `/dashboard/leaderboard`

- Προβολή βάθρου (οι 3 πρώτοι με avatar και XP).
- Επιλογέας εύρους: Παγκόσμια / Εβδομαδιαία / Μηνιαία / Κοινοποιημένα Token / Συνεισφορές.

- Ο τρέχων χρήστης επισημαίνεται στον πίνακα με μια σταθερή γραμμή "Η κατάταξή σας".

### `/dashboard/profile`

- Γραμμή προόδου XP με το τρέχον επίπεδο και το όριο του επόμενου επιπέδου.
- Το σήμα τίτλου εμφανίζεται σε περίοπτη θέση.
- Συλλογή σημάτων — τα κερδισμένα σήματα με την ημερομηνία απόκτησης, ενώ τα μη κερδισμένα σήματα εμφανίζονται με γκρι χρώμα
  (τα κρυφά σήματα εμφανίζουν "???" μέχρι να κερδηθούν).
- Μετρητής σερί με εικονίδιο φλόγας· ημερολόγιο σερί (τελευταίες 30 ημέρες).
- Γράφημα ιστορικού XP (ημερήσιο XP για τις τελευταίες 30 ημέρες).

### `/dashboard/tokens`

- Υπόλοιπο token (σε περίοπτη θέση, στο επάνω μέρος της σελίδας).
- Φόρμα μεταφοράς: παραλήπτης, ποσό, παράθυρο διαλόγου επιβεβαίωσης.
- Πίνακας ιστορικού μεταφορών με φίλτρα (απεσταλμένα/ληφθέντα/όλα).
- Ενότητα προσκλήσεων: ενεργοί κωδικοί, δημιουργία νέου, σύνδεσμος κοινοποίησης.
- Διακομιστές κοινότητας: λίστα με κατάσταση εύρυθμης λειτουργίας, σύνδεση/αποσύνδεση.

### `/dashboard/gamification/admin`

- Λίστα ανωμαλιών με σοβαρότητα, χρήστη, χρονική σήμανση και βαθμολογία z.
- Προβολή αρχείου καταγραφής ελέγχου με φίλτρα (τύπος ενέργειας, χρήστης, εύρος ημερομηνιών).
- Στατιστικά συστήματος: συνολικά XP που απονεμήθηκαν, ενεργοί χρήστες, ποσοστά απόκτησης σημάτων.
- Επισκόπηση εύρυθμης λειτουργίας διακομιστών ομοσπονδίας.

## Ενσωμάτωση στη Διοχέτευση

### Σημείο Ενσωμάτωσης

Η παιχνιδοποίηση συνδέεται στη διοχέτευση αιτημάτων σε ένα μόνο σημείο στο
`open-sse/handlers/chatCore.ts`:

```typescript
// Αφού αποσταλεί η απόκριση στον πελάτη:
setImmediate(() => {
  emitGamificationEvent({
    type: "request.completed",
    apiKeyId,
    metadata: {
      provider: selectedProvider,
      model: selectedModel,
      comboId: resolvedCombo?.id,
      compressionUsed: compressionStats?.applied,
      skillUsed: skillExecution?.name,
    },
  }).catch(() => {
    // Εκτέλεση χωρίς αναμονή: καταγραφή, αλλά ποτέ διάδοση στον πελάτη
  });
});
```

### Τύποι Συμβάντων

| Τύπος Συμβάντος     | Πότε Εκπέμπεται                                            |
| ------------------- | ---------------------------------------------------------- |
| `request.completed` | Απεστάλη επιτυχής απόκριση LLM                             |
| `provider.switch`   | Άλλαξε ο πάροχος (προσμετράται η εφεδρεία combo)           |
| `combo.created`     | Αποθηκεύτηκε νέα διαμόρφωση combo                          |
| `combo.used`        | Ο στόχος combo επιτεύχθηκε επιτυχώς                        |
| `badge.earned`      | Η αξιολόγηση σήματος εντόπισε αντιστοίχιση                 |
| `streak.milestone`  | Ξεπεράστηκε όριο σερί                                      |
| `transfer.sent`     | Ολοκληρώθηκε η μεταφορά token                              |
| `referral.redeemed` | Ο κωδικός πρόσκλησης εξαργυρώθηκε επιτυχώς                 |
| `compression.used`  | Εφαρμόστηκε συμπίεση προτροπής                             |
| `skill.executed`    | Ολοκληρώθηκε η εκτέλεση δεξιότητας                         |
| `model.first_use`   | Το μοντέλο δεν είχε χρησιμοποιηθεί τις τελευταίες 7 ημέρες |

### Εγγύηση Μη Αποκλεισμού

Το μοτίβο `setImmediate` + `.catch(() => {})` διασφαλίζει ότι:

1. Η απόκριση αποστέλλεται πλήρως πριν εκτελεστεί η παιχνιδοποίηση.
2. Τα σφάλματα παιχνιδοποίησης δεν εμφανίζονται ποτέ στον πελάτη.
3. Η επεξεργασία του συμβάντος εκτελείται στην επόμενη μικροεργασία και όχι ενσωματωμένα.
