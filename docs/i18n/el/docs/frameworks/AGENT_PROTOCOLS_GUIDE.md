> **Πηγή:** `src/lib/{a2a,acp,cloudAgent}/`, `src/app/api/{a2a,acp,cloud}/`, `src/app/api/v1/agents/`
> **Τελευταία ενημέρωση:** 2026-06-28 — v3.8.40

Το OmniRoute διαθέτει τρεις διαφορετικές επιφάνειες που σχετίζονται με agents. Με την πρώτη ματιά μοιάζουν, αλλά επιλύουν διαφορετικά προβλήματα. Χρησιμοποιήστε αυτήν τη σελίδα για να επιλέξετε την κατάλληλη.

## Εν συντομία

| Επιφάνεια                   | Ιδανική για                                                                                                                                                           | Μεταφορά                                | Πρότυπο                        |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- | ------------------------------ |
| **A2A — Agent-to-Agent**    | Συνεργασία μεταξύ agents με ομότιμους agents που υποστηρίζουν το πρωτόκολλο A2A                                                                                       | JSON-RPC 2.0 μέσω HTTP                  | A2A v0.3 (ανοικτή προδιαγραφή) |
| **ACP — Μητρώο CLI Agents** | Εντοπισμό / καταχώριση / εκκίνηση CLI agents προγραμματισμού που είναι εγκατεστημένοι στον υπολογιστή του χρήστη (Cursor, Cline, Codex CLI, Claude Code, Aider κ.λπ.) | HTTP REST                               | Ειδικό για το OmniRoute        |
| **Cloud Agents**            | Υποβολή μακροχρόνιων εργασιών προγραμματισμού σε εξωτερικές υπηρεσίες cloud (Codex Cloud, Devin, Jules, Cursor Cloud)                                                 | HTTP REST + εργασίες στη βάση δεδομένων | Ειδικό για το OmniRoute        |

Οι τρεις επιφάνειες είναι ανεξάρτητες — επιλέξτε οποιοδήποτε υποσύνολο.

## Δέντρο αποφάσεων

```
Χρειάζεστε μια υπηρεσία cloud για να εκτελέσει εργασίες εκτός αυτού του υπολογιστή (Codex Cloud / Cursor Cloud / Devin / Jules);
├─ ΝΑΙ → Cloud Agents (POST /api/v1/agents/tasks)
└─ ΟΧΙ → Συνεχίστε
    │
    Έχετε έναν ομότιμο agent που υποστηρίζει το A2A και θέλει να συνεργαστεί;
    ├─ ΝΑΙ → A2A (POST /a2a)
    └─ ΟΧΙ → Συνεχίστε
        │
        Χρειάζεται να παραθέσετε / διαμορφώσετε CLI agents προγραμματισμού που είναι εγκατεστημένοι τοπικά;
        ├─ ΝΑΙ → ACP (GET /api/acp/agents)
        └─ ΟΧΙ → Χρησιμοποιήστε απλώς το /v1/chat/completions
```

## 1. A2A — Agent-to-Agent

**Προδιαγραφή:** [A2A v0.3](https://a2a-protocol.org)
**Τερματικό σημείο OmniRoute:** `POST /a2a` (JSON-RPC 2.0)
**Κάρτα Agent:** `GET /.well-known/agent.json`

### Πότε να το χρησιμοποιήσετε

- Κατά τη δημιουργία ενός συστήματος πολλαπλών agents, όπου το OmniRoute είναι ένας από τους ομότιμους κόμβους
- Για τη διάθεση της ευφυΐας δρομολόγησης του OmniRoute (έξυπνη δρομολόγηση, διαχείριση ορίων χρήσης κ.λπ.) σε agents που λειτουργούν σε πλαίσια όπως το Google ADK ή σε γενικά δίκτυα agents
- Για την ενσωμάτωση του OmniRoute πίσω από μια τυποποιημένη επιφάνεια εντοπισμού + επίκλησης

### Μέθοδοι

- `message/send` — υποβάλλει ένα μήνυμα και λαμβάνει συγχρονισμένη απόκριση
- `message/stream` — υποβάλλει ένα μήνυμα και λαμβάνει συμβάντα προόδου μέσω ροής SSE
- `tasks/get` — διαβάζει μια εργασία βάσει ID
- `tasks/cancel` — ακυρώνει μια εργασία που εκτελείται

### Ενσωματωμένες δεξιότητες (6)

- `smart-routing` — δρομολογεί μια προτροπή μέσω του βέλτιστου συνδυασμού
- `quota-management` — αναφέρει την κατάσταση των ορίων χρήσης ανά πάροχο
- `provider-discovery` — παραθέτει τους εγκατεστημένους παρόχους και τις δυνατότητές τους
- `cost-analysis` — εκτιμά το κόστος ενός αιτήματος/μιας συνομιλίας
- `health-report` — συγκεντρώνει την κατάσταση breaker/cooldown/lockout ανά πάροχο
- `list-capabilities` — απαριθμεί τις διαθέσιμες δεξιότητες και τα μεταδεδομένα του agent

### Αναλυτικές πληροφορίες

Ανατρέξτε στο [A2A-SERVER.md](./A2A-SERVER.md) για λεπτομέρειες σχετικά με τη μεταφορά, τη δομή της κάρτας agent, τη διαμόρφωση TTL των εργασιών και το πρότυπο για την προσθήκη νέων δεξιοτήτων.

## 2. ACP — Μητρώο πρακτόρων CLI

**Τελικό σημείο OmniRoute:** `GET /api/acp/agents`
**Πηγή:** `src/lib/acp/{index,manager,registry}.ts`

### Τι είναι

Το ACP είναι το **τοπικό απόθεμα πρακτόρων CLI** του OmniRoute. Εντοπίζει ποια CLI προγραμματισμού είναι εγκατεστημένα στον κεντρικό υπολογιστή (Cursor, Cline, Claude Code, Codex CLI, Continue κ.λπ.), προσδιορίζει τις εκδόσεις τους και τα εμφανίζει στον πίνακα ελέγχου, ώστε ο χρήστης να μπορεί να ρυθμίσει κάθε CLI ώστε να παραπέμπει στο OmniRoute.

Αυτό ΔΕΝ είναι εξωτερικό πρωτόκολλο — είναι ένα εσωτερικό μητρώο που υποστηρίζει το περιβάλλον χρήστη «CLI Tools» και την παρακολούθηση αποτυπωμάτων CLI (δείτε το [CLI-TOOLS.md](../reference/CLI-TOOLS.md)).

### Τι κάνει

- Ελέγχει τον κεντρικό υπολογιστή για εγκατεστημένα εκτελέσιμα CLI (χρησιμοποιεί `which` / `where` ανά λειτουργικό σύστημα)
- Διαβάζει την έκδοση κάθε CLI (καλεί `<bin> --version`)
- Προαιρετικά δέχεται προσαρμοσμένους πράκτορες που ορίζονται από τον χρήστη (διαδρομή εκτελέσιμου + έλεγχος έκδοσης + ορίσματα εκκίνησης)
- Αποθηκεύει μόνιμα τους προσαρμοσμένους πράκτορες στις ρυθμίσεις
- Επιστρέφει την ενοποιημένη λίστα στον πίνακα ελέγχου

### REST API

| Τελικό σημείο     | Μέθοδος | Περιγραφή                                                                             | Έλεγχος ταυτότητας |
| ----------------- | ------- | ------------------------------------------------------------------------------------- | ------------------ |
| `/api/acp/agents` | GET     | Παραθέτει εντοπισμένους + προσαρμοσμένους πράκτορες (πλήθος εγκατεστημένων/συνολικών) | Κλειδί API         |
| `/api/acp/agents` | POST    | Προσθέτει/ενημερώνει/καταργεί προσαρμοσμένο πράκτορα (διακριτικό ενέργειας στο σώμα)  | Κλειδί API         |

Μορφή σώματος για POST (`customAgentBodySchema` στο `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Περιπτώσεις χρήσης

- Η σελίδα «CLI Tools» του πίνακα ελέγχου παραθέτει όσα είναι εγκατεστημένα και σας βοηθά να κατευθύνετε καθένα από αυτά στο OmniRoute
- Οι προσαρμοσμένοι πράκτορες επιτρέπουν στους προχωρημένους χρήστες να καταχωρίζουν εσωτερικά/ιδιόκτητα CLI που το OmniRoute δεν γνωρίζει από προεπιλογή
- Το αποτέλεσμα του εντοπισμού τροφοδοτεί τον πίνακα αποτυπωμάτων `cli-tools`

### Πότε να ΜΗ χρησιμοποιείτε το ACP

- Το ACP δεν _εκτελεί_ εργασίες. Εντοπίζει και διαμορφώνει μόνο CLI. Για να καλέσετε πραγματικά ένα CLI, το εκκινείτε εσείς με τις μεταβλητές περιβάλλοντος που παρέχει το OmniRoute (`OPENAI_BASE_URL`, `OPENAI_API_KEY` κ.λπ.).

## 3. Πράκτορες cloud

**Τελικά σημεία OmniRoute:** `/api/v1/agents/tasks/*` (κύκλος ζωής) + `/api/cloud/*` (υποδομή)
**Πηγή:** `src/lib/cloudAgent/`

### Τι είναι

Μια ενιαία διεπαφή για πράκτορες προγραμματισμού cloud τρίτων. Υποβάλλετε μια προτροπή + ένα URL αποθετηρίου, το OmniRoute την προωθεί στον κατάλληλο πράκτορα cloud, ελέγχει περιοδικά την κατάσταση και επιστρέφει τα αποτελέσματα.

### Υποστηριζόμενοι πράκτορες (4, όλοι επιβεβαιωμένοι στο `src/lib/cloudAgent/agents/`)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### Κύκλος ζωής

```
POST /api/v1/agents/tasks
  → BaseAgent.createTask() ανά κλάση πράκτορα
  → η εξωτερική υπηρεσία ξεκινά την εργασία
  → δημιουργείται εγγραφή εργασίας στη βάση δεδομένων (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → αναβλητικός συγχρονισμός κατάστασης από τον πάροχο
  → επιστρέφει την τρέχουσα κατάσταση + σχέδιο + αρχείο καταγραφής δραστηριότητας
  ↓
POST /api/v1/agents/tasks/[id]   (ενέργεια: "approve" | "message" | "cancel")
  → προωθεί στον πάροχο (ή επισημαίνει τοπικά ως ακυρωμένη)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → τοπική ακύρωση
```

### Έλεγχος ταυτότητας

⚠️ **Όλα τα τελικά σημεία `/api/v1/agents/tasks/*` απαιτούν έλεγχο ταυτότητας διαχείρισης** (commit `588a0333`). Οι καλούντες που χρησιμοποιούν μόνο Bearer λαμβάνουν 401 από την έκδοση v3.8.0 και μετά.

### Αναλυτική παρουσίαση

Δείτε το [CLOUD_AGENT.md](./CLOUD_AGENT.md) για τη σύμβαση `CloudAgentBase`, τις λεπτομέρειες ανά πράκτορα, τις λεπτομέρειες του σχήματος και τα τελικά σημεία υποδομής διαπιστευτηρίων.

## Σύγκριση: A2A έναντι Cloud Agents

Και τα δύο υποστηρίζουν «εργασίες μεγάλης διάρκειας», αλλά σε διαφορετικά επίπεδα:

| Πτυχή                        | A2A                                                                                    | Cloud Agents                                         |
| ---------------------------- | -------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| Πρότυπο                      | Ανοιχτό A2A v0.3                                                                       | Ειδικό για το OmniRoute                              |
| Πού εκτελείται η επεξεργασία | Εντός του OmniRoute (χρησιμοποιεί τους διαμορφωμένους συνδυασμούς)                     | Εξωτερικά (διακομιστές Codex / Devin / Jules)        |
| Διάρκεια εργασίας            | Προεπιλεγμένο TTL 5 λεπτών (διαμορφώσιμο στο `TaskManager`)                            | Από λεπτά έως ώρες                                   |
| Επίγνωση αποθετηρίου         | Όχι (διαβιβάζει μόνο προτροπές)                                                        | Ναι (URL αποθετηρίου + κλάδος)                       |
| Περίπτωση χρήσης             | Συνεργασία μεταξύ agents, έξυπνη δρομολόγηση ως υπηρεσία                               | Ανάθεση «υλοποίησε τη λειτουργία X στο αποθετήριο Y» |
| Έλεγχος ταυτότητας           | Προαιρετικό `OMNIROUTE_API_KEY` για `/a2a`· διαχείριση για βοηθητικά REST `/api/a2a/*` | Πάντα μέσω διαχείρισης                               |

## Παραδείγματα ενσωμάτωσης

### Ανακάλυψη των δυνατοτήτων A2A του OmniRoute

```bash
curl http://localhost:20128/.well-known/agent.json
```

Επιστρέφει την Κάρτα Agent με όλες τις 6 δεξιότητες, τους τρόπους μεταφοράς και την έκδοση.

### Κλήση του OmniRoute ως A2A agent

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### Εμφάνιση των εγκατεστημένων CLI agents μέσω ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Προσθήκη προσαρμοσμένου CLI agent

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### Υποβολή εργασίας Cloud Agent

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### Περιοδικός έλεγχος της κατάστασης εργασίας στο cloud

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## Πότε να χρησιμοποιείτε τι

- **Frontend chatbot / copilot** → `/v1/chat/completions` (συμβατό με OpenAI — δεν αποτελεί πρωτόκολλο agent)
- **Συνεργασία πολλαπλών agents** → A2A
- **Εμφάνιση τοπικών CLI στον πίνακα ελέγχου** → ACP
- **Ανάθεση εργασιών προγραμματισμού μεγάλης διάρκειας σε υπηρεσίες cloud** → Cloud Agents
