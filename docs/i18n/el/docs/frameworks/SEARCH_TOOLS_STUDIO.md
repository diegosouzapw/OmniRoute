## Επισκόπηση

Το Search Tools Studio μετατρέπει το `/dashboard/search-tools` από ένα βασικό περιβάλλον δοκιμών αναζήτησης σε ένα
Studio τριών καρτελών που ενοποιεί την αναζήτηση ιστού, την εξαγωγή περιεχομένου από ιστοσελίδες και τη σύγκριση παρόχων σε παράλληλη προβολή.

```
┌ Εργαλεία αναζήτησης ───────────────────────────────────────────────────┐
│ [🔍 Αναζήτηση] [📄 Εξαγωγή] [⚖ Σύγκριση]        142ms · $0.001  </>    │
│ ⓘ [Οδηγός τρόπων λειτουργίας]                                          │
├──────────────────────────────────────────┬─────────────────────────────┤
│  {περιεχόμενο ενεργής καρτέλας}          │ ─ Ρυθμίσεις                 │
│                                          │ Πάροχος [αυτόματα ∨]        │
│                                          │   🟢 Serper  $0.001         │
│                                          │   🟢 Tavily  $0.008         │
│                                          │   🔥 Firecrawl (ανάκτηση)   │
│                                          │ Τύπος [ιστός | ειδήσεις]    │
│                                          │ Πλήρης σελίδα [ ] (εξαγωγή)│
│                                          │ Μορφή [md|κείμενο|html]     │
│                                          │ Μοντέλο ανακατάταξης [∨]    │
└──────────────────────────────────────────┴─────────────────────────────┘
```

## Καρτέλες

### Καρτέλα Αναζήτησης

Εξελίσσει τα υπάρχοντα `SearchForm` + `ResultsPanel` + `RerankPanel` σε μία καρτέλα:

- Ερώτημα → αποτελέσματα (τίτλος, URL, απόσπασμα, βαθμολογία συνάφειας).
- Μεταδεδομένα παρόχου στο τμήμα Ρυθμίσεων (κόστος, όριο χρήσης, κατάσταση).
- Ενότητα ανακατάταξης: επιλογή μοντέλου ανακατάταξης, αναδιάταξη αποτελεσμάτων, εμφάνιση του `positionDelta`.
- Κενή κατάσταση με παρότρυνση για ενέργεια όταν δεν έχουν ρυθμιστεί πάροχοι αναζήτησης.
- Ιστορικό αναζητήσεων μέσω του `SearchHistory.tsx`.
- Καλεί το `POST /v1/search` (υπάρχον endpoint, χωρίς αλλαγές).

### Καρτέλα Εξαγωγής

Νέα καρτέλα για την εξαγωγή περιεχομένου από ένα URL μέσω του `POST /v1/web/fetch` (δημιουργήθηκε στο πλάνο 05):

- Είσοδος: URL + διακόπτης πλήρους σελίδας + επιλογέας μορφής (markdown / κείμενο / HTML).
- Υποβολή → ανάκτηση → απόδοση του `ScrapeResult.tsx`.
- Το `ScrapeResult` αποδίδει προεπισκόπηση markdown + διακόπτη ανεπεξέργαστης προβολής.
- Όριο: αν το σώμα της απόκρισης είναι μεγαλύτερο από **256 KB**, το UI εμφανίζει `(περικομμένο, προβολή ανεπεξέργαστου)` και ανοίγει το ανεπεξέργαστο περιεχόμενο σε ένα αναδυόμενο παράθυρο Monaco (D21).
- Πίνακας μεταδεδομένων: πάροχος (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search), καθυστέρηση, κόστος, μέγεθος απόκρισης, πλήθος συνδέσμων.
- Χρησιμοποιεί το hook `useScrapeFetch.ts`.

### Καρτέλα Σύγκρισης

Εκτελεί το ίδιο ερώτημα/URL σε έως και **4 παρόχους παράλληλα** (D22):

- Στήλες σε παράλληλη προβολή ανά πάροχο.
- Μετρικές: καθυστέρηση, κόστος, πλήθος αποτελεσμάτων, μέγεθος απόκρισης.
- Υπολογισμός επικάλυψης URL για την αναζήτηση (αριθμός κοινών URL σε σχέση με το αρχικό αποτέλεσμα).
- Καλεί το `POST /v1/search` (αναζήτηση) ή το `POST /v1/web/fetch` (εξαγωγή) ανά πάροχο.

## Τμήμα Ρυθμίσεων (Κοινόχρηστο)

`SearchToolsConfigPane.tsx` — πάντα ορατό, με δυνατότητα σύμπτυξης.

| Πεδίο                | Σημειώσεις                                                                            |
| -------------------- | ------------------------------------------------------------------------------------- |
| Πάροχος              | Αναπτυσσόμενη λίστα με ένδειξη κατάστασης (ρυθμισμένος / απών / περιορισμένος)        |
| Τύπος                | `web` ή `news` (μόνο για αναζήτηση)                                                   |
| Πλήρης σελίδα        | Διακόπτης για εξαγωγή — ανακτά ολόκληρη τη σελίδα αντί για το πρώτο ορατό περιεχόμενο |
| Μορφή                | `markdown`, `text` ή `html` (μόνο για εξαγωγή)                                        |
| Μοντέλο ανακατάταξης | Προαιρετικό μοντέλο για ανακατάταξη μετά την αναζήτηση                                |
| Ιστορικό             | Πτυσσόμενη ενότητα ιστορικού αναζητήσεων                                              |

## SearchConceptCard

`SearchConceptCard.tsx` — πάντα ορατό, πτυσσόμενο accordion. Εξηγεί:

| Έννοια                   | Σύντομη περιγραφή                                                                   |
| ------------------------ | ----------------------------------------------------------------------------------- |
| **Αναζήτηση**            | Ανακτά μια λίστα αποτελεσμάτων ιστού (τίτλος, URL, απόσπασμα, βαθμολογία συνάφειας) |
| **Εξαγωγή**              | Εξάγει το πλήρες περιεχόμενο ενός URL (markdown, κείμενο ή HTML)                    |
| **Σύγκριση**             | Εκτελεί το ίδιο ερώτημα σε N παρόχους παράλληλα                                     |
| **Ανακατάταξη**          | Αναδιατάσσει τα αποτελέσματα μέσω LLM για βελτίωση της συνάφειας με το ερώτημα      |
| **Αυτόματα (φθηνότερο)** | Επιλέγει αυτόματα τον φθηνότερο διαθέσιμο πάροχο                                    |

## Κατάλογος παρόχων

Το `ProviderCatalog.tsx` εκθέτει την πλήρη λίστα παρόχων από το `GET /api/search/providers`
(επεκτάθηκε στο F4 ώστε να περιλαμβάνει παρόχους ανάκτησης):

| `kind` | `"search"` (20 πάροχοι) ή `"fetch"` (firecrawl, jina-reader, tavily-search, tinyfish, nimble-search, anysearch-search) |

Η κατάσταση **προσδιορίζεται κατά τη στιγμή του αιτήματος**, ελέγχοντας αν υπάρχουν διαπιστευτήρια και αν
όλα τα κλειδιά βρίσκονται επί του παρόντος σε περίοδο αναμονής.

---

## Εξαγωγή κώδικα

Το `ExportCodeModal` (που εισάγεται από το Playground Studio) και το `codeExport.ts` δημιουργούν
αποσπάσματα curl / Python / TypeScript για κλήσεις τόσο στο `/v1/search` όσο και στο `/v1/web/fetch`.
Το σύμβολο κράτησης θέσης για το κλειδί API είναι πάντα `$OMNIROUTE_API_KEY` (D11, κοινόχρηστο με το Playground Studio).

## Αλλαγές στο backend

Για αυτήν τη λειτουργία απαιτήθηκε μόνο μία αλλαγή στο backend:

### Επεκτεταμένο `GET /api/search/providers`

Το `src/app/api/search/providers/route.ts` επεκτάθηκε ώστε να:

- Περιλαμβάνει και τους 6 παρόχους ανάκτησης (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`) στον πίνακα.
- Προσθέτει `kind: "search" | "fetch"` σε κάθε στοιχείο.
- Προσθέτει `status: "configured" | "missing" | "rate_limited"` που προκύπτει από την τρέχουσα κατάσταση των διαπιστευτηρίων.
- Διατηρεί τη συμβατότητα προς τα πίσω — τα υπάρχοντα πεδία (`id`, `name` κ.λπ.) παραμένουν αμετάβλητα.

## Αντιμετώπιση προβλημάτων

| Σύμπτωμα                                                     | Αιτία                                    | Διόρθωση                                                                                                                    |
| ------------------------------------------------------------ | ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Η καρτέλα Scrape εμφανίζει "το endpoint δεν είναι διαθέσιμο" | Το `/v1/web/fetch` δεν είναι συνδεδεμένο | Επαληθεύστε ότι το σχέδιο 05 έχει συγχωνευτεί και ότι υπάρχει το `src/app/api/v1/web/fetch/route.ts`                        |
| Ο κατάλογος παρόχων εμφανίζει όλους ως "απόντες"             | Δεν έχουν ρυθμιστεί διαπιστευτήρια       | Προσθέστε διαπιστευτήρια στο `/dashboard/providers`                                                                         |
| Το περιεχόμενο του Scrape είναι περικομμένο                  | Απόκριση > όριο 256 KB                   | Αναμενόμενη συμπεριφορά (D21). Χρησιμοποιήστε το κουμπί "προβολή ανεπεξέργαστου περιεχομένου" για το πλήρες περιεχόμενο     |
| Η καρτέλα Compare εμφανίζει μόνο 2 παρόχους                  | Ενεργό όριο ρυθμού                       | Δύο ή περισσότεροι πάροχοι ενδέχεται να βρίσκονται σε περίοδο αναμονής — ελέγξτε την κατάσταση των παρόχων στο τμήμα Config |
| Το "Μέγεθος" εμφανίζεται ως ανεπεξέργαστο κλειδί στον πίνακα | Λείπει το κλειδί i18n                    | Επαληθεύστε ότι το `search.size` υπάρχει στο αρχείο τοπικών ρυθμίσεων και επαναλάβετε τη μεταγλώττιση του i18n              |
