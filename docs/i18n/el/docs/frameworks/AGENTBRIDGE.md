Το AgentBridge είναι ο διακομιστής μεσολάβησης MITM (Man-in-the-Middle) του OmniRoute, ο οποίος υποκλέπτει την κίνηση HTTPS από πράκτορες AI σε IDE και την αναδρομολογεί μέσω της ενοποιημένης μηχανής δρομολόγησης του OmniRoute. Υποστηρίζει **10 πράκτορες IDE** — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code και Trae (υπό διερεύνηση) — καθιστώντας το OmniRoute τον διακομιστή μεσολάβησης MITM με την ευρύτερη κάλυψη για βοηθούς προγραμματισμού AI στην αγορά.

**Τοποθεσία πίνακα ελέγχου:** `/dashboard/tools/agent-bridge`
**Ομάδα πλευρικής γραμμής:** Εργαλεία (μετά το Cloud Agents)
**Δείτε επίσης:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — παρακολουθήστε όλη την υποκλαπείσα κίνηση σε πραγματικό χρόνο· `docs/security/MITM-TPROXY-DECRYPT.md` (git· δεν μεταγλωττίζεται στο `/docs`) — η λειτουργία καταγραφής διαφανούς αποκρυπτογράφησης TPROXY για Linux, η οποία ελέγχεται από τη διαδρομή `/api/tools/agent-bridge/tproxy`.

## §1 Επισκόπηση

### Τι είναι το AgentBridge;

Όταν ένας πράκτορας IDE (π.χ. GitHub Copilot, Cursor, Claude Code) πραγματοποιεί μια κλήση API, συνδέεται απευθείας με τον ανάντη πάροχο AI (OpenAI, Anthropic κ.λπ.). Το AgentBridge υποκλέπτει αυτήν τη σύνδεση με διαφανή τρόπο στο επίπεδο TLS — χωρίς να απαιτείται καμία αλλαγή στη διαμόρφωση του πράκτορα — και επανεγγράφει το αίτημα μέσω του OmniRoute.

Αυτό σημαίνει ότι μπορείτε να:

- **Αναδρομολογείτε οποιονδήποτε πράκτορα προς οποιονδήποτε πάροχο**: Το Copilot επικοινωνεί με το OpenAI; Ανακατευθύνετέ το στο Anthropic Claude, στο Gemini ή σε οποιονδήποτε από τους 352 παρόχους του OmniRoute.
- **Εφαρμόζετε αντιστοιχίσεις μοντέλων**: `gemini-3-flash` → `claude-sonnet-4.7` με διαφανή τρόπο σε επίπεδο χειριστή.
- **Παρατηρείτε όλη την κίνηση των πρακτόρων**: κάθε υποκλαπέν αίτημα δημοσιεύεται στο [Traffic Inspector](./TRAFFIC_INSPECTOR.md).
- **Εφαρμόζετε την ανθεκτικότητα του OmniRoute**: η συνδυαστική δρομολόγηση, οι διακόπτες κυκλώματος, οι εφεδρικές επιλογές και η παρακολούθηση κόστους λειτουργούν και για την κίνηση πρακτόρων IDE.

## §2 Αρχιτεκτονική

### 2.1 Επισκόπηση στοιχείων

```
Πράκτορας IDE (VS Code / Cursor / κ.λπ.)
    │  HTTPS (θύρα 443)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← ανακατεύθυνση DNS
    │
    ▼
src/mitm/server.cjs  (θύρα 443, θυγατρική διεργασία CJS)
    │  επιλύει τον προορισμό βάσει του SNI της κεφαλίδας Host
    │  δημιουργεί πιστοποιητικό TLS ανά SNI, υπογεγραμμένο από την CA του AgentBridge
    ├── Αντιστοίχιση στη λίστα παράκαμψης; → διέλευση TCP (χωρίς αποκρυπτογράφηση)
    ├── Αντιστοίχιση προορισμού; → fetch → δρομολογητής OmniRoute (θύρα 20128)
    │       └── handler.intercept() — TypeScript
    │               ├── maskSecrets() στο σώμα/στις κεφαλίδες του αιτήματος
    │               ├── TrafficBuffer.push() — δημοσιεύει στο Traffic Inspector
    │               └── fetchRouter() → /v1/chat/completions
    └── Καμία αντιστοίχιση; → διέλευση TCP (χωρίς αποκρυπτογράφηση)
```

### 2.2 Διακομιστής MITM (`src/mitm/server.cjs`)

Ο βασικός διακομιστής MITM εκτελείται ως θυγατρική διεργασία Node.js CJS (ώστε να αποφευχθεί η επανεγγραφή της υπάρχουσας βάσης κώδικα CJS). Ο διακομιστής:

- Ακούει στη θύρα 443 (απαιτεί δικαιώματα ή `authbind`/`setcap`)
- Λαμβάνει σήραγγες CONNECT από το λειτουργικό σύστημα (μέσω ανακατεύθυνσης DNS στο `/etc/hosts`)
- Δημιουργεί πιστοποιητικά TLS ανά SNI, υπογεγραμμένα από την CA του AgentBridge (`DATA_DIR/mitm/ca.crt`)
- Επιλύει τον πράκτορα προορισμού βάσει της κεφαλίδας Host μέσω του μητρώου `targets/index.ts`
- Προωθεί στο επίπεδο χειριστών TypeScript μέσω HTTP στη διεύθυνση `http://127.0.0.1:20128`

Το `TARGET_HOSTS` φορτώνεται από το `DATA_DIR/mitm/targets.json` (το οποίο εγγράφεται από το `targets/index.ts` κατά την εκκίνηση), επιτρέποντας δυναμικές ενημερώσεις χωρίς επανεκκίνηση του διακομιστή CJS.

> **Μοντέλο root-CA (#6684).** Η προσέγγιση πιστοποιητικού ανά SNI υπογεγραμμένου από CA που περιγράφεται παραπάνω
> είναι το μόνιμα αποθηκευμένο μοντέλο root-CA που προστέθηκε στο #6684 (`src/mitm/cert/rootCa.ts` +
> `src/mitm/_internal/rootCaShim.cjs`, επαναχρησιμοποιώντας την κρυπτογραφία CA/τελικού πιστοποιητικού που έχει ήδη
> δοκιμαστεί για το TPROXY στο `src/mitm/tproxy/dynamicCert.ts`) — αντικαθιστά το
> παλαιότερο, μοναδικό στατικό αυτοϋπογεγραμμένο τελικό πιστοποιητικό (`src/mitm/cert/generate.ts`, το οποίο εξακολουθεί
> να περιορίζεται μόνο στους κεντρικούς υπολογιστές antigravity) που υποδεικνύει ένα απλό ζεύγος
> `server.crt`/`server.key` στον δίσκο. **Συμπεριφορά μετεγκατάστασης**: μια νέα εγκατάσταση (χωρίς προϋπάρχον
> `server.crt`) λαμβάνει αυτόματα το μοντέλο root-CA· μια εγκατάσταση που έχει ήδη
> εμπιστευτεί το παλιό στατικό τελικό πιστοποιητικό συνεχίζει να το χρησιμοποιεί έως ότου ο διαχειριστής ορίσει
> `MITM_ROOT_CA_ENABLED=true` και επανεκκινήσει τη γέφυρα (το `src/mitm/cert/migration.ts`
> είναι η αμιγής συνάρτηση απόφασης — μια έμπιστη CA MITM που μπορεί να υπογράψει τελικό πιστοποιητικό για
> **οποιονδήποτε** κεντρικό υπολογιστή είναι ουσιωδώς ισχυρότερη από το παλιό τελικό πιστοποιητικό σταθερού SAN, επομένως η
> μετάβαση δεν γίνεται ποτέ σιωπηρά σε μια ήδη έμπιστη εγκατάσταση). Το πιστοποιητικό CA εγκαθίσταται
> στην ίδια θέση `omniroute-mitm.crt` του χώρου αποθήκευσης έμπιστων πιστοποιητικών που χρησιμοποιούσε το παλιό τελικό πιστοποιητικό
> (`cert/install.ts::installCaCert`) — δεν απαιτείται εκκαθάριση διπλής εμπιστοσύνης.

### 2.3 Βασικός χειριστής (`src/mitm/handlers/base.ts`)

Όλοι οι χειριστές πρακτόρων επεκτείνουν το `MitmHandlerBase`:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // Προστατευμένες βοηθητικές μέθοδοι: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

Κάθε χειριστής καλεί το `hookBufferStart()` πριν από τη διαμεσολάβηση και το `hookBufferUpdate()` όταν ολοκληρωθεί. Αυτές οι κλήσεις προωθούν καταχωρίσεις `InterceptedRequest` στο `globalTrafficBuffer` (βλ. [Traffic Inspector](./TRAFFIC_INSPECTOR.md) §4).

### 2.4 Μητρώο προορισμών (`src/mitm/targets/`)

Κάθε πράκτορας διαθέτει ένα δηλωτικό αρχείο προορισμού:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

Το μητρώο (`targets/index.ts`) εξάγει το `ALL_TARGETS` και δημιουργεί το `DATA_DIR/mitm/targets.json` κατά την εκκίνηση.

### 2.5 Διέλευση και λίστα παράκαμψης (`src/mitm/passthrough.ts`)

**Λίστα παράκαμψης** (ελέγχεται πρώτη, με προτεραιότητα έναντι της αντιστοίχισης προορισμού):

- Προεπιλεγμένα μοτίβα: κεντρικοί υπολογιστές τραπεζών, `.gov.`, πάροχοι OAuth/SSO (Okta, Auth0) κ.λπ.
- Μοτίβα χρήστη: αποθηκεύονται στον πίνακα βάσης δεδομένων `agent_bridge_bypass`
- Οι κεντρικοί υπολογιστές που παρακάμπτονται λαμβάνουν μια διαφανή σήραγγα TCP — το TLS **δεν αποκρυπτογραφείται ποτέ**

**Προεπιλεγμένη διέλευση** (χωρίς αντιστοίχιση προορισμού και εκτός λίστας παράκαμψης):

- Λαμβάνει επίσης μια σήραγγα TCP — οι συνδέσεις δεν διακόπτονται ποτέ
- Αποτρέπει τη διατάραξη της γενικής κίνησης HTTPS του συστήματος από το AgentBridge

Προτεραιότητα δρομολόγησης:

```
λίστα παράκαμψης → αντιστοίχιση προορισμού → διέλευση
```

### 2.6 Πιστοποιητικό CA ανάντη σύνδεσης (`src/mitm/upstreamTrust.ts`)

Για εταιρικά περιβάλλοντα δικτύου με προσαρμοσμένη CA:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

Όταν οριστεί, διαμορφώνει τον καθολικό διεκπεραιωτή του `undici` με το πρόσθετο πιστοποιητικό CA, επιτρέποντας στο AgentBridge να επικοινωνεί με ανάντη παρόχους μέσω εταιρικών διακομιστών μεσολάβησης τερματισμού TLS.

### 2.7 Απόκρυψη μυστικών (`src/mitm/maskSecrets.ts`)

Ο ανεξάρτητος σαρωτής καθαρής υλοποίησης εφαρμόζεται στα σώματα των αιτημάτων και στις κεφαλίδες διαπιστευτηρίων
**πριν** αυτά εισέλθουν στην προσωρινή μνήμη του Traffic Inspector ή σε οποιοδήποτε αρχείο καταγραφής. Εκτελεί μία γραμμική διέλευση:

- Διακριτικά με πρόθεμα `sk-` / `ak-` / `pk-` (τύπου OpenAI/Anthropic)
- Διαπιστευτήρια RFC 6750 `Authorization: Bearer <token>`, με προτεραιότητα σε ολόκληρο το διακριτικό
- Γενικά μεγάλα αδιαφανή διακριτικά (≥40 χαρακτήρες), συμπεριλαμβανομένων μορφών με τελείες και συμπλήρωση

Η `sanitizeHeaders()` μετατρέπει σε πεζά τα ονόματα που διατηρούνται, συνενώνει τις τιμές πινάκων με ντετερμινιστικό τρόπο, απορρίπτει την
κοινόχρηστη λίστα αποκλεισμού κεφαλίδων ανά άλμα/πλαισίωσης (συμπεριλαμβανομένου του ελέγχου ταυτότητας διακομιστή μεσολάβησης), αποκρύπτει πλήρως τα `cookie` και
`set-cookie` και αναθέτει τις τιμές διαπιστευτηρίων στον σαρωτή.

## §3 Ρύθμιση

### 3.1 Εκκίνηση/διακοπή του διακομιστή MITM

Χρησιμοποιήστε την Κάρτα Διακομιστή AgentBridge στη διαδρομή `/dashboard/tools/agent-bridge`:

| Ενέργεια                     | Περιγραφή                                                                                                       |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Εκκίνηση διακομιστή          | Εκκινεί το `src/mitm/server.cjs` στη θύρα 443                                                                   |
| Διακοπή διακομιστή           | Τερματίζει ομαλά τη θυγατρική διεργασία                                                                         |
| Επανεκκίνηση διακομιστή      | Διακοπή + εκκίνηση (εφαρμόζει τις αλλαγές προορισμού)                                                           |
| Αξιόπιστο πιστοποιητικό      | Εγκαθιστά το `DATA_DIR/mitm/ca.crt` στον χώρο αποθήκευσης αξιόπιστων πιστοποιητικών του λειτουργικού συστήματος |
| Λήψη πιστοποιητικού          | Πραγματοποιεί λήψη του `ca.crt` για μη αυτόματη εγκατάσταση                                                     |
| Αναδημιουργία πιστοποιητικού | Δημιουργεί ένα νέο ζεύγος κλειδιών CA (όλα τα υπάρχοντα πιστοποιητικά ανά πράκτορα ακυρώνονται)                 |

### 3.2 Ορισμός του πιστοποιητικού ως αξιόπιστου

Το πιστοποιητικό CA του AgentBridge πρέπει να θεωρείται αξιόπιστο από το λειτουργικό σύστημα προτού τα IDE αποδεχτούν τη σύνδεση MITM.

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Keychain):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

Εναλλακτικά, χρησιμοποιήστε το κουμπί "Αξιόπιστο πιστοποιητικό" στον πίνακα ελέγχου (εκτελεί την κατάλληλη εντολή για το λειτουργικό σας σύστημα, με προτροπή sudo εάν απαιτείται).

#### Τα IDE που βασίζονται στο Electron αγνοούν τον χώρο αποθήκευσης αξιόπιστων πιστοποιητικών του λειτουργικού συστήματος (`NODE_EXTRA_CA_CERTS`)

Ορισμένα IDE — κυρίως το **Antigravity IDE** και άλλες εφαρμογές που βασίζονται στο Electron / VS Code — ενσωματώνουν
το δικό τους περιβάλλον εκτέλεσης Node.js, το οποίο **δεν συμβουλεύεται τον χώρο αποθήκευσης αξιόπιστων πιστοποιητικών του λειτουργικού συστήματος** για εξερχόμενα
αιτήματα `fetch`/HTTPS. Η προσθήκη του CA ως αξιόπιστου σε επίπεδο λειτουργικού συστήματος/NSS επαρκεί για το εγγενές **backend**
του IDE (π.χ. έναν διακομιστή γλώσσας Go, ο οποίος χρησιμοποιεί το πακέτο CA του λειτουργικού συστήματος), αλλά το **frontend του Electron** θα
εξακολουθεί να αποτυγχάνει στο TLS — αυτό εμφανίζεται ως _αποσύνδεση_ της εφαρμογής ή ως _"σφάλμα σύνδεσης"_,
παρόλο που το αρχείο καταγραφής MITM δείχνει ότι οι κλήσεις αρχικοποίησης του backend επιστρέφουν `200`. Απαιτούνται δύο βήματα
και είναι σημαντικά και τα δύο:

1. Κατευθύνετε ρητά το περιβάλλον εκτέλεσης προς το CA:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **Εκκινήστε το IDE από αυτό το κέλυφος.** Η εκκίνησή του από το εικονίδιο της επιφάνειας εργασίας / το Dock / το μενού Έναρξη
   **δεν** κληρονομεί τις εξαγόμενες μεταβλητές του κελύφους, ενώ το `~/.config/environment.d/*.conf` εφαρμόζεται μόνο μετά
   από νέα είσοδο στο γραφικό περιβάλλον. Κλείστε πρώτα πλήρως το IDE — το κλείδωμα μοναδικής διεργασίας του Electron σημαίνει ότι μια δεύτερη
   εκκίνηση απλώς εστιάζει την υπάρχουσα διεργασία και το νέο περιβάλλον αγνοείται.

Το παραπάνω βήμα ορισμού αξιοπιστίας στο λειτουργικό σύστημα + NSS παραμένει απαραίτητο (η στοίβα δικτύου Chromium που χρησιμοποιείται από ορισμένες ροές
ελέγχου ταυτότητας διαβάζει τον χώρο αποθήκευσης NSS ανά χρήστη και διαθέτει τις δικές της στατικές δεσμεύσεις για το `*.googleapis.com`, τις οποίες
παρακάμπτει ένα τοπικά αξιόπιστο CA). Το `NODE_EXTRA_CA_CERTS` καλύπτει επιπλέον τη διαδρομή `fetch` του Node.

### 3.3 Δρομολόγηση DNS

Για κάθε πράκτορα που θέλετε να αναχαιτίσετε, οι κεντρικοί υπολογιστές API του πρέπει να επιλύονται σε `127.0.0.1`. Το AgentBridge διαχειρίζεται αυτόματα τις καταχωρίσεις του `/etc/hosts` όταν ενεργοποιείτε ή απενεργοποιείτε το DNS για έναν πράκτορα στον Οδηγό Ρύθμισης.

Παράδειγμα καταχωρίσεων `/etc/hosts` για το GitHub Copilot:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 Αντιστοίχιση μοντέλων

Χρησιμοποιήστε τον Πίνακα Αντιστοίχισης Μοντέλων σε κάθε κάρτα πράκτορα για να ορίσετε αντιστοιχίσεις προέλευσης → προορισμού:

| Μοντέλο προέλευσης (εγγενές στον πράκτορα) | Μοντέλο προορισμού (OmniRoute) |
| ------------------------------------------ | ------------------------------ |
| `gpt-4o`                                   | `claude-sonnet-4.7`            |
| `*` (χαρακτήρας μπαλαντέρ)                 | `claude-haiku-4.7`             |

Ο χαρακτήρας μπαλαντέρ `*` αντιστοιχίζει οποιοδήποτε μη αναγνωρισμένο μοντέλο στον καθορισμένο προορισμό. Αποθηκεύεται μόνιμα στον πίνακα `agent_bridge_mappings`.

> **Συμβουλή — ανακαλύψτε τα πραγματικά αναγνωριστικά μοντέλων του πράκτορα.** Ένα IDE ενδέχεται να στέλνει ονόματα μοντέλων που διαφέρουν από
> τις ετικέτες του περιβάλλοντος χρήστη του και αλλάζουν μεταξύ κύριων εκδόσεων. Για παράδειγμα, το **Antigravity 2** στέλνει
> `gemini-3.1-pro-low`, `gemini-pro-agent` και `gemini-3.1-flash-lite` μέσω του δικτύου — όχι το
> `gemini-2.5-pro` που εμφανίζεται σε παλαιότερη τεκμηρίωση. Στείλτε μία συνομιλία χωρίς να υπάρχει αντίστοιχη αντιστοίχιση: το MITM
> καταγράφει την ακριβή εισερχόμενη τιμή `model:` και προωθεί το αίτημα αυτούσιο. Αντιστοιχίστε αυτήν την κυριολεκτική τιμή και, στη συνέχεια,
> το επόμενο αίτημα αναχαιτίζεται και δρομολογείται στον προορισμό σας.

### 3.5 Ειδοποίηση κινδύνου

Το AgentBridge αναχαιτίζει διαπιστευτήρια (διακριτικά OAuth, κλειδιά API) τα οποία χρησιμοποιεί το IDE για έλεγχο ταυτότητας με ανάντη παρόχους. Αυτά **αποκρύπτονται πριν από την καταγραφή** (βλ. §2.7), αλλά είναι ορατά στο επίπεδο MITM του OmniRoute. Κατά την πρώτη ενεργοποίηση κάθε πράκτορα εμφανίζεται ένα αποκλειόμενο παράθυρο ειδοποίησης κινδύνου.

### 3.6 Συντήρηση και διαγνωστικά

Ο πίνακας ελέγχου παρέχει μια κάρτα **Συντήρηση και διαγνωστικά** (`AgentBridgeMaintenanceCard`, στο `src/app/(dashboard)/dashboard/tools/agent-bridge/components/`), η οποία εμφανίζει λειτουργικές διαδρομές MITM που προηγουμένως δεν διέθεταν περιβάλλον χρήστη. Ο υπότιτλός της είναι: _"Εκτελέστε αυτοδιαγνωστικό έλεγχο της διοχέτευσης καταγραφής, αναιρέστε τυχόν υπολειπόμενη κατάσταση συστήματος και μεταφέρετε τη ρύθμισή σας μεταξύ μηχανημάτων."_ Οι βοηθητικές συναρτήσεις πελάτη της κάρτας βρίσκονται στο `src/lib/inspector/agentBridgeMaintenanceApi.ts`.

| Κουμπί                 | Διαδρομή                               | Τι κάνει                                                                                                                                                                                                                                                                      |
| ---------------------- | -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Διάγνωση**           | `GET /api/tools/agent-bridge/diagnose` | Εκτελεί τον αυτοέλεγχο της διοχέτευσης καταγραφής και εμφανίζει μια αναφορά ανά έλεγχο (✓/✗ + υπόδειξη αποκατάστασης).                                                                                                                                                        |
| **Επιδιόρθωση**        | `POST /api/tools/agent-bridge/repair`  | Αναιρεί την ορφανή κατάσταση MITM του συστήματος (καταχωρίσεις πλαστογράφησης DNS, ριζική CA, διακομιστής μεσολάβησης συστήματος) που παρέμεινε μετά από κατάρρευση ή SIGKILL. Είναι ιδιοδύναμη — αναφέρει «Δεν υπάρχει κάτι προς επιδιόρθωση» όταν η κατάσταση είναι καθαρή. |
| **Αφαίρεση CA**        | `DELETE /api/tools/agent-bridge/cert`  | Καταργεί την αξιοπιστία και αφαιρεί τη ριζική CA του MITM από τον χώρο αποθήκευσης αξιόπιστων πιστοποιητικών του λειτουργικού συστήματος (ρητή, ιδιοδύναμη ενέργεια). Εμφανίζεται μόνο όταν η CA θεωρείται αξιόπιστη· απαιτεί ενσωματωμένη επιβεβαίωση «Αφαίρεση CA;».        |
| **Εξαγωγή ρυθμίσεων**  | `GET /api/tools/agent-bridge/config`   | Πραγματοποιεί λήψη του φορητού JSON ρυθμίσεων (βλ. §3.7).                                                                                                                                                                                                                     |
| **Εισαγωγή ρυθμίσεων** | `POST /api/tools/agent-bridge/config`  | Μεταφορτώνει ένα JSON ρυθμίσεων που είχε εξαχθεί προηγουμένως (βλ. §3.7).                                                                                                                                                                                                     |

**Έλεγχοι διάγνωσης** (`summarizeDiagnostics()` στο `src/mitm/inspector/diagnostics.ts`). Η διαδρομή εκτελεί τη δοκιμή με παρενέργειες για κάθε έλεγχο και τροφοδοτεί τις δυαδικές τιμές στον αμιγή μηχανισμό σύνοψης· επιστρέφονται μία ενιαία ετυμηγορία `healthy` και μία υπόδειξη ανά αποτυχία:

| Όνομα ελέγχου      | Τι επαληθεύει                                                                                              | Υπόδειξη σε περίπτωση αποτυχίας                                                                                                                                                                                                    |
| ------------------ | ---------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server-running`   | Η διεργασία του διακομιστή MITM είναι ενεργή                                                               | «Ο διακομιστής MITM δεν εκτελείται. Εκκινήστε τον από την καρτέλα AgentBridge.»                                                                                                                                                    |
| `server-reachable` | Ο διακομιστής MITM δέχεται συνδέσεις στη θύρα του (δοκιμή TCP)                                             | «Ο διακομιστής MITM δεν δέχεται συνδέσεις στη θύρα του. Ελέγξτε ότι η θύρα είναι ελεύθερη και ότι διαθέτετε δικαιώματα για τη δέσμευσή της.»                                                                                       |
| `cert-exists`      | Το πιστοποιητικό MITM έχει δημιουργηθεί στον δίσκο                                                         | «Δεν έχει δημιουργηθεί ακόμη πιστοποιητικό MITM. Δημιουργήστε ένα από την καρτέλα AgentBridge.»                                                                                                                                    |
| `cert-trusted`     | Η ριζική CA του MITM βρίσκεται στον χώρο αποθήκευσης αξιόπιστων πιστοποιητικών του λειτουργικού συστήματος | «Η ριζική CA του MITM δεν θεωρείται αξιόπιστη από τον χώρο αποθήκευσης του λειτουργικού συστήματος, επομένως η υποκλοπή TLS θα αποτύχει. Δηλώστε το πιστοποιητικό ως αξιόπιστο από την καρτέλα AgentBridge.»                       |
| `dns-configured`   | Τα ονόματα κεντρικών υπολογιστών-στόχων πλαστογραφούνται στο `/etc/hosts`                                  | «Τα ονόματα κεντρικών υπολογιστών-στόχων δεν πλαστογραφούνται στο /etc/hosts, επομένως η κίνηση δεν φτάνει ποτέ στον διακομιστή μεσολάβησης. Ενεργοποιήστε το DNS για τους πράκτορες των οποίων την κίνηση θέλετε να καταγράψετε.» |

**Πλαίσιο ορφανής κατάστασης:** όταν η σελίδα εντοπίζει κατάσταση που παρέμεινε μετά από κατάρρευση (πλαστογράφηση DNS / CA / διακομιστής μεσολάβησης συστήματος), η κάρτα εμφανίζει ένα πορτοκαλί πλαίσιο — _«Μια προηγούμενη συνεδρία άφησε πίσω της κατάσταση συστήματος (πλαστογράφηση DNS, CA ή διακομιστή μεσολάβησης συστήματος). Εκτελέστε την Επιδιόρθωση για να την καθαρίσετε.»_ — και επισημαίνει το κουμπί **Επιδιόρθωση**. Η `Repair` είναι το αντίστοιχο, σε επίπεδο εφαρμογής, της σημαίας `--cleanup` του ProxyBridge (αναθέτει την εργασία στη `repairMitm()` στο `src/mitm/manager.ts`).

> Η ριζική CA του MITM παραμένει εγκατεστημένη μεταξύ διακοπής και εκκίνησης, ώστε να αποφεύγονται
> επανειλημμένα αιτήματα sudo (η ίδια συμπεριφορά με τα mitmproxy/Charles), επομένως η αφαίρεσή της αποτελεί
> ρητή ενέργεια **Αφαίρεση CA** και όχι κάτι που συμβαίνει αυτόματα κατά τη διακοπή.

### 3.7 Εισαγωγή/εξαγωγή φορητών ρυθμίσεων

Το AgentBridge μπορεί να σειριοποιήσει την κατάσταση που είναι **ρυθμιζόμενη από τον χειριστή** σε ένα αντικείμενο JSON με έκδοση, ώστε μια διαμόρφωση να μπορεί να αναπαραχθεί σε διαφορετικά μηχανήματα. Ο σειριοποιητής είναι το `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`), με επικύρωση από το `AgentBridgeConfigSchema`.

Η εξαγωγή περιλαμβάνει ακριβώς τρία στοιχεία (οι ενσωματωμένες προεπιλογές **ΔΕΝ** εξάγονται σκόπιμα, ώστε η εισαγωγή να μην τις αντιγράφει ούτε να συγκρούεται μαζί τους):

| Πεδίο            | Προέλευση                                                                             | Σημειώσεις                                                                      |
| ---------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `bypassPatterns` | μοτίβα παράκαμψης που ορίζονται από τον χρήστη (`agent_bridge_bypass`)                | τα προεπιλεγμένα μοτίβα bank/gov/okta εξαιρούνται                               |
| `customHosts`    | προσαρμοσμένοι κεντρικοί υπολογιστές του Traffic Inspector (`inspector_custom_hosts`) | καθένας: `{ host, kind: "llm"\|"app"\|"custom", label? }`                       |
| `agentMappings`  | αντιστοιχίσεις μοντέλων ανά πράκτορα (`agent_bridge_mappings`)                        | `{ [agentId]: [{ source, target }] }` για κάθε πράκτορα που έχει αντιστοιχίσεις |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**Συμπεριφορά εισαγωγής** (`POST /api/tools/agent-bridge/config`): τα μοτίβα παράκαμψης και οι αντιστοιχίσεις ανά πράκτορα **αντικαθίστανται εξ ολοκλήρου**· οι προσαρμοσμένοι κεντρικοί υπολογιστές προστίθενται **ιδιοδύναμα** (`INSERT OR IGNORE`). Η απόκριση αναφέρει πόσα στοιχεία από κάθε κατηγορία εφαρμόστηκαν:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

Τι **ΔΕΝ** περιλαμβάνεται στη διαμόρφωση: η κατάσταση λειτουργίας του διακομιστή, οι διαδρομές των πιστοποιητικών, η κατάσταση DNS ανά agent, η διαδρομή της ανάντη αρχής πιστοποίησης (CA) και οι ρυθμίσεις TPROXY — αυτά αποτελούν κατάσταση του κεντρικού υπολογιστή/περιβάλλοντος εκτέλεσης και όχι φορητές προτιμήσεις.

### Βήματα οδηγού ρύθμισης (ανά agent)

Κάθε κάρτα agent διαθέτει έναν οδηγό ρύθμισης 3 βημάτων:

## §5 Ασφάλεια

### Εφαρμοζόμενοι αυστηροί κανόνες

| Κανόνας                           | Εφαρμογή                                                                                                           |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **#12** `sanitizeErrorMessage`    | Όλα τα σφάλματα των handlers εξυγιαίνονται πριν από την απόκριση ή την καταχώριση στο buffer                       |
| **#13** Μεταβίβαση env στο shell  | Οι τροποποιήσεις του `/etc/hosts` χρησιμοποιούν την επιλογή `env` — χωρίς παρεμβολή συμβολοσειρών στις διαδρομές   |
| **#15 + #17** `isLocalOnlyPath()` | Το `/api/tools/agent-bridge/` είναι LOCAL_ONLY + SPAWN_CAPABLE — επιβάλλεται loopback πριν από την αυθεντικοποίηση |

### Λίστα παράκαμψης για ευαίσθητα hosts

Η λίστα παράκαμψης διασφαλίζει ότι τα χρηματοπιστωτικά ιδρύματα, οι πάροχοι OAuth/SSO και άλλα ευαίσθητα hosts **δεν αποκρυπτογραφούνται ποτέ**. Η κίνηση TLS τους διέρχεται ως διαφανής σήραγγα TCP — το OmniRoute δεν βλέπει ποτέ το απλό κείμενο.

Τα προεπιλεγμένα μοτίβα παράκαμψης περιλαμβάνουν:

- `*.bank.*`, `*.gov.*` (χρηματοπιστωτικά/κυβερνητικά)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/ταυτότητα)
- `*.apple.com`, `*.icloud.com` (υπηρεσίες συστήματος Apple)

Τα μοτίβα παράκαμψης που προσθέτει ο χρήστης αποθηκεύονται στον πίνακα `agent_bridge_bypass` και υπερισχύουν όλων των άλλων.

### Απόκρυψη μυστικών

Εφαρμόζεται η `maskSecrets()` από το `src/mitm/maskSecrets.ts`:

- Σε κάθε σώμα αιτήματος πριν από την `TrafficBuffer.push()`
- Σε κάθε header πριν από την καταγραφή ή τη μετάδοση

Μοτίβα: tokens με πρόθεμα `sk-`/`ak-`/`pk-`, tokens `Bearer` και γενικά tokens ≥40 χαρακτήρων.

### Πιστοποιητικό CA ανάντη

Όταν έχει οριστεί το `AGENTBRIDGE_UPSTREAM_CA_CERT`, το αρχείο διαβάζεται κατά την εκκίνηση. Αν η διαδρομή υπάρχει αλλά το αρχείο δεν είναι αναγνώσιμο, το AgentBridge καταγράφει ένα σαφές σφάλμα και αρνείται να εκκινηθεί (αποτρέποντας σιωπηρές αποτυχίες TLS σε εταιρικά περιβάλλοντα).

### Γνωστοί περιορισμοί

- **Η θύρα 443 απαιτεί προνόμια**: Στο Linux, το AgentBridge χρειάζεται `setcap 'cap_net_bind_service=+ep'` στο εκτελέσιμο αρχείο Node ή πρέπει να εκτελεστεί μέσω `authbind`. Ο Οδηγός Ρύθμισης εμφανίζει οδηγίες ειδικές για το λειτουργικό σύστημα.
- **Απαιτείται επανεκκίνηση του IDE**: Μετά την ανακατεύθυνση DNS, το IDE πρέπει να επανεκκινηθεί ώστε να τεθεί σε ισχύ η νέα επίλυση host.
- **Ενσωματωμένα tokens OAuth**: Ορισμένοι agents (Kiro, Antigravity) αποθηκεύουν τοπικά tokens ανανέωσης OAuth. Αυτά είναι διαφανή για το AgentBridge — βλέπει το token `Bearer` σε κάθε αίτημα, το οποίο αποκρύπτεται πριν από την καταγραφή.
- **Τα frontends Electron χρειάζονται `NODE_EXTRA_CA_CERTS`**: Τα IDE των οποίων το frontend εκτελείται σε ενσωματωμένο runtime Node/Electron αγνοούν το trust store του λειτουργικού συστήματος/NSS και πρέπει να εκκινούνται από shell με ορισμένο το `NODE_EXTRA_CA_CERTS` (βλ. §3.2). Σύμπτωμα όταν λείπει: το backend του IDE αυθεντικοποιείται (το MITM εμφανίζει αποκρίσεις `200`), αλλά το UI παραμένει αποσυνδεδεμένο.
- **Οι πολλαπλές εγκαταστάσεις του ίδιου IDE είναι ανεξάρτητες**: μια εγκατάσταση συστήματος (π.χ. `/usr/share/antigravity/antigravity`) και μια τοπική εγκατάσταση χρήστη "Full" (π.χ. `~/AntigravityIDE_Full/antigravity-ide`) είναι ξεχωριστές διεργασίες με δικά τους runtimes — καθεμία πρέπει να επανεκκινηθεί με το CA ενσωματωμένο. Πριν από την επανεκκίνηση, προσδιορίστε ποια εκτελείται από τη διαδρομή του εκτελέσιμου αρχείου της.
- **Η ταυτότητα ορίζεται από το system prompt του agent και όχι από το δρομολογημένο μοντέλο**: όταν αντιστοιχίζετε εκ νέου το μοντέλο ενός agent σε διαφορετικό πάροχο, η απάντηση εξακολουθεί να δηλώνει την εγγενή ταυτότητα του agent (π.χ. το Antigravity απαντά «Υποστηρίζομαι από το Gemini»), επειδή το IDE την εισάγει στο system prompt. Επιβεβαιώστε το πραγματικό backend στα `call_logs` / `proxy_logs` (`provider`, `model`, `target_format`) και όχι ρωτώντας το μοντέλο ποιο είναι.

## §6 Αντιμετώπιση προβλημάτων

### Διένεξη στη θύρα 443

Εάν κάποια άλλη διεργασία ακούει ήδη στη θύρα 443 (διακομιστής ιστού, VPN κ.λπ.):

```bash
lsof -i :443          # εντοπισμός της διεργασίας
sudo fuser -k 443/tcp  # αναγκαστικός τερματισμός (χρησιμοποιήστε το με προσοχή)
```

Εναλλακτικά, διαμορφώστε μια μη προνομιακή θύρα στις ρυθμίσεις του AgentBridge και ορίστε κανόνες ανακατεύθυνσης `iptables` / `pf`.

### Μη αξιόπιστο πιστοποιητικό

Εάν το IDE εμφανίζει σφάλματα TLS μετά την εκκίνηση του AgentBridge:

1. Επαληθεύστε ότι το πιστοποιητικό εγκαταστάθηκε: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) ή `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. Ορισμένες εφαρμογές διατηρούν τη δική τους αποθήκη αξιόπιστων πιστοποιητικών (Firefox, Chrome σε Linux). Εκτελέστε ξανά το "Trust Cert" και ελέγξτε την αποθήκη πιστοποιητικών που αφορά ειδικά το NSS/Firefox.
3. Επανεκκινήστε το IDE μετά την προσθήκη του πιστοποιητικού ως αξιόπιστου — οι ενεργές συνεδρίες TLS χρησιμοποιούν την προηγούμενη κατάσταση αξιοπιστίας.

### Το IDE έχει αποσυνδεθεί / εμφανίζει "σφάλμα σύνδεσης" παρά την ύπαρξη αξιόπιστης CA

Σύμπτωμα: μετά την ανακατεύθυνση του DNS και την προσθήκη της CA ως αξιόπιστης, ένα IDE που βασίζεται στο Electron (π.χ. Antigravity)
ανοίγει **με αποσυνδεδεμένο χρήστη** ή εμφανίζει σφάλμα ελέγχου ταυτότητας/σύνδεσης, παρόλο που το αρχείο καταγραφής MITM δείχνει ότι οι
κλήσεις εκκίνησης (`loadCodeAssist`, `fetchAvailableModels`, …) επιστρέφουν `200`.

Αιτία: το **ενσωματωμένο περιβάλλον εκτέλεσης Node/Electron του IDE αγνοεί την αποθήκη αξιόπιστων πιστοποιητικών του λειτουργικού συστήματος**. Το εγγενές
backend (ένας διακομιστής γλώσσας Go) εμπιστεύεται την CA του λειτουργικού συστήματος και πραγματοποιεί έλεγχο ταυτότητας, αλλά το frontend του Electron
όχι — επομένως, το περιβάλλον εργασίας χρήστη θεωρεί ότι βρίσκεται εκτός σύνδεσης.

Λύση (και τα δύο βήματα): εξαγάγετε τη μεταβλητή `NODE_EXTRA_CA_CERTS=<ca.crt>` **και επανεκκινήστε το IDE από το συγκεκριμένο
κέλυφος**, όχι από το εικονίδιο της επιφάνειας εργασίας. Τερματίστε πρώτα πλήρως το IDE — το κλείδωμα μοναδικής παρουσίας του Electron σημαίνει
ότι μια δεύτερη εκκίνηση απλώς εστιάζει την υπάρχουσα διεργασία και το νέο περιβάλλον αγνοείται. Ανατρέξτε στην §3.2.
Αυτό αντικατοπτρίζει μια ανοικτή αναφορά σε έργο ανώτερου επιπέδου, στην οποία ένας αυτόνομος agent λειτουργεί μέσω MITM, αλλά η παραλλαγή
IDE αποτυγχάνει με την ίδια διαμόρφωση.

### Το DNS δεν έχει διαδοθεί

Ελέγξτε ότι το `/etc/hosts` ενημερώθηκε:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

Εκκαθαρίστε την προσωρινή μνήμη DNS:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### Το IDE δεν εντοπίστηκε

Ο αυτόματος εντοπισμός χρησιμοποιεί συνήθεις διαδρομές εγκατάστασης. Εάν ο εντοπισμός αποτύχει, αλλά το IDE είναι εγκατεστημένο:

- Ελέγξτε εάν το εκτελέσιμο αρχείο του IDE βρίσκεται σε μη τυπική τοποθεσία
- Ο Οδηγός εγκατάστασης εξακολουθεί να λειτουργεί — η αποτυχία εντοπισμού σημαίνει απλώς ότι το σήμα δεν θα εμφανίζει τη διαδρομή εγκατάστασης

### Σφάλματα χειριστή (αποτυχία ανάκτησης από το upstream)

Εάν το AgentBridge παρεμβάλλεται, αλλά όλα τα αιτήματα αποτυγχάνουν:

1. Επαληθεύστε ότι τουλάχιστον ένας πάροχος είναι συνδεδεμένος στη διαδρομή `/dashboard/providers`
2. Ελέγξτε τα αρχεία καταγραφής του διακομιστή OmniRoute: `APP_LOG_LEVEL=debug` στο `.env`
3. Επαληθεύστε ότι το `OMNIROUTE_BASE_URL` παραπέμπει στο σωστό endpoint του δρομολογητή (προεπιλογή: `http://127.0.0.1:20128`)

## §8 Οδικός χάρτης

### Διερεύνηση του Trae

Το Trae είναι ένας σχετικά νέος βοηθός προγραμματισμού με AI. Πριν από την υλοποίηση ενός handler:

1. Εντοπίστε το εκτελέσιμο αρχείο/την επέκταση στα marketplaces του VS Code / JetBrains ή ως αυτόνομη εφαρμογή
2. Καταγράψτε την κίνηση με το mitmproxy για να ανακαλύψετε τους κεντρικούς υπολογιστές API και τη δομή των endpoint
3. Προσδιορίστε τον μηχανισμό ελέγχου ταυτότητας
4. Αξιολογήστε αν θα προχωρήσει ή όχι, βάσει των TOS και της δυνατότητας ανακάλυψης του API

Μέχρι να ολοκληρωθεί η διερεύνηση, η κάρτα του Trae στον πίνακα ελέγχου εμφανίζει ένα σήμα "Υπό διερεύνηση" με έναν σύνδεσμο "Αναφορά βιωσιμότητας". Το προσχέδιο του handler στο `src/mitm/handlers/trae.ts` εμφανίζει ένα δομημένο σφάλμα `Δεν έχει υλοποιηθεί ακόμη`.

### Agents σε εκκρεμότητα (απαιτείται MITM — δεν υποστηρίζεται προσαρμοσμένο βασικό URL)

Τα ακόλουθα εργαλεία δεν υποστηρίζουν προσαρμοσμένα βασικά URL στις τρέχουσες εκδόσεις τους, καθιστώντας το MITM τη μοναδική οδό αναχαίτισης. Η αξιολόγηση βιωσιμότητας εκκρεμεί:

- **Windsurf** (Codeium/Cognition)
- **Amp** (Sourcegraph)
- **Amazon Q / Kiro CLI** (AWS Bedrock — ξεχωριστό από το Kiro IDE)
- **Cowork** (εφαρμογή επιφάνειας εργασίας της Anthropic)

Σημείωση: Το GitHub Copilot CLI ≥v1.0.19 υποστηρίζει το `COPILOT_PROVIDER_BASE_URL` — χρησιμοποιήστε άμεση διαμόρφωση αντί για MITM για αυτό το εργαλείο.
