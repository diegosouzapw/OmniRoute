Αυτός ο οδηγός καλύπτει την προσθήκη λογαριασμών Kiro (βοηθός προγραμματισμού AI που φιλοξενείται στο AWS) στο OmniRoute,
με έμφαση στην ταυτόχρονη λειτουργία πολλών λογαριασμών χωρίς διενέξεις συνεδριών.

---

## Υπόβαθρο: Γιατί μπορεί να προκύψουν διενέξεις μεταξύ λογαριασμών Kiro

Το backend του Kiro χρησιμοποιεί εγγραφές πελατών AWS SSO OIDC για την παρακολούθηση των ενεργών συνεδριών.
Ο κρίσιμος περιορισμός είναι ότι **κάθε εγγραφή πελάτη OIDC υποστηρίζει μόνο μία ενεργή
συνεδρία κάθε φορά**. Όταν μια δεύτερη συσκευή ή ένας δεύτερος χρήστης πραγματοποιεί έλεγχο ταυτότητας χρησιμοποιώντας τον ίδιο
εγγεγραμμένο πελάτη, το backend ακυρώνει το refresh token του πρώτου λογαριασμού.

Αυτός είναι ο ίδιος μηχανισμός που προκαλεί προβλήματα κατά την εκτέλεση του `kiro-cli login` σε ένα
μηχάνημα όπου είναι ήδη συνδεδεμένος ένας άλλος λογαριασμός Kiro — η νέα σύνδεση ανακαλεί το
token του πρώτου λογαριασμού.

---

## Πώς το επιλύει το OmniRoute (v3.8.0+)

Από την v3.8.0 και μετά, το OmniRoute καλεί τη `registerClient()` (AWS SSO OIDC) κατά τη διάρκεια κάθε
εισαγωγής σύνδεσης Kiro. Έτσι, κάθε σύνδεση OmniRoute αποκτά τη δική της αποκλειστική εγγραφή
πελάτη OIDC. Επειδή κάθε εγγραφή πελάτη είναι ανεξάρτητη, η ανανέωση ή ο εκ νέου
έλεγχος ταυτότητας ενός λογαριασμού δεν επηρεάζει το refresh token κανενός άλλου λογαριασμού.

Η απομόνωση εφαρμόζεται στις μεθόδους εισαγωγής refresh token, ενώ ο έλεγχος ταυτότητας μέσω API key αποφεύγει
πλήρως τις συνεδρίες ανανέωσης OIDC:

| Μέθοδος εισαγωγής                                         | Κατάσταση απομόνωσης                                                                                                                          |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Ροή device-code AWS Builder ID / IDC                      | Απομονωμένη από τότε που εισήχθη η ροή device-code                                                                                            |
| **Εισαγωγή Token** (χειροκίνητη επικόλληση refresh token) | Απομονωμένη από την v3.8.0                                                                                                                    |
| **Σύνδεση μέσω Google / GitHub**                          | Απομονωμένη από την v3.8.0                                                                                                                    |
| **Αυτόματη εισαγωγή** (SQLite του kiro-cli)               | Απομονωμένη από την v3.8.0 (η διαδρομή SQLite ήταν ήδη απομονωμένη· η εναλλακτική χρήση της κρυφής μνήμης SSO είναι πλέον επίσης απομονωμένη) |
| **API Key** (μακράς διάρκειας κλειδί CodeWhisperer)       | Δεν υπάρχει συνεδρία ανανέωσης· το κλειδί επικυρώνεται και αποθηκεύεται ως διαπιστευτήριο bearer                                              |

## Σημείωση μετεγκατάστασης για συνδέσεις που δημιουργήθηκαν πριν από την v3.8.0

Οι συνδέσεις που εισήχθησαν πριν από την v3.8.0 δεν διαθέτουν αποκλειστική εγγραφή πελάτη OIDC
αποθηκευμένη στο `providerSpecificData`. Αυτές οι συνδέσεις εξακολουθούν να λειτουργούν, αλλά χρησιμοποιούν το κοινόχρηστο
endpoint ανανέωσης κοινωνικής σύνδεσης, γεγονός που σημαίνει ότι δύο τέτοιες συνδέσεις μπορούν ακόμα να ακυρώσουν η μία
την άλλη.

**Για να αποκτήσετε απομόνωση:** διαγράψτε την παλιά σύνδεση από το **Πίνακας ελέγχου → Πάροχοι** και
εισαγάγετέ την ξανά χρησιμοποιώντας οποιαδήποτε από τις υποστηριζόμενες ροές εισαγωγής. Όλες οι συνδέσεις που δημιουργούνται εκ νέου θα
λαμβάνουν αυτόματα τη δική τους εγγραφή πελάτη.

## Προσθήκη δύο λογαριασμών Kiro παράλληλα

### Προαπαιτούμενα

- OmniRoute v3.8.0 ή νεότερη έκδοση.
- Ένας λειτουργικός λογαριασμός Kiro (email + κωδικός πρόσβασης ή σύνδεση μέσω Google ή GitHub).
- Προαιρετικά, ένας δεύτερος λογαριασμός Kiro.

### Βήμα 1: Εισαγωγή του πρώτου λογαριασμού

1. Ανοίξτε το **Πίνακας ελέγχου → Πάροχοι → Προσθήκη παρόχου → Kiro**.
2. Επιλέξτε ένα από τα εξής:
   - **Εισαγωγή Token** — επικολλήστε ένα refresh token που ξεκινά με `aorAAAAAG`.
   - **API Key** — επικολλήστε ένα μακράς διάρκειας API key του Kiro / CodeWhisperer.
   - **Σύνδεση μέσω Google / GitHub** — ολοκληρώστε τη ροή OAuth στο πρόγραμμα περιήγησης.
   - **Αυτόματη εισαγωγή** — κάντε κλικ στο κουμπί· το OmniRoute διαβάζει τα διαπιστευτήρια από την
     τοπική βάση δεδομένων του kiro-cli ή από το `~/.aws/sso/cache`.
3. Η σύνδεση αποθηκεύεται. Οι ροές refresh token καταχωρίζουν αυτόματα έναν αποκλειστικό
   πελάτη OIDC. Οι ροές API key επικυρώνουν το κλειδί μέσω AWS και δεν αποθηκεύουν refresh token.

### Βήμα 2: Εισαγωγή του δεύτερου λογαριασμού

Επαναλάβετε το βήμα 1 για τον δεύτερο λογαριασμό. Επειδή κάθε εισαγωγή δημιουργεί μια ξεχωριστή εγγραφή
πελάτη OIDC, οι δύο συνδέσεις είναι πλήρως απομονωμένες.

### Βήμα 3: Επαλήθευση ότι και οι δύο συνδέσεις είναι ενεργές

1. **Πίνακας ελέγχου → Πάροχοι** — και οι δύο συνδέσεις Kiro θα πρέπει να εμφανίζουν κατάσταση **Ενεργή**.
2. **Πίνακας ελέγχου → Υγεία** — και οι δύο συνδέσεις θα πρέπει να περνούν επιτυχώς τον έλεγχο υγείας των token τους.

### Βήμα 4: Χρήση ενός συνδυασμού για δρομολόγηση μεταξύ λογαριασμών

Δημιουργήστε έναν συνδυασμό με τις δύο συνδέσεις ως προορισμούς, για εξισορρόπηση φορτίου ή εναλλακτική δρομολόγηση μεταξύ τους:

```
kiro/kiro-dev → kiro/kiro-pro
```

Ανατρέξτε στο [FEATURES.md](./FEATURES.md) και στην τεκμηρίωση δρομολόγησης για τη διαμόρφωση συνδυασμών.

## Χρήστες Enterprise / IDC

Για λογαριασμούς AWS IAM Identity Center (IDC), χρησιμοποιήστε τη ροή **AWS Builder ID / κωδικού συσκευής IDC**
από το **Dashboard → Providers → Kiro → Device Code**. Η ροή κωδικού συσκευής ήταν
πάντα πλήρως απομονωμένη. Δεν απαιτείται εκ νέου εισαγωγή για αυτές τις συνδέσεις.

Οι χρήστες Enterprise που λειτουργούν σε μη προεπιλεγμένη περιοχή AWS μπορούν να καθορίσουν την περιοχή κατά
την εισαγωγή μέσω του Import Token API:

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/import \
  -H "Content-Type: application/json" \
  -d '{"refreshToken": "aorAAAAAG...", "region": "eu-west-1"}'
```

Το πεδίο `region` έχει ως προεπιλογή το `us-east-1` όταν παραλείπεται.

## Ροή εισαγωγής κλειδιού API

Ο έλεγχος ταυτότητας με κλειδί API προορίζεται για διαπιστευτήρια bearer μακράς διάρκειας του Kiro / AWS CodeWhisperer. Δεν
χρησιμοποιεί ανανέωση OAuth, οπότε αποφεύγει την ακύρωση κοινόχρηστων συνεδριών OIDC.

### Dashboard

1. Ανοίξτε το **Dashboard -> Providers -> Kiro**.
2. Επιλέξτε **API Key**.
3. Επικολλήστε το κλειδί API και, προαιρετικά, την περιοχή AWS (`us-east-1` από προεπιλογή).
4. Το OmniRoute επικυρώνει το κλειδί και αποθηκεύει τη σύνδεση.

### API

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/api-key \
  -H "Content-Type: application/json" \
  -d '{"apiKey": "kiro_or_codewhisperer_key", "region": "us-east-1"}'
```

### Εσωτερική σύμβαση

Η διαδρομή API επικυρώνει το κλειδί καλώντας τη `KiroService.validateApiKey()`, η οποία
χρησιμοποιεί το `ListAvailableProfiles` στο endpoint CodeWhisperer/Amazon Q που αντιστοιχεί στην περιοχή
και προσδιορίζει ένα `profileArn`.

Η αποθηκευμένη σύνδεση χρησιμοποιεί:

```json
{
  "authType": "apikey",
  "providerSpecificData": {
    "authMethod": "api_key",
    "region": "us-east-1",
    "profileArn": "arn:aws:codewhisperer:..."
  }
}
```

Κατά την εκτέλεση, η `KiroExecutor.buildHeaders()` στέλνει το κλειδί ως
`Authorization: Bearer <key>` και προσθέτει `tokentype: API_KEY`. Οι κλήσεις ορίου χρήσης/προφίλ
χρησιμοποιούν την ίδια ένδειξη, ώστε το AWS να αντιμετωπίζει το bearer ως κλειδί API μακράς διάρκειας και όχι
ως διακριτικό πρόσβασης OIDC ή κοινωνικής σύνδεσης.

## Λήξη προγράμματος-πελάτη OIDC

Τα δημόσια προγράμματα-πελάτες AWS SSO OIDC συνήθως λήγουν έπειτα από 90 ημέρες
(`clientSecretExpiresAt`). Το OmniRoute αποθηκεύει αυτή τη χρονική σήμανση στο `providerSpecificData`
για σκοπούς παρατηρησιμότητας. Εάν μια σύνδεση σταματήσει να ανανεώνεται έπειτα από περίπου 90 ημέρες, εισαγάγετε εκ νέου τη
σύνδεση για να αποκτήσετε μια νέα εγγραφή προγράμματος-πελάτη OIDC. Η αυτόματη εκ νέου εγγραφή κατά
τη λήξη παρακολουθείται ως μελλοντική βελτίωση.

Οι συνδέσεις με κλειδί API δεν έχουν λήξη προγράμματος-πελάτη OIDC, επειδή δεν ανανεώνονται
μέσω AWS SSO OIDC.

## Αντιμετώπιση προβλημάτων

### Ο δεύτερος λογαριασμός συνεχίζει να αποσυνδέεται

- Ελέγξτε και τις δύο συνδέσεις στο **Dashboard → Providers** και επιβεβαιώστε ότι καθεμία εμφανίζει μη μηδενικό
  `clientId` στο ανεπεξέργαστο JSON της (ορατό μέσω του εικονιδίου πληροφοριών). Εάν λείπει το
  `clientId` από οποιαδήποτε σύνδεση, αυτή εισήχθη πριν από την v3.8.0 — εισαγάγετέ την εκ νέου.

### Η εισαγωγή αποτυγχάνει με το μήνυμα "Η επικύρωση διακριτικού απέτυχε"

- Βεβαιωθείτε ότι το διακριτικό ανανέωσης ξεκινά με `aorAAAAAG`.
- Βεβαιωθείτε ότι το OmniRoute μπορεί να συνδεθεί στο `https://oidc.us-east-1.amazonaws.com` (ή στη διαμορφωμένη
  περιοχή). Εάν βρίσκεστε πίσω από εταιρικό διακομιστή μεσολάβησης, ορίστε έναν διακομιστή μεσολάβησης σε επίπεδο παρόχου στο
  **Dashboard → Settings → Proxies**.

### Η εισαγωγή κλειδιού API αποτυγχάνει

- Επιβεβαιώστε ότι το κλειδί είναι κλειδί API του Kiro / CodeWhisperer και όχι διακριτικό ανανέωσης.
- Επιβεβαιώστε ότι η περιοχή AWS αντιστοιχεί στο κλειδί/στον λογαριασμό. Η προεπιλογή είναι `us-east-1`.
- Το κλειδί πρέπει να μπορεί να καλεί το `ListAvailableProfiles`· διαφορετικά, το OmniRoute δεν μπορεί
  να προσδιορίσει το απαιτούμενο `profileArn`.

Για άλλα προβλήματα, ανατρέξτε στο κύριο αρχείο [TROUBLESHOOTING.md](./TROUBLESHOOTING.md).
