Πλήρης οδηγός για τη χρήση του Codex CLI με το OmniRoute ως συμβατό με το OpenAI backend.

> **Το TOML είναι η μόνη αποτελεσματική μορφή.** Οι σύγχρονες εκδόσεις του Codex διαβάζουν
> αποκλειστικά το `~/.codex/config.toml` (επαληθεύτηκε με το codex-cli 0.147.0: το `codex --help`
> τεκμηριώνει ότι οι παρακάμψεις `-c/--config` «φορτώνονται από το
> `~/.codex/config.toml`»). Το παλιό `~/.codex/config.yaml` ανήκε στο παρωχημένο npm CLI
> και αγνοείται χωρίς προειδοποίηση. Η γεννήτρια του dashboard (`/api/cli-tools/apply`,
> εργαλείο `codex`) γράφει TOML με συντηρητική συγχώνευση — τα υπάρχοντα κλειδιά και τα
> blocks άλλων παρόχων διατηρούνται, το κλειδί API παραμένει στο `OMNIROUTE_API_KEY`
> (ποτέ μέσα στο αρχείο), ενώ τυχόν παλιό `config.yaml` αναφέρεται ως σημείωση
> μετεγκατάστασης χωρίς να τροποποιείται.

## Έτοιμο για επικόλληση config.toml

Αντικαταστήστε τα `<YOUR_HOST>` και `<YOUR_KEY>` με τις δικές σας τιμές:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # όριο αποθήκευσης ιστορικού ανά κλήση εργαλείου

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc ή ~/.zshrc — πραγματική τιμή κλειδιού, ποτέ στο config.toml
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: Το Codex ενσωματωμένο στην εφαρμογή ChatGPT

Αν εγκαταστήσατε το Codex μέσω της εφαρμογής ChatGPT για υπολογιστές, το εκτελέσιμο
`codex` ενδέχεται να υπάρχει μόνο μέσα στο πακέτο της εφαρμογής και να μην βρίσκεται
ακόμα στο `PATH` του κελύφους σας. Προσθέστε τον κατάλογο πόρων στο αρχείο εκκίνησης
του κελύφους σας:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

Ανοίξτε ένα νέο κέλυφος και, στη συνέχεια, επαληθεύστε:

```bash
command -v codex
codex --version
```

### Τοπικό OmniRoute χωρίς έλεγχο ταυτότητας: αρκεί ένα προσωρινό κλειδί

Το Codex επαληθεύει ότι υπάρχει η μεταβλητή περιβάλλοντος που καθορίζεται από το
`env_key` **πριν** το πρώτο αίτημα εξέλθει από το CLI. Αν η **τοπική** εγκατάσταση
του OmniRoute δεν απαιτεί έλεγχο ταυτότητας, αρκεί οποιαδήποτε μη κενή προσωρινή τιμή:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

Χρησιμοποιήστε πραγματικό κλειδί αν ο OmniRoute server σας είναι προστατευμένος ή απομακρυσμένος.

> **Συνήθεις επιλογές host**
>
> | Πρόσβαση      | URL                           |
> | ------------- | ----------------------------- |
> | Τοπικό δίκτυο | `http://192.168.0.1:20128/v1` |
> | Tailscale     | `http://100.x.x.x:20128/v1`   |
> | Loopback      | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — γιατί λειτουργεί για όλα τα μοντέλα

Το Codex CLI κατάργησε το `wire_api = "chat"` (Chat Completions) τον Φεβρουάριο του 2026 και πλέον **απαιτεί** `wire_api = "responses"` (OpenAI Responses API). Η ρύθμιση `wire_api = "chat"` προκαλεί άμεση κατάρρευση κατά την εκκίνηση από την έκδοση v0.138 και μετά.

Πολλοί πάροχοι, συμπεριλαμβανομένων των GLM και Kimi, εξακολουθούν να παρέχουν μόνο endpoint Chat Completions. Το DeepSeek V4 παρέχει πλέον εγγενές Responses API καθώς και endpoint συμβατό με το Anthropic· το OmniRoute χρησιμοποιεί το Responses από προεπιλογή και επιτρέπει σε κάθε σύνδεση DeepSeek να επιλέγει συμβατότητα με το Anthropic.

**Το OmniRoute επιλύει αυτό το ζήτημα με διαφανή τρόπο:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → Το OmniRoute επιλέγει το εγγενές πρωτόκολλο του παρόχου και πραγματοποιεί μετάφραση όταν χρειάζεται
    → POST /responses (DeepSeek V4) ή /chat/completions (Mistral / GLM / Kimi / άλλα)
```

Δεν χρειάζεστε ποτέ ξεχωριστό proxy μετάφρασης όταν χρησιμοποιείτε το OmniRoute. **Όλα τα μοντέλα χρησιμοποιούν `wire_api = "responses"`** — το OmniRoute αναλαμβάνει τα υπόλοιπα.

> **Το `wire_api` είναι η προεπιλογή** — το πεδίο έχει ως προεπιλεγμένη τιμή το `"responses"` και μπορεί να παραλειφθεί εντελώς από το `config.toml`. Ορίστε το ρητά μόνο αν θέλετε να τεκμηριώσετε την πρόθεση.

## Παράθυρο συμφραζομένων και συμπύκνωση

### Πεδία ρύθμισης token

| Πεδίο                            | Περιγραφή                                                                                                                                                                                                           |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model_context_window`           | Συνολικό όριο token για το ενεργό μοντέλο. Ορίστε το στο δημοσιευμένο όριο του μοντέλου.                                                                                                                            |
| `model_auto_compact_token_limit` | Κατώφλι που ενεργοποιεί την αυτόματη συμπύκνωση του ιστορικού. **Μέγιστο: 90% του `model_context_window`** — τιμές άνω του 90% αγνοούνται σιωπηρά.                                                                  |
| `tool_output_token_limit`        | Όριο στα token που αποθηκεύονται ανά έξοδο κλήσης εργαλείου στο ιστορικό. Αποτρέπει την πλήρωση του παραθύρου από μία μεγάλη απόκριση εργαλείου. **Δεν είναι η μέγιστη έξοδος** — είναι όριο αποθήκευσης ιστορικού. |
| `compact_prompt`                 | Ενσωματωμένη παράκαμψη της προτροπής συστήματος που χρησιμοποιείται κατά τη συμπύκνωση (v0.138+).                                                                                                                   |

> **Σημείωση για το `model_max_output_tokens`**: Αυτό το πεδίο **δεν αποτελεί μέρος του σχήματος ρύθμισης του Codex CLI** (απουσιάζει από τη βάση κώδικα Rust του Codex). Αν οριστεί, αγνοείται σιωπηρά. Μην βασίζεστε σε αυτό — χρησιμοποιήστε το `tool_output_token_limit` για να ελέγξετε πόση έξοδος εργαλείων αποθηκεύεται στο ιστορικό.

## Ένταση συλλογισμού

Ελέγχει πόσο «σκέφτεται» το μοντέλο πριν απαντήσει.

| Τιμή     | Χρήση για                                             |
| -------- | ----------------------------------------------------- |
| `none`   | Χωρίς συλλογισμό — άμεση απάντηση                     |
| `low`    | Απλές εργασίες (μετονομασία, μορφοποίηση)             |
| `medium` | **Προεπιλογή διακομιστή** όταν δεν καθορίζεται        |
| `high`   | Εργασίες μέτριας δυσκολίας (αναδόμηση, αποσφαλμάτωση) |
| `xhigh`  | Αρχιτεκτονική, εις βάθος ανάλυση, σύνθετα προβλήματα  |

```bash
# Παράκαμψη ανά εκτέλεση
codex -c model_reasoning_effort=low "rename variable x to count"
codex -c model_reasoning_effort=xhigh "design the auth module"
```

Ορίστε επίσης μια **σύνοψη** συλλογισμού, ώστε το Desktop να μπορεί να εμφανίζει το κείμενο σκέψης (και όχι μόνο κρυπτογραφημένα τμήματα):

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # ή ultra όταν υποστηρίζεται
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### Προϋπολογισμός σκέψης OmniRoute (ρύθμιση διακομιστή)

Στον κεντρικό υπολογιστή του OmniRoute, η επιλογή **Settings → AI → Thinking Budget** πρέπει να είναι **`passthrough`**, ώστε η ένταση/σύνοψη του Codex να προωθείται στον ανάντη πάροχο. Η λειτουργία **`auto` αφαιρεί** όλα τα πεδία `reasoning` / `reasoning_effort` του πελάτη και αφήνει κενά τα πλαίσια σκέψης, ακόμη και όταν το Codex έχει διαμορφωθεί σωστά.

Πλήρης οδηγός: [THINKING_BUDGET.md](./THINKING_BUDGET.md).

Η συμπίεση και η κρυφή μνήμη προτροπών είναι ανεξάρτητες και συνεχίζουν να λειτουργούν με το `passthrough`.

## Προφίλ — ονομασμένες διαμορφώσεις ανά μοντέλο/ροή εργασίας

Τα προφίλ σάς επιτρέπουν να αλλάζετε μοντέλο + παράθυρο περιβάλλοντος με μία μόνο σημαία. Κάθε προφίλ είναι ένα επίπεδο αρχείο
`~/.codex/<name>.config.toml` που εφαρμόζεται πάνω από το βασικό `config.toml`.

> **Κανόνας ονοματοδοσίας (Codex CLI v0.137+):** το αρχείο πρέπει να είναι `~/.codex/<name>.config.toml` — **χωρίς πρόθεμα `profile-`**.
> Το CLI αντιστοιχίζει το `-p kimi-k27` → `~/.codex/kimi-k27.config.toml`. Εάν το αρχείο δεν βρεθεί, εφαρμόζεται σιωπηρά η προεπιλογή.

```bash
codex --profile kimi-k27 "analyze 10k lines of this codebase"
codex -p glm52 "architecture review"
codex --profile deepseek-flash "rename variable"   # γρήγορο, οικονομικό
```

### Προφίλ έντασης (ίδιο μοντέλο, διαφορετική ένταση)

```bash
codex -p low      # cx/gpt-5.5, ένταση=low
codex -p medium   # cx/gpt-5.5, ένταση=medium
codex -p high     # cx/gpt-5.5, ένταση=high
codex -p xhigh    # cx/gpt-5.5, ένταση=xhigh (προεπιλογή)
codex -p chat     # cx/gpt-5.5, χωρίς καθορισμένη ένταση (προεπιλογή διακομιστή)
```

## Αυτόματη δημιουργία προφίλ με το `omniroute setup-codex`

Αν εκτελείτε το OmniRoute σε VPS, μπορείτε να δημιουργήσετε αυτόματα αρχεία προφίλ από τον ενεργό κατάλογο μοντέλων:

```bash
# Από VPS (χρησιμοποιεί το τοπικό OmniRoute στη θύρα 20128)
omniroute setup-codex

# Από οποιοδήποτε μηχάνημα — υποδείξτε το VPS σας
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# Προεπισκόπηση χωρίς εγγραφή αρχείων
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# Δημιουργία μόνο των προφίλ GLM και Kimi
omniroute setup-codex --only glm,kimi

# Εγγραφή σε προσαρμοσμένο κατάλογο
omniroute setup-codex --codex-home /path/to/.codex
```

Η εντολή ανακτά το `/v1/models`, χρησιμοποιεί βελτιστοποιημένα προφίλ για γνωστά μοντέλα, καταφεύγει στα μεταδεδομένα του καταλόγου για άλλα συμβατά μοντέλα κειμένου και δημιουργεί το `~/.codex/<name>.config.toml` για καθένα από αυτά. Είναι ιδιοδύναμη — μπορεί να εκτελεστεί ξανά με ασφάλεια.

Το OmniRoute μπορεί επίσης να **συγχρονίζει αυτόματα** τα ίδια αρχεία προφίλ αφού μια επιτυχής ανακάλυψη/εισαγωγή μοντέλων παρόχου τροποποιήσει τον ενεργό κατάλογο. Αυτή η δυνατότητα είναι **προαιρετική και απενεργοποιημένη από προεπιλογή**: ενεργοποιήστε την από τον πίνακα εργαλείων **CLI Code** ("Αυτόματος συγχρονισμός προφίλ CLI" → Codex) ή ορίστε `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` (λαμβάνει επίσης υπόψη το `CLI_ALLOW_CONFIG_WRITES`, το οποίο είναι ενεργοποιημένο από προεπιλογή). Όταν είναι ενεργοποιημένη, δημιουργεί μόνο ξεχωριστά αρχεία προφίλ `~/.codex/*.config.toml`· δεν αλλάζει ποτέ το ενεργό/προεπιλεγμένο `~/.codex/config.toml`, τις ρυθμίσεις του Codex-lb, τον έλεγχο ταυτότητας ή την επιλογή παρόχου.

## Εργασίες μεγάλης διάρκειας

Δύο προεπιλογές του OmniRoute μπορούν να υπονομεύσουν αθόρυβα συνεδρίες Codex CLI που διαρκούν πολλές ώρες. Καμία από τις δύο δεν αποτελεί ρύθμιση του Codex CLI — και οι δύο βρίσκονται στην πλευρά του OmniRoute. Οι χρήστες που μεταφέρουν μια διαμόρφωση από διακομιστές μεσολάβησης ανώτερου επιπέδου, οι οποίοι δεσμεύουν λογαριασμούς και απενεργοποιούν τα όρια αδράνειας, συχνά αντιμετωπίζουν και τα δύο προβλήματα και καταλήγουν στο συμπέρασμα ότι το OmniRoute «δεν μπορεί να διατηρήσει μια συνεδρία μεγάλης διάρκειας».

| Σύμπτωμα                                                                                               | Πιθανή αιτία                                                                                  | Ρύθμιση                  |
| ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- | ------------------------ |
| Η συνεδρία αλλάζει συνεχώς λογαριασμούς / η συνέχεια της προσωρινής μνήμης prompt χάνεται μεταξύ γύρων | Το TTL συνάφειας συνεδρίας είναι `0` (απενεργοποιημένο)                                       | `sessionAffinityTtlMs`   |
| Η σύνδεση διακόπτεται κατά τη διάρκεια του συλλογισμού χωρίς μήνυμα προς τον πελάτη                    | Ο επόπτης αδράνειας ροής ενεργοποιήθηκε μετά από 10 λεπτά χωρίς τμήμα από την ανάντη υπηρεσία | `STREAM_IDLE_TIMEOUT_MS` |

Σχετικές συζητήσεις: [#7126](https://github.com/diegosouzapw/OmniRoute/discussions/7126) (διακοπές εργασιών μεγάλης διάρκειας), [#5718](https://github.com/diegosouzapw/OmniRoute/discussions/5718) (γιατί η συνάφεια είναι απενεργοποιημένη από προεπιλογή). Παρακολούθηση: [#7287](https://github.com/diegosouzapw/OmniRoute/issues/7287).

### 1. Συνάφεια συνεδρίας — δέσμευση μίας συνομιλίας σε έναν λογαριασμό

**Προεπιλογή:** `sessionAffinityTtlMs = 0` (απενεργοποιημένο).

**Πού να τη ρυθμίσετε**

- Πίνακας ελέγχου → **Ρυθμίσεις → Δρομολόγηση** → **Συνάφεια συνεδρίας** → **TTL συνάφειας (δευτερόλεπτα)** (`ComboDefaultsTab`)
- Εναλλακτικά, ενημερώστε τις ρυθμίσεις με PATCH χρησιμοποιώντας το `sessionAffinityTtlMs` σε **χιλιοστά του δευτερολέπτου** (εύρος Zod `0`–`86_400_000`, δηλαδή έως 24 ώρες)

> Μετονομάστηκε στο #7274 από το ειδικό για το Codex `codexSessionAffinityTtlMs`. Το παλαιό κλειδί εξακολουθεί να γίνεται αποδεκτό ως ψευδώνυμο μόνο για ανάγνωση· οι νέες διαμορφώσεις θα πρέπει να χρησιμοποιούν το `sessionAffinityTtlMs`. Η συνάφεια εφαρμόζεται πλέον σε **οποιονδήποτε** πάροχο όταν το TTL είναι μεγαλύτερο από `0`, όχι μόνο στο Codex — δείτε το [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → Συνάφεια συνεδρίας.

**Τι παύει να λειτουργεί όταν παραμένει στο 0**

Κάθε γύρος μιας συνομιλίας Codex πολλαπλών γύρων δρομολογείται ανεξάρτητα βάσει της ενεργής συνδυαστικής στρατηγικής και μπορεί να καταλήξει σε **διαφορετικό λογαριασμό ανά γύρο**. Αυτό διακόπτει τη συνέχεια της ανάντη συνεδρίας / προσωρινής μνήμης prompt. Το OmniRoute εξετάζει τις κεφαλίδες συνεδρίας Codex (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) και πεδία σώματος όπως τα `prompt_cache_key` / `session_id` μόνο όταν το TTL είναι μεγαλύτερο από `0` (`extractSessionAffinityKey` στο `src/sse/services/auth.ts`).

**Σύσταση για μία εργασία διάρκειας πολλών ωρών**

Ορίστε το TTL **πάνω από την αναμενόμενη πραγματική χρονική διάρκεια της εργασίας** (το μέγιστο στο περιβάλλον χρήστη είναι **86400 δευτερόλεπτα** = 24 ώρες):

| Αναμενόμενη διάρκεια εργασίας          | TTL συνάφειας (περιβάλλον χρήστη, δευτερόλεπτα) | `sessionAffinityTtlMs` |
| -------------------------------------- | ----------------------------------------------- | ---------------------- |
| Μερικές ώρες                           | `14400` (4 ώρες)                                | `14400000`             |
| Κατά τη διάρκεια της νύχτας / ~12 ώρες | `43200` (12 ώρες)                               | `43200000`             |
| Πλήρης ημέρα                           | `86400` (24 ώρες, μέγιστο)                      | `86400000`             |

Η ρητή ενεργοποίηση είναι σκόπιμη: η απενεργοποίηση της συνάφειας ευνοεί την εξισορρόπηση φορτίου μεταξύ λογαριασμών, ενώ η ενεργοποίησή της ευνοεί τη συνέχεια μιας μακράς συνεδρίας πράκτορα. Αυτός ο οδηγός **δεν** αλλάζει την προεπιλογή — οι διαχειριστές που εκτελούν εργασίες Codex μεγάλης διάρκειας πρέπει να την ενεργοποιήσουν ρητά.

### 2. Χρονικό όριο αδράνειας ροής — μην τερματίζετε αθόρυβους γύρους συλλογισμού

**Προεπιλογή:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 λεπτά). Κληρονομεί την τιμή από το `REQUEST_TIMEOUT_MS` όταν δεν έχει οριστεί· η κοινή βασική τιμή είναι επίσης 600000. Δείτε το [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → Χρονικά όρια.

**Τι παύει να λειτουργεί με την προεπιλογή**

Ένα turn συλλογισμού / εργαλείου του Codex που παραμένει σιωπηλό για περισσότερα από 10 λεπτά χωρίς **κανένα πραγματικό upstream chunk** τερματίζεται αναγκαστικά από το SSE idle watchdog (`open-sse/utils/stream.ts`). Ο client συχνά βλέπει απλώς τη σύνδεση να διακόπτεται — κάτι που ταιριάζει με το «σταμάτησε αυτόματα χωρίς καμία ειδοποίηση».

Κρίσιμη λεπτομέρεια: Το συνθετικό SSE **heartbeat του OmniRoute δεν επαναφέρει** το ρολόι αδράνειας. Μόνο ένα πραγματικό upstream body chunk ενημερώνει το `lastChunkTime`. Ένα μοντέλο που παραμένει ήσυχο ενώ εξακολουθεί να «σκέφτεται» φαίνεται πανομοιότυπο με ένα κολλημένο upstream από την οπτική του watchdog.

Σχετική αδράνεια body του Undici: `FETCH_BODY_TIMEOUT_MS` (από προεπιλογή χρησιμοποιεί επίσης την ίδια βασική τιμή των 10 λεπτών· η τιμή `0` την απενεργοποιεί). Για streaming, το `FETCH_TIMEOUT_MS` καλύπτει μόνο τη δημιουργία της σύνδεσης / τα πρώτα headers — μόλις ενεργοποιηθεί το stream, οι καθυστερήσεις διέπονται από τα `STREAM_IDLE_TIMEOUT_MS` και `FETCH_BODY_TIMEOUT_MS`.

**Συνιστώμενη ρύθμιση για μία εργασία πολλών ωρών**

Στο περιβάλλον διεργασίας του OmniRoute (`.env` / compose / systemd):

```bash
# Απενεργοποίηση των ορίων αδράνειας stream + body για μεγάλα turn συλλογισμού
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

Εναλλακτικά, αυξήστε τα πάνω από το μεγαλύτερο διάστημα σιωπής που αναμένετε (οι τιμές είναι σε χιλιοστά του δευτερολέπτου):

```bash
# Παράδειγμα: να επιτρέπονται έως και 2 ώρες σιωπής μεταξύ upstream chunks
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

Επανεκκινήστε το OmniRoute αφού αλλάξετε αυτές τις μεταβλητές περιβάλλοντος.

### Συγκεκριμένη διαδικασία — εργασία Codex πολλών ωρών

1. **Καρφιτσώστε τον λογαριασμό:** Dashboard → Settings → Routing → Session affinity → Affinity TTL = `43200` (12 ώρες) ή `86400` (μέγιστο 24 ώρες).
2. **Αυξήστε / απενεργοποιήστε τα όρια αδράνειας** στο περιβάλλον του OmniRoute:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. Διατηρήστε το συνηθισμένο `config.toml` του Codex (`wire_api = "responses"`, σωστό `base_url`, `OMNIROUTE_API_KEY`) — δεν υπάρχουν ρυθμίσεις affinity/αδράνειας στην πλευρά του Codex για αυτές τις δύο συμπεριφορές.
4. Επανεκκινήστε το OmniRoute και, στη συνέχεια, ξεκινήστε τη μεγάλη εργασία Codex.

| Ρύθμιση                  | Προεπιλογή έκδοσης  | Αλλαγή σε αυτόν τον οδηγό;                                                                                                 |
| ------------------------ | ------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (ανενεργό)      | **Όχι** — παραμένει προαιρετικό (εξισορρόπηση φορτίου έναντι συνέχειας· βλ. Discussion #5718)                              |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 λεπτά) | **Όχι** — παραμένει στα 10 λεπτά για γενική κίνηση· οι διαχειριστές μεγάλων εργασιών Codex το αυξάνουν ή το απενεργοποιούν |

Η καθολική αλλαγή οποιασδήποτε από τις δύο προεπιλογές θα άλλαζε τη συμπεριφορά για κάθε client ενός instance, όχι μόνο για το Codex. Τεκμηριώστε τις ρυθμίσεις· αφήστε τις προεπιλογές ως έχουν μέχρι μια ρητή απόφαση του διαχειριστή να ορίσει διαφορετικά.

### Διάγνωση τερματισμών λόγω αδράνειας

Όταν ενεργοποιείται το idle watchdog, το OmniRoute καταγράφει μια γραμμή με την εξής μορφή:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

Κάντε grep για `Idle timeout: no data from` (ή για τον κωδικό `stream_idle_timeout` / το όνομα σφάλματος `StreamIdleTimeoutError`). Το τμήμα provider είναι ό,τι χρησιμοποίησε το OmniRoute για το συγκεκριμένο αίτημα (`codex`, άλλο provider id ή `provider` αν είναι άγνωστο) — δεν είναι πάντα η κυριολεκτική συμβολοσειρά `codex`.

## Αντιμετώπιση προβλημάτων

**`Error: wire_api = "chat" is no longer supported`**
Καταργήστε το `wire_api = "chat"` από τη διαμόρφωσή σας. Ορίστε `wire_api = "responses"` ή παραλείψτε το πεδίο (η προεπιλογή είναι `"responses"` από την v0.138).

**`Error: model not found`**
Επαληθεύστε ότι το μοντέλο υπάρχει στο OmniRoute με το σωστό πρόθεμα. Χρησιμοποιήστε `omniroute models list` ή ανοίξτε το `/dashboard/providers/<provider>`.

**`Authentication error`**
Επιβεβαιώστε ότι έχει εξαχθεί η `OMNIROUTE_API_KEY`: `echo $OMNIROUTE_API_KEY`.

**`ERROR: Missing environment variable: OMNIROUTE_API_KEY`**
Το Codex επαληθεύει ότι η μεταβλητή περιβάλλοντος υπάρχει πριν υποβάλει το πρώτο αίτημα. Εξαγάγετε
ένα πραγματικό κλειδί για προστατευμένους διακομιστές ή μια μη κενή ενδεικτική τιμή, όπως
`OMNIROUTE_API_KEY=local`, όταν η **τοπική** σας εγκατάσταση OmniRoute δεν
απαιτεί έλεγχο ταυτότητας. Επανεκκινήστε το κέλυφος αν την προσθέσατε στο `~/.bashrc` ή στο `~/.zshrc`.

**`Connection refused`**
Επαληθεύστε ότι το OmniRoute εκτελείται και ότι ο κεντρικός υπολογιστής/η θύρα του `base_url` είναι σωστά για το δίκτυό σας (τοπικό έναντι Tailscale έναντι VPS).

**Η συνεδρία τερματίζεται απροσδόκητα κοντά στο όριο περιβάλλοντος**
Ορίστε ρητά τα `model_context_window` και `model_auto_compact_token_limit`. Ανατρέξτε στον παραπάνω πίνακα παραθύρων περιβάλλοντος.

**Η συμπύκνωση ενεργοποιείται πολύ αργά**
Μειώστε το `model_auto_compact_token_limit` στο 80–85% του παραθύρου. Μην το ορίζετε ποτέ πάνω από 90%.

**Το προφίλ δεν φορτώνεται (το `-p <name>` αγνοείται χωρίς μήνυμα)**
Επιβεβαιώστε ότι το αρχείο υπάρχει στη διαδρομή `~/.codex/<name>.config.toml` (χωρίς πρόθεμα `profile-`). Εκτελέστε `ls ~/.codex/*.config.toml`.

**Μια εργασία Codex μεγάλης διάρκειας διακόπτεται κατά την εκτέλεση / αλλάζει λογαριασμούς μεταξύ διαδοχικών αιτημάτων**
Ανατρέξτε στην ενότητα [Εργασίες μεγάλης διάρκειας](#long-running-tasks). Ενεργοποιήστε τη συσχέτιση συνεδρίας (TTL μεγαλύτερο από τη διάρκεια της εργασίας) και αυξήστε ή απενεργοποιήστε τα `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS`. Αναζητήστε στα αρχεία καταγραφής του OmniRoute το `Idle timeout: no data from`.
