Το OmniRoute παρέχει **δύο** τρόπους χρήσης του OpenAI Codex:

| Πάροχος                | Πώς επικοινωνεί με το OpenAI                                                                                                                                                                                          | Επισήμανση χρήσης                                                                  |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| **`codex`**            | Αναμεταδίδει το διακριτικό OAuth του ChatGPT/OpenAI απευθείας στο Responses API                                                                                                                                       | **Ναι** — η επίσημη συνεδρία δεν είναι εξουσιοδοτημένη για χρήση μέσω proxy/router |
| **`codex-app-server`** | Χειρίζεται το **ίδιο το `codex app-server` του Codex CLI** μέσω JSON-RPC/WebSocket· το CLI διαχειρίζεται και ανανεώνει αυτόματα το OAuth του (`~/.codex/auth.json`), ακριβώς όπως σε μια διαδραστική συνεδρία `codex` | **Όχι** — το OmniRoute δεν αναμεταδίδει ποτέ διακριτικό στο API                    |

Επειδή το `codex-app-server` δεν αναμεταδίδει ποτέ διακριτικό, δεν υπόκειται στην
επισήμανση χρήσης περί αναμετάδοσης συνεδρίας. Απαιτεί, ωστόσο, ένα **Codex CLI
προσβάσιμο στη διαμορφωμένη διεύθυνση URL του app-server**, και αυτό το CLI πρέπει
να είναι **συνδεδεμένο**.

## 1. Αρχιτεκτονική

```
┌─ Εφαρμογή OmniRoute ─────────────┐        ┌─ Sidecar codex-app-server ──────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ διακριτικό δυνατότητας)       │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  αυτοδιαχειρίζεται το OpenAI OAuth  │
└──────────────────────────────────┘        │  (~/.codex/auth.json, αυτόματη      │
        │ κοινή χρήση (τόμοι compose)        │   ανανέωση)                          │
        ▼                                    └─────────────────────────────────────┘
  codex-appserver-token   → το διακριτικό δυνατότητας WS (προσαρτάται και στα δύο)
  codex-appserver-home    → ~/.codex (το auth.json γράφεται από τον πίνακα ελέγχου
                             και διαβάζεται από το codex app-server του sidecar)
```

- Το sidecar ακούει **μόνο** στο εσωτερικό δίκτυο compose
  (`ws://codex-app-server:1456`), πίσω από ένα διακριτικό δυνατότητας. **Δεν**
  δημοσιεύεται ποτέ στον κεντρικό υπολογιστή ή στο διαδίκτυο.
- Το Codex CLI είναι ενσωματωμένο στο `omniroute:base`, επομένως δεν απαιτείται
  εγκατάσταση του codex στον κεντρικό υπολογιστή ή στο μηχάνημα του χρήστη όταν
  εκτελείτε το sidecar.

## 2. Εκκίνηση

```bash
# Εκκινήστε τη στοίβα ΜΕ το προφίλ sidecar του codex app-server:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

Το sidecar δημιουργεί το διακριτικό δυνατότητας WS κατά την πρώτη εκκίνηση (στον
κοινόχρηστο τόμο `codex-appserver-token`) και η εφαρμογή διαβάζει το ίδιο διακριτικό
μέσω του `OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE`. Δεν απαιτείται χειροκίνητη
ρύθμιση του διακριτικού.

## 3. Σύνδεση + είσοδος

1. Στον πίνακα ελέγχου, προσθέστε μια σύνδεση για το **OpenAI Codex
   (App-Server)**. Δεν απαιτείται κλειδί API ή διακριτικό (είναι πάροχος χωρίς
   έλεγχο ταυτότητας — το sidecar διαχειρίζεται τον έλεγχο ταυτότητας).
2. Εάν το Codex CLI του sidecar **δεν είναι ακόμη συνδεδεμένο**, ο έλεγχος
   εύρυθμης λειτουργίας της σύνδεσης αναφέρει _«εκτελείται, αλλά δεν έχει γίνει
   είσοδος»_ (όχι κόκκινο σφάλμα ελέγχου ταυτότητας). Χρησιμοποιήστε την επιλογή
   **Σύνδεση με ChatGPT**: αυτή εκτελεί την τυπική διαδικασία OAuth μέσω συσκευής
   του Codex στο πρόγραμμα περιήγησής σας και κατόπιν γράφει το
   `~/.codex/auth.json` στον κοινόχρηστο τόμο μέσω της επιλογής **Εφαρμογή
   διαπιστευτηρίων** (η ίδια σύνδεση εξυπηρετεί τόσο τον πάροχο `codex` όσο και
   τον πάροχο `codex-app-server`).
3. Μετά τη σύνδεση, ο έλεγχος εύρυθμης λειτουργίας γίνεται πράσινος (επαληθεύει
   τόσο το `/readyz` **όσο και** το `account/read` — δηλαδή ότι η υπηρεσία
   λειτουργεί _και_ έχει πιστοποιηθεί) και αρχίζει να λειτουργεί.

Ο πίνακας ελέγχου δεν αντικαθιστά ποτέ ένα υπάρχον, έγκυρο
`~/.codex/auth.json` — γράφει μόνο όταν το αρχείο απουσιάζει ή το διακριτικό του
έχει λήξει (δημιουργείται πάντα αντίγραφο ασφαλείας).

## 4. Σενάρια ανάπτυξης

- **Διαχειριστής με ήδη πιστοποιημένο Codex CLI** — προσαρτήστε το `~/.codex` του
  κεντρικού υπολογιστή σας στο sidecar (`codex-appserver-home`) και παραλείψτε το
  βήμα σύνδεσης.
- **Δημόσιος χρήστης χωρίς το codex εγκατεστημένο τοπικά** — δεν έχει σημασία:
  το sidecar διαθέτει το CLI. Ο χρήστης πραγματοποιεί έλεγχο ταυτότητας μόνο
  μέσω του πίνακα ελέγχου.
- **OmniRoute σε φυσικό μηχάνημα (χωρίς sidecar, με codex στον κεντρικό
  υπολογιστή)** — κατευθύνετε το `OMNIROUTE_CODEX_APPSERVER_WS` στο δικό σας
  `codex app-server` και βεβαιωθείτε ότι έχει γίνει είσοδος στο codex του
  κεντρικού υπολογιστή· η υπόδειξη «το codex δεν είναι εγκατεστημένο»
  εμφανίζεται εάν λείπει το εκτελέσιμο αρχείο.

## 5. Οικιακή έξοδος / έξοδος UDP (πρόσθετη επιλογή διαχειριστή, δεν παρέχεται)

Το γενικό sidecar παραπάνω δρομολογεί την εξερχόμενη κίνηση μέσω του κανονικού
δικτύου του container. Ένας διαχειριστής που χρειάζεται η κίνηση του Codex να
εξέρχεται μέσω **οικιακού κόμβου εξόδου** (π.χ. ενός sidecar TUN tailscale που
μεταφέρει TCP + UDP/QUIC) το εκτελεί ως ξεχωριστή παράκαμψη compose· σκόπιμα
**δεν** αποτελεί μέρος του παρεχόμενου προφίλ `codex-app-server`. Ανατρέξτε στο
εσωτερικό εγχειρίδιο λειτουργιών για αυτήν τη ρύθμιση.
