Εκτελέστε το CLI `omniroute` στον φορητό υπολογιστή σας, ενώ το ίδιο το OmniRoute εκτελείται κάπου αλλού
(σε ένα VPS, έναν οικιακό διακομιστή ή άλλο μηχάνημα στο Tailnet σας). Συνδέεστε μία φορά με
`omniroute connect` και, από εκεί και πέρα, **κάθε** εντολή CLI στοχεύει εκείνον τον απομακρυσμένο
διακομιστή — ίδιες εντολές, ίδια έξοδος, απλώς εκτελούνται στον απομακρυσμένο διακομιστή.

Δεν υπάρχει δεύτερο εργαλείο προς εγκατάσταση: η απομακρυσμένη λειτουργία χρησιμοποιεί το κανονικό CLI `omniroute`
μαζί με **διακριτικά πρόσβασης** περιορισμένου εύρους.

```bash
npm install -g omniroute                 # το κανονικό CLI
omniroute connect 192.168.0.15           # σύνδεση (κωδικός πρόσβασης → διακριτικό περιορισμένου εύρους)
omniroute models list                    # ← τώρα παραθέτει τα μοντέλα του ΑΠΟΜΑΚΡΥΣΜΕΝΟΥ διακομιστή
omniroute configure codex                # ← γράφει ένα τοπικό προφίλ Codex από τον απομακρυσμένο κατάλογο
```

## Πώς λειτουργεί

```
ο φορητός υπολογιστής σας                απομακρυσμένο OmniRoute (VPS)
┌────────────────────┐                   ┌───────────────────────────────┐
│ CLI omniroute      │  POST /api/cli/connect  (κωδικός → διακριτικό)     │
│  περιβάλλον: vps   │ ───────────────►  │ εκδίδει διακριτικό πρόσβασης   │
│  baseUrl, token    │  Authorization: Bearer oma_live_…                  │
│                    │ ───────────────►  │ κάθε διαδρομή διαχείρισης, με  │
│ γράφει ρυθμίσεις   │ ◄───────────────  │ έλεγχο του εύρους διακριτικού  │
│ ΤΟΠΙΚΑ             │                   └───────────────────────────────┘
└────────────────────┘
```

- Τα **περιβάλλοντα** αποθηκεύουν από έναν διακομιστή το καθένα (`~/.omniroute/config.json`, `chmod 600`).
  Η εντολή `omniroute contexts use <name>` αλλάζει τον ενεργό διακομιστή· το `default` είναι τοπικό.
- Τα **διακριτικά πρόσβασης** (`oma_live_…`) εξουσιοδοτούν εντολές διαχείρισης. Διαφέρουν
  από τα κλειδιά API συμπερασμού (`sk-…`, που χρησιμοποιούνται για το `/v1/chat/completions`).
- Στην πλευρά του διακομιστή αποθηκεύεται μόνο ο κατακερματισμός SHA-256 ενός διακριτικού. Η τιμή απλού κειμένου εμφανίζεται
  **μία φορά**, κατά τη δημιουργία.

## Σύνδεση

### Με τον κωδικό πρόσβασης διαχείρισης (αρχική ρύθμιση)

```bash
omniroute connect 192.168.0.15
# Κωδικός πρόσβασης διαχείρισης για το http://192.168.0.15:20128: ********
# ✔ Συνδέθηκε στο http://192.168.0.15:20128 — περιβάλλον '192.168.0.15' (εύρος: admin)
```

Η ροή με κωδικό πρόσβασης εκδίδει από προεπιλογή ένα διακριτικό **admin** (εφόσον έχετε τον κωδικό πρόσβασης,
διαθέτετε ήδη πλήρη έλεγχο). Περιορίστε το εύρος με `--scope`:

```bash
omniroute connect 192.168.0.15 --scope write
```

Επιλογές: `--port <p>` (όταν ο κεντρικός υπολογιστής δεν περιλαμβάνει θύρα), `--name <ctx>` (όνομα περιβάλλοντος),
`--scope read|write|admin`. Μια πλήρης διεύθυνση URL χρησιμοποιείται αυτούσια:
`omniroute connect https://omni.example.com`.

### Με ένα προδημιουργημένο διακριτικό

Δημιουργήστε ένα διακριτικό περιορισμένου εύρους στον πίνακα ελέγχου (ή με `omniroute tokens create`) και
επικολλήστε το — δεν απαιτείται κωδικός πρόσβασης:

```bash
omniroute connect 192.168.0.15 --key oma_live_xxxxxxxx
```

Το CLI το επικυρώνει μέσω του `GET /api/cli/whoami` και το αποθηκεύει ως ενεργό περιβάλλον.

## Εύρη

Τρία επίπεδα, ιεραρχικά (`admin ⊃ write ⊃ read`):

| Εύρος   | Επιτρεπόμενες ενέργειες                                                                  |
| ------- | ---------------------------------------------------------------------------------------- |
| `read`  | παράθεση/επιθεώρηση — `models list`, `providers status`, `logs`, `usage`, `cost`         |
| `write` | read **+** ρύθμιση/εφαρμογή — `setup-codex`, `keys add`, `config set`, συνδυασμοί        |
| `admin` | write **+** διαχείριση — CRUD για `tokens`, προσθήκη παρόχων, υπηρεσίες, πολιτική, oauth |

Ο διακομιστής συμπεραίνει το απαιτούμενο εύρος για κάθε διαδρομή από τη μέθοδο HTTP
(`GET`→read, μεταβολές→write), μαζί με μια λίστα επιτρεπόμενων ενεργειών admin για ευαίσθητες επιφάνειες
(μεταβολές στα `/api/cli/tokens`, `/api/providers`, `/api/oauth`, `/api/services`, …).
Ένα διακριτικό με ανεπαρκές εύρος λαμβάνει `403` με σαφές μήνυμα.

> Οι διαδρομές που εκκινούν διεργασίες (`/api/services/*`, `/api/mcp/*`, …) παραμένουν
> προσβάσιμες **μόνο μέσω loopback** — ένα απομακρυσμένο διακριτικό δεν μπορεί ποτέ να αποκτήσει πρόσβαση σε αυτές, ανεξάρτητα από το εύρος του.

## Σύνδεση του Antigravity σε απομακρυσμένη εγκατάσταση

Το Antigravity χρησιμοποιεί την οθόνη συναίνεσης firstparty/nativeapp της Google. Η Google εκδίδει τον κωδικό εξουσιοδότησης μόνο όταν η **ανακατεύθυνση loopback**
(`http://127.0.0.1:<port>/callback`) είναι **προσβάσιμη από το πρόγραμμα περιήγησης που
εγκρίνει τη σύνδεση**. Σε μια απομακρυσμένη εγκατάσταση VPS, αυτό το loopback βρίσκεται
στον διακομιστή και όχι στον υπολογιστή σας, επομένως η οθόνη συναίνεσης **κολλάει για πάντα και δεν
εκδίδει ποτέ κωδικό** — η συνήθης εναλλακτική «επικολλήστε το URL επιστροφής κλήσης» δεν έχει τίποτα προς
επικόλληση. (Αυτός είναι ένας περιορισμός από την πλευρά της Google: το ίδιο κόλλημα συμβαίνει σε οποιονδήποτε διακομιστή μεσολάβησης
που χρησιμοποιεί το ενσωματωμένο πρόγραμμα-πελάτη υπολογιστή Antigravity, όχι μόνο στο OmniRoute.)

Ο πίνακας ελέγχου το εντοπίζει προτού κολλήσετε: αν ανοίξετε **Πάροχοι → Antigravity →
Σύνδεση** από μια διεύθυνση που δεν είναι localhost, η γενική ειδοποίηση «αντιγράψτε το URL επιστροφής κλήσης»
αντικαθίσταται από τις δύο παρακάτω λύσεις, καθεμία με τον κεντρικό υπολογιστή και τη θύρα σας ήδη συμπληρωμένα.
(Μια διεύθυνση LAN υπολογίζεται επίσης — η `192.168.x.x` δεν είναι localhost όσον αφορά αυτή την επιστροφή κλήσης.)

Υπάρχουν δύο υποστηριζόμενοι τρόποι για να συνδέσετε το Antigravity σε ένα απομακρυσμένο OmniRoute.

### Επιλογή A — τοπικό βοηθητικό εργαλείο σύνδεσης (συνιστάται)

Εκτελέστε το OAuth στον **δικό σας υπολογιστή**, όπου το `127.0.0.1` είναι προσβάσιμο. Το βοηθητικό εργαλείο
επικοινωνεί απευθείας με την Google, επομένως η διαδικασία συναίνεσης ολοκληρώνεται εκεί όπου η έκδοση του πίνακα ελέγχου
δεν μπορεί.

**Αν είστε ήδη συνδεδεμένοι** (`omniroute connect <host>`), δεν χρειάζεται να
αντιγράψετε τίποτα — το βοηθητικό εργαλείο παραδίδει τα διαπιστευτήρια σε αυτή την εγκατάσταση για εσάς:

```bash
# Στον ΤΟΠΙΚΟ υπολογιστή σας (απαιτεί Node.js + πρόγραμμα περιήγησης):
omniroute connect 192.168.0.15        # μία φορά — δημιουργεί ένα διακριτικό περιβάλλοντος με εύρος διαχειριστή
npx omniroute login antigravity
#   ↳ ανοίγει τη συναίνεση της Google, καταγράφει την επιστροφή κλήσης σε μια τοπική θύρα loopback,
#     την ανταλλάσσει και στέλνει με POST τα διαπιστευτήρια στο ενεργό περιβάλλον:
#
#   Το Antigravity συνδέθηκε στο http://192.168.0.15:20128 (σύνδεση abc123).
#   Δεν χρειάζεται να επικολλήσετε τίποτα — μπορείτε να κλείσετε αυτό το τερματικό.
```

Η προώθηση πραγματοποιείται αυτόματα κάθε φορά που το ενεργό περιβάλλον παραπέμπει σε άλλο
μηχάνημα. Επιβάλετέ την ή απενεργοποιήστε την με `--push` / `--no-push` ή στοχεύστε ένα συγκεκριμένο
περιβάλλον με `--context <name>`.

**Αν ο υπολογιστής σας δεν μπορεί να επικοινωνήσει με το VPS** (λόγω τείχους προστασίας, απουσίας SSH ή απομονωμένου σταθμού εργασίας), το
βοηθητικό εργαλείο εξακολουθεί να λειτουργεί — χρειάζεται μόνο την Google. Χρησιμοποιήστε `--no-push` ή απλώς αφήστε την
προώθηση να αποτύχει: σε αυτή την περίπτωση, εκτυπώνει το blob αντί να απορρίψει μια
εξουσιοδότηση που έχετε ήδη ολοκληρώσει.

```bash
npx omniroute login antigravity --no-push
#   omniroute-cred-v1.eyJ2IjoxLCJ...
```

Στη συνέχεια, στον **απομακρυσμένο** πίνακα ελέγχου: **Πάροχοι → Antigravity → Σύνδεση**, και επικολλήστε
το blob `omniroute-cred-v1.…` στο πεδίο **Βήμα 2** (δέχεται είτε ένα
URL επιστροφής κλήσης είτε ένα blob διαπιστευτηρίων). Το OmniRoute το αποκωδικοποιεί, εκτελεί την αρχική ρύθμιση του Cloud Code
στην πλευρά του διακομιστή και αποθηκεύει μόνιμα τη σύνδεση.

> Το blob περιέχει ένα διακριτικό ανανέωσης — αντιμετωπίστε το σαν κωδικό πρόσβασης. Κατά την προώθηση
> αποστέλλεται μία φορά μέσω της πιστοποιημένης σύνδεσης του περιβάλλοντός σας· κατά την επικόλληση, μέσω
> της σύνδεσης του πίνακα ελέγχου σας. Σε κάθε περίπτωση αποθηκεύεται κρυπτογραφημένο και μια
> επιτυχημένη προώθηση δεν το εκτυπώνει ποτέ στο τερματικό σας.

Σημαίες: `--no-browser` (εμφάνιση του URL αντί για αυτόματο άνοιγμα), `--port <n>`
(καθορισμός της θύρας loopback), `--timeout <ms>`, `--push` / `--no-push` (παράκαμψη της
αυτόματης παράδοσης), `--context <name>` (στόχευση συγκεκριμένου περιβάλλοντος).

### Επιλογή B — τοπική σήραγγα προώθησης SSH

Αν έχετε πρόσβαση SSH στο VPS, προωθήστε τη θύρα του πίνακα ελέγχου ώστε η
επιστροφή κλήσης loopback να δρομολογείται πίσω στον διακομιστή μέσω της σήραγγας:

```bash
# Στον ΤΟΠΙΚΟ υπολογιστή σας:
ssh -L 20128:127.0.0.1:20128 user@your-vps
# έπειτα ανοίξτε το http://localhost:20128 στο ΤΟΠΙΚΟ πρόγραμμα περιήγησής σας και συνδέστε το Antigravity
# κανονικά — η ανακατεύθυνση 127.0.0.1:20128/callback φτάνει πλέον στο VPS μέσω SSH.
```

Επειδή αποκτάτε πρόσβαση στον πίνακα ελέγχου ως `localhost:20128`, η συναίνεση της Google
ολοκληρώνεται και η επιστροφή κλήσης παραδίδεται στον διακομιστή μέσω της ίδιας σήραγγας —
χωρίς να απαιτείται blob. Διατηρήστε τη σήραγγα ανοιχτή μέχρι η σύνδεση να εμφανιστεί ως ενεργή.

Σε αντίθεση με τους παρακάτω παρόχους σταθερού loopback, **μία προώθηση αρκεί** εδώ: η
επιστροφή κλήσης του Antigravity χρησιμοποιεί την ίδια τη θύρα του πίνακα ελέγχου, επομένως δεν υπάρχει δεύτερη
θύρα ειδική για τον πάροχο που πρέπει να προωθηθεί μέσω σήραγγας.

> Μια πλήρως headless εναλλακτική λύση (χωρίς βοηθητικό εργαλείο και χωρίς σήραγγα) είναι να ρυθμίσετε τα **δικά σας**
> διαπιστευτήρια ιστού Google OAuth + ένα δημόσιο βασικό URL· δείτε τις μεταβλητές περιβάλλοντος OAuth
> του παρόχου. Οι δύο παραπάνω επιλογές δεν απαιτούν πρόσθετη ρύθμιση της Google.

## Σύνδεση Codex / Grok σε απομακρυσμένη εγκατάσταση (πάροχοι με σταθερό loopback)

Τα Codex, xAI (`xai-oauth`) και Grok CLI (`grok-cli`) καταχωρίζουν ένα **σταθερό**
loopback `redirect_uri` στην upstream εφαρμογή OAuth τους. Το OmniRoute δεν μπορεί
να το αλλάξει — ο πάροχος ανακατευθύνει πάντα το πρόγραμμα περιήγησης στην ίδια
hardcoded διεύθυνση:

| Πάροχος     | Σταθερό callback στο οποίο ανακατευθύνει ο πάροχος |
| ----------- | -------------------------------------------------- |
| `codex`     | `http://localhost:1455/auth/callback`              |
| `xai-oauth` | `http://127.0.0.1:56121/callback`                  |
| `grok-cli`  | `http://127.0.0.1:56122/callback`                  |

Το `localhost` εκεί σημαίνει **το μηχάνημα στο οποίο εκτελείται το πρόγραμμα
περιήγησης**, ενώ ο διακομιστής callback PKCE του OmniRoute ακούει στο loopback
του **διακομιστή**. Αν ανοίξετε τον πίνακα ελέγχου σε μια διεύθυνση LAN όπως
`http://192.168.0.15:20128`, τα δύο δεν συναντώνται ποτέ: ο κωδικός
εξουσιοδότησης παραδίδεται στο `localhost:1455` του δικού σας φορητού υπολογιστή,
όπου δεν ακούει τίποτα, και ο πάροχος αποτυγχάνει να ολοκληρώσει τη σύνδεση χωρίς
να εμφανίσει σφάλμα.

Ο πίνακας ελέγχου το εντοπίζει πριν ανοίξει το αναδυόμενο παράθυρο και εμφανίζει
την εντολή tunnel αντί να αφήσει τη σύνδεση να αποτύχει αθόρυβα (#8046).

### Διόρθωση — προωθήστε **και τις δύο** θύρες

```bash
# Στο μηχάνημα όπου εκτελείται το ΠΡΟΓΡΑΜΜΑ ΠΕΡΙΗΓΗΣΗΣ:
ssh -L 20128:127.0.0.1:20128 -L 1455:127.0.0.1:1455 <user>@192.168.0.15
# έπειτα μεταβείτε στο http://localhost:20128 και συνδέστε το Codex από εκεί
```

Απαιτούνται δύο προωθήσεις και η προώθηση μόνο της μίας εξακολουθεί να αποτυγχάνει:

- Η **`20128`** (η θύρα του πίνακα ελέγχου) κάνει το origin πραγματικά τοπικό
  localhost, κάτι που επιτρέπει στο OmniRoute να εκκινήσει τον διακομιστή callback
  PKCE — ένα origin LAN δεν φτάνει ποτέ σε αυτόν τον κλάδο.
- Η **`1455`** (η σταθερή θύρα callback του παρόχου) είναι εκεί όπου επιστρέφει το
  πρόγραμμα περιήγησης· πρέπει να διοχετεύεται μέσω του tunnel στο loopback του
  διακομιστή.

Αντικαταστήστε την `1455` με `56121`/`56122` κατά τη σύνδεση του xAI ή του Grok
CLI και την `20128` με την πραγματική θύρα του πίνακα ελέγχου σας. Διατηρήστε το
tunnel ανοιχτό μέχρι η σύνδεση να εμφανιστεί ως ενεργή.

> **Δεν έχετε πρόσβαση SSH;** Τα Codex και Grok CLI δέχονται επίσης token μέσω
> επικόλλησης — στην καρτέλα **Paste API Key** / **Import auth.json** του παραθύρου
> σύνδεσης. Αυτή η μέθοδος δεν έχει callback loopback, επομένως λειτουργεί από
> οποιοδήποτε origin. Το Codex δέχεται επιπλέον ένα απλό access token ή ένα blob
> συνεδρίας `~/.codex/auth.json`.

## Διαχείριση token

```bash
omniroute tokens create --name "laptop" --scope write [--expires 30]
#   ↳ εμφανίζει το μυστικό ΜΙΑ ΦΟΡΑ — αντιγράψτε το τώρα
omniroute tokens list                 # με απόκρυψη: id, όνομα, scope, πρόθεμα, κατάσταση, λήξη
omniroute tokens revoke <id|prefix>   # άμεση ανάκληση
omniroute tokens scopes               # επεξήγηση των τριών scope
```

Οι εντολές `tokens` απαιτούν διαπιστευτήριο **admin**. Μπορείτε επίσης να
διαχειρίζεστε τα token στον πίνακα ελέγχου, στην ενότητα **Settings → Access
Tokens** (δημιουργία, ανάκληση, αντιγραφή μία φορά).

## Ρύθμιση ενός CLI προγραμματισμού από τον απομακρυσμένο κατάλογο

Η εντολή `omniroute configure` διαβάζει τον ζωντανό κατάλογο μοντέλων του
**ενεργού διακομιστή** και γράφει μια ρύθμιση παραμέτρων στο **δικό σας** μηχάνημα.

```bash
omniroute configure codex
#   Πάροχοι: glm, kmc, ollamacloud, opencode-go, …
#   Πάροχος: glm
#   ID μοντέλου: glm/glm-5.2
#   ✔ Εγγράφηκε το ~/.codex/glm52.config.toml
#   Χρήση:  codex --profile glm52

# μη διαδραστικά
omniroute configure codex --provider glm --model glm/glm-5.2 --name glm52

# διατηρήστε ένα συχνά χρησιμοποιούμενο μοντέλο στην κορυφή του διαδραστικού επιλογέα
omniroute configure codex --provider glm --model glm/glm-5.2 --favorite --yes
```

Ο επιλογέας διατηρεί μόνο ID μοντέλων (ποτέ URL ή διαπιστευτήρια) στο τοπικό
αρχείο `model-preferences.json`, οριοθετημένα ανά context και στόχο CLI. Τα
αγαπημένα εμφανίζονται πριν από τις πρόσφατες επιλογές· χρησιμοποιήστε το
`--unfavorite` για να αφαιρέσετε ένα επιλεγμένο μοντέλο από τη λίστα αυτού του
context/στόχου.

Το προφίλ που εγγράφεται αναφέρεται στο κλειδί inference μέσω μεταβλητής
περιβάλλοντος (`OMNIROUTE_API_KEY`) — το μυστικό δεν εγγράφεται ποτέ στον δίσκο.
Για την εφάπαξ βασική ρύθμιση του Codex (το block
`[model_providers.omniroute]`), ανατρέξτε στο
[CODEX-CLI-CONFIGURATION.md](./CODEX-CLI-CONFIGURATION.md).

### Εκκίνηση ενός CLI προς το απομακρυσμένο σύστημα (χωρίς εγγραφή ρυθμίσεων)

Η εντολή `omniroute run <target>` λαμβάνει επίσης υπόψη το ενεργό context: το
απομακρυσμένο βασικό URL και το διαπιστευτήριο του context εισάγονται μόνο στη
διεργασία που εκκινείται.

```bash
omniroute connect 192.168.0.15
omniroute run claude   --model openai/gpt-5.4          # Claude Code → απομακρυσμένο σύστημα
omniroute run gemini   --model glm/glm-5.2 -- --skip-trust -p "hello"
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"

# Προεπισκόπηση όσων ακριβώς θα εκκινούνταν (μόνο ΟΝΟΜΑΤΑ ΚΛΕΙΔΙΩΝ env, ποτέ τιμές):
omniroute run codex --dry-run --json
```

Στόχοι: `claude`, `codex`, `aider`, `goose`, `opencode`, `qwen`, `gemini`
(μοναδική πηγή: `bin/cli/cli-manifest.mjs`). Τα Qwen και Gemini εκτελούνται με
έναν προσωρινό, απομονωμένο αρχικό κατάλογο, ο οποίος αφαιρείται κατά την έξοδο,
ώστε η εκκίνηση να μην αγγίζει — ούτε να διαρρέει σε — την προσωπική ρύθμιση των
εργαλείων σας.

### Εντολές ρύθμισης ανά CLI

Κάθε υποστηριζόμενο CLI διαθέτει μια εντολή ρύθμισης που γνωρίζει το
απομακρυσμένο σύστημα (όλες λαμβάνουν υπόψη το ενεργό context ή τις επιλογές
`--remote <url> --api-key <key>`):

| CLI         | Εντολή                     | Τι εγγράφει                                                                                                                                                                                             |
| ----------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Codex       | `omniroute setup-codex`    | προφίλ `~/.codex/<name>.config.toml` (ανά μοντέλο)                                                                                                                                                      |
| Claude Code | `omniroute setup-claude`   | `~/.claude/profiles/<name>/settings.json` (ανά μοντέλο)                                                                                                                                                 |
| OpenCode    | `omniroute setup-opencode` | `~/.config/opencode/opencode.json` — ο συμβατός με OpenAI πάροχος `omniroute` με κάθε μοντέλο του καταλόγου (εκτελέστε `opencode -m omniroute/<model>`)                                                 |
| Cline       | `omniroute setup-cline`    | `~/.cline/data/{globalState,secrets}.json` (λειτουργία CLI) + εμφανίζει τις ρυθμίσεις της επέκτασης VS Code προς επικόλληση (συμβατό με OpenAI, βασικό URL **χωρίς** `/v1`)                             |
| Kilo Code   | `omniroute setup-kilo`     | `~/.local/share/kilo/auth.json` (CLI) + ρυθμίσεις `kilocode.*` του VS Code — συμβατό με OpenAI, βασικό URL **με** `/v1`                                                                                 |
| Continue    | `omniroute setup-continue` | `~/.continue/config.yaml` (VS Code/JetBrains + CLI `cn`) — `provider: openai`, `apiBase` **με** `/v1`, κλειδί μέσω `${{ secrets.OMNIROUTE_API_KEY }}`                                                   |
| Cursor      | `omniroute setup-cursor`   | εμφανίζει τα βήματα εντός της εφαρμογής (Ρυθμίσεις → Μοντέλα → Παράκαμψη βασικού URL του OpenAI **με** `/v1` + κλειδί + μοντέλο). Η ρύθμιση του Cursor είναι αδιαφανής SQLite — μόνο πίνακας συνομιλίας |
| Roo Code    | `omniroute setup-roo`      | εγγράφει ένα JSON εισαγωγής του Roo (`~/.omniroute/roo-settings.json`) + ορίζει το `roo-cline.autoImportSettingsPath` + εμφανίζει βήματα για το UI (συμβατό με OpenAI, βασικό URL **με** `/v1`)         |
| Crush       | `omniroute setup-crush`    | `~/.config/crush/crush.json` — πάροχος `openai-compat`, `base_url` **με** `/v1`, κλειδί μέσω `$OMNIROUTE_API_KEY`                                                                                       |
| Goose       | `omniroute setup-goose`    | `~/.config/goose/config.yaml` (`GOOSE_PROVIDER=openai` + `OPENAI_HOST` **χωρίς** `/v1` + `GOOSE_MODEL`) + οδηγίες περιβάλλοντος                                                                         |
| Aider       | `omniroute setup-aider`    | `~/.aider.conf.yml` (`openai-api-base` **χωρίς** `/v1` + `model: openai/<id>`) + οδηγίες περιβάλλοντος (`aider --message --yes`)                                                                        |
| Qwen Code   | `omniroute setup-qwen`     | καταχώριση V4 `modelProviders.openai` στο `~/.qwen/settings.json` + `OMNIROUTE_API_KEY` στο `~/.qwen/.env`                                                                                              |

```bash
# OpenCode (πάροχος συμβατός με OpenAI, όλα τα μοντέλα του καταλόγου, απομακρυσμένο VPS)
omniroute setup-opencode --remote http://192.168.0.15:20128 --api-key oma_live_xxx
omniroute setup-opencode --only glm,kimi        # διατήρηση μόνο των μοντέλων που αντιστοιχούν
opencode -m omniroute/glm/glm-5.2 "..."          # εξαγάγετε πρώτα το OMNIROUTE_API_KEY
```

> Το OpenCode διαθέτει επίσης μια πιο πλούσια ενσωμάτωση μέσω **plugin**: `omniroute setup opencode`
> (πλέον με υποστήριξη απομακρυσμένης σύνδεσης μέσω `--remote`) εγκαθιστά το `@omniroute/opencode-plugin`.
> Το `setup-opencode` είναι η ελαφριά, συμβατή με OpenAI εναλλακτική. Το κλειδί API
> αναφέρεται μέσω `{env:OMNIROUTE_API_KEY}` — δεν εγγράφεται ποτέ στον δίσκο.
>
> Στο OpenCode v2, χρησιμοποιήστε αντ’ αυτού το `@omniroute/opencode-plugin-v2`: ίδιος κατάλογος,
> διαφορετική σύμβαση φόρτωσης. Διαβάζει το κλειδί από τον χώρο αποθήκευσης διαπιστευτηρίων
> του ίδιου του OpenCode όταν η ενσωμάτωση είναι συνδεδεμένη, επομένως μια απομακρυσμένη πύλη δεν χρειάζεται κανένα κλειδί
> στο `opencode.json`.

## Διαχείριση περιβαλλόντων (εναλλαγή μεταξύ διακομιστών)

Ένα **περιβάλλον** είναι ένας αποθηκευμένος διακομιστής (baseUrl + διαπιστευτήρια + πεδίο εφαρμογής). Η εντολή `omniroute connect` δημιουργεί ένα και το καθιστά ενεργό· από εκεί και πέρα, κάθε εντολή το στοχεύει. Διαχειριστείτε και εναλλάξτε μεταξύ τους με την εντολή `omniroute contexts`:

```bash
omniroute contexts list            # όλα τα περιβάλλοντα· το ενεργό επισημαίνεται με ●
omniroute contexts current         # ο ενεργός διακομιστής, κατάσταση ελέγχου ταυτότητας, πεδίο εφαρμογής
```

```text
  | Name    | Base URL                  | Auth  | Scope | Description
● | vps     | http://100.67.86.91:20128 | token | admin | Απομακρυσμένο OmniRoute (…)
  | default | http://localhost:20128    | ✗     |       |
```

**Εναλλαγή διακομιστών** — κάθε επόμενη εντολή ακολουθεί το ενεργό περιβάλλον:

```bash
omniroute contexts use vps         # → όλες οι εντολές τώρα στοχεύουν το απομακρυσμένο VPS
omniroute tokens list              #   (εκτελείται έναντι του VPS)

omniroute contexts use default     # → πίσω στον localhost
omniroute tokens list              #   (εκτελείται έναντι του τοπικού διακομιστή)
```

**Προσθήκη περιβάλλοντος χειροκίνητα** (αντί για `connect`), επιθεώρηση ή μετονομασία:

```bash
omniroute contexts add staging --url https://staging.example.com:20128 \
  --access-token oma_live_xxxx --scope write --description "δοκιμαστικό περιβάλλον"
omniroute contexts show staging    # πλήρεις λεπτομέρειες για ένα περιβάλλον
omniroute contexts rename staging stg
```

**Αφαίρεση περιβάλλοντος** — ζητά επιβεβαίωση· περάστε το `--yes` για να την παραλείψετε (απαιτείται για σενάρια / μη διαδραστικά shells, τα οποία διαφορετικά αρνούνται με ασφάλεια):

```bash
omniroute contexts remove stg --yes
```

> Το `default` (localhost) δεν μπορεί να αφαιρεθεί. Η αφαίρεση του ενεργού περιβάλλοντος επιστρέφει στο `default`. Συμβουλή: η αφαίρεση ενός περιβάλλοντος απλώς διαγράφει τα **τοπικά** αποθηκευμένα διαπιστευτήρια — ανακαλέστε το token στον διακομιστή με την εντολή `omniroute tokens revoke <id>` για να τερματίσετε πραγματικά την πρόσβαση.

**Εξαγωγή / εισαγωγή** περιβαλλόντων (π.χ. για τη μεταφορά τους μεταξύ μηχανών). Οι εξαγωγές παραλείπουν τα διαπιστευτήρια από προεπιλογή, συμπεριλαμβανομένων των διαπιστευτηρίων που αποθηκεύονται από την εφεδρική λύση αρχείου. Χρησιμοποιήστε το `--include-secrets` ρητά όταν απαιτείται ένα φορητό αντίγραφο ασφαλείας που περιέχει διαπιστευτήρια:

```bash
omniroute contexts export --out contexts.json     # λογοκριμένο· προεπιλεγμένος προορισμός: stdout
omniroute contexts export --include-secrets --out private-contexts.json
omniroute contexts import contexts.json            # αντικατάσταση· --merge για διατήρηση των υπαρχόντων
omniroute contexts migrate --yes                  # μετακίνηση παλαιών tokens απλού κειμένου στο keychain
```

Το `--include-secrets` επιλύει τις αναφορές keychain πριν από την εξαγωγή και αποτυγχάνει εάν δεν είναι δυνατή η ανάγνωση οποιουδήποτε αναφερόμενου διαπιστευτηρίου. Το `--no-secrets` έχει πάντα προτεραιότητα. Τα αρχεία εξαγωγής γράφονται ατομικά με δικαιώματα `0600`. Αντιμετωπίστε μια ρητή εξαγωγή που περιέχει μυστικά ως μυστικό υλικό. Σε συστήματα χωρίς οθόνη (headless systems) χωρίς ένα λειτουργικό keychain του λειτουργικού συστήματος, το CLI επιστρέφει στο `config.json` με δικαιώματα `0600` και εκτυπώνει μια εφάπαξ προειδοποίηση· μια προεπιλεγμένη εξαγωγή παραμένει λογοκριμένη σε αυτή τη λειτουργία.

## Γρήγορος έλεγχος από άκρο σε άκρο

Ένας κύκλος ζωής έτοιμος για αντιγραφή και επικόλληση, ώστε να επαληθεύσετε μια απομακρυσμένη εγκατάσταση από την αρχή — σύνδεση, δημιουργία
token με συγκεκριμένο scope, δρομολόγηση μιας εντολής, επιστροφή και κατάργηση. Αντικαταστήστε το
`192.168.0.15` με το όνομα κεντρικού υπολογιστή/IP του διακομιστή σας (Tailscale, LAN ή ένα δημόσιο
URL `https://…`).

```bash
# 1. Σύνδεση (κωδικός πρόσβασης → admin token, αποθηκεύεται ως context που γίνεται ενεργό)
omniroute connect 192.168.0.15                 # ή: --key oma_live_xxxx  (χωρίς κωδικό πρόσβασης)
omniroute contexts current                     # εμφανίζει τον απομακρυσμένο διακομιστή + scope

# 2. Χρήση — οι εντολές διαχείρισης εκτελούνται πλέον στον απομακρυσμένο διακομιστή
omniroute tokens create --name laptop --scope read   # δημιουργία token με πιο περιορισμένο scope
omniroute tokens list                                 # λίστα με αποκρυμμένα στοιχεία, από τον απομακρυσμένο διακομιστή

# 3. Εναλλαγή μεταξύ τοπικού και απομακρυσμένου διακομιστή
omniroute contexts use default                 # → τοπικός
omniroute contexts use 192-168-0-15            # → ξανά απομακρυσμένος (όνομα από το `contexts list`)

# 4. Κατάργηση. ΣΗΜΕΙΩΣΗ: το `contexts remove` διαγράφει μόνο το ΤΟΠΙΚΟ διαπιστευτήριο —
#    ΔΕΝ ανακαλεί το token στον διακομιστή. Πρώτα πραγματοποιήστε ανάκληση στην πλευρά του διακομιστή, εάν
#    θέλετε να διακόψετε πραγματικά την πρόσβαση.
omniroute tokens revoke <id|prefix>            # διακόπτει την πρόσβαση στον διακομιστή
omniroute contexts remove 192-168-0-15 --yes   # καταργεί το τοπικό context (ακόμη και αν είναι ενεργό → επιστρέφει στο default), χωρίς ερώτηση
```

> Το `--yes` καθιστά το `contexts remove` μη διαδραστικό (απαιτείται σε scripts/CI· χωρίς
> αυτό, ένα μη διαδραστικό shell απορρίπτει την ενέργεια με ασφάλεια αντί να παραμένει σε αναμονή). Η κατάργηση του
> **ενεργού** context προκαλεί αυτόματη επιστροφή στο `default`.

## Σημειώσεις ασφαλείας

- Το απλό κείμενο του token εμφανίζεται μία φορά· αποθηκεύεται μόνο το hash SHA-256 (όπως και στα κλειδιά API).
- Το `omniroute connect` επαναχρησιμοποιεί το κλείδωμα έναντι επιθέσεων brute-force κατά τη σύνδεση + την καταγραφή ελέγχου.
- Προτιμήστε HTTPS ή ένα Tailnet για τη μεταφορά· ένας σκέτος host χρησιμοποιεί από προεπιλογή `http://`
  για ευκολία σε LAN/Tailscale — περάστε ένα πλήρες URL `https://…` για TLS.
- Το προτιμώμενο τοπικό αρχείο περιβάλλοντος είναι το `~/.omniroute/config.json` (`chmod 600`)
  και περιέχει μόνο ένα `credentialRef`· το ίδιο το token αποθηκεύεται στην κλειδοθήκη
  του λειτουργικού συστήματος (`keytar`) και δεν εκτυπώνεται ποτέ στα αρχεία καταγραφής. Οι εγκαταστάσεις χωρίς γραφικό περιβάλλον που δεν διαθέτουν
  λειτουργική εγγενή κλειδοθήκη χρησιμοποιούν το ίδιο αρχείο `0600` ως ρητή εφεδρική λύση και
  εμφανίζουν μία φορά μια προειδοποίηση. Χρησιμοποιήστε `omniroute contexts migrate --yes` μετά την εγκατάσταση ενός
  backend κλειδοθήκης.
