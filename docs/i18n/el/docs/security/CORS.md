Το OmniRoute ελέγχει ποιες **προελεύσεις browser** μπορούν να διαβάζουν αποκρίσεις
μεταξύ διαφορετικών προελεύσεων από μία ενιαία, κεντρική λίστα επιτρεπόμενων. Το
μοντέλο είναι **εξ ορισμού κλειστό σε περίπτωση αποτυχίας**: καμία προέλευση δεν
επιτρέπεται μέχρι να την προσθέσετε ρητά. Αυτή η σελίδα τεκμηριώνει τον τρόπο
επίλυσης της λίστας επιτρεπόμενων, τι εκθέτει πραγματικά το `CORS_ALLOW_ALL=true`
(και, κυρίως, τι **δεν** εκθέτει), πώς να ρυθμίσετε με ασφάλεια τα περιβάλλοντα
ανάπτυξης και παραγωγής, καθώς και την προειδοποίηση χρόνου εκτέλεσης που εμφανίζει
ο πίνακας ελέγχου όταν είναι ενεργός ένας χαρακτήρας μπαλαντέρ.

**Πηγή αλήθειας:** `src/server/cors/origins.ts` (`resolveAllowedOrigin`,
`applyCorsHeaders`, `getCorsStatus`). Η λίστα επιτρεπόμενων εφαρμόζεται μία φορά,
στο middleware (`src/server/authz/pipeline.ts`) — οι χειριστές κάθε διαδρομής δεν
ορίζουν οι ίδιοι το `Access-Control-Allow-Origin`.

## Πώς επιλύεται μια προέλευση

Για κάθε αίτημα, το middleware υπολογίζει την τιμή `Access-Control-Allow-Origin`
με την ακόλουθη σειρά:

1. **`CORS_ALLOW_ALL=true`** (ή το παλαιού τύπου `CORS_ORIGIN=*`) → επιστρέφει ως
   έχει το `Origin` του καλούντος (ή `*` όταν δεν υπάρχει κεφαλίδα `Origin`), μαζί
   με `Vary: Origin`, ώστε οι κρυφές μνήμες να παραμένουν σωστές. Το ίδιο σημείο
   ελέγχου `applyCorsHeaders()` προσθέτει επίσης `Vary: Accept-Encoding` σε κάθε
   απόκριση 2xx με σώμα στην επιφάνεια `/v1*`/`/v1beta*` που χρησιμοποιεί έλεγχο
   ταυτότητας μέσω token (`relaxForTokenAuth`, RFC 9110 §12.5.5, ζήτημα #6737),
   ώστε οι μεταγενέστερες/κοινόχρηστες κρυφές μνήμες να μπορούν να διακρίνουν
   σωστά τις συμπιεσμένες από τις μη συμπιεσμένες παραλλαγές.
2. Διαφορετικά, το `Origin` του αιτήματος κανονικοποιείται (μετατρέπεται σε πεζά
   και αφαιρείται η τελική κάθετος) και αντιστοιχίζεται με τη **συγχωνευμένη λίστα
   επιτρεπόμενων**:
   - τη μεταβλητή περιβάλλοντος **`CORS_ALLOWED_ORIGINS`** — λίστα διαχωρισμένη με
     κόμματα, και
   - τη ρύθμιση χρόνου εκτέλεσης **`corsOrigins`** (Πίνακας ελέγχου → Ασφάλεια →
     _Επιτρεπόμενες προελεύσεις CORS_), η οποία εισάγεται μέσω
     `setRuntimeAllowedOrigins()` από το `src/lib/config/runtimeSettings.ts`.
3. Καμία αντιστοίχιση → **δεν εκπέμπεται κεφαλίδα `Access-Control-Allow-Origin`**.
   Ο browser αποκλείει την ανάγνωση μεταξύ διαφορετικών προελεύσεων. Αυτή είναι η
   επιδιωκόμενη εξ ορισμού κλειστή συμπεριφορά.

| Μεταβλητή περιβάλλοντος | Σημασία                                                                                                                 |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `CORS_ALLOWED_ORIGINS`  | CSV με τις ακριβείς προελεύσεις που επιτρέπονται (συνιστάται).                                                          |
| `CORS_ALLOW_ALL`        | `true`/`1` → επιστροφή οποιασδήποτε προέλευσης (χαρακτήρας μπαλαντέρ). Μόνο για ανάπτυξη.                               |
| `CORS_ORIGIN`           | Παλαιού τύπου. Το `*` συμπεριφέρεται όπως το `CORS_ALLOW_ALL`· μία μεμονωμένη τιμή προστίθεται στη λίστα επιτρεπόμενων. |

## Μοντέλο απειλών — τι εκθέτει πραγματικά το `CORS_ALLOW_ALL=true`

Η γενική προειδοποίηση του OWASP («CORS με χαρακτήρα μπαλαντέρ = οποιοσδήποτε
ιστότοπος μπορεί να καλέσει το API σας») αξίζει να ληφθεί σοβαρά υπόψη, αλλά η
έκθεση του OmniRoute είναι **πιο περιορισμένη από τη γενική περίπτωση**, λόγω
ενός συγκεκριμένου χαρακτηριστικού της υλοποίησης:

> **Το κεντρικό `applyCorsHeaders()` δεν εκπέμπει ποτέ
> `Access-Control-Allow-Credentials`.** Ένας browser δεν θα εκθέσει μια
> διαπιστευμένη απόκριση μεταξύ διαφορετικών προελεύσεων (η οποία περιέχει cookie),
> εκτός εάν ο server στείλει `Access-Control-Allow-Credentials: true`. Η κοινόχρηστη
> διαδρομή CORS του OmniRoute δεν το κάνει ποτέ.

Αυτό σημαίνει τα εξής για κάθε επιφάνεια, ακόμη και με `CORS_ALLOW_ALL=true`:

| Επιφάνεια                                             | Μηχανισμός ελέγχου ταυτότητας | Επίδραση του CORS με χαρακτήρα μπαλαντέρ                                                                                                                                                                                                                                                 |
| ----------------------------------------------------- | ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Πίνακας ελέγχου / MANAGEMENT `/api/*`                 | Συνεδρία μέσω cookie          | Η προέλευση επιστρέφεται, αλλά **χωρίς `Allow-Credentials`** ο browser **αποκλείει** τη διαπιστευμένη ανάγνωση. Ένας κακόβουλος ιστότοπος διαφορετικής προέλευσης **δεν μπορεί να διαβάσει** τις πιστοποιημένες αποκρίσεις του πίνακα ελέγχου σας και το cookie συνεδρίας δεν εκτίθεται. |
| API πελάτη `/v1/*`, `/v1beta/*`                       | Κεφαλίδα Bearer / `x-api-key` | Είναι ήδη ανεκτικό **εκ σχεδιασμού** (`relaxForTokenAuth`): οι browsers δεν επισυνάπτουν ποτέ αυτόματα `Authorization`/`x-api-key`, επομένως η σελίδα ενός εισβολέα δεν μπορεί να παράσχει το κλειδί σας. Το `CORS_ALLOW_ALL` δεν διευρύνει αυτήν την πρόσβαση.                          |
| Δημόσια πρόσβαση μόνο για ανάγνωση (`/api/health`, …) | Κανένας                       | Μη ευαίσθητη· ο χαρακτήρας μπαλαντέρ είναι ακίνδυνος.                                                                                                                                                                                                                                    |

Επομένως, η **υπολειπόμενη** έκθεση του `CORS_ALLOW_ALL=true` περιορίζεται στα
εξής: (α) μη διαπιστευμένες **αναγνώσεις** ήδη μη πιστοποιημένων δεδομένων μεταξύ
διαφορετικών προελεύσεων και (β) δυνατότητα επιτυχίας του CORS **preflight** στις
διαδρομές διαχείρισης — οι οποίες εξακολουθούν να απαιτούν έλεγχο ταυτότητας που
δεν μπορεί να παράσχει μια σελίδα διαφορετικής προέλευσης. **Δεν** αποτελεί
διάνυσμα υποκλοπής συνεδρίας ή κλοπής διαπιστευτηρίων στην κοινόχρηστη διαδρομή
CORS.

### Μία πραγματική εξαίρεση — `/api/v1/agents/`

Οι διαδρομές Cloud-Agent (`/api/v1/agents/{health,credentials,tasks,tasks/[id]}`)
ορίζουν τις **δικές τους** κεφαλίδες CORS
(`src/lib/cloudAgent/api.ts`, `getCloudAgentCorsHeaders`) και **εκπέμπουν**
`Access-Control-Allow-Origin: <origin>|*` μαζί με
`Access-Control-Allow-Credentials: true`. Αυτή είναι η μοναδική επιφάνεια όπου
συνυπάρχουν η επιστροφή της προέλευσης και τα διαπιστευτήρια και είναι
**ανεξάρτητη από το `CORS_ALLOW_ALL`**. Αυτές οι διαδρομές διαθέτουν έλεγχο
ταυτότητας διαχείρισης (`requireManagementAuth`)· οι διαχειριστές που εκθέτουν
τον πίνακα ελέγχου εκτός του κεντρικού host θα πρέπει να γνωρίζουν ότι αυτό είναι
το μοναδικό σημείο όπου οι κεφαλίδες απόκρισης επιτρέπουν διαπιστευμένη ανάγνωση
μεταξύ διαφορετικών προελεύσεων. Ο περιορισμός του σε μια ρητή λίστα
επιτρεπόμενων παρακολουθείται ξεχωριστά από αυτές τις οδηγίες CORS.

## Λίστα ελέγχου για περιβάλλον παραγωγής

- **Μην ορίζετε ποτέ `CORS_ALLOW_ALL=true` σε περιβάλλον παραγωγής.** Αφήστε το χωρίς τιμή.
- Ορίστε μια **ρητή** λίστα προελεύσεων — είτε μέσω της μεταβλητής περιβάλλοντος είτε μέσω του πεδίου στην καρτέλα Security:

  ```bash
  CORS_ALLOWED_ORIGINS="https://app.example.com, https://admin.example.com"
  ```

- Αν το OmniRoute εκτελείται πίσω από αντίστροφο διακομιστή μεσολάβησης / σήραγγα (nginx, Caddy, Cloudflare
  Tunnel, Tailscale), το CORS **δεν** είναι ο μοναδικός μηχανισμός ελέγχου — ο μηχανισμός προστασίας διαδρομών
  loopback εξακολουθεί να προστατεύει τις διαδρομές που μπορούν να δημιουργήσουν διεργασίες (δείτε
  [ROUTE_GUARD_TIERS](./ROUTE_GUARD_TIERS.md)). Μην πλαστογραφείτε την κεφαλίδα
  `X-Forwarded-For: 127.0.0.1` για να «διορθώσετε» ένα σφάλμα 403· αυτό ανοίγει ξανά την κατηγορία ευπαθειών RCE την οποία
  αποκλείει ο μηχανισμός προστασίας διαδρομών.
- Επιβεβαιώστε την κατάσταση κατά την εκτέλεση: ο πίνακας ελέγχου εμφανίζει ένα **μόνιμο πορτοκαλί banner**
  στην περιοχή Dashboard → Security → Authorization Inventory κάθε φορά που το
  `CORS_ALLOW_ALL=true` είναι ενεργό, ενώ το `/api/settings/authz-inventory` επιστρέφει ένα
  περίβλημα `cors: { allowAll, allowedOrigins }` το οποίο μπορούν να ελέγχουν περιοδικά τα εργαλεία παρακολούθησης.

## Ευκολία κατά την ανάπτυξη — επιτρέψτε συγκεκριμένες τοπικές προελεύσεις

Σπάνια χρειάζεστε τον χαρακτήρα μπαλαντέρ, ακόμη και κατά την ανάπτυξη. Επιτρέψτε μόνο τους διακομιστές ανάπτυξης που χρησιμοποιείτε:

```bash
# Διακομιστές ανάπτυξης Vite (5173) + Next.js (3000) που καλούν ένα τοπικό OmniRoute
CORS_ALLOWED_ORIGINS="http://localhost:5173, http://localhost:3000"
```

Η αντιστοίχιση των προελεύσεων δεν κάνει διάκριση πεζών-κεφαλαίων και αγνοεί την τελική κάθετο, επομένως τα
`http://localhost:3000` και `http://localhost:3000/` είναι ισοδύναμα. Η ίδια λίστα CSV
μπορεί να οριστεί κατά την εκτέλεση στην περιοχή **Dashboard → Security → CORS Allowed Origins** χωρίς
επανεκκίνηση.

## Κλειδιά API έναντι περιόδων λειτουργίας με cookie

- **Bearer / `x-api-key` (η επιφάνεια εξαγωγής συμπερασμάτων `/v1/*`):** τα προγράμματα περιήγησης δεν τα επισυνάπτουν ποτέ
  αυτόματα. Το CORS δεν αποτελεί ουσιαστικό εμπόδιο εδώ — το κλειδί API είναι το
  εμπόδιο — γι’ αυτό και αυτή η επιφάνεια είναι σκόπιμα ελαστική, ώστε τα προγράμματα-πελάτες προγράμματος περιήγησης και
  Electron να μπορούν να διαβάζουν αποκρίσεις τις οποίες δικαιούνται ήδη.
- **Περίοδος λειτουργίας με cookie (ο πίνακας ελέγχου):** προστατεύεται από την προεπιλεγμένη ρύθμιση αποκλεισμού σε περίπτωση αστοχίας **και**
  από την απουσία του `Access-Control-Allow-Credentials` στην κοινόχρηστη διαδρομή. Μην συμπεριλαμβάνετε
  προελεύσεις διαχείρισης/πίνακα ελέγχου σε καμία ελαστική ρύθμιση παραμέτρων· πρέπει να παραμένουν αυστηρά
  αποκλεισμένες σε περίπτωση αστοχίας.

## Παράδειγμα: αντίστροφος διακομιστής μεσολάβησης μπροστά από το OmniRoute

Το CORS επιβάλλεται από το ίδιο το OmniRoute, επομένως ο διακομιστής μεσολάβησης γενικά **δεν** πρέπει να προσθέτει ή να
επανεγγράφει κεφαλίδες `Access-Control-*` (οι διπλές κεφαλίδες προκαλούν προβλήματα στα προγράμματα περιήγησης). Τερματίστε το TLS
και προωθήστε το αίτημα — αφήστε το OmniRoute να απαντήσει στο αίτημα προκαταρκτικού ελέγχου:

```nginx
# nginx — προώθηση στο OmniRoute· ΜΗΝ εισάγετε κεφαλίδες Access-Control-* εδώ
location / {
    proxy_pass http://127.0.0.1:20128;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    # ΜΗΝ ορίσετε το X-Forwarded-For σε 127.0.0.1 — αυτό παρακάμπτει τον μηχανισμό προστασίας διαδρομών loopback.
}
```

Ορίστε τις επιτρεπόμενες προελεύσεις προγραμμάτων περιήγησης στο OmniRoute (`CORS_ALLOWED_ORIGINS` ή στην καρτέλα
Security), όχι στον διακομιστή μεσολάβησης.
