> **Σημείωση πεδίου εφαρμογής:** Το `socket.yml` ρυθμίζει τη σάρωση μετά τη δημοσίευση από την πλευρά του registry του Socket.dev για το τεχνούργημα npm (διαδρομές προς παράβλεψη για περιεχόμενο που δεν διανέμεται, όπως `tests/`, `docs/` και αναφορές build). Δεν συνδέει κάποια πύλη συγχώνευσης CI/PR — κανένα workflow στο `.github/workflows`, κανένα script στο `package.json` και κανένας στόχος `Makefile` δεν καλεί το Socket.dev.

Αυτό το έγγραφο αποτελεί τη βεβαίωση που συντάχθηκε από τον συντηρητή για τα έξι
ευρήματα `AI-detected potential malware` που επισημάνθηκαν για το `omniroute@3.8.5` και
τα μέτρα μετριασμού που εφαρμόστηκαν στο `omniroute@3.8.6`. Υπάρχει ώστε:

1. Οι διαχειριστές των αγωγών ασφαλείας να έχουν μία ενιαία αναφορά την οποία μπορούν να παραθέτουν όταν χρειάζεται
   να αξιολογήσουν τα ευρήματα σε σχέση με τον πραγματικό πηγαίο κώδικα.
2. Οι μελλοντικοί σαρωτές AI να μπορούν να εντοπίσουν τον υπογεγραμμένο από τον συντηρητή ισχυρισμό ότι κάθε
   επισημασμένη διαδρομή είναι σκόπιμη, προαιρετική και τεκμηριωμένη.
3. Να διαθέτουμε ένα γραπτό αρχείο του _γιατί_ κάθε σημείο κλήσης έχει διαμορφωθεί με τον συγκεκριμένο τρόπο —
   ώστε μια μελλοντική αναδιάρθρωση κώδικα να μην επαναφέρει κατά λάθος ένα αποτύπωμα που
   αφαιρέθηκε σκόπιμα.

Αν διαχειρίζεστε έναν σαρωτή που επισημαίνει ξανά οποιοδήποτε από τα παρακάτω σημεία κλήσης αφού
κυκλοφορήσουν τα μέτρα μετριασμού της v3.8.6, ανοίξτε ένα issue με το ίχνος της σάρωσης και
θα επεκτείνουμε τη βεβαίωση εδώ.

## §1 — Εγκατάσταση ριζικής CA για MITM (`77484.js`)

**Αρχεία προέλευσης**:

- `src/mitm/cert/install.ts` — δημόσιες `installCert()` / `uninstallCert()`,
  και ανά πλατφόρμα `installCertWindows/Mac/Linux`.
- `src/mitm/systemCommands.ts` — κοινόχρηστα βοηθητικά προγράμματα `execFile`
  / `spawn` / PowerShell που χρησιμοποιούνται από τις διαδρομές εγκατάστασης.

**Ενεργοποίηση**: ο χρήστης κάνει κλικ στην επιλογή «Ενεργοποίηση διακομιστή
μεσολάβησης MITM» στον τοπικό πίνακα ελέγχου στη διαδρομή
`/dashboard/cli-tools/mitm`. Η διαδρομή είναι προσβάσιμη μόνο μέσω loopback —
δείτε τον απαράβατο κανόνα #17 στο `CLAUDE.md` και τη
`src/server/authz/routeGuard.ts::isLocalOnlyPath()`. Ένα JWT που έχει διαρρεύσει
και εκτεθεί μέσω tunnel **δεν μπορεί** να ενεργοποιήσει αυτή τη διαδρομή
κώδικα.

**Προνομιούχες λειτουργίες που εκτελούνται (ανά πλατφόρμα)**:

| Λειτουργικό σύστημα    | Εντολή(-ές)                                                                                                       |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | `certutil -addstore Root <cert>` μέσω UAC                                                                         |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | ενημέρωση της βάσης δεδομένων NSS ανά προφίλ μέσω `certutil -d sql:<profile>`                                     |

Αυτές είναι οι ίδιες εντολές που χρησιμοποιούνται από τα `mitmproxy`, Charles
Proxy, Fiddler και Caddy. Το γεγονός ότι υπάρχουν στο OmniRoute τεκμηριώνεται
στο `docs/security/STEALTH_GUIDE.md`.

**Μέτρα μετριασμού της v3.8.6**:

- Η `runElevatedPowerShell()` δεν χρησιμοποιεί πλέον
  `-EncodedCommand <base64utf16le>`. Το ωφέλιμο φορτίο αυξημένων προνομίων
  γράφεται σε ένα προσωρινό αρχείο `.ps1` ανά κλήση (λειτουργία 0o600, μέσα
  σε έναν ιδιωτικό κατάλογο `mkdtempSync`) και γίνεται αναφορά σε αυτό μέσω
  της παραμέτρου `-File`. Το αρχείο αποσυνδέεται στο `finally`. Αυτό αφαιρεί
  το χαρακτηριστικό αποτύπωμα ανύψωσης προνομίων μέσω PowerShell με base64,
  το οποίο επισημάνθηκε από τον ταξινομητή AI του Socket.dev.
- Η `installCertWindows` περιλαμβάνει ένα ενσωματωμένο μπλοκ
  `SECURITY-AUDITOR-NOTE:` που παραπέμπει εδώ.

**Γιατί το διατηρούμε**: ο διακομιστής μεσολάβησης MITM είναι μια
τεκμηριωμένη λειτουργία που χρησιμοποιείται από τα
`docs/security/STEALTH_GUIDE.md` και `docs/frameworks/MITM-PROXY.md`. Η
αφαίρεσή του θα διέκοπτε το σύνολο λειτουργιών agent-bridge.

## §2 — Εισαγωγή διαπιστευτηρίων Zed (`app/api/providers/zed/import/route.js`)

**Αρχεία προέλευσης**:

- `src/app/api/providers/zed/discover/route.ts` _(νέο στην v3.8.6)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(νέο στην v3.8.6)_

**Ενεργοποίηση**: ο χρήστης κάνει κλικ στο "Εισαγωγή από το Zed" στη σελίδα Παρόχων του τοπικού πίνακα ελέγχου. Η πρόσβαση στο endpoint ελέγχεται από το `requireManagementAuth`. Το ίδιο το πρόγραμμα επεξεργασίας Zed γράφει τα API keys των παρόχων του στην κλειδοθήκη του λειτουργικού συστήματος με τεκμηριωμένα ονόματα υπηρεσιών — βλ. https://zed.dev/docs/ai/llm-providers.

**Συμπεριφορά της v3.8.5 (εκείνη που επισημάνθηκε από το Socket.dev)**:

Το `POST /import` εντόπιζε τα διαπιστευτήρια και τα αποθήκευε αυτόματα στην τοπική αποθήκη SQLite σε μία μόνο διαδικασία αιτήματος-απόκρισης. Χωρίς επιβεβαίωση ανά λογαριασμό, χωρίς αποτύπωμα, μόνο "βρέθηκαν N tokens, εισήχθησαν όλα."

**Μετριασμός στην v3.8.6 — επιβεβαίωση 2 βημάτων**:

1. Το **`POST /api/providers/zed/discover`** επιστρέφει
   `{ candidates: [{ provider, service, account, fingerprint }] }`. Το μη
   επεξεργασμένο token **δεν** μεταδίδεται ποτέ. Το αποτύπωμα είναι
   `sha256(service|account|token).slice(0,16)`.
2. Ο πίνακας ελέγχου εμφανίζει τη λίστα υποψηφίων, ο χειριστής επιλέγει ποια θα
   εισαχθούν και στέλνει το `{ confirmedAccounts: [{ service, account, fingerprint }] }`
   στο **`POST /api/providers/zed/import`**.
3. Το endpoint εισαγωγής **διαβάζει ξανά την κλειδοθήκη στον διακομιστή** και φιλτράρει βάσει
   `(service, account, fingerprint)`. Μια παραποιημένη ή επαναχρησιμοποιημένη απόκριση
   εντοπισμού δεν μπορεί να εξαπατήσει το endpoint εισαγωγής ώστε να αποθηκεύσει ένα άσχετο token —
   εάν το ενεργό token έχει αλλάξει μετά τον εντοπισμό, το αποτύπωμα δεν
   αντιστοιχεί πλέον και το διαπιστευτήριο παραλείπεται.

Μια μεταβλητή περιβάλλοντος `OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` διατηρεί τη συμπεριφορά της v3.8.5
για χειριστές που δεν έχουν ενημερώσει ακόμη τους αυτοματισμούς τους. Θα
αφαιρεθεί στην v3.9.

**Γιατί το διατηρούμε**: η εισαγωγή από το Zed είναι η πιο φιλική διαδικασία αρχικής ρύθμισης για χρήστες
που χρησιμοποιούν ήδη το Zed και θέλουν να αντιγράψουν τα κλειδιά των παρόχων τους στο OmniRoute
χωρίς να τα επικολλήσουν ξανά.

## §3 — `execFile` / `spawn` / PowerShell με αυξημένα δικαιώματα (`21843.js`)

**Αρχεία προέλευσης**: `src/mitm/systemCommands.ts`.

**Γιατί επισημάνθηκε**: το τμήμα κώδικα επανεξάγει τα `execFileWithPassword`,
`runElevatedPowerShell` και τον κοινό βοηθό `quotePowerShell`. Ο ταξινομητής
AI του Socket.dev τα αναγνωρίζει ως ένα γενικό "σύνολο εργαλείων εκτέλεσης
στο σύστημα + ανύψωσης δικαιωμάτων." Εντός του OmniRoute χρησιμοποιούνται μόνο
από τη διαδρομή εγκατάστασης πιστοποιητικού MITM (§1) και από το
`execFileWithPassword` για εκτέλεση εντολών `sudo`.

**Μετριασμός στην v3.8.6**:

- Αναδιάρθρωση του `runElevatedPowerShell` (βλ. §1).
- Ένα ενσωματωμένο μπλοκ `SECURITY-AUDITOR-NOTE:` τόσο στο
  `runElevatedPowerShell` όσο και στο `execFileWithPassword` τεκμηριώνει τους
  επιτρεπόμενους καλούντες και την καθορισμένη λίστα εκτελέσιμων αρχείων.
- Η κλήση `spawn()` του `execFileWithPassword` φέρει έναν δείκτη `nosemgrep` με
  τη λίστα των εκτελέσιμων αρχείων που επιτρέπεται να λαμβάνει ο βοηθός — δεν
  υπάρχει **καμία διαδρομή από την είσοδο χρήστη προς τα `finalCommand`/`finalArgs`**.

## §4 / §6 — Επόπτης υπηρεσίας 9router (`api/services/9router/{start,restart}/route.js`)

**Αρχεία προέλευσης**:

- `src/app/api/services/9router/_lib.ts` — εργοστάσιο επόπτη.
- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`.
- `src/lib/services/ServiceSupervisor.ts` — γενικός μηχανισμός spawn / περιοδικού ελέγχου υγείας / προσωρινής αποθήκευσης αρχείων καταγραφής.

**Ενεργοποίηση**: ο χρήστης κάνει κλικ στο "Εγκατάσταση" / "Έναρξη" στη σελίδα
ενσωματωμένων υπηρεσιών του τοπικού πίνακα ελέγχου.

**Ήδη υφιστάμενα μέτρα προστασίας**:

- Όλες οι διαδρομές `/api/services/*` είναι LOCAL_ONLY σύμφωνα με το
  `src/server/authz/routeGuard.ts` (αυστηρός κανόνας #17). Η επιβολή της
  πρόσβασης μέσω loopback πραγματοποιείται πριν από οποιονδήποτε έλεγχο
  ταυτότητας — ένα JWT που έχει διαρρεύσει δεν μπορεί να αποκτήσει πρόσβαση σε αυτές.
- Η γραμμή του 9router στη βάση δεδομένων αρχικοποιείται ως `status='not_installed', auto_start=0` (βλ.
  `src/lib/db/migrations/071_services.sql:19`). Η υπηρεσία **δεν** εκκινείται
  κατά την πρώτη εκτέλεση.
- Η `spawn()` καλείται με τη διαδρομή του δυαδικού αρχείου που επιστρέφεται από τη
  `resolveSpawnArgs(apiKey, PORT)` στο `src/lib/services/installers/ninerouter.ts`,
  η οποία αποτελεί μια σταθερή λίστα υποστηριζόμενων δυαδικών αρχείων.
- Τα stdout/stderr αποθηκεύονται προσωρινά στη μνήμη (όριο 5 MB, βλ. `_lib.ts`) — δεν
  πραγματοποιείται εγγραφή στον δίσκο, εκτός εάν ο χρήστης ενεργοποιήσει την καταγραφή από τον πίνακα ελέγχου.

**Μετριασμός στην v3.8.6**: καμία λειτουργική αλλαγή. Το ελάχιστο προφίλ μεταγλώττισης
(`OMNIROUTE_BUILD_PROFILE=minimal`) αντικαθιστά το
`src/lib/services/installers/ninerouter.ts` με μια υλοποίηση placeholder για χρήστες που θέλουν
οι διαδρομές αυξημένων δικαιωμάτων να αφαιρεθούν φυσικά από το πακέτο.

**Γιατί το διατηρούμε**: το 9router είναι μια προαιρετική, τοπικά εγκαταστάσιμη συνοδευτική
υπηρεσία (σκεφτείτε: πρόσθετο τύπου WordPress) — αυστηρά κατόπιν ρητής επιλογής.

## §5 — Εγγραφή διαπιστευτηρίων από το OmniRoute Cloud Sync (`api/keys/[id]/route.js`)

**Αρχεία προέλευσης**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`.
- `src/app/api/keys/[id]/route.ts` — καλεί το `syncKeysToCloudIfEnabled()`.

**Συνθήκη ενεργοποίησης**: Το `isCloudEnabled()` επιστρέφει `true` (ρυθμίζεται από τον πίνακα ελέγχου) **και**
το `CLOUD_URL` είναι διαμορφωμένο. Όταν και τα δύο είναι απενεργοποιημένα, δεν πραγματοποιείται εξερχόμενη κλήση δικτύου προς το τελικό σημείο του Cloud.

**Συμπεριφορά της v3.8.5 (το σφάλμα που εντόπισε σωστά το Socket.dev)**:

Το `updateLocalTokens()` αντικαθιστούσε τα `accessToken`, `refreshToken` και
`providerSpecificData` από την απόκριση του Cloud όταν
`cloudUpdatedAt > localUpdatedAt`. Χωρίς HMAC, χωρίς υπογραφή, χωρίς άθροισμα ελέγχου. Ένα
λανθασμένα διαμορφωμένο ή κακόβουλο `CLOUD_URL` (ή μια επίθεση MITM στο κανάλι) μπορούσε να αντικαταστήσει σιωπηρά τα διακριτικά OAuth του παρόχου.

**Μέτρα αντιμετώπισης στη v3.8.6**:

1. **Επαλήθευση HMAC**: Το `verifyCloudSignature(rawBody, sigHeader)` ελέγχει
   την κεφαλίδα `X-Cloud-Sig` (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`) πριν από την ανάλυση του JSON. Εάν έχει οριστεί το μυστικό, η υπογραφή είναι
   υποχρεωτική. Εάν δεν έχει οριστεί (λειτουργία συμβατότητας με παλαιότερες εκδόσεις), καταγράφεται μια προειδοποίηση και η απόκριση
   γίνεται αποδεκτή — το μυστικό θα είναι υποχρεωτικό στη v3.9.
2. **Ρητή ενεργοποίηση μυστικών πεδίων**: Τα `accessToken` / `refreshToken` /
   `providerSpecificData` αντικαθίστανται **μόνο** όταν
   `OMNIROUTE_CLOUD_SYNC_SECRETS=true`. Η προεπιλεγμένη λειτουργία συγχρονίζει μόνο
   μεταδεδομένα που δεν αποτελούν διαπιστευτήρια (`expiresAt`, `status`, `lastError*`,
   `rateLimitedUntil`, `updatedAt`). Αυτή είναι μια **ασύμβατη αλλαγή** για τους χρήστες
   που βασίζονταν στον απομακρυσμένο συγχρονισμό διακριτικών — πρέπει να τον ενεργοποιήσουν ρητά.

**Γιατί το διατηρούμε**: Το Cloud Sync είναι ο μόνος τρόπος με τον οποίο ένας μισθωτής του OmniRoute Cloud
μπορεί να συγκεντρώνει κεντρικά τα διαπιστευτήρια της ομάδας. Η διόρθωση αποτυπώνει με ειλικρίνεια το μοντέλο απειλών:
«ο διακομιστής υπογράφει, ο πελάτης επαληθεύει, ο διαχειριστής ενεργοποιεί ρητά».

## Προφίλ δημιουργίας: `minimal`

Για χρήστες που χρειάζονται ένα τεχνούργημα συμβατό με το Socket, εκτελέστε τη δημιουργία με:

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

Το `NormalModuleReplacementPlugin` του webpack αντιστοιχίζει τέσσερις μονάδες σε υποκατάστατα:

| Μονάδα                                      | Υποκατάστατο                                     |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

Κάθε υποκατάστατο εξάγει την ίδια διεπαφή, αλλά κάθε συνάρτηση εγείρει ένα
`featureDisabledError(name)` κατά την εκτέλεση. Οι διαδρομές που εξαρτώνται από την απενεργοποιημένη
μονάδα επιστρέφουν HTTP 503 με ένα σαφές μήνυμα, αντί να ενεργοποιούν την
ευαίσθητη διαδρομή κώδικα.

Το πακέτο που προκύπτει προορίζεται να δημοσιευτεί ως `omniroute-secure`. Ανατρέξτε στο
`docs/ops/PUBLISHING_SECURE.md` για τη διαδικασία δημοσίευσης.
