> **Καρφιτσώστε την εξερχόμενη κίνηση σε μία οικογένεια IP — `auto`, `ipv4` ή `ipv6` — ανά διακομιστή μεσολάβησης, ώστε μια έξοδος αποκλειστικά μέσω IPv6 να μη διαρρέει ποτέ σιωπηρά πίσω στο IPv4.**

> **Πηγή αλήθειας:** `open-sse/utils/proxyFamily.ts`, `open-sse/utils/proxyDispatcher.ts`, `open-sse/utils/proxyFetch.ts`, `open-sse/utils/socksConnectorWithFamily.ts`, `open-sse/utils/proxyFamilyResolve.ts`, `src/shared/validation/schemas.ts`, `src/lib/db/proxies.ts`, `src/lib/db/upstreamProxy.ts`, `src/lib/db/migrations/099_proxy_family.sql`

Το OmniRoute επιτρέπει σε κάθε διακομιστή μεσολάβησης να διαθέτει μια **οδηγία οικογένειας διευθύνσεων για την εξερχόμενη κίνηση**. Από προεπιλογή, το λειτουργικό σύστημα επιλέγει IPv4 ή IPv6 (διπλή στοίβα, «Happy Eyeballs»). Όταν ορίζετε την οδηγία σε `ipv4` ή `ipv6`, το OmniRoute καρφιτσώνει κάθε σύνδεση μέσω αυτού του διακομιστή μεσολάβησης στην επιλεγμένη οικογένεια και **αποτυγχάνει με ασφάλεια**, αντί να επιστρέψει στην άλλη οικογένεια.

Αυτή η σελίδα τεκμηριώνει τι είναι η οδηγία, γιατί υπάρχει, πού τη ρυθμίζετε και πώς επιλύεται κατά την εκτέλεση.

## Τι είναι

Κάθε διακομιστής μεσολάβησης στο μητρώο διαθέτει ένα πεδίο `family` με τρεις πιθανές τιμές, οι οποίες επικυρώνονται από ένα enum του Zod:

```ts
// src/shared/validation/schemas.ts
family: z.enum(["auto", "ipv4", "ipv6"]).optional().default("auto"),
```

Η προεπιλεγμένη τιμή του πεδίου είναι `"auto"`, η οποία διατηρεί την προηγούμενη συμπεριφορά διπλής στοίβας. Ο ορισμός του σε `ipv4` ή `ipv6` καρφιτσώνει την οικογένεια σύνδεσης για τον συγκεκριμένο διακομιστή μεσολάβησης.

Η οδηγία κανονικοποιείται παντού μέσω ενός κοινού βοηθητικού μηχανισμού, ώστε οποιαδήποτε άγνωστη τιμή να μετατρέπεται σε `auto`:

```ts
// open-sse/utils/proxyFamily.ts
export type ProxyFamily = "auto" | "ipv4" | "ipv6";

export function parseProxyFamily(value: unknown): ProxyFamily {
  return value === "ipv4" || value === "ipv6" ? value : "auto";
}
```

## Γιατί υπάρχει

Εισήχθη στο PR [#3777](https://github.com/diegosouzapw/OmniRoute/pull/3777). Τα προβλήματα που οδήγησαν στην υλοποίησή της:

| Πρόβλημα                                                            | Τι διορθώνει η οδηγία                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Διαρροή εξερχόμενης κίνησης αποκλειστικά μέσω IPv6 προς το IPv4** | Όταν ένας κεντρικός υπολογιστής μεσολάβησης διαθέτει εγγραφές A και AAAA (ή το λειτουργικό σύστημα προτιμά το IPv4), το Happy Eyeballs μπορεί να πραγματοποιήσει την εξερχόμενη σύνδεση μέσω IPv4, ακόμη και όταν επιδιώκετε μια διαδρομή αποκλειστικά μέσω IPv6. Το καρφίτσωμα στο `ipv6` εξαλείφει αυτή τη διαρροή.                                                                                          |
| **Ανάκληση λόγω ανωμαλίας κοινόχρηστης εξόδου**                     | Οι εναλλασσόμενοι πάροχοι (codex/openai) ανακαλούν διακριτικά όταν πολλοί λογαριασμοί εξέρχονται μέσω της **ίδιας** IP με υψηλό όγκο κίνησης. Ο έλεγχος της οικογένειας εξόδου συμβάλλει στη διατήρηση των λογαριασμών σε διακριτές, προβλέψιμες διαδρομές εξόδου (δείτε το [`src/lib/proxyEgress.ts`](../../src/lib/proxyEgress.ts) για τα διαγνωστικά IP εξόδου που χρησιμοποιούνται σε συνδυασμό με αυτήν). |
| **Ντετερμινιστική έξοδος για συμμόρφωση/δοκιμές**                   | Όταν πρέπει να εγγυηθείτε ότι η κίνηση εξέρχεται μέσω μιας συγκεκριμένης οικογένειας, το `auto` δεν επαρκεί.                                                                                                                                                                                                                                                                                                   |

Η οδηγία είναι σκόπιμα **ανά διακομιστή μεσολάβησης** και όχι καθολική — διαφορετικοί διακομιστές μεσολάβησης στο σύνολό σας μπορούν να έχουν διαφορετικές πολιτικές.

## Τρόπος Ρύθμισης

### Πίνακας ελέγχου

Ο επιλογέας βρίσκεται στη φόρμα proxy της καρτέλας **Χώρος συγκέντρωσης proxy**:

1. Ανοίξτε **Πίνακας ελέγχου → Ρυθμίσεις → Proxy → Χώρος συγκέντρωσης proxy**
2. Προσθέστε ή επεξεργαστείτε ένα proxy
3. Ορίστε το αναπτυσσόμενο μενού **Οικογένεια IP** σε `Αυτόματο (dual-stack)`, `Μόνο IPv4` ή `Μόνο IPv6`
4. Αποθηκεύστε

Το στοιχείο ελέγχου αποδίδεται από το `ProxyRegistryManager.tsx` (προσαρτημένο στο `proxy/ProxyPoolTab.tsx`).

### API

Το πεδίο `family` αποτελεί μέρος των ωφέλιμων φορτίων δημιουργίας/ενημέρωσης του μητρώου proxy, επικυρώνεται από τα `createProxyRegistrySchema` / `updateProxyRegistrySchema` (`src/shared/validation/schemas.ts`) και διαχειρίζεται από τα `POST` / `PATCH /api/v1/management/proxies`:

```bash
# Δημιουργία proxy μόνο για IPv6
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "IPv6 egress",
    "type": "socks5",
    "host": "proxy.example.com",
    "port": 1080,
    "family": "ipv6"
  }'

# Αλλαγή υπάρχοντος proxy σε μόνο IPv4
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{ "id": "proxy-uuid-here", "family": "ipv4" }'
```

Το ίδιο πεδίο γίνεται επίσης αποδεκτό από το ενσωματωμένο αντικείμενο ρύθμισης proxy που χρησιμοποιείται για καταχωρίσεις upstream proxy (`upstream_proxy_config.family`, δείτε το [Μοντέλο Δεδομένων](#data-model)).

Για το υπόλοιπο API CRUD/ανάθεσης proxy, δείτε το [PROXY_GUIDE.md](../ops/PROXY_GUIDE.md).

## Πώς Επιλύεται το `auto`

Όταν το `family` είναι `auto`, το OmniRoute **δεν** προσαρτά καμία οδηγία — το URL του proxy χρησιμοποιείται ως έχει και η οικογένεια σύνδεσης καθορίζεται εγγενώς.

Κατά τη δημιουργία του URL (`proxyConfigToUrl` / `normalizeProxyUrl` στο `open-sse/utils/proxyDispatcher.ts`), ένα proxy με `auto` παράγει ένα απλό URL χωρίς δείκτη:

```ts
// open-sse/utils/proxyDispatcher.ts
const fam = parseProxyFamily(config.family);
const normalized = normalizeProxyUrl(proxyUrlStr, "context proxy", {
  allowSocks5,
});
return fam === "auto" ? normalized : `${normalized}?family=${fam}`;
```

Κατά την αποστολή (`resolveDispatcherFamily`), το `auto` επιλύεται στην εγγενή οικογένεια ενός κεντρικού υπολογιστή που είναι κυριολεκτική διεύθυνση IP ή σε `null` (ώστε να αποφασίσει το λειτουργικό σύστημα) για ένα όνομα κεντρικού υπολογιστή:

```ts
// open-sse/utils/proxyDispatcher.ts
function resolveDispatcherFamily(parsed: URL): 4 | 6 | null {
  const directive = parseProxyFamily(parsed.searchParams.get("family") ?? undefined);
  const literal = detectIpLiteralFamily(parsed.hostname);
  if (directive === "auto") return literal; // null για όνομα κεντρικού υπολογιστή → επιλέγει το λειτουργικό σύστημα
  // ...
}
```

Επομένως:

- `auto` + κεντρικός υπολογιστής που είναι κυριολεκτική διεύθυνση IP (`192.0.2.1` / `[2001:db8::1]`) → οικογένεια αυτής της διεύθυνσης.
- `auto` + όνομα κεντρικού υπολογιστή → `null` → τυπική επίλυση dual-stack από το λειτουργικό σύστημα.

## Πώς επιβάλλονται τα `ipv4` / `ipv6`

Μια οδηγία διαφορετική από `auto` μεταφέρεται ως ένας μοναδικός συνθετικός δείκτης ερωτήματος — `?family=ipv4` ή `?family=ipv6` — ο οποίος προσαρτάται μία φορά στο κανονικοποιημένο URL του proxy. Η `normalizeProxyUrl` αφαιρεί και επαναπροσαρτά προσεκτικά αυτόν τον δείκτη ακριβώς μία φορά, ώστε να μην αλλοιώνει ποτέ την ανάλυση της θύρας.

Όταν δημιουργείται ο dispatcher, ο δείκτης διαβάζεται και μετατρέπεται σε συγκεκριμένη οικογένεια σύνδεσης. Εάν ο host είναι κυριολεκτική διεύθυνση IP της **αντίθετης** οικογένειας, το OmniRoute προκαλεί εξαίρεση (σε περίπτωση αντίφασης, η λειτουργία αποτυγχάνει με ασφαλή τρόπο):

```ts
// open-sse/utils/proxyDispatcher.ts
const want = directive === "ipv6" ? 6 : 4;
if (literal !== null && literal !== want) {
  throw new Error(
    `[ProxyDispatcher] Proxy family directive ${directive} contradicts ${literal === 6 ? "IPv6" : "IPv4"} literal host`
  );
}
```

Στη συνέχεια, η συγκεκριμένη οικογένεια καθηλώνεται στον connector:

- **HTTP/HTTPS proxies** (`ProxyAgent`): `proxyTls: { family, autoSelectFamily: false }` — απενεργοποιεί το Happy Eyeballs, ώστε να χρησιμοποιείται για σύνδεση αποκλειστικά η επιλεγμένη οικογένεια.
- **SOCKS5 proxies**: ένας προσαρμοσμένος connector προωθεί το `socket_options: { family, autoSelectFamily: false }` στον SOCKS client (δείτε [Συμβατότητα SOCKS5](#socks5-compatibility)).

## Συμβατότητα SOCKS5

Η καθήλωση οικογένειας λειτουργεί με SOCKS5 proxies, αλλά το τυπικό `fetch-socks` δεν εκθέτει τις επιλογές socket που απαιτούνται για την καθήλωση της οικογένειας στο σκέλος του proxy. Το OmniRoute παρέχει τον δικό του connector για αυτόν τον σκοπό:

```ts
// open-sse/utils/socksConnectorWithFamily.ts
export function buildSocksFamilySocketOptions(family: 4 | 6 | null): Record<string, unknown> {
  if (family === 6) return { family: 6, autoSelectFamily: false };
  if (family === 4) return { family: 4, autoSelectFamily: false };
  return {};
}
```

Όλες οι αποστολές SOCKS5 διέρχονται από το `createSocksDispatcherWithFamily` ανεξάρτητα από την τιμή του `family` (συμπεριλαμβανομένου του `null` / `auto` μέσω hostname): το `buildSocksFamilySocketOptions(null)` επιστρέφει `{}` και χρησιμοποιείται η ίδια διαδρομή `SocksClient.createConnection` + TLS `buildConnector`, με καθήλωση μέσω `socket_options`, ώστε το Happy Eyeballs να μην μπορεί να επιλέξει IPv4 για μια πολιτική εξερχόμενης κίνησης αποκλειστικά μέσω IPv6.

Η ίδια η υποστήριξη SOCKS5 είναι ενεργοποιημένη από προεπιλογή (μπορεί να απενεργοποιηθεί μέσω `ENABLE_SOCKS5_PROXY=false`)· δείτε [PROXY_GUIDE.md → Μεταβλητές περιβάλλοντος](../ops/PROXY_GUIDE.md#environment-variables).

## Συμπεριφορά ασφαλούς αποτυχίας

Ο βασικός σκοπός της οδηγίας είναι να **αρνείται** τη σύνδεση αντί να επιστρέφει σιωπηρά στη λανθασμένη οικογένεια. Αυτό επιβάλλεται από δύο ελέγχους:

1. **Αντίφαση κυριολεκτικής διεύθυνσης** — μια οδηγία που αντιφάσκει με έναν host ο οποίος είναι κυριολεκτική διεύθυνση IP προκαλεί εξαίρεση κατά τη δημιουργία του dispatcher (`resolveDispatcherFamily`, όπως φαίνεται παραπάνω).

2. **Προκαταρκτικός έλεγχος DNS του hostname** — για έναν proxy με hostname και καθηλωμένη οικογένεια, το `proxyFetch.ts` επαληθεύει ότι το hostname διαθέτει πράγματι εγγραφή στην απαιτούμενη οικογένεια **πριν** από την έξοδο της κίνησης, μέσω του `assertHostnameSupportsFamily`:

   ```ts
   // open-sse/utils/proxyFamilyResolve.ts
   const hasFamily = records.some((r) => r.family === family);
   if (!hasFamily) {
     throw new Error(
       `[ProxyFamily] Proxy host ${host} has no ${family === 6 ? "IPv6 (AAAA)" : "IPv4 (A)"} record; ` +
         `refusing ${family === 6 ? "IPv6" : "IPv4"}-only egress (fail-closed)`
     );
   }
   ```

   Σε περίπτωση αποτυχίας, το `proxyFetch.ts` επισημαίνει το σφάλμα με `code = "PROXY_FAMILY_UNAVAILABLE"` και `statusCode = 503`. Μια αποτυχία επίλυσης DNS αντιμετωπίζεται επίσης με ασφαλή αποτυχία (άρνηση εξερχόμενης κίνησης).

Για hosts που είναι κυριολεκτικές διευθύνσεις IP, ο προκαταρκτικός έλεγχος DNS δεν εκτελεί καμία ενέργεια — η οικογένειά τους είναι εγγενής και δεν απαιτεί αναζήτηση.

## Μοντέλο Δεδομένων

Η στήλη `family` προστέθηκε μέσω της μετεγκατάστασης `099_proxy_family.sql` σε **δύο** πίνακες:

```sql
-- src/lib/db/migrations/099_proxy_family.sql
ALTER TABLE proxy_registry ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
ALTER TABLE upstream_proxy_config ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
```

- `proxy_registry.family` — η οδηγία ανά διακομιστή μεσολάβησης για τις εγγραφές του μητρώου (`src/lib/db/proxies.ts`). Τα ερωτήματα επίλυσης επιλέγουν το `family` μαζί με τις υπόλοιπες στήλες του διακομιστή μεσολάβησης, ενώ μια τιμή που λείπει ή δεν είναι συμβολοσειρά μετατρέπεται σε `"auto"`.
- `upstream_proxy_config.family` — η οδηγία για τις εγγραφές του ανάντη διακομιστή μεσολάβησης (`src/lib/db/upstreamProxy.ts`), με την ίδια προεπιλεγμένη τιμή `"auto"`.

Όταν ένα επιλυμένο αντικείμενο διακομιστή μεσολάβησης φέρει τιμή `family` διαφορετική από `auto`, το `proxyConfigToUrl` προσαρτά τον δείκτη `?family=`, ώστε η δέσμευση να διατηρείται μέχρι και τον dispatcher.
