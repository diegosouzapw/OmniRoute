Το OmniRoute δημοσιεύει τεχνουργήματα npm + Docker. Αυτές οι πύλες παρέχουν προέλευση,
απογραφή (SBOM) και σάρωση CVE, όλα με λογισμικό ανοικτού κώδικα και ενσωματωμένα στις ροές εργασίας έκδοσης.
Στάση **πρώτα η ενημέρωση** — προς το παρόν αναφέρουν ευρήματα και μετατρέπονται σε αποκλειστικές πύλες μετά την 1η
επιτυχημένη έκδοση.

| Πύλη                 | Εργαλείο                                       | Πού                               | Αποκλείει;                    | Έξοδος                                                                 |
| -------------------- | ---------------------------------------------- | --------------------------------- | ----------------------------- | ---------------------------------------------------------------------- |
| Προέλευση SLSA (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`                 | μόνο αν αποτύχει η δημοσίευση | σήμα npmjs / `npm audit signatures`                                    |
| SBOM npm             | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`                 | μόνο αν αποτύχει η δημιουργία | Πόρος έκδοσης + τεχνούργημα                                            |
| SBOM εικόνας         | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (συγχώνευση) | συμβουλευτική                 | Τεχνούργημα CycloneDX                                                  |
| Trivy CVE (SARIF)    | `aquasecurity/trivy-action`                    | `docker-publish.yml` (συγχώνευση) | συμβουλευτική                 | SARIF (HIGH+CRITICAL) → καρτέλα Security                               |
| Πύλη Trivy CRITICAL  | `aquasecurity/trivy-action`                    | `docker-publish.yml` (συγχώνευση) | **αποκλειστική**              | `exit-code: '1'` για επιδιορθώσιμα CRITICAL                            |
| vulnCount του osv    | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`)     | **αποκλειστική**              | προσαρμόζει μονότονα το `metrics.vulnCount` (κατεύθυνση: προς τα κάτω) |
| OpenSSF Scorecard    | `ossf/scorecard-action`                        | `scorecard.yml` (cron)            | συμβουλευτική                 | SARIF → Security + σήμα                                                |

Η μονότονη προσαρμογή CVE της εικόνας χρησιμοποιεί **δύο βήματα** στο `docker-publish.yml`: το βήμα SARIF
(`HIGH,CRITICAL`, `exit-code: 0`) διατηρεί τα HIGH+CRITICAL ορατά στην καρτέλα Security
χωρίς να αποκλείει· το βήμα _πύλης CRITICAL_ (`severity: CRITICAL`, `ignore-unfixed: true`,
`exit-code: 1`) προκαλεί αποτυχία της έκδοσης σε CVE επιπέδου CRITICAL **για το οποίο υπάρχει διαθέσιμη διόρθωση**. Το `ignore-unfixed`
αποτρέπει τον αποκλεισμό της έκδοσης λόγω CVE της βασικής εικόνας χωρίς ενημερωμένη διόρθωση από τον ανάντη πάροχο.

## ⚠️ Μεταβλητότητα CVE (αποκλειστικές πύλες osv/Trivy)

Τα osv και Trivy συγκρίνουν τις εξαρτήσεις με βάσεις δεδομένων CVE που **εμπλουτίζονται συνεχώς**. Ένα PR
που **δεν τροποποιεί καμία εξάρτηση** μπορεί ξαφνικά να γίνει κόκκινο επειδή αποκαλύφθηκε ένα νέο CVE
σε υπάρχουσα εξάρτηση (osv: μετρημένο `vulnCount` > γραμμή βάσης· Trivy: νέο
επιδιορθώσιμο CRITICAL στην εικόνα). **Αυτή είναι ΑΝΑΜΕΝΟΜΕΝΗ λειτουργική συμπεριφορά μιας αποκλειστικής
πύλης CVE και όχι παλινδρόμηση του προϊόντος.**

Όταν το osv ή το Trivy γίνουν κόκκινα λόγω ενός CVE που αποκαλύφθηκε πρόσφατα, η αντιμετώπιση είναι:

1. **Αναβαθμίστε την επηρεαζόμενη εξάρτηση** (προτιμώμενο) — αναβαθμίστε στη διορθωμένη έκδοση μέσω των `package.json`
   `overrides` (μεταβατικές εξαρτήσεις) ή ανακατασκευάστε την εικόνα πάνω σε διορθωμένη βασική εικόνα.
2. **Αν δεν υπάρχει διόρθωση από τον ανάντη πάροχο:**
   - **osv:** επανακαθορίστε τη γραμμή βάσης του `metrics.vulnCount` στο `config/quality/quality-baseline.json`
     (το `npm run quality:ratchet -- --update` δεν καλύπτει τις αποκλειστικές πύλες — επεξεργαστείτε την τιμή
     χειροκίνητα, `direction:down`) με σημείωση αιτιολόγησης + ζήτημα παρακολούθησης.
   - **Trivy:** προσθέστε μια καταχώριση στο `.trivyignore` (ένα CVE-ID ανά γραμμή) με σχόλιο
     αιτιολόγησης + ζήτημα παρακολούθησης. Το `ignore-unfixed: true` καλύπτει ήδη αυτόματα τα CVE χωρίς
     διορθώσεις.

Και οι δύο πύλες πραγματοποιούν **ομαλή ΠΑΡΑΛΕΙΨΗ** (έξοδος 0) όταν το εργαλείο απουσιάζει ή η μέτρηση
αποτυγχάνει (το osv-scanner δεν βρίσκεται στο PATH, το osv.dev/δίκτυο δεν είναι προσβάσιμο, μη έγκυρο JSON) — μια αποτυχία
**μέτρησης** δεν αποκλείει ποτέ· αποκλείει μόνο μια **μετρημένη** παλινδρόμηση.

## Εκκρεμότητα: Scorecard από συμβουλευτική → αποκλειστική πύλη

Μετά την 1η επιτυχημένη έκδοση με αναφορά από το Scorecard:

- Scorecard: μονότονη προσαρμογή βαθμολογίας (παγώνει τη μετρημένη βαθμολογία· δεν μπορεί να μειωθεί).

Συμπληρώνει τις πύλες της Φάσης 7 (osv-scanner, gitleaks, actionlint+zizmor): το zizmor
ελέγχει τις ίδιες τις ροές εργασίας· το Scorecard μετρά συνολικά τη στάση ασφαλείας του αποθετηρίου.
