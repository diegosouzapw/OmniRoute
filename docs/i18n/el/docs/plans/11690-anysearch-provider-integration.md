## 1. Πραγματικά δεδομένα υπηρεσίας (επίσημη τεκμηρίωση, διασταυρωμένα)

- Βασικό URL: `https://api.anysearch.com` (REST) + `POST /mcp` (MCP, JSON-RPC 2.0).
- `POST /v1/search` - παράμετροι: `query` (υποχρεωτική), `max_results` (1-10, προεπιλογή 10), `tag` (`{domain}.{sub_domain}` κατακόρυφη δρομολόγηση), `zone` (cn/intl), `language`, `params` (δομημένα πεδία κατακόρυφης αναζήτησης), `format` (json/markdown).
- `GET /v1/sub-domains?domain=...` - κατάλογος δυνατοτήτων, ΔΕΝ προσμετράται στο όριο χρήσης.
- `POST /v1/extract` - ανάκτηση/εξαγωγή `{url, title, content}`· αυστηρό σώμα JSON, όριο 16 KiB.
- `POST /v1/auth/email/register` - εγγραφή με μία κλήση, επιστρέφει κλειδί απλού κειμένου μίας χρήσης `as_sk_...`.
- Έλεγχος ταυτότητας: προαιρετικό `Authorization: Bearer <as_sk_...>`· η ανώνυμη πρόσβαση υποβαθμίζεται σε όρια ανά IP που καταναλώνουν το ημερήσιο δωρεάν όριο· ένα μη έγκυρο κλειδί επιστρέφει 401/403 ΧΩΡΙΣ σιωπηρή εναλλακτική μετάπτωση σε ανώνυμη πρόσβαση.
- Δωρεάν βαθμίδα: 1000 αιτήματα/ημέρα, 20 QPS ανά κλειδί. Επί πληρωμή βαθμίδα: χωρίς καθορισμένη τιμή (Προσεχώς).
- Περίβλημα απόκρισης: επιτυχία `{code: 0, message: "success", request_id, data}`· αποτυχία `{code: -1, message}`. Τα σφάλματα ελέγχου ταυτότητας/ορίου χρήσης δεν περιλαμβάνουν δομημένο `error_code` (το κείμενο του μηνύματος αποτελεί το σήμα)· τα σφάλματα που αφορούν ειδικά την εξαγωγή περιλαμβάνουν `error_code` (`invalid_extract_url`, `extract_failed`). Δεν υπάρχει κεφαλίδα `Retry-After` στην απόκριση 429.

## 3. Αποφάσεις (όλες ελήφθησαν στις 2026-08-26)

1. **Στάση δρομολόγησης: `fallbackOnly`.** Αιτιολόγηση: ένας δωρεάν πάροχος κόστους 0 δεν πρέπει ποτέ να επικρατεί στην αυτόματη δρομολόγηση βάσει κόστους· η ρητή επιλογή και η επιστροφή μέσω μηχανισμού ανακατεύθυνσης δεν επηρεάζονται. Προηγούμενο: η συγχωνευμένη καταχώριση xquik.
2. **Εμβέλεια: webSearch + webFetch μέσω `POST /v1/extract` στην v1.** Ευθυγραμμίζεται με το νοητικό μοντέλο διπλής δυνατότητας tavily/exa. Οι κάθετες επιφάνειες (`tag`, `sub-domains`, `batch_search`) παραμένουν εκτός εμβέλειας — δεν υπάρχει επί του παρόντος IR για κάθετες παραμέτρους.
3. **Εμφάνιση ορίου χρήσης: `freeMonthlyQuota: 0`** (συντηρητική εμφάνιση τύπου xquik). Η πραγματική παροχή (1000 αιτήματα/ημέρα, ημερήσιος μηδενισμός) αναφέρεται αντ’ αυτού στο κείμενο `authHint` του καταλόγου UI. Αιτιολόγηση: η εμφάνιση του ορίου χρήσης πρέπει να αντιστοιχεί στη σημασιολογία μηδενισμού· η μετατροπή ενός ημερήσιου ορίου σε μηνιαίο ισοδύναμο (30000) αποτελεί ψευδή υπόσχεση που το UI δεν μπορεί να τηρήσει.
4. **searchTypes: `["web"]` μόνο.** Δεν υπάρχουν δημόσια στοιχεία για κάθετη αναζήτηση ειδήσεων/εικόνων στο AnySearch API· οι πύλες που ενσωματώνουν API χωρίς τεκμηριωμένη κάθετη αναζήτηση (π.χ. Google Custom Search) εκθέτουν μόνο αναζήτηση ιστού, αντί να αντιστοιχίζουν σιωπηρά το news -> web.
5. **Στάση ως προς το κλειδί:** η λειτουργία χωρίς κλειδί υποστηρίζεται· ένα μη έγκυρο κλειδί επιστρέφει 401/403 και δεν υποβαθμίζεται ποτέ σιωπηρά σε ανώνυμη πρόσβαση (αντικατοπτρίζει τη σύμβαση της ανάντη υπηρεσίας).
6. **Σκόπιμες εξαιρέσεις:** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (η αναχαίτιση συνομιλίας παραμένει στα firecrawl/jina/tavily)· `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (τα ανώνυμα απομακρυσμένα τελικά σημεία μοιράζονται μία κοινή δεξαμενή με περιορισμό βάσει IP ανά IP εξόδου, επομένως η εξαγωγή χωρίς κλειδί απαιτεί ρητή ενεργοποίηση και δεν αποτελεί υποψήφια επιλογή αυτόματης δρομολόγησης)· `QUOTA_STATUS_PROVIDERS` (το AnySearch σηματοδοτεί την εξάντληση ορίου μέσω 429/φακέλου απόκρισης, όχι μέσω κατάστασης 402/403).
