Το `copilot-m365-web` (ψευδώνυμο `m365copilot`) στέλνει αιτήματα συνομιλίας σε μορφή OpenAI μέσω μιας
πιστοποιημένης συνεδρίας προγράμματος περιήγησης του Microsoft 365 Copilot BizChat στη διεύθυνση
`m365.cloud.microsoft/chat`. Αυτή είναι μια ανεπίσημη ενσωμάτωση.

> **Δεν έχετε χρησιμοποιήσει ξανά παρόχους Web Cookie;**
>
> Διαβάστε το **`docs/getting-started/WEB-COOKIE-GUIDE.md`** για τη γενική διαδικασία ρύθμισης, τις οδηγίες ελέγχου ταυτότητας, τους περιορισμούς και την αντιμετώπιση προβλημάτων, πριν ακολουθήσετε αυτόν τον οδηγό για τον συγκεκριμένο πάροχο.
>
> **Σημαντικό:** Το διαπιστευτήριο για αυτόν τον πάροχο **δεν είναι cookie**. Μην αντιγράφετε
> cookies από το `m365.cloud.microsoft`. Το διαπιστευτήριο αποτελείται από μια παράμετρο ερωτήματος URL WebSocket
> και ένα τμήμα διαδρομής, τα οποία λαμβάνονται από την καρτέλα Network των DevTools.

## Προαπαιτούμενα

- Ένας λογαριασμός Microsoft 365 με πρόσβαση στο BizChat στη διεύθυνση `m365.cloud.microsoft/chat`
- Ένα πρόγραμμα περιήγησης που βασίζεται στο Chromium (Chrome, Edge) για την επιθεώρηση WebSocket μέσω των DevTools
- Μια άδεια χρήσης M365 Copilot (περιλαμβάνεται σε πολλά προγράμματα Microsoft 365 Business/Enterprise)

## Λήψη διαπιστευτηρίων (μέθοδος WebSocket)

1. Συνδεθείτε στη διεύθυνση `https://m365.cloud.microsoft/chat` και ξεκινήστε μια συνομιλία.
2. Ανοίξτε τα **DevTools → Network**.
3. Φιλτράρετε κατά **WS** (WebSocket).
4. Κάντε κλικ στη σύνδεση WebSocket Chathub. Αναζητήστε ένα URL που αρχίζει με
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Από το **Request URL** της, αντιγράψτε:
   - Την τιμή της παραμέτρου ερωτήματος `access_token` (ένα βραχύβιο JWT).
   - Το τμήμα διαδρομής Chathub μετά το `/Chathub/` (π.χ. `<oid>@<tenant>`).

Το πλήρες URL έχει την εξής μορφή:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. Στο OmniRoute, μεταβείτε στην ενότητα **Providers → Add Provider**, επιλέξτε **Microsoft 365 Copilot
   (BizChat)** και επικολλήστε το διαπιστευτήριο με την εξής μορφή:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Κάντε κλικ στα **Test Connection** και **Save**.

## Λήψη διαπιστευτηρίων (εισαγωγή HAR)

Αντί να αντιγράψετε χειροκίνητα τις τιμές από το URL WebSocket, μπορείτε να εξαγάγετε ένα αρχείο HAR
από τα DevTools:

1. Ανοίξτε τα **DevTools → Network**.
2. Ξεκινήστε ή συνεχίστε μια συνομιλία BizChat (αυτό ενεργοποιεί τη σύνδεση WebSocket).
3. Κάντε δεξί κλικ στον πίνακα Network και επιλέξτε **Save all as HAR with content**.
4. Στο OmniRoute, χρησιμοποιήστε το κουμπί **Import .har file** στο παράθυρο διαλόγου σύνδεσης του παρόχου.

Το OmniRoute σαρώνει το HAR για το URL WebSocket Chathub, εξάγει τα
`access_token` και `chathubPath` και συμπληρώνει αυτόματα τα πεδία διαπιστευτηρίων. Η
εισαγωγή HAR αποκωδικοποιεί τη λήξη του JWT και εμφανίζει τον χρόνο ζωής του token που απομένει.

> **Μην υποβάλλετε ποτέ ένα πραγματικό εξαγόμενο HAR, access token ή refresh token.** Οι τιμές δοκιμών και
> τεκμηρίωσης πρέπει πάντα να είναι σύμβολα κράτησης θέσης.

## Διάρκεια ζωής και ανανέωση του token

Το `access_token` είναι βραχύβιο (συνήθως **~75 λεπτά**). Μετά τη λήξη του, ο πάροχος
αναφέρει ένα σφάλμα σύνδεσης και πρέπει να λάβετε ξανά το διαπιστευτήριο.

### Αυτόματη ανανέωση με `refreshToken`

Για να αποφύγετε τη χειροκίνητη επανάληψη της λήψης, μπορείτε να αποθηκεύσετε ένα Microsoft refresh token στο
**Advanced Settings → providerSpecificData** της σύνδεσης:

| Πεδίο          | Περιγραφή                                                                |
| -------------- | ------------------------------------------------------------------------ |
| `refreshToken` | Microsoft OAuth refresh token για το scope `substrate.office.com/sydney` |
| `tier`         | `individual` (προεπιλογή), `edu` ή `enterprise`                          |

Λάβετε το refresh token από μια ροή device-code ή authorization-code της Microsoft
με scope το `substrate.office.com/sydney`. Όταν έχει οριστεί το `refreshToken`, το OmniRoute
ανανεώνει προληπτικά το `access_token` πριν από κάθε αίτημα, ώστε να μην χρειάζεται να
το λαμβάνετε ξανά μετά από κάθε λήξη διάρκειας ~75 λεπτών.

Εάν δεν έχει οριστεί το `refreshToken`, πρέπει να λαμβάνετε ξανά το διαπιστευτήριο WebSocket χειροκίνητα
μετά από κάθε λήξη.

### Επιλογή βαθμίδας

| Βαθμίδα      | Ψευδώνυμο      | Περιβάλλον                      |
| ------------ | -------------- | ------------------------------- |
| `individual` | _(προεπιλογή)_ | M365 Copilot για καταναλωτές    |
| `edu`        | `included`     | M365 Copilot για την εκπαίδευση |
| `enterprise` | `work`         | M365 Copilot για εργασία        |

Ορίστε τη βαθμίδα στο **Advanced Settings → providerSpecificData → tier**. Η βαθμίδα επηρεάζει
τη δρομολόγηση του BizChat και την πρόσβαση στα μοντέλα.

## Μοντέλο ασφάλειας

- **Ανεπίσημη ενσωμάτωση.** Αυτός ο πάροχος βασίζεται σε αντίστροφη μηχανική του πρωτοκόλλου
  WebSocket του BizChat. Ενδέχεται να σταματήσει να λειτουργεί χωρίς προειδοποίηση όταν η Microsoft αλλάξει το endpoint.
- Η σημαία `subscriptionRisk: true` υποδεικνύει ότι η ενσωμάτωση βασίζεται σε ένα
  μη τεκμηριωμένο endpoint. Ενδέχεται να επιβληθούν περιορισμοί στον λογαριασμό, αλλά αυτό δεν έχει επιβεβαιωθεί.
- Το access token είναι ένα βραχύβιο JWT. Αντιμετωπίστε το όπως έναν κωδικό πρόσβασης: μην το κάνετε commit,
  μην το καταγράφετε σε αρχεία καταγραφής και μην το κοινοποιείτε.
- Το refresh token παρέχει μακροχρόνια πρόσβαση στην επιφάνεια του BizChat. Αποθηκεύστε το με την
  ίδια προσοχή που θα αποθηκεύατε ένα κλειδί API.

## Αντιμετώπιση προβλημάτων

### Ο έλεγχος ταυτότητας αποτυγχάνει αμέσως

- Βεβαιωθείτε ότι αντιγράψατε από το **URL του WebSocket** και όχι από ένα αίτημα XHR/Fetch. Το
  διαπιστευτήριο βρίσκεται στην παράμετρο ερωτήματος `access_token` της σύνδεσης WebSocket
  του Chathub — όχι σε μια κεφαλίδα `Authorization: Bearer`.
- Βεβαιωθείτε ότι το `chathubPath` περιλαμβάνει ολόκληρο το τμήμα `<oid>@<tenant>` από τη διαδρομή
  του URL.

### Το token λήγει μετά από ~75 λεπτά

Αυτό είναι αναμενόμενο. Χωρίς `refreshToken`, το access token είναι βραχύβιο. Μπορείτε είτε:

- Να καταγράψετε ξανά το διαπιστευτήριο από τα DevTools είτε
- Να διαμορφώσετε ένα `refreshToken` στις Σύνθετες ρυθμίσεις για αυτόματη ανανέωση.

### Η δοκιμή σύνδεσης επιτυγχάνει, αλλά η συνομιλία επιστρέφει 401

Το token ενδέχεται να έληξε μεταξύ της επικύρωσης και του πρώτου αιτήματος. Καταγράψτε ξανά ένα
πρόσφατο διαπιστευτήριο.

### Το Copilot δεν εμφανίζεται στη λίστα παρόχων

Βεβαιωθείτε ότι το `copilot-m365-web` είναι ενεργοποιημένο στο **Πίνακας ελέγχου → Πάροχοι**. Ο πάροχος ενδέχεται
να είναι κρυφός από προεπιλογή σε ορισμένα επίπεδα συνδρομής.
