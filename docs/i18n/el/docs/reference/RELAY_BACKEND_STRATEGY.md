## Σύνοψη

Το OmniRoute υποστηρίζει πλέον τρεις λειτουργίες αναμετάδοσης για το `/api/v1/relay/chat/completions`:

- `ts`: Χρήση της αναμετάδοσης TypeScript εντός της ίδιας διεργασίας.
- `bifrost`: Υποχρεωτική χρήση της πύλης Bifrost.
- `auto`: Προτίμηση του Bifrost όταν είναι διαθέσιμο, με εναλλακτική μετάβαση στο TypeScript σε περίπτωση αποτυχίας.

Όταν λειτουργείτε με υψηλό ρυθμό αιτημάτων (μεγάλος αριθμός token/ημέρα, σχεδόν σταθερή διεκπεραιωτική ικανότητα), η καλύτερη στρατηγική είναι να διατηρείτε τη διαδρομή εναλλακτικής μετάβασης ρητή και γρήγορη, ώστε η κύρια διαδρομή να μην αναστέλλεται ποτέ εξαιτίας ενός μη λειτουργικού sidecar.

## Συμπεριφορά λειτουργιών

- `ts`
  - Η χαμηλότερη λειτουργική πολυπλοκότητα.
  - Όλη η δρομολόγηση και η επικύρωση εκτελούνται στο Node.
  - Δεν υπάρχει εξάρτηση από sidecar για τη διαθεσιμότητα.
- `bifrost`
  - Υποχρεωτική διοχέτευση όλων των αιτημάτων μέσω της πύλης sidecar.
  - Δεν υπάρχει αυτόματη εναλλακτική μετάβαση.
  - Χρήσιμο μόνο όταν η εύρυθμη λειτουργία και ο χρόνος απόκρισης του sidecar είναι εγγυημένα.
- `auto`
  - Το sidecar χρησιμοποιείται όταν είναι προσβάσιμο και ενεργοποιημένο.
  - Οι αποτυχημένες προσπάθειες ενεργοποιούν κεφαλίδες εναλλακτικής μετάβασης και επιστρέφουν την κίνηση στο TS, ώστε η επιτυχής εξυπηρέτηση των αιτημάτων να παραμένει εντός ορίων.
  - Αυτή η λειτουργία είναι η ασφαλέστερη επιλογή για περιβάλλον παραγωγής, όταν ο χρόνος αδιάλειπτης λειτουργίας είναι σημαντικότερος από την αυστηρή δρομολόγηση αποκλειστικά μέσω sidecar.

## 9router έναντι CLIPROXYAPI σήμερα

Τα 9router και CLIPROXYAPI είναι και τα δύο ενσωματώσεις που ιστορικά παρείχαν διαδρομές συμβατότητας για ανάντη παρόχους.

- Το 9router είναι μια ενσωματωμένη διαδρομή για την ενορχήστρωση ανάντη υπηρεσιών και τη συμπεριφορά συμβατότητας.
- Το CLIPROXYAPI είναι μια γέφυρα API μεσολάβησης για κίνηση τύπου CLI / SDK.
- Το Bifrost σταθεροποιείται ως η εξωτερικευμένη διαδρομή όταν χρειάζεστε ένα αποκλειστικό ενδιάμεσο βήμα τύπου sidecar και τοπική διεκπεραίωση χαμηλού χρόνου απόκρισης.

Αν συγκρίνετε επί του παρόντος τα 9router/CLIPROXYAPI:

- Διατηρήστε την υπογραφή αιτημάτων, τους ελέγχους λίστας επιτρεπόμενων και τις πύλες πολιτικής της DB στη διαδρομή API πριν από την παράδοση.
- Αν μια ροή εργασίας απαιτεί αυστηρή συμπεριφορά sidecar και μικρότερη διακύμανση ανά αίτημα, χρησιμοποιήστε `OMNIROUTE_RELAY_BACKEND=bifrost`.
- Αν χρειάζεστε ανθεκτικότητα του sidecar με ομαλή υποβάθμιση σε συνθήκες συμβάντος, χρησιμοποιήστε `OMNIROUTE_RELAY_BACKEND=auto`.

## Σύμβαση ορίου backend

Το σταθερό όριο του προϊόντος είναι το API αναμετάδοσης του OmniRoute και όχι η υλοποίηση του πίνακα ελέγχου. Ο πίνακας ελέγχου Next.js μπορεί να εγκαθιστά, να διαμορφώνει και να επιβλέπει τοπικές υπηρεσίες, αλλά η δρομολόγηση αιτημάτων θα πρέπει να εισέρχεται μέσω του API αναμετάδοσης και να παραδίδεται πίσω από αυτό το όριο.

Μακροπρόθεσμες επιλογές backend:

- Διατηρήστε την αναμετάδοση TypeScript ως τη διαδρομή πολιτικής και εναλλακτικής μετάβασης εντός της ίδιας διεργασίας. Ο έλεγχος ταυτότητας, οι λίστες επιτρεπόμενων, η κανονικοποίηση αιτημάτων, η λογιστική καταγραφή και οι έλεγχοι ασφαλείας παραμένουν εδώ πριν από οποιαδήποτε παράδοση σε backend.
- Χρησιμοποιήστε το Bifrost ως το προτιμώμενο sidecar επιπέδου Tier-1 για υψηλή διεκπεραιωτική ικανότητα, όταν η ανάπτυξη απαιτεί μικρότερη διακύμανση δρομολόγησης, κεντρική εναλλαγή παρόχων ή οριζόντια κλιμάκωση σε πολλαπλά αντίγραφα του OmniRoute.
- Διατηρήστε τα 9router και CLIPROXYAPI ως ενσωματωμένες υπηρεσίες συμβατότητας. Εκτελούνται ως επιβλεπόμενες τοπικές διεργασίες και είναι χρήσιμα όταν η συμπεριφορά παρόχου/CLI που προσφέρουν είναι ο επιθυμητός προσαρμογέας, αλλά δεν θα πρέπει να γίνουν η προεπιλεγμένη μηχανή δρομολόγησης Tier-1.
- Μην επιτρέπετε στον πίνακα ελέγχου να διοχετεύει αυθαίρετα URL υπηρεσιών στην κύρια διαδρομή. Τα URL που παρέχονται από το UI είναι είσοδοι διαμόρφωσης· ο κώδικας δρομολόγησης θα πρέπει να επιλύει καταχωρισμένα backend με ελεγμένη εύρυθμη λειτουργία από ρυθμίσεις διακομιστή και από την κατάσταση του επόπτη.
- Προς το παρόν, προτιμήστε HTTP μέσω loopback για επιβλεπόμενες υπηρεσίες, επειδή οι διαχειριζόμενες διεργασίες παρέχουν ήδη API συμβατά με HTTP, ο μηχανισμός προστασίας της διαδρομής μπορεί να ελέγχει το όριο και η συμπεριφορά αποτυχίας/εναλλακτικής μετάβασης είναι ορατή στα αρχεία καταγραφής αιτημάτων. Μια μελλοντική μεταφορά μέσω SDK ή socket αξίζει να προστεθεί μόνο αν μειώνει μετρήσιμα τον χρόνο απόκρισης δρομολόγησης p99 χωρίς να αποδυναμώνει την απομόνωση ή τη σημασιολογία εναλλακτικής μετάβασης.

Για μια ανάπτυξη πολύ υψηλής διεκπεραιωτικής ικανότητας, η προεπιλεγμένη απάντηση είναι επομένως `auto` με ενεργοποιημένο το Bifrost: χρησιμοποιήστε το sidecar σε Go στην κύρια διαδρομή, διατηρώντας παράλληλα την εναλλακτική μετάβαση στο TypeScript για υψηλό ποσοστό επιτυχίας. Χρησιμοποιήστε το `bifrost` μόνο όταν η αυστηρή λειτουργία αποκλειστικά μέσω sidecar είναι σημαντικότερη από την ομαλή υποβάθμιση.

## Οδηγίες για υψηλή διεκπεραιωτική ικανότητα

Για διατηρούμενα υψηλά RPM/RPS και αυστηρό SLO επιτυχίας:

1. Χρησιμοποιήστε το `auto` με πρακτικό χρόνο αναμονής και τηλεμετρία αποτυχιών.
2. Διατηρήστε την επικύρωση ανάντη υπηρεσιών και τους ελέγχους κλειδιών API στο όριο της διαδρομής TypeScript.
3. Ενεργοποιήστε ρητές κεφαλίδες/μετρητές, ώστε οι ειδοποιήσεις σας να εντοπίζουν τη συχνότητα και τους λόγους εναλλακτικής μετάβασης.
4. Ρυθμίστε τα χρονικά όρια του sidecar ώστε να αποτυγχάνει γρήγορα και όχι να περιμένει επ’ αόριστον.
5. Διατηρήστε σε εύρυθμη λειτουργία την αυτόματη επανεκκίνηση υπηρεσιών και τον βρόχο τηλεμετρίας εύρυθμης λειτουργίας, ώστε η εναλλακτική μετάβαση να αποτελεί πράγματι εξαίρεση.

## Προτεινόμενη βασική διαμόρφωση

- `OMNIROUTE_RELAY_BACKEND=auto`
- `BIFROST_ENABLED=1`
- Διατηρήστε ενεργοποιημένα τα κλειδιά API, τη λίστα επιτρεπόμενων, τον μηχανισμό εξυγίανσης και τους ελέγχους ορίων ρυθμού στους χειριστές διαδρομών (εκτελούνται πάντα πριν από την προώθηση σε κατάντη υπηρεσίες).
- Εξαγάγετε μετρικές εναλλακτικής μετάβασης από τον reverse proxy και τα αρχεία καταγραφής αιτημάτων σας, ώστε οι διακοπές λειτουργίας του sidecar να γίνονται ορατές εντός ενός λεπτού.

## Σύμβαση πρόσθετου παρόχου

Τα sidecar θα πρέπει να εισάγουν μεταδεδομένα παρόχων μέσω του δηλωτικού πρόσθετων παρόχου που είναι ασφαλές για JSON, αντί να εξαρτώνται από τις εσωτερικές λεπτομέρειες των εκτελεστών TypeScript. Ανατρέξτε στο
[Δηλωτικό πρόσθετων παρόχου](./PROVIDER_PLUGIN_MANIFEST.md) για τη σύμβαση
καταλληλότητας sidecar και τις φάσεις μετάβασης.
