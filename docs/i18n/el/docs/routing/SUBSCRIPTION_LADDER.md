> Δύο νέα αναγνωριστικά `auto/*` — `auto/subscription` και `auto/thrifty`. Και τα δύο ενεργοποιούνται μόνο
> όταν ζητηθούν: τίποτα δεν δρομολογείται μέσω αυτών, εκτός αν ένας καλών ζητήσει ονομαστικά το
> αναγνωριστικό, και δεν αλλάζει κανένα υπάρχον pool, strategy ή default.

## Γιατί υπάρχει αυτό

Το OmniRoute απαντά ήδη σε δύο ερωτήματα κόστους, αλλά κανένα από αυτά δεν είναι εκείνο που θέτουν οι περισσότεροι διαχειριστές.

| Υπάρχων μηχανισμός                                       | Απαντά                                                  |
| -------------------------------------------------------- | ------------------------------------------------------- |
| `hidePaidModels` (`autoCombo/paidModelFilter.ts`)        | "είναι αυτό το μοντέλο καταχωρισμένο ως δωρεάν;"        |
| `freeAccessPolicy: "strict"` (`strictZeroCostFilter.ts`) | "μπορεί αυτή η σύνδεση να με χρεώσει ποτέ;"             |
| `quotaPreflight` (`combo/quotaExhaustionCutoff.ts`)      | "πλησιάζει αυτή η σύνδεση το όριό της;"                 |
| `budgetCap` / `budgetFallback` (`autoCombo/engine.ts`)   | "περιόρισε τη δαπάνη, υποβάθμισε στη φθηνότερη επιλογή" |

Κάθε μηχανισμός αποκλειστικά δωρεάν χρήσης **αποτυγχάνει σε κλειστή κατάσταση** — ένα εξαντλημένο δωρεάν pool είναι ένα κενό pool, ποτέ
μια μετάβαση προς τα πάνω σε μια επί πληρωμή επιλογή — και κάθε μηχανισμός της επί πληρωμή πλευράς αγνοεί τις βαθμίδες. Κανένα δεν απαντά:

> "Χρησιμοποίησε το quota για το οποίο ήδη πληρώνω. Όταν εξαντληθεί, είτε σταμάτησε είτε ανέβα ένα
> σκαλοπάτι κάθε φορά, περνώντας από τις φθηνότερες επί πληρωμή επιλογές — και επέστρεψε μόλις γίνει reset."

## Η χρέωση είναι χαρακτηριστικό της σύνδεσης, όχι του μοντέλου

Η `classifyTier()` (`open-sse/services/tierResolver.ts`) χρησιμοποιεί ως κλειδί το `(provider, model)` και επιστρέφει
`free | cheap | premium` βάσει των τιμών του καταλόγου. Ωστόσο, το αν ένα αίτημα επιφέρει επιπλέον κόστος
εξαρτάται από **το ποια σύνδεση το εξυπηρετεί**: το ίδιο μοντέλο περιλαμβάνεται στο πρόγραμμα μέσω μιας σύνδεσης OAuth του Claude Code
και χρεώνεται ανά token μέσω μιας σύνδεσης με API key.

Το `provider_connections.auth_type` δεν αποτελεί ασφαλή ένδειξη προς καμία κατεύθυνση — υπάρχουν συνδέσεις OAuth
με ογκοχρέωση και συνδέσεις με API key που περιλαμβάνονται σε πρόγραμμα (ένα seat token του Copilot δεν είναι
API key με ογκοχρέωση). Επομένως, η κλάση χρέωσης προέρχεται από έναν **επιμελημένο κατάλογο**,
`open-sse/config/connectionBillingCatalog.ts`, ο οποίος διαμορφώνεται χειροκίνητα βάσει των δημοσιευμένων όρων κάθε provider —
το ίδιο μοτίβο που έχει ήδη καθιερώσει το `FreeModelBudget.hardStopGuaranteed` για τα δωρεάν μοντέλα.

```ts
type ConnectionBillingClass = "subscription" | "metered" | "keyless" | "unknown";
type ConnectionOverageBehavior = "hard-stop" | "meters-to-paid" | "unknown";
```

Σειρά επίλυσης (`autoCombo/connectionBilling.ts`): το συνθετικό sentinel χωρίς authentication →
`keyless`· μια καταχώριση καταλόγου που αντιστοιχεί τόσο σε provider **όσο και** σε `authType`· μια καταχώριση για ολόκληρο τον provider·
διαφορετικά `unknown`. **Το μη επιμελημένο δεν είναι δωρεάν** — το `unknown` αντιμετωπίζεται ως `metered`
παντού, επομένως ένας provider που προστίθεται αύριο ξεκινά εκτός του σκαλοπατιού subscription και πρέπει να
ενταχθεί σκόπιμα μέσω επιμέλειας.

## Το μοντέλο σκαλοπατιών

Πέντε σκαλοπάτια κατά σειρά κλιμάκωσης. Διαφέρουν σε περισσότερα από την τιμή — καθένα έχει το **δικό του**
σήμα εξάντλησης, γι' αυτό δεν πρόκειται απλώς για ταξινόμηση.

| #   | Σκαλοπάτι      | Συμμετοχή                                             | Εξαντλείται όταν                                           |
| --- | -------------- | ----------------------------------------------------- | ---------------------------------------------------------- |
| 0   | `subscription` | επιμελημένο `billing: "subscription"`                 | το παράθυρο quota βρίσκεται στο όριο αποκοπής ή χαμηλότερα |
| 1   | `keyless`      | η συνθετική διαδρομή χωρίς authentication             | cooldown σύνδεσης / circuit breaker                        |
| 2   | `free`         | σύνδεση με ογκοχρέωση, `classifyTier() === "free"`    | εξαντληθεί το δωρεάν allowance                             |
| 3   | `cheap`        | σύνδεση με ογκοχρέωση, `classifyTier() === "cheap"`   | καταναλωθεί το budget του σκαλοπατιού                      |
| 4   | `premium`      | σύνδεση με ογκοχρέωση, `classifyTier() === "premium"` | καταναλωθεί το budget του σκαλοπατιού                      |

Τα σκαλοπάτια 0-2 εξαντλούνται βάσει **quota**, το οποίο είναι παρατηρήσιμο και ήδη παρακολουθείται. Τα σκαλοπάτια 3-4 δεν έχουν
quota — μια επί πληρωμή σύνδεση εξυπηρετεί επ' αόριστον — επομένως το μόνο λογικό σήμα εξάντλησής τους είναι ένα
**budget** ανά σκαλοπάτι. Χωρίς αυτό, το "κλιμάκωσε όταν εξαντληθεί το cheap" δεν έχει κανένα έναυσμα.

## `auto/subscription` — ασφαλής αποτυχία

Σύνολο = μόνο η βαθμίδα 0, περιορισμένο σε συνδέσεις των οποίων η υπέρβαση ορίου αποτελεί τεκμηριωμένο `hard-stop`, καθεμία από τις οποίες επαληθεύεται σε πραγματικό χρόνο ότι διαθέτει επαρκές υπόλοιπο ποσόστωσης. Οτιδήποτε αμφίσημο αποκλείεται: ένας πάροχος που δεν έχει ελεγχθεί, μια μη επαληθεύσιμη ένδειξη ποσόστωσης, μια παρωχημένη ένδειξη ή μια υπέρβαση που χρεώνεται.

Ένα κενό σύνολο είναι η **επιδιωκόμενη** απάντηση, όχι ελάττωμα — η υπάρχουσα διαδρομή κενού συνόλου του καλούντος το μετατρέπει σε σαφές σφάλμα αντί για σιωπηρή, χρεώσιμη εναλλακτική. Αυτή είναι ολόκληρη η εγγύηση του αναγνωριστικού.

Το `keyless` σκοπίμως **δεν** πληροί τις προϋποθέσεις: αυτή η ομαδοποίηση σημαίνει «το πρόγραμμα για το οποίο πληρώνω», επομένως ένα backend χωρίς έλεγχο ταυτότητας δεν ανήκει σε αυτήν. Χρησιμοποιήστε το `auto/thrifty` (ή το `auto/best-free`) για αυτήν την περίπτωση.

### Ασφάλεια συνδέσεων

Ένας υποψήφιος δεν συνδέεται πάντα με μία μόνο σύνδεση — ένας λογικός υποψήφιος διαθέτει μια λίστα επιτρεπόμενων συνδέσεων `allowedConnectionIds`, ενώ ο λογαριασμός που χρησιμοποιείται πραγματικά επιλέγεται αργότερα, κατά την αποστολή, από το `open-sse/services/combo/autoStrategy.ts`. Επομένως, και οι δύο ομαδοποιήσεις επαληθεύουν **κάθε σύνδεση ξεχωριστά** και επανεγγράφουν το `allowedConnectionIds` ώστε να περιλαμβάνει ακριβώς το υποσύνολο που επιβίωσε — ποτέ ολόκληρη την αρχική λίστα και ποτέ ένα αυθαίρετα επιλεγμένο μέλος. Επειδή το `autoStrategy.ts` ήδη επιβάλλει αυτόν τον πίνακα ως αυστηρή λίστα επιτρεπόμενων συνδέσεων, η επανεγγραφή του εδώ καθιστά τα σύνολα «επαληθευμένο» και «χρησιμοποιείται πραγματικά» ίδια εκ κατασκευής. Πρόκειται για την ίδια αναλλοίωτη συνθήκη και το ίδιο σκεπτικό με το [STRICT_ZERO_COST](./STRICT_ZERO_COST.md).

## `auto/thrifty` — κλιμάκωση κατά μία βαθμίδα τη φορά

Σύνολο = όλες οι βαθμίδες, ταξινομημένες βάσει του δείκτη βαθμίδας, με τους εξαντλημένους υποψηφίους αποκλεισμένους. Η μηχανή `auto` εξακολουθεί να βαθμολογεί **εντός** του συνόλου που απέμεινε: η κλίμακα καθορίζει ποιες βαθμίδες συμμετέχουν, ενώ η βαθμολόγηση καθορίζει ποιος υποψήφιος επικρατεί εντός αυτών. Η σειρά είναι σταθερή μέσα σε κάθε βαθμίδα, επομένως η κατάταξη του ίδιου του μηχανισμού βαθμολόγησης δεν αναδιατάσσεται ποτέ από αυτήν την υπερκείμενη λογική.

Πρόκειται για υπερκείμενη λογική ταξινόμησης + αποκλεισμού, **όχι** για νέο μηχανισμό αποστολής: ο βρόχος υποθετικής εκτέλεσης του `combo.ts` ήδη διατρέχει τους στόχους με τη σειρά και προχωρά στον επόμενο σε περίπτωση αποτυχίας, επομένως μια εξάντληση κατά τον χρόνο εκτέλεσης, την οποία δεν εντόπισε ο προκαταρκτικός έλεγχος, εξακολουθεί να προκαλεί κλιμάκωση στην επόμενη βαθμίδα εντός του ίδιου αιτήματος.

Ενώ το `auto/subscription` αποτυγχάνει **με ασφαλή αποκλεισμό**, το `auto/thrifty` αποτυγχάνει **με ανοιχτή συνέχιση**: μια σύνδεση που περιλαμβάνεται στο πρόγραμμα και δεν διαθέτει αξιοποιήσιμη ένδειξη ποσόστωσης εξακολουθεί να δοκιμάζεται πρώτη. Η δοκιμή της δεν κοστίζει τίποτα και, αν αποδειχθεί ότι έχει εξαντληθεί, η μετάβαση σε περίπτωση αποτυχίας φτάνει ούτως ή άλλως στην επόμενη βαθμίδα — ενώ η άρνηση δοκιμής της θα έστελνε το αίτημα σε μια επί πληρωμή βαθμίδα λόγω έλλειψης τηλεμετρίας, δηλαδή ακριβώς στο αποτέλεσμα που έχει σχεδιαστεί να αποτρέπει η ομαδοποίηση.

## Επιστροφή στο πρόγραμμα μετά από επαναφορά

Τρία ανεξάρτητα στοιχεία πρέπει να λήξουν προτού η δρομολόγηση επιστρέψει στη βαθμίδα 0. Η διόρθωση μόνο ενός από αυτά αφήνει την κλίμακα κολλημένη σε επί πληρωμή βαθμίδες για πολύ χρόνο μετά την αναπλήρωση του προγράμματος.

1. **Η κρυφή μνήμη κατάστασης ποσόστωσης** — το `freeAccessQuota.ts` αποθηκεύει στην κρυφή μνήμη ανά `(provider, connection)` με TTL 180 δευτερολέπτων. Μια καταχώριση στην κρυφή μνήμη της οποίας το ίδιο το `resetAt` έχει ήδη παρέλθει περιγράφει ένα χρονικό παράθυρο που δεν υπάρχει πλέον, επομένως πλέον θεωρείται παρωχημένη **ανεξάρτητα από την ηλικία της** και επιβάλλει ανανέωση. Χωρίς αυτό, ένα πρόγραμμα που αναπληρώθηκε τα μεσάνυχτα εξακολουθεί να εμφανίζεται ως εξαντλημένο μέχρι να λήξει τυχαία το TTL.
2. **Η ίδια η κατάσταση της κλίμακας** — εκ κατασκευής, δεν υπάρχει καμία. Η επιλεξιμότητα των βαθμίδων υπολογίζεται εκ νέου από την ενεργή κατάσταση ποσόστωσης σε κάθε δημιουργία συνόλου· δεν υπάρχει καμία μόνιμα αποθηκευμένη εγγραφή «βρίσκεται επί του παρόντος στη βαθμίδα 3» που θα μπορούσε να παραμείνει μετά από μια επαναφορά και να μπλοκάρει τη δρομολόγηση.
3. **Η περίοδος αναμονής της σύνδεσης** — το 429 που προκαλείται από την εξάντληση ορίζει το `rateLimitedUntil` μέσω εκθετικής υποχώρησης, η οποία για μια σύνδεση προγράμματος μπορεί να υπερβεί την πραγματική χρονική στιγμή επαναφοράς. Το `clampCooldownToReset()` (`subscriptionLadder.ts`) περιορίζει μια περίοδο αναμονής στη χρονική στιγμή επαναφοράς του ανάντη συστήματος και δεν μπορεί ποτέ να την παρατείνει. **Έχει υλοποιηθεί και δοκιμαστεί, αλλά δεν έχει ακόμη συνδεθεί**: η κρυφή μνήμη ποσόστωσης ακυρώνεται στο `src/sse/services/auth.ts` _πριν_ εγγραφεί οποιαδήποτε περίοδος αναμονής, επομένως το `resetAt` πρέπει να καταγραφεί νωρίτερα σε αυτήν τη συνάρτηση — μια αλλαγή στην κρίσιμη διαδρομή ανθεκτικότητας που πρέπει να ενταχθεί σε δικό της, ξεχωριστά ελεγμένο PR. Μέχρι τότε, η επανένταξη περιμένει να παρέλθει η περίοδος αναμονής της σύνδεσης (η οποία ήδη προτιμά τις υποδείξεις `Retry-After` του ανάντη συστήματος, όταν τις αποστέλλει ο πάροχος).

### Αποτροπή ταλάντωσης

Μια βαθμίδα που μόλις επαναφέρθηκε γίνεται ξανά αποδεκτή μόνο πάνω από το `reentryMinRemainingPercent` (προεπιλογή 5), ενώ μια σύνδεση που συμμετέχει ήδη χρειάζεται απλώς να παραμένει πάνω από το `exitCutoffPercent` (προεπιλογή 2, σε αντιστοιχία με το `quotaPreflight.defaultThresholdPercent`). Η διαφορά αποτελεί τη ζώνη υστέρησης — χωρίς αυτήν, μια σύνδεση που κινείται γύρω από το όριο εναλλάσσεται μεταξύ βαθμίδων σε διαδοχικά αιτήματα.

## Ρύθμιση παραμέτρων

Μόνο λεπτομερής ρύθμιση. Σκόπιμα **δεν** υπάρχει σημαία `enabled`: ένας διακόπτης που θα μπορούσε να τις απενεργοποιήσει
θα άφηνε το `auto/subscription` να εξυπηρετεί αθόρυβα ολόκληρη τη δεξαμενή — συμπεριλαμβανομένων των επί πληρωμή μοντέλων — με ένα
όνομα που υπόσχεται το αντίθετο.

```jsonc
{
  "subscriptionLadder": {
    "exitCutoffPercent": 2,
    "reentryMinRemainingPercent": 5,
    "rungBudgetUsd": { "cheap": 5.0, "premium": 0 }, // Το 0 απενεργοποιεί πλήρως ένα σκαλοπάτι
  },
}
```

Ο περιορισμός βάσει προϋπολογισμού παραμένει ανενεργός μέχρι να συνδεθεί ένας μηχανισμός επίλυσης δαπανών: όταν δεν υπάρχει διαθέσιμη λογιστική καταγραφή, ένα επί πληρωμή
σκαλοπάτι ταξινομείται αλλά δεν περιορίζεται ποτέ. Από την v3.8.51, η ρύθμιση `rungBudgetUsd` γίνεται αποδεκτή από το
σχήμα, αλλά ΔΕΝ επιβάλλεται ακόμη — αντιμετωπίστε την ως δεσμευμένη ρύθμιση παραμέτρων και όχι ως ενεργό όριο δαπανών. Η ταξινόμηση των σκαλοπατιών, η εξάντληση βάσει ποσόστωσης και η επανένταξη μετά από επαναφορά
λειτουργούν όλα χωρίς αυτήν.

## Σύνθεση

Τα `subscription` και `thrifty` είναι τιμές `AutoTier`, επομένως συνδυάζονται με κάθε κατηγορία:
`auto/coding:thrifty`, `auto/reasoning:subscription` και ούτω καθεξής. Τα δύο απλά αναγνωριστικά
(`auto/subscription`, `auto/thrifty`) προβάλλονται στο `/v1/models` και στον πίνακα ελέγχου.

Κανένα από τα δύο αναγνωριστικά δεν ανήκει στη βαθμίδα επί πληρωμή, επομένως η `isPaidTierAutoId()` επιστρέφει `false` και για τα δύο, και το
`auto/subscription` παραμένει διαθέσιμο όταν εφαρμόζεται το `hidePaidModels`.
