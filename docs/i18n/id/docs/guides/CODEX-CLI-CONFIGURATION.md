Panduan lengkap untuk menggunakan Codex CLI yang diarahkan ke OmniRoute sebagai backend yang kompatibel dengan OpenAI.

---

> **TOML adalah satu-satunya format yang efektif.** Codex modern membaca `~/.codex/config.toml`
> secara eksklusif (diverifikasi menggunakan codex-cli 0.147.0: `codex --help` mendokumentasikan
> bahwa penggantian `-c/--config` "dimuat dari `~/.codex/config.toml`"). Berkas lama
> `~/.codex/config.yaml` merupakan milik CLI npm lawas dan diabaikan tanpa pemberitahuan.
> Generator dasbor (`/api/cli-tools/apply`, alat `codex`) menulis TOML dengan
> penggabungan konservatif — kunci yang ada dan blok penyedia lainnya dipertahankan,
> kunci API tetap berada di `OMNIROUTE_API_KEY` (tidak pernah di dalam berkas), dan sisa
> `config.yaml` lawas dilaporkan sebagai catatan migrasi tanpa disentuh.

## config.toml siap ditempel

Ganti `<YOUR_HOST>` dan `<YOUR_KEY>` dengan nilai Anda:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # batas penyimpanan riwayat per pemanggilan alat

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc atau ~/.zshrc — nilai kunci sebenarnya, jangan pernah disimpan di config.toml
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: Codex yang disertakan di dalam aplikasi ChatGPT

Jika Anda menginstal Codex melalui aplikasi desktop ChatGPT, biner `codex` mungkin
hanya tersedia di dalam bundel aplikasi dan belum berada di `PATH` shell Anda. Tambahkan
direktori sumber daya ke berkas awal shell Anda:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

Buka shell baru, lalu verifikasi:

```bash
command -v codex
codex --version
```

### OmniRoute lokal tanpa autentikasi: kunci placeholder sudah cukup

Codex memvalidasi bahwa variabel lingkungan yang disebutkan oleh `env_key` tersedia
**sebelum** permintaan pertama dikirim dari CLI. Jika instans OmniRoute **lokal**
Anda tidak memerlukan autentikasi, placeholder apa pun yang tidak kosong dapat digunakan:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

Gunakan kunci asli jika server OmniRoute Anda dilindungi atau berada di lokasi jarak jauh.

> **Opsi host umum**
>
> | Akses          | URL                           |
> | -------------- | ----------------------------- |
> | Jaringan lokal | `http://192.168.0.1:20128/v1` |
> | Tailscale      | `http://100.x.x.x:20128/v1`   |
> | Loopback       | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — alasan konfigurasi ini berfungsi untuk semua model

Codex CLI menghentikan dukungan `wire_api = "chat"` (Chat Completions) pada Februari 2026 dan kini **mewajibkan** `wire_api = "responses"` (OpenAI Responses API). Menetapkan `wire_api = "chat"` menyebabkan crash langsung saat memulai sejak v0.138.

Banyak penyedia, termasuk GLM dan Kimi, masih hanya menyediakan endpoint Chat Completions. DeepSeek V4 kini menyediakan Responses API native serta endpoint yang kompatibel dengan Anthropic; OmniRoute menggunakan Responses secara default dan memungkinkan setiap koneksi DeepSeek memilih kompatibilitas Anthropic.

**OmniRoute menyelesaikan hal ini secara transparan:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute memilih protokol native penyedia dan menerjemahkannya bila diperlukan
    → POST /responses (DeepSeek V4) atau /chat/completions (Mistral / GLM / Kimi / lainnya)
```

Anda tidak pernah memerlukan proksi penerjemahan terpisah saat menggunakan OmniRoute. **Semua model menggunakan `wire_api = "responses"`** — OmniRoute menangani sisanya.

> **`wire_api` adalah nilai default** — bidang ini secara default bernilai `"responses"` dan dapat sepenuhnya dihilangkan dari `config.toml`. Tetapkan secara eksplisit hanya jika Anda ingin mendokumentasikan maksud konfigurasi.

## Jendela konteks dan pemadatan

### Kolom konfigurasi token

| Kolom                            | Deskripsi                                                                                                                                                                                                   |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model_context_window`           | Total anggaran token untuk model aktif. Atur ke batas yang dinyatakan oleh model.                                                                                                                           |
| `model_auto_compact_token_limit` | Ambang batas yang memicu pemadatan riwayat otomatis. **Maksimum: 90% dari `model_context_window`** — nilai di atas 90% diabaikan secara diam-diam.                                                          |
| `tool_output_token_limit`        | Batas token yang disimpan untuk setiap output pemanggilan alat dalam riwayat. Mencegah satu respons alat yang besar memenuhi jendela. **Ini bukan output maksimum** — ini adalah batas penyimpanan riwayat. |
| `compact_prompt`                 | Penggantian sebaris untuk prompt sistem yang digunakan selama pemadatan (v0.138+).                                                                                                                          |

> **Catatan tentang `model_max_output_tokens`**: Kolom ini **bukan bagian dari skema konfigurasi Codex CLI** (tidak ada dalam basis kode Codex Rust). Kolom ini diabaikan secara diam-diam jika diatur. Jangan mengandalkannya — gunakan `tool_output_token_limit` untuk mengontrol seberapa banyak output alat yang disimpan dalam riwayat.

## Upaya Penalaran

Mengatur seberapa banyak model "berpikir" sebelum merespons.

| Nilai    | Digunakan untuk                                 |
| -------- | ----------------------------------------------- |
| `none`   | Tanpa penalaran — respons langsung              |
| `low`    | Tugas sederhana (mengganti nama, memformat)     |
| `medium` | **Default server** jika tidak ditentukan        |
| `high`   | Tugas tingkat menengah (refaktor, debug)        |
| `xhigh`  | Arsitektur, analisis mendalam, masalah kompleks |

```bash
# Penimpaan per pemanggilan
codex -c model_reasoning_effort=low "rename variable x to count"
codex -c model_reasoning_effort=xhigh "design the auth module"
```

Tetapkan juga **ringkasan** penalaran agar Desktop dapat merender teks pemikiran (bukan hanya blob terenkripsi):

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # atau ultra jika didukung
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### Anggaran Pemikiran OmniRoute (pengaturan server)

Pada host OmniRoute, **Settings → AI → Thinking Budget** harus diatur ke **`passthrough`** agar upaya/ringkasan Codex diteruskan ke upstream. Mode **`auto` menghapus** semua kolom `reasoning` / `reasoning_effort` dari klien dan akan mengosongkan panel pemikiran meskipun Codex telah dikonfigurasi dengan benar.

Panduan lengkap: [THINKING_BUDGET.md](./THINKING_BUDGET.md).

Kompresi dan cache prompt bersifat independen dan tetap berfungsi dalam mode `passthrough`.

## Profil — konfigurasi bernama untuk setiap model/alur kerja

Profil memungkinkan Anda mengganti model + jendela konteks dengan satu flag. Setiap profil berupa
`~/.codex/<name>.config.toml` datar yang ditumpangkan di atas `config.toml` dasar.

> **Aturan penamaan (Codex CLI v0.137+):** file harus berupa `~/.codex/<name>.config.toml` — **tanpa prefiks `profile-`**.
> CLI memetakan `-p kimi-k27` → `~/.codex/kimi-k27.config.toml`. Jika file tidak ditemukan, konfigurasi default diterapkan tanpa pemberitahuan.

```bash
codex --profile kimi-k27 "analyze 10k lines of this codebase"
codex -p glm52 "architecture review"
codex --profile deepseek-flash "rename variable"   # cepat, murah
```

### Profil upaya (model yang sama, upaya berbeda)

```bash
codex -p low      # cx/gpt-5.5, effort=low
codex -p medium   # cx/gpt-5.5, effort=medium
codex -p high     # cx/gpt-5.5, effort=high
codex -p xhigh    # cx/gpt-5.5, effort=xhigh (default)
codex -p chat     # cx/gpt-5.5, tanpa effort yang ditetapkan (default server)
```

## Membuat profil secara otomatis dengan `omniroute setup-codex`

Jika Anda menjalankan OmniRoute di VPS, Anda dapat membuat file profil secara otomatis dari katalog model aktif:

```bash
# Dari VPS (menggunakan OmniRoute lokal pada port 20128)
omniroute setup-codex

# Dari mesin mana pun — arahkan ke VPS Anda
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# Pratinjau tanpa menulis file
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# Hanya buat profil GLM dan Kimi
omniroute setup-codex --only glm,kimi

# Tulis ke direktori khusus
omniroute setup-codex --codex-home /path/to/.codex
```

Perintah ini mengambil `/v1/models`, menggunakan profil yang telah disesuaikan untuk model yang dikenal, menggunakan metadata katalog sebagai cadangan untuk model teks kompatibel lainnya, dan menulis `~/.codex/<name>.config.toml` untuk masing-masing model. Bersifat idempoten — aman untuk dijalankan ulang.

OmniRoute juga dapat **menyinkronkan secara otomatis** file profil yang sama setelah penemuan/impor model penyedia yang berhasil mengubah katalog aktif. Fitur ini **harus diaktifkan secara eksplisit dan dinonaktifkan secara default**: aktifkan dari **dasbor CLI Code** ("Sinkronisasi otomatis profil CLI" → Codex), atau tetapkan `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` (fitur ini juga mematuhi `CLI_ALLOW_CONFIG_WRITES`, yang aktif secara default). Saat diaktifkan, fitur ini hanya menulis file profil `~/.codex/*.config.toml` yang terpisah; fitur ini tidak pernah mengubah `~/.codex/config.toml` aktif/default, pengaturan Codex-lb, autentikasi, atau pemilihan penyedia.

## Menjalankan Codex dengan `omniroute launch-codex`

Memeriksa kesehatan instans OmniRoute Anda sebelum menjalankan Codex:


## Tugas yang berjalan lama

Dua nilai bawaan OmniRoute dapat secara diam-diam menyabotase sesi Codex CLI yang berlangsung selama berjam-jam. Keduanya bukan pengaturan Codex CLI — keduanya berada di sisi OmniRoute. Pengguna yang memigrasikan konfigurasi dari proksi upstream yang mempertahankan akun dan menonaktifkan batas waktu idle sering kali mengalami keduanya dan menyimpulkan bahwa OmniRoute “tidak dapat mempertahankan sesi yang panjang.”

| Gejala                                                                       | Kemungkinan penyebab                                               | Pengaturan               |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------ | ------------------------ |
| Sesi terus berganti akun / kontinuitas cache prompt hilang di antara giliran | TTL afinitas sesi adalah `0` (dinonaktifkan)                       | `sessionAffinityTtlMs`   |
| Koneksi terputus saat proses penalaran tanpa prompt yang terlihat oleh klien | Pengawas idle stream terpicu setelah 10 menit tanpa chunk upstream | `STREAM_IDLE_TIMEOUT_MS` |

Diskusi terkait: [#7126](https://github.com/diegosouzapw/OmniRoute/discussions/7126) (tugas panjang terputus), [#5718](https://github.com/diegosouzapw/OmniRoute/discussions/5718) (alasan afinitas dinonaktifkan secara bawaan). Pelacakan: [#7287](https://github.com/diegosouzapw/OmniRoute/issues/7287).

### 1. Afinitas sesi — pertahankan satu percakapan pada satu akun

**Bawaan:** `sessionAffinityTtlMs = 0` (dinonaktifkan).

**Tempat mengaturnya**

- Dasbor → **Pengaturan → Perutean** → **Afinitas sesi** → **TTL afinitas (detik)** (`ComboDefaultsTab`)
- Atau lakukan PATCH pada pengaturan dengan `sessionAffinityTtlMs` dalam **milidetik** (rentang Zod `0`–`86_400_000`, yaitu hingga 24 jam)

> Diubah namanya dalam #7274 dari `codexSessionAffinityTtlMs` yang khusus untuk Codex. Kunci lama masih diterima sebagai alias hanya-baca; konfigurasi baru harus menggunakan `sessionAffinityTtlMs`. Afinitas kini berlaku untuk **semua** penyedia setelah TTL lebih besar dari `0`, bukan hanya Codex — lihat [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → Afinitas sesi.

**Hal yang rusak ketika nilainya tetap 0**

Setiap giliran dalam percakapan Codex dengan banyak giliran dirutekan secara independen oleh strategi kombinasi yang aktif dan dapat diarahkan ke **akun yang berbeda pada setiap giliran**. Hal itu merusak kontinuitas sesi / cache prompt upstream. OmniRoute hanya memeriksa header sesi Codex (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) dan bidang isi seperti `prompt_cache_key` / `session_id` ketika TTL lebih besar dari `0` (`extractSessionAffinityKey` dalam `src/sse/services/auth.ts`).

**Rekomendasi untuk satu tugas yang berlangsung selama beberapa jam**

Atur TTL agar **lebih lama daripada perkiraan durasi waktu nyata tugas tersebut** (maksimum UI adalah **86400 detik** = 24 jam):

| Perkiraan durasi tugas | TTL afinitas (UI, detik) | `sessionAffinityTtlMs` |
| ---------------------- | ------------------------ | ---------------------- |
| Beberapa jam           | `14400` (4j)             | `14400000`             |
| Semalaman / ~12j       | `43200` (12j)            | `43200000`             |
| Sehari penuh           | `86400` (24j, maksimum)  | `86400000`             |

Keikutsertaan bersifat disengaja: menonaktifkan afinitas mengutamakan penyeimbangan beban di antara akun; mengaktifkannya mengutamakan kontinuitas untuk satu sesi agen yang panjang. Panduan ini **tidak** mengubah nilai bawaan — operator yang menjalankan tugas Codex berdurasi panjang harus mengaktifkannya sendiri.

### 2. Batas waktu idle stream — jangan hentikan giliran penalaran yang tenang

**Bawaan:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 menit). Nilai ini diwarisi dari `REQUEST_TIMEOUT_MS` jika tidak ditetapkan; nilai dasar bersama juga 600000. Lihat [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → Batas waktu.

**Hal yang rusak dengan nilai bawaan**

Giliran penalaran / tool Codex yang tetap diam selama lebih dari 10 menit dengan **tidak ada chunk upstream nyata** akan ditutup paksa oleh pengawas idle SSE (`open-sse/utils/stream.ts`). Klien sering kali hanya melihat koneksi terputus begitu saja — sesuai dengan kondisi “berhenti otomatis tanpa pemberitahuan.”

Detail penting: **heartbeat** SSE sintetis OmniRoute tidak mereset penghitung waktu idle. Hanya chunk body upstream nyata yang memperbarui `lastChunkTime`. Model yang diam tetapi masih “berpikir” terlihat sama dengan upstream yang macet dari sudut pandang pengawas.

Terkait inaktivitas body Undici: `FETCH_BODY_TIMEOUT_MS` (nilai default-nya juga menggunakan baseline 10 menit yang sama; `0` menonaktifkannya). Untuk streaming, `FETCH_TIMEOUT_MS` hanya mencakup penyiapan koneksi / header pertama — setelah stream aktif, kondisi macet diatur oleh `STREAM_IDLE_TIMEOUT_MS` dan `FETCH_BODY_TIMEOUT_MS`.

**Rekomendasi untuk satu tugas berdurasi beberapa jam**

Di lingkungan proses OmniRoute (`.env` / compose / systemd):

```bash
# Nonaktifkan batas waktu idle stream + inaktivitas body untuk giliran penalaran yang panjang
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

Atau naikkan nilainya agar melebihi jeda diam terlama yang Anda perkirakan (nilai dalam milidetik):

```bash
# Contoh: izinkan hingga 2 jam tanpa aktivitas di antara chunk upstream
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

Mulai ulang OmniRoute setelah mengubah variabel lingkungan ini.

### Langkah konkret — tugas Codex berdurasi beberapa jam

1. **Sematkan akun:** Dashboard → Settings → Routing → Session affinity → Affinity TTL = `43200` (12 jam) atau `86400` (maks. 24 jam).
2. **Naikkan / nonaktifkan batas waktu idle** di lingkungan OmniRoute:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. Pertahankan `config.toml` Codex seperti biasa (`wire_api = "responses"`, `base_url` yang benar, `OMNIROUTE_API_KEY`) — tidak ada pengaturan afinitas/idle di sisi Codex untuk kedua perilaku ini.
4. Mulai ulang OmniRoute, lalu mulai tugas Codex berdurasi panjang.

### Keputusan nilai default (#7287)

| Pengaturan               | Nilai default rilis | Diubah dalam panduan ini?                                                                                           |
| ------------------------ | ------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (nonaktif)      | **Tidak** — tetap bersifat opt-in (penyeimbangan beban vs kontinuitas; lihat Discussion #5718)                      |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 menit) | **Tidak** — tetap 10 menit untuk lalu lintas umum; operator Codex berdurasi panjang menaikkan atau menonaktifkannya |

Mengubah salah satu nilai default secara global akan mengubah perilaku untuk setiap klien pada sebuah instans, bukan hanya Codex. Dokumentasikan pengaturannya; biarkan nilai default tetap seperti semula hingga ada keputusan eksplisit dari operator yang menyatakan sebaliknya.

### Mendiagnosis pemutusan akibat idle

Saat pengawas idle terpicu, OmniRoute mencatat baris dengan bentuk seperti:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

Lakukan grep untuk `Idle timeout: no data from` (atau kode `stream_idle_timeout` / nama error `StreamIdleTimeoutError`). Segmen penyedia adalah apa pun yang digunakan OmniRoute untuk permintaan tersebut (`codex`, id penyedia lain, atau `provider` jika tidak diketahui) — nilainya tidak selalu berupa string literal `codex`.

## Pemecahan Masalah

**`Error: wire_api = "chat" tidak lagi didukung`**
Hapus `wire_api = "chat"` dari konfigurasi Anda. Tetapkan `wire_api = "responses"` atau hilangkan kolom tersebut (nilai default-nya adalah `"responses"` sejak v0.138).

**`Error: model tidak ditemukan`**
Pastikan model tersedia di OmniRoute dengan prefiks yang benar. Gunakan `omniroute models list` atau buka `/dashboard/providers/<provider>`.

**`Kesalahan autentikasi`**
Pastikan `OMNIROUTE_API_KEY` telah diekspor: `echo $OMNIROUTE_API_KEY`.

**`ERROR: Variabel lingkungan tidak ada: OMNIROUTE_API_KEY`**
Codex memvalidasi bahwa variabel lingkungan tersebut tersedia sebelum membuat permintaan pertama. Ekspor
kunci asli untuk server yang dilindungi, atau placeholder yang tidak kosong seperti
`OMNIROUTE_API_KEY=local` jika instans OmniRoute **lokal** Anda tidak
memerlukan autentikasi. Mulai ulang shell jika Anda menambahkannya ke `~/.bashrc` atau `~/.zshrc`.

**`Koneksi ditolak`**
Pastikan OmniRoute berjalan dan host/port `base_url` sudah benar untuk jaringan Anda (lokal vs Tailscale vs VPS).

**Sesi mengalami crash saat mendekati batas konteks**
Tetapkan `model_context_window` dan `model_auto_compact_token_limit` secara eksplisit. Lihat tabel jendela konteks di atas.

**Pemadatan dijalankan terlalu lambat**
Turunkan `model_auto_compact_token_limit` menjadi 80–85% dari jendela. Jangan pernah menetapkannya di atas 90%.

**Profil tidak dimuat (`-p <name>` diabaikan tanpa pemberitahuan)**
Pastikan berkas tersedia di `~/.codex/<name>.config.toml` (tanpa prefiks `profile-`). Jalankan `ls ~/.codex/*.config.toml`.

**Tugas Codex yang berlangsung lama terputus di tengah proses / berganti akun di antara giliran**
Lihat [Tugas yang berlangsung lama](#long-running-tasks). Aktifkan afinitas sesi (TTL lebih lama daripada durasi tugas) dan naikkan nilainya atau nonaktifkan `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS`. Cari `Idle timeout: no data from` di log OmniRoute menggunakan grep.
