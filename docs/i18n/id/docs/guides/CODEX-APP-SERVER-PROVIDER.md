OmniRoute menyediakan **dua** cara untuk menggunakan OpenAI Codex:

| Penyedia               | Cara berkomunikasi dengan OpenAI                                                                                                                                                              | Catatan penggunaan                                                           |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| **`codex`**            | Mengirim ulang token OAuth ChatGPT/OpenAI Anda secara langsung ke Responses API                                                                                                               | **Ya** — sesi resmi tidak diotorisasi untuk penggunaan melalui proksi/router |
| **`codex-app-server`** | Mengendalikan **`codex app-server` milik Codex CLI** melalui JSON-RPC/WebSocket; CLI memiliki dan memperbarui sendiri OAuth-nya (`~/.codex/auth.json`) persis seperti sesi `codex` interaktif | **Tidak** — OmniRoute tidak pernah mengirim ulang token ke API               |

Karena `codex-app-server` tidak pernah mengirim ulang token, penyedia ini tidak
memiliki catatan penggunaan terkait pengiriman ulang sesi. Namun, penyedia ini
memerlukan **Codex CLI yang dapat dijangkau melalui URL app-server yang
dikonfigurasi**, dan CLI tersebut harus sudah **masuk**.

---

## 1. Arsitektur

```
┌─ Aplikasi OmniRoute ─────────────┐        ┌─ sidecar codex-app-server ──────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ token kapabilitas)           │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  mengelola sendiri OAuth OpenAI     │
└──────────────────────────────────┘        │  (~/.codex/auth.json, pembaruan     │
        │ berbagi (volume compose)           │   otomatis)                         │
        ▼                                   └─────────────────────────────────────┘
  codex-appserver-token   → token kapabilitas WS (dipasang oleh keduanya)
  codex-appserver-home    → ~/.codex (auth.json ditulis oleh dasbor,
                             dibaca oleh codex app-server milik sidecar)
```

- Sidecar hanya mendengarkan di jaringan compose internal
  (`ws://codex-app-server:1456`) di balik token kapabilitas. Sidecar ini **tidak
  pernah** dipublikasikan ke host atau internet.
- Codex CLI sudah disertakan di dalam `omniroute:base`, sehingga Codex tidak
  perlu diinstal pada host atau mesin pengguna saat Anda menjalankan sidecar.

## 2. Menjalankannya

```bash
# Mulai stack DENGAN profil sidecar codex app-server:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

Sidecar membuat token kapabilitas WS-nya saat boot pertama (ke dalam volume
bersama `codex-appserver-token`), dan aplikasi membaca token yang sama melalui
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE`. Tidak diperlukan konfigurasi token
secara manual.

## 3. Hubungkan + masuk

1. Di dasbor, tambahkan koneksi untuk **OpenAI Codex (App-Server)**. Tidak
   diperlukan kunci API atau token (ini adalah penyedia tanpa autentikasi —
   sidecar yang menangani autentikasi).
2. Jika Codex CLI milik sidecar **belum masuk**, pemeriksaan kesehatan koneksi
   akan melaporkan _"berjalan tetapi belum masuk"_ (bukan galat autentikasi
   berwarna merah). Gunakan **Masuk dengan ChatGPT**: tindakan ini menjalankan
   OAuth perangkat Codex standar di browser Anda, lalu menulis
   `~/.codex/auth.json` ke dalam volume bersama melalui **Terapkan autentikasi**
   (satu login yang sama melayani penyedia `codex` dan `codex-app-server`).
3. Setelah masuk, pemeriksaan kesehatan berubah menjadi hijau (pemeriksaan ini
   memverifikasi `/readyz` **dan** `account/read` — yaitu aktif _dan_
   terautentikasi) dan mulai berfungsi.

Dasbor tidak pernah menimpa `~/.codex/auth.json` yang sudah ada dan masih valid
— dasbor hanya menulis ketika berkas tersebut tidak ada atau tokennya sudah
usang (cadangan selalu dibuat).

## 4. Skenario deployment

- **Operator dengan Codex CLI yang sudah terautentikasi** — pasang `~/.codex`
  dari host Anda ke sidecar (`codex-appserver-home`) dan lewati langkah masuk.
- **Pengguna publik, Codex tidak terinstal secara lokal** — tidak menjadi
  masalah: sidecar sudah memiliki CLI. Pengguna hanya melakukan autentikasi
  melalui dasbor.
- **OmniRoute bare-metal (tanpa sidecar, Codex pada host)** — arahkan
  `OMNIROUTE_CODEX_APPSERVER_WS` ke `codex app-server` Anda sendiri dan pastikan
  Codex pada host sudah masuk; petunjuk "Codex belum terinstal" akan muncul jika
  berkas biner tidak tersedia.

## 5. Egress residensial/UDP (tambahan untuk operator, tidak disertakan)

Sidecar generik di atas melakukan egress melalui jaringan normal kontainer.
Operator yang memerlukan lalu lintas Codex untuk melakukan egress melalui
**exit residensial** (misalnya sidecar Tailscale TUN yang membawa TCP + UDP/QUIC)
menjalankannya sebagai override compose terpisah; konfigurasi tersebut sengaja
**tidak** disertakan sebagai bagian dari profil `codex-app-server` yang
didistribusikan. Lihat runbook operasi internal untuk penyiapan tersebut.
