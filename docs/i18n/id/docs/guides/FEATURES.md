## 🔌 Penyedia

Kelola koneksi penyedia AI: penyedia OAuth (Claude Code, Codex), penyedia kunci API (Groq, DeepSeek, OpenRouter), dan penyedia gratis (Qoder, Kiro). Akun Kiro mencakup pelacakan saldo kredit — sisa kredit, total alokasi, dan tanggal perpanjangan dapat dilihat di Dasbor → Penggunaan.

Koneksi OpenRouter dapat menyimpan `preset` per koneksi di Pengaturan Lanjutan. Jika ditetapkan, OmniRoute akan mengirimkannya sebagai bidang permintaan tingkat teratas OpenRouter, misalnya `"preset": "email-copywriter"`, kecuali permintaan klien telah menyediakan `preset` sendiri.

## 🎨 Kombo

Buat kombo perutean model dengan 19 strategi publik: prioritas, berbobot, round-robin, context-relay, fill-first, p2c (pilihan dua pangkat), acak, paling jarang digunakan, dioptimalkan untuk biaya, reset-aware, reset-window, headroom, strict-random, otomatis, lkgp (penyedia terakhir yang diketahui berfungsi), dioptimalkan untuk konteks, dioptimalkan untuk cache, **fusion** (menyebarkan permintaan ke panel model secara paralel, lalu menyintesis satu jawaban melalui penilai), dan **pipeline**. Setiap kombo merangkai beberapa model dengan fallback otomatis serta mencakup templat cepat dan pemeriksaan kesiapan.

Peningkatan kombo terbaru:

- **Pembuat kombo terstruktur** — buat setiap langkah dengan memilih penyedia, model, dan akun/koneksi yang tepat
- **Dukungan penyedia berulang** — gunakan kembali penyedia yang sama berkali-kali dalam satu kombo selama tuple `(provider, model, connection)` unik
- **Kesehatan target kombo** — tampilan analitik dan kesehatan kini membedakan setiap target/langkah kombo alih-alih menggabungkan semuanya menjadi string model
- **Urutan tingkat komposit** — `defaultTier -> fallbackTier` kini memengaruhi urutan eksekusi/fallback saat runtime untuk langkah kombo tingkat teratas
- **Templat prompt sistem** — `system_message` kombo mendukung placeholder sisi server
  `{{MODEL_ID}}`, `{{PROVIDER_ID}}`, `{{ACCOUNT}}`, dan `{{FINGERPRINT}}`
  yang diperluas berdasarkan target yang benar-benar dirutekan tepat sebelum pengiriman.
  Menggunakan daftar yang diizinkan dan tidak rekursif; placeholder yang tidak dikenal tetap literal; nilai kosong
  diperluas menjadi kosong; prompt sistem klien tidak pernah ditulis ulang. `{{FINGERPRINT}}`
  hanya di-resolve untuk penyedia gratis berbasis fingerprint dengan fingerprint yang disematkan atau
  dirotasi otomatis — nilainya diperluas menjadi kosong di tempat lain (misalnya
  koneksi dengan satu fingerprint, penyedia non-fp). Perluasan mencakup
  loop pengiriman standar, round-robin, dan sesi cache konteks yang disematkan;
  strategi fusion, chaos, pipeline, dan nested-execute belum memperluas
  placeholder.

## ⚙️ Pengaturan

Panel pengaturan komprehensif dengan **7 tab**:

- **Umum** — Penyimpanan sistem, pengelolaan cadangan (ekspor/impor basis data)
- **Tampilan** — Pemilih tema (gelap/terang/sistem), prasetel tema warna dan warna khusus, visibilitas log kesehatan, kontrol visibilitas item bilah samping dan pemisah grup, kontrol visibilitas tunnel Endpoint
- **AI** — Fitur asisten AI, prasetel perutean default (Kombinasi Otomatis `auto/coding`, `auto/fast`, `auto/cheap`, `auto/smart`), cache pemutaran ulang penalaran, serta tombol aktif/nonaktif keterampilan/memori
- **Keamanan** — Perlindungan endpoint API, pemblokiran penyedia khusus, pemfilteran IP, informasi sesi
- **Perutean** — Alias model, degradasi tugas latar belakang, perutean tingkat berbasis manifest (W1–W4), `fallbackDelayMs`, perutean persisten per sesi
- **Ketahanan** — Persistensi batas laju, penyesuaian circuit breaker, penonaktifan otomatis akun yang diblokir, pemantauan masa berlaku penyedia, ambang serah terima **Context Relay** dan konfigurasi model ringkasan, klasifikasi 429 per penyedia & tombol aktif/nonaktif `useUpstream429BreakerHints`, cooldown model
- **Lanjutan** — Penimpaan konfigurasi, jejak audit konfigurasi, mode degradasi fallback, degradasi mode latar belakang untuk Responses API

## 🔗 Relay Konteks _(v3.5.5+)_

Strategi kombo yang mempertahankan kesinambungan sesi ketika rotasi akun terjadi di tengah percakapan. Sebelum akun aktif kehabisan kuota, OmniRoute menghasilkan ringkasan serah terima terstruktur di latar belakang. Setelah permintaan berikutnya dialihkan ke akun lain, ringkasan tersebut disisipkan sebagai pesan sistem agar akun baru dapat melanjutkan dengan konteks lengkap.

Dapat dikonfigurasi melalui pengaturan tingkat kombo atau global:

- **Ambang Serah Terima** — Persentase penggunaan kuota yang memicu pembuatan ringkasan (nilai bawaan 85%)
- **Jumlah Maksimal Pesan untuk Ringkasan** — Banyaknya riwayat terbaru yang akan diringkas
- **Model Ringkasan** — Model pengganti opsional untuk menghasilkan ringkasan serah terima

Saat ini mendukung rotasi akun Codex. Lihat [dokumentasi Relay Konteks](../architecture/ARCHITECTURE.md).

## 🗜️ Kompresi Prompt _(v3.7.9+)_

Konteks & Cache kini menyediakan halaman khusus untuk Caveman, RTK, dan Kombo Kompresi:

- **Caveman** — paket aturan yang memahami bahasa, pratinjau, kontrol mode keluaran, dan analitik
- **RTK** — kompresi yang memahami perintah untuk keluaran shell, git, pengujian, build, paket, Docker, infrastruktur, JSON, dan stack trace
- **Kombo Kompresi** — pipeline bernama seperti `rtk -> caveman` yang ditetapkan ke kombo perutean; perhitungan bertumpuk bawaan mencapai rata-rata `~89%` dan penghematan konteks yang memenuhi syarat sebesar `78-95%` ketika kedua mesin diterapkan
- **Pemulihan keluaran mentah** — penunjuk opsional ke keluaran mentah RTK yang telah disunting untuk men-debug kegagalan terkompresi

Lihat [Panduan Kompresi](../compression/COMPRESSION_GUIDE.md), [Kompresi RTK](../compression/RTK_COMPRESSION.md), dan

## 🛡️ Penguatan Proksi _(v3.5.5+)_

Penerapan konfigurasi proksi yang menyeluruh di seluruh pipeline permintaan:

- **Pemeriksaan Kesehatan Token** — Penyegaran OAuth di latar belakang kini menentukan konfigurasi proksi untuk setiap koneksi, sehingga mencegah kegagalan di lingkungan yang mewajibkan proksi

- **Deteksi Versi Node.js** — Halaman masuk secara proaktif mendeteksi versi Node.js yang tidak kompatibel (24+) dan menampilkan spanduk peringatan beserta petunjuk untuk menggunakan Node 22 LTS

## 🖥️ Aplikasi Desktop

Aplikasi desktop Electron native untuk Windows, macOS, dan Linux. Jalankan OmniRoute sebagai aplikasi mandiri dengan integrasi baki sistem, dukungan offline, pembaruan otomatis, dan instalasi sekali klik.

Fitur utama:

- Polling kesiapan server (tanpa layar kosong saat dimulai dari kondisi dingin)
- Baki sistem dengan pengelolaan port
- Kebijakan Keamanan Konten
- Penguncian instans tunggal
- Pembaruan otomatis saat dimulai ulang
- UI kondisional berdasarkan platform (tombol lampu lalu lintas macOS, bilah judul default Windows/Linux)
- Pengemasan build Electron yang diperkuat — `node_modules` yang ditautkan secara simbolis dalam bundel mandiri dideteksi dan ditolak sebelum pengemasan, sehingga mencegah ketergantungan runtime pada mesin build (v2.5.5+)
- **Penonaktifan yang mulus** — `before-quit` Electron mematikan Next.js dengan bersih, sehingga mencegah penguncian basis data SQLite WAL (v3.6.2+)

📖 Lihat [`electron/README.md`](../../electron/README.md) untuk dokumentasi lengkap.

## 🌐 Jembatan WebSocket V1 _(v3.6.6+)_

OmniRoute kini mendukung **klien WebSocket yang kompatibel dengan OpenAI** melalui endpoint peningkatan `/v1/ws`. Server `scripts/dev/v1-ws-bridge.mjs` khusus membungkus Next.js dan meningkatkan koneksi WS menjadi sesi streaming dua arah penuh. Autentikasi menggunakan kunci API atau cookie sesi yang sama seperti permintaan HTTP.

Perilaku utama:

- Peningkatan WS divalidasi oleh `src/lib/ws/handshake.ts` sebelum koneksi dibuat
- Stream dihentikan dengan bersih saat sesi ditutup atau terjadi kesalahan upstream
- Berfungsi secara bersamaan dengan jalur streaming HTTP+SSE yang sudah ada

## 🔑 Token Sinkronisasi & Bundel Konfigurasi _(v3.6.6+)_

Akses multi-perangkat dan operator eksternal kini dimungkinkan melalui **token sinkronisasi dengan cakupan tertentu**:

- **`POST /api/sync/tokens`** — Terbitkan token sinkronisasi baru (dengan cakupan tertentu dan masa berlaku opsional)
- **`DELETE /api/sync/tokens/:id`** — Cabut token
- **`GET /api/sync/bundle`** — Unduh snapshot JSON berversi dan berkunci ETag dari semua pengaturan non-sensitif (kata sandi disamarkan)

Bundel konfigurasi dibuat oleh `src/lib/sync/bundle.ts`. Konsumen membandingkan header respons `ETag` untuk mendeteksi perubahan tanpa mengunduh ulang seluruh payload.

## 🛡️ Pengambilan Data Keluar yang Aman & Perlindungan SSRF _(v3.6.6+)_

Semua panggilan validasi penyedia dan penemuan model kini melalui perlindungan keluar dua lapis:

1. **Perlindungan URL** (`src/shared/network/outboundUrlGuard.ts`) — Memblokir rentang IP privat/loopback/link-local sebelum soket dibuka.
2. **Pembungkus pengambilan aman** (`src/shared/network/safeOutboundFetch.ts`) — Menerapkan perlindungan URL, menormalisasi batas waktu, dan mencoba kembali kesalahan sementara dengan backoff eksponensial.

Pelanggaran perlindungan ditampilkan sebagai HTTP 422 (`URL_GUARD_BLOCKED`) dan ditulis ke log audit kepatuhan melalui `providerAudit.ts`.

## 🔄 Percobaan Ulang yang Mempertimbangkan Masa Jeda _(v3.6.6+)_

Permintaan chat kini **secara otomatis dicoba ulang** ketika penyedia upstream mengembalikan masa jeda yang berlaku untuk model tertentu. Dapat dikonfigurasi melalui `REQUEST_RETRY` (default: 2) dan `MAX_RETRY_INTERVAL_SEC` (default: 30 dtk). Pembelajaran header batas laju telah ditingkatkan untuk `x-ratelimit-reset-requests`, `x-ratelimit-reset-tokens`, dan `Retry-After` — status masa jeda per model dapat dilihat di dasbor Resilience.
