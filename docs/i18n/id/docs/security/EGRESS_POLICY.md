> **Sematkan lalu lintas keluar ke satu keluarga IP — `auto`, `ipv4`, atau `ipv6` — untuk setiap proxy, sehingga egress khusus IPv6 tidak pernah diam-diam kembali bocor ke IPv4.**

> **Sumber acuan:** `open-sse/utils/proxyFamily.ts`, `open-sse/utils/proxyDispatcher.ts`, `open-sse/utils/proxyFetch.ts`, `open-sse/utils/socksConnectorWithFamily.ts`, `open-sse/utils/proxyFamilyResolve.ts`, `src/shared/validation/schemas.ts`, `src/lib/db/proxies.ts`, `src/lib/db/upstreamProxy.ts`, `src/lib/db/migrations/099_proxy_family.sql`

OmniRoute memungkinkan setiap proxy memiliki **direktif egress keluarga alamat**. Secara default, OS memilih IPv4 atau IPv6 (dual-stack, "Happy Eyeballs"). Saat Anda menetapkan direktif ke `ipv4` atau `ipv6`, OmniRoute menyematkan setiap koneksi melalui proxy tersebut ke keluarga yang dipilih dan **gagal secara tertutup** alih-alih beralih kembali ke keluarga lainnya.

Halaman ini mendokumentasikan apa itu direktif tersebut, alasan keberadaannya, tempat Anda mengonfigurasinya, dan cara runtime menyelesaikannya.

## Apa Itu

Setiap proxy dalam registri memiliki bidang `family` dengan tiga kemungkinan nilai, yang divalidasi oleh enum Zod:

```ts
// src/shared/validation/schemas.ts
family: z.enum(["auto", "ipv4", "ipv6"]).optional().default("auto"),
```

Bidang ini secara default bernilai `"auto"`, yang mempertahankan perilaku dual-stack sebelumnya. Menetapkannya ke `ipv4` atau `ipv6` akan menyematkan keluarga koneksi untuk proxy tersebut.

Direktif ini dinormalisasi di semua tempat melalui satu helper sehingga setiap nilai yang tidak dikenal dipetakan menjadi `auto`:

```ts
// open-sse/utils/proxyFamily.ts
export type ProxyFamily = "auto" | "ipv4" | "ipv6";

export function parseProxyFamily(value: unknown): ProxyFamily {
  return value === "ipv4" || value === "ipv6" ? value : "auto";
}
```

## Mengapa Ini Ada

Diperkenalkan dalam PR [#3777](https://github.com/diegosouzapw/OmniRoute/pull/3777). Masalah yang melatarbelakanginya:

| Masalah                                            | Hal yang diperbaiki oleh direktif                                                                                                                                                                                                                                                                                                                                                                               |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Egress khusus IPv6 bocor ke IPv4**               | Ketika host proxy memiliki rekaman A dan AAAA (atau OS lebih memilih IPv4), Happy Eyeballs dapat membuat koneksi keluar melalui IPv4 meskipun Anda menginginkan jalur khusus IPv6. Penyematan `ipv6` menghilangkan kebocoran tersebut.                                                                                                                                                                          |
| **Pencabutan akibat anomali egress bersama**       | Penyedia yang melakukan rotasi (codex/openai) mencabut token ketika banyak akun melakukan egress melalui IP yang **sama** dengan volume tinggi. Mengendalikan keluarga egress merupakan bagian dari upaya mempertahankan akun pada jalur egress yang berbeda dan dapat diprediksi (lihat [`src/lib/proxyEgress.ts`](../../src/lib/proxyEgress.ts) untuk diagnostik IP egress yang digunakan bersama fitur ini). |
| **Egress deterministik untuk kepatuhan/pengujian** | Ketika Anda harus menjamin lalu lintas keluar melalui keluarga tertentu, `auto` tidaklah cukup.                                                                                                                                                                                                                                                                                                                 |

Direktif ini sengaja diterapkan **per proxy**, bukan secara global — proxy yang berbeda dalam kumpulan Anda dapat memiliki kebijakan yang berbeda.

## Tiga Nilai

| Nilai  | Label UI                | Perilaku                                                                                                                                                                 |
| ------ | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `auto` | `Otomatis (dual-stack)` | OS memilih famili. Untuk host proxy berupa literal IP, familinya melekat pada literal tersebut; untuk nama host, kedua famili dapat digunakan. Ini adalah nilai default. |
| `ipv4` | `Hanya IPv4`            | Mengunci koneksi ke IPv4. Koneksi langsung gagal jika host proxy tidak memiliki rekaman IPv4 (A).                                                                        |
| `ipv6` | `Hanya IPv6`            | Mengunci koneksi ke IPv6. Koneksi langsung gagal jika host proxy tidak memiliki rekaman IPv6 (AAAA).                                                                     |

String UI berada di `src/i18n/messages/en.json` (`labelFamily`, `familyAuto`, `familyIpv4`, `familyIpv6`, `familyHint`).

## Cara Mengonfigurasinya

### Dasbor

Pemilih tersedia di formulir proxy pada tab **Kumpulan Proxy**:

1. Buka **Dasbor → Pengaturan → Proxy → Kumpulan Proxy**
2. Tambahkan atau edit proxy
3. Atur menu tarik-turun **Famili IP** ke `Otomatis (dual-stack)`, `Hanya IPv4`, atau `Hanya IPv6`
4. Simpan

Kontrol ini dirender oleh `ProxyRegistryManager.tsx` (dipasang di `proxy/ProxyPoolTab.tsx`).

### API

Kolom `family` merupakan bagian dari payload pembuatan/pembaruan registri proxy, divalidasi oleh `createProxyRegistrySchema` / `updateProxyRegistrySchema` (`src/shared/validation/schemas.ts`) dan ditangani oleh `POST` / `PATCH /api/v1/management/proxies`:

```bash
# Buat proxy khusus IPv6
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "IPv6 egress",
    "type": "socks5",
    "host": "proxy.example.com",
    "port": 1080,
    "family": "ipv6"
  }'

# Ubah proxy yang sudah ada menjadi khusus IPv4
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{ "id": "proxy-uuid-here", "family": "ipv4" }'
```

Kolom yang sama juga diterima oleh objek konfigurasi proxy inline yang digunakan untuk entri proxy upstream (`upstream_proxy_config.family`, lihat [Model Data](#data-model)).

Untuk API CRUD/penetapan proxy lainnya, lihat [PROXY_GUIDE.md](../ops/PROXY_GUIDE.md).

## Cara `auto` Diselesaikan

Ketika `family` bernilai `auto`, OmniRoute **tidak** menambahkan direktif apa pun — URL proxy digunakan sebagaimana adanya dan famili koneksi ditentukan secara intrinsik.

Saat URL dibuat (`proxyConfigToUrl` / `normalizeProxyUrl` di `open-sse/utils/proxyDispatcher.ts`), proxy `auto` menghasilkan URL biasa tanpa penanda:

```ts
// open-sse/utils/proxyDispatcher.ts
const fam = parseProxyFamily(config.family);
const normalized = normalizeProxyUrl(proxyUrlStr, "context proxy", {
  allowSocks5,
});
return fam === "auto" ? normalized : `${normalized}?family=${fam}`;
```

Saat proses dispatch (`resolveDispatcherFamily`), `auto` diselesaikan ke famili intrinsik dari host berupa literal IP, atau `null` (biarkan OS memutuskan) untuk nama host:

```ts
// open-sse/utils/proxyDispatcher.ts
function resolveDispatcherFamily(parsed: URL): 4 | 6 | null {
  const directive = parseProxyFamily(parsed.searchParams.get("family") ?? undefined);
  const literal = detectIpLiteralFamily(parsed.hostname);
  if (directive === "auto") return literal; // null untuk nama host → OS yang memilih
  // ...
}
```

Jadi:

- `auto` + host berupa literal IP (`192.0.2.1` / `[2001:db8::1]`) → famili dari literal tersebut.
- `auto` + nama host → `null` → resolusi dual-stack standar oleh OS.

## Cara Penerapan `ipv4` / `ipv6`

Direktif selain `auto` diteruskan sebagai satu penanda kueri sintetis — `?family=ipv4` atau `?family=ipv6` — yang ditambahkan satu kali ke URL proksi yang telah dinormalisasi. `normalizeProxyUrl` secara hati-hati menghapus dan menambahkan kembali penanda ini tepat satu kali agar tidak pernah merusak penguraian port.

Saat dispatcher dibuat, penanda tersebut dibaca dan dikonversi menjadi keluarga koneksi konkret. Jika host merupakan literal IP dari keluarga yang **berlawanan**, OmniRoute melemparkan kesalahan (kontradiksi ditangani secara fail-closed):

```ts
// open-sse/utils/proxyDispatcher.ts
const want = directive === "ipv6" ? 6 : 4;
if (literal !== null && literal !== want) {
  throw new Error(
    `[ProxyDispatcher] Proxy family directive ${directive} contradicts ${literal === 6 ? "IPv6" : "IPv4"} literal host`
  );
}
```

Keluarga konkret tersebut kemudian ditetapkan pada konektor:

- **Proksi HTTP/HTTPS** (`ProxyAgent`): `proxyTls: { family, autoSelectFamily: false }` — menonaktifkan Happy Eyeballs sehingga hanya keluarga yang dipilih yang dihubungi.
- **Proksi SOCKS5**: konektor khusus meneruskan `socket_options: { family, autoSelectFamily: false }` ke klien SOCKS (lihat [Kompatibilitas SOCKS5](#kompatibilitas-socks5)).

## Kompatibilitas SOCKS5

Penetapan keluarga berfungsi dengan proksi SOCKS5, tetapi `fetch-socks` standar tidak mengekspos opsi soket yang diperlukan untuk menetapkan keluarga pada hop proksi. OmniRoute menyediakan konektornya sendiri untuk keperluan tersebut:

```ts
// open-sse/utils/socksConnectorWithFamily.ts
export function buildSocksFamilySocketOptions(family: 4 | 6 | null): Record<string, unknown> {
  if (family === 6) return { family: 6, autoSelectFamily: false };
  if (family === 4) return { family: 4, autoSelectFamily: false };
  return {};
}
```

Semua dispatch SOCKS5 melewati `createSocksDispatcherWithFamily` tanpa memandang `family` (termasuk `null` / `auto` melalui nama host): `buildSocksFamilySocketOptions(null)` menghasilkan `{}`, dan jalur `SocksClient.createConnection` + `buildConnector` TLS yang sama digunakan dengan penetapan `socket_options` sehingga Happy Eyeballs tidak dapat memilih IPv4 untuk kebijakan egress khusus IPv6.

Dukungan SOCKS5 itu sendiri diaktifkan secara bawaan (dapat dinonaktifkan melalui `ENABLE_SOCKS5_PROXY=false`); lihat [PROXY_GUIDE.md → Variabel Lingkungan](../ops/PROXY_GUIDE.md#environment-variables).

## Perilaku Fail-Closed

Tujuan utama direktif ini adalah untuk **menolak**, alih-alih secara diam-diam beralih ke keluarga yang salah. Dua pengamanan menerapkan hal ini:

1. **Kontradiksi literal** — direktif yang bertentangan dengan host literal IP akan melemparkan kesalahan saat dispatcher dibuat (`resolveDispatcherFamily`, ditampilkan di atas).

2. **Pemeriksaan DNS awal nama host** — untuk proksi nama host dengan keluarga yang ditetapkan, `proxyFetch.ts` memverifikasi bahwa nama host tersebut benar-benar memiliki record dalam keluarga yang diwajibkan **sebelum** melakukan egress, melalui `assertHostnameSupportsFamily`:

   ```ts
   // open-sse/utils/proxyFamilyResolve.ts
   const hasFamily = records.some((r) => r.family === family);
   if (!hasFamily) {
     throw new Error(
       `[ProxyFamily] Proxy host ${host} has no ${family === 6 ? "IPv6 (AAAA)" : "IPv4 (A)"} record; ` +
         `refusing ${family === 6 ? "IPv6" : "IPv4"}-only egress (fail-closed)`
     );
   }
   ```

   Jika terjadi kegagalan, `proxyFetch.ts` menandai kesalahan dengan `code = "PROXY_FAMILY_UNAVAILABLE"` dan `statusCode = 503`. Kegagalan resolusi DNS juga diperlakukan secara fail-closed (menolak melakukan egress).

Host literal IP tidak memerlukan tindakan apa pun dalam pemeriksaan DNS awal — keluarganya bersifat intrinsik dan tidak memerlukan pencarian.

## Model Data

Kolom `family` ditambahkan oleh migrasi `099_proxy_family.sql` ke **dua** tabel:

```sql
-- src/lib/db/migrations/099_proxy_family.sql
ALTER TABLE proxy_registry ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
ALTER TABLE upstream_proxy_config ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
```

- `proxy_registry.family` — arahan per proksi untuk entri registri (`src/lib/db/proxies.ts`). Kueri resolusi memilih `family` bersama kolom proksi lainnya, dan nilai yang hilang/bukan string dikonversi menjadi `"auto"`.
- `upstream_proxy_config.family` — arahan untuk entri proksi upstream (`src/lib/db/upstreamProxy.ts`), dengan nilai default `"auto"` yang sama.

Saat objek proksi yang telah diresolusi memiliki `family` selain `auto`, `proxyConfigToUrl` menambahkan penanda `?family=` agar penguncian tersebut tetap dipertahankan hingga dispatcher.
