## Ikhtisar

Search Tools Studio mengubah `/dashboard/search-tools` dari sarana eksperimen pencarian dasar menjadi
Studio dengan tiga tab yang menyatukan pencarian web, scraping web, dan perbandingan penyedia secara berdampingan.

```
┌ Search Tools ──────────────────────────────────────────────────────────┐
│ [🔍 Pencarian] [📄 Scrape] [⚖ Bandingkan]       142ms · $0.001  </>    │
│ ⓘ [Panduan modalitas]                                                  │
├──────────────────────────────────────────┬─────────────────────────────┤
│  {konten tab aktif}                      │ ─ Konfigurasi               │
│                                          │ Penyedia [otomatis ∨]       │
│                                          │   🟢 Serper  $0.001         │
│                                          │   🟢 Tavily  $0.008         │
│                                          │   🔥 Firecrawl (ambil)      │
│                                          │ Jenis  [web | berita]       │
│                                          │ Halaman penuh [ ] (scrape)  │
│                                          │ Format [md|teks|html]       │
│                                          │ Model rerank [∨]            │
└──────────────────────────────────────────┴─────────────────────────────┘
```

## Tab

### Tab Pencarian

Mengembangkan `SearchForm` + `ResultsPanel` + `RerankPanel` yang sudah ada menjadi sebuah tab:

- Kueri → hasil (judul, URL, cuplikan, skor relevansi).
- Metadata penyedia di panel Konfigurasi (biaya, kuota, status).
- Bagian rerank: pilih model rerank, urutkan ulang hasil, tampilkan `positionDelta`.
- Status kosong dengan CTA saat tidak ada penyedia pencarian yang dikonfigurasi.
- Riwayat pencarian melalui `SearchHistory.tsx`.
- Memanggil `POST /v1/search` (endpoint yang sudah ada, tanpa perubahan).

### Tab Scrape

Tab baru untuk mengekstrak konten dari URL melalui `POST /v1/web/fetch` (dibuat dalam paket 05):

- Input: URL + sakelar halaman penuh + pemilih format (markdown / teks / HTML).
- Kirim → ambil → render `ScrapeResult.tsx`.
- `ScrapeResult` merender pratinjau markdown + sakelar mentah.
- Batas: jika isi respons > **256 KB**, UI menampilkan `(dipotong, lihat data mentah)` dan membuka data mentah dalam modal Monaco (D21).
- Panel metadata: penyedia (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search), latensi, biaya, ukuran respons, jumlah tautan.
- Menggunakan hook `useScrapeFetch.ts`.

### Tab Perbandingan

Menjalankan kueri/URL yang sama di hingga **4 penyedia secara paralel** (D22):

- Kolom berdampingan untuk setiap penyedia.
- Metrik: latensi, biaya, jumlah hasil, ukuran respons.
- Perhitungan tumpang tindih URL untuk pencarian (jumlah URL yang sama dibandingkan dengan hasil awal).
- Memanggil `POST /v1/search` (pencarian) atau `POST /v1/web/fetch` (scrape) untuk setiap penyedia.

## Panel Konfigurasi (Bersama)

`SearchToolsConfigPane.tsx` — selalu terlihat dan dapat diciutkan.

| Bidang        | Catatan                                                                            |
| ------------- | ---------------------------------------------------------------------------------- |
| Penyedia      | Dropdown dengan lencana status (dikonfigurasi / tidak tersedia / dibatasi)         |
| Jenis         | `web` atau `news` (khusus pencarian)                                               |
| Halaman penuh | Sakelar untuk scrape — mengambil seluruh halaman atau konten pertama yang terlihat |
| Format        | `markdown`, `text`, atau `html` (khusus scrape)                                    |
| Model rerank  | Model opsional untuk pemeringkatan ulang setelah pencarian                         |
| Riwayat       | Bagian riwayat pencarian yang dapat diciutkan                                      |

## SearchConceptCard

`SearchConceptCard.tsx` — selalu terlihat, berupa akordeon yang dapat diciutkan. Menjelaskan:

| Konsep                  | Penjelasan singkat                                                     |
| ----------------------- | ---------------------------------------------------------------------- |
| **Pencarian**           | Mengambil daftar hasil web (judul, URL, cuplikan, skor relevansi)      |
| **Scrape**              | Mengekstrak seluruh konten dari sebuah URL (markdown, teks, atau HTML) |
| **Perbandingan**        | Menjalankan kueri yang sama pada N penyedia secara berdampingan        |
| **Pemeringkatan ulang** | Mengurutkan ulang hasil melalui LLM untuk meningkatkan relevansi kueri |
| **Otomatis (termurah)** | Memilih penyedia termurah yang tersedia secara otomatis                |

## Katalog Penyedia

`ProviderCatalog.tsx` menampilkan daftar lengkap penyedia dari `GET /api/search/providers`
(diperluas pada F4 untuk menyertakan penyedia pengambilan):

| `kind` | `"search"` (20 penyedia) atau `"fetch"` (firecrawl, jina-reader, tavily-search, tinyfish, nimble-search, anysearch-search) |

Status **ditentukan pada saat permintaan** dengan memeriksa apakah kredensial tersedia dan apakah
semua kunci sedang dalam masa jeda.

## Ekspor Kode

`ExportCodeModal` (diimpor dari Playground Studio) + `codeExport.ts` menghasilkan
cuplikan curl / Python / TypeScript untuk pemanggilan `/v1/search` dan `/v1/web/fetch`.
Placeholder kunci API selalu `$OMNIROUTE_API_KEY` (D11, digunakan bersama Playground Studio).

## Perubahan Backend

Hanya satu perubahan backend yang diperlukan untuk fitur ini:

### `GET /api/search/providers` yang Diperluas

`src/app/api/search/providers/route.ts` diperluas untuk:

- Menyertakan semua 6 penyedia pengambilan (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`) dalam array.
- Menambahkan `kind: "search" | "fetch"` ke setiap item.
- Menambahkan `status: "configured" | "missing" | "rate_limited"` yang ditentukan dari status kredensial secara langsung.
- Mempertahankan kompatibilitas mundur — field yang sudah ada (`id`, `name`, dll.) tidak berubah.
