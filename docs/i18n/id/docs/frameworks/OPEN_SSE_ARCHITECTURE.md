> **Ringkasnya**: `open-sse/` adalah mesin streaming inti yang mendukung setiap permintaan LLM di OmniRoute. Paket ini berisi sekitar 1.400 file yang mengimplementasikan pipeline permintaan, eksekutor, layanan, server MCP, dan lapisan penerjemahan. Panduan ini menjelaskan bagaimana semua komponen tersebut saling terhubung.

**Sumber:** `open-sse/` (paket workspace, sekitar 1.440 file `.ts` non-pengujian)

---

## Mengapa Menggunakan Paket Workspace Terpisah?

`open-sse/` merupakan **workspace mandiri** dalam monorepo OmniRoute karena beberapa alasan:

1. **Dapat digunakan kembali** — `open-sse` dipublikasikan sebagai `@omniroute/open-sse` di npm, sehingga proyek lain dapat menggunakannya secara independen
2. **Batasan yang jelas** — mesin streaming dipisahkan dari lapisan UI/DB khusus OmniRoute
3. **Performa** — mesin ini tidak memiliki dependensi Next.js, sehingga memungkinkan cold start yang lebih cepat dalam konteks CLI/serverless
4. **Pembuatan versi** — `open-sse` dapat merilis versi sesuai siklusnya sendiri

```json
// package.json
"workspaces": ["open-sse"]
```

## Pipeline Permintaan

Setiap permintaan LLM mengalir melalui **pipeline 5 tahap**:

```
                              ┌──────────────┐
   Permintaan HTTP             │  1. RUTE     │   resolusi combo, pemilihan model
   (rute Next.js)              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │ 2. TERJEMAHKAN│   konversi format (OpenAI ↔ Claude ↔ Gemini)
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │ 3. EKSEKUSI  │   eksekutor penyedia, HTTP, percobaan ulang, pemutus sirkuit
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  4. STREAM   │   transformasi SSE, backpressure
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  5. CATAT    │   pelacakan penggunaan, log panggilan, klasifikasi galat
                              └──────┬───────┘
                                     │
                                     ▼
                              Respons HTTP (SSE atau JSON)
```

### Tahap 1: Rute (services/combo.ts)

**Titik masuk**: `handleComboChat()` di `services/combo.ts`

Menyelesaikan permintaan menjadi tuple `(provider, model, account, credentials)` yang konkret:

- Cari combo berdasarkan ID (atau buat combo virtual untuk model `auto/*`)
- Terapkan strategi perutean (prioritas, berbobot, round-robin, dll.)
- Saring penyedia yang tidak sehat (pemutus sirkuit)
- Pilih target layak berikutnya

Untuk model `auto/*`, tahap ini juga:

- Menjalankan algoritma **penilaian 16 faktor** (`services/autoCombo/`)
- Memilih pasangan `provider+model` berdasarkan kesehatan, biaya, latensi, dll.

### Tahap 2: Terjemahkan (translator/)

Jika format sumber (misalnya, OpenAI) berbeda dari format target (misalnya, Claude), permintaan akan **diterjemahkan**:

- Prompt sistem → pesan sistem
- Definisi tool → format tool khusus penyedia
- Parameter penalaran/pemikiran → padanan khusus penyedia
- Normalisasi peran pesan (`developer` → `system` untuk penyedia selain OpenAI)

`translator/index.ts` mengekspos:

```ts
translateRequest(body, sourceFormat, targetFormat): TranslatedRequest
needsTranslation(source, target): boolean
```

### Tahap 3: Eksekusi (executors/)

**Titik masuk**: `getExecutor(providerId).execute(request, options)`

Semua penyedia menggunakan `DefaultExecutor` (`executors/default.ts`) melalui fallback factory `getExecutor()`. Eksekutor akan:

- Membuat URL upstream (`buildUrl()`)
- Menambahkan header khusus penyedia (`buildHeaders()`)
- Mentransformasi isi permintaan (`transformRequest()`)
- Mengirim permintaan HTTP dengan percobaan ulang + exponential backoff
- Menangani refresh autentikasi jika diperlukan (penyedia OAuth)

Semua eksekutor memperluas `BaseExecutor` (`executors/base.ts`, 1170 baris kode) yang menyediakan:

- Logika percobaan ulang umum
- Integrasi proxy
- Integrasi pemutus sirkuit
- Hook pencatatan penggunaan

### Tahap 4: Stream (utils/stream.ts)

Untuk respons streaming, eksekutor mengembalikan **ReadableStream**. Penangan akan:

- Meneruskan aliran melalui transformasi SSE (`createSSETransformStreamWithLogger`)
- Menerapkan ping heartbeat untuk mendeteksi koneksi yang terputus
- Menangani pemutusan koneksi klien dengan baik (`pipeWithDisconnect`)
- Mentransformasi SSE → JSON untuk klien non-streaming

Untuk respons non-streaming, eksekutor mengembalikan objek JSON yang telah diuraikan dan diteruskan tanpa perubahan.

### Tahap 5: Catat (services/usage.ts)

Setelah respons (berhasil atau gagal), penggunaan dicatat:

- `prompt_tokens`, `completion_tokens`, `cached_tokens` dari respons
- `cost_usd` dihitung dari data harga
- `latency_ms`, `status`, `error_class` jika gagal
- Disimpan ke tabel `usage_history`

Artefak log panggilan (jika diaktifkan) ditulis ke `${DATA_DIR}/call_logs/`.

## Pendalaman File Utama

### chatCore.ts (5977 baris)

**Penangan permintaan utama**. Terlepas dari ukurannya, file ini memiliki struktur yang jelas:

```ts
// Struktur semu chatCore.ts
export async function handleChat(request: NextRequest) {
  // 1. Autentikasi + CORS
  await authenticateRequest(request);
  applyCorsHeaders(response);

  // 2. Validasi isi
  const body = await parseRequestBody(request);

  // 3. Deteksi format + penerjemahan
  const sourceFormat = detectFormat(request);
  const targetFormat = getTargetFormat(providerId);
  if (needsTranslation(sourceFormat, targetFormat)) {
    body = translateRequest(body, sourceFormat, targetFormat);
  }

  // 4. Perutean kombo
  const targets = await resolveComboTargets(comboId, body);
  for (const target of targets) {
    try {
      const result = await executeOnTarget(target, body);
      await recordUsage(result);
      return result;
    } catch (err) {
      // Lanjutkan ke target berikutnya
    }
  }

  // 5. Fallback darurat
  return await emergencyFallback(body);
}
```

Meskipun berupa satu fungsi raksasa, file ini disusun menjadi **bagian-bagian yang diberi komentar** dan dipetakan ke pipeline 5 tahap.

### combo.ts (4456 LOC)

**Mesin perutean** yang menyelesaikan sebuah kombo menjadi target-target terurut.

```ts
// services/combo.ts
export async function handleComboChat(body, comboId): Promise<ChatResult> {
  const targets = await resolveComboTargets(comboId, body);
  for (const target of targets) {
    try {
      return await handleSingleModel(target, body);
    } catch (err) {
      log.warn("target failed, trying next", { target, err });
    }
  }
  throw new ComboExhaustedError("All targets failed");
}
```

## Eksekutor (75+ file)

Satu file per penyedia. Semuanya memperluas `BaseExecutor` dan menimpa bagian yang berbeda.

### Pola Umum

Penyedia di-resolve melalui `getExecutor(providerId)`, yang mengembalikan eksekutor yang telah dikonfigurasi. Penyedia yang kompatibel dengan OpenAI/Anthropic menggunakan `DefaultExecutor` (`executors/default.ts`). Perilaku khusus penyedia (URL dasar, header autentikasi, versi API) dikonfigurasi dalam `open-sse/config/providers/`, sedangkan transformasi body permintaan ditangani dalam `open-sse/translator/`.

**URL khusus** ditetapkan melalui konfigurasi penyedia:

```ts
// Konfigurasi penyedia dalam open-sse/config/providers/
export default {
  id: "together",
  baseURL: "https://api.together.xyz/v1/chat/completions",
}
````

**Autentikasi khusus** ditangani melalui konfigurasi autentikasi registry penyedia (kunci API, OAuth, profil header).

Transformasi **body permintaan khusus** (misalnya, Anthropic memisahkan `system` dari `messages`) didaftarkan per penyedia dalam `open-sse/translator/`.

````

### Factory Eksekutor

`executors/index.ts` mengekspor `getExecutor(providerId)`:

```ts
import { getExecutor } from "@omniroute/open-sse/executors";

const executor = getExecutor("anthropic");
const result = await executor.execute({
  model: "claude-sonnet-4-5",
  messages: [...],
});
````

Resolusi dilakukan melalui `ExecutorRegistry` (`executors/registry.ts`): setiap eksekutor khusus dideklarasikan dalam tabel bawaan `executors/index.ts` dan didaftarkan melalui `registerExecutor(alias, instance)` saat modul dimuat; `getExecutor()` memeriksa registry dan beralih ke `DefaultExecutor` yang dimemoisasi untuk setiap penyedia tanpa entri khusus. Pemetaan lengkap alias → eksekutor dicirikan oleh pengujian golden `tests/unit/executor-map-golden.test.ts`.

## Penerjemah

Menerjemahkan antara **3 format**: OpenAI, Anthropic, Gemini, ditambah Responses API baru.

### Kapan Penerjemahan Dilakukan

```ts
import { needsTranslation, translateRequest } from "@omniroute/open-sse/translator";

if (needsTranslation(sourceFormat, targetFormat)) {
  body = translateRequest(body, sourceFormat, targetFormat);
}
```

Penerjemahan umum:

- `OpenAI → Anthropic`: kolom `system` terpisah, header `x-api-key`
- `OpenAI → Gemini`: `contents` sebagai pengganti `messages`, `systemInstruction`
- `OpenAI → Responses API`: array `input`, status `previous_response_id`

### Kasus Khusus yang Ditangani

- Peran `developer` → `system` untuk selain OpenAI
- Peran `system` → digabungkan ke dalam pesan pengguna pertama untuk GLM/ERNIE
- `json_schema` → `responseMimeType` + `responseSchema` milik Gemini
- `tools` → format alat khusus penyedia
- Parameter penalaran (o1, Claude) → padanan khusus penyedia

## Transformer

`open-sse/transformer/` mengonversi antara format **Chat Completions** dan **Responses API**.

### Mengapa Menggunakan Transformer Terpisah?

Responses API adalah format baru OpenAI dengan **percakapan berstatus** (`previous_response_id`). Saat klien mengirimkan permintaan Responses, OmniRoute:

1. Mengonversi Responses → Chat Completions secara internal
2. Mengirimkannya ke penyedia (penyedia mana pun yang mendukung Chat Completions)
3. Mengonversi kembali respons ke format Responses
4. Mengalirkan respons yang telah dikonversi kepada klien

Transformer (`transformer/responsesTransformer.ts`) menyediakan:

```ts
createResponsesApiTransformStream(): TransformStream
```

Ini menangani:

- Peristiwa `response.output_item.added`
- Peristiwa `response.output_text.delta`
- Peristiwa `response.completed`
- Pemetaan pemanggilan alat (`function_call` ↔ `tool_calls`)

## Batasan Performa

Mesin perutean memiliki batas performa yang ketat:

| Operasi                                                   | Target | Pengukuran                 |
| --------------------------------------------------------- | ------ | -------------------------- |
| Resolusi kombinasi                                        | <10ms  | Untuk 50 target            |
| Pemeriksaan batas laju                                    | <1ms   | Token bucket dalam memori  |
| Fallback keluarga model                                   | <5ms   | Definisi keluarga di-cache |
| Pengiriman perutean permintaan                            | <2ms   | Jalur kritis               |
| **Tidak ada I/O yang memblokir di jalur kritis perutean** | —      | Semuanya asinkron          |

---

## Antipola

❌ **Pemanggilan DB sinkron di `combo.ts`** — lakukan prakomputasi dan simpan dalam cache
❌ **Logika percobaan ulang dalam handler** — gunakan `retry()` dari layanan resiliensi
❌ **Akses langsung ke konfigurasi penyedia** — gunakan getter `providerRegistry`
❌ **Rantai fallback yang di-hardcode** — definisikan di `modelFamilyFallback.ts`
❌ **Mutasi status lintas permintaan bersamaan** — gunakan hanya konteks dengan cakupan permintaan

## Menambahkan Komponen Baru

### Menambahkan Layanan Baru

1. Buat `open-sse/services/[serviceName].ts` dengan tanggung jawab yang terfokus
2. Ekspor fungsi handler utama dan konstanta apa pun
3. Tambahkan pengujian unit di `tests/unit/services/[serviceName].test.mjs`
4. Integrasikan ke pipeline permintaan di `handlers/chatCore.ts` (jika terkait perutean)
5. Perbarui logika perutean di `combo.ts` jika layanan memengaruhi pemilihan target
6. Dokumentasikan dalam file ini

### Menambahkan Executor Baru

1. Buat `open-sse/executors/[provider].ts` yang memperluas `BaseExecutor`
2. Daftarkan di `config/providerRegistry.ts`
3. Tambahkan ke factory `executors/index.ts`
4. Tambahkan pengujian unit untuk executor
5. Dokumentasikan di `docs/architecture/ARCHITECTURE.md`

### Menambahkan Tool MCP Baru

1. Buat atau perbarui `open-sse/mcp-server/tools/[category]Tools.ts`
2. Tentukan skema Zod untuk input
3. Daftarkan tool di `mcp-server/index.ts`
4. Tambahkan ke matriks cakupan di `mcp-server/auth/`
5. Tambahkan pengujian unit
