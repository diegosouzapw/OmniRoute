AgentBridge adalah proxy MITM (Man-in-the-Middle) OmniRoute yang mencegat lalu lintas HTTPS dari agen AI IDE dan mengalihkannya melalui mesin perutean terpadu OmniRoute. AgentBridge mendukung **10 agen IDE** — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code, dan Trae (sedang diselidiki) — sehingga menjadikan OmniRoute sebagai proxy MITM dengan cakupan terluas untuk asisten pemrograman AI di pasar.

**Lokasi dasbor:** `/dashboard/tools/agent-bridge`
**Grup bilah sisi:** Alat (setelah Agen Cloud)
**Lihat juga:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — pantau semua lalu lintas yang dicegat secara real-time; `docs/security/MITM-TPROXY-DECRYPT.md` (git; tidak dikompilasi ke dalam `/docs`) — mode penangkapan dekripsi transparan TPROXY Linux yang dijalankan oleh rute `/api/tools/agent-bridge/tproxy`.

## §1 Gambaran Umum

### Apa itu AgentBridge?

Ketika agen IDE (misalnya, GitHub Copilot, Cursor, Claude Code) melakukan panggilan API, agen tersebut terhubung langsung ke penyedia AI upstream (OpenAI, Anthropic, dan sebagainya). AgentBridge mencegat koneksi tersebut secara transparan pada tingkat TLS — tanpa memerlukan perubahan konfigurasi agen apa pun — dan menulis ulang permintaan tersebut melalui OmniRoute.

Dengan demikian, Anda dapat:

- **Mengalihkan agen apa pun ke penyedia mana pun**: Copilot berkomunikasi dengan OpenAI? Alihkan ke Anthropic Claude, Gemini, atau salah satu dari 352 penyedia OmniRoute.
- **Menerapkan pemetaan model**: `gemini-3-flash` → `claude-sonnet-4.7` secara transparan pada tingkat handler.
- **Mengamati seluruh lalu lintas agen**: setiap permintaan yang dicegat dipublikasikan ke [Traffic Inspector](./TRAFFIC_INSPECTOR.md).
- **Menerapkan ketahanan OmniRoute**: perutean kombo, circuit breaker, fallback, dan pelacakan biaya juga berfungsi untuk lalu lintas agen IDE.

## §2 Arsitektur

### 2.1 Ikhtisar komponen

```
Agen IDE (VS Code / Cursor / dll.)
    │  HTTPS (port 443)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← Pengalihan DNS
    │
    ▼
src/mitm/server.cjs  (port 443, proses anak CJS)
    │  menyelesaikan target berdasarkan SNI header Host
    │  menghasilkan sertifikat TLS per-SNI yang ditandatangani oleh CA AgentBridge
    ├── Cocok dengan daftar bypass? → passthrough TCP (tanpa dekripsi)
    ├── Cocok dengan target? → fetch → router OmniRoute (port 20128)
    │       └── handler.intercept() — TypeScript
    │               ├── maskSecrets() pada isi/header permintaan
    │               ├── TrafficBuffer.push() — menerbitkan ke Traffic Inspector
    │               └── fetchRouter() → /v1/chat/completions
    └── Tidak cocok? → passthrough TCP (tanpa dekripsi)
```

### 2.2 Server MITM (`src/mitm/server.cjs`)

Server MITM inti berjalan sebagai proses anak CJS Node.js (untuk menghindari penulisan ulang basis kode CJS yang sudah ada). Server ini:

- Mendengarkan pada port 443 (memerlukan hak istimewa atau `authbind`/`setcap`)
- Menerima tunnel CONNECT dari OS (melalui pengalihan DNS `/etc/hosts`)
- Menghasilkan sertifikat TLS per-SNI yang ditandatangani oleh CA AgentBridge (`DATA_DIR/mitm/ca.crt`)
- Menyelesaikan agen target berdasarkan header Host melalui registri `targets/index.ts`
- Meneruskan ke lapisan handler TypeScript melalui HTTP ke `http://127.0.0.1:20128`

`TARGET_HOSTS` dimuat dari `DATA_DIR/mitm/targets.json` (ditulis oleh `targets/index.ts` saat boot), sehingga memungkinkan pembaruan dinamis tanpa memulai ulang server CJS.

> **Model CA root (#6684).** Deskripsi sertifikat-per-SNI-yang-ditandatangani-oleh-CA di atas
> adalah model CA root persisten yang ditambahkan dalam #6684 (`src/mitm/cert/rootCa.ts` +
> `src/mitm/_internal/rootCaShim.cjs`, menggunakan kembali kriptografi CA/leaf yang telah
> terbukti untuk TPROXY dalam `src/mitm/tproxy/dynamicCert.ts`) — model ini menggantikan
> leaf statis lama yang ditandatangani sendiri (`src/mitm/cert/generate.ts`, masih
> terbatas hanya pada host antigravity) yang ditunjukkan oleh keberadaan pasangan
> `server.crt`/`server.key` pada disk. **Perilaku migrasi**: instalasi baru (tanpa
> `server.crt` sebelumnya) mendapatkan model CA root secara otomatis; instalasi yang telah
> memercayai leaf statis lama akan terus menggunakannya hingga operator menetapkan
> `MITM_ROOT_CA_ENABLED=true` dan memulai ulang bridge (`src/mitm/cert/migration.ts`
> adalah fungsi keputusan murni — CA MITM tepercaya yang dapat menandatangani leaf untuk
> host **apa pun** secara material lebih kuat daripada leaf SAN tetap yang lama, sehingga
> peralihan tidak pernah dilakukan secara diam-diam untuk instalasi yang telah dipercaya).
> Sertifikat CA dipasang ke slot trust store `omniroute-mitm.crt` yang sama dengan yang
> digunakan leaf lama (`cert/install.ts::installCaCert`) — tidak diperlukan pembersihan
> kepercayaan ganda.

### 2.3 Basis handler (`src/mitm/handlers/base.ts`)

Semua handler agen memperluas `MitmHandlerBase`:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // Helper protected: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

Setiap handler memanggil `hookBufferStart()` sebelum melakukan proxy dan `hookBufferUpdate()` setelah selesai. Keduanya memasukkan entri `InterceptedRequest` ke dalam `globalTrafficBuffer` (lihat [Traffic Inspector](./TRAFFIC_INSPECTOR.md) §4).

### 2.4 Registri target (`src/mitm/targets/`)

Setiap agen memiliki file target deklaratif:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

Registri tersebut (`targets/index.ts`) mengekspor `ALL_TARGETS` dan menghasilkan `DATA_DIR/mitm/targets.json` saat boot.

### 2.5 Passthrough dan daftar bypass (`src/mitm/passthrough.ts`)

**Daftar bypass** (diperiksa terlebih dahulu, dengan prioritas atas kecocokan target):

- Pola default: host perbankan, `.gov.`, penyedia OAuth/SSO (Okta, Auth0), dll.
- Pola pengguna: disimpan dalam tabel DB `agent_bridge_bypass`
- Host yang di-bypass menerima tunnel TCP transparan — TLS **tidak pernah didekripsi**

**Passthrough default** (tidak ada kecocokan target dan tidak ada dalam daftar bypass):

- Juga menerima tunnel TCP — koneksi tidak pernah diputus
- Mencegah AgentBridge mengganggu lalu lintas HTTPS sistem secara umum

Prioritas perutean:

```
daftar bypass → kecocokan target → passthrough
```

### 2.6 Sertifikat CA upstream (`src/mitm/upstreamTrust.ts`)

Untuk lingkungan jaringan perusahaan dengan CA khusus:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

Jika ditetapkan, variabel ini mengonfigurasi dispatcher global `undici` dengan sertifikat CA tambahan, sehingga memungkinkan AgentBridge menjangkau penyedia upstream melalui proxy terminasi TLS perusahaan.

### 2.7 Penyembunyian rahasia (`src/mitm/maskSecrets.ts`)

Pemindai clean-room independen diterapkan pada isi permintaan dan header kredensial
**sebelum** data tersebut masuk ke buffer Traffic Inspector atau log apa pun. Pemindai ini melakukan satu lintasan linear:

- Token berawalan `sk-` / `ak-` / `pk-` (bergaya OpenAI/Anthropic)
- Kredensial RFC 6750 `Authorization: Bearer <token>`, dengan prioritas seluruh token
- Token buram panjang generik (≥40 karakter), termasuk bentuk bertitik dan berpading

`sanitizeHeaders()` mengubah nama yang dipertahankan menjadi huruf kecil, menggabungkan nilai array secara deterministik, menghapus
daftar larangan hop-by-hop/framing bersama (termasuk autentikasi proxy), menyunting sepenuhnya `cookie` dan
`set-cookie`, serta mendelegasikan nilai kredensial kepada pemindai.

## §3 Penyiapan

### 3.1 Memulai/menghentikan server MITM

Gunakan Kartu Server AgentBridge di `/dashboard/tools/agent-bridge`:

| Tindakan              | Deskripsi                                                                      |
| --------------------- | ------------------------------------------------------------------------------ |
| Mulai Server          | Menjalankan `src/mitm/server.cjs` pada port 443                                |
| Hentikan Server       | Menghentikan proses anak secara aman                                           |
| Mulai Ulang Server    | Hentikan + mulai (menerapkan perubahan target)                                 |
| Percayai Sertifikat   | Menginstal `DATA_DIR/mitm/ca.crt` ke penyimpanan kepercayaan OS                |
| Unduh Sertifikat      | Mengunduh `ca.crt` untuk instalasi manual                                      |
| Buat Ulang Sertifikat | Membuat pasangan kunci CA baru (semua sertifikat per agen menjadi tidak valid) |

### 3.2 Memercayai sertifikat

Sertifikat CA AgentBridge harus dipercaya oleh OS sebelum IDE dapat menerima koneksi MITM.

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Keychain):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

Atau gunakan tombol "Percayai Sertifikat" di dasbor (menjalankan perintah yang sesuai untuk OS Anda, dengan prompt sudo jika diperlukan).

#### IDE berbasis Electron mengabaikan penyimpanan kepercayaan OS (`NODE_EXTRA_CA_CERTS`)

Beberapa IDE — terutama **Antigravity IDE**, serta aplikasi lain yang diturunkan dari Electron / VS Code — menyertakan
runtime Node.js sendiri yang **tidak memeriksa penyimpanan kepercayaan OS** untuk `fetch`/HTTPS
keluar. Memercayai CA pada tingkat OS/NSS sudah cukup untuk **backend** native IDE
(misalnya server bahasa Go, yang menggunakan bundel CA OS), tetapi **frontend Electron** masih
akan mengalami kegagalan TLS — hal ini terlihat seolah-olah aplikasi telah _keluar dari akun_ atau menampilkan
_"kesalahan koneksi"_, meskipun log MITM menunjukkan panggilan bootstrap backend mengembalikan `200`. Dua langkah
diperlukan, dan keduanya penting:

1. Arahkan runtime ke CA secara eksplisit:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **Jalankan IDE dari shell tersebut.** Menjalankannya dari ikon desktop / Dock / menu Start
   **tidak** mewarisi ekspor shell, dan `~/.config/environment.d/*.conf` hanya berlaku setelah
   login grafis baru. Tutup IDE sepenuhnya terlebih dahulu — penguncian instans tunggal Electron berarti peluncuran kedua
   hanya akan memfokuskan proses yang sudah ada dan lingkungan baru akan diabaikan.

Langkah kepercayaan OS + NSS di atas tetap diperlukan (tumpukan jaringan Chromium yang digunakan oleh beberapa alur
autentikasi membaca penyimpanan NSS per pengguna, dan memiliki pin statis sendiri untuk `*.googleapis.com` yang
ditimpa oleh CA yang dipercaya secara lokal). `NODE_EXTRA_CA_CERTS` juga mencakup jalur `fetch` Node.

### 3.3 Perutean DNS

Untuk setiap agen yang ingin Anda intersepsi, host API-nya harus di-resolve ke `127.0.0.1`. AgentBridge mengelola entri `/etc/hosts` secara otomatis saat Anda mengaktifkan DNS untuk agen di Wizard Penyiapan.

Contoh entri `/etc/hosts` untuk GitHub Copilot:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 Pemetaan model

Gunakan Tabel Pemetaan Model di setiap kartu agen untuk menentukan pemetaan sumber → target:

| Model sumber (native agen) | Model target (OmniRoute) |
| -------------------------- | ------------------------ |
| `gpt-4o`                   | `claude-sonnet-4.7`      |
| `*` (wildcard)             | `claude-haiku-4.7`       |

Wildcard `*` memetakan model apa pun yang tidak dikenali ke target yang ditentukan. Disimpan secara persisten dalam tabel `agent_bridge_mappings`.

> **Kiat — temukan ID model agen yang sebenarnya.** IDE mungkin mengirim nama model yang berbeda dari
> label UI-nya dan yang berubah di antara versi utama. Sebagai contoh, **Antigravity 2** mengirim
> `gemini-3.1-pro-low`, `gemini-pro-agent`, dan `gemini-3.1-flash-lite` melalui jaringan — bukan
> `gemini-2.5-pro` yang ditampilkan dalam dokumentasi lama. Kirim satu percakapan tanpa pemetaan yang cocok: MITM
> akan mencatat persis `model:` yang masuk dan meneruskan permintaan. Petakan nilai literal tersebut, lalu
> permintaan berikutnya akan diintersepsi dan dirutekan ke target Anda.

### 3.5 Pemberitahuan risiko

AgentBridge mengintersepsi kredensial (token OAuth, kunci API) yang digunakan IDE untuk mengautentikasi ke penyedia upstream. Kredensial ini **disamarkan sebelum dicatat** (lihat §2.7), tetapi dapat dilihat oleh lapisan MITM OmniRoute. Aktivasi pertama setiap agen akan menampilkan modal pemberitahuan risiko yang dapat ditutup.

### 3.6 Pemeliharaan & Diagnostik

Dasbor menyediakan kartu **Pemeliharaan & Diagnostik** (`AgentBridgeMaintenanceCard`, di `src/app/(dashboard)/dashboard/tools/agent-bridge/components/`) yang menampilkan rute MITM operasional yang sebelumnya tidak memiliki UI. Subjudulnya: _"Uji mandiri pipeline penangkapan, batalkan status sistem yang tersisa, dan pindahkan penyiapan Anda antar mesin."_ Helper klien kartu berada di `src/lib/inspector/agentBridgeMaintenanceApi.ts`.

| Tombol                 | Rute                                   | Fungsinya                                                                                                                                                                                                |
| ---------------------- | -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Diagnosis**          | `GET /api/tools/agent-bridge/diagnose` | Menjalankan pengujian mandiri pipeline penangkapan dan menampilkan laporan per pemeriksaan (✓/✗ + petunjuk perbaikan).                                                                                   |
| **Perbaiki**           | `POST /api/tools/agent-bridge/repair`  | Membatalkan status sistem MITM yatim (entri spoof DNS, CA root, proksi sistem) yang tertinggal akibat crash atau SIGKILL. Idempoten — melaporkan "Tidak ada yang perlu diperbaiki" ketika status bersih. |
| **Hapus CA**           | `DELETE /api/tools/agent-bridge/cert`  | Membatalkan kepercayaan dan menghapus CA root MITM dari penyimpanan kepercayaan OS (eksplisit, idempoten). Hanya ditampilkan ketika CA sedang dipercaya; memerlukan konfirmasi langsung "Hapus CA?".     |
| **Ekspor konfigurasi** | `GET /api/tools/agent-bridge/config`   | Mengunduh JSON konfigurasi portabel (lihat §3.7).                                                                                                                                                        |
| **Impor konfigurasi**  | `POST /api/tools/agent-bridge/config`  | Mengunggah JSON konfigurasi yang sebelumnya diekspor (lihat §3.7).                                                                                                                                       |

**Pemeriksaan diagnostik** (`summarizeDiagnostics()` dalam `src/mitm/inspector/diagnostics.ts`). Rute tersebut menjalankan probe berefek untuk masing-masing pemeriksaan dan memasukkan nilai boolean ke peringkas murni; satu hasil `healthy` beserta petunjuk untuk setiap kegagalan akan dikembalikan:

| Nama pemeriksaan   | Hal yang diverifikasi                                  | Petunjuk saat gagal                                                                                                                                     |
| ------------------ | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server-running`   | Proses server MITM aktif                               | "Server MITM tidak berjalan. Jalankan dari tab AgentBridge."                                                                                            |
| `server-reachable` | Server MITM menerima koneksi pada port-nya (probe TCP) | "Server MITM tidak menerima koneksi pada port-nya. Pastikan port tersebut tersedia dan Anda memiliki hak akses untuk mengikatnya."                      |
| `cert-exists`      | Sertifikat MITM telah dibuat di disk                   | "Belum ada sertifikat MITM yang dibuat. Buat sertifikat dari tab AgentBridge."                                                                          |
| `cert-trusted`     | CA root MITM berada di penyimpanan kepercayaan OS      | "CA root MITM tidak dipercaya oleh penyimpanan OS, sehingga intersepsi TLS akan gagal. Percayai sertifikat tersebut dari tab AgentBridge."              |
| `dns-configured`   | Nama host target di-spoof dalam `/etc/hosts`           | "Nama host target tidak di-spoof dalam /etc/hosts, sehingga lalu lintas tidak pernah mencapai proksi. Aktifkan DNS untuk agen yang ingin Anda tangkap." |

**Banner status yatim:** ketika halaman mendeteksi status yang tertinggal akibat crash (spoof DNS / CA / proksi sistem), kartu menampilkan banner kuning — _"Sesi sebelumnya meninggalkan status sistem (spoof DNS, CA, atau proksi sistem). Jalankan Perbaiki untuk membersihkannya."_ — dan menyoroti tombol **Perbaiki**. `Repair` adalah padanan lapisan aplikasi dari flag `--cleanup` milik ProxyBridge (mendelegasikan ke `repairMitm()` dalam `src/mitm/manager.ts`).

> CA root MITM tetap terpasang selama proses berhenti/mulai untuk menghindari prompt sudo
> berulang (perilaku yang sama seperti mitmproxy/Charles), sehingga penghapusannya merupakan tindakan
> **Hapus CA** yang eksplisit, bukan sesuatu yang terjadi secara otomatis saat berhenti.

### 3.7 Impor/ekspor konfigurasi portabel

AgentBridge dapat melakukan serialisasi terhadap status yang **dapat disesuaikan oleh operator** menjadi blob JSON berversi sehingga suatu penyiapan dapat direplikasi di berbagai mesin. Serializer-nya adalah `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`), yang divalidasi oleh `AgentBridgeConfigSchema`.

Ekspor menyertakan tepat tiga bagian (nilai default bawaan sengaja **TIDAK** diekspor, sehingga impor tidak pernah menduplikasi atau bertentangan dengannya):

| Kolom            | Sumber                                                       | Catatan                                                                        |
| ---------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| `bypassPatterns` | pola bypass yang ditentukan pengguna (`agent_bridge_bypass`) | pola default bank/gov/okta dikecualikan                                        |
| `customHosts`    | host khusus Traffic Inspector (`inspector_custom_hosts`)     | masing-masing: `{ host, kind: "llm"\|"app"\|"custom", label? }`                |
| `agentMappings`  | pemetaan model per agen (`agent_bridge_mappings`)            | `{ [agentId]: [{ source, target }] }` untuk setiap agen yang memiliki pemetaan |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**Perilaku impor** (`POST /api/tools/agent-bridge/config`): pola bypass dan pemetaan per agen **diganti seluruhnya**; host khusus ditambahkan secara **idempoten** (`INSERT OR IGNORE`). Respons melaporkan jumlah masing-masing yang diterapkan:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

Yang **TIDAK** ada dalam konfigurasi: status server yang sedang berjalan, jalur sertifikat, status DNS per agen, jalur CA upstream, dan pengaturan TPROXY — semua itu merupakan status host/runtime, bukan preferensi portabel.

## §5 Keamanan

### Aturan Ketat yang diterapkan

| Aturan                            | Penerapan                                                                                                |
| --------------------------------- | -------------------------------------------------------------------------------------------------------- |
| **#12** `sanitizeErrorMessage`    | Semua kesalahan handler disanitasi sebelum dimasukkan ke respons atau buffer                             |
| **#13** Penerusan env shell       | Pengeditan `/etc/hosts` menggunakan opsi `env` — tanpa interpolasi string pada jalur                     |
| **#15 + #17** `isLocalOnlyPath()` | `/api/tools/agent-bridge/` adalah LOCAL_ONLY + SPAWN_CAPABLE — loopback diberlakukan sebelum autentikasi |

### Daftar bypass untuk host sensitif

Daftar bypass memastikan bahwa institusi keuangan, penyedia OAuth/SSO, dan host sensitif lainnya **tidak pernah didekripsi**. Lalu lintas TLS mereka diteruskan sebagai tunnel TCP transparan — OmniRoute tidak pernah melihat teks biasa.

Pola bypass default meliputi:

- `*.bank.*`, `*.gov.*` (keuangan/pemerintahan)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/identitas)
- `*.apple.com`, `*.icloud.com` (layanan sistem Apple)

Pola bypass yang ditambahkan pengguna disimpan dalam tabel `agent_bridge_bypass` dan didahulukan dari semuanya.

### Penyembunyian rahasia

`maskSecrets()` dari `src/mitm/maskSecrets.ts` diterapkan:

- Pada setiap isi permintaan sebelum `TrafficBuffer.push()`
- Pada setiap header sebelum pencatatan log atau penyiaran

Pola: token dengan prefiks `sk-`/`ak-`/`pk-`, token `Bearer`, dan token generik ≥40 karakter.

### Sertifikat CA upstream

Ketika `AGENTBRIDGE_UPSTREAM_CA_CERT` ditetapkan, file dibaca saat startup. Jika jalur tersebut ada tetapi file tidak dapat dibaca, AgentBridge mencatat kesalahan yang jelas dan menolak untuk dimulai (mencegah kegagalan TLS tanpa pemberitahuan di lingkungan perusahaan).

### Keterbatasan yang diketahui

- **Port 443 memerlukan hak istimewa**: Di Linux, AgentBridge memerlukan `setcap 'cap_net_bind_service=+ep'` pada biner Node, atau dijalankan melalui `authbind`. Wizard Penyiapan menampilkan petunjuk khusus OS.
- **IDE harus dimulai ulang**: Setelah pengalihan DNS, IDE harus dimulai ulang agar resolusi host baru diterapkan.
- **Token OAuth yang di-hardcode**: Beberapa agen (Kiro, Antigravity) menyimpan token refresh OAuth secara lokal. Token ini transparan bagi AgentBridge — AgentBridge melihat token Bearer dalam setiap permintaan, yang disembunyikan sebelum pencatatan log.
- **Frontend Electron memerlukan `NODE_EXTRA_CA_CERTS`**: IDE yang frontend-nya berjalan pada runtime Node/Electron bawaan mengabaikan trust store OS/NSS dan harus diluncurkan dari shell dengan `NODE_EXTRA_CA_CERTS` yang telah ditetapkan (lihat §3.2). Gejala jika tidak ada: backend IDE berhasil melakukan autentikasi (MITM menampilkan `200`), tetapi UI tetap dalam keadaan logout.
- **Beberapa instalasi IDE yang sama bersifat independen**: instalasi sistem (misalnya `/usr/share/antigravity/antigravity`) dan instalasi "Full" lokal pengguna (misalnya `~/AntigravityIDE_Full/antigravity-ide`) merupakan proses terpisah dengan runtime masing-masing — semuanya harus diluncurkan ulang dengan CA yang diinjeksi. Identifikasi instalasi yang sedang berjalan berdasarkan jalur binernya sebelum meluncurkannya kembali.
- **Identitas ditetapkan oleh prompt sistem agen, bukan model yang dirutekan**: ketika Anda memetakan ulang model agen ke penyedia lain, balasan tetap mengklaim identitas bawaan agen tersebut (misalnya Antigravity menjawab "Saya didukung oleh Gemini") karena IDE menyuntikkan identitas itu ke dalam prompt sistem. Konfirmasikan backend sebenarnya di `call_logs` / `proxy_logs` (`provider`, `model`, `target_format`), bukan dengan bertanya kepada model tentang identitasnya.

## §6 Pemecahan Masalah

### Konflik port 443

Jika proses lain sudah menggunakan port 443 (server web, VPN, dll.):

```bash
lsof -i :443          # temukan prosesnya
sudo fuser -k 443/tcp  # hentikan secara paksa (gunakan dengan hati-hati)
```

Sebagai alternatif, konfigurasikan port nonprivileged di pengaturan AgentBridge dan siapkan aturan pengalihan `iptables` / `pf`.

### Sertifikat tidak dipercaya

Jika IDE menampilkan kesalahan TLS setelah AgentBridge dimulai:

1. Pastikan sertifikat telah diinstal: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) atau `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. Beberapa aplikasi memiliki trust store sendiri (Firefox, Chrome di Linux). Jalankan "Trust Cert" lagi dan periksa trust store khusus NSS/Firefox.
3. Mulai ulang IDE setelah memercayai sertifikat — sesi TLS yang sedang berlangsung menggunakan status kepercayaan lama.

### IDE keluar dari akun / "kesalahan koneksi" meskipun CA dipercaya

Gejala: setelah mengalihkan DNS dan memercayai CA, IDE berbasis Electron (misalnya Antigravity)
terbuka dalam keadaan **keluar dari akun** atau menampilkan kesalahan autentikasi/koneksi, tetapi log MITM menunjukkan
panggilan bootstrap (`loadCodeAssist`, `fetchAvailableModels`, …) mengembalikan `200`.

Penyebab: **runtime Node/Electron bawaan IDE mengabaikan trust store OS**. Backend
native (server bahasa Go) memercayai CA OS dan berhasil melakukan autentikasi, tetapi frontend Electron
tidak — sehingga UI menganggapnya sedang offline.

Perbaikan (kedua langkah): ekspor `NODE_EXTRA_CA_CERTS=<ca.crt>` **dan jalankan ulang IDE dari
shell tersebut**, bukan dari ikon desktop. Tutup IDE sepenuhnya terlebih dahulu — penguncian singleton Electron menyebabkan
peluncuran kedua hanya memfokuskan proses yang sudah ada dan environment baru diabaikan. Lihat §3.2.
Hal ini mencerminkan laporan upstream terbuka, di mana agen mandiri berfungsi melalui MITM tetapi varian IDE
gagal dengan konfigurasi yang sama.

### DNS belum diterapkan

Periksa apakah `/etc/hosts` telah diperbarui:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

Bersihkan cache DNS:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### IDE tidak terdeteksi

Deteksi otomatis menggunakan lokasi instalasi umum. Jika deteksi gagal tetapi IDE telah diinstal:

- Periksa apakah biner IDE berada di lokasi nonstandar
- Setup Wizard tetap berfungsi — kegagalan deteksi hanya berarti badge tidak akan menampilkan lokasi instalasi

### Kesalahan handler (pengambilan upstream gagal)

Jika AgentBridge melakukan intersepsi tetapi semua permintaan gagal:

1. Pastikan setidaknya satu penyedia terhubung di `/dashboard/providers`
2. Periksa log server OmniRoute: `APP_LOG_LEVEL=debug` di `.env`
3. Pastikan `OMNIROUTE_BASE_URL` mengarah ke endpoint router yang benar (default: `http://127.0.0.1:20128`)

### Investigasi Trae

Trae adalah asisten pengodean AI yang relatif baru. Sebelum mengimplementasikan handler:

1. Identifikasi biner/ekstensi di marketplace VS Code / JetBrains atau sebagai aplikasi mandiri
