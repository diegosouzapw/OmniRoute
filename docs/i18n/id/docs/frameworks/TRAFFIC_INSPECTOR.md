Traffic Inspector adalah debugger trafik HTTPS bawaan OmniRoute — alat seperti Charles Proxy / mitmweb / HTTP Toolkit yang **memahami LLM** dan **memahami agen**. Alat ini tersedia di `/dashboard/tools/traffic-inspector` dan menerima trafik langsung dari hingga 5 sumber penangkapan secara bersamaan.

**Lokasi dasbor:** `/dashboard/tools/traffic-inspector`
**Grup bilah sisi:** Alat (setelah AgentBridge)
**Lihat juga:** [`AGENTBRIDGE.md`](./AGENTBRIDGE.md) — AgentBridge adalah mode penangkapan 1.

### Arsitektur dalam satu paragraf

`TrafficBuffer` (`src/mitm/inspector/buffer.ts`) adalah ring buffer dalam memori bersama (default 1000 entri, dapat dikonfigurasi melalui `INSPECTOR_BUFFER_SIZE`). Semua sumber penangkapan menulis ke buffer tersebut melalui `push()`. Kelas buffer mengklasifikasikan setiap entri menggunakan `kindDetector.ts` (menentukan apakah entri tersebut merupakan permintaan LLM), menghitung `contextKey` (sidik jari SHA-256 dari prompt sistem), dan menyiarkannya kepada semua pelanggan WebSocket melalui `globalTrafficBuffer.subscribe()`. Dasbor terhubung melalui `GET /api/tools/traffic-inspector/ws` dan menerima snapshot saat terhubung, lalu diikuti oleh peristiwa `new`/`update`/`clear`.

## §2 Mode pengambilan

Traffic Inspector mendukung **5 sumber pengambilan simultan**. Masing-masing dapat diaktifkan atau dinonaktifkan secara independen. Field `source` pada setiap `InterceptedRequest` (`src/mitm/inspector/types.ts`) adalah salah satu dari `"agent-bridge"`, `"custom-host"`, `"http-proxy"`, `"system-proxy"`, atau `"tproxy"`.

### Mode 1 — AgentBridge (default, selalu aktif)

**Sumber:** Handler AgentBridge (`src/mitm/handlers/base.ts`)
**Mekanisme:** Setiap pemanggilan `intercept()` di `MitmHandlerBase` memanggil `hookBufferStart()` sebelum meneruskan permintaan dan `hookBufferUpdate()` setelah selesai. Tidak memerlukan konfigurasi tambahan — langsung berfungsi segera setelah AgentBridge berjalan.
**Jangkauan:** 9 agen IDE yang dikonfigurasi di AgentBridge
**Catatan:** Field `source` dalam `InterceptedRequest` = `"agent-bridge"`

### Mode 2 — Host Kustom (pengalihan DNS)

**Sumber:** Daftar host yang ditentukan pengguna (tabel `inspector_custom_hosts`)
**Mekanisme:** Menambahkan host melalui UI akan menambahkan `127.0.0.1 <host>` ke `/etc/hosts` (memerlukan sudo). Server MITM AgentBridge yang sudah ada (port 443) secara dinamis menghasilkan sertifikat SNI untuk host baru tersebut.
**Jangkauan:** Aplikasi apa pun yang menggunakan host yang ditambahkan — tidak memerlukan perubahan konfigurasi aplikasi
**Catatan:** `source` = `"custom-host"`

Contoh kasus penggunaan:

- Memantau `api.openai.com` dari skrip Python
- Men-debug `my-internal-llm.company.com`
- Mengambil lalu lintas dari perangkat seluler di jaringan yang sama (melalui spoofing ARP — tingkat lanjut)

### Mode 3 — Listener HTTP_PROXY (port 8080)

**Sumber:** Aplikasi yang menggunakan environment variable `HTTP_PROXY`/`HTTPS_PROXY`
**Mekanisme:** Listener sekunder pada port 8080 (`src/mitm/inspector/httpProxyServer.ts`) yang bertindak sebagai proxy eksplisit HTTP/HTTPS standar. Menerima tunnel `CONNECT` (HTTPS) dan permintaan HTTP langsung.
**Jangkauan:** Aplikasi apa pun yang mematuhi env `HTTP_PROXY` — tidak memerlukan perubahan DNS maupun sudo
**Catatan:** `source` = `"http-proxy"`

```bash
# Pengambilan cepat untuk satu perintah:
HTTPS_PROXY=http://127.0.0.1:8080 curl https://api.openai.com/v1/models

# Pengambilan persisten dalam sebuah sesi shell:
export HTTP_PROXY=http://127.0.0.1:8080
export HTTPS_PROXY=http://127.0.0.1:8080
```

**Batasan TLS:** Tunnel `CONNECT` HTTPS hanya diambil sebagai metadata (host, port, waktu) — body TLS tidak didekripsi secara default. Aktifkan tombol "Dekripsi HTTPS dalam mode proxy" (opsional, mengharuskan sertifikat AgentBridge dipercaya) untuk memeriksa body secara lengkap.

**Konflik port:** Jika port 8080 sedang digunakan, AgentBridge mengembalikan 409 dengan error terstruktur. Ubah port melalui env var `INSPECTOR_HTTP_PROXY_PORT`.

### Mode 4 — Proxy seluruh sistem (tingkat lanjut, opsional)

**Sumber:** Pengaturan proxy tingkat OS (berlaku untuk semua aplikasi pada mesin)
**Mekanisme:** Menggunakan API OS untuk mengalihkan semua lalu lintas HTTP/HTTPS melalui listener HTTP_PROXY:

- **macOS:** `networksetup -setwebproxy / -setsecurewebproxy`
- **Linux:** `gsettings set org.gnome.system.proxy` + `/etc/environment`
- **Windows:** `netsh winhttp set proxy 127.0.0.1:8080`
  **Jangkauan:** Setiap aplikasi pada mesin yang mematuhi pengaturan proxy sistem
  **Catatan:** `source` = `"system-proxy"`

**Mekanisme keamanan:**

- Timer penonaktifan otomatis (default 30 menit, dapat dikonfigurasi melalui `INSPECTOR_SYSTEM_PROXY_GUARD_MINUTES`)
- Status proxy sistem sebelumnya disimpan dalam DB dan dipulihkan saat dikembalikan
- Dasbor menampilkan prompt "Mengembalikan proxy sistem" jika pengguna berpindah halaman saat fitur ini aktif
- UI menampilkan badge `⚠ Tingkat lanjut` + kotak centang konfirmasi eksplisit

### Mode 5 — Dekripsi transparan TPROXY (Linux, root, opsional)

**Sumber:** TPROXY kernel + policy routing (`src/mitm/tproxy/`)
**Mekanisme:** Menandai koneksi TCP outbound lokal baru ke port target (default `443`) di `mangle OUTPUT`, sebuah `ip rule` mengalihkan ulang paket yang ditandai ke pengiriman lokal, dan target `TPROXY` milik `mangle PREROUTING` menyerahkannya ke listener transparan (**IP_TRANSPARENT**) (port default `8443`). Listener menghentikan TLS menggunakan sertifikat leaf yang diterbitkan **sesuai permintaan untuk setiap hostname SNI** oleh CA dinamis, mengambil pertukaran data yang telah didekripsi, lalu meneruskan permintaan yang telah dienkripsi ulang ke tujuan asli.
**Jangkauan:** Host tujuan **apa pun** pada port target — tanpa spoof `/etc/hosts`, tanpa env `HTTP_PROXY`, dan tanpa perubahan proxy seluruh sistem. Proses yang dicegat tidak memerlukan perubahan konfigurasi, tetapi harus memercayai CA dinamis.
**Catatan:** `source` = `"tproxy"`

**Persyaratan:** Hanya Linux (**IP_TRANSPARENT** hanya tersedia di Linux), kapabilitas **CAP_NET_ADMIN** (root), dan addon N-API native yang harus di-build dengan toolchain C (`npm run build:native:tproxy`). Jika tidak tersedia, tombol dasbor dinonaktifkan dengan tooltip "Dekripsi TPROXY memerlukan Linux + root + addon native". Aturan firewall diterapkan/dikembalikan secara transaksional (crash tidak akan pernah meninggalkan aturan `mangle`) dan dibersihkan saat reboot. Mekanisme anti-loop berbasis SO_MARK mencegah forward terenkripsi ulang milik proxy agar tidak dicegat kembali.

Ini adalah subsistem besar dengan panduan operator tersendiri — lihat `docs/security/MITM-TPROXY-DECRYPT.md` (git; tidak dikompilasi ke `/docs`) untuk resep firewall lengkap, CA dinamis per SNI + penginstal trust store, rute khusus lokal, detail anti-loop, dan skema konfigurasi. Tombol tersebut dikendalikan oleh `GET / POST / DELETE /api/tools/agent-bridge/tproxy` (catatan: route berada di bawah prefiks AgentBridge, bukan prefiks Traffic Inspector).

## §4 Fitur sadar-LLM

### 4.1 Pendeteksi jenis (`src/mitm/inspector/kindDetector.ts`)

Mengklasifikasikan setiap permintaan sebagai `"llm"`, `"app"`, atau `"unknown"` menggunakan 4 sinyal:

1. **Registri host** — ~18 nama host API LLM yang dikenal (OpenAI, Anthropic, Gemini, Groq, Mistral, Together, Fireworks, Cohere, Perplexity, Hugging Face, OpenRouter, xAI, Moonshot, dll.)
2. **Pola jalur** — `/v1/chat/completions`, `/v1/messages`, `/generateContent`, `/v1/responses`, dll.
3. **Struktur isi** — mendeteksi bidang `messages[]` (OpenAI/Claude), `contents[]` (Gemini), `prompt`, `input`
4. **Petunjuk user-agent** — `codex`, `claude`, `gemini`, `antigravity`, `kiro`, `copilot`, `cursor` dalam string UA

Host khusus yang ditambahkan melalui Mode 2 mewarisi `kind` dari input formulir (nilai defaultnya adalah `"custom"`).

### 4.2 Penggabung SSE (`src/mitm/inspector/sseMerger.ts`)

**Implementasi clean-room yang independen.** Penguraian peristiwa mengikuti
[algoritma server-sent events WHATWG](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream),
sedangkan rekonstruksi mengikuti skema streaming publik [OpenAI](https://platform.openai.com/docs/api-reference/chat/create),
[Anthropic](https://platform.claude.com/docs/en/build-with-claude/streaming), dan
[Gemini](https://ai.google.dev/api/generate-content#method:-models.streamgeneratecontent).

Merekonstruksi pesan akhir asisten dari peristiwa delta SSE mentah:

- **Anthropic**: mengakumulasi `content_block_delta` berdasarkan indeks; menangani `text_delta`, `input_json_delta` (pemanggilan alat), `thinking_delta`
- **OpenAI**: mengakumulasi pilihan/pemanggilan alat Chat Completions dan item output Responses API
  berdasarkan indeks
- **Gemini**: mengakumulasi `candidates[i].content.parts`
- **Tidak diketahui**: mengembalikan peristiwa mentah apa adanya

Tab Response menampilkan tombol alih: **"Peristiwa mentah ↔ Digabungkan"**.

### 4.3 Penormalisasi percakapan (`src/mitm/inspector/conversationNormalizer.ts`)

**Implementasi clean-room yang independen.** Normalisasi ditentukan oleh kontrak black-box
lokal dan skema pesan publik OpenAI, Anthropic, serta Gemini; tidak ada sumber implementasi
upstream yang digunakan.

Mengonversi format pesan OpenAI, Anthropic, dan Gemini menjadi satu `NormalizedConversation` sebelum dirender:

```ts
interface NormalizedConversation {
  request: NormalizedTurn[]; // pesan / konten / prompt dari isi permintaan
  response: NormalizedTurn[]; // respons asisten (digabungkan melalui sseMerger)
  contextKey: string | null; // sidik jari SHA-256 prompt sistem
}
```

Jenis blok: `text`, `tool_use`, `tool_result`. Tab Conversation menggunakan struktur ini tanpa memandang penyedia.

### 4.4 Pewarnaan kunci konteks (`src/mitm/inspector/contextKey.ts`)

- Menghitung `SHA-256` dari prompt sistem (pesan `role:system` pertama, atau bidang `system`, atau `systemInstruction` Gemini)
- Mengembalikan prefiks heksadesimal 12 karakter (`"a3f9c2..."`)
- Frontend memetakan kunci ke warna HSL deterministik untuk bilah batas kiri
- **Filter "konteks yang sama"**: mengeklik chip `ctx #a3f` akan menambahkan filter untuk hanya menampilkan permintaan dengan sidik jari yang sama

Hal ini memudahkan pembedaan visual antara berbagai "persona" atau tugas yang berjalan dalam sesi agen yang sama.

### 4.5 Ekstraksi metadata LLM

Untuk permintaan LLM, tab LLM Details mengekstrak:

```ts
interface LlmMetadata {
  provider: string | null; // "openai" | "anthropic" | "gemini" | ...
  apiKind: string | null; // "chat.completions" | "messages" | "embeddings" | ...
  model: string | null; // dari isi permintaan atau respons
  messages: number; // jumlah giliran
  tokensIn: number | null; // usage.prompt_tokens / usage.input_tokens
  tokensOut: number | null; // usage.completion_tokens / usage.output_tokens
  streamed: boolean; // true jika respons SSE
  mappedTo: string | null; // header x-omniroute-mapped
  costEstimateUsd: number | null; // perkiraan biaya berdasarkan harga OmniRoute
}
```

### 4.6 Filter permintaan aktif yang sedang berlangsung

Bidang `status` permintaan adalah `number | "in-flight" | "error"` — entri akan
dimasukkan sebagai `"in-flight"` saat permintaan dimulai dan **diperbarui di tempat**
ketika respons (atau kesalahan) tiba. Tombol alih **"Aktif"** pada toolbar
(`liveOnly`, kunci i18n `trafficInspector.liveOnly`) membatasi daftar ke entri
yang memiliki `status === "in-flight"`, sehingga Anda dapat memantau koneksi terbuka secara real-time.

Filter tersebut merupakan predikat murni sisi klien di
`src/lib/inspector/matchesTrafficFilter.ts`:

```ts
if (f.liveOnly && req.status !== "in-flight") return false;
```

Status tombol alih berada di `useTrafficFilters` (hook dasbor inspektur) dan
digabungkan dengan filter lainnya (profil, host, agen, sumber, status, konteks).

### 4.7 Atribusi proses (Linux)

Di Linux, setiap permintaan yang dicegat dapat diatribusikan ke **proses lokal
asal**. Dua bidang opsional ditambahkan ke `InterceptedRequest`:

```ts
pid?: number;          // id proses asal (khusus Linux)
processName?: string;  // nama proses asal (khusus Linux)
```

`src/mitm/inspector/processAttribution.ts` memetakan port sementara _klien_
koneksi ke PID + nama dengan cara:

1. Membaca `/proc/net/tcp` dan `/proc/net/tcp6` untuk menemukan inode soket bagi
   port tersebut (`parseProcNetTcpForInode`, parser murni yang dapat diuji menggunakan fixture).
2. Memindai `/proc/<pid>/fd/` untuk menemukan symlink ke `socket:[<inode>]`.
3. Membaca nama proses dari `/proc/<pid>/comm`.

Cache TTL 1 detik membatasi biaya pemindaian procfs saat beban tinggi. Atribusi
bersifat **upaya terbaik** — setiap kegagalan menghasilkan `null` dan tidak pernah menghambat penangkapan. Di
macOS/Windows, fungsi mengembalikan `null` (stub; dukungan `lsof`/`GetExtendedTcpTable`
akan ditambahkan kemudian).

## §5 Sesi

### 5.1 Merekam sesi

1. Klik **"● Rekam sesi"** di bilah alat → masukkan nama (opsional)
2. Tail langsung berlanjut seperti biasa; indikator merah yang berkedip menampilkan `◉ REC · <nama> · 00:42 · 23 permintaan`

### 5.2 Melihat sesi yang direkam

Dropdown **Sesi** di bilah alat mencantumkan sesi yang tersimpan. Memilih salah satunya akan:

- Memuat snapshot sesi (status dibekukan)
- Menampilkan banner: `Melihat sesi rekaman "<nama>" — [Kembali ke langsung]`
- Membuat tab Statistik tersedia dengan agregat Recharts

### 5.3 Format ekspor

Setiap sesi dapat diekspor sebagai:

| Format                     | Penggunaan                                                                        |
| -------------------------- | --------------------------------------------------------------------------------- |
| **HAR** (HTTP Archive 1.2) | Kompatibel dengan Chrome DevTools, Charles, Fiddler — impor untuk analisis luring |
| **JSONL**                  | Satu `InterceptedRequest` per baris — kompatibel dengan format `llm-interceptor`  |

Ekspor melalui `GET /api/tools/traffic-inspector/sessions/{id}/export.har` atau tombol ⬇ di dropdown Sesi.

## §6 Keamanan

Traffic Inspector menampilkan **semua lalu lintas HTTPS yang dicegat**, termasuk header otorisasi dan isi permintaan. Kontrol berikut diterapkan:

| Kontrol                            | Detail                                                                                                                                                                  |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LOCAL_ONLY**                     | Semua rute dan endpoint WebSocket hanya dapat diakses melalui loopback (diterapkan di `routeGuard.ts` sebelum autentikasi)                                              |
| **Penyamaran rahasia**             | Pemindai linear `maskSecret()` menyensor kredensial Bearer RFC 6750, kunci berprefiks penyedia, dan token panjang yang tidak transparan sebelum `TrafficBuffer.push()`  |
| **Batas ukuran isi**               | Isi > `INSPECTOR_MAX_BODY_KB` (default 1024 KB) dipotong dengan pemberitahuan `"(dipotong demi performa)"`                                                              |
| **Sanitasi header**                | Nama diubah menjadi huruf kecil; header framing/hop-by-hop dan autentikasi proksi dihapus; cookie disensor sepenuhnya; nilai kredensial didelegasikan ke `maskSecret()` |
| **CSP**                            | Content Security Policy yang ketat pada halaman Traffic Inspector untuk mencegah XSS melalui isi respons yang diinjeksi                                                 |
| **Tidak persisten secara default** | `TrafficBuffer` berada di memori dan hilang saat server dimulai ulang. Sesi hanya dipersistenkan ketika direkam secara eksplisit                                        |

### Aturan Ketat yang diterapkan

| Aturan                            | Penerapan                                                                                    |
| --------------------------------- | -------------------------------------------------------------------------------------------- |
| **#12** `sanitizeErrorMessage`    | Semua respons kesalahan HTTP dari rute Traffic Inspector disanitasi                          |
| **#15 + #17** `isLocalOnlyPath()` | `/api/tools/traffic-inspector/` bersifat LOCAL_ONLY + SPAWN_CAPABLE (perintah proksi sistem) |

### Keterbatasan yang diketahui

- **Mode proksi seluruh sistem** memengaruhi semua aplikasi pada mesin, termasuk klien VPN dan SSO. Selalu gunakan dengan timer penonaktifan otomatis. Jangan gunakan pada mesin bersama.
- **HTTPS terowongan CONNECT**: Mode 3 (HTTP_PROXY) hanya menangkap metadata terowongan untuk tujuan HTTPS kecuali intersepsi TLS diaktifkan. Ini memang dirancang demikian — penangkapan transparan tanpa sertifikat AgentBridge yang dipercaya akan merusak verifikasi TLS untuk aplikasi tersebut.
- **String yang di-hardcode di beberapa komponen**: Beberapa komponen UI (F7/F8) memiliki sejumlah kecil string yang di-hardcode dan belum tercakup oleh kunci i18n. Hal ini didokumentasikan sebagai Keterbatasan yang Diketahui dalam laporan kesenjangan i18n; string tersebut akan dimigrasikan dalam tahap lanjutan. String yang terdampak adalah label dekoratif UI yang tidak memerlukan terjemahan untuk penggunaan fungsional.

## §7 Pemecahan masalah

### Pemutusan koneksi WebSocket

Jika pemantauan langsung menampilkan "Terputus":

1. Periksa apakah server masih berjalan: `GET /api/tools/traffic-inspector/capture-modes`
2. Muat ulang halaman — WebSocket akan tersambung kembali dan menerima snapshot baru
3. Jika server dimulai ulang, buffer dalam memori telah dikosongkan — entri lama akan hilang kecuali sesi telah direkam

### Konflik port 8080

Jika mode HTTP_PROXY gagal dimulai:

```bash
lsof -i :8080    # temukan prosesnya
```

Ubah port:

```bash
# .env
INSPECTOR_HTTP_PROXY_PORT=8888
```

### Proksi sistem tidak dikembalikan

Jika OmniRoute mengalami crash saat mode proksi seluruh sistem aktif:

**macOS:**

```bash
networksetup -setwebproxystate Wi-Fi off
networksetup -setsecurewebproxystate Wi-Fi off
```

**Linux (GNOME):**

```bash
gsettings set org.gnome.system.proxy mode 'none'
```

**Windows:**

```cmd
netsh winhttp reset proxy
```

Dasbor juga akan menawarkan "Kembalikan proksi sistem" saat pemuatan berikutnya jika mendeteksi bahwa status DB menunjukkan proksi sebelumnya aktif.

### Buffer penuh

Ketika buffer mencapai `INSPECTOR_BUFFER_SIZE` (nilai bawaan 1000), entri baru akan menggantikan entri terlama. Jika permintaan penting hilang:

- Tingkatkan `INSPECTOR_BUFFER_SIZE` (misalnya, 5000) — menggunakan lebih banyak memori untuk memperpanjang retensi
- Rekam sesi untuk menyimpan rentang waktu yang relevan ke DB

## §8 Referensi API

Semua rute bersifat `LOCAL_ONLY` (hanya loopback) dan `SPAWN_CAPABLE` (perintah proksi sistem). Lihat `src/server/authz/routeGuard.ts`.

Path dasar: `/api/tools/traffic-inspector/`

### Pengelolaan permintaan

| Metode | Path                        | Deskripsi                                                                                     |
| ------ | --------------------------- | --------------------------------------------------------------------------------------------- |
| GET    | `/requests`                 | Cantumkan permintaan (dapat difilter: `?profile=llm&host=&agent=&status=&source=&sessionId=`) |
| GET    | `/requests/{id}`            | Detail satu permintaan                                                                        |
| DELETE | `/requests`                 | Kosongkan buffer dalam memori                                                                 |
| POST   | `/requests/{id}/replay`     | Jalankan kembali permintaan yang sama melalui router OmniRoute                                |
| PUT    | `/requests/{id}/annotation` | Simpan atau perbarui catatan pada permintaan                                                  |

### WebSocket

| Metode | Path  | Deskripsi                                                                                            |
| ------ | ----- | ---------------------------------------------------------------------------------------------------- |
| GET    | `/ws` | Aliran WebSocket langsung. Mengirim `snapshot` saat terhubung, lalu peristiwa `new`/`update`/`clear` |

### Ekspor

| Metode | Path          | Deskripsi                                        |
| ------ | ------------- | ------------------------------------------------ |
| GET    | `/export.har` | Ekspor daftar terfilter saat ini sebagai HAR 1.2 |

### Host khusus

| Metode | Path            | Deskripsi                                              |
| ------ | --------------- | ------------------------------------------------------ |
| GET    | `/hosts`        | Cantumkan host khusus                                  |
| POST   | `/hosts`        | Tambahkan host (mengedit `/etc/hosts` secara otomatis) |
| DELETE | `/hosts/{host}` | Hapus host                                             |
| PATCH  | `/hosts/{host}` | Aktifkan/nonaktifkan `enabled`                         |

### Mode penangkapan

| Metode | Path                           | Deskripsi                                                                                        |
| ------ | ------------------------------ | ------------------------------------------------------------------------------------------------ |
| GET    | `/capture-modes`               | Status mode AgentBridge / host khusus / HTTP_PROXY / proksi sistem + tombol alih `tls-intercept` |
| POST   | `/capture-modes/http-proxy`    | Mulai/hentikan listener HTTP_PROXY (`{action: "start"\|"stop"}`)                                 |
| POST   | `/capture-modes/system-proxy`  | Terapkan/kembalikan proksi seluruh sistem (`{action: "apply"\|"revert"}`)                        |
| POST   | `/capture-modes/tls-intercept` | Aktifkan/nonaktifkan dekripsi isi HTTPS dalam mode proksi (`{enabled: boolean}`)                 |

> **Dekripsi TPROXY** (mode penangkapan 5) dikendalikan oleh rute **terpisah** di bawah
> prefiks AgentBridge — `GET / POST / DELETE /api/tools/agent-bridge/tproxy` — bukan
> di bawah `/api/tools/traffic-inspector/`. Lihat
> `docs/security/MITM-TPROXY-DECRYPT.md` (git; tidak dikompilasi ke `/docs`).

### Sesi

| Metode | Path                        | Deskripsi                                                              |
| ------ | --------------------------- | ---------------------------------------------------------------------- |
| POST   | `/sessions`                 | Mulai merekam (`{name?: string}`)                                      |
| PATCH  | `/sessions/{id}`            | Hentikan atau ganti nama (`{action: "stop"\|"rename", name?: string}`) |
| GET    | `/sessions`                 | Cantumkan semua sesi tersimpan                                         |
| GET    | `/sessions/{id}`            | Snapshot sesi (semua permintaan)                                       |
| DELETE | `/sessions/{id}`            | Hapus sesi                                                             |
| GET    | `/sessions/{id}/export.har` | Ekspor sesi sebagai HAR 1.2                                            |

### Penyerapan internal (fallback D4)

| Metode | Path               | Deskripsi                                                                                                                |
| ------ | ------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| POST   | `/internal/ingest` | Menerima permintaan yang dicegat dari path passthrough `server.cjs`; memerlukan header `INSPECTOR_INTERNAL_INGEST_TOKEN` |

Skema OpenAPI lengkap: `docs/openapi.yaml` → tag `Traffic Inspector`.
