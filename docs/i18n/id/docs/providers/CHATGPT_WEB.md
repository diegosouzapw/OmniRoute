`chatgpt-web-codex` (alias `cgpt-codex`) menjembatani giliran Codex Responses melalui
sesi browser ChatGPT yang diautentikasi. Provider ini independen dari provider umum
`chatgpt-web` yang telah dihentikan dan menggunakan implementasi berlisensi MIT di
`open-sse/vendor/codex-chatgpt-web/`, yang diperbarui mengikuti commit upstream v4.0.7
`b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494`.

## Penghentian provider umum

ID provider umum sebelumnya, `chatgpt-web` dan `cgpt-web`, tidak lagi disertakan karena
asal-usul implementasi pre-key/proof-of-work miliknya tidak dapat dipastikan. Permintaan
eksplisit ke salah satu ID tersebut, termasuk ID model berawalan garis miring dan alias
yang tersimpan, ditolak secara tertutup dengan HTTP `410` dan kode **PROVIDER_RETIRED**
sebelum permintaan upstream apa pun.

Migrasi `168_retire_chatgpt_web.sql` menandai koneksi provider yang cocok sebagai tidak
aktif dan membatalkan lease sesi aktifnya. Migrasi ini mempertahankan riwayat koneksi
dan daftar izin kunci API; migrasi ini tidak menambahkan akses pengganti ke daftar izin.
Provider Codex dan koneksinya tidak terdampak oleh penghentian ini.

## Prasyarat

- header Cookie lengkap dari sesi ChatGPT yang telah login;
- Chrome atau Chromium beserta sesi grafis atau tampilan Xvfb untuk instalasi npm,
  systemd, dan PM2;
- dengan profil Docker `web`, layanan Chromium internal dari `docker-compose.yml`;
- OpenAI `tunnel-client` v0.0.13 dan konektor khusus ChatGPT untuk alat Codex lokal.

Tunnel hanya diperlukan untuk giliran yang menggunakan alat. Setiap rute yang tercantum,
termasuk `pro`, dapat menggunakan kapabilitas alat lokal yang terikat pada giliran yang
sama saat tunnel dan konektor dikonfigurasi.

## Penyiapan dasbor

1. Buka provider **ChatGPT Web (Codex)** dan tambahkan koneksi.
2. Tempelkan header Cookie ChatGPT lengkap, ID tunnel, runtime key, dan nama konektor
   khusus. Penyiapan baru yang mendukung alat harus menggunakan konektor yang baru dibuat
   dan diberi nama persis `OmniRoute Codex v2`, dengan Authentication diatur ke None dan
   Permissions diatur ke Allow all actions.
3. Jalankan pemeriksaan koneksi. OmniRoute membuka Temporary Chat berbasis browser dan
   mendeteksi apakah Sol dan Pro tersedia untuk akun tersebut.
4. Simpan koneksi. OmniRoute mengganti cookie yang ditempelkan dengan status penyimpanan
   Playwright yang telah diverifikasi dan menyimpannya bersama runtime key melalui
   abstraksi kredensial terenkripsi.

Cookie mentah tidak disimpan setelah berhasil disimpan. Saat sesi kedaluwarsa, buka
koneksi, tempelkan header Cookie lengkap yang baru, lalu jalankan kembali pemeriksaan.
Status doctor dalam dialog pengeditan melaporkan browser, status penyimpanan, login,
Temporary Chat, tunnel, konektor, dan perjalanan pulang-pergi alat secara terpisah.

> Jangan pernah melakukan commit terhadap cookie asli, runtime key, status penyimpanan,
> atau token kapabilitas. Nilai pengujian dan dokumentasi harus selalu berupa placeholder.

## Model dan combo

Rute model tetapnya adalah:

- `chatgpt-web-codex/luna` — GPT-5.6 Luna, upaya rendah
- `chatgpt-web-codex/think` — GPT-5.6 Luna, upaya sedang
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

Tambahkan salah satunya ke combo seperti model lainnya. Aplikasi Codex mengirimkan nama
combo sebagai `model` ke endpoint Responses reguler, `/v1/responses`; tidak ada endpoint
Codex atau peralihan mode yang terpisah.

Akun Free/Go menyediakan rute Luna. Akun yang mendukung Sol menyediakan Instant hingga
High, dan akun yang mendukung Pro juga menyediakan Extra High dan Pro. Setiap rute
memiliki model backend dan tingkat upaya penalaran tetap; tingkat upaya Responses
eksplisit yang bertentangan ditolak secara tertutup alih-alih mengubah mode browser yang
dipilih secara diam-diam.

Jangan mengganti nama atau menggunakan kembali konektor lama `Codex Native` atau
`OmniRoute Codex`. ChatGPT menyimpan cache kontrak MCP publik berdasarkan identitas
konektor, sedangkan bridge yang diperbarui menggunakan kontrak token giliran langsung
yang baru. Runtime menolak identitas lama tersebut dan mengharuskan konektor baru
`OmniRoute Codex v2`.

## Model keamanan

- Jalur native memerlukan permintaan Responses, klien Codex yang dikenali, serta identitas
  thread dan turn yang cocok.
- Workspace, sandbox, kebijakan persetujuan, dan katalog alat berasal dari shell Codex native;
  teks prompt bebas bukanlah otoritas untuk hal-hal tersebut.
- ChatGPT hanya menerima kapabilitas berumur pendek untuk setiap turn. Broker MCP hanya menerima
  alat yang ditawarkan Codex dalam turn tersebut.
- Konfirmasi otomatis **Izinkan sekali** hanya mengembalikan permintaan alat kepada Codex. Hanya Codex yang
  memutuskan persetujuan dan eksekusi.
- Sebelum output pertama, suatu kombinasi dapat beralih ke target kompatibel lainnya. Setelah
  output dimulai, penyedia, model, koneksi, dan turn browser tetap ditetapkan hingga
  turn selesai.
- Cookie, kunci runtime, status penyimpanan, dan token kapabilitas tidak muncul dalam respons
  penyedia ataupun log permintaan.

## VPS tanpa layar dan Docker

Untuk instalasi npm, systemd, dan PM2, OmniRoute mendeteksi jalur Chrome dan Chromium yang umum.
Sebagai alternatif, tetapkan `CHATGPT_WEB_CODEX_CHROME_PATH`. Turn runtime sengaja menggunakan
Chrome dengan antarmuka karena ChatGPT menolak karakteristik browser yang benar-benar headless. Oleh karena itu,
host tanpa layar harus menjalankan OmniRoute dengan tampilan Xvfb privat; menetapkan jalur Chrome saja tidak menyediakan tampilan tersebut.

Profil Docker `web` menjalankan `chatgpt-web-codex-browser` di jaringan internal Compose.
Sidecar menjalankan Chrome dengan antarmuka di dalam Xvfb, sehingga tidak diperlukan layar fisik. Port CDP-nya
tidak dipublikasikan pada host. Volume profil browser yang dilindungi terpisah dari
volume data OmniRoute, dan browser menerima memori bersama yang memadai. Proksi CDP internal
hanya mendengarkan pada port `9223` di dalam jaringan Compose; Chrome tetap terikat ke loopback di
sidecar.

Lease supervisor di bawah `DATA_DIR` mencegah beberapa proses OmniRoute memiliki
status tunnel dan broker yang sama. Konflik dilaporkan oleh doctor.

## Pemulihan interaktif

Jalur Docker otomatis tidak memiliki jendela yang terlihat dari host, tetapi Chrome sendiri berjalan dengan antarmuka di dalam
tampilan Xvfb privat. Saat ChatGPT memerlukan proses masuk atau tantangan interaktif, infrastruktur browser
VNC yang ada dapat digunakan untuk pemulihan. UI browser dan CDP harus tetap hanya dapat dijangkau
melalui loopback, koneksi manajemen yang diautentikasi, atau tunnel SSH; noVNC tetap dinonaktifkan
selama operasi normal.

## Fallback WebSocket

Saat suatu kombinasi berisi ChatGPT Web (Codex), bridge WebSocket Responses meminta
fallback HTTP/SSE sebelum tersambung ke upstream. Transfer kemudian berlangsung melalui
`/v1/responses`.
