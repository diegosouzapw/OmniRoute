`copilot-m365-web` (alias `m365copilot`) mengirim permintaan chat berformat OpenAI melalui sesi browser Microsoft 365 Copilot BizChat yang telah diautentikasi di
`m365.cloud.microsoft/chat`. Ini adalah integrasi tidak resmi.

> **Baru menggunakan penyedia Web Cookie?**
>
> Baca **`docs/getting-started/WEB-COOKIE-GUIDE.md`** untuk mengetahui proses penyiapan umum, panduan autentikasi, batasan, dan pemecahan masalah sebelum mengikuti panduan khusus penyedia ini.
>
> **Penting:** Kredensial untuk penyedia ini **bukan cookie**. Jangan menyalin
> cookie dari `m365.cloud.microsoft`. Kredensial tersebut berupa parameter kueri URL WebSocket
> dan segmen jalur, yang keduanya dibaca dari tab Network di DevTools.

## Prasyarat

- Akun Microsoft 365 dengan akses ke BizChat di `m365.cloud.microsoft/chat`
- Browser berbasis Chromium (Chrome, Edge) untuk memeriksa WebSocket melalui DevTools
- Lisensi M365 Copilot (disertakan dalam banyak paket Microsoft 365 Business/Enterprise)

## Pengambilan kredensial (metode WebSocket)

1. Masuk di `https://m365.cloud.microsoft/chat` dan mulai percakapan.
2. Buka **DevTools → Network**.
3. Filter berdasarkan **WS** (WebSocket).
4. Klik koneksi WebSocket Chathub. Cari URL yang diawali dengan
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Dari **Request URL**-nya, salin:
   - Nilai parameter kueri `access_token` (JWT berumur pendek).
   - Segmen jalur Chathub setelah `/Chathub/` (misalnya `<oid>@<tenant>`).

URL lengkap memiliki format:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. Di OmniRoute, buka **Providers → Add Provider**, pilih **Microsoft 365 Copilot
   (BizChat)**, lalu tempelkan kredensial dengan format:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Klik **Test Connection** dan **Save**.

## Pengambilan kredensial (impor HAR)

Alih-alih menyalin nilai secara manual dari URL WebSocket, Anda dapat mengekspor file HAR
DevTools:

1. Buka **DevTools → Network**.
2. Mulai atau lanjutkan percakapan BizChat (tindakan ini memicu koneksi WebSocket).
3. Klik kanan di panel Network lalu pilih **Save all as HAR with content**.
4. Di OmniRoute, gunakan tombol **Import .har file** pada dialog koneksi penyedia.

OmniRoute memindai HAR untuk menemukan URL WebSocket Chathub, mengekstrak
`access_token` dan `chathubPath`, lalu mengisi kolom kredensial secara otomatis. Impor
HAR mendekode waktu kedaluwarsa JWT dan menampilkan sisa masa berlaku token.

> **Jangan pernah melakukan commit terhadap ekspor HAR asli, token akses, atau token refresh.** Nilai pengujian dan
> dokumentasi harus selalu berupa placeholder.

## Masa berlaku dan refresh token

`access_token` berumur pendek (biasanya **~75 menit**). Setelah kedaluwarsa, penyedia
melaporkan kesalahan koneksi dan Anda harus mengambil ulang kredensial.

### Refresh otomatis dengan `refreshToken`

Untuk menghindari pengambilan ulang secara manual, Anda dapat menyimpan token refresh Microsoft di
**Advanced Settings → providerSpecificData** koneksi:

| Kolom          | Deskripsi                                                               |
| -------------- | ----------------------------------------------------------------------- |
| `refreshToken` | Token refresh OAuth Microsoft untuk scope `substrate.office.com/sydney` |
| `tier`         | `individual` (default), `edu`, atau `enterprise`                        |

Dapatkan token refresh dari alur device-code atau authorization-code Microsoft
dengan scope `substrate.office.com/sydney`. Jika `refreshToken` telah ditetapkan, OmniRoute
melakukan refresh awal terhadap `access_token` sebelum setiap permintaan sehingga Anda tidak perlu
mengambil ulang kredensial setelah setiap periode kedaluwarsa ~75 menit.

Jika `refreshToken` tidak ditetapkan, Anda harus mengambil ulang kredensial WebSocket secara manual
setelah setiap kali kedaluwarsa.

### Pemilihan tingkat

| Tingkat      | Alias       | Layanan                      |
| ------------ | ----------- | ---------------------------- |
| `individual` | _(default)_ | M365 Copilot Konsumen        |
| `edu`        | `included`  | M365 Copilot Pendidikan      |
| `enterprise` | `work`      | M365 Copilot untuk Pekerjaan |

Tetapkan tingkat di **Advanced Settings → providerSpecificData → tier**. Tingkat tersebut memengaruhi
perutean BizChat dan akses model.

## Model keamanan

- **Integrasi tidak resmi.** Penyedia ini merekayasa balik protokol WebSocket
  BizChat. Integrasi ini dapat berhenti berfungsi tanpa pemberitahuan ketika Microsoft mengubah endpoint.
- Flag `subscriptionRisk: true` menunjukkan bahwa integrasi ini bergantung pada
  endpoint yang tidak terdokumentasi. Pembatasan akun mungkin terjadi, tetapi belum dikonfirmasi.
- Token akses adalah JWT berumur pendek. Perlakukan seperti kata sandi: jangan melakukan commit,
  mencatatnya dalam log, atau membagikannya.
- Token penyegaran memberikan akses jangka panjang ke antarmuka BizChat. Simpan dengan
  tingkat kehati-hatian yang sama seperti kunci API.

## Pemecahan masalah

### Autentikasi langsung gagal

- Pastikan Anda menyalinnya dari **URL WebSocket**, bukan dari permintaan XHR/Fetch. Kredensial
  berada dalam parameter kueri `access_token` pada koneksi WebSocket Chathub
  — bukan dalam header `Authorization: Bearer`.
- Pastikan `chathubPath` menyertakan segmen `<oid>@<tenant>` lengkap dari path
  URL.

### Token kedaluwarsa setelah ~75 menit

Ini normal. Tanpa `refreshToken`, token akses berumur pendek. Anda dapat:

- Mengambil ulang kredensial dari DevTools, atau
- Mengonfigurasi `refreshToken` di Pengaturan Lanjutan untuk penyegaran otomatis.

### Uji Koneksi berhasil, tetapi chat menghasilkan 401

Token mungkin telah kedaluwarsa di antara validasi dan permintaan pertama. Ambil ulang
kredensial baru.

### Copilot tidak muncul dalam daftar penyedia

Pastikan `copilot-m365-web` diaktifkan di **Dasbor → Penyedia**. Penyedia tersebut mungkin
disembunyikan secara default pada beberapa tingkat langganan.
