Dokumen ini mencatat keputusan implementasi untuk
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854). Produk publik direpresentasikan
sebagai empat keluarga penyedia. Wilayah merupakan data koneksi, bukan produk terpisah.

## Keputusan

| Keluarga penyedia                                   | ID OmniRoute            | Wilayah global | Wilayah Tiongkok |
| --------------------------------------------------- | ----------------------- | -------------- | ---------------- |
| Alibaba Cloud Model Studio (bayar sesuai pemakaian) | `alibaba`               | Singapura      | Beijing          |
| Alibaba Cloud Token Plan                            | `bailian-coding-plan`   | Singapura      | Beijing          |
| Qwen Cloud (bayar sesuai pemakaian)                 | `qwen-cloud`            | Global         | Beijing          |
| Qwen Cloud Token Plan                               | `qwen-cloud-token-plan` | Singapura      | Beijing          |

ID `alibaba-cn` yang sudah ada tetap dipertahankan sebagai alias kompatibilitas runtime untuk koneksi
tersimpan, rute model, kombinasi, dan riwayat penggunaan. Kartu dasbornya digabungkan ke dalam
`alibaba`; tidak diperlukan penulisan ulang basis data.

Qwen Cloud bayar sesuai pemakaian dan Alibaba Cloud Model Studio saat ini menggunakan host runtime
yang kompatibel dengan DashScope, tetapi keduanya tetap menjadi identitas penyedia yang terpisah
karena pengguna memperoleh kunci dan mengelola akun melalui antarmuka produk yang berbeda. Produk
Alibaba dan Qwen Cloud Token Plan menggunakan keluarga endpoint yang berbeda, sehingga keempat
produk tersebut tetap menggunakan ID penyedia yang terpisah.

## Matriks endpoint

| Keluarga penyedia       | `global-sg`                                                              | `china-beijing`                                                      | Format protokol |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | --------------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI          |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic       |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI          |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI          |

Kunci API dan endpoint harus berasal dari produk dan wilayah yang sama. Memilih wilayah akan
mengubah endpoint prasetel yang digunakan oleh validasi dan permintaan normal.

## Kontrak koneksi

Koneksi baru menyimpan kunci wilayah yang stabil dalam `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

Nilai yang diizinkan adalah `global-sg` dan `china-beijing`. Endpoint diturunkan secara terpusat
dari ID penyedia dan wilayah. `providerSpecificData.baseUrl` non-prasetel tetap menjadi penggantian
eksplisit oleh operator dan memiliki prioritas, sementara URL prasetel lama yang tersimpan
dinormalisasi kembali ke matriks regional.

Hal ini menjaga agar skema koneksi tetap dapat diperluas: wilayah lain dapat ditambahkan ke resolver
tanpa membuat kartu penyedia lain atau mengubah ID penyedia yang tersimpan.

## Kompatibilitas dan peluncuran

1. Tambahkan resolver endpoint regional dan pertahankan default global saat ini.
2. Gunakan penemuan langsung `/models` DashScope regional untuk `alibaba`, ID kompatibilitas
   `alibaba-cn` miliknya, dan `qwen-cloud`. Responsnya terlebih dahulu melewati satu filter
   pembuatan teks karena endpoint generik juga mengembalikan model gambar, video, audio, embedding,
   dan model non-chat lainnya. `qwen-cloud` kemudian menerapkan daftar izin yang dipelihara dan
   dideklarasikan dalam registri providernya. Alibaba Model Studio dan Qwen Cloud mempertahankan
   katalog terkurasi yang terpisah meskipun saat ini keduanya menggunakan host runtime yang sama.
3. Daftarkan `qwen-cloud-token-plan` dengan daftar izin model teks Token Plan saat ini.
4. Tambahkan pemilih region bertipe ke dialog penambahan/pengeditan koneksi.
5. Sembunyikan kartu duplikat `alibaba-cn` dan sertakan koneksi yang sudah ada pada halaman
   provider `alibaba`.
6. Pertahankan override endpoint khusus agar tetap tersedia untuk deployment tingkat lanjut dan
   khusus workspace.

Model media Token Plan tetap berada di luar katalog chat karena menggunakan endpoint khusus.
`wan2.7-image` dan `wan2.7-image-pro` didaftarkan di `open-sse/config/imageRegistry.ts`;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, dan `happyhorse-1.1-r2v` didaftarkan di
`open-sse/config/videoRegistry.ts`. Kedua registri menggunakan kembali identitas koneksi
`qwen-cloud-token-plan` dan kredensial khusus region miliknya.

Qwen Cloud reguler memiliki katalog gambar dan video bayar sesuai pemakaian yang terpisah di bawah
identitas `qwen-cloud`. Model gambarnya adalah `wan2.7-image-pro`, `wan2.7-image`,
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03`, dan
`z-image-turbo`. Model videonya adalah `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`,
`happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`,
`wan2.7-r2v-2026-06-12`, dan `wan2.7-videoedit`. Model-model ini hanya menggunakan kembali koneksi
`qwen-cloud` reguler dan endpoint media DashScope regional. Registri Token Plan dan bayar sesuai
pemakaian tidak mewarisi atau menggabungkan daftar model satu sama lain.

Identitas `bailian-coding-plan` juga memiliki daftar izin media sendiri:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0`, dan `qwen-image-2.0-pro` untuk pembuatan
gambar, serta
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, dan `happyhorse-1.1-r2v` untuk pembuatan
video. Identitas ini hanya menggunakan koneksi Bailian Coding Plan dan endpoint Coding Plan
regional. Registri gambar dan videonya tidak mewarisi dari atau digabungkan dengan provider Qwen
Cloud mana pun.

Identitas `alibaba` reguler memiliki daftar izin gambar dan video yang terpisah. Model gambarnya
adalah `qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo`, dan `wan2.6-t2i`. Model video yang ditambahkan adalah `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12`, dan `wan2.7-videoedit`. Model-model ini hanya menggunakan koneksi Alibaba
Model Studio dan endpoint media regional yang dipilih; model-model tersebut tidak ditambahkan ke
registri Coding Plan atau Qwen Cloud mana pun.

Katalog chat Qwen Cloud Token Plan mengikuti daftar izin teks berbasis pencocokan string persis
milik paket Individual: `qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`,
`qwen3.6-flash`, `glm-5.2`, dan `deepseek-v4-pro`. Entri Wan dan HappyHorse termasuk dalam API
pembuatan gambar/video yang terpisah.

Alibaba Token Plan menyediakan enam ID model pembuatan teks yang sama melalui endpoint yang
kompatibel dengan Anthropic. Opsi Singapura menyimpan kunci region `global-sg` yang sudah ada;
hanya label yang ditampilkan kepada pengguna yang berbeda dari keluarga provider yang menyebut
region tersebut Global.

Katalog chat Qwen Cloud reguler sengaja dibuat lebih sempit daripada respons teks langsung
selengkapnya. Daftar izin yang dipelihara berada di
`open-sse/config/providers/registry/qwen-cloud/index.ts`; penemuan langsung hanya mengembalikan ID
yang terdapat dalam respons upstream sekaligus dalam daftar registri tersebut.

Alibaba Model Studio mengikuti aturan irisan langsung yang sama dengan daftar izin yang dipelihara
secara independen di `open-sse/config/providers/registry/alibaba/index.ts`. Provider kompatibilitas
`alibaba-cn` menggunakan kembali katalog tersebut, tetapi melakukan resolusi penemuan terhadap
endpoint Beijing.
