## Ringkasan

OmniRoute kini mendukung tiga mode relai untuk `/api/v1/relay/chat/completions`:

- `ts`: Menggunakan relai TypeScript dalam proses.
- `bifrost`: Memaksa penggunaan gateway Bifrost.
- `auto`: Memprioritaskan Bifrost saat tersedia dan beralih kembali ke TypeScript jika terjadi kegagalan.

Saat Anda menangani tingkat permintaan yang tinggi (jumlah token/hari yang besar, throughput yang nyaris konstan), strategi terbaik adalah mempertahankan jalur fallback yang eksplisit dan cepat agar jalur utama tidak pernah terhambat oleh sidecar yang tidak berfungsi.

## Perilaku mode

- `ts`
  - Kompleksitas operasional paling rendah.
  - Semua perutean dan validasi berjalan di Node.
  - Ketersediaan tidak bergantung pada sidecar.
- `bifrost`
  - Memaksa semua permintaan melalui gateway sidecar.
  - Tidak ada fallback otomatis.
  - Hanya berguna ketika kesehatan dan latensi sidecar terjamin.
- `auto`
  - Sidecar digunakan saat dapat dijangkau dan diaktifkan.
  - Upaya yang gagal memicu header fallback dan mengembalikan lalu lintas ke TS agar keberhasilan permintaan tetap terjaga dalam batas waktu.
  - Mode ini merupakan pilihan paling aman untuk produksi ketika waktu aktif lebih penting daripada perutean yang secara ketat hanya melalui sidecar.

## 9router vs CLIPROXYAPI saat ini

9router dan CLIPROXYAPI merupakan integrasi yang secara historis menyediakan jalur kompatibilitas untuk penyedia upstream.

- 9router adalah jalur tertanam untuk orkestrasi upstream dan perilaku kompatibilitas.
- CLIPROXYAPI adalah jembatan API proksi untuk lalu lintas bergaya CLI / SDK.
- Bifrost sedang distabilkan sebagai jalur eksternal ketika Anda memerlukan lompatan khusus seperti sidecar dan pengiriman lokal berlatensi rendah.

Jika saat ini Anda membandingkan 9router/CLIPROXYAPI:

- Pertahankan penandatanganan permintaan, pemeriksaan daftar yang diizinkan, dan gerbang kebijakan DB di rute API sebelum serah terima.
- Jika alur kerja memerlukan perilaku sidecar yang ketat dan variansi per permintaan yang lebih rendah, gunakan `OMNIROUTE_RELAY_BACKEND=bifrost`.
- Jika Anda memerlukan ketahanan sidecar dengan degradasi terkendali dalam kondisi insiden, gunakan `OMNIROUTE_RELAY_BACKEND=auto`.

## Kontrak batas backend

Batas produk yang stabil adalah API relai OmniRoute, bukan implementasi dasbor. Dasbor Next.js dapat menginstal, mengonfigurasi, dan mengawasi layanan lokal, tetapi perutean permintaan harus masuk melalui API relai dan diserahkan di balik batas tersebut.

Pilihan backend jangka panjang:

- Pertahankan relai TypeScript sebagai jalur kebijakan dan fallback dalam proses. Autentikasi, daftar yang diizinkan, normalisasi permintaan, pencatatan penggunaan, dan pemeriksaan keamanan tetap dilakukan di sini sebelum serah terima ke backend mana pun.
- Gunakan Bifrost sebagai sidecar Tier-1 ber-throughput tinggi yang diutamakan ketika deployment memerlukan variansi perutean yang lebih rendah, rotasi penyedia terpusat, atau penskalaan horizontal di beberapa replika OmniRoute.
- Pertahankan 9router dan CLIPROXYAPI sebagai layanan kompatibilitas tertanam. Keduanya berjalan sebagai proses lokal yang diawasi dan berguna ketika perilaku penyedia/CLI mereka merupakan adaptor yang diinginkan, tetapi keduanya tidak boleh menjadi mesin perutean Tier-1 default.
- Jangan izinkan dasbor meneruskan URL layanan arbitrer ke jalur utama. URL yang diberikan melalui UI merupakan input konfigurasi; kode perutean harus menetapkan backend yang terdaftar dan telah diperiksa kesehatannya dari pengaturan sisi server serta status supervisor.
- Untuk saat ini, prioritaskan HTTP loopback bagi layanan yang diawasi karena proses terkelola tersebut sudah menyediakan API yang kompatibel dengan HTTP, penjaga rute dapat mengaudit batas tersebut, dan perilaku kegagalan/fallback terlihat dalam log permintaan. Transport SDK atau socket pada masa mendatang hanya layak ditambahkan jika dapat menurunkan latensi perutean p99 secara terukur tanpa melemahkan isolasi atau semantik fallback.

Oleh karena itu, untuk deployment ber-throughput sangat tinggi, pilihan default adalah `auto` dengan Bifrost diaktifkan: gunakan sidecar Go pada jalur utama sambil mempertahankan fallback TypeScript demi tingkat keberhasilan. Gunakan `bifrost` hanya ketika perilaku ketat yang sepenuhnya bergantung pada sidecar lebih penting daripada degradasi terkendali.

## Panduan throughput tinggi

Untuk RPM/RPS tinggi yang berkelanjutan dan SLO keberhasilan yang ketat:

1. Gunakan `auto` dengan periode cooldown yang praktis dan telemetri kegagalan.
2. Pertahankan validasi upstream dan pemeriksaan kunci API pada batas rute TypeScript.
3. Aktifkan header/penghitung eksplisit agar sistem peringatan Anda dapat mendeteksi frekuensi dan alasan fallback.
4. Sesuaikan batas waktu sidecar agar gagal dengan cepat, bukan menunggu tanpa batas.
5. Pastikan mulai ulang otomatis layanan dan loop telemetri kesehatan tetap berfungsi dengan baik agar fallback benar-benar hanya terjadi dalam kondisi luar biasa.

## Konfigurasi dasar yang disarankan

- `OMNIROUTE_RELAY_BACKEND=auto`
- `BIFROST_ENABLED=1`
- Pertahankan pemeriksaan kunci API, daftar yang diizinkan, sanitizer, dan batas laju dalam keadaan aktif di handler rute (pemeriksaan tersebut selalu dijalankan sebelum penerusan ke downstream).
- Ekspor metrik fallback dari proksi terbalik dan log permintaan agar gangguan sidecar dapat terdeteksi dalam waktu satu menit.
