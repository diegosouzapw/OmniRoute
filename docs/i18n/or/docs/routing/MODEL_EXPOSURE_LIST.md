> ସ୍ୱଇଚ୍ଛାରେ ସକ୍ରିୟ କରାଯାଏ, ଡିଫଲ୍ଟ ଭାବେ ବନ୍ଦ (`modelVisibilityAllowlist`/`modelVisibilityDenylist` ଉଭୟ ଖାଲି ଥିଲେ
> `/v1/models` କ୍ୟାଟାଲଗ୍ ଏବଂ ପ୍ରତ୍ୟେକ `auto/*` ପ୍ରାର୍ଥୀ ପୁଲ୍ ବାଇଟ୍-ସ୍ତରରେ ଅପରିବର୍ତ୍ତିତ ରହେ)। ଖର୍ଚ୍ଚ ସହ
> କୌଣସି ସମ୍ପର୍କ ନଥିବା କାରଣରୁ ଏକ ସୁବ୍ୟବସ୍ଥିତ ମଡେଲ୍ ତାଲିକା ଚାହୁଁଥିବା ଅପରେଟର୍ମାନଙ୍କ ପାଇଁ
> `hidePaidModels`/`hideAutoCombos` (`src/lib/db/settings.ts`)ର ଏକ ସହୋଦର ସେଟିଂ।

## ଏହା କାହିଁକି ରହିଛି

`hidePaidModels` "ଏହି ମଡେଲ୍ଟି ମାଗଣା କି?" ପ୍ରଶ୍ନର ଉତ୍ତର ଦିଏ ଏବଂ `hideAutoCombos` "`auto/*`
ଭର୍ଚୁଆଲ୍ idଗୁଡ଼ିକୁ ଆଦୌ ପ୍ରଚାର କରାଯିବା ଉଚିତ କି?" ପ୍ରଶ୍ନର ଉତ୍ତର ଦିଏ — କୌଣସିଟି ମଧ୍ୟ ଏକ ଅପରେଟର୍କୁ
ମଡେଲ୍ଗୁଡ଼ିକର ଏକ ଇଚ୍ଛାନୁସାରୀ ଉପସେଟ୍ ସୁବ୍ୟବସ୍ଥିତ କରିବାକୁ ଦିଏ ନାହିଁ (ଉଦାହରଣସ୍ୱରୂପ, ମୂଲ୍ୟ ନିର୍ଦ୍ଧାରଣରୁ
ସ୍ୱାଧୀନ ଭାବେ, ଏକ ନିର୍ଦ୍ଦିଷ୍ଟ Claude Code / OpenCode କ୍ଲାଏଣ୍ଟ ଯେଉଁ ମଡେଲ୍ଗୁଡ଼ିକୁ ଦେଖିବା ଉଚିତ ଠିକ୍
ସେହିଗୁଡ଼ିକୁ ପ୍ରଦର୍ଶନ କରିବା)। #11481 ଏହାକୁ ଦୁଇଟି ସ୍ୱାଧୀନ, ସ୍ୱଇଚ୍ଛାରେ ସକ୍ରିୟ କରାଯାଉଥିବା
ଷ୍ଟ୍ରିଙ୍ଗ୍-ଆରେ ସେଟିଂ ଭାବେ ଯୋଗ କରେ।

## ସେଟିଂଗୁଡ଼ିକ

| କୀ                         | ପ୍ରକାର     | ଡିଫଲ୍ଟ | ଅର୍ଥ                                                                           |
| -------------------------- | ---------- | ------ | ------------------------------------------------------------------------------ |
| `modelVisibilityDenylist`  | `string[]` | `[]`   | କୌଣସି ପ୍ରାର୍ଥୀ ସହ ମେଳ ଖାଉଥିବା ଏଣ୍ଟ୍ରି ତାହାକୁ କ୍ୟାଟାଲଗ୍/ପ୍ରାର୍ଥୀ ପୁଲ୍ରୁ ଲୁଚାଏ।  |
| `modelVisibilityAllowlist` | `string[]` | `[]`   | ଖାଲି ନଥିଲେ, କେବଳ କୌଣସି ପ୍ରାର୍ଥୀ ସହ ମେଳ ଖାଉଥିବା ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ ହିଁ ପ୍ରକାଶିତ ରହେ। |

ଉଭୟ ପ୍ରତ୍ୟେକ 200 ଅକ୍ଷର ପର୍ଯ୍ୟନ୍ତ ଥିବା ସର୍ବାଧିକ 500ଟି ଏଣ୍ଟ୍ରି ଗ୍ରହଣ କରେ
(`src/shared/validation/settingsSchemas.ts`ରେ Zod ଦ୍ୱାରା ବୈଧତା ଯାଞ୍ଚ କରାଯାଏ)। ଏକ ଏଣ୍ଟ୍ରି ନିମ୍ନରୁ ଗୋଟିଏ:

- ଏକ ସଠିକ୍ କ୍ୟାଟାଲଗ୍ id — `"gpt-4o"` (କେବଳ ମଡେଲ୍ id) କିମ୍ବା `"openai/gpt-4o"` (ପ୍ରଦାନକାରୀ-ପ୍ରିଫିକ୍ସଯୁକ୍ତ), କିମ୍ବା
- `*`/`?` ବ୍ୟବହାର କରୁଥିବା ଏକ ଗ୍ଲବ୍ ପ୍ୟାଟର୍ନ୍ — ଯେପରି `"openai/gpt-4*"` କିମ୍ବା `"anthropic/*"` — ଏହାକୁ
  ସେହି ସାଧାରଣ `globToRegex()` ମ୍ୟାଚର୍ (`src/shared/utils/globPattern.ts`) ମାଧ୍ୟମରେ ସମାଧାନ କରାଯାଏ, ଯାହା ପୂର୍ବରୁ
  `ModelRoutingSection`ର ପ୍ରତି-ମଡେଲ୍ କମ୍ବୋ ମ୍ୟାପିଂ ଏବଂ `freeModels.ts::matchesOnlyPaidModels` ଦ୍ୱାରା ବ୍ୟବହୃତ ହେଉଛି।

ପ୍ରାଥମିକତା: ପ୍ରଥମେ ଡିନାଇଲିଷ୍ଟ ଯାଞ୍ଚ କରାଯାଏ (ଏକ ପ୍ରତ୍ୟାଖ୍ୟାତ ଏଣ୍ଟ୍ରି ସର୍ବଦା ଲୁଚାଯାଏ, ଯଦିଓ ତାହା
ଆଲାଉଲିଷ୍ଟ ସହ ମେଳ ଖାଏ); ଆଲାଉଲିଷ୍ଟ ଖାଲି ନଥିଲେ, କେବଳ ଏହା ସହ ମେଳ ଖାଉଥିବା ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ ରହିଯାଏ।

## ଗୋଟିଏ ନୁହେଁ, ଦୁଇଟି ଚୋକ୍ପଏଣ୍ଟ

#6512ରୁ ମିଳିଥିବା ଶିକ୍ଷା (କେବଳ `hidePaidModels` ଭିତ୍ତିକ କ୍ୟାଟାଲଗ୍ ଫିଲ୍ଟର୍ ତଥାପି `auto/*`କୁ ଏକ
ପେଡ୍ ମଡେଲ୍କୁ ରୁଟ୍ କରିବାକୁ ଦେଇଥିଲା, କାରଣ କମ୍ବୋ ପ୍ରାର୍ଥୀ ପୁଲ୍ ସ୍ୱାଧୀନ ଭାବେ ନିର୍ମିତ ହୋଇଥିଲା) ଏଠାରେ
ଠିକ୍ ସେହିପରି ପ୍ରଯୁଜ୍ୟ। ମ୍ୟାଚିଂ ପ୍ରେଡିକେଟ୍ `isModelExposureAllowed()` (`src/shared/utils/modelExposureList.ts`)କୁ
ଉଭୟ ସ୍ଥାନରୁ କଲ୍ କରାଯାଏ:

- `src/app/api/v1/models/catalog.ts` — `/v1/models` ତାଲିକା ସ୍ୱୟଂ, ସେହି 5ଟି ପ୍ରତି-ଉତ୍ସ
  ଚୋକ୍ପଏଣ୍ଟରେ ଯେଉଁଠାରେ `shouldHidePaid()` ପୂର୍ବରୁ ଗେଟ୍ କରେ (ସ୍ଥିର `PROVIDER_MODELS`, ସିଙ୍କ୍ ହୋଇଥିବା ପ୍ରଦାନକାରୀ ରୋ,
  କଷ୍ଟମ୍ ରୋ, ଏଲିଆସ୍-ସମର୍ଥିତ ରୋ, ପରିଚାଳିତ-ଫଲ୍ବ୍ୟାକ୍ ରୋ)।
- `open-sse/services/autoCombo/modelExposureFilter.ts::filterModelExposureCandidates()` — ସମତୁଲ୍ୟ
  `filterPaidOnlyCandidates()` କଲ୍ର ତୁରନ୍ତ ପରେ `virtualFactory.ts::buildPreparedPool`ରୁ କଲ୍ କରାଯାଏ,
  ଯାହାଦ୍ୱାରା ଏକ ପ୍ରତ୍ୟାଖ୍ୟାତ ମଡେଲ୍କୁ କଦାପି କୌଣସି `auto/*` ପ୍ରାର୍ଥୀ ପୁଲ୍ରେ ଚୟନ କରାଯାଇପାରିବ ନାହିଁ।

## କ’ଣ ଫିଲ୍ଟର୍ କରାଯାଏ ନାହିଁ

`hideAutoCombos`ର ବିଦ୍ୟମାନ ଆଚରଣକୁ ଅନୁସରଣ କରେ: **ସ୍ପଷ୍ଟ ଭାବେ** ପଠାଯାଇଥିବା ଏକ ମଡେଲ୍ id (`auto/*` ମାଧ୍ୟମରେ ନୁହେଁ,
ଏବଂ କ୍ୟାଟାଲଗ୍ ତାଲିକା ମାଧ୍ୟମରେ ଆବିଷ୍କୃତ ନୁହେଁ) ଡିସ୍ପାଚ୍ ସମୟରେ କେବେବି ବ୍ଲକ୍ କରାଯାଏ ନାହିଁ — କେବଳ
ପ୍ରଚାର/ପ୍ରାର୍ଥୀ-ପୁଲ୍ ସଦସ୍ୟତାକୁ ଫିଲ୍ଟର୍ କରାଯାଏ। ଏହା `hidePaidModels`ରୁ ସ୍ୱାଧୀନ;
ଏକ ଅପରେଟର୍ ଖର୍ଚ୍ଚ ସହ କୌଣସି ସମ୍ପର୍କ ନଥିବା କାରଣରୁ ଏକ ସୁବ୍ୟବସ୍ଥିତ ସେଟ୍ ଚାହିଁପାରନ୍ତି, ତେଣୁ ଉଭୟ
ସେଟିଂ ସ୍ୱାଧୀନ AND-କରାଯାଇଥିବା ଫିଲ୍ଟର୍ ଭାବେ ସଂଯୋଜିତ ହୁଏ, `catalog.ts`ର ବିଦ୍ୟମାନ ମଲ୍ଟି-ଫ୍ଲାଗ୍ ସଂଯୋଜନ ପରି।

ସେଟିଂ ରପ୍ତାନି (`GET /api/settings/export-json`) ଅନ୍ୟ ଯେକୌଣସି ସେଟିଂ ଫିଲ୍ଡ ପରି ଉଭୟ ଆରେକୁ ଅବିକଳ ଭାବେ
ଅନ୍ତର୍ଭୁକ୍ତ କରେ — `hidePaidModels`ର କମ୍ବୋ-ଷ୍ଟେପ୍ ରପ୍ତାନି ଫିଲ୍ଟର୍ ପରି ନୁହେଁ, ଏଠାରେ ପୁନଃ-ହାଇଡ୍ରେସନ୍
ବିପଦ ନାହିଁ: ରପ୍ତାନି କରାଯାଇଥିବା କମ୍ବୋ ଷ୍ଟେପ୍ରେ ଏମ୍ବେଡ୍ ହୋଇଥିବା ଏକ ପ୍ରତ୍ୟାଖ୍ୟାତ id ହେଉଛି
ଅପରେଟର୍ଙ୍କ ନିଜସ୍ୱ ସ୍ପଷ୍ଟ ରାଉଟିଂ ପସନ୍ଦ, ରପ୍ତାନି ସୀମାରେ ହଟାଇବାକୁ ପଡ଼ୁଥିବା କିଛି ନୁହେଁ।
