## ସାରାଂଶ

କୋଟା ସହଭାଗୀକରଣ ଇଞ୍ଜିନ୍ ସମାନ ସଂଯୋଗ ସହଭାଗ କରୁଥିବା ଏକାଧିକ API କୀ ମଧ୍ୟରେ ପ୍ରଦାତାଙ୍କ ସମୟ-ଆଧାରିତ କୋଟାକୁ (ଯଥା Codex
5-ଘଣ୍ଟିଆ ୱିଣ୍ଡୋ, Kimi 1500 ଅନୁରୋଧ/ଘଣ୍ଟା) ନ୍ୟାୟସଙ୍ଗତ ଭାବରେ ବଣ୍ଟନ କରେ।

**ଏହା ସମାଧାନ କରୁଥିବା ସମସ୍ୟା:** OmniRoute ସମାନ ଅପ୍ଷ୍ଟ୍ରିମ୍
ପ୍ରଦାତା ଆକାଉଣ୍ଟ ବିପରୀତରେ ଅନେକ API କୀକୁ ପ୍ରକ୍ସି କରେ। ସହଭାଗୀକରଣ ଲଜିକ୍ ବିନା, କୀ A-ରୁ ହଠାତ୍ ଅଧିକ ଅନୁରୋଧ ସେହି
ଘଣ୍ଟା ପାଇଁ ପ୍ରଦାତା କୋଟାକୁ ସମ୍ପୂର୍ଣ୍ଣ ଶେଷ କରିପାରେ, ଫଳରେ ୱିଣ୍ଡୋ ରିସେଟ୍ ହେବା ପର୍ଯ୍ୟନ୍ତ କୀ B ଏବଂ C ଅବରୋଧିତ ରହିବ।
ଇଞ୍ଜିନ୍ ନିମ୍ନ ପ୍ରକାରେ ଏହାକୁ ପ୍ରତିରୋଧ କରେ:

1. ପ୍ରତ୍ୟେକ ଡାଇମେନ୍ସନ୍ (%, ଅନୁରୋଧ, ଟୋକନ୍, $) ପାଇଁ ପ୍ରତ୍ୟେକ କୀର ରୋଲିଂ ବ୍ୟବହାର ଟ୍ରାକ୍ କରିବା।
2. ଏକ କାର୍ଯ୍ୟ-ସଂରକ୍ଷକ ନ୍ୟାୟସଙ୍ଗତ-ହିସ୍ସା ଆଲଗୋରିଦମ୍ ପ୍ରୟୋଗ କରିବା: ଗ୍ଲୋବାଲ୍ ପୁଲ୍ ସାଚୁରେଟ୍ ହୋଇନଥିବାବେଳେ ଗୋଟିଏ କୀ ନିଷ୍କ୍ରିୟ
   ହିସ୍ସାରୁ ଧାର ନେଇପାରିବ।
3. ଅନୁରୋଧଟି ଅପ୍ଷ୍ଟ୍ରିମ୍ ଏକ୍ସିକ୍ୟୁଟର୍ ପାଖରେ ପହଞ୍ଚିବା ପୂର୍ବରୁ ହଟ୍ ପାଥ୍ (`chatCore.ts`) ମଧ୍ୟରେ ଫଳାଫଳକୁ
   ଲାଗୁ କରିବା।

## ଆଲଗୋରିଦମ୍: କାର୍ଯ୍ୟ-ସଂରକ୍ଷକ ନ୍ୟାୟସଙ୍ଗତ-ହିସ୍ସା

`src/lib/quota/fairShare.ts` ମଧ୍ୟରେ କାର୍ଯ୍ୟକାରୀ କରାଯାଇଛି।

### ମୋଡ୍ଗୁଡ଼ିକ

| ସର୍ତ୍ତ                                     | ମୋଡ୍     | ଆଚରଣ                                                          |
| ------------------------------------------ | -------- | ------------------------------------------------------------- |
| `globalUsedPercent < saturationThreshold`  | **ଉଦାର** | କୀ ବ୍ୟବହୃତ-ମୋଟକୁ ବାଦ ଦେଇ ଗ୍ଲୋବାଲ୍ ସୀମା ପର୍ଯ୍ୟନ୍ତ ଧାର ନେଇପାରିବ |
| `globalUsedPercent >= saturationThreshold` | **କଠୋର** | ବ୍ୟକ୍ତିଗତ ନ୍ୟାୟସଙ୍ଗତ ହିସ୍ସାକୁ କଠୋର ଭାବରେ ଲାଗୁ କରେ             |

ଡିଫଲ୍ଟ `saturationThreshold = 0.5` (env `QUOTA_SATURATION_THRESHOLD`)।

### ପ୍ରତି-ଡାଇମେନ୍ସନ୍ ନିଷ୍ପତ୍ତି

ପୁଲ୍ର ପ୍ରତ୍ୟେକ ସକ୍ରିୟ ଡାଇମେନ୍ସନ୍ ପାଇଁ, ଇଞ୍ଜିନ୍ ନିମ୍ନଲିଖିତ ଗଣନା କରେ:

```
fairShareAllowed = poolLimit × (allocationWeight / 100)
consumed        = ଏହି କୀ ପାଇଁ ବର୍ତ୍ତମାନର ରୋଲିଂ ମୂଲ୍ୟ (QuotaStore.peek ରୁ)
remaining       = fairShareAllowed - consumed
```

ତା’ପରେ:

- **`policy = hard`**: ଯଦି `consumed > fairShareAllowed` ଏବଂ ମୋଡ୍ କଠୋର ଅଟେ → **ଅବରୋଧ କରନ୍ତୁ**।
- **`policy = soft`**: ଯଦି `consumed > fairShareAllowed` ଏବଂ ମୋଡ୍ କଠୋର ଅଟେ → **ଦଣ୍ଡିତ କରନ୍ତୁ** (କମ୍ବୋରେ ପ୍ରାଥମିକତା କମାନ୍ତୁ; କେବେବି ସମ୍ପୂର୍ଣ୍ଣ ଅବରୋଧ କରନ୍ତୁ ନାହିଁ)।
- **`policy = burst`**: ନ୍ୟାୟସଙ୍ଗତ ହିସ୍ସାକୁ ଖାତିର ନକରି, ଗ୍ଲୋବାଲ୍ ଅତିରିକ୍ତ କ୍ଷମତା ଉପଲବ୍ଧ ଥିବା ପର୍ଯ୍ୟନ୍ତ ଅନୁମତି ଦିଅନ୍ତୁ।

### ସର୍ବାଧିକ ସୀମା

ଏକ ବଣ୍ଟନରେ `capValue` + `capUnit` ହେଉଛି ମୋଡ୍ କିମ୍ବା
ନୀତିଠାରୁ ସ୍ୱାଧୀନ ଏକ କଠୋର ସର୍ବାଧିକ ସୀମା। `consumed >= capValue` ଥିବା ଯେକୌଣସି ଡାଇମେନ୍ସନ୍ ସର୍ବଦା ଅନୁରୋଧକୁ **ଅବରୋଧ କରେ**।

### ବହୁ-ଡାଇମେନ୍ସନ୍ ଯାଞ୍ଚ

ପୁଲ୍ର **ଯେକୌଣସି** ଡାଇମେନ୍ସନ୍ ଯଦି ଅନୁରୋଧକୁ ଅବରୋଧ କରିବ, ତେବେ ଅନୁରୋଧଟି ଅବରୋଧିତ ହୁଏ। ଡାଇମେନ୍ସନ୍ଗୁଡ଼ିକ
ସ୍ୱାଧୀନ — 5h% ଶେଷ ହେବା weekly% ଡାଇମେନ୍ସନ୍କୁ ପ୍ରଭାବିତ କରେ ନାହିଁ।

### ଧାର ନେବା

ଉଦାର ମୋଡ୍ରେ, ଯେଉଁ କୀର ବଣ୍ଟନ କମ୍ ବ୍ୟବହୃତ ହୋଇଛି, ତାହା ଅନ୍ୟ
କୀଗୁଡ଼ିକର ଅବଣ୍ଟିତ ହିସ୍ସାରୁ ଅତିରିକ୍ତ ଅଂଶ ବ୍ୟବହାର କରିପାରିବ। ସୂତ୍ରଟି ହେଉଛି:

```
maxAllowed = globalLimit - consumedByOtherKeys
```

ଯେଉଁଠାରେ `consumedByOtherKeys = consumedTotal - consumedByThisKey`। ଗ୍ଲୋବାଲ୍ ସର୍ବାଧିକ ସୀମା
(ସେହି ଡାଇମେନ୍ସନ୍ ପାଇଁ ପୁଲ୍ର `limit`) ସର୍ବଦା କଠୋର ସୀମା ଅଟେ।

## ସ୍ଲାଇଡିଂ ୱିଣ୍ଡୋ କାଉଣ୍ଟର୍

`src/lib/quota/sqliteQuotaStore.ts` ଏବଂ `redisQuotaStore.ts` ମଧ୍ୟରେ କାର୍ଯ୍ୟକାରୀ କରାଯାଇଛି।

ପ୍ରତ୍ୟେକ `(apiKeyId, dimensionKey)` ପାଇଁ ଦୁଇଟି ବକେଟ୍:

- `curr`: ବର୍ତ୍ତମାନର ବକେଟ୍ (`floor(nowMs / windowMs)`)
- `prev`: ପୂର୍ବବର୍ତ୍ତୀ ବକେଟ୍ (`curr - 1`)

ପ୍ରଭାବଶାଳୀ ରୋଲିଂ ମୂଲ୍ୟ:

```
effectiveBucketIndex = floor(nowMs / windowMs)
bucketStartMs        = effectiveBucketIndex × windowMs
elapsed              = nowMs - bucketStartMs
weight               = 1 - elapsed / windowMs

effective = prev × weight + curr
```

**ସଠିକତା**: ~99% ସଠିକ୍। ବକେଟ୍ଗୁଡ଼ିକ ମଧ୍ୟର ସୀମାରେ ତ୍ରୁଟି ସର୍ବାଧିକ ୱିଣ୍ଡୋ ଆକାରର 1% ଅଟେ
(2-ବକେଟ୍ ଆନୁମାନିକତାର ଅନ୍ତର୍ନିହିତ ସୀମା)।

### ସମକାଳୀନତା

SQLite ଡ୍ରାଇଭର୍: ପ୍ରତ୍ୟେକ `(apiKeyId | dimensionKey)` କୀ ପାଇଁ ଇନ୍-ମେମୋରି ମ୍ୟୁଟେକ୍ସ
ରିଡ୍-ମଡିଫାଇ-ରାଇଟ୍ ରେସ୍କୁ ପ୍ରତିରୋଧ କରେ। ପ୍ୟାଟର୍ନଟି `src/sse/services/auth.ts`-ର ଆଣ୍ଟି-ଥଣ୍ଡରିଂ-ହର୍ଡ ପ୍ୟାଟର୍ନକୁ ଅନୁସରଣ କରେ।

Redis ଡ୍ରାଇଭର୍: ଆଟମିକ୍ ଇନ୍କ୍ରିମେଣ୍ଟ ପାଇଁ Lua EVAL ସ୍କ୍ରିପ୍ଟ — ଏହା ଗୋଟିଏ Redis କମାଣ୍ଡ୍ ଭାବରେ ଚାଲେ।

- କାଉଣ୍ଟର୍ଗୁଡ଼ିକ ସେୟାର୍ କରିବା ଆବଶ୍ୟକ ଥିବା ମଲ୍ଟି-ରେପ୍ଲିକା ଡିପ୍ଲୟମେଣ୍ଟ ପାଇଁ ସର୍ବୋତ୍ତମ।

### ଡ୍ରାଇଭର୍ ପରିବର୍ତ୍ତନ

ସେଟିଂସ୍ UI (`/dashboard/settings` → କୋଟା ଷ୍ଟୋର୍) ମାଧ୍ୟମରେ, କିମ୍ବା env vars ମାଧ୍ୟମରେ:

```bash
QUOTA_STORE_DRIVER=redis
QUOTA_STORE_REDIS_URL=redis://localhost:6379
```

env ଅପେକ୍ଷା DB ସେଟିଂକୁ ପ୍ରାଥମିକତା ଦିଆଯାଏ। ଯଦି `driver=redis` କିନ୍ତୁ URL ଅନୁପସ୍ଥିତ ଥାଏ କିମ୍ବା
`ioredis` ଇନ୍ଷ୍ଟଲ୍ ହୋଇନଥାଏ, ତେବେ ଫ୍ୟାକ୍ଟରି SQLiteକୁ ଫେରିଯାଏ ଏବଂ ଏକ ଚେତାବନୀ ଲଗ୍ କରେ।

ଡ୍ରାଇଭର୍ ଚୟନ କ୍ରମ:

1. DB ସେଟିଂ `quotaStore.driver`
2. Env `QUOTA_STORE_DRIVER`
3. ଡିଫଲ୍ଟ: `sqlite`

## ପାଇପ୍ଲାଇନ୍ ଇଣ୍ଟିଗ୍ରେସନ୍

### PRE ହୁକ୍ (`open-sse/handlers/chatCore.ts`)

ପ୍ରାମାଣିକରଣ ଏବଂ ନୀତି ଯାଞ୍ଚ ପରେ, ଅପ୍ଷ୍ଟ୍ରିମ୍ ଏକ୍ସିକ୍ୟୁଟର୍ ପୂର୍ବରୁ ଚାଲେ:

```
resolveComboTargets / handleSingleModel
  → enforceQuotaShare(apiKeyId, connectionId, provider, estimatedCost)
      → ପ୍ରତି ଆୟାମ ପାଇଁ getQuotaStore().peek()
      → fairShare.decideFairShare()
      → ଯଦି ବ୍ଲକ୍ ହୁଏ → 429 ଫେରାନ୍ତୁ (buildErrorBody, କଠୋର ନିୟମ #12)
      → ଯଦି ଅନୁମୋଦିତ + ପ୍ରାଥମିକତା ହ୍ରାସ → ପ୍ରାର୍ଥୀ ଉପରେ quotaSoftPenalty=true ସେଟ୍ କରନ୍ତୁ
  → executor.execute()
```

**ଫେଲ୍-ଓପନ୍**: ଯଦି `enforceQuotaShare` ତ୍ରୁଟି ଦିଏ, ଏକ `pino.warn` ଲଗ୍ ସହିତ
ଅନୁରୋଧକୁ ଆଗକୁ ଯିବାକୁ ଅନୁମତି ଦିଆଯାଏ। ଏହା କୋଟା-ଇଞ୍ଜିନ୍ର ଏକ ବଗ୍କୁ ସମସ୍ତ
ଟ୍ରାଫିକ୍ ବ୍ଲକ୍ କରିବାରୁ ରୋକେ।

### POST ହୁକ୍ (ବ୍ୟବହାର ରେକର୍ଡ କରନ୍ତୁ)

ଏକ ସଫଳ ପ୍ରତିକ୍ରିୟା ପରେ:

```
ଏକ୍ସିକ୍ୟୁଟର୍ ସଫଳତା ଫେରାଏ
  → spendRecorder.recordConsumption(apiKeyId, connectionId, provider, actualCost)
      → ପ୍ରତି ଆୟାମ ପାଇଁ getQuotaStore().consume()
      → ଫେଲ୍-ଓପନ୍: ତ୍ରୁଟିଗୁଡ଼ିକ pino.warn ଭାବରେ ଲଗ୍ ହୁଏ, କ୍ଲାଏଣ୍ଟକୁ କେବେ ପ୍ରସାରିତ ହୁଏନାହିଁ
```

**ବିଚ୍ୟୁତି ସୂଚନା**: ଯଦି ପ୍ରତିକ୍ରିୟା ପରେ `consume` ବିଫଳ ହୁଏ, ରୋଲିଂ କାଉଣ୍ଟର୍ କମ୍ ଗଣନା କରେ।
ପ୍ରଦାନକାରୀଙ୍କ ସ୍ୟାଚୁରେସନ୍ ସିଗ୍ନାଲ୍ (ଯଥା `anthropic-ratelimit-unified-5h-utilization`)
ପରବର୍ତ୍ତୀ ଅନୁରୋଧରେ ଗ୍ଲୋବାଲ୍ ଆକଳନକୁ ସଂଶୋଧନ କରେ।

### କମ୍ବୋ ସଫ୍ଟ ପେନାଲ୍ଟି (`open-sse/services/combo.ts`)

ଯେତେବେଳେ `decision.deprioritize === true`:

```ts
if (candidate.quotaSoftPenalty) {
  score *= QUOTA_SOFT_DEPRIORITIZE_FACTOR; // ଡିଫଲ୍ଟ 0.7
}
```

ଅନ୍ୟ ସମସ୍ତ ସ୍କୋରିଂ ଫ୍ୟାକ୍ଟର୍ ପରେ ପେନାଲ୍ଟି ପ୍ରୟୋଗ କରାଯାଏ। ଏହା ସ୍ୟାଚୁରେଟେଡ୍ କୀକୁ
ହାର୍ଡ-ବ୍ଲକ୍ ନକରି ତାହା ଚୟନ ହେବାର ଅଟୋ-କମ୍ବୋ ସମ୍ଭାବନାକୁ କମାଏ।

## ସମସ୍ୟା ସମାଧାନ

### Redis ବିନ୍ୟାସିତ ହୋଇଛି, କିନ୍ତୁ ସଂଯୋଗ ହେଉନାହିଁ

`ioredis` ଇନ୍ଷ୍ଟଲ୍ ହୋଇଛି କି ନାହିଁ (`npm ls ioredis`) ଏବଂ `QUOTA_STORE_REDIS_URL`
ପହଞ୍ଚଯୋଗ୍ୟ କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ। ସଂଯୋଗ ବିଫଳ ହେଲେ ଫ୍ୟାକ୍ଟରୀ SQLite କୁ ଫଲ୍ବ୍ୟାକ୍ କରେ (`warn`
ସ୍ତରରେ ଲଗ୍ କରାଯାଏ)।

### `peek` ପୁରୁଣା ଡାଟା / ଫେଲ୍-ଓପନ୍ ଫେରାଏ

ଯଦି `peek` ତ୍ରୁଟି ଫିଙ୍ଗେ, `enforceQuotaShare` ଫଳାଫଳକୁ "ଅନୁମତି ଦିଅନ୍ତୁ" (ଫେଲ୍-ଓପନ୍) ଭାବେ ବିବେଚନା କରେ।
ମୂଳ କାରଣ ଚିହ୍ନଟ କରିବା ପାଇଁ `quota:enforce` ଏବଂ `quota:factory` ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ ନିମନ୍ତେ
`pino` ଲଗ୍ଗୁଡ଼ିକ ଯାଞ୍ଚ କରନ୍ତୁ।

### ବ୍ୟବହାର କାଉଣ୍ଟର୍ରେ ବିଚ୍ୟୁତି

ଯଦି ପ୍ରକୃତ ପ୍ରଦାନକାରୀ ବ୍ୟବହାର କାଉଣ୍ଟର୍ଗୁଡ଼ିକଠାରୁ ଭିନ୍ନ ହୁଏ, ତେବେ ତାହା ଆଶାକରାଯାଏ — 2-ବକେଟ୍ ସ୍ଲାଇଡିଂ ୱିଣ୍ଡୋରେ ୱିଣ୍ଡୋ ସୀମାରେ ~1% ତ୍ରୁଟି ରହିଥାଏ, ଏବଂ `consume`
ପ୍ରତିକ୍ରିୟା ପରେ ଫାୟାର୍-ଆଣ୍ଡ୍-ଫର୍ଗେଟ୍ ଭାବେ ଚାଲେ। ସାଚୁରେସନ୍ ସିଗ୍ନାଲ୍ (`saturationSignals.ts`)
30s TTL ସହିତ ପ୍ରକୃତ ପ୍ରଦାନକାରୀ ବ୍ୟବହାର ପଢ଼େ ଏବଂ ସେହି ଅନୁଯାୟୀ `globalUsedPercent`
ସମନ୍ୱୟ କରେ।

### ବ୍ୟୟ ହାର ପାଇଁ ପୁଲ୍ରେ "କୌଣସି ଡାଟା ନାହିଁ" ଦେଖାଯାଏ

`computeBurnRate` ପାଇଁ ଅତି କମରେ 2ଟି ଐତିହାସିକ ନମୁନା ଆବଶ୍ୟକ। ପୂର୍ବବର୍ତ୍ତୀ
`consume` କଲ୍ ବିନା ନୂଆ ପୁଲ୍ଗୁଡ଼ିକ `tokensPerSecond: 0` ଏବଂ `timeToExhaustionMs: null` ଦେଖାଇବେ।

## localStorage ରୁ ମାଇଗ୍ରେସନ୍

`/dashboard/costs/quota-share` ପ୍ରଥମେ ଲୋଡ୍ ହେବାବେଳେ, `useLocalStoragePoolMigration` ହୁକ୍ ନିମ୍ନଲିଖିତଗୁଡ଼ିକ ଯାଞ୍ଚ କରେ:

1. `localStorage.getItem("omniroute:quota-share:pools")` ଖାଲି ନୁହେଁ।
2. `GET /api/quota/pools` ରୁ `[]` ଫେରେ (DB ଖାଲି ଅଛି)।

ଉଭୟ ସତ୍ୟ ହେଲେ, ଏହା ପ୍ରତ୍ୟେକ ପୁରୁଣା ପୁଲ୍କୁ ବ୍ୟାଚ୍ ଆକାରରେ `POST /api/quota/pools` କୁ ପୋଷ୍ଟ କରେ,
ତା’ପରେ localStorage କୀ’କୁ ଅପସାରଣ କରେ। ମାଇଗ୍ରେସନ୍ଟି ଆଇଡେମ୍ପୋଟେଣ୍ଟ: ସର୍ତ୍ତ 2
ପୁନଃ-ମାଇଗ୍ରେସନ୍କୁ ପ୍ରତିରୋଧ କରେ।

## ଆଭ୍ୟନ୍ତରୀଣ କୌଶଳ ବର୍ଗୀକରଣ

`quota-share` ହେଉଛି ଏକ **କେବଳ-ଆଭ୍ୟନ୍ତରୀଣ** ରାଉଟିଂ କୌଶଳ (`src/shared/constants/routingStrategies.ts` ରେ
`INTERNAL_ROUTING_STRATEGY_VALUES`)। ଏହା କେବଳ ସିଷ୍ଟମ୍ରେ ସୃଷ୍ଟି ହୋଇଥିବା
`qtSd/` ପୁଲ୍ କମ୍ବୋଗୁଡ଼ିକ ଦ୍ୱାରା ବ୍ୟବହୃତ ହୁଏ ଏବଂ ଏହାକୁ ଜାଣିଶୁଣି `ROUTING_STRATEGY_VALUES` ରୁ ବାଦ ଦିଆଯାଇଛି, ଯାହାଦ୍ୱାରା ଏହା କେବେବି
UI କିମ୍ବା API ରେ ବ୍ୟବହାରକାରୀ-ଚୟନଯୋଗ୍ୟ ବିକଳ୍ପ ଭାବେ ଦେଖାଯିବ ନାହିଁ।

## DB ସ୍କିମା ସାରାଂଶ

ମାଇଗ୍ରେସନ୍ `078`, `079` ଏବଂ `085` ଦ୍ୱାରା ଯୋଡ଼ାଯାଇଥିବା ତିନୋଟି ଟେବୁଲ୍:

- `quota_pools` + `quota_allocations` — ପୁଲ୍ ସଂଜ୍ଞା ଏବଂ ପ୍ରତି-କୀ’ ବଣ୍ଟନ।
- `quota_consumption` — ପ୍ରତ୍ୟେକ `(apiKeyId, dimensionKey)` ପାଇଁ ଚଳନଶୀଳ 2-ବକେଟ୍ କାଉଣ୍ଟର୍।
- `provider_plans` — ମାନୁଆଲ୍ ପ୍ରଦାତା ପ୍ଲାନ୍ ଓଭର୍ରାଇଡ୍ (ପ୍ରତ୍ୟେକ connectionId ପାଇଁ ଡାଇମେନ୍ସନ୍ JSON)।

ସମସ୍ତ ଟେବୁଲ୍ ଆଇଡେମ୍ପୋଟେଣ୍ଟ `CREATE TABLE IF NOT EXISTS` ମାଇଗ୍ରେସନ୍ଗୁଡ଼ିକ ମାଧ୍ୟମରେ ଯୋଡ଼ାଯାଇଛି।
