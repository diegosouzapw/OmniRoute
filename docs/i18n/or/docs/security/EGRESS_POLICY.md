> **ପ୍ରତ୍ୟେକ ପ୍ରକ୍ସି ପାଇଁ ବାହାରମୁଖୀ ଟ୍ରାଫିକ୍କୁ ଗୋଟିଏ IP ଫ୍ୟାମିଲି — `auto`, `ipv4`, କିମ୍ବା `ipv6` — ରେ ସ୍ଥିର କରନ୍ତୁ, ଯାହାଦ୍ୱାରା କେବଳ-IPv6 ଇଗ୍ରେସ୍ କେବେବି ନିରବରେ IPv4କୁ ପୁଣି ଲିକ୍ ହେବ ନାହିଁ।**

> **ପ୍ରାମାଣିକ ଉତ୍ସ:** `open-sse/utils/proxyFamily.ts`, `open-sse/utils/proxyDispatcher.ts`, `open-sse/utils/proxyFetch.ts`, `open-sse/utils/socksConnectorWithFamily.ts`, `open-sse/utils/proxyFamilyResolve.ts`, `src/shared/validation/schemas.ts`, `src/lib/db/proxies.ts`, `src/lib/db/upstreamProxy.ts`, `src/lib/db/migrations/099_proxy_family.sql`

OmniRoute ପ୍ରତ୍ୟେକ ପ୍ରକ୍ସିକୁ ଗୋଟିଏ **ଆଡ୍ରେସ୍-ଫ୍ୟାମିଲି ଇଗ୍ରେସ୍ ନିର୍ଦ୍ଦେଶ** ବହନ କରିବାକୁ ଦିଏ। ଡିଫଲ୍ଟ ଭାବରେ OS IPv4 କିମ୍ବା IPv6 (ଡୁଆଲ୍-ଷ୍ଟାକ୍, "Happy Eyeballs") ବାଛେ। ଆପଣ ନିର୍ଦ୍ଦେଶଟିକୁ `ipv4` କିମ୍ବା `ipv6` ଭାବରେ ସେଟ୍ କଲେ, OmniRoute ସେହି ପ୍ରକ୍ସି ମାଧ୍ୟମରେ ହେଉଥିବା ପ୍ରତ୍ୟେକ ସଂଯୋଗକୁ ବାଛିଥିବା ଫ୍ୟାମିଲିରେ ସ୍ଥିର କରେ ଏବଂ ଅନ୍ୟ ଫ୍ୟାମିଲିକୁ ଫଲ୍ବ୍ୟାକ୍ କରିବା ପରିବର୍ତ୍ତେ **ବନ୍ଦ ଅବସ୍ଥାରେ ବିଫଳ ହୁଏ**।

ଏହି ପୃଷ୍ଠାରେ ନିର୍ଦ୍ଦେଶଟି କ’ଣ, ଏହା କାହିଁକି ରହିଛି, ଆପଣ ଏହାକୁ କେଉଁଠାରେ ବିନ୍ୟାସ କରନ୍ତି ଏବଂ ରନ୍ଟାଇମ୍ ଏହାକୁ କିପରି ସମାଧାନ କରେ, ତାହା ଲିପିବଦ୍ଧ କରାଯାଇଛି।

## ଏହା କ’ଣ

ରେଜିଷ୍ଟ୍ରିରେ ଥିବା ପ୍ରତ୍ୟେକ ପ୍ରକ୍ସିରେ ତିନୋଟି ସମ୍ଭାବ୍ୟ ମୂଲ୍ୟ ବିଶିଷ୍ଟ ଏକ `family` ଫିଲ୍ଡ ରହିଛି, ଯାହାକୁ ଗୋଟିଏ Zod enum ଦ୍ୱାରା ବୈଧ କରାଯାଏ:

```ts
// src/shared/validation/schemas.ts
family: z.enum(["auto", "ipv4", "ipv6"]).optional().default("auto"),
```

ଫିଲ୍ଡଟି ଡିଫଲ୍ଟ ଭାବରେ `"auto"` ହୁଏ, ଯାହା ପୂର୍ବବର୍ତ୍ତୀ ଡୁଆଲ୍-ଷ୍ଟାକ୍ ଆଚରଣକୁ ବଜାୟ ରଖେ। ଏହାକୁ `ipv4` କିମ୍ବା `ipv6` ଭାବରେ ସେଟ୍ କରିବା ସେହି ପ୍ରକ୍ସି ପାଇଁ ସଂଯୋଗ ଫ୍ୟାମିଲିକୁ ସ୍ଥିର କରେ।

ନିର୍ଦ୍ଦେଶଟିକୁ ସବୁ ସ୍ଥାନରେ ଗୋଟିଏ ମାତ୍ର ହେଲ୍ପର୍ ମାଧ୍ୟମରେ ସାମାନ୍ୟୀକୃତ କରାଯାଏ, ଯାହାଦ୍ୱାରା ଯେକୌଣସି ଅଜଣା ମୂଲ୍ୟ `auto`କୁ ପରିବର୍ତ୍ତିତ ହୁଏ:

```ts
// open-sse/utils/proxyFamily.ts
export type ProxyFamily = "auto" | "ipv4" | "ipv6";

export function parseProxyFamily(value: unknown): ProxyFamily {
  return value === "ipv4" || value === "ipv6" ? value : "auto";
}
```

## ଏହା କାହିଁକି ରହିଛି

PR [#3777](https://github.com/diegosouzapw/OmniRoute/pull/3777)ରେ ପ୍ରବର୍ତ୍ତନ କରାଯାଇଛି। ଏହା ପଛରେ ଥିବା ପ୍ରେରକ ସମସ୍ୟାଗୁଡ଼ିକ:

| ସମସ୍ୟା                                       | ନିର୍ଦ୍ଦେଶଟି କ’ଣ ସମାଧାନ କରେ                                                                                                                                                                                                                                                                                                                                       |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **କେବଳ-IPv6 ଇଗ୍ରେସ୍ର IPv4କୁ ଲିକ୍ ହେବା**      | ଯେତେବେଳେ ଗୋଟିଏ ପ୍ରକ୍ସି ହୋଷ୍ଟ୍ରେ ଉଭୟ A ଏବଂ AAAA ରେକର୍ଡ ଥାଏ (କିମ୍ବା OS IPv4କୁ ପ୍ରାଧାନ୍ୟ ଦିଏ), ସେତେବେଳେ ଆପଣ କେବଳ-IPv6 ପଥ ବ୍ୟବହାର କରିବାକୁ ଚାହୁଁଥିଲେ ମଧ୍ୟ Happy Eyeballs IPv4 ମାଧ୍ୟମରେ ବାହାରକୁ ସଂଯୋଗ କରିପାରେ। `ipv6`ରେ ସ୍ଥିର କରିବା ସେହି ଲିକ୍କୁ ଦୂର କରେ।                                                                                                               |
| **ସେୟାର୍ଡ-ଇଗ୍ରେସ୍ ବିସଙ୍ଗତିଜନିତ ପ୍ରତ୍ୟାହାର**  | ଅନେକ ଆକାଉଣ୍ଟ୍ ଅଧିକ ପରିମାଣରେ **ସମାନ** IP ମାଧ୍ୟମରେ ବାହାରକୁ ଯିବାବେଳେ ରୋଟେଟିଂ ପ୍ରଦାନକାରୀମାନେ (codex/openai) ଟୋକନ୍ ପ୍ରତ୍ୟାହାର କରନ୍ତି। ଇଗ୍ରେସ୍ ଫ୍ୟାମିଲିକୁ ନିୟନ୍ତ୍ରଣ କରିବା ଆକାଉଣ୍ଟ୍ଗୁଡ଼ିକୁ ପୃଥକ୍, ପୂର୍ବାନୁମାନଯୋଗ୍ୟ ଇଗ୍ରେସ୍ ପଥରେ ରଖିବାର ଏକ ଅଂଶ (ଏହା ସହିତ ଯୋଡ଼ି ହୋଇଥିବା ଇଗ୍ରେସ୍-IP ଡାଏଗ୍ନୋଷ୍ଟିକ୍ସ ପାଇଁ [`src/lib/proxyEgress.ts`](../../src/lib/proxyEgress.ts) ଦେଖନ୍ତୁ)। |
| **ଅନୁପାଳନ/ପରୀକ୍ଷଣ ପାଇଁ ନିର୍ଦ୍ଧାରିତ ଇଗ୍ରେସ୍** | ଯେତେବେଳେ ଆପଣଙ୍କୁ ଟ୍ରାଫିକ୍ ଏକ ନିର୍ଦ୍ଦିଷ୍ଟ ଫ୍ୟାମିଲି ମାଧ୍ୟମରେ ବାହାରକୁ ଯାଉଛି ବୋଲି ସୁନିଶ୍ଚିତ କରିବାକୁ ପଡ଼େ, ସେତେବେଳେ `auto` ଯଥେଷ୍ଟ ନୁହେଁ।                                                                                                                                                                                                                              |

ନିର୍ଦ୍ଦେଶଟି ଉଦ୍ଦେଶ୍ୟମୂଳକ ଭାବରେ **ପ୍ରତ୍ୟେକ-ପ୍ରକ୍ସି ପାଇଁ**, ଗ୍ଲୋବାଲ୍ ନୁହେଁ — ଆପଣଙ୍କ ପୁଲ୍ରେ ଥିବା ଭିନ୍ନ ପ୍ରକ୍ସିଗୁଡ଼ିକର ଭିନ୍ନ ନୀତି ରହିପାରେ।

## ଏହାକୁ କିପରି ବିନ୍ୟାସ କରିବେ

### ଡ୍ୟାଶବୋର୍ଡ

ଚୟନକର୍ତ୍ତାଟି **Proxy Pool** ଟ୍ୟାବ୍ର ପ୍ରକ୍ସି ଫର୍ମରେ ଅଛି:

1. **Dashboard → Settings → Proxy → Proxy Pool** ଖୋଲନ୍ତୁ
2. ଏକ ପ୍ରକ୍ସି ଯୋଡ଼ନ୍ତୁ କିମ୍ବା ସମ୍ପାଦନ କରନ୍ତୁ
3. **IP family** ଡ୍ରପ୍ଡାଉନ୍କୁ `ସ୍ୱୟଂଚାଳିତ (dual-stack)`, `କେବଳ IPv4`, କିମ୍ବା `କେବଳ IPv6`ରେ ସେଟ୍ କରନ୍ତୁ
4. ସଞ୍ଚୟ କରନ୍ତୁ

ଏହି ନିୟନ୍ତ୍ରଣଟି `ProxyRegistryManager.tsx` ଦ୍ୱାରା ରେଣ୍ଡର୍ ହୁଏ (`proxy/ProxyPoolTab.tsx`ରେ ମାଉଣ୍ଟ କରାଯାଇଛି)।

### API

`family` ଫିଲ୍ଡଟି ପ୍ରକ୍ସି ରେଜିଷ୍ଟ୍ରି ସୃଷ୍ଟି/ଅଦ୍ୟତନ payloadଗୁଡ଼ିକର ଅଂଶ, ଯାହା `createProxyRegistrySchema` / `updateProxyRegistrySchema` (`src/shared/validation/schemas.ts`) ଦ୍ୱାରା ବୈଧୀକୃତ ଏବଂ `POST` / `PATCH /api/v1/management/proxies` ଦ୍ୱାରା ପରିଚାଳିତ ହୁଏ:

```bash
# ଏକ କେବଳ-IPv6 ପ୍ରକ୍ସି ସୃଷ୍ଟି କରନ୍ତୁ
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "IPv6 egress",
    "type": "socks5",
    "host": "proxy.example.com",
    "port": 1080,
    "family": "ipv6"
  }'

# ଏକ ବିଦ୍ୟମାନ ପ୍ରକ୍ସିକୁ କେବଳ-IPv4ରେ ପରିବର୍ତ୍ତନ କରନ୍ତୁ
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{ "id": "proxy-uuid-here", "family": "ipv4" }'
```

ସମାନ ଫିଲ୍ଡଟି upstream-proxy ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ ପାଇଁ ବ୍ୟବହୃତ inline ପ୍ରକ୍ସି config ଅବଜେକ୍ଟ ଦ୍ୱାରା ମଧ୍ୟ ଗ୍ରହଣ କରାଯାଏ (`upstream_proxy_config.family`, [ଡାଟା ମଡେଲ୍](#data-model) ଦେଖନ୍ତୁ)।

ପ୍ରକ୍ସି CRUD/ନ୍ୟସ୍ତକରଣ APIର ଅବଶିଷ୍ଟ ଅଂଶ ପାଇଁ, [PROXY_GUIDE.md](../ops/PROXY_GUIDE.md) ଦେଖନ୍ତୁ।

## `auto` କିପରି ସମାଧାନ ହୁଏ

ଯେତେବେଳେ `family` ହେଉଛି `auto`, OmniRoute କୌଣସି directive ଯୋଡ଼େ **ନାହିଁ** — ପ୍ରକ୍ସି URLଟି ଯେପରି ଅଛି ସେପରି ବ୍ୟବହୃତ ହୁଏ ଏବଂ ସଂଯୋଗ ଫ୍ୟାମିଲି ଅନ୍ତର୍ନିହିତ ଭାବେ ନିର୍ଦ୍ଧାରିତ ହୁଏ।

URL ନିର୍ମାଣ ସମୟରେ (`open-sse/utils/proxyDispatcher.ts`ରେ `proxyConfigToUrl` / `normalizeProxyUrl`), ଏକ `auto` ପ୍ରକ୍ସି କୌଣସି marker ବିନା ଏକ ସାଧାରଣ URL ଦିଏ:

```ts
// open-sse/utils/proxyDispatcher.ts
const fam = parseProxyFamily(config.family);
const normalized = normalizeProxyUrl(proxyUrlStr, "context proxy", {
  allowSocks5,
});
return fam === "auto" ? normalized : `${normalized}?family=${fam}`;
```

dispatch ସମୟରେ (`resolveDispatcherFamily`), `auto` ଏକ IP-literal ହୋଷ୍ଟର ଅନ୍ତର୍ନିହିତ ଫ୍ୟାମିଲିକୁ, କିମ୍ବା ଏକ ହୋଷ୍ଟନାମ ପାଇଁ `null`କୁ (OSକୁ ନିଷ୍ପତ୍ତି ନେବାକୁ ଦିଅନ୍ତୁ) ସମାଧାନ ହୁଏ:

```ts
// open-sse/utils/proxyDispatcher.ts
function resolveDispatcherFamily(parsed: URL): 4 | 6 | null {
  const directive = parseProxyFamily(parsed.searchParams.get("family") ?? undefined);
  const literal = detectIpLiteralFamily(parsed.hostname);
  if (directive === "auto") return literal; // ଏକ ହୋଷ୍ଟନାମ ପାଇଁ null → OS ବାଛେ
  // ...
}
```

ତେଣୁ:

- `auto` + IP-literal ହୋଷ୍ଟ (`192.0.2.1` / `[2001:db8::1]`) → ସେହି literalର ଫ୍ୟାମିଲି।
- `auto` + ହୋଷ୍ଟନାମ → `null` → ମାନକ dual-stack OS resolution।

## `ipv4` / `ipv6` କିପରି ବାଧ୍ୟତାମୂଳକ କରାଯାଏ

ଏକ non-`auto` ନିର୍ଦ୍ଦେଶ ଏକକ ସିନ୍ଥେଟିକ୍ କ୍ୱେରୀ ମାର୍କର୍ — `?family=ipv4` କିମ୍ବା `?family=ipv6` — ଭାବରେ ପ୍ରେରିତ ହୁଏ, ଯାହାକୁ ସାମାନ୍ୟୀକୃତ ପ୍ରକ୍ସି URL ସହିତ ଥରେ ଯୋଡ଼ାଯାଏ। `normalizeProxyUrl` ଏହି ମାର୍କର୍କୁ ଠିକ୍ ଥରେ ଅପସାରଣ କରି ପୁନଃ ଯୋଡ଼ିବାକୁ ସାବଧାନ ରହେ, ଯାହାଦ୍ୱାରା ଏହା କେବେବି ପୋର୍ଟ ପାର୍ସିଂକୁ ବିଗାଡ଼େ ନାହିଁ।

ଡିସ୍ପ୍ୟାଚର୍ ନିର୍ମାଣ ହେବାବେଳେ, ମାର୍କର୍ଟି ପଢ଼ାଯାଇ ଏକ ନିର୍ଦ୍ଦିଷ୍ଟ ସଂଯୋଗ ଫ୍ୟାମିଲିରେ ରୂପାନ୍ତରିତ ହୁଏ। ଯଦି ହୋଷ୍ଟଟି **ବିପରୀତ** ଫ୍ୟାମିଲିର ଏକ IP ଲିଟେରାଲ୍ ହୋଇଥାଏ, ତେବେ OmniRoute ଏକ ତ୍ରୁଟି ଦିଏ (ବିରୋଧାଭାସ ହେଲେ fail-closed ହୁଏ):

```ts
// open-sse/utils/proxyDispatcher.ts
const want = directive === "ipv6" ? 6 : 4;
if (literal !== null && literal !== want) {
  throw new Error(
    `[ProxyDispatcher] Proxy family directive ${directive} contradicts ${literal === 6 ? "IPv6" : "IPv4"} literal host`
  );
}
```

ତା’ପରେ ନିର୍ଦ୍ଦିଷ୍ଟ ଫ୍ୟାମିଲିକୁ କନେକ୍ଟର୍ରେ ପିନ୍ କରାଯାଏ:

- **HTTP/HTTPS ପ୍ରକ୍ସିଗୁଡ଼ିକ** (`ProxyAgent`): `proxyTls: { family, autoSelectFamily: false }` — Happy Eyeballsକୁ ଅକ୍ଷମ କରେ, ଯାହାଦ୍ୱାରା କେବଳ ଚୟନିତ ଫ୍ୟାମିଲିକୁ ହିଁ ଡାଏଲ୍ କରାଯାଏ।
- **SOCKS5 ପ୍ରକ୍ସିଗୁଡ଼ିକ**: ଏକ କଷ୍ଟମ୍ କନେକ୍ଟର୍ SOCKS କ୍ଲାଏଣ୍ଟ ମଧ୍ୟକୁ `socket_options: { family, autoSelectFamily: false }` ପଠାଏ ([SOCKS5 ସୁସଙ୍ଗତତା](#socks5-compatibility) ଦେଖନ୍ତୁ)।

## SOCKS5 ସୁସଙ୍ଗତତା

ଫ୍ୟାମିଲି ପିନ୍ SOCKS5 ପ୍ରକ୍ସିଗୁଡ଼ିକ ସହିତ କାମ କରେ, କିନ୍ତୁ ମାନକ `fetch-socks` ପ୍ରକ୍ସି ହପ୍ର ଫ୍ୟାମିଲିକୁ ପିନ୍ କରିବା ପାଇଁ ଆବଶ୍ୟକ ସକେଟ୍ ବିକଳ୍ପଗୁଡ଼ିକୁ ଉନ୍ମୁକ୍ତ କରେ ନାହିଁ। ଏହା ପାଇଁ OmniRoute ନିଜସ୍ୱ କନେକ୍ଟର୍ ପ୍ରଦାନ କରେ:

```ts
// open-sse/utils/socksConnectorWithFamily.ts
export function buildSocksFamilySocketOptions(family: 4 | 6 | null): Record<string, unknown> {
  if (family === 6) return { family: 6, autoSelectFamily: false };
  if (family === 4) return { family: 4, autoSelectFamily: false };
  return {};
}
```

ସମସ୍ତ SOCKS5 ଡିସ୍ପ୍ୟାଚ୍ `family` ନିର୍ବିଶେଷରେ (`null` / ହୋଷ୍ଟନାମ୍ ଉପରେ `auto` ସମେତ) `createSocksDispatcherWithFamily` ମାଧ୍ୟମରେ ଯାଏ: `buildSocksFamilySocketOptions(null)` ରୁ `{}` ମିଳେ, ଏବଂ ସମାନ `SocksClient.createConnection` + TLS `buildConnector` ପଥକୁ `socket_options` ପିନିଂ ସହିତ ବ୍ୟବହାର କରାଯାଏ, ଯାହାଦ୍ୱାରା Happy Eyeballs ଏକ କେବଳ-IPv6 ଇଗ୍ରେସ୍ ନୀତି ପାଇଁ IPv4 ବାଛିପାରିବ ନାହିଁ।

SOCKS5 ସମର୍ଥନ ନିଜେ ଡିଫଲ୍ଟ ଭାବରେ ସକ୍ଷମ ଅଛି (`ENABLE_SOCKS5_PROXY=false` ମାଧ୍ୟମରେ ଅପ୍ଟ-ଆଉଟ୍); [PROXY_GUIDE.md → ପରିବେଶ ଭେରିଏବଲ୍ଗୁଡ଼ିକ](../ops/PROXY_GUIDE.md#environment-variables) ଦେଖନ୍ତୁ।

## Fail-Closed ଆଚରଣ

ନିର୍ଦ୍ଦେଶଟିର ମୂଳ ଉଦ୍ଦେଶ୍ୟ ହେଉଛି ନିରବରେ ଭୁଲ୍ ଫ୍ୟାମିଲିକୁ ଫଲ୍ବ୍ୟାକ୍ କରିବା ପରିବର୍ତ୍ତେ ତାହାକୁ **ପ୍ରତ୍ୟାଖ୍ୟାନ** କରିବା। ଦୁଇଟି ଗାର୍ଡ ଏହାକୁ ବାଧ୍ୟତାମୂଳକ କରନ୍ତି:

1. **ଲିଟେରାଲ୍ ବିରୋଧାଭାସ** — ଏକ IP-ଲିଟେରାଲ୍ ହୋଷ୍ଟ ସହିତ ବିରୋଧ କରୁଥିବା ନିର୍ଦ୍ଦେଶ ଡିସ୍ପ୍ୟାଚର୍ ନିର୍ମାଣ ସମୟରେ ଏକ ତ୍ରୁଟି ଦିଏ (ଉପରେ ଦର୍ଶାଯାଇଥିବା `resolveDispatcherFamily`)।

2. **ହୋଷ୍ଟନାମ୍ ପ୍ରି-ଫ୍ଲାଇଟ୍ DNS ଯାଞ୍ଚ** — ପିନ୍ କରାଯାଇଥିବା ଫ୍ୟାମିଲି ସହିତ ଏକ ହୋଷ୍ଟନାମ୍ ପ୍ରକ୍ସି ପାଇଁ, `proxyFetch.ts` ଇଗ୍ରେସ୍ କରିବା **ପୂର୍ବରୁ** `assertHostnameSupportsFamily` ମାଧ୍ୟମରେ ହୋଷ୍ଟନାମ୍ରେ ପ୍ରକୃତରେ ଆବଶ୍ୟକ ଫ୍ୟାମିଲିର ଏକ ରେକର୍ଡ ଅଛି କି ନାହିଁ ଯାଞ୍ଚ କରେ:

   ```ts
   // open-sse/utils/proxyFamilyResolve.ts
   const hasFamily = records.some((r) => r.family === family);
   if (!hasFamily) {
     throw new Error(
       `[ProxyFamily] Proxy host ${host} has no ${family === 6 ? "IPv6 (AAAA)" : "IPv4 (A)"} record; ` +
         `refusing ${family === 6 ? "IPv6" : "IPv4"}-only egress (fail-closed)`
     );
   }
   ```

   ବିଫଳତା ଘଟିଲେ, `proxyFetch.ts` ତ୍ରୁଟିଟିକୁ `code = "PROXY_FAMILY_UNAVAILABLE"` ଏବଂ `statusCode = 503` ସହିତ ଟ୍ୟାଗ୍ କରେ। ଏକ DNS ରିଜୋଲ୍ୟୁସନ୍ ବିଫଳତାକୁ ମଧ୍ୟ ସେହିପରି fail-closed ଭାବରେ ବିବେଚନା କରାଯାଏ (ଇଗ୍ରେସ୍ କରିବାକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଏ)।

IP-ଲିଟେରାଲ୍ ହୋଷ୍ଟଗୁଡ଼ିକ ପାଇଁ DNS ପ୍ରି-ଫ୍ଲାଇଟ୍ ଏକ no-op — ସେମାନଙ୍କର ଫ୍ୟାମିଲି ଅନ୍ତର୍ନିହିତ ଏବଂ କୌଣସି ଲୁକ୍ଅପ୍ ଆବଶ୍ୟକ କରେ ନାହିଁ।

## ଡାଟା ମଡେଲ୍

`family` କଲମ୍ଟି ମାଇଗ୍ରେସନ୍ `099_proxy_family.sql` ଦ୍ୱାରା **ଦୁଇଟି** ଟେବୁଲ୍ରେ ଯୋଡ଼ାଯାଇଥିଲା:

```sql
-- src/lib/db/migrations/099_proxy_family.sql
ALTER TABLE proxy_registry ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
ALTER TABLE upstream_proxy_config ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
```

- `proxy_registry.family` — ରେଜିଷ୍ଟ୍ରି ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ ପାଇଁ ପ୍ରତି-ପ୍ରକ୍ସି ନିର୍ଦ୍ଦେଶ (`src/lib/db/proxies.ts`)। ରିଜୋଲ୍ୟୁସନ୍ କ୍ୱେରୀଗୁଡ଼ିକ ଅନ୍ୟ ପ୍ରକ୍ସି କଲମ୍ଗୁଡ଼ିକ ସହିତ `family`କୁ ଚୟନ କରେ, ଏବଂ କୌଣସି ଅନୁପସ୍ଥିତ/ଅଣ-ଷ୍ଟ୍ରିଙ୍ଗ୍ ମୂଲ୍ୟକୁ ବାଧ୍ୟତାମୂଳକ ଭାବେ `"auto"`ରେ ପରିବର୍ତ୍ତନ କରାଯାଏ।
- `upstream_proxy_config.family` — ଅପ୍ଷ୍ଟ୍ରିମ୍-ପ୍ରକ୍ସି ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ ପାଇଁ ନିର୍ଦ୍ଦେଶ (`src/lib/db/upstreamProxy.ts`), ସମାନ `"auto"` ଡିଫଲ୍ଟ ସହିତ।

ଯେତେବେଳେ ଏକ ରିଜଲ୍ଭ୍ ହୋଇଥିବା ପ୍ରକ୍ସି ଅବଜେକ୍ଟ୍ରେ ଏକ ଅଣ-`auto` `family` ଥାଏ, ସେତେବେଳେ ପିନ୍ଟି ଡିସ୍ପାଚର୍ ପର୍ଯ୍ୟନ୍ତ ଅକ୍ଷୁଣ୍ଣ ରହିବା ପାଇଁ `proxyConfigToUrl`, `?family=` ମାର୍କର୍ଟି ଯୋଡ଼େ।
