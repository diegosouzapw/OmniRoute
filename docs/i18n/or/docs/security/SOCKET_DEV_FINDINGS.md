ଏହି ଡକ୍ୟୁମେଣ୍ଟଟି `omniroute@3.8.5` ବିରୋଧରେ ଉଠାଯାଇଥିବା ଛଅଟି
`AI-detected potential malware` ଫଳାଫଳ ଏବଂ `omniroute@3.8.6`ରେ ପ୍ରୟୋଗ
କରାଯାଇଥିବା ପ୍ରତିକାରଗୁଡ଼ିକ ପାଇଁ ରକ୍ଷଣାବେକ୍ଷକ-ଲିଖିତ ପ୍ରମାଣନ। ଏହାର ଉଦ୍ଦେଶ୍ୟ:

1. ସୁରକ୍ଷା-ପାଇପଲାଇନ୍ ପରିଚାଳକମାନଙ୍କୁ ଏକକ ସନ୍ଦର୍ଭ ଯୋଗାଇବା, ଯାହାକୁ ସେମାନେ
   ପ୍ରକୃତ ଉତ୍ସ ସହିତ ଫଳାଫଳଗୁଡ଼ିକର ମୂଲ୍ୟାଙ୍କନ କରିବାବେଳେ ଉଦ୍ଧୃତ କରିପାରିବେ।
2. ଭବିଷ୍ୟତର AI ସ୍କାନରଗୁଡ଼ିକୁ ରକ୍ଷଣାବେକ୍ଷକ-ସ୍ୱାକ୍ଷରିତ ଏହି ଦାବି ଚିହ୍ନଟ କରିବାକୁ
   ସକ୍ଷମ କରିବା ଯେ, ଚିହ୍ନିତ ପ୍ରତ୍ୟେକ ପଥ ଉଦ୍ଦେଶ୍ୟମୂଳକ, ଇଚ୍ଛାଧୀନ ଏବଂ ଡକ୍ୟୁମେଣ୍ଟକୃତ।
3. ପ୍ରତ୍ୟେକ କଲ୍ ସାଇଟ୍କୁ _କାହିଁକି_ ଏହିପରି ଆକାର ଦିଆଯାଇଛି ତାହାର ଏକ ଲିଖିତ ରେକର୍ଡ ରଖିବା —
   ଯାହାଦ୍ୱାରା ଭବିଷ୍ୟତର କୌଣସି ରିଫ୍ୟାକ୍ଟର୍ ଜାଣିଶୁଣି ହଟାଯାଇଥିବା
   ଫିଙ୍ଗରପ୍ରିଣ୍ଟକୁ ଅନିଚ୍ଛାକୃତ ଭାବେ ପୁନଃ ପ୍ରବେଶ କରାଇ ନ ଦିଏ।

ଯଦି ଆପଣ ଏପରି ଏକ ସ୍କାନର୍ ପରିଚାଳନା କରନ୍ତି, ଯାହା v3.8.6 ପ୍ରତିକାରଗୁଡ଼ିକ
ପ୍ରକାଶିତ ହେବା ପରେ ନିମ୍ନର କୌଣସି କଲ୍ ସାଇଟ୍କୁ ପୁନଃ ଚିହ୍ନିତ କରେ, ଦୟାକରି
ସ୍କାନ୍ ଟ୍ରେସ୍ ସହିତ ଏକ ଇସ୍ୟୁ ଖୋଲନ୍ତୁ ଏବଂ ଆମେ ଏଠାରେ ପ୍ରମାଣନକୁ ବିସ୍ତାର କରିବୁ।

## §1 — MITM ରୁଟ୍-CA ସଂସ୍ଥାପନ (`77484.js`)

**ଉତ୍ସ ଫାଇଲଗୁଡ଼ିକ**:

- `src/mitm/cert/install.ts` — ସାର୍ବଜନୀନ `installCert()` / `uninstallCert()`,
  ପ୍ରତି-ପ୍ଲାଟଫର୍ମ `installCertWindows/Mac/Linux`।
- `src/mitm/systemCommands.ts` — ସଂସ୍ଥାପନ ପଥଗୁଡ଼ିକ ଦ୍ୱାରା ବ୍ୟବହୃତ ସହଭାଗୀ `execFile` / `spawn` / PowerShell
  ସହାୟକଗୁଡ଼ିକ।

**ଟ୍ରିଗର୍**: ବ୍ୟବହାରକାରୀ ସ୍ଥାନୀୟ ଡ୍ୟାସବୋର୍ଡରେ
`/dashboard/cli-tools/mitm` ଠାରେ "MITM ପ୍ରକ୍ସି ସକ୍ଷମ କରନ୍ତୁ" କ୍ଲିକ୍ କରନ୍ତି। ରୁଟ୍ଟି କେବଳ ଲୁପ୍ବ୍ୟାକ୍ ପାଇଁ ଉପଲବ୍ଧ — `CLAUDE.md`ର
କଠୋର ନିୟମ #17 ଏବଂ `src/server/authz/routeGuard.ts::isLocalOnlyPath()` ଦେଖନ୍ତୁ। ଏକ ଟନେଲ୍ ମାଧ୍ୟମରେ ପ୍ରକାଶିତ
ଲିକ୍ ହୋଇଥିବା JWT ଏହି କୋଡ୍ ପଥକୁ **ଟ୍ରିଗର୍ କରିପାରିବ ନାହିଁ**।

**ସମ୍ପାଦିତ ବିଶେଷାଧିକାରପ୍ରାପ୍ତ କାର୍ଯ୍ୟଗୁଡ଼ିକ (ପ୍ରତି ପ୍ଲାଟଫର୍ମ)**:

| OS                     | କମାଣ୍ଡ(ଗୁଡ଼ିକ)                                                                                                    |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | UAC ମାଧ୍ୟମରେ `certutil -addstore Root <cert>`                                                                     |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | `certutil -d sql:<profile>` ମାଧ୍ୟମରେ ପ୍ରତି-ପ୍ରୋଫାଇଲ୍ NSS DB ଅଦ୍ୟତନ                                                |

ଏଗୁଡ଼ିକ `mitmproxy`, Charles Proxy, Fiddler ଏବଂ
Caddy ଦ୍ୱାରା ବ୍ୟବହୃତ ସେହି ସମାନ କମାଣ୍ଡ। OmniRouteରେ ଏଗୁଡ଼ିକ ଥିବାର ତଥ୍ୟ
`docs/security/STEALTH_GUIDE.md`ରେ ଡକ୍ୟୁମେଣ୍ଟକୃତ।

**v3.8.6 ପ୍ରତିକାର**:

- `runElevatedPowerShell()` ଆଉ `-EncodedCommand <base64utf16le>` ବ୍ୟବହାର କରେ ନାହିଁ।
  ଉଚ୍ଚାଧିକାରପ୍ରାପ୍ତ ପେଲୋଡ୍କୁ ପ୍ରତି-କଲ୍ ଅସ୍ଥାୟୀ `.ps1` ଫାଇଲ୍ରେ (ମୋଡ୍ 0o600,
  ଏକ ବ୍ୟକ୍ତିଗତ `mkdtempSync` ଡିରେକ୍ଟୋରି ଭିତରେ) ଲେଖାଯାଏ ଏବଂ `-File` ମାଧ୍ୟମରେ ସନ୍ଦର୍ଭିତ କରାଯାଏ। ଫାଇଲ୍ଟି
  `finally`ରେ ଅନଲିଙ୍କ୍ କରାଯାଏ। ଏହା Socket.devର AI
  କ୍ଲାସିଫାୟର୍ ଦ୍ୱାରା ଚିହ୍ନିତ PowerShell ମାଧ୍ୟମରେ base64-ଉଚ୍ଚାଧିକାର ପ୍ରାପ୍ତିର ପାଠ୍ୟପୁସ୍ତକୀୟ
  ଫିଙ୍ଗରପ୍ରିଣ୍ଟକୁ ହଟାଏ।
- `installCertWindows` ଏଠାକୁ ସୂଚାଉଥିବା ଏକ ଇନ୍ଲାଇନ୍ `SECURITY-AUDITOR-NOTE:` ବ୍ଲକ୍
  ଧାରଣ କରେ।

**ଆମେ ଏହାକୁ କାହିଁକି ରଖୁଛୁ**: MITM ପ୍ରକ୍ସି ହେଉଛି
`docs/security/STEALTH_GUIDE.md` ଏବଂ `docs/frameworks/MITM-PROXY.md` ଦ୍ୱାରା ବ୍ୟବହୃତ ଏକ ଡକ୍ୟୁମେଣ୍ଟକୃତ ବୈଶିଷ୍ଟ୍ୟ। ଏହାକୁ ହଟାଇବା
agent-bridge ବୈଶିଷ୍ଟ୍ୟ ସମୂହକୁ ଅକାର୍ଯ୍ୟକରିଦେବ।

## §2 — Zed ପରିଚୟପତ୍ର ଆମଦାନୀ (`app/api/providers/zed/import/route.js`)

**ଉତ୍ସ ଫାଇଲଗୁଡ଼ିକ**:

- `src/app/api/providers/zed/discover/route.ts` _(v3.8.6ରେ ନୂତନ)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(v3.8.6ରେ ନୂତନ)_

**ଟ୍ରିଗର୍**: ବ୍ୟବହାରକାରୀ ସ୍ଥାନୀୟ ଡ୍ୟାସ୍ବୋର୍ଡର ପ୍ରଦାନକାରୀ ପୃଷ୍ଠାରେ "Zedରୁ ଆମଦାନୀ କରନ୍ତୁ" କ୍ଲିକ୍ କରନ୍ତି। ଏଣ୍ଡପଏଣ୍ଟଟି `requireManagementAuth` ଦ୍ୱାରା ସୁରକ୍ଷିତ। Zed ଏଡିଟର୍ ନିଜେ ଏହାର ପ୍ରଦାନକାରୀ API କୀଗୁଡ଼ିକୁ ଡକ୍ୟୁମେଣ୍ଟ କରାଯାଇଥିବା ସେବା ନାମ ଅଧୀନରେ OS କୀଚେନ୍ରେ ଲେଖେ — https://zed.dev/docs/ai/llm-providers ଦେଖନ୍ତୁ।

**v3.8.5ର ଆଚରଣ (ଯାହାକୁ Socket.dev ଫ୍ଲାଗ୍ କରିଥିଲା)**:

`POST /import` ପରିଚୟପତ୍ରଗୁଡ଼ିକୁ ଖୋଜି ଗୋଟିଏ ରାଉଣ୍ଡ-ଟ୍ରିପ୍ରେ ସ୍ୱୟଂଚାଳିତ ଭାବେ ସ୍ଥାନୀୟ SQLite ଷ୍ଟୋର୍ରେ ସଂରକ୍ଷଣ କରୁଥିଲା। ପ୍ରତ୍ୟେକ ଆକାଉଣ୍ଟ ପାଇଁ କୌଣସି ନିଶ୍ଚିତକରଣ କିମ୍ବା ଫିଙ୍ଗରପ୍ରିଣ୍ଟ ନଥିଲା, କେବଳ "Nଟି ଟୋକନ୍ ମିଳିଲା, ସବୁ ଆମଦାନୀ ହେଲା।"

**v3.8.6 ପ୍ରତିକାର — 2-ପର୍ଯ୍ୟାୟ ନିଶ୍ଚିତକରଣ**:

1. **`POST /api/providers/zed/discover`**
   `{ candidates: [{ provider, service, account, fingerprint }] }` ଫେରାଏ। କଞ୍ଚା
   ଟୋକନ୍ଟି **କେବେବି** ପ୍ରେଷଣ କରାଯାଏ ନାହିଁ। ଫିଙ୍ଗରପ୍ରିଣ୍ଟଟି ହେଉଛି
   `sha256(service|account|token).slice(0,16)`।
2. ଡ୍ୟାସ୍ବୋର୍ଡ ପ୍ରାର୍ଥୀ ତାଲିକା ପ୍ରଦର୍ଶନ କରେ, ଅପରେଟର୍ କେଉଁଗୁଡ଼ିକୁ
   ଆମଦାନୀ କରାଯିବ ତାହା ବାଛନ୍ତି ଏବଂ **`POST /api/providers/zed/import`**କୁ
   `{ confirmedAccounts: [{ service, account, fingerprint }] }` ପୋଷ୍ଟ କରନ୍ତି।
3. ଆମଦାନୀ ଏଣ୍ଡପଏଣ୍ଟଟି **ସର୍ଭର୍ରେ କୀଚେନ୍କୁ ପୁନଃ ପଢ଼େ** ଏବଂ

## §5 — OmniRoute Cloud Sync କ୍ରେଡେନ୍ସିଆଲ୍ ରାଇଟ୍-ବ୍ୟାକ୍ (`api/keys/[id]/route.js`)

**ଟ୍ରିଗର୍**: `isCloudEnabled()` `true` ଫେରାଏ (ଡ୍ୟାସ୍ବୋର୍ଡରୁ ସେଟ୍ କରାଯାଇଛି) **ଏବଂ**
`CLOUD_URL` ବିନ୍ୟାସିତ ହୋଇଛି। ଉଭୟ ବନ୍ଦ ଥିଲେ, Cloud ଏଣ୍ଡପଏଣ୍ଟକୁ କୌଣସି ଆଉଟ୍ବାଉଣ୍ଡ୍ ନେଟ୍ୱର୍କ କଲ୍ କରାଯାଏ ନାହିଁ।

**v3.8.5 ଆଚରଣ (Socket.dev ସଠିକ୍ ଭାବରେ ଧରିଥିବା ବଗ୍)**:

`cloudUpdatedAt > localUpdatedAt` ହେଲେ `updateLocalTokens()` Cloud ପ୍ରତିକ୍ରିୟାରୁ
`accessToken`, `refreshToken`, ଏବଂ `providerSpecificData`କୁ ଓଭର୍ରାଇଟ୍ କରୁଥିଲା। କୌଣସି HMAC, ସ୍ୱାକ୍ଷର କିମ୍ବା ଚେକ୍ସମ୍ ନଥିଲା। ଏକ
ଭୁଲ୍ ଭାବେ ବିନ୍ୟାସିତ କିମ୍ବା ବିଦ୍ୱେଷପୂର୍ଣ୍ଣ `CLOUD_URL` (ଅଥବା ଚ୍ୟାନେଲ୍ରେ ଏକ MITM) ନିରବରେ
ପ୍ରଦାନକାରୀଙ୍କ OAuth ଟୋକେନ୍ଗୁଡ଼ିକୁ ବଦଳାଇ ପାରୁଥିଲା।

**v3.8.6 ପ୍ରତିକାର**:

1. **HMAC ଯାଞ୍ଚ**: JSON ପାର୍ସ କରିବା ପୂର୍ବରୁ `verifyCloudSignature(rawBody, sigHeader)`
   `X-Cloud-Sig` ହେଡର୍ (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`)କୁ ଯାଞ୍ଚ କରେ। ସିକ୍ରେଟ୍ ସେଟ୍ ହୋଇଥିଲେ, ସ୍ୱାକ୍ଷର ଆବଶ୍ୟକ।
   ନଥିଲେ (ଲିଗେସି ମୋଡ୍), ଏକ ଚେତାବନୀ ଲଗ୍ କରାଯାଏ ଏବଂ ପ୍ରତିକ୍ରିୟାକୁ
   ଗ୍ରହଣ କରାଯାଏ — v3.9ରେ ସିକ୍ରେଟ୍ ଆବଶ୍ୟକ ହେବ।
2. **ଗୋପନୀୟ ଫିଲ୍ଡ ପାଇଁ ଅପ୍ଟ-ଇନ୍**: `accessToken` / `refreshToken` /
   `providerSpecificData`କୁ **କେବଳ** `OMNIROUTE_CLOUD_SYNC_SECRETS=true`
   ଥିଲେ ଓଭର୍ରାଇଟ୍ କରାଯାଏ। ଡିଫଲ୍ଟ ମୋଡ୍ କେବଳ ଅଣ-କ୍ରେଡେନ୍ସିଆଲ୍
   ମେଟାଡାଟା (`expiresAt`, `status`, `lastError*`,
   `rateLimitedUntil`, `updatedAt`) ସିଙ୍କ୍ କରେ। ରିମୋଟ୍ ଟୋକେନ୍ ସିଙ୍କ୍ ଉପରେ
   ନିର୍ଭର କରୁଥିବା ବ୍ୟବହାରକାରୀଙ୍କ ପାଇଁ ଏହା ଏକ **ବ୍ରେକିଂ ଚେଞ୍ଜ୍** —
   ସେମାନେ ସ୍ପଷ୍ଟ ଭାବରେ ଅପ୍ଟ-ଇନ୍ କରିବା ଆବଶ୍ୟକ।

**ଆମେ ଏହାକୁ କାହିଁକି ରଖୁଛୁ**: ଏକ OmniRoute Cloud ଟେନାଣ୍ଟ ପାଇଁ ଟିମ୍ର
କ୍ରେଡେନ୍ସିଆଲ୍ଗୁଡ଼ିକୁ କେନ୍ଦ୍ରୀଭୂତ କରିବାର ଏକମାତ୍ର ଉପାୟ ହେଉଛି Cloud Sync।
