OmniRoute npm + Docker ଆର୍ଟିଫ୍ୟାକ୍ଟ ପ୍ରକାଶ କରେ। ଏହି ଗେଟ୍ଗୁଡ଼ିକ ଉତ୍ପତ୍ତି ପ୍ରମାଣ,
ଇନ୍ଭେଣ୍ଟୋରି (SBOM) ଏବଂ CVE ସ୍କାନିଂ ପ୍ରଦାନ କରେ; ସବୁଗୁଡ଼ିକ OSS ଏବଂ ରିଲିଜ୍ ୱର୍କଫ୍ଲୋ ସହିତ ସଂଯୁକ୍ତ।
**ପ୍ରଥମେ-ପରାମର୍ଶ** ଆଭିମୁଖ୍ୟ — ଏଗୁଡ଼ିକ ବର୍ତ୍ତମାନ ରିପୋର୍ଟ କରନ୍ତି ଏବଂ ପ୍ରଥମ
ସଫଳ ରିଲିଜ୍ ପରେ ବ୍ଲକିଂ ସ୍ଥିତିକୁ ଉନ୍ନୀତ ହେବେ।

| ଗେଟ୍                       | ଟୁଲ୍                                           | କେଉଁଠାରେ                      | ବ୍ଲକ୍ କରେ କି?            | ଆଉଟ୍ପୁଟ୍                                     |
| -------------------------- | ---------------------------------------------- | ----------------------------- | ------------------------ | -------------------------------------------- |
| SLSA ଉତ୍ପତ୍ତି ପ୍ରମାଣ (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | କେବଳ ପ୍ରକାଶନ ବିଫଳ ହେଲେ   | npmjs ବ୍ୟାଜ୍ / `npm audit signatures`        |
| SBOM npm                   | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | କେବଳ ଜେନେରେସନ୍ ବିଫଳ ହେଲେ | ରିଲିଜ୍ ଆସେଟ୍ + ଆର୍ଟିଫ୍ୟାକ୍ଟ                  |
| SBOM ଇମେଜ୍                 | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (ମର୍ଜ୍)  | ପରାମର୍ଶମୂଳକ              | CycloneDX ଆର୍ଟିଫ୍ୟାକ୍ଟ                       |
| Trivy CVE (SARIF)          | `aquasecurity/trivy-action`                    | `docker-publish.yml` (ମର୍ଜ୍)  | ପରାମର୍ଶମୂଳକ              | SARIF (HIGH+CRITICAL) → ସୁରକ୍ଷା ଟ୍ୟାବ୍       |
| Trivy CRITICAL ଗେଟ୍        | `aquasecurity/trivy-action`                    | `docker-publish.yml` (ମର୍ଜ୍)  | **ବ୍ଲକିଂ**               | ସମାଧାନଯୋଗ୍ୟ CRITICAL ପାଇଁ `exit-code: '1'`   |
| osv vulnCount              | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **ବ୍ଲକିଂ**               | `metrics.vulnCount`କୁ ରାଚେଟ୍ କରେ (ଦିଗ: ତଳକୁ) |
| OpenSSF Scorecard          | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | ପରାମର୍ଶମୂଳକ              | SARIF → ସୁରକ୍ଷା + ବ୍ୟାଜ୍                     |

ଇମେଜ୍ CVE ରାଚେଟ୍ `docker-publish.yml`ରେ **ଦୁଇଟି ପଦକ୍ଷେପ** ବ୍ୟବହାର କରେ: SARIF ପଦକ୍ଷେପ
(`HIGH,CRITICAL`, `exit-code: 0`) ବ୍ଲକ୍ ନକରି HIGH+CRITICALକୁ ସୁରକ୍ଷା ଟ୍ୟାବ୍ରେ
ଦୃଶ୍ୟମାନ ରଖେ; _CRITICAL ଗେଟ୍_ ପଦକ୍ଷେପ (`severity: CRITICAL`, `ignore-unfixed: true`,
`exit-code: 1`) **ସମାଧାନ ଉପଲବ୍ଧ ଥିବା** CRITICAL CVE ପାଇଁ ରିଲିଜ୍କୁ ବିଫଳ କରେ। `ignore-unfixed`
ଅପ୍ଷ୍ଟ୍ରିମ୍ ପ୍ୟାଚ୍ ନଥିବା ବେସ୍-ଇମେଜ୍ CVE କାରଣରୁ ରିଲିଜ୍କୁ ବ୍ଲକ୍ କରିବାରୁ ରୋକେ।

## ⚠️ CVE ଭିନ୍ନତା (ବ୍ଲକିଂ osv/Trivy ଗେଟ୍ଗୁଡ଼ିକ)

osv ଏବଂ Trivy ନିର୍ଭରତାଗୁଡ଼ିକୁ **ନିରନ୍ତର ବୃଦ୍ଧି ପାଉଥିବା** CVE ଡାଟାବେସ୍ଗୁଡ଼ିକ ସହିତ ତୁଳନା କରନ୍ତି। କୌଣସି
ନିର୍ଭରତାକୁ **ସ୍ପର୍ଶ କରୁନଥିବା** PR ହଠାତ୍ ବିଫଳ ହୋଇପାରେ, କାରଣ ଏକ ବିଦ୍ୟମାନ ନିର୍ଭରତାରେ
ନୂତନ CVE ପ୍ରକାଶିତ ହୋଇଛି (osv: ମାପାଯାଇଥିବା `vulnCount` > ବେସ୍ଲାଇନ୍; Trivy: ଇମେଜ୍ରେ ଏକ ନୂତନ
ସମାଧାନଯୋଗ୍ୟ CRITICAL)। **ଏହା ଏକ ବ୍ଲକିଂ CVE ଗେଟ୍ର ଆଶାକରାଯାଇଥିବା ପରିଚାଳନାଗତ ଆଚରଣ,
ପ୍ରଡକ୍ଟ ରିଗ୍ରେସନ୍ ନୁହେଁ।**

ନୂତନ ଭାବେ ପ୍ରକାଶିତ CVE କାରଣରୁ osv କିମ୍ବା Trivy ବିଫଳ ହେଲେ, ପ୍ରତିକାର ହେଉଛି:

1. **ପ୍ରଭାବିତ ନିର୍ଭରତାକୁ ଅପ୍ଗ୍ରେଡ୍ କରନ୍ତୁ** (ପସନ୍ଦଯୋଗ୍ୟ) — `package.json`
   `overrides` (ଟ୍ରାନ୍ଜିଟିଭ୍ ନିର୍ଭରତା) ମାଧ୍ୟମରେ ପ୍ୟାଚ୍ ହୋଇଥିବା ସଂସ୍କରଣକୁ ଅପ୍ଗ୍ରେଡ୍ କରନ୍ତୁ କିମ୍ବା ପ୍ୟାଚ୍ ହୋଇଥିବା ବେସ୍ରେ ଇମେଜ୍କୁ ପୁନଃନିର୍ମାଣ କରନ୍ତୁ।
2. **କୌଣସି ଅପ୍ଷ୍ଟ୍ରିମ୍ ସମାଧାନ ନଥିଲେ:**
   - **osv:** `config/quality/quality-baseline.json`ରେ `metrics.vulnCount`କୁ ପୁନଃ-ବେସ୍ଲାଇନ୍ କରନ୍ତୁ
     (`npm run quality:ratchet -- --update` ଉତ୍ସର୍ଗୀକୃତ ଗେଟ୍ଗୁଡ଼ିକୁ ଅନ୍ତର୍ଭୁକ୍ତ କରେନାହିଁ — ମୂଲ୍ୟଟିକୁ
     ହାତରେ ସମ୍ପାଦନା କରନ୍ତୁ, `direction:down`) ଏବଂ ଏକ ଯଥାର୍ଥତା ଟିପ୍ପଣୀ + ଟ୍ରାକିଂ ଇସ୍ୟୁ ଯୋଡ଼ନ୍ତୁ।
   - **Trivy:** ଏକ ଯଥାର୍ଥତା ଟିପ୍ପଣୀ + ଟ୍ରାକିଂ ଇସ୍ୟୁ ସହିତ `.trivyignore`ରେ ଏକ ଏଣ୍ଟ୍ରି
     (ପ୍ରତି ଧାଡ଼ିରେ CVE-ID) ଯୋଡ଼ନ୍ତୁ। `ignore-unfixed: true` ପ୍ୟାଚ୍ ନଥିବା CVEଗୁଡ଼ିକୁ
     ପୂର୍ବରୁ ସ୍ୱୟଂଚାଳିତ ଭାବେ ଅନ୍ତର୍ଭୁକ୍ତ କରେ।

ଟୁଲ୍ ଅନୁପସ୍ଥିତ ଥିଲେ କିମ୍ବା ମାପ ବିଫଳ ହେଲେ ଉଭୟ ଗେଟ୍ **ସୁରକ୍ଷିତ ଭାବେ SKIP କରନ୍ତି**
(exit 0) (osv-scanner PATHରେ ନାହିଁ, osv.dev/ନେଟୱର୍କ ଅପହଞ୍ଚ, ଅବୈଧ JSON) — ଏକ
**ମାପ** ବିଫଳତା କେବେ ବ୍ଲକ୍ କରେନାହିଁ; କେବଳ ଏକ **ମାପାଯାଇଥିବା** ରିଗ୍ରେସନ୍ ବ୍ଲକ୍ କରେ।

Phase 7 ଗେଟ୍ଗୁଡ଼ିକର (osv-scanner, gitleaks, actionlint+zizmor) ପରିପୂରକ: zizmor
