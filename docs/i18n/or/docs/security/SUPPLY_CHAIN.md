OmniRoute npm + Docker ଆର୍ଟିଫ୍ୟାକ୍ଟ ପ୍ରକାଶ କରେ। ଏହି ଗେଟ୍ଗୁଡ଼ିକ ପ୍ରୋଭେନାନ୍ସ, ଇନଭେଣ୍ଟୋରୀ (SBOM) ଏବଂ CVE ସ୍କାନିଂ ପ୍ରଦାନ କରନ୍ତି, ଯାହା ସମସ୍ତ OSS ଅଟେ ଏବଂ ରିଲିଜ୍ ୱାର୍କଫ୍ଲୋରେ ସଂଯୁକ୍ତ ହୋଇଛି।
**ପରାମର୍ଶ-ପ୍ରଥମ** ଆଭିମୁଖ୍ୟ — ସେମାନେ ବର୍ତ୍ତମାନ ରିପୋର୍ଟ କରନ୍ତି, ପ୍ରଥମ ସବୁଜ ରିଲିଜ୍ ପରେ ବ୍ଲକିଂକୁ ପ୍ରୋତ୍ସାହିତ କରନ୍ତି।

| SBOM image            | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | ପରାମର୍ଶ                   | CycloneDX ଆର୍ଟିଫ୍ୟାକ୍ଟ                       |

| OpenSSF Scorecard     | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | ପରାମର୍ଶ                   | SARIF → ସୁରକ୍ଷା + ବ୍ୟାଜ୍                     |

ଇମେଜ୍ CVE ରାଚେଟ୍ `docker-publish.yml` ରେ **ଦୁଇଟି ପଦକ୍ଷେପ** ବ୍ୟବହାର କରେ: SARIF ପଦକ୍ଷେପ (`HIGH,CRITICAL`, `exit-code: 0`) HIGH+CRITICAL କୁ ସୁରକ୍ଷା ଟ୍ୟାବ୍ ରେ ବ୍ଲକ୍ ନକରି ଦୃଶ୍ୟମାନ ରଖେ; _CRITICAL ଗେଟ୍_ ପଦକ୍ଷେପ (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) ଏକ CRITICAL CVE **ସହିତ ଏକ ଉପଲବ୍ଧ ସୁଧାର** ଉପରେ ରିଲିଜ୍ କୁ ବିଫଳ କରେ। `ignore-unfixed` ଏକ ଅପଷ୍ଟ୍ରିମ୍ ପ୍ୟାଚ୍ ବିନା ଏକ ବେସ୍-ଇମେଜ୍ CVE ପାଇଁ ରିଲିଜ୍ କୁ ବ୍ଲକ୍ କରିବାରୁ ରୋକିଥାଏ।

## ⚠️ CVE ଭେରିଆନ୍ସ (osv/Trivy ଗେଟ୍ ବ୍ଲକ୍ କରୁଛି)

osv ଏବଂ Trivy CVE ଡାଟାବେସ୍ ବିରୁଦ୍ଧରେ ଡେପ୍ସ ତୁଳନା କରନ୍ତି ଯାହା **ଲଗାତାର ବଢ଼ୁଛି**। ଏକ PR ଯାହା **କୌଣସି ଡିପେଣ୍ଡେନ୍ସିକୁ ସ୍ପର୍ଶ କରେ ନାହିଁ** ହଠାତ୍ ଲାଲ୍ ହୋଇପାରେ କାରଣ ଏକ ନୂତନ CVE ଏକ ବିଦ୍ୟମାନ ଡେପ୍ ରେ ପ୍ରକାଶ ପାଇଲା (osv: ମାପାଯାଇଥିବା `vulnCount` > ବେସଲାଇନ୍; Trivy: ଇମେଜ୍ ରେ ଏକ ନୂତନ ସୁଧାର ଯୋଗ୍ୟ CRITICAL)। **ଏହା ଏକ ବ୍ଲକିଂ CVE ଗେଟ୍ ର ଆଶା କରାଯାଉଥିବା କାର୍ଯ୍ୟକ୍ଷମ ଆଚରଣ, ଏକ ଉତ୍ପାଦ ରିଗ୍ରେସନ୍ ନୁହେଁ।**

ଯେତେବେଳେ osv କିମ୍ବା Trivy ଏକ ନୂତନ ଭାବରେ ପ୍ରକାଶିତ CVE ହେତୁ ଲାଲ୍ ହୋଇଯାଏ, ତେବେ ପ୍ରତିକାର ହେଉଛି:

1.  **ପ୍ରଭାବିତ ଡେପ୍ କୁ ବମ୍ପ୍ କରନ୍ତୁ** (ପସନ୍ଦଯୋଗ୍ୟ) — `package.json` `overrides` (ଟ୍ରାନ୍ସିଟିଭ୍ ଡେପ୍ସ) ମାଧ୍ୟମରେ ପ୍ୟାଚ୍ ହୋଇଥିବା ସଂସ୍କରଣକୁ ଅପଗ୍ରେଡ୍ କରନ୍ତୁ କିମ୍ବା ଏକ ପ୍ୟାଚ୍ ହୋଇଥିବା ବେସ୍ ଉପରେ ଇମେଜ୍ ପୁନଃନିର୍ମାଣ କରନ୍ତୁ।
2.  **ଯଦି କୌଣସି ଅପଷ୍ଟ୍ରିମ୍ ସୁଧାର ନାହିଁ:**
    - **osv:** `config/quality/quality-baseline.json` ରେ `metrics.vulnCount` କୁ ପୁନଃ-ବେସଲାଇନ୍ କରନ୍ତୁ (`npm run quality:ratchet -- --update` ଉତ୍ସର୍ଗୀକୃତ ଗେଟ୍ ଗୁଡ଼ିକୁ କଭର୍ କରେ ନାହିଁ — ମୂଲ୍ୟକୁ ହାତରେ ସମ୍ପାଦନା କରନ୍ତୁ, `direction:down`) ଏକ ଯୁକ୍ତିଯୁକ୍ତ ନୋଟ୍ + ଟ୍ରାକିଂ ଇସ୍ୟୁ ସହିତ।
    - **Trivy:** `.trivyignore` ରେ ଏକ ଏଣ୍ଟ୍ରି ଯୋଡନ୍ତୁ (ପ୍ରତି ଧାଡ଼ିରେ CVE-ID) ଏକ ଯୁକ୍ତିଯୁକ୍ତ ମନ୍ତବ୍ୟ + ଟ୍ରାକିଂ ଇସ୍ୟୁ ସହିତ। `ignore-unfixed: true` ପ୍ୟାଚ୍ ବିନା CVE ଗୁଡ଼ିକୁ ସ୍ୱୟଂଚାଳିତ ଭାବରେ କଭର୍ କରେ।

ଉଭୟ ଗେଟ୍ **ସୁନ୍ଦର ଭାବରେ SKIP** (exit 0) କରନ୍ତି ଯେତେବେଳେ ଟୁଲ୍ ଅନୁପସ୍ଥିତ ଥାଏ କିମ୍ବା ମାପ ବିଫଳ ହୁଏ (osv-scanner PATH ରେ ନାହିଁ, osv.dev/network ଅପହଞ୍ଚ, ଅବୈଧ JSON) — ଏକ **ମାପ** ବିଫଳତା କେବେହେଲେ ବ୍ଲକ୍ କରେ ନାହିଁ, କେବଳ ଏକ **ମାପାଯାଇଥିବା** ରିଗ୍ରେସନ୍ ବ୍ଲକ୍ କରେ।

## ଜଣାଶୁଣା ଗ୍ରହଣୀୟ ବିପଦଗୁଡ଼ିକ

### extract-zip 2.0.1 — GHSA-7pqw-9j4j-h8q3 / GHSA-jmr9-qjv8-65gv (#14482)

`extract-zip@2.0.1` ଦୁଇଟି ଅସଂଶୋଧିତ ଉଚ୍ଚ-ଗୁରୁତ୍ୱପୂର୍ଣ୍ଣ symlink-traversal ପରାମର୍ଶ ବହନ କରେ।
ଉପରୋକ୍ତ CVE ଭିନ୍ନତା ପ୍ରତିକାରର "ଉପରମୁଣ୍ଡରେ କୌଣସି ସମାଧାନ ନାହିଁ" ଶାଖା ଅନୁଯାୟୀ, ଏହା ଏକ
**ଗ୍ରହଣୀୟ ବିପଦ**, ବୃଦ୍ଧି ନୁହେଁ:

- **ଶୃଙ୍ଖଳ:** `promptfoo` (devDependency) → `@openai/codex-security` → `extract-zip@2.0.1`।
  `package-lock.json` ମାଧ୍ୟମରେ ନିଶ୍ଚିତ ହୋଇଛି — ସମଗ୍ର ନିର୍ଭରଶୀଳତା
  ବୃକ୍ଷରେ ଠିକ୍ ଗୋଟିଏ ପ୍ୟାକେଜ୍ (`@openai/codex-security`) `extract-zip` ଘୋଷଣା କରେ, ଏବଂ ଠିକ୍ ଗୋଟିଏ ପ୍ୟାକେଜ୍
  (`promptfoo`) `@openai/codex-security` ଘୋଷଣା କରେ।
- **ଶୃଙ୍ଖଳରେ କୌଣସି ସ୍ଥିର ପ୍ରକାଶନ ବିଦ୍ୟମାନ ନାହିଁ।** `extract-zip@2.0.1` (2020 ରେ ପ୍ରକାଶିତ) ହେଉଛି ପ୍ୟାକେଜର ଅନ୍ତିମ ପ୍ରକାଶନ — ଏହା ଅସଂରକ୍ଷିତ। `@openai/codex-security` ର
  ବର୍ତ୍ତମାନର npm-latest (`0.1.29`) ଏପର୍ଯ୍ୟନ୍ତ `extract-zip@2.0.1` ଟାଣୁଛି।
- **ଉତ୍ପାଦନରୁ ଅପହଞ୍ଚ।** `promptfoo` କେବଳ devDependency-ମାତ୍ର (କେବେବି `dependencies` ତଳେ ତାଲିକାଭୁକ୍ତ ନୁହେଁ),
  ଏବଂ `src/`, `open-sse/`, କିମ୍ବା `bin/` ତଳେ କୌଣସି ଫାଇଲ୍
  `extract-zip` npm ପ୍ୟାକେଜ୍ ଆମଦାନୀ କରେ ନାହିଁ — OmniRoute ର ନିଜସ୍ୱ `extractZip()` ସହାୟକ
  (`src/lib/versionManager/binaryManager.ts:93`) ମୂଳ `unzip`/`tar` କୁ ଶେଲ୍ କରେ
  ଏବଂ ଅସମ୍ବନ୍ଧିତ। `@openai/codex-security` ମଧ୍ୟ extract-zip ର onEntry କଲବ୍ୟାକ୍ ଉପରେ ନିଜସ୍ୱ symlink-traversal
  ଗାର୍ଡ ପଠାଏ।
- **`package.json` `overrides` ମାଧ୍ୟମରେ `extract-zip` କୁ ଉପନାମ କରନ୍ତୁ ନାହିଁ** — ଏକମାତ୍ର ବ୍ୟବହାର ଯୋଗ୍ୟ
  ଡ୍ରପ୍-ଇନ୍ ପ୍ରତିସ୍ଥାପନ ହେଉଛି Electron-org-internal ଏବଂ `@openai/codex-security` ର ନିଜସ୍ୱ onEntry/defaultDirMode/defaultFileMode ଯାଞ୍ଚ ସହିତ API-ଅସଙ୍ଗତ;
