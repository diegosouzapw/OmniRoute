OmniRoute ଏପରି ପ୍ରଦାନକାରୀଙ୍କ ସହ ସମନ୍ୱୟ କରେ, ଯାହାଙ୍କ ଏଜ୍ଗୁଡ଼ିକ ଅଣ-ଆଧିକାରିକ କ୍ଲାଏଣ୍ଟମାନଙ୍କୁ ସକ୍ରିୟ ଭାବେ ଫିଙ୍ଗରପ୍ରିଣ୍ଟ କରନ୍ତି (TLS JA3/JA4, ହେଡର୍ କ୍ରମ, JSON ବଡିର ଆକାର, ଅଖଣ୍ଡତା ଟୋକନ୍)। ଏହି ପୃଷ୍ଠାରେ OmniRoute ପ୍ରକାଶ କରୁଥିବା ଗୋପନୀୟତା ପୃଷ୍ଠଗୁଡ଼ିକ ଏବଂ ସେଗୁଡ଼ିକ କେଉଁଠାରେ ରୂପାୟିତ ହୋଇଛି ତାହା ଲିପିବଦ୍ଧ କରାଯାଇଛି।

## ଆଇନଗତ ଏବଂ ନୈତିକ ସୂଚନା

ଗୋପନୀୟତା ବୈଶିଷ୍ଟ୍ୟଗୁଡ଼ିକ ରହିଛି ଯାହାଦ୍ୱାରା OmniRoute ବ୍ୟବହାରକାରୀଙ୍କ ମାଲିକାନାରେ ଥିବା ଆଧିକାରିକ ଆକାଉଣ୍ଟଗୁଡ଼ିକ (Claude Code CLI, Codex, Antigravity, Cursor, ଇତ୍ୟାଦି) ଏବଂ OmniRouteର ଏକୀକୃତ API ମଧ୍ୟରେ ଏକ ସୁସଙ୍ଗତତା ସ୍ତର ଭାବେ କାର୍ଯ୍ୟ କରିପାରିବ। ସେଗୁଡ଼ିକ ଠକେଇ ଚିହ୍ନଟକୁ ଏଡ଼ାଇବା, ପ୍ରମାଣପତ୍ର ଅଂଶୀଦାର କରିବା କିମ୍ବା ପ୍ରଦାନକାରୀଙ୍କ ସେବା ସର୍ତ୍ତାବଳୀ ଉଲ୍ଲଂଘନ କରିବା ପାଇଁ **ନୁହେଁ**। ରକ୍ଷଣାବେକ୍ଷକମାନେ ଆଶା କରନ୍ତି ଯେ ଅପରେଟରମାନେ ଆକାଉଣ୍ଟ ସୃଷ୍ଟି କରିବା ସମୟରେ ସ୍ୱାକ୍ଷର କରିଥିବା ଅପଷ୍ଟ୍ରିମ୍ ToS ପାଳନ କରିବେ।

## TLS ଫିଙ୍ଗରପ୍ରିଣ୍ଟିଂ ସ୍ତର

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

ସ୍ଥାୟୀ `wreq-js` ସେସନ୍ଗୁଡ଼ିକ ପ୍ରତ୍ୟେକ ଆକାଉଣ୍ଟ ସ୍କୋପ୍ ଏବଂ ସମାଧାନ ହୋଇଥିବା ପ୍ରକ୍ସି ପାଇଁ ଆବଶ୍ୟକତା ଅନୁଯାୟୀ ସୃଷ୍ଟି କରାଯାଏ।
ପ୍ରକ୍ରିୟା-ବ୍ୟାପୀ `TlsClient`, Cloudflare ପଛରେ ଥିବା ଅପଷ୍ଟ୍ରିମ୍ଗୁଡ଼ିକ ପାଇଁ **macOSରେ Chrome 124** ଅନୁକରଣ କରୁଥିବା ସର୍ବାଧିକ 128ଟି ସେସନ୍ ପୁଲ୍ କରେ।
ନେଟିଭ୍ ରନ୍ଟାଇମ୍ ଉପଲବ୍ଧ ନଥିବାବେଳେ `TlsClient.fetch()` ବନ୍ଦ ଅବସ୍ଥାରେ ବିଫଳ ହୁଏ; ଏହି ରାପର୍ର ବାହାରେ ଜଣେ କଲର୍ ସ୍ପଷ୍ଟ ଭାବେ ଏକ ଫଲ୍ବ୍ୟାକ୍ ଚୟନ କରିପାରିବେ।

- ସେସନ୍ ପ୍ରୋଫାଇଲ୍: `browser: "chrome_124", os: "macos"`
- ପ୍ରକ୍ସି ସମାଧାନ (ପ୍ରାଥମିକତା): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (ଲୋଅର୍କେସ୍ ମଧ୍ୟ)
- ସମୟସୀମା: `TLS_CLIENT_TIMEOUT_MS` (`FETCH_TIMEOUT_MS`ରୁ ଉତ୍ତରାଧିକାରରେ ପ୍ରାପ୍ତ, ଡିଫଲ୍ଟ 600000)
- `wreq-js` Response, fetch-ସୁସଙ୍ଗତ (`headers`, `text()`, `json()`, `clone()`, `body`)।
- ପ୍ରଥମ-ବାଇଟ୍ ୱାଚ୍ଡଗ୍ (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656): ଅପଷ୍ଟ୍ରିମ୍ ହେଡର୍ଗୁଡ଼ିକ ପହଞ୍ଚିବା ମାତ୍ରେ `TlsClient.fetch()`
  ସମାଧାନ ହୋଇଯାଏ, ତେଣୁ କେବଳ `TLS_CLIENT_TIMEOUT_MS` କୌଣସି ପ୍ରଥମ ବାଇଟ୍ ନ ଦେଉଥିବା
  ବଡିକୁ ସୀମିତ କରିପାରିବ ନାହିଁ। `guardTlsFirstByte()`, ବଡିର ପ୍ରଥମ `read()`କୁ
  `TLS_FIRST_BYTE_WATCHDOG_MS` (ଡିଫଲ୍ଟ `10000`, `0` ଏହାକୁ ଅକ୍ଷମ କରେ) ବିପକ୍ଷରେ ରେସ୍ କରାଏ; ଏକ ସୁସ୍ଥ ବଡି
  ପ୍ରଭାବିତ ହୁଏ ନାହିଁ, ଯେତେବେଳେ ଏକ ଅଟକିଥିବା ବଡି wreq ରିଡର୍କୁ ବାତିଲ କରେ ଏବଂ `proxyFetch`ର ବିଦ୍ୟମାନ
  TLS-ଫଲ୍ବ୍ୟାକ୍ ତର୍କକୁ ସିଧାସଳଖ/ପ୍ରକ୍ସି ଡିସ୍ପାଚର୍କୁ ଯିବାକୁ ଦିଏ (ଏକ ଅଣ-ରିପ୍ଲେ-ନିରାପଦ ଅନୁରୋଧ, ଯଥା
  ବଡି ସହିତ ଏକ POST, ତଥାପି ନିରବରେ ପୁନଃଚେଷ୍ଟା ହେବା ପରିବର୍ତ୍ତେ ତ୍ରୁଟି ଫିଙ୍ଗେ)।

### ୱେବ୍-କୁକି ପ୍ରଦାନକାରୀ ପରିବହନ — wreq-js 3.2.0

`open-sse/services/tlsClientBase.ts` ନିମ୍ନରେ ଥିବା ପାଞ୍ଚଟି ବିଶେଷୀକୃତ
ୱେବ୍-କୁକି ପରିବହନ ପାଇଁ ଅଂଶୀଦାର ଆଡାପ୍ଟର୍। ପ୍ରତ୍ୟେକ ସାନ ପ୍ରଦାନକାରୀ ରାପର୍ ଗୋଟିଏ ବ୍ରାଉଜର୍/OS ପ୍ରୋଫାଇଲ୍ ଚୟନ କରେ। ଆଡାପ୍ଟର୍
`open-sse/utils/tlsClient.ts`ରେ ଥିବା ଏକକ wreq ରନ୍ଟାଇମ୍ ଲୋଡର୍ ଏବଂ ପରିବହନ ପୁଲ୍ ବ୍ୟବହାର କରେ, ଯାହା
ପ୍ରୋଫାଇଲ୍ + OS + ସମାଧାନ ହୋଇଥିବା ପ୍ରକ୍ସି ଦ୍ୱାରା କୀ ହୋଇଥାଏ, ଯେତେବେଳେ ପ୍ରତ୍ୟେକ ଅନୁରୋଧ `cookieMode: "ephemeral"` ବ୍ୟବହାର କରେ। ତେଣୁ ଆକାଉଣ୍ଟ ଏବଂ
ଅନୁରୋଧଗୁଡ଼ିକ ପରିବହନ-ସ୍ତରୀୟ ସଂଯୋଗଗୁଡ଼ିକୁ ଅଂଶୀଦାର କରନ୍ତି, କିନ୍ତୁ କେବେ ମଧ୍ୟ ଏକ wreq ସେସନ୍ କିମ୍ବା କୁକି ଜାର୍ ଅଂଶୀଦାର କରନ୍ତି ନାହିଁ।

  ପ୍ରଭାବିତ ପ୍ରୋଫାଇଲ୍/OS/ପ୍ରକ୍ସି ପରିବହନକୁ ଅବୈଧ ଏବଂ ବନ୍ଦ କରେ, ପରବର୍ତ୍ତୀ ଅନୁରୋଧ ଏହାକୁ ପୁନଃସୃଷ୍ଟି କରିବା ପୂର୍ବରୁ।
- ପ୍ରକ୍ସି ସମାଧାନ ପ୍ରାଥମିକତା ହେଉଛି ପ୍ରତି-କଲ୍ `proxyUrl` → ଅନୁରୋଧ-ସ୍କୋପ୍ ଆକାଉଣ୍ଟ/ଡ୍ୟାଶବୋର୍ଡ ପ୍ରସଙ୍ଗ →
  `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (ଲୋଅର୍କେସ୍ ପ୍ରକାରଗୁଡ଼ିକ ସହିତ)। ସମାଧାନ ତ୍ରୁଟିଗୁଡ଼ିକ ସିଧାସଳଖ ସଂଯୋଗ ଲିକ୍ କରିବା ପରିବର୍ତ୍ତେ
  ବନ୍ଦ ଅବସ୍ଥାରେ ବିଫଳ ହୁଅନ୍ତି। LMArena ଉଦ୍ଦେଶ୍ୟମୂଳକ ଭାବେ `arena.ai` ବିପକ୍ଷରେ ସମାଧାନ କରେ।
- `byteResponse`, UTF-8 ବିକୃତି ବିନା ଏକ କଣ୍ଟେଣ୍ଟ-ଟାଇପ୍ଯୁକ୍ତ `data:` URL ଫେରାଏ।
- ସମସ୍ତ 128ଟି ସୀମାବଦ୍ଧ ପ୍ରୋଫାଇଲ୍/OS/ପ୍ରକ୍ସି ସ୍ଲଟ୍ ସକ୍ରିୟ କିମ୍ବା ବନ୍ଦ ହେଉଥିବାବେଳେ ତ୍ରୁଟିଗୁଡ଼ିକ ହେଉଛି
  `TlsClientUnavailableError` (ପ୍ୟାକେଜ୍/ଆଡ୍ଅନ୍ ଅନୁପଲବ୍ଧ), `TlsClientHangError`
  (ଡେଡ୍ଲାଇନ୍ ଅତିକ୍ରମ କରିଛି), ଏବଂ `WreqTransportCapacityError` (ଅଂଶୀଦାର ସେସନ୍-କ୍ଷମତା ତ୍ରୁଟି କୋଡ୍)।

ଉପରୋକ୍ତ ସାଧାରଣ `TlsClient` ସ୍ଥାୟୀ ବ୍ରାଉଜର୍-ସମର୍ଥିତ କୁକି
ଅବସ୍ଥା ପାଇଁ ବିଶେଷୀକୃତ ହୋଇ ରହେ। ଉଭୟ ପଥ ଗୋଟିଏ କ୍ୟାଶ୍ ହୋଇଥିବା wreq ମଡ୍ୟୁଲ୍ ଲୋଡର୍ ଏବଂ ପ୍ରକ୍ରିୟା ଜୀବନଚକ୍ର ହୁକ୍ ପୁନଃବ୍ୟବହାର କରନ୍ତି; ସେମାନଙ୍କ ପୁଲ୍ଗୁଡ଼ିକ
ପୃଥକ ରହେ କାରଣ ସେମାନଙ୍କର କୁକି ଜୀବନକାଳ ଉଦ୍ଦେଶ୍ୟମୂଳକ ଭାବେ ଭିନ୍ନ।

ପିନ୍ କରାଯାଇଥିବା ପ୍ୟାକେଜ୍ ଦ୍ୱାରା ପ୍ରୋଫାଇଲ୍ଗୁଡ଼ିକ ସମର୍ଥିତ, କିନ୍ତୁ ବାସ୍ତବ WAF ଗ୍ରହଣୀୟତା ସ୍ଥାନୀୟ ଚୁକ୍ତି ପରୀକ୍ଷାଠାରୁ ସ୍ୱାଧୀନ ଭାବେ
ପରିବର୍ତ୍ତିତ ହୋଇପାରେ। ଏକ ଅପଷ୍ଟ୍ରିମ୍ ବ୍ରାଉଜର୍ ସହ ସମତୁଲ୍ୟତା ଦାବି କରିବା ପୂର୍ବରୁ ସ୍ପଷ୍ଟ ଭାବେ ଅନୁମୋଦିତ ଲାଇଭ୍ ଆକାଉଣ୍ଟ ବିପକ୍ଷରେ
ଫିଙ୍ଗରପ୍ରିଣ୍ଟ ପରିବର୍ତ୍ତନଗୁଡ଼ିକୁ ବୈଧ କରନ୍ତୁ।

## Claude Code ଷ୍ଟେଲ୍ଥ ବଣ୍ଡଲ୍

`cliCompatMode` ସକ୍ରିୟ ଥିବାବେଳେ, OmniRoute ବାହାରକୁ ଯାଉଥିବା Claude ଅନୁରୋଧଗୁଡ଼ିକୁ ଏପରି ପୁନର୍ଗଠିତ କରେ ଯେ ସେଗୁଡ଼ିକୁ `claude-cli` ଟ୍ରାଫିକ୍ଠାରୁ ପୃଥକ କରିହେବ ନାହିଁ। ତିନୋଟି ମଡ୍ୟୁଲ୍ ମିଳିତ ଭାବେ କାମ କରନ୍ତି:

### `claudeCodeFingerprint.ts`

ବିଲିଂ ହେଡର୍ରେ ଏମ୍ବେଡ୍ ହୋଇଥିବା 3-ଅକ୍ଷରର `cc_version` ଫିଙ୍ଗରପ୍ରିଣ୍ଟ ଗଣନା କରେ:

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (ହାର୍ଡକୋଡ୍ କରାଯାଇଛି; ଆଧିକାରିକ କ୍ଲାଏଣ୍ଟ ସହ ମେଳ ଖାଏ)
- ଇନ୍ପୁଟ୍: ପ୍ରଥମ ବ୍ୟବହାରକାରୀ ସନ୍ଦେଶ ଟେକ୍ସଟ୍ର ଇଣ୍ଡେକ୍ସ 4, 7, 20 ରେ ଥିବା ଅକ୍ଷରଗୁଡ଼ିକ + ଭର୍ସନ୍ ଷ୍ଟ୍ରିଙ୍ଗ୍
- ଆଉଟ୍ପୁଟ୍: 3-ଅକ୍ଷରର ହେକ୍ସ ପ୍ରିଫିକ୍ସ

### `claudeCodeCCH.ts` (କ୍ଲାଏଣ୍ଟ କଣ୍ଟେଣ୍ଟ ହ୍ୟାଶ୍)

ଆଧିକାରିକ Claude Code CLI, Bun/Zig ମାଧ୍ୟମରେ ଗଣନା କରୁଥିବା ସର୍ଭର୍-ସାଇଡ୍ ଇଣ୍ଟେଗ୍ରିଟି ଯାଞ୍ଚ। OmniRoute ଏହାକୁ `xxhash-wasm` ସହ ପୁନଃକାର୍ଯ୍ୟକାରୀ କରେ:

1. `cch=00000;` ପ୍ଲେସ୍ହୋଲ୍ଡର୍ ସହ ବଡିକୁ ସିରିଆଲାଇଜ୍ କରନ୍ତୁ
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. ଶୂନ୍ୟ ସହ ପ୍ୟାଡ୍ କରାଯାଇଥିବା 5-ଅକ୍ଷରର ଲୋୟର୍କେସ୍ ହେକ୍ସ
4. `cch=00000;`କୁ ଗଣନା କରାଯାଇଥିବା ଟୋକନ୍ ସହ ବଦଳାନ୍ତୁ

କନ୍ଷ୍ଟାଣ୍ଟଗୁଡ଼ିକ:

- ସିଡ୍: `0x6e52736ac806831e`
- ପ୍ୟାଟର୍ନ୍: `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

ଅପ୍ଷ୍ଟ୍ରିମ୍ ଫିଲ୍ଟର୍ଗୁଡ଼ିକ ଯେପରି ସେଗୁଡ଼ିକୁ grep କରିପାରିବେ ନାହିଁ, ସେଥିପାଇଁ "ସମ୍ବେଦନଶୀଳ" କ୍ଲାଏଣ୍ଟ ନାମଗୁଡ଼ିକର ପ୍ରଥମ ଅକ୍ଷର ପରେ ଏକ Unicode **ଶୂନ୍ୟ-ପ୍ରସ୍ଥ ଯୋଗକାରୀ** (`U+200D`) ସନ୍ନିବେଶ କରେ। ଡିଫଲ୍ଟ ଶବ୍ଦ ତାଲିକା:

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

ଏଗୁଡ଼ିକରେ ପ୍ରୟୋଗ କରାଯାଏ: `system` ବ୍ଲକ୍ଗୁଡ଼ିକ, ସମସ୍ତ `messages[].content`, ଏବଂ `tools[].description` / `tools[].function.description`। `setSensitiveWords()` ମାଧ୍ୟମରେ ଅପରେଟର୍ ଏହାକୁ ଓଭର୍ରାଇଡ୍ କରିପାରିବେ।

### `claudeCodeCompatible.ts` — `anthropic-compatible-cc-*` ପ୍ରଦାତା

କେବଳ "ପ୍ରକୃତ Claude Code" ଟ୍ରାଫିକ୍ ଗ୍ରହଣ କରୁଥିବା ତୃତୀୟ-ପକ୍ଷ Anthropic ରିଲେଗୁଡ଼ିକ ପାଇଁ:

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.258 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- ଡିଫଲ୍ଟ ଭାବେ `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"`
- ପ୍ରତି-ସଂଯୋଗ "Enable redact-thinking beta" ଟୋଗଲ୍, କୌଣସି CC Compatible ଅପ୍ଷ୍ଟ୍ରିମ୍କୁ ବିଶେଷ ଭାବରେ ରିଡାକ୍ଟ କରାଯାଇଥିବା ଥିଙ୍କିଂ ଷ୍ଟ୍ରିମ୍ ଆବଶ୍ୟକ ହେଲେ, `redact-thinking-2026-02-12` ଯୋଡ଼ିଥାଏ
- ପ୍ରତି-ସଂଯୋଗ "Enable summarized thinking display" ଟୋଗଲ୍ `providerSpecificData.requestDefaults.summarizeThinking` ସଂରକ୍ଷଣ କରେ ଏବଂ ପୂର୍ବରୁ କୌଣସି ଡିସ୍ପ୍ଲେ ମୋଡ୍ ସେଟ୍ କରିନଥିବା CC Compatible ଥିଙ୍କିଂ ଅନୁରୋଧଗୁଡ଼ିକରେ `display: "summarized"` ଯୋଡ଼େ
- `CONTEXT_1M_BETA_HEADER = "context-1m-2025-08-07"` (Opus/Sonnet 4.x ପରିବାର)
- ଡିଫଲ୍ଟ ପାଥ୍: `/v1/messages?beta=true`

ସମାନ ବଣ୍ଡଲ୍ରେ ଥିବା ସହଯୋଗୀ ମଡ୍ୟୁଲ୍ଗୁଡ଼ିକ:

- `claudeCodeConstraints.ts` — ଟେମ୍ପରେଚର୍ + କ୍ୟାଶ୍-କଣ୍ଟ୍ରୋଲ୍ ନିୟମ
- `claudeCodeToolRemapper.ts` — ଟୁଲ୍-ନାମ ରିମ୍ୟାପିଂ
- `claudeCodeExtraRemap.ts` — ଅତିରିକ୍ତ ପେଲୋଡ୍ ନର୍ମାଲାଇଜେସନ୍

## Antigravity ଷ୍ଟେଲ୍ଥ

Antigravity ଅନୁରୋଧଗୁଡ଼ିକ କଲର୍ର ଟେକ୍ସଟ୍କୁ ବାଇଟ୍-ପ୍ରତି-ବାଇଟ୍ ଅପରିବର୍ତ୍ତିତ ରଖନ୍ତି। OmniRoute ପ୍ରମ୍ପ୍ଟଗୁଡ଼ିକରେ ଶୂନ୍ୟ-ପ୍ରସ୍ଥ ଅକ୍ଷର ସନ୍ନିବେଶ କରେ ନାହିଁ କିମ୍ବା କୌଣସି IDE କ୍ଲାଏଣ୍ଟକୁ ଅନୁକରଣ କରିବା ପାଇଁ ଟୁଲ୍ଗୁଡ଼ିକର ନାମ ବଦଳାଏ/ସନ୍ନିବେଶ କରେ ନାହିଁ।

### `antigravityHeaderScrub.ts`

ଫର୍ୱାର୍ଡ କରିବା ପୂର୍ବରୁ Stainless SDK ମାର୍କର୍ଗୁଡ଼ିକ (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`) ଅପସାରଣ କରେ।

### ⚠️ ବିପଦ: `ANTIGRAVITY_CREDITS=always` (ଆକାଉଣ୍ଟ ବ୍ୟାନ୍ର ହଟ୍ ସ୍ପଟ୍)

`ANTIGRAVITY_CREDITS=always` (`open-sse/executors/antigravity.ts` ଦ୍ୱାରା ବ୍ୟବହୃତ) Googleର ଫ୍ରି-ଟିୟର୍ କୋଟାକୁ ଅନୁରୋଧଗୁଡ଼ିକ ନିୟନ୍ତ୍ରଣ କରିବାକୁ ଦେବା ପରିବର୍ତ୍ତେ **ପ୍ରତ୍ୟେକ** ଅନୁରୋଧକୁ Antigravity AI Credit Overages (ପେଡ୍ Google କ୍ରେଡିଟ୍) ମାଧ୍ୟମରେ ରାଉଟ୍ କରେ। ଏହାକୁ ଏକ ବୈଶିଷ୍ଟ୍ୟ ଭାବେ ଡକ୍ୟୁମେଣ୍ଟ କରାଯାଇଛି, କିନ୍ତୁ ଏହା **ଆମେ ଦେଖୁଥିବା ସବୁଠାରୁ ସାଧାରଣ ToS-ଉଲ୍ଲଂଘନ ରିପୋର୍ଟ** — `=always` ସହ କିଛି ଘଣ୍ଟା ଚାଲିବା ପରେ ଏକାଧିକ Google Ultra ଆକାଉଣ୍ଟ `403 / "service disabled for ToS violation" / insufficient_quota` ସହ ବ୍ୟାନ୍ ହୋଇଛି।

ଅପ୍ଷ୍ଟ୍ରିମ୍ ପ୍ରବର୍ତ୍ତନ **Google ପକ୍ଷରେ** ହୁଏ, OmniRoute ଏହାକୁ ପ୍ରତିରୋଧ କରିପାରିବ ନାହିଁ। env var ନାମ ଏବଂ ବର୍ତ୍ତମାନର ଡକ୍ୟୁମେଣ୍ଟଗୁଡ଼ିକ ଏହାକୁ ସକ୍ରିୟ କରିବା ଏକ ସୁରକ୍ଷିତ ବିକଳ୍ପ ବୋଲି ଶୁଣାଏ; କିନ୍ତୁ ଏହା ସୁରକ୍ଷିତ ନୁହେଁ।

**ଏହା କାହିଁକି କେବଳ ଫ୍ରି-ଟିୟର୍ ବ୍ୟବହାର ତୁଳନାରେ ଅଧିକ ଆକ୍ରମକ ଭାବରେ ଅପବ୍ୟବହାର ଚିହ୍ନଟକୁ ଆକର୍ଷିତ କରେ:**

- ଗୋଟିଏ Google ଆକାଉଣ୍ଟରେ ନିରନ୍ତର ସ୍ୱୟଂଚାଳିତ ଖର୍ଚ୍ଚ, ଫ୍ରି-ଟିୟର୍ରେ କୋଟା ପୂର୍ଣ୍ଣ ହୋଇ ଅଟକିଯିବା ତୁଳନାରେ ଭିନ୍ନ ଭାବରେ ଫ୍ଲାଗ୍ ହୁଏ।
- କ୍ରେଡିଟ୍ ଓଭରେଜ୍ର କୌଣସି ରେଟ୍ ସୀମା ନାହିଁ, ତେଣୁ ଭୁଲ୍ ଭାବରେ କନ୍ଫିଗର୍ ହୋଇଥିବା କ୍ଲାଏଣ୍ଟ କିଛି ମିନିଟ୍ରେ ଅନେକ ଶହ USD ଖର୍ଚ୍ଚ କରିପାରେ ଏବଂ API-କୀ ପୁନଃବିକ୍ରୟ କିମ୍ବା ବଟ୍ ଟ୍ରାଫିକ୍ ଭଳି ଦେଖାଯାଇପାରେ।
- ଗୋଟିଏ ବାହ୍ୟ IPରୁ ସମାନ୍ତରାଳ ଭାବେ ଏକାଧିକ OmniRoute ବ୍ୟବହାରକାରୀଙ୍କ ଓଭରେଜ୍ କ୍ରେଡିଟ୍ ବ୍ୟବହାର କରିବା ସଙ୍କେତକୁ ଅଧିକ ଶକ୍ତିଶାଳୀ କରେ।

**ସୁପାରିସ କରାଯାଇଥିବା ଆଭିମୁଖ୍ୟ:**

1. ଅପରେଟର୍ ସ୍ପଷ୍ଟ ଭାବରେ ପେଡ୍-କ୍ରେଡିଟ୍ ଏବଂ ଆକାଉଣ୍ଟ-ପ୍ରବର୍ତ୍ତନ ବିପଦ ସ୍ୱୀକାର ନକରିବା ପର୍ଯ୍ୟନ୍ତ ଡିଫଲ୍ଟ `ANTIGRAVITY_CREDITS=off` ରଖନ୍ତୁ। `retry` ପ୍ରଥମେ ସାଧାରଣ ଅନୁରୋଧ ପଠାଏ ଏବଂ ଯୋଗ୍ୟ କୋଟା 429 ପରେ ସର୍ବାଧିକ ଥରେ କ୍ରେଡିଟ୍ ସନ୍ନିବେଶ କରେ; `always` ପ୍ରଥମ ଅନୁରୋଧରେ କ୍ରେଡିଟ୍ ସନ୍ନିବେଶ କରେ।
2. ଗୋଟିଏ Antigravity ଆକାଉଣ୍ଟକୁ ସମ୍ପୂର୍ଣ୍ଣ କ୍ଷମତାରେ ବ୍ୟବହାର କରିବା ପରିବର୍ତ୍ତେ **Auto-Combo ମାଧ୍ୟମରେ ପ୍ରଦାତାମାନଙ୍କ ମଧ୍ୟରେ ଲୋଡ୍ ବିତରଣ କରନ୍ତୁ** (`model: "auto"` କିମ୍ବା `kr/glm/etc`-combo)।
3. Antigravity ପ୍ରଦାତାର ସମ୍ପାଦନା ପୃଷ୍ଠାରେ **ପ୍ରତି-ସଂଯୋଗ RPM ସୀମା ସେଟ୍ କରନ୍ତୁ** (Dashboard → Providers → Antigravity → ସଂଯୋଗ → ରେଟ୍ ସୀମା)। ନିରନ୍ତର ବ୍ୟବହାର ପାଇଁ 30–60 RPM ଏକ ଯୁକ୍ତିସଙ୍ଗତ ଉପର ସୀମା।
4. **ସ୍ଥିର, ଅପରେଟର୍-ନିୟନ୍ତ୍ରିତ ଅପ୍ଷ୍ଟ୍ରିମ୍ ନେଟ୍ୱର୍କିଂ ବ୍ୟବହାର କରନ୍ତୁ** ଏବଂ ଅସମ୍ପର୍କିତ ବ୍ୟବହାରକାରୀ କିମ୍ବା ୱର୍କଲୋଡ୍ଗୁଡ଼ିକ ମଧ୍ୟରେ ଗୋଟିଏ ଆକାଉଣ୍ଟ ସେୟାର୍ କରିବା ଏଡ଼ାନ୍ତୁ।
5. **ବ୍ୟାନ୍ ହେଲେ**: Google ପଠାଇଥିବା ସଠିକ୍ `quota_exceeded` / `service disabled` ପ୍ରତିକ୍ରିୟା ବଡି ସହ `support.google.com` → "Restore Workspace/Account access" ମାଧ୍ୟମରେ ଅପିଲ୍ କରନ୍ତୁ। ପୁନରୁଦ୍ଧାର ନିଶ୍ଚିତ ନୁହେଁ।

ପରିବେଶ ସନ୍ଦର୍ଭ ପ୍ରତ୍ୟେକ କ୍ରେଡିଟ୍ ମୋଡ୍ର ଆକାଉଣ୍ଟ ଏବଂ ଖର୍ଚ୍ଚ ସମ୍ବନ୍ଧୀୟ ପ୍ରଭାବଗୁଡ଼ିକୁ ଡକ୍ୟୁମେଣ୍ଟ କରେ।

ସ୍ପର୍ଶ ବିନ୍ଦୁଗୁଡ଼ିକ:

- `open-sse/executors/antigravity.ts` — `process.env.ANTIGRAVITY_CREDITS` ପଢ଼େ

## CLI ଫିଙ୍ଗରପ୍ରିଣ୍ଟ ରେଜିଷ୍ଟ୍ରି — `open-sse/config/cliFingerprints.ts`

ପ୍ରତ୍ୟେକ ପ୍ରଦାନକାରୀ ପାଇଁ ଥିବା ସାରଣୀ, ଯାହା ଅଫିସିଆଲ୍ CLI-ଗୁଡ଼ିକର mitmproxy ଟ୍ରେସ୍ରୁ ଧରାଯାଇଥିବା **ସଠିକ୍** ହେଡର୍ କ୍ରମ ଏବଂ JSON ବଡି ଫିଲ୍ଡ କ୍ରମକୁ ସ୍ଥିର କରେ। ବର୍ତ୍ତମାନ ପଞ୍ଜୀକୃତ: `codex`, `claude`, ଏବଂ `antigravity` ଓ `github` ପାଇଁ `providerHeaderProfiles.ts` ଭିତରେ ଥିବା ରନ୍ଟାଇମ୍ରୁ ନିର୍ଦ୍ଧାରିତ ପ୍ରୋଫାଇଲ୍ଗୁଡ଼ିକ।

```ts
interface CliFingerprint {
  headerOrder: string[]; // ଅକ୍ଷରର କେସ୍ ପ୍ରତି ସମ୍ବେଦନଶୀଳ
  bodyFieldOrder: string[]; // ଶୀର୍ଷ-ସ୍ତରୀୟ JSON କୀଗୁଡ଼ିକ
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

ପ୍ରତ୍ୟେକ ପ୍ରଦାନକାରୀ ପାଇଁ env ମାଧ୍ୟମରେ ଟୋଗଲ୍ କରନ୍ତୁ (ନିମ୍ନରେ ଦେଖନ୍ତୁ)। ଅକ୍ଷମ ଥିବାବେଳେ, ହେଡର୍/ବଡି କୀଗୁଡ଼ିକ Node/JSON ଦ୍ୱାରା ପ୍ରଦତ୍ତ ଯେକୌଣସି କ୍ରମରେ ଦେଖାଯାଆନ୍ତି — ଫିଙ୍ଗରପ୍ରିଣ୍ଟ କରିବା ସହଜ।

## MITM ପ୍ରକ୍ସି (Antigravity, Linux/macOS/Windows)

ଯେଉଁ CLI-ଗୁଡ଼ିକର ବାଇନାରିକୁ `OPENAI_BASE_URL` ମାଧ୍ୟମରେ ପୁନଃନିର୍ଦ୍ଦେଶିତ କରାଯାଇପାରେ ନାହିଁ, ସେଗୁଡ଼ିକ ପାଇଁ OmniRoute ଏକ ସ୍ଥାନୀୟ TLS-ଟର୍ମିନେଟିଂ ପ୍ରକ୍ସି ଚଲାଏ। ଏଣ୍ଡପଏଣ୍ଟଗୁଡ଼ିକ `src/app/api/cli-tools/antigravity-mitm/` ଅଧୀନରେ ରହିଛି।

| ପଦ୍ଧତି | ଏଣ୍ଡପଏଣ୍ଟ                               | ଉଦ୍ଦେଶ୍ୟ                                                 |
| ------ | --------------------------------------- | -------------------------------------------------------- |
| GET    | `/api/cli-tools/antigravity-mitm`       | ସ୍ଥିତି — ଚାଲୁଛି କି ନାହିଁ, pid, dnsConfigured, certExists |
| POST   | `/api/cli-tools/antigravity-mitm`       | MITM ଆରମ୍ଭ କରନ୍ତୁ (`apiKey` + `sudoPassword` ଆବଶ୍ୟକ)     |
| DELETE | `/api/cli-tools/antigravity-mitm`       | MITM ବନ୍ଦ କରନ୍ତୁ                                         |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | ମଡେଲ୍ ଉପନାମଗୁଡ଼ିକର ତାଲିକା ଦେଖାନ୍ତୁ                       |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | ଏକ ଟୁଲ୍ ପାଇଁ ମଡେଲ୍ ଉପନାମଗୁଡ଼ିକ ସଞ୍ଚୟ କରନ୍ତୁ              |

ଅବରୋଧ କରାଯାଉଥିବା ଲକ୍ଷ୍ୟ ହୋଷ୍ଟ: **`daily-cloudcode-pa.googleapis.com`** (Antigravity-ର ଅପ୍ଷ୍ଟ୍ରିମ୍)।

### ଆରମ୍ଭ କ୍ରମ (`src/mitm/manager.ts::startMitm`)

1. `selfsigned` ମାଧ୍ୟମରେ ସ୍ୱୟଂ-ସ୍ୱାକ୍ଷରିତ ସାର୍ଟିଫିକେଟ୍ ସୃଷ୍ଟି କରନ୍ତୁ (RSA-2048, SHA-256, 1y) — `cert/generate.ts`
2. ସିଷ୍ଟମ୍ ଟ୍ରଷ୍ଟ ଷ୍ଟୋର୍ରେ ସାର୍ଟିଫିକେଟ୍ ସଂସ୍ଥାପନ କରନ୍ତୁ — `cert/install.ts`
3. ହୋଷ୍ଟ ଏଣ୍ଟ୍ରି `127.0.0.1 daily-cloudcode-pa.googleapis.com` ଯୋଡ଼ନ୍ତୁ — `dns/dnsConfig.ts`
4. `ROUTER_API_KEY` + `MITM_LOCAL_PORT` (ଡିଫଲ୍ଟ `443`) ସହିତ `src/mitm/server.cjs` ସ୍ପନ୍ କରନ୍ତୁ
5. PID-କୁ `<DATA_DIR>/mitm/.mitm.pid` ରେ ସ୍ଥାୟୀ ଭାବେ ସଞ୍ଚୟ କରନ୍ତୁ

### Linux ଡାଇନାମିକ୍ ଟ୍ରଷ୍ଟ-ଷ୍ଟୋର୍ ଚିହ୍ନଟ — `cert/install.ts`

`getLinuxCertConfig()` ଏକ ପ୍ରାଥମିକତା ତାଲିକାକୁ କ୍ରମାନୁସାରେ ଯାଞ୍ଚ କରେ ଏବଂ ପ୍ରଥମେ ମିଳୁଥିବା ଡିରେକ୍ଟୋରୀକୁ ବାଛେ:

| ଡିଷ୍ଟ୍ରୋ ପରିବାର          | ଡିରେକ୍ଟୋରୀ                                  | ଅପଡେଟ୍ କମାଣ୍ଡ            |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

ସାର୍ଟିଫିକେଟ୍ ଫାଇଲ୍ ନାମ: `omniroute-mitm.crt`। `getCertFingerprint()` ମାଧ୍ୟମରେ ଫିଙ୍ଗରପ୍ରିଣ୍ଟ ମେଳକରଣ (DER-ର SHA-1)।

ଏହା ସହିତ, `certutil` ଉପଲବ୍ଧ ଥିଲେ `updateNssDatabases()` ପ୍ରତ୍ୟେକ ବ୍ୟବହାରକାରୀଙ୍କ NSS DB-ଗୁଡ଼ିକରେ ସଂସ୍ଥାପନ କରେ: `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, ସମସ୍ତ Firefox ପ୍ରୋଫାଇଲ୍ (snap ସମେତ), **`OmniRoute MITM Root CA`** ଉପନାମ ଅଧୀନରେ।

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** ଉନ୍ନତ ଅଧିକାରପ୍ରାପ୍ତ PowerShell → `certutil -addstore Root`

### ପ୍ରମାଣୀକରଣ

ସମସ୍ତ MITM ଏଣ୍ଡପଏଣ୍ଟ ପାଇଁ ପରିଚାଳନା ପ୍ରମାଣୀକରଣ (`requireCliToolsAuth`) ଆବଶ୍ୟକ। sudo ପାସ୍ୱାର୍ଡକୁ ମଡ୍ୟୁଲ୍ ସ୍କୋପ୍ରେ କ୍ୟାଶ୍ କରାଯାଏ (`globalThis` ରେ କେବେ ନୁହେଁ) ଏବଂ `stopMitm()` ସମୟରେ ସଫା କରାଯାଏ।

## ଇନ୍ବାଉଣ୍ଡ୍ ହେଡର୍ ସାନିଟାଇଜେସନ୍

OmniRoute ଫରୱାର୍ଡ କରିବା ପୂର୍ବରୁ ଇନ୍ବାଉଣ୍ଡ୍ କ୍ଲାଏଣ୍ଟ ହେଡର୍ଗୁଡ଼ିକୁ ପରିଷ୍କାର କରେ, ଯାହାଦ୍ୱାରା Cursor ରୁ ଆସୁଥିବା ଅନୁରୋଧ ଏକ Claude ଅପ୍ଷ୍ଟ୍ରିମ୍କୁ `User-Agent: Cursor/X.Y.Z` ଲିକ୍ କରେ ନାହିଁ। Zod ସ୍କିମା ଏବଂ ୟୁନିଟ୍ ପରୀକ୍ଷାଗୁଡ଼ିକ ସହିତ ସମନ୍ୱୟରେ ରଖାଯାଇଥିବା ଡିନାଇଲିଷ୍ଟ ପାଇଁ `src/shared/constants/upstreamHeaders.ts` ଦେଖନ୍ତୁ।

## ଜଣେ ପ୍ରଦାନକାରୀ ପରିବର୍ତ୍ତନ କଲେ ଫିଙ୍ଗରପ୍ରିଣ୍ଟ୍ଗୁଡ଼ିକୁ ଅପଡେଟ୍ କରିବା

1. `mitmproxy` ବ୍ୟବହାର କରି ଆଧିକାରିକ CLI ଟ୍ରାଫିକ୍ କ୍ୟାପ୍ଚର୍ କରନ୍ତୁ (TLS ଇଣ୍ଟରସେପ୍ସନ୍ + ଡମ୍ପ)
2. JA3/JA4 ଏବଂ ହେଡର୍ଗୁଡ଼ିକର ଯଥାର୍ଥ କ୍ରମ ବାହାର କରନ୍ତୁ
3. ସମ୍ପୃକ୍ତ `CLI_FINGERPRINTS[...]` ଏଣ୍ଟ୍ରିକୁ ଅପଡେଟ୍ କରନ୍ତୁ
4. `.env.example` ରେ ମେଳ ଖାଉଥିବା `*_USER_AGENT` ଡିଫଲ୍ଟକୁ ଅପଡେଟ୍ କରନ୍ତୁ
5. ଯଦି TLS ହ୍ୟାଣ୍ଡ୍ଶେକ୍ ନିଜେ ବଦଳିଛି, ତେବେ ସମ୍ପୃକ୍ତ ପ୍ରଦାନକାରୀ ରାପର୍ କିମ୍ବା wreq-js `browser:` ବିକଳ୍ପକୁ ଅପଡେଟ୍ କରନ୍ତୁ
6. ପ୍ରଦାନକାରୀ-ନିର୍ଦ୍ଦିଷ୍ଟ TLS ପରୀକ୍ଷାଗୁଡ଼ିକ ଏବଂ ଲାଇଭ୍ ପ୍ରଦାନକାରୀ ବିପକ୍ଷରେ ଏକ ମାନୁଆଲ୍ କ୍ୟାନେରି ଚଲାନ୍ତୁ
7. ଏକ ପ୍ୟାଚ୍ ରିଲିଜ୍ରେ ପ୍ରକାଶ କରନ୍ତୁ; `CHANGELOG.md` ରେ ଦଲିଲୀକରଣ କରନ୍ତୁ
