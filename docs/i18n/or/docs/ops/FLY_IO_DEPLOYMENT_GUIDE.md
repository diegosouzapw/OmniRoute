ଏହି ଡକ୍ୟୁମେଣ୍ଟ୍ରେ Fly.io ଉପରେ OmniRoute ପାଇଁ ପ୍ରକୃତ ଡିପ୍ଲୟମେଣ୍ଟ ପ୍ରକ୍ରିୟା ବର୍ଣ୍ଣନା କରାଯାଇଛି, ଯେଉଁଥିରେ ଦୁଇଟି ପରିସ୍ଥିତି ଅନ୍ତର୍ଭୁକ୍ତ:

- ବର୍ତ୍ତମାନର ପ୍ରୋଜେକ୍ଟକୁ ପ୍ରଥମ ଥର ପାଇଁ Fly.io ରେ ଡିପ୍ଲୟ କରିବା
- ପରବର୍ତ୍ତୀ କୋଡ୍ ଅପଡେଟ୍ଗୁଡ଼ିକୁ ପ୍ରକାଶ କରିବା
- ସମାନ ଡିପ୍ଲୟମେଣ୍ଟ କାର୍ଯ୍ୟପ୍ରବାହ ଅନୁସରଣ କରୁଥିବା ନୂତନ ପ୍ରୋଜେକ୍ଟଗୁଡ଼ିକ

ଏହି ମାର୍ଗଦର୍ଶିକା ବର୍ତ୍ତମାନର ପ୍ରୋଜେକ୍ଟ ପାଇଁ ଯାଞ୍ଚ କରାଯାଇଥିବା ଏକ କାର୍ଯ୍ୟକ୍ଷମ କନଫିଗରେସନ୍ ଉପରେ ଆଧାରିତ। ଆପ୍ଲିକେସନ୍ର ନାମ ହେଉଛି `omniroute`।

## 1. ନିୟୋଜନ ଲକ୍ଷ୍ୟଗୁଡ଼ିକ

- ପ୍ଲାଟଫର୍ମ: Fly.io
- ନିୟୋଜନ ପଦ୍ଧତି: ସ୍ଥାନୀୟ `flyctl` ସିଧାସଳଖ ପ୍ରକାଶନ
- ରନ୍ଟାଇମ୍: ରିପୋଜିଟୋରୀରେ ଥିବା ବିଦ୍ୟମାନ `Dockerfile` ଏବଂ `fly.toml` ବ୍ୟବହାର କରି
- ଡାଟା ସ୍ଥାୟୀତା: Fly Volume `/data` ରେ ମାଉଣ୍ଟ ହୋଇଛି
- ଆକ୍ସେସ୍ URL: `https://omniroute.fly.dev/`

## 2. ବର୍ତ୍ତମାନର ପ୍ରୋଜେକ୍ଟର ମୁଖ୍ୟ ବିନ୍ୟାସ

ବର୍ତ୍ତମାନର ରିପୋଜିଟୋରୀରେ ଥିବା `fly.toml` ରେ ନିମ୍ନଲିଖିତ ମୁଖ୍ୟ ବିଷୟଗୁଡ଼ିକ ଅଛି ବୋଲି ନିଶ୍ଚିତ କରାଯାଇଛି:

```toml
app = 'omniroute'
primary_region = 'sin'

[[mounts]]
  source = 'data'
  destination = '/data'

[processes]
  app = 'node run-standalone.mjs'

[http_service]
  internal_port = 20128

[env]
  TZ = "Asia/Shanghai"
  HOST = "0.0.0.0"
  HOSTNAME = "0.0.0.0"
  BIND = "0.0.0.0"
```

ନୋଟ୍:

- `app = 'omniroute'` ନିର୍ଦ୍ଧାରଣ କରେ ଯେ ନିୟୋଜନ କେଉଁ Fly ଆପ୍ଲିକେସନ୍ କୁ ଟାର୍ଗେଟ କରେ
- `destination = '/data'` ସ୍ଥାୟୀ ଭଲ୍ୟୁମ୍ ମାଉଣ୍ଟ ଡିରେକ୍ଟୋରୀ ନିର୍ଦ୍ଧାରଣ କରେ
- ଏହି ପ୍ରୋଜେକ୍ଟରେ ନିଶ୍ଚିତ ଭାବରେ `DATA_DIR=/data` ସେଟ୍ କରିବା ଆବଶ୍ୟକ, ଅନ୍ୟଥା ଡାଟାବେସ୍ ଏବଂ କି ଗୁଡ଼ିକ କଣ୍ଟେନରର ଅସ୍ଥାୟୀ ଡିରେକ୍ଟୋରୀରେ ଲେଖାଯିବ

## 3. ପୂର୍ବାବଶ୍ୟକତା

### 3.1 Fly CLI ସଂସ୍ଥାପନ କରିବା

Windows PowerShell:

```powershell
pwsh -Command "iwr https://fly.io/install.ps1 -useb | iex"
```

ଯଦି ଆପଣଙ୍କ ପରିବେଶରେ ଇନଷ୍ଟଲ ସ୍କ୍ରିପ୍ଟ ବିଫଳ ହୁଏ, ଆପଣ ମାନୁଆଲି `flyctl` ବାଇନାରୀ ଡାଉନଲୋଡ୍ କରି ଆପଣଙ୍କ `PATH` ରେ ଯୋଡ଼ିପାରିବେ।

### 3.2 ଆପଣଙ୍କ Fly ଆକାଉଣ୍ଟରେ ଲଗ୍ ଇନ୍ କରିବା

```powershell
flyctl auth login
```

### 3.3 ଲଗ୍ ଇନ୍ ସ୍ଥିତି ଯାଞ୍ଚ କରିବା

```powershell
flyctl auth whoami
flyctl version
```

## 4. ବର୍ତ୍ତମାନର ପ୍ରୋଜେକ୍ଟର ପ୍ରଥମ ଥର ନିୟୋଜନ

### 4.1 କୋଡ୍ କ୍ଲୋନ୍ କରି ଡିରେକ୍ଟୋରୀରେ ପ୍ରବେଶ କରନ୍ତୁ

```powershell
git clone https://github.com/diegosouzapw/OmniRoute.git
cd OmniRoute
```

### 4.2 ଆପ୍ଲିକେସନ୍ ନାମ ନିଶ୍ଚିତ କରନ୍ତୁ

`fly.toml` ଖୋଲି ନିମ୍ନଲିଖିତ ଧାଡ଼ି ଯାଞ୍ଚ କରନ୍ତୁ:

```toml
app = 'omniroute'
```

ଯଦି ଆପଣ ନିଜର ନୂତନ ଆପ୍ଲିକେସନ୍ ରେ ନିୟୋଜନ କରୁଛନ୍ତି, ଆପଣ ଏହାକୁ ଏକ ବିଶ୍ୱସ୍ତରୀୟ ଅନନ୍ୟ ନାମରେ ପରିବର୍ତ୍ତନ କରିପାରିବେ, ଉଦାହରଣ ସ୍ୱରୂପ:

```toml
app = 'omniroute-yourname'
```

ନୋଟ୍:

- ନିଶ୍ଚିତ କରନ୍ତୁ ଯେ କନସୋଲରେ ଦେଖାଯାଉଥିବା ଆପ୍ଲିକେସନ୍ `fly.toml` ର `app` ମୂଲ୍ୟ ସହିତ ମେଳ ଖାଏ
- ଯଦି ଆପଣ ପୂର୍ବରୁ `oroute` ପରି ଏକ ଭିନ୍ନ ନାମ ବ୍ୟବହାର କରିଥିଲେ, ଏହାକୁ `omniroute` ସହିତ ଦ୍ୱନ୍ଦ୍ୱରେ ପକାନ୍ତୁ ନାହିଁ

### 4.3 ଆପ୍ଲିକେସନ୍ ସୃଷ୍ଟି କରନ୍ତୁ

ଯଦି ଆପ୍ଲିକେସନ୍ ଏପର୍ଯ୍ୟନ୍ତ ବିଦ୍ୟମାନ ନାହିଁ:

```powershell
flyctl apps create omniroute
```

ଯଦି ଆପଣ ଆପ୍ଲିକେସନ୍ ନାମ ପରିବର୍ତ୍ତନ କରିଛନ୍ତି, `omniroute` ସ୍ଥାନରେ ଆପଣଙ୍କ ଚୟନ କରାଯାଇଥିବା ନାମ ବ୍ୟବହାର କରନ୍ତୁ।

### 4.4 ପ୍ରଥମ ନିୟୋଜନ

```powershell
flyctl deploy
```

## 5. ଆବଶ୍ୟକୀୟ ପାରାମିଟରଗୁଡ଼ିକ

ଏହି ପ୍ରୋଜେକ୍ଟ Fly.io ରେ ଅତି କମରେ ନିମ୍ନଲିଖିତ ପାରାମିଟରଗୁଡ଼ିକ ବିନ୍ୟାସ କରିବାକୁ ସୁପାରିଶ କରେ।

### 5.1 ଯାଞ୍ଚ କରାଯାଇଥିବା ପାରାମିଟରଗୁଡ଼ିକ

ଏହି ପାରାମିଟରଗୁଡ଼ିକ ବର୍ତ୍ତମାନର `omniroute` ଆପ୍ଲିକେସନ୍ ରେ ପ୍ରକୃତ ନିୟୋଜନରେ ବ୍ୟବହୃତ ହୋଇଛି:

- `API_KEY_SECRET`
- `DATA_DIR`
- `JWT_SECRET`
- `MACHINE_ID_SALT`
- `NEXT_PUBLIC_BASE_URL`
- `OMNIROUTE_WS_BRIDGE_SECRET` (ଉତ୍ପାଦନରେ ଆବଶ୍ୟକ — WebSocket ବ୍ରିଜ୍ ପ୍ରାମାଣିକରଣ ପାଇଁ ବ୍ୟବହୃତ)
- `STORAGE_ENCRYPTION_KEY`

### 5.2 `INITIAL_PASSWORD` ବିଷୟରେ

ବର୍ତ୍ତମାନର ପ୍ରୋଜେକ୍ଟ `INITIAL_PASSWORD` ସେଟ୍ କରେ ନାହିଁ କାରଣ ଏହି ନିୟୋଜନରେ ଏହାର ଆବଶ୍ୟକତା ନାହିଁ।

ଯଦି ଏହା ସେଟ୍ ନକରାଯାଏ:

- ଷ୍ଟାର୍ଟଅପ୍ ଲଗ୍ ସୂଚିତ କରିବ ଯେ ଡିଫଲ୍ଟ ପାସୱାର୍ଡ଼ ହେଉଛି `CHANGEME`
- ନିୟୋଜନ ପରେ ଆପଣ ଯଥାଶୀଘ୍ର ସିଷ୍ଟମ ସେଟିଂସରେ ଲଗିନ୍ ପାସୱାର୍ଡ଼ ପରିବର୍ତ୍ତନ କରିବା ଉଚିତ୍

ଯଦି ଆପଣ ବ୍ୟାକଏଣ୍ଡ ପାସୱାର୍ଡ଼କୁ ଅପରେଟର ବିନା ଆରମ୍ଭ କରିବାକୁ ଚାହାଁନ୍ତି, ଆପଣ ଏହାକୁ ପରେ ଯୋଡ଼ିପାରିବେ:

- `INITIAL_PASSWORD`

## ୬. ପରାମର୍ଶିତ ପାରାମିଟର

### ୬.୧ ସିକ୍ରେଟ୍ସ୍ କନଫିଗରେସନ

Fly ସିକ୍ରେଟ୍ସ୍ ପାଇଁ ନିମ୍ନଲିଖିତ ଭେରିଏବଲ୍ ଗୁଡ଼ିକ ପରାମର୍ଶିତ ହେବା ଉଚିତ:

| ଭେରିଏବଲ୍                       | ପରାମର୍ଶ              | ବିବରଣୀ                                         |
| ------------------------------ | -------------------- | ---------------------------------------------- |
| `API_KEY_SECRET`               | ଆବଶ୍ୟକ               | API କି ଜେନରେସନ୍ ଏବଂ ଭାଲିଡେସନ୍ ପାଇଁ ବ୍ୟବହୃତ     |
| `JWT_SECRET`                   | ଆବଶ୍ୟକ               | ଲଗିନ୍ ସେସନ୍ ଏବଂ JWT ସାଇନିଂ ପାଇଁ ବ୍ୟବହୃତ        |
| `OMNIROUTE_WS_BRIDGE_SECRET`   | ଉତ୍ପାଦନରେ ଆବଶ୍ୟକ     | WebSocket ବ୍ରିଜ୍ ପ୍ରମାଣୀକରଣ ସିକ୍ରେଟ୍           |
| `STORAGE_ENCRYPTION_KEY`       | ଦୃଢ଼ ଭାବରେ ପରାମର୍ଶିତ | ଅବସାଦରେ ସମ୍ବେଦନଶୀଳ ସଂଯୋଗ ସୂଚନାକୁ ଏନକ୍ରିପ୍ଟ କରେ |
| `MACHINE_ID_SALT`              | ପରାମର୍ଶିତ            | ଏକ ସ୍ଥିର ମେସିନ୍ ପରିଚୟକାରୀ ସୃଷ୍ଟି କରେ           |
| `INITIAL_PASSWORD`             | ଐଚ୍ଛିକ               | ପ୍ରଥମ ସ୍ଥାପନରେ ବ୍ୟାକେଣ୍ଡ ପାସୱାର୍ଡ ସେଟ୍ କରେ     |
| OAuth/API ବ୍ୟକ୍ତିଗତ ପ୍ରମାଣପତ୍ର | ଆବଶ୍ୟକ ଅନୁଯାୟୀ       | ବାହ୍ୟ ପ୍ଲାଟଫର୍ମ ପ୍ରମାଣୀକରଣ କନଫିଗରେସନ୍          |

### ୬.୨ ବର୍ତ୍ତମାନ ପ୍ରକଳ୍ପ ପାଇଁ ପରାମର୍ଶିତ ମୂଲ୍ୟ

| ଭେରିଏବଲ୍               | ପରାମର୍ଶିତ ମୂଲ୍ୟ             |
| ---------------------- | --------------------------- |
| `DATA_DIR`             | `/data`                     |
| `NEXT_PUBLIC_BASE_URL` | `https://omniroute.fly.dev` |

ନୋଟ୍:

- `DATA_DIR=/data` ଅତ୍ୟନ୍ତ ଗୁରୁତ୍ୱପୂର୍ଣ୍ଣ ଏବଂ Fly Volume ମାଉଣ୍ଟ ପଏଣ୍ଟ ସହ ମେଳ ଖାଇବା ଉଚିତ
- `NEXT_PUBLIC_BASE_URL` ଶେଡ୍ୟୁଲର, ଫ୍ରଣ୍ଟଏଣ୍ଡ କଲବ୍ୟାକ୍ ଏବଂ ସମାନ ପରିସ୍ଥିତିରେ ବ୍ୟବହୃତ ହୁଏ

### ୬.୩ OAuth କଲବ୍ୟାକ୍ URL କନଫିଗରେସନ

ଯଦି ଆପଣ Fly.io ସ୍ଥାପନରେ OAuth-ଆଧାରିତ ପ୍ରଦାନକାରୀ (ଯେପରିକି Antigravity, Gemini, Cursor) ସକ୍ଷମ କରିବାକୁ ଚାହାଁନ୍ତି, ତେବେ ନିମ୍ନଲିଖିତ ଦୁଇଟି ବିଷୟ ନିଶ୍ଚିତ କରନ୍ତୁ:

1. **`NEXT_PUBLIC_BASE_URL` କୁ ଆପଣଙ୍କ ସାର୍ବଜନୀନ HTTPS ଡୋମେନ୍ ସେଟ୍ କରନ୍ତୁ**

   ```powershell
   flyctl secrets set NEXT_PUBLIC_BASE_URL=https://omniroute.fly.dev -a omniroute
   ```

   ଯଦି ଆପଣ ଏକ କଷ୍ଟମ୍ ଡୋମେନ୍ ବ୍ୟବହାର କରୁଛନ୍ତି, ତେବେ ସଂଗଳ ଡୋମେନ୍ ଦ୍ୱାରା ଏହାକୁ ପ୍ରତିସ୍ଥାପିତ କରନ୍ତୁ (ଉଦାହରଣ `https://omniroute.yourdomain.com`).

2. **ପ୍ରଦାନକାରୀ କନସୋଲରେ କଲବ୍ୟାକ୍ URL କନଫିଗର କରନ୍ତୁ**

   ସମସ୍ତ OAuth ପ୍ରଦାନକାରୀ ଏକକ କଲବ୍ୟାକ୍ ପାଥ୍ `/callback` ସେୟାର କରନ୍ତି — ପ୍ରଦାନକାରୀ-ପ୍ରତି କଲବ୍ୟାକ୍ ରୁଟ୍ ନାହିଁ:

   ```text
   <NEXT_PUBLIC_BASE_URL>/callback
   ```

   ଉଦାହରଣ ସ୍ୱରୂପ, Gemini, Antigravity, Cursor କିମ୍ବା GitLab Duo ହେଉ ନା କାହିଁକି:
   - `https://omniroute.fly.dev/callback`

   ଯଦି `NEXT_PUBLIC_BASE_URL` ପ୍ରଦାନକାରୀ ସହ ପଞ୍ଜିକୃତ କଲବ୍ୟାକ୍ URL ସହ ମେଳ ଖାଏ ନାହିଁ, ତେବେ ବ୍ରାଉଜର୍ ରିଡାଇରେକ୍ଟ୍ ପଦକ୍ଷେପରେ OAuth ପ୍ରବାହ ବିଫଳ ହେବ।

## ୭. ଏକ-କମାଣ୍ଡ ସିକ୍ରେଟ୍ ସେଟଅପ୍

ନିମ୍ନଲିଖିତ କମାଣ୍ଡଗୁଡ଼ିକ ସୁରକ୍ଷିତ ରାନଡମ୍ ମୂଲ୍ୟ ସୃଷ୍ଟି କରେ ଏବଂ ବର୍ତ୍ତମାନ ପ୍ରକଳ୍ପ ପାଇଁ ସମସ୍ତ ଆବଶ୍ୟକୀୟ ପାରାମିଟର Fly ସିକ୍ରେଟ୍ସ୍ରେ ଏକ ପଦକ୍ଷେପରେ ଲେଖେ।

ନୋଟ୍:

- `INITIAL_PASSWORD` ଅନ୍ତର୍ଭୁକ୍ତ ନୁହେଁ
- ବର୍ତ୍ତମାନ ପ୍ରକଳ୍ପ `omniroute` ପାଇଁ ଉଦ୍ଦିଷ୍ଟ

```powershell
$apiKeySecret = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$jwtSecret = [Convert]::ToHexString((1..64 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$machineIdSalt = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$storageKey = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$wsBridgeSecret = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()

flyctl secrets set `
  API_KEY_SECRET=$apiKeySecret `
  JWT_SECRET=$jwtSecret `
  MACHINE_ID_SALT=$machineIdSalt `
  STORAGE_ENCRYPTION_KEY=$storageKey `
  OMNIROUTE_WS_BRIDGE_SECRET=$wsBridgeSecret `
  DATA_DIR=/data `
  NEXT_PUBLIC_BASE_URL=https://omniroute.fly.dev `
  -a omniroute
```

Linux / macOS ରେ, ଆପଣ `openssl rand -hex 32` ମଧ୍ୟ ବ୍ୟବହାର କରିପାରିବେ:

```bash
flyctl secrets set OMNIROUTE_WS_BRIDGE_SECRET=$(openssl rand -hex 32) -a omniroute
```

ନୋଟ୍:

- `OMNIROUTE_WS_BRIDGE_SECRET` ଉତ୍ପାଦନରେ ଆବଶ୍ୟକ; ଏହା ଅନୁପସ୍ଥିତ ଥିଲେ WebSocket ବ୍ରିଜ୍ ହ୍ୟାଣ୍ଡସେକ୍ ଭାଙ୍ଗିବ

ଯଦି ଆପଣ ଏକ ଆରମ୍ଭିକ ପାସୱାର୍ଡ ସେଟ୍ କରିବାକୁ ଚାହାଁନ୍ତି:

```powershell
flyctl secrets set INITIAL_PASSWORD=your-strong-password -a omniroute
```

## ୯. ପରବର୍ତ୍ତୀ ଅପଡେଟ୍ ଏବଂ ରିଲିଜ୍

କୋଡ୍ ଅପଡେଟ୍ ପରେ, ରିଲିଜ୍ ପ୍ରକ୍ରିୟା ସରଳ:

```powershell
git pull
flyctl deploy
```

ଯଦି ଆପଣ କୋଡ୍ ପରିବର୍ତ୍ତନ ନ କରି କେବଳ ପ୍ରାଚଳଗୁଡ଼ିକୁ ଅପଡେଟ୍ କରିବାକୁ ଚାହାଁନ୍ତି:

```powershell
flyctl secrets set KEY=value -a omniroute
```

Fly ସ୍ୱୟଂଚାଳିତ ଭାବରେ ମେସିନ୍ ଗୁଡ଼ିକର ରୋଲିଙ୍ଗ୍ ଅପଡେଟ୍ ପ୍ରଦାନ କରିବ।

### ୯.୧ ଆପଣଙ୍କ ଫୋର୍କର `fly.toml` ସୁରକ୍ଷିତ ରଖି ଅପଷ୍ଟ୍ରିମ୍ ରିପୋଜିଟୋରୀ ଅପଡେଟ୍ ଟ୍ରାକ୍ କରିବା

ଯଦି ବର୍ତ୍ତମାନର ରିପୋଜିଟୋରୀ ଏକ ଫୋର୍କ ଏବଂ ଆପଣ ଅପଷ୍ଟ୍ରିମ୍ `https://github.com/diegosouzapw/OmniRoute` ରୁ ଅପଡେଟ୍ ସିଙ୍କ୍ କରିବାକୁ ଚାହାଁନ୍ତି, ତେବେ ନିମ୍ନଲିଖିତ କାର୍ଯ୍ୟକ୍ରମ ଅନୁସରଣ କରନ୍ତୁ।

ପ୍ରଥମେ, ଆପଣଙ୍କ ରିମୋଟ୍ ଯାଞ୍ଚ କରନ୍ତୁ:

```powershell
git remote -v
```

ଆପଣଙ୍କୁ ଅନ୍ତତଃ ଏଗୁଡ଼ିକ ଦେଖାଯିବା ଉଚିତ୍:

- `origin` ଆପଣଙ୍କ ନିଜ ଫୋର୍କ ଆଡ଼କୁ ନିର୍ଦ୍ଦେଶ କରୁଛି
- `upstream` ମୂଳ ରିପୋଜିଟୋରୀ ଆଡ଼କୁ ନିର୍ଦ୍ଦେଶ କରୁଛି

ଯଦି `upstream` କନଫିଗର ହୋଇ ନାହିଁ, ଏହାକୁ ଯୋଗ କରନ୍ତୁ:

```powershell
git remote add upstream https://github.com/diegosouzapw/OmniRoute.git
```

ଅପଷ୍ଟ୍ରିମ୍ ସହ ସିଙ୍କ୍ କରିବା ପୂର୍ବରୁ, ସର୍ବଶେଷ କମିଟ୍ ଏବଂ ଟ୍ୟାଗ୍ ଆଣନ୍ତୁ:

```powershell
git fetch upstream --tags
```

ବର୍ତ୍ତମାନର ସଂସ୍କରଣ ଏବଂ ଅପଷ୍ଟ୍ରିମ୍ ଟ୍ୟାଗ୍ ଯାଞ୍ଚ କରନ୍ତୁ:

```powershell
git describe --tags --always
git show --no-patch --oneline v3.4.7
```

> ଟିପ୍ପଣୀ: ବର୍ତ୍ତମାନର ପ୍ରୋଜେକ୍ଟ ସଂସ୍କରଣ `v3.8.0`। ନିମ୍ନଲିଖିତ `v3.4.7` ସନ୍ଦର୍ଭଗୁଡ଼ିକ କେବଳ ଐତିହାସିକ ଉଦାହରଣ ଭାବରେ ରଖାଯାଇଛି। ପ୍ରକୃତ ରିଲିଜ୍ ପାଇଁ, `:latest` ବା ବର୍ତ୍ତମାନର ସଂସ୍କରଣ ଟ୍ୟାଗ୍ (ଉଦାହରଣ ସ୍ୱରୂପ `:v3.8.0`) ବ୍ୟବହାର କରନ୍ତୁ।

ଯଦି ଆପଣ ଆପଣଙ୍କ ଫୋର୍କର `fly.toml` କୁ ଜୋରଜବରଦସ୍ତି ସୁରକ୍ଷିତ ରଖି ସର୍ବଶେଷ ଅପଷ୍ଟ୍ରିମ୍ `main` ମିଶ୍ରଣ କରିବାକୁ ଚାହାଁନ୍ତି, ତେବେ ନିମ୍ନଲିଖିତ କାର୍ଯ୍ୟକ୍ରମ ଅନୁସରଣ କରନ୍ତୁ:

```powershell
git merge upstream/main
git checkout HEAD~1 -- fly.toml
git add -- fly.toml
git commit -m "chore(deploy): keep fork fly.toml"
git push origin main
```

ଟିପ୍ପଣୀ:

- `git merge upstream/main` ମୂଳ ରିପୋଜିଟୋରୀରୁ ସର୍ବଶେଷ କୋଡ୍ ସିଙ୍କ୍ କରେ
- `git checkout HEAD~1 -- fly.toml` ମିଶ୍ରଣ ପୂର୍ବରୁ ଥିବା ସମୟରେ ଆପଣଙ୍କ ଫୋର୍କର ନିଜସ୍ୱ `fly.toml` ପୁନରୁଦ୍ଧାର କରେ
- ଯଦି ଅପଷ୍ଟ୍ରିମ୍ `fly.toml` ପରିବର୍ତ୍ତନ କରି ନଥିଲା, ଏହି ପଦକ୍ଷେପ କୌଣସି ପାର୍ଥକ୍ୟ ଆଣିବ ନାହିଁ
- ଯଦି ଅପଷ୍ଟ୍ରିମ୍ `fly.toml` ପରିବର୍ତ୍ତନ କରିଥିଲା, ଏହି ପଦକ୍ଷେପ ନିଶ୍ଚିତ କରେ ଯେ ଆପଣଙ୍କ Fly ଆପ୍ଲିକେସନ୍ ନାମ, ଭଲ୍ୟୁମ୍ ମାଉଣ୍ଟ, ଅଞ୍ଚଳ ଏବଂ ଅନ୍ୟ ଅନ୍ୟାନ୍ୟ ଫୋର୍କ-ନିର୍ଦ୍ଦିଷ୍ଟ ଡିପ୍ଲାୟମେଣ୍ଟ କନଫିଗରେସନ୍ ଅଭିଲେଖ ହୋଇନାହିଁ

ଯଦି ଆପଣ ଏକ ନିର୍ଦ୍ଦିଷ୍ଟ ରିଲିଜ୍ ଟ୍ୟାଗ୍ (ଉଦାହରଣ ସ୍ୱରୂପ `v3.4.7`) ସହ ସମାନ ହେବାକୁ ଚାହାଁନ୍ତି, ତେବେ ପ୍ରଥମେ ଯାଞ୍ଚ କରନ୍ତୁ ଯେ ସେହି ଟ୍ୟାଗ୍ ଇତିମଧ୍ୟରେ `upstream/main` ରେ ଅନ୍ତର୍ଭୁକ୍ତ ହୋଇଛି:

```powershell
git merge-base --is-ancestor v3.4.7 upstream/main
```

ସଫଳ ଫେରାଇବା ଅର୍ଥ `upstream/main` ଇତିମଧ୍ୟରେ ସେହି ସଂସ୍କରଣ ଧାରଣ କରିଛି; ଆପଣ ସହଜରେ `upstream/main` ମିଶ୍ରଣ କରିପାରିବେ।

### ୯.୨ ଅପଷ୍ଟ୍ରିମ୍ ସିଙ୍କ୍ ପରେ ମାନକ ରିଲିଜ୍ କ୍ରମ

ମୂଳ ରିପୋଜିଟୋରୀ ସହ ସିଙ୍କ୍ ହେବା ପରେ, ନିମ୍ନଲିଖିତ ସୁପାରିଶ କରାଯାଇଥିବା ରିଲିଜ୍ କ୍ରମ ଅନୁସରଣ କରନ୍ତୁ:

1. `git fetch upstream --tags`
2. `git merge upstream/main`
3. ଫୋର୍କର `fly.toml` ପୁନରୁଦ୍ଧାର କରନ୍ତୁ
4. `git push origin main`
5. `flyctl deploy`
6. `flyctl status -a omniroute`
7. `flyctl logs --no-tail -a omniroute`

ଏହା ବର୍ତ୍ତମାନର ପ୍ରୋଜେକ୍ଟକୁ `v3.4.7` (ଉଦାହରଣ ଏକ ଐତିହାସିକ ସଂସ୍କରଣକୁ ସନ୍ଦର୍ଭ କରୁଛି; ବର୍ତ୍ତମାନର ପ୍ରକୃତ ସଂସ୍କରଣ `v3.8.0`) ରେ ଅପଗ୍ରେଡ୍ କରିବା ସମୟରେ ବ୍ୟବହୃତ ପ୍ରକୃତ କାର୍ଯ୍ୟକ୍ରମ।

## 10. ଡିପ୍ଲାଏମେଣ୍ଟ ପରବର୍ତ୍ତୀ ଯାଞ୍ଚ

### 10.1 ଆପ୍ଲିକେସନ୍ ସ୍ଥିତି ଯାଞ୍ଚ କରନ୍ତୁ

```powershell
flyctl status -a omniroute
```

### 10.2 ଷ୍ଟାର୍ଟଅପ୍ ଲଗ୍ ଦେଖନ୍ତୁ

```powershell
flyctl logs --no-tail -a omniroute
```

### 10.3 ସାଇଟ୍ ପ୍ରାପ୍ତିଯୋଗ୍ୟତା ଯାଞ୍ଚ କରନ୍ତୁ

```powershell
try {
  (Invoke-WebRequest -Uri "https://omniroute.fly.dev" -MaximumRedirection 5 -UseBasicParsing).StatusCode
} catch {
  if ($_.Exception.Response) {
    $_.Exception.Response.StatusCode.value__
  } else {
    throw
  }
}
```

`200` ର ଏକ ଫେରାଇ ମୂଲ୍ୟ ସୂଚାଏ ଯେ ସାଇଟ୍ ସ୍ୱାଭାବିକ ଭାବରେ ଉତ୍ତର ଦେଉଛି।

## 11. ସଫଳତା ସୂଚକ

ଏକ ସଫଳ ଡିପ୍ଲାଏମେଣ୍ଟ ପରେ, ଲଗ୍ଗୁଡ଼ିକ ସମାନ ବିଷୟ ଦେଖାଇବା ଉଚିତ୍:

```text
[bootstrap] Secrets persisted to: /data/server.env
[DB] SQLite database ready: /data/storage.sqlite
```

ଏହି ଦୁଇଟି ବିନ୍ଦୁ ଗୁରୁତ୍ୱପୂର୍ଣ୍ଣ:

- `/data/server.env` ନିଶ୍ଚିତ କରେ ଯେ ରନ୍ଟାଇମ୍ ସିକ୍ରେଟ୍ସ୍ ସ୍ଥାୟୀ ଭଲ୍ୟୁମ୍ରେ ଲେଖା ଯାଇଛି
- `/data/storage.sqlite` ନିଶ୍ଚିତ କରେ ଯେ ଡାଟାବେସ୍ ସ୍ଥାୟୀ ଭଲ୍ୟୁମ୍ରେ ଲେଖା ଯାଇଛି

ଯଦି ଆପଣ `/app/data/...` ଦେଖନ୍ତି, ତେବେ `DATA_DIR` ସଠିକ୍ ଭାବରେ କନଫିଗର ହୋଇ ନାହିଁ ଏବଂ ତୁରନ୍ତ ସଂଶୋଧନ କରାଯିବା ଉଚିତ୍।

---

## 12. ସାଧାରଣ ସମସ୍ୟା

### 12.1 `Secrets` ପୃଷ୍ଠା ଖାଲି ଅଛି

ସାଧାରଣତଃ ଦୁଇଟି କାରଣ ଅଛି:

- ଆପଣ ଏପର୍ଯ୍ୟନ୍ତ `flyctl secrets set` ଚଳାଇ ନାହାଁନ୍ତି
- ଆପଣ ଏକ ଭିନ୍ନ ଆପ୍ଲିକେସନ୍ ଦେଖୁଛନ୍ତି (ଯେପରିକି `omniroute` ପରିବର୍ତ୍ତେ `oroute`)

### 12.2 `flyctl deploy` `app not found` ରିପୋର୍ଟ କରୁଛି

ପ୍ରଥମେ ଆପ୍ଲିକେସନ୍ ସୃଷ୍ଟି କରନ୍ତୁ:

```powershell
flyctl apps create omniroute
```

### 12.3 `fly.toml` ପାର୍ସିଂ ବିଫଳ ହେଉଛି

ନିମ୍ନଲିଖିତ ଯାଞ୍ଚ କରନ୍ତୁ:

- ମନ୍ତବ୍ୟରେ ଖରାପ ଅକ୍ଷର ଅଛି କି
- TOML ଉଦ୍ଧୃତି ଏବଂ ଇନ୍ଡେଣ୍ଟେସନ୍ ସଠିକ୍ ଅଛି କି

### 12.4 ଡାଟା ସ୍ଥାୟୀ ହେଉ ନାହିଁ

ନିମ୍ନଲିଖିତ ଦୁଇଟି ଯାଞ୍ଚ କରନ୍ତୁ:

- `fly.toml` ରେ `destination = '/data'` ଅଛି
- `DATA_DIR` `/data` ସେଟ୍ ହୋଇଛି

### 12.5 ଏହା `INITIAL_PASSWORD` ବିନା ଚଳାଇ ଯାଇପାରିବ କି?

ହଁ, ଏହା ଚଳିପାରିବ। ଏହା ଡିଫଲ୍ଟ `CHANGEME` ପାସ୍ଓ୍ଜୋର୍ଡରେ ଫାଲ୍ବ୍ୟାକ୍ ହେବ। ପ୍ରଡକସନ୍ରେ ଯଥାଶୀଘ୍ର ବ୍ୟାକେଣ୍ଡ୍ ପାସ୍ଓ୍ଜୋର୍ଡ ପରିବର୍ତ୍ତନ କରିବା ପରାମର୍ଶ ଦିଆଯାଏ।

## 13. ନୂତନ ପ୍ରକଳ୍ପ ପାଇଁ ପୁନଃବ୍ୟବହାର

ଯଦି ଆପଣ ଏହି ଡକୁମେଣ୍ଟ୍ ଅନୁସରଣ କରି ଏକ ନୂତନ ପ୍ରକଳ୍ପ ଡିପ୍ଲାଏ କରୁଛନ୍ତି, ଆପଣଙ୍କୁ କେବଳ ଏହି ଆଇଟମ୍ଗୁଡ଼ିକ ପରିବର୍ତ୍ତନ କରିବାକୁ ହେବ:

1. `fly.toml` ରେ `app` ମୂଲ୍ୟ ପରିବର୍ତ୍ତନ କରନ୍ତୁ
2. `NEXT_PUBLIC_BASE_URL` ପରିବର୍ତ୍ତନ କରନ୍ତୁ
3. `DATA_DIR=/data` ରଖନ୍ତୁ
4. `API_KEY_SECRET`, `JWT_SECRET`, `MACHINE_ID_SALT`, ଏବଂ `STORAGE_ENCRYPTION_KEY` ପୁଣିଥରେ ସୃଷ୍ଟି କରନ୍ତୁ
5. ପ୍ରଥମ ଡିପ୍ଲାଏମେଣ୍ଟ ପରେ, ଲଗ୍ଗୁଡ଼ିକ `/data` ରେ ଲେଖା ଯାଇଛି କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ

ପୂର୍ବବର୍ତ୍ତୀ ପ୍ରକଳ୍ପର କୀ ପୁନଃବ୍ୟବହାର କରନ୍ତୁ ନାହିଁ।

---

## 14. ବର୍ତ୍ତମାନର ପ୍ରକଳ୍ପ ପାଇଁ ସର୍ବନିମ୍ନ ରିଲିଜ୍ ଚେକଲିଷ୍ଟ

ପରବର୍ତ୍ତୀ ରିଲିଜ୍ଗୁଡ଼ିକ ପାଇଁ ସବୁଠାରୁ ବେଶୀ ବ୍ୟବହୃତ କମାଣ୍ଡଗୁଡ଼ିକ ହେଉଛି:

```powershell
flyctl auth whoami
flyctl status -a omniroute
flyctl secrets list -a omniroute
flyctl deploy
flyctl logs --no-tail -a omniroute
```

ଏକ ସାଧାରଣ ରିଲିଜ୍ ପାଇଁ, ମୂଳ କମାଣ୍ଡ କେବଳ:

```powershell
flyctl deploy
```

ଏକ ନୂତନ ପରିବେଶରେ ପ୍ରଥମ ଥର ଡିପ୍ଲାଏମେଣ୍ଟ ପାଇଁ, ମୂଳ ପଦକ୍ଷେପଗୁଡ଼ିକ ହେଉଛି:

1. `flyctl auth login`
2. `flyctl apps create omniroute`
3. `flyctl secrets set ... -a omniroute`
4. `flyctl deploy`
5. `flyctl logs --no-tail -a omniroute`
