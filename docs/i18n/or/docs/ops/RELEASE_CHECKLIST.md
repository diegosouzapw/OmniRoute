## npm ବିଶ୍ୱସ୍ତ ପ୍ରକାଶନ (v3.8.51 ଠାରୁ ଡିଫଲ୍ଟ) — ଅନୁରୋଧରେ ଷ୍ଟେଜ୍ଡ୍, ବିକଳ୍ପ ଭାବେ ସିଧାସଳଖ

`npm-publish.yml` ଡିଫଲ୍ଟ ଭାବେ **npm ବିଶ୍ୱସ୍ତ ପ୍ରକାଶନ (OIDC)** ମାଧ୍ୟମରେ ପ୍ରକାଶ କରେ:
`stage-npm` ଜବ୍ (GitHub ଦ୍ୱାରା ହୋଷ୍ଟ କରାଯାଇଥିବା) ସେହି ରନ୍ ପାଇଁ GitHubର id-tokenକୁ ଏକ ସ୍ୱଳ୍ପକାଳୀନ npm
ପ୍ରମାଣପତ୍ର ସହ ବିନିମୟ କରେ — ରିପୋଜିଟୋରି ସିକ୍ରେଟ୍ଗୁଡ଼ିକରେ କୌଣସି ଦୀର୍ଘକାଳୀନ npm ଟୋକେନ୍ ନାହିଁ, କୌଣସି 2FA ପ୍ରମ୍ପ୍ଟ ନାହିଁ, ଏବଂ ଉତ୍ପତ୍ତି ପ୍ରମାଣ ସଂଲଗ୍ନ ରହେ।
2FAକୁ ଏଡ଼ାଉଥିବା ଟୋକେନ୍ଗୁଡ଼ିକୁ ଅବସର ଦିଆଯାଉଥିବାରୁ, ଏହା ହେଉଛି ବର୍ତ୍ତମାନ npm ଦ୍ୱାରା ଅନୁମୋଦିତ ବାଇପାସ୍;
ଏହା WS1.3 ନିଶ୍ଚୟତାକୁ ବଜାୟ ରଖି ପ୍ରକଳ୍ପର v3.8.48 ପର୍ଯ୍ୟନ୍ତ ଥିବା ସମ୍ପୂର୍ଣ୍ଣ ସ୍ୱୟଂଚାଳିତ ପ୍ରବାହକୁ
ପୁନଃସ୍ଥାପନ କରେ (ଲିକ୍ ହୋଇଥିବା ଟୋକେନ୍ ଏକାକୀ ପ୍ରକାଶ କରିପାରିବ ନାହିଁ — କାରଣ କୌଣସି ଟୋକେନ୍ ହିଁ ନାହିଁ)।

**ଏକକାଳୀନ ସେଟଅପ୍ (ମାଲିକ):** npmjs.com → ପ୍ୟାକେଜ୍ `omniroute` → Settings → _Trusted
Publisher_ → GitHub: ମାଲିକ `diegosouzapw`, ରିପୋ `OmniRoute`, ୱର୍କଫ୍ଲୋ `npm-publish.yml`
(ପରିବେଶ: କିଛି ନାହିଁ)। ଏହା ଉପଲବ୍ଧ ହେବା ପର୍ଯ୍ୟନ୍ତ, ସ୍ୱୟଂଚାଳିତ ପଦକ୍ଷେପଟି `ENEEDAUTH` ସହ ବିଫଳ ହୁଏ:
`publish_mode=staged` (ନିମ୍ନରେ) କିମ୍ବା `direct` ସହ ପୁନଃ-ଡିସ୍ପାଚ୍ କରନ୍ତୁ।

### ଷ୍ଟେଜ୍ଡ୍ ପ୍ରକାଶନ (ଅନୁରୋଧରେ — `publish_mode=staged`)

npm-publish ୱର୍କଫ୍ଲୋ ଆଉ ସିଧାସଳଖ ପ୍ରକାଶ କରେ ନାହିଁ: ଏହା ପ୍ୟାକ୍ ହୋଇଥିବା tarballକୁ
ବୁଟ୍ କରେ (`check:pack-boot`) ଏବଂ ତା’ପରେ `npm stage publish` ଚଲାଏ — ଠିକ୍ ସେହି ବାଇଟ୍ଗୁଡ଼ିକୁ
ରେଜିଷ୍ଟ୍ରିରେ ରଖାଯାଏ, କିନ୍ତୁ ମାଲିକ ଅନୁମୋଦନ ନକରିବା ପର୍ଯ୍ୟନ୍ତ ସେଗୁଡ଼ିକ **ଇନଷ୍ଟଲ୍ଯୋଗ୍ୟ ନୁହେଁ**। ମାନବୀୟ 2FA ଗେଟ୍କୁ
ପ୍ରମାଣର ପୂର୍ବରୁ ନୁହେଁ, ତାହାର ପରକୁ ସ୍ଥାନାନ୍ତର କରାଯାଇଛି।

**ୱର୍କଫ୍ଲୋ ସବୁଜ ହେବା ପରେ ମାଲିକଙ୍କ ପ୍ରବାହ:**

1. `npm stage list omniroute` — ଷ୍ଟେଜ୍ id ଖୋଜନ୍ତୁ (ଏହା ୱର୍କଫ୍ଲୋ ସାରାଂଶରେ ମଧ୍ୟ ପ୍ରିଣ୍ଟ୍ ହୁଏ)।
2. ଷ୍ଟେଜ୍ଡ୍ ବାଇଟ୍ଗୁଡ଼ିକ ଯାଞ୍ଚ କରନ୍ତୁ (ସୁପାରିଶକୃତ): `npm stage download <id>`, ତା’ପରେ ଡାଉନଲୋଡ୍
   କରାଯାଇଥିବା tarballକୁ ଏକ ଅସ୍ଥାୟୀ prefixରେ ଇନଷ୍ଟଲ୍ କରି ବୁଟ୍ କରନ୍ତୁ (`npm run check:pack-boot` CIରେ
   ସେହି pack→install→boot ନିଷ୍ପତ୍ତିକୁ ସ୍ୱୟଂଚାଳିତ କରେ)।
3. `npm stage approve <id>` — 2FA ପ୍ରମ୍ପ୍ଟ୍ଟି ହିଁ ପ୍ରକାଶନ। `npm stage reject <id>` ବାତିଲ୍ କରେ।
4. ପ୍ରକାଶନ-ପରବର୍ତ୍ତୀ ସୁରକ୍ଷା ଜାଲ: ପ୍ରକାଶନ-ପରବର୍ତ୍ତୀ ଯାଞ୍ଚକାରୀ (v3.8.49 ଯୋଜନାର WS1.4) ଏକ ସଫା
   କଣ୍ଟେନର୍ରେ ସାର୍ବଜନୀନ ରେଜିଷ୍ଟ୍ରିରୁ ପ୍ରକାଶିତ ଭର୍ସନ୍କୁ ଇନଷ୍ଟଲ୍ କରି ବୁଟ୍ କରେ।

**ଜରୁରୀକାଳୀନ ବିକଳ୍ପ:** `publish_mode=direct` ସହ `workflow_dispatch` ପୁରୁଣା
ତତ୍କ୍ଷଣାତ୍ `npm publish`କୁ ପୁନଃସ୍ଥାପନ କରେ (କେବଳ ଷ୍ଟେଜିଂ ନିଜେ ଠିକ୍ ଭାବରେ କାମ ନକଲେ ବ୍ୟବହାର କରନ୍ତୁ; କାରଣ ଲେଖି ରଖନ୍ତୁ)।

**ଏକକାଳୀନ ସୁଦୃଢ଼ୀକରଣ (ମାଲିକ, npmjs.com):** `omniroute` ପାଇଁ Trusted Publisherକୁ
କେବଳ-ଷ୍ଟେଜ୍ ମୋଡ୍ରେ ବିନ୍ୟାସ କରନ୍ତୁ, ଯାହାଫଳରେ ଏକ ଲିକ୍ ହୋଇଥିବା ଦୀର୍ଘକାଳୀନ ଟୋକେନ୍ କୌଣସି ସ୍ଥାନରୁ ସିଧାସଳଖ `npm publish`
କରିପାରିବ ନାହିଁ — CI କେବଳ ଷ୍ଟେଜ୍ କରିପାରିବ; କେବଳ ମାଲିକଙ୍କ 2FA ରିଲିଜ୍ କରିପାରିବ।

**ତ୍ରୁଟିପୂର୍ଣ୍ଣ ଆର୍ଟିଫ୍ୟାକ୍ଟ ପ୍ଲେବୁକ୍ (ଅପରିବର୍ତ୍ତିତ):** ଡିଫଲ୍ଟ ତତ୍କ୍ଷଣାତ୍ ପଦକ୍ଷେପ ଭାବେ `npm deprecate omniroute@<bad> "<reason> — use <fixed>"`
(କିଛି ମିନିଟ୍, ପ୍ରତ୍ୟାବର୍ତ୍ତନଯୋଗ୍ୟ); `npm unpublish`କୁ କେବଳ 72h/କୌଣସି-ନିର୍ଭରଶୀଳ-ନଥିବା
ଅବଧି ମଧ୍ୟରେ ବ୍ୟବହାର କରନ୍ତୁ ଏବଂ କେବେ ମଧ୍ୟ ପ୍ରଥମ ପଦକ୍ଷେପ ଭାବେ ନୁହେଁ। Docker: କୌଣସି ଭର୍ସନ୍ ଟ୍ୟାଗ୍କୁ କେବେ ମଧ୍ୟ ପୁନର୍ଲେଖନ କରନ୍ତୁ ନାହିଁ — ରୋଲ୍ବ୍ୟାକ୍ ଅର୍ଥ
`latest`କୁ ଶେଷ ଭଲ digest ପ୍ରତି ପୁନଃନିର୍ଦ୍ଦେଶ କରିବା।

**Docker Hub `latest` (ପ୍ରତ୍ୟେକ ସ୍ଥିର SemVer ପ୍ରକାଶନରେ ଆବଶ୍ୟକ):**
`docker-publish` ୱର୍କଫ୍ଲୋ ନିଶ୍ଚିତ ଭାବେ `X.Y.Z` ଏବଂ, ଯେତେବେଳେ
`should-promote-latest.sh` ଏହା ସର୍ବୋଚ୍ଚ ସ୍ଥିର SemVer ବୋଲି ସହମତ ହୁଏ, `:latest` —
**ଉଭୟକୁ** **ସମାନ digest** ସହ ଟ୍ୟାଗ୍ କରିବା ଆବଶ୍ୟକ। ଜବ୍ ପରେ: Hubର `latest` digest ନୂତନ
SemVer digest ସହ ସମାନ ହେବା ଏବଂ `last_updated` ଆଗକୁ ବଢ଼ିଥିବା ଆବଶ୍ୟକ। ରିଲିଜ୍ ନୋଟ୍ରେ କେବଳ gitରେ ଥିବା ସମାଧାନଗୁଡ଼ିକ ବିଷୟରେ କୁହାଯାଉଥିବା ବେଳେ
`:latest`କୁ କୌଣସି ପୁରୁଣା ବିଲ୍ଡ୍ରେ ଛାଡ଼ି ଦିଅନ୍ତୁ ନାହିଁ। Compose
କ୍ୱିକ୍ଷ୍ଟାର୍ଟଗୁଡ଼ିକ `:latest` ବ୍ୟବହାର କରେ; GitOpsରେ `X.Y.Z` ପିନ୍ କରିବା ଜାରି ରହିବା ଉଚିତ। [Docker ରିଲିଜ୍ ଚ୍ୟାନେଲ୍ଗୁଡ଼ିକ](../guides/DOCKER_GUIDE.md#release-channels) ଏବଂ #10317 ଦେଖନ୍ତୁ।

## ହଟ୍ଫିକ୍ସ ଫାଷ୍ଟ-ଲେନ୍ (`hotfix` ଲେବଲ୍)

`hotfix` ଲେବଲ୍ ଥିବା ଏକ PR ଭାରୀ CI ମ୍ୟାଟ୍ରିକ୍ସ (9-shard E2E, coverage ratchet,
quality-gate, quality-extended)କୁ ଏଡ଼ାଇ ଦ୍ରୁତ, ଉଚ୍ଚ-ସଙ୍କେତ ଗେଟ୍ଗୁଡ଼ିକୁ ରଖେ: build,
unit shards, integration, vitest, lint/typecheck, docs-sync, `check:pack-artifact`
ଏବଂ tarball boot-smoke (`check:pack-boot`)। ଲକ୍ଷ୍ୟ: ~33 ମିନିଟ୍ ପରିବର୍ତ୍ତେ ≤15 ମିନିଟ୍ରେ ସଫଳ।

**ପ୍ରବେଶ ନୀତି — ସମସ୍ତ ଚାରିଟି ଆବଶ୍ୟକ (Chromium/VS Code/Node ଜରୁରୀକାଳୀନ ଲେନ୍ ଅନୁସାରେ ମଡେଲ୍ କରାଯାଇଛି):**

1. **ଗୁରୁତ୍ୱ**: production ଭାଙ୍ଗିଯାଇଛି — ପ୍ରକାଶିତ artifact boot ସମୟରେ crash ହୁଏ /
   ଏକ security fix / releaseର ପ୍ରତ୍ୟେକ user ପ୍ରଭାବିତ। "ଗୁରୁତ୍ୱପୂର୍ଣ୍ଣ" ଅର୍ଥ "ଭାଙ୍ଗିଯାଇଛି" ନୁହେଁ।
2. **କର୍ତ୍ତୃତ୍ୱ**: କେବଳ repository owner `hotfix` ଲେବଲ୍ ପ୍ରୟୋଗ କରନ୍ତି। ଲେବଲ୍ଟି ହିଁ
   ଅନୁମୋଦନ — campaign PRରେ କେବେବି ନିଜେ ଏହା ପ୍ରୟୋଗ କରନ୍ତୁ ନାହିଁ।
3. **ପ୍ରମାଣ**: PR body ପୂର୍ବବର୍ତ୍ତୀ ସମ୍ପୂର୍ଣ୍ଣ-ସଫଳ heavy run (ଯେଉଁ suiteକୁ
   skipped jobs ପୁନଃ-ବୈଧ କରିଥାନ୍ତା) ସହିତ fixର ନିଜସ୍ୱ ପ୍ରଥମେ-ବିଫଳ-ତାପରେ-ସଫଳ testକୁ link କରେ।
4. **ପରିସର**: କେବଳ cherry-pick — ସର୍ବନିମ୍ନ fix, କୌଣସି refactor ନୁହେଁ, କୌଣସି ଅସମ୍ପର୍କିତ ପରିବର୍ତ୍ତନ ନୁହେଁ।

ଏଡ଼ାଯାଇଥିବା coverage/ratchet ପରିସର release branchର ପରବର୍ତ୍ତୀ full run
(continuous release-green) ଦ୍ୱାରା ପୁନଃ-ବୈଧ କରାଯାଏ — ଏହି lane କେବଳ ଅପେକ୍ଷାକୁ ଏଡ଼ାଏ, validationକୁ କେବେବି ନୁହେଁ।
କେବଳ tests ସମ୍ବନ୍ଧୀୟ diff (ସମସ୍ତ file `tests/` ଅଧୀନରେ, କୌଣସିଟି `tests/e2e/` ଅଧୀନରେ ନୁହେଁ) କୌଣସି label ବିନା
ସ୍ୱୟଂଚାଳିତ ଭାବରେ E2E matrixକୁ ଏଡ଼ାଏ।

### Hooks (Husky ଦ୍ୱାରା ବୈଧ କରାଯାଇଛି)

Husky hookଗୁଡ଼ିକ `.husky/`ରେ ରହେ ଏବଂ git operation ସମୟରେ ସ୍ୱୟଂଚାଳିତ ଭାବରେ ଚାଲେ।

- **pre-commit:** `npx lint-staged + node scripts/check/check-docs-sync.mjs + npm run check:any-budget:t11`
- **pre-push:** ଦ୍ରୁତ deterministic gate — `npm run check:any-budget:t11 && npm run check:tracked-artifacts` (2026-06-13ରେ ସକ୍ରିୟ କରାଯାଇଛି)। ଉଦ୍ଦେଶ୍ୟମୂଳକ ଭାବରେ `test:unit`କୁ ବାଦ ଦିଏ (ଧୀର; CI `test-unit` job ଦ୍ୱାରା ଆବୃତ)।
  - release branch push କରିବା ପୂର୍ବରୁ `npm run test:unit`କୁ ହସ୍ତଚାଳିତ ଭାବରେ ଚଲାନ୍ତୁ।

କୌଣସି hook ବିଫଳ ହେଲେ: ମୂଳ ସମସ୍ୟାକୁ ସମାଧାନ କରନ୍ତୁ, `--no-verify` ବ୍ୟବହାର କରି ଏଡ଼ାନ୍ତୁ ନାହିଁ।

### Build Layout

Repositoryଟି ତିନୋଟି ପୃଥକ output directory ବ୍ୟବହାର କରେ — ସେଗୁଡ଼ିକୁ କେବେବି ମିଶାନ୍ତୁ ନାହିଁ:

| Directory | ଉଦ୍ଦେଶ୍ୟ                                                             | Track କରାଯାଏ?   |
| --------- | -------------------------------------------------------------------- | --------------- |
| `src/`    | Application source (TypeScript / TSX)                                | ହଁ              |
| `.build/` | Build intermediate — `next build` output (`distDir`)                 | ନା (gitignored) |
| `dist/`   | ପ୍ରେରଣଯୋଗ୍ୟ npm bundle — `assembleStandalone` ଦ୍ୱାରା assemble କରାଯାଏ | ନା (gitignored) |

> **Operator ଟିପ୍ପଣୀ:** remote VPS image directory `/usr/lib/node_modules/omniroute/app/` ହିଁ ରହିଛି।
> କେବଳ **repository ମଧ୍ୟରେ ଥିବା** build output ସ୍ଥାନାନ୍ତରିତ ହୋଇଛି (`app/` → `dist/`)। deploy skillଗୁଡ଼ିକ
> `dist/`ର contentକୁ remote `app/` directoryରେ rsync କରେ — VPS pathରେ କୌଣସି ପରିବର୍ତ୍ତନ ଆବଶ୍ୟକ ନାହିଁ।

**ଏକକ-build ପ୍ରବାହ:**

```
npm run build:release
  └─ rm -rf .build dist          (ସଫା କରେ)
  └─ next build → .build/next/   (ମଧ୍ୟବର୍ତ୍ତୀ output)
  └─ assembleStandalone          (standalone + static + public + nativeକୁ dist/ରେ copy କରେ)
  └─ dist/BUILD_SHA ଲେଖେ        (HEAD sentinel)
```

Deploy ପାଇଁ `npm run build` ଚଲାଇ ତାହାପରେ ପୃଥକ ଭାବରେ `npm run build:cli` ଚଲାନ୍ତୁ ନାହିଁ —
`npm run build:release` ବ୍ୟବହାର କରନ୍ତୁ, ଯାହା ଗୋଟିଏ commandରେ clean rebuild + sentinel କରେ।

## ରୋଲ୍ବ୍ୟାକ୍

ରିଲିଜ୍ରେ କୌଣସି ଗୁରୁତର ସମସ୍ୟା ଥିଲେ:

1. `gh release edit vX.Y.Z --prerelease` (ଏହାକୁ ସର୍ବଶେଷ ନୁହେଁ ବୋଲି ଚିହ୍ନିତ କରେ)
2. `git tag -d vX.Y.Z && git push --delete origin vX.Y.Z` (କେବଳ ଯଦି ବ୍ୟବହାରକାରୀମାନେ ଏପର୍ଯ୍ୟନ୍ତ ଏହାକୁ ଗ୍ରହଣ କରିନାହାନ୍ତି)
3. କିମ୍ବା: `release/vX.Y.0` ଉପରେ ହଟ୍ଫିକ୍ସ → ପ୍ୟାଚ୍ ରିଲିଜ୍ `vX.Y.(Z+1)`
4. GitHub Discussions ଏବଂ Discord ରେ ତୁରନ୍ତ ସୂଚନା ଦିଅନ୍ତୁ

## କଠୋର ନିୟମାବଳୀ

- କେବେବି ସିଧାସଳଖ `main` କୁ କମିଟ୍ କରନ୍ତୁ ନାହିଁ
- `main` କିମ୍ବା `release/*` ବ୍ରାଞ୍ଚଗୁଡ଼ିକରେ କେବେବି `git push --force` ବ୍ୟବହାର କରନ୍ତୁ ନାହିଁ
- Husky ହୁକ୍ଗୁଡ଼ିକୁ (`--no-verify`) କେବେବି ଏଡ଼ାଇ ଯାଆନ୍ତୁ ନାହିଁ
- ସିକ୍ରେଟ୍, କ୍ରେଡେନ୍ସିଆଲ୍ କିମ୍ବା `.env` ଫାଇଲ୍ଗୁଡ଼ିକୁ କେବେବି କମିଟ୍ କରନ୍ତୁ ନାହିଁ
- କଭରେଜ୍ ≥60/60/60/60 (ଷ୍ଟେଟ୍ମେଣ୍ଟ୍/ଲାଇନ୍/ଫଙ୍କସନ୍/ବ୍ରାଞ୍ଚ୍) ରହିବା ଆବଶ୍ୟକ
- `src/`, `open-sse/`, `electron/`, କିମ୍ବା `bin/` ରେ ପ୍ରଡକ୍ସନ୍ କୋଡ୍ ପରିବର୍ତ୍ତନ କରିବାବେଳେ ସର୍ବଦା ପରୀକ୍ଷଣଗୁଡ଼ିକୁ ଅନ୍ତର୍ଭୁକ୍ତ କିମ୍ବା ଅପଡେଟ୍ କରନ୍ତୁ

## ସ୍ୱୟଂଚାଳିତ ସିଙ୍କ୍ ଯାଞ୍ଚ

PR ଖୋଲିବା ପୂର୍ବରୁ ଲୋକାଲ୍ ଭାବରେ ଡକ୍ୟୁମେଣ୍ଟେସନ୍ ସିଙ୍କ୍ ଗାର୍ଡ ଚଲାନ୍ତୁ:

```bash
npm run check:docs-sync
```

CI ମଧ୍ୟ `.github/workflows/ci.yml` ରେ ଏହି ଯାଞ୍ଚକୁ ଚଲାଏ (ଲିଣ୍ଟ୍ ଜବ୍)।
