## npm ବିଶ୍ୱସ୍ତ ପ୍ରକାଶନ (v3.8.51 ଠାରୁ ଡିଫଲ୍ଟ) — ଅନୁରୋଧରେ ପର୍ଯ୍ୟାୟଭିତ୍ତିକ, ବିକଳ୍ପ ଭାବେ ସିଧାସଳଖ

`npm-publish.yml` ଡିଫଲ୍ଟ ଭାବେ **npm Trusted Publishing (OIDC)** ମାଧ୍ୟମରେ ପ୍ରକାଶ କରେ:
`stage-npm` ଜବ୍ (github-hosted) ସେହି ରନ୍ ପାଇଁ GitHubର id-tokenକୁ ଏକ ସ୍ୱଳ୍ପକାଳୀନ npm
ପରିଚୟପତ୍ର ସହିତ ବିନିମୟ କରେ — ରିପୋଜିଟୋରି ସିକ୍ରେଟ୍ରେ କୌଣସି ଦୀର୍ଘକାଳୀନ npm ଟୋକନ୍ ନାହିଁ, କୌଣସି 2FA ପ୍ରମ୍ପ୍ଟ ନାହିଁ, ଏବଂ ଉତ୍ସ-ପ୍ରମାଣ ସଂଲଗ୍ନ ହୁଏ।
2FA ଏଡ଼ାଇଯାଉଥିବା ଟୋକନ୍ଗୁଡ଼ିକୁ ଅବସର ଦିଆଯାଉଥିବାରୁ npm ବର୍ତ୍ତମାନ ଅନୁମୋଦନ କରୁଥିବା ବାଇପାସ୍ ଏହା;
ଏହା WS1.3 ଗ୍ୟାରେଣ୍ଟିକୁ ବଜାୟ ରଖି ପ୍ରକଳ୍ପର v3.8.48 ପର୍ଯ୍ୟନ୍ତ ଥିବା ସମ୍ପୂର୍ଣ୍ଣ ସ୍ୱୟଂଚାଳିତ ପ୍ରବାହକୁ
ପୁନଃସ୍ଥାପନ କରେ (ଏକ ଲିକ୍ ହୋଇଥିବା ଟୋକନ୍ ଏକାକୀ ପ୍ରକାଶ କରିପାରିବ ନାହିଁ — କାରଣ କୌଣସି ଟୋକନ୍ ହିଁ ନାହିଁ)।

**ଏକକାଳୀନ ସେଟ୍ଅପ୍ (ମାଲିକ):** npmjs.com → package `omniroute` → Settings → _Trusted
Publisher_ → GitHub: owner `diegosouzapw`, repo `OmniRoute`, workflow `npm-publish.yml`
(environment: none)। ଏହା ଉପଲବ୍ଧ ନହେବା ପର୍ଯ୍ୟନ୍ତ, ସ୍ୱୟଂଚାଳିତ ପଦକ୍ଷେପଟି `ENEEDAUTH` ସହିତ ବିଫଳ ହୁଏ:
`publish_mode=staged` (ନିମ୍ନରେ) କିମ୍ବା `direct` ସହିତ ପୁନଃ-ଡିସ୍ପାଚ୍ କରନ୍ତୁ।

### ପର୍ଯ୍ୟାୟଭିତ୍ତିକ ପ୍ରକାଶନ (ଅନୁରୋଧରେ — `publish_mode=staged`)

npm-publish ୱାର୍କଫ୍ଲୋ ଆଉ ସିଧାସଳଖ ପ୍ରକାଶ କରେ ନାହିଁ: ଏହା ପ୍ୟାକ୍ ହୋଇଥିବା tarballକୁ
ବୁଟ୍ କରେ (`check:pack-boot`) ଏବଂ ତା’ପରେ `npm stage publish` ଚଲାଏ — ଠିକ୍ ସେହି ବାଇଟ୍ଗୁଡ଼ିକୁ
ରେଜିଷ୍ଟ୍ରିରେ ରଖାଯାଏ, କିନ୍ତୁ ମାଲିକ ଅନୁମୋଦନ ନ କରିବା ପର୍ଯ୍ୟନ୍ତ ସେଗୁଡ଼ିକ **ଇନ୍ଷ୍ଟଲ୍ଯୋଗ୍ୟ ନୁହେଁ**। ମାନବୀୟ 2FA ଗେଟ୍ଟି
ପ୍ରମାଣ ପୂର୍ବରୁ ନୁହେଁ, ଏହା ପରକୁ ସ୍ଥାନାନ୍ତରିତ ହୋଇଛି।

**ୱାର୍କଫ୍ଲୋ ସବୁଜ ହେବା ପରେ ମାଲିକଙ୍କ ପ୍ରବାହ:**

1. `npm stage list omniroute` — ଷ୍ଟେଜ୍ id ଖୋଜନ୍ତୁ (ୱାର୍କଫ୍ଲୋ ସାରାଂଶରେ ମଧ୍ୟ ମୁଦ୍ରିତ ହୁଏ)।
2. ଷ୍ଟେଜ୍ କରାଯାଇଥିବା ବାଇଟ୍ଗୁଡ଼ିକୁ ଯାଞ୍ଚ କରନ୍ତୁ (ସୁପାରିସକୃତ): `npm stage download <id>`, ତା’ପରେ
   ଡାଉନଲୋଡ୍ କରାଯାଇଥିବା tarballକୁ ଏକ ଅସ୍ଥାୟୀ prefixରେ ଇନ୍ଷ୍ଟଲ୍ କରି ବୁଟ୍ କରନ୍ତୁ (`npm run check:pack-boot`
   CIରେ ସେହି pack→install→boot ନିଷ୍ପତ୍ତିକୁ ସ୍ୱୟଂଚାଳିତ କରେ)।
3. `npm stage approve <id>` — 2FA ପ୍ରମ୍ପ୍ଟଟି ହିଁ ପ୍ରକାଶନ। `npm stage reject <id>` ଏହାକୁ ପରିତ୍ୟାଗ କରେ।
4. ପ୍ରକାଶନ-ପରବର୍ତ୍ତୀ ସୁରକ୍ଷାଜାଲ: ପ୍ରକାଶନ-ପରବର୍ତ୍ତୀ ଯାଞ୍ଚକାରୀ (v3.8.49 ଯୋଜନାର WS1.4) ଏକ ସ୍ୱଚ୍ଛ
   କଣ୍ଟେନର୍ରେ ସାର୍ବଜନୀନ ରେଜିଷ୍ଟ୍ରିରୁ ପ୍ରକାଶିତ ଭର୍ସନ୍କୁ ଇନ୍ଷ୍ଟଲ୍ କରି ବୁଟ୍ କରେ।

**ଜରୁରୀକାଳୀନ ବିକଳ୍ପ:** `publish_mode=direct` ସହିତ `workflow_dispatch` ପୁରୁଣା
ତତ୍କ୍ଷଣାତ୍ `npm publish`କୁ ପୁନଃସ୍ଥାପନ କରେ (କେବଳ staging ନିଜେ ଠିକ୍ ଭାବେ କାମ ନ କଲେ ବ୍ୟବହାର କରନ୍ତୁ; କାରଣ ଲିପିବଦ୍ଧ କରନ୍ତୁ)।

**ଏକକାଳୀନ ଦୃଢ଼ୀକରଣ (ମାଲିକ, npmjs.com):** `omniroute` ପାଇଁ Trusted Publisherକୁ
କେବଳ-ଷ୍ଟେଜ୍ ମୋଡ୍ରେ କନଫିଗର୍ କରନ୍ତୁ, ଯାହାଦ୍ୱାରା ଏକ ଲିକ୍ ହୋଇଥିବା ଦୀର୍ଘକାଳୀନ ଟୋକନ୍ କୌଣସି ସ୍ଥାନରୁ ସିଧାସଳଖ `npm publish`
କରିପାରିବ ନାହିଁ — CI କେବଳ ଷ୍ଟେଜ୍ କରିପାରିବ; କେବଳ ମାଲିକଙ୍କ 2FA ରିଲିଜ୍ କରିପାରିବ।

**ତ୍ରୁଟିପୂର୍ଣ୍ଣ-ଆର୍ଟିଫ୍ୟାକ୍ଟ କାର୍ଯ୍ୟପୁସ୍ତିକା (ଅପରିବର୍ତ୍ତିତ):** ଡିଫଲ୍ଟ ପ୍ରତିକ୍ରିୟା ଭାବେ `npm deprecate omniroute@<bad> "<reason> — use <fixed>"`
(କିଛି ମିନିଟ୍, ପ୍ରତ୍ୟାବର୍ତ୍ତନଯୋଗ୍ୟ); କେବଳ 72h/କୌଣସି-ନିର୍ଭରଶୀଳ-ନଥିବା ୱିଣ୍ଡୋ ଭିତରେ `npm unpublish`
କରନ୍ତୁ ଏବଂ ଏହାକୁ କେବେବି ପ୍ରଥମ ପଦକ୍ଷେପ ଭାବେ ନିଅନ୍ତୁ ନାହିଁ। Docker: କୌଣସି ଭର୍ସନ୍ ଟ୍ୟାଗ୍କୁ କେବେବି ପୁନଃଲେଖନ କରନ୍ତୁ ନାହିଁ — rollback ଅର୍ଥ
`latest`କୁ ଶେଷ ଭଲ digest ପ୍ରତି ପୁନଃନିର୍ଦ୍ଦେଶ କରିବା।

**Docker Hub `latest` (ପ୍ରତ୍ୟେକ ସ୍ଥିର SemVer ପ୍ରକାଶନରେ ଆବଶ୍ୟକ):**
`docker-publish` ୱାର୍କଫ୍ଲୋ ନିଶ୍ଚିତ ଭାବେ `X.Y.Z` ଏବଂ, ଯେତେବେଳେ
`should-promote-latest.sh` ଏହା ସର୍ବୋଚ୍ଚ ସ୍ଥିର SemVer ବୋଲି ସହମତ ହୁଏ, `:latest`
— ଉଭୟକୁ **ସମାନ digest** ସହିତ ଟ୍ୟାଗ୍ କରିବା ଆବଶ୍ୟକ। ଜବ୍ ପରେ: Hub `latest` digest ନୂତନ
SemVer digest ସହିତ ସମାନ ହେବ ଏବଂ `last_updated` ଆଗକୁ ବଢ଼ିଥିବ। କେବଳ gitରେ ଥିବା ସମାଧାନଗୁଡ଼ିକ ବିଷୟରେ
ରିଲିଜ୍ ଟିପ୍ପଣୀରେ କୁହାଯାଉଥିବା ବେଳେ `:latest`କୁ କୌଣସି ପୁରୁଣା ବିଲ୍ଡ୍ରେ ଛାଡ଼ନ୍ତୁ ନାହିଁ।
Compose ଦ୍ରୁତ-ଆରମ୍ଭଗୁଡ଼ିକ `:latest` ବ୍ୟବହାର କରନ୍ତି; GitOpsରେ `X.Y.Z`କୁ ପିନ୍ କରିବା ଜାରି ରଖିବା ଉଚିତ।
[Docker ରିଲିଜ୍ ଚ୍ୟାନେଲ୍ଗୁଡ଼ିକ](../guides/DOCKER_GUIDE.md#release-channels) ଏବଂ #10317 ଦେଖନ୍ତୁ।

## ହଟଫିକ୍ସ ଫାଷ୍ଟ-ଲେନ୍ (ଲେବଲ୍ `hotfix`)

`hotfix` ଲେବଲ୍ ଥିବା ଏକ PR ଭାରୀ CI ମ୍ୟାଟ୍ରିକ୍ସ (9-ଶାର୍ଡ E2E, କଭରେଜ୍ ରାଚେଟ୍,
କ୍ୱାଲିଟି-ଗେଟ୍, କ୍ୱାଲିଟି-ଏକ୍ସଟେଣ୍ଡେଡ୍)କୁ ଏଡ଼ାଇଯାଏ ଏବଂ ଦ୍ରୁତ, ଉଚ୍ଚ-ସଙ୍କେତଯୁକ୍ତ ଗେଟ୍ଗୁଡ଼ିକୁ ରଖେ: ବିଲ୍ଡ,
ୟୁନିଟ୍ ଶାର୍ଡ, ଇଣ୍ଟିଗ୍ରେସନ୍, vitest, lint/typecheck, docs-sync, `check:pack-artifact`
ଏବଂ tarball ବୁଟ୍-ସ୍ମୋକ୍ (`check:pack-boot`)। ଲକ୍ଷ୍ୟ: ~33min ପରିବର୍ତ୍ତେ ≤15min ମଧ୍ୟରେ ସବୁଜ ସ୍ଥିତି।

**ପ୍ରବେଶ ନୀତି — ଚାରୋଟିଯାକ ଆବଶ୍ୟକ (Chromium/VS Code/Node ଜରୁରୀକାଳୀନ ଲେନ୍ ଆଧାରରେ ତିଆରି):**

1. **ଗୁରୁତରତା**: ପ୍ରଡକ୍ସନ୍ ଭାଙ୍ଗିଛି — ପ୍ରକାଶିତ ଆର୍ଟିଫ୍ୟାକ୍ଟ ବୁଟ୍ ସମୟରେ କ୍ରାଶ୍ କରୁଛି / ଏକ
   ସୁରକ୍ଷା ସଂଶୋଧନ / ରିଲିଜ୍ର ପ୍ରତ୍ୟେକ ବ୍ୟବହାରକାରୀ ପ୍ରଭାବିତ। "ଗୁରୁତ୍ୱପୂର୍ଣ୍ଣ"ର ଅର୍ଥ "ଭାଙ୍ଗିଛି" ନୁହେଁ।
2. **କର୍ତ୍ତୃତ୍ୱ**: କେବଳ ରିପୋଜିଟୋରି ମାଲିକ `hotfix` ଲେବଲ୍ ପ୍ରୟୋଗ କରନ୍ତି। ଲେବଲ୍ଟି ହିଁ
   ଅନୁମୋଦନ — କ୍ୟାମ୍ପେନ୍ PRରେ କେବେବି ନିଜେ ଏହା ପ୍ରୟୋଗ କରନ୍ତୁ ନାହିଁ।
3. **ପ୍ରମାଣ**: PR ବଡି ପୂର୍ବବର୍ତ୍ତୀ ସମ୍ପୂର୍ଣ୍ଣ-ସବୁଜ ଭାରୀ ରନ୍କୁ (ଯେଉଁ ସୁଇଟ୍କୁ
   ଏଡ଼ାଇଦିଆଯାଇଥିବା ଜବ୍ଗୁଡ଼ିକ ପୁନଃବୈଧ କରିଥାନ୍ତେ) ଏବଂ ଫିକ୍ସର ନିଜସ୍ୱ ପ୍ରଥମେ-ବିଫଳ-ପରେ-ସଫଳ ଟେଷ୍ଟକୁ ଲିଙ୍କ୍ କରେ।
4. **ପରିସର**: କେବଳ cherry-pick — ସର୍ବନିମ୍ନ ଫିକ୍ସ, କୌଣସି ରିଫ୍ୟାକ୍ଟର୍ ନୁହେଁ, କୌଣସି ଅସମ୍ପର୍କିତ ପରିବର୍ତ୍ତନ ନୁହେଁ।

ଏଡ଼ାଇଦିଆଯାଇଥିବା କଭରେଜ୍/ରାଚେଟ୍ ପରିସର ରିଲିଜ୍ ବ୍ରାଞ୍ଚର ପରବର୍ତ୍ତୀ ସମ୍ପୂର୍ଣ୍ଣ ରନ୍ରେ
ପୁନଃବୈଧ କରାଯାଏ (ନିରନ୍ତର ରିଲିଜ୍-ସବୁଜ) — ଲେନ୍ଟି କେବଳ ଅପେକ୍ଷାକୁ ଏଡ଼ାଏ, ବୈଧିକରଣକୁ କେବେବି ନୁହେଁ।
କେବଳ-ଟେଷ୍ଟ ଡିଫ୍ଗୁଡ଼ିକ (`tests/` ଅଧୀନରେ ସମସ୍ତ ଫାଇଲ୍, `tests/e2e/` ଅଧୀନରେ କୌଣସି ନୁହେଁ) କୌଣସି ଲେବଲ୍ ବିନା
ସ୍ୱୟଂଚାଳିତ ଭାବରେ E2E ମ୍ୟାଟ୍ରିକ୍ସକୁ ଏଡ଼ାଇଯାଏ।

### ହୁକ୍ଗୁଡ଼ିକ (Husky ଦ୍ୱାରା ବୈଧିକୃତ)

Husky ହୁକ୍ଗୁଡ଼ିକ `.husky/`ରେ ରହିଛି ଏବଂ git ଅପରେସନ୍ ସମୟରେ ସ୍ୱୟଂଚାଳିତ ଭାବରେ ଚାଲେ।

- **pre-commit:** `npx lint-staged + node scripts/check/check-docs-sync.mjs + npm run check:any-budget:t11`
- **pre-push:** ଦ୍ରୁତ ନିର୍ଦ୍ଧାରଣାତ୍ମକ ଗେଟ୍ଗୁଡ଼ିକ — `npm run check:any-budget:t11 && npm run check:tracked-artifacts` (2026-06-13ରେ ସକ୍ରିୟ କରାଯାଇଛି)। ଉଦ୍ଦେଶ୍ୟମୂଳକ ଭାବେ `test:unit`କୁ ବାଦ ଦିଏ (ଧୀର; CI `test-unit` ଜବ୍ ଦ୍ୱାରା କଭର୍ ହୁଏ)।
  - ରିଲିଜ୍ ବ୍ରାଞ୍ଚଗୁଡ଼ିକୁ ପୁଶ୍ କରିବା ପୂର୍ବରୁ `npm run test:unit` ମାନୁଆଲ୍ ଭାବେ ଚଲାନ୍ତୁ।

ଯଦି କୌଣସି ହୁକ୍ ବିଫଳ ହୁଏ: ଅନ୍ତର୍ନିହିତ ସମସ୍ୟାକୁ ଠିକ୍ କରନ୍ତୁ, `--no-verify` ସହିତ ଏହାକୁ ବାଇପାସ୍ କରନ୍ତୁ ନାହିଁ।

### ବିଲ୍ଡ ବିନ୍ୟାସ

Repositoryଟି ତିନୋଟି ପୃଥକ output directory ବ୍ୟବହାର କରେ — ସେଗୁଡ଼ିକୁ କେବେବି ମିଶାନ୍ତୁ ନାହିଁ:

| Directory | ଉଦ୍ଦେଶ୍ୟ                                                    | ଟ୍ରାକ୍ କରାଯାଏ କି? |
| --------- | ----------------------------------------------------------- | ----------------- |
| `src/`    | Application source (TypeScript / TSX)                       | ହଁ                |
| `.build/` | Build intermediate — `next build` output (`distDir`)        | ନା (gitignored)   |
| `dist/`   | ବିତରଣଯୋଗ୍ୟ npm bundle — `assembleStandalone` ଦ୍ୱାରା ସଂଯୋଜିତ | ନା (gitignored)   |

> **ଅପରେଟର୍ ଟିପ୍ପଣୀ:** remote VPS image directory ଏବେ ମଧ୍ୟ `/usr/lib/node_modules/omniroute/app/` ରହିଛି।
> କେବଳ **in-repo** build output ସ୍ଥାନାନ୍ତରିତ ହୋଇଛି (`app/` → `dist/`)। Deploy skillଗୁଡ଼ିକ
> `dist/`ର ବିଷୟବସ୍ତୁକୁ remote `app/` directoryରେ rsync କରେ — VPS pathରେ କୌଣସି ପରିବର୍ତ୍ତନ ଆବଶ୍ୟକ ନାହିଁ।

**ଏକକ-build ପ୍ରବାହ:**

```
npm run build:release
  └─ rm -rf .build dist          (ପରିଷ୍କାର)
  └─ next build → .build/next/   (ମଧ୍ୟବର୍ତ୍ତୀ ଫାଇଲ୍)
  └─ assembleStandalone          (standalone + static + public + nativesକୁ dist/ରେ କପି କରେ)
  └─ writes dist/BUILD_SHA       (HEAD sentinel)
```

Deploy ପାଇଁ `npm run build` ଚଲାଇ ତା’ପରେ ପୃଥକ ଭାବେ `npm run build:cli` ଚଲାନ୍ତୁ ନାହିଁ — ଏହା ପରିବର୍ତ୍ତେ
`npm run build:release` ବ୍ୟବହାର କରନ୍ତୁ, ଯାହା ଗୋଟିଏ commandରେ clean rebuild + sentinel କରେ।

କ୍ରମଟି ପ୍ରିଣ୍ଟ କରେ — ପୂର୍ବସର୍ତ୍ତଗୁଡ଼ିକ (ଉତ୍ସ ସମାଧାନ ହୁଏ, ପୂର୍ବବର୍ତ୍ତୀ ଟ୍ୟାଗ୍ ଅଛି, `package.json`
ଲକ୍ଷ୍ୟ ସଂସ୍କରଣରେ ଅଛି, ଏକ `release-freeze` ଇସ୍ୟୁ ଖୋଲା ଅଛି, କୌଣସି ବିଦ୍ୟମାନ ରିଲିଜ୍ ବ୍ରାଞ୍ଚରେ
ଖୋଲା `Release branch not green` ଇସ୍ୟୁ ନାହିଁ — ଅବିଦ୍ୟମାନ ବ୍ରାଞ୍ଚକୁ `?` ଅଜ୍ଞାତ ଭାବେ
ରିପୋର୍ଟ କରାଯାଏ, କେବେ ମଧ୍ୟ ସବୁଜ ନୁହେଁ — Mergify `release` କ୍ୟୁ ବିନ୍ୟାସିତ ଅଛି
(G11: `queue_rules`, `checks_timeout`, ଲେବଲ୍ `queue`), `release/*` ରୁଲ୍ସେଟ୍ ଏବେ ମଧ୍ୟ
ବିଲୋପ ଏବଂ ଫୋର୍ସ-ପୁଶ୍କୁ ଅବରୋଧ କରେ, ଏବଂ `stable/v3` ଓ `develop` ଏପର୍ଯ୍ୟନ୍ତ ନାହାନ୍ତି),
ଦୁଇଟି ବ୍ରାଞ୍ଚ ପଦକ୍ଷେପ, କେଉଁ ସୁପ୍ତ ୱାର୍କଫ୍ଲୋ ଟ୍ରିଗର୍ ଏବଂ `if:` ସର୍ତ୍ତ ସତ୍ୟ ହୁଏ
(ଏବଂ କେଉଁଗୁଡ଼ିକ ଏକ ରିପୋଜିଟୋରି ଭେରିଏବଲ୍ ଦ୍ୱାରା ଗେଟ୍ ହୋଇ ରହେ କିମ୍ବା କ୍ୟାନୋନିକାଲ୍
ରିପୋଜିଟୋରିକୁ ପିନ୍ ହୋଇ ରହେ), ଆଶାକରାଯାଉଥିବା dist-tags (`latest` → 3.9.0, `next` ଏବଂ
`nightly` ଖାଲି) ଏବଂ ରୋଲ୍ବ୍ୟାକ୍। ପ୍ରସ୍ଥାନ `0` = `RESULT: READY`, `1` = ଏକ ଅବରୋଧକ
ପୂର୍ବସର୍ତ୍ତ ବିଫଳ ହେଲା (`✗`), `2` = ବ୍ୟବହାର ତ୍ରୁଟି। `--advisory <id,...>` କୌଣସି ଯାଞ୍ଚକୁ
ଲୁଚାଇବା ବିନା ଏକ ଚେତାବନୀ (`!`)କୁ ଅବନମିତ କରେ।

### PR ପ୍ରିଭ୍ୟୁ ଆର୍ଟିଫ୍ୟାକ୍ଟ (ଥରେ ନିର୍ମାଣ କରନ୍ତୁ, ସେହି ବାଇଟ୍ଗୁଡ଼ିକୁ ପ୍ରମୋଟ୍ କରନ୍ତୁ)

`.github/workflows/preview-artifact.yml` ଏକ PR ହେଡ୍ରୁ ଗୋଟିଏ ପ୍ରୋଡକ୍ସନ୍ ଟାର୍ବଲ୍ ନିର୍ମାଣ କରେ
ଏବଂ ସେହି ନିର୍ଦ୍ଦିଷ୍ଟ ବିଲ୍ଡ୍କୁ ବୈଧ କରେ (#8084 ଖଣ୍ଡ (a))। କେବଳ ସମାନ-ରିପୋଜିଟୋରି PR;
କିଛି ପ୍ରକାଶିତ ହୁଏ ନାହିଁ।

```bash
gh workflow run preview-artifact.yml -f pr_number=<N>   # କିମ୍ବା `preview-artifact` ଲେବଲ୍ ଯୋଡ଼ନ୍ତୁ

npm install -g ./omniroute-*.tgz                          # ପ୍ରିଭ୍ୟୁ ଇନ୍ଷ୍ଟଲ୍
```

ରନ୍ଟି `npm ci`, `npm run build:release`, `npm run check:pack-artifact` କରେ, ଟାର୍ବଲ୍କୁ ପ୍ୟାକ୍ କରେ,
`npm run check:pack-boot` (ନକଲି ସିକ୍ରେଟ୍, କ୍ଷଣସ୍ଥାୟୀ ଡାଟା ଡିରେକ୍ଟୋରି) ଚଳାଏ, ପୁନଃ ପ୍ୟାକ୍ କରେ
ଏବଂ ଡାଇଜେଷ୍ଟ ସମାନ ନହେଲେ ବିଫଳ ହୁଏ, ତା'ପରେ `artifact-identity.json` (ହେଡ୍ SHA, ବେସ୍
SHA, ଲକ୍ଫାଇଲ୍ ହ୍ୟାଶ୍, ପ୍ଲାଟଫର୍ମ, ଆର୍କିଟେକ୍ଚର୍, node ABI, ବଣ୍ଡଲର୍, ବିଲ୍ଡ୍ ନୀତି —
`scripts/release/artifact-identity.mjs`) ରେକର୍ଡ କରେ ଏବଂ ଏକ ପୃଥକ ଜବ୍ରେ ଟାର୍ବଲ୍କୁ
ପ୍ରମାଣିତ କରେ। ଏକ ପ୍ରିଭ୍ୟୁକୁ ପ୍ରମୋଟ୍ କରିବା ଅର୍ଥ ସେହି ଟାର୍ବଲ୍କୁ ଇନ୍ଷ୍ଟଲ୍ କରିବା:

- କେବେବି ସିକ୍ରେଟ୍, କ୍ରେଡେନ୍ସିଆଲ୍ କିମ୍ବା `.env` ଫାଇଲ୍ କମିଟ୍ କରନ୍ତୁ ନାହିଁ
- କଭରେଜ୍ ≥60/60/60/60 (ଷ୍ଟେଟମେଣ୍ଟ୍/ଲାଇନ୍/ଫଙ୍କସନ୍/ବ୍ରାଞ୍ଚ୍) ରହିବା ଆବଶ୍ୟକ
- `src/`, `open-sse/`, `electron/`, କିମ୍ବା `bin/`ରେ ପ୍ରୋଡକ୍ସନ୍ କୋଡ୍ ପରିବର୍ତ୍ତନ କରିବାବେଳେ ସର୍ବଦା ପରୀକ୍ଷଣଗୁଡ଼ିକୁ ସାମିଲ କିମ୍ବା ଅପଡେଟ୍ କରନ୍ତୁ

## ସ୍ୱୟଂଚାଳିତ ସିଙ୍କ୍ ଯାଞ୍ଚ

PR ଖୋଲିବା ପୂର୍ବରୁ ଡକ୍ୟୁମେଣ୍ଟ୍ ସିଙ୍କ୍ ଗାର୍ଡକୁ ସ୍ଥାନୀୟ ଭାବେ ଚଲାନ୍ତୁ:

```bash
npm run check:docs-sync
```

CI ମଧ୍ୟ `.github/workflows/ci.yml`ରେ ଏହି ଯାଞ୍ଚ ଚଲାଏ (lint ଜବ୍)।
