Cloudflare ମାଧ୍ୟମରେ ପରିଚାଳିତ ଡୋମେନ୍ ସହିତ ଏକ VM (VPS) ଉପରେ OmniRoute ସଂସ୍ଥାପନ ଏବଂ ବିନ୍ୟାସ କରିବା ପାଇଁ ସମ୍ପୂର୍ଣ୍ଣ ମାର୍ଗଦର୍ଶିକା।

## ପୂର୍ବାବଶ୍ୟକତାଗୁଡ଼ିକ

| ଆଇଟମ୍      | ସର୍ବନିମ୍ନ             | ସୁପାରିସକୃତ       |
| ---------- | --------------------- | ---------------- |
| **CPU**    | 1 vCPU                | 2 vCPU           |
| **RAM**    | 1 GB                  | 2 GB             |
| **ଡିସ୍କ**  | 10 GB SSD             | 25 GB SSD        |
| **OS**     | Ubuntu 22.04 LTS      | Ubuntu 24.04 LTS |
| **ଡୋମେନ୍** | Cloudflareରେ ପଞ୍ଜୀକୃତ | —                |
| **Docker** | Docker Engine 24+     | Docker 27+       |

**ପରୀକ୍ଷିତ ପ୍ରଦାନକାରୀମାନେ**: Akamai (Linode), DigitalOcean, Vultr, Hetzner, AWS Lightsail.

## 1. VM ବିନ୍ୟାସ କରନ୍ତୁ

### 1.1 ଇନଷ୍ଟାନ୍ସ ସୃଷ୍ଟି କରନ୍ତୁ

ଆପଣଙ୍କ ପସନ୍ଦର VPS ପ୍ରଦାନକାରୀଙ୍କଠାରେ:

- Ubuntu 24.04 LTS ବାଛନ୍ତୁ
- ସର୍ବନିମ୍ନ ପ୍ଲାନ୍ (1 vCPU / 1 GB RAM) ବାଛନ୍ତୁ
- ଏକ ଶକ୍ତିଶାଳୀ root ପାସୱାର୍ଡ ସେଟ୍ କରନ୍ତୁ କିମ୍ବା SSH key ବିନ୍ୟାସ କରନ୍ତୁ
- **ସାର୍ବଜନୀନ IP** ଟିପ୍ପଣୀ କରି ରଖନ୍ତୁ (ଉଦାହରଣସ୍ୱରୂପ, `203.0.113.10`)

### 1.2 SSH ମାଧ୍ୟମରେ ସଂଯୋଗ କରନ୍ତୁ

```bash
ssh root@203.0.113.10
```

### 1.3 ସିଷ୍ଟମ୍ ଅଦ୍ୟତନ କରନ୍ତୁ

```bash
apt update && apt upgrade -y
```

### 1.4 Docker ଇନଷ୍ଟଲ୍ କରନ୍ତୁ

```bash
# ନିର୍ଭରଶୀଳତାଗୁଡ଼ିକ ଇନଷ୍ଟଲ୍ କରନ୍ତୁ
apt install -y ca-certificates curl gnupg

# ଅଧିକୃତ Docker ରିପୋଜିଟୋରୀ ଯୋଡ଼ନ୍ତୁ
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
chmod a+r /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $ (. /etc/os-release && echo "$VERSION_CODENAME") stable" | tee /etc/apt/sources.list.d/docker.list > /dev/null
apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

### 1.5 nginx ଇନଷ୍ଟଲ୍ କରନ୍ତୁ

```bash
apt install -y nginx
```

### 1.6 ଫାୟାରୱାଲ୍ (UFW) ବିନ୍ୟାସ କରନ୍ତୁ

```bash
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp    # SSH
ufw allow 80/tcp    # HTTP (ପୁନଃନିର୍ଦ୍ଦେଶ)
ufw allow 443/tcp   # HTTPS
ufw enable
```

> **ପରାମର୍ଶ**: ସର୍ବାଧିକ ସୁରକ୍ଷା ପାଇଁ, ପୋର୍ଟ 80 ଏବଂ 443କୁ କେବଳ Cloudflare IPଗୁଡ଼ିକ ପାଇଁ ସୀମିତ କରନ୍ତୁ। [ଉନ୍ନତ ସୁରକ୍ଷା](#advanced-security) ବିଭାଗ ଦେଖନ୍ତୁ।

## 2. OmniRoute ଇନଷ୍ଟଲ୍ କରନ୍ତୁ

### 2.1 ବିନ୍ୟାସ ଡିରେକ୍ଟୋରୀ ସୃଷ୍ଟି କରନ୍ତୁ

```bash
mkdir -p /opt/omniroute
```

### 2.2 ପରିବେଶ ଭେରିଏବଲ୍ ଫାଇଲ୍ ସୃଷ୍ଟି କରନ୍ତୁ

```bash
cat > /opt/omniroute/.env << 'EOF'
# === ସୁରକ୍ଷା ===
JWT_SECRET=CHANGE-TO-A-UNIQUE-64-CHAR-SECRET-KEY
INITIAL_PASSWORD=YourSecurePassword123!
API_KEY_SECRET=REPLACE-WITH-ANOTHER-SECRET-KEY
STORAGE_ENCRYPTION_KEY=REPLACE-WITH-THIRD-SECRET-KEY
STORAGE_ENCRYPTION_KEY_VERSION=v1
MACHINE_ID_SALT=CHANGE-TO-A-UNIQUE-SALT
OMNIROUTE_WS_BRIDGE_SECRET=REPLACE-WITH-WS-BRIDGE-SECRET  # ପ୍ରୋଡକ୍ସନ୍ରେ ଆବଶ୍ୟକ: Codex Responses WS bridge ଦ୍ୱାରା ବ୍ୟବହୃତ

# === ଆପ୍ ===
PORT=20128
NODE_ENV=production
HOSTNAME=0.0.0.0
DATA_DIR=/app/data
APP_LOG_TO_FILE=true
AUTH_COOKIE_SECURE=true
REQUIRE_API_KEY=false

# === URLଗୁଡ଼ିକ (ଆପଣଙ୍କ ଡୋମେନ୍କୁ ପରିବର୍ତ୍ତନ କରନ୍ତୁ) ===
# ନିର୍ଦ୍ଧାରିତ କାର୍ଯ୍ୟ / ସ୍ୱୟଂ-fetch ପାଇଁ ଆଭ୍ୟନ୍ତରୀଣ server-to-server ମୂଳ URL।
BASE_URL=http://127.0.0.1:20128
# OAuth callback, dashboard link ଏବଂ ସୃଷ୍ଟି ହୋଇଥିବା ସାର୍ବଜନୀନ URL ପାଇଁ ବ୍ୟବହୃତ browser-facing URL।
NEXT_PUBLIC_BASE_URL=https://llms.seudominio.com
# ସୃଷ୍ଟି ହୋଇଥିବା ସାର୍ବଜନୀନ asset URL ପାଇଁ ଇଚ୍ଛାଧୀନ ସ୍ପଷ୍ଟ public origin override।
# OMNIROUTE_PUBLIC_BASE_URL=https://llms.seudominio.com

# === Cloud Sync (ଇଚ୍ଛାଧୀନ) ===
# CLOUD_URL=https://cloud.omniroute.online
# NEXT_PUBLIC_CLOUD_URL=https://cloud.omniroute.online
EOF
```

> ⚠️ **ଗୁରୁତ୍ୱପୂର୍ଣ୍ଣ**: ଅନନ୍ୟ ଗୁପ୍ତ key ସୃଷ୍ଟି କରନ୍ତୁ! ପ୍ରତ୍ୟେକ key ପାଇଁ `openssl rand -hex 32` ବ୍ୟବହାର କରନ୍ତୁ।

### 2.3 କଣ୍ଟେନର୍ ଆରମ୍ଭ କରନ୍ତୁ

```bash
docker pull diegosouzapw/omniroute:latest

docker run -d \
  --name omniroute \
  --restart unless-stopped \
  --env-file /opt/omniroute/.env \
  -p 20128:20128 \
  -v omniroute-data:/app/data \
  diegosouzapw/omniroute:latest
```

### 2.4 ଏହା ଚାଲୁଥିବା ଯାଞ୍ଚ କରନ୍ତୁ

```bash
docker ps | grep omniroute
docker logs omniroute --tail 20
```

ଏହା `[DB] SQLite database ready` ଏବଂ `listening on port 20128` ପ୍ରଦର୍ଶନ କରିବା ଉଚିତ।

## 3. nginx ବିନ୍ୟାସ କରନ୍ତୁ (ରିଭର୍ସ ପ୍ରକ୍ସି)

### 3.1 SSL ପ୍ରମାଣପତ୍ର ସୃଷ୍ଟି କରନ୍ତୁ (Cloudflare Origin)

Cloudflare ଡ୍ୟାସ୍ବୋର୍ଡରେ:

1. **SSL/TLS → Origin Server**କୁ ଯାଆନ୍ତୁ
2. **Create Certificate**ରେ କ୍ଲିକ୍ କରନ୍ତୁ
3. ଡିଫଲ୍ଟ ମୂଲ୍ୟଗୁଡ଼ିକ ଅପରିବର୍ତ୍ତିତ ରଖନ୍ତୁ (15 ବର୍ଷ, \*.yourdomain.com)
4. **Origin Certificate** ଏବଂ **Private Key** କପି କରନ୍ତୁ

```bash
mkdir -p /etc/nginx/ssl

# ପ୍ରମାଣପତ୍ରଟି ପେଷ୍ଟ କରନ୍ତୁ
nano /etc/nginx/ssl/origin.crt

# ବ୍ୟକ୍ତିଗତ କୀ ପେଷ୍ଟ କରନ୍ତୁ
nano /etc/nginx/ssl/origin.key

chmod 600 /etc/nginx/ssl/origin.key
```

### 3.2 Nginx ବିନ୍ୟାସ

```bash
cat > /etc/nginx/sites-available/omniroute << 'NGINX'
# ଡିଫଲ୍ଟ ସର୍ଭର — IP ମାଧ୍ୟମରେ ସିଧାସଳଖ ପ୍ରବେଶକୁ ଅବରୋଧ କରେ
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    listen 443 ssl default_server;
    listen [::]:443 ssl default_server;
    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    server_name _;
    return 444;
}

# OmniRoute — HTTPS
server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name llms.yourdomain.com;  # ଆପଣଙ୍କ ଡୋମେନ୍କୁ ପରିବର୍ତ୍ତନ କରନ୍ତୁ

    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    client_max_body_size 100M;

    location / {
        proxy_pass http://127.0.0.1:20128;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket ସମର୍ଥନ
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # SSE (ସର୍ଭର-ପ୍ରେରିତ ଇଭେଣ୍ଟ) — ଷ୍ଟ୍ରିମିଂ AI ପ୍ରତିକ୍ରିୟା
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }
}

# HTTP → HTTPS ପୁନଃନିର୍ଦ୍ଦେଶ
server {
    listen 80;
    listen [::]:80;
    server_name llms.yourdomain.com;
    return 301 https://$server_name$request_uri;
}
NGINX
```

ରିଭର୍ସ-ପ୍ରକ୍ସି ଷ୍ଟ୍ରିମ୍ ସମୟସୀମାଗୁଡ଼ିକୁ ଆପଣଙ୍କ OmniRoute ସମୟସୀମା env vars ସହିତ ସମନ୍ୱିତ ରଖନ୍ତୁ। ଯଦି ଆପଣ
`FETCH_TIMEOUT_MS` / `STREAM_IDLE_TIMEOUT_MS` ବୃଦ୍ଧି କରନ୍ତି, ତେବେ `proxy_read_timeout` / `proxy_send_timeout`କୁ
ସେହି ସମୟସୀମାଠାରୁ ଅଧିକ କରନ୍ତୁ।

OAuth କଲ୍ବ୍ୟାକ୍ ଏବଂ ସୃଷ୍ଟି ହୋଇଥିବା ସାର୍ବଜନୀନ ଲିଙ୍କଗୁଡ଼ିକ ପାଇଁ OmniRoute, `NEXT_PUBLIC_BASE_URL`କୁ ପ୍ରାମାଣିକ ବ୍ରାଉଜର୍-ମୁଖୀ ଅରିଜିନ୍ ଭାବରେ ବ୍ୟବହାର କରେ।
ପ୍ରମାଣିତ ଡ୍ୟାସ୍ବୋର୍ଡ ଲେଖନ କାର୍ଯ୍ୟଗୁଡ଼ିକ ସମାନ-ଅରିଜିନ୍ ଅନୁରୋଧ ସହିତ
ସେସନ୍-ବାଉଣ୍ଡ CSRF ସୁରକ୍ଷା ବ୍ୟବହାର କରେ, ତେଣୁ ସେଗୁଡ଼ିକ ପାଇଁ ଏକ ସ୍ଥିର ସାର୍ବଜନୀନ ବେସ୍ URL ଆବଶ୍ୟକ ନୁହେଁ। ଉପରୋକ୍ତ
`X-Forwarded-*` ହେଡର୍ଗୁଡ଼ିକ ତଥାପି ଉପଯୋଗୀ ରାଉଟିଂ ମେଟାଡାଟା, କିନ୍ତୁ OAuth କିମ୍ବା ସୃଷ୍ଟି ହୋଇଥିବା ବ୍ରାଉଜର୍ ଲିଙ୍କଗୁଡ଼ିକ ପାଇଁ ଆବଶ୍ୟକ ହେଲେ ସ୍ପଷ୍ଟ ସାର୍ବଜନୀନ URL ସେଟ୍ କରିବାର
ବିକଳ୍ପ ନୁହେଁ। କେବଳ ସେତେବେଳେ
`OMNIROUTE_TRUST_PROXY` ସକ୍ଷମ କରନ୍ତୁ, ଯେତେବେଳେ କ୍ଲାଏଣ୍ଟମାନେ OmniRouteକୁ ସିଧାସଳଖ ପହଞ୍ଚିପାରନ୍ତି ନାହିଁ ଏବଂ ଆପଣଙ୍କ ପ୍ରକ୍ସି
ଆସୁଥିବା ଫରୱାର୍ଡେଡ୍ ହେଡର୍ଗୁଡ଼ିକୁ ହଟାଇ/ପୁନଃନିର୍ମାଣ କରେ।

## କମ୍-ମେମୋରି / ଛୋଟ VPS ଅପ୍ଟିମାଇଜେସନ୍

ଛୋଟ VPS ଇନ୍ଷ୍ଟାନ୍ସଗୁଡ଼ିକରେ (1 GB RAM କିମ୍ବା ତାହାଠାରୁ କମ୍) ଡିପ୍ଲୟମେଣ୍ଟ ପାଇଁ:

- **ପୃଷ୍ଠଭୂମି ସେବାଗୁଡ଼ିକୁ ଅକ୍ଷମ କରନ୍ତୁ** — scheduler, MCP server ଏବଂ ନିୟମିତ ରକ୍ଷଣାବେକ୍ଷଣ କାର୍ଯ୍ୟଗୁଡ଼ିକୁ ଏଡ଼ାଇବା ପାଇଁ `OMNIROUTE_DISABLE_BACKGROUND_SERVICES=1` ସେଟ୍ କରନ୍ତୁ। `docs/reference/ENVIRONMENT.md` ଦେଖନ୍ତୁ।
- **SQLite WAL ମୋଡ୍ ବ୍ୟବହାର କରନ୍ତୁ** — ଏହା ଡିଫଲ୍ଟ ଭାବରେ ସକ୍ଷମ ଏବଂ ଏକକାଳୀନ ରିଡ୍ ସମୟରେ ସର୍ବାଧିକ ମେମୋରି ବ୍ୟବହାରକୁ କମାଏ।
- **V8 heapକୁ ସୀମିତ କରନ୍ତୁ** — `OMNIROUTE_MEMORY_MB` (ଉଦାହରଣସ୍ୱରୂପ `512`) ସେଟ୍ କରନ୍ତୁ, ଯାହାଦ୍ୱାରା runtime, VMଠାରୁ ବଡ଼ ଏକ ସର୍ବୋଚ୍ଚ ସୀମା କ୍ୟାଲିବ୍ରେଟ୍ କରିବ ନାହିଁ। `docs/reference/ENVIRONMENT.md` ଦେଖନ୍ତୁ।
- **ଭାରୀ ଅନୁରୋଧର ଗ୍ରହଣ heap cap ସହିତ ସ୍ୱୟଂଚାଳିତ ଭାବେ ସ୍କେଲ୍ ହୁଏ** -- ଉପରେ `OMNIROUTE_MEMORY_MB` ସେଟ୍ ହେବା ପରେ, ingest byte budget (`OMNIROUTE_CHAT_MAX_INFLIGHT_BYTES`) ସେହି ସର୍ବୋଚ୍ଚ ସୀମାରୁ ନିଜେ ନିର୍ଦ୍ଧାରିତ ହୁଏ। ତେଣୁ ମେମୋରି-ସୀମିତ VM କୌଣସି ଅତିରିକ୍ତ ଟ୍ୟୁନିଂ ବିନା ଏକ ଛୋଟ ଏକକାଳୀନ-ଅନୁରୋଧ ବଜେଟ୍ ପାଏ; ଅତିରିକ୍ତ ଅନୁରୋଧଗୁଡ଼ିକ ମେମୋରି ପାଇଁ ପ୍ରତିଦ୍ୱନ୍ଦ୍ୱିତା କରିବା ପରିବର୍ତ୍ତେ `Retry-After` ସହିତ ପୁନଃଚେଷ୍ଟାଯୋଗ୍ୟ `503` ପାଆନ୍ତି। ଏହା ଉପରେ ଏକ କଠୋର ସର୍ବୋଚ୍ଚ ସୀମା ଆବଶ୍ୟକ ହେଲେ ମାତ୍ର ପୁରୁଣା `OMNIROUTE_CHAT_MAX_HEAVY_IN_FLIGHT` ଅନୁରୋଧ-ସଂଖ୍ୟା cap ସେଟ୍ କରନ୍ତୁ।
- **VPSରେ `next build` ଏଡ଼ାନ୍ତୁ** — ସ୍ଥାନୀୟ ଭାବରେ build କରନ୍ତୁ ଏବଂ standalone output (`.next/standalone/`) deploy କରନ୍ତୁ।
- **`top` / `free -m` ସହିତ ନିରୀକ୍ଷଣ କରନ୍ତୁ** — 1 GB VMରେ ନିଷ୍କ୍ରିୟ ଅବସ୍ଥାରେ OmniRoute ସାଧାରଣତଃ 200-400 MB RSS ବ୍ୟବହାର କରେ।
