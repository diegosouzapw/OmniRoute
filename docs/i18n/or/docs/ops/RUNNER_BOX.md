## ଜାନିଟର୍ ସଂସ୍ଥାପନ କରନ୍ତୁ (କେବଳ ଥରେ, ମେସିନ୍ରେ)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): ପ୍ରତି 30 ମିନିଟ୍ରେ, /var/log/runner-janitor.logରେ ଲଗ୍ କରନ୍ତୁ
*/30 * * * * MAX_ACTIVE_RUNNERS=6 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` ଆବଶ୍ୟକ: କୌଣସି ପଥ ଅପସାରଣ କରିବା ପୂର୍ବରୁ ଜାନିଟର୍ ଖୋଲା
ଫାଇଲ୍ଗୁଡ଼ିକର ଗୋଟିଏ ସ୍ନାପ୍ସଟ୍ ନେଇ ତାହା ନିଷ୍କ୍ରିୟ ବୋଲି ପ୍ରମାଣ କରେ, ଏବଂ ଏହି ଟୁଲ୍ ନଥିଲେ ଏହା କିଛି
ଅପସାରଣ କରେନାହିଁ ଓ ସେହି କଥା ଜଣାଇଦିଏ
(exit 1)। ଯେକୌଣସି ପରିବର୍ତ୍ତନକୁ ପ୍ରଥମେ `--dry-run` ସହିତ ପରୀକ୍ଷା କରନ୍ତୁ — ଏହା କ’ଣ କରିବ ଠିକ୍ ସେହିପରି ପ୍ରିଣ୍ଟ କରେ
ଏବଂ କିଛି ସ୍ପର୍ଶ କରେନାହିଁ।

ପ୍ରତ୍ୟେକ ଥର ଚାଲିବାବେଳେ ଏହା ଯାହା କରେ: **tmpfsରେ 3 ଘଣ୍ଟା** ପରେ ଏବଂ ଡିସ୍କର
`_work/_temp`ରେ 24 ଘଣ୍ଟା ପରେ ଆମର ନିଜସ୍ୱ ଅବଶିଷ୍ଟଗୁଡ଼ିକ (`runner-*`, `omniroute-*`,
`next-build*`, `e2e-build.tar.gz`) ସଫା କରେ; 75 ମିନିଟ୍ରୁ ପୁରୁଣା `next-build`କୁ ବନ୍ଦ କରେ (କୌଣସି ଜବ୍ ଏତେ ସମୟ ଚାଲେନାହିଁ —
2026-08-27ରେ GitHub ତାହାର ଜବ୍କୁ ହଜିଯାଇଛି ବୋଲି ଘୋଷଣା କରିବା ପରେ ମଧ୍ୟ ଗୋଟିଏ 70 ମିନିଟ୍ ଚାଲିଥିଲା); ଯେଉଁ ରନର୍ଗୁଡ଼ିକର ୟୁନିଟ୍ **ବନ୍ଦ ଅଛି**, ସେମାନଙ୍କର
48 ଘଣ୍ଟା ପୁରୁଣା ଚେକ୍ଆଉଟ୍ଗୁଡ଼ିକୁ ହଟାଏ; ଡିସ୍କ ≥ 85 %, ମେମୋରି PSI
`full/avg60` ≥ 10 %, ଏବଂ `MAX_ACTIVE_RUNNERS`ଠାରୁ ଅଧିକ ଲିସ୍ନର୍ ଥିଲେ ସତର୍କ କରେ (omniroute/ଅନ୍ୟାନ୍ୟ
ବିଭାଜନ ସହିତ)। Exit 1 = ଧ୍ୟାନ ଦେବା ଆବଶ୍ୟକ; ଲଗ୍ ପଢ଼ନ୍ତୁ।

## ରନର୍ ୟୁନିଟ୍ଗୁଡ଼ିକ: KillMode

ରନର୍ର ଡିଫଲ୍ଟ `KillMode=process`, ଗୋଟିଏ ୟୁନିଟ୍କୁ ବନ୍ଦ କିମ୍ବା ପୁନଃଚାଳୁ କରାଗଲେ `Runner.Worker → npm → next-build`
କୁ ସକ୍ରିୟ ରଖିଦିଏ — କୌଣସି ଜବ୍ ସଂଲଗ୍ନ ନଥିଲେ ମଧ୍ୟ ଏକ ଅନାଥ ବିଲ୍ଡ RAM ଏବଂ
CPU ବ୍ୟବହାର କରିଚାଲେ। ପ୍ରତ୍ୟେକ OmniRoute ୟୁନିଟ୍ରେ ଏକ ଡ୍ରପ୍-ଇନ୍
(`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`)
ରହିଛି, ଯେଉଁଥିରେ `KillMode=mixed` ଅଛି: ପ୍ରଥମେ ଲିସନର୍କୁ SIGTERM, ଏବଂ
`TimeoutStop` ସମୟରେ ସମଗ୍ର cgroupକୁ SIGKILL। ୟୁନିଟ୍ର ପରବର୍ତ୍ତୀ ପୁନଃଚାଳନରେ ଏହା ପ୍ରଭାବୀ ହୁଏ — ଏକ ସମୟରେ **କେବଳ ଗୋଟିଏ ରନର୍କୁ,
ଏବଂ ତାହା ନିଷ୍କ୍ରିୟ ଥିବାବେଳେ ମାତ୍ର** ପୁନଃଚାଳୁ କରନ୍ତୁ, ନିଷ୍କ୍ରିୟତା ଯାଞ୍ଚ ଏବଂ ପୁନଃଚାଳନକୁ ସମାନ କମାଣ୍ଡରେ ରଖନ୍ତୁ।

## ପରିଚାଳନା ନିୟମାବଳୀ

  `[self-hosted, omni-build]`କୁ ଲକ୍ଷ୍ୟ କରେ, ଏବଂ କେବଳ
  **`omniroute-113-5`** ପାଖରେ ସେହି ଲେବଲ୍ ରହିଛି (ରନର୍ API ମାଧ୍ୟମରେ ଯୋଡ଼ାଯାଇଛି — କୌଣସି
  ପୁନଃ-ପଞ୍ଜୀକରଣ ନାହିଁ): `ci.yml` `Build`, `npm-publish.yml` `publish`, ଉଭୟ
  `nightly-release-green` ବୈଧତା ଯାଞ୍ଚ, ଏବଂ `docker-publish.yml` **amd64** (ଏହି ଟ୍ରିରେ ହୋଷ୍ଟ କରାଯାଇଥିବା
  7 GB ResourceExhausted — #11976)। arm64 Docker ଲେଗ୍ webpack ସହିତ
  `ubuntu-24.04-arm`ରେ ରହେ (କୌଣସି ARM ବକ୍ସ ନାହିଁ)। Docker amd64 ମଧ୍ୟ webpack ବ୍ୟବହାର କରେ:
  31 GB ଥିଲେ ମଧ୍ୟ ଏହି ଟ୍ରିରେ Turbopack, BuildKit ଭିତରେ ପ୍ୟାନିକ୍ କରିଥିଲା (`TurbopackInternalError:
there must be a path to a root`, ରନ୍ 33253576569); ସମାନ
  ଟ୍ରିର arm64 webpack ବିଲ୍ଡ ହୋଷ୍ଟେଡ୍ ARMରେ ସଫଳ ହୋଇଥିଲା। `docker-publish` amd64,
  `ci.yml` `Build` ସହିତ `heavy-build-main` କନ୍କରେନ୍ସି ଗ୍ରୁପ୍ ଅଂଶୀଦାର କରେ
  (`cancel-in-progress: false`), ତେଣୁ ଏହା ଏକମାତ୍ର ସ୍ଲଟ୍ ପାଇଁ କ୍ୟୁରେ ରହେ। Docker Engine
  ନିଶ୍ଚିତ ଭାବେ `omniroute-113-5`ରେ ଥିବା ଆବଶ୍ୟକ (`docker info` ହେଉଛି ପବ୍ଲିଶ୍
  ଜବ୍ର ପ୍ରଥମ ପଦକ୍ଷେପ)। 31 GB ପାଇଁ ପୂର୍ବର ଦୁଇଟି ସୀମା ଭୁଲ୍ ଥିଲା:
  2026-08-29 17:26 UTCରେ ଦୁଇଟି ସମକାଳୀନ `next-build` (15.4 GB + 17.2 GB RSS) ବକ୍ସର
  ଖାଲି ସ୍ଥାନକୁ 5 GBକୁ ଖସାଇଥିଲା, 4 GB swap ବ୍ୟବହୃତ ହୋଇଥିଲା ଏବଂ kernel ସେଗୁଡ଼ିକ ମଧ୍ୟରୁ ଗୋଟିଏକୁ OOM-kill କରିଥିଲା — systemd
