OmniRoute **CLI ଆବିଷ୍କାର**, **ନେଟିଭ୍ Agent Client Protocol**, ଏବଂ
**ପୁରୁଣା stdio ଆଡାପ୍ଟରଗୁଡ଼ିକୁ** ପୃଥକ୍ କରେ। ଏକ ଇନ୍ଷ୍ଟଲ୍ ହୋଇଥିବା ବାଇନାରି ମିଳିବା ତାହାର
ପ୍ରମାଣୀକରଣ, ମଡେଲ୍ ସୁସଙ୍ଗତତା, କିମ୍ବା ଏକ ପ୍ରମ୍ପ୍ଟ ପରିଚାଳନା କରିବାର ପ୍ରସ୍ତୁତିକୁ ପ୍ରମାଣିତ କରେ ନାହିଁ।

ଡ୍ୟାସ୍ବୋର୍ଡ ଇନ୍ଭେଣ୍ଟୋରି ଏବଂ କଷ୍ଟମ୍-ଏଜେଣ୍ଟ ପଞ୍ଜୀକରଣ ପାଇଁ `GET /api/acp/agents` ଏବଂ
`POST /api/acp/agents` ବ୍ୟବହାର କରେ। ଏଗୁଡ଼ିକ କେବଳ ସ୍ଥାନୀୟ ପରିଚାଳନା ରୁଟ୍, ପ୍ରକ୍ରିୟା
ଆରମ୍ଭ କରିବା କିମ୍ବା ପ୍ରମ୍ପ୍ଟ ଦାଖଲ କରିବା ପାଇଁ କୌଣସି ସାର୍ବଜନୀନ API ନୁହେଁ। ଆଭ୍ୟନ୍ତରୀଣ
`AcpManager` ସ୍ୱୟଂଚାଳିତ ଭାବରେ ଏକ HTTP ପ୍ରଦାତା ଫଲ୍ବ୍ୟାକ୍ ହୁଏ ନାହିଁ।

## ପଞ୍ଜୀକୃତ ଚୁକ୍ତିଗୁଡ଼ିକ

ବିଲ୍ଟ-ଇନ୍ ଲଞ୍ଚ୍ ବାଇନାରି, ଆର୍ଗୁମେଣ୍ଟ ଏବଂ ବ୍ୟାକେଣ୍ଡ ମୋଡ୍ ପାଇଁ
`config/cli-tools-manifest.json` ହେଉଛି ପ୍ରାମାଣିକ ଉତ୍ସ। ରେଜିଷ୍ଟ୍ରି ସେହି ମାନିଫେଷ୍ଟରୁ
ନିଜର ସଂଜ୍ଞାଗୁଡ଼ିକ ବ୍ୟୁତ୍ପନ୍ନ କରେ। ଚିହ୍ନଟ ଫଳାଫଳ 60 ସେକେଣ୍ଡ ପାଇଁ କ୍ୟାଶ୍ କରାଯାଏ।

- `acp`: Gemini ଚୁକ୍ତି `gemini --experimental-acp` ଆରମ୍ଭ କରେ ଏବଂ ଅଧିକୃତ
  TypeScript SDK ମାଧ୍ୟମରେ ନୂଆ-ଧାଡ଼ି ଦ୍ୱାରା ପୃଥକ୍ ACP JSON-RPC ବ୍ୟବହାର କରି ଯୋଗାଯୋଗ କରେ।
- `stdio-adapter`: ଅନ୍ୟ ପଞ୍ଜୀକୃତ ଚୁକ୍ତିଗୁଡ଼ିକ ପୁରୁଣା ନୂଆ-ଧାଡ଼ି-ଇନ୍ପୁଟ୍,
  stdout-ଆଉଟ୍ପୁଟ୍ ଆଡାପ୍ଟରକୁ ବଜାୟ ରଖନ୍ତି। ଦୁଇ-ସେକେଣ୍ଡର ଆଉଟ୍ପୁଟ୍ ନିଷ୍କ୍ରିୟ ଅବଧି ଏହାର ପ୍ରତିକ୍ରିୟାକୁ ସମାପ୍ତ କରେ।
  ଏହି ଆଡାପ୍ଟର ସେହି CLIଗୁଡ଼ିକ ପାଇଁ ନେଟିଭ୍ ACP ସମର୍ଥନକୁ **ପ୍ରମାଣିତ କରେ ନାହିଁ**।

Gemini ଏହାର [CLI ସନ୍ଦର୍ଭ](https://geminicli.com/docs/cli/cli-reference/)ରେ ଲଞ୍ଚ୍ ଫ୍ଲାଗ୍କୁ ଦଲିଲଭୁକ୍ତ କରେ।
କ୍ଲାଏଣ୍ଟ ଆରମ୍ଭୀକରଣ, ସେସନ୍ ସୃଷ୍ଟି, ପ୍ରମ୍ପ୍ଟ ଅନୁରୋଧ, ବିଜ୍ଞପ୍ତି ଏବଂ ବାତିଲ୍ ପାଇଁ
[ଅଧିକୃତ ACP SDK](https://github.com/agentclientprotocol/typescript-sdk) ବ୍ୟବହାର କରେ।

କଷ୍ଟମ୍-ଏଜେଣ୍ଟ ସଂଜ୍ଞାଗୁଡ଼ିକ ପ୍ରଶାସକ-ନିୟନ୍ତ୍ରିତ ଲଞ୍ଚ୍ ଚୁକ୍ତି ଭାବରେ ରହେ।
ଏକ ବାଇନାରି ଏବଂ ଆର୍ଗୁମେଣ୍ଟ ପଞ୍ଜୀକରଣ କରିବା ସେହି ପ୍ରକ୍ରିୟାକୁ ସର୍ଭର ବ୍ୟବହାରକାରୀଙ୍କ ସ୍ଥାନୀୟ
ନିଷ୍ପାଦନ ଅଧିକାର ପ୍ରଦାନ କରେ; ପଞ୍ଜୀକରଣ କୌଣସି ସ୍ୟାଣ୍ଡବକ୍ସ ନୁହେଁ। ସଂସ୍କରଣ ଯାଞ୍ଚ କେବଳ
ପଞ୍ଜୀକୃତ ଏକ୍ସିକ୍ୟୁଟେବଲ୍ ଏବଂ ଏକ ସ୍ୱୀକୃତ ସଂସ୍କରଣ ଫ୍ଲାଗ୍କୁ ଗ୍ରହଣ କରେ।

## ଆଭ୍ୟନ୍ତରୀଣ ଲଞ୍ଚ୍ API

```typescript
import { acpManager } from "@/lib/acp";

const session = acpManager.spawn("gemini", {
  cwd: process.cwd(),
  // କେବଳ ଏହି ଏଜେଣ୍ଟକୁ ଉଦ୍ଦେଶ୍ୟମୂଳକ ଭାବରେ ନ୍ୟସ୍ତ କରାଯାଇଥିବା ପ୍ରଦାତା ଭେରିଏବଲ୍ଗୁଡ଼ିକୁ ପାସ୍ କରନ୍ତୁ।
  env: {
    GEMINI_API_KEY: process.env.GEMINI_API_KEY,
  },
});

try {
  const response = await acpManager.sendPrompt(
    session.id,
    "ଏହି ପ୍ରୋଜେକ୍ଟକୁ ବ୍ୟାଖ୍ୟା କରନ୍ତୁ",
    120_000
  );
  // କଲ୍ କରୁଥିବା ଆପ୍ଲିକେସନ୍ରେ ପ୍ରତିକ୍ରିୟାକୁ ବ୍ୟବହାର କରନ୍ତୁ।
} finally {
  acpManager.kill(session.id);
}
```

`spawn(agentId, options)` ପଞ୍ଜୀକୃତ ସଂଜ୍ଞାରୁ ଏକ୍ସିକ୍ୟୁଟେବଲ୍ ଏବଂ ଆର୍ଗୁମେଣ୍ଟଗୁଡ଼ିକୁ
ସମାଧାନ କରେ। କଲ୍ କରୁଥିବା ବ୍ୟକ୍ତିଙ୍କ ପାଇଁ କେବଳ `cwd` ଏବଂ `env` ବିକଳ୍ପ ଉପଲବ୍ଧ; ପୁରୁଣା
`spawn(agentId, binary, args, env)` ସିଗ୍ନେଚର୍ ଏବଂ ଏକ୍ସିକ୍ୟୁଟେବଲ୍ ଓଭର୍ରାଇଡ୍ଗୁଡ଼ିକୁ
ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଏ। ଏହି ମ୍ୟାନେଜର୍ HTTP ଲଞ୍ଚ୍ ଚୁକ୍ତିଗୁଡ଼ିକୁ ସମର୍ଥନ କରେ ନାହିଁ।

ଚାଇଲ୍ଡ ପ୍ରକ୍ରିୟା CLI ଲଞ୍ଚର୍ଗୁଡ଼ିକ ପରି ସମାନ ଅପରେଟିଂ-ସିଷ୍ଟମ୍, ଟର୍ମିନାଲ୍, ଲୋକେଲ୍ ଏବଂ ସର୍ଟିଫିକେଟ୍
ଅନୁମୋଦିତ-ତାଲିକା ଉତ୍ତରାଧିକାରରେ ପାଏ। ସର୍ଭର୍/ପ୍ରଦାତା ଗୁପ୍ତ ତଥ୍ୟଗୁଡ଼ିକ ପ୍ୟାରେଣ୍ଟ
ପରିବେଶରୁ କପି କରାଯାଏ ନାହିଁ। ଚୟନିତ CLI ପାଇଁ ଆବଶ୍ୟକ କ୍ରେଡେନ୍ସିଆଲ୍ଗୁଡ଼ିକୁ
ସ୍ପଷ୍ଟ ଭାବରେ ପାସ୍ କରିବା କିମ୍ବା ସେହି CLIର ନିଜସ୍ୱ ସ୍ଥାନୀୟ ପ୍ରମାଣୀକରଣ ମାଧ୍ୟମରେ ଯୋଗାଇବା ଆବଶ୍ୟକ।
ଚାଇଲ୍ଡ ତଥାପି ସ୍ଥାନୀୟ ବ୍ୟବହାରକାରୀଙ୍କ ଫାଇଲ୍ସିଷ୍ଟମ୍ ଅନୁମତିଗୁଡ଼ିକ ପାଏ ଏବଂ ନିଜ କନ୍ଫିଗ୍ ପଢ଼ିପାରେ।

## ନେଟିଭ୍ ଜୀବନଚକ୍ର ଏବଂ ସୀମାଗୁଡ଼ିକ

1. ପଞ୍ଜୀକୃତ ବାଇନାରିକୁ ଆରମ୍ଭ କରନ୍ତୁ, ACPକୁ ଆରମ୍ଭୀକରଣ କରନ୍ତୁ, ଏବଂ
   ଚୟନିତ କାର୍ଯ୍ୟକାରୀ ଡିରେକ୍ଟୋରିରେ ରୁଟ୍ ହୋଇଥିବା ଏକ ସେସନ୍ ସୃଷ୍ଟି କରନ୍ତୁ। ଆରମ୍ଭୀକରଣ ପାଇଁ ଦଶ-ସେକେଣ୍ଡର ସୀମା ରହିଛି।
2. ଏକ ପ୍ରମ୍ପ୍ଟ ଦାଖଲ କରନ୍ତୁ ଏବଂ କେବଳ ସେହି ସେସନ୍ ପାଇଁ ଟେକ୍ସଟ୍ ବିଜ୍ଞପ୍ତିଗୁଡ଼ିକ ସଂଗ୍ରହ କରନ୍ତୁ।
   ସମାପ୍ତି ହେଉଛି ପ୍ରମ୍ପ୍ଟ RPC ପ୍ରତିକ୍ରିୟା, stdout ନିରବତାର କୌଣସି ଅବଧି ନୁହେଁ।
3. ଅସମାପ୍ତ ଆରମ୍ଭୀକରଣ ସମେତ ଗୋଟିଏ ପ୍ରମ୍ପ୍ଟ ସମୟସୀମା ବ୍ୟବହାର କରନ୍ତୁ; ଡିଫଲ୍ଟ
   ହେଉଛି 120 ସେକେଣ୍ଡ। ସମାନ ପ୍ରକ୍ରିୟାରେ ସମକାଳୀନ ପ୍ରମ୍ପ୍ଟଗୁଡ଼ିକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଏ।
4. ନେଟିଭ୍ ସମୟସୀମା ଅତିକ୍ରମ ହେଲେ, `session/cancel` ଚେଷ୍ଟା କରନ୍ତୁ ଏବଂ ପ୍ରକ୍ରିୟାକୁ ସମାପ୍ତ କରନ୍ତୁ।
   ସମାପ୍ତି ପୂର୍ବରୁ ଏକ ସୀମିତ 100 ms ୱିଣ୍ଡୋ ବିଜ୍ଞପ୍ତିକୁ ଫ୍ଲସ୍ ହେବାକୁ ଦିଏ।
5. ଆରମ୍ଭୀକରଣ ବିଫଳ ହେଲେ, ସଂଯୋଗ ବନ୍ଦ ହେଲେ, ପ୍ରକ୍ରିୟା ପ୍ରସ୍ଥାନ କଲେ, କିମ୍ବା
   କଲ୍ କରୁଥିବା ବ୍ୟକ୍ତି ଏହାକୁ ବନ୍ଦ କଲେ, ପରିବହନ ଅବସ୍ଥା ବନ୍ଦ କରନ୍ତୁ ଏବଂ ସେସନ୍କୁ ଅପସାରଣ କରନ୍ତୁ।

ଟୁଲ୍ ଅନୁମତି ଅନୁରୋଧଗୁଡ଼ିକୁ ଅସ୍ୱୀକାର କରାଯାଏ। କୌଣସି ଫାଇଲ୍ସିଷ୍ଟମ୍ କିମ୍ବା ଟର୍ମିନାଲ୍ କ୍ଲାଏଣ୍ଟ
କ୍ଷମତାର ବିଜ୍ଞାପନ କରାଯାଏ ନାହିଁ। ଏହି ପ୍ରତିବନ୍ଧଗୁଡ଼ିକ ଚାଇଲ୍ଡ ବାଇନାରିକୁ
ସ୍ୟାଣ୍ଡବକ୍ସ କରେ ନାହିଁ କିମ୍ବା CLIର ନିଜସ୍ୱ ପ୍ରାଧିକରଣ ସେଟିଂସ୍କୁ ପ୍ରତିସ୍ଥାପନ କରେ ନାହିଁ।

ଉଭୟ ନେଟିଭ୍ ଟେକ୍ସଟ୍ ଏବଂ ପୁରୁଣା stdout/stderr ସର୍ବାଧିକ 1 MiB ଅକ୍ଷର ରଖନ୍ତି,
ଏକ କର୍ତ୍ତନ ସୂଚନା ସହ ସବୁଠାରୁ ନୂତନ ଆଉଟ୍ପୁଟ୍କୁ ରଖନ୍ତି। SDK ପାର୍ସିଂ ପୂର୍ବରୁ ଏକକ ନେଟିଭ୍ ୱାୟାର୍
ଫ୍ରେମ୍ 2 MiB ବାଇଟ୍ରେ ସୀମିତ। ପ୍ରତ୍ୟେକ ପ୍ରମ୍ପ୍ଟ ପାଇଁ ବଫର୍ଗୁଡ଼ିକ ରିସେଟ୍ ହୁଅନ୍ତି।

`kill(sessionId)` SIGTERM ପଠାଏ, ତା'ପରେ ପ୍ରକ୍ରିୟାଟି ପ୍ରସ୍ଥାନ ନ କରିଥିଲେ ପାଞ୍ଚ ସେକେଣ୍ଡ ପରେ
SIGKILL ପଠାଏ। ପୁରୁଣା ପ୍ରମ୍ପ୍ଟ ସମୟସୀମା ଅତିକ୍ରମଗୁଡ଼ିକ ଲିସନର୍ ଏବଂ ଟାଇମର୍ଗୁଡ଼ିକୁ ମୁକ୍ତ କରନ୍ତି, କିନ୍ତୁ
ଅନ୍ୟ ଏକ ପ୍ରମ୍ପ୍ଟ ପାଇଁ ସେସନ୍କୁ ଉପଲବ୍ଧ ରଖନ୍ତି; କାର୍ଯ୍ୟ ସମାପ୍ତ ହେଲେ କଲ୍ କରୁଥିବା ବ୍ୟକ୍ତିମାନେ
`kill()` କିମ୍ବା `killAll()` ପାଇଁ ଦାୟୀ ରହନ୍ତି।

## ଇଭେଣ୍ଟ ଏବଂ ନିରୀକ୍ଷଣ

ମ୍ୟାନେଜର୍ `stdout`, `stderr`, ଏବଂ `exit` ନିର୍ଗତ କରେ, ପ୍ରତ୍ୟେକରେ `sessionId` ଥାଏ।
`sessionError` ଏକ ସାନିଟାଇଜ୍ କରାଯାଇଥିବା ପରିବହନ ତ୍ରୁଟି ରିପୋର୍ଟ କରେ। ସୁସଙ୍ଗତତା `error`
ଇଭେଣ୍ଟ କେବଳ ଏହାର ଜଣେ ସବ୍ସ୍କ୍ରାଇବର୍ ଥିଲେ ନିର୍ଗତ ହୁଏ, ତେଣୁ ଏକ ଅନୁପସ୍ଥିତ ବାଇନାରି
ଏକ ଅଣପରିଚାଳିତ EventEmitter ତ୍ରୁଟି ସୃଷ୍ଟି କରିପାରିବ ନାହିଁ।

- `getSession(sessionId)` ଏକ ପରିଚାଳିତ ସେସନ୍ କିମ୍ବା `undefined` ଫେରାଏ।
- `getActiveSessions()` ବନ୍ଦ କିମ୍ବା ବନ୍ଦ ହେଉଥିବା ସେସନ୍ଗୁଡ଼ିକୁ ବାଦ ଦିଏ।
- `sendInput(sessionId, input)` କେବଳ ଏକ ସକ୍ରିୟ ପୁରୁଣା ଆଡାପ୍ଟର୍ ପାଇଁ ଉପଲବ୍ଧ;
  ନିଜ JSON-RPC ଷ୍ଟ୍ରିମ୍କୁ ସୁରକ୍ଷିତ ରଖିବା ପାଇଁ ନେଟିଭ୍ ACP କଞ୍ଚା ଇନ୍ପୁଟ୍କୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ।
- `killAll()` ସେହି ଇନ୍ଷ୍ଟାନ୍ସ ଦ୍ୱାରା ପରିଚାଳିତ ପ୍ରତ୍ୟେକ ସେସନ୍କୁ ସମାପ୍ତ କରେ।

## ବୈଧତା ଯାଞ୍ଚର ସୀମାଗୁଡ଼ିକ

ନିର୍ଦ୍ଧାରଣଯୋଗ୍ୟ ଫିକ୍ସଚର୍ଗୁଡ଼ିକ ନେଟିଭ୍ ହ୍ୟାଣ୍ଡଶେକ୍, ଟେକ୍ସଟ୍ ଆଉଟ୍ପୁଟ୍, ଅସ୍ୱୀକୃତ
ଅନୁମତି, ବାତିଲ୍, ସମକାଳୀନ ପ୍ରମ୍ପ୍ଟ, ବିଫଳ ଆରମ୍ଭୀକରଣ, ପ୍ରକ୍ରିୟା
ପ୍ରସ୍ଥାନ, ଆଉଟ୍ପୁଟ୍ ସୀମା, ଏବଂ ଗୁପ୍ତ ତଥ୍ୟ ପୃଥକୀକରଣକୁ ଅନ୍ତର୍ଭୁକ୍ତ କରେ। ବିଦ୍ୟମାନ ପୁରୁଣା ବଫର୍/ଲିସନର୍
ରିଗ୍ରେସନ୍ଗୁଡ଼ିକ ମଧ୍ୟ ଅନ୍ତର୍ଭୁକ୍ତ ରହିଛି। ଏହି ପରୀକ୍ଷଣଗୁଡ଼ିକ ଏକ ସକ୍ରିୟ Gemini ଲଗ୍ଇନ୍
କିମ୍ବା ସଫଳ ପ୍ରଦାତା ଅନୁମାନକୁ ପ୍ରଦର୍ଶନ କରେ ନାହିଁ; ସେଗୁଡ଼ିକ ପାଇଁ ଲକ୍ଷ୍ୟ ପରିବେଶରେ ପୃଥକ୍ ଭାବେ ପ୍ରାଧିକୃତ ସ୍ମୋକ୍
ପରୀକ୍ଷଣ ଆବଶ୍ୟକ।
