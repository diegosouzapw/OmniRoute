> **TL;DR**: `open-sse/` ହେଉଛି ମୂଳ ଷ୍ଟ୍ରିମିଂ ଇଞ୍ଜିନ୍, ଯାହା OmniRouteର ପ୍ରତ୍ୟେକ LLM ଅନୁରୋଧକୁ ପରିଚାଳିତ କରେ। ଏଥିରେ ଅନୁରୋଧ ପାଇପଲାଇନ୍, ଏକ୍ଜିକ୍ୟୁଟର୍, ସେବା, MCP ସର୍ଭର୍ ଏବଂ ଅନୁବାଦ ସ୍ତର କାର୍ଯ୍ୟକାରୀ କରୁଥିବା ~1,400ଟି ଫାଇଲ୍ ରହିଛି। ଏହି ମାର୍ଗଦର୍ଶିକାରେ ବିଭିନ୍ନ ଅଂଶ କିପରି ଏକାଠି କାମ କରେ ତାହା ବ୍ୟାଖ୍ୟା କରାଯାଇଛି।

**ଉତ୍ସ:** `open-sse/` (ୱର୍କସ୍ପେସ୍ ପ୍ୟାକେଜ୍, ~1,440ଟି ପରୀକ୍ଷଣ-ବହିର୍ଭୂତ `.ts` ଫାଇଲ୍)

## ଏକ ପୃଥକ ୱର୍କସ୍ପେସ୍ ପ୍ୟାକେଜ୍ କାହିଁକି?

ବିଭିନ୍ନ କାରଣରୁ `open-sse/` OmniRoute ମନୋରେପୋରେ ଏକ **ସ୍ୱତନ୍ତ୍ର ୱର୍କସ୍ପେସ୍**:

1. **ପୁନଃବ୍ୟବହାରଯୋଗ୍ୟତା** — `open-sse`କୁ npmରେ `@omniroute/open-sse` ଭାବରେ ପ୍ରକାଶ କରାଯାଏ, ତେଣୁ ଅନ୍ୟ ପ୍ରକଳ୍ପଗୁଡ଼ିକ ଏହାକୁ ସ୍ୱାଧୀନ ଭାବରେ ବ୍ୟବହାର କରିପାରିବେ
2. **ସ୍ପଷ୍ଟ ସୀମା** — ଷ୍ଟ୍ରିମିଂ ଇଞ୍ଜିନ୍କୁ OmniRoute-ନିର୍ଦ୍ଦିଷ୍ଟ UI/DB ସ୍ତରଠାରୁ ପୃଥକ ରଖାଯାଇଛି
3. **କାର୍ଯ୍ୟଦକ୍ଷତା** — ଇଞ୍ଜିନ୍ରେ କୌଣସି Next.js ନିର୍ଭରତା ନାହିଁ, ଯାହା CLI/ସର୍ଭର୍ଲେସ୍ ପରିପ୍ରେକ୍ଷୀରେ ଦ୍ରୁତ କୋଲ୍ଡ ଷ୍ଟାର୍ଟ ସକ୍ଷମ କରେ
4. **ସଂସ୍କରଣ ପରିଚାଳନା** — `open-sse` ନିଜସ୍ୱ ସମୟସୂଚୀ ଅନୁଯାୟୀ ରିଲିଜ୍ କରିପାରେ

```json
// package.json
"workspaces": ["open-sse"]
```

### ପର୍ଯ୍ୟାୟ 1: ରାଉଟ୍ (services/combo.ts)

**ପ୍ରବେଶ ବିନ୍ଦୁ**: `services/combo.ts`ରେ `handleComboChat()`

ଅନୁରୋଧକୁ ଏକ ନିର୍ଦ୍ଦିଷ୍ଟ `(provider, model, account, credentials)` ଟ୍ୟୁପଲ୍ରେ ସମାଧାନ କରେ:

- ID ଦ୍ୱାରା କମ୍ବୋଟି ଖୋଜନ୍ତୁ (କିମ୍ବା `auto/*` ମଡେଲ୍ ପାଇଁ ଏକ ଭର୍ଚୁଆଲ୍ କମ୍ବୋ ନିର୍ମାଣ କରନ୍ତୁ)
- ରାଉଟିଂ କୌଶଳ ପ୍ରୟୋଗ କରନ୍ତୁ (ପ୍ରାଥମିକତା, ଓଜନଯୁକ୍ତ, ରାଉଣ୍ଡ-ରବିନ୍, ଇତ୍ୟାଦି)
- ଅସ୍ୱାସ୍ଥ୍ୟକର ପ୍ରଦାନକାରୀଙ୍କୁ ବାଦ ଦିଅନ୍ତୁ (ସର୍କିଟ୍ ବ୍ରେକର୍)
- ପରବର୍ତ୍ତୀ ଉପଯୋଗଯୋଗ୍ୟ ଲକ୍ଷ୍ୟ ଚୟନ କରନ୍ତୁ

`auto/*` ମଡେଲ୍ ପାଇଁ ଏହି ପର୍ଯ୍ୟାୟ ଆହୁରି:

- **16-କାରକ ସ୍କୋରିଂ** ଆଲଗୋରିଦମ୍ (`services/autoCombo/`) ଚଲାଏ
- ସ୍ୱାସ୍ଥ୍ୟ, ମୂଲ୍ୟ, ବିଳମ୍ବତା ଇତ୍ୟାଦି ଆଧାରରେ ଏକ `provider+model` ଯୁଗଳ ଚୟନ କରେ

### ପର୍ଯ୍ୟାୟ 2: ଅନୁବାଦ (translator/)

ଯଦି ଉତ୍ସ ଫର୍ମାଟ୍ (ଯଥା, OpenAI) ଲକ୍ଷ୍ୟ ଫର୍ମାଟ୍ଠାରୁ (ଯଥା, Claude) ଭିନ୍ନ ହୁଏ, ତେବେ ଅନୁରୋଧଟି **ଅନୁବାଦ** କରାଯାଏ:

- ସିଷ୍ଟମ୍ ପ୍ରମ୍ପ୍ଟ → ସିଷ୍ଟମ୍ ସନ୍ଦେଶ
- ଟୁଲ୍ ସଂଜ୍ଞା → ପ୍ରଦାନକାରୀ-ନିର୍ଦ୍ଦିଷ୍ଟ ଟୁଲ୍ ଫର୍ମାଟ୍
- ଯୁକ୍ତି/ଚିନ୍ତନ ପାରାମିଟର୍ → ପ୍ରଦାନକାରୀ-ନିର୍ଦ୍ଦିଷ୍ଟ ସମତୁଲ୍ୟ
- ସନ୍ଦେଶ ଭୂମିକା ସାମାନ୍ୟୀକରଣ (OpenAI ବ୍ୟତୀତ ଅନ୍ୟମାନଙ୍କ ପାଇଁ `developer` → `system`)

`translator/index.ts` ନିମ୍ନଲିଖିତଗୁଡ଼ିକୁ ଉପଲବ୍ଧ କରାଏ:

```ts
translateRequest(body, sourceFormat, targetFormat): TranslatedRequest
needsTranslation(source, target): boolean
```

### ପର୍ଯ୍ୟାୟ 3: ନିଷ୍ପାଦନ (executors/)

**ପ୍ରବେଶ ବିନ୍ଦୁ**: `getExecutor(providerId).execute(request, options)`

ସମସ୍ତ ପ୍ରଦାନକାରୀ `getExecutor()` ଫ୍ୟାକ୍ଟରି ଫଲ୍ବ୍ୟାକ୍ ମାଧ୍ୟମରେ `DefaultExecutor` (`executors/default.ts`) ବ୍ୟବହାର କରନ୍ତି। ଏକ୍ଜିକ୍ୟୁଟର୍:

- ଅପ୍ଷ୍ଟ୍ରିମ୍ URL ନିର୍ମାଣ କରେ (`buildUrl()`)
- ପ୍ରଦାନକାରୀ-ନିର୍ଦ୍ଦିଷ୍ଟ ହେଡର୍ ଯୋଡ଼େ (`buildHeaders()`)
- ଅନୁରୋଧ ବଡିକୁ ରୂପାନ୍ତର କରେ (`transformRequest()`)
- ପୁନଃଚେଷ୍ଟା + ଏକ୍ସପୋନେନ୍ସିଆଲ୍ ବ୍ୟାକଅଫ୍ ସହିତ HTTP ଅନୁରୋଧ ପଠାଏ
- ଆବଶ୍ୟକ ହେଲେ ପ୍ରମାଣୀକରଣ ରିଫ୍ରେଶ୍ ପରିଚାଳନା କରେ (OAuth ପ୍ରଦାନକାରୀ)

ସମସ୍ତ ଏକ୍ଜିକ୍ୟୁଟର୍ `BaseExecutor` (`executors/base.ts`, 1170 LOC)କୁ ବିସ୍ତାର କରନ୍ତି, ଯାହା ନିମ୍ନଲିଖିତ ପ୍ରଦାନ କରେ:

- ସାଧାରଣ ପୁନଃଚେଷ୍ଟା ତର୍କ
- ପ୍ରକ୍ସି ଏକୀକରଣ
- ସର୍କିଟ୍ ବ୍ରେକର୍ ଏକୀକରଣ
- ବ୍ୟବହାର ରେକର୍ଡିଂ ହୁକ୍

### chatCore.ts (5977 ଧାଡ଼ି)

**ମୁଖ୍ୟ ଅନୁରୋଧ ପରିଚାଳକ (request handler)**। ଏହାର ଆକାର ସତ୍ତ୍ୱେ, ଏହାର ଏକ ସ୍ପଷ୍ଟ ସଂରଚନା ଅଛି:

```ts
// chatCore.ts ର ଛଦ୍ମ-ସଂରଚନା
export async function handleChat(request: NextRequest) {
  // 1. ପ୍ରାମାଣୀକରଣ (Auth) + CORS
  await authenticateRequest(request);
  applyCorsHeaders(response);

  // 2. Body ବୈଧତା ଯାଞ୍ଚ
  const body = await parseRequestBody(request);

  // 3. Format ଚିହ୍ନଟ + ଅନୁବାଦ
  const sourceFormat = detectFormat(request);
  const targetFormat = getTargetFormat(providerId);
  if (needsTranslation(sourceFormat, targetFormat)) {
    body = translateRequest(body, sourceFormat, targetFormat);
  }

  // 4. Combo ରାଉଟିଂ
  const targets = await resolveComboTargets(comboId, body);
  for (const target of targets) {
    try {
      const result = await executeOnTarget(target, body);
      await recordUsage(result);
      return result;
    } catch (err) {
      // ପରବର୍ତ୍ତୀ target କୁ ଆଗକୁ ବଢ଼ନ୍ତୁ
    }
  }

  // 5. ଜରୁରୀକାଳୀନ fallback
  return await emergencyFallback(body);
}
```

ଏହା ଗୋଟିଏ ବିଶାଳ ଫଙ୍କସନ୍ ହେଲେ ମଧ୍ୟ, ଏହା **ମନ୍ତବ୍ୟ-ଚିହ୍ନିତ ବିଭାଗଗୁଡ଼ିକରେ** ସଜାଡ଼ା ହୋଇଛି ଯାହା 5-ପର୍ଯ୍ୟାୟ pipeline ସହ ମେଳ ଖାଏ।

## ଏକ୍ସିକ୍ୟୁଟରଗୁଡ଼ିକ (150 ମଡ୍ୟୁଲ୍)

ଅଧିକାଂଶ କ୍ଷେତ୍ରରେ ପ୍ରତି ପ୍ରୋଭାଇଡର ପାଇଁ ଗୋଟିଏ ଫାଇଲ୍। ଏକ୍ସିକ୍ୟୁଟର କ୍ଲାସଗୁଡ଼ିକ ସମସ୍ତେ `BaseExecutor` କୁ ବିସ୍ତାର କରନ୍ତି ଏବଂ ଯାହା ଭିନ୍ନ ତାହାକୁ ଓଭରରାଇଡ୍ କରନ୍ତି; ଅନ୍ୟ ମଡ୍ୟୁଲଗୁଡ଼ିକ ହେଉଛି ପ୍ରତି-ପ୍ରୋଭାଇଡର ସହାୟକ (ଟୁଲ୍ ସ୍କିମା, fetch/TTS ଆଡାପ୍ଟର, କ୍ୱିର୍କ ହ୍ୟାଣ୍ଡଲର)।

### ସାଧାରଣ ପ୍ୟାଟର୍ଣ୍ଣ

ପ୍ରୋଭାଇଡରଗୁଡ଼ିକ `getExecutor(providerId)` ମାଧ୍ୟମରେ ସମାଧାନ ହୁଅନ୍ତି, ଯାହା କନଫିଗର୍ ହୋଇଥିବା ଏକ୍ସିକ୍ୟୁଟର ଫେରାଏ। OpenAI/Anthropic-ସୁସଙ୍ଗତ ପ୍ରୋଭାଇଡରଗୁଡ଼ିକ `DefaultExecutor` (`executors/default.ts`) ବ୍ୟବହାର କରନ୍ତି। ପ୍ରୋଭାଇଡର-ନିର୍ଦ୍ଦିଷ୍ଟ ଆଚରଣ (ମୂଳ URL, ଅথ୍ ହେଡର, API ସଂସ୍କରଣ) `open-sse/config/providers/` ରେ କନଫିଗର୍ କରାଯାଏ, ଯେତେବେଳେ ଅନୁରୋଧ ବଡି ରୂପାନ୍ତରଣ `open-sse/translator/` ରେ ପରିଚାଳିତ ହୁଏ।

**କଷ୍ଟମ୍ URL** ପ୍ରୋଭାଇଡର କନଫିଗରେସନ୍ ମାଧ୍ୟମରେ ସେଟ୍ କରାଯାଏ:

```ts
// open-sse/config/providers/ ରେ ପ୍ରୋଭାଇଡର କନଫିଗ୍
export default {
  id: "together",
  baseURL: "https://api.together.xyz/v1/chat/completions",
}
````

**କଷ୍ଟମ୍ ଅথ୍** ପ୍ରୋଭାଇଡର ରେଜିଷ୍ଟ୍ରିର ଅথ୍ କନଫିଗରେସନ୍ (API କି, OAuth, ହେଡର ପ୍ରୋଫାଇଲ୍) ମାଧ୍ୟମରେ ପରିଚାଳିତ ହୁଏ।

**କଷ୍ଟମ୍ ଅନୁରୋଧ ବଡି** ରୂପାନ୍ତରଣ (ଯେପରିକି Anthropic `system` କୁ `messages` ରୁ ପୃଥକ କରିବା) `open-sse/translator/` ରେ ପ୍ରତି-ପ୍ରୋଭାଇଡର ପଞ୍ଜୀକୃତ ହୁଏ।

````

### ଏକ୍ସିକ୍ୟୁଟର ଫ୍ୟାକ୍ଟୋରି

`executors/index.ts` `getExecutor(providerId)` ରପ୍ତାନି କରେ:

```ts
import { getExecutor } from "@omniroute/open-sse/executors";

const executor = getExecutor("anthropic");
const result = await executor.execute({
  model: "claude-sonnet-4-5",
  messages: [...],
});
````

ସମାଧାନ `ExecutorRegistry` (`executors/registry.ts`) ମାଧ୍ୟମରେ ହୁଏ: ପ୍ରତ୍ୟେକ ବିଶେଷୀକୃତ ଏକ୍ସିକ୍ୟୁଟର `executors/index.ts` ର ଅନ୍ତର୍ନିର୍ମିତ ସାରଣୀରେ ଘୋଷିତ ହୁଏ ଏବଂ ମଡ୍ୟୁଲ୍ ଲୋଡ୍ ସମୟରେ `registerExecutor(alias, instance)` ମାଧ୍ୟମରେ ପଞ୍ଜୀକୃତ ହୁଏ; `getExecutor()` ରେଜିଷ୍ଟ୍ରି ସହ ପରାମର୍ଶ କରେ ଏବଂ ବିଶେଷୀକୃତ ଏଣ୍ଟ୍ରି ନଥିବା ଯେକୌଣସି ପ୍ରୋଭାଇଡର ପାଇଁ ମେମୋଇଜ୍ ହୋଇଥିବା `DefaultExecutor` କୁ ଫେରିଯାଏ। ସମ୍ପୂର୍ଣ୍ଣ alias → executor ମ୍ୟାପିଂ ଗୋଲ୍ଡେନ୍ ଟେଷ୍ଟ `tests/unit/executor-map-golden.test.ts` ଦ୍ୱାରା ଚିହ୍ନିତ ହୁଏ।

## ଅନୁବାଦକଗୁଡ଼ିକ

**3ଟି ଫର୍ମାଟ୍** ମଧ୍ୟରେ ଅନୁବାଦ କରନ୍ତୁ: OpenAI, Anthropic, Gemini, ଏହା ସହିତ ନୂତନ Responses API।

### ଅନୁବାଦ କେବେ ହୁଏ

```ts
import { needsTranslation, translateRequest } from "@omniroute/open-sse/translator";

if (needsTranslation(sourceFormat, targetFormat)) {
  body = translateRequest(body, sourceFormat, targetFormat);
}
```

ସାଧାରଣ ଅନୁବାଦଗୁଡ଼ିକ:

- `OpenAI → Anthropic`: ପୃଥକ `system` ଫିଲ୍ଡ, `x-api-key` ହେଡର୍
- `OpenAI → Gemini`: `messages` ପରିବର୍ତ୍ତେ `contents`, `systemInstruction`
- `OpenAI → Responses API`: `input` ଆରେ, `previous_response_id` ସ୍ଥିତି

### ପରିଚାଳିତ ବିଶେଷ ପରିସ୍ଥିତିଗୁଡ଼ିକ

- `developer` ଭୂମିକା → OpenAI ବ୍ୟତୀତ ଅନ୍ୟଗୁଡ଼ିକ ପାଇଁ `system`
- `system` ଭୂମିକା → GLM/ERNIE ପାଇଁ ପ୍ରଥମ ବ୍ୟବହାରକାରୀ ସନ୍ଦେଶରେ ମିଶ୍ରିତ
- `json_schema` → Geminiର `responseMimeType` + `responseSchema`
- `tools` → ପ୍ରଦାତା-ନିର୍ଦ୍ଦିଷ୍ଟ ଟୁଲ୍ ଫର୍ମାଟ୍
- ଚିନ୍ତନ ପାରାମିଟରଗୁଡ଼ିକ (o1, Claude) → ପ୍ରଦାତା-ନିର୍ଦ୍ଦିଷ୍ଟ ସମତୁଲ୍ୟ ରୂପ

- ସୂକ୍ଷ୍ମ-ସ୍ତରୀୟ ପ୍ରାଧିକରଣ ପାଇଁ **33ଟି ସ୍କୋପ୍**

### ଟୁଲ୍ ପଞ୍ଜୀକରଣ

ଟୁଲ୍ଗୁଡ଼ିକୁ `open-sse/mcp-server/tools/`ରେ ସ୍ୱତନ୍ତ୍ର ଫାଇଲ୍ ଭାବରେ ପଞ୍ଜୀକୃତ କରାଯାଏ, ପ୍ରତ୍ୟେକଟି ଏକ ନାମ, ସ୍କିମା, ହ୍ୟାଣ୍ଡଲର୍ ଏବଂ ସ୍କୋପ୍ ଏକ୍ସପୋର୍ଟ କରେ:

// open-sse/mcp-server/tools/getHealth.ts
import { z } from "zod";

## ଟ୍ରାନ୍ସଫର୍ମର୍ଗୁଡ଼ିକ

`open-sse/transformer/` **Chat Completions** ଏବଂ **Responses API** ଫର୍ମାଟ୍ ମଧ୍ୟରେ ରୂପାନ୍ତର କରେ।

### ଏକ ପୃଥକ ଟ୍ରାନ୍ସଫର୍ମର୍ କାହିଁକି?

Responses API ହେଉଛି **ସ୍ଥିତିପୂର୍ଣ୍ଣ ବାର୍ତ୍ତାଳାପ** (`previous_response_id`) ସହିତ OpenAIର ନୂତନ ଫର୍ମାଟ୍। ଯେତେବେଳେ ଏକ କ୍ଲାଏଣ୍ଟ Responses ଅନୁରୋଧ ପଠାଏ, OmniRoute:

1. ଆଭ୍ୟନ୍ତରୀଣ ଭାବରେ Responses → Chat Completions ରୂପାନ୍ତର କରେ
2. ପ୍ରଦାତାଙ୍କୁ ପଠାଏ (Chat Completions ସମର୍ଥନ କରୁଥିବା ଯେକୌଣସି ପ୍ରଦାତା)
3. ପ୍ରତିକ୍ରିୟାକୁ ପୁଣି Responses ଫର୍ମାଟ୍କୁ ରୂପାନ୍ତର କରେ
4. ରୂପାନ୍ତରିତ ପ୍ରତିକ୍ରିୟାକୁ କ୍ଲାଏଣ୍ଟ ନିକଟକୁ ଷ୍ଟ୍ରିମ୍ କରେ

ଟ୍ରାନ୍ସଫର୍ମର୍ (`transformer/responsesTransformer.ts`) ଏହା ପ୍ରଦାନ କରେ:

```ts
createResponsesApiTransformStream(): TransformStream
```

ଏହା ନିମ୍ନଲିଖିତଗୁଡ଼ିକୁ ପରିଚାଳନା କରେ:

- `response.output_item.added` ଇଭେଣ୍ଟଗୁଡ଼ିକ
- `response.output_text.delta` ଇଭେଣ୍ଟଗୁଡ଼ିକ
- `response.completed` ଇଭେଣ୍ଟ
- ଟୁଲ୍ କଲ୍ ମ୍ୟାପିଂ (`function_call` ↔ `tool_calls`)

## ଆଣ୍ଟି-ପ୍ୟାଟର୍ନ

❌ **`combo.ts`ରେ ସିଙ୍କ୍ରୋନସ୍ DB କଲ୍** — ପୂର୍ବରୁ ଗଣନା କରି କ୍ୟାଶ୍ କରନ୍ତୁ
❌ **ହ୍ୟାଣ୍ଡଲର୍ଗୁଡ଼ିକରେ ପୁନଃପ୍ରୟାସ ଲଜିକ୍** — ରେଜିଲିଏନ୍ସ ସର୍ଭିସ୍ରୁ `retry()` ବ୍ୟବହାର କରନ୍ତୁ
❌ **ପ୍ରତ୍ୟକ୍ଷ ପ୍ରଦାନକାରୀ କନଫିଗ୍ ଆକ୍ସେସ୍** — `providerRegistry` ଗେଟର୍ଗୁଡ଼ିକ ବ୍ୟବହାର କରନ୍ତୁ
❌ **ହାର୍ଡକୋଡ୍ କରାଯାଇଥିବା ଫଲ୍ବ୍ୟାକ୍ ଚେନ୍** — `modelFamilyFallback.ts`ରେ ସଂଜ୍ଞାୟିତ କରନ୍ତୁ
❌ **ସମକାଳୀନ ଅନୁରୋଧଗୁଡ଼ିକ ମଧ୍ୟରେ ଷ୍ଟେଟ୍ ପରିବର୍ତ୍ତନ** — କେବଳ ଅନୁରୋଧ-ସ୍କୋପ୍ଡ୍ କଣ୍ଟେକ୍ସ୍ଟ ବ୍ୟବହାର କରନ୍ତୁ

## ଏକ ନୂତନ କମ୍ପୋନେଣ୍ଟ ଯୋଡ଼ିବା

### ଏକ ନୂତନ ସର୍ଭିସ୍ ଯୋଡ଼ିବା

1. ନିର୍ଦ୍ଦିଷ୍ଟ ଦାୟିତ୍ୱ ସହିତ `open-sse/services/[serviceName].ts` ସୃଷ୍ଟି କରନ୍ତୁ
2. ମୁଖ୍ୟ ହ୍ୟାଣ୍ଡଲର୍ ଫଙ୍କସନ୍ ଏବଂ ଯେକୌଣସି କନ୍ଷ୍ଟାଣ୍ଟ ଏକ୍ସପୋର୍ଟ କରନ୍ତୁ
3. `tests/unit/services/[serviceName].test.mjs`ରେ ୟୁନିଟ୍ ଟେଷ୍ଟ ଯୋଡ଼ନ୍ତୁ
4. `handlers/chatCore.ts`ର ଅନୁରୋଧ ପାଇପ୍ଲାଇନ୍ରେ ଏକୀକୃତ କରନ୍ତୁ (ଯଦି ରାଉଟିଂ-ସମ୍ବନ୍ଧିତ)
5. ସର୍ଭିସ୍ ଟାର୍ଗେଟ୍ ଚୟନକୁ ପ୍ରଭାବିତ କରୁଥିଲେ `combo.ts`ରେ ରାଉଟିଂ ଲଜିକ୍ ଅପଡେଟ୍ କରନ୍ତୁ
6. ଏହି ଫାଇଲ୍ରେ ଡକ୍ୟୁମେଣ୍ଟ କରନ୍ତୁ

### ଏକ ନୂତନ ଏକ୍ସିକ୍ୟୁଟର୍ ଯୋଡ଼ିବା

1. `BaseExecutor`କୁ ବିସ୍ତାର କରି `open-sse/executors/[provider].ts` ସୃଷ୍ଟି କରନ୍ତୁ
2. `config/providerRegistry.ts`ରେ ପଞ୍ଜୀକରଣ କରନ୍ତୁ
3. `executors/index.ts` ଫ୍ୟାକ୍ଟରୀରେ ଯୋଡ଼ନ୍ତୁ
4. ଏକ୍ସିକ୍ୟୁଟର୍ ପାଇଁ ୟୁନିଟ୍ ଟେଷ୍ଟ ଯୋଡ଼ନ୍ତୁ
5. `docs/architecture/ARCHITECTURE.md`ରେ ଡକ୍ୟୁମେଣ୍ଟ କରନ୍ତୁ

### ଏକ ନୂତନ MCP ଟୁଲ୍ ଯୋଡ଼ିବା

1. `open-sse/mcp-server/tools/[category]Tools.ts` ସୃଷ୍ଟି କିମ୍ବା ଅପଡେଟ୍ କରନ୍ତୁ
2. ଇନ୍ପୁଟ୍ଗୁଡ଼ିକ ପାଇଁ Zod ସ୍କିମା ସଂଜ୍ଞାୟିତ କରନ୍ତୁ
3. `mcp-server/index.ts`ରେ ଟୁଲ୍ ପଞ୍ଜୀକରଣ କରନ୍ତୁ
4. `mcp-server/auth/`ର ସ୍କୋପ୍ ମ୍ୟାଟ୍ରିକ୍ସରେ ଯୋଡ଼ନ୍ତୁ
5. ୟୁନିଟ୍ ଟେଷ୍ଟ ଯୋଡ଼ନ୍ତୁ
