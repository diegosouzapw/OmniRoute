OmniRoute ଏକ ସ୍ଥାନୀୟ-ପ୍ରଥମ ଗେମିଫିକେସନ୍ ସ୍ତର ଅନ୍ତର୍ଭୁକ୍ତ କରେ, ଯାହା ପ୍ଲାଟଫର୍ମ ସହିତ
ସକ୍ରିୟ ଭାବେ ଯୋଡ଼ି ହେବା ପାଇଁ ବ୍ୟବହାରକାରୀଙ୍କୁ ପୁରସ୍କୃତ କରେ — ଅନୁରୋଧ କରିବା, ପ୍ରଦାନକାରୀ ବଦଳାଇବା,
କମ୍ବୋ ସୃଷ୍ଟି କରିବା, ଟୋକେନ୍ ଅଂଶୀଦାର କରିବା ଏବଂ ସମୁଦାୟରେ ଅବଦାନ ଦେବା। ସମସ୍ତ ଅବସ୍ଥା
SQLiteରେ ରହେ; ସମୁଦାୟ ସର୍ଭରଗୁଡ଼ିକ ସହିତ ଫେଡେରେସନ୍ ଇଚ୍ଛାଧୀନ ଏବଂ ପୁସ୍-ଆଧାରିତ।

ସିଷ୍ଟମ୍ଟି **ହଟ୍ ପାଥ୍ରେ ଶୂନ୍ୟ-ବିଳମ୍ବ** ପାଇଁ ଡିଜାଇନ୍ କରାଯାଇଛି — ଗେମିଫିକେସନ୍
ଇଭେଣ୍ଟଗୁଡ଼ିକ ଅନୁରୋଧ ପାଇପଲାଇନ୍ରୁ ଫାୟାର୍-ଆଣ୍ଡ୍-ଫରଗେଟ୍ ଭାବେ ପ୍ରେରିତ ହୁଏ ଏବଂ କେବେବି
କୌଣସି LLM ପ୍ରତିକ୍ରିୟାକୁ ଅବରୋଧ କରେନାହିଁ।

## ସାରାଂଶ

### ଉଦ୍ଦେଶ୍ୟ

ଦୃଶ୍ୟମାନ ପ୍ରଗତି (XP,
ସ୍ତର, ବ୍ୟାଜ୍), ସାମାଜିକ ପ୍ରମାଣ (ଲିଡର୍ବୋର୍ଡ୍) ଏବଂ ଆର୍ଥିକ ପ୍ରୋତ୍ସାହନ (ଟୋକେନ୍
ଅଂଶୀଦାରୀ, ଆମନ୍ତ୍ରଣ ପୁରସ୍କାର) ପ୍ରଦାନ କରି ବ୍ୟବହାରକାରୀଙ୍କ ସକ୍ରିୟତା ଓ ଧାରଣ ବୃଦ୍ଧି କରିବା।

### ଡିଜାଇନ୍ ନୀତି

1. **ସ୍ଥାନୀୟ-ପ୍ରଥମ** — ସମସ୍ତ ଅବସ୍ଥା SQLiteରେ, କୌଣସି ବାହ୍ୟ ସେବା ଆବଶ୍ୟକ ନାହିଁ।
2. **ଅବରୋଧହୀନ** — ଇଭେଣ୍ଟଗୁଡ଼ିକ ଫାୟାର୍-ଆଣ୍ଡ୍-ଫରଗେଟ୍; LLM ପ୍ରତିକ୍ରିୟା ପଥ
   ଗେମିଫିକେସନ୍ ଯୁକ୍ତି ଦ୍ୱାରା କେବେବି ବିଳମ୍ବିତ ହୁଏନାହିଁ।
3. **ସର୍ଭର୍-କର୍ତ୍ତୃତ୍ୱାଧୀନ** — XP କେବଳ ସର୍ଭର୍ ପାର୍ଶ୍ୱରେ ଗଣନା କରାଯାଏ; କ୍ଲାଏଣ୍ଟଗୁଡ଼ିକ
   ସ୍କୋର୍ କୃତ୍ରିମ ଭାବେ ବଢ଼ାଇ ପାରିବେନାହିଁ।
4. **ଗୋପନୀୟତାକୁ ସମ୍ମାନ କରୁଥିବା** — ଲିଡର୍ବୋର୍ଡ୍ରେ ଅଂଶଗ୍ରହଣ ଇଚ୍ଛାଧୀନ; ବ୍ୟବହାରକାରୀମାନେ
   ସେମାନଙ୍କ ପ୍ରୋଫାଇଲ୍ ଲୁଚାଇ ପାରିବେ।
5. **ଫେଡେରେସନ୍-ପ୍ରସ୍ତୁତ** — ସମୁଦାୟ ସର୍ଭରଗୁଡ଼ିକ ସ୍ୱାକ୍ଷରିତ API ମାଧ୍ୟମରେ ସ୍କୋର୍ ପୁସ୍ କରିପାରିବେ;
   ସିଙ୍କ୍ ଓଭର୍ରାଇଟ୍ କରେ, ଯୋଗ କରେନାହିଁ।

## ସ୍ଥାପତ୍ୟ

### ଉଚ୍ଚ-ସ୍ତରୀୟ ପ୍ରବାହ

```

  → /v1/chat/completions
    → handleChatCore()                      [open-sse/handlers/chatCore.ts]
      → ... (ବିଦ୍ୟମାନ ପାଇପଲାଇନ୍) ...
      → ଅପ୍ଷ୍ଟ୍ରିମ୍ ପ୍ରତିକ୍ରିୟା କ୍ଲାଏଣ୍ଟକୁ ପଠାଗଲା
      → setImmediate (ଫାୟାର୍-ଆଣ୍ଡ୍-ଫରଗେଟ୍):
        → emitGamificationEvent()           [src/lib/gamification/events.ts]

          → evaluateBadges()                [src/lib/gamification/badges.ts]
```

`emitGamificationEvent()`କୁ କଲ୍ କରେ; ଇଭେଣ୍ଟ ମଡ୍ୟୁଲ୍ XP, ଷ୍ଟ୍ରିକ୍, ବ୍ୟାଜ୍,
ଲିଡର୍ବୋର୍ଡ୍ ଏବଂ ଠକେଇ-ବିରୋଧୀ ଉପସିଷ୍ଟମ୍ଗୁଡ଼ିକୁ ଇଭେଣ୍ଟ ବିତରଣ କରେ।

### ପୁରସ୍କାର ପ୍ରବାହ

```typescript
export async function awardXp(
  apiKeyId: string,
  action: XpAction,
  metadata?: Record<string, unknown>
): Promise<{ xp: number; level: number; title: string; levelUp: boolean }>;
```

1. XP ପରିମାଣ ପାଇବାକୁ `XP_REWARDS[action]` ଖୋଜନ୍ତୁ।
2. `checkRateLimit()` ମାଧ୍ୟମରେ ପାସ୍ କରନ୍ତୁ (ଠକେଇ-ନିରୋଧୀ: ପ୍ରତି କୀ ପାଇଁ ସର୍ବାଧିକ 1000 XP/ମିନିଟ୍)।
3. ଏକ ଟ୍ରାଞ୍ଜାକ୍ସନ୍ ଖୋଲନ୍ତୁ:
   - ବର୍ତ୍ତମାନର `user_levels` ଧାଡ଼ି ପଢ଼ନ୍ତୁ।
   - XP ଯୋଗ କରନ୍ତୁ; `levelFromXp(totalXp)` ମାଧ୍ୟମରେ ସ୍ତର ପୁନଃଗଣନା କରନ୍ତୁ।
   - ସ୍ତର ପରିବର୍ତ୍ତିତ ହୋଇଥିଲେ, `levelUp = true` ସେଟ୍ କରନ୍ତୁ।
   - `user_levels` ଧାଡ଼ି ଅପଡେଟ୍ କରନ୍ତୁ।
   - `xp_audit_log`ରେ ଇନ୍ସର୍ଟ୍ କରନ୍ତୁ।
4. ଫଳାଫଳ ଫେରାନ୍ତୁ। କଲର୍ ବିଜ୍ଞପ୍ତିଗୁଡ଼ିକ ପରିଚାଳନା କରେ।

### ସହାୟକ: `levelFromXp(totalXp)`

ସଞ୍ଚିତ XP `totalXp`କୁ ଅତିକ୍ରମ ନ କରିବା ପର୍ଯ୍ୟନ୍ତ `xp_for_level(n)` ଯୋଗ କରି ସ୍ତର 1..100 ମଧ୍ୟରେ ପୁନରାବୃତ୍ତି କରେ। ଯେଉଁ ସର୍ବୋଚ୍ଚ ସ୍ତରର ସୀମା ପୂରଣ ହୁଏ, ତାହା ଫେରାଏ।
ଏହା O(100) — ସ୍ତରଗୁଡ଼ିକ 100ରେ ସୀମିତ ଥିବାରୁ ଗ୍ରହଣୀୟ।

### ମୂଲ୍ୟାଙ୍କନ ପ୍ରବାହ

```
emitGamificationEvent(event)
  → evaluateBadges(apiKeyId, event)
    → getBadgeDefinitions()           # ସମସ୍ତ ସଂଜ୍ଞା
    → getUserBadges(apiKeyId)         # ପୂର୍ବରୁ ଅର୍ଜିତ (ଛାଡ଼ନ୍ତୁ)
    → ପ୍ରତ୍ୟେକ ଅନର୍ଜିତ ବ୍ୟାଜ୍ ପାଇଁ:
       → matchesCriteria(badge, event, userState)
       → ମେଳ ହେଲେ: awardBadge(apiKeyId, badgeId)
         → ବିଜ୍ଞପ୍ତି ପେଲୋଡ୍ ଫେରାନ୍ତୁ
```

ମୂଲ୍ୟାଙ୍କନ **ଇଭେଣ୍ଟ-ଚାଳିତ** — ଏହା ପ୍ରତ୍ୟେକ ଗେମିଫିକେସନ୍ ଇଭେଣ୍ଟ ପରେ ଚାଲେ, କିନ୍ତୁ କେବଳ ସେହି ବ୍ୟାଜ୍ଗୁଡ଼ିକୁ ଯାଞ୍ଚ କରେ ଯାହାର `criteria.type` ଇଭେଣ୍ଟ କାର୍ଯ୍ୟ ସହିତ ସମନ୍ୱିତ। ଏହା ମୂଲ୍ୟାଙ୍କନକୁ ଦ୍ରୁତ ରଖେ (ଅଧିକାଂଶ ଇଭେଣ୍ଟ ପାଇଁ < 5ms)।

## ଷ୍ଟ୍ରିକ୍ ଟ୍ରାକର୍

**ଫାଇଲ୍:** `src/lib/gamification/streaks.ts`

### ଡାଟା ମଡେଲ୍

ଷ୍ଟ୍ରିକ୍ଗୁଡ଼ିକୁ ନେମସ୍ପେସ୍ଯୁକ୍ତ କୀ ଅଧୀନରେ `key_value` ଟେବୁଲ୍ରେ (ସହଭାଗୀ ୟୁଟିଲିଟି ଟେବୁଲ୍) ସଂରକ୍ଷଣ କରାଯାଏ:

| କୀ                            | ମୂଲ୍ୟ                            | ବର୍ଣ୍ଣନା             |
| ----------------------------- | -------------------------------- | -------------------- |
| `gamification:streak:{keyId}` | `{current},{longest},{lastDate}` | ସକ୍ରିୟ ଷ୍ଟ୍ରିକ୍ ଡାଟା |

### ଲଜିକ୍

```typescript
export async function updateStreak(
  apiKeyId: string
): Promise<{ current: number; longest: number; milestone: boolean }>;
```

1. `key_value` ରୁ ଷ୍ଟ୍ରିକ୍ ରେକର୍ଡ ପଢ଼ନ୍ତୁ।
2. `{current}`, `{longest}`, `{lastDate}` (ISO ତାରିଖ ଷ୍ଟ୍ରିଙ୍ଗ୍) ପାର୍ସ କରନ୍ତୁ।
3. ଯଦି `lastDate === today` — କୌଣସି ପରିବର୍ତ୍ତନ ନାହିଁ (ଆଜି ପାଇଁ ପୂର୍ବରୁ ଗଣନା କରାଯାଇଛି)।
4. ଯଦି `lastDate === yesterday` — `current` ବୃଦ୍ଧି କରନ୍ତୁ; ଆବଶ୍ୟକ ହେଲେ `longest` ଅଦ୍ୟତନ କରନ୍ତୁ।
5. ଯଦି `lastDate < yesterday` — `current = 1` ଭାବେ ରିସେଟ୍ କରନ୍ତୁ (ଷ୍ଟ୍ରିକ୍ ଭାଙ୍ଗିଗଲା)।
6. ଅଦ୍ୟତିତ ରେକର୍ଡ ଲେଖନ୍ତୁ।
7. ମାଇଲ୍ଷ୍ଟୋନ୍ଗୁଡ଼ିକ ଯାଞ୍ଚ କରନ୍ତୁ: 7, 14, 30, 60, 90, 180, 365 ଦିନ। ଅତିକ୍ରମ କରିଥିଲେ,
   `milestone = true` ସେଟ୍ କରନ୍ତୁ (କଲର୍ XP ପ୍ରଦାନ କରେ ଏବଂ ବ୍ୟାଜ୍ ଯାଞ୍ଚ କରେ)।

### ବିଶେଷ ପରିସ୍ଥିତି

- **ସମୟ ମଣ୍ଡଳ**: ଷ୍ଟ୍ରିକ୍ଗୁଡ଼ିକ UTC ତାରିଖ (`new Date().toISOString().slice(0, 10)`) ବ୍ୟବହାର କରନ୍ତି।
  ଏହା ଉଦ୍ଦେଶ୍ୟମୂଳକ — ଗୋଟିଏ ମାନକ ସମୟ ମଣ୍ଡଳ, ସମୟ ମଣ୍ଡଳ ବଦଳାଇ ବ୍ୟବସ୍ଥାର ଅନୁଚିତ ଲାଭ ନେବାକୁ ପ୍ରତିରୋଧ କରେ।
- **ନୂଆ ବ୍ୟବହାରକାରୀ**: କୌଣସି ଷ୍ଟ୍ରିକ୍ ରେକର୍ଡ ନଥାଏ; ପ୍ରଥମ ଅନୁରୋଧ
  `current=1, longest=1, lastDate=today` ସହିତ ଏହାକୁ ସୃଷ୍ଟି କରେ।
- **ଦିନକୁ ଏକାଧିକ ଅନୁରୋଧ**: UTC ଦିନର କେବଳ ପ୍ରଥମ ଅନୁରୋଧଟି
  ଷ୍ଟ୍ରିକ୍ ବୃଦ୍ଧି କରେ।

### ର୍ୟାଙ୍କ ଗଣନା

ର୍ୟାଙ୍କଗୁଡ଼ିକ ସଂରକ୍ଷଣ କରାଯାଏ ନାହିଁ, ବରଂ **ପଢ଼ିବା ସମୟରେ ଗଣନା କରାଯାଏ**। ଏହା ପୁରୁଣା ର୍ୟାଙ୍କ ଡାଟାକୁ ଏଡ଼ାଇଥାଏ
ଏବଂ ପର୍ଯ୍ୟାୟକ୍ରମିକ ର୍ୟାଙ୍କ ପୁନଃଗଣନା କାର୍ଯ୍ୟର ଆବଶ୍ୟକତାକୁ ଦୂର କରେ।

```typescript
export async function getLeaderboard(
  scope: LeaderboardScope,
  period: string,
  limit: number,
  offset: number
): Promise<{ entries: LeaderboardEntry[]; total: number }>;
```

କ୍ୱେରି ପ୍ୟାଟର୍ନ:

```sql
SELECT api_key_id, score,
       RANK() OVER (ORDER BY score DESC) as rank
FROM leaderboard
WHERE scope = ? AND period = ?
ORDER BY score DESC
LIMIT ? OFFSET ?
```

   `leaderboard_archive` କୁ କପି କରନ୍ତୁ।

   ଘୂର୍ଣ୍ଣନକୁ ଟ୍ରିଗର୍ କରେ।

## ଟୋକନ୍ ସେୟାରିଂ

**ଫାଇଲ୍:** `src/lib/gamification/sharing.ts`

### ଡବଲ୍-ଏଣ୍ଟ୍ରି ଲେଜର୍

ପ୍ରତ୍ୟେକ ଟ୍ରାନ୍ସଫର୍ `token_ledger`ରେ ଦୁଇଟି ଧାଡ଼ି ସୃଷ୍ଟି କରେ:

| ଧାଡ଼ି    | `from_key_id`  | `to_key_id`    | `amount` |
| -------- | -------------- | -------------- | -------- |
| ଡେବିଟ୍   | ପ୍ରେରକ         | ପ୍ରାପ୍ତକର୍ତ୍ତା | +amount  |
| କ୍ରେଡିଟ୍ | ପ୍ରାପ୍ତକର୍ତ୍ତା | ପ୍ରେରକ         | -amount  |

ଅପେକ୍ଷା କରନ୍ତୁ — ପ୍ରଚଳିତ ନିୟମଟି ହେଉଛି:

| ଧାଡ଼ି       | `from_key_id`  | `to_key_id`    | `amount` | ଅର୍ଥ                         |
| ----------- | -------------- | -------------- | -------- | ---------------------------- |
| ପଠାଇବା      | ପ୍ରେରକ         | ପ୍ରାପ୍ତକର୍ତ୍ତା | +amount  | ପ୍ରେରକଠାରୁ ବହିର୍ଗମନ          |
| ଗ୍ରହଣ କରିବା | ପ୍ରାପ୍ତକର୍ତ୍ତା | ପ୍ରେରକ         | +amount  | ପ୍ରାପ୍ତକର୍ତ୍ତାଙ୍କ ପାଖକୁ ଆଗମନ |

ବାଲାନ୍ସ ଏହିପରି ଗଣନା କରାଯାଏ:

```sql
SELECT
  COALESCE(SUM(CASE WHEN to_key_id = ? THEN amount ELSE 0 END), 0)
  - COALESCE(SUM(CASE WHEN from_key_id = ? THEN amount ELSE 0 END), 0)
  AS balance
FROM token_ledger
WHERE from_key_id = ? OR to_key_id = ?
```

### ଟ୍ରାନ୍ସଫର୍ ପ୍ରବାହ

```typescript
export async function transferTokens(
  fromKeyId: string,
  toKeyId: string,
  amount: number,
  idempotencyKey: string
): Promise<{ success: boolean; balance: number }>;
```

1. **ବୈଧତା ଯାଞ୍ଚ**: `amount > 0`, `fromKeyId !== toKeyId`.
2. **ଆଇଡେମ୍ପୋଟେନ୍ସି**: ଲେଜର୍ରେ `idempotency_key` ପୂର୍ବରୁ ଅଛି କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ।
   ଯଦି ଅଛି, କ୍ୟାଶ୍ରେ ଥିବା ଫଳାଫଳ ଫେରାନ୍ତୁ।
3. **ଟ୍ରାନ୍ଜାକ୍ସନ୍** (ଗୋଟିଏ SQLite ଟ୍ରାନ୍ଜାକ୍ସନ୍):
   a. ପ୍ରେରକଙ୍କ ବାଲାନ୍ସ ଗଣନା କରନ୍ତୁ।
   b. ଯଦି `balance < amount`, ବାତିଲ୍ କରନ୍ତୁ (ପର୍ଯ୍ୟାପ୍ତ ପାଣ୍ଠି ନାହିଁ)।
   c. ପଠାଇବା ଧାଡ଼ି ଯୋଡ଼ନ୍ତୁ (`from=sender,` ଫେରାନ୍ତୁ।

### ରେଟ୍ ସୀମିତକରଣ

- ପ୍ରତି API କୀ ପାଇଁ ପ୍ରତି ମିନିଟ୍ରେ ସର୍ବାଧିକ 10ଟି ଟ୍ରାନ୍ସଫର୍।
- ଗୋଟିଏ ଟ୍ରାନ୍ସଫର୍ରେ ସର୍ବାଧିକ 10,000 ଟୋକନ୍।
- ପ୍ରତି API କୀ ପାଇଁ ପ୍ରତିଦିନ ସର୍ବାଧିକ 100,000 ଟୋକନ୍ ଟ୍ରାନ୍ସଫର୍।

## ଆମନ୍ତ୍ରଣ ଏବଂ ଟୋକନ୍ ରିଡିମ୍ କରିବା

**ଫାଇଲ୍:** `src/lib/gamification/invites.ts`

### କୋଡ୍ ଫର୍ମାଟ୍

- **କୋଡ୍**: 8-ଅକ୍ଷର ବିଶିଷ୍ଟ ଅକ୍ଷରାଙ୍କିକ କୋଡ୍ (ଉଦାହରଣ ସ୍ୱରୂପ, `A3K9-X7M2`), ମଣିଷଙ୍କ ପାଇଁ ସହଜରେ ପଠନୀୟ,
  ଯାହା ବ୍ୟବହାରକାରୀଙ୍କୁ ପ୍ରଦର୍ଶିତ ହୁଏ।
- **ଟୋକନ୍**: 32-ବାଇଟ୍ ଯାଦୃଚ୍ଛିକ ଟୋକନ୍, SHA-256 ହ୍ୟାସ୍ ଭାବେ ସଂରକ୍ଷିତ। ଏହା
  ପ୍ରୋଗ୍ରାମାଟିକ୍ ରିଡେମ୍ପସନ୍ ପାଇଁ ବ୍ୟବହୃତ ହୁଏ (ଉଦାହରଣ ସ୍ୱରୂପ, URL ଲିଙ୍କ୍)।

### ସଂରକ୍ଷଣ

| ସ୍ତମ୍ଭ       | ମୂଲ୍ୟ                            |
| ------------ | -------------------------------- |
| `code`       | `A3K9X7M2` (ଅନନ୍ୟ, ଇଣ୍ଡେକ୍ସ୍କୃତ) |
| `token_hash` | SHA-256(raw_token)               |

କଞ୍ଚା ଟୋକନ୍ଟି ସୃଷ୍ଟି ସମୟରେ ଠିକ୍ ଥରେ ମାତ୍ର ବ୍ୟବହାରକାରୀଙ୍କୁ ଫେରାଯାଏ। OmniRoute
ଏହାକୁ ପୁଣି କେବେ ସଂରକ୍ଷଣ କିମ୍ବା ପ୍ରଦର୍ଶନ କରେ ନାହିଁ — କେବଳ ହ୍ୟାସ୍ଟି ସ୍ଥାୟୀ ରହେ।

### ସ୍ୱ-ରେଫରାଲ୍ ପ୍ରତିରୋଧ

ଜଣେ ବ୍ୟବହାରକାରୀ କୌଣସି କୋଡ୍ ରିଡିମ୍ କଲେ, ସିଷ୍ଟମ୍ ଯାଞ୍ଚ କରେ:

1. କୋଡ୍ଟି ଏକ ଭିନ୍ନ `api_key_id`ର ଅଟେ।
2. ରିଡିମ୍ କରୁଥିବା ବ୍ୟବହାରକାରୀ ପୂର୍ବରୁ ସେହି ରେଫରର୍ଙ୍କ କୌଣସି କୋଡ୍
   ରିଡିମ୍ କରିନାହାନ୍ତି (`invite_tokens` + ରିଡେମ୍ପସନ୍ ଲଗ୍ରେ ଜଏନ୍ କରାଯାଏ)।

ଯଦି ଯେକୌଣସି ଯାଞ୍ଚ ବିଫଳ ହୁଏ, ଏକ ସ୍ପଷ୍ଟ ତ୍ରୁଟି ସନ୍ଦେଶ ସହିତ ରିଡେମ୍ପସନ୍କୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଏ।

### ମିଆଦ ଓ ସୀମା

- ଡିଫଲ୍ଟ `max_uses`: 10 (ସୃଷ୍ଟି ସମୟରେ ବିନ୍ୟାସଯୋଗ୍ୟ)।
- ଡିଫଲ୍ଟ `expires_at`: ସୃଷ୍ଟିଠାରୁ 30 ଦିନ।
- ମିଆଦ ଶେଷ ହୋଇଥିବା କିମ୍ବା ବ୍ୟବହାର ସୀମା ପୂର୍ଣ୍ଣ ହୋଇଥିବା କୋଡ୍ଗୁଡ଼ିକ HTTP 410 Gone ଫେରାଏ।

3. ସର୍ଭର ରେକର୍ଡକୁ `status: connected` ସହିତ ସଂରକ୍ଷଣ କରେ।

### ପ୍ରାମାଣିକରଣ

ଫେଡେରେସନ୍ ଅନୁରୋଧଗୁଡ଼ିକରେ ଏଗୁଡ଼ିକ ଅନ୍ତର୍ଭୁକ୍ତ:

```
Authorization: Bearer <raw_token>
X-Federation-Version: 1
```

ରିମୋଟ୍ ସର୍ଭର ଟୋକନ୍କୁ ହ୍ୟାଶ୍ କରେ ଏବଂ ମେଳ ଖାଉଥିବା `community_servers` ଧାଡ଼ିକୁ ଖୋଜେ। ଏହା ସଂରକ୍ଷିତ ହ୍ୟାଶ୍କୁ ପ୍ରେରଣ କରିବାରୁ ବଞ୍ଚାଏ।

### ସ୍ୱାସ୍ଥ୍ୟ ନିରୀକ୍ଷଣ

ପ୍ରତ୍ୟେକ ସର୍ଭର ରେକର୍ଡ ନିମ୍ନଲିଖିତ ବିଷୟଗୁଡ଼ିକୁ ଟ୍ରାକ୍ କରେ:

| ଫିଲ୍ଡ       | ବର୍ଣ୍ଣନା                               |
| ----------- | -------------------------------------- |
| `status`    | `connected`, `degraded`, `unreachable` |
| `last_sync` | ଶେଷ ସଫଳ ସିଙ୍କ୍ର ISO ଟାଇମ୍ଷ୍ଟାମ୍ପ       |

### ହାର ସୀମିତକରଣ

### Z-ସ୍କୋର୍ ବିସଙ୍ଗତି ଚିହ୍ନଟ

ପ୍ରତ୍ୟେକ API କୀ ପାଇଁ, ସିଷ୍ଟମ୍ ପ୍ରତି ଘଣ୍ଟାରେ ଅର୍ଜିତ XPର ଏକ ରୋଲିଂ 7-ଦିନିଆ ୱିଣ୍ଡୋ ବଜାୟ ରଖେ। ପ୍ରତ୍ୟେକ XP ପୁରସ୍କାର ସମୟରେ:

1. ବ୍ୟବହାରକାରୀଙ୍କ ବର୍ତ୍ତମାନର ଘଣ୍ଟାପ୍ରତି XP ହାର ଗଣନା କରନ୍ତୁ।
2. ସମଷ୍ଟିର ମାଧ୍ୟ ଏବଂ ମାନକ ବିଚ୍ୟୁତି ଗଣନା କରନ୍ତୁ।
3. `z = (user_rate - mean) / stddev` ଗଣନା କରନ୍ତୁ।
4. ଯଦି `z > 3.0` (3 ମାନକ ବିଚ୍ୟୁତି), ତେବେ ଏହାକୁ ବିସଙ୍ଗତି ଭାବରେ ଚିହ୍ନିତ କରନ୍ତୁ।

ବିସଙ୍ଗତିଗୁଡ଼ିକୁ `action = 'anomaly_detected'` ସହିତ `xp_audit_log`ରେ ଲଗ୍ କରାଯାଏ ଏବଂ ଆଡମିନ୍ ଡ୍ୟାଶବୋର୍ଡରେ ପ୍ରଦର୍ଶିତ କରାଯାଏ।

### ଅଡିଟ୍ ଟ୍ରେଲ୍

ପ୍ରତ୍ୟେକ XP ପୁରସ୍କାର, ଟ୍ରାନ୍ସଫର୍, ବ୍ୟାଜ୍ ଅର୍ଜନ ଏବଂ ବିସଙ୍ଗତି ଚିହ୍ନଟକୁ ନିମ୍ନଲିଖିତ ବିବରଣୀ ସହିତ `xp_audit_log`ରେ ଲଗ୍ କରାଯାଏ:

| ଫିଲ୍ଡ        | ବର୍ଣ୍ଣନା                                      |
| ------------ | --------------------------------------------- |
| `api_key_id` | କିଏ                                           |
| `action`     | କ’ଣ ଘଟିଲା (xp_award, transfer, anomaly, …)    |
| `xp_awarded` | ପରିମାଣ (ଅଣ-XP ଇଭେଣ୍ଟ ପାଇଁ 0)                  |

### ଏକୀକରଣ ବିନ୍ଦୁ

ଗେମିଫିକେସନ୍ `open-sse/handlers/chatCore.ts` ରେ ଥିବା ଅନୁରୋଧ ପାଇପ୍ଲାଇନ୍ର ଗୋଟିଏ ବିନ୍ଦୁରେ ସଂଯୁକ୍ତ ହୁଏ:

```typescript
// କ୍ଲାଏଣ୍ଟକୁ ପ୍ରତିକ୍ରିୟା ପଠାଯିବା ପରେ:
setImmediate(() => {
  emitGamificationEvent({
    type: "request.completed",
    apiKeyId,
    metadata: {
      provider: selectedProvider,
      model: selectedModel,
      comboId: resolvedCombo?.id,
      compressionUsed: compressionStats?.applied,
      skillUsed: skillExecution?.name,
    },
  }).catch(() => {
    // ଫାୟାର୍-ଆଣ୍ଡ୍-ଫର୍ଗେଟ୍: ଲଗ୍ କରନ୍ତୁ, କିନ୍ତୁ କ୍ଲାଏଣ୍ଟକୁ କେବେ ମଧ୍ୟ ପ୍ରସାରିତ କରନ୍ତୁ ନାହିଁ
  });
});
```

### ଅବରୋଧ-ମୁକ୍ତ ନିଶ୍ଚିତତା

`setImmediate` + `.catch(() => {})` ପ୍ୟାଟର୍ନ ନିମ୍ନଲିଖିତ ବିଷୟ ସୁନିଶ୍ଚିତ କରେ:

1. ଗେମିଫିକେସନ୍ ଚାଲିବା ପୂର୍ବରୁ ପ୍ରତିକ୍ରିୟାଟି ସମ୍ପୂର୍ଣ୍ଣ ଭାବରେ ପଠାଯାଏ।
2. ଗେମିଫିକେସନ୍ ତ୍ରୁଟିଗୁଡ଼ିକ କେବେ ମଧ୍ୟ କ୍ଲାଏଣ୍ଟ ପର୍ଯ୍ୟନ୍ତ ପହଞ୍ଚେ ନାହିଁ।
3. ଇଭେଣ୍ଟ ପ୍ରକ୍ରିୟାକରଣ ଇନ୍ଲାଇନ୍ରେ ନୁହେଁ, ପରବର୍ତ୍ତୀ ମାଇକ୍ରୋଟାସ୍କରେ ଚାଲେ।

## ଭବିଷ୍ୟତର ବିଚାରଗୁଡ଼ିକ

- **ଋତୁକାଳୀନ ଇଭେଣ୍ଟଗୁଡ଼ିକ**: ସୀମିତ ସମୟ ପାଇଁ ବ୍ୟାଜ୍ ସେଟ୍ ଏବଂ ଲିଡରବୋର୍ଡ ସିଜନ୍।
- **ଟିମ୍ ଲିଡରବୋର୍ଡଗୁଡ଼ିକ**: ସଂଗଠନ କିମ୍ବା କମ୍ବୋ ଅନୁସାରେ ବ୍ୟବହାରକାରୀମାନଙ୍କୁ ଗୋଷ୍ଠୀଭୁକ୍ତ କରନ୍ତୁ।
- **XP ଗୁଣକଗୁଡ଼ିକ**: ପ୍ରଚାରମୂଳକ ଅବଧିରେ XP ବୃଦ୍ଧି କରନ୍ତୁ।
- **ଉପଲବ୍ଧି ଅଂଶୀଦାରୀ**: ଅଂଶୀଦାର କରାଯାଇପାରୁଥିବା ବ୍ୟାଜ୍ କାର୍ଡଗୁଡ଼ିକ (OpenGraph ପ୍ରତିଛବି) ସୃଷ୍ଟି କରନ୍ତୁ।
- **ମୋବାଇଲ୍ ପୁଶ୍**: ବ୍ୟାଜ୍/ସ୍ତର ଇଭେଣ୍ଟଗୁଡ଼ିକ ପାଇଁ webhook-ଆଧାରିତ ବିଜ୍ଞପ୍ତି।
- **ଲିଡରବୋର୍ଡ API**: ତୃତୀୟ-ପକ୍ଷ ସମନ୍ୱୟ ପାଇଁ ସାର୍ବଜନୀନ API।
