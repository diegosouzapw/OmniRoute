OmniRoute ଏକ ବିସ୍ତାରଯୋଗ୍ୟ Skills ଫ୍ରେମୱର୍କ ପ୍ରଦାନ କରେ, ଯାହା ଭାଷା ମଡେଲଗୁଡ଼ିକୁ (ଏବଂ ଅପରେଟରମାନଙ୍କୁ) ପୁନଃବ୍ୟବହାରଯୋଗ୍ୟ କ୍ଷମତାଗୁଡ଼ିକୁ ସଂଯୋଜନ କରିବାର ସୁବିଧା ଦିଏ — ଫାଇଲସିଷ୍ଟମ୍ ପଠନ ଏବଂ HTTP ଅନୁରୋଧଠାରୁ ଆରମ୍ଭ କରି ସ୍ୟାଣ୍ଡବକ୍ସ ଭିତ୍ତିକ କୋଡ୍ ନିଷ୍ପାଦନ ଓ ବଛାଯାଇଥିବା ମାର୍କେଟପ୍ଲେସ୍ ସ୍କିଲ୍ ପର୍ଯ୍ୟନ୍ତ।

ଏକ ସ୍କିଲ୍ ହେଉଛି କାର୍ଯ୍ୟର ଏକ ସଂସ୍କରଣୀକୃତ, ସ୍କିମା-ପରିଭାଷିତ ଏକକ। OmniRoute ବହିର୍ଗାମୀ ଅନୁରୋଧଗୁଡ଼ିକରେ ସ୍କିଲ୍ଗୁଡ଼ିକୁ ଟୁଲ୍ ପରିଭାଷା ଭାବରେ ସନ୍ନିବେଶ କରିପାରେ, ମଡେଲରୁ ଫେରିଆସୁଥିବା ଟୁଲ୍ କଲ୍ଗୁଡ଼ିକୁ ମଧ୍ୟପଥରେ ଧରିପାରେ, ମେଳ ଖାଉଥିବା ହ୍ୟାଣ୍ଡଲର୍କୁ ଚଲାଇପାରେ ଏବଂ ଫଳାଫଳକୁ ପୁଣି ମଡେଲକୁ ପଠାଇପାରେ, ଯାହାଦ୍ୱାରା ବାର୍ତ୍ତାଳାପ ଜାରି ରହିପାରେ। ମଡେଲ୍ କେବେବି କାର୍ଯ୍ୟାନ୍ୱୟନକୁ ଦେଖେ ନାହିଁ — କେବଳ ଟୁଲ୍ ଇଣ୍ଟରଫେସ୍କୁ ଦେଖେ।

**Agent Skills** ହେଉଛି ଦଲିଲୀକରଣ କ୍ୟାଟାଲଗ୍ — ଏଗୁଡ଼ିକ ବାହ୍ୟ ଏଜେଣ୍ଟମାନଙ୍କୁ OmniRouteର REST API ଏବଂ CLI _କିପରି ବ୍ୟବହାର କରିବେ_ ତାହା ବୁଝାଏ; ଏଥିରେ ଏଜେଣ୍ଟ ପ୍ରମ୍ପ୍ଟ୍ଗୁଡ଼ିକରେ ସିଧାସଳଖ ଭାବେ ଯୋଗାଇହେବା ଯୋଗ୍ୟ ସଂରଚିତ SKILL.md ଫାଇଲ୍ ରହିଛି।

Agent Skills କ୍ୟାଟାଲଗ୍, ଜେନେରେଟର୍, MCP ଟୁଲ୍ ଏବଂ A2A ସ୍କିଲ୍ ପାଇଁ [docs/frameworks/AGENT-SKILLS.md](./AGENT-SKILLS.md) ଦେଖନ୍ତୁ।

## ଧାରଣାଗୁଡ଼ିକ

### ସ୍କିଲ୍ ଉତ୍ସଗୁଡ଼ିକ

ସମାନ ରେଜିଷ୍ଟ୍ରିରେ ସ୍କିଲ୍ର ତିନୋଟି ଉତ୍ସ ସହାବସ୍ଥାନ କରେ:

1. **ବିଲ୍ଟ-ଇନ୍ ସ୍କିଲ୍ଗୁଡ଼ିକ** (`src/lib/skills/builtins.ts`) — OmniRoute ସହିତ ପ୍ରଦାନ କରାଯାଏ। ଏଗୁଡ଼ିକ ସାଧାରଣ ବ୍ୟବହାର କ୍ଷେତ୍ରଗୁଡ଼ିକୁ ଆବୃତ କରେ:
   - `file_read`, `file_write` — `<DATA_DIR>/skills/workspaces/<hashed-key>/` ଅଧୀନରେ ପ୍ରତି-API-key ସ୍ୟାଣ୍ଡବକ୍ସ ୱର୍କସ୍ପେସ୍
   - `http_request` — `guard: "public-only"` ସହିତ `safeOutboundFetch` ମାଧ୍ୟମରେ ବହିର୍ଗାମୀ HTTP
   - `web_search` — କ୍ୟାଶିଂ ସହିତ ପ୍ଲଗ୍ଯୋଗ୍ୟ ସର୍ଚ୍ଚ ପ୍ରଦାତା (`executeWebSearch`)
   - `eval_code` — Docker-ସ୍ୟାଣ୍ଡବକ୍ସ ଭିତ୍ତିକ `node` କିମ୍ବା `python` ନିଷ୍ପାଦନ
   - `execute_command` — Docker-ସ୍ୟାଣ୍ଡବକ୍ସ ଭିତ୍ତିକ ଶେଲ୍ କମାଣ୍ଡ
   - `browser` — Playwright-ସମର୍ଥିତ ସ୍କାଫୋଲ୍ଡିଂ, ଡିଫଲ୍ଟ ଭାବରେ ଅକ୍ଷମ (`builtin/browser.ts`)
2. **SkillsMP** (OmniRoute ମାର୍କେଟପ୍ଲେସ୍) — `https://skillsmp.com/api/v1/skills/search`ରୁ ଅଣାଯାଏ। Settingsରେ `skillsmpApiKey` ଆବଶ୍ୟକ।
3. **SkillsSH** (`skills.sh` କମ୍ୟୁନିଟି କ୍ୟାଟାଲଗ୍) — `https://skills.sh/api/search`ରୁ ଅଣାଯାଏ। କୌଣସି ପ୍ରାମାଣୀକରଣ ଆବଶ୍ୟକ ନାହିଁ; SKILL.md ବିଷୟବସ୍ତୁ GitHub rawରୁ ଅଣାଯାଏ।

ଡ୍ୟାଶବୋର୍ଡ କେଉଁ କ୍ୟାଟାଲଗ୍ରୁ ଇନ୍ଷ୍ଟଲ୍ କରେ, ତାହା ଗୋଟିଏ "ସକ୍ରିୟ ପ୍ରଦାତା" ନିୟନ୍ତ୍ରଣ କରେ (`src/lib/skills/providerSettings.ts`)। ଏହାକୁ **Settings → Memory & Skills** ଅଧୀନରେ ପରିବର୍ତ୍ତନ କରନ୍ତୁ। ଡିଫଲ୍ଟ: `skillsmp`।

### ସ୍କିଲ୍ ପରିଚୟ

ଇନ୍-ମେମୋରି ରେଜିଷ୍ଟ୍ରି (`src/lib/skills/registry.ts`)ରେ ସ୍କିଲ୍ଗୁଡ଼ିକୁ `name@version` ଦ୍ୱାରା କୀ କରାଯାଏ। ସଂସ୍କରଣଟି semver (`^\d+\.\d+\.\d+$`) ହେବା ଆବଶ୍ୟକ। `resolveVersion()` `^`, `~`, `>`, `>=`, `<`, `<=`, `==` ଏବଂ ସଠିକ୍-ମେଳ ସୀମାବନ୍ଧନଗୁଡ଼ିକୁ ବୁଝେ।

### ସ୍କିଲ୍ ମୋଡ୍

ପ୍ରତ୍ୟେକ ସ୍କିଲ୍ର ଏକ ରନ୍ଟାଇମ୍ ମୋଡ୍ ରହିଛି, ଯାହା ଏହା କେବେ ସନ୍ନିବେଶିତ ହେବ ତାହା ନିୟନ୍ତ୍ରଣ କରେ:

| ମୋଡ୍   | ଆଚରଣ                                                                                              |
| ------ | ------------------------------------------------------------------------------------------------- |
| `on`   | ସର୍ବଦା ଟୁଲ୍ ପରିଭାଷା ଭାବରେ ସନ୍ନିବେଶିତ ହୁଏ                                                          |
| `off`  | କେବେବି ସନ୍ନିବେଶିତ ହୁଏ ନାହିଁ, କେବେବି ନିଷ୍ପାଦନଯୋଗ୍ୟ ନୁହେଁ                                           |
| `auto` | ଆସୁଥିବା ଅନୁରୋଧ ସହିତ ସ୍କୋର୍ କରାଯାଏ; ସ୍କୋର୍ ≥ `AUTO_MIN_SCORE` (ଡିଫଲ୍ଟ 3) ହେଲେ ମାତ୍ର ସନ୍ନିବେଶିତ ହୁଏ |

ମାର୍କେଟପ୍ଲେସ୍ରୁ ଇନ୍ଷ୍ଟଲ୍ ହୋଇଥିବା ସ୍କିଲ୍ଗୁଡ଼ିକ ପାଇଁ `auto` ହେଉଛି ଡିଫଲ୍ଟ। `enabled=true` ଏବଂ `mode="off"` ଏକାସାଙ୍ଗରେ ଥିବାର ଅର୍ଥ "ପଞ୍ଜୀକୃତ କିନ୍ତୁ ନିଷ୍କ୍ରିୟ" — ପୁରୁଣା କୋଡ୍ପଥଗୁଡ଼ିକ ସୁସଙ୍ଗତ ରହିବା ପାଇଁ ଲିଗେସି କଲମ୍ ମାଧ୍ୟମରେ `enabled` ଟୋଗଲ୍ କଲେ `mode` ମଧ୍ୟ ଅଦ୍ୟତନ ହୁଏ (`src/app/api/skills/[id]/route.ts`)।

### ସ୍ଥିତି (ନିଷ୍ପାଦନଗୁଡ଼ିକ)

ସ୍କିଲ୍ ନିଷ୍ପାଦନଗୁଡ଼ିକୁ ନିମ୍ନଲିଖିତ ସ୍ଥିତି ସହିତ `skill_executions` ଟେବୁଲ୍ରେ ଟ୍ରାକ୍ କରାଯାଏ (`src/lib/skills/types.ts`):

```ts
enum SkillStatus {
  PENDING = "pending",
  RUNNING = "running",
  SUCCESS = "success",
  ERROR = "error",
  TIMEOUT = "timeout",
}
```

### ରେଜିଷ୍ଟ୍ରି କ୍ୟାଶ୍

`SkillRegistry` ହେଉଛି 60-ସେକେଣ୍ଡ TTL କ୍ୟାଶ୍ (`registry.ts:14`) ସହିତ ଏକ ସିଙ୍ଗଲଟନ୍। `loadFromDatabase()` ହେଉଛି ଆଇଡେମ୍ପୋଟେଣ୍ଟ ଏବଂ `pendingLoad` ମାଧ୍ୟମରେ ସମକାଳୀନ କଲ୍ଗୁଡ଼ିକୁ ଡିଡ୍ୟୁପ୍ କରେ। ଯେକୌଣସି ଲେଖନ (`register`/`unregister`/`unregisterById`) କ୍ୟାଶ୍କୁ ଅବୈଧ କରେ। `getSkillVersions(name)` ଏବଂ `resolveVersion(name, constraint)` ମାଧ୍ୟମରେ ସଂସ୍କରଣଗୁଡ଼ିକୁ ଖୋଜନ୍ତୁ।

### ପ୍ରଦାତା-ସଚେତନ ସନ୍ନିବେଶ

`src/lib/skills/injection.ts`ରେ ଥିବା `injectSkills()` ହେଉଛି ପଞ୍ଜୀକୃତ ସ୍କିଲ୍ଗୁଡ଼ିକୁ ପ୍ରଦାତା-ନିର୍ଦ୍ଦିଷ୍ଟ ଟୁଲ୍ ପରିଭାଷାରେ ପରିଣତ କରୁଥିବା ପ୍ରବେଶ ବିନ୍ଦୁ:

- **OpenAI** — `{ type: "function", function: { name, description, parameters } }`
- **Anthropic** — `{ name, description, input_schema }`
- **Google (Gemini)** — `{ name, description, parameters }`

ଟୁଲ୍ର ନାମକୁ `name@version` ଭାବେ ଏନ୍କୋଡ୍ କରାଯାଏ, ଯାହାଫଳରେ ମଡେଲ୍ ଏହାକୁ ପୁନଃ କଲ୍ କଲେ ହ୍ୟାଣ୍ଡଲର୍ ସଠିକ୍ ସଂସ୍କରଣ ବାଛିପାରିବ।

### AUTO ସ୍କୋରିଂ

| ପ୍ରତ୍ୟେକ ବର୍ଣ୍ଣନା ଟୋକନ୍ ପ୍ରସଙ୍ଗ ସହ ମେଳ ଖାଏ                   | +1               |

### ଟୁଲ୍ କଲ୍ ଇଣ୍ଟରସେପ୍ସନ୍

ଅପ୍ଷ୍ଟ୍ରିମ୍ରୁ ଟୁଲ୍-କଲିଂ ପ୍ରତିକ୍ରିୟା ଫେରିବା ପରେ, ଚାଟ୍ ହ୍ୟାଣ୍ଡଲର୍ ଦ୍ୱାରା `src/lib/skills/interception.ts` ରେ ଥିବା `handleToolCallExecution()` କୁ ଆହ୍ୱାନ କରାଯାଏ:

1. `extractToolCalls()` ପ୍ରଦାନକାରୀ-ନିର୍ଦ୍ଦିଷ୍ଟ ଗଠନଗୁଡ଼ିକୁ ପଢ଼େ (OpenAI `tool_calls` / Responses `function_call`, Anthropic `tool_use`, Gemini `functionCalls`)।
2. ବିଲ୍ଟ-ଇନ୍ ଟୁଲ୍ ଉପନାମଗୁଡ଼ିକ (ଯେପରିକି `omniroute_web_search` → `web_search`) ପ୍ରଥମେ ସମାଧାନ କରାଯାଏ। ବିଲ୍ଟ-ଇନ୍ ହ୍ୟାଣ୍ଡଲର୍ଗୁଡ଼ିକ ଇନ୍ଲାଇନ୍ରେ ଚାଲେ।
3. ଅନ୍ୟ ସବୁକିଛି `skillExecutor.execute(name@version, args, { apiKeyId, sessionId })` ମାଧ୍ୟମରେ ରାଉଟ୍ କରାଯାଏ।
4. ଫଳାଫଳଗୁଡ଼ିକୁ ପୁନଃ ପ୍ରତିକ୍ରିୟାରେ ଯୋଡ଼ାଯାଏ — ଯଥାଯୋଗ୍ୟ ଭାବେ `tool_results`, `function_call_output` ଆଇଟମ୍ କିମ୍ବା Anthropic `tool_result` ବ୍ଲକ୍ ଭାବରେ।

କେବଳ ବିଲ୍ଟ-ଇନ୍ ଇଣ୍ଟରସେପ୍ସନ୍କୁ ଅନୁମତି ଦେବା ପାଇଁ ନିଷ୍ପାଦନ ପ୍ରସଙ୍ଗରେ `customSkillExecutionEnabled` କୁ `false` ଭାବେ ସେଟ୍ କରାଯାଇପାରେ (ବ୍ୟବହାରକାରୀ-ନିର୍ଦ୍ଧାରିତ ହ୍ୟାଣ୍ଡଲର୍ଗୁଡ଼ିକୁ ସ୍ପଷ୍ଟ ଭାବେ ଅକ୍ଷମ କରୁଥିବା ଅନୁରୋଧ ପଥଗୁଡ଼ିକରେ ଏହା ବ୍ୟବହୃତ ହୁଏ)।

## Docker ସ୍ୟାଣ୍ଡବକ୍ସ

ଅନ୍ତର୍ନିର୍ମିତ ନୁହେଁ ଏପରି କୋଡ୍ ପଥଗୁଡ଼ିକ (`eval_code`, `execute_command`) `SandboxRunner` (`src/lib/skills/sandbox.ts`) ମାଧ୍ୟମରେ Docker ଭିତରେ ଚାଲେ। ପ୍ରତ୍ୟେକ କଣ୍ଟେନର୍ ନିମ୍ନଲିଖିତ ସହିତ ଆରମ୍ଭ କରାଯାଏ:

```
--rm --network none|bridge --cap-drop ALL
--security-opt no-new-privileges --pids-limit 100
--cpus <cpuLimit/1000> --memory <memoryLimit>m
--tmpfs /tmp:rw,noexec,nosuid,size=64m
--tmpfs /workspace:rw,noexec,nosuid,size=64m
--read-only (ଯେତେବେଳେ readOnly=true)
```

ଡିଫଲ୍ଟଗୁଡ଼ିକ (`SandboxRunner.DEFAULT_CONFIG`):

| ଫିଲ୍ଡ            | ଡିଫଲ୍ଟ          | ଟିପ୍ପଣୀ                                                 |
| ---------------- | --------------- | ------------------------------------------------------- |
| `cpuLimit`       | 100 (= 0.1 CPU) | `--cpus`କୁ ପଠାଇବା ପୂର୍ବରୁ 1000 ଦ୍ୱାରା ବିଭାଜିତ           |
| `memoryLimit`    | 256 MB          | କଠୋର ସୀମା                                               |
| `timeout`        | 30000 ms        | `SIGTERM` + `docker kill` ମାଧ୍ୟମରେ ସହଜ ବନ୍ଦ             |
| `networkEnabled` | `false`         | `--network none`ରେ ପରିଣତ ହୁଏ                            |
| `readOnly`       | `true`          | ରୁଟ୍ FS କେବଳ-ପଠନୀୟ; `/tmp` ଏବଂ `/workspace` ହେଉଛି tmpfs |

ବନ୍ଦ କରିବା ପାଇଁ `SandboxRunner.kill(id)` ଏବଂ `killAll()` ଉନ୍ମୁକ୍ତ କରାଯାଇଛି; ଚାଲୁଥିବା କଣ୍ଟେନର୍ଗୁଡ଼ିକୁ `runningContainers: Map<string, ChildProcess>`ରେ ଟ୍ରାକ୍ କରାଯାଏ।

### ସ୍ୟାଣ୍ଡବକ୍ସ ପରିବେଶ ଭେରିଏବଲ୍ଗୁଡ଼ିକ

`src/lib/skills/builtins.ts`ରେ `process.env` ମାଧ୍ୟମରେ ବିନ୍ୟାସ କରାଯାଇଛି:

| ପରିବେଶ ଭେରିଏବଲ୍                   | ଡିଫଲ୍ଟ           | ଉଦ୍ଦେଶ୍ୟ                                                                                           |
| --------------------------------- | ---------------- | -------------------------------------------------------------------------------------------------- |
| `SKILLS_MAX_FILE_BYTES`           | `1048576` (1 MB) | `file_read` ଏବଂ `file_write` ପାଇଁ ସୀମା                                                             |
| `SKILLS_MAX_HTTP_RESPONSE_BYTES`  | `256000`         | `http_request` ପ୍ରତିକ୍ରିୟା ବଡି ପାଇଁ ସୀମା                                                           |
| `SKILLS_MAX_SANDBOX_OUTPUT_CHARS` | `100000`         | କଲର୍କୁ ଫେରାଯାଇଥିବା stdout/stderr ପାଇଁ ସୀମା                                                         |
| `SKILLS_SANDBOX_TIMEOUT_MS`       | `10000`          | ସ୍ୟାଣ୍ଡବକ୍ସ କମାଣ୍ଡଗୁଡ଼ିକ ପାଇଁ ଡିଫଲ୍ଟ ସମୟସୀମା; 60 sରେ ସୀମିତ                                         |
| `SKILLS_SANDBOX_NETWORK_ENABLED`  | `false`          | ବାହ୍ୟଗମନ ପାଇଁ ମୁଖ୍ୟ ନିୟନ୍ତ୍ରଣ। ପ୍ରତି-କଲ୍ ଅପ୍ଟ-ଇନ୍କୁ ଅନୁମତି ଦେବା ପାଇଁ `1` କିମ୍ବା `true` ସେଟ୍ କରନ୍ତୁ |
| `SKILLS_ALLOWED_SANDBOX_IMAGES`   | (ତଳେ ଦେଖନ୍ତୁ)    | Docker ଇମେଜ୍ଗୁଡ଼ିକର କମା-ପୃଥକ ଅନୁମତି ତାଲିକା                                                         |

ଡିଫଲ୍ଟ ଅନୁମୋଦିତ ଇମେଜ୍ଗୁଡ଼ିକ: `alpine:3.20`, `node:22-alpine`, `python:3.12-alpine`। `SKILLS_ALLOWED_SANDBOX_IMAGES` ମାଧ୍ୟମରେ ଯୋଡ଼ାଯାଇଥିବା ଯେକୌଣସି ଇମେଜ୍ ଡିଫଲ୍ଟଗୁଡ଼ିକ ସହିତ ମିଶ୍ରଣ କରାଯାଏ; ଅଜଣା ଇମେଜ୍ଗୁଡ଼ିକୁ `normalizeImage()` ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ।

> ଟିପ୍ପଣୀ: କୌଣସି ପୃଥକ `SKILLS_EXECUTION_TIMEOUT_MS` ପରିବେଶ ଭେରିଏବଲ୍ ନାହିଁ। ଅଣ-ସ୍ୟାଣ୍ଡବକ୍ସ ହ୍ୟାଣ୍ଡଲର୍ ସମୟସୀମା `SkillExecutor` (`executor.ts:13`)ରେ 30 sକୁ ହାର୍ଡ-କୋଡ୍ କରାଯାଇଛି, କିନ୍ତୁ ରନ୍ଟାଇମ୍ରେ `skillExecutor.setTimeout(ms)` ମାଧ୍ୟମରେ ଏହାକୁ ଓଭରରାଇଡ୍ କରାଯାଇପାରିବ।

### ୱର୍କସ୍ପେସ୍ ପୃଥକୀକରଣ

`file_read` ଏବଂ `file_write` ପ୍ରତ୍ୟେକ ପଥକୁ `<DATA_DIR>/skills/workspaces/<sha256(apiKeyId).slice(0,24)>/`ରେ ଥିବା ପ୍ରତି-API-କି ୱର୍କସ୍ପେସ୍ ସାପେକ୍ଷରେ ସମାଧାନ କରେ। କୌଣସି ଡିସ୍କ I/O ପୂର୍ବରୁ ପଥ ଅତିକ୍ରମଣ (`..`) ଏବଂ ନିଷିଦ୍ଧ ସେଗମେଣ୍ଟଗୁଡ଼ିକ (`.env`, `.git`, `.ssh`, `.omniroute`, `.codex`, `secrets`) ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଏ।

### HTTP ସୁଦୃଢ଼ୀକରଣ

`http_request` (`builtins.ts:257`):

- ଅନୁମୋଦିତ ମେଥଡ୍ ତାଲିକା: `GET, HEAD, POST, PUT, PATCH, DELETE`
- ଅବରୋଧିତ ବାହ୍ୟଗାମୀ ହେଡର୍ଗୁଡ଼ିକ: `host, connection, content-length, cookie, set-cookie, authorization, proxy-authorization`
- ରିଡାଇରେକ୍ଟଗୁଡ଼ିକ ଅକ୍ଷମ କରାଯାଇଛି (`allowRedirect: false`)
- `guard: "public-only"` ସହିତ `safeOutboundFetch` ମାଧ୍ୟମରେ ରୁଟ୍ କରାଯାଏ (ବ୍ୟକ୍ତିଗତ/ଲୁପ୍ବ୍ୟାକ୍ ରେଞ୍ଜଗୁଡ଼ିକ ଅବରୋଧିତ)
- ପ୍ରତିକ୍ରିୟାକୁ `SKILLS_MAX_HTTP_RESPONSE_BYTES`ରେ କାଟଛାଣ୍ଟ କରାଯାଏ; କ୍ଲାଏଣ୍ଟ `truncated: true` ଦେଖେ

## ହାଇବ୍ରିଡ୍ ଏକ୍ସିକ୍ୟୁଟର୍ (ପୂର୍ବାବଲୋକନ)

`src/lib/skills/hybrid.ts` ଏକ `HybridExecutor` ନିର୍ଦ୍ଧାରଣ କରେ, ଯାହା ପ୍ରତ୍ୟେକ କଲ୍ ପାଇଁ `direct` (ଇନ୍-ପ୍ରୋସେସ୍) ଏବଂ `sandbox` ନିଷ୍ପାଦନ ମଧ୍ୟରୁ ଗୋଟିଏ ବାଛେ, ଏବଂ ଟାଇମ୍ଆଉଟ୍/ମେମୋରି ତ୍ରୁଟି ସମୟରେ `autoUpgrade` ପୁନଃପ୍ରୟାସ ପଥ ବ୍ୟବହାର କରେ। ସଂଯୁକ୍ତ `directExecutor` / `sandboxRunner` ଇମ୍ପ୍ଲିମେଣ୍ଟେସନ୍ଗୁଡ଼ିକ ଷ୍ଟବ୍ (`executeDirect`, `executeInSandbox` ପ୍ଲେସ୍ହୋଲ୍ଡର୍ ଅବଜେକ୍ଟ ଫେରାନ୍ତି) — ଏହି ମଡ୍ୟୁଲ୍କୁ ନିର୍ମାଣାଧୀନ ଏକ ଚୁକ୍ତି ଭାବେ ବିବେଚନା କରନ୍ତୁ। ପ୍ରକୃତ ନିଷ୍ପାଦନ ଏବେ ମଧ୍ୟ `skillExecutor` + `SandboxRunner` ମାଧ୍ୟମରେ ହୁଏ।

## REST API

ସମସ୍ତ ଏଣ୍ଡପଏଣ୍ଟ `src/app/api/skills/` ଅଧୀନରେ ରହିଛି। ପରିଚାଳନା ଏଣ୍ଡପଏଣ୍ଟଗୁଡ଼ିକ (`/api/skills`, `/api/skills/[id]`, `/api/skills/install`) ପାଇଁ `requireManagementAuth()` ମାଧ୍ୟମରେ **ପରିଚାଳନା ପ୍ରମାଣୀକରଣ** ଆବଶ୍ୟକ। ମାର୍କେଟ୍ପ୍ଲେସ୍/ଇନ୍ଷ୍ଟଲ୍ ପ୍ରବାହଗୁଡ଼ିକ ଅପେକ୍ଷାକୃତ ହାଲୁକା `isAuthenticated()` (ସେସନ୍ କିମ୍ବା API କୀ) ବ୍ୟବହାର କରନ୍ତି।

| ଏଣ୍ଡପଏଣ୍ଟ | ପଦ୍ଧତି | ଉଦ୍ଦେଶ୍ୟ |
| --------------------------------- | ------ | ------------------------------------------------------------------------ | --- | ------------------------ | -------- | ------------------ |
| `/api/skills` | GET | ପଞ୍ଜୀକୃତ ସ୍କିଲ୍ଗୁଡ଼ିକର ତାଲିକା। `?q=`, `?mode=on                        | off | auto`, `?source=skillsmp | skillssh | local`, ପୃଷ୍ଠାଙ୍କନ ସମର୍ଥନ କରେ |
| `/api/skills/[id]` | PUT | `enabled` କିମ୍ବା `mode` ଅପଡେଟ୍ କରନ୍ତୁ |
| `/api/skills/[id]` | DELETE | id ଦ୍ୱାରା ପଞ୍ଜୀକରଣ ବାତିଲ୍ କରନ୍ତୁ |
| `/api/skills/install` | POST | ଏକ କଷ୍ଟମ୍ ସ୍କିଲ୍ ଇନ୍ଷ୍ଟଲ୍ କରନ୍ତୁ (ହ୍ୟାଣ୍ଡଲର୍ କୋଡ୍ + ସ୍କିମା) |
| `/api/skills/marketplace` | GET | SkillsMP କ୍ୟାଟାଲଗ୍ରେ ସନ୍ଧାନ କରନ୍ତୁ (`q` ଖାଲି ଥିଲେ ଲୋକପ୍ରିୟ ଡିଫଲ୍ଟଗୁଡ଼ିକ ଫେରାଏ) |
| `/api/skills/marketplace/install` | POST | ଏକ SkillsMP ସ୍କିଲ୍ ଇନ୍ଷ୍ଟଲ୍ କରନ୍ତୁ (ସକ୍ରିୟ ପ୍ରଦାନକାରୀ = `skillsmp` ହେବା ଆବଶ୍ୟକ) |
| `/api/skills/skillssh` | GET | skills.sh କ୍ୟାଟାଲଗ୍ରେ ସନ୍ଧାନ କରନ୍ତୁ (`?q=&limit=`, ସର୍ବାଧିକ 100ରେ ସୀମିତ) |
| `/api/skills/skillssh/install` | POST | ଏକ skills.sh ସ୍କିଲ୍ ଇନ୍ଷ୍ଟଲ୍ କରନ୍ତୁ (ସକ୍ରିୟ ପ୍ରଦାନକାରୀ = `skillssh` ହେବା ଆବଶ୍ୟକ) |
| `/api/skills/executions` | GET | ପୃଷ୍ଠାଙ୍କିତ ନିଷ୍ପାଦନ ଇତିହାସ (`?apiKeyId=`) |
| `/api/skills/executions` | POST | ଏକ ପଞ୍ଜୀକୃତ ସ୍କିଲ୍କୁ ତତ୍କ୍ଷଣାତ୍ ନିଷ୍ପାଦନ କରନ୍ତୁ |

`settings.skillsEnabled === false` ଥିଲେ `POST /api/skills/executions` ଏଣ୍ଡପଏଣ୍ଟ `{ error: "Skills execution is disabled..." }` ସହିତ HTTP `503` ଫେରାଏ (`executor.ts:42-45`)। ଅପରେଟର୍ମାନେ **ସେଟିଂସ୍ → AI**ରୁ ମାଷ୍ଟର୍ ସ୍ୱିଚ୍ ପରିବର୍ତ୍ତନ କରିପାରିବେ।

### ଉଦାହରଣ: ଏକ କଷ୍ଟମ୍ ସ୍କିଲ୍ ଇନ୍ଷ୍ଟଲ୍ କରନ୍ତୁ

```bash
curl -X POST http://localhost:20128/api/skills/install \
  -H "Authorization: Bearer $OMNIROUTE_MGMT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "reverse-text",
    "version": "1.0.0",
    "description": "Reverses a string",
    "schema": {
      "input":  { "type": "object", "properties": { "text": { "type": "string" } }, "required": ["text"] },
      "output": { "type": "object", "properties": { "reversed": { "type": "string" } } }
    },
    "handlerCode": "echo-handler",
    "apiKeyId": "your-api-key-id"
  }'
```

`handlerCode` ଷ୍ଟ୍ରିଙ୍ଗ୍ଟି ଏକ **ହ୍ୟାଣ୍ଡଲର୍ ନାମ ଲୁକ୍ଅପ୍** — ନିଷ୍ପାଦନଯୋଗ୍ୟ କୋଡ୍ ନୁହେଁ। ଏକ୍ସିକ୍ୟୁଟର୍ `skillExecutor.registerHandler(name, fn)` (`executor.ts:25`) ମାଧ୍ୟମରେ ଏହାକୁ ମ୍ୟାପ୍ କରେ। ମାର୍କେଟ୍ପ୍ଲେସ୍ ଇନ୍ଷ୍ଟଲ୍ଗୁଡ଼ିକ ଡକ୍ୟୁମେଣ୍ଟେସନ୍ ଭାବେ SKILL.md ପାଠ୍ୟକୁ ଏହି ଫିଲ୍ଡରେ ସଂରକ୍ଷଣ କରନ୍ତି ଏବଂ ମଡେଲ୍-ଜେନେରେଟେଡ୍ ଟୁଲ୍ କଲ୍ଗୁଡ଼ିକ ମାଧ୍ୟମରେ ନିଷ୍ପାଦନକୁ ରୁଟ୍ କରନ୍ତି। ବ୍ୟବହାରକାରୀଙ୍କ ଦ୍ୱାରା ଯୋଗାଇ ଦିଆଯାଇଥିବା ଇଚ୍ଛାଧୀନ ସୋର୍ସକୁ eval କରାଯାଏ ନାହିଁ।

## ଏକ ନୂତନ ବିଲ୍ଟ-ଇନ୍ ସ୍କିଲ୍ ଯୋଡ଼ିବା

1. `src/lib/skills/builtins.ts`ରେ (କିମ୍ବା `src/lib/skills/builtin/` ଅଧୀନରେ ଥିବା ଏକ ସହୋଦର ଫାଇଲ୍ରେ) **ହ୍ୟାଣ୍ଡଲର୍କୁ ପରିଭାଷିତ କରନ୍ତୁ**। ସିଗ୍ନେଚର୍: `(input, { apiKeyId, sessionId }) => Promise<output>`।
2. **ସ୍ୟାଣ୍ଡବକ୍ସ୍ କୋଡ୍ ପଥ?** `sandboxRunner.run(image, command, env, sandboxConfig({...}))`କୁ କଲ୍ କରନ୍ତୁ। ଅନୁମତି-ତାଲିକା ବିପକ୍ଷରେ `normalizeImage()` ବ୍ୟବହାର କରନ୍ତୁ।
3. **ଫାଇଲ୍ସିଷ୍ଟମ୍ ପଥ?** ଡିସ୍କକୁ ସ୍ପର୍ଶ କରିବା ପୂର୍ବରୁ ସର୍ବଦା `resolveWorkspacePath(input, context)` ମାଧ୍ୟମରେ ପାସ୍ କରନ୍ତୁ।
4. **ନେଟୱର୍କ କଲ୍?** `guard: "public-only"` ସହିତ `safeOutboundFetch` ବ୍ୟବହାର କରନ୍ତୁ; `sanitizeHeaders()` ମାଧ୍ୟମରେ ହେଡର୍ଗୁଡ଼ିକୁ ସାନିଟାଇଜ୍ କରନ୍ତୁ।
5. `builtinSkills`ରେ ଏଣ୍ଟ୍ରି ଯୋଡ଼ି (କିମ୍ବା ବୁଟ୍ ସମୟରେ `registerBrowserSkill(executor)`-ଶୈଳୀର କଲ୍ କରି) **ପଞ୍ଜୀକରଣ କରନ୍ତୁ**।
6. ଯଦି ଅପ୍ଷ୍ଟ୍ରିମ୍ ମଡେଲ୍ ଏକ ଭିନ୍ନ ନାମ ନିର୍ଗତ କରେ, `BUILTIN_TOOL_ALIASES` (`interception.ts:23`)ରେ **ବିଲ୍ଟ-ଇନ୍ ଟୁଲ୍ ଉପନାମଗୁଡ଼ିକୁ ସଂଯୋଗ କରନ୍ତୁ** (ବୈକଳ୍ପିକ)।
7. `src/lib/skills/__tests__/`ରେ **ପରୀକ୍ଷାଗୁଡ଼ିକ** (Vitest)।

## ଏକ କଷ୍ଟମ୍ (ଅଣ-ବିଲ୍ଟ-ଇନ୍) ସ୍କିଲ୍ ଯୋଡ଼ିବା

## ପରିଚାଳନାଗତ ପରାମର୍ଶ

- **ମାଷ୍ଟର୍ ସ୍ୱିଚ୍:** `settings.skillsEnabled = false` ସମସ୍ତ ନିଷ୍ପାଦନକୁ ଅବରୋଧ କରେ ଏବଂ `/api/skills/executions`ରେ HTTP `503` ଫେରାଏ। ରେଜିଷ୍ଟ୍ରି ଲୋଡ୍ ହେବା ଜାରି ରଖେ।
- **ଇଗ୍ରେସ୍କୁ ଲକ୍ ଡାଉନ୍ କରନ୍ତୁ:** ସମ୍ପୂର୍ଣ୍ଣ ଏୟାର୍-ଗ୍ୟାପ୍ଡ ସ୍ୟାଣ୍ଡବକ୍ସିଂ ପାଇଁ `SKILLS_SANDBOX_NETWORK_ENABLED`କୁ ଅସେଟ୍ (ଡିଫଲ୍ଟ) ରଖନ୍ତୁ। ପ୍ରତି-କଲ୍ `networkEnabled: true` ପାଇଁ ତଥାପି ମାଷ୍ଟର୍ ଗେଟ୍ ଆବଶ୍ୟକ।
- **ନିର୍ଦ୍ଦିଷ୍ଟ ଇମେଜ୍ଗୁଡ଼ିକୁ ଅନୁମତି ଦିଅନ୍ତୁ:** ଅନୁମତି-ତାଲିକାକୁ ବିସ୍ତାର କରିବା ପାଇଁ `SKILLS_ALLOWED_SANDBOX_IMAGES="myorg/sandbox:1.0,node:22-alpine"` ସେଟ୍ କରନ୍ତୁ।
- **ନିଷ୍ପାଦନଗୁଡ଼ିକୁ ଅଡିଟ୍ କରନ୍ତୁ:** `/dashboard/skills/executions` ଏବଂ `omniroute_skills_executions` ଉଭୟ `skill_executions`କୁ କ୍ୱେରି କରନ୍ତି। ସଫଳ ରନ୍ଗୁଡ଼ିକରେ `durationMs` ଅନ୍ତର୍ଭୁକ୍ତ ଥାଏ; ବିଫଳତାଗୁଡ଼ିକରେ `errorMessage` ଅନ୍ତର୍ଭୁକ୍ତ ଥାଏ।
- **କ୍ୟାଶ୍ ଇନ୍ଭାଲିଡେସନ୍:** ମାନୁଆଲ୍ DB ସମ୍ପାଦନ ପରେ `skillRegistry.invalidateCache()`କୁ କଲ୍ କରନ୍ତୁ; ଅନ୍ୟଥା 60 s ଅପେକ୍ଷା କରନ୍ତୁ।
- **ଅଜ୍ଞାତ ୱର୍କସ୍ପେସ୍:** ଯେତେବେଳେ `apiKeyId` ଖାଲି ଥାଏ, ସମସ୍ତ କଲ୍ ସମାନ `"anonymous"` ୱର୍କସ୍ପେସ୍କୁ ହ୍ୟାଶ୍ ହୁଏ — ସେୟାର୍-ସଚେତନ କୋଡ୍ ସର୍ବଦା ଏକ ପ୍ରକୃତ କୀ ପାସ୍ କରିବା ଉଚିତ।

## ନିଷ୍ପାଦନ ଜୀବନଚକ୍ର (v3.8.16+)

`SkillExecutor` (`src/lib/skills/executor.ts`) ହେଉଛି ଏକ **ସିଙ୍ଗଲଟନ୍**, ଯାହା ପ୍ରତ୍ୟେକ ସ୍କିଲ୍ ଆହ୍ୱାନକୁ ପରିଚାଳନା କରେ। ଟାଇମ୍ଆଉଟ୍, ପୁନଃପ୍ରୟାସ ଏବଂ ନିଷ୍ପାଦନ ସ୍ଥିତି ଡିବଗ୍ କରିବା ପାଇଁ ଏହାର ଜୀବନଚକ୍ର ବୁଝିବା ଅତ୍ୟନ୍ତ ଜରୁରୀ।

### ୫-ପର୍ଯ୍ୟାୟ ଜୀବନଚକ୍ର

```
   execute() ଆହ୍ୱାନ କରାଗଲା

        ▼
  ┌─────────────┐

  └──────┬──────┘
         │ ହ୍ୟାଣ୍ଡଲର୍ ଆରମ୍ଭ
         ▼
  ┌─────────────┐
  │  RUNNING    │  ← ଟାଇମ୍ଆଉଟ୍ ସହିତ ହ୍ୟାଣ୍ଡଲର୍ ଆହ୍ୱାନ କରାଯାଇଛି
  └──────┬──────┘
         │
    ┌────┴────┬──────────┬──────────┐
    │         │          │          │

    │         │          │
    └────┬────┴──────────┘
         │
```

### ଡିଫଲ୍ଟ ବିନ୍ୟାସ

| ସେଟିଂ        | ଡିଫଲ୍ଟ        | ଏହା ମାଧ୍ୟମରେ ବିନ୍ୟାସଯୋଗ୍ୟ            |
| ------------ | ------------- | ------------------------------------ |
| `timeout`    | `30000` (30s) | `skillExecutor.setTimeout(ms)`       |
| `maxRetries` | `3`           | `skillExecutor.setMaxRetries(count)` |

> **ଗୁରୁତ୍ୱପୂର୍ଣ୍ଣ**: ଏକ୍ସିକ୍ୟୁଟର୍ଟି ଏକ ସିଙ୍ଗଲଟନ୍ — `setTimeout()` ଆହ୍ୱାନ କଲେ ପରବର୍ତ୍ତୀ ସମସ୍ତ ଆହ୍ୱାନ ବିଶ୍ୱବ୍ୟାପୀ ଭାବେ ପ୍ରଭାବିତ ହୁଏ। ପ୍ରତି-ସ୍କିଲ୍ ଟାଇମ୍ଆଉଟ୍ ବର୍ତ୍ତମାନ ସମର୍ଥିତ ନୁହେଁ; ପ୍ରତ୍ୟେକ ସ୍କିଲ୍ ପାଇଁ ଭିନ୍ନ ଟାଇମ୍ଆଉଟ୍ ଆବଶ୍ୟକ ହେଲେ, ପୃଥକ ପ୍ରୋସେସ୍ ସବମିଟ୍ କରନ୍ତୁ କିମ୍ବା ଏକ୍ସିକ୍ୟୁଟର୍କୁ ଫୋର୍କ କରନ୍ତୁ।

### ସ୍ଥିତି ମୂଲ୍ୟଗୁଡ଼ିକ

`src/lib/skills/types.ts` ରୁ:

```ts
enum SkillStatus {
  PENDING = "pending", // ଧାଡ଼ିରେ ଅଛି, ଏପର୍ଯ୍ୟନ୍ତ ଆରମ୍ଭ ହୋଇନାହିଁ
  RUNNING = "running", // ହ୍ୟାଣ୍ଡଲର୍ ଆହ୍ୱାନ କରାଯାଇଛି
  SUCCESS = "success", // ହ୍ୟାଣ୍ଡଲର୍ ବୈଧ ଆଉଟ୍ପୁଟ୍ ଫେରାଇଛି
  ERROR = "error", // ହ୍ୟାଣ୍ଡଲର୍ ଏକ ଏକ୍ସେପ୍ସନ୍ ଥ୍ରୋ କରିଛି
  TIMEOUT = "timeout", // ଏକ୍ସିକ୍ୟୁଟର୍ର ଟାଇମ୍ଆଉଟ୍ ଅତିକ୍ରମ କରିଛି
}
```

> **ଟିପ୍ପଣୀ**: `TIMEOUT` ସ୍ଥିତିଟି enum ରେ ପରିଭାଷିତ ହୋଇଛି, କିନ୍ତୁ ବର୍ତ୍ତମାନର ଏକ୍ସିକ୍ୟୁଟର୍ କାର୍ଯ୍ୟାନ୍ୱୟନ ଦ୍ୱାରା ଏହା **ପ୍ରକୃତରେ DB ରେ ଲେଖାଯାଏ ନାହିଁ** — ଟାଇମ୍ଆଉଟ୍ଗୁଡ଼ିକ `"Skill execution timed out"` ବାର୍ତ୍ତା ସହିତ `ERROR` ଭାବେ ଦେଖାଯାଏ। ଏହି ସ୍ଥିତି enum ଭବିଷ୍ୟତରେ ବ୍ୟବହାର ପାଇଁ ସଂରକ୍ଷିତ।

### ନିଷ୍ପାଦନଗୁଡ଼ିକ ଯାଞ୍ଚ କରିବା

```ts
import { skillExecutor } from "omniroute/skills/executor";

// ID ଦ୍ୱାରା ଏକ ନିର୍ଦ୍ଦିଷ୍ଟ ନିଷ୍ପାଦନ ପ୍ରାପ୍ତ କରନ୍ତୁ
const exec = skillExecutor.getExecution("exec-uuid-123");
if (exec) {
  console.log(`${exec.skillName}: ${exec.status} in ${exec.durationMs}ms`);
}

// ଏକ API କୀ ପାଇଁ ସାମ୍ପ୍ରତିକ ନିଷ୍ପାଦନଗୁଡ଼ିକର ତାଲିକା ପ୍ରାପ୍ତ କରନ୍ତୁ
const recent = skillExecutor.listExecutions("api-key-id", 50, 0);
for (const e of recent) {
  console.log(`${e.skillName} → ${e.status} (${e.durationMs}ms)`);
}

// ମୋଟ ନିଷ୍ପାଦନ ସଂଖ୍ୟା ଗଣନା କରନ୍ତୁ
const total = skillExecutor.countExecutions("api-key-id");
```

### ପୁନଃପ୍ରୟାସ ଆଚରଣ

`maxRetries` ସେଟିଂଟି ସଂରକ୍ଷିତ ହୁଏ, କିନ୍ତୁ ଏକ୍ସିକ୍ୟୁଟର୍ର `execute()` ପଦ୍ଧତି ଦ୍ୱାରା **ବର୍ତ୍ତମାନ ବ୍ୟବହୃତ ହୁଏ ନାହିଁ** — ଏହା କେବଳ ଗୋଟିଏ ପ୍ରୟାସ କରେ। `maxRetries` ମୂଲ୍ୟଟି ଭବିଷ୍ୟତ କାର୍ଯ୍ୟାନ୍ୱୟନ ଏବଂ ଏହାକୁ ପଢ଼ିବାକୁ ଚାହୁଁଥିବା ହୁକ୍ଗୁଡ଼ିକ ପାଇଁ ଉନ୍ମୋଚିତ କରାଯାଇଛି।

ବର୍ତ୍ତମାନ ପାଇଁ, ପୁନଃପ୍ରୟାସଗୁଡ଼ିକୁ ସ୍କିଲ୍ ହ୍ୟାଣ୍ଡଲର୍ ମଧ୍ୟରେ ହିଁ କାର୍ଯ୍ୟାନ୍ୱୟନ କରିବା ଆବଶ୍ୟକ। ବିଲ୍ଟ-ଇନ୍
ସ୍କିଲ୍ଗୁଡ଼ିକ ଏକ୍ସିକ୍ୟୁଟର୍ ବିପରୀତରେ ପଞ୍ଜୀକୃତ ହୋଇଥାଏ (ଉଦାହରଣ ସ୍ୱରୂପ `registerBuiltinSkills(executor)`
/ `registerBrowserSkill(executor)` `src/lib/skills/builtin/` ରେ); ଆପଣ ଯେଉଁ ହ୍ୟାଣ୍ଡଲର୍
ପଞ୍ଜୀକରଣ କରନ୍ତି, ତାହା ନିଜର ପୁନଃପ୍ରୟାସ ଲୁପ୍କୁ ରାପ୍ କରିପାରିବ:

```ts
// ଏକ ସ୍କିଲ୍ ହ୍ୟାଣ୍ଡଲର୍ ଭିତରେ
async function handler(input, ctx) {
  const maxRetries = 3;
  let lastError: Error | null = null;

  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      return await fetchSomething(input);
    } catch (err) {
      lastError = err as Error;
      if (attempt < maxRetries) {
        await new Promise((r) => setTimeout(r, 1000 * attempt));
      }
    }
  }
  throw lastError;
}
```

## SkillMode ବିଷୟରେ ବିସ୍ତୃତ ବିବରଣୀ

`SkillMode` enum (`src/lib/skills/types.ts`) ସ୍କିଲ୍ଗୁଡ଼ିକୁ **କେବେ ଏବଂ କିପରି** ଆହ୍ୱାନ କରାଯିବ, ତାହା ନିୟନ୍ତ୍ରଣ କରେ:

```ts
enum SkillMode {
  AUTO = "auto", // ସ୍କିଲ୍ଟିକୁ କେବେ କଲ୍ କରାଯିବ, ତାହା LLM ନିର୍ଦ୍ଧାରଣ କରେ
  MANUAL = "manual", // କେବଳ ସ୍ପଷ୍ଟ ବ୍ୟବହାରକାରୀ ଅନୁରୋଧ ଦ୍ୱାରା ଆହ୍ୱାନ କରାଯାଏ
  HYBRID = "hybrid", // AUTO ସ୍କୋରିଂ + ମାନୁଆଲ୍ ଓଭରରାଇଡ୍
}
```

> **ଟିପ୍ପଣୀ**: କୋଡ୍ବେସ୍ରେ `SkillMode` (AUTO/MANUAL/HYBRID) ପରିଭାଷିତ ହୋଇଛି, ଯେତେବେଳେ `Skill.mode` ଫିଲ୍ଡ ଏକ ଭିନ୍ନ ରୂପ (`"on" | "off" | "auto"`) ବ୍ୟବହାର କରେ। ସେଗୁଡ଼ିକ ପରସ୍ପର ସମ୍ବନ୍ଧିତ, କିନ୍ତୁ ଏକା ନୁହେଁ — `SkillMode` ନିଷ୍ପାଦକ ନୀତି ପାଇଁ ଏବଂ `Skill.mode` ପ୍ରତ୍ୟେକ ସ୍କିଲ୍କୁ ସକ୍ଷମ କରିବା ପାଇଁ ଉଦ୍ଦିଷ୍ଟ।

### ପ୍ରତ୍ୟେକ ମୋଡ୍ କେବେ ବ୍ୟବହାର କରିବେ

| ମୋଡ୍     | LLM ଆଚରଣ                                                                                  | ବ୍ୟବହାର କ୍ଷେତ୍ର                                              |
| -------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `AUTO`   | ଆବଶ୍ୟକ ବୋଲି ବିବେଚନା କଲେ LLM ସ୍କିଲ୍ଟିକୁ କଲ୍ କରିପାରିବ                                       | ସାଧାରଣ-ଉଦ୍ଦେଶ୍ୟର ସ୍କିଲ୍ଗୁଡ଼ିକ (ଫାଇଲ୍ ପଠନ, HTTP ଅନୁରୋଧ)       |
| `MANUAL` | LLM ସ୍କିଲ୍ଟିକୁ କଲ୍ କରିପାରିବ ନାହିଁ; କେବଳ ଏକ ସ୍ପଷ୍ଟ `executeSkill` API କଲ୍ ଏହାକୁ ଆହ୍ୱାନ କରେ | ସମ୍ବେଦନଶୀଳ କାର୍ଯ୍ୟଗୁଡ଼ିକ (ଡାଟାବେସ୍ରେ ଲେଖିବା, ପେମେଣ୍ଟ)        |
| `HYBRID` | LLM ସ୍କିଲ୍ଟିକୁ ପ୍ରସ୍ତାବ କରିପାରିବ; ବ୍ୟବହାରକାରୀଙ୍କୁ ନିଶ୍ଚିତ କରିବାକୁ ପଡ଼ିବ                   | ପାର୍ଶ୍ୱ ପ୍ରଭାବ ଥିବା, କିନ୍ତୁ ବିପଜ୍ଜନକ ନୁହେଁ ଏପରି ସ୍କିଲ୍ଗୁଡ଼ିକ |

### AUTO ସ୍କୋରିଂ

`AUTO` ମୋଡ୍ ସକ୍ରିୟ ଥିବାବେଳେ, `src/lib/skills/injection.ts` ଭିତରେ ଥିବା `scoreAutoSkill()` ଦ୍ୱାରା ପ୍ରତ୍ୟେକ ପ୍ରାର୍ଥୀ ସ୍କିଲ୍କୁ ଅନୁରୋଧ
ପ୍ରସଙ୍ଗ ଅନୁଯାୟୀ ସ୍କୋର୍ କରାଯାଏ — ଏହା ଏକ ଯୋଗାତ୍ମକ,
ପୂର୍ଣ୍ଣସଂଖ୍ୟା ପଏଣ୍ଟ ପ୍ରଣାଳୀ (ସ୍କିଲ୍-ନାମ ମେଳ, ନାମ/ଟ୍ୟାଗ୍/ବର୍ଣ୍ଣନା ଟୋକେନ୍ର ସମାପତନ,
ପୃଷ୍ଠଭୂମି-କାରଣ ସଙ୍କେତ, ପ୍ରଦାତା-ସଙ୍କେତ ବୋନସ୍/ଦଣ୍ଡ)। `score >= AUTO_MIN_SCORE = 3` ଥିବା ଶୀର୍ଷ
`AUTO_MAX_SKILLS = 5`ଟି ସ୍କିଲ୍କୁ କଲ୍ କରାଯାଇପାରୁଥିବା ଟୁଲ୍ ଭାବେ ଇଞ୍ଜେକ୍ଟ କରାଯାଏ,
ସମାନ ସ୍କୋର୍ ହେଲେ ପ୍ରଥମେ `installCount` ଏବଂ ପରେ ନାମ ଆଧାରରେ କ୍ରମ ନିର୍ଦ୍ଧାରଣ କରାଯାଏ। ସମ୍ପୂର୍ଣ୍ଣ ପଏଣ୍ଟ ସାରଣୀ ପାଇଁ ଏହି
ଡକ୍ୟୁମେଣ୍ଟର ପୂର୍ବବର୍ତ୍ତୀ [**ଟୁଲ୍ ସ୍କିମା ଜେନେରେସନ୍ → AUTO ସ୍କୋରିଂ**](#auto-scoring) ଦେଖନ୍ତୁ;
ଏଠାରେ କୌଣସି ଫ୍ଲୋଟ୍ `0.6`-ଶୈଳୀର ଥ୍ରେଶୋଲ୍ଡ ନାହିଁ ଏବଂ `registry.ts`ରେ କୌଣସି ସ୍କୋରିଂ ହୁଏ ନାହିଁ।

## ବିଲ୍ଟ-ଇନ୍ ସ୍କିଲ୍ କ୍ୟାଟାଲଗ୍

OmniRoute ସହିତ `src/lib/skills/builtin/`ରେ ବିଶେଷ ଭାବେ ଚୟନ କରାଯାଇଥିବା ବିଲ୍ଟ-ଇନ୍ ସ୍କିଲ୍ଗୁଡ଼ିକର ଏକ ସେଟ୍ ଉପଲବ୍ଧ ଅଛି। ସବୁଠାରୁ ସାଧାରଣ ସ୍କିଲ୍ଗୁଡ଼ିକ:

### ବ୍ରାଉଜର୍ ଅଟୋମେସନ୍ ସ୍କିଲ୍

ବ୍ରାଉଜର୍ ସ୍କିଲ୍ (`src/lib/skills/builtin/browser.ts`) Playwright/Puppeteer ମାଧ୍ୟମରେ ହେଡ୍ଲେସ୍ ବ୍ରାଉଜର୍ ଅଟୋମେସନ୍ ପ୍ରଦାନ କରେ। **ଏହା କାର୍ଯ୍ୟକାରୀ କରାଯାଇଛି, କିନ୍ତୁ ଡିଫଲ୍ଟ ସ୍କିଲ୍ କ୍ୟାଟାଲଗ୍ରେ ନାହିଁ** — ଏହାକୁ ବ୍ୟବହାର କରିବା ପାଇଁ ବ୍ରାଉଜର୍ ଏକ୍ସଟେନ୍ସନ୍ ପ୍ଲଗ୍ଇନ୍କୁ ପୃଥକ ଭାବେ ଇନ୍ଷ୍ଟଲ୍ କରନ୍ତୁ।

```ts
// ଆପଣଙ୍କ କନ୍ଫିଗ୍ରେ ସକ୍ଷମ କରନ୍ତୁ
const config: SkillConfig = {
  enabled: true,
  mode: SkillMode.MANUAL, // ସର୍ବଦା ସ୍ପଷ୍ଟ ଆହ୍ୱାନ ଆବଶ୍ୟକ କରନ୍ତୁ
  allowedSkills: ["browser"],
  timeout: 60000, // ପୃଷ୍ଠା ଲୋଡ୍ ପାଇଁ 60s
  maxRetries: 1,
};
```
