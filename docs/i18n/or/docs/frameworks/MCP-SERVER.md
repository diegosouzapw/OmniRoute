## ଇନଷ୍ଟଲେସନ୍

OmniRoute MCP ବିଲ୍ଟ-ଇନ୍ ଅଟେ। ଏହାକୁ ଏହିପରି ଆରମ୍ଭ କରନ୍ତୁ:

```bash
omniroute --mcp
```

କିମ୍ବା open-sse ଟ୍ରାନ୍ସପୋର୍ଟ ମାଧ୍ୟମରେ:

```bash
# HTTP ଷ୍ଟ୍ରିମ୍ଯୋଗ୍ୟ ଟ୍ରାନ୍ସପୋର୍ଟ (ପୋର୍ଟ 20130)
omniroute --dev  # /mcp ଏଣ୍ଡପଏଣ୍ଟରେ MCP ସ୍ୱୟଂଚାଳିତ ଭାବେ ଆରମ୍ଭ ହୁଏ
```

HTTP ଟ୍ରାନ୍ସପୋର୍ଟଗୁଡ଼ିକ (`sse` / `streamable-http`, ଡ୍ୟାସବୋର୍ଡ ସର୍ଭର ଦ୍ୱାରା ଇନ୍-ପ୍ରୋସେସ୍ରେ ପରିବେଷିତ)
ଡିଫଲ୍ଟ ଭାବେ ବନ୍ଦ ଥାଏ ଏବଂ ପୂର୍ବରୁ କେବଳ `/dashboard/mcp` ପୃଷ୍ଠାରୁ ଟୋଗଲ୍ କରାଯାଇପାରୁଥିଲା। v3.8.51 ଠାରୁ
CLIରେ ମଧ୍ୟ ସମାନ ସୁବିଧା ଉପଲବ୍ଧ:

```bash
omniroute mcp status                                  # ସକ୍ଷମ/ଅନଲାଇନ୍, ଟ୍ରାନ୍ସପୋର୍ଟ, ଟୁଲ୍ ସଂଖ୍ୟା
omniroute mcp enable [--transport stdio|sse|streamable-http]
omniroute mcp disable
omniroute mcp restart                                 # ସକ୍ରିୟ sse/streamable-http ସେସନ୍ଗୁଡ଼ିକୁ ପୁନଃସେଟ୍ କରେ
```

`mcp enable`/`mcp disable`, `/api/settings` ମାଧ୍ୟମରେ ଡ୍ୟାସବୋର୍ଡ ଟୋଗଲ୍ କରୁଥିବା ସେହି
`mcpEnabled` (ଏବଂ ଇଚ୍ଛାନୁସାରେ `mcpTransport`) ସେଟିଂକୁ PATCH କରେ। `mcp restart`, `POST /api/mcp/restart`କୁ କଲ୍ କରେ: ଏହା
ସକ୍ରିୟ `sse`/`streamable-http` ସେସନ୍ଗୁଡ଼ିକୁ ବନ୍ଦ କରିଦିଏ, ଯାହାଦ୍ୱାରା ପରବର୍ତ୍ତୀ ଅନୁରୋଧ ସ୍ୱଚ୍ଛ ଭାବେ ପୁନଃ-ଇନିସିଆଲାଇଜ୍ ହୁଏ; MCP ଅକ୍ଷମ ଥିଲେ
`409` ଏବଂ `stdio` ଟ୍ରାନ୍ସପୋର୍ଟ ପାଇଁ `501` ଫେରାଏ (stdio କ୍ଲାଏଣ୍ଟଗୁଡ଼ିକ ନିଜ ସବ୍ପ୍ରୋସେସ୍ର ମାଲିକ —
ପୁନଃଆରମ୍ଭ କରିବା ପାଇଁ କୌଣସି ଇନ୍-ପ୍ରୋସେସ୍ ହ୍ୟାଣ୍ଡଲ୍ ନାହିଁ)।

## ଟ୍ରାନ୍ସପୋର୍ଟଗୁଡ଼ିକ

MCP ସର୍ଭର ତିନୋଟି ଟ୍ରାନ୍ସପୋର୍ଟ ପ୍ରଦାନ କରେ, ସମସ୍ତ ସମାନ `createMcpServer()` ଫ୍ୟାକ୍ଟ୍ରି ଦ୍ୱାରା ସମର୍ଥିତ:

| Transport         | Where                                       | When to use                                                       |
| :---------------- | :------------------------------------------ | :---------------------------------------------------------------- |
| `stdio`           | `open-sse/mcp-server/server.ts`             | IDE ଇଣ୍ଟିଗ୍ରେସନ୍ (Claude Desktop, Cursor, ଇତ୍ୟାଦି)                |
| `sse`             | `POST/GET /api/mcp/sse` via `httpTransport` | ବ୍ରାଉଜର/ଏଜେଣ୍ଟ କ୍ଲାଏଣ୍ଟମାନେ ଯେଉଁମାନଙ୍କୁ ଏକ ଇଭେଣ୍ଟ ସ୍ଟ୍ରିମ୍ ଆବଶ୍ୟକ |
| `streamable-http` | `POST/GET/DELETE /api/mcp/stream`           | ମଲ୍ଟି-ସେସନ୍ HTTP କ୍ଲାଏଣ୍ଟମାନେ (`mcp-session-id` ହେଡର୍)            |

ସକ୍ରିୟ HTTP ଟ୍ରାନ୍ସପୋର୍ଟ (`sse` କିମ୍ବା `streamable-http`) `mcpTransport` ସେଟିଂ ଦ୍ୱାରା ଚୟନ କରାଯାଏ। ଟ୍ରାନ୍ସପୋର୍ଟ ପରିବର୍ତ୍ତନ କରିବା ଅନ୍ୟ ଟ୍ରାନ୍ସପୋର୍ଟରେ ଥିବା ବିଦ୍ୟମାନ ସେସନ୍ଗୁଡ଼ିକୁ ବନ୍ଦ କରିଦିଏ।

### ରିମୋଟ୍ ଆକ୍ସେସ୍ (manage-scope ବାଇପାସ୍)

`/api/mcp/*` LOCAL_ONLY ସ୍ତରରେ ଅଛି (`src/server/authz/routeGuard.ts`) — ଡିଫଲ୍ଟ ଭାବରେ କେବଳ loopback ହୋଷ୍ଟଗୁଡ଼ିକ (`localhost`, `127.0.0.1`, `::1`) ଏହାକୁ ଆକ୍ସେସ୍ କରିପାରିବେ। v3.8.2 ଠାରୁ, non-loopback କ୍ଲାଏଣ୍ଟମାନେ ସେତେବେଳେ ସଂଯୋଗ କରିପାରିବେ ଯେତେବେଳେ ସେମାନେ `Authorization: Bearer <api-key>` ଉପସ୍ଥାପନ କରନ୍ତି ଯାହାର କି `manage` ସ୍କୋପ୍ ଧାରଣ କରେ। ଟନେଲ୍, ରିଭର୍ସ ପ୍ରକ୍ସି, କିମ୍ବା ସାର୍ବଜନୀନ ହୋଷ୍ଟନେମ୍ ମାଧ୍ୟମରେ ରିମୋଟ୍ MCP ସର୍ଭରରେ ପହଞ୍ଚିବାର ଏହା ଏକମାତ୍ର ଉପାୟ।

```bash
# manage ସ୍କୋପ୍ ପ୍ରଦାନ କରନ୍ତୁ: ଡ୍ୟାସବୋର୍ଡ API କୀ ପୃଷ୍ଠା ଖୋଲନ୍ତୁ ଏବଂ ଟଗଲ୍ କରନ୍ତୁ
# କୀରେ "Management Access", କିମ୍ବା ସୃଷ୍ଟି ସମୟରେ POST scopes:["manage"] କରନ୍ତୁ।

# ତାପରେ ଏକ ରିମୋଟ୍ MCP କ୍ଲାଏଣ୍ଟରୁ ସଂଯୋଗ କରନ୍ତୁ:
curl -i \
  -H "Host: your-public-host.example" \
  -H "Authorization: Bearer sk-…" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"my-client","version":"0"}}}' \
  https://your-public-host.example/api/mcp/stream
```

ଏକ non-manage କୀ (କିମ୍ବା Bearer ନଥିଲେ) `403 LOCAL_ONLY` ଫେରାଇଥାଏ। ସହଯୋଗୀ ଉପସର୍ଗ `/api/cli-tools/runtime/*` ଉଦ୍ଦେଶ୍ୟମୂଳକ ଭାବରେ ବାଇପାସ୍ କରାଯାଇପାରିବ ନାହିଁ — [Route Guard Tiers — Manage-scope carve-out](../security/ROUTE_GUARD_TIERS.md#manage-scope-carve-out) ଦେଖନ୍ତୁ।

ବର୍ଣ୍ଣନା (`tools`, `prompts`, `resources`, ଏବଂ `resourceTemplates`) ପାଇଁ ମେଟାଡେଟା-ଆକାର ଅନୁମାନ; ସେମାନେ ପ୍ରଦାନକର୍ତ୍ତା ବ୍ୟବହାର

### MCP ଆକ୍ସେସିବିଲିଟି ଟ୍ରି ଫିଲ୍ଟର୍ (v3.8.0)

ଉପରେ ଦିଆଯାଇଥିବା କମ୍ପ୍ରେସନ୍ ଉପକରଣଗୁଡ଼ିକ ଠାରୁ ଅଲଗା, OmniRoute ରେ ଏକ ପୋଷ୍ଟ-ଏକ୍ସିକ୍ୟୁସନ୍ ଫିଲ୍ଟର୍ ଅଛି ଯାହା
MCP ବ୍ରାଉଜର୍/ଆକ୍ସେସିବିଲିଟି ଉପକରଣଗୁଡ଼ିକର **ଟୁଲ୍ ଫଳାଫଳ** କୁ ଏଜେଣ୍ଟ୍ ନିକଟକୁ ଫେରାଇ ଆଣିବା ପୂର୍ବରୁ ସଂକୁଚିତ କରେ।
ଏହି ଫିଲ୍ଟର୍ ନିଜେ ଏକ ଉପକରଣ ନୁହେଁ — ଏହା ସ୍ୱଚାଳିତ ଭାବରେ କୌଣସି ଟୁଲ୍ ଫଳାଫଳ ଉପରେ ଚାଲେ ଯାହାରେ ବିସ୍ତୃତ
ଆକ୍ସେସିବିଲିଟି-ଟ୍ରି କିମ୍ବା ବ୍ରାଉଜର୍-ସ୍ନାପସଟ୍ ଟେକ୍ସଟ୍ (≥2000 ଅକ୍ଷର) ଥାଏ।

ମୁଖ୍ୟ ବ୍ୟବହାର:

- ≥30 ଲଗାତାର ପୁନରାବୃତ୍ତି ହୋଇଥିବା ସାଇବ୍ଲିଙ୍ଗ୍ ଲାଇନ୍ଗୁଡ଼ିକୁ ହେଡ୍ + ଟେଲ୍ ସାରାଂଶ ଭାବରେ ସଙ୍କୁଚିତ କରେ
- Playwright/computer-use ଦ୍ୱାରା ଆବଶ୍ୟକ `ref=eXX]` ଏଙ୍କର୍ଗୁଡ଼ିକୁ ସଂରକ୍ଷଣ କରେ
- ବିଶାଳ ଟେକ୍ସଟ୍ (>50,000 ଅକ୍ଷର) କୁ ଏକ ନ୍ୟାଭିଗେସନ୍ ସୂଚନା ସହ ହାର୍ଡ-ଟ୍ରାନ୍କେଟ୍ କରେ
- ଅପେକ୍ଷିତ ସଞ୍ଚୟ: ବ୍ରାଉଜର୍ ସ୍ନାପସଟ୍ ପେଲୋଡ୍ଗୁଡ଼ିକରେ **୬୦–୮୦%**

କନଫିଗରେସନ୍: ସାମଗ୍ରିକ ସେଟିଂସ୍ରେ `compression.mcpAccessibility` (ମାଇଗ୍ରେସନ୍ ୦୫୬)।
ବାସ୍ତବାୟନ: `open-sse/services/compression/engines/mcpAccessibility/`।
ସମ୍ପୂର୍ଣ୍ଣ ଡକ୍ସ: [କମ୍ପ୍ରେସନ୍ ଇଞ୍ଜିନ୍ଗୁଡ଼ିକ — MCP ଆକ୍ସେସିବିଲିଟି ଟ୍ରି ଫିଲ୍ଟର୍](../compression/COMPRESSION_ENGINES.md#mcp-accessibility-tree-filter)।

ଏହି ଉପକରଣଗୁଡ଼ିକ ପଛରେ ଥିବା ରନ୍ଟାଇମ୍ କମ୍ପ୍ରେସନ୍ ମଡେଲ୍ ପାଇଁ [କମ୍ପ୍ରେସନ୍ ଇଞ୍ଜିନ୍ଗୁଡ଼ିକ](../compression/COMPRESSION_ENGINES.md) ଏବଂ [RTK କମ୍ପ୍ରେସନ୍](../compression/RTK_COMPRESSION.md) ଦେଖନ୍ତୁ।

OmniRoute ସହ ସମାନ କନେକସନ୍ ମୋଡେଲ୍ ମାଧ୍ୟମରେ ୱାୟାର୍ କରାଯାଇଛି ଯାହା LLM ପ୍ରୋଭାଇଡରମାନଙ୍କ ପାଇଁ ବ୍ୟବହୃତ ହୁଏ। ସେମାନେ
ନିଜର REST ସରଫେସ୍ (`/api/v1/agents/*`) ମାଧ୍ୟମରେ ଏକ୍ସପୋଜ୍ ହୁଅନ୍ତି ଏବଂ MCP ଟୁଲ୍ କ୍ୟାଟାଲଗ୍ ର ଅଂଶ ନୁହଁନ୍ତି
— ଏକ କ୍ଲାଉଡ୍ ଏଜେଣ୍ଟ ଡାକିବା MCP ସ୍କୋପ୍ ଖାଇ ନ ଥାଏ।

- ବାସ୍ତବାୟନ: `src/lib/cloudAgent/` (`registry.ts`, `agents/codex.ts`, `agents/cursor.ts`, `agents/devin.ts`, `agents/jules.ts`)।
- ଜୀବନଚକ୍ର: `createTask`, `getStatus`, `approvePlan`, `sendMessage`, `listSources`।
- ଡକୁମେଣ୍ଟେସନ୍: [docs/frameworks/CLOUD_AGENT.md](./CLOUD_AGENT.md)।

### ଗାର୍ଡରେଲ୍ସ

ଗାର୍ଡରେଲ୍ସ ହେଉଛି ପୂର୍ବ/ପର-ନିଷ୍ପାଦନ ଫିଲ୍ଟର (vision-bridge, pii-masker, prompt-injection)
ଚ୍ୟାଟ୍ ପାଇପଲାଇନ୍ ମଧ୍ୟରେ ପ୍ରୟୋଗ କରାଯାଏ। ସେମାନେ MCP ଟୁଲ୍/ରୁଟ୍ ସ୍ତର ପହଞ୍ଚିବା ପୂର୍ବରୁ ଚାଲୁଥାନ୍ତି
ଏବଂ ଅଡିଟ୍ ପାଇପଲାଇନ୍କୁ ସଂରଚିତ ଉଲ୍ଲଂଘନ ପ୍ରେରଣ କରନ୍ତି; ସେମାନେ MCP ଟୁଲ୍ସ ଭାବରେ ଡାକା ଯାଏ ନାହିଁ।

- ବାସ୍ତବାୟନ: `src/lib/guardrails/`।
- ଡକୁମେଣ୍ଟେସନ୍: [docs/security/GUARDRAILS.md](../security/GUARDRAILS.md)।

ଯେତେବେଳେ ଏକ MCP କଲ୍ ଯାହା ଅବରୋଧିତ ଲାଗୁଛି ସେହି ଡିବଗ୍ କରିବା ସମୟରେ, MCP ଅଡିଟ୍ ଲଗ୍ ଏବଂ ଗାର୍ଡରେଲ୍ସ ଅଡିଟ୍ ଟ୍ରେଲ୍ ଦୁଇଟି ଯାଞ୍ଚ କରନ୍ତୁ — ଏକ ଅନୁରୋଧ MCP ସ୍କୋପ୍ ପ୍ରତିଷ୍ଠା ସ୍ତରରେ ପହଞ୍ଚିବା **ଆଗରୁ** ଏକ ଗାର୍ଡରେଲ୍ ଦ୍ୱାରା ପ୍ରତ୍ୟାଖ୍ୟାନ ହୋଇପାରେ।

### `mcp:connect` — ସଂକୀର୍ଣ୍ଣ ରୁଟ୍ କ୍ଷମତା (#7895)

ନନ-ଲୁପବ୍ୟାକରୁ HTTP/SSE MCP ପରିବହନ (`/api/mcp/*`) ପହଞ୍ଚିବା ପାଇଁ
`/api/mcp/` LOCAL_ONLY ବାଦବାକୀ ଆବଶ୍ୟକ (ଦେଖନ୍ତୁ `docs/security/ROUTE_GUARD_TIERS.md`)। ଐତିହାସିକ ଭାବରେ
ସେହି ବାଦବାକୀ କେବଳ ଏକ ସମ୍ପୂର୍ଣ୍ଣ `manage`/`admin`-ସ୍କୋପ୍ API କୀ ଗ୍ରହଣ କରୁଥିଲା — ଯେଉଁ କଲର୍ କେବଳ MCP ସହ କଥା ହେବାର ଆବଶ୍ୟକତା ଅଛି ତାହା ପାଇଁ ବହୁତ ବ୍ୟାପକ। `src/shared/constants/managementScopes.ts` ବର୍ତ୍ତମାନ `MCP_CONNECT_SCOPE = "mcp:connect"` ର ରପ୍ତାନି କରେ: ଏକ ସମନ୍ୱୟାତ୍ମକ, ସଂକୀର୍ଣ୍ଣ ସ୍କୋପ୍ (`SELF_USAGE_SCOPE` ସହ ସମାନ ପ୍ରାକୃତିକ) ଯାହା କେବଳ
`src/server/authz/policies/management.ts` ରେ `/api/mcp/` ବାଇପାସ୍ ଅଧିକୃତ କରେ — ଏହା ଅନ୍ୟ କୌଣସି ପରିଚାଳନା-ରୁଟ୍ ପ୍ରବେଶ ପ୍ରଦାନ କରେ ନାହିଁ ଏବଂ ଜାଣିଶୁଣି `MANAGEMENT_API_KEY_SCOPES` ବାହାରେ ରଖାଯାଇଛି। ଏକ କୀ `manage`/`admin` ଧାରଣ କରୁଥିଲେ ସେ ବାଦବାକୀ ମାଧ୍ୟମରେ ଏବେ ବି ପାସ୍ କରେ; `mcp:connect` ରିମୋଟ୍ MCP-ମାତ୍ର କଲର୍ଗୁଡିକ ପାଇଁ ଏକ ନିମ୍ନ-ଅଧିକାର ବିକଳ୍ପ, `hasMcpConnectOrManageScope()` ମାଧ୍ୟମରେ ଯାଞ୍ଚ କରାଯାଏ।

### ପ୍ରତି-କୀ HTTP ସ୍କୋପ୍ ବାଇନ୍ଡିଂ (#7895)

HTTP/SSE ଉପରେ, `open-sse/mcp-server/httpTransport.ts` ବର୍ତ୍ତମାନ କଲର୍ର ପ୍ରକୃତ
`api_keys.scopes` କୁ `resolveMcpCallerAuthInfo()` (`open-sse/mcp-server/httpAuthContext.ts`) ମାଧ୍ୟମରେ ସମାଧାନ କରେ ଏବଂ ଏହାକୁ MCP SDK ର `transport.handleRequest(req, { authInfo })` କୁ ପ୍ରେରଣ କରେ, ତେଣୁ
`extra.authInfo.scopes` ପ୍ରତ୍ୟେକ ଟୁଲ୍ କଲ୍ ରେ ପହଞ୍ଚୁଥିବା Bearer କୀ ର ନିଜ ସ୍କୋପ୍ ପ୍ରତିଫଳିତ କରେ।
`scopeEnforcement.ts` ର `resolveCallerScopeContext()` ଇତିମଧ୍ୟରେ `_meta` ଏବଂ `OMNIROUTE_MCP_SCOPES` ଏନଭାଇରନ୍ମେଣ୍ଟ ଫଲବ୍ୟାକ୍ ଉପରେ `authInfo` କୁ ପ୍ରାଥମିକତା ଦେଉଥିଲା — ଏହା କେବଳ ସେହି ପ୍ରଥମ, ସର୍ବୋଚ୍ଚ-ପ୍ରାଥମିକତା ଉତ୍ସକୁ ପୂରଣ କରେ, ଯାହା ପୂର୍ବରୁ HTTP ଉପରେ ଅପୂରଣ ଥିଲା। ଯେତେବେଳେ କୌଣସି API କୀ ସମାଧାନ ହୁଏ ନାହିଁ (କୌଣସି ହେଡର୍ ନାହିଁ, ଅବୈଧ କୀ), `authInfo` `undefined` ରହେ ଏବଂ ସମାଧାନ ଅପରିବର୍ତ୍ତିତ ଭାବରେ ବିଦ୍ୟମାନ `meta`/ଏନଭାଇରନ୍ମେଣ୍ଟ ଶୃଙ୍ଖଳା ମଧ୍ୟକୁ ପ୍ରବାହିତ ହୁଏ। ଏହା `OMNIROUTE_MCP_ENFORCE_SCOPES` ର ଡିଫଲ୍ଟ୍ ପରିବର୍ତ୍ତନ କରେ ନାହିଁ — ପ୍ରୟୋଗ ଏବେ ବି ସ୍ପଷ୍ଟ ଭାବରେ ସକ୍ରିୟ ହେବା ଆବଶ୍ୟକ; ଏହି ପରିବର୍ତ୍ତନ କେବଳ ପ୍ରତି-କୀ ପଥକୁ ସକ୍ରିୟ ହେଲେ ପ୍ରାଥମିକତା ନେବାକୁ ସକ୍ଷମ କରେ। stdio ରେ କୌଣସି ପ୍ରତି-କଲର୍ ପରିଚୟ ନାହିଁ (ଦେଖନ୍ତୁ
`mcpCallerIdentity.ts`) ଏବଂ ଏହା ପ୍ରଭାବିତ ହୁଏ ନାହିଁ — ଏହା `_meta`/ଏନଭାଇରନ୍ମେଣ୍ଟ ଫଲବ୍ୟାକ୍ ଶୃଙ୍ଖଳା ଉପରେ ରହେ।

## ବର୍ଣ୍ଣନା ସଂକୋଚନ

MCP ଟୁଲ୍, ପ୍ରମ୍ପଟ୍, ଏବଂ ରିସୋର୍ସ ରେଜିଷ୍ଟ୍ରୀ ଗୁଡିକ ଗ୍ରାହକମାନଙ୍କୁ ପ୍ରଦାନ କରାଯାଉଥିବା ମେଟାଡାଟା ଫୁଟ୍ପ୍ରିଣ୍ଟ୍ (ଏବଂ ତେଣୁ ପ୍ରମ୍ପଟ୍ କନ୍ଟେକ୍ସ୍ଟ୍ ଖର୍ଚ୍ଚ) ହ୍ରାସ କରିବାକୁ ପଞ୍ଜିକରଣ/ଲିଷ୍ଟ ସମୟରେ ବର୍ଣ୍ଣନା ଗୁଡିକୁ ସଂକୋଚନ କରିପାରନ୍ତି। ଏହି କାର୍ଯ୍ୟାନ୍ୱୟନ `open-sse/mcp-server/descriptionCompressor.ts` ରେ ଥାଏ ଏବଂ `createMcpServer()` ର ମଧ୍ୟରେ `compressMcpRegistryMetadata` ମାଧ୍ୟମରେ MCP ସର୍ଭରରେ ୱାୟାର୍ଡ କରାଯାଏ।

- ସଂକୋଚନ ବର୍ଣ୍ଣନା ଟେକ୍ସଟ୍ ଉପରେ କେଭମ୍ୟାନ୍ ନିୟମାବଳୀ (`getRulesForContext("all", "full")`) ସହିତ ସଂରକ୍ଷିତ-ବ୍ଲକ୍ ଏକ୍ସଟ୍ରାକ୍ସନ (କୋଡ୍ ସ୍ପାନ୍, ଫେନ୍ସ୍ଡ ବ୍ଲକ୍ ଇତ୍ୟାଦି) ସହିତ ଚାଲେ, ତେଣୁ ସଂରଚନାତ୍ମକ ବିଷୟବସ୍ତୁକୁ ପରିବର୍ତ୍ତନ କରାଯାଏ ନାହିଁ।
- ପ୍ରତ୍ୟେକ ପରିବେଶ ପାଇଁ `key_value` ସେଟିଂସ୍ ଟେବୁଲ୍ ରେ `compression.mcpDescriptionCompressionEnabled` ମୂଲ୍ୟ ମାଧ୍ୟମରେ ଟଗୁଲ୍ କରନ୍ତୁ (ଡିଫଲ୍ଟ: ସକ୍ରିୟ) — UI ରେ **Analytics → MCP description compression** ଭାବରେ ପ୍ରଦାନ କରାଯାଏ।
- `OMNIROUTEMCP_COMPRESS_DESCRIPTIONS=false` କିମ୍ବା `OMNIROUTE_MCP_DESCRIPTION_COMPRESSION=false` ମାଧ୍ୟମରେ ସମଗ୍ର ପ୍ରକ୍ରିୟା ପାଇଁ ଟଗୁଲ୍ କରନ୍ତୁ।
- ରିଅଲଟାଇମ୍ ପରିସଂଖ୍ୟାନ `analytics.mcpDescriptionCompression` ଅଧୀନରେ `omniroute_compression_status` ମାଧ୍ୟମରେ ସାମ୍ନାକୁ ଆସେ ଏବଂ ପ୍ରକୃତ ପ୍ରଦାତା ବ୍ୟବହାର ରସିଦ୍ ଗୁଡିକରୁ ବିଭେଦନ ପାଇଁ `source: "mcp_metadata_estimate"` ଟ୍ୟାଗ୍ ହୋଇଥାଏ।

## ଟୁଲ୍ କାର୍ଡିନାଲିଟି ହ୍ରାସ (F4.3)

ବର୍ଣ୍ଣନା ସଙ୍କୋଚନ ପ୍ରତ୍ୟେକ ଟୁଲ୍ର ମେଟାଡାଟାକୁ ସଙ୍କୁଚିତ କରେ; **ଟୁଲ୍-କାର୍ଡିନାଲିଟି ହ୍ରାସ** ଆଉ ଏକ ପଦକ୍ଷେପ ଆଗକୁ ଯାଇ ମୋଟାମୋଟି _କେତେଗୁଡିକ_ ଟୁଲ୍ ଘୋଷିତ ହେଉଛନ୍ତି ସେଥିରୁ ହ୍ରାସ କରେ। `tools/list` ମ୍ୟାନିଫେଷ୍ଟରେ କମ୍ ଟୁଲ୍ ପ୍ରଚାର କରିବା ଦ୍ୱାରା କ୍ଲାଏଣ୍ଟ ମଡେଲ ଦ୍ୱାରା ଟୁଲ୍ କ୍ୟାଟାଲଗ୍ ("ଲେୟାର 5" ସଙ୍କୋଚନ) ପାଇଁ ପ୍ରତି-ଅନୁରୋଧ ଟୋକେନ୍ ଖର୍ଚ୍ଚ କମ୍ ହୁଏ। ଏହାର କାର୍ଯ୍ୟାନ୍ୱୟନ ହେଉଛି `open-sse/mcp-server/toolCardinality.ts` (`reduceToolManifest`) ରେ ଏକ ବିଶୁଦ୍ଧ, ଅବସ୍ଥାନରହିତ ଫିଲ୍ଟର, ଯାହା `createMcpServer()` (`open-sse/mcp-server/server.ts`) ରେ ଥିବା ପଞ୍ଜିକରଣ ଲୁପ୍ରେ ସଂଯୋଗ କରାଯାଇଛି।

**ବିକଳ୍ପ-ଅନୁମୋଦିତ, ଡିଫଲ୍ଟରେ ଅଫ୍।** ଫିଲ୍ଟର କେବଳ ସେତେବେଳେ ଚଳେ ଯେତେବେଳେ ଦୁଇଟି ପରିବେଶ ଭେରିଆବଲ୍ରୁ ଅନ୍ତତଃ ଗୋଟିଏ ସେଟ୍ ଥାଏ; ଦୁଇଟି ମଧ୍ୟ ସେଟ୍ ନ ଥିଲେ, ସମସ୍ତ ୧୧୦ଟି ଟୁଲ୍ ଅପରିବର୍ତ୍ତିତ ଭାବରେ ଘୋଷିତ ହୁଏ।

| ଭେରିଆବଲ୍         | ମୋଡ୍                                                                                |
| :--------------- | :---------------------------------------------------------------------------------- |
| `MCP_TOOL_DENY`  | ବ୍ଲାକଲିଷ୍ଟ — କମା-ବିଭାଜିତ ଟୁଲ୍ ନାମ ଯାହା `tools/list` ରୁ ସର୍ବଦା ହଟାଯାଏ                |
| `MCP_TOOL_ALLOW` | ଅନୁମୋଦନ ତାଲିକା — କମା-ବିଭାଜିତ ଟୁଲ୍ ନାମ; କେବଳ ଏହିଗୁଡିକ ବଞ୍ଚିଥାନ୍ତି, ଅନ୍ୟ ସମସ୍ତ ହଟାଯାଏ |

`deny` କୁ `allow` ଉପରେ ଅଗ୍ରାଧିକାର ଦିଆଯାଏ। ନାମଗୁଡିକ କମା-ବିଭାଜିତ, ଟ୍ରିମ୍ କରାଯାଇଛି, ଏବଂ ଖାଲି ଏଣ୍ଟ୍ରିଗୁଡିକୁ ଅଣଦେଖା କରାଯାଏ। ଉଦାହରଣ:

```bash
# କ୍ୟାଟାଲଗ୍ ରୁ ଦୁଇଟି ଟୁଲ୍ ହଟାନ୍ତୁ
MCP_TOOL_DENY="omniroute_get_health,omniroute_list_combos" omniroute --mcp

# କେବଳ ରୁଟିଂ୍ + କୋଟା ଟୁଲ୍ ଘୋଷଣା କରନ୍ତୁ (ଅନୁମୋଦନ ତାଲିକା ମୋଡ୍)
MCP_TOOL_ALLOW="omniroute_route_request,omniroute_check_quota" omniroute --mcp
```

**ଫିଲ୍ଟର୍ କରାଯାଇଥିବା ଟୁଲ୍ କିପରି ହଟାଯାଏ:** ପଞ୍ଜିକରଣ ସର୍ବଦା ସଫଳ ହୁଏ; ପ୍ରୋଫାଇଲ୍ ଦ୍ୱାରା ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଇଥିବା ଏକ ଟୁଲ୍, MCP SDK ହ୍ୟାଣ୍ଡଲ୍ ଉପରେ `.disable()` କରାଯାଏ, ତେଣୁ ସେ `tools/list` ରେ କେବଳ ଦେଖାଯାଏ ନାହିଁ କିନ୍ତୁ ୱାୟାରିଂ ଅଖଣ୍ଡ ରହେ (ସ୍ୱଚ୍ଛ ସକ୍ରିୟ/ନିଷ୍କ୍ରିୟ, ପୁନର୍ପଞ୍ଜିକରଣ ନାହିଁ)। ପ୍ରୋଫାଇଲ୍ ପାର୍ସର୍ ହେଉଛି `readMcpToolProfileFromEnv(process.env)`, ଯାହା ଉଭୟ ଭେରିଆବଲ୍ ଖାଲି ଥିଲେ `null` (କୌଣସି ଫିଲ୍ଟରିଂ ନାହିଁ) ଫେରାଏ।

`reduceToolManifest` ପଛରେ ଥିବା ସମୃଦ୍ଧ `ToolProfile` ସୃଷ୍ଟି ସ୍କୋପ୍-ଇଣ୍ଟରସେକ୍ସନ୍ ଫିଲ୍ଟରିଂ (`allowScopes`, `read:*`-ଶୈଳୀ ୱାଇଲ୍ଡକାର୍ଡ ମ୍ୟାଚିଂ ସହ), ଏବଂ ଏକ ନିଶ୍ଚିତ `maxTools` ସୀମା ମଧ୍ୟ ସମର୍ଥନ କରେ, କିନ୍ତୁ ସେହି ଦୁଇଟି ନିୟନ୍ତ୍ରଣ ପଞ୍ଜିକରଣ ସମୟରେ ସମ୍ପୂର୍ଣ୍ଣ ମ୍ୟାନିଫେଷ୍ଟ ଆବଶ୍ୟକ କରନ୍ତି ଏବଂ ଆଜି ପରିବେଶ ଭେରିଆବଲ୍ ମାଧ୍ୟମରେ **ପ୍ରଦର୍ଶିତ ହୁଏ ନାହିଁ** (`tools/list`-ସ୍ତରର ହୁକ୍ ଏକ ଟ୍ରାକ୍ କରାଯାଇଥିବା ଫଲୋ-ଅପ୍)। ହ୍ରାସ ପୂର୍ବରୁ ଏବଂ ପରେ ମ୍ୟାନିଫେଷ୍ଟ ଟୋକେନ୍ ଖର୍ଚ୍ଚ ତୁଳନା କରିବାକୁ `estimateManifestTokens()` ଉପಲବ୍ଧ।

## ରନ୍ଟାଇମ୍ ହାର୍ଟବିଟ୍

stdio ଟ୍ରାନ୍ସପୋର୍ଟ ପ୍ରତି ୫ ସେକେଣ୍ଡରେ `${DATA_DIR}/runtime/mcp-heartbeat.json` ରେ ଲାଇଭ୍ନେସ୍ ସ୍ଥାୟୀ କରେ। ଡ୍ୟାସବୋର୍ଡ (`/api/mcp/status`) ଏହି ଫାଇଲ୍ ଏବଂ PID ଲାଇଭ୍ନେସ୍ ପଢ଼ି `online` ପ୍ରାପ୍ତ କରେ। HTTP ଟ୍ରାନ୍ସପୋର୍ଟଗୁଡିକ ପ୍ରକ୍ରିୟା-ଭିତରେ `getMcpHttpStatus()` ରୁ ସ୍ଥିତି ରିପୋର୍ଟ କରେ (ଫାଇଲ୍ ଲେଖା ନାହିଁ)।

ହାର୍ଟବିଟ୍ ସ୍ନାପସ଼ଟ୍ ଅନ୍ତର୍ଭୁକ୍ତ କରେ:

```json
{
  "pid": 12345,
  "startedAt": "2026-05-13T12:34:56.000Z",
  "lastHeartbeatAt": "2026-05-13T12:35:01.000Z",
  "version": "1.8.1",
  "transport": "stdio",
  "scopesEnforced": false,
  "allowedScopes": [],
  "toolCount": 110
}
```

- ଟୁଲ୍ ନାମ, ଆର୍ଗୁମେଣ୍ଟ୍ (ପ୍ରତି-ଟୁଲ୍ `auditLevel` ଅନୁସାରେ ହ୍ୟାସ୍/ଟ୍ରଙ୍କେଟ୍), ଫଳାଫଳ
- ସମୟ ମିଲିସେକେଣ୍ଡରେ, ସଫଳତା/ବିଫଳତା ଫ୍ଲାଗ୍, ତ୍ରୁଟି ବାର୍ତ୍ତା (ଯେତେବେଳେ ପ୍ରଯୁଜ୍ୟ)
- API କୀ ହ୍ୟାସ୍, ଟାଇମ୍�୍ଟାମ୍ପ
- ସ୍କୋପ୍ ଅସ୍ୱୀକାରଗୁଡିକ `scope_denied:<reason>` ଭାବରେ ଲଗ୍ ହୁଏ ସହ ଅନୁପସ୍ଥିତ ସ୍କୋପ୍ ତାଲିକା

ସାମ୍ପ୍ରତିକ କଲ୍ ପରଖିବାକୁ ଡ୍ୟାସବୋର୍ଡ୍ ବା `/api/mcp/audit` ଏବଂ `/api/mcp/audit/stats` REST ଏଣ୍ଡପଏଣ୍ଟ୍ ବ୍ୟବହାର କରନ୍ତୁ।
