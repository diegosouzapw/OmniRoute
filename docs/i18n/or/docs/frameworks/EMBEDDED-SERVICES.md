ଏମ୍ବେଡେଡ୍ ସେବାଗୁଡ଼ିକ ହେଉଛି ସ୍ଥାନୀୟ ଭାବେ ଇନ୍ଷ୍ଟଲ୍ ହୋଇଥିବା ପ୍ରୋସେସ୍ ସାଇଡ୍କାର୍ ଟୁଲ୍, ଯାହାକୁ OmniRoute ଇନ୍ଷ୍ଟଲ୍ ଓ ନିରୀକ୍ଷଣ କରେ ଏବଂ
ପ୍ରଥମ-ଶ୍ରେଣୀର ରାଉଟିଂ ଲକ୍ଷ୍ୟ ଭାବେ ଉପଲବ୍ଧ କରାଏ। ବାହ୍ୟ ପ୍ରଦାନକାରୀମାନଙ୍କ ପରି ନୁହେଁ (ଯେଉଁମାନଙ୍କ ସହ API କି ମାଧ୍ୟମରେ ଇଣ୍ଟରନେଟ୍ ଉପରେ
ଯୋଗାଯୋଗ କରାଯାଏ), ଏମ୍ବେଡେଡ୍ ସେବାଗୁଡ଼ିକ OmniRoute ଥିବା ସେହି ମେସିନ୍ରେ ଚାଲେ ଏବଂ ଲୁପ୍ବ୍ୟାକ୍ ମାଧ୍ୟମରେ ଯୋଗାଯୋଗ କରେ।

## 1. ସାରାଂଶ

### ଏମ୍ବେଡେଡ୍ ସେବାଗୁଡ଼ିକ କାହିଁକି?

ଛଅଟି ସେବା ଏମ୍ବେଡ୍ କରାଯାଇଛି:

| ସେବା            | npm ପ୍ୟାକେଜ୍                       | ଡିଫଲ୍ଟ ପୋର୍ଟ | ଉଦ୍ଦେଶ୍ୟ                                                                                                                                                                                          |
| --------------- | ---------------------------------- | :----------: | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **9Router**     | `9router`                          |    20130     | AI ରାଉଟର୍, ଯାହାକୁ OmniRoute ଏକ ସବ୍-ପ୍ରୋଭାଇଡର୍ ଭାବେ ବ୍ୟବହାର କରିପାରେ। ମଡେଲ୍ଗୁଡ଼ିକ `9router/{sub}/{model}` ଭାବେ ଉପଲବ୍ଧ କରାଯାଏ                                                                        |
| **CLIProxyAPI** | GitHub ରିଲିଜ୍ ବାଇନାରି (`cliproxy`) |     8317     | Anthropic CLI ପ୍ରମାଣୀକରଣ ପ୍ରବାହ ପାଇଁ ସ୍ଥାନୀୟ ପ୍ରକ୍ସି ଆଡାପ୍ଟର୍। OAuth ଟୋକନ୍ର ମିଆଦ ସମାପ୍ତ ହେଲେ ଫଲ୍ବ୍ୟାକ୍ ରାଉଟିଂ ପ୍ରଦାନ କରେ                                                                          |
| **Mux**         | `mux` (ହେଡ୍ଲେସ୍ `mux server`)      |     8322     | ସ୍ଥାନୀୟ ଏଜେଣ୍ଟ-ଅର୍କେଷ୍ଟ୍ରେସନ୍ ଡେମନ୍ (coder/mux)। କେବଳ ଜୀବନଚକ୍ର ପରିଚାଳିତ — ଏହା ଏକ ରାଉଟିଂ ଲକ୍ଷ୍ୟ ନୁହେଁ (କୌଣସି LLM ପ୍ରକ୍ସିଂ ନାହିଁ)।                                                                  |
| **Bifrost**     | `@maximhq/bifrost`                 |     8080     | Go AI-ଗେଟ୍ୱେ ରିଲେ ବ୍ୟାକଏଣ୍ଡ। ଚାଲୁଥିବାବେଳେ, ରିଲେ ରୁଟ୍ (`/v1/relay/`) ଦ୍ୱାରା ସ୍ୱୟଂଚାଳିତ ଭାବେ ଚୟନ କରାଯାଏ                                                                                             |
| **Dario**       | `@askalf/dario`                    |     3456     | Claude-ସବ୍ସ୍କ୍ରିପ୍ସନ୍ ପ୍ରକ୍ସି — Claude-Code-ଆକୃତିର ଟ୍ରାଫିକ୍ ପାଇଁ CLIProxyAPIର ବିକଳ୍ପ/ଫେଲ୍ଓଭର୍; ଇଞ୍ଜେକ୍ଟ କରାଯାଇଥିବା କୀ `DARIO_ADMIN_TOKEN` ହୋଇ ଏହାର `/admin/*` OAuth ନିୟନ୍ତ୍ରଣ ସ୍ତରକୁ ସୁରକ୍ଷିତ କରେ |
| **open-wa**     | `@open-wa/wa-automate`             |     8323     | WhatsApp Web ସ୍ୱୟଂଚାଳନ (Puppeteer ମାଧ୍ୟମରେ ହେଡ୍ଲେସ୍ Chromium)। କେବଳ ଜୀବନଚକ୍ର ପରିଚାଳିତ — ଏହା ଏକ ରାଉଟିଂ ଲକ୍ଷ୍ୟ ନୁହେଁ।                                                                               |

ସମସ୍ତ ଛଅଟି ସେବା ସମାନ ପର୍ଯ୍ୟବେକ୍ଷଣ ମଡେଲ୍ ଅନୁସରଣ କରେ:

- OmniRoute ସେଗୁଡ଼ିକୁ `DATA_DIR/services/{name}/` ଅଧୀନରେ ଇନ୍ଷ୍ଟଲ୍ କରେ (OmniRouteର ନିଜସ୍ୱ `package.json`ଠାରୁ ପୃଥକ)
- OmniRoute ସେଗୁଡ଼ିକୁ ଚାଇଲ୍ଡ ପ୍ରୋସେସ୍ ଭାବେ ଆରମ୍ଭ ଓ ନିରୀକ୍ଷଣ କରେ
- OmniRoute ଚାଇଲ୍ଡ ପ୍ରୋସେସ୍ର ପରିବେଶରେ ଏକ ଅସ୍ଥାୟୀ API କୀ ଇଞ୍ଜେକ୍ଟ କରେ ଏବଂ ଡାଉନ୍ଟାଇମ୍ ବିନା ତାହାକୁ ରୋଟେଟ୍ କରେ (ଯେଉଁଠାରେ ପ୍ରଯୁଜ୍ୟ)
- ସମସ୍ତ ପରିଚାଳନା ରୁଟ୍ (`/api/services/*`) **LOCAL_ONLY** — କେବଳ ଲୁପ୍ବ୍ୟାକ୍ରୁ ଆକ୍ସେସ୍ଯୋଗ୍ୟ (କଠୋର ନିୟମ #17)

## 3. ଜୀବନଚକ୍ର ଅବସ୍ଥା ଯନ୍ତ୍ର

```
                    install()
  ┌─────────────┐ ──────────► ┌─────────────┐
  │ not_installed│             │   stopped   │◄──────────────────┐
  └─────────────┘             └──────┬──────┘                   │
                                     │ start()                   │
                                     ▼                           │ stop()
                               ┌──────────┐                      │
                               │ starting │                      │
                               └────┬─────┘                     │
             ସ୍ୱାସ୍ଥ୍ୟ ଯାଞ୍ଚ ସଫଳ   │         କ୍ରାଶ୍ / SIGTERM    │
                               ┌────▼─────┐  (5s ମଧ୍ୟରେ ପ୍ରସ୍ଥାନ) │
                               │ running  │──── କ୍ରାଶ୍ ─────────►┤
                               └────┬─────┘                   ┌─▼────┐
                             stop() │                          │error │
                                    ▼                          └──────┘
                               ┌──────────┐
                               │ stopping │
                               └──────────┘
```

ଅବସ୍ଥାଗୁଡ଼ିକ `version_manager` DB ଟେବୁଲ୍ରେ (`status` ସ୍ତମ୍ଭ) ସଂରକ୍ଷିତ ହୁଏ ଏବଂ
`ServiceSupervisor`-ର ଇନ୍-ମେମୋରି ଅବସ୍ଥାରେ ପ୍ରତିଫଳିତ ହୁଏ। ଚାଲୁଥିବା ଏକ ପ୍ରକ୍ରିୟା ପାଇଁ
ଇନ୍-ମେମୋରି ଅବସ୍ଥା ପ୍ରାମାଣିକ; ବୁଟ୍ ସମୟରେ DB ଅବସ୍ଥା ହେଉଛି ସ୍ଥାୟୀ ଫଲ୍ବ୍ୟାକ୍।

### ଅବସ୍ଥା ପରିବର୍ତ୍ତନଗୁଡ଼ିକ

| ଏଠାରୁ           | ଘଟଣା                                            | ଏଠାକୁ                  |
| --------------- | ----------------------------------------------- | ---------------------- |
| `not_installed` | `install()` ସଫଳ ହୁଏ                             | `stopped`              |
| `stopped`       | `start()` କଲ୍ କରାଯାଏ                            | `starting`             |
| `starting`      | ସ୍ୱାସ୍ଥ୍ୟ ଯାଞ୍ଚ 200 ଫେରାଏ                       | `running`              |

| `running`       | ପ୍ରକ୍ରିୟା ଅପ୍ରତ୍ୟାଶିତ ଭାବେ ପ୍ରସ୍ଥାନ କରେ (> 5 s) | `error`                |

### ଅପରେସନ୍ ଲକ୍

`ServiceSupervisor` ଏକ ଅସିଙ୍କ୍ ଅପରେସନ୍ ଲକ୍
(`withLock()`) ମାଧ୍ୟମରେ ଜୀବନଚକ୍ର ଅପରେସନ୍ଗୁଡ଼ିକୁ କ୍ରମିକ କରେ। ସମାନ ସୁପରଭାଇଜର୍ରେ ଏକାସାଙ୍ଗରେ
ହୋଇଥିବା `start()` କଲ୍ଗୁଡ଼ିକ ଠିକ୍ ଗୋଟିଏ ସ୍ପନ୍ ସୃଷ୍ଟି କରେ; ଦ୍ୱିତୀୟ କଲର୍ ଅପେକ୍ଷା କରି
ବିଦ୍ୟମାନ ସ୍ଥିତି ଫେରାଏ। ଏହା, ଉଦାହରଣ ସ୍ୱରୂପ, ଅଟୋ-ଷ୍ଟାର୍ଟ ଏବଂ ଏକ UI ବଟନ୍
ଏକାସାଙ୍ଗରେ ସକ୍ରିୟ ହେଲେ ରେସ୍ କଣ୍ଡିସନ୍କୁ ପ୍ରତିରୋଧ କରେ।

## 4. API ସନ୍ଦର୍ଭ

`/api/services/` ଅଧୀନରେ ଥିବା ସମସ୍ତ ରୁଟ୍ **LOCAL_ONLY** (କେବଳ ଲୁପ୍ବ୍ୟାକ୍, କଠୋର ନିୟମ #17)।
ପ୍ରମାଣୀକରଣ ଟୋକେନ୍ ନିର୍ବିଶେଷରେ ଅଣ-ଲୁପ୍ବ୍ୟାକ୍ ଅନୁରୋଧଗୁଡ଼ିକ `403 LOCAL_ONLY` ପାଆନ୍ତି।

### 4.1 9Router ଏଣ୍ଡପଏଣ୍ଟଗୁଡ଼ିକ (11ଟି ରୁଟ୍)

#### `POST /api/services/9router/install`

npmରୁ 9Router ଇନ୍ଷ୍ଟଲ୍ କରେ। ଏହାର ନିଜସ୍ୱ `package.json` ଏବଂ `node_modules/` ସହିତ
`DATA_DIR/services/9router/` ସୃଷ୍ଟି କରେ। OmniRouteର ନିଜସ୍ୱ ନିର୍ଭରତାଗୁଡ଼ିକ ସହିତ ଦ୍ୱନ୍ଦ୍ୱ ସୃଷ୍ଟି କରେ ନାହିଁ।

**ଅନୁରୋଧ ବଡି** (ସମସ୍ତ ଇଚ୍ଛାଧୀନ):

```json
{ "version": "latest" }
```

| ଫିଲ୍ଡ     | ପ୍ରକାର   | ଡିଫଲ୍ଟ     | ବର୍ଣ୍ଣନା                                               |
| --------- | -------- | ---------- | ------------------------------------------------------ |
| `version` | `string` | `"latest"` | ଇନ୍ଷ୍ଟଲ୍ କରିବାକୁ ଥିବା npm ସଂସ୍କରଣ ଟ୍ୟାଗ୍ କିମ୍ବା semver |

**ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକ:**

| ସ୍ଥିତି | ବର୍ଣ୍ଣନା                                                  |
| ------ | --------------------------------------------------------- |
| `200`  | `{ ok: true, installedVersion: "x.y.z", path: "..." }`    |
| `400`  | ଅବୈଧ ଅନୁରୋଧ ବଡି (Zod ବୈଧତା ଯାଞ୍ଚ ବିଫଳ)                    |
| `409`  | ଇନ୍ଷ୍ଟଲେସନ୍ ପୂର୍ବରୁ ଚାଲିଛି (ଲକ୍ ଧାରଣ କରାଯାଇଛି)            |
| `500`  | npm install ବିଫଳ — ସହଜବୋଧ୍ୟ ତ୍ରୁଟି ପାଇଁ `message` ଦେଖନ୍ତୁ |

**ଟିପ୍ପଣୀ:** `execFile('npm', [...])` ବ୍ୟବହାର କରେ — କୌଣସି shell ନାହିଁ, କୌଣସି interpolation ନାହିଁ (କଠୋର ନିୟମ #13)।
EACCES ତ୍ରୁଟିଗୁଡ଼ିକୁ ସହଜବୋଧ୍ୟ ବାର୍ତ୍ତା ଭାବେ ଦର୍ଶାଯାଏ।

#### `POST /api/services/9router/start`

9Router ଆରମ୍ଭ କରେ। ପୂର୍ବରୁ ପଞ୍ଜୀକୃତ ହୋଇନଥିଲେ ଏକ supervisor ପଞ୍ଜୀକୃତ କରେ, ତା’ପରେ
`supervisor.start()` କଲ୍ କରେ। ପୂର୍ବରୁ ଚାଲୁଥିଲେ ଏହା idempotent ଅଟେ।

**ଅନୁରୋଧ ବଡି:** କିଛି ନାହିଁ

**ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକ:**

| ସ୍ଥିତି | ବର୍ଣ୍ଣନା                                              |
| ------ | ----------------------------------------------------- |
| `200`  | `ServiceStatus` ଅବଜେକ୍ଟ (ନିମ୍ନରେ ଥିବା schema ଦେଖନ୍ତୁ) |
| `409`  | 9Router ଇନ୍ଷ୍ଟଲ୍ ହୋଇନାହିଁ (`status: "not_installed"`) |
| `503`  | ଆରମ୍ଭ ବିଫଳ (ପ୍ରକ୍ରିୟା ତ୍ରୁଟି — `lastError` ଦେଖନ୍ତୁ)   |

**ServiceStatus schema:**

```json
{
  "tool": "9router",
  "state": "running",
  "pid": 12345,
  "port": 20130,
  "health": "healthy",
  "startedAt": "2026-05-25T10:00:00.000Z",
  "lastError": null
}
```

#### `POST /api/services/9router/stop`

9Routerକୁ ସୁରୁଚିପୂର୍ଣ୍ଣ ଭାବେ ବନ୍ଦ କରେ। SIGTERM ପଠାଏ, 15 s ଅପେକ୍ଷା କରେ, ଏବଂ ତଥାପି ସକ୍ରିୟ ଥିଲେ SIGKILL ପଠାଏ।
ପୂର୍ବରୁ ବନ୍ଦ ଥିଲେ ଏହା idempotent ଅଟେ।

**ଅନୁରୋଧ ବଡି:** କିଛି ନାହିଁ

**ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକ:**

| ସ୍ଥିତି | ବର୍ଣ୍ଣନା                              |
| ------ | ------------------------------------- |
| `200`  | `ServiceStatus` (state: "stopped")    |
| `503`  | ବନ୍ଦ କରିବା ଅପ୍ରତ୍ୟାଶିତ ଭାବେ ବିଫଳ ହେଲା |

#### `POST /api/services/9router/restart`

ଅପରେସନ୍ ଲକ୍ ଅଧୀନରେ `stop()` ଏବଂ ତା’ପରେ `start()` କରିବା ସହିତ ସମତୁଲ୍ୟ।

**ଅନୁରୋଧ ବଡି:** କିଛି ନାହିଁ

**ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକ:** `start` ସହିତ ସମାନ (ଅନ୍ତିମ `ServiceStatus` ଫେରାଏ)।

#### `POST /api/services/9router/update`

9Routerକୁ ଏକ ନୂତନ npm ସଂସ୍କରଣକୁ ଅପଡେଟ୍ କରେ। ସେବାଟି ଚାଲୁଥିଲେ, ପ୍ରଥମେ ଏହାକୁ ବନ୍ଦ
କରାଯାଏ, npm install ଚଲାଯାଏ (ନୂତନ ସଂସ୍କରଣକୁ ସେହି ସ୍ଥାନରେ ଇନ୍ଷ୍ଟଲ୍ କରି), ଏବଂ ତା’ପରେ
ସେବାଟିକୁ ପୁନଃଆରମ୍ଭ କରାଯାଏ।

**ଅନୁରୋଧ ବଡି** (ସମସ୍ତ ଇଚ୍ଛାଧୀନ):

```json
{ "version": "latest" }
```

**ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକ:**

| ------ | --------------------------------------------------------------- |
| `200`  | `{ ok: true, previousVersion: "...", installedVersion: "..." }` |
| `400`  | ଅବୈଧ ବଡି                                                        |
| `500`  | npm update ବିଫଳ                                                 |

#### `POST /api/services/9router/rotate-key`

9Router ପାଇଁ ଏକ ନୂତନ API କୀ ସୃଷ୍ଟି କରେ, ସଂରକ୍ଷଣ ସମୟରେ ଏହାକୁ ଏନ୍କ୍ରିପ୍ଟ କରେ, ଏବଂ ସେବାଟି
ଚାଲୁଥିଲେ ଏହାକୁ ପୁନଃଆରମ୍ଭ କରେ, ଯାହାଦ୍ୱାରା ଏହା ନିଜ ପରିବେଶରୁ ନୂତନ କୀଟିକୁ ଗ୍ରହଣ କରେ। ପୁରୁଣା କୀଟିକୁ
ତୁରନ୍ତ ଅବୈଧ କରାଯାଏ।

**ଅନୁରୋଧ ବଡି:** କିଛି ନାହିଁ

**ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକ:**

| ସ୍ଥିତି | ବର୍ଣ୍ଣନା                                   |
| ------ | ------------------------------------------ |
| `200`  | `{ keyRotated: true, restarted: boolean }` |
| `500`  | କୀ ପରିବର୍ତ୍ତନ ବିଫଳ ହେଲା                    |

**ସୁରକ୍ଷା:** ନୂତନ କୀଟିକୁ ପ୍ରତିକ୍ରିୟାରେ କେବେବି ଫେରାଯାଏ ନାହିଁ (ପ୍ରମାଣପତ୍ର ଲିକ୍ ନାହିଁ)।

### 4.6 open-wa ଏଣ୍ଡପଏଣ୍ଟଗୁଡ଼ିକ (7ଟି ରୁଟ୍)

open-wa (`@open-wa/wa-automate`) WhatsApp Webକୁ ସ୍ୱୟଂଚାଳିତ କରିବା ପାଇଁ ଏକ ହେଡ୍ଲେସ୍

ବ୍ୟବହାର କରେ (ଏପର୍ଯ୍ୟନ୍ତ କୌଣସି `rotate-key` ରୁଟ୍ ନାହିଁ)। ଏହା କେବଳ ଲାଇଫସାଇକେଲ୍-ପରିଚାଳିତ

Bearer`ରୁ ନୁହେଁ); `/api-docs*`କୁ ଯାଞ୍ଚରୁ ସ୍ପଷ୍ଟ ଭାବରେ ବାଦ ଦିଆଯାଇଛି

କୌଣସି ପ୍ରମାଣୀକରଣ ହେଡର୍ ଆବଶ୍ୟକ ନାହିଁ।

ନମ୍ବରଟି WhatsAppର ନିଜସ୍ୱ ସ୍ୱୟଂଚାଳନ ଚିହ୍ନଟକରଣ ଦ୍ୱାରା ବ୍ୟାନ୍ ହେବାର ବିପଦ ବହନ କରେ।
ପ୍ରଥମ ଆରମ୍ଭରେ, ପେୟାରିଂ QR କୋଡ୍ stdoutରେ ପ୍ରିଣ୍ଟ ହୁଏ ଏବଂ
ବିଦ୍ୟମାନ ଲଗ୍ ପ୍ୟାନେଲ୍/SSE ଷ୍ଟ୍ରିମ୍ ମାଧ୍ୟମରେ ଦେଖାଯାଏ — ଏହି ଇଣ୍ଟିଗ୍ରେସନ୍ରେ
ଏପର୍ଯ୍ୟନ୍ତ କୌଣସି ଉତ୍ସର୍ଗୀକୃତ QR-ଇମେଜ୍ ଏଣ୍ଡପଏଣ୍ଟ ନାହିଁ।

### 4.7 ରିଭର୍ସ ପ୍ରକ୍ସି (9Router ଡ୍ୟାସ୍ବୋର୍ଡ ଏମ୍ବେଡ୍)

ଡ୍ୟାସ୍ବୋର୍ଡଟି ଏଠାରେ ଥିବା ଏକ ଆଭ୍ୟନ୍ତରୀଣ ରିଭର୍ସ
ପ୍ରକ୍ସି ମାଧ୍ୟମରେ iframe ଭିତରେ 9Router ୱେବ୍ UIକୁ ଏମ୍ବେଡ୍ କରେ:

```
GET|POST|... /dashboard/providers/services/9router/embed/[...path]
```

ଏହି ପ୍ରକ୍ସି:

- ଅନୁରୋଧକୁ `http://127.0.0.1:{port}/{path}`କୁ ଫରୱାର୍ଡ କରେ (କେବଳ ଲୁପ୍ବ୍ୟାକ୍)
- ଆସୁଥିବା `cookie` ଏବଂ `authorization` ହେଡର୍ଗୁଡ଼ିକୁ ହଟାଏ (OmniRoute ସେସନ୍ର କୌଣସି ଲିକେଜ୍ ନାହିଁ)
- 9Router ପ୍ରମାଣୀକରଣ ପାଇଁ `Authorization: Bearer {apiKey}` ଇଞ୍ଜେକ୍ଟ କରେ
- ପ୍ରତିକ୍ରିୟାରୁ `set-cookie`, `content-security-policy`, `x-frame-options`, `cross-origin-*` ହଟାଏ
- `<base href>` ଇଞ୍ଜେକ୍ଟ କରିବା ଏବଂ ଆବ୍ସୋଲ୍ୟୁଟ୍ ପଥଗୁଡ଼ିକୁ ସ୍ୱାଭାବିକ କରିବା ପାଇଁ HTML ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକୁ ପୁନଃଲିଖନ କରେ (`/foo` → `/dashboard/.../embed/foo`)

ଏମ୍ବେଡ୍ ହୋଇଥିବା ଡ୍ୟାସ୍ବୋର୍ଡ ପାଇଁ WebSocket ଅପଗ୍ରେଡ୍ଗୁଡ଼ିକୁ ଏକ
ଉତ୍ସର୍ଗୀକୃତ ପୋର୍ଟରେ ଥିବା ସହାୟକ ସର୍ଭର୍ ଦ୍ୱାରା ପରିଚାଳନା କରାଯାଏ (`src/lib/services/embedWsProxy.ts` ଦେଖନ୍ତୁ)।

**ସୁରକ୍ଷା:** ଏମ୍ବେଡ୍ ପ୍ରକ୍ସି ରୁଟ୍ଗୁଡ଼ିକୁ `LOCAL_ONLY_API_PREFIXES`
ଅଧୀନରେ ବର୍ଗୀକୃତ କରାଯାଇଛି ଏବଂ କେବଳ ଲୁପ୍ବ୍ୟାକ୍ରୁ ଆକ୍ସେସ୍ କରାଯାଇପାରେ। Cloudflare/Ngrok ଟନେଲ୍ ମାଧ୍ୟମରେ
JWT ପାଇଥିବା ଜଣେ ଆକ୍ରମଣକାରୀ ଏମ୍ବେଡ୍ ହୋଇଥିବା ସେବାଗୁଡ଼ିକ ଭିତରକୁ ପ୍ରକ୍ସି କରିପାରିବେ ନାହିଁ।

## 5. ସୁରକ୍ଷା

### LOCAL_ONLY ପ୍ରବର୍ତ୍ତନ (କଠୋର ନିୟମ #17)

`/api/services/` ଏବଂ `/dashboard/providers/services/*/embed/` ଅଧୀନରେ ଥିବା ସମସ୍ତ ରୁଟ୍କୁ
`src/server/authz/routeGuard.ts` ମଧ୍ୟରେ LOCAL_ONLY ଭାବେ ବର୍ଗୀକୃତ କରାଯାଇଛି। ଯେକୌଣସି ପ୍ରମାଣୀକରଣ ଶାଖା ପୂର୍ବରୁ
ଲୁପ୍ବ୍ୟାକ୍ ଯାଞ୍ଚ ବିନା ସର୍ତ୍ତରେ ଚାଲେ:

```
ଅନୁରୋଧ ପହଞ୍ଚେ
  → isLocalOnlyPath(path)?
      → ନନ୍-ଲୁପ୍ବ୍ୟାକ୍ → 403 LOCAL_ONLY (ସର୍ବଦା, ପ୍ରମାଣୀକରଣ ଯାଞ୍ଚ ପୂର୍ବରୁ)
      → ଲୁପ୍ବ୍ୟାକ୍     → ସାଧାରଣ ପ୍ରମାଣୀକରଣକୁ ଅଗ୍ରସର ହୁଏ
```

ଏହା ଏକ ଲିକ୍ ହୋଇଥିବା JWTକୁ (ଉଦାହରଣ ସ୍ୱରୂପ, ଏକ ଟନେଲ୍ ମାଧ୍ୟମରେ) `npm install` କିମ୍ବା
ପ୍ରକ୍ରିୟା ସ୍ପନିଂ ଟ୍ରିଗର୍ କରିବାରୁ ରୋକେ। ସମ୍ପୂର୍ଣ୍ଣ ଟିୟର୍
ମ୍ୟାଟ୍ରିକ୍ସ ପାଇଁ `docs/security/ROUTE_GUARD_TIERS.md` ଦେଖନ୍ତୁ।

### API କି ଇଞ୍ଜେକ୍ସନ୍

9Router ଏବଂ Muxକୁ ସେମାନଙ୍କ ନିଜସ୍ୱ HTTP ଏଣ୍ଡପଏଣ୍ଟଗୁଡ଼ିକ ପାଇଁ ଏକ API କି/ବିଅରର୍ ଟୋକେନ୍ ଆବଶ୍ୟକ।
OmniRoute:

1. ଏକ ସେବା-ନିର୍ଦ୍ଦିଷ୍ଟ ଉପସର୍ଗ ସହିତ `crypto.randomBytes(32).toString("base64url")` ମାଧ୍ୟମରେ ଏକ କି
   ସୃଷ୍ଟି କରେ (9Router ପାଇଁ `nr_`, Mux ପାଇଁ `mx_`)।
2. AES-256-GCM ବ୍ୟବହାର କରି ସ୍ଥିରାବସ୍ଥାରେ ଏହାକୁ ଏନ୍କ୍ରିପ୍ଟ କରେ (ପ୍ରଦାତା କ୍ରେଡେନ୍ସିଆଲ୍ ପାଇଁ ବ୍ୟବହୃତ ସମାନ ସାଇଫର୍)।
3. ସ୍ପନ୍ ସମୟରେ ଏହାକୁ ଡିକ୍ରିପ୍ଟ କରି ଏକ ପରିବେଶ ଚର ଭାବେ ଇଞ୍ଜେକ୍ଟ କରେ —
   9Router ପାଇଁ `NINEROUTER_API_KEY`, Mux ପାଇଁ `MUX_SERVER_AUTH_TOKEN` (କେବେ ମଧ୍ୟ ଏକ CLI
   ଫ୍ଲାଗ୍ ଭାବେ ନୁହେଁ, ତେଣୁ ଟୋକେନ୍ଟି କେବେ ମଧ୍ୟ `ps`/ପ୍ରକ୍ରିୟା ତାଲିକାରେ ଦେଖାଯାଏ ନାହିଁ)।
4. କୌଣସି HTTP ପ୍ରତିକ୍ରିୟାରେ କେବେ ମଧ୍ୟ ପ୍ଲେନ୍ଟେକ୍ସ୍ଟ କି ଫେରସ୍ତ କରେ ନାହିଁ।

CLIProxyAPI ସ୍ପନ୍ ସମୟରେ ଇଞ୍ଜେକ୍ଟ କରାଯାଇଥିବା ଏକ ଉତ୍ସର୍ଗୀକୃତ ଡାଟା-ପ୍ଲେନ୍ କି ପାଏ
(`needsApiKey: true` — ଆଡାପ୍ଟର୍ ବିପକ୍ଷରେ ମଡେଲ୍ ସିଙ୍କ୍ ପାଇଁ ବ୍ୟବହୃତ)।

### SSRF ପ୍ରତିରକ୍ଷା

ରିଭର୍ସ HTTP ପ୍ରକ୍ସି (`/dashboard/.../embed/[...path]`) କେବଳ
`http://127.0.0.1:{port}`କୁ ଫର୍ୱାର୍ଡ କରିବା ପାଇଁ ହାର୍ଡକୋଡ୍ କରାଯାଇଛି। ଏହା କେବେ ମଧ୍ୟ ନନ୍-ଲୁପ୍ବ୍ୟାକ୍
ଗନ୍ତବ୍ୟସ୍ଥଳକୁ ରିଡାଇରେକ୍ଟ ଅନୁସରଣ କରେ ନାହିଁ। ଲୁପ୍ବ୍ୟାକ୍ ପରିସର ବାହାରେ ରିଜଲ୍ଭ ହେଉଥିବା ଯେକୌଣସି ଅପ୍ଷ୍ଟ୍ରିମ୍ URLକୁ
ପ୍ରତ୍ୟାଖ୍ୟାନ କରିବା ପାଇଁ `ssrf-req-filter` ଲାଇବ୍ରେରୀ ବ୍ୟବହାର କରାଯାଏ।

### ଶେଲ୍ ସୁରକ୍ଷା (କଠୋର ନିୟମ #13)

`npm install`କୁ `execFile('npm', ['install', pkg, '--prefix', dir])` ମାଧ୍ୟମରେ ଆହ୍ୱାନ କରାଯାଏ —
କୌଣସି ଟେମ୍ପ୍ଲେଟ୍ ଲିଟେରାଲ୍ ନାହିଁ, କୌଣସି ଶେଲ୍ ନାହିଁ, କମାଣ୍ଡ
ଷ୍ଟ୍ରିଙ୍ଗ୍ରେ ବାହ୍ୟ ପଥଗୁଡ଼ିକର କୌଣସି ଇଣ୍ଟର୍ପୋଲେସନ୍ ନାହିଁ। ରନ୍ଟାଇମ୍ ମୂଲ୍ୟଗୁଡ଼ିକ (ପୋର୍ଟ, API କି) ଚାଇଲ୍ଡର `env` ଅବଜେକ୍ଟ ମାଧ୍ୟମରେ ପାସ୍ କରାଯାଏ।

### ତ୍ରୁଟି ସାନିଟାଇଜେସନ୍ (କଠୋର ନିୟମ #12)

`/api/services/*`ରୁ ଆସୁଥିବା ସମସ୍ତ ତ୍ରୁଟି ପ୍ରତିକ୍ରିୟା `buildErrorBody()` କିମ୍ବା
`sanitizeErrorMessage()` ମାଧ୍ୟମରେ ଯାଏ। କାଞ୍ଚା `err.stack` ଏବଂ `err.message`କୁ କେବେ ମଧ୍ୟ
କଲର୍କୁ ଅବିକଳ ଭାବେ ଫେରସ୍ତ କରାଯାଏ ନାହିଁ।

## 6. ଏକ ନୂତନ ଏମ୍ବେଡେଡ୍ ସେବା ଯୋଡ଼ିବା

ଏହି 8ଟି ପଦକ୍ଷେପ ଅନୁସରଣ କରନ୍ତୁ। ପ୍ରାମାଣିକ ସନ୍ଦର୍ଭ ଭାବେ `src/lib/services/installers/`
ଏବଂ `src/app/api/services/`ରେ ଥିବା ବିଦ୍ୟମାନ ଇମ୍ପ୍ଲିମେଣ୍ଟେସନ୍ଗୁଡ଼ିକ ପଢ଼ନ୍ତୁ।

### ପଦକ୍ଷେପ 1 — ଇନ୍ଷ୍ଟଲର୍ ସୃଷ୍ଟି କରନ୍ତୁ

`ninerouter.ts` ଅନୁସାରେ ମଡେଲ୍ କରାଯାଇଥିବା `src/lib/services/installers/{name}.ts` ସୃଷ୍ଟି କରନ୍ତୁ:

```typescript
export const NAME_PACKAGE = "your-npm-package";
export const NAME_DEFAULT_PORT = 20132; // ଏକ ଖାଲି ପୋର୍ଟ ବାଛନ୍ତୁ

export async function install(version = "latest"): Promise<InstallResult> { ... }
export async function update(version = "latest"): Promise<InstallResult> { ... }
export async function uninstall(): Promise<void> { ... }
export function resolveSpawnArgs(apiKey: string, port: number): SpawnArgs { ... }
export async function getInstalledVersion(): Promise<string | null> { ... }
export async function getLatestVersion(): Promise<string | null> { ... }
```

`installers/utils.ts`ରୁ `runNpm(['install', NAME_PACKAGE, '--prefix', dir])` ବ୍ୟବହାର କରନ୍ତୁ
— କେବେ ମଧ୍ୟ `execSync` କିମ୍ବା ଶେଲ୍ ଇଣ୍ଟର୍ପୋଲେସନ୍ ବ୍ୟବହାର କରନ୍ତୁ ନାହିଁ।

### ପଦକ୍ଷେପ 2 — ବୁଟ୍ଷ୍ଟ୍ରାପ୍ରେ ପଞ୍ଜୀକରଣ କରନ୍ତୁ

`src/lib/services/bootstrap.ts`ରେ ଥିବା `SERVICES` ଆରେରେ ଏକ `ServiceEntry` ଯୋଡ଼ନ୍ତୁ:

```typescript
{
  tool: "myservice",
  port: NAME_DEFAULT_PORT,
  healthPath: "/health",
  healthIntervalMs: 5_000,
  stopTimeoutMs: 15_000,
  logsBufferBytes: 5_242_880,
  needsApiKey: true, // API କି ଆବଶ୍ୟକ ନଥିଲେ false
}
```

`cfg.tool === "myservice"`କୁ ପରିଚାଳନା କରିବା ପାଇଁ `buildSpawnArgsFactory()`କୁ ବିସ୍ତାର କରନ୍ତୁ।

#### ପ୍ଲଗ୍ଯୋଗ୍ୟ ପ୍ରଦାତା-ପ୍ଲଗିନ୍ ଚୁକ୍ତି (ପର୍ଯ୍ୟାୟ 1, #7333)

`src/lib/services/providerPlugins/` ଏକ `ServiceProviderPlugin` ଚୁକ୍ତି ପ୍ରବର୍ତ୍ତନ କରେ, ଯାହା
ଏକ ବ୍ୟାକ୍ଏଣ୍ଡର `bootstrap.ts` `ServiceEntry` ଫିଲ୍ଡଗୁଡ଼ିକ ଏବଂ `serviceBackends.ts`
ମାନିଫେଷ୍ଟ-ଟେମ୍ପ୍ଲେଟ୍ ଫିଲ୍ଡଗୁଡ଼ିକୁ ଗୋଟିଏ ଅବଜେକ୍ଟରେ ପ୍ୟାକେଜ୍ କରେ, ଯାହାଦ୍ୱାରା ସମାନ ବ୍ୟାକ୍ଏଣ୍ଡର ଗଠନକୁ
ଦୁଇଟି ଅସମ୍ପର୍କିତ ଫାଇଲ୍ରେ ପୃଥକ ଭାବେ ପ୍ରକାଶ କରିବାକୁ ପଡ଼େ ନାହିଁ। ଏହା ଲେଖାଯିବା ସମୟରେ **କେବଳ `9router`କୁ
ମାଇଗ୍ରେଟ୍ କରାଯାଇଛି** — `bootstrap.ts` ଏହାର `SERVICES[]` ଏଣ୍ଟ୍ରିକୁ
`getServiceProviderPlugin("9router")` (`src/lib/services/providerPlugins/registry.ts`)ରୁ ନିଷ୍ପନ୍ନ କରେ,
ଏବଂ ପ୍ଲଗିନ୍ଟି କେବେ ଅନୁପସ୍ଥିତ ହେଲେ ଏକ ଷ୍ଟାର୍ଟଅପ୍ ତ୍ରୁଟି ଥ୍ରୋ କରେ। `cliproxy`, `mux`, ଏବଂ `bifrost`
ପୂର୍ବରୁ ଥିବା ଇନ୍ଲାଇନ୍ `SERVICES[]` ଲିଟେରାଲ୍ଗୁଡ଼ିକରେ ଅପରିବର୍ତ୍ତିତ ରହିଛନ୍ତି।

`open-sse/config/providerPluginManifest.ts` ମଧ୍ୟ ଏକ ଯୋଗାତ୍ମକ
`createServiceBackendManifestEntry(pluginId, template)` ହେଲ୍ପର୍ ପାଇଛି, ଯାହା ଏକ `SERVICE_BACKEND_MANIFEST_TEMPLATE` ଏଣ୍ଟ୍ରିରୁ ଏକ ସୁଗଠିତ
`ProviderPluginManifestEntry` ତିଆରି କରେ — ଏହାକୁ
**ଏପର୍ଯ୍ୟନ୍ତ କୌଣସି ସକ୍ରିୟ ଅନୁରୋଧ ପଥ ସହିତ** ଯୋଡ଼ାଯାଇ ନାହିଁ (`generateProviderPluginManifestFromRegistry()`
କିମ୍ବା `/v1/providers/[provider]/models` ମଧ୍ୟରୁ କୌଣସିଟି ସହିତ ନୁହେଁ); ଦ୍ୱିତୀୟ ବ୍ୟାକ୍ଏଣ୍ଡ ପାଇଁ ଚୁକ୍ତିଟି ପ୍ରମାଣିତ ହେବା ପରେ ତାହା ଏକ ଫଲୋ-ଅପ୍ ଭାବେ ରହିବ।

ଇସ୍ୟୁ #7333 ଅଧୀନରେ ଟ୍ରାକ୍ କରାଯାଇଥିବା ଫଲୋ-ଅପ୍ PRଗୁଡ଼ିକ ପାଇଁ ସ୍ଥଗିତ: ସମାନ
ରେଜିଷ୍ଟ୍ରି ମାଧ୍ୟମରେ `cliproxyapi`କୁ ମାଇଗ୍ରେଟ୍ କରିବା, `mux`/`bifrost`କୁ `ServiceBackendPluginId` ୟୁନିଅନ୍ରେ ସାଧାରଣୀକରଣ କରିବା,
ଏକ୍ଜିକ୍ୟୁଟର୍-ରାଉଟିଂ ସ୍ୱତନ୍ତ୍ର ପରିଚାଳନାକୁ (`open-sse/executors/index.ts`,
`open-sse/handlers/chatCore/executorProxy.ts`) ପ୍ଲଗିନ୍ ଚୁକ୍ତିରେ ସମ୍ମିଳିତ କରିବା, ଏବଂ
`createServiceBackendManifestEntry()`କୁ ଏକ ସକ୍ରିୟ ମାନିଫେଷ୍ଟ/ମଡେଲ୍ କୋଡ୍ ପଥ ସହିତ ଯୋଡ଼ିବା।

### ପଦକ୍ଷେପ 3 — ମାଇଗ୍ରେସନ୍ ଏବଂ DB ସିଡ୍ ଯୋଡ଼ନ୍ତୁ

`src/lib/db/migrations/`ରେ ଏକ ମାଇଗ୍ରେସନ୍ ମାଧ୍ୟମରେ ସେବାଟିର `version_manager`ରେ ଗୋଟିଏ ଧାଡ଼ି ଥିବା ସୁନିଶ୍ଚିତ କରନ୍ତୁ।
ଧାଡ଼ିଟି ଏପରି ହେବା ଉଚିତ:

```sql
INSERT OR IGNORE INTO version_manager (tool, status, auto_start, provider_expose)
VALUES ('myservice', 'not_installed', 0, 0);
```

### ପଦକ୍ଷେପ 4 — 7ଟି API ଏଣ୍ଡପଏଣ୍ଟ ସୃଷ୍ଟି କରନ୍ତୁ

`src/app/api/services/{name}/` ଅଧୀନରେ:

```
_lib.ts            getOrInitSupervisor() ହେଲ୍ପର୍
install/route.ts   POST — installer.install()କୁ କଲ୍ କରେ
start/route.ts     POST — supervisor.start()କୁ କଲ୍ କରେ
stop/route.ts      POST — supervisor.stop()କୁ କଲ୍ କରେ
restart/route.ts   POST — supervisor.restart()କୁ କଲ୍ କରେ
update/route.ts    POST — installer.update()କୁ କଲ୍ କରେ
status/route.ts    GET  — ଲାଇଭ୍ + DB ସ୍ଥିତିକୁ ମିଶ୍ରଣ କରେ
auto-start/route.ts POST — auto_start ଫ୍ଲାଗ୍କୁ ଟଗଲ୍ କରେ
```

ସାମାନ୍ୟ `GET /api/services/[name]/logs` ରୁଟ୍ଟି ପୂର୍ବରୁ ସଂଯୋଜିତ ହୋଇଛି — ସେଠାରେ କୌଣସି ପରିବର୍ତ୍ତନ
ଆବଶ୍ୟକ ନାହିଁ।

ସମସ୍ତ ତ୍ରୁଟି ପ୍ରତିକ୍ରିୟାକୁ `createErrorResponse()` / `buildErrorBody()` ମାଧ୍ୟମରେ ପରିଚାଳନା କରନ୍ତୁ।

### ପଦକ୍ଷେପ 5 — LOCAL_ONLY_API_PREFIXES ରେ ଯୋଡ଼ନ୍ତୁ

`src/server/authz/routeGuard.ts` ରେ `/api/services/` ପୂର୍ବରୁ ତାଲିକାଭୁକ୍ତ ଅଛି କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ।
ଯଦି ଆପଣ ଏକ ନୂଆ ପ୍ରିଫିକ୍ସ ଯୋଡ଼ନ୍ତି (ଯଥା, `/api/tools/`), ତେବେ ଏହାକୁ
`LOCAL_ONLY_API_PREFIXES` ଏବଂ, ଯଦି ଏହା ପ୍ରୋସେସ୍ ସୃଷ୍ଟି କରେ, `SPAWN_CAPABLE_PREFIXES` ଉଭୟରେ ଯୋଡ଼ନ୍ତୁ।
`tests/unit/authz/routeGuard.test.ts` ରେ ଏକ ପରୀକ୍ଷା ଯୋଡ଼ନ୍ତୁ।

### ପଦକ୍ଷେପ 6 — UI ଟ୍ୟାବ୍ ଯୋଡ଼ନ୍ତୁ

`src/app/(dashboard)/dashboard/providers/services/tabs/{Name}ServiceTab.tsx` ସୃଷ୍ଟି କରନ୍ତୁ।
ସାମାନ୍ୟ କମ୍ପୋନେଣ୍ଟଗୁଡ଼ିକୁ ପୁନଃବ୍ୟବହାର କରନ୍ତୁ:

- `ServiceStatusCard` — ଲାଇଭ୍ ଅବସ୍ଥା + ସ୍ୱାସ୍ଥ୍ୟ ବ୍ୟାଜ୍
- `ServiceLifecycleButtons` — ଆରମ୍ଭ / ବନ୍ଦ / ପୁନଃଆରମ୍ଭ / ଅଦ୍ୟତନ
- `ServiceLogsPanel` — SSE ଲଗ୍ର ଶେଷାଂଶ (`/api/services/{name}/logs` ସହିତ ସଂଯୋଗ କରେ)
- `ApiKeyCard` — କୀ ପ୍ରଦର୍ଶନ + ପରିବର୍ତ୍ତନ (ଯଦି `needsApiKey: true`)

`ServicesPageShell.tsx` ରେ ଟ୍ୟାବ୍ଟିକୁ ପଞ୍ଜିକୃତ କରନ୍ତୁ।

### ପଦକ୍ଷେପ 7 — ପ୍ରଦାନକାରୀ ଏଣ୍ଟ୍ରି ଯୋଡ଼ନ୍ତୁ (ଯଦି ସେବାଟି ଏକ ରାଉଟିଂ ଲକ୍ଷ୍ୟ ଅଟେ)

ଯଦି ଏମ୍ବେଡେଡ୍ ସେବାଟି ଏକ OpenAI-ସୁସଙ୍ଗତ `/v1/chat/completions` ଏଣ୍ଡପଏଣ୍ଟ ଉପଲବ୍ଧ କରାଏ:

1. `src/shared/constants/providers.ts` ରେ `isEmbeddedService: true` ସହିତ ଏକ ପ୍ରଦାନକାରୀ ଏଣ୍ଟ୍ରି ଯୋଡ଼ନ୍ତୁ।
2. `BaseExecutor` କୁ ବିସ୍ତାର କରି `open-sse/executors/{name}.ts` ସୃଷ୍ଟି କରନ୍ତୁ। ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ପାଇଁ ପୋର୍ଟ ଏବଂ
   API କୀ ପୁନଃସନ୍ଧାନ କରନ୍ତୁ (କନ୍ଷ୍ଟ୍ରକ୍ଟର୍ରେ କେବେବି କ୍ୟାଶ୍ କରନ୍ତୁ ନାହିଁ)। ସୁପରଭାଇଜର୍ର ଅବସ୍ଥା `"running"` ନଥିଲେ
   ଏକ `503 service_not_running` ପ୍ରତିକ୍ରିୟା ଫେରାନ୍ତୁ।
3. ସେବା ପ୍ରିଫିକ୍ସ ସହିତ `open-sse/config/providerRegistry.ts` ରେ ମଡେଲ୍ଗୁଡ଼ିକୁ ପଞ୍ଜିକୃତ କରନ୍ତୁ
   (ଯଥା, `myservice/sub/model`)। `modelSync.ts` ସେଗୁଡ଼ିକୁ ଅଦ୍ୟତିତ ରଖିବ।

### ପଦକ୍ଷେପ 8 — ଡକ୍ୟୁମେଣ୍ଟ ଏବଂ ପରୀକ୍ଷା କରନ୍ତୁ

1. `docs/frameworks/EMBEDDED-SERVICES.md` (ଏହି ଫାଇଲ୍) ଅଦ୍ୟତନ କରନ୍ତୁ — §1 ରେ ଥିବା
   ସାରଣୀରେ ସେବାଟିକୁ ଏବଂ §4 ରେ ଯେକୌଣସି ନୂଆ ଏଣ୍ଡପଏଣ୍ଟକୁ ଯୋଡ଼ନ୍ତୁ।
2. `tests/unit/services/` ରେ ୟୁନିଟ୍ ପରୀକ୍ଷାଗୁଡ଼ିକ ଯୋଡ଼ନ୍ତୁ (ଜୀବନଚକ୍ର, ଇନ୍ଷ୍ଟଲର୍, API ଗଠନ)।
3. `tests/integration/services/` ରେ ଏକ ଇଣ୍ଟିଗ୍ରେସନ୍ ପରୀକ୍ଷା ଯୋଡ଼ନ୍ତୁ (`RUN_SERVICES_INT=1` ପଛରେ)।
4. ନୂଆ ଏଣ୍ଡପଏଣ୍ଟଗୁଡ଼ିକ ସହିତ `docs/openapi.yaml` ଅଦ୍ୟତନ କରନ୍ତୁ।

## 7. ସମସ୍ୟା ସମାଧାନ

### ସେବା ଆରମ୍ଭ ହେଉନାହିଁ

**ଲକ୍ଷଣ:** Start ବଟନ୍ 503 ଫେରାଏ, ଅବସ୍ଥା `"error"` କିମ୍ବା `"starting"` ହୋଇ ରହିଥାଏ।

**ଯାଞ୍ଚ ତାଲିକା:**

1. `GET /api/services/{name}/logs` (କିମ୍ବା ଡ୍ୟାସବୋର୍ଡର Logs ପ୍ୟାନେଲ୍) ଯାଞ୍ଚ କରନ୍ତୁ। `Error: ENOENT`, `address already in use`, କିମ୍ବା `Cannot find module` ପରି ଧାଡ଼ି ଖୋଜନ୍ତୁ।
2. `npm` PATH ରେ ଅଛି କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ: OmniRoute ଚଲାଉଥିବା ସେହି ବ୍ୟବହାରକାରୀ ଆକାଉଣ୍ଟରୁ `which npm` ଚଲାନ୍ତୁ।
3. ସେବାଟି ଇନଷ୍ଟଲ୍ ହୋଇଛି କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ: `installedVersion` ପାଇଁ `GET /api/services/{name}/status` ଯାଞ୍ଚ କରନ୍ତୁ। ଯଦି ଏହା `null`, ପ୍ରଥମେ ଇନଷ୍ଟଲ୍ ଚଲାନ୍ତୁ।
4. `DATA_DIR/services/{name}/node_modules/` ଅଛି ଏବଂ ଖାଲି ନୁହେଁ ବୋଲି ଯାଞ୍ଚ କରନ୍ତୁ।
5. ପରିଷ୍କୃତ ପ୍ରସ୍ଥାନ କାରଣ ପାଇଁ ସ୍ଥିତି ପ୍ରତିକ୍ରିୟାରେ ଥିବା `lastError` ଫିଲ୍ଡ ଯାଞ୍ଚ କରନ୍ତୁ।

### କୋଲ୍ଡ ଷ୍ଟାର୍ଟ ଧୀର ଅଟେ (`running` ଅବସ୍ଥାରେ ପହଞ୍ଚିବାକୁ > 10 s)

**ଲକ୍ଷଣ:** `"running"` କିମ୍ବା `"error"`କୁ ଯିବା ପୂର୍ବରୁ ଅବସ୍ଥା ଦୀର୍ଘ ସମୟ ପର୍ଯ୍ୟନ୍ତ `"starting"` ହୋଇ ରହିଥାଏ।

**ବ୍ୟାଖ୍ୟା:** 9Routerର କୋଲ୍ଡ ଷ୍ଟାର୍ଟରେ ବଡ଼ ନିର୍ଭରଶୀଳତା ଟ୍ରିଗୁଡ଼ିକୁ (DNS, ଟନେଲ୍, MITM ମଡ୍ୟୁଲ୍) ଇମ୍ପୋର୍ଟ କରିବା ଅନ୍ତର୍ଭୁକ୍ତ। ଡିଫଲ୍ଟ ସ୍ୱାସ୍ଥ୍ୟ ଯାଞ୍ଚ ବ୍ୟବଧାନ 2 s ଏବଂ ସୁପରଭାଇଜର୍ ଟାଇମ୍ଆଉଟ୍ ଘୋଷଣା କରିବା ପୂର୍ବରୁ 3ଟି ପ୍ରୟାସ କରେ (କିନ୍ତୁ ପୋଲିଂ ଜାରି ରଖେ)।

**ସମାଧାନ:** `healthIntervalMs` ଏବଂ `waitForHealthy` ଟାଇମ୍ଆଉଟ୍ (`healthIntervalMs * 3`)କୁ `bootstrap.ts`ରେ ବିନ୍ୟାସ କରାଯାଇପାରେ। ଅଧିକ ଷ୍ଟାର୍ଟଅପ୍ ସମୟ ଆବଶ୍ୟକ କରୁଥିବା ସେବାଗୁଡ଼ିକ ପାଇଁ `healthIntervalMs`କୁ 5000 ଏବଂ `stopTimeoutMs`କୁ 30 000 ପର୍ଯ୍ୟନ୍ତ ବଢ଼ାନ୍ତୁ।

### ପୋର୍ଟ ସଂଘର୍ଷ (`EADDRINUSE`)

**ଲକ୍ଷଣ:** ଲଗ୍ଗୁଡ଼ିକରେ `address already in use :::20130` ଦେଖାଯାଏ।

**କାରଣ:**

- ଅନ୍ୟ ଏକ ପ୍ରକ୍ରିୟା ପୂର୍ବରୁ ପୋର୍ଟ 20130 ବ୍ୟବହାର କରୁଛି।
- ପୂର୍ବବର୍ତ୍ତୀ 9Router ପ୍ରକ୍ରିୟା ସମ୍ପୂର୍ଣ୍ଣ ଭାବେ ବନ୍ଦ ହୋଇନଥିଲା (ଜମ୍ବି PID)।

**ସମାଧାନ:**

1. `.env`ରେ `NINEROUTER_PORT` ପରିବେଶ ଭେରିଏବଲ୍ ମାଧ୍ୟମରେ ଡିଫଲ୍ଟ ପୋର୍ଟ ପରିବର୍ତ୍ତନ କରନ୍ତୁ।
2. ସଂଘର୍ଷ ସୃଷ୍ଟି କରୁଥିବା ପ୍ରକ୍ରିୟା ଖୋଜି ଶେଷ କରନ୍ତୁ: `lsof -ti :20130 | xargs kill -9`।
3. `bootstrap.ts`ରେ `port` ଫିଲ୍ଡ ମାଧ୍ୟମରେ ପ୍ରତ୍ୟେକ ସେବା ପାଇଁ ପୋର୍ଟ ବିନ୍ୟାସ କରାଯାଇପାରେ।

**ଟିପ୍ପଣୀ:** OmniRouteର ଡିଫଲ୍ଟ ପୋର୍ଟ 20128 ସହିତ ସଂଘର୍ଷ ଏଡ଼ାଇବା ପାଇଁ 9Router ବିଶେଷ ଭାବରେ ପୋର୍ଟ 20130କୁ ଡିଫଲ୍ଟ ଭାବେ ବ୍ୟବହାର କରେ।

### ଇନଷ୍ଟଲ୍ କରିବା ସମୟରେ ଅନୁମତି ଅସ୍ୱୀକୃତ (EACCES)

**ଲକ୍ଷଣ:** ଇନଷ୍ଟଲ୍ 500 ଫେରାଏ, ଲଗ୍ଗୁଡ଼ିକରେ `EACCES` କିମ୍ବା `permission denied` ଦେଖାଯାଏ।

**କାରଣ:**

- `DATA_DIR` କିମ୍ବା ଏହାର ପ୍ୟାରେଣ୍ଟ ଡିରେକ୍ଟୋରୀ OmniRoute ପ୍ରକ୍ରିୟା ଦ୍ୱାରା ଲେଖନଯୋଗ୍ୟ ନୁହେଁ।
- ମ୍ୟାପ୍ ହୋଇଥିବା ଭଲ୍ୟୁମ୍ରେ ଲେଖନ ଅନୁମତି ବିନା Docker rootless ଭିତରେ ଚାଲୁଛି।

**ସମାଧାନ:**

1. `DATA_DIR` (ଡିଫଲ୍ଟ: `~/.omniroute/`) ଯାଞ୍ଚ କରନ୍ତୁ: `ls -la ~/.omniroute/`
2. OmniRoute ପ୍ରକ୍ରିୟାର ବ୍ୟବହାରକାରୀ ଡିରେକ୍ଟୋରୀର ମାଲିକ ବୋଲି ସୁନିଶ୍ଚିତ କରନ୍ତୁ: `chown -R $USER ~/.omniroute/`
3. Dockerରେ, ଭଲ୍ୟୁମ୍ ମାଉଣ୍ଟରେ କଣ୍ଟେନର୍ ବ୍ୟବହାରକାରୀ ପାଇଁ ସଠିକ୍ ଅନୁମତି ଅଛି ବୋଲି ସୁନିଶ୍ଚିତ କରନ୍ତୁ।

### ଅପଡେଟ୍ ବିଫଳ ହୁଏ (`npm install` ଟାଇମ୍ଆଉଟ୍ କିମ୍ବା ନେଟୱର୍କ ତ୍ରୁଟି)

**ଯାଞ୍ଚ ତାଲିକା:**

1. npm ରେଜିଷ୍ଟ୍ରି ଉପଲବ୍ଧ ଅଛି ବୋଲି ନିଶ୍ଚିତ କରନ୍ତୁ: `npm ping`।

3. ହସ୍ତଚାଳିତ ଭାବେ ଇନଷ୍ଟଲ୍ କରି ଦେଖନ୍ତୁ: `npm install {package}@latest --prefix ~/.omniroute/services/{name}/`।
4. ଯଦି ଏକ ଏୟାର୍-ଗ୍ୟାପ୍ ପଛରେ ଅଛନ୍ତି, ଟାରବଲ୍କୁ ପୂର୍ବରୁ ଡାଉନଲୋଡ୍ କରନ୍ତୁ ଏବଂ `npm install /path/to/tarball.tgz` ବ୍ୟବହାର କରନ୍ତୁ।

### ଆରମ୍ଭ ହେବାର ତୁରନ୍ତ ପରେ ସେବା `"error"` ଅବସ୍ଥା ଦେଖାଏ (ଦ୍ରୁତ କ୍ରାଶ୍)

**ଲକ୍ଷଣ:** 5 ସେକେଣ୍ଡରୁ କମ୍ ସମୟ ମଧ୍ୟରେ ଅବସ୍ଥା `"starting"`ରୁ `"error"`କୁ ପରିବର୍ତ୍ତିତ ହୁଏ। `lastError`ରେ `"Fast crash (exited with code 1)"` ଦେଖାଯାଏ।

1. ସମ୍ପୂର୍ଣ୍ଣ ଲଗ୍ ଶେଷାଂଶ ପଢ଼ନ୍ତୁ: `GET /api/services/{name}/logs?tail=500`।

3. 9Router ପାଇଁ: ସ୍ପନ୍ ସମୟରେ ପାସ୍ କରାଯାଇଥିବା envରେ `NINEROUTER_DISABLE_MITM=true` ଏବଂ `NINEROUTER_DISABLE_TUNNEL=true` ଅଛି ବୋଲି ଯାଞ୍ଚ କରନ୍ତୁ (`installers/ninerouter.ts`ର `resolveSpawnArgs` ଦେଖନ୍ତୁ)।

## 8. ପ୍ରାୟ ପଚରାଯାଉଥିବା ପ୍ରଶ୍ନ

**ପ୍ର: ମୁଁ ଏମ୍ବେଡେଡ୍ ସେବାଗୁଡ଼ିକର ଏଣ୍ଡପଏଣ୍ଟଗୁଡ଼ିକୁ non-loopback କ୍ଲାଏଣ୍ଟମାନଙ୍କ ପାଇଁ ଉନ୍ମୁକ୍ତ କରିପାରିବି କି?**

ନା। LOCAL_ONLY ସ୍ତରଟି ଉଦ୍ଦେଶ୍ୟମୂଳକ (କଠୋର ନିୟମ #17)। `npm install` ଆହ୍ୱାନ କରିପାରୁଥିବା କିମ୍ବା `node` ପ୍ରକ୍ରିୟା ଆରମ୍ଭ କରିପାରୁଥିବା ରୁଟ୍ଗୁଡ଼ିକ non-loopback ଟ୍ରାଫିକ୍ରୁ ପହଞ୍ଚଯୋଗ୍ୟ ହେବା ଉଚିତ୍ ନୁହେଁ, କାରଣ ଅନ୍ୟଥା କୌଣସି ଟନେଲ୍ (Cloudflare, Ngrok, Tailscale) ମାଧ୍ୟମରେ ଲିକ୍ ହୋଇଥିବା JWT ଇଚ୍ଛାମତେ ପ୍ରକ୍ରିୟା ଆରମ୍ଭ କରିବାକୁ ଅନୁମତି ଦେବ। `/api/services/` ପାଇଁ ଏଥିରୁ ବାହାରିବାର କୌଣସି ବିଶେଷ ଛାଡ଼ ନାହିଁ — `/api/mcp/` ଭଳି ନୁହେଁ, ଏହା manage-scope bypass ତାଲିକାରୁ ବାଦ ଦିଆଯାଇଛି। `docs/security/ROUTE_GUARD_TIERS.md` ଦେଖନ୍ତୁ।

---

**ପ୍ର: ପ୍ରଡକ୍ସନ୍/କ୍ଲାଉଡ୍ ଡିପ୍ଲୟମେଣ୍ଟରେ 9Router ଏବଂ CLIProxyAPI ଉପଲବ୍ଧ ହେବ କି?**

ହଁ। ଉଭୟ ସେବା OmniRoute ନିଜେ ଅନୁସରଣ କରୁଥିବା ସମାନ local-first ମଡେଲ୍ ଅନୁସରଣ କରନ୍ତି। ସେଗୁଡ଼ିକ ସମାନ ମେସିନ୍ରେ ଚାଲେ ଏବଂ loopback ମାଧ୍ୟମରେ ଯୋଗାଯୋଗ କରେ। ଏଠାରେ "ପ୍ରଡକ୍ସନ୍"ର ଅର୍ଥ ହେଉଛି OmniRoute ଡିପ୍ଲୟ କରାଯାଇଥିବା VPS କିମ୍ବା ସ୍ଥାନୀୟ ସର୍ଭର୍, କୌଣସି ରିମୋଟ୍ କ୍ଲାଉଡ୍ ପ୍ରଦାନକାରୀ ନୁହେଁ।

---

**ପ୍ର: ମୁଁ ସୁପରଭାଇଜର୍କୁ କିପରି ଡିବଗ୍ କରିବି?**

1. SSE ଲଗ୍ ଷ୍ଟ୍ରିମ୍କୁ ଲାଇଭ୍ ଅନୁସରଣ କରନ୍ତୁ: `curl -N http://localhost:20128/api/services/9router/logs`।
2. `service:supervisor` namespace ଦ୍ୱାରା ଫିଲ୍ଟର୍ କରାଯାଇଥିବା OmniRouteର pino ଆଉଟପୁଟ୍ରେ ସଂରଚିତ ଲଗ୍ଗୁଡ଼ିକ ଯାଞ୍ଚ କରନ୍ତୁ।
3. DB ଧାଡ଼ିଟି ଯାଞ୍ଚ କରନ୍ତୁ: `sqlite3 ~/.omniroute/omniroute.db "SELECT * FROM version_manager WHERE tool='9router'"`।
4. ବର୍ତ୍ତମାନର ଲାଇଭ୍ ଅବସ୍ଥା, PID, ସ୍ୱାସ୍ଥ୍ୟ ଏବଂ `lastError`କୁ ଗୋଟିଏ କଲ୍ରେ ଦେଖିବା ପାଇଁ `GET /api/services/9router/status` ବ୍ୟବହାର କରନ୍ତୁ।

---

**ପ୍ର: ସୁପରଭାଇଜର୍ `health: "degraded"` କିମ୍ବା `health: "unknown"` ଦେଖାଉଛି, କିନ୍ତୁ ଅବସ୍ଥା `"running"` ଅଛି। ଏହା କୌଣସି ସମସ୍ୟା କି?**

`"degraded"`ର ଅର୍ଥ ହେଉଛି health probe ଏକ non-200 ପ୍ରତିକ୍ରିୟା ଫେରାଇଛି। `"unknown"`ର ଅର୍ଥ ହେଉଛି ଏପର୍ଯ୍ୟନ୍ତ କୌଣସି probe ସମ୍ପୂର୍ଣ୍ଣ ହୋଇନାହିଁ (ପ୍ରଥମ poll ସହିତ race)। ଷ୍ଟାର୍ଟଅପ୍ ସମୟରେ ଉଭୟ ଅବସ୍ଥା ଅସ୍ଥାୟୀ। `"running"` ହେବା ପରେ ଯଦି ସ୍ୱାସ୍ଥ୍ୟ `healthIntervalMs * 3` msରୁ ଅଧିକ ସମୟ ପର୍ଯ୍ୟନ୍ତ `"degraded"` ରହେ, ତେବେ ଏମ୍ବେଡେଡ୍ ସେବାଟି ଚାଲୁଛି, କିନ୍ତୁ ଏହାର HTTP API ପ୍ରତିକ୍ରିୟା ଦେଉନାହିଁ। ଷ୍ଟାଟସ୍ ପ୍ରତିକ୍ରିୟାରେ ପୋର୍ଟଟି ସଠିକ୍ ଅଛି କି ଏବଂ ସେବାଟି ପ୍ରକୃତରେ ସେହି ପୋର୍ଟରେ ଶୁଣୁଛି କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ।

---

**ପ୍ର: ସମ୍ପୂର୍ଣ୍ଣ ପୁନଃଆରମ୍ଭ ବିନା ମୁଁ 9Router API କି ପରିବର୍ତ୍ତନ କରିପାରିବି କି?**

ନା। spawn ସମୟରେ ଏକ environment variable ମାଧ୍ୟମରେ API କି 9Routerକୁ ପ୍ରଦାନ କରାଯାଏ। ଚାଲୁଥିବା ପ୍ରକ୍ରିୟାରେ environment variableଗୁଡ଼ିକୁ ପରିବର୍ତ୍ତନ କରାଯାଇପାରିବ ନାହିଁ। ନୂତନ କି ପ୍ରୟୋଗ କରିବା ପାଇଁ `POST .../rotate-key` ସ୍ୱୟଂଚାଳିତ ଭାବରେ ସେବାଟିକୁ ବନ୍ଦ କରି ପୁନଃଆରମ୍ଭ କରେ। କି ରୋଟେସନ୍ ସେବାର `stopTimeoutMs` (ଡିଫଲ୍ଟ 15 s) ସହିତ ଏହାର ଷ୍ଟାର୍ଟଅପ୍ ସମୟ ମଧ୍ୟରେ କାର୍ଯ୍ୟକାରୀ ହୁଏ।

---

**ପ୍ର: ring bufferର ସୀମା କେତେ ଏବଂ ଏହା ପୂର୍ଣ୍ଣ ହେଲେ କ’ଣ ହୁଏ?**

ପ୍ରତ୍ୟେକ ସେବାର ଏକ ଉତ୍ସର୍ଗୀକୃତ 5 MB ring buffer ଅଛି। buffer ପୂର୍ଣ୍ଣ ହେଲେ, ନୂତନ ଲଗ୍ ଲାଇନ୍ଗୁଡ଼ିକ ପାଇଁ ସ୍ଥାନ ତିଆରି କରିବାକୁ ସବୁଠାରୁ ପୁରୁଣା ଲଗ୍ ଲାଇନ୍ଗୁଡ଼ିକୁ ବାହାର କରାଯାଏ। SSE `snapshot` ଇଭେଣ୍ଟ `tail` ସୀମା ମଧ୍ୟରେ ସବୁଠାରୁ ସାମ୍ପ୍ରତିକ ଲାଇନ୍ଗୁଡ଼ିକ ଫେରାଏ। DB ଧାଡ଼ିରେ `logsBufferPath` ସେଟ୍ ନଥିଲେ ଲଗ୍ଗୁଡ଼ିକ ଡିସ୍କରେ ସ୍ଥାୟୀ ଭାବରେ ସଂରକ୍ଷିତ ହୁଏ ନାହିଁ।
