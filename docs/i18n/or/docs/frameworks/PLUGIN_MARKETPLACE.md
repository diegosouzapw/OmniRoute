> **ସତ୍ୟର ମୂଳ ଉତ୍ସ:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/`, ଏବଂ
> `src/app/(dashboard)/dashboard/plugins/`
> **ଶେଷ ଅଦ୍ୟତନ:** 2026-06-28 — v3.8.40

OmniRoute ଏକ WordPress-ଶୈଳୀର ପ୍ଲଗଇନ୍ ସିଷ୍ଟମ୍ ସହିତ ଆସେ। ପ୍ଲଗଇନ୍ଗୁଡ଼ିକ ସ୍ୱୟଂ-ସମ୍ପୂର୍ଣ୍ଣ
ଡିରେକ୍ଟୋରୀ — ପ୍ରତ୍ୟେକରେ ଏକ `plugin.json` ମାନିଫେଷ୍ଟ ଏବଂ ଏକ ଏଣ୍ଟ୍ରି ଫାଇଲ୍ ଥାଏ — ଯାହା
ଅନୁରୋଧ ପାଇପଲାଇନ୍ (`onRequest` / `onResponse` / `onError`) ଏବଂ
ଜୀବନଚକ୍ର ଇଭେଣ୍ଟଗୁଡ଼ିକ (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`) ସହିତ ହୁକ୍ ହୁଏ।

**ପ୍ଲଗଇନ୍ ମାର୍କେଟପ୍ଲେସ୍** ହେଉଛି ସେହି ସିଷ୍ଟମ୍ ଉପରେ ଥିବା ଆବିଷ୍କାର ସ୍ତର। ଏହା
ଇନ୍ଷ୍ଟଲ୍ କରିହେବା ପ୍ଲଗଇନ୍ଗୁଡ଼ିକର ଏକ ବ୍ରାଉଜ୍ଯୋଗ୍ୟ କ୍ୟାଟାଲଗ୍ ପ୍ରଦର୍ଶନ କରେ। ଡିଫଲ୍ଟ ଭାବରେ କ୍ୟାଟାଲଗ୍ଟି
ଏକ ଛୋଟ ବିଲ୍ଟ-ଇନ୍ ସିଡ୍ ରେଜିଷ୍ଟ୍ରି ଅଟେ; ଜଣେ ଅପରେଟର୍ ଏହାକୁ ଏକ କଷ୍ଟମ୍ ରିମୋଟ୍
ରେଜିଷ୍ଟ୍ରି URL ଦିଗରେ ନିର୍ଦ୍ଦେଶ କରିପାରିବେ, ଯେଉଁ କ୍ଷେତ୍ରରେ ଫେଚ୍କୁ ଏକ DNS-ରିଜଲ୍ଭିଂ SSRF ଗାର୍ଡ ଦ୍ୱାରା
ସୁଦୃଢ଼ କରାଯାଏ ([ସୁରକ୍ଷା](#security) ଦେଖନ୍ତୁ)।

ପ୍ରତ୍ୟେକ ପ୍ଲଗଇନ୍ ରୁଟ୍ **କେବଳ ଲୁପ୍ବ୍ୟାକ୍ ପାଇଁ** (ଟିୟର୍ 1 — `LOCAL_ONLY`): ପ୍ଲଗଇନ୍ଗୁଡ଼ିକ ଚାଇଲ୍ଡ ପ୍ରୋସେସ୍ରେ
କୋଡ୍ ଲୋଡ୍ ଏବଂ ନିଷ୍ପାଦନ କରନ୍ତି, ତେଣୁ ପ୍ରମାଣୀକରଣ ନିର୍ବିଶେଷରେ ଏହି ରୁଟ୍ଗୁଡ଼ିକୁ
ଏକ ନନ୍-ଲୁପ୍ବ୍ୟାକ୍ ଅରିଜିନ୍ରୁ ପହଞ୍ଚିହେବ ନାହିଁ। ଦେଖନ୍ତୁ
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md)।

## ଏହା କିପରି ଏକାଠି କାମ କରେ

```
ଡ୍ୟାସ୍ବୋର୍ଡ (/dashboard/plugins)
  ├─ "ଇନ୍ଷ୍ଟଲ୍ ହୋଇଥିବା" ଟ୍ୟାବ୍ → GET /api/plugins            (listPlugins)
  │                              POST /api/plugins/scan      (pluginManager.scan)
  │                              POST /api/plugins/{name}/activate|deactivate
  │                              DELETE /api/plugins/{name}   (ଅନ୍ଇନ୍ଷ୍ଟଲ୍)
  └─ "ମାର୍କେଟପ୍ଲେସ୍" ଟ୍ୟାବ୍ → GET /api/plugins/marketplace
                                 → listMarketplacePlugins()
                                   ├─ କଷ୍ଟମ୍ URL ନାହିଁ → ବିଲ୍ଟ-ଇନ୍ SEED_REGISTRY
                                   └─ କଷ୍ଟମ୍ URL → isSafeMarketplaceUrl() SSRF ଗାର୍ଡ
                                                  → safeOutboundFetch(guard:"public-only")
```

- **ରେଜିଷ୍ଟ୍ରି ସ୍ତର** — `src/lib/plugins/marketplace.ts`: କୌଣସି ବିଫଳତା ଘଟିଲେ ସିଡ୍ ରେଜିଷ୍ଟ୍ରିକୁ
  ଫଲ୍ବ୍ୟାକ୍ କରି କ୍ୟାଟାଲଗ୍କୁ ତାଲିକାଭୁକ୍ତ / ସନ୍ଧାନ କରେ।
- **ଜୀବନଚକ୍ର ସ୍ତର** — `src/lib/plugins/manager.ts` (`pluginManager` ସିଙ୍ଗଲ୍ଟନ୍):
  ଇନ୍ଷ୍ଟଲ୍, ଅପ୍ଗ୍ରେଡ୍, ସକ୍ରିୟ, ନିଷ୍କ୍ରିୟ, ଅନ୍ଇନ୍ଷ୍ଟଲ୍, ସ୍କାନ୍, ଷ୍ଟାର୍ଟଅପ୍ ଲୋଡ୍।
- **ମାନିଫେଷ୍ଟ ସ୍ତର** — `src/lib/plugins/manifest.ts`: `plugin.json` ପାଇଁ Zod ସ୍କିମା + ଡିଫଲ୍ଟଗୁଡ଼ିକ।
- **ସ୍କାନର୍** — `src/lib/plugins/scanner.ts`: ପ୍ଲଗଇନ୍ ଡିରେକ୍ଟୋରୀ ଅଧୀନରେ ଡିସ୍କରେ ଥିବା
  ପ୍ଲଗଇନ୍ଗୁଡ଼ିକୁ ଖୋଜେ।
- **ଲୋଡର୍** — `src/lib/plugins/loader.ts`: ପ୍ରତ୍ୟେକ ପ୍ଲଗଇନ୍କୁ ଏକ ବିଚ୍ଛିନ୍ନ
  ଚାଇଲ୍ଡ ପ୍ରୋସେସ୍ରେ ସୃଷ୍ଟି କରେ ଏବଂ IPC ମାଧ୍ୟମରେ ହୁକ୍ କଲ୍ଗୁଡ଼ିକୁ ମଧ୍ୟସ୍ଥତା କରେ।

## ମାର୍କେଟପ୍ଲେସ୍ କ୍ୟାଟାଲଗ୍

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) `MarketplaceEntry`
ଅବଜେକ୍ଟଗୁଡ଼ିକର ଏକ ତାଲିକା ଫେରାଏ:

| ଫିଲ୍ଡ         | ପ୍ରକାର   | ଟିପ୍ପଣୀ                                  |
| ------------- | -------- | ---------------------------------------- |
| `name`        | string   | kebab-case ପ୍ଲଗଇନ୍ ନାମ                   |
| `version`     | string   | semver                                   |
| `description` | string   | ସଂକ୍ଷିପ୍ତ ସାରାଂଶ                         |
| `author`      | string   | ଲେଖକ / ସଂଗଠନ                             |
| `license`     | string   | SPDX-ଶୈଳୀର ଲାଇସେନ୍ସ id                   |
| `downloadUrl` | string   | ଉତ୍ସ ଡାଉନ୍ଲୋଡ୍ URL (ଖାଲି ହୋଇପାରେ)        |
| `repository`  | string?  | ଇଚ୍ଛାଧୀନ ରିପୋଜିଟୋରୀ URL                  |
| `tags`        | string[] | ସନ୍ଧାନ/ଫିଲ୍ଟର୍ ଟ୍ୟାଗ୍ଗୁଡ଼ିକ              |
| `downloads`   | number   | ଡାଉନ୍ଲୋଡ୍ ସଂଖ୍ୟା                         |
| `rating`      | number   | 0–5                                      |
| `verified`    | boolean  | ଏଣ୍ଟ୍ରିଟି ଯାଞ୍ଚକୃତ ଭାବେ ଚିହ୍ନିତ କି ନାହିଁ |
| `lastUpdated` | string   | ISO-ସଦୃଶ ତାରିଖ ଷ୍ଟ୍ରିଙ୍ଗ୍                |

ଯେତେବେଳେ କୌଣସି କଷ୍ଟମ୍ ରେଜିଷ୍ଟ୍ରି URL କନଫିଗର୍ ହୋଇନଥାଏ, କ୍ୟାଟାଲଗ୍ଟି ହେଉଛି ବିଲ୍ଟ-ଇନ୍
`SEED_REGISTRY` (ବର୍ତ୍ତମାନ `request-logger`, `rate-limiter`, `cost-tracker`, ଏବଂ
`theme-manager`)। ସିଡ୍ ରେଜିଷ୍ଟ୍ରି ସର୍ବଦା ଉପଲବ୍ଧ — ଯଦି ଏକ କନଫିଗର୍ ହୋଇଥିବା ରିମୋଟ୍
ରେଜିଷ୍ଟ୍ରିକୁ ପହଞ୍ଚିହେବ ନାହିଁ, ଏକ ନନ୍-`200` ଷ୍ଟାଟସ୍ ଫେରାଏ, କିମ୍ବା ଏକ ଅପରିଚିତ
ବଡି ଫେରାଏ, `listMarketplacePlugins()` ଏକ ଚେତାବନୀ ଲଗ୍ କରେ ଏବଂ ସିଡ୍ ତାଲିକାକୁ ଫଲ୍ବ୍ୟାକ୍ କରେ।

> ଟିପ୍ପଣୀ: ମାର୍କେଟପ୍ଲେସ୍ **କ୍ୟାଟାଲଗ୍** (ବ୍ରାଉଜ୍/ସନ୍ଧାନ) ଆରମ୍ଭରୁ ଶେଷ ପର୍ଯ୍ୟନ୍ତ ସଂଯୋଜିତ ହୋଇଛି, କିନ୍ତୁ
> କ୍ୟାଟାଲଗ୍ରୁ ଏକ-କ୍ଲିକ୍ ମାର୍କେଟପ୍ଲେସ୍ **ଇନ୍ଷ୍ଟଲ୍** ଏପର୍ଯ୍ୟନ୍ତ କାର୍ଯ୍ୟକାରୀ କରାଯାଇନାହିଁ —
> ଏକ ମାର୍କେଟପ୍ଲେସ୍ ଏଣ୍ଟ୍ରିରେ ଥିବା ଡ୍ୟାସ୍ବୋର୍ଡର "ଇନ୍ଷ୍ଟଲ୍" ବଟନ୍ ବର୍ତ୍ତମାନ ଏକ
> "ଶୀଘ୍ର ଆସୁଛି" ସୂଚନା ଦେଖାଏ। ବର୍ତ୍ତମାନ ଇନ୍ଷ୍ଟଲେସନ୍ ସ୍ଥାନୀୟ-ପାଥ୍ ଇନ୍ଷ୍ଟଲ୍
> ପ୍ରବାହ (`POST /api/plugins`) ଏବଂ ଅନ୍-ଡିସ୍କ ଆବିଷ୍କାର (`POST /api/plugins/scan`) ମାଧ୍ୟମରେ ହୁଏ।

## REST API

ସମସ୍ତ endpoint ପାଇଁ management auth (`requireManagementAuth`) **ଆବଶ୍ୟକ** ଏବଂ ସେଗୁଡ଼ିକ
କେବଳ loopback ପାଇଁ ଉପଲବ୍ଧ — `/api/plugins` ଏବଂ `/api/plugins/` କୁ
`LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`) ରେ ତାଲିକାଭୁକ୍ତ କରାଯାଇଛି।

| Endpoint                         | ପଦ୍ଧତି | ବର୍ଣ୍ଣନା                                                                       |
| -------------------------------- | ------ | ------------------------------------------------------------------------------ |
| `/api/plugins`                   | GET    | ଇନଷ୍ଟଲ୍ ହୋଇଥିବା plugin ଗୁଡ଼ିକର ତାଲିକା (ଇଚ୍ଛାଧୀନ `?status=` filter)             |
| `/api/plugins`                   | POST   | ଏକ absolute local path ରୁ plugin ଇନଷ୍ଟଲ୍ କରନ୍ତୁ                                |
| `/api/plugins/scan`              | POST   | plugin directory କୁ scan କରି ନୂଆ plugin ଗୁଡ଼ିକୁ ପଞ୍ଜୀକୃତ କରନ୍ତୁ                |
| `/api/plugins/marketplace`       | GET    | marketplace catalog entry ଗୁଡ଼ିକର ତାଲିକା ଦେଖାନ୍ତୁ                              |
| `/api/plugins/[name]`            | GET    | ଇନଷ୍ଟଲ୍ ହୋଇଥିବା plugin ର ବିବରଣୀ ପାଆନ୍ତୁ                                        |
| `/api/plugins/[name]`            | DELETE | ଏକ plugin ଅନଇନଷ୍ଟଲ୍ କରନ୍ତୁ                                                     |
| `/api/plugins/[name]/activate`   | POST   | ସକ୍ରିୟ କରନ୍ତୁ (load + hook ପଞ୍ଜୀକରଣ)                                           |
| `/api/plugins/[name]/deactivate` | POST   | ନିଷ୍କ୍ରିୟ କରନ୍ତୁ (`onDeactivate` ଚାଳନ କରି hook ଗୁଡ଼ିକର ପଞ୍ଜୀକରଣ ବାତିଲ୍ କରନ୍ତୁ) |
| `/api/plugins/[name]/config`     | GET    | plugin config + config schema ପାଆନ୍ତୁ                                          |
| `/api/plugins/[name]/config`     | PUT    | plugin config ଅପଡେଟ୍ କରନ୍ତୁ (schema ସହିତ ବୈଧତା ଯାଞ୍ଚ କରାଯାଇଥାଏ)                |

`GET /api/plugins` ର `status` filter
`installed` / `active` / `inactive` / `error` ମଧ୍ୟରୁ ଗୋଟିଏ ଗ୍ରହଣ କରେ। ଏକ ଅବୈଧ ମୂଲ୍ୟ `400` ଫେରାଏ।

### ଇନଷ୍ଟଲ୍ ହୋଇଥିବା plugin ଗୁଡ଼ିକର ତାଲିକା

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### ଏକ local path ରୁ ଇନଷ୍ଟଲ୍ କରନ୍ତୁ

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` ଟି **absolute** ହେବା ଆବଶ୍ୟକ ଏବଂ ଏଥିରେ `..` traversal segment କିମ୍ବା
null byte ରହିପାରିବ ନାହିଁ (Zod ଦ୍ୱାରା ପ୍ରୟୋଗ କରାଯାଏ)। source directory ରେ ଏକ ବୈଧ
`plugin.json` ରହିବା ଆବଶ୍ୟକ (କିମ୍ବା ଏହା ସେହି directory ର parent ହେବା ଆବଶ୍ୟକ)। ସଫଳ ହେଲେ response ଟି ଇନଷ୍ଟଲ୍ ହୋଇଥିବା plugin row ସହିତ `201` ହୁଏ।

### marketplace ବ୍ରାଉଜ୍ କରନ୍ତୁ

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### plugin config ଅପଡେଟ୍ କରନ୍ତୁ

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` ଦିଆଯାଇଥିବା ପ୍ରତ୍ୟେକ ମୂଲ୍ୟକୁ plugin ର
`configSchema` (manifest ରେ ଘୋଷିତ) ସହିତ ବୈଧତା ଯାଞ୍ଚ କରେ: `number` field ଗୁଡ଼ିକ `min`/`max` କୁ ମାନନ୍ତି,
`select` field ଗୁଡ଼ିକ ଘୋଷିତ `enum` ସହିତ ମେଳ ଖାଇବା ଆବଶ୍ୟକ। schema ରେ ନଥିବା key ଗୁଡ଼ିକୁ
ଅନୁମତି ଦିଆଯାଏ।

## ବିନ୍ୟାସ

### Plugin directory

Plugin ଗୁଡ଼ିକ OmniRoute data directory ଅଧୀନରେ ରହେ:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (କିମ୍ବା manifest.main ଯାହାକୁ ସୂଚାଏ)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) ସେହି directory କୁ
ତିନୋଟି ପଦକ୍ଷେପରେ resolve କରେ:

1. **`OMNIROUTE_PLUGINS_DIR`**, ସେଟ୍ ହୋଇଥିଲେ — `HOME` ଯାହା କହୁଥାଉ ନା କାହିଁକି, ଏହାକୁ ଅବିକଳ ଭାବରେ ବ୍ୟବହାର କରାଯାଏ। ଏହା
   Docker/K8s ପାଇଁ ସ୍ପଷ୍ଟ ନିୟନ୍ତ୍ରଣ, ଯେଉଁଠାରେ plugin tree କୁ ଏମିତି ଏକ path ରେ bind-mount କରାଯାଏ
   ଯାହାର ସାଧାରଣତଃ container ର home directory ସହିତ କୌଣସି ସମ୍ପର୍କ ନଥାଏ (#11827)।
2. `<home>/.omniroute/plugins`, ଯେଉଁଠାରେ `<home>` ଟି `HOME` / `USERPROFILE`
   environment variable ରୁ ଆସେ।
3. `/tmp/.omniroute/plugins`, ଯେତେବେଳେ process କୌଣସି home export କରେ ନାହିଁ।

resolve ହୋଇଥିବା directory କୁ startup ସମୟରେ `scanner.dir_resolved` ଭାବରେ ଥରେ log କରାଯାଏ, ଏବଂ
କେଉଁ input ଚୟନ ହେଲା (`OMNIROUTE_PLUGINS_DIR`, `home`, କିମ୍ବା `no-home-fallback`) ତାହା ଉଲ୍ଲେଖ କରାଯାଏ — ତେଣୁ ଏକ image
ନିରବରେ ପଦକ୍ଷେପ 3 ରେ ପହଞ୍ଚିଲେ, କେବଳ ଏକ ଖାଲି plugin ତାଲିକା ରିପୋର୍ଟ କରିବା ପରିବର୍ତ୍ତେ ତାହା ଜଣାଇଦିଏ।
`POST /api/plugins/scan` ସେଠାରେ ଏକ ବୈଧ
`plugin.json` ଥିବା ଯେକୌଣସି subdirectory କୁ ଖୋଜି ପଞ୍ଜୀକୃତ କରେ; ସେହି directory ଟି ମଧ୍ୟ ସେହି root ଯେଉଁଠାକୁ
`pluginManager.install()` plugin ଗୁଡ଼ିକୁ copy କରେ, ତେଣୁ ଏକ override discovery ଏବଂ
installation ଉଭୟକୁ ଏକାସାଙ୍ଗରେ ସ୍ଥାନାନ୍ତର କରେ।

> **`OMNIROUTE_PLUGINS_DIR`, `OMNIROUTE_PLUGIN_PATH` ନୁହେଁ।** ପରବର୍ତ୍ତୀଟିକୁ କେବଳ
> CLI command-plugin loader (`bin/cli/plugins.mjs`) ଦ୍ୱାରା `omniroute` subcommand ଯୋଡ଼ୁଥିବା `omniroute-cmd-*` npm
> package ଖୋଜିବା ପାଇଁ ପଢ଼ାଯାଏ — ଏଠାରେ ବର୍ଣ୍ଣିତ runtime scanner ଉପରେ ଏହାର କୌଣସି ପ୍ରଭାବ ନାହିଁ।
> ସେହି ପକ୍ଷ ପାଇଁ [PLUGINS.md](./PLUGINS.md) ଦେଖନ୍ତୁ।

### Custom marketplace registry URL

marketplace catalog ର source କୁ `pluginMarketplaceUrl` setting ରୁ ପଢ଼ାଯାଏ
(`src/lib/plugins/marketplace.ts` ରେ `settings.pluginMarketplaceUrl` ପଢ଼ାଯାଏ)। ଏହାକୁ
ଏକ `http(s)` URL ରେ ସେଟ୍ କରାଗଲେ, `listMarketplacePlugins()` ସେହି URL କୁ fetch କରେ ଏବଂ
entry ଗୁଡ଼ିକର ଏକ top-level JSON array କିମ୍ବା ଏକ `plugins` array ଥିବା object କୁ ଗ୍ରହଣ କରେ;
string `name` ନଥିବା entry ଗୁଡ଼ିକୁ filter କରି ବାହାର କରାଯାଏ। ସେଟ୍ ହୋଇନଥିଲେ (କିମ୍ବା fetch
SSRF guard ରେ ବିଫଳ ହେଲେ / ଏକ ଖରାପ response ଫେରାଇଲେ), built-in seed registry
ବ୍ୟବହାର କରାଯାଏ।

dashboard ର "Marketplace" tab ଏହି URL ପାଇଁ ଏକ field ପ୍ରଦର୍ଶନ କରେ (`GET /api/settings` ରୁ
ପୁନଃ ପଢ଼ାଯାଏ)।

> କାର୍ଯ୍ୟାନ୍ୱୟନ ଟିପ୍ପଣୀ: dashboard ର "Save" action
> `pluginMarketplaceUrl` କୁ `PATCH /api/settings` ନିକଟକୁ ପଠାଏ। ଲେଖାଯିବା ସମୟରେ ଏହି
> key ଟି `updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`) ରେ ଘୋଷିତ ହୋଇନାହିଁ, ତେଣୁ ଏହା ଉପରେ ନିର୍ଭର କରିବା ପୂର୍ବରୁ ଆପଣଙ୍କ
> release ରେ persistence ଯାଞ୍ଚ କରନ୍ତୁ — settings
> store ରେ key ଟି ଉପସ୍ଥିତ ହୋଇଗଲେ **read** path (`getSettings()` →
> `listMarketplacePlugins()`) ଏହାକୁ ସମ୍ମାନ କରେ।

## ସୁରକ୍ଷା

### ରୁଟ୍ ସ୍ତର — କେବଳ ଲୁପ୍ବ୍ୟାକ୍

ପ୍ଲଗଇନ୍ଗୁଡ଼ିକ ସୃଷ୍ଟି କରାଯାଇଥିବା ଚାଇଲ୍ଡ ପ୍ରୋସେସ୍ରେ କୋଡ୍ ନିଷ୍ପାଦନ କରନ୍ତି, ତେଣୁ ସମଗ୍ର `/api/plugins`
ପୃଷ୍ଠକୁ `LOCAL_ONLY` (ସ୍ତର 1) ଭାବେ ବର୍ଗୀକୃତ କରାଯାଇଛି। କୌଣସି ପ୍ରମାଣୀକରଣ ଯାଞ୍ଚର **ପୂର୍ବରୁ**
ଲୁପ୍ବ୍ୟାକ୍ ପ୍ରବର୍ତ୍ତନ ବିନା ସର୍ତ୍ତରେ ଚାଲେ, ତେଣୁ ଟନେଲ୍ ମାଧ୍ୟମରେ ବକ୍ସ୍କୁ ପହଞ୍ଚିଥିବା
ଏକ ଲିକ୍ ହୋଇଥିବା ପରିଚାଳନା ଟୋକେନ୍ ମଧ୍ୟ କୌଣସି ପ୍ଲଗଇନ୍କୁ ଇନ୍ଷ୍ଟଲ୍, ସକ୍ରିୟ କିମ୍ବା ଅନ୍ଇନ୍ଷ୍ଟଲ୍
କରିପାରିବ ନାହିଁ। [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) ଏବଂ
କଠୋର ନିୟମ #15 / #17 ଦେଖନ୍ତୁ।

### ମାର୍କେଟପ୍ଲେସ୍ ରେଜିଷ୍ଟ୍ରି SSRF ସୁରକ୍ଷା

ଏକ କଷ୍ଟମ୍ ରେଜିଷ୍ଟ୍ରି URL ଆକ୍ରମଣକାରୀଙ୍କ ଦ୍ୱାରା ପ୍ରଭାବିତ ହୋଇପାରୁଥିବା ବିନ୍ୟାସ, ତେଣୁ ଏହାକୁ
ଆଣିବା ପୂର୍ବରୁ `listMarketplacePlugins()` ଏହାକୁ ଦୁଇଟି ସ୍ତର ମାଧ୍ୟମରେ ଚଲାଏ:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - `http:` / `https:` ନୁହେଁ ଏପରି ସବୁକିଛିକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ।
   - ପ୍ରାମାଣିକ `isPrivateHost`
     (`src/shared/network/outboundUrlGuard.ts`) ମାଧ୍ୟମରେ ଆକ୍ଷରିକ ପ୍ରାଇଭେଟ୍/ଲୁପ୍ବ୍ୟାକ୍/ଲିଙ୍କ୍-ଲୋକାଲ୍/ULA ହୋଷ୍ଟ୍ଗୁଡ଼ିକୁ (IPv4-ମ୍ୟାପ୍ ହୋଇଥିବା ଠିକଣା ସମେତ IPv4 **ଏବଂ** IPv6)
     ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ।
   - **ଉଭୟ** `A` ଏବଂ `AAAA` ରେକର୍ଡକୁ ରିଜଲ୍ଭ କରେ ଏବଂ ରିଜଲ୍ଭ ହୋଇଥିବା **କୌଣସି** ଠିକଣା
     ପ୍ରାଇଭେଟ୍ ହେଲେ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ — ଫଳରେ ପବ୍ଲିକ୍-ହୋଷ୍ଟନାମ୍ → ପ୍ରାଇଭେଟ୍-IP ବାଇପାସ୍ ବନ୍ଦ ହୁଏ।
   - **ବିଫଳ ହେଲେ ବନ୍ଦ କରେ**: DNS ରିଜଲ୍ୟୁସନ୍ ବିଫଳ ହେଲେ URL ପ୍ରତ୍ୟାଖ୍ୟାନ ହୁଏ।
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`**
   (`src/shared/network/safeOutboundFetch.ts`): ଫେଚ୍ କରିବା ସମୟରେ କେବଳ-ପବ୍ଲିକ୍ URL
   ସୁରକ୍ଷାକୁ ପୁଣି ପ୍ରୟୋଗ କରେ ଏବଂ **ରିଡାଇରେକ୍ଟଗୁଡ଼ିକୁ ଅବରୋଧ କରେ** (କୌଣସି ପବ୍ଲିକ୍ → ପ୍ରାଇଭେଟ୍ `30x`
   ପିଭଟ୍ ନାହିଁ)।

ଯେଉଁ URL କୌଣସି ଗୋଟିଏ ସ୍ତରରେ ବିଫଳ ହୁଏ, ତାହା ଅନୁରୋଧକୁ ବାତିଲ କରେ ନାହିଁ — ମାର୍କେଟପ୍ଲେସ୍
ନିରବରେ ବିଲ୍ଟ-ଇନ୍ ସିଡ୍ ରେଜିଷ୍ଟ୍ରିକୁ ଫେରିଯାଏ ଏବଂ ଏକ ସତର୍କବାଣୀ ଲଗ୍ କରେ।

> ବିଶେଷ ଭାବରେ A + AAAA ରିଜଲ୍ଭ କରିବା ଏବଂ କେବଳ-IPv4 ଯାଞ୍ଚ ପରିବର୍ତ୍ତେ
> ପ୍ରାମାଣିକ `isPrivateHost` ବ୍ୟବହାର କରିବା ପାଇଁ PR #3774ରେ ଏହି ସୁରକ୍ଷାକୁ ଅଧିକ ଦୃଢ଼ କରାଯାଇଥିଲା।

- **ପ୍ରୋସେସ୍ ପୃଥକୀକରଣ** — `loadPlugin()` (`src/lib/plugins/loader.ts`) ପ୍ରତ୍ୟେକ
  ପ୍ଲଗଇନ୍କୁ ଏକ ପୃଥକ Node.js ଚାଇଲ୍ଡ ପ୍ରୋସେସ୍ରେ ସୃଷ୍ଟି କରେ ଏବଂ IPC ମାଧ୍ୟମରେ ଯୋଗାଯୋଗ କରେ।
  ହୁକ୍ କଲ୍ଗୁଡ଼ିକରେ `SIGTERM` → `SIGKILL` ଏସ୍କାଲେସନ୍ ସହିତ ଏକ ସମୟସୀମା ରହିଛି।
- **Env ଅନୁମୋଦିତ ତାଲିକା** — ଚାଇଲ୍ଡ କେବଳ ଅନୁମୋଦିତ ତାଲିକାର ପରିବେଶ
  ଭେରିଏବଲ୍ଗୁଡ଼ିକୁ ପାଏ; ମାନିଫେଷ୍ଟ `env` ଅନୁମତି ଅନୁରୋଧ କଲେ ହିଁ ବ୍ୟାପକ ସେଟ୍ ପ୍ରଦାନ କରାଯାଏ।
- **ପଥ ପରିସୀମନ** — କୌଣସି କପି କିମ୍ବା ପୁନରାବୃତ୍ତିମୂଳକ ବିଲୋପ ପୂର୍ବରୁ, ଇନ୍ଷ୍ଟଲ୍/ଅପ୍ଗ୍ରେଡ୍/ଅନ୍ଇନ୍ଷ୍ଟଲ୍
  ପ୍ଲଗଇନ୍ ଡିରେକ୍ଟୋରୀ ଏବଂ `manifest.main` ପରିଚାଳିତ ପ୍ଲଗଇନ୍ ରୁଟ୍ର **ମଧ୍ୟରେ**
  ରିଜଲ୍ଭ ହେଉଥିବା ସୁନିଶ୍ଚିତ କରେ (ବିକୃତ DB ପଥ ଏବଂ `manifest.main`ରେ
  `../` ଟ୍ରାଭର୍ସାଲ୍ରୁ ସୁରକ୍ଷା ଦିଏ)। ସକ୍ରିୟକରଣ `realpath` ମାଧ୍ୟମରେ ସିମ୍ଲିଙ୍କ୍ଗୁଡ଼ିକୁ ରିଜଲ୍ଭ କରେ
  ଏବଂ ପ୍ଲଗଇନ୍ ଡିରେକ୍ଟୋରୀରୁ ବାହାରିଯାଉଥିବା ଏକ ଏଣ୍ଟ୍ରି ପଏଣ୍ଟ ଲୋଡ୍ କରିବାକୁ ମନା କରେ।
- **ଇଚ୍ଛାଧୀନ ଇଣ୍ଟେଗ୍ରିଟି ପିନ୍** — ଏକ ମାନିଫେଷ୍ଟ ଏକ `integrity`
  (`sha256-<base64>`, SRI ଫର୍ମାଟ୍) ଫିଲ୍ଡ ଘୋଷଣା କରିପାରେ। ଏହା ଉପସ୍ଥିତ ଥିଲେ, ଲୋଡର୍ ଲୋଡ୍ ସମୟରେ
  ଏଣ୍ଟ୍ରି ଫାଇଲ୍ର ହ୍ୟାସ୍ ଯାଞ୍ଚ କରେ ଏବଂ ଅମେଳ ହେଲେ ସକ୍ରିୟ କରିବାକୁ ମନା କରେ। ଏହା
  ଇଚ୍ଛାଧୀନ ବିକୃତି-ଚିହ୍ନଟ, **ସୁରକ୍ଷା ସୀମା ନୁହେଁ** — କେବଳ-ଲୁପ୍ବ୍ୟାକ୍ ରାଉଟିଂ
  ଏବଂ ଅନୁମତି ମଡେଲ୍ ହେଉଛି ପ୍ରକୃତ ସୀମା।

## ମାନିଫେଷ୍ଟ (`plugin.json`)

`PluginManifestSchema` (`src/lib/plugins/manifest.ts`) ଦ୍ୱାରା ବୈଧୀକୃତ:

| ଫିଲ୍ଡ              | ପ୍ରକାର    | ଟିପ୍ପଣୀ                                                            |
| ------------------ | --------- | ------------------------------------------------------------------ |
| `name`             | string    | ଆବଶ୍ୟକ; kebab-case (`^[a-z0-9-]+$`), 1–100 ଅକ୍ଷର                   |
| `version`          | string    | ଆବଶ୍ୟକ; semver (`MAJOR.MINOR.PATCH`)                               |
| `description`      | string?   | ≤ 500 ଅକ୍ଷର                                                        |
| `author`           | string?   | ≤ 200 ଅକ୍ଷର                                                        |
| `license`          | string?   | ଡିଫଲ୍ଟ ଭାବେ `MIT`                                                  |
| `main`             | string?   | ଏଣ୍ଟ୍ରି ଫାଇଲ୍; ଡିଫଲ୍ଟ ଭାବେ `index.js`                              |
| `source`           | enum?     | `local` \| `marketplace` (ଡିଫଲ୍ଟ ଭାବେ `local`)                     |
| `tags`             | string[]? | ସନ୍ଧାନ ଟ୍ୟାଗ୍                                                      |
| `requires`         | object?   | `{ omniroute?, permissions[] }`                                    |
| `hooks`            | object?   | ପ୍ଲଗଇନ୍ କେଉଁ ହୁକ୍ଗୁଡ଼ିକୁ ରୂପାୟନ କରେ ତାହା ଘୋଷଣା କରୁଥିବା ବୁଲିୟନ୍     |
| `skills`           | object[]? | ଇଚ୍ଛାଧୀନ ଦକ୍ଷତା ସଂଜ୍ଞାଗୁଡ଼ିକ                                       |
| `enabledByDefault` | boolean?  | ଇନ୍ଷ୍ଟଲ୍ ସମୟରେ ସ୍ୱୟଂଚାଳିତ ଭାବେ ସକ୍ରିୟ କରେ                          |
| `configSchema`     | object?   | ବିନ୍ୟାସ ଫିଲ୍ଡଗୁଡ଼ିକର ମ୍ୟାପ୍ (`string`/`number`/`boolean`/`select`) |
| `integrity`        | string?   | ଇଚ୍ଛାଧୀନ `sha256-<base64>` ଏଣ୍ଟ୍ରି-ଫାଇଲ୍ ପିନ୍                      |

ଅନୁମତିଗୁଡ଼ିକ
`network` / `file-read` / `file-write` / `env` / `exec` enumରୁ ନିଆଯାଏ।

## ଜୀବନଚକ୍ର ପ୍ରବାହ

```
install (POST /api/plugins, ପଥ)
  → manifest ସ୍କାନ୍/ବୈଧତା ଯାଞ୍ଚ → stagingକୁ କପି → main ଡିରେକ୍ଟୋରୀ ଭିତରେ ଥିବା ସୁନିଶ୍ଚିତ କରନ୍ତୁ
  → ପରମାଣବିକ ଭାବେ ~/.omniroute/plugins/<name>କୁ ନାମ ପରିବର୍ତ୍ତନ → DB ଧାଡ଼ି ଯୋଡ଼ନ୍ତୁ
  → onInstall ଚାଲୁ କରନ୍ତୁ → enabledByDefault ହେଲେ: ସକ୍ରିୟ କରନ୍ତୁ

activate (POST /api/plugins/{name}/activate)
  → realpath ସୀମାବଦ୍ଧତା ଯାଞ୍ଚ → loadPlugin() (child process ଆରମ୍ଭ କରନ୍ତୁ)
  → ଘୋଷିତ hooks ପଞ୍ଜୀକରଣ କରନ୍ତୁ → status = "active" → onActivate ଚାଲୁ କରନ୍ତୁ

deactivate (POST /api/plugins/{name}/deactivate)
  → onDeactivate ଚାଲୁ କରନ୍ତୁ (ପଞ୍ଜୀକରଣ ରଦ୍ଦ କରିବା ପୂର୍ବରୁ) → hooksର ପଞ୍ଜୀକରଣ ରଦ୍ଦ କରନ୍ତୁ
  → child process ବନ୍ଦ କରନ୍ତୁ → status = "inactive"

uninstall (DELETE /api/plugins/{name})
  → ସକ୍ରିୟ ଥିଲେ deactivate କରନ୍ତୁ → onUninstall ଚାଲୁ କରନ୍ତୁ
  → ସୀମାବଦ୍ଧତା-ଯାଞ୍ଚ ସହିତ plugin ଡିରେକ୍ଟୋରୀକୁ ପୁନରାବର୍ତ୍ତୀ ଭାବେ ଅପସାରଣ କରନ୍ତୁ → DB ଧାଡ଼ି ବିଲୋପ କରନ୍ତୁ
```

ଇନ୍ଷ୍ଟଲ୍ ହୋଇଥିବା ସଂସ୍କରଣଠାରୁ ଯେଉଁ ଡିରେକ୍ଟୋରୀର manifest ସଂସ୍କରଣ **କଠୋର ଭାବେ
ନୂତନ**, ସେହି ଡିରେକ୍ଟୋରୀ ଉପରେ `install` ପୁଣି ଚଲାଇଲେ ସ୍ୱୟଂଚାଳିତ ଭାବେ ଅପଗ୍ରେଡ୍ ହୁଏ (ସ୍ୱଚ୍ଛ ପୁନଃ-ଇନ୍ଷ୍ଟଲ୍; config
ଡିଫଲ୍ଟ ମୂଲ୍ୟକୁ ପୁନଃସେଟ୍ ହୁଏ)। ସମାନ କିମ୍ବା ପୁରୁଣା ସଂସ୍କରଣ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଏ।

## ଡ୍ୟାସ୍ବୋର୍ଡ

`/dashboard/plugins`ରେ ଥିବା ଡ୍ୟାସ୍ବୋର୍ଡ ପୃଷ୍ଠା
(`src/app/(dashboard)/dashboard/plugins/page.tsx`) ଦୁଇଟି ଟ୍ୟାବ୍ ପ୍ରଦାନ କରେ:

- **ଇନ୍ଷ୍ଟଲ୍ ହୋଇଥିବା** — ଇନ୍ଷ୍ଟଲ୍ ହୋଇଥିବା pluginsକୁ ସେମାନଙ୍କ ଘୋଷିତ hooks, ଏକ
  activate/deactivate ଟଗଲ୍, ଏକ uninstall ବଟନ୍ ଏବଂ ଏକ "plugins ପାଇଁ ସ୍କାନ୍ କରନ୍ତୁ"
  କାର୍ଯ୍ୟ (`POST /api/plugins/scan`) ସହିତ ତାଲିକାଭୁକ୍ତ କରେ।
- **ମାର୍କେଟ୍ପ୍ଲେସ୍** — ଏକ କଷ୍ଟମ୍ registry URL ସେଟ୍ କରିବା ପାଇଁ ଫିଲ୍ଡ ସହିତ
  `GET /api/plugins/marketplace`ରୁ catalog ଦେଖାଏ।

ପ୍ରତ୍ୟେକ plugin ପାଇଁ config ପୃଷ୍ଠା `/dashboard/plugins/[name]/config`ରେ ଅଛି
(`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`)।
