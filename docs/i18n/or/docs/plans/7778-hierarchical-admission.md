1. ବର୍ତ୍ତମାନର ଏକକ-key semaphore contract ଏବଂ ନୂତନ atomic multi-key
   contractକୁ କେନ୍ଦ୍ରିତ testଗୁଡ଼ିକ ସହିତ ସୁନିଶ୍ଚିତ କରନ୍ତୁ: କୌଣସି partial reservation ନୁହେଁ, FIFO queueing, abort,
   timeout, queue-full, idempotent release, stats, ଏବଂ cleanup।
2. ବର୍ତ୍ତମାନର account semaphoreକୁ ସେହି ସ୍ଥାନରେ generalize କରନ୍ତୁ। `acquire()`କୁ
   `acquireMany()` ଚାରିପାଖରେ ଏକ compatibility wrapper ଭାବରେ ରଖନ୍ତୁ; ଦ୍ୱିତୀୟ scheduler
   କିମ୍ବା dependency ଯୋଡ଼ନ୍ତୁ ନାହିଁ।
3. `chatCore`ର account-only acquisitionକୁ `withRateLimit`ର ଠିକ୍ ପୂର୍ବରୁ ଗୋଟିଏ cumulative
   global/provider/account acquisition ସହିତ ପ୍ରତିସ୍ଥାପନ କରନ୍ତୁ।
   account rotation ଦ୍ୱାରା connection ପରିବର୍ତ୍ତନ ହେଲେ ପ୍ରତିଥର ସମ୍ପୂର୍ଣ୍ଣ setକୁ ପୁନଃ acquire କରନ୍ତୁ,
   ଏବଂ streaming ସମ୍ପୂର୍ଣ୍ଣ ହେବା ପର୍ଯ୍ୟନ୍ତ releaseକୁ ଧରି ରଖନ୍ତୁ।
4. global
   ଏବଂ provider capଗୁଡ଼ିକ ସହିତ ବର୍ତ୍ତମାନର resilience settings pipeline (types, defaults,
   normalization, schema, API response, UI, ଏବଂ translations)କୁ ବିସ୍ତାର କରନ୍ତୁ। ପୁରୁଣା Bottleneck concurrency controlକୁ
   connection/quota-scope concurrency ଭାବରେ ପୁନଃ label କରନ୍ତୁ, ଯାହାଦ୍ୱାରା ଏହାର ପ୍ରକୃତ scope ସ୍ପଷ୍ଟ ହୁଏ।
5. କେନ୍ଦ୍ରିତ test, lint, typecheck, static check, ଏବଂ ସମ୍ପୂର୍ଣ୍ଣ test suite ଚଲାନ୍ତୁ;
   behavioral ପରିବର୍ତ୍ତନକୁ changelogରେ document କରନ୍ତୁ।

ଉଦ୍ଦେଶ୍ୟମୂଳକ ଭାବେ ସଂରକ୍ଷିତ behavior: zero/null concurrency ଗୋଟିଏ gateକୁ bypass କରେ,
account-only callerମାନେ `acquire()` ବ୍ୟବହାର ଜାରି ରଖନ୍ତି, blocked-account controlଗୁଡ଼ିକ
ସେମାନଙ୍କର key format ଏବଂ APIକୁ ଅପରିବର୍ତ୍ତିତ ରଖନ୍ତି, ଏବଂ provider rate-limit queue behavior
ଅପରିବର୍ତ୍ତିତ ରହେ।
