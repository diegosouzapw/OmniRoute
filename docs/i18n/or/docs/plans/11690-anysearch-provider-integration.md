## 1. ସେବାର ପ୍ରାମାଣିକ ତଥ୍ୟ (ଆଧିକାରିକ ଡକ୍ୟୁମେଣ୍ଟେସନ୍, ପରସ୍ପର ଯାଞ୍ଚିତ)

- ବେସ୍ URL: `https://api.anysearch.com` (REST) + `POST /mcp` (MCP, JSON-RPC 2.0)।
- `POST /v1/search` - ପାରାମିଟର୍ଗୁଡ଼ିକ: `query` (ଆବଶ୍ୟକ), `max_results` (1-10, ଡିଫଲ୍ଟ 10), `tag` (`{domain}.{sub_domain}` ଭର୍ଟିକାଲ୍ ରାଉଟିଂ), `zone` (cn/intl), `language`, `params` (ସଂରଚିତ ଭର୍ଟିକାଲ୍ ଫିଲ୍ଡଗୁଡ଼ିକ), `format` (json/markdown)।
- `GET /v1/sub-domains?domain=...` - କ୍ଷମତା କ୍ୟାଟାଲଗ୍, କୋଟାରେ ଗଣନା ହୁଏ ନାହିଁ।
- `POST /v1/extract` - `{url, title, content}` ଫେଚ୍/ଏକ୍ସଟ୍ରାକ୍ଟ କରେ; କଠୋର JSON ବଡି, 16 KiB ସୀମା।
- `POST /v1/auth/email/register` - ଏକକ-କଲ୍ ପଞ୍ଜୀକରଣ, ଏକକାଳୀନ ପ୍ଲେନ୍ଟେକ୍ସ୍ଟ କୀ `as_sk_...` ଫେରାଏ।
- ପ୍ରମାଣୀକରଣ: ଇଚ୍ଛାଧୀନ `Authorization: Bearer <as_sk_...>`; ଅଜ୍ଞାତନାମା ଅନୁରୋଧଗୁଡ଼ିକ ଦୈନିକ ମାଗଣା କୋଟା ବ୍ୟବହାର କରୁଥିବା ପ୍ରତି-IP ସୀମାକୁ ଅବନମିତ ହୁଏ; ଅବୈଧ କୀ 401/403 ଫେରାଏ ଏବଂ କୌଣସି ନିରବ ଅଜ୍ଞାତନାମା ଫଲ୍ବ୍ୟାକ୍ ହୁଏ ନାହିଁ।
- ମାଗଣା ସ୍ତର: ପ୍ରତିଦିନ 1000ଟି ଅନୁରୋଧ, ପ୍ରତି କୀ ପାଇଁ 20 QPS। ଦେୟ ସ୍ତର: ମୂଲ୍ୟ ନିର୍ଦ୍ଧାରିତ ହୋଇନାହିଁ (ଶୀଘ୍ର ଆସୁଛି)।
- ପ୍ରତିକ୍ରିୟା ଏନ୍ଭେଲୋପ୍: ସଫଳତା `{code: 0, message: "success", request_id, data}`; ବିଫଳତା `{code: -1, message}`। ପ୍ରମାଣୀକରଣ/କୋଟା ତ୍ରୁଟିଗୁଡ଼ିକରେ ସଂରଚିତ `error_code` ନଥାଏ (`message` ଟେକ୍ସ୍ଟ ହିଁ ସଙ୍କେତ); ଏକ୍ସଟ୍ରାକ୍ଟ-ନିର୍ଦ୍ଦିଷ୍ଟ ତ୍ରୁଟିଗୁଡ଼ିକରେ `error_code` (`invalid_extract_url`, `extract_failed`) ଥାଏ। 429 ରେ କୌଣସି `Retry-After` ହେଡର୍ ନାହିଁ।

## 3. ସିଦ୍ଧାନ୍ତଗୁଡ଼ିକ (ସମସ୍ତ ସିଦ୍ଧାନ୍ତ 2026-08-26 ରେ ନିଆଯାଇଛି)

1. **ରାଉଟିଂ ଧାରା: `fallbackOnly`।** ଯୁକ୍ତି: cost-0 ମାଗଣା ପ୍ରଦାତା କେବେବି ସ୍ୱୟଂଚାଳିତ ମୂଲ୍ୟ-ଆଧାରିତ ରାଉଟିଂରେ ପ୍ରାଧାନ୍ୟ ପାଇବା ଉଚିତ ନୁହେଁ; ସ୍ପଷ୍ଟ ଚୟନ ଏବଂ ଫେଲଓଭର୍ ରିଟର୍ନ ଅପରିବର୍ତ୍ତିତ ରହିବ। ପୂର୍ବ ଉଦାହରଣ: ମର୍ଜ୍ ହୋଇଥିବା xquik ଏଣ୍ଟ୍ରି।
2. **ପରିସର: v1 ରେ `POST /v1/extract` ମାଧ୍ୟମରେ webSearch + webFetch।** tavily/exa ର ଦ୍ୱୈତ-କ୍ଷମତା ମାନସିକ ମଡେଲ୍ ସହ ସମନ୍ୱିତ। ଭର୍ଟିକାଲ୍ ସର୍ଫେସ୍ଗୁଡ଼ିକ (`tag`, `sub-domains`, `batch_search`) ପରିସର ବାହାରେ ରହିବ — ବର୍ତ୍ତମାନ ଭର୍ଟିକାଲ୍ ପାରାମିଟର୍ଗୁଡ଼ିକ ପାଇଁ କୌଣସି IR ନାହିଁ।
3. **କୋଟା ପ୍ରଦର୍ଶନ: `freeMonthlyQuota: 0`** (xquik-ଶୈଳୀର ରକ୍ଷଣଶୀଳ ପ୍ରଦର୍ଶନ)। ପ୍ରକୃତ ସୀମା (1000 ଅନୁରୋଧ/ଦିନ, ଦୈନିକ ରିସେଟ୍) ପରିବର୍ତ୍ତେ UI କ୍ୟାଟାଲଗ୍ର `authHint` କପିରେ ଦିଆଯାଇଛି। ଯୁକ୍ତି: କୋଟା ପ୍ରଦର୍ଶନ ରିସେଟ୍ ସେମାଣ୍ଟିକ୍ସ ସହ ମେଳ ଖାଇବା ଆବଶ୍ୟକ; ଏକ ଦୈନିକ ସୀମାକୁ ମାସିକ-ସମତୁଲ୍ୟ (30000)ରେ ରୂପାନ୍ତର କରିବା ହେଉଛି ଏକ ମିଥ୍ୟା ପ୍ରତିଶ୍ରୁତି, ଯାହାକୁ UI ପୂରଣ କରିପାରିବ ନାହିଁ।
4. **searchTypes: କେବଳ `["web"]`।** AnySearch API ରେ news/images ଭର୍ଟିକାଲ୍ର କୌଣସି ସାର୍ବଜନିକ ପ୍ରମାଣ ନାହିଁ; ଡକ୍ୟୁମେଣ୍ଟ କରାଯାଇନଥିବା ଭର୍ଟିକାଲ୍ ସହିତ API ଏକୀକୃତ କରୁଥିବା ଗେଟୱେଗୁଡ଼ିକ (ଯଥା Google Custom Search), news -> web କୁ ନିରବରେ ମ୍ୟାପ୍ କରିବା ପରିବର୍ତ୍ତେ କେବଳ web କୁ ଉନ୍ମୁକ୍ତ କରନ୍ତି।
5. **କୀ ଧାରା:** କୀ ବିନା କାମ କରେ; ଏକ ଅବୈଧ କୀ 401/403 ଫେରାଏ ଏବଂ ଏହାକୁ କେବେବି ନିରବରେ ଅଜ୍ଞାତ ମୋଡ୍କୁ ଅବନମିତ କରାଯାଏ ନାହିଁ (ଅପସ୍ଟ୍ରିମ୍ ଚୁକ୍ତିକୁ ଅନୁସରଣ କରେ)।
6. **ସଚେତନ ବହିଷ୍କାରଗୁଡ଼ିକ:** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (ଚାଟ୍ ଇଣ୍ଟରସେପ୍ସନ୍ firecrawl/jina/tavily ରେ ରହିବ); `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (ଅଜ୍ଞାତ ରିମୋଟ୍ ଏଣ୍ଡପଏଣ୍ଟଗୁଡ଼ିକ ପ୍ରତି egress IP ପାଇଁ ଗୋଟିଏ IP-ସୀମିତ ପୁଲ୍ ସେୟାର୍ କରନ୍ତି, ତେଣୁ କୀବିହୀନ extract ହେଉଛି opt-in, ସ୍ୱୟଂଚାଳିତ ରାଉଟିଂ ପ୍ରାର୍ଥୀ ନୁହେଁ); `QUOTA_STATUS_PROVIDERS` (AnySearch 402/403 ସ୍ଥିତି ନୁହେଁ, ବରଂ 429/envelope ମାଧ୍ୟମରେ କୋଟା ସଙ୍କେତ ଦିଏ)।
