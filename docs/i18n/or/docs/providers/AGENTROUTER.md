[AgentRouter](https://agentrouter.org) ହେଉଛି ଏକ Anthropic-ସୁସଙ୍ଗତ ରିଲେ, ଯାହା Claude ଏବଂ ଅନ୍ୟ ମଡେଲ୍ଗୁଡ଼ିକୁ ପୁନଃବିକ୍ରୟ କରେ,
ପ୍ରାୟତଃ ସିଧାସଳଖ Anthropic API ତୁଳନାରେ କମ୍ ମୂଲ୍ୟରେ। ଏହାକୁ ଅଧିକୃତ Claude Code
କ୍ଲାଏଣ୍ଟ ପାଇଁ ଏକ ଡ୍ରପ୍-ଇନ୍ `ANTHROPIC_BASE_URL` ପ୍ରତିସ୍ଥାପନ ଭାବେ ଡିଜାଇନ୍ କରାଯାଇଛି,
ତେଣୁ ଏହା କେବଳ Claude Code ୱାୟାର୍ ଇମେଜ୍ ସହ ମେଳ ଖାଉଥିବା ଟ୍ରାଫିକ୍କୁ ଗ୍ରହଣ କରେ (ନିର୍ଦ୍ଦିଷ୍ଟ
User-Agent, `anthropic-beta` ଫ୍ଲାଗ୍ଗୁଡ଼ିକ, Stainless SDK ହେଡର୍ଗୁଡ଼ିକ ଇତ୍ୟାଦି)।

## ଦ୍ରୁତ ଆରମ୍ଭ — ନେଟିଭ୍ `agentrouter` ପ୍ରଦାନକାରୀ ବ୍ୟବହାର କରନ୍ତୁ (ସୁପାରିଶକୃତ)

ଅଧିକାଂଶ ବ୍ୟବହାରକାରୀଙ୍କ ପାଇଁ, **କୌଣସି ବିଶେଷ ସେଟଅପ୍ର ଆବଶ୍ୟକତା ନାହିଁ**। OmniRoute ସମ୍ପୂର୍ଣ୍ଣ Claude Code
ୱାୟାର୍ ଇମେଜ୍ ପୂର୍ବରୁ ଅନ୍ତର୍ନିହିତ ଥିବା ଏକ ବିଲ୍ଟ-ଇନ୍ `agentrouter` ପ୍ରଦାନକାରୀ ସହିତ ଆସେ (ଦେଖନ୍ତୁ
`open-sse/config/providerRegistry.ts` → `agentrouter`)। ଏହାକୁ ବ୍ୟବହାର କରିବା ପାଇଁ:

1. **Dashboard → Providers → Add Provider** ଖୋଲନ୍ତୁ।
2. ତାଲିକାରୁ **AgentRouter** ଚୟନ କରନ୍ତୁ।
3. ଆପଣଙ୍କ `sk-...` API କୀ ପେଷ୍ଟ କରି ସେଭ୍ କରନ୍ତୁ।

ବସ୍ ଏତିକି — କୌଣସି ଏନଭାୟରନମେଣ୍ଟ ଭେରିଏବଲ୍ କିମ୍ବା କଷ୍ଟମ୍ ପ୍ରଦାନକାରୀ ପ୍ରକାର ଆବଶ୍ୟକ ନାହିଁ। ବିଲ୍ଟ-ଇନ୍ ମଡେଲ୍ଗୁଡ଼ିକ ମଧ୍ୟରେ
`claude-opus-4-6`, `claude-haiku-4-5-20251001`, `glm-5.1`, ଏବଂ
`deepseek-v3.2` ଅନ୍ତର୍ଭୁକ୍ତ।

ଏହି ଗାଇଡ୍ର ଅବଶିଷ୍ଟ ଅଂଶରେ **ଉନ୍ନତ ପଦ୍ଧତି** ଅନ୍ତର୍ଭୁକ୍ତ:
`anthropic-compatible-cc-*` ପ୍ରଦାନକାରୀ ପ୍ରକାର ବ୍ୟବହାର କରିବା। ୱାୟାର୍ ଇମେଜ୍ ଉପରେ ଅଧିକ ନିୟନ୍ତ୍ରଣ
ଆବଶ୍ୟକ ହେଲେ ଏହାକୁ ବ୍ୟବହାର କରନ୍ତୁ — ଉଦାହରଣ ସ୍ୱରୂପ, ନେଟିଭ୍ ପ୍ରଦାନକାରୀ ରେଜିଷ୍ଟ୍ରିରେ ଏପର୍ଯ୍ୟନ୍ତ
ନଥିବା ଅନ୍ୟ AgentRouter-ଶୈଳୀର ରିଲେଗୁଡ଼ିକ ସହ ସଂଯୋଗ କରିବା ବେଳେ, କିମ୍ବା
ବେସ୍ URL, ଚାଟ୍ ପାଥ୍ କିମ୍ବା ହେଡର୍ ସେଟ୍କୁ ଓଭରରାଇଡ୍ କରିବା ବେଳେ।

## ଉନ୍ନତ: Claude Code ସୁସଙ୍ଗତ ପ୍ରଦାନକାରୀ ପ୍ରକାର ମାଧ୍ୟମରେ ସଂଯୋଗ କରିବା

OmniRoute, **Claude Code ସୁସଙ୍ଗତ** ପ୍ରଦାନକାରୀ ପ୍ରକାର (`anthropic-compatible-cc-*`) ମାଧ୍ୟମରେ
AgentRouter (ଏବଂ ସମାନ ରିଲେଗୁଡ଼ିକ)କୁ ମଧ୍ୟ ସମର୍ଥନ କରେ, ଯାହା ସଠିକ୍ ୱାୟାର୍ ଇମେଜ୍ ସହିତ
Anthropic Messages API ବ୍ୟବହାର କରେ। `https://agentrouter.org`କୁ ପଏଣ୍ଟ୍ କରୁଥିବା ଏକ ସାଧାରଣ
`openai-compatible-chat` ପ୍ରଦାନକାରୀ **କାମ କରିବ ନାହିଁ** — Claude
Code ଭଳି ଦେଖାଯାଉ ନଥିବା ଅନୁରୋଧଗୁଡ଼ିକୁ ଅପ୍ଷ୍ଟ୍ରିମ୍ WAF ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ।

## ପୂର୍ବାବଶ୍ୟକତା

- ଏକ AgentRouter ଆକାଉଣ୍ଟ ଏବଂ API କୀ। ନୂତନ ସାଇନ୍ଅପ୍ଗୁଡ଼ିକ ପ୍ରକଳ୍ପର [README](../README.md)ରେ ଥିବା ଆଫିଲିଏଟ୍
  ଲିଙ୍କ୍ ମାଧ୍ୟମରେ ମାଗଣା କ୍ରେଡିଟ୍ ପାଆନ୍ତି।
- `ENABLE_CC_COMPATIBLE_PROVIDER` ଫିଚର୍ ଫ୍ଲାଗ୍ ସକ୍ଷମ ଥିବା ଅବସ୍ଥାରେ OmniRoute ଚାଲୁଥିବା ଆବଶ୍ୟକ
  (ନିମ୍ନରେ ଦେଖନ୍ତୁ)।

## 1. CC-ସୁସଙ୍ଗତ ପ୍ରଦାନକାରୀ ପ୍ରକାରକୁ ସକ୍ଷମ କରନ୍ତୁ

Claude Code ସୁସଙ୍ଗତ ପ୍ରଦାନକାରୀ ପ୍ରକାର ଏକ ଫିଚର୍ ଫ୍ଲାଗ୍ ପଛରେ ରହିଛି, କାରଣ ଏହା
ଅଧିକୃତ Claude Code କ୍ଲାଏଣ୍ଟକୁ ଅତି ନିକଟରୁ ଅନୁକରଣ କରୁଥିବା ଟ୍ରାଫିକ୍ ପଠାଏ। OmniRoute ଆରମ୍ଭ କରିବା ପୂର୍ବରୁ
ଏକ ଏନଭାୟରନମେଣ୍ଟ ଭେରିଏବଲ୍ ସେଟ୍ କରି ଏହାକୁ ସକ୍ଷମ କରନ୍ତୁ:

```bash
ENABLE_CC_COMPATIBLE_PROVIDER=true
```

Docker ଉଦାହରଣ:

```bash
docker run -d --name omniroute \
  --restart unless-stopped \
  -p 20128:20128 \
  -v omniroute-data:/app/data \
  -e ENABLE_CC_COMPATIBLE_PROVIDER=true \
  diegosouzapw/omniroute:latest
```

ପୁନଃଆରମ୍ଭ କରିବା ପରେ, ଡ୍ୟାସ୍ବୋର୍ଡ ବିଦ୍ୟମାନ OpenAI-ସୁସଙ୍ଗତ ଏବଂ Anthropic-ସୁସଙ୍ଗତ ପ୍ରବାହଗୁଡ଼ିକ ସହିତ
ଏକ **Add Claude Code Compatible** ବିକଳ୍ପ ପ୍ରଦର୍ଶନ କରେ।

## 2. ଡ୍ୟାସ୍ବୋର୍ଡରେ ପ୍ରଦାନକାରୀ ସୃଷ୍ଟି କରନ୍ତୁ

1. **Dashboard → Providers → Add Provider** ଖୋଲନ୍ତୁ।
2. **Add Claude Code Compatible** ଚୟନ କରନ୍ତୁ (କେବଳ ଉପରୋକ୍ତ ଫ୍ଲାଗ୍ ସେଟ୍ ଥିଲେ ଦୃଶ୍ୟମାନ ହୁଏ)।
3. ଫିଲ୍ଡଗୁଡ଼ିକ ପୂରଣ କରନ୍ତୁ:

| ଫିଲ୍ଡ     | ମୂଲ୍ୟ                                                                      |
| --------- | -------------------------------------------------------------------------- |
| ନାମ       | `AgentRouter` (କିମ୍ବା ଯେକୌଣସି ଲେବଲ୍)                                       |
| ପ୍ରିଫିକ୍ସ | `agentrouter` (ଲଗ୍ ଏବଂ ଡ୍ୟାସ୍ବୋର୍ଡରେ ଦେଖାଯାଉଥିବା ବ୍ୟବହାରକାରୀ-ଅନୁକୂଳ ଉପନାମ) |
| ବେସ୍ URL  | `https://agentrouter.org`                                                  |
| ଚାଟ୍ ପାଥ୍ | `/v1/messages?beta=true` (ଡିଫଲ୍ଟ — ଅପରିବର୍ତ୍ତିତ ରଖନ୍ତୁ)                    |

> କ୍ୟାନୋନିକାଲ୍ ମଡେଲ୍ ପରିଚାୟକ ଏବେ ମଧ୍ୟ ସମ୍ପୂର୍ଣ୍ଣ ପ୍ରଦାନକାରୀ ନୋଡ୍ ID
> (`anthropic-compatible-cc-{uuid}/{model}`) ବ୍ୟବହାର କରେ। **ପ୍ରିଫିକ୍ସ** କେବଳ ଅଧିକ ବ୍ୟବହାରକାରୀ-ଅନୁକୂଳ ଲଗ୍ ଆଉଟ୍ପୁଟ୍ ପାଇଁ
> `src/lib/usage/callLogs.ts` ଦ୍ୱାରା ରିଜଲ୍ଭ କରାଯାଉଥିବା ଏକ ପ୍ରଦର୍ଶନ ଉପନାମ।

4. (ଇଚ୍ଛାଧୀନ) ଆପଣଙ୍କ API କୀକୁ **Validate** ଫିଲ୍ଡରେ ପେଷ୍ଟ କରନ୍ତୁ ଏବଂ ସେଭ୍ କରିବା ପୂର୍ବରୁ
   ସଂଯୋଗକ୍ଷମତା ନିଶ୍ଚିତ କରିବା ପାଇଁ **Check** କ୍ଲିକ୍ କରନ୍ତୁ।
5. **Add** କ୍ଲିକ୍ କରନ୍ତୁ।

ସୃଷ୍ଟି ହୋଇଗଲା ପରେ, ପ୍ରଦାନକାରୀକୁ ଖୋଲନ୍ତୁ ଏବଂ ଆପଣଙ୍କ AgentRouter API
କୀ (`sk-...`) ସହିତ ଏକ **Connection** ଯୋଡ଼ନ୍ତୁ। ସଂଯୋଗର `test_status` `active` ହେବା ଉଚିତ।

## 3. କମ୍ବୋ ମାଧ୍ୟମରେ କିମ୍ବା ସିଧାସଳଖ ଏହାକୁ ବ୍ୟବହାର କରନ୍ତୁ

ଆପଣଙ୍କ ପ୍ରଦାନକାରୀଙ୍କ ପ୍ରିଫିକ୍ସକୁ ନେମସ୍ପେସ୍ ଭାବେ ବ୍ୟବହାର କରି ମଡେଲ୍କୁ ସନ୍ଦର୍ଭ କରନ୍ତୁ:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "agentrouter/claude-opus-4-6",
    "messages": [{"role": "user", "content": "hello"}],
    "max_tokens": 100
  }'
```

କ୍ୟାନୋନିକାଲ୍ ମଡେଲ୍ ID `anthropic-compatible-cc-{uuid}/claude-opus-4-6` ମଧ୍ୟ କାମ କରେ
ଏବଂ ଏହାହିଁ ଡାଟାବେସ୍ ଓ କମ୍ବୋ କନଫିଗରେସନ୍ରେ ଦେଖାଯାଏ।

କିମ୍ବା ଅନ୍ୟ ଯେକୌଣସି ପ୍ରଦାନକାରୀ ପରି ରାଉଟିଂ, ଫଲ୍ବ୍ୟାକ୍ ଏବଂ କୋଟା ପରିଚାଳନା ପାଇଁ ଏହାକୁ ଏକ କମ୍ବୋରେ

## ସମସ୍ୟା ସମାଧାନ

**`{"error":{"message":"unauthorized client detected, ..."}}`** — ଆପଣଙ୍କ ଅନୁରୋଧ
Claude Code ୱାୟାର୍ ଇମେଜ୍ ସହ ମେଳ ଖାଇଲା ନାହିଁ। ପ୍ରଦାନକାରୀଙ୍କୁ
`anthropic-compatible-cc` ପରିବର୍ତ୍ତେ `openai-compatible-chat` ଭାବେ କନଫିଗର୍ କରାଯାଇଥିଲେ, କିମ୍ବା
ଷ୍ଟାର୍ଟଅପ୍ ସମୟରେ `ENABLE_CC_COMPATIBLE_PROVIDER=true` ଫ୍ଲାଗ୍ ସେଟ୍ କରାଯାଇ ନଥିଲେ ଏହା ଘଟେ।

**`{"error":{"message":"无效的令牌","type":"new_api_error"}}` (HTTP 401)** —
"ଅବୈଧ ଟୋକନ୍"। ୱାୟାର୍ ଇମେଜ୍ ସଠିକ୍, କିନ୍ତୁ API କି ପ୍ରତ୍ୟାଖ୍ୟାନ ହୋଇଛି। AgentRouter ଡ୍ୟାସ୍ବୋର୍ଡରେ ଏକ
ନୂଆ କି ସୃଷ୍ଟି କରନ୍ତୁ ଏବଂ କନେକ୍ସନ୍କୁ ଅପଡେଟ୍ କରନ୍ତୁ।

**`{"error":{"code":"content-blocked","type":"agent_router_api_error"}}`
(HTTP 400)** — AgentRouterର ମଡରେସନ୍ ହୁକ୍ ଅନୁରୋଧର ବିଷୟବସ୍ତୁକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରିଛି, କିମ୍ବା
କିର ପ୍ଲାନ୍ ଅନୁରୋଧ କରାଯାଇଥିବା ମଡେଲ୍କୁ ଅନୁମତି ଦିଏ ନାହିଁ। ଅନ୍ୟ ଏକ ପ୍ରମ୍ପ୍ଟ କିମ୍ବା ମଡେଲ୍ ଚେଷ୍ଟା କରନ୍ତୁ;
କୌଣସି ନିର୍ଦ୍ଦୋଷ ପ୍ରମ୍ପ୍ଟ ଲଗାତାର ବ୍ଲକ୍ ହେଉଥିଲେ AgentRouter ସହାୟତା ଦଳ ସହ ଯୋଗାଯୋଗ କରନ୍ତୁ।

**କେବଳ ନିର୍ଦ୍ଦିଷ୍ଟ ମଡେଲ୍ଗୁଡ଼ିକରେ `[400]: content-blocked`** — ଅଧିକାଂଶ AgentRouter ପ୍ଲାନ୍ କେବଳ
ମଡେଲ୍ଗୁଡ଼ିକର ଏକ ଉପସେଟ୍କୁ (ଯଥା `claude-opus-4-6`) ଅନୁମତି ଦିଏ। କି ବୈଧ ହୋଇଥିଲେ ମଧ୍ୟ ଅନ୍ୟ ମଡେଲ୍ IDଗୁଡ଼ିକ
`unauthorized_client_error` ଫେରାଇଥାଏ। AgentRouter ଡ୍ୟାସ୍ବୋର୍ଡରେ ଆପଣଙ୍କ
ପ୍ଲାନ୍ କେଉଁ ମଡେଲ୍ଗୁଡ଼ିକୁ ଅନ୍ତର୍ଭୁକ୍ତ କରେ ଯାଞ୍ଚ କରନ୍ତୁ।

**omniroute ଲଗ୍ଗୁଡ଼ିକରେ `Invalid JSON response from provider (reset after Ns)`** —
ଅପ୍ଷ୍ଟ୍ରିମ୍ ଏକ ଅଣ-JSON ବଡି ଫେରାଇଛି (ସାଧାରଣତଃ WAFରୁ ଏକ HTML ତ୍ରୁଟି ପୃଷ୍ଠା)।
ସାଧାରଣତଃ ଏହାର ଅର୍ଥ ଅନୁରୋଧଟି କେବେବି AgentRouter ବ୍ୟାକ୍ଏଣ୍ଡରେ ପହଞ୍ଚି ନଥିଲା — ପ୍ରଦାନକାରୀ ID
`anthropic-compatible-cc-`ରୁ ଆରମ୍ଭ ହେଉଛି କି ନାହିଁ ପୁନଃଯାଞ୍ଚ କରନ୍ତୁ (ଶେଷ ଡ୍ୟାସ୍ଟି ଧ୍ୟାନ ଦିଅନ୍ତୁ —
`open-sse/services/claudeCodeCompatible.ts`ରେ `CLAUDE_CODE_COMPATIBLE_PREFIX` ଦେଖନ୍ତୁ)
ଏବଂ ଫିଚର୍ ଫ୍ଲାଗ୍ ସକ୍ଷମ ଅଛି କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ।

**ଏକ AgentRouter ପ୍ରଦାନକାରୀ ପୂର୍ବରୁ ଥିବା ସତ୍ତ୍ୱେ `unauthorized client detected` / HTML ତ୍ରୁଟି ପୃଷ୍ଠା** — ସମ୍ଭବତଃ ଆପଣଙ୍କ ପାଖରେ **ଏକରୁ ଅଧିକ** AgentRouter ପ୍ରଦାନକାରୀ ଅଛନ୍ତି
ଏବଂ ଆପଣଙ୍କ ଅନୁରୋଧ ଭୁଲ୍ ପ୍ରଦାନକାରୀ ପାଖକୁ ଯାଉଛି। ଯଦି `agentrouter` ପ୍ରିଫିକ୍ସ ସହ
କୌଣସି ଅବଶିଷ୍ଟ ହାତରେ ତିଆରି କରାଯାଇଥିବା `anthropic-compatible-*` (ଅଣ-`cc`) କିମ୍ବା `openai-compatible-chat-*` ପ୍ରଦାନକାରୀ
ସୃଷ୍ଟି କରାଯାଇଥିଲା, ତେବେ ଏହା `agentrouter/<model>` ମଡେଲ୍
IDଗୁଡ଼ିକୁ ନିଜ ଅଧୀନରେ ରଖିପାରେ (ଏବଂ କମ୍ବୋଗୁଡ଼ିକ ଏହାକୁ ନୋଡ୍ ID ଦ୍ୱାରା ସନ୍ଦର୍ଭ କରିପାରନ୍ତି), ଫଳରେ ଟ୍ରାଫିକ୍ ସଠିକ୍ ୱାୟାର୍ ଇମେଜ୍ ସହ ପୂର୍ବରୁ ଆସୁଥିବା ବିଲ୍ଟ-ଇନ୍
`agentrouter` ପ୍ରଦାନକାରୀ ପରିବର୍ତ୍ତେ ସେହି ପ୍ରଦାନକାରୀ ପାଖକୁ ରାଉଟ୍ ହୁଏ —
ଯାହା ଏକ ସାଧାରଣ User-Agent ପଠାଏ ଏବଂ ପ୍ରତ୍ୟାଖ୍ୟାନ ହୁଏ। omniroute ଲଗ୍ଗୁଡ଼ିକରେ ମଡେଲ୍ଟି
ପ୍ରକୃତରେ କେଉଁଠାରେ ରିଜଲ୍ଭ ହୁଏ ଯାଞ୍ଚ କରନ୍ତୁ (`ROUTING` ଟ୍ୟାଗ୍
`agentrouter/<model> → <providerId>/<model>` ଦେଖାଏ); ଯଦି `<providerId>`
`agentrouter` ନୁହେଁ, ତେବେ ନେଟିଭ୍ ପ୍ରଦାନକାରୀ ଉପରେ ଏକୀକୃତ କରନ୍ତୁ: କମ୍ବୋଗୁଡ଼ିକୁ
`agentrouter/<model>` (providerId `agentrouter`) ଆଡ଼କୁ ନିର୍ଦ୍ଦେଶ କରନ୍ତୁ ଏବଂ ଡୁପ୍ଲିକେଟ୍
କମ୍ପାଟିବଲ୍ ପ୍ରଦାନକାରୀଗୁଡ଼ିକୁ ଡିଲିଟ୍ କରନ୍ତୁ। ନେଟିଭ୍ ପ୍ରଦାନକାରୀ ପାଇଁ କୌଣସି ୱାୟାର୍-ଇମେଜ୍ କନଫିଗରେସନ୍ କିମ୍ବା
`customUserAgent` ଆବଶ୍ୟକ ନାହିଁ।
