`copilot-m365-web` (ଛଦ୍ମନାମ `m365copilot`) ଏକ ପ୍ରମାଣୀକୃତ Microsoft 365 Copilot BizChat ବ୍ରାଉଜର୍ ସେସନ୍ ମାଧ୍ୟମରେ
`m365.cloud.microsoft/chat`କୁ OpenAI-ଫର୍ମାଟ୍ ଚାଟ୍ ଅନୁରୋଧ ପଠାଏ। ଏହା ଏକ ଅନୌପଚାରିକ ଇଣ୍ଟିଗ୍ରେସନ୍।

> **Web Cookie ପ୍ରଦାନକାରୀଙ୍କ ପାଇଁ ନୂଆ?**
>
> ଏହି ପ୍ରଦାନକାରୀ-ନିର୍ଦ୍ଦିଷ୍ଟ ଗାଇଡ୍ ଅନୁସରଣ କରିବା ପୂର୍ବରୁ ସାଧାରଣ ସେଟଅପ୍ ପ୍ରକ୍ରିୟା, ପ୍ରମାଣୀକରଣ ମାର୍ଗଦର୍ଶନ, ସୀମାବଦ୍ଧତା ଏବଂ ସମସ୍ୟା ସମାଧାନ ପାଇଁ
> **`docs/getting-started/WEB-COOKIE-GUIDE.md`** ପଢ଼ନ୍ତୁ।
>
> **ଗୁରୁତ୍ୱପୂର୍ଣ୍ଣ:** ଏହି ପ୍ରଦାନକାରୀଙ୍କ କ୍ରେଡେନ୍ସିଆଲ୍ **କୁକି ନୁହେଁ**। `m365.cloud.microsoft`ରୁ
> କୁକିଗୁଡ଼ିକ କପି କରନ୍ତୁ ନାହିଁ। କ୍ରେଡେନ୍ସିଆଲ୍ ହେଉଛି ଏକ WebSocket URL କ୍ୱେରୀ
> ପାରାମିଟର୍ ଏବଂ ପାଥ୍ ସେଗମେଣ୍ଟ୍, ଯାହା ଉଭୟ DevTools Network ଟ୍ୟାବ୍ରୁ ପଢ଼ାଯାଏ।

## ପୂର୍ବାବଶ୍ୟକତା

- `m365.cloud.microsoft/chat`ରେ BizChat ଆକ୍ସେସ୍ ଥିବା ଏକ Microsoft 365 ଆକାଉଣ୍ଟ୍
- DevTools WebSocket ଯାଞ୍ଚ ପାଇଁ ଏକ Chromium-ଆଧାରିତ ବ୍ରାଉଜର୍ (Chrome, Edge)
- ଏକ M365 Copilot ଲାଇସେନ୍ସ (ଅନେକ Microsoft 365 Business/Enterprise ପ୍ଲାନ୍ରେ ଅନ୍ତର୍ଭୁକ୍ତ)

## କ୍ରେଡେନ୍ସିଆଲ୍ ସଂଗ୍ରହ (WebSocket ପଦ୍ଧତି)

1. `https://m365.cloud.microsoft/chat`ରେ ସାଇନ୍ ଇନ୍ କରି ଏକ ବାର୍ତ୍ତାଳାପ ଆରମ୍ଭ କରନ୍ତୁ।
2. **DevTools → Network** ଖୋଲନ୍ତୁ।
3. **WS** (WebSocket) ଦ୍ୱାରା ଫିଲ୍ଟର୍ କରନ୍ତୁ।
4. Chathub WebSocket କନେକ୍ସନ୍ରେ କ୍ଲିକ୍ କରନ୍ତୁ। ନିମ୍ନଲିଖିତ ଭାବେ ଆରମ୍ଭ ହେଉଥିବା ଏକ URL ଖୋଜନ୍ତୁ
   `wss://substrate.office.com/m365Copilot/Chathub/`।
5. ଏହାର **Request URL**ରୁ ନିମ୍ନଲିଖିତଗୁଡ଼ିକ କପି କରନ୍ତୁ:
   - `access_token` କ୍ୱେରୀ ପାରାମିଟର୍ ମୂଲ୍ୟ (ଏକ ସ୍ୱଳ୍ପକାଳୀନ JWT)।
   - `/Chathub/` ପରେ ଥିବା Chathub ପାଥ୍ ସେଗମେଣ୍ଟ୍ (ଉଦାହରଣ ସ୍ୱରୂପ `<oid>@<tenant>`)।

ସମ୍ପୂର୍ଣ୍ଣ URLର ଫର୍ମ ହେଉଛି:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRouteରେ, **Providers → Add Provider**କୁ ଯାଆନ୍ତୁ, **Microsoft 365 Copilot
   (BizChat)** ଚୟନ କରନ୍ତୁ ଏବଂ ନିମ୍ନଲିଖିତ ଫର୍ମାଟ୍ରେ କ୍ରେଡେନ୍ସିଆଲ୍ ପେଷ୍ଟ୍ କରନ୍ତୁ:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. **Test Connection** ଏବଂ **Save**ରେ କ୍ଲିକ୍ କରନ୍ତୁ।

## କ୍ରେଡେନ୍ସିଆଲ୍ ସଂଗ୍ରହ (HAR ଇମ୍ପୋର୍ଟ୍)

WebSocket URLରୁ ମୂଲ୍ୟଗୁଡ଼ିକୁ ମାନୁଆଲ୍ ଭାବେ କପି କରିବା ପରିବର୍ତ୍ତେ, ଆପଣ ଏକ DevTools HAR
ଫାଇଲ୍ ଏକ୍ସପୋର୍ଟ୍ କରିପାରିବେ:

1. **DevTools → Network** ଖୋଲନ୍ତୁ।
2. ଏକ BizChat ବାର୍ତ୍ତାଳାପ ଆରମ୍ଭ କିମ୍ବା ଜାରି ରଖନ୍ତୁ (ଏହା WebSocket କନେକ୍ସନ୍କୁ ଟ୍ରିଗର୍ କରେ)।
3. Network ପ୍ୟାନେଲ୍ରେ ରାଇଟ୍-କ୍ଲିକ୍ କରି **Save all as HAR with content** ଚୟନ କରନ୍ତୁ।
4. OmniRouteରେ, ପ୍ରଦାନକାରୀ କନେକ୍ସନ୍ ଡାଏଲଗ୍ରେ ଥିବା **Import .har file** ବଟନ୍ ବ୍ୟବହାର କରନ୍ତୁ।

OmniRoute Chathub WebSocket URL ପାଇଁ HARକୁ ସ୍କାନ୍ କରେ,
`access_token` ଏବଂ `chathubPath` ବାହାର କରେ, ଏବଂ କ୍ରେଡେନ୍ସିଆଲ୍ ଫିଲ୍ଡଗୁଡ଼ିକୁ ସ୍ୱୟଂଚାଳିତ ଭାବେ ପୂରଣ କରେ।
HAR ଇମ୍ପୋର୍ଟ୍ JWTର ମିଆଦ ସମାପ୍ତି ସମୟକୁ ଡିକୋଡ୍ କରେ ଏବଂ ଅବଶିଷ୍ଟ ଟୋକନ୍ ଜୀବନକାଳ ଦେଖାଏ।

> **କୌଣସି ପ୍ରକୃତ HAR ଏକ୍ସପୋର୍ଟ୍, ଆକ୍ସେସ୍ ଟୋକନ୍ କିମ୍ବା ରିଫ୍ରେଶ୍ ଟୋକନ୍ କେବେବି କମିଟ୍ କରନ୍ତୁ ନାହିଁ।** ପରୀକ୍ଷଣ ଏବଂ
> ଡକ୍ୟୁମେଣ୍ଟେସନ୍ ମୂଲ୍ୟଗୁଡ଼ିକ ସର୍ବଦା ପ୍ଲେସ୍ହୋଲ୍ଡର୍ ହେବା ଆବଶ୍ୟକ।

## ଟୋକନ୍ ଜୀବନକାଳ ଏବଂ ରିଫ୍ରେଶ୍

`access_token` ସ୍ୱଳ୍ପକାଳୀନ (ସାଧାରଣତଃ **~75 ମିନିଟ୍**)। ଏହାର ମିଆଦ ସମାପ୍ତ ହେବା ପରେ, ପ୍ରଦାନକାରୀ
ଏକ କନେକ୍ସନ୍ ତ୍ରୁଟି ରିପୋର୍ଟ୍ କରେ ଏବଂ ଆପଣଙ୍କୁ କ୍ରେଡେନ୍ସିଆଲ୍ ପୁନଃ ସଂଗ୍ରହ କରିବାକୁ ପଡ଼ିବ।

### `refreshToken` ସହିତ ସ୍ୱୟଂଚାଳିତ ରିଫ୍ରେଶ୍

ମାନୁଆଲ୍ ପୁନଃ ସଂଗ୍ରହକୁ ଏଡ଼ାଇବା ପାଇଁ, ଆପଣ କନେକ୍ସନ୍ର
**Advanced Settings → providerSpecificData**ରେ ଏକ Microsoft ରିଫ୍ରେଶ୍ ଟୋକନ୍ ସଂରକ୍ଷଣ କରିପାରିବେ:

| ଫିଲ୍ଡ          | ବିବରଣୀ                                                                   |
| -------------- | ------------------------------------------------------------------------ |
| `refreshToken` | `substrate.office.com/sydney` ସ୍କୋପ୍ ପାଇଁ Microsoft OAuth ରିଫ୍ରେଶ୍ ଟୋକନ୍ |
| `tier`         | `individual` (ଡିଫଲ୍ଟ), `edu`, କିମ୍ବା `enterprise`                        |

`substrate.office.com/sydney` ପାଇଁ ସ୍କୋପ୍ କରାଯାଇଥିବା ଏକ Microsoft device-code କିମ୍ବା authorization-code ଫ୍ଲୋରୁ
ରିଫ୍ରେଶ୍ ଟୋକନ୍ ପ୍ରାପ୍ତ କରନ୍ତୁ। `refreshToken` ସେଟ୍ ଥିଲେ, OmniRoute
ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ପୂର୍ବରୁ `access_token`କୁ ପ୍ରି-ଫ୍ଲାଇଟ୍-ରିଫ୍ରେଶ୍ କରେ, ତେଣୁ ପ୍ରତ୍ୟେକ ~75-ମିନିଟ୍ ମିଆଦ ସମାପ୍ତି ପରେ ଆପଣଙ୍କୁ
ପୁନଃ ସଂଗ୍ରହ କରିବାକୁ ପଡ଼େ ନାହିଁ।

ଯଦି `refreshToken` ସେଟ୍ ହୋଇନାହିଁ, ତେବେ ପ୍ରତ୍ୟେକ ମିଆଦ ସମାପ୍ତି ପରେ ଆପଣଙ୍କୁ WebSocket କ୍ରେଡେନ୍ସିଆଲ୍ ମାନୁଆଲ୍ ଭାବେ
ପୁନଃ ସଂଗ୍ରହ କରିବାକୁ ପଡ଼ିବ।

### ଟିୟର୍ ଚୟନ

| ଟିୟର୍        | ଛଦ୍ମନାମ    | ସର୍ଫେସ୍                   |
| ------------ | ---------- | ------------------------- |
| `individual` | _(ଡିଫଲ୍ଟ)_ | ଉପଭୋକ୍ତା M365 Copilot     |
| `edu`        | `included` | ଶିକ୍ଷା M365 Copilot       |
| `enterprise` | `work`     | କାର୍ଯ୍ୟ ପାଇଁ M365 Copilot |

**Advanced Settings → providerSpecificData → tier**ରେ ଟିୟର୍ ସେଟ୍ କରନ୍ତୁ। ଟିୟର୍
BizChat ରାଉଟିଂ ଏବଂ ମଡେଲ୍ ଆକ୍ସେସ୍କୁ ପ୍ରଭାବିତ କରେ।

## ସୁରକ୍ଷା ମଡେଲ୍

- **ଅନୌପଚାରିକ ଇଣ୍ଟିଗ୍ରେସନ୍।** ଏହି ପ୍ରଦାନକାରୀ BizChat WebSocket
  ପ୍ରୋଟୋକଲ୍କୁ ରିଭର୍ସ-ଇଞ୍ଜିନିୟର୍ କରେ। Microsoft ଏଣ୍ଡପଏଣ୍ଟ ପରିବର୍ତ୍ତନ କଲେ ଏହା ବିନା ସୂଚନାରେ କାମ କରିବା ବନ୍ଦ କରିପାରେ।
- `subscriptionRisk: true` ଫ୍ଲାଗ୍ ଦର୍ଶାଏ ଯେ ଇଣ୍ଟିଗ୍ରେସନ୍ଟି ଏକ
  ଅଲିଖିତ ଏଣ୍ଡପଏଣ୍ଟ ଉପରେ ନିର୍ଭର କରେ। ଆକାଉଣ୍ଟ ଉପରେ ପ୍ରତିବନ୍ଧକ ଲାଗିପାରେ, କିନ୍ତୁ ଏହା ନିଶ୍ଚିତ ନୁହେଁ।
- ଆକ୍ସେସ୍ ଟୋକନ୍ ହେଉଛି ଏକ ସ୍ୱଳ୍ପକାଳୀନ JWT। ଏହାକୁ ପାସୱାର୍ଡ ପରି ବ୍ୟବହାର କରନ୍ତୁ: ଏହାକୁ କମିଟ୍,
  ଲଗ୍ କିମ୍ବା ସେୟାର୍ କରନ୍ତୁ ନାହିଁ।
- ରିଫ୍ରେଶ୍ ଟୋକନ୍ BizChat ସେବାକୁ ଦୀର୍ଘକାଳୀନ ଆକ୍ସେସ୍ ପ୍ରଦାନ କରେ। ଏହାକୁ ଏକ
  API କି ପରି ସମାନ ସତର୍କତାର ସହ ସଂରକ୍ଷଣ କରନ୍ତୁ।

## ସମସ୍ୟା ନିବାରଣ

### ପ୍ରମାଣୀକରଣ ତୁରନ୍ତ ବିଫଳ ହେଉଛି

- ଆପଣ ଏହାକୁ କୌଣସି XHR/Fetch ଅନୁରୋଧରୁ ନୁହେଁ, **WebSocket URL**ରୁ କପି କରିଥିବା ନିଶ୍ଚିତ କରନ୍ତୁ। ପ୍ରମାଣପତ୍ରଟି
  Chathub WebSocket ସଂଯୋଗର `access_token` କ୍ୱେରି ପାରାମିଟର୍ରେ ଅଛି —
  `Authorization: Bearer` ହେଡର୍ରେ ନୁହେଁ।
- `chathubPath`ରେ URL
  ପଥରୁ ସମ୍ପୂର୍ଣ୍ଣ `<oid>@<tenant>` ଅଂଶ ଅନ୍ତର୍ଭୁକ୍ତ ଥିବା ନିଶ୍ଚିତ କରନ୍ତୁ।

### ଟୋକନ୍ର ଅବଧି ~75 ମିନିଟ୍ ପରେ ସମାପ୍ତ ହେଉଛି

ଏହା ଆଶାକରାଯାଇଥାଏ। `refreshToken` ବିନା ଆକ୍ସେସ୍ ଟୋକନ୍ ସ୍ୱଳ୍ପକାଳୀନ ଅଟେ। ନିମ୍ନଲିଖିତ ମଧ୍ୟରୁ ଗୋଟିଏ କରନ୍ତୁ:

- DevToolsରୁ ପ୍ରମାଣପତ୍ରଟି ପୁନଃ କ୍ୟାପଚର୍ କରନ୍ତୁ, କିମ୍ବା
- ସ୍ୱୟଂଚାଳିତ ରିଫ୍ରେଶ୍ ପାଇଁ ଉନ୍ନତ ସେଟିଂସ୍ରେ ଏକ `refreshToken` ବିନ୍ୟାସ କରନ୍ତୁ।

### ସଂଯୋଗ ପରୀକ୍ଷା ସଫଳ ହେଉଛି, କିନ୍ତୁ ଚାଟ୍ 401 ଫେରାଉଛି

ବୈଧତା ଯାଞ୍ଚ ଏବଂ ପ୍ରଥମ ଅନୁରୋଧ ମଧ୍ୟରେ ଟୋକନ୍ର ଅବଧି ସମାପ୍ତ ହୋଇଥାଇପାରେ। ଏକ
ନୂଆ ପ୍ରମାଣପତ୍ର ପୁନଃ କ୍ୟାପଚର୍ କରନ୍ତୁ।

### ପ୍ରଦାନକାରୀ ତାଲିକାରେ Copilot ଦେଖାଯାଉ ନାହିଁ

**Dashboard → Providers**ରେ `copilot-m365-web` ସକ୍ଷମ ଥିବା ନିଶ୍ଚିତ କରନ୍ତୁ। କେତେକ ସ୍ତରରେ ପ୍ରଦାନକାରୀଟି
ଡିଫଲ୍ଟ ଭାବରେ ଲୁକ୍କାୟିତ ଥାଇପାରେ।
