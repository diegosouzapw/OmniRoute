IDE ସେସନ୍ ବିନା Cursorକୁ OmniRoute ପଛରେ ରଖିବାର ଦୁଇଟି ଉପାୟ:

1. **`cursor-api` ପ୍ରଦାନକାରୀ** (କାର୍ଡ "Cursor API", ଉପନାମ `cua`): ଏକ API-key
   ପ୍ରଦାନକାରୀ, ଯାହା ଏକ Cursor ବ୍ୟବହାରକାରୀ API key (`crsr_…`,
   `https://cursor.com/dashboard/api`ରେ ସୃଷ୍ଟି ହୋଇଥିବା) ଧାରଣ କରେ। ତା’ପରେ ଯେକୌଣସି OmniRoute କ୍ଲାଏଣ୍ଟ
   ସାଧାରଣ କୋଟା, ଫଲବ୍ୟାକ୍ ଏବଂ ଲଗିଂ ସ୍ତରଗୁଡ଼ିକ ସହିତ `/v1/chat/completions` ମାଧ୍ୟମରେ
   `cursor-api/<model>` କିମ୍ବା `cua/<model>` ଭାବରେ Cursor ମଡେଲଗୁଡ଼ିକୁ ଆକ୍ସେସ୍ କରେ। IDE
   ପ୍ରଦାନକାରୀ (`cursor`, OAuth/IDE ସେସନ୍) ଅପରିବର୍ତ୍ତିତ ରହେ।
2. **Cursor CLI ପାସ୍ଥ୍ରୁ**: Cursor CLI (`agent`)କୁ OmniRoute ଆଡ଼କୁ ନିର୍ଦ୍ଦେଶିତ କରନ୍ତୁ, ଯାହାଦ୍ୱାରା
   CLI କରୁଥିବା ପ୍ରତ୍ୟେକ RPC ଏକ OmniRoute API key ସହିତ ପ୍ରମାଣୀକୃତ ହୁଏ, ଏକ
   `cursor-api` ସଂଯୋଗର ପ୍ରମାଣପତ୍ର ସହିତ Cursorକୁ ଫରୱାର୍ଡ କରାଯାଏ ଏବଂ
   Logs ପୃଷ୍ଠାରେ ରେକର୍ଡ ହୁଏ।

## key କାହିଁକି ବିନିମୟ କରାଯାଏ

`api2.cursor.sh` ଏକ ମୂଳ `crsr_…` keyକୁ Bearer token ଭାବରେ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ (401)। Cursor
CLI ପ୍ରଥମେ keyଟିକୁ `/auth/exchange_user_api_key`ରେ POST କରେ ଏବଂ ଏକ ସେସନ୍
JWT ପାଏ, ଯାହାର ଅବଧି ଏକ ଘଣ୍ଟା ପରେ ସମାପ୍ତ ହୁଏ; ଫେରସ୍ତ ମିଳିଥିବା `refreshToken`ରେ ସେହି
`exp` ଥାଏ, ତେଣୁ ରିଫ୍ରେଶ୍ କରିବାର ଅର୍ଥ ହେଉଛି keyଟିକୁ ପୁଣି ବିନିମୟ କରିବା।
`open-sse/services/cursorApiKeyAuth.ts` ସେହି ବିନିମୟ କରେ, ପ୍ରତ୍ୟେକ key ପାଇଁ ଗୋଟିଏ ସେସନ୍
token କ୍ୟାଶ୍ କରେ, ଅବଧି ସମାପ୍ତିର ପାଞ୍ଚ ମିନିଟ୍ ପୂର୍ବରୁ ପୁଣି ବିନିମୟ କରେ ଏବଂ Cursor
401 ଉତ୍ତର ଦେଲେ କ୍ୟାଶ୍ ହୋଇଥିବା tokenକୁ ବାଦ ଦିଏ। `CursorExecutor`, `cursor-api`
ସଂଯୋଗଗୁଡ଼ିକ ପାଇଁ ଅପ୍ଷ୍ଟ୍ରିମ୍ ଷ୍ଟ୍ରିମ୍ ଖୋଲିବାର ଠିକ୍ ପୂର୍ବରୁ ଏହାକୁ କଲ୍ କରେ।

## `cursor-api` ପ୍ରଦାନକାରୀ

ରେଜିଷ୍ଟ୍ରି: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, `cursor` ସହିତ ସମାନ `format`, `baseUrl` ଏବଂ
`models`)। କ୍ୟାଟାଲଗ୍ କାର୍ଡ:
`src/shared/constants/providers/apikey/specialty-media.ts`। ଏକ୍ସିକ୍ୟୁଟର୍ ମ୍ୟାପ୍:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`)।

ଡ୍ୟାଶବୋର୍ଡ: Providers → Cursor API → Add API key।

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

ତା’ପରେ:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

ଟିପ୍ପଣୀ:

- `cursor-api` ପାଇଁ ମଡେଲ୍ ତାଲିକା ସ୍ଥିର Cursor ରେଜିଷ୍ଟ୍ରିରୁ ଆସେ (
  IDE ପ୍ରଦାନକାରୀ ଫଲବ୍ୟାକ୍ କରୁଥିବା ସେହି ତାଲିକା); OmniRoute ହୋଷ୍ଟରେ
  `cursor-agent` ଇନ୍ଷ୍ଟଲ୍ କରିବା ଆବଶ୍ୟକ ନୁହେଁ।
- `POST /api/providers/{id}/refresh-cursor` କେବଳ `cursor` IDE ପ୍ରଦାନକାରୀ
  ପାଇଁ; `cursor-api` ସଂଯୋଗଗୁଡ଼ିକରେ ନବୀକରଣ କରିବାକୁ କୌଣସି IDE ସେସନ୍ ନାହିଁ।

## Cursor CLI ପାସ୍ଥ୍ରୁ

ରୁଟ୍: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`। `/api/cursor-cli/` ଉପସର୍ଗଟି
`src/shared/constants/publicApiRoutes.ts`ରେ ପଞ୍ଜୀକୃତ ହୋଇଛି, କାରଣ ହ୍ୟାଣ୍ଡଲର୍
ନିଜସ୍ୱ ପ୍ରମାଣୀକରଣ ପ୍ରୟୋଗ କରେ:

| ପଥ                                                                                                                           | CLIରୁ ଆଶା କରାଯାଉଥିବା ପ୍ରମାଣୀକରଣ | OmniRoute କ’ଣ କରେ                                                                                                                                                       |
| ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                           | `Bearer <OmniRoute API key>`    | keyଟିକୁ ବୈଧ କରେ, ଏକ 1h HS256 JWT (`JWT_SECRET` ସହିତ ସ୍ୱାକ୍ଷରିତ) ସୃଷ୍ଟି କରେ ଏବଂ ତାହାକୁ ଫେରାଏ                                                                             |
| ଅନ୍ୟ ପ୍ରତ୍ୟେକ ପଥ (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`             | ଜାରିକର୍ତ୍ତା/ଦର୍ଶକ/ଅବଧି ସମାପ୍ତି ଯାଞ୍ଚ କରେ, ଏକ ସକ୍ରିୟ `cursor-api` ସଂଯୋଗ ବାଛେ, ବିନିମୟ ହୋଇଥିବା Cursor token ପାଇଁ Authorization ହେଡର୍କୁ ବଦଳାଏ ଏବଂ ଉତ୍ତରକୁ ପଛକୁ ଷ୍ଟ୍ରିମ୍ କରେ |

CLI ଯେକୌଣସି ପ୍ରାପ୍ତ tokenରୁ `exp` ଡିକୋଡ୍ କରେ, ତେଣୁ ଏହାକୁ ଏକ ଅପାରଦର୍ଶୀ
token ଦେଲେ ପ୍ରାୟ ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ପୂର୍ବରୁ ଏହା ପୁଣି ବିନିମୟ କରେ; ସୃଷ୍ଟି ହୋଇଥିବା JWT
ତାହାକୁ ଏଡ଼ାଏ। OmniRouteରୁ ଏକ 401 ମିଳିଲେ CLI ପୁଣି ବିନିମୟ କରେ।

### ସେଟଅପ୍

1. ଏକ OmniRoute API key (Dashboard → API keys) ଏବଂ ଏକ `cursor-api`
   ସଂଯୋଗ ସୃଷ୍ଟି କରନ୍ତୁ।
2. ଏଜେଣ୍ଟ ଷ୍ଟ୍ରିମ୍ ପାଇଁ HTTP/1.1 ବ୍ୟବହାର କରିବାକୁ CLIକୁ କୁହନ୍ତୁ।
   `~/.cursor/cli-config.json`ରେ:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   ଏହା ବିନା CLI, ପୃଥକ ଭାବେ ବିନ୍ୟାସିତ ଏକ ଏଜେଣ୍ଟ ହୋଷ୍ଟକୁ HTTP/2 ମାଧ୍ୟମରେ
   ଏଜେଣ୍ଟ ଟର୍ନ୍ ଖୋଲେ ଏବଂ କେବଳ କଣ୍ଟ୍ରୋଲ୍-ପ୍ଲେନ୍ RPCଗୁଡ଼ିକ
   ଏଣ୍ଡପଏଣ୍ଟ ମାଧ୍ୟମରେ ଯାଆନ୍ତି।

3. OmniRoute ବିପରୀତରେ CLI ଚଲାନ୍ତୁ:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

ପ୍ରତ୍ୟେକ ହପ୍ Logsରେ ପ୍ରଦାନକାରୀ `cursor-api`, ଅନୁରୋଧ ପ୍ରକାର `cursor-cli`,
ପଥ `/api/cursor-cli/<rpc>` ଭାବରେ ପହଞ୍ଚେ ଏବଂ OmniRoute API key ଓ ଏହାକୁ
ସେବା ଦେଇଥିବା ସଂଯୋଗ ସହିତ ଯୋଡ଼ାଯାଏ।

### ବିଫଳତା ପ୍ରକାରଗୁଡ଼ିକ

| ପରିସ୍ଥିତି                                         | CLI ପ୍ରତି ପ୍ରତିକ୍ରିୟା                                    |
| ------------------------------------------------- | -------------------------------------------------------- |
| ଅଜଣା OmniRoute କୀ ଏବଂ `REQUIRE_API_KEY=true`      | ଏକ୍ସଚେଞ୍ଜ ସମୟରେ 401 `unauthenticated`                    |
| `REQUIRE_API_KEY=false`                           | ଅଜ୍ଞାତନାମା ସେସନ୍ (`/v1/*` ଆଚରଣକୁ ଅନୁସରଣ କରେ)             |
| ମেয়ାଦୋତ୍ତୀର୍ଣ୍ଣ / ବିଦେଶୀ / ପରିବର୍ତ୍ତିତ ସେସନ୍ JWT | 401, CLI ପୁନଃ ଏକ୍ସଚେଞ୍ଜ କରେ                              |
