IDE ସେସନ୍ ବିନା Cursorକୁ OmniRoute ପଛରେ ରଖିବାର ଦୁଇଟି ଉପାୟ:

1. **`cursor-api` ପ୍ରଦାନକାରୀ** (କାର୍ଡ "Cursor API", ଉପନାମ `cua`): ଏକ API-କି
   ପ୍ରଦାନକାରୀ, ଯାହା Cursor ବ୍ୟବହାରକାରୀ API କି (`crsr_…`, ଯାହା
   `https://cursor.com/dashboard/api`ରେ ସୃଷ୍ଟି ହୁଏ) ଧାରଣ କରେ। ତା’ପରେ ଯେକୌଣସି OmniRoute କ୍ଲାଏଣ୍ଟ
   ସାଧାରଣ କୋଟା, ଫଲ୍ବ୍ୟାକ୍ ଏବଂ ଲଗିଂ ସ୍ତର ସହିତ `/v1/chat/completions` ମାଧ୍ୟମରେ
   `cursor-api/<model>` କିମ୍ବା `cua/<model>` ଭାବରେ Cursor ମଡେଲଗୁଡ଼ିକୁ ପହଞ୍ଚିପାରିବ। IDE
   ପ୍ରଦାନକାରୀ (`cursor`, OAuth/IDE ସେସନ୍) ଅପରିବର୍ତ୍ତିତ ରହିଛି।
2. **Cursor CLI ପାସ୍ଥ୍ରୁ**: Cursor CLI (`agent`)କୁ OmniRoute ଆଡ଼କୁ ନିର୍ଦ୍ଦେଶିତ କରନ୍ତୁ, ଯାହାଦ୍ୱାରା
   CLI କରୁଥିବା ପ୍ରତ୍ୟେକ RPC ଏକ OmniRoute API କି ସହିତ ପ୍ରମାଣିତ ହୁଏ, ଏକ
   `cursor-api` ସଂଯୋଗର କ୍ରେଡେନ୍ସିଆଲ୍ ସହିତ Cursorକୁ ଫରୱାର୍ଡ କରାଯାଏ, ଏବଂ
   Logs ପୃଷ୍ଠାରେ ରେକର୍ଡ ହୁଏ।

## କିକୁ କାହିଁକି ବିନିମୟ କରାଯାଏ

`api2.cursor.sh` ଏକ କଞ୍ଚା `crsr_…` କିକୁ Bearer ଟୋକନ୍ ଭାବରେ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ (401)। Cursor
CLI ପ୍ରଥମେ କିକୁ `/auth/exchange_user_api_key`କୁ POST କରେ ଏବଂ ଏକ ସେସନ୍
JWT ପାଏ, ଯାହା ଏକ ଘଣ୍ଟା ପରେ ମିଆଦ ସମାପ୍ତ ହୁଏ; ଫେରସ୍ତ ମିଳିଥିବା `refreshToken`ରେ ସେହି
`exp` ଥାଏ, ତେଣୁ ରିଫ୍ରେଶ୍ କରିବାର ଅର୍ଥ କିକୁ ପୁନଃ ବିନିମୟ କରିବା।
`open-sse/services/cursorApiKeyAuth.ts` ସେହି ବିନିମୟ କରେ, ପ୍ରତ୍ୟେକ କି ପାଇଁ ଗୋଟିଏ ସେସନ୍
ଟୋକନ୍ କ୍ୟାଶ୍ କରେ, ମିଆଦ ସମାପ୍ତିର ପାଞ୍ଚ ମିନିଟ୍ ପୂର୍ବରୁ ପୁନଃ ବିନିମୟ କରେ ଏବଂ Cursor 401
ଉତ୍ତର ଦେଲେ କ୍ୟାଶ୍ ହୋଇଥିବା ଟୋକନ୍କୁ ବିଲୋପ କରେ। `CursorExecutor`
`cursor-api` ସଂଯୋଗଗୁଡ଼ିକ ପାଇଁ ଅପ୍ଷ୍ଟ୍ରିମ୍ ଷ୍ଟ୍ରିମ୍ ଖୋଲିବାର ଠିକ୍ ପୂର୍ବରୁ ଏହାକୁ କଲ୍ କରେ।

## `cursor-api` ପ୍ରଦାନକାରୀ

ରେଜିଷ୍ଟ୍ରି: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, `cursor` ସହିତ ସମାନ `format`, `baseUrl` ଏବଂ
`models`)। କ୍ୟାଟାଲଗ୍ କାର୍ଡ:
`src/shared/constants/providers/apikey/specialty-media.ts`। ଏକ୍ସିକ୍ୟୁଟର୍ ମ୍ୟାପ୍:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`)।

ଡ୍ୟାସ୍ବୋର୍ଡ: Providers → Cursor API → Add API key।

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

ତା’ପରେ:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

ଟିପ୍ପଣୀ:

- `cursor-api` ପାଇଁ ମଡେଲ୍ ତାଲିକା ସ୍ଥିର Cursor ରେଜିଷ୍ଟ୍ରିରୁ ଆସେ (IDE
  ପ୍ରଦାନକାରୀ ଯେଉଁ ସମାନ ତାଲିକାକୁ ଫଲ୍ବ୍ୟାକ୍ କରେ); OmniRoute ହୋଷ୍ଟରେ
  `cursor-agent` ଇନ୍ଷ୍ଟଲ୍ କରିବା ଆବଶ୍ୟକ ନୁହେଁ।
- `POST /api/providers/{id}/refresh-cursor` କେବଳ `cursor` IDE ପ୍ରଦାନକାରୀ
  ପାଇଁ; `cursor-api` ସଂଯୋଗଗୁଡ଼ିକର ନବୀକରଣ କରିବାକୁ କୌଣସି IDE ସେସନ୍ ନାହିଁ।

## ନେଟିଭ୍ ମଡେଲ୍ ID ଏବଂ ପ୍ରୟାସ

`cursor` / `cu` ଏବଂ `cursor-api` / `cua` ପାଇଁ, ଅଂଶୀଦାରୀ Claude-ପ୍ରୟାସ ନର୍ମାଲାଇଜର୍
ଅନୁରୋଧ କରାଯାଇଥିବା ମଡେଲ୍ IDକୁ ଅପରିବର୍ତ୍ତିତ ରଖେ। Cursor ଏକ OmniRoute ପ୍ରୟାସ ଉପନାମ
ଭାବରେ ନୁହେଁ, ବରଂ ଏକ ପ୍ରକୃତ ମଡେଲ୍ IDର ଅଂଶ ଭାବରେ `-low` ପରି ଏକ ସଫିକ୍ସର
ବିଜ୍ଞାପନ କରିପାରେ। Cursor ଏକ୍ସିକ୍ୟୁଟର୍ ଏକ ସଠିକ୍ ଲାଇଭ୍-କ୍ୟାଟାଲଗ୍ ମେଳକୁ ସଂରକ୍ଷିତ ରଖେ;
କୌଣସି ମେଳ ନଥିଲେ, ଏହାର ବିଦ୍ୟମାନ ମଡେଲ୍ ରିଜଲ୍ଭର୍ ସଫିକ୍ସରୁ ପାରାମିଟର୍କୁ ଫଲ୍ବ୍ୟାକ୍
ପରିଚାଳନା କରେ।

ଏହା ସିଧାସଳଖ Claude, Claude-ସୁସଙ୍ଗତ, କିମ୍ବା Vertex ରୁଟ୍ଗୁଡ଼ିକ ପାଇଁ ପ୍ରୟାସ
ନର୍ମାଲାଇଜେସନ୍କୁ ପରିବର୍ତ୍ତନ କରେ ନାହିଁ। ଉପଲବ୍ଧତା ଏପର୍ଯ୍ୟନ୍ତ ଚୟନିତ Cursor ଆକାଉଣ୍ଟର
କ୍ୟାଟାଲଗ୍ ଏବଂ ଏଣ୍ଟାଇଟଲ୍ମେଣ୍ଟ ଉପରେ ନିର୍ଭର କରେ।

## Cursor CLI ପାସ୍ଥ୍ରୁ

ରୁଟ୍: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`। ଉପସର୍ଗ `/api/cursor-cli/` କୁ
`src/shared/constants/publicApiRoutes.ts` ରେ ପଞ୍ଜୀକୃତ କରାଯାଇଛି, କାରଣ ହ୍ୟାଣ୍ଡଲର୍
ନିଜସ୍ୱ ପ୍ରମାଣୀକରଣ ବାଧ୍ୟତାମୂଳକ କରେ:

| ପଥ                                                                                                                        | CLI ଠାରୁ ଆଶା କରାଯାଉଥିବା ପ୍ରମାଣୀକରଣ | OmniRoute କ’ଣ କରେ                                                                                                                                                       |
| ------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                        | `Bearer <OmniRoute API key>`       | କୀ’ଟିକୁ ବୈଧ କରେ, 1 ଘଣ୍ଟାର HS256 JWT (`JWT_SECRET` ଦ୍ୱାରା ସ୍ୱାକ୍ଷରିତ) ତିଆରି କରେ ଏବଂ ତାହା ଫେରାଏ                                                                           |
| ଅନ୍ୟ ସମସ୍ତ ପଥ (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`                | ପ୍ରଦାନକାରୀ/ଶ୍ରୋତା/ମିଆଦ ସମାପ୍ତି ଯାଞ୍ଚ କରେ, ଏକ ସକ୍ରିୟ `cursor-api` ସଂଯୋଗ ବାଛେ, ବିନିମୟ ହୋଇଥିବା Cursor ଟୋକନ୍ ସହିତ Authorization ହେଡର୍କୁ ବଦଳାଏ ଏବଂ ଉତ୍ତରକୁ ପୁଣି ଷ୍ଟ୍ରିମ୍ କରେ |

CLI ପ୍ରାପ୍ତ ଯେକୌଣସି ଟୋକନ୍ରୁ `exp` ଡିକୋଡ୍ କରେ, ତେଣୁ ଏହାକୁ ଏକ ଅସ୍ପଷ୍ଟ
ଟୋକନ୍ ଦେଲେ ପ୍ରାୟ ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ପୂର୍ବରୁ ଏହା ପୁଣି ବିନିମୟ କରେ; ତିଆରି ହୋଇଥିବା JWT
ଏହାକୁ ଏଡ଼ାଇଥାଏ। OmniRoute ଠାରୁ 401 ମିଳିଲେ CLI ପୁଣି ବିନିମୟ କରେ।

### ସେଟଅପ୍

1. ଏକ OmniRoute API କୀ (Dashboard → API କୀଗୁଡ଼ିକ) ଏବଂ ଏକ `cursor-api`
   ସଂଯୋଗ ତିଆରି କରନ୍ତୁ।
2. ଏଜେଣ୍ଟ ଷ୍ଟ୍ରିମ୍ ପାଇଁ HTTP/1.1 ବ୍ୟବହାର କରିବାକୁ CLI କୁ କୁହନ୍ତୁ।
   `~/.cursor/cli-config.json` ରେ:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   ଏହା ବିନା CLI ଏକ ପୃଥକ ଭାବରେ ବିନ୍ୟାସିତ ଏଜେଣ୍ଟ ହୋଷ୍ଟକୁ HTTP/2 ମାଧ୍ୟମରେ ଏଜେଣ୍ଟ ଟର୍ନ୍ ଖୋଲେ
   ଏବଂ କେବଳ କଣ୍ଟ୍ରୋଲ୍-ପ୍ଲେନ୍ RPC ଗୁଡ଼ିକ ଏଣ୍ଡପଏଣ୍ଟ ଦେଇ ଯାଆନ୍ତି।

3. OmniRoute ବିପକ୍ଷରେ CLI ଚଲାନ୍ତୁ:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

ପ୍ରତ୍ୟେକ ହପ୍ Logs ରେ ପ୍ରଦାନକାରୀ `cursor-api`, ଅନୁରୋଧ ପ୍ରକାର `cursor-cli`,
ପଥ `/api/cursor-cli/<rpc>` ଭାବେ ଦର୍ଜ ହୁଏ ଏବଂ ଏହାକୁ ସେବା ଦେଇଥିବା OmniRoute API କୀ ଓ
ସଂଯୋଗ ସହିତ ସମ୍ବନ୍ଧିତ କରାଯାଏ।
