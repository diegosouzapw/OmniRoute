ଏହି ଡକ୍ୟୁମେଣ୍ଟଟି
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854) ପାଇଁ କାର୍ଯ୍ୟାନ୍ୱୟନ ନିଷ୍ପତ୍ତିକୁ ରେକର୍ଡ କରେ। ସାର୍ବଜନୀନ ପ୍ରଡକ୍ଟଗୁଡ଼ିକୁ
ଚାରିଟି ପ୍ରଦାତା ପରିବାର ଭାବରେ ଉପସ୍ଥାପନ କରାଯାଇଛି। ଅଞ୍ଚଳ ହେଉଛି ସଂଯୋଗ ଡାଟା, ଏକ ପୃଥକ ପ୍ରଡକ୍ଟ ନୁହେଁ।

## ନିଷ୍ପତ୍ତି

| ପ୍ରଦାତା ପରିବାର                                   | OmniRoute ID            | ବିଶ୍ୱସ୍ତରୀୟ ଅଞ୍ଚଳ | ଚୀନ୍ ଅଞ୍ଚଳ |
| ------------------------------------------------ | ----------------------- | ----------------- | ---------- |
| Alibaba Cloud Model Studio (ବ୍ୟବହାର ଅନୁସାରେ ଦେୟ) | `alibaba`               | ସିଙ୍ଗାପୁର         | ବେଜିଂ      |
| Alibaba Cloud Token Plan                         | `bailian-coding-plan`   | ସିଙ୍ଗାପୁର         | ବେଜିଂ      |
| Qwen Cloud (ବ୍ୟବହାର ଅନୁସାରେ ଦେୟ)                 | `qwen-cloud`            | ବିଶ୍ୱସ୍ତରୀୟ       | ବେଜିଂ      |
| Qwen Cloud Token Plan                            | `qwen-cloud-token-plan` | ସିଙ୍ଗାପୁର         | ବେଜିଂ      |

ବିଦ୍ୟମାନ `alibaba-cn` ID ସଞ୍ଚିତ ସଂଯୋଗ, ମଡେଲ୍
ରୁଟ୍, କମ୍ବୋ ଏବଂ ଐତିହାସିକ ବ୍ୟବହାର ପାଇଁ ଏକ ରନ୍ଟାଇମ୍ ସୁସଙ୍ଗତତା ଉପନାମ ଭାବରେ ରହିବ। ଏହାର ଡ୍ୟାଶବୋର୍ଡ କାର୍ଡକୁ `alibaba` ମଧ୍ୟରେ ଏକତ୍ର କରାଯାଇଛି; କୌଣସି ଡାଟାବେସ୍
ପୁନଃଲିଖନ ଆବଶ୍ୟକ ନୁହେଁ।

Qwen Cloudର ବ୍ୟବହାର-ଅନୁସାରେ-ଦେୟ ଏବଂ Alibaba Cloud Model Studio ବର୍ତ୍ତମାନ DashScope-ସୁସଙ୍ଗତ
ରନ୍ଟାଇମ୍ ହୋଷ୍ଟଗୁଡ଼ିକୁ ସହଭାଗ କରନ୍ତି, କିନ୍ତୁ ସେଗୁଡ଼ିକ ପୃଥକ ପ୍ରଦାତା ପରିଚୟ ଭାବରେ ରହନ୍ତି, କାରଣ ବ୍ୟବହାରକାରୀମାନେ ଭିନ୍ନ ପ୍ରଡକ୍ଟ ଇଣ୍ଟରଫେସ୍ ମାଧ୍ୟମରେ କୀ ପ୍ରାପ୍ତ କରନ୍ତି ଏବଂ
ଆକାଉଣ୍ଟ ପରିଚାଳନା କରନ୍ତି। Alibaba ଏବଂ Qwen Cloud Token Plan ପ୍ରଡକ୍ଟଗୁଡ଼ିକ ଭିନ୍ନ
ଏଣ୍ଡପଏଣ୍ଟ ପରିବାର ବ୍ୟବହାର କରନ୍ତି, ତେଣୁ ସମସ୍ତ ଚାରିଟି ପ୍ରଡକ୍ଟ ପୃଥକ ପ୍ରଦାତା ID ଭାବରେ ରହେ।

API କୀ ଏବଂ ଏଣ୍ଡପଏଣ୍ଟ ନିଶ୍ଚିତ ଭାବରେ ସମାନ ପ୍ରଡକ୍ଟ ଏବଂ ଅଞ୍ଚଳର ହୋଇଥିବା ଆବଶ୍ୟକ। ଏକ ଅଞ୍ଚଳ ଚୟନ କରିବା ଦ୍ୱାରା
ବୈଧୀକରଣ ଏବଂ ସାଧାରଣ ଅନୁରୋଧଗୁଡ଼ିକରେ ବ୍ୟବହୃତ ପୂର୍ବନିର୍ଦ୍ଧାରିତ ଏଣ୍ଡପଏଣ୍ଟ ପରିବର୍ତ୍ତିତ ହୁଏ।

## ସଂଯୋଗ ଚୁକ୍ତି

ନୂତନ ସଂଯୋଗଗୁଡ଼ିକ `providerSpecificData`ରେ ସ୍ଥିର ଅଞ୍ଚଳ କୀ ସଞ୍ଚୟ କରନ୍ତି:

```json
{
  "region": "global-sg"
}
```

ଅନୁମୋଦିତ ମୂଲ୍ୟଗୁଡ଼ିକ ହେଲା `global-sg` ଏବଂ `china-beijing`। ଏଣ୍ଡପଏଣ୍ଟକୁ କେନ୍ଦ୍ରୀୟ ଭାବରେ
ପ୍ରଦାତା ID ଏବଂ ଅଞ୍ଚଳରୁ ନିର୍ଦ୍ଧାରଣ କରାଯାଏ। ଏକ ଅଣ-ପୂର୍ବନିର୍ଦ୍ଧାରିତ `providerSpecificData.baseUrl` ଏକ ସ୍ପଷ୍ଟ ଅପରେଟର୍
ଓଭର୍ରାଇଡ୍ ଭାବରେ ରହେ ଏବଂ ଏହାକୁ ପ୍ରାଧାନ୍ୟ ଦିଆଯାଏ, ଯେତେବେଳେ ପୁରୁଣା ସଞ୍ଚିତ ପୂର୍ବନିର୍ଦ୍ଧାରିତ URLଗୁଡ଼ିକୁ ଆଞ୍ଚଳିକ
ମ୍ୟାଟ୍ରିକ୍ସକୁ ପୁନଃ ସାମାନ୍ୟୀକୃତ କରାଯାଏ।

ଏହା ସଂଯୋଗ ସ୍କିମାକୁ ବିସ୍ତାରଯୋଗ୍ୟ ରଖେ: ଅନ୍ୟ ଏକ ଅଞ୍ଚଳକୁ
ଅନ୍ୟ ଏକ ପ୍ରଦାତା କାର୍ଡ ସୃଷ୍ଟି ନକରି କିମ୍ବା ସଞ୍ଚିତ ପ୍ରଦାତା IDଗୁଡ଼ିକୁ ପରିବର୍ତ୍ତନ ନକରି ରିଜଲ୍ଭର୍ରେ ଯୋଡ଼ାଯାଇପାରିବ।

## ସୁସଙ୍ଗତତା ଏବଂ ରୋଲଆଉଟ୍

1. ଆଞ୍ଚଳିକ ଏଣ୍ଡପଏଣ୍ଟ ରିଜଲ୍ଭର୍ ଯୋଡ଼ନ୍ତୁ ଏବଂ ବର୍ତ୍ତମାନର ଗ୍ଲୋବାଲ୍ ଡିଫଲ୍ଟଗୁଡ଼ିକୁ ବଜାୟ ରଖନ୍ତୁ।
2. `alibaba`, ଏହାର `alibaba-cn` ସୁସଙ୍ଗତତା ID ଏବଂ `qwen-cloud` ପାଇଁ ଲାଇଭ୍ ଆଞ୍ଚଳିକ DashScope `/models` ଡିସ୍କଭରି ବ୍ୟବହାର କରନ୍ତୁ। ସାଧାରଣ
   ଏଣ୍ଡପଏଣ୍ଟ ଇମେଜ୍, ଭିଡିଓ, ଅଡିଓ, ଏମ୍ବେଡିଂ ଏବଂ ଅନ୍ୟାନ୍ୟ ଅଣ-ଚାଟ୍ ମଡେଲ୍ ମଧ୍ୟ ଫେରାଉଥିବାରୁ, ସେମାନଙ୍କ ପ୍ରତିକ୍ରିୟା ପ୍ରଥମେ ଏକ ଟେକ୍ସଟ୍-ଜେନେରେସନ୍ ଫିଲ୍ଟର୍ ଦେଇ ଯାଏ। ଏହା ପରେ `qwen-cloud`
   ତାହାର ପ୍ରଦାତା ରେଜିଷ୍ଟ୍ରିରେ ଘୋଷିତ ଏବଂ ରକ୍ଷଣାବେକ୍ଷଣ କରାଯାଉଥିବା ଅନୁମୋଦିତ ତାଲିକା ପ୍ରୟୋଗ କରେ। Alibaba Model Studio
   ଏବଂ Qwen Cloud ବର୍ତ୍ତମାନ ସମାନ ରନ୍ଟାଇମ୍ ହୋଷ୍ଟ ସେୟାର୍ କରୁଥିଲେ ମଧ୍ୟ, ପୃଥକ ଭାବେ ଚୟନିତ କ୍ୟାଟାଲଗ୍ ବଜାୟ ରଖନ୍ତି।
3. ବର୍ତ୍ତମାନର Token Plan ଟେକ୍ସଟ୍-ମଡେଲ୍ ଅନୁମୋଦିତ ତାଲିକା ସହିତ `qwen-cloud-token-plan` ପଞ୍ଜୀକରଣ କରନ୍ତୁ।
4. ସଂଯୋଗ ଯୋଡ଼ିବା/ସମ୍ପାଦନ କରିବା ଡାଏଲଗ୍ଗୁଡ଼ିକରେ ଏକ ଟାଇପ୍ଡ୍ ଅଞ୍ଚଳ ଚୟନକାରୀ ଯୋଡ଼ନ୍ତୁ।
5. ନକଲି `alibaba-cn` କାର୍ଡକୁ ଲୁଚାନ୍ତୁ ଏବଂ ଏହାର ବିଦ୍ୟମାନ ସଂଯୋଗଗୁଡ଼ିକୁ `alibaba`
   ପ୍ରଦାତା ପୃଷ୍ଠାରେ ସାମିଲ କରନ୍ତୁ।
