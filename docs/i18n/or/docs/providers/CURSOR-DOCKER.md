ଯେତେବେଳେ OmniRoute Docker ଭିତରେ ଚାଲେ, କଣ୍ଟେନର୍ ହୋଷ୍ଟରେ ଥିବା Cursor
ଇନଷ୍ଟଲେସନ୍କୁ ଦେଖିପାରୁ ନଥିବାରୁ ପୁରୁଣା **Cursor IDEରୁ ଆମଦାନୀ** /
`cursor-agent` ପ୍ରବାହ ବିଫଳ ହୁଏ। ଏହା ପରିବର୍ତ୍ତେ **Cursor ସହିତ ଲଗଇନ୍ କରନ୍ତୁ** (deep-control PKCE)
ବ୍ୟବହାର କରନ୍ତୁ।

## Dockerରେ IDE / CLI ଆମଦାନୀ କାହିଁକି ବିଫଳ ହୁଏ

1. **ଫାଇଲ୍ସିଷ୍ଟମ୍ ପୃଥକୀକରଣ** — ସ୍ୱୟଂଚାଳିତ ଆମଦାନୀ କଣ୍ଟେନର୍ _ଭିତରେ_
   `~/.config/Cursor/User/globalStorage/state.vscdb` ପରି Linux ପଥ ଖୋଜେ।
   macOS ପାଇଁ Docker Desktopରେ ହୋଷ୍ଟ IDE DB ଡିଫଲ୍ଟ ଭାବେ ମାଉଣ୍ଟ ହୋଇନଥାଏ, ଏବଂ
   ହୋଷ୍ଟ Darwin ହୋଇଥିଲେ ମଧ୍ୟ କଣ୍ଟେନର୍ OS ହେଉଛି Linux।
2. **କୌଣସି `cursor-agent` ବାଇନେରୀ ନାହିଁ** — ଆଧିକାରିକ OmniRoute ଇମେଜ୍ଗୁଡ଼ିକରେ
   `cursor-agent` ଅନ୍ତର୍ଭୁକ୍ତ ନଥାଏ। ଉପଲବ୍ଧ ମଡେଲ୍ଗୁଡ଼ିକ ପୂର୍ବରୁ
   `cursor-agent --list-models`କୁ ଶେଲ୍ ମାଧ୍ୟମରେ ଚଳାଉଥିଲେ ଏବଂ ଏକ ସ୍ଥିର କ୍ୟାଟାଲଗ୍କୁ ଫଲ୍ବ୍ୟାକ୍ କରୁଥିଲେ।
3. **ଭୁଲ୍ ବାଇନେରୀ** — ଏକ macOS `cursor-agent`କୁ Linux କଣ୍ଟେନର୍ରେ
   ବାଇଣ୍ଡ-ମାଉଣ୍ଟ **କରନ୍ତୁ ନାହିଁ**। ଏହା ଚାଲିବ ନାହିଁ।

## ସୁପାରିସକୃତ: Cursor ସହିତ ଲଗଇନ୍ କରନ୍ତୁ

1. **ଡ୍ୟାସ୍ବୋର୍ଡ → ପ୍ରଦାନକାରୀ → Cursor** ଖୋଲନ୍ତୁ।
2. **Cursor ସହିତ ଲଗଇନ୍ କରନ୍ତୁ** ଟ୍ୟାବ୍ ବାଛନ୍ତୁ।
3. **Cursor ସହିତ ଲଗଇନ୍ କରନ୍ତୁ** କ୍ଲିକ୍ କରନ୍ତୁ — OmniRoute ଆପଣଙ୍କ **ହୋଷ୍ଟ**
   ବ୍ରାଉଜର୍ରେ `https://cursor.com/loginDeepControl?…` ଖୋଲେ।
4. ବ୍ରାଉଜର୍ରେ ଲଗଇନ୍ ଅନୁମୋଦନ କରନ୍ତୁ, ତା’ପରେ ଡ୍ୟାସ୍ବୋର୍ଡକୁ ଫେରନ୍ତୁ। ଟୋକେନ୍ ଆସିବା ପର୍ଯ୍ୟନ୍ତ OmniRoute
   `api2.cursor.sh/auth/poll`କୁ ପୋଲ୍ କରେ।
5. OmniRoute **ଆକ୍ସେସ୍ + ରିଫ୍ରେଶ୍** ଟୋକେନ୍ ସଂରକ୍ଷଣ କରେ ଏବଂ
   `https://api2.cursor.sh/auth/exchange_user_api_key` ମାଧ୍ୟମରେ ସେଗୁଡ଼ିକୁ ରିଫ୍ରେଶ୍ କରେ।

ଏହି ପଥ ପାଇଁ କଣ୍ଟେନର୍ ଭିତରେ Cursor IDE କିମ୍ବା `cursor-agent` ଆବଶ୍ୟକ ନୁହେଁ।

## ମଡେଲ୍ ଆବିଷ୍କାର

ଏକ ଲଗଇନ୍ ହୋଇଥିବା ସଂଯୋଗ ସହିତ, **ଉପଲବ୍ଧ ମଡେଲ୍ / ସ୍ୱୟଂଚାଳିତ ସିଙ୍କ୍** ସଂଯୋଗର bearer token
ବ୍ୟବହାର କରି Cursorର HTTP `AiService/AvailableModels` କ୍ୟାଟାଲଗ୍କୁ ପ୍ରାଥମିକତା ଦିଏ।
ଏହା ବିଫଳ ହେଲେ, OmniRoute ତଥାପି ହୋଷ୍ଟ `cursor-agent`କୁ (ଉପସ୍ଥିତ ଥିଲେ) ଚେଷ୍ଟା କରେ, ତା’ପରେ
ସ୍ଥିର ରେଜିଷ୍ଟ୍ରି ସିଡ୍କୁ ଚେଷ୍ଟା କରେ।

OmniRoute କ୍ୟାଟାଲଗ୍ରେ ସର୍ବଦା **`auto`** (ପ୍ରଦର୍ଶନ ନାମ “Auto”), ଏବଂ
OpenCodex-ଶୈଳୀ ରାଉଟର୍ ମୋଡ୍ **`auto-cost`**, **`auto-balance`**, ଓ
**`auto-intelligence`** ପ୍ରଦର୍ଶନ କରେ। ୱାୟାର୍ରେ ଏଗୁଡ଼ିକ Cursorର `default` ମଡେଲ୍କୁ
(ତିନୋଟି ଭାରିଆଣ୍ଟ ପାଇଁ ଏକ `optimization` ModelParameter ସହିତ) ମ୍ୟାପ୍ ହୁଏ। ପ୍ରିମିୟମ୍
ମଡେଲ୍ଗୁଡ଼ିକର ବ୍ୟବହାର ସୀମା ଶେଷ ହେଲେ `cu/auto`କୁ ପ୍ରାଥମିକତା ଦିଅନ୍ତୁ — Autoରେ ପ୍ରାୟତଃ ତଥାପି ବଜେଟ୍ ରହିଥାଏ।

### ସିଙ୍କ୍ ହୋଇଥିଲେ ଲାଇଭ୍ କ୍ୟାଟାଲଗ୍ ସ୍ୱତନ୍ତ୍ର ଅଟେ

ଏକ ସଫଳ Cursor ମଡେଲ୍ ସିଙ୍କ୍ (`cursor-agent --list-models` → ସଂରକ୍ଷିତ
ସିଙ୍କ୍ ହୋଇଥିବା କ୍ୟାଟାଲଗ୍, କିମ୍ବା ଉପରୋକ୍ତ bearer-ପ୍ରମାଣୀକୃତ `AvailableModels` ଫେଚ୍) ପରେ,
**ଡ୍ୟାସ୍ବୋର୍ଡ**, **`/v1/models`**, ଏବଂ **ସମସ୍ତଙ୍କୁ ପରୀକ୍ଷା କରନ୍ତୁ** ଏଗୁଡ଼ିକୁ ତାଲିକାଭୁକ୍ତ କରେ:

1. ଲାଇଭ୍ ସିଙ୍କ୍ରୁ ଫେରିଥିବା ମଡେଲ୍ଗୁଡ଼ିକ
2. ଇଞ୍ଜେକ୍ଟ କରାଯାଇଥିବା ସ୍ୱୟଂଚାଳିତ-ରାଉଟର୍ idଗୁଡ଼ିକ: `auto`, `auto-cost`, `auto-balance`, `auto-intelligence`
3. ଅପରେଟର୍ଙ୍କ **କଷ୍ଟମ୍** ମଡେଲ୍ଗୁଡ଼ିକ (ଆମଦାନୀ / ମାନୁଆଲ୍) — ସିଙ୍କ୍ ଦ୍ୱାରା କେବେବି ହଟାଯାଏ ନାହିଁ

`open-sse/config/providers/registry/cursor/` ଅଧୀନରେ ଥିବା ବଡ଼ ସ୍ଥିର ରେଜିଷ୍ଟ୍ରିଟି
**କେବଳ ଅଫ୍ଲାଇନ୍ ଫଲ୍ବ୍ୟାକ୍**। ସିଙ୍କ୍ ହୋଇଥିବା ତାଲିକା ଖାଲି ଥିଲେ (କିମ୍ବା ଆବିଷ୍କାର ବିଫଳ ହେଲେ),
ତାଲିକା ପ୍ରଦର୍ଶନ ସେହି ରେଜିଷ୍ଟ୍ରିକୁ ଫଲ୍ବ୍ୟାକ୍ କରେ।

Effort-ପ୍ରତ୍ୟୟଯୁକ୍ତ idଗୁଡ଼ିକ (ଉଦାହରଣ ସ୍ୱରୂପ `claude-4.6-sonnet-high`)କୁ ରନ୍ଟାଇମ୍ରେ ତଥାପି
**ଅନୁରୋଧ** କରାଯାଇପାରେ: `resolveRequestedModel` ପ୍ରତ୍ୟୟଟିକୁ ଅଲଗା କରି ଏକ ୱାୟାର୍
`ModelParameter`ରେ ପରିଣତ କରେ। ସ୍ୱତନ୍ତ୍ର ତାଲିକାଭୁକ୍ତକରଣ ଉଦ୍ଦେଶ୍ୟମୂଳକ ଭାବେ ସେହି ସ୍ଥିର ଭାରିଆଣ୍ଟଗୁଡ଼ିକୁ
ସମସ୍ତଙ୍କୁ ପରୀକ୍ଷା କରନ୍ତୁରୁ ଲୁଚାଏ, ଯାହାଦ୍ୱାରା ପ୍ରୋବ୍ଗୁଡ଼ିକ Cursor ପ୍ରକୃତରେ ଉପଲବ୍ଧ ବୋଲି ଫେରାଉଥିବା ମଡେଲ୍ଗୁଡ଼ିକ ସହିତ ମେଳ ଖାଏ।

### ସହାୟକଗୁଡ଼ିକ

- `providerUsesExclusiveSyncedListing("cursor"|"cu")` —
  `src/lib/providers/modelListingCapability.ts`

- `ensureCursorAutoCatalogEntry` — ଆବିଷ୍କାର + ତାଲିକାଭୁକ୍ତକରଣ ସମୟରେ auto* ଇଞ୍ଜେକ୍ସନ୍
- `shouldSuppressStaticModelForExclusiveListing` — `/v1/models` ସ୍ଥିର ଲୁପ୍

## ପ୍ରଦାନକାରୀ ସୀମା (କୋଟା)

Cursor ପାଇଁ **ବ୍ୟବହାର → ପ୍ରଦାନକାରୀ ସୀମା** PKCE କିମ୍ବା ଟୋକେନ୍
ଆମଦାନୀ ପରେ `api2.cursor.sh`ରେ Bearer APIଗୁଡ଼ିକ
(`GetCurrentPeriodUsage` → ବ୍ୟବହାର ସାରାଂଶ → auth/usage) ବ୍ୟବହାର କରେ।
ପୁରୁଣା IDE-ଆମଦାନୀ ହୋଇଥିବା ସେସନ୍ଗୁଡ଼ିକ ପାଇଁ ପୁରୁଣା cookie/`cursor.com` ଡ୍ୟାସ୍ବୋର୍ଡ ପଥ
ଶେଷ ଫଲ୍ବ୍ୟାକ୍ ଭାବେ ରହିଥାଏ।

ୱିଣ୍ଡୋଗୁଡ଼ିକରେ ସାଧାରଣତଃ **ମୋଟ**, **Auto + Composer**, ଏବଂ **API** ଅନ୍ତର୍ଭୁକ୍ତ ଥାଏ।
ସୀମାଗୁଡ଼ିକ ଖାଲି ଦେଖାଗଲେ, **Cursor ସହିତ ଲଗଇନ୍ କରନ୍ତୁ** ପୁଣି ଚଲାନ୍ତୁ କିମ୍ବା ଟୋକେନ୍ଗୁଡ଼ିକୁ ପୁନଃ-ଆମଦାନୀ କରନ୍ତୁ
(କେବଳ IDE ଆମଦାନୀ ଆଉ ଆବଶ୍ୟକ ନୁହେଁ)।

## ଖାଲି ଟର୍ନ୍ / ବ୍ୟବହାର ସୀମା ଶେଷ

ଯେତେବେଳେ Cursor ଏକ Run ଗ୍ରହଣ କରେ କିନ୍ତୁ କୌଣସି assistant ଟେକ୍ସଟ୍ ଫେରାଏ ନାହିଁ (ପ୍ରିମିୟମ୍
ବ୍ୟବହାର ସୀମା ଶେଷ ହେଲେ ଏହା ସାଧାରଣ), OmniRoute କାର୍ଯ୍ୟୋପଯୋଗୀ **429** (କୋଟା ସଙ୍କେତ) କିମ୍ବା
ନିର୍ଦ୍ଦେଶନା ସହିତ **502** ଦେଖାଏ — କେବଳ “Provider returned empty content” ନୁହେଁ। Streaming
ବିଫଳତା, ଯେପରିକି `not_found: AI Model Not Found` (ବ୍ୟବହାର ୱିଣ୍ଡୋ ଶେଷ),କୁ
**Cursor ହାର ସୀମା / ବ୍ୟବହାର ଅତିକ୍ରମ** ଭାବେ ବର୍ଗୀକୃତ କରାଯାଏ ଏବଂ SSE ପାଇପ୍ଲାଇନ୍ ମାଧ୍ୟମରେ ସେହି ବାର୍ତ୍ତାକୁ
ବଜାୟ ରଖାଯାଏ (ସହଭାଗୀ ଖାଲି-stream guard ପୂର୍ବରୁ ନିର୍ଗତ ହୋଇଥିବା ତ୍ରୁଟିକୁ ଓଭର୍ରାଇଟ୍ କରେ ନାହିଁ)।
ପ୍ରଦାନକାରୀ ସୀମା ଯାଞ୍ଚ କରନ୍ତୁ, **`auto`** ମଡେଲ୍ ଚେଷ୍ଟା କରନ୍ତୁ, କିମ୍ବା Cursor ପ୍ଲାନ୍ ସୀମା ବଢ଼ାନ୍ତୁ।

## କ୍ଲାଏଣ୍ଟ ସଂସ୍କରଣ (ହେଡ୍ଲେସ୍)

ଏକ ସ୍ଥାନୀୟ `cursor-agent` ଇନଷ୍ଟଲେସନ୍ ବିନା, OmniRoute
ପ୍ରଥମେ env `CURSOR_AGENT_CLI_VERSION`, ତା’ପରେ Cursor ଇନଷ୍ଟଲର୍ ସ୍କ୍ରିପ୍ଟର ଏକ disk-cached
scrape, ଏବଂ ଶେଷରେ ଏକ pinned build id ମାଧ୍ୟମରେ `x-cursor-client-version` ସମାଧାନ କରେ।
ଆବଶ୍ୟକ ହେଲେ `CURSOR_AGENT_CLI_VERSION` ଦ୍ୱାରା ଓଭର୍ରାଇଡ୍ କରନ୍ତୁ।

## ଫଲ୍ବ୍ୟାକ୍: ମାନୁଆଲ୍ ଟୋକେନ୍ ଆମଦାନୀ

ଆପଣ ବ୍ରାଉଜର୍ ଲଗଇନ୍ ସମ୍ପୂର୍ଣ୍ଣ କରିପାରୁ ନଥିଲେ:

1. ହୋଷ୍ଟରେ Cursorର `state.vscdb`ରୁ ଟୋକେନ୍ଗୁଡ଼ିକ ବାହାର କରନ୍ତୁ:

   ```bash
   sqlite3 "$HOME/Library/Application Support/Cursor/User/globalStorage/state.vscdb" \
     "SELECT key, value FROM ItemTable WHERE key IN ('cursorAuth/accessToken','cursorAuth/refreshToken','storage.serviceMachineId');"
   ```

2. Cursor auth ମୋଡାଲ୍ରେ **ଟୋକେନ୍ ଆମଦାନୀ କରନ୍ତୁ** ଖୋଲନ୍ତୁ।
3. **ଆକ୍ସେସ୍ ଟୋକେନ୍** ଏବଂ ଉପଲବ୍ଧ ଥିଲେ **ରିଫ୍ରେଶ୍ ଟୋକେନ୍** ପେଷ୍ଟ କରନ୍ତୁ (ସ୍ୱୟଂଚାଳିତ
   ରିଫ୍ରେଶ୍ ପାଇଁ ଆବଶ୍ୟକ)। Machine ID ଇଚ୍ଛାଧୀନ।

କେବଳ ଆକ୍ସେସ୍-ଟୋକେନ୍ ଆମଦାନୀ ଏବେ ମଧ୍ୟ କାମ କରେ, କିନ୍ତୁ ରିଫ୍ରେଶ୍ ଟୋକେନ୍ ବିନା ଏହାର ମିଆଦ ଶେଷ ହେବ —
ଚାଟ୍ ପ୍ରମାଣୀକରଣ ତ୍ରୁଟି ଫେରାଇଲେ ପୁନଃ-ଆମଦାନୀ କରନ୍ତୁ।
