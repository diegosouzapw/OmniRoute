OmniRoute, ଚାଟ୍ର ସମାନ ପ୍ରଦାନକାରୀ id `cursor` (ଉପନାମ `cu`) ମାଧ୍ୟମରେ `POST /v1/images/generations` ଉପରେ Cursor ପ୍ଲାନ୍ର **ପ୍ରତିଛବି ଉତ୍ପାଦନ** ଉପଲବ୍ଧ କରାଏ।

| କ୍ଷେତ୍ର              | ମୂଲ୍ୟ                                                                           |
| -------------------- | ------------------------------------------------------------------------------- |
| `IMAGE_PROVIDERS` id | `cursor`                                                                        |
| ଫର୍ମାଟ୍              | `cursor-agent-image`                                                            |
| ପ୍ରାମାଣିକରଣ          | ଚାଟ୍ ସହ ସମାନ OAuth / API-key ସଂଯୋଗ (`provider_connections.provider = "cursor"`) |
| ମଡେଲ୍ଗୁଡ଼ିକ          | `cursor/auto`, `cursor/composer-2`, `cursor/composer-2.5`                       |

## Agent CLI କାହିଁକି

OmniRoute ମଧ୍ୟରେ Cursor ଚାଟ୍ `agent.v1.AgentService/Run` (protobuf) ବ୍ୟବହାର କରେ। ସେହି ପଥ ବିଲ୍ଟ-ଇନ୍ କ୍ଲାଏଣ୍ଟ ଟୁଲ୍ଗୁଡ଼ିକୁ (shell, write, …) **ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ**। ପ୍ରତିଛବି ଉତ୍ପାଦନ ହେଉଛି ଏକ Cursor-ନେଟିଭ୍ ଟୁଲ୍, ଯାହା seat ବିପକ୍ଷରେ **`agent` CLI** ଦ୍ୱାରା ନିଷ୍ପାଦିତ ହୁଏ। ତେଣୁ ପ୍ରତିଛବି ହ୍ୟାଣ୍ଡଲର୍ ଏକ ଲକ୍ କରାଯାଇଥିବା ପ୍ରମ୍ପ୍ଟ ଏବଂ ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ପାଇଁ ଏକ ଅସ୍ଥାୟୀ workspace (କମ୍ୟୁନିଟି seat bridgeଗୁଡ଼ିକ ସହ ସମାନ ଗଠନ) ସହିତ `agent` ସ୍ପନ୍ କରେ, ତା’ପରେ OpenAI-ସୁସଙ୍ଗତ `b64_json` ଫେରାଏ।

## ପ୍ରବେଶ ପ୍ରତିବନ୍ଧକ (Hard Rules #15 + #17)

ଏହା ହେଉଛି ଏକମାତ୍ର `IMAGE_PROVIDERS` ଫର୍ମାଟ୍ ଯାହା ଏକ ଚାଇଲ୍ଡ ପ୍ରୋସେସ୍ (`agent`
ବାଇନାରି) ସ୍ପନ୍ କରେ। ଯେହେତୁ `POST /v1/images/generations` ପ୍ରାୟ 40ଟି ଅନ୍ୟ,
ସ୍ପନ୍ ନ କରୁଥିବା ପ୍ରତିଛବି ପ୍ରଦାନକାରୀଙ୍କ ଦ୍ୱାରା ଅଂଶୀଦାର ଭାବେ ବ୍ୟବହୃତ ହୁଏ, ଯାହାକୁ ଦୂରସ୍ଥ କଲର୍ମାନେ ବୈଧ ଭାବେ ବ୍ୟବହାର କରନ୍ତି, ସମ୍ପୂର୍ଣ୍ଣ ରୁଟ୍ଟିକୁ
`LOCAL_ONLY` ଭାବେ ଶ୍ରେଣୀବଦ୍ଧ କରାଯାଇନାହିଁ — ଏହା ପରିବର୍ତ୍ତେ `handleCursorAgentImageGeneration` ନିଜସ୍ୱ
ଗେଟ୍ ପ୍ରୟୋଗ କରେ, ଯେଉଁଥିରେ authz ପାଇପ୍ଲାଇନ୍ ପ୍ରତ୍ୟେକ ଅନୁରୋଧରେ ଷ୍ଟାମ୍ପ କରୁଥିବା ବିଶ୍ୱସନୀୟ `AUTHZ_HEADER_PEER_LOCALITY` ନିଷ୍ପତ୍ତି
(ପ୍ରକୃତ TCP peer ଠାରୁ, କେବେ ମଧ୍ୟ spoof କରାଯାଇପାରୁଥିବା `Host` header ଠାରୁ ନୁହେଁ) ବ୍ୟବହାର ହୁଏ: କେବଳ
`loopback` ଏବଂ `lan` କଲର୍ମାନେ spawn ପର୍ଯ୍ୟନ୍ତ ପହଞ୍ଚିପାରିବେ; ଅନ୍ୟ ସମସ୍ତଙ୍କୁ (ଏଥିରେ ଏକ public tunnel ମାଧ୍ୟମରେ ପୁନଃଚାଳିତ
ଲିକ୍ ହୋଇଥିବା API key ମଧ୍ୟ ଅନ୍ତର୍ଭୁକ୍ତ) କୌଣସି credential lookup କିମ୍ବା
process spawn ହେବା ପୂର୍ବରୁ `403` ମିଳିବ। ଅବଶିଷ୍ଟ `LOCAL_ONLY` ସ୍ତରରେ ପ୍ରୟୋଗ କରାଯାଇଥିବା ସମାନ
ନୀତି ପାଇଁ `src/server/authz/policies/management.ts` ଦେଖନ୍ତୁ।

## Concurrency gate ହେଉଛି ମଡ୍ୟୁଲ୍-ସ୍ତରୀୟ (ଏକକ-instance ସୀମାବଦ୍ଧତା)

`CURSOR_IMG_MAX_CONCURRENT`କୁ
Node ମଡ୍ୟୁଲ୍ instance (`open-sse/handlers/imageGeneration/providers/cursorAgentImage.ts`) ମଧ୍ୟରେ ସୀମିତ ଏକ in-memory counter/queue ଦ୍ୱାରା ପ୍ରୟୋଗ କରାଯାଏ।
ଏହା ଗୋଟିଏ OmniRoute process ମଧ୍ୟରେ ସମସାମୟିକ `agent` spawnଗୁଡ଼ିକୁ ସଠିକ୍ ଭାବେ ସୀମିତ କରେ, କିନ୍ତୁ ସମାନ Cursor seat ଅଂଶୀଦାର କରୁଥିବା
ଏକାଧିକ process/instance ମଧ୍ୟରେ ସମନ୍ୱୟ **କରେ ନାହିଁ**
(ଉଦାହରଣ ସ୍ୱରୂପ, ଏକ multi-replica deployment) — ପ୍ରତ୍ୟେକ instance ନିଜର ସ୍ୱାଧୀନ ସୀମା ପ୍ରୟୋଗ କରେ।
ଏକ single-instance deployment (ଡିଫଲ୍ଟ) ପାଇଁ ଏହା ସଠିକ୍; horizontally scaled
deploymentଗୁଡ଼ିକ ପ୍ରତ୍ୟେକ instance ପାଇଁ `CURSOR_IMG_MAX_CONCURRENT`କୁ ସଂଯତ ରଖିବା କିମ୍ବା
Cursor ପ୍ରତିଛବି trafficକୁ ଗୋଟିଏ instanceକୁ route କରିବା ଉଚିତ।

## ଆବଶ୍ୟକତାଗୁଡ଼ିକ

1. ଡ୍ୟାସ୍ବୋର୍ଡରେ ଏକ ସଂଯୁକ୍ତ Cursor ଆକାଉଣ୍ଟ (OAuth କିମ୍ବା `crsr_…` API key)।
2. OmniRoute process ପାଇଁ Cursor Agent ବାଇନାରି ଉପଲବ୍ଧ ଥିବା ଆବଶ୍ୟକ:
   - env `CURSOR_AGENT_BIN=/path/to/agent`, କିମ୍ବା
   - `~/.local/bin/agent`, କିମ୍ବା
   - Cursor connection ଉପରେ `providerSpecificData.agentBin`।

ଇଚ୍ଛାଧୀନ ଟ୍ୟୁନିଂ:

| Env                         | ଡିଫଲ୍ଟ                  | ଅର୍ଥ                            |
| --------------------------- | ----------------------- | ------------------------------- |
| `CURSOR_IMG_TIMEOUT_MS`     | `210000`                | ପ୍ରତି ପ୍ରତିଛବି wall clock       |
| `CURSOR_IMG_MAX_CONCURRENT` | `2`                     | Shared-seat concurrency gate    |
| `CURSOR_IMG_MODEL`          | (ଅନୁରୋଧ ମଡେଲ୍ / `auto`) | CLI `--model`କୁ override କରନ୍ତୁ |

## ଉଦାହରଣ

```bash
curl -sS https://<host>/v1/images/generations \
  -H "Authorization: Bearer <omni-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor/auto","prompt":"a lantern in fog","size":"1024x1024"}'
```

ଉତ୍ପାଦନ ସାଧାରଣତଃ 1–2 ମିନିଟ୍ ନିଏ। ଏକ ଆଭ୍ୟନ୍ତରୀଣ network pathକୁ ପ୍ରାଥମିକତା ଦିଅନ୍ତୁ; ପ୍ରାୟ 100s timeout ଥିବା edge proxyଗୁଡ଼ିକ ବିଫଳ ହେବ।
