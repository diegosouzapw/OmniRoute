`chatgpt-web-codex` (ଉପନାମ `cgpt-codex`) ଏକ ପ୍ରମାଣୀକୃତ ChatGPT ବ୍ରାଉଜର୍ ସେସନ୍ ମାଧ୍ୟମରେ Codex Responses ଟର୍ଣ୍ଣଗୁଡ଼ିକୁ
ସଂଯୋଗ କରେ। ଏହା ଅବସରପ୍ରାପ୍ତ ସାଧାରଣ `chatgpt-web` ପ୍ରଦାନକାରୀଠାରୁ ସ୍ୱାଧୀନ ଏବଂ
`open-sse/vendor/codex-chatgpt-web/` ଅଧୀନରେ MIT ସୂଚନାଯୁକ୍ତ କାର୍ଯ୍ୟାନ୍ୱୟନ ବ୍ୟବହାର କରେ, ଯାହାକୁ
ଅପସ୍ଟ୍ରିମ୍ v4.0.7 କମିଟ୍ `b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494` ମାଧ୍ୟମରେ
ସତେଜ କରାଯାଇଛି।

## ସାଧାରଣ ପ୍ରଦାନକାରୀର ଅବସରଗ୍ରହଣ

ପୂର୍ବତନ ସାଧାରଣ ପ୍ରଦାନକାରୀ ID `chatgpt-web` ଏବଂ `cgpt-web` ଆଉ ବିତରଣ କରାଯାଉନାହିଁ, କାରଣ ସେମାନଙ୍କ
ପ୍ରି-କି/ପ୍ରୁଫ୍-ଅଫ୍-ୱର୍କ କାର୍ଯ୍ୟାନ୍ୱୟନର ଉତ୍ସ-ପ୍ରମାଣ ସ୍ପଷ୍ଟ କରାଯାଇପାରିଲା ନାହିଁ। ସ୍ଲାଶ୍-ଉପସର୍ଗଯୁକ୍ତ ମଡେଲ୍ ID ଏବଂ ସ୍ଥାୟୀ ଭାବେ ସଂରକ୍ଷିତ ଉପନାମ ସମେତ
ଯେକୌଣସି ID ପ୍ରତି ସ୍ପଷ୍ଟ ଅନୁରୋଧ, କୌଣସି ଅପସ୍ଟ୍ରିମ୍ ଅନୁରୋଧ ପୂର୍ବରୁ HTTP `410` ଏବଂ
କୋଡ୍ **PROVIDER_RETIRED** ସହିତ ବନ୍ଦ ହୋଇ ବିଫଳ ହୁଏ।

ମାଇଗ୍ରେସନ୍ `168_retire_chatgpt_web.sql` ମେଳ ଖାଉଥିବା ପ୍ରଦାନକାରୀ ସଂଯୋଗଗୁଡ଼ିକୁ ଟୁମ୍ଷ୍ଟୋନ୍ କରେ ଏବଂ
ସେମାନଙ୍କ ସକ୍ରିୟ ସେସନ୍ ଲିଜ୍ଗୁଡ଼ିକୁ ଅବୈଧ କରେ। ଏହା ସଂଯୋଗ ଇତିହାସ ଏବଂ API-କି
ଅନୁମୋଦିତ ତାଲିକାଗୁଡ଼ିକୁ ସଂରକ୍ଷିତ ରଖେ; ଏହା କୌଣସି ଅନୁମୋଦିତ ତାଲିକାରେ ପ୍ରତିସ୍ଥାପନ ଆକ୍ସେସ୍ ଯୋଡ଼େ ନାହିଁ। Codex ପ୍ରଦାନକାରୀ ଏବଂ
ଏହାର ସଂଯୋଗଗୁଡ଼ିକ ଏହି ଅବସରଗ୍ରହଣ ସହିତ ମେଳ ଖାଏ ନାହିଁ।

## ପୂର୍ବାବଶ୍ୟକତା

- ସାଇନ୍-ଇନ୍ କରାଯାଇଥିବା ChatGPT ସେସନ୍ରୁ ଏକ ସମ୍ପୂର୍ଣ୍ଣ Cookie ହେଡର୍;
- npm, systemd, ଏବଂ PM2 ଇନ୍ଷ୍ଟଲେସନ୍ ପାଇଁ Chrome କିମ୍ବା Chromium ସହିତ ଏକ ଗ୍ରାଫିକାଲ୍ ସେସନ୍ କିମ୍ବା Xvfb ଡିସ୍ପ୍ଲେ;
- Docker `web` ପ୍ରୋଫାଇଲ୍ ସହିତ, `docker-compose.yml`ର ଆଭ୍ୟନ୍ତରୀଣ Chromium ସେବା;
- ସ୍ଥାନୀୟ Codex ଟୁଲ୍ଗୁଡ଼ିକ ପାଇଁ OpenAI `tunnel-client` v0.0.13 ଏବଂ ଏକ ChatGPT କଷ୍ଟମ୍ କନେକ୍ଟର୍।

ଟନେଲ୍ କେବଳ ଟୁଲ୍ ଟର୍ଣ୍ଣଗୁଡ଼ିକ ପାଇଁ ଆବଶ୍ୟକ। `pro` ସମେତ ତାଲିକାଭୁକ୍ତ ପ୍ରତ୍ୟେକ ରୁଟ୍,
ଟନେଲ୍ ଏବଂ କନେକ୍ଟର୍ କନଫିଗର୍ କରାଯାଇଥିଲେ ସମାନ ଟର୍ଣ୍ଣ-ଆବଦ୍ଧ ସ୍ଥାନୀୟ ଟୁଲ୍ କ୍ଷମତା ବ୍ୟବହାର କରିପାରିବ।

## ଡ୍ୟାସ୍ବୋର୍ଡ ସେଟ୍ଅପ୍

1. **ChatGPT Web (Codex)** ପ୍ରଦାନକାରୀ ଖୋଲନ୍ତୁ ଏବଂ ଏକ ସଂଯୋଗ ଯୋଡ଼ନ୍ତୁ।
2. ସମ୍ପୂର୍ଣ୍ଣ ChatGPT Cookie ହେଡର୍, ଟନେଲ୍ ID, ରନ୍ଟାଇମ୍ କି, ଏବଂ କଷ୍ଟମ୍ କନେକ୍ଟର୍
   ନାମ ପେଷ୍ଟ କରନ୍ତୁ। ନୂତନ ଟୁଲ୍-କ୍ଷମ ସେଟ୍ଅପ୍ଗୁଡ଼ିକ ଠିକ୍ `OmniRoute Codex v2` ନାମରେ
   ଏକ ନୂଆ ସୃଷ୍ଟି ହୋଇଥିବା କନେକ୍ଟର୍ ବ୍ୟବହାର କରିବା ଆବଶ୍ୟକ, ଯେଉଁଥିରେ Authentication କୁ None ଏବଂ Permissions କୁ Allow all
   actions ଭାବେ ସେଟ୍ କରାଯାଇଥିବ।
3. ସଂଯୋଗ ଯାଞ୍ଚ ଚଳାନ୍ତୁ। OmniRoute ଏକ ବ୍ରାଉଜର୍-ସମର୍ଥିତ Temporary Chat ଖୋଲେ ଏବଂ
   ଆକାଉଣ୍ଟ ପାଇଁ Sol ଏବଂ Pro ଉପଲବ୍ଧ କି ନାହିଁ ଚିହ୍ନଟ କରେ।
4. ସଂଯୋଗଟି ସଂରକ୍ଷଣ କରନ୍ତୁ। OmniRoute ପେଷ୍ଟ କରାଯାଇଥିବା କୁକିକୁ ଯାଞ୍ଚିତ
   Playwright ଷ୍ଟୋରେଜ୍ ସ୍ଥିତି ସହିତ ପ୍ରତିସ୍ଥାପନ କରେ ଏବଂ ଏନ୍କ୍ରିପ୍ଟେଡ୍
   କ୍ରେଡେନ୍ସିଆଲ୍ ଅବ୍ଷ୍ଟ୍ରାକ୍ସନ୍ ମାଧ୍ୟମରେ ରନ୍ଟାଇମ୍ କି ସହିତ ଏହାକୁ ସଂରକ୍ଷଣ କରେ।

ସଫଳ ଭାବରେ ସଂରକ୍ଷଣ ପରେ କଞ୍ଚା କୁକି ରଖାଯାଏ ନାହିଁ। ସେସନ୍ର ମିଆଦ ଶେଷ ହେଲେ,
ସଂଯୋଗଟି ଖୋଲନ୍ତୁ, ଏକ ନୂଆ ସମ୍ପୂର୍ଣ୍ଣ Cookie ହେଡର୍ ପେଷ୍ଟ କରନ୍ତୁ, ଏବଂ ଯାଞ୍ଚଟି ପୁଣି ଚଳାନ୍ତୁ। ସମ୍ପାଦନା ଡାଏଲଗ୍ରେ ଥିବା ଡକ୍ଟର୍ ସ୍ଥିତି
ବ୍ରାଉଜର୍, ଷ୍ଟୋରେଜ୍ ସ୍ଥିତି, ସାଇନ୍-ଇନ୍, Temporary Chat, ଟନେଲ୍,
କନେକ୍ଟର୍, ଏବଂ ଟୁଲ୍ ରାଉଣ୍ଡ-ଟ୍ରିପ୍କୁ ପୃଥକ ଭାବରେ ରିପୋର୍ଟ କରେ।

> କେବେବି ପ୍ରକୃତ କୁକି, ରନ୍ଟାଇମ୍ କି, ଷ୍ଟୋରେଜ୍ ସ୍ଥିତି, କିମ୍ବା କ୍ଷମତା ଟୋକନ୍ କମିଟ୍ କରନ୍ତୁ ନାହିଁ। ପରୀକ୍ଷଣ ଏବଂ
> ଡକ୍ୟୁମେଣ୍ଟେସନ୍ ମୂଲ୍ୟଗୁଡ଼ିକ ସର୍ବଦା ପ୍ଲେସ୍ହୋଲ୍ଡର୍ ହେବା ଆବଶ୍ୟକ।

ଚୟନିତ ବ୍ରାଉଜର୍ ମୋଡ୍କୁ ନିରବରେ ପରିବର୍ତ୍ତନ କରିବା ପରିବର୍ତ୍ତେ ବନ୍ଦ ହୋଇ ବିଫଳ ହୁଏ।

ପୁରୁଣା `Codex Native` କିମ୍ବା `OmniRoute Codex` କନେକ୍ଟର୍କୁ ପୁନଃନାମକରଣ କିମ୍ବା ପୁନଃବ୍ୟବହାର କରନ୍ତୁ ନାହିଁ। ChatGPT
କନେକ୍ଟର୍ ପରିଚୟ ଆଧାରରେ ସାର୍ବଜନୀନ MCP ଚୁକ୍ତିକୁ କ୍ୟାଶ୍ କରେ, ଯେତେବେଳେ ସତେଜ ହୋଇଥିବା ବ୍ରିଜ୍ ଏକ
ନୂଆ ସିଧାସଳଖ ଟର୍ଣ୍ଣ-ଟୋକନ୍ ଚୁକ୍ତି ବ୍ୟବହାର କରେ। ରନ୍ଟାଇମ୍ ସେହି ପୁରୁଣା ପରିଚୟଗୁଡ଼ିକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ ଏବଂ
ଏକ ନୂଆ `OmniRoute Codex v2` କନେକ୍ଟର୍ ଆବଶ୍ୟକ କରେ।

## ସୁରକ୍ଷା ମଡେଲ୍

- ନେଟିଭ୍ ପଥ ପାଇଁ ଏକ Responses ଅନୁରୋଧ, ଏକ ସ୍ୱୀକୃତ Codex କ୍ଲାଏଣ୍ଟ ଏବଂ ମେଳ ଖାଉଥିବା
  ଥ୍ରେଡ୍ ଓ ଟର୍ନ ପରିଚୟ ଆବଶ୍ୟକ।
- ୱର୍କସ୍ପେସ୍, ସ୍ୟାଣ୍ଡବକ୍ସ, ଅନୁମୋଦନ ନୀତି ଏବଂ ଟୁଲ୍ କ୍ୟାଟାଲଗ୍ ନେଟିଭ୍ Codex ସେଲ୍ରୁ ଆସେ;
  ଏଗୁଡ଼ିକ ପାଇଁ ମୁକ୍ତ-ରୂପୀ ପ୍ରମ୍ପ୍ଟ ଟେକ୍ସଟ୍ କର୍ତ୍ତୃପକ୍ଷ ନୁହେଁ।
- ChatGPT ପ୍ରତି ଟର୍ନ ପାଇଁ କେବଳ ଏକ ସ୍ୱଳ୍ପକାଳୀନ କ୍ଷମତା ପ୍ରାପ୍ତ କରେ। MCP ବ୍ରୋକର୍ କେବଳ
  ସେହି ନିର୍ଦ୍ଦିଷ୍ଟ ଟର୍ନରେ Codex ପ୍ରଦାନ କରିଥିବା ଟୁଲ୍ଗୁଡ଼ିକୁ ଗ୍ରହଣ କରେ।
- **Allow once**କୁ ସ୍ୱୟଂଚାଳିତ ଭାବେ ନିଶ୍ଚିତ କରିବା କେବଳ ଟୁଲ୍ ଅନୁରୋଧକୁ Codexକୁ ଫେରାଇଦିଏ। କେବଳ Codex
  ଅନୁମୋଦନ ଏବଂ ନିଷ୍ପାଦନ ବିଷୟରେ ନିଷ୍ପତ୍ତି ନିଏ।
- ପ୍ରଥମ ଆଉଟପୁଟ୍ ପୂର୍ବରୁ, ଏକ କମ୍ବୋ ଅନ୍ୟ ଏକ ସୁସଙ୍ଗତ ଟାର୍ଗେଟ୍କୁ ଫଲ୍ବ୍ୟାକ୍ କରିପାରେ। ଆଉଟପୁଟ୍
  ଆରମ୍ଭ ହେବା ପରେ, ଟର୍ନ ସମ୍ପୂର୍ଣ୍ଣ ହେବା ପର୍ଯ୍ୟନ୍ତ ପ୍ରଦାତା, ମଡେଲ୍, ସଂଯୋଗ ଏବଂ ବ୍ରାଉଜର୍ ଟର୍ନ ପିନ୍ ହୋଇ ରହେ।
- କୁକି, ରନ୍ଟାଇମ୍ କି, ଷ୍ଟୋରେଜ୍ ଅବସ୍ଥା ଏବଂ କ୍ଷମତା ଟୋକେନ୍ଗୁଡ଼ିକ ପ୍ରଦାତା
  ପ୍ରତିକ୍ରିୟା କିମ୍ବା ଅନୁରୋଧ ଲଗ୍ରେ ଦେଖାଯାଏ ନାହିଁ।

## ଡିସ୍ପ୍ଲେବିହୀନ VPS ଏବଂ Docker

npm, systemd ଏବଂ PM2 ଇନ୍ଷ୍ଟଲେସନ୍ ପାଇଁ, OmniRoute ସାଧାରଣ Chrome ଏବଂ Chromium ପଥଗୁଡ଼ିକୁ ଚିହ୍ନଟ କରେ।
ବିକଳ୍ପ ଭାବେ, `CHATGPT_WEB_CODEX_CHROME_PATH` ସେଟ୍ କରନ୍ତୁ। ରନ୍ଟାଇମ୍ ଟର୍ନଗୁଡ଼ିକ ଜାଣିଶୁଣି ହେଡେଡ୍
Chrome ବ୍ୟବହାର କରେ, କାରଣ ChatGPT ପ୍ରକୃତ-ହେଡ୍ଲେସ୍ ବ୍ରାଉଜର୍ ଆକୃତିକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ। ତେଣୁ ଏକ ଡିସ୍ପ୍ଲେବିହୀନ ହୋଷ୍ଟକୁ
ଏକ ବ୍ୟକ୍ତିଗତ Xvfb ଡିସ୍ପ୍ଲେ ସହ OmniRoute ଚଳାଇବାକୁ ପଡ଼ିବ; କେବଳ Chrome ପଥ ସେଟ୍ କରିବା ଦ୍ୱାରା ଡିସ୍ପ୍ଲେ ଉପଲବ୍ଧ ହୁଏ ନାହିଁ।

Docker `web` ପ୍ରୋଫାଇଲ୍ ଆଭ୍ୟନ୍ତରୀଣ Compose
ନେଟୱର୍କରେ `chatgpt-web-codex-browser` ଆରମ୍ଭ କରେ। ସାଇଡ୍କାର୍ Xvfb ମଧ୍ୟରେ ହେଡେଡ୍ Chrome ଚଳାଏ, ତେଣୁ କୌଣସି ଭୌତିକ ଡିସ୍ପ୍ଲେ ଆବଶ୍ୟକ ହୁଏ ନାହିଁ। ଏହାର CDP
ପୋର୍ଟ ହୋଷ୍ଟରେ ପ୍ରକାଶିତ ହୁଏ ନାହିଁ। ସୁରକ୍ଷିତ ବ୍ରାଉଜର୍ ପ୍ରୋଫାଇଲ୍ ଭଲ୍ୟୁମ୍ OmniRoute ଡାଟା ଭଲ୍ୟୁମ୍ରୁ ପୃଥକ ଅଟେ, ଏବଂ ବ୍ରାଉଜର୍ ପର୍ଯ୍ୟାପ୍ତ ସେୟାର୍ଡ ମେମୋରି ପ୍ରାପ୍ତ କରେ। ଆଭ୍ୟନ୍ତରୀଣ CDP ପ୍ରକ୍ସି
Compose ନେଟୱର୍କ ଭିତରେ କେବଳ `9223` ପୋର୍ଟରେ ଲିସେନ୍ କରେ; ସାଇଡ୍କାର୍ରେ Chrome ଲୁପ୍ବ୍ୟାକ୍ରେ ବାଇଣ୍ଡ୍ ହୋଇ ରହେ।

`DATA_DIR` ଅଧୀନରେ ଥିବା ଏକ ସୁପରଭାଇଜର୍ ଲିଜ୍ ଏକାଧିକ OmniRoute ପ୍ରକ୍ରିୟାକୁ
ସମାନ ଟନେଲ୍ ଏବଂ ବ୍ରୋକର୍ ଅବସ୍ଥାର ମାଲିକ ହେବାରୁ ରୋକେ। କୌଣସି ବିବାଦ ଥିଲେ ଡକ୍ଟର୍ ତାହା ରିପୋର୍ଟ କରେ।

## ଇଣ୍ଟରାକ୍ଟିଭ୍ ପୁନରୁଦ୍ଧାର

ସ୍ୱୟଂଚାଳିତ Docker ପଥରେ ହୋଷ୍ଟକୁ ଦୃଶ୍ୟମାନ କୌଣସି ୱିଣ୍ଡୋ ନାହିଁ, କିନ୍ତୁ ବ୍ୟକ୍ତିଗତ Xvfb ଡିସ୍ପ୍ଲେ ଭିତରେ Chrome ନିଜେ ହେଡେଡ୍ ଭାବେ ଚାଲେ। ChatGPTକୁ ଯେତେବେଳେ ଏକ ଇଣ୍ଟରାକ୍ଟିଭ୍ ସାଇନ୍-ଇନ୍ କିମ୍ବା ଚ୍ୟାଲେଞ୍ଜ ଆବଶ୍ୟକ ହୁଏ, ପୁନରୁଦ୍ଧାର ପାଇଁ ବିଦ୍ୟମାନ VNC
ବ୍ରାଉଜର୍ ଢାଞ୍ଚା ବ୍ୟବହାର କରାଯାଇପାରେ। ବ୍ରାଉଜର୍ UI ଏବଂ CDP କେବଳ
ଲୁପ୍ବ୍ୟାକ୍, ଏକ ପ୍ରମାଣିତ ପରିଚାଳନା ସଂଯୋଗ, କିମ୍ବା ଏକ SSH ଟନେଲ୍ ମାଧ୍ୟମରେ ପହଞ୍ଚଯୋଗ୍ୟ ରହିବା ଆବଶ୍ୟକ; ସାଧାରଣ କାର୍ଯ୍ୟ ସମୟରେ noVNC ଅକ୍ଷମ ରହେ।
