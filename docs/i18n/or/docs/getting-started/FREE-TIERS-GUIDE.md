> **TL;DR**: ନିଜର ଯୋଗ୍ୟ ପ୍ରଦାତା ଆକାଉଣ୍ଟଗୁଡ଼ିକ ବ୍ୟବହାର କରନ୍ତୁ। OmniRoute ଆପଣ କନଫିଗର୍ କରିଥିବା ସଂଯୋଗଗୁଡ଼ିକୁ ଏକତ୍ର କରେ; ଏହା ବିଜ୍ଞାପିତ ସମୁଦାୟ ଟୋକେନ୍ ବଜେଟ୍ ପ୍ରଦାନ କରେ ନାହିଁ। ମାଗଣା ଆକ୍ସେସ୍ ପାଇଁ ସାଇନ୍ ଅପ୍, ଏକ API କୀ, ଅନୁମୋଦନ କିମ୍ବା ଏକ ପେମେଣ୍ଟ ପଦ୍ଧତି ଆବଶ୍ୟକ ହୋଇପାରେ। ପ୍ରଦାତାଙ୍କ ସୀମା, ଗୋପନୀୟତା ନୀତି ଏବଂ ସର୍ତ୍ତାବଳୀ ଏଥିରେ ମଧ୍ୟ ପ୍ରଯୁଜ୍ୟ।

## ମାଗଣା ସ୍ତରଗୁଡ଼ିକ କ’ଣ?

ଅନେକ AI ପ୍ରଦାନକାରୀ କୌଣସି ନା କୌଣସି ପ୍ରକାରର **ମାଗଣା ପ୍ରବେଶ** ପ୍ରଦାନ କରନ୍ତି। ପ୍ରଦାନକାରୀଙ୍କ ଉପରେ ନିର୍ଭର କରି, ଏହାର ଅର୍ଥ ପ୍ରମାଣୀକରଣ-ବିହୀନ ଏଣ୍ଡପଏଣ୍ଟ, ପୁନରାବୃତ୍ତ କୋଟା, ହାର-ସୀମିତ ଅସୀମିତ ପ୍ରବେଶ, ସାଇନ୍ଅପ୍ ଅନୁଦାନ, ମାନୁଆଲ୍ ଅନୁମୋଦନ କିମ୍ବା ଏକ ଅସ୍ଥାୟୀ ପ୍ରଚାର ହୋଇପାରେ। କେତେକ ବିକଳ୍ପ ପାଇଁ ଏକ ଆକାଉଣ୍ଟ, API କୀ, କ୍ରେଡିଟ୍ କାର୍ଡ, KYC କିମ୍ବା ପ୍ରଦାନକାରୀ-ନିର୍ଦ୍ଦିଷ୍ଟ ସର୍ତ୍ତାବଳୀର ସ୍ୱୀକୃତି ଆବଶ୍ୟକ ହୁଏ।

OmniRoute ବିନ୍ୟାସିତ ସଂଯୋଗଗୁଡ଼ିକୁ ଗୋଟିଏ ଏଣ୍ଡପଏଣ୍ଟରେ **ଏକତ୍ରିତ** କରେ। ଆକାଉଣ୍ଟ ଆବଶ୍ୟକ କରୁଥିବା ପ୍ରତ୍ୟେକ ପ୍ରଦାନକାରୀଙ୍କ ପାଇଁ ଆପଣଙ୍କୁ ତଥାପି ପୃଥକ ଭାବେ ସାଇନ୍ଅପ୍ କରିବାକୁ ପଡ଼ିବ। ସେହି ଆକାଉଣ୍ଟଗୁଡ଼ିକୁ ସଂଯୋଗ କରନ୍ତୁ ଏବଂ ଯୋଗ୍ୟ ଲକ୍ଷ୍ୟଗୁଡ଼ିକ ମଧ୍ୟରେ ରାଉଟ୍ କରିବା ପାଇଁ `model: "auto"` ବ୍ୟବହାର କରନ୍ତୁ। ଏକ ନୂତନ ଇନ୍ଷ୍ଟଲେସନ୍ରେ କୌଣସି ଯୋଗ୍ୟ କୀ-ବିହୀନ ଲକ୍ଷ୍ୟ ନଥାଇପାରେ; କେବଳ OmniRoute ଇନ୍ଷ୍ଟଲ୍ କରିବା ଏକ ସଫଳ ଚାଟ୍ ପ୍ରତିକ୍ରିୟାର ଗ୍ୟାରେଣ୍ଟି ଦିଏ ନାହିଁ।

## ମାଗଣା ଟିୟରଗୁଡ଼ିକୁ କିପରି ଷ୍ଟାକ୍ କରିବେ

- ଯଦି କି ବିନା ଥିବା ପ୍ରଦାନକାରୀ ଉପଲବ୍ଧ ନଥାଏ → ଅବଶିଷ୍ଟ ଲକ୍ଷ୍ୟଗୁଡ଼ିକୁ କ୍ରମାନୁସାରେ ଚେଷ୍ଟା କରିବ

ଏବଂ ToS ମେଟାଡାଟା ଯାଞ୍ଚ କରନ୍ତୁ। ପ୍ରଦାନକାରୀ କାର୍ଡ ଏବଂ

ଏକ `NOAUTH` ପ୍ରଦାନକାରୀ ପାଇଁ, OmniRoute କୌଣସି ଅପ୍ଷ୍ଟ୍ରିମ୍ ପ୍ରମାଣପତ୍ର ଅନୁରୋଧ କରେ ନାହିଁ। ଏହା ଅପ୍ଷ୍ଟ୍ରିମ୍ଟି ତୃତୀୟ-ପକ୍ଷ କ୍ଲାଏଣ୍ଟମାନଙ୍କୁ ଗ୍ରହଣ କରେ କିମ୍ବା ସେଠାରେ ଉପଲବ୍ଧ କ୍ଷମତା ଅଛି ବୋଲି ନିଶ୍ଚିତ କରେ ନାହିଁ। OAuth ଏବଂ API-key ପ୍ରଦାନକାରୀମାନଙ୍କୁ ସେମାନଙ୍କର ଦସ୍ତାବିଜଭୁକ୍ତ ଆକାଉଣ୍ଟ ପ୍ରବାହ ମାଧ୍ୟମରେ ସଂଯୋଗ କରିବା ଆବଶ୍ୟକ। ରାଉଟର୍ ପ୍ରାମାଣିକରଣ ସକ୍ଷମ ଥିବାବେଳେ ମଧ୍ୟ ଆପଣଙ୍କ କ୍ଲାଏଣ୍ଟ **ଡ୍ୟାସବୋର୍ଡ → ଏଣ୍ଡପଏଣ୍ଟସ୍**ରେ ଦର୍ଶାଯାଇଥିବା OmniRoute API କି ବ୍ୟବହାର କରେ।

  ନିଶ୍ଚିତତା ଦିଏ ନାହିଁ।
- `hasFree` ହେଉଛି ସନ୍ଧାନ-ସମ୍ବନ୍ଧୀୟ ମେଟାଡାଟା। ଏହା ଏକ ପୁନରାବୃତ୍ତ କୋଟା, କୀ-ବିହୀନ ପ୍ରବେଶ,
  ସାଇନ୍ଅପ୍ କ୍ରେଡିଟ୍, ଅନୁମୋଦନ କାର୍ଯ୍ୟକ୍ରମ କିମ୍ବା ପ୍ରଚାରକୁ ସୂଚାଇପାରେ।
- `recurring-uncapped`ର ଅର୍ଥ ହେଉଛି କୌଣସି ପ୍ରକାଶିତ ଟୋକନ୍ ସର୍ବୋଚ୍ଚ ସୀମା ଉପଲବ୍ଧ ନଥିଲା; ତଥାପି ହାର ଏବଂ
  ସମସାମୟିକତା ସୀମା ପ୍ରଯୁଜ୍ୟ ରହିବ।
- `one-time-initial` ସାଇନ୍ଅପ୍ ଅନୁଦାନ ବ୍ୟବହାର ହୋଇସାରିବା ପରେ ପୁନରାବୃତ୍ତ ହୁଏ ନାହିଁ।
- `tos: avoid` ପ୍ରଦାନକାରୀମାନଙ୍କୁ ଡିଫଲ୍ଟ ଭାବରେ ସ୍ୱୟଂଚାଳିତ ରାଉଟିଂରୁ ବାଦ ଦିଆଯାଏ (`excludeTosAvoid`)। ଏକ ଆକାଉଣ୍ଟ ସଂଯୋଗ କରିବା ଦ୍ୱାରା ଏହି ଫିଲ୍ଟର୍କୁ ଏଡ଼ାଇ ହୁଏ ନାହିଁ। ଅପରେଟରଙ୍କ ଯେକୌଣସି ଓଭର୍ରାଇଡ୍ ପ୍ରଦାନକାରୀଙ୍କ ସର୍ତ୍ତାବଳୀ ଏବଂ ଆକାଉଣ୍ଟ ବିପଦର ସମୀକ୍ଷା ପରେ କରାଯିବା ଉଚିତ।
- `discontinued` ଭାବେ ଚିହ୍ନିତ ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ ଐତିହାସିକ ପ୍ରମାଣ ଭାବେ ରହିଥାଏ ଏବଂ ସେଗୁଡ଼ିକୁ
  ବର୍ତ୍ତମାନ ମାଗଣା ଭାବେ ଉପସ୍ଥାପନ କରାଯିବା ଉଚିତ ନୁହେଁ।

## OmniRoute କିପରି ମାଗଣା ଟିୟରଗୁଡ଼ିକୁ ଅଧିକ ଉନ୍ନତ କରେ

### 1. ସ୍ୱୟଂଚାଳିତ ଫଲ୍ବ୍ୟାକ୍

ଯଦି ଗୋଟିଏ ମାଗଣା ପ୍ରଦାନକାରୀ ବ୍ୟସ୍ତ କିମ୍ବା ବନ୍ଦ ଥାଏ, OmniRoute ସ୍ୱୟଂଚାଳିତ ଭାବେ ପରବର୍ତ୍ତୀ ପ୍ରଦାନକାରୀକୁ ଚେଷ୍ଟା କରେ। ଆପଣଙ୍କୁ କିଛି କରିବା ଆବଶ୍ୟକ ନାହିଁ।

### 2. ସ୍ମାର୍ଟ ରାଉଟିଂ

OmniRoute ନିମ୍ନଲିଖିତ ଆଧାରରେ ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ପାଇଁ **ସର୍ବୋତ୍ତମ ମାଗଣା ପ୍ରଦାନକାରୀ** ବାଛେ:

- ଗତି — ବର୍ତ୍ତମାନ କେଉଁ ପ୍ରଦାନକାରୀ ସବୁଠାରୁ ଦ୍ରୁତ?
- ଗୁଣବତ୍ତା — ଏହି କାର୍ଯ୍ୟ ପାଇଁ କେଉଁ ପ୍ରଦାନକାରୀ ସର୍ବୋତ୍ତମ?
- କ୍ଷମତା — କେଉଁ ପ୍ରଦାନକାରୀଙ୍କ ପାଖରେ କୋଟା ଅବଶିଷ୍ଟ ଅଛି?

### 3. ଟୋକେନ୍ ସଞ୍ଚୟ

OmniRouteର କମ୍ପ୍ରେସନ୍ ପାଇପ୍ଲାଇନ୍ ଯୋଗ୍ୟ ପ୍ରମ୍ପ୍ଟ ଏବଂ ଟୁଲ୍-ଆଉଟ୍ପୁଟ୍ ଟୋକେନ୍ଗୁଡ଼ିକୁ କମାଇପାରେ।
ପ୍ରକୃତ ସଞ୍ଚୟ ବିଷୟବସ୍ତୁ, ଚୟନିତ ଇଞ୍ଜିନ୍, ପ୍ରଦାନକାରୀଙ୍କ ହିସାବ ପଦ୍ଧତି ଏବଂ ବିଶ୍ୱସ୍ତତା
ସେଟିଂସ୍ ଉପରେ ନିର୍ଭର କରେ; କମ୍ପ୍ରେସନ୍ ପ୍ରତ୍ୟେକ ପ୍ରଦାନକାରୀଙ୍କ କୋଟାକୁ ଏକ ନିର୍ଦ୍ଦିଷ୍ଟ ଗୁଣକରେ ବଢ଼ାଏ ନାହିଁ।

### 4. ଏକାଧିକ-ଆକାଉଣ୍ଟ ସମର୍ଥନ

ଯଦି ପ୍ରଦାନକାରୀଙ୍କ ସର୍ତ୍ତାବଳୀ ଏକାଧିକ ଆକାଉଣ୍ଟ କିମ୍ବା ପ୍ରମାଣପତ୍ରକୁ ଅନୁମତି ଦିଏ, OmniRoute ପ୍ରତ୍ୟେକ
ସଂଯୋଗକୁ ଏକ ପୃଥକ ରାଉଟିଂ ପ୍ରାର୍ଥୀ ଭାବେ ବିବେଚନା କରିପାରେ। ପ୍ରଦାନକାରୀଙ୍କ କୋଟା କିମ୍ବା ଆକ୍ସେସ୍ ନୀତିକୁ ଏଡ଼ାଇବା ପାଇଁ ଅତିରିକ୍ତ ଆକାଉଣ୍ଟ ସୃଷ୍ଟି କରନ୍ତୁ ନାହିଁ।

## ସାଧାରଣ ପ୍ରଶ୍ନ

### "ଏହା ପ୍ରକୃତରେ ମାଗଣା କି?"

କ୍ୟାଟାଲଗ୍ରେ ପ୍ରଦାନକାରୀଙ୍କ ଦ୍ୱାରା ପ୍ରକାଶିତ ସର୍ତ୍ତାବଳୀ ଏବଂ ପ୍ରକଳ୍ପ ଗବେଷଣା ରେକର୍ଡ କରାଯାଏ, କିନ୍ତୁ ଅଫର୍ଗୁଡ଼ିକ ପରିବର୍ତ୍ତିତ ହୋଇପାରେ।
ବ୍ୟବହାର ପୂର୍ବରୁ ପ୍ରଦାନକାରୀଙ୍କ ବର୍ତ୍ତମାନର ମୂଲ୍ୟ, କୋଟା, ଗୋପନୀୟତା ନୀତି ଏବଂ ଯୋଗ୍ୟତା ଯାଞ୍ଚ କରନ୍ତୁ।

### "ମାଗଣା ଟିୟର୍ ଶେଷ ହୋଇଯିବ କି?"

ପ୍ରତ୍ୟେକ ପ୍ରଦାନକାରୀ ହାର-ସୀମା ଲାଗୁ କରିପାରନ୍ତି, ମଡେଲ୍ ପରିବର୍ତ୍ତନ କରିପାରନ୍ତି, ଆକ୍ସେସ୍ ସ୍ଥଗିତ କରିପାରନ୍ତି କିମ୍ବା ଅଫ୍ଲାଇନ୍ ହୋଇପାରନ୍ତି। ଏକାଧିକ
ସଂଯୋଗ ଫଲ୍ବ୍ୟାକ୍ କଭରେଜ୍କୁ ଉନ୍ନତ କରେ, କିନ୍ତୁ ଏକ ଉପଲବ୍ଧ ମାଗଣା ରୁଟ୍ର ଗ୍ୟାରେଣ୍ଟି ଦିଏ ନାହିଁ।

### "ମୁଁ ଉତ୍ପାଦନ ପାଇଁ ମାଗଣା ପ୍ରଦାନକାରୀଙ୍କୁ ବ୍ୟବହାର କରିପାରିବି କି?"

କେବଳ ପ୍ରଦାନକାରୀଙ୍କ SLA, ଡାଟା ପରିଚାଳନା, ସୀମା ଏବଂ ସର୍ତ୍ତାବଳୀ ଆପଣଙ୍କ ଉତ୍ପାଦନ
ଆବଶ୍ୟକତା ପୂରଣ କରୁଥିଲେ। ଗୁରୁତ୍ୱପୂର୍ଣ୍ଣ ୱର୍କଲୋଡ୍ ପାଇଁ ନିରୀକ୍ଷଣ କରାଯାଉଥିବା, ଚୁକ୍ତିଗତ ଭାବେ ଉପଯୁକ୍ତ ଫଲ୍ବ୍ୟାକ୍ ରହିବା ଉଚିତ।

### "ଏଥିରେ ଅସୁବିଧା କ’ଣ?"

ଏଥିରେ ଥିବା ବିନିମୟଗୁଡ଼ିକ ମଧ୍ୟରେ କଠୋର ସୀମା, ପ୍ରତୀକ୍ଷା ତାଲିକା, KYC, କ୍ରେଡିଟ୍-କାର୍ଡ ଯାଞ୍ଚ, ପ୍ରମ୍ପ୍ଟ ଉପରେ
ପ୍ରଶିକ୍ଷଣ, ଦୁର୍ବଳ ଗୋପନୀୟତା, SLAର ଅନୁପସ୍ଥିତି, ବାରମ୍ବାର ମଡେଲ୍ ପରିବର୍ତ୍ତନ, ଭୌଗୋଳିକ ପ୍ରତିବନ୍ଧକ, ଦେୟଯୁକ୍ତ ଅତିରିକ୍ତ ବ୍ୟବହାର କିମ୍ବା
ଆକାଉଣ୍ଟ-ନୀତି ସମ୍ବନ୍ଧୀୟ ବିପଦ ଅନ୍ତର୍ଭୁକ୍ତ ହୋଇପାରେ। OmniRoute ଉପଲବ୍ଧ ମେଟାଡାଟା ପ୍ରଦର୍ଶନ କରେ; କ’ଣ ସକ୍ଷମ କରିବେ ତାହା ଆପଣ ବାଛନ୍ତି।

### "ମୁଁ କିପରି ଅଧିକ ମାଗଣା କୋଟା ପାଇପାରିବି?"

1. ଅଧିକ ମାଗଣା ପ୍ରଦାନକାରୀଙ୍କୁ ସଂଯୋଗ କରନ୍ତୁ
2. ଉପଯୁକ୍ତ କମ୍ପ୍ରେସନ୍ ଇଞ୍ଜିନ୍ଗୁଡ଼ିକ ସକ୍ଷମ କରନ୍ତୁ ଏବଂ ଆପଣଙ୍କ ୱର୍କଲୋଡ୍ ପାଇଁ ସଞ୍ଚୟ ମାପନ୍ତୁ
3. ମାଗଣା/ଶସ୍ତା ପ୍ରଦାନକାରୀଙ୍କୁ ପ୍ରାଥମିକତା ଦେବା ପାଇଁ `auto/cheap` ବ୍ୟବହାର କରନ୍ତୁ
4. ପ୍ରଦାନକାରୀଙ୍କ ସର୍ତ୍ତାବଳୀ ଉଲ୍ଲଂଘନ ନ କରି ଅତିରିକ୍ତ ଅନୁମୋଦିତ ପ୍ରଦାନକାରୀ କିମ୍ବା ପରିଚୟପତ୍ର ଯୋଡ଼ନ୍ତୁ

### "ମାଗଣା ପ୍ରଦାନକାରୀଙ୍କ ଗୁଣବତ୍ତା ଖରାପ କି?"

ଅବଶ୍ୟ ନୁହେଁ। କିଛି ପ୍ରଦାନକାରୀ ଦେୟଯୁକ୍ତ ରୁଟ୍ଗୁଡ଼ିକ ମାଧ୍ୟମରେ ଉପଲବ୍ଧ ସମାନ ମଡେଲ୍ ପରିବାରଗୁଡ଼ିକୁ ପ୍ରଦାନ କରନ୍ତି,
କିନ୍ତୁ ସୀମା, ବିଳମ୍ବତା, ଗୋପନୀୟତା, ନିର୍ଭରଯୋଗ୍ୟତା ଏବଂ ମଡେଲ୍ ସଂସ୍କରଣ ଭିନ୍ନ ହୋଇପାରେ। ଗୁଣବତ୍ତାର ଏକ ସଙ୍କେତ ଭାବେ
ମାଗଣା ପ୍ରଦାନକାରୀ ରାଙ୍କିଙ୍ଗ୍ ପୃଷ୍ଠା ବ୍ୟବହାର କରନ୍ତୁ ଏବଂ ବାସ୍ତବରେ ପ୍ରଦାନ କରାଯାଉଥିବା ମଡେଲ୍ଟିକୁ ଯାଞ୍ଚ କରନ୍ତୁ।
