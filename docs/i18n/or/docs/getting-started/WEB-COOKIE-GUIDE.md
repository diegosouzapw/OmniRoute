Web Cookie ପ୍ରଦାନକାରୀମାନେ OmniRouteକୁ API key ପରିବର୍ତ୍ତେ ଆପଣଙ୍କ ବର୍ତ୍ତମାନର ବ୍ରାଉଜର ସେସନ୍ ମାଧ୍ୟମରେ ଏକ AI ସେବା ବ୍ୟବହାର କରିବାକୁ ଦିଅନ୍ତି। ଯେତେବେଳେ ଆପଣଙ୍କ ପାଖରେ ପୂର୍ବରୁ କୌଣସି ସେବାର ୱେବସାଇଟ୍ ମାଧ୍ୟମରେ ପ୍ରବେଶାଧିକାର ଥାଏ ଏବଂ OmniRoute ସେହି ପ୍ରମାଣିତ ସେସନ୍କୁ ବ୍ୟବହାର କରୁ ବୋଲି ଚାହାନ୍ତି, ସେତେବେଳେ ଏଗୁଡ଼ିକ ଉପଯୋଗୀ।

API-key ପ୍ରଦାନକାରୀଙ୍କ ତୁଳନାରେ, Web Cookie ପ୍ରଦାନକାରୀମାନେ ଆପଣଙ୍କ ବ୍ରାଉଜର ୱେବସାଇଟ୍କୁ ପଠାଉଥିବା ପ୍ରମାଣପତ୍ର ବ୍ୟବହାର କରି ପ୍ରମାଣୀକରଣ କରନ୍ତି।

# ଆରମ୍ଭ କରିବା ପୂର୍ବରୁ

> **ଗୁରୁତ୍ୱପୂର୍ଣ୍ଣ:** ସର୍ବଦା ଏକ **ସକ୍ରିୟ ନେଟୱର୍କ ଅନୁରୋଧ**ରୁ ପ୍ରମାଣପତ୍ର କପି କରନ୍ତୁ, ଆପଣଙ୍କ ବ୍ରାଉଜରର cookie ସଂରକ୍ଷଣରୁ **ନୁହେଁ**।

ଭୁଲ୍ ସ୍ଥାନରୁ cookies କପି କରିବା ଯୋଗୁଁ ଅନେକ ପ୍ରମାଣୀକରଣ ସମସ୍ୟା ହୋଇଥାଏ।

## Cookie ସଂରକ୍ଷଣରୁ କପି କରନ୍ତୁ ନାହିଁ

ଅଧିକାଂଶ ବ୍ରାଉଜର ଏଠାରେ ସଂରକ୍ଷିତ cookies ଦେଖାଇଥାଏ:

```
DevTools
→ Application (କିମ୍ବା Storage)
→ Cookies
```

ଏହି cookies ସଠିକ୍ ଦେଖାଯାଉଥିଲେ ମଧ୍ୟ, ସେଗୁଡ଼ିକ ହୋଇପାରେ:

- ପୁରୁଣା
- ଅସମ୍ପୂର୍ଣ୍ଣ
- କେବଳ ପ୍ରମାଣିତ ଅନୁରୋଧରେ ପଠାଯାଉଥିବା cookies ଅନୁପସ୍ଥିତ ଥିବା

ଏହି ମୂଲ୍ୟଗୁଡ଼ିକ ବୈଧ ଦେଖାଯାଉଥିଲେ ମଧ୍ୟ, ସେଗୁଡ଼ିକୁ ବ୍ୟବହାର କଲେ ପ୍ରମାଣୀକରଣ ବିଫଳ ହୋଇପାରେ।

## ଏକ ସକ୍ରିୟ ଅନୁରୋଧରୁ କପି କରନ୍ତୁ

ଏହା ପରିବର୍ତ୍ତେ, ଏକ ସଫଳ ଅନୁରୋଧରୁ cookies ବ୍ୟବହାର କରନ୍ତୁ:

```
DevTools
→ Network
→ ପୃଷ୍ଠାକୁ ରିଫ୍ରେଶ୍ କରନ୍ତୁ
→ ଏକ chat କିମ୍ବା conversation ଅନୁରୋଧ ଖୋଲନ୍ତୁ
→ Request Headers
→ Cookie
```

`Cookie` ଅନୁରୋଧ headerରେ ଆପଣଙ୍କ ବ୍ରାଉଜର ସଫଳତାର ସହିତ ବ୍ୟବହାର କରିଥିବା ସଠିକ୍ ପ୍ରମାଣୀକରଣ ସୂଚନା ରହିଥାଏ।

ଅଧିକାଂଶ Web Cookie ପ୍ରଦାନକାରୀଙ୍କ ପାଇଁ, ଏହି ମୂଲ୍ୟକୁ OmniRouteରେ ପେଷ୍ଟ କରିବା ଉଚିତ।

# ସାଧାରଣ ସେଟଅପ୍

ଅଧିକାଂଶ Web Cookie ପ୍ରଦାନକାରୀଙ୍କ ପାଇଁ ସେଟଅପ୍ ପ୍ରକ୍ରିୟା ସମାନ।

1. ପ୍ରଦାନକାରୀଙ୍କ ୱେବସାଇଟ୍ରେ ସାଇନ୍ ଇନ୍ କରନ୍ତୁ।
2. ବ୍ରାଉଜରର Developer Tools ଖୋଲନ୍ତୁ।
3. **Network** ଟ୍ୟାବ୍ ଖୋଲନ୍ତୁ।
4. ପୃଷ୍ଠାକୁ ରିଫ୍ରେଶ୍ କରନ୍ତୁ।
5. ଏକ ପ୍ରମାଣିତ chat କିମ୍ବା conversation ଅନୁରୋଧ ଖୋଲନ୍ତୁ।
6. ଆବଶ୍ୟକ ପ୍ରମାଣୀକରଣ ପ୍ରମାଣପତ୍ର କପି କରନ୍ତୁ।
7. OmniRoute ଖୋଲନ୍ତୁ।
8. **Providers → Add Provider**କୁ ଯାଆନ୍ତୁ।
9. ଆପଣଙ୍କ Web Cookie ପ୍ରଦାନକାରୀକୁ ଚୟନ କରନ୍ତୁ।
10. ପ୍ରମାଣପତ୍ରଗୁଡ଼ିକୁ ପେଷ୍ଟ କରନ୍ତୁ।
11. **Test Connection**ରେ କ୍ଲିକ୍ କରନ୍ତୁ।
12. ପ୍ରଦାନକାରୀକୁ ସେଭ୍ କରନ୍ତୁ।

ଆବଶ୍ୟକ ନିର୍ଦ୍ଦିଷ୍ଟ ପ୍ରମାଣପତ୍ରଗୁଡ଼ିକ ପ୍ରଦାନକାରୀ ଉପରେ ନିର୍ଭର କରେ।

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) ହେଉଛି ଏକ ମାଗଣା ଉପଭୋକ୍ତା ଚାଟ୍ ପ୍ଲାଟଫର୍ମ, ଯେଉଁଥିରେ ସାଇନ୍ଅପ୍ ଆବଶ୍ୟକ ନାହିଁ — ପ୍ରଥମ ଥର ପରିଦର୍ଶନ କଲେ ସେସନ୍ଟି ଅଜ୍ଞାତ ଭାବରେ ସୃଷ୍ଟି ହୁଏ ଏବଂ ତିନୋଟି କୁକି ମାଧ୍ୟମରେ ବଜାୟ ରହେ: `uid`, `si_usr_id`, ଏବଂ `si_ses_id`। OmniRoute ଗୋଟିଏ ମାତ୍ର ମଡେଲ୍ ଆଇଡି (`notrack-c`, ଉପନାମ `ntw`) ମାଧ୍ୟମରେ ସେହି ଏକା `/api/dispatch` ଏଣ୍ଡପଏଣ୍ଟକୁ ପ୍ରକ୍ସି କରେ।

### ସଂଯୋଗ କରିବାର ପଦକ୍ଷେପ

1. ଆପଣଙ୍କ ବ୍ରାଉଜର୍ରେ [notrack.ai](https://notrack.ai) ଖୋଲନ୍ତୁ ଏବଂ ଅଜ୍ଞାତ ସେସନ୍ କୁକିକୁ ସେଟ୍ ହେବାକୁ ଦିଅନ୍ତୁ।
2. **DevTools → Network** ଖୋଲନ୍ତୁ, ପୃଷ୍ଠାକୁ ରିଫ୍ରେଶ୍ କରନ୍ତୁ, ଏବଂ ଯେକୌଣସି `/api` ଅନୁରୋଧରେ କ୍ଲିକ୍ କରନ୍ତୁ।
3. **Request Headers** ମଧ୍ୟରେ, ସମ୍ପୂର୍ଣ୍ଣ `Cookie` ହେଡର୍ ମୂଲ୍ୟ କପି କରନ୍ତୁ।
4. OmniRoute ମଧ୍ୟରେ **Providers → Add Provider → NoTrack Web (Free)** କୁ ଯାଆନ୍ତୁ।
5. କୁକି ଷ୍ଟ୍ରିଙ୍ଗ୍କୁ `apiKey` ଫିଲ୍ଡରେ ପେଷ୍ଟ କରନ୍ତୁ ଏବଂ **Save** କରନ୍ତୁ।

OmniRoute ପେଷ୍ଟ କରାଯାଇଥିବା ଷ୍ଟ୍ରିଙ୍ଗ୍ରୁ `uid`, `si_usr_id`, ଏବଂ `si_ses_id` ବାହାର କରେ ଏବଂ କେବଳ ସେହି ଯୁଗଳଗୁଡ଼ିକ ସହିତ ଏକ ପରିଷ୍କାର `Cookie` ହେଡର୍ ପୁନଃନିର୍ମାଣ କରେ — ଏହା ସହିତ ଉପସ୍ଥିତ ଥିଲେ `nt_session` (ଲଗ୍ଇନ୍ ହୋଇଥିବା ଆକାଉଣ୍ଟଗୁଡ଼ିକ ପାଇଁ ସେଟ୍ ହୋଇଥିବା `ntk_…` ଟୋକେନ୍) ମଧ୍ୟ ଯୋଡ଼ାଯାଏ। ଯଦି ତିନୋଟି ମଧ୍ୟରୁ କୌଣସିଟି ଅନୁପସ୍ଥିତ ଥାଏ, ତେବେ ଅପରେଟର୍ମାନେ ବିକଳ୍ପ ଗଠନ ସହିତ ପରୀକ୍ଷା କରିପାରିବା ପାଇଁ ପେଷ୍ଟ କରାଯାଇଥିବା ମୂଳ ଷ୍ଟ୍ରିଙ୍ଗ୍କୁ ଅପରିବର୍ତ୍ତିତ ଭାବରେ ଫରୱାର୍ଡ କରାଯାଏ।

### କ୍ଷମତାଗୁଡ଼ିକ

- **ଷ୍ଟ୍ରିମିଂ ଏବଂ ଅଣ-ଷ୍ଟ୍ରିମିଂ** ଚାଟ୍ ସମାପ୍ତିଗୁଡ଼ିକ।
- **ଟୁଲ୍ କଲିଂ** — ଅନୁରୋଧରେ `tools: [...]` ସେଟ୍ କରନ୍ତୁ; ଏକ୍ଜିକ୍ୟୁଟର୍ ସେଗୁଡ଼ିକୁ ଏକ ଟୁଲ୍-କଲ୍ ଏନ୍ଭେଲପ୍ ଚୁକ୍ତିରେ ସିରିଆଲାଇଜ୍ କରେ ଏବଂ ମଡେଲ୍ର ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକୁ ପୁଣି OpenAI `tool_calls` ଭାବରେ ପାର୍ସ କରେ।
- **`response_format`** — `json_object` ଏବଂ `json_schema` ସମର୍ଥିତ। ଏକ୍ଜିକ୍ୟୁଟର୍ ମଡେଲ୍ର ଉତ୍ତରରୁ ପ୍ରଥମ JSON ଅବଜେକ୍ଟ ବାହାର କରେ ଏବଂ ଫେରାଇବା ପୂର୍ବରୁ ଏହାକୁ ଷ୍ଟ୍ରିଙ୍ଗ୍ରେ ପରିଣତ କରେ।
- **ରିଜନିଂ ସୂଚନା** — ଅପ୍ଷ୍ଟ୍ରିମ୍ ଏକ `thinking` ଇଭେଣ୍ଟ ପଠାଇଲେ ଏକ୍ଜିକ୍ୟୁଟର୍ ଏକ `reasoning` ଡେଲ୍ଟା ନିର୍ଗତ କରେ।

### ସୀମାବଦ୍ଧତାଗୁଡ଼ିକ

- ଅପ୍ଷ୍ଟ୍ରିମ୍ ଅଜ୍ଞାତ ବ୍ୟବହାର କୋଟା ଲାଗୁ କରେ — ଏହା ଅତିକ୍ରମ ହେଲେ, ଏକ୍ଜିକ୍ୟୁଟର୍ ଏକ ବ୍ୟବହାରକାରୀ-ଅନୁକୂଳ ସନ୍ଦେଶ ସହିତ 429 ପ୍ରଦର୍ଶନ କରେ।
- ସମସ୍ତ ମଡେଲ୍ ଆଇଡି ସମାନ ଅପ୍ଷ୍ଟ୍ରିମ୍ ଡିସ୍ପାଚ୍ ମଡେଲ୍କୁ ସୂଚାଏ; ପ୍ରତି-ମଡେଲ୍ ସୁଇଚ୍ ନାହିଁ।
- ଏକ୍ଜିକ୍ୟୁଟର୍ ଅପ୍ଷ୍ଟ୍ରିମ୍ର `/api/chats` ଏଣ୍ଡପଏଣ୍ଟକୁ କଲ୍ କରେ ନାହିଁ, ତେଣୁ ଚାଟ୍ ଇତିହାସ / ସେସନ୍ଗୁଡ଼ିକ ସ୍ୱୟଂଚାଳିତ ଭାବରେ ପରିଚାଳିତ ହୁଏ ନାହିଁ। ଏକ ବିଦ୍ୟମାନ ଅପ୍ଷ୍ଟ୍ରିମ୍ ଚାଟ୍ ପୁନଃଆରମ୍ଭ କରିବାକୁ `notrack_chat_id` ବ୍ୟବହାର କରନ୍ତୁ।

# ୱେବ୍ କୁକି ପ୍ରଦାନକାରୀମାନେ କ’ଣ କରିପାରନ୍ତି ଏବଂ କ’ଣ କରିପାରନ୍ତି ନାହିଁ

ୱେବ୍ କୁକି ପ୍ରଦାନକାରୀମାନେ ଏକ ୱେବ୍ସାଇଟ୍ର ଚାଟ୍ ଇଣ୍ଟରଫେସ୍କୁ ପୁନଃବ୍ୟବହାର କରନ୍ତି। ସେମାନେ ଆଧିକାରିକ APIଗୁଡ଼ିକ ପରି ସମାନ କ୍ଷମତା ପ୍ରଦାନ କରନ୍ତି **ନାହିଁ**।

## ସମର୍ଥିତ

- ଆପଣଙ୍କ ବର୍ତ୍ତମାନର ବ୍ରାଉଜର୍ ସେସନ୍ ବ୍ୟବହାର କରି ପ୍ରାମାଣୀକରଣ କରନ୍ତୁ
- ଆପଣଙ୍କ ଆକାଉଣ୍ଟ ମାଧ୍ୟମରେ ଉପଲବ୍ଧ ମଡେଲ୍ଗୁଡ଼ିକୁ ଆକ୍ସେସ୍ କରନ୍ତୁ
- ଚାଟ୍ ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକୁ ଷ୍ଟ୍ରିମ୍ କରନ୍ତୁ
- କୌଣସି API କୀ ଆବଶ୍ୟକ ନାହିଁ

## ସମର୍ଥିତ ନୁହେଁ

- ଫଙ୍କସନ୍ କଲିଂ
- ଟୁଲ୍ କଲିଂ
- ସ୍ୱୟଂଚାଳିତ ଫାଇଲ୍ ସମ୍ପାଦନ
- ଏଜେଣ୍ଟିକ୍ IDE କାର୍ଯ୍ୟପ୍ରବାହ
- କେବଳ-API ବୈଶିଷ୍ଟ୍ୟଗୁଡ଼ିକ

ଏହା ଆଶାକରାଯାଇଥିବା ଆଚରଣ ଏବଂ ଏହା **କୌଣସି** ବଗ୍ ନୁହେଁ।

ଯଦି ଆପଣଙ୍କୁ ଟୁଲ୍ ନିଷ୍ପାଦନ, ସ୍ୱୟଂଚାଳିତ ଫାଇଲ୍ ସମ୍ପାଦନ କିମ୍ବା ଅନ୍ୟାନ୍ୟ ଏଜେଣ୍ଟ କାର୍ଯ୍ୟପ୍ରବାହ ଆବଶ୍ୟକ, ତେବେ Web Cookie ପ୍ରଦାନକାରୀ ପରିବର୍ତ୍ତେ ଏକ **API-key ପ୍ରଦାନକାରୀ** ବ୍ୟବହାର କରନ୍ତୁ।

ଏକ ସଫଳ **ସଂଯୋଗ ପରୀକ୍ଷା** କିମ୍ବା କୁକି ବୈଧତା ଯାଞ୍ଚ କେବଳ ଏହା ଯାଞ୍ଚ କରେ ଯେ ପ୍ରଦତ୍ତ ପରିଚୟପତ୍ରଗୁଡ଼ିକ ଆଶାକରାଯାଇଥିବା ଫର୍ମାଟ୍ରେ ଥିବା ପରି ଦେଖାଯାଉଛି।

Issue #7857 ସମାଧାନ ନହେବା ପର୍ଯ୍ୟନ୍ତ, ଏକ ସଫଳ ବୈଧତା ଯାଞ୍ଚ ପ୍ରଦାନକାରୀ ସଫଳତାର ସହ ପ୍ରାମାଣୀକରଣ କରିବ ବୋଲି **ନିଶ୍ଚିତ କରେ ନାହିଁ**।

ଯଦି ପ୍ରାମାଣୀକରଣ ତଥାପି ବିଫଳ ହୁଏ, ତେବେ ଯାଞ୍ଚ କରନ୍ତୁ ଯେ ଆପଣ ବ୍ରାଉଜର୍ କୁକି ଷ୍ଟୋରେଜ୍ ପରିବର୍ତ୍ତେ ଏକ ସକ୍ରିୟ ନେଟୱର୍କ ଅନୁରୋଧରୁ ପରିଚୟପତ୍ରଗୁଡ଼ିକ କପି କରିଛନ୍ତି।

# ସମସ୍ୟା ନିବାରଣ

ଯାଞ୍ଚ କରନ୍ତୁ ଯେ ପରିଚୟପତ୍ରଗୁଡ଼ିକ ଏଠାରୁ କପି କରାଯାଇଛି:

ଏବଂ ଏଠାରୁ **ନୁହେଁ**:

```
ଆପ୍ଲିକେସନ୍

```

## ସେସନ୍ର ଅବଧି ସମାପ୍ତ ହୋଇଛି

Web Cookie ପ୍ରଦାନକାରୀମାନେ ଆପଣଙ୍କ ବର୍ତ୍ତମାନର ବ୍ରାଉଜର୍ ସେସନ୍ ବ୍ୟବହାର କରନ୍ତି।

ଯଦି ଆପଣଙ୍କ ବ୍ରାଉଜର୍ ସେସନ୍ର ଅବଧି ସମାପ୍ତ ହୁଏ କିମ୍ବା ଆପଣ ସାଇନ୍ ଆଉଟ୍ କରନ୍ତି, ତେବେ ଆପଣଙ୍କୁ ଏକ ନୂତନ ପରିଚୟପତ୍ର ସେଟ୍ କପି କରିବାକୁ ପଡ଼ିବ। ସମର୍ଥିତ ୱେବ୍ ପ୍ରଦାନକାରୀଙ୍କ ପାଇଁ କୁକି ନବୀକରଣ ସ୍ୱୟଂଚାଳିତ କରିବାକୁ, ସହାୟକ ଟୁଲ୍ [ବ୍ରାଉଜର୍ ସେସନ୍ ସିଙ୍କ୍ ଏକ୍ସଟେନ୍ସନ୍](../guides/SESSION-SYNC-EXTENSION.md) ଦେଖନ୍ତୁ।

## ସଂଯୋଗ ପରୀକ୍ଷା ସଫଳ ହୁଏ କିନ୍ତୁ ଅନୁରୋଧଗୁଡ଼ିକ ବିଫଳ ହୁଏ

Issue #7857 ସମାଧାନ ନହେବା ପର୍ଯ୍ୟନ୍ତ, ବୈଧତା ଯାଞ୍ଚରେ ସଫଳତା ପ୍ରାମାଣୀକରଣ ଅନୁରୋଧ ସଫଳ ହେବ ବୋଲି ନିଶ୍ଚିତ କରେ ନାହିଁ।

ଆଗକୁ ସମସ୍ୟା ନିବାରଣ କରିବା ପୂର୍ବରୁ ଏକ ନୂତନ ପ୍ରାମାଣୀକୃତ ଅନୁରୋଧରୁ ଆପଣଙ୍କ ପରିଚୟପତ୍ରଗୁଡ଼ିକୁ ପୁଣି କପି କରନ୍ତୁ।

# ପ୍ରଦାନକାରୀ ଉଦାହରଣ

ଏକ ସମ୍ପୂର୍ଣ୍ଣ ପ୍ରଦାନକାରୀ-ନିର୍ଦ୍ଦିଷ୍ଟ ମାର୍ଗଦର୍ଶିକା ପାଇଁ, ଦେଖନ୍ତୁ:

- **Claude Web** — `docs/providers/CLAUDE_WEB.md`

Claude Web ମାର୍ଗଦର୍ଶିକା ଏକ Web Cookie ପ୍ରଦାନକାରୀ ପାଇଁ ସମ୍ପୂର୍ଣ୍ଣ ସେଟ୍ଅପ୍ ପ୍ରକ୍ରିୟା ପ୍ରଦର୍ଶନ କରେ ଏବଂ ସନ୍ଦର୍ଭ କାର୍ଯ୍ୟାନ୍ୱୟନ ଭାବରେ କାର୍ଯ୍ୟ କରେ।

# ସର୍ବୋତ୍ତମ ଅଭ୍ୟାସଗୁଡ଼ିକ

- ଏକ ନୂତନ ପ୍ରାମାଣୀକୃତ ଅନୁରୋଧରୁ ପରିଚୟପତ୍ରଗୁଡ଼ିକ କପି କରନ୍ତୁ।
- ପୁରୁଣା କୁକିଗୁଡ଼ିକୁ ପୁଣି ବ୍ୟବହାର କରିବାରୁ ବିରତ ରୁହନ୍ତୁ।
- Web Cookie ପ୍ରଦାନକାରୀ ବ୍ୟବହାର କରୁଥିବା ସମୟରେ ଆପଣଙ୍କ ବ୍ରାଉଜର୍ ସେସନ୍କୁ ସକ୍ରିୟ ରଖନ୍ତୁ।
- କପି କରାଯାଇଥିବା କୁକିଗୁଡ଼ିକୁ ସମ୍ବେଦନଶୀଳ ପରିଚୟପତ୍ର ଭାବରେ ବିବେଚନା କରନ୍ତୁ।
- ଯେତେବେଳେ ଆପଣଙ୍କୁ ଫଙ୍କସନ୍ କଲିଂ କିମ୍ବା ଏଜେଣ୍ଟ କାର୍ଯ୍ୟପ୍ରବାହ ଆବଶ୍ୟକ, API-key ପ୍ରଦାନକାରୀ ବ୍ୟବହାର କରନ୍ତୁ।
