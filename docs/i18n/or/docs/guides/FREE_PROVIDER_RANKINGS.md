> **TL;DR**: OmniRoute ଏହାର **ମାଗଣା** ପ୍ରଦାନକାରୀମାନଙ୍କୁ ମଡେଲ୍ର ଗୁଣବତ୍ତା ଅନୁସାରେ **Arena AI
> (LMArena-ଶୈଳୀ) ELO ସ୍କୋର୍** ବ୍ୟବହାର କରି ରାଙ୍କ୍ କରେ। ଆପଣଙ୍କ କାର୍ଯ୍ୟ ପାଇଁ କେଉଁ ମାଗଣା ପ୍ରଦାନକାରୀ ସବୁଠାରୁ ଶକ୍ତିଶାଳୀ ମଡେଲ୍ ପ୍ରଦାନ କରନ୍ତି ତାହା ଦେଖିବାକୁ
> ଡ୍ୟାସ୍ବୋର୍ଡ୍ରେ **Free Provider Rankings** ପୃଷ୍ଠା ଖୋଲନ୍ତୁ —
> ସାମଗ୍ରିକ ଭାବରେ କିମ୍ବା ବର୍ଗ ଅନୁସାରେ ଫିଲ୍ଟର୍ କରି (କୋଡିଂ, ସମୀକ୍ଷା, ଡକ୍ୟୁମେଣ୍ଟେସନ୍, ଡିବଗିଂ)।

## ଏହା କ’ଣ

OmniRoute 329ଟି ପ୍ରଦାନକାରୀଙ୍କୁ ପଞ୍ଜୀକୃତ କରେ, ଯେଉଁଥିରେ **free/no-auth** ଭାବେ ଚିହ୍ନିତ 155ଟି କ୍ୟାଟାଲଗ୍ ଏଣ୍ଟ୍ରି ଅନ୍ତର୍ଭୁକ୍ତ
(no-auth,
free-tier OAuth, କିମ୍ବା free-tier API key —
[Free Tiers Guide](../getting-started/FREE-TIERS-GUIDE.md) ଏବଂ ସମ୍ପୂର୍ଣ୍ଣ
[Free Tiers directory](../reference/FREE_TIERS.md) ଦେଖନ୍ତୁ)। ସମସ୍ୟା ହେଉଛି: ମାଗଣା ପ୍ରଦାନକାରୀମାନଙ୍କର
ମଡେଲ୍ ଗୁଣବତ୍ତାରେ ବ୍ୟାପକ ପାର୍ଥକ୍ୟ ରହିଥାଏ। ଏକ ଫ୍ରଣ୍ଟିୟର୍ ମଡେଲ୍ ପ୍ରଦାନ କରୁଥିବା no-auth ପ୍ରଦାନକାରୀ,
ଏକ ଛୋଟ ପୁରୁଣା ମଡେଲ୍ ପ୍ରଦାନ କରୁଥିବା ପ୍ରଦାନକାରୀଠାରୁ ଅଧିକ ଉପଯୋଗୀ।

**Free Provider Rankings**, "**କେଉଁ ମାଗଣା ପ୍ରଦାନକାରୀ ମୋତେ ସର୍ବୋତ୍ତମ ମଡେଲ୍ ଦେଉଛନ୍ତି?**" ପ୍ରଶ୍ନର ଉତ୍ତର
ପ୍ରତ୍ୟେକ ମାଗଣା ପ୍ରଦାନକାରୀଙ୍କ କ୍ୟାଟାଲଗ୍କୁ **Arena AI leaderboard**-ର
**କ୍ରାଉଡ୍-ସୋର୍ସ୍ଡ୍ ଗୁଣବତ୍ତା ସ୍କୋର୍** ସହିତ ଯୋଡ଼ି ଦେଇଥାଏ (ମାନବ-ପସନ୍ଦ ELO, LMArena
ଚାଟ୍ବଟ୍ ଆରେନା ପଛରେ ଥିବା ସମାନ ଧାରଣା)। ତା’ପରେ ପ୍ରଦାନକାରୀମାନଙ୍କୁ ସେମାନଙ୍କର **ସର୍ବୋତ୍ତମ ମାଗଣା ମଡେଲ୍**-ର କ୍ଷମତା ଅନୁସାରେ ରାଙ୍କ୍ କରାଯାଏ।

ଏହି ରାଙ୍କିଂ ତିନୋଟି ବାସ୍ତବ ଉତ୍ସରୁ ଗଣନା କରାଯାଏ:

1. ମାଗଣା-ପ୍ରଦାନକାରୀ ତାଲିକାଗୁଡ଼ିକ — `NOAUTH_PROVIDERS`, ଏବଂ `hasFree` ଭାବେ ଫ୍ଲାଗ୍ ହୋଇଥିବା `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ
   (`src/shared/constants/providers.ts`)।
2. ପ୍ରଦାନକାରୀ ରେଜିଷ୍ଟ୍ରିରୁ ପ୍ରତ୍ୟେକ ପ୍ରଦାନକାରୀଙ୍କ ମଡେଲ୍ କ୍ୟାଟାଲଗ୍
   (`open-sse/config/providerRegistry.ts`)।
3. Arena ELO ସିଙ୍କ୍ ଇଞ୍ଜିନ୍ (`src/lib/arenaEloSync.ts`) ଦ୍ୱାରା `model_intelligence` DB ଟେବୁଲ୍ରେ ସଂରକ୍ଷିତ
   ELO-ରୁ ପ୍ରାପ୍ତ ଟାସ୍କ୍-ଫିଟ୍ ସ୍କୋର୍ଗୁଡ଼ିକ।

ଯୋଡ଼ିବାର ଲଜିକ୍ `src/lib/freeProviderRankings.ts`-ରେ ରହିଛି।

## କିପରି ପ୍ରବେଶ କରିବେ

### ଡ୍ୟାସ୍ବୋର୍ଡ୍ ପୃଷ୍ଠା

ଡ୍ୟାସ୍ବୋର୍ଡ୍ ଖୋଲି **Costs → Free Provider Rankings**-କୁ ଯାଆନ୍ତୁ, କିମ୍ବା ସିଧାସଳଖ ଏଠାକୁ ନେଭିଗେଟ୍ କରନ୍ତୁ:

```
/dashboard/free-provider-rankings
```

ଏହି ପୃଷ୍ଠା (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) ଦେଖାଏ:

- ସର୍ବୋତ୍ତମ ରାଙ୍କ୍ ପାଇଥିବା ମାଗଣା ପ୍ରଦାନକାରୀମାନଙ୍କର ଏକ **ଶୀର୍ଷ-3 ପୋଡିୟମ୍** (🥇 🥈 🥉)।
- ଏହି ସ୍ତମ୍ଭଗୁଡ଼ିକ ସହିତ ଏକ ସମ୍ପୂର୍ଣ୍ଣ **ରାଙ୍କିଂ ଟେବୁଲ୍**: **ରାଙ୍କ୍**, **ପ୍ରଦାନକାରୀ**, **ଶୀର୍ଷ ମଡେଲ୍**,
  **ସ୍କୋର୍**, **ହାରାହାରି ସ୍କୋର୍**, **ମଡେଲ୍ଗୁଡ଼ିକ**, **ପ୍ରକାର**।
- **ବର୍ଗ ଫିଲ୍ଟର୍ ବଟନ୍ଗୁଡ଼ିକ**: _ସମସ୍ତ ବର୍ଗ_, _ଡିଫଲ୍ଟ_, _କୋଡିଂ_, _ସମୀକ୍ଷା_,
  _ଡକ୍ୟୁମେଣ୍ଟେସନ୍_, _ଡିବଗିଂ_।

ପ୍ରତ୍ୟେକ ପ୍ରଦାନକାରୀଙ୍କ **ପ୍ରକାର** ବ୍ୟାଜ୍ ଏହା କିପରି ମାଗଣା ତାହା ଜଣାଏ:

| ବ୍ୟାଜ୍   | ଅର୍ଥ                                               |
| -------- | -------------------------------------------------- |
| `NOAUTH` | ସର୍ବଦା ମାଗଣା, କୌଣସି ପ୍ରମାଣପତ୍ର ଆବଶ୍ୟକ ନାହିଁ        |
| `OAUTH`  | ଏକ ମାଗଣା ଟିୟର୍ (`hasFree`) ଥିବା OAuth ପ୍ରଦାନକାରୀ   |
| `APIKEY` | ଏକ ମାଗଣା ଟିୟର୍ (`hasFree`) ଥିବା API-key ପ୍ରଦାନକାରୀ |

ସ୍କୋର୍ଗୁଡ଼ିକ କଞ୍ଚା ସଂଖ୍ୟା ବଦଳରେ ମଣିଷ ପାଇଁ ସହଜବୋଧ୍ୟ ଲେବଲ୍ (ଯେପରିକି _ଶ୍ରେଷ୍ଠ_, _ଅତ୍ୟୁତ୍ତମ_, _ବହୁତ ଭଲ_,
_ଭଲ_, _ହାରାହାରି_) ଭାବେ ଦେଖାଯାଏ, କାରଣ ଅନ୍ତର୍ନିହିତ ମୂଲ୍ୟଟି ଏକ ଆପେକ୍ଷିକ
ରାଙ୍କିଂ ଗୁଣବତ୍ତା, ଶତକଡ଼ା ନୁହେଁ।

### API ଏଣ୍ଡପଏଣ୍ଟ୍

ଏହି ପୃଷ୍ଠାଟି ଏକ ସାର୍ବଜନୀନ ରିଡ୍ ଏଣ୍ଡପଏଣ୍ଟ୍
(`src/app/api/free-provider-rankings/route.ts`) ଦ୍ୱାରା ସମର୍ଥିତ:

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

କ୍ୱେରି ପାରାମିଟର୍ଗୁଡ଼ିକ (Zod ସହିତ ବୈଧୀକୃତ):

| ପାରାମିଟର୍  | ପ୍ରକାର | ଡିଫଲ୍ଟ       | ଟିପ୍ପଣୀ                                                                                                             |
| ---------- | ------ | ------------ | ------------------------------------------------------------------------------------------------------------------- |
| `category` | string | (କିଛି ନାହିଁ) | `default`, `coding`, `review`, `documentation`, `debugging` ମଧ୍ୟରୁ ଗୋଟିଏ। ସଂଯୁକ୍ତ ରାଙ୍କିଂ ପାଇଁ ଏହାକୁ ଛାଡ଼ି ଦିଅନ୍ତୁ। |
| `limit`    | number | `50`         | `1–100` ପରିସର ମଧ୍ୟରେ ସୀମିତ।                                                                                         |

ପ୍ରତିକ୍ରିୟାର ଗଠନ:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` ହେଉଛି ମୂଳ Arena ELO ମୂଲ୍ୟ; `score` ହେଉଛି ସାମାନ୍ୟୀକୃତ ଟାସ୍କ୍-ଫିଟ୍ ମୂଲ୍ୟ
(ନିମ୍ନରେ ଦେଖନ୍ତୁ)। କୌଣସି ସ୍କୋର୍ ହୋଇଥିବା ମଡେଲ୍ ନଥିବା ପ୍ରଦାନକାରୀମାନଙ୍କୁ ପ୍ରତିକ୍ରିୟାରୁ ବାଦ ଦିଆଯାଏ।

## ସ୍କୋରଗୁଡ଼ିକ କିପରି କାମ କରେ

### ଉତ୍ସ: Arena AI ଲିଡରବୋର୍ଡ

Arena ELO ସିଙ୍କ୍ ଇଞ୍ଜିନ୍ (`src/lib/arenaEloSync.ts`), Arena AI ଲିଡରବୋର୍ଡ API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) ରୁ ଦୁଇଟି ଲିଡରବୋର୍ଡ — `text`
ଏବଂ `code` — ଆଣେ। ପ୍ରତ୍ୟେକ ଲିଡରବୋର୍ଡ ଏଣ୍ଟ୍ରିରେ ଗୋଟିଏ ମଡେଲ୍ ନାମ, ଭେଣ୍ଡର୍, ELO `score`,
କନ୍ଫିଡେନ୍ସ ଇଣ୍ଟରଭାଲ୍ ଏବଂ ଭୋଟ୍ ସଂଖ୍ୟା ଥାଏ।

ଲିଡରବୋର୍ଡ ବର୍ଗଗୁଡ଼ିକ OmniRoute କାର୍ଯ୍ୟ ବର୍ଗଗୁଡ଼ିକ ସହିତ ନିମ୍ନପ୍ରକାରେ ମ୍ୟାପ୍ ହୁଏ:

| Arena ଲିଡରବୋର୍ଡ | OmniRoute କାର୍ଯ୍ୟ ବର୍ଗଗୁଡ଼ିକ                      |
| --------------- | ------------------------------------------------- |
| `text`          | `default`, `review`, `documentation`, `debugging` |
| `code`          | `coding`                                          |

### ସାମାନ୍ୟୀକରଣ (କାର୍ଯ୍ୟ-ଉପଯୋଗିତା ସ୍କୋର୍)

କଞ୍ଚା ELO ସ୍କୋର୍ଗୁଡ଼ିକୁ ପ୍ରତ୍ୟେକ ଲିଡରବୋର୍ଡ ପାଇଁ ଗୋଟିଏ **`[0.4, 0.98]` ମଧ୍ୟରେ କାର୍ଯ୍ୟ-ଉପଯୋଗିତା ମୂଲ୍ୟ** ଭାବରେ ସାମାନ୍ୟୀକରଣ କରାଯାଏ:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

ସ୍କୋର୍ କେବେ ମଧ୍ୟ `0` କିମ୍ବା `1` ରେ ପହଞ୍ଚେ ନାହିଁ, ଯାହା ଉପଭୋକ୍ତା ଓଭର୍ରାଇଡ୍ ପାଇଁ ଅତିରିକ୍ତ ସୁଯୋଗ ରଖେ। ଏହା ହେଉଛି API ପ୍ରତିକ୍ରିୟାରେ ଆପଣ ଦେଖୁଥିବା `score` ଫିଲ୍ଡ ଏବଂ ଡ୍ୟାସ୍ବୋର୍ଡରେ ଦେଖାଯାଉଥିବା ଲେବଲ୍।

### ବିଶ୍ୱସନୀୟତା

Arena ଭୋଟ୍ ସଂଖ୍ୟା ଆଧାରରେ ପ୍ରତ୍ୟେକ ଏଣ୍ଟ୍ରିକୁ ଗୋଟିଏ ବିଶ୍ୱସନୀୟତା ସ୍ତର ଦିଆଯାଏ:

| ବିଶ୍ୱସନୀୟତା | ଭୋଟ୍ଗୁଡ଼ିକ |
| ----------- | ---------- |
| `high`      | ≥ 5,000    |
| `medium`    | ≥ 1,000    |
| `low`       | < 1,000    |

### ସଂରକ୍ଷଣ ଏବଂ ସତେଜତା

ସାମାନ୍ୟୀକୃତ ଏଣ୍ଟ୍ରିଗୁଡ଼ିକୁ `source = "arena_elo"` ସହିତ `model_intelligence` DB ଟେବୁଲ୍ରେ
ଲେଖାଯାଏ (`src/lib/db/modelIntelligence.ts`)। ଏଣ୍ଟ୍ରିଗୁଡ଼ିକର **7 ଦିନ ପରେ
ମିଆଦ ଶେଷ ହୁଏ**, ତେଣୁ ସିଙ୍କ୍ କରିବା ବନ୍ଦ କରିଥିବା କୌଣସି ପ୍ରଦାନକାରୀ ପୁରୁଣା ତଥ୍ୟ
ପରିବେଷଣ କରିବା ପରିବର୍ତ୍ତେ ଶେଷରେ ବାଦ୍ ପଡ଼େ।

ସିଙ୍କ୍ **ଡିଫଲ୍ଟ ଭାବରେ ଚାଲୁ** ଥାଏ:

- ଏହା ସର୍ଭର୍ ଆରମ୍ଭ ସମୟରେ ଥରେ ଏବଂ ତା’ପରେ ଏକ ପର୍ଯ୍ୟାୟକ୍ରମିକ ଟାଇମର୍ରେ ଚାଲେ
  (`src/lib/arenaEloSync.ts`, `src/instrumentation-node.ts` ରୁ ସଂଯୋଜିତ)।
- ଏହା **ଅବରୋଧକାରୀ ନୁହେଁ ଏବଂ କେବେ ମଧ୍ୟ ମାରାତ୍ମକ ନୁହେଁ** — ଯଦି ଅପ୍ଷ୍ଟ୍ରିମ୍ ଫେଚ୍ ବିଫଳ ହୁଏ, OmniRoute
  ଚାଲୁ ରହେ ଏବଂ ର୍ୟାଙ୍କିଙ୍ଗ୍ଗୁଡ଼ିକ କେବଳ ଶେଷ ଭଲ ତଥ୍ୟ (କିମ୍ବା ଏକ ଖାଲି ଅବସ୍ଥା) ଦେଖାଏ।

ଦୁଇଟି ପରିବେଶ ଭେରିଏବଲ୍ ଏହାକୁ ନିୟନ୍ତ୍ରଣ କରେ (
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md) ରେ ଡକ୍ୟୁମେଣ୍ଟ କରାଯାଇଛି):

| ଭେରିଏବଲ୍                  | ଡିଫଲ୍ଟ        | ଉଦ୍ଦେଶ୍ୟ                                                   |
| ------------------------- | ------------- | ---------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | ଆଉଟ୍ବାଉଣ୍ଡ ସିଙ୍କ୍ରୁ ବାଦ୍ ଦେବାକୁ `false` ଭାବରେ ସେଟ୍ କରନ୍ତୁ। |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | ସେକେଣ୍ଡରେ ସିଙ୍କ୍ ବ୍ୟବଧାନ।                                  |

### ମାନୁଆଲ୍ ସିଙ୍କ୍ / ସ୍ଥିତି / ସଫା କରିବା

ଅପରେଟର୍ମାନଙ୍କ ପାଇଁ, ଗୋଟିଏ ପ୍ରମାଣୀକୃତ ପରିଚାଳନା ଏଣ୍ଡପଏଣ୍ଟ ମାନୁଆଲ୍ ନିୟନ୍ତ୍ରଣ ପ୍ରଦାନ କରେ
(`src/app/api/intelligence/sync/route.ts` — ପରିଚାଳନା ପ୍ରମାଣୀକରଣ ଆବଶ୍ୟକ):

```
GET    /api/intelligence/sync          # ବର୍ତ୍ତମାନର ସିଙ୍କ୍ ସ୍ଥିତି (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # ଏକ ମାନୁଆଲ୍ ସିଙ୍କ୍ ଟ୍ରିଗର୍ କରନ୍ତୁ; ଲେଖିବା ବିନା ପୂର୍ବାବଲୋକନ କରିବାକୁ ବଡି: { "dryRun": true }
DELETE /api/intelligence/sync          # ସମସ୍ତ ସିଙ୍କ୍ ହୋଇଥିବା arena_elo ଇଣ୍ଟେଲିଜେନ୍ସ ଏଣ୍ଟ୍ରି ସଫା କରନ୍ତୁ
```

ଯଦି ର୍ୟାଙ୍କିଙ୍ଗ୍ ପୃଷ୍ଠାଟି ଖାଲି ଅଛି, ଏକ ମାନୁଆଲ୍ `POST /api/intelligence/sync` (କିମ୍ବା କେବଳ
ସର୍ଭର୍କୁ ପୁନଃଆରମ୍ଭ କରିବା) ଏହାକୁ ପୁନଃ ପୂରଣ କରେ।

### ମଡେଲ୍ଗୁଡ଼ିକୁ ଲିଡରବୋର୍ଡ ସହିତ ମେଳ କରିବା

ରେଜିଷ୍ଟ୍ରି ମଡେଲ୍ ID ଏବଂ Arena ମଡେଲ୍ ନାମଗୁଡ଼ିକ ସବୁବେଳେ ସଠିକ୍ ଭାବରେ ମେଳ ଖାଆନ୍ତି ନାହିଁ। ର୍ୟାଙ୍କିଙ୍ଗ୍
ନମନୀୟ ମେଳକ ବ୍ୟବହାର କରେ (`src/lib/freeProviderRankings.ts` ରେ `findMatchingIntelligence`):

1. ସାମାନ୍ୟୀକୃତ ମଡେଲ୍ ID ସହିତ ସଠିକ୍ ମେଳ।
2. ଶେଷରେ ଥିବା ସଂସ୍କରଣ ସଫିକ୍ସ କାଢ଼ିବା ପରେ ମେଳ (ଯଥା `kimi-k2.6` → `kimi-k2`)।
3. ପ୍ରିଫିକ୍ସ ମେଳ (ଗୋଟିଏ ଲିଡରବୋର୍ଡ ମଡେଲ୍ ନାମ ରେଜିଷ୍ଟ୍ରି ID-ର ଏକ ପ୍ରିଫିକ୍ସ ଅଟେ)।

ସିଙ୍କ୍ ପାର୍ଶ୍ୱରେ, ଜଣାଶୁଣା ଭେଣ୍ଡର୍ ପ୍ରିଫିକ୍ସଗୁଡ଼ିକ (`anthropic/`, `openai/`, `google/`, …)
କାଢ଼ି ଦିଆଯାଏ ଏବଂ ଏକ ଛୋଟ ଉପନାମ ମ୍ୟାପ୍ କ୍ୟାନୋନିକାଲ୍ ନାମଗୁଡ଼ିକୁ OmniRoute ଆଭ୍ୟନ୍ତରୀଣ ଭାବେ
ବ୍ୟବହାର କରୁଥିବା ରୂପାନ୍ତରଗୁଡ଼ିକୁ ବିସ୍ତାର କରେ, ଯାହାଦ୍ୱାରା ମଡେଲ୍ଗୁଡ଼ିକ କୌଣସି ନାମ ଅଧୀନରେ ଖୋଜାଯାଇପାରେ।

### ଜଣେ ପ୍ରଦାନକାରୀଙ୍କୁ କିପରି ର୍ୟାଙ୍କ୍ କରାଯାଏ

ପ୍ରତ୍ୟେକ ମାଗଣା ପ୍ରଦାନକାରୀ ପାଇଁ, ଇଞ୍ଜିନ୍ ତାହାର କ୍ୟାଟାଲଗ୍ରେ ଥିବା ପ୍ରତ୍ୟେକ ମଡେଲ୍କୁ ସ୍କୋର୍ କରେ, ତା’ପରେ:

- **ଶୀର୍ଷ ମଡେଲ୍** = ପ୍ରଦାନକାରୀଙ୍କ ସର୍ବାଧିକ ସ୍କୋର୍ ପାଇଥିବା ମଡେଲ୍।
- **ହାରାହାରି ସ୍କୋର୍** = ସେହି ପ୍ରଦାନକାରୀଙ୍କ ସମସ୍ତ ସ୍କୋର୍ କରାଯାଇଥିବା ମଡେଲ୍ର ହାରାହାରି ସ୍କୋର୍।
- **ମଡେଲ୍ଗୁଡ଼ିକ** = ପ୍ରଦାନକାରୀଙ୍କ କେତୋଟି ମଡେଲ୍ର Arena ସ୍କୋର୍ ଥିଲା।

ପ୍ରଦାନକାରୀମାନଙ୍କୁ ପ୍ରଥମେ **ଶୀର୍ଷ-ମଡେଲ୍ ସ୍କୋର୍** ଏବଂ ତା’ପରେ ହାରାହାରି ସ୍କୋର୍ ଅନୁସାରେ ସଜାଯାଏ। ଏହା
ଅତି କମ୍ରେ ଗୋଟିଏ ଶକ୍ତିଶାଳୀ ମାଗଣା ମଡେଲ୍ ପ୍ରଦାନ କରୁଥିବା ପ୍ରଦାନକାରୀଙ୍କୁ ପୁରସ୍କୃତ କରେ।

## ମାଗଣା ପ୍ରଦାତା ବାଛିବା ପାଇଁ ଏହାର ବ୍ୟବହାର

1. **ସଠିକ୍ ବର୍ଗ ବାଛନ୍ତୁ।** ଏଜେଣ୍ଟ-ଆଧାରିତ/କୋଡ୍ ୱାର୍କଲୋଡ୍ ପାଇଁ **Coding** ଫିଲ୍ଟର୍ ବ୍ୟବହାର କରନ୍ତୁ, କିମ୍ବା
   ସାଧାରଣ ଚାଟ୍ ପାଇଁ ଏହାକୁ **All Categories** / **Default**ରେ ରଖନ୍ତୁ। ପ୍ରତ୍ୟେକ ଲିଡର୍ବୋର୍ଡରେ ଏକ ପ୍ରଦାତାର ଶ୍ରେଷ୍ଠ ମଡେଲ୍ ଭିନ୍ନ ହୋଇଥିବାରୁ,
   ସେହି ପ୍ରଦାତା ବିଭିନ୍ନ ବର୍ଗରେ ଭିନ୍ନ ସ୍ଥାନ ପାଇପାରେ।
2. **ଏକକ-ସେଟ୍ଅପ୍ ପାଇଁ ଶୀର୍ଷ ସ୍ଥାନଗୁଡ଼ିକୁ ପ୍ରାଧାନ୍ୟ ଦିଅନ୍ତୁ।** ଯଦି ଆପଣ କେବଳ ଗୋଟିଏ କିମ୍ବା ଦୁଇଟି ମାଗଣା
   ପ୍ରଦାତାଙ୍କୁ ସଂଯୋଗ କରିବାକୁ ଚାହାନ୍ତି, ତେବେ ନିଜ ବର୍ଗରେ ସର୍ବୋଚ୍ଚ ମାନ୍ୟତାପ୍ରାପ୍ତ ପ୍ରଦାତାଙ୍କଠାରୁ ଆରମ୍ଭ କରନ୍ତୁ।
3. **Type ବ୍ୟାଜ୍ ଯାଞ୍ଚ କରନ୍ତୁ।** `NOAUTH` ପ୍ରଦାତାମାନଙ୍କୁ ସବୁଠାରୁ ଶୀଘ୍ର ସଂଯୋଗ କରାଯାଇପାରେ (କୌଣସି
   ପରିଚୟପତ୍ର ଆବଶ୍ୟକ ନାହିଁ)। `OAUTH` / `APIKEY` ମାଗଣା ସ୍ତରଗୁଡ଼ିକ ପାଇଁ ଶୀଘ୍ର ସାଇନ୍-ଅପ୍ ଆବଶ୍ୟକ, କିନ୍ତୁ ସେଗୁଡ଼ିକ ପ୍ରାୟତଃ
   ଅଧିକ ଶକ୍ତିଶାଳୀ ମଡେଲ୍ ଉପଲବ୍ଧ କରାନ୍ତି। ସଂଯୋଗ ପଦକ୍ଷେପ ପାଇଁ
   [ମାଗଣା ସ୍ତର ମାର୍ଗଦର୍ଶିକା](../getting-started/FREE-TIERS-GUIDE.md) ଦେଖନ୍ତୁ।
4. **ଏକାଧିକ ପ୍ରଦାତାଙ୍କୁ ସଂଯୋଗ କରନ୍ତୁ ଏବଂ Auto-Comboକୁ ନିଷ୍ପତ୍ତି ନେବାକୁ ଦିଅନ୍ତୁ।** ଏହି ପୃଷ୍ଠାକୁ ପରିଚାଳିତ କରୁଥିବା ସମାନ Arena ELO ଡାଟା
   Auto-Combo ସ୍କୋରିଂ ଇଞ୍ଜିନ୍ର **କାର୍ଯ୍ୟ-ଉପଯୋଗିତା ଗୁଣକ**କୁ ମଧ୍ୟ ଯୋଗାଇଥାଏ
   (`open-sse/services/autoCombo/taskFitness.ts`, ସମାଧାନ କ୍ରମ
   `user_override → arena_elo → models_dev_tier → static table`)। ତେଣୁ ଆପଣ ଶୀର୍ଷ ମାଗଣା ପ୍ରଦାତାଙ୍କୁ ସଂଯୋଗ କରିବା ପରେ,
   `model: "auto"` (ଯଥା `auto/coding`) ସହିତ ରାଉଟିଂ ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ପାଇଁ
   ଉଚ୍ଚ-ଗୁଣବତ୍ତାର ମାଗଣା ମଡେଲ୍ଗୁଡ଼ିକୁ ସ୍ୱୟଂଚାଳିତ ଭାବେ ପ୍ରାଧାନ୍ୟ ଦେବ। ସମ୍ପୂର୍ଣ୍ଣ 16-ଗୁଣକ ସ୍କୋରିଂ ପାଇଁ
   [Auto-Combo](../routing/AUTO-COMBO.md) ଦେଖନ୍ତୁ।
