## 🎨 କମ୍ବୋ

19 ଟି ସାର୍ବଜନୀନ ରଣନୀତି ସହିତ ମଡେଲ୍ ରୁଟିଂ କମ୍ବୋ ସୃଷ୍ଟି କରନ୍ତୁ: ପ୍ରାଥମିକତା, ୱେଟେଡ୍, ରାଉଣ୍ଡ-ରୋବିନ୍, କଣ୍ଟେକ୍ସଟ୍-ରେଲେ, ଫିଲ୍-ଫାର୍ଷ୍ଟ, p2c (ପାୱର-ଅଫ୍-ଟୁ ଚୟସ୍), ରାଣ୍ଡମ୍, ଲିଷ୍ଟ-ଅଷ୍ଟ୍, କୋଷ୍ଟ୍-ଅପ୍ଟିମାଇଜ୍ଡ୍, ରିସେଟ୍-ଆୱେୟାର୍, ରିସେଟ୍-ୱିଣ୍ଡୋ, ହେଡ୍ରୁମ୍, ଷ୍ଟ୍ରିକ୍ଟ-ରାଣ୍ଡମ୍, ଅଟୋ, lkgp (ଲାଷ୍ଟ-ନୋନ-ଗୁଡ୍-ପ୍ରଦାୟକ), କଣ୍ଟେକ୍ସଟ୍-ଅପ୍ଟିମାଇଜ୍ଡ୍, କ୍ୟାଶେ-ଅପ୍ଟିମାଇଜ୍ଡ୍, **ଫ୍ୟୁଜନ୍** (ଏକ ପାନେଲ୍ ଅଫ୍ ମଡେଲ୍କୁ ସମାନ୍ତରାଳରେ ଫ୍ୟାନ୍ ଆଉଟ୍ କରନ୍ତୁ, ତାପରେ ଏକ ଜଜ୍ ମାଧ୍ୟମରେ ଏକ ଉତ୍ତର ସଂଶ୍ଳେଷଣ କରନ୍ତୁ), ଏବଂ **ପାଇପଲାଇନ୍**। ପ୍ରତ୍ୟେକ କମ୍ବୋ ସ୍ୱୟଂଚାଳିତ ଫଲବ୍ୟାକ୍ ସହିତ ଏକାଧିକ ମଡେଲ୍ ଚେନ୍ କରେ ଏବଂ ଶୀଘ୍ର ଟେମ୍ପ୍ଲେଟ୍ ଏବଂ ସାଜିଦ୍ ଯାଞ୍ଚ ଅନ୍ତର୍ଭୁକ୍ତ କରେ।

ସାମ୍ପ୍ରତିକ କମ୍ବୋ ଉନ୍ନତି:

- **ସଂରଚିତ କମ୍ବୋ ନିର୍ମାତା** — ପ୍ରଦାୟକ, ମଡେଲ୍ ଏବଂ ସଠିକ୍ ଆକାଉଣ୍ଟ/ସଂଯୋଗ ଚୟନ କରି ପ୍ରତ୍ୟେକ ପଦକ୍ଷେପ ସୃଷ୍ଟି କରନ୍ତୁ
- **ପୁନରାବୃତ୍ତି ପ୍ରଦାୟକ ସମର୍ଥନ** — ଯଦି `(provider, model, connection)` ଟୁପଲ୍ ଅନନ୍ୟ ଅଟେ ତେବେ ଗୋଟିଏ କମ୍ବୋରେ ଅନେକ ଥର ସମାନ ପ୍ରଦାୟକ ପୁନଃବ୍ୟବହାର କରନ୍ତୁ
- **କମ୍ବୋ ଲକ୍ଷ୍ୟ ସ୍ୱାସ୍ଥ୍ୟ** — ବିଶ୍ଳେଷଣ ଏବଂ ସ୍ୱାସ୍ଥ୍ୟ ପୃଷ୍ଠଗୁଡିକ ଏବେ ମଡେଲ୍ ଷ୍ଟ୍ରିଂଗ୍ରେ ସବୁକିଛି ମିଶାଇ ନ ଦେଇ ସମ୍ପୂର୍ଣ୍ଣ କମ୍ବୋ ଲକ୍ଷ୍ୟ/ପଦକ୍ଷେପଗୁଡିକୁ ପାର୍ଥକ୍ୟ କରନ୍ତି
- **ସଂଯୁକ୍ତ ସ୍ତର ଅର୍ଡରିଂ** — `defaultTier -> fallbackTier` ଏବେ ଶୀର୍ଷ-ସ୍ତରୀୟ କମ୍ବୋ ପଦକ୍ଷେପଗୁଡିକ ପାଇଁ ରନଟାଇମ୍ କାର୍ଯ୍ୟକାରିତା/ଫଲବ୍ୟାକ୍ ଅର୍ଡରକୁ ପ୍ରଭାବିତ କରେ
- **ସିଷ୍ଟମ୍ ପ୍ରମ୍ପ୍ଟ୍ ଟେମ୍ପ୍ଲେଟ୍** — କମ୍ବୋ `system_message` ସର୍ଭର୍-ସାଇଡ୍

- **ସାଧାରଣ** — ସିଷ୍ଟମ୍ ଷ୍ଟୋରେଜ୍, ବ୍ୟାକଅପ୍ ପ୍ରବନ୍ଧନ (ଡାଟାବେସ୍ ରପ୍ତାନି/ଆମଦାନୀ)
- **ଦୃଶ୍ୟ** — ଥିମ୍ ସିଲେକ୍ଟର୍ (ଡାର୍କ/ଲାଇଟ୍/ସିଷ୍ଟମ୍), ରଙ୍ଗ ଥିମ୍ ପ୍ରିସେଟ୍ ଏବଂ କଷ୍ଟମ୍ ରଙ୍ଗ, ସ୍ୱାସ୍ଥ୍ୟ ଲଗ୍ ଦୃଶ୍ୟତା, ସାଇଡବାର୍ ଆଇଟମ୍ ଏବଂ ଗ୍ରୁପ୍ ସେପାରେଟର୍ ଦୃଶ୍ୟତା ନିୟନ୍ତ୍ରଣ, ଏଣ୍ଡପଏଣ୍ଟ ଟନେଲ୍ ଦୃଶ୍ୟତା ନିୟନ୍ତ୍ରଣ
- **ଏଆଇ** — ଏଆଇ ସହାୟକ ବୈଶିଷ୍ଟ୍ୟ, ଡିଫଲ୍ଟ ରୁଟିଂ ପ୍ରିସେଟ୍ (`auto/coding`, `auto/fast`, `auto/cheap`, `auto/smart`), ଯୁକ୍ତି ପୁନର୍ବାର କ୍ୟାଶ୍ ଏବଂ ସ୍କିଲ୍/ମେମୋରୀ ଟୋଗୁଲ୍
- **ସୁରକ୍ଷା** — ଏପିଆଇ ଏଣ୍ଡପଏଣ୍ଟ ସୁରକ୍ଷା, କଷ୍ଟମ୍ ପ୍ରଦାତା ଅବରୋଧ, ଆଇପି ଫିଲ୍ଟରିଂ, ସେସନ୍ ସୂଚନା
- **ରୁଟିଂ** — ମଡେଲ୍ ଉପନାମ, ପୃଷ୍ଠଭୂମି ଟାସ୍କ ଡିଗ୍ରେଡେସନ୍, ମ୍ୟାନିଫେଷ୍ଟ-ସଚେତନ ଟିୟର୍ ରୁଟିଂ (W1–W4), `fallbackDelayMs`, ପ୍ରତି-ସେସନ୍ ଷ୍ଟିକି ରୁଟିଂ
- **ପ୍ରତିରୋଧକତା** — ହାର୍ ଲିମିଟ୍ ସ୍ଥାୟିତ୍ୱ, ସର୍କିଟ୍ ବ୍ରେକର୍ ଟ୍ୟୁନିଂ, ନିଷିଦ୍ଧ ଆକାଉଣ୍ଟ ସ୍ୱୟଂ-ଅକ୍ଷମ, ପ୍ରଦାତା ସମାପ୍ତି ମନିଟରିଂ, **କନ୍ଟେକ୍ଷ୍ଟ ରିଲେ** ହ୍ୟାଣ୍ଡଅଫ୍ ଥ୍ରେଶହୋଲ୍ଡ ଏବଂ ସାରାଂଶ ମଡେଲ୍ କନଫିଗରେସନ, ପ୍ରତି-ପ୍ରଦାତା 429 ଶ୍ରେଣୀକରଣ ଏବଂ `useUpstream429BreakerHints` ଟୋଗୁଲ୍, ମଡେଲ୍ କୁଲଡାଉନ୍
- **ଉନ୍ନତ** — କନଫିଗରେସନ ଓଭରରାଇଡ୍, କନଫିଗରେସନ ଅଡିଟ୍ ଟ୍ରେଲ୍, ଫଲବ୍ୟାକ୍ ଡିଗ୍ରେଡେସନ୍ ମୋଡ୍, ରେସ୍ପନ୍ସ ଏପିଆଇ ପାଇଁ ପୃଷ୍ଠଭୂମି ମୋଡ୍ ଡିଗ୍ରେଡେସନ୍

- **CLI ଫିଙ୍ଗରପ୍ରିଣ୍ଟ୍ ମ୍ୟାଚିଂ** — ନେଟିଭ୍ CLI ଅନୁରୋଧ ସ୍ବାକ୍ଷର ମ୍ୟାଚ୍ କରିବା ପାଇଁ ପ୍ରତି-ପ୍ରଦାତା ଟୋଗୁଲ୍, ପ୍ରକ୍ସି IP ସଂରକ୍ଷଣ କରିବା ସହ ନିଷେଧ ଆଶା ହ୍ରାସ କରେ

## 🔗 ସାଂଗ୍ରେ ରିଲେ _(v3.5.5+)_

ଏକ କମ୍ବୋ ରଣନୀତି ଯାହା ବାର୍ତ୍ତାଳାପ ମଧ୍ୟରେ ଖାତା ପରିବର୍ତ୍ତନ ହୋଇଲେ ସେସନ୍ ସାତତ୍ଯ ସଂରକ୍ଷଣ କରେ। ସକ୍ରିୟ ଖାତା ଶେଷ ହେବା ପୂର୍ବରୁ, OmniRoute ପୃଷ୍ଠଭୂମିରେ ଏକ ସଂରଚିତ ହ୍ୟାଣ୍ଡଅଫ୍ ସାରାଂଶ ସୃଷ୍ଟି କରେ। ପରବର୍ତ୍ତୀ ଅନୁରୋଧ ଏକ ଭିନ୍ନ ଖାତାକୁ ନିର୍ଦ୍ଦେଶିତ ହେବା ପରେ, ସାରାଂଶ ଏକ ସିଷ୍ଟମ୍ ସନ୍ଦେଶ ଭାବରେ ଇଂଜେକ୍ଟ୍ କରାଯାଏ ଯାହା ଦ୍ୱାରା ନୂଆ ଖାତା ସମ୍ପୂର୍ଣ୍ଣ ସାଂଗ୍ରେ ସହ ଜାରି ରହେ।

କମ୍ବୋ ସ୍ତର ବା ବୈଶ୍ୱିକ ସେଟିଂସ୍ ମାଧ୍ୟମରେ କନଫିଗର ଯୋଗ୍ୟ:

- **ହ୍ୟାଣ୍ଡଅଫ୍ ଥ୍ରେଶହୋଲ୍ଡ** — ସାରାଂଶ ସୃଷ୍ଟି ଟ୍ରିଗର କରୁଥିବା କୋଟା ବ୍ୟବହାର ପ୍ରତିଶତ (ଡିଫଲ୍ଟ 85%)
- **ସାରାଂଶ ପାଇଁ ସର୍ବାଧିକ ସନ୍ଦେଶ** — ସାମ୍ପ୍ରତିକ ଇତିହାସର କେତେ ଅଂଶ ସାରାଂଶ କରିବା ଆବଶ୍ୟକ
- **ସାରାଂଶ ମଡେଲ** — ହ୍ୟାଣ୍ଡଅଫ୍ ସାରାଂଶ ସୃଷ୍ଟି ପାଇଁ ଐଚ୍ଛିକ ଓଭରରାଇଡ୍ ମଡେଲ୍

ବର୍ତ୍ତମାନ Codex ଖାତା ପରିବର୍ତ୍ତନ ସମର୍ଥିତ। [ସାଂଗ୍ରେ ରିଲେ ଡକୁମେଣ୍ଟେସନ୍](../architecture/ARCHITECTURE.md) ଦେଖନ୍ତୁ।

## 🗜️ ପ୍ରମ୍ପଟ୍ ସଙ୍କୁଚିତକରଣ _(v3.7.9+)_

Context & Cache ଏବେ Caveman, RTK, ଏବଂ ସଙ୍କୁଚିତକରଣ କମ୍ବୋ ପାଇଁ ସମର୍ପିତ ପୃଷ୍ଠ ପ୍ରଦାନ କରେ:

- **Caveman** — ଭାଷା-ସଚେତନ ନିୟମ ପ୍ୟାକ୍, ପ୍ରିଭିଉ, ଆଉଟପୁଟ୍ ମୋଡ୍ କଣ୍ଟ୍ରୋଲ୍, ଏବଂ ବିଶ୍ଲେଷଣ
- **RTK** — ସେଲ୍, git, ପରୀକ୍ଷଣ, ନିର୍ମାଣ, ପ୍ୟାକେଜ୍, Docker, ଅବକାଠାମୋ, JSON, ଏବଂ ସ୍ଟ୍ୟାକ୍-ଟ୍ରେସ୍ ଆଉଟପୁଟ୍ ପାଇଁ କମାଣ୍ଡ୍-ସଚେତନ ସଙ୍କୁଚିତକରଣ
- **ସଙ୍କୁଚିତକରଣ କମ୍ବୋ** — କମ୍ବୋ ରୁଟିଂକୁ ନିୟୋଜିତ `rtk -> caveman` ଭଳି ନାମକରଣ କରାଯାଇଥିବା ପାଇପ୍ଲାଇନ୍; ଡିଫଲ୍ଟ ସ୍ୟାକ୍ଡ୍ ମ୍ୟାଥ୍ ଦୁଇଟି ଇଞ୍ଜିନ୍ ପ୍ରୟୋଗ ହେଲେ ~89% ଗଡ଼ାଣି ଏବଂ 78-95% ଯୋଗ୍ୟ-ସାଂଗ୍ରେ ସଞ୍ଚୟ ପ୍ରାପ୍ତ କରେ
- **କଞ୍ଚା-ଆଉଟପୁଟ୍ ପୁନରୁଦ୍ଧାର** — ସଙ୍କୁଚିତ ବିଫଳତା ଡିବଗ୍ କରିବା ପାଇଁ ଐଚ୍ଛିକ redacted RTK କଞ୍ଚା-ଆଉଟପୁଟ୍ ପଏଣ୍ଟର୍

[ସଙ୍କୁଚିତକରଣ ଗାଇଡ୍](../compression/COMPRESSION_GUIDE.md), [RTK ସଙ୍କୁଚିତକରଣ](../compression/RTK_COMPRESSION.md), ଏବଂ
[ସଙ୍କୁଚିତକରଣ ଇଞ୍ଜିନ୍](../compression/COMPRESSION_ENGINES.md) ଦେଖନ୍ତୁ।

## 🛡️ ପ୍ରକ୍ସି ହାର୍ଡେନିଂ _(v3.5.5+)_

ସମ୍ପୂର୍ଣ୍ଣ ଅନୁରୋଧ ପାଇପ୍ଲାଇନ୍ ଜୁଡ଼ି ବିସ୍ତୃତ ପ୍ରକ୍ସି କନଫିଗରେସନ୍ ପ୍ରୟୋଗ:

- **ଟୋକେନ୍ ସ୍ୱାସ୍ଥ୍ୟ ଯାଞ୍ଚ** — ପୃଷ୍ଠଭୂମି OAuth ରିଫ୍ରେଶ୍ ଏବେ ପ୍ରତ୍ୟେକ ସଂଯୋଗ ଅନୁଯାୟୀ ପ୍ରକ୍ସି କନଫିଗ୍ ସମାଧାନ କରେ, ପ୍ରକ୍ସି ଆବଶ୍ୟକ ପରିବେଶରେ ବିଫଳତା ରୋକାଇଥାଏ
- **API କୀ ଯାଞ୍ଚ** — ପ୍ରଦାତା କୀ ଯାଞ୍ଚ (`POST /api/providers/validate`) `runWithProxyContext` ମାଧ୍ୟମରେ ରୁଟ୍ ହୁଏ, ପ୍ରଦାତା-ସ୍ତରୀୟ ଏବଂ ବୈଶ୍ୱିକ ପ୍ରକ୍ସି ସେଟିଂସ୍ ସମ୍ମାନ ଦିଏ
- **undici ଡିସ୍ପ୍ୟାଚର୍ ଫିକ୍ସ** — ପ୍ରକ୍ସି ଡିସ୍ପ୍ୟାଚର୍ Node.js ର ବିଲ୍ଟ୍-ଇନ୍ fetch ବଦଳରେ undici ର ନିଜସ୍ୱ fetch ବାସ୍ତବିକତା ବ୍ୟବହାର କରେ, Node.js 22 ରେ `invalid onRequestStart method` ତ୍ରୁଟି ସମାଧାନ କରେ
- **Node.js ସଂସ୍କରଣ ସନ୍ଧାନ** — ଲଗିନ୍ ପୃଷ୍ଠ ସକ୍ରିୟ ଭାବରେ ଅସଂଗତ Node.js ସଂସ୍କରଣ (24+) ସନ୍ଧାନ କରେ ଏବଂ Node 22 LTS ବ୍ୟବହାର କରିବା ପାଇଁ ନିର୍ଦ୍ଦେଶ ସହ ଏକ ଚେତାବନୀ ବ୍ୟାନର ପ୍ରଦର୍ଶନ କରେ

## 🌐 V1 WebSocket ବ୍ରିଜ୍ _(v3.6.6+)_

OmniRoute ବର୍ତ୍ତମାନ `/v1/ws` ଅପଗ୍ରେଡ୍ ଏଣ୍ଡପଏଣ୍ଟ ମାଧ୍ୟମରେ **OpenAI-ସୁସଙ୍ଗତ WebSocket କ୍ଲାଇଣ୍ଟ** କୁ ସମର୍ଥନ କରେ। କଷ୍ଟମ୍ `scripts/dev/v1-ws-bridge.mjs` ସର୍ଭର Next.js କୁ ଆବୃତ୍ତ କରେ ଏବଂ WS ସଂଯୋଗଗୁଡ଼ିକୁ ସମ୍ପୂର୍ଣ୍ଣ ଦ୍ୱି-ଦିଗୀୟ ସ୍ଟ୍ରିମିଂ ଅଧିବେଶନରେ ଅପଗ୍ରେଡ୍ କରେ। ପ୍ରାମାଣିକିକରଣ HTTP ଅନୁରୋଧ ପରି ସମାନ API କି କିମ୍ବା ସେସନ୍ କୁକି ବ୍ୟବହାର କରେ।

ମୁଖ୍ୟ ଆଚରଣଗୁଡ଼ିକ:

- WS ଅପଗ୍ରେଡ୍ ସଂଯୋଗ ସ୍ଥାପନ ହେବା ପୂର୍ବରୁ `src/lib/ws/handshake.ts` ଦ୍ୱାରା ବୈଧ କରାଯାଏ
- ଅଧିବେଶନ ବନ୍ଦ କିମ୍ବା ଅପସ୍ଟ୍ରିମ୍ ତ୍ରୁଟିରେ ସ୍ଟ୍ରିମ୍ ସଫାସୁତୁରା ସମାପ୍ତ ହୁଏ
- ଏକ ସମୟରେ ବିଦ୍ୟମାନ HTTP+SSE ସ୍ଟ୍ରିମିଂ ପଥ ସହିତ କାର୍ଯ୍ୟ କରେ

## 🔱 ସିଙ୍କ ଟୋକେନ ଏବଂ କନ୍ଫିଗ ବଣ୍ଡଲ _(v3.6.6+)_

**ସ୍କୋପ କରାଯାଇଥିବା ସିଙ୍କ ଟୋକେନ** ମାଧ୍ୟମରେ ଏବେ ବହୁ-ଡିଭାଇସ ଏବଂ ବାହ୍ୟ ଅପରେଟର ପ୍ରବେଶ ସମ୍ଭବ ହେଲା:

- **`POST /api/sync/tokens`** — ଏକ ନୂଆ ସିଙ୍କ ଟୋକେନ ଜାରି କରନ୍ତୁ (ସ୍କୋପ କରାଯାଇଥିବା, ବିକଳ୍ପ ସମୟ ସୀମା ସହ)
- **`DELETE /api/sync/tokens/:id`** — ଏକ ଟୋକେନ ରଦ୍ଦ କରନ୍ତୁ
- **`GET /api/sync/bundle`** — ସମସ୍ତ ସମ୍ବେଦନଶୀଳ ନୁହେଁ ତଥ୍ୟ ସେଟିଙ୍ଗସ (ପାସୱାର୍ଡ ଲୁଚାଯାଇଥିବା) ର ଏକ ସଂସ୍କରଣ-ସୂଚିତ, ETag-କି-କରାଯାଇଥିବା JSON ସ୍ନାପଶଟ ଡାଉନଲୋଡ କରନ୍ତୁ

କନ୍ଫିଗ ବଣ୍ଡଲ `src/lib/sync/bundle.ts` ଦ୍ୱାରା ନିର୍ମାଣ କରାଯାଇଛି। ଉପଭୋକ୍ତାମାନେ ସମ୍ପୂର୍ଣ୍ଣ ପେଲୋଡ ପୁଣି ଡାଉନଲୋଡ ନକରି ପରିବର୍ତ୍ତନ ଚିହ୍ନଟ କରିବା ପାଇଁ `ETag` ପ୍ରତିକ୍ରିୟା ହେଡର ତୁଳନା କରନ୍ତି।

**ହାଇବ୍ରିଡ ଟୋକେନ ଗଣନା** ମଧ୍ୟ v3.6.6 ରେ ଅବତରଣ କରେ: ଯେତେବେଳେ ଏକ Claude-ସୁସଙ୍ଗତ ପ୍ରଦାନକାରୀ `/messages/count_tokens` ପ୍ରଦାନ କରେ, OmniRoute ବୃହତ୍ ଅନୁରୋଧ ପୂର୍ବରୁ ଏହାକୁ ଡାକେ ଏବଂ ସୁସମ୍ପର୍ଣ୍ଣ ଅନୁମାନ ଫାଲବ୍ୟାକ ସହ।

## 🛡️ ସୁରକ୍ଷିତ ଆଉଟବାଉଣ୍ଡ ଫେଚ ଏବଂ SSRF ଗାର୍ଡ _(v3.6.6+)_

ସମସ୍ତ ପ୍ରଦାନକାରୀ ଯାଞ୍ଚ ଏବଂ ମଡେଲ ଆବିଷ୍କାର କଲ୍ ଏବେ ଏକ ଦୁଇ-ସ୍ତରୀୟ ଆଉଟବାଉଣ୍ଡ ଗାର୍ଡ ମଧ୍ୟଦେଇ ଯାଏ:

1. **URL ଗାର୍ଡ** (`src/shared/network/outboundUrlGuard.ts`) — ସକେଟ ଖୋଲିବା ପୂର୍ବରୁ ନିଜସ୍ୱ/ଲୁପବ୍ୟାକ/ଲିଙ୍କ-ଲୋକାଲ IP ପରିସରକୁ ଅବରୋଧ କରେ।
2. **ସୁରକ୍ଷିତ ଫେଚ ୱାରାପର** (`src/shared/network/safeOutboundFetch.ts`) — URL ଗାର୍ଡ ପ୍ରୟୋଗ କରେ, ସମୟ-ସୀମା ସାମାନ୍ୟ କରେ, ଏବଂ କ୍ଷଣିକ ତୃଟି ସହ ଘାତାତ୍ମକ ପଛକୁ ପ୍ରୟୋଗ କରି ପୁନରାବୃତ୍ତି କରେ।

ଗାର୍ଡ ଉଲ୍ଲଂଘନ HTTP 422 (`URL_GUARD_BLOCKED`) ରୂପରେ ଦୃଶ୍ୟ ହୁଏ ଏବଂ `providerAudit.ts` ମାଧ୍ୟମରେ ସମ୍ମତି ଅଡିଟ ଲଗରେ ଲେଖା ଯାଏ।

## 🔄 କୁଲଡାଉନ୍-ସଚେତନ ପୁନରାବୃତ୍ତି _(v3.6.6+)_

ଯେତେବେଳେ ଏକ ଅପ୍ଷ୍ଟ୍ରିମ୍ ପ୍ରଦାନକାରୀ ଏକ ମଡେଲ-ସ୍କୋପ କୁଲଡାଉନ୍ ଫେରାଉଛି, ଚାଟ ଅନୁରୋଧ ଏବେ **ସ୍ୱୟଂଚାଳିତ ଭାବରେ ପୁନରାବୃତ୍ତି** କରେ। `REQUEST_RETRY` (ଡିଫଲ୍ଟ: 2) ଏବଂ `MAX_RETRY_INTERVAL_SEC` (ଡିଫଲ୍ଟ: 30 ସେକେଣ୍ଡ) ମାଧ୍ୟମରେ ବିନ୍ୟାସ ଯୋଗ୍ୟ। `x-ratelimit-reset-requests`, `x-ratelimit-reset-tokens`, ଏବଂ `Retry-After` ମଧ୍ୟରେ ରେଟ-ଲିମିଟ ହେଡର ଶିକ୍ଷା ଉନ୍ନତ ହୋଇଛି — ପ୍ରତ୍ୟେକ ମଡେଲ-ସ୍କୋପ କୁଲଡାଉନ୍ ଅବସ୍ଥା ରେଜିଲିଏନ୍ସ ଡ୍ୟାସବୋର୍ଡରେ ଦୃଶ୍ୟମାନ।
