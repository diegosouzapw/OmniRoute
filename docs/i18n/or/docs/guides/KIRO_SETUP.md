ଏହି ମାର୍ଗଦର୍ଶିକାରେ OmniRoute-ରେ Kiro (AWS-ହୋଷ୍ଟେଡ୍ AI କୋଡିଂ ସହାୟକ) ଆକାଉଣ୍ଟ ଯୋଡ଼ିବା ବିଷୟରେ ବର୍ଣ୍ଣନା କରାଯାଇଛି,
ଯେଉଁଥିରେ ସେସନ୍ ଦ୍ୱନ୍ଦ୍ୱ ବିନା ଏକାସାଙ୍ଗରେ ଏକାଧିକ ଆକାଉଣ୍ଟ ଚଲାଇବା ଉପରେ ଗୁରୁତ୍ୱ ଦିଆଯାଇଛି।

## ପୃଷ୍ଠଭୂମି: Kiro ଆକାଉଣ୍ଟଗୁଡ଼ିକ ମଧ୍ୟରେ କାହିଁକି ଦ୍ୱନ୍ଦ୍ୱ ହୋଇପାରେ

Kiro-ର ବ୍ୟାକଏଣ୍ଡ ସକ୍ରିୟ ସେସନ୍ଗୁଡ଼ିକୁ ଟ୍ରାକ୍ କରିବା ପାଇଁ AWS SSO OIDC କ୍ଲାଏଣ୍ଟ ପଞ୍ଜୀକରଣ ବ୍ୟବହାର କରେ।
ମୁଖ୍ୟ ସୀମାବଦ୍ଧତା: **ପ୍ରତ୍ୟେକ OIDC କ୍ଲାଏଣ୍ଟ ପଞ୍ଜୀକରଣ ଏକ ସମୟରେ କେବଳ ଗୋଟିଏ ସକ୍ରିୟ
ସେସନ୍କୁ ସମର୍ଥନ କରେ**। ଯେତେବେଳେ ଦ୍ୱିତୀୟ ଡିଭାଇସ୍ କିମ୍ବା ବ୍ୟବହାରକାରୀ ସେହି ସମାନ
ପଞ୍ଜୀକୃତ କ୍ଲାଏଣ୍ଟ ବ୍ୟବହାର କରି ପ୍ରମାଣୀକରଣ କରନ୍ତି, ବ୍ୟାକଏଣ୍ଡ ପ୍ରଥମ ଆକାଉଣ୍ଟର ରିଫ୍ରେଶ୍ ଟୋକନ୍କୁ ଅବୈଧ କରିଦିଏ।

ଏହା ସେହି ସମାନ ପ୍ରକ୍ରିୟା, ଯାହା ଏପରି ଏକ ମେସିନ୍ରେ `kiro-cli login` ଚଲାଇବା ସମୟରେ ସମସ୍ୟା ସୃଷ୍ଟି କରେ
ଯେଉଁଠାରେ ଅନ୍ୟ ଏକ Kiro ଆକାଉଣ୍ଟ ପୂର୍ବରୁ ସାଇନ୍ ଇନ୍ ହୋଇଛି — ନୂତନ ଲଗଇନ୍ ପ୍ରଥମ
ଆକାଉଣ୍ଟର ଟୋକନ୍କୁ ପ୍ରତ୍ୟାହାର କରିଦିଏ।

## OmniRoute ଏହାକୁ କିପରି ସମାଧାନ କରେ (v3.8.0+)

v3.8.0 ଠାରୁ ଆରମ୍ଭ କରି, ପ୍ରତ୍ୟେକ Kiro ସଂଯୋଗ ଆମଦାନୀ ସମୟରେ OmniRoute `registerClient()` (AWS SSO OIDC) କଲ୍ କରେ।
ଏହା ପ୍ରତ୍ୟେକ OmniRoute ସଂଯୋଗକୁ ତାହାର ନିଜସ୍ୱ ଉତ୍ସର୍ଗୀକୃତ OIDC କ୍ଲାଏଣ୍ଟ ପଞ୍ଜୀକରଣ ପ୍ରଦାନ କରେ।
ପ୍ରତ୍ୟେକ କ୍ଲାଏଣ୍ଟ ପଞ୍ଜୀକରଣ ସ୍ୱାଧୀନ ହୋଇଥିବାରୁ, ଗୋଟିଏ ଆକାଉଣ୍ଟକୁ ରିଫ୍ରେଶ୍ କିମ୍ବା
ପୁନଃ-ପ୍ରମାଣୀକରଣ କରିବା ଦ୍ୱାରା ଅନ୍ୟ କୌଣସି ଆକାଉଣ୍ଟର ରିଫ୍ରେଶ୍ ଟୋକନ୍ ପ୍ରଭାବିତ ହୁଏ ନାହିଁ।

ପୃଥକୀକରଣ ରିଫ୍ରେଶ୍-ଟୋକନ୍ ଆମଦାନୀ ପଦ୍ଧତିଗୁଡ଼ିକ ପାଇଁ ପ୍ରଯୁଜ୍ୟ ହୁଏ, ଏବଂ API-key ପ୍ରମାଣୀକରଣ
OIDC ରିଫ୍ରେଶ୍ ସେସନ୍ଗୁଡ଼ିକୁ ସମ୍ପୂର୍ଣ୍ଣ ଭାବେ ଏଡ଼ାଇଥାଏ:

| ଆମଦାନୀ ପଦ୍ଧତି                                   | ପୃଥକୀକରଣ ସ୍ଥିତି                                                                               |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------- |
| AWS Builder ID / IDC ଡିଭାଇସ୍-କୋଡ୍ ପ୍ରବାହ        | ଡିଭାଇସ୍-କୋଡ୍ ପ୍ରବାହ ପ୍ରଚଳିତ ହେବା ପରଠାରୁ ପୃଥକୀକୃତ                                              |
| **ଟୋକନ୍ ଆମଦାନୀ** (ମାନୁଆଲ୍ ରିଫ୍ରେଶ୍ ଟୋକନ୍ ପେଷ୍ଟ) | v3.8.0 ଠାରୁ ପୃଥକୀକୃତ                                                                          |
| **Google / GitHub ସୋସିଆଲ୍ ଲଗଇନ୍**               | v3.8.0 ଠାରୁ ପୃଥକୀକୃତ                                                                          |
| **ସ୍ୱୟଂଚାଳିତ ଆମଦାନୀ** (kiro-cli SQLite)         | v3.8.0 ଠାରୁ ପୃଥକୀକୃତ (SQLite ପଥ ପୂର୍ବରୁ ପୃଥକୀକୃତ ଥିଲା; SSO-cache ଫଲ୍ବ୍ୟାକ୍ ଏବେ ମଧ୍ୟ ପୃଥକୀକୃତ) |
| **API Key** (ଦୀର୍ଘକାଳୀନ CodeWhisperer କୀ)       | କୌଣସି ରିଫ୍ରେଶ୍ ସେସନ୍ ନାହିଁ; କୀ-ଟିକୁ ବୈଧ କରାଯାଇ ଏକ bearer ପରିଚୟପତ୍ର ଭାବେ ସଂରକ୍ଷଣ କରାଯାଏ        |

## v3.8.0 ପୂର୍ବରୁ ସୃଷ୍ଟି ହୋଇଥିବା ସଂଯୋଗଗୁଡ଼ିକ ପାଇଁ ସ୍ଥାନାନ୍ତରଣ ଟିପ୍ପଣୀ

v3.8.0 ପୂର୍ବରୁ ଆମଦାନୀ ହୋଇଥିବା ସଂଯୋଗଗୁଡ଼ିକର `providerSpecificData`-ରେ କୌଣସି ଉତ୍ସର୍ଗୀକୃତ OIDC କ୍ଲାଏଣ୍ଟ ପଞ୍ଜୀକରଣ
ସଂରକ୍ଷିତ ନାହିଁ। ଏହି ସଂଯୋଗଗୁଡ଼ିକ କାର୍ଯ୍ୟ କରିବା ଜାରି ରଖିବ, କିନ୍ତୁ ସେମାନେ ଅଂଶୀଦାରିତ
ସୋସିଆଲ୍-ପ୍ରମାଣୀକରଣ ରିଫ୍ରେଶ୍ ଏଣ୍ଡପଏଣ୍ଟ ବ୍ୟବହାର କରନ୍ତି, ଯାହାର ଅର୍ଥ ହେଉଛି ଏପରି ଦୁଇଟି ସଂଯୋଗ ଏବେ ମଧ୍ୟ ପରସ୍ପରକୁ
ଅବୈଧ କରିପାରେ।

**ପୃଥକୀକରଣ ପାଇବା ପାଇଁ:** **ଡ୍ୟାସବୋର୍ଡ → ପ୍ରଦାତାଗଣ**ରୁ ପୁରୁଣା ସଂଯୋଗକୁ ବିଲୋପ କରନ୍ତୁ ଏବଂ
ସମର୍ଥିତ ଆମଦାନୀ ପ୍ରବାହଗୁଡ଼ିକ ମଧ୍ୟରୁ ଯେକୌଣସି ଗୋଟିଏ ବ୍ୟବହାର କରି ଏହାକୁ ପୁନଃ-ଆମଦାନୀ କରନ୍ତୁ। ସମସ୍ତ ନୂତନ ସଂଯୋଗ
ସ୍ୱୟଂଚାଳିତ ଭାବେ ସେମାନଙ୍କର ନିଜସ୍ୱ କ୍ଲାଏଣ୍ଟ ପଞ୍ଜୀକରଣ ପାଇବ।

## ଦୁଇଟି Kiro ଆକାଉଣ୍ଟକୁ ପାର୍ଶ୍ୱରେ ପାର୍ଶ୍ୱରେ ଯୋଡ଼ିବା

### ପୂର୍ବାବଶ୍ୟକତା

- OmniRoute v3.8.0 କିମ୍ବା ପରବର୍ତ୍ତୀ ସଂସ୍କରଣ।
- ଏକ କାର୍ଯ୍ୟକ୍ଷମ Kiro ଆକାଉଣ୍ଟ (ଇମେଲ୍ + ପାସୱାର୍ଡ, Google, କିମ୍ବା GitHub ଲଗଇନ୍)।
- ବୈକଳ୍ପିକ ଭାବେ ଏକ ଦ୍ୱିତୀୟ Kiro ଆକାଉଣ୍ଟ।

### ପଦକ୍ଷେପ 1: ପ୍ରଥମ ଆକାଉଣ୍ଟ ଆମଦାନୀ କରନ୍ତୁ

1. **ଡ୍ୟାସବୋର୍ଡ → ପ୍ରଦାତାଗଣ → ପ୍ରଦାତା ଯୋଡ଼ନ୍ତୁ → Kiro** ଖୋଲନ୍ତୁ।
2. ନିମ୍ନଲିଖିତ ମଧ୍ୟରୁ ଗୋଟିଏ ବାଛନ୍ତୁ:
   - **ଟୋକନ୍ ଆମଦାନୀ** — `aorAAAAAG`ରୁ ଆରମ୍ଭ ହେଉଥିବା ଏକ ରିଫ୍ରେଶ୍ ଟୋକନ୍ ପେଷ୍ଟ କରନ୍ତୁ।
   - **API Key** — ଏକ ଦୀର୍ଘକାଳୀନ Kiro / CodeWhisperer API କୀ ପେଷ୍ଟ କରନ୍ତୁ।
   - **Google / GitHub ଲଗଇନ୍** — ବ୍ରାଉଜର୍ରେ OAuth ପ୍ରବାହ ସମ୍ପୂର୍ଣ୍ଣ କରନ୍ତୁ।
   - **ସ୍ୱୟଂଚାଳିତ ଆମଦାନୀ** — ବଟନ୍ଟି କ୍ଲିକ୍ କରନ୍ତୁ; OmniRoute ସ୍ଥାନୀୟ
     kiro-cli ଡାଟାବେସ୍ କିମ୍ବା `~/.aws/sso/cache`ରୁ ପରିଚୟପତ୍ରଗୁଡ଼ିକ ପଢ଼େ।
3. ସଂଯୋଗଟି ସଂରକ୍ଷିତ ହୁଏ। ରିଫ୍ରେଶ୍-ଟୋକନ୍ ପ୍ରବାହଗୁଡ଼ିକ ସ୍ୱୟଂଚାଳିତ ଭାବେ ଏକ ଉତ୍ସର୍ଗୀକୃତ
   OIDC କ୍ଲାଏଣ୍ଟ ପଞ୍ଜୀକୃତ କରନ୍ତି। API-key ପ୍ରବାହଗୁଡ଼ିକ AWS ସହିତ କୀ-କୁ ବୈଧ କରନ୍ତି ଏବଂ କୌଣସି ରିଫ୍ରେଶ୍ ଟୋକନ୍ ସଂରକ୍ଷଣ କରନ୍ତି ନାହିଁ।

### ପଦକ୍ଷେପ 2: ଦ୍ୱିତୀୟ ଆକାଉଣ୍ଟ ଆମଦାନୀ କରନ୍ତୁ

ଦ୍ୱିତୀୟ ଆକାଉଣ୍ଟ ପାଇଁ ପଦକ୍ଷେପ 1 ପୁନରାବୃତ୍ତି କରନ୍ତୁ। ପ୍ରତ୍ୟେକ ଆମଦାନୀ ଏକ ପୃଥକ OIDC
କ୍ଲାଏଣ୍ଟ ପଞ୍ଜୀକରଣ ସୃଷ୍ଟି କରୁଥିବାରୁ, ଦୁଇଟି ସଂଯୋଗ ସମ୍ପୂର୍ଣ୍ଣ ଭାବେ ପୃଥକୀକୃତ ରହେ।

### ପଦକ୍ଷେପ 3: ଉଭୟ ସଂଯୋଗ ସକ୍ରିୟ ଥିବା ଯାଞ୍ଚ କରନ୍ତୁ

1. **ଡ୍ୟାସବୋର୍ଡ → ପ୍ରଦାତାଗଣ** — ଉଭୟ Kiro ସଂଯୋଗର ସ୍ଥିତି **ସକ୍ରିୟ** ଭାବେ ଦେଖାଯିବା ଉଚିତ।
2. **ଡ୍ୟାସବୋର୍ଡ → ସ୍ୱାସ୍ଥ୍ୟ** — ଉଭୟ ସଂଯୋଗ ସେମାନଙ୍କର ଟୋକନ୍ ସ୍ୱାସ୍ଥ୍ୟ ଯାଞ୍ଚରେ ସଫଳ ହେବା ଉଚିତ।

### ପଦକ୍ଷେପ 4: ଆକାଉଣ୍ଟଗୁଡ଼ିକ ମଧ୍ୟରେ ରାଉଟ୍ କରିବା ପାଇଁ ଏକ କମ୍ବୋ ବ୍ୟବହାର କରନ୍ତୁ

ଲୋଡ୍-ବ୍ୟାଲାନ୍ସ କରିବା କିମ୍ବା ସେମାନଙ୍କ ମଧ୍ୟରେ ଫଲ୍ବ୍ୟାକ୍ କରିବା ପାଇଁ ଉଭୟ ସଂଯୋଗକୁ ଲକ୍ଷ୍ୟ ଭାବେ ରଖି ଏକ କମ୍ବୋ ସୃଷ୍ଟି କରନ୍ତୁ:

```
kiro/kiro-dev → kiro/kiro-pro
```

କମ୍ବୋ ବିନ୍ୟାସ ପାଇଁ [FEATURES.md](./FEATURES.md) ଏବଂ ରାଉଟିଂ ଡକ୍ୟୁମେଣ୍ଟେସନ୍ ଦେଖନ୍ତୁ।

## ଏଣ୍ଟରପ୍ରାଇଜ୍ / IDC ବ୍ୟବହାରକାରୀ

AWS IAM Identity Center (IDC) ଆକାଉଣ୍ଟଗୁଡ଼ିକ ପାଇଁ, **Dashboard → Providers → Kiro → Device Code** ରୁ **AWS Builder ID / IDC device-code** ପ୍ରବାହ ବ୍ୟବହାର କରନ୍ତୁ। device-code ପ୍ରବାହ ସର୍ବଦା ସମ୍ପୂର୍ଣ୍ଣ ଭାବେ ପୃଥକ ରହିଆସିଛି। ଏହି ସଂଯୋଗଗୁଡ଼ିକ ପାଇଁ ପୁନଃ-ଆମଦାନୀ ଆବଶ୍ୟକ ନୁହେଁ।

ଏକ ଅଣ-ଡିଫଲ୍ଟ AWS ଅଞ୍ଚଳରେ କାର୍ଯ୍ୟ କରୁଥିବା ଏଣ୍ଟରପ୍ରାଇଜ୍ ବ୍ୟବହାରକାରୀମାନେ Import Token API ମାଧ୍ୟମରେ ଆମଦାନୀ କରିବା ସମୟରେ ଅଞ୍ଚଳ ନିର୍ଦ୍ଦିଷ୍ଟ କରିପାରିବେ:

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/import \
  -H "Content-Type: application/json" \
  -d '{"refreshToken": "aorAAAAAG...", "region": "eu-west-1"}'
```

`region` ଫିଲ୍ଡ ଛାଡ଼ି ଦିଆଗଲେ, ଏହା ଡିଫଲ୍ଟ ଭାବେ `us-east-1` ବ୍ୟବହାର କରେ।

## API-Key ଆମଦାନୀ ପ୍ରବାହ

API-key ପ୍ରମାଣୀକରଣ ଦୀର୍ଘକାଳୀନ Kiro / AWS CodeWhisperer bearer ପ୍ରମାଣପତ୍ରଗୁଡ଼ିକ ପାଇଁ ଉଦ୍ଦିଷ୍ଟ। ଏହା OAuth refresh ବ୍ୟବହାର କରେ ନାହିଁ, ତେଣୁ ଅଂଶୀଦାରିତ OIDC ସେସନ୍ ଅବୈଧ ହେବାରୁ ଏହା ରକ୍ଷା କରେ।

### ଡ୍ୟାସବୋର୍ଡ

1. **Dashboard -> Providers -> Kiro** ଖୋଲନ୍ତୁ।
2. **API Key** ବାଛନ୍ତୁ।
3. API key ଏବଂ ଇଚ୍ଛାଧୀନ AWS ଅଞ୍ଚଳ (ଡିଫଲ୍ଟ ଭାବେ `us-east-1`) ପେଷ୍ଟ କରନ୍ତୁ।
4. OmniRoute keyକୁ ବୈଧ କରି ସଂଯୋଗଟି ସଞ୍ଚୟ କରେ।

### API

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/api-key \
  -H "Content-Type: application/json" \
  -d '{"apiKey": "kiro_or_codewhisperer_key", "region": "us-east-1"}'
```

### ଆଭ୍ୟନ୍ତରୀଣ ଚୁକ୍ତି

API ରୁଟ୍ `KiroService.validateApiKey()`କୁ କଲ୍ କରି keyକୁ ବୈଧ କରେ, ଯାହା ଅଞ୍ଚଳ ସହ ମେଳ ଖାଉଥିବା CodeWhisperer/Amazon Q endpoint ବିପକ୍ଷରେ `ListAvailableProfiles` ବ୍ୟବହାର କରି ଏକ `profileArn` ସମାଧାନ କରେ।

ସଞ୍ଚିତ ସଂଯୋଗ ନିମ୍ନଲିଖିତକୁ ବ୍ୟବହାର କରେ:

```json
{
  "authType": "apikey",
  "providerSpecificData": {
    "authMethod": "api_key",
    "region": "us-east-1",
    "profileArn": "arn:aws:codewhisperer:..."
  }
}
```

ରନ୍ଟାଇମ୍ରେ, `KiroExecutor.buildHeaders()` keyକୁ `Authorization: Bearer <key>` ଭାବେ ପଠାଏ ଏବଂ `tokentype: API_KEY` ଯୋଡ଼େ। କୋଟା/ପ୍ରୋଫାଇଲ୍ କଲ୍ଗୁଡ଼ିକ ସମାନ ମାର୍କର୍ ବ୍ୟବହାର କରନ୍ତି, ଯାହାଦ୍ୱାରା AWS bearerକୁ OIDC କିମ୍ବା ସାମାଜିକ access token ପରିବର୍ତ୍ତେ ଏକ ଦୀର୍ଘକାଳୀନ API key ଭାବେ ବିବେଚନା କରେ।

## OIDC କ୍ଲାଏଣ୍ଟର ମିଆଦ ସମାପ୍ତି

AWS SSO OIDC ସାର୍ବଜନୀନ କ୍ଲାଏଣ୍ଟଗୁଡ଼ିକର ମିଆଦ ସାଧାରଣତଃ 90 ଦିନ ପରେ ସମାପ୍ତ ହୁଏ (`clientSecretExpiresAt`)। ପର୍ଯ୍ୟବେକ୍ଷଣଯୋଗ୍ୟତା ପାଇଁ OmniRoute ଏହି timestampକୁ `providerSpecificData`ରେ ସଞ୍ଚୟ କରେ। ଯଦି କୌଣସି ସଂଯୋଗ ~90 ଦିନ ପରେ refresh ହେବା ବନ୍ଦ କରେ, ଏକ ନୂତନ OIDC କ୍ଲାଏଣ୍ଟ ପଞ୍ଜୀକରଣ ପାଇବା ପାଇଁ ସଂଯୋଗଟିକୁ ପୁନଃ-ଆମଦାନୀ କରନ୍ତୁ। ମିଆଦ ସମାପ୍ତି ସମୟରେ ସ୍ୱୟଂଚାଳିତ ପୁନଃ-ପଞ୍ଜୀକରଣକୁ ଭବିଷ୍ୟତ ଉନ୍ନତି ଭାବେ ଟ୍ରାକ୍ କରାଯାଉଛି।

API-key ସଂଯୋଗଗୁଡ଼ିକରେ OIDC କ୍ଲାଏଣ୍ଟ ମିଆଦ ସମାପ୍ତି ନଥାଏ, କାରଣ ସେଗୁଡ଼ିକ AWS SSO OIDC ମାଧ୍ୟମରେ refresh କରନ୍ତି ନାହିଁ।

## ସମସ୍ୟା ନିବାରଣ

### ଦ୍ୱିତୀୟ ଆକାଉଣ୍ଟଟି ବାରମ୍ବାର ଲଗ୍ ଆଉଟ୍ ହେଉଛି

- **Dashboard → Providers**ରେ ଉଭୟ ସଂଯୋଗ ଯାଞ୍ଚ କରନ୍ତୁ ଏବଂ ପ୍ରତ୍ୟେକର raw JSONରେ (ସୂଚନା ଆଇକନ୍ ମାଧ୍ୟମରେ ଦୃଶ୍ୟମାନ) ଏକ non-null `clientId` ଦେଖାଯାଉଛି ବୋଲି ନିଶ୍ଚିତ କରନ୍ତୁ। ଯଦି କୌଣସି ସଂଯୋଗରେ `clientId` ନାହିଁ, ତେବେ ଏହା v3.8.0 ପୂର୍ବରୁ ଆମଦାନୀ କରାଯାଇଥିଲା — ଏହାକୁ ପୁନଃ-ଆମଦାନୀ କରନ୍ତୁ।

### "Token validation failed" ସହିତ ଆମଦାନୀ ବିଫଳ ହେଉଛି

- refresh tokenଟି `aorAAAAAG`ରୁ ଆରମ୍ଭ ହେଉଛି ବୋଲି ନିଶ୍ଚିତ କରନ୍ତୁ।
- OmniRoute `https://oidc.us-east-1.amazonaws.com` (କିମ୍ବା ବିନ୍ୟାସିତ ଅଞ୍ଚଳ)ରେ ପହଞ୍ଚିପାରୁଛି ବୋଲି ନିଶ୍ଚିତ କରନ୍ତୁ। ଯଦି ଆପଣ ଏକ କର୍ପୋରେଟ୍ proxy ପଛରେ ଅଛନ୍ତି, ତେବେ **Dashboard → Settings → Proxies**ରେ ଏକ provider-level proxy ସେଟ୍ କରନ୍ତୁ।

### API-key ଆମଦାନୀ ବିଫଳ ହେଉଛି

- keyଟି ଏକ Kiro / CodeWhisperer API key, refresh token ନୁହେଁ ବୋଲି ନିଶ୍ଚିତ କରନ୍ତୁ।
- AWS ଅଞ୍ଚଳଟି key/ଆକାଉଣ୍ଟ ସହ ମେଳ ଖାଉଛି ବୋଲି ନିଶ୍ଚିତ କରନ୍ତୁ। `us-east-1` ହେଉଛି ଡିଫଲ୍ଟ।
- keyଟି `ListAvailableProfiles`କୁ କଲ୍ କରିପାରିବା ଆବଶ୍ୟକ; ନଚେତ୍ OmniRoute ଆବଶ୍ୟକ `profileArn`କୁ ସମାଧାନ କରିପାରିବ ନାହିଁ।

ଅନ୍ୟାନ୍ୟ ସମସ୍ୟା ପାଇଁ, ମୁଖ୍ୟ [TROUBLESHOOTING.md](./TROUBLESHOOTING.md) ଦେଖନ୍ତୁ।
