OmniRoute-କୁ Termux ମାଧ୍ୟମରେ Android ଉପରେ ଏକ ହେଡ୍ଲେସ୍ ସର୍ଭର ଭାବେ ଚଲାଯାଇପାରିବ। Electron ଡେସ୍କଟପ୍ ଆପ୍ଟି Termux-ରେ ସମର୍ଥିତ ନୁହେଁ, କିନ୍ତୁ ୱେବ୍ ଡ୍ୟାସ୍ବୋର୍ଡ ଏବଂ OpenAI-ସୁସଙ୍ଗତ API ସ୍ଥାନୀୟ ବ୍ରାଉଜର୍ କିମ୍ବା ସେହି ନେଟୱର୍କରେ ଥିବା ଅନ୍ୟ ଡିଭାଇସ୍ରୁ କାମ କରେ।

## ପୂର୍ବାବଶ୍ୟକତା

F-Droid କିମ୍ବା GitHub ରିଲିଜ୍ରୁ Termux ଇନଷ୍ଟଲ୍ କରନ୍ତୁ, ତା’ପରେ ପ୍ୟାକେଜ୍ଗୁଡ଼ିକୁ ଅପଡେଟ୍ କରି `better-sqlite3` ପରି ନେଟିଭ୍ ଡିପେଣ୍ଡେନ୍ସି ପାଇଁ ଆବଶ୍ୟକ ବିଲ୍ଡ ଟୁଲ୍ଗୁଡ଼ିକ ଇନଷ୍ଟଲ୍ କରନ୍ତୁ।

```bash
pkg update
pkg upgrade
pkg install nodejs python build-essential git
```

> **Node.js ସଂସ୍କରଣ:** OmniRoute ପାଇଁ Node `>=22.22.2 <23 || >=24.0.0 <27` ଆବଶ୍ୟକ (`package.json` / `SUPPORTED_NODE_RANGE`-ରେ ଥିବା `engines` ସହ ମେଳ ଖାଏ)। Termux-ର `nodejs-lts` ସାଧାରଣତଃ Node 20 LTS ପ୍ରଦାନ କରେ, ଯାହା **ଆଉ ସମର୍ଥିତ ନୁହେଁ** — ଏହା ପରିବର୍ତ୍ତେ `pkg install nodejs` (ବର୍ତ୍ତମାନର ସଂସ୍କରଣ) ଇନଷ୍ଟଲ୍ କରନ୍ତୁ ଏବଂ `node --version` 22.x/24.x+ ଶୃଙ୍ଖଳାର ଏକ ସଂସ୍କରଣ ଦେଖାଉଛି ବୋଲି ଯାଞ୍ଚ କରନ୍ତୁ।

ନେଟିଭ୍ ପ୍ୟାକେଜ୍ କମ୍ପାଇଲେସନ୍ ବିଫଳ ହେଲେ, ଉପରୋକ୍ତ `pkg install` କମାଣ୍ଡ୍ଟି ପୁଣି ଚଲାନ୍ତୁ ଏବଂ ତା’ପରେ OmniRoute ଇନଷ୍ଟଲେସନ୍ ପୁନଃଚେଷ୍ଟା କରନ୍ତୁ।

## ଇନଷ୍ଟଲ୍ କରିବା

ସର୍ବଶେଷ ପ୍ରକାଶିତ ପ୍ୟାକେଜ୍ଟିକୁ ସିଧାସଳଖ ଚଲାନ୍ତୁ:

```bash
npx -y omniroute@latest
```

ଆପଣ ଏହାକୁ ଗ୍ଲୋବାଲ୍ ଭାବରେ ମଧ୍ୟ ଇନଷ୍ଟଲ୍ କରିପାରିବେ:

```bash
npm install -g omniroute
omniroute
```

## ଚଲାଇବା

OmniRoute-କୁ ହେଡ୍ଲେସ୍ ସର୍ଭର ମୋଡ୍ରେ ଆରମ୍ଭ କରନ୍ତୁ:

```bash
omniroute
```

କିମ୍ବା:

```bash
npx omniroute
```

ଡ୍ୟାସ୍ବୋର୍ଡ ଏଠାରେ ଶୁଣେ:

```text
http://localhost:20128
```

Android ବ୍ରାଉଜର୍ରେ ସେହି URL ଖୋଲନ୍ତୁ। ଯଦି ଆପଣ Termux ଭିତରେ କ୍ଲାଏଣ୍ଟ ଚଲାଉଛନ୍ତି, ତେବେ OpenAI-ସୁସଙ୍ଗତ ବେସ୍ URL ଭାବେ ସମାନ ହୋଷ୍ଟ ଏବଂ ପୋର୍ଟ ବ୍ୟବହାର କରନ୍ତୁ।

## ପୃଷ୍ଠଭୂମିରେ ନିଷ୍ପାଦନ

ଏକ ସରଳ ପୃଷ୍ଠଭୂମି ପ୍ରକ୍ରିୟା ପାଇଁ:

```bash
nohup omniroute > omniroute.log 2>&1 &
```

ଏହାକୁ ବନ୍ଦ କରିବା ପାଇଁ:

```bash
pkill -f omniroute
```

ଡିଭାଇସ୍ ବୁଟ୍ ହେବା ପରେ ସ୍ୱୟଂଚାଳିତ ଷ୍ଟାର୍ଟଅପ୍ ପାଇଁ, Termux:Boot ଆଡ୍-ଅନ୍ ଇନଷ୍ଟଲ୍ କରନ୍ତୁ ଏବଂ ଏକ ବୁଟ୍ ସ୍କ୍ରିପ୍ଟ ତିଆରି କରନ୍ତୁ:

```bash
mkdir -p ~/.termux/boot
cat > ~/.termux/boot/omniroute.sh <<'EOF'
#!/data/data/com.termux/files/usr/bin/sh
cd "$HOME"
nohup omniroute > "$HOME/omniroute.log" 2>&1 &
EOF
chmod +x ~/.termux/boot/omniroute.sh
```

Android ବ୍ୟାଟେରୀ ଅପ୍ଟିମାଇଜେସନ୍ ଦୀର୍ଘ ସମୟ ଧରି ଚାଲୁଥିବା ପୃଷ୍ଠଭୂମି ପ୍ରକ୍ରିୟାଗୁଡ଼ିକୁ ବନ୍ଦ କରିପାରେ। ସର୍ଭର୍ଟି ଅନଲାଇନ୍ ରହିବା ଆଶା କରାଯାଉଥିଲେ Termux ପାଇଁ ବ୍ୟାଟେରୀ ଅପ୍ଟିମାଇଜେସନ୍ ଅକ୍ଷମ କରନ୍ତୁ।

## ଅନ୍ୟ ଡିଭାଇସ୍ରୁ ପ୍ରବେଶ

WiFi ନେଟୱର୍କରେ ଫୋନ୍ର IP ଠିକଣା ଖୋଜନ୍ତୁ:

```bash
ip addr show wlan0
```

ତା’ପରେ ଅନ୍ୟ ଏକ ଡିଭାଇସ୍ରୁ ଡ୍ୟାସ୍ବୋର୍ଡ ଖୋଲନ୍ତୁ:

```text
http://PHONE_IP:20128
```

ଉଦାହରଣ ସ୍ୱରୂପ:

```text
http://192.168.1.50:20128
```

ଫୋନ୍ ଏବଂ କ୍ଲାଏଣ୍ଟକୁ ସମାନ ବିଶ୍ୱସ୍ତ ନେଟୱର୍କରେ ରଖନ୍ତୁ। ଯଦି ଆପଣ OmniRoute-କୁ ଫୋନ୍ ବାହାରେ ଉପଲବ୍ଧ କରାନ୍ତି, ତେବେ API କୀ ଏବଂ ଡ୍ୟାସ୍ବୋର୍ଡ ପ୍ରମାଣୀକରଣ ସକ୍ଷମ କରନ୍ତୁ।

## ଡାଟା ଡିରେକ୍ଟୋରୀ

ଡିଫଲ୍ଟ ଭାବରେ OmniRoute, Linux-ରେ ବ୍ୟବହୃତ ସମାନ ସର୍ଭର୍-ସାଇଡ୍ ଡାଟା ପଥ ଆଚରଣ ଅନୁସରଣ କରି, Termux ହୋମ୍ ଡିରେକ୍ଟୋରୀ ଅଧୀନରେ ଡାଟା ସଞ୍ଚୟ କରେ। ଡାଟାବେସ୍କୁ ଏକ ସ୍ପଷ୍ଟ ସ୍ଥାନରେ ରଖିବା ପାଇଁ:

```bash
export DATA_DIR="$HOME/.omniroute"
omniroute
```

## ସୀମାବଦ୍ଧତା

- Electron, Termux-ରେ ଚାଲେ ନାହିଁ।
- କୌଣସି ସିଷ୍ଟମ୍ ଟ୍ରେ କିମ୍ବା ଡେସ୍କଟପ୍ ଇଣ୍ଟିଗ୍ରେସନ୍ ନାହିଁ।
- ଏହି ସେଟଅପ୍ କେବଳ ସର୍ଭର ପାଇଁ: ବ୍ରାଉଜର୍ ଡ୍ୟାସ୍ବୋର୍ଡ ବ୍ୟବହାର କରନ୍ତୁ।
- ନେଟିଭ୍ ଡିପେଣ୍ଡେନ୍ସିଗୁଡ଼ିକ ପାଇଁ ସ୍ଥାନୀୟ କମ୍ପାଇଲେସନ୍ ଆବଶ୍ୟକ ହୋଇପାରେ।
- କମ୍ ମେମୋରୀ ଥିବା Android ଡିଭାଇସ୍ରେ କମ୍ ସଂଖ୍ୟକ ସମକାଳୀନ ଅନୁରୋଧ ଆବଶ୍ୟକ ହୋଇପାରେ।
- MITM/ସିଷ୍ଟମ୍ ସାର୍ଟିଫିକେଟ୍ ବୈଶିଷ୍ଟ୍ୟଗୁଡ଼ିକ ପାଇଁ Termux ବାହାରେ Android-ସ୍ତରୀୟ ଟ୍ରଷ୍ଟ-ଷ୍ଟୋର୍ କାର୍ଯ୍ୟ ଆବଶ୍ୟକ ହୋଇପାରେ।

## ସମସ୍ୟା ସମାଧାନ

### ଅସମର୍ଥିତ ପ୍ଲାଟଫର୍ମ: android (ପ୍ରତ୍ୟେକ ଅନୁରୋଧ HTTP 500 ଫେରାଏ)

**ଲକ୍ଷଣ:** `omniroute` / `omniroute serve`, `✔ OmniRoute is running!` ପ୍ରିଣ୍ଟ କରେ, କିନ୍ତୁ ପ୍ରତ୍ୟେକ ଡ୍ୟାସ୍ବୋର୍ଡ କିମ୍ବା API ଅନୁରୋଧ ଏକ ସାଧାରଣ `500 Internal Server Error` ଫେରାଏ। `~/.omniroute/logs/application/app.log` ଖାଲି ରହେ, `APP_LOG_LEVEL=debug` କୌଣସି ଉପଯୋଗୀ ସୂଚନା ପ୍ରିଣ୍ଟ କରେ ନାହିଁ ଏବଂ ପ୍ରତିକ୍ରିୟା ବଡି କୌଣସି JSON ବିବରଣୀ ବିନା ସାଧାରଣ ଟେକ୍ସଟ୍ (`Internal Server Error`) ହୋଇଥାଏ।

**କାରଣ:** କିଛି Termux/Node ବିଲ୍ଡ `process.platform === "android"` ରିପୋର୍ଟ କରେ। Next.js `getCacheDirectory()` ସେହି ପ୍ଲାଟଫର୍ମକୁ ପରିଚାଳନା କରେ ନାହିଁ: ଏହା ପାଇଁ `~/.cache` (କିମ୍ବା ଏକ ସାଧାରଣ tmp ଡିରେକ୍ଟୋରୀ) _ପୂର୍ବରୁ_ ଅବସ୍ଥିତ ରହିବା ଆବଶ୍ୟକ, ନଚେତ୍ ଇନଷ୍ଟ୍ରୁମେଣ୍ଟେସନ୍ ହୁକ୍ ଲୋଡ୍ କରିବା ସମୟରେ ଏହି ତ୍ରୁଟି ସହ ବିଫଳ ହୁଏ:

```text
Error: An error occurred while loading instrumentation hook: Unsupported platform: android
```

ହୁକ୍ଟି କେବେ ଲୋଡ୍ ହେଉନଥିବାରୁ, ଲଗିଂ କେବେ ଆରମ୍ଭ ହୁଏ ନାହିଁ — ତେଣୁ 500 ତ୍ରୁଟିଟି ସମ୍ପୂର୍ଣ୍ଣ ଭାବେ ନିଦାନ କରିବା ଅସମ୍ଭବ ମନେ ହୁଏ। Android/Termux-ରେ ଏହି ପ୍ରୋବ୍ ସଫଳ ହେବା ପାଇଁ OmniRoute, Next.js ଆରମ୍ଭ ହେବା ପୂର୍ବରୁ CLI ଏଣ୍ଟ୍ରିପଏଣ୍ଟରେ `~/.cache` ତିଆରି କରେ (ଏବଂ `XDG_CACHE_HOME` ସେଟ୍ ହୋଇନଥିଲେ ଏହାକୁ ସେଟ୍ କରେ)।

**ସମର୍ଥିତ ସମାଧାନ (ପ୍ୟାକେଜ୍ ପ୍ୟାଚିଂ ବିନା):**

```bash
mkdir -p ~/.cache
omniroute serve
```

ବର୍ତ୍ତମାନର OmniRoute ବିଲ୍ଡଗୁଡ଼ିକରେ CLI, Android/Termux ଉପରେ ଏହା ସ୍ୱୟଂଚାଳିତ ଭାବରେ କରେ — ଏକ ନୂତନ `npx -y omniroute@latest` / ଗ୍ଲୋବାଲ୍ ଇନଷ୍ଟଲେସନ୍ରେ ଏହି ମାନୁଆଲ୍ ପଦକ୍ଷେପ ଆବଶ୍ୟକ ହେବା ଉଚିତ୍ ନୁହେଁ। ଅପଗ୍ରେଡ୍ କରିବା ପରେ ମଧ୍ୟ ଯଦି ଆପଣ ତ୍ରୁଟିଟି ଦେଖନ୍ତି, ତେବେ ଉପରୋକ୍ତ ଭାବରେ ଥରେ `~/.cache` ତିଆରି କରି ପୁନଃଆରମ୍ଭ କରନ୍ତୁ।

`process.platform = "linux"` ବାଧ୍ୟତାମୂଳକ କରିବା ପାଇଁ `dist/server.js`-କୁ ପ୍ୟାଚ୍ **କରନ୍ତୁ ନାହିଁ**। ଏପରି ପ୍ୟାକେଜ୍ ପ୍ୟାଚ୍ ପ୍ରତ୍ୟେକ ପୁନଃଇନଷ୍ଟଲେସନ୍/ଅପଗ୍ରେଡ୍ରେ ଓଭର୍ରାଇଟ୍ ହୋଇଯାଏ ଏବଂ କ୍ୟାଶ୍ ଡିରେକ୍ଟୋରୀ ଥରେ ତିଆରି ହୋଇଗଲେ ଏହା ଅନାବଶ୍ୟକ।

pkg install nodejs python build-essential

### ପୋର୍ଟ ପୂର୍ବରୁ ବ୍ୟବହାରରେ ଅଛି

ଡିଫଲ୍ଟ ପୋର୍ଟରେ କେଉଁ ପ୍ରକ୍ରିୟା ଶୁଣୁଛି ଯାଞ୍ଚ କରନ୍ତୁ:

ss -ltnp | grep 20128
```

```

### ଅନ୍ୟ ଡିଭାଇସ୍ରୁ ଡ୍ୟାସ୍ବୋର୍ଡ ଉପଲବ୍ଧ ନୁହେଁ

ଉଭୟ ଡିଭାଇସ୍ ସମାନ WiFi ନେଟୱର୍କରେ ଅଛନ୍ତି ବୋଲି ଯାଞ୍ଚ କରନ୍ତୁ, ତା’ପରେ Termux-ରୁ ପରୀକ୍ଷା କରନ୍ତୁ:

```bash
curl http://localhost:20128
```

ସ୍ଥାନୀୟ ପ୍ରବେଶ କାମ କରୁଥିଲେ ମଧ୍ୟ LAN ପ୍ରବେଶ କାମ ନକଲେ, ଫୋନ୍ର Android ହଟ୍ସ୍ପଟ୍/WiFi ଆଇସୋଲେସନ୍ ଏବଂ ଯେକୌଣସି ଫାୟାରୱାଲ୍ କିମ୍ବା VPN ପ୍ରୋଫାଇଲ୍ ଯାଞ୍ଚ କରନ୍ତୁ।
