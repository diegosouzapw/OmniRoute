OmniRoute, OpenAI Codex ବ୍ୟବହାର କରିବା ପାଇଁ **ଦୁଇଟି** ଉପାୟ ପ୍ରଦାନ କରେ:

| ପ୍ରଦାନକାରୀ             | ଏହା OpenAI ସହ କିପରି ଯୋଗାଯୋଗ କରେ                                                                                                                                                                      | ବ୍ୟବହାର ସମ୍ବନ୍ଧୀୟ ସତର୍କତା                                            |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| **`codex`**            | ଆପଣଙ୍କ ChatGPT/OpenAI OAuth ଟୋକେନ୍କୁ ସିଧାସଳଖ Responses APIକୁ ପୁନଃପ୍ରେରଣ କରେ                                                                                                                          | **ହଁ** — ଅଧିକୃତ ସେସନ୍ଟି proxy/router ବ୍ୟବହାର ପାଇଁ ଅନୁମୋଦିତ ନୁହେଁ     |
| **`codex-app-server`** | JSON-RPC/WebSocket ମାଧ୍ୟମରେ **Codex CLIର ନିଜସ୍ୱ `codex app-server`** ପରିଚାଳନା କରେ; ଏକ ଇଣ୍ଟରାକ୍ଟିଭ୍ `codex` ସେସନ୍ ପରି CLI ନିଜ OAuth (`~/.codex/auth.json`)ର ମାଲିକାନା ରଖେ ଏବଂ ନିଜେ ତାହାକୁ ରିଫ୍ରେଶ୍ କରେ | **ନା** — OmniRoute କେବେ ମଧ୍ୟ APIକୁ କୌଣସି ଟୋକେନ୍ ପୁନଃପ୍ରେରଣ କରେ ନାହିଁ |

ଯେହେତୁ `codex-app-server` କେବେ ମଧ୍ୟ କୌଣସି ଟୋକେନ୍ ପୁନଃପ୍ରେରଣ କରେ ନାହିଁ, ତେଣୁ ଏହା ପାଇଁ
ସେସନ୍ ପୁନଃପ୍ରେରଣ ସମ୍ବନ୍ଧୀୟ ବ୍ୟବହାର ସତର୍କତା ପ୍ରଯୁଜ୍ୟ ନୁହେଁ। ଏଥିପାଇଁ କିନ୍ତୁ **ବିନ୍ୟାସିତ
app-server URLରେ ପହଞ୍ଚଯୋଗ୍ୟ ଏକ Codex CLI** ଆବଶ୍ୟକ, ଏବଂ ସେହି CLIରେ **ସାଇନ୍ ଇନ୍ କରାଯାଇଥିବା** ଆବଶ୍ୟକ।

## 1. ସଂରଚନା

```
┌─ OmniRoute ଆପ୍ ────────────────┐        ┌─ codex-app-server sidecar ─────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ କ୍ଷମତା ଟୋକେନ୍)              │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  OpenAI OAuth ନିଜେ ପରିଚାଳନା କରେ    │
└──────────────────────────────────┘        │  (~/.codex/auth.json, ସ୍ୱୟଂ-ରିଫ୍ରେଶ୍) │
        │ ସେୟାର୍ କରେ (compose volumes)       └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → WS କ୍ଷମତା ଟୋକେନ୍ (ଉଭୟ ଏହାକୁ ମାଉଣ୍ଟ୍ କରନ୍ତି)
  codex-appserver-home    → ~/.codex (ଡ୍ୟାସ୍ବୋର୍ଡ ଦ୍ୱାରା auth.json ଲେଖାଯାଏ,
                             sidecarର codex app-server ଦ୍ୱାରା ପଢ଼ାଯାଏ)
```

- sidecarଟି ଏକ କ୍ଷମତା ଟୋକେନ୍ ପଛରେ କେବଳ ଆଭ୍ୟନ୍ତରୀଣ compose ନେଟୱର୍କରେ
  (`ws://codex-app-server:1456`) ଶୁଣେ। ଏହାକୁ **କେବେ ମଧ୍ୟ**
  ହୋଷ୍ଟ କିମ୍ବା ଇଣ୍ଟରନେଟ୍ରେ ପ୍ରକାଶ କରାଯାଏ ନାହିଁ।
- Codex CLIକୁ `omniroute:base` ମଧ୍ୟରେ ସମ୍ମିଳିତ କରାଯାଇଛି, ତେଣୁ sidecar ଚଲାଇବାବେଳେ
  ହୋଷ୍ଟ କିମ୍ବା ବ୍ୟବହାରକାରୀଙ୍କ ମେସିନ୍ରେ codex ଇନ୍ଷ୍ଟଲ୍ କରିବା ଆବଶ୍ୟକ ନାହିଁ।

## 2. ଏହାକୁ ଚାଲୁ କରନ୍ତୁ

```bash
# codex app-server sidecar ପ୍ରୋଫାଇଲ୍ ସହିତ ଷ୍ଟାକ୍ ଆରମ୍ଭ କରନ୍ତୁ:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

ପ୍ରଥମ ବୁଟ୍ରେ sidecar ନିଜର WS କ୍ଷମତା ଟୋକେନ୍ ସୃଷ୍ଟି କରେ (ସେୟାର୍ କରାଯାଇଥିବା
`codex-appserver-token` volumeରେ) ଏବଂ ଆପ୍ଟି
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE` ମାଧ୍ୟମରେ ସେହି ଟୋକେନ୍କୁ ପଢ଼େ।
ଟୋକେନ୍କୁ ହାତରେ ସଂଯୋଗ କରିବା ଆବଶ୍ୟକ ନାହିଁ।

## 3. ସଂଯୋଗ + ସାଇନ୍ ଇନ୍

1. ଡ୍ୟାସ୍ବୋର୍ଡରେ **OpenAI Codex (App-Server)** ପାଇଁ ଏକ ସଂଯୋଗ ଯୋଡ଼ନ୍ତୁ। କୌଣସି API
   key କିମ୍ବା ଟୋକେନ୍ ଆବଶ୍ୟକ ନାହିଁ (ଏହା ଏକ no-auth ପ୍ରଦାନକାରୀ — sidecar ପ୍ରମାଣୀକରଣ ପରିଚାଳନା କରେ)।
2. sidecarର Codex CLIରେ ଯଦି **ଏପର୍ଯ୍ୟନ୍ତ ସାଇନ୍ ଇନ୍ କରାଯାଇନାହିଁ**, ତେବେ ସଂଯୋଗ ସ୍ୱାସ୍ଥ୍ୟ
   ଯାଞ୍ଚ _"ଚାଲୁଛି, କିନ୍ତୁ ସାଇନ୍ ଇନ୍ ହୋଇନାହିଁ"_ ବୋଲି ରିପୋର୍ଟ କରେ (ଏହା ଲାଲ୍ auth ତ୍ରୁଟି ନୁହେଁ)। ବ୍ୟବହାର କରନ୍ତୁ
   **ChatGPT ସହିତ ସାଇନ୍ ଇନ୍ କରନ୍ତୁ**: ଏହା ଆପଣଙ୍କ ବ୍ରାଉଜର୍ରେ ମାନକ Codex device-OAuth ଚଲାଏ
   ଏବଂ ତା’ପରେ **Apply auth** ମାଧ୍ୟମରେ ସେୟାର୍ volumeରେ `~/.codex/auth.json` ଲେଖେ
   (ସେହି ଗୋଟିଏ login, `codex` ଏବଂ `codex-app-server` ଉଭୟ
   ପ୍ରଦାନକାରୀ ପାଇଁ କାର୍ଯ୍ୟ କରେ)।
3. ସାଇନ୍ ଇନ୍ ହୋଇଗଲା ପରେ, ସ୍ୱାସ୍ଥ୍ୟ ଯାଞ୍ଚ ସବୁଜ ହୋଇଯାଏ (ଏହା `/readyz` **ଏବଂ**
   `account/read` ଉଭୟକୁ ଯାଞ୍ଚ କରେ — ଅର୍ଥାତ୍ ଚାଲୁ _ଏବଂ_ ପ୍ରମାଣୀକୃତ) ଏବଂ କାମ ଆରମ୍ଭ କରେ।

ଡ୍ୟାସ୍ବୋର୍ଡ କେବେ ମଧ୍ୟ ଏକ ସୁସ୍ଥ ବିଦ୍ୟମାନ `~/.codex/auth.json`କୁ ଓଭର୍ରାଇଟ୍ କରେ ନାହିଁ — ଫାଇଲ୍ଟି
ଅନୁପସ୍ଥିତ ଥିଲେ କିମ୍ବା ତାହାର ଟୋକେନ୍ ପୁରୁଣା ହୋଇଥିଲେ ମାତ୍ର ଏହା ଲେଖେ (ସବୁବେଳେ ଏକ backup ନିଆଯାଏ)।

## 4. ନିୟୋଜନ ପରିସ୍ଥିତିଗୁଡ଼ିକ

- **ପୂର୍ବରୁ ପ୍ରମାଣୀକୃତ Codex CLI ଥିବା ଅପରେଟର୍** — ଆପଣଙ୍କ ହୋଷ୍ଟର
  `~/.codex`କୁ sidecar (`codex-appserver-home`) ମଧ୍ୟରେ ମାଉଣ୍ଟ୍ କରନ୍ତୁ ଏବଂ ସାଇନ୍-ଇନ୍ ପଦକ୍ଷେପଟି ଛାଡ଼ିଦିଅନ୍ତୁ।
- **ସାର୍ବଜନୀନ ବ୍ୟବହାରକାରୀ, ସ୍ଥାନୀୟ ଭାବେ codex ଇନ୍ଷ୍ଟଲ୍ ହୋଇନାହିଁ** — ଏହା ଅପ୍ରାସଙ୍ଗିକ: sidecarରେ
  CLI ଅଛି। ବ୍ୟବହାରକାରୀ କେବଳ ଡ୍ୟାସ୍ବୋର୍ଡ ମାଧ୍ୟମରେ ପ୍ରମାଣୀକରଣ କରନ୍ତି।
- **Bare-metal OmniRoute (sidecar ନାହିଁ, ହୋଷ୍ଟରେ codex)** — ଆପଣଙ୍କ ନିଜସ୍ୱ
  `codex app-server` ଆଡ଼କୁ `OMNIROUTE_CODEX_APPSERVER_WS`କୁ ନିର୍ଦ୍ଦେଶ କରନ୍ତୁ ଏବଂ
  ହୋଷ୍ଟର codexରେ ସାଇନ୍ ଇନ୍ ହୋଇଥିବା ସୁନିଶ୍ଚିତ କରନ୍ତୁ; binary ଅନୁପସ୍ଥିତ ଥିଲେ
  "codex ଇନ୍ଷ୍ଟଲ୍ ହୋଇନାହିଁ" ସୂଚନା ଦେଖାଯାଏ।

## 5. ଆବାସିକ / UDP egress (ଅପରେଟର୍ ପାଇଁ ଅତିରିକ୍ତ, ସହିତ ପଠାଯାଏ ନାହିଁ)

ଉପରୋକ୍ତ ସାଧାରଣ sidecar, containerର ସାଧାରଣ ନେଟୱର୍କ ମାଧ୍ୟମରେ egress କରେ। ଯେଉଁ
