OmniRouteକୁ OpenAI-ସୁସଙ୍ଗତ ବ୍ୟାକଏଣ୍ଡ ଭାବରେ ନିର୍ଦ୍ଦେଶ କରି Codex CLI ବ୍ୟବହାର କରିବା ପାଇଁ ସମ୍ପୂର୍ଣ୍ଣ ମାର୍ଗଦର୍ଶିକା।

---

> **TOML ହିଁ ଏକମାତ୍ର କାର୍ଯ୍ୟକ୍ଷମ ଫର୍ମାଟ୍।** ଆଧୁନିକ Codex କେବଳ `~/.codex/config.toml`
> ପଢ଼େ (codex-cli 0.147.0 ସହିତ ଯାଞ୍ଚିତ: `codex --help`ରେ
> `-c/--config` ଓଭରରାଇଡ୍ଗୁଡ଼ିକ "`~/.codex/config.toml`ରୁ ଲୋଡ୍ ହୋଇଛି" ବୋଲି ଉଲ୍ଲେଖ ଅଛି)। ପୁରୁଣା
> `~/.codex/config.yaml` ଲେଗେସି npm CLIର ଥିଲା ଏବଂ ଏହାକୁ କୌଣସି ସୂଚନା ବିନା ଅଣଦେଖା କରାଯାଏ।
> ଡ୍ୟାସ୍ବୋର୍ଡ ଜେନେରେଟର୍ (`/api/cli-tools/apply`, ଟୁଲ୍ `codex`) ଏକ
> ସାବଧାନୀପୂର୍ଣ୍ଣ ମର୍ଜ୍ ସହିତ TOML ଲେଖେ — ବିଦ୍ୟମାନ କି ଏବଂ ଅନ୍ୟ ପ୍ରଦାତା ବ୍ଲକ୍ଗୁଡ଼ିକୁ ସଂରକ୍ଷିତ ରଖାଯାଏ,
> API କି `OMNIROUTE_API_KEY`ରେ ରହେ (ଫାଇଲ୍ରେ କେବେ ନୁହେଁ), ଏବଂ ଅବଶିଷ୍ଟ ଲେଗେସି
> `config.yaml`କୁ ସ୍ପର୍ଶ ନକରି ଏକ ମାଇଗ୍ରେସନ୍ ଟିପ୍ପଣୀ ଭାବରେ ରିପୋର୍ଟ କରାଯାଏ।

## ସିଧାସଳଖ ପେଷ୍ଟ କରିବାକୁ ପ୍ରସ୍ତୁତ config.toml

`<YOUR_HOST>` ଏବଂ `<YOUR_KEY>`କୁ ଆପଣଙ୍କ ମୂଲ୍ୟଗୁଡ଼ିକ ସହିତ ବଦଳାନ୍ତୁ:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # ପ୍ରତ୍ୟେକ ଟୁଲ୍ କଲ୍ ପାଇଁ ଇତିହାସ ସଂରକ୍ଷଣ ସୀମା

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc କିମ୍ବା ~/.zshrc — ପ୍ରକୃତ କି ମୂଲ୍ୟ, config.tomlରେ କେବେ ନୁହେଁ
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: ChatGPT ଆପ୍ ଭିତରେ ସମ୍ମିଳିତ Codex

ଯଦି ଆପଣ ChatGPT ଡେସ୍କଟପ୍ ଆପ୍ ମାଧ୍ୟମରେ Codex ଇନ୍ଷ୍ଟଲ୍ କରିଛନ୍ତି, ତେବେ `codex` ବାଇନେରି
କେବଳ ଆପ୍ ବଣ୍ଡଲ୍ ଭିତରେ ଥାଇପାରେ ଏବଂ ଏପର୍ଯ୍ୟନ୍ତ ଆପଣଙ୍କ ଶେଲ୍ `PATH`ରେ ନଥାଇପାରେ। ରିସୋର୍ସ
ଡିରେକ୍ଟୋରିକୁ ଆପଣଙ୍କ ଶେଲ୍ ଷ୍ଟାର୍ଟଅପ୍ ଫାଇଲ୍ରେ ଯୋଡ଼ନ୍ତୁ:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

ଏକ ନୂଆ ଶେଲ୍ ଖୋଲନ୍ତୁ, ତା’ପରେ ଯାଞ୍ଚ କରନ୍ତୁ:

```bash
command -v codex
codex --version
```

### ସ୍ଥାନୀୟ ଅପ୍ରମାଣୀକୃତ OmniRoute: ପ୍ଲେସହୋଲ୍ଡର୍ କି ଯଥେଷ୍ଟ

ପ୍ରଥମ ଅନୁରୋଧ CLIରୁ ବାହାରିବାର **ପୂର୍ବରୁ**, `env_key` ଦ୍ୱାରା ନାମିତ ପରିବେଶ
ଭେରିଏବଲ୍ଟି ଅଛି କି ନାହିଁ Codex ଯାଞ୍ଚ କରେ। ଯଦି ଆପଣଙ୍କ **ସ୍ଥାନୀୟ** OmniRoute
ଇନ୍ଷ୍ଟାନ୍ସ ପାଇଁ ପ୍ରମାଣୀକରଣ ଆବଶ୍ୟକ ନୁହେଁ, ଯେକୌଣସି ଖାଲି ନଥିବା ପ୍ଲେସହୋଲ୍ଡର୍ କାମ କରିବ:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

ଆପଣଙ୍କ OmniRoute ସର୍ଭର୍ ସୁରକ୍ଷିତ କିମ୍ବା ରିମୋଟ୍ ହୋଇଥିଲେ, ଏହା ବଦଳରେ ଏକ ପ୍ରକୃତ କି ବ୍ୟବହାର କରନ୍ତୁ।

> **ସାଧାରଣ ହୋଷ୍ଟ ବିକଳ୍ପଗୁଡ଼ିକ**
>
> | ପ୍ରବେଶ          | URL                           |
> | --------------- | ----------------------------- |
> | ସ୍ଥାନୀୟ ନେଟୱର୍କ | `http://192.168.0.1:20128/v1` |
> | Tailscale       | `http://100.x.x.x:20128/v1`   |
> | ଲୁପ୍ବ୍ୟାକ୍      | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — ଏହା ସମସ୍ତ ମଡେଲ୍ ପାଇଁ କାହିଁକି କାମ କରେ

Codex CLI ଫେବୃଆରୀ 2026ରେ `wire_api = "chat"` (Chat Completions)କୁ ଅପ୍ରଚଳିତ କରିଥିଲା ଏବଂ ବର୍ତ୍ତମାନ **`wire_api = "responses"` ଆବଶ୍ୟକ କରେ** (OpenAI Responses API)। `wire_api = "chat"` ସେଟ୍ କଲେ v0.138 ପରଠାରୁ ଷ୍ଟାର୍ଟଅପ୍ ସମୟରେ ତୁରନ୍ତ କ୍ରାଶ୍ ହୁଏ।

GLM ଏବଂ Kimi ସମେତ ଅନେକ ପ୍ରଦାତା ଏପର୍ଯ୍ୟନ୍ତ କେବଳ Chat Completions ଏଣ୍ଡପଏଣ୍ଟ ପ୍ରଦାନ କରନ୍ତି। DeepSeek V4 ବର୍ତ୍ତମାନ ଏକ Anthropic-ସୁସଙ୍ଗତ ଏଣ୍ଡପଏଣ୍ଟ ସହିତ ଏକ ନେଟିଭ୍ Responses API ମଧ୍ୟ ପ୍ରଦାନ କରେ; OmniRoute ଡିଫଲ୍ଟ ଭାବରେ Responses ବ୍ୟବହାର କରେ ଏବଂ ପ୍ରତ୍ୟେକ DeepSeek ସଂଯୋଗକୁ Anthropic ସୁସଙ୍ଗତତା ଚୟନ କରିବାକୁ ଦିଏ।

**OmniRoute ଏହାକୁ ସ୍ୱଚ୍ଛ ଭାବରେ ସମାଧାନ କରେ:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute ପ୍ରଦାତାଙ୍କ ନେଟିଭ୍ ପ୍ରୋଟୋକଲ୍ ଚୟନ କରେ ଏବଂ ଆବଶ୍ୟକ ହେଲେ ଅନୁବାଦ କରେ
    → POST /responses (DeepSeek V4) କିମ୍ବା /chat/completions (Mistral / GLM / Kimi / ଅନ୍ୟମାନେ)
```

OmniRoute ବ୍ୟବହାର କରିବା ସମୟରେ ଆପଣଙ୍କୁ କେବେ ମଧ୍ୟ ଅଲଗା ଅନୁବାଦ ପ୍ରକ୍ସି ଆବଶ୍ୟକ ହୁଏ ନାହିଁ। **ସମସ୍ତ ମଡେଲ୍ `wire_api = "responses"` ବ୍ୟବହାର କରନ୍ତି** — ବାକି ସବୁ OmniRoute ପରିଚାଳନା କରେ।

> **`wire_api` ହେଉଛି ଡିଫଲ୍ଟ** — ଏହି ଫିଲ୍ଡର ଡିଫଲ୍ଟ ମୂଲ୍ୟ `"responses"` ଏବଂ ଏହାକୁ `config.toml`ରୁ ସମ୍ପୂର୍ଣ୍ଣ ଭାବରେ ବାଦ ଦିଆଯାଇପାରେ। ଉଦ୍ଦେଶ୍ୟକୁ ଡକ୍ୟୁମେଣ୍ଟ କରୁଥିଲେ ମାତ୍ର ଏହାକୁ ସ୍ପଷ୍ଟ ଭାବରେ ସେଟ୍ କରନ୍ତୁ।

## ପ୍ରସଙ୍ଗ ୱିଣ୍ଡୋ ଏବଂ ସଙ୍କୋଚନ

### ଟୋକନ୍ ବିନ୍ୟାସ ଫିଲ୍ଡଗୁଡ଼ିକ

| ଫିଲ୍ଡ                            | ବର୍ଣ୍ଣନା                                                                                                                                                                          |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model_context_window`           | ସକ୍ରିୟ ମଡେଲ୍ ପାଇଁ ମୋଟ ଟୋକନ୍ ବଜେଟ୍। ଏହାକୁ ମଡେଲ୍ର ପ୍ରଚାରିତ ସୀମାରେ ସେଟ୍ କରନ୍ତୁ।                                                                                                      |

| `tool_output_token_limit`        | ପ୍ରତ୍ୟେକ ଟୁଲ୍ କଲ୍ ଆଉଟପୁଟ୍ ପାଇଁ ଇତିହାସରେ ସଞ୍ଚିତ ଟୋକନ୍ର ସୀମା। ଏହା ଗୋଟିଏ ବଡ଼ ଟୁଲ୍ ପ୍ରତିକ୍ରିୟାକୁ ୱିଣ୍ଡୋ ପୂରଣ କରିବାରୁ ରୋକେ। **ଏହା ସର୍ବାଧିକ ଆଉଟପୁଟ୍ ନୁହେଁ** — ଏହା ଏକ ଇତିହାସ ସଞ୍ଚୟ ସୀମା। |

## ତର୍କ ପ୍ରୟାସ

ପ୍ରତିକ୍ରିୟା ଦେବା ପୂର୍ବରୁ ମଡେଲ୍ କେତେ ପରିମାଣରେ "ଚିନ୍ତା" କରିବ, ତାହା ନିୟନ୍ତ୍ରଣ କରେ।

| ମୂଲ୍ୟ    | ଏଥିପାଇଁ ବ୍ୟବହାର କରନ୍ତୁ                    |
| -------- | ----------------------------------------- |
| `none`   | କୌଣସି ତର୍କ ନାହିଁ — ସିଧାସଳଖ ପ୍ରତିକ୍ରିୟା    |
| `low`    | ଅତି ସରଳ କାର୍ଯ୍ୟ (ନାମ ପରିବର୍ତ୍ତନ, ଫର୍ମାଟ୍) |
| `medium` | ଉଲ୍ଲେଖ ନଥିଲେ **ସର୍ଭର ଡିଫଲ୍ଟ**             |
| `high`   | ମଧ୍ୟବର୍ତ୍ତୀ କାର୍ଯ୍ୟ (ରିଫ୍ୟାକ୍ଟରିଂ, ଡିବଗ୍) |
| `xhigh`  | ଆର୍କିଟେକ୍ଚର୍, ଗଭୀର ବିଶ୍ଳେଷଣ, ଜଟିଳ ସମସ୍ୟା  |

```bash
# ପ୍ରତ୍ୟେକ ଆହ୍ୱାନ ପାଇଁ ଓଭରରାଇଡ୍
codex -c model_reasoning_effort=low "rename variable x to count"
codex -c model_reasoning_effort=xhigh "design the auth module"
```

ଏହା ସହିତ ଏକ ତର୍କ **ସାରାଂଶ** ମଧ୍ୟ ସେଟ୍ କରନ୍ତୁ, ଯାହାଦ୍ୱାରା Desktop ଚିନ୍ତନ ପାଠ୍ୟକୁ ରେଣ୍ଡର୍ କରିପାରିବ (କେବଳ ଏନ୍କ୍ରିପ୍ଟ୍ ହୋଇଥିବା ବ୍ଲବ୍ ନୁହେଁ):

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # କିମ୍ବା ସମର୍ଥିତ ହେଲେ ultra
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### OmniRoute ଚିନ୍ତନ ବଜେଟ୍ (ସର୍ଭର ସେଟିଂ)

OmniRoute ହୋଷ୍ଟରେ, Codex ପ୍ରୟାସ/ସାରାଂଶକୁ ଅପ୍ଷ୍ଟ୍ରିମ୍ରେ ପହଞ୍ଚାଇବା ପାଇଁ **Settings → AI → Thinking Budget** ନିଶ୍ଚିତ ଭାବରେ **`passthrough`** ହେବା ଆବଶ୍ୟକ। **`auto` strips** ମୋଡ୍ ସମସ୍ତ କ୍ଲାଏଣ୍ଟ `reasoning` / `reasoning_effort` ଫିଲ୍ଡକୁ ବାଦ ଦିଏ ଏବଂ Codex ସଠିକ୍ ଭାବରେ କନଫିଗର୍ ହୋଇଥିଲେ ମଧ୍ୟ ଚିନ୍ତନ ପ୍ୟାନେଲ୍ଗୁଡ଼ିକୁ ଖାଲି କରିଦେବ।

ସମ୍ପୂର୍ଣ୍ଣ ମାର୍ଗଦର୍ଶିକା: [THINKING_BUDGET.md](./THINKING_BUDGET.md)।

କମ୍ପ୍ରେସନ୍ ଏବଂ ପ୍ରମ୍ପ୍ଟ କ୍ୟାଶ୍ ସ୍ୱାଧୀନ ଏବଂ `passthrough` ଅଧୀନରେ କାର୍ଯ୍ୟ କରିବା ଜାରି ରଖନ୍ତି।

## ପ୍ରୋଫାଇଲ୍ — ପ୍ରତ୍ୟେକ ମଡେଲ୍/କାର୍ଯ୍ୟପ୍ରବାହ ପାଇଁ ନାମିତ କନଫିଗରେସନ୍

ପ୍ରୋଫାଇଲ୍ଗୁଡ଼ିକ ଆପଣଙ୍କୁ ଗୋଟିଏ ଫ୍ଲାଗ୍ରେ ମଡେଲ୍ + କନ୍ଟେକ୍ସ୍ଟ ୱିଣ୍ଡୋ ବଦଳାଇବାକୁ ଦିଅନ୍ତି। ପ୍ରତ୍ୟେକ ପ୍ରୋଫାଇଲ୍ ହେଉଛି ଏକ ଫ୍ଲାଟ୍
`~/.codex/<name>.config.toml`, ଯାହା ମୂଳ `config.toml` ଉପରେ ଓଭର୍ଲେ ହୁଏ।

> **ନାମକରଣ ନିୟମ (Codex CLI v0.137+):** ଫାଇଲ୍ଟି ନିଶ୍ଚିତ ଭାବରେ `~/.codex/<name>.config.toml` ହେବା ଆବଶ୍ୟକ — **କୌଣସି `profile-` ପ୍ରିଫିକ୍ସ ନୁହେଁ**।
> CLI `-p kimi-k27` → `~/.codex/kimi-k27.config.toml` ଭାବରେ ସମାଧାନ କରେ। ଯଦି ଫାଇଲ୍ଟି ମିଳେ ନାହିଁ, ତେବେ ଡିଫଲ୍ଟ ନିରବରେ ପ୍ରୟୋଗ ହୁଏ।

```bash

```

## `omniroute setup-codex` ସହିତ ସ୍ୱୟଂଚାଳିତ ଭାବେ ପ୍ରୋଫାଇଲ୍ ସୃଷ୍ଟି କରିବା

ଯଦି ଆପଣ ଏକ VPSରେ OmniRoute ଚଳାନ୍ତି, ତେବେ ସକ୍ରିୟ ମଡେଲ୍ କ୍ୟାଟାଲଗ୍ରୁ ପ୍ରୋଫାଇଲ୍ ଫାଇଲ୍ଗୁଡ଼ିକ ସ୍ୱୟଂଚାଳିତ ଭାବେ ସୃଷ୍ଟି କରିପାରିବେ:

```bash
# ଏକ VPSରୁ (ପୋର୍ଟ 20128ରେ ସ୍ଥାନୀୟ OmniRoute ବ୍ୟବହାର କରେ)
omniroute setup-codex

# ଯେକୌଣସି ମେସିନ୍ରୁ — ଆପଣଙ୍କ VPSକୁ ଲକ୍ଷ୍ୟ କରନ୍ତୁ
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# ଫାଇଲ୍ ନ ଲେଖି ପୂର୍ବାବଲୋକନ କରନ୍ତୁ
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# କେବଳ GLM ଏବଂ Kimi ପ୍ରୋଫାଇଲ୍ ସୃଷ୍ଟି କରନ୍ତୁ
omniroute setup-codex --only glm,kimi

# ଏକ କଷ୍ଟମ୍ ଡିରେକ୍ଟୋରିରେ ଲେଖନ୍ତୁ
omniroute setup-codex --codex-home /path/to/.codex
```

ଏହି କମାଣ୍ଡ୍ `/v1/models` ଆଣେ, ଜଣାଶୁଣା ମଡେଲ୍ଗୁଡ଼ିକ ପାଇଁ ସୁସମନ୍ୱିତ ପ୍ରୋଫାଇଲ୍ ବ୍ୟବହାର କରେ, ଅନ୍ୟ ସୁସଙ୍ଗତ ଟେକ୍ସଟ୍ ମଡେଲ୍ଗୁଡ଼ିକ ପାଇଁ କ୍ୟାଟାଲଗ୍ ମେଟାଡାଟାକୁ ବିକଳ୍ପ ଭାବେ ବ୍ୟବହାର କରେ, ଏବଂ ପ୍ରତ୍ୟେକ ପାଇଁ `~/.codex/<name>.config.toml` ଲେଖେ। ଏହା idempotent — ପୁନର୍ବାର ଚଳାଇବା ସୁରକ୍ଷିତ।

ସଫଳ provider model discovery/import ପରେ ସକ୍ରିୟ କ୍ୟାଟାଲଗ୍ ପରିବର୍ତ୍ତିତ ହେଲେ, OmniRoute ଏହି ସମାନ ପ୍ରୋଫାଇଲ୍ ଫାଇଲ୍ଗୁଡ଼ିକୁ **ସ୍ୱୟଂଚାଳିତ ଭାବେ ସିଙ୍କ୍** ମଧ୍ୟ କରିପାରେ। ଏହା **opt-in ଏବଂ ଡିଫଲ୍ଟ ଭାବେ ବନ୍ଦ**: **CLI Code dashboard**ରୁ ଏହାକୁ ଟୋଗଲ୍ କରନ୍ତୁ ("CLI profile auto-sync" → Codex), କିମ୍ବା `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` ସେଟ୍ କରନ୍ତୁ (ଏହା `CLI_ALLOW_CONFIG_WRITES`କୁ ମଧ୍ୟ ସମ୍ମାନ କରେ, ଯାହା ଡିଫଲ୍ଟ ଭାବେ ସକ୍ରିୟ)। ସକ୍ରିୟ ଥିବାବେଳେ, ଏହା କେବଳ ପୃଥକ `~/.codex/*.config.toml` ପ୍ରୋଫାଇଲ୍ ଫାଇଲ୍ଗୁଡ଼ିକ ଲେଖେ; ଏହା କେବେବି ସକ୍ରିୟ/ଡିଫଲ୍ଟ `~/.codex/config.toml`, Codex-lb ସେଟିଂସ୍, ପ୍ରମାଣୀକରଣ, କିମ୍ବା provider ଚୟନକୁ ପରିବର୍ତ୍ତନ କରେ ନାହିଁ।

ଦୁଇଟି OmniRoute ଡିଫଲ୍ଟ ନିରବରେ ବହୁ-ଘଣ୍ଟିଆ Codex CLI ସେସନ୍ଗୁଡ଼ିକୁ ବିଫଳ କରିପାରେ। ଏଥିରୁ କୌଣସିଟି ମଧ୍ୟ Codex CLI ସେଟିଂ ନୁହେଁ — ଉଭୟ OmniRoute ପାର୍ଶ୍ୱରେ ରହିଛି। ଆକାଉଣ୍ଟ ପିନ୍ କରୁଥିବା ଏବଂ ନିଷ୍କ୍ରିୟତା କଟ୍ଅଫ୍ ଅକ୍ଷମ କରୁଥିବା ଅପ୍ଷ୍ଟ୍ରିମ୍ ପ୍ରକ୍ସିଗୁଡ଼ିକରୁ ବିନ୍ୟାସ ସ୍ଥାନାନ୍ତର କରୁଥିବା ବ୍ୟବହାରକାରୀମାନେ ପ୍ରାୟତଃ ଉଭୟ ସମସ୍ୟାର ସମ୍ମୁଖୀନ ହୋଇ ନିଷ୍କର୍ଷ କରନ୍ତି ଯେ OmniRoute “ଏକ ଦୀର୍ଘ ସେସନ୍ ବଜାୟ ରଖିପାରେ ନାହିଁ।”

| ଲକ୍ଷଣ                                                                                            | ସମ୍ଭାବ୍ୟ କାରଣ                                                                     | ନିୟନ୍ତ୍ରଣ                |
| ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- | ------------------------ |

### 1. ସେସନ୍ ଆଫିନିଟି — ଗୋଟିଏ ବାର୍ତ୍ତାଳାପକୁ ଗୋଟିଏ ଆକାଉଣ୍ଟରେ ପିନ୍ କରନ୍ତୁ

**ଡିଫଲ୍ଟ:** `sessionAffinityTtlMs = 0` (ଅକ୍ଷମ)।

**ଏହାକୁ କେଉଁଠାରେ ସେଟ୍ କରିବେ**

- ଡ୍ୟାସ୍ବୋର୍ଡ → **ସେଟିଂସ୍ → ରାଉଟିଂ** → **ସେସନ୍ ଆଫିନିଟି** → **ଆଫିନିଟି TTL (ସେକେଣ୍ଡ)** (`ComboDefaultsTab`)
- କିମ୍ବା **ମିଲିସେକେଣ୍ଡ**ରେ `sessionAffinityTtlMs` ସହିତ ସେଟିଂସ୍ PATCH କରନ୍ତୁ (Zod ପରିସର `0`–`86_400_000`, ଅର୍ଥାତ୍ 24 ଘଣ୍ଟା ପର୍ଯ୍ୟନ୍ତ)

> #7274ରେ କେବଳ Codex ପାଇଁ ଥିବା `codexSessionAffinityTtlMs`ରୁ ଏହାର ନାମ ପରିବର୍ତ୍ତନ କରାଯାଇଛି। ପୁରୁଣା କି’ ଏପର୍ଯ୍ୟନ୍ତ ଏକ କେବଳ-ପଠନୀୟ ଉପନାମ ଭାବେ ଗ୍ରହଣ କରାଯାଏ; ନୂଆ ବିନ୍ୟାସଗୁଡ଼ିକ `sessionAffinityTtlMs` ବ୍ୟବହାର କରିବା ଉଚିତ। TTL `0`ରୁ ଅଧିକ ହେଲେ ଆଫିନିଟି ବର୍ତ୍ତମାନ କେବଳ Codex ନୁହେଁ, **ଯେକୌଣସି** ପ୍ରଦାନକାରୀ ପାଇଁ ପ୍ରଯୁଜ୍ୟ — [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → ସେସନ୍ ଆଫିନିଟି ଦେଖନ୍ତୁ।

**ଏହା 0ରେ ରହିଲେ କ’ଣ ବିଗିଡ଼େ**

ଏକ ବହୁ-ଟର୍ଣ୍ଣ Codex ବାର୍ତ୍ତାଳାପର ପ୍ରତ୍ୟେକ ଟର୍ଣ୍ଣକୁ ସକ୍ରିୟ କମ୍ବୋ କୌଶଳ ଦ୍ୱାରା ସ୍ୱାଧୀନ ଭାବେ ରାଉଟ୍ କରାଯାଏ ଏବଂ ଏହା **ପ୍ରତି ଟର୍ଣ୍ଣରେ ଏକ ଭିନ୍ନ ଆକାଉଣ୍ଟ**ରେ ପହଞ୍ଚିପାରେ। ଏହା ଅପ୍ଷ୍ଟ୍ରିମ୍ ସେସନ୍ / ପ୍ରମ୍ପ୍ଟ-କ୍ୟାଶ୍ ନିରନ୍ତରତାକୁ ଭଙ୍ଗ କରେ। TTL `0`ରୁ ଅଧିକ ଥିବାବେଳେ ମାତ୍ର OmniRoute, Codex ସେସନ୍ ହେଡର୍ଗୁଡ଼ିକ (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) ଏବଂ `prompt_cache_key` / `session_id` ପରି ବଡି ଫିଲ୍ଡଗୁଡ଼ିକୁ ପରାମର୍ଶ କରେ (`src/sse/services/auth.ts`ରେ `extractSessionAffinityKey`)।

**ବହୁ-ଘଣ୍ଟିଆ ଏକକ କାର୍ଯ୍ୟ ପାଇଁ ସୁପାରିଶ**

TTLକୁ **କାର୍ଯ୍ୟର ଆଶାକରାଯାଉଥିବା ବାସ୍ତବ ସମୟ ଅବଧିଠାରୁ ଅଧିକ** ସେଟ୍ କରନ୍ତୁ (UIର ସର୍ବାଧିକ ସୀମା **86400 ସେକେଣ୍ଡ** = 24 ଘଣ୍ଟା):

| ଆଶାକରାଯାଉଥିବା କାର୍ଯ୍ୟ ଅବଧି | ଆଫିନିଟି TTL (UI, ସେକେଣ୍ଡ) | `sessionAffinityTtlMs` |
| -------------------------- | ------------------------- | ---------------------- |
| କିଛି ଘଣ୍ଟା                 | `14400` (4h)              | `14400000`             |
| ରାତିସାରା / ~12h            | `43200` (12h)             | `43200000`             |
| ପୂରା ଦିନ                   | `86400` (24h, ସର୍ବାଧିକ)   | `86400000`             |

ଇଚ୍ଛାଧୀନ ସକ୍ରିୟକରଣ ଉଦ୍ଦେଶ୍ୟମୂଳକ: ଆଫିନିଟି ଅକ୍ଷମ କରିବା ଆକାଉଣ୍ଟଗୁଡ଼ିକ ମଧ୍ୟରେ ଲୋଡ୍-ବାଲାନ୍ସିଂକୁ ପ୍ରାଧାନ୍ୟ ଦିଏ; ଏହାକୁ ସକ୍ଷମ କରିବା ଗୋଟିଏ ଦୀର୍ଘ ଏଜେଣ୍ଟ ସେସନ୍ ପାଇଁ ନିରନ୍ତରତାକୁ ପ୍ରାଧାନ୍ୟ ଦିଏ। ଏହି ଗାଇଡ୍ ଡିଫଲ୍ଟକୁ ପରିବର୍ତ୍ତନ କରେ **ନାହିଁ** — ଦୀର୍ଘ Codex କାର୍ଯ୍ୟ ଚଲାଉଥିବା ଅପରେଟର୍ମାନେ ଏହାକୁ ନିଜେ ସକ୍ରିୟ କରିବା ଆବଶ୍ୟକ।

### 2. ଷ୍ଟ୍ରିମ୍ ଆଇଡଲ୍ ଟାଇମ୍ଆଉଟ୍ — ନିରବ ତର୍କ ଟର୍ଣ୍ଣଗୁଡ଼ିକୁ ବନ୍ଦ କରନ୍ତୁ ନାହିଁ

**ଡିଫଲ୍ଟ:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 ମିନିଟ୍)। ଏହା ସେଟ୍ ହୋଇନଥିଲେ `REQUEST_TIMEOUT_MS`ରୁ ମୂଲ୍ୟ ଗ୍ରହଣ କରେ; ସାଧାରଣ ବେସ୍ଲାଇନ୍ ମଧ୍ୟ 600000। [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → ଟାଇମ୍ଆଉଟ୍ଗୁଡ଼ିକ ଦେଖନ୍ତୁ।

**ଡିଫଲ୍ଟରେ କ’ଣ ବିଗିଡ଼େ**

10 ମିନିଟ୍ରୁ ଅଧିକ ସମୟ ଧରି **କୌଣସି ପ୍ରକୃତ ଅପ୍ଷ୍ଟ୍ରିମ୍ ଚଙ୍କ୍ ବିନା** ନିରବ ରହୁଥିବା ଏକ Codex ରିଜନିଂ / ଟୁଲ୍ ଟର୍ନକୁ SSE ନିଷ୍କ୍ରିୟତା ୱାଚ୍ଡଗ୍ (`open-sse/utils/stream.ts`) ବାଧ୍ୟତାମୂଳକ ଭାବରେ ବନ୍ଦ କରିଦିଏ। କ୍ଲାଏଣ୍ଟ ପ୍ରାୟତଃ କେବଳ ସଂଯୋଗ ବିଚ୍ଛିନ୍ନ ହେବା ଦେଖେ — ଯାହା “କୌଣସି ସୂଚନା ବିନା ସ୍ୱୟଂଚାଳିତ ଭାବରେ ବନ୍ଦ ହୋଇଗଲା” ସହ ମେଳ ଖାଏ।

ଗୁରୁତ୍ୱପୂର୍ଣ୍ଣ ବିବରଣୀ: OmniRouteର ସିନ୍ଥେଟିକ୍ SSE **ହାର୍ଟବିଟ୍ ନିଷ୍କ୍ରିୟତା ଘଡ଼ିକୁ ରିସେଟ୍ କରେ ନାହିଁ**। କେବଳ ଏକ ପ୍ରକୃତ ଅପ୍ଷ୍ଟ୍ରିମ୍ ବଡି ଚଙ୍କ୍ `lastChunkTime`କୁ ଅପଡେଟ୍ କରେ। ଏବେ ମଧ୍ୟ “ଚିନ୍ତା କରୁଥିବା” ଏକ ନିରବ ମଡେଲ୍ ୱାଚ୍ଡଗ୍ର ଦୃଷ୍ଟିକୋଣରୁ ଏକ ଅଟକିଥିବା ଅପ୍ଷ୍ଟ୍ରିମ୍ ସହ ସମାନ ଦେଖାଯାଏ।

ସମ୍ପର୍କିତ Undici ବଡି ନିଷ୍କ୍ରିୟତା: `FETCH_BODY_TIMEOUT_MS` (ଏହା ମଧ୍ୟ ସେହି 10-ମିନିଟ୍ର ମୂଳ ଡିଫଲ୍ଟ ମାନ ବ୍ୟବହାର କରେ; `0` ଏହାକୁ ଅକ୍ଷମ କରେ)। ଷ୍ଟ୍ରିମିଂ ପାଇଁ, `FETCH_TIMEOUT_MS` କେବଳ ସଂଯୋଗ ସେଟଅପ୍ / ପ୍ରଥମ ହେଡର୍ଗୁଡ଼ିକୁ କଭର୍ କରେ — ଷ୍ଟ୍ରିମ୍ ସକ୍ରିୟ ହୋଇଗଲା ପରେ, ଷ୍ଟଲ୍ଗୁଡ଼ିକ `STREAM_IDLE_TIMEOUT_MS` ଏବଂ `FETCH_BODY_TIMEOUT_MS` ଦ୍ୱାରା ନିୟନ୍ତ୍ରିତ ହୁଏ।

**ଏକାଧିକ ଘଣ୍ଟାର ଗୋଟିଏ କାର୍ଯ୍ୟ ପାଇଁ ସୁପାରିସ୍**

OmniRoute ପ୍ରୋସେସ୍ ପରିବେଶରେ (`.env` / compose / systemd):

```bash
# ଦୀର୍ଘ ରିଜନିଂ ଟର୍ନ ପାଇଁ ଷ୍ଟ୍ରିମ୍ ନିଷ୍କ୍ରିୟତା + ବଡି ନିଷ୍କ୍ରିୟତା କଟଅଫ୍ଗୁଡ଼ିକୁ ଅକ୍ଷମ କରନ୍ତୁ
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

ଅଥବା ଆପଣ ଆଶା କରୁଥିବା ସର୍ବାଧିକ ନିରବ ବ୍ୟବଧାନଠାରୁ ଅଧିକ ମାନକୁ ସେଗୁଡ଼ିକୁ ବଢ଼ାନ୍ତୁ (ମାନଗୁଡ଼ିକ ମିଲିସେକେଣ୍ଡରେ ଅଛି):

```bash
# ଉଦାହରଣ: ଅପ୍ଷ୍ଟ୍ରିମ୍ ଚଙ୍କ୍ଗୁଡ଼ିକ ମଧ୍ୟରେ ସର୍ବାଧିକ 2 ଘଣ୍ଟାର ନିରବତାକୁ ଅନୁମତି ଦିଅନ୍ତୁ
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

ଏହି ପରିବେଶ ଭେରିଏବଲ୍ଗୁଡ଼ିକ ପରିବର୍ତ୍ତନ କରିବା ପରେ OmniRouteକୁ ପୁନଃଚାଳନ କରନ୍ତୁ।

### ନିର୍ଦ୍ଦିଷ୍ଟ ପଦ୍ଧତି — ଏକାଧିକ ଘଣ୍ଟାର Codex କାର୍ଯ୍ୟ

1. **ଆକାଉଣ୍ଟକୁ ପିନ୍ କରନ୍ତୁ:** Dashboard → Settings → Routing → Session affinity → Affinity TTL = `43200` (12h) କିମ୍ବା `86400` (ସର୍ବାଧିକ 24h)।
2. OmniRouteର ପରିବେଶରେ **ନିଷ୍କ୍ରିୟତା କଟଅଫ୍ଗୁଡ଼ିକୁ ବଢ଼ାନ୍ତୁ / ଅକ୍ଷମ କରନ୍ତୁ**:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. ସାଧାରଣ Codex `config.toml` (`wire_api = "responses"`, ସଠିକ୍ `base_url`, `OMNIROUTE_API_KEY`) ବ୍ୟବହାର କରିଚାଲନ୍ତୁ — ଏହି ଦୁଇଟି ଆଚରଣ ପାଇଁ Codex ପକ୍ଷରେ କୌଣସି ଆଫିନିଟି/ନିଷ୍କ୍ରିୟତା ନିୟନ୍ତ୍ରଣ ନାହିଁ।
4. OmniRouteକୁ ପୁନଃଚାଳନ କରନ୍ତୁ, ତା’ପରେ ଦୀର୍ଘ Codex କାର୍ଯ୍ୟ ଆରମ୍ଭ କରନ୍ତୁ।

### ଡିଫଲ୍ଟ ସମ୍ବନ୍ଧୀୟ ନିଷ୍ପତ୍ତି (#7287)

| ନିୟନ୍ତ୍ରଣ                | ପ୍ରକାଶିତ ଡିଫଲ୍ଟ      | ଏହି ଗାଇଡ୍ରେ ପରିବର୍ତ୍ତନ କରିବେ?                                                                                         |
| ------------------------ | -------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (ବନ୍ଦ)           | **ନା** — ଅପ୍ଟ-ଇନ୍ ହୋଇ ରହିବ (ଲୋଡ୍-ବାଲାନ୍ସିଂ ବନାମ ନିରନ୍ତରତା; Discussion #5718 ଦେଖନ୍ତୁ)                                  |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 ମିନିଟ୍) | **ନା** — ସାଧାରଣ ଟ୍ରାଫିକ୍ ପାଇଁ 10 ମିନିଟ୍ ହୋଇ ରହିବ; ଦୀର୍ଘ Codex କାର୍ଯ୍ୟର ଅପରେଟର୍ମାନେ ଏହାକୁ ବଢ଼ାନ୍ତି କିମ୍ବା ଅକ୍ଷମ କରନ୍ତି |

ଯେକୌଣସି ଡିଫଲ୍ଟକୁ ବିଶ୍ୱସ୍ତରରେ ବଦଳାଇଲେ, କେବଳ Codex ନୁହେଁ, ଏକ ଇନ୍ଷ୍ଟାନ୍ସର ପ୍ରତ୍ୟେକ କ୍ଲାଏଣ୍ଟ ପାଇଁ ଆଚରଣ ପରିବର୍ତ୍ତିତ ହେବ। ନିୟନ୍ତ୍ରଣଗୁଡ଼ିକୁ ଡକ୍ୟୁମେଣ୍ଟ କରନ୍ତୁ; ଏକ ସ୍ପଷ୍ଟ ଅପରେଟର୍ ନିଷ୍ପତ୍ତି ଅନ୍ୟଥା ନ କହିବା ପର୍ଯ୍ୟନ୍ତ ଡିଫଲ୍ଟଗୁଡ଼ିକୁ ଅପରିବର୍ତ୍ତିତ ରଖନ୍ତୁ।

### ନିଷ୍କ୍ରିୟତାଜନିତ ବିଚ୍ଛେଦ ନିଦାନ କରିବା

ନିଷ୍କ୍ରିୟତା ୱାଚ୍ଡଗ୍ ସକ୍ରିୟ ହେଲେ, OmniRoute ନିମ୍ନ ଆକୃତିର ଏକ ଲାଇନ୍ ଲଗ୍ କରେ:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

`Idle timeout: no data from` ପାଇଁ grep କରନ୍ତୁ (କିମ୍ବା କୋଡ୍ `stream_idle_timeout` / ଏରର୍ ନାମ `StreamIdleTimeoutError`)। ପ୍ରୋଭାଇଡର୍ ସେଗମେଣ୍ଟଟି ହେଉଛି ସେହି ଅନୁରୋଧ ପାଇଁ OmniRoute ଯାହା ବ୍ୟବହାର କରିଥିଲା (`codex`, ଅନ୍ୟ ଏକ ପ୍ରୋଭାଇଡର୍ ଆଇଡି, କିମ୍ବା ଅଜଣା ହେଲେ `provider`) — ଏହା ସବୁବେଳେ ଆକ୍ଷରିକ ଷ୍ଟ୍ରିଙ୍ଗ୍ `codex` ନୁହେଁ।

## ସମସ୍ୟା ସମାଧାନ

**`Error: wire_api = "chat" is no longer supported`**
ଆପଣଙ୍କ କନଫିଗ୍ରୁ `wire_api = "chat"` ହଟାନ୍ତୁ। `wire_api = "responses"` ସେଟ୍ କରନ୍ତୁ କିମ୍ବା ଫିଲ୍ଡଟି ବାଦ ଦିଅନ୍ତୁ (v0.138 ଠାରୁ ଡିଫଲ୍ଟ ହେଉଛି `"responses"`)।

**`Error: model not found`**
ସଠିକ୍ ପ୍ରିଫିକ୍ସ ସହିତ ମଡେଲ୍ଟି OmniRouteରେ ଅଛି କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ। `omniroute models list` ବ୍ୟବହାର କରନ୍ତୁ କିମ୍ବା `/dashboard/providers/<provider>` ଖୋଲନ୍ତୁ।

**`Authentication error`**
`OMNIROUTE_API_KEY` ଏକ୍ସପୋର୍ଟ ହୋଇଛି କି ନାହିଁ ନିଶ୍ଚିତ କରନ୍ତୁ: `echo $OMNIROUTE_API_KEY`।

**`ERROR: Missing environment variable: OMNIROUTE_API_KEY`**
ପ୍ରଥମ ଅନୁରୋଧ କରିବା ପୂର୍ବରୁ env varଟି ଅଛି କି ନାହିଁ Codex ଯାଞ୍ଚ କରେ। ସୁରକ୍ଷିତ ସର୍ଭରଗୁଡ଼ିକ ପାଇଁ ଏକ ପ୍ରକୃତ key ଏକ୍ସପୋର୍ଟ କରନ୍ତୁ, କିମ୍ବା ଆପଣଙ୍କ **ସ୍ଥାନୀୟ** OmniRoute ଇନ୍ଷ୍ଟାନ୍ସ ପାଇଁ auth ଆବଶ୍ୟକ ନଥିଲେ `OMNIROUTE_API_KEY=local` ପରି ଏକ ଅଣ-ଖାଲି ପ୍ଲେସହୋଲ୍ଡର୍ ବ୍ୟବହାର କରନ୍ତୁ। ଯଦି ଆପଣ ଏହାକୁ `~/.bashrc` କିମ୍ବା `~/.zshrc`ରେ ଯୋଡ଼ିଛନ୍ତି, ତେବେ shellକୁ ପୁନଃଚାଳନ କରନ୍ତୁ।

**`Connection refused`**
OmniRoute ଚାଲୁଛି ଏବଂ ଆପଣଙ୍କ ନେଟୱର୍କ ପାଇଁ `base_url` host/port ସଠିକ୍ ଅଛି କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ (ସ୍ଥାନୀୟ ବନାମ Tailscale ବନାମ VPS)।

**କଣ୍ଟେକ୍ସ୍ଟ ସୀମା ନିକଟରେ ସେସନ୍ କ୍ରାଶ୍ ହେଉଛି**
`model_context_window` ଏବଂ `model_auto_compact_token_limit` ସ୍ପଷ୍ଟ ଭାବରେ ସେଟ୍ କରନ୍ତୁ। ଉପରେ ଥିବା କଣ୍ଟେକ୍ସ୍ଟ ୱିଣ୍ଡୋ ସାରଣୀ ଦେଖନ୍ତୁ।

**କମ୍ପାକ୍ସନ୍ ଅତ୍ୟଧିକ ବିଳମ୍ବରେ ସକ୍ରିୟ ହେଉଛି**
`model_auto_compact_token_limit`କୁ ୱିଣ୍ଡୋର 80–85% ପର୍ଯ୍ୟନ୍ତ କମାନ୍ତୁ। କେବେବି 90%ରୁ ଅଧିକ ସେଟ୍ କରନ୍ତୁ ନାହିଁ।

**ପ୍ରୋଫାଇଲ୍ ଲୋଡ୍ ହେଉନାହିଁ (`-p <name>`କୁ ନିରବରେ ଅଣଦେଖା କରାଯାଉଛି)**
ଫାଇଲ୍ଟି `~/.codex/<name>.config.toml`ରେ ଅଛି କି ନାହିଁ ନିଶ୍ଚିତ କରନ୍ତୁ (`profile-` ପ୍ରିଫିକ୍ସ ବିନା)। `ls ~/.codex/*.config.toml` ଚଲାନ୍ତୁ।

**ଦୀର୍ଘ Codex କାର୍ଯ୍ୟ ଚାଲିଥିବା ବେଳେ ମଝିରେ ବିଚ୍ଛିନ୍ନ ହେଉଛି / ଟର୍ନଗୁଡ଼ିକ ମଧ୍ୟରେ ଆକାଉଣ୍ଟ ବଦଳୁଛି**
[ଦୀର୍ଘ ସମୟ ଚାଲୁଥିବା କାର୍ଯ୍ୟଗୁଡ଼ିକ](#long-running-tasks) ଦେଖନ୍ତୁ। ସେସନ୍ ଆଫିନିଟି ସକ୍ରିୟ କରନ୍ତୁ (TTL କାର୍ଯ୍ୟର ଅବଧିଠାରୁ ଅଧିକ ରଖନ୍ତୁ) ଏବଂ `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS` ବଢ଼ାନ୍ତୁ କିମ୍ବା ଅକ୍ଷମ କରନ୍ତୁ। `Idle timeout: no data from` ପାଇଁ OmniRoute ଲଗ୍ଗୁଡ଼ିକରେ grep କରନ୍ତୁ।
