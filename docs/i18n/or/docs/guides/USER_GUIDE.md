## 🎯 ବ୍ୟବହାର ପରିସ୍ଥିତି

### ପରିସ୍ଥିତି 1: "ମୋ ପାଖରେ Claude Pro ସବସ୍କ୍ରିପ୍ସନ୍ ଅଛି"

**ସମସ୍ୟା:** କୋଟା ବ୍ୟବହାର ନ ହୋଇ ସମାପ୍ତ ହୁଏ, ଅଧିକ କୋଡିଂ ସମୟରେ ରେଟ୍ ଲିମିଟ୍ ଲାଗେ

```
କମ୍ବୋ: "maximize-claude"
  1. cc/claude-opus-4-7        (ସବସ୍କ୍ରିପ୍ସନ୍‌କୁ ସମ୍ପୂର୍ଣ୍ଣ ଭାବେ ବ୍ୟବହାର କରନ୍ତୁ)
  2. glm/glm-4.7               (କୋଟା ସରିଗଲେ ଶସ୍ତା ବ୍ୟାକଅପ୍)
  3. if/qwen3.8-max-preview       (ମାଗଣା ଜରୁରୀକାଳୀନ ଫଲ୍‌ବ୍ୟାକ୍)

ମାସିକ ଖର୍ଚ୍ଚ: $20 (ସବସ୍କ୍ରିପ୍ସନ୍) + ~$5 (ବ୍ୟାକଅପ୍) = ମୋଟ $25
ତୁଳନାରେ $20 + ସୀମାରେ ପହଞ୍ଚିବା = ହତାଶା
```

### ପରିସ୍ଥିତି 2: "ମୁଁ ଶୂନ୍ୟ ଖର୍ଚ୍ଚ ଚାହୁଁଛି"

**ସମସ୍ୟା:** ସବସ୍କ୍ରିପ୍ସନ୍ କିଣିବାକୁ ସକ୍ଷମ ନୁହେଁ, ନିର୍ଭରଯୋଗ୍ୟ AI କୋଡିଂ ଆବଶ୍ୟକ

```
କମ୍ବୋ: "zero-cost"
  1. if/kimi-k2.7-code          (ତାଲିକାଭୁକ୍ତ ମାଗଣା ଆକ୍ସେସ୍; ରେଟ୍ ଲିମିଟ୍ ପ୍ରଯୁଜ୍ୟ ହୋଇପାରେ)
  2. kr/qwen3-coder-next        (Kiro ମାଗଣା ଫଲ୍‌ବ୍ୟାକ୍)

ମାସିକ ଖର୍ଚ୍ଚ: $0
```

### ଟ୍ରେ ମୋଡ୍

ସିଷ୍ଟମ୍ ଟ୍ରେରେ OmniRoute ଆରମ୍ଭ କରନ୍ତୁ:

```bash
omniroute serve --tray
```

ସର୍ଭର ଏବଂ ଟ୍ରେ ପ୍ରସ୍ତୁତ ହେବା ପରେ କମାଣ୍ଡଟି ଫେରିଆସେ।

ଟର୍ମିନାଲ୍ ବିନା ସର୍ଭର ଚାଲୁ ରହେ।

ଟ୍ରେ ମୋଡ୍ macOS, Windows ଏବଂ ଗ୍ରାଫିକାଲ୍ Linux ସେସନ୍‌ଗୁଡ଼ିକୁ ସମର୍ଥନ କରେ। ଟ୍ରେ ମୋଡ୍ ସ୍ୱୟଂଚାଳିତ ଭାବରେ ଡ୍ୟାଶବୋର୍ଡ ଖୋଲେ ନାହିଁ।

ଏହି କାର୍ଯ୍ୟଗୁଡ଼ିକ ପାଇଁ ଟ୍ରେ ମେନୁ ବ୍ୟବହାର କରନ୍ତୁ:

- ଡ୍ୟାଶବୋର୍ଡ ଖୋଲନ୍ତୁ।
- `/dashboard/logs` ଖୋଲନ୍ତୁ।
- ସ୍ୱୟଂଚାଳିତ ଆରମ୍ଭ ପରିବର୍ତ୍ତନ କରନ୍ତୁ।
- OmniRoute ବନ୍ଦ କରନ୍ତୁ।

ଏହି ବିକଳ୍ପଗୁଡ଼ିକ ସହିତ `--tray`କୁ ଏକାଠି ବ୍ୟବହାର କରନ୍ତୁ ନାହିଁ:

- `--daemon`
- `--log`
- `--no-recovery`

ଏହି ମୋଡ୍‌ଗୁଡ଼ିକ ପାଇଁ ଭିନ୍ନ ପ୍ରକ୍ରିୟା ମାଲିକାନା ଆବଶ୍ୟକ।

ପରବର୍ତ୍ତୀ ମେସିନ୍ ଲଗ୍‌ଇନ୍ ସମୟରେ ଷ୍ଟାର୍ଟଅପ୍ ସକ୍ଷମ କରନ୍ତୁ:

```bash
omniroute autostart enable
```

ସ୍ୱୟଂଚାଳିତ ଆରମ୍ଭ macOS, Windows ଏବଂ ଗ୍ରାଫିକାଲ୍ Linux ସେସନ୍‌ଗୁଡ଼ିକରେ ଟ୍ରେ ମୋଡ୍ ବ୍ୟବହାର କରେ। ହେଡ୍‌ଲେସ୍ Linux ବିଦ୍ୟମାନ systemd ବ୍ୟବହାରକାରୀ ସେବା ବ୍ୟବହାର କରେ।

ଲଗ୍‌ଇନ୍ ସମୟରେ ଷ୍ଟାର୍ଟଅପ୍ ଅକ୍ଷମ କରନ୍ତୁ:

```bash
omniroute autostart disable
```

### ଅନଇନ୍‌ଷ୍ଟଲ୍ କରିବା

ଯେତେବେଳେ ଆପଣଙ୍କୁ ଆଉ OmniRoute ଆବଶ୍ୟକ ନଥାଏ, ସମ୍ପୂର୍ଣ୍ଣ ଭାବେ ହଟାଇବା ପାଇଁ ଆମେ ଦୁଇଟି ଦ୍ରୁତ ସ୍କ୍ରିପ୍ଟ ପ୍ରଦାନ କରୁଛୁ:

| କମାଣ୍ଡ                   | କାର୍ଯ୍ୟ                                                                            |
| ------------------------ | ---------------------------------------------------------------------------------- |
| `npm run uninstall`      | ସିଷ୍ଟମ୍ ଆପ୍‌କୁ ହଟାଏ, କିନ୍ତୁ `~/.omniroute`ରେ **ଆପଣଙ୍କ DB ଏବଂ ବିନ୍ୟାସଗୁଡ଼ିକୁ ରଖେ**। |
| `npm run uninstall:full` | ଆପ୍‌କୁ ହଟାଏ ଏବଂ **ସମସ୍ତ ବିନ୍ୟାସ, କୀ ଓ ଡାଟାବେସ୍‌କୁ ସ୍ଥାୟୀ ଭାବରେ ଲିଭାଇଦିଏ**।         |

> ଟିପ୍ପଣୀ: ଏହି କମାଣ୍ଡଗୁଡ଼ିକ ଚଲାଇବା ପାଇଁ OmniRoute ପ୍ରୋଜେକ୍ଟ ଫୋଲ୍ଡରକୁ ଯାଆନ୍ତୁ (ଯଦି ଆପଣ ଏହାକୁ କ୍ଲୋନ୍ କରିଥିଲେ) ଏବଂ ସେଗୁଡ଼ିକୁ ଚଲାନ୍ତୁ। ବିକଳ୍ପ ଭାବେ, ଯଦି ଏହା ଗ୍ଲୋବାଲ୍ ଭାବେ ଇନ୍‌ଷ୍ଟଲ୍ ହୋଇଛି, ତେବେ ଆପଣ କେବଳ `npm uninstall -g omniroute` ଚଲାଇପାରିବେ।

```bash

revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"
maintainer="zenobit <zenobit@disroot.org>"
license="MIT"
homepage="https://github.com/diegosouzapw/OmniRoute"
distfiles="https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz"
checksum=009400afee90a9f32599d8fe734145cfd84098140b7287990183dde45ae2245b
system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"

export npm_config_loglevel=error

	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	# 1) ସମସ୍ତ ନିର୍ଭରଶୀଳତା ଇନ୍‌ଷ୍ଟଲ୍ କରନ୍ତୁ – ସ୍କ୍ରିପ୍ଟଗୁଡ଼ିକୁ ଏଡ଼ାଇ ଯାଆନ୍ତୁ

	npm run build

	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	# 5) କମ୍ପାଇଲ୍ ହୋଇଥିବା ବାଇଣ୍ଡିଂକୁ ଷ୍ଟାଣ୍ଡଅଲୋନ୍ ବଣ୍ଡଲ୍‌ରେ ରଖନ୍ତୁ
	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	# 6) ଆର୍କିଟେକ୍ଚର୍-ନିର୍ଦ୍ଦିଷ୍ଟ sharp ବଣ୍ଡଲ୍‌ଗୁଡ଼ିକୁ ଅପସାରଣ କରନ୍ତୁ

	for _d in \

export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
```

## 🧩 ଉନ୍ନତ ବୈଶିଷ୍ଟ୍ୟଗୁଡ଼ିକ

### କଷ୍ଟମ୍ ମଡେଲ୍‌ଗୁଡ଼ିକ

ଆପ୍ ଅପଡେଟ୍ ପାଇଁ ଅପେକ୍ଷା ନକରି ଯେକୌଣସି ପ୍ରଦାନକାରୀଙ୍କ ସହ ଯେକୌଣସି ମଡେଲ୍ ID ଯୋଡ଼ନ୍ତୁ:

```bash
# API ମାଧ୍ୟମରେ
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# ତାଲିକା: curl http://localhost:20128/api/provider-models?provider=openai
# ଅପସାରଣ: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

କିମ୍ବା ଡ୍ୟାସ୍‌ବୋର୍ଡ ବ୍ୟବହାର କରନ୍ତୁ: **ପ୍ରଦାନକାରୀ → [ପ୍ରଦାନକାରୀ] → କଷ୍ଟମ୍ ମଡେଲ୍‌ଗୁଡ଼ିକ**।

ଟିପ୍ପଣୀ:

- OpenRouter ଏବଂ OpenAI/Anthropic-ସୁସଙ୍ଗତ ପ୍ରଦାନକାରୀମାନଙ୍କୁ କେବଳ **ଉପଲବ୍ଧ ମଡେଲ୍‌ଗୁଡ଼ିକ**ରୁ ପରିଚାଳନା କରାଯାଏ। ମାନୁଆଲ୍ ଯୋଗ, ଆମଦାନୀ ଏବଂ ସ୍ୱୟଂକ୍ରିୟ ସିଙ୍କ୍—ସବୁ ସମାନ ଉପଲବ୍ଧ-ମଡେଲ୍ ତାଲିକାରେ ସଂରକ୍ଷିତ ହୁଏ, ତେଣୁ ସେହି ପ୍ରଦାନକାରୀମାନଙ୍କ ପାଇଁ ଅଲଗା କଷ୍ଟମ୍ ମଡେଲ୍ ବିଭାଗ ନାହିଁ।
- **କଷ୍ଟମ୍ ମଡେଲ୍‌ଗୁଡ଼ିକ** ବିଭାଗଟି ପରିଚାଳିତ ଉପଲବ୍ଧ-ମଡେଲ୍ ଆମଦାନୀ ପ୍ରଦାନ କରୁନଥିବା ପ୍ରଦାନକାରୀମାନଙ୍କ ପାଇଁ ଉଦ୍ଦିଷ୍ଟ।

### OmniRoute ପିଅର୍‌ଗୁଡ଼ିକୁ ଶୃଙ୍ଖଳିତ କରିବା

ଅନ୍ୟ ଏକ OmniRoute ଗେଟୱେକୁ ଏକ **କଷ୍ଟମ୍ OpenAI-ସୁସଙ୍ଗତ** ପ୍ରଦାନକାରୀ ଭାବେ ଯୋଡ଼ାଯାଇପାରିବ। ସେହି ପିଅର୍‌ର `/v1` ବେସ୍ URL ଏବଂ ତାହା ଦ୍ୱାରା ଜାରି କରାଯାଇଥିବା ଏକ ଉତ୍ସର୍ଗୀକୃତ, ସର୍ବନିମ୍ନ-ଅଧିକାର API କୀ ବ୍ୟବହାର କରନ୍ତୁ।

ପାରସ୍ପରିକ କିମ୍ବା ମଲ୍ଟି-ହପ୍ ଶୃଙ୍ଖଳ ପାଇଁ, ପ୍ରତ୍ୟେକ ଗେଟୱେରେ ଅପ୍ଟ-ଇନ୍ ଲୁପ୍ ଗାର୍ଡ ସକ୍ଷମ କରନ୍ତୁ:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

କେବଳ ସ୍ପଷ୍ଟ ଭାବରେ ଅନୁମୋଦିତ ତାଲିକାରେ ଥିବା ପିଅର୍ URLକୁ ପଠାଯାଇଥିବା ଅନୁରୋଧଗୁଡ଼ିକ `X-OmniRoute-Peer-Trace` ହେଡର୍ ପାଆନ୍ତି। ଏକ ଗେଟୱେ ପୁନରାବୃତ୍ତ ଇନ୍‌ଷ୍ଟାନ୍ସ ID କିମ୍ବା ସମାପ୍ତ ହୋଇଥିବା ହପ୍ ବଜେଟ୍‌କୁ HTTP `508 Loop Detected` ସହ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ; ସାଧାରଣ ଅପ୍‌ଷ୍ଟ୍ରିମ୍ ପ୍ରଦାନକାରୀମାନେ କୌଣସି ପିଅର୍ ମେଟାଡାଟା ପାଆନ୍ତି ନାହିଁ।

ପିଅର୍ ଶୃଙ୍ଖଳନ ଡାଟାବେସ୍ ପ୍ରତିକୃତିକରଣ କିମ୍ବା ହୋଷ୍ଟ ଫେଲ୍‌ଓଭର୍ ନୁହେଁ। ପ୍ରତ୍ୟେକ ଗେଟୱେ ସ୍ୱାଧୀନ SQLite ଅବସ୍ଥା, କ୍ୟାଶ୍, ରେଟ୍ କାଉଣ୍ଟର୍ ଏବଂ ସେସନ୍ ରଖେ। ସକ୍ରିୟ/ନିଷ୍କ୍ରିୟ କିମ୍ବା ସକ୍ରିୟ/ସକ୍ରିୟ ଉପଲବ୍ଧତା ପାଇଁ ସ୍ୱାସ୍ଥ୍ୟ-ଯାଞ୍ଚଯୁକ୍ତ ରିଭର୍ସ ପ୍ରକ୍ସି କିମ୍ବା କ୍ଲାଏଣ୍ଟ ଫେଲ୍‌ଓଭର୍ ବ୍ୟବହାର କରନ୍ତୁ, ଏବଂ ଗୋଟିଏ SQLite ଡାଟାବେସ୍‌କୁ ଏକାଧିକ ଚାଲୁଥିବା OmniRoute ଇନ୍‌ଷ୍ଟାନ୍ସରେ କେବେବି ମାଉଣ୍ଟ କରନ୍ତୁ ନାହିଁ।

### ନେଟୱର୍କ ପ୍ରକ୍ସି ବିନ୍ୟାସ

```bash
# ଗ୍ଲୋବାଲ୍ ପ୍ରକ୍ସି ସେଟ୍ କରନ୍ତୁ
```

### କ୍ଲାଉଡ୍ ସିଙ୍କ୍

- ଡିଭାଇସ୍‌ଗୁଡ଼ିକ ମଧ୍ୟରେ ପ୍ରଦାନକାରୀ, କମ୍ବୋ ଏବଂ ସେଟିଂଗୁଡ଼ିକୁ ସିଙ୍କ୍ କରନ୍ତୁ
- ଟାଇମ୍‌ଆଉଟ୍ + ଫେଲ୍-ଫାଷ୍ଟ ସହ ସ୍ୱୟଂକ୍ରିୟ ପୃଷ୍ଠଭୂମି ସିଙ୍କ୍
- ପ୍ରଡକ୍ସନ୍‌ରେ ସର୍ଭର୍-ସାଇଡ୍ `NEXT_PUBLIC_BASE_URL`/`NEXT_PUBLIC_CLOUD_URL`କୁ ପ୍ରାଥମ୍ୟ ଦିଅନ୍ତୁ

### Cloudflare କ୍ୱିକ୍ ଟନେଲ୍

- Docker ଏବଂ ଅନ୍ୟ ସ୍ୱୟଂ-ହୋଷ୍ଟେଡ୍ ଡିପ୍ଲୟମେଣ୍ଟ ପାଇଁ **ଡ୍ୟାସ୍‌ବୋର୍ଡ → ଏଣ୍ଡପଏଣ୍ଟଗୁଡ଼ିକ**ରେ ଉପଲବ୍ଧ
- ଏକ ଅସ୍ଥାୟୀ `https://*.trycloudflare.com` URL ସୃଷ୍ଟି କରେ, ଯାହା ଆପଣଙ୍କ ବର୍ତ୍ତମାନର OpenAI-ସୁସଙ୍ଗତ `/v1` ଏଣ୍ଡପଏଣ୍ଟକୁ ଫରୱାର୍ଡ କରେ
- ପ୍ରଥମ ଥର ସକ୍ଷମ କଲେ କେବଳ ଆବଶ୍ୟକ ହେବା ସମୟରେ `cloudflared` ଇନ୍‌ଷ୍ଟଲ୍ ହୁଏ; ପରବର୍ତ୍ତୀ ରିଷ୍ଟାର୍ଟଗୁଡ଼ିକ ସମାନ ପରିଚାଳିତ ବାଇନାରିକୁ ପୁନଃବ୍ୟବହାର କରେ
- OmniRoute କିମ୍ବା କଣ୍ଟେନର୍ ରିଷ୍ଟାର୍ଟ ପରେ କ୍ୱିକ୍ ଟନେଲ୍‌ଗୁଡ଼ିକ ସ୍ୱୟଂକ୍ରିୟ ଭାବେ ପୁନରୁଦ୍ଧାର ହୁଏ ନାହିଁ; ଆବଶ୍ୟକ ହେଲେ ଡ୍ୟାସ୍‌ବୋର୍ଡରୁ ସେଗୁଡ଼ିକୁ ପୁନଃସକ୍ଷମ କରନ୍ତୁ
- ଟନେଲ୍ URLଗୁଡ଼ିକ ଅସ୍ଥାୟୀ ଏବଂ ଆପଣ ଟନେଲ୍‌କୁ ପ୍ରତ୍ୟେକ ଥର ବନ୍ଦ/ଆରମ୍ଭ କଲେ ପରିବର୍ତ୍ତିତ ହୁଏ
- ସୀମିତ କଣ୍ଟେନର୍‌ଗୁଡ଼ିକରେ ଅନାବଶ୍ୟକ QUIC UDP ବଫର୍ ସତର୍କବାର୍ତ୍ତା ଏଡ଼ାଇବା ପାଇଁ ପରିଚାଳିତ କ୍ୱିକ୍ ଟନେଲ୍‌ଗୁଡ଼ିକ ଡିଫଲ୍ଟ ଭାବେ HTTP/2 ଟ୍ରାନ୍ସପୋର୍ଟ ବ୍ୟବହାର କରେ
- ପରିଚାଳିତ ଟ୍ରାନ୍ସପୋର୍ଟ ପସନ୍ଦକୁ ଓଭର୍‌ରାଇଡ୍ କରିବାକୁ ଚାହୁଁଥିଲେ `CLOUDFLARED_PROTOCOL=quic` କିମ୍ବା `auto` ସେଟ୍ କରନ୍ତୁ
- ପରିଚାଳିତ ଡାଉନଲୋଡ୍ ପରିବର୍ତ୍ତେ ପୂର୍ବରୁ ଇନ୍‌ଷ୍ଟଲ୍ ହୋଇଥିବା `cloudflared` ବାଇନାରି ବ୍ୟବହାର କରିବାକୁ ପସନ୍ଦ କଲେ `CLOUDFLARED_BIN` ସେଟ୍ କରନ୍ତୁ
- Cloudflare କ୍ୱିକ୍ ଟନେଲ୍, Tailscale ଫନେଲ୍ ଏବଂ ngrok ଟନେଲ୍ ପ୍ୟାନେଲ୍‌ଗୁଡ଼ିକୁ **ସେଟିଂସ୍ → ଦୃଶ୍ୟରୂପ**ରେ ଦେଖାଯାଇପାରେ କିମ୍ବା ଲୁଚାଯାଇପାରେ। ଏକ ପ୍ୟାନେଲ୍ ଲୁଚାଇବା ଦ୍ୱାରା ଚାଲୁଥିବା ଟନେଲ୍ ବନ୍ଦ ହୁଏ ନାହିଁ।

### LLM ଗେଟୱେ ବୁଦ୍ଧିମତ୍ତା (ପର୍ଯ୍ୟାୟ 9)

- **ସିମାଣ୍ଟିକ୍ କ୍ୟାଶ୍** — ନନ୍-ଷ୍ଟ୍ରିମିଂ, temperature=0 ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକୁ ସ୍ୱୟଂକ୍ରିୟ ଭାବେ କ୍ୟାଶ୍ କରେ (`X-OmniRoute-No-Cache: true` ସହ ବାଇପାସ୍ କରନ୍ତୁ)
- **ଅନୁରୋଧ ଆଇଡେମ୍ପୋଟେନ୍ସି** — `Idempotency-Key` କିମ୍ବା `X-Request-Id` ହେଡର୍ ମାଧ୍ୟମରେ 5s ମଧ୍ୟରେ ଅନୁରୋଧଗୁଡ଼ିକର ନକଲ୍ ହଟାଏ
- **ପ୍ରଗତି ଟ୍ରାକିଂ** — `X-OmniRoute-Progress: true` ହେଡର୍ ମାଧ୍ୟମରେ ଅପ୍ଟ-ଇନ୍ SSE `event: progress` ଇଭେଣ୍ଟ

### ଅନୁବାଦକ ପ୍ଲେଗ୍ରାଉଣ୍ଡ

**ଡ୍ୟାସ୍‌ବୋର୍ଡ → ଅନୁବାଦକ** ମାଧ୍ୟମରେ ପ୍ରବେଶ କରନ୍ତୁ। OmniRoute କିପରି ପ୍ରଦାନକାରୀମାନଙ୍କ ମଧ୍ୟରେ API ଅନୁରୋଧଗୁଡ଼ିକୁ ଅନୁବାଦ କରେ, ତାହାକୁ ଡିବଗ୍ ଏବଂ ଭିଜୁଆଲାଇଜ୍ କରନ୍ତୁ।

| ମୋଡ୍              | ଉଦ୍ଦେଶ୍ୟ                                                                                         |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| **ପ୍ଲେଗ୍ରାଉଣ୍ଡ**  | ଉତ୍ସ/ଲକ୍ଷ୍ୟ ଫର୍ମାଟ୍ ବାଛନ୍ତୁ, ଏକ ଅନୁରୋଧ ପେଷ୍ଟ କରନ୍ତୁ ଏବଂ ଅନୁବାଦିତ ଆଉଟପୁଟ୍ ତୁରନ୍ତ ଦେଖନ୍ତୁ          |
| **ଚାଟ୍ ପରୀକ୍ଷକ**  | ପ୍ରକ୍ସି ମାଧ୍ୟମରେ ଲାଇଭ୍ ଚାଟ୍ ବାର୍ତ୍ତା ପଠାନ୍ତୁ ଏବଂ ସମ୍ପୂର୍ଣ୍ଣ ଅନୁରୋଧ/ପ୍ରତିକ୍ରିୟା ଚକ୍ର ଯାଞ୍ଚ କରନ୍ତୁ |

| **ଲାଇଭ୍ ମନିଟର୍**  | ଅନୁରୋଧଗୁଡ଼ିକ ପ୍ରକ୍ସି ମାଧ୍ୟମରେ ପ୍ରବାହିତ ହେବା ସମୟରେ ରିଅଲ୍-ଟାଇମ୍ ଅନୁବାଦଗୁଡ଼ିକୁ ଦେଖନ୍ତୁ              |

**ବ୍ୟବହାର କ୍ଷେତ୍ରଗୁଡ଼ିକ:**

- ଏକ ନିର୍ଦ୍ଦିଷ୍ଟ କ୍ଲାଏଣ୍ଟ/ପ୍ରଦାନକାରୀ ସଂଯୋଜନ କାହିଁକି ବିଫଳ ହୁଏ, ତାହା ଡିବଗ୍ କରନ୍ତୁ
- ଥିଙ୍କିଂ ଟ୍ୟାଗ୍, ଟୁଲ୍ କଲ୍ ଏବଂ ସିଷ୍ଟମ୍ ପ୍ରମ୍ପ୍ଟଗୁଡ଼ିକ ସଠିକ ଭାବେ ଅନୁବାଦିତ ହେଉଛି କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ
- OpenAI, Claude, Gemini ଏବଂ Responses API ଫର୍ମାଟ୍‌ଗୁଡ଼ିକ ମଧ୍ୟରେ ଫର୍ମାଟ୍ ପାର୍ଥକ୍ୟ ତୁଳନା କରନ୍ତୁ

### ରାଉଟିଂ କୌଶଳଗୁଡ଼ିକ

**ଡ୍ୟାଶବୋର୍ଡ → ସେଟିଂସ୍ → ରାଉଟିଂ** ମାଧ୍ୟମରେ ବିନ୍ୟାସ କରନ୍ତୁ। ଡ୍ୟାଶବୋର୍ଡରେ ସର୍ବାଧିକ ବ୍ୟବହୃତ ଛଅଟି କୌଶଳ ଉପଲବ୍ଧ ଅଛି; କମ୍ବୋ ଏବଂ ଅଟୋ-ରାଉଟର୍ ଆଭ୍ୟନ୍ତରୀଣ ଭାବରେ ଅଧିକ ବ୍ୟାପକ କୌଶଳ ସମୂହକୁ ସମର୍ଥନ କରେ।

**ଡ୍ୟାଶବୋର୍ଡରେ ଦୃଶ୍ୟମାନ କୌଶଳଗୁଡ଼ିକ (ଆକାଉଣ୍ଟ-ସ୍ତରୀୟ ରାଉଟିଂ):**

| କୌଶଳ                          | ବିବରଣୀ                                                                                                            |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| **ପ୍ରଥମେ ପୂରଣ**               | ପ୍ରାଥମିକତା କ୍ରମରେ ଆକାଉଣ୍ଟଗୁଡ଼ିକୁ ବ୍ୟବହାର କରେ — ଅନୁପଲବ୍ଧ ହେବା ପର୍ଯ୍ୟନ୍ତ ପ୍ରାଥମିକ ଆକାଉଣ୍ଟ ସମସ୍ତ ଅନୁରୋଧ ପରିଚାଳନା କରେ |
| **ରାଉଣ୍ଡ ରବିନ୍**              | ବିନ୍ୟାସଯୋଗ୍ୟ ଷ୍ଟିକି ସୀମା ସହିତ ସମସ୍ତ ଆକାଉଣ୍ଟକୁ ଚକ୍ରାକାରରେ ବ୍ୟବହାର କରେ (ଡିଫଲ୍ଟ: ପ୍ରତି ଆକାଉଣ୍ଟ ପାଇଁ 3ଟି କଲ୍)         |
| **P2C (ଦୁଇଟି ବିକଳ୍ପର ଶକ୍ତି)** | 2ଟି ଯାଦୃଚ୍ଛିକ ଆକାଉଣ୍ଟ ବାଛି ଅଧିକ ସୁସ୍ଥ ଆକାଉଣ୍ଟକୁ ରାଉଟ୍ କରେ — ସ୍ୱାସ୍ଥ୍ୟ ସ୍ଥିତିକୁ ଧ୍ୟାନରେ ରଖି ଲୋଡ୍ ସନ୍ତୁଳିତ କରେ      |
| **ଯାଦୃଚ୍ଛିକ**                 | Fisher-Yates ଶଫଲ୍ ବ୍ୟବହାର କରି ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ପାଇଁ ଯାଦୃଚ୍ଛିକ ଭାବରେ ଗୋଟିଏ ଆକାଉଣ୍ଟ ବାଛେ                             |
| **ସର୍ବନିମ୍ନ ବ୍ୟବହୃତ**         | ସବୁଠାରୁ ପୁରୁଣା `lastUsedAt` ଟାଇମଷ୍ଟାମ୍ପ ଥିବା ଆକାଉଣ୍ଟକୁ ରାଉଟ୍ କରି ଟ୍ରାଫିକ୍ ସମାନ ଭାବରେ ବଣ୍ଟନ କରେ                    |
| **ଖର୍ଚ୍ଚ ଅନୁକୂଳିତ**           | ସର୍ବନିମ୍ନ ପ୍ରାଥମିକତା ମୂଲ୍ୟ ଥିବା ଆକାଉଣ୍ଟକୁ ରାଉଟ୍ କରି ସର୍ବନିମ୍ନ-ଖର୍ଚ୍ଚ ପ୍ରଦାତାଙ୍କ ପାଇଁ ଅନୁକୂଳନ କରେ                  |

**ଉନ୍ନତ କମ୍ବୋ ଏବଂ ଅଟୋ କୌଶଳଗୁଡ଼ିକ** (ପ୍ରତ୍ୟେକ କମ୍ବୋ ପାଇଁ କିମ୍ବା `auto/*` ପ୍ରିଫିକ୍ସ ମାଧ୍ୟମରେ ବିନ୍ୟାସଯୋଗ୍ୟ — [AUTO-COMBO.md](../routing/AUTO-COMBO.md) ଦେଖନ୍ତୁ):

- `priority` — କଠୋର କ୍ରମ, କେବେ ମଧ୍ୟ ରାଉଣ୍ଡ-ରବିନ୍ କରେ ନାହିଁ
- `weighted` — ପ୍ରତି-ମଡେଲ୍ ଓଜନ ଅନୁସାରେ ଆନୁପାତିକ ଟ୍ରାଫିକ୍ ବିଭାଜନ
- `fill-first` — ସୀମା ପୂରଣ ହେବା ପର୍ଯ୍ୟନ୍ତ ପ୍ରଥମ ମଡେଲ୍‌କୁ ବ୍ୟବହାର କରେ
- `round-robin` / `strict-random` / `random`
- `p2c` (ଦୁଇଟି ବିକଳ୍ପର ଶକ୍ତି)
- `least-used` ଏବଂ `cost-optimized`
- `auto` — ସମସ୍ତ ପ୍ରାର୍ଥୀ ମଧ୍ୟରେ ସ୍କୋର୍-ଆଧାରିତ ଚୟନ
- `lkgp` (ଶେଷ ଜଣାଶୁଣା ଭଲ ପ୍ରଦାତା) — ଶେଷ ସଫଳ ପ୍ରଦାତାକୁ ଧରି ରଖେ, ତା’ପରେ ନିୟମଗୁଡ଼ିକୁ ଫଲ୍‌ବ୍ୟାକ୍ କରେ
- `context-optimized` — ସବୁଠାରୁ ବଡ଼ ଖାଲି କଣ୍ଟେକ୍ସ୍ଟ ୱିଣ୍ଡୋ ଥିବା ମଡେଲ୍‌କୁ ବାଛେ
- `context-relay` — ପରବର୍ତ୍ତୀ ଟର୍ନଗୁଡ଼ିକ ପାଇଁ ଦୀର୍ଘ-କଣ୍ଟେକ୍ସ୍ଟ ମଡେଲ୍‌ଗୁଡ଼ିକୁ ଶୃଙ୍ଖଳିତ କରେ

#### ବାହ୍ୟ ଷ୍ଟିକି ସେସନ୍ ହେଡର୍

ବାହ୍ୟ ସେସନ୍ ଆଫିନିଟି ପାଇଁ (ଉଦାହରଣ ସ୍ୱରୂପ, ରିଭର୍ସ ପ୍ରକ୍ସି ପଛରେ ଥିବା Claude Code/Codex ଏଜେଣ୍ଟ), ଏହା ପଠାନ୍ତୁ:

```http
X-Session-Id: your-session-key
```

OmniRoute `x_session_id`କୁ ମଧ୍ୟ ଗ୍ରହଣ କରେ ଏବଂ ପ୍ରଭାବୀ ସେସନ୍ କୀକୁ `X-OmniRoute-Session-Id`ରେ ଫେରାଇଥାଏ।

ଆପଣ Nginx ବ୍ୟବହାର କରୁଥିଲେ ଏବଂ ଅଣ୍ଡରସ୍କୋର୍-ରୂପୀ ହେଡର୍ ପଠାଉଥିଲେ, ଏହାକୁ ସକ୍ଷମ କରନ୍ତୁ:

```nginx
underscores_in_headers on;
```

#### ୱାଇଲ୍ଡକାର୍ଡ ମଡେଲ୍ ଉପନାମ

ମଡେଲ୍ ନାମଗୁଡ଼ିକୁ ପୁନଃମ୍ୟାପ୍ କରିବା ପାଇଁ ୱାଇଲ୍ଡକାର୍ଡ ପ୍ୟାଟର୍ନ ସୃଷ୍ଟି କରନ୍ତୁ:

```
ପ୍ୟାଟର୍ନ: claude-sonnet-*     →  ଲକ୍ଷ୍ୟ: cc/claude-sonnet-4-6
ପ୍ୟାଟର୍ନ: gpt-*               →  ଲକ୍ଷ୍ୟ: gh/gpt-5.3-codex
```

ୱାଇଲ୍ଡକାର୍ଡଗୁଡ଼ିକ `*` (ଯେକୌଣସି ଅକ୍ଷରଗୁଡ଼ିକ) ଏବଂ `?` (ଗୋଟିଏ ଅକ୍ଷର)କୁ ସମର୍ଥନ କରେ।

#### ଫଲ୍‌ବ୍ୟାକ୍ ଶୃଙ୍ଖଳା

ସମସ୍ତ ଅନୁରୋଧରେ ପ୍ରଯୁଜ୍ୟ ଗ୍ଲୋବାଲ୍ ଫଲ୍‌ବ୍ୟାକ୍ ଶୃଙ୍ଖଳାଗୁଡ଼ିକୁ ପରିଭାଷିତ କରନ୍ତୁ:

```
ଶୃଙ୍ଖଳା: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### ସ୍ଥିତିସ୍ଥାପକତା ଏବଂ ସର୍କିଟ୍ ବ୍ରେକର୍

**ଡ୍ୟାଶବୋର୍ଡ → ସେଟିଂସ୍ → ସ୍ଥିତିସ୍ଥାପକତା** ମାଧ୍ୟମରେ ବିନ୍ୟାସ କରନ୍ତୁ।

OmniRoute ପାଞ୍ଚଟି ଉପାଦାନ ସହିତ ପ୍ରଦାତା-ସ୍ତରୀୟ ସ୍ଥିତିସ୍ଥାପକତା କାର୍ଯ୍ୟକାରୀ କରେ:

1. **ଅନୁରୋଧ କ୍ୟୁ ଏବଂ ପେସିଂ** — ସିଷ୍ଟମ୍-ସ୍ତରୀୟ ଅନୁରୋଧ ନିୟନ୍ତ୍ରଣ:
   - **ପ୍ରତି ମିନିଟ୍‌ରେ ଅନୁରୋଧ (RPM)** — ପ୍ରତି ଆକାଉଣ୍ଟ ପାଇଁ ପ୍ରତି ମିନିଟ୍‌ରେ ସର୍ବାଧିକ ଅନୁରୋଧ
   - **ଅନୁରୋଧଗୁଡ଼ିକ ମଧ୍ୟରେ ସର୍ବନିମ୍ନ ସମୟ** — ଅନୁରୋଧଗୁଡ଼ିକ ମଧ୍ୟରେ ମିଲିସେକେଣ୍ଡରେ ସର୍ବନିମ୍ନ ବ୍ୟବଧାନ
   - **ସର୍ବାଧିକ ସମସାମୟିକ ଅନୁରୋଧ** — ପ୍ରତି ଆକାଉଣ୍ଟ ପାଇଁ ସର୍ବାଧିକ ଏକକାଳୀନ ଅନୁରୋଧ

2. **କନେକ୍ସନ୍ କୁଲ୍‌ଡାଉନ୍** — ପୁନଃଚେଷ୍ଟାଯୋଗ୍ୟ ବିଫଳତା ପରେ ଗୋଟିଏ କନେକ୍ସନ୍ ପାଇଁ ପ୍ରତି-ପ୍ରମାଣୀକରଣ-ପ୍ରକାର ବିନ୍ୟାସ:
   - **ମୂଳ କୁଲ୍‌ଡାଉନ୍** — ପୁନଃଚେଷ୍ଟାଯୋଗ୍ୟ ଅପ୍‌ଷ୍ଟ୍ରିମ୍ ବିଫଳତା ପାଇଁ ଡିଫଲ୍ଟ କୁଲ୍‌ଡାଉନ୍ ୱିଣ୍ଡୋ
   - **ଅପ୍‌ଷ୍ଟ୍ରିମ୍ ପୁନଃଚେଷ୍ଟା ସୂଚନା ବ୍ୟବହାର କରନ୍ତୁ** — ପ୍ରଦାନ କରାଯାଇଥିଲେ ପ୍ରାମାଣିକ `Retry-After` କିମ୍ବା ରିସେଟ୍ ସୂଚନାକୁ ମାନେ
   - **ସର୍ବାଧିକ ବ୍ୟାକ୍‌ଅଫ୍ ପଦକ୍ଷେପ** — ପୁନରାବୃତ୍ତ ବିଫଳତା ପାଇଁ ସର୍ବାଧିକ ଏକ୍ସପୋନେନ୍ସିଆଲ୍ ବ୍ୟାକ୍‌ଅଫ୍ ସ୍ତର

3. **ପ୍ରଦାତା ସର୍କିଟ୍ ବ୍ରେକର୍** — ଆରମ୍ଭରୁ ଶେଷ ପର୍ଯ୍ୟନ୍ତ ପ୍ରଦାତା ବିଫଳତାଗୁଡ଼ିକୁ ଟ୍ରାକ୍ କରେ, ବିନ୍ୟାସିତ ଚେତାବନୀ ସୀମାରେ ପ୍ରଦାତାକୁ ଅବନତ ଭାବେ ଚିହ୍ନିତ କରେ, ଏବଂ ବିନ୍ୟାସିତ ବିଫଳତା ସୀମା ପହଞ୍ଚିଲେ ବ୍ରେକର୍‌କୁ ଖୋଲେ:
   - **ଅବନତି ସୀମା** — `DEGRADED`ରେ ପ୍ରବେଶ କରିବା ପୂର୍ବରୁ କ୍ରମାଗତ ପ୍ରଦାତା ବିଫଳତା
   - **ବିଫଳତା ସୀମା** — `OPEN`ରେ ପ୍ରବେଶ କରିବା ପୂର୍ବରୁ କ୍ରମାଗତ ପ୍ରଦାତା ବିଫଳତା
   - **ରିସେଟ୍ ସମୟସୀମା** — ପ୍ରଦାତାକୁ ପୁଣି ପରୀକ୍ଷା କରିବା ପୂର୍ବରୁ ସମୟ ୱିଣ୍ଡୋ
   - **CLOSED** (ସୁସ୍ଥ) — ଅନୁରୋଧଗୁଡ଼ିକ ସାଧାରଣ ଭାବରେ ପ୍ରବାହିତ ହୁଏ
   - **DEGRADED** — ବର୍ଦ୍ଧିତ ବିଫଳତାଗୁଡ଼ିକୁ ଟ୍ରାକ୍ କରାଯାଉଥିବା ବେଳେ ମଧ୍ୟ ଅନୁରୋଧଗୁଡ଼ିକ ପ୍ରବାହିତ ହୁଏ
   - **OPEN** — ପୁନରାବୃତ୍ତ ବିଫଳତା ପରେ ପ୍ରଦାତାକୁ ଅସ୍ଥାୟୀ ଭାବରେ ଅବରୋଧ କରାଯାଏ
   - **HALF_OPEN** — ପ୍ରଦାତା ପୁନରୁଦ୍ଧାର ହୋଇଛି କି ନାହିଁ ପରୀକ୍ଷା କରାଯାଉଛି

   କନେକ୍ସନ୍-ସ୍କୋପ୍‌ଯୁକ୍ତ `429` ରେଟ୍ ସୀମାଗୁଡ଼ିକ **କନେକ୍ସନ୍ କୁଲ୍‌ଡାଉନ୍**ରେ ରହେ ଏବଂ ପ୍ରଦାତା ବ୍ରେକର୍ ପାଇଁ ଗଣନା କରାଯାଏ ନାହିଁ।

   ପ୍ରଦାତା ବ୍ରେକର୍‌ର ରନ୍‌ଟାଇମ୍ ସ୍ଥିତି କେବଳ **ଡ୍ୟାଶବୋର୍ଡ → ସ୍ୱାସ୍ଥ୍ୟ**ରେ ଦେଖାଯାଏ।

4. **କୁଲ୍‌ଡାଉନ୍ ପାଇଁ ଅପେକ୍ଷା କରନ୍ତୁ** — ଯଦି ପ୍ରତ୍ୟେକ ପ୍ରାର୍ଥୀ କନେକ୍ସନ୍ ପୂର୍ବରୁ କୁଲ୍‌ଡାଉନ୍‌ରେ ଅଛି, ତେବେ OmniRoute ସବୁଠାରୁ ଶୀଘ୍ର ସମାପ୍ତ ହେବାକୁ ଥିବା କୁଲ୍‌ଡାଉନ୍ ପାଇଁ ଅପେକ୍ଷା କରି ସେହି କ୍ଲାଏଣ୍ଟ ଅନୁରୋଧକୁ ସ୍ୱୟଂଚାଳିତ ଭାବରେ ପୁନଃଚେଷ୍ଟା କରିପାରେ।

5. **ରେଟ୍ ସୀମା ସ୍ୱୟଂଚାଳିତ ଚିହ୍ନଟ** — ଅପ୍‌ଷ୍ଟ୍ରିମ୍ ପ୍ରଦାତାମାନେ ସ୍ପଷ୍ଟ ଅପେକ୍ଷା ୱିଣ୍ଡୋ ଫେରାଇଲେ, ସେଟିଂ ସକ୍ଷମ ଥିବା ସମୟରେ ସେହି ସୂଚନାଗୁଡ଼ିକ ସ୍ଥାନୀୟ କନେକ୍ସନ୍ କୁଲ୍‌ଡାଉନ୍‌କୁ ଅଗ୍ରାଧିକାର ଦେଇ ପ୍ରତିସ୍ଥାପିତ କରେ।

**ବିଶେଷଜ୍ଞ ପରାମର୍ଶ:** ଆଉଟେଜ୍ ପରେ ସକ୍ରିୟ ପ୍ରଦାତା ବ୍ରେକର୍‌ଗୁଡ଼ିକୁ ଯାଞ୍ଚ ଏବଂ ରିସେଟ୍ କରିବା ପାଇଁ **ସ୍ୱାସ୍ଥ୍ୟ** ପୃଷ୍ଠା ବ୍ୟବହାର କରନ୍ତୁ। ସ୍ଥିତିସ୍ଥାପକତା ପୃଷ୍ଠା କେବଳ ବିନ୍ୟାସ ପରିବର୍ତ୍ତନ କରେ।

### ଡାଟାବେସ୍ ରପ୍ତାନି / ଆମଦାନି

**ଡ୍ୟାଶବୋର୍ଡ → ସେଟିଂସ୍ → ସିଷ୍ଟମ୍ ଏବଂ ଷ୍ଟୋରେଜ୍**ରେ ଡାଟାବେସ୍ ବ୍ୟାକଅପ୍‌ଗୁଡ଼ିକୁ ପରିଚାଳନା କରନ୍ତୁ।

| କାର୍ଯ୍ୟ                       | ବିବରଣୀ                                                                                                                                                                      |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ଡାଟାବେସ୍ ରପ୍ତାନି**          | ବର୍ତ୍ତମାନର SQLite ଡାଟାବେସ୍‌କୁ ଏକ `.sqlite` ଫାଇଲ୍ ଭାବେ ଡାଉନଲୋଡ୍ କରେ                                                                                                          |
| **ସବୁକିଛି ରପ୍ତାନି (.tar.gz)** | ଏଗୁଡ଼ିକ ସହିତ ଏକ ସମ୍ପୂର୍ଣ୍ଣ ବ୍ୟାକଅପ୍ ଆର୍କାଇଭ୍ ଡାଉନଲୋଡ୍ କରେ: ଡାଟାବେସ୍, ସେଟିଂସ୍, କମ୍ବୋ, ପ୍ରଦାନକାରୀ ସଂଯୋଗ (କୌଣସି ପ୍ରମାଣପତ୍ର ନୁହେଁ), API କି’ ମେଟାଡାଟା                            |
| **ଡାଟାବେସ୍ ଆମଦାନି**           | ବର୍ତ୍ତମାନର ଡାଟାବେସ୍‌କୁ ପ୍ରତିସ୍ଥାପନ କରିବା ପାଇଁ ଏକ `.sqlite` ଫାଇଲ୍ ଅପଲୋଡ୍ କରେ। `DISABLE_SQLITE_AUTO_BACKUP=true` ନ ଥିଲେ ଆମଦାନି ପୂର୍ବରୁ ସ୍ୱୟଂଚାଳିତ ଭାବେ ଏକ ବ୍ୟାକଅପ୍ ସୃଷ୍ଟି ହୁଏ |

```bash
# API: ଡାଟାବେସ୍ ରପ୍ତାନି
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: ସବୁକିଛି ରପ୍ତାନି (ସମ୍ପୂର୍ଣ୍ଣ ଆର୍କାଇଭ୍)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: ଡାଟାବେସ୍ ଆମଦାନି
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**ଆମଦାନି ବୈଧୀକରଣ:** ଆମଦାନି ହୋଇଥିବା ଫାଇଲ୍‌ର ଅଖଣ୍ଡତା (SQLite pragma ଯାଞ୍ଚ), ଆବଶ୍ୟକ ସାରଣୀ (`provider_connections`, `provider_nodes`, `combos`, `api_keys`) ଏବଂ ଆକାର (ସର୍ବାଧିକ 100MB) ବୈଧୀକରଣ କରାଯାଏ।

**ବ୍ୟବହାର ପରିସ୍ଥିତି:**

- OmniRouteକୁ ଗୋଟିଏ ମେସିନ୍‌ରୁ ଅନ୍ୟ ମେସିନ୍‌କୁ ସ୍ଥାନାନ୍ତର କରନ୍ତୁ
- ବିପର୍ଯ୍ୟୟ ପୁନରୁଦ୍ଧାର ପାଇଁ ବାହ୍ୟ ବ୍ୟାକଅପ୍ ସୃଷ୍ଟି କରନ୍ତୁ
- ଦଳୀୟ ସଦସ୍ୟମାନଙ୍କ ମଧ୍ୟରେ ବିନ୍ୟାସ ଅଂଶୀଦାର କରନ୍ତୁ (ସବୁକିଛି ରପ୍ତାନି → ଆର୍କାଇଭ୍ ଅଂଶୀଦାର କରନ୍ତୁ)

ସହଜ ନେଭିଗେସନ୍ ପାଇଁ ସେଟିଂସ୍ ପୃଷ୍ଠାକୁ **7ଟି ଟ୍ୟାବ୍**‌ରେ ସଂଗଠିତ କରାଯାଇଛି:

| ଟ୍ୟାବ୍             | ବିଷୟବସ୍ତୁ                                                                                                                                                                      |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **ସାଧାରଣ**         | ସିଷ୍ଟମ୍ ଷ୍ଟୋରେଜ୍ ଉପକରଣ, ଡିଫଲ୍ଟ ଆଚରଣ, ଏଣ୍ଡପଏଣ୍ଟ ଟନେଲ୍ ଦୃଶ୍ୟମାନତା                                                                                                                |

| **ସ୍ଥିତିସ୍ଥାପକତା** | ଅନୁରୋଧ କ୍ୟୁ, ସଂଯୋଗ କୁଲ୍‌ଡାଉନ୍, ପ୍ରଦାନକାରୀ ବ୍ରେକର୍ ବିନ୍ୟାସ ଏବଂ କୁଲ୍‌ଡାଉନ୍ ପାଇଁ ଅପେକ୍ଷା ଆଚରଣ                                                                                     |
| **ଉନ୍ନତ**          | ଗ୍ଲୋବାଲ୍ ପ୍ରକ୍ସି ବିନ୍ୟାସ (HTTP/SOCKS5), ପ୍ରତି-ପ୍ରଦାନକାରୀ ପ୍ରକ୍ସି ଓଭର୍‌ରାଇଡ୍                                                                                                    |

ସାଧାରଣ ଟ୍ୟାବ୍‌ରେ ଆଉ କେବଳ ପଠନଯୋଗ୍ୟ ଲଗିଂ ଏବଂ କ୍ୟାଶ୍ ଟିପ୍ପଣୀର ପୁନରାବୃତ୍ତି ହୁଏ ନାହିଁ। ଡାଟାବେସ୍ ଧାରଣ ଏବଂ
ଅପ୍ଟିମାଇଜେସନ୍ ସେଟିଂସ୍ `/api/settings/database` ମାଧ୍ୟମରେ ସଂରକ୍ଷିତ ରହେ; ମାନୁଆଲ୍ କ୍ୟାଶ୍ ସଫା କରିବା ପାଇଁ
`DELETE /api/cache` ବ୍ୟବହୃତ ହୁଏ। ଅନୁରୋଧ ଏବଂ ପ୍ରକ୍ସି ଲଗ୍ ଧାଡ଼ି ସୀମା
`CALL_LOGS_TABLE_MAX_ROWS` ଏବଂ `PROXY_LOGS_TABLE_MAX_ROWS` ଦ୍ୱାରା ନିୟନ୍ତ୍ରିତ ହୁଏ।

| **ବଜେଟ୍**            | ଦୈନିକ/ସାପ୍ତାହିକ/ମାସିକ ବଜେଟ୍ ଏବଂ ରିଅଲ୍-ଟାଇମ୍ ଟ୍ରାକିଂ ସହିତ ପ୍ରତ୍ୟେକ API କି’ ପାଇଁ ଖର୍ଚ୍ଚ ସୀମା ସେଟ୍ କରନ୍ତୁ                       |
| **ମୂଲ୍ୟ ନିର୍ଦ୍ଧାରଣ** | ମଡେଲ୍ ମୂଲ୍ୟ ଏଣ୍ଟ୍ରିଗୁଡ଼ିକୁ ଦେଖନ୍ତୁ ଏବଂ ସମ୍ପାଦନା କରନ୍ତୁ — ପ୍ରତ୍ୟେକ ପ୍ରଦାନକାରୀ ପାଇଁ ପ୍ରତି 1K ଇନ୍‌ପୁଟ୍/ଆଉଟ୍‌ପୁଟ୍ ଟୋକନ୍‌ର ଖର୍ଚ୍ଚ |

```bash
# API: ଏକ ବଜେଟ୍ ସେଟ୍ କରନ୍ତୁ
curl -X POST http://localhost:20128/api/usage/budget \
  -H "Content-Type: application/json" \
  -d '{"keyId": "key-123", "limit": 50.00, "period": "monthly"}'

# API: ବର୍ତ୍ତମାନର ବଜେଟ୍ ସ୍ଥିତି ପାଆନ୍ତୁ
curl http://localhost:20128/api/usage/budget
```

**ଖର୍ଚ୍ଚ ଟ୍ରାକିଂ:** ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ଟୋକନ୍ ବ୍ୟବହାରକୁ ଲଗ୍ କରେ ଏବଂ ମୂଲ୍ୟ ସାରଣୀ ବ୍ୟବହାର କରି ଖର୍ଚ୍ଚ ଗଣନା କରେ। ପ୍ରଦାନକାରୀ, ମଡେଲ୍ ଏବଂ API କି’ ଅନୁସାରେ ବିବରଣୀ **ଡ୍ୟାସବୋର୍ଡ → ବ୍ୟବହାର**‌ରେ ଦେଖନ୍ତୁ।

### ଅଡିଓ ଟ୍ରାନ୍ସକ୍ରିପ୍ସନ୍

OmniRoute, OpenAI-ସୁସଙ୍ଗତ ଏଣ୍ଡପଏଣ୍ଟ ମାଧ୍ୟମରେ ଅଡିଓ ଟ୍ରାନ୍ସକ୍ରିପ୍ସନ୍‌କୁ ସମର୍ଥନ କରେ:

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data

# curl ସହିତ ଉଦାହରଣ
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@audio.mp3" \
  -F "model=openai/whisper-1"
```

`deepgram/nova-3` ହେଉଛି ମୂଳ Deepgram ରୁଟ୍ ଏବଂ ଏଥିପାଇଁ ଏକ Deepgram API କି’ ଆବଶ୍ୟକ।
ଯଦି କେବଳ OpenRouter ବିନ୍ୟାସିତ ହୋଇଛି, ତେବେ `openrouter/deepgram/nova-3` ବ୍ୟବହାର କରନ୍ତୁ।

**ବାଣୀରୁ-ପାଠ୍ୟ (ଟ୍ରାନ୍ସକ୍ରିପ୍ସନ୍)** ପ୍ରଦାନକାରୀ:

### କମ୍ବୋ ସନ୍ତୁଳନ କୌଶଳ

**ଡ୍ୟାସବୋର୍ଡ → କମ୍ବୋ → ସୃଷ୍ଟି/ସମ୍ପାଦନା → କୌଶଳ**‌ରେ ପ୍ରତି-କମ୍ବୋ ସନ୍ତୁଳନ ବିନ୍ୟାସ କରନ୍ତୁ।

| କୌଶଳ                  | ବିବରଣୀ                                                                              |
| --------------------- | ----------------------------------------------------------------------------------- |
| **ରାଉଣ୍ଡ-ରବିନ୍**      | ମଡେଲ୍‌ଗୁଡ଼ିକୁ କ୍ରମାନୁସାରେ ପାଳି କରି ବ୍ୟବହାର କରେ                                      |
| **ପ୍ରାଥମିକତା**        | ସର୍ବଦା ପ୍ରଥମ ମଡେଲ୍‌କୁ ଚେଷ୍ଟା କରେ; କେବଳ ତ୍ରୁଟି ହେଲେ ଫଲ୍‌ବ୍ୟାକ୍ କରେ                   |
| **ଯାଦୃଚ୍ଛିକ**         | ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ପାଇଁ କମ୍ବୋରୁ ଏକ ଯାଦୃଚ୍ଛିକ ମଡେଲ୍ ବାଛେ                                |
| **ଭାରିତ**             | ପ୍ରତି ମଡେଲ୍‌କୁ ନିର୍ଦ୍ଧାରିତ ଭାର ଆଧାରରେ ଆନୁପାତିକ ଭାବେ ରାଉଟ୍ କରେ                       |
| **ସର୍ବନିମ୍ନ-ବ୍ୟବହୃତ** | ସବୁଠାରୁ କମ୍ ସାମ୍ପ୍ରତିକ ଅନୁରୋଧ ଥିବା ମଡେଲ୍‌କୁ ରାଉଟ୍ କରେ (କମ୍ବୋ ମେଟ୍ରିକ୍ସ ବ୍ୟବହାର କରେ) |
| **ଖର୍ଚ୍ଚ-ଅନୁକୂଳିତ**   | ଉପଲବ୍ଧ ସବୁଠାରୁ ଶସ୍ତା ମଡେଲ୍‌କୁ ରାଉଟ୍ କରେ (ମୂଲ୍ୟ ତାଲିକା ବ୍ୟବହାର କରେ)                  |

ଗ୍ଲୋବାଲ୍ କମ୍ବୋ ଡିଫଲ୍ଟଗୁଡ଼ିକୁ **ଡ୍ୟାସ୍‌ବୋର୍ଡ → ସେଟିଂସ୍ → ରାଉଟିଂ → କମ୍ବୋ ଡିଫଲ୍ଟସ୍**‌ରେ ସେଟ୍ କରାଯାଇପାରେ।
ଡିଫଲ୍ଟ ଭାବେ କମ୍ବୋ ଟାର୍ଗେଟ୍ ଟାଇମ୍‌ଆଉଟ୍‌ଗୁଡ଼ିକ ବର୍ତ୍ତମାନର ଅନୁରୋଧ ଟାଇମ୍‌ଆଉଟ୍‌କୁ ଉତ୍ତରାଧିକାରରେ ପାଆନ୍ତି। କେବଳ ଯେତେବେଳେ ପ୍ରତି-ଟାର୍ଗେଟ୍‌ର ଏକ କମ୍ ସୀମା
ଦ୍ରୁତ ଫଲ୍‌ବ୍ୟାକ୍ ସକ୍ରିୟ କରିବା ଉଚିତ, ସେତେବେଳେ କମ୍ବୋ ଡିଫଲ୍ଟ କିମ୍ବା କୌଣସି ବ୍ୟକ୍ତିଗତ କମ୍ବୋରେ **ଟାର୍ଗେଟ୍ ଟାଇମ୍‌ଆଉଟ୍
(ସେକେଣ୍ଡ)** ବ୍ୟବହାର କରନ୍ତୁ।

ଶୂନ୍ୟ-ବିଳମ୍ବ କମ୍ବୋ ଅନୁକୂଳନଗୁଡ଼ିକ ଇଚ୍ଛାଧୀନ। ଏହି ବିଳମ୍ବ ବୈଶିଷ୍ଟ୍ୟଗୁଡ଼ିକୁ ଫଲ୍‌ବ୍ୟାକ୍ ଟାର୍ଗେଟ୍‌ଗୁଡ଼ିକ ସହ ପ୍ରତିଯୋଗିତା କରିବା, TTFT
ଇତିହାସ ଆଧାରରେ ଟାର୍ଗେଟ୍‌ଗୁଡ଼ିକୁ ଏଡ଼ାଇବା କିମ୍ବା ଫଲ୍‌ବ୍ୟାକ୍ ଅନୁରୋଧଗୁଡ଼ିକୁ ସଂକୁଚିତ କରିବାରୁ ରୋକିବା ପାଇଁ **ଶୂନ୍ୟ-ବିଳମ୍ବ ଅନୁକୂଳନ** ଅକ୍ଷମ ରଖନ୍ତୁ; ଏହାକୁ ସକ୍ଷମ କଲେ ବିନ୍ୟାସିତ ହେଜିଂ, ପୂର୍ବାନୁମାନମୂଳକ TTFT
ଏଡ଼ାଇବା ଏବଂ ସକ୍ରିୟ ଫଲ୍‌ବ୍ୟାକ୍ ସଂକୋଚନକୁ କମ୍ ଟେଲ୍
ବିଳମ୍ବ ପାଇଁ ରାଉଟିଂ/ଅନୁରୋଧର ଯଥାର୍ଥତା ସହ ସମନ୍ୱୟ କରିବାକୁ ଅନୁମତି ମିଳେ।

ଯେତେବେଳେ ଅପ୍‌ଷ୍ଟ୍ରିମ୍ ପ୍ରଦାନକାରୀମାନେ କଠୋର
`max_tokens` / `maxOutputTokens` ସୀମା ଆବଶ୍ୟକ କରନ୍ତି, **ରିଜନିଂ ଟୋକନ୍ ବଫର୍** ଅକ୍ଷମ କରନ୍ତୁ। ସକ୍ଷମ ଥିଲେ, କମ୍ବୋ ରାଉଟିଂ କେବଳ ଜଣାଶୁଣା ଆଉଟ୍‌ପୁଟ୍ ସୀମା ଥିବା ମଡେଲ୍‌ଗୁଡ଼ିକ ପାଇଁ ରିଜନିଂ-ମଡେଲ୍
ହେଡ୍‌ରୁମ୍ ଯୋଡ଼େ ଏବଂ ଯେତେବେଳେ ସୁରକ୍ଷିତ ବଫର୍ ମୂଲ୍ୟ ସେହି ସୀମାକୁ ଅତିକ୍ରମ କରିବ, ସେତେବେଳେ କ୍ଲାଏଣ୍ଟ୍ ଟୋକନ୍ ସୀମାକୁ ଅପରିବର୍ତ୍ତିତ ରଖେ। ଯଦି କ୍ଲାଏଣ୍ଟ୍ ସୀମା ପୂର୍ବରୁ ଏକ ଜଣାଶୁଣା ସୀମାଠାରୁ ଅଧିକ ଥାଏ,
ତେବେ ଅପ୍‌ଷ୍ଟ୍ରିମ୍ ଅନୁରୋଧ ପଠାଇବା ପୂର୍ବରୁ OmniRoute ଏହାକୁ ସେହି ସୀମା ପର୍ଯ୍ୟନ୍ତ କମାଇଦିଏ।

## 🤖 ସ୍ୱୟଂଚାଳିତ ରାଉଟିଂ (ଶୂନ୍ୟ-କନଫିଗ୍)

OmniRoute ଏକ **ସ୍କୋର୍-ଆଧାରିତ ସ୍ୱୟଂଚାଳିତ ରାଉଟର୍** ସହିତ ଆସେ, ଯାହା ପ୍ରତ୍ୟେକ ସଂଯୁକ୍ତ ପ୍ରଦାନକାରୀ ମଧ୍ୟରୁ ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ପାଇଁ ସର୍ବୋତ୍ତମ ମଡେଲ୍ ବାଛେ — ରକ୍ଷଣାବେକ୍ଷଣ କରିବାକୁ କୌଣସି କମ୍ବୋ ନାହିଁ। କେବଳ `auto/*` ପ୍ରିଫିକ୍ସଗୁଡ଼ିକ ମଧ୍ୟରୁ ଗୋଟିଏ ସହିତ ଅନୁରୋଧ ପଠାନ୍ତୁ, ଏବଂ OmniRoute ତତ୍କ୍ଷଣାତ୍ ଏକ ଭର୍ଚୁଆଲ୍ କମ୍ବୋ ତିଆରି କରିବ। ଏହା ବିଳମ୍ବ, ଖର୍ଚ୍ଚ, ସଫଳତା ହାର, ପ୍ରସଙ୍ଗ ଉପଯୁକ୍ତତା, କାର୍ଯ୍ୟ ପାଇଁ ମଡେଲ୍‌ର ଉପଯୁକ୍ତତା, ସାମ୍ପ୍ରତିକ ବିଫଳତା, କୋଟା ଏବଂ ସର୍କିଟ୍-ବ୍ରେକର୍ ସ୍ଥିତି ଆଧାରରେ ପ୍ରାର୍ଥୀମାନଙ୍କୁ ସ୍କୋର୍ କରେ।

| ପ୍ରିଫିକ୍ସ      | ଯାହା ପାଇଁ ଅପ୍ଟିମାଇଜ୍ କରେ                                                                       |
| -------------- | ---------------------------------------------------------------------------------------------- |
| `auto`         | ସନ୍ତୁଳିତ ଡିଫଲ୍ଟ (ବିଳମ୍ବ × ଖର୍ଚ୍ଚ × ସଫଳତା ହାର)                                                  |
| `auto/coding`  | କୋଡିଂ କାର୍ଯ୍ୟ: Claude, GPT-5, GLM, Kimi, Qwen Coder, DeepSeek କୋଡର୍‌ଗୁଡ଼ିକୁ ପ୍ରାଧାନ୍ୟ ଦିଏ      |
| `auto/cheap`   | ସର୍ବନିମ୍ନ $/ଟୋକେନ୍, ଅଧିକ ବିଳମ୍ବ ଗ୍ରହଣ କରେ                                                      |
| `auto/fast`    | ସର୍ବନିମ୍ନ ବିଳମ୍ବ, ଖର୍ଚ୍ଚକୁ ଅଣଦେଖା କରେ                                                          |
| `auto/offline` | କେବଳ ସ୍ଥାନୀୟ ପ୍ରଦାନକାରୀ (Ollama, vLLM, llama.cpp) — ଏୟାର୍-ଗ୍ୟାପ୍ଡ ସେଟଅପ୍ ପାଇଁ ଉପଯୋଗୀ           |
| `auto/smart`   | ଯୁକ୍ତିକରଣ ଗୁଣବତ୍ତାକୁ ପ୍ରଥମ ପ୍ରାଥମିକତା (Opus, GPT-5 xhigh, R1, GLM 5.1 reasoning)               |
| `auto/lkgp`    | "ଶେଷ ଜଣାଶୁଣା ଭଲ ପ୍ରଦାନକାରୀ" — ଶେଷ ସଫଳ ପ୍ରଦାନକାରୀକୁ ପିନ୍ କରେ, ତା’ପରେ ନିୟମଗୁଡ଼ିକୁ ଫଲ୍‌ବ୍ୟାକ୍ କରେ |

```bash
    "model": "auto/coding",

    "stream": true
  }'
```

## 🔌 MCP ଏବଂ A2A ଏକୀକରଣ

OmniRoute ଉଭୟ ଏକ **MCP ସର୍ଭର୍** (Model Context Protocol) ଏବଂ ଏକ **A2A ସର୍ଭର୍** (Agent-to-Agent JSON-RPC 2.0) ଅଟେ। ଯେକୌଣସି MCP-ସୁସଙ୍ଗତ IDE କିମ୍ବା ଏଜେଣ୍ଟ ହୋଷ୍ଟ ସିଧାସଳଖ OmniRoute ଟୁଲ୍‌ଗୁଡ଼ିକୁ କଲ୍ କରିପାରିବ — କୌଣସି ଅତିରିକ୍ତ ରାପର୍ ଆବଶ୍ୟକ ନାହିଁ।

### MCP ପରିବହନ

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **ଷ୍ଟ୍ରିମ୍‌ଯୋଗ୍ୟ HTTP**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (stdioକୁ ପସନ୍ଦ କରୁଥିବା IDE ପ୍ଲଗଇନ୍‌ଗୁଡ଼ିକ ପାଇଁ)

### Claude Desktop ସଂଯୋଗ କରନ୍ତୁ

`~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) କିମ୍ବା Windows/Linuxରେ ଏହାର ସମତୁଲ୍ୟ ଫାଇଲ୍‌କୁ ସମ୍ପାଦନା କରନ୍ତୁ:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Cursor / Continue / VS Code MCP ସଂଯୋଗ କରନ୍ତୁ

SSE URL `http://localhost:20128/api/mcp/sse` ଏବଂ **Dashboard → API Keys**ରେ ସୃଷ୍ଟି ହୋଇଥିବା ଏକ Bearer API କୀ ବ୍ୟବହାର କରନ୍ତୁ।

### ସ୍କୋପ୍‌ଗୁଡ଼ିକ

MCP ବର୍ତ୍ତମାନ 32ଟି ନାମିତ ସ୍କୋପ୍ ନିର୍ଦ୍ଧାରଣ କରେ। ପ୍ରତ୍ୟେକ Bearer କୀକୁ ନିର୍ଦ୍ଦିଷ୍ଟ ସ୍କୋପ୍‌ଗୁଡ଼ିକ ମଧ୍ୟରେ ସୀମିତ କରାଯାଇପାରିବ — ପ୍ରାମାଣିକ ସ୍କୋପ୍ ଏବଂ ଟୁଲ୍ ତାଲିକା ପାଇଁ [MCP-SERVER.md](../frameworks/MCP-SERVER.md) ଏବଂ JSON-RPC ସ୍କିମା ପାଇଁ [A2A-SERVER.md](../frameworks/A2A-SERVER.md) ଦେଖନ୍ତୁ।

## 💾 ମେମୋରି ସିଷ୍ଟମ୍

OmniRoute ହାଇବ୍ରିଡ୍ ପୁନରୁଦ୍ଧାର ସହିତ **ଦୀର୍ଘକାଳୀନ କଥୋପକଥନ ମେମୋରି**କୁ ସ୍ଥାୟୀ ଭାବରେ ସଂରକ୍ଷଣ କରେ:

- ପୂର୍ବବର୍ତ୍ତୀ ବାର୍ତ୍ତାଳାପରେ କୀୱାର୍ଡ ସନ୍ଧାନ ପାଇଁ **SQLite FTS5**
- ଅର୍ଥଗତ ସ୍ମରଣ ପାଇଁ **Qdrant vector store** (ଇଚ୍ଛାଧୀନ)
- **ସ୍ୱୟଂଚାଳିତ ତଥ୍ୟ ନିଷ୍କାସନ** — ପ୍ରତ୍ୟେକ ସେସନ୍ ପରେ ଏଣ୍ଟିଟି, ପସନ୍ଦ ଏବଂ ନିଷ୍ପତ୍ତିଗୁଡ଼ିକର ସାରାଂଶ ପ୍ରସ୍ତୁତ କରାଯାଇ `memory_facts` ଟେବୁଲ୍‌ରେ ସଂରକ୍ଷଣ କରାଯାଏ
- ମେମୋରିଗୁଡ଼ିକ ପ୍ରତ୍ୟେକ API କୀ ଏବଂ ପ୍ରତ୍ୟେକ ସେସନ୍ ଅନୁଯାୟୀ ସ୍କୋପ୍ କରାଯାଏ

**Dashboard → Memory**ରେ ମେମୋରିଗୁଡ଼ିକୁ ପରିଚାଳନା କରନ୍ତୁ (ସନ୍ଧାନ, ସମ୍ପାଦନା, ରପ୍ତାନି, ସମ୍ପୂର୍ଣ୍ଣ ବିଲୋପ)। HTTP ଇଣ୍ଟରଫେସ୍ (`/api/memory/*`) ଏଜେଣ୍ଟମାନଙ୍କୁ ପ୍ରୋଗ୍ରାମାଟିକ୍ ଭାବରେ ତଥ୍ୟ ପଠାଇବା ଏବଂ କ୍ୱେରି କରିବାର ସୁବିଧା ଦିଏ — [MEMORY.md](../frameworks/MEMORY.md) ଦେଖନ୍ତୁ।

## 🔔 ୱେବ୍‌ହୁକ୍‌ଗୁଡ଼ିକ

ରିଅଲ୍-ଟାଇମ୍ ମନିଟରିଂ ଏବଂ ସ୍ୱୟଂଚାଳନ ପାଇଁ OmniRoute ଇଭେଣ୍ଟଗୁଡ଼ିକୁ ସବ୍‌ସ୍କ୍ରାଇବ୍ କରନ୍ତୁ।

- ଟାର୍ଗେଟ୍ URL ଏବଂ HMAC ସାଇନିଂ ସିକ୍ରେଟ୍ ସହିତ **Dashboard → Webhooks**ରେ ଏକ ୱେବ୍‌ହୁକ୍ ସୃଷ୍ଟି କରନ୍ତୁ
- ଉପଲବ୍ଧ ଇଭେଣ୍ଟଗୁଡ଼ିକ: `request.completed`, `request.failed`, `provider.unavailable`, `budget.exceeded`, `combo.switched`, `circuit_breaker.opened`, `circuit_breaker.closed`
- ଯାଞ୍ଚ ପାଇଁ ପ୍ରତ୍ୟେକ ପେଲୋଡ୍‌ରେ `X-OmniRoute-Signature` (HMAC-SHA256) ଅନ୍ତର୍ଭୁକ୍ତ ଥାଏ
- ପୁନଃପ୍ରୟାସ: ଏକ୍ସପୋନେନ୍ସିଆଲ୍ ବ୍ୟାକଅଫ୍ ସହିତ 3ଟି ପ୍ରୟାସ, ତା’ପରେ ଡେଡ୍-ଲେଟର୍ କ୍ୟୁ

ସମ୍ପୂର୍ଣ୍ଣ ସ୍କିମା [WEBHOOKS.md](../frameworks/WEBHOOKS.md)ରେ ଉପଲବ୍ଧ।

## 🛠️ ପ୍ରୋଗ୍ରାମାଟିକ୍ ପରିଚାଳନା

ଆପଣ **`manage` ସ୍କୋପ୍ ଥିବା Bearer କୀ** ବ୍ୟବହାର କରି HTTP ମାଧ୍ୟମରେ ପ୍ରତ୍ୟେକ OmniRoute ରିସୋର୍ସ (ପ୍ରଦାତା, କମ୍ବୋ, କୀ, ସେଟିଂସ୍) ପରିଚାଳନା କରିପାରିବେ।

**Dashboard → API Keys → New Key → Scope: manage**ରେ କୀ ସୃଷ୍ଟି କରନ୍ତୁ, ତା’ପରେ:

```bash
# ପ୍ରଦାତାମାନଙ୍କର ତାଲିକା ଦେଖାନ୍ତୁ
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# ଏକ ପ୍ରଦାତା ସଂଯୋଗ ଯୋଗ କରନ୍ତୁ
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# ଏକ କମ୍ବୋ ସୃଷ୍ଟି କରନ୍ତୁ
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# API କୀଗୁଡ଼ିକର ତାଲିକା ଦେଖାନ୍ତୁ/ସୃଷ୍ଟି କରନ୍ତୁ
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

ସମ୍ପୂର୍ଣ୍ଣ ଏଣ୍ଡପଏଣ୍ଟ କ୍ୟାଟାଲଗ୍ ଏବଂ ଅନୁରୋଧ/ପ୍ରତିକ୍ରିୟା ସ୍କିମା ପାଇଁ [API_REFERENCE.md](../reference/API_REFERENCE.md) ଦେଖନ୍ତୁ।

## 💻 ଆଭ୍ୟନ୍ତରୀଣ CLI

ସେଟଅପ୍, ନିଦାନ ଏବଂ ରନ୍‌ଟାଇମ୍ ନିୟନ୍ତ୍ରଣ ପାଇଁ OmniRoute ଏକ ଆଭ୍ୟନ୍ତରୀଣ CLI (`omniroute …`) ସହିତ ଆସେ। ଏହା **ଡ୍ୟାସ୍‌ବୋର୍ଡରେ ଥିବା "CLI ଟୁଲ୍ସ" ପୃଷ୍ଠାଠାରୁ ଅଲଗା**, ଯାହା ତୃତୀୟ-ପକ୍ଷ CLIଗୁଡ଼ିକୁ (Claude Code, Cursor, Codex, Cline, …) ବିନ୍ୟାସ କରେ, ଯାହାଦ୍ୱାରା ସେଗୁଡ଼ିକ OmniRoute ସହିତ ଯୋଗାଯୋଗ କରିପାରିବେ।

```bash
omniroute setup                    # ଇଣ୍ଟରାକ୍ଟିଭ୍ ୱିଜାର୍ଡ (ପାସ୍‌ୱାର୍ଡ, ପ୍ରଦାନକାରୀ, କମ୍ବୋ)
omniroute setup --non-interactive  # CI-ଅନୁକୂଳ
omniroute doctor                   # ସ୍ୱାସ୍ଥ୍ୟ ନିଦାନ (ଡାଟା ଡିରେକ୍ଟୋରୀ, DB, ପ୍ରଦାନକାରୀ, ପୋର୍ଟ)
omniroute providers available      # ସମର୍ଥିତ ପ୍ରଦାନକାରୀଗୁଡ଼ିକର ତାଲିକା
omniroute providers list           # ବିନ୍ୟାସିତ ସଂଯୋଗଗୁଡ଼ିକର ତାଲିକା
omniroute providers test <id>      # ଏକ ପ୍ରଦାନକାରୀ ସଂଯୋଗର ଲାଇଭ୍ ପରୀକ୍ଷା
omniroute combos list              # କମ୍ବୋଗୁଡ଼ିକର ତାଲିକା
omniroute combos switch <name>     # ଡିଫଲ୍ଟ କମ୍ବୋ ସେଟ୍ କରନ୍ତୁ
omniroute models                   # ଉପଲବ୍ଧ ମଡେଲ୍‌ଗୁଡ଼ିକର ତାଲିକା (--json, --search)
omniroute keys add | list | remove # ଟର୍ମିନାଲ୍‌ରୁ API କୀଗୁଡ଼ିକ ପରିଚାଳନା କରନ୍ତୁ
omniroute backup                   # ବିନ୍ୟାସ + DBର ସ୍ନାପ୍‌ଶଟ୍
omniroute restore [<timestamp>]    # ଏକ ସ୍ନାପ୍‌ଶଟ୍‌ରୁ ପୁନରୁଦ୍ଧାର କରନ୍ତୁ
omniroute health                   # ବିସ୍ତୃତ ସ୍ୱାସ୍ଥ୍ୟ ସୂଚନା (ବ୍ରେକର୍, କ୍ୟାଶ୍, ମେମୋରୀ)
omniroute quota                    # ପ୍ରଦାନକାରୀ କୋଟା ବ୍ୟବହାର
omniroute mcp status               # MCP ସର୍ଭର ସ୍ଥିତି
omniroute a2a status               # A2A ସର୍ଭର ସ୍ଥିତି
omniroute tunnel list|create|stop  # Cloudflare/Tailscale/ngrok ଟନେଲ୍‌ଗୁଡ଼ିକ
omniroute reset-password           # ଆଡ୍‌ମିନ୍ ପାସ୍‌ୱାର୍ଡ ରିସେଟ୍ କରନ୍ତୁ
omniroute --mcp                    # stdio ମାଧ୍ୟମରେ MCP ସର୍ଭର ଆରମ୍ଭ କରନ୍ତୁ
omniroute --port 3000              # ଏକ କଷ୍ଟମ୍ ପୋର୍ଟରେ ସର୍ଭର ଆରମ୍ଭ କରନ୍ତୁ
```

ପରାମର୍ଶ: ଅସ୍ୱାସ୍ଥ୍ୟକର ପ୍ରଦାନକାରୀ ସଂଯୋଗଗୁଡ଼ିକ ବିଷୟରେ ସତର୍କତା ପାଇବାକୁ ଆପଣଙ୍କ ନିରୀକ୍ଷଣ ଟୁଲ୍ ସହିତ `omniroute doctor --json` ବ୍ୟବହାର କରନ୍ତୁ।

## 🖥️ ଡେସ୍କଟପ୍ ଆପ୍ଲିକେସନ୍ (Electron)

OmniRoute Windows, macOS ଏବଂ Linux ପାଇଁ ଏକ ନେଟିଭ୍ ଡେସ୍କଟପ୍ ଆପ୍ଲିକେସନ୍ ଭାବେ ଉପଲବ୍ଧ।

### ସଂସ୍ଥାପନ

```bash
# electron ଡିରେକ୍ଟୋରୀରୁ:
cd electron
npm install

# ଡେଭଲପ୍‌ମେଣ୍ଟ ମୋଡ୍ (ଚାଲୁଥିବା Next.js ଡେଭ୍ ସର୍ଭର ସହିତ ସଂଯୋଗ କରେ):
npm run dev

# ପ୍ରଡକ୍ସନ୍ ମୋଡ୍ (ସ୍ୱତନ୍ତ୍ର ବିଲ୍ଡ ବ୍ୟବହାର କରେ):
npm start
```

### ଇନ୍‌ଷ୍ଟଲର୍ ନିର୍ମାଣ

```bash
cd electron
npm run build          # ବର୍ତ୍ତମାନର ପ୍ଲାଟଫର୍ମ
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg ୟୁନିଭର୍ସାଲ୍)
npm run build:linux    # Linux (.AppImage)
```

ଆଉଟ୍‌ପୁଟ୍ → `electron/dist-electron/`
