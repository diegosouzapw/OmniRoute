**ଉତ୍ସଗୁଡ଼ିକ:**

- `open-sse/services/usage.ts` (~70KB) — ମୁଖ୍ୟ ବ୍ୟବହାର ଟ୍ରାକିଂ
- `src/lib/usageAnalytics.ts` (~10KB) — ଡ୍ୟାସବୋର୍ଡ ପାଇଁ ସମାହାର
- `src/lib/db/quotaSnapshots.ts` — ଐତିହାସିକ କୋଟା ତଥ୍ୟ
- `src/lib/db/usage*.ts` — ବ୍ୟବହାର-ସମ୍ବନ୍ଧୀୟ ଏକାଧିକ DB ମଡ୍ୟୁଲ୍

## ସାରାଂଶ

OmniRoute ମାଧ୍ୟମରେ ପ୍ରବାହିତ ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ଏକ **ବ୍ୟବହାର ରେକର୍ଡ** ସୃଷ୍ଟି କରେ, ଯେଉଁଥିରେ ନିମ୍ନଲିଖିତ ତଥ୍ୟ ସଂଗୃହୀତ ହୁଏ:

- **ପରିଚୟ**: କେଉଁ API key, ପ୍ରଦାତା, ମଡେଲ୍, କମ୍ବୋ
- **ଟୋକନ୍ଗୁଡ଼ିକ**: ପ୍ରମ୍ପ୍ଟ ଟୋକନ୍, ସମାପ୍ତି ଟୋକନ୍, କ୍ୟାଶ୍ ହୋଇଥିବା ଟୋକନ୍, ସର୍ବମୋଟ
- **ଖର୍ଚ୍ଚ**: USD ପରିମାଣ (ମୂଲ୍ୟ ତଥ୍ୟରୁ ଗଣନା କରାଯାଇଥାଏ)
- **ସମୟ**: ବିଳମ୍ବତା, ଆରମ୍ଭ/ଶେଷ ଟାଇମ୍ଷ୍ଟାମ୍ପ
- **ସ୍ଥିତି**: ସଫଳତା, ତ୍ରୁଟି, ହାର-ସୀମିତ ଇତ୍ୟାଦି

ଏହି ରେକର୍ଡଗୁଡ଼ିକୁ **ବିଶ୍ଳେଷଣ ତଥ୍ୟ** ଭାବରେ ସମାହାର କରାଯାଏ, **କୋଟା ସ୍ନାପ୍ଶଟ୍** ଭାବରେ ସ୍ଥାୟୀ ଭାବେ ସଂରକ୍ଷଣ କରାଯାଏ ଏବଂ **ପ୍ରତି-key ବଜେଟ୍ ସୀମା** ଲାଗୁ କରିବାରେ ବ୍ୟବହୃତ ହୁଏ।

```
ଅନୁରୋଧ ──▶ chatCore ──▶ usage.record() ──▶ SQLite
                                  │
                          ┌───────┼───────┐
                          ▼       ▼       ▼
                    ବିଶ୍ଳେଷଣ   କୋଟା    ବିଲିଂ
                    (ଡ୍ୟାସବୋର୍ଡ) (ଲାଗୁ) (ରପ୍ତାନି)
```

## କେଉଁ ତଥ୍ୟ ରେକର୍ଡ କରାଯାଏ

`usage.ts` ସେବା ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ପାଇଁ ଏକ **ବ୍ୟବହାର ଘଟଣା** ସଂଗୃହୀତ କରେ:

| ଫିଲ୍ଡ              | ପ୍ରକାର  | ଉତ୍ସ                                                       |
| ------------------ | ------- | ---------------------------------------------------------- |
| `id`               | string  | ରେକର୍ଡ କରିବା ସମୟରେ ସୃଷ୍ଟ UUID                              |
| `apiKeyId`         | string  | ଅନୁରୋଧ ଆରମ୍ଭ କରିଥିବା API key                               |
| `provider`         | string  | ପ୍ରଦାତା ID (openai, anthropic ଇତ୍ୟାଦି)                     |
| `model`            | string  | ମଡେଲ୍ ID (gpt-5, claude-opus-4-6 ଇତ୍ୟାଦି)                  |
| `comboId`          | string? | ଏକ କମ୍ବୋ ମାଧ୍ୟମରେ ରାଉଟ୍ ହୋଇଥିଲେ କମ୍ବୋ ID                   |
| `promptTokens`     | number  | ଅପ୍ଷ୍ଟ୍ରିମ୍ ପ୍ରତିକ୍ରିୟାରୁ                                  |
| `completionTokens` | number  | ଅପ୍ଷ୍ଟ୍ରିମ୍ ପ୍ରତିକ୍ରିୟାରୁ                                  |
| `cachedTokens`     | number  | କ୍ୟାଶ୍ ହିଟ୍ ଟୋକନ୍ (Anthropic ପ୍ରମ୍ପ୍ଟ କ୍ୟାଶିଂ ଇତ୍ୟାଦି)     |
| `totalTokens`      | number  | ପ୍ରମ୍ପ୍ଟ + ସମାପ୍ତି                                         |
| `costUsd`          | number  | ମୂଲ୍ୟ ତଥ୍ୟରୁ ଗଣନା କରାଯାଇଥାଏ                                |
| `latencyMs`        | number  | ଆରମ୍ଭରୁ ଶେଷ ପର୍ଯ୍ୟନ୍ତ ଅନୁରୋଧର ଅବଧି                         |
| `status`           | enum    | `success`, `error`, `rate_limited`, `timeout`, `cancelled` |
| `errorClass`       | string? | ସ୍ଥିତି != success ହେଲେ ତ୍ରୁଟି ଶ୍ରେଣୀ                       |
| `timestamp`        | string  | ISO 8601 UTC                                               |
| `metadata`         | object  | ପ୍ଲଗ୍ଇନ୍ ଦ୍ୱାରା ଯୋଡ଼ାଯାଇଥିବା କଷ୍ଟମ୍ ତଥ୍ୟ                   |

### ଟୋକନ୍ଗୁଡ଼ିକ କେଉଁଠାରୁ ଆସେ

ଟୋକନ୍ଗୁଡ଼ିକୁ **ପ୍ରତିକ୍ରିୟା ହ୍ୟାଣ୍ଡଲର୍** ମଧ୍ୟରେ ଅପ୍ଷ୍ଟ୍ରିମ୍ ପ୍ରଦାତାଙ୍କ ପ୍ରତିକ୍ରିୟାରୁ ବାହାର କରାଯାଏ:

```ts
// open-sse/handlers/chatCore.ts ରୁ
const response = await providerExecutor.execute(provider, request);
const usage = response.usage || {
  prompt_tokens: 0,
  completion_tokens: 0,
  cached_tokens: 0,
};
```

ଯେଉଁ ପ୍ରଦାତାମାନେ ବ୍ୟବହାର ତଥ୍ୟ ଫେରାନ୍ତି ନାହିଁ (କିଛି ୱେବ୍-କୁକି ପ୍ରଦାତା), ସେମାନଙ୍କ ପାଇଁ OmniRoute `~4 chars per token` ଅନୁମାନମୂଳକ ନିୟମ ବ୍ୟବହାର କରି ଟୋକନ୍ର **ଆକଳନ** କରେ (`open-sse/services/autoCombo/pipelineRouter.ts` ଦେଖନ୍ତୁ)।

### କ୍ୟାଶ୍ ହୋଇଥିବା ଟୋକନ୍ଗୁଡ଼ିକ

OmniRoute `cached_tokens`କୁ `prompt_tokens`ଠାରୁ ପୃଥକ ଭାବେ ଟ୍ରାକ୍ କରେ, କାରଣ:

- Anthropic ପ୍ରମ୍ପ୍ଟ କ୍ୟାଶିଂ କ୍ୟାଶ୍ ହୋଇଥିବା ଟୋକନ୍ ପାଇଁ ହ୍ରାସପ୍ରାପ୍ତ ହାର (ସାଧାରଣ ହାରର 10%) ନିଏ
- କିଛି ପ୍ରଦାତା `cache_read_input_tokens` ଫେରାନ୍ତି, ଯାହାର ମୂଲ୍ୟ ଭିନ୍ନ ଭାବରେ ନିର୍ଦ୍ଧାରଣ କରାଯିବା ଉଚିତ
- ବିଶ୍ଳେଷଣ ତଥ୍ୟ **କ୍ୟାଶ୍ ହିଟ୍ ହାର** = `cached_tokens / prompt_tokens` ଦେଖାଇପାରେ

## ଖର୍ଚ୍ଚ ଗଣନା

LiteLLMରୁ ସିଙ୍କ୍ ହୋଇଥିବା **ମୂଲ୍ୟ ତଥ୍ୟ** (`src/lib/pricingSync.ts`) ଆଧାରରେ ଖର୍ଚ୍ଚ ଗଣନା କରାଯାଏ:

| ମଡେଲ୍             | ଇନ୍ପୁଟ୍ $/1M | ଆଉଟ୍ପୁଟ୍ $/1M | କ୍ୟାଶ୍ଡ୍ $/1M |
| ----------------- | ------------ | ------------- | ------------- |
| gpt-5             | $2.50        | $10.00        | —             |
| claude-opus-4-6   | $15.00       | $75.00        | $1.50         |
| claude-sonnet-4-5 | $3.00        | $15.00        | $0.30         |
| gemini-2.5-pro    | $1.25        | $10.00        | —             |

ଖର୍ଚ୍ଚ ସୂତ୍ର (`src/lib/usage/costCalculator.ts`):

```ts
cost =
  (prompt_tokens - cached_tokens) * input_price +
  cached_tokens * cached_price +
  completion_tokens * output_price;
```

> **ପ୍ରମ୍ପ୍ଟ୍ରୁ କ୍ୟାଶ୍ଡ୍ ଅଂଶକୁ କାହିଁକି ବିୟୋଗ କରାଯାଏ?** କ୍ୟାଶ୍ଡ୍ ଅଂଶର ମୂଲ୍ୟ ପୃଥକ୍ ଭାବେ ଗଣନା କରାଯାଏ; ସମ୍ପୂର୍ଣ୍ଣ ପ୍ରମ୍ପ୍ଟ୍ ଉପରେ ଇନ୍ପୁଟ୍ ମୂଲ୍ୟ ଲାଗୁ କଲେ ଅତିରିକ୍ତ ଗଣନା ହେବ।

### ମୂଲ୍ୟ ସିଙ୍କ୍

`/api/pricing/sync` ଏଣ୍ଡପଏଣ୍ଟ୍ ମାଧ୍ୟମରେ LiteLLMରୁ ମୂଲ୍ୟ ତଥ୍ୟ ସ୍ୱୟଂଚାଳିତ ଭାବେ ସିଙ୍କ୍ ହୁଏ (ଏହା ବିଲ୍ଟ-ଇନ୍ cron ଟାସ୍କ୍ ଦ୍ୱାରା ଟ୍ରିଗର୍ ହୁଏ, ବ୍ୟବହାରକାରୀଙ୍କ ପାଇଁ ଉପଲବ୍ଧ env var ଦ୍ୱାରା ନୁହେଁ):

```bash
# ମାନୁଆଲ୍ ଟ୍ରିଗର୍
curl -X POST http://localhost:20128/api/pricing/sync
```

ଯେଉଁ ମଡେଲ୍ଗୁଡ଼ିକ ପାଇଁ ମୂଲ୍ୟ ତଥ୍ୟ ଉପଲବ୍ଧ ନାହିଁ, ସେଗୁଡ଼ିକ ପାଇଁ OmniRoute ଆଭ୍ୟନ୍ତରୀଣ ହାରାହାରି ଦର (LiteLLMର ମୂଲ୍ୟ ତଥ୍ୟରୁ ଉତ୍ସାହରିତ) ବ୍ୟବହାର କରି **ଖର୍ଚ୍ଚ ଆକଳନ** କରେ।

## ତାରିଖ ପରିସର ସମାହାର

`usageAnalytics.ts` ମଡ୍ୟୁଲ୍ କଞ୍ଚା ବ୍ୟବହାର ତଥ୍ୟରୁ ଡ୍ୟାସ୍ବୋର୍ଡ୍ ୱିଜେଟ୍ଗୁଡ଼ିକ ଗଣନା କରେ। ଏହା 7ଟି ସମୟ ପରିସର ସମର୍ଥନ କରେ:

| ପରିସର    | ସମୟସୀମା                           | ବ୍ୟବହାର କ୍ଷେତ୍ର                   |
| -------- | --------------------------------- | --------------------------------- |
| `1d`     | ଗତ 24 ଘଣ୍ଟା                       | ଘଣ୍ଟାଭିତ୍ତିକ ଖର୍ଚ୍ଚ ବୃଦ୍ଧି ଚିହ୍ନଟ |
| `7d`     | ଗତ 7 ଦିନ                          | ସାପ୍ତାହିକ ସମୀକ୍ଷା                 |
| `30d`    | ଗତ 30 ଦିନ                         | ମାସିକ ବିଲିଂ                       |
| `90d`    | ଗତ 90 ଦିନ                         | ତ୍ରୈମାସିକ ବିଶ୍ଳେଷଣ                |
| `ytd`    | ଚଳିତ ବର୍ଷର ଜାନୁଆରୀ 1ରୁ            | ବାର୍ଷିକ ବଜେଟ୍ ଟ୍ରାକିଂ             |
| `all`    | ସମସ୍ତ ସମୟ                         | ଆଜୀବନ ପରିସଂଖ୍ୟାନ                  |
| `custom` | ବ୍ୟବହାରକାରୀ-ନିର୍ଦ୍ଧାରିତ ଆରମ୍ଭ/ଶେଷ | ଅଡିଟ୍, ଆବଶ୍ୟକତା-ଆଧାରିତ କ୍ୱେରୀ     |

### ଗଣନା କରାଯାଉଥିବା ଡ୍ୟାସ୍ବୋର୍ଡ୍ ୱିଜେଟ୍ଗୁଡ଼ିକ

ଯେକୌଣସି ତାରିଖ ପରିସର ପାଇଁ, ଆନାଲିଟିକ୍ସ ସ୍ତର ନିମ୍ନଲିଖିତଗୁଡ଼ିକ ଗଣନା କରେ:

| ୱିଜେଟ୍                     | ବର୍ଣ୍ଣନା                                              |
| -------------------------- | ----------------------------------------------------- |
| **ସାରାଂଶ କାର୍ଡ୍ଗୁଡ଼ିକ**    | ମୋଟ ଅନୁରୋଧ, ମୋଟ ଖର୍ଚ୍ଚ, ମୋଟ ଟୋକନ୍, ସଫଳତା ହାର          |
| **ଦୈନିକ ପ୍ରବଣତା ଚାର୍ଟ୍**   | ପ୍ରତିଦିନର ଖର୍ଚ୍ଚ + ଟୋକନ୍, ମଡେଲ୍ ଅନୁସାରେ ସ୍ତୂପୀକୃତ     |
| **କାର୍ଯ୍ୟକଳାପ ହିଟ୍ମ୍ୟାପ୍** | ଦିନର ଘଣ୍ଟା × ସପ୍ତାହର ଦିନ ଗ୍ରିଡ୍, ରଙ୍ଗ = ଅନୁରୋଧ ସଂଖ୍ୟା |
| **ମଡେଲ୍ ବିଭାଜନ**           | ମଡେଲ୍ ଅନୁସାରେ ଖର୍ଚ୍ଚର ପାଇ ଚାର୍ଟ୍                      |
| **ପ୍ରଦାନକାରୀ ବିଭାଜନ**      | ପ୍ରଦାନକାରୀ ଅନୁସାରେ ଅନୁରୋଧର ବାର୍ ଚାର୍ଟ୍                |
| **ଶୀର୍ଷ API କୀଗୁଡ଼ିକ**     | ଖର୍ଚ୍ଚ ଅନୁସାରେ ଶୀର୍ଷ 10ଟି କୀର ସାରଣୀ                   |
| **ତ୍ରୁଟି ବିଶ୍ଳେଷଣ**        | ସମୟ ସହିତ ତ୍ରୁଟି ହାର, ଶୀର୍ଷ ତ୍ରୁଟି ଶ୍ରେଣୀଗୁଡ଼ିକ        |

### ପ୍ରୋଗ୍ରାମାଟିକ୍ ଆକ୍ସେସ୍

````ts
import { computeAnalytics } from "@/lib/usageAnalytics";

const analytics = await computeAnalytics(
  history,              // ବ୍ୟବହାର ଇତିହାସ ରେକର୍ଡ୍ଗୁଡ଼ିକ
  "7d",                 // ସମୟ ପରିସର: "1d" | "7d" | "30d" | "90d" | "ytd" | "all" | "custom"
  connectionMap,        // ପ୍ରଦାନକାରୀ ସଂଯୋଗ ମ୍ୟାପ୍ (connectionId → ଆକାଉଣ୍ଟ୍ ନାମ)
  {
    startDate: "2025-01-01",  // ଇଚ୍ଛାଧୀନ: "custom" ପରିସର ପାଇଁ
    endDate: "2025-06-01",   // ଇଚ୍ଛାଧୀନ: "custom" ପରିସର ପାଇଁ
  }
);

console.log(analytics.summary.totalCost);   // 12.34 (ସେଣ୍ଟ୍)
console.log(analytics.byModel[0]);           // { model, cost, requests, promptTokens, completionTokens }

## କୋଟା ପ୍ରବର୍ତ୍ତନ

ପ୍ରତ୍ୟେକ API କୀ ପାଇଁ କୋଟା ଦୁଇଟି ସ୍ଥାନରେ ପ୍ରବର୍ତ୍ତନ କରାଯାଏ:

1. **ସଫ୍ଟ ସୀମା** (`quotaWarnAt`): ବ୍ୟବହାର ସୀମା ଅତିକ୍ରମ କଲେ ଡ୍ୟାସ୍ବୋର୍ଡ ଚେତାବନୀ
2. **ହାର୍ଡ ସୀମା** (`quotaLimit`): ସୀମା ଅତିକ୍ରମ କଲେ ଅନୁରୋଧ HTTP 429 ସହିତ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଏ

### ବିନ୍ୟାସ

```ts
// ପ୍ରତ୍ୟେକ API କୀ ପାଇଁ
await updateApiKey(keyId, {
  quotaWarnAt: 5_00,    // $5.00 — ଚେତାବନୀ ଦେଖାନ୍ତୁ
  quotaLimit: 10_00,    // $10.00 — ସମ୍ପୂର୍ଣ୍ଣ ଭାବେ ବନ୍ଦ କରନ୍ତୁ
  quotaWindow: "month", // "day" | "week" | "month" | "all"
});
````

### ପ୍ରବର୍ତ୍ତନ ପ୍ରବାହ

```
ଅନୁରୋଧ ──▶ quotaCheck()
              │
              ├── ସୀମା ଭିତରେ?  ──▶ ଅନୁମତି ଦିଅନ୍ତୁ
              │
              └── ସୀମା ଅତିକ୍ରମ କରିଛି?  ──▶ 429 ଅତ୍ୟଧିକ ଅନୁରୋଧ
                                   Retry-After ହେଡର୍ ସହିତ
```

### କୋଟା ସ୍ନାପ୍ଶଟ୍

ପ୍ରବଣତା ବିଶ୍ଳେଷଣ ପାଇଁ `quotaSnapshots` ଟେବୁଲ୍ **ଐତିହାସିକ କୋଟା ସ୍ଥିତି** ସଂରକ୍ଷଣ କରେ:

| ଫିଲ୍ଡ | ବର୍ଣ୍ଣନା |
| ----------- | -------------------------------- | ------ | ------- |
| `apiKeyId` | ଟ୍ରାକ୍ କରାଯାଉଥିବା କୀ |
| `window` | "day" | "week" | "month" |
| `used` | ଏହି ସମୟସୀମାରେ ବ୍ୟବହୃତ ମୂଲ୍ୟ (ସେଣ୍ଟ୍) |
| `limit` | ସୀମା (ସେଣ୍ଟ୍) |
| `resetAt` | ସମୟସୀମା କେବେ ରିସେଟ୍ ହୁଏ |
| `createdAt` | ସ୍ନାପ୍ଶଟ୍ କେବେ ନିଆଯାଇଥିଲା |

> 0 ମୂଲ୍ୟ ବ୍ୟବହାର କରୁଥିବା **ପ୍ରତ୍ୟେକ ଅନୁରୋଧରେ** ସ୍ନାପ୍ଶଟ୍ ନିଆଯାଏ ଏବଂ ଏଗୁଡ଼ିକୁ ନିମ୍ନଲିଖିତ କାମ ପାଇଁ ବ୍ୟବହାର କରାଯାଏ:

- ଡ୍ୟାସ୍ବୋର୍ଡରେ କୋଟା ପ୍ରଗତି ବାର୍ ରେଣ୍ଡର୍ କରିବା
- 30-ଦିନର କୋଟା ପ୍ରବଣତା ଚାର୍ଟ ଦେଖାଇବା
- ବ୍ୟବହାର ସୀମାର ନିକଟବର୍ତ୍ତୀ ହେଲେ ସତର୍କତା ସକ୍ରିୟ କରିବା

## ଧାରଣ ଏବଂ ପରିଷ୍କାର

ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ପିଛା ବ୍ୟବହାର ଡାଟା ~1-10KB ବୃଦ୍ଧି ପାଏ। ବୃହତ୍ ସ୍ତରରେ ଏହା ଉଲ୍ଲେଖନୀୟ ହୋଇପାରେ।

### ଧାରଣ ସେଟିଂସ୍

ବ୍ୟବହାର ଇତିହାସର ଧାରଣ UIରେ ଥିବା Database Settings ମାଧ୍ୟମରେ କିମ୍ବା `/api/settings/database` ମାଧ୍ୟମରେ ବିନ୍ୟାସ କରାଯାଏ।

ଡିଫଲ୍ଟ ଭାବରେ, ବ୍ୟବହାର ଇତିହାସ **90 ଦିନ** ପାଇଁ ରଖାଯାଏ।

### ପରିଷ୍କାର

ପୁରୁଣା ରେକର୍ଡଗୁଡ଼ିକୁ `src/lib/db/cleanup.ts` ଦ୍ୱାରା ପରିଷ୍କାର କରାଯାଏ:

- ପୃଷ୍ଠଭୂମି cron ପ୍ରକ୍ରିୟା ଦ୍ୱାରା ଟ୍ରିଗର୍ ହୁଏ
- ବିନ୍ୟାସିତ `usageHistory` ଧାରଣ ସେଟିଂଠାରୁ ପୁରୁଣା `usage_history` ରେକର୍ଡଗୁଡ଼ିକୁ ବିଲୋପ କରେ

### ସଂରକ୍ଷଣ ଆକଳନ

| ଅନୁରୋଧ ହାର         | 30-ଦିନର ସଂରକ୍ଷଣ | 90-ଦିନର ସଂରକ୍ଷଣ |
| ------------------ | --------------- | --------------- |
| 100 ଅନୁରୋଧ/ଦିନ     | ~3MB            | ~9MB            |
| 1,000 ଅନୁରୋଧ/ଦିନ   | ~30MB           | ~90MB           |
| 10,000 ଅନୁରୋଧ/ଦିନ  | ~300MB          | ~900MB          |
| 100,000 ଅନୁରୋଧ/ଦିନ | ~3GB            | ~9GB            |

ଅତ୍ୟଧିକ ଟ୍ରାଫିକ୍ ପାଇଁ, ନିମ୍ନଲିଖିତ ବିଷୟ ବିଚାର କରନ୍ତୁ:

- Database Settings ମାଧ୍ୟମରେ ଧାରଣ ଅବଧି ହ୍ରାସ କରିବା
- ଅପରିଷ୍କୃତ ରେକର୍ଡ ପରିବର୍ତ୍ତେ `aggregated_metrics` ବ୍ୟବହାର କରିବା (କେବଳ ଆନାଲିଟିକ୍ସ ପାଇଁ)

## ଖର୍ଚ୍ଚ ଅନୁକୂଳନ ପରାମର୍ଶ

### 1. ଉପଯୁକ୍ତ ମଡେଲ୍ ବ୍ୟବହାର କରନ୍ତୁ


### 2. କ୍ୟାଶିଂ ସକ୍ଷମ କରନ୍ତୁ

Anthropic ପ୍ରମ୍ପ୍ଟ କ୍ୟାଶିଂ **ପୁନରାବୃତ୍ତ ପ୍ରସଙ୍ଗରେ 90% ସଞ୍ଚୟ କରେ**:

```ts
// କ୍ୟାଶିଂ ସ୍ୱୟଂଚାଳିତ — କେବଳ ସେହି ବୃହତ୍ system promptକୁ ସାମିଲ କରନ୍ତୁ
const response = await openai.chat({
  model: "claude-sonnet-4-5",
  system: longSystemPrompt, // ସ୍ୱୟଂଚାଳିତ ଭାବରେ କ୍ୟାଶ୍ ହେବ
  messages: [{ role: "user", content: "..." }],
});
```

### 3. ସଙ୍କୋଚନ ବ୍ୟବହାର କରନ୍ତୁ

RTK + Caveman ସଙ୍କୋଚନ **ଟୁଲ୍-ପ୍ରଧାନ ସେସନ୍ଗୁଡ଼ିକରେ 15-95% ସଞ୍ଚୟ କରେ**:

```ts
const config = {
  compression: {
    engine: "rtk",
    intensity: "aggressive",
  },
};
```

### 4. ପ୍ରତି-କୀ କୋଟା ସେଟ୍ କରନ୍ତୁ

ଅନିୟନ୍ତ୍ରିତ ଖର୍ଚ୍ଚ ରୋକିବା ପାଇଁ ସର୍ବଦା `quotaLimit` ସେଟ୍ କରନ୍ତୁ:

```ts
await updateApiKey(keyId, { quotaLimit: 10_00 }); // $10/ମାସ ସୀମା
```

### 5. ସର୍ବାଧିକ ବ୍ୟବହାରକାରୀଙ୍କ ଅଡିଟ୍ କରନ୍ତୁ

API କୀ ଅନୁଯାୟୀ ଗ୍ରୁପ୍ କରିବା ଏବଂ ଖର୍ଚ୍ଚ ଅନୁଯାୟୀ ସଜାଇବା ପାଇଁ ଡ୍ୟାସବୋର୍ଡ କିମ୍ବା **`/api/usage/analytics`** ବ୍ୟବହାର କରନ୍ତୁ:

```bash
GET /api/usage/analytics?groupBy=apiKey
```

## ସମସ୍ୟା ସମାଧାନ

### "ଖର୍ଚ୍ଚ ଆଶାଠାରୁ ଅଧିକ"

1. **`/api/usage/analytics?groupBy=model`** ଯାଞ୍ଚ କରନ୍ତୁ — ମହଙ୍ଗା ମଡେଲ୍ ଖୋଜନ୍ତୁ
2. **`/api/usage/analytics?groupBy=apiKey`** ଯାଞ୍ଚ କରନ୍ତୁ — ଅଧିକ ବ୍ୟବହାରକାରୀଙ୍କୁ ଖୋଜନ୍ତୁ
3. ମୂଲ୍ୟ ଡାଟା ଅଦ୍ୟତିତ ଅଛି କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ: `POST /api/pricing/sync`

### "ରେକର୍ଡ ମିଳୁନାହିଁ"

- Dashboard → Database → Cleanup ଅଧୀନରେ DB ଧାରଣ ସେଟିଂସ୍ ଯାଞ୍ଚ କରନ୍ତୁ — ପୁରୁଣା ରେକର୍ଡଗୁଡ଼ିକୁ ନିୟମିତ ପରିଷ୍କାର କାର୍ଯ୍ୟ (`src/lib/db/cleanup.ts`) ଦ୍ୱାରା ବିଲୋପ କରାଯାଏ
- `src/lib/db/usage*.ts`ରେ ତ୍ରୁଟି ଯାଞ୍ଚ କରନ୍ତୁ — DB ଲେଖା ବିଫଳତାଗୁଡ଼ିକୁ ଲଗ୍ କରାଯାଏ, କିନ୍ତୁ ପ୍ରଦର୍ଶନ କରାଯାଏ ନାହିଁ
- ଅନୁରୋଧଟି ପ୍ରକୃତରେ `chatCore`ରେ ପହଞ୍ଚିଛି କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ — combo routing ଯାଞ୍ଚ କରନ୍ତୁ

### "କୋଟା ଲାଗୁ ହେଉନାହିଁ"

- କୀର `quotaLimit` ସେଟିଂ ଯାଞ୍ଚ କରନ୍ତୁ
- `quotaWindow` ସଠିକ୍ ଭାବରେ ସେଟ୍ ହୋଇଛି କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ
- `quotaSnapshots` ରେକର୍ଡ ଖୋଜନ୍ତୁ — ସେଗୁଡ଼ିକ ପ୍ରତ୍ୟେକ ଅନୁରୋଧରେ ସୃଷ୍ଟି ହେବା ଉଚିତ
