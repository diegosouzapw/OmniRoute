ଆପଣଙ୍କ ଲ୍ୟାପଟପ୍ରେ `omniroute` CLI ଚଲାନ୍ତୁ, ଯେତେବେଳେ OmniRoute ନିଜେ ଅନ୍ୟ କୌଣସି ସ୍ଥାନରେ
(ଏକ VPS, ଏକ ହୋମ୍ ସର୍ଭର୍, ଆପଣଙ୍କ Tailnetରେ ଥିବା ଅନ୍ୟ ଏକ ମେସିନ୍) ଚାଲୁଥାଏ। ଆପଣ
`omniroute connect` ସହିତ ଥରେ ଲଗ୍ ଇନ୍ କରନ୍ତି, ଏବଂ ତା'ପରଠାରୁ **ପ୍ରତ୍ୟେକ** CLI କମାଣ୍ଡ ସେହି ରିମୋଟ୍
ସର୍ଭର୍କୁ ଲକ୍ଷ୍ୟ କରେ — ସମାନ କମାଣ୍ଡ, ସମାନ ଆଉଟପୁଟ୍, କେବଳ ରିମୋଟ୍ରେ ନିଷ୍ପାଦିତ ହୁଏ।

ଇନଷ୍ଟଲ୍ କରିବା ପାଇଁ କୌଣସି ଦ୍ୱିତୀୟ ଟୁଲ୍ ନାହିଁ: ରିମୋଟ୍ ମୋଡ୍ ହେଉଛି ନିୟମିତ `omniroute` CLI
ସହିତ ସ୍କୋପ୍ଯୁକ୍ତ **ଆକ୍ସେସ୍ ଟୋକନ୍**।

```bash
npm install -g omniroute                 # ସାଧାରଣ CLI
omniroute connect 192.168.0.15           # ଲଗ୍ ଇନ୍ କରନ୍ତୁ (ପାସୱାର୍ଡ → ସ୍କୋପ୍ଯୁକ୍ତ ଟୋକନ୍)
omniroute models list                    # ← ବର୍ତ୍ତମାନ ରିମୋଟ୍ ସର୍ଭର୍ର ମଡେଲ୍ଗୁଡ଼ିକୁ ତାଲିକାଭୁକ୍ତ କରେ
omniroute configure codex                # ← ରିମୋଟ୍ କ୍ୟାଟାଲଗ୍ରୁ ଏକ ସ୍ଥାନୀୟ Codex ପ୍ରୋଫାଇଲ୍ ଲେଖେ
```

## ଏହା କିପରି କାମ କରେ

```
ଆପଣଙ୍କ ଲ୍ୟାପଟପ୍                         ରିମୋଟ୍ OmniRoute (VPS)
┌────────────────────┐                   ┌───────────────────────────────┐
│ omniroute CLI      │  POST /api/cli/connect  (ପାସୱାର୍ଡ → ଟୋକନ୍)        │
│  context: vps      │ ───────────────►  │ ଏକ ସ୍କୋପ୍ଯୁକ୍ତ ଆକ୍ସେସ୍ ଟୋକନ୍ ଜାରି କରେ │
│  baseUrl, token    │  Authorization: Bearer oma_live_…                  │
│                    │ ───────────────►  │ ପ୍ରତ୍ୟେକ ପରିଚାଳନା ରୁଟ୍, ଟୋକନ୍ର │
│ କନଫିଗ୍ଗୁଡ଼ିକୁ    │ ◄───────────────  │ ସ୍କୋପ୍ ଅନୁଯାୟୀ ଯାଞ୍ଚ କରାଯାଏ    │
│ ସ୍ଥାନୀୟ ଭାବେ ଲେଖେ │                   └───────────────────────────────┘
└────────────────────┘
```

- **କନଟେକ୍ସ୍ଟଗୁଡ଼ିକ** ପ୍ରତ୍ୟେକଟି ଗୋଟିଏ ସର୍ଭର୍ ସଂରକ୍ଷଣ କରେ (`~/.omniroute/config.json`, `chmod 600`)।
  `omniroute contexts use <name>` ସକ୍ରିୟ ସର୍ଭର୍କୁ ବଦଳାଏ; `default` ହେଉଛି ସ୍ଥାନୀୟ।
- **ଆକ୍ସେସ୍ ଟୋକନ୍ଗୁଡ଼ିକ** (`oma_live_…`) ପରିଚାଳନା କମାଣ୍ଡଗୁଡ଼ିକୁ ଅନୁମୋଦନ କରେ। ସେଗୁଡ଼ିକ
  ଇନଫରେନ୍ସ API କି'ଗୁଡ଼ିକଠାରୁ (`sk-…`, `/v1/chat/completions` ପାଇଁ ବ୍ୟବହୃତ) ଭିନ୍ନ।
- ଗୋଟିଏ ଟୋକନ୍ର କେବଳ SHA-256 ହ୍ୟାସ୍ ସର୍ଭର୍ ପାର୍ଶ୍ୱରେ ସଂରକ୍ଷିତ ହୁଏ। ପ୍ଲେନ୍ଟେକ୍ସ୍ଟ
  ସୃଷ୍ଟି ସମୟରେ **କେବଳ ଥରେ** ଦେଖାଯାଏ।

## ସଂଯୋଗ କରିବା

### ପରିଚାଳନା ପାସୱାର୍ଡ ସହିତ (ବୁଟ୍ଷ୍ଟ୍ରାପ୍)

```bash
omniroute connect 192.168.0.15
# http://192.168.0.15:20128 ପାଇଁ ପରିଚାଳନା ପାସୱାର୍ଡ: ********
# ✔ http://192.168.0.15:20128 ସହିତ ସଂଯୁକ୍ତ — କନଟେକ୍ସ୍ଟ '192.168.0.15' (ସ୍କୋପ୍: admin)
```

ପାସୱାର୍ଡ ପ୍ରବାହ ଡିଫଲ୍ଟ ଭାବେ ଏକ **admin** ଟୋକନ୍ ଜାରି କରେ (ଆପଣଙ୍କ ପାଖରେ ପାସୱାର୍ଡ ଅଛି, ତେଣୁ
ଆପଣଙ୍କ ପାଖରେ ପୂର୍ବରୁ ସମ୍ପୂର୍ଣ୍ଣ ନିୟନ୍ତ୍ରଣ ଅଛି)। `--scope` ସହିତ ସ୍କୋପ୍ କମାନ୍ତୁ:

```bash
omniroute connect 192.168.0.15 --scope write
```

ବିକଳ୍ପଗୁଡ଼ିକ: `--port <p>` (ହୋଷ୍ଟରେ ପୋର୍ଟ ନଥିଲେ), `--name <ctx>` (କନଟେକ୍ସ୍ଟ ନାମ),
`--scope read|write|admin`। ଏକ ସମ୍ପୂର୍ଣ୍ଣ URLକୁ ଯଥାରୂପେ ଗ୍ରହଣ କରାଯାଏ:
`omniroute connect https://omni.example.com`।

### ପୂର୍ବରୁ ସୃଷ୍ଟି ହୋଇଥିବା ଟୋକନ୍ ସହିତ

ଡ୍ୟାସବୋର୍ଡରେ (କିମ୍ବା `omniroute tokens create` ସହିତ) ଏକ ସ୍କୋପ୍ଯୁକ୍ତ ଟୋକନ୍ ସୃଷ୍ଟି କରନ୍ତୁ ଏବଂ
ତାହାକୁ ପେଷ୍ଟ କରନ୍ତୁ — କୌଣସି ପାସୱାର୍ଡ ଆବଶ୍ୟକ ନାହିଁ:

```bash
omniroute connect 192.168.0.15 --key oma_live_xxxxxxxx
```

CLI ଏହାକୁ `GET /api/cli/whoami` ମାଧ୍ୟମରେ ବୈଧତା ଯାଞ୍ଚ କରେ ଏବଂ ସକ୍ରିୟ କନଟେକ୍ସ୍ଟ ଭାବେ ସଂରକ୍ଷଣ କରେ।

## ସ୍କୋପ୍ଗୁଡ଼ିକ

ତିନୋଟି ସ୍ତର, କ୍ରମାନୁକ୍ରମିକ (`admin ⊃ write ⊃ read`):

| ସ୍କୋପ୍  | କ'ଣ କରିପାରିବ                                                                   |
| ------- | ------------------------------------------------------------------------------ |
| `read`  | ତାଲିକା/ନିରୀକ୍ଷଣ — `models list`, `providers status`, `logs`, `usage`, `cost`   |
| `write` | read **+** କନଫିଗର୍/ପ୍ରୟୋଗ — `setup-codex`, `keys add`, `config set`, ସମ୍ମିଶ୍ରଣ |
| `admin` | write **+** ପରିଚାଳନା — `tokens` CRUD, ପ୍ରଦାତା ଯୋଡ଼ିବା, ସେବା, ନୀତି, oauth       |

HTTP ମେଥଡ୍ (`GET`→read, ପରିବର୍ତ୍ତନ→write) ଏବଂ ସମ୍ବେଦନଶୀଳ ଅଂଶଗୁଡ଼ିକ ପାଇଁ ଏକ admin ଅନୁମତି-ତାଲିକା
(`/api/cli/tokens`, `/api/providers` ପରିବର୍ତ୍ତନ, `/api/oauth`, `/api/services`, …)
ଆଧାରରେ ସର୍ଭର୍ ପ୍ରତ୍ୟେକ ରୁଟ୍କୁ ଆବଶ୍ୟକ ସ୍କୋପ୍ ନିର୍ଣ୍ଣୟ କରେ।
ଅପର୍ଯ୍ୟାପ୍ତ ସ୍କୋପ୍ ଥିବା ଏକ ଟୋକନ୍ ସ୍ପଷ୍ଟ ବାର୍ତ୍ତା ସହିତ `403` ପାଏ।

> ପ୍ରକ୍ରିୟା ଆରମ୍ଭ କରୁଥିବା ରୁଟ୍ଗୁଡ଼ିକ (`/api/services/*`, `/api/mcp/*`, …)
> **କେବଳ loopback** ରହେ — ସ୍କୋପ୍ ଯାହାହେଉ ନା କାହିଁକି, ଏକ ରିମୋଟ୍ ଟୋକନ୍ କେବେବି ସେଗୁଡ଼ିକୁ ପହଞ୍ଚିପାରିବ ନାହିଁ।

## ରିମୋଟ୍ ଇନଷ୍ଟଲେସନ୍ରେ Antigravity ସଂଯୋଗ କରିବା

Antigravity Googleର firstparty/nativeapp ସମ୍ମତି ସ୍କ୍ରିନ୍ ବ୍ୟବହାର କରେ। Google କେବଳ
ସେତେବେଳେ ଅନୁମୋଦନ କୋଡ୍ ଜାରି କରେ, ଯେତେବେଳେ **loopback redirect**
(`http://127.0.0.1:<port>/callback`)ଟି **ସାଇନ୍-ଇନ୍କୁ ଅନୁମୋଦନ କରୁଥିବା ବ୍ରାଉଜରରୁ
ପହଞ୍ଚଯୋଗ୍ୟ** ଥାଏ। ଏକ ରିମୋଟ୍ VPS ଇନଷ୍ଟଲେସନ୍ରେ ସେହି loopback ଆପଣଙ୍କ
ମେସିନ୍ରେ ନୁହେଁ, ସର୍ଭର୍ରେ ଥାଏ, ତେଣୁ ସମ୍ମତି ସ୍କ୍ରିନ୍ଟି **ଅନନ୍ତକାଳ ପର୍ଯ୍ୟନ୍ତ
ଅଟକି ରହେ ଏବଂ କେବେ ମଧ୍ୟ କୋଡ୍ ଦିଏ ନାହିଁ** — ସାଧାରଣ "callback URL ପେଷ୍ଟ କରନ୍ତୁ"
ବିକଳ୍ପରେ ପେଷ୍ଟ କରିବା ପାଇଁ କିଛି ନଥାଏ। (ଏହା Google ପକ୍ଷର ଏକ ସୀମାବଦ୍ଧତା:
କେବଳ OmniRouteରେ ନୁହେଁ, ବଣ୍ଡଲ୍ ହୋଇଥିବା Antigravity desktop client ବ୍ୟବହାର
କରୁଥିବା ଯେକୌଣସି proxyରେ ମଧ୍ୟ ସମାନ ଭାବେ ଅଟକିଯାଏ।)

ଆପଣ ଅଟକିଯିବା ପୂର୍ବରୁ dashboard ଏହାକୁ ଚିହ୍ନଟ କରେ: ଏକ non-localhost ଠିକଣାରୁ
**Providers → Antigravity → Connect** ଖୋଲିଲେ ସାଧାରଣ "callback URL କପି କରନ୍ତୁ"
ସୂଚନା ବଦଳରେ ନିମ୍ନର ଦୁଇଟି ସମାଧାନ ଦେଖାଯାଏ, ଯେଉଁଥିରେ ଆପଣଙ୍କ host ଏବଂ port
ପୂର୍ବରୁ ପୂରଣ ହୋଇଥାଏ। (ଏକ LAN ଠିକଣା ମଧ୍ୟ ଏଥିରେ ଗଣାଯାଏ — ଏହି callback
ଦୃଷ୍ଟିରୁ `192.168.x.x` localhost ନୁହେଁ।)

ଏକ ରିମୋଟ୍ OmniRoute ସହିତ Antigravity ସଂଯୋଗ କରିବା ପାଇଁ ଦୁଇଟି ସମର୍ଥିତ ଉପାୟ ଅଛି।

### ବିକଳ୍ପ A — ସ୍ଥାନୀୟ ଲଗଇନ୍ ସହାୟକ (ସୁପାରିସକୃତ)

OAuthକୁ **ଆପଣଙ୍କ ନିଜ କମ୍ପ୍ୟୁଟର୍ରେ** ଚଲାନ୍ତୁ, ଯେଉଁଠାରେ `127.0.0.1`
ପହଞ୍ଚଯୋଗ୍ୟ। ସହାୟକଟି Google ସହିତ ସିଧାସଳଖ ଯୋଗାଯୋଗ କରେ, ତେଣୁ dashboardର
ସଂସ୍କରଣ ଯେଉଁଠାରେ ସମ୍ପୂର୍ଣ୍ଣ କରିପାରେ ନାହିଁ, ସେଠାରେ ସମ୍ମତି ପ୍ରକ୍ରିୟା ସମ୍ପୂର୍ଣ୍ଣ ହୁଏ।

**ଯଦି ଆପଣ ପୂର୍ବରୁ ସଂଯୁକ୍ତ ଅଛନ୍ତି** (`omniroute connect <host>`), ତେବେ
କପି କରିବାକୁ କିଛି ନାହିଁ — ସହାୟକଟି ଆପଣଙ୍କ ପାଇଁ credentialକୁ ସେହି
ଇନଷ୍ଟଲେସନ୍ରେ ପହଞ୍ଚାଇଦିଏ:

```bash
# ଆପଣଙ୍କ LOCAL ମେସିନ୍ରେ (Node.js + ଏକ ବ୍ରାଉଜର୍ ଆବଶ୍ୟକ):
omniroute connect 192.168.0.15        # ଥରେ — ଏକ admin-scoped context token ସୃଷ୍ଟି କରେ
npx omniroute login antigravity
#   ↳ Google ସମ୍ମତି ପୃଷ୍ଠା ଖୋଲେ, ଏକ ସ୍ଥାନୀୟ loopback portରେ callbackକୁ ଧରେ,
#     ଏହାକୁ ବିନିମୟ କରେ ଏବଂ credentialକୁ ସକ୍ରିୟ contextରେ POST କରେ:
#
#   Antigravity connected on http://192.168.0.15:20128 (connection abc123).
#   ପେଷ୍ଟ କରିବାକୁ କିଛି ନାହିଁ — ଆପଣ ଏହି terminalକୁ ବନ୍ଦ କରିପାରିବେ।
```

ସକ୍ରିୟ context ଅନ୍ୟ ଏକ ମେସିନ୍କୁ ସୂଚାଉଥିବାବେଳେ push ସ୍ୱୟଂଚାଳିତ ଭାବେ
ହୁଏ। `--push` / `--no-push` ଦ୍ୱାରା ଯେକୌଣସି ଆଚରଣକୁ ବାଧ୍ୟତାମୂଳକ କରନ୍ତୁ,
କିମ୍ବା `--context <name>` ସହିତ ଏକ ନିର୍ଦ୍ଦିଷ୍ଟ contextକୁ ଲକ୍ଷ୍ୟ କରନ୍ତୁ।

**ଯଦି ଆପଣଙ୍କ ମେସିନ୍ VPSକୁ ପହଞ୍ଚିପାରେ ନାହିଁ** (firewall ଦ୍ୱାରା ଅବରୋଧିତ,
SSH ନାହିଁ, air-gapped desk), ତଥାପି ସହାୟକଟି କାମ କରେ — ଏହାକୁ କେବଳ
Googleର ହିଁ _ଆବଶ୍ୟକତା_ ଥାଏ। `--no-push` ବ୍ୟବହାର କରନ୍ତୁ, କିମ୍ବା pushକୁ
ବିଫଳ ହେବାକୁ ଦିଅନ୍ତୁ: ଆପଣ ପୂର୍ବରୁ ସମ୍ପୂର୍ଣ୍ଣ କରିଥିବା authorizationକୁ
ବାତିଲ୍ କରିବା ପରିବର୍ତ୍ତେ ଏହା blobକୁ ପ୍ରିଣ୍ଟ କରିବ।

```bash
npx omniroute login antigravity --no-push
#   omniroute-cred-v1.eyJ2IjoxLCJ...
```

ତା’ପରେ, **ରିମୋଟ୍** dashboardରେ: **Providers → Antigravity → Connect**କୁ ଯାଆନ୍ତୁ,
ଏବଂ `omniroute-cred-v1.…` blobକୁ **Step 2** ଫିଲ୍ଡରେ ପେଷ୍ଟ କରନ୍ତୁ (ଏହା
callback URL କିମ୍ବା credential blob, ଉଭୟକୁ ଗ୍ରହଣ କରେ)। OmniRoute ଏହାକୁ
decode କରେ, server-sideରେ Cloud Code onboarding ଚଲାଏ ଏବଂ ସଂଯୋଗକୁ ସ୍ଥାୟୀ
ଭାବେ ସଂରକ୍ଷଣ କରେ।

> blobରେ ଏକ refresh token ରହିଛି — ଏହାକୁ password ପରି ସୁରକ୍ଷିତ ରଖନ୍ତୁ। push
> ପଥରେ ଏହା ଆପଣଙ୍କ contextର ପ୍ରାମାଣିକୃତ ସଂଯୋଗ ମାଧ୍ୟମରେ ଥରେ ପଠାଯାଏ; paste
> ପଥରେ ଏହା ଆପଣଙ୍କ dashboard ସଂଯୋଗ ମାଧ୍ୟମରେ ପଠାଯାଏ। ଉଭୟ କ୍ଷେତ୍ରରେ ଏହା
> ସ୍ଥିର ଅବସ୍ଥାରେ encrypted ଭାବେ ସଂରକ୍ଷିତ ହୁଏ, ଏବଂ ଏକ ସଫଳ push ଏହାକୁ କେବେ
> ମଧ୍ୟ ଆପଣଙ୍କ terminalରେ ପ୍ରିଣ୍ଟ କରେ ନାହିଁ।

Flags: `--no-browser` (ସ୍ୱୟଂଚାଳିତ ଭାବେ ଖୋଲିବା ପରିବର୍ତ୍ତେ URL ପ୍ରିଣ୍ଟ କରେ),
`--port <n>` (loopback portକୁ ନିର୍ଦ୍ଦିଷ୍ଟ କରେ), `--timeout <ms>`,
`--push` / `--no-push` (ସ୍ୱୟଂଚାଳିତ ବିତରଣକୁ override କରେ),
`--context <name>` (ଏକ ନିର୍ଦ୍ଦିଷ୍ଟ contextକୁ ଲକ୍ଷ୍ୟ କରେ)।

### ବିକଳ୍ପ B — SSH local-forward tunnel

ଯଦି ଆପଣଙ୍କର VPSକୁ SSH access ଅଛି, ତେବେ dashboard portକୁ forward କରନ୍ତୁ,
ଯାହାଦ୍ୱାରା loopback callbackଟି tunnel ମାଧ୍ୟମରେ ପୁଣି ସର୍ଭର୍କୁ ପହଞ୍ଚିବ:

```bash
# ଆପଣଙ୍କ LOCAL ମେସିନ୍ରେ:
ssh -L 20128:127.0.0.1:20128 user@your-vps
# ତା’ପରେ ଆପଣଙ୍କ LOCAL ବ୍ରାଉଜର୍ରେ http://localhost:20128 ଖୋଲନ୍ତୁ ଏବଂ ସାଧାରଣ ଭାବେ
# Antigravity ସଂଯୋଗ କରନ୍ତୁ — 127.0.0.1:20128/callback redirect ଏବେ SSH ମାଧ୍ୟମରେ VPSକୁ ପହଞ୍ଚିବ।
```

ଆପଣ `localhost:20128` ଭାବେ dashboardକୁ ପହଞ୍ଚୁଥିବାରୁ, Google ସମ୍ମତି ପ୍ରକ୍ରିୟା
ସମ୍ପୂର୍ଣ୍ଣ ହୁଏ ଏବଂ callbackଟି ସେହି tunnel ମାଧ୍ୟମରେ ସର୍ଭର୍କୁ ପହଞ୍ଚାଯାଏ —
କୌଣସି blob ଆବଶ୍ୟକ ନାହିଁ। ସଂଯୋଗଟି ସକ୍ରିୟ ଭାବେ ଦେଖାଯିବା ପର୍ଯ୍ୟନ୍ତ tunnelକୁ
ଖୋଲା ରଖନ୍ତୁ।

ନିମ୍ନର fixed-loopback providers ଠାରୁ ଭିନ୍ନ ଭାବେ, ଏଠାରେ **ଗୋଟିଏ forward ଯଥେଷ୍ଟ**:
Antigravity callbackଟି dashboard port ମାଧ୍ୟମରେ ହିଁ ଯାଏ, ତେଣୁ tunnel କରିବାକୁ
ଦ୍ୱିତୀୟ provider-specific port ଆବଶ୍ୟକ ନାହିଁ।

> ଏକ ସମ୍ପୂର୍ଣ୍ଣ headless ବିକଳ୍ପ (କୌଣସି helper ନାହିଁ, କୌଣସି tunnel ନାହିଁ) ହେଉଛି
> ଆପଣଙ୍କ **ନିଜ** Google OAuth web credentials + ଏକ public base URL ବିନ୍ୟାସ କରିବା;
> providerର OAuth environment variables ଦେଖନ୍ତୁ। ଉପରୋକ୍ତ ଦୁଇଟି ବିକଳ୍ପ ପାଇଁ
> କୌଣସି ଅତିରିକ୍ତ Google setup ଆବଶ୍ୟକ ନାହିଁ।

## ରିମୋଟ୍ ଇନ୍ଷ୍ଟଲେସନ୍ରେ Codex / Grok ସଂଯୋଗ କରିବା (ସ୍ଥିର-ଲୁପ୍ବ୍ୟାକ୍ ପ୍ରଦାନକାରୀ)

Codex, xAI (`xai-oauth`) ଏବଂ Grok CLI (`grok-cli`) ସେମାନଙ୍କ ଅପ୍ଷ୍ଟ୍ରିମ୍ OAuth ଆପ୍ ସହିତ ଏକ **ସ୍ଥିର** ଲୁପ୍ବ୍ୟାକ୍
`redirect_uri` ପଞ୍ଜୀକୃତ କରନ୍ତି। OmniRoute ଏହାକୁ ପରିବର୍ତ୍ତନ କରିପାରେ ନାହିଁ — ପ୍ରଦାନକାରୀ
ସର୍ବଦା ବ୍ରାଉଜର୍କୁ ସେହି ଏକା ହାର୍ଡକୋଡ୍ କରାଯାଇଥିବା ଠିକଣାକୁ ଫେରାଇ ପଠାଏ:

| ପ୍ରଦାନକାରୀ  | ପ୍ରଦାନକାରୀ ରିଡାଇରେକ୍ଟ କରୁଥିବା ସ୍ଥିର କଲ୍ବ୍ୟାକ୍ |
| ----------- | --------------------------------------------- |
| `codex`     | `http://localhost:1455/auth/callback`         |
| `xai-oauth` | `http://127.0.0.1:56121/callback`             |
| `grok-cli`  | `http://127.0.0.1:56122/callback`             |

ଏଠାରେ `localhost`ର ଅର୍ଥ ହେଉଛି **ବ୍ରାଉଜର୍ ଚାଲୁଥିବା ମେସିନ୍**, ଯେତେବେଳେ OmniRouteର PKCE
କଲ୍ବ୍ୟାକ୍ ସର୍ଭର୍ **ସର୍ଭର୍ର** ଲୁପ୍ବ୍ୟାକ୍ରେ ଲିସେନ୍ କରେ। `http://192.168.0.15:20128` ପରି ଏକ LAN
ଠିକଣାରେ ଡ୍ୟାସ୍ବୋର୍ଡ ଖୋଲିଲେ ଦୁଇଟି କେବେ ମଧ୍ୟ ପରସ୍ପର ସହିତ ଯୋଡ଼ି ହୁଅନ୍ତି ନାହିଁ: ଅଥରାଇଜେସନ୍
କୋଡ୍ ଆପଣଙ୍କ ନିଜ ଲାପ୍ଟପ୍ର `localhost:1455`କୁ ପହଞ୍ଚାଯାଏ, ଯେଉଁଠାରେ କିଛି ଲିସେନ୍ କରୁନାହିଁ,
ଏବଂ ପ୍ରଦାନକାରୀ କୌଣସି ତ୍ରୁଟି ଦୃଶ୍ୟମାନ ନ କରି ସାଇନ୍-ଇନ୍ ବିଫଳ କରେ।

ପପ୍ଅପ୍ ଖୋଲିବା ପୂର୍ବରୁ ଡ୍ୟାସ୍ବୋର୍ଡ ଏହାକୁ ଚିହ୍ନଟ କରେ ଏବଂ ଲଗ୍ଇନ୍କୁ ନିରବରେ ବିଫଳ ହେବାକୁ
ଦେବା ପରିବର୍ତ୍ତେ ଟନେଲ୍ କମାଣ୍ଡ ଦେଖାଏ (#8046)।

### ସମାଧାନ — **ଉଭୟ** ପୋର୍ଟ ଫରୱାର୍ଡ କରନ୍ତୁ

```bash
# ବ୍ରାଉଜର୍ ଚାଲୁଥିବା ମେସିନ୍ରେ:
ssh -L 20128:127.0.0.1:20128 -L 1455:127.0.0.1:1455 <user>@192.168.0.15
# ତା'ପରେ http://localhost:20128କୁ ବ୍ରାଉଜ୍ କରନ୍ତୁ ଏବଂ ସେଠାରୁ Codex ସଂଯୋଗ କରନ୍ତୁ
```

ଦୁଇଟି ଫରୱାର୍ଡ ଆବଶ୍ୟକ, ଏବଂ କେବଳ ଗୋଟିଏ ଫରୱାର୍ଡ କଲେ ମଧ୍ୟ ଏହା ବିଫଳ ହୁଏ:

- **`20128`** (ଡ୍ୟାସ୍ବୋର୍ଡ ପୋର୍ଟ) ଅରିଜିନ୍କୁ ପ୍ରକୃତ-ଲୋକାଲ୍ହୋଷ୍ଟ କରେ, ଯାହା ଫଳରେ
  OmniRoute ଆଦୌ PKCE କଲ୍ବ୍ୟାକ୍ ସର୍ଭର୍ ଆରମ୍ଭ କରେ — ଏକ LAN ଅରିଜିନ୍ କେବେ ମଧ୍ୟ
  ସେହି ବ୍ରାଞ୍ଚ୍କୁ ପହଞ୍ଚେ ନାହିଁ।
- **`1455`** (ପ୍ରଦାନକାରୀଙ୍କ ସ୍ଥିର କଲ୍ବ୍ୟାକ୍ ପୋର୍ଟ) ହେଉଛି ବ୍ରାଉଜର୍କୁ ଫେରାଇ
  ପଠାଯାଉଥିବା ସ୍ଥାନ; ଏହାକୁ ଟନେଲ୍ ମାଧ୍ୟମରେ ସର୍ଭର୍ର ଲୁପ୍ବ୍ୟାକ୍ ପର୍ଯ୍ୟନ୍ତ ପହଞ୍ଚିବାକୁ ପଡ଼ିବ।

xAI କିମ୍ବା Grok CLI ସଂଯୋଗ କରିବାବେଳେ `1455`କୁ `56121`/`56122` ସହିତ, ଏବଂ `20128`କୁ
ଆପଣଙ୍କ ପ୍ରକୃତ ଡ୍ୟାସ୍ବୋର୍ଡ ପୋର୍ଟ ସହିତ ବଦଳାନ୍ତୁ। ସଂଯୋଗଟି ସକ୍ରିୟ ଭାବେ ଦେଖାଯିବା ପର୍ଯ୍ୟନ୍ତ
ଟନେଲ୍କୁ ଖୋଲା ରଖନ୍ତୁ।

> **SSH ଆକ୍ସେସ୍ ନାହିଁ?** Codex ଏବଂ Grok CLI ପେଷ୍ଟ କରାଯାଇଥିବା ଟୋକନ୍କୁ ମଧ୍ୟ ଗ୍ରହଣ କରନ୍ତି — ସଂଯୋଗ ଡାଏଲଗ୍ରେ ଥିବା **Paste API
> Key** / **Import auth.json** ଟ୍ୟାବ୍। ସେହି ପଥରେ କୌଣସି ଲୁପ୍ବ୍ୟାକ୍
> କଲ୍ବ୍ୟାକ୍ ନାହିଁ, ତେଣୁ ଏହା ଯେକୌଣସି ଅରିଜିନ୍ରୁ କାମ କରେ। Codex ଅତିରିକ୍ତ ଭାବେ ଏକ ସ୍ୱତନ୍ତ୍ର ଆକ୍ସେସ୍
> ଟୋକନ୍ କିମ୍ବା ଏକ `~/.codex/auth.json` ସେସନ୍ ବ୍ଲବ୍କୁ ଗ୍ରହଣ କରେ।

## ଟୋକନ୍ ପରିଚାଳନା

```bash
omniroute tokens create --name "laptop" --scope write [--expires 30]
#   ↳ ସିକ୍ରେଟ୍କୁ କେବଳ ଥରେ ମୁଦ୍ରଣ କରେ — ଏବେ ଏହାକୁ କପି କରନ୍ତୁ
omniroute tokens list                 # ମାସ୍କ କରାଯାଇଛି: id, name, scope, prefix, status, expiry
omniroute tokens revoke <id|prefix>   # ତୁରନ୍ତ ରଦ୍ଦ କରନ୍ତୁ
omniroute tokens scopes               # ତିନୋଟି ସ୍କୋପ୍କୁ ବ୍ୟାଖ୍ୟା କରେ
```

`tokens` କମାଣ୍ଡଗୁଡ଼ିକ ପାଇଁ ଏକ **admin** କ୍ରେଡେନ୍ସିଆଲ୍ ଆବଶ୍ୟକ। ଆପଣ ଡ୍ୟାସ୍ବୋର୍ଡର
**Settings → Access Tokens** ଅଧୀନରେ ମଧ୍ୟ ଟୋକନ୍ ପରିଚାଳନା କରିପାରିବେ (ସୃଷ୍ଟି, ରଦ୍ଦ, ଥରେ-ମାତ୍ର କପି)।

## ରିମୋଟ୍ କ୍ୟାଟାଲଗ୍ରୁ ଏକ କୋଡିଂ CLI ବିନ୍ୟାସ କରିବା

`omniroute configure` **ସକ୍ରିୟ ସର୍ଭର୍ର** ଲାଇଭ୍ ମଡେଲ୍ କ୍ୟାଟାଲଗ୍ ପଢ଼େ ଏବଂ
**ଆପଣଙ୍କ** ମେସିନ୍ରେ ଏକ କନ୍ଫିଗ୍ ଲେଖେ।

```bash
omniroute configure codex
#   ପ୍ରଦାନକାରୀ: glm, kmc, ollamacloud, opencode-go, …
#   ପ୍ରଦାନକାରୀ: glm
#   ମଡେଲ୍ id: glm/glm-5.2
#   ✔ ~/.codex/glm52.config.toml ଲେଖାଗଲା
#   ଏହାକୁ ବ୍ୟବହାର କରନ୍ତୁ:  codex --profile glm52

# ଅଣ-ଇଣ୍ଟରାକ୍ଟିଭ୍
omniroute configure codex --provider glm --model glm/glm-5.2 --name glm52

# ବାରମ୍ବାର ବ୍ୟବହୃତ ମଡେଲ୍କୁ ଇଣ୍ଟରାକ୍ଟିଭ୍ ପିକର୍ର ଶୀର୍ଷରେ ରଖନ୍ତୁ
omniroute configure codex --provider glm --model glm/glm-5.2 --favorite --yes
```

ପିକର୍ ସ୍ଥାନୀୟ `model-preferences.json` ଫାଇଲ୍ରେ କେବଳ ମଡେଲ୍ IDଗୁଡ଼ିକୁ ରଖେ (କେବେ ମଧ୍ୟ URL କିମ୍ବା କ୍ରେଡେନ୍ସିଆଲ୍ ନୁହେଁ),
ଯାହା କଣ୍ଟେକ୍ସ୍ଟ ଏବଂ CLI ଟାର୍ଗେଟ୍ ଅନୁସାରେ ସ୍କୋପ୍ ହୋଇଥାଏ। ସାମ୍ପ୍ରତିକ ଚୟନଗୁଡ଼ିକ ପୂର୍ବରୁ
ପସନ୍ଦଗୁଡ଼ିକ ଦେଖାଯାଏ; ସେହି କଣ୍ଟେକ୍ସ୍ଟ/ଟାର୍ଗେଟ୍ ତାଲିକାରୁ ଏକ ଚୟନିତ ମଡେଲ୍କୁ ହଟାଇବା ପାଇଁ `--unfavorite`
ବ୍ୟବହାର କରନ୍ତୁ।

ଲେଖାଯାଇଥିବା ପ୍ରୋଫାଇଲ୍ env var ଦ୍ୱାରା ଇନ୍ଫରେନ୍ସ କୀକୁ ସନ୍ଦର୍ଭ କରେ
(`OMNIROUTE_API_KEY`) — ସିକ୍ରେଟ୍କୁ କେବେ ମଧ୍ୟ ଡିସ୍କରେ ଲେଖାଯାଏ ନାହିଁ। ଏକକାଳୀନ
ମୂଳ Codex ସେଟ୍ଅପ୍ (`[model_providers.omniroute]` ବ୍ଲକ୍) ପାଇଁ,
[CODEX-CLI-CONFIGURATION.md](./CODEX-CLI-CONFIGURATION.md) ଦେଖନ୍ତୁ।

### ରିମୋଟ୍ ବିପକ୍ଷରେ ଏକ CLI ଲଞ୍ଚ୍ କରିବା (କୌଣସି କନ୍ଫିଗ୍ ଲେଖାଯାଏ ନାହିଁ)

`omniroute run <target>` ମଧ୍ୟ ସକ୍ରିୟ କଣ୍ଟେକ୍ସ୍ଟକୁ ସମ୍ମାନ କରେ: ରିମୋଟ୍ ବେସ୍ URL
ଏବଂ କଣ୍ଟେକ୍ସ୍ଟ କ୍ରେଡେନ୍ସିଆଲ୍କୁ କେବଳ ସ୍ପନ୍ କରାଯାଇଥିବା ପ୍ରୋସେସ୍ରେ ଇଞ୍ଜେକ୍ଟ କରାଯାଏ।

```bash
omniroute connect 192.168.0.15
omniroute run claude   --model openai/gpt-5.4          # Claude Code → ରିମୋଟ୍
omniroute run gemini   --model glm/glm-5.2 -- --skip-trust -p "hello"
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"

# ଠିକ୍ କ'ଣ ସ୍ପନ୍ କରାଯିବ ତାହାର ପୂର୍ବାବଲୋକନ କରନ୍ତୁ (କେବଳ env KEY ନାମ, କେବେ ମଧ୍ୟ ମୂଲ୍ୟ ନୁହେଁ):
omniroute run codex --dry-run --json
```

ଟାର୍ଗେଟ୍ଗୁଡ଼ିକ: `claude`, `codex`, `aider`, `goose`, `opencode`, `qwen`, `gemini`
(ଏକକ ଉତ୍ସ: `bin/cli/cli-manifest.mjs`)। Qwen ଏବଂ Gemini ଏକ
ଅସ୍ଥାୟୀ ପୃଥକ୍ ହୋମ୍ ସହିତ ଚାଲନ୍ତି, ଯାହା ପ୍ରସ୍ଥାନ ସମୟରେ ହଟାଯାଏ, ତେଣୁ ଲଞ୍ଚ୍ କେବେ ମଧ୍ୟ ଆପଣଙ୍କ ବ୍ୟକ୍ତିଗତ
ଟୁଲ୍ କନ୍ଫିଗରେସନ୍କୁ ସ୍ପର୍ଶ କରେ ନାହିଁ — କିମ୍ବା ସେଥିରେ ଲିକ୍ ହୁଏ ନାହିଁ।

କଣ୍ଟେକ୍ସ୍ଟ, କିମ୍ବା `--remote <url> --api-key <key>`କୁ ସମ୍ମାନ କରନ୍ତି):


> OpenCodeର ଏକ ଅଧିକ ସମୃଦ୍ଧ **ପ୍ଲଗଇନ୍** ଇଣ୍ଟିଗ୍ରେସନ୍ ମଧ୍ୟ ଅଛି: `omniroute setup opencode`
> (ଏବେ `--remote` ମାଧ୍ୟମରେ ରିମୋଟ୍-ସଚେତନ) `@omniroute/opencode-plugin` ଇନ୍ଷ୍ଟଲ୍ କରେ।
> `setup-opencode` ହେଉଛି ହାଲୁକା openai-ସୁସଙ୍ଗତ ବିକଳ୍ପ। API କୀକୁ
> `{env:OMNIROUTE_API_KEY}` ମାଧ୍ୟମରେ ସନ୍ଦର୍ଭିତ କରାଯାଏ — ଏହା କେବେବି ଡିସ୍କରେ ଲେଖାଯାଏ ନାହିଁ।
>
> OpenCode v2ରେ, ଏହା ପରିବର୍ତ୍ତେ `@omniroute/opencode-plugin-v2` ବ୍ୟବହାର କରନ୍ତୁ: ସମାନ କ୍ୟାଟାଲଗ୍,
> ଭିନ୍ନ ଲୋଡର୍ କଣ୍ଟ୍ରାକ୍ଟ। ଇଣ୍ଟିଗ୍ରେସନ୍ ସଂଯୁକ୍ତ ଥିବାବେଳେ ଏହା OpenCodeର ନିଜସ୍ୱ କ୍ରେଡେନ୍ସିଆଲ୍
> ଷ୍ଟୋର୍ରୁ କୀ ପଢ଼େ, ତେଣୁ ଏକ ରିମୋଟ୍ ଗେଟୱେ ପାଇଁ `opencode.json`ରେ ଆଦୌ କୌଣସି କୀ ଆବଶ୍ୟକ ହୁଏ ନାହିଁ।

## କଣ୍ଟେକ୍ସ୍ଟ ପରିଚାଳନା (ସର୍ଭରଗୁଡ଼ିକ ମଧ୍ୟରେ ସୁଇଚ୍ କରନ୍ତୁ)

ଏକ **କଣ୍ଟେକ୍ସ୍ଟ** ହେଉଛି ଏକ ସଞ୍ଚିତ ସର୍ଭର (baseUrl + ପରିଚୟପତ୍ର + ସ୍କୋପ୍)। `omniroute connect`
ଗୋଟିଏ କଣ୍ଟେକ୍ସ୍ଟ ସୃଷ୍ଟି କରି ତାହାକୁ ସକ୍ରିୟ କରେ; ଏହାପରଠାରୁ ପ୍ରତ୍ୟେକ କମାଣ୍ଡ ଏହାକୁ ଲକ୍ଷ୍ୟ କରେ। `omniroute contexts`
ସାହାଯ୍ୟରେ ସେଗୁଡ଼ିକୁ ପରିଚାଳନା କରନ୍ତୁ ଏବଂ ସେମାନଙ୍କ ମଧ୍ୟରେ ସୁଇଚ୍ କରନ୍ତୁ:

```bash
omniroute contexts list            # ସମସ୍ତ କଣ୍ଟେକ୍ସ୍ଟ; ସକ୍ରିୟଟି ● ଦ୍ୱାରା ଚିହ୍ନିତ
omniroute contexts current         # ସକ୍ରିୟ ସର୍ଭର, ପ୍ରମାଣୀକରଣ ସ୍ଥିତି, ସ୍କୋପ୍
```

```text
  | ନାମ     | ମୂଳ URL                   | ପ୍ରମାଣୀକରଣ | ସ୍କୋପ୍ | ବର୍ଣ୍ଣନା
● | vps     | http://100.67.86.91:20128 | token       | admin | ରିମୋଟ୍ OmniRoute (…)
  | default | http://localhost:20128    | ✗           |       |
```

**ସର୍ଭର ସୁଇଚ୍ କରନ୍ତୁ** — ପରବର୍ତ୍ତୀ ପ୍ରତ୍ୟେକ କମାଣ୍ଡ ସକ୍ରିୟ କଣ୍ଟେକ୍ସ୍ଟକୁ ଅନୁସରଣ କରେ:

```bash
omniroute contexts use vps         # → ସମସ୍ତ କମାଣ୍ଡ ବର୍ତ୍ତମାନ ରିମୋଟ୍ VPSକୁ ଲକ୍ଷ୍ୟ କରେ
omniroute tokens list              #   (VPS ବିରୁଦ୍ଧରେ ଚାଲେ)

omniroute contexts use default     # → localhostକୁ ଫେରନ୍ତୁ
omniroute tokens list              #   (ସ୍ଥାନୀୟ ସର୍ଭର ବିରୁଦ୍ଧରେ ଚାଲେ)
```

**ହସ୍ତଚାଳିତ ଭାବରେ ଏକ କଣ୍ଟେକ୍ସ୍ଟ ଯୋଡ଼ନ୍ତୁ** (`connect` ବଦଳରେ), ଯାଞ୍ଚ କରନ୍ତୁ କିମ୍ବା ନାମ ପରିବର୍ତ୍ତନ କରନ୍ତୁ:

```bash
omniroute contexts add staging --url https://staging.example.com:20128 \
  --access-token oma_live_xxxx --scope write --description "staging box"
omniroute contexts show staging    # ଗୋଟିଏ କଣ୍ଟେକ୍ସ୍ଟ ପାଇଁ ସମ୍ପୂର୍ଣ୍ଣ ବିବରଣୀ
omniroute contexts rename staging stg
```

**ଏକ କଣ୍ଟେକ୍ସ୍ଟ ଅପସାରଣ କରନ୍ତୁ** — ନିଶ୍ଚିତକରଣ ପାଇଁ ପଚାରେ; ଏହାକୁ ଏଡ଼ାଇବା ପାଇଁ `--yes` ପାସ୍ କରନ୍ତୁ
(ସ୍କ୍ରିପ୍ଟ / ନନ୍-ଇଣ୍ଟରାକ୍ଟିଭ୍ ସେଲ୍ ପାଇଁ ଆବଶ୍ୟକ, ନଚେତ୍ ସେଗୁଡ଼ିକ ସୁରକ୍ଷିତ ଭାବରେ ଅସ୍ୱୀକାର କରେ):

```bash
omniroute contexts remove stg --yes
```

> `default` (localhost)କୁ ଅପସାରଣ କରାଯାଇପାରିବ ନାହିଁ। ସକ୍ରିୟ କଣ୍ଟେକ୍ସ୍ଟକୁ ଅପସାରଣ କଲେ
> `default`କୁ ଫେରିଯାଏ। ପରାମର୍ଶ: ଏକ କଣ୍ଟେକ୍ସ୍ଟ ଅପସାରଣ କଲେ କେବଳ **ସ୍ଥାନୀୟ** ସଞ୍ଚିତ ପରିଚୟପତ୍ର ଅପସାରିତ ହୁଏ —
> ପ୍ରକୃତରେ ପ୍ରବେଶ ବନ୍ଦ କରିବା ପାଇଁ `omniroute tokens revoke <id>` ସହିତ ସର୍ଭରରେ ଟୋକନ୍ଟିକୁ
> ପ୍ରତ୍ୟାହାର କରନ୍ତୁ।

**କଣ୍ଟେକ୍ସ୍ଟ ରପ୍ତାନି / ଆମଦାନୀ କରନ୍ତୁ** (ଯଥା, ସେଗୁଡ଼ିକୁ ମେସିନ୍ଗୁଡ଼ିକ ମଧ୍ୟରେ ସ୍ଥାନାନ୍ତର କରିବା ପାଇଁ)। ନୂତନ କଣ୍ଟେକ୍ସ୍ଟଗୁଡ଼ିକ କେବଳ
ଏକ କୀଚେନ୍ ରେଫରେନ୍ସ ସ୍ଥାୟୀ ଭାବରେ ରଖେ; OS କୀଚେନ୍ ଉପଲବ୍ଧ ଥିଲେ ପରିଚୟପତ୍ରଗୁଡ଼ିକୁ
ରପ୍ତାନିରେ କପି କରାଯାଏ ନାହିଁ:

```bash
omniroute contexts export --out contexts.json     # ଡିଫଲ୍ଟ: stdout
omniroute contexts import contexts.json            # ଓଭରରାଇଟ୍; ବିଦ୍ୟମାନଗୁଡ଼ିକୁ ରଖିବା ପାଇଁ --merge
omniroute contexts migrate --yes                  # ପୁରୁଣା ପ୍ଲେନ୍ଟେକ୍ସ୍ଟ ଟୋକନ୍ଗୁଡ଼ିକୁ କୀଚେନ୍କୁ ସ୍ଥାନାନ୍ତର କରନ୍ତୁ
```

ବ୍ୟବହାରଯୋଗ୍ୟ OS କୀଚେନ୍ ନଥିବା ହେଡ୍ଲେସ୍ ସିଷ୍ଟମ୍ରେ, CLI
`0600` ମୋଡ୍ରେ `config.json`କୁ ଫଲ୍ବ୍ୟାକ୍ କରେ ଏବଂ ଏକକାଳୀନ ଚେତାବନୀ ପ୍ରଦର୍ଶନ କରେ। ସେହି
ଫଲ୍ବ୍ୟାକ୍ରୁ ହୋଇଥିବା ରପ୍ତାନିଗୁଡ଼ିକୁ (ଏବଂ ମାଇଗ୍ରେସନ୍ ପୂର୍ବରୁ ଯେକୌଣସି ପୁରୁଣା କନଫିଗ୍କୁ) ଗୋପନୀୟ ସାମଗ୍ରୀ ଭାବେ ବିବେଚନା କରନ୍ତୁ।

## ଦ୍ରୁତ ଆରମ୍ଭରୁ-ଶେଷ ପର୍ଯ୍ୟନ୍ତ ଯାଞ୍ଚ

ଆରମ୍ଭରୁ ଏକ ରିମୋଟ୍ ସେଟଅପ୍ ଯାଞ୍ଚ କରିବା ପାଇଁ କପି-ପେଷ୍ଟ କରିହେବା ଏକ ଜୀବନଚକ୍ର — ସଂଯୋଗ କରନ୍ତୁ, ଏକ
ସ୍କୋପ୍ଯୁକ୍ତ ଟୋକନ୍ ସୃଷ୍ଟି କରନ୍ତୁ, ଏକ କମାଣ୍ଡ ରୁଟ୍ କରନ୍ତୁ, ପୁଣି ଫେରିଆସନ୍ତୁ ଏବଂ ସବୁକିଛି ହଟାନ୍ତୁ।
`192.168.0.15`କୁ ଆପଣଙ୍କ ସର୍ଭରର ହୋଷ୍ଟ/IP (Tailscale, LAN, କିମ୍ବା ଏକ ସାର୍ବଜନୀନ
`https://…` URL) ସହିତ ବଦଳାନ୍ତୁ।

```bash
# 1. ସଂଯୋଗ କରନ୍ତୁ (ପାସୱାର୍ଡ → admin ଟୋକନ୍, ସକ୍ରିୟ ହେଉଥିବା ଏକ କଣ୍ଟେକ୍ସ୍ଟ ଭାବେ ସଞ୍ଚିତ)
omniroute connect 192.168.0.15                 # କିମ୍ବା: --key oma_live_xxxx  (ପାସୱାର୍ଡ ବିନା)
omniroute contexts current                     # ରିମୋଟ୍ ସର୍ଭର + ସ୍କୋପ୍ ଦେଖାଏ

# 2. ଏହାକୁ ବ୍ୟବହାର କରନ୍ତୁ — ପରିଚାଳନା କମାଣ୍ଡଗୁଡ଼ିକ ବର୍ତ୍ତମାନ ରିମୋଟ୍ ବିରୁଦ୍ଧରେ ଚାଲେ
omniroute tokens create --name laptop --scope read   # ଏକ ଅଧିକ ସୀମିତ ଟୋକନ୍ ସୃଷ୍ଟି କରନ୍ତୁ
omniroute tokens list                                 # ରିମୋଟ୍ରୁ ମାସ୍କ କରାଯାଇଥିବା ତାଲିକା

# 3. ଆଗପଛ ସୁଇଚ୍ କରନ୍ତୁ
omniroute contexts use default                 # → ସ୍ଥାନୀୟ
omniroute contexts use 192-168-0-15            # → ପୁଣି ରିମୋଟ୍ (`contexts list`ରୁ ନାମ)

# 4. ସବୁକିଛି ହଟାନ୍ତୁ। ଟିପ୍ପଣୀ: `contexts remove` କେବଳ ସ୍ଥାନୀୟ ପରିଚୟପତ୍ରକୁ ଡିଲିଟ୍ କରେ —
#    ଏହା ସର୍ଭରରେ ଥିବା ଟୋକନ୍କୁ ପ୍ରତ୍ୟାହାର କରେ ନାହିଁ। ଯଦି ଆପଣ ପ୍ରକୃତରେ
#    ପ୍ରବେଶ ବନ୍ଦ କରିବାକୁ ଚାହାନ୍ତି, ପ୍ରଥମେ ସର୍ଭର ପକ୍ଷରେ ଏହାକୁ ପ୍ରତ୍ୟାହାର କରନ୍ତୁ।
omniroute tokens revoke <id|prefix>            # ସର୍ଭରରେ ପ୍ରବେଶ ବନ୍ଦ କରେ
omniroute contexts remove 192-168-0-15 --yes   # ସ୍ଥାନୀୟ କଣ୍ଟେକ୍ସ୍ଟ ହଟାନ୍ତୁ (ସକ୍ରିୟ ଥିଲେ ମଧ୍ୟ → defaultକୁ ଫେରେ), କୌଣସି ପ୍ରମ୍ପ୍ଟ ନାହିଁ
```

> `--yes`, `contexts remove`କୁ ନନ୍-ଇଣ୍ଟରାକ୍ଟିଭ୍ କରେ (ସ୍କ୍ରିପ୍ଟ/CIରେ ଆବଶ୍ୟକ; ଏହା ବିନା
> ଏକ ନନ୍-ଇଣ୍ଟରାକ୍ଟିଭ୍ ସେଲ୍ ଅଟକି ରହିବା ପରିବର୍ତ୍ତେ ସୁରକ୍ଷିତ ଭାବରେ ଅସ୍ୱୀକାର କରେ)। **ସକ୍ରିୟ**
> କଣ୍ଟେକ୍ସ୍ଟକୁ ଅପସାରଣ କଲେ ସ୍ୱୟଂଚାଳିତ ଭାବରେ `default`କୁ ଫେରିଯାଏ।

## ସୁରକ୍ଷା ଟିପ୍ପଣୀ

- ଟୋକନର ସାଧା ପାଠ୍ୟ କେବଳ ଥରେ ଦେଖାଯାଏ; କେବଳ SHA-256 ହ୍ୟାସ୍ ସ୍ଥାୟୀ ଭାବରେ ସଂରକ୍ଷିତ ହୁଏ (API କୀଗୁଡ଼ିକ ପରି)।
- `omniroute connect` ଲଗଇନ୍ ବ୍ରୁଟ୍-ଫୋର୍ସ ଲକ୍ଆଉଟ୍ + ଅଡିଟ୍ ଲଗିଂକୁ ପୁନଃବ୍ୟବହାର କରେ।
- ପରିବହନ ପାଇଁ HTTPS କିମ୍ବା ଏକ Tailnetକୁ ପ୍ରାଧାନ୍ୟ ଦିଅନ୍ତୁ; LAN/Tailscale ସୁବିଧା ପାଇଁ ଏକ ଖାଲି ହୋଷ୍ଟ୍ ଡିଫଲ୍ଟ ଭାବେ `http://`
  ବ୍ୟବହାର କରେ — TLS ପାଇଁ ଏକ ସମ୍ପୂର୍ଣ୍ଣ `https://…` URL ପାସ୍ କରନ୍ତୁ।
- ପ୍ରାଧାନ୍ୟପ୍ରାପ୍ତ ସ୍ଥାନୀୟ କଣ୍ଟେକ୍ସ୍ଟ ଫାଇଲ୍ ହେଉଛି `~/.omniroute/config.json` (`chmod 600`),
  ଯେଉଁଥିରେ କେବଳ ଏକ `credentialRef` ଥାଏ; ଟୋକନଟି OS
  କୀଚେନ୍ରେ (`keytar`) ସଂରକ୍ଷିତ ହୁଏ ଏବଂ ଲଗ୍ଗୁଡ଼ିକରେ କେବେ ମଧ୍ୟ ପ୍ରିଣ୍ଟ ହୁଏ ନାହିଁ। କାର୍ଯ୍ୟକ୍ଷମ ନେଟିଭ୍ କୀଚେନ୍ ବିନା ଥିବା ହେଡ୍ଲେସ୍ ଇନ୍ଷ୍ଟଲେସନ୍ଗୁଡ଼ିକ ସ୍ପଷ୍ଟ ଫଲ୍ବ୍ୟାକ୍ ଭାବେ ସେହି
  `0600` ଫାଇଲ୍କୁ ବ୍ୟବହାର କରନ୍ତି ଏବଂ ଥରେ ଏକ ସତର୍କବାର୍ତ୍ତା ନିର୍ଗତ କରନ୍ତି। ଏକ
  କୀଚେନ୍ ବ୍ୟାକେଣ୍ଡ ଇନ୍ଷ୍ଟଲ୍ କରିବା ପରେ `omniroute contexts migrate --yes` ବ୍ୟବହାର କରନ୍ତୁ।
