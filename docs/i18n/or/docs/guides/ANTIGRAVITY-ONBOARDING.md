## 1. Antigravity ବନାମ Antigravity CLI (agy)

ଉଭୟ ପ୍ରଦାନକାରୀ **ସମାନ Google ବ୍ୟାକଏଣ୍ଡ** ଅଂଶୀଦାର କରନ୍ତି — ସମାନ OAuth କ୍ଲାଏଣ୍ଟ, ଟୋକନ୍ ରିଫ୍ରେଶ୍, ଏଣ୍ଡପଏଣ୍ଟ ଏବଂ Google ଆକାଉଣ୍ଟ। ପାର୍ଥକ୍ୟ ହେଉଛି ଆପଣ କେଉଁ ମଡେଲ୍ଗୁଡ଼ିକ ଦେଖନ୍ତି।

> Googleର ଆଧିକାରିକ ତୁଳନା ପାଇଁ [Antigravity CLI ଘୋଷଣା](https://antigravity.google/blog/introducing-google-antigravity-cli) ଦେଖନ୍ତୁ।

| ଦିଗ                        | `antigravity` (IDE)                                           | `agy` (CLI)                                                        |
| -------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------ |
| **Google ପ୍ରଡକ୍ଟ**         | Antigravity 2.0 / Antigravity IDE                             | Antigravity CLI                                                    |

**ଉପଲବ୍ଧ ମଡେଲ୍ଗୁଡ଼ିକ (ପରୀକ୍ଷଣ ମାଧ୍ୟମରେ ଯାଞ୍ଚ କରାଯାଇଛି, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (ବିଭିନ୍ନ ଚିନ୍ତନ ସ୍ତର)
- Claude: Sonnet 4.6, Opus 4.6 (ପ୍ରତ୍ୟେକର default/low/medium/high ଭାରିଆଣ୍ଟ ସହିତ)
- ଅନ୍ୟାନ୍ୟ: GPT-OSS 120B Medium
- **Claude Sonnet 5 ଉପଲବ୍ଧ ନୁହେଁ** — କେବଳ 4.6 ଭାରିଆଣ୍ଟଗୁଡ଼ିକ ସମର୍ଥିତ

**ମଡେଲ୍ କ୍ୟାଟାଲଗ୍ ଭିନ୍ନ ହେବାର କାରଣ**: Googleର CLIକୁ “ଗତି ଏବଂ କମ୍ ଓଭରହେଡ୍ ପାଇଁ ଅପ୍ଟିମାଇଜ୍” ଏବଂ “Gemini ମଡେଲ୍ଗୁଡ଼ିକ ସହ ସହ-ଅପ୍ଟିମାଇଜ୍” କରାଯାଇଛି (Googleର ଆଧିକାରିକ ବ୍ଲଗ୍ ଅନୁଯାୟୀ)। Web/IDE ପ୍ରଡକ୍ଟକୁ “ବ୍ୟାପକତା ପାଇଁ ଅପ୍ଟିମାଇଜ୍” କରାଯାଇଛି। CLI ମଡେଲ୍ଗୁଡ଼ିକୁ ଗତିଶୀଳ ଭାବରେ ଆବିଷ୍କାର କରିବା ପାଇଁ `:fetchAvailableModels` ବ୍ୟବହାର କରେ, ଯେତେବେଳେ IDE ଏକ ସ୍ଥିର ଭାବେ ବଛାଯାଇଥିବା ତାଲିକା ବ୍ୟବହାର କରେ।

**ବାସ୍ତବ ବ୍ୟବହାରରେ**: Gemini ମଡେଲ୍ଗୁଡ଼ିକ ପାଇଁ `agy/` ପ୍ରିଫିକ୍ସ ବ୍ୟବହାର କରନ୍ତୁ (ଉଦାହରଣ ସ୍ୱରୂପ `agy/gemini-3.7-flash-high`)। ସ୍ଥିର ଭାବେ ବଛାଯାଇଥିବା ତାଲିକା ପାଇଁ `antigravity/` ବ୍ୟବହାର କରନ୍ତୁ। ଉଭୟ ସମାନ Google ବ୍ୟାକଏଣ୍ଡକୁ ଅନୁରୋଧ ପଠାନ୍ତି, କିନ୍ତୁ ଭିନ୍ନ ମଡେଲ୍ ନାମକରଣ ପ୍ରଦର୍ଶନ କରନ୍ତି। କୋଟା ଅଂଶୀଦାରିତ — ଯେକୌଣସି ପ୍ରଦାନକାରୀର ବ୍ୟବହାର ସମାନ Google ଆକାଉଣ୍ଟର ସୀମାରେ ଗଣାଯାଏ।

## 2. Google One AI Pro: କୋଟା ସିଷ୍ଟମ୍

> ଅଧିକୃତ କୋଟା ବିବରଣୀ ପାଇଁ [Antigravity Docs: Plans](https://antigravity.google/docs/plans) ଏବଂ ସର୍ବଶେଷ ମୂଲ୍ୟ ଅପଡେଟ୍ ପାଇଁ [Changes to Antigravity Plans](https://antigravity.google/blog/changes-to-antigravity-plans) ଦେଖନ୍ତୁ।

Google Antigravity ବାର୍ତ୍ତା ସଂଖ୍ୟା ଉପରେ ନୁହେଁ, ବରଂ "ସମ୍ପନ୍ନ କାର୍ଯ୍ୟ" (ଗଣନାତ୍ମକ ଭାର) ଉପରେ ଆଧାରିତ ଏକ **ଦ୍ୱି-ସ୍ତରୀୟ କୋଟା** ବ୍ୟବହାର କରେ।

### ଦୁଇଟି ସ୍ତର

| ସ୍ତର                    | ଏହା କ’ଣ                               | ରିଫ୍ରେଶ୍ ଚକ୍ର                                                                                  |
| ----------------------- | ------------------------------------- | ---------------------------------------------------------------------------------------------- |
| **5-ଘଣ୍ଟିଆ ସ୍ପ୍ରିଣ୍ଟ୍** | "ସମ୍ପନ୍ନ କାର୍ଯ୍ୟ"ର ତତ୍କାଳ ଉପଲବ୍ଧ ପୁଲ୍ | ଏକ ସେସନ୍ରେ ପ୍ରଥମ ଅନୁରୋଧର 5 ଘଣ୍ଟା ପରେ ରିସେଟ୍ ହୁଏ                                                |
| **7-ଦିନିଆ ବେସ୍ଲାଇନ୍**   | ସାପ୍ତାହିକ ସର୍ବୋଚ୍ଚ ସୀମା               | ଏହି ସୀମାରେ ପହଞ୍ଚିଲେ 5-ଘଣ୍ଟିଆ ରିଫ୍ରେଶ୍କୁ ଅଗ୍ରାହ୍ୟ କରେ; ପରବର୍ତ୍ତୀ 7-ଦିନିଆ ଅବଧି ପର୍ଯ୍ୟନ୍ତ ଲକ୍ କରେ |

**"ସମ୍ପନ୍ନ କାର୍ଯ୍ୟ" କିପରି ଗଣନା କରାଯାଏ**: ଏଜେଣ୍ଟ-ଭାରୀ କାର୍ଯ୍ୟଗୁଡ଼ିକ (ଯେପରିକି "ଏହି ସମ୍ପୂର୍ଣ୍ଣ ରିପୋଜିଟୋରିକୁ ରିଫ୍ୟାକ୍ଟର୍ କରନ୍ତୁ") ସରଳ କାର୍ଯ୍ୟଗୁଡ଼ିକ (ଯେପରିକି "ଏହି ଫଙ୍କସନ୍ଟି ଠିକ୍ କରନ୍ତୁ") ତୁଳନାରେ ବହୁତ ଶୀଘ୍ର କୋଟା ବ୍ୟୟ କରେ। ବ୍ୟବହାର ଦେଖାଉଥିବା କୌଣସି ରିଅଲ୍-ଟାଇମ୍ ଡ୍ୟାସ୍ବୋର୍ଡ ନାହିଁ।

### Gemini ବନାମ Non-Gemini ମଡେଲ୍ଗୁଡ଼ିକ

- **Gemini ମଡେଲ୍ଗୁଡ଼ିକ** (Flash + Pro): API ମୂଲ୍ୟ ଅନୁଯାୟୀ ହ୍ରାସ ପାଉଥିବା ଏକକ ହାର ସୀମା ସେୟାର୍ କରନ୍ତି। ଯଦି Flash, Pro ତୁଳନାରେ 8x ଶସ୍ତା ହୁଏ, ତେବେ ଆପଣ 8x ଅଧିକ Flash ଟୋକେନ୍ ପାଇବେ।
- **Non-Gemini ମଡେଲ୍ଗୁଡ଼ିକ** (Claude, GPT-OSS): ଏଗୁଡ଼ିକର **ପୃଥକ** ହାର ସୀମା ରହିଛି। Gemini ଲକ୍ ହୋଇଥିଲେ ମଧ୍ୟ ଏଗୁଡ଼ିକ ଉପଲବ୍ଧ ରହିପାରେ।

### AI କ୍ରେଡିଟ୍ଗୁଡ଼ିକ (ଅତିରିକ୍ତ ବ୍ୟବହାର)

> କ୍ରେଡିଟ୍ କିପରି କାମ କରେ ତାହା ପାଇଁ [Google One AI credits](https://support.google.com/googleone/answer/14534406) ଦେଖନ୍ତୁ।

ବେସ୍ଲାଇନ୍ କୋଟା ଶେଷ ହେଲେ:

- **କେବେ ନୁହେଁ**: କୋଟା ରିଫ୍ରେଶ୍ ହେବା ପର୍ଯ୍ୟନ୍ତ ଅପେକ୍ଷା କରେ; "ବେସ୍ଲାଇନ୍ ମଡେଲ୍ କୋଟା ସୀମାରେ ପହଞ୍ଚିଛି" ଦେଖାଏ
- **ସର୍ବଦା**: ସ୍ୱୟଂଚାଳିତ ଭାବେ AI କ୍ରେଡିଟ୍ ବ୍ୟବହାର କରେ; ବେସ୍ଲାଇନ୍ ରିଫ୍ରେଶ୍ ହେଲେ ପୁଣି ତାହାକୁ ଫେରିଯାଏ

କ୍ରେଡିଟ୍ଗୁଡ଼ିକ ପୃଥକ ଭାବେ କିଣାଯାଏ ଏବଂ ମାନକ API ମୂଲ୍ୟ ଅନୁଯାୟୀ କଟାଯାଏ।

**ଆପଣଙ୍କ ଆକାଉଣ୍ଟ୍ର କୋଟା ଶେଷ ହେଲେ**: OmniRoute କମ୍ବୋ ରୁଟ୍ରେ ପରବର୍ତ୍ତୀ ଉପଲବ୍ଧ ଆକାଉଣ୍ଟ୍ ସହିତ ସ୍ୱୟଂଚାଳିତ ଭାବେ ପୁନଃଚେଷ୍ଟା କରେ। କୌଣସି ମାନୁଆଲ୍ ହସ୍ତକ୍ଷେପ ଆବଶ୍ୟକ ନାହିଁ।

## 3. projectId କିପରି ପାଇବେ

ପ୍ରତ୍ୟେକ antigravity/agy ସଂଯୋଗ ପାଇଁ ଏକ Google Cloud Code `projectId` ଆବଶ୍ୟକ। ଏହା ବିନା, `/v1internal:models` ଏଣ୍ଡପଏଣ୍ଟ୍ 404 ଫେରାଏ।

### ପଦ୍ଧତି A: ସ୍ୱୟଂଚାଳିତ (ସୁପାରିଶକୃତ)

OmniRoute ଏହାକୁ ସ୍ୱୟଂଚାଳିତ ଭାବେ ପରିଚାଳନା କରେ। ଆପଣ Dashboard OAuth ମାଧ୍ୟମରେ ଏକ ନୂଆ Google ଆକାଉଣ୍ଟ୍ ଯୋଡ଼ିବାବେଳେ:

1. OmniRoute ଟୋକେନ୍କୁ ରିଫ୍ରେଶ୍ କରେ
2. projectId ଖୋଜିବା ପାଇଁ `loadCodeAssist`କୁ କଲ୍ କରେ
3. କୌଣସି ପ୍ରୋଜେକ୍ଟ୍ ନଥିଲେ, ଗୋଟିଏ ସୃଷ୍ଟି କରିବା ପାଇଁ `onboardUser`କୁ କଲ୍ କରେ
4. ନୂଆ ଭାବେ ସୃଷ୍ଟି ହୋଇଥିବା projectId ପାଇବା ପାଇଁ `loadCodeAssist`କୁ ପୁନଃଚେଷ୍ଟା କରେ
5. ଏହାକୁ ଡାଟାବେସ୍ରେ ସେଭ୍ କରେ

**ଏହା ଅଧିକାଂଶ ଆକାଉଣ୍ଟ୍ ପାଇଁ କାମ କରେ** — କୌଣସି ମାନୁଆଲ୍ ପଦକ୍ଷେପ ଆବଶ୍ୟକ ନାହିଁ।

## 4. OAuth ପୁନଃନିର୍ଦ୍ଦେଶ URI

### ସମସ୍ୟା

Google OAuth ପାଇଁ ଏକ ବୈଧ ପୁନଃନିର୍ଦ୍ଦେଶ URI ଆବଶ୍ୟକ। OmniRoute ର ଡିଫଲ୍ଟ ଭାବେ `http://127.0.0.1:20128/callback` (ଲୁପ୍ବ୍ୟାକ୍) ବ୍ୟବହାର ହୁଏ। ଏହା ସ୍ଥାନୀୟ ବିଲ୍ଡ ପାଇଁ କାମ କରେ, କିନ୍ତୁ **ଦୂରସ୍ଥ ଡିପ୍ଲୟମେଣ୍ଟ ପାଇଁ ବିଫଳ ହୁଏ** (ଉଦାହରଣ ସ୍ୱରୂପ, LAN IP ମାଧ୍ୟମରେ ଆକ୍ସେସ୍ କରାଯାଉଥିବା ସର୍ଭର)।

Google ନିମ୍ନଲିଖିତ ପୁନଃନିର୍ଦ୍ଦେଶ URIଗୁଡ଼ିକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ:

- IP ଠିକଣା ବ୍ୟବହାର କରେ (`.com`, `.org` ଇତ୍ୟାଦିରେ ଶେଷ ହେଉଥିବା ଡୋମେନ୍ ହେବା ଆବଶ୍ୟକ)
- OAuth କ୍ଲାଏଣ୍ଟ କନଫିଗ୍ରେ ପଞ୍ଜୀକୃତ ପୁନଃନିର୍ଦ୍ଦେଶ URIଗୁଡ଼ିକ ସହିତ ମେଳ ଖାଏ ନାହିଁ

### ସମାଧାନ

**ବିକଳ୍ପ A: ଅନ୍ତର୍ନିହିତ OAuth ପ୍ରବାହ ବ୍ୟବହାର କରନ୍ତୁ (ଡିଫଲ୍ଟ)**

- ଆପଣ `localhost` କିମ୍ବା `127.0.0.1`ରୁ OmniRoute ଆକ୍ସେସ୍ କଲେ ଏହା କାମ କରେ
- କୌଣସି କନଫିଗରେସନ୍ ଆବଶ୍ୟକ ନାହିଁ

**ବିକଳ୍ପ B: କଷ୍ଟମ୍ OAuth ପ୍ରମାଣପତ୍ର**

- ଆପଣଙ୍କ ଏନ୍ଭାଇରନ୍ମେଣ୍ଟରେ `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` ସେଟ୍ କରନ୍ତୁ
- ନିଜର Google OAuth ପ୍ରମାଣପତ୍ର ପ୍ରଦାନ କରନ୍ତୁ:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Google Cloud Consoleରେ `https://your-domain.com/callback`କୁ ଏକ ଅନୁମୋଦିତ ପୁନଃନିର୍ଦ୍ଦେଶ URI ଭାବେ ପଞ୍ଜୀକୃତ କରନ୍ତୁ

**ବିକଳ୍ପ C: ପ୍ରାରମ୍ଭିକ ଲଗଇନ୍ ପାଇଁ agy CLI ବ୍ୟବହାର କରନ୍ତୁ**

- OmniRoute ଆକ୍ସେସ୍ କରିବାକୁ ଥିବା ମେସିନ୍ରେ `agy login` ଚଲାନ୍ତୁ
- OAuth ପ୍ରବାହ ସ୍ଥାନୀୟ ଭାବେ ସମ୍ପୂର୍ଣ୍ଣ ହୁଏ ଏବଂ ଟୋକେନ୍ଗୁଡ଼ିକ ସଂରକ୍ଷିତ ହୁଏ
- Dashboard ମାଧ୍ୟମରେ ସଂଯୋଗଟି OmniRouteକୁ ଆମଦାନୀ କରନ୍ତୁ

### ସୀମାବଦ୍ଧତା

- କଷ୍ଟମ୍ OAuth ପ୍ରମାଣପତ୍ର ପାଇଁ ଏକ ଡୋମେନ୍ ନାମ ଆବଶ୍ୟକ (Google ପୁନଃନିର୍ଦ୍ଦେଶ URI ଭାବେ IP ଠିକଣା ଗ୍ରହଣ କରେ ନାହିଁ)
- ଯଦି ଆପଣଙ୍କ ପାଖରେ ଡୋମେନ୍ ନାହିଁ, ତେବେ ଏହା ପରିବର୍ତ୍ତେ ବିକଳ୍ପ A କିମ୍ବା C ବ୍ୟବହାର କରନ୍ତୁ

## 5. ସମସ୍ୟା ନିବାରଣ: ସ୍ୱୟଂଚାଳିତ ସେଟଅପ୍ ବିଫଳ ହେଲେ

ଅଧିକାଂଶ ଆକାଉଣ୍ଟ ପାଇଁ OmniRoute ସ୍ୱୟଂଚାଳିତ ଭାବେ projectId ଅନ୍ୱେଷଣ ଏବଂ ଅନ୍ବୋର୍ଡିଂ ପରିଚାଳନା କରେ। ଏହା ବିଫଳ ହେଲେ, ମୂଳ କାରଣ ସାଧାରଣତଃ ନିମ୍ନଲିଖିତ ମଧ୍ୟରୁ ଗୋଟିଏ ହୋଇଥାଏ:

### ଆକାଉଣ୍ଟ ଅଞ୍ଚଳ ଅବରୋଧିତ ଅଛି

**ଲକ୍ଷଣ**: `agy login` ଚଲାଇଲେ "Eligibility check failed: Your current account is not eligible for Antigravity, because it is not currently available in your location." ଫେରାଏ।

**ମୂଳ କାରଣ**: Google ଆକାଉଣ୍ଟଗୁଡ଼ିକରେ ପଞ୍ଜୀକରଣ ସମୟରେ ସେଟ୍ ହୋଇଥିବା ଏକ ବ୍ୟାକ୍ଏଣ୍ଡ୍ "Country Association" ଫିଲ୍ଡ ଥାଏ। agy CLI ଏବଂ Cloud Code API ଏହି ଫିଲ୍ଡକୁ କଡ଼ାକଡ଼ି ଭାବେ ଯାଞ୍ଚ କରନ୍ତି — ୱେବ୍ Gemini କେବଳ ଆପଣଙ୍କ ବର୍ତ୍ତମାନର IP ଯାଞ୍ଚ କରିଥାଏ।

> ଆପଣଙ୍କ ଆକାଉଣ୍ଟ ସହିତ ସଂଯୁକ୍ତ ଅଞ୍ଚଳ ଯାଞ୍ଚ କିମ୍ବା ପରିବର୍ତ୍ତନ କରିବାକୁ, [Google ଦେଶ ସଂଯୋଗ ଫର୍ମ](https://policies.google.com/country-association-form) ପରିଦର୍ଶନ କରନ୍ତୁ।

**ୱେବ୍ Gemini କାମ କରୁଥିବାବେଳେ agy କାହିଁକି କାମ କରେ ନାହିଁ**:

- ୱେବ୍ Gemini / Google One: କେବଳ ବର୍ତ୍ତମାନର IP ଯାଞ୍ଚ କରେ (ପ୍ରକ୍ସି କାମ କରେ)
- agy CLI / Cloud Code API: ବ୍ୟାକ୍ଏଣ୍ଡ୍ Country Association ଫିଲ୍ଡ ପଢ଼େ (ପ୍ରକ୍ସି ସାହାଯ୍ୟ କରେ ନାହିଁ)

**ସମାଧାନ**:

1. US IP ବ୍ୟବହାର କରୁଥିବାବେଳେ [Google ଦେଶ ସଂଯୋଗ ଫର୍ମ](https://policies.google.com/country-association-form) ପରିଦର୍ଶନ କରନ୍ତୁ
2. ଅଞ୍ଚଳ ପରିବର୍ତ୍ତନ ଅନୁରୋଧ ଦାଖଲ କରନ୍ତୁ ("I live in a different country" ଚୟନ କରନ୍ତୁ)
3. Google ଦ୍ୱାରା ପ୍ରକ୍ରିୟାକରଣ ଏବଂ ଇମେଲ୍ ବିଜ୍ଞପ୍ତି ପାଇଁ 1-24 ଘଣ୍ଟା ଅପେକ୍ଷା କରନ୍ତୁ
4. ତା’ପରେ `agy login` ସଫଳ ହେବା ଉଚିତ

### ଆକାଉଣ୍ଟରେ କୌଣସି Cloud Code ପ୍ରୋଜେକ୍ଟ ନାହିଁ

**ଲକ୍ଷଣ**: ଲଗ୍ଗୁଡ଼ିକରେ `loadCodeAssist returned no project id` ଏବଂ `onboardUser failed (400)` ଦେଖାଯାଏ।

**ମୂଳ କାରଣ**: ଆକାଉଣ୍ଟଟି କେବେବି Google Cloud Code ସହିତ ପଞ୍ଜୀକୃତ ହୋଇନାହିଁ ଏବଂ ସ୍ୱୟଂଚାଳିତ ଅନ୍ବୋର୍ଡିଂ ବିଫଳ ହୋଇଛି।

**ସମାଧାନ**: Cloud Code ପଞ୍ଜୀକରଣ ଆରମ୍ଭ କରିବା ପାଇଁ ମାନୁଆଲ୍ ଭାବେ `agy login` ଚଲାନ୍ତୁ, ତା’ପରେ OmniRoute Dashboardରେ ଟୋକେନ୍ଟି ରିଫ୍ରେଶ୍ କରନ୍ତୁ।

### ଟୋକେନ୍ର ଅବଧି ସମାପ୍ତ ହୋଇଛି କିମ୍ବା ଏହା ପ୍ରତ୍ୟାହାର କରାଯାଇଛି

**ଲକ୍ଷଣ**: ଲଗ୍ଗୁଡ଼ିକରେ 401 ତ୍ରୁଟି କିମ୍ବା "Token has expired" ସନ୍ଦେଶ ଦେଖାଯାଏ।

**ସମାଧାନ**: Dashboard → Providers → agy → ରିଫ୍ରେଶ୍ ଆଇକନ୍ କ୍ଲିକ୍ କରନ୍ତୁରେ ଟୋକେନ୍ଟି ରିଫ୍ରେଶ୍ କରନ୍ତୁ। ଯଦି ରିଫ୍ରେଶ୍ ଟୋକେନ୍ଟି ନିଜେ ପ୍ରତ୍ୟାହାର କରାଯାଇଥାଏ, ତେବେ ଆପଣଙ୍କୁ OAuth ମାଧ୍ୟମରେ ପୁନଃ ପ୍ରମାଣୀକରଣ କରିବାକୁ ପଡ଼ିବ।
