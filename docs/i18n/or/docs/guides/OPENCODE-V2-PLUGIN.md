`@omniroute/opencode-plugin-v2` ଆପଣଙ୍କ ସମ୍ପୂର୍ଣ୍ଣ OmniRoute କ୍ୟାଟାଲଗ୍ — ମଡେଲ୍, କମ୍ବୋ ଏବଂ
ଅଟୋ-କମ୍ବୋ — ପ୍ରଦର୍ଶନ ନାମ, ମୂଲ୍ୟ ଏବଂ ମାଗଣା-ସ୍ତର ବଜେଟ୍ ସହିତ OpenCode v2ର ମଡେଲ୍ ଚୟନକର୍ତ୍ତାରେ
ଉପଲବ୍ଧ କରାଏ।

ଏହା `@omniroute/opencode-plugin`ଠାରୁ ଏକ ପୃଥକ ପ୍ୟାକେଜ୍, କାରଣ OpenCode v1 ଏବଂ v2
ଭିନ୍ନ ଚୁକ୍ତି ମାଧ୍ୟମରେ ପ୍ଲଗଇନ୍ ଲୋଡ୍ କରନ୍ତି। ଆପଣଙ୍କ OpenCodeର ମେଜର୍ ସଂସ୍କରଣ ସହ ମେଳ ଖାଉଥିବାଟି
ବାଛନ୍ତୁ; ସେମାନଙ୍କ ମଧ୍ୟରେ କିଛି ଅଂଶୀଦାର ନାହିଁ, ତେଣୁ ଗୋଟିଏକୁ ଅପ୍ଗ୍ରେଡ୍ କଲେ ଅନ୍ୟଟି ଉପରେ କୌଣସି ବାଧ୍ୟବାଧକତା ଆସେ ନାହିଁ।

## ଆବଶ୍ୟକତାଗୁଡ଼ିକ

- OpenCode v2।
- ପହଞ୍ଚଯୋଗ୍ୟ OmniRoute ଗେଟୱେ (ଡିଫଲ୍ଟ ଭାବେ `http://localhost:20128`)।
- Node.js 22 କିମ୍ବା 24।

## ଇନ୍ଷ୍ଟଲ୍ କରନ୍ତୁ

`opencode.json`ରେ ପ୍ଲଗଇନ୍ଟି ଯୋଡ଼ନ୍ତୁ:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

ତା’ପରେ ମଡେଲ୍ଗୁଡ଼ିକ `omniroute/<provider>/<model>` ଭାବେ ଦେଖାଯାଏ; `providerId` ସେହି ଉପସର୍ଗ ଏବଂ
OpenCode ଯେଉଁ ଇଣ୍ଟିଗ୍ରେସନ୍ ଆଇଡି ଅଧୀନରେ ପରିଚୟପତ୍ର ସଂରକ୍ଷଣ କରେ, ତାହା ନିର୍ଦ୍ଧାରଣ କରେ।

## ପରିଚୟପତ୍ର

ପ୍ଲଗଇନ୍ ନିମ୍ନଲିଖିତ କ୍ରମରେ ତିନୋଟି ସ୍ଥାନରେ ଗେଟୱେ କୀ ଖୋଜେ:

1. **OpenCodeରେ ଆପଣ ସଂଯୋଗ କରିଥିବା ପରିଚୟପତ୍ର।** ପ୍ଲଗଇନ୍ ଏକ ଇଣ୍ଟିଗ୍ରେସନ୍ ପଞ୍ଜୀକୃତ କରେ, ତେଣୁ
   OpenCodeର ନିଜସ୍ୱ ପ୍ରମାଣୀକରଣ ପ୍ରବାହ କୀଟି ସଂରକ୍ଷଣ କରିପାରେ। `opencode.json`ରେ କିଛି ସଂରକ୍ଷିତ ହୁଏ ନାହିଁ — ଏହାକୁ ପ୍ରାଥମିକତା ଦିଅନ୍ତୁ।
2. ପ୍ରତି-ପ୍ରକଳ୍ପ ଓଭର୍ରାଇଡ୍ ପାଇଁ ପ୍ଲଗଇନ୍ ବିକଳ୍ପଗୁଡ଼ିକରେ `apiKey`। ଏହା କୀଟିକୁ ଏପରି ଏକ ଫାଇଲ୍ରେ ରଖେ
   ଯାହାକୁ ଆପଣ କମିଟ୍ କରୁଥାଇପାରନ୍ତି।
3. ପରିବେଶରେ `OMNIROUTE_API_KEY`।

ଏହି ତିନୋଟି ମଧ୍ୟରୁ କୌଣସିଟି ନଥିଲେ, କ୍ୟାଟାଲଗ୍ ଖାଲି ରହେ ଏବଂ ନିରବରେ ଖାଲି ଚୟନକର୍ତ୍ତା ଛାଡ଼ିବା ପରିବର୍ତ୍ତେ
ପ୍ଲଗଇନ୍ ଷ୍ଟାର୍ଟଅପ୍ ସମୟରେ ଥରେ ଏହା ବିଷୟରେ ଜଣାଏ।

### ପରିଚାଳନା ଟୋକେନ୍ ଏକ ଭିନ୍ନ କୀ

କମ୍ବୋ, ପ୍ରଦାତା ସ୍ୱାସ୍ଥ୍ୟ ଏବଂ ସମୃଦ୍ଧିକରଣ (ପ୍ରଦର୍ଶନ ନାମ, ମୂଲ୍ୟ, ମାଗଣା-ସ୍ତର ବଜେଟ୍)
ଗେଟୱେର `/api/*` ଏଣ୍ଡପଏଣ୍ଟଗୁଡ଼ିକରୁ ଆସେ, ଯାହାକୁ ଅଧିକାଂଶ ଡିପ୍ଲୟମେଣ୍ଟ ଇନ୍ଫରେନ୍ସ କୀ ପରିବର୍ତ୍ତେ
ଏକ **ପରିଚାଳନା** ଟୋକେନ୍ ପଛରେ ସୁରକ୍ଷିତ କରନ୍ତି:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<management read token>"
}
```

ସେଟ୍ ନକରି ଛାଡ଼ିଦେଲେ, `managementReadToken` `apiKey`କୁ ଫଲ୍ବ୍ୟାକ୍ କରେ। ଯେତେବେଳେ କୌଣସି ଗେଟୱେ ସେହି ଫଲ୍ବ୍ୟାକ୍କୁ
ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ, କ୍ୟାଟାଲଗ୍ ତଥାପି ପ୍ରକାଶିତ ହୁଏ, କିନ୍ତୁ ପ୍ରଦର୍ଶନ ନାମ ପରିବର୍ତ୍ତେ କଞ୍ଚା ମଡେଲ୍ ଆଇଡି ସହିତ,
କ୍ୟାନୋନିକାଲ୍ ଉପନାମ ଡିଡ୍ୟୁପ୍ଲିକେସନ୍ ବିନା, ମୂଲ୍ୟ ବିନା ଏବଂ କମ୍ବୋ ବିନା। ଏହା ଘଟିଲେ ପ୍ଲଗଇନ୍ ପ୍ରତ୍ୟେକ ଏଣ୍ଡପଏଣ୍ଟ ପାଇଁ ଥରେ
ସତର୍କ କରେ ଏବଂ ଏଣ୍ଡପଏଣ୍ଟ ସହ କ’ଣ ହରାଇଗଲା ତାହାର ନାମ ଉଲ୍ଲେଖ କରେ — ତେଣୁ ଅବନତ ଚୟନକର୍ତ୍ତା କେବେବି ରହସ୍ୟ ହୋଇ ରହେ ନାହିଁ।

| `geminiSanitization`             | `true`                                        | ଟୁଲ୍ ସ୍କିମାରୁ Gemini ପ୍ରତ୍ୟାଖ୍ୟାନ କରୁଥିବା JSON-Schema କୀୱାର୍ଡଗୁଡ଼ିକୁ ବାହାର କରେ (`$ref` ଟୁଲ୍ଗୁଡ଼ିକ ଅପରିବର୍ତ୍ତିତ ଭାବେ ଫରୱାର୍ଡ ହୁଏ) |
| `apiFormat.allowAnthropic`       | `false`                                       | ଅନୁମତି ତାଲିକାଭୁକ୍ତ ଆଇଡିଗୁଡ଼ିକୁ Anthropic API ବ୍ଲକ୍ ମାଧ୍ୟମରେ ରୁଟ୍ କରେ                                                             |
| `apiFormat.anthropicModels`      | `[]`                                          | Anthropicକୁ ରୁଟ୍ କରାଯାଇଥିବା ସମ୍ପୂର୍ଣ୍ଣ ମଡେଲ୍ ଆଇଡି                                                                                |
| `logLevel` / `startupDebug`      | `warn` / `false`                              | ଲଗର୍ର ବିବରଣୀ ସ୍ତର                                                                                                                |

## କ୍ୟାଟାଲଗ୍ କିପରି ସତେଜ ରହେ

କ୍ୟାଟାଲଗ୍ଟି ଆବଶ୍ୟକତା ଅନୁଯାୟୀ ଫେଚ୍ କରାଯାଇ `modelCacheTtlMs` ପର୍ଯ୍ୟନ୍ତ କ୍ୟାଶ୍ କରାଯାଏ, ଏବଂ ଗେଟୱେ ଉପଲବ୍ଧ ନଥିବା ସମୟରେ ଏକ ଡିସ୍କ ସ୍ନାପ୍ଶଟ୍ ସର୍ବଶେଷ ଜଣାଶୁଣା କ୍ୟାଟାଲଗ୍କୁ
ଉପଲବ୍ଧ ରଖେ — ଏକ ବିଭ୍ରାଟ ଆପଣଙ୍କୁ ସତେଜତା ବ୍ୟତୀତ ଆଉ କିଛି ହରାଇବାକୁ ଦିଏ ନାହିଁ।
ମଡେଲ୍ ଏବଂ କମ୍ବୋଗୁଡ଼ିକ ପହଞ୍ଚିବା ମାତ୍ରେ ପ୍ରକାଶିତ ହୁଏ; ଅଟୋ-କମ୍ବୋ, ପ୍ରଦାନକାରୀ
ତାଲିକା ଏବଂ ସମୃଦ୍ଧୀକରଣ ଓଭରଲେ ପହଞ୍ଚିବା ପରେ ସେଥିରେ ସମ୍ମିଳିତ ହୁଏ, ତେଣୁ ଗୋଟିଏ ଧୀର ଏଣ୍ଡପଏଣ୍ଟ ସମଗ୍ର
ଚୟନକାରୀକୁ ଅଟକାଇ ରଖିପାରେ ନାହିଁ।

ନାମଗୁଡ଼ିକରେ ଗେଟୱେ ଜାଣିଥିବା ସୂଚନା ରହେ: ଏକ ମଡେଲ୍ ଯେଉଁ ଅପ୍ଷ୍ଟ୍ରିମ୍ ପ୍ରଦାନକାରୀକୁ ରାଉଟ୍ ହୁଏ, ଏକ `[Free]` ଚିହ୍ନ
ଏବଂ ଏହା ସହିତ ଆସୁଥିବା ବଜେଟ୍ — ଯାହାଦ୍ୱାରା ସମାନ ମଡେଲ୍ ବିକ୍ରି କରୁଥିବା ଦୁଇଟି ସଂଯୋଗକୁ
ପୃଥକ୍ ଭାବେ ଚିହ୍ନଟ କରାଯାଇପାରେ। `"providerTag": false` ସହିତ ଉପସର୍ଗଟିକୁ ବନ୍ଦ କରନ୍ତୁ।

କୌଣସି ମାନୁଆଲ୍ ରିଫ୍ରେଶ୍ କମାଣ୍ଡ ନାହିଁ: OpenCode v2 କମାଣ୍ଡଗୁଡ଼ିକ ପ୍ରମ୍ପ୍ଟ ଟେମ୍ପଲେଟ୍, କଲ୍ବ୍ୟାକ୍ ନୁହେଁ,
ତେଣୁ ଏକ ପ୍ଲଗିନ୍ ଏପରି କମାଣ୍ଡ ଉପଲବ୍ଧ କରାଇପାରିବ ନାହିଁ। ରିଫ୍ରେଶ୍ଗୁଡ଼ିକ TTL ଅନୁସରଣ କରେ; କ୍ୟାଟାଲଗ୍
କିମ୍ବା ଓଭରଲେ ପ୍ରକୃତରେ ବଦଳିଲେ ମାତ୍ର ହୋଷ୍ଟକୁ ପୁନଃଲୋଡ୍ କରିବାକୁ କୁହାଯାଏ, ପ୍ରତ୍ୟେକ ରିଫ୍ରେଶ୍ରେ ନୁହେଁ।

## Geminiରେ ଟୁଲ୍ କଲିଂ

ଯେଉଁ ସମ୍ପୂର୍ଣ୍ଣ ଅନୁରୋଧର ଟୁଲ୍ ଘୋଷଣାରେ `$schema` କିମ୍ବା
`additionalProperties` ଥାଏ, Gemini ତାହାକୁ `400 INVALID_ARGUMENT` ଉତ୍ତର ଦେଇ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ। ପ୍ଲଗିନ୍ଟି
ଏହି ପ୍ରଦାନକାରୀଙ୍କ Gemini ମଡେଲ୍କୁ ପଠାଯାଉଥିବା ଟୁଲ୍ ସ୍କିମାରୁ ସେହି କୀୱାର୍ଡଗୁଡ଼ିକୁ ହଟାଇଦିଏ ଏବଂ ଅନ୍ୟ ସମସ୍ତ ଅନୁରୋଧକୁ ଅପରିବର୍ତ୍ତିତ ରଖେ।
`$ref` ଥିବା ଏକ ଟୁଲ୍କୁ କିଛି ନ ହଟାଇ ଅପରିବର୍ତ୍ତିତ ଭାବେ ଫରୱାର୍ଡ କରାଯାଏ, କାରଣ
ରେଫରେନ୍ସଟି ହଟାଇଲେ ସ୍କିମାଟି "ଯେକୌଣସି କିଛି ଗ୍ରହଣ କରିବା" ପର୍ଯ୍ୟନ୍ତ ବ୍ୟାପକ ହୋଇଯିବ।
ଏହାକୁ ବନ୍ଦ କରିବା ପାଇଁ `"geminiSanitization": false` ସେଟ୍ କରନ୍ତୁ।
