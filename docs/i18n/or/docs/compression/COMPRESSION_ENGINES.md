OmniRoute ସଂକୋଚନ ଇଞ୍ଜିନ୍ ଚୁକ୍ତିଗୁଡ଼ିକୁ କେନ୍ଦ୍ର କରି ନିର୍ମିତ। ଗୋଟିଏ ମୋଡ୍ ସିଧାସଳଖ ଭାବେ ଗୋଟିଏ ଇଞ୍ଜିନ୍
(`caveman` କିମ୍ବା `rtk`) ଚଲାଇପାରେ କିମ୍ବା ଏକ ନିର୍ଦ୍ଧାରିତ ସ୍ତରୀକୃତ ପାଇପଲାଇନ୍ ଚଲାଇପାରେ, ଯାହା କ୍ରମାନୁସାରେ ଏକାଧିକ ଇଞ୍ଜିନ୍ ନିଷ୍ପାଦନ କରେ।

## ମୋଡ୍ଗୁଡ଼ିକ

| ମୋଡ୍ | ଇଞ୍ଜିନ୍ ପଥ | ଉଦ୍ଦିଷ୍ଟ ଇନପୁଟ୍ |
| ------------ | ------------------------------------------------------------------------------------- | ଠିକ୍ ପ୍ରମ୍ପ୍ଟ ସଂରକ୍ଷଣ |
| `off` | କିଛି ନାହିଁ | ନିମ୍ନ-ବିପଦ ସର୍ବଦା-ଅନ୍ କ୍ଲିନ୍ଅପ୍ |
| `lite` | Caveman lite helpers | ପ୍ରାକୃତିକ-ଭାଷା ପ୍ରମ୍ପ୍ଟ ସଂକ୍ଷେପଣ |
| `standard` | Caveman | ଦୀର୍ଘ ଚାଟ୍ ସେସନ୍ଗୁଡ଼ିକ |
| `aggressive` | Caveman + history/tool summarizers | ପ୍ରସଙ୍ଗ-ସୀମା ପୁନରୁଦ୍ଧାର |
| `ultra` | Caveman + pruning helpers | ଟର୍ମିନାଲ୍, ସେଲ୍, ବିଲ୍ଡ, ଟେଷ୍ଟ, ଏବଂ ଗିଟ୍ ଆଉଟପୁଟ୍ |
| `rtk` | RTK | ନେଟିଭ୍ ପ୍ରଦାନକାରୀ ୱାୟାରରେ ପ୍ରସଙ୍ଗ-ଭାବରେ-ପ୍ରତିଛବି |
| `omniglyph` | OmniGlyph | ମିଶ୍ରିତ ଟୁଲ୍ ଲଗ୍ ଏବଂ ଗଦ୍ୟ, ସର୍ବାଧିକ ସଞ୍ଚୟ |
| `stacked` | ପାଇପଲାଇନ୍। ଅନୁରୋଧ ଡିଫଲ୍ଟ ହେଉଛି `session-dedup -> lite`। `rtk -> caveman` ହେଉଛି ଅପ୍ଟ-ଇନ୍। |

### OmniGlyph କମ୍ପ୍ରେସନ୍ ପ୍ରୋଫାଇଲ୍ଗୁଡ଼ିକ

`omniglyph` ଇଞ୍ଜିନ୍ (ପ୍ୟାକେଜ୍ `omniglyph`, 1.4.0+) ଏକ ନାମିତ ସେମାଣ୍ଟିକ୍ ପ୍ରୋଫାଇଲ୍ ଗ୍ରହଣ କରେ, ଯାହା
କମ୍ପ୍ରେସନ୍ ସେଟିଂସରେ `omniglyph.profile` ମାଧ୍ୟମରେ ବିଶ୍ୱସ୍ତରରେ କିମ୍ବା
ଷ୍ଟାକ୍ଡ୍ ପାଇପଲାଇନ୍ର ଷ୍ଟେପ୍ କନଫିଗ୍ ମାଧ୍ୟମରେ ପ୍ରତି ଷ୍ଟେପ୍ରେ ସେଟ୍ ହୋଇଥାଏ:

| ପ୍ରୋଫାଇଲ୍     | ସୀମା                                                                                         |
| ------------- | -------------------------------------------------------------------------------------------- |
| `aggressive`  | ଡିଫଲ୍ଟ। ପ୍ରକାଶିତ ରସିଦଗୁଡ଼ିକ ମାପିଥିବା ନୀତି — ପ୍ରତିଛବି ସିଷ୍ଟମ୍, ଟୁଲ୍ ଡକ୍ୟୁମେଣ୍ଟ୍ ଏବଂ ଘନ ଇତିହାସ |
| `balanced`    | ଲାଇଭ୍ ଷ୍ଟେଟ୍କୁ ନେଟିଭ୍ ରଖେ, ଶେଷ 8 ଟର୍ଣ୍ଣକୁ ସୁରକ୍ଷା ଦିଏ, ପୁରୁଣା ବନ୍ଦ ଇତିହାସକୁ ସଙ୍କୁଚିତ କରେ     |
| `coding-safe` | ଅଥରିଟି, ଟୁଲ୍ ସ୍କିମା ଏବଂ ଲାଇଭ୍ ଟୁଲ୍ ଆଉଟପୁଟ୍କୁ ନେଟିଭ୍ ରଖେ, ଶେଷ 12 ଟର୍ଣ୍ଣକୁ ସୁରକ୍ଷା ଦିଏ         |
| `passthrough` | ରୂପାନ୍ତର ନକରି ରୁଟ୍ କରେ; ଇଞ୍ଜିନ୍କୁ ଛାଡି ଦିଆଯାଏ                                                |

ପ୍ରୋଫାଇଲ୍ ହେଉଛି ଏକ **ସିଲିଂ, ଫ୍ଲୋର୍ ନୁହେଁ**: ପ୍ୟାକେଜ୍ରେ `mergeCompressionProfileOptions`
କଲର୍କୁ ଏକ ଲସି ଲେନ୍କୁ ପୁନଃ ଖୋଲିବାକୁ ଅନୁମତି ଦିଏ ନାହିଁ ଯାହାକୁ ପ୍ରୋଫାଇଲ୍ ବନ୍ଦ କରିଛି, ତେଣୁ ଏକ ପ୍ରତି-ଷ୍ଟେପ୍
`preserveSystemPrompt: false` `coding-safe` ଅଧୀନରେ ସିଷ୍ଟମ୍ କମ୍ପ୍ରେସନ୍କୁ ପୁନଃ ସକ୍ଷମ କରିପାରିବ ନାହିଁ।

ଏହି କୋଡବେସ୍ରେ ମାପ କରାଯାଇଛି: `coding-safe` ଏବଂ `balanced` `minCompressChars`କୁ ଏହାର
ସର୍ବାଧିକକୁ ବଢ଼ାନ୍ତି ଏବଂ ସିଷ୍ଟମ୍, ଟୁଲ୍ ସ୍କିମା ଏବଂ ଟୁଲ୍ ଫଳାଫଳକୁ ନେଟିଭ୍ ରଖନ୍ତି, ତେଣୁ ଏକ ସେସନ୍ ଯାହା
ଇତିହାସ ସଂଗ୍ରହ କରିନାହିଁ ତାହା `below_min_chars`ରେ ଅଟକିଯାଏ ଏବଂ ଇଞ୍ଜିନ୍ କିଛି ରୂପାନ୍ତର କରେ ନାହିଁ।
ସେଥିପାଇଁ ଡିଫଲ୍ଟ ସବୁଠାରୁ ସୁରକ୍ଷିତ ପ୍ରୋଫାଇଲ୍ ଅପେକ୍ଷା `aggressive` ଅଟେ।

ପ୍ୟାକେଜ୍ ଏହାର ପରିବେଶ କନଫିଗରେସନ୍ରୁ ଏହାର ନିଜସ୍ୱ ମଡେଲ୍ ସ୍କୋପ୍ ଏବଂ ପ୍ରୋଫାଇଲ୍କୁ ସମାଧାନ କରେ।
OmniRoute କେବେ ବି ନିଷ୍ପତ୍ତିକୁ ପ୍ରତିନିଧିତ୍ୱ କରେ ନାହିଁ: ଆଡାପ୍ଟର୍ ମଡେଲ୍ ଗେଟ୍କୁ ପ୍ୟାକେଜ୍ର
ସବୁଠାରୁ ପ୍ରତିବନ୍ଧିତ ସ୍କୋପ୍ରେ ପିନ୍ କରେ, ତେଣୁ ହୋଷ୍ଟ ପରିବେଶ ସେଟିଂସଗୁଡ଼ିକ କେବଳ ଅନୁମତି ତାଲିକାକୁ ସଂକୀର୍ଣ୍ଣ କରିପାରିବ,
OmniRouteର ମାପିତ ରସିଦଗୁଡ଼ିକ ଅତିକ୍ରମ କରି କେବେ ବି ବିସ୍ତାର କରିପାରିବ ନାହିଁ।

## ଇଞ୍ଜିନ୍ ରେଜିଷ୍ଟ୍ରି

ରେଜିଷ୍ଟ୍ରିଟି `open-sse/services/compression/engines/registry.ts` ରେ ଅବସ୍ଥିତ। ଇଞ୍ଜିନ୍ଗୁଡ଼ିକ ଏକ ସାଧାରଣ
ଚୁକ୍ତି ପ୍ରକାଶ କରନ୍ତି:

- `id`: `caveman` କିମ୍ବା `rtk` ପରି ସ୍ଥିର ଇଞ୍ଜିନ୍ id
- `apply(text, config)`: ଷ୍ଟାକ୍ଡ ପାଇପ୍ଲାଇନ୍ଗୁଡ଼ିକ ଦ୍ୱାରା ବ୍ୟବହୃତ ପୁରୁଣା ନିଷ୍ପାଦନ ପଥ
- `compress(input, config)`: ଟେକ୍ସଟ୍ + ପରିସଂଖ୍ୟାନ ଫେରାଉଥିବା ପ୍ରାଥମିକ ନିଷ୍ପାଦନ ପଥ
- `getConfigSchema()`: ବୈଧ କନଫିଗ୍ର JSON-Schema-ସଦୃଶ ଆକୃତି ଫେରାଏ
- `validateConfig(config)`: `{ valid, errors[] }` ଫେରାଏ

ପଞ୍ଜୀକରଣ ପାଇଁ `registerCompressionEngine(engine)` (କିମ୍ବା ଉନ୍ନତ ପରିସ୍ଥିତିଗୁଡ଼ିକ ପାଇଁ `registerEngine`) ବ୍ୟବହାର କରାଯାଏ,
ଯାହା ଗ୍ରହଣ କରିବା ପୂର୍ବରୁ `assertValidEngine()` ଏବଂ `validateConfig(defaultConfig)` କୁ କଲ୍ କରେ।
ରନ୍ଟାଇମ୍ରେ ଏକ ଇଞ୍ଜିନ୍ ଅପସାରଣ କରିବାକୁ `unregisterCompressionEngine(id)` ବ୍ୟବହାର କରନ୍ତୁ।

କମ୍ପ୍ରେସନ୍ ଚାଲିବା ପୂର୍ବରୁ `strategySelector.ts` ବିଲ୍ଟ-ଇନ୍ ଇଞ୍ଜିନ୍ଗୁଡ଼ିକୁ ପଞ୍ଜୀକୃତ କରେ। ଏହା ପ୍ରିଭ୍ୟୁ,
ରନ୍ଟାଇମ୍ କମ୍ପ୍ରେସନ୍, ଷ୍ଟାକ୍ଡ ମୋଡ୍, ପରୀକ୍ଷଣ ଏବଂ ଭବିଷ୍ୟତ ଇଞ୍ଜିନ୍ଗୁଡ଼ିକୁ ସମାନ ନିଷ୍ପାଦନ ପଥ ବ୍ୟବହାର କରିବାକୁ ଦିଏ।

### MCP ବର୍ଣ୍ଣନା କମ୍ପ୍ରେସନ୍ (ସମ୍ପର୍କିତ)

ଏକ ପୃଥକ ରେଜିଷ୍ଟ୍ରି, ରେଜିଷ୍ଟ୍ରି ସ୍ତରରେ MCP ଟୁଲ୍ ବର୍ଣ୍ଣନା ମେଟାଡାଟାକୁ କମ୍ପ୍ରେସ୍ କରେ — ଦେଖନ୍ତୁ
`open-sse/mcp-server/descriptionCompressor.ts` ଏବଂ [MCP-SERVER.md](../frameworks/MCP-SERVER.md)। ଏହା Caveman ନିୟମଗୁଡ଼ିକୁ ପୁନଃବ୍ୟବହାର
କରେ, କିନ୍ତୁ ଅନୁରୋଧ ପେଲୋଡ୍ଗୁଡ଼ିକ ଉପରେ ନୁହେଁ, ଟୁଲ୍ ମେଟାଡାଟା ଉପରେ କାର୍ଯ୍ୟ କରେ।

## Caveman

Caveman ମୋଡ୍ ସାଧାରଣ ଗଦ୍ୟର ଅର୍ଥଗତ ସଂକ୍ଷିପ୍ତକରଣ ଉପରେ କେନ୍ଦ୍ରିତ:

- କୋଡ୍ ବ୍ଲକ୍, URL, JSON, ପାଥ୍ ଏବଂ ସଂରଚିତ ଡାଟାକୁ ସଂରକ୍ଷିତ ରଖେ
- ଅନାବଶ୍ୟକ ଶବ୍ଦ, ଅନିଶ୍ଚିତତାସୂଚକ ଭାଷା, ପୁନରାବୃତ୍ତ ପ୍ରସଙ୍ଗ ଏବଂ ଦୀର୍ଘ ସଂଯୋଜକ ବାକ୍ୟାଂଶକୁ ହଟାଏ
- `open-sse/services/compression/rules/`ରେ ଭାଷା-ସଚେତନ ଫାଇଲ୍ ନିୟମ ପ୍ୟାକ୍ଗୁଡ଼ିକୁ ସମର୍ଥନ କରେ
- ପୁରୁଣା `standard`, `aggressive` ଏବଂ `ultra` ମୋଡ୍ଗୁଡ଼ିକ ମାଧ୍ୟମରେ ଉପଲବ୍ଧ ରହେ

ଡ୍ୟାସ୍ବୋର୍ଡ ସ୍ଥାନ ହେଉଛି `Dashboard -> Context & Cache -> Caveman`।

Caveman ଅପ୍ଷ୍ଟ୍ରିମ୍ ପ୍ରାୟ `~75%` କମ୍ ଆଉଟ୍ପୁଟ୍ ଟୋକନ୍, ବେଞ୍ଚମାର୍କଗୁଡ଼ିକରେ `65%` ହାରାହାରି ଆଉଟ୍ପୁଟ୍ ସଞ୍ଚୟ
ଏବଂ `22-87%` ପରିସର ସହ ଏକ `~46%` ଇନ୍ପୁଟ୍-କମ୍ପ୍ରେସନ୍ ଟୁଲ୍ ରିପୋର୍ଟ କରେ। ଷ୍ଟାକ୍ କରାଯାଇଥିବା ପ୍ରମ୍ପ୍ଟ/କଣ୍ଟେକ୍ସ୍ଟ ସଞ୍ଚୟକୁ
ଦଲିଲଭୁକ୍ତ କରିବାବେଳେ OmniRoute, Cavemanର ଇନ୍ପୁଟ୍-ପକ୍ଷ ସଂଖ୍ୟା ବ୍ୟବହାର କରେ; Caveman ଆଉଟ୍ପୁଟ୍ ମୋଡ୍ ଏକ ପୃଥକ
ପ୍ରତିକ୍ରିୟା-ଆଚରଣ ବୈଶିଷ୍ଟ୍ୟ ଭାବେ ରହେ।

## LLMLingua-2 (ଅର୍ଥଗତ ଛାଟ)

LLMLingua-2 ମୋଡ୍ ଏକ ଛୋଟ ONNX ଟୋକନ୍
କ୍ଲାସିଫାୟର୍ ବ୍ୟବହାର କରି ଗଦ୍ୟରେ **ଅର୍ଥଗତ ଟୋକନ୍ ଛାଟ** କରେ, ଯାହା ନିୟମ-ଆଧାରିତ Caveman ଏବଂ RTK ଇଞ୍ଜିନ୍ଗୁଡ଼ିକର ପରିପୂରକ:

- କେବଳ ଅଣ-ସିଷ୍ଟମ୍ ସନ୍ଦେଶର ଗଦ୍ୟକୁ କମ୍ପ୍ରେସ୍ କରେ; ଫେନ୍ସ୍ଡ କୋଡ୍ ବ୍ଲକ୍ ଏବଂ ଅନ୍ୟ ସଂରକ୍ଷିତ
  ଗଠନଗୁଡ଼ିକୁ କେବେ ପରିବର୍ତ୍ତନ କରାଯାଏ ନାହିଁ
- ଏକ ୱର୍କର୍ ଥ୍ରେଡ୍ରେ `@atjsh/llmlingua-2` ବ୍ୟାକ୍ଏଣ୍ଡ (`@huggingface/transformers` ମାଧ୍ୟମରେ ONNX) ଚଲାଏ,
  ଯାହା ଫଳରେ ମଡେଲ୍ ଇନ୍ଫରେନ୍ସ କେବେ ମଧ୍ୟ ଅନୁରୋଧ ଇଭେଣ୍ଟ ଲୁପ୍କୁ ଅବରୋଧ କରେ ନାହିଁ
- ଏହା **ଷ୍ଟାକ୍ ଯୋଗ୍ୟ** (`stackPriority` 35): ଏକ ଷ୍ଟାକ୍ କରାଯାଇଥିବା ପାଇପ୍ଲାଇନ୍ରେ ଏହା
  ସଂରଚନାତ୍ମକ ଇଞ୍ଜିନ୍ଗୁଡ଼ିକ (CCR, session-dedup, headroom, Caveman) ପରେ, କିନ୍ତୁ `ultra` ପୂର୍ବରୁ ଚାଲେ, କାରଣ
  ପୂର୍ବରୁ ସଂରଚନାତ୍ମକ ଭାବେ କମ୍ପ୍ରେସ୍ ହୋଇଥିବା ପାଠ୍ୟରେ ଅର୍ଥଗତ ଛାଟ ସବୁଠାରୁ ପ୍ରଭାବଶାଳୀ — ଉଦାହରଣ ସ୍ୱରୂପ
  `rtk -> caveman -> llmlingua`
- **ଯେକୌଣସି ତ୍ରୁଟିରେ ଅବାଧ ଭାବେ ଜାରି ରହେ** (ଅନୁପସ୍ଥିତ ଇଚ୍ଛାଧୀନ ନିର୍ଭରତା, ୱର୍କର୍ ସ୍ପନ୍, ମଡେଲ୍ ଲୋଡ୍, ଇନ୍ଫରେନ୍ସ
  କିମ୍ବା ଟାଇମ୍ଆଉଟ୍) → କୌଣସି ତ୍ରୁଟି ନୁହେଁ, ମୂଳ ପାଠ୍ୟକୁ ଅପରିବର୍ତ୍ତିତ ଭାବେ ଫେରାଯାଏ

### ମଡେଲ୍ଗୁଡ଼ିକ

ଡିଫଲ୍ଟ ମଡେଲ୍ ହେଉଛି **TinyBERT** (`atjsh/llmlingua-2-js-tinybert-meetingbank`, ~57 MB,

`${DATA_DIR}/models/llmlingua` ମଧ୍ୟକୁ ଡାଉନ୍ଲୋଡ୍ କରେ (`modelStore.ts`); ଏହା ପରିବର୍ତ୍ତେ `modelPath` କନ୍ଫିଗ୍
ଓଭର୍ରାଇଡ୍ ଏହାକୁ ଏକ ସ୍ଥାନୀୟ କପି ପ୍ରତି ନିର୍ଦ୍ଦେଶ କରେ (ଅଫ୍ଲାଇନ୍ / ଏୟାର୍-ଗ୍ୟାପ୍ଡ ଇନ୍ଷ୍ଟଲ୍)।

### ଇଚ୍ଛାଧୀନ ନିର୍ଭରତା ଏବଂ ଆବଶ୍ୟକତା-ଅନୁସାରେ ଇନ୍ଷ୍ଟଲ୍

ଛାଟଯୋଗ୍ୟ LLMLingua ରନ୍ଟାଇମ୍ ପିଅର୍ ଷ୍ଟାକ୍ **ଇଚ୍ଛାଧୀନ**। ଦୁଇଟି ପ୍ୟାକେଜ୍କୁ
`package.json`ରେ `optionalDependencies` ଭାବେ ଘୋଷଣା କରାଯାଇଛି ଏବଂ ପ୍ରଡକ୍ସନ୍ ବିଲ୍ଡ ଦ୍ୱାରା **ବାହ୍ୟ** ରଖାଯାଇଛି
(`scripts/build/prepublish.ts` ସେଗୁଡ଼ିକୁ ବଣ୍ଡଲ୍ କରେ ନାହିଁ):

| ପ୍ୟାକେଜ୍             | ସଂସ୍କରଣ (ପିନ୍) | ଟିପ୍ପଣୀ                                           |
| -------------------- | -------------- | ------------------------------------------------- |
| `@atjsh/llmlingua-2` | `2.0.5`        | ପ୍ରବେଶ ପ୍ୟାକେଜ୍; ଅନ୍ୟଗୁଡ଼ିକୁ ପିଅର୍ ଭାବେ ଘୋଷଣା କରେ |
| `js-tiktoken`        | `^1.0.20`      | ଟୋକନାଇଜର୍                                         |

`@huggingface/transformers`କୁ `^4.2.0`ରେ ପିନ୍ କରାଯାଇଛି (ସ୍ଥାନୀୟ ଏମ୍ବେଡିଂ ପାଥ୍ ସହ ସହଭାଗୀ ଏବଂ
ସ୍ୱତନ୍ତ୍ର ବଣ୍ଡଲ୍ରେ ମଧ୍ୟ ଟ୍ରେସ୍ କରାଯାଇଛି); `@atjsh/llmlingua-2@2.0.5`, ଏହା ଉପରେ
`"^3.5.2 || ^4.0.0"` ସହିତ ପିଅର୍ ନିର୍ଭରତା ରଖେ, ତେଣୁ Transformers.js v3 ଏବଂ v4 ଉଭୟ ସମର୍ଥିତ। 2.0.4 ପରଠାରୁ,
`@atjsh/llmlingua-2`କୁ ଆଉ `@tensorflow/tfjs` ଆବଶ୍ୟକ ହୁଏ ନାହିଁ, ଯାହା SLM ଷ୍ଟାକ୍ରୁ ସବୁଠାରୁ ବଡ଼ ଏକକ
ଅବଦାନକାରୀ (TensorFlow.js)କୁ ହଟାଇଛି। କେବଳ ଉପରୋକ୍ତ ଦୁଇଟି ପ୍ୟାକେଜ୍ ଛାଟଯୋଗ୍ୟ SLM
ପିଅର୍। ଇଚ୍ଛାଧୀନ ନିର୍ଭରତାଗୁଡ଼ିକୁ ବାଦ ଦିଆନଯାଇଥିଲେ, ଏକ ମାନକ `npm install` (dev) ଇଚ୍ଛାଧୀନ ଷ୍ଟାକ୍କୁ ସ୍ୱୟଂଚାଳିତ ଭାବେ ଇନ୍ଷ୍ଟଲ୍ କରେ।

**ଆବଶ୍ୟକତା-ଅନୁସାରେ କାହିଁକି:** npmରେ ପ୍ରକାଶିତ ପ୍ୟାକେଜ୍, ସ୍ୱତନ୍ତ୍ର ବଣ୍ଡଲ୍ ଏବଂ Docker ଇମେଜ୍କୁ
ହାଲୁକା ରଖିବା ପାଇଁ ଏହି ନିର୍ଭରତାଗୁଡ଼ିକ **ବିନା** ପ୍ରଦାନ କରାଯାଏ। ସେଗୁଡ଼ିକ ଅନୁପସ୍ଥିତ ଥିବାବେଳେ, ୱର୍କର୍ର ନିର୍ଭରତା
ଗେଟ୍ (`worker.ts`ରେ ଏକ `@atjsh/llmlingua-2` ରିଜଲ୍ଭ ପ୍ରୋବ୍) ବିଫଳ ହୁଏ ଏବଂ ଇଞ୍ଜିନ୍
**ନିରବରେ ଅବାଧ ଭାବେ ଜାରି ରହେ** — LLMLingua ଚୟନ କରିବା ଏକ ନୋ-ଅପ୍ ହୋଇଯାଏ (ପାଠ୍ୟ ଅପରିବର୍ତ୍ତିତ ଭାବେ ଫେରେ, କୌଣସି
ତ୍ରୁଟି ଲଗ୍ କରାଯାଏ ନାହିଁ)। ଛାଟ କରାଯାଇଥିବା ପରିବେଶରେ ଏହାକୁ ସକ୍ରିୟ କରିବା ପାଇଁ, ଇଚ୍ଛାଧୀନ ଷ୍ଟାକ୍ ଇନ୍ଷ୍ଟଲ୍ କରନ୍ତୁ:

```bash
# package.json optionalDependenciesରେ ଘୋଷିତ ସଂସ୍କରଣଗୁଡ଼ିକୁ ପିନ୍ କରନ୍ତୁ
npm install @atjsh/llmlingua-2@2.0.5 js-tiktoken
```

`@tensorflow/tfjs` ଅପସାରଣ (2.0.4+) ପୂର୍ବରୁ ପ୍ରମୁଖ ~800 MB
ଅବଦାନକାରୀକୁ ହଟାଏ — ଅବଶିଷ୍ଟ ଆକାର ହେଉଛି transformers.js + onnxruntime-node ରନ୍ଟାଇମ୍,
ଏବଂ ପ୍ରଥମ ବ୍ୟବହାରରେ ଡାଉନ୍ଲୋଡ୍ ହେଉଥିବା TinyBERT ମଡେଲ୍ (~57 MB) (npm ମାଧ୍ୟମରେ ନୁହେଁ)।

ପ୍ରତ୍ୟେକ ପରିବେଶ ପାଇଁ:

- **Dev / `npm install`** — ଆପଣ `--omit=optional` (କିମ୍ବା `--no-optional`) ପାସ୍ କରିନଥିଲେ
  ସ୍ୱୟଂଚାଳିତ ଭାବେ ଇନ୍ଷ୍ଟଲ୍ ହୋଇଯାଏ। କୌଣସି ପଦକ୍ଷେପ ଆବଶ୍ୟକ ନାହିଁ।
- **ଗ୍ଲୋବାଲ୍ npm (`npm i -g omniroute`) / ସ୍ୱତନ୍ତ୍ର** — ଇନ୍ଷ୍ଟଲ୍ ହୋଇଥିବା ପ୍ୟାକେଜ୍
  ଡିରେକ୍ଟୋରୀ ଭିତରେ ଉପରୋକ୍ତ ଇନ୍ଷ୍ଟଲ୍ କମାଣ୍ଡ ଚଲାନ୍ତୁ, କିମ୍ବା ଇଚ୍ଛାଧୀନ ନିର୍ଭରଶୀଳତାଗୁଡ଼ିକୁ ବାଦ ନଦେଇ ପୁନଃ ଇନ୍ଷ୍ଟଲ୍ କରନ୍ତୁ।
- **Docker** — ଏକ ଡିରାଇଭ୍ଡ୍ ଇମେଜ୍ ଲେୟର୍ରେ ଇନ୍ଷ୍ଟଲ୍ କମାଣ୍ଡ ଯୋଡ଼ନ୍ତୁ; ପ୍ରକାଶିତ ଇମେଜ୍ଟି
  ଉଦ୍ଦେଶ୍ୟମୂଳକ ଭାବେ ସ୍ଲିମ୍ ରଖାଯାଇଛି।
- **VPS (PM2)** — ଆପ୍ର `node_modules` ଭିତରେ ଇନ୍ଷ୍ଟଲ୍ କରନ୍ତୁ, ତା’ପରେ ପ୍ରୋସେସ୍ଟି ପୁନଃଚାଳୁ କରନ୍ତୁ, ଯାହାଦ୍ୱାରା
  ୱର୍କର୍ ଗେଟ୍କୁ ପୁଣି ପ୍ରୋବ୍ କରିବ।
- **Raw Next ସ୍ୱତନ୍ତ୍ର (`npm run build` → `.build/next/standalone/server.js`)** — ସ୍ୱତନ୍ତ୍ର
  ଟ୍ରେସ୍ରେ ୱର୍କର୍ କିମ୍ବା ଇଚ୍ଛାଧୀନ ନିର୍ଭରଶୀଳତା—କୌଣସିଟି ମଧ୍ୟ ଥାଏ ନାହିଁ, ତେଣୁ ଇଞ୍ଜିନ୍ ନିରବରେ
  ଫେଲ୍-ଓପେନ୍ ହୁଏ। `scripts/build/colocate-standalone.mjs` ଉଭୟକୁ ପୁନଃ ପ୍ରୟୋଗ କରେ (ୱର୍କର୍ esbuild +
  ଇଚ୍ଛାଧୀନ-ନିର୍ଭରଶୀଳତା କ୍ଲୋଜର୍କୁ ସ୍ୱତନ୍ତ୍ର ଟ୍ରି ଭିତରେ); ପ୍ରତ୍ୟେକ ବିଲ୍ଡ ପରେ ଏହା
  `postbuild` npm ହୁକ୍ ମାଧ୍ୟମରେ ସ୍ୱୟଂଚାଳିତ ଭାବେ ଚାଲେ। ଏହା ଇଡେମ୍ପୋଟେଣ୍ଟ ଏବଂ ନିର୍ଭରଶୀଳତା ଅନୁପସ୍ଥିତ ଥିଲେ ଫେଲ୍-ସଫ୍ଟ ହୁଏ।

**ଏହା ସକ୍ରିୟ ଅଛି ବୋଲି ଯାଞ୍ଚ କରନ୍ତୁ:** LLMLingua ଚୟନ କରାଯାଇଥିଲେ, ପ୍ରକୃତ ଗଦ୍ୟ ବାସ୍ତବରେ ସଂକୁଚିତ ହୁଏ (ଇଞ୍ଜିନ୍

`${DATA_DIR}/models/llmlingua` ଭିତରେ ଡାଉନଲୋଡ୍ କରାଏ। ଗେଟ୍ଟି ଉଦ୍ଦେଶ୍ୟମୂଳକ ଭାବେ କେବଳ `@atjsh/llmlingua-2`କୁ ପ୍ରୋବ୍ କରେ —
ଅନ୍ୟ ପିୟର୍ଗୁଡ଼ିକ କେବଳ ESM ଏବଂ ସେଗୁଡ଼ିକ ଉପସ୍ଥିତ ଥିଲେ ମଧ୍ୟ `require.resolve` ସେଗୁଡ଼ିକ ଉପରେ ତ୍ରୁଟି ଥ୍ରୋ କରେ — ତେଣୁ

```txt
rtk -> caveman
```

ଯେଉଁ କୋଡିଂ-ଏଜେଣ୍ଟ ସେସନ୍ଗୁଡ଼ିକରେ ଏକ ପ୍ରମ୍ପ୍ଟ କମାଣ୍ଡ ଆଉଟପୁଟ୍କୁ ମାନବ କିମ୍ବା ସହାୟକଙ୍କ ଗଦ୍ୟ ସହିତ ଯୋଡ଼େ, ସେଗୁଡ଼ିକ ପାଇଁ ଏହା ବ୍ୟବହାର କରନ୍ତୁ। RTK ପ୍ରଥମେ କୋଳାହଳପୂର୍ଣ୍ଣ ଟୁଲ୍ ଲଗ୍ଗୁଡ଼ିକୁ ହ୍ରାସ କରେ, ତା’ପରେ Caveman ଅବଶିଷ୍ଟ ପ୍ରାକୃତିକ ଭାଷାକୁ ସଙ୍କୁଚିତ କରେ।

ପାଇପଲାଇନ୍ ପଦକ୍ଷେପଗୁଡ଼ିକ କମ୍ପ୍ରେସନ୍ ସେଟିଂସ୍ରେ `stackedPipeline` ଦ୍ୱାରା କିମ୍ବା କମ୍ପ୍ରେସନ୍ କମ୍ବୋଗୁଡ଼ିକ ମାଧ୍ୟମରେ କନଫିଗର୍ କରାଯାଏ।

ଯେତେବେଳେ ଉଭୟ ଇଞ୍ଜିନ୍ ସମାନ ଯୋଗ୍ୟ ପେଲୋଡ୍କୁ ହ୍ରାସ କରନ୍ତି, ସଞ୍ଚୟ ଯୌଗିକ ଭାବେ ବୃଦ୍ଧି ପାଏ:

```txt
combined = 1 - (1 - RTK savings) * (1 - Caveman input savings)
average  = 1 - (1 - 0.80) * (1 - 0.46) = 89.2%
range    = 1 - (1 - 0.60..0.90) * (1 - 0.46) = 78.4-94.6%
```

## MCP ଆକ୍ସେସିବିଲିଟି ଟ୍ରି ଫିଲ୍ଟର୍

MCP ଆକ୍ସେସିବିଲିଟି-ଟ୍ରି ସ୍ମାର୍ଟ ଫିଲ୍ଟର୍ ହେଉଛି ଏକ ପୋଷ୍ଟ-ଏକ୍ସିକ୍ୟୁସନ୍ କମ୍ପ୍ରେସନ୍ ସ୍ତର, ଯାହା ପ୍ରମ୍ପ୍ଟ କିମ୍ବା କଣ୍ଟେକ୍ସ୍ଟ ଉପରେ ନୁହେଁ, MCP **ଟୁଲ୍ ଫଳାଫଳଗୁଡ଼ିକ** ଉପରେ ଚାଲେ। ଏହା Playwright, computer-use ଏବଂ browser-automation MCP ସର୍ଭର୍ଗୁଡ଼ିକ ପରି ଟୁଲ୍ଗୁଡ଼ିକ ଦ୍ୱାରା ଫେରସ୍ତ କରାଯାଉଥିବା ଅତ୍ୟଧିକ ବିସ୍ତୃତ ଆକ୍ସେସିବିଲିଟି-ଟ୍ରି ଓ ବ୍ରାଉଜର୍ ସ୍ନାପ୍ଶଟ୍ ପେଲୋଡ୍ଗୁଡ଼ିକୁ ଲକ୍ଷ୍ୟ କରେ।

### ଏହା କ’ଣ କରେ

1. **ଅନାବଶ୍ୟକ ବିଷୟବସ୍ତୁ ଅପସାରଣ** — ଖାଲି generic/text ଏଣ୍ଟ୍ରିଗୁଡ଼ିକୁ (`- generic:`, `- text: ""`) ହଟାଏ
2. **ସିବ୍ଲିଂ କୋଲାପ୍ସ** — ଯେତେବେଳେ କ୍ରମାଗତ ≥ `collapseThreshold` (ଡିଫଲ୍ଟ 30) ଧାଡ଼ି ସଂରଚନାତ୍ମକ ଭାବେ ପୁନରାବୃତ୍ତ ହୁଏ, ସେଗୁଡ଼ିକୁ ପ୍ରଥମ `collapseKeepHead` (ଡିଫଲ୍ଟ 10) ଧାଡ଼ି + ଏକ ସଂଖ୍ୟା ସାରାଂଶ + ଶେଷ `collapseKeepTail` (ଡିଫଲ୍ଟ 5) ଧାଡ଼ିରେ ସଙ୍କୁଚିତ କରେ
3. **ରେଫ୍ ସଂରକ୍ଷଣ** — Playwright/computer-use ପାଇଁ ଆବଶ୍ୟକ `[ref=eXX]` ଆଙ୍କର୍ଗୁଡ଼ିକୁ କେବେବି ପରିବର୍ତ୍ତନ କରାଯାଏ ନାହିଁ
4. **ହାର୍ଡ ଟ୍ରଙ୍କେସନ୍** — କୋଲାପ୍ସ ପରେ ମଧ୍ୟ ଯଦି ଟେକ୍ସ୍ଟ `maxTextChars` (ଡିଫଲ୍ଟ 50,000) ଅତିକ୍ରମ କରେ, ତେବେ ଏଜେଣ୍ଟ ଯେପରି କାମ ଜାରି ରଖିପାରିବ ସେଥିପାଇଁ ଏକ ନାଭିଗେସନ୍ ସଙ୍କେତ ସହିତ ଏହାକୁ ଛୋଟ କରେ

### ଇଞ୍ଜିନ୍ର ଅବସ୍ଥାନ

```txt
open-sse/services/compression/engines/mcpAccessibility/
  index.ts            ← smartFilterText() entry point
  collapseRepeated.ts ← sibling-collapse algorithm
  constants.ts        ← DEFAULT_MCP_ACCESSIBILITY_CONFIG
```

### କନଫିଗରେସନ୍

ଗ୍ଲୋବାଲ୍ ସେଟିଂସ୍ରେ `compression.mcpAccessibility` (ମାଇଗ୍ରେସନ୍ 056) ଦ୍ୱାରା ନିୟନ୍ତ୍ରିତ। ଡିଫଲ୍ଟ କନଫିଗ୍:

```json
{
  "enabled": true,
  "maxTextChars": 50000,
  "collapseThreshold": 30,
  "collapseKeepHead": 10,
  "collapseKeepTail": 5,
  "minLengthToProcess": 2000
}
```

ଫିଲ୍ଟର୍ଟି କେବଳ ସେହି ଟୁଲ୍-ରେଜଲ୍ଟ ପେଲୋଡ୍ଗୁଡ଼ିକରେ ପ୍ରୟୋଗ ହୁଏ ଯାହାର `type` ହେଉଛି `"text"` ଏବଂ ଯାହାର ଦୈର୍ଘ୍ୟ `minLengthToProcess` ଅତିକ୍ରମ କରେ। ଏହା ପ୍ରମ୍ପ୍ଟ କମ୍ପ୍ରେସନ୍ କିମ୍ବା ରିକ୍ୱେଷ୍ଟ ପେଲୋଡ୍ଗୁଡ଼ିକୁ ପ୍ରଭାବିତ କରେ ନାହିଁ।

### ଆଶାକରାଯାଉଥିବା ସଞ୍ଚୟ

ପୃଷ୍ଠାର ଜଟିଳତା ଉପରେ ନିର୍ଭର କରି ବ୍ରାଉଜର୍ ସ୍ନାପ୍ଶଟ୍ ଟୁଲ୍ ଫଳାଫଳଗୁଡ଼ିକରେ 60–80%। କୋଲାପ୍ସ ଆଲଗୋରିଦମ୍ ଧାଡ଼ି ସଂଖ୍ୟା ଅନୁସାରେ O(n) ଅଟେ ଏବଂ ନଗଣ୍ୟ ବିଳମ୍ବ ଯୋଡ଼େ।

## ପରିସର ଏବଂ ବାଦ୍ଗୁଡ଼ିକ

**Embeddings କେବେବି ସଂକୋଚିତ ହୁଏ ନାହିଁ।** `open-sse/handlers/embeddings.ts` କେବେବି କୌଣସି
ସଂକୋଚନ ଇଞ୍ଜିନ୍କୁ କଲ୍ କରେ ନାହିଁ — ଅନୁରୋଧ/ପ୍ରତିକ୍ରିୟା ବଡିଗୁଡ଼ିକ ଅପରିବର୍ତ୍ତିତ ଭାବେ ସିଧାସଳଖ ଏକ୍ସିକ୍ୟୁଟର୍କୁ ଯାଏ।
ବର୍ତ୍ତମାନ ଏହା ଗଠନମୂଳକ (embeddings ଏବଂ chat completions ପୃଥକ୍ ହ୍ୟାଣ୍ଡଲର୍), ଏହା କୌଣସି
ରନ୍ଟାଇମ୍ ଯାଞ୍ଚ ନୁହେଁ, କିନ୍ତୁ ଏହାର ଅର୍ଥ #8034ରେ ଥିବା ଭେକ୍ଟର୍-ବିକୃତି ସମସ୍ୟାର
embeddings ପଥରେ କୌଣସି ପ୍ରଭାବ ପୃଷ୍ଠ ନାହିଁ।

**ପ୍ରତି-ମଡେଲ୍/ଏଣ୍ଡପଏଣ୍ଟ ବାଦ୍ ଫିଲ୍ଟର୍ (#8034)।** chat completions ପାଇଁ, ଏକ ଅପରେଟର୍
କେବେବି ସଂକୋଚିତ ହେବା ଉଚିତ୍ ନୁହେଁ ଏପରି ମଡେଲ୍ id / `provider/model` ଲକ୍ଷ୍ୟଗୁଡ଼ିକୁ ନାମିତ କରିପାରିବେ — ପରବର୍ତ୍ତୀ ସମୟରେ
ସଂକୋଚନକୁ embeddings-ସଂଲଗ୍ନ ପଥର ନିକଟରେ ସଂଯୋଜନ କରାଗଲେ ଏହା ଏକ ଉପଯୋଗୀ ସୁରକ୍ଷା ବ୍ୟବସ୍ଥା, ଏବଂ ସାଧାରଣତଃ
ଯେକୌଣସି ଏପରି ମଡେଲ୍ ପାଇଁ ଉପଯୋଗୀ ଯାହାର ସଠିକ୍ ବାଇଟ୍-ପ୍ରତି-ବାଇଟ୍ ପ୍ରମ୍ପ୍ଟ ଗୁରୁତ୍ୱପୂର୍ଣ୍ଣ (ନିର୍ଦ୍ଧାରଣବାଦୀ ମୂଲ୍ୟାୟନ, କ୍ୟାଶ୍-ସମ୍ବେଦନଶୀଳ
ପ୍ରିଫିକ୍ସ ଇତ୍ୟାଦି)।

- ସେଟିଂସ୍ ଫିଲ୍ଡ: ସାର୍ବଜନୀନ ସଂକୋଚନ ବିନ୍ୟାସରେ `exclusions?: string[]`
  (`GET`/`PUT /api/settings/compression`), ବିଦ୍ୟମାନ `key_value` ସଂକୋଚନ
  ନେମସ୍ପେସ୍ (`src/lib/db/compression.ts`) ମାଧ୍ୟମରେ ସ୍ଥାୟୀ ଭାବେ ସଂରକ୍ଷିତ — କୌଣସି ନୂତନ ଟେବୁଲ୍ ନାହିଁ।
- ଡ୍ୟାସବୋର୍ଡ ଟ୍ୟାବ୍: **Dashboard → Compression → Exclusions**
  (`/dashboard/compression/exclusions`)।
- ପ୍ୟାଟର୍ନ ସିଣ୍ଟାକ୍ସ: `*` ହେଉଛି ଏକମାତ୍ର ୱାଇଲ୍ଡକାର୍ଡ। ପ୍ୟାଟର୍ନରେ ଥିବା ଅନ୍ୟ ପ୍ରତ୍ୟେକ regex ମେଟାକ୍ୟାରେକ୍ଟର୍କୁ
  ମେଳ କରିବା ପୂର୍ବରୁ ଏସ୍କେପ୍ କରାଯାଏ, ତେଣୁ `gpt-5.6` କେବଳ ଆକ୍ଷରିକ ଷ୍ଟ୍ରିଙ୍ଗ୍ ସହିତ ମେଳ ଖାଏ, କେବେବି `gpt-5x6` ସହିତ ନୁହେଁ
  (ReDoS-ସୁରକ୍ଷିତ, ସୀମାବଦ୍ଧ, କୌଣସି ନେଷ୍ଟେଡ୍ କ୍ୱାଣ୍ଟିଫାୟର୍ ନାହିଁ)। ପ୍ୟାଟର୍ନଗୁଡ଼ିକ
  ଉଭୟ ଖାଲି ମଡେଲ୍ id ଏବଂ `provider/model` କମ୍ପୋଜିଟ୍ ସହିତ କେସ୍-ଅସମ୍ବେଦନଶୀଳ ଭାବେ ମେଳ ଖାଏ — `gpt-5-6`, `openai/gpt-5-6`,
  ଏବଂ `openai/*` ସବୁ କାମ କରେ, ଏବଂ କେବଳ `*` ପ୍ରତ୍ୟେକ ମଡେଲ୍କୁ ବାଦ୍ ଦିଏ।
- ମେଳକରଣ: `open-sse/services/compression/exclusions.ts`ରେ
  `isCompressionExcluded()` / `normalizeCompressionExclusions()`। `chatCore.ts` ସଂକୋଚନ ସେଟିଂସ୍ ସମାଧାନ କରିବାର
  ଠିକ୍ ପରେ, **କୌଣସି ଇଞ୍ଜିନ୍ ଚାଲିବା ପୂର୍ବରୁ**, ବାଦ୍ ଦିଆଯାଇଥିବା ଲକ୍ଷ୍ୟକୁ ଯାଞ୍ଚ କରେ ଏବଂ ଏକ ମେଳକୁ
  ସଂକୋଚନ ସାର୍ବଜନୀନ ଭାବେ ଅକ୍ଷମ ଥିବା ପରି ଠିକ୍ ସେହିଭଳି ବ୍ୟବହାର କରେ — ଅନୁରୋଧ ବଡି ପ୍ରମାଣଯୋଗ୍ୟ ଭାବେ
  ବାଇଟ୍-ସମାନ ରହେ। ଆନାଲିଟିକ୍ସରେ ଦୃଶ୍ୟମାନତା ପାଇଁ ଏହି ସ୍କିପ୍କୁ `writeCompressionSkip(..., "excluded")` ମାଧ୍ୟମରେ
  ରେକର୍ଡ କରାଯାଏ।
- ଡିଫଲ୍ଟ (ଖାଲି/ଅନୁପସ୍ଥିତ ତାଲିକା): pre-#8034 ଆଚରଣ ସହିତ ସମାନ — କିଛି ବି ବାଦ୍ ଦିଆଯାଏ ନାହିଁ।

## ଜଣାଶୁଣା ସୀମାବଦ୍ଧତାଗୁଡ଼ିକ

- **LLMLingua-2 (SLM) ପାଇଁ ସହ-ଅବସ୍ଥିତ ଇଚ୍ଛାଧୀନ ନିର୍ଭରଶୀଳତା ଆବଶ୍ୟକ।** କେବଳ
  `@atjsh/llmlingua-2` + ପିଅର୍ଗୁଡ଼ିକୁ `dist/node_modules` ମଧ୍ୟରେ ସହ-ଅବସ୍ଥିତ କରାଯାଇଥିଲେ
  worker ଏକ ପ୍ରଡକ୍ସନ୍ ବିଲ୍ଡ୍ରେ ଚାଲେ (`scripts/build/colocateOptionals.mjs`, #4286 ଦେଖନ୍ତୁ)। ସେଗୁଡ଼ିକ ବିନା
  ଇଞ୍ଜିନ୍ fail-open ହୁଏ (ମୂଳ ପାଠ୍ୟ ଫେରାଏ)। Worker ରିଜୋଲ୍ୟୁସନ୍ ଆଉ
  `import.meta.url` ଉପରେ ନିର୍ଭର କରେ ନାହିଁ (ଏହା standalone bundle ମଧ୍ୟରେ ବିଫଳ ହୁଏ) — ଏହା runtime
  cwd / `argv[1]` କୁ ଆଧାର କରେ।
- **Caveman ଭାଷା ପ୍ୟାକ୍ `de` / `fr` / `ja` ଆଂଶିକ।** ସେଗୁଡ଼ିକ `context` +
  `filler` + `structural` ନିୟମ ସହିତ ଆସେ, କିନ୍ତୁ `dedup` / `ultra` ପ୍ୟାକ୍ ନାହିଁ; ତେଣୁ ସେହି ଭାଷାଗୁଡ଼ିକ ପାଇଁ `ultra` ତୀବ୍ରତା
  `full` ଠାରୁ ଅଧିକ ଶକ୍ତିଶାଳୀ ନୁହେଁ (ସେମାନେ କେବଳ ନିଜସ୍ୱ ନିୟମ ବ୍ୟବହାର କରନ୍ତି — ଇଂରାଜୀ
  `dedup`/`ultra` ନିୟମକୁ କୌଣସି ନିରବ fall-back ନାହିଁ, ଯାହା ବିଦେଶୀ ପାଠ୍ୟକୁ ବିକୃତ କରିଦେଇପାରେ)।
  `en` / `es` / `id` / `pt-BR` ସମ୍ପୂର୍ଣ୍ଣ। ଆଂଶିକ ପ୍ୟାକ୍ଗୁଡ଼ିକ ପାଇଁ `dedup.json` + `ultra.json`
  ର ଅବଦାନ ସ୍ୱାଗତଯୋଗ୍ୟ।
- **Stacked telemetry କେବଳ ସଙ୍କୋଚନ କରିଥିବା ଇଞ୍ଜିନ୍ଗୁଡ଼ିକୁ ତାଲିକାଭୁକ୍ତ କରେ।** ଏକ stacked-pipeline ପଦକ୍ଷେପର
  ଇଞ୍ଜିନ୍ ଚାଲିଥିଲେ ମଧ୍ୟ 0 % ସଞ୍ଚୟ ହୋଇଥିଲେ, ଏହା `stats:null` ଫେରାଏ ଏବଂ ତେଣୁ
  `engineBreakdown` ରେ ଦେଖାଯାଏ ନାହିଁ — ଯାହା ଏଡ଼ାଇ ଦିଆଯାଇଥିବା ଏକ ପଦକ୍ଷେପଠାରୁ ପୃଥକ୍ କରିହୁଏ ନାହିଁ।
  "ଚାଲିଥିଲା, 0 %" କୁ "ଏଡ଼ାଇ ଦିଆଯାଇଥିଲା" ଠାରୁ ପୃଥକ୍ କରିବା ପାଇଁ breakdown-model ପରିବର୍ତ୍ତନ ଆବଶ୍ୟକ ହେବ ଏବଂ ଏହାକୁ ସ୍ଥଗିତ ରଖାଯାଇଛି।
