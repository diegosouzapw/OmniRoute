ପ୍ରତ୍ୟାୟୋଜିତ **Context Editing** ହେଉଛି କେବଳ Claude ପାଇଁ ଉପଲବ୍ଧ ଏକ କନ୍ଟେକ୍ସ୍ଟ-ପରିଚାଳନା ବୈଶିଷ୍ଟ୍ୟ। OmniRouteର ସ୍ଥାନୀୟ
କମ୍ପ୍ରେସନ୍ ଇଞ୍ଜିନ୍ଗୁଡ଼ିକ (Caveman, RTK, LLMLingua, stacked pipelines) — ଯେଉଁଗୁଡ଼ିକ ଅନୁରୋଧ ବଡିକୁ ପ୍ରକ୍ସିରୁ ବାହାରିବା
_ପୂର୍ବରୁ_ ପୁନଃଲିଖନ କରନ୍ତି — ସେଗୁଡ଼ିକଠାରୁ ଭିନ୍ନ ଭାବରେ, Context Editing **ପ୍ରଦାନକାରୀକୁ** ତାହାର ନିଜ ଚାଲୁଥିବା
କନ୍ଟେକ୍ସ୍ଟ ୱିଣ୍ଡୋରୁ ପୁରୁଣା tool-use / tool-result ବ୍ଲକ୍ଗୁଡ଼ିକୁ ସଫା କରିବାକୁ କହେ। OmniRoute କେବଳ ଏକ ବଡି
ପାରାମିଟର୍ (`context_management.edits[]`) ସଂଲଗ୍ନ କରେ; Claude ତାହାର ନିଜ tokenizer ଅନୁଯାୟୀ ପ୍ରକୃତ ସଫାକରଣ କରେ।

ଏହା ସ୍ୱଭାବତଃ ଏକ ପ୍ରତ୍ୟାୟୋଜିତ କ୍ଷମତା: ଅନ୍ୟ ପ୍ରଦାନକାରୀମାନେ ଏହି ପାରାମିଟର୍କୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରନ୍ତି, ତେଣୁ OmniRoute ଏହାକୁ
କେବଳ Claude ଏବଂ Claude-Code-ସୁସଙ୍ଗତ ରିଲେଗୁଡ଼ିକ ପର୍ଯ୍ୟନ୍ତ କଡ଼ାକଡ଼ି ଭାବେ ସୀମିତ ରଖେ।

ପ୍ରାମାଣିକ ଉତ୍ସ: `open-sse/config/contextEditing.ts` (ଷ୍ଟ୍ରାଟେଜି idଗୁଡ଼ିକ, ବଡି ଇଞ୍ଜେକ୍ସନ୍, ଟେଲିମେଟ୍ରି
ନିଷ୍କାଷଣ), `open-sse/executors/base.ts` (ଇଞ୍ଜେକ୍ସନ୍ ଗେଟ୍ + 400-ଫଲ୍ବ୍ୟାକ୍), ଏବଂ
`open-sse/services/compression/types.ts` (କନ୍ଫିଗ୍ ଆକୃତି + ଡିଫଲ୍ଟ)।

## `clear_tool_uses` କ’ଣ କରେ

OmniRoute ବାହାରକୁ ପଠାଯାଉଥିବା Anthropic Messages ବଡିରେ ଗୋଟିଏ ଏଡିଟ୍ ଇଞ୍ଜେକ୍ଟ କରେ:

```json
{
  "context_management": {
    "edits": [
      {
        "type": "clear_tool_uses_20250919",
        "trigger": { "type": "input_tokens", "value": 100000 },
        "keep": { "type": "tool_uses", "value": 3 }
      }
    ]
  }
}
```

- `type: "clear_tool_uses_20250919"` — ତାରିଖ-ଯୁକ୍ତ Anthropic ଷ୍ଟ୍ରାଟେଜି id (`CLEAR_TOOL_USES_STRATEGY`)।
- `trigger.value: 100000` — ଅନୁରୋଧର input tokenଗୁଡ଼ିକ ଏହି ସୀମା ଅତିକ୍ରମ କରିବା ପରେ, Claude ପୁରୁଣା
  tool-use/result ଯୋଡ଼ିଗୁଡ଼ିକୁ ସଫା କରିବା ଆରମ୍ଭ କରେ (`CONTEXT_EDITING_DEFAULT_TRIGGER_TOKENS`, Anthropicର ଡିଫଲ୍ଟ)।
- `keep.value: 3` — ସବୁଠାରୁ ସାମ୍ପ୍ରତିକ Nଟି tool-use/result ଯୋଡ଼ିକୁ ଅପରିବର୍ତ୍ତିତ ରଖାଯାଏ
  (`CONTEXT_EDITING_DEFAULT_KEEP_TOOL_USES`)।

ବିଟାକୁ `anthropic-beta: context-management-2025-06-27` ହେଡର୍ ମାଧ୍ୟମରେ ଘୋଷଣା କରାଯାଏ, ଯାହାକୁ
OmniRoute ପୂର୍ବରୁ Claude ଅନୁରୋଧଗୁଡ଼ିକରେ ପଠାଇଥାଏ।

ଇଞ୍ଜେକ୍ସନ୍ `applyContextEditingToBody()` ଦ୍ୱାରା କରାଯାଏ ଏବଂ ଏହା **idempotent**: ଯଦି ବଡିରେ ପୂର୍ବରୁ ଏକ `clear_tool_uses`
ଏଡିଟ୍ ରହିଛି (ପୂର୍ବ କଲ୍ରେ ଯୋଡ଼ାଯାଇଥିବା କିମ୍ବା କ୍ଲାଏଣ୍ଟ ଦ୍ୱାରା ଯୋଗାଇ ଦିଆଯାଇଥିବା), ତେବେ ବଡିକୁ
ଯେପରି ଅଛି ସେପରି ଛାଡ଼ି ଦିଆଯାଏ। ଯଦି ଏକ `clear_thinking_20251015` ଏଡିଟ୍ ମଧ୍ୟ ଉପସ୍ଥିତ ଅଛି, OmniRoute
`clear_thinking` ଏଡିଟ୍କୁ ସ୍ଥିର ଭାବରେ ସର୍ଟ୍ କରି ସାମ୍ନାକୁ ଆଣେ, କାରଣ Anthropic ଅନୁଯାୟୀ `edits[]` ଆରେରେ
`clear_thinking`, `clear_tool_uses` ପୂର୍ବରୁ ରହିବା ଆବଶ୍ୟକ।

## ପ୍ରତି-କମ୍ବୋ ସକ୍ଷମକରଣ ଟଗଲ୍

Context Editing ଡିଫଲ୍ଟ ଭାବରେ **ବନ୍ଦ** ଥାଏ ଏବଂ ଏହା opt-in ଅଟେ। ଟଗଲ୍ଟି କମ୍ପ୍ରେସନ୍ କନ୍ଫିଗ୍ରେ ରହିଥିବା ଏକମାତ୍ର boolean:

- ସେଟିଂ କି: `contextEditing.enabled` (camelCase — `context_editing` / `context-editing` **ନୁହେଁ**)।
- ପ୍ରକାର: `open-sse/services/compression/types.ts`ରେ
  `ContextEditingConfig { enabled: boolean }`।
- ଡିଫଲ୍ଟ: `DEFAULT_CONTEXT_EDITING_CONFIG = { enabled: false }`।
- Zod ସ୍କିମା: `src/shared/validation/compressionConfigSchemas.ts`ରେ `contextEditingConfigSchema`।
- ଷ୍ଟୋରେଜ୍: ଅବଶିଷ୍ଟ କମ୍ପ୍ରେସନ୍ ସେଟିଂଗୁଡ଼ିକ ସହିତ ସ୍ଥାୟୀ ଭାବରେ ସଂରକ୍ଷିତ (`src/lib/db/compression.ts`ରେ
  ନର୍ମାଲାଇଜ୍ କରାଯାଏ)।

ଡ୍ୟାସ୍ବୋର୍ଡରେ ଟଗଲ୍ଟି କମ୍ପ୍ରେସନ୍ ହବ୍ରେ
(`src/app/(dashboard)/dashboard/context/combos/CompressionHub.tsx`) ରହେ ଏବଂ `saveSettings()` ମାଧ୍ୟମରେ
`{ contextEditing: { enabled: … } }`କୁ ପୁନଃ ଲେଖେ। ଏହା କମ୍ପ୍ରେସନ୍-ସେଟିଂସ୍ ଅବଜେକ୍ଟ ସହିତ ବହନ ହେଉଥିବାରୁ, ଏହା ଏକ
ସମ୍ପୂର୍ଣ୍ଣ ସ୍ୱାଧୀନ ପୃଷ୍ଠ ହେବା ପରିବର୍ତ୍ତେ ପ୍ରତି-କମ୍ବୋ କମ୍ପ୍ରେସନ୍ ପ୍ରୋଫାଇଲ୍ ସହିତ ସଂଯୋଜିତ ହୁଏ — କନ୍ଫିଗ୍ରେ କେବଳ
ଚାଲୁ/ବନ୍ଦ ଫ୍ଲାଗ୍ ରହେ; ସମସ୍ତ ସୀମା (`trigger`, `keep`) ଉପରେ ଦଲିଲଭୁକ୍ତ କନ୍ଷ୍ଟାଣ୍ଟଗୁଡ଼ିକ ଅଟେ।

## କେବଳ Claude ପାଇଁ ଗେଟିଂ

ଇଞ୍ଜେକ୍ସନ୍ କେବଳ ପ୍ରକୃତ Claude କିମ୍ବା Claude-Code-ସୁସଙ୍ଗତ ରିଲେଗୁଡ଼ିକ ପାଇଁ ହୁଏ। `open-sse/executors/base.ts` ରେ ଥିବା ଗେଟ୍ ହେଉଛି:

```ts
if (
  (this.provider === "claude" || isClaudeCodeCompatible(this.provider)) &&
  contextEditing?.enabled &&
  !contextEditingDisabled
) {
  applyContextEditingToBody(transformedBody, { enabled: true });
}
```

- `this.provider === "claude"` — ପ୍ରକୃତ Anthropic କୀ/OAuth।
- `isClaudeCodeCompatible(this.provider)` — ଯେଉଁ ରିଲେଗୁଡ଼ିକର provider id
  `anthropic-compatible-cc-` ଉପସର୍ଗରୁ ଆରମ୍ଭ ହୁଏ (ସେମାନେ Claude Code ସୁସଙ୍ଗତତା ଘୋଷଣା କରନ୍ତି, ତେଣୁ ସେମାନେ
  beta ଗ୍ରହଣ କରିବାର ସର୍ବାଧିକ ସମ୍ଭାବନା ଥିବା ରିଲେ)। `open-sse/services/provider.ts` ଦେଖନ୍ତୁ।

ଜାଣିଶୁଣି **ବାଦ ଦିଆଯାଇଛି**:

- `claude-web` — `create_conversation_params` ଅନୁରୋଧ ଆକୃତି ଥିବା ଏକ ବ୍ରାଉଜର୍ ରିଲେ, ଯାହା କେବେବି
  `context_management` ଦେଖେ ନାହିଁ।
- ସାଧାରଣ `anthropic-compatible-*` ରିଲେଗୁଡ଼ିକ (`-cc-` ଉପସର୍ଗ ବିନା) — ଅନିଶ୍ଚିତ
  beta ସମର୍ଥନ ଥିବା ତୃତୀୟ-ପକ୍ଷ ଏଣ୍ଡପଏଣ୍ଟଗୁଡ଼ିକ।

ଟଗଲ୍ ଚାଲୁ ଥିଲେ ମଧ୍ୟ ଅଣ-Claude providerଗୁଡ଼ିକ କେବେବି `context_management` ପାରାମିଟର୍ ପ୍ରାପ୍ତ କରନ୍ତି ନାହିଁ।

## 400 fallback / ରିଲେ କଭରେଜ୍

ଏକ Claude-ସୁସଙ୍ଗତ ରିଲେ beta ଘୋଷଣା କରିପାରେ, କିନ୍ତୁ ତଥାପି HTTP 400 ସହିତ `context_management` ପାରାମିଟର୍କୁ
ପ୍ରତ୍ୟାଖ୍ୟାନ କରିପାରେ। ଅନୁରୋଧକୁ ବିଫଳ କରିବା ପରିବର୍ତ୍ତେ ସୁଚାରୁ ଭାବେ ପଛକୁ ଫେରିବା ପାଇଁ, executor ପାରାମିଟର୍ଟିକୁ
ହଟାଇ ସେହି URLକୁ **ଥରେ** ପୁନଃଚେଷ୍ଟା କରେ:

```ts
if (
  response.status === HTTP_STATUS.BAD_REQUEST &&
  contextEditing?.enabled &&
  !contextEditingDisabled &&
  transformedBody?.context_management !== undefined
) {
  const errText = await response
    .clone()
    .text()
    .catch(() => "");
  if (/context[_-]management|context editing/i.test(errText)) {
    contextEditingDisabled = true;
    delete transformedBody.context_management;
    let retryBody = JSON.stringify(transformedBody);
    if (isClaudeCodeCompatible(this.provider) || this.provider === "claude") {
      retryBody = await signRequestBody(retryBody);
    }
    response = await fetch(url, { ...fetchOptions, body: retryBody });
  }
}
```

ଆଚରଣ:

1. context editing ସକ୍ଷମ ଥିବା ଏବଂ bodyରେ ପ୍ରକୃତରେ `context_management` ଥିବା ସମୟରେ କେବଳ ଏକ `400` ଉପରେ ଏହା ଟ୍ରିଗର୍ ହୁଏ।
2. 400 bodyକୁ ଏକ `clone()` ମାଧ୍ୟମରେ ପଢ଼ାଯାଏ, ଯାହାଦ୍ୱାରା ମେଳ ନ ହେଉଥିବା ପଥ ପାଇଁ ମୂଳ response ଅକ୍ଷୁଣ୍ଣ ରହେ।
3. ତ୍ରୁଟି ପାଠ୍ୟ `/context[_-]management|context editing/i` ସହିତ ମେଳ ହେବା ଆବଶ୍ୟକ — ଏକ ଅସମ୍ବନ୍ଧିତ 400 (ଯଥା
   `max_tokens must be >= 1`) fallbackକୁ ଟ୍ରିଗର୍ କରେ **ନାହିଁ**; ମୂଳ ତ୍ରୁଟି ପ୍ରସାରିତ ହୁଏ।
4. ମେଳ ହେଲେ ଏହା `contextEditingDisabled = true` ସେଟ୍ କରେ (ଯାହା ପରବର୍ତ୍ତୀ ସମୟରେ retry/fallback URL ପାଇଁ ଏକ ନୂତନ
   `transformedBody` ତିଆରି ହେଲେ ପୁନଃ-ଇଞ୍ଜେକ୍ସନ୍କୁ ଦମନ କରେ), `context_management` ବିଲୋପ କରେ,
   Claude / Claude-Code-ସୁସଙ୍ଗତ ରିଲେଗୁଡ଼ିକ ପାଇଁ bodyକୁ ପୁନଃ-ସ୍ୱାକ୍ଷର କରେ (`signRequestBody`), ଏବଂ ସେହି
   URLକୁ ଥରେ ପୁନଃଚେଷ୍ଟା କରେ।

ପ୍ରକୃତ Claude `ANTHROPIC_BETA_BASE` ରେ betaକୁ ବହନ କରେ ଏବଂ ଏହି fallback ପଥକୁ ଯାଏ ନାହିଁ।

## `applied_edits` ଟେଲିମେଟ୍ରି

ଏକ Claude response ପରେ, provider ପ୍ରକୃତରେ କେତେ context ସଫା କଲା ତାହା OmniRoute ରେକର୍ଡ କରେ। ଏହା
**stream କରାଯାଏ ନାହିଁ** — ଏହା non-streaming response bodyରୁ ସର୍ବୋତ୍ତମ ପ୍ରୟାସରେ ବାହାର କରାଯାଏ ଏବଂ
responseକୁ କେବେବି ପ୍ରଭାବିତ କରେ ନାହିଁ (ଟେଲିମେଟ୍ରି ବିଫଳତାଗୁଡ଼ିକୁ ଅଣଦେଖା କରାଯାଏ)।

- ନିଷ୍କାସନ: `open-sse/config/contextEditing.ts` ରେ `extractContextEditingTelemetry(responseBody)`।
  ଏହା ତିନୋଟି ସ୍ଥାନରେ `applied_edits` ଯାଞ୍ଚ କରେ (response ଆକୃତି ପ୍ରତି ସତର୍କତାମୂଳକ ଭାବେ):
  - `context_management.applied_edits`
  - `usage.context_management.applied_edits`
  - `usage.applied_edits`
- ପ୍ରତ୍ୟେକ entryରୁ ପଢ଼ାଯାଉଥିବା fieldଗୁଡ଼ିକ: `cleared_input_tokens` ଏବଂ `cleared_tool_uses`
  (snake_case, Anthropic-native), ସହିତ `clearedInputTokens` / `clearedToolUses` camelCase fallback।
- କୌଣସି `applied_edits` array ନ ମିଳିଲେ କିମ୍ବା ପ୍ରକୃତରେ କିଛି ସଫା ହୋଇନଥିଲେ `null` ଫେରାଏ।

receiptର ଆକୃତି ହେଉଛି `ContextEditingTelemetry { editCount, clearedInputTokens, clearedToolUses }`।
ରେକର୍ଡିଂ `open-sse/handlers/chatCore.ts` ରେ (`provider === "claude"` ପାଇଁ gated)
`recordContextEditingTelemetry()` (`src/lib/db/compressionAnalytics.ts`) ମାଧ୍ୟମରେ ହୁଏ, ଯାହା ନିମ୍ନପ୍ରକାର tag ହୋଇଥିବା ଏକ compression
analytics row ଲେଖେ:

- `mode: "context-editing"`
- `engine: "context-editing"`
- `tokens_saved` / `original_tokens` = ସଫା କରାଯାଇଥିବା input-token ସଂଖ୍ୟା
- `request_id` ସହିତ `::context-editing` ପ୍ରତ୍ୟୟ ଯୋଡ଼ାଯାଇଛି

ତେଣୁ ପ୍ରତିନିଧିତ୍ୱ ମାଧ୍ୟମରେ ହୋଇଥିବା clearing ସ୍ଥାନୀୟ engineଗୁଡ଼ିକ ସହିତ compression analyticsରେ,
`context-editing` engine label ଅଧୀନରେ ଦେଖାଯାଏ ଏବଂ RTK/Caveman/LLMLingua ସଞ୍ଚୟଠାରୁ ପୃଥକ ଭାବେ ଚିହ୍ନଟ କରାଯାଇପାରେ।
