## ଫିଚର୍ ଫ୍ଲାଗ୍ କ'ଣ

ଏକ ଫିଚର୍ ଫ୍ଲାଗ୍ ହେଉଛି ଏକ ନାମିତ ଟଗଲ୍ (ବୁଲିଆନ୍ କିମ୍ବା ଏନମ୍) ଯାହାର ମୂଲ୍ୟ ରନଟାଇମ୍ ରେ ପରିବର୍ତ୍ତନ କରାଯାଇପାରିବ ଏବଂ ଡାଟାବେସ୍ ରେ ସ୍ଥାୟୀ ଭାବରେ ସଂରକ୍ଷିତ ହୋଇପାରିବ, କୌଣସି ପ୍ରକ୍ରିୟା ରିଡିପ୍ଲୟ ଆବଶ୍ୟକ ନାହିଁ। ପ୍ରତ୍ୟେକ ଫ୍ଲାଗ୍ ଏକ `FeatureFlagDefinition` ଦ୍ୱାରା ବର୍ଣ୍ଣିତ ହୋଇଥାଏ ଯେଉଁଥିରେ ଏକ `key`, `label`, `description`, `category`, `defaultValue`, `type`, ଏବଂ ଏକ `requiresRestart` ସୂଚନା ଥାଏ।

### ରିଜୋଲ୍ୟୁସନ୍ ଅର୍ଡର

ଏକ ଫ୍ଲାଗ୍ ର **ପ୍ରଭାବଶାଳୀ ମୂଲ୍ୟ** ଏହି ପ୍ରାଧାନ୍ୟ (ସର୍ବୋଚ୍ଚ ବିଜୟ) ସହିତ
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) ଦ୍ୱାରା ରିଜୋଲ୍ଭ କରାଯାଏ:

1.  **DB override** — `key_value` ଟେବୁଲ୍ ରେ `feature_flags` ନାମସ୍ପେସ୍ ଅଧୀନରେ ସଂରକ୍ଷିତ ଏକ ମୂଲ୍ୟ (ଡ୍ୟାସବୋର୍ଡ କିମ୍ବା REST API ମାଧ୍ୟମରେ ସେଟ୍ କରାଯାଇଛି)।
2.  **ପରିବେଶ ଭେରିଏବଲ୍** — `process.env[<KEY>]`, ଯଦି ସେଟ୍ ହୋଇଛି ଏବଂ ଖାଲି ନୁହେଁ।
3.  **ଡେଫିନିସନ୍ ଡିଫଲ୍ଟ** — `featureFlagDefinitions.ts` ରୁ `defaultValue`।

ଏକ ବୁଲିଆନ୍ ଫ୍ଲାଗ୍ **ସକ୍ଷମ** ବୋଲି ବିବେଚନା କରାଯାଏ ଯେତେବେଳେ ଏହାର ପ୍ରଭାବଶାଳୀ ମୂଲ୍ୟ `"true"`, `"1"`, କିମ୍ବା `"yes"` ହୋଇଥାଏ (`isFeatureFlagEnabled()` ଦେଖନ୍ତୁ)।

> [!NOTE]
> ଅଧିକାଂଶ ଫ୍ଲାଗ୍ ରେ [`ENVIRONMENT.md`](./ENVIRONMENT.md) ରେ ଡକ୍ୟୁମେଣ୍ଟ୍ ହୋଇଥିବା **ସମାନ ନାମ** ର ଏକ ମେଳ ଖାଉଥିବା ପରିବେଶ ଭେରିଏବଲ୍ ମଧ୍ୟ ଥାଏ। ଫ୍ଲାଗ୍ ର DB ଓଭରରାଇଡ୍ ସେହି ପରିବେଶ ଭେରିଏବଲ୍ ଉପରେ ପ୍ରାଧାନ୍ୟ ନେଇଥାଏ। `requiresRestart: true` ଥିବା ଏକ ଫ୍ଲାଗ୍ ତୁରନ୍ତ ସ୍ଥାୟୀ ହୋଇଥାଏ କିନ୍ତୁ କେବଳ ପ୍ରକ୍ରିୟା ଆରମ୍ଭରେ ପୁନଃ ପଢ଼ାଯାଏ — ଏହାକୁ ଟଗଲ୍ କରିବା ଦ୍ୱାରା ଡ୍ୟାସବୋର୍ଡରେ ଏକ **"ସର୍ଭର ପୁନଃ ଆରମ୍ଭ କରନ୍ତୁ"** ବ୍ୟାନର୍ ଦେଖାଯାଏ।

> ତୁରନ୍ତ ସ୍ଥାୟୀ ଭାବେ ସଂରକ୍ଷିତ ହୁଏ, କିନ୍ତୁ ପ୍ରକ୍ରିୟା ପୁନଃଲୋଡ୍ ହେବା ପରେ ହିଁ ପ୍ରଭାବୀ ହୁଏ। Enum
> ଫ୍ଲାଗ୍ଗୁଡ଼ିକ ସେମାନଙ୍କର ଅନୁମୋଦିତ ସେଟ୍ ବାହାରର ଯେକୌଣସି ମୂଲ୍ୟକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ (
> `setFeatureFlagOverride()` ଏବଂ REST `PUT` ହ୍ୟାଣ୍ଡଲର୍—ଉଭୟରେ ସର୍ଭର୍ ପକ୍ଷରୁ ବୈଧତା ଯାଞ୍ଚ କରାଯାଏ)।

## ଫ୍ଲାଗ୍ସ ଟୋଗଲ୍ କରିବା

### ଡ୍ୟାସବୋର୍ଡ

**ଡ୍ୟାସବୋର୍ଡ → ସେଟିଙ୍ଗ୍ସ → ଫିଚର୍ ଫ୍ଲାଗ୍ସ** (`/dashboard/settings/feature-flags`) କୁ ଯାଆନ୍ତୁ। ଗ୍ରିଡ୍
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`) ନିମ୍ନଲିଖିତକୁ ସମର୍ଥନ କରେ:

- କି' କିମ୍ବା ବର୍ଣ୍ଣନା ଅନୁଯାୟୀ **ଖୋଜନ୍ତୁ**, ଏବଂ ବର୍ଗ ଅନୁଯାୟୀ **ଫିଲ୍ଟର୍ କରନ୍ତୁ** (ଏକ ସିନ୍ଥେଟିକ୍ **ପୁନଃ ଆରମ୍ଭ ଆବଶ୍ୟକ** ଦୃଶ୍ୟ ସହିତ)।
- ବୁଲିଆନ୍ ଫ୍ଲାଗ୍ସ ପାଇଁ ଏକ **ଟୋଗଲ୍** ଏବଂ ଏନମ୍ ଫ୍ଲାଗ୍ସ ପାଇଁ ଏକ **ଡ୍ରପ୍ଡାଉନ୍**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`)।
- ପ୍ରତ୍ୟେକ ଫ୍ଲାଗ୍ ପାଇଁ ଏକ **ଉତ୍ସ ବ୍ୟାଜ୍** — `DB`, `ENV`, କିମ୍ବା `DEF` — ଯାହା ପ୍ରଭାବଶାଳୀ ମୂଲ୍ୟ କେଉଁଠାରୁ ଆସିଛି ତାହା ଦର୍ଶାଏ।
- ଓଭରରାଇଡ୍ ଛାଡ଼ିବା ପାଇଁ ଏକ **ରିସେଟ୍** ବଟନ୍ (କେବଳ `DB`-ଉତ୍ସ ଫ୍ଲାଗ୍ସ ପାଇଁ ଦର୍ଶାଯାଇଛି), ଏବଂ ତଳେ ଏକ **ସମସ୍ତ ଓଭରରାଇଡ୍ ରିସେଟ୍ କରନ୍ତୁ** ବଟନ୍।
- ଯେତେବେଳେ ଏକ `requiresRestart` ଫ୍ଲାଗ୍ ପରିବର୍ତ୍ତନ କରାଯାଏ, ସେତେବେଳେ ଏକ **ସର୍ଭର ପୁନଃ ଆରମ୍ଭ** ବ୍ୟାନର୍।

### REST API

ସମସ୍ତ କାର୍ଯ୍ୟ ଗୋଟିଏ ରୁଟ୍ ମାଧ୍ୟମରେ ଯାଏ:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts)।
ପ୍ରତ୍ୟେକ ମେଥଡ୍ ପାଇଁ ଏକ ପ୍ରମାଣୀକୃତ ଡ୍ୟାସବୋର୍ଡ ସେସନ୍ ଆବଶ୍ୟକ (`401` ଅନ୍ୟଥା)।

#### `GET /api/settings/feature-flags`

ଏହାର ପ୍ରଭାବଶାଳୀ ମୂଲ୍ୟ, ଉତ୍ସ ଏବଂ ଏକ ସାରାଂଶ ସହିତ ପ୍ରତ୍ୟେକ ଫ୍ଲାଗ୍ ଫେରାଇଥାଏ।

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... all 77 flags
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

ଗୋଟିଏ ଓଭରରାଇଡ୍ ସେଟ୍ କରନ୍ତୁ କିମ୍ବା ହଟାନ୍ତୁ। ବଡି: `{ key: string; value?: string }`।
`value` ଛାଡ଼ିଦେଲେ ଓଭରରାଇଡ୍ ହଟାଇଦିଏ (env / ଡିଫଲ୍ଟ ପୁନଃସ୍ଥାପିତ କରେ)।

```bash
# ଏକ DB ଓଭରରାଇଡ୍ ସେଟ୍ କରନ୍ତୁ
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# ଓଭରରାଇଡ୍ ହଟାନ୍ତୁ ("value" ନାହିଁ)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

ପ୍ରତିକ୍ରିୟା ନୂତନ `effectiveValue`/`source`, `previousValue`/
`previousSource`, ଏବଂ `requiresRestart` କୁ ପ୍ରତିଧ୍ୱନିତ କରେ। ଅଜ୍ଞାତ କି' ଏବଂ ସୀମା ବାହାରେ ଥିବା ଏନମ୍
ମୂଲ୍ୟଗୁଡ଼ିକୁ `400` ସହିତ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଏ।

#### `DELETE /api/settings/feature-flags`

ଏକକାଳୀନ **ସମସ୍ତ** DB ଓଭରରାଇଡ୍ ସଫା କରେ, ପ୍ରତ୍ୟେକ ଫ୍ଲାଗ୍କୁ ଏହାର env / ଡିଫଲ୍ଟ
ମୂଲ୍ୟକୁ ପୁନଃସ୍ଥାପିତ କରେ। `{ cleared: <count>, message: "..." }` ଫେରାଇଥାଏ।

> [!NOTE]
> `requiresRestart: true` ଥିବା ଫ୍ଲାଗ୍ଗୁଡ଼ିକ କେବଳ ଏକ ପ୍ରକ୍ରିୟା ପୁନଃଲୋଡ୍ ପରେ କାର୍ଯ୍ୟକାରୀ ହୁଏ।
> ଡ୍ୟାସବୋର୍ଡର ପୁନଃ ଆରମ୍ଭ ପ୍ରବାହ `POST /api/restart` କୁ କଲ୍ କରେ ଏବଂ ତା’ପରେ
> ସର୍ଭର ପୁନର୍ବାର କାର୍ଯ୍ୟକ୍ଷମ ହେବା ପର୍ଯ୍ୟନ୍ତ `GET /api/health/ping` କୁ ପୋଲ୍ କରେ।

ଅନୁରୋଧଗୁଡ଼ିକ ସେମାନଙ୍କ ବଜେଟ୍ ଶେଷ କରିଦିଅନ୍ତି, ସେଗୁଡ଼ିକ ସିଧାସଳଖ ବିଫଳ ହେବା ପରିବର୍ତ୍ତେ

ଏବଂ ବଜେଟ୍-ଶେଷ ହୋଇଥିବା ଅନୁରୋଧଗୁଡ଼ିକୁ ବିଫଳ ହେବାକୁ ଦେବା ପାଇଁ ଏହାକୁ `false` (କିମ୍ବା `0`)
କୁ ସେଟ୍ କରନ୍ତୁ — ଡ୍ୟାସବୋର୍ଡ ଟୋଗଲ୍, ଏକ DB ଓଭରରାଇଡ୍, କିମ୍ବା
`OMNIROUTE_EMERGENCY_FALLBACK` ପରିବେଶ ଭେରିଏବଲ୍ ମାଧ୍ୟମରେ।
(PRs #3741 / #3752 ରେ ଏକ ଡ୍ୟାସବୋର୍ଡ ଟୋଗଲ୍ ଭାବରେ ପ୍ରକାଶିତ।)
