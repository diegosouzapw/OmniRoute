## ସାରାଂଶ

OmniRoute ବର୍ତ୍ତମାନ `/api/v1/relay/chat/completions` ପାଇଁ ତିନୋଟି ରିଲେ ମୋଡ୍ ସମର୍ଥନ କରେ:

- `ts`: ପ୍ରକ୍ରିୟା ମଧ୍ୟରେ TypeScript ରିଲେ ବ୍ୟବହାର କରନ୍ତୁ।
- `bifrost`: Bifrost ଗେଟୱେକୁ ବାଧ୍ୟତାମୂଳକ ଭାବେ ବ୍ୟବହାର କରନ୍ତୁ।
- `auto`: ଉପଲବ୍ଧ ଥିଲେ Bifrostକୁ ପ୍ରାଥମିକତା ଦିଅନ୍ତୁ, ବିଫଳ ହେଲେ TypeScriptକୁ ଫଲ୍ବ୍ୟାକ୍ କରନ୍ତୁ।

ଉଚ୍ଚ ଅନୁରୋଧ ହାରରେ (ପ୍ରତିଦିନ ବହୁ ସଂଖ୍ୟକ ଟୋକେନ୍, ପ୍ରାୟ ନିରନ୍ତର ଥ୍ରୁପୁଟ୍) ଚାଲୁଥିବା ବେଳେ, ସର୍ବୋତ୍ତମ କୌଶଳ ହେଉଛି ଫଲ୍ବ୍ୟାକ୍ ପଥକୁ ସ୍ପଷ୍ଟ ଏବଂ ଦ୍ରୁତ ରଖିବା, ଯାହାଦ୍ୱାରା ହଟ୍ ପାଥ୍ କେବେବି ଏକ ଅଚଳ ସାଇଡ୍କାର୍ ପାଇଁ ଅବରୋଧିତ ହେବ ନାହିଁ।

## ମୋଡ୍ର ଆଚରଣ

- `ts`
  - ସର୍ବନିମ୍ନ ପରିଚାଳନାଗତ ଜଟିଳତା।
  - ସମସ୍ତ ରାଉଟିଂ ଏବଂ ବୈଧୀକରଣ Nodeରେ ଚାଲେ।
  - ଉପଲବ୍ଧତା ପାଇଁ କୌଣସି ସାଇଡ୍କାର୍ ନିର୍ଭରଶୀଳତା ନାହିଁ।
- `bifrost`
  - ସମସ୍ତ ଅନୁରୋଧକୁ ସାଇଡ୍କାର୍ ଗେଟୱେ ମାଧ୍ୟମରେ ଯିବାକୁ ବାଧ୍ୟ କରେ।
  - କୌଣସି ସ୍ୱୟଂଚାଳିତ ଫଲ୍ବ୍ୟାକ୍ ନାହିଁ।
  - କେବଳ ସାଇଡ୍କାର୍ର ସ୍ୱାସ୍ଥ୍ୟ ଏବଂ ବିଳମ୍ବତା ନିଶ୍ଚିତ ଥିବା ବେଳେ ଉପଯୋଗୀ।
- `auto`
  - ସାଇଡ୍କାର୍ ସକ୍ଷମ ଥିଲେ ଏବଂ ତାହା ସହ ଯୋଗାଯୋଗ କରିହେଲେ, ଏହା ବ୍ୟବହୃତ ହୁଏ।
  - ବିଫଳ ପ୍ରୟାସଗୁଡ଼ିକ ଫଲ୍ବ୍ୟାକ୍ ହେଡର୍କୁ ସକ୍ରିୟ କରେ ଏବଂ ଟ୍ରାଫିକ୍କୁ TSକୁ ଫେରାଇଦିଏ, ଫଳରେ ଅନୁରୋଧର ସଫଳତା ଏକ ନିର୍ଦ୍ଧାରିତ ସୀମା ମଧ୍ୟରେ ରହେ।
  - କେବଳ ସାଇଡ୍କାର୍ ମାଧ୍ୟମରେ କଠୋର ରାଉଟିଂ ଅପେକ୍ଷା ଅପ୍ଟାଇମ୍ ଅଧିକ ଗୁରୁତ୍ୱପୂର୍ଣ୍ଣ ଥିବା ପ୍ରଡକ୍ସନ୍ ପରିବେଶ ପାଇଁ ଏହି ମୋଡ୍ ସବୁଠାରୁ ସୁରକ୍ଷିତ ବିକଳ୍ପ।

## ଆଜିର 9router ବନାମ CLIPROXYAPI

9router ଏବଂ CLIPROXYAPI ଉଭୟ ଏପରି ଇଣ୍ଟିଗ୍ରେସନ୍, ଯେଉଁଗୁଡ଼ିକ ଐତିହାସିକ ଭାବେ ଅପ୍ଷ୍ଟ୍ରିମ୍ ପ୍ରଦାନକାରୀମାନଙ୍କ ପାଇଁ ସୁସଙ୍ଗତତା ପଥ ପ୍ରଦାନ କରିଆସିଛି।

- 9router ହେଉଛି ଅପ୍ଷ୍ଟ୍ରିମ୍ ଅର୍କେଷ୍ଟ୍ରେସନ୍ ଏବଂ ସୁସଙ୍ଗତତା ଆଚରଣ ପାଇଁ ଏକ ଏମ୍ବେଡେଡ୍ ପଥ।
- CLIPROXYAPI ହେଉଛି CLI / SDK ଶୈଳୀର ଟ୍ରାଫିକ୍ ପାଇଁ ଏକ ପ୍ରକ୍ସି API ବ୍ରିଜ୍।
- ଏକ ଉତ୍ସର୍ଗୀକୃତ ସାଇଡ୍କାର୍-ସଦୃଶ ହପ୍ ଏବଂ କମ୍ ବିଳମ୍ବତାର ସ୍ଥାନୀୟ ଡିସ୍ପାଚ୍ ଆବଶ୍ୟକ ହେଲେ, Bifrostକୁ ବାହ୍ୟୀକୃତ ପଥ ଭାବେ ସ୍ଥିର କରାଯାଉଛି।

ଆପଣ ବର୍ତ୍ତମାନ 9router/CLIPROXYAPI ତୁଳନା କରୁଥିଲେ:

- ହ୍ୟାଣ୍ଡଅଫ୍ ପୂର୍ବରୁ API ରୁଟ୍ରେ ଅନୁରୋଧ ସ୍ୱାକ୍ଷରକରଣ, ଅଲାଉଲିଷ୍ଟ ଯାଞ୍ଚ ଏବଂ DB ନୀତି ଗେଟ୍ଗୁଡ଼ିକୁ ରଖନ୍ତୁ।
- କୌଣସି ୱାର୍କଫ୍ଲୋ ପାଇଁ କଠୋର ସାଇଡ୍କାର୍ ଆଚରଣ ଏବଂ ପ୍ରତି-ଅନୁରୋଧରେ କମ୍ ବିଚଳନ ଆବଶ୍ୟକ ହେଲେ, `OMNIROUTE_RELAY_BACKEND=bifrost` ବ୍ୟବହାର କରନ୍ତୁ।
- ଘଟଣା ପରିସ୍ଥିତିରେ ସୁବ୍ୟବସ୍ଥିତ ଅବନତି ସହିତ ସାଇଡ୍କାର୍ର ସହନଶୀଳତା ଆବଶ୍ୟକ ହେଲେ, `OMNIROUTE_RELAY_BACKEND=auto` ବ୍ୟବହାର କରନ୍ତୁ।

## ବ୍ୟାକ୍ଏଣ୍ଡ ସୀମା ଚୁକ୍ତି

ସ୍ଥିର ଉତ୍ପାଦ ସୀମା ହେଉଛି OmniRoute ରିଲେ API, ଡ୍ୟାସ୍ବୋର୍ଡ ଇମ୍ପ୍ଲିମେଣ୍ଟେସନ୍ ନୁହେଁ। Next.js ଡ୍ୟାସ୍ବୋର୍ଡ ସ୍ଥାନୀୟ ସେବାଗୁଡ଼ିକୁ ଇନ୍ଷ୍ଟଲ୍, କନ୍ଫିଗର୍ ଏବଂ ତଦାରଖ କରିପାରେ, କିନ୍ତୁ ଅନୁରୋଧ ରାଉଟିଂ ରିଲେ API ମାଧ୍ୟମରେ ପ୍ରବେଶ କରିବା ଏବଂ ସେହି ସୀମା ପଛରେ ହ୍ୟାଣ୍ଡଅଫ୍ ହେବା ଉଚିତ।

ଦୀର୍ଘମିଆଦୀ ବ୍ୟାକ୍ଏଣ୍ଡ ବିକଳ୍ପଗୁଡ଼ିକ:

- TypeScript ରିଲେକୁ ପ୍ରକ୍ରିୟା-ମଧ୍ୟସ୍ଥ ନୀତି ଏବଂ ଫଲ୍ବ୍ୟାକ୍ ପଥ ଭାବେ ରଖନ୍ତୁ। ଯେକୌଣସି ବ୍ୟାକ୍ଏଣ୍ଡ ହ୍ୟାଣ୍ଡଅଫ୍ ପୂର୍ବରୁ ପ୍ରାମାଣିକରଣ, ଅଲାଉଲିଷ୍ଟ, ଅନୁରୋଧ ସାମାନ୍ୟୀକରଣ, ହିସାବ ଏବଂ ସୁରକ୍ଷା ଯାଞ୍ଚ ଏଠାରେ ରହିବ।
- ଡିପ୍ଲୟମେଣ୍ଟ ପାଇଁ କମ୍ ରାଉଟିଂ ବିଚଳନ, କେନ୍ଦ୍ରୀକୃତ ପ୍ରଦାନକାରୀ ରୋଟେସନ୍ କିମ୍ବା ଏକାଧିକ OmniRoute ରେପ୍ଲିକାରେ ସ୍କେଲ୍-ଆଉଟ୍ ଆବଶ୍ୟକ ହେଲେ, Bifrostକୁ ପସନ୍ଦିତ ଉଚ୍ଚ-ଥ୍ରୁପୁଟ୍ Tier-1 ସାଇଡ୍କାର୍ ଭାବେ ବ୍ୟବହାର କରନ୍ତୁ।
- 9router ଏବଂ CLIPROXYAPIକୁ ଏମ୍ବେଡେଡ୍ ସୁସଙ୍ଗତତା ସେବା ଭାବେ ରଖନ୍ତୁ। ସେଗୁଡ଼ିକ ତଦାରଖ ହେଉଥିବା ସ୍ଥାନୀୟ ପ୍ରକ୍ରିୟା ଭାବେ ଚାଲେ ଏବଂ ଯେତେବେଳେ ସେମାନଙ୍କର ପ୍ରଦାନକାରୀ/CLI ଆଚରଣ ଇଚ୍ଛିତ ଆଡାପ୍ଟର୍ ହୁଏ ସେତେବେଳେ ଉପଯୋଗୀ, କିନ୍ତୁ ସେଗୁଡ଼ିକ ଡିଫଲ୍ଟ Tier-1 ରାଉଟିଂ ଇଞ୍ଜିନ୍ ହେବା ଉଚିତ ନୁହେଁ।
- ଡ୍ୟାସ୍ବୋର୍ଡକୁ ହଟ୍ ପାଥ୍ରେ ଇଚ୍ଛାମତା ସେବା URL ପାସ୍ କରିବାକୁ ଦିଅନ୍ତୁ ନାହିଁ। UI-ପ୍ରଦତ୍ତ URLଗୁଡ଼ିକ କନ୍ଫିଗରେସନ୍ ଇନ୍ପୁଟ୍; ରାଉଟିଂ କୋଡ୍ ସର୍ଭର୍-ସାଇଡ୍ ସେଟିଂସ୍ ଏବଂ ସୁପରଭାଇଜର୍ ସ୍ଥିତିରୁ ପଞ୍ଜୀକୃତ, ସ୍ୱାସ୍ଥ୍ୟ-ଯାଞ୍ଚିତ ବ୍ୟାକ୍ଏଣ୍ଡଗୁଡ଼ିକୁ ନିର୍ଣ୍ଣୟ କରିବା ଉଚିତ।
- ଆଜି ତଦାରଖ ହେଉଥିବା ସେବାଗୁଡ଼ିକ ପାଇଁ ଲୁପ୍ବ୍ୟାକ୍ HTTPକୁ ପ୍ରାଥମିକତା ଦିଅନ୍ତୁ, କାରଣ ପରିଚାଳିତ ପ୍ରକ୍ରିୟାଗୁଡ଼ିକ ପୂର୍ବରୁ HTTP-ସୁସଙ୍ଗତ API ପ୍ରଦାନ କରେ, ରୁଟ୍ ଗାର୍ଡ ସୀମାକୁ ଅଡିଟ୍ କରିପାରେ ଏବଂ ବିଫଳତା/ଫଲ୍ବ୍ୟାକ୍ ଆଚରଣ ଅନୁରୋଧ ଲଗ୍ରେ ଦୃଶ୍ୟମାନ ହୁଏ। ଭବିଷ୍ୟତର SDK କିମ୍ବା ସକେଟ୍ ଟ୍ରାନ୍ସପୋର୍ଟ କେବଳ ସେତେବେଳେ ଯୋଡ଼ିବା ଯୋଗ୍ୟ, ଯଦି ଏହା ଆଇସୋଲେସନ୍ କିମ୍ବା ଫଲ୍ବ୍ୟାକ୍ ସେମାଣ୍ଟିକ୍ସକୁ ଦୁର୍ବଳ ନକରି p99 ରାଉଟିଂ ବିଳମ୍ବତାକୁ ମାପଯୋଗ୍ୟ ଭାବେ ହ୍ରାସ କରେ।

ତେଣୁ ଅତ୍ୟଧିକ ଉଚ୍ଚ-ଥ୍ରୁପୁଟ୍ ଡିପ୍ଲୟମେଣ୍ଟ ପାଇଁ ଡିଫଲ୍ଟ ଉତ୍ତର ହେଉଛି Bifrost ସକ୍ଷମ ଥିବା `auto`: ସଫଳତା ହାର ପାଇଁ TypeScript ଫଲ୍ବ୍ୟାକ୍କୁ ସଂରକ୍ଷିତ ରଖି ହଟ୍ ପାଥ୍ରେ Go ସାଇଡ୍କାର୍ ବ୍ୟବହାର କରନ୍ତୁ। ସୁବ୍ୟବସ୍ଥିତ ଅବନତି ଅପେକ୍ଷା କେବଳ-ସାଇଡ୍କାର୍ର କଠୋର ଆଚରଣ ଅଧିକ ଗୁରୁତ୍ୱପୂର୍ଣ୍ଣ ହେଲେ ମାତ୍ର `bifrost` ବ୍ୟବହାର କରନ୍ତୁ।

## ଉଚ୍ଚ-ଥ୍ରୁପୁଟ୍ ମାର୍ଗଦର୍ଶନ

ଦୀର୍ଘସ୍ଥାୟୀ ଉଚ୍ଚ RPM/RPS ଏବଂ କଠୋର ସଫଳତା SLO ପାଇଁ:

1. ଏକ ବ୍ୟବହାରିକ କୁଲ୍ଡାଉନ୍ ଏବଂ ବିଫଳତା ଟେଲିମେଟ୍ରି ସହିତ `auto` ବ୍ୟବହାର କରନ୍ତୁ।
2. ଅପ୍ଷ୍ଟ୍ରିମ୍ ବୈଧୀକରଣ ଏବଂ API-କି ଯାଞ୍ଚଗୁଡ଼ିକୁ TypeScript ରୁଟ୍ ସୀମାରେ ରଖନ୍ତୁ।
3. ସ୍ପଷ୍ଟ ହେଡର୍/କାଉଣ୍ଟର୍ ସକ୍ଷମ କରନ୍ତୁ, ଯାହାଦ୍ୱାରା ଆପଣଙ୍କ ଆଲର୍ଟିଂ ଫଲ୍ବ୍ୟାକ୍ର ଘନତା ଏବଂ କାରଣଗୁଡ଼ିକୁ ଚିହ୍ନଟ କରିପାରିବ।
4. ଅନନ୍ତକାଳ ଅପେକ୍ଷା କରିବା ପରିବର୍ତ୍ତେ ଶୀଘ୍ର ବିଫଳ ହେବା ପାଇଁ ସାଇଡ୍କାର୍ ଟାଇମ୍ଆଉଟ୍ଗୁଡ଼ିକୁ ଟ୍ୟୁନ୍ କରନ୍ତୁ।
5. ସେବାର ସ୍ୱୟଂଚାଳିତ ପୁନଃଚାଳନ ଏବଂ ସ୍ୱାସ୍ଥ୍ୟ ଟେଲିମେଟ୍ରି ଲୁପ୍କୁ ସୁସ୍ଥ ରଖନ୍ତୁ, ଯାହାଦ୍ୱାରା ଫଲ୍ବ୍ୟାକ୍ ପ୍ରକୃତରେ ଏକ ବ୍ୟତିକ୍ରମ ହୋଇ ରହିବ।

## ପ୍ରସ୍ତାବିତ ମୂଳ ବିନ୍ୟାସ

- `OMNIROUTE_RELAY_BACKEND=auto`
- `BIFROST_ENABLED=1`
- API କି, ଅଲାଉଲିଷ୍ଟ, ସାନିଟାଇଜର୍ ଏବଂ ହାର-ସୀମା ଯାଞ୍ଚଗୁଡ଼ିକୁ ରୁଟ୍ ହ୍ୟାଣ୍ଡଲର୍ରେ ସକ୍ଷମ ରଖନ୍ତୁ (ସେଗୁଡ଼ିକ ସର୍ବଦା ଡାଉନ୍ଷ୍ଟ୍ରିମ୍ ଫରୱାର୍ଡିଂ ପୂର୍ବରୁ ଚାଲେ)।
- ଆପଣଙ୍କ ରିଭର୍ସ ପ୍ରକ୍ସି ଏବଂ ଅନୁରୋଧ ଲଗ୍ରୁ ଫଲ୍ବ୍ୟାକ୍ ମେଟ୍ରିକ୍ସ ଏକ୍ସପୋର୍ଟ କରନ୍ତୁ, ଯାହାଦ୍ୱାରା ସାଇଡ୍କାର୍ ବିଭ୍ରାଟଗୁଡ଼ିକ ଏକ ମିନିଟ୍ ମଧ୍ୟରେ ଦୃଶ୍ୟମାନ ହେବ।
