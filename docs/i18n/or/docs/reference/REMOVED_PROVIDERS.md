କିଛି ସେବା OmniRoute ସହିତ ଏକୀକୃତ କରାଯାଇଥିଲା ଏବଂ ପରେ ସେଗୁଡ଼ିକୁ ପରିଚାଳନା କରୁଥିବା ବ୍ୟକ୍ତିମାନେ ଅନୁରୋଧ କରିବାରୁ ସେଗୁଡ଼ିକୁ ଅପସାରଣ କରାଯାଇଥିଲା। ଏହି ପୃଷ୍ଠା ସେହି ଅପସାରଣଗୁଡ଼ିକର ସ୍ଥାୟୀ ରେକର୍ଡ। ଏହାର ଏକମାତ୍ର ଉଦ୍ଦେଶ୍ୟ ହେଉଛି ସେଗୁଡ଼ିକୁ ଭୁଲବଶତଃ ପୁଣି ଯୋଡ଼ାଯିବାରୁ ରୋକିବା: କୌଣସି ଅବଦାନକାରୀ ଏକ ପୁରୁଣା fork, cached npm tarball, archived issue କିମ୍ବା "provider X ପୁନଃସ୍ଥାପନ କରନ୍ତୁ" ଅନୁରୋଧ ପାଇଲେ, ତାଙ୍କ ପାଇଁ **ପୁନଃ ପ୍ରବର୍ତ୍ତନ କରନ୍ତୁ ନାହିଁ** ବୋଲି ଉଲ୍ଲେଖ କରୁଥିବା ଗୋଟିଏ ସ୍ଥାନ ଆବଶ୍ୟକ।

ଏହି ପୃଷ୍ଠାଟି ବନ୍ଦ ହୋଇଯାଇଥିବା କିମ୍ବା ଆଉ ଉପଲବ୍ଧ ନଥିବା ସେବାଗୁଡ଼ିକର ତାଲିକା **ନୁହେଁ**। ସେଗୁଡ଼ିକୁ [`FREE_TIERS.md`](FREE_TIERS.md) ("ଅପସାରିତ / ମାଗଣା ସ୍ତର ନାହିଁ")ରେ ଟ୍ରାକ୍ କରାଯାଏ ଏବଂ ସେବାଟି ପୁଣି ଫେରିଲେ ସେଗୁଡ଼ିକ ମଧ୍ୟ ପୁଣି ଫେରିପାରିବ। ନିମ୍ନରେ ଥିବା ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ କେବଳ ଅନୁରୋଧରେ ନାମିତ ଅପରେଟରଙ୍କ ଲିଖିତ ଅନୁମତି ସହିତ ପୁଣି ଫେରିପାରିବ, ଏବଂ ସେହି ଅନୁମତିର ଲିଙ୍କ୍ ଏଣ୍ଟ୍ରିରେ ଦିଆଯିବା ଆବଶ୍ୟକ।

## ନୀତି

1. **ସେବା ଅପରେଟରଙ୍କ ଅପସାରଣ ଅନୁରୋଧକୁ ସମ୍ମାନ କରାଯାଏ, ଏହା ଆଲୋଚନାସାପେକ୍ଷ ନୁହେଁ।** OmniRoute କୌଣସି upstream ସେବା ସହିତ ସମ୍ବନ୍ଧିତ ନୁହେଁ। କୌଣସି ସେବାର ଅପରେଟର ଏକୀକରଣକୁ ଅପସାରଣ କରିବାକୁ କହିଲେ, ଏକୀକରଣଟି ଅଧିକୃତ API ବ୍ୟବହାର କରୁଥିଲା କି ନାହିଁ ତାହା ନିର୍ବିଶେଷରେ ଏହାକୁ ଅପସାରଣ କରାଯାଏ।
2. **"ଅପସାରିତ"ର ଅର୍ଥ OmniRoute ନିୟନ୍ତ୍ରଣ କରୁଥିବା ପ୍ରତ୍ୟେକ ସ୍ଥାନ।** Executor, registry entry, provider id ଏବଂ alias, model list, endpoints, environment variables, icon, dashboard cards, ଉତ୍ପାଦିତ provider reference, `FREE_TIERS.md`, environment reference, README counts, `llm.txt` mirrors, ନିର୍ଦ୍ଦିଷ୍ଟ tests ଏବଂ golden snapshots, code comments, CHANGELOG bullets (ledgered reconciliation ସହିତ, `config/release/changelog-reconciliations.json` ଦେଖନ୍ତୁ), GitHub Releases notes, wiki, ଏବଂ ସେହି provider ବିଷୟକ GitHub issues, discussions ଓ pull requests (issues ଏବଂ discussions ବିଲୋପ କରାଯାଏ; pull requestsର ଶୀର୍ଷକ ପରିବର୍ତ୍ତନ କରାଯାଏ, ସେଗୁଡ଼ିକର ବର୍ଣ୍ଣନା ବଦଳାଯାଏ ଏବଂ thread lock କରାଯାଏ, କାରଣ GitHub pull requests ବିଲୋପ କରିପାରେ ନାହିଁ)।
3. **ଲିଖିତ ଅନୁମତି ବିନା ଏହି ପୃଷ୍ଠାର କୌଣସି ଏଣ୍ଟ୍ରିକୁ କେବେବି ପୁନଃ ପ୍ରବର୍ତ୍ତନ କରନ୍ତୁ ନାହିଁ।** ଏଥିରେ କୌଣସି provider catalogରେ id କିମ୍ବା aliasକୁ ପୁଣି ଯୋଡ଼ିବା, executorରେ domains ଯୋଡ଼ିବା, ଏହାକୁ "ପୁନଃସ୍ଥାପନ" କରୁଥିବା କୌଣସି ଅବଦାନକାରୀଙ୍କ PR ଗ୍ରହଣ କରିବା, ଏହାକୁ free-model catalogରେ ଯୋଡ଼ିବା କିମ୍ବା OmniRoute ମାଧ୍ୟମରେ ଏଥିରେ ପହଞ୍ଚିବାର କୌଣସି manual ଉପାୟକୁ ଡକ୍ୟୁମେଣ୍ଟ କରିବା ଅନ୍ତର୍ଭୁକ୍ତ। ଏହି ପୃଷ୍ଠାର ଲିଙ୍କ୍ ସହିତ ଏପରି PRs ଏବଂ issues ବନ୍ଦ କରନ୍ତୁ।
4. **ଏଣ୍ଟ୍ରିକୁ ସର୍ବନିମ୍ନ ରଖନ୍ତୁ।** କୌଣସି ପୁନଃ ପ୍ରବର୍ତ୍ତନକୁ ଚିହ୍ନିବା ପାଇଁ ସମୀକ୍ଷକଙ୍କୁ ଆବଶ୍ୟକ ତଥ୍ୟମାନେ ମାତ୍ର ରେକର୍ଡ କରନ୍ତୁ: identifiers, domains, dates ଏବଂ ଅପସାରଣ କରିଥିବା pull request। ଏକୀକରଣଟି କିପରି କାମ କରୁଥିଲା ତାହା ବର୍ଣ୍ଣନା କରନ୍ତୁ ନାହିଁ।
5. **Regression guard ହେଉଛି `tests/unit/removed-providers-blocklist.test.ts`।** ନିମ୍ନରେ ଥିବା କୌଣସି identifier କିମ୍ବା domain provider catalogs, executor map କିମ୍ବା provider registry sourcesରେ ପୁଣି ଦେଖାଦେଲେ ଏହା ବିଫଳ ହୁଏ। ଏଠାରେ row ଯୋଡ଼ୁଥିବା ସେହି PRରେ ଏହି testକୁ ନୂଆ identifiers ଯୋଡ଼ନ୍ତୁ।

## ଏକ ଏଣ୍ଟ୍ରି ଯୋଡ଼ିବା

ଏକ ନୂଆ ଅପସାରଣ ଅନୁରୋଧ ଆସିଲେ:

1. ଅନୁରୋଧଟି ସେବାର ଅପରେଟରଙ୍କଠାରୁ (ସେମାନଙ୍କ support address କିମ୍ବା ସେମାନଙ୍କ ନିୟନ୍ତ୍ରଣାଧୀନ domain) ଆସିଛି ବୋଲି ନିଶ୍ଚିତ କରନ୍ତୁ ଏବଂ ସନ୍ଦେଶଟିକୁ ବ୍ୟକ୍ତିଗତ ଭାବେ ରଖନ୍ତୁ।
2. ନୀତିର item 2ର checklist ଅନୁସରଣ କରି ଏକୀକରଣକୁ ଅପସାରଣ କରନ୍ତୁ। ଏକ keyless provider ପାଇଁ [#12440](https://github.com/diegosouzapw/OmniRoute/pull/12440)କୁ reference ଭାବେ ଏବଂ ସଞ୍ଚିତ connections ଥିବା API-key provider ପାଇଁ [#10210](https://github.com/diegosouzapw/OmniRoute/pull/10210)କୁ ବ୍ୟବହାର କରନ୍ତୁ (ଏକ migration ଯୋଡ଼ନ୍ତୁ)।
3. ସେହି PRରେ ଉପରୋକ୍ତ tableରେ ଗୋଟିଏ row ଏବଂ `tests/unit/removed-providers-blocklist.test.ts`ରେ identifiers ଯୋଡ଼ନ୍ତୁ।
4. PR merge ହେବା ପରେ ଅପରେଟରଙ୍କୁ ଉତ୍ତର ଦିଅନ୍ତୁ, କ’ଣ ଅପସାରଣ କରାଯାଇଛି ଏବଂ OmniRoute କ’ଣ ପରିବର୍ତ୍ତନ କରିପାରିବ ନାହିଁ (ପୂର୍ବରୁ ପ୍ରକାଶିତ npm ଏବଂ Docker versions, git history, third-party forks) ତାହା ତାଲିକାଭୁକ୍ତ କରନ୍ତୁ।
