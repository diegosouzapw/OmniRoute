ରିଲେଗୁଡ଼ିକ (Vercel, Deno, Cloudflare) ଏକ ସର୍ଭରଲେସ୍ ବ୍ୟାକଏଣ୍ଡରେ ଅପ୍ଷ୍ଟ୍ରିମ୍ ସଂଯୋଗକୁ ସମାପ୍ତ କରନ୍ତି, ଯାହାଦ୍ୱାରା ପ୍ରଦାନକାରୀ API କୀକୁ ସର୍ଭର ପାର୍ଶ୍ୱରେ ରଖି OmniRoute ଏକ ସ୍ଥିର ଅଞ୍ଚଳରୁ ଏଗ୍ରେସ୍ କରିପାରେ। ଏହି ଡକ୍ୟୁମେଣ୍ଟରେ ଅପରେଟରମାନେ ପ୍ରଡକ୍ସନ୍ରେ ସମ୍ମୁଖୀନ ହେଉଥିବା ଦୁଇଟି ବିଫଳତା ମୋଡ୍ ଏବଂ ପ୍ରତ୍ୟେକ ପାଇଁ OmniRoute ପ୍ରଦାନ କରୁଥିବା ପୁନରୁଦ୍ଧାର ପଥ ବିଷୟରେ ବର୍ଣ୍ଣନା କରାଯାଇଛି।

## ରିଲେ ପ୍ରମାଣୀକରଣ କିପରି ସଂରକ୍ଷିତ ହୁଏ

ଆପଣ **Settings → Proxy Pool → Deploy Relay** ରୁ ଏକ ରିଲେ ଡିପ୍ଲୟ କଲେ, ଡିପ୍ଲୟ ପ୍ରକ୍ରିୟା ରିଲେର ପ୍ରମାଣୀକରଣ ଟୋକେନ୍କୁ ପ୍ରକ୍ସିର `notes` JSON ଫିଲ୍ଡରେ ସଂରକ୍ଷଣ କରେ:

- ଯଦି `STORAGE_ENCRYPTION_KEY` ସେଟ୍ ହୋଇଥାଏ, ତେବେ ଟୋକେନ୍ଟି `relayAuthEnc`
  ଭାବରେ ଲେଖାଯାଏ (ସ୍ଥିର ଅବସ୍ଥାରେ AES-ଏନ୍କ୍ରିପ୍ଟ ହୋଇଥାଏ)।
- ଅନ୍ୟଥା, ଏହା ପ୍ଲେନ୍ଟେକ୍ସ୍ଟ `relayAuth` ଭାବରେ ଲେଖାଯାଏ।

ଅନୁରୋଧ ସମୟରେ `extractRelayAuth(notes)` ଉପଲବ୍ଧ ଥିବା ଯେକୌଣସି ରୂପକୁ ଫେରାଏ, ତେଣୁ ପୁନଃଚାଳନ ପରେ ମଧ୍ୟ ରିଲେ କାର୍ଯ୍ୟ କରିଚାଲେ।

## ବିଫଳତା ମୋଡ୍ 1 — କୀ ରୋଟେସନ୍ ପରେ ଡିକ୍ରିପ୍ଟ ହୋଇପାରୁ ନଥିବା ଟୋକେନ୍

**ଲକ୍ଷଣ:** ପୂର୍ବରୁ କାର୍ଯ୍ୟ କରୁଥିବା ରିଲେଗୁଡ଼ିକ ଏବେ ପରିବେଶ କିମ୍ବା ସିକ୍ରେଟ୍-ମ୍ୟାନେଜର୍ରେ `STORAGE_ENCRYPTION_KEY` ରୋଟେସନ୍ ପରେ ଅପ୍ଷ୍ଟ୍ରିମ୍ `401`/ପ୍ରମାଣୀକରଣ ତ୍ରୁଟି ଫେରାଉଛନ୍ତି। ସଂରକ୍ଷିତ `relayAuthEnc` ବ୍ଲବ୍କୁ ଆଉ ଡିକ୍ରିପ୍ଟ କରାଯାଇପାରୁ ନାହିଁ, ତେଣୁ `extractRelayAuth` ଖାଲି ଷ୍ଟ୍ରିଂ ଫେରାଏ ଏବଂ ରିଲେ କୌଣସି ପ୍ରମାଣୀକରଣ ପଠାଏ ନାହିଁ।

**ପୁନରୁଦ୍ଧାର — ସେହି ସ୍ଥାନରେ ମରାମତି କରନ୍ତୁ (ପୁନଃଡିପ୍ଲୟ ଆବଶ୍ୟକ ନାହିଁ):**

1. **Settings → Proxy Pool** ଖୋଲନ୍ତୁ।
2. ଯେଉଁ ରିଲେ ଧାଡ଼ିଗୁଡ଼ିକରେ ପ୍ରମାଣୀକରଣ ନାହିଁ, ସେଥିରେ ହଳଦିଆ `auth missing` ବ୍ୟାଜ୍ ଏବଂ ଏକ **Repair** ବଟନ୍ ଦେଖାଯାଏ।
3. **Repair** କ୍ଲିକ୍ କରନ୍ତୁ। OmniRoute
   `POST /api/settings/proxies/[id]/repair-relay` କଲ୍ କରେ, ଯାହା:
   - **ବର୍ତ୍ତମାନର** କୀ ସହିତ `relayAuthEnc` କୁ ଡିକ୍ରିପ୍ଟ କରେ,
   - ପ୍ଲେନ୍ଟେକ୍ସ୍ଟ `relayAuth` କୁ ପୁଣି `notes` ଭିତରେ ଲେଖେ,
   - `{ repaired: true, mode: "recovered" }` ଫେରାଏ।

କୌଣସି ଡିପ୍ଲୟ ପରିଚୟପତ୍ର ପୁନଃପ୍ରବେଶ କରାଇବା ବିନା ରିଲେ ପୁଣି ସେବା ଯୋଗାଇବା ଆରମ୍ଭ କରେ।

ଏହା କେବଳ ସେତେବେଳେ କାର୍ଯ୍ୟ କରେ, ଯଦି ବର୍ତ୍ତମାନର `STORAGE_ENCRYPTION_KEY` ଏବେ ମଧ୍ୟ ବ୍ଲବ୍କୁ ଡିକ୍ରିପ୍ଟ କରିପାରେ। ଯଦି ଆପଣ କୌଣସି ମାଇଗ୍ରେସନ୍ **ବିନା** କୀକୁ ରୋଟେଟ୍ କରିଥାନ୍ତି, ତେବେ ବ୍ଲବ୍କୁ ପୁନରୁଦ୍ଧାର କରାଯାଇପାରିବ ନାହିଁ।

## ବିଫଳତା ମୋଡ୍ 2 — ପୁନରୁଦ୍ଧାର ହୋଇପାରୁ ନଥିବା ଟୋକେନ୍ (କୀ ରୋଟେଟ୍ ହୋଇ ଉପଲବ୍ଧ ନାହିଁ)

**ଲକ୍ଷଣ:** ଆପଣ **Repair** କ୍ଲିକ୍ କରିଛନ୍ତି ଏବଂ
`{ repaired: false, mode: "redeploy", status: 409 }` ପାଇଛନ୍ତି।

**ପୁନରୁଦ୍ଧାର — ପୁନଃଡିପ୍ଲୟ କରନ୍ତୁ:**

ସଂରକ୍ଷିତ ଟୋକେନ୍କୁ ବର୍ତ୍ତମାନର କୀ ସହିତ ପୁନରୁଦ୍ଧାର କରାଯାଇପାରିବ ନାହିଁ। ଆପଣ ମୂଳତଃ ବ୍ୟବହାର କରିଥିବା ସେହି ମୋଡାଲ୍ରୁ ରିଲେକୁ ପୁନଃଡିପ୍ଲୟ କରନ୍ତୁ (**Deploy Relay** ମେନୁ → Vercel / Deno / Cloudflare)। ଡିପ୍ଲୟ ପ୍ରକ୍ରିୟା ଏକ ନୂତନ ଟୋକେନ୍ ଲେଖେ (ବର୍ତ୍ତମାନର କୀ ସହିତ ଏନ୍କ୍ରିପ୍ଟ ହୋଇଥିବା) ଏବଂ ଧାଡ଼ିର `auth missing` ବ୍ୟାଜ୍ ହଟିଯାଏ।

ଟୋକେନ୍ଟି ପୁନରୁଦ୍ଧାର ହୋଇପାରୁ ନଥିଲେ UI ରେ **Repair** ବଟନ୍ ନିଜେ ପୁନଃଡିପ୍ଲୟ ମୋଡାଲ୍କୁ ଟ୍ରିଗର୍ କରେ, ତେଣୁ ଆପଣଙ୍କୁ ଏହାକୁ ମାନୁଆଲ୍ ଭାବେ ଖୋଜିବାକୁ ପଡ଼େ ନାହିଁ।

## ବିଫଳତା ମୋଡ୍ 3 — ରିଲେ ପହଞ୍ଚଯୋଗ୍ୟ କିନ୍ତୁ ଅସୁସ୍ଥ

**ଲକ୍ଷଣ:** ପ୍ରକ୍ସି ପରୀକ୍ଷା (`speed` ବଟନ୍) ରିଲେକୁ ସକ୍ରିୟ ଦେଖାଏ, କିନ୍ତୁ ଅନୁରୋଧଗୁଡ଼ିକ ତଥାପି ବିରତି ସହିତ ବିଫଳ ହୁଏ।

OmniRoute ର ସ୍ୱୟଂଚାଳିତ ପରୀକ୍ଷା ପ୍ରୋବ୍ ଦ୍ୱାରା ଫେରାଯାଇଥିବା ରିଲେ ସଚେତନତା ହେଡର୍ଗୁଡ଼ିକ ଯାଞ୍ଚ କରନ୍ତୁ (**Settings → Proxy Pool** ଏବଂ `relayTested` / `relayAlive` କାଉଣ୍ଟର୍ଗୁଡ଼ିକ ଦେଖନ୍ତୁ):

- `x-relay-url` — କେଉଁ ରିଲେ ବ୍ୟାକଏଣ୍ଡ ଉତ୍ତର ଦେଇଛି।
- `x-relay-mode` — ସେହି ଅନୁରୋଧ ପାଇଁ `ts` | `bifrost` | `auto`।
- `x-relay-attempts` — ସଫଳତା ପୂର୍ବରୁ କେତୋଟି ରିଲେ ହପ୍ ଚେଷ୍ଟା କରାଯାଇଥିଲା।
- `x-relay-fallback` — ଯେତେବେଳେ ଅନୁରୋଧଟି ପସନ୍ଦିତ ବ୍ୟାକଏଣ୍ଡରୁ TypeScript ରିଲେକୁ ଫଲ୍ବ୍ୟାକ୍ କରେ, ସେତେବେଳେ `true`।

କମ୍ `relayAlive` ସହିତ ଉଚ୍ଚ `x-relay-fallback` ହାରର ଅର୍ଥ ହେଉଛି ସାଇଡ୍କାର୍ ବ୍ୟାକଏଣ୍ଡ ଅସୁସ୍ଥ ଏବଂ ଆପଣ ଏହାକୁ ଠିକ୍ କରିବା କିମ୍ବା ରିଲେ ବ୍ୟାକଏଣ୍ଡ କୌଶଳକୁ `ts` କୁ ପରିବର୍ତ୍ତନ କରିବା ଉଚିତ (`RELAY_BACKEND_STRATEGY.md` ଦେଖନ୍ତୁ)।

| `POST` | `/api/settings/proxies/[id]/repair-relay` | `{ "id": "<proxyId>" }` | ପୁନଃବ୍ୟୁତ୍ପନ୍ନ ହେଲେ `200 { repaired: true, mode: "recovered" }`; ପ୍ଲେନ୍ଟେକ୍ସ୍ଟ ପୂର୍ବରୁ ଉପସ୍ଥିତ ଥିଲେ `200 { repaired: false, mode: "noop" }` | ପୁନରୁଦ୍ଧାର ଅସମ୍ଭବ ହେଲେ `409 { mode: "redeploy" }`; ରିଲେ ପ୍ରକାର ନ ହୋଇଥିଲେ `400`; ମିଳିଲା ନାହିଁ ହେଲେ `404` |

ତାଲିକା ରୁଟ୍ `GET /api/settings/proxies` ପ୍ରତ୍ୟେକ ଆଇଟମ୍ରେ ସିକ୍ରେଟ୍-ମୁକ୍ତ `relayInfo: { isRelay, authMissing, repairMode }` ସଂଲଗ୍ନ କରେ, ଯାହାଦ୍ୱାରା ଡ୍ୟାସ୍ବୋର୍ଡ କେବେ ବି ଟୋକେନ୍କୁ ପ୍ରକାଶ ନ କରି ମରାମତି ବିକଳ୍ପକୁ ରେଣ୍ଡର୍ କରିପାରେ।
