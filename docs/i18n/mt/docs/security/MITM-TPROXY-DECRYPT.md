Id-dekriptaġġ trasparenti TPROXY huwa l-**5 mod ta' qbid** ta' OmniRoute għall-munzell MITM ta'
[Traffic Inspector](../frameworks/TRAFFIC_INSPECTOR.md) / [AgentBridge](../frameworks/AGENTBRIDGE.md).
Dan jinterċetta u **jiddekripta** traffiku HTTPS lokali ħiereġ fuq Linux
bl-użu ta' TPROXY tal-kernel + routing ibbażat fuq politika — **mingħajr** ma jiffalsifika `/etc/hosts` u
**mingħajr** ma jimmodifika s-settings tal-proxy tas-sistema għall-OS kollu. Huwa adattat għal ambjenti headless
(l-ebda bidla fid-DNS x'tindif) u r-regoli tal-firewall jitneħħew awtomatikament meta s-sistema terġa' tibda.

B'differenza mill-modi l-oħra ta' qbid, TPROXY ma jeħtieġ ebda konfigurazzjoni għal kull host: huwa
jinterċetta b'mod trasparenti hosts ta' destinazzjoni **arbitrarji** fuq port fil-mira, itemm TLS b'
ċertifikat leaf li joħroġ minnufih għal kull hostname SNI, jaqbad l-
iskambju ddekriptat, u jerġa' jikkripta t-talba lejn id-destinazzjoni oriġinali.

> **Linux biss, root biss, b'attivazzjoni volontarja.** Dan il-mod jeħtieġ Linux, addon nattiv
> mibni b'toolchain C, u l-kapaċità **CAP_NET_ADMIN** (tipikament root). Huwa ristrett
> wara l-API ta' AgentBridge disponibbli biss fuq loopback u huwa diżattivat b'mod awtomatiku. CA MITM
> fdata li tista' tiffirma kwalunkwe host hija kapaċità qawwija — ara [§6 Sigurtà](#6-security).

**Sors:** `src/mitm/tproxy/`
**Rotta tal-API:** `GET / POST / DELETE /api/tools/agent-bridge/tproxy`
**Swiċċ fid-dashboard:** Traffic Inspector → toolbar tal-modi ta' qbid → **"TPROXY Decrypt"** ⚠
**Ara wkoll:** [`docs/frameworks/TRAFFIC_INSPECTOR.md`](../frameworks/TRAFFIC_INSPECTOR.md),
[`docs/frameworks/AGENTBRIDGE.md`](../frameworks/AGENTBRIDGE.md)

## §1 X'inhu u meta għandek tużah

Kull wieħed mill-erba' modi l-oħra ta' qbid għandu limitazzjoni:

| Mod                       | Kif jiġi dirett it-traffiku                                           | Limitazzjoni                                            |
| ------------------------- | --------------------------------------------------------------------- | ------------------------------------------------------- |
| AgentBridge               | Falsifikazzjoni DNS permezz ta' `/etc/hosts` għal sett fiss ta' hosts | il-hosts irreġistrati tal-aġent tal-IDE biss            |
| Hosts Personalizzati      | Falsifikazzjoni DNS permezz ta' `/etc/hosts` għal kull host           | entrata waħda għal kull host; sudo biex teditja l-hosts |
| HTTP_PROXY                | Varjabbli tal-ambjent `HTTP_PROXY`/`HTTPS_PROXY`                      | l-apps li jirrispettaw il-varjabbli tal-ambjent biss    |
| Proxy għas-sistema kollha | Settings tal-proxy tal-OS                                             | jimmodifika l-istat globali; jeħtieġ treġġigħ lura      |

Minflok, id-dekriptaġġ trasparenti TPROXY jidderieġi t-traffiku fil-livell tal-**kernel**. Huwa
jimmarka konnessjonijiet TCP lokali ħerġin ġodda lejn port fil-mira (`443` b'mod awtomatiku) fil-
katina `mangle OUTPUT`, regola `ip rule` terġa' tidderieġi l-pakketti mmarkati lejn konsenja lokali,
u meta jerġgħu jidħlu, it-target `TPROXY` ta' `mangle PREROUTING` jgħaddihom lil listener
**IP_TRANSPARENT** — li mbagħad itemm TLS u jaqbad it-test sempliċi.

Użah meta trid taqbad u tiddekripta traffiku minn proċess li:

- jikkomunika ma' host li AgentBridge ma jirreġistrax, u
- ma jirrispettax `HTTP_PROXY`, u
- ma tridx tfixklu b'bidla fil-proxy għas-sistema kollha.

Minħabba li l-interċettazzjoni sseħħ fil-kernel, il-proċess li joriġina t-traffiku ma jeħtieġ **ebda
bidla fil-konfigurazzjoni** — iżda l-proċess irid jafda s-CA dinamika li OmniRoute
jinstalla (ara [§4](#4-the-per-sni-dynamic-ca-and-trust-store-installer)).

## §3 L-addon nattiv IP_TRANSPARENT

Il-modulu `net` ta' Node ma jistax jagħmel `setsockopt(IP_TRANSPARENT)` _qabel_ `bind()`, kif
jeħtieġ TPROXY (inkella l-kernel iwarrab il-pakketti ridirezzjonati). L-addon
(`src/mitm/tproxy/native/transparent.c`, mibni permezz ta' `binding.gyp`) huwa modulu N-API
żgħir li jesponi tliet funzjonijiet, użati permezz ta' `transparentSocket.ts`:

| Funzjoni tal-addon                    | Xogħol tas-socket                                                                                            | Użata għal                                                                               |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| `createTransparentListener(ip, port)` | `socket()` + **SO_REUSEADDR** + **IP_TRANSPARENT** + `bind()` + `listen()`, tirritorna l-fd mhux ipproċessat | il-listener trasparenti tal-qbid (Node jadotta l-fd permezz ta' `server.listen({ fd })`) |
| `setSocketMark(fd, mark)`             | `setsockopt` **SO_MARK** fuq fd eżistenti                                                                    | kontra l-loop (jimmarka s-sockets tal-proxy stess)                                       |
| `connectMarked(ip, port, mark)`       | `socket()` + **SO_MARK** **qabel** `connect()` mhux imblokkanti, tirritorna fd                               | it-trażmissjoni upstream ikkriptata mill-ġdid (is-SYN iġorr il-marka)                    |

Id-destinazzjoni oriġinali tinqara minn `socket.localAddress`/`localPort` — TPROXY
jippreservaha, għalhekk ma hemm ebda tfittxija **SO_ORIGINAL_DST**/NAT.

### Bini tal-addon

```bash
npm run build:native:tproxy      # cd src/mitm/tproxy/native && node-gyp rebuild
                                 # -> native/build/Release/transparent.node
```

- Matul `npm run build`, `scripts/build/build-tproxy-native.mjs` iħaddem `node-gyp
rebuild`. Dan huwa **għal Linux biss u mhux fatali** — toolchain nieqes sempliċement iħalli
  l-modalità tal-qbid mhux disponibbli.
- `assembleStandalone.mjs` jikkopja `build/Release/transparent.node` fil-bundle
  standalone; `transparentSocket.ts` isolvih kemm relattivament għall-modulu kif ukoll
  relattivament għas-cwd (`<cwd>/src/mitm/tproxy/native/...`).
- `build/` u `prebuilds/` huma injorati minn git — il-binarju **jinbena, qatt ma
  jiġi committed**.

Il-loader jipprova, skont l-ordni ta' prijorità:
`native/build/Release/transparent.node`, imbagħad `native/prebuilds/transparent.node`
(it-tnejn relattivament għall-modulu u taħt `<cwd>/src/mitm/tproxy/`).

## §4 Is-CA dinamika għal kull SNI u l-installatur tal-maħżen tal-fiduċja

> **Aġġornament #6684:** is-server statiku ta' AgentBridge (`src/mitm/server.cjs`) issa
> juża wkoll dan l-istess mudell ta' arkitettura CA/leaf minflok leaf statika
> waħda awtofirmata. Juża istanza CA **distinta**
> (`src/mitm/cert/rootCa.ts`, ippersistita f'`<DATA_DIR>/mitm/ca.key`/`ca.crt`)
> u jinstallaha fl-islott eżistenti tal-maħżen tal-fiduċja `omniroute-mitm.crt`
> (filwaqt li tissostitwixxi l-leaf waħda l-antika hemmhekk — mhu meħtieġ ebda tindif
> ta' fiduċja doppja), u tinżamm kompletament separata mill-islott
> `omniroute-tproxy-ca.crt` ta' TPROXY deskritt hawn taħt.
> Installazzjonijiet ġodda ta' AgentBridge jirċievu l-mudell CA awtomatikament;
> installazzjoni li diġà tafda l-leaf statika l-antika tibqa' tużaha sakemm
> l-operatur jagħżel li jaqleb permezz ta' `MITM_ROOT_CA_ENABLED=true` (ara
> `src/mitm/cert/migration.ts`) — CA MITM fdata li tista' tiffirma leaf għal
> **kwalunkwe** host hija sostanzjalment aktar b'saħħitha mil-leaf l-antika
> b'SAN fiss, għalhekk il-bidla qatt ma ssir fis-skiet għal installazzjoni
> li diġà tafdaha.

Storikament, iċ-ċertifikat MITM statiku ta' AgentBridge kien jaħdem biss għax
AgentBridge jagħmel DNS spoofing għal sett **fiss** ta' hosts (issa unifikat
mal-mudell ta' hawn taħt). TPROXY jinterċetta hosts **arbitrarji**, għalhekk
il-listener tiegħu jrid jippreżenta leaf valida għal kwalunkwe SNI li jitlob
il-klijent — l-istess rekwiżit li AgentBridge issa għandu għas-sett sħiħ
`MITM_TOOL_HOSTS` (9 entrati ta' għodod) minflok biss l-4 hosts ta'
antigravity.

### CA dinamika (`src/mitm/tproxy/dynamicCert.ts`)

`DynamicCertStore` iħaddem CA lokali (mibnija fuq id-dipendenza `selfsigned`) li:

- Tiġġenera CA b'ħajja twila permezz ta' `generateMitmCa()` (CN `"OmniRoute MITM CA"`,
  validità ta' 10 snin, `basicConstraints CA=true` + `keyUsage keyCertSign,cRLSign`,
  RSA ta' 2048 bit / SHA-256).
- Toħroġ **leaf għal kull hostname SNI meta tintalab** permezz ta'
  `issueLeafCert()` (validità ta' sena, `subjectAltName` = il-host SNI) u
  żżomm fil-cache `tls.SecureContext` wieħed għal kull hostname.
- Tesponi `createSNICallback()` għas-server li jittermina t-TLS (ara [§5](#5-how-decrypt-and-capture-work)).
- Tista' tinbena b'`existingCa` biex il-CA tibqa' stabbli bejn restarts
  (sabiex il-maħżen tal-fiduċja ma jkollux għalfejn jerġa' jiġi installat).

Iċ-ċavetta privata tal-CA **qatt ma titlaq mill-magna**.

### Installatur tal-maħżen tal-fiduċja (`src/mitm/tproxy/caTrust.ts`)

Il-klijent interċettat irid jafda l-CA dinamika, għalhekk il-bidu tal-modalità
ta' capture jinstalla ċ-ċertifikat CA fil-maħżen tal-fiduċja tal-OS taħt
**slot iddedikat** — `omniroute-tproxy-ca.crt` (il-kostanti
`TPROXY_CA_CERT_NAME`) — miżmum separat mill-islott taċ-ċertifikat MITM statiku
(`omniroute-mitm.crt`) sabiex it-tnejn qatt ma jissostitwixxu lil xulxin.

`installTproxyCa(caPem, sudoPassword?)` jidentifika d-direttorju tal-anchors
tad-distribuzzjoni (f'din l-ordni: l-ewwel dak tal-istil Debian) u jħaddem
il-kmand ta' refresh korrispondenti:

| Direttorju tal-anchors                      | Kmand ta' refresh        |
| ------------------------------------------- | ------------------------ |
| `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

L-installazzjoni tpoġġi l-PEM fi staging f'fajl temporanju, imbagħad
(privileġġjatament) tuża `mkdir -p` għad-direttorju tal-anchors, `cp` biex
tikkopja l-fajl imqiegħed fi staging fih, u tħaddem il-kmand ta' refresh.
`uninstallTproxyCa()` ineħħi biss l-islott iddedikat (u jħalli ċ-ċertifikat MITM
statiku mhux mittiefes) u jagħmel refresh — fuq sistemi mhux Linux ma jagħmel
xejn.

Il-kmandi privileġġjati kollha jitħaddmu permezz ta' `execFileWithPassword`
(`src/mitm/systemCommands.ts`) — `spawn` b'**arrays ta' argumenti, mingħajr
shell, mingħajr interpolazzjoni ta' strings** (Regola Stretta #13). Meta
l-proċess ikun root (eż. il-VPS), il-mira titħaddem direttament u ma tkun
meħtieġa ebda password; fuq desktop mhux root, `sudoPassword` tintbagħat
permezz ta' `sudo -S` fuq stdin.

> Is-`sudoPassword` tad-desktop tingħata fil-body tal-POST biex tawtorizza
> l-installazzjoni fil-maħżen tal-fiduċja; tiġi injorata kompletament meta
> l-proċess ikun root.

## §5 Kif jaħdmu d-deċifrar u l-qbid

Il-pipeline (kollu taħt `src/mitm/tproxy/`):

```
app lokali  ──TCP/443──▶  mangle OUTPUT jimmarka l-konnessjoni (fwmark)
                           ip rule → tabella tar-routing lokali → lo
                           mangle PREROUTING TPROXY → listener IP_TRANSPARENT (port 8443)
                              │  captureMode.ts: jaqra d-destinazzjoni oriġinali minn socket.localAddress
                              ▼
                          tlsCapture.ts:
                            1. Itemm it-TLS tal-KLIJENT b'leaf għal kull SNI (dynamicCert)
                            2. http.Server intern jipparsja t-test ċar iddeċifrat
                            3. qbid → globalTrafficBuffer.push() b'source: "tproxy"
                               (sanitizeHeaders + maskSecret applikati)
                            4. jgħaddi 'l quddiem, ikkriptat MILL-ĠDID, lejn id-destinazzjoni oriġinali
                               fuq socket immarkat għall-bypass (connectMarked, kontra l-loop)
                              │
                              ▼
                          upstream oriġinali (api.example.com)
```

- **Terminazzjoni tat-TLS** (`createTlsCaptureServer`): tgeżwer is-socket mhux ipproċessat
  interċettat f'`tls.TLSSocket` fuq in-naħa tas-server billi tuża l-callback tal-SNI
  tas-CA dinamika, imbagħad tgħaddi l-fluss iddeċifrat lil `http.Server` intern
  (it-teknika standard tat-terminazzjoni MITM). It-tul tal-ħajja tas-sockets huwa
  limitat minn `MITM_IDLE_TIMEOUT_MS` sabiex mina mwaħħla ma tkunx tista' teżawrixxi
  d-deskritturi tal-fajls.
- **Qbid** (`handleDecryptedRequest`): iżżid `InterceptedRequest` b'
  `source: "tproxy"`, status li jibda bħala `"in-flight"`, headers mgħoddija minn
  `sanitizeHeaders()` u bodies minn `maskSecret()` qabel ma jidħlu fil-
  buffer. Imbagħad l-entrata tiġi aġġornata bir-rispons, id-daqsijiet u l-latenza.
- **Trażmissjoni 'l quddiem ikkriptata mill-ġdid** (`createForward` / `realForward`):
  terġa' tikkripta lejn id-destinazzjoni oriġinali. `rejectUnauthorized` għandu
  l-valur predefinit **`true`** (sigur b'mod predefinit) — iċ-ċertifikat upstream
  jiġi vverifikat kontra l-SNI/Host mitlub mill-klijent, għalhekk il-proxy jirrifjuta
  eżattament dak li kien jirrifjuta l-klijent oriġinali.

### Kontra l-loop (SO_MARK)

Minħabba li r-regoli jimmarkaw konnessjonijiet lokali ħerġin ġodda, it-trażmissjoni
'l quddiem ikkriptata mill-ġdid tal-proxy **stess** normalment terġa' tiġi
interċettata — loop infinit. Il-mogħdija tat-trażmissjoni 'l quddiem tiddefendi
kontra dan b'marka ta' bypass fuq is-socket (**SO_MARK**):

- `realForward` jiftaħ is-socket upstream tiegħu permezz ta'
  `connectMarked(ip, port, DEFAULT_BYPASS_MARK)` — `DEFAULT_BYPASS_MARK = 0x539`
  — li jistabbilixxi **SO_MARK** **qabel** `connect()`, sabiex is-SYN
  tat-trażmissjoni 'l quddiem iġorr il-marka tal-bypass.
- Ir-regola `mangle OUTPUT` teskludi konnessjonijiet li diġà jġorru l-marka
  tal-bypass (`-m mark ! --mark <bypassMark>`), għalhekk it-trażmissjoni 'l quddiem
  tal-proxy **ma terġax** tiġi mmarkata u ma terġax tidħol fit-TPROXY.

> Nota dwar l-implimentazzjoni: is-socket immarkat għall-bypass irid jiġi installat
> fuq `createConnection` tal-agent (`https.request({ createConnection })` jiġi
> injorat mingħajr ebda avviż meta jkun hemm agent), inkella t-trażmissjoni 'l
> quddiem tiftaħ socket mhux immarkat u l-loop jerġa' jseħħ. Din kienet is-soluzzjoni
> kontra l-loop ivvalidata permezz tal-e2e.

## §7 Applikazzjoni / treġġigħ lura tranżazzjonali tal-firewall

Kraxx qatt ma għandu jħalli warajh regola `mangle` jew rotta skaduta. Il-bennej tal-kmandi
(`src/mitm/tproxy/commands.ts`) u l-eżekutur (`src/mitm/tproxy/setup.ts`) jiggarantixxu li
**t-treġġigħ lura huwa l-invers eżatt tal-applikazzjoni, f’ordni bil-maqlub**.

`applyTproxy(cfg)` iħaddem il-kmandi tal-applikazzjoni fl-ordni; f’każ ta’ **kwalunkwe** falliment iħaddem
`revertTproxy(cfg)` sħiħ fuq bażi tal-aħjar sforz u jerġa’ jitfa’ l-iżball — għalhekk il-firewall ikun jew
applikat kompletament jew imreġġa’ lura kompletament, u qatt applikat parzjalment. `revertTproxy(cfg)` iħaddem
il-kmandi inversi f’ordni bil-maqlub u jinjora l-fallimenti (idempotenti — jista’ jissejjaħ
mingħajr kundizzjoni, eż. mit-tindif `repairMitm()` ta’ AgentBridge).

`validateTproxyConfig(cfg)` jitħaddem qabel kwalunkwe kmand: il-ports iridu jkunu `1–65535`,
`mark`/`routeTable`/`bypassMark` iridu jkunu numri sħaħ pożittivi, u `bypassMark` irid
ikun differenti minn `mark` (kontra l-loop).

### Kmandi tal-applikazzjoni (fl-ordni)

```bash
ip rule add fwmark <mark> lookup <routeTable>
ip route add local 0.0.0.0/0 dev lo table <routeTable>
iptables -t mangle -A OUTPUT -p tcp --dport <dport> -m mark ! --mark <bypassMark> -j MARK --set-mark <mark>
iptables -t mangle -A PREROUTING -p tcp --dport <dport> -m mark --mark <mark> -j TPROXY --on-port <onPort> --tproxy-mark <mark>
```

It-treġġigħ lura jħassarhom f’ordni bil-maqlub: `PREROUTING -D`, `OUTPUT -D`, `ip route del`, `ip rule del`.

> Ir-riċetta hija bbażata fuq **OUTPUT** minħabba li l-każ ta’ użu tal-MITM huwa traffiku
> ħiereġ _lokali_ (apps fuq l-istess host), li TPROXY f’`PREROUTING` waħdu ma
> jarax — `PREROUTING` jara biss traffiku mgħoddi. Il-katina `OUTPUT` timmarka
> konnessjonijiet lokali ġodda, l-`ip rule` terġa’ tidderiġihom lejn kunsinna lokali (`lo`), u
> mbagħad `PREROUTING` tassenjahom lis-semmiegħ trasparenti.

## §8 Konfigurazzjoni

It-talba għall-bidu (`POST /api/tools/agent-bridge/tproxy`) taċċetta l-oqsma li ġejjin,
ivvalidati minn `StartTproxyBodySchema` (`tproxy/route.ts`). Kollha huma fakultattivi
u, jekk ma jingħatawx, jużaw il-valuri predefiniti tagħhom:

| Qasam            | Tip                | Valur predefinit | Noti                                                                                                                                         |
| ---------------- | ------------------ | ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **dport**        | int (1–65535)      | `443`            | Il-port TCP tad-destinazzjoni li għandu jiġi interċettat b’mod trasparenti                                                                   |
| **mark**         | int (≥1)           | `0x2333`         | Il-marka tal-firewall issettjata fuq `OUTPUT`, imqabbla mill-`ip rule` + `PREROUTING`                                                        |
| **onPort**       | int (1–65535)      | `8443`           | Il-port li miegħu jintrabat is-semmiegħ trasparenti (**IP_TRANSPARENT**)                                                                     |
| **routeTable**   | int (≥1)           | `233`            | L-id tat-tabella tar-routing tal-politika li fiha tinsab ir-rotta `local 0.0.0.0/0`                                                          |
| **bypassMark**   | int (≥1, ≠ `mark`) | `0x539`          | Il-marka tal-bypass tas-socket (**SO_MARK**) li l-proxy jissettja fuq il-konnessjonijiet upstream tiegħu; eskluża f’`OUTPUT` (kontra l-loop) |
| **sudoPassword** | string             | —                | Għal desktops mhux root biss: tawtorizza l-installazzjoni fit-trust store; tiġi injorata meta l-utent ikun root                              |

Ma hemm **ebda varjabbli tal-ambjent** għal TPROXY — il-konfigurazzjoni kollha ssir permezz
tal-body tal-POST jew tal-valuri predefiniti ta’ hawn fuq.

## §10 Soluzzjoni tal-problemi

### It-toggle huwa diżattivat

L-addon nattiv ma jistax jitgħabba. Ikkonferma: li qed tuża Linux, li bnejt l-addon
(`npm run build:native:tproxy`), u li l-proċess jista' jgħabbi `transparent.node`.
`isTransparentSocketAvailable()` jikkontrolla t-toggle; `GET /api/tools/agent-bridge/tproxy`
jirritorna `available: false` meta l-addon ikun nieqes.

### Ma jinqabad xejn

- Ikkonferma li l-proċess interċettat fil-fatt jikkonnettja mad-`dport`
  ikkonfigurat (il-valur predefinit huwa `443`).
- Ikkonferma li l-proċess jafda s-CA dinamika. Is-CA tiġi installata taħt
  `omniroute-tproxy-ca.crt`; apps bil-maħżen tal-fiduċja tagħhom stess (Firefox/Chrome NSS)
  jista' jkollhom bżonn li ċ-ċertifikat jiżdied hemm ukoll.
- Ħaddem l-awtotest **Dijanjostika** ta' AgentBridge (ara
  [`AGENTBRIDGE.md`](../frameworks/AGENTBRIDGE.md)) għal kontrolli tal-fiduċja fiċ-ċertifikat /
  tas-saħħa tas-server.

### Regoli tal-firewall li jibqgħu wara crash

`revertTproxy()` huwa l-invers eżatt tal-applikazzjoni u huwa idempotenti. Meta twaqqaf
il-modalità, ir-regoli jitreġġgħu lura; jekk OmniRoute twaqqaf f'nofs sessjoni, uża l-azzjoni
**Tiswija** ta' AgentBridge (`POST /api/tools/agent-bridge/repair`) biex tneħħi l-istat
orfni tas-sistema (spoof tad-DNS, CA ewlenija, proxy tas-sistema). Ir-regoli `mangle`
ta' TPROXY u r-rotta jitneħħew ukoll awtomatikament meta terġa' titħaddem is-sistema.

### Loop infinit / il-proxy jinterċetta t-trażmissjoni tiegħu stess

Dan huwa l-każ kontra l-loop. Ikkonferma li `bypassMark` huwa differenti minn `mark` (il-validazzjoni
tiżgura dan) u li t-trażmissjoni tuża `connectMarked` (hekk tagħmel f'`realForward`).
Ara [§5 Kontra l-loop](#anti-loop-so_mark).
