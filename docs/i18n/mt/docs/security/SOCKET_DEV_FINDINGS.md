sejbiet ta’ `AI-detected potential malware` irrappurtati kontra `omniroute@3.8.5` u
l-miżuri ta’ mitigazzjoni applikati f’`omniroute@3.8.6`. Jeżisti sabiex:

1. L-operaturi tal-pipeline tas-sigurtà jkollhom referenza waħda x’jiċċitaw meta jkollhom bżonn
   jevalwaw is-sejbiet fid-dawl tal-kodiċi sors reali.
2. Skaners tal-IA futuri jkunu jistgħu jagħrfu d-dikjarazzjoni ffirmata mill-mantenitur li kull
   mogħdija mmarkata hija intenzjonata, tintuża biss b’għażla espliċita, u hija ddokumentata.
3. Ikollna rekord bil-miktub ta’ _għaliex_ kull post tas-sejħa huwa strutturat kif inhu —
   sabiex refactoring futur ma jerġax jintroduċi bi żball marka distintiva li
   tneħħiet apposta.

Jekk tħaddem skaner li jerġa’ jimmarka xi wieħed mill-postijiet tas-sejħiet hawn taħt wara li
l-mitigazzjonijiet ta’ v3.8.6 ikunu ġew rilaxxati, jekk jogħġbok iftaħ issue bit-traċċa tal-iskan u
aħna nestendu l-attestazzjoni hawnhekk.

## §1 — Installazzjoni ta’ root CA għall-MITM (`77484.js`)

**Fajls tas-sors**:

- `src/mitm/cert/install.ts` — `installCert()` / `uninstallCert()` pubbliċi,
  u `installCertWindows/Mac/Linux` għal kull pjattaforma.
- `src/mitm/systemCommands.ts` — helpers kondiviżi ta’ `execFile` / `spawn` / PowerShell
  użati mill-mogħdijiet tal-installazzjoni.

**Attivatur**: l-utent jikklikkja "Ippermetti l-proxy MITM" fid-dashboard lokali f’
`/dashboard/cli-tools/mitm`. Ir-rotta hija disponibbli biss permezz tal-loopback — ara r-regola stretta #17 f’
`CLAUDE.md` u `src/server/authz/routeGuard.ts::isLocalOnlyPath()`. JWT żvelat
permezz ta’ mina **ma jistax** jattiva din il-mogħdija tal-kodiċi.

**Operazzjonijiet privileġġati mwettqa (għal kull pjattaforma)**:

| OS                     | Kmand(i)                                                                                                          |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | `certutil -addstore Root <cert>` permezz tal-UAC                                                                  |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | aġġornament tad-DB NSS għal kull profil permezz ta’ `certutil -d sql:<profile>`                                   |

Dawn huma l-istess kmandi użati minn `mitmproxy`, Charles Proxy, Fiddler, u
Caddy. Il-fatt li jeżistu f’OmniRoute huwa ddokumentat f’
`docs/security/STEALTH_GUIDE.md`.

**Mitigazzjoni ta’ v3.8.6**:

- `runElevatedPowerShell()` ma għadux juża `-EncodedCommand <base64utf16le>`.
  Il-payload elevat jinkiteb f’fajl temporanju `.ps1` għal kull sejħa (modalità 0o600,
  ġewwa direttorju privat `mkdtempSync`) u ssir referenza għalih permezz ta’ `-File`. Il-
  fajl jitneħħa f’`finally`. Dan ineħħi l-marka distintiva tipika ta’
  elevazzjoni permezz ta’ PowerShell bil-base64 li ġiet immarkata mill-klassifikatur tal-AI ta’
  Socket.dev.
- `installCertWindows` jinkludi blokka inline `SECURITY-AUDITOR-NOTE:`
  li tindika din it-taqsima.

**Għaliex inżommuh**: il-proxy MITM huwa funzjonalità ddokumentata użata minn
`docs/security/STEALTH_GUIDE.md` u `docs/frameworks/MITM-PROXY.md`. It-tneħħija
tiegħu tkisser is-sett ta’ funzjonalitajiet tal-agent bridge.

## §2 — Importazzjoni tal-kredenzjali ta’ Zed (`app/api/providers/zed/import/route.js`)

**Fajls tas-sors**:

- `src/app/api/providers/zed/discover/route.ts` _(ġdid f’v3.8.6)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(ġdid f’v3.8.6)_

**Attivazzjoni**: l-utent jikklikkja "Importa minn Zed" fil-paġna Providers tad-dashboard lokali. L-endpoint huwa protett minn `requireManagementAuth`. L-editur Zed innifsu jikteb iċ-ċwievet API tal-fornituri tiegħu fil-keychain tas-sistema operattiva taħt ismijiet ta’ servizzi dokumentati — ara https://zed.dev/docs/ai/llm-providers.

**Imġiba f’v3.8.5 (dik li Socket.dev immarka)**:

`POST /import` kien jiskopri l-kredenzjali u jissejvjahom awtomatikament fil-ħażna SQLite lokali fi vjaġġ wieħed. L-ebda konferma għal kull kont, l-ebda fingerprint, sempliċiment "instabu N tokens, kollha ġew importati."

**Mitigazzjoni f’v3.8.6 — konferma f’2 passi**:

1. **`POST /api/providers/zed/discover`** jirritorna
   `{ candidates: [{ provider, service, account, fingerprint }] }`. It-token mhux ipproċessat **qatt** ma jiġi trażmess. Il-fingerprint huwa
   `sha256(service|account|token).slice(0,16)`.
2. Id-dashboard juri l-lista tal-kandidati, l-operatur jagħżel liema minnhom għandu jimporta, u jibgħat `{ confirmedAccounts: [{ service, account, fingerprint }] }`
   lil **`POST /api/providers/zed/import`**.
3. L-endpoint tal-importazzjoni **jerġa’ jaqra l-keychain fuq is-server** u jiffiltra skont
   `(service, account, fingerprint)`. Rispons ta’ discover li jkun ġie mbagħbas jew riprodott mill-ġdid ma jistax iqarraq bl-endpoint tal-importazzjoni biex jissejvja token mhux relatat —
   jekk it-token attwali jkun inbidel minn meta sar discover, il-fingerprint ma jibqax jaqbel u l-kredenzjali tinqabeż.

Flag tal-ambjent `OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` iżomm l-imġiba ta’ v3.8.5 għall-operaturi li għadhom ma aġġornawx l-awtomazzjoni tagħhom. Dan se jitneħħa f’v3.9.

**Għaliex inżommuh**: l-importazzjoni minn Zed hija l-aktar rotta faċli ta’ onboarding għall-utenti li diġà jużaw Zed u jridu jirriflettu ċ-ċwievet tal-fornituri tagħhom f’OmniRoute mingħajr ma jerġgħu jwaħħluhom.

## §3 — `execFile` / `spawn` / PowerShell bi privileġġi elevati (`21843.js`)

**Fajls tas-sors**: `src/mitm/systemCommands.ts`.

**Għaliex ġie mmarkat**: iċ-chunk jerġa’ jesporta `execFileWithPassword`,
`runElevatedPowerShell`, u l-helper kondiviż `quotePowerShell`. Il-klassifikatur tal-IA ta’ Socket.dev jarahom bħala "sett ġeneriku ta’ għodod għall-eżekuzzjoni fuq il-host u l-elevazzjoni tal-privileġġi." Fi ħdan OmniRoute dawn jintużaw biss mir-rotta tal-installazzjoni taċ-ċertifikat MITM
(§1) u minn `execFileWithPassword` għall-eżekuzzjoni ta’ kmandi `sudo`.

**Mitigazzjoni f’v3.8.6**:

- Rifatturazzjoni ta’ `runElevatedPowerShell` (ara §1).
- Blokka inline `SECURITY-AUDITOR-NOTE:` kemm f’
  `runElevatedPowerShell` kif ukoll f’`execFileWithPassword` tiddokumenta l-callers fil-lista permessa u l-lista fissa tal-fajls eżegwibbli.
- Is-sejħa `spawn()` ta’ `execFileWithPassword` tinkludi markatur `nosemgrep` bil-lista permessa ta’ fajls eżegwibbli li l-helper jista’ jirċievi — **ma teżisti ebda rotta mill-input tal-utent għal `finalCommand`/`finalArgs`**.

## §4 / §6 — Superviżur tas-servizz 9router (`api/services/9router/{start,restart}/route.js`)

**Fajls tas-sors**:

- `src/app/api/services/9router/_lib.ts` — fabbrika tas-superviżur.
- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`.
- `src/lib/services/ServiceSupervisor.ts` — spawn ġeneriku / stħarriġ tas-saħħa / buffer tar-reġistru.

**Attivazzjoni**: l-utent jikklikkja "Installa" / "Ibda" fil-paġna tas-servizzi integrati fid-dashboard lokali.

**Protezzjonijiet diġà implimentati**:

- Ir-rotot kollha `/api/services/*` huma LOCAL_ONLY skont
  `src/server/authz/routeGuard.ts` (regola stretta #17). L-infurzar tal-loopback iseħħ qabel kwalunkwe verifika tal-awtentikazzjoni — JWT żvelat ma jistax jilħaqhom.
- Ir-ringiela ta’ 9router fid-DB tinħoloq bħala `status='not_installed', auto_start=0` (ara
  `src/lib/db/migrations/071_services.sql:19`). Is-servizz **ma** jibdiex mal-ewwel tnedija.
- `spawn()` jissejjaħ bil-path tal-binary ritornat minn
  `resolveSpawnArgs(apiKey, PORT)` f’`src/lib/services/installers/ninerouter.ts`,
  li hija lista fissa ta’ binaries appoġġjati.
- Stdout/stderr jinżamm f’buffer fil-memorja (limitu ta’ 5 MB, ara `_lib.ts`) — ma ssir ebda kitba fuq id-diska sakemm l-utent ma jattivax il-logging mid-dashboard.

**Mitigazzjoni f’v3.8.6**: ebda bidla funzjonali. Il-profil minimu tal-build
(`OMNIROUTE_BUILD_PROFILE=minimal`) jissostitwixxi
`src/lib/services/installers/ninerouter.ts` bi stub għall-utenti li jridu li r-rotot privileġġati jitneħħew fiżikament mill-bundle.

**Għaliex inżommuh**: 9router huwa servizz anċillari fakultattiv li jista’ jiġi installat lokalment (aħseb fih bħal plugin ta’ WordPress) — strettament fuq għażla espliċita.

## §5 — Kitba lura tal-kredenzjali ta’ OmniRoute Cloud Sync (`api/keys/[id]/route.js`)

**Fajls tas-sors**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`.
- `src/app/api/keys/[id]/route.ts` — isejjaħ `syncKeysToCloudIfEnabled()`.

**Attivatur**: `isCloudEnabled()` jirritorna `true` (issettjat mid-dashboard) **u**
`CLOUD_URL` ikun ikkonfigurat. Meta t-tnejn ikunu mitfija, ma ssir l-ebda sejħa
tan-network ’il barra lejn l-endpoint tal-Cloud.

**Imġiba ta’ v3.8.5 (il-bug li Socket.dev identifika b’mod korrett)**:

`updateLocalTokens()` kien jissostitwixxi `accessToken`, `refreshToken`, u
`providerSpecificData` mir-rispons tal-Cloud meta
`cloudUpdatedAt > localUpdatedAt`. L-ebda HMAC, l-ebda firma, l-ebda checksum.
`CLOUD_URL` ikkonfigurat ħażin jew ostili (jew MITM fuq il-kanal) seta’
jissostitwixxi t-tokens OAuth tal-fornitur mingħajr ebda indikazzjoni.

**Mitigazzjoni f’v3.8.6**:

1. **Verifika HMAC**: `verifyCloudSignature(rawBody, sigHeader)` jiċċekkja
   l-header `X-Cloud-Sig` (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`) qabel ma jipproċessa l-JSON. Jekk is-secret ikun issettjat, il-firma
   tkun meħtieġa. Jekk le (modalità legacy), jiġi rreġistrat twissija u r-rispons
   jiġi aċċettat — is-secret se jkun meħtieġ f’v3.9.
2. **Opt-in għall-fields sigrieti**: `accessToken` / `refreshToken` /
   `providerSpecificData` jiġu sostitwiti **biss** meta
   `OMNIROUTE_CLOUD_SYNC_SECRETS=true`. Il-modalità awtomatika tissinkronizza
   biss metadata li mhijiex kredenzjali (`expiresAt`, `status`, `lastError*`,
   `rateLimitedUntil`, `updatedAt`). Din hija **bidla inkompatibbli** għall-utenti
   li kienu jiddependu fuq is-sinkronizzazzjoni remota tat-tokens — iridu jagħmlu
   opt-in b’mod espliċitu.

**Għaliex inżommuha**: Cloud Sync huwa l-uniku mod kif tenant ta’ OmniRoute Cloud
jista’ jiċċentralizza l-kredenzjali tat-tim. Is-soluzzjoni tagħmel il-mudell
tat-theddid ċar:
"is-server jiffirma, il-klijent jivverifika, l-operatur jagħmel opt-in."

## Profil tal-build: `minimal`

Għall-utenti li jeħtieġu artifact adattat għal Socket, agħmlu build b’:

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

Il-webpack `NormalModuleReplacementPlugin` jagħmel alias ta’ erba’ modules għal stubs:

| Module                                      | Stub                                             |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

Kull stub jesporta l-istess interfaċċa, iżda kull funzjoni tarmi
`featureDisabledError(name)` waqt l-eżekuzzjoni. Ir-routes li jiddependu fuq il-module
diżattivat jirritornaw HTTP 503 b’messaġġ ċar minflok jattivaw il-mogħdija
sensittiva tal-code.

Il-bundle li jirriżulta huwa maħsub biex jiġi ppubblikat bħala `omniroute-secure`. Ara
`docs/ops/PUBLISHING_SECURE.md` għar-riċetta tal-pubblikazzjoni.

## Qsim tal-plugin (segwit għal v4)

Fuq medda twila ta' żmien, għandna l-ħsieb li naqsmu l-pakkett npm f'moduli
li jistgħu jiġu awditjati separatament. Ara l-istadju importanti v4 fit-tracker tal-issues ta' GitHub għall-issue
ta' traċċar.
