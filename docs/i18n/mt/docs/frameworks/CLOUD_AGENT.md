OmniRoute jorkestra aġenti ta’ kodifikazzjoni ospitati fil-cloud minn partijiet terzi (Codex Cloud, Cursor,
Devin, Jules) bħala kompiti li jdumu għaddejjin fit-tul. Kull aġent jitgeżwer wara interfaċċa uniformi sabiex
il-klijenti jkunu jistgħu jissottomettu prompt + URL tar-repożitorju u jirċievu r-riżultati mingħajr ma jkollhom
jittrattaw APIs speċifiċi għall-fornitur.

Kompitu ta’ Cloud Agent **mhuwiex** tlestija regolari ta’ chat. Huwa unità ta’ xogħol
durabbli u b’diversi passi li tista’ tieħu minn minuti sa sigħat, tista’ tipproduċi Pull Request bħala
l-artefatt tagħha, u tappoġġja messaġġi ta’ segwitu u (għal xi fornituri) stadji ta’ approvazzjoni tal-pjan.

## Arkitettura

```
Klijent (Dashboard / CLI / API)
  → POST /api/v1/agents/tasks (awtentikazzjoni tal-ġestjoni meħtieġa)
    → validazzjoni ta’ CreateCloudAgentTaskSchema (Zod)
    → registry.getAgent(providerId)
    → getCloudAgentCredentials(providerId)
      └─ jikseb minn getProviderConnections({ provider, isActive: true })
         (apiKey l-ewwel, u jekk ma jkunx disponibbli juża accessToken)
    → agent.createTask({ prompt, source, options }, credentials)
      └─ HTTP POST lejn l-API tal-fornitur upstream
      └─ jirritorna CloudAgentTask b’id intern + externalId
    → insertCloudAgentTask(...) f’cloud_agent_tasks (SQLite)

Stħarriġ perjodiku (sinkronizzazzjoni għażżiena waqt il-qari):
  GET /api/v1/agents/tasks/[id]
    → getCloudAgentTaskById(id)
    → agent.getStatus(externalId, credentials)  // jaġġorna l-istatus + l-attivitajiet
    → updateCloudAgentTask(...) bl-istatus, ir-riżultat u completed_at il-ġodda
    → jirritorna l-kompitu sserjalizzat

Interazzjonijiet:
  POST /api/v1/agents/tasks/[id]  korp: { action: "approve" | "message" | "cancel" }
    → agent.approvePlan(externalId, credentials)        għal "approve"
    → agent.sendMessage(externalId, message, credentials) għal "message"
    → l-istatus jinbidel għal "cancelled"               għal "cancel" (lokali biss)
```

Is-sinkronizzazzjoni hija **għażżiena**: l-istatus jiġi aġġornat mill-upstream ma’ kull `GET /tasks/[id]`.
Ma hemm l-ebda stħarriġ perjodiku fl-isfond. Dashboards li jeħtieġu stat aġġornat għandhom jagħmlu stħarriġ tal-endpoint GET
f’intervall raġonevoli.

## Interfaċċa `CloudAgentBase`

Sors: `src/lib/cloudAgent/baseAgent.ts`

```typescript
export interface AgentCredentials {
  apiKey: string;
  baseUrl?: string;
}

export interface CreateTaskParams {
  prompt: string;
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
}

export interface GetStatusResult {
  status: CloudAgentStatus;
  externalId?: string;
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
}

export abstract class CloudAgentBase {
  abstract readonly providerId: string;
  abstract readonly baseUrl: string;

  abstract createTask(p: CreateTaskParams, c: AgentCredentials): Promise<CloudAgentTask>;
  abstract getStatus(externalId: string, c: AgentCredentials): Promise<GetStatusResult>;
  abstract approvePlan(externalId: string, c: AgentCredentials): Promise<void>;
  abstract sendMessage(
    externalId: string,
    message: string,
    c: AgentCredentials
  ): Promise<CloudAgentActivity>;
  abstract listSources(
    c: AgentCredentials
  ): Promise<{ name: string; url: string; branch?: string }[]>;

  protected mapStatus(raw: string): CloudAgentStatus; // string tal-fornitur upstream ibbażata fuq euristika → enum
  protected generateTaskId(): string; // `task_<ts>_<rand>`
  protected generateActivityId(): string; // `act_<ts>_<rand>`
}
```

`CodexCloudAgent.approvePlan` intenzjonalment jarmi eċċezzjoni — Codex Cloud jippjana
awtomatikament u ma għandux stadju ta' approvazzjoni. `CodexCloudAgent.listSources`
jirritorna `[]`.

`CursorCloudAgent` iħaddem il-Background / Cloud Agents ta' Cursor permezz tal-API REST
uffiċjali tiegħu (`api.cursor.com/v0`) b'**API key ta' utent jew ta' service account** —
l-alternattiva aktar sikura u tal-fornitur innifsu għall-użu mill-ġdid tas-sessjoni OAuth
tal-Cursor IDE (il-fornitur `cursor`, li jġorr twissija dwar ir-riskju ta' projbizzjoni).
Huwa adapter REST sempliċi (mingħajr dipendenza nattiva fuq `@cursor/sdk`).
`approvePlan` jarmi eċċezzjoni (l-aġenti ta' Cursor jaħdmu b'mod awtonomu);
`listSources` jelenka r-repożitorji aċċessibbli bil-key. Cursor jirritorna enums
tal-istatus b'ittri kbar (`CREATING`/`RUNNING`/`FINISHED`/`ERROR`), immappjati
b'mod espliċitu mal-`CloudAgentStatus` kondiviż. `baseUrl` jista' jiġi sostitwit
għal kull kredenzjali sabiex il-verżjoni/il-path tal-API jkunu jistgħu jiġu kkoreġuti
mingħajr bidla fil-code.

```typescript
export const CLOUD_AGENT_STATUS = {
  QUEUED: "queued",
  RUNNING: "running",
  AWAITING_APPROVAL: "awaiting_approval",
  COMPLETED: "completed",
  FAILED: "failed",
  CANCELLED: "cancelled",

export interface CloudAgentSource {
  repoName: string;
  repoUrl: string; // irid ikun URL validu
  branch?: string;
}

export interface CloudAgentResult {

  commitMessage?: string;
  diffUrl?: string;
  summary?: string;

export interface CloudAgentActivity {
  id: string;
  type: "plan" | "command" | "code_change" | "message" | "error" | "completion";
  content: string;
  timestamp: string; // ISO 8601
  metadata?: Record<string, unknown>;
}

export interface CloudAgentTask {
  id: string; // id intern `task_...`
  providerId: "jules" | "devin" | "codex-cloud" | "cursor-cloud";
  externalId?: string; // l-id tal-fornitur upstream
  status: CloudAgentStatus;
  prompt: string; // 1..10000 karattru
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
  createdAt: string;
  updatedAt: string;
  completedAt?: string;
}
```

## Bażi tad-data

Sors: `src/lib/cloudAgent/db.ts` — it-tabella tinħoloq b’mod differit permezz ta’
`createCloudAgentTaskTable()` (imsejħa wkoll minn `src/lib/cloudAgent/index.ts` waqt
l-importazzjoni tal-modulu).

```sql
CREATE TABLE IF NOT EXISTS cloud_agent_tasks (
  id           TEXT PRIMARY KEY,
  provider_id  TEXT NOT NULL,
  external_id  TEXT,
  status       TEXT NOT NULL DEFAULT 'queued',
  prompt       TEXT NOT NULL,
  source       TEXT NOT NULL,             -- JSON
  options      TEXT DEFAULT '{}',         -- JSON
  result       TEXT,                       -- JSON
  activities   TEXT DEFAULT '[]',          -- JSON
  error        TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_provider ON cloud_agent_tasks(provider_id);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_status   ON cloud_agent_tasks(status);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_created  ON cloud_agent_tasks(created_at DESC);
```

`updateCloudAgentTask` jinforza **lista permessa ta’ kolonni** biex jipprevjeni l-injezzjoni SQL:
`status`, `prompt`, `source`, `options`, `result`, `activities`, `error`,
`completed_at`. Kull key oħra fl-aġġornament parzjali titneħħa mingħajr ebda avviż.

## REST API — Ċiklu tal-ħajja tal-kompitu

**Awtentikazzjoni:** L-endpoints kollha `/api/v1/agents/tasks*` jeħtieġu **awtentikazzjoni tal-ġestjoni**
(`requireCloudAgentManagementAuth` tinkapsula `requireManagementAuth` minn
`src/lib/api/requireManagementAuth`). Dan ilu jiġi infurzat mill-commit `588a0333`
(_"fix(auth): require management auth for agent and cooldown APIs"_).

| Metodu  | Path                          | Għan                                                                  |
| ------- | ----------------------------- | --------------------------------------------------------------------- |
| OPTIONS | `/api/v1/agents/tasks`        | Preflight ta’ CORS                                                    |
| GET     | `/api/v1/agents/tasks`        | Elenka l-kompiti (filtru: `provider`, `status`, `limit≤500`)          |
| POST    | `/api/v1/agents/tasks`        | Oħloq kompitu (jibagħtu upstream + jippersistih)                      |
| DELETE  | `/api/v1/agents/tasks?id=...` | Ħassar kompitu permezz tal-query id (**ma** jikkanċellax upstream)    |
| OPTIONS | `/api/v1/agents/tasks/[id]`   | Preflight ta’ CORS                                                    |
| GET     | `/api/v1/agents/tasks/[id]`   | Aqra l-kompitu + issinkronizza b’mod differit l-istatus minn upstream |
| POST    | `/api/v1/agents/tasks/[id]`   | Azzjoni: `approve` / `message` / `cancel`                             |
| DELETE  | `/api/v1/agents/tasks/[id]`   | Ħassar kompitu permezz tal-path id                                    |

### Oħloq kompitu

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Fix the bug in src/foo.ts where the parser returns null",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    },
    "options": {
      "autoCreatePr": true,
      "planApprovalRequired": false
    }
  }'
```

Rispons `201`:

```json
{
  "data": {
    "id": "task_1731512345678_abc123def",
    "providerId": "devin",
    "externalId": "session_xyz",
    "status": "queued",
    "prompt": "...",
    "source": { "repoName": "user/repo", "repoUrl": "...", "branch": "main" },
    "options": { "autoCreatePr": true },
    "createdAt": "2026-05-13T12:34:56.789Z"
  }

```

### Approva pjan

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"action":"approve"}'
```

### Ibgħat messaġġ ta’ segwitu

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"message","message":"Also add a unit test for the parser"}'
```

### Ikkanċella (status lokali biss)

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"cancel"}'
```

`cancel` ibiddel `status` għal `"cancelled"` fid-DB lokali iżda **ma** jsejjaħx lill-
fornitur upstream — m’hemm l-ebda abort RPC f’`CloudAgentBase`. Biex twaqqaf il-kontijiet
upstream, waqqaf il-kompitu mill-console tal-fornitur stess.

## REST API — Infrastruttura tal-Fornitur tal-Cloud

Dawn l-endpoints awżiljarji taħt `src/app/api/cloud/` jintużaw minn klijenti remoti
(is-CLI, l-app Electron, jew ħaddiema tas-sinkronizzazzjoni) biex jaqraw il-metadata tal-konnessjoni tal-fornitur
u jirriżolvu l-aliases tal-mudelli. Dawn jiġu awtentikati b’**ċavetta API regolari**
(permezz ta’ `validateApiKey`), mhux bl-awtentikazzjoni tal-ġestjoni użata mill-endpoints tal-kompiti.

| Metodu | Mogħdija                        | Għan                                                                                       |
| ------ | ------------------------------- | ------------------------------------------------------------------------------------------ |
| POST   | `/api/cloud/auth`               | Jivvalida ċ-ċavetta API, jirritorna metadata tal-konnessjoni moħbija + aliases tal-mudelli |
| PUT    | `/api/cloud/credentials/update` | Jaġġorna `accessToken` / `refreshToken` / `expiresAt`                                      |
| POST   | `/api/cloud/model/resolve`      | Jirriżolvi alias ta’ mudell għal `{ provider, model }`                                     |
| GET    | `/api/cloud/models/alias`       | Jelenka l-aliases kollha tal-mudelli                                                       |
| PUT    | `/api/cloud/models/alias`       | Jissettja alias ta’ mudell (u jissinkronizzah awtomatikament mal-Cloud jekk attivat)       |

`/api/cloud/auth` qatt ma jirritorna `apiKey` / `accessToken` / `refreshToken` mhux moħbija. Huwa
jirritorna `hasApiKey`, `hasAccessToken`, `hasRefreshToken`, u dehra parzjali moħbija
(`maskedApiKey`: l-ewwel 4 + `****` + l-aħħar 4).

## Riżoluzzjoni tal-Kredenzjali

`getCloudAgentCredentials(providerId)` f’`src/lib/cloudAgent/api.ts`:

1. Jgħabbi l-konnessjonijiet attivi tal-fornitur permezz ta’ `getProviderConnections({ provider: providerId, isActive: true })`.
2. Għal kull konnessjoni, jippreferi `apiKey` (wara li jitneħħa l-ispazju żejjed). Jekk din ma tkunx disponibbli, juża `accessToken`.
3. Jirritorna l-ewwel token mhux vojt imgeżwer bħala `{ apiKey: token }`.
4. Jirritorna `null` jekk ma jinstab ebda token li jista’ jintuża — l-API twieġeb b’`400` u
   `"No active credentials configured for cloud agent provider: <id>"`.

Dan ifisser li l-Cloud Agents jerġgħu jużaw l-istess tabella tal-Konnessjonijiet tal-Fornituri bħall-fornituri LLM
regolari. Biex tattiva lil Jules, oħloq konnessjoni attiva b’`provider: "jules"`
u `apiKey` mimlija.

## Integrazzjoni ma’ A2A

Il-Cloud Agents jistgħu jiġu esposti bħala ħiliet A2A billi tiġi rreġistrata ħila A2A li tiddelega

tal-kompiti A2A għall-protokoll JSON-RPC 2.0. Ara [A2A-SERVER.md](./A2A-SERVER.md).

## Żieda ta’ Cloud Agent Ġdid

1. Oħloq `src/lib/cloudAgent/agents/<name>.ts` li jestendi `CloudAgentBase`.
2. Implimenta `createTask`, `getStatus`, `approvePlan` (jew iġġenera eċċezzjoni jekk mhux applikabbli),
   `sendMessage`, `listSources`. Uża `this.mapStatus(...)` għan-normalizzazzjoni tal-istatus.
3. Irreġistrah f’`src/lib/cloudAgent/registry.ts` taħt `providerId` stabbli.
4. Estendi l-unjoni litterali `providerId` f’`src/lib/cloudAgent/types.ts`
   (`CloudAgentTask.providerId` u `CreateCloudAgentTaskSchema`).
5. Żid il-fornitur ma’ `src/shared/constants/providers.ts` jekk jeħtieġ rekord ta’
   konnessjoni. Il-fornituri bbażati fuq OAuth jeħtieġu wkoll `src/lib/oauth/providers/`.
6. Żid testijiet taħt `tests/unit/cloud-agent-*.test.ts`.
7. Aġġorna dan id-dokument u l-kostanti `CLOUD_AGENTS` tad-dashboard.
