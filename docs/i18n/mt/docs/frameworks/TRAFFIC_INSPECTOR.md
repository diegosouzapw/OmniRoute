Traffic Inspector huwa d-debugger integrat tat-traffiku HTTPS ta' OmniRoute — għodda simili għal Charles Proxy / mitmweb / HTTP Toolkit li hija **konxja tal-LLM** u **konxja tal-aġenti**. Tinsab f'`/dashboard/tools/traffic-inspector` u tirċievi traffiku dirett minn sa 5 sorsi ta' qbid simultanji.

**Post fid-dashboard:** `/dashboard/tools/traffic-inspector`
**Grupp fil-sidebar:** Għodod (wara AgentBridge)
**Ara wkoll:** [`AGENTBRIDGE.md`](./AGENTBRIDGE.md) — AgentBridge huwa l-modalità ta' qbid 1.

### L-arkitettura f'paragrafu wieħed

It-`TrafficBuffer` (`src/mitm/inspector/buffer.ts`) huwa buffer ċirkolari kondiviż fil-memorja (b'mod awtomatiku 1000 entrata, konfigurabbli permezz ta' `INSPECTOR_BUFFER_SIZE`). Is-sorsi kollha tal-qbid jiktbu fih permezz ta' `push()`. Il-buffer jikklassifika kull entrata billi juża `kindDetector.ts` (jiddetermina jekk hijiex talba lil LLM), jikkalkula `contextKey` (marka tas-swaba' SHA-256 tal-prompt tas-sistema), u jxandar lill-abbonati kollha tal-WebSocket permezz ta' `globalTrafficBuffer.subscribe()`. Id-dashboard jikkonnettja permezz ta' `GET /api/tools/traffic-inspector/ws` u jirċievi snapshot mal-konnessjoni, segwit minn avvenimenti `new`/`update`/`clear`.

## §2 Modi tal-qbid

Traffic Inspector jappoġġja **5 sorsi simultanji tal-qbid**. Kull wieħed jista’ jiġi attivat jew diżattivat b’mod indipendenti. Il-kamp `source` fuq kull `InterceptedRequest` (`src/mitm/inspector/types.ts`) ikun wieħed minn `"agent-bridge"`, `"custom-host"`, `"http-proxy"`, `"system-proxy"`, jew `"tproxy"`.

### Modalità 1 — AgentBridge (predefinita, dejjem attiva)

**Sors:** Handlers ta’ AgentBridge (`src/mitm/handlers/base.ts`)
**Mekkaniżmu:** Kull sejħa `intercept()` f’`MitmHandlerBase` issejjaħ `hookBufferStart()` qabel it-trażmissjoni u `hookBufferUpdate()` meta titlesta. Ma teħtieġ ebda konfigurazzjoni addizzjonali — taħdem malli AgentBridge ikun qed jaħdem.
**Kopertura:** Id-9 aġenti tal-IDE kkonfigurati f’AgentBridge
**Nota:** Il-kamp `source` f’`InterceptedRequest` = `"agent-bridge"`

### Modalità 2 — Hosts personalizzati (ridirezzjoni tad-DNS)

**Sors:** Lista ta’ hosts definita mill-utent (tabella `inspector_custom_hosts`)
**Mekkaniżmu:** Iż-żieda ta’ host permezz tal-UI żżid `127.0.0.1 <host>` ma’ `/etc/hosts` (teħtieġ sudo). Is-server MITM eżistenti ta’ AgentBridge (port 443) jiġġenera ċertifikat SNI b’mod dinamiku għall-host il-ġdid.
**Kopertura:** Kwalunkwe applikazzjoni li tuża l-host miżjud — ma hija meħtieġa ebda bidla fil-konfigurazzjoni tal-applikazzjoni
**Nota:** `source` = `"custom-host"`

Eżempji ta’ każijiet ta’ użu:

- Immonitorja `api.openai.com` minn skripts Python
- Iddibaggja `my-internal-llm.company.com`
- Aqbad traffiku minn apparati mobbli fuq l-istess netwerk (permezz ta’ ARP spoofing — avvanzat)

### Modalità 3 — Listener HTTP_PROXY (port 8080)

**Sors:** Applikazzjonijiet li jużaw il-varjabbli tal-ambjent `HTTP_PROXY`/`HTTPS_PROXY`
**Mekkaniżmu:** Listener sekondarju fuq il-port 8080 (`src/mitm/inspector/httpProxyServer.ts`) li jaġixxi bħala proxy HTTP/HTTPS espliċitu standard. Jaċċetta mini `CONNECT` (HTTPS) u talbiet HTTP diretti.
**Kopertura:** Kwalunkwe applikazzjoni li tirrispetta l-varjabbli tal-ambjent `HTTP_PROXY` — ebda bidla fid-DNS, ebda sudo
**Nota:** `source` = `"http-proxy"`

```bash
# Qbid rapidu għal kmand wieħed:
HTTPS_PROXY=http://127.0.0.1:8080 curl https://api.openai.com/v1/models

# Qbid persistenti f'sessjoni tax-shell:
export HTTP_PROXY=http://127.0.0.1:8080
export HTTPS_PROXY=http://127.0.0.1:8080
```

**Limitazzjoni tat-TLS:** Il-mini HTTPS `CONNECT` jinqabdu bħala metadata biss (host, port, ħinijiet) — il-korp TLS ma jiġix deċifrat b’mod predefinit. Attiva l-għażla "Iddeċifra HTTPS fil-modalità proxy" (teħtieġ attivazzjoni espliċita u li ċ-ċertifikat ta’ AgentBridge ikun fdat) biex tispezzjona l-korp kollu.

**Kunflitt tal-port:** Jekk il-port 8080 ikun qed jintuża, AgentBridge jirritorna 409 bi żball strutturat. Ibdel il-port permezz tal-varjabbli tal-ambjent `INSPECTOR_HTTP_PROXY_PORT`.

### Modalità 4 — Proxy għas-sistema kollha (avvanzata, teħtieġ attivazzjoni espliċita)

**Sors:** Settings tal-proxy fil-livell tas-sistema operattiva (japplikaw għall-applikazzjonijiet kollha fuq il-magna)
**Mekkaniżmu:** Juża APIs tas-sistema operattiva biex jirridirezzjona t-traffiku HTTP/HTTPS kollu permezz tal-listener HTTP_PROXY:

- **macOS:** `networksetup -setwebproxy / -setsecurewebproxy`
- **Linux:** `gsettings set org.gnome.system.proxy` + `/etc/environment`
- **Windows:** `netsh winhttp set proxy 127.0.0.1:8080`
  **Kopertura:** Kull applikazzjoni fuq il-magna li tirrispetta s-settings tal-proxy tas-sistema
  **Nota:** `source` = `"system-proxy"`

**Mekkaniżmi tas-sikurezza:**

- Timer għad-diżattivazzjoni awtomatika (30 minuta b’mod predefinit, konfigurabbli permezz ta’ `INSPECTOR_SYSTEM_PROXY_GUARD_MINUTES`)
- L-istat preċedenti tal-proxy tas-sistema jiġi ssejvjat fid-DB u rrestawrat meta l-bidla titreġġa’ lura
- Id-dashboard juri l-messaġġ "Qed jitreġġa’ lura l-proxy tas-sistema" jekk l-utent jinnaviga ’l bogħod waqt li jkun attiv
- L-UI turi badge `⚠ Avvanzat` + kaxxa ta’ kontroll għal konferma espliċita

### Modalità 5 — Deċifrar trasparenti TPROXY (Linux, root, teħtieġ attivazzjoni espliċita)

**Sors:** TPROXY tal-kernel + routing ibbażat fuq policies (`src/mitm/tproxy/`)
**Mekkaniżmu:** Jimmarka konnessjonijiet TCP lokali ġodda li joħorġu lejn port fil-mira (b’mod predefinit `443`) f’`mangle OUTPUT`; `ip rule` jerġa’ jidderieġi l-pakketti mmarkati lejn il-konsenja lokali, u l-mira `TPROXY` ta’ `mangle PREROUTING` tgħaddihom lil listener trasparenti (**IP_TRANSPARENT**) (b’mod predefinit fuq il-port `8443`). Il-listener itemm it-TLS b’ċertifikat leaf maħruġ **għal kull hostname SNI meta jintalab** minn CA dinamika, jaqbad l-iskambju ddeċifrat, u jittrażmetti t-talba, ikkriptata mill-ġdid, lejn id-destinazzjoni oriġinali.
**Kopertura:** Hosts ta’ destinazzjoni **arbitrarji** fuq il-port fil-mira — ebda spoof ta’ `/etc/hosts`, ebda varjabbli tal-ambjent `HTTP_PROXY`, u ebda bidla fil-proxy tas-sistema kollha. Il-proċess interċettat ma jeħtieġ ebda bidla fil-konfigurazzjoni, iżda jrid jafda lis-CA dinamika.
**Nota:** `source` = `"tproxy"`

**Rekwiżiti:** Linux biss (**IP_TRANSPARENT** huwa disponibbli fuq Linux biss), il-kapaċità **CAP_NET_ADMIN** (root), u addon N-API nattiv li jrid jinbena b’toolchain C (`npm run build:native:tproxy`). Meta ma jkunx disponibbli, l-għażla fid-dashboard tkun diżattivata bit-tooltip "Id-deċifrar TPROXY jeħtieġ Linux + root + l-addon nattiv". Ir-regoli tal-firewall jiġu applikati jew imreġġgħin lura b’mod tranżazzjonali (crash qatt ma jħalli warajh regola `mangle`) u jitneħħew meta s-sistema terġa’ tinbeda. Mekkaniżmu kontra l-loops ibbażat fuq SO_MARK jipprevjeni li t-trażmissjoni tal-proxy stess, ikkriptata mill-ġdid, terġa’ tiġi interċettata.

Din hija sottosistema sostanzjali bil-gwida ddedikata tagħha għall-operaturi — ara `docs/security/MITM-TPROXY-DECRYPT.md` (git; mhux ikkumpilata f’`/docs`) għar-riċetta sħiħa tal-firewall, is-CA dinamika għal kull SNI + l-installatur tal-maħżen taċ-ċertifikati fdati, ir-rotta lokali biss, id-dettalji kontra l-loops, u l-iskema tal-konfigurazzjoni. L-għażla hija kkontrollata minn `GET / POST / DELETE /api/tools/agent-bridge/tproxy` (nota: ir-rotta tinsab taħt il-prefiss ta’ AgentBridge, mhux taħt il-prefiss ta’ Traffic Inspector).

### 3.2 Lista tat-talbiet (pannell tax-xellug)

- **Virtwalizzata** (`useVirtualList` + `ResizeObserver`): timmaniġġja 1000 element mingħajr ma teħel
- **Skrolljar awtomatiku** b'kontroll biex twaqqfu waqt l-ispezzjoni
- **Status ikkodifikat bil-kuluri**: aħdar (2xx), isfar (3xx), aħmar (4xx/5xx), griż (għadu għaddej)
- **Emoji tal-aġent**: 🔵 Antigravity, 🟢 Copilot, 🟠 Kiro, 🟣 Codex, 🔷 Cursor, 🟤 Zed, 🟡 Claude Code, ⚫ Open Code, 🌐 host personalizzat
- **Barra tal-kulur tal-kuntest**: bordura tax-xellug ta' 1px ikkulurita skont `contextKey` (SHA-256 tal-prompt tas-sistema) — tiġbor viżwalment konverżazzjonijiet relatati
- **Body għażżien**: il-body tat-talba magħżula biss jiġi mmaterjalizzat fit-tabs tad-dettalji (jevita r-rendering ta' 1000 body ta' 1MB kull wieħed)

## §4 Karatteristiċi konxji tal-LLM

### 4.1 Ditekter tat-tip (`src/mitm/inspector/kindDetector.ts`)

Jikklassifika kull talba bħala `"llm"`, `"app"`, jew `"unknown"` permezz ta’ 4 sinjali:

1. **Reġistru tal-hosts** — madwar 18-il hostname magħruf tal-API tal-LLM (OpenAI, Anthropic, Gemini, Groq, Mistral, Together, Fireworks, Cohere, Perplexity, Hugging Face, OpenRouter, xAI, Moonshot, eċċ.)
2. **Mudelli tal-paths** — `/v1/chat/completions`, `/v1/messages`, `/generateContent`, `/v1/responses`, eċċ.
3. **Struttura tal-body** — jidentifika l-fields `messages[]` (OpenAI/Claude), `contents[]` (Gemini), `prompt`, `input`
4. **Indikazzjonijiet mill-user-agent** — `codex`, `claude`, `gemini`, `antigravity`, `kiro`, `copilot`, `cursor` fis-string tal-UA

Il-hosts personalizzati miżjuda permezz tal-Modalità 2 jirtu l-`kind` tagħhom mill-input tal-formola (b’mod awtomatiku jkun `"custom"`).

### 4.2 Għaqda tal-SSE (`src/mitm/inspector/sseMerger.ts`)

**Implimentazzjoni indipendenti clean-room.** L-ipproċessar tal-events isegwi l-
[algoritmu WHATWG għall-events mibgħuta mis-server](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream),
filwaqt li r-rikostruzzjoni ssegwi l-iskemi pubbliċi ta’ streaming ta’
[OpenAI](https://platform.openai.com/docs/api-reference/chat/create),
[Anthropic](https://platform.claude.com/docs/en/build-with-claude/streaming), u
[Gemini](https://ai.google.dev/api/generate-content#method:-models.streamgeneratecontent).

Jirrikostitwixxi l-messaġġ finali tal-assistent mill-events delta mhux ipproċessati tal-SSE:

- **Anthropic**: jakkumula `content_block_delta` skont l-indiċi; jimmaniġġja `text_delta`, `input_json_delta` (sejħiet tal-għodod), `thinking_delta`
- **OpenAI**: jakkumula l-għażliet/sejħiet tal-għodod ta’ Chat Completions u l-output items tal-Responses API
  skont l-indiċi
- **Gemini**: jakkumula `candidates[i].content.parts`
- **Mhux magħruf**: jirritorna l-events mhux ipproċessati kif inhuma

It-tab Response turi swiċċ: **"Events mhux ipproċessati ↔ Magħqudin"**.

### 4.3 Normalizzatur tal-konverżazzjonijiet (`src/mitm/inspector/conversationNormalizer.ts`)

**Implimentazzjoni indipendenti clean-room.** In-normalizzazzjoni hija ddefinita minn kuntratti
black-box lokali u mill-iskemi pubbliċi tal-messaġġi ta’ OpenAI, Anthropic, u Gemini; ma jintuża
l-ebda kodiċi tas-sors tal-implimentazzjoni upstream.

Jikkonverti l-formati tal-messaġġi ta’ OpenAI, Anthropic, u Gemini għal `NormalizedConversation` waħda qabel ir-rendering:

```ts
interface NormalizedConversation {
  request: NormalizedTurn[]; // messages / contents / prompt mill-body tat-talba
  response: NormalizedTurn[]; // risposta tal-assistent (magħquda permezz ta’ sseMerger)
  contextKey: string | null; // marka tas-swaba’ SHA-256 tal-prompt tas-sistema
}
```

Tipi ta’ blocks: `text`, `tool_use`, `tool_result`. It-tab Conversation tuża din l-istruttura irrispettivament mill-fornitur.

### 4.4 Kulurizzazzjoni tal-context key (`src/mitm/inspector/contextKey.ts`)

- Jikkalkula `SHA-256` tal-prompt tas-sistema (l-ewwel messaġġ `role:system`, jew il-field `system`, jew `systemInstruction` ta’ Gemini)
- Jirritorna prefiss eżadeċimali ta’ 12-il karattru (`"a3f9c2..."`)
- Il-frontend jimmappja ċ-ċavetta għal kulur HSL deterministiku għall-barra tax-xellug
- **Filtru "l-istess kuntest"**: meta tikklikkja ċ-chip `ctx #a3f`, jiżdied filtru biex jintwerew biss it-talbiet bl-istess marka tas-swaba’

Dan jagħmilha faċli biex viżwalment tiddistingwi bejn "personas" jew kompiti differenti li jkunu qed jitħaddmu fl-istess sessjoni tal-aġent.

### 4.5 Estrazzjoni tal-metadata tal-LLM

Għat-talbiet tal-LLM, it-tab LLM Details testratta:

```ts
interface LlmMetadata {
  provider: string | null; // "openai" | "anthropic" | "gemini" | ...
  apiKind: string | null; // "chat.completions" | "messages" | "embeddings" | ...
  model: string | null; // mill-body tat-talba jew mir-risposta
  messages: number; // għadd ta’ turns
  tokensIn: number | null; // usage.prompt_tokens / usage.input_tokens
  tokensOut: number | null; // usage.completion_tokens / usage.output_tokens
  streamed: boolean; // true jekk ir-risposta tkun SSE
  mappedTo: string | null; // header x-omniroute-mapped
  costEstimateUsd: number | null; // spiża stmata abbażi tal-ipprezzar ta’ OmniRoute
}
```

### 4.6 Filtru live għal talbiet li għadhom għaddejjin

Il-field `status` tat-talba huwa `number | "in-flight" | "error"` — entrata
tiġi miżjuda bħala `"in-flight"` fil-mument li tibda t-talba u tiġi **aġġornata fl-istess post**
meta tasal ir-risposta (jew l-iżball). Is-swiċċ **"Live"** tat-toolbar
(`liveOnly`, iċ-ċavetta i18n `trafficInspector.liveOnly`) jirrestrinġi l-lista għall-entrati
li għandhom `status === "in-flight"`, biex tkun tista’ tosserva l-konnessjonijiet miftuħa f’ħin reali.

Il-filtru huwa predicate pur fuq in-naħa tal-client f’
`src/lib/inspector/matchesTrafficFilter.ts`:

```ts
if (f.liveOnly && req.status !== "in-flight") return false;
```

L-istat tas-swiċċ jinsab f’`useTrafficFilters` (il-hooks tad-dashboard tal-ispettur) u
jingħaqad mal-filtri l-oħra (profil, host, aġent, sors, status, kuntest).

### 4.7 Attribuzzjoni tal-proċess (Linux)

Fuq Linux, kull talba interċettata tista’ tiġi attribwita lill-**proċess lokali
li oriġinaha**. Żewġ fields fakultattivi jiżdiedu ma’ `InterceptedRequest`:

```ts
pid?: number;          // id tal-proċess li oriġinaha (Linux biss)
processName?: string;  // isem tal-proċess li oriġinaha (Linux biss)
```

`src/mitm/inspector/processAttribution.ts` jimmappja l-port temporanju tal-_client_
tal-konnessjoni għal PID + isem billi:

1. Jaqra `/proc/net/tcp` u `/proc/net/tcp6` biex isib l-inode tas-socket għall-
   port (`parseProcNetTcpForInode`, parser pur li jista’ jiġi ttestjat b’fixtures).
2. Jiskennja `/proc/<pid>/fd/` għal symlink lejn `socket:[<inode>]`.
3. Jaqra l-isem tal-proċess minn `/proc/<pid>/comm`.

Cache TTL ta’ sekonda jillimita l-ispiża tal-iskennjar tal-procfs taħt tagħbija. L-attribuzzjoni ssir
fuq bażi ta’ **best-effort** — kwalunkwe falliment jirriżolvi għal `null` u qatt ma jimblokka l-capture. Fuq
macOS/Windows il-funzjoni tirritorna `null` (stub; l-appoġġ għal `lsof`/`GetExtendedTcpTable`
huwa titjib sussegwenti).

## §6 Sigurtà

Traffic Inspector juri **t-traffiku HTTPS interċettat kollu**, inklużi l-headers tal-awtorizzazzjoni u l-bodies tat-talbiet. Hemm dawn il-kontrolli fis-seħħ:

| Kontroll                              | Dettalji                                                                                                                                                                                                        |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LOCAL_ONLY**                        | Ir-rotot kollha u l-endpoint tal-WebSocket huma aċċessibbli biss permezz tal-loopback (infurzat f'`routeGuard.ts` qabel l-awtentikazzjoni)                                                                      |
| **Maskra tas-sigrieti**               | L-iskaner lineari `maskSecret()` jaħbi l-kredenzjali Bearer ta' RFC 6750, iċ-ċwievet bi prefiss tal-fornitur u t-tokens opaki twal qabel `TrafficBuffer.push()`                                                 |
| **Limitu tad-daqs tal-body**          | Il-bodies > `INSPECTOR_MAX_BODY_KB` (default 1024 KB) jitqassru b'avviż `"(imqassar għall-prestazzjoni)"`                                                                                                       |
| **Sanitizzazzjoni tal-headers**       | L-ismijiet jinbidlu għal ittri żgħar; il-headers tal-framing/hop-by-hop u tal-awtentikazzjoni tal-proxy jitneħħew; il-cookies jinħbew kompletament; il-valuri tal-kredenzjali jiġu ddelegati lil `maskSecret()` |
| **CSP**                               | Politika stretta tas-Sigurtà tal-Kontenut fuq il-paġni ta' Traffic Inspector biex tipprevjeni XSS permezz ta' bodies tar-risposti injettati                                                                     |
| **Ebda persistenza b'mod awtomatiku** | It-`TrafficBuffer` jinżamm fil-memorja u jintilef meta jerġa' jinbeda s-server. Is-sessjonijiet jinżammu b'mod persistenti biss meta jiġu rreġistrati espliċitament                                             |

### Regoli stretti applikati

| Regola                            | Applikazzjoni                                                                                  |
| --------------------------------- | ---------------------------------------------------------------------------------------------- |
| **#12** `sanitizeErrorMessage`    | Ir-risposti kollha ta' żball HTTP mir-rotot ta' Traffic Inspector jiġu sanitizzati             |
| **#15 + #17** `isLocalOnlyPath()` | `/api/tools/traffic-inspector/` hija LOCAL_ONLY + SPAWN_CAPABLE (kmandi tal-proxy tas-sistema) |

### Limitazzjonijiet magħrufa

- **Il-modalità tal-proxy għas-sistema kollha** taffettwa l-applikazzjonijiet kollha fuq il-magna, inklużi l-klijenti VPN u SSO. Dejjem użaha bit-tajmer tad-diżattivazzjoni awtomatika. Tużahiex fuq magni kondiviżi.
- **HTTPS permezz ta' mina CONNECT**: Il-Modalità 3 (HTTP_PROXY) taqbad biss il-metadata tal-mina għal destinazzjonijiet HTTPS sakemm ma tkunx attivata l-interċettazzjoni TLS. Dan huwa intenzjonat — il-qbid trasparenti mingħajr ma ċ-ċertifikat ta' AgentBridge ikun fdat jikser il-verifika TLS għal dawk l-apps.
- **Strings hardcoded f'xi komponenti**: Xi komponenti tal-UI (F7/F8) għandhom għadd żgħir ta' strings hardcoded li għadhom mhumiex koperti minn ċwievet i18n. Dawn huma ddokumentati bħala Limitazzjoni Magħrufa fir-rapport tal-lakuni tal-i18n; se jiġu migrati f'fażi sussegwenti. L-strings affettwati huma tikketti dekorattivi tal-UI li ma jeħtiġux traduzzjoni għall-użu funzjonali.

## §7 Soluzzjoni tal-problemi

### Skonnessjoni tal-WebSocket

Jekk il-monitoraġġ dirett juri "Skonnettjat":

1. Iċċekkja li s-server għadu qed jaħdem: `GET /api/tools/traffic-inspector/capture-modes`
2. Erġa' tella' l-paġna — il-WebSocket jerġa' jaqbad u jirċievi stampa aġġornata
3. Jekk is-server reġa' nbeda, il-buffer fil-memorja jkun tħassar — l-entrati l-qodma jintilfu sakemm ma tkunx ġiet irreġistrata sessjoni

### Kunflitt fil-port 8080

Jekk il-modalità HTTP_PROXY tonqos milli tibda:

```bash
lsof -i :8080    # sib il-proċess
```

Ibdel il-port:

```bash
# .env
INSPECTOR_HTTP_PROXY_PORT=8888
```

### Il-proxy tas-sistema ma ġiex irriversjat

Jekk OmniRoute jieqaf jaħdem waqt li l-modalità proxy tas-sistema kollha tkun attiva:

**macOS:**

```bash
networksetup -setwebproxystate Wi-Fi off
networksetup -setsecurewebproxystate Wi-Fi off
```

**Linux (GNOME):**

```bash
gsettings set org.gnome.system.proxy mode 'none'
```

**Windows:**

```cmd
netsh winhttp reset proxy
```

Fid-dħul li jmiss, id-dashboard se joffri wkoll "Irriversja l-proxy tas-sistema" jekk jinduna li l-istat fid-DB jindika li l-proxy kien attiv.

### Buffer mimli

Meta l-buffer jilħaq `INSPECTOR_BUFFER_SIZE` (il-valur predefinit huwa 1000), l-entrati l-ġodda jneħħu l-eqdem entrati. Jekk qed jintilfu talbiet importanti:

- Żid `INSPECTOR_BUFFER_SIZE` (eż., 5000) — dan juża aktar memorja biex id-data tinżamm għal aktar żmien
- Irreġistra sessjoni biex tippersisti l-medda rilevanti fid-DB
