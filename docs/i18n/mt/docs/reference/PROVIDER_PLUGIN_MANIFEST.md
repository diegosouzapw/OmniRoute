`open-sse/config/providerPluginManifest.ts` jiddefinixxi l-kuntratt tal-plugin tal-fornitur
li huwa sikur għall-JSON. `open-sse/config/providerPluginManifestRegistry.ts` jorbot dak
il-kuntratt mar-reġistru attwali tal-fornituri għal sidecars bħal Bifrost,
CLIProxyAPI, jew router futur bil-Go/Rust. Ir-reġistru TypeScript jibqa'
s-sors awtorevoli, iżda s-sidecars jistgħu jużaw il-manifest mingħajr ma jimportaw
kodiċi tal-eżekutur, valuri predefiniti ta' OAuth, headers, jew l-istat tal-ambjent tal-proċess.

L-istess manifest huwa disponibbli fuq HTTP f'
`GET /api/v1/provider-plugin-manifest` għal sidecars li jaħdmu barra mill-proċess.

OmniRoute jirreklama dak il-URL lil Bifrost u CLIProxyAPI permezz tal-header tat-talba
`X-OmniRoute-Provider-Manifest-Url`. Issettja
`OMNIROUTE_PROVIDER_MANIFEST_URL` meta s-sidecar ikollu bżonn URL pubbliku jew URL tan-network
tal-container minflok l-oriġini lokali tat-talba.

## Aġġornament tal-Manifest

L-endpoint HTTP jirritorna `Cache-Control: public, max-age=60` u
`ETag` b'saħħtu. Sidecar għandu jżomm l-aħħar manifest ivvalidat u jibgħat l-ETag tiegħu
f'`If-None-Match` meta jaġġorna. Rispons `304 Not Modified` ma jkollux body;
is-sidecar iżomm il-manifest fil-cache tiegħu. Jekk ma jeżisti ebda manifest ivvalidat fil-cache,
is-sidecar għandu jagħmel talba mingħajr kundizzjonijiet minflok jaċċetta `304`.

## Għan

Il-metadata tal-fornituri għandha timxi lejn kuntratt ta' plugin sabiex il-passaġġ attiv tat-talbiet
ikun jista' eventwalment jiġi ġestit minn sidecar b'latency aktar baxxa filwaqt li OmniRoute jżomm
ir-rotta TypeScript bħala l-punt ta' kontroll tal-politiki u bħala fallback. Il-manifest huwa addittiv:
waħdu ma jbiddilx ir-routing tat-talbiet.

## Kuntratt

Il-manifest fih:

- l-id u l-alias tal-fornitur
- il-format upstream u l-isem tal-eżekutur
- it-tip ta' awtentikazzjoni, il-header tal-awtentikazzjoni, u prefiss fakultattiv tal-awtentikazzjoni
- metadata statika tal-endpoint
- l-eliġibbiltà għas-sidecar u raġunijiet espliċiti meta fornitur għandu jibqa' fuq TS
- metadata tal-mudelli sikura għall-JSON bħat-tul tal-kuntest, il-flags tal-viżjoni/irraġunar, u
  params mhux appoġġjati
- tags tal-kapaċitajiet inklużi `apikey`, `oauth`, `custom-executor`,
  `passthrough-models`, `responses`, `sidecar-candidate`, `usage-fetch`, u `usage-supported`

Il-manifest jeskludi intenzjonalment:

- sigrieti tal-klijent OAuth u valuri sigrieti predefiniti
- ir-riżoluzzjoni tal-ambjent waqt l-eżekuzzjoni
- headers tat-talbiet u helpers tal-kredenzjali pubbliċi
- builders dinamiċi tal-URLs
- funzjonijiet tal-eżekutur
- dettalji interni tal-pool tas-sessjonijiet

## Tags tal-Kapaċitajiet

`capabilities` huwa array magħżul ta' tags derivati mill-entrata tar-reġistru. L-integraturi
għandhom iqisuh bħala t-tweġiba li tinqara mill-magni għall-mistoqsija "x'jista' jagħmel dan il-fornitur", minflok
jerġgħu jaqraw is-sorsi TypeScript.

| Tag                  | Tifsira                                                                                      |
| -------------------- | -------------------------------------------------------------------------------------------- |
| `apikey`             | Jaċċetta API key (`authType` huwa `apikey` jew `optional`).                                  |
| `oauth`              | Juża fluss OAuth jew fluss ta' sessjoni.                                                     |
| `responses`          | Jesponi URL bażi tal-OpenAI Responses API.                                                   |
| `passthrough-models` | Joffri mudelli direttament mill-upstream minflok katalgu statiku.                            |
| `custom-executor`    | Iħaddem eżekutur mhux predefinit, għalhekk jibqa' fuq il-passaġġ TypeScript.                 |
| `sidecar-candidate`  | Jirrifletti `sidecar.eligible` — sikur biex jiġi kkunsidrat għall-importazzjoni fis-sidecar. |
| `usage-fetch`        | Għandu fetcher tal-użu jew tal-kwota mqabbad (`getUsageForProvider`).                        |
| `usage-supported`    | L-API tal-użu taċċetta lil dan il-fornitur (`isSupportedUsageConnection`).                   |

`usage-fetch` huwa biss għall-iskoperta. Jindika li OmniRoute jaf kif jaqra l-użu għall-
fornitur; ma jattivax il-fetching, ma jbiddilx is-semantika tal-kwoti, u lanqas ma jimplika li
l-widget tal-kwoti fid-Dashboard huwa attivat għall-fornitur — dak il-widget huwa kkontrollat separatament minn
`USAGE_SUPPORTED_PROVIDERS`. Is-sors awtorevoli huwa `USAGE_FETCHER_PROVIDERS` f'
`open-sse/services/usage/fetcherProviders.ts`.

Dik il-lista tuża bħala keys l-strings li jaċċetta d-dispatcher tal-użu, għalhekk tħallat ids kanoniċi
ma' aliases u hija ftit itwal min-numru ta' fornituri bit-tags: entrati li
mhumiex fornituri taċ-chat fir-reġistru tal-manifest (pereżempju l-fornitur tat-tiftix `firecrawl`
u l-fornitur ACP `amazon-q`) m'għandhomx entrata fil-manifest li magħha jista' jiġi assoċjat tag.

`usage-supported` jindika jekk ir-rotot tal-użu tas-server u tad-Dashboard jaċċettawx konnessjoni
għall-fornitur. Jirrifletti `isSupportedUsageConnection()` (`src/lib/usage/providerLimits.ts`)
u `supportsProviderQuota()` (`src/shared/utils/providerQuotaVisibility.ts`), it-tnejn ikkontrollati minn
`USAGE_SUPPORTED_PROVIDERS` (`open-sse/services/usage/supportedProviders.ts`). Għall-kuntrarju ta'
`usage-fetch`, dan jinħareġ fuq l-id tal-fornitur biss — il-kontroll waqt l-eżekuzzjoni jagħmel
`USAGE_SUPPORTED_PROVIDERS.includes(providerId)` mingħajr riżoluzzjoni tal-alias, għalhekk il-manifest
iżomm l-istess regola. Iż-żewġ tags għandhom ambiti differenti: 3 fornituri għandhom biss
`usage-fetch` (`opencode`, `opencode-zen`, `xai`) u 1 għandu biss
`usage-supported` (`xiaomi-mimo-token-plan`), għalhekk wieħed ma jimplikax lill-ieħor.

## Użu tas-Sidecar

Is-sidecars għandhom iqisu `sidecar.eligible` bħala sinjal konservattiv ta’ kandidat, mhux bħala deċiżjoni inkundizzjonata ta’ routing. L-ewwel miri għall-importazzjoni għandhom ikunu fornituri li jużaw API key u endpoint statiku bl-eżekutur predefinit. Fornituri b’eżekuturi web personalizzati, flussi OAuth/session, bennejja dinamiċi tal-URL, jew konfigurazzjoni tal-pool għandhom jibqgħu fil-perkors fallback ta’ TypeScript sakemm sidecar jimplimenta mġiba ekwivalenti u t-telemetrija turi parità.

Fażijiet suġġeriti għall-migrazzjoni:

1. Iġġenera u vvalida l-manifest tal-plugin tal-fornitur mir-reġistru TS.
2. Għallem lil Bifrost jew CLIProxyAPI jimporta l-manifest għall-fornituri b’API key/endpoint statiku.
3. Irrutta l-fornituri eliġibbli permezz tas-sidecar wara `OMNIROUTE_RELAY_BACKEND`, filwaqt li żżomm it-TS fallback attivat.
4. Ippromwovi l-fornituri biss meta r-rata ta’ suċċess, il-latenza p99, l-imġiba tal-istreaming, u l-ġestjoni ta’ parametri mhux appoġġjati jaqblu mal-perkors TS.
5. Żid plugins nattivi għas-sidecar għall-eżekuturi personalizzati, familja waħda ta’ fornituri kull darba.

## Għaliex Ma Ninkorporawx il-Fornituri Direttament F’Next

Il-frontend ta’ Next m’għandux ikun responsabbli għall-eżekuzzjoni tal-fornituri. Għandu jsejjaħ il-konfini tal-API. Imbagħad il-backend jista’ jiddeċiedi jekk jużax l-eżekutur ta’ TypeScript, Bifrost, CLIProxyAPI, jew sidecar nattiv futur. Dan iżomm l-iffirmar tat-talbiet, il-verifiki tal-allowlist, il-politika tad-DB, u l-imġiba ta’ fallback ċentralizzati qabel kwalunkwe trasferiment lejn sidecar.
