Ir-relays (Vercel, Deno, Cloudflare) itemmu l-konnessjoni upstream fuq backend
serverless sabiex OmniRoute jkun jista’ joħroġ minn reġjun stabbli filwaqt li
jżomm il-kjavi API tal-fornitur fuq in-naħa tas-server. Dan id-dokument ikopri ż-żewġ modi ta’
falliment li l-operaturi jiltaqgħu magħhom fil-produzzjoni u l-modi ta’ rkupru li OmniRoute jipprovdi għal
kull wieħed.

## Kif tinħażen l-awtentikazzjoni tar-relay

Meta tuża relay minn **Settings → Proxy Pool → Deploy Relay**, il-proċess ta’
użu jaħżen it-token tal-awtentikazzjoni tar-relay fil-field JSON `notes` tal-proxy:

- Jekk `STORAGE_ENCRYPTION_KEY` ikun issettjat, it-token jinkiteb bħala `relayAuthEnc`
  (ikkriptat b’AES waqt il-ħażna).
- Inkella jinkiteb bħala test sempliċi `relayAuth`.

Fil-ħin tat-talba, `extractRelayAuth(notes)` jirritorna kwalunkwe forma li tkun preżenti,
għalhekk ir-relay jibqa’ jaħdem wara li jerġa’ jinbeda.

## Mod ta’ falliment 1 — token li ma jistax jiġi ddekriptat wara rotazzjoni tal-kjavi

**Sintomu:** relays li qabel kienu jaħdmu issa jirritornaw żbalji upstream
`401`/ta’ awtentikazzjoni wara rotazzjoni tal-ambjent jew tal-maniġer tas-sigrieti ta’
`STORAGE_ENCRYPTION_KEY`. Il-blob `relayAuthEnc` maħżun ma jistax jibqa’
jiġi ddekriptat, għalhekk `extractRelayAuth` jirritorna string vojta u r-relay ma jibgħat
l-ebda awtentikazzjoni.

**Irkupru — tiswija fil-post (mingħajr użu mill-ġdid):**

1. Iftaħ **Settings → Proxy Pool**.
2. Ir-ringieli tar-relay li l-awtentikazzjoni tagħhom hija nieqsa juru badge safra `auth missing` u
   buttuna **Repair**.
3. Ikklikkja **Repair**. OmniRoute jsejjaħ
   `POST /api/settings/proxies/[id]/repair-relay`, li:
   - jiddekripta `relayAuthEnc` bil-kjavi **attwali**,
   - jerġa’ jikteb it-test sempliċi `relayAuth` f’`notes`,
   - jirritorna `{ repaired: true, mode: "recovered" }`.

Ir-relay jerġa’ jibda jservi mingħajr ma jkollok terġa’ ddaħħal kredenzjali tal-użu.

Dan jaħdem biss jekk il-`STORAGE_ENCRYPTION_KEY` attwali jkun għadu jista’ jiddekripta l-
blob. Jekk dawwart il-kjavi **mingħajr** migrazzjoni, il-blob ma jistax
jiġi rkuprat.

## Mod ta’ falliment 2 — token li ma jistax jiġi rkuprat (il-kjavi preċedenti m’għadhomx disponibbli)

**Sintomu:** għafast **Repair** u rċevejt
`{ repaired: false, mode: "redeploy", status: 409 }`.

**Irkupru — użu mill-ġdid:**

It-token maħżun ma jistax jiġi rkuprat bil-kjavi attwali. Erġa’ uża r-relay
mill-istess modal li użajt oriġinarjament (il-menu **Deploy Relay** → Vercel / Deno
/ Cloudflare). Il-proċess tal-użu jikteb token ġdid (ikkriptat bil-kjavi attwali)
u l-badge `auth missing` tar-ringiela tisparixxi.

Fl-UI, il-buttuna **Repair** stess tiftaħ il-modal tal-użu mill-ġdid meta t-
token ma jkunx jista’ jiġi rkuprat, għalhekk qatt ma jkollok għalfejn tfittxu manwalment.

## Mod ta’ falliment 3 — relay aċċessibbli iżda mhux f’saħħtu

**Sintomu:** it-test tal-proxy (il-buttuna `speed`) juri li r-relay huwa attiv iżda t-talbiet
xorta jfallu b’mod intermittenti.

Iċċekkja l-headers ta’ għarfien tar-relay irritornati mis-sonda tat-test awtomatiku ta’ OmniRoute
(ara **Settings → Proxy Pool** u l-counters `relayTested` / `relayAlive`):

- `x-relay-url` — liema backend tar-relay wieġeb.
- `x-relay-mode` — `ts` | `bifrost` | `auto` għal dik it-talba.
- `x-relay-attempts` — kemm-il qabża tar-relay ġiet ippruvata qabel is-suċċess.
- `x-relay-fallback` — `true` meta t-talba qalbet mill-backend preferut
  għar-relay TypeScript.

Rata għolja ta’ `x-relay-fallback` flimkien ma’ `relayAlive` baxx tfisser li l-backend
sidecar mhuwiex f’saħħtu u għandek jew issewwih jew tibdel l-istrateġija tal-backend tar-relay
għal `ts` (ara `RELAY_BACKEND_STRATEGY.md`).

## Referenza tal-API

| Metodu | Mogħdija                                  | Korp                    | Suċċess                                                                                                                                                  | Falliment                                                                                       |
| ------ | ----------------------------------------- | ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `POST` | `/api/settings/proxies/[id]/repair-relay` | `{ "id": "<proxyId>" }` | `200 { repaired: true, mode: "recovered" }` meta jiġi derivat mill-ġdid; `200 { repaired: false, mode: "noop" }` meta t-test sempliċi jkun diġà preżenti | `409 { mode: "redeploy" }` ma jistax jiġi rkuprat; `400` mhuwiex tip ta’ relay; `404` ma nstabx |

Ir-route tal-lista `GET /api/settings/proxies` iżżid
`relayInfo: { isRelay, authMissing, repairMode }` mingħajr sigrieti ma’ kull element sabiex id-dashboard
ikun jista’ juri l-għażla tat-tiswija mingħajr qatt ma jesponi t-token.
