> **TOML huwa l-uniku format effettiv.** Codex modern jaqra `~/.codex/config.toml`
> esklussivament (ivverifikat b’codex-cli 0.147.0: `codex --help` jiddokumenta
> s-sostituzzjonijiet ta’ `-c/--config` bħala "loaded from `~/.codex/config.toml`"). Il-fajl l-antik
> `~/.codex/config.yaml` kien tal-CLI npm preċedenti u jiġi injorat mingħajr avviż.
> Il-ġeneratur tad-dashboard (`/api/cli-tools/apply`, għodda `codex`) jikteb TOML b’merġjar
> konservattiv — iċ-ċwievet eżistenti u l-blokki ta’ providers oħra jinżammu, iċ-ċavetta
> tal-API tibqa’ f’`OMNIROUTE_API_KEY` (qatt fil-fajl), u `config.yaml` preċedenti li jkun
> għadu fadal jiġi rrappurtat bħala nota ta’ migrazzjoni mingħajr ma jintmess.

## config.toml lest biex jitwaħħal

Ibdel `<YOUR_HOST>` u `<YOUR_KEY>` bil-valuri tiegħek:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # limitu tal-ħażna tal-istorja għal kull sejħa tal-għodda

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc jew ~/.zshrc — il-valur proprju taċ-ċavetta, qatt f’config.toml
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: Codex inkluż fl-app ChatGPT

Jekk installajt Codex permezz tal-app tad-desktop ChatGPT, il-binarju `codex` jista’
jkun jeżisti biss fil-pakkett tal-app u jkun għadu mhux fuq il-`PATH` tas-shell tiegħek. Żid
id-direttorju tar-riżorsi mal-fajl tal-istartjar tas-shell tiegħek:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

Iftaħ shell ġdid, imbagħad ivverifika:

```bash
command -v codex
codex --version
```

### OmniRoute lokali mingħajr awtentikazzjoni: ċavetta fittizja hija biżżejjed

Codex jivvalida li l-varjabbli tal-ambjent imsemmi minn `env_key` jeżisti
**qabel** ma l-ewwel talba titlaq mill-CLI. Jekk l-istanza **lokali** tiegħek ta’ OmniRoute
ma teħtieġx awtentikazzjoni, kwalunkwe valur fittizju mhux vojt jaħdem:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

Minflok, uża ċavetta vera meta s-server OmniRoute tiegħek ikun protett jew remot.

> **Għażliet komuni tal-host**
>
> | Aċċess         | URL                           |
> | -------------- | ----------------------------- |
> | Network lokali | `http://192.168.0.1:20128/v1` |
> | Tailscale      | `http://100.x.x.x:20128/v1`   |
> | Loopback       | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — għaliex jaħdem mal-mudelli kollha

Codex CLI iddepreka `wire_api = "chat"` (Chat Completions) fi Frar 2026 u issa **jeħtieġ** `wire_api = "responses"` (OpenAI Responses API). L-issettjar ta’ `wire_api = "chat"` jikkawża crash immedjat waqt l-istartjar minn v0.138 ’il quddiem.

Ħafna providers, inklużi GLM u Kimi, għadhom jesponu biss endpoint ta’ Chat Completions. DeepSeek V4 issa jesponi wkoll Responses API nattiva kif ukoll endpoint kompatibbli ma’ Anthropic; OmniRoute juża Responses b’mod awtomatiku u jippermetti lil kull konnessjoni DeepSeek tagħżel il-kompatibbiltà ma’ Anthropic.

**OmniRoute isolvi dan b’mod trasparenti:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute jagħżel il-protokoll nattiv tal-provider u jittraduċi meta jkun meħtieġ
    → POST /responses (DeepSeek V4) jew /chat/completions (Mistral / GLM / Kimi / oħrajn)
```

Meta tuża OmniRoute, qatt ma jkollok bżonn proxy tat-traduzzjoni separat. **Il-mudelli kollha jużaw `wire_api = "responses"`** — OmniRoute jieħu ħsieb il-bqija.

> **`wire_api` huwa l-valur awtomatiku** — il-field għandu valur awtomatiku ta’ `"responses"` u jista’ jitħalla barra għalkollox minn `config.toml`. Issettjah b’mod espliċitu biss jekk tkun qed tiddokumenta l-intenzjoni.

## Tieqa tal-kuntest u kompattazzjoni

### Oqsma tal-konfigurazzjoni tat-tokens

| Qasam                            | Deskrizzjoni                                                                                                                                                                                                                   |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `model_context_window`           | Il-baġit totali ta’ tokens għall-mudell attiv. Issettjah għal-limitu ddikjarat tal-mudell.                                                                                                                                     |
| `model_auto_compact_token_limit` | Il-limitu li jattiva l-kompattazzjoni awtomatika tal-istorja. **Massimu: 90% ta’ `model_context_window`** — valuri ogħla minn 90% jiġu injorati mingħajr avviż.                                                                |
| `tool_output_token_limit`        | Limitu massimu fuq it-tokens maħżuna fl-istorja għal kull output ta’ sejħa ta’ għodda. Dan jipprevjeni li rispons wieħed kbir ta’ għodda jimla t-tieqa. **Dan mhuwiex l-output massimu** — huwa limitu għall-ħażna fl-istorja. |
| `compact_prompt`                 | Sostituzzjoni inline għall-prompt tas-sistema użat waqt il-kompattazzjoni (v0.138+).                                                                                                                                           |

> **Nota dwar `model_max_output_tokens`**: Dan il-qasam **mhuwiex parti mill-iskema tal-konfigurazzjoni ta’ Codex CLI** (huwa nieqes mill-codebase ta’ Codex Rust). Jiġi injorat mingħajr avviż jekk jiġi ssettjat. Tiddependix fuqu — uża `tool_output_token_limit` biex tikkontrolla kemm output tal-għodod jinħażen fl-istorja.

## Sforz ta' Raġunament

Jikkontrolla kemm il-mudell "jaħseb" qabel iwieġeb.

| Valur    | Użah għal                                            |
| -------- | ---------------------------------------------------- |
| `none`   | Ebda raġunament — tweġiba diretta                    |
| `low`    | Kompiti trivjali (tibdil tal-isem, ifformattjar)     |
| `medium` | **Valur predefinit tas-server** meta mhux speċifikat |
| `high`   | Kompiti intermedji (refactoring, debug)              |
| `xhigh`  | Arkitettura, analiżi profonda, problemi kumplessi    |

```bash
# Sostituzzjoni għal kull invokazzjoni
codex -c model_reasoning_effort=low "rename variable x to count"
codex -c model_reasoning_effort=xhigh "design the auth module"
```

Issettja wkoll **sommarju** tar-raġunament sabiex Desktop ikun jista' jirrendi t-test tal-ħsieb (mhux biss blobs kriptati):

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # jew ultra meta jkun appoġġjat
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### Baġit tal-Ħsieb ta' OmniRoute (issettjar tas-server)

Fuq il-host ta' OmniRoute, **Settings → AI → Thinking Budget** irid ikun **`passthrough`** sabiex l-isforz/is-sommarju ta' Codex jasal għand il-fornitur upstream. Il-modalità **`auto` tneħħi** l-fields `reasoning` / `reasoning_effort` kollha tal-klijent u tħalli l-panels tal-ħsieb vojta anke meta Codex ikun ikkonfigurat sew.

Gwida sħiħa: [THINKING_BUDGET.md](./THINKING_BUDGET.md).

Il-kompressjoni u l-cache tal-prompt huma indipendenti u jibqgħu jaħdmu taħt `passthrough`.

## Profili — konfigurazzjonijiet bl-isem għal kull mudell/fluss tax-xogħol

Il-profili jippermettulek taqleb il-mudell + it-tieqa tal-kuntest b'flag wieħed. Kull profil huwa fajl ċatt
`~/.codex/<name>.config.toml` li jitqiegħed fuq il-`config.toml` bażi.

> **Regola tal-għoti tal-ismijiet (Codex CLI v0.137+):** il-fajl irid ikun `~/.codex/<name>.config.toml` — **mingħajr il-prefiss `profile-`**.
> Is-CLI jirriżolvi `-p kimi-k27` → `~/.codex/kimi-k27.config.toml`. Jekk il-fajl ma jinstabx, il-valur predefinit jiġi applikat mingħajr twissija.

```bash
codex --profile kimi-k27 "analyze 10k lines of this codebase"
codex -p glm52 "architecture review"
codex --profile deepseek-flash "rename variable"   # veloċi, irħis
```

### Profili tal-isforz (l-istess mudell, sforz differenti)

codex -p low      # cx/gpt-5.5, sforz=low

codex -p chat     # cx/gpt-5.5, ebda sforz issettjat (valur predefinit tas-server)

## Ġenerazzjoni awtomatika ta' profili b'`omniroute setup-codex`

Jekk tħaddem OmniRoute fuq VPS, tista' tiġġenera awtomatikament fajls tal-profili mill-katalgu tal-mudelli attiv:

```bash
# Minn VPS (juża OmniRoute lokali fuq il-port 20128)
omniroute setup-codex

# Minn kwalunkwe magna — ipponta lejn il-VPS tiegħek
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# Ara previżjoni mingħajr ma tikteb fajls
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# Iġġenera biss il-profili GLM u Kimi
omniroute setup-codex --only glm,kimi

# Ikteb f'direttorju personalizzat
omniroute setup-codex --codex-home /path/to/.codex
```

Il-kmand iġib `/v1/models`, juża profili rfinuti għal mudelli magħrufa, jirrikorri għall-metadata tal-katalgu għal mudelli oħra tat-test kompatibbli, u jikteb `~/.codex/<name>.config.toml` għal kull wieħed. Huwa idempotenti — tista' terġa' tħaddmu mingħajr periklu.

OmniRoute jista' wkoll **jissinkronizza awtomatikament** dawn l-istess fajls tal-profili wara li sejba/importazzjoni b'suċċess tal-mudelli ta' fornitur tibdel il-katalgu attiv. Din il-karatteristika trid **tiġi attivata espliċitament u hija mitfija b'mod awtomatiku**: aqleb l-għażla mid-**dashboard CLI Code** ("CLI profile auto-sync" → Codex), jew issettja `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` (jirrispetta wkoll `CLI_ALLOW_CONFIG_WRITES`, li huwa mixgħul b'mod awtomatiku). Meta tkun attivata, tikteb biss fajls separati tal-profili `~/.codex/*.config.toml`; qatt ma tibdel il-`~/.codex/config.toml` attiv/predefinit, is-settings ta' Codex-lb, l-awtentikazzjoni, jew l-għażla tal-fornitur.

## Kompiti li jdumu għaddejjin

Żewġ valuri predefiniti ta’ OmniRoute jistgħu fis-skiet ifixklu sessjonijiet ta’ Codex CLI li jdumu diversi sigħat. L-ebda wieħed minnhom mhu setting ta’ Codex CLI — it-tnejn jinsabu fuq in-naħa ta’ OmniRoute. Utenti li jemigraw konfigurazzjoni minn proxies upstream li jorbtu l-kontijiet u jiddiżattivaw il-limiti ta’ inattività spiss jiltaqgħu mat-tnejn u jikkonkludu li OmniRoute “ma jistax iżomm sessjoni twila.”

| Sintomu                                                                                                | Kawża probabbli                                                                    | Kontroll                 |
| ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------- | ------------------------ |
| Is-sessjoni tibqa’ taqleb il-kontijiet / il-kontinwità tal-cache tal-prompt tintilef bejn dawra u oħra | It-TTL tal-affinità tas-sessjoni huwa `0` (diżattivat)                             | `sessionAffinityTtlMs`   |
| Il-konnessjoni tieqaf waqt ir-raġunament mingħajr prompt viżibbli għall-klijent                        | Il-watchdog tal-inattività tal-fluss attiva wara 10 minuti mingħajr chunk upstream | `STREAM_IDLE_TIMEOUT_MS` |

Diskussjonijiet relatati: [#7126](https://github.com/diegosouzapw/OmniRoute/discussions/7126) (kompiti twal li jieqfu), [#5718](https://github.com/diegosouzapw/OmniRoute/discussions/5718) (għaliex l-affinità hija diżattivata b’mod predefinit). Traċċar: [#7287](https://github.com/diegosouzapw/OmniRoute/issues/7287).

### 1. Affinità tas-sessjoni — orbot konverżazzjoni waħda ma’ kont wieħed

**Valur predefinit:** `sessionAffinityTtlMs = 0` (diżattivat).

**Fejn għandek tissettjah**

- Dashboard → **Settings → Routing** → **Session affinity** → **Affinity TTL (seconds)** (`ComboDefaultsTab`)
- Jew ibgħat PATCH lis-settings b’`sessionAffinityTtlMs` f’**millisekondi** (medda ta’ Zod `0`–`86_400_000`, jiġifieri sa 24 siegħa)

> Ingħata isem ġdid f’#7274 minn `codexSessionAffinityTtlMs`, li kien għal Codex biss. Il-key antika għadha aċċettata bħala alias li jinqara biss; konfigurazzjonijiet ġodda għandhom jużaw `sessionAffinityTtlMs`. L-affinità issa tapplika għal **kwalunkwe** provider ladarba t-TTL ikun ogħla minn `0`, mhux għal Codex biss — ara [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → Affinità tas-sessjoni.

**X’jieqaf jaħdem meta jibqa’ f’0**

Kull dawra ta’ konverżazzjoni Codex b’diversi dawriet tiġi diretta b’mod indipendenti mill-istrateġija combo attiva u tista’ tasal f’**kont differenti għal kull dawra**. Dan jikser il-kontinwità tas-sessjoni / tal-cache tal-prompt upstream. OmniRoute jikkonsulta biss il-headers tas-sessjoni ta’ Codex (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) u oqsma tal-body bħal `prompt_cache_key` / `session_id` meta t-TTL ikun akbar minn `0` (`extractSessionAffinityKey` f’`src/sse/services/auth.ts`).

**Rakkomandat għal kompitu wieħed li jdum diversi sigħat**

Issettja t-TTL **ogħla mit-tul mistenni tal-kompitu skont il-ħin reali** (il-massimu tal-UI huwa **86400 sekonda** = 24 siegħa):

| Tul mistenni tal-kompitu | TTL tal-affinità (UI, sekondi) | `sessionAffinityTtlMs` |
| ------------------------ | ------------------------------ | ---------------------- |
| Ftit sigħat              | `14400` (4s)                   | `14400000`             |
| Matul il-lejl / ~12s     | `43200` (12s)                  | `43200000`             |
| Ġurnata sħiħa            | `86400` (24s, massimu)         | `86400000`             |

L-għażla volontarja hija intenzjonata: id-diżattivazzjoni tal-affinità tiffavorixxi l-ibbilanċjar tat-tagħbija bejn il-kontijiet; l-attivazzjoni tagħha tiffavorixxi l-kontinwità għal sessjoni twila waħda ta’ aġent. Din il-gwida **ma** tibdilx il-valur predefinit — l-operaturi li jħaddmu kompiti twal ta’ Codex iridu jagħżlu li jattivawha.

### 2. Timeout tal-inattività tal-fluss — twaqqafx dawriet ta’ raġunament kwieti

**Valur predefinit:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 minuti). Meta ma jkunx issettjat, jiret minn `REQUEST_TIMEOUT_MS`; il-linja bażi kondiviża hija wkoll 600000. Ara [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → Timeouts.

**X’jieqaf jaħdem bil-valur predefinit**

Turn ta’ raġunament / għodda ta’ Codex li jibqa’ sieket għal aktar minn 10 minuti **mingħajr ebda blokka reali upstream** jingħalaq bil-forza mill-għassies tal-inattività SSE (`open-sse/utils/stream.ts`). Il-klijent spiss jara biss qtugħ tal-konnessjoni — li jaqbel ma’ “waqaf awtomatikament mingħajr ebda notifika.”

Dettall kritiku: Il-**heartbeat** SSE sintetiku ta’ OmniRoute ma jirrisettjax l-arloġġ tal-inattività. Blokka reali biss mill-body upstream taġġorna `lastChunkTime`. Mudell sieket li għadu qed “jaħseb” jidher identiku għal upstream imwaħħal mill-perspettiva tal-għassies.

Inattività relatata tal-body ta’ Undici: `FETCH_BODY_TIMEOUT_MS` (b’mod awtomatiku juża wkoll l-istess bażi ta’ 10 minuti; `0` jiddiżattivah). Għall-istreaming, `FETCH_TIMEOUT_MS` ikopri biss l-istabbiliment tal-konnessjoni / l-ewwel headers — ladarba l-istream ikun attiv, il-waqfiet jiġu rregolati minn `STREAM_IDLE_TIMEOUT_MS` u `FETCH_BODY_TIMEOUT_MS`.

**Rakkomandat għal kompitu wieħed ta’ diversi sigħat**

Fl-ambjent tal-proċess ta’ OmniRoute (`.env` / compose / systemd):

```bash
# Iddiżattiva l-limiti tal-inattività tal-istream u tal-body għal turns twal ta’ raġunament
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

Jew għollihom għal aktar mill-itwal intervall ta’ silenzju li tistenna (il-valuri huma f’millisekondi):

```bash
# Eżempju: ippermetti sa sagħtejn ta’ silenzju bejn blokok upstream
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

Erġa’ ibda OmniRoute wara li tibdel dawn il-varjabbli tal-ambjent.

### Riċetta konkreta — kompitu Codex ta’ diversi sigħat

1. **Waħħal il-kont:** Dashboard → Settings → Routing → Session affinity → Affinity TTL = `43200` (12h) jew `86400` (massimu ta’ 24h).
2. **Għolli / iddiżattiva l-limiti tal-inattività** fl-ambjent ta’ OmniRoute:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. Żomm il-`config.toml` tas-soltu ta’ Codex (`wire_api = "responses"`, `base_url` korrett, `OMNIROUTE_API_KEY`) — ma jeżistux settings min-naħa ta’ Codex għall-affinità/inattività għal dawn iż-żewġ imġibiet.
4. Erġa’ ibda OmniRoute, imbagħad ibda l-kompitu twil ta’ Codex.

### Deċiżjoni dwar il-valuri awtomatiċi (#7287)

| Setting                  | Valur awtomatiku distribwit | Jinbidel f’din il-gwida?                                                                                              |
| ------------------------ | --------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (mitfi)                 | **Le** — jibqa’ fakultattiv (ibbilanċjar tat-tagħbija kontra kontinwità; ara Discussion #5718)                        |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 min)           | **Le** — jibqa’ 10 minuti għat-traffiku ġenerali; l-operaturi ta’ Codex għal kompiti twal jgħolluh jew jiddiżattivawh |

Il-bidla ta’ kwalunkwe wieħed minn dawn il-valuri awtomatiċi globalment tibdel l-imġiba għal kull klijent ta’ istanza, mhux għal Codex biss. Iddokumenta s-settings; ħalli l-valuri awtomatiċi kif inhuma sakemm deċiżjoni espliċita tal-operatur ma tgħidx mod ieħor.

### Dijanjosi ta’ qtugħ minħabba inattività

Meta jiskatta l-għassies tal-inattività, OmniRoute jirreġistra linja b’din il-forma:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

Fittex b’grep għal `Idle timeout: no data from` (jew il-kodiċi `stream_idle_timeout` / l-isem tal-iżball `StreamIdleTimeoutError`). Is-segment tal-fornitur ikun dak li OmniRoute uża għal dik it-talba (`codex`, id ta’ fornitur ieħor, jew `provider` jekk mhux magħruf) — mhux dejjem ikun litteralment is-string `codex`.

## Soluzzjoni tal-Problemi

**`Error: wire_api = "chat" is no longer supported`**
Neħħi `wire_api = "chat"` mill-konfigurazzjoni tiegħek. Issettja `wire_api = "responses"` jew ħalli barra dan il-field (minn v0.138, il-valur default huwa `"responses"`).

**`Error: model not found`**
Ivverifika li l-mudell jeżisti f’OmniRoute bil-prefiss korrett. Uża `omniroute models list` jew iftaħ `/dashboard/providers/<provider>`.

**`Authentication error`**
Ikkonferma li `OMNIROUTE_API_KEY` hija esportata: `echo $OMNIROUTE_API_KEY`.

**`ERROR: Missing environment variable: OMNIROUTE_API_KEY`**
Codex jivvalida li l-varjabbli tal-ambjent teżisti qabel ma jagħmel l-ewwel talba. Esporta
ċavetta reali għal servers protetti, jew placeholder mhux vojt bħal
`OMNIROUTE_API_KEY=local` meta l-istanza **lokali** tiegħek ta’ OmniRoute ma
teħtieġx awtentikazzjoni. Erġa’ ibda s-shell jekk żidtha ma’ `~/.bashrc` jew `~/.zshrc`.

**`Connection refused`**
Ivverifika li OmniRoute qed jaħdem u li l-host/port ta’ `base_url` huwa korrett għan-network tiegħek (lokali vs Tailscale vs VPS).

**Is-sessjoni tiġġarraf qrib il-limitu tal-kuntest**
Issettja `model_context_window` u `model_auto_compact_token_limit` b’mod espliċitu. Ara t-tabella tat-tieqa tal-kuntest hawn fuq.

**Il-kompattazzjoni tibda tard wisq**
Naqqas `model_auto_compact_token_limit` għal 80–85% tat-tieqa. Qatt tissettjah ’il fuq minn 90%.

**Il-profil ma jitgħabbiex (`-p <name>` jiġi injorat mingħajr avviż)**
Ikkonferma li l-file jeżisti f’`~/.codex/<name>.config.toml` (mingħajr il-prefiss `profile-`). Ħaddem `ls ~/.codex/*.config.toml`.

**Task twil ta’ Codex jieqaf f’nofs l-eżekuzzjoni / jaqleb bejn il-kontijiet bejn turn u ieħor**
Ara [Tasks li jdumu għaddejjin](#long-running-tasks). Attiva l-affinità tas-sessjoni (b’TTL itwal mit-tul tat-task) u żid jew iddiżattiva `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS`. Fittex fil-logs ta’ OmniRoute għal `Idle timeout: no data from`.
