> **Notă privind domeniul de aplicare:** `socket.yml` configurează scanarea post-publicare, la nivelul registrului, efectuată de Socket.dev asupra artefactului npm (căi ignorate pentru conținut care nu este distribuit, precum `tests/`, `docs/` și rapoarte de compilare). Acesta nu configurează un mecanism de blocare a integrării CI/PR — niciun flux de lucru din `.github/workflows`, niciun script din `package.json` și nicio țintă din `Makefile` nu invocă Socket.dev.

Acest document reprezintă atestarea redactată de persoana responsabilă cu mentenanța pentru cele șase
constatări `AI-detected potential malware` semnalate pentru `omniroute@3.8.5` și
măsurile de remediere aplicate în `omniroute@3.8.6`. Scopurile sale sunt:

1. Operatorii fluxurilor de securitate să dispună de o singură referință pe care să o citeze atunci când trebuie
   să evalueze constatările în raport cu sursa efectivă.
2. Viitoarele scanere AI să poată identifica declarația semnată de persoana responsabilă cu mentenanța conform căreia fiecare
   cale semnalată este intenționată, opțională și documentată.
3. Să avem o evidență scrisă a motivului pentru care fiecare punct de apel este structurat în modul respectiv —
   astfel încât o refactorizare viitoare să nu reintroducă accidental o amprentă care
   a fost eliminată în mod deliberat.

Dacă administrați un scaner care semnalează din nou oricare dintre punctele de apel de mai jos după ce
măsurile de remediere din v3.8.6 au fost publicate, vă rugăm să deschideți o problemă cu trasarea scanării, iar
noi vom extinde aici atestarea.

## §1 — Instalarea CA-ului rădăcină MITM (`77484.js`)

**Fișiere sursă**:

- `src/mitm/cert/install.ts` — funcțiile publice `installCert()` / `uninstallCert()`,
  precum și `installCertWindows/Mac/Linux`, specifice fiecărei platforme.
- `src/mitm/systemCommands.ts` — funcțiile auxiliare comune `execFile` / `spawn` / PowerShell
  utilizate de căile de instalare.

**Declanșator**: utilizatorul face clic pe „Enable MITM proxy” în panoul de control local de la
`/dashboard/cli-tools/mitm`. Ruta este accesibilă numai prin interfața loopback — consultați regula strictă #17 din
`CLAUDE.md` și `src/server/authz/routeGuard.ts::isLocalOnlyPath()`. Un JWT divulgat
expus printr-un tunel **nu poate** declanșa această cale de cod.

**Operațiuni privilegiate efectuate (pentru fiecare platformă)**:

| SO                     | Comandă/Comenzi                                                                                                   |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | `certutil -addstore Root <cert>` prin UAC                                                                         |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | actualizarea bazei de date NSS pentru fiecare profil prin `certutil -d sql:<profile>`                             |

Acestea sunt aceleași comenzi utilizate de `mitmproxy`, Charles Proxy, Fiddler și
Caddy. Faptul că acestea există în OmniRoute este documentat la
`docs/security/STEALTH_GUIDE.md`.

**Măsuri de atenuare în v3.8.6**:

- `runElevatedPowerShell()` nu mai utilizează `-EncodedCommand <base64utf16le>`.
  Sarcina utilă cu privilegii ridicate este scrisă într-un fișier temporar `.ps1` pentru fiecare apel (modul 0o600,
  într-un director privat `mkdtempSync`) și este indicată prin `-File`. Fișierul
  este șters în `finally`. Această modificare elimină amprenta clasică
  de escaladare prin PowerShell folosind base64, semnalată de clasificatorul AI al
  Socket.dev.
- `installCertWindows` conține un bloc inline `SECURITY-AUDITOR-NOTE:`
  care face trimitere aici.

**De ce îl păstrăm**: proxy-ul MITM este o funcționalitate documentată, utilizată de
`docs/security/STEALTH_GUIDE.md` și `docs/frameworks/MITM-PROXY.md`. Eliminarea
acestuia ar afecta setul de funcționalități agent-bridge.

## §2 — Importarea credențialelor Zed (`app/api/providers/zed/import/route.js`)

**Fișiere sursă**:

- `src/app/api/providers/zed/discover/route.ts` _(nou în v3.8.6)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(nou în v3.8.6)_

**Declanșare**: utilizatorul face clic pe „Import from Zed” în pagina locală
Providers a tabloului de bord. Accesul la endpoint este restricționat prin
`requireManagementAuth`. Editorul Zed însuși își scrie cheile API ale
furnizorilor în keychain-ul sistemului de operare, folosind numele de servicii
documentate — consultați https://zed.dev/docs/ai/llm-providers.

**Comportamentul din v3.8.5 (cel semnalat de Socket.dev)**:

`POST /import` descoperea credențialele și le salva automat în baza de date
SQLite locală, într-un singur schimb de mesaje. Fără confirmare pentru fiecare
cont, fără amprentă, doar „au fost găsite N tokenuri și toate au fost importate”.

**Măsura de remediere din v3.8.6 — confirmare în 2 pași**:

1. **`POST /api/providers/zed/discover`** returnează
   `{ candidates: [{ provider, service, account, fingerprint }] }`. Tokenul brut
   nu este transmis **niciodată**. Amprenta este
   `sha256(service|account|token).slice(0,16)`.
2. Tabloul de bord afișează lista de candidați, operatorul îi selectează pe cei
   care trebuie importați și trimite `{ confirmedAccounts: [{ service, account, fingerprint }] }`
   către **`POST /api/providers/zed/import`**.
3. Endpointul de import **recitește keychain-ul pe server** și filtrează după
   `(service, account, fingerprint)`. Un răspuns de descoperire modificat sau
   reluat nu poate determina endpointul de import să salveze un token fără
   legătură — dacă tokenul activ s-a schimbat după descoperire, amprenta nu mai
   corespunde, iar credențialul este omis.

Un flag de mediu `OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` păstrează
comportamentul din v3.8.5 pentru operatorii care nu și-au actualizat încă
automatizările. Acesta va fi eliminat în v3.9.

**De ce îl păstrăm**: importul din Zed este cea mai accesibilă metodă de
inițializare pentru utilizatorii care folosesc deja Zed și doresc să-și copieze
cheile furnizorilor în OmniRoute fără să le lipească din nou.

## §3 — `execFile` / `spawn` / PowerShell cu privilegii ridicate (`21843.js`)

**Fișiere sursă**: `src/mitm/systemCommands.ts`.

**De ce a fost semnalat**: fragmentul reexportă `execFileWithPassword`,
`runElevatedPowerShell` și funcția auxiliară comună `quotePowerShell`.
Clasificatorul AI al Socket.dev le interpretează ca pe un set generic de
instrumente pentru „execuție pe sistemul gazdă + escaladarea privilegiilor”.
În OmniRoute, acestea sunt utilizate numai de fluxul de instalare a
certificatului MITM (§1) și de `execFileWithPassword` pentru executarea
comenzilor `sudo`.

**Măsura de remediere din v3.8.6**:

- Refactorizarea `runElevatedPowerShell` (consultați §1).
- Un bloc `SECURITY-AUDITOR-NOTE:` inclus direct atât la
  `runElevatedPowerShell`, cât și la `execFileWithPassword` documentează
  apelanții permiși și lista fixă de executabile.
- Apelul `spawn()` din `execFileWithPassword` conține un marcaj `nosemgrep`
  cu lista executabilelor pe care funcția auxiliară le poate primi — **nu
  există nicio cale de la datele introduse de utilizator către
  `finalCommand`/`finalArgs`**.

## §4 / §6 — Supervizorul serviciului 9router (`api/services/9router/{start,restart}/route.js`)

**Fișiere sursă**:

- `src/app/api/services/9router/_lib.ts` — fabrica supervizorului.
- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`.
- `src/lib/services/ServiceSupervisor.ts` — mecanism generic pentru spawn / interogarea stării de funcționare / memorarea temporară a jurnalelor.

**Declanșare**: utilizatorul face clic pe „Install” / „Start” în pagina
serviciilor încorporate din tabloul de bord local.

**Protecții deja implementate**:

- Toate rutele `/api/services/*` sunt LOCAL_ONLY conform
  `src/server/authz/routeGuard.ts` (regula strictă nr. 17). Restricționarea la
  interfața loopback are loc înaintea oricărei verificări de autentificare —
  un JWT compromis nu le poate accesa.
- Rândul 9router din baza de date este inițializat cu
  `status='not_installed', auto_start=0` (consultați
  `src/lib/db/migrations/071_services.sql:19`). Serviciul **nu** pornește la
  prima lansare.
- `spawn()` este apelat cu calea binarului returnată de
  `resolveSpawnArgs(apiKey, PORT)` din `src/lib/services/installers/ninerouter.ts`,
  care reprezintă o listă fixă de binare acceptate.
- Stdout/stderr este memorat temporar în memorie (limită de 5 MB, consultați
  `_lib.ts`) — nu se scrie nimic pe disc decât dacă utilizatorul activează
  jurnalizarea din tabloul de bord.

**Măsura de remediere din v3.8.6**: nicio modificare funcțională. Profilul
minimal de compilare (`OMNIROUTE_BUILD_PROFILE=minimal`) înlocuiește
`src/lib/services/installers/ninerouter.ts` cu un stub pentru utilizatorii care
doresc eliminarea fizică a căilor privilegiate din pachet.

**De ce îl păstrăm**: 9router este un serviciu companion opțional, care poate
fi instalat local (similar unui plugin WordPress) — activarea este strict
opțională.

## §5 — Rescrierea credențialelor OmniRoute Cloud Sync (`api/keys/[id]/route.js`)

**Fișiere sursă**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`.
- `src/app/api/keys/[id]/route.ts` — invocă `syncKeysToCloudIfEnabled()`.

**Declanșator**: `isCloudEnabled()` returnează `true` (setat din panoul de control) **și**
`CLOUD_URL` este configurat. Când ambele sunt dezactivate, nu se efectuează niciun apel de rețea extern către endpointul Cloud.

**Comportamentul din v3.8.5 (eroarea pe care Socket.dev a detectat-o corect)**:

`updateLocalTokens()` suprascria `accessToken`, `refreshToken` și
`providerSpecificData` din răspunsul Cloud atunci când
`cloudUpdatedAt > localUpdatedAt`. Fără HMAC, fără semnătură, fără sumă de control. Un
`CLOUD_URL` configurat greșit sau ostil (ori un atac MITM asupra canalului) putea înlocui
în mod silențios tokenurile OAuth ale furnizorului.

**Măsuri de remediere în v3.8.6**:

1. **Verificare HMAC**: `verifyCloudSignature(rawBody, sigHeader)` verifică
   antetul `X-Cloud-Sig` (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`) înainte de a analiza JSON-ul. Dacă secretul este setat, semnătura este
   obligatorie. În caz contrar (modul vechi), se înregistrează un avertisment, iar răspunsul este
   acceptat — secretul va fi obligatoriu în v3.9.
2. **Activarea explicită a câmpurilor secrete**: `accessToken` / `refreshToken` /
   `providerSpecificData` sunt suprascrise **doar** când
   `OMNIROUTE_CLOUD_SYNC_SECRETS=true`. Modul implicit sincronizează doar
   metadatele care nu conțin credențiale (`expiresAt`, `status`, `lastError*`,
   `rateLimitedUntil`, `updatedAt`). Aceasta este o **schimbare incompatibilă** pentru utilizatorii
   care se bazau pe sincronizarea la distanță a tokenurilor — aceștia trebuie să o activeze explicit.

**De ce o păstrăm**: Cloud Sync este singura modalitate prin care un tenant OmniRoute Cloud
poate centraliza credențialele echipei. Remedierea face ca modelul de amenințări să fie onest:
„serverul semnează, clientul verifică, operatorul activează explicit”.

## Profil de compilare: `minimal`

Pentru utilizatorii care au nevoie de un artefact compatibil cu Socket, compilați folosind:

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

`NormalModuleReplacementPlugin` din webpack creează aliasuri pentru patru module către implementări stub:

| Modul                                       | Stub                                             |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

Fiecare stub exportă aceeași interfață, dar fiecare funcție aruncă o eroare
`featureDisabledError(name)` în timpul execuției. Rutele care depind de modulul dezactivat
returnează HTTP 503 cu un mesaj clar, în loc să activeze
calea de cod sensibilă.

Pachetul rezultat este destinat publicării ca `omniroute-secure`. Consultați
`docs/ops/PUBLISHING_SECURE.md` pentru instrucțiunile de publicare.
