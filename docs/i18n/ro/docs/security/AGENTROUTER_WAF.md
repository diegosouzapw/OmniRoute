Gateway-ul upstream `agentrouter` rulează un filtru de conținut bazat pe cuvinte-cheie pentru
`messages[].content`. Filtrul este parțial determinist (blochează întotdeauna
anumite expresii) și parțial probabilistic (sensibil la rafale — devine
mai agresiv după solicitări rapide și revine la normal după o perioadă de pauză).

Când WAF-ul blochează o solicitare, returnează:

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## Domeniul de aplicare al filtrului

WAF-ul inspectează doar `messages[].content`. Acesta **nu** inspectează:

- Promptul `system`
- Blocurile de conținut structurat (`tool_result`, `tool_use`, `thinking`, `image`)
- Câmpurile `description` și `input_schema` ale instrumentelor
- Metadatele solicitării, anteturile sau id-ul modelului

## Tipare blocate întotdeauna (fără diferențiere între majuscule și minuscule)

| Tipar                        | Note                                                          |
| ---------------------------- | ------------------------------------------------------------- |
| Orice variantă `Lorem ipsum` | Întregul vocabular latin lorem este blocat                    |
| `language model` (singur)    | „the language model” și „large language model” sunt acceptate |
| `virtual assistant`          | „AI assistant” este acceptat                                  |
| `I'm here to help`           | Și „here to help” singur este blocat                          |
| `Claude, made by Anthropic`  | Doar expresia completă                                        |

## Tipare blocate aproape întotdeauna

| Tipar                                                      | Note                                                    |
| ---------------------------------------------------------- | ------------------------------------------------------- |
| `placeholder`                                              | Atunci când apare singur (nu ca nume de parametru etc.) |
| `dummy data`                                               | Expresie inițială folosită frecvent pentru fixture-uri  |
| `foo bar baz`                                              | Expresie substitut canonică                             |
| Tokenuri scurte repetate (`AAA BBB CCC`, `test test test`) | Detector pentru supraîncărcarea cu cuvinte-cheie        |

## Comportamentul în condiții de încărcare

După aproximativ 5 solicitări rapide într-un interval scurt, WAF-ul începe să blocheze conținut
care în mod normal ar fi acceptat. Limita revine la normal după aproximativ 5–10 secunde de
inactivitate. Acesta este același limitator de rată asociat adresei IP și cheii care provoacă
erori intermitente `400 content-blocked` atunci când Claude Code sau Codex CLI
efectuează în succesiune rapidă mai multe apeluri de utilizare a instrumentelor / trimitere a mesajelor.

## Atenuări deja aplicate în OmniRoute

1. **`open-sse/services/wafRateLimit.ts`** — mecanism de protecție împotriva rafalelor care impune un
   interval minim de 500 ms între solicitările de ieșire către orice URL
   `agentrouter:*`. Intervalul este mult sub pragul uman de percepție a latenței și împiedică
   activarea WAF-ului în condiții normale de trafic.

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — atunci când un serviciu upstream returnează
   `400 content-blocked`, executorul reîncearcă același URL folosind
   o întârziere exponențială (1,5 s, 3,0 s, maximum 2 încercări). După această întârziere,
   WAF-ul revine de obicei la normal, iar reîncercarea reușește.

3. **`tests/unit/compression/harness.test.ts`** — fixture-ul de test
   `longInput` a fost schimbat din `"lorem ipsum dolor sit amet ".repeat(40)`
   în `"example content for testing purposes ".repeat(40)`, astfel încât, atunci când
   Claude Code citește acest fișier prin instrumentul `Read`, conținutul fișierului
   să nu fie retransmis printr-un bloc `tool_result` și să declanșeze WAF-ul.

## Recomandări pentru prompturi și rezultatele instrumentelor

Dacă o sesiune Claude Code sau Codex CLI întâmpină în mod repetat eroarea
`400 content-blocked`, verificați dacă cel mai recent mesaj al utilizatorului și cel mai
recent rezultat al instrumentului conțin vreunul dintre tiparele de mai sus și reformulați-le. Soluții
alternative frecvente:

- Înlocuiți `Lorem ipsum …` cu `example text …` sau cu acel conținut efectiv
  pe care testul sau fixture-ul încearcă să îl modeleze.
- Înlocuiți `placeholder` (atunci când apare singur) cu `example value`,
  `sample value` sau cu valoarea reală.
- Înlocuiți `language model` cu `large language model` sau `the model`.
- Înlocuiți `dummy data` cu `sample data` sau cu valori inițiale realiste.
- Înlocuiți `I'm here to help` / `here to help` cu o introducere mai specifică
  (de exemplu, „Voi examina fișierul pe care l-ați menționat”).

## Raportarea rezultatelor fals pozitive către serviciul upstream

Filtrul actual este excesiv de agresiv — blochează „Lorem ipsum” în
blocurile `tool_result`, chiar dacă în mod clar operatorul nu a intenționat să
injecteze un prompt. Operatorii care doresc remedierea acestei probleme la sursă ar trebui să
contacteze `agentrouter.org` pentru a raporta rezultatele fals pozitive. Lista de blocare
de mai sus reprezintă rezultatul empiric al testării serviciului upstream la data de 2026-08-03.
