> **Sursă:** `src/lib/{a2a,acp,cloudAgent}/`, `src/app/api/{a2a,acp,cloud}/`, `src/app/api/v1/agents/`
> **Ultima actualizare:** 2026-06-28 — v3.8.40

OmniRoute expune trei interfețe diferite legate de agenți. La prima vedere, acestea par similare, dar rezolvă probleme diferite. Folosiți această pagină pentru a o alege pe cea potrivită.

## Pe scurt

| Interfață                         | Recomandată pentru                                                                                                                                                 | Transport                         | Standard                         |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------- | -------------------------------- |
| **A2A — Agent-la-Agent**          | Colaborare între agenți cu agenți parteneri care utilizează protocolul A2A                                                                                         | JSON-RPC 2.0 prin HTTP            | A2A v0.3 (specificație deschisă) |
| **ACP — Registrul agenților CLI** | Detectarea / înregistrarea / lansarea agenților CLI pentru programare instalați pe dispozitivul utilizatorului (Cursor, Cline, Codex CLI, Claude Code, Aider etc.) | HTTP REST                         | Specific OmniRoute               |
| **Agenți cloud**                  | Trimiterea sarcinilor de programare de lungă durată către servicii cloud externe (Codex Cloud, Devin, Jules, Cursor Cloud)                                         | HTTP REST + sarcini stocate în BD | Specific OmniRoute               |

Cele trei sunt independente — puteți alege orice combinație.

## Arbore decizional

```
Aveți nevoie ca un serviciu cloud să efectueze activități în afara acestui dispozitiv (Codex Cloud / Cursor Cloud / Devin / Jules)?
├─ DA → Agenți cloud (POST /api/v1/agents/tasks)
└─ NU → Continuați
    │
    Aveți un agent partener care utilizează A2A și dorește să colaboreze?
    ├─ DA → A2A (POST /a2a)
    └─ NU → Continuați
        │
        Trebuie să listați / configurați agenții CLI pentru programare instalați local?
        ├─ DA → ACP (GET /api/acp/agents)
        └─ NU → Utilizați direct /v1/chat/completions
```

## 1. A2A — Agent-la-Agent

**Specificație:** [A2A v0.3](https://a2a-protocol.org)
**Endpoint OmniRoute:** `POST /a2a` (JSON-RPC 2.0)
**Fișa agentului:** `GET /.well-known/agent.json`

### Când se utilizează

- Construirea unui sistem multi-agent în care OmniRoute este unul dintre participanți
- Expunerea mecanismelor inteligente de rutare ale OmniRoute (`smart-routing`, `quota-management` etc.) către agenți din framework-uri precum Google ADK sau din rețele generice de agenți
- Încapsularea OmniRoute în spatele unei interfețe standard de descoperire și invocare

### Metode

- `message/send` — trimite un mesaj și primește un răspuns sincron
- `message/stream` — trimite un mesaj și primește evenimente de progres transmise prin SSE
- `tasks/get` — citește sarcina după ID
- `tasks/cancel` — anulează o sarcină în curs de execuție

### Capabilități încorporate (6)

- `smart-routing` — direcționează un prompt prin combinația optimă
- `quota-management` — raportează starea cotei pentru fiecare furnizor
- `provider-discovery` — listează furnizorii instalați și capabilitățile acestora
- `cost-analysis` — estimează costul unei solicitări/conversații
- `health-report` — agregă starea mecanismelor de întrerupere, a perioadelor de așteptare și a blocărilor pentru fiecare furnizor
- `list-capabilities` — enumeră capabilitățile disponibile ale agentului și metadatele acestora

### Detalii aprofundate

Consultați [A2A-SERVER.md](./A2A-SERVER.md) pentru detalii despre transport, structura fișei agentului, configurarea TTL-ului sarcinilor și șablonul pentru adăugarea unor capabilități noi.

## 2. ACP — Registrul agenților CLI

**Endpoint OmniRoute:** `GET /api/acp/agents`
**Sursă:** `src/lib/acp/{index,manager,registry}.ts`

### Ce este

ACP este **inventarul local de agenți CLI** al OmniRoute. Acesta detectează ce CLI-uri pentru programare sunt instalate pe gazdă (Cursor, Cline, Claude Code, Codex CLI, Continue etc.), determină versiunile acestora și le afișează în panoul de control, astfel încât utilizatorul să poată configura fiecare CLI să utilizeze OmniRoute.

Acesta NU este un protocol extern — este un registru intern care alimentează interfața „CLI Tools” și urmărirea amprentelor CLI (consultați [CLI-TOOLS.md](../reference/CLI-TOOLS.md)).

### Ce face

- Verifică gazda pentru a găsi binarele CLI instalate (utilizează `which` / `where`, în funcție de sistemul de operare)
- Citește versiunea fiecărui CLI (apelează `<bin> --version`)
- Acceptă opțional agenți personalizați definiți de utilizator (calea binarului + verificarea versiunii + argumente de pornire)
- Păstrează agenții personalizați în setări
- Returnează lista unificată către panoul de control

### API REST

| Endpoint          | Metodă | Descriere                                                                 | Autentificare |
| ----------------- | ------ | ------------------------------------------------------------------------- | ------------- |
| `/api/acp/agents` | GET    | Listează agenții detectați + personalizați (numărul instalați/total)      | Cheie API     |
| `/api/acp/agents` | POST   | Adaugă/actualizează/elimină un agent personalizat (acțiunea este în corp) | Cheie API     |

Structura corpului pentru POST (`customAgentBodySchema` din `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Cazuri de utilizare

- Pagina „CLI Tools” din panoul de control listează ce este instalat și vă ajută să configurați fiecare instrument să utilizeze OmniRoute
- Agenții personalizați permit utilizatorilor avansați să înregistreze CLI-uri interne/proprietare pe care OmniRoute nu le recunoaște în mod implicit
- Rezultatul detectării alimentează matricea de amprente `cli-tools`

### Când să NU utilizați ACP

- ACP nu _execută_ sarcini. Acesta doar detectează și configurează CLI-uri. Pentru a invoca efectiv un CLI, trebuie să îl lansați personal cu variabilele de mediu furnizate de OmniRoute (`OPENAI_BASE_URL`, `OPENAI_API_KEY` etc.).

## 3. Agenți cloud

**Endpointuri OmniRoute:** `/api/v1/agents/tasks/*` (ciclu de viață) + `/api/cloud/*` (infrastructură)
**Sursă:** `src/lib/cloudAgent/`

### Ce este

O interfață uniformă pentru agenții de programare cloud de la terți. Trimiteți un prompt și adresa URL a unui depozit, iar OmniRoute deleagă sarcina agentului cloud corespunzător, verifică periodic starea și returnează rezultatele.

### Agenți acceptați (4, toți confirmați în `src/lib/cloudAgent/agents/`)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### Ciclul de viață

```
POST /api/v1/agents/tasks
  → BaseAgent.createTask() pentru fiecare clasă de agent
  → serviciul extern începe lucrul
  → este creat un rând pentru sarcină în baza de date (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → sincronizare întârziată a stării de la furnizor
  → returnează starea curentă + planul + jurnalul de activitate
  ↓
POST /api/v1/agents/tasks/[id]   (acțiune: "approve" | "message" | "cancel")
  → transmite către furnizor (sau marchează local drept anulată)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → anulare locală
```

### Autentificare

⚠️ **Toate endpointurile `/api/v1/agents/tasks/*` necesită autentificare de administrare** (commit `588a0333`). Apelanții care utilizează numai un token Bearer primesc 401 începând cu v3.8.0.

### Analiză detaliată

Consultați [CLOUD_AGENT.md](./CLOUD_AGENT.md) pentru contractul `CloudAgentBase`, detaliile specifice fiecărui agent, detaliile schemei și endpointurile infrastructurii pentru acreditări.

## Comparație: A2A vs Cloud Agents

Ambele au „sarcini de lungă durată”, dar la niveluri diferite:

| Aspect                  | A2A                                                                                                                         | Cloud Agents                                                            |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Standard                | Open A2A v0.3                                                                                                               | Specific OmniRoute                                                      |
| Unde rulează procesarea | În OmniRoute (utilizează combinațiile configurate)                                                                          | Extern (servere Codex / Devin / Jules)                                  |
| Durata sarcinii         | TTL implicit de 5 min. (configurabil în `TaskManager`)                                                                      | De la câteva minute la câteva ore                                       |
| Conștient de repository | Nu (transmite doar prompturi)                                                                                               | Da (URL-ul repository-ului + ramura)                                    |
| Caz de utilizare        | Colaborare între agenți, rutare inteligentă ca serviciu                                                                     | Delegarea cererii „implementează funcționalitatea X în repository-ul Y” |
| Autentificare           | `OMNIROUTE_API_KEY` opțională pentru `/a2a`; autentificare de administrare pentru endpointurile REST auxiliare `/api/a2a/*` | Întotdeauna autentificare de administrare                               |

## Exemple de integrare

### Descoperirea capabilităților A2A ale OmniRoute

```bash
curl http://localhost:20128/.well-known/agent.json
```

Returnează fișa agentului cu toate cele 6 abilități, mecanismele de transport și versiunea.

### Apelarea OmniRoute ca agent A2A

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### Listarea agenților CLI instalați prin ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Adăugarea unui agent CLI personalizat

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### Trimiterea unei sarcini către un Cloud Agent

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### Verificarea periodică a stării sarcinii din cloud

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## Ce să utilizați și când

- **Interfață frontend pentru chatbot / copilot** → `/v1/chat/completions` (compatibil OpenAI — nu este un protocol pentru agenți)
- **Colaborare între mai mulți agenți** → A2A
- **Listarea instrumentelor CLI locale în panoul de control** → ACP
- **Delegarea sarcinilor de programare de lungă durată către servicii cloud** → Cloud Agents

```
                ┌─────────────────────┐
                │  Nucleul OmniRoute  │
                └─────────────────────┘
                  ↑       ↑        ↑
        ┌─────────┘       │        └─────────┐
        │                 │                  │
    ┌───────┐        ┌─────────┐       ┌────────────┐
    │  A2A  │        │   ACP   │       │  Agenți    │

    └───────┘        └─────────┘       │ (/v1/agents│
        │                 │            │  /tasks)   │
        ↓                 ↓            └────────────┘

   omologi care      locale pe               ↓
   utilizează A2A    gazdă              Codex Cloud, Cursor,
   v0.3                                  Devin, Jules
```
