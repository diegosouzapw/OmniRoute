> **Sursa canonică:** `src/lib/obsidian/api.ts` (client REST + sincronizare),
> `src/lib/db/obsidian.ts` (persistența tokenului / URL-ului de bază / WebDAV),
> `src/lib/obsidianSync.ts` (sincronizarea seifului prin WebDAV), `open-sse/mcp-server/tools/obsidianTools.ts`
> (22 de instrumente MCP), `src/app/api/settings/obsidian/route.ts` +
> `src/app/api/settings/obsidian/webdav/route.ts` (API-uri pentru configurări). Înregistrarea
> instrumentelor și asocierea domeniilor de acces se află în `open-sse/mcp-server/server.ts`.

## Ce este

OmniRoute se conectează la un seif **Obsidian** ca **sursă de context** — o bază locală
de cunoștințe Markdown pe care agenții o citesc și o modifică prin serverul MCP încorporat.
Integrarea comunică cu pluginul comunitar **Obsidian Local REST API** care rulează în
aplicația desktop, astfel încât agenții pot căuta notițe, citi/scrie/aplica modificări
fișierelor, lista conținutul seifului, lucra cu notițe periodice zilnice/săptămânale,
gestiona etichete, executa comenzi Obsidian și, opțional, coordona o sincronizare
bidirecțională desktop↔mobil a seifului.

Clientul (`src/lib/obsidian/api.ts`) încapsulează Local REST API și oferă:

- **Reîncercări cu backoff** pentru erori tranzitorii `5xx`, **timeout de 30 de secunde** prin `AbortController`.
- **Clasificarea tipizată a erorilor** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- Un **mesaj util „Obsidian nu poate fi accesat”** care evidențiază greșeala frecventă
  privind portul (HTTP pe `27123`, **nu** endpoint-ul MCP de pe `27124`) și forma pentru Tailscale.
- **Codificarea căilor** relative la seif, astfel încât căile notițelor care conțin spații/bare oblice să fie sigure.

## Configurare

Nu există **nicio variabilă de mediu** pentru tokenul Obsidian sau URL-ul de bază — ambele
sunt stocate în tabelul SQLite `key_value` (spațiul de nume `obsidian`) prin
`src/lib/db/obsidian.ts`. Tokenul este **criptat în repaus** (AES-256-GCM, cu
mecanism alternativ de compatibilitate retroactivă pentru text simplu). Configurați din fila
**Surse de context** a panoului de control al endpoint-ului (`ObsidianSourceCard`) sau prin
API-ul REST pentru configurări.

> [!IMPORTANT]
> Pluginul **Obsidian Local REST API** trebuie să fie instalat și să ruleze. Interfața sa
> REST ascultă pe **HTTP `127.0.0.1:27123`** (URL-ul de bază implicit). Portul `27124`
> este un endpoint MCP/HTTPS _separat_ și este respins în mod explicit de ruta pentru configurări.
> Dacă vă conectați de pe alt dispozitiv, utilizați `http://<tailscale-ip>:27123`.

### Chei de configurare (SQLite `key_value`, spațiul de nume `obsidian`)

| Cheie             | Scop                                                           | Criptată |
| ----------------- | -------------------------------------------------------------- | -------- |
| `api_key`         | Token bearer pentru Local REST API                             | da       |
| `base_url`        | URL de bază REST (implicit `http://127.0.0.1:27123`)           | nu       |
| `vault_path`      | Calea absolută către directorul seifului (pentru sincronizare) | nu       |
| `webdav_username` | Nume de utilizator WebDAV generat (sincronizarea seifului)     | nu       |
| `webdav_password` | Parolă WebDAV generată (sincronizarea seifului)                | da       |
| `webdav_enabled`  | Dacă sincronizarea seifului prin WebDAV este activată          | nu       |

### Configurare prin REST

```bash
# Salvați și validați tokenul Local REST API (POST validează printr-o verificare de stare)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Verificați starea conexiunii (returnează connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# Deconectați-vă (șterge tokenul stocat)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Toate metodele necesită autentificare în panoul de control. `POST` respinge orice URL de pe
portul `27124` și validează tokenul apelând endpoint-ul de stare al Local REST API înainte
de a-l persista.

### Sincronizarea seifului prin WebDAV

`src/app/api/settings/obsidian/webdav/route.ts` gestionează o sincronizare opțională a
seifului bazată pe WebDAV (controlată de `src/lib/obsidianSync.ts`). Activarea acesteia
configurează OmniRoute să utilizeze un director local al seifului și generează aleatoriu o
pereche nume de utilizator/parolă WebDAV:

```bash
# Activați sincronizarea WebDAV pentru un director de seif (generează numele de utilizator/parola)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# Obțineți starea sincronizării WebDAV (datele de autentificare sunt returnate numai cât timp este activată)
curl http://localhost:20128/api/settings/obsidian/webdav

# Dezactivați sincronizarea WebDAV (șterge datele de autentificare + fișierul .stignore gestionat)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Sursă de context pentru fiecare cheie API (opțional)

Configurația Obsidian poate avea un domeniu de aplicare **pentru fiecare cheie API** prin
tabelul `api_key_context_sources` (`src/lib/db/apiKeyContextSources.ts`). Când un apel MCP
conține id-ul unei chei API autentificate, `getObsidianConfigForApiKey()` preferă
tokenul/URL-ul de bază/calea seifului proprii acelei chei (`source: "api_key"`), iar în caz
contrar revine la configurația globală (`source: "global"`).

## Instrumente MCP (22)

Definite în `open-sse/mcp-server/tools/obsidianTools.ts`. Tokenul/adresa URL de bază sunt determinate
pentru fiecare apel (mai întâi cheia API, apoi configurația globală). Instrumentele care accesează **serverul de sincronizare**
OmniRoute (cele patru instrumente `obsidian_sync_*`) necesită în plus tokenul de autentificare pentru sincronizare configurat
în setările OmniRoute.

### Instrumente de citire (`read:obsidian`)

| Instrument                   | Descriere                                                                                                                  |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Verifică dacă API-ul REST local este accesibil și autentificat.                                                            |
| `obsidian_search_simple`     | Căutare în textul integral al conținutului notițelor; returnează fragmente cu căile fișierelor.                            |
| `obsidian_search_structured` | Căutare folosind o expresie JSON Logic (filtre and/or/regex/path).                                                         |
| `obsidian_read_note`         | Citește o notiță după calea relativă la seif; opțional, un anumit titlu/bloc/frontmatter.                                  |
| `obsidian_list_vault`        | Listează fișierele și directoarele din seif (arbore de intrări).                                                           |
| `obsidian_get_document_map`  | Obține structura titlurilor notiței sub forma unei mapări titluri → numere de linie.                                       |
| `obsidian_get_note_metadata` | Obține frontmatter-ul, etichetele, linkurile și numărul de caractere/cuvinte fără conținutul integral.                     |
| `obsidian_get_active_file`   | Obține calea și conținutul fișierului activ în prezent în Obsidian.                                                        |
| `obsidian_get_periodic_note` | Obține notița periodică zilnică/săptămânală/lunară pentru o dată (astăzi, dacă este omisă).                                |
| `obsidian_get_tags`          | Listează toate etichetele din seif împreună cu frecvențele lor.                                                            |
| `obsidian_list_commands`     | Listează ID-urile comenzilor Obsidian disponibile (de utilizat cu `obsidian_execute_command`).                             |
| `obsidian_sync_status`       | Starea serverului de sincronizare OmniRoute: rulează, numele seifului, portul, durata de funcționare, ultima sincronizare. |
| `obsidian_sync_conflicts`    | Listează conflictele de sincronizare nerezolvate (cale, calea conflictului, momentul detectării).                          |

### Instrumente de scriere (`write:obsidian`)

| Instrument                       | Descriere                                                                                             |
| -------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Creează sau suprascrie o notiță cu conținutul Markdown furnizat.                                      |
| `obsidian_append_note`           | Adaugă conținut la o notiță; opțional, la un anumit titlu/bloc.                                       |
| `obsidian_patch_note`            | Adaugă la final/început sau înlocuiește cu precizie la nivelul unui titlu, bloc sau câmp frontmatter. |
| `obsidian_delete_note`           | Șterge definitiv o notiță din seif.                                                                   |
| `obsidian_move_note`             | Mută sau redenumește o notiță în cadrul seifului.                                                     |
| `obsidian_execute_command`       | Execută o comandă Obsidian după ID-ul acesteia.                                                       |
| `obsidian_open_file`             | Deschide un fișier în Obsidian (îl creează dacă nu există).                                           |
| `obsidian_sync_trigger`          | Declanșează imediat o sincronizare bidirecțională a seifului desktop↔mobil.                           |
| `obsidian_sync_resolve_conflict` | Rezolvă un conflict de sincronizare: păstrează `local` (mobil), `remote` (desktop) sau `keep-both`.   |

> [!NOTE]
> Țintele `obsidian_patch_note` acceptă un `targetType` de tip `heading | block | frontmatter`
> și o `operation` de tip `append | prepend | replace`, cu un
> `createTargetIfMissing` opțional. Cele patru instrumente `obsidian_sync_*` comunică cu serverul local de sincronizare
> (`http://127.0.0.1:27781` în mod implicit) și necesită tokenul de sincronizare.

### Domenii de acces

Instrumentele de citire necesită `read:obsidian`; instrumentele de scriere necesită `write:obsidian`. Aplicarea regulilor
este identică cu cea din Notion — gestionată de `withScopeEnforcement()` în
`open-sse/mcp-server/server.ts`, condiționată de `OMNIROUTE_MCP_ENFORCE_SCOPES=true`, cu
domeniile de acces permise preluate din `OMNIROUTE_MCP_SCOPES` sau din contextul domeniilor de acces al cheii API. Consultați
[MCP-SERVER.md](./MCP-SERVER.md).

## Endpointuri

| Metodă   | Cale                            | Scop                                                                  |
| -------- | ------------------------------- | --------------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | Returnează `{ connected, hasToken, baseUrl, vaultPath }`.             |
| `POST`   | `/api/settings/obsidian`        | Salvează și validează tokenul (respinge portul `27124`).              |
| `DELETE` | `/api/settings/obsidian`        | Deconectează (șterge tokenul stocat).                                 |
| `GET`    | `/api/settings/obsidian/webdav` | Starea sincronizării WebDAV și acreditările (cât timp este activată). |
| `POST`   | `/api/settings/obsidian/webdav` | Activează sincronizarea WebDAV pentru un director de seif.            |
| `DELETE` | `/api/settings/obsidian/webdav` | Dezactivează sincronizarea WebDAV.                                    |

> Acestea sunt rute pentru setările tabloului de bord. Seiful propriu-zis este accesat prin API-ul
> REST local Obsidian (`base_url` configurat) și prin instrumentele MCP de mai sus — nu există
> niciun endpoint proxy Obsidian public `/v1`.

## Cazuri de utilizare

- **Răspunsuri bazate pe seif** — `obsidian_search_simple` / `obsidian_search_structured`
  urmate de `obsidian_read_note`, astfel încât un agent să răspundă pe baza notițelor tale reale.
- **Crearea notițelor / jurnalizare** — `obsidian_write_note`, `obsidian_append_note` sau
  instrumentul precis `obsidian_patch_note` pentru a înregistra în seif rezultatele agentului, rezumate sau notițe zilnice
  (`obsidian_get_periodic_note`).
- **Navigarea în seif** — `obsidian_list_vault`, `obsidian_get_document_map` și
  `obsidian_get_tags` pentru a explora structura înainte de citire/scriere.
- **Automatizarea Obsidian** — `obsidian_list_commands` + `obsidian_execute_command` pentru a
  controla pluginuri/comenzi prin intermediul unui agent; `obsidian_open_file` pentru a afișa o notiță în interfața cu utilizatorul.
- **Sincronizare mobilă** — activează sincronizarea WebDAV, apoi `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  pentru a coordona sincronizarea desktop↔mobil și a rezolva conflictele.
