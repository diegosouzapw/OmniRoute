> **Pe scurt**: Setați modelul la `auto`, iar OmniRoute alege automat cel mai bun furnizor AI pentru fiecare solicitare. Nu este necesară nicio configurare.

---

## Ce face

În loc să alegeți un anumit model AI (precum GPT-4o sau Claude), puteți permite OmniRoute să **îl aleagă automat pe cel mai bun** pentru fiecare solicitare. Acesta ia în considerare:

- **Starea de funcționare** — Furnizorul funcționează în acest moment?
- **Viteza** — Cât de rapid este?
- **Costul** — Cât costă?
- **Calitatea** — Este potrivit pentru acest tip de sarcină?
- **Capacitatea** — Mai are cotă disponibilă?

OmniRoute evaluează toți furnizorii conectați și îl alege pe cel mai bun. Dacă acesta eșuează, îl încearcă automat pe următorul.

---

## Pornire rapidă

**Pasul 1**: Setați modelul la `auto` în IDE sau CLI:

```
model: "auto"
```

**Pasul 2**: Asta este tot! OmniRoute se ocupă de restul.

**Pasul 3** (opțional): Utilizați o variantă pentru anumite sarcini:

```
model: "auto/coding"    # Cel mai bun pentru cod
model: "auto/fast"      # Cel mai rapid răspuns
model: "auto/cheap"     # Cea mai ieftină opțiune
```

---

## Ce variantă „auto” ar trebui să folosesc?

| Dacă doriți...                   | Folosiți       | Ideal pentru                      | Cum funcționează                                      |
| -------------------------------- | -------------- | --------------------------------- | ----------------------------------------------------- |
| **Cea mai bună per total**       | `auto`         | Întrebări generale, conversații   | Echilibrează viteza, costul și calitatea              |
| **Cel mai bun cod**              | `auto/coding`  | Scrierea codului, depanare        | Alege modele potrivite pentru sarcini de programare   |
| **Cel mai rapid răspuns**        | `auto/fast`    | Răspunsuri rapide, latență redusă | Prioritizează viteza înaintea tuturor celorlalte      |
| **Cea mai ieftină opțiune**      | `auto/cheap`   | Economisirea banilor              | Alege cel mai ieftin furnizor                         |
| **Cel mai inteligent model**     | `auto/smart`   | Sarcini complexe                  | Pune calitatea pe primul loc și explorează modele noi |
| **Cea mai mare disponibilitate** | `auto/offline` | Când furnizorii sunt ocupați      | Alege furnizorii cu cea mai mare capacitate           |

### Exemple

```bash
# Conversație generală — echilibrată
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'

# Generare de cod — calitatea pe primul loc
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/coding","messages":[{"role":"user","content":"Write a Python function"}]}'

# Răspuns rapid — viteza pe primul loc
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/fast","messages":[{"role":"user","content":"What is 2+2?"}]}'
```

## Cum funcționează (versiunea simplă)

Când trimiteți o solicitare cu `model: "auto"`, OmniRoute:

1. **Analizează toți furnizorii conectați** — Fiecare furnizor pe care l-ați adăugat (OpenAI, Anthropic, Google etc.)
2. **Îl evaluează pe fiecare**, luând în calcul, printre altele:
   - Funcționează? (starea de funcționare)
   - Are capacitate disponibilă? (cotă)
   - Cât costă? (preț)
   - Cât de rapid este? (viteză)
   - Este potrivit pentru această sarcină? (calitate)
3. **Îl alege pe cel mai bun** — Furnizorul cu cel mai mare scor primește solicitarea
4. **Se recuperează automat** — Dacă acesta eșuează, OmniRoute îl încearcă automat pe următorul

### Sistemul de evaluare

Fiecare furnizor primește un scor între 0 și 1. Cu cât scorul este mai mare, cu atât furnizorul este mai potrivit.

| Factor               | Pondere | Ce înseamnă                                            |
| -------------------- | ------- | ------------------------------------------------------ |
| Stare de funcționare | 20%     | Furnizorul funcționează? (starea circuit breaker-ului) |
| Cotă                 | 15%     | Mai are capacitate disponibilă?                        |
| Cost                 | 15%     | Cât de scump este? (mai ieftin = scor mai mare)        |
| Viteză               | 12%     | Cât de rapid este? (latență mai mică = scor mai mare)  |
| Potrivire cu sarcina | 8%      | Este potrivit pentru acest tip de sarcină?             |
| Stabilitate          | 5%      | Este consecvent? (rată redusă de erori)                |
| Nivel                | 5%      | Nivelul contului (Ultra > Pro > Free)                  |
| Altele               | 20%     | Afinitatea contextului, densitatea conexiunilor etc.   |

### Cum modifică variantele evaluarea

Fiecare variantă utilizează ponderi diferite:

| Variantă       | Prioritizează          | Ponderi principale              |
| -------------- | ---------------------- | ------------------------------- |
| `auto`         | Echilibrul             | health=20%, quota=15%, cost=15% |
| `auto/coding`  | Calitatea              | taskFit=37%, stability=15%      |
| `auto/fast`    | Viteza                 | latency=32%, health=28%         |
| `auto/cheap`   | Costul                 | cost=37%                        |
| `auto/smart`   | Calitatea + explorarea | taskFit=37%, exploration=10%    |
| `auto/offline` | Capacitatea            | quota=37%, health=28%           |

## Cum gestionează erorile

OmniRoute are **trei niveluri de protecție**:

### 1. Revenire automată

Dacă cel mai bun furnizor eșuează, OmniRoute îl încearcă automat pe următorul. Nu trebuie să faceți nimic.

### 2. Auto-remediere

Dacă un furnizor eșuează în mod repetat:

- **Scor < 0.2** → Exclus timp de 5 minute
- **Disjunctor deschis** → Exclus automat
- **Peste 50% dintre furnizori sunt indisponibili** → Mod de incident (fără explorare)

### 3. Soluție de rezervă pentru situații de urgență

Dacă toți furnizorii eșuează, OmniRoute direcționează solicitările către furnizori gratuiți și stabili (precum Kiro sau Qoder), ca ultimă soluție.

---

## Compatibilitate cu mai multe conturi

Dacă aveți mai multe conturi pentru același furnizor (de exemplu, două chei OpenAI), OmniRoute îl tratează pe fiecare drept un **candidat separat**. Aceasta înseamnă:

- Contul A mai are cotă disponibilă → este utilizat
- Contul B are limita de frecvență atinsă → este omis
- Contul C este mai ieftin → este preferat

Fiecare cont este evaluat independent, în funcție de propria stare de funcționare, cotă și viteză.

---

## Explorare de tip bandit

OmniRoute **explorează** ocazional furnizori noi pentru a descoperi opțiuni mai bune:

- **Implicit**: 5% dintre solicitări sunt direcționate către furnizori aleatorii
- **Auto/smart**: rată de explorare de 10%
- **Dezactivată** când peste 50% dintre furnizori au probleme

Acest lucru ajută OmniRoute să identifice furnizorii care funcționează cel mai bine pentru tiparele dumneavoastră de utilizare.

## Întrebări frecvente

### „Va alege întotdeauna cel mai scump model?”

**Nu.** În mod implicit, costul reprezintă doar 15% din scor. Un furnizor ieftin, rapid și fiabil poate avea un scor mai bun decât unul scump. Folosiți `auto/cheap` dacă doriți să acordați o prioritate și mai mare costului.

### „Ce se întâmplă dacă un furnizor devine indisponibil?”

OmniRoute îl omite automat și îl încearcă pe următorul. Dacă un furnizor eșuează în mod repetat, este exclus temporar (timp de 5-30 de minute). Nu trebuie să faceți nimic.

### „Pot vedea ce furnizor a fost utilizat?”

Verificați anteturile răspunsului — OmniRoute include în fiecare răspuns furnizorul și modelul utilizate.

### „Învață din modul în care îl utilizez?”

Da! Sistemul de evaluare folosește date istorice (latență, rate de eroare, rate de succes) pentru a lua decizii mai bune în timp.

### „Care este diferența dintre `auto` și `auto/smart`?”

- `auto` — Echilibrat, explorare de 5%
- `auto/smart` — Calitatea pe primul loc (aceleași ponderi ca `auto/coding`), explorare de 10%

Folosiți `auto/smart` când doriți cea mai bună calitate și acceptați explorarea ocazională.

### „Pot impune un anumit furnizor?”

Da! Folosiți o combinație cu strategia `priority` în loc de `auto`, apoi trimiteți **numele exact** al combinației în câmpul `model` (de exemplu, `model: "my-combo"` — nu `auto`). Pentru detalii, consultați [Referința tehnică](../routing/AUTO-COMBO.md).

### „Prin ce diferă de metoda round-robin?”

Metoda round-robin parcurge furnizorii pe rând. Auto-combo **evaluează fiecare furnizor** și îl alege pe cel mai bun. Este mai inteligent — ia în considerare starea de funcționare, viteza, costul și calitatea.
