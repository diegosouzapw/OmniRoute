Furnizorii Web Cookie permit OmniRoute să utilizeze un serviciu AI prin sesiunea existentă din browser, în locul unei chei API. Aceștia sunt utili atunci când aveți deja acces la un serviciu prin intermediul site-ului său web și doriți ca OmniRoute să utilizeze aceeași sesiune autentificată.

Spre deosebire de furnizorii cu cheie API, furnizorii Web Cookie se autentifică folosind acreditările pe care browserul le trimite site-ului web.

---

# Înainte de a începe

> **Important:** Copiați întotdeauna acreditările dintr-o **cerere de rețea activă**, **nu** din spațiul de stocare a cookie-urilor al browserului.

Multe probleme de autentificare sunt cauzate de copierea cookie-urilor din locul greșit.

## NU copiați din spațiul de stocare a cookie-urilor

Majoritatea browserelor afișează cookie-urile stocate prin:

```
DevTools
→ Application (sau Storage)
→ Cookies
```

Deși aceste cookie-uri par corecte, ele pot fi:

- expirate
- incomplete
- lipsite de cookie-uri trimise numai în cadrul cererilor autentificate

Utilizarea acestor valori poate cauza erori de autentificare, chiar dacă ele par valide.

## Copiați dintr-o cerere activă

În schimb, utilizați cookie-urile dintr-o cerere efectuată cu succes:

```
DevTools
→ Network
→ Reîmprospătați pagina
→ Deschideți o cerere de chat sau de conversație
→ Request Headers
→ Cookie
```

Antetul de cerere `Cookie` conține informațiile exacte de autentificare pe care browserul le-a utilizat cu succes.

Pentru majoritatea furnizorilor Web Cookie, aceasta este valoarea care trebuie lipită în OmniRoute.

# Configurare generală

Procesul de configurare este același pentru majoritatea furnizorilor Web Cookie.

1. Autentificați-vă pe site-ul web al furnizorului.
2. Deschideți instrumentele pentru dezvoltatori ale browserului.
3. Deschideți fila **Network**.
4. Reîmprospătați pagina.
5. Deschideți o cerere autentificată de chat sau de conversație.
6. Copiați acreditările de autentificare necesare.
7. Deschideți OmniRoute.
8. Accesați **Providers → Add Provider**.
9. Selectați furnizorul Web Cookie.
10. Lipiți acreditările.
11. Faceți clic pe **Test Connection**.
12. Salvați furnizorul.

Acreditările exacte necesare depind de furnizor.

# Ce pot și ce nu pot face furnizorii Web Cookie

Furnizorii Web Cookie reutilizează interfața de chat a unui site web. Aceștia **nu** oferă aceleași capabilități ca API-urile oficiale.

## Funcționalități acceptate

- Autentificarea folosind sesiunea existentă din browser
- Accesarea modelelor disponibile prin contul dumneavoastră
- Redarea în flux a răspunsurilor din chat
- Nu este necesară nicio cheie API

## Funcționalități neacceptate

- Apelarea funcțiilor
- Apelarea instrumentelor
- Editarea automată a fișierelor
- Fluxuri de lucru IDE bazate pe agenți
- Funcționalități disponibile numai prin API

Acesta este comportamentul așteptat și **nu** reprezintă o eroare.

Dacă aveți nevoie de executarea instrumentelor, editarea automată a fișierelor sau alte fluxuri de lucru bazate pe agenți, utilizați un **furnizor cu cheie API** în locul unui furnizor Web Cookie.

---

# Limitarea validării

Un rezultat pozitiv pentru **Test Connection** sau pentru validarea cookie-urilor verifică doar dacă acreditările furnizate par să respecte formatul așteptat.

Până la rezolvarea Issue #7857, validarea reușită **nu garantează** că furnizorul se va autentifica cu succes.

Dacă autentificarea continuă să eșueze, verificați dacă ați copiat acreditările dintr-o cerere de rețea activă, nu din spațiul de stocare a cookie-urilor al browserului.

---

# Depanare

## Autentificarea eșuează

Verificați dacă acreditările au fost copiate din:

```
Network
→ Request Headers
→ Cookie
```

și **nu** din:

```
Application
→ Cookies
```

---

## Cookie-ul funcționează în browser, dar nu și în OmniRoute

Unii furnizori includ cookie-uri care sunt trimise numai în timpul cererilor autentificate.

Copiați din nou acreditările dintr-o cerere de rețea nouă, după deschiderea cu succes a unei conversații.

---

## Sesiunea a expirat

Furnizorii Web Cookie utilizează sesiunea existentă din browser.

Dacă sesiunea din browser expiră sau vă deconectați, trebuie să copiați un nou set de acreditări.

---

## Testarea conexiunii reușește, dar cererile eșuează

Până la rezolvarea Issue #7857, trecerea validării nu garantează că cererea de autentificare va reuși.

Copiați din nou acreditările dintr-o cerere autentificată nouă înainte de a continua depanarea.

# Bune practici

- Copiați acreditările dintr-o cerere autentificată nouă.
- Evitați reutilizarea cookie-urilor vechi.
- Mențineți activă sesiunea din browser în timp ce utilizați furnizori Web Cookie.
- Tratați cookie-urile copiate ca acreditări sensibile.
- Utilizați furnizori cu cheie API atunci când aveți nevoie de apelarea funcțiilor sau de fluxuri de lucru bazate pe agenți.
