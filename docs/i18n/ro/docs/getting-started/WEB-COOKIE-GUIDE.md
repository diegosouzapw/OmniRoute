Furnizorii Web Cookie permit OmniRoute să utilizeze un serviciu AI prin sesiunea existentă din browser, în locul unei chei API. Aceștia sunt utili atunci când aveți deja acces la un serviciu prin site-ul său web și doriți ca OmniRoute să utilizeze aceeași sesiune autentificată.

Spre deosebire de furnizorii care folosesc chei API, furnizorii Web Cookie se autentifică folosind credențialele pe care browserul le trimite către site-ul web.

---

# Înainte de a începe

> **Important:** Copiați întotdeauna credențialele dintr-o **solicitare de rețea activă**, **nu** din spațiul de stocare a cookie-urilor din browser.

Multe probleme de autentificare sunt cauzate de copierea cookie-urilor din locul greșit.

## NU copiați din spațiul de stocare a cookie-urilor

Majoritatea browserelor afișează cookie-urile stocate prin:

```
DevTools
→ Application (sau Storage)
→ Cookies
```

Deși aceste cookie-uri par corecte, ele pot fi:

- învechite
- incomplete
- lipsite de cookie-uri care sunt trimise numai în solicitările autentificate

Utilizarea acestor valori poate cauza erori de autentificare, chiar dacă ele par valide.

## Copiați dintr-o solicitare activă

În schimb, utilizați cookie-urile dintr-o solicitare reușită:

```
DevTools
→ Network
→ Reîmprospătați pagina
→ Deschideți o solicitare de chat sau conversație
→ Request Headers
→ Cookie
```

Antetul de solicitare `Cookie` conține informațiile exacte de autentificare pe care browserul le-a utilizat cu succes.

Pentru majoritatea furnizorilor Web Cookie, aceasta este valoarea care trebuie lipită în OmniRoute.

# Configurare generală

Procesul de configurare este același pentru majoritatea furnizorilor Web Cookie.

1. Conectați-vă la site-ul web al furnizorului.
2. Deschideți instrumentele pentru dezvoltatori ale browserului.
3. Deschideți fila **Network**.
4. Reîmprospătați pagina.
5. Deschideți o solicitare autentificată de chat sau conversație.
6. Copiați credențialele de autentificare necesare.
7. Deschideți OmniRoute.
8. Accesați **Providers → Add Provider**.
9. Selectați furnizorul Web Cookie.
10. Lipiți credențialele.
11. Faceți clic pe **Test Connection**.
12. Salvați furnizorul.

Credențialele exacte necesare depind de furnizor.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) este o platformă gratuită de chat pentru consumatori, care nu necesită înregistrare — sesiunea este creată anonim la prima vizită și persistă prin intermediul a trei module cookie: `uid`, `si_usr_id` și `si_ses_id`. OmniRoute intermediază același endpoint `/api/dispatch` printr-un singur identificator de model (`notrack-c`, alias `ntw`).

### Pași pentru conectare

1. Deschideți [notrack.ai](https://notrack.ai) în browser și permiteți setarea modulului cookie pentru sesiunea anonimă.
2. Deschideți **DevTools → Network**, reîmprospătați pagina și faceți clic pe orice solicitare `/api`.
3. În **Request Headers**, copiați valoarea completă a antetului `Cookie`.
4. În OmniRoute, accesați **Providers → Add Provider → NoTrack Web (Free)**.
5. Lipiți șirul cookie în câmpul `apiKey` și apăsați pe **Save**.

OmniRoute extrage `uid`, `si_usr_id` și `si_ses_id` din șirul lipit și reconstruiește un antet `Cookie` curat, care conține numai acele perechi — plus `nt_session` (tokenul `ntk_…` setat pentru conturile autentificate), atunci când este prezent. Dacă lipsește oricare dintre cele trei valori, șirul brut lipit este redirecționat fără modificări, astfel încât operatorii să poată experimenta cu formate alternative.

### Identificatori de model

| Identificator de model | Nume afișat | Note                                                           |
| ---------------------- | ----------- | -------------------------------------------------------------- |
| `notrack-c`            | NoTrack C   | Implicit — modelul de distribuire din amonte `C`.              |
| `C`                    | NoTrack C   | Alias pentru `notrack-c` (cod brut de distribuire din amonte). |
| `notrack`              | NoTrack C   | Alias pentru `notrack-c`.                                      |
| `ntw`                  | NoTrack C   | Alias scurt pentru `notrack-c`.                                |

Toți cei patru identificatori de model sunt mapați la același model de distribuire din amonte (`C`).

### Opțiuni pentru solicitare

Executorul acceptă următoarele câmpuri opționale în corpul solicitării:

| Câmp din corp         | Valoare implicită | Scop                                                                                                 |
| --------------------- | ----------------- | ---------------------------------------------------------------------------------------------------- |
| `notrack_mode`        | `usual`           | Mod de distribuire (șir în format liber; serviciul din amonte acceptă `usual`, …)                    |
| `notrack_max_turns`   | `6`               | Numărul de interacțiuni interne pe care serviciul din amonte le poate efectua înainte de a răspunde. |
| `notrack_chat_id`     | `null`            | Reia un chat existent din amonte (omiteți pentru un chat nou).                                       |
| `notrack_attachments` | `[]`              | Matrice transmisă direct, conținând descriptorii atașamentelor din amonte.                           |
| `notrack_regenerate`  | `false`           | Setați la `true` pentru a solicita regenerarea răspunsului pentru interacțiunea anterioară.          |

### Capacități

- Completări de chat **cu streaming și fără streaming**.
- **Apelarea instrumentelor** — setați `tools: [...]` în solicitare; executorul le serializează într-un contract de tip plic pentru apelarea instrumentelor și interpretează răspunsurile modelului înapoi în formatul OpenAI `tool_calls`.
- **`response_format`** — sunt acceptate `json_object` și `json_schema`. Executorul extrage primul obiect JSON din răspunsul modelului și îl serializează într-un șir înainte de a-l returna.
- **Indiciu privind raționamentul** — executorul emite un delta `reasoning` atunci când serviciul din amonte trimite un eveniment `thinking`.

### Limitări

- Serviciul din amonte impune cote de utilizare anonimă — când acestea sunt depășite, executorul returnează o eroare 429 cu un mesaj ușor de înțeles.
- Toți identificatorii de model sunt rezolvați la același model de distribuire din amonte; nu există posibilitatea de comutare între modele.
- Executorul nu apelează endpointul `/api/chats` al serviciului din amonte, astfel încât istoricul chatului / sesiunile nu sunt gestionate automat. Utilizați `notrack_chat_id` pentru a relua un chat existent din amonte.

# Ce pot și ce nu pot face furnizorii Web Cookie

Furnizorii Web Cookie reutilizează interfața de chat a unui site web. Aceștia **nu** oferă aceleași capacități ca API-urile oficiale.

## Funcționalități acceptate

- Autentificarea folosind sesiunea existentă din browser
- Accesarea modelelor disponibile prin contul dvs.
- Transmiterea în flux a răspunsurilor conversației
- Nu este necesară nicio cheie API

## Funcționalități neacceptate

- Apelarea funcțiilor
- Apelarea instrumentelor
- Editarea automată a fișierelor
- Fluxurile de lucru de tip agent în IDE
- Funcționalitățile disponibile exclusiv prin API

Acesta este comportamentul așteptat și **nu** reprezintă o eroare.

Dacă aveți nevoie de executarea instrumentelor, editarea automată a fișierelor sau alte fluxuri de lucru de tip agent, utilizați un **furnizor cu cheie API** în locul unui furnizor Web Cookie.

# Avertisment privind validarea

O operațiune **Test Connection** reușită sau validarea cu succes a cookie-urilor confirmă doar faptul că datele de autentificare furnizate par să aibă formatul așteptat.

Până la rezolvarea problemei #7857, o validare reușită **nu garantează** că furnizorul va efectua autentificarea cu succes.

Dacă autentificarea eșuează în continuare, verificați dacă ați copiat datele de autentificare dintr-o solicitare de rețea activă, nu din spațiul de stocare a cookie-urilor din browser.

---

# Depanare

## Autentificarea eșuează

Verificați dacă datele de autentificare au fost copiate din:

```
Rețea
→ Antetele solicitării
→ Cookie
```

și **nu** din:

```
Aplicație
→ Cookie-uri
```

---

## Cookie-ul funcționează în browser, dar nu și în OmniRoute

Unii furnizori includ cookie-uri care sunt trimise numai în timpul solicitărilor autentificate.

Copiați din nou datele de autentificare dintr-o solicitare de rețea nouă, după deschiderea cu succes a unei conversații.

---

## Sesiune expirată

Furnizorii Web Cookie utilizează sesiunea dvs. existentă din browser.

Dacă sesiunea din browser expiră sau vă deconectați, trebuie să copiați un nou set de date de autentificare. Pentru a automatiza reînnoirea cookie-urilor pentru furnizorii web acceptați, consultați instrumentul complementar [Extensia de sincronizare a sesiunii din browser](../guides/SESSION-SYNC-EXTENSION.md).

---

## Testarea conexiunii reușește, dar solicitările eșuează

Până la rezolvarea problemei #7857, trecerea validării nu garantează că solicitarea de autentificare va reuși.

Copiați din nou datele de autentificare dintr-o solicitare autentificată nouă înainte de a continua depanarea.

# Bune practici

- Copiați datele de autentificare dintr-o solicitare autentificată nouă.
- Evitați reutilizarea cookie-urilor vechi.
- Mențineți activă sesiunea din browser în timp ce utilizați furnizori Web Cookie.
- Tratați cookie-urile copiate drept date de autentificare sensibile.
- Utilizați furnizori cu cheie API atunci când aveți nevoie de apelarea funcțiilor sau de fluxuri de lucru de tip agent.
