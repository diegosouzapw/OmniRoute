## Valori de referință

Există mai multe valori pentru acoperire, în funcție de modul în care este calculat raportul. Pentru planificare, doar una dintre ele este utilă.

| Metrică                          | Domeniu de aplicare                                   | Instrucțiuni / Linii | Ramuri | Funcții | Note                                                             |
| -------------------------------- | ----------------------------------------------------- | -------------------: | -----: | ------: | ---------------------------------------------------------------- |
| Moștenită                        | Vechiul `npm run test:coverage`                       |               79.42% | 75.15% |  67.94% | Supraevaluată: numără fișierele de test și exclude `open-sse`    |
| Diagnostică                      | Doar surse, excluzând testele și `open-sse`           |               68.16% | 63.55% |  64.06% | Utilă doar pentru izolarea `src/**`                              |
| Valoare de referință recomandată | Doar surse, excluzând testele și incluzând `open-sse` |               82.58% | 75.22% |  84.23% | Aceasta este valoarea de referință de îmbunătățit pentru proiect |

Valoarea de referință recomandată este cea în raport cu care trebuie efectuată optimizarea.

## Reguli

- Obiectivele de acoperire se aplică fișierelor sursă, nu directoarelor `tests/**`.
- `open-sse/**` face parte din produs și trebuie să rămână în domeniul de aplicare.
- Codul nou nu ar trebui să reducă acoperirea în zonele modificate.
- Se preferă testarea comportamentului și a rezultatelor ramurilor în locul detaliilor de implementare.
- Pentru `src/lib/db/**`, se preferă baze de date SQLite temporare și fixture-uri mici în locul mock-urilor extinse.

## Setul actual de comenzi

- `npm run test:coverage`
  - Verificarea principală a acoperirii surselor pentru suita de teste unitare
  - Generează `text-summary`, `html`, `json-summary` și `lcov`
- `npm run coverage:report`
  - Raport detaliat, fișier cu fișier, din cea mai recentă rulare
- `npm run test:coverage:legacy`
  - Numai pentru comparații istorice

## Politica de creștere incrementală a pragurilor

Actualizați pragurile pentru `npm run test:coverage` numai după ce proiectul depășește efectiv următoarea etapă cu o marjă confortabilă.

**Pragul curent:** `npm run test:coverage` impune **60 instrucțiuni / 60 linii / 60 funcții / 60 ramuri** (metrica a fost recalibrată în Quality-Gates Faza 6A.1 — valoarea de referință anterioară de 82,58% era mărită artificial, deoarece număra fișierele de testare și excludea `open-sse`). Comanda `test:coverage:legacy` păstrează vechea metrică 50/50/50 pentru comparații istorice.

Pentru verificări ad-hoc ale pragurilor pe baza celui mai recent raport, utilizați:

```bash
node scripts/check/test-report-summary.mjs --threshold 75
```

Secvența recomandată de creștere incrementală a pragurilor (ordinea este `instrucțiuni-linii / ramuri / funcții`):

1. 55/60/55
2. 60/62/58
3. 65/64/62
4. 70/66/66
5. 75/70/72 <-- pragul curent (75/70/75)
6. 80/75/78
7. 85/80/84
8. 90/85/88

Următoarea țintă de creștere a pragurilor este `80/75/78`, odată ce acoperirea ramurilor se menține peste 78% în două rulări consecutive.

## Lacună cunoscută

Comanda actuală de acoperire măsoară suita principală de teste unitare Node și include codul sursă atins de aceasta, inclusiv `open-sse`. Aceasta nu combină încă acoperirea Vitest într-un singur raport unificat. Această combinare merită realizată ulterior, dar nu reprezintă un impediment pentru începerea creșterii de la 60% -> 80%.
