## 1. Datele de referință ale serviciului (documentație oficială, verificată încrucișat)

- URL de bază: `https://api.anysearch.com` (REST) + `POST /mcp` (MCP, JSON-RPC 2.0).
- `POST /v1/search` - parametri: `query` (obligatoriu), `max_results` (1-10, implicit 10), `tag` (rutare verticală `{domain}.{sub_domain}`), `zone` (cn/intl), `language`, `params` (câmpuri verticale structurate), `format` (json/markdown).
- `GET /v1/sub-domains?domain=...` - catalog de capabilități, NU se contorizează în cotă.
- `POST /v1/extract` - preia/extrage `{url, title, content}`; corp JSON strict, limită de 16 KiB.
- `POST /v1/auth/email/register` - înregistrare printr-un singur apel, returnează cheia în text clar, valabilă o singură dată, `as_sk_...`.
- Autentificare: `Authorization: Bearer <as_sk_...>` opțional; accesul anonim este limitat per adresă IP și consumă cota zilnică gratuită; o cheie nevalidă returnează 401/403, FĂRĂ revenire silențioasă la accesul anonim.
- Nivel gratuit: 1000 de cereri/zi, 20 QPS per cheie. Nivel cu plată: fără preț stabilit (În curând).
- Anvelopa răspunsului: succes `{code: 0, message: "success", request_id, data}`; eșec `{code: -1, message}`. Erorile de autentificare/cotă nu conțin un `error_code` structurat (textul mesajului este semnalul); erorile specifice extragerii conțin `error_code` (`invalid_extract_url`, `extract_failed`). Niciun antet `Retry-After` pentru 429.

## 3. Decizii (toate luate la 2026-08-26)

1. **Strategia de rutare: `fallbackOnly`.** Justificare: un furnizor gratuit cu cost 0 nu trebuie să domine niciodată rutarea automată în funcție de cost; selecția explicită și revenirea în caz de failover nu sunt afectate. Precedent: intrarea xquik integrată.
2. **Domeniu de aplicare: webSearch + webFetch prin `POST /v1/extract` în v1.** Aliniat cu modelul conceptual de capabilități duale tavily/exa. Suprafețele verticale (`tag`, `sub-domains`, `batch_search`) rămân în afara domeniului de aplicare — în prezent nu există o reprezentare intermediară pentru parametrii verticali.
3. **Afișarea cotei: `freeMonthlyQuota: 0`** (afișare conservatoare în stil xquik). Limita reală (1000 de solicitări/zi, resetare zilnică) este prezentată în schimb în textul `authHint` din catalogul interfeței. Justificare: afișarea cotei trebuie să corespundă semanticii de resetare; transformarea unei limite zilnice într-un echivalent lunar (30000) reprezintă o promisiune falsă pe care interfața nu o poate respecta.
4. **searchTypes: doar `["web"]`.** Nu există dovezi publice privind o secțiune verticală de știri/imagini în API-ul AnySearch; gateway-urile care integrează API-uri fără o secțiune verticală documentată (de exemplu, Google Custom Search) expun doar căutarea web, în loc să mapeze în mod implicit news -> web.
5. **Strategia privind cheia:** funcționarea fără cheie este posibilă; o cheie nevalidă returnează 401/403 și nu este niciodată retrogradată în mod implicit la acces anonim (reflectă contractul serviciului din amonte).
6. **Excluderi deliberate:** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (interceptarea conversațiilor rămâne pe firecrawl/jina/tavily); `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (endpoint-urile anonime de la distanță partajează un singur fond limitat în funcție de IP pentru fiecare adresă IP de ieșire, astfel că extragerea fără cheie este opțională, nu un candidat pentru rutarea automată); `QUOTA_STATUS_PROVIDERS` (AnySearch semnalează cota prin 429/plicul de răspuns, nu prin starea 402/403).
