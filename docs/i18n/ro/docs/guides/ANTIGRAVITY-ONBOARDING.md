## 1. Antigravity vs Antigravity CLI (agy)

Ambii furnizori utilizează **același backend Google** — client OAuth, reîmprospătarea tokenului, endpointurile și conturile Google sunt identice. Diferența constă în modelele pe care le vedeți.

> Consultați [anunțul Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli) pentru comparația oficială oferită de Google.

| Aspect                        | `antigravity` (IDE)                                  | `agy` (CLI)                                                      |
| ----------------------------- | ---------------------------------------------------- | ---------------------------------------------------------------- |
| **Produs Google**             | Antigravity 2.0 / Antigravity IDE                    | Antigravity CLI                                                  |
| **Backend**                   | Același API Google Cloud Code                        | Același API Google Cloud Code                                    |
| **OAuth / Token**             | Același client, aceeași reîmprospătare               | Același client, aceeași reîmprospătare                           |
| **Catalog de modele**         | Listă statică selecționată (codificată în OmniRoute) | Interogat în timp real de la Google prin `:fetchAvailableModels` |
| **Modele Claude**             | Sonnet 4.6, Opus 4.6 (câte 4 variante fiecare)       | Sonnet 4.6, Opus 4.6 (câte 4 variante fiecare)                   |
| **Denumiri Gemini**           | Etichete clare (Low/Medium/High)                     | ID-uri din sursa upstream (extra-low/low/agent)                  |
| **Modele suplimentare**       | `gpt-oss-120b-medium`                                | Poate include modele suplimentare de la Google                   |
| **Caz de utilizare implicit** | Integrare IDE (VS Code, JetBrains)                   | Acces CLI / API                                                  |
| **Cotă**                      | Partajată cu agy (același cont Google)               | Partajată cu antigravity (același cont Google)                   |

**Modele disponibile (verificate experimental, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (diverse niveluri de raționament)
- Claude: Sonnet 4.6, Opus 4.6 (fiecare cu variantele default/low/medium/high)
- Altele: GPT-OSS 120B Medium
- **Claude Sonnet 5 NU este disponibil** — sunt acceptate numai variantele 4.6

**De ce diferă catalogul de modele**: CLI-ul Google este „optimizat pentru viteză și sarcină redusă” și „co-optimizat cu modelele Gemini” (conform blogului oficial Google). Produsul Web/IDE este „optimizat pentru exhaustivitate”. CLI-ul utilizează `:fetchAvailableModels` pentru a descoperi dinamic modelele, în timp ce IDE-ul utilizează o listă statică selecționată.

**În practică**: Utilizați prefixul `agy/` pentru modelele Gemini (de exemplu, `agy/gemini-3.7-flash-high`). Utilizați `antigravity/` pentru lista statică selecționată. Ambele accesează același backend Google, dar expun denumiri diferite pentru modele. Cota este partajată — utilizarea oricăruia dintre furnizori se ia în calcul pentru aceleași limite ale contului Google.

## 2. Google One AI Pro: Sistemul de cote

> Consultați [Documentația Antigravity: Planuri](https://antigravity.google/docs/plans) pentru detalii oficiale despre cote și [Modificări ale planurilor Antigravity](https://antigravity.google/blog/changes-to-antigravity-plans) pentru cele mai recente actualizări ale prețurilor.

Google Antigravity utilizează o **cotă pe două niveluri**, bazată pe „Volumul de lucru efectuat” (ponderea computațională), nu pe numărul de mesaje.

### Cele două niveluri

| Nivel                 | Ce reprezintă                        | Ciclu de reîmprospătare                                                                                  |
| --------------------- | ------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| **Interval de 5 ore** | Rezervă imediată de „lucru efectuat” | Se resetează la 5 ore după prima solicitare dintr-o sesiune                                              |
| **Limită de 7 zile**  | Limită maximă săptămânală            | Are prioritate față de reîmprospătarea la 5 ore; blochează accesul până la următoarea perioadă de 7 zile |

**Cum este calculat „Volumul de lucru efectuat”**: Sarcinile care utilizează intens agenții (de exemplu, „Refactorizează întregul depozit”) consumă cota mult mai rapid decât sarcinile simple (de exemplu, „Corectează această funcție”). Nu există un tablou de bord în timp real care să afișeze consumul.

### Nivelurile planurilor

| Plan         | Preț         | Cotă                                            | Limită săptămânală                                               |
| ------------ | ------------ | ----------------------------------------------- | ---------------------------------------------------------------- |
| Gratuit      | $0           | Cotă semnificativă, reîmprospătată săptămânal   | Da                                                               |
| AI Pro       | $19.99/lună  | Cotă ridicată, reîmprospătare continuă la 5 ore | Da (are prioritate față de intervalul de 5 ore dacă este atinsă) |
| AI Ultra 5x  | $99.99/lună  | De 5 ori cota Pro                               | Fără limită săptămânală                                          |
| AI Ultra 20x | $199.99/lună | De 20 de ori cota Pro                           | Fără limită săptămânală                                          |

### Modele Gemini comparativ cu modelele non-Gemini

- **Modelele Gemini** (Flash + Pro): Partajează o singură limită de utilizare, consumată conform tarifelor API. Dacă Flash este de 8 ori mai ieftin decât Pro, primiți de 8 ori mai multe tokenuri Flash.
- **Modelele non-Gemini** (Claude, GPT-OSS): Au limite de utilizare **separate**. Pot rămâne disponibile chiar și atunci când Gemini este blocat.

### Credite AI (utilizare suplimentară)

> Consultați [Credite Google One AI](https://support.google.com/googleone/answer/14534406) pentru a afla cum funcționează creditele.

Când cota de bază este epuizată:

- **Niciodată**: Așteaptă reîmprospătarea cotei; afișează „Cota modelului de bază a fost atinsă”
- **Întotdeauna**: Utilizează automat creditele AI; revine la cota de bază atunci când aceasta este reîmprospătată

Creditele sunt achiziționate separat și deduse conform tarifelor API standard.

### Detalii importante

- Cota este **partajată la nivel de cont** — același cont Google utilizat în Antigravity IDE, CLI și OmniRoute partajează o singură rezervă de cotă
- Fiecare cont Google are propria cotă independentă — mai multe conturi = mai multe rezerve de cotă
- Utilizatorii AI Pro au raportat **blocări de 7 zile** în locul resetărilor la 5 ore atunci când limita săptămânală de bază este atinsă (Google a confirmat că acest comportament este intenționat în perioadele cu cerere ridicată)

**Când cota contului este epuizată**: OmniRoute reîncearcă automat cu următorul cont disponibil din ruta combinată. Nu este necesară nicio intervenție manuală.

## 3. Cum să obțineți un projectId

Fiecare conexiune antigravity/agy necesită un `projectId` Google Cloud Code. Fără acesta, endpointul `/v1internal:models` returnează 404.

### Metoda A: Automată (recomandată)

OmniRoute gestionează automat acest proces. Când adăugați un cont Google nou prin OAuth din tabloul de bord:

1. OmniRoute reîmprospătează tokenul
2. Apelează `loadCodeAssist` pentru a identifica projectId
3. Dacă nu există niciun proiect, apelează `onboardUser` pentru a crea unul
4. Reîncearcă `loadCodeAssist` pentru a obține projectId nou creat
5. Îl salvează în baza de date

**Această metodă funcționează pentru majoritatea conturilor** — nu sunt necesari pași manuali.

### Metoda B: Manuală, prin agy CLI

Dacă identificarea automată eșuează (consultați Secțiunea 5 pentru situațiile în care se întâmplă acest lucru):

```bash
# Instalați agy CLI (dacă nu este deja instalat)
npm install -g @anthropic-ai/agy

# Autentificați-vă cu contul Google
agy login

# Selectați contul care trebuie integrat
# Acest lucru declanșează înregistrarea în Cloud Code și atribuie un projectId
```

După ce `agy login` se finalizează cu succes, reîmprospătați tokenul în tabloul de bord OmniRoute. projectId va fi identificat automat.

### Cum să verificați

Verificați baza de date:

```bash
# În interiorul containerului OmniRoute
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Sau verificați jurnalele:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. URI de redirecționare OAuth

### Problema

Google OAuth necesită un URI de redirecționare valid. Configurația implicită OmniRoute utilizează `http://127.0.0.1:20128/callback` (loopback). Aceasta funcționează pentru buildurile locale, dar **eșuează în cazul implementărilor la distanță** (de exemplu, un server accesat printr-o adresă IP din LAN).

Google respinge URI-urile de redirecționare care:

- Utilizează adrese IP (trebuie utilizat un domeniu care se termină în `.com`, `.org` etc.)
- Nu corespund URI-urilor de redirecționare înregistrate în configurația clientului OAuth

### Soluția

**Opțiunea A: Utilizați fluxul OAuth încorporat (implicit)**

- Funcționează când accesați OmniRoute de la `localhost` sau `127.0.0.1`
- Nu este necesară nicio configurare

**Opțiunea B: Date de autentificare OAuth personalizate**

- Setați `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` în mediul dvs.
- Furnizați propriile date de autentificare Google OAuth:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Înregistrați `https://your-domain.com/callback` ca URI de redirecționare autorizat în Google Cloud Console

**Opțiunea C: Utilizați CLI-ul agy pentru autentificarea inițială**

- Rulați `agy login` pe dispozitivul care va accesa OmniRoute
- Fluxul OAuth se finalizează local, iar tokenurile sunt stocate
- Importați conexiunea în OmniRoute prin intermediul panoului de control

### Limitări

- Datele de autentificare OAuth personalizate necesită un nume de domeniu (Google nu acceptă adrese IP ca URI-uri de redirecționare)
- Dacă nu aveți un domeniu, utilizați în schimb opțiunea A sau C

## 5. Depanare: când configurarea automată eșuează

OmniRoute gestionează automat descoperirea projectId și integrarea inițială pentru majoritatea conturilor. Când procesul eșuează, cauza principală este de obicei una dintre următoarele:

### Regiunea contului este blocată

**Simptom**: `agy login` returnează „Verificarea eligibilității a eșuat: contul dvs. actual nu este eligibil pentru Antigravity, deoarece serviciul nu este disponibil momentan în locația dvs.”

**Cauza principală**: Conturile Google au un câmp „Asocierea țării” în backend, setat la momentul înregistrării. CLI-ul agy și API-ul Cloud Code verifică strict acest câmp — spre deosebire de versiunea web Gemini, care verifică numai adresa IP actuală.

> Pentru a verifica sau modifica regiunea asociată contului dvs., accesați [Formularul Google pentru asocierea țării](https://policies.google.com/country-association-form).

**De ce versiunea web Gemini funcționează, dar agy nu**:

- Versiunea web Gemini / Google One: verifică numai adresa IP actuală (proxy-ul permite trecerea verificării)
- CLI-ul agy / API-ul Cloud Code: citește câmpul Asocierea țării din backend (proxy-ul nu ajută)

**Remediere**:

1. Accesați [Formularul Google pentru asocierea țării](https://policies.google.com/country-association-form) în timp ce utilizați o adresă IP din SUA
2. Trimiteți o solicitare de schimbare a regiunii (selectați „Locuiesc într-o altă țară”)
3. Așteptați între 1 și 24 de ore pentru procesarea solicitării de către Google și notificarea prin e-mail
4. Apoi, `agy login` ar trebui să funcționeze

### Contul nu are niciun proiect Cloud Code

**Simptom**: Jurnalele afișează `loadCodeAssist returned no project id` și `onboardUser failed (400)`.

**Cauza principală**: Contul nu a fost înregistrat niciodată în Google Cloud Code, iar integrarea inițială automată a eșuat.

**Remediere**: Rulați manual `agy login` pentru a declanșa înregistrarea în Cloud Code, apoi reîmprospătați tokenul în panoul de control OmniRoute.

### Tokenul a expirat sau a fost revocat

**Simptom**: Erori 401 în jurnale sau mesaje de tipul „Tokenul a expirat”.

**Remediere**: Reîmprospătați tokenul în Panou de control → Furnizori → agy → Faceți clic pe pictograma de reîmprospătare. Dacă tokenul de reîmprospătare a fost revocat, va trebui să vă autentificați din nou prin OAuth.
