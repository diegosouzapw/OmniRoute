`chatgpt-web-codex` (alias `cgpt-codex`) intermediază interacțiunile Codex Responses printr-o
sesiune autentificată în browserul ChatGPT. Este independent de furnizorul comun retras
`chatgpt-web` și utilizează implementarea cu notificare MIT din
`open-sse/vendor/codex-chatgpt-web/`, actualizată până la commitul v4.0.7 din amonte
`b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494`.

## Retragerea furnizorului comun

Fostele ID-uri ale furnizorului comun, `chatgpt-web` și `cgpt-web`, nu mai sunt livrate, deoarece
proveniența implementării lor pentru pre-cheie/dovada muncii nu a putut fi clarificată. Solicitările
explicite către oricare dintre aceste ID-uri, inclusiv ID-urile de model prefixate cu bară oblică și aliasurile persistate, eșuează
în mod închis cu HTTP `410` și codul **PROVIDER_RETIRED** înainte de orice solicitare către serviciul din amonte.

Migrarea `168_retire_chatgpt_web.sql` marchează drept eliminate conexiunile corespunzătoare ale furnizorului și
le invalidează permisele de sesiune active. Aceasta păstrează istoricul conexiunilor și listele de permisiuni pentru cheile API;
nu adaugă acces de înlocuire într-o listă de permisiuni. Furnizorul Codex și
conexiunile sale nu sunt vizate de această retragere.

## Cerințe preliminare

- un antet Cookie complet dintr-o sesiune ChatGPT autentificată;
- Chrome sau Chromium împreună cu o sesiune grafică ori un afișaj Xvfb pentru instalările npm, systemd și PM2;
- cu profilul Docker `web`, serviciul Chromium intern din
  `docker-compose.yml`;
- OpenAI `tunnel-client` v0.0.13 și un conector personalizat ChatGPT pentru instrumentele Codex locale.

Tunelul este necesar doar pentru interacțiunile cu instrumente. Fiecare rută enumerată, inclusiv `pro`, poate utiliza aceeași
capabilitate locală pentru instrumente, asociată interacțiunii, atunci când tunelul și conectorul sunt configurate.

## Configurarea din panoul de control

1. Deschideți furnizorul **ChatGPT Web (Codex)** și adăugați o conexiune.
2. Lipiți antetul Cookie ChatGPT complet, ID-ul tunelului, cheia de execuție și numele conectorului
   personalizat. Configurările noi cu suport pentru instrumente trebuie să utilizeze un conector nou creat, denumit exact
   `OmniRoute Codex v2`, cu Authentication setat la None și Permissions setat la Allow all
   actions.
3. Rulați verificarea conexiunii. OmniRoute deschide un Temporary Chat susținut de browser și detectează
   dacă Sol și Pro sunt disponibile pentru cont.
4. Salvați conexiunea. OmniRoute înlocuiește modulul cookie lipit cu starea de stocare
   Playwright verificată și o stochează împreună cu cheia de execuție prin abstractizarea
   criptată a acreditărilor.

Modulul cookie brut nu este păstrat după o salvare reușită. Când sesiunea expiră, deschideți
conexiunea, lipiți un antet Cookie complet nou și rulați din nou verificarea. Starea doctor
din dialogul de editare raportează separat browserul, starea de stocare, autentificarea, Temporary Chat, tunelul,
conectorul și ciclul complet al instrumentului.

> Nu includeți niciodată într-un commit un modul cookie real, o cheie de execuție, o stare de stocare sau un token de capabilitate. Valorile pentru teste și
> documentație trebuie să fie întotdeauna substituenți.

## Modele și combinații

Rutele fixe ale modelelor sunt:

- `chatgpt-web-codex/luna` — GPT-5.6 Luna, efort redus
- `chatgpt-web-codex/think` — GPT-5.6 Luna, efort mediu
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

Adăugați unul dintre acestea într-o combinație la fel ca orice alt model. Aplicația Codex trimite numele combinației drept
`model` către endpointul Responses obișnuit, `/v1/responses`; nu există un endpoint Codex
separat sau un comutator de mod.

Conturile Free/Go expun rutele Luna. Conturile cu acces la Sol expun rutele de la Instant până la
High, iar conturile cu acces la Pro expun suplimentar Extra High și Pro. Fiecare rută are un
model backend și un nivel de efort de raționament fixe; un nivel de efort Responses explicit aflat în conflict determină o eroare
în mod închis, în loc să modifice în tăcere modul de browser selectat.

Nu redenumiți și nu reutilizați un conector mai vechi `Codex Native` sau `OmniRoute Codex`. ChatGPT
păstrează în cache contractul MCP public pe baza identității conectorului, în timp ce puntea actualizată utilizează un
nou contract direct pentru tokenul interacțiunii. Mediul de execuție respinge aceste identități vechi și necesită
un conector nou `OmniRoute Codex v2`.

## Model de securitate

- Calea nativă necesită o solicitare Responses, un client Codex recunoscut și identități corespunzătoare pentru fir și tură.
- Spațiul de lucru, sandboxul, politica de aprobare și catalogul de instrumente provin din shell-ul Codex nativ; textul liber al promptului nu are autoritate asupra acestora.
- ChatGPT primește doar o capabilitate cu durată scurtă de viață pentru fiecare tură. Brokerul MCP acceptă numai instrumentele oferite de Codex în exact acea tură.
- Confirmarea automată a opțiunii **Permite o dată** doar returnează solicitarea instrumentului către Codex. Numai Codex decide asupra aprobării și executării.
- Înainte de primul rezultat, o combinație poate recurge la o altă țintă compatibilă. După începerea rezultatului, furnizorul, modelul, conexiunea și tura browserului rămân fixate până la finalizarea turei.
- Cookie-urile, cheile de execuție, starea de stocare și tokenurile de capabilitate nu apar în răspunsurile furnizorului sau în jurnalele solicitărilor.

## VPS fără afișaj și Docker

Pentru instalările npm, systemd și PM2, OmniRoute detectează căile uzuale pentru Chrome și Chromium.
Alternativ, setați `CHATGPT_WEB_CODEX_CHROME_PATH`. Turele de execuție utilizează în mod deliberat Chrome cu interfață grafică, deoarece ChatGPT respinge configurația unui browser complet headless. Prin urmare, o gazdă fără afișaj trebuie să ruleze OmniRoute cu un afișaj Xvfb privat; simpla setare a căii către Chrome nu furnizează unul.

Profilul Docker `web` pornește `chatgpt-web-codex-browser` în rețeaua Compose internă.
Serviciul sidecar rulează Chrome cu interfață grafică în Xvfb, astfel încât nu este necesar un afișaj fizic. Portul său CDP nu este publicat pe gazdă. Volumul protejat al profilului browserului este separat de volumul de date OmniRoute, iar browserul primește suficientă memorie partajată. Proxy-ul CDP intern ascultă numai pe portul `9223` în cadrul rețelei Compose; Chrome rămâne legat la interfața loopback în serviciul sidecar.

Un contract de închiriere al supervizorului din `DATA_DIR` împiedică mai multe procese OmniRoute să dețină aceeași stare a tunelului și a brokerului. Un conflict este raportat de instrumentul de diagnosticare.

## Recuperare interactivă

Calea Docker automatizată nu are o fereastră vizibilă pe gazdă, însă Chrome însuși rulează cu interfață grafică în afișajul Xvfb privat. Atunci când ChatGPT necesită o autentificare interactivă sau o verificare, infrastructura existentă de browser VNC poate fi utilizată pentru recuperare. Interfața browserului și CDP trebuie să rămână accesibile numai prin loopback, printr-o conexiune de administrare autentificată sau printr-un tunel SSH; noVNC rămâne dezactivat în timpul funcționării normale.

## Alternativă WebSocket

Atunci când o combinație conține ChatGPT Web (Codex), puntea WebSocket pentru Responses solicită alternativa HTTP/SSE înainte de conectarea la serviciul upstream. Transferul trece apoi prin
`/v1/responses`.
