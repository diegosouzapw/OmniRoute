Acest document consemnează decizia de implementare pentru
[Problema #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854). Produsele publice sunt
reprezentate sub forma a patru familii de furnizori. Regiunea reprezintă date de conexiune, nu un produs separat.

## Decizie

| Familie de furnizori                            | ID OmniRoute            | Regiune globală | Regiunea China |
| ----------------------------------------------- | ----------------------- | --------------- | -------------- |
| Alibaba Cloud Model Studio (plată la utilizare) | `alibaba`               | Singapore       | Beijing        |
| Alibaba Cloud Token Plan                        | `bailian-coding-plan`   | Singapore       | Beijing        |
| Qwen Cloud (plată la utilizare)                 | `qwen-cloud`            | Global          | Beijing        |
| Qwen Cloud Token Plan                           | `qwen-cloud-token-plan` | Singapore       | Beijing        |

ID-ul existent `alibaba-cn` rămâne un alias de compatibilitate la rulare pentru conexiunile salvate, rutele
modelelor, combinații și utilizarea istorică. Cardul său din tabloul de bord este integrat în `alibaba`; nu este
necesară rescrierea bazei de date.

Qwen Cloud cu plată la utilizare și Alibaba Cloud Model Studio utilizează în prezent aceleași gazde de rulare
compatibile cu DashScope, însă rămân identități de furnizor separate, deoarece utilizatorii obțin cheile și își
gestionează conturile prin interfețe de produs diferite. Produsele Alibaba și Qwen Cloud Token Plan utilizează
familii diferite de endpoint-uri, astfel încât toate cele patru produse rămân ID-uri de furnizor separate.

## Matricea endpoint-urilor

| Familie de furnizori    | `global-sg`                                                              | `china-beijing`                                                      | Format de transfer |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ------------------ |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI             |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic          |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI             |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI             |

Cheia API și endpoint-ul trebuie să aparțină aceluiași produs și aceleiași regiuni. Selectarea unei regiuni modifică
endpoint-ul prestabilit utilizat pentru validare și solicitările normale.

## Contractul conexiunii

Conexiunile noi stochează cheia stabilă a regiunii în `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

Valorile permise sunt `global-sg` și `china-beijing`. Endpoint-ul este derivat centralizat din
ID-ul furnizorului și regiune. Un `providerSpecificData.baseUrl` care nu este prestabilit rămâne o suprascriere
explicită a operatorului și are prioritate, în timp ce vechile URL-uri prestabilite salvate sunt normalizate din nou conform
matricei regionale.

Astfel, schema conexiunii rămâne extensibilă: o altă regiune poate fi adăugată în resolver fără
a crea un alt card de furnizor sau a modifica ID-urile de furnizor salvate.

## Compatibilitate și lansare

1. Adăugați resolverul pentru endpoint-uri regionale și păstrați valorile implicite globale actuale.
2. Utilizați descoperirea în timp real a `/models` regional DashScope pentru `alibaba`, ID-ul său de compatibilitate `alibaba-cn` și `qwen-cloud`. Răspunsurile acestora trec mai întâi printr-un filtru pentru generarea de text, deoarece endpoint-ul generic returnează și modele de imagine, video, audio, embedding și alte modele care nu sunt pentru chat. `qwen-cloud` aplică apoi lista de permisiuni întreținută, declarată în registrul furnizorului său. Alibaba Model Studio și Qwen Cloud păstrează cataloage organizate separat, chiar dacă în prezent folosesc aceleași gazde de execuție.
3. Înregistrați `qwen-cloud-token-plan` cu lista actuală de permisiuni pentru modelele text din Token Plan.
4. Adăugați un selector de regiune tipizat în dialogurile pentru adăugarea/editarea conexiunilor.
5. Ascundeți cardul duplicat `alibaba-cn` și includeți conexiunile sale existente în pagina furnizorului `alibaba`.
6. Păstrați disponibile suprascrierile personalizate ale endpoint-urilor pentru implementări avansate și specifice spațiilor de lucru.

Modelele media din Token Plan rămân în afara catalogului de chat, deoarece utilizează endpoint-uri dedicate.
`wan2.7-image` și `wan2.7-image-pro` sunt înregistrate în `open-sse/config/imageRegistry.ts`;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` și `happyhorse-1.1-r2v` sunt înregistrate în
`open-sse/config/videoRegistry.ts`. Ambele registre reutilizează identitatea conexiunii `qwen-cloud-token-plan`
și acreditările sale specifice regiunii.

Qwen Cloud obișnuit are cataloage separate, cu plată în funcție de utilizare, pentru imagini și videoclipuri, sub identitatea `qwen-cloud`.
Modelele sale de imagine sunt `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` și `z-image-turbo`. Modelele sale
video sunt `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` și
`wan2.7-videoedit`. Aceste modele reutilizează numai conexiunea obișnuită `qwen-cloud` și endpoint-ul media
regional DashScope. Registrele Token Plan și cele cu plată în funcție de utilizare nu moștenesc și nu combină
listele de modele unul de la celălalt.

Identitatea `bailian-coding-plan` are, de asemenea, propriile liste de permisiuni pentru media:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` și `qwen-image-2.0-pro` pentru generarea
de imagini, plus
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` și `happyhorse-1.1-r2v` pentru generarea
de videoclipuri. Aceasta utilizează numai conexiunea Bailian Coding Plan și endpoint-ul regional Coding Plan.
Registrele sale de imagini și videoclipuri nu moștenesc și nu se combină cu niciunul dintre furnizorii Qwen Cloud.

Identitatea obișnuită `alibaba` are liste de permisiuni separate pentru imagini și videoclipuri. Modelele sale de imagine sunt
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` și `wan2.6-t2i`. Modelele video adăugate sunt `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` și `wan2.7-videoedit`. Aceste modele utilizează numai conexiunea Alibaba Model Studio
și endpoint-ul media regional selectat al acesteia; ele nu sunt adăugate în niciun registru Coding Plan sau Qwen
Cloud.

Catalogul de chat Qwen Cloud Token Plan urmează lista de permisiuni text cu potrivire exactă a planului Individual:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` și
`deepseek-v4-pro`. Intrările Wan și HappyHorse aparțin API-urilor separate pentru generarea de imagini/videoclipuri.

Alibaba Token Plan expune aceleași șase ID-uri actuale de modele pentru generarea de text prin endpoint-ul său
compatibil cu Anthropic. Opțiunea sa Singapore stochează cheia de regiune existentă `global-sg`;
numai eticheta afișată utilizatorului diferă față de familiile de furnizori care denumesc regiunea Global.

Catalogul de chat Qwen Cloud obișnuit este în mod intenționat mai restrâns decât răspunsul text complet în timp real. Lista sa
de permisiuni întreținută se află în `open-sse/config/providers/registry/qwen-cloud/index.ts`; descoperirea în timp
real returnează numai ID-urile prezente atât în răspunsul sursei, cât și în lista registrului respectiv.

Alibaba Model Studio urmează aceeași regulă de intersecție în timp real cu lista sa de permisiuni întreținută independent
în `open-sse/config/providers/registry/alibaba/index.ts`. Furnizorul de compatibilitate `alibaba-cn`
reutilizează catalogul respectiv, rezolvând în același timp descoperirea prin endpoint-ul Beijing.
