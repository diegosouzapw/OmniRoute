# 🚀 OmniRoute — Безплатният AI шлюз

<img src="./docs/diagrams/readme-hero.svg" width="100%" alt="OmniRoute — Никога не спирайте да програмирате. Всеки AI инструмент → 359 доставчици — над 150 безплатни — чрез една крайна точка. Claude Code, Codex, Cursor, Cline, Copilot и Antigravity към БЕЗПЛАТНИ Claude / GPT / Gemini с автоматично превключване при отказ. Комбинираната компресия RTK + Caveman спестява 15–95% от токените (~89% средно) — никога не достигайте ограниченията. 359 AI доставчици · над 150 безплатни нива · ~1,62 млрд. безплатни токена/месец · 19 стратегии за маршрутизиране · $0 за начало."/>

<div align="center">

## 💰 ~1.62B безплатни токена / месец

</div>

> Ръчното комбиниране на безплатни планове е мъчително — десетки SDK пакети, десетки ограничения на заявките и никаква представа с какво количество всъщност разполагате. OmniRoute каталогизира **489 записа за безплатни планове в 35 ключа за периодично възстановяващи се пулове** и изчислява общия брой токени въз основа на **17-те пула с публикуван положителен месечен бюджет плюс пет лимита на Groq за отделни модели**, като премахва дублиранията при споделените пулове. Квотите, които се активират само след регионална проверка на самоличността (към момента: ModelScope), са показани отделно — +~6M след регионална проверка на самоличността — и никога не се включват в общата стойност. Резултатът остава видим в таблото за управление (`/dashboard/free-tiers`).

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="Карта на бюджета за безплатните планове на OmniRoute: постоянно ~1.62B безплатни токена на месец и до ~2.22B през първия месец с кредити при регистрация, от 35 документирани ключа за периодично възстановяващи се пулове, обхващащи 489 каталогизирани записа за безплатни планове зад една крайна точка. Коректно изчисление с премахване на дублираните пулове — всеки споделен пул се брои веднъж, включително 17 периодично възстановяващи се пула с публикуван положителен месечен бюджет от токени плюс пет лимита на Groq за отделни модели; 13 доставчици са отбелязани като avoid в каталога за рискове, свързани с условията, така че вие решавате. Лентата на бюджета включва Mistral 1B, Nara 210M, LLM7 150M, xKiro 150M, Groq 30M (пет лимита за отделни модели) и по-малки пулове, както и кредити при регистрация за първия месец и постоянно безплатни доставчици без лимит на токените, показани отделно, за да не завишават общата стойност. Актуално използвано/оставащо количество на /dashboard/free-tiers."/>

> Анимирано обобщение на страницата `/dashboard/free-tiers` с актуални данни. Пълна методология (премахване на дублирани пулове, нива на кредитите, условия на доставчиците): **[docs/reference/FREE_TIERS.md](docs/reference/FREE_TIERS.md)**.
>
> <sub>Тези стойности се проверяват отново на всеки две седмици спрямо актуалния каталог и **се променят и в двете посоки** — ако доставчик прекрати безплатен план, стойността намалява; ако се появи нов, тя нараства. Публикуваме това, което каталогът действително изчислява, а не закръглен нагоре най-добър сценарий.</sub>

## 📡 OmniRoute Radar

Основното предимство на безплатното ниво остава **~1,62 млрд. токена/месец** от документирания
по-горе каталог с премахнато дублиране между общите квоти. Временните кредити при регистрация при доставчици могат отделно да увеличат обема за първия
месец до **~2,22 млрд.** Radar е незадължителен, подписан допълнителен слой към каталога за хора, които искат по-актуална
информация за наличността на безплатни модели между изданията на OmniRoute; каталогът на общността и всички съществуващи безплатни
функции остават безплатни.

Поддръжниците могат да получат каталога на живо и допълнителни възможности от доставчици. Неговият отделен,
променлив таван е **приблизително най-много 3 млрд. токена/месец** в зависимост от наличността при доставчиците.
Този таван не е гарантиран: доставчиците могат по всяко време да променят квотите, критериите за допустимост, моделите или регионите.

Radar се използва само по желание и поддържа единствено GET. Клиентът на OmniRoute не качва подкани, трафик, конфигурация на доставчици,
телеметрия за използването или локалното състояние за отхвърляне на съобщения. Научете повече за критериите за допустимост и
текущия каталог на **[radar.omniroute.online/planos](https://radar.omniroute.online/planos)**.

**Стартирайте всеки поддържан CLI чрез OmniRoute с една команда** — без записване на конфигурационни файлове,
идентификационните данни се подават за всеки процес, а Qwen/Gemini получават временна изолирана домашна директория:

```bash
omniroute run claude   --model openai/gpt-5.4          # Claude Code
omniroute run codex    --model glm/glm-5.2             # OpenAI Codex CLI
omniroute run aider    --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose    --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"
omniroute run qwen     --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini   --model glm/glm-5.2 -- --skip-trust -p "reply OK"

# Или изберете интерактивно доставчик и модел и запишете собствената конфигурация на инструмента:
omniroute configure codex          # също: claude opencode qwen aider goose gemini cline continue kilo
```

Всяка команда зачита активния отдалечен контекст (`omniroute connect <host>`), `--dry-run`
показва предварително точните променливи на средата/аргументи без изпълнение, а `--api-key-env NAME` не допуска тайните
в хронологията на вашата обвивка. → [CLI интеграции](docs/guides/CLI-INTEGRATIONS.md)

## 🔌 Пълнофункционален CLI + A2A и MCP

> Освен сървъра, OmniRoute е **пълнофункционален център за управление от командния ред** с **над 80 команди**, както и с отворени протоколи за агенти, така че AI агент да може да го управлява **самостоятелно**.

### ⌨️ Истински CLI (не само `start`)

```bash
omniroute               # стартира шлюза + таблото за управление (порт 20128)
omniroute chat          # интерактивен TUI клиент за чат (наклонени команди: /model /combo /skill /memory)
omniroute setup         # насочван помощник за първоначална настройка
```

### 🛰️ Отдалечен режим — изпълнявайте CLI тук, а OmniRoute на VPS

OmniRoute е на сървър? Управлявайте го от лаптопа си със **същия CLI**. Влезте еднократно
с токен за достъп с ограничен обхват; след това всяка команда се насочва към отдалечения сървър.

```bash
omniroute connect 192.168.0.15            # парола → токен с ограничен обхват, запазен като контекст
omniroute models list                     # ← изпълнява се спрямо ОТДАЛЕЧЕНИЯ сървър
omniroute configure codex                 # ← избира отдалечен модел и записва локален профил на Codex
omniroute tokens create --name ci --scope read   # създава токени с по-тесен обхват за други машини
omniroute contexts use default            # ← превключва обратно към локалния сървър
```

Токените имат обхват `read` / `write` / `admin`; маршрутите, стартиращи процеси, остават достъпни само през loopback.

### 📖 Как работи — конвейер, архитектура и изчисляване на спестяванията

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="Конвейер за компресиране на OmniRoute: илюстративна клиентска заявка от 10 000 токена преминава през 12 съставни механизма — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra и OmniGlyph — и в документирания комбиниран пример може да достигне до доставчика с около 1 080 токена. Структурираното съдържание е защитено чрез предпазни механизми за запазване и проверки за точност на всяка стъпка; изрично избраните режими със загуби или експериментални режими могат да преобразуват допустимото съдържание."/>

Стандартната комбинирана конфигурация изпълнява `RTK → Caveman`. Когато и двата механизма обработват едни и същи данни от инструмент или контекст, спестяванията се натрупват:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

Блоковете с код, URL адресите, JSON и структурираните данни са **винаги защитени** от механизма за запазване.

> **Защо да използвате много токени, когато малко вършат работа?** Всяка заявка преминава през конвейера за компресиране на OmniRoute **прозрачно** — без промени в клиента. Сега той представлява **набор от 12 съставни механизма**, които се изпълняват последователно и могат да се комбинират във всякакви конфигурации за маршрутизиране — въз основа на идеи от [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K+), [LLMLingua-2](https://github.com/microsoft/LLMLingua) и [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR).

### 🎚️ Отвъд механизмите — стилове на изхода, адаптивният регулатор и контролът за всяка заявка

12-те механизма по-горе намаляват това, което влиза **на входа**. Още три слоя определят **как**, **кога** и какво излиза **на изхода**:

- **🪄 Стилове на изхода** _(управление по оста на изхода)_ — добавят детерминистични, безопасни за кеширане инструкции за оформяне на отговора; могат да се комбинират, всеки с интензивност `lite` / `full` / `ultra`. Добавянето на стил е едноредов запис в регистъра:
  - **Лаконична проза** — премахва пълнежа / членовете / уговорките; запазва техническото съдържание точно.
  - **По-малко код** — YAGNI подход на „мързелив старши разработчик“: най-малката работеща промяна, без непоискана инфраструктура.
  - **Конска опашка (мързелив старши разработчик)** — изкачва стълбата на YAGNI, отстранява първопричината, използва най-малката работеща разлика.
  - **Имам ADHD (първо действие)** — започва със следващото действие, номерирани стъпки, една конкретна следваща стъпка, без увод.
  - **Лаконичен CJK (文言)** — ултралаконичен стил на класически китайски (ограничен до локал `zh`).
- **🎯 Адаптивен бюджет на контекста** _(регулаторът)_ — вместо един праг за токени с включване/изключване, активира най-евтините механизми с най-малко загуби само доколкото е необходимо, за да **се вмести в контекстния прозорец на модела**. Политика: `reserve-output` (по подразбиране, съобразена с модела) · `percentage` · `absolute`. Режим: `floor` (гарантира побиране) · `replace-autotrigger` (вашият изричен избор има предимство) · `off` (наследен праг).
- **🎛️ Къде се определя компресията** _(приоритет, от висок към нисък)_ — заглавка `x-omniroute-compression` за конкретна заявка › замяна за комбинацията за маршрутизиране › активен именуван профил › адаптивно / автоматично задействане › настройка по подразбиране от панела › изключено. Приложеният план се връща в заглавката на отговора `X-OmniRoute-Compression: <mode>; source=<source>`.

Използвайте автоматично задействане според праг на токените, включете адаптивния регулатор, фиксирайте именуван профил, задайте еднократна настройка за конкретна заявка или присвоете конвейер към комбинация за маршрутизиране — според нуждите на работното натоварване. Незадължителен офлайн **инструмент за оценяване** (`npm run eval:compression`) измерва достоверността спрямо спестяванията върху фиксиран корпус, преди да внедрите дадена промяна.

📖 [`COMPRESSION_GUIDE.md`](docs/compression/COMPRESSION_GUIDE.md) · [`RTK_COMPRESSION.md`](docs/compression/RTK_COMPRESSION.md) · [`COMPRESSION_ENGINES.md`](docs/compression/COMPRESSION_ENGINES.md)

Табло → **Доставчици** → свържете **Kiro AI** (безплатен Claude, ~50 кредита месечно за акаунт) или **OpenCode Free** (без удостоверяване) → готово.

**3) Насочете инструмента си за програмиране**

```txt
Основен URL адрес: http://localhost:20128/v1
API ключ:          [копирайте от Табло → Крайни точки]
Модел:             auto            (интелигентно маршрутизиране без конфигурация — или произволен доставчик/модел)
```

```bash
curl http://localhost:20128/v1/models -H "Authorization: Bearer YOUR_KEY"
```

Ако клиентът ви не може да изпраща персонализирани заглавки, OmniRoute предлага и токенизирани псевдоними за съвместимост:

```txt
Каталог на OpenAI:  http://localhost:20128/vscode/YOUR_KEY/

Чат на OpenAI:      http://localhost:20128/vscode/YOUR_KEY/chat/completions
Отговори на OpenAI: http://localhost:20128/vscode/YOUR_KEY/responses
Чат на Ollama:      http://localhost:20128/vscode/YOUR_KEY/api/chat
Етикети на Ollama:  http://localhost:20128/vscode/YOUR_KEY/api/tags
```

Използвайте ги само за клиенти, които не могат да добавят `Authorization: Bearer ...`. Удостоверяването чрез заглавка остава предпочитаният режим.

## 📦 Още методи за инсталиране — Docker, изходен код, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

`:latest` следва най-високата **публикувана** стабилна SemVer версия. Той не следва git `main`. Фиксирайте `:X.Y.Z` за GitOps. Вижте [Канали за издания на Docker](docs/guides/DOCKER_GUIDE.md#release-channels).Образът фиксира **`OMNIROUTE_MEMORY_MB=1024`**. Това е достатъчно за таблото и лек чат. **Агентите за програмиране** (`POST /v1/responses` от Claude Code, Codex, Grok, …) се нуждаят от много по-голяма V8 heap памет, в противен случай процесът завършва с `FATAL ERROR` при около 12 GiB с два припокриващи се дълги контекста. Оразмерете контейнера над размера на heap паметта (собствените буфери са извън V8):

| Натоварване                                       | Heap (`-e OMNIROUTE_MEMORY_MB`)   | Контейнер (`--memory`) |
| ------------------------------------------------- | --------------------------------- | ---------------------- |
| Табло / лек чат                                   | `1024` (по подразбиране в образа) | ≥2 g                   |
| Един агент за програмиране                        | `8192`                            | ≥10 g                  |
| Две едновременни дълги заявки към `/v1/responses` | `10240`–`12288`                   | ≥12–16 g               |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

Пълна таблица: [Ръководство за Docker — оперативна памет за изпълнение](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

> **Docker канал за предварителни издания:** `diegosouzapw/omniroute:next` и
> `diegosouzapw/omniroute:next-web` следват текущия стандартен клон `release/v*`.
> Тези променливи тагове са предназначени само за тестване на непубликувани корекции и
> **не се поддържат за продукционна среда**. Вижте
> [Канали за издания на Docker](docs/guides/DOCKER_GUIDE.md#release-channels).

**🥟 Bun**

Стандартното `bun install` и глобалното инсталиране (`bun install -g omniroute`) се поддържат чрез откриване на средата за изпълнение Bun:

- **Вграден `bun:sqlite`**: OmniRoute използва вградения в Bun драйвер `bun:sqlite`, когато се изпълнява под Bun, като преминава към `better-sqlite3` при Node.js или към `sql.js`.
- **Автоматичен избор на Webpack като пакетиращ инструмент при разработка**: Режимът за разработка (`bun run dev`) автоматично открива Bun и деактивира Turbopack в полза на Webpack, за да предотврати несъвместимости със собствените V8 обвързвания. Продукционните компилации (`bun run build`) следват `OMNIROUTE_USE_TURBOPACK` точно както при Node: Turbopack по подразбиране, `OMNIROUTE_USE_TURBOPACK=0` за компилиране с Webpack (`Dockerfile.bun` го предоставя като `--build-arg`).
- **Специализиран Dockerfile за Bun**: Многоетапен `Dockerfile.bun` за собствени продукционни внедрявания с Bun (`docker build -f Dockerfile.bun -t omniroute:bun .`).

```bash
# Инсталиране и стартиране с Bun
bun install
bun run dev
```

**⚡ По-бързо / по-леко инсталиране (пропускане на собствената компилация)**

Собственият SQLite енджин (`better-sqlite3`) е **незадължима** зависимост, така че глобалното
инсталиране никога не блокира заради компилиране от изходен код: използва предварително компилиран двоичен файл, когато има съвпадащ
за вашата платформа/Node, а в противен случай прозрачно преминава към енджин, реализиран изцяло на JS
(`node:sqlite` при Node 22+, иначе включения `sql.js` WASM) — не са необходими инструменти за компилиране.

За да пропуснете напълно собственото предварително инициализиране след инсталиране (CI, среди без графичен интерфейс или бавни машини):

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 също го пропуска
```

За най-бързо инсталиране предпочитайте **pnpm** (хранилище, адресирано по съдържание + твърди връзки — вижте по-горе).
За среда за изпълнение без табло и без графичен интерфейс използвайте Docker профила `base` (по-горе) или
[ръководството за Termux](docs/guides/TERMUX_GUIDE.md). CLI и уеб таблото се обслужват от
един и същ процес на един порт, така че към момента няма отделен пакет само за CLI.

1. Направете fork на хранилището

6. Отворете Pull Request с **base = съответния клон `release/vX.Y.Z`**
