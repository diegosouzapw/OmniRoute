## 1. Antigravity спрямо Antigravity CLI (agy)

И двата доставчика използват **един и същ бекенд на Google** — идентичен OAuth клиент, обновяване на токени, крайни точки и акаунти в Google. Разликата е в моделите, които виждате.

> Вижте [обявяването на Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli) за официалното сравнение от Google.

| Аспект                         | `antigravity` (IDE)                                  | `agy` (CLI)                                               |
| ------------------------------ | ---------------------------------------------------- | --------------------------------------------------------- |
| **Продукт на Google**          | Antigravity 2.0 / Antigravity IDE                    | Antigravity CLI                                           |
| **Бекенд**                     | Същият Google Cloud Code API                         | Същият Google Cloud Code API                              |
| **OAuth / токен**              | Същият клиент, същото обновяване                     | Същият клиент, същото обновяване                          |
| **Каталог с модели**           | Статичен подбран списък (твърдо кодиран в OmniRoute) | Динамично извлечен от Google чрез `:fetchAvailableModels` |
| **Модели Claude**              | Sonnet 4.6, Opus 4.6 (по 4 варианта за всеки)        | Sonnet 4.6, Opus 4.6 (по 4 варианта за всеки)             |
| **Именуване на Gemini**        | Ясни етикети (Low/Medium/High)                       | Идентификатори от първоизточника (extra-low/low/agent)    |
| **Допълнителни модели**        | `gpt-oss-120b-medium`                                | Може да включва допълнителни модели от Google             |
| **Основен случай на употреба** | Интеграция с IDE (VS Code, JetBrains)                | Достъп чрез CLI / API                                     |
| **Квота**                      | Споделена с agy (същият акаунт в Google)             | Споделена с antigravity (същият акаунт в Google)          |

**Налични модели (потвърдено чрез експеримент, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (различни нива на разсъждение)
- Claude: Sonnet 4.6, Opus 4.6 (всеки с варианти default/low/medium/high)
- Други: GPT-OSS 120B Medium
- **Claude Sonnet 5 НЕ е наличен** — поддържат се само вариантите на 4.6

**Защо каталогът с модели се различава**: CLI на Google е „оптимизиран за скорост и ниски допълнителни разходи“ и „съвместно оптимизиран с моделите Gemini“ (според официалния блог на Google). Уеб/IDE продуктът е „оптимизиран за изчерпателност“. CLI използва `:fetchAvailableModels`, за да открива динамично моделите, докато IDE използва статичен подбран списък.

**На практика**: Използвайте префикса `agy/` за моделите Gemini (напр. `agy/gemini-3.7-flash-high`). Използвайте `antigravity/` за статичния подбран списък. И двата използват един и същ бекенд на Google, но предоставят различно именуване на моделите. Квотата е споделена — използването на който и да е от двата доставчика се отчита спрямо ограниченията на същия акаунт в Google.

## 2. Google One AI Pro: Система за квоти

> Вижте [Документация на Antigravity: Планове](https://antigravity.google/docs/plans) за официални подробности относно квотите и [Промени в плановете на Antigravity](https://antigravity.google/blog/changes-to-antigravity-plans) за най-новите актуализации на цените.

Google Antigravity използва **двуслойна квота**, базирана на „Извършена работа“ (изчислителна тежест), а не на броя съобщения.

### Двата слоя

| Слой                      | Какво представлява                     | Цикъл на обновяване                                                                                         |
| ------------------------- | -------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| **5-часов спринт**        | Незабавен резерв от „извършена работа“ | Нулира се 5 часа след първата заявка в дадена сесия                                                         |
| **7-дневна базова квота** | Твърд седмичен лимит                   | Има предимство пред 5-часовото обновяване, ако бъде достигнат; блокира достъпа до следващия 7-дневен период |

**Как се изчислява „Извършената работа“**: Задачите, използващи интензивно агенти (напр. „Рефакторирай цялото това хранилище“), изчерпват квотата много по-бързо от простите задачи (напр. „Поправи тази функция“). Няма табло в реално време, което да показва потреблението.

### Нива на плановете

| План         | Цена       | Квота                                    | Седмичен лимит                                                     |
| ------------ | ---------- | ---------------------------------------- | ------------------------------------------------------------------ |
| Free         | $0         | Значителна квота, обновявана ежеседмично | Да                                                                 |
| AI Pro       | $19.99/mo  | Висока квота, текущо 5-часово обновяване | Да (има предимство пред 5-часовото обновяване, ако бъде достигнат) |
| AI Ultra 5x  | $99.99/mo  | 5x квотата на Pro                        | Няма седмичен лимит                                                |
| AI Ultra 20x | $199.99/mo | 20x квотата на Pro                       | Няма седмичен лимит                                                |

### Модели Gemini спрямо модели, различни от Gemini

- **Модели Gemini** (Flash + Pro): Споделят един общ лимит на заявките, който се изразходва според цените на API. Ако Flash е 8x по-евтин от Pro, получавате 8x повече Flash токени.
- **Модели, различни от Gemini** (Claude, GPT-OSS): Имат **отделни** лимити на заявките. Те може да останат достъпни дори когато Gemini е блокиран.

### AI кредити (допълнително потребление)

> Вижте [Google One AI кредити](https://support.google.com/googleone/answer/14534406), за да разберете как работят кредитите.

Когато базовата квота бъде изчерпана:

- **Никога**: Изчаква обновяването на квотата; показва „Достигната е базовата квота на модела“
- **Винаги**: Автоматично използва AI кредити; връща се към базовата квота, когато тя бъде обновена

Кредитите се закупуват отделно и се приспадат по стандартните цени на API.

### Основни подробности

- Квотата е **споделена на ниво акаунт** — един и същ Google акаунт в Antigravity IDE, CLI и OmniRoute споделя един общ резерв от квота
- Всеки Google акаунт има собствена независима квота — няколко акаунта = няколко резерва от квота
- Потребители на AI Pro съобщават за **7-дневни блокирания** вместо 5-часови нулирания при достигане на седмичната базова квота (Google потвърди, че това е предвидено при високо търсене)

**Когато квотата на акаунта ви е изчерпана**: OmniRoute автоматично опитва отново със следващия наличен акаунт в комбинирания маршрут. Не е необходима ръчна намеса.

## 3. Как да получите projectId

Всяка връзка с antigravity/agy се нуждае от `projectId` на Google Cloud Code. Без него крайната точка `/v1internal:models` връща 404.

### Метод A: Автоматично (препоръчително)

OmniRoute се справя с това автоматично. Когато добавите нов Google акаунт чрез OAuth в таблото за управление:

1. OmniRoute обновява токена
2. Извиква `loadCodeAssist`, за да открие projectId
3. Ако не съществува проект, извиква `onboardUser`, за да създаде такъв
4. Опитва отново с `loadCodeAssist`, за да получи новосъздадения projectId
5. Записва го в базата данни

**Това работи за повечето акаунти** — не са необходими ръчни стъпки.

### Метод B: Ръчно чрез agy CLI

Ако автоматичното откриване е неуспешно (вижте Раздел 5 за случаите, в които това се случва):

```bash
# Инсталирайте agy CLI (ако все още не е инсталиран)
npm install -g @anthropic-ai/agy

# Влезте с вашия Google акаунт
agy login

# Изберете акаунта, който трябва да бъде регистриран
# Това задейства регистрацията в Cloud Code и присвоява projectId
```

След като `agy login` завърши успешно, обновете токена в таблото за управление на OmniRoute. projectId ще бъде открит автоматично.

### Как да проверите

Проверете базата данни:

```bash
# В контейнера на OmniRoute
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Или проверете регистрационните файлове:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. URI за пренасочване на OAuth

### Проблемът

Google OAuth изисква валиден URI за пренасочване. По подразбиране OmniRoute използва `http://127.0.0.1:20128/callback` (loopback). Това работи за локални инсталации, но **не работи при отдалечени внедрявания** (напр. сървър, достъпен чрез IP адрес в LAN).

Google отхвърля URI адреси за пренасочване, които:

- Използват IP адреси (трябва да бъде домейн, завършващ на `.com`, `.org` и т.н.)
- Не съвпадат с регистрираните URI адреси за пренасочване в конфигурацията на OAuth клиента

### Решението

**Опция A: Използване на вградения OAuth процес (по подразбиране)**

- Работи, когато осъществявате достъп до OmniRoute от `localhost` или `127.0.0.1`
- Не е необходима конфигурация

**Опция B: Персонализирани идентификационни данни за OAuth**

- Задайте `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` във вашата среда
- Предоставете свои идентификационни данни за Google OAuth:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Регистрирайте `https://your-domain.com/callback` като оторизиран URI за пренасочване в Google Cloud Console

**Опция C: Използване на agy CLI за първоначално влизане**

- Изпълнете `agy login` на машината, която ще осъществява достъп до OmniRoute
- OAuth процесът завършва локално и токените се съхраняват
- Импортирайте връзката в OmniRoute чрез таблото за управление

### Ограничения

- Персонализираните идентификационни данни за OAuth изискват име на домейн (Google не приема IP адреси като URI адреси за пренасочване)
- Ако нямате домейн, използвайте вместо това Опция A или C

## 5. Отстраняване на проблеми: когато автоматичната настройка е неуспешна

OmniRoute обработва автоматично откриването на projectId и първоначалната регистрация за повечето акаунти. Когато процесът е неуспешен, основната причина обикновено е една от следните:

### Регионът на акаунта е блокиран

**Симптом**: `agy login` връща „Eligibility check failed: Your current account is not eligible for Antigravity, because it is not currently available in your location.“

**Основна причина**: Акаунтите в Google имат бекенд поле „Country Association“, което се задава при регистрацията. agy CLI и Cloud Code API проверяват стриктно това поле — за разлика от уеб версията на Gemini, която проверява само текущия ви IP адрес.

> За да проверите или промените свързания с акаунта ви регион, посетете [формуляра на Google за асоцииране с държава](https://policies.google.com/country-association-form).

**Защо уеб версията на Gemini работи, но agy не работи**:

- Уеб версия на Gemini / Google One: проверява само текущия IP адрес (проксито е достатъчно)
- agy CLI / Cloud Code API: прочита бекенд полето Country Association (проксито не помага)

**Решение**:

1. Посетете [формуляра на Google за асоцииране с държава](https://policies.google.com/country-association-form), докато използвате IP адрес от САЩ
2. Изпратете заявка за промяна на региона (изберете „I live in a different country“)
3. Изчакайте 1–24 часа, докато Google обработи заявката и изпрати известие по имейл
4. След това `agy login` би трябвало да завърши успешно

### Акаунтът няма проект в Cloud Code

**Симптом**: Регистрационните файлове показват `loadCodeAssist returned no project id` и `onboardUser failed (400)`.

**Основна причина**: Акаунтът никога не е бил регистриран в Google Cloud Code и автоматичната първоначална регистрация е била неуспешна.

**Решение**: Изпълнете ръчно `agy login`, за да задействате регистрацията в Cloud Code, след което обновете токена в таблото за управление на OmniRoute.

### Токенът е изтекъл или е отменен

**Симптом**: Грешки 401 в регистрационните файлове или съобщения „Token has expired“.

**Решение**: Обновете токена от Табло за управление → Доставчици → agy → Щракнете върху иконата за обновяване. Ако самият токен за обновяване е отменен, ще трябва да се удостоверите отново чрез OAuth.

```
├─ Зададена ли е „Асоциация с държава“ на акаунта към ограничен регион?

│  │         (https://policies.google.com/country-association-form)

│  └─ НЕ ↓
│
├─ Акаунтът има ли абонамент за Google One AI Pro?
│  ├─ НЕ → Първо се абонирайте на one.google.com
│  └─ ДА ↓
│
├─ Опитайте автоматично откриване (опреснете токена в таблото за управление)
│  ├─ Работи → Готово
│  └─ Все още не работи ↓
│
└─ Ръчно: Изпълнете `agy login` на машината
   ├─ Работи → Опреснете токена в таблото за управление, projectId е открит
   └─ Не работи → Проверете съобщението за грешка; вероятно има проблем с региона или абонамента
```
