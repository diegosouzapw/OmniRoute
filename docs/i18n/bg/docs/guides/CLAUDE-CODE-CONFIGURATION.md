Насочете CLI инструмента **Claude Code** (`claude`) към OmniRoute — локално или към отдалечен VPS —
с профили за отделните модели, аналогично на конфигурацията за Codex.

---

## Бърз старт

```bash
# Стартирайте Claude Code с локален OmniRoute (автоматично открива активния контекст)
omniroute launch

# С отдалечен OmniRoute (след `omniroute connect <host>` това става автоматично)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# Генерирайте профили за отделните модели, след което стартирайте един от тях
omniroute setup-claude            # записва ~/.claude/profiles/<name>/settings.json
omniroute launch --profile glm52  # Claude Code използва glm/glm-5.2 чрез OmniRoute
```

## Как Claude Code се свързва с шлюз

Claude Code комуникира чрез **Anthropic Messages API** и се насочва към персонализирана
крайна точка чрез променливи на средата (няма флаг `--base-url`):

| Променлива                                   | Предназначение                                                                                          |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `ANTHROPIC_BASE_URL`                         | Основен URL адрес на шлюза (Claude Code добавя `/v1/messages`). **Без суфикс `/v1`.**                   |
| `ANTHROPIC_AUTH_TOKEN`                       | Изпраща се като `Authorization: Bearer …` — използвайте своя токен за достъп / API ключ за OmniRoute    |
| `ANTHROPIC_API_KEY`                          | Алтернатива: изпраща се като `x-api-key`. Ако са зададени и двете, `ANTHROPIC_AUTH_TOKEN` има приоритет |
| `ANTHROPIC_MODEL`                            | Налага конкретен модел (замества избрания по подразбиране чрез `/model`)                                |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` → вграденият списък `/model` показва моделите `claude*`/`anthropic*` от `/v1/models`                |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`              | Ограничава изходните токени за всеки отговор (напр. `65536`)                                            |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`            | Праг на токените за автоматично уплътняване                                                             |

> Променливите на средата се прочитат **само веднъж при стартиране** — рестартирайте Claude Code, след като ги промените.

`omniroute launch` задава всички тези променливи вместо вас: определя основния URL адрес и токена
от активния контекст (така че след `omniroute connect <vps>` командата `omniroute launch`
просто работи), проверява състоянието на сървъра и изпълнява `claude`.

## Псевдоними за откриване — показване на модели, различни от Claude, в списъка `/model`

Откриването на модели чрез шлюз в Claude Code показва само идентификатори, които започват с `claude`
или `anthropic`, така че при `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` вграденият
списък `/model` обикновено показва **само** Claude/Anthropic моделите на OmniRoute — модели като
`kimi/kimi-k2.6` или `glm/glm-5.2` никога не се появяват, въпреки че маршрутизирането им работи.

OmniRoute може да дублира всеки активиран модел (и комбинация) под идентификатор `claude/…`, така че той
да премине през този филтър и да се появи в списъка:

```
kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<комбинация "custo-otimizado"> →  claude/combo/custo-otimizado
```

Когато изберете някой от тях в Claude Code, OmniRoute премахва обвивката `claude/`
и възстановява реалния идентификатор преди маршрутизиране — истински идентификатор `claude/<real-claude-model>`
(от действителния доставчик на Claude OAuth) винаги остава непроменен.

**Това е изключено по подразбиране** и се управлява чрез тристепенна йерархия (най-конкретната
настройка има приоритет), така че стандартна инсталация на OmniRoute никога не удвоява каталога си за клиенти, които не използват
Claude Code:

| Ниво      | Местоположение                                                                                      |
| --------- | --------------------------------------------------------------------------------------------------- |
| Модел     | Страница с подробности за доставчика → превключвател „Показване в Claude Code“ за модела            |
| Доставчик | Страница с подробности за доставчика → превключвател на ниво доставчик (обхваща всичките му модели) |
| Глобално  | Настройки → Флагове за функции → `EXPOSE_CC_DISCOVERY_ALIASES` (изключено по подразбиране)          |

Променливата на средата `EXPOSE_CC_DISCOVERY_ALIASES` принудително включва глобалното ниво
и има приоритет пред настройката от таблото за управление (екранът „Флагове за функции“ показва
бележка „активно чрез променлива на средата“, когато това е така). Превключвателите за отделните
доставчици и модели допълнително прецизират настройката — напр. глобално изключване + включен доставчик Kimi показва
само моделите на Kimi.

> ⚠️ **Несъответствие на контекстния прозорец при модели, различни от Claude.** Claude Code приема контекстен
> прозорец от 200K за всеки идентификатор, който не разпознава (не може да прочете реалния размер на прозореца от
> `/v1/models`). За модел с по-голям прозорец (напр. 256K при Kimi K2) задайте
> `CLAUDE_CODE_AUTO_COMPACT_WINDOW` на стойност под реалния прозорец на модела, така че
> автоматичното уплътняване да не се задейства преждевременно. Генерираните по-горе профили вече
> задават това поотделно за всеки модел.

## Блок за първоначална настройка в таблото

Картата на инструмента Claude (**Табло → CLI Code**) визуализира точния фрагмент от `settings.json`
за тази инстанция до информационния бутон за псевдонима за откриване, както и бутон за копиране:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}
```

Базовият URL адрес е този, който е определен от картата (включително въведена от вас персонализирана стойност), и вече е
нормализиран — без суфикс `/v1` и без завършваща наклонена черта. **Ключът никога не се визуализира**: блокът съдържа
заместващ текст, така че екранна снимка или поставен фрагмент да не може да го разкрие. Поставете ключа си върху него.

Добавете `CLAUDE_CODE_AUTO_COMPACT_WINDOW` в същия блок `env` за всеки модел, чийто действителен
контекстен прозорец не е 200K — Claude Code приема 200K за всеки идентификатор, който не разпознава, поради което
автоматичното компактиране иначе се задейства в неправилния момент (вижте предупреждението в предишния раздел).
Конструкторът на фрагмента приема и тази стойност, така че извикваща страна, която знае размера на контекстния прозорец на целевия модел,
може да я подаде директно.

Източник: `src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet` (чист
конструктор, покрит с модулни тестове), визуализиран от `ClaudeGatewayOnboardingBlock`.

## Профили (`CLAUDE_CONFIG_DIR`)

Claude Code **няма собствени файлове за профили** (за разлика от `~/.codex/<name>.config.toml` на Codex).
Стандартният механизъм е `CLAUDE_CONFIG_DIR` — отделна конфигурационна директория за всеки
профил, всяка със собствен `settings.json`, идентификационни данни, хронология и кеш.

`omniroute setup-claude` извлича актуалния каталог `/v1/models` и записва по един
профил за всеки модел в `~/.claude/profiles/<name>/settings.json`, като използва повторно
**същите имена като `setup-codex`** (`glm52`, `kimi-k27`, `deepseek-pro`, …):

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}
```

> **Токенът за удостоверяване никога не се записва в профила.** Стартирайте с
> `omniroute launch --profile <name>` (командата инжектира `ANTHROPIC_AUTH_TOKEN` от
> активния контекст) или сами експортирайте `ANTHROPIC_AUTH_TOKEN` и изпълнете
> `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude`.

**Автоматична синхронизация след откриване на модели (по избор).** OmniRoute може автоматично да генерира повторно същите
файлове `~/.claude/profiles/<name>/settings.json` всеки път, когато синхронизацията на моделите на доставчик
промени актуалния каталог — така новите или преименуваните модели получават профили, без да се изпълнява повторно
командата. Функцията е **изключена по подразбиране**: включете я от **таблото CLI Code** („Автоматична
синхронизация на CLI профили“ → Claude Code) или задайте `OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true` (взема предвид и
`CLI_ALLOW_CONFIG_WRITES`, което е включено по подразбиране). Когато е активирана, тя записва само файлове на профили; никога не
променя вашата активна/стандартна конфигурация на Claude, данните за удостоверяване или `~/.claude/settings.json`.

### Генериране и използване на профили

```bash
# Локален OmniRoute
omniroute setup-claude

# Отдалечен VPS (вгражда URL адреса на VPS във всеки профил)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# Само някои доставчици
omniroute setup-claude --only glm,kimi

# Преглед без записване
omniroute setup-claude --dry-run

# Стартиране на профил
omniroute launch --profile kimi-k27
```

## Нива на моделите (по избор)

Claude Code насочва заявките към нива според възможностите. Съпоставете всяко от тях с модел на OmniRoute чрез променливи на средата /
настройки, ако искате различни доставчици за всяко ниво:

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm/glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="kmc/kimi-k2.6"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="glm/glm-4.7-flash"
```

В противен случай за всичко се използва една променлива `ANTHROPIC_MODEL` (задавана от профилите).

## Отдалечен режим

След като изпълните `omniroute connect <host>` (вижте
[Отдалечен режим](./REMOTE-MODE.md)), `omniroute launch` и `omniroute setup-claude`
автоматично се насочват към този отдалечен сървър и използват неговия токен за достъп с ограничен обхват — не са
необходими допълнителни флагове. Можете да замените настройките за отделно извикване с `--remote` / `--api-key`.

## Отстраняване на проблеми

**Claude Code игнорира шлюза** — потвърдете, че `ANTHROPIC_BASE_URL` **не съдържа
`/v1`**, и рестартирайте `claude` (променливите на средата се прочитат еднократно при стартиране). `omniroute launch`
прави това вместо вас.

**Селекторът `/model` е празен / моделите на шлюза липсват** — необходими са Claude Code
v2.1.219+ и `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`. В селектора се показват само идентификатори на модели `claude*` /
`anthropic*`; задайте принудително друг модел чрез
`ANTHROPIC_MODEL=<id>` (точно това правят профилите).

**`400 Ambiguous model 'claude-…'`** — Claude Code винаги изпраща **идентификатори на модели без префикс**
(напр. `claude-opus-4-8`), така че когато са свързани едновременно доставчиците Claude Code (`cc/…`) и
Claude (`claude/…`), идентификаторът без префикс съответства на два маршрута и
OmniRoute отказва да избере вместо вас. Коригирайте това по един от следните начини: задайте идентификатор с префикс чрез
`ANTHROPIC_MODEL=cc/claude-opus-4-8` или активирайте **Предпочитане на Claude Code за
модели на Claude без префикс** — чрез превключвателя на страницата на доставчика Claude или
`OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true` (по подразбиране е изключено;
вижте [Среда](../reference/ENVIRONMENT.md)) — което насочва идентификаторите `claude-*` без префикс
към Claude Code. Изрично зададените префикси на доставчици винаги са с предимство.

**Грешки при удостоверяване** — профилът не съдържа токен. Използвайте `omniroute launch --profile`
(вмъква го) или експортирайте `ANTHROPIC_AUTH_TOKEN`.

**Профилите не са изолирани** — всеки профил използва отделна `CLAUDE_CONFIG_DIR`;
проверете дали `echo $CLAUDE_CONFIG_DIR` в рамките на сесията сочи към
`~/.claude/profiles/<name>`.
