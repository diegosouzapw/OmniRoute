**OmniCopilot** добавя всеки модел, обслужван от вашия OmniRoute, в _вградения_ инструмент за избор на модели на GitHub Copilot Chat.
Без втора странична лента и без отделен интерфейс за чат — агентният режим на Copilot, извикването на инструменти,
MCP сървърите и персонализираните инструкции продължават да работят, просто използвайки избрания от вас модел.

| **Инсталиране (разклонения)** | [Open VSX](https://open-vsx.org/extension/diegosouzapw/omnicopilot) — Cursor, Windsurf, VSCodium, Theia, code-server, Gitpod, Antigravity, Kiro |
| **Изходен код / проблеми**    | [github.com/diegosouzapw/OmniCopilot](https://github.com/diegosouzapw/OmniCopilot) (MIT)                                                        |

> **Не е необходим абонамент за Copilot.** От VS Code 1.122 нататък доставчикът на езиков модел работи
> без влизане в GitHub и без какъвто и да е план за Copilot. Вградените допълвания и
> функциите, базирани на векторни представяния, остават извън API на доставчика и все още изискват Copilot.

## Настройване

1. **Стартирайте OmniRoute** — `npm install -g omniroute && omniroute` (таблото е на `http://localhost:20128`).
2. **Инсталирайте разширението** — потърсете „OmniRoute“ в изгледа Extensions.
3. **Изберете модел** — Copilot Chat → инструмент за избор на модел → **Manage Models…** → **OmniRoute**, след което отметнете
   желаните модели.

Не е необходимо да конфигурирате нищо, когато OmniRoute работи на порта по подразбиране. За отдалечен екземпляр отворете
**иконата на OmniRoute в Activity Bar** (или изпълнете `OmniRoute: Manage Connection`) и задайте:

- **URL на сървъра** — кореновият адрес на сървъра, напр. `http://192.168.0.15:20128`. Суфиксът `/v1` се
  добавя от разширението; не го включвайте.
- **API ключ** — само когато сървърът задава `REQUIRE_API_KEY`. Съхранява се в хранилището за ключове на операционната система чрез VS
  Code SecretStorage, никога в `settings.json`.

## Какво ще показва инструментът за избор

Разширението не показва необработения отговор от `GET /v1/models` — то го преобразува и броят, който
виждате, е по-малък от размера на каталога поради две умишлено избрани причини.

### Заявява по един id за всеки модел

Стойността по подразбиране на `MODELS_CATALOG_PREFIX_MODE` е **`dual`**, което представя всеки модел два пъти — веднъж
с префикса на краткия псевдоним и веднъж с каноничния префикс на доставчика — така че по-старите клиентски
конфигурации да продължат да разпознават и двете форми:

```
cc/claude-sonnet-4-6        ← префикс на псевдонима
claude/claude-sonnet-4-6    ← каноничен префикс, същият модел
```

Разширението заявява **`GET /v1/models?prefix=alias`**, така че за всеки модел да се получава по един id, без
да се променя общата настройка на сървъра за останалите ви клиенти. При референтен екземпляр това намали
**2345 записа до 1396 — 949 дубликата, без загубен нито един модел.**

Ако предпочитате да коригирате това на ниво сървър за _всеки_ клиент, задайте флага за функционалност
`MODELS_CATALOG_PREFIX_MODE` на `alias` в таблото. Вижте
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) за
параметъра на заявката и таблицата за отделните режими.

### Скрива моделите, които не поддържат чат

Каталогът също съдържа модели за изображения, видео, аудио, пренареждане, векторни представяния и модериране. Те
така или иначе се отхвърлят при заявка за чат:

```
HTTP 400 — Model '<id>' is an image-generation model and cannot be used on
/v1/chat/completions. Use POST /v1/images/generations instead.
```

затова се филтрират според полето си `type`, преди да достигнат до инструмента за избор. **Моделите за Responses API
се запазват** — всеки запис за Codex / GPT-5.x обявява `supported_endpoints: ["responses"]`,
а OmniRoute ги преобразува за `/v1/chat/completions`, така че те са напълно използваеми.

### Доставчици, които никога не сте конфигурирали

Каталогът изброява модели от доставчици с **активна връзка**, както и всички доставчици с **noAuth** —
тези без ключ, които съставляват голяма част от безплатното ниво. Това е умишлено. За да ги скриете,
добавете ги към `blockedProviders` в настройките на таблото; нищо в разширението не се променя.

## Табло за управление в раздел на VS Code

`omnicopilot.dashboardOpen: "editor"` визуализира таблото за управление на OmniRoute в раздел на редактора чрез
Simple Browser вместо във външен браузър. Вграждането се **активира изрично на сървъра** чрез
`DASHBOARD_ALLOW_EMBED=vscode`, което предоставя HTML страниците с
`frame-ancestors 'self' vscode-webview:` вместо стандартните `frame-ancestors 'none'` +
`X-Frame-Options: DENY`. API интерфейсът (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) запазва
строгите заглавки и в двата случая.

> ⚠️ **Това е флаг за времето на компилиране, а не за времето на изпълнение.** Next.js компилира `headers()` в манифеста
> на маршрутите, така че `next.config.mjs` прочита променливата, докато пакетът се компилира
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> Експортирането ѝ пред вече компилиран сървър не променя нищо — заглавките са вградени.

```bash
# променливата трябва да присъства в командата за КОМПИЛИРАНЕ
DASHBOARD_ALLOW_EMBED=vscode npm run build        # или npm run build:release
npm start
```

| Начин на инсталиране       | Можете ли да активирате вграждането?                                                                                                                   |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| От изходния код            | ✅ задайте променливата в командата за компилиране, както е показано по-горе                                                                           |
| `npm install -g omniroute` | ❌ публикуваният пакет се доставя с предварително компилиран пакет — вместо това компилирайте от изходния код                                          |
| Docker образ               | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — предварително компилираният образ в Docker Hub не поддържа вграждане |

Без компилация с активирано вграждане страницата отказва да бъде показана в рамка, разширението открива това от
заглавките на отговора и се връща към външния браузър — нищо не се поврежда и то уведомява за това веднъж.
Вижте [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) и проблем
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273).

## Конфигуриране на другите ви инструменти от VS Code

**`OmniRoute: Configure Coding CLI`** използва CLI инструмента `omniroute`, за да създаде готови за употреба профили
за Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code,
Kilo и Roo — същите конфигурации, описани в
[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md). API ключът се предава на CLI инструмента чрез променливата на средата
`OMNIROUTE_API_KEY`, никога чрез командния ред.

## Отстраняване на неизправности

| Симптом                                                     | Причина / решение                                                                                                                                                                                                                                                                                              |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Няма модели на OmniRoute в списъка за избор                 | Сървърът е недостъпен. Точката в лентата на състоянието става сива; изпълнете `OmniRoute: Check Connection`. Откриването е безшумно по замисъл и не добавя модели, вместо да показва подкана.                                                                                                                  |
| Всеки модел се показва два пъти                             | Използвате версия на OmniCopilot, по-стара от 1.0.1 — актуализирайте. Разширението вече заявява `?prefix=alias`.                                                                                                                                                                                               |
| Модел за изображения/аудио е бил в списъка, но вече го няма | Това е умишлено от версия 1.0.1 насам — той никога не е можел да отговори на заявка в чат.                                                                                                                                                                                                                     |
| Панелът липсва от лентата за дейности                       | VS Code премества допълнителните контейнери за изгледи в менюто **„…“** в долната част на лентата за дейности, а контейнер, скрит чрез щракване с десния бутон, остава скрит. Щракнете с десния бутон върху лентата за дейности → отметнете **OmniRoute** или го отворете чрез `OmniRoute: Manage Connection`. |
| Таблото се отваря в браузъра въпреки режим `editor`         | Сървърът не е бил **компилиран** с `DASHBOARD_ALLOW_EMBED=vscode` (вижте по-горе) — задаването му при стартиране на предварително компилирана инсталация не променя нищо. Връщането към браузъра е умишлено.                                                                                                   |
| Списъкът с модели е остарял след промяна на доставчиците    | Изпълнете `OmniRoute: Refresh Models` или използвайте връзката ↻ в панела.                                                                                                                                                                                                                                     |
