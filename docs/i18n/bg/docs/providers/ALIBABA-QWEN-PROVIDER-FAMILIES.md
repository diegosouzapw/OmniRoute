Този документ описва решението за имплементация по
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854). Публичните продукти са
представени като четири семейства доставчици. Регионът е част от данните за връзката, а не отделен продукт.

## Решение

| Семейство доставчици                                      | OmniRoute ID            | Глобален регион | Регион Китай |
| --------------------------------------------------------- | ----------------------- | --------------- | ------------ |
| Alibaba Cloud Model Studio (плащане според потреблението) | `alibaba`               | Сингапур        | Пекин        |
| Alibaba Cloud Token Plan                                  | `bailian-coding-plan`   | Сингапур        | Пекин        |
| Qwen Cloud (плащане според потреблението)                 | `qwen-cloud`            | Глобален        | Пекин        |
| Qwen Cloud Token Plan                                     | `qwen-cloud-token-plan` | Сингапур        | Пекин        |

Съществуващият ID `alibaba-cn` остава псевдоним за съвместимост по време на изпълнение за запазени връзки, маршрути
към модели, комбинации и исторически данни за използването. Неговата карта в таблото за управление е обединена с `alibaba`; не се
изисква пренаписване на базата данни.

В момента Qwen Cloud с плащане според потреблението и Alibaba Cloud Model Studio споделят съвместимите с DashScope
хостове за изпълнение, но остават отделни идентичности на доставчици, тъй като потребителите получават ключове и управляват
акаунти чрез различни продуктови интерфейси. Продуктите Alibaba и Qwen Cloud Token Plan използват
различни семейства крайни точки, поради което и четирите продукта остават с отделни ID на доставчици.

## Матрица на крайните точки

| Семейство доставчици    | `global-sg`                                                              | `china-beijing`                                                      | Формат по мрежата |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ----------------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI            |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic         |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI            |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI            |

API ключът и крайната точка трябва да принадлежат към един и същ продукт и регион. Избирането на регион променя
предварително зададената крайна точка, използвана при валидиране и обичайни заявки.

## Договор за връзката

Новите връзки съхраняват стабилния ключ на региона в `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

Допустимите стойности са `global-sg` и `china-beijing`. Крайната точка се извежда централизирано от
ID на доставчика и региона. Стойност на `providerSpecificData.baseUrl`, която не е предварително зададена, остава изрично
заместване от оператора и има предимство, докато старите запазени URL адреси на предварително зададени крайни точки се нормализират обратно към регионалната
матрица.

Това запазва разширяемостта на схемата за връзки: към механизма за определяне може да бъде добавен друг регион, без
да се създава друга карта на доставчик или да се променят запазените ID на доставчици.

## Съвместимост и внедряване

1. Добавете механизма за определяне на регионалната крайна точка и запазете текущите глобални настройки по подразбиране.
2. Използвайте динамично регионално откриване чрез DashScope `/models` за `alibaba`, неговия идентификатор за съвместимост `alibaba-cn` и `qwen-cloud`. Техните отговори първо преминават през филтър за модели за генериране на текст, тъй като общата крайна точка връща също модели за изображения, видео, аудио, вграждания и други модели, които не са предназначени за чат. След това `qwen-cloud` прилага поддържания списък с разрешени модели, деклариран в регистъра на доставчика. Alibaba Model Studio и Qwen Cloud поддържат отделни курирани каталози, въпреки че в момента използват едни и същи хостове по време на изпълнение.
3. Регистрирайте `qwen-cloud-token-plan` с текущия списък с разрешени текстови модели за Token Plan.
4. Добавете типизиран селектор за регион към диалоговите прозорци за добавяне/редактиране на връзка.
5. Скрийте дублиращата се карта `alibaba-cn` и включете съществуващите ѝ връзки в страницата на доставчика `alibaba`.
6. Запазете възможността за персонализирано заместване на крайните точки за разширени внедрявания и внедрявания, специфични за работното пространство.

Мултимедийните модели на Token Plan остават извън каталога за чат, защото използват специализирани крайни точки.
`wan2.7-image` и `wan2.7-image-pro` са регистрирани в `open-sse/config/imageRegistry.ts`;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` и `happyhorse-1.1-r2v` са регистрирани в
`open-sse/config/videoRegistry.ts`. И двата регистъра използват повторно идентичността на връзката `qwen-cloud-token-plan`
и нейните специфични за региона идентификационни данни.

Стандартният Qwen Cloud има отделни каталози за изображения и видео с разплащане според потреблението под идентичността `qwen-cloud`.
Неговите модели за изображения са `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` и `z-image-turbo`. Неговите видео
модели са `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` и
`wan2.7-videoedit`. Тези модели използват повторно само стандартната връзка `qwen-cloud` и регионалната
мултимедийна крайна точка на DashScope. Регистрите за Token Plan и за разплащане според потреблението не наследяват и не обединяват
списъците си с модели един с друг.

Идентичността `bailian-coding-plan` също има собствени списъци с разрешени мултимедийни модели:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` и `qwen-image-2.0-pro` за генериране на
изображения, както и
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` и `happyhorse-1.1-r2v` за генериране на
видео. Тя използва само връзката за Bailian Coding Plan и регионалната крайна точка на Coding Plan.
Нейните регистри за изображения и видео не наследяват и не се обединяват с никой от доставчиците на Qwen Cloud.

Стандартната идентичност `alibaba` има отделни списъци с разрешени модели за изображения и видео. Нейните модели за изображения са
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` и `wan2.6-t2i`. Добавените ѝ видео модели са `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` и `wan2.7-videoedit`. Тези модели използват само връзката към Alibaba Model Studio
и избраната за нея регионална мултимедийна крайна точка; те не се добавят към никой регистър на Coding Plan или Qwen
Cloud.

Каталогът за чат на Qwen Cloud Token Plan следва списъка с разрешени текстови модели чрез точно съвпадение на низове за плана Individual:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` и
`deepseek-v4-pro`. Записите за Wan и HappyHorse принадлежат към отделните API за генериране на изображения/видео.

Alibaba Token Plan предоставя същите шест текущи идентификатора на модели за генериране на текст чрез своята
крайна точка, съвместима с Anthropic. Опцията за Сингапур съхранява съществуващия ключ за регион `global-sg`;
само видимият за потребителя етикет се различава от семействата доставчици, които наричат региона „Глобален“.

Стандартният каталог за чат на Qwen Cloud умишлено е по-ограничен от пълния динамичен отговор за текстови модели. Неговият
поддържан списък с разрешени модели се намира в `open-sse/config/providers/registry/qwen-cloud/index.ts`; динамичното
откриване връща само идентификатори, които присъстват едновременно в отговора от доставчика и в този списък на регистъра.

Alibaba Model Studio следва същото правило за динамично пресичане със своя независимо поддържан
списък с разрешени модели в `open-sse/config/providers/registry/alibaba/index.ts`. Доставчикът за съвместимост `alibaba-cn`
използва повторно този каталог, като извършва откриването чрез крайната точка в Пекин.
