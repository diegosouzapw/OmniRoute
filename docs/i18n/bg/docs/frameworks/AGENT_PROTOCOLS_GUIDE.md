> **Източник:** `src/lib/{a2a,acp,cloudAgent}/`, `src/app/api/{a2a,acp,cloud}/`, `src/app/api/v1/agents/`
> **Последна актуализация:** 2026-06-28 — v3.8.40

OmniRoute предоставя три различни интерфейса, свързани с агенти. На пръв поглед те изглеждат сходни, но решават различни проблеми. Използвайте тази страница, за да изберете правилния.

## Накратко

| Интерфейс                        | Най-подходящ за                                                                                                                                                  | Транспорт                            | Стандарт                         |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ | -------------------------------- |
| **A2A — агент към агент**        | Сътрудничество между агенти с партньорски агенти, които поддържат протокола A2A                                                                                  | JSON-RPC 2.0 през HTTP               | A2A v0.3 (отворена спецификация) |
| **ACP — регистър на CLI агенти** | Откриване / регистриране / стартиране на CLI агенти за програмиране, инсталирани на машината на потребителя (Cursor, Cline, Codex CLI, Claude Code, Aider и др.) | HTTP REST                            | Специфичен за OmniRoute          |
| **Облачни агенти**               | Подаване на дългосрочни задачи за програмиране към външни облачни услуги (Codex Cloud, Devin, Jules, Cursor Cloud)                                               | HTTP REST + задачи, съхранявани в БД | Специфичен за OmniRoute          |

Трите са независими — изберете произволна комбинация от тях.

## Дърво за вземане на решения

```
Нуждаете ли се от облачна услуга, която да извършва работа извън тази машина (Codex Cloud / Cursor Cloud / Devin / Jules)?
├─ ДА → Облачни агенти (POST /api/v1/agents/tasks)
└─ НЕ → Продължете
    │
    Имате ли партньорски агент, който поддържа A2A и иска да си сътрудничи?
    ├─ ДА → A2A (POST /a2a)
    └─ НЕ → Продължете
        │
        Трябва ли да изброите / конфигурирате CLI агенти за програмиране, инсталирани локално?
        ├─ ДА → ACP (GET /api/acp/agents)
        └─ НЕ → Използвайте директно /v1/chat/completions
```

## 1. A2A — агент към агент

**Спецификация:** [A2A v0.3](https://a2a-protocol.org)
**Крайна точка на OmniRoute:** `POST /a2a` (JSON-RPC 2.0)
**Карта на агента:** `GET /.well-known/agent.json`

### Кога да се използва

- Изграждане на система с множество агенти, в която OmniRoute е един от равнопоставените участници
- Предоставяне на маршрутизиращите възможности на OmniRoute (интелигентно маршрутизиране, управление на квоти и др.) на агенти в среди като Google ADK или общи мрежи от агенти
- Обвиване на OmniRoute със стандартен интерфейс за откриване и извикване

### Методи

- `message/send` — подаване на съобщение и получаване на синхронен отговор
- `message/stream` — подаване и получаване на поточно предавани чрез SSE събития за напредъка
- `tasks/get` — прочитане на задача по ID
- `tasks/cancel` — отмяна на изпълняваща се задача

### Вградени умения (6)

- `smart-routing` — маршрутизиране на подкана чрез оптималната комбинация
- `quota-management` — отчитане на състоянието на квотата за всеки доставчик
- `provider-discovery` — изброяване на инсталираните доставчици и техните възможности
- `cost-analysis` — оценяване на стойността на заявка/разговор
- `health-report` — обобщаване на състоянието на прекъсвачите, периодите на изчакване и блокиранията за всеки доставчик
- `list-capabilities` — изброяване на наличните умения и метаданни на агента

### Подробности

Вижте [A2A-SERVER.md](./A2A-SERVER.md) за подробности относно транспорта, структурата на картата на агента, конфигурацията на TTL на задачите и шаблона за добавяне на нови умения.

## 2. ACP — Регистър на CLI агенти

**OmniRoute крайна точка:** `GET /api/acp/agents`
**Изходен код:** `src/lib/acp/{index,manager,registry}.ts`

### Какво представлява

ACP е **локалният регистър на CLI агенти** на OmniRoute. Той открива кои CLI инструменти за програмиране са инсталирани на хоста (Cursor, Cline, Claude Code, Codex CLI, Continue и др.), определя версиите им и ги показва в таблото за управление, така че потребителят да може да конфигурира всеки CLI да използва OmniRoute.

Това НЕ е външен протокол — това е вътрешен регистър, който обслужва потребителския интерфейс „CLI Tools“ и проследяването на CLI отпечатъци (вижте [CLI-TOOLS.md](../reference/CLI-TOOLS.md)).

### Какво прави

- Проверява хоста за инсталирани CLI изпълними файлове (използва `which` / `where` според ОС)
- Прочита версията на всеки CLI (извиква `<bin> --version`)
- По желание приема дефинирани от потребителя персонализирани агенти (път до изпълним файл + проверка на версията + аргументи за стартиране)
- Запазва персонализираните агенти в настройките
- Връща обединения списък към таблото за управление

### REST API

| Крайна точка      | Метод | Описание                                                              | Удостоверяване |
| ----------------- | ----- | --------------------------------------------------------------------- | -------------- |
| `/api/acp/agents` | GET   | Изброява откритите + персонализираните агенти (брой инсталирани/общо) | API ключ       |
| `/api/acp/agents` | POST  | Добавя/актуализира/премахва персонализиран агент (действие в тялото)  | API ключ       |

Структура на тялото за POST (`customAgentBodySchema` в `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Случаи на употреба

- Страницата „CLI Tools“ в таблото за управление показва какво е инсталирано и ви помага да насочите всеки инструмент към OmniRoute
- Персонализираните агенти позволяват на напредналите потребители да регистрират вътрешни/собствени CLI инструменти, които OmniRoute не разпознава по подразбиране
- Резултатът от откриването захранва матрицата с отпечатъци `cli-tools`

### Кога да НЕ използвате ACP

- ACP не _изпълнява_ задачи. Той само открива + конфигурира CLI инструменти. За да извикате действително CLI, трябва да го стартирате сами с променливите на средата, предоставени от OmniRoute (`OPENAI_BASE_URL`, `OPENAI_API_KEY` и др.).

## 3. Облачни агенти

**OmniRoute крайни точки:** `/api/v1/agents/tasks/*` (жизнен цикъл) + `/api/cloud/*` (инфраструктура)
**Изходен код:** `src/lib/cloudAgent/`

### Какво представлява

Унифициран интерфейс към облачни агенти за програмиране от трети страни. Подавате подкана + URL адрес на хранилище, OmniRoute я изпраща към правилния облачен агент, проверява периодично състоянието и връща резултатите.

### Поддържани агенти (4, всички потвърдени в `src/lib/cloudAgent/agents/`)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### Жизнен цикъл

```
POST /api/v1/agents/tasks
  → BaseAgent.createTask() за съответния клас на агента
  → външната услуга започва работа
  → в БД се създава запис за задачата (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → отложено синхронизиране на състоянието от доставчика
  → връща текущото състояние + план + дневник на активността
  ↓
POST /api/v1/agents/tasks/[id]   (действие: "approve" | "message" | "cancel")
  → препраща към доставчика (или маркира като отменена локално)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → локално отменяне
```

### Удостоверяване

⚠️ **Всички крайни точки `/api/v1/agents/tasks/*` изискват административно удостоверяване** (комит `588a0333`). Заявките само с Bearer получават 401 от v3.8.0 насам.

### Подробен преглед

Вижте [CLOUD_AGENT.md](./CLOUD_AGENT.md) за договора `CloudAgentBase`, специфичните особености на всеки агент, подробностите за схемата и крайните точки за управление на идентификационните данни.

## Сравнение: A2A спрямо Cloud Agents

И двете поддържат „дълго изпълняващи се задачи“, но на различни нива:

| Аспект                         | A2A                                                                                                  | Cloud Agents                                              |
| ------------------------------ | ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| Стандарт                       | Отворен A2A v0.3                                                                                     | Специфичен за OmniRoute                                   |
| Къде се извършват изчисленията | В OmniRoute (използва конфигурираните комбинации)                                                    | Външно (сървъри на Codex / Devin / Jules)                 |
| Продължителност на задачата    | TTL по подразбиране 5 мин (конфигурируемо в `TaskManager`)                                           | От минути до часове                                       |
| Отчита хранилището             | Не (предава само подкани)                                                                            | Да (URL на хранилището + клон)                            |
| Случай на употреба             | Сътрудничество между агенти, интелигентно маршрутизиране като услуга                                 | Делегиране на „реализирай функционалност X в хранилище Y“ |
| Удостоверяване                 | Незадължителен `OMNIROUTE_API_KEY` за `/a2a`; административно за REST помощните ресурси `/api/a2a/*` | Винаги административно                                    |

## Примери за интеграция

### Откриване на A2A възможностите на OmniRoute

```bash
curl http://localhost:20128/.well-known/agent.json
```

Връща картата на агента с всичките 6 умения, транспортни механизми и версията.

### Извикване на OmniRoute като A2A агент

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### Извеждане на инсталираните CLI агенти чрез ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Добавяне на персонализиран CLI агент

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### Подаване на задача към Cloud Agent

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### Периодична проверка на състоянието на облачната задача

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## Кога какво да използвате

- **Потребителски интерфейс за чатбот / copilot** → `/v1/chat/completions` (съвместим с OpenAI — не е протокол за агенти)
- **Сътрудничество между множество агенти** → A2A
- **Показване на локалните CLI инструменти в таблото за управление** → ACP
- **Делегиране на дълго изпълняващи се задачи за програмиране към облачни услуги** → Cloud Agents

```

        ┌─────────┘       │        └─────────┐

    ┌───────┐        ┌─────────┐       ┌────────────┐

```
