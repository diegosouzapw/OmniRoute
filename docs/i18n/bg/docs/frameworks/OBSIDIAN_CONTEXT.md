> **Източник на истина:** `src/lib/obsidian/api.ts` (REST + клиент за синхронизация),
> `src/lib/db/obsidian.ts` (съхранение на токен / базов URL / WebDAV),
> `src/lib/obsidianSync.ts` (WebDAV синхронизация на хранилището), `open-sse/mcp-server/tools/obsidianTools.ts`
> (22 MCP инструмента), `src/app/api/settings/obsidian/route.ts` +
> `src/app/api/settings/obsidian/webdav/route.ts` (API за настройки). Регистрирането на
> инструментите и свързването на обхватите се намират в `open-sse/mcp-server/server.ts`.

## Какво представлява

OmniRoute се свързва с хранилище на **Obsidian** като **източник на контекст** — локална
база от знания в Markdown, която агентите четат и променят чрез вградения MCP сървър.
Интеграцията комуникира с общностната добавка **Obsidian Local REST API**, работеща в
настолното приложение, така че агентите могат да търсят бележки, да четат/записват/актуализират
файлове, да извеждат съдържанието на хранилището, да работят с ежедневни/седмични периодични
бележки, да управляват етикети, да изпълняват команди на Obsidian и (по избор) да
координират двупосочна синхронизация на хранилището между настолно и мобилно устройство.

Клиентът (`src/lib/obsidian/api.ts`) обвива Local REST API със:

- **Повторни опити с изчакване** при временни грешки `5xx`, **30-секундно прекъсване**
  чрез `AbortController`.
- **Типизирано класифициране на грешките** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- **Разбираемо указание „Obsidian не може да бъде достигнат“**, което посочва често срещаната
  грешка с порта (HTTP на `27123`, **а не** MCP крайната точка на `27124`) и формата за Tailscale.
- **Кодиране на пътищата** спрямо хранилището, така че пътищата до бележки с интервали/наклонени
  черти да бъдат безопасни.

## Настройване

Няма **променлива на средата** за токена или базовия URL адрес на Obsidian — и двете се
съхраняват в SQLite таблицата `key_value` (пространство от имена `obsidian`) чрез
`src/lib/db/obsidian.ts`. Токенът е **шифрован при съхранение** (AES-256-GCM, с резервна
обратна съвместимост за нешифрован текст). Конфигурирайте от раздела **Източници на контекст**
на таблото за управление на крайната точка (`ObsidianSourceCard`) или чрез REST API за настройки.

> [!IMPORTANT]
> Добавката **Obsidian Local REST API** трябва да бъде инсталирана и стартирана. Нейният REST
> интерфейс слуша на **HTTP `127.0.0.1:27123`** (базовият URL по подразбиране). Порт `27124`
> е _отделна_ MCP/HTTPS крайна точка и изрично се отхвърля от маршрута за настройки.
> При свързване от друго устройство използвайте `http://<tailscale-ip>:27123`.

### Конфигурационни ключове (SQLite `key_value`, пространство от имена `obsidian`)

| Ключ              | Предназначение                                                        | Шифрован |
| ----------------- | --------------------------------------------------------------------- | -------- |
| `api_key`         | Bearer токен за Local REST API                                        | да       |
| `base_url`        | Базов REST URL (по подразбиране `http://127.0.0.1:27123`)             | не       |
| `vault_path`      | Абсолютен път до директорията на хранилището (за синхронизация)       | не       |
| `webdav_username` | Генерирано потребителско име за WebDAV (синхронизация на хранилището) | не       |
| `webdav_password` | Генерирана парола за WebDAV (синхронизация на хранилището)            | да       |
| `webdav_enabled`  | Дали WebDAV синхронизацията на хранилището е активирана               | не       |

### Конфигуриране чрез REST

```bash
# Запазване + валидиране на токена за Local REST API (POST валидира чрез проверка на състоянието)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Проверка на състоянието на връзката (връща connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# Прекъсване на връзката (изтрива съхранения токен)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Всички методи изискват удостоверяване в таблото за управление. `POST` отхвърля всеки URL
на порт `27124` и валидира токена чрез извикване на крайната точка за състоянието на
Local REST API, преди да го съхрани.

### WebDAV синхронизация на хранилището

`src/app/api/settings/obsidian/webdav/route.ts` управлява незадължителна, базирана на WebDAV
синхронизация на хранилището (задвижвана от `src/lib/obsidianSync.ts`). Активирането ѝ
насочва OmniRoute към локална директория на хранилище и генерира произволна двойка
потребителско име/парола за WebDAV:

```bash
# Активиране на WebDAV синхронизацията за директория на хранилище (генерира потребителско име/парола)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# Получаване на състоянието на WebDAV синхронизацията (идентификационните данни се връщат само докато е активирана)
curl http://localhost:20128/api/settings/obsidian/webdav

# Деактивиране на WebDAV синхронизацията (изтрива идентификационните данни + управлявания .stignore)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Източник на контекст за отделен API ключ (по избор)

Конфигурацията на Obsidian може да бъде ограничена **за отделен API ключ** чрез таблицата
`api_key_context_sources` (`src/lib/db/apiKeyContextSources.ts`). Когато MCP извикване
съдържа идентификатор на удостоверен API ключ, `getObsidianConfigForApiKey()` предпочита
собствения токен/базов URL/път до хранилището на този ключ (`source: "api_key"`), а в
противен случай използва глобалната конфигурация (`source: "global"`).

## MCP инструменти (22)

Дефинирани в `open-sse/mcp-server/tools/obsidianTools.ts`. Токенът/базовият URL адрес се определят
при всяко извикване (първо за конкретния API ключ, след това глобално). Инструментите, които използват **сървъра за синхронизация** на OmniRoute
(четирите инструмента `obsidian_sync_*`), допълнително изискват токена за удостоверяване при синхронизация, конфигуриран
в настройките на OmniRoute.

### Инструменти за четене (`read:obsidian`)

| Инструмент                   | Описание                                                                                                                      |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Проверява дали Local REST API е достъпен и удостоверен.                                                                       |
| `obsidian_search_simple`     | Пълнотекстово търсене в съдържанието на бележките; връща откъси с пътища до файловете.                                        |
| `obsidian_search_structured` | Търсене чрез JSON Logic израз (филтри and/or/regex/path).                                                                     |
| `obsidian_read_note`         | Прочита бележка по път спрямо трезора; по избор — конкретно заглавие/блок/frontmatter.                                        |
| `obsidian_list_vault`        | Изброява файловете и директориите в трезора (дърво от записи).                                                                |
| `obsidian_get_document_map`  | Получава структурата на заглавията в бележката като съответствие заглавия → номера на редове.                                 |
| `obsidian_get_note_metadata` | Получава frontmatter, тагове, връзки и брой знаци/думи без пълното съдържание.                                                |
| `obsidian_get_active_file`   | Получава пътя и съдържанието на текущо активния файл в Obsidian.                                                              |
| `obsidian_get_periodic_note` | Получава дневната/седмичната/месечната периодична бележка за дадена дата (днес, ако е пропусната).                            |
| `obsidian_get_tags`          | Изброява всички тагове в трезора и честотата им.                                                                              |
| `obsidian_list_commands`     | Изброява наличните идентификатори на команди в Obsidian (използва се с `obsidian_execute_command`).                           |
| `obsidian_sync_status`       | Състояние на сървъра за синхронизация на OmniRoute: работи ли, име на трезора, порт, време на работа, последна синхронизация. |
| `obsidian_sync_conflicts`    | Изброява неразрешените конфликти при синхронизация (път, път до конфликта, момент на откриване).                              |

### Инструменти за запис (`write:obsidian`)

| Инструмент                       | Описание                                                                                                                  |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Създава или презаписва бележка с дадено Markdown съдържание.                                                              |
| `obsidian_append_note`           | Добавя съдържание към бележка; по избор — към конкретно заглавие/блок.                                                    |
| `obsidian_patch_note`            | Прецизно добавя след/преди или заменя съдържание при заглавие, блок или frontmatter поле.                                 |
| `obsidian_delete_note`           | Изтрива окончателно бележка от трезора.                                                                                   |
| `obsidian_move_note`             | Премества или преименува бележка в рамките на трезора.                                                                    |
| `obsidian_execute_command`       | Изпълнява команда на Obsidian чрез нейния идентификатор.                                                                  |
| `obsidian_open_file`             | Отваря файл в Obsidian (създава го, ако не съществува).                                                                   |
| `obsidian_sync_trigger`          | Задейства незабавна двупосочна синхронизация на трезора между настолен компютър и мобилно устройство.                     |
| `obsidian_sync_resolve_conflict` | Разрешава конфликт при синхронизация: запазва `local` (мобилно устройство), `remote` (настолен компютър) или `keep-both`. |

> [!NOTE]
> Целите на `obsidian_patch_note` приемат `targetType` със стойност `heading | block | frontmatter`
> и `operation` със стойност `append | prepend | replace`, с незадължителен
> `createTargetIfMissing`. Четирите инструмента `obsidian_sync_*` комуникират с локалния сървър за синхронизация
> (`http://127.0.0.1:27781` по подразбиране) и изискват токена за синхронизация.

### Обхвати

Инструментите за четене изискват `read:obsidian`; инструментите за запис изискват `write:obsidian`. Прилагането
е идентично с това при Notion — обработва се от `withScopeEnforcement()` в
`open-sse/mcp-server/server.ts`, активира се при `OMNIROUTE_MCP_ENFORCE_SCOPES=true`, като
разрешените обхвати се извличат от `OMNIROUTE_MCP_SCOPES` или от контекста на обхватите на API ключа. Вижте
[MCP-SERVER.md](./MCP-SERVER.md).

## Крайни точки

| Метод    | Път                             | Предназначение                                                                       |
| -------- | ------------------------------- | ------------------------------------------------------------------------------------ |
| `GET`    | `/api/settings/obsidian`        | Връща `{ connected, hasToken, baseUrl, vaultPath }`.                                 |
| `POST`   | `/api/settings/obsidian`        | Запазва и валидира токена (отхвърля порт `27124`).                                   |
| `DELETE` | `/api/settings/obsidian`        | Прекъсва връзката (изчиства съхранения токен).                                       |
| `GET`    | `/api/settings/obsidian/webdav` | Състояние на WebDAV синхронизирането и идентификационни данни (докато е активирано). |
| `POST`   | `/api/settings/obsidian/webdav` | Активира WebDAV синхронизиране за директория на хранилище.                           |
| `DELETE` | `/api/settings/obsidian/webdav` | Деактивира WebDAV синхронизирането.                                                  |

> Това са маршрути за настройки на таблото за управление. Самото хранилище е достъпно чрез Obsidian
> Local REST API (конфигурирания `base_url`) и чрез MCP инструментите по-горе — няма
> публична Obsidian прокси крайна точка `/v1`.

## Случаи на употреба

- **Отговори, базирани на хранилището** — `obsidian_search_simple` / `obsidian_search_structured`,
  следвани от `obsidian_read_note`, така че агентът да отговаря въз основа на действителните ви бележки.
- **Създаване на бележки / водене на дневник** — `obsidian_write_note`, `obsidian_append_note` или
  прецизният `obsidian_patch_note` за записване на изходни данни от агента, обобщения или ежедневни бележки
  (`obsidian_get_periodic_note`) в хранилището.
- **Навигация в хранилището** — `obsidian_list_vault`, `obsidian_get_document_map` и
  `obsidian_get_tags` за проучване на структурата преди четене/писане.
- **Автоматизация на Obsidian** — `obsidian_list_commands` + `obsidian_execute_command` за
  управление на приставки/команди чрез агент; `obsidian_open_file` за показване на бележка в потребителския интерфейс.
- **Мобилно синхронизиране** — активирайте WebDAV синхронизирането, след което използвайте `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`,
  за да координирате настолен компютър↔мобилно устройство и да разрешавате конфликти.
