> **Източник на истина:** `src/lib/gamification/`, `src/lib/db/gamification.ts`, `src/app/api/gamification/`
> **Последно актуализирано:** 2026-06-28 — v3.8.40

OmniRoute включва локално ориентиран слой за геймификация, който възнаграждава потребителите за
взаимодействието им с платформата — извършване на заявки, смяна на доставчици, създаване на
комбинации, споделяне на токени и принос към общността. Цялото състояние се съхранява в
SQLite; федерацията със сървъри на общността е по избор и се основава на изпращане на данни.

Системата е проектирана за **нулево забавяне по критичния път** — събитията за геймификация
се изпращат без изчакване от конвейера за заявки и никога не блокират
отговор от LLM.

---

## Общ преглед

### Предназначение

Повишаване на ангажираността и задържането на потребителите чрез видим напредък (XP,
нива, значки), социално доказателство (класации) и икономически стимули (споделяне на
токени, награди за покани).

### Обхват

| Функционалност       | Описание                                                                                       |
| -------------------- | ---------------------------------------------------------------------------------------------- |
| XP и нива            | Печелене на XP за действие; преминаване на нива по полиномиална крива                          |
| Значки               | Над 20 постижения в 5 категории с 4 нива на рядкост                                            |
| Серии                | Ежедневно проследяване на активността с текуща/най-дълга серия                                 |
| Класации             | Глобален, седмичен, месечен обхват, споделяне на токени и принос                               |
| Споделяне на токени  | Прехвърляне на кредити между потребители чрез счетоводна книга с двойно записване              |
| Покани и осребряване | Кодове за препоръки със съхранение на SHA-256 хешове                                           |
| Сървъри на общността | Федерация с външни инстанции на OmniRoute                                                      |
| Защита от измами     | Оценяване от страна на сървъра, ограничаване на честотата, откриване на аномалии чрез z-оценка |

### Принципи на проектиране

1. **Локално ориентирана архитектура** — цялото състояние е в SQLite; не са необходими външни услуги.
2. **Неблокираща работа** — събитията се изпращат без изчакване; пътят на отговора от LLM
   никога не се забавя от логиката за геймификация.
3. **Сървърът е водещ** — XP се изчислява единствено от страна на сървъра; клиентите не могат
   изкуствено да увеличават резултатите.
4. **Зачитане на поверителността** — участието в класациите е по избор; потребителите могат
   да скриват профила си.
5. **Готовност за федерация** — сървърите на общността могат да изпращат резултати чрез подписан API;
   синхронизирането презаписва стойностите, вместо да ги натрупва.

## Архитектура

### Поток на високо ниво

```
Клиентска заявка
  → /v1/chat/completions
    → handleChatCore()                      [open-sse/handlers/chatCore.ts]
      → ... (съществуващ конвейер) ...
      → отговорът от доставчика е изпратен до клиента
      → setImmediate (изпращане без изчакване):
        → emitGamificationEvent()           [src/lib/gamification/events.ts]
          → awardXp()                       [src/lib/gamification/xp.ts]
          → updateStreak()                  [src/lib/gamification/streaks.ts]
          → evaluateBadges()                [src/lib/gamification/badges.ts]
          → updateLeaderboard()             [src/lib/gamification/leaderboard.ts]
          → checkAnomalies()                [src/lib/gamification/antiCheat.ts]
```

Модулът за генериране на събития е единствената точка за интеграция. `chatCore.ts` извиква
`emitGamificationEvent()` след изпращането на отговора; модулът за събития разпределя
обработката към подсистемите за XP, серии, значки, класации и защита от измами.

### Граф на зависимостите между модулите


## Система за XP / нива

**Файл:** `src/lib/gamification/xp.ts`

### Крива на нивата

XP, необходим за достигане на ниво `n`, следва полиномиална крива:

```
xp_for_level(n) = floor(100 * n^1.5)
```

| Ниво | XP до следващото | Кумулативен XP | Титла        |
| ---- | ---------------- | -------------- | ------------ |
| 1    | 100              | 100            | Начинаещ     |
| 5    | 1,118            | 2,415          | Начинаещ     |
| 10   | 3,162            | 10,523         | Изследовател |
| 25   | 12,500           | 86,024         | Изследовател |
| 50   | 35,355           | 345,529        | Експерт      |
| 75   | 64,952           | 948,683        | Майстор      |
| 100  | 100,000          | 2,050,000      | Легенда      |

### Титли

| Диапазон от нива | Титла        |
| ---------------- | ------------ |
| 1 – 9            | Начинаещ     |
| 10 – 24          | Изследовател |
| 25 – 49          | Експерт      |
| 50 – 74          | Майстор      |
| 75 – 100         | Легенда      |

### XP награди

| Действие          | XP  | Описание                                                                  |
| ----------------- | --- | ------------------------------------------------------------------------- |
| `request`         | 1   | За всяка API заявка, маршрутизирана през OmniRoute                        |
| `provider_switch` | 5   | Превключване към друг доставчик                                           |
| `model_switch`    | 3   | Превключване към друг модел                                               |
| `combo_create`    | 10  | Създаване на нова комбинация                                              |
| `combo_use`       | 2   | Използване на комбинация за заявка                                        |
| `token_share`     | 1   | За всеки 1 000 токена, споделени с друг потребител                        |
| `invite_redeem`   | 50  | Осребряване на код за покана                                              |
| `daily_login`     | 5   | Ежедневно активно използване (веднъж дневно)                              |
| `streak_bonus`    | 2   | За всеки последователен ден от серията (умножено по дължината на серията) |
| `badge_unlock`    | 10  | Отключване на значка                                                      |

### Процес на присъждане

```typescript
export async function awardXp(
  apiKeyId: string,
  action: XpAction,
  metadata?: Record<string, unknown>
): Promise<{ xp: number; level: number; title: string; levelUp: boolean }>;
```

1. Направете справка в `XP_REWARDS[action]`, за да получите количеството XP.
2. Подайте през `checkRateLimit()` (защита срещу измама: максимум 1000 XP/минута за ключ).
3. Отворете транзакция:
   - Прочетете текущия ред в `user_levels`.
   - Добавете XP; преизчислете нивото чрез `levelFromXp(totalXp)`.
   - Ако нивото се е променило, задайте `levelUp = true`.
   - Актуализирайте реда в `user_levels`.
   - Вмъкнете запис в `xp_audit_log`.
4. Върнете резултата. Извикващият код обработва известията.

### Помощна функция: `levelFromXp(totalXp)`

Обхожда нивата от 1 до 100, като сумира `xp_for_level(n)`, докато кумулативният XP
надвиши `totalXp`. Връща най-високото ниво, чийто праг е достигнат.
Това е O(100) — приемливо, тъй като нивата са ограничени до 100.

## Система за значки

**Файл:** `src/lib/gamification/badges.ts`

### Категории

| Категория      | Описание                                   | Примерни значки                                    |
| -------------- | ------------------------------------------ | -------------------------------------------------- |
| `usage`        | Етапи, базирани на обем                    | Първа заявка, 1K заявки, 100K                      |
| `sharing`      | Споделяне на токени и препоръки            | Първо споделяне, Щедър (10 споделяния)             |
| `contribution` | Ангажираност с общността                   | Създател на комбинации, Изследовател на доставчици |
| `streak`       | Постоянство във времето                    | Седмичен воин, Месечно отдаден                     |
| `rare`         | Трудни за получаване или скрити постижения | Ранен потребител, Докладчик на грешки              |

### Редкости

| Рядкост     | Цвят   | Ориентир за вероятността |
| ----------- | ------ | ------------------------ |
| `common`    | Сив    | Повечето потребители     |
| `uncommon`  | Зелен  | Активни потребители      |
| `rare`      | Син    | Отдадени потребители     |
| `legendary` | Златен | Топ 1%                   |

### Типове критерии

| Тип            | Поле         | Описание                                                      |
| -------------- | ------------ | ------------------------------------------------------------- |
| `action_count` | `count`      | Изпълнение на действие N пъти (напр. 1000 заявки)             |
| `streak`       | `days`       | Поддържане на серия в продължение на N последователни дни     |
| `unique_count` | `field`, `n` | Използване на N уникални стойности (напр. 10 различни модела) |
| `rank`         | `scope`, `n` | Достигане на ранг N в обхват на класация                      |
| `first`        | —            | Първи да изпълни дадено действие                              |
| `hidden`       | (варира)     | Критериите не се показват, докато значката не бъде спечелена  |

Дефинициите на значките се съхраняват в `badge_definitions` като JSON `criteria`:

```json
{
  "type": "action_count",
  "action": "request",
  "count": 1000
}
```

### Процес на оценяване

```
emitGamificationEvent(event)
  → evaluateBadges(apiKeyId, event)
    → getBadgeDefinitions()           # всички дефиниции
    → getUserBadges(apiKeyId)         # вече спечелени (пропускане)
    → за всяка неспечелена значка:
       → matchesCriteria(badge, event, userState)
       → при съвпадение: awardBadge(apiKeyId, badgeId)
         → връщане на данните за известието
```

Оценяването е **задвижвано от събития** — изпълнява се след всяко геймификационно събитие, но
проверява само значките, чийто `criteria.type` съответства на действието на събитието. Това
поддържа оценяването бързо (< 5ms за повечето събития).

| Тип критерий   | Проверка                                                   |

## Проследяване на поредици

**Файл:** `src/lib/gamification/streaks.ts`

### Модел на данните

Поредиците се съхраняват в таблицата `key_value` (споделена помощна таблица) под ключове с пространства от имена:

| Ключ                          | Стойност                         | Описание                  |
| ----------------------------- | -------------------------------- | ------------------------- |
| `gamification:streak:{keyId}` | `{current},{longest},{lastDate}` | Данни за активна поредица |

### Логика

```typescript
export async function updateStreak(
  apiKeyId: string
): Promise<{ current: number; longest: number; milestone: boolean }>;
```

1. Прочитане на записа за поредицата от `key_value`.
2. Анализиране на `{current}`, `{longest}`, `{lastDate}` (низ с дата във формат ISO).
3. Ако `lastDate === today` — без промяна (днешният ден вече е отчетен).
4. Ако `lastDate === yesterday` — увеличаване на `current`; актуализиране на `longest`, ако е необходимо.
5. Ако `lastDate < yesterday` — нулиране до `current = 1` (поредицата е прекъсната).
6. Записване на актуализирания запис.
7. Проверка за етапи: 7, 14, 30, 60, 90, 180, 365 дни. Ако някой бъде достигнат,
   задаване на `milestone = true` (извикващият код присъжда XP и проверява значките).

### Гранични случаи

- **Часова зона**: поредиците използват дати по UTC (`new Date().toISOString().slice(0, 10)`).
  Това е умишлено — единна канонична часова зона предотвратява злоупотреби чрез
  смяна на часовите зони.
- **Нови потребители**: не съществува запис за поредица; първата заявка го създава със
  `current=1, longest=1, lastDate=today`.
- **Множество заявки на ден**: само първата заявка за UTC деня
  увеличава поредицата.

## Класация

**Файл:** `src/lib/gamification/leaderboard.ts`

### Обхвати

| Обхват          | Период  | Описание                                                         |
| --------------- | ------- | ---------------------------------------------------------------- |
| `global`        | `all`   | Кумулативен XP за цялото време                                   |
| `weekly`        | `week`  | XP, спечелен през текущата UTC седмица (понеделник–неделя)       |
| `monthly`       | `month` | XP, спечелен през текущия UTC месец                              |
| `tokens_shared` | `all`   | Общ брой токени, прехвърлени към други                           |
| `contributions` | `all`   | Създадени комбинации + използвани доставчици + използвани умения |

### Изчисляване на позицията

Позициите се **изчисляват при четене**, а не се съхраняват. Това предотвратява наличието на остарели данни за позициите
и премахва необходимостта от периодични задачи за преизчисляването им.

```typescript
export async function getLeaderboard(
  scope: LeaderboardScope,
  period: string,
  limit: number,
  offset: number
): Promise<{ entries: LeaderboardEntry[]; total: number }>;
```

Шаблон на заявката:

```sql
SELECT api_key_id, score,
       RANK() OVER (ORDER BY score DESC) as rank
FROM leaderboard
WHERE scope = ? AND period = ?
ORDER BY score DESC
LIMIT ? OFFSET ?
```

### Смяна на периода

Седмичните и месечните класации се сменят автоматично:

1. **Архивиране**: при границата на периода текущите записи се копират в
   `leaderboard_archive` с етикета на периода.
2. **Нулиране**: записите за изтеклия период се изтриват.
3. **Задействане**: извършва се проверка при всяко извикване на `updateLeaderboard()`; първата заявка
   от новия период задейства смяната.

Това гарантира, че седмичните класации се нулират всеки понеделник в 00:00 UTC, а месечните класации —
на първия ден от всеки месец.

### Актуализации в реално време чрез SSE

**Крайна точка:** `GET /api/gamification/stream`

```
Клиент → GET /api/gamification/stream
  → Установява се SSE връзка
  → Сървърът незабавно изпраща моментна снимка на първите 10 в класацията
  → На всеки 5 секунди: изпращане на актуализираните първи 10, ако има промяна
  → На всеки 15 секунди: коментар за проверка на връзката (": heartbeat\n\n")
  → Клиентът прекъсва връзката → почистване (премахване на слушателя)
```

Формат на събитието:

```
event: leaderboard
data: {"scope":"global","entries":[...]}

event: leaderboard
data: {"scope":"weekly","entries":[...]}

: heartbeat
```

SSE мениджърът проследява свързаните клиенти за всеки обхват и изпраща актуализации само
когато данните в класацията действително са се променили след последното изпращане.

## Споделяне на токени

**Файл:** `src/lib/gamification/sharing.ts`

### Счетоводна книга с двойно записване

Всеки трансфер създава два реда в `token_ledger`:

| Ред    | `from_key_id` | `to_key_id` | `amount` |
| ------ | ------------- | ----------- | -------- |
| Дебит  | подател       | получател   | +сума    |
| Кредит | получател     | подател     | -сума    |

Момент — конвенцията е:

| Ред        | `from_key_id` | `to_key_id` | `amount` | Значение                    |
| ---------- | ------------- | ----------- | -------- | --------------------------- |
| Изпращане  | подател       | получател   | +сума    | Изходящ поток от подателя   |
| Получаване | получател     | подател     | +сума    | Входящ поток към получателя |

Балансът се изчислява по следния начин:

```sql
SELECT
  COALESCE(SUM(CASE WHEN to_key_id = ? THEN amount ELSE 0 END), 0)
  - COALESCE(SUM(CASE WHEN from_key_id = ? THEN amount ELSE 0 END), 0)
  AS balance
FROM token_ledger
WHERE from_key_id = ? OR to_key_id = ?
```

### Процес на трансфер

```typescript
export async function transferTokens(
  fromKeyId: string,
  toKeyId: string,
  amount: number,
  idempotencyKey: string
): Promise<{ success: boolean; balance: number }>;
```

1. **Валидиране**: `amount > 0`, `fromKeyId !== toKeyId`.
2. **Идемпотентност**: проверка дали `idempotency_key` вече съществува в счетоводната книга.
   Ако да, връщане на кеширания резултат.
3. **Транзакция** (единична SQLite транзакция):
   a. Изчисляване на баланса на подателя.
   b. Ако `balance < amount`, прекратяване (недостатъчна наличност).
   c. Вмъкване на ред за изпращане (`from=подател, to=получател, amount`).
   d. Вмъкване на ред за получаване (`from=получател, to=подател, amount`).
4. **Ограничаване на честотата**: проверка на честотата на трансферите за подателя (макс. 10 трансфера/мин).
5. **Събитие**: излъчване на геймификационно събитие `token_share` за оценяване на XP + значки.
6. Връщане на `{ success: true, balance: newBalance }`.

### Ограничаване на честотата

- Максимум 10 трансфера в минута за всеки API ключ.
- Максимум 10 000 токена за един трансфер.
- Максимум 100 000 прехвърлени токена на ден за всеки API ключ.

## Токени за покана и активиране

**Файл:** `src/lib/gamification/invites.ts`

### Формат на кода

- **Код**: 8-знаков буквено-цифров код (напр. `A3K9-X7M2`), лесен за четене,
  показван на потребителя.
- **Токен**: 32-байтов случаен токен, съхраняван като SHA-256 хеш. Използва се за
  програмно активиране (напр. URL връзки).

### Съхранение

| Колона       | Стойност                           |
| ------------ | ---------------------------------- |
| `code`       | `A3K9X7M2` (уникална, индексирана) |
| `token_hash` | SHA-256(raw_token)                 |

Необработеният токен се връща на потребителя точно веднъж при създаването. OmniRoute
никога повече не го съхранява или показва — запазва се само хешът.

### Предотвратяване на самостоятелни препоръки

Когато потребител активира код, системата проверява:

1. Кодът принадлежи на различен `api_key_id`.
2. Активиращият потребител не е активирал преди това код от същия
   препоръчващ потребител (обединение по `invite_tokens` + дневника за активирания).

Ако някоя от проверките е неуспешна, активирането се отхвърля с ясно съобщение за грешка.

### Валидност и ограничения

- Стойност по подразбиране за `max_uses`: 10 (може да се конфигурира при създаване).
- Стойност по подразбиране за `expires_at`: 30 дни след създаването.
- Изтеклите или изчерпаните кодове връщат HTTP 410 Gone.

## Федерация на сървъри на общността

**Файл:** `src/lib/gamification/servers.ts`

### Свързване

Сървър на общността се регистрира чрез токен за покана, издаден от отдалечения сървър. Локалната инстанция:

1. Получава токена за покана (напр. поставен в таблото за управление).
2. Извиква `POST /api/gamification/federation/leaderboard` на отдалечения сървър, за да валидира токена и да извлече текущата класация.
3. Съхранява записа за сървъра със `status: connected`.

### Модел за синхронизация

Федерацията използва **синхронизация чрез презаписване**, а не чрез натрупване:

```
Локална инстанция              Сървър на общността
     │                              │
     ├── изпращане на резултат ────►│  POST /federation/score
     │   { api_key_id, score }      │  (сървърът валидира хеша на токена)
     │                              │
     ├── извличане на класацията ──►│  GET /federation/leaderboard
     │◄── първите N записа ─────────┤  (презаписва локалния кеш)
     │                              │
     └── проверка на състоянието ──►│  GET /federation/health
         (на всеки 60s, изчакване 5s)│
```

### Удостоверяване

Заявките за федерация включват:

```
Authorization: Bearer <raw_token>
X-Federation-Version: 1
```

Отдалеченият сървър хешира токена и търси съответстващия ред в `community_servers`. Така се избягва предаването на съхранения хеш.

### Наблюдение на състоянието

Всеки запис за сървър проследява:

| Поле        | Описание                                              |
| ----------- | ----------------------------------------------------- |
| `status`    | `connected`, `degraded`, `unreachable`                |
| `last_sync` | ISO времеви печат на последната успешна синхронизация |
| `failures`  | Последователни неуспешни проверки на състоянието      |

След 5 последователни неуспеха състоянието се променя на `unreachable`, а синхронизацията се поставя на пауза, докато ръчна проверка на състоянието не завърши успешно.

## Защита срещу измами

**Файл:** `src/lib/gamification/antiCheat.ts`

### Изчисляване на резултата от страна на сървъра

Всички изчисления на XP се извършват в `src/lib/gamification/xp.ts`. Клиентите никога не подават резултат — те подават действия, а сървърът изчислява XP. Колоната `leaderboard.score` може да бъде записвана само от код от страна на сървъра.

### Ограничаване на честотата

| Ограничение                  | Стойност | Обхват      |
| ---------------------------- | -------- | ----------- |
| Максимум XP на минута        | 1,000    | За API ключ |
| Максимум трансфери на минута | 10       | За API ключ |
| Максимална сума на трансфер  | 10,000   | За трансфер |
| Максимум трансфери на ден    | 100,000  | За API ключ |

Ограниченията на честотата използват плъзгащ се прозорец в паметта (по същия модел като `RateLimitManager` в `open-sse/services/`). При рестартиране на процеса се използват като резервен вариант броячи, съхранявани в SQLite.

### Откриване на аномалии чрез Z-оценка

За всеки API ключ системата поддържа плъзгащ се 7-дневен прозорец на спечелените XP на час. При всяко присъждане на XP:

1. Изчислява текущата часова скорост на натрупване на XP на потребителя.
2. Изчислява средната стойност и стандартното отклонение на популацията.
3. Изчислява `z = (user_rate - mean) / stddev`.
4. Ако `z > 3.0` (3 стандартни отклонения), отбелязва случая като аномалия.

Аномалиите се записват в `xp_audit_log` с `action = 'anomaly_detected'` и се показват в администраторското табло за управление.

### Одитна следа

Всяко присъждане на XP, трансфер, получаване на значка и откриване на аномалия се записва в `xp_audit_log` със:

| Поле         | Описание                                             |
| ------------ | ---------------------------------------------------- |
| `api_key_id` | Кой                                                  |
| `action`     | Какво се е случило (xp_award, transfer, anomaly, …)  |
| `xp_awarded` | Количество (0 за събития, които не са свързани с XP) |
| `metadata`   | JSON с контекст (тип действие, цел, …)               |
| `created_at` | Кога (ISO 8601)                                      |

Администраторите могат да заявят пълната одитна следа чрез `GET /api/gamification/anomalies`.

## Страници на таблото за управление

### `/dashboard/leaderboard`

- Показване на подиум (първите 3 с аватари и XP).
- Селектор за обхват: Глобално / Седмично / Месечно / Споделени токени / Приноси.
- Таблица със странициране (25 на страница) с ранг, име, резултат, ниво и титла.
- Актуализации в реално време чрез SSE — промените в ранга се анимират.
- Текущият потребител е откроен в таблицата със закрепен ред „Вашият ранг“.

### `/dashboard/profile`

- Лента за напредъка на XP с текущото ниво и прага за следващото ниво.
- Значката за титла е показана на видно място.
- Галерия със значки — спечелените значки са с дата на спечелване, а неспечелените са показани в сиво
  (скритите значки показват „???“, докато не бъдат спечелени).
- Брояч на серията с икона на пламък; календар на серията (последните 30 дни).
- Диаграма на историята на XP (XP по дни за последните 30 дни).

### `/dashboard/tokens`

- Баланс на токените (на видно място в горната част на страницата).
- Формуляр за прехвърляне: получател, сума, диалогов прозорец за потвърждение.
- Таблица с историята на прехвърлянията и филтри (изпратени/получени/всички).
- Секция за покани: активни кодове, генериране на нови, връзка за споделяне.
- Сървъри на общността: списък със здравен статус, свързване/прекъсване на връзката.

### `/dashboard/gamification/admin`

- Списък с аномалии, включващ сериозност, потребител, времеви печат и z-резултат.
- Преглед на журнала за одит с филтри (тип действие, потребител, период от време).
- Системна статистика: общо присъдено XP, активни потребители, честота на спечелване на значки.
- Общ преглед на здравния статус на сървърите във федерацията.

## Интеграция с конвейера

### Точка на интеграция

Геймификацията се включва в конвейера за заявки в една-единствена точка в
`open-sse/handlers/chatCore.ts`:

```typescript
// След като отговорът бъде изпратен на клиента:
setImmediate(() => {
  emitGamificationEvent({
    type: "request.completed",
    apiKeyId,
    metadata: {
      provider: selectedProvider,
      model: selectedModel,
      comboId: resolvedCombo?.id,
      compressionUsed: compressionStats?.applied,
      skillUsed: skillExecution?.name,
    },
  }).catch(() => {
    // Изпълнение без изчакване: регистриране в журнала без предаване към клиента
  });
});
```

### Типове събития

| Тип събитие         | Кога се задейства                                                        |
| ------------------- | ------------------------------------------------------------------------ |
| `request.completed` | Изпратен е успешен отговор от LLM                                        |
| `provider.switch`   | Доставчикът е променен (аварийното превключване на комбинация се отчита) |
| `combo.created`     | Запазена е нова конфигурация на комбинация                               |
| `combo.used`        | Целта на комбинацията е достигната успешно                               |
| `badge.earned`      | Оценяването на значка е открило съвпадение                               |
| `streak.milestone`  | Преминат е праг на серията                                               |
| `transfer.sent`     | Прехвърлянето на токени е завършено                                      |
| `referral.redeemed` | Кодът за покана е използван успешно                                      |
| `compression.used`  | Приложена е компресия на подканата                                       |
| `skill.executed`    | Изпълнението на умението е завършено                                     |
| `model.first_use`   | Моделът не е използван през последните 7 дни                             |

### Гаранция за неблокиращо изпълнение

Шаблонът `setImmediate` + `.catch(() => {})` гарантира:

1. Отговорът е изпратен изцяло, преди да се изпълни геймификацията.
2. Грешките при геймификацията никога не достигат до клиента.
3. Обработката на събитието се изпълнява в следващата микрозадача, а не на място.

## Сигурност

### Модел на заплахите

| Заплаха                           | Мярка за ограничаване                                                                    |
| --------------------------------- | ---------------------------------------------------------------------------------------- |
| Изкуствено завишаване на точки    | Изчисляване на XP само от страна на сървъра; клиентите изпращат действия, а не резултати |
| Атаки с повторно изпълнение       | Ключове за идемпотентност при трансфери; дедупликация на журнала за одит                 |
| Измами с трансфери                | Счетоводен регистър с двойно записване; атомарни транзакции; ограничения на честотата    |
| Саморефериране                    | Кръстосана проверка на `api_key_id` при осребряване                                      |
| Манипулиране на класацията        | Откриване на аномалии чрез Z-резултат; административно табло за аномалии                 |
| Кражба на токен за федерация      | Съхранение на SHA-256 хеш; необработеният токен се показва само веднъж                   |
| Груба сила срещу кодове за покана | Ограничаване на честотата за крайната точка за осребряване; 8-знакова ентропия           |
| XSS в показваните имена           | Показваните имена се пречистват; записите в класацията се екранират                      |
| Времеви атаки срещу хешове        | `crypto.timingSafeEqual` за сравняване на хешове на токени                               |

### Изисквания за удостоверяване

- **Публичен достъп** (без удостоверяване): `GET /leaderboard`, `GET /stream` (класации
  само за четене).
- **Изисква се API ключ**: всички операции за запис, профил, трансфери, покани.
- **Само за администратори**: табло за аномалии, преглед на журнала за одит.
- **Федерация**: отделен път за удостоверяване чрез необработен токен в заглавката
  `Authorization`, валидиран спрямо съхранения SHA-256 хеш.

## Бъдещи възможности

- **Сезонни събития**: комплекти от значки и сезони на класацията с ограничена продължителност.
- **Отборни класации**: групиране на потребителите по организация или комбинация.
- **Множители на XP**: увеличаване на XP по време на промоционални периоди.
- **Споделяне на постижения**: генериране на карти със значки за споделяне (OpenGraph изображения).
- **Мобилни push известия**: известия, базирани на webhook, за събития със значки/нива.
- **API за класацията**: публичен API за интеграции с трети страни.
