Препоръчителната базова стойност е числото, спрямо което трябва да се оптимизира.

## Правила

- Целите за покритие се прилагат към файловете с изходен код, а не към `tests/**`.
- `open-sse/**` е част от продукта и трябва да остане в обхвата.
- Новият код не трябва да намалява покритието в засегнатите области.
- Предпочитайте тестване на поведението и резултатите от разклоненията пред детайлите на реализацията.
- За `src/lib/db/**` предпочитайте временни SQLite бази данни и малки тестови набори от данни пред широкообхватни имитации.

## Текущ набор от команди

- `npm run test:coverage`
  - Основна проверка на покритието на изходния код за набора от модулни тестове
  - Генерира `text-summary`, `html`, `json-summary` и `lcov`
- `npm run coverage:report`
  - Подробен отчет файл по файл от последното изпълнение
- `npm run test:coverage:legacy`
  - Само за сравнение с исторически данни

## Политика за постепенно повишаване

Актуализирайте праговете на `npm run test:coverage` само след като проектът действително надхвърли следващия етап с достатъчен резерв.

**Текущ праг:** `npm run test:coverage` налага **60 оператора / 60 реда / 60 функции / 60 разклонения** (метриката беше преизчислена в Quality-Gates Fase 6A.1 — предишната базова стойност от 82.58% беше завишена, защото включваше тестови файлове и изключваше `open-sse`). Командата `test:coverage:legacy` запазва старата метрика 50/50/50 за историческо сравнение.

За еднократни проверки на прага спрямо последния отчет използвайте:

```bash
node scripts/check/test-report-summary.mjs --threshold 75
```

Препоръчителна последователност за постепенно повишаване (редът е `оператори-редове / разклонения / функции`):

1. 55/60/55
2. 60/62/58
3. 65/64/62
4. 70/66/66
5. 75/70/72 <-- текущ праг (75/70/75)
6. 80/75/78
7. 85/80/84
8. 90/85/88

Следващата цел за постепенно повишаване е `80/75/78`, след като покритието на разклоненията се задържи над 78% при две последователни изпълнения.

## Известен пропуск

Текущата команда за покритие измерва основния набор от модулни тестове за Node и включва достигнатия от него изходен код, включително `open-sse`. Тя все още не обединява покритието от Vitest в един общ отчет. Това обединяване си струва да бъде направено по-късно, но не е пречка за започване на повишаването от 60% към 80%.
