## Предварителни изисквания

| Компонент  | Минимум                  | Препоръчително   |
| ---------- | ------------------------ | ---------------- |
| **CPU**    | 1 vCPU                   | 2 vCPU           |
| **RAM**    | 1 GB                     | 2 GB             |
| **Диск**   | 10 GB SSD                | 25 GB SSD        |
| **ОС**     | Ubuntu 22.04 LTS         | Ubuntu 24.04 LTS |
| **Домейн** | Регистриран в Cloudflare | —                |
| **Docker** | Docker Engine 24+        | Docker 27+       |

**Тествани доставчици**: Akamai (Linode), DigitalOcean, Vultr, Hetzner, AWS Lightsail.

## 1. Конфигуриране на виртуалната машина

### 1.1 Създаване на инстанцията

При предпочитания от вас VPS доставчик:

- Изберете Ubuntu 24.04 LTS
- Изберете минималния план (1 vCPU / 1 GB RAM)
- Задайте силна root парола или конфигурирайте SSH ключ
- Запишете **публичния IP адрес** (напр. `203.0.113.10`)

### 1.2 Свързване чрез SSH

```bash
ssh root@203.0.113.10
```

### 1.3 Актуализиране на системата

```bash
apt update && apt upgrade -y
```

### 1.4 Инсталиране на Docker

```bash
# Инсталиране на зависимостите
apt install -y ca-certificates curl gnupg

# Добавяне на официалното хранилище на Docker
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
chmod a+r /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $ (. /etc/os-release && echo "$VERSION_CODENAME") stable" | tee /etc/apt/sources.list.d/docker.list > /dev/null
apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

### 1.5 Инсталиране на nginx

```bash
apt install -y nginx
```

### 1.6 Конфигуриране на защитната стена (UFW)

```bash
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp    # SSH
ufw allow 80/tcp    # HTTP (пренасочване)
ufw allow 443/tcp   # HTTPS
ufw enable
```

> **Съвет**: За максимална сигурност ограничете портове 80 и 443 само до IP адресите на Cloudflare. Вижте раздела [Разширена сигурност](#advanced-security).

## 2. Инсталиране на OmniRoute

### 2.1 Създаване на директория за конфигурацията

```bash
mkdir -p /opt/omniroute
```

### 2.2 Създаване на файл с променливи на средата

```bash
cat > /opt/omniroute/.env << 'EOF'
# === Сигурност ===
JWT_SECRET=CHANGE-TO-A-UNIQUE-64-CHAR-SECRET-KEY
INITIAL_PASSWORD=YourSecurePassword123!
API_KEY_SECRET=REPLACE-WITH-ANOTHER-SECRET-KEY
STORAGE_ENCRYPTION_KEY=REPLACE-WITH-THIRD-SECRET-KEY
STORAGE_ENCRYPTION_KEY_VERSION=v1
MACHINE_ID_SALT=CHANGE-TO-A-UNIQUE-SALT
OMNIROUTE_WS_BRIDGE_SECRET=REPLACE-WITH-WS-BRIDGE-SECRET  # ЗАДЪЛЖИТЕЛНО в продукционна среда: използва се от Codex Responses WS bridge

# === Приложение ===
PORT=20128
NODE_ENV=production
HOSTNAME=0.0.0.0
DATA_DIR=/app/data
APP_LOG_TO_FILE=true
AUTH_COOKIE_SECURE=true
REQUIRE_API_KEY=false

# === URL адреси (променете ги според вашия домейн) ===
# Вътрешен базов URL адрес между сървърите за планирани задачи / заявки към самия сървър.
BASE_URL=http://127.0.0.1:20128
# URL адрес за браузъра, използван за OAuth обратни извиквания, връзки към таблото за управление и генерирани публични URL адреси.
NEXT_PUBLIC_BASE_URL=https://llms.seudominio.com
# Незадължително изрично заместване на публичния origin за генерираните публични URL адреси на ресурси.
# OMNIROUTE_PUBLIC_BASE_URL=https://llms.seudominio.com

# === Облачно синхронизиране (незадължително) ===
# CLOUD_URL=https://cloud.omniroute.online
# NEXT_PUBLIC_CLOUD_URL=https://cloud.omniroute.online
EOF
```

> ⚠️ **ВАЖНО**: Генерирайте уникални секретни ключове! Използвайте `openssl rand -hex 32` за всеки ключ.

### 2.3 Стартиране на контейнера

```bash
docker pull diegosouzapw/omniroute:latest

docker run -d \
  --name omniroute \
  --restart unless-stopped \
  --env-file /opt/omniroute/.env \
  -p 20128:20128 \
  -v omniroute-data:/app/data \
  diegosouzapw/omniroute:latest
```

### 2.4 Проверка дали работи

```bash
docker ps | grep omniroute
docker logs omniroute --tail 20
```

Трябва да се покажат: `[DB] SQLite database ready` и `listening on port 20128`.

## 3. Конфигуриране на nginx (обратен прокси сървър)

### 3.1 Генериране на SSL сертификат (Cloudflare Origin)

В таблото за управление на Cloudflare:

1. Отидете на **SSL/TLS → Origin Server**
2. Щракнете върху **Create Certificate**
3. Запазете настройките по подразбиране (15 години, \*.yourdomain.com)
4. Копирайте **Origin Certificate** и **Private Key**

```bash
mkdir -p /etc/nginx/ssl

# Поставете сертификата
nano /etc/nginx/ssl/origin.crt

# Поставете частния ключ
nano /etc/nginx/ssl/origin.key

chmod 600 /etc/nginx/ssl/origin.key
```

### 3.2 Конфигурация на Nginx

```bash
cat > /etc/nginx/sites-available/omniroute << 'NGINX'
# Сървър по подразбиране — блокира директния достъп чрез IP адрес
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    listen 443 ssl default_server;
    listen [::]:443 ssl default_server;
    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    server_name _;
    return 444;
}

# OmniRoute — HTTPS
server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name llms.yourdomain.com;  # Променете на вашия домейн

    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    client_max_body_size 100M;

    location / {
        proxy_pass http://127.0.0.1:20128;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Поддръжка на WebSocket
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # SSE (събития, изпращани от сървъра) — поточно предаване на отговори от ИИ
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }
}

# Пренасочване от HTTP към HTTPS
server {
    listen 80;
    listen [::]:80;
    server_name llms.yourdomain.com;
    return 301 https://$server_name$request_uri;
}
NGINX
```

Поддържайте времената за изчакване на потоците в обратния прокси сървър съгласувани с променливите на средата за време на изчакване на OmniRoute. Ако увеличите
`FETCH_TIMEOUT_MS` / `STREAM_IDLE_TIMEOUT_MS`, увеличете `proxy_read_timeout` / `proxy_send_timeout`
над същия праг.

OmniRoute използва `NEXT_PUBLIC_BASE_URL` като каноничен, видим за браузъра източник за OAuth
обратни извиквания и генерирани публични връзки. Удостоверените операции за запис в таблото за управление използват заявки от същия източник
заедно със защита срещу CSRF, обвързана със сесията, така че не изискват статичен публичен базов URL адрес. Посочените по-горе
заглавки `X-Forwarded-*` все пак са полезни метаданни за маршрутизиране, но не заместват
задаването на изричен публичен URL адрес, когато такъв е необходим за OAuth или генерирани връзки за браузъра. Активирайте
`OMNIROUTE_TRUST_PROXY` само ако OmniRoute не е директно достъпен за клиенти и вашият прокси сървър
премахва/пресъздава входящите препратени заглавки.

### 3.3 Активиране и тестване

```bash
# Премахване на конфигурацията по подразбиране
rm -f /etc/nginx/sites-enabled/default

# Активиране на OmniRoute
ln -sf /etc/nginx/sites-available/omniroute /etc/nginx/sites-enabled/omniroute

# Тестване и презареждане
nginx -t && systemctl reload nginx
```

## 4. Конфигуриране на Cloudflare DNS

### 4.1 Добавяне на DNS запис

В таблото за управление на Cloudflare → DNS:

| Тип | Име    | Съдържание                | Проксиране    |
| --- | ------ | ------------------------- | ------------- |
| A   | `llms` | `203.0.113.10` (IP на VM) | ✅ Проксирано |

### 4.2 Конфигуриране на SSL

В **SSL/TLS → Overview**:

- Режим: **Full (Strict)**

В **SSL/TLS → Edge Certificates**:

- Винаги използвай HTTPS: ✅ Включено
- Минимална версия на TLS: TLS 1.2
- Автоматично пренаписване към HTTPS: ✅ Включено

### 4.3 Тестване

```bash
curl -sI https://llms.seudominio.com/health
# Трябва да върне HTTP/2 200
```

```bash
# Копиране на данните от тома към хоста
docker cp omniroute:/app/data ./backup-$(date +%F)

# Или компресиране на целия том
docker run --rm -v omniroute-data:/data -v $(pwd):/backup \
  alpine tar czf /backup/omniroute-data-$(date +%F).tar.gz /data
```

### Възстановяване от архив

```bash
docker stop omniroute
docker run --rm -v omniroute-data:/data -v $(pwd):/backup \
  alpine sh -c "rm -rf /data/* && tar xzf /backup/omniroute-data-YYYY-MM-DD.tar.gz -C /"
docker start omniroute
```

## Оптимизация за малко памет / малък VPS

За внедрявания на малки VPS инстанции (с 1 GB RAM или по-малко):

- **Деактивирайте фоновите услуги** — задайте `OMNIROUTE_DISABLE_BACKGROUND_SERVICES=1`, за да пропуснете планировчика, MCP сървъра и периодичните задачи за поддръжка. Вижте `docs/reference/ENVIRONMENT.md`.
- **Използвайте SQLite в режим WAL** — активиран е по подразбиране и намалява пиковото потребление на памет при едновременни операции за четене.
- **Ограничете heap паметта на V8** — задайте `OMNIROUTE_MEMORY_MB` (напр. `512`), така че средата за изпълнение да не определя таван, по-голям от този на виртуалната машина. Вижте `docs/reference/ENVIRONMENT.md`.
- **Допускането на тежки заявки се мащабира автоматично според ограничението на heap паметта** -- след като зададете `OMNIROUTE_MEMORY_MB` по-горе, бюджетът в байтове за приемане (`OMNIROUTE_CHAT_MAX_INFLIGHT_BYTES`) се извежда автоматично от същия таван, така че виртуална машина с ограничена памет получава по-малък бюджет за едновременни заявки без допълнителна настройка; излишните заявки получават подлежаща на повторен опит грешка `503` с `Retry-After`, вместо да се конкурират за памет. Задайте старото ограничение за брой заявки `OMNIROUTE_CHAT_MAX_HEAVY_IN_FLIGHT` само ако ви е необходим твърд таван в допълнение към това.
- **Избягвайте `next build` на VPS** — компилирайте локално и внедрете самостоятелния изход (`.next/standalone/`).
- **Наблюдавайте с `top` / `free -m`** — OmniRoute обикновено използва 200–400 MB RSS в неактивно състояние на виртуална машина с 1 GB памет.
