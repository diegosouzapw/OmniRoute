## 1. Фактическа информация за услугата (официална документация, проверена чрез съпоставка)

- Базов URL адрес: `https://api.anysearch.com` (REST) + `POST /mcp` (MCP, JSON-RPC 2.0).
- `POST /v1/search` — параметри: `query` (задължителен), `max_results` (1–10, по подразбиране 10), `tag` (`{domain}.{sub_domain}` вертикално маршрутизиране), `zone` (cn/intl), `language`, `params` (структурирани полета за вертикалата), `format` (json/markdown).
- `GET /v1/sub-domains?domain=...` — каталог с възможности, НЕ се отчита към квотата.
- `POST /v1/extract` — извлича/обработва `{url, title, content}`; строго JSON тяло, ограничение от 16 KiB.
- `POST /v1/auth/email/register` — регистрация с едно извикване, връща еднократен ключ в открит текст `as_sk_...`.
- Удостоверяване: незадължителен `Authorization: Bearer <as_sk_...>`; анонимният достъп преминава към ограничения за отделен IP адрес, които използват безплатната дневна квота; невалиден ключ връща 401/403 БЕЗ неусетно преминаване към анонимен достъп.
- Безплатен план: 1000 заявки/ден, 20 QPS на ключ. Платен план: без обявена цена (Очаквайте скоро).
- Обвивка на отговора: успех `{code: 0, message: "success", request_id, data}`; неуспех `{code: -1, message}`. Грешките при удостоверяване/изчерпана квота не съдържат структуриран `error_code` (сигналът е текстът на съобщението); специфичните за извличането грешки съдържат `error_code` (`invalid_extract_url`, `extract_failed`). При 429 няма заглавка `Retry-After`.

## 3. Решения (всички взети на 2026-08-26)

1. **Поведение при маршрутизиране: `fallbackOnly`.** Обосновка: безплатен доставчик с цена 0 никога не трябва да доминира автоматичното маршрутизиране по цена; изричният избор и връщането при отказ остават незасегнати. Прецедент: обединеният запис за xquik.
2. **Обхват: webSearch + webFetch чрез `POST /v1/extract` във v1.** В съответствие с концептуалния модел за двойна функционалност на tavily/exa. Вертикалните интерфейси (`tag`, `sub-domains`, `batch_search`) остават извън обхвата — понастоящем няма IR за вертикални параметри.
3. **Показване на квотата: `freeMonthlyQuota: 0`** (консервативно показване в стила на xquik). Реалният лимит (1000 заявки/ден, ежедневно нулиране) вместо това е посочен в текста `authHint` на каталога в потребителския интерфейс. Обосновка: показването на квотата трябва да съответства на начина на нулиране; преобразуването на дневен лимит в месечен еквивалент (30000) е невярно обещание, което потребителският интерфейс не може да изпълни.
4. **searchTypes: само `["web"]`.** Няма публични доказателства за вертикала за новини/изображения в AnySearch API; шлюзовете, които интегрират API без документирана вертикала (напр. Google Custom Search), предоставят само уеб търсене, вместо безмълвно да преобразуват news -> web.
5. **Поведение на ключа:** работата без ключ се поддържа; невалиден ключ връща 401/403 и никога не се понижава безмълвно до анонимен достъп (отразява договора на услугата нагоре по веригата).
6. **Преднамерени изключения:** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (прихващането на чат остава с firecrawl/jina/tavily); `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (анонимните отдалечени крайни точки споделят един пул с IP ограничение за всеки изходящ IP адрес, затова извличането без ключ се включва изрично, а не е кандидат за автоматично маршрутизиране); `QUOTA_STATUS_PROVIDERS` (AnySearch сигнализира за квота чрез 429/обвивка, а не чрез статус 402/403).
