Dashboard → Providers → **Import from file** 可從 CSV 或 JSON 清單建立 API 金鑰連線。每一列都可以指定不同的提供者。允許部分失敗是既定行為：即使部分列失敗，有效的列仍會匯入，而對話框會列出失敗列遭拒絕的原因。

此匯入功能**不會**建立新的 OpenAI/Anthropic 相容端點節點。請先建立這些節點（Dashboard → Providers → Add OpenAI-Compatible，或 `omniroute nodes add`），然後匯入 `provider` 欄位為該節點 id 的列。每列的 `baseUrl` 仍可覆寫節點的 URL。

## CSV（按位置解析）

欄位名稱僅供識別。解析器會分割每一列，並依索引解構：

| 索引 | 欄位       | 必填 | 備註                                                                                               |
| ---- | ---------- | ---- | -------------------------------------------------------------------------------------------------- |
| 0    | `provider` | 是   | 現有的受管理提供者 id（`openai`、`anthropic`，…），**或**已註冊的 OpenAI/Anthropic 相容**節點** id |
| 1    | `name`     | 是   | 連線顯示名稱                                                                                       |
| 2    | `apiKey`   | 是   | API 金鑰                                                                                           |
| 3    | `baseUrl`  | 否   | 每列的 URL 覆寫值                                                                                  |
| 4    | `priority` | 否   | 1–100 的整數                                                                                       |

如果第一行的第一欄是字面值 `provider`（不分大小寫），則會將其視為標頭並略過。空白行與 `#` 註解也會略過。

可從匯入對話框下載起始檔案（**Download CSV template**）。範例：

```csv
# OmniRoute 提供者匯入（按位置排列的欄位）
provider,name,apiKey,baseUrl,priority
openai,Prod OpenAI,sk-your-openai-key,,1
```

虛構的 id（例如 `openai-compatible-chat-001`）並不是節點。API 會針對該列傳回 `Unknown or unsupported provider`；對話框會在該列名稱旁顯示此訊息。

## JSON

由物件組成的 JSON 陣列，使用相同的欄位（`provider`、`name`、`apiKey`、`baseUrl?`、`priority?`）。與 CSV 不同，JSON 鍵具有名稱。

```json
[
  {
    "provider": "openai",
    "name": "Prod OpenAI",
    "apiKey": "sk-your-openai-key",
    "priority": 1
  }
]
```
