`copilot-m365-web`（別名 `m365copilot`）透過已驗證的 Microsoft 365 Copilot BizChat 瀏覽器工作階段，在 `m365.cloud.microsoft/chat` 傳送 OpenAI 格式的聊天請求。這是非官方整合。

> **第一次使用 Web Cookie 提供者嗎？**
>
> 在依照此提供者專用指南操作之前，請先閱讀 **`docs/getting-started/WEB-COOKIE-GUIDE.md`**，以瞭解一般設定流程、驗證指南、限制與疑難排解。
>
> **重要：** 此提供者的憑證**不是 Cookie**。請勿從 `m365.cloud.microsoft` 複製 Cookie。此憑證由 WebSocket URL 查詢參數和路徑區段組成，兩者皆需從 DevTools 的 Network 分頁中取得。

## 先決條件

- 可存取 `m365.cloud.microsoft/chat` 中 BizChat 的 Microsoft 365 帳戶
- 用於透過 DevTools 檢查 WebSocket 的 Chromium 系瀏覽器（Chrome、Edge）
- M365 Copilot 授權（許多 Microsoft 365 Business/Enterprise 方案皆包含此授權）

## 擷取憑證（WebSocket 方法）

1. 登入 `https://m365.cloud.microsoft/chat` 並開始對話。
2. 開啟 **DevTools → Network**。
3. 依 **WS**（WebSocket）篩選。
4. 按一下 Chathub WebSocket 連線。尋找開頭如下的 URL：
   `wss://substrate.office.com/m365Copilot/Chathub/`。
5. 從其 **Request URL** 複製：
   - `access_token` 查詢參數值（短效期 JWT）。
   - `/Chathub/` 之後的 Chathub 路徑區段（例如 `<oid>@<tenant>`）。

完整 URL 的格式如下：

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. 在 OmniRoute 中，前往 **Providers → Add Provider**，選取 **Microsoft 365 Copilot
   (BizChat)**，然後以下列格式貼上憑證：

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. 按一下 **Test Connection**，然後按一下 **Save**。

## 擷取憑證（匯入 HAR）

除了手動從 WebSocket URL 複製值之外，您也可以匯出 DevTools HAR 檔案：

1. 開啟 **DevTools → Network**。
2. 開始或繼續 BizChat 對話（這會觸發 WebSocket 連線）。
3. 在 Network 面板中按一下滑鼠右鍵，然後選取 **Save all as HAR with content**。
4. 在 OmniRoute 中，使用提供者連線對話方塊上的 **Import .har file** 按鈕。

OmniRoute 會掃描 HAR 以尋找 Chathub WebSocket URL、擷取 `access_token` 和 `chathubPath`，並自動填入憑證欄位。匯入 HAR 時會解碼 JWT 到期時間，並顯示權杖的剩餘有效時間。

> **切勿提交真實的 HAR 匯出檔、存取權杖或重新整理權杖。** 測試和文件中的值一律必須使用預留位置。

## 權杖有效期限與重新整理

`access_token` 的有效期很短（通常約為 **75 分鐘**）。到期後，提供者會回報連線錯誤，您必須重新擷取憑證。

### 使用 `refreshToken` 自動重新整理

若要避免手動重新擷取，您可以在連線的 **Advanced Settings → providerSpecificData** 中儲存 Microsoft 重新整理權杖：

| 欄位           | 說明                                                                     |
| -------------- | ------------------------------------------------------------------------ |
| `refreshToken` | 適用於 `substrate.office.com/sydney` 範圍的 Microsoft OAuth 重新整理權杖 |
| `tier`         | `individual`（預設）、`edu` 或 `enterprise`                              |

透過範圍設定為 `substrate.office.com/sydney` 的 Microsoft 裝置代碼或授權代碼流程取得重新整理權杖。設定 `refreshToken` 後，OmniRoute 會在每次請求前預先重新整理 `access_token`，因此無須在每次約 75 分鐘的有效期屆滿後重新擷取。

如果未設定 `refreshToken`，則每次到期後都必須手動重新擷取 WebSocket 憑證。

### 層級選擇

| 層級         | 別名       | 使用介面              |
| ------------ | ---------- | --------------------- |
| `individual` | _（預設）_ | 消費者版 M365 Copilot |
| `edu`        | `included` | 教育版 M365 Copilot   |
| `enterprise` | `work`     | M365 Copilot for Work |

請在 **Advanced Settings → providerSpecificData → tier** 中設定層級。該層級會影響 BizChat 路由和模型存取權限。

## 安全性模型

- **非官方整合。** 此提供者透過逆向工程解析 BizChat WebSocket
  通訊協定。當 Microsoft 變更端點時，此整合可能會在未事先通知的情況下失效。
- `subscriptionRisk: true` 旗標表示此整合依賴未公開文件的端點。帳戶可能會受到限制，但尚未獲得證實。
- 存取權杖是短期有效的 JWT。請將其視同密碼：請勿提交至版本控制、記錄於日誌中或與他人分享。
- 重新整理權杖可長期存取 BizChat 介面。請以與 API 金鑰相同的謹慎程度加以儲存。

## 疑難排解

### 驗證立即失敗

- 請確認您是從 **WebSocket URL** 複製，而不是從 XHR/Fetch 請求複製。認證資訊位於 Chathub WebSocket
  連線的 `access_token` 查詢參數中，而不是位於 `Authorization: Bearer` 標頭中。
- 請確認 `chathubPath` 包含 URL
  路徑中完整的 `<oid>@<tenant>` 區段。

### 權杖約在 75 分鐘後到期

這是預期行為。若沒有 `refreshToken`，存取權杖的有效期很短。您可以：

- 從 DevTools 重新擷取認證資訊，或
- 在「進階設定」中設定 `refreshToken`，以自動重新整理。

### 測試連線成功，但聊天功能傳回 401

權杖可能已在驗證完成後、首次請求送出前到期。請重新擷取新的認證資訊。

### Copilot 未出現在提供者清單中

請確認已在 **Dashboard → Providers** 中啟用 `copilot-m365-web`。在某些方案層級中，此提供者可能預設為隱藏。
