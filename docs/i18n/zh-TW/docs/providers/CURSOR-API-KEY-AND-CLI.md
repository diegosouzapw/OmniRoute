無需 IDE 工作階段，即可透過以下兩種方式將 Cursor 置於 OmniRoute 後方：

1. **`cursor-api` 提供者**（卡片「Cursor API」，別名 `cua`）：這是一個使用 API 金鑰的
   提供者，持有 Cursor 使用者 API 金鑰（`crsr_…`，產生自
   `https://cursor.com/dashboard/api`）。之後，任何 OmniRoute 用戶端皆可透過
   `/v1/chat/completions`，以 `cursor-api/<model>` 或
   `cua/<model>` 存取 Cursor 模型，並套用一般的配額、備援及記錄層。IDE
   提供者（`cursor`，OAuth/IDE 工作階段）維持不變。
2. **Cursor CLI 直通**：將 Cursor CLI（`agent`）指向 OmniRoute，使
   CLI 發出的每個 RPC 都使用 OmniRoute API 金鑰進行驗證，並使用
   `cursor-api` 連線的憑證轉送至 Cursor，同時記錄於
   Logs 頁面中。

## 為何要交換金鑰

`api2.cursor.sh` 會拒絕將原始 `crsr_…` 金鑰作為 Bearer 權杖（401）。Cursor
CLI 會先將金鑰 POST 至 `/auth/exchange_user_api_key`，並取得一個一小時後
到期的工作階段 JWT；傳回的 `refreshToken` 具有相同的
`exp`，因此重新整理實際上表示再次交換金鑰。
`open-sse/services/cursorApiKeyAuth.ts` 會執行此交換、為每個金鑰快取一個工作階段
權杖、在到期前五分鐘重新交換，並在 Cursor 回應 401 時捨棄快取的
權杖。`CursorExecutor` 會在為 `cursor-api` 連線開啟
上游串流之前立即呼叫它。

## `cursor-api` 提供者

登錄檔：`open-sse/config/providers/registry/cursor/index.ts`
（`cursor_apiProvider`、`authType: "apikey"`，並使用與 `cursor` 相同的 `format`、`baseUrl` 和
`models`）。目錄卡片：
`src/shared/constants/providers/apikey/specialty-media.ts`。執行器對應：
`open-sse/executors/index.ts`（`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`）。

儀表板：Providers → Cursor API → Add API key。

REST：

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

接著：

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

注意事項：

- `cursor-api` 的模型清單來自靜態 Cursor 登錄檔（與
  IDE 提供者備援使用的清單相同）；OmniRoute 主機上無需安裝
  `cursor-agent`。
- `POST /api/providers/{id}/refresh-cursor` 僅適用於 `cursor` IDE 提供者；
  `cursor-api` 連線沒有需要續期的 IDE 工作階段。

## 原生模型 ID 與 effort

對於 `cursor` / `cu` 和 `cursor-api` / `cua`，共用的 Claude effort 正規化器
會保留所要求的模型 ID 不變。Cursor 可將像是
`-low` 的尾碼作為實際模型 ID 的一部分公開，而非作為 OmniRoute effort 別名。
Cursor 執行器會保留與即時目錄完全相符的項目；若沒有
相符項目，則由其現有的模型解析器負責將尾碼轉換為參數的備援處理。

這不會變更直接 Claude、Claude 相容或
Vertex 路由的 effort 正規化。可用性仍取決於所選 Cursor 帳戶的
目錄與權限。

## Cursor CLI 透傳

路由：`src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`。前綴 `/api/cursor-cli/` 已註冊於
`src/shared/constants/publicApiRoutes.ts`，因為處理常式會自行強制執行驗證：

| 路徑                                                                                                                       | CLI 預期的驗證方式            | OmniRoute 的處理方式                                                                                                            |
| -------------------------------------------------------------------------------------------------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                         | `Bearer <OmniRoute API 金鑰>` | 驗證金鑰、簽發有效期為 1 小時的 HS256 JWT（使用 `JWT_SECRET` 簽署），並將其傳回                                                 |
| 其他所有路徑（`/aiserver.v1.*`、`/agent.v1.AgentService/RunSSE`、`/aiserver.v1.BidiService/BidiAppend`、`/v1/traces`，……） | `Bearer <該 JWT>`             | 驗證簽發者、受眾與有效期，選擇有效的 `cursor-api` 連線，將 Authorization 標頭替換為交換取得的 Cursor 權杖，並以串流方式傳回回應 |

CLI 會解碼其收到之任何權杖中的 `exp`，因此若提供不透明權杖，會導致它幾乎在每次請求前都重新交換；簽發的 JWT 可避免此情況。若 OmniRoute 傳回 401，CLI 會再次交換。

### 設定

1. 建立 OmniRoute API 金鑰（儀表板 → API 金鑰）和 `cursor-api`
   連線。
2. 指示 CLI 對代理程式串流使用 HTTP/1.1。於
   `~/.cursor/cli-config.json` 中設定：

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   若未如此設定，CLI 會透過 HTTP/2 在另一個獨立設定的代理程式主機上開啟代理程式回合，只有控制平面 RPC 會經過此端點。

3. 透過 OmniRoute 執行 CLI：

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

每一個躍點都會記錄於「日誌」中，其中提供者為 `cursor-api`、請求類型為 `cursor-cli`、路徑為 `/api/cursor-cli/<rpc>`，並歸屬於 OmniRoute API 金鑰及處理該請求的連線。

### 失敗模式

| 情況                                        | 傳回 CLI 的回應                               |
| ------------------------------------------- | --------------------------------------------- |
| OmniRoute 金鑰不明且 `REQUIRE_API_KEY=true` | 交換時傳回 401 `unauthenticated`              |
| `REQUIRE_API_KEY=false`                     | 匿名工作階段（行為與 `/v1/*` 相同）           |
| 工作階段 JWT 已過期／來自外部／遭竄改       | 401，CLI 會重新交換                           |
| OmniRoute API 金鑰在交換後遭撤銷            | 下一次 RPC 時傳回 401                         |
| 沒有有效的 `cursor-api` 連線                | 503 `unavailable`                             |
| Cursor 拒絕該連線的金鑰                     | 401 `unauthenticated`，快取的工作階段會被捨棄 |
| 無法連線至上游                              | 502 `unavailable`（已清理敏感資訊的訊息）     |
| 未設定 `JWT_SECRET`                         | 交換時傳回 503                                |
