本文件記錄
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854) 的實作決策。公開產品以四個提供者系列表示。區域屬於連線資料，而非獨立產品。

## 決策

| 提供者系列                             | OmniRoute ID            | 全球區域 | 中國區域 |
| -------------------------------------- | ----------------------- | -------- | -------- |
| Alibaba Cloud Model Studio（隨用隨付） | `alibaba`               | 新加坡   | 北京     |
| Alibaba Cloud Token Plan               | `bailian-coding-plan`   | 新加坡   | 北京     |
| Qwen Cloud（隨用隨付）                 | `qwen-cloud`            | 全球     | 北京     |
| Qwen Cloud Token Plan                  | `qwen-cloud-token-plan` | 新加坡   | 北京     |

現有的 `alibaba-cn` ID 仍保留作為已儲存連線、模型路由、組合及歷史使用記錄的執行階段相容性別名。其儀表板卡片會合併至 `alibaba`；不需要重寫資料庫。

Qwen Cloud 隨用隨付與 Alibaba Cloud Model Studio 目前共用與 DashScope 相容的執行階段主機，但兩者仍維持為不同的提供者身分，因為使用者會透過不同的產品介面取得金鑰並管理帳戶。Alibaba 與 Qwen Cloud Token Plan 產品使用不同的端點系列，因此四種產品仍維持各自獨立的提供者 ID。

## 端點矩陣

| 提供者系列              | `global-sg`                                                              | `china-beijing`                                                      | 線路格式  |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | --------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI    |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI    |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI    |

API 金鑰與端點必須屬於相同的產品和區域。選取區域會變更驗證與一般請求所使用的預設端點。

## 連線契約

新連線會將穩定的區域鍵儲存在 `providerSpecificData` 中：

```json
{
  "region": "global-sg"
}
```

允許的值為 `global-sg` 和 `china-beijing`。端點會根據提供者 ID 與區域集中推導。非預設的 `providerSpecificData.baseUrl` 仍視為操作人員的明確覆寫設定，並具有較高優先順序；舊有已儲存的預設 URL 則會正規化回區域矩陣。

這可讓連線結構描述保持可擴充性：可以在解析器中新增其他區域，而不必建立另一張提供者卡片或變更已儲存的提供者 ID。

## 相容性與推出

1. 新增區域端點解析器，並保留目前的全域預設值。
2. 對 `alibaba`、其 `alibaba-cn` 相容性 ID，以及 `qwen-cloud` 使用即時區域 DashScope `/models` 探索。由於通用端點也會傳回影像、影片、音訊、嵌入及其他非聊天模型，因此其回應會先通過文字生成篩選器。接著，`qwen-cloud` 會套用其提供者登錄檔中宣告並持續維護的允許清單。儘管 Alibaba Model Studio 與 Qwen Cloud 目前共用執行階段主機，兩者仍各自維護獨立的精選目錄。
3. 使用目前 Token Plan 的文字模型允許清單登錄 `qwen-cloud-token-plan`。
4. 在新增／編輯連線對話方塊中加入具類型的區域選擇器。
5. 隱藏重複的 `alibaba-cn` 卡片，並將其現有連線納入 `alibaba` 提供者頁面。
6. 為進階及工作區特定的部署保留自訂端點覆寫功能。

Token Plan 媒體模型仍不包含在聊天目錄中，因為它們使用專用端點。`wan2.7-image` 和 `wan2.7-image-pro` 登錄於 `open-sse/config/imageRegistry.ts`；`happyhorse-1.1-i2v`、`happyhorse-1.1-t2v` 和 `happyhorse-1.1-r2v` 登錄於 `open-sse/config/videoRegistry.ts`。這兩個登錄檔都會重複使用 `qwen-cloud-token-plan` 連線識別身分及其區域特定憑證。

一般 Qwen Cloud 在 `qwen-cloud` 識別身分下具有獨立的隨用隨付影像與影片目錄。其影像模型為 `wan2.7-image-pro`、`wan2.7-image`、`qwen-image-3.0-pro`、`qwen-image-2.0-pro-2026-06-22`、`qwen-image-2.0-2026-03-03` 和 `z-image-turbo`。其影片模型為 `happyhorse-1.1-i2v`、`happyhorse-1.1-t2v`、`happyhorse-1.1-r2v`、`happyhorse-1.0-video-edit`、`wan2.7-t2v`、`wan2.7-i2v`、`wan2.7-r2v-2026-06-12` 和 `wan2.7-videoedit`。這些模型僅重複使用一般 `qwen-cloud` 連線和區域 DashScope 媒體端點。Token Plan 與隨用隨付登錄檔不會繼承或合併彼此的模型清單。

`bailian-coding-plan` 識別身分也有自己的媒體允許清單：用於影像生成的 `wan2.7-image`、`wan2.7-image-pro`、`qwen-image-2.0` 和 `qwen-image-2.0-pro`，以及用於影片生成的 `happyhorse-1.1-i2v`、`happyhorse-1.1-t2v` 和 `happyhorse-1.1-r2v`。它僅使用 Bailian Coding Plan 連線和區域 Coding Plan 端點。其影像與影片登錄檔不會從任一 Qwen Cloud 提供者繼承或與其合併。

一般 `alibaba` 識別身分具有獨立的影像與影片允許清單。其影像模型為 `qwen-image-3.0-pro`、`qwen-image-2.0-pro-2026-06-22`、`qwen-image-2.0`、`z-image-turbo` 和 `wan2.6-t2i`。其新增的影片模型為 `happyhorse-1.1-i2v`、`happyhorse-1.1-t2v`、`happyhorse-1.1-r2v`、`happyhorse-1.0-video-edit`、`wan2.7-i2v-2026-04-25`、`wan2.6-i2v-flash`、`wan2.7-t2v-2026-06-12`、`wan2.7-r2v-2026-06-12` 和 `wan2.7-videoedit`。這些模型僅使用 Alibaba Model Studio 連線及其所選的區域媒體端點；它們不會新增至任何 Coding Plan 或 Qwen Cloud 登錄檔。

Qwen Cloud Token Plan 聊天目錄遵循 Individual 方案的完全字串比對文字允許清單：`qwen3.8-max-preview`、`qwen3.7-max`、`qwen3.7-plus`、`qwen3.6-flash`、`glm-5.2` 和 `deepseek-v4-pro`。Wan 與 HappyHorse 項目屬於獨立的影像／影片生成 API。

Alibaba Token Plan 透過其 Anthropic 相容端點公開相同的六個目前文字生成模型 ID。其新加坡選項會儲存既有的 `global-sg` 區域鍵；只有面向使用者的標籤與將該區域稱為「全域」的其他提供者系列不同。

一般 Qwen Cloud 聊天目錄刻意設計得比完整的即時文字回應更精簡。其維護的允許清單位於 `open-sse/config/providers/registry/qwen-cloud/index.ts`；即時探索只會傳回同時存在於上游回應和該登錄檔清單中的 ID。

Alibaba Model Studio 遵循相同的即時交集規則，並使用其位於 `open-sse/config/providers/registry/alibaba/index.ts` 中獨立維護的允許清單。`alibaba-cn` 相容性提供者會重複使用該目錄，同時針對北京端點解析探索請求。
