中繼（Vercel、Deno、Cloudflare）會在無伺服器後端終止上游連線，讓 OmniRoute 能從穩定區域對外連線，同時將提供者 API 金鑰保留在伺服器端。本文說明維運人員在正式環境中會遇到的兩種故障模式，以及 OmniRoute 為每種模式提供的復原方式。

## 中繼驗證資訊的儲存方式

當您從 **設定 → Proxy Pool → 部署中繼** 部署中繼時，部署流程會將中繼的驗證權杖儲存在代理的 `notes` JSON 欄位中：

- 如果已設定 `STORAGE_ENCRYPTION_KEY`，權杖會以 `relayAuthEnc` 寫入（使用 AES 加密後靜態儲存）。
- 否則，權杖會以明文 `relayAuth` 寫入。

在請求時，`extractRelayAuth(notes)` 會傳回目前存在的形式，因此中繼在重新啟動後仍能繼續運作。

## 故障模式 1 — 金鑰輪替後無法解密權杖

**症狀：**先前可正常運作的中繼，在環境或祕密管理工具輪替 `STORAGE_ENCRYPTION_KEY` 後，開始傳回上游 `401`／驗證錯誤。已儲存的 `relayAuthEnc` 資料區塊無法再解密，因此 `extractRelayAuth` 會傳回空字串，而中繼不會傳送任何驗證資訊。

**復原方式 — 原地修復（無須重新部署）：**

1. 開啟 **設定 → Proxy Pool**。
2. 缺少驗證資訊的中繼資料列會顯示黃色的 `缺少驗證資訊` 徽章和 **修復** 按鈕。
3. 按一下 **修復**。OmniRoute 會呼叫
   `POST /api/settings/proxies/[id]/repair-relay`，此操作會：
   - 使用**目前的**金鑰解密 `relayAuthEnc`，
   - 將明文 `relayAuth` 寫回 `notes`，
   - 傳回 `{ repaired: true, mode: "recovered" }`。

中繼無須重新輸入任何部署認證資訊即可恢復服務。

只有在目前的 `STORAGE_ENCRYPTION_KEY` 仍可解密該資料區塊時，此方式才有效。如果您輪替金鑰時**未**執行移轉，該資料區塊將無法復原。

## 故障模式 2 — 無法復原的權杖（金鑰已被輪替）

**症狀：**您按下 **修復** 後收到
`{ repaired: false, mode: "redeploy", status: 409 }`。

**復原方式 — 重新部署：**

目前的金鑰無法復原已儲存的權杖。請從最初使用的相同對話方塊重新部署中繼（**部署中繼**選單 → Vercel / Deno / Cloudflare）。部署流程會寫入新的權杖（使用目前的金鑰加密），且該資料列的 `缺少驗證資訊` 徽章會消失。

在 UI 中，當權杖無法復原時，**修復**按鈕本身會觸發重新部署對話方塊，因此您不必手動尋找該功能。

## 故障模式 3 — 中繼可連線但狀況不良

**症狀：**代理測試（`speed` 按鈕）顯示中繼已啟動，但請求仍會間歇性失敗。

請檢查 OmniRoute 自動測試探查所傳回的中繼感知標頭（請參閱 **設定 → Proxy Pool** 及 `relayTested` / `relayAlive` 計數器）：

- `x-relay-url` — 回應的是哪個中繼後端。
- `x-relay-mode` — 該請求使用的模式：`ts` | `bifrost` | `auto`。
- `x-relay-attempts` — 成功前嘗試了多少個中繼躍點。
- `x-relay-fallback` — 當請求從偏好的後端回退至 TypeScript 中繼時為 `true`。

如果 `x-relay-fallback` 比率偏高且 `relayAlive` 偏低，表示 sidecar 後端狀況不良；您應修復該後端，或將中繼後端策略切換為 `ts`（請參閱 `RELAY_BACKEND_STRATEGY.md`）。

## API 參考

| 方法   | 路徑                                      | 主體                    | 成功                                                                                                             | 失敗                                                                            |
| ------ | ----------------------------------------- | ----------------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `POST` | `/api/settings/proxies/[id]/repair-relay` | `{ "id": "<proxyId>" }` | 重新衍生時為 `200 { repaired: true, mode: "recovered" }`；已存在明文時為 `200 { repaired: false, mode: "noop" }` | 無法復原時為 `409 { mode: "redeploy" }`；非中繼類型時為 `400`；找不到時為 `404` |

清單路由 `GET /api/settings/proxies` 會為每個項目附加不含祕密資訊的 `relayInfo: { isRelay, authMissing, repairMode }`，讓儀表板能在不暴露權杖的情況下顯示修復操作。
