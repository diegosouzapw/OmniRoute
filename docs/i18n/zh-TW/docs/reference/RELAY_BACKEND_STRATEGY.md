## 摘要

OmniRoute 現在針對 `/api/v1/relay/chat/completions` 支援三種中繼模式：

- `ts`：使用行程內的 TypeScript 中繼。
- `bifrost`：強制使用 Bifrost 閘道。
- `auto`：可用時優先使用 Bifrost，失敗時回退至 TypeScript。

當您以高請求速率運行時（每日大量 token、接近持續不間斷的輸送量），最佳策略是讓回退路徑保持明確且快速，確保熱路徑永遠不會因失效的 sidecar 而阻塞。

## 模式行為

- `ts`
  - 操作複雜度最低。
  - 所有路由與驗證都在 Node 中執行。
  - 可用性不依賴 sidecar。
- `bifrost`
  - 強制所有請求都經過 sidecar 閘道。
  - 不會自動回退。
  - 僅適合可保證 sidecar 健康狀態與延遲的情況。
- `auto`
  - sidecar 可連線且已啟用時便會使用。
  - 嘗試失敗會觸發回退標頭，並將流量導回 TS，使請求成功時間維持在可控範圍內。
  - 當正常運行時間比嚴格限定僅使用 sidecar 的路由更重要時，此模式是最安全的生產環境選擇。

## 目前的 9router 與 CLIPROXYAPI 比較

9router 與 CLIPROXYAPI 都是過去曾為上游提供者公開相容性路徑的整合項目。

- 9router 是用於上游協調與相容性行為的內嵌路徑。
- CLIPROXYAPI 是供 CLI / SDK 類型流量使用的代理 API 橋接器。
- 當您需要專用的 sidecar 類型躍點與低延遲的本機分派時，Bifrost 正逐步穩定成為外部化路徑。

如果您目前正在比較 9router/CLIPROXYAPI：

- 請在交接前，於 API 路由中保留請求簽署、允許清單檢查與 DB 政策閘門。
- 如果工作流程需要嚴格的 sidecar 行為及較低的單次請求變異，請使用 `OMNIROUTE_RELAY_BACKEND=bifrost`。
- 如果您需要 sidecar 韌性，並能在事故情況下優雅降級，請使用 `OMNIROUTE_RELAY_BACKEND=auto`。

## 後端邊界合約

穩定的產品邊界是 OmniRoute 中繼 API，而非儀表板實作。Next.js 儀表板可以安裝、設定及監管本機服務，但請求路由應從中繼 API 進入，並在該邊界後方進行交接。

長期後端選擇：

- 保留 TypeScript 中繼作為行程內政策與回退路徑。驗證、允許清單、請求正規化、計量與安全檢查都應在任何後端交接前留在此處。
- 當部署需要較低的路由變異、集中式提供者輪替，或跨多個 OmniRoute 複本進行水平擴充時，請使用 Bifrost 作為首選的高輸送量 Tier-1 sidecar。
- 保留 9router 與 CLIPROXYAPI 作為內嵌相容性服務。它們以受監管的本機程序執行；當其提供者/CLI 行為是所需的轉接器時便很有用，但不應成為預設的 Tier-1 路由引擎。
- 不要讓儀表板將任意服務 URL 傳入熱路徑。UI 提供的 URL 是設定輸入；路由程式碼應根據伺服器端設定與監管程式狀態，解析已註冊且通過健康檢查的後端。
- 目前對受監管服務應優先使用迴環 HTTP，因為受管理的程序已公開 HTTP 相容 API、路由防護機制可以稽核邊界，而且請求日誌中可看到失敗/回退行為。只有在未削弱隔離或回退語意的前提下，未來的 SDK 或 socket 傳輸能明顯降低 p99 路由延遲時，才值得加入。

因此，對於超高輸送量部署，預設答案是啟用 Bifrost 的 `auto`：在熱路徑上使用 Go sidecar，同時保留 TypeScript 回退機制以維持成功率。只有當嚴格限定僅使用 sidecar 的行為比優雅降級更重要時，才使用 `bifrost`。

## 高輸送量指南

針對持續的高 RPM/RPS 與嚴格的成功率 SLO：

1. 使用 `auto`，並搭配實用的冷卻時間與失敗遙測。
2. 將上游驗證與 API 金鑰檢查保留在 TypeScript 路由邊界上。
3. 啟用明確的標頭/計數器，讓您的警示系統能掌握回退頻率與原因。
4. 調整 sidecar 逾時設定，使其快速失敗，而非無限等待。
5. 維持服務自動重新啟動與健康狀態遙測迴圈正常運作，使回退真正成為例外情況。

## 建議基準設定

- `OMNIROUTE_RELAY_BACKEND=auto`
- `BIFROST_ENABLED=1`
- 在路由處理常式中保持啟用 API 金鑰、允許清單、清理器與速率限制檢查（這些檢查一律會在向下游轉送前執行）。
- 從反向代理與請求日誌匯出回退指標，確保能在一分鐘內察覺 sidecar 中斷。

## 提供者外掛程式合約

Sidecar 應透過 JSON 安全的提供者外掛程式資訊清單匯入提供者中繼資料，而非依賴 TypeScript 執行器內部機制。請參閱
[提供者外掛程式資訊清單](./PROVIDER_PLUGIN_MANIFEST.md)，以瞭解 sidecar
資格合約與遷移階段。
