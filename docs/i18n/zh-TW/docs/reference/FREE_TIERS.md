## TL;DR — OmniRoute 實際彙整了多少免費推論額度？

| 指標                                 | Token／月  | 含義                                                                                                                                                                                                                                                               |
| ------------------------------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

## 兩種機制 — 計算與判定

OmniRoute 透過兩種機制回答「是否免費？」；這兩種機制刻意讀取
不同的來源：

| 機制           | 真實來源                                                                                                                                                 | 適用介面                                                                                                 |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| **計算／顯示** | 已解析的目錄 — 以 Radar 摘要資訊（`getRadarCatalog`）覆蓋已發布的基準資料                                                                                | 免費方案總量、預算卡片、儀表板                                                                           |
| **判定**       | 僅限已發布的目錄（`open-sse/config/freeModelCatalog.data.ts` 中的 `FREE_MODEL_BUDGETS`），以及本機啟發式規則（`:free` 後綴、零定價、`grantsFreeAccess`） | `src/shared/utils/freeModels.ts` 的所有使用者：模型匯入、`auto/*` 路由、`GET /v1/models`，以及瀏覽器預覽 |

只要摘要資訊可用，計算結果便可隨時改進。判定則維持以
發布成品為準，因此瀏覽器與伺服器上的答案完全一致、
可離線重現，且無須資料庫即可測試。若讓瀏覽器
預覽讀取一個來源，而伺服器匯入讀取另一個來源，就會導致
預覽結果與點擊後實際發生的情況不一致 — 因此刻意保留
這項區分。

## 方法論與注意事項

- 數字是根據截至 **2026-06-17** 各提供者所記載之免費方案限制，透過網路研究整理出的**上限估計值**。免費方案經常變更——在依賴任何數字之前，請重新驗證。
- **每筆項目實際保證的內容。** 各筆項目都沒有逐列信心評等，API 也不提供此資訊——請將上述每個數字都視為品質相同但未明確說明的估計值。有兩項事實則不同，因為它們是人工整理而非推斷得出：44 筆項目具有獨立文件證實的硬性停止機制（其中 39 筆是 xKiro 列，它們共用相同的每日額度），另有 13 筆項目附有提示詞訓練揭露。只有當提供者自身條款明確指出，超出免費額度時會拒絕請求，而非在未明確告知的情況下開始計費，才會設定 `hardStopGuaranteed`，並在項目旁的註解中附上來源；它絕不會預設為 `true`，而未經任何人驗證的項目會維持未設定狀態。因此，缺少硬性停止旗標代表「尚未證實」，而不是「已知會向你收費」。**STRICT 模式**（選用的 `freeAccessPolicy=strict` 路由防護）只信任具有該旗標的項目；所有其他免費方案都會以 `no-hard-stop` 為由排除（請參閱 `open-sse/services/autoCombo/strictZeroCostFilter.ts`）。
- `estMonthlyFreeTokens` = 僅計算每月週期性提供的 token。**一次性註冊額度不會重複提供**，因此計為 0。已終止的方案也計為 0。
- 每日 token 上限 → `monthly = daily × 30`。若僅記載 RPD → `RPD × ~800 output tokens × 30`。若僅有 RPM/TPM（沒有每日上限）→ **無上限**（見下文）。
- **永久免費，但未公布 token 上限**（`siliconflow`、`glm-cn`、`tencent`、`baidu`、`kilo-gateway`、`opencode-zen`、`gemini`、`ollama-cloud`）：這些確實是持續提供的免費存取，但受速率／並行數限制。我們將其分類為 `recurring-uncapped`，且**絕不納入加總**——以 `RPM × 24/7 × 30d` 相乘會得出不切實際的虛構上限（這正是我們拒絕採用的膨脹算法）。列出它們是為了讓你知道這些方案確實存在。
- **儲值解鎖增額：**一次性的小額儲值，可永久提高免費配額（OpenRouter：$10 → 1000 req/day ≈ +24M/mo）。此數字會單獨呈現，不納入穩定持續額度的主要數字。
- **資格限制配額**（`eligibilityGate: "regional-identity"`）：這是真實且持續提供的配額，但只有通過地區限定的身分驗證後才會開放（目前為中國大陸實名驗證）。依照相同的額度池去重規則，計入獨立數字（`gatedRecurringTokens`），絕不納入穩定持續額度的主要數字。其方案類型（`freeType`）維持不變，因此路由行為也不變。
- **證據類別。** 規則如下：目錄中的數字會在項目旁的 `// evidence:` 註解中引用其來源——`public-page`（任何人皆可瀏覽的提供者頁面）、`api-public`（提供者無須驗證即可存取的端點，例如 NaraRouter 位於 router.bynara.id 的公開方案端點），或 `console-verified <date> por <who>`（該數字僅能在帳戶主控台內查看；註解會記錄查看者與查看日期，以及說明該上限確實存在的公開頁面）。目前狀態如下：於 2026-09-02 重新稽核的五個區塊均附有此資訊（`gemini`、`groq`、`mistral`、`ollama-cloud`、`nara`）；早於 2026-09-02 重新稽核的項目，在被更新前會沿用先前的研究結果；任何**新增或變更**但沒有證據註解的數字都屬於錯誤。目前只有 `mistral` 經過主控台驗證。

## 為什麼我們的數字比其他彙整服務小

這個領域中大多數的「每月免費 token」數字，都是將各模型標示的額度加總而成。我們刻意不這麼做：

- **每個共用額度池只計算一次。** Mistral 的免費方案是每個組織每月共用 1B 的額度；將它列在五個模型下並不會讓它變成 5B。若依模型加總，我們自己的目錄會顯示為 **~7.4B**（於 2026-09-03 重新計算；此數字不受 CI 檢查約束——每當目錄變更時都應重新測量）——標題寫的是 **~1.47B**，因為這才是每個提供者各一個帳戶實際可使用的額度。
- **每日上限會換算，速率限制則不會。** 有明確文件記載的 tokens/day 上限會換算成 `× 30`；有明確文件記載的 requests/day 上限會換算成 `RPD × ~800 tokens × 30`；若提供者只公布每分鐘請求數，則**不會**提供每月數字，而是列為_無上限_，且絕不納入加總。將速率限制乘以 24/7 正是我們拒絕採用的灌水方式。
- **需要區域身分驗證才能取得的額度會分開顯示**（`+~6M behind regional identity verification`），因為大多數讀者無法使用這些額度。
- **註冊點數僅適用於首月**，並會作為第二個數字單獨呈現，絕不混入穩定的常態數字中。
- **此數字由 CI 強制驗證。** `npm run check:docs-counts` 會根據目錄重新計算總額，並在此檔案、README 或預算卡片中的數字與計算結果不一致時，讓建置失敗。

## 詞彙表

| 術語                 | 含義                                                   |
| -------------------- | ------------------------------------------------------ |
| **RPM / RPD / RPH**  | 每分鐘／每日／每小時的請求數                           |
| **TPM / TPD**        | 每分鐘／每日的權杖數                                   |
| **有明文記載的額度** | 提供者公布明確的每日／每月權杖上限（可據以規劃的預算） |
| **理論上限**         | `rate-limit × 24/7 × 30d` — 最大值，而非已授予的預算   |
| **Neuron**           | Cloudflare 運算單位（約等於 1 個輸出權杖）             |
