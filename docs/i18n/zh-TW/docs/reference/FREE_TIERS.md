## 兩種機制——統計與判定

OmniRoute 透過兩種機制回答「是否免費？」；這兩種機制刻意讀取不同的來源：

| 機制           | 真實資料來源                                                                                                                                                 | 呈現／適用範圍                                                                                           |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| **統計／顯示** | 解析後的目錄——已發布的基準資料疊加 Radar 資料來源（`getRadarCatalog`）                                                                                       | 免費方案總量、預算卡片、儀表板                                                                           |
| **判定**       | 僅使用已發布的目錄（`open-sse/config/freeModelCatalog.data.ts` 中的 `FREE_MODEL_BUDGETS`），再加上本機啟發式規則（`:free` 後綴、零定價、`grantsFreeAccess`） | `src/shared/utils/freeModels.ts` 的所有使用端：模型匯入、`auto/*` 路由、`GET /v1/models`，以及瀏覽器預覽 |

只要資料來源可用，統計結果便可隨時改善。判定則維持使用發布成品，因此瀏覽器與伺服器上的答案完全一致，可離線重現，也能在不使用資料庫的情況下進行測試。若讓瀏覽器預覽讀取一個來源，而伺服器匯入讀取另一個來源，就會造成預覽結果與點擊後的實際行為不一致——因此刻意保留這種劃分。

## 方法論與注意事項

- 數字是根據截至 **2026-06-17** 各提供者文件所載免費方案限制，透過網路研究得出的**上限估算值**。免費方案隨時都可能變更——在依賴任何數字之前，請重新驗證。
- **各項目實際保證的內容。** 沒有任何項目具備逐列的可信度評等，API 也不提供此資訊——請將上述每個數字都視為品質相同但未明確說明的估算值。不過有兩類事實不同，因為它們是人工整理，而非推論得出：44 個項目具有獨立文件記載的硬性停止機制（其中 39 個是 xKiro 列，它們共用同一個每日額度），另有 13 個項目提供提示詞訓練用途的揭露資訊。只有當提供者自身條款明確指出，超出免費額度時會拒絕請求，而不是在未明確告知的情況下開始計費，才會設定 `hardStopGuaranteed`；來源會列在項目旁的註解中。此值絕不會預設為 `true`，而尚未經任何人驗證的項目會維持未設定狀態。因此，缺少硬性停止旗標代表「尚未確認」，而不是「已知會向你收費」。**STRICT 模式**（選擇啟用的 `freeAccessPolicy=strict` 路由防護機制）只信任帶有此旗標的項目；其他所有免費方案都會以 `no-hard-stop` 為由排除（請參閱 `open-sse/services/autoCombo/strictZeroCostFilter.ts`）。當防護機制篩選資源池時，操作人員可見的日誌會同時回報排除數量，以及其中 `no-hard-stop` 所占的比例。
- `estMonthlyFreeTokens` = 僅計算每月週期性提供的 token。**一次性註冊點數不會重複提供**，因此計為 0。已終止的方案也計為 0。
- 每日 token 上限 → `monthly = daily × 30`。若僅有 RPD 文件 → `RPD × ~800 output tokens × 30`。若僅有 RPM/TPM（無每日上限）→ **無上限**（見下文）。
- **永久免費，但未公布 token 上限**（`siliconflow`、`glm-cn`、`tencent`、`baidu`、`kilo-gateway`、`opencode-zen`、`gemini`、`ollama-cloud`）：這些確實是持續提供的免費存取，但受到速率／並行數限制。我們將其分類為 `recurring-uncapped`，並且**絕不加總**——以 `RPM × 24/7 × 30d` 相乘會得出不切實際的理論上限（這正是我們拒絕採用的膨脹估算）。列出這些項目是為了讓你知道它們確實存在。
- **儲值解鎖加成：** 一次性的小額儲值，可永久提高免費額度（OpenRouter：$10 → 每日 1000 個請求 ≈ 每月額外 +24M）。此數字會單獨回報，不計入穩定額度的主要數字。
- **受資格條件限制的額度**（`eligibilityGate: "regional-identity"`）：這是真實且週期性提供的額度，但只有在完成與特定地區綁定的身分驗證後才會開放（目前為中國大陸實名認證）。依照相同的資源池去重規則，計入獨立數字（`gatedRecurringTokens`），絕不納入穩定額度的主要數字。其制度類型（`freeType`）維持不變，因此路由行為也不變。
- **證據類別。** 規則如下：目錄中的數字會在項目旁的 `// evidence:` 註解中註明來源——`public-page`（任何人都能閱讀的提供者頁面）、`api-public`（提供者不需驗證即可存取的端點，例如 NaraRouter 位於 router.bynara.id 的公開方案端點），或 `console-verified <date> por <who>`（該數字僅能在帳戶控制台內查看；註解會記錄查看者及查看日期，以及說明該上限確實存在的公開頁面）。目前狀態如下：於 2026-09-02 重新稽核的五個區塊均帶有此資訊（`gemini`、`groq`、`mistral`、`ollama-cloud`、`nara`）；早於 2026-09-02 重新稽核的項目，在更新前沿用先前的研究結果；任何**新增或變更**但沒有證據註解的數字都屬於錯誤。目前只有 `mistral` 經控制台驗證。

## 為何我們的數字比其他彙整平台更小

在這個領域中，大多數「每月免費 token」數字都是各模型標示額度的總和。我們刻意不這麼計算：

- **每個共享額度池只計算一次。** Mistral 的免費方案是每個組織每月共享 1B 額度；將它列在五個模型之下，並不會讓額度變成 5B。若按模型加總，我們自己的目錄會顯示為 **~7.4B**（於 2026-09-03 重新計算；此數字不受 CI 檢查限制——每當目錄變更時都應重新測量）——標題顯示 **~1.47B**，因為這才是每個提供者各一個帳號實際能使用的額度。
- **每日上限會換算，速率限制則不會。** 有明確文件記載的每日 token 上限會以 `× 30` 換算；有明確文件記載的每日請求上限會以 `RPD × ~800 tokens × 30` 換算；若提供者只公布每分鐘請求數，則**不會**提供每月數字，並會標示為_無上限_，絕不納入加總。我們拒絕以全天候 24/7 運作為前提來乘算速率限制，因為這會灌水數字。
- **需要區域身分驗證才能取得的額度會另外列出**（`+~6M behind regional identity verification`），因為大多數讀者無法使用這些額度。
- **註冊贈送額度僅適用於第一個月**，並以第二個數字另行呈現，絕不混入穩定的常態數字。
- **此數字由 CI 強制驗證。** `npm run check:docs-counts` 會根據目錄重新計算總額；當此檔案、README 或預算卡片中的數字與其不一致時，建置就會失敗。

## OpenCode Free：用戶端合約限制 (#14313)

無金鑰的 `opencode` 提供者（公開的 `https://opencode.ai/zen/v1`）會拒絕任何不符合 OpenCode 用戶端合約的請求，並傳回 **403 `FreeTierError`** 以及句子 _「OpenCode 的免費方案只能在 OpenCode 內使用」_。這是針對請求範圍的拒絕（對於相同的請求形態，每個帳戶都會得到相同的判定），而不是模型封鎖或連線冷卻——OmniRoute 將其分類為 `project_route_error`、略過模型鎖定／冷卻，並且（在合成的 `noauth` 路徑上）於短暫的 TTL 期間暫停自動組合重新選擇。請傳送包含非空工具清單、`stream: true`，以及 OpenCode 工作階段／UA 標頭（`opencodeFreeTierContract.ts`）的請求，否則預期會收到 403。

## 詞彙表

| 詞彙                 | 含義                                                          |
| -------------------- | ------------------------------------------------------------- |
| **RPM / RPD / RPH**  | 每分鐘／每天／每小時的請求數                                  |
| **TPM / TPD**        | 每分鐘／每天的 Token 數                                       |
| **有文件記載的配額** | 提供者公布明確的每日／每月 Token 上限（可作為可靠依據的額度） |
| **理論上限**         | `rate-limit × 24/7 × 30d` — 最大值，而非獲配的額度            |
| **Neuron**           | Cloudflare 運算單位（約等於 1 個輸出 Token）                  |

> 根據 2026-06-05 各提供者的研究資料產生。若要更新，請重新執行研究工作流程（請參閱 `_tasks/features-v3.8.12`）。
