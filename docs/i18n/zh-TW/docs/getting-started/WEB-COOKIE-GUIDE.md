Web Cookie 提供者可讓 OmniRoute 透過您現有的瀏覽器工作階段使用 AI 服務，而不需使用 API 金鑰。當您已經可以透過某項服務的網站進行存取，並希望 OmniRoute 使用相同的已驗證工作階段時，這類提供者非常實用。

與 API 金鑰提供者不同，Web Cookie 提供者使用瀏覽器傳送給網站的憑證進行驗證。

---

# 開始之前

> **重要：** 一律從**即時網路請求**複製憑證，**不要**從瀏覽器的 Cookie 儲存區複製。

許多驗證問題都是因為從錯誤的位置複製 Cookie 所造成。

## 請勿從 Cookie 儲存區複製

大多數瀏覽器會透過以下位置顯示已儲存的 Cookie：

```
DevTools
→ Application（或 Storage）
→ Cookies
```

雖然這些 Cookie 看起來正確，但它們可能：

- 已過期
- 不完整
- 缺少僅在已驗證請求中傳送的 Cookie

即使這些值看起來有效，使用它們仍可能導致驗證失敗。

## 從即時請求複製

請改為使用成功請求中的 Cookie：

```
DevTools
→ Network
→ 重新整理頁面
→ 開啟聊天或對話請求
→ Request Headers
→ Cookie
```

`Cookie` 請求標頭包含瀏覽器成功使用的確切驗證資訊。

對大多數 Web Cookie 提供者而言，這就是應貼到 OmniRoute 中的值。

# 一般設定

大多數 Web Cookie 提供者的設定流程都相同。

1. 登入提供者的網站。
2. 開啟瀏覽器的開發人員工具。
3. 開啟 **Network** 分頁。
4. 重新整理頁面。
5. 開啟已驗證的聊天或對話請求。
6. 複製所需的驗證憑證。
7. 開啟 OmniRoute。
8. 前往 **Providers → Add Provider**。
9. 選取您的 Web Cookie 提供者。
10. 貼上憑證。
11. 按一下 **Test Connection**。
12. 儲存提供者。

確切所需的憑證取決於提供者。

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) 是一個免費的消費者聊天平台，無須註冊——首次造訪時會匿名建立工作階段，並透過三個 Cookie 持續保存：`uid`、`si_usr_id` 和 `si_ses_id`。OmniRoute 透過單一模型 ID（`notrack-c`，別名 `ntw`）代理相同的 `/api/dispatch` 端點。

### 連線步驟

1. 在瀏覽器中開啟 [notrack.ai](https://notrack.ai)，並讓網站設定匿名工作階段 Cookie。
2. 開啟**開發人員工具 → 網路**，重新整理頁面，然後點選任何 `/api` 請求。
3. 在**要求標頭**中，複製完整的 `Cookie` 標頭值。
4. 在 OmniRoute 中，前往**提供者 → 新增提供者 → NoTrack Web（免費）**。
5. 將 Cookie 字串貼入 `apiKey` 欄位，然後按一下**儲存**。

OmniRoute 會從貼上的字串中擷取 `uid`、`si_usr_id` 和 `si_ses_id`，並重新建立僅包含這些鍵值對的乾淨 `Cookie` 標頭；如果存在 `nt_session`（為已登入帳戶設定的 `ntk_…` 權杖），也會一併加入。若三者中有任何一個缺少，系統會原封不動地轉送所貼上的原始字串，讓操作人員可以嘗試其他格式。

### 模型 ID

| 模型 ID     | 顯示名稱  | 備註                                     |
| ----------- | --------- | ---------------------------------------- |
| `notrack-c` | NoTrack C | 預設——上游分派模型 `C`。                 |
| `C`         | NoTrack C | `notrack-c` 的別名（原始上游分派代碼）。 |
| `notrack`   | NoTrack C | `notrack-c` 的別名。                     |
| `ntw`       | NoTrack C | `notrack-c` 的簡短別名。                 |

這四個模型 ID 全都對應至相同的上游分派模型（`C`）。

### 請求選項

執行器接受請求本文中的下列選填欄位：

| 本文欄位              | 預設值  | 用途                                            |
| --------------------- | ------- | ----------------------------------------------- |
| `notrack_mode`        | `usual` | 分派模式（自由格式字串；上游接受 `usual` 等值） |
| `notrack_max_turns`   | `6`     | 上游在回答前可進行的內部輪次數量。              |
| `notrack_chat_id`     | `null`  | 繼續既有的上游聊天（若要開始新聊天，請省略）。  |
| `notrack_attachments` | `[]`    | 直接傳遞的上游附件描述元陣列。                  |
| `notrack_regenerate`  | `false` | 設為 `true`，可要求針對上一輪重新產生回答。     |

### 功能

- **串流與非串流**聊天補全。
- **工具呼叫**——在請求中設定 `tools: [...]`；執行器會將其序列化為工具呼叫封套合約，並將模型的回應解析回 OpenAI `tool_calls`。
- **`response_format`**——支援 `json_object` 和 `json_schema`。執行器會從模型回覆中擷取第一個 JSON 物件，將其字串化後再傳回。
- **推理提示**——當上游傳送 `thinking` 事件時，執行器會發出 `reasoning` 增量。

### 限制

- 上游會對匿名使用量實施配額限制——觸發限制時，執行器會傳回 429，並附上易於理解的訊息。
- 所有模型 ID 都會解析至相同的上游分派模型；無法依模型進行切換。
- 執行器不會呼叫上游的 `/api/chats` 端點，因此不會自動管理聊天記錄／工作階段。請使用 `notrack_chat_id` 繼續既有的上游聊天。

# Web Cookie 提供者能做與不能做的事

Web Cookie 提供者會重複使用網站的聊天介面。它們**不會**提供與官方 API 相同的功能。

## 支援項目

- 使用現有的瀏覽器工作階段進行驗證
- 存取您帳戶可用的模型
- 串流聊天回應
- 不需要 API 金鑰

## 不支援項目

- 函式呼叫
- 工具呼叫
- 自動編輯檔案
- 代理式 IDE 工作流程
- 僅限 API 的功能

這是預期行為，**不是**錯誤。

如果您需要執行工具、自動編輯檔案或其他代理工作流程，請使用 **API 金鑰提供者**，而非 Web Cookie 提供者。

# 驗證注意事項

成功的 **Test Connection** 或 Cookie 驗證僅表示所提供的憑證格式似乎符合預期。

在 Issue #7857 解決之前，驗證成功**並不保證**提供者能成功完成身分驗證。

如果身分驗證仍然失敗，請確認您是從即時網路請求中複製憑證，而非從瀏覽器 Cookie 儲存區中複製。

---

# 疑難排解

## 身分驗證失敗

請確認憑證是從以下位置複製：

```
Network
→ Request Headers
→ Cookie
```

而**不是**從以下位置複製：

```
Application
→ Cookies
```

---

## Cookie 可在瀏覽器中使用，但無法在 OmniRoute 中使用

部分提供者包含只會在已驗證的請求期間傳送的 Cookie。

成功開啟對話後，請從新的網路請求中重新複製憑證。

---

## 工作階段已過期

Web Cookie 提供者會使用您現有的瀏覽器工作階段。

如果瀏覽器工作階段過期或您登出，就必須複製一組新的憑證。若要自動更新受支援 Web 提供者的 Cookie，請參閱配套工具 [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md)。

---

## Test Connection 通過，但請求失敗

在 Issue #7857 解決之前，通過驗證並不保證身分驗證請求能夠成功。

在進一步排解問題之前，請從新的已驗證請求中重新複製憑證。

# 最佳實務

- 從新的已驗證請求中複製憑證。
- 避免重複使用舊 Cookie。
- 使用 Web Cookie 提供者時，請保持瀏覽器工作階段有效。
- 將複製的 Cookie 視為敏感憑證。
- 需要函式呼叫或代理工作流程時，請使用 API 金鑰提供者。
