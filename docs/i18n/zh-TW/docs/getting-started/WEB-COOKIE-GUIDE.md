Web Cookie 提供者可讓 OmniRoute 透過您現有的瀏覽器工作階段使用 AI 服務，而無需 API 金鑰。當您已能透過某項服務的網站存取該服務，並希望 OmniRoute 使用相同的已驗證工作階段時，這類提供者非常實用。

與 API 金鑰提供者不同，Web Cookie 提供者會使用瀏覽器傳送至網站的憑證進行驗證。

---

# 開始之前

> **重要：**請務必從**即時網路請求**複製憑證，**不要**從瀏覽器的 Cookie 儲存空間複製。

許多驗證問題都是因為從錯誤的位置複製 Cookie 所造成的。

## 請勿從 Cookie 儲存空間複製

大多數瀏覽器都會透過以下位置顯示已儲存的 Cookie：

```
開發人員工具
→ 應用程式（或儲存空間）
→ Cookie
```

雖然這些 Cookie 看起來正確，但它們可能：

- 已過期
- 不完整
- 缺少僅在已驗證請求中傳送的 Cookie

即使這些值看起來有效，使用它們仍可能導致驗證失敗。

## 從即時請求複製

請改為使用成功請求中的 Cookie：

```
開發人員工具
→ 網路
→ 重新整理頁面
→ 開啟聊天或對話請求
→ 請求標頭
→ Cookie
```

`Cookie` 請求標頭包含瀏覽器成功使用的確切驗證資訊。

對大多數 Web Cookie 提供者而言，這就是應貼入 OmniRoute 的值。

---

# 一般設定

大多數 Web Cookie 提供者的設定流程都相同。

1. 登入提供者的網站。
2. 開啟瀏覽器的開發人員工具。
3. 開啟**網路**分頁。
4. 重新整理頁面。
5. 開啟已驗證的聊天或對話請求。
6. 複製所需的驗證憑證。
7. 開啟 OmniRoute。
8. 前往**提供者 → 新增提供者**。
9. 選取您的 Web Cookie 提供者。
10. 貼上憑證。
11. 按一下**測試連線**。
12. 儲存提供者。

所需的確切憑證取決於提供者。

# Web Cookie 提供者可以與無法執行的操作

Web Cookie 提供者會重複使用網站的聊天介面。它們**不會**提供與官方 API 相同的功能。

## 支援

- 使用您現有的瀏覽器工作階段進行驗證
- 存取您帳戶可用的模型
- 串流聊天回應
- 不需要 API 金鑰

## 不支援

- 函式呼叫
- 工具呼叫
- 自動編輯檔案
- 代理式 IDE 工作流程
- 僅限 API 的功能

這是預期行為，**不是**錯誤。

如果您需要執行工具、自動編輯檔案或其他代理工作流程，請使用 **API 金鑰提供者**，而不是 Web Cookie 提供者。

---

# 驗證注意事項

成功完成**測試連線**或 Cookie 驗證，只代表所提供的憑證看起來符合預期格式。

在 Issue #7857 解決之前，驗證成功**不保證**提供者能夠成功完成身分驗證。

如果驗證仍然失敗，請確認您是從即時網路請求複製憑證，而不是從瀏覽器的 Cookie 儲存空間複製。

---

# 疑難排解

## 驗證失敗

請確認憑證是從以下位置複製：

```
網路
→ 請求標頭
→ Cookie
```

而**不是**從以下位置複製：

```
應用程式
→ Cookie
```

---

## Cookie 在瀏覽器中有效，但在 OmniRoute 中無效

有些提供者包含僅在已驗證請求期間傳送的 Cookie。

成功開啟對話後，請從新的網路請求重新複製憑證。

---

## 工作階段已過期

Web Cookie 提供者會使用您現有的瀏覽器工作階段。

如果瀏覽器工作階段過期或您登出，則必須複製一組新的憑證。

---

## 測試連線通過，但請求失敗

在 Issue #7857 解決之前，通過驗證不保證驗證請求一定會成功。

進一步進行疑難排解之前，請從新的已驗證請求重新複製憑證。

# 最佳實務

- 從新的已驗證請求複製憑證。
- 避免重複使用舊 Cookie。
- 使用 Web Cookie 提供者時，請讓瀏覽器工作階段保持有效。
- 將複製的 Cookie 視為敏感憑證。
- 需要函式呼叫或代理工作流程時，請使用 API 金鑰提供者。
