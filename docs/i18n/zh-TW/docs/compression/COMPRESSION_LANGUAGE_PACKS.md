穴居人壓縮除了內建的英文規則外，還可以載入特定語言的規則套件。
這可讓核心引擎保持穩定，同時允許葡萄牙文、西班牙文、德文、法文、義大利文、日文以及
未來的語言套件各自獨立演進。

## 位置

語言套件位於：

```txt
open-sse/services/compression/rules/<language>/
```

目前隨附的套件（已依據 `rules/` 目錄內容驗證）：

| 語言             | 目錄           | 現有規則類別                                        |
| ---------------- | -------------- | --------------------------------------------------- |
| 英文             | `rules/en/`    | `context`、`dedup`、`filler`、`structural`、`ultra` |
| 西班牙文         | `rules/es/`    | `context`、`dedup`、`filler`、`structural`、`ultra` |
| 葡萄牙文（巴西） | `rules/pt-BR/` | `context`、`dedup`、`filler`、`structural`、`ultra` |
| 印尼文           | `rules/id/`    | `context`、`dedup`、`filler`、`structural`、`ultra` |
| 義大利文         | `rules/it/`    | `context`、`dedup`、`filler`、`structural`、`ultra` |
| 德文             | `rules/de/`    | `context`、`filler`、`structural`                   |
| 法文             | `rules/fr/`    | `context`、`filler`、`structural`                   |
| 日文             | `rules/ja/`    | `context`、`filler`、`structural`                   |

> **完整性備註：** `en`、`es`、`pt-BR`、`id` 和 `it` 套件具備完整的 5 個類別；`de`、`fr`、`ja` 隨附 3 個類別。缺少的 `dedup` 和 `ultra` 類別會自動且不另行提示地回退至內建的英文規則。歡迎貢獻，為較小的套件新增 `dedup.json` 和 `ultra.json`。
>
> `pt-BR` 套件以 Lenine Júnior 的 **[Troglodita](https://github.com/leninejunior/troglodita)** 為基礎——這是一套專為巴西葡萄牙文文法從零設計的壓縮系統（減少贅語、移除 PT-BR 填充詞，以及提供巴西開發者社群使用的技術縮寫）。
>
> 標準類別清單和各類別結構描述位於 [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json)（JSON Schema draft 2020-12）。

## 語言偵測

`languageDetector.ts` 使用輕量級啟發式方法，從提示文字推斷語言。
設定的預設語言仍會受到尊重；如需精確控制，也可以透過設定停用偵測。

偵測結果僅用於選擇規則套件，不會變更提供者路由、地區設定
選擇或 UI 語言。

## 設定結構

壓縮設定可包含：

```json
{
  "languageConfig": {
    "enabled": true,
    "defaultLanguage": "en",
    "autoDetect": true,
    "enabledPacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  },
  "cavemanConfig": {
    "language": "en",
    "autoDetectLanguage": true,
    "enabledLanguagePacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  }
}
```

`languageConfig` 控制儀表板／預覽的預設值。`cavemanConfig` 是穴居人壓縮訊息文字時
所使用的執行階段引擎設定。

## 新增語言套件

1. 建立 `open-sse/services/compression/rules/<language>/<pack>.json`。
2. 使用 `docs/compression/COMPRESSION_RULES_FORMAT.md` 中的 Caveman 規則格式。
3. 採取保守的替換方式，避免變更程式碼、識別碼、URL 或 JSON。
4. 新增或更新語言選擇與替換行為的測試。
5. 如果該語言會出現在 UI 選擇器中，請公開新的儀表板/i18n 標籤。

## API

可使用以下方式查詢可用的套件：

```bash
curl http://localhost:20128/api/compression/language-packs
```

預覽端點接受語言設定覆寫：

```bash
curl -X POST http://localhost:20128/api/compression/preview \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "standard",
    "text": "Por favor, eu gostaria que voce basicamente resumisse isso.",
    "config": {
      "languageConfig": {
        "defaultLanguage": "pt-BR",
        "autoDetect": true
      }
    }
  }'
```

## SHARED_BOUNDARIES (v3.8.0)

在 v3.8.0 中，所有 6 個語言套件都加入了 `SHARED_BOUNDARIES` 子句，並套用於每個
Caveman 強度（LITE、FULL、ULTRA）。它會指示引擎逐字保留以下模式，
不受周圍填充內容移除作業的影響：

| 模式類型                | 範例                                   |
| ----------------------- | -------------------------------------- |
| 圍欄式程式碼區塊        | ` ```python\n...\n``` `                |
| 行內程式碼              | `` `my_var` ``                         |
| URL                     | `https://example.com/path`             |
| 檔案路徑（絕對 + 相對） | `/etc/hosts`, `./src/index.ts`         |
| 錯誤標頭                | `Error:`, `TypeError:`, `SyntaxError:` |
| 堆疊追蹤行              | `  at functionName (file.ts:12:3)`     |

這些模式會填入 `DEFAULT_CAVEMAN_CONFIG.preservePatterns`（先前為 `[]`）。
此常數位於 `open-sse/services/compression/types.ts`。

### 為何這很重要

如果沒有 SHARED_BOUNDARIES，積極的 Caveman 模式可能會移除看起來像重複
散文、但實際上是程式碼片段、檔案路徑或錯誤堆疊的內容。SHARED_BOUNDARIES 會作為
不受語言影響的安全網，在執行填充內容規則之前套用。

### 自訂 preservePatterns

可在執行階段透過壓縮設定新增其他模式：

````json
{
  "cavemanConfig": {
    "preservePatterns": [
      "```[\\s\\S]*?```",
      "`[^`]+`",
      "https?://\\S+",
      "(?:/|\\./)[^\\s]+",
      "\\b(?:Error|TypeError|SyntaxError|RangeError):",
      "\\s+at\\s+\\S+\\s+\\(\\S+:\\d+:\\d+\\)"
    ]
  }
}
````

自訂模式會擴充（而非取代）這 6 個預設模式。

## 操作注意事項

- 缺少語言套件時，仍會使用內建英文規則作為備援。
- 無效的內建 JSON 套件將無法通過驗證，以免發布資產在沒有任何提示的情況下劣化。
- 規則套件僅包含資料，不應匯入程式碼或執行任意邏輯。
- 壓縮分析層會記錄所選的模式與引擎，而不會記錄完整的提示文字。
