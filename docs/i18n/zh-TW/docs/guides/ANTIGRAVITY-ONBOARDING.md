## 1. Antigravity 與 Antigravity CLI (agy) 比較

兩個提供者共用**相同的 Google 後端**，包括完全相同的 OAuth 用戶端、權杖重新整理機制、端點及 Google 帳戶。兩者的差異在於您可看到哪些模型。

> 如需 Google 的官方比較，請參閱 [Antigravity CLI 發布公告](https://antigravity.google/blog/introducing-google-antigravity-cli)。

| 面向                | `antigravity` (IDE)                   | `agy` (CLI)                                     |
| ------------------- | ------------------------------------- | ----------------------------------------------- |
| **Google 產品**     | Antigravity 2.0 / Antigravity IDE     | Antigravity CLI                                 |
| **後端**            | 相同的 Google Cloud Code API          | 相同的 Google Cloud Code API                    |
| **OAuth / 權杖**    | 相同用戶端、相同重新整理機制          | 相同用戶端、相同重新整理機制                    |
| **模型目錄**        | 靜態精選清單（硬編碼於 OmniRoute）    | 透過 `:fetchAvailableModels` 從 Google 即時探測 |
| **Claude 模型**     | Sonnet 4.6、Opus 4.6（各有 4 種變體） | Sonnet 4.6、Opus 4.6（各有 4 種變體）           |
| **Gemini 命名方式** | 清楚的標籤（Low/Medium/High）         | 上游 ID（extra-low/low/agent）                  |
| **額外模型**        | `gpt-oss-120b-medium`                 | 可能包含 Google 提供的其他模型                  |
| **預設使用情境**    | IDE 整合（VS Code、JetBrains）        | CLI / API 存取                                  |
| **配額**            | 與 agy 共用（相同的 Google 帳戶）     | 與 antigravity 共用（相同的 Google 帳戶）       |

**可用模型（已透過實驗驗證，2026-07-29）**：

- Gemini：3.6 Flash、3.5 Flash、3.1 Pro、3 Flash、2.5 Flash（具備不同的思考層級）
- Claude：Sonnet 4.6、Opus 4.6（各自提供 default/low/medium/high 變體）
- 其他：GPT-OSS 120B Medium
- **Claude Sonnet 5 並不可用**——僅支援 4.6 變體

**模型目錄不同的原因**：根據 Google 官方部落格所述，Google 的 CLI「針對速度與低額外負擔進行最佳化」，並「與 Gemini 模型共同最佳化」。Web/IDE 產品則「針對完整性進行最佳化」。CLI 使用 `:fetchAvailableModels` 動態探索模型，而 IDE 則使用靜態精選清單。

**實際使用方式**：Gemini 模型請使用 `agy/` 前綴（例如 `agy/gemini-3.7-flash-high`）。若要使用靜態精選清單，請使用 `antigravity/`。兩者皆連線至相同的 Google 後端，但公開的模型命名方式不同。配額為共用——使用任一提供者都會計入同一個 Google 帳戶的限制。

## 2. Google One AI Pro：配額系統

> 如需官方配額詳細資訊，請參閱 [Antigravity 文件：方案](https://antigravity.google/docs/plans)；如需最新價格更新，請參閱 [Antigravity 方案變更](https://antigravity.google/blog/changes-to-antigravity-plans)。

Google Antigravity 採用以「完成的工作量」（運算權重）而非訊息數量為基礎的**雙層配額**。

### 兩個層級

| 層級               | 說明                             | 更新週期                                                     |
| ------------------ | -------------------------------- | ------------------------------------------------------------ |
| **5 小時短期配額** | 可立即使用的「已完成工作量」額度 | 在工作階段中的首次請求後 5 小時重設                          |
| **7 天基準配額**   | 每週硬性上限                     | 若達到上限，將覆蓋 5 小時更新機制；鎖定至下一個 7 天週期為止 |

**「完成的工作量」如何計算**：大量使用代理程式的任務（例如「重構整個儲存庫」）會比簡單任務（例如「修正這個函式」）更快耗盡配額。目前沒有可顯示即時用量的儀表板。

### 方案級別

| 方案         | 價格       | 配額                      | 每週限制                          |
| ------------ | ---------- | ------------------------- | --------------------------------- |
| Free         | $0         | 足量配額，每週更新        | 有                                |
| AI Pro       | $19.99/月  | 高配額，每 5 小時滾動更新 | 有（若達上限，將覆蓋 5 小時更新） |
| AI Ultra 5x  | $99.99/月  | Pro 配額的 5 倍           | 無每週限制                        |
| AI Ultra 20x | $199.99/月 | Pro 配額的 20 倍          | 無每週限制                        |

### Gemini 與非 Gemini 模型

- **Gemini 模型**（Flash + Pro）：共用單一速率限制，並依 API 定價扣除額度。如果 Flash 比 Pro 便宜 8 倍，您就能取得 8 倍的 Flash 權杖。
- **非 Gemini 模型**（Claude、GPT-OSS）：具有**獨立的**速率限制。即使 Gemini 已遭鎖定，這些模型仍可能可以使用。

### AI 點數（超額用量）

> 如需瞭解點數的運作方式，請參閱 [Google One AI 點數](https://support.google.com/googleone/answer/14534406)。

當基準配額用盡時：

- **永不使用**：等待配額更新；顯示「已達基準模型配額」
- **一律使用**：自動使用 AI 點數；基準配額更新後切換回基準配額

點數需另行購買，並依標準 API 定價扣除。

### 重要詳細資訊

- 配額是**帳戶層級共用**的——Antigravity IDE、CLI 和 OmniRoute 中的同一個 Google 帳戶會共用一個配額集區
- 每個 Google 帳戶都有各自獨立的配額——多個帳戶 = 多個配額集區
- AI Pro 使用者曾回報，在達到每週基準上限後遭到**鎖定 7 天**，而非每 5 小時重設（Google 已確認，這是針對高需求而刻意設計的機制）

**當您的帳戶配額用盡時**：OmniRoute 會自動使用組合路由中的下一個可用帳戶重試。無需手動介入。

## 3. 如何取得 projectId

每個 antigravity/agy 連線都需要 Google Cloud Code `projectId`。若未提供，`/v1internal:models` 端點會傳回 404。

### 方法 A：自動取得（建議）

OmniRoute 會自動處理此程序。當您透過儀表板 OAuth 新增 Google 帳戶時：

1. OmniRoute 更新權杖
2. 呼叫 `loadCodeAssist` 以探索 projectId
3. 如果專案不存在，則呼叫 `onboardUser` 建立專案
4. 重試 `loadCodeAssist` 以取得新建立的 projectId
5. 將其儲存至資料庫

**這適用於大多數帳戶**——無需手動操作。

### 方法 B：透過 agy CLI 手動取得

如果自動探索失敗（何時會發生此情況，請參閱第 5 節）：

```bash
# 安裝 agy CLI（若尚未安裝）
npm install -g @anthropic-ai/agy

# 使用您的 Google 帳戶登入
agy login

# 選取需要進行初始設定的帳戶
# 這會觸發 Cloud Code 註冊並指派 projectId
```

`agy login` 成功後，請在 OmniRoute 儀表板中更新權杖。系統將自動探索 projectId。

### 如何驗證

檢查資料庫：

```bash
# 在 OmniRoute 容器內
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

或檢查記錄：

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. OAuth 重新導向 URI

### 問題

Google OAuth 需要有效的重新導向 URI。OmniRoute 預設使用 `http://127.0.0.1:20128/callback`（回送位址）。這適用於本機建置，但在**遠端部署時會失敗**（例如，透過區域網路 IP 存取的伺服器）。

Google 會拒絕以下重新導向 URI：

- 使用 IP 位址（必須是以 `.com`、`.org` 等結尾的網域）
- 與 OAuth 用戶端設定中已註冊的重新導向 URI 不符

### 解決方案

**選項 A：使用內建 OAuth 流程（預設）**

- 適用於從 `localhost` 或 `127.0.0.1` 存取 OmniRoute
- 無需設定

**選項 B：自訂 OAuth 憑證**

- 在您的環境中設定 `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web`
- 提供您自己的 Google OAuth 憑證：
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- 在 Google Cloud Console 中將 `https://your-domain.com/callback` 註冊為已授權的重新導向 URI

**選項 C：使用 agy CLI 進行初次登入**

- 在將存取 OmniRoute 的機器上執行 `agy login`
- OAuth 流程會在本機完成，並儲存權杖
- 透過 Dashboard 將連線匯入 OmniRoute

### 限制

- 自訂 OAuth 憑證需要網域名稱（Google 不接受以 IP 位址作為重新導向 URI）
- 如果您沒有網域，請改用選項 A 或 C

## 5. 疑難排解：自動設定失敗時

對於大多數帳戶，OmniRoute 會自動處理 projectId 探索及初始設定。若處理失敗，根本原因通常是以下其中之一：

### 帳戶區域遭封鎖

**症狀**：`agy login` 回傳「Eligibility check failed: Your current account is not eligible for Antigravity, because it is not currently available in your location.」

**根本原因**：Google 帳戶在註冊時會設定後端的「Country Association」欄位。agy CLI 與 Cloud Code API 會嚴格檢查此欄位，這與僅檢查目前 IP 的網頁版 Gemini 不同。

> 若要查看或變更帳戶的關聯區域，請造訪 [Google Country Association Form](https://policies.google.com/country-association-form)。

**為何網頁版 Gemini 可正常運作，但 agy 不行**：

- 網頁版 Gemini / Google One：僅檢查目前的 IP（代理伺服器可通過檢查）
- agy CLI / Cloud Code API：讀取後端的 Country Association 欄位（代理伺服器無法解決）

**修正方法**：

1. 使用美國 IP 造訪 [Google Country Association Form](https://policies.google.com/country-association-form)
2. 提交區域變更申請（選取「I live in a different country」）
3. 等待 1-24 小時，讓 Google 處理申請並寄送電子郵件通知
4. 之後執行 `agy login` 應可成功

### 帳戶沒有 Cloud Code 專案

**症狀**：記錄顯示 `loadCodeAssist returned no project id` 和 `onboardUser failed (400)`。

**根本原因**：該帳戶從未向 Google Cloud Code 註冊，且自動初始設定失敗。

**修正方法**：手動執行 `agy login` 以觸發 Cloud Code 註冊，然後在 OmniRoute Dashboard 中重新整理權杖。

### 權杖已過期或遭撤銷

**症狀**：記錄中出現 401 錯誤或「Token has expired」訊息。

**修正方法**：在 Dashboard → Providers → agy 中重新整理權杖 → 按一下重新整理圖示。如果重新整理權杖本身已遭撤銷，您需要透過 OAuth 重新驗證身分。

## 決策流程圖

```
帳戶無法運作？
│
├─ 資料庫中是否有 projectId？
│  ├─ 是 → 問題出在其他地方（權杖已過期、速率限制等）
│  └─ 否 ↓
│
├─ 帳戶的國家/地區關聯是否設定為受限制的區域？
│  ├─ 是 → 前往 Google 國家/地區關聯表單變更區域
│  │         (https://policies.google.com/country-association-form)
│  │         等待 1 至 24 小時，然後重試
│  └─ 否 ↓
│
├─ 帳戶是否訂閱了 Google One AI Pro？
│  ├─ 否 → 請先前往 one.google.com 訂閱
│  └─ 是 ↓
│
├─ 嘗試自動探索（在控制面板中重新整理權杖）
│  ├─ 成功 → 完成
│  └─ 仍然失敗 ↓
│
└─ 手動操作：在機器上執行 `agy login`
   ├─ 成功 → 在控制面板中重新整理權杖，即可探索到 projectId
   └─ 失敗 → 檢查錯誤訊息，可能是區域或訂閱問題
```
