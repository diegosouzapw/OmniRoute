## 🎯 使用案例

### 案例 1：「我有 Claude Pro 訂閱」

**問題：** 配額尚未使用便過期，大量編寫程式碼時會遇到速率限制

```
組合：「maximize-claude」
  1. cc/claude-opus-4-7        （充分利用訂閱）
  2. glm/glm-4.7               （配額用盡時的低成本備援）
  3. if/qwen3.8-max-preview       （免費的緊急後備方案）

每月費用：$20（訂閱）+ 約 $5（備援）= 總計 $25
相較之下，僅支付 $20 卻遇到限制，會令人感到挫折
```

### 案例 2：「我想要零成本」

**問題：** 無法負擔訂閱費用，但需要可靠的 AI 程式開發工具

```
組合：「zero-cost」
  1. if/kimi-k2.7-code          （列為可免費使用；可能有速率限制）
  2. kr/qwen3-coder-next        （Kiro 免費後備方案）

每月費用：$0
品質：請針對您的工作負載確認模型、限制、隱私權及 SLA
```

### 案例 3：「我需要全天候編寫程式碼，不可中斷」

**問題：** 有截止期限，無法承受停機

```
組合：「always-on」
  1. cc/claude-opus-4-7        （最佳品質）
  2. cx/gpt-5.5                （第二個訂閱）
  3. glm/glm-4.7               （低成本，每日重設）
  4. minimax/MiniMax-M2.1      （最便宜，5 小時重設）
  5. if/deepseek-v4-flash       （列為可免費使用；可能有速率限制）

結果：5 層後備方案可提高韌性；不保證上游服務的可用性
每月費用：$20-200（訂閱）+ $10-20（備援）
```

### 案例 4：「我想在 OpenClaw 中使用免費 AI」

**問題：** 需要可用於通訊應用程式且完全免費的 AI 助理

```
組合：「openclaw-free」
  1. if/qwen3.8-max-preview     （列為可免費使用；可能有速率限制）
  2. if/deepseek-v4-flash       （列為可免費使用；可能有速率限制）
  3. if/kimi-k2.7-code          （列為可免費使用；可能有速率限制）

每月費用：$0
可透過以下平台存取：WhatsApp、Telegram、Slack、Discord、iMessage、Signal……
```

## 📖 提供者設定

若要從 CSV 或 JSON 檔案大量新增 API 金鑰連線，請使用 **儀表板 → 提供者 → 從檔案匯入**。欄位採固定順序（`provider,name,apiKey,baseUrl,priority`）；`provider` 必須已存在，且為受管理的提供者或相容節點。請參閱[從 CSV 或 JSON 檔案匯入提供者](../providers/CSV-IMPORT.md)。

### 🔐 訂閱制提供者

#### Claude Code (Pro/Max)

```bash
儀表板 → 提供者 → 連接 Claude Code
→ OAuth 登入 → 自動重新整理權杖
→ 5 小時 + 每週配額追蹤

模型：
  cc/claude-opus-4-7
  cc/claude-sonnet-4-6
  cc/claude-haiku-4-5-20251001
```

**專業提示：** 複雜任務使用 Opus，追求速度則使用 Sonnet。OmniRoute 會依模型追蹤配額！

與 Claude 和 Claude Code 相容的路由會保留 Opus 與 Sonnet 模型的 `max` 思考強度。Haiku 模型不接受 `max` 強度層級，因此 OmniRoute 會先將該要求降級為高思考預算，再傳送至上游。

#### OpenAI Codex (Plus/Pro)

```bash
儀表板 → 提供者 → 連接 Codex
→ OAuth 登入（連接埠 1455）
→ 5 小時 + 每週重設

模型：
  cx/gpt-5.5
  cx/gpt-5.4
  cx/gpt-5.3-codex
  cx/gpt-5.3-codex-spark
```

#### GitHub Copilot

```bash
儀表板 → 提供者 → 連接 GitHub
→ 透過 GitHub 進行 OAuth
→ 每月重設（每月 1 日）

模型：
  gh/gpt-5.5
  gh/gpt-5.4
  gh/claude-sonnet-4.6
  gh/claude-opus-4.7
  gh/gemini-3.1-pro-preview
```

### 💰 平價提供者

#### GLM-4.7（每日重設，$0.6/1M）

1. 註冊：[Zhipu AI](https://open.bigmodel.cn)
2. 從 Coding Plan 取得 API 金鑰
3. 儀表板 → 新增 API 金鑰：提供者：`glm`，API 金鑰：`your-key`

**使用：** `glm/glm-4.7` — **專業提示：** Coding Plan 以 1/7 的成本提供 3 倍配額！每日上午 10:00 重設。

#### MiniMax M2.1（5 小時重設，$0.20/1M）

1. 註冊：[MiniMax](https://www.minimax.io)
2. 取得 API 金鑰 → 儀表板 → 新增 API 金鑰

**使用：** `minimax/MiniMax-M2.1` — **專業提示：** 長上下文最便宜的選項（1M 個權杖）！

#### Kimi K2（每月固定 $9）

1. 訂閱：[Moonshot AI](https://platform.kimi.ai?aff=omniroute)
2. 取得 API 金鑰 → 儀表板 → 新增 API 金鑰

**使用：** `kimi/kimi-k2.5` — **專業提示：** 每月固定 $9 可使用 10M 個權杖，相當於每 1M 個權杖的有效成本為 $0.90！

#### Baidu Qianfan / ERNIE

1. 註冊：[Baidu AI Cloud Qianfan](https://cloud.baidu.com/product/wenxinworkshop)
2. 建立 Qianfan API 金鑰 → 儀表板 → 新增 API 金鑰：提供者：`qianfan`

**使用：** `qianfan/ernie-5.1`、`qianfan/ernie-x1.1`，或其他與 OpenAI 相容的 Qianfan 模型 ID。

### 🆓 免費提供者

無需驗證的免費提供者，其提供者頁面上的 **不需要驗證** 旁會有一個開關。
關閉開關會停用該提供者、將其從提供者的已設定/精簡檢視中移除，並
從 `/v1/models` 中移除其模型。

#### Qoder（9 個免費模型）

```bash
儀表板 → 連接 Qoder → OAuth 登入 → 存取受目前提供者限制約束

模型：if/qwen3.8-max-preview, if/qwen3.7-max, if/qwen3.7-plus, if/kimi-k3, if/kimi-k2.7-code, if/glm-5.2, if/deepseek-v4-pro, if/deepseek-v4-flash, if/minimax-m3
```

#### Kiro（免費 Claude）

```bash
儀表板 → 連接 Kiro → AWS Builder ID 或 Google/GitHub → 每月約 50 點額度

模型：kr/claude-sonnet-4.5, kr/claude-haiku-4.5
```

## 🎨 組合

你可以在 **儀表板 → 組合** 中拖曳每張卡片上的控點，直接重新排列組合卡片。順序會儲存在 SQLite 中，並在重新載入時還原。

### 範例 1：最大化運用訂閱 → 低價備援

```
儀表板 → 組合 → 建立新組合

名稱：premium-coding
模型：
```

## 🚀 部署

### 全域 npm 安裝（建議）

```bash
npm install -g omniroute

# 建立設定目錄
mkdir -p ~/.omniroute

# 建立 .env 檔案（請參閱 .env.example）
cp .env.example ~/.omniroute/.env

# 啟動伺服器
omniroute
# 或使用自訂連接埠：
omniroute --port 3000
```

CLI 會自動從 `~/.omniroute/.env` 或 `./.env` 載入 `.env`。

### 系統匣模式

在系統匣中啟動 OmniRoute：

```bash
omniroute serve --tray
```

伺服器與系統匣準備就緒後，此命令便會返回。

伺服器會在沒有終端機的情況下繼續執行。

系統匣模式支援 macOS、Windows 與具有圖形介面的 Linux 工作階段。系統匣模式不會自動開啟儀表板。

使用系統匣選單執行下列操作：

- 開啟儀表板。
- 開啟 `/dashboard/logs`。
- 變更自動啟動設定。
- 停止 OmniRoute。

請勿將 `--tray` 與下列選項搭配使用：

- `--daemon`
- `--log`
- `--no-recovery`

這些模式需要不同的程序擁有權。

啟用下次登入機器時自動啟動：

```bash
omniroute autostart enable
```

在 macOS、Windows 與具有圖形介面的 Linux 工作階段中，自動啟動會使用系統匣模式。無頭 Linux 則使用現有的 systemd 使用者服務。

停用登入時自動啟動：

```bash
omniroute autostart disable
```

### 解除安裝

當你不再需要 OmniRoute 時，我們提供兩個快速指令碼，可乾淨地將其移除：

| 命令                     | 動作                                                             |
| ------------------------ | ---------------------------------------------------------------- |
| `npm run uninstall`      | 移除系統應用程式，但會**保留 `~/.omniroute` 中的資料庫與設定**。 |
| `npm run uninstall:full` | 移除應用程式，並永久**清除所有設定、金鑰與資料庫**。             |

> 注意：若要執行這些命令，請前往 OmniRoute 專案資料夾（如果你已複製該專案），然後執行命令。或者，若是以全域方式安裝，只需執行 `npm uninstall -g omniroute`。

```bash
# 'omniroute' 的範本檔案
pkgname=omniroute

	# 判斷 node-gyp 的目標 CPU 架構

		i686*) _gyp_arch=ia32 ;;

	NODE_ENV=development npm ci --ignore-scripts

	cp -r .next/static .next/standalone/.next/static

	rm -rf .next/standalone/node_modules/@img

	for _mod in pino-abstract-transport split2 process-warning; do

	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	# 防止安裝後掛鉤移除空的 Next.js 應用程式路由器目錄

		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \

#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"

exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```

## 🧩 進階功能

### 自訂模型

將任何模型 ID 新增至任何提供者，無需等待應用程式更新：

```bash
# 透過 API
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# 列出：curl http://localhost:20128/api/provider-models?provider=openai
# 移除：curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

或者使用儀表板：**提供者 → [提供者] → 自訂模型**。

注意事項：

- OpenRouter 和 OpenAI/Anthropic 相容提供者只能從**可用模型**進行管理。手動新增、匯入和自動同步都會進入同一份可用模型清單，因此這些提供者沒有獨立的「自訂模型」區段。
- **自訂模型**區段適用於不提供受管理可用模型匯入功能的提供者。

### 自訂 OpenAI 相容提供者

任何使用 OpenAI API 的閘道（自行託管的代理、vLLM、第三方彙整器）
都可以新增為獨立的提供者節點：

1. **提供者 → 新增 OpenAI 相容提供者**。
2. **名稱**：節點的顯示標籤。
3. **前綴**：路由名稱。用戶端會以 `<prefix>/<model>` 的形式呼叫模型，因此前綴為
   `mygw` 的節點會提供 `mygw/gpt-4o-mini`。此欄位為必填，且沒有字元限制。
4. **API 類型**：閘道所提供的端點系列（聊天完成、Responses、
   嵌入、音訊、圖片）。
5. **基礎 URL**：API 根路徑，直到並包含 `/v1`（例如
   `https://gateway.example.com/v1`），而非完整的 `/chat/completions` 路徑。具有
   非標準路徑的閘道可在**進階設定**下設定（聊天路徑、模型路徑）。
6. **API 金鑰（用於檢查）**欄位僅用於測試連線。建立節點後，
   開啟該節點並使用**新增連線**來儲存請求將使用的金鑰。

節點會取得格式為 `openai-compatible-<apiType>-<uuid>` 的內部 ID；您永遠
不需要輸入它，前綴才是公開名稱。

#### 保留前綴

前綴不能是內建提供者的 ID 或別名（例如 `openai`、`cf`），也不能
是已停用提供者的 ID。模型解析器會先檢查內建 ID 和別名，再檢查
自訂節點，因此使用其中任一前綴的節點永遠不會收到流量：
`<prefix>/model` 會改由內建提供者處理；若該提供者已停用，則會以封閉方式失敗。
使用此類前綴建立或編輯節點時，系統會拒絕操作並顯示：

```text
prefix: "<prefix>" 是保留的提供者前綴 — 請選擇其他前綴（保留的 ID／別名不能用於自訂節點，因為像 <prefix>/model 這類請求會路由至內建提供者，或在該提供者停用時以封閉方式失敗）
```

請選擇不同的前綴（`mygw`、`acme-proxy`）。如果傳送至自訂節點的請求失敗，
且錯誤訊息提及內建提供者或其憑證，請檢查節點前綴是否
為保留前綴：在此規則出現之前儲存的節點仍會保留，但其前綴會路由至
內建提供者。請編輯該節點並指定新的前綴。

### 串接 OmniRoute 對等節點

另一個 OmniRoute 閘道可以新增為**自訂 OpenAI 相容**提供者。請使用
對等節點的 `/v1` 基礎 URL，以及由該對等節點簽發、專用且遵循最小權限原則的 API 金鑰。

對於雙向或多躍點串接，請在每個閘道上啟用選用的迴圈防護：

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

只有傳送至明確允許清單中對等節點 URL 的請求，才會收到
`X-OmniRoute-Peer-Trace` 標頭。當執行個體 ID 重複或躍點
額度耗盡時，閘道會以 HTTP `508 Loop Detected` 拒絕請求；一般上游提供者不會收到任何對等節點中繼資料。

對等節點串接並非資料庫複寫或主機容錯移轉。每個閘道都會維護獨立的
SQLite 狀態、快取、速率計數器和工作階段。若要實現主動／被動或主動／主動可用性，請使用具備健康檢查的反向代理或用戶端
容錯移轉，而且絕不要將同一個 SQLite 資料庫掛載至多個正在執行的 OmniRoute 執行個體。

### Cloudflare 快速通道

- 適用於 Docker 與其他自行託管的部署，可在 **Dashboard → Endpoints** 中使用
- 建立暫時性的 `https://*.trycloudflare.com` URL，並將其轉送至您目前與 OpenAI 相容的 `/v1` 端點
- 首次啟用時，僅會在需要時安裝 `cloudflared`；後續重新啟動時會重複使用相同的受管理二進位檔
- OmniRoute 或容器重新啟動後，不會自動還原 Quick Tunnels；需要時請從儀表板重新啟用
- Tunnel URL 是暫時性的，每次停止／啟動 Tunnel 時都會變更

- 如果您偏好使用預先安裝的 `cloudflared` 二進位檔，而非受管理的下載版本，請設定 `CLOUDFLARED_BIN`
- Cloudflare Quick Tunnel、Tailscale Funnel 與 ngrok Tunnel 面板可在 **Settings → Appearance** 中顯示或隱藏。隱藏面板不會停止正在執行的 Tunnel。

### 路由策略

透過 **Dashboard → Settings → Routing** 設定。儀表板提供六種最常用的策略；組合與自動路由器在內部支援更廣泛的策略。

**儀表板中可見的策略（帳戶層級路由）：**

| 策略                      | 說明                                                                |
| ------------------------- | ------------------------------------------------------------------- |
| **優先填滿**              | 依優先順序使用帳戶——主要帳戶會處理所有請求，直到無法使用為止        |
| **輪詢**                  | 在所有帳戶間循環，並提供可設定的黏著限制（預設：每個帳戶 3 次呼叫） |
| **P2C（兩個選項的力量）** | 隨機選取 2 個帳戶，並路由至狀態較健康的帳戶——兼顧健康狀態來平衡負載 |
| **隨機**                  | 使用 Fisher-Yates 洗牌，為每個請求隨機選取帳戶                      |
| **最少使用**              | 路由至 `lastUsedAt` 時間戳記最早的帳戶，以平均分配流量              |
| **成本最佳化**            | 路由至優先值最低的帳戶，以選用成本最低的提供者                      |

**進階組合與自動策略**（可針對每個組合設定，或透過 `auto/*` 前綴設定——請參閱 [AUTO-COMBO.md](../routing/AUTO-COMBO.md)）：

- `priority` — 採用嚴格順序，絕不輪詢
- `weighted` — 依每個模型的權重按比例分配流量
- `fill-first` — 持續使用第一個模型，直到達到限制
- `round-robin` / `strict-random` / `random`
- `p2c`（兩個選項的力量）
- `least-used` 與 `cost-optimized`
- `auto` — 根據分數在所有候選項目中選擇
- `lkgp`（最後已知的良好提供者）— 固定使用上次成功的提供者，之後再回退至規則
- `context-optimized` — 選取可用上下文視窗最大的模型
- `context-relay` — 串連長上下文模型以處理後續輪次

#### 外部黏著工作階段標頭

若要使用外部工作階段親和性（例如位於反向代理後方的 Claude Code/Codex 代理程式），請傳送：


OmniRoute 也接受 `x_session_id`，並會在 `X-OmniRoute-Session-Id` 中傳回實際使用的工作階段金鑰。

### 韌性與斷路器

透過 **Dashboard → Settings → Resilience** 設定。

OmniRoute 使用五個元件實作提供者層級的韌性：

1. **請求佇列與速率控制** — 系統層級的請求流量塑形：
   - **每分鐘請求數（RPM）** — 每個帳戶每分鐘的請求數上限
   - **請求之間的最短時間** — 請求之間以毫秒計算的最短間隔
   - **並行請求數上限** — 每個帳戶可同時處理的請求數上限
2. **連線冷卻** — 針對可重試失敗後的單一連線，依驗證類型個別設定：
   - **基礎冷卻時間** — 可重試上游失敗的預設冷卻時間範圍
   - **使用上游重試提示** — 若上游提供具權威性的 `Retry-After` 或重設提示，則予以採用
   - **最大退避階段數** — 重複失敗時的最大指數退避級別

3. **提供者斷路器** — 追蹤提供者的端對端失敗；達到設定的警告閾值時將提供者標記為降級，達到設定的失敗閾值時則開啟斷路器：
   - **降級閾值** — 進入 `DEGRADED` 前允許的提供者連續失敗次數
   - **失敗閾值** — 進入 `OPEN` 前允許的提供者連續失敗次數
   - **重設逾時** — 再次測試提供者前的等待時間範圍
   - **CLOSED**（正常）— 請求正常流通
   - **DEGRADED** — 請求仍會流通，同時追蹤增加的失敗
   - **OPEN** — 重複失敗後暫時封鎖提供者
   - **HALF_OPEN** — 測試提供者是否已恢復

   連線範圍的 `429` 速率限制會保留在**連線冷卻**中，且不會計入提供者斷路器。

   提供者斷路器的執行階段狀態只會顯示於**儀表板 → 健康狀態**。

4. **等待冷卻完成** — 如果所有候選連線都已處於冷卻狀態，OmniRoute 可以等待最早結束的冷卻時間，並自動重試相同的用戶端請求。

5. **自動偵測速率限制** — 當上游提供者傳回明確的等待時間範圍時，若已啟用此設定，這些提示將覆寫本機連線冷卻時間。

**專業提示：** 發生服務中斷後，請使用**健康狀態**頁面檢查並重設即時提供者斷路器。「韌性」頁面只會變更設定。

### 資料庫匯出／匯入

在**儀表板 → 設定 → 系統與儲存空間**中管理資料庫備份。

| 操作                   | 說明                                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------------------- |
| **匯出資料庫**         | 將目前的 SQLite 資料庫下載為 `.sqlite` 檔案                                                                 |
| **全部匯出 (.tar.gz)** | 下載完整的備份封存檔，其中包括：資料庫、設定、組合、提供者連線（不含憑證）、API 金鑰中繼資料                |
| **匯入資料庫**         | 上傳 `.sqlite` 檔案以取代目前的資料庫。除非 `DISABLE_SQLITE_AUTO_BACKUP=true`，否則系統會自動建立匯入前備份 |

```bash
# API：匯出資料庫
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API：全部匯出（完整封存檔）
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API：匯入資料庫
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**匯入驗證：** 系統會驗證匯入檔案的完整性（SQLite pragma 檢查）、必要資料表（`provider_connections`、`provider_nodes`、`combos`、`api_keys`）以及大小（上限 100MB）。

**使用案例：**

- 在不同機器之間移轉 OmniRoute
- 建立外部備份以供災難復原
- 在團隊成員之間分享設定（全部匯出 → 分享封存檔）

### 組合平衡策略

在 **儀表板 → 組合 → 建立/編輯 → 策略** 中設定各組合的平衡方式。

| 策略           | 說明                                           |
| -------------- | ---------------------------------------------- |
| **輪詢**       | 依序輪替使用各個模型                           |
| **優先順序**   | 一律先嘗試第一個模型；僅在發生錯誤時才後援切換 |
| **隨機**       | 每個請求都從組合中隨機選擇一個模型             |
| **加權**       | 根據為每個模型指派的權重，按比例路由           |
| **最少使用**   | 路由至近期請求數最少的模型（使用組合指標）     |
| **成本最佳化** | 路由至成本最低的可用模型（使用定價表）         |

全域組合預設值可在 **儀表板 → 設定 → 路由 → 組合預設值** 中設定。
組合目標逾時預設會繼承目前的請求逾時。只有當較短的個別目標限制應觸發更快的後援切換時，
才應在組合預設值或個別組合上使用 **目標逾時（秒）**。

零延遲組合最佳化為選擇性啟用。停用 **零延遲最佳化**，可防止這些延遲功能與後援目標
競速、根據 TTFT 歷史記錄略過目標，或壓縮後援請求；啟用後則允許使用已設定的對沖、
預測性 TTFT 略過及主動式後援壓縮，以犧牲路由/請求的忠實度來換取較低的尾端延遲。

當上游提供者要求嚴格遵守 `max_tokens` / `maxOutputTokens` 限制時，請停用
**推理權杖緩衝區**。啟用後，組合路由只會為具有已知輸出上限的推理模型增加額外空間，
並且當安全的緩衝值超過該上限時，保持用戶端權杖限制不變。如果用戶端限制已高於已知上限，
OmniRoute 會在傳送上游請求前將其限制為該上限。

## 🤖 自動路由（零設定）

OmniRoute 內建**評分驅動的自動路由器**，可從所有已連線的提供者中，為每個請求選擇最佳模型，無需維護任何組合。只需使用其中一個 `auto/*` 前綴傳送請求，OmniRoute 就會即時建立虛擬組合，並根據延遲、成本、成功率、上下文適配度、模型對任務的適用性、近期失敗情況、配額及斷路器狀態為候選項目評分。

| 前綴           | 最佳化目標                                                                         |
| -------------- | ---------------------------------------------------------------------------------- |
| `auto`         | 平衡的預設選項（延遲 × 成本 × 成功率）                                             |
| `auto/coding`  | 程式設計任務：優先選擇 Claude、GPT-5、GLM、Kimi、Qwen Coder、DeepSeek 程式設計模型 |
| `auto/cheap`   | 最低的每 token 成本，可接受較高延遲                                                |
| `auto/fast`    | 最低延遲，忽略成本                                                                 |
| `auto/offline` | 僅限本機提供者（Ollama、vLLM、llama.cpp）——適用於實體隔離環境                      |
| `auto/smart`   | 推理品質優先（Opus、GPT-5 xhigh、R1、GLM 5.1 reasoning）                           |
| `auto/lkgp`    | 「最後已知的良好提供者」——固定使用最後成功的提供者，然後再退回至規則               |

範例：

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Refactor this Python function" }],
    "stream": true
  }'
```

[AUTO-COMBO.md](../routing/AUTO-COMBO.md) 完整說明了自動路由器，包括如何調整評分權重、將提供者加入黑名單，以及在**儀表板 → 自動組合**中檢查路由決策。

## 🔌 MCP 與 A2A 整合

OmniRoute 同時是 **MCP 伺服器**（Model Context Protocol，模型上下文協定）與 **A2A 伺服器**（Agent-to-Agent JSON-RPC 2.0）。任何與 MCP 相容的 IDE 或代理程式主機都能直接呼叫 OmniRoute 工具，無需額外的包裝層。

### MCP 傳輸方式

- **SSE**：`http://localhost:20128/api/mcp/sse`
- **可串流 HTTP**：`http://localhost:20128/api/mcp/stream`
- **stdio**：`omniroute --mcp`（適用於偏好 stdio 的 IDE 外掛程式）

### 連接 Claude Desktop

編輯 `~/Library/Application Support/Claude/claude_desktop_config.json`（macOS），或 Windows/Linux 上的對應檔案：

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### 連接 Cursor / Continue / VS Code MCP

使用 SSE URL `http://localhost:20128/api/mcp/sse`，以及在**儀表板 → API 金鑰**中產生的 Bearer API 金鑰。

### 權限範圍

MCP 目前定義了 32 個具名權限範圍。每個 Bearer 金鑰都能限制為僅可存取特定權限範圍——如需具權威性的權限範圍與工具清單，請參閱 [MCP-SERVER.md](../frameworks/MCP-SERVER.md)；如需 JSON-RPC 結構描述，請參閱 [A2A-SERVER.md](../frameworks/A2A-SERVER.md)。

## 🔔 Webhook

訂閱 OmniRoute 事件，以進行即時監控與自動化。

- 在**儀表板 → Webhook**中建立 Webhook，並設定目標 URL 與 HMAC 簽署密鑰
- 可用事件：`request.completed`、`request.failed`、`provider.unavailable`、`budget.exceeded`、`combo.switched`、`circuit_breaker.opened`、`circuit_breaker.closed`
- 每個承載資料皆包含 `X-OmniRoute-Signature`（HMAC-SHA256），以供驗證
- 重試：採用指數退避進行 3 次嘗試，之後移至無效信件佇列

完整結構定義請參閱 [WEBHOOKS.md](../frameworks/WEBHOOKS.md)。

## 🛠️ 程式化管理

您可以透過 HTTP，使用**具備 `manage` 作用域的 Bearer 金鑰**管理每一項 OmniRoute 資源（提供者、組合、金鑰、設定）。

在**儀表板 → API 金鑰 → 新增金鑰 → 作用域：manage**中產生金鑰，接著執行：

```bash
# 列出提供者
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# 新增提供者連線
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# 建立組合
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# 列出/建立 API 金鑰
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

如需完整的端點目錄與請求/回應結構定義，請參閱 [API_REFERENCE.md](../reference/API_REFERENCE.md)。

## 💻 內部 CLI

OmniRoute 內建內部 CLI（`omniroute …`），用於設定、診斷與執行階段控制。這與儀表板中的「CLI 工具」頁面**不同**；該頁面用於設定第三方 CLI（Claude Code、Cursor、Codex、Cline 等），讓它們能與 OmniRoute 通訊。

```bash
omniroute setup                    # 互動式精靈（密碼、提供者、組合）
omniroute setup --non-interactive  # 適用於 CI
omniroute doctor                   # 健康狀態診斷（資料目錄、資料庫、提供者、連接埠）
omniroute providers available      # 列出支援的提供者
omniroute providers list           # 列出已設定的連線
omniroute providers test <id>      # 即時測試提供者連線
omniroute combos list              # 列出組合
omniroute combos switch <name>     # 設定預設組合
omniroute models                   # 列出可用模型（--json、--search）
omniroute keys add | list | remove # 從終端機管理 API 金鑰
omniroute backup                   # 建立設定與資料庫快照
omniroute restore [<timestamp>]    # 從快照還原
omniroute health                   # 詳細健康狀態（斷路器、快取、記憶體）
omniroute quota                    # 提供者配額使用情況
omniroute mcp status               # MCP 伺服器狀態
omniroute a2a status               # A2A 伺服器狀態
omniroute tunnel list|create|stop  # Cloudflare/Tailscale/ngrok 通道
omniroute reset-password           # 重設管理員密碼
omniroute --mcp                    # 透過 stdio 啟動 MCP 伺服器
omniroute --port 3000              # 在自訂連接埠上啟動伺服器
```

提示：將 `omniroute doctor --json` 與監控工具搭配使用，以便在提供者連線狀態異常時發出警示。
