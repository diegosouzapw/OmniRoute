`@omniroute/opencode-plugin-v2` 會將您的整個 OmniRoute 目錄（包括模型、組合與
自動組合）整合至 OpenCode v2 的模型選擇器中，並提供顯示名稱、定價與免費方案
額度。

它與 `@omniroute/opencode-plugin` 是不同的套件，因為 OpenCode v1 與 v2 會透過
不同的介面載入外掛程式。請選擇與您的 OpenCode 主要版本相符的套件；兩者之間
不共用任何內容，因此升級其中一個絕不會迫使另一個也升級。

## 系統需求

- OpenCode v2。
- 可連線的 OmniRoute 閘道（預設為 `http://localhost:20128`）。
- Node.js 22 或 24。

## 安裝

將外掛程式新增至 `opencode.json`：

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

模型隨後會以 `omniroute/<provider>/<model>` 的格式顯示；`providerId` 決定此前綴，
以及 OpenCode 用來儲存憑證的整合項目 ID。

## 憑證

此外掛程式會依照下列順序，從三個位置尋找閘道金鑰：

1. **您在 OpenCode 中連線的憑證。**此外掛程式會註冊一個整合項目，因此
   OpenCode 本身的驗證流程可以儲存金鑰。任何資料都不會寫入 `opencode.json`——建議優先使用此方式。
2. 外掛程式選項中的 `apiKey`，用於個別專案的覆寫設定。這會將金鑰放在您
   可能提交至版本控制的檔案中。
3. 環境中的 `OMNIROUTE_API_KEY`。

如果三者皆未設定，目錄將為空，且外掛程式會在啟動時提示一次，而不會只留下
沒有任何提示的空白選擇器。

### 管理權杖是不同的金鑰

組合、提供者健康狀態與擴充資訊（顯示名稱、定價、免費方案額度）均來自
閘道的 `/api/*` 端點；多數部署會使用**管理**權杖來保護這些端點，而不是使用推論金鑰：

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<管理唯讀權杖>"
}
```

若未設定，`managementReadToken` 會回退使用 `apiKey`。當閘道拒絕該回退方式時，
目錄仍會發布，但只會顯示原始模型 ID，而不會顯示名稱、不會執行標準別名去重，
也不會提供定價與組合。發生這種情況時，外掛程式會針對每個端點警告一次，
並指出端點名稱及缺少的內容——因此選擇器功能降級的原因絕不會令人困惑。

## 選項

| 金鑰                             | 預設值                                   | 說明                                                                                  |
| -------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------- |
| `providerId`                     | `"omniroute"`                            | 提供者 ID、整合項目 ID，以及模型顯示時所使用的前綴                                    |
| `baseURL`                        | 必填                                     | 閘道根網址，僅限 `http(s)`；會在需要時加入 `/v1` 後綴                                 |
| `apiKey`                         | 已連線的憑證，其次為 `OMNIROUTE_API_KEY` | `/v1/*` 的聊天金鑰                                                                    |
| `managementReadToken`            | 回退使用 `apiKey`                        | `/api/*` 的金鑰——通常與聊天金鑰**不同**                                               |
| `displayName`                    | `"OmniRoute"`                            | 選擇器中的提供者名稱                                                                  |
| `timeoutMs`                      | `10000`                                  | 各端點的擷取逾時時間（自動組合使用 5 秒）                                             |
| `modelCacheTtlMs`                | `300000`                                 | 目錄快取 TTL；磁碟快照可加速冷啟動                                                    |
| `timeouts`                       | 回退使用 `timeoutMs`                     | 各端點的時間預算（毫秒）：`models`、`combos`、`autoCombos`、`enrichment`              |
| `enrichment`                     | `true`                                   | 擷取名稱、定價與免費方案額度                                                          |
| `providerTag`                    | `true`                                   | 在顯示名稱前加上其路由目標的上游提供者                                                |
| `usableOnly`                     | `false`                                  | 僅保留閘道回報為已佈建的提供者                                                        |
| `visibleModels` / `hiddenModels` | `[]`                                     | 精確比對或後綴比對的允許清單；拒絕規則優先                                            |
| `geminiSanitization`             | `true`                                   | 從工具結構描述中移除 Gemini 不接受的 JSON-Schema 關鍵字（含 `$ref` 的工具會原樣轉送） |
| `apiFormat.allowAnthropic`       | `false`                                  | 透過 Anthropic API 區塊路由允許清單中的 ID                                            |
| `apiFormat.anthropicModels`      | `[]`                                     | 路由至 Anthropic 的完整模型 ID                                                        |
| `logLevel` / `startupDebug`      | `warn` / `false`                         | 記錄器詳細程度                                                                        |

## 目錄如何保持最新

目錄會以延遲方式擷取，並快取 `modelCacheTtlMs` 所指定的時間；磁碟快照則會在閘道無法連線時，讓最後已知的目錄仍可供使用——服務中斷只會影響資料的新鮮度，不會造成其他損失。模型與組合一抵達便會立即發布；自動組合、提供者清單及擴充覆疊資料則會在抵達後併入，因此單一反應緩慢的端點無法拖住整個選擇器。

名稱會包含閘道所知的資訊：模型所路由至的上游提供者、`[Free]` 標記，以及其隨附的預算——因此，銷售相同模型的兩個連線仍可區分。若要關閉前綴，請設定 `"providerTag": false`。

目前沒有手動重新整理命令：OpenCode v2 命令是提示詞範本，而非回呼，因此外掛程式無法公開此類命令。重新整理會依 TTL 執行；只有在目錄或覆疊資料實際變更時，才會要求主程式重新載入，而不會每次重新整理都要求載入。

## Gemini 上的工具呼叫

如果工具宣告包含 `$schema` 或 `additionalProperties`，Gemini 會拒絕整個請求，並回覆 `400 INVALID_ARGUMENT`。此外掛程式會從傳送至此提供者之 Gemini 模型的工具結構描述中移除這些關鍵字，其他所有請求則維持不變。若工具包含 `$ref`，則會原樣轉送而不移除任何內容，因為移除參照會將結構描述放寬為「接受任何內容」。
設定 `"geminiSanitization": false` 即可停用此功能。

## 疑難排解

| 症狀                             | 原因                                                                                        |
| -------------------------------- | ------------------------------------------------------------------------------------------- |
| 選擇器未顯示任何 OmniRoute 模型  | 未解析出金鑰（請檢查啟動警告），或閘道無法連線                                              |
| 顯示原始模型 ID，沒有組合或定價  | 管理端點拒絕了權杖——請設定 `managementReadToken`                                            |
| 工作階段固定至 `opencode-<id>/…` | v1 外掛程式發布的是 `opencode-<id>`；v2 則直接發布 `<id>`，因此請在 `<id>/…` 下重新選取模型 |
