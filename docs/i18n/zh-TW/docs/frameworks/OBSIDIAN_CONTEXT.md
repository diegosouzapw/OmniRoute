> `src/lib/db/obsidian.ts`（權杖 / 基礎 URL / WebDAV 持久化）、
> `src/lib/obsidianSync.ts`（WebDAV 儲存庫同步）、`open-sse/mcp-server/tools/obsidianTools.ts`
> （22 個 MCP 工具）、`src/app/api/settings/obsidian/route.ts` +
> `src/app/api/settings/obsidian/webdav/route.ts`（設定 API）。工具註冊
> 與作用域連接位於 `open-sse/mcp-server/server.ts`。

## 這是什麼

OmniRoute 將 **Obsidian** 儲存庫連接為**上下文來源**——這是一個本機 Markdown
知識庫，代理程式可透過內建的 MCP 伺服器讀取及寫入內容。此整合會與桌面
應用程式中執行的 **Obsidian Local REST API** 社群外掛程式通訊，讓代理程式能夠
搜尋筆記、讀取/寫入/修補檔案、列出儲存庫內容、處理每日/每週週期性筆記、
管理標籤、執行 Obsidian 命令，以及（可選）協調桌面裝置↔行動裝置之間的
雙向儲存庫同步。

用戶端（`src/lib/obsidian/api.ts`）封裝了 Local REST API，並提供：

- 對暫時性 `5xx` 錯誤進行**帶退避機制的重試**，並透過 `AbortController` 設定 **30 秒逾時**。
- **具類型的錯誤分類**——`ObsidianAuthError`（401/403）、
  `ObsidianNotFoundError`（404）、`ObsidianServerError`（5xx）、`ObsidianTimeoutError`。
- 友善的**「無法連線至 Obsidian」提示**，會指出常見的連接埠錯誤
  （HTTP 使用 `27123`，**而不是**位於 `27124` 的 MCP 端點），以及 Tailscale 格式。
- 儲存庫相對**路徑編碼**，確保包含空格/斜線的筆記路徑可安全使用。

## 設定

Obsidian 權杖或基礎 URL **沒有對應的環境變數**——兩者皆透過
`src/lib/db/obsidian.ts` 儲存在 SQLite `key_value` 資料表中（命名空間為 `obsidian`）。
權杖會**以加密形式靜態儲存**（AES-256-GCM，並提供純文字向後相容備援）。
可從 Endpoint 儀表板的 **Context Sources** 分頁（`ObsidianSourceCard`）進行設定，
或透過設定 REST API 完成設定。

> [!IMPORTANT]
> 必須安裝並執行 **Obsidian Local REST API** 外掛程式。其 REST
> 介面會監聽 **HTTP `127.0.0.1:27123`**（預設基礎 URL）。連接埠 `27124`
> 是一個_獨立的_ MCP/HTTPS 端點，設定路由會明確拒絕該連接埠。
> 若要從其他裝置連線，請使用 `http://<tailscale-ip>:27123`。

### 設定鍵（SQLite `key_value`，命名空間為 `obsidian`）

| 鍵                | 用途                                             | 已加密 |
| ----------------- | ------------------------------------------------ | ------ |
| `api_key`         | Local REST API bearer 權杖                       | 是     |
| `base_url`        | REST 基礎 URL（預設為 `http://127.0.0.1:27123`） | 否     |
| `vault_path`      | 儲存庫目錄的絕對路徑（用於同步）                 | 否     |
| `webdav_username` | 產生的 WebDAV 使用者名稱（儲存庫同步）           | 否     |
| `webdav_password` | 產生的 WebDAV 密碼（儲存庫同步）                 | 是     |
| `webdav_enabled`  | 是否啟用 WebDAV 儲存庫同步                       | 否     |

### 透過 REST 設定

```bash
# 儲存並驗證 Local REST API 權杖（POST 會透過狀態檢查進行驗證）
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# 檢查連線狀態（傳回 connected、hasToken、baseUrl、vaultPath）
curl http://localhost:20128/api/settings/obsidian

# 中斷連線（清除已儲存的權杖）
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

所有方法都需要儀表板驗證。`POST` 會拒絕任何使用連接埠 `27124` 的 URL，
並在持久化之前，透過呼叫 Local REST API 狀態端點驗證權杖。

### WebDAV 儲存庫同步

`src/app/api/settings/obsidian/webdav/route.ts` 管理可選的 WebDAV 後端
儲存庫同步（由 `src/lib/obsidianSync.ts` 驅動）。啟用此功能後，OmniRoute
會指向本機儲存庫目錄，並產生一組隨機的 WebDAV 使用者名稱/密碼：

```bash
# 為儲存庫目錄啟用 WebDAV 同步（產生使用者名稱/密碼）
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# 取得 WebDAV 同步狀態（僅在啟用時傳回認證資訊）
curl http://localhost:20128/api/settings/obsidian/webdav

# 停用 WebDAV 同步（清除認證資訊及受管理的 .stignore）
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### 每個 API 金鑰的上下文來源（可選）

Obsidian 設定可透過 `api_key_context_sources` 資料表，**依每個 API 金鑰**
設定作用域（`src/lib/db/apiKeyContextSources.ts`）。當 MCP 呼叫攜帶已驗證的 API
金鑰 ID 時，`getObsidianConfigForApiKey()` 會優先使用該金鑰本身的權杖/基礎 URL/儲存庫路徑
（`source: "api_key"`）；若無，則退回使用全域設定（`source: "global"`）。

## MCP 工具（22 個）

定義於 `open-sse/mcp-server/tools/obsidianTools.ts`。權杖／基底 URL 會在每次呼叫時解析（優先使用各 API 金鑰的設定，接著使用全域設定）。存取 OmniRoute **同步伺服器**的工具（四個 `obsidian_sync_*` 工具）還需要在 OmniRoute 設定中配置同步驗證權杖。

### 讀取工具（`read:obsidian`）

| 工具                         | 說明                                                                             |
| ---------------------------- | -------------------------------------------------------------------------------- |
| `obsidian_check_status`      | 檢查 Local REST API 是否可連線且已通過驗證。                                     |
| `obsidian_search_simple`     | 對筆記內容進行全文搜尋；傳回包含檔案路徑的片段。                                 |
| `obsidian_search_structured` | 使用 JSON Logic 運算式（and/or/regex/path 篩選器）進行搜尋。                     |
| `obsidian_read_note`         | 依相對於儲存庫的路徑讀取筆記；可選擇特定標題／區塊／frontmatter。                |
| `obsidian_list_vault`        | 列出儲存庫中的檔案與目錄（項目樹狀結構）。                                       |
| `obsidian_get_document_map`  | 取得筆記的標題結構，以標題 → 行號的對應表呈現。                                  |
| `obsidian_get_note_metadata` | 取得 frontmatter、標籤、連結、字元數／字數，而不包含完整內容。                   |
| `obsidian_get_active_file`   | 取得 Obsidian 中目前作用中檔案的路徑與內容。                                     |
| `obsidian_get_periodic_note` | 取得指定日期的每日／每週／每月週期筆記（若省略則為今天）。                       |
| `obsidian_get_tags`          | 列出儲存庫中的所有標籤及其出現頻率。                                             |
| `obsidian_list_commands`     | 列出可用的 Obsidian 命令 ID（搭配 `obsidian_execute_command` 使用）。            |
| `obsidian_sync_status`       | OmniRoute 同步伺服器狀態：執行狀態、儲存庫名稱、連接埠、執行時間、上次同步時間。 |
| `obsidian_sync_conflicts`    | 列出尚未解決的同步衝突（路徑、衝突路徑、偵測時間）。                             |

### 寫入工具（`write:obsidian`）

| 工具                             | 說明                                                                     |
| -------------------------------- | ------------------------------------------------------------------------ |
| `obsidian_write_note`            | 使用指定的 Markdown 內容建立或覆寫筆記。                                 |
| `obsidian_append_note`           | 將內容附加至筆記；可選擇附加至特定標題／區塊。                           |
| `obsidian_patch_note`            | 在標題、區塊或 frontmatter 欄位精確地附加、前置或取代內容。              |
| `obsidian_delete_note`           | 從儲存庫中永久刪除筆記。                                                 |
| `obsidian_move_note`             | 在儲存庫內移動或重新命名筆記。                                           |
| `obsidian_execute_command`       | 依 Obsidian 命令 ID 執行命令。                                           |
| `obsidian_open_file`             | 在 Obsidian 中開啟檔案（若檔案不存在則建立）。                           |
| `obsidian_sync_trigger`          | 立即觸發桌面端↔行動端儲存庫的雙向同步。                                  |
| `obsidian_sync_resolve_conflict` | 解決同步衝突：保留 `local`（行動端）、`remote`（桌面端）或 `keep-both`。 |

> [!NOTE]
> `obsidian_patch_note` 的目標可接受 `heading | block | frontmatter` 的 `targetType`
> 以及 `append | prepend | replace` 的 `operation`，並可選擇指定
> `createTargetIfMissing`。四個 `obsidian_sync_*` 工具會與本機同步
> 伺服器通訊（預設為 `http://127.0.0.1:27781`），且需要同步權杖。

### 權限範圍

讀取工具需要 `read:obsidian`；寫入工具需要 `write:obsidian`。強制執行方式
與 Notion 相同——由 `open-sse/mcp-server/server.ts` 中的
`withScopeEnforcement()` 處理，並由 `OMNIROUTE_MCP_ENFORCE_SCOPES=true` 控制是否啟用；
允許的權限範圍來源為 `OMNIROUTE_MCP_SCOPES` 或 API 金鑰的權限範圍上下文。請參閱
[MCP-SERVER.md](./MCP-SERVER.md)。

## 端點

| 方法     | 路徑                            | 用途                                                 |
| -------- | ------------------------------- | ---------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | 傳回 `{ connected, hasToken, baseUrl, vaultPath }`。 |
| `POST`   | `/api/settings/obsidian`        | 儲存並驗證權杖（拒絕連接埠 `27124`）。               |
| `DELETE` | `/api/settings/obsidian`        | 中斷連線（清除已儲存的權杖）。                       |
| `GET`    | `/api/settings/obsidian/webdav` | WebDAV 同步狀態與認證資訊（啟用時）。                |
| `POST`   | `/api/settings/obsidian/webdav` | 為保管庫目錄啟用 WebDAV 同步。                       |
| `DELETE` | `/api/settings/obsidian/webdav` | 停用 WebDAV 同步。                                   |

> 這些是儀表板設定路由。保管庫本身透過 Obsidian
> Local REST API（已設定的 `base_url`）以及上述 MCP 工具存取——並沒有
> 公開的 `/v1` Obsidian 代理端點。

## 使用案例

- **以保管庫內容為依據的回答** — 先使用 `obsidian_search_simple` / `obsidian_search_structured`，
  再使用 `obsidian_read_note`，讓代理程式根據您的實際筆記回答。
- **筆記撰寫／日誌記錄** — 使用 `obsidian_write_note`、`obsidian_append_note`，或
  精準操作的 `obsidian_patch_note`，將代理程式輸出、摘要或每日筆記
  （`obsidian_get_periodic_note`）記錄至保管庫。
- **保管庫導覽** — 使用 `obsidian_list_vault`、`obsidian_get_document_map` 和
  `obsidian_get_tags`，在讀取／寫入前探索其結構。
- **Obsidian 自動化** — 使用 `obsidian_list_commands` + `obsidian_execute_command`，
  由代理程式驅動外掛程式／命令；使用 `obsidian_open_file` 在 UI 中顯示筆記。
- **行動裝置同步** — 啟用 WebDAV 同步，然後使用 `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  協調桌面裝置↔行動裝置的同步並解決衝突。
