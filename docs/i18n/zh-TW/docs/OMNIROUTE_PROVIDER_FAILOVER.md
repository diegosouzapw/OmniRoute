系統會先對失敗進行分類，再決定是否重試。

逾時、網路錯誤、速率限制及提供者 5xx 回應等暫時性失敗，可能會觸發容錯移轉。驗證錯誤、權限錯誤、無效請求、模型不可用及未知失敗，不會盲目重試。

預設的跨提供者原則最多允許嘗試三個提供者，並會在遇到速率限制和逾時時重試，同時將管理性停用與暫時性斷路器狀態分開處理。

斷路器狀態包括 `closed`、`open` 和 `half_open`。冷卻期會排定一次有界限的探測；探測成功時會關閉斷路器，探測失敗時則會重新開啟。
