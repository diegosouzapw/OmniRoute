1. 以聚焦測試鎖定現有的單鍵 semaphore 契約與新的原子多鍵契約：不得部分保留、FIFO 排隊、中止、逾時、佇列已滿、冪等釋放、統計資料及清理。
2. 就地泛化現有的帳戶 semaphore。保留 `acquire()` 作為 `acquireMany()` 的相容性包裝器；不要新增第二個排程器或相依套件。
3. 在 `chatCore` 中，將僅限帳戶的取得操作替換為緊接在 `withRateLimit` 之前執行的一次累積式全域／提供者／帳戶取得操作。每當帳戶輪替變更連線時，重新取得整組資源，並持續保留至串流完成後才釋放。
4. 擴充現有的韌性設定管線（類型、預設值、正規化、schema、API 回應、UI 及翻譯），加入全域與提供者上限。將舊有的 Bottleneck 並行控制重新標示為連線／配額範圍並行控制，以明確呈現其實際作用範圍。
5. 執行聚焦測試、lint、類型檢查、靜態檢查及完整測試套件；並在 changelog 中記錄此行為變更。

刻意保留的行為：零值／null 並行數會略過 gate、僅限帳戶的呼叫端繼續使用 `acquire()`、遭封鎖帳戶的控制機制保留其鍵格式與 API，且提供者 rate-limit 佇列的行為維持不變。
