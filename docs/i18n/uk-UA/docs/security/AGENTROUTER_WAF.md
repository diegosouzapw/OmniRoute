Шлюз висхідного рівня `agentrouter` запускає фільтр вмісту на основі ключових слів для
`messages[].content`. Фільтр є частково детермінованим (завжди блокує
певні фрази) і частково ймовірнісним (чутливим до сплесків — стає
агресивнішим після швидких послідовних запитів і відновлюється після періоду очікування).

Коли WAF блокує запит, він повертає:

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## Область дії фільтра

WAF перевіряє лише `messages[].content`. Він **не** перевіряє:

- Системний запит `system`
- Структуровані блоки вмісту (`tool_result`, `tool_use`, `thinking`, `image`)
- Поля `description` та `input_schema` інструментів
- Метадані запиту, заголовки або ідентифікатор моделі

## Шаблони, що блокуються завжди (без урахування регістру)

| Шаблон                          | Примітки                                                    |
| ------------------------------- | ----------------------------------------------------------- |
| Будь-який варіант `Lorem ipsum` | Блокується весь латинський словник lorem                    |
| `language model` (окремо)       | "the language model" і "large language model" пропускаються |
| `virtual assistant`             | "AI assistant" пропускається                                |
| `I'm here to help`              | "here to help" окремо також блокується                      |
| `Claude, made by Anthropic`     | Лише повна фраза                                            |

## Шаблони, що блокуються майже завжди

| Шаблон                                                       | Примітки                                         |
| ------------------------------------------------------------ | ------------------------------------------------ |
| `placeholder`                                                | Коли стоїть окремо (не як назва параметра тощо)  |
| `dummy data`                                                 | Поширена початкова фраза для фікстур             |
| `foo bar baz`                                                | Канонічна фраза-заповнювач                       |
| Повторювані короткі токени (`AAA BBB CCC`, `test test test`) | Детектор надмірного наповнення ключовими словами |

## Поведінка під навантаженням

Після приблизно 5 швидких запитів протягом короткого проміжку часу WAF починає блокувати вміст,
який зазвичай пропускається. Ліміт відновлюється після приблизно 5–10 секунд
бездіяльності. Це той самий обмежувач частоти запитів, прив’язаний до IP-адреси та ключа, який спричиняє
періодичні помилки `400 content-blocked`, коли Claude Code або Codex CLI
швидко послідовно здійснює кілька викликів використання інструментів / надсилання повідомлень.

## Заходи протидії, уже застосовані в OmniRoute

1. **`open-sse/services/wafRateLimit.ts`** — захист від сплесків, який забезпечує
   мінімальний інтервал 500 мс між вихідними запитами до будь-якої URL-адреси `agentrouter:*`.
   Цей інтервал значно нижчий за поріг сприйняття затримки людиною та запобігає
   активації WAF за нормального трафіку.

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — коли висхідний сервіс повертає
   `400 content-blocked`, виконавець повторює запит до тієї самої URL-адреси із
   експоненційною затримкою (1,5 с, 3,0 с, максимум 2 спроби). Після цієї затримки
   WAF зазвичай послаблює обмеження, і повторна спроба завершується успішно.

3. **`tests/unit/compression/harness.test.ts`** — тестову фікстуру
   `longInput` було змінено з `"lorem ipsum dolor sit amet ".repeat(40)`
   на `"example content for testing purposes ".repeat(40)`, щоб, коли
   Claude Code читає цей файл за допомогою інструмента `Read`, вміст файлу
   не передавався назад через блок `tool_result` і не активував WAF.

## Рекомендації щодо запитів і виводу інструментів

Якщо сеанс Claude Code або Codex CLI неодноразово отримує
`400 content-blocked`, перевірте останнє повідомлення користувача та останній
результат інструмента на наявність будь-яких наведених вище шаблонів і перефразуйте їх. Поширені
обхідні рішення:

- Замініть `Lorem ipsum …` на `example text …` або фактичний вміст,
  який намагається моделювати тест чи фікстура.
- Замініть `placeholder` (коли стоїть окремо) на `example value`,
  `sample value` або реальне значення.
- Замініть `language model` на `large language model` або `the model`.
- Замініть `dummy data` на `sample data` або реалістичні початкові значення.
- Замініть `I'm here to help` / `here to help` на конкретніший
  вступ (наприклад, "I'll review the file you mentioned").

## Повідомлення про хибні спрацьовування висхідному сервісу

Поточний фільтр надто агресивний — він блокує "Lorem ipsum" у
блоках `tool_result`, хоча оператор явно не мав наміру
впроваджувати запит. Операторам, які хочуть, щоб це було виправлено в джерелі,
слід звернутися до `agentrouter.org`, щоб повідомити про хибні спрацьовування. Наведений
вище список блокування є емпіричним результатом перевірки висхідного сервісу станом на 2026-08-03.
