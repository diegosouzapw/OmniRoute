OmniRoute публікує артефакти npm + Docker. Ці шлюзи забезпечують походження, інвентаризацію (SBOM) та сканування CVE, все це є відкритим вихідним кодом (OSS) і інтегровано в робочі процеси випуску.
**Консультативний підхід** — вони повідомляють зараз, а після першого успішного випуску підвищують до блокування.

| Шлюз                  | Інструмент                                     | Де                            | Блокує?                          | Вивід                                         |
| :-------------------- | :--------------------------------------------- | :---------------------------- | :------------------------------- | :-------------------------------------------- |
| SLSA provenance (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | лише якщо публікація не вдається | badge npmjs / `npm audit signatures`          |
| SBOM npm              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | лише якщо генерація не вдається  | Релізний ресурс + артефакт                    |
| SBOM image            | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | консультативний                  | Артефакт CycloneDX                            |
| Trivy CVE (SARIF)     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | консультативний                  | SARIF (ВИСОКИЙ+КРИТИЧНИЙ) → вкладка Безпека   |
| Trivy CRITICAL gate   | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | **блокує**                       | `exit-code: '1'` при виправному КРИТИЧНОМУ    |
| osv vulnCount         | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **блокує**                       | збільшує `metrics.vulnCount` (напрямок: вниз) |
| OpenSSF Scorecard     | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | консультативний                  | SARIF → Безпека + значок                      |

Механізм CVE для образів використовує **два кроки** у `docker-publish.yml`: крок SARIF (`HIGH,CRITICAL`, `exit-code: 0`) зберігає ВИСОКІ+КРИТИЧНІ вразливості видимими на вкладці Безпека без блокування; крок _CRITICAL gate_ (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) призводить до збою випуску при КРИТИЧНІЙ CVE **з доступним виправленням**. `ignore-unfixed` запобігає блокуванню випуску для CVE базового образу без виправлення від постачальника.

## ⚠️ Відхилення CVE (блокуючі шлюзи osv/Trivy)

osv та Trivy порівнюють залежності з базами даних CVE, які **постійно зростають**. PR, який **не торкається залежностей**, може раптово стати червоним, оскільки нова CVE була розкрита в існуючій залежності (osv: виміряний `vulnCount` > базовий рівень; Trivy: нова виправна КРИТИЧНА вразливість в образі). **Це ОЧІКУВАНА операційна поведінка блокуючого шлюзу CVE, а не регресія продукту.**

Коли osv або Trivy стають червоними через новорозкриту CVE, рішення таке:

1.  **Оновити залежність, що постраждала** (бажано) — оновити до виправленої версії через `overrides` у `package.json` (транзитивні залежності) або перезібрати образ на виправленій базовій версії.
2.  **Якщо немає виправлення від постачальника:**
    - **osv:** перевстановити базовий рівень `metrics.vulnCount` у `config/quality/quality-baseline.json` (`npm run quality:ratchet -- --update` не охоплює спеціальні шлюзи — відредагуйте значення вручну, `direction:down`) з обґрунтуванням + відстежуваним завданням.
    - **Trivy:** додати запис у `.trivyignore` (CVE-ID на рядок) з коментарем-обґрунтуванням + відстежуваним завданням. `ignore-unfixed: true` вже автоматично охоплює CVE без виправлень.

Обидва шлюзи **коректно ПРОПУСКАЮТЬ** (exit 0), якщо інструмент відсутній або вимірювання не вдається (osv-scanner не в PATH, osv.dev/network недоступний, недійсний JSON) — збій **вимірювання** ніколи не блокує, блокує лише **виміряна** регресія.

## Відомі прийняті ризики

### extract-zip 2.0.1 — GHSA-7pqw-9j4j-h8q3 / GHSA-jmr9-qjv8-65gv (#14482)

`extract-zip@2.0.1` містить дві невиправлені вразливості високого рівня небезпеки, пов'язані з обходом символічних посилань (symlink-traversal).
Відповідно до гілки "без виправлення від розробника" вищезгаданого виправлення CVE Variance, це **прийнятий ризик**, а не оновлення:

- **Ланцюжок:** `promptfoo` (devDependency) → `@openai/codex-security` → `extract-zip@2.0.1`.
  Підтверджено через `package-lock.json` — рівно один пакет у всьому дереві залежностей
  (`@openai/codex-security`) оголошує `extract-zip`, і рівно один пакет
  (`promptfoo`) оголошує `@openai/codex-security`.
- **Виправленої версії не існує в жодному місці ланцюжка.** `extract-zip@2.0.1` (опублікований у 2020 році) є останнім випуском пакета — він не підтримується. `@openai/codex-security`'s
  поточний npm-latest (`0.1.29`) все ще використовує `extract-zip@2.0.1`.
- **Недоступний з виробничого середовища.** `promptfoo` є лише devDependency (ніколи не вказаний
  у `dependencies`), і жоден файл у `src/`, `open-sse/` або `bin/` не імпортує
  пакет npm `extract-zip` — власний допоміжний метод `extractZip()` OmniRoute
  (`src/lib/versionManager/binaryManager.ts:93`) використовує нативні `unzip`/`tar`
  і не пов'язаний з цим. `@openai/codex-security` також має власний захист від обходу символічних посилань
  на додаток до зворотного виклику onEntry `extract-zip`.
- **Не** створюйте псевдонім `extract-zip` через `overrides` у `package.json` — єдина життєздатна
  заміна є внутрішньою для Electron-org і несумісною з API
  власних перевірок onEntry/defaultDirMode/defaultFileMode `@openai/codex-security`;
  перевизначення цього призвело б до тихого порушення перевірок безпеки цього пакета.
- **Базовий рівень:** виміряний `vulnCount` osv (3) вже значно нижчий за заморожений
  базовий рівень `config/quality/quality-baseline.json` (27) — зміна "храповика" не потрібна.
- **Захист від регресії:** `tests/unit/extract-zip-14482-exposure.test.ts` стверджує
  ланцюжок та вищезгаданий інваріант відсутності імпорту у виробниче середовище; він призводить до збою CI, якщо будь-який з них
  коли-небудь порушується (наприклад, майбутній PR робить `extract-zip` доступним з виробничого середовища).
- **Відстеження:** issue #14482.
