OmniRoute публікує артефакти npm + Docker. Ці контрольні шлюзи забезпечують походження,
інвентаризацію (SBOM) і сканування CVE; усі вони мають відкритий код та інтегровані в робочі процеси випуску.
Підхід **спочатку рекомендації** — наразі вони лише звітують, а після 1-го
успішного випуску стануть блокувальними.

| Шлюз                  | Інструмент                                     | Де                            | Блокує?                       | Результат                                   |
| --------------------- | ---------------------------------------------- | ----------------------------- | ----------------------------- | ------------------------------------------- |
| Походження SLSA (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | лише якщо публікація невдала  | значок npmjs / `npm audit signatures`       |
| SBOM npm              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | лише якщо генерування невдале | ресурс випуску + артефакт                   |
| SBOM образу           | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (злиття) | рекомендаційний               | артефакт CycloneDX                          |
| CVE Trivy (SARIF)     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (злиття) | рекомендаційний               | SARIF (HIGH+CRITICAL) → вкладка «Безпека»   |
| Шлюз CRITICAL Trivy   | `aquasecurity/trivy-action`                    | `docker-publish.yml` (злиття) | **блокувальний**              | `exit-code: '1'` для виправних CRITICAL     |
| vulnCount osv         | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **блокувальний**              | фіксує `metrics.vulnCount` (напрямок: униз) |
| OpenSSF Scorecard     | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | рекомендаційний               | SARIF → «Безпека» + значок                  |

Механізм фіксації CVE образу використовує **два кроки** в `docker-publish.yml`: крок SARIF
(`HIGH,CRITICAL`, `exit-code: 0`) залишає HIGH+CRITICAL видимими на вкладці «Безпека»,
не блокуючи процес; крок _шлюзу CRITICAL_ (`severity: CRITICAL`, `ignore-unfixed: true`,
`exit-code: 1`) зупиняє випуск у разі CRITICAL CVE, **для якої доступне виправлення**. `ignore-unfixed`
запобігає блокуванню випуску через CVE базового образу, для якої немає виправлення від постачальника.

## ⚠️ Варіативність CVE (блокувальні шлюзи osv/Trivy)

osv і Trivy порівнюють залежності з базами даних CVE, які **безперервно зростають**. PR,
який **не змінює жодних залежностей**, може раптово отримати червоний статус через розкриття
нової CVE в наявній залежності (osv: виміряне значення `vulnCount` > базового; Trivy: нова
виправна CRITICAL у образі). **Це ОЧІКУВАНА операційна поведінка блокувального
шлюзу CVE, а не регресія продукту.**

Якщо osv або Trivy отримують червоний статус через нещодавно розкриту CVE, слід:

1. **Оновити відповідну залежність** (бажано) — перейти на виправлену версію через `package.json`
   `overrides` (транзитивні залежності) або повторно зібрати образ на основі виправленого базового образу.
2. **Якщо виправлення від постачальника відсутнє:**
   - **osv:** повторно встановити базове значення `metrics.vulnCount` у `config/quality/quality-baseline.json`
     (`npm run quality:ratchet -- --update` не охоплює спеціалізовані шлюзи — змініть значення
     вручну, `direction:down`), додавши обґрунтування й задачу для відстеження.
   - **Trivy:** додати запис до `.trivyignore` (CVE-ID у кожному рядку) з коментарем,
     що містить обґрунтування, і задачею для відстеження. `ignore-unfixed: true` уже автоматично
     охоплює CVE без виправлень.

Обидва шлюзи **коректно ПРОПУСКАЮТЬСЯ** (код завершення 0), якщо інструмент відсутній або вимірювання
не вдалося (osv-scanner відсутній у PATH, osv.dev/мережа недоступні, неприпустимий JSON) —
помилка **вимірювання** ніколи не блокує; блокує лише **виміряна** регресія.

## Невиконані завдання: Scorecard із рекомендаційного → блокувальний

Після 1-го успішного випуску зі звітуванням Scorecard:

- Scorecard: фіксація оцінки (фіксує виміряну оцінку; вона не може зменшуватися).

Доповнює шлюзи Фази 7 (osv-scanner, gitleaks, actionlint+zizmor): zizmor
перевіряє самі робочі процеси; Scorecard оцінює загальний стан репозиторію.
