> **Коротко**: OmniRoute ранжує своїх **безкоштовних** провайдерів за якістю моделей, використовуючи **ELO-оцінки Arena AI
> (у стилі LMArena)**. Відкрийте сторінку **Рейтинг безкоштовних провайдерів** на
> панелі керування, щоб дізнатися, які безкоштовні провайдери пропонують найпотужніші моделі для вашого завдання —
> загалом або з фільтрацією за категоріями (програмування, перевірка, документація, налагодження).

---

## Що це таке

OmniRoute реєструє 329 провайдерів, зокрема 155 записів каталогу, позначених як **безкоштовні/без автентифікації**
(без автентифікації,
OAuth із безкоштовним рівнем або API-ключ із безкоштовним рівнем — див.
[Посібник із безкоштовних рівнів](../getting-started/FREE-TIERS-GUIDE.md) та повний
[каталог безкоштовних рівнів](../reference/FREE_TIERS.md)). Але є нюанс: якість моделей
безкоштовних провайдерів дуже різниться. Провайдер без автентифікації, який надає передову модель, значно корисніший
за провайдера, що пропонує невелику застарілу модель.

**Рейтинг безкоштовних провайдерів** відповідає на запитання: «**який безкоштовний провайдер надає мені найкращу модель?**»,
поєднуючи каталог кожного безкоштовного провайдера з **оцінками якості, отриманими від спільноти**, з
**таблиці лідерів Arena AI** (ELO на основі людських уподобань — та сама ідея, що лежить в основі
арени чатботів LMArena). Потім провайдери ранжуються за потужністю їхньої **найкращої безкоштовної моделі**.

Рейтинг обчислюється на основі трьох реальних джерел:

1. Списки безкоштовних провайдерів — `NOAUTH_PROVIDERS`, а також записи `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS`, позначені `hasFree`
   (`src/shared/constants/providers.ts`).
2. Каталог моделей кожного провайдера з реєстру провайдерів
   (`open-sse/config/providerRegistry.ts`).
3. Отримані на основі ELO оцінки відповідності завданням, які рушій синхронізації Arena ELO
   (`src/lib/arenaEloSync.ts`) зберігає в таблиці БД `model_intelligence`.

Логіка поєднання міститься у файлі `src/lib/freeProviderRankings.ts`.

## Як отримати доступ

### Сторінка панелі керування

Відкрийте панель керування та перейдіть до розділу **Витрати → Рейтинг безкоштовних провайдерів** або відкрийте безпосередньо:

```
/dashboard/free-provider-rankings
```

На сторінці (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) відображаються:

- **Подіум із трьома лідерами** (🥇 🥈 🥉) серед безкоштовних провайдерів із найвищим рейтингом.
- Повна **таблиця рейтингу** зі стовпцями: **Місце**, **Провайдер**, **Найкраща модель**,
  **Оцінка**, **Середня оцінка**, **Моделі**, **Тип**.
- **Кнопки фільтрації за категоріями**: _Усі категорії_, _За замовчуванням_, _Програмування_, _Перевірка_,
  _Документація_, _Налагодження_.

Позначка **Тип** кожного провайдера вказує, у який спосіб він надається безкоштовно:

| Позначка | Значення                                              |
| -------- | ----------------------------------------------------- |
| `NOAUTH` | Завжди безкоштовно, облікові дані не потрібні         |
| `OAUTH`  | OAuth-провайдер із безкоштовним рівнем (`hasFree`)    |
| `APIKEY` | Провайдер API-ключа з безкоштовним рівнем (`hasFree`) |

Оцінки відображаються як зрозумілі людині позначення (наприклад, _Елітна_, _Відмінна_, _Дуже добра_,
_Добра_, _Середня_), а не як необроблені числа, оскільки базове значення є відносною
оцінкою якості в рейтингу, а не відсотком.

### Кінцева точка API

Сторінка використовує загальнодоступну кінцеву точку для читання
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

Параметри запиту (перевіряються за допомогою Zod):

| Параметр   | Тип    | Значення за замовчуванням | Примітки                                                                                                            |
| ---------- | ------ | ------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `category` | string | (немає)                   | Одне зі значень: `default`, `coding`, `review`, `documentation`, `debugging`. Не вказуйте для об’єднаного рейтингу. |
| `limit`    | number | `50`                      | Обмежується діапазоном `1–100`.                                                                                     |

Структура відповіді:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` — це початкове значення Arena ELO; `score` — нормалізоване значення відповідності завданню
(див. нижче). Провайдери, які не мають оцінених моделей, не включаються до відповіді.

## Як працюють оцінки

### Джерело: рейтинг Arena AI

Механізм синхронізації Arena ELO (`src/lib/arenaEloSync.ts`) отримує два рейтинги — `text`
і `code` — з API рейтингу Arena AI
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`). Кожен запис рейтингу
містить назву моделі, постачальника, оцінку ELO `score`, довірчий інтервал і кількість голосів.

Категорії рейтингу зіставляються з категоріями завдань OmniRoute:

| Рейтинг Arena | Категорії завдань OmniRoute                       |
| ------------- | ------------------------------------------------- |
| `text`        | `default`, `review`, `documentation`, `debugging` |
| `code`        | `coding`                                          |

### Нормалізація (оцінка відповідності завданню)

Необроблені оцінки ELO нормалізуються окремо для кожного рейтингу до **значення відповідності завданню в діапазоні `[0.4, 0.98]`**:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

Оцінка ніколи не досягає `0` або `1`, залишаючи запас для користувацьких перевизначень. Це
поле `score`, яке ви бачите у відповіді API, і позначка, що відображається на інформаційній панелі.

### Рівень довіри

Кожен запис отримує рівень довіри на основі кількості голосів в Arena:

| Рівень довіри | Голоси  |
| ------------- | ------- |
| `high`        | ≥ 5 000 |
| `medium`      | ≥ 1 000 |
| `low`         | < 1 000 |

### Зберігання та актуальність

Нормалізовані записи зберігаються в таблиці БД `model_intelligence` зі значенням
`source = "arena_elo"` (`src/lib/db/modelIntelligence.ts`). Термін дії записів **спливає через
7 днів**, тож постачальник, який припинив синхронізацію, зрештою зникає замість того, щоб
надавати застарілі дані.

Синхронізацію **увімкнено за замовчуванням**:

- Вона виконується один раз під час запуску сервера, а потім періодично за таймером
  (`src/lib/arenaEloSync.ts`, підключено з `src/instrumentation-node.ts`).
- Вона **не блокує роботу й ніколи не спричиняє критичної помилки** — якщо отримати дані з зовнішнього джерела не вдається, OmniRoute продовжує
  працювати, а рейтинги просто показують останні коректні дані (або порожній стан).

Її роботу контролюють дві змінні середовища (описані в
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)):

| Змінна                    | Значення за замовчуванням | Призначення                                                     |
| ------------------------- | ------------------------- | --------------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`                    | Установіть `false`, щоб відмовитися від вихідної синхронізації. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24 год)          | Інтервал синхронізації в секундах.                              |

### Ручна синхронізація / стан / очищення

Для операторів автентифікована кінцева точка керування надає можливість ручного керування
(`src/app/api/intelligence/sync/route.ts` — потребує автентифікації для керування):

```
GET    /api/intelligence/sync          # поточний стан синхронізації (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # запустити ручну синхронізацію; тіло: { "dryRun": true } для попереднього перегляду без запису
DELETE /api/intelligence/sync          # очистити всі синхронізовані записи даних arena_elo
```

Якщо сторінка рейтингів порожня, ручний запит `POST /api/intelligence/sync` (або простий
перезапуск сервера) повторно наповнить її даними.

### Зіставлення моделей із рейтингом

Ідентифікатори моделей у реєстрі та назви моделей Arena не завжди збігаються точно. Для рейтингу використовується
гнучке зіставлення (`findMatchingIntelligence` у `src/lib/freeProviderRankings.ts`):

1. Точний збіг нормалізованого ідентифікатора моделі.
2. Збіг після видалення суфікса версії в кінці (наприклад, `kimi-k2.6` → `kimi-k2`).
3. Збіг за префіксом (назва моделі в рейтингу є префіксом ідентифікатора в реєстрі).

Під час синхронізації відомі префікси постачальників (`anthropic/`, `openai/`, `google/`, …)
видаляються, а невелика карта псевдонімів розгортає канонічні назви у варіанти, які OmniRoute використовує
всередині, тому моделі можна знайти за будь-якою назвою.

### Як визначається місце постачальника в рейтингу

Для кожного безплатного постачальника механізм оцінює кожну модель у його каталозі, а потім:

- **Найкраща модель** = модель постачальника з найвищою оцінкою.
- **Середня оцінка** = середнє значення оцінок усіх оцінених моделей цього постачальника.
- **Моделі** = кількість моделей постачальника, які мали оцінку Arena.

Постачальники сортуються спочатку за **оцінкою найкращої моделі**, а потім за середньою оцінкою. Це надає перевагу
постачальнику, який пропонує принаймні одну потужну безплатну модель.

## Використання для вибору безкоштовних провайдерів

1. **Виберіть правильну категорію.** Використовуйте фільтр **Coding** для агентних завдань і завдань із кодом або
   залиште **All Categories** / **Default** для загального спілкування. Один і той самий провайдер може
   мати різні позиції в різних категоріях, оскільки його найкраща модель відрізняється залежно від таблиці лідерів.
2. **Для налаштувань з одним провайдером віддавайте перевагу призерам.** Якщо ви хочете підключити лише одного або двох безкоштовних
   провайдерів, почніть із тих, що посідають найвищі місця у вашій категорії.
3. **Перевірте позначку Type.** Провайдери `NOAUTH` підключаються найшвидше (без
   облікових даних). Безкоштовні рівні `OAUTH` / `APIKEY` потребують швидкої реєстрації, але часто надають доступ до
   потужніших моделей. Інструкції з підключення див. у [Посібнику з безкоштовних рівнів](../getting-started/FREE-TIERS-GUIDE.md).
4. **Підключіть кілька провайдерів і дозвольте Auto-Combo зробити вибір.** Ті самі дані Arena ELO, на основі яких працює
   ця сторінка, також використовуються для **коефіцієнта відповідності завданню** механізму оцінювання Auto-Combo
   (`open-sse/services/autoCombo/taskFitness.ts`, порядок визначення:
   `user_override → arena_elo → models_dev_tier → static table`). Тож після підключення
   найкращих безкоштовних провайдерів маршрутизація з `model: "auto"` (наприклад, `auto/coding`) буде
   автоматично віддавати перевагу якіснішим безкоштовним моделям для кожного запиту. Повний опис оцінювання за 16 факторами див. у
   [Auto-Combo](../routing/AUTO-COMBO.md).
