## 1. Antigravity і Antigravity CLI (agy): порівняння

Обидва провайдери використовують **однакову серверну інфраструктуру Google** — ідентичний клієнт OAuth, оновлення токенів, кінцеві точки та облікові записи Google. Відмінність полягає в тому, які моделі вам доступні.

> Офіційне порівняння від Google див. в [оголошенні про Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli).

| Аспект                            | `antigravity` (IDE)                                    | `agy` (CLI)                                                    |
| --------------------------------- | ------------------------------------------------------ | -------------------------------------------------------------- |
| **Продукт Google**                | Antigravity 2.0 / Antigravity IDE                      | Antigravity CLI                                                |
| **Серверна інфраструктура**       | Той самий Google Cloud Code API                        | Той самий Google Cloud Code API                                |
| **OAuth / токен**                 | Той самий клієнт, те саме оновлення                    | Той самий клієнт, те саме оновлення                            |
| **Каталог моделей**               | Статичний кураторський список (вбудований в OmniRoute) | Динамічно отримується від Google через `:fetchAvailableModels` |
| **Моделі Claude**                 | Sonnet 4.6, Opus 4.6 (по 4 варіанти кожної)            | Sonnet 4.6, Opus 4.6 (по 4 варіанти кожної)                    |
| **Назви Gemini**                  | Зрозумілі мітки (Low/Medium/High)                      | Внутрішні ідентифікатори (extra-low/low/agent)                 |
| **Додаткові моделі**              | `gpt-oss-120b-medium`                                  | Може містити додаткові моделі від Google                       |
| **Типовий сценарій використання** | Інтеграція з IDE (VS Code, JetBrains)                  | Доступ через CLI / API                                         |
| **Квота**                         | Спільна з agy (той самий обліковий запис Google)       | Спільна з antigravity (той самий обліковий запис Google)       |

**Доступні моделі (перевірено експериментально, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (різні рівні міркування)
- Claude: Sonnet 4.6, Opus 4.6 (кожна у варіантах default/low/medium/high)
- Інші: GPT-OSS 120B Medium
- **Claude Sonnet 5 НЕДОСТУПНА** — підтримуються лише варіанти 4.6

**Чому каталоги моделей відрізняються**: CLI від Google «оптимізований для швидкості та низьких накладних витрат» і «спільно оптимізований із моделями Gemini» (згідно з офіційним блогом Google). Вебпродукт / IDE «оптимізований для комплексності». CLI використовує `:fetchAvailableModels` для динамічного виявлення моделей, тоді як IDE використовує статичний кураторський список.

**На практиці**: використовуйте префікс `agy/` для моделей Gemini (наприклад, `agy/gemini-3.7-flash-high`). Для статичного кураторського списку використовуйте `antigravity/`. Обидва звертаються до тієї самої серверної інфраструктури Google, але надають різні назви моделей. Квота є спільною — використання будь-якого з провайдерів зараховується до лімітів того самого облікового запису Google.

## 2. Google One AI Pro: система квот

> Офіційні відомості про квоти див. у [документації Antigravity: плани](https://antigravity.google/docs/plans), а останні оновлення цін — у [змінах у планах Antigravity](https://antigravity.google/blog/changes-to-antigravity-plans).

Google Antigravity використовує **дворівневу систему квот**, що базується на «виконаній роботі» (обчислювальному навантаженні), а не на кількості повідомлень.

### Два рівні

| Рівень              | Що це таке                           | Цикл оновлення                                                                  |
| ------------------- | ------------------------------------ | ------------------------------------------------------------------------------- |
| **5-годинний цикл** | Безпосередній пул «виконаної роботи» | Скидається через 5 годин після першого запиту в сеансі                          |
| **7-денний ліміт**  | Жорстке тижневе обмеження            | Має пріоритет над 5-годинним оновленням; блокує до наступного 7-денного періоду |

**Як обчислюється «виконана робота»**: завдання з активним використанням агента (наприклад, «Виконай рефакторинг усього цього репозиторію») витрачають квоту набагато швидше, ніж прості завдання (наприклад, «Виправ цю функцію»). Панелі моніторингу споживання в реальному часі немає.

### Рівні планів

| План         | Ціна       | Квота                                    | Тижневий ліміт                     |
| ------------ | ---------- | ---------------------------------------- | ---------------------------------- |
| Free         | $0         | Значна квота, оновлюється щотижня        | Так                                |
| AI Pro       | $19.99/mo  | Висока квота, ковзне 5-годинне оновлення | Так (має пріоритет над 5-годинним) |
| AI Ultra 5x  | $99.99/mo  | У 5 разів більша квота, ніж у Pro        | Без тижневого ліміту               |
| AI Ultra 20x | $199.99/mo | У 20 разів більша квота, ніж у Pro       | Без тижневого ліміту               |

### Моделі Gemini та інші моделі

- **Моделі Gemini** (Flash + Pro): спільно використовують єдиний ліміт частоти запитів, який витрачається відповідно до тарифів API. Якщо Flash у 8 разів дешевша за Pro, ви отримуєте у 8 разів більше токенів Flash.
- **Моделі, відмінні від Gemini** (Claude, GPT-OSS): мають **окремі** ліміти частоти запитів. Вони можуть залишатися доступними, навіть коли Gemini заблоковано.

### Кредити AI (перевищення квоти)

> Інформацію про використання кредитів див. у статті [Кредити Google One AI](https://support.google.com/googleone/answer/14534406).

Коли базову квоту вичерпано:

- **Ніколи**: очікувати оновлення квоти; відображається повідомлення «Досягнуто базової квоти моделі»
- **Завжди**: автоматично використовувати кредити AI; після оновлення базової квоти система повертається до неї

Кредити купуються окремо та списуються за стандартними тарифами API.

### Ключові відомості

- Квота є **спільною на рівні облікового запису** — той самий обліковий запис Google в Antigravity IDE, CLI та OmniRoute використовує один спільний пул квоти
- Кожен обліковий запис Google має власну незалежну квоту — кілька облікових записів = кілька пулів квоти
- Користувачі AI Pro повідомляли про **7-денні блокування** замість 5-годинних скидань після досягнення тижневого базового ліміту (Google підтвердила, що за високого попиту це передбачена поведінка)

**Коли квоту вашого облікового запису вичерпано**: OmniRoute автоматично повторює спробу з наступним доступним обліковим записом у комбінованому маршруті. Ручне втручання не потрібне.

## 3. Як отримати projectId

Для кожного підключення antigravity/agy потрібен Google Cloud Code `projectId`. Без нього кінцева точка `/v1internal:models` повертає помилку 404.

### Спосіб A: автоматично (рекомендовано)

OmniRoute виконує це автоматично. Коли ви додаєте новий обліковий запис Google через OAuth на панелі керування:

1. OmniRoute оновлює токен
2. Викликає `loadCodeAssist`, щоб визначити projectId
3. Якщо проєкту немає, викликає `onboardUser`, щоб створити його
4. Повторно викликає `loadCodeAssist`, щоб отримати щойно створений projectId
5. Зберігає його в базі даних

**Це працює для більшості облікових записів** — ручні дії не потрібні.

### Спосіб B: вручну через agy CLI

Якщо автоматичне визначення не вдалося (випадки, коли це трапляється, див. у розділі 5):

```bash
# Установіть agy CLI (якщо його ще не встановлено)
npm install -g @anthropic-ai/agy

# Увійдіть за допомогою свого облікового запису Google
agy login

# Виберіть обліковий запис, який потрібно зареєструвати
# Це запускає реєстрацію Cloud Code та призначає projectId
```

Після успішного виконання `agy login` оновіть токен на панелі керування OmniRoute. projectId буде визначено автоматично.

### Як перевірити

Перевірте базу даних:

```bash
# Усередині контейнера OmniRoute
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Або перевірте журнали:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. URI перенаправлення OAuth

### Проблема

Google OAuth вимагає дійсний URI перенаправлення. OmniRoute за замовчуванням використовує `http://127.0.0.1:20128/callback` (loopback-адресу). Це працює для локальних збірок, але **не працює для віддалених розгортань** (наприклад, на сервері, доступ до якого здійснюється через IP-адресу локальної мережі).

Google відхиляє URI перенаправлення, які:

- Використовують IP-адреси (потрібен домен, що закінчується на `.com`, `.org` тощо)
- Не збігаються із зареєстрованими URI перенаправлення в конфігурації клієнта OAuth

### Рішення

**Варіант A: Використовуйте вбудований процес OAuth (за замовчуванням)**

- Працює, коли ви отримуєте доступ до OmniRoute через `localhost` або `127.0.0.1`
- Налаштування не потрібне

**Варіант B: Власні облікові дані OAuth**

- Установіть `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` у своєму середовищі
- Надайте власні облікові дані Google OAuth:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Зареєструйте `https://your-domain.com/callback` як авторизований URI перенаправлення в Google Cloud Console

**Варіант C: Використовуйте agy CLI для початкового входу**

- Запустіть `agy login` на комп’ютері, з якого здійснюватиметься доступ до OmniRoute
- Процес OAuth завершиться локально, а токени буде збережено
- Імпортуйте підключення в OmniRoute через панель керування

### Обмеження

- Власні облікові дані OAuth потребують доменного імені (Google не приймає IP-адреси як URI перенаправлення)
- Якщо у вас немає домену, скористайтеся натомість варіантом A або C

## 5. Усунення несправностей: коли автоматичне налаштування не працює

Для більшості облікових записів OmniRoute автоматично виконує виявлення projectId і початкове налаштування. Якщо цей процес завершується помилкою, основна причина зазвичай полягає в одному з наведених нижче факторів:

### Регіон облікового запису заблоковано

**Ознака**: `agy login` повертає повідомлення «Eligibility check failed: Your current account is not eligible for Antigravity, because it is not currently available in your location.»

**Основна причина**: Облікові записи Google мають внутрішнє поле «Country Association», значення якого встановлюється під час реєстрації. agy CLI та Cloud Code API суворо перевіряють це поле — на відміну від вебверсії Gemini, яка перевіряє лише вашу поточну IP-адресу.

> Щоб перевірити або змінити регіон, пов’язаний із вашим обліковим записом, відвідайте [форму прив’язки країни Google](https://policies.google.com/country-association-form).

**Чому вебверсія Gemini працює, а agy — ні**:

- Вебверсія Gemini / Google One: перевіряє лише поточну IP-адресу (проксі допомагає пройти перевірку)
- agy CLI / Cloud Code API: зчитує внутрішнє поле Country Association (проксі не допомагає)

**Виправлення**:

1. Відвідайте [форму прив’язки країни Google](https://policies.google.com/country-association-form), використовуючи IP-адресу США
2. Надішліть запит на зміну регіону (виберіть «I live in a different country»)
3. Зачекайте від 1 до 24 годин, поки Google опрацює запит і надішле сповіщення електронною поштою
4. Після цього команда `agy login` має виконатися успішно

### Обліковий запис не має проєкту Cloud Code

**Ознака**: У журналах відображаються повідомлення `loadCodeAssist returned no project id` і `onboardUser failed (400)`.

**Основна причина**: Обліковий запис ніколи не було зареєстровано в Google Cloud Code, а автоматичне початкове налаштування завершилося помилкою.

**Виправлення**: Запустіть `agy login` вручну, щоб ініціювати реєстрацію в Cloud Code, а потім оновіть токен у панелі керування OmniRoute.

### Термін дії токена завершився або його відкликано

**Ознака**: Помилки 401 у журналах або повідомлення «Token has expired».

**Виправлення**: Оновіть токен у розділі «Панель керування → Постачальники → agy → Натисніть піктограму оновлення». Якщо сам токен оновлення було відкликано, вам потрібно буде повторно автентифікуватися через OAuth.

## Блок-схема прийняття рішень

```
Обліковий запис не працює?
│
├─ Чи має він projectId у базі даних?
│  ├─ ТАК → Проблема в іншому (термін дії токена минув, обмеження частоти запитів тощо)
│  └─ НІ ↓
│
├─ Чи встановлено для облікового запису в Country Association регіон з обмеженнями?
│  ├─ ТАК → Змініть регіон у формі Google Country Association
│  │         (https://policies.google.com/country-association-form)
│  │         Зачекайте 1–24 години, а потім повторіть спробу
│  └─ НІ ↓
│
├─ Чи має обліковий запис підписку Google One AI Pro?
│  ├─ НІ → Спочатку оформіть підписку на one.google.com
│  └─ ТАК ↓
│
├─ Спробуйте автоматичне виявлення (оновіть токен у Dashboard)
│  ├─ Працює → Готово
│  └─ Усе ще не працює ↓
│
└─ Вручну: виконайте `agy login` на комп’ютері
   ├─ Працює → Оновіть токен у Dashboard, projectId буде виявлено
   └─ Не працює → Перевірте повідомлення про помилку; імовірно, проблема з регіоном або підпискою
```
