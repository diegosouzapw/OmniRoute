**OmniCopilot** додає кожну модель, яку обслуговує ваш OmniRoute, до _вбудованого_ засобу вибору моделей GitHub Copilot Chat.
Жодної другої бічної панелі чи окремого інтерфейсу чату — режим агента Copilot, виклики інструментів,
сервери MCP і користувацькі інструкції продовжують працювати, просто на вибраній вами моделі.

|                             |                                                                                                                                                 |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Установлення (VS Code)**  | [Marketplace → `diegosouzapw.omnicopilot`](https://marketplace.visualstudio.com/items?itemName=diegosouzapw.omnicopilot)                        |
| **Установлення (форки)**    | [Open VSX](https://open-vsx.org/extension/diegosouzapw/omnicopilot) — Cursor, Windsurf, VSCodium, Theia, code-server, Gitpod, Antigravity, Kiro |
| **Вихідний код / проблеми** | [github.com/diegosouzapw/OmniCopilot](https://github.com/diegosouzapw/OmniCopilot) (MIT)                                                        |
| **Вимоги**                  | VS Code 1.104+                                                                                                                                  |

> **Підписка на Copilot не потрібна.** Починаючи з VS Code 1.122, постачальник мовних моделей працює
> без входу через GitHub і без будь-якого плану Copilot. Вбудовані доповнення коду та
> функції на основі векторних представлень залишаються поза API постачальника й усе ще потребують Copilot.

## Налаштування

1. **Запустіть OmniRoute** — `npm install -g omniroute && omniroute` (панель керування доступна на `http://localhost:20128`).
2. **Установіть розширення** — знайдіть «OmniRoute» у поданні розширень.
3. **Виберіть модель** — Copilot Chat → засіб вибору моделей → **Керувати моделями…** → **OmniRoute**, а потім позначте
   потрібні моделі.

Коли OmniRoute працює на стандартному порту, нічого налаштовувати не потрібно. Для віддаленого екземпляра відкрийте
**піктограму OmniRoute на панелі активності** (або виконайте `OmniRoute: Manage Connection`) і вкажіть:

- **URL сервера** — коренева адреса сервера, наприклад `http://192.168.0.15:20128`. Суфікс `/v1`
  додається розширенням; не включайте його.
- **Ключ API** — лише якщо на сервері задано `REQUIRE_API_KEY`. Зберігається у сховищі ключів ОС через
  VS Code SecretStorage, а не в `settings.json`.

## Що відображатиметься в засобі вибору

Розширення не відображає необроблений вміст відповіді `GET /v1/models` — воно перетворює його, тому кількість,
яку ви бачите, менша за розмір каталогу з двох навмисних причин.

### Воно запитує один ідентифікатор для кожної моделі

Стандартне значення `MODELS_CATALOG_PREFIX_MODE` — **`dual`**, за якого кожна модель оголошується двічі: один раз
із коротким префіксом псевдоніма й один раз із канонічним префіксом постачальника, — щоб старі конфігурації
клієнтів і надалі могли розпізнавати обидві форми:

```
cc/claude-sonnet-4-6        ← префікс псевдоніма
claude/claude-sonnet-4-6    ← канонічний префікс, та сама модель
```

Розширення надсилає запит **`GET /v1/models?prefix=alias`**, тому для кожної моделі надходить один ідентифікатор,
а загальносерверне налаштування для інших клієнтів не змінюється. На еталонному екземплярі це скоротило
**2345 записів до 1396 — 949 дублікатів, жодної втраченої моделі.**

Якщо ви бажаєте виправити це на рівні всього сервера для _кожного_ клієнта, установіть для прапорця функції
`MODELS_CATALOG_PREFIX_MODE` значення `alias` на панелі керування. Відомості про
параметр запиту та таблицю для кожного режиму див. у розділі
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix).

### Воно приховує моделі, які не підтримують чат

Каталог також містить моделі для зображень, відео, аудіо, повторного ранжування, векторних представлень і модерації.
Запити до чату для них усе одно відхиляються:

```
HTTP 400 — Модель '<id>' призначена для генерування зображень і не може використовуватися з
/v1/chat/completions. Натомість використовуйте POST /v1/images/generations.
```

тому перед відображенням у засобі вибору їх відфільтровують за полем `type`. **Моделі Responses API
зберігаються** — кожен запис Codex / GPT-5.x оголошує `supported_endpoints: ["responses"]`,
а OmniRoute перетворює їх для `/v1/chat/completions`, тому вони цілком придатні до використання.

### Постачальники, яких ви не налаштовували

Каталог містить моделі від постачальників з **активним підключенням**, а також від усіх постачальників **noAuth** —
тих, що не потребують ключів і становлять значну частину безкоштовного рівня. Це зроблено навмисно. Щоб приховати
їх, додайте їх до `blockedProviders` у налаштуваннях панелі керування; у розширенні нічого не зміниться.

## Панель керування у вкладці VS Code

`omnicopilot.dashboardOpen: "editor"` відображає панель керування OmniRoute у вкладці редактора за допомогою
Simple Browser замість зовнішнього браузера. Вбудовування **активується на сервері за бажанням** через
`DASHBOARD_ALLOW_EMBED=vscode`, унаслідок чого HTML-сторінки надсилаються із
`frame-ancestors 'self' vscode-webview:` замість стандартних `frame-ancestors 'none'` +
`X-Frame-Options: DENY`. Поверхня API (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) у будь-якому разі
зберігає суворі заголовки.

> ⚠️ **Це параметр часу збирання, а не виконання.** Next.js компілює `headers()` у маніфест
> маршрутів, тому `next.config.mjs` зчитує змінну під час збирання пакета
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> Експортування її перед запуском уже зібраного сервера нічого не змінює — заголовки вбудовано під час збирання.

```bash
# змінна має бути задана для команди ЗБИРАННЯ
DASHBOARD_ALLOW_EMBED=vscode npm run build        # або npm run build:release
npm start
```

| Спосіб установлення        | Чи можна ввімкнути вбудовування?                                                                                                                    |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| З вихідного коду           | ✅ задайте змінну для команди збирання, як показано вище                                                                                            |
| `npm install -g omniroute` | ❌ опублікований пакет містить попередньо зібраний пакет — натомість зберіть із вихідного коду                                                      |
| Образ Docker               | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — попередньо зібраний образ на Docker Hub не підтримує вбудовування |

Без збирання з підтримкою вбудовування сторінка відмовляється відображатися у фреймі, розширення визначає це за
заголовками відповіді та повертається до зовнішнього браузера — нічого не порушується, і воно один раз повідомляє про це.
Див. [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) та проблему
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273).

## Налаштування інших інструментів із VS Code

**`OmniRoute: Configure Coding CLI`** використовує CLI `omniroute` для створення готових до використання профілів
для Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code,
Kilo та Roo — тих самих конфігурацій, які описано в
[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md). Ключ API передається CLI через змінну середовища
`OMNIROUTE_API_KEY`, а не через командний рядок.

## Усунення несправностей

| Симптом                                                        | Причина / вирішення                                                                                                                                                                                                                                                                                         |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| У засобі вибору немає моделей OmniRoute                        | Сервер недоступний. Крапка в рядку стану стає сірою; запустіть `OmniRoute: Check Connection`. Виявлення навмисно відбувається без сповіщень і не додає жодних моделей замість показу запиту.                                                                                                                |
| Кожна модель відображається двічі                              | Ви використовуєте OmniCopilot версії, старішої за 1.0.1 — оновіть його. Тепер розширення надсилає запит `?prefix=alias`.                                                                                                                                                                                    |
| Модель зображень/аудіо раніше була в списку, але зникла        | Це зроблено навмисно, починаючи з версії 1.0.1 — така модель ніколи не могла відповісти на запит чату.                                                                                                                                                                                                      |
| Панель відсутня на панелі активності                           | VS Code переміщує додаткові контейнери подань до меню переповнення **"…"** внизу панелі активності, а контейнер, прихований через контекстне меню, залишається прихованим. Клацніть панель активності правою кнопкою → позначте **OmniRoute** або відкрийте її за допомогою `OmniRoute: Manage Connection`. |
| Панель керування відкривається в браузері попри режим `editor` | Сервер не було **зібрано** з `DASHBOARD_ALLOW_EMBED=vscode` (див. вище) — установлення цієї змінної під час запуску попередньо зібраної інсталяції нічого не змінює. Перехід до резервного варіанта є навмисним.                                                                                            |
| Список моделей застарів після зміни постачальників             | `OmniRoute: Refresh Models` або посилання ↻ на панелі.                                                                                                                                                                                                                                                      |
