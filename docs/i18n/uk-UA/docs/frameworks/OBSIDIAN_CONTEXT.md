> **Джерело істини:** `src/lib/obsidian/api.ts` (клієнт REST + синхронізації),
> `src/lib/db/obsidian.ts` (зберігання токена / базової URL-адреси / WebDAV),
> `src/lib/obsidianSync.ts` (синхронізація сховища через WebDAV), `open-sse/mcp-server/tools/obsidianTools.ts`
> (22 інструменти MCP), `src/app/api/settings/obsidian/route.ts` +
> `src/app/api/settings/obsidian/webdav/route.ts` (API налаштувань). Реєстрація інструментів
> і прив’язування областей доступу розміщені в `open-sse/mcp-server/server.ts`.

## Що це таке

OmniRoute підключається до сховища **Obsidian** як до **джерела контексту** — локальної бази
знань Markdown, яку агенти читають і змінюють через вбудований сервер MCP. Інтеграція
взаємодіє зі стороннім плагіном **Obsidian Local REST API**, запущеним у настільному
застосунку, тому агенти можуть шукати нотатки, читати/записувати/редагувати файли, переглядати
вміст сховища, працювати зі щоденними/щотижневими періодичними нотатками, керувати тегами,
виконувати команди Obsidian і (за бажанням) координувати двонапрямну синхронізацію сховища
між настільним і мобільним пристроями.

Клієнт (`src/lib/obsidian/api.ts`) надає обгортку для Local REST API з такими можливостями:

- **Повторні спроби з відтермінуванням** для тимчасових помилок `5xx`, **30-секундний тайм-аут** через `AbortController`.
- **Типізована класифікація помилок** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- **Зрозуміла підказка «не вдається підключитися до Obsidian»**, яка вказує на поширену
  помилку з портом (HTTP на `27123`, **а не** кінцева точка MCP на `27124`) і формат Tailscale.
- **Кодування шляхів** відносно сховища, щоб безпечно обробляти шляхи до нотаток із пробілами/скісними рисками.

## Налаштування

Для токена або базової URL-адреси Obsidian **немає змінної середовища** — обидва значення
зберігаються в таблиці SQLite `key_value` (простір імен `obsidian`) через
`src/lib/db/obsidian.ts`. Токен **зашифровано в стані спокою** (AES-256-GCM, із
резервною підтримкою зворотної сумісності з відкритим текстом). Налаштуйте інтеграцію
на вкладці **Джерела контексту** панелі керування кінцевою точкою (`ObsidianSourceCard`)
або через REST API налаштувань.

> [!IMPORTANT]
> Плагін **Obsidian Local REST API** має бути встановлений і запущений. Його REST-інтерфейс
> прослуховує **HTTP `127.0.0.1:27123`** (базова URL-адреса за замовчуванням). Порт `27124`
> є _окремою_ кінцевою точкою MCP/HTTPS і явно відхиляється маршрутом налаштувань.
> Для підключення з іншого пристрою використовуйте `http://<tailscale-ip>:27123`.

### Ключі конфігурації (SQLite `key_value`, простір імен `obsidian`)

| Ключ              | Призначення                                                 | Зашифровано |
| ----------------- | ----------------------------------------------------------- | ----------- |
| `api_key`         | Токен-носій Local REST API                                  | так         |
| `base_url`        | Базова URL-адреса REST (типово `http://127.0.0.1:27123`)    | ні          |
| `vault_path`      | Абсолютний шлях до каталогу сховища (для синхронізації)     | ні          |
| `webdav_username` | Згенероване ім’я користувача WebDAV (синхронізація сховища) | ні          |
| `webdav_password` | Згенерований пароль WebDAV (синхронізація сховища)          | так         |
| `webdav_enabled`  | Чи ввімкнено синхронізацію сховища через WebDAV             | ні          |

### Налаштування через REST

```bash
# Зберегти та перевірити токен Local REST API (POST виконує перевірку через запит стану)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Перевірити стан підключення (повертає connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# Відключитися (видаляє збережений токен)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Усі методи вимагають автентифікації в панелі керування. `POST` відхиляє будь-яку URL-адресу
на порту `27124` і перевіряє токен, викликаючи кінцеву точку стану Local REST API перед
збереженням.

### Синхронізація сховища через WebDAV

`src/app/api/settings/obsidian/webdav/route.ts` керує необов’язковою синхронізацією
сховища на основі WebDAV (якою керує `src/lib/obsidianSync.ts`). Її ввімкнення
спрямовує OmniRoute до локального каталогу сховища та створює випадкову пару імені
користувача й пароля WebDAV:

```bash
# Увімкнути синхронізацію через WebDAV для каталогу сховища (створює ім’я користувача та пароль)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# Отримати стан синхронізації через WebDAV (облікові дані повертаються лише тоді, коли її ввімкнено)
curl http://localhost:20128/api/settings/obsidian/webdav

# Вимкнути синхронізацію через WebDAV (видаляє облікові дані та керований .stignore)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Джерело контексту для окремого API-ключа (необов’язково)

Конфігурацію Obsidian можна визначити **окремо для кожного API-ключа** через таблицю
`api_key_context_sources` (`src/lib/db/apiKeyContextSources.ts`). Коли виклик MCP містить
ідентифікатор автентифікованого API-ключа, `getObsidianConfigForApiKey()` надає перевагу
власному токену/базовій URL-адресі/шляху до сховища цього ключа (`source: "api_key"`),
а за їх відсутності використовує глобальну конфігурацію (`source: "global"`).

## Інструменти MCP (22)

Визначені в `open-sse/mcp-server/tools/obsidianTools.ts`. Токен і базова URL-адреса визначаються
для кожного виклику (спочатку для конкретного API-ключа, потім глобально). Інструменти, що звертаються до **сервера синхронізації**
OmniRoute (чотири інструменти `obsidian_sync_*`), додатково потребують токена автентифікації синхронізації, налаштованого
в параметрах OmniRoute.

### Інструменти читання (`read:obsidian`)

| Інструмент                   | Опис                                                                                                               |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `obsidian_check_status`      | Перевірити, чи доступний і автентифікований Local REST API.                                                        |
| `obsidian_search_simple`     | Повнотекстовий пошук у вмісті нотаток; повертає фрагменти зі шляхами до файлів.                                    |
| `obsidian_search_structured` | Пошук за допомогою виразу JSON Logic (фільтри and/or/regex/path).                                                  |
| `obsidian_read_note`         | Прочитати нотатку за шляхом відносно сховища; за потреби — певний заголовок, блок або frontmatter.                 |
| `obsidian_list_vault`        | Отримати список файлів і каталогів у сховищі (дерево записів).                                                     |
| `obsidian_get_document_map`  | Отримати структуру заголовків нотатки у вигляді мапи «заголовки → номери рядків».                                  |
| `obsidian_get_note_metadata` | Отримати frontmatter, теги, посилання, кількість символів і слів без повного вмісту.                               |
| `obsidian_get_active_file`   | Отримати шлях і вміст поточного активного файлу в Obsidian.                                                        |
| `obsidian_get_periodic_note` | Отримати щоденну, щотижневу або щомісячну періодичну нотатку для дати (сьогодні, якщо дату не вказано).            |
| `obsidian_get_tags`          | Отримати список усіх тегів сховища та частоту їх використання.                                                     |
| `obsidian_list_commands`     | Отримати список доступних ідентифікаторів команд Obsidian (для використання з `obsidian_execute_command`).         |
| `obsidian_sync_status`       | Стан сервера синхронізації OmniRoute: робота, назва сховища, порт, час безперервної роботи, остання синхронізація. |
| `obsidian_sync_conflicts`    | Отримати список невирішених конфліктів синхронізації (шлях, шлях конфлікту, час виявлення).                        |

### Інструменти запису (`write:obsidian`)

| Інструмент                       | Опис                                                                                                                       |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Створити або перезаписати нотатку із заданим вмістом Markdown.                                                             |
| `obsidian_append_note`           | Додати вміст до нотатки; за потреби — до певного заголовка або блока.                                                      |
| `obsidian_patch_note`            | Точково додати після, додати перед або замінити вміст заголовка, блока чи поля frontmatter.                                |
| `obsidian_delete_note`           | Безповоротно видалити нотатку зі сховища.                                                                                  |
| `obsidian_move_note`             | Перемістити або перейменувати нотатку в межах сховища.                                                                     |
| `obsidian_execute_command`       | Виконати команду Obsidian за її ідентифікатором.                                                                           |
| `obsidian_open_file`             | Відкрити файл в Obsidian (створює його, якщо він не існує).                                                                |
| `obsidian_sync_trigger`          | Запустити негайну двонапрямну синхронізацію сховища між настільним і мобільним пристроями.                                 |
| `obsidian_sync_resolve_conflict` | Вирішити конфлікт синхронізації: зберегти `local` (мобільну версію), `remote` (настільну версію) або `keep-both` (обидві). |

> [!NOTE]
> Цілі `obsidian_patch_note` приймають `targetType` зі значенням `heading | block | frontmatter`
> і `operation` зі значенням `append | prepend | replace`, а також необов’язковий параметр
> `createTargetIfMissing`. Чотири інструменти `obsidian_sync_*` взаємодіють із локальним сервером
> синхронізації (`http://127.0.0.1:27781` за замовчуванням) і потребують токена синхронізації.

### Області доступу

Інструменти читання потребують `read:obsidian`; інструменти запису потребують `write:obsidian`. Застосування
правил ідентичне Notion — виконується функцією `withScopeEnforcement()` у
`open-sse/mcp-server/server.ts`, активується за умови `OMNIROUTE_MCP_ENFORCE_SCOPES=true`, а
дозволені області доступу отримуються з `OMNIROUTE_MCP_SCOPES` або контексту областей доступу API-ключа. Див.
[MCP-SERVER.md](./MCP-SERVER.md).

## Кінцеві точки

| Метод    | Шлях                            | Призначення                                                    |
| -------- | ------------------------------- | -------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | Повертає `{ connected, hasToken, baseUrl, vaultPath }`.        |
| `POST`   | `/api/settings/obsidian`        | Зберігає та перевіряє токен (порт `27124` відхиляється).       |
| `DELETE` | `/api/settings/obsidian`        | Відключає (видаляє збережений токен).                          |
| `GET`    | `/api/settings/obsidian/webdav` | Статус синхронізації WebDAV та облікові дані (коли ввімкнено). |
| `POST`   | `/api/settings/obsidian/webdav` | Вмикає синхронізацію WebDAV для каталогу сховища.              |
| `DELETE` | `/api/settings/obsidian/webdav` | Вимикає синхронізацію WebDAV.                                  |

> Це маршрути налаштувань панелі керування. Доступ до самого сховища здійснюється через
> Local REST API Obsidian (налаштований `base_url`) і наведені вище інструменти MCP —
> загальнодоступної кінцевої точки проксі Obsidian `/v1` немає.

## Варіанти використання

- **Відповіді на основі сховища** — `obsidian_search_simple` / `obsidian_search_structured`,
  а потім `obsidian_read_note`, щоб агент відповідав на основі ваших справжніх нотаток.
- **Створення нотаток / ведення щоденника** — `obsidian_write_note`, `obsidian_append_note` або
  точковий `obsidian_patch_note` для запису у сховище результатів роботи агента, підсумків чи щоденних нотаток
  (`obsidian_get_periodic_note`).
- **Навігація сховищем** — `obsidian_list_vault`, `obsidian_get_document_map` і
  `obsidian_get_tags` для вивчення структури перед читанням або записом.
- **Автоматизація Obsidian** — `obsidian_list_commands` + `obsidian_execute_command` для
  запуску плагінів і команд агентом; `obsidian_open_file` — для відкриття нотатки в інтерфейсі.
- **Мобільна синхронізація** — увімкніть синхронізацію WebDAV, а потім використовуйте `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  для координації між комп’ютером і мобільним пристроєм та розв’язання конфліктів.
