> **Джерело істини:** `src/lib/localCorpus/index.ts` (обмежений текстовий індекс),
> `src/lib/localCorpus/configured.ts` (налаштоване середовище виконання),
> `src/lib/db/localCorpus.ts` (збереження кореневого шляху),
> `open-sse/mcp-server/tools/localCorpusTools.ts` (3 інструменти MCP лише для читання) та
> `src/app/api/settings/local-corpus/route.ts` (API налаштувань).

## Що це

Local Corpus дає оператору змогу надати MCP-серверу OmniRoute доступ до одного явно схваленого каталогу текстових файлів. Файли залишаються у своєму початковому каталозі: OmniRoute зберігає в SQLite лише канонічний кореневий шлях і підтримує пошуковий індекс у пам’яті. Вміст корпусу не копіюється до репозиторію чи бази даних.

Індекс оновлюється інкрементно. Незмінені файли повторно використовуються на основі їхнього розміру та часу змінення, змінені файли перечитуються й хешуються за допомогою SHA-256, а видалені файли вилучаються. Під час пошуку індекс оновлюється, якщо він старіший за 30 секунд; клієнти також можуть запитати негайне оновлення.

## Налаштування джерела

Маршрут налаштувань вимагає такої самої автентифікації керування, як і інші API налаштувань. Наданий шлях має вже існувати та бути абсолютним шляхом до каталогу.

```bash
# Підключити схвалений каталог
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# Перевірити конфігурацію та стан індексу
curl http://localhost:20128/api/settings/local-corpus

# Відключити, не змінюючи вихідні файли
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## Інструменти MCP

Усі три інструменти потребують `read:local-corpus`. Відповіді інструментів містять відносні шляхи та базове ім’я кореневого каталогу, але ніколи не містять його абсолютного шляху.

| Інструмент            | Опис                                                                                  |
| :-------------------- | :------------------------------------------------------------------------------------ |
| `local_corpus_status` | Повідомляє стан конфігурації, розмір індексу, обмеження та час останнього оновлення   |
| `local_corpus_search` | Шукає індексований текст і повертає обмежені фрагменти за рядками (до 20 результатів) |
| `local_corpus_read`   | Читає обмежений діапазон рядків з одного дозволеного файлу, заданого відносно корпусу |

Приклади вхідних даних MCP:

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## Межі безпеки

- Список дозволених типів орієнтований на текстові файли: `.cfg`, `.csv`, `.geojson`, `.htm`, `.html`, `.ini`,
  `.js`, `.json`, `.jsonl`, `.jsx`, `.log`, `.md`, `.mjs`, `.ps1`, `.py`, `.sh`,
  `.sql`, `.toml`, `.ts`, `.tsx`, `.txt`, `.xml`, `.yaml` і `.yml`.
- Символічні посилання пропускаються. Шляхи читання канонізуються й мають залишатися в межах
  налаштованого кореневого каталогу; абсолютні шляхи та спроби обходу каталогів відхиляються.
- Каталоги із чутливими й згенерованими даними виключаються: `.build`, `.codex`, `.env`,
  `.git`, `.next`, `.omniroute`, `.ssh`, `coverage`, `dist`, `node_modules` і
  `secrets`.
- Типові обмеження: 5 000 файлів, 1 MiB на файл, 64 MiB загального індексованого вмісту,
  приблизно 4 000 символів на пошуковий фрагмент і 400 рядків на операцію читання.
- Файли, що містять NUL, вважаються нетекстовими та пропускаються або відхиляються.

Бінарні документи, як-от PDF, DOCX, зображення та архіви, навмисно не підтримуються. Перед індексуванням перетворіть їх на схвалений текстовий формат у налаштованому каталозі.

## Операційні примітки

- Змінення або видалення налаштованого кореневого каталогу очищає спільний індекс у пам’яті.
- Перезапуск процесу видаляє індекс; наступний пошук повторно створить його з налаштованого
  джерела.
- `local_corpus_status` не запускає примусове сканування. Використовуйте `local_corpus_search` із
  `refresh: true`, коли потрібне негайне повторне сканування.
- Помилки сканування та читання підраховуються або повертаються як очищені повідомлення про помилки; вихідні файли
  ніколи не змінюються.
