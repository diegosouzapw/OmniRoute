## Огляд

Search Tools Studio перетворює `/dashboard/search-tools` із базового середовища для експериментів із пошуком на
Studio із трьома вкладками, що об’єднує вебпошук, вебскрапінг і паралельне порівняння провайдерів.

```
┌ Інструменти пошуку ────────────────────────────────────────────────────┐
│ [🔍 Пошук] [📄 Скрапінг] [⚖ Порівняння]         142ms · $0.001  </>    │
│ ⓘ [Посібник із модальностей]                                           │
├──────────────────────────────────────────┬─────────────────────────────┤
│  {вміст активної вкладки}                │ ─ Конфігурація              │
│                                          │ Провайдер [авто ∨]          │
│                                          │   🟢 Serper  $0.001         │
│                                          │   🟢 Tavily  $0.008         │
│                                          │   🔥 Firecrawl (отримання)  │
│                                          │ Тип   [веб | новини]        │
│                                          │ Повна сторінка [ ] (скрапінг)│
│                                          │ Формат [md|текст|html]      │
│                                          │ Модель реранжування [∨]     │
└──────────────────────────────────────────┴─────────────────────────────┘
```

## Вкладки

### Вкладка пошуку

Розширює наявні `SearchForm` + `ResultsPanel` + `RerankPanel`, перетворюючи їх на вкладку:

- Запит → результати (заголовок, URL, фрагмент, оцінка релевантності).
- Метадані провайдера на панелі конфігурації (вартість, квота, статус).
- Розділ реранжування: вибір моделі реранжування, зміна порядку результатів, відображення `positionDelta`.
- Порожній стан із закликом до дії, якщо не налаштовано жодного пошукового провайдера.
- Історія пошуку через `SearchHistory.tsx`.
- Викликає `POST /v1/search` (наявна кінцева точка, без змін).

### Вкладка скрапінгу

Нова вкладка для видобування вмісту з URL через `POST /v1/web/fetch` (створено в плані 05):

- Введення: URL + перемикач повної сторінки + вибір формату (Markdown / текст / HTML).
- Надсилання → отримання → рендеринг `ScrapeResult.tsx`.
- `ScrapeResult` рендерить попередній перегляд Markdown і перемикач необробленого вмісту.
- Обмеження: якщо тіло відповіді перевищує **256 KB**, інтерфейс показує `(обрізано, переглянути необроблений вміст)` і відкриває необроблений вміст у модальному вікні Monaco (D21).
- Панель метаданих: провайдер (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search), затримка, вартість, розмір відповіді, кількість посилань.
- Використовує хук `useScrapeFetch.ts`.

### Вкладка порівняння

Виконує однаковий запит/URL паралельно через щонайбільше **4 провайдери** (D22):

- Розташовані поруч стовпці для кожного провайдера.
- Метрики: затримка, вартість, кількість результатів, розмір відповіді.
- Обчислення перетину URL для пошуку (кількість спільних URL порівняно з початковим результатом).
- Викликає `POST /v1/search` (пошук) або `POST /v1/web/fetch` (скрапінг) для кожного провайдера.

## Панель конфігурації (спільна)

`SearchToolsConfigPane.tsx` — завжди видима, її можна згорнути.

| Поле                | Примітки                                                                                  |
| ------------------- | ----------------------------------------------------------------------------------------- |
| Провайдер           | Розкривний список зі значком статусу (налаштовано / відсутній / обмежено частоту запитів) |
| Тип                 | `web` або `news` (лише для пошуку)                                                        |
| Повна сторінка      | Перемикач для скрапінгу — отримує всю сторінку замість першого видимого вмісту            |
| Формат              | `markdown`, `text` або `html` (лише для скрапінгу)                                        |
| Модель реранжування | Необов’язкова модель для реранжування після пошуку                                        |
| Історія             | Згортаний розділ історії пошуку                                                           |

## SearchConceptCard

`SearchConceptCard.tsx` — завжди видимий згортний акордеон. Пояснює:

| Концепція             | Короткий опис                                                                   |
| --------------------- | ------------------------------------------------------------------------------- |
| **Пошук**             | Отримує список вебрезультатів (заголовок, URL, фрагмент, оцінка релевантності)  |
| **Скрапінг**          | Витягує повний вміст URL (markdown, текст або HTML)                             |
| **Порівняння**        | Виконує той самий запит у N провайдерів паралельно                              |
| **Переранжування**    | Змінює порядок результатів за допомогою LLM для підвищення релевантності запиту |
| **Авто (найдешевше)** | Автоматично вибирає найдешевшого доступного провайдера                          |

## Каталог провайдерів

`ProviderCatalog.tsx` відображає повний список провайдерів з `GET /api/search/providers`
(розширений у F4 для додавання провайдерів отримання даних):

| `kind` | `"search"` (20 провайдерів) або `"fetch"` (firecrawl, jina-reader, tavily-search, tinyfish, nimble-search, anysearch-search) |

Статус **визначається під час запиту** шляхом перевірки наявності облікових даних і того,
чи всі ключі наразі перебувають у періоді очікування.

## Експорт коду

`ExportCodeModal` (імпортований із Playground Studio) + `codeExport.ts` генерують
фрагменти curl / Python / TypeScript для викликів `/v1/search` і `/v1/web/fetch`.
Заповнювач ключа API — завжди `$OMNIROUTE_API_KEY` (D11, спільний із Playground Studio).

## Зміни в бекенді

Для цієї функції знадобилася лише одна зміна в бекенді:

### Розширений `GET /api/search/providers`

`src/app/api/search/providers/route.ts` було розширено, щоб:

- Додати до масиву всіх 6 провайдерів отримання даних (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`).
- Додати `kind: "search" | "fetch"` до кожного елемента.
- Додати `status: "configured" | "missing" | "rate_limited"`, визначений на основі актуального стану облікових даних.
- Зберегти зворотну сумісність — наявні поля (`id`, `name` тощо) не змінено.

## Усунення несправностей

| Симптом                                                 | Причина                                     | Виправлення                                                                                                      |
| ------------------------------------------------------- | ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| На вкладці Scrape відображається «endpoint недоступний» | `/v1/web/fetch` не підключено               | Переконайтеся, що план 05 об’єднано; перевірте наявність `src/app/api/v1/web/fetch/route.ts`                     |
| У каталозі провайдерів усі позначені як «відсутні»      | Облікові дані не налаштовано                | Додайте облікові дані в `/dashboard/providers`                                                                   |
| Вміст Scrape обрізано                                   | Розмір відповіді перевищує обмеження 256 КБ | Очікувана поведінка (D21). Скористайтеся кнопкою «переглянути необроблені дані», щоб побачити повний вміст       |
| На вкладці Compare відображаються лише 2 провайдери     | Активне обмеження частоти запитів           | Два або більше провайдерів можуть перебувати в режимі очікування — перевірте статус провайдерів на панелі Config |
| «Size» відображається в таблиці як необроблений ключ    | Відсутній ключ i18n                         | Переконайтеся, що `search.size` існує у файлі локалі; перебудуйте i18n                                           |
