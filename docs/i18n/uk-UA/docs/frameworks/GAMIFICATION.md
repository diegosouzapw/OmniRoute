> **Джерело істини:** `src/lib/gamification/`, `src/lib/db/gamification.ts`, `src/app/api/gamification/`
> **Останнє оновлення:** 2026-06-28 — v3.8.40

OmniRoute містить локальний шар гейміфікації, який винагороджує користувачів за
взаємодію з платформою — виконання запитів, перемикання провайдерів, створення
комбінацій, обмін токенами та внесок у спільноту. Увесь стан зберігається в
SQLite; федерація із серверами спільноти є добровільною та здійснюється через надсилання даних.

Систему спроєктовано для **нульової затримки на критичному шляху** — події гейміфікації
надсилаються з конвеєра запитів за принципом «надіслати й не чекати» та ніколи не блокують
відповідь LLM.

---

## Огляд

### Призначення

Підвищення залученості й утримання користувачів завдяки відображенню прогресу (XP,
рівні, значки), соціальному підтвердженню (таблиці лідерів) та економічним стимулам (обмін
токенами, винагороди за запрошення).

### Обсяг

| Функція                 | Опис                                                                                   |
| ----------------------- | -------------------------------------------------------------------------------------- |
| XP і рівні              | Нарахування XP за кожну дію; підвищення рівня за поліноміальною кривою                 |
| Значки                  | Понад 20 досягнень у 5 категоріях із 4 рівнями рідкісності                             |
| Серії                   | Відстеження щоденної активності з поточною та найдовшою серією                         |
| Таблиці лідерів         | Глобальні, щотижневі, щомісячні рейтинги, а також рейтинги обміну токенами й внесків   |
| Обмін токенами          | Передавання кредитів між користувачами через реєстр подвійного запису                  |
| Запрошення та активація | Реферальні коди зі зберіганням хешів SHA-256                                           |
| Сервери спільноти       | Федерація із зовнішніми екземплярами OmniRoute                                         |
| Захист від шахрайства   | Серверне нарахування балів, обмеження частоти запитів, виявлення аномалій за z-оцінкою |

### Принципи проєктування

1. **Орієнтація на локальну роботу** — увесь стан зберігається в SQLite, зовнішні служби не потрібні.
2. **Неблокувальна робота** — події надсилаються за принципом «надіслати й не чекати»; шлях відповіді LLM
   ніколи не затримується логікою гейміфікації.
3. **Сервер як авторитетне джерело** — XP обчислюється лише на сервері; клієнти не можуть
   штучно завищувати бали.
4. **Повага до приватності** — участь у таблиці лідерів є добровільною; користувачі можуть
   приховати свій профіль.
5. **Готовність до федерації** — сервери спільноти можуть надсилати бали через підписаний API;
   синхронізація перезаписує значення, а не додає їх.

## Архітектура

### Високорівневий потік

```
Запит клієнта
  → /v1/chat/completions
    → handleChatCore()                      [open-sse/handlers/chatCore.ts]
      → ... (наявний конвеєр) ...
      → відповідь сервера надсилається клієнту
      → setImmediate (надіслати й не чекати):
        → emitGamificationEvent()           [src/lib/gamification/events.ts]
          → awardXp()                       [src/lib/gamification/xp.ts]
          → updateStreak()                  [src/lib/gamification/streaks.ts]
          → evaluateBadges()                [src/lib/gamification/badges.ts]
          → updateLeaderboard()             [src/lib/gamification/leaderboard.ts]
          → checkAnomalies()                [src/lib/gamification/antiCheat.ts]
```

Емітер подій є єдиною точкою інтеграції. `chatCore.ts` викликає
`emitGamificationEvent()` після надсилання відповіді; модуль подій розподіляє
її між підсистемами XP, серій, значків, таблиці лідерів і захисту від шахрайства.

### Граф залежностей модулів


## Система XP / рівнів

**Файл:** `src/lib/gamification/xp.ts`

### Крива рівнів

Кількість XP, необхідна для досягнення рівня `n`, визначається поліноміальною кривою:

```
xp_for_level(n) = floor(100 * n^1.5)
```

| Рівень | XP до наступного рівня | Сумарний XP | Звання      |
| ------ | ---------------------- | ----------- | ----------- |
| 1      | 100                    | 100         | Початківець |
| 5      | 1,118                  | 2,415       | Початківець |
| 10     | 3,162                  | 10,523      | Дослідник   |
| 25     | 12,500                 | 86,024      | Дослідник   |
| 50     | 35,355                 | 345,529     | Експерт     |
| 75     | 64,952                 | 948,683     | Майстер     |
| 100    | 100,000                | 2,050,000   | Легенда     |

### Звання

| Діапазон рівнів | Звання      |
| --------------- | ----------- |
| 1 – 9           | Початківець |
| 10 – 24         | Дослідник   |
| 25 – 49         | Експерт     |
| 50 – 74         | Майстер     |
| 75 – 100        | Легенда     |

### Винагороди XP

| Дія               | XP  | Опис                                                            |
| ----------------- | --- | --------------------------------------------------------------- |
| `request`         | 1   | За кожен API-запит, маршрутизований через OmniRoute             |
| `provider_switch` | 5   | Перемикання на іншого провайдера                                |
| `model_switch`    | 3   | Перемикання на іншу модель                                      |
| `combo_create`    | 10  | Створення нової комбінації                                      |
| `combo_use`       | 2   | Використання комбінації для запиту                              |
| `token_share`     | 1   | За кожні 1 000 токенів, якими поділилися з іншим користувачем   |
| `invite_redeem`   | 50  | Активація коду запрошення                                       |
| `daily_login`     | 5   | Щоденне активне використання (один раз на день)                 |
| `streak_bonus`    | 2   | За кожен послідовний день серії (множиться на тривалість серії) |
| `badge_unlock`    | 10  | Розблокування значка                                            |

### Процес нарахування

```typescript
export async function awardXp(
  apiKeyId: string,
  action: XpAction,
  metadata?: Record<string, unknown>
): Promise<{ xp: number; level: number; title: string; levelUp: boolean }>;
```

1. Знайти `XP_REWARDS[action]`, щоб отримати кількість XP.
2. Передати через `checkRateLimit()` (захист від шахрайства: максимум 1000 XP/хв на ключ).
3. Відкрити транзакцію:
   - Прочитати поточний рядок `user_levels`.
   - Додати XP; повторно обчислити рівень за допомогою `levelFromXp(totalXp)`.
   - Якщо рівень змінився, установити `levelUp = true`.
   - Оновити рядок `user_levels`.
   - Додати запис до `xp_audit_log`.
4. Повернути результат. Викликач обробляє сповіщення.

### Допоміжна функція: `levelFromXp(totalXp)`

Перебирає рівні 1..100, підсумовуючи `xp_for_level(n)`, доки сумарний XP
не перевищить `totalXp`. Повертає найвищий рівень, поріг якого досягнуто.
Складність становить O(100) — це прийнятно, оскільки максимальний рівень дорівнює 100.

## Система значків

**Файл:** `src/lib/gamification/badges.ts`

### Категорії

| Категорія      | Опис                                   | Приклади значків                          |
| -------------- | -------------------------------------- | ----------------------------------------- |
| `usage`        | Досягнення на основі обсягу            | Перший запит, 1 тис. запитів, 100 тис.    |
| `sharing`      | Обмін токенами та рекомендації         | Перший обмін, Щедрий (10 обмінів)         |

| `streak`       | Послідовність упродовж часу            | Тижневий воїн, Відданий протягом місяця   |
| `rare`         | Важкодоступні або приховані досягнення | Першопроходець, Автор звіту про помилку   |

### Рідкісність

| Рідкісність | Колір   | Орієнтовна ймовірність |
| ----------- | ------- | ---------------------- |
| `common`    | Сірий   | Більшість користувачів |
| `uncommon`  | Зелений | Активні користувачі    |
| `rare`      | Синій   | Віддані користувачі    |
| `legendary` | Золотий | Найкращий 1%           |

### Типи критеріїв

| Тип            | Поле                   | Опис                                                            |
| -------------- | ---------------------- | --------------------------------------------------------------- |
| `action_count` | `count`                | Виконати дію N разів (наприклад, 1000 запитів)                  |
| `streak`       | `days`                 | Підтримувати серію протягом N послідовних днів                  |
| `unique_count` | `field`, `n`           | Використати N унікальних значень (наприклад, 10 різних моделей) |
| `rank`         | `scope`, `n`           | Досягти позиції N у певній таблиці лідерів                      |
| `first`        | —                      | Першим виконати дію                                             |
| `hidden`       | (залежить від випадку) | Критерії не відображаються до отримання значка                  |

Визначення значків зберігаються в `badge_definitions` як JSON `criteria`:

```json
{
  "type": "action_count",
  "action": "request",
  "count": 1000
}
```

### Процес оцінювання

```
emitGamificationEvent(event)
  → evaluateBadges(apiKeyId, event)
    → getBadgeDefinitions()           # усі визначення
    → getUserBadges(apiKeyId)         # уже отримані (пропустити)
    → для кожного неотриманого значка:
       → matchesCriteria(badge, event, userState)
       → якщо є збіг: awardBadge(apiKeyId, badgeId)
         → повернути дані сповіщення
```

Оцінювання є **подієво-орієнтованим** — воно виконується після кожної події гейміфікації, але
перевіряє лише ті значки, значення `criteria.type` яких відповідає дії події. Це
забезпечує швидке оцінювання (< 5 мс для більшості подій).

### `matchesCriteria(badge, event, userState)`

| Тип критерію   | Перевірка                                                   |
| -------------- | ----------------------------------------------------------- |
| `action_count` | `getActionCount(apiKeyId, action) >= count`                 |

| `unique_count` | `getUniqueCount(apiKeyId, field) >= n`                      |
| `rank`         | `getRank(apiKeyId, scope) <= n`                             |
| `first`        | Немає попереднього запису `xp_audit_log` для цього типу дії |
| `hidden`       | Делегує відповідній підперевірці                            |

## Відстеження серій

**Файл:** `src/lib/gamification/streaks.ts`

### Модель даних

Серії зберігаються в таблиці `key_value` (спільній службовій таблиці) під
ключами з простором імен:

| Ключ                          | Значення                         | Опис                |
| ----------------------------- | -------------------------------- | ------------------- |
| `gamification:streak:{keyId}` | `{current},{longest},{lastDate}` | Дані активної серії |

### Логіка

```typescript
export async function updateStreak(
  apiKeyId: string
): Promise<{ current: number; longest: number; milestone: boolean }>;
```

1. Прочитати запис серії з `key_value`.
2. Розібрати `{current}`, `{longest}`, `{lastDate}` (рядок дати ISO).
3. Якщо `lastDate === today` — без змін (сьогодні вже враховано).
4. Якщо `lastDate === yesterday` — збільшити `current`; за потреби оновити `longest`.
5. Якщо `lastDate < yesterday` — скинути `current = 1` (серію перервано).
6. Записати оновлений запис.
7. Перевірити етапи: 7, 14, 30, 60, 90, 180, 365 днів. Якщо етап досягнуто,
   установити `milestone = true` (викликач нараховує XP і перевіряє відзнаки).

### Граничні випадки

- **Часовий пояс**: для серій використовуються дати UTC (`new Date().toISOString().slice(0, 10)`).
  Це зроблено навмисно — єдиний канонічний часовий пояс запобігає маніпуляціям
  через зміну часових поясів.
- **Нові користувачі**: запису серії ще немає; перший запит створює його зі
  значеннями `current=1, longest=1, lastDate=today`.
- **Кілька запитів на день**: лише перший запит за день UTC
  збільшує серію.

## Таблиця лідерів

**Файл:** `src/lib/gamification/leaderboard.ts`

### Області

| Область         | Період  | Опис                                                   |
| --------------- | ------- | ------------------------------------------------------ |
| `global`        | `all`   | Сукупна кількість XP за весь час                       |
| `weekly`        | `week`  | XP, зароблені в поточному тижні UTC (пн–нд)            |
| `monthly`       | `month` | XP, зароблені в поточному місяці UTC                   |
| `tokens_shared` | `all`   | Загальна кількість токенів, переданих іншим            |
| `contributions` | `all`   | Створені комбінації + використані провайдери + навички |

### Обчислення позицій

Позиції **обчислюються під час читання**, а не зберігаються. Це дає змогу
уникнути застарілих даних про позиції та усуває потребу в періодичних завданнях
їх перерахунку.

```typescript
export async function getLeaderboard(
  scope: LeaderboardScope,
  period: string,
  limit: number,
  offset: number
): Promise<{ entries: LeaderboardEntry[]; total: number }>;
```

Шаблон запиту:

```sql
SELECT api_key_id, score,
       RANK() OVER (ORDER BY score DESC) as rank
FROM leaderboard
WHERE scope = ? AND period = ?
ORDER BY score DESC
LIMIT ? OFFSET ?
```

### Ротація періодів

Щотижневі та щомісячні таблиці лідерів оновлюються автоматично:

1. **Архівування**: на межі періоду скопіювати поточні записи до
   `leaderboard_archive` із міткою періоду.
2. **Скидання**: видалити записи за завершений період.
3. **Запуск**: перевірка виконується під час кожного виклику `updateLeaderboard()`; перший запит
   нового періоду запускає ротацію.

Це забезпечує скидання щотижневих таблиць щопонеділка о 00:00 UTC, а щомісячних —
першого числа кожного місяця.

### Оновлення в реальному часі через SSE

**Кінцева точка:** `GET /api/gamification/stream`

```
Клієнт → GET /api/gamification/stream
  → Установлено SSE-з’єднання
  → Сервер негайно надсилає знімок топ-10 таблиці лідерів
  → Кожні 5 секунд: надсилати оновлений топ-10, якщо він змінився
  → Кожні 15 секунд: коментар-пульс (": heartbeat\n\n")
  → Клієнт від’єднується → очищення (видалення слухача)
```

Формат події:

```
event: leaderboard
data: {"scope":"global","entries":[...]}

event: leaderboard
data: {"scope":"weekly","entries":[...]}

: heartbeat
```

Менеджер SSE відстежує підключених клієнтів для кожної області та надсилає
оновлення лише тоді, коли дані таблиці лідерів фактично змінилися після
останнього надсилання.

## Передавання токенів

**Файл:** `src/lib/gamification/sharing.ts`

### Бухгалтерський облік подвійним записом

Кожне передавання створює два рядки в `token_ledger`:

| Рядок  | `from_key_id` | `to_key_id` | `amount` |
| ------ | ------------- | ----------- | -------- |
| Дебет  | відправник    | отримувач   | +сума    |
| Кредит | отримувач     | відправник  | -сума    |

Зачекайте — використовується така угода:

| Рядок      | `from_key_id` | `to_key_id` | `amount` | Значення                  |
| ---------- | ------------- | ----------- | -------- | ------------------------- |
| Надсилання | відправник    | отримувач   | +сума    | Відтік від відправника    |
| Отримання  | отримувач     | відправник  | +сума    | Надходження до отримувача |

Баланс обчислюється так:

```sql
SELECT
  COALESCE(SUM(CASE WHEN to_key_id = ? THEN amount ELSE 0 END), 0)
  - COALESCE(SUM(CASE WHEN from_key_id = ? THEN amount ELSE 0 END), 0)
  AS balance
FROM token_ledger
WHERE from_key_id = ? OR to_key_id = ?
```

### Процес передавання

```typescript
export async function transferTokens(
  fromKeyId: string,
  toKeyId: string,
  amount: number,
  idempotencyKey: string
): Promise<{ success: boolean; balance: number }>;
```

1. **Перевірка**: `amount > 0`, `fromKeyId !== toKeyId`.
2. **Ідемпотентність**: перевірити, чи `idempotency_key` уже існує в реєстрі.
   Якщо так, повернути кешований результат.
3. **Транзакція** (одна транзакція SQLite):
   a. Обчислити баланс відправника.
   b. Якщо `balance < amount`, перервати операцію (недостатньо коштів).
   c. Вставити рядок надсилання (`from=sender,`.

### Обмеження частоти

- Щонайбільше 10 передавань на хвилину для кожного ключа API.
- Щонайбільше 10 000 токенів за одне передавання.
- Щонайбільше 100 000 токенів, переданих за день для кожного ключа API.

## Токени запрошення та активації

**Файл:** `src/lib/gamification/invites.ts`

### Формат коду

- **Код**: 8-символьний буквено-цифровий код (наприклад, `A3K9-X7M2`), зручний для читання,
  який відображається користувачеві.
- **Токен**: 32-байтовий випадковий токен, що зберігається у вигляді хешу SHA-256. Використовується для
  програмної активації (наприклад, через URL-посилання).

### Зберігання

| Стовпець     | Значення                              |
| ------------ | ------------------------------------- |
| `code`       | `A3K9X7M2` (унікальний, індексований) |
| `token_hash` | SHA-256(raw_token)                    |

Необроблений токен повертається користувачеві лише один раз під час створення. OmniRoute
ніколи більше не зберігає та не відображає його — зберігається лише хеш.

### Запобігання самореферальним запрошенням

Коли користувач активує код, система перевіряє:

1. Код належить іншому `api_key_id`.
2. Користувач, який активує код, раніше не активував жодного коду від того самого
   реферера (об’єднання за `invite_tokens` і журналом активацій).

Якщо будь-яка з перевірок не проходить, активація відхиляється з чітким повідомленням про помилку.

### Термін дії та обмеження

- Значення `max_uses` за замовчуванням: 10 (налаштовується під час створення).
- Значення `expires_at` за замовчуванням: 30 днів від моменту створення.
- Для кодів зі сплилим терміном дії або вичерпаним лімітом повертається HTTP 410 Gone.

## Федерація серверів спільноти

**Файл:** `src/lib/gamification/servers.ts`

### Підключення

Сервер спільноти реєструється за допомогою токена-запрошення, виданого віддаленим сервером. Локальний екземпляр:

1. Отримує токен-запрошення (наприклад, вставлений у панель керування).
2. Викликає `POST /api/gamification/federation/leaderboard` на віддаленому сервері, щоб перевірити токен і отримати поточну таблицю лідерів.
3. Зберігає запис сервера зі `status: connected`.

### Модель синхронізації

Федерація використовує **синхронізацію з перезаписом**, а не з додаванням:

```
Локальний екземпляр              Сервер спільноти
     │                                  │
     ├── надсилання балів ─────────────►│  POST /federation/score
     │   { api_key_id, score }          │  (сервер перевіряє хеш токена)
     │                                  │
     ├── отримання таблиці лідерів ────►│  GET /federation/leaderboard
     │◄── перші N записів ──────────────┤  (перезаписує локальний кеш)
     │                                  │
     └── перевірка стану ──────────────►│  GET /federation/health
         (кожні 60 с, тайм-аут 5 с)     │
```

### Автентифікація

Запити федерації містять:

```
Authorization: Bearer <raw_token>
X-Federation-Version: 1
```

Віддалений сервер хешує токен і шукає відповідний рядок у `community_servers`. Це дає змогу уникнути передавання збереженого хешу.

### Моніторинг стану

Кожен запис сервера відстежує:

| Поле        | Опис                                               |
| ----------- | -------------------------------------------------- |
| `status`    | `connected`, `degraded`, `unreachable`             |
| `last_sync` | Позначка часу ISO останньої успішної синхронізації |
| `failures`  | Послідовні невдалі перевірки стану                 |

Після 5 послідовних невдалих спроб статус змінюється на `unreachable`, а синхронізація призупиняється, доки ручна перевірка стану не завершиться успішно.

## Захист від шахрайства

**Файл:** `src/lib/gamification/antiCheat.ts`

### Обчислення балів на сервері

Усі обчислення XP виконуються у `src/lib/gamification/xp.ts`. Клієнти ніколи не надсилають бали — вони надсилають дії, а сервер обчислює XP. Стовпець `leaderboard.score` може змінюватися лише серверним кодом.

### Обмеження частоти запитів

| Обмеження                  | Значення | Область дії     |
| -------------------------- | -------- | --------------- |
| Максимум XP за хвилину     | 1,000    | На ключ API     |
| Максимум переказів за хв   | 10       | На ключ API     |
| Максимальна сума переказу  | 10,000   | На один переказ |
| Максимум переказів за день | 100,000  | На ключ API     |

Для обмежень частоти використовується ковзне вікно в пам’яті (за тим самим шаблоном, що й `RateLimitManager` у `open-sse/services/`). Якщо процес перезапускається, система використовує резервні лічильники на базі SQLite.

### Виявлення аномалій за Z-оцінкою

Для кожного ключа API система підтримує рухоме 7-денне вікно кількості XP, отриманого за годину. Під час кожного нарахування XP:

1. Обчислюється поточна погодинна швидкість отримання XP користувачем.
2. Обчислюються середнє значення та стандартне відхилення для сукупності.
3. Обчислюється `z = (user_rate - mean) / stddev`.
4. Якщо `z > 3.0` (3 стандартні відхилення), подія позначається як аномалія.

Аномалії записуються до `xp_audit_log` з `action = 'anomaly_detected'` і відображаються в панелі адміністратора.

### Журнал аудиту

Кожне нарахування XP, переказ, отримання значка та виявлення аномалії записується до `xp_audit_log` із такими даними:

| Поле         | Опис                                         |
| ------------ | -------------------------------------------- |
| `api_key_id` | Хто                                          |
| `action`     | Що сталося (xp_award, transfer, anomaly, …)  |
| `xp_awarded` | Кількість (0 для подій, не пов’язаних із XP) |
| `metadata`   | JSON із контекстом (тип дії, ціль, …)        |
| `created_at` | Коли (ISO 8601)                              |

Адміністратори можуть запитувати повний журнал аудиту через `GET /api/gamification/anomalies`.

## Сторінки панелі керування

### `/dashboard/leaderboard`

- Відображення п’єдесталу (3 найкращі учасники з аватарами та XP).
- Вибір області: глобальна / щотижнева / щомісячна / поширені токени / внески.
- Таблиця з пагінацією (25 записів на сторінку), що містить рейтинг, ім’я, результат, рівень і звання.
- Оновлення в реальному часі через SSE — зміни рейтингу анімуються.
- Поточного користувача виділено в таблиці за допомогою закріпленого рядка «Ваш рейтинг».

### `/dashboard/profile`

- Індикатор прогресу XP із поточним рівнем і порогом наступного рівня.
- Значок звання відображається на видному місці.
- Галерея значків — отримані значки з датою отримання, а неотримані значки відображаються сірими
  (для прихованих значків відображається «???», доки їх не буде отримано).
- Лічильник серії з піктограмою полум’я; календар серії (останні 30 днів).
- Графік історії XP (щоденний XP за останні 30 днів).

### `/dashboard/tokens`

- Баланс токенів (на видному місці у верхній частині сторінки).
- Форма переказу: одержувач, сума, діалогове вікно підтвердження.
- Таблиця історії переказів із фільтрами (надіслані/отримані/усі).
- Розділ запрошень: активні коди, створення нових, посилання для поширення.
- Сервери спільноти: список зі станом працездатності, підключення/відключення.

### `/dashboard/gamification/admin`

- Список аномалій із рівнем серйозності, користувачем, часовою позначкою та z-оцінкою.
- Засіб перегляду журналу аудиту з фільтрами (тип дії, користувач, діапазон дат).
- Системна статистика: загальна кількість нарахованого XP, активні користувачі, частота отримання значків.
- Огляд стану федеративних серверів.

## Інтеграція з конвеєром

### Точка інтеграції

Гейміфікація підключається до конвеєра обробки запитів в одній точці у
`open-sse/handlers/chatCore.ts`:

```typescript
// Після надсилання відповіді клієнту:
setImmediate(() => {
  emitGamificationEvent({
    type: "request.completed",
    apiKeyId,
    metadata: {
      provider: selectedProvider,
      model: selectedModel,
      comboId: resolvedCombo?.id,
      compressionUsed: compressionStats?.applied,
      skillUsed: skillExecution?.name,
    },
  }).catch(() => {
    // Запуск без очікування: записати в журнал, але ніколи не передавати клієнту
  });
});
```

### Типи подій

| Тип події           | Коли надсилається                                                 |
| ------------------- | ----------------------------------------------------------------- |
| `request.completed` | Успішну відповідь LLM надіслано                                   |
| `provider.switch`   | Постачальника змінено (враховуються резервні переходи комбінації) |
| `combo.created`     | Нову конфігурацію комбінації збережено                            |
| `combo.used`        | Ціль комбінації успішно досягнуто                                 |
| `badge.earned`      | Під час оцінювання значків знайдено відповідність                 |
| `streak.milestone`  | Порогове значення серії подолано                                  |
| `transfer.sent`     | Переказ токенів завершено                                         |
| `referral.redeemed` | Код запрошення успішно використано                                |
| `compression.used`  | Застосовано стиснення запиту                                      |
| `skill.executed`    | Виконання навички завершено                                       |
| `model.first_use`   | Модель не використовувалася протягом останніх 7 днів              |

### Гарантія неблокувальної роботи

Шаблон `setImmediate` + `.catch(() => {})` забезпечує:

1. Відповідь повністю надсилається до запуску гейміфікації.
2. Помилки гейміфікації ніколи не передаються клієнту.
3. Обробка події виконується в наступному мікрозавданні, а не безпосередньо.

### Модель загроз

| Загроза                        | Захист                                                                 |
| ------------------------------ | ---------------------------------------------------------------------- |
| Штучне завищення балів         | Обчислення XP лише на сервері; клієнти надсилають дії, а не бали       |
| Атаки повторного відтворення   | Ключі ідемпотентності для переказів; дедуплікація журналу аудиту       |
| Шахрайство з переказами        | Подвійний бухгалтерський запис; атомарні транзакції; обмеження частоти |
| Самореферал                    | Перехресна перевірка `api_key_id` під час активації                    |
| Маніпуляції з таблицею лідерів | Виявлення аномалій за Z-оцінкою; панель аномалій для адміністратора    |
| Крадіжка токена федерації      | Зберігання хешу SHA-256; необроблений токен показується лише один раз  |
| Перебір кодів запрошень        | Обмеження частоти на кінцевій точці активації; ентропія 8 символів     |
| XSS у відображуваних іменах    | Відображувані імена очищуються; записи таблиці лідерів екрануються     |
| Атаки за часом на хеші         | `crypto.timingSafeEqual` для порівняння хешів токенів                  |

### Вимоги до автентифікації

- **Публічний доступ** (без автентифікації): `GET /leaderboard`, `GET /stream` (таблиці
  лідерів лише для читання).
- **Потрібен ключ API**: усі операції запису, профіль, перекази, запрошення.
- **Лише для адміністратора**: панель аномалій, засіб перегляду журналу аудиту.
- **Федерація**: окремий шлях автентифікації з використанням необробленого токена в
  заголовку `Authorization`, який перевіряється за збереженим хешем SHA-256.

## Майбутні можливості

- **Сезонні події**: набори значків із обмеженим терміном дії та сезони таблиці лідерів.
- **Командні таблиці лідерів**: групування користувачів за організацією або комбінацією.
- **Множники XP**: збільшення XP під час рекламних періодів.
- **Поширення досягнень**: створення карток зі значками, якими можна ділитися (зображення OpenGraph).
- **Мобільні push-сповіщення**: сповіщення на основі вебхуків про отримання значків або досягнення нових рівнів.
- **API таблиці лідерів**: публічний API для інтеграцій зі сторонніми сервісами.
