OmniRoute розділяє **виявлення CLI**, **нативний Agent Client Protocol** і
**застарілі адаптери stdio**. Виявлення встановленого виконуваного файлу не підтверджує
його автентифікацію, сумісність із моделлю чи готовність обробляти запит.

Панель керування використовує `GET /api/acp/agents` і `POST /api/acp/agents` для інвентаризації
та реєстрації користувацьких агентів. Це локальні маршрути керування, а не
публічний API для запуску процесів або надсилання запитів. Внутрішній
`AcpManager` не стає автоматично резервним HTTP-провайдером.

## Зареєстровані контракти

`config/cli-tools-manifest.json` є джерелом істини для вбудованих виконуваних
файлів запуску, аргументів і режимів бекенду. Реєстр отримує свої визначення
з цього маніфесту. Результати виявлення кешуються на 60 секунд.

- `acp`: контракт Gemini запускає `gemini --experimental-acp` і обмінюється
  ACP JSON-RPC із розділенням новими рядками через офіційний TypeScript SDK.
- `stdio-adapter`: інші зареєстровані контракти зберігають застарілий адаптер
  із введенням, розділеним новими рядками, та виведенням у stdout. Двосекундний
  період бездіяльності виведення завершує його відповідь. Цей адаптер **не**
  підтверджує підтримку нативного ACP цими CLI.

Gemini документує прапорець запуску у своєму [довіднику CLI](https://geminicli.com/docs/cli/cli-reference/).
Клієнт використовує [офіційний ACP SDK](https://github.com/agentclientprotocol/typescript-sdk)
для ініціалізації, створення сесій, надсилання запитів, сповіщень і скасування.

Визначення користувацьких агентів залишаються контрактами запуску, якими керує
адміністратор. Реєстрація виконуваного файлу й аргументів надає цьому процесу
локальні привілеї виконання користувача сервера; реєстрація не є пісочницею.
Перевірки версії приймають лише зареєстрований виконуваний файл і розпізнаний
прапорець версії.

## Внутрішній API запуску

```typescript
import { acpManager } from "@/lib/acp";

const session = acpManager.spawn("gemini", {
  cwd: process.cwd(),
  // Передавайте лише змінні провайдера, навмисно призначені цьому агенту.
  env: {
    GEMINI_API_KEY: process.env.GEMINI_API_KEY,
  },
});

try {
  const response = await acpManager.sendPrompt(session.id, "Explain this project", 120_000);
  // Обробіть відповідь у застосунку, що викликає цей код.
} finally {
  acpManager.kill(session.id);
}
```

`spawn(agentId, options)` визначає виконуваний файл і аргументи із
зареєстрованого визначення. Єдиними параметрами виклику є `cwd` та `env`;
стара сигнатура `spawn(agentId, binary, args, env)` і перевизначення виконуваного
файлу відхиляються. Цей менеджер не підтримує контракти запуску через HTTP.

Дочірній процес успадковує ту саму операційну систему, термінал, локаль і список
дозволених сертифікатів, що й засоби запуску CLI. Секрети сервера чи провайдера
не копіюються з батьківського середовища. Облікові дані, потрібні вибраному CLI,
мають бути передані явно або надані через власну локальну автентифікацію цього
CLI. Дочірній процес усе одно має дозволи локального користувача на файлову
систему й може читати власну конфігурацію.

## Нативний життєвий цикл та обмеження

1. Запустіть зареєстрований виконуваний файл, ініціалізуйте ACP і створіть сесію,
   коренем якої є вибраний робочий каталог. Ініціалізація має обмеження в десять секунд.
2. Надішліть запит і збирайте текстові сповіщення лише для цієї сесії.
   Завершенням є відповідь RPC на запит, а не період тиші в stdout.
3. Використовуйте один кінцевий термін для запиту, включно з будь-якою незавершеною
   ініціалізацією; типове значення становить 120 секунд. Одночасні запити в тому
   самому процесі відхиляються.
4. У разі нативного тайм-ауту спробуйте виконати `session/cancel` і завершіть процес.
   Обмежене вікно тривалістю 100 мс дає змогу відправити сповіщення перед завершенням.
5. Закрийте стан транспорту та видаліть сесію, коли ініціалізація зазнає невдачі,
   з'єднання закривається, процес завершується або викликач зупиняє його.

Запити на дозвіл використання інструментів відхиляються. Можливості клієнта
файлової системи чи термінала не оголошуються. Ці обмеження не ізолюють сам
дочірній виконуваний файл у пісочниці й не замінюють власні налаштування
авторизації CLI.

Як нативний текст, так і застарілі stdout/stderr зберігають щонайбільше 1 MiB
символів, залишаючи найновіші дані виведення з повідомленням про усічення.
Окремий нативний кадр передавання обмежено 2 MiB байтів до синтаксичного аналізу
SDK. Буфери скидаються для кожного запиту.

`kill(sessionId)` надсилає SIGTERM, а потім SIGKILL через п'ять секунд, якщо процес
не завершився. Тайм-аути застарілих запитів звільняють слухачі й таймери, але
залишають сесію доступною для іншого запиту; після завершення викликачі й надалі
відповідають за виклик `kill()` або `killAll()`.

## Події та перевірка стану

Менеджер генерує події `stdout`, `stderr` і `exit`, кожна з яких містить `sessionId`.
`sessionError` повідомляє про очищену від чутливих даних помилку транспорту. Подія
сумісності `error` генерується лише тоді, коли має підписника, тому відсутній
виконуваний файл не може спричинити необроблену помилку EventEmitter.

- `getSession(sessionId)` повертає керовану сесію або `undefined`.
- `getActiveSessions()` виключає зупинені сесії та сесії, що зупиняються.
- `sendInput(sessionId, input)` доступний лише для активного застарілого адаптера;
  нативний ACP відхиляє необроблене введення, щоб захистити свій потік JSON-RPC.
- `killAll()` завершує всі сесії, якими керує цей екземпляр.

## Межі перевірки

Детерміновані фікстури охоплюють нативне встановлення зв'язку, текстове виведення,
відмови в дозволах, скасування, одночасні запити, невдалу ініціалізацію, завершення
процесу, обмеження виведення та ізоляцію секретів. Наявні регресійні сценарії
застарілих буферів і слухачів також залишаються покритими. Ці тести не підтверджують
активний вхід у Gemini або успішне виконання інференсу провайдера; для цього
потрібен окремо авторизований димовий тест у цільовому середовищі.
