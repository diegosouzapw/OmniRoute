> **Джерело:** `src/lib/{a2a,acp,cloudAgent}/`, `src/app/api/{a2a,acp,cloud}/`, `src/app/api/v1/agents/`
> **Останнє оновлення:** 2026-06-28 — v3.8.40

OmniRoute надає три різні інтерфейси, пов’язані з агентами. На перший погляд вони схожі, але розв’язують різні завдання. Скористайтеся цією сторінкою, щоб вибрати відповідний інтерфейс.

## Коротко

| Інтерфейс                    | Найкраще підходить для                                                                                                                                     | Транспорт                 | Стандарт                         |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- | -------------------------------- |
| **A2A — агент-агент**        | Взаємодії між агентами з одноранговими агентами, які підтримують протокол A2A                                                                              | JSON-RPC 2.0 через HTTP   | A2A v0.3 (відкрита специфікація) |
| **ACP — реєстр CLI-агентів** | Виявлення, реєстрації та запуску CLI-агентів для програмування, установлених на комп’ютері користувача (Cursor, Cline, Codex CLI, Claude Code, Aider тощо) | HTTP REST                 | Специфічний для OmniRoute        |
| **Хмарні агенти**            | Надсилання довготривалих завдань із програмування зовнішнім хмарним сервісам (Codex Cloud, Devin, Jules, Cursor Cloud)                                     | HTTP REST + завдання в БД | Специфічний для OmniRoute        |

Усі три інтерфейси незалежні — виберіть будь-яку їх підмножину.

## Дерево рішень

```
Вам потрібен хмарний сервіс для виконання роботи поза цим комп’ютером (Codex Cloud / Cursor Cloud / Devin / Jules)?
├─ ТАК → Хмарні агенти (POST /api/v1/agents/tasks)
└─ НІ → Продовжуйте
    │
    У вас є одноранговий агент, який підтримує A2A та хоче взаємодіяти?
    ├─ ТАК → A2A (POST /a2a)
    └─ НІ → Продовжуйте
        │
        Вам потрібно переглядати або налаштовувати локально встановлені CLI-агенти для програмування?
        ├─ ТАК → ACP (GET /api/acp/agents)
        └─ НІ → Використовуйте звичайний /v1/chat/completions
```

## 1. A2A — агент-агент

**Специфікація:** [A2A v0.3](https://a2a-protocol.org)
**Кінцева точка OmniRoute:** `POST /a2a` (JSON-RPC 2.0)
**Картка агента:** `GET /.well-known/agent.json`

### Коли використовувати

- Створення багатоагентної системи, у якій OmniRoute є одним з однорангових учасників
- Надання агентам у фреймворках на кшталт Google ADK або в універсальних мережах агентів доступу до інтелектуальних можливостей маршрутизації OmniRoute (розумної маршрутизації, керування квотами тощо)
- Розміщення OmniRoute за стандартним інтерфейсом виявлення та виклику

### Методи

- `message/send` — надіслати повідомлення й отримати синхронну відповідь
- `message/stream` — надіслати повідомлення й отримувати потокові події перебігу виконання через SSE
- `tasks/get` — прочитати завдання за ID
- `tasks/cancel` — скасувати виконуване завдання

### Вбудовані навички (6)

- `smart-routing` — спрямувати запит через оптимальну комбінацію
- `quota-management` — повідомити стан квоти для кожного провайдера
- `provider-discovery` — перелічити встановлених провайдерів та їхні можливості
- `cost-analysis` — оцінити вартість запиту або розмови
- `health-report` — агрегувати стан переривника, періоду очікування та блокування для кожного провайдера
- `list-capabilities` — перелічити доступні навички агента та метадані

### Докладніше

Докладну інформацію про транспорт, структуру картки агента, конфігурацію TTL завдань і шаблон для додавання нових навичок див. у [A2A-SERVER.md](./A2A-SERVER.md).

## 2. ACP — реєстр CLI-агентів

**Ендпоінт OmniRoute:** `GET /api/acp/agents`
**Джерело:** `src/lib/acp/{index,manager,registry}.ts`

### Що це таке

ACP — це **локальний реєстр CLI-агентів** OmniRoute. Він визначає, які CLI для програмування встановлено на хості (Cursor, Cline, Claude Code, Codex CLI, Continue тощо), визначає їхні версії та відображає їх на панелі керування, щоб користувач міг налаштувати кожен CLI для роботи через OmniRoute.

Це НЕ зовнішній протокол — це внутрішній реєстр, який забезпечує роботу інтерфейсу «CLI Tools» і відстеження відбитків CLI (див. [CLI-TOOLS.md](../reference/CLI-TOOLS.md)).

### Що він робить

- Перевіряє хост на наявність установлених бінарних файлів CLI (використовує `which` / `where` залежно від ОС)
- Зчитує версію кожного CLI (викликає `<bin> --version`)
- За потреби приймає визначені користувачем власні агенти (шлях до бінарного файлу + команда перевірки версії + аргументи запуску)
- Зберігає власні агенти в налаштуваннях
- Повертає уніфікований список на панель керування

### REST API

| Ендпоінт          | Метод | Опис                                                                  | Автентифікація |
| ----------------- | ----- | --------------------------------------------------------------------- | -------------- |
| `/api/acp/agents` | GET   | Список виявлених + власних агентів (кількість установлених/загальна)  | Ключ API       |
| `/api/acp/agents` | POST  | Додавання/оновлення/видалення власного агента (дія вказується в тілі) | Ключ API       |

Структура тіла для POST (`customAgentBodySchema` у `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Варіанти використання

- Сторінка «CLI Tools» панелі керування показує, що встановлено, і допомагає налаштувати кожен інструмент для роботи через OmniRoute
- Власні агенти дають досвідченим користувачам змогу реєструвати внутрішні/пропрієтарні CLI, про які OmniRoute не знає за замовчуванням
- Результат виявлення наповнює матрицю відбитків `cli-tools`

### Коли НЕ слід використовувати ACP

- ACP не _запускає_ завдання. Він лише виявляє та налаштовує CLI. Щоб фактично викликати CLI, запустіть його самостійно зі змінними середовища, які надає OmniRoute (`OPENAI_BASE_URL`, `OPENAI_API_KEY` тощо).

## 3. Хмарні агенти

**Ендпоінти OmniRoute:** `/api/v1/agents/tasks/*` (життєвий цикл) + `/api/cloud/*` (інфраструктура)
**Джерело:** `src/lib/cloudAgent/`

### Що це таке

Уніфікований інтерфейс для сторонніх хмарних агентів програмування. Ви надсилаєте запит + URL репозиторію, OmniRoute передає їх відповідному хмарному агенту, опитує стан і повертає результати.

### Підтримувані агенти (4, усі підтверджені в `src/lib/cloudAgent/agents/`)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### Життєвий цикл

```
POST /api/v1/agents/tasks
  → BaseAgent.createTask() для кожного класу агента
  → зовнішній сервіс починає роботу
  → у БД створюється запис завдання (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → відкладена синхронізація стану з провайдером
  → повертає поточний стан + план + журнал активності
  ↓
POST /api/v1/agents/tasks/[id]   (дія: "approve" | "message" | "cancel")
  → пересилає провайдеру (або локально позначає як скасоване)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → локальне скасування
```

### Автентифікація

⚠️ **Усі ендпоінти `/api/v1/agents/tasks/*` потребують адміністративної автентифікації** (коміт `588a0333`). Починаючи з v3.8.0, клієнти, які використовують лише Bearer-токен, отримують 401.

### Докладний опис

Див. [CLOUD_AGENT.md](./CLOUD_AGENT.md), щоб дізнатися про контракт `CloudAgentBase`, особливості кожного агента, деталі схеми та ендпоінти інфраструктури облікових даних.

## Порівняння: A2A та хмарні агенти

Обидва підтримують «тривалі завдання», але на різних рівнях:

| Аспект                      | A2A                                                                                                                       | Хмарні агенти                                                |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Стандарт                    | Відкритий A2A v0.3                                                                                                        | Специфічний для OmniRoute                                    |
| Де виконуються обчислення   | Усередині OmniRoute (використовує налаштовані комбінації)                                                                 | Зовні (сервери Codex / Devin / Jules)                        |
| Тривалість завдання         | TTL за замовчуванням — 5 хв (налаштовується в `TaskManager`)                                                              | Від кількох хвилин до кількох годин                          |
| Обізнаність про репозиторій | Ні (передає лише запити)                                                                                                  | Так (URL репозиторію + гілка)                                |
| Варіант використання        | Взаємодія між агентами, інтелектуальна маршрутизація як сервіс                                                            | Делегування завдання «реалізувати функцію X у репозиторії Y» |
| Автентифікація              | Необов’язковий `OMNIROUTE_API_KEY` для `/a2a`; адміністративна автентифікація для допоміжних REST-ендпоінтів `/api/a2a/*` | Завжди адміністративна автентифікація                        |

## Приклади інтеграції

### Виявлення можливостей A2A в OmniRoute

```bash
curl http://localhost:20128/.well-known/agent.json
```

Повертає картку агента з усіма 6 навичками, транспортами та версією.

### Виклик OmniRoute як агента A2A

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### Отримання списку встановлених CLI-агентів через ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Додавання власного CLI-агента

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### Надсилання завдання хмарному агенту

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### Опитування стану хмарного завдання

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## Що й коли використовувати

- **Фронтенд чатбота / копілота** → `/v1/chat/completions` (сумісний з OpenAI — це не протокол агентів)
- **Взаємодія між кількома агентами** → A2A
- **Відображення локальних CLI у панелі керування** → ACP
- **Делегування тривалих завдань із програмування хмарним сервісам** → хмарні агенти
