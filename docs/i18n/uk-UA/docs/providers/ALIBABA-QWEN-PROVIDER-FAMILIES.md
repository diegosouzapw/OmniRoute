Цей документ фіксує рішення щодо реалізації для
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854). Публічні продукти
представлено як чотири сімейства провайдерів. Регіон — це дані підключення, а не окремий продукт.

## Рішення

| Сімейство провайдерів                                      | ID OmniRoute            | Глобальний регіон | Регіон Китаю |
| ---------------------------------------------------------- | ----------------------- | ----------------- | ------------ |
| Alibaba Cloud Model Studio (оплата за фактом використання) | `alibaba`               | Сінгапур          | Пекін        |
| Alibaba Cloud Token Plan                                   | `bailian-coding-plan`   | Сінгапур          | Пекін        |
| Qwen Cloud (оплата за фактом використання)                 | `qwen-cloud`            | Глобальний        | Пекін        |
| Qwen Cloud Token Plan                                      | `qwen-cloud-token-plan` | Сінгапур          | Пекін        |

Наявний ID `alibaba-cn` залишається псевдонімом для сумісності під час виконання для збережених підключень, маршрутів
моделей, комбінацій та історичних даних про використання. Його картку на панелі керування об’єднано з `alibaba`; переписування
бази даних не потрібне.

Qwen Cloud з оплатою за фактом використання та Alibaba Cloud Model Studio наразі спільно використовують сумісні з DashScope
хости середовища виконання, але залишаються окремими ідентичностями провайдерів, оскільки користувачі отримують ключі та керують
обліковими записами через різні інтерфейси продуктів. Продукти Alibaba та Qwen Cloud Token Plan використовують
різні сімейства кінцевих точок, тому всі чотири продукти залишаються окремими ID провайдерів.

## Матриця кінцевих точок

| Сімейство провайдерів   | `global-sg`                                                              | `china-beijing`                                                      | Формат обміну |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ------------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI        |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic     |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI        |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI        |

Ключ API та кінцева точка мають належати до того самого продукту й регіону. Вибір регіону змінює
попередньо налаштовану кінцеву точку, яку використовують для валідації та звичайних запитів.

## Контракт підключення

Нові підключення зберігають стабільний ключ регіону в `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

Допустимими значеннями є `global-sg` і `china-beijing`. Кінцева точка визначається централізовано на основі
ID провайдера та регіону. Значення `providerSpecificData.baseUrl`, яке не відповідає попередньо налаштованій кінцевій точці, залишається явним
перевизначенням оператора й має пріоритет, тоді як старі збережені URL-адреси попередньо налаштованих кінцевих точок нормалізуються відповідно до регіональної
матриці.

Це забезпечує розширюваність схеми підключення: до засобу визначення можна додати інший регіон без
створення ще однієї картки провайдера або зміни збережених ID провайдерів.

## Сумісність і розгортання

1. Додайте засіб визначення регіональної кінцевої точки та збережіть поточні глобальні значення за замовчуванням.
2. Використовуйте актуальне регіональне виявлення DashScope `/models` для `alibaba`, його ідентифікатора сумісності `alibaba-cn` та `qwen-cloud`. Їхні відповіді спочатку проходять один фільтр моделей генерації тексту, оскільки універсальна кінцева точка також повертає моделі зображень, відео, аудіо, векторних представлень та інші моделі, не призначені для чатів. Потім `qwen-cloud` застосовує підтримуваний список дозволених моделей, оголошений у його реєстрі провайдера. Alibaba Model Studio та Qwen Cloud зберігають окремі кураторські каталоги, хоча наразі використовують спільні хости середовища виконання.
3. Зареєструйте `qwen-cloud-token-plan` із поточним списком дозволених текстових моделей Token Plan.
4. Додайте типізований селектор регіону до діалогових вікон додавання та редагування підключень.
5. Приховайте дубльовану картку `alibaba-cn` і додайте її наявні підключення на сторінку провайдера `alibaba`.
6. Залиште перевизначення користувацьких кінцевих точок доступними для розширених розгортань і розгортань, специфічних для робочого простору.

Мультимедійні моделі Token Plan залишаються поза каталогом чатів, оскільки використовують спеціалізовані кінцеві точки.
`wan2.7-image` і `wan2.7-image-pro` зареєстровані в `open-sse/config/imageRegistry.ts`;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` і `happyhorse-1.1-r2v` зареєстровані в
`open-sse/config/videoRegistry.ts`. Обидва реєстри повторно використовують ідентичність підключення `qwen-cloud-token-plan`
та її регіональні облікові дані.

Звичайний Qwen Cloud має окремі каталоги зображень і відео з оплатою за використання в межах ідентичності `qwen-cloud`.
Його моделі зображень: `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` і `z-image-turbo`. Його моделі
відео: `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` і
`wan2.7-videoedit`. Ці моделі повторно використовують лише звичайне підключення `qwen-cloud` і регіональну
мультимедійну кінцеву точку DashScope. Реєстри Token Plan і тарифікації за використання не успадковують і не об’єднують
списки моделей один одного.

Ідентичність `bailian-coding-plan` також має власні списки дозволених мультимедійних моделей:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` і `qwen-image-2.0-pro` для генерації
зображень, а також
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` і `happyhorse-1.1-r2v` для генерації
відео. Вона використовує лише підключення Bailian Coding Plan і регіональну кінцеву точку Coding Plan.
Її реєстри зображень і відео не успадковуються від жодного з провайдерів Qwen Cloud і не об’єднуються з ними.

Звичайна ідентичність `alibaba` має окремі списки дозволених моделей зображень і відео. Її моделі зображень:
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` і `wan2.6-t2i`. Її додані моделі відео: `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` і `wan2.7-videoedit`. Ці моделі використовують лише підключення Alibaba Model Studio
і вибрану для нього регіональну мультимедійну кінцеву точку; вони не додаються до жодного реєстру Coding Plan або Qwen
Cloud.

Каталог чатів Qwen Cloud Token Plan відповідає списку дозволених текстових моделей плану Individual із точним зіставленням рядків:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` і
`deepseek-v4-pro`. Записи Wan і HappyHorse належать до окремих API генерації зображень і відео.

Alibaba Token Plan надає ті самі шість актуальних ідентифікаторів моделей генерації тексту через свою
Anthropic-сумісну кінцеву точку. Для варіанта Singapore зберігається наявний ключ регіону `global-sg`;
від сімейств провайдерів, які називають цей регіон Global, відрізняється лише мітка, видима користувачеві.

Звичайний каталог чатів Qwen Cloud навмисно вужчий за повну актуальну відповідь із текстовими моделями. Його
підтримуваний список дозволених моделей міститься в `open-sse/config/providers/registry/qwen-cloud/index.ts`; актуальне
виявлення повертає лише ідентифікатори, наявні як у відповіді зовнішнього сервісу, так і в цьому списку реєстру.

Alibaba Model Studio дотримується того самого правила перетину з актуальними даними, використовуючи власний незалежно підтримуваний
список дозволених моделей у `open-sse/config/providers/registry/alibaba/index.ts`. Провайдер сумісності `alibaba-cn`
повторно використовує цей каталог, виконуючи виявлення через пекінську кінцеву точку.
