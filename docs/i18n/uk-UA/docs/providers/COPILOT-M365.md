`copilot-m365-web` (псевдонім `m365copilot`) надсилає запити чату у форматі OpenAI через
автентифікований браузерний сеанс Microsoft 365 Copilot BizChat за адресою
`m365.cloud.microsoft/chat`. Це неофіційна інтеграція.

> **Вперше використовуєте провайдери Web Cookie?**
>
> Перш ніж виконувати вказівки цього посібника для конкретного провайдера, ознайомтеся з **`docs/getting-started/WEB-COOKIE-GUIDE.md`**, де описано загальний процес налаштування, рекомендації щодо автентифікації, обмеження та усунення несправностей.
>
> **Важливо:** Облікові дані для цього провайдера — **не cookie**. Не копіюйте
> cookie з `m365.cloud.microsoft`. Обліковими даними є параметр запиту URL-адреси WebSocket
> і сегмент шляху, які зчитуються на вкладці Network у DevTools.

## Передумови

- Обліковий запис Microsoft 365 із доступом до BizChat за адресою `m365.cloud.microsoft/chat`
- Браузер на основі Chromium (Chrome, Edge) для перевірки WebSocket у DevTools
- Ліцензія M365 Copilot (входить до складу багатьох планів Microsoft 365 Business/Enterprise)

## Отримання облікових даних (метод WebSocket)

1. Увійдіть на `https://m365.cloud.microsoft/chat` і розпочніть розмову.
2. Відкрийте **DevTools → Network**.
3. Відфільтруйте за **WS** (WebSocket).
4. Виберіть WebSocket-з’єднання Chathub. Знайдіть URL-адресу, що починається з
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. З її **Request URL** скопіюйте:
   - Значення параметра запиту `access_token` (короткостроковий JWT).
   - Сегмент шляху Chathub після `/Chathub/` (наприклад, `<oid>@<tenant>`).

Повна URL-адреса має такий формат:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. В OmniRoute перейдіть до **Providers → Add Provider**, виберіть **Microsoft 365 Copilot
   (BizChat)** і вставте облікові дані в такому форматі:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Натисніть **Test Connection**, а потім **Save**.

## Отримання облікових даних (імпорт HAR)

Замість копіювання значень з URL-адреси WebSocket вручну можна експортувати файл HAR
із DevTools:

1. Відкрийте **DevTools → Network**.
2. Розпочніть або продовжте розмову в BizChat (це ініціює WebSocket-з’єднання).
3. Клацніть правою кнопкою миші на панелі Network і виберіть **Save all as HAR with content**.
4. У діалоговому вікні підключення провайдера OmniRoute скористайтеся кнопкою **Import .har file**.

OmniRoute сканує HAR на наявність URL-адреси WebSocket Chathub, вилучає
`access_token` і `chathubPath` та автоматично заповнює поля облікових даних. Під час
імпорту HAR декодується термін дії JWT і відображається залишковий час дії токена.

> **Ніколи не додавайте реальний експорт HAR, токен доступу чи токен оновлення до репозиторію.** Значення для тестування та
> документації завжди мають бути заповнювачами.

## Термін дії та оновлення токена

`access_token` є короткостроковим (зазвичай **~75 хвилин**). Після завершення терміну дії провайдер
повідомляє про помилку з’єднання, і вам потрібно повторно отримати облікові дані.

### Автоматичне оновлення за допомогою `refreshToken`

Щоб уникнути повторного отримання вручну, можна зберегти токен оновлення Microsoft у
**Advanced Settings → providerSpecificData** підключення:

| Поле           | Опис                                                                      |
| -------------- | ------------------------------------------------------------------------- |
| `refreshToken` | Токен оновлення Microsoft OAuth для області `substrate.office.com/sydney` |
| `tier`         | `individual` (за замовчуванням), `edu` або `enterprise`                   |

Отримайте токен оновлення за допомогою потоку Microsoft із кодом пристрою або кодом авторизації
з областю `substrate.office.com/sydney`. Якщо задано `refreshToken`, OmniRoute
попередньо оновлює `access_token` перед кожним запитом, тож вам не потрібно
повторно отримувати його після кожного завершення приблизно 75-хвилинного терміну дії.

Якщо `refreshToken` не задано, після кожного завершення терміну дії потрібно вручну
повторно отримувати облікові дані WebSocket.

### Вибір рівня

| Рівень       | Псевдонім            | Середовище              |
| ------------ | -------------------- | ----------------------- |
| `individual` | _(за замовчуванням)_ | Споживчий M365 Copilot  |
| `edu`        | `included`           | Освітній M365 Copilot   |
| `enterprise` | `work`               | M365 Copilot для роботи |

Установіть рівень у **Advanced Settings → providerSpecificData → tier**. Рівень впливає
на маршрутизацію BizChat і доступ до моделей.

## Модель безпеки

- **Неофіційна інтеграція.** Цей провайдер використовує протокол BizChat WebSocket,
  відтворений методом зворотного проєктування. Інтеграція може перестати працювати без попередження, коли Microsoft змінить кінцеву точку.
- Прапорець `subscriptionRisk: true` вказує на те, що інтеграція покладається на
  недокументовану кінцеву точку. Обмеження облікового запису можливі, але не підтверджені.
- Токен доступу — це короткостроковий JWT. Поводьтеся з ним як із паролем: не додавайте його до комітів,
  не записуйте в журнали та не поширюйте.
- Токен оновлення надає довгостроковий доступ до інтерфейсу BizChat. Зберігайте його з такою самою
  обережністю, як ключ API.

## Усунення несправностей

### Автентифікація одразу завершується помилкою

- Переконайтеся, що ви скопіювали дані з **URL-адреси WebSocket**, а не із запиту XHR/Fetch. Облікові
  дані містяться в параметрі запиту `access_token` з’єднання Chathub WebSocket,
  а не в заголовку `Authorization: Bearer`.
- Переконайтеся, що `chathubPath` містить повний сегмент `<oid>@<tenant>` зі шляху
  URL-адреси.

### Термін дії токена завершується приблизно через 75 хвилин

Це очікувана поведінка. Без `refreshToken` токен доступу має короткий термін дії. Виконайте одну з таких дій:

- Повторно отримайте облікові дані через DevTools або
- Налаштуйте `refreshToken` у розширених налаштуваннях для автоматичного оновлення.

### Перевірка з’єднання проходить успішно, але чат повертає 401

Термін дії токена міг завершитися між перевіркою та першим запитом. Повторно отримайте
актуальні облікові дані.

### Copilot не відображається в списку провайдерів

Переконайтеся, що `copilot-m365-web` увімкнено в розділі **Панель керування → Провайдери**. У деяких тарифних планах провайдер може
бути прихований за замовчуванням.
