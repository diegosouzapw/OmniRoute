`chatgpt-web-codex` (псевдонім `cgpt-codex`) передає запити Codex Responses через
автентифікований браузерний сеанс ChatGPT. Він не залежить від вилученого спільного
провайдера `chatgpt-web` і використовує реалізацію з повідомленням про ліцензію MIT у
`open-sse/vendor/codex-chatgpt-web/`, оновлену до коміту
`b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494` версії v4.0.7 з основного репозиторію.

## Вилучення спільного провайдера

Колишні ідентифікатори спільного провайдера `chatgpt-web` і `cgpt-web` більше не
постачаються, оскільки не вдалося підтвердити походження їхньої реалізації
попереднього ключа/доказу виконання роботи. Явні запити до будь-якого з цих
ідентифікаторів, зокрема ідентифікатори моделей із префіксом-косою рискою та збережені
псевдоніми, блокуються з HTTP `410` і кодом **PROVIDER_RETIRED** до виконання будь-якого
запиту до зовнішнього сервісу.

Міграція `168_retire_chatgpt_web.sql` позначає відповідні підключення провайдера як
вилучені та анулює оренди їхніх активних сеансів. Вона зберігає історію підключень і
списки дозволених API-ключів; вона не додає доступ до заміни в список дозволених.
Це вилучення не поширюється на провайдера Codex і його підключення.

## Передумови

- повний заголовок Cookie із сеансу ChatGPT, у якому виконано вхід;
- Chrome або Chromium, а також графічний сеанс чи дисплей Xvfb для встановлень через npm, systemd і PM2;
- під час використання профілю Docker `web` — внутрішня служба Chromium із
  `docker-compose.yml`;
- OpenAI `tunnel-client` v0.0.13 і спеціальний конектор ChatGPT для локальних інструментів Codex.

Тунель потрібен лише для запитів із викликами інструментів. Кожен зазначений маршрут,
зокрема `pro`, може використовувати ту саму прив’язану до запиту можливість локальних
інструментів, якщо тунель і конектор налаштовано.

## Налаштування через панель керування

1. Відкрийте провайдера **ChatGPT Web (Codex)** і додайте підключення.
2. Вставте повний заголовок Cookie ChatGPT, ідентифікатор тунелю, ключ середовища
   виконання та назву спеціального конектора. Для нових конфігурацій із підтримкою
   інструментів необхідно використовувати новостворений конектор із точною назвою
   `OmniRoute Codex v2`, параметром Authentication зі значенням None і параметром
   Permissions зі значенням Allow all actions.
3. Запустіть перевірку підключення. OmniRoute відкриває підтримуваний браузером Temporary Chat
   і визначає, чи доступні для облікового запису Sol і Pro.
4. Збережіть підключення. OmniRoute замінює вставлений файл cookie перевіреним станом
   сховища Playwright і зберігає його разом із ключем середовища виконання через
   абстракцію зашифрованих облікових даних.

Необроблений файл cookie не зберігається після успішного збереження. Коли термін дії
сеансу завершиться, відкрийте підключення, вставте новий повний заголовок Cookie і
повторно запустіть перевірку. Стан діагностики в діалоговому вікні редагування окремо
показує стан браузера, сховища, входу, Temporary Chat, тунелю, конектора та повного циклу
виклику інструмента.

> Ніколи не додавайте справжній файл cookie, ключ середовища виконання, стан сховища чи
> токен можливості до коміту. Значення для тестів і документації завжди мають бути
> заповнювачами.

## Моделі та комбінації

Фіксовані маршрути моделей:

- `chatgpt-web-codex/luna` — GPT-5.6 Luna, низький рівень зусиль
- `chatgpt-web-codex/think` — GPT-5.6 Luna, середній рівень зусиль
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

Додайте один із них до комбінації так само, як будь-яку іншу модель. Застосунок Codex
надсилає назву комбінації як `model` до звичайної кінцевої точки Responses,
`/v1/responses`; окремої кінцевої точки Codex або перемикача режимів немає.

Облікові записи Free/Go мають доступ до маршрутів Luna. Облікові записи з підтримкою Sol
мають доступ до маршрутів від Instant до High, а облікові записи з підтримкою Pro
додатково мають доступ до Extra High і Pro. Кожен маршрут має фіксовану серверну модель
та рівень зусиль для міркування; конфліктний явно заданий рівень зусиль Responses
призводить до блокування запиту замість непомітної зміни вибраного режиму браузера.

Не перейменовуйте та не використовуйте повторно старіший конектор `Codex Native` або
`OmniRoute Codex`. ChatGPT кешує публічний контракт MCP за ідентичністю конектора, тоді
як оновлений міст використовує новий прямий контракт токена запиту. Середовище виконання
відхиляє ці застарілі ідентичності та вимагає новий конектор `OmniRoute Codex v2`.

## Модель безпеки

- Нативний шлях вимагає запиту Responses, розпізнаного клієнта Codex і збігу ідентифікаторів
  гілки та ходу.
- Робочий простір, пісочниця, політика схвалення та каталог інструментів надходять із нативної оболонки Codex;
  текст запиту у вільній формі не є для них джерелом повноважень.
- ChatGPT отримує лише короткочасну можливість для кожного ходу. Брокер MCP приймає лише
  інструменти, які Codex запропонував саме в цьому ході.
- Автоматичне підтвердження **Дозволити один раз** лише повертає запит інструмента до Codex. Лише Codex
  ухвалює рішення щодо схвалення та виконання.
- До першого виведення комбінація може перемкнутися на іншу сумісну ціль. Після
  початку виведення постачальник, модель, з’єднання та хід браузера залишаються закріпленими до
  завершення ходу.
- Файли cookie, ключі середовища виконання, стан сховища та токени можливостей не з’являються у відповідях
  постачальника чи журналах запитів.

## VPS без дисплея та Docker

Для встановлень через npm, systemd і PM2 OmniRoute виявляє поширені шляхи до Chrome і Chromium.
Альтернативно задайте `CHATGPT_WEB_CODEX_CHROME_PATH`. Ходи середовища виконання навмисно використовують Chrome
із графічним інтерфейсом, оскільки ChatGPT відхиляє конфігурацію справді безголового браузера. Тому хост без дисплея має
запускати OmniRoute із приватним дисплеєм Xvfb; одного лише задання шляху до Chrome недостатньо.

Профіль Docker `web` запускає `chatgpt-web-codex-browser` у внутрішній мережі
Compose. Допоміжний контейнер запускає Chrome із графічним інтерфейсом усередині Xvfb, тому фізичний дисплей не потрібен. Його порт
CDP не публікується на хості. Захищений том профілю браузера відокремлений від
тому даних OmniRoute, а браузер отримує достатньо спільної пам’яті. Внутрішній проксі CDP
прослуховує лише порт `9223` у мережі Compose; Chrome у допоміжному контейнері залишається прив’язаним до loopback-інтерфейсу.

Оренда супервізора в `DATA_DIR` запобігає одночасному володінню кількома процесами OmniRoute
одним і тим самим станом тунелю та брокера. Конфлікт виявляє засіб діагностики.

## Інтерактивне відновлення

Автоматизований шлях Docker не має видимого на хості вікна, але сам Chrome працює з графічним інтерфейсом усередині
приватного дисплея Xvfb. Коли ChatGPT вимагає інтерактивного входу або проходження перевірки, для відновлення
можна використовувати наявну браузерну інфраструктуру VNC. Інтерфейс браузера та CDP мають залишатися доступними лише
через loopback-інтерфейс, автентифіковане адміністративне з’єднання або тунель SSH; noVNC залишається вимкненим
під час звичайної роботи.

## Резервний перехід на WebSocket

Коли комбінація містить ChatGPT Web (Codex), міст Responses WebSocket запитує
резервний перехід на HTTP/SSE перед підключенням до висхідного сервера. Після цього передавання відбувається через
`/v1/responses`.

## Перевірка

Запустіть перевірки постачальника, не викликаючи виведеного з експлуатації постачальника:

```bash
node --import tsx/esm --test \\
  tests/unit/chatgpt-web-codex.test.ts \\
  tests/unit/chatgpt-web-codex-turn-pin.test.ts \\
  tests/unit/chatgpt-web-environment-double-unescape.test.ts
```

Засоби захисту від регресій після виведення з експлуатації містяться в:

- `tests/unit/chatgpt-web-retirement.test.ts`
- `tests/unit/chatgpt-web-runtime-block.test.ts`
- `tests/unit/chatgpt-web-image-handler-retirement.test.ts`
- `tests/unit/chatgpt-web-source-retirement.test.ts`
- `tests/unit/migration-168-retire-chatgpt-web.test.ts`
