---

## Що це робить

Замість вибору конкретної моделі ШІ (наприклад, GPT-4o або Claude) ви можете дозволити OmniRoute **автоматично вибирати найкращу** для кожного запиту. Враховуються:

- **Справність** — Чи працює постачальник зараз?
- **Швидкість** — Наскільки швидко він працює?
- **Вартість** — Скільки це коштує?
- **Якість** — Чи добре він виконує завдання цього типу?
- **Потужність** — Чи залишилася в нього квота?

OmniRoute оцінює всіх підключених постачальників і вибирає найкращого. Якщо запит завершується невдало, система автоматично пробує наступного.

---

## Швидкий початок

**Крок 1**: Установіть для моделі значення `auto` у своїй IDE або CLI:

```
model: "auto"
```

**Крок 2**: Ось і все! OmniRoute подбає про решту.

**Крок 3** (необов’язково): Використовуйте варіант для конкретних завдань:

```
model: "auto/coding"    # Найкращий для коду
model: "auto/fast"      # Найшвидша відповідь
model: "auto/cheap"     # Найдешевший варіант
```

## Який варіант "auto" слід використовувати?

| Якщо вам потрібно...    | Використовуйте | Найкраще підходить для               | Як це працює                                    |
| ----------------------- | -------------- | ------------------------------------ | ----------------------------------------------- |
| **Найкращий загалом**   | `auto`         | Загальних запитань, чату             | Балансує швидкість, вартість і якість           |
| **Найкращий код**       | `auto/coding`  | Написання коду, налагодження         | Вибирає моделі, які добре працюють із кодом     |
| **Найшвидша відповідь** | `auto/fast`    | Швидких відповідей, низької затримки | Надає швидкості найвищий пріоритет              |
| **Найдешевший варіант** | `auto/cheap`   | Економії коштів                      | Вибирає найдешевшого постачальника              |
| **Найрозумніша модель** | `auto/smart`   | Складних завдань                     | Пріоритет якості + дослідження нових моделей    |
| **Найвища доступність** | `auto/offline` | Ситуацій, коли постачальники зайняті | Вибирає постачальників із найбільшою потужністю |

## Як це працює (просте пояснення)

Коли ви надсилаєте запит із `model: "auto"`, OmniRoute:

1. **Переглядає всіх підключених постачальників** — Кожного доданого вами постачальника (OpenAI, Anthropic, Google тощо)
2. **Оцінює кожного з них**, зокрема враховуючи:
   - Чи працює він? (справність)
   - Чи має він достатньо потужності? (квота)
   - Скільки це коштує? (ціна)
   - Наскільки швидко він працює? (швидкість)
   - Чи добре він виконує це завдання? (якість)
3. **Вибирає найкращого** — Постачальник із найвищою оцінкою отримує ваш запит
4. **Автоматично відновлюється** — Якщо запит завершується невдало, OmniRoute автоматично пробує наступного постачальника

### Система оцінювання

Кожен постачальник отримує оцінку від 0 до 1. Що вища оцінка, то краще він підходить.

| Чинник                 | Вага | Що це означає                                               |
| ---------------------- | ---- | ----------------------------------------------------------- |
| Справність             | 20%  | Чи працює постачальник? (стан автоматичного вимикача)       |
| Квота                  | 15%  | Чи залишилася в нього доступна потужність?                  |
| Вартість               | 15%  | Наскільки це дорого? (дешевше = вища оцінка)                |
| Швидкість              | 12%  | Наскільки швидко він працює? (менша затримка = вища оцінка) |
| Відповідність завданню | 8%   | Чи добре він виконує завдання цього типу?                   |
| Стабільність           | 5%   | Чи стабільно він працює? (низька частота помилок)           |
| Рівень                 | 5%   | Рівень облікового запису (Ultra > Pro > Free)               |
| Інше                   | 20%  | Спорідненість контексту, щільність з’єднань тощо            |

### Як варіанти змінюють оцінювання

Кожен варіант використовує різні ваги:

| Варіант        | Надає пріоритет      | Основні ваги                    |
| -------------- | -------------------- | ------------------------------- |
| `auto`         | Балансу              | health=20%, quota=15%, cost=15% |
| `auto/coding`  | Якості               | taskFit=37%, stability=15%      |
| `auto/fast`    | Швидкості            | latency=32%, health=28%         |
| `auto/cheap`   | Вартості             | cost=37%                        |
| `auto/smart`   | Якості + дослідженню | taskFit=37%, exploration=10%    |
| `auto/offline` | Потужності           | quota=37%, health=28%           |

## Як обробляються збої

OmniRoute має **три рівні захисту**:

### 1. Автоматичне перемикання

Якщо найкращий провайдер зазнає збою, OmniRoute автоматично спробує наступного. Вам не потрібно нічого робити.

### 2. Самовідновлення

Якщо провайдер продовжує зазнавати збоїв:

- **Оцінка < 0.2** → Виключається на 5 хвилин
- **Автоматичний вимикач розімкнений** → Автоматично виключається
- **Понад 50% провайдерів недоступні** → Режим інциденту (без дослідження)

### 3. Аварійне перемикання

Якщо всі провайдери зазнають збою, OmniRoute у крайньому разі спрямовує запити до стабільних безкоштовних провайдерів (наприклад, Kiro або Qoder).

---

## Підтримка кількох облікових записів

Якщо у вас є кілька облікових записів одного провайдера (наприклад, два ключі OpenAI), OmniRoute розглядає кожен із них як **окремого кандидата**. Це означає:

- В облікового запису A залишилася квота → використовувати його
- На обліковий запис B діє обмеження частоти запитів → пропустити його
- Обліковий запис C дешевший → надати йому перевагу

Кожен обліковий запис оцінюється незалежно на основі його стану, квоти та швидкості.

---

## Дослідження методом багаторукого бандита

OmniRoute час від часу **досліджує** нових провайдерів, щоб знаходити кращі варіанти:

- **За замовчуванням**: 5% запитів надсилаються випадковим провайдерам
- **Auto/smart**: частота дослідження — 10%
- **Вимикається**, коли понад 50% провайдерів перебувають у несправному стані

Це допомагає OmniRoute визначати, які провайдери найкраще відповідають вашим сценаріям використання.

## Поширені запитання

### «Чи завжди вибиратиметься найдорожча модель?»

**Ні.** За замовчуванням вартість становить лише 15% оцінки. Дешевий, швидкий і надійний провайдер може випередити дорогого. Використовуйте `auto/cheap`, якщо хочете надати вартості ще вищий пріоритет.

### «Що станеться, якщо провайдер стане недоступним?»

OmniRoute автоматично пропустить його та спробує наступного. Якщо провайдер продовжує зазнавати збоїв, його тимчасово виключають (на 5–30 хвилин). Вам не потрібно нічого робити.

### «Чи можу я побачити, якого провайдера було використано?»

Перевірте заголовки відповіді — OmniRoute вказує використаного провайдера та модель у кожній відповіді.

### «Чи навчається система на основі мого використання?»

Так! Система оцінювання використовує історичні дані (затримку, частоту помилок, частоту успішних запитів), щоб із часом приймати кращі рішення.

### «У чому різниця між `auto` та `auto/smart`?»

- `auto` — Збалансований режим, 5% дослідження
- `auto/smart` — Якість передусім (такі самі вагові коефіцієнти, як у `auto/coding`), 10% дослідження

Використовуйте `auto/smart`, якщо прагнете найкращої якості й не заперечуєте проти періодичного дослідження.

### «Чи можу я примусово вибрати певного провайдера?»

Так! Використовуйте комбінацію зі стратегією `priority` замість `auto`, а потім передайте **точну назву** комбінації в полі `model` (наприклад, `model: "my-combo"` — не `auto`). Докладніше див. у [технічній довідці](../routing/AUTO-COMBO.md).

### «Чим це відрізняється від циклічного розподілу?»

Циклічний розподіл почергово перебирає провайдерів у заданому порядку. Auto-combo **оцінює кожного провайдера** та вибирає найкращого. Це розумніший підхід, адже він враховує стан, швидкість, вартість і якість.
