Провайдери Web Cookie дають змогу OmniRoute використовувати сервіс ШІ через ваш наявний сеанс браузера замість ключа API. Вони корисні, якщо ви вже маєте доступ до сервісу через його вебсайт і хочете, щоб OmniRoute використовував той самий автентифікований сеанс.

На відміну від провайдерів із ключами API, провайдери Web Cookie виконують автентифікацію за допомогою облікових даних, які ваш браузер надсилає вебсайту.

---

# Перед початком

> **Важливо:** Завжди копіюйте облікові дані з **активного мережевого запиту**, а **не** зі сховища файлів cookie у браузері.

Багато проблем з автентифікацією виникають через копіювання файлів cookie не з того місця.

## НЕ копіюйте зі сховища файлів cookie

Більшість браузерів надають доступ до збережених файлів cookie через:

```
Інструменти розробника
→ Application (або Storage)
→ Cookies
```

Хоча ці файли cookie можуть виглядати правильними, вони можуть бути:

- застарілими
- неповними
- без файлів cookie, які надсилаються лише в автентифікованих запитах

Використання цих значень може спричинити помилки автентифікації, навіть якщо вони здаються дійсними.

## Копіюйте з активного запиту

Натомість використовуйте файли cookie з успішного запиту:

```
Інструменти розробника
→ Network
→ Оновіть сторінку
→ Відкрийте запит чату або розмови
→ Request Headers
→ Cookie
```

Заголовок запиту `Cookie` містить точні автентифікаційні дані, які ваш браузер успішно використав.

Для більшості провайдерів Web Cookie саме це значення слід вставити в OmniRoute.

---

# Загальне налаштування

Процес налаштування однаковий для більшості провайдерів Web Cookie.

1. Увійдіть на вебсайт провайдера.
2. Відкрийте інструменти розробника браузера.
3. Відкрийте вкладку **Network**.
4. Оновіть сторінку.
5. Відкрийте автентифікований запит чату або розмови.
6. Скопіюйте необхідні автентифікаційні дані.
7. Відкрийте OmniRoute.
8. Перейдіть до **Providers → Add Provider**.
9. Виберіть свого провайдера Web Cookie.
10. Вставте облікові дані.
11. Натисніть **Test Connection**.
12. Збережіть провайдера.

Точні вимоги до облікових даних залежать від провайдера.

# Що можуть і чого не можуть провайдери Web Cookie

Провайдери Web Cookie повторно використовують інтерфейс чату вебсайту. Вони **не** надають тих самих можливостей, що й офіційні API.

## Підтримується

- Автентифікація за допомогою наявного сеансу браузера
- Доступ до моделей, доступних через ваш обліковий запис
- Потокове передавання відповідей чату
- Ключ API не потрібен

## Не підтримується

- Виклик функцій
- Виклик інструментів
- Автоматичне редагування файлів
- Агентні робочі процеси IDE
- Функції, доступні лише через API

Це очікувана поведінка, а **не** помилка.

Якщо вам потрібні виконання інструментів, автоматичне редагування файлів або інші агентні робочі процеси, використовуйте **провайдера з ключем API** замість провайдера Web Cookie.

---

# Застереження щодо перевірки

Успішне **Test Connection** або перевірка файлів cookie лише підтверджує, що надані облікові дані відповідають очікуваному формату.

До вирішення Issue #7857 успішна перевірка **не гарантує**, що провайдер успішно пройде автентифікацію.

Якщо автентифікація все одно не вдається, переконайтеся, що ви скопіювали облікові дані з активного мережевого запиту, а не зі сховища файлів cookie у браузері.

---

# Усунення несправностей

## Помилка автентифікації

Переконайтеся, що облікові дані скопійовано з:

```
Network
→ Request Headers
→ Cookie
```

а **не** з:

```
Application
→ Cookies
```

---

## Файл cookie працює у браузері, але не в OmniRoute

Деякі провайдери використовують файли cookie, які надсилаються лише під час автентифікованих запитів.

Повторно скопіюйте облікові дані зі свіжого мережевого запиту після успішного відкриття розмови.

---

## Термін дії сеансу закінчився

Провайдери Web Cookie використовують ваш наявний сеанс браузера.

Якщо термін дії сеансу браузера закінчиться або ви вийдете з облікового запису, потрібно скопіювати новий набір облікових даних.

---

## Test Connection проходить успішно, але запити не виконуються

До вирішення Issue #7857 успішна перевірка не гарантує, що запит автентифікації буде успішним.

Перш ніж продовжувати усунення несправностей, повторно скопіюйте облікові дані зі свіжого автентифікованого запиту.

---

# Рекомендації

- Копіюйте облікові дані зі свіжого автентифікованого запиту.
- Не використовуйте повторно старі файли cookie.
- Підтримуйте сеанс браузера активним під час використання провайдерів Web Cookie.
- Вважайте скопійовані файли cookie конфіденційними обліковими даними.
- Використовуйте провайдерів із ключами API, якщо вам потрібні виклики функцій або агентні робочі процеси.
