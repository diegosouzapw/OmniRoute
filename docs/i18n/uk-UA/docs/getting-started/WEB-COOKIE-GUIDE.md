Провайдери Web Cookie дають змогу OmniRoute використовувати службу ШІ через наявний сеанс браузера замість ключа API. Вони корисні, якщо ви вже маєте доступ до служби через її вебсайт і хочете, щоб OmniRoute використовував той самий автентифікований сеанс.

На відміну від провайдерів із ключами API, провайдери Web Cookie автентифікуються за допомогою облікових даних, які браузер надсилає вебсайту.

---

# Перед початком

> **Важливо:** Завжди копіюйте облікові дані з **активного мережевого запиту**, а **не** зі сховища файлів cookie у браузері.

Багато проблем з автентифікацією виникають через копіювання файлів cookie з неправильного місця.

## НЕ копіюйте зі сховища файлів cookie

Більшість браузерів надають доступ до збережених файлів cookie через:

```
DevTools
→ Application (або Storage)
→ Cookies
```

Хоча ці файли cookie можуть виглядати правильними, вони можуть бути:

- застарілими
- неповними
- без файлів cookie, які надсилаються лише в автентифікованих запитах

Використання цих значень може спричинити помилки автентифікації, навіть якщо вони здаються правильними.

## Копіюйте з активного запиту

Натомість використовуйте файли cookie з успішного запиту:

```
DevTools
→ Network
→ Оновіть сторінку
→ Відкрийте запит чату або розмови
→ Request Headers
→ Cookie
```

Заголовок запиту `Cookie` містить точні автентифікаційні дані, які браузер успішно використав.

Для більшості провайдерів Web Cookie саме це значення слід вставити в OmniRoute.

# Загальне налаштування

Процес налаштування однаковий для більшості провайдерів Web Cookie.

1. Увійдіть на вебсайт провайдера.
2. Відкрийте інструменти розробника в браузері.
3. Відкрийте вкладку **Network**.
4. Оновіть сторінку.
5. Відкрийте автентифікований запит чату або розмови.
6. Скопіюйте необхідні облікові дані для автентифікації.
7. Відкрийте OmniRoute.
8. Перейдіть до **Providers → Add Provider**.
9. Виберіть свого провайдера Web Cookie.
10. Вставте облікові дані.
11. Натисніть **Test Connection**.
12. Збережіть провайдера.

Точний перелік необхідних облікових даних залежить від провайдера.

# Формати облікових даних провайдерів

Різні вебсайти зберігають автентифікаційні дані по-різному. Деяким потрібні лише файли cookie, тоді як іншим можуть знадобитися додаткові заголовки або токени.

| Провайдер                       | Формат облікових даних         | Посібник із провайдера           |
| ------------------------------- | ------------------------------ | -------------------------------- |
| Claude Web                      | Повний заголовок запиту Cookie | `docs/providers/CLAUDE_WEB.md`   |
| ChatGPT Web (Codex)             | Повний заголовок Cookie        | `docs/providers/CHATGPT_WEB.md`  |
| Gemini Web                      | _(перевірити)_                 |                                  |
| Copilot Web                     | _(перевірити)_                 | `docs/providers/COPILOT-M365.md` |
| Microsoft 365 Copilot (BizChat) | WS access_token + chathubPath  | `docs/providers/COPILOT-M365.md` |
| Grok Web                        | _(перевірити)_                 |                                  |
| ...                             | ...                            | ...                              |

> Оновлюйте цю таблицю в міру додавання нових провайдерів Web Cookie або зміни вимог до автентифікації наявних провайдерів.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) — це безплатна споживча чат-платформа, яка не потребує реєстрації: сеанс створюється анонімно під час першого відвідування та зберігається за допомогою трьох файлів cookie: `uid`, `si_usr_id` і `si_ses_id`. OmniRoute проксіює той самий кінцевий пункт `/api/dispatch` через єдиний ідентифікатор моделі (`notrack-c`, псевдонім `ntw`).

### Кроки для підключення

1. Відкрийте [notrack.ai](https://notrack.ai) у браузері та дочекайтеся встановлення файлу cookie анонімного сеансу.
2. Відкрийте **Інструменти розробника → Мережа**, оновіть сторінку та клацніть будь-який запит `/api`.
3. У розділі **Заголовки запиту** скопіюйте повне значення заголовка `Cookie`.
4. В OmniRoute перейдіть до **Провайдери → Додати провайдера → NoTrack Web (безплатний)**.
5. Вставте рядок cookie в поле `apiKey` і натисніть **Зберегти**.

OmniRoute витягує `uid`, `si_usr_id` і `si_ses_id` зі вставленого рядка та формує чистий заголовок `Cookie`, що містить лише ці пари, а також `nt_session` (токен `ntk_…`, установлений для облікових записів, у які виконано вхід), якщо він наявний. Якщо будь-який із трьох параметрів відсутній, необроблений вставлений рядок пересилається без змін, щоб оператори могли експериментувати з альтернативними форматами.

### Ідентифікатори моделей

| Ідентифікатор моделі | Відображувана назва | Примітки                                                                |
| -------------------- | ------------------- | ----------------------------------------------------------------------- |
| `notrack-c`          | NoTrack C           | Типовий варіант — висхідна модель диспетчеризації `C`.                  |
| `C`                  | NoTrack C           | Псевдонім для `notrack-c` (необроблений висхідний код диспетчеризації). |
| `notrack`            | NoTrack C           | Псевдонім для `notrack-c`.                                              |
| `ntw`                | NoTrack C           | Короткий псевдонім для `notrack-c`.                                     |

Усі чотири ідентифікатори моделей зіставляються з тією самою висхідною моделлю диспетчеризації (`C`).

### Параметри запиту

Виконавець приймає такі необов’язкові поля в тілі запиту:

| Поле тіла             | Типове значення | Призначення                                                                            |
| --------------------- | --------------- | -------------------------------------------------------------------------------------- |
| `notrack_mode`        | `usual`         | Режим диспетчеризації (довільний рядок; висхідний сервіс приймає `usual`, …)           |
| `notrack_max_turns`   | `6`             | Кількість внутрішніх кроків, які висхідний сервіс може виконати перед відповіддю.      |
| `notrack_chat_id`     | `null`          | Відновлення наявного висхідного чату (не вказуйте для нового чату).                    |
| `notrack_attachments` | `[]`            | Масив дескрипторів вкладень висхідного сервісу, що передається без змін.               |
| `notrack_regenerate`  | `false`         | Установіть `true`, щоб запитати повторно згенеровану відповідь для попереднього кроку. |

### Можливості

- **Потокові та непотокові** завершення чату.
- **Виклик інструментів** — установіть `tools: [...]` у запиті; виконавець серіалізує їх у контракт конверта виклику інструментів і перетворює відповіді моделі назад у `tool_calls` OpenAI.
- **`response_format`** — підтримуються `json_object` і `json_schema`. Виконавець витягує перший об’єкт JSON із відповіді моделі та перетворює його на рядок перед поверненням.
- **Індикація міркування** — виконавець надсилає дельту `reasoning`, коли висхідний сервіс надсилає подію `thinking`.

### Обмеження

- Висхідний сервіс застосовує квоти анонімного використання — коли їх перевищено, виконавець повертає помилку 429 зі зрозумілим повідомленням.
- Усі ідентифікатори моделей відповідають одній висхідній моделі диспетчеризації; окремого перемикання для кожної моделі немає.
- Виконавець не викликає кінцевий пункт `/api/chats` висхідного сервісу, тому історія чатів і сеанси не керуються автоматично. Використовуйте `notrack_chat_id`, щоб відновити наявний висхідний чат.

# Що можуть і чого не можуть провайдери Web Cookie

Провайдери Web Cookie повторно використовують чат-інтерфейс вебсайту. Вони **не** надають тих самих можливостей, що й офіційні API.

## Підтримується

- Автентифікація за допомогою наявного сеансу браузера
- Доступ до моделей, доступних через ваш обліковий запис
- Потокове передавання відповідей чату
- Ключ API не потрібен

## Не підтримується

- Виклик функцій
- Виклик інструментів
- Автоматичне редагування файлів
- Агентні робочі процеси в IDE
- Функції, доступні лише через API

Це очікувана поведінка, а **не** помилка.

Якщо вам потрібні виконання інструментів, автоматичне редагування файлів або інші агентні робочі процеси, використовуйте **провайдера з ключем API** замість провайдера Web Cookie.

# Застереження щодо перевірки

Успішна **перевірка з’єднання** або перевірка файлів cookie лише підтверджує, що надані облікові дані, імовірно, мають очікуваний формат.

Доклад проблему #7857 не буде вирішено, успішна перевірка **не гарантує**, що провайдер успішно пройде автентифікацію.

Якщо автентифікація все одно не вдається, переконайтеся, що ви скопіювали облікові дані з активного мережевого запиту, а не зі сховища файлів cookie браузера.

---

# Усунення несправностей

## Автентифікація не вдається

Переконайтеся, що облікові дані скопійовано з:

```
Мережа
→ Заголовки запиту
→ Cookie
```

а **не** з:

```
Програма
→ Файли cookie
```

---

## Файл cookie працює в браузері, але не в OmniRoute

Деякі провайдери додають файли cookie, які надсилаються лише під час автентифікованих запитів.

Повторно скопіюйте облікові дані зі свіжого мережевого запиту після успішного відкриття розмови.

---

## Термін дії сеансу минув

Провайдери Web Cookie використовують ваш наявний сеанс браузера.

Якщо термін дії сеансу браузера минув або ви вийшли з облікового запису, потрібно скопіювати новий набір облікових даних. Щоб автоматизувати оновлення файлів cookie для підтримуваних вебпровайдерів, скористайтеся супровідним інструментом [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md).

---

## Перевірка з’єднання успішна, але запити не виконуються

Доклад проблему #7857 не буде вирішено, успішна перевірка не гарантує виконання запиту автентифікації.

Перш ніж продовжувати усунення несправностей, повторно скопіюйте облікові дані зі свіжого автентифікованого запиту.

# Рекомендації

- Копіюйте облікові дані зі свіжого автентифікованого запиту.
- Не використовуйте старі файли cookie повторно.
- Підтримуйте сеанс браузера активним під час використання провайдерів Web Cookie.
- Вважайте скопійовані файли cookie конфіденційними обліковими даними.
- Використовуйте провайдерів із ключами API, якщо вам потрібні виклики функцій або агентні робочі процеси.
