## Базові показники

Існує кілька показників покриття залежно від способу формування звіту. Для планування корисний лише один із них.

| Рекомендована база  | Лише вихідний код, без тестів, але з урахуванням `open-sse` |             82.58% | 75.22% |  84.23% | Це базовий показник для всього проєкту, який потрібно покращувати |

Оптимізувати слід відносно рекомендованого базового показника.

## Правила

- Цільові показники покриття застосовуються до файлів вихідного коду, а не до `tests/**`.
- `open-sse/**` є частиною продукту й має залишатися в області охоплення.
- Новий код не повинен знижувати покриття в змінених ділянках.
- Надавайте перевагу тестуванню поведінки й результатів гілок, а не деталей реалізації.
- Для `src/lib/db/**` надавайте перевагу тимчасовим базам даних SQLite і невеликим фікстурам, а не широкому використанню моків.

## Поточний набір команд

- `npm run test:coverage`
  - Основна перевірка покриття вихідного коду для набору модульних тестів
  - Генерує `text-summary`, `html`, `json-summary` і `lcov`
- `npm run coverage:report`
  - Детальний пофайловий звіт за результатами останнього запуску
- `npm run test:coverage:legacy`
  - Лише для порівняння з історичними даними

## Політика поступового підвищення порогів

Оновлюйте порогові значення `npm run test:coverage` лише після того, як проєкт фактично перевищить наступну контрольну позначку із достатнім запасом.

**Поточний поріг:** `npm run test:coverage` вимагає **60 операторів / 60 рядків / 60 функцій / 60 гілок** (метрику було перебазовано у Quality-Gates Fase 6A.1 — попередній базовий показник 82.58% був завищений, оскільки враховував тестові файли та виключав `open-sse`). Команда `test:coverage:legacy` зберігає стару метрику 50/50/50 для історичного порівняння.

Для ситуативної перевірки порогових значень за останнім звітом використовуйте:

```bash
node scripts/check/test-report-summary.mjs --threshold 75
```

Рекомендована послідовність поступового підвищення порогів (порядок: `оператори-рядки / гілки / функції`):

2. 60/62/58
3. 65/64/62
4. 70/66/66
5. 75/70/72 <-- поточний поріг (75/70/75)
6. 80/75/78

Наступна ціль підвищення порогів — `80/75/78`, щойно покриття гілок триматиметься вище 78% протягом двох послідовних запусків.

## Відома прогалина

Поточна команда покриття вимірює основний набір модульних тестів Node та включає вихідний код, виконаний під час них, зокрема `open-sse`. Вона поки що не об’єднує покриття Vitest в єдиний уніфікований звіт. Це об’єднання варто реалізувати пізніше, але воно не перешкоджає початку підвищення покриття з 60% до 80%.
