Деякі сервіси були інтегровані в OmniRoute, а згодом видалені на вимогу їхніх власників. Ця сторінка є постійним архівом таких видалень. Її єдина мета — запобігти їхньому випадковому поверненню: розробник, який знайде старий форк, кешований архів `npm`, заархівований запит або запит на кшталт «відновити провайдера X», повинен мати одне місце, де чітко зазначено: **не впроваджуйте їх знову**.

Ця сторінка **не є** списком непрацюючих або припинених сервісів. Вони відстежуються в [`FREE_TIERS.md`](FREE_TIERS.md) («Видалено / немає безплатного тарифу») і можуть повернутися, якщо сервіс відновиться. Записи нижче можуть повернутися лише за наявності письмового дозволу від оператора, зазначеного в запиті, і посилання на цей дозвіл має бути додане до запису.

## Політика

1. **Запит на видалення від оператора сервісу виконується беззаперечно, без обговорень.** OmniRoute не пов'язаний із жодним висхідним сервісом. Когда оператор сервісу просить прибрати інтеграцію, вона зникає, незалежно від того, чи використовувала інтеграція офіційний API, чи ні.
2. **«Видалено» означає видалення звідусіль, що контролює OmniRoute.** Виконавець (Executor), запис у реєстрі, ідентифікатор та псевдонім провайдера, список моделей, кінцеві точки, змінні середовища, іконка, картки панелі керування, згенерована довідка про провайдера, `FREE_TIERS.md`, довідка про середовище, лічильники в README, дзеркала `llm.txt`, виділені тести та золоті знімки (golden snapshots), коментарі в коді, пункти в CHANGELOG (з відповідним врегулюванням, див. `config/release/changelog-reconciliations.json`), примітки до GitHub Releases, вікі, а також проблеми (issues), обговорення (discussions) та запити на злиття (pull requests) на GitHub, тема яких стосувалася цього провайдера (проблеми та обговорення видаляються; запити на злиття перейменовуються, їхній опис замінюється, а гілка блокується, оскільки GitHub не дозволяє видаляти pull requests).
3. **Ніколи не впроваджуйте повторно записи з цієї сторінки без письмового дозволу.** Це включає додавання ідентифікатора або псевдоніма назад до будь-якого каталогу провайдерів, додавання доменів до виконавця, прийняття PR від розробника, який «відновлює» його, додавання до каталогу безплатних моделей або документування ручного способу доступу через OmniRoute. Закривайте такі PR та issues із посиланням на цю сторінку.
4. **Зберігайте запис мінімалістичним.** Записуйте лише те, що потрібно рецензенту для розпізнавання повторного впровадження: ідентифікатори, домени, дати та pull request, через який було виконано видалення. Не описуйте, як працювала інтеграція.
5. **Захистом від регресій є тест `tests/unit/removed-providers-blocklist.test.ts`.** Він завершується помилкою, якщо будь-який ідентифікатор або домен із переліку нижче знову з'являється в каталогах провайдерів, мапі виконавців або джерелах реєстру провайдерів. Додавайте нові ідентифікатори до цього тесту в тому ж PR, який додає новий рядок сюди.

## Додавання запису

Коли надходить новий запит на видалення:

1. Переконайтеся, що запит надійшов від оператора сервісу (їхня адреса підтримки або
   домен, який вони контролюють), і зберігайте повідомлення конфіденційно.
2. Видаліть інтеграцію, дотримуючись контрольного списку в пункті політики 2. Використовуйте
   [#12440](https://github.com/diegosouzapw/OmniRoute/pull/12440) як посилання для
   провайдера без ключа та [#10210](https://github.com/diegosouzapw/OmniRoute/pull/10210) для
   провайдера з API-ключем зі збереженими з'єднаннями (додайте міграцію).
3. Додайте один рядок до таблиці вище та ідентифікатори до
   `tests/unit/removed-providers-blocklist.test.ts` в тому ж PR.
4. Відповіжте оператору після злиття PR, перерахувавши, що було видалено та що OmniRoute
   не може змінити (вже опубліковані версії npm та Docker, історія git, сторонні форки).
