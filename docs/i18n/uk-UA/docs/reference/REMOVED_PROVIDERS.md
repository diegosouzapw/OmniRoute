Деякі сервіси були інтегровані в OmniRoute, а потім видалені, оскільки люди, які ними керують, попросили про це. Ця сторінка є постійним записом цих видалень. Її єдина мета — запобігти їх випадковому поверненню: учасник, який знайде старий форк, кешований npm tarball, архівну проблему або запит на «відновлення провайдера X», потребує одного місця, де буде сказано **не впроваджувати повторно**.

Ця сторінка **не є** списком мертвих або припинених сервісів. Вони відстежуються в [`FREE_TIERS.md`](FREE_TIERS.md) («Видалено / немає безкоштовного рівня») і можуть повернутися, якщо сервіс відновиться. Записи нижче можуть бути відновлені лише за письмовим дозволом оператора, зазначеного в запиті, і цей дозвіл має бути пов'язаний із записом.

## Політика

1.  **Запит на видалення від оператора сервісу виконується, а не обговорюється.** OmniRoute не пов'язаний з жодним вихідним сервісом. Коли оператор сервісу просить видалити інтеграцію, вона видаляється, незалежно від того, чи використовувала інтеграція офіційний API, чи ні.
2.  **«Видалено» означає кожну поверхню, яку контролює OmniRoute.** Виконавець, запис реєстру, ідентифікатор і псевдонім провайдера, список моделей, кінцеві точки, змінні середовища, іконка, картки панелі інструментів, згенероване посилання на провайдера, `FREE_TIERS.md`, посилання на середовище, лічильники README, дзеркала `llm.txt`, спеціальні тести та золоті знімки, коментарі до коду, пункти CHANGELOG (з узгодженням у реєстрі, див. `config/release/changelog-reconciliations.json`), примітки до випусків GitHub, вікі, а також проблеми, обговорення та запити на злиття GitHub, предметом яких був цей провайдер (проблеми та обговорення видалено; запити на злиття перейменовано, їхній опис замінено, а гілку заблоковано, оскільки GitHub не може видаляти запити на злиття).
3.  **Ніколи не відновлюйте запис на цій сторінці без письмового дозволу.** Це включає додавання ідентифікатора або псевдоніма назад до будь-якого каталогу провайдерів, додавання доменів до виконавця, прийняття PR від учасника, який «відновлює» його, додавання його до каталогу безкоштовних моделей або документування ручного способу доступу до нього через OmniRoute. Закривайте такі PR та проблеми з посиланням на цю сторінку.
4.  **Зберігайте запис мінімальним.** Записуйте лише те, що потрібно рецензенту для розпізнавання повторного впровадження: ідентифікатори, домени, дати та запит на злиття, який здійснив видалення. Не описуйте, як працювала інтеграція.
5.  **Захист від регресії — це `tests/unit/removed-providers-blocklist.test.ts`.** Він видає помилку, коли будь-який ідентифікатор або домен, зазначений нижче, знову з'являється в каталогах провайдерів, карті виконавців або джерелах реєстру провайдерів. Додайте нові ідентифікатори до цього тесту в тому ж PR, який додає рядок сюди.

## Додавання запису

Коли надходить новий запит на видалення:

1. Переконайтеся, що запит надійшов від оператора сервісу (з його адреси підтримки або домену, який він контролює), і зберігайте повідомлення приватно.
2. Видаліть інтеграцію, дотримуючись контрольного списку в пункті політики 2. Використовуйте
   [#12440](https://github.com/diegosouzapw/OmniRoute/pull/12440) як зразок для провайдера без ключів та [#10210](https://github.com/diegosouzapw/OmniRoute/pull/10210) для провайдера з ключем API зі збереженими з'єднаннями (додайте міграцію).
3. Додайте один рядок до таблиці вище та ідентифікатори до
   `tests/unit/removed-providers-blocklist.test.ts` в тому ж PR.
4. Відповіжте оператору після злиття PR, перерахувавши, що було видалено, а що OmniRoute
   не може змінити (вже опубліковані версії npm та Docker, історія git, сторонні форки).
