> Перемикачі під час виконання, які змінюють поведінку OmniRoute **без повторного розгортання**.
> Кожен перелічений тут прапорець визначено у файлі
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> — єдиному джерелі істини. І панель керування, і REST API зчитують дані з
> цього файлу, тому наведену нижче таблицю згенеровано для точної відповідності йому у співвідношенні 1:1.

## Що таке прапорці функцій

Прапорець функції — це іменований перемикач (логічний або перелічуваний), значення якого можна змінювати
під час виконання та зберігати в базі даних без необхідності повторного розгортання процесу. Кожен
прапорець описується об’єктом `FeatureFlagDefinition` із `key`, `label`,
`description`, `category`, `defaultValue`, `type` і підказкою `requiresRestart`.

### Порядок визначення

**Ефективне значення** прапорця визначається функцією
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) з таким
порядком пріоритетності (перемагає найвищий пріоритет):

1. **Перевизначення в БД** — значення, збережене в таблиці `key_value` у просторі імен
   `feature_flags` (установлене через панель керування або REST API).
2. **Змінна середовища** — `process.env[<KEY>]`, якщо її встановлено й вона не порожня.
3. **Значення за замовчуванням із визначення** — `defaultValue` із `featureFlagDefinitions.ts`.

Логічний прапорець вважається **увімкненим**, коли його ефективне значення дорівнює `"true"`,
`"1"` або `"yes"` (див. `isFeatureFlagEnabled()`).

> [!NOTE]
> Більшість прапорців також мають відповідну змінну середовища з **такою самою назвою**,
> задокументовану у файлі [`ENVIRONMENT.md`](./ENVIRONMENT.md). Перевизначення прапорця в БД
> має пріоритет над цією змінною середовища. Прапорець із
> `requiresRestart: true` зберігається негайно, але повторно зчитується лише під час запуску
> процесу — його перемикання відображає банер **«Перезапустити сервер»** на панелі керування.

Помилка 5xx залишається невизначеною в будь-якому випадку; відмова ніколи не видаляє, не вимикає та не повторно активує проксі-сервер. |
| `DB_HEALTHCHECK_STARTUP_DEFERRED_ENABLED` | boolean | `false` | Запустити перевірку цілісності/стану бази даних під час запуску після того, як сервер почне приймати запити (через `setImmediate`), замість блокування запуску до її завершення (#13717). За замовчуванням вимкнено: запуск блокується так само, як і до цього PR.                                                                          |

> [!NOTE]
> `INPUT_SANITIZER_BLOCK_THRESHOLD` та його застарілий псевдонім
> `INJECTION_GUARD_BLOCK_THRESHOLD` налаштовують режим `block` для
> `INJECTION_GUARD_MODE`, але вони є звичайними змінними середовища, які читаються
> [`src/shared/utils/injectionSeverity.ts`](../../src/shared/utils/injectionSeverity.ts),
> а не функціональними прапорцями: вони не мають перевизначення в БД та перемикача на панелі керування.
> Дивіться [`ENVIRONMENT.md`](./ENVIRONMENT.md#4-security--authentication).

> [!NOTE]
> Стовпець `Restart` позначає прапорці з `requiresRestart: true` — значення
> зберігається миттєво, але набуває чинності лише після перезавантаження процесу. Прапорці
> перерахування відхиляють будь-яке значення поза їхнім дозволеним набором (перевіряється
> на стороні сервера як у `setFeatureFlagOverride()`, так і в обробнику REST `PUT`).

## Перемикання прапорців

### Панель керування

Перейдіть до **Панель керування → Налаштування → Прапорці функцій**
(`/dashboard/settings/feature-flags`). Сітка
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
підтримує:

- **Пошук** за ключем або описом, та **фільтрацію** за категорією (плюс синтетичний вигляд **Потребує перезапуску**).
- **Перемикач** для булевих прапорців та **випадаючий список** для прапорців-переліків
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- **Значок джерела** для кожного прапорця — `DB`, `ENV` або `DEF` — що показує, звідки походить ефективне значення.
- Кнопка **Скинути** (відображається лише для прапорців з джерелом `DB`), щоб скасувати перевизначення, та кнопка **Скинути всі перевизначення** внизу.
- Банер **Перезапустити сервер**, коли змінюється прапорець `requiresRestart`.

### REST API

Усі операції проходять через єдиний маршрут:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Кожен метод вимагає автентифікованої сесії панелі керування (інакше `401`).

#### `GET /api/settings/feature-flags`

Повертає кожен прапорець з його ефективним значенням, джерелом та зведенням.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... all 77 flags
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Встановити або видалити одне перевизначення. Тіло запиту: `{ key: string; value?: string }`.
Пропуск `value` видаляє перевизначення (відновлюючи значення середовища / за замовчуванням).

```bash
# Set a DB override
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Remove the override (no "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Відповідь відображає нові `effectiveValue`/`source`, `previousValue`/
`previousSource` та `requiresRestart`. Невідомі ключі та значення переліків поза діапазоном
відхиляються з `400`.

#### `DELETE /api/settings/feature-flags`

Очищає **всі** перевизначення БД одночасно, відновлюючи кожен прапорець до його значення середовища / за замовчуванням. Повертає `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> Прапорці з `requiresRestart: true` набувають чинності лише після перезавантаження процесу.
> Процес перезапуску панелі керування викликає `POST /api/restart`, а потім опитує
> `GET /api/health/ping`, доки сервер не відновиться.

## Аварійний резервний варіант у разі вичерпання бюджету

`OMNIROUTE_EMERGENCY_FALLBACK` (категорія `runtime`, типове значення `true`) керує
аварійним шляхом безкоштовного резервного оброблення в
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Коли його ввімкнено, запити, що вичерпали свій бюджет, спрямовуються до безкоштовного
резервного постачальника/моделі замість негайного завершення з помилкою. Установіть
значення `false` (або `0`) — за допомогою перемикача на панелі керування,
перевизначення в БД або змінної середовища `OMNIROUTE_EMERGENCY_FALLBACK` — щоб
вимкнути цю поведінку й дозволити завершення з помилкою запитів, які вичерпали бюджет.
(Додано як перемикач панелі керування в PR #3741 / #3752.)
