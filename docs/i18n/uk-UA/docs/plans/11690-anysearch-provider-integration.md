## 1. Фактичні дані про сервіс (офіційна документація, перевірена за кількома джерелами)

- Базова URL-адреса: `https://api.anysearch.com` (REST) + `POST /mcp` (MCP, JSON-RPC 2.0).
- `POST /v1/search` — параметри: `query` (обов’язковий), `max_results` (1–10, за замовчуванням 10), `tag` (`{domain}.{sub_domain}` — вертикальна маршрутизація), `zone` (cn/intl), `language`, `params` (структуровані поля вертикалі), `format` (json/markdown).
- `GET /v1/sub-domains?domain=...` — каталог можливостей, НЕ враховується в квоті.
- `POST /v1/extract` — отримує/видобуває `{url, title, content}`; суворо визначене тіло JSON, обмеження 16 КіБ.
- `POST /v1/auth/email/register` — реєстрація одним викликом, повертає одноразовий ключ у відкритому вигляді `as_sk_...`.
- Автентифікація: необов’язковий заголовок `Authorization: Bearer <as_sk_...>`; анонімний доступ обмежується лімітами для кожної IP-адреси та витрачає безкоштовну добову квоту; недійсний ключ призводить до відповіді 401/403 БЕЗ неявного переходу до анонімного доступу.
- Безкоштовний рівень: 1000 запитів на день, 20 QPS на ключ. Платний рівень: ціна не визначена (незабаром).
- Конверт відповіді: успіх `{code: 0, message: "success", request_id, data}`; помилка `{code: -1, message}`. Помилки автентифікації/квоти не містять структурованого `error_code` (сигналом є текст повідомлення); специфічні для видобування помилки містять `error_code` (`invalid_extract_url`, `extract_failed`). Заголовок `Retry-After` у відповіді 429 відсутній.

## 3. Рішення (усі ухвалені 2026-08-26)

1. **Режим маршрутизації: `fallbackOnly`.** Обґрунтування: безкоштовний провайдер із вартістю 0 не повинен домінувати в автоматичній маршрутизації за вартістю; явний вибір і повернення до резервного провайдера залишаються без змін. Прецедент: об’єднаний запис xquik.
2. **Обсяг: webSearch + webFetch через `POST /v1/extract` у v1.** Узгоджено з ментальною моделлю подвійних можливостей tavily/exa. Вертикальні інтерфейси (`tag`, `sub-domains`, `batch_search`) залишаються поза обсягом — наразі IR для вертикальних параметрів немає.
3. **Відображення квоти: `freeMonthlyQuota: 0`** (консервативне відображення в стилі xquik). Фактичний ліміт (1000 запитів на день зі щоденним скиданням) натомість зазначено в тексті `authHint` каталогу інтерфейсу. Обґрунтування: відображення квоти має відповідати семантиці скидання; перетворення денного ліміту на місячний еквівалент (30000) є хибною обіцянкою, яку інтерфейс не може виконати.
4. **searchTypes: лише `["web"]`.** Немає публічних підтверджень наявності вертикалі новин/зображень в API AnySearch; шлюзи, які інтегрують API без задокументованої вертикалі (наприклад, Google Custom Search), надають лише вебпошук, а не непомітно зіставляють news -> web.
5. **Політика ключів:** робота без ключа підтримується; недійсний ключ повертає 401/403 і ніколи непомітно не понижується до анонімного режиму (відповідає контракту зовнішнього сервісу).
6. **Свідомі виключення:** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (перехоплення чату залишається на firecrawl/jina/tavily); `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (анонімні віддалені кінцеві точки спільно використовують один пул з обмеженням за IP-адресою для кожної вихідної IP-адреси, тому extract без ключа вмикається явно, а не є кандидатом для автоматичної маршрутизації); `QUOTA_STATUS_PROVIDERS` (AnySearch сигналізує про квоту через 429/конверт, а не через статус 402/403).
