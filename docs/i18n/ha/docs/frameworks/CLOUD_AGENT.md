> **Sabuntawa ta ƙarshe:** 2026-06-28 — v3.8.40 (sabunta frontmatter; wakilai 4 ciki har da cursor-cloud)

OmniRoute yana tsara wakilan rubuta lamba da wasu kamfanoni ke masaukinsu a cloud (Codex Cloud, Cursor,
Devin, Jules) a matsayin ayyuka masu ɗaukar dogon lokaci. Ana naɗe kowane wakili a bayan haɗaɗɗiyar mahanga guda domin
abokan hulɗa su iya aika prompt + URL na ma'ajiyar lamba sannan su karɓi sakamako ba tare da hulɗa da
API na musamman ga kowane mai samarwa ba.

Aikin Cloud Agent **ba** kammala tattaunawa na yau da kullum ba ne. Rukuni ne mai ɗorewa, mai matakai da yawa
na aiki wanda zai iya ɗaukar mintuna zuwa awanni, zai iya samar da Pull Request a matsayin
artifact ɗinsa, kuma yana goyon bayan saƙonnin bibiya da kuma (ga wasu masu samarwa) ƙofofin amincewa da tsari.

## Tsarin Gine-gine

```
Abokin hulɗa (Dashboard / CLI / API)
  → POST /api/v1/agents/tasks (ana buƙatar tantancewar gudanarwa)
    → Tabbatarwar CreateCloudAgentTaskSchema (Zod)
    → registry.getAgent(providerId)
    → getCloudAgentCredentials(providerId)
      └─ yana ɗauko daga getProviderConnections({ provider, isActive: true })
         (apiKey da farko, idan bai samu ba sai accessToken)
    → agent.createTask({ prompt, source, options }, credentials)
      └─ HTTP POST zuwa API na mai samarwar upstream
      └─ yana dawo da CloudAgentTask mai id na ciki + externalId
    → insertCloudAgentTask(...) cikin cloud_agent_tasks (SQLite)

Bincike lokaci-lokaci (lazy sync yayin karantawa):
  GET /api/v1/agents/tasks/[id]
    → getCloudAgentTaskById(id)
    → agent.getStatus(externalId, credentials)  // yana sabunta status + activities
    → updateCloudAgentTask(...) tare da sabon status, result, completed_at
    → dawo da aikin da aka mayar zuwa serialized

Mu'amaloli:
  POST /api/v1/agents/tasks/[id]  body: { action: "approve" | "message" | "cancel" }
    → agent.approvePlan(externalId, credentials)        don "approve"
    → agent.sendMessage(externalId, message, credentials) don "message"
    → status yana komawa "cancelled"                    don "cancel" (na cikin gida kawai)
```

Sync ɗin **lazy** ne: ana sabunta status daga upstream a duk lokacin da aka yi `GET /tasks/[id]`.
Babu background poller. Dashboard da ke buƙatar sabon matsayi ya kamata su riƙa binciken endpoint na GET
a tazara mai dacewa.

## Mahadar `CloudAgentBase`

Tushe: `src/lib/cloudAgent/baseAgent.ts`

```typescript
export interface AgentCredentials {
  apiKey: string;
  baseUrl?: string;
}

export interface CreateTaskParams {
  prompt: string;
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
}

export interface GetStatusResult {
  status: CloudAgentStatus;
  externalId?: string;
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
}

export abstract class CloudAgentBase {
  abstract readonly providerId: string;
  abstract readonly baseUrl: string;

  abstract createTask(p: CreateTaskParams, c: AgentCredentials): Promise<CloudAgentTask>;
  abstract getStatus(externalId: string, c: AgentCredentials): Promise<GetStatusResult>;
  abstract approvePlan(externalId: string, c: AgentCredentials): Promise<void>;
  abstract sendMessage(
    externalId: string,
    message: string,
    c: AgentCredentials
  ): Promise<CloudAgentActivity>;
  abstract listSources(
    c: AgentCredentials
  ): Promise<{ name: string; url: string; branch?: string }[]>;

  protected mapStatus(raw: string): CloudAgentStatus; // kimantawa daga rubutun upstream → enum
  protected generateTaskId(): string; // `task_<ts>_<rand>`
  protected generateActivityId(): string; // `act_<ts>_<rand>`
}
```

`CodexCloudAgent.approvePlan` yana jefa kuskure da gangan — Codex Cloud yana tsara tsari ta atomatik kuma
ba shi da matakin amincewa. `CodexCloudAgent.listSources` yana mayar da `[]`.

`CursorCloudAgent` yana sarrafa Background / Cloud Agents na Cursor ta hanyar REST
API ɗinsa na hukuma (`api.cursor.com/v0`) tare da **makullin API na mai amfani ko na asusun-sabis** — zaɓin
ɓangare-na-farko mafi aminci maimakon sake amfani da zaman OAuth na Cursor IDE (mai bayarwa `cursor`,
wanda ke ɗauke da gargaɗin haɗarin dakatarwa). Adaftan REST ne kawai (ba shi da dogaro na asali
kan `@cursor/sdk`). `approvePlan` yana jefa kuskure (wakilan Cursor suna aiki da kansu); `listSources` yana lissafa
ma'ajiyoyin da makullin zai iya isa gare su. Cursor yana mayar da enum na matsayi a UPPERCASE
(`CREATING`/`RUNNING`/`FINISHED`/`ERROR`), waɗanda ake danganta su kai tsaye da
`CloudAgentStatus` na bai ɗaya. Ana iya sauya `baseUrl` ga kowace credential domin a iya
gyara sigar/hanyar API ba tare da sauya lamba ba.

## Nau'ikan Domain

Tushe: `src/lib/cloudAgent/types.ts`

```typescript
export const CLOUD_AGENT_STATUS = {
  QUEUED: "queued",
  RUNNING: "running",
  AWAITING_APPROVAL: "awaiting_approval",
  COMPLETED: "completed",
  FAILED: "failed",
  CANCELLED: "cancelled",
} as const;

export interface CloudAgentSource {
  repoName: string;
  repoUrl: string; // dole ne ya zama ingantaccen URL
  branch?: string;
}

export interface CloudAgentResult {
  prUrl?: string;
  prNumber?: number;
  commitMessage?: string;
  diffUrl?: string;
  summary?: string;
  duration?: number; // sakanni, int mai kyau
  cost?: number; // float mai kyau
}

export interface CloudAgentActivity {
  id: string;
  type: "plan" | "command" | "code_change" | "message" | "error" | "completion";
  content: string;
  timestamp: string; // ISO 8601
  metadata?: Record<string, unknown>;
}

export interface CloudAgentTask {
  id: string; // ID na ciki mai tsarin `task_...`
  providerId: "jules" | "devin" | "codex-cloud" | "cursor-cloud";
  externalId?: string; // ID na mai bayarwar upstream
  status: CloudAgentStatus;
  prompt: string; // haruffa 1..10000
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
  createdAt: string;
  updatedAt: string;
  completedAt?: string;
}
```

Ana fitar da tsare-tsaren tabbatarwa (`CreateCloudAgentTaskSchema`, `UpdateCloudAgentTaskSchema`) tare
da nau'ikan, kuma masu sarrafa hanyoyi suna amfani da su.

## Ma'ajiyar bayanai

Tushe: `src/lib/cloudAgent/db.ts` — ana ƙirƙirar teburin ne kawai lokacin da ake buƙata ta hanyar
`createCloudAgentTaskTable()` (ana kuma kiransa daga `src/lib/cloudAgent/index.ts` a lokacin
shigo da module).

```sql
CREATE TABLE IF NOT EXISTS cloud_agent_tasks (
  id           TEXT PRIMARY KEY,
  provider_id  TEXT NOT NULL,
  external_id  TEXT,
  status       TEXT NOT NULL DEFAULT 'queued',
  prompt       TEXT NOT NULL,
  source       TEXT NOT NULL,             -- JSON
  options      TEXT DEFAULT '{}',         -- JSON
  result       TEXT,                       -- JSON
  activities   TEXT DEFAULT '[]',          -- JSON
  error        TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_provider ON cloud_agent_tasks(provider_id);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_status   ON cloud_agent_tasks(status);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_created  ON cloud_agent_tasks(created_at DESC);
```

`updateCloudAgentTask` yana tilasta amfani da **jerin ginshiƙan da aka amince da su** don hana SQL injection:
`status`, `prompt`, `source`, `options`, `result`, `activities`, `error`,
`completed_at`. Duk wani maɓalli daban a cikin sabuntawar ɓangare ana watsar da shi ba tare da sanarwa ba.

## REST API — Zagayowar Aikin Task

**Tabbatar da izini:** Duk endpoints na `/api/v1/agents/tasks*` suna buƙatar **management auth**
(`requireCloudAgentManagementAuth` yana lulluɓe `requireManagementAuth` daga
`src/lib/api/requireManagementAuth`). Ana tilasta wannan bayan commit `588a0333`
(_"fix(auth): buƙaci management auth don APIs na agent da cooldown"_).

| Hanya   | Path                          | Manufa                                                      |
| ------- | ----------------------------- | ----------------------------------------------------------- |
| OPTIONS | `/api/v1/agents/tasks`        | Binciken farko na CORS                                      |
| GET     | `/api/v1/agents/tasks`        | Jera tasks (tacewa: `provider`, `status`, `limit≤500`)      |
| POST    | `/api/v1/agents/tasks`        | Ƙirƙiri task (yana aika zuwa upstream sannan ya adana)      |
| DELETE  | `/api/v1/agents/tasks?id=...` | Goge task ta query id (**ba ya** soke ta a upstream)        |
| OPTIONS | `/api/v1/agents/tasks/[id]`   | Binciken farko na CORS                                      |
| GET     | `/api/v1/agents/tasks/[id]`   | Karanta task + daidaita status daga upstream idan an buƙata |
| POST    | `/api/v1/agents/tasks/[id]`   | Aiki: `approve` / `message` / `cancel`                      |
| DELETE  | `/api/v1/agents/tasks/[id]`   | Goge task ta path id                                        |

### Ƙirƙiri task

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Fix the bug in src/foo.ts where the parser returns null",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    },
    "options": {
      "autoCreatePr": true,
      "planApprovalRequired": false
    }
  }'
```

Amsar `201`:

```json
{
  "data": {
    "id": "task_1731512345678_abc123def",
    "providerId": "devin",
    "externalId": "session_xyz",
    "status": "queued",
    "prompt": "...",
    "source": { "repoName": "user/repo", "repoUrl": "...", "branch": "main" },
    "options": { "autoCreatePr": true },
    "createdAt": "2026-05-13T12:34:56.789Z"
  }
}
```

### Amince da tsari

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"action":"approve"}'
```

### Aika saƙon bibiya

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"message","message":"Also add a unit test for the parser"}'
```

### Soke (status na cikin gida kawai)

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"cancel"}'
```

`cancel` yana sauya `status` zuwa `"cancelled"` a DB na cikin gida amma **ba ya** kiran
upstream provider — babu abort RPC a cikin `CloudAgentBase`. Don dakatar da cajin kuɗi
a upstream, kawo ƙarshen task ɗin a console na provider ɗin.

## REST API — Haɗin Cloud Provider

Waɗannan ƙarin endpoints da ke ƙarƙashin `src/app/api/cloud/` ana amfani da su ne ta clients masu nisa
(CLI, manhajar Electron, ko sync workers) don karanta metadata na haɗin provider
da warware aliases na model. Ana tabbatar da sahihancinsu da **API key na yau da kullum**
(ta hanyar `validateApiKey`), ba management auth da endpoints na task ke amfani da shi ba.

| Hanya | Path                            | Manufa                                                                       |
| ----- | ------------------------------- | ---------------------------------------------------------------------------- |
| POST  | `/api/cloud/auth`               | Tabbatar da API key, dawo da metadata na haɗi da aka ɓoye + aliases na model |
| PUT   | `/api/cloud/credentials/update` | Sabunta `accessToken` / `refreshToken` / `expiresAt`                         |
| POST  | `/api/cloud/model/resolve`      | Warware alias na model zuwa `{ provider, model }`                            |
| GET   | `/api/cloud/models/alias`       | Jera duk aliases na model                                                    |
| PUT   | `/api/cloud/models/alias`       | Saita alias na model (kuma a yi auto-sync zuwa Cloud idan an kunna)          |

`/api/cloud/auth` ba ya taɓa dawo da ainihin `apiKey` / `accessToken` / `refreshToken`. Yana
dawo da `hasApiKey`, `hasAccessToken`, `hasRefreshToken`, da samfurin da aka ɓoye
(`maskedApiKey`: haruffa 4 na farko + `****` + haruffa 4 na ƙarshe).

## Warware Credentials

`getCloudAgentCredentials(providerId)` a cikin `src/lib/cloudAgent/api.ts`:

1. Yana loda haɗe-haɗen provider masu aiki ta hanyar `getProviderConnections({ provider: providerId, isActive: true })`.
2. Ga kowane haɗi, yana fifita `apiKey` (bayan cire sararin gefuna). Idan babu, yana komawa ga `accessToken`.
3. Yana dawo da token na farko da ba fanko ba a matsayin `{ apiKey: token }`.
4. Yana dawo da `null` idan ba a sami token mai amfani ba — API yana amsawa da `400` tare da
   `"Ba a saita credentials masu aiki ba don cloud agent provider: <id>"`.

Wannan yana nufin Cloud Agents suna sake amfani da teburin Provider Connection iri ɗaya da providers na LLM
na yau da kullum. Don kunna Jules, ƙirƙiri haɗi mai aiki mai `provider: "jules"`
da `apiKey` da aka cika.

## Dashboard

Tushe: `src/app/(dashboard)/dashboard/cloud-agents/page.tsx`

Shafin React mai `"use client"` wanda yake:

- Jera tasks (ana bincikarsu lokaci-lokaci ta `GET /api/v1/agents/tasks`).
- Tura sababbin tasks ta form da ya dace da `CreateCloudAgentTaskSchema`.
- Nuna alamomin status (`queued`, `running`, `awaiting_approval`, `completed`,
  `failed`, `cancelled`) kuma ya nuna timeline na `activities[]`.
- Bayyana `result.prUrl` / `commitMessage` / `summary` lokacin da `status === "completed"`.

## Haɗawa da A2A

Ana iya gabatar da Cloud Agents a matsayin skills na A2A ta hanyar yin rajistar skill na A2A wanda ke miƙa
handler ɗinsa na `tasks/send` zuwa `getAgent(...).createTask(...)` kuma yana fassara events na status ɗin task na A2A
zuwa ƙa'idar JSON-RPC 2.0. Duba [A2A-SERVER.md](./A2A-SERVER.md).

## Ƙara Sabon Cloud Agent

1. Ƙirƙiri `src/lib/cloudAgent/agents/<name>.ts` wanda ya gaji `CloudAgentBase`.
2. Aiwatar da `createTask`, `getStatus`, `approvePlan` (ko jefa kuskure idan bai shafi lamarin ba),
   `sendMessage`, `listSources`. Yi amfani da `this.mapStatus(...)` don daidaita status.
3. Yi rajista a `src/lib/cloudAgent/registry.ts` ƙarƙashin tsayayyen `providerId`.
4. Faɗaɗa literal union na `providerId` a cikin `src/lib/cloudAgent/types.ts`
   (`CloudAgentTask.providerId` da `CreateCloudAgentTaskSchema`).
5. Ƙara provider ɗin zuwa `src/shared/constants/providers.ts` idan yana buƙatar
   bayanin haɗi. Providers masu amfani da OAuth suna kuma buƙatar `src/lib/oauth/providers/`.
6. Ƙara tests ƙarƙashin `tests/unit/cloud-agent-*.test.ts`.
7. Sabunta wannan takarda da constant na dashboard mai suna `CLOUD_AGENTS`.
