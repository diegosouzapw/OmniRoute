**OmniCopilot** yana sanya duk wani model da OmniRoute ɗinka ke samarwa cikin mai zaɓar model na _asali_ na GitHub Copilot Chat.
Babu sidebar na biyu, babu wata UI ta chat dabam — agent mode na Copilot, kiran kayan aiki,
MCP servers da custom instructions duk suna ci gaba da aiki, sai dai suna gudana ne a kan model ɗin da ka zaɓa.

> **Ba a buƙatar rajistar Copilot.** Tun daga VS Code 1.122, language-model provider yana aiki
> ba tare da shiga GitHub ba kuma ba tare da wani tsarin Copilot ba. Inline completions da
> fasalolin da suka dogara da embeddings ba sa cikin provider API kuma har yanzu suna buƙatar Copilot.

## Saitawa

1. **Gudanar da OmniRoute** — `npm install -g omniroute && omniroute` (dashboard a `http://localhost:20128`).
2. **Shigar da extension** — bincika "OmniRoute" a cikin kallon Extensions.
3. **Zaɓi model** — Copilot Chat → mai zaɓar model → **Manage Models…** → **OmniRoute**, sannan ka yi alama
   a kan waɗanda kake so.

Ba sai an saita komai ba idan OmniRoute yana gudana a default port. Don instance mai nisa, buɗe
**alamar OmniRoute a Activity Bar** (ko gudanar da `OmniRoute: Manage Connection`) sannan ka saita:

- **Server URL** — tushen server, misali `http://192.168.0.15:20128`. Extension ɗin ne yake
  ƙara suffix ɗin `/v1`; kada ka haɗa shi.
- **API key** — kawai idan server ya saita `REQUIRE_API_KEY`. Ana adana shi a OS keychain ta hanyar VS
  Code SecretStorage, ba a taɓa adana shi a `settings.json` ba.

## Abin da mai zaɓar zai nuna

Extension ɗin ba ya nuna raw payload na `GET /v1/models` — yana tsara shi, kuma adadin da
kake gani ya yi ƙasa da girman catalog saboda dalilai biyu da aka yi da gangan.

### Yana neman id ɗaya ga kowane model

`MODELS_CATALOG_PREFIX_MODE` yana amfani da **`dual`** ta default, wanda ke tallata kowane model sau biyu — sau ɗaya
ƙarƙashin gajeren alias prefix, sannan sau ɗaya ƙarƙashin canonical provider prefix — domin tsofaffin
saitunan client su ci gaba da gano kowanne nau'i:

```
cc/claude-sonnet-4-6        ← alias prefix
claude/claude-sonnet-4-6    ← canonical prefix, model ɗaya ne
```

Extension ɗin yana neman **`GET /v1/models?prefix=alias`** domin id ɗaya ya iso ga kowane model, ba tare da
canza saitin server gaba ɗaya ga sauran clients ɗinka ba. A wani reference instance, wannan ya rage
**entries 2345 zuwa 1396 — duplicates 949, babu model ɗin da aka rasa.**

Idan ka fi son gyara shi a duk faɗin server ga _kowane_ client, saita feature flag na
`MODELS_CATALOG_PREFIX_MODE` zuwa `alias` a dashboard. Duba
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) domin ganin
query parameter da jadawalin kowane mode.

### Yana ɓoye models waɗanda ba za su iya chat ba

Catalog ɗin kuma yana lissafa image, video, audio, rerank, embedding da moderation models. Waɗannan
za a ƙi su idan aka yi chat request:

```
HTTP 400 — Model '<id>' model ne na ƙirƙirar hoto kuma ba za a iya amfani da shi a
/v1/chat/completions ba. Yi amfani da POST /v1/images/generations a maimakonsa.
```

saboda haka ana tace su ta amfani da field ɗinsu na `type` kafin su isa ga mai zaɓar. **Ana riƙe da Responses-API
models** — kowane Codex / GPT-5.x entry yana tallata `supported_endpoints: ["responses"]`,
kuma OmniRoute yana fassara waɗannan don `/v1/chat/completions`, saboda haka ana iya amfani da su sosai.

### Providers da ba ka taɓa saita su ba

Catalog ɗin yana lissafa models daga providers masu **active connection** _tare da_ kowane provider na **noAuth**
— waɗanda ba sa buƙatar key, waɗanda suka ƙunshi babban ɓangare na free tier. An yi hakan ne da gangan. Don ɓoye
su, ƙara su zuwa `blockedProviders` a cikin saitunan dashboard; babu abin da zai canza a cikin
extension.

## Dashboard a cikin shafin VS Code

`omnicopilot.dashboardOpen: "editor"` yana nuna dashboard na OmniRoute a cikin shafin edita ta hanyar
Simple Browser maimakon burauzar waje. Saka shi a ciki **zaɓi ne da ake kunnawa a uwar garke** ta hanyar
`DASHBOARD_ALLOW_EMBED=vscode`, wanda ke gabatar da shafukan HTML tare da
`frame-ancestors 'self' vscode-webview:` maimakon tsohon `frame-ancestors 'none'` +
`X-Frame-Options: DENY`. Fuskar API (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) tana ci gaba da
amfani da tsauraran headers a kowane hali.

> ⚠️ **Wannan flag ne na lokacin build, ba na lokacin runtime ba.** Next.js yana tattara `headers()` cikin manifest na route,
> don haka `next.config.mjs` yana karanta variable ɗin yayin da ake yin build na bundle
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> Export ɗinsa kafin fara uwar garken da aka riga aka yi wa build ba ya canza komai — an riga an kafe headers ɗin.

```bash
# dole ne variable ɗin ya kasance a kan umarnin BUILD
DASHBOARD_ALLOW_EMBED=vscode npm run build        # ko npm run build:release
npm start
```

| Yadda kuka girka           | Za ku iya kunna saka shi a ciki?                                                                                                               |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Daga source                | ✅ saita variable ɗin a kan umarnin build, kamar yadda aka nuna a sama                                                                         |
| `npm install -g omniroute` | ❌ package da aka wallafa yana zuwa da bundle da aka riga aka yi wa build — maimakon haka, yi build daga source                                |
| Docker image               | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — prebuilt image da ke Docker Hub ba a kunna masa embedding ba |

Ba tare da build da aka kunna masa embedding ba, shafin zai ƙi shiga frame, extension ɗin zai gano hakan daga
response headers sannan ya koma amfani da burauzar waje — babu abin da zai lalace, kuma zai sanar da haka sau ɗaya.
Duba [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) da issue
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273).

## Daidaita sauran kayan aikinku daga cikin VS Code

**`OmniRoute: Configure Coding CLI`** yana sarrafa `omniroute` CLI domin rubuta profiles da suke shirye don amfani
ga Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code,

[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md). Ana miƙa API key ɗin zuwa CLI ta hanyar
environment variable `OMNIROUTE_API_KEY`, ba a kan command line ba.
