## Hanyoyin Shigarwa

### npm (ana ba da shawara)

```bash
npm install -g omniroute
omniroute
```

Dashboard yana buɗewa a `http://localhost:20128`, sannan tushen URL na API shi ne `http://localhost:20128/v1`.

### pnpm

```bash
pnpm add -g omniroute@latest --allow-build=better-sqlite3 --allow-build=@swc/core
omniroute
```

> **Masu amfani da pnpm:** ana buƙatar tutar `--allow-build` domin kunna rubutun ginawa na asali don `better-sqlite3` da `@swc/core`. Ba a goyon bayan umarnin `pnpm approve-builds -g` don shigarwa ta duniya a pnpm v11.

### Arch Linux (AUR)

```bash
yay -S omniroute-bin
systemctl --user enable --now omniroute.service
```

[Kunshin AUR](https://aur.archlinux.org/packages/omniroute-bin) yana shigar da OmniRoute kuma yana samar da sabis na mai amfani na systemd.

### Daga Lambar Tushe

```bash
npm install
PORT=20128 DASHBOARD_PORT=20129 NEXT_PUBLIC_BASE_URL=http://localhost:20129 npm run dev
```

> **Bayanan Windows:** Ta tsohuwa, OmniRoute yana amfani da `%APPDATA%\omniroute` idan tsohon kundin adireshi na `%USERPROFILE%\.omniroute` ba ya nan. Saita `DATA_DIR` don zaɓar wani wurin kundin bayanai daban.

> **Lura:** `npm install` yana samar da `.env` kai tsaye daga `.env.example` a farkon gudanarwa. Shigarwa na gaba ba za su sake rubuta `.env` da ke akwai ba, don haka ana adana gyare-gyare. Don sake samar da shi daga tushe, share `.env` kafin sake gudanarwa.

### Docker

Duba [Jagorar Docker](./DOCKER_GUIDE.md) don cikakken saitin Docker, ciki har da bayanan martabar Compose da Caddy HTTPS.

### Manhajar Tebur (Electron)

OmniRoute yana zuwa da manhajar tebur da aka gina bisa Electron 41 + electron-builder 26.10. Rubutun da ake da su (a tushen workspace):

```bash
npm run electron:dev          # Gudanar da manhajar tebur tare da sake lodawa kai tsaye
npm run electron:build        # Gina don OS na yanzu (ana gano shi kai tsaye)
npm run electron:build:win    # Mai shigarwar Windows (NSIS + mai ɗaukuwa)
npm run electron:build:mac    # macOS (dmg + zip, arm64+x64)
npm run electron:build:linux  # Linux (AppImage + deb + rpm)
npm run electron:smoke:packaged  # Gwajin farko na ginin da aka shirya
```

Ana haɗa fitarwar masu shigar da manhajar tebur zuwa GitHub Releases. Don cikakken bayani mai zurfi game da Electron (sa hannu, gadar IPC, rabe-raben Linux), duba [`ELECTRON_GUIDE.md`](./ELECTRON_GUIDE.md) _(an ƙirƙira a wani mataki na gaba)_.

### Sabar da ba ta da mahaɗin gani (CI/aikin atomatik)

Don saituna marasa buƙatar kulawa (Docker, Kubernetes, CI), yi amfani da:

```bash
omniroute setup --non-interactive
omniroute providers test-batch
```

Idan aka haɗa da sauye-sauyen muhalli (`INITIAL_PASSWORD`, `OMNIROUTE_WS_BRIDGE_SECRET`, da sauransu), wannan yana ba ka damar ƙaddamar da wani misalin OmniRoute da za a iya sarrafa shi gaba ɗaya ta rubutun umarni.

### Zaɓuɓɓukan CLI

| Umarni                  | Bayani                                                                |
| ----------------------- | --------------------------------------------------------------------- |
| `omniroute`             | Fara sabar (`PORT=20128`, API da dashboard a port ɗaya)               |
| `omniroute setup`       | Jagorar farawa ta CLI don kalmar sirri da mai samarwa na farko        |
| `omniroute doctor`      | Gudanar da gwaje-gwajen lafiyar gida ba tare da fara sabar ba         |
| `omniroute providers`   | Gano, jera, tabbatar, da gwada masu samarwa daga CLI                  |
| `omniroute config`      | Tsarin kayan aikin CLI — jera, samu, saita, tabbatar da tsare-tsare   |
| `omniroute status`      | Dashboard na matsayi marar layi — siga, DB, kayan aiki, tsari         |
| `omniroute logs`        | Nuna rajistan amfani kai tsaye daga API (yana goyon bayan `--follow`) |
| `omniroute update`      | Bincika ko aiwatar da sabuntawar OmniRoute                            |
| `omniroute provider`    | Sarrafa haɗin masu samarwa — ƙara, jera, cire, gwada, tsoho           |
| `omniroute --port 3000` | Saita port na asali/API zuwa 3000                                     |
| `omniroute --mcp`       | Fara sabar MCP (sufurin stdio)                                        |
| `omniroute --no-open`   | Kada a buɗe burauza kai tsaye                                         |
| `omniroute --help`      | Nuna taimako                                                          |

Ana iya sarrafa saitin da ba shi da mahaɗin gani ta rubutun umarni ta amfani da tutoci ko sauye-sauyen muhalli:

```bash
omniroute setup --non-interactive --password "$OMNIROUTE_PASSWORD"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY" --test-provider
```

Gudanar da binciken matsalolin gida ba tare da buɗe dashboard ba:

```bash
omniroute doctor
omniroute doctor --json
omniroute doctor --no-liveness
```

Sarrafa masu samarwa daga SSH ko rubutun umarni ba tare da buɗe dashboard ba:

```bash
omniroute providers available
omniroute providers available --search openai
omniroute providers available --category api-key
omniroute providers list
omniroute providers test <id-or-name>
omniroute providers test-all
omniroute providers validate
```

## Daidaita Kayan Aikin CLI

### 1) Haɗa Masu Samar da Sabis kuma Ƙirƙiri Maɓallin API

1. Buɗe Dashboard → `Providers` sannan ka haɗa aƙalla mai samar da sabis guda ɗaya (OAuth ko maɓallin API).
2. Buɗe Dashboard → `Endpoints` sannan ka ƙirƙiri maɓallin API.
3. (Na zaɓi) Buɗe Dashboard → `Combos` sannan ka saita jerin madadin naka.

### 2) Daidaita Kayan Aikin Rubuta Lambarka

```txt
Tushen URL: http://localhost:20128/v1
Maɓallin API:  [kwafa daga shafin Endpoint]
Samfuri:    if/qwen3.8-max-preview (ko kowane prefix na provider/model)
```

Idan editanka ba zai iya aika `Authorization: Bearer ...` ba, yi amfani da tushen daidaituwa mai token a maimakonsa:

```txt
Tushen URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/
URL na Samfura: http://localhost:20128/api/v1/vscode/YOUR_KEY/models
URL na Tattaunawa: http://localhost:20128/api/v1/vscode/YOUR_KEY/chat/completions
URL na Alamomin Ollama: http://localhost:20128/api/v1/vscode/YOUR_KEY/api/tags
```

Yana aiki da Claude Code, Codex CLI, Cursor, Cline, OpenClaw, OpenCode, da SDKs masu dacewa da OpenAI.

#### Daidaitawa ta atomatik da `setup-*`

Maimakon liƙa tushen URL da maɓalli da hannu, bari OmniRoute ya rubuta saitunan kowane kayan aiki
daga kundin samfura na kai tsaye. Umarni guda ɗaya ga kowane kayan aiki:

```bash
omniroute setup-codex        # Bayanan martaba na ~/.codex/<name>.config.toml
omniroute setup-claude       # ~/.claude/profiles/<name>/settings.json
omniroute setup-opencode     # ~/.config/opencode/opencode.json (mai dacewa da openai)
omniroute setup-cline        # Saitunan Cline CLI + tsawo na VS Code
omniroute setup-kilo         # Kilo Code
omniroute setup-continue     # ~/.continue/config.yaml (Continue / cn)
omniroute setup-cursor       # Yana buga matakan da za a bi a cikin Cursor
omniroute setup-roo          # Shigo da Roo Code + manunin autoImport
omniroute setup-crush        # ~/.config/crush/crush.json
omniroute setup-goose        # ~/.config/goose/config.yaml
omniroute setup-aider        # ~/.aider.conf.yml
omniroute setup-qwen         # ~/.qwen/settings.json + ~/.qwen/.env
```

Kowane ɗaya yana karɓar `--remote <url> --api-key <key>` don daidaita kayan aiki na gida da
OmniRoute na **nesa**, tare da `--dry-run` don samfoti. Don ƙaddamar da CLI tare da
env da ya dace ba tare da rubuta wani saitin ba kwata-kwata, yi amfani da mai ƙaddamarwa na gama-gari
`omniroute run <target>` (claude, codex, aider, goose, opencode, qwen, gemini);
tsofaffin masu ƙaddamarwa na kowane kayan aiki `omniroute launch` (Claude Code) da
`omniroute launch-codex` (Codex) suna nan har yanzu.

Don cikakken tebur (abin da kowane umarni yake rubutawa, dukkan flags, na gida da na nesa, ƙa'idodin tushen URL
`/v1`), duba **[Haɗaɗɗun CLI](./CLI-INTEGRATIONS.md)**.

Don cikakken bayanin daidaita kowane kayan aiki (Claude Code, Codex CLI, Cursor, Cline, OpenClaw, Kilo Code, Copilot, da sauransu), duba keɓantaccen **[Jagorar Kayan Aikin CLI](../reference/CLI-TOOLS.md)**.

## Saitin Yarjejeniya (MCP + A2A)

### Saitin MCP (Yarjejeniyar Mahallin Samfuri)

Fara jigilar MCP a yanayin stdio:

```bash
omniroute --mcp
```

Hanyar tabbatarwa da aka ba da shawara:

```bash
# 1. Fara sabar MCP
omniroute --mcp

# 2. Daga MCP client ɗinka, kira:
omniroute_get_health        # Ya kamata ya dawo da lafiyar tsarin
omniroute_list_combos       # Ya kamata ya dawo da combos masu aiki

# 3. Ko gudanar da cikakken jerin gwajin E2E:
npm run test:protocols:e2e
```

#### Daidaita MCP Client

**Claude Code:**

```bash
claude mcp add-server omniroute --type http --url http://localhost:20128/api/mcp/stream
```

**Cursor / Cline:**

Ƙara wannan zuwa saitunan MCP naka:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"],
      "env": {}
    }
  }
}
```

**Cikakkun takardun MCP:** [README na Sabar MCP](../../open-sse/mcp-server/README.md) — kayan aiki 110, saitunan IDE, clients na Python/TS/Go.

### Saitin A2A (Yarjejeniyar Agent-zuwa-Agent)

Tabbatar da Agent Card:

```bash
curl http://localhost:20128/.well-known/agent.json
```

Aika wani aiki:

```bash
curl -X POST http://localhost:20128/a2a \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":"quickstart","method":"message/send","params":{"skill":"quota-management","messages":[{"role":"user","content":"Give me a short quota summary."}]}}'
```

**Cikakkun takardun A2A:** [README na Sabar A2A](../../src/lib/a2a/README.md) — JSON-RPC 2.0, ƙwarewa, watsawa kai tsaye, da zagayowar rayuwar aiki.

## Saitin Lokacin Jira

### Lokutan Jira na Asali

Ga yawancin turawa, waɗannan canje-canje guda biyu kaɗai kake buƙata:

| Canji                    | Tsoho                               | Manufa                                                                                                                                                                  |
| ------------------------ | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `REQUEST_TIMEOUT_MS`     | `600000`                            | Ma'aunin tushe na bai ɗaya don lokacin jiran fara amsar uwar-garke, ɓoyayyun lokutan jiran Undici, buƙatun sawun yatsan TLS, da lokutan jiran buƙata/proxy na gadar API |
| `STREAM_IDLE_TIMEOUT_MS` | yana gado daga `REQUEST_TIMEOUT_MS` | Matsakaicin tazarar lokaci tsakanin gutsattsarin bayanan da ake watsawa kafin OmniRoute ya dakatar da rafin SSE                                                         |

An kiyaye dacewa da tsoffin nau'ikan: `FETCH_TIMEOUT_MS`, `API_BRIDGE_PROXY_TIMEOUT_MS`, da sauran canje-canjen lokacin jira na kowane mataki da ake da su har yanzu suna aiki kuma suna maye gurbin ma'aunin tushe na bai ɗaya.

### Bayanan Musamman na Mai Bayarwa

Ga uwar-garken da suka dace da Claude Code (`anthropic-compatible-cc-*`), OmniRoute yana samar da kanun `X-Stainless-Timeout` mai fita daga lokacin jiran fetch da aka ƙayyade, domin lokutan jiran karantawa a ɓangaren mai bayarwa su ci gaba da daidaituwa da saitunan env ɗinka.

Ga reverse proxies na wasu kamfanoni masu dacewa da Claude Code, OmniRoute yana kiyaye tsoffin saitunan `anthropic-beta` cikin taka-tsantsan kuma, idan an bar `Client Cache Control` a kan `Auto`, yana tura alamomin `cache_control` da abokin ciniki ya bayar kawai. Kunna maɓallin "Enable redact-thinking beta" na kowace haɗi ne kawai idan uwar-garken yana buƙatar rafukan tunanin Claude da aka ɓoye musamman.

### Sauye-sauyen Lokacin Jira na Ci-gaba

| Canji                                    | Tsoho                                           | Manufa                                                                                  |
| ---------------------------------------- | ----------------------------------------------- | --------------------------------------------------------------------------------------- |
| `FETCH_TIMEOUT_MS`                       | yana gado daga `REQUEST_TIMEOUT_MS`             | Lokacin jiran fara amsar uwar-garke da ake amfani da shi har sai kanun amsa sun iso     |
| `FETCH_HEADERS_TIMEOUT_MS`               | yana gado daga `FETCH_TIMEOUT_MS`               | Iyakar lokacin Undici don karɓar kanun amsar uwar-garke                                 |
| `FETCH_BODY_TIMEOUT_MS`                  | yana gado daga `FETCH_TIMEOUT_MS`               | Iyakar lokacin Undici tsakanin gutsattsarin jikin amsar uwar-garke (`0` yana kashe shi) |
| `FETCH_CONNECT_TIMEOUT_MS`               | `30000`                                         | Lokacin jiran haɗin TCP na Undici                                                       |
| `FETCH_KEEPALIVE_TIMEOUT_MS`             | `4000`                                          | Lokacin jiran soket ɗin keep-alive marar aiki na Undici                                 |
| `TLS_CLIENT_TIMEOUT_MS`                  | yana gado daga `FETCH_TIMEOUT_MS`               | Lokacin jiran buƙatun sawun yatsan TLS da aka yi ta hanyar `wreq-js`                    |
| `API_BRIDGE_PROXY_TIMEOUT_MS`            | yana gado daga `REQUEST_TIMEOUT_MS` ko `600000` | Lokacin jiran tura proxy na `/v1` daga tashar API zuwa tashar dashboard                 |
| `API_BRIDGE_SERVER_REQUEST_TIMEOUT_MS`   | `max(API_BRIDGE_PROXY_TIMEOUT_MS, 300000)`      | Lokacin jiran buƙata mai shigowa a sabar gadar API                                      |
| `API_BRIDGE_SERVER_HEADERS_TIMEOUT_MS`   | `60000`                                         | Lokacin jiran kanun mai shigowa a sabar gadar API                                       |
| `API_BRIDGE_SERVER_KEEPALIVE_TIMEOUT_MS` | `5000`                                          | Lokacin jiran keep-alive a sabar gadar API                                              |
| `API_BRIDGE_SERVER_SOCKET_TIMEOUT_MS`    | `0`                                             | Lokacin jiran rashin aiki na soket a sabar gadar API (`0` yana kashe shi)               |

> **Lura:** Ga buƙatun watsawa, `FETCH_TIMEOUT_MS` yana rufe kafa haɗi / jiran amsar farko daga uwar-garke kawai. Da zarar rafin ya fara aiki, OmniRoute zai dakatar da shi ne kawai idan an samu tsayawar gaske (`STREAM_IDLE_TIMEOUT_MS`) ko rashin aikin jikin Undici (`FETCH_BODY_TIMEOUT_MS`).

### Dacewa da Reverse Proxy

Idan kana gudanar da OmniRoute a bayan Nginx, Caddy, Cloudflare, ko wani reverse proxy, ka tabbatar cewa lokutan jiran proxy ɗin ma sun fi lokutan jiran stream/fetch na OmniRoute tsawo.

## Samfurin Void Linux (xbps-src)

Ga masu amfani da Void Linux, za ku iya gina kunshin asali ta amfani da `xbps-src`. Ajiye wannan ɓangaren a matsayin `srcpkgs/omniroute/template`:

```bash
# Fayil ɗin samfuri na 'omniroute'
pkgname=omniroute
version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"
maintainer="zenobit <zenobit@disroot.org>"
license="MIT"
homepage="https://github.com/diegosouzapw/OmniRoute"
distfiles="https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz"
# Sake samar da checksum ga kowace fitarwa da:
#   curl -L -o /tmp/omniroute.tar.gz "https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz" && sha256sum /tmp/omniroute.tar.gz
checksum=PLACEHOLDER_REGENERATE_PER_RELEASE
system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	NODE_ENV=development npm ci --ignore-scripts
	npm run build
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	rm -rf .next/standalone/node_modules/@img

	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

exec node /usr/lib/omniroute/.next/standalone/server.js "$@"

	vbin "${WRKDIR}/omniroute"
```
