> 옵트인 방식이며 기본적으로 비활성화됩니다(`modelVisibilityAllowlist`/`modelVisibilityDenylist`가
> 모두 비어 있으면 `/v1/models` 카탈로그와 모든 `auto/*` 후보 풀이 바이트 단위로 동일하게 유지됩니다).
> 비용과 무관한 이유로 선별된 모델 목록을 제공하려는 운영자를 위한
> `hidePaidModels`/`hideAutoCombos`(`src/lib/db/settings.ts`)의 동급 설정입니다.

## 이 기능이 존재하는 이유

`hidePaidModels`는 "이 모델이 무료인가?"에 답하고, `hideAutoCombos`는 "`auto/*` 가상 id를
아예 노출해야 하는가?"에 답합니다. 하지만 어느 쪽도 운영자가 임의의 모델 하위 집합을
선별할 수 있게 해 주지는 않습니다(예: 가격과 무관하게 특정 Claude Code / OpenCode 클라이언트에
정확히 표시되어야 할 모델만 제공). #11481은 이를 서로 독립적인 옵트인 문자열 배열 설정 두 개로 추가합니다.

## 설정

| 키                         | 타입       | 기본값 | 의미                                                     |
| -------------------------- | ---------- | ------ | -------------------------------------------------------- |
| `modelVisibilityDenylist`  | `string[]` | `[]`   | 후보와 일치하는 항목은 카탈로그/후보 풀에서 숨깁니다.    |
| `modelVisibilityAllowlist` | `string[]` | `[]`   | 비어 있지 않으면 후보와 일치하는 항목만 계속 노출됩니다. |

둘 다 최대 200자인 항목을 최대 500개까지 허용합니다
(`src/shared/validation/settingsSchemas.ts`에서 Zod로 검증). 각 항목은 다음 중 하나입니다.

- 정확한 카탈로그 id — `"gpt-4o"`(모델 id만 사용) 또는 `"openai/gpt-4o"`(provider 접두사 포함), 또는
- `*`/`?`를 사용하는 glob 패턴 — 예: `"openai/gpt-4*"` 또는 `"anthropic/*"` — 이미
  `ModelRoutingSection`의 모델별 combo 매핑과 `freeModels.ts::matchesOnlyPaidModels`에서 사용되는
  동일한 공유 `globToRegex()` 매처(`src/shared/utils/globPattern.ts`)를 통해 판별됩니다.

우선순위: denylist를 먼저 확인합니다(거부된 항목은 allowlist와도 일치하더라도 항상 숨겨집니다).
allowlist가 비어 있지 않으면 allowlist와 일치하는 항목만 남습니다.

## 하나가 아닌 두 개의 초크포인트

#6512에서 얻은 교훈(`hidePaidModels`만 적용한 카탈로그 필터로는 combo 후보 풀이 별도로
구성되기 때문에 여전히 `auto/*`가 유료 모델로 라우팅될 수 있었음)은 여기에도 동일하게 적용됩니다.
일치 여부를 판정하는 `isModelExposureAllowed()`(`src/shared/utils/modelExposureList.ts`)는
다음 두 곳 모두에서 호출됩니다.

- `src/app/api/v1/models/catalog.ts` — `/v1/models` 목록 자체에서 기존에 `shouldHidePaid()`가
  제어하는 것과 동일한 소스별 5개 초크포인트(static `PROVIDER_MODELS`, 동기화된 provider 행,
  custom 행, alias 기반 행, managed-fallback 행).
- `open-sse/services/autoCombo/modelExposureFilter.ts::filterModelExposureCandidates()` —
  `virtualFactory.ts::buildPreparedPool`에서 이에 대응하는 `filterPaidOnlyCandidates()` 호출 직후
  호출되므로, 거부된 모델은 `auto/*` 후보 풀에도 절대 선택될 수 없습니다.

## 필터링되지 않는 항목

`hideAutoCombos`의 기존 동작을 따릅니다. **명시적으로** 전송된 모델 id(`auto/*`를 통하지 않고
카탈로그 목록을 통해 발견된 것도 아닌 경우)는 디스패치 시점에 절대 차단되지 않으며,
노출 여부/후보 풀 포함 여부만 필터링됩니다. 이는 `hidePaidModels`와 독립적입니다.
운영자는 비용과 무관한 이유로 선별된 집합을 원할 수 있으므로, 두 설정은 `catalog.ts`의
기존 다중 플래그 조합과 마찬가지로 서로 독립적인 AND 필터로 조합됩니다.

설정 내보내기(`GET /api/settings/export-json`)에는 다른 설정 필드와 마찬가지로 두 배열이
그대로 포함됩니다. `hidePaidModels`의 combo 단계 내보내기 필터와 달리 여기에는 재수화
위험이 없습니다. 내보낸 combo 단계에 포함된 거부 id는 운영자가 직접 명시한 라우팅
선택이지, 내보내기 경계에서 제거해야 할 항목이 아닙니다.
