> 옵트인 방식이며 기본적으로 비활성화되어 있습니다(`settings.freeAccessPolicy !== "strict"`인 경우 모든 `auto/*`
> 후보 풀은 바이트 단위까지 동일하게 유지됩니다). 금전적 지출이 추가로 발생하지 않도록 단순히 "무료로 명시됨"을 넘어
> **어떠한 경우에도** 확실하게 보장해야 하는 운영자를 위한 `hidePaidModels`
> (`open-sse/services/autoCombo/paidModelFilter.ts`, #6512)의 더 엄격한 동급 기능입니다.

## 이 기능이 필요한 이유와 `hidePaidModels`만으로는 충분하지 않은 이유

`hidePaidModels`는 "현재 이 모델이 `FREE_MODEL_BUDGETS`에서 무료로 분류되어 있는가?"에
답합니다. 이는 특정 시점의 카탈로그 정보이며 `isFreeModel()`/`providerHasFreeModels()`
(`src/shared/utils/freeModels.ts`)를 통해 확인됩니다. 하지만 다음 두 가지 실질적인 위험에
대해서는 아무것도 알려주지 않습니다.

1. `recurring-*`/`one-time-initial` 무료 티어의 허용량은 **소진될 수 있습니다**. 카탈로그에는
   여전히 해당 모델이 무료로 표시되지만, 그 이면의 계정에는 더 이상 사용 가능한 여유분이 없습니다.
2. 무료 티어 초과가 항상 강제 중단을 의미하는 것은 아닙니다. 일부 제공업체는 결제 수단을
   절대 등록할 수 없다고 명시적으로 안내하지만("신용 카드 필요 없음"), 그렇지 않은 업체도 있으며,
   일부는 무료 허용량을 초과하면 자동으로 요금을 청구합니다.

`hidePaidModels`는 이러한 경우를 구분할 수 없으며, 애초에 그러도록 설계된 기능도 아닙니다. STRICT_ZERO_COST는
바로 이 두 가지 검사를 각 후보별로 **카테고리/티어 순위를 정하기 전에**, 그리고 **디스패치 전에**
수행합니다. 요청이 이미 전송된 후에는 절대 수행하지 않습니다.

## 후보 분류

풀의 모든 후보에 대해(`open-sse/services/autoCombo/virtualFactory.ts::buildPreparedPool`,
`filterPaidOnlyCandidates` 직후) 다음을 적용합니다.

1. **`FREE_MODEL_BUDGETS`에 전혀 없음** → 제외됩니다. 여기에는 실제 유료 모델과 OmniRoute가
   아직 분류하지 않은 모든 제공업체/모델이 포함됩니다. 즉, 새 후보는 포함된 상태가 아니라 제외된 상태로 시작합니다.
2. **`freeType: "keyless"`** → 즉시 통과하지만, **실제로 인증 없는 경로를 통해 들어온
   후보에만** 적용됩니다(`connectionId === SYNTHETIC_NOAUTH_CONNECTION_ID`,
   `open-sse/services/autoCombo/resilienceCandidateFilter.ts`). 해당 후보에는 자격 증명이
   존재하지 않으므로, 그 후보에 대한 요청에 요금이 청구될 가능성이 전혀 없습니다. 따라서 런타임 검사는
   필요하지도 않고 가능하지도 않습니다. 카탈로그상 동일한 `keyless` 제공업체/모델이라도 **실제** DB
   연결을 통해 접근한 경우(`connectionId`가 실제 연결 ID이거나 후보가
   `allowedConnectionIds`를 포함하는 경우)에는 이 단축 경로를 적용하지 않습니다. `keyless` 메타데이터는
   제공업체 전반이 아니라 인증 없는 경로만을 구체적으로 설명하며, 실제 자격 증명이 있는 계정의 사용을
   허용하지 않습니다. 이러한 후보는 다른 후보와 마찬가지로 검사 3으로 넘어가며, 카탈로그 항목에
   `hardStopGuaranteed: true`가 별도로 지정되어 있지 않으면 제외됩니다(실제
   `keyless` 항목에는 절대 지정되지 않습니다. 이 단축 경로가 안전성을 확보할 수 있는 유일한 방법이기 때문입니다).
3. **그 밖의 모든 `freeType`**(`recurring-daily`, `recurring-monthly`, `recurring-credit`,
   `recurring-uncapped`, `one-time-initial` 및 이 모듈에서 별도로 처리하지 않는 향후의 모든 유형) → 다음
   조건을 **모두** 충족하는 경우에만 통과합니다.
   - 카탈로그 항목에 `hardStopGuaranteed: true`가 설정되어 있어야 합니다(`FreeModelBudget.hardStopGuaranteed`,
     `open-sse/config/freeModelCatalog.ts`). 이는 제공업체가 직접 공개한 약관(예: 명시적인
     "신용 카드 필요 없음" 문구)에 관한 **선별되어 수동으로 설정된 정보**이며, `freeType`이나 라이브 API
     응답으로부터 유추해서는 안 됩니다. 미설정(`undefined`)과 `false`는 모두 "보장되지 않음"으로
     처리됩니다.
   - `USAGE_FETCHER_PROVIDERS`에 해당 제공업체의 사용량 어댑터가 있어야 합니다
     (`open-sse/services/usage.ts`). 이는 할당량 대시보드와 `getUsageForProvider()`를 이미
     지원하는 동일한 레지스트리입니다. 어댑터가 없으면 어댑터가 추가될 때까지 계속 제외됩니다.
   - **실제로 평가 중인 특정 연결**에 대한 캐시된 실시간 `FreeAccessState`가
     `status: "SAFE"`여야 하며, `settings.autoRefreshProviderQuotaInterval` 이내에
     확인된 상태여야 하고(기본값 180s — 새로운 값이 아니라 기존 설정), 보고된
     `remainingFreeAllowance`가 작은 안전 여유분보다 커야 합니다.
4. **`freeType: "discontinued"`** → 항상 제외됩니다.

## 연결 안전성(후보별이 아닌 연결별 검증)

자동 조합 풀의 후보가 항상 하나의 연결에만 묶여 있는 것은 아닙니다. "논리적" 후보
(`connectionId: null`)에는 `allowedConnectionIds` 허용 목록이 포함됩니다. 이 목록에는
요청을 처리할 수 있는 하나 이상의 실제 제공자 연결/계정이 있으며, 실제로 사용할 계정은
나중에 디스패치 시점에 `open-sse/services/combo/autoStrategy.ts`에서 결정됩니다
(`allowedConnectionIds`를 자체 연결 선택 로직과 교차 확인, 약 315~331행).

STRICT_ZERO_COST는 해당 허용 목록에 있는 **각 연결의 무료 액세스 상태를 개별적으로**
검증하고(`strictZeroCostFilter.ts`의 `evaluateCandidateConnections()`),
`allowedConnectionIds`를 `SAFE`로 판정된 정확한 하위 집합으로 다시 작성합니다. 전체
원본 목록이나 임의로 선택한 단일 구성원으로 설정하지 않습니다. 구체적으로는 다음과 같습니다.

- 계정 A가 `SAFE`이고 계정 B가 `UNKNOWN`/소진됨/유료임 → A만 선택 가능한 상태로 남습니다.
- 모든 계정이 `UNKNOWN`임 → 안전한 집합이 비어 있으므로 후보가 완전히 제거됩니다.
- 단일 연결 후보(`connectionId`가 직접 설정되고 허용 목록이 없음)가 검증에 실패하면
  즉시 제거되며, 빈 `allowedConnectionIds`와 함께 반환되지 않습니다.

`autoStrategy.ts`는 디스패치할 연결을 선택하기 전에 이미 `allowedConnectionIds`를 엄격한
허용 목록으로 적용하므로, 이를 검증된 `SAFE` 하위 집합으로 다시 작성하는 것만으로도
디스패치 시 실제로 사용되는 연결이 항상 이 필터 자체에서 검증한 연결임을 보장할 수
있습니다. 즉, 같은 후보에 속한 검증되지 않은 다른 계정이 사용되는 일은 없습니다.
회귀 검증(keyless-bypass 사례 A/B/C 및 다중 계정 사례 1~5)은
`tests/unit/autoCombo/strict-zero-cost-connection-safety.test.ts`를 참조하세요.

`자동 검색됨`: 올바른 메타데이터를 갖춘 제공자/모델(카탈로그에 있으며, 사용량 어댑터가
있고, `hardStopGuaranteed: true`임)이 내일 출시되더라도 OmniRoute가 이를 인식하는 즉시
사용할 수 있습니다. 코드 변경, 허용 목록 항목 추가, 이 모듈의 편집이 전혀 필요하지
않습니다. 카탈로그에서 제거된 항목도 같은 방식으로 사라집니다. 회귀 검증은
`tests/unit/autoCombo/strict-zero-cost-autodiscovery.test.ts`를 참조하세요
(실제 카탈로그를 변경하지 않고 주입 가능한 픽스처를 통해 검증).

## 할당량 캐싱(`open-sse/services/autoCombo/freeAccessQuota.ts`)

`getUsageForProvider()`를 재사용하며, 별도의 두 번째 할당량 시스템은 없습니다. 짧은
인메모리 프로세스 수명 캐시가 그 앞에 위치합니다(TTL은 기본
`autoRefreshProviderQuotaInterval`과 동일). 따라서 Telegram 규모의 요청 속도에서도
요청마다 각 후보에 대해 실시간 결제 API 호출이 발생하지 않습니다. 읽기는 동기식입니다.
캐시 미스는 `undefined`를 반환하고(→ 제외, 장애 시 차단) _다음_ 읽기를 위한 백그라운드
새로 고침을 시작합니다. 후보 풀을 구축하는 경로에서는 네트워크 호출을 기다리는 일이
전혀 없습니다.

어떤 이유로든 연결에 실패하는 즉시
`src/sse/services/auth.ts::markAccountUnavailable()`에서
`invalidateFreeAccessState(provider, connectionId)`가 호출됩니다. 따라서 바로 다음 풀
구축에서는 오래된 `SAFE` 항목 대신 정상적인 캐시 미스를 읽습니다. 즉,
402/403/할당량 소진 응답 이후 TTL이 만료될 때까지 기다릴 필요가 없습니다.

## ToS 가드(경제적 안전성과는 독립적)

`excludeTosAvoid`(기본값 `false`)는 선별된 `tos` 판정
(`FreeModelBudget.tos`)이 `"avoid"`인 모든 후보를 제외합니다. 이는 `hidePaidModels`의 관련 문서
(`docs/reference/FREE_TIERS.md`)에서 이미 채우고 있는 동일한 필드를 재사용합니다.
`freeAccessPolicy`와는 의도적으로 분리되어 있습니다. 후보가 경제적으로 `SAFE`하더라도 계약상의
이유로 여기서 제외될 수 있으며, 반대로 이 가드가 꺼져 있으면 `freeAccessPolicy: "strict"`가
활성화되어 있어도 후보가 유지될 수 있습니다.

## 가드가 제외하는 항목 확인하기

`GET /v1/auto-combo/{channel}/candidates`는 이 가드로 인해 디스패치에서 제외될 후보를 포함하여
모든 후보를 나열하며, 각 후보에는 `freeAccessExclusion`이 포함됩니다. 가드 조건을 충족하면
`null`이고, 그렇지 않으면 제외 사유가 들어갑니다. 이 목록은 상태만 보고하며 정책을 적용하지는
않습니다. 정책을 끄면 모든 항목에서 이 필드가 `null`이 되며 비용은 발생하지 않습니다.

| `freeAccessExclusion`  | 의미                                                                                                               | 조치 방법                                                                                                                  |
| :--------------------- | :----------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------- |
| `not-in-catalog`       | 제공자/모델 쌍이 `FREE_MODEL_BUDGETS`에 없습니다.                                                                  | 선별된 항목을 추가하거나, 새로운 쌍은 처음부터 제외된다는 점을 받아들이세요. 이는 의도된 설계입니다.                       |
| `regime-not-free`      | 카탈로그에는 있지만, 해당 `freeType`이 무료 액세스를 제공하는 유형이 아닙니다(예: 중단된 티어).                    | 수정할 사항이 없습니다. 이 모델은 비용이 발생합니다.                                                                       |
| `no-hard-stop`         | 무료 체계이지만 `hardStopGuaranteed`가 `true`가 아니므로, 허용량 초과 시 별도 알림 없이 과금이 시작될 수 있습니다. | 제공자의 약관을 확인하고 출처를 주석에 명시하여 플래그를 설정하세요. 카탈로그를 늘리기 위한 목적으로 설정해서는 안 됩니다. |
| `contradictory-noauth` | 인증이 필요 없는 후보의 카탈로그 항목이 `keyless`가 아닙니다. 메타데이터가 일관되지 않으므로 실패 시 차단합니다.   | 카탈로그 항목을 수정하세요. 두 정보가 서로 일치하지 않습니다.                                                              |
| `exhausted`            | 최신 조회 결과 허용량을 모두 소진했습니다.                                                                         | 재설정될 때까지 기다리세요. 이 문제는 저절로 해결됩니다.                                                                   |
| `state-unknown`        | 할당량 조회 결과가 없거나, 신뢰하기에는 너무 오래되었습니다.                                                       | 확인이 필요합니다. 제공자에 등록된 사용량 어댑터가 없거나 할당량 조회가 실패하고 있을 수 있습니다.                         |
| `no-connection`        | 후보에 확인할 계정이 전혀 없습니다.                                                                                | 할당량 문제가 아닙니다. 후보가 연결 없이 생성되었으므로 아무것도 조회되지 않았습니다. 풀이 어떻게 구성되었는지 확인하세요. |

마지막 두 항목은 구분할 가치가 있습니다. 소진된 허용량은 저절로 재설정되지만, 조회 결과가 아예
도착하지 않는다면 조회 자체가 고장 난 것입니다. 지금까지는 외부에서 볼 때 두 경우가 동일하게
보였습니다. 즉, 후보가 단순히 사라졌습니다.

**한 가지 공백이 남아 있으며, 이는 의도된 것입니다.** `excludeTosAvoid`는 여전히 목록이
생성되기 전에 후보를 제거하므로, `tos: "avoid"`로 선별된 모델은 사유 없이 누락됩니다. 이는
이 섹션에서 방금 해소한 제로 비용 가드의 비가시성과 동일합니다. 이 문제까지 해소하려면 ToS
제외가 무엇을 보고해야 하는지 결정해야 하며, 이는 경제적 안전성과는 별개의 문제입니다. 이
페이지에서는 그런 공백이 없는 척하지 않고 명시적으로 밝힙니다.

오프라인에서 변경 전후를 비교하려면 `npx tsx scripts/ad-hoc/dry-run-strict-zero-cost.ts`를
실행 중인 인스턴스의 후보 출력에 대해 여전히 사용할 수 있습니다. 이 스크립트는 각 후보의 실제
`connectionId`를 읽으므로 연결 안전성 경로도 함께 검증합니다. 키 없는 후보는 실제 연결이 아닌
합성된 무인증 `connectionId`를 사용해 전달되어야 합니다. 현재 기본 제공되는 키 없는 자동 경로는
OpenCode Free입니다. 정확한 후보 수는 여전히 실시간 모델 검색 결과에 따라 달라지므로, 이전 실행
결과를 복사하지 말고 대상 배포 환경에서 측정해야 합니다. `recurring-*` 후보는 등록된 사용량
어댑터와 `hardStopGuaranteed: true`를 모두 갖춘 경우에만 통과합니다. 불완전한 메타데이터는
계속해서 실패 시 차단됩니다.

`excludeTosAvoid: true`이면 `tos: "avoid"`로 선별된 모든 후보가 제거됩니다. 현재 OpenCode Free에는
이 판정이 지정되어 있으므로, 가드를 활성화하면 배포 환경에 남아 있는 키 없는 풀이 비게 될 수
있습니다. 이는 버그가 아니라 ToS 가드를 활성화할 때 예상되는 절충입니다. 바로 이러한 이유로
가드의 기본값은 `false`입니다(위의 "ToS 가드" 참조).

## 활성화

```json
PUT /api/settings
{ "freeAccessPolicy": "strict", "excludeTosAvoid": false }
```

두 신규 설정은 모두 기능 도입 이전의 값(`"off"` / `false`)을 기본값으로 사용하므로, 어느 것도 활성화하지 않으면
기존 `auto/*` 라우팅 동작은 변경되지 않습니다.
