IDE 세션 없이 OmniRoute 뒤에 Cursor를 연결하는 두 가지 방법:

1. **`cursor-api` 프로바이더**(카드 "Cursor API", 별칭 `cua`): Cursor 사용자 API 키(`crsr_…`, `https://cursor.com/dashboard/api`에서 생성)를 보관하는 API 키 프로바이더입니다. 그러면 모든 OmniRoute 클라이언트가 일반적인 할당량, 폴백 및 로깅 계층을 거쳐 `/v1/chat/completions`를 통해 `cursor-api/<model>` 또는 `cua/<model>`로 Cursor 모델에 접근할 수 있습니다. IDE 프로바이더(`cursor`, OAuth/IDE 세션)는 변경되지 않습니다.
2. **Cursor CLI 패스스루**: Cursor CLI(`agent`)가 OmniRoute를 가리키도록 설정하면 CLI가 수행하는 모든 RPC가 OmniRoute API 키로 인증되고, `cursor-api` 연결의 자격 증명을 사용해 Cursor로 전달되며, Logs 페이지에 기록됩니다.

## 키를 교환하는 이유

`api2.cursor.sh`는 원본 `crsr_…` 키를 Bearer 토큰으로 사용하면 거부합니다(401). Cursor CLI는 먼저 키를 `/auth/exchange_user_api_key`에 POST하고 1시간 후 만료되는 세션 JWT를 받습니다. 반환된 `refreshToken`에도 동일한 `exp`가 있으므로 갱신하려면 키를 다시 교환해야 합니다.
`open-sse/services/cursorApiKeyAuth.ts`는 이 교환을 수행하고 키마다 하나의 세션 토큰을 캐시하며, 만료 5분 전에 다시 교환하고 Cursor가 401로 응답하면 캐시된 토큰을 삭제합니다. `CursorExecutor`는 `cursor-api` 연결을 위한 업스트림 스트림을 열기 직전에 이를 호출합니다.

## `cursor-api` 프로바이더

레지스트리: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, `cursor`와 동일한 `format`, `baseUrl` 및
`models`). 카탈로그 카드:
`src/shared/constants/providers/apikey/specialty-media.ts`. 실행기 맵:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

대시보드: Providers → Cursor API → Add API key.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

그런 다음:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

참고:

- `cursor-api`의 모델 목록은 정적 Cursor 레지스트리(IDE 프로바이더가 폴백하는 것과 동일한 목록)에서 가져오므로 OmniRoute 호스트에 `cursor-agent`를 설치할 필요가 없습니다.
- `POST /api/providers/{id}/refresh-cursor`는 `cursor` IDE 프로바이더 전용입니다. `cursor-api` 연결에는 갱신할 IDE 세션이 없습니다.

## Cursor CLI 패스스루

라우트: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. 핸들러가 자체 인증을 적용하므로 접두사 `/api/cursor-cli/`는
`src/shared/constants/publicApiRoutes.ts`에 등록되어 있습니다.

| 경로                                                                                                                      | CLI에서 요구되는 인증        | OmniRoute의 동작                                                                                                                              |
| ------------------------------------------------------------------------------------------------------------------------- | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                        | `Bearer <OmniRoute API key>` | 키를 검증하고 `JWT_SECRET`으로 서명한 1시간 유효 HS256 JWT를 발급하여 반환합니다                                                              |
| 기타 모든 경로(`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`          | 발급자/대상/만료를 검증하고 활성 `cursor-api` 연결을 선택한 뒤, Authorization 헤더를 교환된 Cursor 토큰으로 바꾸고 응답을 다시 스트리밍합니다 |

CLI는 수신하는 모든 토큰에서 `exp`를 디코딩하므로 불투명 토큰을 전달하면 거의 모든 요청 전에 다시 교환합니다. 발급된 JWT는 이를 방지합니다. OmniRoute에서 401을 반환하면 CLI가 다시 교환합니다.

### 설정

1. OmniRoute API 키(Dashboard → API keys)와 `cursor-api` 연결을 생성합니다.
2. CLI가 에이전트 스트림에 HTTP/1.1을 사용하도록 지정합니다.
   `~/.cursor/cli-config.json`에서:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   이 설정이 없으면 CLI가 별도로 구성된 에이전트 호스트에 HTTP/2로 에이전트 턴을 열고, 컨트롤 플레인 RPC만 엔드포인트를 통과합니다.

3. OmniRoute를 대상으로 CLI를 실행합니다.

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

각 홉은 프로바이더 `cursor-api`, 요청 유형 `cursor-cli`, 경로 `/api/cursor-cli/<rpc>`로 Logs에 기록되며, OmniRoute API 키와 요청을 처리한 연결에 귀속됩니다.

### 실패 모드

| 상황                                               | CLI에 대한 응답                         |
| -------------------------------------------------- | --------------------------------------- |
| 알 수 없는 OmniRoute 키 및 `REQUIRE_API_KEY=true`  | 교환 시 401 `unauthenticated`           |
| `REQUIRE_API_KEY=false`                            | 익명 세션(`/v1/*` 동작과 동일)          |
| 만료되었거나 외부에서 발급되었거나 변조된 세션 JWT | 401, CLI가 다시 교환 수행               |
| 교환 후 OmniRoute API 키가 취소됨                  | 다음 RPC에서 401                        |
| 활성 `cursor-api` 연결 없음                        | 503 `unavailable`                       |
| Cursor가 연결 키를 거부함                          | 401 `unauthenticated`, 캐시된 세션 삭제 |
| 업스트림에 연결할 수 없음                          | 502 `unavailable`(정제된 메시지)        |
| `JWT_SECRET` 미설정                                | 교환 시 503                             |
