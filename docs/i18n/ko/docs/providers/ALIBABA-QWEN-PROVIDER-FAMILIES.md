이 문서는 [Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854)에 대한 구현 결정을 기록합니다. 공개 제품은 네 가지 공급자 제품군으로 표시됩니다. 리전은 연결 데이터이며 별도의 제품이 아닙니다.

## 결정

| 공급자 제품군                      | OmniRoute ID            | 글로벌 리전 | 중국 리전 |
| ---------------------------------- | ----------------------- | ----------- | --------- |
| Alibaba Cloud Model Studio(종량제) | `alibaba`               | 싱가포르    | 베이징    |
| Alibaba Cloud Token Plan           | `bailian-coding-plan`   | 싱가포르    | 베이징    |
| Qwen Cloud(종량제)                 | `qwen-cloud`            | 글로벌      | 베이징    |
| Qwen Cloud Token Plan              | `qwen-cloud-token-plan` | 싱가포르    | 베이징    |

기존 `alibaba-cn` ID는 저장된 연결, 모델 라우트, 콤보 및 과거 사용량을 위한 런타임 호환성 별칭으로 유지됩니다. 해당 대시보드 카드는 `alibaba`에 통합되며, 데이터베이스를 다시 작성할 필요는 없습니다.

Qwen Cloud 종량제와 Alibaba Cloud Model Studio는 현재 DashScope 호환 런타임 호스트를 공유하지만, 사용자가 서로 다른 제품 인터페이스를 통해 키를 발급받고 계정을 관리하므로 별도의 공급자 ID로 유지됩니다. Alibaba 및 Qwen Cloud Token Plan 제품은 서로 다른 엔드포인트 제품군을 사용하므로 네 제품 모두 별도의 공급자 ID로 유지됩니다.

## 엔드포인트 매트릭스

| 공급자 제품군           | `global-sg`                                                              | `china-beijing`                                                      | 통신 형식 |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | --------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI    |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI    |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI    |

API 키와 엔드포인트는 동일한 제품 및 리전에 속해야 합니다. 리전을 선택하면 검증 및 일반 요청에서 사용하는 사전 설정 엔드포인트가 변경됩니다.

## 연결 계약

새 연결은 안정적인 리전 키를 `providerSpecificData`에 저장합니다.

```json
{
  "region": "global-sg"
}
```

허용되는 값은 `global-sg`와 `china-beijing`입니다. 엔드포인트는 공급자 ID와 리전을 기반으로 중앙에서 파생됩니다. 사전 설정이 아닌 `providerSpecificData.baseUrl`은 명시적인 운영자 재정의로 유지되며 우선 적용됩니다. 반면 이전에 저장된 사전 설정 URL은 다시 리전 매트릭스에 맞게 정규화됩니다.

이렇게 하면 연결 스키마의 확장성을 유지할 수 있습니다. 즉, 다른 공급자 카드를 만들거나 저장된 공급자 ID를 변경하지 않고도 리졸버에 다른 리전을 추가할 수 있습니다.

## 호환성 및 롤아웃

1. 리전별 엔드포인트 리졸버를 추가하고 현재의 글로벌 기본값을 유지합니다.
2. `alibaba`, 호환 ID인 `alibaba-cn`, `qwen-cloud`에 대해 리전별 DashScope `/models` 실시간 검색을 사용합니다. 범용 엔드포인트는 이미지, 비디오, 오디오, 임베딩 및 기타 비채팅 모델도 반환하므로, 해당 응답에는 먼저 텍스트 생성 필터 하나를 적용합니다. 그런 다음 `qwen-cloud`는 공급자 레지스트리에 선언된 관리형 허용 목록을 적용합니다. Alibaba Model Studio와 Qwen Cloud는 현재 런타임 호스트를 공유하더라도 별도의 선별된 카탈로그를 유지합니다.
3. 현재 Token Plan 텍스트 모델 허용 목록으로 `qwen-cloud-token-plan`을 등록합니다.
4. 연결 추가/편집 대화 상자에 형식이 지정된 리전 선택기를 추가합니다.
5. 중복된 `alibaba-cn` 카드를 숨기고 기존 연결을 `alibaba` 공급자 페이지에 포함합니다.
6. 고급 및 워크스페이스별 배포를 위해 사용자 지정 엔드포인트 재정의를 계속 사용할 수 있도록 유지합니다.

Token Plan 미디어 모델은 전용 엔드포인트를 사용하므로 채팅 카탈로그에 포함되지 않습니다.
`wan2.7-image`와 `wan2.7-image-pro`는 `open-sse/config/imageRegistry.ts`에 등록되어 있으며,
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`는
`open-sse/config/videoRegistry.ts`에 등록되어 있습니다. 두 레지스트리 모두 `qwen-cloud-token-plan` 연결
ID와 해당 리전별 자격 증명을 재사용합니다.

일반 Qwen Cloud에는 `qwen-cloud` ID 아래에 별도의 종량제 이미지 및 비디오 카탈로그가 있습니다.
이미지 모델은 `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03`, `z-image-turbo`입니다. 비디오
모델은 `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12`,
`wan2.7-videoedit`입니다. 이러한 모델은 일반 `qwen-cloud` 연결과 리전별 DashScope 미디어
엔드포인트만 재사용합니다. Token Plan과 종량제 레지스트리는 서로의 모델 목록을 상속하거나 병합하지
않습니다.

`bailian-coding-plan` ID에도 자체 미디어 허용 목록이 있습니다. 이미지 생성용 모델은
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0`, `qwen-image-2.0-pro`이며,
비디오 생성용 모델은
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`입니다.
이 ID는 Bailian Coding Plan 연결과 리전별 Coding Plan 엔드포인트만 사용합니다.
해당 이미지 및 비디오 레지스트리는 어느 Qwen Cloud 공급자로부터도 상속받거나 병합되지 않습니다.

일반 `alibaba` ID에는 별도의 이미지 및 비디오 허용 목록이 있습니다. 이미지 모델은
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo`, `wan2.6-t2i`입니다. 추가된 비디오 모델은 `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12`, `wan2.7-videoedit`입니다. 이러한 모델은 Alibaba Model Studio
연결과 선택된 리전별 미디어 엔드포인트만 사용하며, Coding Plan 또는 Qwen Cloud
레지스트리에는 추가되지 않습니다.

Qwen Cloud Token Plan 채팅 카탈로그는 Individual 플랜의 정확한 문자열 일치 방식의 텍스트 허용 목록을 따릅니다.
해당 목록은 `qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2`,
`deepseek-v4-pro`입니다. Wan 및 HappyHorse 항목은 별도의 이미지/비디오 생성 API에 속합니다.

Alibaba Token Plan은 Anthropic 호환 엔드포인트를 통해 동일한 최신 텍스트 생성 모델 ID 6개를
제공합니다. Singapore 옵션은 기존 `global-sg` 리전 키를 저장하며, 리전을 Global이라고 부르는
공급자 계열과 사용자에게 표시되는 레이블만 다릅니다.

일반 Qwen Cloud 채팅 카탈로그는 의도적으로 전체 실시간 텍스트 응답보다 범위가 좁습니다. 관리되는
허용 목록은 `open-sse/config/providers/registry/qwen-cloud/index.ts`에 있으며, 실시간
검색은 업스트림 응답과 해당 레지스트리 목록 모두에 존재하는 ID만 반환합니다.

Alibaba Model Studio도 `open-sse/config/providers/registry/alibaba/index.ts`에서 독립적으로
관리되는 허용 목록을 사용하여 동일한 실시간 교집합 규칙을 따릅니다. `alibaba-cn` 호환
공급자는 베이징 엔드포인트를 대상으로 검색을 수행하면서 해당 카탈로그를 재사용합니다.
