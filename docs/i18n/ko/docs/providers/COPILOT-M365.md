`copilot-m365-web`(별칭 `m365copilot`)는 인증된 Microsoft 365 Copilot BizChat 브라우저 세션을 통해 `m365.cloud.microsoft/chat`으로 OpenAI 형식의 채팅 요청을 전송합니다. 이는 비공식 통합입니다.

> **웹 쿠키 공급자를 처음 사용하시나요?**
>
> 이 공급자별 가이드를 따르기 전에 일반적인 설정 절차, 인증 지침, 제한 사항 및 문제 해결 방법은 **`docs/getting-started/WEB-COOKIE-GUIDE.md`**를 참조하세요.
>
> **중요:** 이 공급자의 자격 증명은 **쿠키가 아닙니다**. `m365.cloud.microsoft`에서 쿠키를 복사하지 마세요. 자격 증명은 WebSocket URL 쿼리 매개변수와 경로 세그먼트이며, 둘 다 DevTools의 Network 탭에서 확인할 수 있습니다.

## 사전 요구 사항

- `m365.cloud.microsoft/chat`에서 BizChat에 액세스할 수 있는 Microsoft 365 계정
- DevTools에서 WebSocket을 검사하기 위한 Chromium 기반 브라우저(Chrome, Edge)
- M365 Copilot 라이선스(많은 Microsoft 365 Business/Enterprise 플랜에 포함됨)

## 자격 증명 캡처(WebSocket 방식)

1. `https://m365.cloud.microsoft/chat`에 로그인하고 대화를 시작합니다.
2. **DevTools → Network**를 엽니다.
3. **WS**(WebSocket)로 필터링합니다.
4. Chathub WebSocket 연결을 클릭합니다. `wss://substrate.office.com/m365Copilot/Chathub/`로 시작하는 URL을 찾습니다.
5. 해당 **Request URL**에서 다음을 복사합니다.
   - `access_token` 쿼리 매개변수 값(수명이 짧은 JWT)
   - `/Chathub/` 뒤의 Chathub 경로 세그먼트(예: `<oid>@<tenant>`)

전체 URL의 형식은 다음과 같습니다.

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute에서 **Providers → Add Provider**로 이동하여 **Microsoft 365 Copilot
   (BizChat)**을 선택한 후, 다음 형식으로 자격 증명을 붙여 넣습니다.

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. **Test Connection**을 클릭한 다음 **Save**를 클릭합니다.

## 자격 증명 캡처(HAR 가져오기)

WebSocket URL에서 값을 수동으로 복사하는 대신 DevTools HAR 파일을 내보낼 수 있습니다.

1. **DevTools → Network**를 엽니다.
2. BizChat 대화를 시작하거나 계속합니다(이렇게 하면 WebSocket 연결이 트리거됩니다).
3. Network 패널을 마우스 오른쪽 버튼으로 클릭하고 **Save all as HAR with content**를 선택합니다.
4. OmniRoute의 공급자 연결 대화 상자에서 **Import .har file** 버튼을 사용합니다.

OmniRoute는 HAR에서 Chathub WebSocket URL을 검색하고 `access_token`과 `chathubPath`를 추출한 후 자격 증명 필드를 자동으로 채웁니다. HAR 가져오기는 JWT 만료 시간을 디코딩하여 남은 토큰 수명을 표시합니다.

> **실제 HAR 내보내기 파일, 액세스 토큰 또는 새로 고침 토큰을 절대로 커밋하지 마세요.** 테스트 및 문서 값에는 항상 자리 표시자를 사용해야 합니다.

## 토큰 수명 및 새로 고침

`access_token`은 수명이 짧습니다(일반적으로 **약 75분**). 만료되면 공급자가 연결 오류를 보고하며 자격 증명을 다시 캡처해야 합니다.

### `refreshToken`을 사용한 자동 새로 고침

수동으로 다시 캡처하지 않으려면 연결의 **Advanced Settings → providerSpecificData**에 Microsoft 새로 고침 토큰을 저장할 수 있습니다.

| 필드           | 설명                                                                     |
| -------------- | ------------------------------------------------------------------------ |
| `refreshToken` | `substrate.office.com/sydney` 범위에 대한 Microsoft OAuth 새로 고침 토큰 |
| `tier`         | `individual`(기본값), `edu` 또는 `enterprise`                            |

`substrate.office.com/sydney` 범위로 설정된 Microsoft 디바이스 코드 또는 인증 코드 흐름에서 새로 고침 토큰을 가져옵니다. `refreshToken`이 설정되어 있으면 OmniRoute가 각 요청 전에 `access_token`을 미리 새로 고치므로 약 75분마다 만료된 후 다시 캡처할 필요가 없습니다.

`refreshToken`이 설정되어 있지 않으면 만료될 때마다 WebSocket 자격 증명을 수동으로 다시 캡처해야 합니다.

### 계층 선택

| 계층         | 별칭       | 서비스                |
| ------------ | ---------- | --------------------- |
| `individual` | _(기본값)_ | 소비자용 M365 Copilot |
| `edu`        | `included` | 교육용 M365 Copilot   |
| `enterprise` | `work`     | 업무용 M365 Copilot   |

**Advanced Settings → providerSpecificData → tier**에서 계층을 설정합니다. 계층은 BizChat 라우팅 및 모델 액세스에 영향을 줍니다.

## 보안 모델

- **비공식 통합.** 이 공급자는 BizChat WebSocket 프로토콜을 리버스 엔지니어링하여 사용합니다. Microsoft가 엔드포인트를 변경하면 사전 공지 없이 작동이 중단될 수 있습니다.
- `subscriptionRisk: true` 플래그는 이 통합이 문서화되지 않은 엔드포인트에 의존한다는 사실을 나타냅니다. 계정이 제한될 가능성이 있지만 확인된 바는 없습니다.
- 액세스 토큰은 수명이 짧은 JWT입니다. 비밀번호처럼 취급하여 커밋하거나, 로그에 기록하거나, 공유하지 마세요.
- 리프레시 토큰은 BizChat 서비스에 대한 장기 액세스 권한을 부여합니다. API 키와 동일한 수준으로 안전하게 보관하세요.

## 문제 해결

### 인증이 즉시 실패하는 경우

- XHR/Fetch 요청이 아니라 **WebSocket URL**에서 복사했는지 확인하세요. 자격 증명은 `Authorization: Bearer` 헤더가 아니라 Chathub WebSocket 연결의 `access_token` 쿼리 매개변수에 있습니다.
- `chathubPath`에 URL 경로의 전체 `<oid>@<tenant>` 세그먼트가 포함되어 있는지 확인하세요.

### 토큰이 약 75분 후 만료되는 경우

이는 정상적인 동작입니다. `refreshToken`이 없으면 액세스 토큰의 수명이 짧습니다. 다음 중 하나를 수행하세요.

- DevTools에서 자격 증명을 다시 캡처하거나
- 자동 갱신을 위해 고급 설정에서 `refreshToken`을 구성하세요.

### 연결 테스트는 통과하지만 채팅에서 401이 반환되는 경우

검증과 첫 번째 요청 사이에 토큰이 만료되었을 수 있습니다. 새로운 자격 증명을 다시 캡처하세요.

### 공급자 목록에 Copilot이 표시되지 않는 경우

**대시보드 → 공급자**에서 `copilot-m365-web`이 활성화되어 있는지 확인하세요. 일부 티어에서는 이 공급자가 기본적으로 숨겨져 있을 수 있습니다.
