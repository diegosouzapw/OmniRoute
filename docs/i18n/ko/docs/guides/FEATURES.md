## ✨ v3.8.0 주요 변경 사항

v3.7.x → v3.8.0 주기에는 설정이 필요 없는 자동 라우팅, 새로운 제공자, OAuth 흐름, 한층 강화된 복원력, 더욱 풍부해진 CLI 경험이 추가되었습니다. 주요 기능은 아래와 같습니다. 전체 세부 정보는 이 문서의 뒷부분과 링크된 사양을 참조하세요.

- 🤖 **Auto Combo / 설정이 필요 없는 자동 라우팅** — `auto/coding`, `auto/fast`, `auto/cheap`, `auto/offline`, `auto/smart`, `auto/lkgp`, `auto/chaos` 접두사를 사용할 수 있습니다. 16가지 요소의 점수 산정 엔진과 엄선된 6개의 **모드 팩**(ship-fast, cost-saver, quality-first, offline-friendly, reliability-first, chaos-mode)을 기반으로 합니다.
- 🆕 **Command Code 제공자** (#2199) — 모델 카탈로그 및 할당량 추적을 포함한 일급 등록 기능
- 🆕 **Z.AI 제공자** — 할당량 레이블을 제공하는 새로운 무료 티어 제공자
- 🎬 **KIE 미디어 확장** — 동영상 생성 모델을 포함하도록 카탈로그 확장
- 🔐 **Devin 인증** — Desktop은 기존 Devin API 키를 가져오며, CLI는 로컬 `devin auth login` 자격 증명을 사용
- 🆓 **새로운 무료 제공자 8개** — LLM7, Lepton, UncloseAI, BazaarLink, Completions, Enally, FreeTheAi, Command Code
- 🎯 **매니페스트 인식 티어 라우팅 W1–W4** — 제공자 매니페스트를 기반으로 가중치가 적용된 티어 선택
- 🎨 **Cursor의 완전한 OpenAI 호환성** — 도구 호출, 스트리밍, 세션 관리를 엔드투엔드로 지원
- 📊 **Cursor Pro 플랜 사용량** — 제공자 한도 대시보드에 할당량 및 주기 데이터 표시
- ⚡ **서비스 티어 분석 / Codex 고속 티어 분석** — 티어별 사용량 가시성 제공
- 📌 **세션별 고정 라우팅** — Codex 세션이 턴 사이에도 동일한 계정에 고정됨
- 🔊 **Inworld TTS 개선** — 음성 카탈로그, 스트리밍 및 지연 시간 개선
- 🔑 **Kiro 헤드리스 인증** — 브라우저 없이 로컬 `kiro-cli` SQLite 저장소를 통해 로그인
- 📉 **DeepSeek 할당량 및 한도 모니터링** — 대시보드에서 일별/월별 사용량 제공
- 🔄 **재설정 인식 라우팅 전략** — 이제 콤보는 할당량 기간이 가장 빨리 재설정되는 계정을 우선 선택
- ⏱️ **`fallbackDelayMs`** 및 **동적 도구 한도 감지** — 더 세밀한 폴백 타이밍과 제공자별 도구 개수 한도
- 🔧 **백그라운드 모드 성능 저하 처리(Responses API)** — 업스트림이 백그라운드 폴링을 지원하지 않을 경우 구조화된 경고와 함께 동기 모드로 폴백

- 💻 **CLI 개선 기능 모음** — `omniroute providers`, `omniroute combos`, `omniroute doctor`, `omniroute setup`을 포함한 20개 이상의 명령어
- 🔍 **Qdrant 임베딩 모델 검색** — 자동 벡터 저장소 모델 탐색
- 🔑 **`manage` 범위가 지정된 API 키 / Bearer 키** — API를 통해 프로그래밍 방식으로 관리 작업 수행

- 🤝 **GitLab Duo OAuth 제공자** — GitLab 자격 증명으로 로그인

## 🔌 제공업체

AI 제공업체 연결을 관리합니다: OAuth 제공업체(Claude Code, Codex), API 키 제공업체(Groq, DeepSeek, OpenRouter), 무료 제공업체(Qoder, Kiro). Kiro 계정은 크레딧 잔액 추적을 지원하며, Dashboard → Usage에서 남은 크레딧, 총한도 및 갱신 날짜를 확인할 수 있습니다.

OpenRouter 연결은 Advanced Settings에서 연결별 `preset`을 저장할 수 있습니다. 설정된 경우, 클라이언트 요청에서 자체 `preset`을 이미 제공하지 않았다면 OmniRoute는 이를 OpenRouter의 최상위 요청 필드로 전송합니다. 예: `"preset": "email-copywriter"`.

## 🎨 콤보

19가지 공개 전략으로 모델 라우팅 콤보를 생성합니다: priority, weighted, round-robin, context-relay, fill-first, p2c(power-of-two choices), random, least-used, cost-optimized, reset-aware, reset-window, headroom, strict-random, auto, lkgp(last-known-good-provider), context-optimized, cache-optimized, **fusion**(여러 모델 패널에 병렬로 요청한 다음 심사 모델을 통해 하나의 답변으로 종합), **pipeline**. 각 콤보는 자동 폴백을 통해 여러 모델을 연결하며, 빠른 템플릿과 준비 상태 검사를 포함합니다.

최근 콤보 개선 사항:

- **구조화된 콤보 빌더** — 제공업체, 모델 및 정확한 계정/연결을 선택하여 각 단계를 생성
- **동일 제공업체 반복 지원** — `(provider, model, connection)` 튜플이 고유하다면 하나의 콤보에서 동일한 제공업체를 여러 번 재사용 가능
- **콤보 대상 상태** — 분석 및 상태 화면에서 모든 항목을 모델 문자열로 통합하지 않고 개별 콤보 대상/단계를 구분
- **복합 티어 순서** — 이제 `defaultTier -> fallbackTier`가 최상위 콤보 단계의 런타임 실행/폴백 순서에 영향을 줌
- **시스템 프롬프트 템플릿** — 콤보 `system_message`는 서버 측
  `{{MODEL_ID}}`, `{{PROVIDER_ID}}`, `{{ACCOUNT}}` 및 `{{FINGERPRINT}}`
  자리표시자를 지원하며, 디스패치 직전에 실제로 라우팅된 대상으로부터 확장됩니다.
  허용 목록 기반이며 재귀적으로 처리되지 않습니다. 알 수 없는 자리표시자는 리터럴 그대로 유지되고, 빈 값은
  빈 문자열로 확장되며, 클라이언트 시스템 프롬프트는 절대 다시 작성되지 않습니다. `{{FINGERPRINT}}`는
  고정되거나 자동 순환되는 핑거프린트를 사용하는 핑거프린트 기반 무료 제공업체에서만 해석되며,
  그 외의 경우(예:
  단일 핑거프린트 연결, 비-fp 제공업체)에는 빈 문자열로 확장됩니다. 확장은
  표준 디스패치 루프, round-robin 및 고정된 컨텍스트 캐시 세션에 적용됩니다.
  fusion, chaos, pipeline 및 nested-execute 전략은 아직
  자리표시자를 확장하지 않습니다.

## 🌐 V1 WebSocket 브리지 _(v3.6.6+)_

이제 OmniRoute는 `/v1/ws` 업그레이드 엔드포인트를 통해 **OpenAI 호환 WebSocket 클라이언트**를 지원합니다. 사용자 지정 `scripts/dev/v1-ws-bridge.mjs` 서버는 Next.js를 래핑하고 WS 연결을 완전한 양방향 스트리밍 세션으로 업그레이드합니다. 인증에는 HTTP 요청과 동일한 API 키 또는 세션 쿠키를 사용합니다.

- 세션 종료 또는 업스트림 오류 발생 시 스트림을 정상적으로 종료

## 🔑 동기화 토큰 및 구성 번들 _(v3.6.6+)_

- **`POST /api/sync/tokens`** — 새 동기화 토큰 발급(범위 지정, 선택적 만료 설정)

## 🛡️ 안전한 아웃바운드 가져오기 및 SSRF 방어 _(v3.6.6+)_

이제 모든 공급자 검증 및 모델 탐색 호출은 2계층 아웃바운드 방어를 거칩니다.

1. **URL 방어** (`src/shared/network/outboundUrlGuard.ts`) — 소켓이 열리기 전에 사설/루프백/링크 로컬 IP 범위를 차단합니다.
2. **안전한 가져오기 래퍼** (`src/shared/network/safeOutboundFetch.ts`) — URL 방어를 적용하고, 시간 제한을 정규화하며, 일시적 오류 발생 시 지수 백오프로 재시도합니다.

방어 정책 위반은 HTTP 422(`URL_GUARD_BLOCKED`)로 표시되며 `providerAudit.ts`를 통해 규정 준수 감사 로그에 기록됩니다.

---

## 🔄 쿨다운 인식 재시도 _(v3.6.6+)_

이제 업스트림 공급자가 모델 범위의 쿨다운을 반환하면 채팅 요청이 **자동으로 재시도**됩니다. `REQUEST_RETRY`(기본값: 2) 및 `MAX_RETRY_INTERVAL_SEC`(기본값: 30초)를 통해 구성할 수 있습니다. `x-ratelimit-reset-requests`, `x-ratelimit-reset-tokens`, `Retry-After` 전반에서 속도 제한 헤더 학습이 개선되었으며, 모델별 쿨다운 상태는 복원력 대시보드에서 확인할 수 있습니다.

---

## 📋 규정 준수 감사 v2 _(v3.6.6+)_

감사 로그가 커서 기반 페이지네이션, 요청 컨텍스트 보강(요청 ID, 사용자 에이전트, IP), 구조화된 인증 이벤트, 차이 컨텍스트가 포함된 공급자 CRUD 이벤트, SSRF 차단 검증 로깅을 지원하도록 확장되었습니다. 새 이벤트는 `src/lib/compliance/providerAudit.ts`에서 생성됩니다.
