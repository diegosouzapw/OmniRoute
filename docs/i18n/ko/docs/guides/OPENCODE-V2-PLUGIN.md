`@omniroute/opencode-plugin-v2`는 전체 OmniRoute 카탈로그(모델, 콤보 및
자동 콤보)를 표시 이름, 가격 및 무료 티어 예산과 함께 OpenCode v2의 모델 선택기에
추가합니다.

OpenCode v1과 v2는 서로 다른 계약을 통해 플러그인을 로드하므로, 이 패키지는
`@omniroute/opencode-plugin`과 별도의 패키지입니다. 사용 중인 OpenCode의 메이저 버전에
맞는 패키지를 선택하세요. 두 패키지 간에 공유되는 항목이 없으므로, 하나를 업그레이드해도
다른 하나를 강제로 업그레이드할 필요가 없습니다.

## 요구 사항

- OpenCode v2.
- 접근 가능한 OmniRoute 게이트웨이(기본값: `http://localhost:20128`).
- Node.js 22 또는 24.

## 설치

`opencode.json`에 플러그인을 추가합니다.

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

그러면 모델은 `omniroute/<provider>/<model>` 형식으로 표시됩니다. `providerId`는 해당
접두사와 OpenCode가 자격 증명을 저장하는 통합의 ID를 결정합니다.

## 자격 증명

플러그인은 다음 세 위치에서 순서대로 게이트웨이 키를 찾습니다.

1. **OpenCode에서 연결한 자격 증명.** 플러그인이 통합을 등록하므로 OpenCode 자체 인증
   흐름을 통해 키를 저장할 수 있습니다. `opencode.json`에는 아무것도 저장되지 않으므로
   이 방식을 권장합니다.
2. 프로젝트별 재정의를 위한 플러그인 옵션의 `apiKey`. 커밋할 수도 있는 파일에 키가
   저장됩니다.
3. 환경의 `OMNIROUTE_API_KEY`.

세 가지 모두 설정되지 않은 경우 카탈로그는 비어 있으며, 플러그인은 아무 설명 없이 빈
선택기만 표시하는 대신 시작 시 이를 한 번 알립니다.

### 관리 토큰은 별도의 키입니다

콤보, 제공자 상태 및 보강 정보(표시 이름, 가격, 무료 티어 예산)는 게이트웨이의
`/api/*` 엔드포인트에서 가져옵니다. 대부분의 배포 환경에서는 추론 키가 아닌
**관리** 토큰으로 이러한 엔드포인트를 보호합니다.

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<관리 읽기 토큰>"
}
```

`managementReadToken`을 설정하지 않으면 `apiKey`로 대체됩니다. 게이트웨이가 이 대체
키를 거부해도 카탈로그는 계속 게시되지만, 표시 이름 대신 원시 모델 ID가 표시되고,
정규 별칭 중복 제거, 가격 및 콤보는 제공되지 않습니다. 이런 상황이 발생하면 플러그인은
엔드포인트별로 한 번씩 경고하면서 해당 엔드포인트와 손실된 정보를 명시하므로, 기능이
축소된 선택기가 표시되는 이유를 언제나 알 수 있습니다.

## 옵션

| 키                               | 기본값                                       | 참고                                                                                     |
| -------------------------------- | -------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `providerId`                     | `"omniroute"`                                | 제공자 ID, 통합 ID 및 모델이 표시되는 접두사                                             |
| `baseURL`                        | 필수                                         | 게이트웨이 루트, `http(s)`만 지원하며 필요한 경우 `/v1` 접미사가 추가됨                  |
| `apiKey`                         | 연결된 자격 증명, 그다음 `OMNIROUTE_API_KEY` | `/v1/*`용 채팅 키                                                                        |
| `managementReadToken`            | `apiKey`로 대체                              | `/api/*`용 키 — 일반적으로 **동일한 키가 아님**                                          |
| `displayName`                    | `"OmniRoute"`                                | 선택기에 표시되는 제공자 이름                                                            |
| `timeoutMs`                      | `10000`                                      | 엔드포인트별 가져오기 시간 제한(자동 콤보는 5초 사용)                                    |
| `modelCacheTtlMs`                | `300000`                                     | 카탈로그 캐시 TTL. 디스크 스냅샷으로 콜드 스타트를 예열                                  |
| `timeouts`                       | `timeoutMs`로 대체                           | 엔드포인트별 시간 예산(ms): `models`, `combos`, `autoCombos`, `enrichment`               |
| `enrichment`                     | `true`                                       | 이름, 가격 및 무료 티어 예산 가져오기                                                    |
| `providerTag`                    | `true`                                       | 표시 이름 앞에 해당 이름이 라우팅되는 업스트림 제공자 표시                               |
| `usableOnly`                     | `false`                                      | 게이트웨이가 프로비저닝된 것으로 보고하는 제공자만 유지                                  |
| `visibleModels` / `hiddenModels` | `[]`                                         | 정확히 일치하거나 접미사가 일치하는 허용 목록. 거부 목록이 우선함                        |
| `geminiSanitization`             | `true`                                       | 도구 스키마에서 Gemini가 거부하는 JSON-Schema 키워드 제거 (`$ref` 도구는 수정 없이 전달) |
| `apiFormat.allowAnthropic`       | `false`                                      | 허용 목록에 포함된 ID를 Anthropic API 블록을 통해 라우팅                                 |
| `apiFormat.anthropicModels`      | `[]`                                         | Anthropic으로 라우팅되는 전체 모델 ID                                                    |
| `logLevel` / `startupDebug`      | `warn` / `false`                             | 로거 상세 수준                                                                           |

## 카탈로그가 최신 상태를 유지하는 방식

카탈로그는 지연 방식으로 가져오며 `modelCacheTtlMs` 동안 캐시됩니다. 또한 디스크 스냅샷을 통해 게이트웨이에 연결할 수 없을 때도 마지막으로 확인된 카탈로그를 사용할 수 있으므로, 서비스 중단 시에도 최신성만 저하될 뿐입니다. 모델과 콤보는 도착하는 즉시 게시됩니다. 자동 콤보, 공급자 목록 및 보강 오버레이도 도착하는 대로 반영되므로, 느린 엔드포인트 하나가 전체 선택기를 지연시킬 수 없습니다.

이름에는 게이트웨이가 알고 있는 정보, 즉 모델이 라우팅되는 업스트림 공급자, `[Free]` 표시 및 함께 제공되는 예산이 포함됩니다. 따라서 동일한 모델을 제공하는 두 연결을 구분할 수 있습니다. 접두사를 끄려면 `"providerTag": false`로 설정하세요.

수동 새로 고침 명령은 없습니다. OpenCode v2 명령은 콜백이 아니라 프롬프트 템플릿이므로 플러그인이 이러한 명령을 제공할 수 없습니다. 새로 고침은 TTL을 따르며, 호스트에는 카탈로그나 오버레이가 실제로 변경된 경우에만 다시 로드하도록 요청합니다. 새로 고칠 때마다 요청하지는 않습니다.

## Gemini에서 도구 호출

Gemini는 도구 선언에 `$schema` 또는 `additionalProperties`가 포함된 요청 전체를 거부하고 `400 INVALID_ARGUMENT`로 응답합니다. 플러그인은 이 공급자의 Gemini 모델로 전송되는 도구 스키마에서 해당 키워드를 제거하며, 그 외의 모든 요청은 그대로 둡니다. `$ref`가 포함된 도구는 제거하지 않고 그대로 전달합니다. 참조를 제거하면 스키마가 "무엇이든 허용"하도록 확장되기 때문입니다.
이 기능을 끄려면 `"geminiSanitization": false`로 설정하세요.

## 문제 해결

| 증상                                            | 원인                                                                                                                 |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 선택기에 OmniRoute 모델이 표시되지 않음         | 확인된 키가 없거나(시작 경고 확인) 게이트웨이에 연결할 수 없음                                                       |
| 원시 모델 ID만 표시되고 콤보와 가격 정보가 없음 | 관리 엔드포인트가 토큰을 거부함 — `managementReadToken`을 설정하세요                                                 |
| 세션이 `opencode-<id>/…`에 고정됨               | v1 플러그인은 `opencode-<id>`를 게시했지만 v2는 `<id>`를 그대로 게시하므로, `<id>/…` 아래에서 모델을 다시 선택하세요 |
