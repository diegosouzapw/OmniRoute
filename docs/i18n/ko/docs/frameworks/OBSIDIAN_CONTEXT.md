> `src/lib/obsidianSync.ts` (WebDAV 볼트 동기화), `open-sse/mcp-server/tools/obsidianTools.ts`

> `src/app/api/settings/obsidian/webdav/route.ts` (설정 API). 도구 등록과
> 범위 연결은 `open-sse/mcp-server/server.ts`에 있습니다.

## 개요

OmniRoute는 **Obsidian** 볼트를 **컨텍스트 소스**로 연결합니다. 이는 에이전트가
내장 MCP 서버를 통해 읽고 쓸 수 있는 로컬 Markdown 지식 베이스입니다. 이 통합은
데스크톱 앱 내에서 실행되는 **Obsidian Local REST API** 커뮤니티 플러그인과 통신하므로,
에이전트가 노트를 검색하고, 파일을 읽고/쓰고/패치하고, 볼트의 내용을 나열하며,
일간/주간 정기 노트를 사용하고, 태그를 관리하고, Obsidian 명령을 실행하며,
선택적으로 데스크톱↔모바일 간 양방향 볼트 동기화를 조정할 수 있습니다.

클라이언트(`src/lib/obsidian/api.ts`)는 Local REST API를 다음 기능과 함께 래핑합니다.

- 일시적인 `5xx` 오류에 대한 **백오프 재시도**, `AbortController`를 통한 **30초 제한 시간**.
- **형식화된 오류 분류** — `ObsidianAuthError`(401/403),
  `ObsidianNotFoundError`(404), `ObsidianServerError`(5xx), `ObsidianTimeoutError`.
- 흔히 발생하는 포트 오류(HTTP는 `27123`이며, `27124`의 MCP 엔드포인트가 **아님**)와
  Tailscale 형식을 명시하는 사용자 친화적인 **"Obsidian에 연결할 수 없음" 안내**.
- 공백이나 슬래시가 포함된 노트 경로를 안전하게 처리하기 위한 볼트 상대 **경로 인코딩**.

## 설정

Obsidian 토큰이나 기본 URL을 위한 **환경 변수는 없습니다**. 둘 다
`src/lib/db/obsidian.ts`를 통해 SQLite `key_value` 테이블(namespace `obsidian`)에
저장됩니다. 토큰은 **저장 시 암호화**됩니다(AES-256-GCM, 이전 버전과의 호환성을 위한
평문 폴백 포함). Endpoint 대시보드의 **Context Sources** 탭(`ObsidianSourceCard`)에서
또는 설정 REST API를 통해 구성할 수 있습니다.

> [!IMPORTANT]
> **Obsidian Local REST API** 플러그인이 설치되어 실행 중이어야 합니다. REST
> 인터페이스는 **HTTP `127.0.0.1:27123`**(기본 URL)에서 수신 대기합니다. 포트 `27124`는
> _별도의_ MCP/HTTPS 엔드포인트이며 설정 라우트에서 명시적으로 거부됩니다.
> 다른 기기에서 연결하는 경우 `http://<tailscale-ip>:27123`을 사용하세요.

### 구성 키(SQLite `key_value`, namespace `obsidian`)

| 키                | 용도                                           | 암호화 여부 |
| ----------------- | ---------------------------------------------- | ----------- |
| `api_key`         | Local REST API bearer 토큰                     | 예          |
| `base_url`        | REST 기본 URL(기본값 `http://127.0.0.1:27123`) | 아니요      |
| `vault_path`      | 볼트 디렉터리의 절대 경로(동기화용)            | 아니요      |
| `webdav_username` | 생성된 WebDAV 사용자 이름(볼트 동기화)         | 아니요      |
| `webdav_password` | 생성된 WebDAV 비밀번호(볼트 동기화)            | 예          |
| `webdav_enabled`  | WebDAV 볼트 동기화 활성화 여부                 | 아니요      |

### REST를 통한 구성

```bash
# Local REST API 토큰 저장 + 검증(POST는 상태 확인을 통해 검증)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# 연결 상태 확인(connected, hasToken, baseUrl, vaultPath 반환)
curl http://localhost:20128/api/settings/obsidian

# 연결 해제(저장된 토큰 삭제)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

모든 메서드에는 대시보드 인증이 필요합니다. `POST`는 포트 `27124`를 사용하는 모든 URL을
거부하며, 저장하기 전에 Local REST API 상태 엔드포인트를 호출하여 토큰을 검증합니다.

### WebDAV 볼트 동기화

`src/app/api/settings/obsidian/webdav/route.ts`는 선택적 WebDAV 기반 볼트 동기화를
관리합니다(`src/lib/obsidianSync.ts`에 의해 구동). 이를 활성화하면 OmniRoute가 로컬
볼트 디렉터리를 가리키도록 설정되고 임의의 WebDAV 사용자 이름/비밀번호 쌍이 생성됩니다.

```bash
# 볼트 디렉터리에 WebDAV 동기화 활성화(사용자 이름/비밀번호 생성)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# WebDAV 동기화 상태 확인(활성화된 동안에만 자격 증명 반환)
curl http://localhost:20128/api/settings/obsidian/webdav

# WebDAV 동기화 비활성화(자격 증명 + 관리되는 .stignore 삭제)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### API 키별 컨텍스트 소스(선택 사항)

Obsidian 구성은 `api_key_context_sources` 테이블을 통해 **API 키별로** 범위를 지정할 수
있습니다(`src/lib/db/apiKeyContextSources.ts`). MCP 호출에 인증된 API 키 id가 포함되면
`getObsidianConfigForApiKey()`는 해당 키 자체의 토큰/기본 URL/볼트 경로
(`source: "api_key"`)를 우선 사용하고, 그렇지 않으면 전역 구성
(`source: "global"`)으로 폴백합니다.

## MCP 도구 (22개)

`open-sse/mcp-server/tools/obsidianTools.ts`에 정의되어 있습니다. 토큰/base-URL은
호출별로 확인됩니다(API 키별 설정을 먼저 확인한 다음 전역 설정 확인). OmniRoute **동기화 서버**에
접근하는 도구(4개의 `obsidian_sync_*` 도구)는 OmniRoute 설정에 구성된 동기화 인증 토큰도
추가로 필요합니다.

### 읽기 도구 (`read:obsidian`)

| 도구                         | 설명                                                                                             |
| ---------------------------- | ------------------------------------------------------------------------------------------------ |
| `obsidian_check_status`      | Local REST API에 연결할 수 있고 인증되었는지 확인합니다.                                         |
| `obsidian_search_simple`     | 노트 콘텐츠를 전체 텍스트 검색하며, 파일 경로가 포함된 스니펫을 반환합니다.                      |
| `obsidian_search_structured` | JSON Logic 표현식(and/or/regex/path 필터)을 사용하여 검색합니다.                                 |
| `obsidian_read_note`         | 볼트 기준 상대 경로로 노트를 읽으며, 선택적으로 특정 제목/블록/frontmatter를 지정할 수 있습니다. |
| `obsidian_list_vault`        | 볼트의 파일과 디렉터리를 나열합니다(항목 트리).                                                  |
| `obsidian_get_document_map`  | 노트의 제목 구조를 제목 → 줄 번호 맵으로 가져옵니다.                                             |
| `obsidian_get_note_metadata` | 전체 콘텐츠 없이 frontmatter, 태그, 링크, 문자/단어 수를 가져옵니다.                             |
| `obsidian_get_active_file`   | Obsidian에서 현재 활성화된 파일의 경로와 콘텐츠를 가져옵니다.                                    |
| `obsidian_get_periodic_note` | 특정 날짜의 일간/주간/월간 정기 노트를 가져옵니다(생략하면 오늘).                                |
| `obsidian_get_tags`          | 모든 볼트 태그와 각 태그의 사용 빈도를 나열합니다.                                               |
| `obsidian_list_commands`     | 사용 가능한 Obsidian 명령 ID를 나열합니다(`obsidian_execute_command`와 함께 사용).               |
| `obsidian_sync_status`       | OmniRoute 동기화 서버 상태: 실행 여부, 볼트 이름, 포트, 가동 시간, 마지막 동기화.                |
| `obsidian_sync_conflicts`    | 해결되지 않은 동기화 충돌을 나열합니다(경로, 충돌 경로, 감지 시각).                              |

### 쓰기 도구 (`write:obsidian`)

| 도구                             | 설명                                                                                 |
| -------------------------------- | ------------------------------------------------------------------------------------ |
| `obsidian_write_note`            | 지정된 Markdown 콘텐츠로 노트를 생성하거나 덮어씁니다.                               |
| `obsidian_append_note`           | 노트에 콘텐츠를 추가하며, 선택적으로 특정 제목/블록에 추가할 수 있습니다.            |
| `obsidian_patch_note`            | 제목, 블록 또는 frontmatter 필드에 정밀하게 추가/앞에 추가/교체합니다.               |
| `obsidian_delete_note`           | 볼트에서 노트를 영구적으로 삭제합니다.                                               |
| `obsidian_move_note`             | 볼트 내에서 노트를 이동하거나 이름을 변경합니다.                                     |
| `obsidian_execute_command`       | Obsidian 명령 ID로 명령을 실행합니다.                                                |
| `obsidian_open_file`             | Obsidian에서 파일을 엽니다(존재하지 않으면 생성).                                    |
| `obsidian_sync_trigger`          | 데스크톱↔모바일 볼트의 즉각적인 양방향 동기화를 트리거합니다.                        |
| `obsidian_sync_resolve_conflict` | 동기화 충돌을 해결합니다: `local`(모바일), `remote`(데스크톱) 또는 `keep-both` 유지. |

> [!NOTE]
> `obsidian_patch_note` 대상은 `heading | block | frontmatter` 중 하나를 `targetType`으로,
> `append | prepend | replace` 중 하나를 `operation`으로 사용하며, 선택적으로
> `createTargetIfMissing`를 사용할 수 있습니다. 4개의 `obsidian_sync_*` 도구는 로컬 동기화
> 서버(기본값: `http://127.0.0.1:27781`)와 통신하며 동기화 토큰이 필요합니다.

### 범위

읽기 도구에는 `read:obsidian`이 필요하고, 쓰기 도구에는 `write:obsidian`이 필요합니다. 적용 방식은
Notion과 동일합니다. 즉, `open-sse/mcp-server/server.ts`의 `withScopeEnforcement()`에서 처리되며,
`OMNIROUTE_MCP_ENFORCE_SCOPES=true`일 때 활성화되고, 허용된 범위는 `OMNIROUTE_MCP_SCOPES` 또는
API 키의 범위 컨텍스트에서 가져옵니다. [MCP-SERVER.md](./MCP-SERVER.md)를 참조하세요.

## 엔드포인트

| 메서드   | 경로                            | 용도                                                        |
| -------- | ------------------------------- | ----------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | `{ connected, hasToken, baseUrl, vaultPath }`를 반환합니다. |
| `POST`   | `/api/settings/obsidian`        | 토큰을 저장하고 검증합니다(포트 `27124`는 거부됨).          |
| `DELETE` | `/api/settings/obsidian`        | 연결을 해제합니다(저장된 토큰 삭제).                        |
| `GET`    | `/api/settings/obsidian/webdav` | WebDAV 동기화 상태와 자격 증명을 반환합니다(활성화된 동안). |
| `POST`   | `/api/settings/obsidian/webdav` | 볼트 디렉터리에 대해 WebDAV 동기화를 활성화합니다.          |
| `DELETE` | `/api/settings/obsidian/webdav` | WebDAV 동기화를 비활성화합니다.                             |

> 이는 대시보드 설정 경로입니다. 볼트 자체에는 Obsidian
> Local REST API(구성된 `base_url`) 및 위의 MCP 도구를 통해 접근합니다. 공개
> `/v1` Obsidian 프록시 엔드포인트는 없습니다.

## 사용 사례

- **볼트 기반 답변** — `obsidian_search_simple` / `obsidian_search_structured`를 실행한
  다음 `obsidian_read_note`를 사용하여 에이전트가 실제 노트를 바탕으로 답변하도록 합니다.
- **노트 작성 / 저널링** — `obsidian_write_note`, `obsidian_append_note` 또는 정밀한
  `obsidian_patch_note`를 사용하여 에이전트 출력, 요약 또는 일일 노트
  (`obsidian_get_periodic_note`)를 볼트에 기록합니다.
- **볼트 탐색** — 읽기/쓰기 전에 `obsidian_list_vault`, `obsidian_get_document_map`,
  `obsidian_get_tags`를 사용하여 구조를 탐색합니다.
- **Obsidian 자동화** — `obsidian_list_commands` + `obsidian_execute_command`를 사용하여
  에이전트에서 플러그인/명령을 실행하고, `obsidian_open_file`을 사용하여 UI에 노트를 표시합니다.
- **모바일 동기화** — WebDAV 동기화를 활성화한 다음 `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`를
  사용하여 데스크톱↔모바일 동기화를 조정하고 충돌을 해결합니다.
