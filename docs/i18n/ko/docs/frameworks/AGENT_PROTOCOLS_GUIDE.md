OmniRoute는 서로 다른 세 가지 에이전트 관련 인터페이스를 제공합니다. 언뜻 보기에는 비슷하지만 서로 다른 문제를 해결합니다. 이 페이지를 참고하여 적합한 인터페이스를 선택하세요.

## 요약

| 인터페이스                        | 적합한 용도                                                                                                    | 전송 방식                | 표준                 |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------ | -------------------- |
| **A2A — 에이전트 간 통신**        | A2A 프로토콜을 사용하는 동료 에이전트와의 에이전트 간 협업                                                     | HTTP 기반 JSON-RPC 2.0   | A2A v0.3 (공개 사양) |
| **ACP — CLI 에이전트 레지스트리** | 사용자 컴퓨터에 설치된 CLI 코딩 에이전트(Cursor, Cline, Codex CLI, Claude Code, Aider 등)의 감지, 등록 및 실행 | HTTP REST                | OmniRoute 전용       |
| **클라우드 에이전트**             | 외부 클라우드 서비스(Codex Cloud, Devin, Jules, Cursor Cloud)에 장시간 실행되는 코딩 작업 제출                 | HTTP REST + DB 기반 작업 | OmniRoute 전용       |

세 인터페이스는 서로 독립적이므로 필요한 것만 선택해 사용할 수 있습니다.

## 결정 트리

```
이 컴퓨터 외부에서 작업을 수행할 클라우드 서비스(Codex Cloud / Cursor Cloud / Devin / Jules)가 필요한가요?
├─ 예 → 클라우드 에이전트(POST /api/v1/agents/tasks)
└─ 아니요 → 계속
    │
    A2A를 사용하며 협업하려는 동료 에이전트가 있나요?
    ├─ 예 → A2A(POST /a2a)
    └─ 아니요 → 계속
        │
        로컬에 설치된 CLI 코딩 에이전트를 나열하거나 구성해야 하나요?
        ├─ 예 → ACP(GET /api/acp/agents)
        └─ 아니요 → 일반 /v1/chat/completions 사용
```

## 1. A2A — 에이전트 간 통신

**사양:** [A2A v0.3](https://a2a-protocol.org)
**OmniRoute 엔드포인트:** `POST /a2a` (JSON-RPC 2.0)
**에이전트 카드:** `GET /.well-known/agent.json`

### 사용 시기

- OmniRoute가 동료 중 하나로 참여하는 멀티 에이전트 시스템을 구축할 때
- Google ADK 또는 범용 에이전트 메시와 같은 프레임워크의 에이전트에 OmniRoute의 라우팅 인텔리전스(smart-routing, quota-management 등)를 제공할 때
- 표준 검색 및 호출 인터페이스 뒤에 OmniRoute를 래핑할 때

### 메서드

- `message/send` — 메시지를 제출하고 동기 응답 수신
- `message/stream` — 메시지를 제출하고 SSE로 스트리밍되는 진행 이벤트 수신
- `tasks/get` — ID로 작업 조회
- `tasks/cancel` — 실행 중인 작업 취소

### 기본 제공 스킬(6개)

- `smart-routing` — 최적의 조합을 통해 프롬프트 라우팅
- `quota-management` — 공급자별 할당량 상태 보고
- `provider-discovery` — 설치된 공급자와 해당 기능 목록 표시
- `cost-analysis` — 요청 또는 대화 비용 추정
- `health-report` — 공급자별 차단기, 쿨다운 및 잠금 상태 집계
- `list-capabilities` — 에이전트에서 사용 가능한 스킬과 메타데이터 열거

### 자세히 알아보기

전송 세부 정보, 에이전트 카드 구조, 작업 TTL 구성 및 새 스킬을 추가하기 위한 템플릿은 [A2A-SERVER.md](./A2A-SERVER.md)를 참조하세요.

## 2. ACP — CLI 에이전트 레지스트리

**OmniRoute 엔드포인트:** `GET /api/acp/agents`
**소스:** `src/lib/acp/{index,manager,registry}.ts`

### 개요

ACP는 OmniRoute의 **로컬 CLI 에이전트 인벤토리**입니다. 호스트에 설치된 코딩 CLI(Cursor, Cline, Claude Code, Codex CLI, Continue 등)를 감지하고 해당 버전을 확인한 뒤, 사용자가 각 CLI를 OmniRoute에 연결하도록 대시보드에 표시합니다.

이는 외부 프로토콜이 **아닙니다**. "CLI Tools" UI와 CLI 핑거프린트 추적을 지원하는 내부 레지스트리입니다([CLI-TOOLS.md](../reference/CLI-TOOLS.md) 참조).

### 기능

- 호스트에 설치된 CLI 바이너리를 탐색합니다(OS에 따라 `which` / `where` 사용).
- 각 CLI의 버전을 확인합니다(`<bin> --version` 호출).
- 필요에 따라 사용자 정의 에이전트(바이너리 경로 + 버전 확인 명령 + 실행 인수)를 허용합니다.
- 사용자 정의 에이전트를 설정에 영구 저장합니다.
- 통합된 목록을 대시보드에 반환합니다.

### REST API

| 엔드포인트        | 메서드 | 설명                                                             | 인증   |
| ----------------- | ------ | ---------------------------------------------------------------- | ------ |
| `/api/acp/agents` | GET    | 감지된 에이전트와 사용자 정의 에이전트 목록(설치된 수/전체 수)   | API 키 |
| `/api/acp/agents` | POST   | 사용자 정의 에이전트 추가/업데이트/제거(본문의 작업 판별자 사용) | API 키 |

POST의 본문 형식(`src/app/api/acp/agents/route.ts`의 `customAgentBodySchema`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### 사용 사례

- 대시보드의 "CLI Tools" 페이지에서 설치된 항목을 나열하고 각 항목이 OmniRoute를 가리키도록 설정하는 데 도움을 줍니다.
- 고급 사용자는 사용자 정의 에이전트를 통해 OmniRoute가 기본적으로 인식하지 못하는 내부/독점 CLI를 등록할 수 있습니다.
- 감지 결과는 `cli-tools` 핑거프린트 매트릭스에 사용됩니다.

### ACP를 사용하지 않아야 하는 경우

- ACP는 작업을 _실행_하지 않습니다. CLI를 감지하고 구성할 뿐입니다. CLI를 실제로 호출하려면 OmniRoute가 제공하는 환경 변수(`OPENAI_BASE_URL`, `OPENAI_API_KEY` 등)를 사용하여 직접 실행해야 합니다.

## 3. 클라우드 에이전트

**OmniRoute 엔드포인트:** `/api/v1/agents/tasks/*`(수명 주기) + `/api/cloud/*`(연결 기반 기능)
**소스:** `src/lib/cloudAgent/`

### 개요

타사 클라우드 코딩 에이전트를 위한 통합 인터페이스입니다. 프롬프트와 저장소 URL을 제출하면 OmniRoute가 적절한 클라우드 에이전트에 작업을 전달하고, 상태를 폴링한 후 결과를 반환합니다.

### 지원되는 에이전트(`src/lib/cloudAgent/agents/`에서 모두 확인됨)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### 수명 주기

```
POST /api/v1/agents/tasks
  → 에이전트 클래스별 BaseAgent.createTask()
  → 외부 서비스가 작업 시작
  → DB에 작업 행 생성(cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → 제공자에서 지연 상태 동기화
  → 현재 상태 + 계획 + 활동 로그 반환
  ↓
POST /api/v1/agents/tasks/[id]   (action: "approve" | "message" | "cancel")
  → 제공자에게 전달(또는 로컬에서 취소됨으로 표시)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → 로컬 취소
```

### 인증

⚠️ **모든 `/api/v1/agents/tasks/*` 엔드포인트에는 관리 인증이 필요합니다**(커밋 `588a0333`). v3.8.0부터 Bearer 전용 호출자는 401 응답을 받습니다.

### 자세히 알아보기

`CloudAgentBase` 계약, 에이전트별 세부 사항, 스키마 상세 정보 및 자격 증명 연결 엔드포인트는 [CLOUD_AGENT.md](./CLOUD_AGENT.md)를 참조하세요.

## 비교: A2A와 Cloud Agents

둘 다 "장기 실행 작업"을 지원하지만 서로 다른 계층에서 작동합니다.

| 측면             | A2A                                                                              | Cloud Agents                     |
| ---------------- | -------------------------------------------------------------------------------- | -------------------------------- |
| 표준             | Open A2A v0.3                                                                    | OmniRoute 전용                   |
| 컴퓨팅 실행 위치 | OmniRoute 내부(구성된 조합 사용)                                                 | 외부(Codex / Devin / Jules 서버) |
| 작업 소요 시간   | 기본 TTL 5분(`TaskManager`에서 구성 가능)                                        | 수분에서 수시간                  |
| 저장소 인식      | 아니요(프롬프트만 전달)                                                          | 예(저장소 URL + 브랜치)          |
| 사용 사례        | 에이전트 간 협업, 서비스 형태의 스마트 라우팅                                    | "저장소 Y에 기능 X 구현" 위임    |
| 인증             | `/a2a`에는 선택적 `OMNIROUTE_API_KEY`, `/api/a2a/*` REST 헬퍼에는 관리 인증 필요 | 항상 관리 인증 필요              |

## 통합 예시

### OmniRoute의 A2A 기능 검색

```bash
curl http://localhost:20128/.well-known/agent.json
```

6개 스킬, 전송 방식 및 버전이 모두 포함된 Agent Card를 반환합니다.

### OmniRoute를 A2A 에이전트로 호출

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### ACP를 통해 설치된 CLI 에이전트 목록 조회

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### 사용자 정의 CLI 에이전트 추가

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### Cloud Agent 작업 제출

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### 클라우드 작업 상태 폴링

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## 상황별 사용 방법

- **챗봇 / 코파일럿 프런트엔드** → `/v1/chat/completions` (OpenAI 호환 — 에이전트 프로토콜이 아님)
- **멀티 에이전트 협업** → A2A
- **대시보드에서 로컬 CLI 목록 조회** → ACP
- **장기 실행 코딩 작업을 클라우드 서비스에 위임** → Cloud Agents
