> **신뢰할 수 있는 원본:** `src/lib/cloudAgent/` 및 `src/app/api/v1/agents/tasks/`
> **최종 업데이트:** 2026-06-28 — v3.8.40 (frontmatter 갱신, cursor-cloud를 포함한 에이전트 4개)

OmniRoute는 타사 클라우드 호스팅 코딩 에이전트(Codex Cloud, Cursor,
Devin, Jules)를 장기 실행 작업으로 오케스트레이션합니다. 각 에이전트는 통일된 인터페이스로 래핑되므로
클라이언트는 제공자별 API를 직접 다루지 않고도 프롬프트와 저장소 URL을 제출하고
결과를 받을 수 있습니다.

Cloud Agent 작업은 일반적인 채팅 완성이 **아닙니다**. 이는 완료하는 데 수분에서 수 시간이
걸릴 수 있는 지속적인 다단계 작업 단위이며, Pull Request를 결과물로 생성할 수 있고
후속 메시지와 일부 제공자의 경우 계획 승인 단계를 지원합니다.

## 지원되는 에이전트

| 제공자 ID      | 클래스             | 소스                                  | 업스트림 기본 URL                       | 계획 승인     |
| -------------- | ------------------ | ------------------------------------- | --------------------------------------- | ------------- |
| `jules`        | `JulesAgent`       | `src/lib/cloudAgent/agents/jules.ts`  | `https://jules.googleapis.com/v1alpha`  | 예            |
| `devin`        | `DevinAgent`       | `src/lib/cloudAgent/agents/devin.ts`  | `https://api.devin.ai/v1`               | 예            |
| `codex-cloud`  | `CodexCloudAgent`  | `src/lib/cloudAgent/agents/codex.ts`  | `https://api.openai.com/v1/codex/cloud` | 아니요 (자동) |
| `cursor-cloud` | `CursorCloudAgent` | `src/lib/cloudAgent/agents/cursor.ts` | `https://api.cursor.com/v0`             | 아니요 (자동) |

레지스트리: `src/lib/cloudAgent/registry.ts` — `getAgent(providerId)`,
`getAvailableAgents()`, `isCloudAgentProvider(providerId)`를 내보냅니다. 레지스트리는
모듈 로드 시 채워지는 단순한 인메모리 `Record<string, CloudAgentBase>`입니다.

## 아키텍처

```
클라이언트(대시보드 / CLI / API)
  → POST /api/v1/agents/tasks (관리 인증 필요)
    → CreateCloudAgentTaskSchema 유효성 검사(Zod)
    → registry.getAgent(providerId)
    → getCloudAgentCredentials(providerId)
      └─ getProviderConnections({ provider, isActive: true })에서 가져옴
         (apiKey 우선, 없으면 accessToken 사용)
    → agent.createTask({ prompt, source, options }, credentials)
      └─ 업스트림 제공자 API로 HTTP POST
      └─ 내부 id + externalId가 포함된 CloudAgentTask 반환
    → cloud_agent_tasks(SQLite)에 insertCloudAgentTask(...)

폴링(읽기 시 지연 동기화):
  GET /api/v1/agents/tasks/[id]
    → getCloudAgentTaskById(id)
    → agent.getStatus(externalId, credentials)  // 상태 + 활동 갱신
    → 새로운 상태, 결과, completed_at으로 updateCloudAgentTask(...)
    → 직렬화된 작업 반환

상호작용:
  POST /api/v1/agents/tasks/[id]  본문: { action: "approve" | "message" | "cancel" }
    → agent.approvePlan(externalId, credentials)        "approve"의 경우
    → agent.sendMessage(externalId, message, credentials) "message"의 경우
    → 상태를 "cancelled"로 변경                       "cancel"의 경우(로컬 전용)
```

동기화는 **지연 방식**입니다. `GET /tasks/[id]`를 호출할 때마다 업스트림에서 상태를
갱신합니다. 백그라운드 폴러는 없습니다. 최신 상태가 필요한 대시보드는 적절한 간격으로
GET 엔드포인트를 폴링해야 합니다.

## `CloudAgentBase` 인터페이스

소스: `src/lib/cloudAgent/baseAgent.ts`

```typescript
export interface AgentCredentials {
  apiKey: string;
  baseUrl?: string;
}

export interface CreateTaskParams {
  prompt: string;
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
}

export interface GetStatusResult {
  status: CloudAgentStatus;
  externalId?: string;
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
}

export abstract class CloudAgentBase {
  abstract readonly providerId: string;
  abstract readonly baseUrl: string;

  abstract createTask(p: CreateTaskParams, c: AgentCredentials): Promise<CloudAgentTask>;
  abstract getStatus(externalId: string, c: AgentCredentials): Promise<GetStatusResult>;
  abstract approvePlan(externalId: string, c: AgentCredentials): Promise<void>;
  abstract sendMessage(
    externalId: string,
    message: string,
    c: AgentCredentials
  ): Promise<CloudAgentActivity>;
  abstract listSources(
    c: AgentCredentials
  ): Promise<{ name: string; url: string; branch?: string }[]>;

  protected mapStatus(raw: string): CloudAgentStatus; // 경험적 규칙으로 업스트림 문자열 → 열거형 변환
  protected generateTaskId(): string; // `task_<ts>_<rand>`
  protected generateActivityId(): string; // `act_<ts>_<rand>`
}
```

`CodexCloudAgent.approvePlan`은 의도적으로 예외를 발생시킵니다. Codex Cloud는 자동으로 계획을 수립하며
승인 단계가 없습니다. `CodexCloudAgent.listSources`는 `[]`를 반환합니다.

`CursorCloudAgent`는 **사용자 또는 서비스 계정 API 키**를 사용하여 공식 REST
API(`api.cursor.com/v0`)를 통해 Cursor의 Background / Cloud Agents를 구동합니다. 이는
차단 위험 경고가 있는 Cursor IDE의 OAuth 세션을 재사용하는 방식(provider `cursor`)보다 안전한
공식 대안입니다. 이는 일반 REST 어댑터이며 `@cursor/sdk` 네이티브 의존성이 없습니다.
`approvePlan`은 예외를 발생시킵니다(Cursor 에이전트는 자율적으로 실행됨). `listSources`는
해당 키로 접근할 수 있는 저장소를 나열합니다. Cursor는 대문자 상태 열거형
(`CREATING`/`RUNNING`/`FINISHED`/`ERROR`)을 반환하며, 이는 공유
`CloudAgentStatus`에 명시적으로 매핑됩니다. `baseUrl`은 자격 증명별로 재정의할 수 있으므로
코드를 변경하지 않고도 API 버전/경로를 수정할 수 있습니다.

## 데이터베이스

소스: `src/lib/cloudAgent/db.ts` — 테이블은
`createCloudAgentTaskTable()`을 통해 지연 생성됩니다(모듈을 가져올 때
`src/lib/cloudAgent/index.ts`에서도 호출됨).

```sql
CREATE TABLE IF NOT EXISTS cloud_agent_tasks (
  id           TEXT PRIMARY KEY,
  provider_id  TEXT NOT NULL,
  external_id  TEXT,
  status       TEXT NOT NULL DEFAULT 'queued',
  prompt       TEXT NOT NULL,
  source       TEXT NOT NULL,             -- JSON
  options      TEXT DEFAULT '{}',         -- JSON
  result       TEXT,                       -- JSON
  activities   TEXT DEFAULT '[]',          -- JSON
  error        TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_provider ON cloud_agent_tasks(provider_id);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_status   ON cloud_agent_tasks(status);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_created  ON cloud_agent_tasks(created_at DESC);
```

`updateCloudAgentTask`는 SQL 인젝션을 방지하기 위해 **열 허용 목록**을 적용합니다:
`status`, `prompt`, `source`, `options`, `result`, `activities`, `error`,
`completed_at`. 부분 업데이트에 포함된 다른 모든 키는 별도의 알림 없이 삭제됩니다.

## REST API — 작업 수명 주기

**인증:** 모든 `/api/v1/agents/tasks*` 엔드포인트에는 **관리 인증**이 필요합니다
(`requireCloudAgentManagementAuth`는
`src/lib/api/requireManagementAuth`의 `requireManagementAuth`를 래핑함). 이는 커밋 `588a0333`
(_"수정(auth): 에이전트 및 쿨다운 API에 관리 인증 요구"_) 이후 적용됩니다.

| 메서드  | 경로                          | 목적                                                    |
| ------- | ----------------------------- | ------------------------------------------------------- |
| OPTIONS | `/api/v1/agents/tasks`        | CORS 사전 요청                                          |
| GET     | `/api/v1/agents/tasks`        | 작업 목록 조회(필터: `provider`, `status`, `limit≤500`) |
| POST    | `/api/v1/agents/tasks`        | 작업 생성(업스트림으로 전달하고 저장)                   |
| DELETE  | `/api/v1/agents/tasks?id=...` | 쿼리 ID로 작업 삭제(업스트림 작업은 취소하지 **않음**)  |
| OPTIONS | `/api/v1/agents/tasks/[id]`   | CORS 사전 요청                                          |
| GET     | `/api/v1/agents/tasks/[id]`   | 작업 조회 및 업스트림 상태 지연 동기화                  |
| POST    | `/api/v1/agents/tasks/[id]`   | 작업: `approve` / `message` / `cancel`                  |
| DELETE  | `/api/v1/agents/tasks/[id]`   | 경로 ID로 작업 삭제                                     |

### 작업 생성

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \

  -H "Content-Type: application/json" \

    "prompt": "Fix the bug in src/foo.ts where the parser returns null",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    },
    "options": {
      "autoCreatePr": true,
      "planApprovalRequired": false
    }
  }'
```

```json
{
  "data": {
    "id": "task_1731512345678_abc123def",
    "providerId": "devin",
    "externalId": "session_xyz",
    "status": "queued",
    "prompt": "...",
    "source": { "repoName": "user/repo", "repoUrl": "...", "branch": "main" },
    "options": { "autoCreatePr": true },

```

### 계획 승인

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"action":"approve"}'
```

### 후속 메시지 전송

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"message","message":"Also add a unit test for the parser"}'
```

### 취소(로컬 상태만 해당)

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"cancel"}'
```

`cancel`은 로컬 DB의 `status`를 `"cancelled"`로 변경하지만 업스트림
공급자를 호출하지는 **않습니다**. `CloudAgentBase`에는 중단 RPC가 없습니다. 업스트림
과금을 중단하려면 공급자 자체 콘솔에서 작업을 종료하세요.

## REST API — 클라우드 제공자 연동

`src/app/api/cloud/` 아래의 이러한 보조 엔드포인트는 원격 클라이언트
(CLI, Electron 앱 또는 동기화 워커)가 제공자 연결 메타데이터를 읽고
모델 별칭을 확인하는 데 사용됩니다. 태스크 엔드포인트에서 사용하는 관리 인증이 아니라
**일반 API 키**(`validateApiKey`를 통해)로 인증됩니다.

| 메서드 | 경로                            | 용도                                                        |
| ------ | ------------------------------- | ----------------------------------------------------------- |
| POST   | `/api/cloud/auth`               | API 키를 검증하고 마스킹된 연결 메타데이터 + 모델 별칭 반환 |
| PUT    | `/api/cloud/credentials/update` | `accessToken` / `refreshToken` / `expiresAt` 갱신           |
| POST   | `/api/cloud/model/resolve`      | 모델 별칭을 `{ provider, model }`로 확인                    |
| GET    | `/api/cloud/models/alias`       | 모든 모델 별칭 나열                                         |
| PUT    | `/api/cloud/models/alias`       | 모델 별칭 설정(활성화된 경우 Cloud에 자동 동기화)           |

`/api/cloud/auth`는 원본 `apiKey` / `accessToken` / `refreshToken`을 절대 반환하지 않습니다.
대신 `hasApiKey`, `hasAccessToken`, `hasRefreshToken`과 마스킹된 미리보기
(`maskedApiKey`: 처음 4자 + `****` + 마지막 4자)를 반환합니다.

## 자격 증명 확인

`src/lib/cloudAgent/api.ts`의 `getCloudAgentCredentials(providerId)`:

1. `getProviderConnections({ provider: providerId, isActive: true })`를 통해 활성 제공자 연결을 불러옵니다.
2. 각 연결에서 공백을 제거한 `apiKey`를 우선 사용합니다. 없으면 `accessToken`을 사용합니다.
3. 비어 있지 않은 첫 번째 토큰을 `{ apiKey: token }`으로 래핑하여 반환합니다.
4. 사용할 수 있는 토큰을 찾지 못하면 `null`을 반환하며, API는
   `"No active credentials configured for cloud agent provider: <id>"`와 함께 `400`으로 응답합니다.

즉, Cloud Agents는 일반 LLM 제공자와 동일한 Provider Connection 테이블을 재사용합니다.
Jules를 활성화하려면 `provider: "jules"`이고 `apiKey`가 입력된 활성 연결을 생성하세요.

## A2A와의 통합

`tasks/send` 핸들러를 `getAgent(...).createTask(...)`에 위임하고 A2A 태스크
상태 이벤트를 JSON-RPC 2.0 프로토콜로 변환하는 A2A 스킬을 등록하면 Cloud Agents를
A2A 스킬로 노출할 수 있습니다. [A2A-SERVER.md](./A2A-SERVER.md)를 참조하세요.

## 새 Cloud Agent 추가

1. `CloudAgentBase`를 확장하는 `src/lib/cloudAgent/agents/<name>.ts`를 생성합니다.
2. `createTask`, `getStatus`, `approvePlan`(또는 해당되지 않는 경우 예외 발생),
   `sendMessage`, `listSources`를 구현합니다. 상태 정규화에는 `this.mapStatus(...)`를 사용합니다.

   (`CloudAgentTask.providerId` 및 `CreateCloudAgentTaskSchema`).
5. 연결 레코드가 필요한 경우 제공자를 `src/shared/constants/providers.ts`에 추가합니다.
   OAuth 기반 제공자의 경우 `src/lib/oauth/providers/`도 필요합니다.
6. `tests/unit/cloud-agent-*.test.ts` 아래에 테스트를 추가합니다.
7. 이 문서와 대시보드의 `CLOUD_AGENTS` 상수를 업데이트합니다.

## 구성

| 환경 변수        | 용도                                                      |
| ---------------- | --------------------------------------------------------- |
| `DATA_DIR`       | `cloud_agent_tasks`를 저장하는 SQLite 데이터베이스의 위치 |
| `JWT_SECRET`     | 작업 엔드포인트의 관리 인증에 필요                        |
| `API_KEY_SECRET` | 저장된 공급자 연결 자격 증명을 암호화하는 데 필요         |

현재 Cloud-Agent 전용 환경 변수는 없습니다. 모든 비밀 정보는
`provider_connections` 테이블에 저장됩니다.
