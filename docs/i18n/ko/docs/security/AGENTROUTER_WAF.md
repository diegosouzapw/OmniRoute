`agentrouter` 업스트림 게이트웨이는 `messages[].content`에 키워드 기반 콘텐츠 필터를 적용합니다. 이 필터는 일부는 결정론적으로 작동하며(특정 문구는 항상 차단), 일부는 확률적으로 작동합니다(버스트에 민감하여 짧은 시간에 요청이 몰리면 더 공격적으로 차단하고, 쿨다운 후에는 정상화됨).

WAF가 요청을 차단하면 다음을 반환합니다.

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## 필터의 적용 범위

WAF는 `messages[].content`만 검사합니다. 다음 항목은 검사하지 **않습니다**.

- `system` 프롬프트
- 구조화된 콘텐츠 블록(`tool_result`, `tool_use`, `thinking`, `image`)
- 도구의 `description` 및 `input_schema` 필드
- 요청 메타데이터, 헤더 또는 모델 ID

## 항상 차단되는 패턴(대소문자 구분 없음)

| 패턴                        | 참고 사항                                             |
| --------------------------- | ----------------------------------------------------- |
| 모든 `Lorem ipsum` 변형     | 전체 라틴어 로렘 어휘가 차단됨                        |
| `language model`(단독)      | "the language model" 및 "large language model"은 통과 |
| `virtual assistant`         | "AI assistant"는 통과                                 |
| `I'm here to help`          | "here to help"만 있어도 차단됨                        |
| `Claude, made by Anthropic` | 전체 문구만 해당                                      |

## 거의 항상 차단되는 패턴

| 패턴                                            | 참고 사항                                                   |
| ----------------------------------------------- | ----------------------------------------------------------- |
| `placeholder`                                   | 단독으로 사용될 때(매개변수 이름 등으로 사용되는 경우 제외) |
| `dummy data`                                    | 픽스처에 흔히 사용되는 시드 문구                            |
| `foo bar baz`                                   | 대표적인 플레이스홀더 문구                                  |
| 짧은 토큰 반복(`AAA BBB CCC`, `test test test`) | 키워드 스터핑 탐지기                                        |

## 부하가 걸릴 때의 동작

짧은 시간 동안 약 5개의 요청이 빠르게 전송되면 WAF는 평소라면 통과할 콘텐츠도 차단하기 시작합니다. 버킷은 약 5~10초 동안 요청이 없으면 완화됩니다. 이는 Claude Code 또는 Codex CLI가 짧은 시간에 여러 차례 도구 사용/메시지 전송 호출을 할 때 간헐적으로 `400 content-blocked` 오류를 일으키는 것과 동일한 IP 및 키 기반 속도 제한기입니다.

## OmniRoute에 이미 적용된 완화 조치

1. **`open-sse/services/wafRateLimit.ts`** — 모든 `agentrouter:*` URL로 전송되는 아웃바운드 요청 사이에 최소 500 ms 간격을 적용하는 버스트 방지 장치입니다. 이 간격은 사람이 지연을 인지할 수 있는 수준보다 훨씬 짧으며, 정상 트래픽에서 WAF가 활성화되는 것을 방지합니다.

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — 업스트림이 `400 content-blocked`를 반환하면 실행기는 지수 백오프(1.5 s, 3.0 s, 최대 2회)를 적용하여 동일한 URL로 다시 요청합니다. 백오프 후에는 일반적으로 WAF가 완화되어 재시도가 성공합니다.

3. **`tests/unit/compression/harness.test.ts`** — Claude Code가 `Read` 도구를 통해 이 파일을 읽을 때 파일 내용이 `tool_result` 블록을 통해 다시 전달되어 WAF를 작동시키지 않도록, 테스트 픽스처 `longInput`을 `"lorem ipsum dolor sit amet ".repeat(40)`에서 `"example content for testing purposes ".repeat(40)`로 변경했습니다.

## 프롬프트 및 도구 출력에 대한 지침

Claude Code 또는 Codex CLI 세션에서 `400 content-blocked`가 반복적으로 발생하면 가장 최근의 사용자 메시지와 가장 최근의 도구 결과에 위 패턴이 포함되어 있는지 확인하고 다른 표현으로 바꾸십시오. 일반적인 우회 방법은 다음과 같습니다.

- `Lorem ipsum …`을 `example text …` 또는 테스트나 픽스처가 모델링하려는 실제 콘텐츠로 바꿉니다.
- 단독으로 사용된 `placeholder`를 `example value`, `sample value` 또는 실제 값으로 바꿉니다.
- `language model`을 `large language model` 또는 `the model`로 바꿉니다.
- `dummy data`를 `sample data` 또는 현실적인 시드 값으로 바꿉니다.
- `I'm here to help` / `here to help`를 더 구체적인 시작 문구로 바꿉니다(예: "I'll review the file you mentioned").

## 업스트림에 오탐 보고하기

현재 필터는 지나치게 공격적입니다. 운영자가 프롬프트를 삽입할 의도가 전혀 없었음에도 `tool_result` 블록의 "Lorem ipsum"을 차단합니다. 이 문제를 근본적으로 해결하고자 하는 운영자는 `agentrouter.org`에 연락하여 오탐을 보고해야 합니다. 위 차단 목록은 2026-08-03 기준으로 업스트림을 조사하여 얻은 실증적 결과입니다.
