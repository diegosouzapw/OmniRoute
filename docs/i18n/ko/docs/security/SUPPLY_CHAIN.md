OmniRoute는 npm + Docker 아티팩트를 게시합니다. 이러한 게이트는 모두 OSS로 제공되는 출처 증명,
인벤토리(SBOM), CVE 스캔 기능을 릴리스 워크플로에 통합합니다.
**권고 우선** 방침 — 현재는 결과만 보고하며, 첫 번째
그린 릴리스 이후 차단 방식으로 전환합니다.

| 게이트                | 도구                                           | 위치                          | 차단 여부        | 출력                                                       |
| --------------------- | ---------------------------------------------- | ----------------------------- | ---------------- | ---------------------------------------------------------- |
| SLSA 출처 증명(npm)   | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | 게시 실패 시에만 | npmjs 배지 / `npm audit signatures`                        |
| npm SBOM              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | 생성 실패 시에만 | 릴리스 자산 + 아티팩트                                     |
| 이미지 SBOM           | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (병합)   | 권고             | CycloneDX 아티팩트                                         |
| Trivy CVE (SARIF)     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (병합)   | 권고             | SARIF (HIGH+CRITICAL) → Security 탭                        |
| Trivy CRITICAL 게이트 | `aquasecurity/trivy-action`                    | `docker-publish.yml` (병합)   | **차단**         | 수정 가능한 CRITICAL에 대해 `exit-code: '1'`               |
| osv vulnCount         | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **차단**         | `metrics.vulnCount`를 래칫 방식으로 관리(`direction:down`) |
| OpenSSF Scorecard     | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | 권고             | SARIF → Security + 배지                                    |

이미지 CVE 래칫은 `docker-publish.yml`에서 **두 단계**를 사용합니다. SARIF 단계
(`HIGH,CRITICAL`, `exit-code: 0`)는 차단하지 않으면서 HIGH+CRITICAL 항목이 Security 탭에
계속 표시되도록 합니다. _CRITICAL 게이트_ 단계(`severity: CRITICAL`, `ignore-unfixed: true`,
`exit-code: 1`)는 **수정 버전이 제공되는** CRITICAL CVE가 있을 경우 릴리스를 실패 처리합니다. `ignore-unfixed`는
업스트림 패치가 없는 베이스 이미지 CVE 때문에 릴리스가 차단되는 것을 방지합니다.

## ⚠️ CVE 변동성(차단형 osv/Trivy 게이트)

osv와 Trivy는 의존성을 **지속적으로 증가하는** CVE 데이터베이스와 비교합니다. 의존성을
**전혀 변경하지 않은** PR도 기존 의존성에서 새로운 CVE가 공개되면
갑자기 실패할 수 있습니다(osv: 측정된 `vulnCount` > 기준값, Trivy: 이미지에서 수정 가능한 새로운
CRITICAL 발견). **이는 차단형 CVE 게이트에서 예상되는 운영 동작이며,
제품 회귀가 아닙니다.**

새로 공개된 CVE로 인해 osv 또는 Trivy가 실패할 경우 해결 방법은 다음과 같습니다.

1. **영향받는 의존성 버전 올리기**(권장) — `package.json`의
   `overrides`(전이 의존성)를 통해 패치된 버전으로 업그레이드하거나, 패치된 베이스를 사용해 이미지를 다시 빌드합니다.
2. **업스트림 수정 사항이 없는 경우:**
   - **osv:** 근거 메모 + 추적 이슈와 함께 `config/quality/quality-baseline.json`의
     `metrics.vulnCount` 기준값을 다시 설정합니다
     (`npm run quality:ratchet -- --update`는 전용 게이트를 처리하지 않으므로 값을
     직접 수정하고 `direction:down`을 유지합니다).
   - **Trivy:** 근거
     주석 + 추적 이슈와 함께 `.trivyignore`에 항목을 추가합니다(줄마다 CVE-ID 하나). `ignore-unfixed: true`는
     패치가 없는 CVE를 이미 자동으로 처리합니다.

두 게이트 모두 도구가 없거나 측정에
실패하면(osv-scanner가 PATH에 없음, osv.dev/네트워크에 연결할 수 없음, 잘못된 JSON) **정상적으로 건너뜁니다**(exit 0). **측정**
실패는 절대 차단하지 않으며, **측정된** 회귀만 차단합니다.

## 백로그: Scorecard 권고 → 차단

Scorecard 보고가 포함된 첫 번째 그린 릴리스 이후:

- Scorecard: 점수 래칫(측정된 점수를 고정하며, 점수가 낮아질 수 없음).

Phase 7 게이트(osv-scanner, gitleaks, actionlint+zizmor)를 보완합니다. zizmor는
워크플로 자체를 감사하고, Scorecard는 저장소의 전반적인 보안 태세를 측정합니다.
