권장 기준선을 최적화 기준으로 삼습니다.

## 규칙

- 커버리지 목표는 `tests/**`가 아닌 소스 파일에 적용됩니다.
- `open-sse/**`는 제품의 일부이며 범위에 계속 포함되어야 합니다.
- 새 코드는 변경된 영역의 커버리지를 낮추지 않아야 합니다.
- 구현 세부 사항보다 동작과 분기 결과를 테스트하는 것을 우선합니다.
- `src/lib/db/**`에서는 광범위한 모킹보다 임시 SQLite 데이터베이스와 작은 픽스처를 우선합니다.

## 현재 명령어 세트

- `npm run test:coverage`
  - 단위 테스트 스위트의 주요 소스 커버리지 게이트
  - `text-summary`, `html`, `json-summary`, `lcov` 생성
- `npm run coverage:report`
  - 최근 실행 결과를 바탕으로 상세한 파일별 보고서 생성
- `npm run test:coverage:legacy`
  - 과거 결과 비교 전용

## 래칫 정책

프로젝트가 충분한 여유를 두고 다음 마일스톤을 실제로 초과한 후에만 `npm run test:coverage` 임계값을 업데이트합니다.

**현재 게이트:** `npm run test:coverage`는 **구문 60 / 라인 60 / 함수 60 / 분기 60**을 적용합니다(이 지표는 Quality-Gates 6A.1 단계에서 기준이 재설정되었습니다. 이전의 82.58% 기준선은 테스트 파일을 집계하고 `open-sse`를 제외했기 때문에 부풀려진 수치였습니다). `test:coverage:legacy` 명령은 과거 비교를 위해 기존 50/50/50 지표를 유지합니다.

최신 보고서에 대해 임시로 임계값을 검사하려면 다음을 사용합니다.

```bash
node scripts/check/test-report-summary.mjs --threshold 75
```

권장 래칫 순서(순서는 `구문-라인 / 분기 / 함수`):

1. 55/60/55
2. 60/62/58
3. 65/64/62
4. 70/66/66
5. 75/70/72 <-- 현재 게이트 (75/70/75)
6. 80/75/78
7. 85/80/84
8. 90/85/88

분기 커버리지가 연속 두 번의 실행에서 78%를 넘으면 다음 래칫 목표는 `80/75/78`입니다.

## 알려진 격차

현재 커버리지 명령은 기본 Node 단위 테스트 스위트를 측정하며, `open-sse`를 포함해 해당 스위트에서 실행되는 소스도 포함합니다. 아직 Vitest 커버리지를 하나의 통합 보고서로 병합하지는 않습니다. 이 병합은 나중에 수행할 가치가 있지만, 60%에서 80%로 높이는 작업을 시작하는 데 방해가 되지는 않습니다.
