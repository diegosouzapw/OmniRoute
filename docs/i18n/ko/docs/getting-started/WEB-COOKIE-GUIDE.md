웹 쿠키 공급자를 사용하면 API 키 대신 기존 브라우저 세션을 통해 OmniRoute에서 AI 서비스를 이용할 수 있습니다. 웹사이트를 통해 이미 서비스에 접근할 수 있고, OmniRoute에서도 동일한 인증 세션을 사용하려는 경우 유용합니다.

API 키 공급자와 달리 웹 쿠키 공급자는 브라우저가 웹사이트에 전송하는 자격 증명을 사용하여 인증합니다.

---

# 시작하기 전에

> **중요:** 자격 증명은 항상 브라우저의 쿠키 저장소가 **아닌**, **실시간 네트워크 요청**에서 복사하세요.

잘못된 위치에서 쿠키를 복사하여 발생하는 인증 문제가 많습니다.

## 쿠키 저장소에서 복사하지 마세요

대부분의 브라우저는 다음 위치에서 저장된 쿠키를 표시합니다.

```
DevTools
→ Application(또는 Storage)
→ Cookies
```

이러한 쿠키가 올바르게 보이더라도 다음과 같은 문제가 있을 수 있습니다.

- 오래된 쿠키
- 불완전한 쿠키
- 인증된 요청에만 전송되는 쿠키 누락

이 값을 사용하면 유효해 보이더라도 인증에 실패할 수 있습니다.

## 실시간 요청에서 복사하기

대신 성공한 요청에서 쿠키를 가져오세요.

```
DevTools
→ Network
→ 페이지 새로 고침
→ 채팅 또는 대화 요청 열기
→ Request Headers
→ Cookie
```

`Cookie` 요청 헤더에는 브라우저가 성공적으로 사용한 정확한 인증 정보가 포함되어 있습니다.

대부분의 웹 쿠키 공급자에서는 이 값을 OmniRoute에 붙여넣어야 합니다.

---

# 일반 설정

대부분의 웹 쿠키 공급자에서 설정 절차는 동일합니다.

1. 공급자의 웹사이트에 로그인합니다.
2. 브라우저의 개발자 도구를 엽니다.
3. **Network** 탭을 엽니다.
4. 페이지를 새로 고칩니다.
5. 인증된 채팅 또는 대화 요청을 엽니다.
6. 필요한 인증 자격 증명을 복사합니다.
7. OmniRoute를 엽니다.
8. **Providers → Add Provider**로 이동합니다.
9. 사용할 웹 쿠키 공급자를 선택합니다.
10. 자격 증명을 붙여넣습니다.
11. **Test Connection**을 클릭합니다.
12. 공급자를 저장합니다.

필요한 정확한 자격 증명은 공급자에 따라 다릅니다.

---

# 공급자 자격 증명 형식

웹사이트마다 인증 정보를 저장하는 방식이 다릅니다. 일부는 쿠키만 필요하지만, 다른 웹사이트는 추가 헤더나 토큰이 필요할 수 있습니다.

| 공급자                          | 자격 증명 형식                | 공급자 가이드                    |
| ------------------------------- | ----------------------------- | -------------------------------- |
| Claude Web                      | 전체 Cookie 요청 헤더         | `docs/providers/CLAUDE_WEB.md`   |
| ChatGPT Web (Codex)             | 전체 Cookie 헤더              | `docs/providers/CHATGPT_WEB.md`  |
| Gemini Web                      | _(확인 필요)_                 |                                  |
| Copilot Web                     | _(확인 필요)_                 | `docs/providers/COPILOT-M365.md` |
| Microsoft 365 Copilot (BizChat) | WS access_token + chathubPath | `docs/providers/COPILOT-M365.md` |
| Grok Web                        | _(확인 필요)_                 |                                  |
| ...                             | ...                           | ...                              |

> 새로운 웹 쿠키 공급자가 추가되거나 기존 공급자의 인증 요구 사항이 변경되면 이 표를 업데이트하세요.

# 웹 쿠키 공급자가 지원하는 기능과 지원하지 않는 기능

웹 쿠키 공급자는 웹사이트의 채팅 인터페이스를 재사용합니다. 공식 API와 동일한 기능을 제공하지는 **않습니다**.

## 지원됨

- 기존 브라우저 세션을 사용한 인증
- 계정을 통해 이용 가능한 모델에 접근
- 채팅 응답 스트리밍
- API 키 불필요

## 지원되지 않음

- 함수 호출
- 도구 호출
- 자동 파일 편집
- 에이전트형 IDE 워크플로
- API 전용 기능

이는 예상된 동작이며 버그가 **아닙니다**.

도구 실행, 자동 파일 편집 또는 기타 에이전트 워크플로가 필요한 경우 웹 쿠키 공급자 대신 **API 키 공급자**를 사용하세요.

---

# 유효성 검사 관련 주의 사항

**Test Connection** 또는 쿠키 유효성 검사에 성공하더라도 제공된 자격 증명의 형식이 예상 형식과 일치하는 것으로 보인다는 점만 확인됩니다.

Issue #7857이 해결되기 전까지는 유효성 검사에 성공해도 공급자 인증이 성공한다고 **보장할 수 없습니다**.

인증이 계속 실패하면 브라우저 쿠키 저장소가 아니라 실시간 네트워크 요청에서 자격 증명을 복사했는지 확인하세요.

---

# 문제 해결

## 인증 실패

자격 증명을 다음 위치에서 복사했는지 확인하세요.

```
Network
→ Request Headers
→ Cookie
```

다음 위치에서 복사하면 **안 됩니다**.

```
Application
→ Cookies
```

---

## 브라우저에서는 쿠키가 작동하지만 OmniRoute에서는 작동하지 않음

일부 공급자는 인증된 요청 중에만 전송되는 쿠키를 포함합니다.

대화를 성공적으로 연 후 새로운 네트워크 요청에서 자격 증명을 다시 복사하세요.

---

## 세션 만료

웹 쿠키 공급자는 기존 브라우저 세션을 사용합니다.

브라우저 세션이 만료되거나 로그아웃하면 새로운 자격 증명 세트를 복사해야 합니다.

---

## 연결 테스트는 통과하지만 요청은 실패함

Issue #7857이 해결되기 전까지는 유효성 검사를 통과해도 인증 요청의 성공이 보장되지 않습니다.

추가로 문제를 해결하기 전에 새로운 인증 요청에서 자격 증명을 다시 복사하세요.

---

# 공급자 예시

공급자별 전체 안내는 다음 문서를 참조하세요.

- **Claude Web** — `docs/providers/CLAUDE_WEB.md`

Claude Web 가이드는 웹 쿠키 공급자의 전체 설정 절차를 보여주며 참조 구현 역할을 합니다.

---

# 권장 사항

- 새로운 인증 요청에서 자격 증명을 복사하세요.
- 오래된 쿠키를 재사용하지 마세요.
- 웹 쿠키 공급자를 사용하는 동안 브라우저 세션을 활성 상태로 유지하세요.
- 복사한 쿠키를 민감한 자격 증명으로 취급하세요.
- 함수 호출이나 에이전트 워크플로가 필요한 경우 API 키 공급자를 사용하세요.
