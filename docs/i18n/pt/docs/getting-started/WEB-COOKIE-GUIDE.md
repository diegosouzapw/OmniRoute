Os fornecedores de Web Cookie permitem que o OmniRoute utilize um serviço de IA através da sua sessão existente no navegador, em vez de uma chave de API. São úteis quando já tem acesso a um serviço através do respetivo site e pretende que o OmniRoute utilize a mesma sessão autenticada.

Ao contrário dos fornecedores com chave de API, os fornecedores de Web Cookie autenticam-se através das credenciais que o navegador envia para o site.

---

# Antes de Começar

> **Importante:** copie sempre as credenciais a partir de um **pedido de rede em curso**, **não** a partir do armazenamento de cookies do navegador.

Muitos problemas de autenticação são causados pela cópia de cookies a partir do local errado.

## NÃO copie a partir do Armazenamento de Cookies

A maioria dos navegadores apresenta os cookies armazenados através de:

```
DevTools
→ Application (ou Storage)
→ Cookies
```

Embora estes cookies pareçam corretos, podem estar:

- desatualizados
- incompletos
- sem cookies que são enviados apenas em pedidos autenticados

A utilização destes valores pode causar falhas de autenticação, mesmo que pareçam válidos.

## Copiar a partir de um Pedido em Curso

Em vez disso, utilize os cookies de um pedido bem-sucedido:

```
DevTools
→ Network
→ Atualize a página
→ Abra um pedido de chat ou de conversa
→ Request Headers
→ Cookie
```

O cabeçalho de pedido `Cookie` contém as informações de autenticação exatas que o navegador utilizou com êxito.

Para a maioria dos fornecedores de Web Cookie, este é o valor que deve ser colado no OmniRoute.

---

# Configuração Geral

O processo de configuração é o mesmo para a maioria dos fornecedores de Web Cookie.

1. Inicie sessão no site do fornecedor.
2. Abra as Ferramentas de Programador do navegador.
3. Abra o separador **Network**.
4. Atualize a página.
5. Abra um pedido autenticado de chat ou de conversa.
6. Copie as credenciais de autenticação necessárias.
7. Abra o OmniRoute.
8. Aceda a **Providers → Add Provider**.
9. Selecione o seu fornecedor de Web Cookie.
10. Cole as credenciais.
11. Clique em **Test Connection**.
12. Guarde o fornecedor.

As credenciais exatas necessárias dependem do fornecedor.

# O Que os Fornecedores de Web Cookie Podem e Não Podem Fazer

Os fornecedores de Web Cookie reutilizam a interface de chat de um site. **Não** fornecem as mesmas capacidades que as APIs oficiais.

## Suportado

- Autenticação através da sua sessão existente no navegador
- Acesso aos modelos disponíveis através da sua conta
- Transmissão contínua de respostas do chat
- Não é necessária uma chave de API

## Não Suportado

- Chamada de funções
- Chamada de ferramentas
- Edição automática de ficheiros
- Fluxos de trabalho agênticos em IDE
- Funcionalidades exclusivas da API

Este é o comportamento esperado e **não** é um erro.

Se necessitar de execução de ferramentas, edição automática de ficheiros ou outros fluxos de trabalho com agentes, utilize um **fornecedor com chave de API** em vez de um fornecedor de Web Cookie.

---

# Limitação da Validação

Um **Test Connection** bem-sucedido ou uma validação de cookies bem-sucedida apenas confirma que as credenciais fornecidas parecem estar no formato esperado.

Até que o Problema #7857 seja resolvido, uma validação bem-sucedida **não garante** que o fornecedor consiga efetuar a autenticação com êxito.

Se a autenticação continuar a falhar, confirme que copiou as credenciais a partir de um pedido de rede em curso e não do armazenamento de cookies do navegador.

---

# Resolução de Problemas

## Falha na Autenticação

Confirme que as credenciais foram copiadas de:

```
Network
→ Request Headers
→ Cookie
```

e **não** de:

```
Application
→ Cookies
```

---

## O Cookie Funciona no Navegador, mas Não no OmniRoute

Alguns fornecedores incluem cookies que são enviados apenas durante pedidos autenticados.

Volte a copiar as credenciais a partir de um novo pedido de rede depois de abrir uma conversa com êxito.

---

## Sessão Expirada

Os fornecedores de Web Cookie utilizam a sua sessão existente no navegador.

Se a sessão do navegador expirar ou se terminar sessão, terá de copiar um novo conjunto de credenciais.

---

## O Teste de Ligação é Bem-Sucedido, mas os Pedidos Falham

Até que o Problema #7857 seja resolvido, passar na validação não garante que o pedido de autenticação seja bem-sucedido.

Volte a copiar as suas credenciais a partir de um novo pedido autenticado antes de continuar a resolução de problemas.

# Boas Práticas

- Copie as credenciais a partir de um novo pedido autenticado.
- Evite reutilizar cookies antigos.
- Mantenha a sessão do navegador ativa enquanto utiliza fornecedores de Web Cookie.
- Trate os cookies copiados como credenciais confidenciais.
- Utilize fornecedores com chave de API quando necessitar de chamadas de funções ou de fluxos de trabalho com agentes.
