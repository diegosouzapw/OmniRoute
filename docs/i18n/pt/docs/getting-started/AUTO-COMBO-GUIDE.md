> **TL;DR**: Defina o seu modelo como `auto` e o OmniRoute selecionará automaticamente o melhor fornecedor de IA para cada pedido. Não é necessária qualquer configuração.

---

## O que faz

Em vez de escolher um modelo de IA específico (como GPT-4o ou Claude), pode deixar que o OmniRoute **selecione automaticamente o melhor** para cada pedido. Tem em consideração:

- **Estado** — O fornecedor está a funcionar neste momento?
- **Velocidade** — Qual é a sua rapidez?
- **Custo** — Quanto custa?
- **Qualidade** — É adequado para este tipo de tarefa?
- **Capacidade** — Ainda tem quota disponível?

O OmniRoute atribui uma pontuação a todos os seus fornecedores ligados e seleciona o melhor. Se este falhar, tenta automaticamente o seguinte.

---

## Início rápido

**Passo 1**: Defina o seu modelo como `auto` no seu IDE ou CLI:

```
model: "auto"
```

**Passo 2**: Já está! O OmniRoute trata do resto.

**Passo 3** (opcional): Utilize uma variante para tarefas específicas:

```
model: "auto/coding"    # Melhor para código
model: "auto/fast"      # Resposta mais rápida
model: "auto/cheap"     # Opção mais económica
```

---

## Que opção "auto" devo utilizar?

| Se pretender...           | Utilize        | Ideal para                            | Como funciona                                |
| ------------------------- | -------------- | ------------------------------------- | -------------------------------------------- |
| **Melhor no geral**       | `auto`         | Perguntas gerais, conversação         | Equilibra velocidade, custo e qualidade      |
| **Melhor código**         | `auto/coding`  | Escrever código, depuração            | Seleciona modelos adequados para programação |
| **Resposta mais rápida**  | `auto/fast`    | Respostas rápidas, baixa latência     | Dá prioridade à velocidade acima de tudo     |
| **Opção mais económica**  | `auto/cheap`   | Poupar dinheiro                       | Seleciona o fornecedor mais económico        |
| **Modelo mais avançado**  | `auto/smart`   | Tarefas complexas                     | Prioriza a qualidade + explora novos modelos |
| **Maior disponibilidade** | `auto/offline` | Quando os fornecedores estão ocupados | Seleciona fornecedores com maior capacidade  |

### Exemplos

```bash
# Conversação geral — equilibrada
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'

# Geração de código — prioridade à qualidade
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/coding","messages":[{"role":"user","content":"Write a Python function"}]}'

# Resposta rápida — prioridade à velocidade
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/fast","messages":[{"role":"user","content":"What is 2+2?"}]}'
```

## Como funciona (versão simples)

Quando envia um pedido com `model: "auto"`, o OmniRoute:

1. **Analisa todos os seus fornecedores ligados** — Todos os fornecedores que adicionou (OpenAI, Anthropic, Google, etc.)
2. **Atribui uma pontuação a cada um**, ponderando, entre outros aspetos:
   - Está a funcionar? (estado)
   - Tem capacidade? (quota)
   - Quanto custa? (preço)
   - Qual é a sua rapidez? (velocidade)
   - É adequado para esta tarefa? (qualidade)
3. **Seleciona o melhor** — O fornecedor com a pontuação mais elevada recebe o seu pedido
4. **Recupera automaticamente** — Se este falhar, o OmniRoute tenta automaticamente o seguinte

### O sistema de pontuação

Cada fornecedor recebe uma pontuação de 0 a 1. Quanto mais elevada for a pontuação, mais adequado será.

| Fator              | Peso | O que significa                                                 |
| ------------------ | ---- | --------------------------------------------------------------- |
| Estado             | 20%  | O fornecedor está a funcionar? (estado do circuit breaker)      |
| Quota              | 15%  | Ainda tem capacidade disponível?                                |
| Custo              | 15%  | Quanto custa? (mais barato = pontuação mais elevada)            |
| Velocidade         | 12%  | Qual é a sua rapidez? (menor latência = pontuação mais elevada) |
| Adequação à tarefa | 8%   | É adequado para este tipo de tarefa?                            |
| Estabilidade       | 5%   | É consistente? (baixa taxa de erros)                            |
| Nível              | 5%   | Nível da conta (Ultra > Pro > Free)                             |
| Outros             | 20%  | Afinidade de contexto, densidade de ligações, etc.              |

### Como as variantes alteram a pontuação

Cada variante utiliza ponderações diferentes:

| Variante       | Dá prioridade a        | Principais ponderações          |
| -------------- | ---------------------- | ------------------------------- |
| `auto`         | Equilíbrio             | health=20%, quota=15%, cost=15% |
| `auto/coding`  | Qualidade              | taskFit=37%, stability=15%      |
| `auto/fast`    | Velocidade             | latency=32%, health=28%         |
| `auto/cheap`   | Custo                  | cost=37%                        |
| `auto/smart`   | Qualidade + Exploração | taskFit=37%, exploration=10%    |
| `auto/offline` | Capacidade             | quota=37%, health=28%           |

## Como Lida com Falhas

O OmniRoute tem **três camadas de proteção**:

### 1. Alternativa Automática

Se o melhor fornecedor falhar, o OmniRoute tenta automaticamente o seguinte. Não precisa de fazer nada.

### 2. Autorrecuperação

Se um fornecedor continuar a falhar:

- **Pontuação < 0,2** → Excluído durante 5 minutos
- **Disjuntor aberto** → Excluído automaticamente
- **Mais de 50% dos fornecedores indisponíveis** → Modo de incidente (sem exploração)

### 3. Alternativa de Emergência

Se todos os fornecedores falharem, o OmniRoute encaminha os pedidos para fornecedores gratuitos estáveis (como o Kiro ou o Qoder) como último recurso.

---

## Suporte para Várias Contas

Se tiver várias contas para o mesmo fornecedor (por exemplo, duas chaves da OpenAI), o OmniRoute trata cada uma como um **candidato separado**. Isto significa:

- A conta A ainda tem quota disponível → utilizá-la
- A conta B está sujeita a um limite de pedidos → ignorá-la
- A conta C é mais barata → dar-lhe preferência

Cada conta é pontuada de forma independente com base no respetivo estado, quota e velocidade.

---

## Exploração por Bandit

O OmniRoute **explora** ocasionalmente novos fornecedores para descobrir melhores opções:

- **Predefinição**: 5% dos pedidos são enviados para fornecedores aleatórios
- **Auto/smart**: taxa de exploração de 10%
- **Desativada** quando mais de 50% dos fornecedores estão indisponíveis

Isto ajuda o OmniRoute a determinar quais os fornecedores que funcionam melhor para os seus padrões de utilização.

## Perguntas Frequentes

### "Irá escolher sempre o modelo mais caro?"

**Não.** Por predefinição, o custo representa apenas 15% da pontuação. Um fornecedor barato, rápido e operacional pode superar um mais caro. Utilize `auto/cheap` se quiser dar ainda mais prioridade ao custo.

### "O que acontece se um fornecedor ficar indisponível?"

O OmniRoute ignora-o automaticamente e tenta o seguinte. Se um fornecedor continuar a falhar, é temporariamente excluído (durante 5 a 30 minutos). Não precisa de fazer nada.

### "Posso ver qual foi o fornecedor utilizado?"

Verifique os cabeçalhos da resposta — o OmniRoute inclui o fornecedor e o modelo utilizados em cada resposta.

### "O sistema aprende com a minha utilização?"

Sim! O sistema de pontuação utiliza dados históricos (latência, taxas de erro e taxas de sucesso) para tomar decisões melhores ao longo do tempo.

### "Qual é a diferença entre `auto` e `auto/smart`?"

- `auto` — Equilibrado, 5% de exploração
- `auto/smart` — Prioriza a qualidade (as mesmas ponderações que `auto/coding`), 10% de exploração

Utilize `auto/smart` quando pretender a melhor qualidade e não se importar com explorações ocasionais.

### "Posso forçar a utilização de um fornecedor específico?"

Sim! Utilize uma combinação com a estratégia `priority` em vez de `auto` e, em seguida, envie o **nome exato** da combinação no campo `model` (por exemplo, `model: "my-combo"` — não `auto`). Consulte a [Referência Técnica](../routing/AUTO-COMBO.md) para obter mais detalhes.

### "Qual é a diferença em relação ao round-robin?"

O round-robin percorre os fornecedores sequencialmente. A combinação automática **atribui uma pontuação a cada fornecedor** e escolhe o melhor. É mais inteligente — tem em conta o estado, a velocidade, o custo e a qualidade.
