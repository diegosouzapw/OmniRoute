## 1. Antigravity vs Antigravity CLI (agy)

Ambos os fornecedores partilham o **mesmo backend da Google** — cliente OAuth, renovação de tokens, endpoints e contas Google idênticos. A diferença está nos modelos que são apresentados.

> Consulte o [anúncio da CLI do Antigravity](https://antigravity.google/blog/introducing-google-antigravity-cli) para ver a comparação oficial da Google.

| Aspeto                             | `antigravity` (IDE)                                             | `agy` (CLI)                                                           |
| ---------------------------------- | --------------------------------------------------------------- | --------------------------------------------------------------------- |
| **Produto da Google**              | Antigravity 2.0 / Antigravity IDE                               | Antigravity CLI                                                       |
| **Backend**                        | Mesma API Google Cloud Code                                     | Mesma API Google Cloud Code                                           |
| **OAuth / Token**                  | Mesmo cliente, mesma renovação                                  | Mesmo cliente, mesma renovação                                        |
| **Catálogo de modelos**            | Lista selecionada estática (integrada diretamente no OmniRoute) | Consultado em tempo real na Google através de `:fetchAvailableModels` |
| **Modelos Claude**                 | Sonnet 4.6, Opus 4.6 (4 variantes de cada)                      | Sonnet 4.6, Opus 4.6 (4 variantes de cada)                            |
| **Nomenclatura do Gemini**         | Rótulos simples (Low/Medium/High)                               | IDs do upstream (extra-low/low/agent)                                 |
| **Modelos adicionais**             | `gpt-oss-120b-medium`                                           | Pode incluir modelos adicionais da Google                             |
| **Caso de utilização predefinido** | Integração com IDE (VS Code, JetBrains)                         | Acesso por CLI / API                                                  |
| **Quota**                          | Partilhada com o agy (mesma conta Google)                       | Partilhada com o antigravity (mesma conta Google)                     |

**Modelos disponíveis (verificados experimentalmente, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (vários níveis de raciocínio)
- Claude: Sonnet 4.6, Opus 4.6 (cada um com variantes default/low/medium/high)
- Outros: GPT-OSS 120B Medium
- **O Claude Sonnet 5 NÃO está disponível** — apenas são suportadas as variantes 4.6

**Por que motivo o catálogo de modelos difere**: A CLI da Google é «otimizada para velocidade e baixo overhead» e «co-otimizada com os modelos Gemini» (de acordo com o blogue oficial da Google). O produto Web/IDE é «otimizado para abrangência». A CLI utiliza `:fetchAvailableModels` para descobrir modelos dinamicamente, enquanto o IDE utiliza uma lista selecionada estática.

**Na prática**: Utilize o prefixo `agy/` para modelos Gemini (por exemplo, `agy/gemini-3.7-flash-high`). Utilize `antigravity/` para a lista selecionada estática. Ambos acedem ao mesmo backend da Google, mas apresentam nomenclaturas de modelos diferentes. A quota é partilhada — a utilização de qualquer um dos fornecedores é contabilizada nos limites da mesma conta Google.

## 2. Google One AI Pro: Sistema de quotas

> Consulte [Documentação do Antigravity: Planos](https://antigravity.google/docs/plans) para obter detalhes oficiais sobre as quotas e [Alterações aos planos do Antigravity](https://antigravity.google/blog/changes-to-antigravity-plans) para obter as atualizações de preços mais recentes.

O Google Antigravity utiliza uma **quota de duas camadas** baseada no «Trabalho realizado» (peso computacional), e não no número de mensagens.

### As duas camadas

| Camada                    | O que é                                  | Ciclo de renovação                                                                             |
| ------------------------- | ---------------------------------------- | ---------------------------------------------------------------------------------------------- |
| **Ciclo de 5 horas**      | Reserva imediata de «trabalho realizado» | É reposta 5 horas após o primeiro pedido de uma sessão                                         |
| **Limite base de 7 dias** | Limite máximo semanal                    | Sobrepõe-se à renovação de 5 horas se for atingido; bloqueia até ao período de 7 dias seguinte |

**Como é calculado o «Trabalho realizado»**: as tarefas que exigem uma utilização intensiva de agentes (por exemplo, «Refatorizar todo este repositório») esgotam a quota muito mais rapidamente do que as tarefas simples (por exemplo, «Corrigir esta função»). Não existe um painel em tempo real que mostre o consumo.

### Níveis dos planos

| Plano        | Preço       | Quota                                        | Limite semanal                               |
| ------------ | ----------- | -------------------------------------------- | -------------------------------------------- |
| Free         | $0          | Quota significativa, reposta semanalmente    | Sim                                          |
| AI Pro       | $19.99/mês  | Quota elevada, renovação contínua de 5 horas | Sim (sobrepõe-se às 5 horas se for atingido) |
| AI Ultra 5x  | $99.99/mês  | 5x a quota do Pro                            | Sem limite semanal                           |
| AI Ultra 20x | $199.99/mês | 20x a quota do Pro                           | Sem limite semanal                           |

### Modelos Gemini vs. não Gemini

- **Modelos Gemini** (Flash + Pro): partilham um único limite de utilização, consumido de acordo com os preços da API. Se o Flash for 8x mais barato do que o Pro, obtém 8x mais tokens do Flash.
- **Modelos não Gemini** (Claude, GPT-OSS): têm limites de utilização **separados**. Podem continuar disponíveis mesmo quando o Gemini está bloqueado.

### Créditos de IA (utilização excedentária)

> Consulte [Créditos de IA do Google One](https://support.google.com/googleone/answer/14534406) para saber como funcionam os créditos.

Quando a quota base se esgota:

- **Nunca**: aguarda que a quota seja reposta; apresenta «Quota base do modelo atingida»
- **Sempre**: utiliza automaticamente créditos de IA; volta à quota base quando esta for reposta

Os créditos são adquiridos separadamente e deduzidos de acordo com os preços padrão da API.

### Detalhes importantes

- A quota é **partilhada ao nível da conta** — a mesma conta Google no Antigravity IDE, CLI e OmniRoute partilha uma única reserva de quota
- Cada conta Google tem a sua própria quota independente — várias contas = várias reservas de quota
- Os utilizadores do AI Pro relataram **bloqueios de 7 dias** em vez de reposições após 5 horas quando o limite base semanal é atingido (a Google confirmou que isto é intencional em períodos de elevada procura)

**Quando a quota da sua conta se esgota**: o OmniRoute tenta novamente, de forma automática, com a conta disponível seguinte na rota combinada. Não é necessária qualquer intervenção manual.

## 3. Como obter um projectId

Cada ligação antigravity/agy necessita de um `projectId` do Google Cloud Code. Sem este, o endpoint `/v1internal:models` devolve 404.

### Método A: Automático (recomendado)

O OmniRoute trata deste processo automaticamente. Quando adiciona uma nova conta Google através do OAuth do Dashboard:

1. O OmniRoute atualiza o token
2. Chama `loadCodeAssist` para descobrir o projectId
3. Se não existir nenhum projeto, chama `onboardUser` para criar um
4. Tenta novamente `loadCodeAssist` para obter o projectId recém-criado
5. Guarda-o na base de dados

**Isto funciona para a maioria das contas** — não são necessários passos manuais.

### Método B: Manual através da CLI agy

Se a deteção automática falhar (consulte a Secção 5 para saber quando isto acontece):

```bash
# Instalar a CLI agy (caso ainda não esteja instalada)
npm install -g @anthropic-ai/agy

# Iniciar sessão com a sua conta Google
agy login

# Selecionar a conta que necessita de integração
# Isto aciona o registo no Cloud Code e atribui um projectId
```

Depois de `agy login` ser concluído com êxito, atualize o token no Dashboard do OmniRoute. O projectId será detetado automaticamente.

### Como verificar

Verifique a base de dados:

```bash
# Dentro do contentor do OmniRoute
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Ou verifique os registos:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. URI de redirecionamento OAuth

### O problema

O Google OAuth requer um URI de redirecionamento válido. Por predefinição, o OmniRoute utiliza `http://127.0.0.1:20128/callback` (loopback). Isto funciona para compilações locais, mas **falha em implementações remotas** (por exemplo, num servidor acedido através de um IP da LAN).

O Google rejeita URIs de redirecionamento que:

- Utilizem endereços IP (tem de ser um domínio terminado em `.com`, `.org`, etc.)
- Não correspondam aos URIs de redirecionamento registados na configuração do cliente OAuth

### A solução

**Opção A: Utilizar o fluxo OAuth integrado (predefinição)**

- Funciona quando acede ao OmniRoute a partir de `localhost` ou `127.0.0.1`
- Não é necessária qualquer configuração

**Opção B: Credenciais OAuth personalizadas**

- Defina `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` no seu ambiente
- Forneça as suas próprias credenciais OAuth do Google:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Registe `https://your-domain.com/callback` como um URI de redirecionamento autorizado na Google Cloud Console

**Opção C: Utilizar a CLI agy para o início de sessão inicial**

- Execute `agy login` na máquina que irá aceder ao OmniRoute
- O fluxo OAuth é concluído localmente e os tokens são armazenados
- Importe a ligação para o OmniRoute através do Dashboard

### Limitações

- As credenciais OAuth personalizadas requerem um nome de domínio (o Google não aceita endereços IP como URIs de redirecionamento)
- Se não tiver um domínio, utilize antes a Opção A ou C

## 5. Resolução de problemas: quando a configuração automática falha

O OmniRoute trata automaticamente da deteção do projectId e da integração inicial para a maioria das contas. Quando o processo falha, a causa principal costuma ser uma das seguintes:

### A região da conta está bloqueada

**Sintoma**: `agy login` devolve "Eligibility check failed: Your current account is not eligible for Antigravity, because it is not currently available in your location."

**Causa principal**: As contas Google têm um campo interno "Country Association" definido no momento do registo. A CLI agy e a API Cloud Code verificam este campo de forma rigorosa — ao contrário do Gemini na Web, que verifica apenas o seu IP atual.

> Para verificar ou alterar a região associada à sua conta, visite o [Formulário de Associação de País da Google](https://policies.google.com/country-association-form).

**Por que motivo o Gemini na Web funciona, mas o agy não**:

- Gemini na Web / Google One: verifica apenas o IP atual (o proxy funciona)
- CLI agy / API Cloud Code: lê o campo interno Country Association (o proxy não ajuda)

**Correção**:

1. Visite o [Formulário de Associação de País da Google](https://policies.google.com/country-association-form) enquanto utiliza um IP dos EUA
2. Envie um pedido de alteração de região (selecione "I live in a different country")
3. Aguarde entre 1 e 24 horas para que a Google processe o pedido e envie uma notificação por e-mail
4. Depois disso, `agy login` deverá funcionar

### A conta não tem um projeto do Cloud Code

**Sintoma**: Os registos apresentam `loadCodeAssist returned no project id` e `onboardUser failed (400)`.

**Causa principal**: A conta nunca foi registada no Google Cloud Code e a integração automática falhou.

**Correção**: Execute `agy login` manualmente para iniciar o registo no Cloud Code e, em seguida, atualize o token no Dashboard do OmniRoute.

### Token expirado ou revogado

**Sintoma**: Erros 401 nos registos ou mensagens "Token has expired".

**Correção**: Atualize o token em Dashboard → Providers → agy → Clique no ícone de atualização. Se o próprio token de atualização tiver sido revogado, terá de voltar a autenticar-se através de OAuth.

## Fluxograma de decisão

```
A conta não funciona?
│
├─ Tem um projectId na base de dados?
│  ├─ SIM → O problema está noutro local (token expirado, limite de pedidos, etc.)
│  └─ NÃO ↓
│
├─ A Associação de país da conta está definida para uma região restrita?
│  ├─ SIM → Altere a região no Formulário de associação de país da Google
│  │         (https://policies.google.com/country-association-form)
│  │         Aguarde entre 1 e 24 horas e tente novamente
│  └─ NÃO ↓
│
├─ A conta tem uma subscrição do Google One AI Pro?
│  ├─ NÃO → Subscreva primeiro em one.google.com
│  └─ SIM ↓
│
├─ Tente a deteção automática (atualize o token no Painel)
│  ├─ Funciona → Concluído
│  └─ Continua a falhar ↓
│
└─ Manual: Execute `agy login` na máquina
   ├─ Funciona → Atualize o token no Painel; o projectId será detetado
   └─ Falha → Verifique a mensagem de erro; provavelmente é um problema de região ou subscrição
```
