**OmniCopilot** coloca todos os modelos disponibilizados pelo OmniRoute no seletor de modelos
_nativo_ do GitHub Copilot Chat. Sem uma segunda barra lateral, sem uma interface de chat separada — o modo de agente do Copilot, a invocação de ferramentas,
os servidores MCP e as instruções personalizadas continuam a funcionar, simplesmente utilizando o modelo que escolher.

|                          |                                                                                                                                                 |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Instalar (VS Code)**   | [Marketplace → `diegosouzapw.omnicopilot`](https://marketplace.visualstudio.com/items?itemName=diegosouzapw.omnicopilot)                        |
| **Instalar (forks)**     | [Open VSX](https://open-vsx.org/extension/diegosouzapw/omnicopilot) — Cursor, Windsurf, VSCodium, Theia, code-server, Gitpod, Antigravity, Kiro |
| **Código-fonte / erros** | [github.com/diegosouzapw/OmniCopilot](https://github.com/diegosouzapw/OmniCopilot) (MIT)                                                        |
| **Requer**               | VS Code 1.104+                                                                                                                                  |

> **Não é necessária uma subscrição do Copilot.** Desde o VS Code 1.122, um fornecedor de modelos de linguagem funciona
> sem iniciar sessão no GitHub e sem qualquer plano do Copilot. As conclusões inline e as
> funcionalidades baseadas em embeddings permanecem fora da API do fornecedor e continuam a exigir o Copilot.

## Configuração

1. **Execute o OmniRoute** — `npm install -g omniroute && omniroute` (painel em `http://localhost:20128`).
2. **Instale a extensão** — pesquise "OmniRoute" na vista Extensões.
3. **Escolha um modelo** — Copilot Chat → seletor de modelos → **Gerir Modelos…** → **OmniRoute** e, em seguida, selecione
   o que pretende.

Não é necessário configurar nada quando o OmniRoute é executado na porta predefinida. Para uma instância remota, abra o
**ícone do OmniRoute na Barra de Atividade** (ou execute `OmniRoute: Manage Connection`) e defina:

- **URL do servidor** — a raiz do servidor, por exemplo, `http://192.168.0.15:20128`. O sufixo `/v1` é
  acrescentado pela extensão; não o inclua.
- **Chave da API** — apenas quando o servidor define `REQUIRE_API_KEY`. É armazenada no porta-chaves do sistema operativo através do
  SecretStorage do VS Code, nunca em `settings.json`.

## O que será apresentado no seletor

A extensão não apresenta a carga útil não processada de `GET /v1/models` — esta é adaptada, e a contagem apresentada
é inferior ao tamanho do catálogo por duas razões deliberadas.

### Solicita um id por modelo

Por predefinição, `MODELS_CATALOG_PREFIX_MODE` está definido como **`dual`**, o que anuncia cada modelo duas vezes — uma
com o prefixo curto do alias e outra com o prefixo canónico do fornecedor — para que as configurações de clientes
mais antigos continuem a resolver ambas as formas:

```
cc/claude-sonnet-4-6        ← prefixo do alias
claude/claude-sonnet-4-6    ← prefixo canónico, mesmo modelo
```

A extensão solicita **`GET /v1/models?prefix=alias`** para receber um id por modelo, sem
alterar a definição global do servidor para os outros clientes. Numa instância de referência, isto reduziu
**2345 entradas para 1396 — 949 duplicados, sem perder qualquer modelo.**

Se preferir corrigir isto globalmente no servidor para _todos_ os clientes, defina o sinalizador de funcionalidade
`MODELS_CATALOG_PREFIX_MODE` como `alias` no painel. Consulte
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) para obter informações sobre o
parâmetro de consulta e a tabela de cada modo.

### Oculta modelos que não permitem conversar

O catálogo também inclui modelos de imagem, vídeo, áudio, reordenação, embedding e moderação. Estes são
sempre rejeitados num pedido de chat:

```
HTTP 400 — O modelo '<id>' é um modelo de geração de imagens e não pode ser utilizado em
/v1/chat/completions. Em alternativa, utilize POST /v1/images/generations.
```

por isso, são filtrados pelo respetivo campo `type` antes de chegarem ao seletor. **Os modelos da Responses API
são mantidos** — todas as entradas Codex / GPT-5.x anunciam `supported_endpoints: ["responses"]`,
e o OmniRoute converte-as para `/v1/chat/completions`, pelo que são perfeitamente utilizáveis.

### Fornecedores que nunca configurou

O catálogo inclui modelos de fornecedores com uma **ligação ativa**, além de todos os fornecedores **noAuth**
— os que não requerem chaves e que constituem grande parte do escalão gratuito. Isto é intencional. Para os ocultar,
adicione-os a `blockedProviders` nas definições do painel; nada muda na
extensão.

## Dashboard num interior de um separador do VS Code

`omnicopilot.dashboardOpen: "editor"` apresenta o dashboard do OmniRoute num separador do editor através do
Simple Browser, em vez de utilizar um browser externo. A incorporação é **opcional no servidor** através de
`DASHBOARD_ALLOW_EMBED=vscode`, que disponibiliza as páginas HTML com
`frame-ancestors 'self' vscode-webview:` em vez da predefinição `frame-ancestors 'none'` +
`X-Frame-Options: DENY`. A superfície da API (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) mantém os
cabeçalhos estritos em qualquer dos casos.

> ⚠️ **É um sinalizador de compilação, não de execução.** O Next.js compila `headers()` no manifesto
> de rotas, pelo que `next.config.mjs` lê a variável enquanto o bundle é compilado
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> Exportá-la antes de iniciar um servidor já compilado não altera nada — os cabeçalhos ficam incorporados.

```bash
# a variável tem de estar presente no comando de COMPILAÇÃO
DASHBOARD_ALLOW_EMBED=vscode npm run build        # ou npm run build:release
npm start
```

| Método de instalação       | É possível ativar a incorporação?                                                                                                               |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| A partir do código-fonte   | ✅ defina a variável no comando de compilação, como indicado acima                                                                              |
| `npm install -g omniroute` | ❌ o pacote publicado inclui um bundle pré-compilado — em alternativa, compile a partir do código-fonte                                         |
| Imagem Docker              | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — a imagem pré-compilada no Docker Hub não permite incorporação |

Sem uma compilação que permita a incorporação, a página recusa ser apresentada numa frame, a extensão deteta-o através dos
cabeçalhos da resposta e recorre ao browser externo — nada deixa de funcionar e a extensão informa-o uma vez.
Consulte [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) e o issue
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273).

## Configurar as suas outras ferramentas a partir do VS Code

**`OmniRoute: Configure Coding CLI`** utiliza a CLI `omniroute` para criar perfis prontos a utilizar
para Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code,
Kilo e Roo — as mesmas configurações descritas em
[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md). A chave da API é fornecida à CLI através da
variável de ambiente `OMNIROUTE_API_KEY`, nunca na linha de comandos.

## Resolução de problemas

| Sintoma                                                            | Causa / solução                                                                                                                                                                                                                                                                                                                  |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Não aparecem modelos OmniRoute no seletor                          | Não é possível aceder ao servidor. O ponto da barra de estado fica cinzento; execute `OmniRoute: Check Connection`. A deteção é silenciosa por predefinição e não disponibiliza modelos em vez de apresentar uma solicitação.                                                                                                    |
| Todos os modelos aparecem duas vezes                               | Está a utilizar uma versão do OmniCopilot anterior à 1.0.1 — atualize-a. A extensão agora solicita `?prefix=alias`.                                                                                                                                                                                                              |
| Um modelo de imagem/áudio estava listado e desapareceu             | Intencional desde a versão 1.0.1 — nunca conseguiria responder a um pedido de chat.                                                                                                                                                                                                                                              |
| O painel não aparece na Barra de Atividades                        | O VS Code move os contentores de vistas adicionais para o menu excedente **"…"** na parte inferior da Barra de Atividades, e um contentor ocultado através do botão direito do rato permanece oculto. Clique com o botão direito na Barra de Atividades → selecione **OmniRoute**, ou abra-o com `OmniRoute: Manage Connection`. |
| O dashboard abre no browser apesar do modo `editor`                | O servidor não foi **compilado** com `DASHBOARD_ALLOW_EMBED=vscode` (consulte acima) — defini-la durante o arranque numa instalação pré-compilada não produz qualquer efeito. O recurso ao browser externo é intencional.                                                                                                        |
| A lista de modelos está desatualizada após alterar os fornecedores | Execute `OmniRoute: Refresh Models` ou utilize a ligação ↻ no painel.                                                                                                                                                                                                                                                            |
