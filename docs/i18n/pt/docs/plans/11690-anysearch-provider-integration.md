## 1. Fonte de verdade do serviço (documentação oficial, verificada de forma cruzada)

- URL base: `https://api.anysearch.com` (REST) + `POST /mcp` (MCP, JSON-RPC 2.0).
- `POST /v1/search` - parâmetros: `query` (obrigatório), `max_results` (1-10, predefinição 10), `tag` (encaminhamento vertical `{domain}.{sub_domain}`), `zone` (cn/intl), `language`, `params` (campos verticais estruturados), `format` (json/markdown).
- `GET /v1/sub-domains?domain=...` - catálogo de capacidades, NÃO é contabilizado para a quota.
- `POST /v1/extract` - obtém/extrai `{url, title, content}`; corpo JSON estrito, limite de 16 KiB.
- `POST /v1/auth/email/register` - registo numa única chamada, devolve uma chave em texto simples de utilização única `as_sk_...`.
- Autenticação: `Authorization: Bearer <as_sk_...>` opcional; o acesso anónimo é limitado por IP e consome a quota diária gratuita; uma chave inválida devolve 401/403 SEM recurso silencioso ao acesso anónimo.
- Plano gratuito: 1000 pedidos/dia, 20 QPS por chave. Plano pago: sem preço definido (Brevemente).
- Envelope da resposta: sucesso `{code: 0, message: "success", request_id, data}`; falha `{code: -1, message}`. Os erros de autenticação/quota não incluem um `error_code` estruturado (o texto de `message` é o sinal); os erros específicos de extração incluem `error_code` (`invalid_extract_url`, `extract_failed`). Nenhum cabeçalho `Retry-After` em respostas 429.

## 3. Decisões (todas tomadas em 2026-08-26)

1. **Postura de encaminhamento: `fallbackOnly`.** Fundamentação: um fornecedor gratuito com custo 0 nunca deve prevalecer no encaminhamento automático por custo; a seleção explícita e o retorno por ativação pós-falha não são afetados. Precedente: entrada xquik integrada.
2. **Âmbito: webSearch + webFetch através de `POST /v1/extract` na v1.** Alinhado com o modelo mental de capacidade dupla tavily/exa. As superfícies verticais (`tag`, `sub-domains`, `batch_search`) permanecem fora do âmbito — atualmente, não existe IR para parâmetros verticais.
3. **Apresentação da quota: `freeMonthlyQuota: 0`** (apresentação conservadora ao estilo xquik). O limite real (1000 pedidos/dia, reposição diária) é indicado no texto `authHint` do catálogo da IU. Fundamentação: a apresentação da quota deve corresponder à semântica de reposição; converter um limite diário num equivalente mensal (30000) é uma falsa promessa que a IU não pode cumprir.
4. **searchTypes: `["web"]` apenas.** Não existem indícios públicos de uma vertical de notícias/imagens na API AnySearch; os gateways que integram APIs sem uma vertical documentada (por exemplo, Google Custom Search) expõem apenas a Web, em vez de mapearem silenciosamente notícias -> Web.
5. **Postura relativa à chave:** funciona sem chave; uma chave inválida devolve 401/403 e nunca é silenciosamente substituída por acesso anónimo (reflete o contrato do serviço a montante).
6. **Exclusões deliberadas:** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (a interceção de chat permanece em firecrawl/jina/tavily); `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (os endpoints remotos anónimos partilham um único conjunto limitado por IP para cada IP de saída, pelo que a extração sem chave é opcional, não sendo candidata ao encaminhamento automático); `QUOTA_STATUS_PROVIDERS` (a AnySearch assinala a quota através de 429/envelope, não dos estados 402/403).
