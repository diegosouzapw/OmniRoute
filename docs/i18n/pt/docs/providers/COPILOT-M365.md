`copilot-m365-web` (alias `m365copilot`) envia pedidos de chat no formato OpenAI através de uma
sessão autenticada do Microsoft 365 Copilot BizChat no browser em
`m365.cloud.microsoft/chat`. Esta é uma integração não oficial.

> **É a primeira vez que utiliza fornecedores de cookies Web?**
>
> Leia **`docs/getting-started/WEB-COOKIE-GUIDE.md`** para conhecer o processo geral de configuração, as orientações de autenticação, as limitações e a resolução de problemas antes de seguir este guia específico do fornecedor.
>
> **Importante:** A credencial deste fornecedor **não é um cookie**. Não copie
> cookies de `m365.cloud.microsoft`. A credencial consiste num parâmetro de consulta de URL
> WebSocket e num segmento do caminho, ambos obtidos no separador Network do DevTools.

## Pré-requisitos

- Uma conta Microsoft 365 com acesso ao BizChat em `m365.cloud.microsoft/chat`
- Um browser baseado em Chromium (Chrome, Edge) para inspecionar WebSockets no DevTools
- Uma licença do M365 Copilot (incluída em muitos planos Microsoft 365 Business/Enterprise)

## Obtenção da credencial (método WebSocket)

1. Inicie sessão em `https://m365.cloud.microsoft/chat` e comece uma conversa.
2. Abra **DevTools → Network**.
3. Filtre por **WS** (WebSocket).
4. Clique na ligação WebSocket do Chathub. Procure um URL que comece por
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. No respetivo **Request URL**, copie:
   - O valor do parâmetro de consulta `access_token` (um JWT de curta duração).
   - O segmento do caminho do Chathub após `/Chathub/` (por exemplo, `<oid>@<tenant>`).

O URL completo tem o seguinte formato:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. No OmniRoute, aceda a **Providers → Add Provider**, selecione **Microsoft 365 Copilot
   (BizChat)** e cole a credencial no seguinte formato:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Clique em **Test Connection** e **Save**.

## Obtenção da credencial (importação de HAR)

Em vez de copiar manualmente os valores do URL WebSocket, pode exportar um ficheiro HAR
do DevTools:

1. Abra **DevTools → Network**.
2. Inicie ou continue uma conversa no BizChat (isto aciona a ligação WebSocket).
3. Clique com o botão direito do rato no painel Network e selecione **Save all as HAR with content**.
4. No OmniRoute, utilize o botão **Import .har file** na caixa de diálogo de ligação do fornecedor.

O OmniRoute analisa o HAR para encontrar o URL WebSocket do Chathub, extrai o
`access_token` e o `chathubPath` e preenche automaticamente os campos da credencial. A
importação do HAR descodifica a validade do JWT e apresenta o tempo de vida restante do token.

> **Nunca faça commit de uma exportação HAR real, de um token de acesso ou de um token de atualização.** Os valores de teste e
> de documentação devem ser sempre marcadores de posição.

## Duração e atualização do token

O `access_token` tem uma duração curta (normalmente **~75 minutos**). Após expirar, o fornecedor
comunica um erro de ligação e terá de obter novamente a credencial.

### Atualização automática com `refreshToken`

Para evitar ter de obter novamente a credencial de forma manual, pode guardar um token de atualização da Microsoft em
**Advanced Settings → providerSpecificData** da ligação:

| Campo          | Descrição                                                                           |
| -------------- | ----------------------------------------------------------------------------------- |
| `refreshToken` | Token de atualização OAuth da Microsoft para o âmbito `substrate.office.com/sydney` |
| `tier`         | `individual` (predefinição), `edu` ou `enterprise`                                  |

Obtenha o token de atualização através de um fluxo de código de dispositivo ou de código de autorização da Microsoft
com o âmbito `substrate.office.com/sydney`. Com `refreshToken` definido, o OmniRoute
atualiza preventivamente o `access_token` antes de cada pedido, pelo que não necessita de
voltar a obter a credencial após cada expiração de ~75 minutos.

Se `refreshToken` não estiver definido, terá de voltar a obter manualmente a credencial WebSocket
após cada expiração.

### Seleção do nível

| Nível        | Alias            | Modalidade                     |
| ------------ | ---------------- | ------------------------------ |
| `individual` | _(predefinição)_ | M365 Copilot para consumidores |
| `edu`        | `included`       | M365 Copilot para Educação     |
| `enterprise` | `work`           | M365 Copilot para Trabalho     |

Defina o nível em **Advanced Settings → providerSpecificData → tier**. O nível afeta
o encaminhamento do BizChat e o acesso aos modelos.

## Modelo de segurança

- **Integração não oficial.** Este fornecedor utiliza engenharia inversa do protocolo
  WebSocket do BizChat. Poderá deixar de funcionar sem aviso prévio quando a Microsoft alterar o endpoint.
- O sinalizador `subscriptionRisk: true` indica que a integração depende de um
  endpoint não documentado. É possível que sejam aplicadas restrições à conta, mas tal não está confirmado.
- O token de acesso é um JWT de curta duração. Trate-o como uma palavra-passe: não o inclua em commits,
  não o registe em logs nem o partilhe.
- O token de atualização concede acesso prolongado à interface do BizChat. Armazene-o com o
  mesmo cuidado que uma chave de API.

## Resolução de problemas

### A autenticação falha imediatamente

- Verifique se copiou a partir do **URL do WebSocket**, e não de um pedido XHR/Fetch. A
  credencial encontra-se no parâmetro de consulta `access_token` da ligação WebSocket
  do Chathub — não num cabeçalho `Authorization: Bearer`.
- Certifique-se de que `chathubPath` inclui o segmento `<oid>@<tenant>` completo do caminho
  do URL.

### O token expira após ~75 minutos

Isto é esperado. Sem um `refreshToken`, o token de acesso tem uma duração curta. Pode:

- Voltar a obter a credencial a partir das DevTools; ou
- Configurar um `refreshToken` nas Definições avançadas para a atualização automática.

### O teste de ligação é bem-sucedido, mas o chat devolve 401

O token poderá ter expirado entre a validação e o primeiro pedido. Volte a obter uma
credencial válida.

### O Copilot não aparece na lista de fornecedores

Certifique-se de que `copilot-m365-web` está ativado em **Painel → Fornecedores**. O fornecedor poderá
estar oculto por predefinição em alguns níveis.
