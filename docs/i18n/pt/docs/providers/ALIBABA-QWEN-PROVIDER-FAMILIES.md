Este documento regista a decisão de implementação relativa à
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854). Os produtos públicos são
representados como quatro famílias de fornecedores. A região corresponde a dados da ligação, não a um produto separado.

## Decisão

| Família de fornecedores                        | ID do OmniRoute         | Região global | Região da China |
| ---------------------------------------------- | ----------------------- | ------------- | --------------- |
| Alibaba Cloud Model Studio (pagamento por uso) | `alibaba`               | Singapura     | Pequim          |
| Alibaba Cloud Token Plan                       | `bailian-coding-plan`   | Singapura     | Pequim          |
| Qwen Cloud (pagamento por uso)                 | `qwen-cloud`            | Global        | Pequim          |
| Qwen Cloud Token Plan                          | `qwen-cloud-token-plan` | Singapura     | Pequim          |

O ID `alibaba-cn` existente mantém-se como um alias de compatibilidade em tempo de execução para ligações guardadas, rotas de modelos, combinações e utilização histórica. O respetivo cartão no painel é integrado em `alibaba`; não é necessária qualquer reescrita da base de dados.

Atualmente, o Qwen Cloud com pagamento por uso e o Alibaba Cloud Model Studio partilham os anfitriões de execução compatíveis com o DashScope, mas mantêm identidades de fornecedor distintas porque os utilizadores obtêm chaves e gerem contas através de interfaces de produto diferentes. Os produtos Alibaba e Qwen Cloud Token Plan utilizam famílias de endpoints diferentes, pelo que os quatro produtos mantêm IDs de fornecedor distintos.

## Matriz de endpoints

| Família de fornecedores | `global-sg`                                                              | `china-beijing`                                                      | Formato de transmissão |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ---------------------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI                 |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic              |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI                 |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI                 |

A chave da API e o endpoint têm de pertencer ao mesmo produto e à mesma região. A seleção de uma região altera o endpoint predefinido utilizado pela validação e pelos pedidos normais.

## Contrato da ligação

As novas ligações armazenam a chave estável da região em `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

Os valores permitidos são `global-sg` e `china-beijing`. O endpoint é obtido centralmente a partir do ID do fornecedor e da região. Um `providerSpecificData.baseUrl` não predefinido continua a constituir uma substituição explícita por parte do operador e tem precedência, enquanto os URLs predefinidos anteriormente guardados são normalizados de acordo com a matriz regional.

Isto mantém o esquema da ligação extensível: é possível adicionar outra região ao resolvedor sem criar outro cartão de fornecedor nem alterar os IDs de fornecedor guardados.

## Compatibilidade e implementação

1. Adicionar o resolvedor de endpoints regionais e manter os valores globais atuais como predefinições.
2. Utilizar a descoberta em tempo real de `/models` regional do DashScope para `alibaba`, o respetivo ID de compatibilidade `alibaba-cn` e `qwen-cloud`. As respostas passam primeiro por um filtro de geração de texto, uma vez que o endpoint genérico também devolve modelos de imagem, vídeo, áudio, embeddings e outros modelos não destinados a chat. Em seguida, `qwen-cloud` aplica a lista de permissões mantida e declarada no respetivo registo de fornecedor. O Alibaba Model Studio e o Qwen Cloud mantêm catálogos selecionados separados, embora atualmente partilhem os mesmos hosts de runtime.
3. Registar `qwen-cloud-token-plan` com a lista de permissões atual de modelos de texto do Token Plan.
4. Adicionar um seletor de região tipado às caixas de diálogo para adicionar/editar ligações.
5. Ocultar o cartão `alibaba-cn` duplicado e incluir as ligações existentes do mesmo na página do fornecedor `alibaba`.
6. Manter disponíveis as substituições de endpoints personalizados para implementações avançadas e específicas de espaços de trabalho.

Os modelos multimédia do Token Plan permanecem fora do catálogo de chat porque utilizam endpoints dedicados.
`wan2.7-image` e `wan2.7-image-pro` estão registados em `open-sse/config/imageRegistry.ts`;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` e `happyhorse-1.1-r2v` estão registados em
`open-sse/config/videoRegistry.ts`. Ambos os registos reutilizam a identidade de ligação
`qwen-cloud-token-plan` e as respetivas credenciais específicas da região.

O Qwen Cloud normal tem catálogos separados de imagem e vídeo com pagamento consoante a utilização sob a identidade `qwen-cloud`. Os respetivos modelos de imagem são `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` e `z-image-turbo`. Os respetivos modelos de vídeo
são `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` e
`wan2.7-videoedit`. Estes modelos reutilizam apenas a ligação normal `qwen-cloud` e o endpoint
multimédia regional do DashScope. Os registos do Token Plan e de pagamento consoante a utilização não herdam nem combinam
as listas de modelos um do outro.

A identidade `bailian-coding-plan` também tem as suas próprias listas de permissões multimédia:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` e `qwen-image-2.0-pro` para geração de
imagens, bem como
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` e `happyhorse-1.1-r2v` para geração de
vídeo. Utiliza apenas a ligação do Bailian Coding Plan e o endpoint regional do Coding Plan.
Os respetivos registos de imagem e vídeo não herdam nem são combinados com nenhum dos fornecedores do Qwen Cloud.

A identidade normal `alibaba` tem listas de permissões separadas para imagem e vídeo. Os respetivos modelos de imagem são
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` e `wan2.6-t2i`. Os modelos de vídeo adicionados são `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` e `wan2.7-videoedit`. Estes modelos utilizam apenas a ligação do Alibaba Model Studio
e o respetivo endpoint multimédia regional selecionado; não são adicionados a nenhum registo do Coding Plan ou do Qwen
Cloud.

O catálogo de chat do Qwen Cloud Token Plan segue a lista de permissões de texto com correspondência exata de cadeias do plano Individual:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` e
`deepseek-v4-pro`. As entradas Wan e HappyHorse pertencem às APIs separadas de geração de imagem/vídeo.

O Alibaba Token Plan disponibiliza os mesmos seis IDs atuais de modelos de geração de texto através do respetivo
endpoint compatível com Anthropic. A opção de Singapura armazena a chave de região existente `global-sg`;
apenas a etiqueta apresentada ao utilizador difere das famílias de fornecedores que designam a região como Global.

O catálogo normal de chat do Qwen Cloud é intencionalmente mais restrito do que a resposta de texto completa em tempo real. A respetiva
lista de permissões mantida encontra-se em `open-sse/config/providers/registry/qwen-cloud/index.ts`; a descoberta em tempo real
apenas devolve IDs presentes tanto na resposta do serviço a montante como nessa lista do registo.

O Alibaba Model Studio segue a mesma regra de interseção em tempo real com a sua lista de permissões mantida de forma independente
em `open-sse/config/providers/registry/alibaba/index.ts`. O fornecedor de compatibilidade `alibaba-cn`
reutiliza esse catálogo, mas resolve a descoberta através do endpoint de Pequim.
