> Alternadores em tempo de execução que alteram o comportamento do OmniRoute **sem uma nova implementação**.
> Todos os sinalizadores aqui indicados estão definidos em
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> — a única fonte de verdade. Tanto o painel como a API REST leem esse
> ficheiro, pelo que a tabela abaixo é gerada para corresponder ao mesmo na proporção de 1:1.

---

## O Que São Sinalizadores de Funcionalidade

Um sinalizador de funcionalidade é um alternador com nome (booleano ou enumeração) cujo valor pode ser alterado em
tempo de execução e mantido na base de dados, sem que seja necessária uma nova implementação do processo. Cada
sinalizador é descrito por uma `FeatureFlagDefinition` com uma `key`, `label`,
`description`, `category`, `defaultValue`, `type` e uma indicação `requiresRestart`.

### Ordem de Resolução

O **valor efetivo** de um sinalizador é determinado por
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) com a seguinte
precedência (a mais elevada prevalece):

1. **Substituição na BD** — um valor armazenado na tabela `key_value`, no espaço de nomes
   `feature_flags` (definido através do painel ou da API REST).
2. **Variável de ambiente** — `process.env[<KEY>]`, se estiver definida e não estiver vazia.
3. **Predefinição da definição** — o `defaultValue` de `featureFlagDefinitions.ts`.

Um sinalizador booleano é considerado **ativado** quando o seu valor efetivo é `"true"`,
`"1"` ou `"yes"` (consulte `isFeatureFlagEnabled()`).

> [!NOTE]
> A maioria dos sinalizadores também tem uma variável de ambiente correspondente com o **mesmo nome**,
> documentada em [`ENVIRONMENT.md`](./ENVIRONMENT.md). A substituição do sinalizador na BD
> tem precedência sobre essa variável de ambiente. Um sinalizador com
> `requiresRestart: true` é mantido imediatamente, mas apenas é lido novamente no arranque do
> processo — alterná-lo apresenta uma faixa **"Reiniciar Servidor"** no painel.

## Alternar Flags

### Painel

Navegue para **Painel → Definições → Flags de Funcionalidades**
(`/dashboard/settings/feature-flags`). A grelha
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
suporta:

- **Pesquisa** por chave ou descrição e **filtragem** por categoria (incluindo uma vista
  sintética **Requer Reinício**).
- Um **botão de alternância** para flags booleanas e uma **lista pendente** para flags de enumeração
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- Um **distintivo de origem** por flag — `DB`, `ENV` ou `DEF` — que mostra de onde
  veio o valor efetivo.
- Um botão **Repor** (apresentado apenas para flags provenientes de `DB`) para remover a substituição
  e um botão **Repor Todas as Substituições** na parte inferior.
- Uma faixa **Reiniciar Servidor** quando uma flag `requiresRestart` é alterada.

### API REST

Todas as operações passam por uma única rota:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Todos os métodos requerem uma sessão autenticada no painel (caso contrário, `401`).

#### `GET /api/settings/feature-flags`

Devolve todas as flags com o respetivo valor efetivo, origem e um resumo.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Exigir Chave de API",
      "description": "Exigir uma chave de API para todos os pedidos recebidos",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... todas as 75 flags
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Define ou remove uma única substituição. Corpo: `{ key: string; value?: string }`.
Omitir `value` remove a substituição (restaurando o valor de env / predefinido).

```bash
# Definir uma substituição na DB
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Remover a substituição (sem "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

A resposta devolve o novo `effectiveValue`/`source`, o `previousValue`/
`previousSource` e `requiresRestart`. As chaves desconhecidas e os valores de enumeração
fora do intervalo são rejeitados com `400`.

#### `DELETE /api/settings/feature-flags`

Limpa **todas** as substituições da DB de uma só vez, restaurando cada flag para o respetivo
valor de env / predefinido. Devolve `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> As flags com `requiresRestart: true` só produzem efeito após o processo ser recarregado.
> O fluxo de reinício do painel chama `POST /api/restart` e, em seguida, consulta repetidamente
> `GET /api/health/ping` até o servidor voltar a estar operacional.

## Alternativa de emergência para o orçamento

`OMNIROUTE_EMERGENCY_FALLBACK` (categoria `runtime`, predefinição `true`) controla o
caminho alternativo gratuito de emergência em
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Quando está ativo, os pedidos que esgotam o respetivo orçamento são encaminhados para um
fornecedor/modelo alternativo gratuito, em vez de falharem de imediato. Defina-o como `false` (ou `0`) — através do
botão de alternância do painel de controlo, de uma substituição da DB ou da variável de ambiente
`OMNIROUTE_EMERGENCY_FALLBACK` — para desativar este comportamento e permitir que os pedidos
cujo orçamento se esgotou falhem. (Disponibilizado como um botão de alternância no painel de controlo nos PRs #3741 / #3752.)
