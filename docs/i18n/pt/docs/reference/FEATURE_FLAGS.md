> Alternadores de tempo de execução que alteram o comportamento do OmniRoute **sem uma nova implementação**.
> Cada sinalizador listado aqui é definido em
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> — a única fonte de verdade. O painel e a API REST leem desse arquivo, então a tabela abaixo é gerada para corresponder 1:1.

---

## O que são Sinalizadores de Funcionalidade

Um sinalizador de funcionalidade é um alternador nomeado (booleano ou enum) cujo valor pode ser alterado em tempo de execução e persistido na base de dados, sem necessidade de nova implementação do processo. Cada sinalizador é descrito por uma `FeatureFlagDefinition` com uma `key`, `label`, `description`, `category`, `defaultValue`, `type` e uma dica `requiresRestart`.

### Ordem de Resolução

O **valor efetivo** de um sinalizador é resolvido por
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) com esta precedência (o mais alto vence):

1. **Substituição da BD** — um valor armazenado na tabela `key_value` sob o espaço de nomes `feature_flags` (definido através do painel ou da API REST).
2. **Variável de ambiente** — `process.env[<KEY>]`, se definida e não vazia.
3. **Padrão de definição** — o `defaultValue` de `featureFlagDefinitions.ts`.

Um sinalizador booleano é considerado **ativado** quando o seu valor efetivo é `"true"`, `"1"` ou `"yes"` (ver `isFeatureFlagEnabled()`).

> [!NOTE]
> A maioria dos sinalizadores também tem uma variável de ambiente correspondente com o **mesmo nome**
> documentada em [`ENVIRONMENT.md`](./ENVIRONMENT.md). A substituição da BD do sinalizador tem precedência sobre essa variável de ambiente. Um sinalizador com
> `requiresRestart: true` é persistido imediatamente, mas apenas é relido no arranque do processo — alterná-lo exibe um banner **"Reiniciar Servidor"** no painel.

## Ativar/Desativar Feature Flags

### Dashboard

Navegue para **Dashboard → Definições → Feature Flags**
(`/dashboard/settings/feature-flags`). A grelha
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
suporta:

- **Pesquisa** por chave ou descrição, e **filtro** por categoria (além de uma vista sintética
  **Requer Reinício**).
- Um **interruptor** para feature flags booleanas e um **menu pendente** para feature flags
  de enumeração (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- Um **emblema de origem** por feature flag — `DB`, `ENV`, ou `DEF` — mostrando de onde
  veio o valor efetivo.
- Um botão **Repor** (mostrado apenas para feature flags com origem `DB`) para remover a
  substituição, e um botão **Repor Todas as Substituições** na parte inferior.
- Um banner **Reiniciar Servidor** quando uma feature flag `requiresRestart` é alterada.

### API REST

Todas as operações passam por uma única rota:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Cada método requer uma sessão de dashboard autenticada (código `401` caso contrário).

#### `GET /api/settings/feature-flags`

Devolve cada feature flag com o seu valor efetivo, origem e um resumo.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... todas as 77 feature flags
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Define ou remove uma única substituição. Corpo: `{ key: string; value?: string }`.
Omitir `value` remove a substituição (restaurando o ambiente / predefinição).

```bash
# Definir uma substituição DB
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Remover a substituição (sem "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

A resposta reflete o novo `effectiveValue`/`source`, o `previousValue`/
`previousSource`, e `requiresRestart`. Chaves desconhecidas e valores de enumeração
fora do intervalo são rejeitados com `400`.

#### `DELETE /api/settings/feature-flags`

Limpa **todas** as substituições DB de uma só vez, restaurando cada feature flag para o seu
valor de ambiente / predefinido. Devolve `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> Feature flags com `requiresRestart: true` só entram em vigor após um recarregamento do processo.
> O fluxo de reinício do dashboard chama `POST /api/restart` e depois consulta
> `GET /api/health/ping` até que o servidor esteja novamente ativo.

## Recurso de Emergência para Orçamento

`OMNIROUTE_EMERGENCY_FALLBACK` (categoria `runtime`, predefinição `true`) controla o
caminho de recurso de emergência gratuito em
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Quando ativado, os pedidos que esgotam o seu orçamento são encaminhados para um fornecedor/modelo
de recurso gratuito em vez de falharem completamente. Defina-o para `false` (ou `0`) —
através do interruptor do dashboard, de uma substituição DB, ou da variável de ambiente
`OMNIROUTE_EMERGENCY_FALLBACK` — para desativar o comportamento e permitir que os pedidos
com orçamento esgotado falhem. (Apresentado como um interruptor do dashboard nos PRs #3741 / #3752.)
