> `src/app/api/settings/obsidian/webdav/route.ts` (APIs de definições). O registo das ferramentas
> e a configuração dos âmbitos encontram-se em `open-sse/mcp-server/server.ts`.

## O que é

O OmniRoute liga-se a um cofre do **Obsidian** como **fonte de contexto** — uma base de
conhecimento Markdown local que os agentes leem e na qual escrevem através do servidor
MCP integrado. A integração comunica com o plugin comunitário **Obsidian Local REST API**
em execução na aplicação de ambiente de trabalho, permitindo aos agentes pesquisar notas,
ler/escrever/aplicar patches a ficheiros, listar o cofre, trabalhar com notas periódicas
diárias/semanais, gerir etiquetas, executar comandos do Obsidian e, opcionalmente,
coordenar uma sincronização bidirecional do cofre entre computador↔dispositivo móvel.

O cliente (`src/lib/obsidian/api.ts`) encapsula a Local REST API com:

- **Novas tentativas com espera progressiva** para erros `5xx` transitórios e **tempo limite
  de 30 segundos** através de `AbortController`.
- **Classificação tipada de erros** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- Uma **sugestão clara de "não é possível contactar o Obsidian"** que destaca o erro
  comum de porta (HTTP em `27123`, **não** o endpoint MCP em `27124`) e o formato
  do Tailscale.
- **Codificação de caminhos** relativos ao cofre, para que os caminhos de notas com
  espaços/barras sejam seguros.

## Configuração

Não existe **qualquer variável de ambiente** para o token ou URL base do Obsidian —
ambos são armazenados na tabela SQLite `key_value` (namespace `obsidian`) através de
`src/lib/db/obsidian.ts`. O token é **encriptado quando armazenado** (AES-256-GCM, com
compatibilidade retroativa para texto simples). Configure-o no separador **Fontes de
contexto** do painel de endpoints (`ObsidianSourceCard`) ou através da API REST de
definições.

> [!IMPORTANT]
> O plugin **Obsidian Local REST API** tem de estar instalado e em execução. A respetiva
> interface REST escuta em **HTTP `127.0.0.1:27123`** (a URL base predefinida). A porta
> `27124` é um endpoint MCP/HTTPS _separado_ e é explicitamente rejeitada pela rota de
> definições. Se estabelecer a ligação a partir de outro dispositivo, utilize
> `http://<tailscale-ip>:27123`.

### Chaves de configuração (SQLite `key_value`, namespace `obsidian`)

| Chave             | Finalidade                                                      | Encriptada |
| ----------------- | --------------------------------------------------------------- | ---------- |
| `api_key`         | Token bearer da Local REST API                                  | sim        |
| `base_url`        | URL base REST (predefinição `http://127.0.0.1:27123`)           | não        |
| `vault_path`      | Caminho absoluto para o diretório do cofre (para sincronização) | não        |
| `webdav_username` | Nome de utilizador WebDAV gerado (sincronização do cofre)       | não        |
| `webdav_password` | Palavra-passe WebDAV gerada (sincronização do cofre)            | sim        |
| `webdav_enabled`  | Indica se a sincronização do cofre via WebDAV está ativada      | não        |

### Configurar através de REST

```bash
# Guardar + validar o token da Local REST API (o POST valida através de uma verificação de estado)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Verificar o estado da ligação (devolve connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# Desligar (remove o token armazenado)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Todos os métodos exigem autenticação no painel. O `POST` rejeita qualquer URL na porta
`27124` e valida o token chamando o endpoint de estado da Local REST API antes de o
armazenar.

### Sincronização do cofre via WebDAV

`src/app/api/settings/obsidian/webdav/route.ts` gere uma sincronização opcional do cofre
através de WebDAV (controlada por `src/lib/obsidianSync.ts`). Ao ativá-la, o OmniRoute
é configurado para utilizar um diretório de cofre local e gera um par aleatório de nome
de utilizador/palavra-passe WebDAV:

```bash
# Ativar a sincronização WebDAV para um diretório de cofre (gera nome de utilizador/palavra-passe)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# Obter o estado da sincronização WebDAV (as credenciais só são devolvidas enquanto estiver ativada)
curl http://localhost:20128/api/settings/obsidian/webdav

# Desativar a sincronização WebDAV (remove as credenciais + o ficheiro .stignore gerido)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Fonte de contexto por chave de API (opcional)

A configuração do Obsidian pode ser definida **por chave de API** através da tabela
`api_key_context_sources` (`src/lib/db/apiKeyContextSources.ts`). Quando uma chamada MCP
inclui o id de uma chave de API autenticada, `getObsidianConfigForApiKey()` dá preferência
ao token/URL base/caminho do cofre próprios dessa chave (`source: "api_key"`) e, caso
contrário, recorre à configuração global (`source: "global"`).

## Ferramentas MCP (22)

Definidas em `open-sse/mcp-server/tools/obsidianTools.ts`. O token/URL base são resolvidos
por chamada (primeiro por chave de API e depois globalmente). As ferramentas que acedem ao **servidor de sincronização**
do OmniRoute (as quatro ferramentas `obsidian_sync_*`) requerem adicionalmente o token de autenticação de sincronização configurado
nas definições do OmniRoute.

### Ferramentas de leitura (`read:obsidian`)

| Ferramenta                   | Descrição                                                                                                                       |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Verificar se a API REST local está acessível e autenticada.                                                                     |
| `obsidian_search_simple`     | Pesquisa de texto integral no conteúdo das notas; devolve excertos com caminhos de ficheiros.                                   |
| `obsidian_search_structured` | Pesquisar utilizando uma expressão JSON Logic (filtros and/or/regex/path).                                                      |
| `obsidian_read_note`         | Ler uma nota pelo caminho relativo ao cofre; opcionalmente, um cabeçalho/bloco/frontmatter específico.                          |
| `obsidian_list_vault`        | Listar ficheiros e diretórios no cofre (árvore de entradas).                                                                    |
| `obsidian_get_document_map`  | Obter a estrutura de cabeçalhos da nota como um mapa de cabeçalhos → números de linha.                                          |
| `obsidian_get_note_metadata` | Obter frontmatter, etiquetas, ligações e contagem de caracteres/palavras sem o conteúdo integral.                               |
| `obsidian_get_active_file`   | Obter o caminho e o conteúdo do ficheiro atualmente ativo no Obsidian.                                                          |
| `obsidian_get_periodic_note` | Obter a nota periódica diária/semanal/mensal de uma data (hoje, caso seja omitida).                                             |
| `obsidian_get_tags`          | Listar todas as etiquetas do cofre com as respetivas frequências.                                                               |
| `obsidian_list_commands`     | Listar os IDs dos comandos disponíveis do Obsidian (utilizar com `obsidian_execute_command`).                                   |
| `obsidian_sync_status`       | Estado do servidor de sincronização do OmniRoute: em execução, nome do cofre, porta, tempo de atividade e última sincronização. |
| `obsidian_sync_conflicts`    | Listar conflitos de sincronização não resolvidos (caminho, caminho do conflito e data/hora de deteção).                         |

### Ferramentas de escrita (`write:obsidian`)

| Ferramenta                       | Descrição                                                                                                        |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Criar ou substituir uma nota com o conteúdo Markdown indicado.                                                   |
| `obsidian_append_note`           | Acrescentar conteúdo a uma nota; opcionalmente, a um cabeçalho/bloco específico.                                 |
| `obsidian_patch_note`            | Acrescentar, antepor ou substituir de forma precisa num cabeçalho, bloco ou campo de frontmatter.                |
| `obsidian_delete_note`           | Eliminar permanentemente uma nota do cofre.                                                                      |
| `obsidian_move_note`             | Mover ou mudar o nome de uma nota no cofre.                                                                      |
| `obsidian_execute_command`       | Executar um comando do Obsidian através do respetivo ID.                                                         |
| `obsidian_open_file`             | Abrir um ficheiro no Obsidian (cria-o caso não exista).                                                          |
| `obsidian_sync_trigger`          | Acionar uma sincronização bidirecional imediata do cofre entre computador↔dispositivo móvel.                     |
| `obsidian_sync_resolve_conflict` | Resolver um conflito de sincronização: manter `local` (dispositivo móvel), `remote` (computador) ou `keep-both`. |

> [!NOTE]
> Os destinos de `obsidian_patch_note` aceitam um `targetType` de `heading | block | frontmatter`
> e uma `operation` de `append | prepend | replace`, com um
> `createTargetIfMissing` opcional. As quatro ferramentas `obsidian_sync_*` comunicam com o servidor de sincronização
> local (`http://127.0.0.1:27781` por predefinição) e requerem o token de sincronização.

### Âmbitos

As ferramentas de leitura requerem `read:obsidian`; as ferramentas de escrita requerem `write:obsidian`. A aplicação
é idêntica à do Notion — gerida por `withScopeEnforcement()` em
`open-sse/mcp-server/server.ts`, condicionada a `OMNIROUTE_MCP_ENFORCE_SCOPES=true`, com os
âmbitos permitidos obtidos de `OMNIROUTE_MCP_SCOPES` ou do contexto de âmbito da chave de API. Consulte
[MCP-SERVER.md](./MCP-SERVER.md).

## Endpoints

| Método   | Caminho                         | Finalidade                                                     |
| -------- | ------------------------------- | -------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | Devolve `{ connected, hasToken, baseUrl, vaultPath }`.         |
| `POST`   | `/api/settings/obsidian`        | Guarda e valida o token (rejeita a porta `27124`).             |
| `DELETE` | `/api/settings/obsidian`        | Desliga a ligação (limpa o token armazenado).                  |
| `GET`    | `/api/settings/obsidian/webdav` | Estado da sincronização WebDAV e credenciais (quando ativada). |
| `POST`   | `/api/settings/obsidian/webdav` | Ativa a sincronização WebDAV para um diretório do cofre.       |
| `DELETE` | `/api/settings/obsidian/webdav` | Desativa a sincronização WebDAV.                               |

> Estas são rotas de definições do painel. O próprio cofre é acedido através da API REST
> local do Obsidian (o `base_url` configurado) e das ferramentas MCP acima — não existe
> nenhum endpoint proxy público `/v1` do Obsidian.

## Casos de utilização

- **Respostas baseadas no cofre** — `obsidian_search_simple` / `obsidian_search_structured`
  e, em seguida, `obsidian_read_note`, para que um agente responda com base nas suas notas reais.
- **Criação de notas / diário** — `obsidian_write_note`, `obsidian_append_note` ou
  a operação cirúrgica `obsidian_patch_note` para registar resultados do agente, resumos ou notas diárias
  (`obsidian_get_periodic_note`) no cofre.
- **Navegação no cofre** — `obsidian_list_vault`, `obsidian_get_document_map` e
  `obsidian_get_tags` para explorar a estrutura antes de ler/escrever.
- **Automatização do Obsidian** — `obsidian_list_commands` + `obsidian_execute_command` para
  executar plugins/comandos a partir de um agente; `obsidian_open_file` para apresentar uma nota na interface.
- **Sincronização móvel** — ative a sincronização WebDAV e, em seguida, utilize `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  para coordenar a sincronização entre o computador e o dispositivo móvel e resolver conflitos.
