## Visão geral

O Search Tools Studio transforma `/dashboard/search-tools` de uma área básica de experimentação de pesquisa num
Studio com três separadores que unifica pesquisa web, extração de conteúdo web e comparação lado a lado entre fornecedores.

```
┌ Ferramentas de pesquisa ───────────────────────────────────────────────┐
│ [🔍 Pesquisar] [📄 Extrair] [⚖ Comparar]        142ms · $0.001  </>    │
│ ⓘ [Guia de modalidades]                                                │
├──────────────────────────────────────────┬─────────────────────────────┤
│  {conteúdo do separador ativo}           │ ─ Configuração              │
│                                          │ Fornecedor [auto ∨]         │
│                                          │   🟢 Serper  $0.001         │
│                                          │   🟢 Tavily  $0.008         │
│                                          │   🔥 Firecrawl (obtenção)   │
│                                          │ Tipo   [web | notícias]     │
│                                          │ Página completa [ ] (extr.) │
│                                          │ Formato [md|texto|html]     │
│                                          │ Modelo de reordenação [∨]   │
└──────────────────────────────────────────┴─────────────────────────────┘
```

## Separadores

### Separador Pesquisa

Transforma os componentes existentes `SearchForm` + `ResultsPanel` + `RerankPanel` num separador:

- Consulta → resultados (título, URL, excerto, pontuação de relevância).
- Metadados do fornecedor no painel Configuração (custo, quota, estado).
- Secção de reordenação: selecionar um modelo de reordenação, reordenar os resultados e apresentar `positionDelta`.
- Estado vazio com chamada para ação quando não existem fornecedores de pesquisa configurados.
- Histórico de pesquisas através de `SearchHistory.tsx`.
- Chama `POST /v1/search` (endpoint existente, sem alterações).

### Separador Extração

Novo separador para extrair conteúdo de um URL através de `POST /v1/web/fetch` (criado no plano 05):

- Entrada: URL + seletor de página completa + seletor de formato (markdown / texto / HTML).
- Submeter → obter → apresentar `ScrapeResult.tsx`.
- `ScrapeResult` apresenta uma pré-visualização do markdown + opção para alternar para conteúdo em bruto.
- Limite: se o corpo da resposta for superior a **256 KB**, a IU apresenta `(truncado, ver conteúdo em bruto)` e abre o conteúdo em bruto numa janela modal do Monaco (D21).
- Painel de metadados: fornecedor (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search), latência, custo, tamanho da resposta, número de ligações.
- Utiliza o hook `useScrapeFetch.ts`.

### Separador Comparação

Executa a mesma consulta/URL em até **4 fornecedores em paralelo** (D22):

- Colunas lado a lado por fornecedor.
- Métricas: latência, custo, número de resultados, tamanho da resposta.
- Cálculo da sobreposição de URLs para pesquisa (número de URLs partilhados em comparação com o resultado inicial).
- Chama `POST /v1/search` (pesquisa) ou `POST /v1/web/fetch` (extração) por fornecedor.

## Painel Configuração (Partilhado)

`SearchToolsConfigPane.tsx` — sempre visível, minimizável.

| Campo                 | Notas                                                                              |
| --------------------- | ---------------------------------------------------------------------------------- |
| Fornecedor            | Menu pendente com distintivo de estado (configurado / em falta / limitado)         |
| Tipo                  | `web` ou `news` (apenas pesquisa)                                                  |
| Página completa       | Seletor para extração — obtém a página inteira em vez do primeiro conteúdo visível |
| Formato               | `markdown`, `text` ou `html` (apenas extração)                                     |
| Modelo de reordenação | Modelo opcional para reordenação posterior à pesquisa                              |
| Histórico             | Secção minimizável do histórico de pesquisas                                       |

## SearchConceptCard

`SearchConceptCard.tsx` — sempre visível, acordeão recolhível. Explica:

| Conceito                        | Descrição breve                                                                   |
| ------------------------------- | --------------------------------------------------------------------------------- |
| **Pesquisa**                    | Obtém uma lista de resultados web (título, URL, excerto, pontuação de relevância) |
| **Extração**                    | Extrai o conteúdo completo de um URL (markdown, texto ou HTML)                    |
| **Comparação**                  | Executa a mesma consulta em N fornecedores lado a lado                            |
| **Reordenação**                 | Reordena os resultados através de um LLM para melhorar a relevância da consulta   |
| **Automático (mais económico)** | Seleciona automaticamente o fornecedor disponível mais económico                  |

## Catálogo de fornecedores

`ProviderCatalog.tsx` disponibiliza a lista completa de fornecedores a partir de `GET /api/search/providers`
(alargada em F4 para incluir fornecedores de obtenção):

| `kind` | `"search"` (20 fornecedores) ou `"fetch"` (firecrawl, jina-reader, tavily-search, tinyfish, nimble-search, anysearch-search) |

O estado é **determinado no momento do pedido**, verificando se existem credenciais e se
todas as chaves estão atualmente em período de espera.

## Exportação de código

`ExportCodeModal` (importado do Playground Studio) + `codeExport.ts` geram
excertos de curl / Python / TypeScript para chamadas a `/v1/search` e `/v1/web/fetch`.
O marcador de posição da chave da API é sempre `$OMNIROUTE_API_KEY` (D11, partilhado com o Playground Studio).

---

## Alterações no backend

Foi necessária apenas uma alteração ao backend para esta funcionalidade:

### `GET /api/search/providers` alargado

`src/app/api/search/providers/route.ts` foi alargado para:

- Incluir os 6 fornecedores de obtenção (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`) no array.
- Adicionar `kind: "search" | "fetch"` a cada item.
- Adicionar `status: "configured" | "missing" | "rate_limited"`, determinado a partir do estado atual das credenciais.
- Manter a retrocompatibilidade — os campos existentes (`id`, `name`, etc.) permanecem inalterados.

## Resolução de problemas

| Sintoma                                                    | Causa                           | Correção                                                                                                                |
| ---------------------------------------------------------- | ------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| O separador Scrape apresenta "endpoint não disponível"     | `/v1/web/fetch` não está ligado | Confirme que o plano 05 foi integrado; verifique se `src/app/api/v1/web/fetch/route.ts` existe                          |
| O catálogo de fornecedores apresenta todos como "em falta" | Credenciais não configuradas    | Adicione as credenciais em `/dashboard/providers`                                                                       |
| O conteúdo extraído está truncado                          | Resposta > limite de 256 KB     | Comportamento esperado (D21). Utilize o botão "ver conteúdo bruto" para consultar o conteúdo completo                   |
| O separador Comparar apresenta apenas 2 fornecedores       | Limite de pedidos ativo         | Dois ou mais fornecedores podem estar em período de espera — verifique o estado dos fornecedores no painel Configuração |
| "Tamanho" é apresentado como chave bruta na tabela         | Chave i18n em falta             | Verifique se `search.size` existe no ficheiro de idioma; reconstrua o i18n                                              |
