## O que é

O Local Corpus permite que um operador disponibilize um diretório explicitamente aprovado de ficheiros de texto ao
servidor MCP do OmniRoute. Os ficheiros permanecem no respetivo diretório original: o OmniRoute armazena apenas
o caminho raiz canónico no SQLite e mantém um índice de pesquisa em memória. Não
copia o conteúdo do corpus para o repositório nem para a base de dados.

A atualização do índice é incremental. Os ficheiros inalterados são reutilizados com base no tamanho e na hora de
modificação, os ficheiros alterados são relidos e é-lhes aplicado um hash SHA-256, e os ficheiros eliminados são removidos.
A pesquisa atualiza qualquer índice com mais de 30 segundos; os clientes também podem solicitar uma
atualização imediata.

## Configurar a origem

A rota de definições exige a mesma autenticação de gestão que as outras APIs de definições.
O caminho submetido já tem de existir e tem de ser um caminho absoluto para um diretório.

```bash
# Associar um diretório aprovado
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# Verificar a configuração e o estado do índice
curl http://localhost:20128/api/settings/local-corpus

# Desassociar sem alterar os ficheiros de origem
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## Ferramentas MCP

As três ferramentas requerem `read:local-corpus`. As respostas das ferramentas apresentam caminhos relativos e
o nome base do diretório raiz, nunca o respetivo caminho absoluto.

| Ferramenta            | Descrição                                                                                         |
| :-------------------- | :------------------------------------------------------------------------------------------------ |
| `local_corpus_status` | Comunica o estado da configuração, o tamanho do índice, os limites e a hora da última atualização |
| `local_corpus_search` | Pesquisa texto indexado e devolve excertos limitados e circunscritos a linhas (até 20 resultados) |
| `local_corpus_read`   | Lê um intervalo limitado de linhas de um ficheiro permitido, com caminho relativo ao corpus       |

Exemplos de entradas MCP:

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## Limites de segurança

- A lista de permissões destina-se a texto: `.cfg`, `.csv`, `.geojson`, `.htm`, `.html`, `.ini`,
  `.js`, `.json`, `.jsonl`, `.jsx`, `.log`, `.md`, `.mjs`, `.ps1`, `.py`, `.sh`,
  `.sql`, `.toml`, `.ts`, `.tsx`, `.txt`, `.xml`, `.yaml` e `.yml`.
- As ligações simbólicas são ignoradas. Os caminhos de leitura são convertidos para a forma canónica e têm de permanecer dentro da
  raiz configurada; os caminhos absolutos e as tentativas de travessia são rejeitados.
- Os nomes de diretórios sensíveis e gerados são excluídos: `.build`, `.codex`, `.env`,
  `.git`, `.next`, `.omniroute`, `.ssh`, `coverage`, `dist`, `node_modules` e
  `secrets`.
- Os limites predefinidos são 5 000 ficheiros, 1 MiB por ficheiro, 64 MiB de conteúdo indexado no total,
  aproximadamente 4 000 carateres por segmento de pesquisa e 400 linhas por leitura.
- Os ficheiros que contenham NUL são tratados como não textuais e são ignorados ou rejeitados.

Os documentos binários, como PDF, DOCX, imagens e arquivos, não são intencionalmente suportados.
Converta-os para um formato de texto aprovado no diretório configurado antes da indexação.

## Notas operacionais

- Alterar ou eliminar a raiz configurada limpa o índice partilhado em memória.
- Um reinício do processo elimina o índice; a pesquisa seguinte volta a criá-lo a partir da origem
  configurada.
- `local_corpus_status` não força uma análise. Utilize `local_corpus_search` com
  `refresh: true` quando for necessário efetuar imediatamente uma nova análise.
- As falhas de análise e leitura são contabilizadas ou devolvidas como erros sanitizados; os ficheiros de origem
  nunca são modificados.
