O gateway upstream `agentrouter` executa um filtro de conteúdos baseado em palavras-chave em
`messages[].content`. O filtro é parcialmente determinístico (bloqueia sempre
determinadas expressões) e parcialmente probabilístico (sensível a rajadas — torna-se
mais agressivo após pedidos rápidos e recupera após um período de espera).

Quando o WAF bloqueia um pedido, devolve:

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## Âmbito do filtro

O WAF inspeciona apenas `messages[].content`. **Não** inspeciona:

- O prompt `system`
- Blocos de conteúdo estruturado (`tool_result`, `tool_use`, `thinking`, `image`)
- Os campos `description` e `input_schema` das ferramentas
- Metadados do pedido, cabeçalhos ou ID do modelo

## Padrões sempre bloqueados (sem distinção entre maiúsculas e minúsculas)

| Padrão                             | Notas                                                        |
| ---------------------------------- | ------------------------------------------------------------ |
| Qualquer variante de `Lorem ipsum` | Todo o vocabulário latino de lorem é bloqueado               |
| `language model` (isolado)         | "the language model" e "large language model" são permitidos |
| `virtual assistant`                | "AI assistant" é permitido                                   |
| `I'm here to help`                 | "here to help" isolado também é bloqueado                    |
| `Claude, made by Anthropic`        | Apenas a expressão completa                                  |

## Padrões quase sempre bloqueados

| Padrão                                                    | Notas                                                     |
| --------------------------------------------------------- | --------------------------------------------------------- |
| `placeholder`                                             | Quando aparece isolado (não como nome de parâmetro, etc.) |
| `dummy data`                                              | Expressão inicial comum para fixtures                     |
| `foo bar baz`                                             | Expressão placeholder canónica                            |
| Tokens curtos repetidos (`AAA BBB CCC`, `test test test`) | Detetor de acumulação de palavras-chave                   |

## Comportamento sob carga

Após cerca de 5 pedidos rápidos num curto intervalo, o WAF começa a bloquear conteúdo
que normalmente seria permitido. O bucket fica menos restritivo após cerca de 5–10 segundos
de inatividade. Este é o mesmo limitador de taxa associado ao IP e à chave que causa
erros intermitentes `400 content-blocked` quando o Claude Code ou o Codex CLI
efetua várias chamadas de utilização de ferramentas/envio de mensagens em rápida sucessão.

## Mitigações já aplicadas no OmniRoute

1. **`open-sse/services/wafRateLimit.ts`** — proteção contra rajadas que impõe um
   intervalo mínimo de 500 ms entre pedidos enviados para qualquer URL `agentrouter:*`.
   O intervalo está muito abaixo da perceção humana de latência e impede
   a ativação do WAF em tráfego normal.

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — quando um upstream devolve
   `400 content-blocked`, o executor repete o pedido para o mesmo URL com
   backoff exponencial (1,5 s, 3,0 s, máximo de 2 tentativas). Após o backoff,
   o WAF normalmente fica menos restritivo e a nova tentativa é bem-sucedida.

3. **`tests/unit/compression/harness.test.ts`** — a fixture de teste
   `longInput` foi alterada de `"lorem ipsum dolor sit amet ".repeat(40)`
   para `"example content for testing purposes ".repeat(40)`, para que, quando
   o Claude Code lê este ficheiro através da ferramenta `Read`, o conteúdo do ficheiro
   não seja reenviado através de um bloco `tool_result` e não acione o WAF.

## Orientações para prompts e resultados de ferramentas

Se uma sessão do Claude Code ou do Codex CLI encontrar repetidamente
`400 content-blocked`, verifique se a mensagem mais recente do utilizador e o
resultado mais recente de uma ferramenta contêm algum dos padrões acima e reformule-os.
Soluções alternativas comuns:

- Substitua `Lorem ipsum …` por `example text …` ou pelo conteúdo real
  que o teste ou a fixture tenta representar.
- Substitua `placeholder` (quando aparece isolado) por `example value`,
  `sample value` ou pelo valor real.
- Substitua `language model` por `large language model` ou `the model`.
- Substitua `dummy data` por `sample data` ou por valores iniciais realistas.
- Substitua `I'm here to help` / `here to help` por uma introdução mais específica
  (por exemplo, "I'll review the file you mentioned").

## Comunicar os falsos positivos ao upstream

O filtro atual é excessivamente agressivo — bloqueia "Lorem ipsum" em
blocos `tool_result`, embora o operador claramente não pretendesse
injetar um prompt. Os operadores que pretendam que isto seja corrigido na origem devem
contactar `agentrouter.org` para comunicar os falsos positivos. A lista de bloqueio
acima é o resultado empírico de testes ao upstream em 2026-08-03.
