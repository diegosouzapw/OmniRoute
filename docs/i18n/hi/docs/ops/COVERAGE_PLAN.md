## नियम

- कवरेज लक्ष्य सोर्स फ़ाइलों पर लागू होते हैं, `tests/**` पर नहीं।
- `open-sse/**` प्रोडक्ट का हिस्सा है और इसे दायरे में रहना चाहिए।
- नया कोड प्रभावित क्षेत्रों में कवरेज को कम नहीं करना चाहिए।
- इम्प्लीमेंटेशन विवरणों के बजाय व्यवहार और ब्रांच परिणामों के परीक्षण को प्राथमिकता दें।
- `src/lib/db/**` के लिए व्यापक मॉक की बजाय अस्थायी SQLite डेटाबेस और छोटे फ़िक्स्चर को प्राथमिकता दें।

## वर्तमान कमांड सेट

- `npm run test:coverage`
  - यूनिट टेस्ट सूट के लिए मुख्य सोर्स कवरेज गेट
  - `text-summary`, `html`, `json-summary`, और `lcov` जनरेट करता है
- `npm run coverage:report`
  - नवीनतम रन से विस्तृत फ़ाइल-दर-फ़ाइल रिपोर्ट
- `npm run test:coverage:legacy`
  - केवल ऐतिहासिक तुलना के लिए

## ज्ञात कमी

वर्तमान कवरेज कमांड मुख्य Node यूनिट सुइट को मापता है और उससे पहुँचने वाले सोर्स को शामिल करता है, जिसमें `open-sse` भी शामिल है। यह अभी तक Vitest कवरेज को एक एकीकृत रिपोर्ट में मर्ज नहीं करता। यह मर्ज बाद में करना उपयोगी होगा, लेकिन 60% -> 80% की प्रगति शुरू करने के लिए यह कोई अवरोध नहीं है।
