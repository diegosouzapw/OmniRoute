कुछ सेवाओं को OmniRoute में एकीकृत किया गया था और बाद में उन्हें संचालित करने वाले लोगों के अनुरोध पर हटा दिया गया। यह पृष्ठ उन निष्कासनों का स्थायी अभिलेख है। इसका एकमात्र उद्देश्य उन्हें गलती से दोबारा जोड़े जाने से रोकना है: किसी पुराने fork, कैश किए गए npm tarball, संग्रहीत issue या "प्रदाता X को पुनर्स्थापित करें" अनुरोध को खोजने वाले योगदानकर्ता को ऐसी एक जगह चाहिए जो स्पष्ट रूप से कहे: **दोबारा शामिल न करें**।

यह पृष्ठ बंद या समाप्त हो चुकी सेवाओं की सूची **नहीं** है। उन्हें
[`FREE_TIERS.md`](FREE_TIERS.md) ("हटाई गईं / कोई निःशुल्क स्तर नहीं") में ट्रैक किया जाता है और सेवा के वापस आने पर उन्हें भी वापस लाया जा सकता है। नीचे दी गई प्रविष्टियाँ केवल तभी वापस लाई जा सकती हैं, जब अनुरोध में उल्लिखित संचालक से लिखित अनुमति प्राप्त हो और उस अनुमति का लिंक प्रविष्टि में दिया गया हो।

## नीति

1. **सेवा संचालक से प्राप्त निष्कासन अनुरोध का पालन किया जाता है, उस पर बातचीत नहीं की जाती।** OmniRoute किसी भी upstream सेवा से संबद्ध नहीं है। जब किसी सेवा का संचालक एकीकरण हटाने के लिए कहता है, तो उसे हटा दिया जाता है, चाहे एकीकरण ने आधिकारिक API का उपयोग किया हो या नहीं।
2. **"हटाया गया" का अर्थ OmniRoute द्वारा नियंत्रित प्रत्येक सतह से हटाया जाना है।** Executor, registry प्रविष्टि, प्रदाता आईडी और alias, मॉडल सूची, endpoints, environment variables, icon, dashboard cards, जनरेट किया गया प्रदाता संदर्भ, `FREE_TIERS.md`, environment संदर्भ, README में दी गई संख्याएँ, `llm.txt` mirrors, समर्पित tests और golden snapshots, code comments, CHANGELOG bullets (अभिलेखित reconciliation के साथ, `config/release/changelog-reconciliations.json` देखें), GitHub Releases notes, wiki और वे GitHub issues, discussions तथा pull requests जिनका विषय वह प्रदाता था (issues और discussions हटा दिए जाते हैं; pull requests के शीर्षक बदले जाते हैं, उनका विवरण प्रतिस्थापित किया जाता है और thread को lock कर दिया जाता है, क्योंकि GitHub pull requests को हटा नहीं सकता)।
3. **लिखित अनुमति के बिना इस पृष्ठ की किसी प्रविष्टि को कभी दोबारा शामिल न करें।** इसमें किसी भी प्रदाता catalog में आईडी या alias को वापस जोड़ना, किसी executor में domains जोड़ना, उसे "पुनर्स्थापित" करने वाले योगदानकर्ता के PR को स्वीकार करना, उसे निःशुल्क मॉडल catalog में जोड़ना या OmniRoute के माध्यम से उस तक मैन्युअल रूप से पहुँचने का तरीका दर्ज करना शामिल है। ऐसे PRs और issues को इस पृष्ठ के लिंक के साथ बंद करें।
4. **प्रविष्टि को न्यूनतम रखें।** केवल वही जानकारी दर्ज करें जिसकी किसी समीक्षक को दोबारा शामिल किए जाने की पहचान करने के लिए आवश्यकता हो: identifiers, domains, dates और निष्कासन करने वाला pull request। एकीकरण कैसे काम करता था, इसका वर्णन न करें।
5. **Regression guard `tests/unit/removed-providers-blocklist.test.ts` है।** नीचे दिया गया कोई identifier या domain यदि प्रदाता catalogs, executor map या प्रदाता registry sources में दोबारा दिखाई देता है, तो यह विफल हो जाता है। यहाँ नई पंक्ति जोड़ने वाले उसी PR में इस test में नए identifiers भी जोड़ें।

## प्रविष्टि जोड़ना

जब कोई नया निष्कासन अनुरोध प्राप्त हो:

1. पुष्टि करें कि अनुरोध सेवा के संचालक से आया है (उनके support address या उनके नियंत्रण वाले domain से), और संदेश को निजी रूप से सुरक्षित रखें।
2. नीति के बिंदु 2 में दी गई checklist के अनुसार एकीकरण हटाएँ। कुंजी-रहित प्रदाता के संदर्भ के रूप में
   [#12440](https://github.com/diegosouzapw/OmniRoute/pull/12440) और संग्रहीत connections वाले API-कुंजी प्रदाता के लिए [#10210](https://github.com/diegosouzapw/OmniRoute/pull/10210) का उपयोग करें (एक migration जोड़ें)।
3. उसी PR में ऊपर की तालिका में एक पंक्ति और
   `tests/unit/removed-providers-blocklist.test.ts` में identifiers जोड़ें।
4. PR merge होने के बाद संचालक को उत्तर दें और बताएँ कि क्या-क्या हटाया गया तथा OmniRoute क्या नहीं बदल सकता (पहले से प्रकाशित npm और Docker versions, git history, third-party forks)।
