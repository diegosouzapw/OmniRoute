`devin-cli-agentic` वास्तविक Claude Code रनटाइम को OmniRoute के स्थानीय Anthropic
Messages एंडपॉइंट का उपयोग करने देता है, जबकि आधिकारिक Devin CLI ACP stdio के माध्यम से मॉडल
प्रतिक्रियाएँ प्रदान करता है। यह मौजूदा Anthropic, Claude OAuth, Claude Web या `devin-cli`
प्रोवाइडर में कोई बदलाव नहीं करता।

> **वर्तमान स्थिति: Claude Code `2.1.258` पर पिन किया गया; ऑफ़लाइन और लाइव सत्यापन अंतिम बार
> `2.1.220` पर दर्ज किया गया था।** `2.1.220` पिन ने Devin CLI
> `3000.2.17` और मॉडल `swe-1-7-lightning` के माध्यम से तीन पृथक परिदृश्य पूरे किए; उस अंतिम लाइव रन ने क्लाइंट-स्वामित्व वाले `Read`,
> `Edit` और `Bash` टर्न, सफल `npm test` परिणाम, प्रोजेक्ट कमांड और स्किल
> डिस्कवरी, केवल-Devin रूटिंग और Claude की ओर शून्य आउटगोइंग ट्रैफ़िक को प्रमाणित किया। इसके बाद पिन को बढ़ाकर `2.1.258`
> कर दिया गया (वह CLI पीढ़ी जिसका OmniRoute की Claude पहचान प्रतिरूपण करती है, और पहली रिलीज़ लाइन जिसमें
> Fable 5.1 टियर मूल रूप से शामिल है)। नए पिन पर पिन की गई बेस इमेज में इंस्टॉलेशन लेयर और `claude --version` को
> सत्यापित किया गया, और ब्रिज यूनिट सुइट, `compose config` तथा
> स्थैतिक आइसोलेशन प्रमाण सफल होते हैं—लेकिन ऑफ़लाइन मॉक परिदृश्य और लाइव तीन-परिदृश्य
> सुइट को अभी दोबारा नहीं चलाया गया है। इस पिन के साथ ब्रिज पर भरोसा करने से पहले उन्हें फिर से चलाएँ
> ("पिन किए गए टूल अपडेट करना" देखें)।

## आर्किटेक्चर

```text
Claude Code 2.1.258 (पृथक गैर-रूट Linux कंटेनर)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-फ़ॉर्मैट, बिना प्रमाणीकरण वाला प्रोवाइडर)
  -> devin acp --agent-type summarizer (आधिकारिक ACP stdio, कोई Devin टूल नहीं)
  -> समर्पित devin-auth वॉल्यूम में Devin खाता
```

आधिकारिक CLI का डिफ़ॉल्ट ACP एजेंट अपने टूल स्वयं निष्पादित कर सकता है, इसलिए यह ब्रिज
उसका उपयोग नहीं करता। यह निर्धारित `summarizer` ACP एजेंट शुरू करता है, जिसके आधिकारिक CLI मोड में कोई टूल नहीं होता, और
क्रमबद्ध Anthropic अनुरोध को निष्पादन ट्रेस के रूप में फ़्रेम करता है। जब Claude-स्वामित्व वाली कोई अन्य
कार्रवाई आवश्यक होती है, तो प्रतिक्रिया में ठीक एक क्लाइंट टूल एनवेलप होना चाहिए। किसी भी ACP
`tool_call` या `tool_call_update` को प्रतिक्रिया को सफल घोषित किए जाने से पहले अस्वीकार कर दिया जाता है।

`open-sse/executors/devin-agentic/serializer.ts` में मौजूद सीरियलाइज़र `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` और Claude Code द्वारा
दिए गए टूल को संरक्षित रखता है। इमेज और अज्ञात ब्लॉक स्पष्ट रूप से विफल होते हैं। बड़े टूल परिणामों में
एक दृश्यमान ट्रंकेशन मार्कर का उपयोग किया जाता है।

पार्सर प्रति मॉडल टर्न एक स्वतंत्र `<tool>{...}</tool>` एनवेलप स्वीकार करता है। यह
अनुरोध की टूल सूची से नाम की जाँच करता है, उस टूल के JSON
Schema के विरुद्ध आर्ग्युमेंट सत्यापित करता है, मिश्रित विवरण/कार्रवाइयों को अस्वीकार करता है और एक सीमित सुधार की अनुमति देता है। इसके बाद Claude Code
परिणामी Anthropic `tool_use` को स्थानीय रूप से निष्पादित करता है और `tool_result` को OmniRoute के माध्यम से
वापस भेजता है।

## आइसोलेशन और खतरा मॉडल

होस्ट की Claude इंस्टॉलेशन, खाता और कॉन्फ़िगरेशन इस दायरे से बाहर हैं और उन्हें
निषिद्ध माना जाता है। Compose सेवाएँ:

- UID/GID `10001:10001` के रूप में, केवल-पढ़ने योग्य रूट फ़ाइल सिस्टम, हटाई गई क्षमताओं और
  `no-new-privileges` के साथ चलती हैं;
- निजी `/home/bridge`, समर्पित Claude कॉन्फ़िगरेशन वॉल्यूम, पृथक OmniRoute डेटा
  और अलग `devin-auth` वॉल्यूम का उपयोग करती हैं;
- केवल अस्थायी `.sandbox` वर्कस्पेस/साक्ष्य माउंट करती हैं;
- होस्ट होम, Keychain, SSH, क्लाउड क्रेडेंशियल या Docker सॉकेट माउंट नहीं करतीं;
- स्पष्ट एनवायरनमेंट बनाती हैं और Anthropic API/OAuth/रूटिंग वेरिएबल हटाती हैं;
- केवल-स्थानीय कुंजी के साथ Claude Code इन्फ़रेंस को केवल `http://omniroute:20128` पर निर्देशित करती हैं।

ऑफ़लाइन प्रोफ़ाइल एक आंतरिक नेटवर्क का उपयोग करती है। लाइव प्रोफ़ाइल में OmniRoute केवल
`network-guard` के माध्यम से आधिकारिक Devin एंडपॉइंट तक पहुँचता है; असंबंधित गंतव्य अस्वीकार कर दिए जाते हैं।
Claude Code के पास एक अलग, सभी आउटगोइंग ट्रैफ़िक अस्वीकार करने वाला गार्ड है और वह `NO_PROXY` के माध्यम से केवल स्थानीय OmniRoute
सेवा तक पहुँच सकता है। गार्ड ऑडिट फ़ाइलें केवल उनकी संबंधित गार्ड प्रक्रिया द्वारा माउंट की जाती हैं। स्क्रिप्ट
टोकन-मुक्त साक्ष्य एक्सपोर्ट करने से पहले फ़ाइल स्वामित्व, मोड, लिंक संख्या और प्रत्येक निर्णय को सत्यापित
करती हैं।

आइसोलेशन प्रमाण को स्वतंत्र रूप से चलाएँ:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

यह टोपोलॉजी, नामित माउंट, गैर-रूट/केवल-पढ़ने योग्य सेटिंग, स्पष्ट स्थानीय रूटिंग,
संवेदनशील एनवायरनमेंट वेरिएबल की अनुपस्थिति, Docker सॉकेट की अनुपस्थिति, `api.anthropic.com`
और `claude.ai` तक अवरुद्ध पहुँच, केवल-Devin प्रोवाइडर चयन तथा ACP बैकएंड अनुपलब्ध होने पर
स्पष्ट विफलता को सत्यापित करता है।

## पहली बार सेटअप और सामान्य उपयोग

पिन की गई इमेज बिल्ड करें:

```bash
./scripts/devin-bridge/build
```

केवल पृथक Devin वॉल्यूम को प्रमाणित करें:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

लॉगिन कमांड रिमोट/कंटेनर परिवेशों के लिए निर्धारित आधिकारिक मैन्युअल-टोकन प्रवाह का उपयोग करता है। मान सीधे CLI प्रॉम्प्ट में दर्ज किया जाता है; इसे प्रोसेस आर्ग्युमेंट के रूप में पास नहीं किया जाता, Git में लिखा नहीं जाता, या होस्ट से कॉपी नहीं किया जाता।

पृथक Claude Code रनटाइम लॉन्च करें:

```bash
./scripts/devin-bridge/launch
```

`launch` कंटेनराइज़्ड Claude Code शुरू करने से पहले पृथक्करण, Devin प्रमाणीकरण और मॉडल खोज की दोबारा जाँच करता है। यह कभी भी होस्ट के Claude एक्ज़ीक्यूटेबल को नहीं चलाता। मॉडल उपनाम `.env.devin-bridge` में सेट किए जा सकते हैं; प्रत्येक कॉन्फ़िगर किए गए मान में `devin-cli-agentic/` प्रीफ़िक्स होना आवश्यक है।

## सत्यापन कमांड

पुनरुत्पाद्य ऑफ़लाइन पथ के लिए किसी Devin खाते की आवश्यकता नहीं होती और इसमें रनटाइम इंटरनेट उपलब्ध नहीं होता:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

प्रमाणित ऑप्ट-इन लाइव पथ है:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

लाइव रनर ACP सत्रों को एक साथ बड़ी संख्या में खोलने से बचने के लिए परिदृश्यों के बीच प्रतीक्षा करता है और पाठ्य दावों पर भरोसा करने के बजाय संरचित Claude स्ट्रीम इवेंट को सत्यापित करता है। इसके तीन परिदृश्य निम्नलिखित प्रमाणित करते हैं:

1. प्रोजेक्ट को सीधे पढ़ना और दोष विश्लेषण;
2. एक वास्तविक `Edit`, क्लाइंट-स्वामित्व वाला `Bash` `npm test`, और एक अंतिम परिणाम;
3. `/bridge-check` के साथ `bridge-proof` की खोज, प्रोजेक्ट को पढ़ना, क्लाइंट-स्वामित्व वाले एक अन्य `npm test` की सफलता, और बिना किसी लंबित कार्य के पूर्णता।

अंतिम गेट Devin नेटवर्क ऑडिट की भी जाँच करता है और यह आवश्यक बनाता है कि Claude इग्रेस ऑडिट खाली रहे।

## पिन किए गए टूल अपडेट करना

इमेज में Node, Claude Code और Devin CLI को `docker/devin-bridge/Dockerfile` में पिन किया गया है। अपडेट करने के लिए:

1. स्पष्ट संस्करण बदलें;
2. दोनों आर्किटेक्चर-विशिष्ट Devin आर्काइव चेकसम को आधिकारिक आर्टिफ़ैक्ट के मानों से बदलें;
3. दोबारा बिल्ड करें और प्रत्येक ऑफ़लाइन सत्यापन कमांड चलाएँ;
4. इमेज के अंदर संस्करणों की पुष्टि करें;
5. प्रमाणित तीन-परिदृश्य वाली लाइव सुइट दोबारा चलाएँ।

किसी भी CLI को होस्ट पर ग्लोबल रूप से इंस्टॉल न करें और चेकसम सत्यापन को किसी असत्यापित डाउनलोड से न बदलें।

## निदान और क्लीनअप

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  स्थानीय रूटिंग और सैनिटाइज़ किए गए एक्ज़ीक्यूटर एरर दिखाता है।
- `.sandbox/evidence/mock-acp.jsonl` नियतात्मक मॉक ACP कार्रवाइयाँ रिकॉर्ड करता है।
- `.sandbox/evidence/claude-stream.jsonl` वास्तविक Claude Code ऑफ़लाइन रन रिकॉर्ड करता है।
- `.sandbox/evidence/live-*.jsonl` तीन सत्यापित लाइव स्ट्रीम रिकॉर्ड करता है।
- `.sandbox/evidence/egress.jsonl` और `.sandbox/evidence/claude-egress.jsonl` गार्ड ऑडिट की सत्यापित, टोकन-मुक्त प्रतियाँ हैं।

लॉगिन/कॉन्फ़िगरेशन वॉल्यूम को संरक्षित रखते हुए स्वामित्व वाले कंटेनर और नेटवर्क रोकें:

```bash
./scripts/devin-bridge/clean
```

नामित वॉल्यूम सहित, ब्रिज के स्वामित्व वाले संपूर्ण परिवेश को हटाएँ:

```bash
./scripts/devin-bridge/clean --all
```

## सीमाएँ

- ब्रिज निर्धारित बिना-टूल वाली `summarizer` भूमिका पर निर्भर करता है, क्योंकि Devin CLI `3000.2.17`
  किसी निष्पक्ष बिना-टूल वाले ACP एजेंट को उजागर नहीं करता। एडाप्टर सारांश-जैसी
  मध्यवर्ती प्रतिक्रियाओं की भरपाई करता है, लेकिन एक सीमित सुधार फिर भी स्पष्ट रूप से विफल हो सकता है।
- लाइव ACP कॉल क्षणिक `502`/`504` प्रतिक्रियाएँ लौटा सकती हैं। हार्नेस परिदृश्यों के बीच अंतराल रखता है;
  लगातार विफलता की स्थिति में यह बंद रहकर विफल होता है और कभी किसी अन्य प्रदाता का चयन नहीं करता।
- ACP संदर्भ प्रत्येक Anthropic अनुरोध से पुनर्निर्मित किया जाता है; कोई प्रोसेस/सेशन
  संबद्धता नहीं होती।
- प्रत्येक मॉडल प्रतिक्रिया में एक टूल कॉल समर्थित है; समानांतर कॉल अस्वीकार कर दी जाती हैं।
- इमेज स्पष्ट रूप से असमर्थित हैं। विज़न, थिंकिंग आउटपुट, प्रयास नियंत्रण और 1M
  संदर्भ विंडो को उपलब्ध घोषित नहीं किया जाता।
- SSE मान्य Anthropic जीवनचक्र इवेंट का उपयोग करता है, लेकिन सीमित ACP टर्न एकत्र होने के बाद उत्सर्जित होता है;
  ACP चंक को क्रमिक रूप से अग्रेषित नहीं किया जाता।
