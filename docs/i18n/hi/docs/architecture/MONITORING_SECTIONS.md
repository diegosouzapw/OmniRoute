## निगरानी अनुभाग (पुनर्गठित)

निगरानी अनुभाग में अब सबसे ऊपर **गतिविधि** है, जिसके बाद **3 उपसमूह** हैं:

```
निगरानी
├── गतिविधि             ← टाइमलाइन फ़ीड (शीर्ष-स्तरीय आइटम)
├── लॉग समूह
│   ├── लॉग (सभी)
│   ├── प्रॉक्सी लॉग
│   └── कंसोल लॉग
├── ऑडिट समूह
│   ├── ऑडिट लॉग
│   ├── MCP ऑडिट
│   └── A2A ऑडिट
└── सिस्टम समूह
    ├── स्वास्थ्य
    └── रनटाइम
```

### पुरानी संरचना से क्या बदला

| पहले                                                                              | बाद में                                        |
| --------------------------------------------------------------------------------- | ---------------------------------------------- |
| गतिविधि = लॉग के अंदर एक टैब, जो ऑडिट लॉग रेंडर करता था                           | गतिविधि = समर्पित फ़ीड (`/dashboard/activity`) |
| निगरानी में लागत पैरामीटर समूह                                                    | लागत अनुभाग में स्थानांतरित                    |
| समतल सूची: लॉग, गतिविधि (लॉग), ऑडिट, स्वास्थ्य, रनटाइम, मूल्य निर्धारण, बजट, कोटा | संरचित 3-समूह + समर्पित लागत अनुभाग            |

## गतिविधि बनाम ऑडिट लॉग

ये दोनों अब अलग-अलग हैं:

| आयाम               | गतिविधि (`/dashboard/activity`)                        | ऑडिट लॉग (`/dashboard/audit`)             |
| ------------------ | ------------------------------------------------------ | ----------------------------------------- |
| **उद्देश्य**       | उपयोगकर्ता-केंद्रित इवेंट फ़ीड ("हाल ही में क्या हुआ") | अनुपालन / सुरक्षा लॉग                     |
| **डेटा स्रोत**     | `GET /api/compliance/audit-log?level=high`             | `GET /api/compliance/audit-log?level=all` |
| **फ़ॉर्मेट**       | दिन के अनुसार समूहीकृत टाइमलाइन, पठनीय क्रियाएँ + आइकन | सघन पृष्ठांकित तालिका, 50/पृष्ठ           |
| **फ़िल्टर**        | इवेंट प्रकार श्रेणी                                    | कार्रवाई, गंभीरता, कर्ता, दिनांक सीमा     |
| **एक्सपोर्ट**      | उपलब्ध नहीं                                            | JSON एक्सपोर्ट                            |
| **कर्ता फ़िल्टर**  | लागू नहीं                                              | कर्ता के अनुसार फ़िल्टर किया जा सकता है   |
| **दिखाए गए इवेंट** | केवल उच्च-स्तरीय कार्रवाइयाँ (अनुमति-सूची)             | सभी ऑडिट इवेंट                            |

### उच्च-स्तरीय कार्रवाइयों की अनुमति-सूची

`src/lib/audit/highLevelActions.ts` में परिभाषित। यह नियंत्रित करती है कि गतिविधि
फ़ीड में कौन-से इवेंट दिखाई दें। अनुमति-सूची में निम्न शामिल हैं:

- प्रदाता जोड़ने/हटाने/परीक्षण करने के इवेंट
- कॉम्बो बनाना/अपडेट करना/हटाना
- API कुंजी जीवनचक्र (बनाना, निरस्त करना, रोटेट करना)
- बजट सीमा पूरी होना
- प्रमाणीकरण लॉगिन/लॉगआउट
- क्लाउड एजेंट सत्र बनाना
- MCP टूल पंजीकरण
- वेबहुक बनाना/हटाना
- कोटा पूल/प्लान परिवर्तन (`quota.*` कार्रवाइयाँ, Group B)
- प्लेटफ़ॉर्म इवेंट (अपडेट, डिप्लॉय)
- कौशल इंस्टॉल करना/हटाना

जो इवेंट इस सूची में नहीं हैं, वे केवल ऑडिट लॉग में दिखाई देते हैं।

### नई उच्च-स्तरीय कार्रवाई जोड़ना

`src/lib/audit/highLevelActions.ts` को संपादित करें और कार्रवाई स्ट्रिंग को
`HIGH_LEVEL_ACTIONS` में जोड़ें। इसके लिए एक PR आवश्यक है (सूची कोड में है, DB से कॉन्फ़िगर करने योग्य नहीं)।
संबंधित आइकन को `src/lib/audit/activityIcons.ts` में जोड़ा जा सकता है।

## रीडायरेक्ट: `/dashboard/logs/activity`

पुराना पाथ `/dashboard/logs/activity`, `src/app/(dashboard)/dashboard/logs/activity/page.tsx`
में `permanentRedirect()` के माध्यम से स्थायी रूप से (HTTP 308)
`/dashboard/activity` पर रीडायरेक्ट किया जाता है।

लेगेसी साइडबार ID `logs-activity` को `HIDEABLE_SIDEBAR_ITEM_IDS`
में बनाए रखा गया है (लेकिन `SIDEBAR_DEFINITIONS` से हटा दिया गया है), ताकि पुराने ID को
संदर्भित करने वाले उपयोगकर्ता प्रीसेट प्रभावित न हों।
