OmniRoute npm + Docker आर्टिफ़ैक्ट प्रकाशित करता है। ये गेट उत्पत्ति-प्रमाण (provenance),
इन्वेंट्री (SBOM) और CVE स्कैनिंग प्रदान करते हैं; ये सभी OSS हैं और रिलीज़ वर्कफ़्लो में
एकीकृत हैं। **पहले एडवाइज़री** दृष्टिकोण — अभी ये रिपोर्ट करते हैं और पहली सफल
रिलीज़ के बाद इन्हें ब्लॉकिंग बनाया जाएगा।

| गेट                        | टूल                                            | स्थान                         | ब्लॉक करता है?            | आउटपुट                                            |
| -------------------------- | ---------------------------------------------- | ----------------------------- | ------------------------- | ------------------------------------------------- |
| SLSA उत्पत्ति-प्रमाण (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | केवल प्रकाशन विफल होने पर | बैज npmjs / `npm audit signatures`                |
| SBOM npm                   | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | केवल जनरेशन विफल होने पर  | रिलीज़ एसेट + आर्टिफ़ैक्ट                         |
| SBOM इमेज                  | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (मर्ज)   | एडवाइज़री                 | CycloneDX आर्टिफ़ैक्ट                             |
| Trivy CVE (SARIF)          | `aquasecurity/trivy-action`                    | `docker-publish.yml` (मर्ज)   | एडवाइज़री                 | SARIF (HIGH+CRITICAL) → सुरक्षा टैब               |
| Trivy CRITICAL गेट         | `aquasecurity/trivy-action`                    | `docker-publish.yml` (मर्ज)   | **ब्लॉकिंग**              | सुधार-योग्य CRITICAL पर `exit-code: '1'`          |
| osv vulnCount              | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **ब्लॉकिंग**              | `metrics.vulnCount` को रैचेट करता है (दिशा: नीचे) |
| OpenSSF Scorecard          | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | एडवाइज़री                 | SARIF → सुरक्षा + बैज                             |

इमेज CVE रैचेट `docker-publish.yml` में **दो चरणों** का उपयोग करता है: SARIF चरण
(`HIGH,CRITICAL`, `exit-code: 0`) HIGH+CRITICAL को बिना ब्लॉक किए सुरक्षा टैब में
दृश्यमान रखता है; _CRITICAL गेट_ चरण (`severity: CRITICAL`, `ignore-unfixed: true`,
`exit-code: 1`) **उपलब्ध सुधार वाले** CRITICAL CVE पर रिलीज़ को विफल कर देता है। `ignore-unfixed`
किसी अपस्ट्रीम पैच के बिना बेस-इमेज CVE के कारण रिलीज़ को ब्लॉक होने से रोकता है।

## ⚠️ CVE परिवर्तनशीलता (ब्लॉकिंग osv/Trivy गेट)

osv और Trivy निर्भरताओं की तुलना उन CVE डेटाबेस से करते हैं जो **लगातार बढ़ते रहते हैं**। कोई ऐसा PR
जो **किसी निर्भरता को नहीं बदलता**, अचानक लाल हो सकता है क्योंकि किसी मौजूदा निर्भरता में
नया CVE सार्वजनिक किया गया है (osv: मापा गया `vulnCount` > बेसलाइन; Trivy: इमेज में कोई नया
सुधार-योग्य CRITICAL)। **यह ब्लॉकिंग CVE गेट का अपेक्षित परिचालन व्यवहार है,
उत्पाद में कोई प्रतिगमन नहीं।**

जब किसी नए सार्वजनिक किए गए CVE के कारण osv या Trivy लाल हो जाए, तो समाधान है:

1. **प्रभावित निर्भरता का संस्करण बढ़ाएँ** (प्राथमिकता) — `package.json` के
   `overrides` (ट्रांज़िटिव निर्भरताएँ) के माध्यम से पैच किए गए संस्करण में अपग्रेड करें या पैच किए गए बेस पर इमेज दोबारा बनाएँ।
2. **यदि कोई अपस्ट्रीम सुधार उपलब्ध नहीं है:**
   - **osv:** `config/quality/quality-baseline.json` में `metrics.vulnCount` को फिर से बेसलाइन करें
     (`npm run quality:ratchet -- --update` समर्पित गेट को कवर नहीं करता — औचित्य नोट +
     ट्रैकिंग इश्यू के साथ मान को मैन्युअल रूप से संपादित करें, `direction:down`)।
   - **Trivy:** औचित्य टिप्पणी + ट्रैकिंग इश्यू के साथ `.trivyignore` में एक प्रविष्टि
     जोड़ें (प्रति पंक्ति एक CVE-ID)। `ignore-unfixed: true` बिना पैच वाले CVE को
     पहले से ही स्वचालित रूप से कवर करता है।

टूल अनुपस्थित होने या मापन विफल होने पर दोनों गेट **सुरक्षित रूप से SKIP** (exit 0) करते हैं
(osv-scanner का PATH में न होना, osv.dev/नेटवर्क का अनुपलब्ध होना, अमान्य JSON) — किसी
**मापन** की विफलता कभी ब्लॉक नहीं करती; केवल **मापा गया** प्रतिगमन ब्लॉक करता है।

## बैकलॉग: Scorecard एडवाइज़री → ब्लॉकिंग

Scorecard रिपोर्टिंग के साथ पहली सफल रिलीज़ के बाद:

- Scorecard: स्कोर रैचेट (मापे गए स्कोर को स्थिर करता है; वह घट नहीं सकता)।

यह Phase 7 गेट (osv-scanner, gitleaks, actionlint+zizmor) का पूरक है: zizmor
स्वयं वर्कफ़्लो का ऑडिट करता है; Scorecard समग्र रूप से रिपॉज़िटरी की स्थिति को मापता है।
