## कानूनी और नैतिक सूचना

स्टेल्थ सुविधाएँ इसलिए मौजूद हैं ताकि OmniRoute उपयोगकर्ता-स्वामित्व वाले आधिकारिक खातों (Claude Code CLI, Codex, Antigravity, Cursor आदि) और OmniRoute के एकीकृत API के बीच एक संगतता परत के रूप में कार्य कर सके। वे धोखाधड़ी पहचान से बचने, क्रेडेंशियल साझा करने या प्रदाता की सेवा की शर्तों का उल्लंघन करने के लिए **नहीं** हैं। अनुरक्षकों की अपेक्षा है कि ऑपरेटर खाते बनाते समय स्वीकार की गई अपस्ट्रीम ToS का अनुपालन करें।

## TLS फिंगरप्रिंटिंग परत

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

स्थायी `wreq-js` सत्र प्रत्येक खाता स्कोप और समाधान किए गए प्रॉक्सी के लिए आवश्यकतानुसार बनाए जाते हैं।
प्रोसेस-व्यापी `TlsClient`, Cloudflare के पीछे स्थित अपस्ट्रीम के लिए **macOS पर Chrome 124** का
प्रतिरूपण करने वाले अधिकतम 128 सत्रों को पूल करता है। नेटिव रनटाइम अनुपलब्ध होने पर
`TlsClient.fetch()` बिना फ़ॉलबैक के विफल होता है; कॉलर इस रैपर के बाहर स्पष्ट रूप से किसी फ़ॉलबैक का चयन कर सकता है।

- सत्र प्रोफ़ाइल: `browser: "chrome_124", os: "macos"`
- प्रॉक्सी समाधान (प्राथमिकता): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (लोअर-केस भी)
- टाइमआउट: `TLS_CLIENT_TIMEOUT_MS` (`FETCH_TIMEOUT_MS` से इनहेरिट होता है, डिफ़ॉल्ट 600000)
- `wreq-js` Response, fetch-संगत है (`headers`, `text()`, `json()`, `clone()`, `body`)।
- फ़र्स्ट-बाइट वॉचडॉग (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656): `TlsClient.fetch()`
  अपस्ट्रीम हेडर आते ही रिज़ॉल्व हो जाता है, इसलिए अकेला `TLS_CLIENT_TIMEOUT_MS` ऐसी बॉडी को सीमित नहीं कर सकता
  जो कभी पहली बाइट प्रदान नहीं करती। `guardTlsFirstByte()` बॉडी के पहले `read()` और
  `TLS_FIRST_BYTE_WATCHDOG_MS` (डिफ़ॉल्ट `10000`, `0` इसे अक्षम करता है) के बीच रेस कराता है; स्वस्थ बॉडी
  अप्रभावित रहती है, जबकि रुकी हुई बॉडी wreq रीडर को रद्द कर देती है और `proxyFetch` के मौजूदा
  TLS-फ़ॉलबैक लॉजिक को डायरेक्ट/प्रॉक्सी डिस्पैचर पर जाने देती है (ऐसा अनुरोध जिसे सुरक्षित रूप से फिर से नहीं चलाया जा सकता, जैसे
  बॉडी वाला POST, चुपचाप पुनः प्रयास किए जाने के बजाय अब भी त्रुटि उत्पन्न करता है)।

### वेब-कुकी प्रदाता ट्रांसपोर्ट — wreq-js 3.2.0

`open-sse/services/tlsClientBase.ts` नीचे दिए गए पाँच विशिष्ट
वेब-कुकी ट्रांसपोर्ट के लिए साझा अडैप्टर है। प्रत्येक हल्का प्रदाता रैपर एक ब्राउज़र/OS प्रोफ़ाइल चुनता है। अडैप्टर
`open-sse/utils/tlsClient.ts` में मौजूद एकल wreq रनटाइम लोडर और ट्रांसपोर्ट पूल का उपयोग करता है, जिसे
प्रोफ़ाइल + OS + समाधान किए गए प्रॉक्सी के आधार पर कुंजीबद्ध किया जाता है, जबकि प्रत्येक अनुरोध `cookieMode: "ephemeral"` का उपयोग करता है। इसलिए खाते और
अनुरोध ट्रांसपोर्ट-स्तरीय कनेक्शन साझा करते हैं, लेकिन कभी भी wreq सत्र या कुकी जार साझा नहीं करते।

| प्रदाता    | प्रोफ़ाइल     | अनुकरण किया गया OS | स्ट्रीम EOF नीति                        |
| ---------- | ------------- | ------------------ | --------------------------------------- |
| Claude     | `chrome_146`  | Linux              | `[DONE]` शामिल करें                     |
| Perplexity | `firefox_148` | macOS              | `event: end_of_stream` शामिल करें       |
| Grok       | `chrome_146`  | Linux              | `[DONE]` को छोड़ दें                    |
| Notion     | `chrome_146`  | Windows            | `[DONE]` शामिल करें                     |
| LMArena    | `chrome_146`  | Windows            | कोई सेंटिनल नहीं; नेटिव EOF पर बंद करें |

- स्ट्रीमिंग सीधे नेटिव रिस्पॉन्स `ReadableStream` का उपभोग करती है; कोई अस्थायी फ़ाइल या साइडकार
  नहीं बनाया जाता।
- स्ट्रीम उपलब्ध कराने से पहले अधिकतम 256 आरंभिक बाइट का निरीक्षण किया जाता है। SSE प्रदाता गैर-SSE
  त्रुटियों को बफ़र करते हैं; Grok/LMArena, Cloudflare चुनौतियों को `403` और HTML इंटरस्टिशियल को `502` में मैप करते हैं।
- नेटिव अनुरोध टाइमआउट को एक निरपेक्ष JS हार्ड डेडलाइन से रैप किया जाता है। हैंग होने पर केवल
  प्रभावित प्रोफ़ाइल/OS/प्रॉक्सी ट्रांसपोर्ट अमान्य करके बंद किया जाता है, फिर अगला अनुरोध उसे पुनः बनाता है।
- प्रॉक्सी समाधान की प्राथमिकता है: प्रति-कॉल `proxyUrl` → अनुरोध-स्कोप वाला खाता/डैशबोर्ड संदर्भ →
  `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (लोअरकेस वेरिएंट सहित)। समाधान त्रुटियाँ
  डायरेक्ट कनेक्शन लीक करने के बजाय बिना फ़ॉलबैक के विफल होती हैं। LMArena जानबूझकर `arena.ai` के विरुद्ध समाधान करता है।
- `byteResponse`, UTF-8 करप्शन के बिना कंटेंट-टाइप युक्त `data:` URL लौटाता है।
- त्रुटियाँ हैं: `TlsClientUnavailableError` (पैकेज/ऐडऑन अनुपलब्ध), `TlsClientHangError`
  (डेडलाइन पार हो गई), और `WreqTransportCapacityError` (साझा सत्र-क्षमता त्रुटि कोड),
  जब सभी 128 सीमित प्रोफ़ाइल/OS/प्रॉक्सी स्लॉट सक्रिय हों या बंद हो रहे हों।

ऊपर दिया गया सामान्य `TlsClient` सत्र स्थायी ब्राउज़र-समर्थित कुकी
स्थिति के लिए विशिष्ट बना रहता है। दोनों पथ एक कैश किए गए wreq मॉड्यूल लोडर और प्रोसेस लाइफ़साइकल हुक का पुनः उपयोग करते हैं; उनके पूल अलग
रहते हैं क्योंकि उनकी कुकी अवधियाँ जानबूझकर अलग हैं।

प्रोफ़ाइल पिन किए गए पैकेज द्वारा समर्थित हैं, लेकिन वास्तविक WAF स्वीकृति स्थानीय
कॉन्ट्रैक्ट परीक्षणों से स्वतंत्र रूप से बदल सकती है। किसी अपस्ट्रीम ब्राउज़र के साथ समानता का दावा करने से पहले फिंगरप्रिंट परिवर्तनों को
स्पष्ट रूप से अधिकृत लाइव खाते के विरुद्ध सत्यापित करें।

## Claude Code स्टेल्थ बंडल

जब `cliCompatMode` चालू होता है, तो OmniRoute बाहर जाने वाले Claude अनुरोधों को इस तरह पुनर्गठित करता है कि उन्हें `claude-cli` ट्रैफ़िक से अलग पहचानना संभव न हो। तीन मॉड्यूल मिलकर काम करते हैं:

### `claudeCodeFingerprint.ts`

बिलिंग हेडर में एम्बेड किया गया 3-वर्णों का `cc_version` फ़िंगरप्रिंट परिकलित करता है:

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (हार्डकोड किया गया; आधिकारिक क्लाइंट से मेल खाता है)
- इनपुट: पहले उपयोगकर्ता संदेश के टेक्स्ट में इंडेक्स 4, 7, 20 पर मौजूद वर्ण + वर्ज़न स्ट्रिंग
- आउटपुट: 3-वर्णों का हेक्स प्रीफ़िक्स

### `claudeCodeCCH.ts` (क्लाइंट कंटेंट हैश)

सर्वर-साइड अखंडता जाँच, जिसे आधिकारिक Claude Code CLI, Bun/Zig के माध्यम से परिकलित करता है। OmniRoute इसे `xxhash-wasm` के साथ पुनः कार्यान्वित करता है:

1. बॉडी को `cch=00000;` प्लेसहोल्डर के साथ सीरियलाइज़ करें
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. शून्य से पैड किया गया 5-वर्णों का लोअरकेस हेक्स
4. `cch=00000;` को परिकलित टोकन से बदलें

कॉन्स्टेंट:

- सीड: `0x6e52736ac806831e`
- पैटर्न: `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

"संवेदनशील" क्लाइंट नामों के पहले वर्ण के बाद एक Unicode **ज़ीरो-विथ जॉइनर** (`U+200D`) सम्मिलित करता है, ताकि अपस्ट्रीम फ़िल्टर उन्हें grep न कर सकें। डिफ़ॉल्ट शब्द सूची:

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

इन पर लागू: `system` ब्लॉक, सभी `messages[].content`, और `tools[].description` / `tools[].function.description`। ऑपरेटर इसे `setSensitiveWords()` के माध्यम से ओवरराइड कर सकता है।

### `claudeCodeCompatible.ts` — `anthropic-compatible-cc-*` प्रोवाइडर

ऐसे तृतीय-पक्ष Anthropic रिले के लिए, जो केवल "वास्तविक Claude Code" ट्रैफ़िक स्वीकार करते हैं:

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.258 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- डिफ़ॉल्ट रूप से `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"`
- प्रति-कनेक्शन "Enable redact-thinking beta" टॉगल तब `redact-thinking-2026-02-12` जोड़ता है, जब किसी CC Compatible अपस्ट्रीम को विशेष रूप से रिडैक्टेड थिंकिंग स्ट्रीम की आवश्यकता होती है
- प्रति-कनेक्शन "Enable summarized thinking display" टॉगल `providerSpecificData.requestDefaults.summarizeThinking` संग्रहीत करता है और उन CC Compatible थिंकिंग अनुरोधों में `display: "summarized"` जोड़ता है, जिन्होंने पहले से कोई डिस्प्ले मोड सेट नहीं किया है

## Antigravity स्टेल्थ

Antigravity अनुरोध कॉलर के टेक्स्ट को बाइट-दर-बाइट यथावत रखते हैं। किसी IDE क्लाइंट की नकल करने के लिए OmniRoute प्रॉम्प्ट में ज़ीरो-विथ वर्ण सम्मिलित नहीं करता और न ही टूल का नाम बदलता या उन्हें इंजेक्ट करता है।

### `antigravityHeaderScrub.ts`

फ़ॉरवर्ड करने से पहले Stainless SDK मार्कर (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`) हटा देता है।

### ⚠️ जोखिम: `ANTIGRAVITY_CREDITS=always` (अकाउंट-बैन का प्रमुख जोखिम क्षेत्र)

`ANTIGRAVITY_CREDITS=always` (जिसका उपयोग `open-sse/executors/antigravity.ts` करता है) Google के फ़्री-टियर कोटा द्वारा अनुरोधों को सीमित होने देने के बजाय **प्रत्येक** अनुरोध को Antigravity AI Credit Overages (भुगतान वाले Google क्रेडिट) के माध्यम से रूट करता है। इसे एक फ़ीचर के रूप में दस्तावेज़ित किया गया है, लेकिन यह **हमें मिलने वाली ToS उल्लंघन रिपोर्टों का सबसे आम कारण है** — `=always` के साथ कुछ घंटों तक चलने के बाद कई Google Ultra अकाउंट को `403 / "service disabled for ToS violation" / insufficient_quota` के साथ प्रतिबंधित किया गया है।

अपस्ट्रीम प्रवर्तन **Google की ओर से** होता है, और OmniRoute इसे रोक नहीं सकता। एनवायरनमेंट वेरिएबल का नाम और मौजूदा दस्तावेज़ इसे ऐसा दर्शाते हैं मानो इसे चालू करना सुरक्षित हो; जबकि ऐसा नहीं है।

**यह केवल फ़्री-टियर उपयोग की तुलना में दुरुपयोग पहचान को अधिक आक्रामक रूप से क्यों सक्रिय करता है:**

- किसी एक Google अकाउंट पर निरंतर स्वचालित खर्च, फ़्री-टियर के कोटा तक पहुँचकर रुक जाने वाले उपयोग की तुलना में अलग तरह से फ़्लैग होता है।
- क्रेडिट ओवरेज पर कोई दर सीमा नहीं होती, इसलिए गलत तरीके से कॉन्फ़िगर किया गया क्लाइंट कुछ ही मिनटों में कई सौ USD खर्च कर सकता है और API-की पुनर्विक्रय या बॉट ट्रैफ़िक जैसा दिखाई दे सकता है।
- एक ही बाहरी IP से कई OmniRoute उपयोगकर्ताओं द्वारा समानांतर रूप से ओवरेज क्रेडिट इस्तेमाल करना इस संकेत को और मज़बूत करता है।

**अनुशंसित रुख:**

1. डिफ़ॉल्ट `ANTIGRAVITY_CREDITS=off` बनाए रखें, जब तक कि ऑपरेटर भुगतान वाले क्रेडिट और अकाउंट प्रवर्तन के जोखिम को स्पष्ट रूप से स्वीकार न करे। `retry` पहले सामान्य अनुरोध भेजता है और योग्य कोटा 429 के बाद अधिकतम एक बार क्रेडिट इंजेक्ट करता है; `always` पहले ही अनुरोध में क्रेडिट इंजेक्ट करता है।
2. किसी एक Antigravity अकाउंट को पूरी तरह व्यस्त करने के बजाय **Auto-Combo के माध्यम से प्रोवाइडरों में लोड वितरित करें** (`model: "auto"` या `kr/glm/etc`-combo)।
3. Antigravity प्रोवाइडर के संपादन पेज में **प्रति-कनेक्शन RPM सीमाएँ सेट करें** (Dashboard → Providers → Antigravity → connection → rate limit)। निरंतर उपयोग के लिए 30–60 RPM एक तर्कसंगत ऊपरी सीमा है।
4. **स्थिर, ऑपरेटर-नियंत्रित अपस्ट्रीम नेटवर्किंग का उपयोग करें** और असंबंधित उपयोगकर्ताओं या वर्कलोड के बीच एक अकाउंट साझा करने से बचें।
5. **प्रतिबंधित होने पर**: Google द्वारा भेजे गए सटीक `quota_exceeded` / `service disabled` रिस्पॉन्स बॉडी के साथ `support.google.com` → "Restore Workspace/Account access" के माध्यम से अपील करें। अकाउंट बहाली की गारंटी नहीं है।

एनवायरनमेंट संदर्भ प्रत्येक क्रेडिट मोड के अकाउंट और खर्च संबंधी प्रभावों का दस्तावेज़ीकरण करता है।

संबंधित स्थान:

- `open-sse/executors/antigravity.ts` — `process.env.ANTIGRAVITY_CREDITS` पढ़ता है
- `src/lib/oauth/providers/antigravity.ts` — क्रेडेंशियल प्लंबिंग
- मूल घटना रिपोर्ट: चर्चा [#1183](https://github.com/diegosouzapw/OmniRoute/discussions/1183)

## CLI फ़िंगरप्रिंट रजिस्ट्री — `open-sse/config/cliFingerprints.ts`

प्रति-प्रदाता तालिका, जो आधिकारिक CLI के mitmproxy ट्रेस से कैप्चर किए गए हेडर के **सटीक** क्रम और JSON बॉडी फ़ील्ड के क्रम को निर्धारित करती है। वर्तमान में पंजीकृत: `codex`, `claude`, साथ ही `antigravity` और `github` के लिए `providerHeaderProfiles.ts` में रनटाइम-व्युत्पन्न प्रोफ़ाइल।

```ts
interface CliFingerprint {
  headerOrder: string[]; // केस-संवेदी
  bodyFieldOrder: string[]; // शीर्ष-स्तरीय JSON कुंजियाँ
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

env के माध्यम से प्रत्येक प्रदाता के लिए टॉगल करें (नीचे देखें)। अक्षम होने पर, हेडर/बॉडी कुंजियाँ Node/JSON द्वारा दिए गए किसी भी क्रम में दिखाई देती हैं — जिससे फ़िंगरप्रिंट करना आसान हो जाता है।

## MITM प्रॉक्सी (Antigravity, Linux/macOS/Windows)

जिन CLI की बाइनरी को `OPENAI_BASE_URL` के माध्यम से रीडायरेक्ट नहीं किया जा सकता, उनके लिए OmniRoute एक स्थानीय TLS-टर्मिनेटिंग प्रॉक्सी चलाता है। एंडपॉइंट `src/app/api/cli-tools/antigravity-mitm/` के अंतर्गत स्थित हैं।

| विधि   | एंडपॉइंट                                | उद्देश्य                                           |
| ------ | --------------------------------------- | -------------------------------------------------- |
| GET    | `/api/cli-tools/antigravity-mitm`       | स्थिति — चल रहा है, pid, dnsConfigured, certExists |
| POST   | `/api/cli-tools/antigravity-mitm`       | MITM शुरू करें (`apiKey` + `sudoPassword` आवश्यक)  |
| DELETE | `/api/cli-tools/antigravity-mitm`       | MITM रोकें                                         |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | मॉडल उपनामों की सूची बनाएँ                         |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | किसी टूल के लिए मॉडल उपनाम सहेजें                  |

इंटरसेप्ट किया जाने वाला लक्षित होस्ट: **`daily-cloudcode-pa.googleapis.com`** (Antigravity का अपस्ट्रीम)।

### प्रारंभ क्रम (`src/mitm/manager.ts::startMitm`)

1. `selfsigned` के माध्यम से स्व-हस्ताक्षरित प्रमाणपत्र जनरेट करें (RSA-2048, SHA-256, 1y) — `cert/generate.ts`
2. प्रमाणपत्र को सिस्टम ट्रस्ट स्टोर में इंस्टॉल करें — `cert/install.ts`
3. hosts प्रविष्टि `127.0.0.1 daily-cloudcode-pa.googleapis.com` जोड़ें — `dns/dnsConfig.ts`
4. `ROUTER_API_KEY` + `MITM_LOCAL_PORT` (डिफ़ॉल्ट `443`) के साथ `src/mitm/server.cjs` स्पॉन करें
5. PID को `<DATA_DIR>/mitm/.mitm.pid` में बनाए रखें

### Linux डायनेमिक ट्रस्ट-स्टोर पहचान — `cert/install.ts`

`getLinuxCertConfig()` प्राथमिकता सूची में क्रमशः खोजता है और पहली मौजूदा डायरेक्टरी चुनता है:

| डिस्ट्रो परिवार          | डायरेक्टरी                                  | अपडेट कमांड              |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

प्रमाणपत्र फ़ाइल नाम: `omniroute-mitm.crt`। `getCertFingerprint()` के माध्यम से फ़िंगरप्रिंट मिलान (DER का SHA-1)।

इसके अतिरिक्त, `certutil` उपलब्ध होने पर `updateNssDatabases()` प्रति-उपयोगकर्ता NSS DB में इंस्टॉल करता है: `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, सभी Firefox प्रोफ़ाइल (snap सहित), उपनाम **`OmniRoute MITM Root CA`** के अंतर्गत।

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** उन्नत PowerShell → `certutil -addstore Root`

### प्रमाणीकरण

सभी MITM एंडपॉइंट के लिए प्रबंधन प्रमाणीकरण (`requireCliToolsAuth`) आवश्यक है। sudo पासवर्ड मॉड्यूल स्कोप में कैश किया जाता है (`globalThis` में कभी नहीं) और `stopMitm()` पर साफ़ कर दिया जाता है।

## इनबाउंड हेडर सैनिटाइज़ेशन

OmniRoute अग्रेषित करने से पहले इनबाउंड क्लाइंट हेडर साफ़ करता है, ताकि Cursor से आने वाला अनुरोध Claude अपस्ट्रीम को `User-Agent: Cursor/X.Y.Z` लीक न करे। डिनायलिस्ट के लिए `src/shared/constants/upstreamHeaders.ts` देखें, जिसे Zod स्कीमा और यूनिट परीक्षणों के साथ पूरी तरह समकालिक रखा जाता है।

## प्रदाता द्वारा फ़िंगरप्रिंट बदलने पर उन्हें अपडेट करना

1. `mitmproxy` से आधिकारिक CLI ट्रैफ़िक कैप्चर करें (TLS इंटरसेप्शन + डंप)
2. JA3/JA4 और हेडर का सटीक क्रम निकालें
3. संबंधित `CLI_FINGERPRINTS[...]` प्रविष्टि अपडेट करें
4. `.env.example` में मेल खाने वाले `*_USER_AGENT` डिफ़ॉल्ट को अपडेट करें
5. यदि TLS हैंडशेक स्वयं बदल गया है, तो संबंधित प्रदाता रैपर या wreq-js के `browser:` विकल्प को अपडेट करें
6. प्रदाता-विशिष्ट TLS परीक्षण चलाएँ और लाइव प्रदाता पर मैन्युअल कैनरी परीक्षण करें
7. पैच रिलीज़ में जारी करें; `CHANGELOG.md` में दस्तावेज़ित करें
