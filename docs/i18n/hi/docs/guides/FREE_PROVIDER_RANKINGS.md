> **संक्षेप में**: OmniRoute अपने **मुफ़्त** प्रदाताओं को मॉडल की गुणवत्ता के आधार पर **Arena AI
> (LMArena-शैली) ELO स्कोर** का उपयोग करके रैंक करता है। यह देखने के लिए कि कौन-से मुफ़्त प्रदाता आपके कार्य के लिए
> सबसे शक्तिशाली मॉडल उपलब्ध कराते हैं, डैशबोर्ड में **मुफ़्त प्रदाता रैंकिंग** पृष्ठ खोलें —
> समग्र रूप से, या श्रेणी (कोडिंग, समीक्षा, दस्तावेज़ीकरण, डीबगिंग) के अनुसार फ़िल्टर करके।

---

## यह क्या है

OmniRoute 329 प्रदाताओं को पंजीकृत करता है, जिनमें **मुफ़्त/प्रमाणीकरण-रहित** के रूप में चिह्नित 155 कैटलॉग प्रविष्टियाँ
शामिल हैं (प्रमाणीकरण-रहित,
मुफ़्त-टियर OAuth, या मुफ़्त-टियर API कुंजी — देखें
[मुफ़्त टियर गाइड](../getting-started/FREE-TIERS-GUIDE.md) और संपूर्ण
[मुफ़्त टियर निर्देशिका](../reference/FREE_TIERS.md))। समस्या यह है कि मुफ़्त प्रदाताओं की
मॉडल गुणवत्ता में बहुत अधिक अंतर होता है। फ़्रंटियर मॉडल उपलब्ध कराने वाला प्रमाणीकरण-रहित प्रदाता,
किसी छोटे पुराने मॉडल को उपलब्ध कराने वाले प्रदाता से कहीं अधिक उपयोगी होता है।

**मुफ़्त प्रदाता रैंकिंग** इस प्रश्न का उत्तर देती है: "**कौन-सा मुफ़्त प्रदाता मुझे सर्वोत्तम मॉडल देता है?**"। इसके लिए
यह प्रत्येक मुफ़्त प्रदाता के कैटलॉग को **Arena AI लीडरबोर्ड** से प्राप्त
**क्राउड-सोर्स किए गए गुणवत्ता स्कोर** (मानवीय प्राथमिकता वाला ELO, वही अवधारणा जो LMArena
चैटबॉट एरीना के पीछे है) के साथ जोड़ती है। इसके बाद प्रदाताओं को उनके **सर्वोत्तम मुफ़्त मॉडल** की क्षमता के आधार पर रैंक किया जाता है।

रैंकिंग की गणना तीन वास्तविक स्रोतों से की जाती है:

1. मुफ़्त प्रदाताओं की सूचियाँ — `NOAUTH_PROVIDERS`, साथ ही `hasFree` से चिह्नित
   `OAUTH_PROVIDERS` / `APIKEY_PROVIDERS` प्रविष्टियाँ
   (`src/shared/constants/providers.ts`)।
2. प्रदाता रजिस्ट्री से प्रत्येक प्रदाता का मॉडल कैटलॉग
   (`open-sse/config/providerRegistry.ts`)।
3. Arena ELO सिंक इंजन (`src/lib/arenaEloSync.ts`) द्वारा `model_intelligence` DB तालिका में
   संग्रहीत ELO-व्युत्पन्न कार्य-उपयुक्तता स्कोर।

जोड़ने का तर्क `src/lib/freeProviderRankings.ts` में मौजूद है।

## एक्सेस करने का तरीका

### डैशबोर्ड पृष्ठ

डैशबोर्ड खोलें और **लागत → मुफ़्त प्रदाता रैंकिंग** पर जाएँ, या सीधे यहाँ नेविगेट करें:

```
/dashboard/free-provider-rankings
```

यह पृष्ठ (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) निम्नलिखित दिखाता है:

- सर्वोच्च रैंक वाले मुफ़्त प्रदाताओं का **शीर्ष-3 पोडियम** (🥇 🥈 🥉)।
- इन कॉलम वाली एक पूर्ण **रैंकिंग तालिका**: **रैंक**, **प्रदाता**, **शीर्ष मॉडल**,
  **स्कोर**, **औसत स्कोर**, **मॉडल**, **प्रकार**।
- **श्रेणी फ़िल्टर बटन**: _सभी श्रेणियाँ_, _डिफ़ॉल्ट_, _कोडिंग_, _समीक्षा_,
  _दस्तावेज़ीकरण_, _डीबगिंग_।

प्रत्येक प्रदाता का **प्रकार** बैज बताता है कि वह किस प्रकार मुफ़्त है:

| बैज      | अर्थ                                            |
| -------- | ----------------------------------------------- |
| `NOAUTH` | हमेशा मुफ़्त, किसी क्रेडेंशियल की आवश्यकता नहीं |
| `OAUTH`  | मुफ़्त टियर (`hasFree`) वाला OAuth प्रदाता      |
| `APIKEY` | मुफ़्त टियर (`hasFree`) वाला API-कुंजी प्रदाता  |

स्कोर को अपरिष्कृत संख्याओं के बजाय मानव-पठनीय लेबल (जैसे _विशिष्ट_, _उत्कृष्ट_, _बहुत अच्छा_,
_अच्छा_, _औसत_) के रूप में दिखाया जाता है, क्योंकि अंतर्निहित मान सापेक्ष
रैंकिंग गुणवत्ता है, प्रतिशत नहीं।

### API एंडपॉइंट

यह पृष्ठ एक सार्वजनिक रीड एंडपॉइंट
(`src/app/api/free-provider-rankings/route.ts`) द्वारा समर्थित है:

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

क्वेरी पैरामीटर (Zod से सत्यापित):

| पैरामीटर   | प्रकार | डिफ़ॉल्ट   | टिप्पणियाँ                                                                                                  |
| ---------- | ------ | ---------- | ----------------------------------------------------------------------------------------------------------- |
| `category` | string | (कोई नहीं) | `default`, `coding`, `review`, `documentation`, `debugging` में से एक। संयुक्त रैंकिंग के लिए इसे छोड़ दें। |
| `limit`    | number | `50`       | `1–100` की सीमा में सीमित।                                                                                  |

प्रतिक्रिया की संरचना:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` मूल Arena ELO मान है; `score` सामान्यीकृत कार्य-उपयुक्तता मान है
(नीचे देखें)। जिन प्रदाताओं के पास कोई स्कोर किया गया मॉडल नहीं है, उन्हें प्रतिक्रिया से हटा दिया जाता है।

## स्कोर कैसे काम करते हैं

### स्रोत: Arena AI लीडरबोर्ड

Arena ELO सिंक इंजन (`src/lib/arenaEloSync.ts`), Arena AI लीडरबोर्ड API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) से दो लीडरबोर्ड — `text`
और `code` — प्राप्त करता है। प्रत्येक लीडरबोर्ड प्रविष्टि में मॉडल का नाम, विक्रेता, ELO
`score`, कॉन्फ़िडेंस इंटरवल और वोटों की संख्या होती है।

लीडरबोर्ड श्रेणियाँ OmniRoute कार्य श्रेणियों से इस प्रकार मैप होती हैं:

| Arena लीडरबोर्ड | OmniRoute कार्य श्रेणियाँ                         |
| --------------- | ------------------------------------------------- |
| `text`          | `default`, `review`, `documentation`, `debugging` |
| `code`          | `coding`                                          |

### सामान्यीकरण (कार्य-उपयुक्तता स्कोर)

रॉ ELO स्कोर को प्रत्येक लीडरबोर्ड के अनुसार सामान्यीकृत करके **`[0.4, 0.98]` में कार्य-उपयुक्तता मान** बनाया जाता है:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

स्कोर कभी भी `0` या `1` तक नहीं पहुँचता, जिससे उपयोगकर्ता ओवरराइड के लिए गुंजाइश बनी रहती है। यह वही
`score` फ़ील्ड है जिसे आप API प्रतिक्रिया में देखते हैं और जिसका लेबल डैशबोर्ड पर प्रदर्शित होता है।

### विश्वसनीयता

प्रत्येक प्रविष्टि को Arena के वोटों की संख्या के आधार पर विश्वसनीयता स्तर मिलता है:

| विश्वसनीयता | वोट     |
| ----------- | ------- |
| `high`      | ≥ 5,000 |
| `medium`    | ≥ 1,000 |
| `low`       | < 1,000 |

### भंडारण और नवीनता

सामान्यीकृत प्रविष्टियाँ `source = "arena_elo"` के साथ `model_intelligence` DB तालिका में
लिखी जाती हैं (`src/lib/db/modelIntelligence.ts`)। प्रविष्टियाँ **7 दिनों के बाद
समाप्त हो जाती हैं**, इसलिए सिंक करना बंद करने वाला प्रदाता अंततः पुराने डेटा को प्रस्तुत करने के बजाय
सूची से हट जाता है।

सिंक **डिफ़ॉल्ट रूप से चालू** रहता है:

- यह सर्वर स्टार्टअप पर एक बार और फिर आवधिक टाइमर पर चलता है
  (`src/lib/arenaEloSync.ts`, जिसे `src/instrumentation-node.ts` से जोड़ा गया है)।
- यह **नॉन-ब्लॉकिंग है और कभी घातक नहीं होता** — यदि अपस्ट्रीम फ़ेच विफल हो जाता है, तो OmniRoute
  चलता रहता है और रैंकिंग केवल पिछला अच्छा डेटा (या खाली स्थिति) दिखाती है।

इसे दो एनवायरनमेंट वेरिएबल नियंत्रित करते हैं (इनका दस्तावेज़ीकरण
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md) में किया गया है):

| वेरिएबल                   | डिफ़ॉल्ट      | उद्देश्य                                                   |
| ------------------------- | ------------- | ---------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | आउटबाउंड सिंक से बाहर रहने के लिए इसे `false` पर सेट करें। |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | सिंक अंतराल, सेकंड में।                                    |

### मैन्युअल सिंक / स्थिति / साफ़ करना

ऑपरेटरों के लिए, एक प्रमाणित प्रबंधन एंडपॉइंट मैन्युअल नियंत्रण उपलब्ध कराता है
(`src/app/api/intelligence/sync/route.ts` — प्रबंधन प्रमाणीकरण आवश्यक है):

```
GET    /api/intelligence/sync          # वर्तमान सिंक स्थिति (सक्षम, अंतिम सिंक, अगला सिंक, अंतराल मिलीसेकंड)
POST   /api/intelligence/sync          # मैन्युअल सिंक ट्रिगर करें; बिना लिखे पूर्वावलोकन के लिए बॉडी: { "dryRun": true }
DELETE /api/intelligence/sync          # सभी सिंक की गई arena_elo इंटेलिजेंस प्रविष्टियाँ साफ़ करें
```

यदि रैंकिंग पृष्ठ खाली है, तो मैन्युअल `POST /api/intelligence/sync` (या केवल
सर्वर को पुनः प्रारंभ करना) इसे फिर से भर देता है।

### मॉडल का लीडरबोर्ड से मिलान

रजिस्ट्री मॉडल ID और Arena मॉडल नाम हमेशा पूरी तरह मेल नहीं खाते। रैंकिंग
लचीले मिलान का उपयोग करती है (`src/lib/freeProviderRankings.ts` में `findMatchingIntelligence`):

1. सामान्यीकृत मॉडल ID पर सटीक मिलान।
2. अंत में आने वाले वर्ज़न सफ़िक्स को हटाने के बाद मिलान (उदाहरण के लिए `kimi-k2.6` → `kimi-k2`)।
3. प्रीफ़िक्स मिलान (लीडरबोर्ड मॉडल नाम, रजिस्ट्री ID का प्रीफ़िक्स हो)।

सिंक की ओर, ज्ञात विक्रेता प्रीफ़िक्स (`anthropic/`, `openai/`, `google/`, …)
हटा दिए जाते हैं और एक छोटा एलियास मैप कैनॉनिकल नामों को उन वैरिएंट में विस्तृत करता है जिनका OmniRoute
आंतरिक रूप से उपयोग करता है, ताकि मॉडल किसी भी नाम के अंतर्गत खोजे जा सकें।

### किसी प्रदाता को कैसे रैंक किया जाता है

प्रत्येक मुफ़्त प्रदाता के लिए, इंजन उसके कैटलॉग में मौजूद हर मॉडल को स्कोर करता है, फिर:

- **शीर्ष मॉडल** = प्रदाता का सर्वाधिक स्कोर वाला मॉडल।
- **औसत स्कोर** = उस प्रदाता के सभी स्कोर किए गए मॉडलों का औसत स्कोर।
- **मॉडल** = प्रदाता के कितने मॉडलों के पास Arena स्कोर था।

प्रदाताओं को पहले **शीर्ष-मॉडल स्कोर** और फिर औसत स्कोर के आधार पर क्रमबद्ध किया जाता है। इससे
कम से कम एक मज़बूत मुफ़्त मॉडल उपलब्ध कराने वाले प्रदाता को पुरस्कृत किया जाता है।

## मुफ़्त प्रदाताओं को चुनने के लिए इसका उपयोग

1. **सही श्रेणी चुनें।** एजेंट-आधारित/कोड कार्यभार के लिए **Coding** फ़िल्टर का उपयोग करें, या
   सामान्य चैट के लिए इसे **All Categories** / **Default** पर छोड़ दें। एक ही प्रदाता की
   रैंक अलग-अलग श्रेणियों में भिन्न हो सकती है, क्योंकि प्रत्येक लीडरबोर्ड के अनुसार उसका शीर्ष मॉडल अलग होता है।
2. **एकल सेटअप के लिए पोडियम को प्राथमिकता दें।** यदि आप केवल एक या दो मुफ़्त
   प्रदाताओं को कनेक्ट करना चाहते हैं, तो अपनी श्रेणी में सर्वोच्च रैंक वाले प्रदाताओं से शुरुआत करें।
3. **Type बैज जाँचें।** `NOAUTH` प्रदाताओं को कनेक्ट करना सबसे तेज़ है (किसी
   क्रेडेंशियल की आवश्यकता नहीं)। `OAUTH` / `APIKEY` मुफ़्त टियर के लिए तुरंत साइन-अप करना पड़ता है, लेकिन वे अक्सर
   अधिक शक्तिशाली मॉडल उपलब्ध कराते हैं। कनेक्शन के चरणों के लिए
   [मुफ़्त टियर मार्गदर्शिका](../getting-started/FREE-TIERS-GUIDE.md) देखें।
4. **कई प्रदाताओं को कनेक्ट करें और Auto-Combo को निर्णय लेने दें।** इस पृष्ठ को संचालित करने वाला वही Arena ELO डेटा
   Auto-Combo स्कोरिंग इंजन के **कार्य-उपयुक्तता कारक** को भी डेटा प्रदान करता है
   (`open-sse/services/autoCombo/taskFitness.ts`, समाधान क्रम
   `user_override → arena_elo → models_dev_tier → static table`)। इसलिए, शीर्ष मुफ़्त प्रदाताओं को कनेक्ट करने के बाद,
   `model: "auto"` (जैसे `auto/coding`) के साथ रूटिंग प्रत्येक अनुरोध के लिए
   उच्च-गुणवत्ता वाले मुफ़्त मॉडलों को स्वचालित रूप से प्राथमिकता देगी। संपूर्ण 16-कारक स्कोरिंग के लिए
   [Auto-Combo](../routing/AUTO-COMBO.md) देखें।
