**Claude Code** CLI (`claude`) को OmniRoute — स्थानीय या रिमोट VPS — की ओर इंगित करें,
Codex सेटअप की तरह ही प्रति-मॉडल प्रोफ़ाइलों के साथ।

---

## त्वरित शुरुआत

```bash
# स्थानीय OmniRoute के साथ Claude Code लॉन्च करें (सक्रिय कॉन्टेक्स्ट का स्वतः पता लगाता है)
omniroute launch

# रिमोट OmniRoute के साथ (`omniroute connect <host>` के बाद यह स्वचालित होता है)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# प्रति-मॉडल प्रोफ़ाइलें जनरेट करें, फिर उनमें से एक लॉन्च करें
omniroute setup-claude            # ~/.claude/profiles/<name>/settings.json में लिखता है
omniroute launch --profile glm52  # OmniRoute के माध्यम से glm/glm-5.2 का उपयोग करता Claude Code
```

## Claude Code किसी गेटवे से कैसे कनेक्ट होता है

Claude Code **Anthropic Messages API** से संचार करता है और environment variables के माध्यम से
एक कस्टम endpoint की ओर इंगित किया जाता है (इसमें कोई `--base-url` फ़्लैग नहीं है):

| वेरिएबल                                      | उद्देश्य                                                                                                         |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `ANTHROPIC_BASE_URL`                         | गेटवे का रूट URL (Claude Code `/v1/messages` जोड़ता है)। **कोई `/v1` suffix नहीं।**                              |
| `ANTHROPIC_AUTH_TOKEN`                       | `Authorization: Bearer …` के रूप में भेजा जाता है — अपने OmniRoute access token / API key का उपयोग करें          |
| `ANTHROPIC_API_KEY`                          | विकल्प: `x-api-key` के रूप में भेजा जाता है। यदि दोनों सेट हों, तो `ANTHROPIC_AUTH_TOKEN` को प्राथमिकता मिलती है |
| `ANTHROPIC_MODEL`                            | किसी विशिष्ट मॉडल को बाध्य करें (`/model` picker के डिफ़ॉल्ट को ओवरराइड करता है)                                 |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` → मूल `/model` picker `/v1/models` से `claude*`/`anthropic*` मॉडल सूचीबद्ध करता है                           |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`              | प्रति response output tokens की सीमा तय करें (जैसे `65536`)                                                      |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`            | स्वचालित compaction के लिए token threshold                                                                       |

> Env vars को **स्टार्टअप पर केवल एक बार** पढ़ा जाता है — उन्हें बदलने के बाद Claude Code पुनः शुरू करें।

`omniroute launch` आपके लिए इन सभी को सेट करता है: यह सक्रिय context से base URL + token
resolve करता है (इसलिए `omniroute connect <vps>` और फिर `omniroute launch`
सीधे काम करता है), server का health-check करता है और `claude` को exec करता है।

## Discovery aliases — गैर-Claude मॉडलों को `/model` picker में दिखाएँ

Claude Code का gateway model discovery केवल उन IDs को सूचीबद्ध करता है जो `claude`
या `anthropic` से शुरू होती हैं, इसलिए `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` के साथ मूल
`/model` picker सामान्यतः OmniRoute के **केवल** Claude/Anthropic मॉडल दिखाता है —
`kimi/kimi-k2.6` या `glm/glm-5.2` कभी दिखाई नहीं देता, भले ही उसकी routing ठीक से होती हो।

OmniRoute किसी भी सक्षम मॉडल (और combo) को `claude/…` ID के अंतर्गत mirror कर सकता है, ताकि वह
इस filter से गुज़रकर picker में दिखाई दे:

```
kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<combo "custo-otimizado"> →  claude/combo/custo-otimizado
```

जब आप Claude Code में इनमें से किसी एक को चुनते हैं, तो OmniRoute routing से पहले `claude/` wrapper
हटाकर वास्तविक ID वापस प्राप्त कर लेता है — वास्तविक `claude/<real-claude-model>` ID
(वास्तविक Claude OAuth provider) को हमेशा अपरिवर्तित रखा जाता है।

**यह डिफ़ॉल्ट रूप से बंद है** और एक तीन-स्तरीय gate द्वारा नियंत्रित होता है (सबसे विशिष्ट
सेटिंग प्रभावी होती है), ताकि सामान्य OmniRoute उन clients के लिए अपने catalog को दोगुना न करे जो
Claude Code का उपयोग नहीं करते:

| स्तर     | स्थान                                                                          |
| -------- | ------------------------------------------------------------------------------ |
| मॉडल     | Provider detail page → प्रति-मॉडल "Expose in Claude Code" toggle               |
| Provider | Provider detail page → provider-level toggle (इसके सभी मॉडलों पर लागू)         |
| Global   | Settings → Feature Flags → `EXPOSE_CC_DISCOVERY_ALIASES` (डिफ़ॉल्ट रूप से बंद) |

`EXPOSE_CC_DISCOVERY_ALIASES` environment variable global स्तर को बलपूर्वक चालू करता है
और dashboard override पर प्राथमिकता लेता है (ऐसा होने पर Feature Flags screen
"active via environment variable" नोट दिखाती है)। इसके बाद प्रति-provider और
प्रति-मॉडल toggles इसे और परिष्कृत करते हैं — उदाहरण के लिए, global बंद + Kimi provider चालू होने पर
केवल Kimi के मॉडल दिखाई देते हैं।

> ⚠️ **गैर-Claude मॉडलों पर window mismatch।** Claude Code किसी भी ऐसी ID के लिए 200K context
> window मानता है जिसे वह नहीं पहचानता (वह `/v1/models` से वास्तविक window नहीं पढ़ सकता)।
> अधिक बड़ी window वाले मॉडल (जैसे Kimi K2 की 256K) के लिए,
> `CLAUDE_CODE_AUTO_COMPACT_WINDOW` को मॉडल की वास्तविक window से कम मान पर सेट करें, ताकि
> auto-compaction समय से पहले शुरू न हो। ऊपर जनरेट की गई प्रोफ़ाइलें पहले से ही
> प्रति मॉडल ऐसा करती हैं।

## डैशबोर्ड पर ऑनबोर्डिंग ब्लॉक

Claude टूल कार्ड (**Dashboard → CLI Code**) इस इंस्टेंस के लिए सटीक `settings.json` फ़्रैगमेंट को
डिस्कवरी-अलायस जानकारी बटन के पास, कॉपी बटन के साथ रेंडर करता है:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}
```

बेस URL वही है जिसे कार्ड ने रिज़ॉल्व किया है (आपके द्वारा टाइप किया गया कस्टम ओवरराइड भी शामिल है), और वह पहले से
नॉर्मलाइज़ किया हुआ है — न कोई `/v1` सफ़िक्स, न अंत में स्लैश। **कुंजी कभी रेंडर नहीं की जाती**: ब्लॉक में एक
प्लेसहोल्डर होता है, इसलिए स्क्रीनशॉट या पेस्ट किए गए स्निपेट से कुंजी लीक नहीं हो सकती। इसके स्थान पर अपनी कुंजी पेस्ट करें।

ऐसे किसी भी मॉडल के लिए, जिसकी वास्तविक कॉन्टेक्स्ट विंडो 200K नहीं है, उसी `env` ब्लॉक के अंतर्गत
`CLAUDE_CODE_AUTO_COMPACT_WINDOW` जोड़ें — Claude Code हर उस id के लिए 200K मान लेता है जिसे वह नहीं पहचानता,
इसलिए अन्यथा ऑटो-कम्पैक्शन गलत बिंदु पर शुरू हो जाता है (पिछले अनुभाग की चेतावनी देखें)।
स्निपेट बिल्डर भी इस मान को स्वीकार करता है, इसलिए लक्ष्य मॉडल की विंडो जानने वाला कॉलर
इसे सीधे उत्सर्जित कर सकता है।

स्रोत: `src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet` (शुद्ध
बिल्डर, यूनिट-परीक्षित), जिसे `ClaudeGatewayOnboardingBlock` द्वारा रेंडर किया जाता है।

## प्रोफ़ाइल (`CLAUDE_CONFIG_DIR`)

Claude Code में **कोई नेटिव प्रोफ़ाइल फ़ाइलें नहीं हैं** (Codex की `~/.codex/<name>.config.toml` के विपरीत)।
प्रचलित तंत्र `CLAUDE_CONFIG_DIR` है — प्रत्येक प्रोफ़ाइल के लिए एक अलग कॉन्फ़िग डायरेक्टरी,
जिसमें प्रत्येक की अपनी `settings.json`, क्रेडेंशियल्स, हिस्ट्री और कैश होती है।

`omniroute setup-claude` लाइव `/v1/models` कैटलॉग प्राप्त करता है और
`~/.claude/profiles/<name>/settings.json` में प्रत्येक मॉडल के लिए एक प्रोफ़ाइल लिखता है,
जिसमें **`setup-codex` वाले समान नामों** (`glm52`, `kimi-k27`, `deepseek-pro`, …) का पुनः उपयोग किया जाता है:

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}
```

> **ऑथ टोकन कभी भी प्रोफ़ाइल में नहीं लिखा जाता।** इसे
> `omniroute launch --profile <name>` के साथ लॉन्च करें (यह सक्रिय कॉन्टेक्स्ट से `ANTHROPIC_AUTH_TOKEN`
> इंजेक्ट करता है), या स्वयं `ANTHROPIC_AUTH_TOKEN` एक्सपोर्ट करें और
> `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude` चलाएँ।

**मॉडल डिस्कवरी के बाद ऑटो-सिंक (ऑप्ट-इन)।** जब भी कोई प्रोवाइडर मॉडल
सिंक लाइव कैटलॉग को बदलता है, OmniRoute इन्हीं `~/.claude/profiles/<name>/settings.json`
फ़ाइलों को अपने आप फिर से जनरेट कर सकता है — ताकि नए/बदले हुए नाम वाले मॉडलों को कमांड दोबारा चलाए बिना
प्रोफ़ाइल मिल जाएँ। यह **डिफ़ॉल्ट रूप से बंद** होता है: इसे **CLI Code dashboard** से टॉगल करें ("CLI profile
auto-sync" → Claude Code), या `OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true` सेट करें (यह
`CLI_ALLOW_CONFIG_WRITES` का भी पालन करता है, जो डिफ़ॉल्ट रूप से चालू है)। सक्षम होने पर यह केवल प्रोफ़ाइल फ़ाइलें लिखता है; यह कभी भी
आपके सक्रिय/डिफ़ॉल्ट Claude कॉन्फ़िग, ऑथ या `~/.claude/settings.json` को नहीं बदलता।

### प्रोफ़ाइल जनरेट करना + उपयोग करना

```bash
# स्थानीय OmniRoute
omniroute setup-claude

# रिमोट VPS (हर प्रोफ़ाइल में VPS URL समाहित करता है)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# केवल कुछ प्रोवाइडर
omniroute setup-claude --only glm,kimi

# लिखे बिना पूर्वावलोकन
omniroute setup-claude --dry-run

# कोई प्रोफ़ाइल लॉन्च करें
omniroute launch --profile kimi-k27
```

## मॉडल स्तर (वैकल्पिक)

Claude Code क्षमताओं के अनुसार अलग-अलग स्तरों पर रूट करता है। यदि आप प्रत्येक स्तर के लिए अलग प्रदाता चाहते हैं, तो env /
सेटिंग्स के माध्यम से प्रत्येक स्तर को एक OmniRoute मॉडल से मैप करें:

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm/glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="kmc/kimi-k2.6"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="glm/glm-4.7-flash"
```

अन्यथा हर चीज़ के लिए एक ही `ANTHROPIC_MODEL` (जिसे प्रोफ़ाइल सेट करती हैं) का उपयोग किया जाता है।

---

## रिमोट मोड

एक बार `omniroute connect <host>` चलाने के बाद ([रिमोट मोड](./REMOTE-MODE.md) देखें), `omniroute launch` और `omniroute setup-claude`
स्वचालित रूप से उस रिमोट सर्वर को लक्षित करते हैं और उसके सीमित-दायरे वाले एक्सेस टोकन का उपयोग करते हैं — किसी
अतिरिक्त फ़्लैग की आवश्यकता नहीं होती। प्रत्येक आमंत्रण के लिए `--remote` / `--api-key` से इसे ओवरराइड करें।

## समस्या निवारण

**Claude Code गेटवे की अनदेखी करता है** — पुष्टि करें कि `ANTHROPIC_BASE_URL` में **`/v1`
नहीं है** और `claude` को पुनः आरंभ करें (env को स्टार्टअप के समय केवल एक बार पढ़ा जाता है)। `omniroute launch`
आपके लिए इसे संभालता है।

**`/model` चयनकर्ता खाली है / गेटवे मॉडल मौजूद नहीं हैं** — इसके लिए Claude Code
v2.1.219+ और `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` आवश्यक हैं। चयनकर्ता में केवल `claude*` /
`anthropic*` मॉडल ID दिखाई देती हैं; किसी अन्य मॉडल को
`ANTHROPIC_MODEL=<id>` से बाध्य करें (प्रोफ़ाइल यही करती हैं)।

**`400 Ambiguous model 'claude-…'`** — Claude Code हमेशा **उपसर्ग-रहित**
मॉडल ID भेजता है (उदा. `claude-opus-4-8`), इसलिए जब Claude Code (`cc/…`) और
Claude (`claude/…`) दोनों प्रदाता कनेक्ट हों, तो मूल ID दो रूट से मेल खाती है और
OmniRoute अनुमान लगाने से मना कर देता है। इसे किसी भी तरह ठीक करें: उपसर्ग वाली ID को
`ANTHROPIC_MODEL=cc/claude-opus-4-8` से पिन करें, या **उपसर्ग-रहित Claude मॉडलों के लिए Claude Code को प्राथमिकता दें**
सक्षम करें — Claude प्रदाता पृष्ठ पर मौजूद टॉगल, या
`OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true` (डिफ़ॉल्ट रूप से बंद;
[परिवेश](../reference/ENVIRONMENT.md) देखें) — जो मूल `claude-*`
ID को इसके बजाय Claude Code पर रूट करता है। स्पष्ट प्रदाता उपसर्गों को हमेशा प्राथमिकता मिलती है।

**प्रमाणीकरण त्रुटियाँ** — प्रोफ़ाइल में कोई टोकन नहीं होता। `omniroute launch --profile`
का उपयोग करें (यह उसे इंजेक्ट करता है) या `ANTHROPIC_AUTH_TOKEN` एक्सपोर्ट करें।

**प्रोफ़ाइल अलग-अलग नहीं रहतीं** — प्रत्येक प्रोफ़ाइल एक अलग `CLAUDE_CONFIG_DIR` है;
सत्यापित करें कि सत्र के भीतर `echo $CLAUDE_CONFIG_DIR`
`~/.claude/profiles/<name>` की ओर इंगित करता है।
