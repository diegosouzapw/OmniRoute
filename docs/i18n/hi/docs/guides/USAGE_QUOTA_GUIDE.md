> **संक्षेप में**: OmniRoute हर अनुरोध के टोकन उपयोग को ट्रैक करता है, लागत की गणना करता है, प्रत्येक API कुंजी के लिए कोटा लागू करता है और डैशबोर्ड में विश्लेषण प्रस्तुत करता है। यह मार्गदर्शिका बताती है कि यह सब कैसे काम करता है।

**स्रोत:**

- `open-sse/services/usage.ts` (~70KB) — मुख्य उपयोग ट्रैकिंग
- `src/lib/usageAnalytics.ts` (~10KB) — डैशबोर्ड के लिए एकत्रीकरण
- `src/lib/db/quotaSnapshots.ts` — ऐतिहासिक कोटा डेटा
- `src/lib/db/usage*.ts` — उपयोग से संबंधित कई DB मॉड्यूल

## अवलोकन

OmniRoute से होकर जाने वाला प्रत्येक अनुरोध एक **उपयोग रिकॉर्ड** उत्पन्न करता है, जिसमें ये विवरण दर्ज होते हैं:

- **पहचान**: कौन-सी API कुंजी, प्रदाता, मॉडल और कॉम्बो
- **टोकन**: प्रॉम्प्ट टोकन, पूर्णता टोकन, कैश किए गए टोकन और कुल टोकन
- **लागत**: USD राशि (मूल्य-निर्धारण डेटा से परिकलित)
- **समय**: विलंबता, आरंभ/समाप्ति टाइमस्टैम्प
- **स्थिति**: सफल, त्रुटि, दर-सीमित आदि

इन रिकॉर्ड्स को एकत्रित करके **विश्लेषण** तैयार किया जाता है, **कोटा स्नैपशॉट** के रूप में स्थायी रूप से संग्रहीत किया जाता है और **प्रति-कुंजी बजट सीमाएँ** लागू करने के लिए उपयोग किया जाता है।

```
अनुरोध ──▶ chatCore ──▶ usage.record() ──▶ SQLite
                                  │
                          ┌───────┼───────┐
                          ▼       ▼       ▼
                     विश्लेषण   कोटा    बिलिंग
                    (डैशबोर्ड) (प्रवर्तन) (निर्यात)
```

## क्या रिकॉर्ड किया जाता है

`usage.ts` सेवा प्रत्येक अनुरोध के लिए एक **उपयोग इवेंट** दर्ज करती है:

| फ़ील्ड             | प्रकार  | स्रोत                                                      |
| ------------------ | ------- | ---------------------------------------------------------- |
| `id`               | string  | रिकॉर्ड करते समय जनरेट किया गया UUID                       |
| `apiKeyId`         | string  | अनुरोध शुरू करने वाली API कुंजी                            |
| `provider`         | string  | प्रदाता ID (openai, anthropic आदि)                         |
| `model`            | string  | मॉडल ID (gpt-5, claude-opus-4-6 आदि)                       |
| `comboId`          | string? | यदि कॉम्बो के माध्यम से रूट किया गया हो, तो कॉम्बो ID      |
| `promptTokens`     | number  | अपस्ट्रीम प्रतिक्रिया से                                   |
| `completionTokens` | number  | अपस्ट्रीम प्रतिक्रिया से                                   |
| `cachedTokens`     | number  | कैश हिट टोकन (Anthropic प्रॉम्प्ट कैशिंग आदि)              |
| `totalTokens`      | number  | प्रॉम्प्ट + पूर्णता                                        |
| `costUsd`          | number  | मूल्य-निर्धारण डेटा से परिकलित                             |
| `latencyMs`        | number  | शुरू से अंत तक अनुरोध की अवधि                              |
| `status`           | enum    | `success`, `error`, `rate_limited`, `timeout`, `cancelled` |
| `errorClass`       | string? | यदि स्थिति != success हो, तो त्रुटि वर्ग                   |
| `timestamp`        | string  | ISO 8601 UTC                                               |
| `metadata`         | object  | प्लगइन द्वारा प्रविष्ट किया गया कस्टम डेटा                 |

### टोकन कहाँ से आते हैं

टोकन, **प्रतिक्रिया हैंडलर** में अपस्ट्रीम प्रदाता की प्रतिक्रिया से निकाले जाते हैं:

```ts
// open-sse/handlers/chatCore.ts से
const response = await providerExecutor.execute(provider, request);
const usage = response.usage || {
  prompt_tokens: 0,
  completion_tokens: 0,
  cached_tokens: 0,
};
```

जो प्रदाता उपयोग डेटा नहीं लौटाते हैं (कुछ वेब-कुकी प्रदाता), उनके लिए OmniRoute `~4 chars per token` अनुमानी नियम का उपयोग करके टोकन का **अनुमान** लगाता है (`open-sse/services/autoCombo/pipelineRouter.ts` देखें)।

### कैश किए गए टोकन

OmniRoute `cached_tokens` को `prompt_tokens` से अलग ट्रैक करता है, क्योंकि:

- Anthropic प्रॉम्प्ट कैशिंग, कैश किए गए टोकन के लिए कम दर वसूलती है (सामान्य दर का 10%)
- कुछ प्रदाता `cache_read_input_tokens` लौटाते हैं, जिनकी कीमत अलग तरीके से निर्धारित की जानी चाहिए
- विश्लेषण **कैश हिट दर** = `cached_tokens / prompt_tokens` दिखा सकता है

## लागत की गणना

लागत की गणना LiteLLM से सिंक किए गए **मूल्य-निर्धारण डेटा** (`src/lib/pricingSync.ts`) से की जाती है:

| मॉडल              | इनपुट $/1M | आउटपुट $/1M | कैश किया गया $/1M |
| ----------------- | ---------- | ----------- | ----------------- |
| gpt-5             | $2.50      | $10.00      | —                 |
| claude-opus-4-6   | $15.00     | $75.00      | $1.50             |
| claude-sonnet-4-5 | $3.00      | $15.00      | $0.30             |
| gemini-2.5-pro    | $1.25      | $10.00      | —                 |

लागत का सूत्र (`src/lib/usage/costCalculator.ts`):

```ts
cost =
  (prompt_tokens - cached_tokens) * input_price +
  cached_tokens * cached_price +
  completion_tokens * output_price;
```

> **कैश किए गए टोकन को प्रॉम्प्ट से क्यों घटाया जाता है?** कैश किए गए हिस्से का मूल्य अलग से निर्धारित होता है; पूरे प्रॉम्प्ट पर इनपुट मूल्य लगाने से लागत की अतिरिक्त गणना हो जाएगी।

### मूल्य-निर्धारण सिंक

मूल्य-निर्धारण डेटा `/api/pricing/sync` एंडपॉइंट के माध्यम से LiteLLM से स्वतः सिंक किया जाता है (इसे अंतर्निहित cron कार्य ट्रिगर करता है, न कि उपयोगकर्ता के लिए उपलब्ध कोई env var):

```bash
# मैन्युअल ट्रिगर
curl -X POST http://localhost:20128/api/pricing/sync
```

जिन मॉडलों के लिए मूल्य-निर्धारण डेटा उपलब्ध नहीं है, उनके लिए OmniRoute आंतरिक औसत दरों (LiteLLM के मूल्य-निर्धारण डेटा से प्राप्त) का उपयोग करके **लागत का अनुमान** लगाता है।

## दिनांक सीमा का एकत्रीकरण

`usageAnalytics.ts` मॉड्यूल अपरिष्कृत उपयोग डेटा से डैशबोर्ड विजेट की गणना करता है। यह 7 समय सीमाओं का समर्थन करता है:

| सीमा     | अवधि                              | उपयोग का उदाहरण                       |
| -------- | --------------------------------- | ------------------------------------- |
| `1d`     | पिछले 24 घंटे                     | प्रति घंटे लागत में उछाल का पता लगाना |
| `7d`     | पिछले 7 दिन                       | साप्ताहिक समीक्षा                     |
| `30d`    | पिछले 30 दिन                      | मासिक बिलिंग                          |
| `90d`    | पिछले 90 दिन                      | त्रैमासिक विश्लेषण                    |
| `ytd`    | चालू वर्ष की 1 जनवरी से           | वार्षिक बजट ट्रैकिंग                  |
| `all`    | संपूर्ण अवधि                      | अब तक के आँकड़े                       |
| `custom` | उपयोगकर्ता-निर्धारित आरंभ/समाप्ति | ऑडिट, तदर्थ क्वेरी                    |

### गणना किए गए डैशबोर्ड विजेट

किसी भी दिनांक सीमा के लिए, एनालिटिक्स परत निम्न की गणना करती है:

| विजेट                  | विवरण                                                     |
| ---------------------- | --------------------------------------------------------- |
| **सारांश कार्ड**       | कुल अनुरोध, कुल लागत, कुल टोकन, सफलता दर                  |
| **दैनिक रुझान चार्ट**  | प्रति दिन लागत + टोकन, मॉडल के अनुसार स्टैक किए गए        |
| **गतिविधि हीटमैप**     | दिन के घंटे × सप्ताह के दिन की ग्रिड, रंग = अनुरोध संख्या |
| **मॉडल विश्लेषण**      | मॉडल के अनुसार लागत का पाई चार्ट                          |
| **प्रोवाइडर विश्लेषण** | प्रोवाइडर के अनुसार अनुरोधों का बार चार्ट                 |
| **शीर्ष API कुंजियाँ** | लागत के अनुसार शीर्ष 10 कुंजियों की तालिका                |
| **त्रुटि विश्लेषण**    | समय के साथ त्रुटि दर, शीर्ष त्रुटि क्लास                  |

### प्रोग्रामेटिक एक्सेस

````ts
import { computeAnalytics } from "@/lib/usageAnalytics";

const analytics = await computeAnalytics(
  history,              // उपयोग इतिहास के रिकॉर्ड
  "7d",                 // समय सीमा: "1d" | "7d" | "30d" | "90d" | "ytd" | "all" | "custom"
  connectionMap,        // प्रोवाइडर कनेक्शन मैप (connectionId → खाते का नाम)
  {
    startDate: "2025-01-01",  // वैकल्पिक: "custom" सीमा के लिए
    endDate: "2025-06-01",   // वैकल्पिक: "custom" सीमा के लिए
  }
);

console.log(analytics.summary.totalCost);   // 12.34 (सेंट)
console.log(analytics.byModel[0]);           // { model, cost, requests, promptTokens, completionTokens }

## कोटा प्रवर्तन

प्रति-API-कुंजी कोटा दो स्थानों पर लागू किया जाता है:

1. **सॉफ्ट सीमा** (`quotaWarnAt`): उपयोग के सीमा से अधिक होने पर डैशबोर्ड चेतावनी
2. **हार्ड सीमा** (`quotaLimit`): सीमा से अधिक होने पर अनुरोध HTTP 429 के साथ अस्वीकार कर दिया जाता है

### कॉन्फ़िगरेशन

```ts
// प्रति API कुंजी
await updateApiKey(keyId, {
  quotaWarnAt: 5_00,    // $5.00 — चेतावनी दिखाएँ
  quotaLimit: 10_00,    // $10.00 — पूर्ण रोक
  quotaWindow: "month", // "day" | "week" | "month" | "all"
});
````

### प्रवर्तन प्रवाह

```
अनुरोध ──▶ quotaCheck()
              │
              ├── सीमा के भीतर?  ──▶ अनुमति दें
              │
              └── सीमा से अधिक?  ──▶ 429 Too Many Requests
                                   Retry-After हेडर के साथ
```

### कोटा स्नैपशॉट

`quotaSnapshots` तालिका रुझान विश्लेषण के लिए **ऐतिहासिक कोटा स्थिति** संग्रहीत करती है:

| फ़ील्ड | विवरण |
| ----------- | -------------------------------- | ------ | ------- |
| `apiKeyId` | ट्रैक की जा रही कुंजी |
| `window` | "day" | "week" | "month" |
| `used` | इस विंडो में उपयोग की गई लागत (सेंट) |
| `limit` | सीमा (सेंट) |
| `resetAt` | विंडो कब रीसेट होती है |
| `createdAt` | स्नैपशॉट कब लिया गया |

> 0 लागत वाले **प्रत्येक अनुरोध पर** स्नैपशॉट लिए जाते हैं और इनका उपयोग निम्न के लिए किया जाता है:

- डैशबोर्ड में कोटा प्रगति बार रेंडर करना
- 30-दिवसीय कोटा रुझान चार्ट दिखाना
- उपयोग के सीमा के निकट पहुँचने पर अलर्ट ट्रिगर करना

## REST API

### उपयोग रिकॉर्ड सूचीबद्ध करें

```bash
GET /api/usage?range=7d&limit=100
GET /api/usage?apiKeyId=key-123&range=30d
GET /api/usage?provider=openai&range=1d
```

प्रतिक्रिया:

```json
{
  "records": [
    {
      "id": "uuid",
      "apiKeyId": "key-123",
```

### उपयोग एनालिटिक्स क्वेरी करें

उपयोग डेटा को प्रत्यक्ष REST निर्यात एंडपॉइंट के बजाय डैशबोर्ड या MCP टूल के माध्यम से एक्सेस किया जाता है। उपलब्ध एनालिटिक्स:

- **`/api/usage/analytics`** — एकत्रित उपयोग मेट्रिक्स (मॉडल, प्रदाता, कुंजी के आधार पर समूहित)
- **`/api/usage/quota`** — प्रति API कुंजी वर्तमान कोटा स्थिति
- **`/api/usage/history`** — अनुरोध इतिहास लॉग

## प्रतिधारण और सफ़ाई

उपयोग डेटा प्रत्येक अनुरोध पर ~1-10KB बढ़ता है। बड़े पैमाने पर यह महत्वपूर्ण हो सकता है।

### प्रतिधारण सेटिंग्स

उपयोग इतिहास का प्रतिधारण UI में Database Settings के माध्यम से या `/api/settings/database` के माध्यम से कॉन्फ़िगर किया जाता है।

डिफ़ॉल्ट रूप से, उपयोग इतिहास **90 दिनों** तक रखा जाता है।

### सफ़ाई

पुराने रिकॉर्ड `src/lib/db/cleanup.ts` द्वारा साफ़ किए जाते हैं:

- बैकग्राउंड cron प्रक्रिया द्वारा ट्रिगर किया जाता है
- कॉन्फ़िगर की गई `usageHistory` प्रतिधारण सेटिंग से पुराने रिकॉर्ड `usage_history` से हटाता है

### स्टोरेज अनुमान

| अनुरोध दर          | 30-दिन का स्टोरेज | 90-दिन का स्टोरेज |
| ------------------ | ----------------- | ----------------- |
| 100 अनुरोध/दिन     | ~3MB              | ~9MB              |
| 1,000 अनुरोध/दिन   | ~30MB             | ~90MB             |
| 10,000 अनुरोध/दिन  | ~300MB            | ~900MB            |
| 100,000 अनुरोध/दिन | ~3GB              | ~9GB              |

बहुत अधिक ट्रैफ़िक के लिए, इन पर विचार करें:

- Database Settings के माध्यम से प्रतिधारण अवधि कम करना
- रॉ रिकॉर्ड के बजाय `aggregated_metrics` का उपयोग करना (केवल एनालिटिक्स के लिए)

## लागत अनुकूलन सुझाव

### 1. सही मॉडल का उपयोग करें

```bash
# त्वरित उत्तर — सस्ता + तेज़ उपयोग करें
curl -d '{"model":"auto/fast","messages":[...]}'

# जटिल कार्य — गुणवत्ता वाला मॉडल उपयोग करें
curl -d '{"model":"auto/smart","messages":[...]}'
```

### 2. कैशिंग सक्षम करें

Anthropic प्रॉम्प्ट कैशिंग **दोहराए गए कॉन्टेक्स्ट पर 90% बचत** करती है:

```ts
// कैशिंग स्वचालित है — बस वही बड़ा सिस्टम प्रॉम्प्ट शामिल करें
const response = await openai.chat({
  model: "claude-sonnet-4-5",
  system: longSystemPrompt, // स्वचालित रूप से कैश किया जाएगा
  messages: [{ role: "user", content: "..." }],
});
```

### 3. कम्प्रेशन का उपयोग करें

RTK + Caveman कम्प्रेशन **टूल-प्रधान सेशन पर 15-95% बचत** करता है:

```ts
const config = {
  compression: {
    engine: "rtk",
    intensity: "aggressive",
  },
};
```

### 4. प्रत्येक कुंजी के लिए कोटा सेट करें

अनियंत्रित लागत को रोकने के लिए हमेशा `quotaLimit` सेट करें:

```ts
await updateApiKey(keyId, { quotaLimit: 10_00 }); // $10/माह की सीमा
```

### 5. शीर्ष उपभोक्ताओं का ऑडिट करें

API कुंजी के आधार पर समूह बनाने और लागत के अनुसार क्रमबद्ध करने के लिए डैशबोर्ड या **`/api/usage/analytics`** का उपयोग करें:

```bash
GET /api/usage/analytics?groupBy=apiKey
```

## समस्या निवारण

### "लागत अपेक्षा से अधिक है"

1. **`/api/usage/analytics?groupBy=model`** जाँचें — महँगा मॉडल खोजें
2. **`/api/usage/analytics?groupBy=apiKey`** जाँचें — अधिक उपयोग करने वाले उपभोक्ता को खोजें
3. सत्यापित करें कि मूल्य निर्धारण डेटा अद्यतित है: `POST /api/pricing/sync`

### "रिकॉर्ड उपलब्ध नहीं हैं"

- Dashboard → Database → Cleanup के अंतर्गत DB प्रतिधारण सेटिंग्स जाँचें — पुराने रिकॉर्ड आवधिक सफ़ाई कार्य (`src/lib/db/cleanup.ts`) द्वारा हटा दिए जाते हैं
- `src/lib/db/usage*.ts` में त्रुटियाँ जाँचें — DB लेखन विफलताएँ लॉग की जाती हैं, लेकिन प्रदर्शित नहीं होतीं
- सत्यापित करें कि अनुरोध वास्तव में `chatCore` तक पहुँचा था — कॉम्बो रूटिंग जाँचें

### "कोटा लागू नहीं हो रहा है"

- कुंजी की `quotaLimit` सेटिंग जाँचें
- सत्यापित करें कि `quotaWindow` सही तरीके से सेट है
- `quotaSnapshots` रिकॉर्ड देखें — इन्हें प्रत्येक अनुरोध पर बनाया जाना चाहिए
