## 1. Antigravity बनाम Antigravity CLI (agy)

दोनों प्रदाता **एक ही Google बैकएंड** साझा करते हैं — समान OAuth क्लाइंट, टोकन रीफ़्रेश, एंडपॉइंट और Google खाते। अंतर केवल यह है कि आपको कौन-से मॉडल दिखाई देते हैं।

> Google की आधिकारिक तुलना के लिए [Antigravity CLI की घोषणा](https://antigravity.google/blog/introducing-google-antigravity-cli) देखें।

| पहलू                        | `antigravity` (IDE)                                | `agy` (CLI)                                              |
| --------------------------- | -------------------------------------------------- | -------------------------------------------------------- |
| **Google उत्पाद**           | Antigravity 2.0 / Antigravity IDE                  | Antigravity CLI                                          |
| **बैकएंड**                  | वही Google Cloud Code API                          | वही Google Cloud Code API                                |
| **OAuth / टोकन**            | वही क्लाइंट, वही रीफ़्रेश                          | वही क्लाइंट, वही रीफ़्रेश                                |
| **मॉडल कैटलॉग**             | स्थिर रूप से चयनित सूची (OmniRoute में हार्डकोडेड) | `:fetchAvailableModels` के माध्यम से Google से लाइव जाँच |
| **Claude मॉडल**             | Sonnet 4.6, Opus 4.6 (प्रत्येक के 4 संस्करण)       | Sonnet 4.6, Opus 4.6 (प्रत्येक के 4 संस्करण)             |
| **Gemini नामकरण**           | स्पष्ट लेबल (निम्न/मध्यम/उच्च)                     | अपस्ट्रीम ID (extra-low/low/agent)                       |
| **अतिरिक्त मॉडल**           | `gpt-oss-120b-medium`                              | Google के अतिरिक्त मॉडल शामिल हो सकते हैं                |
| **डिफ़ॉल्ट उपयोग परिदृश्य** | IDE एकीकरण (VS Code, JetBrains)                    | CLI / API पहुँच                                          |
| **कोटा**                    | agy के साथ साझा (वही Google खाता)                  | antigravity के साथ साझा (वही Google खाता)                |

**उपलब्ध मॉडल (प्रयोग द्वारा सत्यापित, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (विभिन्न चिंतन स्तर)
- Claude: Sonnet 4.6, Opus 4.6 (प्रत्येक के default/low/medium/high संस्करण)
- अन्य: GPT-OSS 120B Medium
- **Claude Sonnet 5 उपलब्ध नहीं है** — केवल 4.6 संस्करण समर्थित हैं

**मॉडल कैटलॉग अलग क्यों है**: Google का CLI, Google के आधिकारिक ब्लॉग के अनुसार, "गति और कम ओवरहेड के लिए अनुकूलित" और "Gemini मॉडल के साथ सह-अनुकूलित" है। Web/IDE उत्पाद "व्यापकता के लिए अनुकूलित" है। CLI मॉडल को गतिशील रूप से खोजने के लिए `:fetchAvailableModels` का उपयोग करता है, जबकि IDE एक स्थिर रूप से चयनित सूची का उपयोग करता है।

**व्यवहार में**: Gemini मॉडल के लिए `agy/` उपसर्ग का उपयोग करें (उदाहरण के लिए `agy/gemini-3.7-flash-high`)। स्थिर रूप से चयनित सूची के लिए `antigravity/` का उपयोग करें। दोनों एक ही Google बैकएंड का उपयोग करते हैं, लेकिन मॉडल के अलग-अलग नाम प्रदर्शित करते हैं। कोटा साझा होता है — किसी भी प्रदाता का उपयोग उसी Google खाते की सीमाओं में गिना जाता है।

## 2. Google One AI Pro: कोटा सिस्टम

> आधिकारिक कोटा विवरण के लिए [Antigravity Docs: Plans](https://antigravity.google/docs/plans) और नवीनतम मूल्य निर्धारण अपडेट के लिए [Changes to Antigravity Plans](https://antigravity.google/blog/changes-to-antigravity-plans) देखें।

Google Antigravity संदेशों की संख्या के बजाय "Work Done" (कम्प्यूटेशनल भार) पर आधारित **दो-स्तरीय कोटा** का उपयोग करता है।

### दो स्तर

| स्तर                   | यह क्या है                | रीफ़्रेश चक्र                                                                                 |
| ---------------------- | ------------------------- | --------------------------------------------------------------------------------------------- |
| **5-घंटे का स्प्रिंट** | "Work Done" का तत्काल पूल | किसी सत्र में पहले अनुरोध के 5 घंटे बाद रीसेट होता है                                         |
| **7-दिन की बेसलाइन**   | साप्ताहिक सख्त सीमा       | सीमा पूरी होने पर 5-घंटे के रीफ़्रेश को ओवरराइड करती है; अगली 7-दिन की अवधि तक लॉक कर देती है |

**"Work Done" की गणना कैसे होती है**: एजेंट-प्रधान कार्य (जैसे, "इस पूरे रिपॉज़िटरी को रीफ़ैक्टर करें") साधारण कार्यों (जैसे, "इस फ़ंक्शन को ठीक करें") की तुलना में कोटा बहुत तेज़ी से खर्च करते हैं। खपत दिखाने वाला कोई रीयल-टाइम डैशबोर्ड उपलब्ध नहीं है।

### प्लान स्तर

| ------------ | ---------- | ------------------------------------ | ------------------------------------------------- |

### Gemini बनाम Non-Gemini मॉडल

- **Gemini मॉडल** (Flash + Pro): एक ही दर सीमा साझा करते हैं, जिसकी खपत API मूल्य निर्धारण के अनुसार होती है। यदि Flash, Pro से 8x सस्ता है, तो आपको 8x अधिक Flash टोकन मिलते हैं।
- **Non-Gemini मॉडल** (Claude, GPT-OSS): इनकी **अलग-अलग** दर सीमाएँ होती हैं। Gemini लॉक होने पर भी ये उपलब्ध रह सकते हैं।

### AI क्रेडिट (अतिरिक्त उपयोग)

> क्रेडिट कैसे काम करते हैं, इसके लिए [Google One AI credits](https://support.google.com/googleone/answer/14534406) देखें।

बेसलाइन कोटा समाप्त होने पर:

- **कभी नहीं**: कोटा रीफ़्रेश होने की प्रतीक्षा करें; "Baseline model quota reached" दिखाता है
- **हमेशा**: AI क्रेडिट का स्वतः उपयोग करें; बेसलाइन रीफ़्रेश होने पर वापस उसी पर स्विच हो जाता है

क्रेडिट अलग से खरीदे जाते हैं और मानक API मूल्य निर्धारण के अनुसार काटे जाते हैं।

### प्रमुख विवरण

- कोटा **अकाउंट स्तर पर साझा** होता है — Antigravity IDE, CLI और OmniRoute में एक ही Google अकाउंट एक ही कोटा पूल साझा करता है
- प्रत्येक Google अकाउंट का अपना स्वतंत्र कोटा होता है — एकाधिक अकाउंट = एकाधिक कोटा पूल
- AI Pro उपयोगकर्ताओं ने साप्ताहिक बेसलाइन सीमा पूरी होने पर 5-घंटे के रीसेट के बजाय **7-दिन के लॉकआउट** की सूचना दी है (Google ने पुष्टि की है कि उच्च माँग के लिए यह डिज़ाइन के अनुसार है)

**जब आपके अकाउंट का कोटा समाप्त हो जाता है**: OmniRoute कॉम्बो रूट में अगले उपलब्ध अकाउंट के साथ स्वचालित रूप से पुनः प्रयास करता है। किसी मैन्युअल हस्तक्षेप की आवश्यकता नहीं है।

## 3. projectId कैसे प्राप्त करें

प्रत्येक antigravity/agy कनेक्शन के लिए Google Cloud Code `projectId` आवश्यक है। इसके बिना, `/v1internal:models` एंडपॉइंट 404 लौटाता है।

### विधि A: स्वचालित (अनुशंसित)

OmniRoute इसे स्वचालित रूप से संभालता है। जब आप Dashboard OAuth के माध्यम से नया Google अकाउंट जोड़ते हैं:

1. OmniRoute टोकन को रीफ़्रेश करता है
2. projectId का पता लगाने के लिए `loadCodeAssist` को कॉल करता है
3. यदि कोई प्रोजेक्ट मौजूद नहीं है, तो उसे बनाने के लिए `onboardUser` को कॉल करता है
4. नए बनाए गए projectId को प्राप्त करने के लिए `loadCodeAssist` का पुनः प्रयास करता है
5. उसे डेटाबेस में सहेजता है

**यह अधिकांश अकाउंट के लिए काम करता है** — किसी मैन्युअल चरण की आवश्यकता नहीं है।

### विधि B: agy CLI के माध्यम से मैन्युअल

यदि स्वचालित खोज विफल हो जाती है (ऐसा कब होता है, इसके लिए अनुभाग 5 देखें):

```bash
# agy CLI इंस्टॉल करें (यदि पहले से इंस्टॉल नहीं है)
npm install -g @anthropic-ai/agy

# अपने Google अकाउंट से लॉग इन करें
agy login

# उस अकाउंट का चयन करें जिसे ऑनबोर्डिंग की आवश्यकता है
# यह Cloud Code पंजीकरण शुरू करता है और एक projectId निर्दिष्ट करता है
```

`agy login` सफल होने के बाद, OmniRoute Dashboard में टोकन रीफ़्रेश करें। projectId का स्वचालित रूप से पता लगा लिया जाएगा।

### सत्यापन कैसे करें

डेटाबेस जाँचें:

```bash
# OmniRoute कंटेनर के अंदर
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

या लॉग जाँचें:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. OAuth रीडायरेक्ट URI

### समस्या

Google OAuth के लिए एक मान्य रीडायरेक्ट URI आवश्यक है। OmniRoute डिफ़ॉल्ट रूप से `http://127.0.0.1:20128/callback` (लूपबैक) का उपयोग करता है। यह स्थानीय बिल्ड के लिए काम करता है, लेकिन **रिमोट डिप्लॉयमेंट के लिए विफल हो जाता है** (उदाहरण के लिए, LAN IP के माध्यम से एक्सेस किया गया सर्वर)।

Google ऐसे रीडायरेक्ट URI अस्वीकार करता है जो:

- IP पतों का उपयोग करते हैं (डोमेन का अंत `.com`, `.org` आदि से होना चाहिए)
- OAuth क्लाइंट कॉन्फ़िगरेशन में पंजीकृत रीडायरेक्ट URI से मेल नहीं खाते

### समाधान

**विकल्प A: बिल्ट-इन OAuth फ़्लो का उपयोग करें (डिफ़ॉल्ट)**

- यह तब काम करता है, जब आप OmniRoute को `localhost` या `127.0.0.1` से एक्सेस करते हैं
- किसी कॉन्फ़िगरेशन की आवश्यकता नहीं है

**विकल्प B: कस्टम OAuth क्रेडेंशियल**

- अपने एनवायरनमेंट में `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` सेट करें
- अपने Google OAuth क्रेडेंशियल प्रदान करें:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Google Cloud Console में `https://your-domain.com/callback` को अधिकृत रीडायरेक्ट URI के रूप में पंजीकृत करें

**विकल्प C: शुरुआती लॉगिन के लिए agy CLI का उपयोग करें**

- उस मशीन पर `agy login` चलाएँ जो OmniRoute को एक्सेस करेगी
- OAuth फ़्लो स्थानीय रूप से पूरा होता है और टोकन संग्रहीत हो जाते हैं
- Dashboard के माध्यम से कनेक्शन को OmniRoute में इंपोर्ट करें

### सीमाएँ

- कस्टम OAuth क्रेडेंशियल के लिए डोमेन नाम आवश्यक है (Google रीडायरेक्ट URI के रूप में IP पते स्वीकार नहीं करता)
- यदि आपके पास डोमेन नहीं है, तो इसके बजाय विकल्प A या C का उपयोग करें

## 5. समस्या निवारण: जब स्वचालित सेटअप विफल हो जाए

OmniRoute अधिकांश खातों के लिए projectId की खोज और ऑनबोर्डिंग को स्वचालित रूप से संभालता है। इसके विफल होने पर मूल कारण आमतौर पर इनमें से कोई एक होता है:

### खाते का क्षेत्र अवरुद्ध है

**लक्षण**: `agy login` यह संदेश देता है: "पात्रता जाँच विफल रही: आपका वर्तमान खाता Antigravity के लिए पात्र नहीं है, क्योंकि यह फ़िलहाल आपके स्थान पर उपलब्ध नहीं है।"

**मूल कारण**: Google खातों में बैकएंड का "देश संबद्धता" फ़ील्ड होता है, जिसे पंजीकरण के समय सेट किया जाता है। agy CLI और Cloud Code API इस फ़ील्ड की सख्ती से जाँच करते हैं — वेब Gemini के विपरीत, जो केवल आपके वर्तमान IP की जाँच करता है।

> अपने खाते से संबद्ध क्षेत्र की जाँच करने या उसे बदलने के लिए, [Google देश संबद्धता फ़ॉर्म](https://policies.google.com/country-association-form) पर जाएँ।

**वेब Gemini काम करता है, लेकिन agy क्यों नहीं**:

- वेब Gemini / Google One: केवल वर्तमान IP की जाँच करता है (प्रॉक्सी से काम हो जाता है)
- agy CLI / Cloud Code API: बैकएंड का देश संबद्धता फ़ील्ड पढ़ता है (प्रॉक्सी से सहायता नहीं मिलती)

**समाधान**:

1. US IP का उपयोग करते हुए [Google देश संबद्धता फ़ॉर्म](https://policies.google.com/country-association-form) पर जाएँ
2. क्षेत्र बदलने का अनुरोध सबमिट करें ("मैं किसी दूसरे देश में रहता/रहती हूँ" चुनें)
3. Google द्वारा अनुरोध संसाधित किए जाने और ईमेल सूचना मिलने के लिए 1-24 घंटे प्रतीक्षा करें
4. इसके बाद `agy login` सफल होना चाहिए

### खाते में कोई Cloud Code प्रोजेक्ट नहीं है

**लक्षण**: लॉग में `loadCodeAssist returned no project id` और `onboardUser failed (400)` दिखाई देता है।

**मूल कारण**: खाता कभी भी Google Cloud Code के साथ पंजीकृत नहीं हुआ है और स्वचालित ऑनबोर्डिंग विफल हो गई है।

**समाधान**: Cloud Code पंजीकरण ट्रिगर करने के लिए `agy login` को मैन्युअल रूप से चलाएँ, फिर OmniRoute Dashboard में टोकन को रीफ़्रेश करें।

### टोकन की समय-सीमा समाप्त हो गई है या उसे निरस्त कर दिया गया है

**लक्षण**: लॉग में 401 त्रुटियाँ या "टोकन की समय-सीमा समाप्त हो गई है" संदेश दिखाई देते हैं।

**समाधान**: Dashboard → Providers → agy → रीफ़्रेश आइकन पर क्लिक करके टोकन को रीफ़्रेश करें। यदि रीफ़्रेश टोकन स्वयं निरस्त कर दिया गया है, तो आपको OAuth के माध्यम से फिर से प्रमाणीकरण करना होगा।
