यह गाइड OmniRoute में Kiro (AWS द्वारा होस्ट किया गया AI कोडिंग सहायक) खाते जोड़ने की प्रक्रिया बताती है,
जिसमें सत्र टकरावों के बिना एक साथ कई खाते चलाने पर विशेष ध्यान दिया गया है।

---

## पृष्ठभूमि: Kiro खातों में टकराव क्यों हो सकता है

Kiro का बैकएंड सक्रिय सत्रों को ट्रैक करने के लिए AWS SSO OIDC क्लाइंट पंजीकरणों का उपयोग करता है।
महत्वपूर्ण बाधा: **प्रत्येक OIDC क्लाइंट पंजीकरण एक समय में केवल एक सक्रिय
सत्र का समर्थन करता है**। जब कोई दूसरा डिवाइस या उपयोगकर्ता उसी पंजीकृत
क्लाइंट का उपयोग करके प्रमाणित करता है, तो बैकएंड पहले खाते के रीफ़्रेश टोकन को अमान्य कर देता है।

यह वही तंत्र है जो उस मशीन पर `kiro-cli login` चलाने पर समस्याएँ पैदा करता है
जहाँ कोई अन्य Kiro खाता पहले से साइन इन है — नया लॉगिन पहले
खाते के टोकन को रद्द कर देता है।

## OmniRoute इसे कैसे हल करता है (v3.8.0+)

v3.8.0 से शुरू होकर, OmniRoute प्रत्येक Kiro कनेक्शन आयात के दौरान
`registerClient()` (AWS SSO OIDC) को कॉल करता है। इससे प्रत्येक OmniRoute कनेक्शन को अपना समर्पित OIDC
क्लाइंट पंजीकरण मिलता है। चूँकि प्रत्येक क्लाइंट पंजीकरण स्वतंत्र होता है, इसलिए किसी एक खाते को रीफ़्रेश या
फिर से प्रमाणित करने से किसी अन्य खाते का रीफ़्रेश टोकन प्रभावित नहीं होता।

यह पृथक्करण रीफ़्रेश-टोकन आयात विधियों पर लागू होता है, और API-कुंजी प्रमाणीकरण
OIDC रीफ़्रेश सत्रों से पूरी तरह बचता है:

| आयात विधि                                                     | पृथक्करण की स्थिति                                                                                |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| AWS Builder ID / IDC डिवाइस-कोड फ़्लो                         | डिवाइस-कोड फ़्लो प्रस्तुत किए जाने के समय से पृथक                                                 |
| **टोकन आयात करें** (रीफ़्रेश टोकन मैन्युअल रूप से पेस्ट करना) | v3.8.0 से पृथक                                                                                    |
| **Google / GitHub सोशल लॉगिन**                                | v3.8.0 से पृथक                                                                                    |
| **स्वतः आयात** (kiro-cli SQLite)                              | v3.8.0 से पृथक (SQLite पथ पहले से पृथक था; SSO-कैश फ़ॉलबैक भी अब पृथक है)                         |
| **API कुंजी** (दीर्घकालिक CodeWhisperer कुंजी)                | कोई रीफ़्रेश सत्र नहीं; कुंजी को सत्यापित करके बियरर क्रेडेंशियल के रूप में संग्रहीत किया जाता है |

## v3.8.0 से पहले बनाए गए कनेक्शनों के लिए माइग्रेशन नोट

v3.8.0 से पहले आयात किए गए कनेक्शनों के `providerSpecificData` में समर्पित OIDC क्लाइंट पंजीकरण
संग्रहीत नहीं होता। ये कनेक्शन काम करना जारी रखते हैं, लेकिन साझा
सोशल-प्रमाणीकरण रीफ़्रेश एंडपॉइंट का उपयोग करते हैं, जिसका अर्थ है कि ऐसे दो कनेक्शन अब भी एक-दूसरे को
अमान्य कर सकते हैं।

**पृथक्करण प्राप्त करने के लिए:** पुराने कनेक्शन को **डैशबोर्ड → प्रदाता** से हटाएँ और
किसी भी समर्थित आयात फ़्लो का उपयोग करके उसे फिर से आयात करें। सभी नए बनाए गए कनेक्शनों को
अपना क्लाइंट पंजीकरण स्वचालित रूप से मिल जाएगा।

## दो Kiro खाते साथ-साथ जोड़ना

### पूर्वापेक्षाएँ

- OmniRoute v3.8.0 या उसके बाद का संस्करण।
- एक कार्यशील Kiro खाता (ईमेल + पासवर्ड, Google या GitHub लॉगिन)।
- वैकल्पिक रूप से, दूसरा Kiro खाता।

### चरण 1: पहला खाता आयात करें

1. **डैशबोर्ड → प्रदाता → प्रदाता जोड़ें → Kiro** खोलें।
2. इनमें से एक चुनें:
   - **टोकन आयात करें** — `aorAAAAAG` से शुरू होने वाला रीफ़्रेश टोकन पेस्ट करें।
   - **API कुंजी** — दीर्घकालिक Kiro / CodeWhisperer API कुंजी पेस्ट करें।
   - **Google / GitHub लॉगिन** — ब्राउज़र में OAuth फ़्लो पूरा करें।
   - **स्वतः आयात** — बटन पर क्लिक करें; OmniRoute स्थानीय kiro-cli डेटाबेस या
     `~/.aws/sso/cache` से क्रेडेंशियल पढ़ता है।
3. कनेक्शन सहेज दिया जाता है। रीफ़्रेश-टोकन फ़्लो स्वचालित रूप से एक समर्पित
   OIDC क्लाइंट पंजीकृत करते हैं। API-कुंजी फ़्लो AWS के साथ कुंजी को सत्यापित करते हैं और रीफ़्रेश टोकन संग्रहीत नहीं करते।

### चरण 2: दूसरा खाता आयात करें

दूसरे खाते के लिए चरण 1 दोहराएँ। चूँकि प्रत्येक आयात एक अलग OIDC
क्लाइंट पंजीकरण बनाता है, इसलिए दोनों कनेक्शन पूरी तरह पृथक रहते हैं।

### चरण 3: सत्यापित करें कि दोनों कनेक्शन सक्रिय हैं

1. **डैशबोर्ड → प्रदाता** — दोनों Kiro कनेक्शनों को **सक्रिय** स्थिति दिखानी चाहिए।
2. **डैशबोर्ड → स्वास्थ्य** — दोनों कनेक्शनों को अपनी टोकन स्वास्थ्य जाँच पास करनी चाहिए।

### चरण 4: खातों के बीच रूट करने के लिए कॉम्बो का उपयोग करें

उनके बीच लोड-बैलेंसिंग या फ़ॉलबैक के लिए दोनों कनेक्शनों को लक्ष्य बनाकर एक कॉम्बो बनाएँ:

```
kiro/kiro-dev → kiro/kiro-pro
```

कॉम्बो कॉन्फ़िगरेशन के लिए [FEATURES.md](./FEATURES.md) और रूटिंग दस्तावेज़ देखें।

## एंटरप्राइज़ / IDC उपयोगकर्ता

AWS IAM Identity Center (IDC) खातों के लिए, **Dashboard → Providers → Kiro → Device Code** से **AWS Builder ID / IDC device-code** प्रवाह का उपयोग करें। device-code प्रवाह हमेशा से पूरी तरह पृथक रहा है। इन कनेक्शनों के लिए दोबारा इंपोर्ट करने की आवश्यकता नहीं है।

गैर-डिफ़ॉल्ट AWS क्षेत्र में काम करने वाले एंटरप्राइज़ उपयोगकर्ता Import Token API के माध्यम से इंपोर्ट करते समय क्षेत्र निर्दिष्ट कर सकते हैं:

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/import \
  -H "Content-Type: application/json" \
  -d '{"refreshToken": "aorAAAAAG...", "region": "eu-west-1"}'
```

यदि `region` फ़ील्ड नहीं दिया जाता है, तो इसका डिफ़ॉल्ट मान `us-east-1` होता है।

## API-Key इंपोर्ट प्रवाह

API-key प्रमाणीकरण लंबे समय तक मान्य रहने वाले Kiro / AWS CodeWhisperer bearer क्रेडेंशियल्स के लिए है। यह OAuth रिफ़्रेश का उपयोग नहीं करता, इसलिए साझा OIDC सत्र के अमान्य होने से बचाता है।

### डैशबोर्ड

1. **Dashboard -> Providers -> Kiro** खोलें।
2. **API Key** चुनें।
3. API key और वैकल्पिक AWS क्षेत्र पेस्ट करें (डिफ़ॉल्ट रूप से `us-east-1`)।
4. OmniRoute key को सत्यापित करता है और कनेक्शन सहेजता है।

### API

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/api-key \
  -H "Content-Type: application/json" \
  -d '{"apiKey": "kiro_or_codewhisperer_key", "region": "us-east-1"}'
```

### आंतरिक अनुबंध

API रूट `KiroService.validateApiKey()` को कॉल करके key को सत्यापित करता है, जो क्षेत्र से मेल खाने वाले CodeWhisperer/Amazon Q endpoint पर `ListAvailableProfiles` का उपयोग करता है और एक `profileArn` निर्धारित करता है।

सहेजा गया कनेक्शन इसका उपयोग करता है:

```json
{
  "authType": "apikey",
  "providerSpecificData": {
    "authMethod": "api_key",
    "region": "us-east-1",
    "profileArn": "arn:aws:codewhisperer:..."
  }
}
```

रनटाइम पर, `KiroExecutor.buildHeaders()` key को `Authorization: Bearer <key>` के रूप में भेजता है और `tokentype: API_KEY` जोड़ता है। कोटा/प्रोफ़ाइल कॉल उसी मार्कर का उपयोग करते हैं, ताकि AWS bearer को OIDC या सोशल access token के बजाय लंबे समय तक मान्य रहने वाली API key माने।

## OIDC क्लाइंट की समय-सीमा समाप्ति

AWS SSO OIDC public clients की समय-सीमा आम तौर पर 90 दिनों के बाद समाप्त हो जाती है (`clientSecretExpiresAt`)। प्रेक्षणीयता के लिए OmniRoute इस timestamp को `providerSpecificData` में संग्रहीत करता है। यदि कोई कनेक्शन लगभग 90 दिनों के बाद रिफ़्रेश होना बंद कर देता है, तो नया OIDC client registration प्राप्त करने के लिए कनेक्शन को दोबारा इंपोर्ट करें। समय-सीमा समाप्त होने पर स्वचालित पुनः-पंजीकरण को भावी सुधार के रूप में ट्रैक किया गया है।

API-key कनेक्शनों में OIDC client expiry नहीं होती, क्योंकि वे AWS SSO OIDC के माध्यम से रिफ़्रेश नहीं होते हैं।

## समस्या निवारण

### दूसरा खाता बार-बार लॉग आउट हो रहा है

- **Dashboard → Providers** में दोनों कनेक्शन जाँचें और पुष्टि करें कि प्रत्येक के raw JSON में गैर-null `clientId` दिखाई दे रहा है (info icon के माध्यम से देखा जा सकता है)। यदि किसी भी कनेक्शन में `clientId` नहीं है, तो उसे v3.8.0 से पहले इंपोर्ट किया गया था — उसे दोबारा इंपोर्ट करें।

### इंपोर्ट "Token validation failed" के साथ विफल होता है

- सुनिश्चित करें कि refresh token `aorAAAAAG` से शुरू होता है।
- सुनिश्चित करें कि OmniRoute `https://oidc.us-east-1.amazonaws.com` (या कॉन्फ़िगर किए गए क्षेत्र) तक पहुँच सकता है। यदि आप corporate proxy के पीछे हैं, तो **Dashboard → Settings → Proxies** में provider-level proxy सेट करें।

### API-key इंपोर्ट विफल होता है

- पुष्टि करें कि key एक Kiro / CodeWhisperer API key है, refresh token नहीं।
- पुष्टि करें कि AWS क्षेत्र key/खाते से मेल खाता है। `us-east-1` डिफ़ॉल्ट है।
- key को `ListAvailableProfiles` कॉल करने में सक्षम होना चाहिए; अन्यथा OmniRoute आवश्यक `profileArn` निर्धारित नहीं कर सकता।
