**OmniCopilot** आपके OmniRoute द्वारा उपलब्ध कराए जाने वाले प्रत्येक मॉडल को _नेटिव_ GitHub Copilot Chat
मॉडल पिकर में जोड़ता है। कोई दूसरा साइडबार नहीं, कोई अलग चैट UI नहीं — Copilot का एजेंट मोड, टूल कॉलिंग,
MCP सर्वर और कस्टम निर्देश सभी काम करते रहते हैं, बस आपके चुने हुए मॉडल पर चलते हैं।

## सेटअप

1. **OmniRoute चलाएँ** — `npm install -g omniroute && omniroute` (`http://localhost:20128` पर डैशबोर्ड)।
2. **एक्सटेंशन इंस्टॉल करें** — Extensions दृश्य में "OmniRoute" खोजें।
3. **कोई मॉडल चुनें** — Copilot Chat → मॉडल पिकर → **मॉडल प्रबंधित करें…** → **OmniRoute**, फिर
   अपनी इच्छित चीज़ों पर सही का निशान लगाएँ।

जब OmniRoute डिफ़ॉल्ट पोर्ट पर चलता है, तो कुछ भी कॉन्फ़िगर करने की आवश्यकता नहीं होती। किसी रिमोट इंस्टेंस के लिए,
**Activity Bar में OmniRoute आइकन** खोलें (या `OmniRoute: Manage Connection` चलाएँ) और ये सेट करें:

- **सर्वर URL** — सर्वर रूट, उदाहरण के लिए `http://192.168.0.15:20128`। `/v1` प्रत्यय
  एक्सटेंशन द्वारा जोड़ा जाता है; इसे शामिल न करें।
- **API कुंजी** — केवल तब, जब सर्वर `REQUIRE_API_KEY` सेट करता है। इसे VS
  Code SecretStorage के माध्यम से OS कीचेन में संग्रहीत किया जाता है, `settings.json` में कभी नहीं।

## पिकर क्या दिखाएगा

एक्सटेंशन अपरिष्कृत `GET /v1/models` पेलोड नहीं दिखाता — यह उसे व्यवस्थित करता है, और आपको दिखाई देने वाली
संख्या दो जानबूझकर किए गए कारणों से कैटलॉग के आकार से कम होती है।

### यह प्रत्येक मॉडल के लिए एक id माँगता है

`MODELS_CATALOG_PREFIX_MODE` डिफ़ॉल्ट रूप से **`dual`** होता है, जो प्रत्येक मॉडल को दो बार प्रदर्शित करता है — एक बार
संक्षिप्त उपनाम प्रीफ़िक्स के अंतर्गत और एक बार कैनोनिकल प्रदाता प्रीफ़िक्स के अंतर्गत — ताकि पुराने क्लाइंट
कॉन्फ़िगरेशन दोनों में से किसी भी रूप को हल करना जारी रख सकें:

```
cc/claude-sonnet-4-6        ← उपनाम प्रीफ़िक्स
claude/claude-sonnet-4-6    ← कैनोनिकल प्रीफ़िक्स, वही मॉडल
```

एक्सटेंशन **`GET /v1/models?prefix=alias`** का अनुरोध करता है, ताकि आपके अन्य क्लाइंट के लिए सर्वर-व्यापी
सेटिंग बदले बिना प्रत्येक मॉडल के लिए एक id प्राप्त हो। एक संदर्भ इंस्टेंस पर इससे
**2345 प्रविष्टियाँ घटकर 1396 हो गईं — 949 डुप्लिकेट, एक भी मॉडल नष्ट नहीं हुआ।**

यदि आप इसके बजाय इसे _हर_ क्लाइंट के लिए सर्वर-व्यापी रूप से ठीक करना चाहते हैं, तो डैशबोर्ड में
`MODELS_CATALOG_PREFIX_MODE` फ़ीचर फ़्लैग को `alias` पर सेट करें। क्वेरी पैरामीटर और
प्रत्येक मोड की तालिका के लिए [API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) देखें।

### यह उन मॉडलों को छिपाता है जो चैट नहीं कर सकते

कैटलॉग में इमेज, वीडियो, ऑडियो, रीरैंक, एम्बेडिंग और मॉडरेशन मॉडल भी सूचीबद्ध होते हैं। वैसे भी चैट अनुरोध पर
उन्हें अस्वीकार कर दिया जाता है:

```
HTTP 400 — मॉडल '<id>' एक इमेज-जनरेशन मॉडल है और इसका उपयोग
/v1/chat/completions पर नहीं किया जा सकता। इसके बजाय POST /v1/images/generations का उपयोग करें।
```

इसलिए पिकर तक पहुँचने से पहले उन्हें उनके `type` फ़ील्ड के आधार पर फ़िल्टर कर दिया जाता है। **Responses-API
मॉडल बनाए रखे जाते हैं** — प्रत्येक Codex / GPT-5.x प्रविष्टि `supported_endpoints: ["responses"]` प्रदर्शित करती है,
और OmniRoute उन्हें `/v1/chat/completions` के लिए रूपांतरित करता है, इसलिए वे पूरी तरह उपयोग योग्य हैं।

### वे प्रदाता जिन्हें आपने कभी कॉन्फ़िगर नहीं किया

कैटलॉग **सक्रिय कनेक्शन** वाले प्रदाताओं के मॉडल और प्रत्येक **noAuth**
प्रदाता — वे कुंजी-रहित प्रदाता जो मुफ़्त टियर का बड़ा हिस्सा बनाते हैं — सूचीबद्ध करता है। यह जानबूझकर किया गया है। उन्हें छिपाने के लिए,
उन्हें डैशबोर्ड सेटिंग में `blockedProviders` में जोड़ें; एक्सटेंशन में कुछ भी नहीं बदलता।

## VS Code टैब के भीतर डैशबोर्ड

`omnicopilot.dashboardOpen: "editor"` बाहरी ब्राउज़र के बजाय Simple Browser के माध्यम से OmniRoute डैशबोर्ड को एडिटर टैब में रेंडर करता है। एम्बेडिंग को **सर्वर पर ऑप्ट-इन** करना होता है, जिसके लिए `DASHBOARD_ALLOW_EMBED=vscode` का उपयोग किया जाता है। इससे HTML पेज डिफ़ॉल्ट `frame-ancestors 'none'` + `X-Frame-Options: DENY` के बजाय `frame-ancestors 'self' vscode-webview:` के साथ सर्व किए जाते हैं। API सरफ़ेस (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) दोनों ही स्थितियों में सख़्त हेडर बनाए रखता है।

> ⚠️ **यह बिल्ड-टाइम फ़्लैग है, रनटाइम फ़्लैग नहीं।** Next.js `headers()` को रूट
> मैनिफ़ेस्ट में कंपाइल करता है, इसलिए `next.config.mjs` बंडल बनाए जाते समय वेरिएबल पढ़ता है
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`)।
> इसे पहले से बिल्ड किए गए सर्वर के आगे एक्सपोर्ट करने से कुछ नहीं बदलता — हेडर पहले से ही बेक किए गए होते हैं।

```bash
# वेरिएबल BUILD कमांड में मौजूद होना चाहिए
DASHBOARD_ALLOW_EMBED=vscode npm run build        # या npm run build:release
npm start
```

| आपने कैसे इंस्टॉल किया     | क्या आप एम्बेडिंग सक्षम कर सकते हैं?                                                                                                       |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| सोर्स से                   | ✅ ऊपर बताए अनुसार, बिल्ड कमांड पर वेरिएबल सेट करें                                                                                        |
| `npm install -g omniroute` | ❌ प्रकाशित पैकेज में पहले से बिल्ड किया हुआ बंडल शामिल होता है — इसके बजाय सोर्स से बिल्ड करें                                            |
| Docker इमेज                | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — Docker Hub पर उपलब्ध प्रीबिल्ट इमेज एम्बेड-सक्षम नहीं है |

एम्बेड-सक्षम बिल्ड के बिना पेज फ़्रेम में खुलने से मना कर देता है। एक्सटेंशन रिस्पॉन्स हेडर से इसका पता लगाता है और बाहरी ब्राउज़र पर वापस चला जाता है — कुछ भी खराब नहीं होता और यह एक बार इसकी सूचना देता है।
[`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) और इश्यू
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273) देखें।

## VS Code के भीतर से अपने अन्य टूल कॉन्फ़िगर करना

**`OmniRoute: Configure Coding CLI`** Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code, Kilo और Roo के लिए इस्तेमाल के लिए तैयार प्रोफ़ाइल लिखने हेतु `omniroute` CLI चलाता है — ये वही कॉन्फ़िगरेशन हैं जिनका वर्णन

| `editor` मोड के बावजूद डैशबोर्ड ब्राउज़र में खुलता है | सर्वर को `DASHBOARD_ALLOW_EMBED=vscode` के साथ **बिल्ड** नहीं किया गया था (ऊपर देखें) — प्रीबिल्ट इंस्टॉलेशन पर इसे स्टार्टअप के समय सेट करने से कुछ नहीं होता। फ़ॉलबैक जानबूझकर किया गया है।                                                                        |
| प्रोवाइडर बदलने के बाद मॉडल सूची पुरानी है            | `OmniRoute: Refresh Models` चलाएँ, या पैनल में ↻ लिंक का उपयोग करें।                                                                                                                                                                                                 |
