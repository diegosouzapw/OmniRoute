## इंस्टॉलेशन विधियाँ

### npm (अनुशंसित)

```bash
npm install -g omniroute
omniroute
```

डैशबोर्ड `http://localhost:20128` पर खुलता है और API का आधार URL `http://localhost:20128/v1` है।

### pnpm

```bash
pnpm add -g omniroute@latest --allow-build=better-sqlite3 --allow-build=@swc/core
omniroute
```

> **pnpm उपयोगकर्ता:** `better-sqlite3` और `@swc/core` के लिए नेटिव बिल्ड स्क्रिप्ट सक्षम करने हेतु `--allow-build` फ़्लैग आवश्यक है। pnpm v11 पर ग्लोबल इंस्टॉलेशन के लिए `pnpm approve-builds -g` कमांड समर्थित नहीं है।

### Arch Linux (AUR)

```bash
yay -S omniroute-bin
systemctl --user enable --now omniroute.service
```

[AUR पैकेज](https://aur.archlinux.org/packages/omniroute-bin) OmniRoute इंस्टॉल करता है और एक systemd उपयोगकर्ता सेवा प्रदान करता है।

### स्रोत से

```bash
npm install
PORT=20128 DASHBOARD_PORT=20129 NEXT_PUBLIC_BASE_URL=http://localhost:20129 npm run dev
```

> **Windows संबंधी टिप्पणी:** डिफ़ॉल्ट रूप से, जब पुरानी `%USERPROFILE%\.omniroute` डायरेक्टरी मौजूद नहीं होती है, तो OmniRoute `%APPDATA%\omniroute` का उपयोग करता है। किसी अन्य डेटा-डायरेक्टरी स्थान को चुनने के लिए `DATA_DIR` सेट करें।

> **टिप्पणी:** पहली बार चलाने पर `npm install`, `.env.example` से `.env` स्वतः जनरेट करता है। बाद के इंस्टॉलेशन मौजूदा `.env` को ओवरराइट नहीं करेंगे, इसलिए अनुकूलन सुरक्षित रहते हैं। इसे फिर से जनरेट करने के लिए, दोबारा चलाने से पहले `.env` हटाएँ।

### Docker

Compose प्रोफ़ाइल और Caddy HTTPS सहित संपूर्ण Docker सेटअप के लिए [Docker मार्गदर्शिका](./DOCKER_GUIDE.md) देखें।

### डेस्कटॉप ऐप (Electron)

OmniRoute के साथ Electron 41 + electron-builder 26.10 पर निर्मित एक डेस्कटॉप रैपर मिलता है। उपलब्ध स्क्रिप्ट (वर्कस्पेस रूट):

```bash
npm run electron:dev          # हॉट-रीलोड के साथ डेस्कटॉप चलाएँ
npm run electron:build        # वर्तमान OS के लिए बिल्ड करें (स्वतः पहचाना गया)
npm run electron:build:win    # Windows इंस्टॉलर (NSIS + पोर्टेबल)
npm run electron:build:mac    # macOS (dmg + zip, arm64+x64)
npm run electron:build:linux  # Linux (AppImage + deb + rpm)
npm run electron:smoke:packaged  # पैकेज किए गए बिल्ड का स्मोक-टेस्ट करें
```

डेस्कटॉप इंस्टॉलर के रिलीज़ GitHub Releases से संलग्न होते हैं। Electron के संपूर्ण गहन विवरण (साइनिंग, IPC ब्रिज, डिस्ट्रो) के लिए, [`ELECTRON_GUIDE.md`](./ELECTRON_GUIDE.md) देखें _(बाद के चरण में बनाया गया)_।

### हेडलेस सर्वर (CI/ऑटोमेशन)

बिना निगरानी वाले सेटअप (Docker, Kubernetes, CI) के लिए, इसका उपयोग करें:

```bash
omniroute setup --non-interactive
omniroute providers test-batch
```

env vars (`INITIAL_PASSWORD`, `OMNIROUTE_WS_BRIDGE_SECRET`, आदि) के साथ संयोजित करके, यह आपको पूरी तरह स्क्रिप्ट-योग्य OmniRoute इंस्टेंस शुरू करने देता है।

### CLI विकल्प

| कमांड                   | विवरण                                                                                           |
| ----------------------- | ----------------------------------------------------------------------------------------------- |
| `omniroute`             | सर्वर शुरू करें (`PORT=20128`, API और डैशबोर्ड एक ही पोर्ट पर)                                  |
| `omniroute setup`       | पासवर्ड और पहले प्रोवाइडर के लिए निर्देशित CLI ऑनबोर्डिंग                                       |
| `omniroute doctor`      | सर्वर शुरू किए बिना स्थानीय स्वास्थ्य जाँच चलाएँ                                                |
| `omniroute providers`   | CLI से प्रोवाइडर खोजें, सूचीबद्ध करें, सत्यापित करें और उनका परीक्षण करें                       |
| `omniroute config`      | CLI टूल कॉन्फ़िगरेशन — कॉन्फ़िग सूचीबद्ध करें, प्राप्त करें, सेट करें और सत्यापित करें          |
| `omniroute status`      | ऑफ़लाइन स्थिति डैशबोर्ड — संस्करण, DB, टूल, कॉन्फ़िग                                            |
| `omniroute logs`        | API से उपयोग लॉग स्ट्रीम करें (`--follow` समर्थित है)                                           |
| `omniroute update`      | OmniRoute अपडेट की जाँच करें या उन्हें लागू करें                                                |
| `omniroute provider`    | प्रोवाइडर कनेक्शन प्रबंधित करें — जोड़ें, सूचीबद्ध करें, हटाएँ, परीक्षण करें, डिफ़ॉल्ट सेट करें |
| `omniroute --port 3000` | कैनोनिकल/API पोर्ट को 3000 पर सेट करें                                                          |
| `omniroute --mcp`       | MCP सर्वर शुरू करें (stdio ट्रांसपोर्ट)                                                         |
| `omniroute --no-open`   | ब्राउज़र स्वतः न खोलें                                                                          |
| `omniroute --help`      | सहायता दिखाएँ                                                                                   |

हेडलेस सेटअप को फ़्लैग या एनवायरनमेंट वेरिएबल के साथ स्क्रिप्ट किया जा सकता है:

```bash
omniroute setup --non-interactive --password "$OMNIROUTE_PASSWORD"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY" --test-provider
```

डैशबोर्ड खोले बिना स्थानीय डायग्नोस्टिक्स चलाएँ:

```bash
omniroute doctor
omniroute doctor --json
omniroute doctor --no-liveness
```

डैशबोर्ड खोले बिना SSH या स्क्रिप्ट से प्रोवाइडर प्रबंधित करें:

```bash
omniroute providers available
omniroute providers available --search openai
omniroute providers available --category api-key
omniroute providers list
omniroute providers test <id-or-name>
omniroute providers test-all
omniroute providers validate
```

## CLI टूल कॉन्फ़िगरेशन

### 1) प्रोवाइडर कनेक्ट करें और API कुंजी बनाएँ

1. Dashboard → `Providers` खोलें और कम-से-कम एक प्रोवाइडर (OAuth या API कुंजी) कनेक्ट करें।
2. Dashboard → `Endpoints` खोलें और एक API कुंजी बनाएँ।
3. (वैकल्पिक) Dashboard → `Combos` खोलें और अपनी फ़ॉलबैक शृंखला सेट करें।

### 2) अपने कोडिंग टूल को कॉन्फ़िगर करें

```txt
बेस URL: http://localhost:20128/v1
API कुंजी:  [Endpoint पेज से कॉपी करें]
मॉडल:    if/qwen3.8-max-preview (या कोई भी प्रोवाइडर/मॉडल प्रीफ़िक्स)
```

यदि आपका एडिटर `Authorization: Bearer ...` नहीं भेज सकता, तो इसके बजाय टोकनयुक्त संगतता बेस का उपयोग करें:

```txt
बेस URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/
मॉडल URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/models
चैट URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/chat/completions
Ollama टैग URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/api/tags
```

यह Claude Code, Codex CLI, Cursor, Cline, OpenClaw, OpenCode और OpenAI-संगत SDKs के साथ काम करता है।

#### `setup-*` से स्वचालित रूप से कॉन्फ़िगर करें

बेस URL और कुंजी को मैन्युअल रूप से पेस्ट करने के बजाय, OmniRoute को लाइव मॉडल कैटलॉग से प्रत्येक टूल की
अपनी कॉन्फ़िगरेशन लिखने दें। प्रत्येक टूल के लिए एक कमांड:

```bash
omniroute setup-codex        # ~/.codex/<name>.config.toml प्रोफ़ाइल
omniroute setup-claude       # ~/.claude/profiles/<name>/settings.json
omniroute setup-opencode     # ~/.config/opencode/opencode.json (openai-संगत)
omniroute setup-cline        # Cline CLI + VS Code एक्सटेंशन सेटिंग्स
omniroute setup-kilo         # Kilo Code
omniroute setup-continue     # ~/.continue/config.yaml (Continue / cn)
omniroute setup-cursor       # Cursor के इन-ऐप चरण प्रिंट करता है
omniroute setup-roo          # Roo Code इम्पोर्ट + autoImport पॉइंटर
omniroute setup-crush        # ~/.config/crush/crush.json
omniroute setup-goose        # ~/.config/goose/config.yaml
omniroute setup-aider        # ~/.aider.conf.yml
omniroute setup-qwen         # ~/.qwen/settings.json + ~/.qwen/.env
```

स्थानीय टूल को किसी **रिमोट** OmniRoute के लिए कॉन्फ़िगर करने हेतु प्रत्येक कमांड `--remote <url> --api-key <key>` स्वीकार करता है, और पूर्वावलोकन के लिए `--dry-run` भी स्वीकार करता है। सही
env इंजेक्ट करके और बिना कोई कॉन्फ़िगरेशन लिखे CLI लॉन्च करने के लिए सामान्य लॉन्चर
`omniroute run <target>` (claude, codex, aider, goose, opencode, qwen, gemini) का उपयोग करें;
पुराने प्रति-टूल लॉन्चर `omniroute launch` (Claude Code) और
`omniroute launch-codex` (Codex) अभी भी उपलब्ध हैं।

पूरी तालिका (प्रत्येक कमांड क्या लिखता है, हर फ़्लैग, स्थानीय बनाम रिमोट, बेस-URL
`/v1` परंपराएँ) के लिए, **[CLI इंटीग्रेशन](./CLI-INTEGRATIONS.md)** देखें।

प्रत्येक टूल की विस्तृत कॉन्फ़िगरेशन (Claude Code, Codex CLI, Cursor, Cline, OpenClaw, Kilo Code, Copilot और अन्य) के लिए, समर्पित **[CLI टूल्स गाइड](../reference/CLI-TOOLS.md)** देखें।

## प्रोटोकॉल सेटअप (MCP + A2A)

### MCP सेटअप (Model Context Protocol)

MCP ट्रांसपोर्ट को stdio मोड में शुरू करें:

```bash
omniroute --mcp
```

अनुशंसित सत्यापन प्रवाह:

```bash
# 1. MCP सर्वर शुरू करें
omniroute --mcp

# 2. अपने MCP क्लाइंट से इन्हें कॉल करें:
omniroute_get_health        # सिस्टम की स्थिति लौटानी चाहिए
omniroute_list_combos       # सक्रिय कॉम्बो लौटाने चाहिए

# 3. या पूरा E2E सूट चलाएँ:
npm run test:protocols:e2e
```

#### MCP क्लाइंट कॉन्फ़िगरेशन

**Claude Code:**

```bash
claude mcp add-server omniroute --type http --url http://localhost:20128/api/mcp/stream
```

**Cursor / Cline:**

अपनी MCP सेटिंग्स में जोड़ें:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"],
      "env": {}
    }
  }
}
```

**संपूर्ण MCP दस्तावेज़ीकरण:** [MCP Server README](../../open-sse/mcp-server/README.md) — 110 टूल, IDE कॉन्फ़िगरेशन, Python/TS/Go क्लाइंट।

### A2A सेटअप (Agent-to-Agent Protocol)

Agent Card सत्यापित करें:

```bash
curl http://localhost:20128/.well-known/agent.json
```

एक कार्य भेजें:

```bash
curl -X POST http://localhost:20128/a2a \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":"quickstart","method":"message/send","params":{"skill":"quota-management","messages":[{"role":"user","content":"Give me a short quota summary."}]}}'
```

**संपूर्ण A2A दस्तावेज़ीकरण:** [A2A Server README](../../src/lib/a2a/README.md) — JSON-RPC 2.0, कौशल, स्ट्रीमिंग, कार्य जीवनचक्र।

## टाइमआउट कॉन्फ़िगरेशन

### बुनियादी टाइमआउट

अधिकांश डिप्लॉयमेंट के लिए, आपको केवल इन दो वेरिएबल की आवश्यकता होती है:

| वेरिएबल                  | डिफ़ॉल्ट                        | उद्देश्य                                                                                                                                           |
| ------------------------ | ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `REQUEST_TIMEOUT_MS`     | `600000`                        | अपस्ट्रीम रिस्पॉन्स शुरू होने के टाइमआउट, छिपे हुए Undici टाइमआउट, TLS फ़िंगरप्रिंट अनुरोधों और API ब्रिज अनुरोध/प्रॉक्सी टाइमआउट के लिए साझा आधार |
| `STREAM_IDLE_TIMEOUT_MS` | `REQUEST_TIMEOUT_MS` से प्राप्त | OmniRoute द्वारा SSE स्ट्रीम को निरस्त करने से पहले स्ट्रीमिंग चंक्स के बीच अधिकतम अंतराल                                                          |

बैकवर्ड कम्पैटिबिलिटी बरकरार रखी गई है: मौजूदा `FETCH_TIMEOUT_MS`, `API_BRIDGE_PROXY_TIMEOUT_MS` और अन्य प्रति-लेयर टाइमआउट वेरिएबल अब भी काम करते हैं और साझा आधार को ओवरराइड करते हैं।

### प्रोवाइडर-विशिष्ट टिप्पणियाँ

Claude Code-संगत अपस्ट्रीम (`anthropic-compatible-cc-*`) के लिए, OmniRoute निर्धारित फ़ेच टाइमआउट से आउटबाउंड `X-Stainless-Timeout` हेडर प्राप्त करता है, ताकि प्रोवाइडर-साइड रीड टाइमआउट आपके एनवायरनमेंट कॉन्फ़िगरेशन के अनुरूप रहें।

तृतीय-पक्ष Claude Code-संगत रिवर्स प्रॉक्सी के लिए, OmniRoute डिफ़ॉल्ट `anthropic-beta` सेट को सीमित रखता है और जब `Client Cache Control` को `Auto` पर छोड़ा जाता है, तो केवल क्लाइंट द्वारा दिए गए `cache_control` मार्कर फ़ॉरवर्ड करता है। प्रति-कनेक्शन "रीडैक्ट-थिंकिंग बीटा सक्षम करें" टॉगल केवल तभी सक्षम करें, जब अपस्ट्रीम को विशेष रूप से रीडैक्ट की गई Claude थिंकिंग स्ट्रीम की आवश्यकता हो।

### उन्नत टाइमआउट ओवरराइड

| वेरिएबल                                  | डिफ़ॉल्ट                                    | उद्देश्य                                                                       |
| ---------------------------------------- | ------------------------------------------- | ------------------------------------------------------------------------------ |
| `FETCH_TIMEOUT_MS`                       | `REQUEST_TIMEOUT_MS` से प्राप्त             | रिस्पॉन्स हेडर आने तक उपयोग किया जाने वाला अपस्ट्रीम रिस्पॉन्स-स्टार्ट टाइमआउट |
| `FETCH_HEADERS_TIMEOUT_MS`               | `FETCH_TIMEOUT_MS` से प्राप्त               | अपस्ट्रीम रिस्पॉन्स हेडर प्राप्त करने के लिए Undici की समय-सीमा                |
| `FETCH_BODY_TIMEOUT_MS`                  | `FETCH_TIMEOUT_MS` से प्राप्त               | अपस्ट्रीम बॉडी चंक्स के बीच Undici की समय-सीमा (`0` इसे अक्षम करता है)         |
| `FETCH_CONNECT_TIMEOUT_MS`               | `30000`                                     | Undici TCP कनेक्ट टाइमआउट                                                      |
| `FETCH_KEEPALIVE_TIMEOUT_MS`             | `4000`                                      | Undici निष्क्रिय कीप-अलाइव सॉकेट टाइमआउट                                       |
| `TLS_CLIENT_TIMEOUT_MS`                  | `FETCH_TIMEOUT_MS` से प्राप्त               | `wreq-js` के माध्यम से किए गए TLS फ़िंगरप्रिंट अनुरोधों का टाइमआउट             |
| `API_BRIDGE_PROXY_TIMEOUT_MS`            | `REQUEST_TIMEOUT_MS` या `600000` से प्राप्त | API पोर्ट से डैशबोर्ड पोर्ट तक `/v1` प्रॉक्सी फ़ॉरवर्डिंग का टाइमआउट           |
| `API_BRIDGE_SERVER_REQUEST_TIMEOUT_MS`   | `max(API_BRIDGE_PROXY_TIMEOUT_MS, 300000)`  | API ब्रिज सर्वर पर इनकमिंग अनुरोध का टाइमआउट                                   |
| `API_BRIDGE_SERVER_HEADERS_TIMEOUT_MS`   | `60000`                                     | API ब्रिज सर्वर पर इनकमिंग हेडर का टाइमआउट                                     |
| `API_BRIDGE_SERVER_KEEPALIVE_TIMEOUT_MS` | `5000`                                      | API ब्रिज सर्वर पर कीप-अलाइव टाइमआउट                                           |
| `API_BRIDGE_SERVER_SOCKET_TIMEOUT_MS`    | `0`                                         | API ब्रिज सर्वर पर सॉकेट निष्क्रियता टाइमआउट (`0` इसे अक्षम करता है)           |

> **नोट:** स्ट्रीमिंग अनुरोधों के लिए, `FETCH_TIMEOUT_MS` केवल कनेक्शन सेटअप / पहले अपस्ट्रीम रिस्पॉन्स की प्रतीक्षा को कवर करता है। स्ट्रीम सक्रिय होने के बाद, OmniRoute केवल वास्तविक रुकावट (`STREAM_IDLE_TIMEOUT_MS`) या Undici बॉडी निष्क्रियता (`FETCH_BODY_TIMEOUT_MS`) की स्थिति में ही इसे निरस्त करेगा।

### रिवर्स प्रॉक्सी संगतता

यदि आप OmniRoute को Nginx, Caddy, Cloudflare या किसी अन्य रिवर्स प्रॉक्सी के पीछे चलाते हैं, तो सुनिश्चित करें कि प्रॉक्सी टाइमआउट भी आपके OmniRoute स्ट्रीम/फ़ेच टाइमआउट से अधिक हों।

## स्प्लिट-पोर्ट मोड

उन्नत परिदृश्यों (रिवर्स प्रॉक्सी, कंटेनर नेटवर्किंग) के लिए API और डैशबोर्ड को अलग-अलग पोर्ट पर चलाएँ:

```bash
PORT=20128 DASHBOARD_PORT=20129 omniroute
# API:       http://localhost:20128/v1
# डैशबोर्ड: http://localhost:20129
```

## Void Linux (`xbps-src`) टेम्पलेट

Void Linux उपयोगकर्ता `xbps-src` का उपयोग करके एक नेटिव पैकेज बना सकते हैं। इस ब्लॉक को `srcpkgs/omniroute/template` के रूप में सहेजें:

```bash
# 'omniroute' के लिए टेम्पलेट फ़ाइल
pkgname=omniroute
version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"
maintainer="zenobit <zenobit@disroot.org>"
license="MIT"
homepage="https://github.com/diegosouzapw/OmniRoute"
distfiles="https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz"
# प्रत्येक रिलीज़ के लिए चेकसम को इसके साथ पुनः जनरेट करें:
#   curl -L -o /tmp/omniroute.tar.gz "https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz" && sha256sum /tmp/omniroute.tar.gz
checksum=PLACEHOLDER_REGENERATE_PER_RELEASE
system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	NODE_ENV=development npm ci --ignore-scripts
	npm run build
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	rm -rf .next/standalone/node_modules/@img

	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
		touch "${DESTDIR}/usr/lib/omniroute/${_d}/.keep"
	done

	cat > "${WRKDIR}/omniroute" <<'EOF'
#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"
mkdir -p "${DATA_DIR}"
exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```

## अनइंस्टॉल करना

| कमांड                    | कार्रवाई                                                                                               |
| ------------------------ | ------------------------------------------------------------------------------------------------------ |
| `npm run uninstall`      | सिस्टम ऐप को हटाता है, लेकिन `~/.omniroute` में मौजूद **आपके DB और कॉन्फ़िगरेशन को सुरक्षित रखता है**। |
| `npm run uninstall:full` | ऐप को हटाता है और **सभी कॉन्फ़िगरेशन, कुंजियों तथा डेटाबेस को स्थायी रूप से मिटा देता है**।            |

> सभी विधियों के लिए विस्तृत अनइंस्टॉल निर्देशों हेतु [UNINSTALL.md](./UNINSTALL.md) देखें।
