OmniRoute, OpenAI Codex का उपयोग करने के **दो** तरीके उपलब्ध कराता है:

| प्रदाता                | यह OpenAI से कैसे संचार करता है                                                                                                                                                                                                  | उपयोग संबंधी चेतावनी                                                |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| **`codex`**            | आपके ChatGPT/OpenAI OAuth टोकन को सीधे Responses API पर रीप्ले करता है                                                                                                                                                           | **हाँ** — आधिकारिक सत्र proxy/router के उपयोग के लिए अधिकृत नहीं है |
| **`codex-app-server`** | JSON-RPC/WebSocket के माध्यम से **Codex CLI के अपने `codex app-server`** को संचालित करता है; CLI अपने OAuth (`~/.codex/auth.json`) का स्वामित्व रखता है और उसे स्वयं रीफ़्रेश करता है, बिल्कुल एक इंटरैक्टिव `codex` सत्र की तरह | **नहीं** — OmniRoute कभी भी API पर टोकन रीप्ले नहीं करता            |

चूँकि `codex-app-server` कभी भी टोकन रीप्ले नहीं करता, इसलिए इस पर
सत्र-रीप्ले उपयोग संबंधी चेतावनी लागू नहीं होती। इसके लिए **कॉन्फ़िगर किए गए
app-server URL पर पहुँच योग्य Codex CLI** आवश्यक है, और उस CLI में **साइन इन**
होना चाहिए।

## 1. आर्किटेक्चर

```
┌─ OmniRoute ऐप ──────────────────┐        ┌─ codex-app-server साइडकार ─────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ क्षमता टोकन)                 │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  OpenAI OAuth को स्वयं प्रबंधित करता है │
└──────────────────────────────────┘        │  (~/.codex/auth.json, स्वतः-रीफ़्रेश) │
        │ साझा करता है (compose volumes)    └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → WS क्षमता टोकन (दोनों इसे माउंट करते हैं)
  codex-appserver-home    → ~/.codex (auth.json को डैशबोर्ड लिखता है,
                             और साइडकार का codex app-server इसे पढ़ता है)
```

- साइडकार क्षमता टोकन के पीछे **केवल** आंतरिक compose नेटवर्क
  (`ws://codex-app-server:1456`) पर सुनता है। इसे होस्ट या इंटरनेट पर **कभी भी**
  प्रकाशित नहीं किया जाता।
- Codex CLI को `omniroute:base` में पहले से शामिल किया गया है, इसलिए साइडकार
  चलाते समय होस्ट या उपयोगकर्ता की मशीन पर codex इंस्टॉल करने की आवश्यकता नहीं है।

## 2. इसे शुरू करें

```bash
# codex app-server साइडकार प्रोफ़ाइल के साथ स्टैक शुरू करें:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

पहली बार बूट होने पर साइडकार अपना WS क्षमता टोकन बनाता है (साझा
`codex-appserver-token` वॉल्यूम में) और ऐप उसी टोकन को
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE` के माध्यम से पढ़ता है। टोकन को
मैन्युअल रूप से जोड़ने की आवश्यकता नहीं है।

## 3. कनेक्ट करें + साइन इन करें

1. डैशबोर्ड में **OpenAI Codex (App-Server)** के लिए एक कनेक्शन जोड़ें। किसी API
   कुंजी या टोकन की आवश्यकता नहीं है (यह no-auth प्रदाता है — प्रमाणीकरण का
   स्वामित्व साइडकार के पास है)।
2. यदि साइडकार के Codex CLI में **अभी तक साइन इन नहीं किया गया है**, तो कनेक्शन
   स्वास्थ्य जाँच _"चल रहा है, लेकिन साइन इन नहीं है"_ रिपोर्ट करती है (लाल
   प्रमाणीकरण त्रुटि नहीं)। **ChatGPT से साइन इन करें** का उपयोग करें: यह आपके
   ब्राउज़र में मानक Codex device-OAuth चलाता है और फिर **प्रमाणीकरण लागू करें**
   के माध्यम से साझा वॉल्यूम में `~/.codex/auth.json` लिखता है (एक ही लॉगिन
   `codex` और `codex-app-server`, दोनों प्रदाताओं के लिए काम करता है)।
3. साइन इन होने के बाद, स्वास्थ्य जाँच हरी हो जाती है (यह `/readyz` **और**
   `account/read`, दोनों को सत्यापित करती है — यानी सेवा चालू _और_ प्रमाणित है)
   और काम करना शुरू कर देती है।

डैशबोर्ड किसी मौजूदा स्वस्थ `~/.codex/auth.json` को कभी ओवरराइट नहीं करता —
यह केवल तब लिखता है जब फ़ाइल अनुपस्थित हो या उसका टोकन पुराना हो गया हो
(हमेशा एक बैकअप लिया जाता है)।

## 4. डिप्लॉयमेंट परिदृश्य

- **पहले से प्रमाणित Codex CLI वाला ऑपरेटर** — अपने होस्ट के
  `~/.codex` को साइडकार (`codex-appserver-home`) में माउंट करें और साइन-इन चरण
  छोड़ दें।
- **सार्वजनिक उपयोगकर्ता, स्थानीय रूप से codex इंस्टॉल नहीं है** — इससे कोई
  फ़र्क नहीं पड़ता: साइडकार में CLI मौजूद है। उपयोगकर्ता केवल डैशबोर्ड के
  माध्यम से प्रमाणीकरण करता है।
- **बेयर-मेटल OmniRoute (कोई साइडकार नहीं, होस्ट codex)** — अपने स्वयं के
  `codex app-server` की ओर `OMNIROUTE_CODEX_APPSERVER_WS` को इंगित करें और
  सुनिश्चित करें कि होस्ट codex में साइन इन किया गया है; यदि बाइनरी अनुपस्थित
  है, तो "codex इंस्टॉल नहीं है" संकेत दिखाई देता है।

## 5. रेज़िडेंशियल / UDP इग्रेस (ऑपरेटर के लिए अतिरिक्त, साथ में उपलब्ध नहीं)

ऊपर दिया गया सामान्य साइडकार कंटेनर के सामान्य नेटवर्क से इग्रेस करता है। जिस
ऑपरेटर को Codex ट्रैफ़िक को **रेज़िडेंशियल एग्ज़िट** के माध्यम से इग्रेस कराने
की आवश्यकता हो (उदाहरण के लिए TCP + UDP/QUIC ले जाने वाला TUN tailscale
साइडकार), वह इसे एक अलग compose ओवरराइड के रूप में चलाता है; इसे जानबूझकर
उपलब्ध कराई गई `codex-app-server` प्रोफ़ाइल का हिस्सा **नहीं** बनाया गया है।
उस सेटअप के लिए आंतरिक संचालन रनबुक देखें।
