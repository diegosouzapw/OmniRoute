`@omniroute/opencode-plugin-v2` आपके पूरे OmniRoute कैटलॉग — मॉडल, कॉम्बो और
ऑटो-कॉम्बो — को डिस्प्ले नामों, मूल्य निर्धारण और फ़्री-टियर
बजट के साथ OpenCode v2 के मॉडल पिकर में उपलब्ध कराता है।

यह `@omniroute/opencode-plugin` से अलग पैकेज है, क्योंकि OpenCode v1 और v2
प्लगइन को अलग-अलग अनुबंधों के माध्यम से लोड करते हैं। अपने OpenCode के प्रमुख संस्करण से मेल खाने वाला पैकेज चुनें;
इनके बीच कुछ भी साझा नहीं होता, इसलिए एक को अपग्रेड करने से दूसरे को अपग्रेड करना आवश्यक नहीं होता।

## आवश्यकताएँ

- OpenCode v2।
- पहुँच योग्य OmniRoute गेटवे (डिफ़ॉल्ट रूप से `http://localhost:20128`)।
- Node.js 22 या 24।

## इंस्टॉल करना

प्लगइन को `opencode.json` में जोड़ें:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

इसके बाद मॉडल `omniroute/<provider>/<model>` के रूप में दिखाई देते हैं; `providerId` उस प्रीफ़िक्स और
उस इंटीग्रेशन की id निर्धारित करता है जिसके अंतर्गत OpenCode क्रेडेंशियल संग्रहीत करता है।

## क्रेडेंशियल

प्लगइन निम्नलिखित तीन स्थानों पर इसी क्रम में गेटवे कुंजी खोजता है:

1. **वह क्रेडेंशियल जिसे आपने OpenCode में कनेक्ट किया है।** प्लगइन एक इंटीग्रेशन पंजीकृत करता है, इसलिए
   OpenCode का अपना प्रमाणीकरण प्रवाह कुंजी को संग्रहीत कर सकता है। `opencode.json` में कुछ भी नहीं जाता — इसे प्राथमिकता दें।
2. हर प्रोजेक्ट के लिए अलग ओवरराइड हेतु प्लगइन विकल्पों में `apiKey`। इससे कुंजी ऐसी फ़ाइल में आ जाती है
   जिसे आप कमिट कर सकते हैं।
3. एनवायरनमेंट में `OMNIROUTE_API_KEY`।

इन तीनों में से कोई भी उपलब्ध न होने पर कैटलॉग खाली रहता है और प्लगइन मौन रूप से खाली पिकर
छोड़ने के बजाय स्टार्टअप के समय एक बार इसकी सूचना देता है।

### मैनेजमेंट टोकन एक अलग कुंजी है

कॉम्बो, प्रोवाइडर की स्थिति और संवर्धन (डिस्प्ले नाम, मूल्य निर्धारण, फ़्री-टियर बजट)
गेटवे के `/api/*` एंडपॉइंट से आते हैं, जिन्हें अधिकांश डिप्लॉयमेंट इन्फ़रेंस कुंजी के बजाय
**मैनेजमेंट** टोकन से सुरक्षित करते हैं:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<management read token>"
}
```

सेट न होने पर `managementReadToken`, `apiKey` पर फ़ॉलबैक करता है। जब कोई गेटवे उस फ़ॉलबैक को
अस्वीकार करता है, तब भी कैटलॉग प्रकाशित होता है, लेकिन उसमें डिस्प्ले नामों के बजाय मूल मॉडल id होते हैं,
कैनोनिकल एलियस का डीडुप्लिकेशन नहीं होता, मूल्य निर्धारण नहीं होता और कॉम्बो भी नहीं होते। ऐसा होने पर प्लगइन हर
एंडपॉइंट के लिए एक बार चेतावनी देता है, जिसमें एंडपॉइंट और अनुपलब्ध हुई जानकारी का उल्लेख होता है — इसलिए सीमित
क्षमता वाला पिकर कभी रहस्य नहीं रहता।

## विकल्प

| कुंजी                            | डिफ़ॉल्ट                                             | टिप्पणियाँ                                                                                                                 |
| -------------------------------- | ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `providerId`                     | `"omniroute"`                                        | प्रोवाइडर id, इंटीग्रेशन id और वह प्रीफ़िक्स जिसके अंतर्गत मॉडल दिखाई देते हैं                                             |
| `baseURL`                        | आवश्यक                                               | गेटवे रूट, केवल `http(s)`; जहाँ आवश्यक हो वहाँ `/v1` सफ़िक्स जोड़ा जाता है                                                 |
| `apiKey`                         | कनेक्ट किया गया क्रेडेंशियल, फिर `OMNIROUTE_API_KEY` | `/v1/*` के लिए चैट कुंजी                                                                                                   |
| `managementReadToken`            | `apiKey` पर फ़ॉलबैक करता है                          | `/api/*` के लिए कुंजी — आम तौर पर यह **वही** कुंजी नहीं होती                                                               |
| `displayName`                    | `"OmniRoute"`                                        | पिकर में प्रोवाइडर का नाम                                                                                                  |
| `timeoutMs`                      | `10000`                                              | प्रत्येक एंडपॉइंट के लिए फ़ेच टाइमआउट (ऑटो-कॉम्बो 5s का उपयोग करते हैं)                                                    |
| `modelCacheTtlMs`                | `300000`                                             | कैटलॉग कैश TTL; डिस्क स्नैपशॉट कोल्ड स्टार्ट को तेज़ करता है                                                               |
| `timeouts`                       | `timeoutMs` पर फ़ॉलबैक करता है                       | ms में प्रत्येक एंडपॉइंट का बजट: `models`, `combos`, `autoCombos`, `enrichment`                                            |
| `enrichment`                     | `true`                                               | नाम, मूल्य निर्धारण और फ़्री-टियर बजट प्राप्त करें                                                                         |
| `providerTag`                    | `true`                                               | डिस्प्ले नाम के आगे उस अपस्ट्रीम प्रोवाइडर का नाम जोड़ें जिस पर यह रूट करता है                                             |
| `usableOnly`                     | `false`                                              | केवल उन्हीं प्रोवाइडर को रखें जिन्हें गेटवे प्रोविज़न्ड के रूप में रिपोर्ट करता है                                         |
| `visibleModels` / `hiddenModels` | `[]`                                                 | सटीक-या-सफ़िक्स अनुमति सूचियाँ; निषेध को प्राथमिकता मिलती है                                                               |
| `geminiSanitization`             | `true`                                               | टूल स्कीमा से वे JSON-Schema कीवर्ड हटाएँ जिन्हें Gemini अस्वीकार करता है (`$ref` टूल बिना बदलाव के फ़ॉरवर्ड किए जाते हैं) |
| `apiFormat.allowAnthropic`       | `false`                                              | अनुमति सूची में शामिल id को Anthropic API ब्लॉक के माध्यम से रूट करें                                                      |
| `apiFormat.anthropicModels`      | `[]`                                                 | Anthropic पर रूट किए जाने वाले पूर्ण मॉडल id                                                                               |
| `logLevel` / `startupDebug`      | `warn` / `false`                                     | लॉगर की विवरण-प्रचुरता                                                                                                     |

## कैटलॉग कैसे नवीनतम बना रहता है

कैटलॉग को आवश्यकता पड़ने पर फ़ेच किया जाता है और `modelCacheTtlMs` की अवधि तक कैश किया जाता है, तथा डिस्क स्नैपशॉट अंतिम ज्ञात कैटलॉग को तब भी उपलब्ध रखता है जब गेटवे तक नहीं पहुँचा जा सकता — आउटेज में आपको केवल नवीनता का नुकसान होता है। मॉडल और कॉम्बो आते ही प्रकाशित कर दिए जाते हैं; ऑटो-कॉम्बो, प्रदाता सूची और एनरिचमेंट ओवरले उपलब्ध होते ही शामिल हो जाते हैं, ताकि कोई धीमा एंडपॉइंट पूरे पिकर को बाधित न कर सके।

नामों में गेटवे को ज्ञात जानकारी शामिल होती है: वह अपस्ट्रीम प्रदाता जिस पर मॉडल रूट होता है, एक `[Free]` मार्कर और उसके साथ मिलने वाला बजट — इसलिए एक ही मॉडल बेचने वाले दो कनेक्शन अलग पहचाने जा सकते हैं। `"providerTag": false` से प्रीफ़िक्स बंद करें।

कोई मैन्युअल रीफ़्रेश कमांड नहीं है: OpenCode v2 कमांड प्रॉम्प्ट टेम्पलेट हैं, कॉलबैक नहीं, इसलिए प्लगइन ऐसा कमांड उपलब्ध नहीं करा सकता। रीफ़्रेश TTL के अनुसार होते हैं; होस्ट से केवल तभी रीलोड करने को कहा जाता है जब कैटलॉग या ओवरले वास्तव में बदला हो, हर रीफ़्रेश पर नहीं।

## Gemini पर टूल कॉलिंग

Gemini ऐसे पूरे अनुरोध को अस्वीकार कर देता है जिसके टूल डिक्लेरेशन में `$schema` या `additionalProperties` हों, और `400 INVALID_ARGUMENT` लौटाता है। प्लगइन इस प्रदाता के Gemini मॉडल को भेजे जाने वाले टूल स्कीमा से उन कीवर्ड को हटा देता है और प्रत्येक अन्य अनुरोध को अपरिवर्तित छोड़ता है। `$ref` वाला टूल हटाने की प्रक्रिया के बजाय अपरिवर्तित फ़ॉरवर्ड किया जाता है, क्योंकि रेफ़रेंस हटाने से स्कीमा का दायरा बढ़कर "कुछ भी स्वीकार करें" हो जाएगा।
इसे बंद करने के लिए `"geminiSanitization": false` सेट करें।

## समस्या निवारण

| लक्षण                                                         | कारण                                                                                                                        |
| ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| पिकर कोई OmniRoute मॉडल नहीं दिखाता                           | कोई कुंजी नहीं मिली (स्टार्टअप चेतावनी जाँचें), या गेटवे तक नहीं पहुँचा जा सकता                                             |
| अपरिष्कृत मॉडल आईडी, कोई कॉम्बो नहीं, कोई मूल्य निर्धारण नहीं | प्रबंधन एंडपॉइंट ने टोकन अस्वीकार कर दिया — `managementReadToken` सेट करें                                                  |
| `opencode-<id>/…` पर पिन किया गया सत्र                        | v1 प्लगइन ने `opencode-<id>` प्रकाशित किया था; v2 केवल `<id>` प्रकाशित करता है, इसलिए `<id>/…` के अंतर्गत मॉडल फिर से चुनें |
