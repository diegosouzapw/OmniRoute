## यह क्या है

OmniRoute एक **Obsidian** वॉल्ट से **संदर्भ स्रोत** के रूप में जुड़ता है — एक स्थानीय Markdown
ज्ञान आधार, जिसे एजेंट अंतर्निहित MCP सर्वर के माध्यम से पढ़ते और लिखते हैं। यह
एकीकरण डेस्कटॉप ऐप के भीतर चल रहे **Obsidian Local REST API** कम्युनिटी प्लगइन से संचार करता है,
जिससे एजेंट नोट खोज सकते हैं, फ़ाइलें पढ़/लिख/पैच कर सकते हैं, वॉल्ट की सूची देख सकते हैं, दैनिक/साप्ताहिक
आवधिक नोट्स के साथ काम कर सकते हैं, टैग प्रबंधित कर सकते हैं, Obsidian कमांड चला सकते हैं और (वैकल्पिक रूप से)
द्विदिशात्मक डेस्कटॉप↔मोबाइल वॉल्ट सिंक का समन्वय कर सकते हैं।

क्लाइंट (`src/lib/obsidian/api.ts`) Local REST API को निम्न सुविधाओं के साथ रैप करता है:

- अस्थायी `5xx` त्रुटियों के लिए **बैकऑफ़ के साथ पुनः प्रयास**, `AbortController` के माध्यम से **30-सेकंड की टाइमआउट**।
- **टाइप-आधारित त्रुटि वर्गीकरण** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`।
- एक **उपयोगकर्ता-अनुकूल "Obsidian तक नहीं पहुँचा जा सकता" संकेत**, जो पोर्ट से जुड़ी सामान्य गलती
  (HTTP के लिए `27123`, `27124` पर MCP एंडपॉइंट **नहीं**) और Tailscale प्रारूप को स्पष्ट करता है।
- वॉल्ट-सापेक्ष **पाथ एन्कोडिंग**, ताकि रिक्त स्थान/स्लैश वाले नोट पाथ सुरक्षित रहें।

## सेटअप

Obsidian टोकन या बेस URL के लिए **कोई एनवायरनमेंट वेरिएबल नहीं है** — दोनों को
`src/lib/db/obsidian.ts` के माध्यम से SQLite `key_value` तालिका (नेमस्पेस `obsidian`) में
संग्रहीत किया जाता है। टोकन **स्थिर अवस्था में एन्क्रिप्टेड** रहता है (AES-256-GCM, प्लेनटेक्स्ट
पश्च-संगतता फ़ॉलबैक के साथ)। इसे Endpoint डैशबोर्ड के **Context Sources** टैब
(`ObsidianSourceCard`) से या सेटिंग्स REST API के माध्यम से कॉन्फ़िगर करें।

> [!IMPORTANT]
> **Obsidian Local REST API** प्लगइन इंस्टॉल और चालू होना चाहिए। इसका REST
> इंटरफ़ेस **HTTP `127.0.0.1:27123`** (डिफ़ॉल्ट बेस URL) पर सुनता है। पोर्ट `27124`
> एक _अलग_ MCP/HTTPS एंडपॉइंट है और सेटिंग्स रूट द्वारा स्पष्ट रूप से अस्वीकार किया जाता है।
> किसी अन्य डिवाइस से कनेक्ट करते समय `http://<tailscale-ip>:27123` का उपयोग करें।

### कॉन्फ़िगरेशन कुंजियाँ (SQLite `key_value`, नेमस्पेस `obsidian`)

| कुंजी             | उद्देश्य                                          | एन्क्रिप्टेड |
| ----------------- | ------------------------------------------------- | ------------ |
| `api_key`         | Local REST API बेयरर टोकन                         | हाँ          |
| `base_url`        | REST बेस URL (डिफ़ॉल्ट `http://127.0.0.1:27123`)  | नहीं         |
| `vault_path`      | वॉल्ट डायरेक्टरी का पूर्ण पाथ (सिंक के लिए)       | नहीं         |
| `webdav_username` | जनरेट किया गया WebDAV उपयोगकर्ता नाम (वॉल्ट सिंक) | नहीं         |
| `webdav_password` | जनरेट किया गया WebDAV पासवर्ड (वॉल्ट सिंक)        | हाँ          |
| `webdav_enabled`  | WebDAV वॉल्ट सिंक सक्षम है या नहीं                | नहीं         |

### REST के माध्यम से कॉन्फ़िगर करें

```bash
# Local REST API टोकन सहेजें + सत्यापित करें (POST स्थिति जाँच के माध्यम से सत्यापन करता है)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# कनेक्शन स्थिति जाँचें (connected, hasToken, baseUrl, vaultPath लौटाता है)
curl http://localhost:20128/api/settings/obsidian

# डिस्कनेक्ट करें (संग्रहीत टोकन हटाता है)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

सभी विधियों के लिए डैशबोर्ड प्रमाणीकरण आवश्यक है। `POST`, पोर्ट `27124` वाले किसी भी URL को
अस्वीकार करता है और सहेजने से पहले Local REST API स्थिति एंडपॉइंट को कॉल करके टोकन सत्यापित करता है।

### WebDAV वॉल्ट सिंक

`src/app/api/settings/obsidian/webdav/route.ts`, एक वैकल्पिक WebDAV-समर्थित
वॉल्ट सिंक (`src/lib/obsidianSync.ts` द्वारा संचालित) प्रबंधित करता है। इसे सक्षम करने पर OmniRoute को
स्थानीय वॉल्ट डायरेक्टरी पर इंगित किया जाता है और एक यादृच्छिक WebDAV उपयोगकर्ता नाम/पासवर्ड जोड़ी बनाई जाती है:

```bash
# किसी वॉल्ट डायरेक्टरी के लिए WebDAV सिंक सक्षम करें (उपयोगकर्ता नाम/पासवर्ड बनाता है)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# WebDAV सिंक स्थिति प्राप्त करें (क्रेडेंशियल केवल सक्षम रहने के दौरान लौटाए जाते हैं)
curl http://localhost:20128/api/settings/obsidian/webdav

# WebDAV सिंक अक्षम करें (क्रेडेंशियल + प्रबंधित .stignore हटाता है)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### प्रति-API-कुंजी संदर्भ स्रोत (वैकल्पिक)

Obsidian कॉन्फ़िगरेशन को `api_key_context_sources` तालिका
(`src/lib/db/apiKeyContextSources.ts`) के माध्यम से **प्रति API कुंजी** स्कोप किया जा सकता है। जब कोई MCP कॉल एक प्रमाणित API
कुंजी id के साथ आती है, तो `getObsidianConfigForApiKey()` उस कुंजी के अपने टोकन/बेस-URL/वॉल्ट-पाथ
(`source: "api_key"`) को प्राथमिकता देता है और अन्यथा वैश्विक कॉन्फ़िगरेशन (`source: "global"`) पर फ़ॉलबैक करता है।

## MCP टूल्स (22)

`open-sse/mcp-server/tools/obsidianTools.ts` में परिभाषित। टोकन/base-URL को
प्रत्येक कॉल के लिए हल किया जाता है (पहले प्रति-API-key, फिर ग्लोबल)। OmniRoute **sync server**
से संपर्क करने वाले टूल्स (चार `obsidian_sync_*` टूल्स) को इसके अतिरिक्त OmniRoute सेटिंग्स
में कॉन्फ़िगर किए गए sync auth token की आवश्यकता होती है।

### रीड टूल्स (`read:obsidian`)

| टूल                          | विवरण                                                                                         |
| ---------------------------- | --------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | जाँचें कि Local REST API पहुँच योग्य और प्रमाणीकृत है या नहीं।                                |
| `obsidian_search_simple`     | नोट सामग्री में पूर्ण-पाठ खोज; file paths सहित स्निपेट लौटाता है।                             |
| `obsidian_search_structured` | JSON Logic एक्सप्रेशन (and/or/regex/path फ़िल्टर्स) का उपयोग करके खोजें।                      |
| `obsidian_read_note`         | vault-relative path द्वारा नोट पढ़ें; वैकल्पिक रूप से कोई विशिष्ट heading/block/frontmatter।  |
| `obsidian_list_vault`        | vault में फ़ाइलों और डायरेक्टरीज़ को सूचीबद्ध करें (एंट्रीज़ का ट्री)।                        |
| `obsidian_get_document_map`  | नोट की heading संरचना को headings → line numbers के मैप के रूप में प्राप्त करें।              |
| `obsidian_get_note_metadata` | पूर्ण सामग्री के बिना frontmatter, टैग्स, लिंक्स और char/word count प्राप्त करें।             |
| `obsidian_get_active_file`   | Obsidian में वर्तमान में सक्रिय फ़ाइल का path + content प्राप्त करें।                         |
| `obsidian_get_periodic_note` | किसी तारीख़ के लिए दैनिक/साप्ताहिक/मासिक periodic note प्राप्त करें (छोड़ने पर आज की तारीख़)। |
| `obsidian_get_tags`          | सभी vault tags को उनकी frequencies के साथ सूचीबद्ध करें।                                      |
| `obsidian_list_commands`     | उपलब्ध Obsidian command IDs सूचीबद्ध करें (`obsidian_execute_command` के साथ उपयोग करें)।     |
| `obsidian_sync_status`       | OmniRoute sync server की स्थिति: चालू, vault name, port, uptime, अंतिम sync।                  |
| `obsidian_sync_conflicts`    | अनसुलझे sync conflicts सूचीबद्ध करें (path, conflict path, detected-at)।                      |

### राइट टूल्स (`write:obsidian`)

| टूल                              | विवरण                                                                                |
| -------------------------------- | ------------------------------------------------------------------------------------ |
| `obsidian_write_note`            | दी गई Markdown सामग्री के साथ नोट बनाएँ या ओवरराइट करें।                             |
| `obsidian_append_note`           | नोट में सामग्री जोड़ें; वैकल्पिक रूप से किसी विशिष्ट heading/block में।              |
| `obsidian_patch_note`            | किसी heading, block या frontmatter field पर सटीक रूप से append/prepend/replace करें। |
| `obsidian_delete_note`           | vault से किसी नोट को स्थायी रूप से हटाएँ।                                            |
| `obsidian_move_note`             | vault के भीतर किसी नोट को स्थानांतरित करें या उसका नाम बदलें।                        |
| `obsidian_execute_command`       | किसी Obsidian command को उसकी command ID द्वारा निष्पादित करें।                      |
| `obsidian_open_file`             | Obsidian में कोई फ़ाइल खोलें (यदि वह मौजूद नहीं है, तो उसे बनाता है)।                |
| `obsidian_sync_trigger`          | तत्काल द्विदिशात्मक desktop↔mobile vault sync ट्रिगर करें।                           |
| `obsidian_sync_resolve_conflict` | sync conflict हल करें: `local` (mobile), `remote` (desktop), या `keep-both` रखें।    |

> [!NOTE]
> `obsidian_patch_note` targets, `heading | block | frontmatter` के `targetType`
> और `append | prepend | replace` के `operation` को स्वीकार करते हैं, साथ ही वैकल्पिक
> `createTargetIfMissing`। चार `obsidian_sync_*` टूल्स स्थानीय sync
> server (डिफ़ॉल्ट रूप से `http://127.0.0.1:27781`) से संपर्क करते हैं और उन्हें sync token की आवश्यकता होती है।

### स्कोप्स

रीड टूल्स के लिए `read:obsidian` आवश्यक है; राइट टूल्स के लिए `write:obsidian` आवश्यक है। प्रवर्तन
Notion के समान है — इसे `open-sse/mcp-server/server.ts` में `withScopeEnforcement()` द्वारा
संभाला जाता है, जो `OMNIROUTE_MCP_ENFORCE_SCOPES=true` पर निर्भर है, और अनुमत
स्कोप्स `OMNIROUTE_MCP_SCOPES` या API key के scope context से प्राप्त होते हैं। देखें
[MCP-SERVER.md](./MCP-SERVER.md)।

| `GET`    | `/api/settings/obsidian`        | `{ connected, hasToken, baseUrl, vaultPath }` लौटाएँ।         |
| `POST`   | `/api/settings/obsidian`        | टोकन सहेजें + सत्यापित करें (पोर्ट `27124` अस्वीकार करता है)। |
| `DELETE` | `/api/settings/obsidian`        | डिस्कनेक्ट करें (संग्रहीत टोकन साफ़ करें)।                    |
| `GET`    | `/api/settings/obsidian/webdav` | WebDAV सिंक स्थिति + क्रेडेंशियल (सक्षम रहने के दौरान)।       |
| `POST`   | `/api/settings/obsidian/webdav` | किसी वॉल्ट डायरेक्टरी के लिए WebDAV सिंक सक्षम करें।          |
| `DELETE` | `/api/settings/obsidian/webdav` | WebDAV सिंक अक्षम करें।                                       |

> ये डैशबोर्ड सेटिंग्स रूट हैं। वॉल्ट तक स्वयं Obsidian Local REST API
> (कॉन्फ़िगर किया गया `base_url`) और ऊपर दिए गए MCP टूल के माध्यम से पहुँचा जाता है —
> कोई सार्वजनिक `/v1` Obsidian प्रॉक्सी एंडपॉइंट नहीं है।

## उपयोग के मामले

- **वॉल्ट-आधारित उत्तर** — `obsidian_search_simple` / `obsidian_search_structured`
  और फिर `obsidian_read_note`, ताकि एजेंट आपके वास्तविक नोट्स से उत्तर दे।
- **नोट लेखन / जर्नलिंग** — एजेंट आउटपुट, सारांश या दैनिक नोट्स
  (`obsidian_get_periodic_note`) को वॉल्ट में दर्ज करने के लिए `obsidian_write_note`,
  `obsidian_append_note` या सटीक बदलाव करने वाला `obsidian_patch_note`।
- **वॉल्ट नेविगेशन** — पढ़ने/लिखने से पहले संरचना का अन्वेषण करने के लिए
  `obsidian_list_vault`, `obsidian_get_document_map` और `obsidian_get_tags`।
- **Obsidian ऑटोमेशन** — एजेंट से प्लगइन/कमांड संचालित करने के लिए
  `obsidian_list_commands` + `obsidian_execute_command`; UI में कोई नोट दिखाने के लिए
  `obsidian_open_file`।
- **मोबाइल सिंक** — WebDAV सिंक सक्षम करें, फिर डेस्कटॉप↔मोबाइल का समन्वय करने और
  टकरावों को हल करने के लिए `obsidian_sync_trigger` / `obsidian_sync_status` /
  `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict` का उपयोग करें।
