> **सत्य का स्रोत:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/`, और
> `src/app/(dashboard)/dashboard/plugins/`
> **अंतिम अपडेट:** 2026-06-28 — v3.8.40

OmniRoute में WordPress-शैली का प्लगइन सिस्टम शामिल है। प्लगइन स्व-निहित
डायरेक्टरियाँ हैं — प्रत्येक में एक `plugin.json` मैनिफ़ेस्ट और एक एंट्री फ़ाइल होती है — जो
अनुरोध पाइपलाइन (`onRequest` / `onResponse` / `onError`) और
लाइफ़साइकल इवेंट्स (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`) से जुड़ती हैं।

**प्लगइन मार्केटप्लेस** उस सिस्टम के ऊपर बनी डिस्कवरी लेयर है। यह
इंस्टॉल किए जा सकने वाले प्लगइन्स की ब्राउज़ करने योग्य कैटलॉग उपलब्ध कराती है। डिफ़ॉल्ट रूप से कैटलॉग एक
छोटी अंतर्निहित सीड रजिस्ट्री होती है; कोई ऑपरेटर इसे कस्टम रिमोट
रजिस्ट्री URL पर इंगित कर सकता है, ऐसी स्थिति में फ़ेच को DNS-रिज़ॉल्विंग SSRF गार्ड द्वारा
सुरक्षित बनाया जाता है ([सुरक्षा](#security) देखें)।

प्रत्येक प्लगइन रूट **केवल लूपबैक** है (Tier 1 — `LOCAL_ONLY`): प्लगइन्स चाइल्ड प्रोसेसेज़ में
कोड लोड और निष्पादित करते हैं, इसलिए प्रमाणीकरण की परवाह किए बिना ये रूट किसी भी
गैर-लूपबैक मूल से पहुँच योग्य नहीं हैं। देखें
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md)।

## यह सब एक साथ कैसे काम करता है

```
डैशबोर्ड (/dashboard/plugins)
  ├─ "इंस्टॉल किए गए" टैब → GET /api/plugins            (listPlugins)
  │                         POST /api/plugins/scan      (pluginManager.scan)
  │                         POST /api/plugins/{name}/activate|deactivate
  │                         DELETE /api/plugins/{name}   (अनइंस्टॉल)
  └─ "मार्केटप्लेस" टैब   → GET /api/plugins/marketplace
                              → listMarketplacePlugins()
                                ├─ कोई कस्टम URL नहीं → अंतर्निहित SEED_REGISTRY
                                └─ कस्टम URL → isSafeMarketplaceUrl() SSRF गार्ड
                                              → safeOutboundFetch(guard:"public-only")
```

- **रजिस्ट्री लेयर** — `src/lib/plugins/marketplace.ts`: कैटलॉग को सूचीबद्ध करता / खोजता है और
  किसी भी विफलता पर सीड रजिस्ट्री का उपयोग करता है।
- **लाइफ़साइकल लेयर** — `src/lib/plugins/manager.ts` (`pluginManager` सिंगलटन):
  इंस्टॉल, अपग्रेड, सक्रिय, निष्क्रिय, अनइंस्टॉल, स्कैन और स्टार्टअप लोड।
- **मैनिफ़ेस्ट लेयर** — `src/lib/plugins/manifest.ts`: `plugin.json` के लिए Zod स्कीमा + डिफ़ॉल्ट।
- **स्कैनर** — `src/lib/plugins/scanner.ts`: प्लगइन डायरेक्टरी के अंतर्गत डिस्क पर
  प्लगइन्स खोजता है।
- **लोडर** — `src/lib/plugins/loader.ts`: प्रत्येक प्लगइन को एक पृथक
  चाइल्ड प्रोसेस में शुरू करता है और IPC पर हुक कॉल्स की मध्यस्थता करता है।

## मार्केटप्लेस कैटलॉग

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`)
`MarketplaceEntry` ऑब्जेक्ट्स की एक सूची लौटाता है:

| फ़ील्ड        | प्रकार   | टिप्पणियाँ                                 |
| ------------- | -------- | ------------------------------------------ |
| `name`        | string   | kebab-case प्लगइन नाम                      |
| `version`     | string   | semver                                     |
| `description` | string   | संक्षिप्त सारांश                           |
| `author`      | string   | लेखक / संगठन                               |
| `license`     | string   | SPDX-शैली लाइसेंस आईडी                     |
| `downloadUrl` | string   | स्रोत डाउनलोड URL (रिक्त हो सकता है)       |
| `repository`  | string?  | वैकल्पिक रिपॉज़िटरी URL                    |
| `tags`        | string[] | खोज/फ़िल्टर टैग्स                          |
| `downloads`   | number   | डाउनलोड संख्या                             |
| `rating`      | number   | 0–5                                        |
| `verified`    | boolean  | क्या एंट्री सत्यापित के रूप में चिह्नित है |
| `lastUpdated` | string   | ISO-जैसी दिनांक स्ट्रिंग                   |

जब कोई कस्टम रजिस्ट्री URL कॉन्फ़िगर नहीं किया गया हो, तब कैटलॉग अंतर्निहित
`SEED_REGISTRY` होता है (वर्तमान में `request-logger`, `rate-limiter`, `cost-tracker`, और
`theme-manager`)। सीड रजिस्ट्री हमेशा उपलब्ध रहती है — यदि कॉन्फ़िगर की गई रिमोट
रजिस्ट्री पहुँच योग्य न हो, गैर-`200` स्थिति लौटाए या कोई अपरिचित
बॉडी लौटाए, तो `listMarketplacePlugins()` एक चेतावनी लॉग करता है और सीड सूची का उपयोग करता है।

> नोट: मार्केटप्लेस **कैटलॉग** (ब्राउज़/खोज) पूरी तरह से जुड़ी हुई है, लेकिन
> कैटलॉग से एक-क्लिक मार्केटप्लेस **इंस्टॉल** अभी लागू नहीं किया गया है — किसी
> मार्केटप्लेस एंट्री पर डैशबोर्ड का "इंस्टॉल करें" बटन वर्तमान में
> "जल्द आ रहा है" सूचना दिखाता है। फ़िलहाल इंस्टॉलेशन स्थानीय-पाथ इंस्टॉल
> फ़्लो (`POST /api/plugins`) और ऑन-डिस्क डिस्कवरी (`POST /api/plugins/scan`) के माध्यम से होता है।

## REST API

सभी एंडपॉइंट के लिए प्रबंधन प्रमाणीकरण (`requireManagementAuth`) आवश्यक है **और** वे
केवल लूपबैक के लिए उपलब्ध हैं — `/api/plugins` और `/api/plugins/` को
`LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`) में सूचीबद्ध किया गया है।

| एंडपॉइंट                         | विधि   | विवरण                                                             |
| -------------------------------- | ------ | ----------------------------------------------------------------- |
| `/api/plugins`                   | GET    | इंस्टॉल किए गए प्लगइन सूचीबद्ध करें (वैकल्पिक `?status=` फ़िल्टर) |
| `/api/plugins`                   | POST   | किसी निरपेक्ष स्थानीय पथ से प्लगइन इंस्टॉल करें                   |
| `/api/plugins/scan`              | POST   | प्लगइन डायरेक्टरी स्कैन करें और नए प्लगइन पंजीकृत करें            |
| `/api/plugins/marketplace`       | GET    | मार्केटप्लेस कैटलॉग प्रविष्टियाँ सूचीबद्ध करें                    |
| `/api/plugins/[name]`            | GET    | इंस्टॉल किए गए प्लगइन का विवरण प्राप्त करें                       |
| `/api/plugins/[name]`            | DELETE | प्लगइन अनइंस्टॉल करें                                             |
| `/api/plugins/[name]/activate`   | POST   | सक्रिय करें (लोड करें + हुक पंजीकृत करें)                         |
| `/api/plugins/[name]/deactivate` | POST   | निष्क्रिय करें (`onDeactivate` चलाएँ, हुक अपंजीकृत करें)          |
| `/api/plugins/[name]/config`     | GET    | प्लगइन कॉन्फ़िगरेशन + कॉन्फ़िगरेशन स्कीमा प्राप्त करें            |
| `/api/plugins/[name]/config`     | PUT    | प्लगइन कॉन्फ़िगरेशन अपडेट करें (स्कीमा के विरुद्ध सत्यापित)       |

`GET /api/plugins` का `status` फ़िल्टर इनमें से कोई एक मान स्वीकार करता है:
`installed` / `active` / `inactive` / `error`। अमान्य मान देने पर `400` लौटाया जाता है।

### इंस्टॉल किए गए प्लगइन सूचीबद्ध करें

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### किसी स्थानीय पथ से इंस्टॉल करें

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` **निरपेक्ष** होना चाहिए और उसमें `..` ट्रैवर्सल सेगमेंट या
नल बाइट नहीं हो सकते (Zod द्वारा लागू)। स्रोत डायरेक्टरी में एक मान्य
`plugin.json` होना चाहिए (या वह इसकी पैरेंट डायरेक्टरी होनी चाहिए)। सफल होने पर प्रतिक्रिया `201` और
इंस्टॉल किए गए प्लगइन की पंक्ति होती है।

### मार्केटप्लेस ब्राउज़ करें

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### प्लगइन कॉन्फ़िगरेशन अपडेट करें

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` दिए गए प्रत्येक मान को प्लगइन के
`configSchema` (मैनिफ़ेस्ट में घोषित) के विरुद्ध सत्यापित करता है: `number` फ़ील्ड `min`/`max` का पालन करते हैं,
और `select` फ़ील्ड घोषित `enum` से मेल खाने चाहिए। स्कीमा में मौजूद न होने वाली कुंजियों
को स्वीकार किया जाता है।

## कॉन्फ़िगरेशन

### प्लगइन डायरेक्टरी

प्लगइन OmniRoute डेटा डायरेक्टरी के अंतर्गत रहते हैं:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (या manifest.main जिस ओर इंगित करता हो)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) उस डायरेक्टरी को
तीन चरणों में निर्धारित करता है:

1. **`OMNIROUTE_PLUGINS_DIR`**, सेट होने पर — `HOME` का मान चाहे जो हो, इसे ज्यों का त्यों उपयोग किया जाता है। यह
   Docker/K8s के लिए स्पष्ट नियंत्रण है, जहाँ प्लगइन ट्री ऐसे पथ पर बाइंड-माउंट किया जाता है
   जिसका आमतौर पर कंटेनर की होम डायरेक्टरी से कोई संबंध नहीं होता (#11827)।
2. `<home>/.omniroute/plugins`, जहाँ `<home>` को `HOME` / `USERPROFILE`
   एनवायरनमेंट वेरिएबल से लिया जाता है।
3. `/tmp/.omniroute/plugins`, जब प्रोसेस कोई होम बिल्कुल एक्सपोर्ट नहीं करती।

निर्धारित डायरेक्टरी को स्टार्टअप पर एक बार `scanner.dir_resolved` के रूप में लॉग किया जाता है, जिसमें
प्रभावी इनपुट (`OMNIROUTE_PLUGINS_DIR`, `home`, या `no-home-fallback`) का नाम होता है — ताकि कोई इमेज
जो चुपचाप चरण 3 पर पहुँच जाती है, केवल खाली प्लगइन सूची दिखाने के बजाय इसकी जानकारी भी दे।
`POST /api/plugins/scan` वहाँ की ऐसी किसी भी सबडायरेक्टरी को खोजता और पंजीकृत करता है जिसमें मान्य
`plugin.json` मौजूद हो; यही डायरेक्टरी वह रूट भी है जिसमें
`pluginManager.install()` प्लगइन कॉपी करता है, इसलिए ओवरराइड से खोज और
इंस्टॉलेशन दोनों एक साथ स्थानांतरित होते हैं।

> **`OMNIROUTE_PLUGINS_DIR`, `OMNIROUTE_PLUGIN_PATH` नहीं है।** बाद वाले को केवल
> CLI कमांड-प्लगइन लोडर (`bin/cli/plugins.mjs`), `omniroute` सबकमांड जोड़ने वाले
> `omniroute-cmd-*` npm पैकेज खोजने के लिए पढ़ता है — इसका यहाँ वर्णित रनटाइम स्कैनर
> पर कोई प्रभाव नहीं पड़ता। उस पक्ष की जानकारी के लिए [PLUGINS.md](./PLUGINS.md) देखें।

### कस्टम मार्केटप्लेस रजिस्ट्री URL

मार्केटप्लेस कैटलॉग का स्रोत `pluginMarketplaceUrl` सेटिंग से पढ़ा जाता है
(`src/lib/plugins/marketplace.ts`, `settings.pluginMarketplaceUrl` को पढ़ता है)। जब
इसे किसी `http(s)` URL पर सेट किया जाता है, तब `listMarketplacePlugins()` उस URL को फ़ेच करता है और
या तो प्रविष्टियों की शीर्ष-स्तरीय JSON सरणी या `plugins` सरणी वाला ऑब्जेक्ट स्वीकार करता है;
स्ट्रिंग `name` के बिना प्रविष्टियों को फ़िल्टर कर दिया जाता है। सेट न होने पर (या फ़ेच के
SSRF गार्ड में विफल होने / खराब प्रतिक्रिया लौटाने पर), अंतर्निहित सीड रजिस्ट्री का
उपयोग किया जाता है।

डैशबोर्ड का "Marketplace" टैब इस URL के लिए एक फ़ील्ड दिखाता है (जिसे
`GET /api/settings` से वापस पढ़ा जाता है)।

> कार्यान्वयन संबंधी नोट: डैशबोर्ड की "Save" क्रिया
> `pluginMarketplaceUrl` को `PATCH /api/settings` पर भेजती है। इसे लिखे जाने के समय यह
> कुंजी `updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`) में घोषित नहीं है, इसलिए इस पर निर्भर होने से पहले अपने
> रिलीज़ में इसके स्थायी रूप से सहेजे जाने की पुष्टि करें — सेटिंग्स
> स्टोर में कुंजी मौजूद होने के बाद **रीड** पथ (`getSettings()` →
> `listMarketplacePlugins()`) उसका उपयोग करता है।

## सुरक्षा

### रूट टियर — केवल लूपबैक

प्लगइन स्पॉन की गई चाइल्ड प्रक्रियाओं में कोड निष्पादित करते हैं, इसलिए संपूर्ण `/api/plugins`
सतह को `LOCAL_ONLY` (टियर 1) के रूप में वर्गीकृत किया गया है। लूपबैक प्रवर्तन किसी भी प्रमाणीकरण जाँच से **पहले** बिना किसी शर्त के चलता है, इसलिए टनल के माध्यम से मशीन तक पहुँचने वाला लीक हुआ प्रबंधन टोकन भी किसी प्लगइन को इंस्टॉल, सक्रिय या अनइंस्टॉल नहीं कर सकता।
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) और
कठोर नियम #15 / #17 देखें।

### मार्केटप्लेस रजिस्ट्री SSRF सुरक्षा

कस्टम रजिस्ट्री URL हमलावर से प्रभावित हो सकने वाला कॉन्फ़िगरेशन है, इसलिए
इसे फ़ेच करने से पहले `listMarketplacePlugins()` इसे दो परतों से गुजारता है:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - ऐसी किसी भी चीज़ को अस्वीकार करता है जो `http:` / `https:` नहीं है।
   - कैनॉनिकल `isPrivateHost`
     (`src/shared/network/outboundUrlGuard.ts`) के माध्यम से स्पष्ट प्राइवेट/लूपबैक/लिंक-लोकल/ULA होस्ट (IPv4 **और** IPv6,
     जिसमें IPv4-मैप्ड भी शामिल है) को अस्वीकार करता है।
   - **दोनों** `A` और `AAAA` रिकॉर्ड रिज़ॉल्व करता है और यदि रिज़ॉल्व किया गया **कोई भी**
     पता प्राइवेट है, तो उसे अस्वीकार करता है — इससे सार्वजनिक-होस्टनेम → प्राइवेट-IP बायपास बंद हो जाता है।
   - **बंद अवस्था में विफल होता है**: DNS रिज़ॉल्यूशन विफल होने पर URL अस्वीकार कर दिया जाता है।
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`**
   (`src/shared/network/safeOutboundFetch.ts`): फ़ेच के समय केवल-सार्वजनिक URL
   सुरक्षा को फिर से लागू करता है और **रीडायरेक्ट को ब्लॉक करता है** (कोई सार्वजनिक → प्राइवेट `30x`
   पिवट नहीं)।

किसी भी परत पर विफल होने वाला URL अनुरोध को निरस्त नहीं करता — मार्केटप्लेस
चुपचाप अंतर्निहित सीड रजिस्ट्री पर वापस चला जाता है और एक चेतावनी लॉग करता है।

> इस सुरक्षा को PR #3774 में विशेष रूप से A + AAAA रिज़ॉल्व करने और
> केवल-IPv4 जाँच के बजाय कैनॉनिकल `isPrivateHost` का उपयोग करने के लिए सुदृढ़ किया गया था।

### प्लगइन निष्पादन पृथक्करण

- **प्रक्रिया पृथक्करण** — `loadPlugin()` (`src/lib/plugins/loader.ts`) प्रत्येक प्लगइन को
  एक अलग Node.js चाइल्ड प्रक्रिया में स्पॉन करता है और IPC के माध्यम से संचार करता है।
  हुक कॉल के लिए `SIGTERM` → `SIGKILL` एस्केलेशन सहित एक टाइमआउट होता है।
- **Env अनुमति-सूची** — चाइल्ड को केवल अनुमति-सूची में शामिल एनवायरनमेंट
  वेरिएबल्स का सेट मिलता है; व्यापक सेट केवल तभी दिया जाता है जब मैनिफ़ेस्ट
  `env` अनुमति का अनुरोध करता है।
- **पथ परिसीमन** — इंस्टॉल/अपग्रेड/अनइंस्टॉल यह सुनिश्चित करते हैं कि प्लगइन
  डायरेक्टरी और `manifest.main`, किसी भी कॉपी या रिकर्सिव डिलीट से पहले, प्रबंधित प्लगइन रूट के **भीतर** रिज़ॉल्व हों (यह छेड़छाड़ किए गए DB पथों और
  `manifest.main` में `../` ट्रैवर्सल से सुरक्षा देता है)। सक्रियण `realpath` के माध्यम से सिमलिंक रिज़ॉल्व करता है और प्लगइन
  डायरेक्टरी से बाहर जाने वाले एंट्री पॉइंट को लोड करने से मना करता है।
- **वैकल्पिक इंटीग्रिटी पिन** — मैनिफ़ेस्ट एक `integrity`
  (`sha256-<base64>`, SRI प्रारूप) फ़ील्ड घोषित कर सकता है। मौजूद होने पर, लोडर
  लोड के समय एंट्री फ़ाइल हैश सत्यापित करता है और बेमेल होने पर सक्रिय करने से मना करता है। यह
  ऑप्ट-इन छेड़छाड़-पहचान है, सुरक्षा सीमा **नहीं** — केवल-लूपबैक रूटिंग
  और अनुमति मॉडल वास्तविक सीमाएँ हैं।

## मैनिफ़ेस्ट (`plugin.json`)

`PluginManifestSchema` (`src/lib/plugins/manifest.ts`) द्वारा सत्यापित:

| फ़ील्ड             | प्रकार    | टिप्पणियाँ                                                        |
| ------------------ | --------- | ----------------------------------------------------------------- |
| `name`             | string    | आवश्यक; kebab-case (`^[a-z0-9-]+$`), 1–100 वर्ण                   |
| `version`          | string    | आवश्यक; semver (`MAJOR.MINOR.PATCH`)                              |
| `description`      | string?   | ≤ 500 वर्ण                                                        |
| `author`           | string?   | ≤ 200 वर्ण                                                        |
| `license`          | string?   | डिफ़ॉल्ट `MIT`                                                    |
| `main`             | string?   | एंट्री फ़ाइल; डिफ़ॉल्ट `index.js`                                 |
| `source`           | enum?     | `local` \| `marketplace` (डिफ़ॉल्ट `local`)                       |
| `tags`             | string[]? | खोज टैग                                                           |
| `requires`         | object?   | `{ omniroute?, permissions[] }`                                   |
| `hooks`            | object?   | बूलियन जो घोषित करते हैं कि प्लगइन कौन-से हुक कार्यान्वित करता है |
| `skills`           | object[]? | वैकल्पिक कौशल परिभाषाएँ                                           |
| `enabledByDefault` | boolean?  | इंस्टॉल पर स्वतः सक्रिय करें                                      |
| `configSchema`     | object?   | कॉन्फ़िग फ़ील्ड का मैप (`string`/`number`/`boolean`/`select`)     |
| `integrity`        | string?   | वैकल्पिक `sha256-<base64>` एंट्री-फ़ाइल पिन                       |

अनुमतियाँ निम्न enum से ली जाती हैं:
`network` / `file-read` / `file-write` / `env` / `exec`।

## जीवनचक्र प्रवाह

```
install (POST /api/plugins, पथ)
  → मैनिफ़ेस्ट को स्कैन/सत्यापित करें → स्टेजिंग में कॉपी करें → सुनिश्चित करें कि main डायरेक्टरी के भीतर है
  → परमाणु रूप से नाम बदलकर ~/.omniroute/plugins/<name> में रखें → DB पंक्ति जोड़ें
  → onInstall चलाएँ → यदि enabledByDefault हो: सक्रिय करें

activate (POST /api/plugins/{name}/activate)
  → realpath सीमांकन जाँच → loadPlugin() (चाइल्ड प्रोसेस आरंभ करें)
  → घोषित हुक पंजीकृत करें → status = "active" → onActivate चलाएँ

deactivate (POST /api/plugins/{name}/deactivate)
  → onDeactivate चलाएँ (अपंजीकरण से पहले) → हुक अपंजीकृत करें
  → चाइल्ड प्रोसेस समाप्त करें → status = "inactive"

uninstall (DELETE /api/plugins/{name})
  → सक्रिय होने पर निष्क्रिय करें → onUninstall चलाएँ
  → सीमांकन-जाँच के साथ प्लगइन डायरेक्टरी पुनरावर्ती रूप से हटाएँ → DB पंक्ति हटाएँ
```

किसी ऐसी डायरेक्टरी पर `install` को दोबारा चलाने पर, जिसके मैनिफ़ेस्ट का संस्करण इंस्टॉल किए गए संस्करण से **निश्चित रूप से
नया** है, स्वतः अपग्रेड हो जाता है (स्वच्छ पुनः-इंस्टॉल; कॉन्फ़िगरेशन डिफ़ॉल्ट मानों पर रीसेट
हो जाता है)। समान या पुराने संस्करण को अस्वीकार कर दिया जाता है।

## डैशबोर्ड

`/dashboard/plugins` पर उपलब्ध डैशबोर्ड पृष्ठ
(`src/app/(dashboard)/dashboard/plugins/page.tsx`) दो टैब प्रदान करता है:

- **इंस्टॉल किए गए** — इंस्टॉल किए गए प्लगइनों को उनके घोषित हुक, सक्रिय/निष्क्रिय
  टॉगल, अनइंस्टॉल बटन और "प्लगइनों के लिए स्कैन करें"
  कार्रवाई (`POST /api/plugins/scan`) के साथ सूचीबद्ध करता है।
- **मार्केटप्लेस** — कस्टम रजिस्ट्री URL सेट करने के लिए एक
  फ़ील्ड के साथ `GET /api/plugins/marketplace` से कैटलॉग दिखाता है।

प्रत्येक प्लगइन का कॉन्फ़िगरेशन पृष्ठ `/dashboard/plugins/[name]/config` पर उपलब्ध है
(`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`)।
