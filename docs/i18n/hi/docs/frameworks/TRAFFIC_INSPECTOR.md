Traffic Inspector, OmniRoute का अंतर्निहित HTTPS ट्रैफ़िक डीबगर है — Charles Proxy / mitmweb / HTTP Toolkit जैसा एक टूल, जो **LLM-जागरूक** और **एजेंट-जागरूक** है। यह `/dashboard/tools/traffic-inspector` पर उपलब्ध है और एक साथ अधिकतम 5 कैप्चर स्रोतों से लाइव ट्रैफ़िक प्राप्त करता है।

**डैशबोर्ड स्थान:** `/dashboard/tools/traffic-inspector`
**साइडबार समूह:** टूल्स (AgentBridge के बाद)
**यह भी देखें:** [`AGENTBRIDGE.md`](./AGENTBRIDGE.md) — AgentBridge कैप्चर मोड 1 है।

### एक अनुच्छेद में आर्किटेक्चर

`TrafficBuffer` (`src/mitm/inspector/buffer.ts`) एक साझा इन-मेमोरी रिंग बफ़र है (डिफ़ॉल्ट रूप से 1000 प्रविष्टियाँ, `INSPECTOR_BUFFER_SIZE` के माध्यम से कॉन्फ़िगर करने योग्य)। सभी कैप्चर स्रोत `push()` के माध्यम से इसमें लिखते हैं। बफ़र `kindDetector.ts` का उपयोग करके प्रत्येक प्रविष्टि को वर्गीकृत करता है (यह निर्धारित करता है कि वह LLM अनुरोध है या नहीं), एक `contextKey` (सिस्टम प्रॉम्प्ट का SHA-256 फ़िंगरप्रिंट) की गणना करता है, और `globalTrafficBuffer.subscribe()` के माध्यम से सभी WebSocket सब्सक्राइबरों को प्रसारित करता है। डैशबोर्ड `GET /api/tools/traffic-inspector/ws` के माध्यम से कनेक्ट होता है और कनेक्ट होने पर एक स्नैपशॉट प्राप्त करता है, जिसके बाद `new`/`update`/`clear` इवेंट प्राप्त होते हैं।

## §2 कैप्चर मोड

Traffic Inspector **5 समकालिक कैप्चर स्रोतों** का समर्थन करता है। प्रत्येक को स्वतंत्र रूप से चालू या बंद किया जा सकता है। प्रत्येक `InterceptedRequest` (`src/mitm/inspector/types.ts`) का `source` फ़ील्ड `"agent-bridge"`, `"custom-host"`, `"http-proxy"`, `"system-proxy"`, या `"tproxy"` में से एक होता है।

### मोड 1 — AgentBridge (डिफ़ॉल्ट, हमेशा चालू)

**स्रोत:** AgentBridge हैंडलर (`src/mitm/handlers/base.ts`)
**कार्यविधि:** `MitmHandlerBase` में प्रत्येक `intercept()` कॉल फ़ॉरवर्ड करने से पहले `hookBufferStart()` और पूर्ण होने पर `hookBufferUpdate()` को कॉल करती है। किसी अतिरिक्त कॉन्फ़िगरेशन की आवश्यकता नहीं है — AgentBridge के चलते ही यह काम करने लगता है।
**दायरा:** AgentBridge में कॉन्फ़िगर किए गए 9 IDE एजेंट
**नोट:** `InterceptedRequest` में `source` फ़ील्ड = `"agent-bridge"`

### मोड 2 — कस्टम होस्ट (DNS रीडायरेक्ट)

**स्रोत:** उपयोगकर्ता द्वारा परिभाषित होस्ट सूची (`inspector_custom_hosts` तालिका)
**कार्यविधि:** UI के माध्यम से कोई होस्ट जोड़ने पर `/etc/hosts` में `127.0.0.1 <host>` जोड़ा जाता है (sudo आवश्यक)। मौजूदा AgentBridge MITM सर्वर (पोर्ट 443) नए होस्ट के लिए गतिशील रूप से SNI प्रमाणपत्र बनाता है।
**दायरा:** जो भी एप्लिकेशन जोड़े गए होस्ट का उपयोग करता है — एप्लिकेशन कॉन्फ़िगरेशन में किसी बदलाव की आवश्यकता नहीं
**नोट:** `source` = `"custom-host"`

उपयोग के उदाहरण:

- Python स्क्रिप्ट से `api.openai.com` की निगरानी करना
- `my-internal-llm.company.com` को डीबग करना
- समान नेटवर्क पर मौजूद मोबाइल डिवाइसों से ट्रैफ़िक कैप्चर करना (ARP स्पूफ़िंग के माध्यम से — उन्नत)

### मोड 3 — HTTP_PROXY लिसनर (पोर्ट 8080)

**स्रोत:** `HTTP_PROXY`/`HTTPS_PROXY` एनवायरनमेंट वेरिएबल का उपयोग करने वाले एप्लिकेशन
**कार्यविधि:** पोर्ट 8080 पर एक द्वितीयक लिसनर (`src/mitm/inspector/httpProxyServer.ts`), जो एक मानक स्पष्ट HTTP/HTTPS प्रॉक्सी के रूप में कार्य करता है। यह `CONNECT` टनल (HTTPS) और सीधे HTTP अनुरोध स्वीकार करता है।
**दायरा:** `HTTP_PROXY` एनवायरनमेंट का अनुपालन करने वाला कोई भी एप्लिकेशन — किसी DNS बदलाव या sudo की आवश्यकता नहीं
**नोट:** `source` = `"http-proxy"`

```bash
# किसी एक कमांड के लिए त्वरित कैप्चर:
HTTPS_PROXY=http://127.0.0.1:8080 curl https://api.openai.com/v1/models

# किसी शेल सत्र में स्थायी कैप्चर:
export HTTP_PROXY=http://127.0.0.1:8080
export HTTPS_PROXY=http://127.0.0.1:8080
```

**TLS सीमा:** HTTPS `CONNECT` टनल के लिए डिफ़ॉल्ट रूप से केवल मेटाडेटा (होस्ट, पोर्ट, समय) कैप्चर किया जाता है — TLS बॉडी डिक्रिप्ट नहीं होती। पूरी बॉडी का निरीक्षण करने के लिए "प्रॉक्सी मोड में HTTPS डिक्रिप्ट करें" टॉगल सक्षम करें (ऑप्ट-इन, AgentBridge प्रमाणपत्र का विश्वसनीय होना आवश्यक है)।

**पोर्ट टकराव:** यदि पोर्ट 8080 उपयोग में है, तो AgentBridge संरचित त्रुटि के साथ 409 लौटाता है। `INSPECTOR_HTTP_PROXY_PORT` एनवायरनमेंट वेरिएबल के माध्यम से पोर्ट बदलें।

### मोड 4 — सिस्टम-व्यापी प्रॉक्सी (उन्नत, ऑप्ट-इन)

**स्रोत:** OS-स्तरीय प्रॉक्सी सेटिंग (मशीन के सभी ऐप्स पर लागू)
**कार्यविधि:** सभी HTTP/HTTPS ट्रैफ़िक को HTTP_PROXY लिसनर के माध्यम से रीडायरेक्ट करने के लिए OS API का उपयोग करता है:

- **macOS:** `networksetup -setwebproxy / -setsecurewebproxy`
- **Linux:** `gsettings set org.gnome.system.proxy` + `/etc/environment`
- **Windows:** `netsh winhttp set proxy 127.0.0.1:8080`
  **दायरा:** मशीन का प्रत्येक एप्लिकेशन जो सिस्टम प्रॉक्सी सेटिंग का अनुपालन करता है
  **नोट:** `source` = `"system-proxy"`

**सुरक्षा तंत्र:**

- स्वतः-अक्षम टाइमर (डिफ़ॉल्ट 30 मिनट, `INSPECTOR_SYSTEM_PROXY_GUARD_MINUTES` के माध्यम से कॉन्फ़िगर करने योग्य)
- पिछली सिस्टम प्रॉक्सी स्थिति DB में सहेजी जाती है और वापस लौटाने पर पुनर्स्थापित की जाती है
- सक्रिय होने के दौरान उपयोगकर्ता के पेज छोड़ने पर डैशबोर्ड "सिस्टम प्रॉक्सी वापस लौटाई जा रही है" प्रॉम्प्ट दिखाता है
- UI `⚠ उन्नत` बैज + स्पष्ट पुष्टिकरण चेकबॉक्स दिखाता है

### मोड 5 — TPROXY पारदर्शी डिक्रिप्शन (Linux, root, ऑप्ट-इन)

**स्रोत:** कर्नेल TPROXY + पॉलिसी रूटिंग (`src/mitm/tproxy/`)
**कार्यविधि:** `mangle OUTPUT` में लक्षित पोर्ट (डिफ़ॉल्ट `443`) पर नए स्थानीय आउटबाउंड TCP कनेक्शन चिह्नित करता है, एक `ip rule` चिह्नित पैकेट को स्थानीय डिलीवरी की ओर पुनः रूट करता है, और `mangle PREROUTING` का `TPROXY` लक्ष्य उन्हें एक पारदर्शी (**IP_TRANSPARENT**) लिसनर (डिफ़ॉल्ट पोर्ट `8443`) को सौंपता है। लिसनर एक डायनेमिक CA द्वारा माँग पर **प्रत्येक SNI होस्टनेम के लिए** जारी किए गए लीफ़ प्रमाणपत्र से TLS समाप्त करता है, डिक्रिप्ट किए गए आदान-प्रदान को कैप्चर करता है, और अनुरोध को पुनः एन्क्रिप्ट करके मूल गंतव्य तक फ़ॉरवर्ड करता है।
**दायरा:** लक्षित पोर्ट पर **कोई भी** गंतव्य होस्ट — किसी `/etc/hosts` स्पूफ़, `HTTP_PROXY` एनवायरनमेंट या सिस्टम-व्यापी प्रॉक्सी बदलाव की आवश्यकता नहीं। इंटरसेप्ट की गई प्रक्रिया में किसी कॉन्फ़िगरेशन बदलाव की आवश्यकता नहीं होती, लेकिन उसे डायनेमिक CA पर भरोसा करना चाहिए।
**नोट:** `source` = `"tproxy"`

**आवश्यकताएँ:** केवल Linux (**IP_TRANSPARENT** केवल Linux पर उपलब्ध है), **CAP_NET_ADMIN** क्षमता (root), और एक नेटिव N-API ऐड-ऑन जिसे C टूलचेन के साथ बिल्ड करना आवश्यक है (`npm run build:native:tproxy`)। अनुपलब्ध होने पर, डैशबोर्ड टॉगल "TPROXY डिक्रिप्शन के लिए Linux + root + नेटिव ऐड-ऑन आवश्यक है" टूलटिप के साथ अक्षम रहता है। फ़ायरवॉल नियम ट्रांज़ैक्शनल रूप से लागू/वापस किए जाते हैं (क्रैश होने पर कभी भी कोई `mangle` नियम शेष नहीं रहता) और रीबूट पर साफ़ हो जाते हैं। SO_MARK-आधारित एंटी-लूप प्रॉक्सी के स्वयं के पुनः एन्क्रिप्ट किए गए फ़ॉरवर्ड को दोबारा इंटरसेप्ट होने से रोकता है।

यह एक व्यापक सबसिस्टम है जिसकी अपनी समर्पित ऑपरेटर गाइड है — संपूर्ण फ़ायरवॉल विधि, प्रत्येक SNI के लिए डायनेमिक CA + ट्रस्ट-स्टोर इंस्टॉलर, केवल-स्थानीय रूट, एंटी-लूप विवरण और कॉन्फ़िगरेशन स्कीमा के लिए `docs/security/MITM-TPROXY-DECRYPT.md` (git; `/docs` में संकलित नहीं) देखें। टॉगल `GET / POST / DELETE /api/tools/agent-bridge/tproxy` द्वारा संचालित होता है (ध्यान दें: रूट Traffic Inspector प्रीफ़िक्स के बजाय AgentBridge प्रीफ़िक्स के अंतर्गत है)।

## §4 LLM-जागरूक सुविधाएँ

### 4.1 प्रकार डिटेक्टर (`src/mitm/inspector/kindDetector.ts`)

4 संकेतों का उपयोग करके प्रत्येक अनुरोध को `"llm"`, `"app"`, या `"unknown"` के रूप में वर्गीकृत करता है:

1. **होस्ट रजिस्ट्री** — ~18 ज्ञात LLM API होस्टनाम (OpenAI, Anthropic, Gemini, Groq, Mistral, Together, Fireworks, Cohere, Perplexity, Hugging Face, OpenRouter, xAI, Moonshot, आदि)
2. **पाथ पैटर्न** — `/v1/chat/completions`, `/v1/messages`, `/generateContent`, `/v1/responses`, आदि।
3. **बॉडी संरचना** — `messages[]` (OpenAI/Claude), `contents[]` (Gemini), `prompt`, `input` फ़ील्ड का पता लगाता है
4. **यूज़र-एजेंट संकेत** — UA स्ट्रिंग में `codex`, `claude`, `gemini`, `antigravity`, `kiro`, `copilot`, `cursor`

Mode 2 के माध्यम से जोड़े गए कस्टम होस्ट, फ़ॉर्म इनपुट से अपना `kind` प्राप्त करते हैं (डिफ़ॉल्ट `"custom"` है)।

### 4.2 SSE मर्जर (`src/mitm/inspector/sseMerger.ts`)

**स्वतंत्र क्लीन-रूम कार्यान्वयन।** इवेंट पार्सिंग
[WHATWG server-sent events algorithm](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream)
का पालन करती है, जबकि पुनर्निर्माण सार्वजनिक [OpenAI](https://platform.openai.com/docs/api-reference/chat/create),
[Anthropic](https://platform.claude.com/docs/en/build-with-claude/streaming), और
[Gemini](https://ai.google.dev/api/generate-content#method:-models.streamgeneratecontent)
स्ट्रीमिंग स्कीमा का पालन करता है।

कच्चे SSE डेल्टा इवेंट से अंतिम असिस्टेंट संदेश का पुनर्निर्माण करता है:

- **Anthropic**: इंडेक्स के अनुसार `content_block_delta` संचित करता है; `text_delta`, `input_json_delta` (टूल कॉल), `thinking_delta` को संभालता है
- **OpenAI**: Chat Completions के विकल्पों/टूल कॉल और Responses API आउटपुट आइटम को
  इंडेक्स के अनुसार संचित करता है
- **Gemini**: `candidates[i].content.parts` संचित करता है
- **अज्ञात**: कच्चे इवेंट को बिना बदलाव के लौटाता है

Response टैब एक टॉगल दिखाता है: **"कच्चे इवेंट ↔ मर्ज किए गए"**।

### 4.3 वार्तालाप नॉर्मलाइज़र (`src/mitm/inspector/conversationNormalizer.ts`)

**स्वतंत्र क्लीन-रूम कार्यान्वयन।** नॉर्मलाइज़ेशन को स्थानीय ब्लैक-बॉक्स
कॉन्ट्रैक्ट और सार्वजनिक OpenAI, Anthropic, तथा Gemini संदेश स्कीमा द्वारा परिभाषित किया गया है; किसी अपस्ट्रीम
कार्यान्वयन स्रोत का उपयोग नहीं किया गया है।

रेंडरिंग से पहले OpenAI, Anthropic, और Gemini संदेश प्रारूपों को एकल `NormalizedConversation` में परिवर्तित करता है:

```ts
interface NormalizedConversation {
  request: NormalizedTurn[]; // अनुरोध बॉडी से messages / contents / prompt
  response: NormalizedTurn[]; // असिस्टेंट प्रतिक्रिया (sseMerger के माध्यम से मर्ज की गई)
  contextKey: string | null; // SHA-256 सिस्टम-प्रॉम्प्ट फ़िंगरप्रिंट
}
```

ब्लॉक प्रकार: `text`, `tool_use`, `tool_result`। Conversation टैब, प्रदाता चाहे कोई भी हो, इसी संरचना का उपयोग करता है।

### 4.4 कॉन्टेक्स्ट-की कलराइज़ेशन (`src/mitm/inspector/contextKey.ts`)

- सिस्टम प्रॉम्प्ट (`role:system` वाला पहला संदेश, या `system` फ़ील्ड, या Gemini `systemInstruction`) का `SHA-256` परिकलित करता है
- 12-वर्णों वाला हेक्स प्रीफ़िक्स (`"a3f9c2..."`) लौटाता है
- फ़्रंटएंड, बाएँ बॉर्डर की पट्टी के लिए की को एक नियतात्मक HSL रंग से मैप करता है
- **"समान कॉन्टेक्स्ट" फ़िल्टर**: `ctx #a3f` चिप पर क्लिक करने से केवल समान फ़िंगरप्रिंट वाले अनुरोध दिखाने हेतु एक फ़िल्टर जुड़ जाता है

इससे एक ही एजेंट सत्र में चल रहे अलग-अलग "व्यक्तित्वों" या कार्यों को दृश्य रूप से पहचानना आसान हो जाता है।

### 4.5 LLM मेटाडेटा निष्कर्षण

LLM अनुरोधों के लिए, LLM Details टैब यह जानकारी निकालता है:

```ts
interface LlmMetadata {
  provider: string | null; // "openai" | "anthropic" | "gemini" | ...
  apiKind: string | null; // "chat.completions" | "messages" | "embeddings" | ...
  model: string | null; // अनुरोध बॉडी या प्रतिक्रिया से
  messages: number; // टर्न की संख्या
  tokensIn: number | null; // usage.prompt_tokens / usage.input_tokens
  tokensOut: number | null; // usage.completion_tokens / usage.output_tokens
  streamed: boolean; // यदि SSE प्रतिक्रिया है, तो true
  mappedTo: string | null; // x-omniroute-mapped हेडर
  costEstimateUsd: number | null; // OmniRoute मूल्य-निर्धारण पर आधारित अनुमानित लागत
}
```

### 4.6 लाइव इन-फ़्लाइट अनुरोध फ़िल्टर

अनुरोध का `status` फ़ील्ड `number | "in-flight" | "error"` है — अनुरोध शुरू होते ही एक प्रविष्टि
`"in-flight"` के रूप में पुश की जाती है और प्रतिक्रिया (या त्रुटि) आने पर उसे **उसी स्थान पर अपडेट**
किया जाता है। टूलबार का **"Live"** टॉगल
(`liveOnly`, i18n की `trafficInspector.liveOnly`) सूची को उन प्रविष्टियों तक सीमित करता है
जिनका `status === "in-flight"` है, जिससे आप खुले कनेक्शन को रीयल टाइम में देख सकते हैं।

यह फ़िल्टर
`src/lib/inspector/matchesTrafficFilter.ts` में एक शुद्ध, क्लाइंट-साइड प्रेडिकेट है:

```ts
if (f.liveOnly && req.status !== "in-flight") return false;
```

टॉगल स्थिति `useTrafficFilters` (इंस्पेक्टर डैशबोर्ड हुक) में रहती है और
अन्य फ़िल्टर (प्रोफ़ाइल, होस्ट, एजेंट, स्रोत, स्थिति, कॉन्टेक्स्ट) के साथ संयोजित होती है।

### 4.7 प्रोसेस एट्रिब्यूशन (Linux)

Linux पर, प्रत्येक इंटरसेप्ट किए गए अनुरोध को **उद्गम स्थानीय
प्रोसेस** से संबद्ध किया जा सकता है। `InterceptedRequest` में दो वैकल्पिक फ़ील्ड जोड़े जाते हैं:

```ts
pid?: number;          // उद्गम प्रोसेस आईडी (केवल Linux)
processName?: string;  // उद्गम प्रोसेस का नाम (केवल Linux)
```

`src/mitm/inspector/processAttribution.ts`, कनेक्शन के _क्लाइंट_
इफ़ेमरल पोर्ट को निम्न प्रकार से PID + नाम से मैप करता है:

1. पोर्ट का सॉकेट inode खोजने के लिए `/proc/net/tcp` और `/proc/net/tcp6` को पढ़ना
   (`parseProcNetTcpForInode`, एक शुद्ध फ़िक्स्चर-परीक्षण योग्य पार्सर)।
2. `socket:[<inode>]` के सिमलिंक के लिए `/proc/<pid>/fd/` को स्कैन करना।
3. `/proc/<pid>/comm` से प्रोसेस का नाम पढ़ना।

1-सेकंड का TTL कैश लोड के दौरान procfs स्कैन की लागत को सीमित रखता है। एट्रिब्यूशन
**सर्वोत्तम-प्रयास** पर आधारित है — कोई भी विफलता `null` में रिज़ॉल्व होती है और कैप्चर को कभी अवरुद्ध नहीं करती।
macOS/Windows पर फ़ंक्शन `null` लौटाता है (स्टब; `lsof`/`GetExtendedTcpTable`
समर्थन एक अनुवर्ती कार्य है)।

## §5 सत्र

### 5.1 सत्र रिकॉर्ड करना

1. टूलबार में **"● सत्र रिकॉर्ड करें"** पर क्लिक करें → एक नाम दर्ज करें (वैकल्पिक)
2. लाइव टेल सामान्य रूप से जारी रहती है; एक लाल स्पंदित संकेतक `◉ REC · <name> · 00:42 · 23 अनुरोध` दिखाता है
3. **"⏹ रोकें"** पर क्लिक करें → सत्र स्नैपशॉट `inspector_sessions` + `inspector_session_requests` में सहेजा जाता है

### 5.2 रिकॉर्ड किया गया सत्र देखना

टूलबार में **सत्र** ड्रॉपडाउन सहेजे गए सत्रों को सूचीबद्ध करता है। किसी एक को चुनने पर:

- सत्र का स्नैपशॉट लोड होता है (स्थिर स्थिति)
- एक बैनर दिखाता है: `रिकॉर्ड किया गया सत्र "<name>" देखा जा रहा है — [लाइव पर वापस जाएँ]`
- Recharts एग्रीगेट्स के साथ आँकड़े टैब उपलब्ध हो जाता है

### 5.3 निर्यात प्रारूप

प्रत्येक सत्र को इन प्रारूपों में निर्यात किया जा सकता है:

| प्रारूप                    | उपयोग                                                                             |
| -------------------------- | --------------------------------------------------------------------------------- |
| **HAR** (HTTP Archive 1.2) | Chrome DevTools, Charles, Fiddler के साथ संगत — ऑफ़लाइन विश्लेषण के लिए आयात करें |
| **JSONL**                  | प्रति पंक्ति एक `InterceptedRequest` — `llm-interceptor` प्रारूप के साथ संगत      |

`GET /api/tools/traffic-inspector/sessions/{id}/export.har` या सत्र ड्रॉपडाउन में ⬇ बटन के माध्यम से निर्यात करें।

## §6 सुरक्षा

ट्रैफ़िक इंस्पेक्टर प्राधिकरण हेडर और अनुरोध बॉडी सहित **सभी इंटरसेप्ट किए गए HTTPS ट्रैफ़िक** को दिखाता है। निम्नलिखित नियंत्रण लागू हैं:

| नियंत्रण                               | विवरण                                                                                                                                                                        |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LOCAL_ONLY**                         | सभी रूट और WebSocket एंडपॉइंट केवल लूपबैक तक सीमित हैं (प्रमाणीकरण से पहले `routeGuard.ts` में लागू)                                                                         |
| **गोपनीय जानकारी मास्क करना**          | रैखिक `maskSecret()` स्कैनर `TrafficBuffer.push()` से पहले RFC 6750 Bearer क्रेडेंशियल, प्रदाता-उपसर्गित कुंजियों और लंबे अपारदर्शी टोकन को छिपाता है                        |
| **बॉडी आकार सीमा**                     | `INSPECTOR_MAX_BODY_KB` (डिफ़ॉल्ट 1024 KB) से बड़ी बॉडी को `"(प्रदर्शन के लिए छोटा किया गया)"` सूचना के साथ छोटा किया जाता है                                                |
| **हेडर सैनिटाइज़ेशन**                  | नाम लोअरकेस किए जाते हैं; फ़्रेमिंग/हॉप-बाय-हॉप और प्रॉक्सी-प्रमाणीकरण हेडर हटा दिए जाते हैं; कुकी पूरी तरह छिपाई जाती हैं; क्रेडेंशियल मान `maskSecret()` को सौंपे जाते हैं |
| **CSP**                                | इंजेक्ट की गई प्रतिक्रिया बॉडी के माध्यम से XSS रोकने के लिए ट्रैफ़िक इंस्पेक्टर पृष्ठों पर सख्त Content Security Policy                                                     |
| **डिफ़ॉल्ट रूप से कोई स्थायित्व नहीं** | `TrafficBuffer` इन-मेमोरी है और सर्वर पुनरारंभ होने पर खो जाता है। सत्र केवल स्पष्ट रूप से रिकॉर्ड किए जाने पर ही स्थायी रूप से सहेजे जाते हैं                               |

### लागू किए गए कठोर नियम

| नियम                              | अनुप्रयोग                                                                             |
| --------------------------------- | ------------------------------------------------------------------------------------- |
| **#12** `sanitizeErrorMessage`    | ट्रैफ़िक इंस्पेक्टर रूट से सभी HTTP त्रुटि प्रतिक्रियाएँ सैनिटाइज़ की जाती हैं        |
| **#15 + #17** `isLocalOnlyPath()` | `/api/tools/traffic-inspector/` LOCAL_ONLY + SPAWN_CAPABLE है (सिस्टम प्रॉक्सी कमांड) |

### ज्ञात सीमाएँ

- **सिस्टम-व्यापी प्रॉक्सी मोड** VPN क्लाइंट और SSO सहित मशीन पर सभी एप्लिकेशन को प्रभावित करता है। हमेशा स्वतः-अक्षम टाइमर के साथ उपयोग करें। साझा मशीनों पर उपयोग न करें।
- **CONNECT टनल HTTPS**: जब तक TLS इंटरसेप्शन सक्षम न हो, मोड 3 (HTTP_PROXY) HTTPS गंतव्यों के लिए केवल टनल मेटाडेटा कैप्चर करता है। यह डिज़ाइन के अनुसार है — उन ऐप्स द्वारा AgentBridge प्रमाणपत्र पर भरोसा किए बिना पारदर्शी कैप्चर उनके लिए TLS सत्यापन को बाधित कर देगा।
- **कुछ कंपोनेंट में हार्डकोड की गई स्ट्रिंग**: कुछ UI कंपोनेंट (F7/F8) में थोड़ी संख्या में हार्डकोड की गई स्ट्रिंग हैं, जिन्हें अभी तक i18n कुंजियाँ कवर नहीं करती हैं। इन्हें i18n अंतराल रिपोर्ट में ज्ञात सीमा के रूप में प्रलेखित किया गया है; इन्हें आगामी चरण में माइग्रेट किया जाएगा। प्रभावित स्ट्रिंग UI के सजावटी लेबल हैं, जिन्हें कार्यात्मक उपयोग के लिए अनुवाद की आवश्यकता नहीं होती।

## §7 समस्या निवारण

### WebSocket डिस्कनेक्शन

यदि लाइव टेल में "डिस्कनेक्टेड" दिखाई देता है:

1. जाँचें कि सर्वर अभी भी चल रहा है: `GET /api/tools/traffic-inspector/capture-modes`
2. पेज को फिर से लोड करें — WebSocket दोबारा कनेक्ट होता है और एक नया स्नैपशॉट प्राप्त करता है
3. यदि सर्वर पुनः शुरू किया गया था, तो इन-मेमोरी बफ़र साफ़ हो गया था — पुरानी प्रविष्टियाँ उपलब्ध नहीं रहेंगी, जब तक कि कोई सेशन रिकॉर्ड न किया गया हो

### पोर्ट 8080 का टकराव

यदि HTTP_PROXY मोड शुरू नहीं हो पाता:

```bash
lsof -i :8080    # प्रक्रिया खोजें
```

पोर्ट बदलें:

```bash
# .env
INSPECTOR_HTTP_PROXY_PORT=8888
```

### सिस्टम प्रॉक्सी पूर्ववत नहीं हुआ

यदि सिस्टम-वाइड प्रॉक्सी मोड सक्रिय होने के दौरान OmniRoute क्रैश हो जाता है:

**macOS:**

```bash
networksetup -setwebproxystate Wi-Fi off
networksetup -setsecurewebproxystate Wi-Fi off
```

**Linux (GNOME):**

```bash
gsettings set org.gnome.system.proxy mode 'none'
```

**Windows:**

```cmd
netsh winhttp reset proxy
```

यदि डैशबोर्ड को पता चलता है कि DB स्थिति के अनुसार प्रॉक्सी सक्रिय था, तो अगली बार लोड होने पर वह "सिस्टम प्रॉक्सी पूर्ववत करें" विकल्प भी प्रस्तुत करेगा।

### बफ़र भर गया

जब बफ़र `INSPECTOR_BUFFER_SIZE` (डिफ़ॉल्ट 1000) तक पहुँच जाता है, तो नई प्रविष्टियाँ सबसे पुरानी प्रविष्टियों को बाहर कर देती हैं। यदि महत्वपूर्ण अनुरोध खो रहे हैं:

- `INSPECTOR_BUFFER_SIZE` बढ़ाएँ (जैसे, 5000) — इससे अधिक मेमोरी के बदले अधिक समय तक डेटा सुरक्षित रहता है
- संबंधित समयावधि को DB में बनाए रखने के लिए एक सेशन रिकॉर्ड करें
