API कुंजियों के माध्यम से पहुँचा जाता है) के विपरीत, एम्बेडेड सेवाएँ OmniRoute वाली मशीन पर ही चलती हैं और लूपबैक के माध्यम से संचार करती हैं।

## 1. अवलोकन

### एम्बेडेड सेवाएँ क्यों?

छह सेवाएँ एम्बेड की गई हैं:

| सेवा            | npm पैकेज                         | डिफ़ॉल्ट पोर्ट | उद्देश्य                                                                                                                                                                                                               |
| --------------- | --------------------------------- | :------------: | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **9Router**     | `9router`                         |     20130      | AI राउटर, जिसे OmniRoute उप-प्रदाता के रूप में उपयोग कर सकता है। मॉडल `9router/{sub}/{model}` के रूप में उपलब्ध कराए जाते हैं                                                                                          |
| **CLIProxyAPI** | GitHub रिलीज़ बाइनरी (`cliproxy`) |      8317      | Anthropic CLI प्रमाणीकरण प्रवाहों के लिए स्थानीय प्रॉक्सी अडैप्टर। OAuth टोकन की समय-सीमा समाप्त होने पर फ़ॉलबैक रूटिंग प्रदान करता है                                                                                 |
| **Mux**         | `mux` (हेडलेस `mux server`)       |      8322      | स्थानीय एजेंट-ऑर्केस्ट्रेशन डेमन (coder/mux)। केवल जीवनचक्र-प्रबंधित — रूटिंग लक्ष्य नहीं (कोई LLM प्रॉक्सीइंग नहीं)।                                                                                                  |
| **Bifrost**     | `@maximhq/bifrost`                |      8080      | Go AI-गेटवे रिले बैकएंड। चलने के दौरान, रिले रूट (`/v1/relay/`) द्वारा स्वचालित रूप से चयनित होता है                                                                                                                   |
| **Dario**       | `@askalf/dario`                   |      3456      | Claude-सब्सक्रिप्शन प्रॉक्सी — Claude-Code-स्वरूपित ट्रैफ़िक के लिए CLIProxyAPI का विकल्प/फ़ेलओवर; इंजेक्ट की गई कुंजी `DARIO_ADMIN_TOKEN` बन जाती है, जो इसके `/admin/*` OAuth नियंत्रण तल तक पहुँच नियंत्रित करती है |
| **open-wa**     | `@open-wa/wa-automate`            |      8323      | WhatsApp Web स्वचालन (Puppeteer के माध्यम से हेडलेस Chromium)। केवल जीवनचक्र-प्रबंधित — रूटिंग लक्ष्य नहीं।                                                                                                            |

सभी छह समान पर्यवेक्षी मॉडल का पालन करते हैं:

- OmniRoute उन्हें `DATA_DIR/services/{name}/` के अंतर्गत इंस्टॉल करता है (OmniRoute के अपने `package.json` से पृथक)
- OmniRoute उन्हें चाइल्ड प्रोसेस के रूप में शुरू करता है और उनकी निगरानी करता है
- OmniRoute चाइल्ड के एनवायरनमेंट में एक अल्पकालिक API कुंजी इंजेक्ट करता है और बिना डाउनटाइम के उसे रोटेट करता है (जहाँ लागू हो)
- सभी प्रबंधन रूट (`/api/services/*`) **LOCAL_ONLY** हैं — केवल लूपबैक से पहुँच योग्य (अनिवार्य नियम #17)

### प्रमुख निर्णय (डिज़ाइन योजना से)

| निर्णय                                   | मान                                                                                                     |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 9Router के नेटिव UI तक डैशबोर्ड की पहुँच | `/dashboard/providers/services/9router/embed/*` पर रिवर्स प्रॉक्सी                                      |
| इंस्टॉलेशन तंत्र                         | `execFile` के माध्यम से `npm install {package}` (कोई शेल इंटरपोलेशन नहीं)                               |
| उपभोग मोड                                | रूटिंग इंजन में `9router/{sub}/{model}` के रूप में पंजीकृत प्रदाता                                      |
| API कुंजी प्रबंधन                        | OmniRoute जनरेट करता है, एट-रेस्ट एन्क्रिप्ट करता है (AES-256-GCM), और env के माध्यम से इंजेक्ट करता है |
| डैशबोर्ड स्थान                           | `/dashboard/providers/services` (तीन टैब)                                                               |
| ऑटो-स्टार्ट                              | प्रत्येक सेवा के लिए टॉगल, डिफ़ॉल्ट रूप से बंद                                                          |

```
                             stop() │                          │error │
                                    ▼                          └──────┘
                               ┌──────────┐
                               │ stopping │
                               └──────────┘
```

स्थितियाँ `version_manager` DB तालिका (`status` कॉलम) में संग्रहीत होती हैं और
`ServiceSupervisor` की इन-मेमोरी स्थिति में प्रतिबिंबित होती हैं। किसी चल रही
प्रक्रिया के लिए इन-मेमोरी स्थिति प्रामाणिक होती है; बूट के समय DB स्थिति स्थायी
फ़ॉलबैक होती है।

### स्थिति संक्रमण

| इससे            | घटना                                                 | इसमें                  |
| --------------- | ---------------------------------------------------- | ---------------------- |
| `not_installed` | `install()` सफल होता है                              | `stopped`              |
| `stopped`       | `start()` कॉल किया जाता है                           | `starting`             |
| `starting`      | स्वास्थ्य जाँच 200 लौटाती है                         | `running`              |
| `starting`      | स्वस्थ होने से पहले प्रक्रिया बंद होती है            | `error`                |
| `running`       | `stop()` कॉल किया जाता है                            | `stopping` → `stopped` |
| `running`       | प्रक्रिया अप्रत्याशित रूप से बंद होती है (< 5 सेकंड) | `error` (तीव्र क्रैश)  |
| `running`       | प्रक्रिया अप्रत्याशित रूप से बंद होती है (> 5 सेकंड) | `error`                |
| `error`         | `start()` कॉल किया जाता है                           | `starting`             |
| कोई भी          | `stopping` के दौरान `stop()`                         | कोई कार्रवाई नहीं      |

### ऑपरेशन लॉक

`ServiceSupervisor` एक असिंक्रोनस ऑपरेशन लॉक (`withLock()`) के माध्यम से जीवनचक्र
ऑपरेशनों को क्रमबद्ध करता है। एक ही सुपरवाइज़र पर समवर्ती `start()` कॉल के परिणामस्वरूप
ठीक एक ही प्रक्रिया स्पॉन होती है; दूसरा कॉलर प्रतीक्षा करता है और मौजूदा स्थिति
लौटाता है। यह रेस कंडीशन को रोकता है, उदाहरण के लिए, जब ऑटो-स्टार्ट और कोई UI बटन
एक साथ सक्रिय होते हैं।

## 4. API संदर्भ

`/api/services/` के अंतर्गत सभी रूट **LOCAL_ONLY** हैं (केवल लूपबैक, कठोर नियम #17)।
गैर-लूपबैक अनुरोधों को ऑथ टोकन की परवाह किए बिना `403 LOCAL_ONLY` प्राप्त होता है।

### 4.1 9Router एंडपॉइंट (11 रूट)

#### `POST /api/services/9router/install`

npm से 9Router इंस्टॉल करता है। अपने स्वयं के `package.json` और `node_modules/` के साथ
`DATA_DIR/services/9router/` बनाता है। यह OmniRoute की अपनी डिपेंडेंसी से टकराव नहीं करता।

**अनुरोध बॉडी** (सभी वैकल्पिक):

```json
{ "version": "latest" }
```

| फ़ील्ड    | प्रकार   | डिफ़ॉल्ट   | विवरण                                        |
| --------- | -------- | ---------- | -------------------------------------------- |
| `version` | `string` | `"latest"` | इंस्टॉल करने के लिए npm वर्ज़न टैग या semver |

**प्रतिक्रियाएँ:**

| स्थिति | विवरण                                                              |
| ------ | ------------------------------------------------------------------ |
| `200`  | `{ ok: true, installedVersion: "x.y.z", path: "..." }`             |
| `400`  | अमान्य अनुरोध बॉडी (Zod सत्यापन विफलता)                            |
| `409`  | इंस्टॉलेशन पहले से जारी है (लॉक सक्रिय है)                         |
| `500`  | npm इंस्टॉल विफल — उपयोगकर्ता-अनुकूल त्रुटि के लिए `message` देखें |

**टिप्पणियाँ:** `execFile('npm', [...])` का उपयोग करता है — कोई शेल नहीं, कोई इंटरपोलेशन नहीं (कठोर नियम #13)।
EACCES त्रुटियों को उपयोगकर्ता-अनुकूल संदेशों के रूप में दिखाया जाता है।

---

#### `POST /api/services/9router/start`

9Router प्रारंभ करता है। यदि सुपरवाइज़र पहले से पंजीकृत नहीं है, तो उसे पंजीकृत करता है और फिर
`supervisor.start()` को कॉल करता है। पहले से चल रहा होने पर यह आइडेम्पोटेंट है।

**अनुरोध बॉडी:** कोई नहीं

**प्रतिक्रियाएँ:**

| स्थिति | विवरण                                                      |
| ------ | ---------------------------------------------------------- |
| `200`  | `ServiceStatus` ऑब्जेक्ट (नीचे स्कीमा देखें)               |
| `409`  | 9Router इंस्टॉल नहीं है (`status: "not_installed"`)        |
| `503`  | प्रारंभ करना विफल रहा (प्रोसेस त्रुटि — `lastError` देखें) |

**ServiceStatus स्कीमा:**

```json
{
  "tool": "9router",
  "state": "running",
  "pid": 12345,
  "port": 20130,
  "health": "healthy",
  "startedAt": "2026-05-25T10:00:00.000Z",
  "lastError": null
}
```

#### `POST /api/services/9router/stop`

9Router को सुचारु रूप से रोकता है। SIGTERM भेजता है, 15 s प्रतीक्षा करता है और यदि प्रोसेस अब भी सक्रिय हो,
तो SIGKILL भेजता है। पहले से रुका हुआ होने पर यह आइडेम्पोटेंट है।

**अनुरोध बॉडी:** कोई नहीं

**प्रतिक्रियाएँ:**

| स्थिति | विवरण                              |
| ------ | ---------------------------------- |
| `200`  | `ServiceStatus` (state: "stopped") |
| `503`  | रोकना अप्रत्याशित रूप से विफल रहा  |

---

#### `POST /api/services/9router/restart`

ऑपरेशन लॉक के अंतर्गत `stop()` और फिर `start()` के समतुल्य।

**अनुरोध बॉडी:** कोई नहीं

**प्रतिक्रियाएँ:** `start` के समान (अंतिम `ServiceStatus` लौटाता है)।

---

#### `POST /api/services/9router/update`

9Router को नए npm वर्ज़न में अपडेट करता है। यदि सेवा चल रही है, तो पहले उसे रोका जाता है,
npm इंस्टॉल चलाया जाता है (नया वर्ज़न उसी स्थान पर इंस्टॉल किया जाता है) और फिर
सेवा को पुनः प्रारंभ किया जाता है।

**अनुरोध बॉडी** (सभी वैकल्पिक):

```json
{ "version": "latest" }
```

**प्रतिक्रियाएँ:**

| स्थिति | विवरण                                                           |
| ------ | --------------------------------------------------------------- |
| `200`  | `{ ok: true, previousVersion: "...", installedVersion: "..." }` |
| `400`  | अमान्य बॉडी                                                     |
| `500`  | npm अपडेट विफल रहा                                              |

#### `POST /api/services/9router/rotate-key`

9Router के लिए एक नई API कुंजी जनरेट करता है, उसे स्थिर अवस्था में एन्क्रिप्ट करता है और सेवा को
(यदि चल रही हो) पुनः प्रारंभ करता है, ताकि वह अपने एनवायरनमेंट से नई कुंजी प्राप्त कर सके। पुरानी कुंजी
तुरंत अमान्य कर दी जाती है।

**अनुरोध बॉडी:** कोई नहीं

**प्रतिक्रियाएँ:**

| स्थिति | विवरण                                      |
| ------ | ------------------------------------------ |
| `200`  | `{ keyRotated: true, restarted: boolean }` |
| `500`  | कुंजी रोटेशन विफल रहा                      |

**सुरक्षा:** नई कुंजी प्रतिक्रिया में कभी नहीं लौटाई जाती (क्रेडेंशियल लीक नहीं होता)।
इसे `version_manager` टेबल में एन्क्रिप्टेड रूप में (AES-256-GCM) संग्रहीत किया जाता है।

### 4.2 CLIProxyAPI एंडपॉइंट (10 रूट)

CLIProxyAPI में 9Router जैसी ही एंडपॉइंट संरचना है, सिवाय `rotate-key` के, और इसमें
`accounts`, `provider-expose` तथा `auto-restart-adopted` भी शामिल हैं। अब इसे
आरंभ करते समय एक समर्पित डेटा-प्लेन API कुंजी इंजेक्ट की जाती है (`bootstrap.ts` में
`needsApiKey: true`, जिसका उपयोग मॉडल सिंक के लिए होता है); `status` में कम फ़ील्ड शामिल हैं।

| विधि   | पथ                                  | विवरण                                  |
| ------ | ----------------------------------- | -------------------------------------- |
| `POST` | `/api/services/cliproxy/install`    | npm से CLIProxyAPI इंस्टॉल करें        |
| `POST` | `/api/services/cliproxy/start`      | CLIProxyAPI शुरू करें                  |
| `POST` | `/api/services/cliproxy/stop`       | CLIProxyAPI रोकें                      |
| `POST` | `/api/services/cliproxy/restart`    | CLIProxyAPI पुनः शुरू करें             |
| `POST` | `/api/services/cliproxy/update`     | नए संस्करण में अपडेट करें              |
| `GET`  | `/api/services/cliproxy/status`     | लाइव + DB स्थिति (`apiKeyMasked` नहीं) |
| `POST` | `/api/services/cliproxy/auto-start` | स्वतः-प्रारंभ टॉगल करें                |

साझा `GET /api/services/{name}/logs` एंडपॉइंट (§4.1 देखें), `[name]` डायनेमिक
सेगमेंट का उपयोग करके सभी चार सेवाओं के लिए काम करता है।

### 4.3 Mux एंडपॉइंट (8 रूट)

लेकिन अभी तक कोई समर्पित रोटेशन एंडपॉइंट नहीं है)। Mux का केवल जीवनचक्र प्रबंधित किया
जाता है: 9Router के विपरीत, इसमें कोई लेयर 4 एक्ज़ीक्यूटर नहीं है और इसे कभी भी रूटिंग

| `POST` | `/api/services/mux/start`      | Mux शुरू करें (`mux server`)          |
| `POST` | `/api/services/mux/stop`       | Mux रोकें                             |

| `POST` | `/api/services/mux/auto-start` | स्वतः-प्रारंभ टॉगल करें               |

के माध्यम से) एक हेडलेस Chromium इंस्टेंस संचालित करता है। यह Mux जैसी ही एंडपॉइंट

प्रबंधित किया जाता है — यह रूटिंग लक्ष्य नहीं है और इसमें कोई लेयर 4 एक्ज़ीक्यूटर/प्रोवाइडर
प्रविष्टि नहीं है।

| विधि   | पथ                                | विवरण                                                      |
| ------ | --------------------------------- | ---------------------------------------------------------- |
| `POST` | `/api/services/openwa/install`    | npm से open-wa (`@open-wa/wa-automate`) इंस्टॉल करें       |
| `POST` | `/api/services/openwa/start`      | पोर्ट 8323 (डिफ़ॉल्ट) पर open-wa शुरू करें                 |
| `POST` | `/api/services/openwa/stop`       | open-wa बंद करें                                           |
| `POST` | `/api/services/openwa/restart`    | open-wa पुनः शुरू करें                                     |
| `POST` | `/api/services/openwa/update`     | नए संस्करण में अपडेट करें                                  |
| `GET`  | `/api/services/openwa/status`     | लाइव + DB स्थिति                                           |
| `POST` | `/api/services/openwa/auto-start` | स्वतः-प्रारंभ टॉगल करें                                    |
| `GET`  | `/api/services/openwa/logs`       | SSE लॉग टेल (साझा `[name]/logs` डायनेमिक रूट के माध्यम से) |

**API कुंजी:** `WA_KEY` के रूप में इंजेक्ट की जाती है — open-wa का सामान्य `WA_*`-प्रीफ़िक्स वाला env
ओवरराइड इसे `--key`/`-k` CLI विकल्प पर मैप करता है
(`dist/cli/setup.js::envArgs()`, इंस्टॉल किए गए 4.76.0
पैकेज के विरुद्ध सत्यापित)। `generateServiceApiKey()` द्वारा जनरेट किए जाने पर `ow_`
प्रीफ़िक्स लगाया जाता है। open-wa कुंजी को `key`/`api_key` HTTP हेडर से वापस पढ़ता है (`Authorization:
Bearer` से नहीं); `/api-docs*` को स्पष्ट रूप से जाँच से छूट दी गई है
(`dist/cli/server.js` में `setupAuthenticationLayer`), इसलिए हेल्थ प्रोब को
किसी प्रमाणीकरण हेडर की आवश्यकता नहीं होती।

**पेयरिंग:** open-wa अनौपचारिक है और WhatsApp से संबद्ध नहीं है — कनेक्ट किए गए
नंबर पर WhatsApp की अपनी ऑटोमेशन पहचान प्रणाली के कारण प्रतिबंध लगने का जोखिम रहता है।
पहली बार शुरू होने पर, पेयरिंग QR कोड stdout पर प्रिंट होता है और मौजूदा
लॉग पैनल/SSE स्ट्रीम के माध्यम से प्रदर्शित किया जाता है — इस एकीकरण में अभी तक
कोई समर्पित QR-इमेज एंडपॉइंट नहीं है।

### 4.7 रिवर्स प्रॉक्सी (9Router डैशबोर्ड एम्बेड)

डैशबोर्ड एक आंतरिक रिवर्स
प्रॉक्सी के माध्यम से iframe के अंदर 9Router वेब UI एम्बेड करता है:

```
GET|POST|... /dashboard/providers/services/9router/embed/[...path]
```

यह प्रॉक्सी:

- अनुरोध को `http://127.0.0.1:{port}/{path}` पर फ़ॉरवर्ड करता है (केवल लूपबैक)
- इनकमिंग `cookie` और `authorization` हेडर हटाता है (OmniRoute सत्र का कोई रिसाव नहीं)
- 9Router प्रमाणीकरण के लिए `Authorization: Bearer {apiKey}` इंजेक्ट करता है
- प्रतिक्रिया से `set-cookie`, `content-security-policy`, `x-frame-options`, `cross-origin-*` हटाता है
- `<base href>` इंजेक्ट करने और निरपेक्ष पथों को सामान्यीकृत करने के लिए HTML प्रतिक्रियाओं को फिर से लिखता है (`/foo` → `/dashboard/.../embed/foo`)

एम्बेड किए गए डैशबोर्ड के WebSocket अपग्रेड को एक समर्पित पोर्ट पर मौजूद सहायक सर्वर द्वारा संभाला जाता है
(`src/lib/services/embedWsProxy.ts` देखें)।

**सुरक्षा:** एम्बेड प्रॉक्सी रूट्स को `LOCAL_ONLY_API_PREFIXES`
के अंतर्गत वर्गीकृत किया गया है और उन तक केवल लूपबैक से पहुँचा जा सकता है। Cloudflare/Ngrok
टनल के माध्यम से JWT प्राप्त करने वाला हमलावर एम्बेड की गई सेवाओं में प्रॉक्सी नहीं कर सकता।

## 5. सुरक्षा

### LOCAL_ONLY प्रवर्तन (सख्त नियम #17)

`/api/services/` और `/dashboard/providers/services/*/embed/` के अंतर्गत आने वाले सभी रूट
`src/server/authz/routeGuard.ts` में LOCAL_ONLY के रूप में वर्गीकृत हैं। लूपबैक जाँच
किसी भी प्रमाणीकरण शाखा से पहले बिना शर्त चलती है:

```
अनुरोध आता है
  → isLocalOnlyPath(path)?
      → गैर-लूपबैक → 403 LOCAL_ONLY (हमेशा, प्रमाणीकरण जाँच से पहले)
      → लूपबैक     → सामान्य प्रमाणीकरण पर आगे बढ़ें
```

यह लीक हुए JWT (उदाहरण के लिए, किसी टनल के माध्यम से) को `npm install` ट्रिगर करने या
प्रोसेस शुरू करने से रोकता है। संपूर्ण टियर मैट्रिक्स के लिए
`docs/security/ROUTE_GUARD_TIERS.md` देखें।

### API कुंजी इंजेक्शन

9Router और Mux को अपने HTTP एंडपॉइंट्स के लिए API कुंजी/बेयरर टोकन की आवश्यकता होती है।
OmniRoute:

1. सेवा-विशिष्ट प्रीफ़िक्स (9Router के लिए `nr_`, Mux के लिए `mx_`) के साथ
   `crypto.randomBytes(32).toString("base64url")` के माध्यम से एक कुंजी जनरेट करता है।
2. AES-256-GCM (प्रोवाइडर क्रेडेंशियल्स के लिए उपयोग किया जाने वाला वही साइफ़र) का उपयोग करके
   इसे स्थिर अवस्था में एन्क्रिप्ट करता है।
3. स्पॉन के समय इसे डिक्रिप्ट करके एक एनवायरनमेंट वेरिएबल के रूप में इंजेक्ट करता है —
   9Router के लिए `NINEROUTER_API_KEY`, Mux के लिए `MUX_SERVER_AUTH_TOKEN` (कभी भी CLI
   फ़्लैग के रूप में नहीं, ताकि टोकन कभी भी `ps`/प्रोसेस सूचियों में दिखाई न दे)।
4. किसी भी HTTP रिस्पॉन्स में कभी भी प्लेनटेक्स्ट कुंजी नहीं लौटाता।

CLIProxyAPI को स्पॉन के समय इंजेक्ट की गई एक समर्पित डेटा-प्लेन कुंजी मिलती है
(`needsApiKey: true` — एडाप्टर के विरुद्ध मॉडल सिंक के लिए उपयोग की जाती है)।

### SSRF से सुरक्षा

रिवर्स HTTP प्रॉक्सी (`/dashboard/.../embed/[...path]`) को केवल
`http://127.0.0.1:{port}` पर फ़ॉरवर्ड करने के लिए हार्डकोड किया गया है। यह कभी भी
गैर-लूपबैक गंतव्यों पर रीडायरेक्ट का अनुसरण नहीं करता। लूपबैक रेंज के बाहर रिज़ॉल्व होने वाले
किसी भी अपस्ट्रीम URL को अस्वीकार करने के लिए `ssrf-req-filter` लाइब्रेरी का उपयोग किया जाता है।

### शेल सुरक्षा (सख्त नियम #13)

`npm install` को `execFile('npm', ['install', pkg, '--prefix', dir])` के माध्यम से लागू किया जाता है —
कोई टेम्पलेट लिटरल नहीं, कोई शेल नहीं, और कमांड स्ट्रिंग में बाहरी पाथ का कोई इंटरपोलेशन नहीं।
रनटाइम मान (पोर्ट, API कुंजियाँ) चाइल्ड के `env` ऑब्जेक्ट के माध्यम से पास किए जाते हैं।

### त्रुटि स्वच्छीकरण (सख्त नियम #12)

`/api/services/*` से आने वाले सभी त्रुटि रिस्पॉन्स `buildErrorBody()` या
`sanitizeErrorMessage()` से होकर गुजरते हैं। अपरिष्कृत `err.stack` और `err.message` कभी भी
कॉलर को यथावत नहीं लौटाए जाते।

## 6. नई एम्बेडेड सेवा जोड़ना

इन 8 चरणों का पालन करें। प्रामाणिक संदर्भ के रूप में `src/lib/services/installers/`
और `src/app/api/services/` में मौजूद कार्यान्वयनों को पढ़ें।

### चरण 1 — इंस्टॉलर बनाएँ

`ninerouter.ts` के अनुरूप `src/lib/services/installers/{name}.ts` बनाएँ:

```typescript
export const NAME_PACKAGE = "your-npm-package";
export const NAME_DEFAULT_PORT = 20132; // कोई खाली पोर्ट चुनें

export async function install(version = "latest"): Promise<InstallResult> { ... }
export async function update(version = "latest"): Promise<InstallResult> { ... }
export async function uninstall(): Promise<void> { ... }
export function resolveSpawnArgs(apiKey: string, port: number): SpawnArgs { ... }
export async function getInstalledVersion(): Promise<string | null> { ... }
export async function getLatestVersion(): Promise<string | null> { ... }
```

`installers/utils.ts` से `runNpm(['install', NAME_PACKAGE, '--prefix', dir])` का उपयोग करें
— कभी भी `execSync` या शेल इंटरपोलेशन का उपयोग न करें।

### चरण 2 — बूटस्ट्रैप में पंजीकृत करें

`src/lib/services/bootstrap.ts` में `SERVICES` ऐरे में एक `ServiceEntry` जोड़ें:

```typescript
{
  tool: "myservice",
  port: NAME_DEFAULT_PORT,
  healthPath: "/health",
  healthIntervalMs: 5_000,
  stopTimeoutMs: 15_000,
  logsBufferBytes: 5_242_880,
  needsApiKey: true, // यदि API कुंजी की आवश्यकता नहीं है, तो false
}
```

`cfg.tool === "myservice"` को संभालने के लिए `buildSpawnArgsFactory()` का विस्तार करें।

#### प्लग करने योग्य प्रोवाइडर-प्लगइन अनुबंध (चरण 1, #7333)

`src/lib/services/providerPlugins/` एक `ServiceProviderPlugin` अनुबंध प्रस्तुत करता है, जो
किसी बैकएंड के `bootstrap.ts` के `ServiceEntry` फ़ील्ड और `serviceBackends.ts` के
मैनिफ़ेस्ट-टेम्पलेट फ़ील्ड को एक ही ऑब्जेक्ट में पैकेज करता है, बजाय इसके कि उसी बैकएंड के
स्वरूप को दो असंबंधित फ़ाइलों में अलग-अलग व्यक्त किया जाए। इस लेखन के समय **केवल `9router`
माइग्रेट किया गया है** — `bootstrap.ts`, `getServiceProviderPlugin("9router")`
(`src/lib/services/providerPlugins/registry.ts`) से अपनी `SERVICES[]` प्रविष्टि प्राप्त करता है,
और यदि प्लगइन कभी अनुपस्थित हो तो स्टार्टअप त्रुटि उत्पन्न करता है। `cliproxy`, `mux`, और `bifrost`
पहले से मौजूद इनलाइन `SERVICES[]` लिटरल पर अपरिवर्तित बने हुए हैं।

`open-sse/config/providerPluginManifest.ts` में एक अतिरिक्त
`createServiceBackendManifestEntry(pluginId, template)` हेल्पर भी जोड़ा गया है, जो किसी
`SERVICE_BACKEND_MANIFEST_TEMPLATE` प्रविष्टि से एक सुव्यवस्थित
`ProviderPluginManifestEntry` बनाता है — इसे अभी तक किसी भी सक्रिय अनुरोध पाथ में
**नहीं** जोड़ा गया है (न तो `generateProviderPluginManifestFromRegistry()` में,
न ही `/v1/providers/[provider]/models` में); अनुबंध के दूसरे बैकएंड के लिए प्रमाणित होने तक
यह अनुवर्ती कार्य बना रहेगा।

अनुवर्ती PRs के लिए स्थगित, issue #7333 के अंतर्गत ट्रैक किया गया: उसी रजिस्ट्री के माध्यम से
`cliproxyapi` को माइग्रेट करना, `mux`/`bifrost` को `ServiceBackendPluginId` यूनियन में
सामान्यीकृत करना, एक्ज़ीक्यूटर-रूटिंग के विशेष प्रबंधन (`open-sse/executors/index.ts`,
`open-sse/handlers/chatCore/executorProxy.ts`) को प्लगइन अनुबंध में समाहित करना, और
`createServiceBackendManifestEntry()` को सक्रिय मैनिफ़ेस्ट/मॉडल कोड पाथ में जोड़ना।

### चरण 3 — माइग्रेशन और DB सीड जोड़ें

### चरण 4 — 7 API एंडपॉइंट बनाएँ

`src/app/api/services/{name}/` के अंतर्गत:

`LOCAL_ONLY_API_PREFIXES` और, यदि वह प्रक्रियाएँ शुरू करता है, तो `SPAWN_CAPABLE_PREFIXES`
दोनों में जोड़ें। `tests/unit/authz/routeGuard.test.ts` में एक परीक्षण जोड़ें।

### चरण 7 — प्रोवाइडर प्रविष्टि जोड़ें (यदि सेवा एक रूटिंग लक्ष्य है)

यदि एम्बेडेड सेवा OpenAI-संगत `/v1/chat/completions` एंडपॉइंट उपलब्ध कराती है:

1. `src/shared/constants/providers.ts` में `isEmbeddedService: true` के साथ एक प्रोवाइडर प्रविष्टि जोड़ें।
2. `BaseExecutor` को एक्सटेंड करने वाली `open-sse/executors/{name}.ts` बनाएँ। प्रत्येक अनुरोध पर पोर्ट और
   API कुंजी को फिर से खोजें (कंस्ट्रक्टर में कभी कैश न करें)। जब सुपरवाइज़र स्थिति `"running"` न हो,
   तब `503 service_not_running` प्रतिक्रिया लौटाएँ।
3. सेवा प्रीफ़िक्स के साथ `open-sse/config/providerRegistry.ts` में मॉडल पंजीकृत करें
   (जैसे, `myservice/sub/model`)। `modelSync.ts` उन्हें अपडेट रखेगा।

### चरण 8 — दस्तावेज़ बनाएँ और परीक्षण करें

1. `docs/frameworks/EMBEDDED-SERVICES.md` (यह फ़ाइल) अपडेट करें — सेवा को
   §1 की तालिका में और किसी भी नए एंडपॉइंट को §4 में जोड़ें।
2. `tests/unit/services/` में यूनिट परीक्षण जोड़ें (जीवनचक्र, इंस्टॉलर, API संरचना)।
3. `tests/integration/services/` में इंटीग्रेशन परीक्षण जोड़ें (`RUN_SERVICES_INT=1` के पीछे)।
4. नए एंडपॉइंट्स के साथ `docs/openapi.yaml` अपडेट करें।

## 7. समस्या निवारण

### सेवा शुरू नहीं होती

**लक्षण:** Start बटन 503 लौटाता है, स्थिति `"error"` या `"starting"` पर बनी रहती है।

**जाँच-सूची:**

1. `GET /api/services/{name}/logs` जाँचें (या डैशबोर्ड में Logs पैनल)। `Error: ENOENT`,
   `address already in use`, या `Cannot find module` जैसी पंक्तियाँ खोजें।
2. सत्यापित करें कि `npm` PATH में है: OmniRoute चलाने वाले उसी उपयोगकर्ता खाते से `which npm` चलाएँ।
3. सत्यापित करें कि सेवा इंस्टॉल की गई है: `installedVersion` के लिए
   `GET /api/services/{name}/status` जाँचें। यदि यह `null` है, तो पहले इंस्टॉल चलाएँ।
4. जाँचें कि `DATA_DIR/services/{name}/node_modules/` मौजूद है और खाली नहीं है।
5. संशोधित निकास कारण के लिए स्थिति प्रतिक्रिया में `lastError` फ़ील्ड जाँचें।

---

### कोल्ड स्टार्ट धीमा है (`running` तक पहुँचने में > 10 सेकंड)

**लक्षण:** स्थिति `"running"` या `"error"` में जाने से पहले लंबे समय तक `"starting"` पर बनी रहती है।

**व्याख्या:** 9Router के कोल्ड स्टार्ट में बड़े डिपेंडेंसी ट्री (DNS,
टनल, MITM मॉड्यूल) आयात करना शामिल है। डिफ़ॉल्ट स्वास्थ्य अंतराल 2 सेकंड है और
सुपरवाइज़र द्वारा टाइमआउट घोषित करने से पहले 3 प्रयास किए जाते हैं (लेकिन पोलिंग जारी रहती है)।

**समाधान:** `healthIntervalMs` और `waitForHealthy` टाइमआउट
(`healthIntervalMs * 3`) को `bootstrap.ts` में कॉन्फ़िगर किया जा सकता है। अधिक
स्टार्टअप समय वाली सेवाओं के लिए, `healthIntervalMs` को 5000 और `stopTimeoutMs` को 30 000 तक बढ़ाएँ।

---

### पोर्ट टकराव (`EADDRINUSE`)

**लक्षण:** लॉग में `address already in use :::20130` दिखाई देता है।

**कारण:**

- कोई अन्य प्रोसेस पहले से पोर्ट 20130 का उपयोग कर रहा है।
- पिछला 9Router प्रोसेस पूरी तरह बंद नहीं हुआ था (ज़ॉम्बी PID)।

**समाधान:**

1. `.env` में `NINEROUTER_PORT` एनवायरनमेंट वेरिएबल के माध्यम से डिफ़ॉल्ट पोर्ट बदलें।
2. टकराव उत्पन्न करने वाले प्रोसेस को खोजकर समाप्त करें: `lsof -ti :20130 | xargs kill -9`।
3. पोर्ट को `bootstrap.ts` में `port` फ़ील्ड के माध्यम से प्रत्येक सेवा के लिए कॉन्फ़िगर किया जा सकता है।

**नोट:** OmniRoute के डिफ़ॉल्ट पोर्ट 20128 से टकराव से बचने के लिए
9Router विशेष रूप से पोर्ट 20130 का उपयोग करता है।

---

### इंस्टॉल करते समय अनुमति अस्वीकृत (EACCES)

**लक्षण:** इंस्टॉल 500 लौटाता है, लॉग में `EACCES` या `permission denied` दिखाई देता है।

**कारण:**

- `DATA_DIR` या इसकी पैरेंट डायरेक्टरी OmniRoute प्रोसेस द्वारा लिखने योग्य नहीं है।
- मैप किए गए वॉल्यूम पर लिखने की अनुमति के बिना रूटलेस Docker के अंदर चलाना।

**समाधान:**

1. `DATA_DIR` जाँचें (डिफ़ॉल्ट: `~/.omniroute/`): `ls -la ~/.omniroute/`
2. सुनिश्चित करें कि OmniRoute प्रोसेस का उपयोगकर्ता डायरेक्टरी का स्वामी है: `chown -R $USER ~/.omniroute/`
3. Docker में, सुनिश्चित करें कि वॉल्यूम माउंट के पास कंटेनर उपयोगकर्ता के लिए सही अनुमतियाँ हैं।

---

### अपडेट विफल होता है (`npm install` टाइमआउट या नेटवर्क त्रुटि)

**लक्षण:** अपडेट `InstallError` के साथ 500 लौटाता है, लॉग में नेटवर्क टाइमआउट दिखाई देता है।

**जाँच-सूची:**

1. पुष्टि करें कि npm रजिस्ट्री पहुँच योग्य है: `npm ping`।
2. कॉर्पोरेट प्रॉक्सी की जाँच करें: `npm config get proxy`, `npm config get https-proxy`।
3. इंस्टॉल को मैन्युअल रूप से आज़माएँ: `npm install {package}@latest --prefix ~/.omniroute/services/{name}/`।
4. यदि एयर-गैप के पीछे हैं, तो tarball पहले से डाउनलोड करें और `npm install /path/to/tarball.tgz` का उपयोग करें।

---

### सेवा शुरू होने के तुरंत बाद `"error"` स्थिति दिखाती है (तेज़ क्रैश)

**लक्षण:** स्थिति 5 सेकंड से कम समय में `"starting"` से `"error"` में बदल जाती है।
`lastError` में `"Fast crash (exited with code 1)"` दिखाई देता है।

**जाँच-सूची:**

1. पूरा लॉग टेल पढ़ें: `GET /api/services/{name}/logs?tail=500`।
2. सामान्य कारण: सेवा द्वारा अपेक्षित एनवायरनमेंट वेरिएबल अनुपस्थित होना।
3. 9Router के लिए: सत्यापित करें कि `NINEROUTER_DISABLE_MITM=true` और
   `NINEROUTER_DISABLE_TUNNEL=true` स्पॉन के समय पास किए गए env में हैं (`installers/ninerouter.ts`
   के `resolveSpawnArgs` को देखें)।

---

## 8. अक्सर पूछे जाने वाले प्रश्न

**प्रश्न: क्या मैं एम्बेडेड सेवाओं के एंडपॉइंट्स को गैर-लूपबैक क्लाइंट्स के लिए उपलब्ध करा सकता हूँ?**

नहीं। LOCAL_ONLY टियर जानबूझकर लागू किया गया है (कठोर नियम #17)। वे रूट, जो
`npm install` चला सकते हैं या `node` प्रक्रियाएँ शुरू कर सकते हैं, गैर-लूपबैक
ट्रैफ़िक से पहुँच योग्य नहीं होने चाहिए, क्योंकि टनल (Cloudflare, Ngrok, Tailscale) के माध्यम से लीक हुआ JWT
अन्यथा मनमानी प्रक्रियाएँ शुरू करने की अनुमति दे देगा। `/api/services/` के लिए
इससे बाहर निकलने का कोई अपवाद नहीं है — `/api/mcp/` के विपरीत, इसे manage-scope बायपास
सूची से बाहर रखा गया है। `docs/security/ROUTE_GUARD_TIERS.md` देखें।

---

**प्रश्न: क्या 9Router और CLIProxyAPI प्रोडक्शन/क्लाउड परिनियोजनों में उपलब्ध होंगे?**

हाँ। दोनों सेवाएँ OmniRoute के समान local-first मॉडल का पालन करती हैं। वे
उसी मशीन पर चलती हैं और लूपबैक के माध्यम से संचार करती हैं। यहाँ "प्रोडक्शन" का अर्थ वह VPS
या स्थानीय सर्वर है जहाँ OmniRoute परिनियोजित है, न कि कोई रिमोट क्लाउड प्रदाता।

---

**प्रश्न: मैं सुपरवाइज़र को डीबग कैसे करूँ?**

1. SSE लॉग स्ट्रीम को लगातार देखें: `curl -N http://localhost:20128/api/services/9router/logs`।
2. OmniRoute के pino आउटपुट में संरचित लॉग जाँचें, जिन्हें
   `service:supervisor` नेमस्पेस के अनुसार फ़िल्टर किया गया हो।
3. DB पंक्ति का निरीक्षण करें: `sqlite3 ~/.omniroute/omniroute.db "SELECT * FROM version_manager WHERE tool='9router'"`।
4. वर्तमान लाइव स्थिति, PID, स्वास्थ्य और `lastError` को एक ही कॉल में देखने के लिए
   `GET /api/services/9router/status` का उपयोग करें।

---

**प्रश्न: सुपरवाइज़र `health: "degraded"` या `health: "unknown"` दिखाता है, लेकिन स्थिति `"running"` है। क्या यह कोई समस्या है?**

`"degraded"` का अर्थ है कि स्वास्थ्य जाँच ने गैर-200 प्रतिक्रिया लौटाई। `"unknown"` का अर्थ है कि
अभी तक कोई जाँच पूरी नहीं हुई है (पहले पोल के साथ रेस)। स्टार्टअप के दौरान दोनों स्थितियाँ अस्थायी होती हैं।
यदि `"running"` के बाद `healthIntervalMs * 3` ms से अधिक समय तक स्वास्थ्य स्थिति
`"degraded"` बनी रहती है, तो एम्बेडेड सेवा चल रही है, लेकिन उसका HTTP API प्रतिक्रिया नहीं दे रहा है। जाँचें
कि स्थिति प्रतिक्रिया में पोर्ट सही है या नहीं और सेवा वास्तव में
उस पोर्ट पर सुन रही है या नहीं।

---

**प्रश्न: क्या मैं पूर्ण रीस्टार्ट के बिना 9Router API कुंजी बदल सकता हूँ?**

नहीं। API कुंजी 9Router को प्रक्रिया शुरू होते समय एक पर्यावरण चर के माध्यम से दी जाती है।
चल रही प्रक्रिया में पर्यावरण चर बदले नहीं जा सकते। `POST .../rotate-key`
नई कुंजी लागू करने के लिए सेवा को स्वचालित रूप से रोककर पुनः शुरू करता है। कुंजी रोटेशन
सेवा के `stopTimeoutMs` (डिफ़ॉल्ट 15 s) और उसके स्टार्टअप
समय के भीतर प्रभावी हो जाता है।

---

**प्रश्न: रिंग बफ़र की सीमा क्या है और इसके भर जाने पर क्या होता है?**

प्रत्येक सेवा के पास एक समर्पित 5 MB रिंग बफ़र होता है। बफ़र भर जाने पर, नई लॉग
पंक्तियों के लिए स्थान बनाने हेतु सबसे पुरानी पंक्तियाँ हटा दी जाती हैं। SSE `snapshot` इवेंट
`tail` सीमा के भीतर की सबसे हालिया पंक्तियाँ लौटाता है। लॉग्स डिस्क पर स्थायी रूप से संग्रहीत नहीं किए जाते, जब तक कि
DB पंक्ति में `logsBufferPath` सेट न किया गया हो।
