> **अंतिम बार अपडेट किया गया:** 2026-06-28 — v3.8.40 (फ्रंटमैटर रीफ़्रेश; cursor-cloud सहित 4 एजेंट)

OmniRoute तृतीय-पक्ष क्लाउड-होस्टेड कोडिंग एजेंटों (Codex Cloud, Cursor,
Devin, Jules) को लंबे समय तक चलने वाले कार्यों के रूप में समन्वित करता है। प्रत्येक एजेंट को एक समान इंटरफ़ेस के पीछे रैप किया गया है, ताकि
क्लाइंट प्रदाता-विशिष्ट API से निपटे बिना एक प्रॉम्प्ट + रिपॉज़िटरी URL सबमिट कर सकें और परिणाम प्राप्त कर सकें।

Cloud Agent कार्य कोई नियमित चैट कम्प्लीशन **नहीं** है। यह कार्य की एक टिकाऊ, बहु-चरणीय
इकाई है जिसे पूरा होने में मिनटों से लेकर घंटों तक का समय लग सकता है, जो अपने
आर्टिफ़ैक्ट के रूप में Pull Request बना सकती है, और फ़ॉलो-अप संदेशों तथा (कुछ प्रदाताओं में) योजना अनुमोदन गेट का समर्थन करती है।

## आर्किटेक्चर

```
क्लाइंट (डैशबोर्ड / CLI / API)
  → POST /api/v1/agents/tasks (प्रबंधन प्रमाणीकरण आवश्यक)
    → CreateCloudAgentTaskSchema सत्यापन (Zod)
    → registry.getAgent(providerId)
    → getCloudAgentCredentials(providerId)
      └─ getProviderConnections({ provider, isActive: true }) से प्राप्त करता है
         (पहले apiKey, फ़ॉलबैक के रूप में accessToken)
    → agent.createTask({ prompt, source, options }, credentials)
      └─ अपस्ट्रीम प्रदाता API को HTTP POST
      └─ आंतरिक id + externalId के साथ CloudAgentTask लौटाता है
    → cloud_agent_tasks (SQLite) में insertCloudAgentTask(...)

पोलिंग (रीड पर लेज़ी सिंक):
  GET /api/v1/agents/tasks/[id]
    → getCloudAgentTaskById(id)
    → agent.getStatus(externalId, credentials)  // स्थिति + गतिविधियों को रीफ़्रेश करता है
    → नई स्थिति, परिणाम, completed_at के साथ updateCloudAgentTask(...)
    → सीरियलाइज़ किया गया कार्य लौटाता है

इंटरैक्शन:
  POST /api/v1/agents/tasks/[id]  बॉडी: { action: "approve" | "message" | "cancel" }
    → agent.approvePlan(externalId, credentials)        "approve" के लिए
    → agent.sendMessage(externalId, message, credentials) "message" के लिए
    → स्थिति "cancelled" में बदल जाती है               "cancel" के लिए (केवल स्थानीय)
```

सिंक **लेज़ी** है: प्रत्येक `GET /tasks/[id]` पर स्थिति को अपस्ट्रीम से रीफ़्रेश किया जाता है।
कोई बैकग्राउंड पोलर नहीं है। जिन डैशबोर्ड को ताज़ा स्थिति चाहिए, उन्हें उचित अंतराल पर GET
एंडपॉइंट को पोल करना चाहिए।

## `CloudAgentBase` इंटरफ़ेस

स्रोत: `src/lib/cloudAgent/baseAgent.ts`

```typescript
export interface AgentCredentials {
  apiKey: string;
  baseUrl?: string;
}

export interface CreateTaskParams {
  prompt: string;
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
}

export interface GetStatusResult {
  status: CloudAgentStatus;
  externalId?: string;
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
}

export abstract class CloudAgentBase {
  abstract readonly providerId: string;
  abstract readonly baseUrl: string;

  abstract createTask(p: CreateTaskParams, c: AgentCredentials): Promise<CloudAgentTask>;
  abstract getStatus(externalId: string, c: AgentCredentials): Promise<GetStatusResult>;
  abstract approvePlan(externalId: string, c: AgentCredentials): Promise<void>;
  abstract sendMessage(
    externalId: string,
    message: string,
    c: AgentCredentials
  ): Promise<CloudAgentActivity>;
  abstract listSources(
    c: AgentCredentials
  ): Promise<{ name: string; url: string; branch?: string }[]>;

  protected mapStatus(raw: string): CloudAgentStatus; // अनुमान-आधारित अपस्ट्रीम स्ट्रिंग → enum
  protected generateTaskId(): string; // `task_<ts>_<rand>`
  protected generateActivityId(): string; // `act_<ts>_<rand>`
}
```

`CodexCloudAgent.approvePlan` जानबूझकर त्रुटि उत्पन्न करता है — Codex Cloud स्वतः योजना बनाता है और इसमें
कोई अनुमोदन द्वार नहीं है। `CodexCloudAgent.listSources`, `[]` लौटाता है।

`CursorCloudAgent`, Cursor के Background / Cloud Agents को उसकी आधिकारिक REST
API (`api.cursor.com/v0`) के माध्यम से **उपयोगकर्ता या सेवा-खाता API कुंजी** के साथ संचालित करता है — यह Cursor IDE के OAuth सत्र का पुनः उपयोग करने का अधिक सुरक्षित,
प्रथम-पक्ष विकल्प है (प्रदाता `cursor`,
जिसमें प्रतिबंध के जोखिम की चेतावनी होती है)। यह एक सामान्य REST अडैप्टर है (कोई `@cursor/sdk` नेटिव
निर्भरता नहीं)। `approvePlan` त्रुटि उत्पन्न करता है (Cursor एजेंट स्वायत्त रूप से चलते हैं); `listSources`
कुंजी द्वारा पहुँच योग्य रिपॉज़िटरी सूचीबद्ध करता है। Cursor अपरकेस स्थिति enum
(`CREATING`/`RUNNING`/`FINISHED`/`ERROR`) लौटाता है, जिन्हें स्पष्ट रूप से साझा
`CloudAgentStatus` पर मैप किया जाता है। `baseUrl` को प्रत्येक क्रेडेंशियल के अनुसार ओवरराइड किया जा सकता है, ताकि API संस्करण/पथ को
कोड बदले बिना ठीक किया जा सके।

## डोमेन प्रकार

स्रोत: `src/lib/cloudAgent/types.ts`

```typescript
export const CLOUD_AGENT_STATUS = {
  QUEUED: "queued",
  RUNNING: "running",
  AWAITING_APPROVAL: "awaiting_approval",
  COMPLETED: "completed",
  FAILED: "failed",
  CANCELLED: "cancelled",
} as const;

export interface CloudAgentSource {
  repoName: string;
  repoUrl: string; // एक मान्य URL होना चाहिए
  branch?: string;
}

export interface CloudAgentResult {
  prUrl?: string;
  prNumber?: number;
  commitMessage?: string;
  diffUrl?: string;
  summary?: string;
  duration?: number; // सेकंड, धनात्मक पूर्णांक
  cost?: number; // धनात्मक फ़्लोट
}

export interface CloudAgentActivity {
  id: string;
  type: "plan" | "command" | "code_change" | "message" | "error" | "completion";
  content: string;
  timestamp: string; // ISO 8601
  metadata?: Record<string, unknown>;
}

export interface CloudAgentTask {
  id: string; // आंतरिक `task_...` आईडी
  providerId: "jules" | "devin" | "codex-cloud" | "cursor-cloud";
  externalId?: string; // अपस्ट्रीम प्रदाता की आईडी
  status: CloudAgentStatus;
  prompt: string; // 1..10000 वर्ण
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
  createdAt: string;
  updatedAt: string;
  completedAt?: string;
}
```

सत्यापन स्कीमा (`CreateCloudAgentTaskSchema`, `UpdateCloudAgentTaskSchema`) को
प्रकारों के साथ एक्सपोर्ट किया जाता है और रूट हैंडलर द्वारा उपयोग किया जाता है।

## डेटाबेस

स्रोत: `src/lib/cloudAgent/db.ts` — तालिका को
`createCloudAgentTaskTable()` के माध्यम से आवश्यकतानुसार बनाया जाता है (`src/lib/cloudAgent/index.ts` से
मॉड्यूल इंपोर्ट के समय भी कॉल किया जाता है)।

```sql
CREATE TABLE IF NOT EXISTS cloud_agent_tasks (
  id           TEXT PRIMARY KEY,
  provider_id  TEXT NOT NULL,
  external_id  TEXT,
  status       TEXT NOT NULL DEFAULT 'queued',
  prompt       TEXT NOT NULL,
  source       TEXT NOT NULL,             -- JSON
  options      TEXT DEFAULT '{}',         -- JSON
  result       TEXT,                       -- JSON
  activities   TEXT DEFAULT '[]',          -- JSON
  error        TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_provider ON cloud_agent_tasks(provider_id);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_status   ON cloud_agent_tasks(status);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_created  ON cloud_agent_tasks(created_at DESC);
```

SQL इंजेक्शन को रोकने के लिए `updateCloudAgentTask` एक **कॉलम श्वेतसूची** लागू करता है:
`status`, `prompt`, `source`, `options`, `result`, `activities`, `error`,
`completed_at`। आंशिक अपडेट में मौजूद किसी भी अन्य कुंजी को बिना किसी सूचना के हटा दिया जाता है।

## REST API — कार्य जीवनचक्र

**प्रमाणीकरण:** सभी `/api/v1/agents/tasks*` एंडपॉइंट के लिए **प्रबंधन प्रमाणीकरण**
आवश्यक है (`requireCloudAgentManagementAuth`, `src/lib/api/requireManagementAuth` के
`requireManagementAuth` को रैप करता है)। इसे कमिट `588a0333`
(_"fix(auth): एजेंट और कूलडाउन API के लिए प्रबंधन प्रमाणीकरण आवश्यक करें"_) के बाद लागू किया गया है।

| विधि    | पथ                            | उद्देश्य                                                                  |
| ------- | ----------------------------- | ------------------------------------------------------------------------- |
| OPTIONS | `/api/v1/agents/tasks`        | CORS प्रीफ़्लाइट                                                          |
| GET     | `/api/v1/agents/tasks`        | कार्यों की सूची प्राप्त करें (फ़िल्टर: `provider`, `status`, `limit≤500`) |
| POST    | `/api/v1/agents/tasks`        | कार्य बनाएँ (अपस्ट्रीम को भेजता है + सहेजता है)                           |
| DELETE  | `/api/v1/agents/tasks?id=...` | क्वेरी आईडी से कार्य हटाएँ (अपस्ट्रीम को रद्द **नहीं** करता)              |
| OPTIONS | `/api/v1/agents/tasks/[id]`   | CORS प्रीफ़्लाइट                                                          |
| GET     | `/api/v1/agents/tasks/[id]`   | कार्य पढ़ें + अपस्ट्रीम से स्थिति को लेज़ी-सिंक करें                      |
| POST    | `/api/v1/agents/tasks/[id]`   | कार्रवाई: `approve` / `message` / `cancel`                                |
| DELETE  | `/api/v1/agents/tasks/[id]`   | पथ आईडी से कार्य हटाएँ                                                    |

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \

  -H "Content-Type: application/json" \
  -d '{

    "prompt": "Fix the bug in src/foo.ts where the parser returns null",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"

    "options": {
      "autoCreatePr": true,

  }'
```

```bash

```

### रद्द करें (केवल स्थानीय स्थिति)

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"cancel"}'
```

`cancel` स्थानीय DB में `status` को `"cancelled"` में बदल देता है, लेकिन
अपस्ट्रीम प्रदाता को कॉल **नहीं** करता — `CloudAgentBase` में कोई निरस्तीकरण RPC नहीं है। अपस्ट्रीम
बिलिंग रोकने के लिए, प्रदाता के अपने कंसोल में कार्य समाप्त करें।

## REST API — क्लाउड प्रोवाइडर प्लंबिंग

`src/app/api/cloud/` के अंतर्गत ये सहायक एंडपॉइंट रिमोट क्लाइंट
(CLI, Electron ऐप या सिंक वर्कर) द्वारा प्रोवाइडर कनेक्शन मेटाडेटा पढ़ने
और मॉडल एलियास रिज़ॉल्व करने के लिए उपयोग किए जाते हैं। इन्हें टास्क एंडपॉइंट द्वारा उपयोग किए जाने वाले मैनेजमेंट ऑथ के बजाय **नियमित API कुंजी**
(`validateApiKey` के माध्यम से) से प्रमाणित किया जाता है।

| विधि | पथ                              | उद्देश्य                                                                      |
| ---- | ------------------------------- | ----------------------------------------------------------------------------- |
| POST | `/api/cloud/auth`               | API कुंजी सत्यापित करना, मास्क किया हुआ कनेक्शन मेटाडेटा + मॉडल एलियास लौटाना |
| PUT  | `/api/cloud/credentials/update` | `accessToken` / `refreshToken` / `expiresAt` रीफ़्रेश करना                    |
| POST | `/api/cloud/model/resolve`      | मॉडल एलियास को `{ provider, model }` में रिज़ॉल्व करना                        |
| GET  | `/api/cloud/models/alias`       | सभी मॉडल एलियास सूचीबद्ध करना                                                 |
| PUT  | `/api/cloud/models/alias`       | मॉडल एलियास सेट करना (और सक्षम होने पर Cloud से अपने-आप सिंक करना)            |

`/api/cloud/auth` कभी भी अपरिष्कृत `apiKey` / `accessToken` / `refreshToken` नहीं लौटाता। यह
`hasApiKey`, `hasAccessToken`, `hasRefreshToken` और एक मास्क किया हुआ पूर्वावलोकन
(`maskedApiKey`: पहले 4 + `****` + अंतिम 4) लौटाता है।

## क्रेडेंशियल रिज़ॉल्यूशन

`src/lib/cloudAgent/api.ts` में `getCloudAgentCredentials(providerId)`:

1. `getProviderConnections({ provider: providerId, isActive: true })` के माध्यम से सक्रिय प्रोवाइडर कनेक्शन लोड करता है।
2. प्रत्येक कनेक्शन के लिए `apiKey` (ट्रिम किया हुआ) को प्राथमिकता देता है। उपलब्ध न होने पर `accessToken` का उपयोग करता है।
3. पहले गैर-रिक्त टोकन को `{ apiKey: token }` के रूप में रैप करके लौटाता है।
4. यदि कोई उपयोग योग्य टोकन नहीं मिलता, तो `null` लौटाता है — API `400` के साथ
   `"क्लाउड एजेंट प्रोवाइडर के लिए कोई सक्रिय क्रेडेंशियल कॉन्फ़िगर नहीं है: <id>"` लौटाता है।

इसका अर्थ है कि Cloud Agents नियमित LLM प्रोवाइडर की तरह उसी Provider Connection तालिका का पुनः उपयोग करते हैं।
Jules को सक्षम करने के लिए `provider: "jules"` और भरे हुए `apiKey` वाला एक सक्रिय कनेक्शन बनाएँ।

## डैशबोर्ड

स्रोत: `src/app/(dashboard)/dashboard/cloud-agents/page.tsx`

एक `"use client"` React पेज जो:

- टास्क सूचीबद्ध करता है (`GET /api/v1/agents/tasks` के माध्यम से नियमित रूप से पोल किए जाते हैं)।
- `CreateCloudAgentTaskSchema` से मैप होने वाले फ़ॉर्म के माध्यम से नए टास्क सबमिट करता है।
- स्टेटस बैज (`queued`, `running`, `awaiting_approval`, `completed`,
  `failed`, `cancelled`) दिखाता है और `activities[]` टाइमलाइन रेंडर करता है।
- जब `status === "completed"` हो, तब `result.prUrl` / `commitMessage` / `summary` प्रदर्शित करता है।

## A2A के साथ एकीकरण

Cloud Agents को एक ऐसा A2A स्किल पंजीकृत करके A2A स्किल के रूप में उपलब्ध कराया जा सकता है, जो
अपने `tasks/send` हैंडलर को `getAgent(...).createTask(...)` को डेलीगेट करता है और A2A टास्क
स्टेटस इवेंट को JSON-RPC 2.0 प्रोटोकॉल में रूपांतरित करता है। [A2A-SERVER.md](./A2A-SERVER.md) देखें।

## नया Cloud Agent जोड़ना

1. `CloudAgentBase` को एक्सटेंड करने वाली `src/lib/cloudAgent/agents/<name>.ts` फ़ाइल बनाएँ।
2. `createTask`, `getStatus`, `approvePlan` (या लागू न होने पर त्रुटि थ्रो करें),
   `sendMessage`, `listSources` इम्प्लीमेंट करें। स्टेटस सामान्यीकरण के लिए `this.mapStatus(...)` का उपयोग करें।
3. एक स्थिर `providerId` के अंतर्गत `src/lib/cloudAgent/registry.ts` में पंजीकृत करें।
4. `src/lib/cloudAgent/types.ts` में `providerId` लिटरल यूनियन को विस्तारित करें
   (`CloudAgentTask.providerId` और `CreateCloudAgentTaskSchema`)।
5. यदि प्रोवाइडर को कनेक्शन रिकॉर्ड की आवश्यकता है, तो उसे `src/shared/constants/providers.ts` में जोड़ें।
   OAuth-आधारित प्रोवाइडर के लिए `src/lib/oauth/providers/` भी आवश्यक है।
6. `tests/unit/cloud-agent-*.test.ts` के अंतर्गत टेस्ट जोड़ें।
7. इस दस्तावेज़ और डैशबोर्ड के `CLOUD_AGENTS` कॉन्स्टेंट को अपडेट करें।
