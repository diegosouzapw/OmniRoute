1. मौजूदा single-key semaphore अनुबंध और नए atomic multi-key अनुबंध को केंद्रित परीक्षणों के साथ सुनिश्चित करें: कोई आंशिक reservation नहीं, FIFO queueing, abort, timeout, queue-full, idempotent release, stats, और cleanup।
2. मौजूदा account semaphore को उसी स्थान पर सामान्यीकृत करें। `acquire()` को `acquireMany()` के compatibility wrapper के रूप में बनाए रखें; दूसरा scheduler या dependency न जोड़ें।
3. `chatCore` में account-only acquisition को `withRateLimit` से ठीक पहले एक संचयी global/provider/account acquisition से बदलें। जब भी account rotation से connection बदले, पूरे set को फिर से acquire करें, और streaming पूरी होने तक release को बनाए रखें।
4. मौजूदा resilience settings pipeline (types, defaults, normalization, schema, API response, UI, और translations) को global और provider caps के साथ विस्तारित करें। पुराने Bottleneck concurrency control को connection/quota-scope concurrency के रूप में पुनः लेबल करें, ताकि उसका वास्तविक scope स्पष्ट हो।
5. केंद्रित tests, lint, typecheck, static checks, और पूरा test suite चलाएँ; behavioral change को changelog में दर्ज करें।

जानबूझकर संरक्षित व्यवहार: zero/null concurrency किसी gate को bypass करती है, account-only callers `acquire()` का उपयोग जारी रखते हैं, blocked-account controls अपना key format और API बनाए रखते हैं, और provider rate-limit queue का व्यवहार अपरिवर्तित रहता है।
