यह दस्तावेज़
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854) के लिए कार्यान्वयन निर्णय दर्ज करता है। सार्वजनिक उत्पादों को
चार प्रदाता परिवारों के रूप में दर्शाया गया है। क्षेत्र कनेक्शन डेटा है, कोई अलग उत्पाद नहीं।

## निर्णय

| प्रदाता परिवार                                      | OmniRoute ID            | वैश्विक क्षेत्र | चीन क्षेत्र |
| --------------------------------------------------- | ----------------------- | --------------- | ----------- |
| Alibaba Cloud Model Studio (उपयोग के अनुसार भुगतान) | `alibaba`               | सिंगापुर        | बीजिंग      |
| Alibaba Cloud Token Plan                            | `bailian-coding-plan`   | सिंगापुर        | बीजिंग      |
| Qwen Cloud (उपयोग के अनुसार भुगतान)                 | `qwen-cloud`            | वैश्विक         | बीजिंग      |
| Qwen Cloud Token Plan                               | `qwen-cloud-token-plan` | सिंगापुर        | बीजिंग      |

मौजूदा `alibaba-cn` ID सहेजे गए कनेक्शनों, मॉडल
रूटों, कॉम्बो और ऐतिहासिक उपयोग के लिए रनटाइम संगतता उपनाम बना रहेगा। इसका डैशबोर्ड कार्ड `alibaba` में समाहित कर दिया गया है; डेटाबेस को
दोबारा लिखने की आवश्यकता नहीं है।

Qwen Cloud का उपयोग के अनुसार भुगतान वाला उत्पाद और Alibaba Cloud Model Studio वर्तमान में DashScope-संगत
रनटाइम होस्ट साझा करते हैं, लेकिन वे अलग प्रदाता पहचान बने रहते हैं क्योंकि उपयोगकर्ता अलग-अलग उत्पाद इंटरफ़ेस के माध्यम से कुंजियाँ प्राप्त करते और
खातों का प्रबंधन करते हैं। Alibaba और Qwen Cloud Token Plan उत्पाद अलग-अलग एंडपॉइंट परिवारों का उपयोग करते हैं,
इसलिए सभी चार उत्पाद अलग प्रदाता ID बने रहते हैं।

## एंडपॉइंट मैट्रिक्स

| प्रदाता परिवार          | `global-sg`                                                              | `china-beijing`                                                      | वायर प्रारूप |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ------------ |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI       |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic    |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI       |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI       |

API कुंजी और एंडपॉइंट एक ही उत्पाद और क्षेत्र से संबंधित होने चाहिए। किसी क्षेत्र का चयन करने पर
सत्यापन और सामान्य अनुरोधों द्वारा उपयोग किया जाने वाला प्रीसेट एंडपॉइंट बदल जाता है।

## कनेक्शन अनुबंध

नए कनेक्शन स्थिर क्षेत्र कुंजी को `providerSpecificData` में संग्रहीत करते हैं:

```json
{
  "region": "global-sg"
}
```

अनुमत मान `global-sg` और `china-beijing` हैं। एंडपॉइंट को
प्रदाता ID और क्षेत्र के आधार पर केंद्रीय रूप से निर्धारित किया जाता है। गैर-प्रीसेट `providerSpecificData.baseUrl` स्पष्ट ऑपरेटर
ओवरराइड बना रहता है और उसे प्राथमिकता दी जाती है, जबकि पुराने सहेजे गए प्रीसेट URL को फिर से क्षेत्रीय
मैट्रिक्स के अनुरूप सामान्यीकृत किया जाता है।

इससे कनेक्शन स्कीमा विस्तार योग्य बना रहता है: किसी अन्य क्षेत्र को रिज़ॉल्वर में जोड़ा जा सकता है, बिना
किसी अन्य प्रदाता कार्ड को बनाए या सहेजे गए प्रदाता ID को बदले।

## संगतता और रोलआउट

1. क्षेत्रीय एंडपॉइंट रिज़ॉल्वर जोड़ें और वर्तमान वैश्विक डिफ़ॉल्ट बनाए रखें।
2. `alibaba`, इसकी `alibaba-cn` संगतता ID और `qwen-cloud` के लिए लाइव क्षेत्रीय DashScope `/models` डिस्कवरी का उपयोग करें। उनके प्रतिसाद पहले एक टेक्स्ट-जनरेशन फ़िल्टर से गुज़रते हैं, क्योंकि जेनेरिक एंडपॉइंट इमेज, वीडियो, ऑडियो, एम्बेडिंग और अन्य गैर-चैट मॉडल भी लौटाता है। इसके बाद `qwen-cloud` अपनी प्रोवाइडर रजिस्ट्री में घोषित अनुरक्षित अनुमत-सूची लागू करता है। Alibaba Model Studio और Qwen Cloud अलग-अलग क्यूरेटेड कैटलॉग बनाए रखते हैं, भले ही वे वर्तमान में समान रनटाइम होस्ट साझा करते हों।
3. वर्तमान Token Plan टेक्स्ट-मॉडल अनुमत-सूची के साथ `qwen-cloud-token-plan` को पंजीकृत करें।
4. कनेक्शन जोड़ने/संपादित करने वाले डायलॉग में टाइपयुक्त क्षेत्र चयनकर्ता जोड़ें।
5. डुप्लिकेट `alibaba-cn` कार्ड छिपाएँ और उसके मौजूदा कनेक्शन `alibaba` प्रोवाइडर पेज पर शामिल करें।
6. उन्नत और वर्कस्पेस-विशिष्ट डिप्लॉयमेंट के लिए कस्टम एंडपॉइंट ओवरराइड उपलब्ध रखें।

Token Plan मीडिया मॉडल चैट कैटलॉग से बाहर रहते हैं, क्योंकि वे समर्पित एंडपॉइंट का उपयोग करते हैं।
`wan2.7-image` और `wan2.7-image-pro`, `open-sse/config/imageRegistry.ts` में पंजीकृत हैं;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, और `happyhorse-1.1-r2v`,
`open-sse/config/videoRegistry.ts` में पंजीकृत हैं। दोनों रजिस्ट्रियाँ `qwen-cloud-token-plan`
कनेक्शन पहचान और उसके क्षेत्र-विशिष्ट क्रेडेंशियल का पुनः उपयोग करती हैं।

नियमित Qwen Cloud के पास `qwen-cloud` पहचान के अंतर्गत अलग पे-ऐज़-यू-गो इमेज और वीडियो कैटलॉग हैं। इसके इमेज मॉडल `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03`, और `z-image-turbo` हैं। इसके वीडियो
मॉडल `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12`, और
`wan2.7-videoedit` हैं। ये मॉडल केवल नियमित `qwen-cloud` कनेक्शन और क्षेत्रीय
DashScope मीडिया एंडपॉइंट का पुनः उपयोग करते हैं। Token Plan और पे-ऐज़-यू-गो रजिस्ट्रियाँ एक-दूसरे की मॉडल सूचियों को इनहेरिट या मर्ज नहीं करतीं।

`bailian-coding-plan` पहचान की भी अपनी मीडिया अनुमत-सूचियाँ हैं:
इमेज जनरेशन के लिए `wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0`, और `qwen-image-2.0-pro`,
साथ ही वीडियो जनरेशन के लिए
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, और `happyhorse-1.1-r2v`।
यह केवल Bailian Coding Plan कनेक्शन और क्षेत्रीय Coding Plan एंडपॉइंट का उपयोग करता है।
इसकी इमेज और वीडियो रजिस्ट्रियाँ किसी भी Qwen Cloud प्रोवाइडर से इनहेरिट या उसके साथ मर्ज नहीं होतीं।

नियमित `alibaba` पहचान की अलग इमेज और वीडियो अनुमत-सूचियाँ हैं। इसके इमेज मॉडल
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo`, और `wan2.6-t2i` हैं। इसके जोड़े गए वीडियो मॉडल `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12`, और `wan2.7-videoedit` हैं। ये मॉडल केवल Alibaba Model Studio
कनेक्शन और उसके चयनित क्षेत्रीय मीडिया एंडपॉइंट का उपयोग करते हैं; इन्हें किसी Coding Plan या Qwen
Cloud रजिस्ट्री में नहीं जोड़ा जाता।

Qwen Cloud Token Plan चैट कैटलॉग Individual प्लान की सटीक-स्ट्रिंग टेक्स्ट अनुमत-सूची का पालन करता है:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2`, और
`deepseek-v4-pro`। Wan और HappyHorse प्रविष्टियाँ अलग इमेज/वीडियो जनरेशन API से संबंधित हैं।

Alibaba Token Plan अपने Anthropic-संगत एंडपॉइंट के माध्यम से उन्हीं छह मौजूदा टेक्स्ट-जनरेशन मॉडल ID को उपलब्ध कराता है। इसका Singapore विकल्प मौजूदा `global-sg` क्षेत्र कुंजी संग्रहीत करता है;
केवल उपयोगकर्ता को दिखाई देने वाला लेबल उन प्रोवाइडर परिवारों से अलग है जो इस क्षेत्र को Global कहते हैं।

नियमित Qwen Cloud चैट कैटलॉग जानबूझकर पूर्ण लाइव टेक्स्ट प्रतिसाद की तुलना में अधिक सीमित है। इसकी
अनुरक्षित अनुमत-सूची `open-sse/config/providers/registry/qwen-cloud/index.ts` में स्थित है; लाइव
डिस्कवरी केवल वे ID लौटाती है जो अपस्ट्रीम प्रतिसाद और उस रजिस्ट्री सूची, दोनों में मौजूद हैं।

Alibaba Model Studio अपनी स्वतंत्र रूप से अनुरक्षित अनुमत-सूची के साथ इसी लाइव-इंटरसेक्शन नियम का पालन करता है, जो
`open-sse/config/providers/registry/alibaba/index.ts` में है। `alibaba-cn` संगतता
