`copilot-m365-web` (उपनाम `m365copilot`) एक प्रमाणीकृत Microsoft 365 Copilot BizChat ब्राउज़र सत्र के माध्यम से
`m365.cloud.microsoft/chat` पर OpenAI-प्रारूप चैट अनुरोध भेजता है। यह एक अनौपचारिक एकीकरण है।

> **Web Cookie प्रदाताओं के लिए नए हैं?**
>
> इस प्रदाता-विशिष्ट मार्गदर्शिका का अनुसरण करने से पहले सामान्य सेटअप प्रक्रिया, प्रमाणीकरण मार्गदर्शन, सीमाओं और समस्या निवारण के लिए **`docs/getting-started/WEB-COOKIE-GUIDE.md`** पढ़ें।
>
> **महत्वपूर्ण:** इस प्रदाता का क्रेडेंशियल **कुकी नहीं है**। `m365.cloud.microsoft` से
> कुकी कॉपी न करें। क्रेडेंशियल एक WebSocket URL क्वेरी
> पैरामीटर और पाथ सेगमेंट है, जिन्हें DevTools Network टैब से पढ़ा जाता है।

## पूर्वापेक्षाएँ

- `m365.cloud.microsoft/chat` पर BizChat की एक्सेस वाला Microsoft 365 खाता
- DevTools WebSocket निरीक्षण के लिए Chromium-आधारित ब्राउज़र (Chrome, Edge)
- M365 Copilot लाइसेंस (कई Microsoft 365 Business/Enterprise योजनाओं के साथ शामिल)

## क्रेडेंशियल कैप्चर (WebSocket विधि)

1. `https://m365.cloud.microsoft/chat` पर साइन इन करें और बातचीत शुरू करें।
2. **DevTools → Network** खोलें।
3. **WS** (WebSocket) के आधार पर फ़िल्टर करें।
4. Chathub WebSocket कनेक्शन पर क्लिक करें। ऐसे URL को खोजें जो
   `wss://substrate.office.com/m365Copilot/Chathub/` से शुरू होता हो।
5. इसके **Request URL** से निम्नलिखित कॉपी करें:
   - `access_token` क्वेरी पैरामीटर का मान (कम अवधि वाला JWT)।
   - `/Chathub/` के बाद आने वाला Chathub पाथ सेगमेंट (उदा. `<oid>@<tenant>`)।

पूर्ण URL का प्रारूप इस प्रकार होता है:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute में **Providers → Add Provider** पर जाएँ, **Microsoft 365 Copilot
   (BizChat)** चुनें और क्रेडेंशियल को निम्न प्रारूप में पेस्ट करें:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. **Test Connection** और **Save** पर क्लिक करें।

## क्रेडेंशियल कैप्चर (HAR आयात)

WebSocket URL से मानों को मैन्युअल रूप से कॉपी करने के बजाय, आप एक DevTools HAR
फ़ाइल निर्यात कर सकते हैं:

1. **DevTools → Network** खोलें।
2. BizChat बातचीत शुरू करें या जारी रखें (इससे WebSocket कनेक्शन ट्रिगर होता है)।
3. Network पैनल में राइट-क्लिक करें और **Save all as HAR with content** चुनें।
4. OmniRoute में, प्रदाता कनेक्शन डायलॉग पर **Import .har file** बटन का उपयोग करें।

OmniRoute, Chathub WebSocket URL के लिए HAR को स्कैन करता है, `access_token`
और `chathubPath` निकालता है और क्रेडेंशियल फ़ील्ड को स्वचालित रूप से भर देता है।
HAR आयात JWT की समाप्ति को डिकोड करता है और टोकन की शेष अवधि दिखाता है।

> **किसी वास्तविक HAR निर्यात, एक्सेस टोकन या रीफ़्रेश टोकन को कभी कमिट न करें।** परीक्षण और
> दस्तावेज़ीकरण के मान हमेशा प्लेसहोल्डर होने चाहिए।

## टोकन की अवधि और रीफ़्रेश

`access_token` की अवधि कम होती है (आमतौर पर **~75 मिनट**)। अवधि समाप्त होने के बाद, प्रदाता
कनेक्शन त्रुटि की रिपोर्ट करता है और आपको क्रेडेंशियल फिर से कैप्चर करना होगा।

### `refreshToken` के साथ स्वचालित रीफ़्रेश

मैन्युअल रूप से फिर से कैप्चर करने से बचने के लिए, आप कनेक्शन की
**Advanced Settings → providerSpecificData** में Microsoft रीफ़्रेश टोकन संग्रहीत कर सकते हैं:

| फ़ील्ड         | विवरण                                                                    |
| -------------- | ------------------------------------------------------------------------ |
| `refreshToken` | `substrate.office.com/sydney` स्कोप के लिए Microsoft OAuth रीफ़्रेश टोकन |
| `tier`         | `individual` (डिफ़ॉल्ट), `edu`, या `enterprise`                          |

`substrate.office.com/sydney` के लिए स्कोप किए गए Microsoft device-code या authorization-code फ़्लो से रीफ़्रेश टोकन
प्राप्त करें। `refreshToken` सेट होने पर, OmniRoute प्रत्येक अनुरोध से पहले
`access_token` को प्री-फ़्लाइट-रीफ़्रेश करता है, इसलिए आपको प्रत्येक ~75-मिनट की समाप्ति के बाद
इसे फिर से कैप्चर करने की आवश्यकता नहीं होती।

यदि `refreshToken` सेट नहीं है, तो आपको प्रत्येक समाप्ति के बाद WebSocket क्रेडेंशियल को मैन्युअल रूप से
फिर से कैप्चर करना होगा।

### टियर चयन

| टियर         | उपनाम        | सतह                       |
| ------------ | ------------ | ------------------------- |
| `individual` | _(डिफ़ॉल्ट)_ | उपभोक्ता M365 Copilot     |
| `edu`        | `included`   | शिक्षा M365 Copilot       |
| `enterprise` | `work`       | कार्य के लिए M365 Copilot |

**Advanced Settings → providerSpecificData → tier** में टियर सेट करें। टियर
BizChat रूटिंग और मॉडल एक्सेस को प्रभावित करता है।

## सुरक्षा मॉडल

- **अनौपचारिक एकीकरण।** यह प्रदाता BizChat WebSocket
  प्रोटोकॉल की रिवर्स इंजीनियरिंग करता है। Microsoft द्वारा एंडपॉइंट बदलने पर यह बिना सूचना के काम करना बंद कर सकता है।
- `subscriptionRisk: true` फ़्लैग दर्शाता है कि यह एकीकरण एक
  गैर-दस्तावेज़ीकृत एंडपॉइंट पर निर्भर करता है। खाते पर प्रतिबंध संभव हैं, लेकिन इसकी पुष्टि नहीं हुई है।
- एक्सेस टोकन एक अल्पकालिक JWT है। इसे पासवर्ड की तरह संभालें: इसे कमिट,
  लॉग या साझा न करें।
- रिफ़्रेश टोकन BizChat इंटरफ़ेस तक दीर्घकालिक पहुँच प्रदान करता है। इसे
  API कुंजी जितनी ही सावधानी से संग्रहीत करें।

## समस्या निवारण

### प्रमाणीकरण तुरंत विफल हो जाता है

- सत्यापित करें कि आपने **WebSocket URL** से कॉपी किया है, न कि किसी XHR/Fetch अनुरोध से। यह
  क्रेडेंशियल Chathub WebSocket कनेक्शन के `access_token` क्वेरी पैरामीटर में होता है
  — `Authorization: Bearer` हेडर में नहीं।
- सुनिश्चित करें कि `chathubPath` में URL
  पथ का पूरा `<oid>@<tenant>` खंड शामिल है।

### टोकन ~75 मिनट बाद समाप्त हो जाता है

यह अपेक्षित है। `refreshToken` के बिना, एक्सेस टोकन अल्पकालिक होता है। इनमें से कोई एक करें:

- DevTools से क्रेडेंशियल दोबारा कैप्चर करें, या
- स्वचालित रिफ़्रेश के लिए उन्नत सेटिंग्स में `refreshToken` कॉन्फ़िगर करें।

### कनेक्शन परीक्षण सफल होता है, लेकिन चैट 401 लौटाती है

सत्यापन और पहले अनुरोध के बीच टोकन की समय-सीमा समाप्त हो सकती है। नया
क्रेडेंशियल दोबारा कैप्चर करें।

### Copilot प्रदाता सूची में दिखाई नहीं देता

सुनिश्चित करें कि **Dashboard → Providers** में `copilot-m365-web` सक्षम है। कुछ स्तरों में प्रदाता
डिफ़ॉल्ट रूप से छिपा हो सकता है।
