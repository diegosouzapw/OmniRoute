Caveman कम्प्रेशन में अंतर्निहित अंग्रेज़ी नियमों के अतिरिक्त भाषा-विशिष्ट नियम पैक लोड किए जा सकते हैं।
इससे मुख्य इंजन स्थिर रहता है, जबकि पुर्तगाली, स्पेनिश, जर्मन, फ़्रेंच, इतालवी, जापानी और
भविष्य के भाषा पैक स्वतंत्र रूप से विकसित हो सकते हैं।

## स्थान

भाषा पैक यहाँ स्थित होते हैं:

```txt
open-sse/services/compression/rules/<language>/
```

वर्तमान में उपलब्ध पैक (`rules/` डायरेक्टरी की सामग्री से सत्यापित):

| भाषा                 | डायरेक्टरी     | उपलब्ध नियम श्रेणियाँ                               |
| -------------------- | -------------- | --------------------------------------------------- |
| अंग्रेज़ी            | `rules/en/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| स्पेनिश              | `rules/es/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| पुर्तगाली (ब्राज़ील) | `rules/pt-BR/` | `context`, `dedup`, `filler`, `structural`, `ultra` |
| इंडोनेशियाई          | `rules/id/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| इतालवी               | `rules/it/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| जर्मन                | `rules/de/`    | `context`, `filler`, `structural`                   |
| फ़्रेंच              | `rules/fr/`    | `context`, `filler`, `structural`                   |
| जापानी               | `rules/ja/`    | `context`, `filler`, `structural`                   |

> **समानता संबंधी टिप्पणी:** `en`, `es`, `pt-BR`, `id`, और `it` पैक में सभी 5 श्रेणियाँ हैं; `de`, `fr`, `ja` में 3 श्रेणियाँ उपलब्ध हैं। अनुपलब्ध `dedup` और `ultra` श्रेणियाँ बिना किसी सूचना के अंतर्निहित अंग्रेज़ी नियमों पर फ़ॉलबैक करती हैं। छोटे पैक में `dedup.json` और `ultra.json` जोड़ने के लिए योगदान आमंत्रित हैं।
>
> `pt-BR` पैक Lenine Júnior द्वारा निर्मित **[Troglodita](https://github.com/leninejunior/troglodita)** पर आधारित है — यह ब्राज़ीली पुर्तगाली व्याकरण के लिए शुरू से डिज़ाइन की गई कम्प्रेशन प्रणाली है (अनावश्यक पुनरुक्ति में कमी, PT-BR फ़िलर हटाना, dev BR समुदाय के लिए तकनीकी संक्षिप्तियाँ)।
>
> प्रामाणिक श्रेणी सूची और प्रत्येक श्रेणी की स्कीमा [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) में उपलब्ध है (JSON Schema draft 2020-12)।

## भाषा पहचान

`languageDetector.ts` प्रॉम्प्ट टेक्स्ट से भाषा का अनुमान लगाने के लिए हल्की ह्यूरिस्टिक्स का उपयोग करता है।
कॉन्फ़िगर की गई डिफ़ॉल्ट भाषा का अब भी सम्मान किया जाता है, और जब सटीक नियंत्रण आवश्यक हो, तो कॉन्फ़िगरेशन द्वारा पहचान को अक्षम किया जा सकता है।

पहचान के आउटपुट का उपयोग केवल नियम पैक चुनने के लिए किया जाता है। यह प्रोवाइडर रूटिंग, लोकेल
चयन या UI भाषा को नहीं बदलता।

## कॉन्फ़िगरेशन संरचना

कम्प्रेशन सेटिंग्स में निम्न शामिल हो सकते हैं:

```json
{
  "languageConfig": {
    "enabled": true,
    "defaultLanguage": "en",
    "autoDetect": true,
    "enabledPacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  },
  "cavemanConfig": {
    "language": "en",
    "autoDetectLanguage": true,
    "enabledLanguagePacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  }
}
```

`languageConfig` डैशबोर्ड/प्रीव्यू के डिफ़ॉल्ट मानों को नियंत्रित करता है। `cavemanConfig` वह रनटाइम इंजन कॉन्फ़िगरेशन है,
जिसका उपयोग Caveman संदेश टेक्स्ट को कम्प्रेस करते समय करता है।

## भाषा पैक जोड़ना

1. `open-sse/services/compression/rules/<language>/<pack>.json` बनाएँ।
2. `docs/compression/COMPRESSION_RULES_FORMAT.md` में दिए गए Caveman नियम प्रारूप का उपयोग करें।
3. प्रतिस्थापनों को सीमित रखें और कोड, पहचानकर्ताओं, URLs या JSON को बदलने से बचें।
4. भाषा चयन और प्रतिस्थापन व्यवहार के लिए परीक्षण जोड़ें या अपडेट करें।
5. यदि भाषा UI चयनकर्ताओं में दिखाई देती है, तो नए dashboard/i18n लेबल उपलब्ध कराएँ।

## API

उपलब्ध पैक्स को निम्न कमांड से क्वेरी किया जा सकता है:

```bash
curl http://localhost:20128/api/compression/language-packs
```

पूर्वावलोकन एंडपॉइंट भाषा कॉन्फ़िगरेशन ओवरराइड स्वीकार करता है:

```bash
curl -X POST http://localhost:20128/api/compression/preview \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "standard",
    "text": "Por favor, eu gostaria que voce basicamente resumisse isso.",
    "config": {
      "languageConfig": {
        "defaultLanguage": "pt-BR",
        "autoDetect": true
      }
    }
  }'
```

## SHARED_BOUNDARIES (v3.8.0)

सभी 6 भाषा पैक्स में v3.8.0 में एक `SHARED_BOUNDARIES` क्लॉज़ जोड़ा गया, जिसे प्रत्येक
Caveman तीव्रता (LITE, FULL, ULTRA) पर लागू किया जाता है। यह इंजन को आसपास के अनावश्यक शब्दों को हटाए जाने के बावजूद,
इन पैटर्न को अक्षरशः संरक्षित रखने का निर्देश देता है:

| पैटर्न प्रकार                 | उदाहरण                                 |
| ----------------------------- | -------------------------------------- |
| फ़ेन्स्ड कोड ब्लॉक            | ` ```python\n...\n``` `                |
| इनलाइन कोड                    | `` `my_var` ``                         |
| URLs                          | `https://example.com/path`             |
| फ़ाइल पथ (निरपेक्ष + सापेक्ष) | `/etc/hosts`, `./src/index.ts`         |
| त्रुटि हेडर                   | `Error:`, `TypeError:`, `SyntaxError:` |
| स्टैक ट्रेस पंक्तियाँ         | `  at functionName (file.ts:12:3)`     |

इन पैटर्न को `DEFAULT_CAVEMAN_CONFIG.preservePatterns` (पहले `[]`) में भरा जाता है।
यह कॉन्स्टेंट `open-sse/services/compression/types.ts` में स्थित है।

### यह क्यों महत्वपूर्ण है

SHARED_BOUNDARIES के बिना, आक्रामक Caveman मोड ऐसी सामग्री को हटा सकते थे जो दोहराव वाले
गद्य जैसी दिखती थी, लेकिन वास्तव में एक कोड स्निपेट, फ़ाइल पथ या त्रुटि स्टैक थी। SHARED_BOUNDARIES एक
भाषा-अज्ञेय सुरक्षा तंत्र के रूप में कार्य करता है, जिसे अनावश्यक शब्द हटाने वाले नियमों के चलने से पहले लागू किया जाता है।

### preservePatterns को अनुकूलित करना

कम्प्रेशन सेटिंग्स के माध्यम से रनटाइम पर अतिरिक्त पैटर्न जोड़े जा सकते हैं:

````json
{
  "cavemanConfig": {
    "preservePatterns": [
      "```[\\s\\S]*?```",
      "`[^`]+`",
      "https?://\\S+",
      "(?:/|\\./)[^\\s]+",
      "\\b(?:Error|TypeError|SyntaxError|RangeError):",
      "\\s+at\\s+\\S+\\s+\\(\\S+:\\d+:\\d+\\)"
    ]
  }
}
````

कस्टम पैटर्न 6 डिफ़ॉल्ट पैटर्न का विस्तार करते हैं (उन्हें प्रतिस्थापित नहीं करते)।

## परिचालन संबंधी टिप्पणियाँ

- किसी भाषा पैक के अनुपलब्ध होने पर अंतर्निहित अंग्रेज़ी नियम फ़ॉलबैक के रूप में बने रहते हैं।
- अमान्य अंतर्निहित JSON पैक्स सत्यापन में विफल हो जाते हैं, ताकि रिलीज़ एसेट्स की गुणवत्ता चुपचाप कम न हो।
- नियम पैक्स केवल डेटा वाले होते हैं और उन्हें कोड इम्पोर्ट नहीं करना चाहिए या मनमाना लॉजिक नहीं चलाना चाहिए।
- कम्प्रेशन एनालिटिक्स परत चयनित मोड और इंजन को रिकॉर्ड करती है, पूरे प्रॉम्प्ट टेक्स्ट को नहीं।
