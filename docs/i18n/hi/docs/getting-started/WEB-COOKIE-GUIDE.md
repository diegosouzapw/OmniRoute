Web Cookie प्रदाता OmniRoute को API key के बजाय आपके मौजूदा ब्राउज़र सत्र के माध्यम से AI सेवा का उपयोग करने देते हैं। ये तब उपयोगी होते हैं, जब आपके पास किसी सेवा की वेबसाइट के माध्यम से पहले से पहुँच हो और आप चाहते हों कि OmniRoute उसी प्रमाणीकृत सत्र का उपयोग करे।

API-key प्रदाताओं के विपरीत, Web Cookie प्रदाता उन क्रेडेंशियल का उपयोग करके प्रमाणीकृत करते हैं जिन्हें आपका ब्राउज़र वेबसाइट पर भेजता है।

# शुरू करने से पहले

> **महत्वपूर्ण:** क्रेडेंशियल हमेशा किसी **लाइव नेटवर्क अनुरोध** से कॉपी करें, अपने ब्राउज़र के cookie storage से **नहीं**।

कई प्रमाणीकरण समस्याएँ गलत स्थान से cookies कॉपी करने के कारण होती हैं।

## Cookie Storage से कॉपी न करें

अधिकांश ब्राउज़र संग्रहीत cookies को यहाँ प्रदर्शित करते हैं:

```
DevTools
→ Application (या Storage)
→ Cookies
```

भले ही ये cookies सही दिखाई दें, वे निम्न हो सकती हैं:

- पुरानी
- अधूरी
- केवल प्रमाणीकृत अनुरोधों पर भेजी जाने वाली cookies से रहित

इन मानों का उपयोग करने से प्रमाणीकरण विफल हो सकता है, भले ही वे मान्य दिखाई दें।

## लाइव अनुरोध से कॉपी करें

इसके बजाय, किसी सफल अनुरोध की cookies का उपयोग करें:

```
DevTools
→ Network
→ पृष्ठ रीफ़्रेश करें
→ कोई चैट या वार्तालाप अनुरोध खोलें
→ Request Headers
→ Cookie
```

`Cookie` अनुरोध हेडर में वही सटीक प्रमाणीकरण जानकारी होती है जिसका आपके ब्राउज़र ने सफलतापूर्वक उपयोग किया था।

अधिकांश Web Cookie प्रदाताओं के लिए, यही वह मान है जिसे OmniRoute में पेस्ट किया जाना चाहिए।

# सामान्य सेटअप

अधिकांश Web Cookie प्रदाताओं के लिए सेटअप प्रक्रिया समान होती है।

1. प्रदाता की वेबसाइट पर साइन इन करें।
2. ब्राउज़र के Developer Tools खोलें।
3. **Network** टैब खोलें।
4. पृष्ठ रीफ़्रेश करें।
5. कोई प्रमाणीकृत चैट या वार्तालाप अनुरोध खोलें।
6. आवश्यक प्रमाणीकरण क्रेडेंशियल कॉपी करें।
7. OmniRoute खोलें।
8. **Providers → Add Provider** पर जाएँ।
9. अपना Web Cookie प्रदाता चुनें।
10. क्रेडेंशियल पेस्ट करें।
11. **Test Connection** पर क्लिक करें।
12. प्रदाता को सहेजें।

आवश्यक क्रेडेंशियल प्रदाता पर निर्भर करते हैं।

# Web Cookie प्रदाता क्या कर सकते हैं और क्या नहीं

Web Cookie प्रदाता किसी वेबसाइट के चैट इंटरफ़ेस का पुनः उपयोग करते हैं। वे आधिकारिक APIs जैसी क्षमताएँ **प्रदान नहीं** करते।

## समर्थित

- अपने मौजूदा ब्राउज़र सत्र का उपयोग करके प्रमाणीकृत करना
- अपने खाते के माध्यम से उपलब्ध मॉडल एक्सेस करना
- चैट प्रतिक्रियाओं को स्ट्रीम करना
- API key की आवश्यकता नहीं

## असमर्थित

- फ़ंक्शन कॉलिंग
- टूल कॉलिंग
- स्वचालित फ़ाइल संपादन
- एजेंट-आधारित IDE कार्यप्रवाह
- केवल-API सुविधाएँ

यह अपेक्षित व्यवहार है और कोई बग **नहीं** है।

यदि आपको टूल निष्पादन, स्वचालित फ़ाइल संपादन या अन्य एजेंट कार्यप्रवाहों की आवश्यकता है, तो Web Cookie प्रदाता के बजाय **API-key प्रदाता** का उपयोग करें।

# सत्यापन संबंधी चेतावनी

सफल **Test Connection** या cookie सत्यापन केवल यह सत्यापित करता है कि दिए गए क्रेडेंशियल अपेक्षित प्रारूप में प्रतीत होते हैं।

Issue #7857 के समाधान होने तक, सफल सत्यापन इस बात की **गारंटी नहीं देता** कि प्रदाता सफलतापूर्वक प्रमाणीकृत होगा।

यदि प्रमाणीकरण फिर भी विफल होता है, तो सत्यापित करें कि आपने क्रेडेंशियल ब्राउज़र cookie storage के बजाय किसी लाइव नेटवर्क अनुरोध से कॉपी किए थे।

---

# समस्या निवारण

## प्रमाणीकरण विफल होता है

सत्यापित करें कि क्रेडेंशियल यहाँ से कॉपी किए गए थे:

```
Network
→ Request Headers
→ Cookie
```

और यहाँ से **नहीं**:

```
Application
→ Cookies
```

---

## Cookie ब्राउज़र में काम करती है, लेकिन OmniRoute में नहीं

कुछ प्रदाता ऐसी cookies शामिल करते हैं जो केवल प्रमाणीकृत अनुरोधों के दौरान भेजी जाती हैं।

किसी वार्तालाप को सफलतापूर्वक खोलने के बाद एक नए नेटवर्क अनुरोध से क्रेडेंशियल दोबारा कॉपी करें।

---

## सत्र की समय-सीमा समाप्त हो गई

Web Cookie प्रदाता आपके मौजूदा ब्राउज़र सत्र का उपयोग करते हैं।

यदि आपके ब्राउज़र सत्र की समय-सीमा समाप्त हो जाती है या आप साइन आउट करते हैं, तो आपको क्रेडेंशियल का नया सेट कॉपी करना होगा।

---

## Test Connection सफल होता है, लेकिन अनुरोध विफल होते हैं

Issue #7857 के समाधान होने तक, सत्यापन में सफल होने से यह गारंटी नहीं मिलती कि प्रमाणीकरण अनुरोध सफल होगा।

आगे समस्या निवारण करने से पहले किसी नए प्रमाणीकृत अनुरोध से अपने क्रेडेंशियल दोबारा कॉपी करें।

---

# प्रदाता उदाहरण

प्रदाता-विशिष्ट पूरी चरण-दर-चरण मार्गदर्शिका के लिए, देखें:

- **Claude Web** — `docs/providers/CLAUDE_WEB.md`

Claude Web मार्गदर्शिका किसी Web Cookie प्रदाता की पूरी सेटअप प्रक्रिया प्रदर्शित करती है और संदर्भ कार्यान्वयन के रूप में काम करती है।

# सर्वोत्तम अभ्यास

- किसी नए प्रमाणीकृत अनुरोध से क्रेडेंशियल कॉपी करें।
- पुरानी cookies का दोबारा उपयोग करने से बचें।
- Web Cookie प्रदाताओं का उपयोग करते समय अपना ब्राउज़र सत्र सक्रिय रखें।
- कॉपी की गई cookies को संवेदनशील क्रेडेंशियल मानें।
- जब आपको फ़ंक्शन कॉलिंग या एजेंट कार्यप्रवाहों की आवश्यकता हो, तो API-key प्रदाताओं का उपयोग करें।
