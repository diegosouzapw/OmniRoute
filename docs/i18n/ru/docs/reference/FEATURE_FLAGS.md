> Переключатели среды выполнения, которые изменяют поведение OmniRoute **без повторного развертывания**.
> Каждый перечисленный здесь флаг определен в
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> — единственном источнике истины. Панель управления и REST API считывают данные
> из этого файла, поэтому приведенная ниже таблица сформирована в точном соответствии с ним.

---

## Что такое флаги функций

Флаг функции — это именованный переключатель (логический или перечисляемый), значение которого можно изменять
во время выполнения и сохранять в базе данных без необходимости повторного развертывания процесса. Каждый
флаг описывается объектом `FeatureFlagDefinition` с полями `key`, `label`,
`description`, `category`, `defaultValue`, `type` и подсказкой `requiresRestart`.

### Порядок определения значения

**Эффективное значение** флага определяется функцией
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) со следующим
приоритетом (побеждает значение с наивысшим приоритетом):

1. **Переопределение в БД** — значение, хранящееся в таблице `key_value` в пространстве имен
   `feature_flags` (задается через панель управления или REST API).
2. **Переменная окружения** — `process.env[<KEY>]`, если она задана и не пуста.
3. **Значение по умолчанию из определения** — `defaultValue` из `featureFlagDefinitions.ts`.

Логический флаг считается **включенным**, если его эффективное значение равно `"true"`,
`"1"` или `"yes"` (см. `isFeatureFlagEnabled()`).

> [!NOTE]
> Большинство флагов также имеют соответствующую переменную окружения **с тем же именем**,
> задокументированную в [`ENVIRONMENT.md`](./ENVIRONMENT.md). Переопределение флага
> в БД имеет приоритет над этой переменной окружения. Флаг с
> `requiresRestart: true` сохраняется немедленно, но повторно считывается только при запуске
> процесса — его переключение приводит к появлению баннера **«Перезапустить сервер»** в панели управления.

## Переключение флагов

### Панель управления

Перейдите в **Панель управления → Настройки → Флаги функций**
(`/dashboard/settings/feature-flags`). Сетка
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
поддерживает:

- **Поиск** по ключу или описанию, а также **фильтрацию** по категории (плюс синтетический
  вид **Требуется перезапуск**).
- **Переключатель** для булевых флагов и **выпадающий список** для флагов перечисления
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- **Значок источника** для каждого флага — `DB`, `ENV` или `DEF` — показывающий, откуда
  было получено эффективное значение.
- Кнопка **Сброс** (показывается только для флагов с источником `DB`) для отмены переопределения,
  и кнопка **Сбросить все переопределения** внизу.
- Баннер **Перезапустить сервер** при изменении флага `requiresRestart`.

### REST API

Все операции проходят через один маршрут:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Каждый метод требует аутентифицированной сессии панели управления (`401` в противном случае).

#### `GET /api/settings/feature-flags`

Возвращает каждый флаг с его эффективным значением, источником и сводкой.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... все 77 флагов
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Установить или удалить одно переопределение. Тело: `{ key: string; value?: string }`.
Опущение `value` удаляет переопределение (восстанавливая env / значение по умолчанию).

```bash
# Установить переопределение DB
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Удалить переопределение (без "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Ответ повторяет новые `effectiveValue`/`source`, `previousValue`/
`previousSource` и `requiresRestart`. Неизвестные ключи и значения перечисления
вне диапазона отклоняются с `400`.

#### `DELETE /api/settings/feature-flags`

Очищает **все** переопределения БД сразу, восстанавливая каждый флаг до его значения
из env / по умолчанию. Возвращает `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> Флаги с `requiresRestart: true` вступают в силу только после перезагрузки процесса.
> Процесс перезапуска панели управления вызывает `POST /api/restart`, а затем опрашивает
> `GET /api/health/ping` до тех пор, пока сервер не будет снова запущен.

## Аварийный резервный маршрут при исчерпании бюджета

`OMNIROUTE_EMERGENCY_FALLBACK` (категория `runtime`, значение по умолчанию — `true`) управляет
аварийным бесплатным резервным маршрутом в
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Если этот параметр включен, запросы, исчерпавшие бюджет, направляются к бесплатному резервному
провайдеру/модели вместо немедленного завершения с ошибкой. Установите значение `false` (или `0`) — с помощью
переключателя на панели управления, переопределения в БД или переменной окружения
`OMNIROUTE_EMERGENCY_FALLBACK` —
чтобы отключить это поведение и позволить запросам с исчерпанным бюджетом завершаться
с ошибкой. (Добавлено на панель управления в PR #3741 / #3752.)

Ответ, полученный через этот резервный маршрут, содержит заголовок
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>`, благодаря чему
клиент может определить, что запрос был перенаправлен, не сравнивая `X-OmniRoute-Provider` с параметрами своего
запроса. Во всех остальных ответах этот заголовок отсутствует.
