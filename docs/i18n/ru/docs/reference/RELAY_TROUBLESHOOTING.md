Ретрансляторы (Vercel, Deno, Cloudflare) завершают исходящее соединение в бессерверной среде, позволяя OmniRoute выполнять исходящие запросы из стабильного региона и хранить API-ключ провайдера на стороне сервера. В этом документе описаны два режима отказа, с которыми операторы сталкиваются в рабочей среде, а также предусмотренные OmniRoute способы восстановления для каждого из них.

## Как хранятся данные аутентификации ретранслятора

Когда вы развёртываете ретранслятор через **Настройки → Пул прокси → Развернуть ретранслятор**, процесс развёртывания сохраняет токен аутентификации ретранслятора в JSON-поле `notes` прокси:

- Если задан `STORAGE_ENCRYPTION_KEY`, токен записывается как `relayAuthEnc`
  (в состоянии покоя он зашифрован с помощью AES).
- В противном случае он записывается в открытом виде как `relayAuth`.

При обработке запроса `extractRelayAuth(notes)` возвращает имеющуюся форму,
поэтому ретранслятор продолжает работать после перезапусков.

## Режим отказа 1 — токен невозможно расшифровать после ротации ключа

**Признак:** ретрансляторы, которые ранее работали, теперь возвращают ошибки
аутентификации или `401` от вышестоящего сервиса после ротации
`STORAGE_ENCRYPTION_KEY` в окружении или диспетчере секретов. Сохранённый блок
`relayAuthEnc` больше невозможно расшифровать, поэтому `extractRelayAuth`
возвращает пустую строку, и ретранслятор не отправляет данные аутентификации.

**Восстановление — исправление на месте (без повторного развёртывания):**

1. Откройте **Настройки → Пул прокси**.
2. В строках ретрансляторов с отсутствующими данными аутентификации отображаются
   жёлтый значок `auth missing` и кнопка **Исправить**.
3. Нажмите **Исправить**. OmniRoute вызывает
   `POST /api/settings/proxies/[id]/repair-relay`, который:
   - расшифровывает `relayAuthEnc` с помощью **текущего** ключа;
   - записывает открытый текст `relayAuth` обратно в `notes`;
   - возвращает `{ repaired: true, mode: "recovered" }`.

Ретранслятор возобновляет обслуживание запросов без повторного ввода учётных
данных для развёртывания.

Это работает, только если текущий `STORAGE_ENCRYPTION_KEY` всё ещё позволяет
расшифровать блок. Если вы выполнили ротацию ключа **без** миграции, восстановить
блок невозможно.

## Режим отказа 2 — невосстановимый токен (старый ключ больше недоступен)

**Признак:** вы нажали **Исправить** и получили
`{ repaired: false, mode: "redeploy", status: 409 }`.

**Восстановление — повторное развёртывание:**

Сохранённый токен невозможно восстановить с помощью текущего ключа. Повторно
разверните ретранслятор из того же модального окна, которое использовали
изначально (меню **Развернуть ретранслятор** → Vercel / Deno / Cloudflare).
Процесс развёртывания запишет новый токен (зашифрованный текущим ключом), после
чего значок `auth missing` в строке исчезнет.

Если токен невозможно восстановить, кнопка **Исправить** в интерфейсе сама
открывает модальное окно повторного развёртывания, поэтому вам не придётся
искать его вручную.

## Режим отказа 3 — ретранслятор доступен, но работает нестабильно

**Признак:** тест прокси (кнопка `speed`) показывает, что ретранслятор доступен,
однако запросы по-прежнему периодически завершаются с ошибкой.

Проверьте заголовки состояния ретранслятора, возвращаемые автоматической
проверкой OmniRoute (см. **Настройки → Пул прокси** и счётчики `relayTested` /
`relayAlive`):

- `x-relay-url` — какой сервер ретрансляции ответил.
- `x-relay-mode` — `ts` | `bifrost` | `auto` для этого запроса.
- `x-relay-attempts` — сколько переходов через ретрансляторы было предпринято
  до успешного выполнения.
- `x-relay-fallback` — `true`, если запрос был перенаправлен с предпочтительного
  сервера на ретранслятор TypeScript.

Высокая доля `x-relay-fallback` при низком значении `relayAlive` означает, что
вспомогательный сервер работает нестабильно: необходимо либо исправить его,
либо переключить стратегию сервера ретрансляции на `ts` (см.
`RELAY_BACKEND_STRATEGY.md`).

## Справочник API

| Метод  | Путь                                      | Тело                    | Успешный результат                                                                                                                       | Ошибка                                                                                                             |
| ------ | ----------------------------------------- | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `POST` | `/api/settings/proxies/[id]/repair-relay` | `{ "id": "<proxyId>" }` | `200 { repaired: true, mode: "recovered" }` при восстановлении; `200 { repaired: false, mode: "noop" }`, если открытый текст уже имеется | `409 { mode: "redeploy" }` — восстановление невозможно; `400` — тип не является ретранслятором; `404` — не найдено |

Маршрут списка `GET /api/settings/proxies` добавляет к каждому элементу не
содержащее секретов поле `relayInfo: { isRelay, authMissing, repairMode }`,
чтобы панель управления могла отображать возможность восстановления, никогда
не раскрывая токен.
