## 1. Antigravity и Antigravity CLI (agy)

Оба провайдера используют **один и тот же бэкенд Google** — идентичные OAuth-клиент, обновление токенов, конечные точки и аккаунты Google. Разница заключается в том, какие модели вам доступны.

> Официальное сравнение от Google см. в [анонсе Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli).

| Аспект                                  | `antigravity` (IDE)                               | `agy` (CLI)                                                      |
| --------------------------------------- | ------------------------------------------------- | ---------------------------------------------------------------- |
| **Продукт Google**                      | Antigravity 2.0 / Antigravity IDE                 | Antigravity CLI                                                  |
| **Бэкенд**                              | Тот же Google Cloud Code API                      | Тот же Google Cloud Code API                                     |
| **OAuth / токен**                       | Тот же клиент, то же обновление                   | Тот же клиент, то же обновление                                  |
| **Каталог моделей**                     | Статический курируемый список (задан в OmniRoute) | Динамически запрашивается у Google через `:fetchAvailableModels` |
| **Модели Claude**                       | Sonnet 4.6, Opus 4.6 (по 4 варианта каждой)       | Sonnet 4.6, Opus 4.6 (по 4 варианта каждой)                      |
| **Именование Gemini**                   | Понятные метки (Low/Medium/High)                  | Исходные идентификаторы (extra-low/low/agent)                    |
| **Дополнительные модели**               | `gpt-oss-120b-medium`                             | Может включать дополнительные модели от Google                   |
| **Сценарий использования по умолчанию** | Интеграция с IDE (VS Code, JetBrains)             | Доступ через CLI / API                                           |
| **Квота**                               | Общая с agy (тот же аккаунт Google)               | Общая с antigravity (тот же аккаунт Google)                      |

**Доступные модели (подтверждено экспериментально, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (различные уровни рассуждений)
- Claude: Sonnet 4.6, Opus 4.6 (каждая с вариантами default/low/medium/high)
- Другие: GPT-OSS 120B Medium
- **Claude Sonnet 5 НЕДОСТУПНА** — поддерживаются только варианты 4.6

**Почему каталоги моделей различаются**: CLI от Google «оптимизирован для скорости и низких накладных расходов» и «совместно оптимизирован с моделями Gemini» (согласно официальному блогу Google). Веб-продукт/IDE «оптимизирован для полноты возможностей». CLI использует `:fetchAvailableModels` для динамического обнаружения моделей, тогда как IDE использует статический курируемый список.

**На практике**: используйте префикс `agy/` для моделей Gemini (например, `agy/gemini-3.7-flash-high`). Используйте `antigravity/` для статического курируемого списка. Оба провайдера обращаются к одному и тому же бэкенду Google, но используют разные схемы именования моделей. Квота общая — использование любого из провайдеров учитывается в лимитах одного и того же аккаунта Google.

## 2. Google One AI Pro: система квот

> Официальные сведения о квотах см. в [документации Antigravity: тарифные планы](https://antigravity.google/docs/plans), а последние изменения цен — в статье [Изменения в тарифных планах Antigravity](https://antigravity.google/blog/changes-to-antigravity-plans).

Google Antigravity использует **двухуровневую систему квот**, основанную на показателе «Выполненная работа» (вычислительная нагрузка), а не на количестве сообщений.

### Два уровня

| Уровень              | Что это такое                      | Цикл обновления                                                                          |
| -------------------- | ---------------------------------- | ---------------------------------------------------------------------------------------- |
| **5-часовой спринт** | Текущий запас «выполненной работы» | Сбрасывается через 5 часов после первого запроса в рамках сеанса                         |
| **7-дневный лимит**  | Жёсткое недельное ограничение      | При достижении отменяет 5-часовое обновление; блокирует до следующего 7-дневного периода |

**Как рассчитывается «Выполненная работа»**: задачи с интенсивным использованием агентов (например, «Проведи рефакторинг всего этого репозитория») расходуют квоту намного быстрее, чем простые задачи (например, «Исправь эту функцию»). Панели мониторинга, показывающей потребление в реальном времени, нет.

### Уровни тарифных планов

| Тариф        | Цена       | Квота                                           | Недельный лимит                                   |
| ------------ | ---------- | ----------------------------------------------- | ------------------------------------------------- |
| Free         | $0         | Значительная квота, обновляемая еженедельно     | Да                                                |
| AI Pro       | $19.99/mo  | Высокая квота с плавающим 5-часовым обновлением | Да (при достижении отменяет 5-часовое обновление) |
| AI Ultra 5x  | $99.99/mo  | В 5 раз больше квоты Pro                        | Недельного лимита нет                             |
| AI Ultra 20x | $199.99/mo | В 20 раз больше квоты Pro                       | Недельного лимита нет                             |

### Модели Gemini и модели, отличные от Gemini

- **Модели Gemini** (Flash + Pro): используют единый лимит запросов, расходуемый в соответствии с ценами API. Если Flash в 8 раз дешевле Pro, вы получаете в 8 раз больше токенов Flash.
- **Модели, отличные от Gemini** (Claude, GPT-OSS): имеют **отдельные** лимиты запросов. Они могут оставаться доступными, даже когда доступ к Gemini заблокирован.

### Кредиты AI (сверхлимитное использование)

> Сведения о принципах работы кредитов см. в статье [Кредиты Google One AI](https://support.google.com/googleone/answer/14534406).

Когда базовая квота исчерпана:

- **Никогда**: ожидать обновления квоты; отображается сообщение «Достигнута базовая квота модели»
- **Всегда**: автоматически использовать кредиты AI; после обновления базовой квоты система переключается обратно на неё

Кредиты приобретаются отдельно и списываются по стандартным тарифам API.

### Ключевые сведения

- Квота **общая для всей учётной записи** — одна и та же учётная запись Google в Antigravity IDE, CLI и OmniRoute использует единый пул квоты
- У каждой учётной записи Google есть собственная независимая квота — несколько учётных записей означают несколько пулов квоты
- Пользователи AI Pro сообщали о **7-дневной блокировке** вместо 5-часового сброса при достижении недельного базового лимита (Google подтвердил, что это предусмотренное поведение при высоком спросе)

**Когда квота вашей учётной записи исчерпана**: OmniRoute автоматически повторяет запрос со следующей доступной учётной записью в комбинированном маршруте. Ручное вмешательство не требуется.

## 3. Как получить projectId

Для каждого подключения antigravity/agy требуется Google Cloud Code `projectId`. Без него конечная точка `/v1internal:models` возвращает ошибку 404.

### Способ A: автоматически (рекомендуется)

OmniRoute выполняет это автоматически. Когда вы добавляете новую учётную запись Google через OAuth на панели управления:

1. OmniRoute обновляет токен
2. Вызывает `loadCodeAssist`, чтобы определить projectId
3. Если проекта нет, вызывает `onboardUser`, чтобы создать его
4. Повторно вызывает `loadCodeAssist`, чтобы получить projectId только что созданного проекта
5. Сохраняет его в базе данных

**Это работает для большинства учётных записей** — никаких ручных действий не требуется.

### Способ B: вручную через agy CLI

Если автоматическое определение завершается сбоем (условия, при которых это происходит, см. в разделе 5):

```bash
# Установите agy CLI (если он ещё не установлен)
npm install -g @anthropic-ai/agy

# Войдите с помощью своей учётной записи Google
agy login

# Выберите учётную запись, для которой требуется регистрация
# Это запускает регистрацию Cloud Code и назначает projectId
```

После успешного выполнения `agy login` обновите токен на панели управления OmniRoute. projectId будет определён автоматически.

### Как проверить

Проверьте базу данных:

```bash
# Внутри контейнера OmniRoute
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Или проверьте журналы:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. URI перенаправления OAuth

### Проблема

Для Google OAuth требуется действительный URI перенаправления. По умолчанию OmniRoute использует `http://127.0.0.1:20128/callback` (loopback-адрес). Это работает для локальных сборок, но **не работает при удалённом развёртывании** (например, на сервере, доступ к которому осуществляется по IP-адресу локальной сети).

Google отклоняет URI перенаправления, которые:

- Используют IP-адреса (необходимо доменное имя, заканчивающееся на `.com`, `.org` и т. д.)
- Не совпадают с URI перенаправления, зарегистрированными в конфигурации клиента OAuth

### Решение

**Вариант A: использовать встроенный процесс OAuth (по умолчанию)**

- Работает при доступе к OmniRoute через `localhost` или `127.0.0.1`
- Настройка не требуется

**Вариант B: собственные учётные данные OAuth**

- Установите `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` в своём окружении
- Укажите собственные учётные данные Google OAuth:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Зарегистрируйте `https://your-domain.com/callback` как авторизованный URI перенаправления в Google Cloud Console

**Вариант C: использовать CLI agy для первоначального входа**

- Выполните `agy login` на компьютере, с которого будет осуществляться доступ к OmniRoute
- Процесс OAuth завершится локально, а токены будут сохранены
- Импортируйте подключение в OmniRoute через панель управления

### Ограничения

- Для собственных учётных данных OAuth требуется доменное имя (Google не принимает IP-адреса в качестве URI перенаправления)
- Если у вас нет домена, используйте вариант A или C

## 5. Устранение неполадок: если автоматическая настройка завершается ошибкой

Для большинства аккаунтов OmniRoute автоматически определяет projectId и выполняет первоначальную настройку. Если возникает ошибка, её основная причина обычно заключается в одном из следующих факторов:

### Регион аккаунта заблокирован

**Симптом**: `agy login` возвращает сообщение «Проверка соответствия требованиям не пройдена: ваш текущий аккаунт не может использовать Antigravity, поскольку сервис пока недоступен в вашем регионе».

**Основная причина**: в аккаунтах Google есть внутреннее поле «Привязка к стране», которое задаётся при регистрации. CLI agy и Cloud Code API строго проверяют это поле — в отличие от веб-версии Gemini, которая проверяет только ваш текущий IP-адрес.

> Чтобы проверить или изменить регион, связанный с вашим аккаунтом, перейдите на страницу [формы Google для изменения привязки к стране](https://policies.google.com/country-association-form).

**Почему веб-версия Gemini работает, а agy — нет**:

- Веб-версия Gemini / Google One: проверяет только текущий IP-адрес (прокси помогает пройти проверку)
- CLI agy / Cloud Code API: считывает внутреннее поле «Привязка к стране» (прокси не помогает)

**Исправление**:

1. Перейдите на страницу [формы Google для изменения привязки к стране](https://policies.google.com/country-association-form), используя IP-адрес США
2. Отправьте запрос на изменение региона (выберите «Я живу в другой стране»)
3. Подождите от 1 до 24 часов, пока Google обработает запрос и отправит уведомление по электронной почте
4. После этого команда `agy login` должна выполниться успешно

### В аккаунте отсутствует проект Cloud Code

**Симптом**: в журналах отображаются сообщения `loadCodeAssist returned no project id` и `onboardUser failed (400)`.

**Основная причина**: аккаунт никогда не регистрировался в Google Cloud Code, а автоматическая первоначальная настройка завершилась ошибкой.

**Исправление**: выполните `agy login` вручную, чтобы запустить регистрацию Cloud Code, затем обновите токен в панели управления OmniRoute.

### Срок действия токена истёк или токен отозван

**Симптом**: ошибки 401 в журналах или сообщения «Срок действия токена истёк».

**Исправление**: обновите токен в разделе «Панель управления → Поставщики → agy» → нажмите значок обновления. Если сам токен обновления отозван, потребуется повторно пройти аутентификацию через OAuth.

## Блок-схема принятия решений

```
Аккаунт не работает?
│
├─ Есть ли у него projectId в базе данных?
│  ├─ ДА → Проблема в другом (истёк срок действия токена, превышен лимит запросов и т. д.)
│  └─ НЕТ ↓
│
├─ Установлен ли для аккаунта ограниченный регион в Country Association?
│  ├─ ДА → Измените регион в форме Google Country Association
│  │         (https://policies.google.com/country-association-form)
│  │         Подождите 1–24 часа, затем повторите попытку
│  └─ НЕТ ↓
│
├─ Есть ли у аккаунта подписка Google One AI Pro?
│  ├─ НЕТ → Сначала оформите подписку на one.google.com
│  └─ ДА ↓
│
├─ Попробуйте автоматическое обнаружение (обновите токен в панели управления)
│  ├─ Работает → Готово
│  └─ По-прежнему не работает ↓
│
└─ Вручную: выполните `agy login` на компьютере
   ├─ Работает → Обновите токен в панели управления, projectId будет обнаружен
   └─ Не работает → Проверьте сообщение об ошибке; скорее всего, проблема связана с регионом или подпиской
```
