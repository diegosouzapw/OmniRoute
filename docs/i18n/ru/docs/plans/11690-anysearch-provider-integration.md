## 1. Фактические сведения о сервисе (официальная документация, проверено по нескольким источникам)

- Базовый URL: `https://api.anysearch.com` (REST) + `POST /mcp` (MCP, JSON-RPC 2.0).
- `POST /v1/search` — параметры: `query` (обязательный), `max_results` (1–10, по умолчанию 10), `tag` (вертикальная маршрутизация `{domain}.{sub_domain}`), `zone` (cn/intl), `language`, `params` (структурированные поля вертикали), `format` (json/markdown).
- `GET /v1/sub-domains?domain=...` — каталог возможностей, НЕ учитывается в квоте.
- `POST /v1/extract` — получение/извлечение `{url, title, content}`; строгое тело JSON, ограничение 16 KiB.
- `POST /v1/auth/email/register` — регистрация одним вызовом, возвращает одноразовый ключ в открытом виде `as_sk_...`.
- Аутентификация: необязательный заголовок `Authorization: Bearer <as_sk_...>`; при анонимном доступе применяются ограничения на IP-адрес с расходованием бесплатной суточной квоты; недействительный ключ возвращает 401/403 БЕЗ незаметного переключения на анонимный доступ.
- Бесплатный тариф: 1000 запросов в день, 20 QPS на ключ. Платный тариф: цена не указана (скоро).
- Конверт ответа: успех — `{code: 0, message: "success", request_id, data}`; ошибка — `{code: -1, message}`. Ошибки аутентификации/квоты не содержат структурированного `error_code` (сигналом служит текст сообщения); ошибки, специфичные для извлечения, содержат `error_code` (`invalid_extract_url`, `extract_failed`). Заголовок `Retry-After` при ответе 429 отсутствует.

## 3. Решения (все приняты 2026-08-26)

1. **Стратегия маршрутизации: `fallbackOnly`.** Обоснование: бесплатный провайдер с нулевой стоимостью не должен преобладать при автоматической маршрутизации по стоимости; явный выбор и возврат после отказа остаются без изменений. Прецедент: объединённая запись xquik.
2. **Область применения: webSearch + webFetch через `POST /v1/extract` в v1.** Соответствует концептуальной модели двойных возможностей tavily/exa. Вертикальные функции (`tag`, `sub-domains`, `batch_search`) остаются за рамками — в настоящее время IR для вертикальных параметров отсутствует.
3. **Отображение квоты: `freeMonthlyQuota: 0`** (консервативное отображение в стиле xquik). Фактический лимит (1000 запросов в день с ежедневным сбросом) вместо этого указывается в тексте `authHint` каталога пользовательского интерфейса. Обоснование: отображение квоты должно соответствовать семантике сброса; преобразование дневного лимита в месячный эквивалент (30000) создаёт ложное обещание, которое пользовательский интерфейс не может выполнить.
4. **searchTypes: только `["web"]`.** Нет общедоступных свидетельств наличия в AnySearch API вертикального поиска по новостям или изображениям; шлюзы, интегрирующие API без документированной вертикали (например, Google Custom Search), предоставляют только веб-поиск, а не выполняют неявное сопоставление news -> web.
5. **Политика ключей:** работа без ключа поддерживается; недействительный ключ приводит к ответу 401/403 и никогда не вызывает неявного перехода в анонимный режим (в соответствии с контрактом вышестоящего сервиса).
6. **Намеренно исключено:** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (перехват чата по-прежнему использует firecrawl/jina/tavily); `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (анонимные удалённые конечные точки используют общий пул с ограничением по IP для каждого исходящего IP-адреса, поэтому извлечение без ключа доступно только при явном выборе и не является кандидатом для автоматической маршрутизации); `QUOTA_STATUS_PROVIDERS` (AnySearch сообщает об исчерпании квоты через 429/конверт ответа, а не через статус 402/403).
