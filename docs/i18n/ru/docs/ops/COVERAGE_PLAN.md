Оптимизировать следует относительно рекомендуемого исходного показателя.

## Правила

- Целевые показатели покрытия применяются к файлам исходного кода, а не к `tests/**`.
- `open-sse/**` является частью продукта и должен оставаться в области охвата.
- Новый код не должен снижать покрытие в затронутых областях.
- Предпочтительно тестировать поведение и результаты ветвлений, а не детали реализации.
- Для `src/lib/db/**` предпочтительно использовать временные базы данных SQLite и небольшие фикстуры вместо масштабного применения моков.

## Текущий набор команд

- `npm run test:coverage`
  - Основная проверка покрытия исходного кода набором модульных тестов
  - Формирует отчёты `text-summary`, `html`, `json-summary` и `lcov`
- `npm run coverage:report`
  - Подробный пофайловый отчёт по результатам последнего запуска
- `npm run test:coverage:legacy`
  - Только для сравнения с историческими данными

## Политика ratchet

Обновляйте пороговые значения `npm run test:coverage` только после того, как проект действительно превысит следующую контрольную отметку с комфортным запасом.

**Текущий порог:** `npm run test:coverage` требует **60 для операторов / 60 для строк / 60 для функций / 60 для ветвей** (метрика была пересчитана в Quality-Gates Fase 6A.1 — прежний базовый показатель 82.58% был завышен, поскольку учитывал тестовые файлы и исключал `open-sse`). Команда `test:coverage:legacy` сохраняет старую метрику 50/50/50 для исторического сравнения.

Для разовых проверок порогового значения по последнему отчёту используйте:

```bash
node scripts/check/test-report-summary.mjs --threshold 75
```

Рекомендуемая последовательность повышения порогов (порядок: `операторы-строки / ветви / функции`):

## Известный пробел

Текущая команда проверки покрытия измеряет основной набор модульных тестов Node и включает исходный код, который выполняется из него, в том числе `open-sse`. Пока она не объединяет покрытие Vitest в единый отчёт. Такое объединение стоит реализовать позже, но оно не препятствует началу повышения покрытия с 60% до 80%.
