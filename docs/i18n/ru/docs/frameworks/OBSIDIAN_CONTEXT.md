> **Источник истины:** `src/lib/obsidian/api.ts` (REST-клиент и клиент синхронизации),
> `src/lib/db/obsidian.ts` (хранение токена / базового URL / настроек WebDAV),
> `src/lib/obsidianSync.ts` (синхронизация хранилища через WebDAV), `open-sse/mcp-server/tools/obsidianTools.ts`
> (22 инструмента MCP), `src/app/api/settings/obsidian/route.ts` +
> `src/app/api/settings/obsidian/webdav/route.ts` (API настроек). Регистрация инструментов
> и настройка областей доступа находятся в `open-sse/mcp-server/server.ts`.

## Что это такое

OmniRoute подключается к хранилищу **Obsidian** как к **источнику контекста** — локальной
базе знаний в формате Markdown, которую агенты читают и изменяют через встроенный сервер
MCP. Интеграция взаимодействует с плагином сообщества **Obsidian Local REST API**,
запущенным внутри настольного приложения, благодаря чему агенты могут искать заметки,
читать/записывать/частично изменять файлы, просматривать содержимое хранилища, работать
с ежедневными/еженедельными периодическими заметками, управлять тегами, выполнять
команды Obsidian и (опционально) координировать двунаправленную синхронизацию хранилища
между настольным и мобильным приложениями.

Клиент (`src/lib/obsidian/api.ts`) предоставляет обёртку над Local REST API со следующими возможностями:

- **Повторные попытки с увеличивающейся задержкой** для временных ошибок `5xx`,
  **30-секундный тайм-аут** через `AbortController`.
- **Типизированная классификация ошибок** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- **Понятная подсказка «не удаётся подключиться к Obsidian»**, указывающая на
  распространённую ошибку с портом (HTTP на `27123`, **а не** конечная точка MCP на
  `27124`) и вариант адреса для Tailscale.
- **Кодирование путей** относительно хранилища, позволяющее безопасно обрабатывать пути
  к заметкам с пробелами и косыми чертами.

## Настройка

Для токена Obsidian и базового URL **не предусмотрено переменных окружения** — оба
значения хранятся в таблице SQLite `key_value` (пространство имён `obsidian`) через
`src/lib/db/obsidian.ts`. Токен **зашифрован при хранении** (AES-256-GCM, с резервной
поддержкой незашифрованного текста для обратной совместимости). Настройку можно выполнить
на вкладке **Context Sources** панели управления Endpoint (`ObsidianSourceCard`) или
через REST API настроек.

> [!IMPORTANT]
> Плагин **Obsidian Local REST API** должен быть установлен и запущен. Его REST-интерфейс
> принимает подключения по адресу **HTTP `127.0.0.1:27123`** (базовый URL по умолчанию).
> Порт `27124` — это _отдельная_ конечная точка MCP/HTTPS, которая явно отклоняется
> маршрутом настроек. При подключении с другого устройства используйте
> `http://<tailscale-ip>:27123`.

### Ключи конфигурации (SQLite `key_value`, пространство имён `obsidian`)

| Ключ              | Назначение                                                        | Зашифрован |
| ----------------- | ----------------------------------------------------------------- | ---------- |
| `api_key`         | Bearer-токен Local REST API                                       | да         |
| `base_url`        | Базовый URL REST (по умолчанию `http://127.0.0.1:27123`)          | нет        |
| `vault_path`      | Абсолютный путь к каталогу хранилища (для синхронизации)          | нет        |
| `webdav_username` | Сгенерированное имя пользователя WebDAV (синхронизация хранилища) | нет        |
| `webdav_password` | Сгенерированный пароль WebDAV (синхронизация хранилища)           | да         |
| `webdav_enabled`  | Включена ли синхронизация хранилища через WebDAV                  | нет        |

### Настройка через REST

```bash
# Сохранить и проверить токен Local REST API (POST выполняет проверку через запрос статуса)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Проверить состояние подключения (возвращает connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# Отключиться (удаляет сохранённый токен)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Все методы требуют аутентификации в панели управления. `POST` отклоняет любой URL с
портом `27124` и перед сохранением проверяет токен, вызывая конечную точку статуса
Local REST API.

### Синхронизация хранилища через WebDAV

`src/app/api/settings/obsidian/webdav/route.ts` управляет опциональной синхронизацией
хранилища на основе WebDAV (реализованной в `src/lib/obsidianSync.ts`). При её включении
OmniRoute настраивается на использование локального каталога хранилища и генерирует
случайную пару из имени пользователя и пароля WebDAV:

```bash
# Включить синхронизацию через WebDAV для каталога хранилища (генерирует имя пользователя и пароль)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# Получить состояние синхронизации WebDAV (учётные данные возвращаются только при включённой синхронизации)
curl http://localhost:20128/api/settings/obsidian/webdav

# Отключить синхронизацию WebDAV (удаляет учётные данные и управляемый файл .stignore)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Источник контекста для отдельного API-ключа (опционально)

Конфигурацию Obsidian можно задать **отдельно для каждого API-ключа** через таблицу
`api_key_context_sources` (`src/lib/db/apiKeyContextSources.ts`). Когда вызов MCP
содержит идентификатор аутентифицированного API-ключа, `getObsidianConfigForApiKey()`
предпочитает собственные токен, базовый URL и путь к хранилищу этого ключа
(`source: "api_key"`), а при их отсутствии использует глобальную конфигурацию
(`source: "global"`).

## Инструменты MCP (22)

Определены в `open-sse/mcp-server/tools/obsidianTools.ts`. Токен и базовый URL разрешаются
для каждого вызова (сначала для конкретного API-ключа, затем глобально). Инструменты, обращающиеся к **серверу синхронизации**
OmniRoute (четыре инструмента `obsidian_sync_*`), дополнительно требуют токен аутентификации синхронизации, настроенный
в параметрах OmniRoute.

### Инструменты чтения (`read:obsidian`)

| Инструмент                   | Описание                                                                                                               |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Проверить, доступен ли Local REST API и выполнена ли аутентификация.                                                   |
| `obsidian_search_simple`     | Полнотекстовый поиск по содержимому заметок; возвращает фрагменты с путями к файлам.                                   |
| `obsidian_search_structured` | Поиск с использованием выражения JSON Logic (фильтры and/or/regex/path).                                               |
| `obsidian_read_note`         | Прочитать заметку по пути относительно хранилища; при необходимости — конкретный заголовок, блок или frontmatter.      |
| `obsidian_list_vault`        | Вывести список файлов и каталогов в хранилище (дерево элементов).                                                      |
| `obsidian_get_document_map`  | Получить структуру заголовков заметки в виде карты «заголовки → номера строк».                                         |
| `obsidian_get_note_metadata` | Получить frontmatter, теги, ссылки и количество символов/слов без полного содержимого.                                 |
| `obsidian_get_active_file`   | Получить путь и содержимое текущего активного файла в Obsidian.                                                        |
| `obsidian_get_periodic_note` | Получить ежедневную, еженедельную или ежемесячную периодическую заметку для заданной даты (по умолчанию — сегодня).    |
| `obsidian_get_tags`          | Вывести все теги хранилища с частотой их использования.                                                                |
| `obsidian_list_commands`     | Вывести доступные идентификаторы команд Obsidian (для использования с `obsidian_execute_command`).                     |
| `obsidian_sync_status`       | Состояние сервера синхронизации OmniRoute: запущен ли он, имя хранилища, порт, время работы и последняя синхронизация. |
| `obsidian_sync_conflicts`    | Вывести неразрешённые конфликты синхронизации (путь, путь к конфликтующей версии, время обнаружения).                  |

### Инструменты записи (`write:obsidian`)

| Инструмент                       | Описание                                                                                                                           |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Создать или перезаписать заметку с заданным содержимым Markdown.                                                                   |
| `obsidian_append_note`           | Добавить содержимое в заметку; при необходимости — в конкретный заголовок или блок.                                                |
| `obsidian_patch_note`            | Точечно добавить содержимое в начало/конец или заменить его в заголовке, блоке либо поле frontmatter.                              |
| `obsidian_delete_note`           | Безвозвратно удалить заметку из хранилища.                                                                                         |
| `obsidian_move_note`             | Переместить или переименовать заметку в хранилище.                                                                                 |
| `obsidian_execute_command`       | Выполнить команду Obsidian по её идентификатору.                                                                                   |
| `obsidian_open_file`             | Открыть файл в Obsidian (создаёт его, если он не существует).                                                                      |
| `obsidian_sync_trigger`          | Запустить немедленную двунаправленную синхронизацию хранилища между настольным и мобильным устройствами.                           |
| `obsidian_sync_resolve_conflict` | Разрешить конфликт синхронизации: сохранить `local` (мобильную версию), `remote` (настольную версию) или `keep-both` (обе версии). |

> [!NOTE]
> Цели `obsidian_patch_note` принимают `targetType` со значением `heading | block | frontmatter`
> и `operation` со значением `append | prepend | replace`, а также необязательный параметр
> `createTargetIfMissing`. Четыре инструмента `obsidian_sync_*` обращаются к локальному серверу
> синхронизации (`http://127.0.0.1:27781` по умолчанию) и требуют токен синхронизации.

### Области доступа

Инструментам чтения требуется `read:obsidian`, а инструментам записи — `write:obsidian`. Применение ограничений
идентично Notion: оно выполняется функцией `withScopeEnforcement()` в
`open-sse/mcp-server/server.ts`, включается при `OMNIROUTE_MCP_ENFORCE_SCOPES=true`, а
разрешённые области доступа берутся из `OMNIROUTE_MCP_SCOPES` или контекста областей доступа API-ключа. См.
[MCP-SERVER.md](./MCP-SERVER.md).

## Эндпоинты

| Метод    | Путь                            | Назначение                                                                   |
| -------- | ------------------------------- | ---------------------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | Возвращает `{ connected, hasToken, baseUrl, vaultPath }`.                    |
| `POST`   | `/api/settings/obsidian`        | Сохраняет и проверяет токен (порт `27124` отклоняется).                      |
| `DELETE` | `/api/settings/obsidian`        | Отключает интеграцию (удаляет сохранённый токен).                            |
| `GET`    | `/api/settings/obsidian/webdav` | Возвращает статус синхронизации WebDAV и учётные данные (пока она включена). |
| `POST`   | `/api/settings/obsidian/webdav` | Включает синхронизацию WebDAV для каталога хранилища.                        |
| `DELETE` | `/api/settings/obsidian/webdav` | Отключает синхронизацию WebDAV.                                              |

> Это маршруты настроек панели управления. Доступ к самому хранилищу осуществляется через
> локальный REST API Obsidian (настроенный `base_url`) и через указанные выше инструменты MCP —
> публичной прокси-конечной точки Obsidian `/v1` не существует.

## Сценарии использования

- **Ответы на основе хранилища** — `obsidian_search_simple` / `obsidian_search_structured`,
  затем `obsidian_read_note`, чтобы агент отвечал на основе ваших реальных заметок.
- **Создание заметок / ведение журнала** — `obsidian_write_note`, `obsidian_append_note` или
  точечный инструмент `obsidian_patch_note` для сохранения результатов работы агента, сводок или ежедневных заметок
  (`obsidian_get_periodic_note`) в хранилище.
- **Навигация по хранилищу** — `obsidian_list_vault`, `obsidian_get_document_map` и
  `obsidian_get_tags` для изучения структуры перед чтением или записью.
- **Автоматизация Obsidian** — `obsidian_list_commands` + `obsidian_execute_command` для
  управления плагинами и командами через агента; `obsidian_open_file` для отображения заметки в интерфейсе.
- **Мобильная синхронизация** — включите синхронизацию WebDAV, затем используйте `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  для координации синхронизации между настольным и мобильным приложениями и разрешения конфликтов.
