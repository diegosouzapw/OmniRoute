OmniRoute разделяет **обнаружение CLI**, **нативный Agent Client Protocol** и
**устаревшие stdio-адаптеры**. Обнаружение установленного исполняемого файла не подтверждает
его аутентификацию, совместимость с моделью или готовность обрабатывать запрос.

Панель управления использует `GET /api/acp/agents` и `POST /api/acp/agents` для инвентаризации
и регистрации пользовательских агентов. Это локальные маршруты управления, а не
публичный API для запуска процессов или отправки запросов. Внутренний
`AcpManager` не становится автоматически резервным HTTP-провайдером.

## Зарегистрированные контракты

`config/cli-tools-manifest.json` является источником истины для встроенных исполняемых
файлов запуска, аргументов и режимов бэкенда. Реестр формирует свои определения
на основе этого манифеста. Результаты обнаружения кэшируются на 60 секунд.

- `acp`: контракт Gemini запускает `gemini --experimental-acp` и обменивается
  ACP JSON-RPC с разделением по строкам через официальный TypeScript SDK.
- `stdio-adapter`: другие зарегистрированные контракты сохраняют устаревший адаптер
  с построчным вводом и выводом в stdout. Двухсекундный период отсутствия вывода
  завершает формирование ответа. Этот адаптер **не** подтверждает нативную поддержку ACP
  этими CLI.

Gemini документирует флаг запуска в своем [справочнике по CLI](https://geminicli.com/docs/cli/cli-reference/).
Клиент использует [официальный ACP SDK](https://github.com/agentclientprotocol/typescript-sdk)
для инициализации, создания сеансов, отправки запросов, уведомлений и отмены.

Определения пользовательских агентов остаются контролируемыми администратором контрактами запуска.
Регистрация исполняемого файла и аргументов предоставляет этому процессу локальные
права выполнения пользователя сервера; регистрация не является песочницей. Проверки версий
принимают только зарегистрированный исполняемый файл и распознанный флаг версии.

## Внутренний API запуска

```typescript
import { acpManager } from "@/lib/acp";

const session = acpManager.spawn("gemini", {
  cwd: process.cwd(),
  // Передавайте только переменные провайдера, намеренно назначенные этому агенту.
  env: {
    GEMINI_API_KEY: process.env.GEMINI_API_KEY,
  },
});

try {
  const response = await acpManager.sendPrompt(session.id, "Объясни этот проект", 120_000);
  // Обработайте ответ в вызывающем приложении.
} finally {
  acpManager.kill(session.id);
}
```

`spawn(agentId, options)` определяет исполняемый файл и аргументы из
зарегистрированного определения. Единственные параметры вызывающей стороны — `cwd` и `env`;
старая сигнатура `spawn(agentId, binary, args, env)` и переопределения исполняемого файла
отклоняются. Этот менеджер не поддерживает HTTP-контракты запуска.

Дочерний процесс наследует те же настройки операционной системы, терминала, локали и
списка разрешенных сертификатов, что и средства запуска CLI. Секреты сервера/провайдера
не копируются из родительского окружения. Учетные данные, необходимые выбранному CLI,
должны быть переданы явно или предоставлены через собственную локальную аутентификацию
этого CLI. Дочерний процесс по-прежнему имеет права локального пользователя на файловую
систему и может читать собственную конфигурацию.

## Нативный жизненный цикл и ограничения

1. Запустить зарегистрированный исполняемый файл, инициализировать ACP и создать сеанс,
   связанный с выбранным рабочим каталогом. Инициализация ограничена десятью секундами.
2. Отправить запрос и собирать текстовые уведомления только для этого сеанса.
   Завершением считается ответ RPC на запрос, а не период отсутствия вывода в stdout.
3. Использовать один крайний срок выполнения запроса, включающий любую незавершенную
   инициализацию; по умолчанию он составляет 120 секунд. Параллельные запросы
   в одном процессе отклоняются.
4. При превышении времени ожидания нативной операции попытаться выполнить `session/cancel`
   и завершить процесс. Ограниченное окно в 100 мс позволяет сбросить уведомления
   перед завершением.
5. Закрыть состояние транспорта и удалить сеанс при сбое инициализации, закрытии
   соединения, завершении процесса или принудительном завершении со стороны вызывающего кода.

Запросы разрешений для инструментов отклоняются. Клиентские возможности файловой системы
или терминала не объявляются. Эти ограничения не помещают сам дочерний исполняемый файл
в песочницу и не заменяют собственные настройки авторизации CLI.

Как нативный текст, так и устаревшие stdout/stderr сохраняют не более 1 МиБ символов,
оставляя самый новый вывод с уведомлением об усечении. Размер отдельного нативного кадра
протокола ограничен 2 МиБ до обработки SDK. Буферы сбрасываются для каждого запроса.

`kill(sessionId)` отправляет SIGTERM, а затем SIGKILL через пять секунд, если процесс
не завершился. Тайм-ауты устаревших запросов освобождают обработчики событий и таймеры,
но оставляют сеанс доступным для другого запроса; по завершении работы вызывающая сторона
по-прежнему отвечает за вызов `kill()` или `killAll()`.

## События и проверка состояния

Менеджер генерирует события `stdout`, `stderr` и `exit`, каждое с `sessionId`.
`sessionError` сообщает санитизированную ошибку транспорта. Событие совместимости `error`
генерируется только при наличии подписчика, поэтому отсутствие исполняемого файла не может
привести к необработанной ошибке EventEmitter.

- `getSession(sessionId)` возвращает управляемый сеанс или `undefined`.
- `getActiveSessions()` исключает остановленные или останавливаемые сеансы.
- `sendInput(sessionId, input)` доступен только для активного устаревшего адаптера;
  нативный ACP отклоняет необработанный ввод для защиты своего потока JSON-RPC.
- `killAll()` завершает все сеансы, управляемые данным экземпляром.

## Границы проверки

Детерминированные фикстуры охватывают нативное установление соединения, текстовый вывод,
отклонение разрешений, отмену, параллельные запросы, неудачную инициализацию, завершение
процесса, ограничения вывода и изоляцию секретов. Существующие регрессионные тесты
буферов и обработчиков устаревшего адаптера также сохраняются. Эти тесты не подтверждают
работоспособность входа в Gemini или успешный инференс провайдера; для этого требуется
отдельно авторизованный smoke-тест в целевом окружении.
