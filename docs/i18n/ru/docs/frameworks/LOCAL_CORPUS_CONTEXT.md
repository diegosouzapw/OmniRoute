> `src/lib/db/localCorpus.ts` (хранение пути к корневому каталогу),
> `open-sse/mcp-server/tools/localCorpusTools.ts` (3 инструмента MCP только для чтения) и
> `src/app/api/settings/local-corpus/route.ts` (API настроек).

## Что это такое

Local Corpus позволяет оператору предоставить MCP-серверу OmniRoute доступ к одному явно одобренному каталогу с текстовыми файлами. Файлы остаются в исходном каталоге: OmniRoute хранит в SQLite только канонический путь к корневому каталогу и поддерживает поисковый индекс в памяти. Содержимое корпуса не копируется в репозиторий или базу данных.

Индекс обновляется инкрементно. Неизменённые файлы повторно используются на основании их размера и времени изменения, изменённые файлы считываются заново и хешируются с помощью SHA-256, а удалённые файлы исключаются. При поиске обновляется индекс, если он старше 30 секунд; вызывающая сторона также может запросить немедленное обновление.

## Настройка источника

Маршрут настроек требует той же управленческой аутентификации, что и другие API настроек. Передаваемый путь должен уже существовать и быть абсолютным путём к каталогу.

```bash
# Подключить одобренный каталог
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# Проверить конфигурацию и состояние индекса
curl http://localhost:20128/api/settings/local-corpus

# Отключить каталог, не изменяя исходные файлы
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## Инструменты MCP

Для всех трёх инструментов требуется `read:local-corpus`. В ответах инструментов указываются относительные пути и базовое имя корневого каталога, но никогда не раскрывается его абсолютный путь.

| Инструмент            | Описание                                                                                                                 |
| :-------------------- | :----------------------------------------------------------------------------------------------------------------------- |
| `local_corpus_status` | Сообщает состояние конфигурации, размер индекса, ограничения и время последнего обновления                               |
| `local_corpus_search` | Выполняет поиск по индексированному тексту и возвращает ограниченные фрагменты с привязкой к строкам (до 20 результатов) |
| `local_corpus_read`   | Читает ограниченный диапазон строк из одного разрешённого файла по пути относительно корпуса                             |

Примеры входных данных MCP:

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## Границы безопасности

- Список разрешённых расширений ориентирован на текстовые файлы: `.cfg`, `.csv`, `.geojson`, `.htm`, `.html`, `.ini`,
  `.js`, `.json`, `.jsonl`, `.jsx`, `.log`, `.md`, `.mjs`, `.ps1`, `.py`, `.sh`,
  `.sql`, `.toml`, `.ts`, `.tsx`, `.txt`, `.xml`, `.yaml` и `.yml`.
- Символические ссылки пропускаются. Пути для чтения канонизируются и должны оставаться внутри
  настроенного корневого каталога; абсолютные пути и попытки обхода каталогов отклоняются.
- Конфиденциальные и сгенерированные каталоги исключаются по именам: `.build`, `.codex`, `.env`,
  `.git`, `.next`, `.omniroute`, `.ssh`, `coverage`, `dist`, `node_modules` и
  `secrets`.
- Ограничения по умолчанию: 5 000 файлов, 1 МиБ на файл, 64 МиБ общего объёма индексируемого содержимого,
  приблизительно 4 000 символов на поисковый фрагмент и 400 строк на операцию чтения.
- Файлы, содержащие NUL, считаются нетекстовыми и пропускаются или отклоняются.

Бинарные документы, такие как PDF, DOCX, изображения и архивы, намеренно не поддерживаются.
Перед индексированием преобразуйте их в разрешённый текстовый формат в настроенном каталоге.

## Примечания по эксплуатации

- Изменение или удаление настроенного корневого каталога очищает общий индекс в памяти.
- При перезапуске процесса индекс удаляется; при следующем поиске он перестраивается из настроенного
  источника.
- `local_corpus_status` не запускает принудительное сканирование. Если требуется немедленное повторное сканирование, используйте `local_corpus_search` с
  `refresh: true`.
- Ошибки сканирования и чтения подсчитываются или возвращаются в очищенном виде; исходные файлы
  никогда не изменяются.
