Провайдеры Web Cookie позволяют OmniRoute использовать сервис ИИ через существующий сеанс браузера вместо API-ключа. Они полезны, если у вас уже есть доступ к сервису через его веб-сайт и вы хотите, чтобы OmniRoute использовал тот же аутентифицированный сеанс.

В отличие от провайдеров с API-ключами, провайдеры Web Cookie выполняют аутентификацию с помощью учётных данных, которые браузер отправляет веб-сайту.

---

# Перед началом работы

> **Важно:** Всегда копируйте учётные данные из **активного сетевого запроса**, а **не** из хранилища файлов cookie браузера.

Многие проблемы с аутентификацией возникают из-за копирования файлов cookie из неправильного места.

## НЕ копируйте из хранилища файлов cookie

В большинстве браузеров сохранённые файлы cookie доступны по следующему пути:

```
DevTools
→ Application (или Storage)
→ Cookies
```

Хотя эти файлы cookie могут выглядеть корректно, они могут быть:

- устаревшими
- неполными
- без файлов cookie, отправляемых только с аутентифицированными запросами

Использование этих значений может привести к сбоям аутентификации, даже если они кажутся действительными.

## Копируйте из активного запроса

Вместо этого используйте файлы cookie из успешно выполненного запроса:

```
DevTools
→ Network
→ Обновите страницу
→ Откройте запрос чата или беседы
→ Request Headers
→ Cookie
```

Заголовок запроса `Cookie` содержит точные данные аутентификации, которые браузер успешно использовал.

Для большинства провайдеров Web Cookie именно это значение следует вставить в OmniRoute.

# Общая настройка

Процесс настройки одинаков для большинства провайдеров Web Cookie.

1. Войдите на веб-сайт провайдера.
2. Откройте инструменты разработчика браузера.
3. Откройте вкладку **Network**.
4. Обновите страницу.
5. Откройте аутентифицированный запрос чата или беседы.
6. Скопируйте необходимые учётные данные для аутентификации.
7. Откройте OmniRoute.
8. Перейдите в раздел **Providers → Add Provider**.
9. Выберите своего провайдера Web Cookie.
10. Вставьте учётные данные.
11. Нажмите **Test Connection**.
12. Сохраните провайдера.

Точный набор необходимых учётных данных зависит от провайдера.

# Возможности и ограничения провайдеров Web Cookie

Провайдеры Web Cookie повторно используют интерфейс чата веб-сайта. Они **не** предоставляют те же возможности, что и официальные API.

## Поддерживается

- Аутентификация с помощью существующего сеанса браузера
- Доступ к моделям, доступным в вашей учётной записи
- Потоковая передача ответов чата
- API-ключ не требуется

## Не поддерживается

- Вызов функций
- Вызов инструментов
- Автоматическое редактирование файлов
- Агентные рабочие процессы в IDE
- Возможности, доступные только через API

Это ожидаемое поведение, а **не** ошибка.

Если вам нужно выполнение инструментов, автоматическое редактирование файлов или другие агентные рабочие процессы, используйте **провайдера с API-ключом** вместо провайдера Web Cookie.

---

# Ограничение проверки

Успешное выполнение **Test Connection** или проверка файлов cookie подтверждает лишь то, что предоставленные учётные данные соответствуют ожидаемому формату.

Пока проблема #7857 не решена, успешная проверка **не гарантирует**, что провайдер сможет успешно выполнить аутентификацию.

Если аутентификация по-прежнему завершается сбоем, убедитесь, что вы скопировали учётные данные из активного сетевого запроса, а не из хранилища файлов cookie браузера.

---

# Устранение неполадок

## Сбой аутентификации

Убедитесь, что учётные данные были скопированы из:

```
Network
→ Request Headers
→ Cookie
```

а **не** из:

```
Application
→ Cookies
```

---

## Файлы cookie работают в браузере, но не в OmniRoute

Некоторые провайдеры используют файлы cookie, которые отправляются только во время аутентифицированных запросов.

Повторно скопируйте учётные данные из нового сетевого запроса после успешного открытия беседы.

---

## Срок действия сеанса истёк

Провайдеры Web Cookie используют существующий сеанс браузера.

Если срок действия сеанса браузера истёк или вы вышли из системы, необходимо скопировать новый набор учётных данных.

---

## Test Connection проходит успешно, но запросы завершаются сбоем

Пока проблема #7857 не решена, успешная проверка не гарантирует успешного выполнения запроса аутентификации.

Прежде чем продолжить устранение неполадок, повторно скопируйте учётные данные из нового аутентифицированного запроса.

# Рекомендации

- Копируйте учётные данные из нового аутентифицированного запроса.
- Не используйте повторно старые файлы cookie.
- Поддерживайте сеанс браузера активным во время использования провайдеров Web Cookie.
- Обращайтесь со скопированными файлами cookie как с конфиденциальными учётными данными.
- Используйте провайдеров с API-ключами, если вам необходимы вызов функций или агентные рабочие процессы.
