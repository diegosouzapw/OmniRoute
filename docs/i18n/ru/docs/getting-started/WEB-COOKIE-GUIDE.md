Провайдеры Web Cookie позволяют OmniRoute использовать сервис ИИ через существующий сеанс браузера вместо ключа API. Они полезны, если у вас уже есть доступ к сервису через его веб-сайт и вы хотите, чтобы OmniRoute использовал тот же аутентифицированный сеанс.

В отличие от провайдеров с ключом API, провайдеры Web Cookie выполняют аутентификацию с помощью учётных данных, которые браузер отправляет веб-сайту.

---

# Перед началом

> **Важно:** Всегда копируйте учётные данные из **активного сетевого запроса**, а **не** из хранилища файлов cookie браузера.

Многие проблемы с аутентификацией возникают из-за копирования файлов cookie не из того места.

## НЕ копируйте из хранилища файлов cookie

Большинство браузеров позволяет просматривать сохранённые файлы cookie через:

```
DevTools
→ Application (или Storage)
→ Cookies
```

Хотя эти файлы cookie могут выглядеть корректно, они могут быть:

- устаревшими
- неполными
- без файлов cookie, отправляемых только в аутентифицированных запросах

Использование этих значений может привести к сбоям аутентификации, даже если они выглядят действительными.

## Копируйте из активного запроса

Вместо этого используйте файлы cookie из успешно выполненного запроса:

```
DevTools
→ Network
→ Обновите страницу
→ Откройте запрос чата или беседы
→ Request Headers
→ Cookie
```

Заголовок запроса `Cookie` содержит точные данные аутентификации, которые браузер успешно использовал.

Для большинства провайдеров Web Cookie именно это значение следует вставить в OmniRoute.

# Общая настройка

Процесс настройки одинаков для большинства провайдеров Web Cookie.

1. Войдите на веб-сайт провайдера.
2. Откройте инструменты разработчика браузера.
3. Откройте вкладку **Network**.
4. Обновите страницу.
5. Откройте аутентифицированный запрос чата или беседы.
6. Скопируйте необходимые учётные данные для аутентификации.
7. Откройте OmniRoute.
8. Перейдите в раздел **Providers → Add Provider**.
9. Выберите своего провайдера Web Cookie.
10. Вставьте учётные данные.
11. Нажмите **Test Connection**.
12. Сохраните провайдера.

Точный набор необходимых учётных данных зависит от провайдера.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) — это бесплатная пользовательская чат-платформа, не требующая регистрации. Анонимный сеанс создаётся при первом посещении и сохраняется с помощью трёх файлов cookie: `uid`, `si_usr_id` и `si_ses_id`. OmniRoute проксирует тот же эндпоинт `/api/dispatch` через единый идентификатор модели (`notrack-c`, псевдоним `ntw`).

### Шаги для подключения

1. Откройте [notrack.ai](https://notrack.ai) в браузере и дождитесь установки файла cookie анонимного сеанса.
2. Откройте **DevTools → Network**, обновите страницу и выберите любой запрос к `/api`.
3. В разделе **Request Headers** скопируйте полное значение заголовка `Cookie`.
4. В OmniRoute перейдите в раздел **Providers → Add Provider → NoTrack Web (Free)**.
5. Вставьте строку cookie в поле `apiKey` и нажмите **Save**.

OmniRoute извлекает `uid`, `si_usr_id` и `si_ses_id` из вставленной строки и формирует чистый заголовок `Cookie`, содержащий только эти пары, а также `nt_session` (токен `ntk_…`, устанавливаемый для учётных записей с выполненным входом), если он присутствует. Если отсутствует хотя бы один из трёх параметров, исходная вставленная строка пересылается без изменений, чтобы операторы могли экспериментировать с альтернативными форматами.

### Идентификаторы моделей

| Идентификатор модели | Отображаемое имя | Примечания                                                   |
| -------------------- | ---------------- | ------------------------------------------------------------ |
| `notrack-c`          | NoTrack C        | По умолчанию — вышестоящая модель диспетчеризации `C`.       |
| `C`                  | NoTrack C        | Псевдоним для `notrack-c` (исходный код вышестоящей модели). |
| `notrack`            | NoTrack C        | Псевдоним для `notrack-c`.                                   |
| `ntw`                | NoTrack C        | Короткий псевдоним для `notrack-c`.                          |

Все четыре идентификатора модели соответствуют одной и той же вышестоящей модели диспетчеризации (`C`).

### Параметры запроса

Исполнитель принимает следующие необязательные поля в теле запроса:

| Поле тела запроса     | Значение по умолчанию | Назначение                                                                                      |
| --------------------- | --------------------- | ----------------------------------------------------------------------------------------------- |
| `notrack_mode`        | `usual`               | Режим диспетчеризации (произвольная строка; вышестоящий сервис принимает `usual`, …)            |
| `notrack_max_turns`   | `6`                   | Количество внутренних итераций, которые вышестоящий сервис может выполнить перед ответом.       |
| `notrack_chat_id`     | `null`                | Продолжить существующий чат вышестоящего сервиса (не указывайте для нового чата).               |
| `notrack_attachments` | `[]`                  | Массив дескрипторов вложений вышестоящего сервиса, передаваемый без изменений.                  |
| `notrack_regenerate`  | `false`               | Установите значение `true`, чтобы запросить повторную генерацию ответа для предыдущей итерации. |

### Возможности

- **Потоковые и непотоковые** ответы чата.
- **Вызов инструментов** — укажите `tools: [...]` в запросе; исполнитель сериализует их в формат конверта вызова инструментов и преобразует ответы модели обратно в OpenAI `tool_calls`.
- **`response_format`** — поддерживаются `json_object` и `json_schema`. Исполнитель извлекает первый объект JSON из ответа модели и сериализует его в строку перед возвратом.
- **Указание на рассуждение** — исполнитель отправляет дельту `reasoning`, когда вышестоящий сервис отправляет событие `thinking`.

### Ограничения

- Вышестоящий сервис применяет квоты анонимного использования — при их превышении исполнитель возвращает ошибку 429 с понятным сообщением.
- Все идентификаторы моделей соответствуют одной и той же вышестоящей модели диспетчеризации; переключение между моделями отсутствует.
- Исполнитель не вызывает эндпоинт `/api/chats` вышестоящего сервиса, поэтому история чата и сеансы не управляются автоматически. Используйте `notrack_chat_id`, чтобы продолжить существующий чат вышестоящего сервиса.

# Что могут и чего не могут провайдеры Web Cookie

Провайдеры Web Cookie повторно используют интерфейс чата веб-сайта. Они **не** предоставляют те же возможности, что и официальные API.

## Поддерживается

- Аутентификация с использованием существующего сеанса браузера
- Доступ к моделям, доступным через вашу учетную запись
- Потоковая передача ответов чата
- API-ключ не требуется

## Не поддерживается

- Вызов функций
- Вызов инструментов
- Автоматическое редактирование файлов
- Агентные рабочие процессы в IDE
- Функции, доступные только через API

Это ожидаемое поведение, и оно **не** является ошибкой.

Если вам требуется выполнение инструментов, автоматическое редактирование файлов или другие агентные рабочие процессы, используйте поставщика **с API-ключом** вместо поставщика Web Cookie.

# Ограничение проверки

Успешная **проверка подключения** или проверка файлов cookie лишь подтверждает, что предоставленные учетные данные имеют ожидаемый формат.

До устранения проблемы #7857 успешная проверка **не гарантирует**, что поставщик сможет успешно выполнить аутентификацию.

Если аутентификация по-прежнему не выполняется, убедитесь, что вы скопировали учетные данные из активного сетевого запроса, а не из хранилища файлов cookie браузера.

---

# Устранение неполадок

## Ошибка аутентификации

Убедитесь, что учетные данные были скопированы из:

```
Сеть
→ Заголовки запроса
→ Cookie
```

а **не** из:

```
Приложение
→ Файлы cookie
```

---

## Файлы cookie работают в браузере, но не в OmniRoute

Некоторые поставщики используют файлы cookie, которые отправляются только во время аутентифицированных запросов.

Повторно скопируйте учетные данные из нового сетевого запроса после успешного открытия беседы.

---

## Срок действия сеанса истек

Поставщики Web Cookie используют существующий сеанс браузера.

Если срок действия сеанса браузера истечет или вы выйдете из учетной записи, необходимо скопировать новый набор учетных данных. Чтобы автоматизировать обновление файлов cookie для поддерживаемых веб-поставщиков, воспользуйтесь вспомогательным инструментом [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md).

---

## Проверка подключения проходит успешно, но запросы завершаются с ошибкой

До устранения проблемы #7857 успешное прохождение проверки не гарантирует успешного выполнения запроса аутентификации.

Прежде чем продолжать устранение неполадок, повторно скопируйте учетные данные из нового аутентифицированного запроса.

# Рекомендации

- Копируйте учетные данные из нового аутентифицированного запроса.
- Не используйте повторно старые файлы cookie.
- Поддерживайте сеанс браузера активным во время использования поставщиков Web Cookie.
- Обращайтесь со скопированными файлами cookie как с конфиденциальными учетными данными.
- Используйте поставщиков с API-ключом, если вам требуется вызов функций или агентные рабочие процессы.
