`copilot-m365-web` (псевдоним `m365copilot`) отправляет запросы чата в формате OpenAI через
аутентифицированный браузерный сеанс Microsoft 365 Copilot BizChat по адресу
`m365.cloud.microsoft/chat`. Это неофициальная интеграция.

> **Впервые используете провайдеры Web Cookie?**
>
> Перед выполнением инструкций этого руководства для конкретного провайдера прочитайте **`docs/getting-started/WEB-COOKIE-GUIDE.md`**, где описаны общий процесс настройки, рекомендации по аутентификации, ограничения и устранение неполадок.
>
> **Важно:** Учетные данные для этого провайдера — **не файл cookie**. Не копируйте
> файлы cookie с `m365.cloud.microsoft`. Учетными данными являются параметр запроса URL-адреса WebSocket
> и сегмент пути, которые можно получить на вкладке Network в DevTools.

## Предварительные требования

- Учетная запись Microsoft 365 с доступом к BizChat по адресу `m365.cloud.microsoft/chat`
- Браузер на базе Chromium (Chrome, Edge) для проверки WebSocket через DevTools
- Лицензия M365 Copilot (включена во многие планы Microsoft 365 Business/Enterprise)

## Получение учетных данных (метод WebSocket)

1. Войдите в систему по адресу `https://m365.cloud.microsoft/chat` и начните беседу.
2. Откройте **DevTools → Network**.
3. Отфильтруйте по **WS** (WebSocket).
4. Нажмите на WebSocket-соединение Chathub. Найдите URL-адрес, начинающийся с
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Из его **Request URL** скопируйте:
   - Значение параметра запроса `access_token` (короткоживущий JWT).
   - Сегмент пути Chathub после `/Chathub/` (например, `<oid>@<tenant>`).

Полный URL-адрес имеет следующий вид:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. В OmniRoute перейдите в раздел **Providers → Add Provider**, выберите **Microsoft 365 Copilot
   (BizChat)** и вставьте учетные данные в следующем формате:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Нажмите **Test Connection**, а затем **Save**.

## Получение учетных данных (импорт HAR)

Вместо ручного копирования значений из URL-адреса WebSocket можно экспортировать HAR-файл
из DevTools:

1. Откройте **DevTools → Network**.
2. Начните или продолжите беседу в BizChat (это инициирует WebSocket-соединение).
3. Щелкните правой кнопкой мыши на панели Network и выберите **Save all as HAR with content**.
4. В OmniRoute используйте кнопку **Import .har file** в диалоговом окне подключения провайдера.

OmniRoute сканирует HAR-файл на наличие URL-адреса WebSocket Chathub, извлекает
`access_token` и `chathubPath` и автоматически заполняет поля учетных данных. При
импорте HAR декодируется срок действия JWT и отображается оставшееся время жизни токена.

> **Никогда не добавляйте реальный экспорт HAR, токен доступа или токен обновления в репозиторий.** В тестах и
> документации всегда должны использоваться значения-заполнители.

## Срок действия и обновление токена

`access_token` имеет короткий срок действия (обычно **~75 минут**). После истечения срока действия провайдер
сообщает об ошибке подключения, и вам необходимо повторно получить учетные данные.

### Автоматическое обновление с помощью `refreshToken`

Чтобы избежать повторного получения вручную, можно сохранить токен обновления Microsoft в разделе
**Advanced Settings → providerSpecificData** подключения:

| Поле           | Описание                                                                   |
| -------------- | -------------------------------------------------------------------------- |
| `refreshToken` | Токен обновления Microsoft OAuth для области `substrate.office.com/sydney` |
| `tier`         | `individual` (по умолчанию), `edu` или `enterprise`                        |

Получите токен обновления с помощью потока Microsoft device-code или authorization-code
с областью `substrate.office.com/sydney`. Если задан `refreshToken`, OmniRoute
предварительно обновляет `access_token` перед каждым запросом, поэтому вам не требуется
повторно получать его после каждого истечения срока действия через ~75 минут.

Если `refreshToken` не задан, после каждого истечения срока действия необходимо вручную
повторно получать учетные данные WebSocket.

### Выбор уровня

| Уровень      | Псевдоним        | Вариант использования        |
| ------------ | ---------------- | ---------------------------- |
| `individual` | _(по умолчанию)_ | M365 Copilot для частных лиц |
| `edu`        | `included`       | M365 Copilot для образования |
| `enterprise` | `work`           | M365 Copilot для работы      |

Задайте уровень в разделе **Advanced Settings → providerSpecificData → tier**. Уровень влияет
на маршрутизацию BizChat и доступ к моделям.

## Модель безопасности

- **Неофициальная интеграция.** Этот провайдер использует протокол BizChat WebSocket,
  реализованный методом обратной разработки. Интеграция может перестать работать без предупреждения, если Microsoft изменит конечную точку.
- Флаг `subscriptionRisk: true` указывает, что интеграция использует
  недокументированную конечную точку. Ограничения учетной записи возможны, но не подтверждены.
- Токен доступа представляет собой краткосрочный JWT. Обращайтесь с ним как с паролем: не добавляйте его в коммиты,
  не записывайте в журналы и не передавайте другим.
- Токен обновления предоставляет долгосрочный доступ к интерфейсу BizChat. Храните его
  так же безопасно, как ключ API.

## Устранение неполадок

### Аутентификация немедленно завершается с ошибкой

- Убедитесь, что вы скопировали данные из **URL-адреса WebSocket**, а не из запроса XHR/Fetch. Учетные
  данные находятся в параметре запроса `access_token` подключения Chathub WebSocket,
  а не в заголовке `Authorization: Bearer`.
- Убедитесь, что `chathubPath` содержит полный сегмент `<oid>@<tenant>` из пути
  URL-адреса.

### Срок действия токена истекает примерно через 75 минут

Это ожидаемое поведение. Без `refreshToken` токен доступа действует недолго. Выполните одно из следующих действий:

- Повторно получите учетные данные через DevTools или
- Настройте `refreshToken` в расширенных настройках для автоматического обновления.

### Проверка подключения проходит успешно, но чат возвращает ошибку 401

Срок действия токена мог истечь между проверкой и первым запросом. Повторно получите
актуальные учетные данные.

### Copilot отсутствует в списке провайдеров

Убедитесь, что `copilot-m365-web` включен в разделе **Панель управления → Провайдеры**. В некоторых
тарифах провайдер может быть скрыт по умолчанию.
