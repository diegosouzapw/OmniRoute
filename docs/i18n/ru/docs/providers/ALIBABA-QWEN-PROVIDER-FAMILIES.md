В этом документе зафиксировано решение по реализации для
[задачи #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854). Публичные продукты
представлены в виде четырёх семейств провайдеров. Регион — это данные подключения, а не отдельный продукт.

## Решение

| Семейство провайдеров                                     | ID в OmniRoute          | Глобальный регион | Регион Китая |
| --------------------------------------------------------- | ----------------------- | ----------------- | ------------ |
| Alibaba Cloud Model Studio (оплата по мере использования) | `alibaba`               | Сингапур          | Пекин        |
| Тарифный план Alibaba Cloud Token                         | `bailian-coding-plan`   | Сингапур          | Пекин        |
| Qwen Cloud (оплата по мере использования)                 | `qwen-cloud`            | Глобальный        | Пекин        |
| Тарифный план Qwen Cloud Token                            | `qwen-cloud-token-plan` | Сингапур          | Пекин        |

Существующий ID `alibaba-cn` остаётся псевдонимом для совместимости во время выполнения для сохранённых подключений, маршрутов
моделей, комбинаций и исторических данных об использовании. Его карточка на панели управления объединена с `alibaba`; перезапись
базы данных не требуется.

Qwen Cloud с оплатой по мере использования и Alibaba Cloud Model Studio в настоящее время используют общие хосты среды выполнения,
совместимые с DashScope, но остаются отдельными провайдерами, поскольку пользователи получают ключи и управляют
учётными записями через разные интерфейсы продуктов. Продукты Alibaba и Qwen Cloud Token Plan используют
разные семейства конечных точек, поэтому все четыре продукта остаются отдельными ID провайдеров.

## Матрица конечных точек

| Семейство провайдеров   | `global-sg`                                                              | `china-beijing`                                                      | Формат обмена |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ------------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI        |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic     |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI        |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI        |

Ключ API и конечная точка должны относиться к одному продукту и региону. При выборе региона изменяется
предустановленная конечная точка, используемая для проверки и обычных запросов.

## Контракт подключения

Новые подключения сохраняют стабильный ключ региона в `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

Допустимые значения: `global-sg` и `china-beijing`. Конечная точка централизованно определяется на основе
ID провайдера и региона. Значение `providerSpecificData.baseUrl`, не соответствующее предустановленному, остаётся явным
переопределением оператора и имеет приоритет, тогда как старые сохранённые предустановленные URL нормализуются в соответствии с региональной
матрицей.

Так схема подключения остаётся расширяемой: в резолвер можно добавить другой регион без
создания ещё одной карточки провайдера или изменения сохранённых ID провайдеров.

## Совместимость и развертывание

1. Добавить региональный механизм выбора конечных точек и сохранить текущие глобальные значения по умолчанию.
2. Использовать динамическое региональное обнаружение DashScope `/models` для `alibaba`, совместимого с ним
   идентификатора `alibaba-cn` и `qwen-cloud`. Их ответы сначала проходят фильтр моделей генерации текста,
   поскольку универсальная конечная точка также возвращает модели для изображений, видео, аудио, эмбеддингов
   и другие модели, не предназначенные для чатов. Затем `qwen-cloud` применяет поддерживаемый список разрешенных
   моделей, объявленный в его реестре провайдера. Alibaba Model Studio и Qwen Cloud используют отдельные
   курируемые каталоги, хотя в настоящее время они работают на общих хостах.
3. Зарегистрировать `qwen-cloud-token-plan` с текущим списком разрешенных текстовых моделей Token Plan.
4. Добавить типизированный селектор региона в диалоги добавления и редактирования подключений.
5. Скрыть дублирующую карточку `alibaba-cn` и включить существующие подключения этого провайдера на страницу
   провайдера `alibaba`.
6. Сохранить возможность переопределения пользовательских конечных точек для расширенных развертываний
   и развертываний, специфичных для рабочих пространств.

Медиа-модели Token Plan остаются вне каталога чатов, поскольку они используют выделенные конечные точки.
`wan2.7-image` и `wan2.7-image-pro` зарегистрированы в `open-sse/config/imageRegistry.ts`;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` и `happyhorse-1.1-r2v` зарегистрированы в
`open-sse/config/videoRegistry.ts`. Оба реестра повторно используют идентификатор подключения
`qwen-cloud-token-plan` и соответствующие региону учетные данные.

Обычный Qwen Cloud имеет отдельные каталоги изображений и видео с оплатой по факту использования под
идентификатором `qwen-cloud`. Его модели изображений: `wan2.7-image-pro`, `wan2.7-image`,
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` и
`z-image-turbo`. Его модели видео: `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`,
`happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`,
`wan2.7-r2v-2026-06-12` и `wan2.7-videoedit`. Эти модели используют только обычное подключение
`qwen-cloud` и региональную медиа-конечную точку DashScope. Реестры Token Plan и модели с оплатой
по факту использования не наследуют и не объединяют списки моделей друг друга.

Идентификатор `bailian-coding-plan` также имеет собственные списки разрешенных медиа-моделей:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` и `qwen-image-2.0-pro` для генерации
изображений, а также
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` и `happyhorse-1.1-r2v` для генерации
видео. Он использует только подключение Bailian Coding Plan и региональную конечную точку Coding Plan.
Его реестры изображений и видео не наследуются и не объединяются ни с одним из провайдеров Qwen Cloud.

Обычный идентификатор `alibaba` имеет отдельные списки разрешенных моделей изображений и видео. Его модели
изображений: `qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` и `wan2.6-t2i`. Добавленные модели видео: `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` и `wan2.7-videoedit`. Эти модели используют только подключение Alibaba
Model Studio и выбранную для него региональную медиа-конечную точку; они не добавляются ни в один
реестр Coding Plan или Qwen Cloud.

Каталог чатов Qwen Cloud Token Plan следует точному списку разрешенных текстовых моделей тарифа Individual:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` и
`deepseek-v4-pro`. Записи Wan и HappyHorse относятся к отдельным API генерации изображений и видео.

Alibaba Token Plan предоставляет те же шесть текущих идентификаторов моделей генерации текста через
Anthropic-совместимую конечную точку. Вариант для Сингапура сохраняет существующий ключ региона `global-sg`;
от других семейств провайдеров, называющих этот регион Global, отличается только отображаемая пользователю метка.

Обычный каталог чатов Qwen Cloud намеренно уже полного динамического ответа с текстовыми моделями. Поддерживаемый
список разрешенных моделей находится в `open-sse/config/providers/registry/qwen-cloud/index.ts`; динамическое
обнаружение возвращает только идентификаторы, присутствующие одновременно в ответе вышестоящего сервиса и в этом
списке реестра.

Alibaba Model Studio следует тому же правилу пересечения динамически полученного списка с собственным независимо
поддерживаемым списком разрешенных моделей в `open-sse/config/providers/registry/alibaba/index.ts`. Провайдер
совместимости `alibaba-cn` повторно использует этот каталог, выполняя обнаружение через конечную точку в Пекине.
