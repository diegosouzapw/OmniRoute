`chatgpt-web-codex` (псевдоним `cgpt-codex`) передаёт ходы Codex Responses через
аутентифицированный браузерный сеанс ChatGPT. Он не зависит от выведенного из эксплуатации общего
провайдера `chatgpt-web` и использует реализацию с уведомлением MIT из
`open-sse/vendor/codex-chatgpt-web/`, обновлённую до коммита upstream v4.0.7
`b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494`.

## Вывод общего провайдера из эксплуатации

Прежние идентификаторы общего провайдера `chatgpt-web` и `cgpt-web` больше не поставляются, поскольку
происхождение их реализации предварительного ключа/доказательства выполнения работы не удалось подтвердить. Явные
запросы к любому из этих идентификаторов, включая идентификаторы моделей с префиксом-косой чертой и сохранённые псевдонимы, завершаются
отказом с HTTP `410` и кодом **PROVIDER_RETIRED** до отправки какого-либо запроса upstream.

Миграция `168_retire_chatgpt_web.sql` помечает соответствующие подключения провайдера как удалённые и
аннулирует их активные аренды сеансов. Она сохраняет историю подключений и списки разрешённых
API-ключей; она не добавляет в список разрешений доступ к замене. На провайдер Codex и
его подключения этот вывод из эксплуатации не распространяется.

## Предварительные требования

- полный заголовок Cookie из авторизованного сеанса ChatGPT;
- Chrome или Chromium, а также графический сеанс или дисплей Xvfb для установок npm, systemd и PM2;
- при использовании профиля Docker `web` — внутренний сервис Chromium из
  `docker-compose.yml`;
- OpenAI `tunnel-client` v0.0.13 и пользовательский коннектор ChatGPT для локальных инструментов Codex.

Туннель требуется только для ходов с инструментами. Каждый из перечисленных маршрутов, включая `pro`, может использовать
одну и ту же локальную возможность инструментов, привязанную к ходу, если туннель и коннектор настроены.

## Настройка через панель управления

1. Откройте провайдер **ChatGPT Web (Codex)** и добавьте подключение.
2. Вставьте полный заголовок Cookie ChatGPT, идентификатор туннеля, ключ среды выполнения и имя пользовательского коннектора.
   Для новых конфигураций с поддержкой инструментов необходимо использовать вновь созданный коннектор с точным именем
   `OmniRoute Codex v2`, параметром Authentication, установленным в None, и параметром Permissions, установленным в Allow all
   actions.
3. Запустите проверку подключения. OmniRoute открывает поддерживаемый браузером Temporary Chat и определяет,
   доступны ли для учётной записи Sol и Pro.
4. Сохраните подключение. OmniRoute заменяет вставленный файл cookie проверенным
   состоянием хранилища Playwright и сохраняет его вместе с ключом среды выполнения через абстракцию
   зашифрованных учётных данных.

Необработанный файл cookie не сохраняется после успешного сохранения. Когда срок действия сеанса истечёт, откройте
подключение, вставьте новый полный заголовок Cookie и повторно запустите проверку. Статус диагностики
в диалоговом окне редактирования отдельно сообщает о браузере, состоянии хранилища, входе в систему, Temporary Chat, туннеле,
коннекторе и цикле вызова инструмента.

> Никогда не добавляйте в коммит реальные файлы cookie, ключи среды выполнения, состояния хранилища или токены возможностей. Значения для тестов и
> документации всегда должны быть заполнителями.

## Модели и комбинации

Доступны следующие фиксированные маршруты моделей:

- `chatgpt-web-codex/luna` — GPT-5.6 Luna, низкий уровень рассуждений
- `chatgpt-web-codex/think` — GPT-5.6 Luna, средний уровень рассуждений
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

Добавьте любой из них в комбинацию так же, как любую другую модель. Приложение Codex передаёт имя комбинации в качестве
`model` обычной конечной точке Responses, `/v1/responses`; отдельной конечной точки Codex
или переключателя режима нет.

Учётным записям Free/Go доступны маршруты Luna. Учётным записям с поддержкой Sol доступны маршруты от Instant до
High, а учётным записям с поддержкой Pro дополнительно доступны Extra High и Pro. Каждый маршрут имеет
фиксированную серверную модель и уровень рассуждений; конфликтующее явно заданное значение Responses
приводит к отказу вместо неявного изменения выбранного браузерного режима.

Не переименовывайте и не используйте повторно старый коннектор `Codex Native` или `OmniRoute Codex`. ChatGPT
кэширует публичный контракт MCP по идентификатору коннектора, тогда как обновлённый мост использует
новый прямой контракт токена хода. Среда выполнения отклоняет эти устаревшие идентификаторы и требует
новый коннектор `OmniRoute Codex v2`.

## Модель безопасности

- Нативный путь требует запроса Responses, распознанного клиента Codex и совпадающих
  идентификаторов потока и хода.
- Рабочая область, песочница, политика подтверждения и каталог инструментов предоставляются нативной оболочкой Codex;
  текст запроса в свободной форме не является для них источником полномочий.
- ChatGPT получает только краткосрочное разрешение для каждого хода. Брокер MCP принимает только
  те инструменты, которые Codex предложил именно в этом ходе.
- Автоматическое подтверждение **Разрешить один раз** лишь возвращает запрос инструмента в Codex. Только Codex
  принимает решение о подтверждении и выполнении.
- До появления первого вывода комбинация может переключиться на другую совместимую цель. После
  начала вывода поставщик, модель, подключение и ход браузера остаются закреплёнными до
  завершения хода.
- Файлы cookie, ключи среды выполнения, состояние хранилища и токены разрешений не появляются в ответах
  поставщика или журналах запросов.

## VPS без дисплея и Docker

При установке через npm, systemd и PM2 OmniRoute обнаруживает распространённые пути к Chrome и Chromium.
В качестве альтернативы задайте `CHATGPT_WEB_CODEX_CHROME_PATH`. В ходе выполнения намеренно используется Chrome
с графическим интерфейсом, поскольку ChatGPT отклоняет конфигурацию настоящего безголового браузера. Поэтому хост без дисплея должен
запускать OmniRoute с приватным дисплеем Xvfb; одного лишь указания пути к Chrome недостаточно.

Профиль Docker `web` запускает `chatgpt-web-codex-browser` во внутренней сети Compose.
Вспомогательный контейнер запускает Chrome с графическим интерфейсом внутри Xvfb, поэтому физический дисплей не требуется. Его порт CDP
не публикуется на хосте. Защищённый том профиля браузера отделён от тома данных
OmniRoute, а браузеру предоставляется достаточно общей памяти. Внутренний прокси-сервер CDP
прослушивает только порт `9223` внутри сети Compose; Chrome остаётся привязанным к loopback-интерфейсу во
вспомогательном контейнере.

Аренда супервизора в `DATA_DIR` предотвращает одновременное владение одним и тем же состоянием туннеля и брокера
несколькими процессами OmniRoute. Утилита диагностики сообщает о конфликте.

## Интерактивное восстановление

Автоматизированный путь Docker не имеет окна, видимого на хосте, однако сам Chrome работает с графическим интерфейсом внутри
приватного дисплея Xvfb. Когда ChatGPT требует интерактивного входа или прохождения проверки, для восстановления
можно использовать существующую браузерную инфраструктуру VNC. Интерфейс браузера и CDP должны оставаться доступными только
через loopback-интерфейс, аутентифицированное управляющее подключение или туннель SSH; noVNC остаётся отключённым
при обычной работе.

## Резервный переход на WebSocket

Если комбинация содержит ChatGPT Web (Codex), мост Responses WebSocket запрашивает
резервный переход на HTTP/SSE до подключения к вышестоящему сервису. Затем передача выполняется через
`/v1/responses`.
