> Два новых id `auto/*` — `auto/subscription` и `auto/thrifty`. Оба активируются только при явном
> запросе: трафик через них направляется лишь в том случае, если вызывающая сторона запрашивает id по имени;
> существующие пулы, стратегии и значения по умолчанию не изменяются.

## Зачем это нужно

OmniRoute уже отвечает на два вопроса о стоимости, но ни один из них — не тот, который задаёт большинство операторов.

| Существующий механизм                                    | На какой вопрос отвечает                              |
| -------------------------------------------------------- | ----------------------------------------------------- |
| `hidePaidModels` (`autoCombo/paidModelFilter.ts`)        | «эта модель указана в каталоге как бесплатная?»       |
| `freeAccessPolicy: "strict"` (`strictZeroCostFilter.ts`) | «может ли это подключение когда-либо выставить счёт?» |
| `quotaPreflight` (`combo/quotaExhaustionCutoff.ts`)      | «это подключение приближается к своему лимиту?»       |
| `budgetCap` / `budgetFallback` (`autoCombo/engine.ts`)   | «ограничить расходы, перейти на самое дешёвое»        |

Каждый механизм, допускающий только бесплатные варианты, **отказывает с запретом**: исчерпанный бесплатный пул становится пустым пулом, а не поводом перейти на платный вариант. При этом каждый механизм для платных вариантов не учитывает уровни. Ни один из них не отвечает на вопрос:

> «Используй квоту, за которую я уже плачу. Когда она закончится, либо остановись, либо переходи
> по одной ступени вверх к самым дешёвым платным вариантам — и вернись сразу же после её сброса».

## Оплата — свойство подключения, а не модели

`classifyTier()` (`open-sse/services/tierResolver.ts`) использует `(provider, model)` в качестве ключа и возвращает
`free | cheap | premium` на основе цен из каталога. Но наличие дополнительной платы за запрос
зависит от того, **какое подключение его обслуживает**: одна и та же модель включена в тариф при использовании
OAuth-подключения Claude Code и оплачивается за каждый токен при использовании подключения с API-ключом.

`provider_connections.auth_type` нельзя надёжно использовать как признак ни в одном из направлений: существуют
тарифицируемые OAuth-подключения и включённые в тариф подключения с API-ключами (токен рабочего места Copilot —
это не тарифицируемый API-ключ). Поэтому класс оплаты берётся из **поддерживаемого вручную каталога**
`open-sse/config/connectionBillingCatalog.ts` и задаётся вручную на основе опубликованных условий каждого провайдера —
по тому же принципу, который уже реализован для бесплатных моделей в `FreeModelBudget.hardStopGuaranteed`.

```ts
type ConnectionBillingClass = "subscription" | "metered" | "keyless" | "unknown";
type ConnectionOverageBehavior = "hard-stop" | "meters-to-paid" | "unknown";
```

Порядок определения (`autoCombo/connectionBilling.ts`): синтетический маркер отсутствия аутентификации →
`keyless`; запись каталога, совпадающая по провайдеру **и** `authType`; запись для всего провайдера;
иначе `unknown`. **Отсутствие в каталоге не означает бесплатность** — `unknown` повсеместно обрабатывается как `metered`,
поэтому добавленный завтра провайдер изначально находится вне уровня подписки и должен быть
добавлен в каталог намеренно.

## Модель ступеней

Пять ступеней в порядке повышения. Они различаются не только ценой: у каждой есть **собственный**
сигнал исчерпания, поэтому это не просто сортировка.

| #   | Ступень        | Условие включения                                          | Условие исчерпания                  |
| --- | -------------- | ---------------------------------------------------------- | ----------------------------------- |
| 0   | `subscription` | задано в каталоге как `billing: "subscription"`            | окно квоты достигло порога или ниже |
| 1   | `keyless`      | синтетический путь без аутентификации                      | задержка подключения / размыкатель  |
| 2   | `free`         | тарифицируемое подключение, `classifyTier() === "free"`    | бесплатный лимит исчерпан           |
| 3   | `cheap`        | тарифицируемое подключение, `classifyTier() === "cheap"`   | бюджет ступени израсходован         |
| 4   | `premium`      | тарифицируемое подключение, `classifyTier() === "premium"` | бюджет ступени израсходован         |

Ступени 0–2 исчерпываются по **квоте**, которую можно наблюдать и которая уже отслеживается. У ступеней 3–4
квоты нет: платное подключение может обслуживать запросы бесконечно, поэтому единственный разумный сигнал
их исчерпания — **бюджет** для каждой ступени. Без него у правила «повысить ступень, когда дешёвый вариант исчерпан»
нет условия срабатывания.

## `auto/subscription` — закрытое поведение при сбое

Пул = только ступень 0, ограниченная подключениями, для которых превышение квоты задокументировано как `hard-stop` и для каждого из которых в реальном времени подтверждён запас квоты. Всё неоднозначное исключается: некурируемый провайдер, непроверяемое показание квоты, устаревшее показание или превышение квоты, приводящее к платному учёту.

Пустой пул — **ожидаемый** результат, а не дефект: существующий у вызывающей стороны путь обработки пустого пула преобразует его в понятную ошибку вместо незаметного перехода на тарифицируемый резервный вариант. В этом и состоит вся гарантия данного id.

`keyless` намеренно **не** соответствует требованиям: эта группа означает «тарифный план, за который я плачу», поэтому бэкенд без аутентификации к ней не относится. Для этого используйте `auto/thrifty` (или `auto/best-free`).

### Безопасность подключений

Кандидат не всегда привязан к одному подключению — логический кандидат содержит список разрешённых подключений `allowedConnectionIds`, а фактически используемая учётная запись выбирается позже, при отправке, в `open-sse/services/combo/autoStrategy.ts`. Поэтому обе группы проверяют **каждое подключение по отдельности** и сокращают `allowedConnectionIds` ровно до подмножества, прошедшего проверку, — это никогда не полный исходный список и не один произвольно выбранный элемент. Поскольку `autoStrategy.ts` уже применяет этот массив как жёсткий список разрешений, его перезапись на этом этапе конструктивно гарантирует, что множества «проверенных» и «фактически используемых» подключений совпадают. Это тот же инвариант и та же логика, что и в [STRICT_ZERO_COST](./STRICT_ZERO_COST.md).

## `auto/thrifty` — повышение на одну ступень за раз

Пул = все ступени, упорядоченные по индексу ступени, из которого исключены кандидаты с исчерпанной квотой. Движок `auto` по-прежнему выполняет оценку **внутри** оставшегося пула: лестница определяет, какие ступени участвуют, а оценка — какой кандидат побеждает среди них. Порядок внутри ступени стабилен, поэтому эта надстройка никогда не переупорядочивает собственный рейтинг механизма оценки.

Это надстройка для упорядочивания и отсеивания, **а не** новый диспетчер: спекулятивный цикл `combo.ts` уже перебирает цели по порядку и при сбое переходит к следующей, поэтому исчерпание квоты во время выполнения, не обнаруженное предварительной проверкой, всё равно приводит к переходу на следующую ступень в рамках того же запроса.

В то время как `auto/subscription` использует **закрытое** поведение при сбое, `auto/thrifty` использует **открытое**: подключение, включённое в тарифный план, для которого невозможно получить пригодное показание квоты, всё равно пробуется первым. Такая попытка ничего не стоит, а если выяснится, что квота исчерпана, механизм перехода при сбое всё равно дойдёт до следующей ступени. Если же отказаться от попытки, запрос будет отправлен на платную ступень из-за отсутствия телеметрии — именно такого результата эта группа и призвана избегать.

## Возврат к тарифному плану после сброса

Прежде чем маршрутизация вернётся на ступень 0, должны независимо истечь три состояния. Исправление только одного из них оставит лестницу на платных ступенях ещё долго после пополнения квоты тарифного плана.

1. **Кэш состояния квоты** — `freeAccessQuota.ts` кэширует данные для каждой пары `(provider, connection)` с TTL 180 секунд. Кэшированная запись, у которой уже прошло собственное значение `resetAt`, описывает окно, которого больше не существует, поэтому теперь она считается устаревшей **независимо от возраста** и принудительно обновляется. Без этого тарифный план, квота которого пополнилась в полночь, продолжает отображаться как исчерпанный, пока случайно не истечёт TTL.
2. **Собственное состояние лестницы** — его намеренно нет. Допуск ступеней пересчитывается на основе актуального состояния квоты при каждом построении пула; не существует сохраняемой записи «сейчас используется ступень 3», которая могла бы пережить сброс и заблокировать маршрутизацию.
3. **Период ожидания подключения** — ответ 429 при исчерпании квоты задаёт `rateLimitedUntil` на основе экспоненциальной задержки, которая для подключения тарифного плана может выйти за пределы фактического момента сброса. `clampCooldownToReset()` (`subscriptionLadder.ts`) сокращает период ожидания до заданного вышестоящим сервисом момента сброса и никогда не может его увеличить. **Эта функция реализована и протестирована, но ещё не подключена**: кэш квоты инвалидируется в `src/sse/services/auth.ts` _до_ записи периода ожидания, поэтому `resetAt` необходимо получить раньше в этой функции — это изменение критического пути обеспечения отказоустойчивости, которое должно быть вынесено в отдельный рецензируемый PR. До тех пор повторный допуск произойдёт только после завершения периода ожидания подключения, который уже отдаёт предпочтение подсказкам `Retry-After` от вышестоящего сервиса, если провайдер их отправляет.

### Защита от колебаний

Только что сброшенная ступень повторно допускается лишь при значении выше `reentryMinRemainingPercent` (по умолчанию 5), тогда как уже используемому подключению достаточно оставаться выше `exitCutoffPercent` (по умолчанию 2, что соответствует `quotaPreflight.defaultThresholdPercent`). Разница между ними образует полосу гистерезиса — без неё подключение, находящееся около порога, переключалось бы между ступенями при последовательных запросах.

## Конфигурация

Только тонкая настройка. Флаг `enabled` намеренно **отсутствует**: переключатель, способный отключить эти режимы,
привёл бы к тому, что `auto/subscription` незаметно предоставлял бы весь пул — включая платные модели — под
названием, обещающим обратное.

```jsonc
{
  "subscriptionLadder": {
    "exitCutoffPercent": 2,
    "reentryMinRemainingPercent": 5,
    "rungBudgetUsd": { "cheap": 5.0, "premium": 0 }, // 0 полностью отключает ступень
  },
}
```

Ограничение по бюджету не действует, пока не подключён механизм определения расходов: при отсутствии учёта платная
ступень включается в порядок, но никогда не блокируется. Начиная с v3.8.51 настройка `rungBudgetUsd` принимается
схемой, но пока НЕ применяется — рассматривайте её как зарезервированную конфигурацию, а не как действующий лимит расходов. Упорядочивание ступеней, исчерпание на основе квоты и повторный вход после сброса
работают без неё.

## Композиция

`subscription` и `thrifty` являются значениями `AutoTier`, поэтому они сочетаются с любой категорией:
`auto/coding:thrifty`, `auto/reasoning:subscription` и так далее. Два плоских идентификатора
(`auto/subscription`, `auto/thrifty`) публикуются в `/v1/models` и на панели управления.

Ни один из идентификаторов не относится к платному уровню, поэтому `isPaidTierAutoId()` возвращает `false` для обоих, а
`auto/subscription` сохраняется при использовании `hidePaidModels`.
