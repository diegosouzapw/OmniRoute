Web Cookie 提供者允许 OmniRoute 通过您现有的浏览器会话使用 AI 服务，而无需 API 密钥。如果您已经可以通过某项服务的网站访问该服务，并希望 OmniRoute 使用同一个已认证会话，它们会非常有用。

与 API 密钥提供者不同，Web Cookie 提供者使用浏览器发送给网站的凭据进行身份验证。

---

# 开始之前

> **重要：** 始终从**实时网络请求**中复制凭据，**不要**从浏览器的 Cookie 存储中复制。

许多身份验证问题都是由于从错误的位置复制 Cookie 导致的。

## 不要从 Cookie 存储中复制

大多数浏览器通过以下位置公开已存储的 Cookie：

```
开发者工具
→ 应用程序（或存储）
→ Cookie
```

尽管这些 Cookie 看起来正确，但它们可能：

- 已过期
- 不完整
- 缺少仅在已认证请求中发送的 Cookie

使用这些值可能会导致身份验证失败，即使它们看起来有效。

## 从实时请求中复制

请改为使用成功请求中的 Cookie：

```
开发者工具
→ 网络
→ 刷新页面
→ 打开聊天或对话请求
→ 请求标头
→ Cookie
```

`Cookie` 请求标头包含浏览器成功使用的确切身份验证信息。

对于大多数 Web Cookie 提供者，应将此值粘贴到 OmniRoute 中。

---

# 常规设置

大多数 Web Cookie 提供者的设置流程都相同。

1. 登录提供者的网站。
2. 打开浏览器的开发者工具。
3. 打开**网络**选项卡。
4. 刷新页面。
5. 打开一个已认证的聊天或对话请求。
6. 复制所需的身份验证凭据。
7. 打开 OmniRoute。
8. 前往**提供者 → 添加提供者**。
9. 选择您的 Web Cookie 提供者。
10. 粘贴凭据。
11. 点击**测试连接**。
12. 保存提供者。

具体需要哪些凭据取决于提供者。

# Web Cookie 提供者可以做什么和不能做什么

Web Cookie 提供者复用网站的聊天界面。它们**不**具备与官方 API 相同的功能。

## 支持

- 使用现有浏览器会话进行身份验证
- 访问您的账户可用的模型
- 以流式方式返回聊天响应
- 无需 API 密钥

## 不支持

- 函数调用
- 工具调用
- 自动编辑文件
- 智能体式 IDE 工作流
- 仅限 API 的功能

这是预期行为，**不是**错误。

如果您需要执行工具、自动编辑文件或使用其他智能体工作流，请使用 **API 密钥提供者**，而不是 Web Cookie 提供者。

---

# 验证注意事项

**测试连接**或 Cookie 验证成功仅表示所提供的凭据看起来符合预期格式。

在 Issue #7857 解决之前，验证成功**并不能保证**提供者能够成功完成身份验证。

如果身份验证仍然失败，请确认您是从实时网络请求中复制凭据，而不是从浏览器 Cookie 存储中复制。

---

# 故障排除

## 身份验证失败

确认凭据是从以下位置复制的：

```
网络
→ 请求标头
→ Cookie
```

而**不是**从以下位置复制的：

```
应用程序
→ Cookie
```

---

## Cookie 在浏览器中有效，但在 OmniRoute 中无效

某些提供者包含仅在已认证请求期间发送的 Cookie。

成功打开对话后，请从新的网络请求中重新复制凭据。

---

## 会话已过期

Web Cookie 提供者使用您现有的浏览器会话。

如果浏览器会话过期或您已退出登录，则必须复制一组新的凭据。

---

## 测试连接通过，但请求失败

在 Issue #7857 解决之前，通过验证并不能保证身份验证请求一定成功。

在进一步排查问题之前，请从新的已认证请求中重新复制凭据。

# 最佳实践

- 从新的已认证请求中复制凭据。
- 避免重复使用旧 Cookie。
- 使用 Web Cookie 提供者时，请保持浏览器会话处于活动状态。
- 将复制的 Cookie 视为敏感凭据。
- 需要函数调用或智能体工作流时，请使用 API 密钥提供者。
