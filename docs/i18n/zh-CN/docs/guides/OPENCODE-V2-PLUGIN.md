`@omniroute/opencode-plugin-v2` 会将你的整个 OmniRoute 目录（模型、组合和自动组合）添加到 OpenCode v2 的模型选择器中，并提供显示名称、定价和免费额度预算。

它是一个独立于 `@omniroute/opencode-plugin` 的包，因为 OpenCode v1 和 v2 使用不同的契约加载插件。请选择与你的 OpenCode 主版本匹配的插件；二者之间不共享任何内容，因此升级其中一个绝不会强制升级另一个。

## 要求

- OpenCode v2。
- 可访问的 OmniRoute 网关（默认为 `http://localhost:20128`）。
- Node.js 22 或 24。

## 安装

将插件添加到 `opencode.json`：

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

随后，模型将显示为 `omniroute/<provider>/<model>`；`providerId` 决定该前缀，以及 OpenCode 用于存储凭据的集成 ID。

## 凭据

插件会按以下顺序在三个位置查找网关密钥：

1. **你在 OpenCode 中连接的凭据。** 插件会注册一个集成，因此 OpenCode 自身的身份验证流程可以存储该密钥。不会有任何内容写入 `opencode.json`——请优先使用此方式。
2. 插件选项中的 `apiKey`，用于按项目覆盖。它会将密钥放入你可能会提交的文件中。
3. 环境中的 `OMNIROUTE_API_KEY`。

如果这三项都没有，目录将为空，并且插件会在启动时提示一次，而不是只留下一个没有任何提示的空白选择器。

### 管理令牌是另一种密钥

组合、提供者运行状况和补充信息（显示名称、定价、免费额度预算）来自网关的 `/api/*` 端点。大多数部署使用**管理**令牌而不是推理密钥来保护这些端点：

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<管理读取令牌>"
}
```

如果未设置，`managementReadToken` 会回退到 `apiKey`。当网关拒绝该回退值时，目录仍会发布，但只包含原始模型 ID，不包含显示名称、规范别名去重、定价和组合。发生这种情况时，插件会针对每个端点警告一次，并指出端点和缺失的内容——因此，选择器功能降级的原因绝不会令人费解。

## 选项

| 键                               | 默认值                                   | 说明                                                                              |
| -------------------------------- | ---------------------------------------- | --------------------------------------------------------------------------------- |
| `providerId`                     | `"omniroute"`                            | 提供者 ID、集成 ID，以及模型显示时使用的前缀                                      |
| `baseURL`                        | 必填                                     | 网关根地址，仅支持 `http(s)`；在需要时会添加 `/v1` 后缀                           |
| `apiKey`                         | 已连接的凭据，然后是 `OMNIROUTE_API_KEY` | 用于 `/v1/*` 的聊天密钥                                                           |
| `managementReadToken`            | 回退到 `apiKey`                          | 用于 `/api/*` 的密钥——通常与聊天密钥**不同**                                      |
| `displayName`                    | `"OmniRoute"`                            | 选择器中的提供者名称                                                              |
| `timeoutMs`                      | `10000`                                  | 每个端点的获取超时时间（自动组合使用 5 秒）                                       |
| `modelCacheTtlMs`                | `300000`                                 | 目录缓存 TTL；磁盘快照可加速冷启动                                                |
| `timeouts`                       | 回退到 `timeoutMs`                       | 各端点的时间预算（毫秒）：`models`、`combos`、`autoCombos`、`enrichment`          |
| `enrichment`                     | `true`                                   | 获取名称、定价和免费额度预算                                                      |
| `providerTag`                    | `true`                                   | 在显示名称前添加其路由到的上游提供者                                              |
| `usableOnly`                     | `false`                                  | 仅保留网关报告为已配置的提供者                                                    |
| `visibleModels` / `hiddenModels` | `[]`                                     | 精确匹配或后缀匹配的允许列表；拒绝规则优先                                        |
| `geminiSanitization`             | `true`                                   | 从工具架构中移除 Gemini 拒绝的 JSON-Schema 关键字（包含 `$ref` 的工具将原样转发） |
| `apiFormat.allowAnthropic`       | `false`                                  | 通过 Anthropic API 块路由允许列表中的 ID                                          |
| `apiFormat.anthropicModels`      | `[]`                                     | 路由到 Anthropic 的完整模型 ID                                                    |
| `logLevel` / `startupDebug`      | `warn` / `false`                         | 日志记录器的详细程度                                                              |

## 目录如何保持最新

目录会按需获取，并缓存 `modelCacheTtlMs` 指定的时长；同时，磁盘快照会在网关无法访问时保留最后已知的目录，因此服务中断只会影响目录的新鲜度。模型和组合一到达就会发布；自动组合、提供者列表和扩充覆盖层会在到达后合并，因此单个缓慢的端点不会拖住整个选择器。

名称包含网关已知的信息：模型路由到的上游提供者、`[Free]` 标记及其附带的预算——因此，销售同一模型的两个连接仍可区分。可通过 `"providerTag": false` 关闭前缀。

没有手动刷新命令：OpenCode v2 命令是提示词模板，而不是回调，因此插件无法公开此类命令。刷新遵循 TTL；仅当目录或覆盖层实际发生变化时，才会请求宿主重新加载，而不会每次刷新都请求。

## Gemini 上的工具调用

如果工具声明包含 `$schema` 或 `additionalProperties`，Gemini 会拒绝整个请求，并返回 `400 INVALID_ARGUMENT`。该插件会从发往此提供者 Gemini 模型的工具 schema 中移除这些关键字，而其他所有请求均保持不变。包含 `$ref` 的工具会原样转发，而不会进行清理，因为移除该引用会将 schema 放宽为“接受任何内容”。

设置 `"geminiSanitization": false` 可将其关闭。

## 故障排除

| 症状                              | 原因                                                                                  |
| --------------------------------- | ------------------------------------------------------------------------------------- |
| 选择器中未显示 OmniRoute 模型     | 未解析到密钥（请检查启动警告），或者网关无法访问                                      |
| 仅显示原始模型 ID，没有组合或定价 | 管理端点拒绝了令牌——请设置 `managementReadToken`                                      |
| 会话固定到 `opencode-<id>/…`      | v1 插件发布的是 `opencode-<id>`；v2 直接发布 `<id>`，因此请在 `<id>/…` 下重新选择模型 |
