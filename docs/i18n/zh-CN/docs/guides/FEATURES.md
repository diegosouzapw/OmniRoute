## 🔌 提供者

管理 AI 提供者连接：OAuth 提供者（Claude Code、Codex）、API 密钥提供者（Groq、DeepSeek、OpenRouter）以及免费提供者（Qoder、Kiro）。Kiro 账户支持额度余额跟踪——可在仪表板 → 使用情况中查看剩余额度、总额度和续期日期。

OpenRouter 连接可以在高级设置中存储每个连接专属的 `preset`。设置后，OmniRoute 会将其作为 OpenRouter 的顶层请求字段发送，例如 `"preset": "email-copywriter"`，除非客户端请求已提供自己的 `preset`。

## 🎨 组合

使用 19 种公开策略创建模型路由组合：优先级、加权、轮询、上下文中继、优先填充、p2c（两项随机选择）、随机、最少使用、成本优化、重置感知、重置窗口、余量、严格随机、自动、lkgp（最后已知可用提供者）、上下文优化、缓存优化、**融合**（并行分发至一组模型，然后由评审模型综合生成一个答案）和**流水线**。每个组合可串联多个模型，支持自动回退，并包含快速模板和就绪状态检查。

近期的组合改进：

- **结构化组合构建器**——通过选择提供者、模型及确切的账户/连接来创建每个步骤
- **重复提供者支持**——只要 `(provider, model, connection)` 元组唯一，即可在一个组合中多次复用同一提供者
- **组合目标健康状态**——分析和健康状态界面现在会区分各个组合目标/步骤，而不会将所有内容合并为模型字符串
- **复合层级排序**——`defaultTier -> fallbackTier` 现在会影响顶层组合步骤的运行时执行/回退顺序
- **系统提示词模板**——组合的 `system_message` 支持服务端
  `{{MODEL_ID}}`、`{{PROVIDER_ID}}`、`{{ACCOUNT}}` 和 `{{FINGERPRINT}}`
  占位符；这些占位符会在分发前，根据实际路由到的目标进行展开。
  占位符仅限允许列表且不会递归展开；未知占位符保持原样；空值
  会展开为空字符串；客户端系统提示词绝不会被重写。`{{FINGERPRINT}}`
  仅对具有固定或自动轮换指纹、基于指纹的免费提供者进行解析——在其他情况下会展开为空
  （例如，单指纹连接、非指纹提供者）。展开适用于
  标准分发循环、轮询和固定的上下文缓存会话；
  融合、混沌、流水线和嵌套执行策略目前尚不支持展开
  占位符。

## 🎨 主题 _(v2.0.5+)_

## ⚙️ 设置

包含 **7 个选项卡**的综合设置面板：

- **常规** — 系统存储、备份管理（导出/导入数据库）
- **外观** — 主题选择器（深色/浅色/跟随系统）、颜色主题预设和自定义颜色、健康日志可见性、侧边栏项目和分组分隔符可见性控制、端点隧道可见性控制
- **AI** — AI 助手功能、默认路由预设（Auto Combo `auto/coding`、`auto/fast`、`auto/cheap`、`auto/smart`）、推理重放缓存，以及技能/记忆开关
- **安全** — API 端点保护、自定义提供者阻止、IP 过滤、会话信息
- **路由** — 模型别名、后台任务降级、可感知清单的分层路由（W1–W4）、`fallbackDelayMs`、按会话粘性路由
- **弹性** — 速率限制持久化、断路器调优、自动禁用被封禁的账户、提供者过期监控、**上下文中继**移交阈值和摘要模型配置、按提供者配置的 429 分类与 `useUpstream429BreakerHints` 开关、模型冷却
- **高级** — 配置覆盖、配置审计跟踪、回退降级模式、Responses API 的后台模式降级

## 🔗 上下文接力 _(v3.5.5+)_

一种组合策略，可在对话中途发生账户轮换时保持会话连续性。在当前活动账户的额度耗尽之前，OmniRoute 会在后台生成结构化的交接摘要。当后续请求被路由到其他账户后，该摘要会作为系统消息注入，使新账户能够在完整上下文的基础上继续对话。

可通过组合级或全局设置进行配置：

- **交接阈值** — 触发摘要生成的额度使用百分比（默认 85%）
- **摘要最大消息数** — 要压缩的近期历史消息数量
- **摘要模型** — 用于生成交接摘要的可选覆盖模型

目前支持 Codex 账户轮换。请参阅[上下文接力文档](../architecture/ARCHITECTURE.md)。

## 🛡️ 代理强化 _(v3.5.5+)_

在整个请求管线中全面强制执行代理配置：

- **令牌健康检查** — 后台 OAuth 刷新现在会按连接解析代理配置，防止在必须使用代理的环境中发生失败

## 🌐 V1 WebSocket 桥接器 _(v3.6.6+)_

OmniRoute 现在通过 `/v1/ws` 升级端点支持**兼容 OpenAI 的 WebSocket 客户端**。自定义 `scripts/dev/v1-ws-bridge.mjs` 服务器会封装 Next.js，并将 WS 连接升级为完整的双向流式会话。身份验证使用与 HTTP 请求相同的 API 密钥或会话 Cookie。

主要行为：

- 在建立连接之前，由 `src/lib/ws/handshake.ts` 验证 WS 升级
- 会话关闭或上游发生错误时彻底终止流
- 可与现有 HTTP+SSE 流式传输路径同时运行

## 🔑 同步令牌与配置包 _(v3.6.6+)_

现在可通过**限定作用域的同步令牌**实现多设备和外部操作员访问：

- **`POST /api/sync/tokens`** — 签发新的同步令牌（限定作用域，可选过期时间）
- **`DELETE /api/sync/tokens/:id`** — 撤销令牌
- **`GET /api/sync/bundle`** — 下载包含所有非敏感设置的、带版本且以 ETag 为键的 JSON 快照（密码已脱敏）

配置包由 `src/lib/sync/bundle.ts` 构建。使用方通过比较 `ETag` 响应头来检测变更，无需重新下载完整载荷。

## 🛡️ 安全出站请求与 SSRF 防护 _(v3.6.6+)_

所有提供者验证和模型发现调用现在都会经过双层出站防护：

1. **URL 防护**（`src/shared/network/outboundUrlGuard.ts`）— 在套接字打开前阻止访问私有、环回和链路本地 IP 范围。
2. **安全请求封装器**（`src/shared/network/safeOutboundFetch.ts`）— 应用 URL 防护、规范化超时设置，并通过指数退避机制重试暂时性错误。

违反防护规则时会返回 HTTP 422（`URL_GUARD_BLOCKED`），并通过 `providerAudit.ts` 写入合规审计日志。

## 🔄 感知冷却状态的重试 _(v3.6.6+)_

当上游提供者返回模型级冷却状态时，聊天请求现在会**自动重试**。可通过 `REQUEST_RETRY`（默认值：2）和 `MAX_RETRY_INTERVAL_SEC`（默认值：30 s）进行配置。现已改进对 `x-ratelimit-reset-requests`、`x-ratelimit-reset-tokens` 和 `Retry-After` 等速率限制响应头的解析与学习——可在“弹性”仪表板中查看各模型的冷却状态。
