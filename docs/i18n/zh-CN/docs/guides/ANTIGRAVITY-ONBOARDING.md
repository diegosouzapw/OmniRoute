## 1. Antigravity 与 Antigravity CLI (agy) 对比

这两个提供者共享**同一个 Google 后端**——使用相同的 OAuth 客户端、令牌刷新机制、端点和 Google 账号。区别在于您可以看到哪些模型。

> 有关 Google 的官方对比，请参阅 [Antigravity CLI 发布公告](https://antigravity.google/blog/introducing-google-antigravity-cli)。

| 方面                | `antigravity` (IDE)                   | `agy` (CLI)                                     |
| ------------------- | ------------------------------------- | ----------------------------------------------- |
| **Google 产品**     | Antigravity 2.0 / Antigravity IDE     | Antigravity CLI                                 |
| **后端**            | 相同的 Google Cloud Code API          | 相同的 Google Cloud Code API                    |
| **OAuth / 令牌**    | 相同的客户端、相同的刷新机制          | 相同的客户端、相同的刷新机制                    |
| **模型目录**        | 静态精选列表（硬编码于 OmniRoute）    | 通过 `:fetchAvailableModels` 从 Google 实时探测 |
| **Claude 模型**     | Sonnet 4.6、Opus 4.6（各有 4 个变体） | Sonnet 4.6、Opus 4.6（各有 4 个变体）           |
| **Gemini 命名方式** | 简洁标签（Low/Medium/High）           | 上游 ID（extra-low/low/agent）                  |
| **额外模型**        | `gpt-oss-120b-medium`                 | 可能包含 Google 提供的其他模型                  |
| **默认用例**        | IDE 集成（VS Code、JetBrains）        | CLI / API 访问                                  |
| **配额**            | 与 agy 共享（同一 Google 账号）       | 与 antigravity 共享（同一 Google 账号）         |

**可用模型（经实验验证，2026-07-29）**：

- Gemini：3.6 Flash、3.5 Flash、3.1 Pro、3 Flash、2.5 Flash（具有不同的思考级别）
- Claude：Sonnet 4.6、Opus 4.6（各有 default/low/medium/high 变体）
- 其他：GPT-OSS 120B Medium
- **Claude Sonnet 5 不可用**——仅支持 4.6 变体

**模型目录存在差异的原因**：根据 Google 官方博客，Google 的 CLI“针对速度和低开销进行了优化”，并“与 Gemini 模型进行了协同优化”。Web/IDE 产品则“针对全面性进行了优化”。CLI 使用 `:fetchAvailableModels` 动态发现模型，而 IDE 使用静态精选列表。

**实际使用建议**：对 Gemini 模型使用 `agy/` 前缀（例如 `agy/gemini-3.7-flash-high`）。使用 `antigravity/` 访问静态精选列表。两者使用相同的 Google 后端，但公开的模型命名方式不同。配额是共享的——使用任一提供者都会计入同一 Google 账号的限额。

## 2. Google One AI Pro：配额系统

> 有关官方配额详情，请参阅 [Antigravity 文档：方案](https://antigravity.google/docs/plans)；有关最新定价更新，请参阅 [Antigravity 方案变更](https://antigravity.google/blog/changes-to-antigravity-plans)。

Google Antigravity 使用基于“已完成工作量”（计算权重）而非消息数量的**双层配额**。

### 两个层级

| 层级               | 说明                       | 刷新周期                                             |
| ------------------ | -------------------------- | ---------------------------------------------------- |
| **5 小时冲刺配额** | 可立即使用的“工作量”配额池 | 在会话中首次请求后的 5 小时重置                      |
| **7 天基准配额**   | 每周硬性上限               | 达到上限时覆盖 5 小时刷新机制；锁定至下一个 7 天周期 |

**“已完成工作量”的计算方式**：大量使用智能体的任务（例如“重构整个代码库”）比简单任务（例如“修复这个函数”）消耗配额的速度快得多。目前没有显示配额消耗情况的实时仪表板。

### 方案等级

| 方案         | 价格       | 配额                      | 每周限制                        |
| ------------ | ---------- | ------------------------- | ------------------------------- |
| Free         | $0         | 可观的配额，每周刷新      | 有                              |
| AI Pro       | $19.99/月  | 高配额，每 5 小时滚动刷新 | 有（达到上限时覆盖 5 小时刷新） |
| AI Ultra 5x  | $99.99/月  | Pro 配额的 5 倍           | 无每周限制                      |
| AI Ultra 20x | $199.99/月 | Pro 配额的 20 倍          | 无每周限制                      |

### Gemini 与非 Gemini 模型

- **Gemini 模型**（Flash + Pro）：共享同一个速率限制，并根据 API 定价扣减。如果 Flash 比 Pro 便宜 8 倍，则可使用的 Flash 令牌数量是 Pro 的 8 倍。
- **非 Gemini 模型**（Claude、GPT-OSS）：拥有**独立的**速率限制。即使 Gemini 被锁定，这些模型仍可能可用。

### AI 点数（超额用量）

> 有关点数的工作方式，请参阅 [Google One AI 点数](https://support.google.com/googleone/answer/14534406)。

基准配额耗尽时：

- **Never**：等待配额刷新；显示“已达到基准模型配额”
- **Always**：自动使用 AI 点数；基准配额刷新后切换回基准配额

点数需单独购买，并按照标准 API 定价扣除。

### 关键详情

- 配额在**账户级别共享**——Antigravity IDE、CLI 和 OmniRoute 中使用的同一个 Google 账户共享同一个配额池
- 每个 Google 账户都有各自独立的配额——多个账户 = 多个配额池
- AI Pro 用户报告称，达到每周基准上限时会被**锁定 7 天**，而不是在 5 小时后重置（Google 已确认，对于高需求情况，这是预期设计）

**账户配额耗尽时**：OmniRoute 会自动使用组合路由中的下一个可用账户重试，无需手动干预。

## 3. 如何获取 projectId

每个 antigravity/agy 连接都需要一个 Google Cloud Code `projectId`。如果没有该值，`/v1internal:models` 端点会返回 404。

### 方法 A：自动获取（推荐）

OmniRoute 会自动处理此过程。通过仪表板 OAuth 添加新的 Google 账户时：

1. OmniRoute 刷新令牌
2. 调用 `loadCodeAssist` 以发现 projectId
3. 如果不存在项目，则调用 `onboardUser` 创建项目
4. 再次调用 `loadCodeAssist` 以获取新创建的 projectId
5. 将其保存到数据库

**此方法适用于大多数账户**——无需手动操作。

### 方法 B：通过 agy CLI 手动获取

如果自动发现失败（发生这种情况的原因请参阅第 5 节）：

```bash
# 安装 agy CLI（如果尚未安装）
npm install -g @anthropic-ai/agy

# 使用您的 Google 账户登录
agy login

# 选择需要完成初始设置的账户
# 这会触发 Cloud Code 注册并分配 projectId
```

`agy login` 成功后，在 OmniRoute 仪表板中刷新令牌。系统将自动发现 projectId。

### 如何验证

检查数据库：

```bash
# 在 OmniRoute 容器内
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

或者检查日志：

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. OAuth 重定向 URI

### 问题

Google OAuth 要求使用有效的重定向 URI。OmniRoute 默认使用 `http://127.0.0.1:20128/callback`（环回地址）。这适用于本地构建，但在**远程部署**中会失败（例如，通过局域网 IP 访问的服务器）。

Google 会拒绝以下重定向 URI：

- 使用 IP 地址（必须是以 `.com`、`.org` 等结尾的域名）
- 与 OAuth 客户端配置中注册的重定向 URI 不匹配

### 解决方案

**选项 A：使用内置 OAuth 流程（默认）**

- 当您通过 `localhost` 或 `127.0.0.1` 访问 OmniRoute 时有效
- 无需配置

**选项 B：自定义 OAuth 凭据**

- 在您的环境中设置 `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web`
- 提供您自己的 Google OAuth 凭据：
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- 在 Google Cloud Console 中将 `https://your-domain.com/callback` 注册为已获授权的重定向 URI

**选项 C：使用 agy CLI 进行初始登录**

- 在将访问 OmniRoute 的计算机上运行 `agy login`
- OAuth 流程将在本地完成，并存储令牌
- 通过仪表板将连接导入 OmniRoute

### 限制

- 自定义 OAuth 凭据需要域名（Google 不接受将 IP 地址用作重定向 URI）
- 如果您没有域名，请改用选项 A 或 C

## 5. 故障排除：自动设置失败时

对于大多数账户，OmniRoute 会自动处理 projectId 发现和注册流程。失败时，根本原因通常是以下情况之一：

### 账户区域被阻止

**症状**：`agy login` 返回“资格检查失败：您的当前账户不符合使用 Antigravity 的条件，因为该服务目前在您所在的位置不可用。”

**根本原因**：Google 账户有一个在注册时设置的后端“国家/地区关联”字段。agy CLI 和 Cloud Code API 会严格检查此字段，而 Web 版 Gemini 仅检查您当前的 IP。

> 要查看或更改账户的关联区域，请访问 [Google 国家/地区关联表单](https://policies.google.com/country-association-form)。

**为什么 Web 版 Gemini 可以使用，但 agy 不行**：

- Web 版 Gemini / Google One：仅检查当前 IP（使用代理可通过）
- agy CLI / Cloud Code API：读取后端的国家/地区关联字段（代理无效）

**修复方法**：

1. 使用美国 IP 访问 [Google 国家/地区关联表单](https://policies.google.com/country-association-form)
2. 提交区域变更请求（选择“我居住在其他国家/地区”）
3. 等待 1-24 小时，让 Google 处理请求并发送电子邮件通知
4. 之后，`agy login` 应可成功执行

### 账户没有 Cloud Code 项目

**症状**：日志显示 `loadCodeAssist returned no project id` 和 `onboardUser failed (400)`。

**根本原因**：该账户从未注册过 Google Cloud Code，并且自动注册流程失败。

**修复方法**：手动运行 `agy login` 以触发 Cloud Code 注册，然后在 OmniRoute 仪表板中刷新令牌。

### 令牌已过期或被撤销

**症状**：日志中出现 401 错误或“令牌已过期”消息。

**修复方法**：在“仪表板 → 提供者 → agy”中刷新令牌，然后单击刷新图标。如果刷新令牌本身已被撤销，您需要通过 OAuth 重新进行身份验证。

## 决策流程图

```
账号无法使用？
│
├─ 数据库中是否有 projectId？
│  ├─ 是 → 问题出在其他地方（令牌已过期、速率限制等）
│  └─ 否 ↓
│
├─ 账号的国家/地区关联是否设置为受限区域？
│  ├─ 是 → 在 Google 国家/地区关联表单中更改区域
│  │         (https://policies.google.com/country-association-form)
│  │         等待 1-24 小时，然后重试
│  └─ 否 ↓
│
├─ 账号是否订阅了 Google One AI Pro？
│  ├─ 否 → 请先在 one.google.com 订阅
│  └─ 是 ↓
│
├─ 尝试自动发现（在控制面板中刷新令牌）
│  ├─ 成功 → 完成
│  └─ 仍然失败 ↓
│
└─ 手动操作：在该计算机上运行 `agy login`
   ├─ 成功 → 在控制面板中刷新令牌，系统将发现 projectId
   └─ 失败 → 检查错误消息，可能是区域或订阅问题
```
