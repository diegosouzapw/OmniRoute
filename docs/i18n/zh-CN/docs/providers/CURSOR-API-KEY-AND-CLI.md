无需 IDE 会话，即可通过以下两种方式将 Cursor 接入 OmniRoute：

1. **`cursor-api` 提供者**（卡片名称“Cursor API”，别名 `cua`）：一种 API 密钥
   提供者，用于保存 Cursor 用户 API 密钥（`crsr_…`，在
   `https://cursor.com/dashboard/api` 生成）。任何 OmniRoute 客户端随后都可通过
   `/v1/chat/completions`，使用 `cursor-api/<model>` 或
   `cua/<model>` 访问 Cursor 模型，并照常使用配额、回退和日志记录层。IDE
   提供者（`cursor`，OAuth/IDE 会话）保持不变。
2. **Cursor CLI 透传**：将 Cursor CLI（`agent`）指向 OmniRoute，使 CLI 发出的
   每个 RPC 都使用 OmniRoute API 密钥进行身份验证，再使用 `cursor-api`
   连接的凭据转发至 Cursor，并记录在“日志”页面中。

## 为何需要交换密钥

`api2.cursor.sh` 不接受将原始 `crsr_…` 密钥用作 Bearer 令牌（会返回 401）。Cursor
CLI 首先将该密钥 POST 到 `/auth/exchange_user_api_key`，并收到一个一小时后过期的会话
JWT；返回的 `refreshToken` 具有相同的 `exp`，因此刷新实际上意味着重新交换密钥。
`open-sse/services/cursorApiKeyAuth.ts` 执行该交换，为每个密钥缓存一个会话
令牌，在过期前五分钟重新交换，并在 Cursor 返回 401 时删除缓存的
令牌。`CursorExecutor` 会在为 `cursor-api` 连接打开上游流之前调用它。

## `cursor-api` 提供者

注册表：`open-sse/config/providers/registry/cursor/index.ts`
（`cursor_apiProvider`、`authType: "apikey"`，其 `format`、`baseUrl` 和
`models` 与 `cursor` 相同）。目录卡片：
`src/shared/constants/providers/apikey/specialty-media.ts`。执行器映射：
`open-sse/executors/index.ts`（`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`）。

控制面板：提供者 → Cursor API → 添加 API 密钥。

REST：

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

然后：

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

注意：

- `cursor-api` 的模型列表来自静态 Cursor 注册表（与 IDE 提供者回退时使用的
  列表相同）；无需在 OmniRoute 主机上安装 `cursor-agent`。
- `POST /api/providers/{id}/refresh-cursor` 仅用于 `cursor` IDE 提供者；
  `cursor-api` 连接没有需要续期的 IDE 会话。

## Cursor CLI 透传

路由：`src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`。前缀 `/api/cursor-cli/` 已在
`src/shared/constants/publicApiRoutes.ts` 中注册，因为处理程序会
自行执行身份验证：

| 路径                                                                                                                       | CLI 应提供的身份验证         | OmniRoute 的处理方式                                                                                                                    |
| -------------------------------------------------------------------------------------------------------------------------- | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                         | `Bearer <OmniRoute API key>` | 验证密钥，生成一个有效期为 1 小时的 HS256 JWT（使用 `JWT_SECRET` 签名）并将其返回                                                       |
| 其他所有路径（`/aiserver.v1.*`、`/agent.v1.AgentService/RunSSE`、`/aiserver.v1.BidiService/BidiAppend`、`/v1/traces`，……） | `Bearer <that JWT>`          | 验证签发者、受众和有效期，选择一个活跃的 `cursor-api` 连接，将 Authorization 标头替换为交换得到的 Cursor 令牌，然后将响应以流式方式传回 |

CLI 会从收到的任何令牌中解码 `exp`，因此如果向其提供不透明
令牌，它几乎会在每次请求前重新交换；生成的 JWT 可避免这种
情况。OmniRoute 返回 401 时，CLI 会再次执行交换。

### 设置

1. 创建一个 OmniRoute API 密钥（控制面板 → API 密钥）和一个 `cursor-api`
   连接。
2. 告知 CLI 对 agent 流使用 HTTP/1.1。在
   `~/.cursor/cli-config.json` 中：

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   如果不这样设置，CLI 会通过 HTTP/2 向单独配置的 agent 主机发起 agent
   轮次，只有控制平面 RPC 会经过该端点。

3. 让 CLI 通过 OmniRoute 运行：

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

每一跳都会记录在“日志”中，其中提供者为 `cursor-api`，请求类型为 `cursor-cli`，
路径为 `/api/cursor-cli/<rpc>`，并归因到对应的 OmniRoute API 密钥和处理该请求的
连接。

### 故障模式

| 情况                                           | CLI 的响应                                 |
| ---------------------------------------------- | ------------------------------------------ |
| 未知的 OmniRoute 密钥且 `REQUIRE_API_KEY=true` | 交换时返回 401 `unauthenticated`           |
| `REQUIRE_API_KEY=false`                        | 匿名会话（与 `/v1/*` 的行为一致）          |
| 会话 JWT 已过期 / 来自其他服务 / 被篡改        | 返回 401，CLI 重新交换                     |
| OmniRoute API 密钥在交换后被撤销               | 下一个 RPC 返回 401                        |
| 没有活跃的 `cursor-api` 连接                   | 返回 503 `unavailable`                     |
| Cursor 拒绝该连接的密钥                        | 返回 401 `unauthenticated`，丢弃缓存的会话 |
| 无法访问上游服务                               | 返回 502 `unavailable`（已净化的消息）     |
| 未设置 `JWT_SECRET`                            | 交换时返回 503                             |
