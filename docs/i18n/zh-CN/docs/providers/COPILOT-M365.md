`copilot-m365-web`（别名 `m365copilot`）通过位于
`m365.cloud.microsoft/chat` 的、已通过身份验证的 Microsoft 365 Copilot BizChat 浏览器会话，发送 OpenAI 格式的聊天请求。这是一个非官方集成。

> **首次使用 Web Cookie 提供者？**
>
> 在按照本提供者专用指南操作之前，请阅读 **`docs/getting-started/WEB-COOKIE-GUIDE.md`**，了解常规设置流程、身份验证指南、限制和故障排除方法。
>
> **重要：** 此提供者的凭据**不是 cookie**。请勿从
> `m365.cloud.microsoft` 复制 cookie。该凭据由 WebSocket URL 查询
> 参数和路径段组成，两者均可从 DevTools 的 Network 标签页中读取。

## 前提条件

- 拥有可访问 `m365.cloud.microsoft/chat` 上 BizChat 的 Microsoft 365 账户
- 使用基于 Chromium 的浏览器（Chrome、Edge）通过 DevTools 检查 WebSocket
- 拥有 M365 Copilot 许可证（许多 Microsoft 365 商业版/企业版计划中已包含）

## 获取凭据（WebSocket 方法）

1. 登录 `https://m365.cloud.microsoft/chat` 并开始对话。
2. 打开 **DevTools → Network**。
3. 按 **WS**（WebSocket）筛选。
4. 点击 Chathub WebSocket 连接。查找以
   `wss://substrate.office.com/m365Copilot/Chathub/` 开头的 URL。
5. 从其 **Request URL** 中复制：
   - `access_token` 查询参数的值（一个短期有效的 JWT）。
   - `/Chathub/` 之后的 Chathub 路径段（例如 `<oid>@<tenant>`）。

完整 URL 的格式如下：

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. 在 OmniRoute 中，前往 **Providers → Add Provider**，选择 **Microsoft 365 Copilot
   (BizChat)**，然后按以下格式粘贴凭据：

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. 点击 **Test Connection**，然后点击 **Save**。

## 获取凭据（导入 HAR）

除了从 WebSocket URL 手动复制值之外，还可以导出 DevTools HAR
文件：

1. 打开 **DevTools → Network**。
2. 开始或继续 BizChat 对话（这将触发 WebSocket 连接）。
3. 在 Network 面板中右键单击，然后选择 **Save all as HAR with content**。
4. 在 OmniRoute 的提供者连接对话框中，使用 **Import .har file** 按钮。

OmniRoute 会扫描 HAR 以查找 Chathub WebSocket URL，提取
`access_token` 和 `chathubPath`，并自动填充凭据字段。
导入 HAR 时还会解码 JWT 的过期时间，并显示令牌的剩余有效期。

> **切勿提交真实的 HAR 导出文件、访问令牌或刷新令牌。** 测试和
> 文档中的值必须始终使用占位符。

## 令牌有效期和刷新

`access_token` 的有效期较短（通常约为 **~75 分钟**）。过期后，提供者
会报告连接错误，此时必须重新获取凭据。

### 使用 `refreshToken` 自动刷新

为了避免手动重新获取凭据，可以将 Microsoft 刷新令牌存储在连接的
**Advanced Settings → providerSpecificData** 中：

| 字段           | 说明                                                               |
| -------------- | ------------------------------------------------------------------ |
| `refreshToken` | 用于 `substrate.office.com/sydney` 范围的 Microsoft OAuth 刷新令牌 |
| `tier`         | `individual`（默认）、`edu` 或 `enterprise`                        |

通过范围限定为 `substrate.office.com/sydney` 的 Microsoft 设备代码流程或授权代码流程
获取刷新令牌。设置 `refreshToken` 后，OmniRoute 会在每次请求前预先刷新
`access_token`，因此无需在每次约 75 分钟的有效期结束后重新获取凭据。

如果未设置 `refreshToken`，则必须在每次凭据过期后手动重新获取 WebSocket 凭据。

### 层级选择

| 层级         | 别名       | 使用场景                  |
| ------------ | ---------- | ------------------------- |
| `individual` | _（默认）_ | 面向消费者的 M365 Copilot |
| `edu`        | `included` | 教育版 M365 Copilot       |
| `enterprise` | `work`     | M365 Copilot for Work     |

在 **Advanced Settings → providerSpecificData → tier** 中设置层级。该层级会影响
BizChat 的路由和模型访问权限。

## 安全模型

- **非官方集成。** 此供应商对 BizChat WebSocket
  协议进行了逆向工程。当 Microsoft 更改端点时，它可能会在没有通知的情况下失效。
- `subscriptionRisk: true` 标志表示此集成依赖于一个
  未公开的端点。账户可能会受到限制，但尚未得到证实。
- 访问令牌是一个短期有效的 JWT。请像对待密码一样对待它：不要提交、
  记录或分享它。
- 刷新令牌授予对 BizChat 服务的长期访问权限。请像保管 API 密钥一样
  妥善保管它。

## 故障排除

### 身份验证立即失败

- 请确认你复制的是 **WebSocket URL**，而不是 XHR/Fetch 请求中的内容。
  凭据位于 Chathub WebSocket 连接的 `access_token` 查询参数中，
  而不在 `Authorization: Bearer` 标头中。
- 请确保 `chathubPath` 包含 URL
  路径中完整的 `<oid>@<tenant>` 段。

### 令牌在约 75 分钟后过期

这是预期行为。如果没有 `refreshToken`，访问令牌的有效期很短。你可以：

- 从 DevTools 中重新获取凭据，或
- 在高级设置中配置 `refreshToken`，以便自动刷新。

### 测试连接通过，但聊天返回 401

令牌可能在验证与首次请求之间已过期。请重新获取一个
新凭据。

### Copilot 未出现在供应商列表中

请确保已在 **Dashboard → Providers** 中启用 `copilot-m365-web`。在某些层级中，该供应商可能
默认隐藏。
