本文档记录了针对
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854) 的实现决策。公开产品划分为四个提供者系列。区域属于连接数据，而不是独立产品。

## 决策

| 提供者系列                             | OmniRoute ID            | 全球区域 | 中国区域 |
| -------------------------------------- | ----------------------- | -------- | -------- |
| Alibaba Cloud Model Studio（按量付费） | `alibaba`               | 新加坡   | 北京     |
| Alibaba Cloud Token Plan               | `bailian-coding-plan`   | 新加坡   | 北京     |
| Qwen Cloud（按量付费）                 | `qwen-cloud`            | 全球     | 北京     |
| Qwen Cloud Token Plan                  | `qwen-cloud-token-plan` | 新加坡   | 北京     |

现有的 `alibaba-cn` ID 仍作为运行时兼容性别名，用于已保存的连接、模型路由、组合和历史用量。其仪表板卡片将合并到 `alibaba` 中；无需重写数据库。

Qwen Cloud 按量付费产品和 Alibaba Cloud Model Studio 当前共享兼容 DashScope 的运行时主机，但两者仍保留各自独立的提供者身份，因为用户通过不同的产品界面获取密钥和管理账户。Alibaba 和 Qwen Cloud 的 Token Plan 产品使用不同的端点系列，因此所有四种产品仍使用独立的提供者 ID。

## 端点矩阵

| 提供者系列              | `global-sg`                                                              | `china-beijing`                                                      | 传输格式  |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | --------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI    |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI    |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI    |

API 密钥和端点必须属于同一产品和区域。选择区域会更改验证和常规请求所使用的预设端点。

## 连接约定

新连接会将稳定的区域键存储在 `providerSpecificData` 中：

```json
{
  "region": "global-sg"
}
```

允许的值为 `global-sg` 和 `china-beijing`。端点根据提供者 ID 和区域进行集中推导。非预设的 `providerSpecificData.baseUrl` 仍作为运维人员的显式覆盖项并具有更高优先级，而旧版已保存的预设 URL 会重新规范化为区域矩阵中的值。

这使连接架构保持可扩展性：可以向解析器添加其他区域，而无需创建新的提供者卡片或更改已保存的提供者 ID。

## 兼容性与发布

1. 添加区域端点解析器，并保留当前的全局默认设置。
2. 对 `alibaba`、其兼容性 ID `alibaba-cn` 以及 `qwen-cloud` 使用实时的区域 DashScope `/models` 发现。它们的响应会先通过一次文本生成模型筛选，因为通用端点还会返回图像、视频、音频、嵌入及其他非聊天模型。随后，`qwen-cloud` 会应用其提供者注册表中声明并持续维护的允许列表。尽管 Alibaba Model Studio 和 Qwen Cloud 当前共享运行时主机，但两者仍维护各自独立的精选目录。
3. 使用当前 Token Plan 文本模型允许列表注册 `qwen-cloud-token-plan`。
4. 在添加/编辑连接对话框中添加类型化的区域选择器。
5. 隐藏重复的 `alibaba-cn` 卡片，并将其现有连接纳入 `alibaba` 提供者页面。
6. 为高级部署和工作区特定部署保留自定义端点覆盖功能。

Token Plan 媒体模型仍不包含在聊天目录中，因为它们使用专用端点。
`wan2.7-image` 和 `wan2.7-image-pro` 注册在 `open-sse/config/imageRegistry.ts` 中；
`happyhorse-1.1-i2v`、`happyhorse-1.1-t2v` 和 `happyhorse-1.1-r2v` 注册在
`open-sse/config/videoRegistry.ts` 中。两个注册表均复用 `qwen-cloud-token-plan` 连接
标识及其区域特定凭据。

常规 Qwen Cloud 在 `qwen-cloud` 标识下拥有独立的按量付费图像和视频目录。其图像模型包括
`wan2.7-image-pro`、`wan2.7-image`、`qwen-image-3.0-pro`、
`qwen-image-2.0-pro-2026-06-22`、`qwen-image-2.0-2026-03-03` 和 `z-image-turbo`。其视频
模型包括 `happyhorse-1.1-i2v`、`happyhorse-1.1-t2v`、`happyhorse-1.1-r2v`、
`happyhorse-1.0-video-edit`、`wan2.7-t2v`、`wan2.7-i2v`、`wan2.7-r2v-2026-06-12` 和
`wan2.7-videoedit`。这些模型仅复用常规 `qwen-cloud` 连接和区域
DashScope 媒体端点。Token Plan 与按量付费注册表不会相互继承或合并
对方的模型列表。

`bailian-coding-plan` 标识也有自己的媒体允许列表：
用于图像生成的 `wan2.7-image`、`wan2.7-image-pro`、`qwen-image-2.0` 和 `qwen-image-2.0-pro`，
以及用于视频生成的
`happyhorse-1.1-i2v`、`happyhorse-1.1-t2v` 和 `happyhorse-1.1-r2v`。
它仅使用 Bailian Coding Plan 连接和区域 Coding Plan 端点。
其图像和视频注册表不会从任何一个 Qwen Cloud 提供者继承，也不会与其合并。

常规 `alibaba` 标识拥有独立的图像和视频允许列表。其图像模型包括
`qwen-image-3.0-pro`、`qwen-image-2.0-pro-2026-06-22`、`qwen-image-2.0`、
`z-image-turbo` 和 `wan2.6-t2i`。新增的视频模型包括 `happyhorse-1.1-i2v`、
`happyhorse-1.1-t2v`、`happyhorse-1.1-r2v`、`happyhorse-1.0-video-edit`、
`wan2.7-i2v-2026-04-25`、`wan2.6-i2v-flash`、`wan2.7-t2v-2026-06-12`、
`wan2.7-r2v-2026-06-12` 和 `wan2.7-videoedit`。这些模型仅使用 Alibaba Model Studio
连接及其选定的区域媒体端点；它们不会被添加到任何 Coding Plan 或 Qwen
Cloud 注册表中。

Qwen Cloud Token Plan 聊天目录遵循 Individual 方案的精确字符串文本允许列表：
`qwen3.8-max-preview`、`qwen3.7-max`、`qwen3.7-plus`、`qwen3.6-flash`、`glm-5.2` 和
`deepseek-v4-pro`。Wan 和 HappyHorse 条目属于独立的图像/视频生成 API。

Alibaba Token Plan 通过其 Anthropic 兼容端点公开相同的六个当前文本生成模型 ID。
其新加坡选项存储现有的 `global-sg` 区域键；只有面向用户的标签与将该区域称为“全球”的提供者系列不同。

常规 Qwen Cloud 聊天目录有意设计得比完整的实时文本响应更精简。其持续维护的允许列表位于
`open-sse/config/providers/registry/qwen-cloud/index.ts`；实时
发现仅返回同时存在于上游响应和该注册表列表中的 ID。

Alibaba Model Studio 遵循相同的实时交集规则，并使用其在
`open-sse/config/providers/registry/alibaba/index.ts` 中独立维护的允许列表。`alibaba-cn` 兼容性
提供者会复用该目录，同时针对北京端点执行发现解析。
