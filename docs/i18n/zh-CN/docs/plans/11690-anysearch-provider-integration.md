## 1. 服务事实基准（官方文档，已交叉核验）

- 基础 URL：`https://api.anysearch.com`（REST）+ `POST /mcp`（MCP，JSON-RPC 2.0）。
- `POST /v1/search` - 参数：`query`（必填）、`max_results`（1-10，默认 10）、`tag`（使用 `{domain}.{sub_domain}` 进行垂直路由）、`zone`（cn/intl）、`language`、`params`（结构化垂直领域字段）、`format`（json/markdown）。
- `GET /v1/sub-domains?domain=...` - 能力目录，不计入配额。
- `POST /v1/extract` - 获取/提取 `{url, title, content}`；严格的 JSON 请求体，大小上限为 16 KiB。
- `POST /v1/auth/email/register` - 单次调用注册，返回一次性明文密钥 `as_sk_...`。
- 身份验证：可选的 `Authorization: Bearer <as_sk_...>`；匿名访问会降级为按 IP 限流，并消耗每日免费配额；无效密钥会返回 401/403，且不会静默回退到匿名访问。
- 免费套餐：每天 1000 次请求，每个密钥 20 QPS。付费套餐：尚未定价（即将推出）。
- 响应封装：成功时为 `{code: 0, message: "success", request_id, data}`；失败时为 `{code: -1, message}`。身份验证/配额错误不包含结构化的 `error_code`（以消息文本作为信号）；提取相关错误会包含 `error_code`（`invalid_extract_url`、`extract_failed`）。429 响应中没有 `Retry-After` 标头。

## 3. 决策（均于 2026-08-26 达成）

1. **路由策略：`fallbackOnly`。** 理由：成本为 0 的免费提供者绝不能在自动成本路由中占据主导地位；显式选择和故障转移返回不受影响。先例：已合并的 xquik 条目。
2. **范围：v1 中通过 `POST /v1/extract` 支持 webSearch + webFetch。** 与 tavily/exa 双能力心智模型保持一致。垂直功能（`tag`、`sub-domains`、`batch_search`）暂不纳入范围——目前尚无用于垂直参数的 IR。
3. **配额显示：`freeMonthlyQuota: 0`**（采用 xquik 风格的保守显示）。实际额度（每天 1000 次请求、每日重置）改为在 UI 目录的 `authHint` 文案中说明。理由：配额显示必须与重置语义一致；将每日上限换算为月度等价值（30000）会构成 UI 无法兑现的虚假承诺。
4. **searchTypes：仅 `["web"]`。** 没有公开证据表明 AnySearch API 提供新闻/图片垂直搜索；对于集成了没有已记录垂直搜索能力的 API 的网关（例如 Google Custom Search），应仅公开网页搜索，而不是静默地将新闻搜索映射到网页搜索。
5. **密钥策略：** 无密钥可用；无效密钥返回 401/403，且绝不会静默降级为匿名访问（与上游契约一致）。
6. **有意排除的内容：** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend`（聊天拦截仍使用 firecrawl/jina/tavily）；`ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS`（匿名远程端点按出口 IP 共享同一个受 IP 限制的池，因此无密钥提取属于选择启用功能，而非自动路由候选项）；`QUOTA_STATUS_PROVIDERS`（AnySearch 通过 429/响应封装指示配额状态，而不是 402/403 状态）。
