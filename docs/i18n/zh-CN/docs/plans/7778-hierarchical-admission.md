1. 通过针对性测试锁定现有的单键信号量契约和新的原子多键契约：不得部分预留、FIFO 排队、中止、超时、队列已满、幂等释放、统计信息和清理。
2. 就地泛化现有的账户信号量。保留 `acquire()`，将其作为 `acquireMany()` 的兼容性封装；不要添加第二个调度器或依赖项。
3. 将 `chatCore` 中仅针对账户的获取操作替换为一次累积式的全局/提供者/账户获取，并将其放在 `withRateLimit` 之前。每当账户轮换导致连接发生变化时，重新获取整组资源，并持续持有直至流式传输完成后再释放。
4. 扩展现有的弹性设置管道（类型、默认值、规范化、架构、API 响应、UI 和翻译），加入全局和提供者并发上限。将旧的 Bottleneck 并发控制重新标记为连接/配额范围并发，以明确其实际作用域。
5. 运行针对性测试、lint、类型检查、静态检查和完整测试套件；在变更日志中记录此行为变更。

有意保留的行为：并发数为零/null 时绕过相应关卡；仅针对账户的调用方继续使用 `acquire()`；已阻止账户的控制机制保留其键格式和 API；提供者速率限制队列的行为保持不变。
