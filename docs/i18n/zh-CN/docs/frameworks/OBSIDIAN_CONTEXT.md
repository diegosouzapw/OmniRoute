> 和作用域连接位于 `open-sse/mcp-server/server.ts`。

## 功能简介

OmniRoute 将 **Obsidian** 仓库连接为**上下文源**——这是一个本地 Markdown
知识库，智能体通过内置 MCP 服务器对其进行读写。此集成与运行在
桌面应用中的 **Obsidian Local REST API** 社区插件通信，因此智能体可以搜索笔记、
读取/写入/修补文件、列出仓库内容、处理每日/每周周期笔记、管理标签、运行 Obsidian
命令，以及（可选）协调桌面端↔移动端的双向仓库同步。

客户端（`src/lib/obsidian/api.ts`）对 Local REST API 进行了封装，提供：

- 针对临时性 `5xx` 错误的**退避重试**，并通过 `AbortController` 实现**30 秒超时**。
- **类型化错误分类**——`ObsidianAuthError`（401/403）、
  `ObsidianNotFoundError`（404）、`ObsidianServerError`（5xx）、`ObsidianTimeoutError`。
- 友好的**“无法连接到 Obsidian”提示**，明确指出常见的端口错误
  （HTTP 使用 `27123`，**而不是** `27124` 上的 MCP 端点），并说明 Tailscale 地址格式。
- 仓库相对路径的**路径编码**，确保包含空格/斜杠的笔记路径可安全使用。

## 设置

Obsidian 令牌或基础 URL **没有对应的环境变量**——两者均通过
`src/lib/db/obsidian.ts` 存储在 SQLite `key_value` 表（命名空间 `obsidian`）中。
令牌会**加密存储**（AES-256-GCM，并提供明文向后兼容回退）。可以在 Endpoint
仪表板的 **Context Sources** 选项卡（`ObsidianSourceCard`）中进行配置，也可以通过
设置 REST API 配置。

> [!IMPORTANT]
> 必须安装并运行 **Obsidian Local REST API** 插件。其 REST
> 接口监听 **HTTP `127.0.0.1:27123`**（默认基础 URL）。端口 `27124`
> 是一个_独立的_ MCP/HTTPS 端点，设置路由会明确拒绝该端口。
> 如果从其他设备连接，请使用 `http://<tailscale-ip>:27123`。

### 配置键（SQLite `key_value`，命名空间 `obsidian`）

| 键                | 用途                                           | 是否加密 |
| ----------------- | ---------------------------------------------- | -------- |
| `api_key`         | Local REST API bearer 令牌                     | 是       |
| `base_url`        | REST 基础 URL（默认 `http://127.0.0.1:27123`） | 否       |
| `vault_path`      | 仓库目录的绝对路径（用于同步）                 | 否       |
| `webdav_username` | 生成的 WebDAV 用户名（仓库同步）               | 否       |
| `webdav_password` | 生成的 WebDAV 密码（仓库同步）                 | 是       |
| `webdav_enabled`  | 是否启用 WebDAV 仓库同步                       | 否       |

### 通过 REST 配置

```bash
# 保存并验证 Local REST API 令牌（POST 通过状态检查进行验证）
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# 检查连接状态（返回 connected、hasToken、baseUrl、vaultPath）
curl http://localhost:20128/api/settings/obsidian

# 断开连接（清除已存储的令牌）
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

所有方法都需要仪表板身份验证。`POST` 会拒绝端口为 `27124`
的任何 URL，并在持久化之前通过调用 Local REST API 状态端点来验证令牌。

### WebDAV 仓库同步

`src/app/api/settings/obsidian/webdav/route.ts` 管理可选的、由 WebDAV 支持的
仓库同步（由 `src/lib/obsidianSync.ts` 驱动）。启用后，它会将 OmniRoute 指向
本地仓库目录，并生成一对随机的 WebDAV 用户名/密码：

```bash
# 为仓库目录启用 WebDAV 同步（生成用户名/密码）
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# 获取 WebDAV 同步状态（仅在启用时返回凭据）
curl http://localhost:20128/api/settings/obsidian/webdav

# 禁用 WebDAV 同步（清除凭据和托管的 .stignore）
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### 每个 API 密钥的上下文源（可选）

可以通过 `api_key_context_sources` 表为**每个 API 密钥**单独设置 Obsidian 配置
（`src/lib/db/apiKeyContextSources.ts`）。当 MCP 调用携带经过身份验证的 API
密钥 ID 时，`getObsidianConfigForApiKey()` 会优先使用该密钥自己的令牌/基础 URL/仓库路径
（`source: "api_key"`），否则回退到全局配置（`source: "global"`）。

## MCP 工具 (22)

定义于 `open-sse/mcp-server/tools/obsidianTools.ts`。令牌/基础 URL 会在每次调用时解析（优先使用每个 API 密钥的配置，其次使用全局配置）。调用 OmniRoute **同步服务器**的工具（四个 `obsidian_sync_*` 工具）还需要在 OmniRoute 设置中配置同步认证令牌。

### 读取工具 (`read:obsidian`)

| 工具                         | 描述                                                                         |
| ---------------------------- | ---------------------------------------------------------------------------- |
| `obsidian_check_status`      | 检查 Local REST API 是否可访问且已通过认证。                                 |
| `obsidian_search_simple`     | 对笔记内容进行全文搜索；返回包含文件路径的片段。                             |
| `obsidian_search_structured` | 使用 JSON Logic 表达式（and/or/regex/path 过滤器）进行搜索。                 |
| `obsidian_read_note`         | 按仓库相对路径读取笔记；可选择特定标题/块/frontmatter。                      |
| `obsidian_list_vault`        | 列出仓库中的文件和目录（条目树）。                                           |
| `obsidian_get_document_map`  | 获取笔记的标题结构，格式为标题 → 行号映射。                                  |
| `obsidian_get_note_metadata` | 获取 frontmatter、标签、链接、字符数/字数，而不获取完整内容。                |
| `obsidian_get_active_file`   | 获取 Obsidian 中当前活动文件的路径和内容。                                   |
| `obsidian_get_periodic_note` | 获取指定日期的每日/每周/每月周期笔记（省略时为今天）。                       |
| `obsidian_get_tags`          | 列出仓库中的所有标签及其出现频率。                                           |
| `obsidian_list_commands`     | 列出可用的 Obsidian 命令 ID（与 `obsidian_execute_command` 配合使用）。      |
| `obsidian_sync_status`       | OmniRoute 同步服务器状态：运行状态、仓库名称、端口、运行时间、上次同步时间。 |
| `obsidian_sync_conflicts`    | 列出未解决的同步冲突（路径、冲突路径、检测时间）。                           |

### 写入工具 (`write:obsidian`)

| 工具                             | 描述                                                                     |
| -------------------------------- | ------------------------------------------------------------------------ |
| `obsidian_write_note`            | 使用给定的 Markdown 内容创建或覆盖笔记。                                 |
| `obsidian_append_note`           | 向笔记追加内容；可选择追加到特定标题/块。                                |
| `obsidian_patch_note`            | 在标题、块或 frontmatter 字段处精确追加/前置/替换内容。                  |
| `obsidian_delete_note`           | 从仓库中永久删除笔记。                                                   |
| `obsidian_move_note`             | 在仓库内移动或重命名笔记。                                               |
| `obsidian_execute_command`       | 按 Obsidian 命令 ID 执行命令。                                           |
| `obsidian_open_file`             | 在 Obsidian 中打开文件（如果文件不存在则创建）。                         |
| `obsidian_sync_trigger`          | 立即触发桌面端↔移动端仓库双向同步。                                      |
| `obsidian_sync_resolve_conflict` | 解决同步冲突：保留 `local`（移动端）、`remote`（桌面端）或 `keep-both`。 |

> [!NOTE]
> `obsidian_patch_note` 目标接受 `heading | block | frontmatter` 类型的 `targetType`
> 和 `append | prepend | replace` 类型的 `operation`，并可选择设置
> `createTargetIfMissing`。四个 `obsidian_sync_*` 工具与本地同步
> 服务器通信（默认为 `http://127.0.0.1:27781`），并且需要同步令牌。

### 作用域

读取工具需要 `read:obsidian`；写入工具需要 `write:obsidian`。其强制执行机制
与 Notion 相同——由 `open-sse/mcp-server/server.ts` 中的
`withScopeEnforcement()` 处理，通过 `OMNIROUTE_MCP_ENFORCE_SCOPES=true` 启用，
允许的作用域来自 `OMNIROUTE_MCP_SCOPES` 或 API 密钥的作用域上下文。请参阅
[MCP-SERVER.md](./MCP-SERVER.md)。

## 端点

| 方法     | 路径                            | 用途                                                 |
| -------- | ------------------------------- | ---------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | 返回 `{ connected, hasToken, baseUrl, vaultPath }`。 |
| `POST`   | `/api/settings/obsidian`        | 保存并验证令牌（拒绝端口 `27124`）。                 |
| `DELETE` | `/api/settings/obsidian`        | 断开连接（清除已存储的令牌）。                       |
| `GET`    | `/api/settings/obsidian/webdav` | WebDAV 同步状态和凭据（启用期间）。                  |
| `POST`   | `/api/settings/obsidian/webdav` | 为某个仓库目录启用 WebDAV 同步。                     |
| `DELETE` | `/api/settings/obsidian/webdav` | 禁用 WebDAV 同步。                                   |

> 这些是仪表板设置路由。仓库本身通过 Obsidian
> Local REST API（配置的 `base_url`）以及上述 MCP 工具进行访问——不存在公开的
> `/v1` Obsidian 代理端点。

## 使用场景

- **基于仓库内容的回答** — 先使用 `obsidian_search_simple` / `obsidian_search_structured`，
  然后使用 `obsidian_read_note`，让智能体根据你的真实笔记作答。
- **笔记撰写 / 日志记录** — 使用 `obsidian_write_note`、`obsidian_append_note` 或
  可进行精准修改的 `obsidian_patch_note`，将智能体输出、摘要或每日笔记
  （`obsidian_get_periodic_note`）记录到仓库中。
- **仓库导航** — 使用 `obsidian_list_vault`、`obsidian_get_document_map` 和
  `obsidian_get_tags`，在读取/写入之前探索结构。
- **Obsidian 自动化** — 使用 `obsidian_list_commands` + `obsidian_execute_command`
  让智能体驱动插件/命令；使用 `obsidian_open_file` 在 UI 中显示笔记。
- **移动端同步** — 启用 WebDAV 同步，然后使用 `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  协调桌面端↔移动端同步并解决冲突。
