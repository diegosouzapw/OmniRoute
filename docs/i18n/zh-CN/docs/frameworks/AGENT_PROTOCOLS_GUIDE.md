> **来源：** `src/lib/{a2a,acp,cloudAgent}/`、`src/app/api/{a2a,acp,cloud}/`、`src/app/api/v1/agents/`
> **最后更新：** 2026-06-28 — v3.8.40

OmniRoute 提供了三个不同的智能体相关接口。它们乍看之下很相似，但解决的是不同的问题。请使用本页选择合适的接口。

## 简要概述

| 接口                       | 最适合                                                                                                 | 传输方式                   | 标准                 |
| -------------------------- | ------------------------------------------------------------------------------------------------------ | -------------------------- | -------------------- |
| **A2A — 智能体到智能体**   | 与支持 A2A 协议的对等智能体进行跨智能体协作                                                            | 基于 HTTP 的 JSON-RPC 2.0  | A2A v0.3（开放规范） |
| **ACP — CLI 智能体注册表** | 检测 / 注册 / 启动用户计算机上安装的 CLI 编码智能体（Cursor、Cline、Codex CLI、Claude Code、Aider 等） | HTTP REST                  | OmniRoute 专用       |
| **云智能体**               | 将长时间运行的编码任务提交给外部云服务（Codex Cloud、Devin、Jules、Cursor Cloud）                      | HTTP REST + 数据库后端任务 | OmniRoute 专用       |

三者彼此独立，可任意选择其中一个或多个。

## 决策树

```
是否需要云服务在本机之外执行工作（Codex Cloud / Cursor Cloud / Devin / Jules）？
├─ 是 → 云智能体（POST /api/v1/agents/tasks）
└─ 否 → 继续
    │
    是否有一个支持 A2A 并希望进行协作的对等智能体？
    ├─ 是 → A2A（POST /a2a）
    └─ 否 → 继续
        │
        是否需要列出 / 配置本地安装的 CLI 编码智能体？
        ├─ 是 → ACP（GET /api/acp/agents）
        └─ 否 → 使用普通的 /v1/chat/completions
```

## 1. A2A — 智能体到智能体

**规范：** [A2A v0.3](https://a2a-protocol.org)
**OmniRoute 端点：** `POST /a2a`（JSON-RPC 2.0）
**智能体卡片：** `GET /.well-known/agent.json`

### 适用场景

- 构建以 OmniRoute 作为对等方之一的多智能体系统
- 向 Google ADK 等框架中的智能体或通用智能体网络开放 OmniRoute 的路由能力（智能路由、配额管理等）
- 使用标准的发现与调用接口封装 OmniRoute

### 方法

- `message/send` — 提交消息并接收同步响应
- `message/stream` — 提交消息并接收通过 SSE 流式传输的进度事件
- `tasks/get` — 通过 ID 读取任务
- `tasks/cancel` — 取消正在运行的任务

### 内置技能（6 项）

- `smart-routing` — 通过最佳组合路由提示词
- `quota-management` — 报告各提供者的配额状态
- `provider-discovery` — 列出已安装的提供者及其功能
- `cost-analysis` — 估算请求/对话的成本
- `health-report` — 汇总各提供者的断路器/冷却/锁定状态
- `list-capabilities` — 列举智能体可用的技能及元数据

### 深入了解

有关传输细节、智能体卡片结构、任务 TTL 配置以及添加新技能的模板，请参阅 [A2A-SERVER.md](./A2A-SERVER.md)。

## 2. ACP — CLI 代理注册表

**OmniRoute 端点：** `GET /api/acp/agents`
**源代码：** `src/lib/acp/{index,manager,registry}.ts`

### 简介

ACP 是 OmniRoute 的**本地 CLI 代理清单**。它会检测主机上安装了哪些编程 CLI（Cursor、Cline、Claude Code、Codex CLI、Continue 等），解析其版本，并将这些信息显示在仪表板中，以便用户将各个 CLI 配置为指向 OmniRoute。

这不是外部协议，而是一个内部注册表，用于支持“CLI 工具”界面和 CLI 指纹跟踪（参见 [CLI-TOOLS.md](../reference/CLI-TOOLS.md)）。

### 功能

- 探测主机上已安装的 CLI 二进制文件（根据操作系统使用 `which` / `where`）
- 读取各个 CLI 的版本（调用 `<bin> --version`）
- 可选择接受用户定义的自定义代理（二进制文件路径 + 版本探测命令 + 启动参数）
- 将自定义代理持久化到设置中
- 向仪表板返回统一列表

### REST API

| 端点              | 方法 | 描述                                                         | 认证     |
| ----------------- | ---- | ------------------------------------------------------------ | -------- |
| `/api/acp/agents` | GET  | 列出检测到的代理和自定义代理（已安装数量/总数）              | API 密钥 |
| `/api/acp/agents` | POST | 添加/更新/移除自定义代理（请求体中通过 action 字段进行区分） | API 密钥 |

POST 的请求体结构（`src/app/api/acp/agents/route.ts` 中的 `customAgentBodySchema`）：

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### 使用场景

- 仪表板的“CLI 工具”页面会列出已安装的工具，并帮助你将各个工具配置为指向 OmniRoute
- 自定义代理允许高级用户注册 OmniRoute 默认不识别的内部/专有 CLI
- 检测结果会用于生成 `cli-tools` 指纹矩阵

### 不应使用 ACP 的场景

- ACP 不会_运行_任务。它只负责检测和配置 CLI。要实际调用 CLI，你需要使用 OmniRoute 提供的环境变量（`OPENAI_BASE_URL`、`OPENAI_API_KEY` 等）自行启动它。

## 3. 云代理

**OmniRoute 端点：** `/api/v1/agents/tasks/*`（生命周期）+ `/api/cloud/*`（底层衔接）
**源代码：** `src/lib/cloudAgent/`

### 简介

这是第三方云端编程代理的统一接口。你可以提交提示词和仓库 URL，OmniRoute 会将任务分派给相应的云代理、轮询状态并返回结果。

### 支持的代理（3 个，均已在 `src/lib/cloudAgent/agents/` 中确认）

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### 生命周期

```
POST /api/v1/agents/tasks
  → 每个代理类的 BaseAgent.createTask()
  → 外部服务开始执行工作
  → 在 DB 中创建任务记录（cloud_agent_tasks）
  ↓
GET /api/v1/agents/tasks/[id]
  → 从提供者延迟同步状态
  → 返回当前状态 + 计划 + 活动日志
  ↓
POST /api/v1/agents/tasks/[id]   （action: "approve" | "message" | "cancel"）
  → 转发给提供者（或在本地标记为已取消）
  ↓
DELETE /api/v1/agents/tasks/[id]
  → 在本地取消
```

### 认证

⚠️ **所有 `/api/v1/agents/tasks/*` 端点都需要管理认证**（提交 `588a0333`）。从 v3.8.0 开始，仅使用 Bearer 认证的调用方会收到 401 响应。

### 深入了解

有关 `CloudAgentBase` 契约、各代理的具体信息、模式详情以及凭据衔接端点，请参阅 [CLOUD_AGENT.md](./CLOUD_AGENT.md)。

## 对比：A2A 与 Cloud Agents

两者都有“长时间运行的任务”，但所处层级不同：

| 方面         | A2A                                                                             | Cloud Agents                         |
| ------------ | ------------------------------------------------------------------------------- | ------------------------------------ |
| 标准         | 开放标准 A2A v0.3                                                               | OmniRoute 专用                       |
| 计算运行位置 | OmniRoute 内部（使用已配置的组合）                                              | 外部（Codex / Devin / Jules 服务器） |
| 任务持续时间 | 默认 TTL 为 5 分钟（可在 `TaskManager` 中配置）                                 | 数分钟至数小时                       |
| 仓库感知     | 否（仅传递提示词）                                                              | 是（仓库 URL + 分支）                |
| 使用场景     | 跨智能体协作、将智能路由作为服务                                                | 委派“在仓库 Y 中实现功能 X”          |
| 身份验证     | `/a2a` 可选使用 `OMNIROUTE_API_KEY`；`/api/a2a/*` REST 辅助接口使用管理身份验证 | 始终使用管理身份验证                 |

## 集成示例

### 发现 OmniRoute 的 A2A 功能

```bash
curl http://localhost:20128/.well-known/agent.json
```

返回包含全部 6 项技能、传输方式和版本信息的 Agent Card。

### 将 OmniRoute 作为 A2A 智能体调用

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### 通过 ACP 列出已安装的 CLI 智能体

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### 添加自定义 CLI 智能体

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### 提交 Cloud Agent 任务

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### 轮询云端任务状态

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## 何时使用哪一种

- **聊天机器人 / copilot 前端** → `/v1/chat/completions`（兼容 OpenAI，但不是智能体协议）
- **多智能体协作** → A2A
- **在控制面板中列出本地 CLI** → ACP
- **将长时间运行的编码任务委派给云服务** → Cloud Agents

```

   Agent                              Codex Cloud、Cursor、
                                      Devin、Jules
```
