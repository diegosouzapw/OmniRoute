> `open-sse/mcp-server/tools/localCorpusTools.ts`（3 个只读 MCP 工具），以及
> `src/app/api/settings/local-corpus/route.ts`（设置 API）。

## 功能简介

Local Corpus 允许操作员将一个明确批准的文本文件目录提供给 OmniRoute 的 MCP 服务器。文件保留在其原始目录中：OmniRoute 仅将规范化根路径存储在 SQLite 中，并维护一个内存搜索索引。它不会将语料库内容复制到代码仓库或数据库中。

索引采用增量刷新。系统会根据文件大小和修改时间复用未更改的文件，重新读取已更改的文件并使用 SHA-256 计算哈希值，同时移除已删除的文件。搜索时会刷新超过 30 秒未更新的索引；调用方也可以请求立即刷新。

## 配置数据源

设置路由需要与其他设置 API 相同的管理身份验证。提交的路径必须已存在，并且必须是绝对目录路径。

```bash
# 连接已批准的目录
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# 检查配置和索引状态
curl http://localhost:20128/api/settings/local-corpus

# 断开连接，但不更改源文件
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## MCP 工具

所有三个工具都需要 `read:local-corpus`。工具响应仅公开相对路径和根目录的基本名称，绝不会公开其绝对路径。

| 工具                  | 描述                                                             |
| :-------------------- | :--------------------------------------------------------------- |
| `local_corpus_status` | 报告配置状态、索引大小、限制以及上次刷新时间                     |
| `local_corpus_search` | 搜索已索引文本，并返回有界、按行定位的摘要片段（最多 20 个结果） |
| `local_corpus_read`   | 从一个允许的语料库相对路径文件中读取有界的行范围                 |

MCP 输入示例：

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## 安全边界

- 允许列表面向文本格式：`.cfg`、`.csv`、`.geojson`、`.htm`、`.html`、`.ini`、
  `.js`、`.json`、`.jsonl`、`.jsx`、`.log`、`.md`、`.mjs`、`.ps1`、`.py`、`.sh`、
  `.sql`、`.toml`、`.ts`、`.tsx`、`.txt`、`.xml`、`.yaml` 和 `.yml`。
- 系统会跳过符号链接。读取路径会被规范化，并且必须始终位于已配置的根目录内；绝对路径和路径遍历尝试将被拒绝。
- 以下敏感目录名和生成目录名会被排除：`.build`、`.codex`、`.env`、
  `.git`、`.next`、`.omniroute`、`.ssh`、`coverage`、`dist`、`node_modules` 和
  `secrets`。
- 默认限制为 5,000 个文件、每个文件 1 MiB、索引内容总计 64 MiB、每个搜索分块约 4,000 个字符，以及每次读取 400 行。
- 包含 NUL 的文件会被视为非文本文件，并被跳过或拒绝。

系统有意不支持 PDF、DOCX、图像和归档文件等二进制文档。请先在已配置的目录中将它们转换为获准的文本格式，然后再进行索引。

## 运维说明

- 更改或删除已配置的根目录会清除共享的内存索引。
- 进程重启会丢弃索引；下次搜索时将从已配置的数据源重建索引。
- `local_corpus_status` 不会强制执行扫描。需要立即重新扫描时，请使用带有
  `refresh: true` 的 `local_corpus_search`。
- 扫描和读取失败会被计数，或以经过净化的错误形式返回；源文件绝不会被修改。
