`agentrouter` 上游网关会对 `messages[].content` 运行基于关键字的内容过滤器。该过滤器一部分是确定性的（始终拦截某些短语），另一部分是概率性的（对突发请求敏感——快速发送请求后会变得更加严格，并在冷却后恢复）。

当 WAF 拦截请求时，会返回：

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## 过滤范围

WAF 仅检查 `messages[].content`。它**不会**检查：

- `system` 提示词
- 结构化内容块（`tool_result`、`tool_use`、`thinking`、`image`）
- 工具的 `description` 和 `input_schema` 字段
- 请求元数据、请求头或模型 ID

## 始终被拦截的模式（不区分大小写）

| 模式                        | 备注                                                    |
| --------------------------- | ------------------------------------------------------- |
| 任何 `Lorem ipsum` 变体     | 完整的拉丁文 lorem 词汇会被拦截                         |
| 单独出现的 `language model` | "the language model" 和 "large language model" 可以通过 |
| `virtual assistant`         | "AI assistant" 可以通过                                 |
| `I'm here to help`          | 单独的 "here to help" 也会被拦截                        |
| `Claude, made by Anthropic` | 仅完整短语会被拦截                                      |

## 几乎总是被拦截的模式

| 模式                                            | 备注                             |
| ----------------------------------------------- | -------------------------------- |
| `placeholder`                                   | 单独出现时（而不是作为参数名等） |
| `dummy data`                                    | 测试夹具中常见的种子短语         |
| `foo bar baz`                                   | 典型的占位短语                   |
| 重复的短词元（`AAA BBB CCC`、`test test test`） | 用于检测关键字堆砌               |

## 负载下的行为

在短时间窗口内快速发送约 5 个请求后，WAF 会开始拦截通常能够通过的内容。空闲约 5–10 秒后，限流桶会恢复。这与基于相同 IP 和密钥的限流器有关；当 Claude Code 或 Codex CLI 快速连续发起多个工具使用/消息发送调用时，该限流器会导致间歇性的 `400 content-blocked` 错误。

## OmniRoute 中已应用的缓解措施

1. **`open-sse/services/wafRateLimit.ts`** — 突发请求保护机制，强制要求向任何 `agentrouter:*` URL 发出的两个请求之间至少间隔 500 ms。该间隔远低于人类可感知的延迟，并可防止 WAF 在正常流量下被激活。

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — 当上游返回 `400 content-blocked` 时，执行器会使用指数退避策略重试同一 URL（1.5 s、3.0 s，最多重试 2 次）。退避完成后，WAF 通常已经放宽限制，重试即可成功。

3. **`tests/unit/compression/harness.test.ts`** — 测试夹具 `longInput` 已从 `"lorem ipsum dolor sit amet ".repeat(40)` 更改为 `"example content for testing purposes ".repeat(40)`，这样，当 Claude Code 通过 `Read` 工具读取该文件时，文件内容就不会通过 `tool_result` 块回传并触发 WAF。

## 提示词和工具输出指南

如果 Claude Code 或 Codex CLI 会话反复遇到 `400 content-blocked`，请检查最近的用户消息和最近的工具结果中是否包含上述任一模式，并改写相关内容。常见的规避方法：

- 将 `Lorem ipsum …` 替换为 `example text …`，或替换为测试或夹具实际尝试模拟的内容。
- 将单独出现的 `placeholder` 替换为 `example value`、`sample value` 或真实值。
- 将 `language model` 替换为 `large language model` 或 `the model`。
- 将 `dummy data` 替换为 `sample data` 或更真实的种子值。
- 将 `I'm here to help` / `here to help` 替换为更具体的开场白（例如 "I'll review the file you mentioned"）。

## 向上游报告误报

当前过滤器过于激进——它甚至会拦截 `tool_result` 块中的 "Lorem ipsum"，尽管操作者显然无意注入提示词。希望从源头解决此问题的运营者应联系 `agentrouter.org` 报告这些误报。上述阻止列表是截至 2026-08-03 对上游进行探测所得的经验结果。
