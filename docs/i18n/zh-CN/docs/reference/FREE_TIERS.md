## TL;DR — OmniRoute 实际聚合了多少免费推理额度？

这些数字描述了整个目录中彼此独立的第三方账户和资格条件。OmniRoute 并不直接提供这些额度：你必须获取所需的账户或凭据、连接符合条件的提供者，并遵守其限制。实际可用容量可能更低；在全新安装且没有符合条件的路由时，甚至可能为零。标记为 `tos: avoid` 的提供者默认不参与自动路由。

## 两种机制——统计与判定

OmniRoute 通过两种机制回答“它是否免费？”；这两种机制有意读取不同的数据源：

| 机制            | 权威来源                                                                                                                                                 | 应用范围                                                                                              |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| **统计 / 显示** | 解析后的目录——已发布的基线叠加 Radar 数据源（`getRadarCatalog`）                                                                                         | 免费层级总量、预算卡片、仪表板                                                                        |
| **判定**        | 仅使用已发布的目录（`open-sse/config/freeModelCatalog.data.ts` 中的 `FREE_MODEL_BUDGETS`）以及本地启发式规则（`:free` 后缀、零定价、`grantsFreeAccess`） | `src/shared/utils/freeModels.ts` 的所有使用方：模型导入、`auto/*` 路由、`GET /v1/models` 和浏览器预览 |

只要数据源可用，统计结果就可以持续改进。判定则始终以发布产物为准，因此其结果在浏览器和服务器上完全一致，可离线复现，也可以在不使用数据库的情况下进行测试。如果让浏览器预览读取一个数据源，而服务器导入读取另一个数据源，就会导致预览结果与点击后实际发生的行为不一致——这种划分是有意保留的。

## 方法论与注意事项

- 数字是根据各提供者截至 **2026-06-17** 记录的免费层级限制，通过网络调研得出的**上限估算值**。免费层级经常变化——在依赖某个数字之前，请重新核实。
- **每个条目实际保证的内容。** 条目没有逐行置信度评级，API 也不提供此类评级——应将上述每个数字都视为质量相同但未明确说明的估算值。不过，有两类事实不同，因为它们是人工整理而非推断得出的：44 个条目有独立记录的硬性停止机制（其中 39 个是 xKiro 条目，它们共享同一个每日配额），13 个条目有提示词训练披露。仅当提供者自身的条款明确说明，超出免费配额后会拒绝请求，而不是静默开始计费时，才会设置 `hardStopGuaranteed`，且来源会写在该条目旁的注释中；它绝不会默认设为 `true`，未经任何人验证的条目会保持未设置状态。因此，缺少硬性停止标志意味着“尚未证实”，而不是“已知会向你收费”。**STRICT 模式**（可选启用的 `freeAccessPolicy=strict` 路由防护）仅信任带有该标志的条目；其他所有免费层级都会以 `no-hard-stop` 为由排除（参见 `open-sse/services/autoCombo/strictZeroCostFilter.ts`）。当该防护筛选资源池时，面向运维人员的日志会同时报告排除数量及其中 `no-hard-stop` 所占比例。
- `estMonthlyFreeTokens` = 仅限每月重复提供的 token。**一次性注册赠金不会重复发放**，因此按 0 计算。已停止的层级也按 0 计算。
- 每日 token 上限 → `monthly = daily × 30`。仅记录了 RPD → `RPD × ~800 个输出 token × 30`。仅有 RPM/TPM（无每日上限）→ **不设上限**（见下文）。
- **永久免费，但未公布 token 上限**（`siliconflow`、`glm-cn`、`tencent`、`baidu`、`kilo-gateway`、`opencode-zen`、`gemini`、`ollama-cloud`）：这些确实是持续提供的免费访问，但受速率/并发限制。我们将其归类为 `recurring-uncapped`，并且**绝不将其计入总和**——用 `RPM × 24/7 × 30d` 计算会得出不切实际的上限（我们拒绝这种虚高估算）。列出它们是为了让你知道这些服务确实存在。
- **充值解锁提升：** 一次性少量充值可永久提高免费配额（OpenRouter：$10 → 1000 次请求/天 ≈ 每月增加 24M）。该数字单独报告，不计入稳定配额的主要统计值。
- **受资格限制的配额**（`eligibilityGate: "regional-identity"`）：仅在完成受地区约束的身份验证后才开放的真实持续配额（目前为中国大陆实名认证）。按照相同的资源池去重规则计入单独的数字（`gatedRecurringTokens`），绝不计入稳定配额的主要统计值。其类别（`freeType`）保持不变，因此路由行为也保持不变。
- **证据类别。** 规则如下：目录中的数字会在对应条目旁的 `// evidence:` 注释中引用来源——`public-page`（任何人都可以阅读的提供者页面）、`api-public`（提供者无需身份验证即可访问的端点，例如 NaraRouter 位于 router.bynara.id 的公开套餐端点），或 `console-verified <date> por <who>`（该数字仅在账户控制台内可见；注释会记录查看者、查看时间，以及说明该上限存在的公开页面）。当前状态：2026-09-02 重新审核的五个区块均带有此信息（`gemini`、`groq`、`mistral`、`ollama-cloud`、`nara`）；早于 2026-09-02 重新审核的条目，在更新前沿用此前的调研结果；任何**新增或变更**但没有证据注释的数字都属于错误。目前只有 `mistral` 经控制台验证。

## 为什么我们的数字小于其他聚合器

在这一领域，大多数“每月免费 token”数字都是各模型标注额度的总和。我们有意不采用这种算法：

- **每个共享额度池只计算一次。** Mistral 的免费计划为每个组织提供每月 1B 的统一额度；将它列在五个模型下并不会使其变成 5B。如果按模型累加，我们自己的目录会显示为 **~7.4B**（于 2026-09-03 重新计算；此数字不受 CI 检查约束——每当目录发生变化时都应重新测算）——标题显示 **~1.47B**，因为这才是每个提供者各使用一个账户时实际可以消耗的额度。
- **每日上限会换算，速率限制不会。** 有明确记录的每日 token 上限会按 `× 30` 换算；有明确记录的每日请求上限会按 `RPD × ~800 tokens × 30` 换算；如果提供者只公布每分钟请求数，则**不会**给出月度数字，而会列为_无上限_，且绝不会计入总和。将速率限制按 24/7 全天候使用来计算，正是我们拒绝采用的虚增方式。
- **需要区域身份验证的额度会单独列出**（`+~6M，需通过区域身份验证`），因为大多数读者无法使用这些额度。
- **注册赠送额度仅适用于首月**，并以第二个数字单独报告，绝不会混入稳定额度。
- **该数字由 CI 强制校验。** `npm run check:docs-counts` 会根据目录重新计算总额，并在此文件、README 或预算卡片中的数字与其不一致时使构建失败。

## OpenCode 免费版：客户端合约限制 (#14313)

无密钥的 `opencode` 提供者（公共端点 `https://opencode.ai/zen/v1`）会拒绝任何不符合 OpenCode 客户端合约的请求，并返回 **403 `FreeTierError`** 及提示语 _“OpenCode 的免费套餐只能在 OpenCode 内部使用”_。这是针对请求的拒绝（对于相同的请求结构，所有账户都会得到相同的判定），而不是模型封禁或连接冷却——OmniRoute 将其归类为 `project_route_error`，跳过模型锁定/冷却，并且（在合成的 `noauth` 路径上）暂停自动组合重新选择一小段 TTL 时间。请发送包含非空工具列表、`stream: true` 以及 OpenCode 会话/UA 请求头（`opencodeFreeTierContract.ts`）的请求，否则将收到 403。

## 术语表

| 术语                | 含义                                                    |
| ------------------- | ------------------------------------------------------- |
| **RPM / RPD / RPH** | 每分钟 / 每天 / 每小时的请求数                          |
| **TPM / TPD**       | 每分钟 / 每天的令牌数                                   |
| **明确公布的配额**  | 提供者公布的明确每日/每月令牌上限（可作为可靠预算依据） |
| **理论上限**        | `速率限制 × 24/7 × 30d`——最大值，而非已授予的预算       |
| **Neuron**          | Cloudflare 计算单位（约等于 1 个输出令牌）              |
