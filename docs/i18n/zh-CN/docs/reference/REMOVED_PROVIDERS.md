一些服务曾被集成到 OmniRoute 中，但后来因其运营者提出要求而被移除。本页面是这些移除事项的永久记录。其唯一目的是防止这些服务被意外重新引入：当贡献者发现旧分支、缓存的 npm tarball、已归档的议题，或收到“恢复提供者 X”的请求时，需要有一个明确说明**不要重新引入**的地方。

本页面**不是**已失效或停止运营的服务列表。这些服务记录在
[`FREE_TIERS.md`](FREE_TIERS.md)（“已移除/无免费层级”）中，如果服务恢复运营，则可以重新引入。以下条目只有在获得请求中所列运营者的书面许可后才能恢复，并且该许可必须链接在相应条目中。

## 政策

1. **服务运营者提出的下架请求应予执行，不进行协商。** OmniRoute 与任何上游服务均无关联。当服务运营者要求移除集成时，无论该集成是否使用官方 API，都必须将其移除。
2. **“已移除”是指从 OmniRoute 控制的所有界面和位置中移除。** 包括执行器、注册表条目、提供者 ID 和别名、模型列表、端点、环境变量、图标、仪表板卡片、生成的提供者参考文档、`FREE_TIERS.md`、环境参考文档、README 中的数量、`llm.txt` 镜像、专用测试和黄金快照、代码注释、CHANGELOG 条目（需有台账记录的核对项，参见 `config/release/changelog-reconciliations.json`）、GitHub Releases 发行说明、Wiki，以及主题与该提供者相关的 GitHub 议题、讨论和拉取请求（删除议题和讨论；重新命名拉取请求、替换其描述并锁定讨论串，因为 GitHub 无法删除拉取请求）。
3. **未经书面许可，绝不得重新引入本页面中的条目。** 这包括将 ID 或别名重新添加到任何提供者目录、将域名添加到执行器、接受“恢复”该提供者的贡献者 PR、将其添加到免费模型目录，或记录通过 OmniRoute 手动访问该服务的方法。关闭此类 PR 和议题时，应附上本页面的链接。
4. **保持条目精简。** 仅记录审查者识别重新引入行为所需的信息：标识符、域名、日期，以及执行移除操作的拉取请求。不要描述该集成的工作方式。
5. **回归防护测试为 `tests/unit/removed-providers-blocklist.test.ts`。** 如果以下任何标识符或域名再次出现在提供者目录、执行器映射或提供者注册表源代码中，该测试就会失败。在新增此处表格行的同一个 PR 中，将新的标识符添加到该测试。

## 添加条目

收到新的下架请求时：

1. 确认请求来自该服务的运营者（通过其支持邮箱或由其控制的域名），并私下保存该消息。
2. 按照政策第 2 项中的清单移除集成。对于无密钥提供者，以
   [#12440](https://github.com/diegosouzapw/OmniRoute/pull/12440) 为参考；对于存在已存储连接的
   API 密钥提供者，以 [#10210](https://github.com/diegosouzapw/OmniRoute/pull/10210) 为参考（需添加迁移）。
3. 在同一个 PR 中，向上表添加一行，并将标识符添加到
   `tests/unit/removed-providers-blocklist.test.ts`。
4. PR 合并后回复运营者，列明已移除的内容，以及 OmniRoute 无法更改的内容（已经发布的 npm 和 Docker 版本、git 历史记录、第三方分支）。
