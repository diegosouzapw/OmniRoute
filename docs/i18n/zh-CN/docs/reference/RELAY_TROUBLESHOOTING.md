中继（Vercel、Deno、Cloudflare）会在无服务器后端终止上游连接，使 OmniRoute 能够从稳定区域发出请求，同时将提供者 API 密钥保留在服务器端。本文介绍运维人员在生产环境中会遇到的两种故障模式，以及 OmniRoute 为每种故障提供的恢复路径。

## 中继身份验证信息的存储方式

当你通过 **设置 → 代理池 → 部署中继** 部署中继时，部署流程会将中继的身份验证令牌存储在代理的 `notes` JSON 字段中：

- 如果设置了 `STORAGE_ENCRYPTION_KEY`，令牌将以 `relayAuthEnc` 的形式写入
  （使用 AES 加密后静态存储）。
- 否则，它将以明文 `relayAuth` 的形式写入。

在请求时，`extractRelayAuth(notes)` 会返回其中存在的形式，因此中继在重启后仍可继续工作。

## 故障模式 1 — 密钥轮换后无法解密令牌

**症状：** 之前可以正常工作的中继，在环境或密钥管理器轮换
`STORAGE_ENCRYPTION_KEY` 后，现在返回上游 `401`/身份验证错误。存储的
`relayAuthEnc` 数据块无法再被解密，因此 `extractRelayAuth` 返回空字符串，
中继发送请求时不会携带身份验证信息。

**恢复方式 — 原地修复（无需重新部署）：**

1. 打开 **设置 → 代理池**。
2. 缺少身份验证信息的中继行会显示黄色的 `缺少身份验证信息` 徽章和
   **修复** 按钮。
3. 单击 **修复**。OmniRoute 会调用
   `POST /api/settings/proxies/[id]/repair-relay`，该接口会：
   - 使用**当前**密钥解密 `relayAuthEnc`，
   - 将明文 `relayAuth` 写回 `notes`，
   - 返回 `{ repaired: true, mode: "recovered" }`。

无需重新输入任何部署凭据，中继即可恢复提供服务。

仅当当前的 `STORAGE_ENCRYPTION_KEY` 仍能解密该数据块时，此方法才有效。
如果你在**未进行**迁移的情况下轮换了密钥，则该数据块无法恢复。

## 故障模式 2 — 无法恢复令牌（旧密钥已被轮换掉）

**症状：** 你单击了**修复**，并收到
`{ repaired: false, mode: "redeploy", status: 409 }`。

**恢复方式 — 重新部署：**

使用当前密钥无法恢复已存储的令牌。请从最初使用的同一模态窗口中重新部署中继
（**部署中继**菜单 → Vercel / Deno / Cloudflare）。部署流程会写入一个新令牌
（使用当前密钥加密），随后该行的 `缺少身份验证信息` 徽章会消失。

在 UI 中，如果令牌无法恢复，**修复**按钮本身会触发重新部署模态窗口，
因此你无需手动查找该窗口。

## 故障模式 3 — 中继可访问但运行状况异常

**症状：** 代理测试（`速度`按钮）显示中继在线，但请求仍会间歇性失败。

检查 OmniRoute 自动测试探针返回的中继感知标头
（请参阅**设置 → 代理池**以及 `relayTested` / `relayAlive` 计数器）：

- `x-relay-url` — 响应请求的中继后端。
- `x-relay-mode` — 该请求使用的模式：`ts` | `bifrost` | `auto`。
- `x-relay-attempts` — 成功之前尝试了多少次中继跃点。
- `x-relay-fallback` — 当请求从首选后端回退到 TypeScript 中继时为 `true`。

如果 `x-relay-fallback` 比率较高且 `relayAlive` 较低，则意味着 sidecar
后端运行状况异常，你应修复该后端，或将中继后端策略切换为 `ts`
（请参阅 `RELAY_BACKEND_STRATEGY.md`）。

## API 参考

| 方法   | 路径                                      | 请求体                  | 成功                                                                                                                 | 失败                                                                                    |
| ------ | ----------------------------------------- | ----------------------- | -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `POST` | `/api/settings/proxies/[id]/repair-relay` | `{ "id": "<proxyId>" }` | 重新派生时返回 `200 { repaired: true, mode: "recovered" }`；已存在明文时返回 `200 { repaired: false, mode: "noop" }` | 无法恢复时返回 `409 { mode: "redeploy" }`；不是中继类型时返回 `400`；未找到时返回 `404` |

列表路由 `GET /api/settings/proxies` 会为每个项目附加一个不含密钥的
`relayInfo: { isRelay, authMissing, repairMode }`，以便仪表板在不暴露令牌的情况下
呈现修复操作入口。
