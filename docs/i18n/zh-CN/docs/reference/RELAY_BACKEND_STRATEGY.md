## 摘要

OmniRoute 现在为 `/api/v1/relay/chat/completions` 支持三种中继模式：

- `ts`：在进程内使用 TypeScript 中继。
- `bifrost`：强制使用 Bifrost 网关。
- `auto`：优先使用 Bifrost；失败时回退到 TypeScript。

当请求速率较高时（每天处理大量 token、吞吐量近乎恒定），最佳策略是保持回退路径明确且快速，确保热路径永远不会因失效的 sidecar 而阻塞。

## 模式行为

- `ts`
  - 运维复杂度最低。
  - 所有路由和验证均在 Node 中运行。
  - 可用性不依赖 sidecar。
- `bifrost`
  - 强制所有请求通过 sidecar 网关。
  - 不会自动回退。
  - 仅适用于能够保证 sidecar 健康状态和延迟的情况。
- `auto`
  - 当 sidecar 可访问且已启用时使用 sidecar。
  - 尝试失败会触发回退标头，并将流量交还给 TS，从而确保请求成功时间有界。
  - 当正常运行时间比严格的仅使用 sidecar 路由更重要时，此模式是最安全的生产环境选择。

## 当前的 9router 与 CLIPROXYAPI 对比

9router 和 CLIPROXYAPI 都是集成组件，过去用于为上游提供者公开兼容路径。

- 9router 是用于上游编排和兼容行为的嵌入式路径。
- CLIPROXYAPI 是用于 CLI / SDK 风格流量的代理 API 桥接器。
- 当需要专用的类 sidecar 跳转和低延迟本地分发时，Bifrost 正在被稳定化为外置路径。

如果你目前正在比较 9router/CLIPROXYAPI：

- 在交接之前，将请求签名、允许列表检查和 DB 策略门控保留在 API 路由中。
- 如果工作流需要严格的 sidecar 行为和更低的单请求差异，请使用 `OMNIROUTE_RELAY_BACKEND=bifrost`。
- 如果需要 sidecar 韧性，并在故障情况下实现平稳降级，请使用 `OMNIROUTE_RELAY_BACKEND=auto`。

## 后端边界契约

稳定的产品边界是 OmniRoute 中继 API，而不是仪表板实现。Next.js 仪表板可以安装、配置和监控本地服务，但请求路由应通过中继 API 进入，并在该边界之后进行交接。

长期后端选择：

- 将 TypeScript 中继保留为进程内策略和回退路径。在交接给任何后端之前，身份验证、允许列表、请求规范化、计量和安全检查仍在此处执行。
- 当部署需要更低的路由差异、集中式提供者轮换，或跨多个 OmniRoute 副本进行横向扩展时，使用 Bifrost 作为首选的高吞吐量 Tier-1 sidecar。
- 将 9router 和 CLIPROXYAPI 保留为嵌入式兼容服务。它们作为受监控的本地进程运行，并在需要其提供者/CLI 行为作为适配器时发挥作用，但不应成为默认的 Tier-1 路由引擎。
- 不要让仪表板将任意服务 URL 传入热路径。UI 提供的 URL 是配置输入；路由代码应根据服务器端设置和监控器状态，解析已注册且通过健康检查的后端。
- 目前应优先为受监控服务使用环回 HTTP，因为托管进程已经公开了 HTTP 兼容 API，路由守卫可以审计该边界，并且请求日志中可以看到失败/回退行为。只有当未来的 SDK 或套接字传输能在不削弱隔离或回退语义的前提下，显著降低 p99 路由延迟时，才值得添加。

因此，对于超高吞吐量部署，默认选择是启用 Bifrost 的 `auto`：在热路径上使用 Go sidecar，同时保留 TypeScript 回退路径以确保成功率。仅当严格的仅使用 sidecar 行为比平稳降级更重要时，才使用 `bifrost`。

## 高吞吐量指南

对于持续的高 RPM/RPS 和严格的成功率 SLO：

1. 使用 `auto`，并设置合理的冷却时间和失败遥测。
2. 将上游验证和 API 密钥检查保留在 TypeScript 路由边界上。
3. 启用明确的标头/计数器，使告警系统能够看到回退频率和原因。
4. 调整 sidecar 超时设置，使其快速失败，而不是无限期等待。
5. 保持服务自动重启和健康遥测循环正常运行，确保回退确实只是例外情况。

## 建议的基准配置

- `OMNIROUTE_RELAY_BACKEND=auto`
- `BIFROST_ENABLED=1`
- 在路由处理程序中保持启用 API 密钥、允许列表、清理器和速率限制检查（这些检查始终在向下游转发之前运行）。
- 从反向代理和请求日志中导出回退指标，确保能够在一分钟内发现 sidecar 中断。

## 提供者插件契约

Sidecar 应通过 JSON 安全的提供者插件清单导入提供者元数据，而不是依赖 TypeScript 执行器内部实现。有关 sidecar 适用性契约和迁移阶段，请参阅[提供者插件清单](./PROVIDER_PLUGIN_MANIFEST.md)。
