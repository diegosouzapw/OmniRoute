`devin-cli-agentic` 允许真正的 Claude Code 运行时使用 OmniRoute 的本地 Anthropic
Messages 端点，同时由官方 Devin CLI 通过 ACP stdio 提供模型响应。它不会
修改现有的 Anthropic、Claude OAuth、Claude Web 或 `devin-cli` 提供者。

> **当前状态：固定使用 Claude Code `2.1.258`；最近一次离线和在线验证记录
> 基于 `2.1.220`。** 固定使用 `2.1.220` 时，已通过 Devin CLI
> `3000.2.17` 和模型 `swe-1-7-lightning` 完成三个相互隔离的场景；最后一次在线运行验证了由客户端控制的 `Read`、
> `Edit` 和 `Bash` 轮次、成功的 `npm test` 结果、项目命令与技能
> 发现、仅限 Devin 的路由，以及 Claude 零出站流量。随后固定版本提升至 `2.1.258`
> （OmniRoute 的 Claude 身份所模拟的 CLI 代际，也是首个原生提供
> Fable 5.1 层级的版本）。在新固定版本上，已基于固定的基础镜像验证安装层和 `claude --version`，
> 并且桥接单元测试套件、`compose config` 和
> 静态隔离证明均已通过——但尚未重新运行离线模拟场景和在线三场景
> 测试套件。在依赖此固定版本的桥接之前，请重新运行这些测试（参见“更新固定工具”）。

## 架构

```text
Claude Code 2.1.258（隔离的非 root Linux 容器）
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic（Claude 格式、无身份验证的提供者）
  -> devin acp --agent-type summarizer（官方 ACP stdio，无 Devin 工具）
  -> 专用 devin-auth 卷中的 Devin 账户
```

官方 CLI 的默认 ACP 代理可以执行自己的工具，因此此桥接不使用
它。桥接会启动固定的 `summarizer` ACP 代理，该代理的官方 CLI 模式不提供工具，并将序列化后的 Anthropic 请求构造为执行轨迹。当需要由 Claude 执行另一个
操作时，响应必须包含且仅包含一个客户端工具信封。任何 ACP
`tool_call` 或 `tool_call_update` 都会在响应被报告为
成功之前遭到拒绝。

`open-sse/executors/devin-agentic/serializer.ts` 中的序列化器会保留 `system`、
`text`、`tool_use`、`tool_result`、`thinking`、`redacted_thinking`、`tool_choice` 以及
Claude Code 提供的工具。对于图像和未知块会明确报错。大型工具结果
会使用可见的截断标记。

解析器接受每个模型轮次中一个独立的 `<tool>{...}</tool>` 信封。它会根据请求的工具列表
检查名称，依据该工具的 JSON
Schema 验证参数，拒绝叙述与操作混合的内容，并允许一次有界修复。随后，Claude Code
会在本地执行生成的 Anthropic `tool_use`，并通过
OmniRoute 发回 `tool_result`。

## 隔离与威胁模型

主机上的 Claude 安装、账户和配置不在范围内，并被视为
禁止访问的资源。Compose 服务：

- 以 UID/GID `10001:10001` 运行，使用只读根文件系统、移除 capabilities，并启用
  `no-new-privileges`；
- 使用私有 `/home/bridge`、专用 Claude 配置卷、隔离的 OmniRoute 数据
  以及单独的 `devin-auth` 卷；
- 仅挂载可丢弃的 `.sandbox` 工作区/证据；
- 不挂载主目录、Keychain、SSH、云凭据或 Docker 套接字；
- 构造显式环境，并移除 Anthropic API/OAuth/路由变量；
- 仅将 Claude Code 推理定向到 `http://omniroute:20128`，并使用仅限本地的密钥。

离线配置使用内部网络。在在线配置中，OmniRoute 仅通过 `network-guard` 访问
官方 Devin 端点；与无关目标的连接会被拒绝。
Claude Code 使用独立的拒绝所有出站流量防护，并且只能通过 `NO_PROXY` 访问本地 OmniRoute
服务。防护审计文件仅由对应的防护进程挂载。脚本会验证文件所有权、模式、链接数量以及每项决策，然后才导出
不含令牌的证据。

单独运行隔离证明：

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

它会验证拓扑、命名挂载、非 root/只读设置、显式本地路由、
不存在敏感环境变量、不存在 Docker 套接字、对
`api.anthropic.com` 和 `claude.ai` 的访问已被阻止、仅选择 Devin 提供者，以及
ACP 后端不可用时会明确失败。

## 首次设置和常规使用

构建固定版本的镜像：

```bash
./scripts/devin-bridge/build
```

仅对隔离的 Devin 卷进行身份验证：

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

登录命令使用专为远程/容器环境设计的官方手动令牌流程。令牌值会直接输入到 CLI 提示符中；它不会作为进程参数传递、写入 Git，也不会从主机复制。

启动隔离的 Claude Code 运行时：

```bash
./scripts/devin-bridge/launch
```

`launch` 会在启动容器化的 Claude Code 之前，重新检查隔离性、Devin 身份验证和模型发现。它绝不会运行主机上的 Claude 可执行文件。可以在 `.env.devin-bridge` 中设置模型别名；每个配置值都必须保留 `devin-cli-agentic/` 前缀。

## 验证命令

可复现的离线路径不需要 Devin 账户，并且运行时无需访问互联网：

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

需要身份验证并由用户选择启用的实时路径为：

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

实时运行器会在不同场景之间等待，以避免突发开启 ACP 会话，并验证结构化的 Claude 流事件，而不是采信文本声明。它的三个场景用于证明：

1. 直接读取项目并分析缺陷；
2. 执行一次真实的 `Edit`、一次由客户端负责的 `Bash` `npm test`，并获得终态结果；
3. 发现 `/bridge-check` 和 `bridge-proof`、读取项目、再次成功执行由客户端负责的 `npm test`，并在没有待处理工作的情况下完成。

最终门禁还会检查 Devin 网络审计，并要求 Claude 出站流量审计保持为空。

## 更新固定版本的工具

镜像在 `docker/devin-bridge/Dockerfile` 中固定了 Node、Claude Code 和 Devin CLI 的版本。更新步骤如下：

1. 更改明确指定的版本；
2. 将两个架构特定的 Devin 归档文件校验和替换为官方构件对应的值；
3. 重新构建并运行所有离线验证命令；
4. 确认镜像内的版本；
5. 重新运行经过身份验证的三场景实时测试套件。

不要在主机上全局安装任一 CLI，也不要使用未经验证的下载来替代校验和验证。

## 诊断和清理

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  显示本地路由信息和经过清理的执行器错误。
- `.sandbox/evidence/mock-acp.jsonl` 记录确定性的模拟 ACP 操作。
- `.sandbox/evidence/claude-stream.jsonl` 记录真实的 Claude Code 离线运行。
- `.sandbox/evidence/live-*.jsonl` 记录三个已验证的实时流。
- `.sandbox/evidence/egress.jsonl` 和 `.sandbox/evidence/claude-egress.jsonl` 是经过验证且不含令牌的防护审计副本。

停止归桥接器所有的容器和网络，同时保留登录/配置卷：

```bash
./scripts/devin-bridge/clean
```

移除归桥接器所有的完整环境，包括命名卷：

```bash
./scripts/devin-bridge/clean --all
```

## 限制

- 该桥接器依赖固定的无工具 `summarizer` 角色，因为 Devin CLI `3000.2.17` 未提供中立的无工具 ACP 代理。适配器会对摘要式中间响应进行补偿，但一次有界修复仍可能明确失败。
- 实时 ACP 调用可能返回暂时性的 `502`/`504` 响应。测试工具会将各场景错开执行；持续性故障仍会以故障关闭方式处理，且绝不会选择其他提供者。
- ACP 上下文会根据每个 Anthropic 请求重新构建；不存在进程/会话亲和性。
- 每个模型响应支持一次工具调用；并行调用会被拒绝。
- 明确不支持图像。不会声明支持视觉、思维输出、effort 控制和 1M 上下文窗口。
- SSE 使用有效的 Anthropic 生命周期事件，但会在收集完有界 ACP 轮次后才发送；ACP 数据块不会被增量转发。
