> **სიმართლის წყარო:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/` და
> `src/app/(dashboard)/dashboard/plugins/`
> **ბოლო განახლება:** 2026-06-28 — v3.8.40

OmniRoute-ს მოჰყვება WordPress-ის სტილის პლაგინების სისტემა. პლაგინები თვითკმარი
დირექტორიებია — თითოეულს აქვს `plugin.json` მანიფესტი და შესასვლელი ფაილი — რომლებიც
ერთვებიან მოთხოვნების დამუშავების კონვეიერში (`onRequest` / `onResponse` / `onError`) და
სასიცოცხლო ციკლის მოვლენებში (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`).

**პლაგინების მარკეტპლეისი** ამ სისტემის თავზე არსებული აღმოჩენის შრეა. ის
გთავაზობთ დასაყენებელი პლაგინების დათვალიერებად კატალოგს. ნაგულისხმევად კატალოგი
მცირე, ჩაშენებული საწყისი რეესტრია; ოპერატორს შეუძლია მიუთითოს მორგებული დისტანციური
რეესტრის URL, რა შემთხვევაშიც ამოღების ოპერაცია დაცულია DNS-რეზოლვინგიანი SSRF დამცავით
(იხილეთ [უსაფრთხოება](#security)).

პლაგინების ყველა მარშრუტი **მხოლოდ loopback-ისთვისაა** (დონე 1 — `LOCAL_ONLY`): პლაგინები
შვილობილ პროცესებში ტვირთავენ და ასრულებენ კოდს, ამიტომ მარშრუტები მიუწვდომელია
არა-loopback წყაროდან, ავტორიზაციის მიუხედავად. იხილეთ
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md).

## როგორ მუშაობს ყველაფერი ერთად

```
მართვის პანელი (/dashboard/plugins)
  ├─ ჩანართი „დაყენებული“ → GET /api/plugins            (listPlugins)
  │                        POST /api/plugins/scan      (pluginManager.scan)
  │                        POST /api/plugins/{name}/activate|deactivate
  │                        DELETE /api/plugins/{name}   (დეინსტალაცია)
  └─ ჩანართი „მარკეტპლეისი“ → GET /api/plugins/marketplace
                                → listMarketplacePlugins()
                                  ├─ მორგებული URL არ არის → ჩაშენებული SEED_REGISTRY
                                  └─ მორგებული URL → isSafeMarketplaceUrl() SSRF დამცავი
                                                   → safeOutboundFetch(guard:"public-only")
```

- **რეესტრის შრე** — `src/lib/plugins/marketplace.ts`: ჩამოთვლის / ეძებს
  კატალოგში და ნებისმიერი შეცდომის შემთხვევაში საწყის რეესტრზე გადადის.
- **სასიცოცხლო ციკლის შრე** — `src/lib/plugins/manager.ts` (`pluginManager` singleton):
  დაყენება, განახლება, გააქტიურება, დეაქტივაცია, დეინსტალაცია, სკანირება, გაშვებისას ჩატვირთვა.
- **მანიფესტის შრე** — `src/lib/plugins/manifest.ts`: Zod სქემა + ნაგულისხმევი მნიშვნელობები
  `plugin.json`-ისთვის.
- **სკანერი** — `src/lib/plugins/scanner.ts`: დისკზე, პლაგინების
  დირექტორიაში, აღმოაჩენს პლაგინებს.
- **ჩამტვირთავი** — `src/lib/plugins/loader.ts`: თითოეულ პლაგინს იზოლირებულ
  შვილობილ პროცესში უშვებს და IPC-ის მეშვეობით შუამავლობს ჰუკების გამოძახებებს.

## მარკეტპლეისის კატალოგი

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) აბრუნებს
`MarketplaceEntry` ობიექტების სიას:

| ველი          | ტიპი     | შენიშვნები                                      |
| ------------- | -------- | ----------------------------------------------- |
| `name`        | string   | პლაგინის სახელი kebab-case ფორმატში             |
| `version`     | string   | semver                                          |
| `description` | string   | მოკლე შეჯამება                                  |
| `author`      | string   | ავტორი / ორგანიზაცია                            |
| `license`     | string   | SPDX-ის სტილის ლიცენზიის id                     |
| `downloadUrl` | string   | წყაროს ჩამოტვირთვის URL (შეიძლება ცარიელი იყოს) |
| `repository`  | string?  | რეპოზიტორიის არასავალდებულო URL                 |
| `tags`        | string[] | ძიების/ფილტრაციის ტეგები                        |
| `downloads`   | number   | ჩამოტვირთვების რაოდენობა                        |
| `rating`      | number   | 0–5                                             |
| `verified`    | boolean  | მონიშნულია თუ არა ჩანაწერი ვერიფიცირებულად      |
| `lastUpdated` | string   | ISO-ს მსგავსი თარიღის სტრიქონი                  |

როდესაც მორგებული რეესტრის URL კონფიგურირებული არ არის, კატალოგად გამოიყენება ჩაშენებული
`SEED_REGISTRY` (ამჟამად `request-logger`, `rate-limiter`, `cost-tracker` და
`theme-manager`). საწყისი რეესტრი ყოველთვის ხელმისაწვდომია — თუ კონფიგურირებული დისტანციური
რეესტრი მიუწვდომელია, აბრუნებს `200`-ისგან განსხვავებულ სტატუსს ან დაუდგენელი
ფორმატის სხეულს, `listMarketplacePlugins()` ჟურნალში წერს გაფრთხილებას და საწყის სიაზე გადადის.

> შენიშვნა: მარკეტპლეისის **კატალოგი** (დათვალიერება/ძიება) სრულად არის დაკავშირებული, მაგრამ
> კატალოგიდან მარკეტპლეისის **ერთი დაწკაპუნებით დაყენება** ჯერ არ არის განხორციელებული —
> მარკეტპლეისის ჩანაწერზე მართვის პანელის ღილაკი „დაყენება“ ამჟამად აჩვენებს
> შეტყობინებას „მალე იქნება“. ამჟამად დაყენება ხორციელდება ლოკალური ბილიკიდან დაყენების
> პროცესით (`POST /api/plugins`) და დისკზე აღმოჩენით (`POST /api/plugins/scan`).

## REST API

ყველა საბოლოო წერტილი მოითხოვს მართვის ავტორიზაციას (`requireManagementAuth`) **და**
ხელმისაწვდომია მხოლოდ loopback-იდან — `/api/plugins` და `/api/plugins/` ჩამოთვლილია
`LOCAL_ONLY_API_PREFIXES`-ში (`src/server/authz/routeGuard.ts`).

| საბოლოო წერტილი                  | მეთოდი | აღწერა                                                                    |
| -------------------------------- | ------ | ------------------------------------------------------------------------- |
| `/api/plugins`                   | GET    | დაინსტალირებული პლაგინების სია (არასავალდებულო `?status=` ფილტრი)         |
| `/api/plugins`                   | POST   | პლაგინის ინსტალაცია აბსოლუტური ლოკალური ბილიკიდან                         |
| `/api/plugins/scan`              | POST   | პლაგინების დირექტორიის სკანირება და ახალი პლაგინების რეგისტრაცია          |
| `/api/plugins/marketplace`       | GET    | მარკეტპლეისის კატალოგის ჩანაწერების სია                                   |
| `/api/plugins/[name]`            | GET    | დაინსტალირებული პლაგინის დეტალების მიღება                                 |
| `/api/plugins/[name]`            | DELETE | პლაგინის დეინსტალაცია                                                     |
| `/api/plugins/[name]/activate`   | POST   | გააქტიურება (ჩატვირთვა + ჰუკების რეგისტრაცია)                             |
| `/api/plugins/[name]/deactivate` | POST   | დეაქტივაცია (`onDeactivate`-ის გამოძახება, ჰუკების რეგისტრაციის გაუქმება) |
| `/api/plugins/[name]/config`     | GET    | პლაგინის კონფიგურაციისა და კონფიგურაციის სქემის მიღება                    |
| `/api/plugins/[name]/config`     | PUT    | პლაგინის კონფიგურაციის განახლება (სქემასთან ვალიდაციით)                   |

`GET /api/plugins`-ის `status` ფილტრი იღებს ერთ-ერთ მნიშვნელობას:
`installed` / `active` / `inactive` / `error`. არასწორი მნიშვნელობა აბრუნებს `400`-ს.

### დაინსტალირებული პლაგინების სია

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### ინსტალაცია ლოკალური ბილიკიდან

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` უნდა იყოს **აბსოლუტური** და არ უნდა შეიცავდეს `..` გადასვლის სეგმენტებს ან
null-ბაიტებს (ამას Zod უზრუნველყოფს). საწყისი დირექტორია უნდა შეიცავდეს მართებულ
`plugin.json`-ს (ან მისი მშობელი დირექტორია უნდა იყოს). წარმატების შემთხვევაში პასუხია
`201`, დაინსტალირებული პლაგინის ჩანაწერთან ერთად.

### მარკეტპლეისის დათვალიერება

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### პლაგინის კონფიგურაციის განახლება

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` თითოეულ გადაცემულ მნიშვნელობას ამოწმებს პლაგინის
`configSchema`-სთან (რომელიც მანიფესტშია გამოცხადებული): `number` ველები ითვალისწინებს
`min`/`max`-ს, ხოლო `select` ველები უნდა ემთხვეოდეს გამოცხადებულ `enum`-ს. სქემაში
არარსებული გასაღებები დაშვებულია.

## კონფიგურაცია

### პლაგინების დირექტორია

პლაგინები ინახება OmniRoute-ის მონაცემთა დირექტორიაში:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (ან ის, რაზეც manifest.main მიუთითებს)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) ამ დირექტორიას სამ
ეტაპად განსაზღვრავს:

1. **`OMNIROUTE_PLUGINS_DIR`**, თუ დაყენებულია — გამოიყენება უცვლელად, მიუხედავად იმისა,
   თუ რას მიუთითებს `HOME`. ეს არის Docker/K8s-ის ცხადი პარამეტრი, სადაც პლაგინების ხე
   bind-mount-ით თავსდება ბილიკზე, რომელსაც, როგორც წესი, კონტეინერის სახლის
   დირექტორიასთან საერთო არაფერი აქვს (#11827).
2. `<home>/.omniroute/plugins`, სადაც `<home>` მიიღება `HOME` / `USERPROFILE`
   გარემოს ცვლადებიდან.
3. `/tmp/.omniroute/plugins`, როდესაც პროცესი საერთოდ არ ექსპორტირებს სახლის
   დირექტორიას.

განსაზღვრული დირექტორია გაშვებისას ერთხელ იწერება ჟურნალში, როგორც
`scanner.dir_resolved`, იმ წყაროს მითითებით, რომელმაც უპირატესობა მიიღო
(`OMNIROUTE_PLUGINS_DIR`, `home` ან `no-home-fallback`) — ამიტომ გამოსახულება,
რომელიც შეუმჩნევლად გადადის მე-3 ეტაპზე, ამის შესახებ პირდაპირ იტყობინება და მხოლოდ
პლაგინების ცარიელ სიას არ აჩვენებს. `POST /api/plugins/scan` იქ აღმოაჩენს ყველა
ქვედირექტორიას, რომელიც მართებულ `plugin.json`-ს შეიცავს, და არეგისტრირებს მას;
იგივე დირექტორიაა ძირეული დირექტორია, რომელშიც `pluginManager.install()` პლაგინებს
აკოპირებს, ამიტომ ჩანაცვლება აღმოჩენასა და ინსტალაციას ერთად გადაადგილებს.

> **`OMNIROUTE_PLUGINS_DIR` არ არის `OMNIROUTE_PLUGIN_PATH`.** ამ უკანასკნელს მხოლოდ
> CLI-ის ბრძანების პლაგინების ჩამტვირთავი (`bin/cli/plugins.mjs`) კითხულობს იმ
> `omniroute-cmd-*` npm პაკეტების მოსაძებნად, რომლებიც `omniroute`-ს ქვებრძანებებს
> ამატებს — ის აქ აღწერილ შესრულების დროის სკანერზე გავლენას არ ახდენს. ამ მხარის
> შესახებ იხილეთ [PLUGINS.md](./PLUGINS.md).

### მარკეტპლეისის რეესტრის მორგებული URL

მარკეტპლეისის კატალოგის წყარო იკითხება `pluginMarketplaceUrl` პარამეტრიდან
(`src/lib/plugins/marketplace.ts` კითხულობს `settings.pluginMarketplaceUrl`-ს). როდესაც
ის დაყენებულია `http(s)` URL-ზე, `listMarketplacePlugins()` იღებს მონაცემებს ამ
URL-იდან და იღებს ან ზედა დონის ჩანაწერების JSON მასივს, ან ობიექტს `plugins`
მასივით; ჩანაწერები, რომლებსაც სტრიქონული `name` არ აქვს, იფილტრება. როდესაც
პარამეტრი დაყენებული არ არის (ან მონაცემების მიღება ვერ გადის SSRF დაცვას / აბრუნებს
არასწორ პასუხს), გამოიყენება ჩაშენებული საწყისი რეესტრი.

მართვის პანელის ჩანართი „Marketplace“ ამ URL-ისთვის ველს აჩვენებს (რომელიც
`GET /api/settings`-იდან იკითხება).

> განხორციელების შენიშვნა: მართვის პანელში მოქმედება „Save“
> `pluginMarketplaceUrl`-ს აგზავნის `PATCH /api/settings`-ზე. ამ ტექსტის დაწერის
> მომენტისთვის ეს გასაღები `updateSettingsSchema`-ში გამოცხადებული არ არის
> (`src/shared/validation/settingsSchemas.ts`), ამიტომ მასზე დაყრდნობამდე თქვენს
> გამოშვებაში მონაცემთა შენახვა გადაამოწმეთ — **წაკითხვის** გზა (`getSettings()` →
> `listMarketplacePlugins()`) გასაღებს ითვალისწინებს, როგორც კი ის პარამეტრების
> საცავში აღმოჩნდება.

## უსაფრთხოება

### მარშრუტის დონე — მხოლოდ loopback

პლაგინები კოდს წარმოქმნილ შვილობილ პროცესებში ასრულებენ, ამიტომ `/api/plugins`-ის
მთელი ზედაპირი კლასიფიცირებულია როგორც `LOCAL_ONLY` (დონე 1). loopback-ის შეზღუდვა
უპირობოდ მოქმედებს ავთენტიფიკაციის **ნებისმიერ** შემოწმებამდე, ამიტომ ტუნელის
გავლით ჰოსტამდე მიღწეული გაჟონილი მართვის ტოკენიც კი ვერ შეძლებს პლაგინის
დაყენებას, გააქტიურებას ან წაშლას.
იხილეთ [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) და
მკაცრი წესები #15 / #17.

### Marketplace-ის რეესტრის SSRF დაცვა

მორგებული რეესტრის URL არის კონფიგურაცია, რომელზეც თავდამსხმელს შეუძლია გავლენის
მოხდენა, ამიტომ მის მიღებამდე `listMarketplacePlugins()` მას ორ შრეში ამოწმებს:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - უარყოფს ყველაფერს, რაც არ არის `http:` / `https:`.
   - უარყოფს ლიტერალურ კერძო/loopback/link-local/ULA ჰოსტებს (როგორც IPv4-ს,
     ისე IPv6-ს, IPv4-mapped მისამართების ჩათვლით) კანონიკური `isPrivateHost`-ის
     (`src/shared/network/outboundUrlGuard.ts`) მეშვეობით.
   - ამუშავებს **როგორც** `A`, ისე `AAAA` ჩანაწერებს და უარყოფს, თუ
     გადაწყვეტილი მისამართებიდან **რომელიმე** კერძოა — რითაც იხურება
     საჯარო-ჰოსტის-სახელი → კერძო-IP გვერდის ავლის გზა.
   - **დახურულად იჭრება**: DNS-ის გადაწყვეტის შეცდომის შემთხვევაში URL უარყოფილია.
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`**
   (`src/shared/network/safeOutboundFetch.ts`): მიღების მომენტში ხელახლა იყენებს
   მხოლოდ საჯარო URL-ების დაცვას და **ბლოკავს გადამისამართებებს** (საჯარო →
   კერძო `30x` გადასვლა შეუძლებელია).

თუ URL რომელიმე შრის შემოწმებას ვერ გაივლის, მოთხოვნა არ წყდება — marketplace
უხმაუროდ უბრუნდება ჩაშენებულ საწყის რეესტრს და ჟურნალში გაფრთხილებას წერს.

> ეს დაცვა PR #3774-ში სპეციალურად გამკაცრდა, რათა დამუშავდეს A + AAAA და
> მხოლოდ IPv4-ის შემოწმების ნაცვლად გამოყენებული იყოს კანონიკური
> `isPrivateHost`.

### პლაგინის შესრულების იზოლაცია

- **პროცესის იზოლაცია** — `loadPlugin()` (`src/lib/plugins/loader.ts`) თითოეულ
  პლაგინს ცალკე Node.js-ის შვილობილ პროცესში უშვებს და IPC-ის საშუალებით
  უკავშირდება. ჰუკების გამოძახებებს აქვს დროის ლიმიტი `SIGTERM` → `SIGKILL`
  ესკალაციით.
- **გარემოს ცვლადების დასაშვები სია** — შვილობილი პროცესი იღებს მხოლოდ
  დასაშვებ სიაში შეტანილ გარემოს ცვლადებს; უფრო ფართო ნაკრები მხოლოდ მაშინ
  ენიჭება, როდესაც მანიფესტი `env` ნებართვას ითხოვს.
- **გზის საზღვრებში მოქცევა** — დაყენების/განახლების/წაშლის ოპერაციები ნებისმიერი
  კოპირების ან რეკურსიული წაშლის წინ ამოწმებს, რომ პლაგინის დირექტორია და
  `manifest.main` მართული პლაგინების ძირეული დირექტორიის **შიგნით** გადაწყდეს
  (იცავს შეცვლილი DB გზებისა და `manifest.main`-ში `../` გადასვლისგან).
  გააქტიურებისას სიმბოლური ბმულები `realpath`-ის მეშვეობით მუშავდება და სისტემა
  უარს ამბობს ისეთი შესვლის წერტილის ჩატვირთვაზე, რომელიც პლაგინის დირექტორიის
  ფარგლებს სცდება.
- **არასავალდებულო მთლიანობის ფიქსაცია** — მანიფესტს შეუძლია გამოაცხადოს
  `integrity` (`sha256-<base64>`, SRI ფორმატი) ველი. მისი არსებობისას ჩამტვირთავი
  ჩატვირთვის დროს ამოწმებს შესვლის ფაილის ჰეშს და შეუსაბამობის შემთხვევაში
  გააქტიურებაზე უარს ამბობს. ეს არის სურვილისამებრ გამოსაყენებელი ცვლილებების
  აღმოჩენის მექანიზმი და **არა** უსაფრთხოების საზღვარი — რეალური საზღვრებია
  მხოლოდ loopback-ზე დაშვებული მარშრუტიზაცია და ნებართვების მოდელი.

| `author`           | string?   | ≤ 200 სიმბოლო                                                                |

| `integrity`        | string?   | არასავალდებულო `sha256-<base64>` შესვლის ფაილის ფიქსაცია                     |

## სასიცოცხლო ციკლის მიმდინარეობა

```
ინსტალაცია (POST /api/plugins, გზა)
  → მანიფესტის სკანირება/ვალიდაცია → დროებით საცავში კოპირება → შემოწმება, რომ main დირექტორიის შიგნითაა
  → ატომარული სახელის გადარქმევა ~/.omniroute/plugins/<name>-ში → ჩანაწერის დამატება DB-ში
  → onInstall-ის გამოძახება → თუ enabledByDefault: აქტივაცია

აქტივაცია (POST /api/plugins/{name}/activate)
  → realpath-ის მოქცევის შემოწმება → loadPlugin() (შვილობილი პროცესის გაშვება)
  → დეკლარირებული ჰუკების რეგისტრაცია → status = "active" → onActivate-ის გამოძახება

დეაქტივაცია (POST /api/plugins/{name}/deactivate)
  → onDeactivate-ის გამოძახება (რეგისტრაციის გაუქმებამდე) → ჰუკების რეგისტრაციის გაუქმება
  → შვილობილი პროცესის შეწყვეტა → status = "inactive"

დეინსტალაცია (DELETE /api/plugins/{name})
  → თუ აქტიურია, დეაქტივაცია → onUninstall-ის გამოძახება
  → პლაგინის დირექტორიის მოქცევის შემოწმებით რეკურსიული წაშლა → ჩანაწერის წაშლა DB-დან
```

`install`-ის ხელახლა გაშვება დირექტორიაზე, რომლის მანიფესტის ვერსია დაინსტალირებულ ვერსიაზე **მკაცრად
უფრო ახალია**, ავტომატურად ასრულებს განახლებას (სუფთა ხელახალი ინსტალაცია; კონფიგურაცია
ნაგულისხმევ მნიშვნელობებზე ბრუნდება). იგივე ან უფრო ძველი ვერსია უარყოფილი იქნება.

## მონაცემთა ბაზა

ცხრილი `plugins` (მიგრაცია `076_create_plugins.sql`):

| სვეტი           | ტიპი    | შენიშვნები                                                      |
| --------------- | ------- | --------------------------------------------------------------- |
| `id`            | TEXT PK | UUID                                                            |
| `name`          | TEXT    | უნიკალური                                                       |
| `version`       | TEXT    | semver; ნაგულისხმევად `1.0.0`                                   |
| `description`   | TEXT    | არასავალდებულო                                                  |
| `author`        | TEXT    | არასავალდებულო                                                  |
| `license`       | TEXT    | ნაგულისხმევად `MIT`                                             |
| `main`          | TEXT    | შესასვლელი ფაილი; ნაგულისხმევად `index.js`                      |
| `source`        | TEXT    | ნაგულისხმევად `local`                                           |
| `tags`          | TEXT    | JSON მასივი; ნაგულისხმევად `[]`                                 |
| `status`        | TEXT    | `installed` \| `active` \| `inactive` \| `error`                |
| `enabled`       | INT     | 0/1; ნაგულისხმევად 0                                            |
| `manifest`      | TEXT    | სრული მანიფესტი JSON ფორმატში                                   |
| `config`        | TEXT    | JSON; ნაგულისხმევად `{}`                                        |
| `config_schema` | TEXT    | JSON; ნაგულისხმევად `{}`                                        |
| `hooks`         | TEXT    | დეკლარირებული ჰუკების სახელების JSON მასივი; ნაგულისხმევად `[]` |
| `permissions`   | TEXT    | JSON მასივი; ნაგულისხმევად `[]`                                 |
| `plugin_dir`    | TEXT    | ინსტალაციის აბსოლუტური დირექტორია                               |
| `error_message` | TEXT    | მიეთითება, როდესაც `status = "error"`                           |
| `installed_at`  | TEXT    | `datetime('now')`                                               |
| `updated_at`    | TEXT    | `datetime('now')`                                               |
| `activated_at`  | TEXT    | მიეთითება აქტივაციისას                                          |

პლაგინის მეტრიკები/ანალიტიკა დამატებით ცხრილებში აღირიცხება
(`090_plugin_metrics.sql`, `091_plugin_analytics.sql`).

## მართვის პანელი

მართვის პანელის გვერდი მისამართზე `/dashboard/plugins`
(`src/app/(dashboard)/dashboard/plugins/page.tsx`) შეიცავს ორ ჩანართს:

- **დაინსტალირებული** — ჩამოთვლის დაინსტალირებულ პლაგინებს მათი დეკლარირებული ჰუკებით, შეიცავს
  აქტივაციის/დეაქტივაციის გადამრთველს, დეინსტალაციის ღილაკსა და „პლაგინების სკანირების“
  მოქმედებას (`POST /api/plugins/scan`).
- **მარკეტპლეისი** — აჩვენებს კატალოგს `GET /api/plugins/marketplace`-დან და შეიცავს
  ველს რეესტრის მორგებული URL-ის დასაყენებლად.

თითოეული პლაგინის კონფიგურაციის გვერდი მდებარეობს მისამართზე `/dashboard/plugins/[name]/config`
(`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`).
