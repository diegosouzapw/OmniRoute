> სფეროების დაკავშირება განთავსებულია `open-sse/mcp-server/server.ts`-ში.

## რა არის ეს

OmniRoute-ს შეუძლია დაუკავშირდეს **Notion** სამუშაო სივრცეს, როგორც **კონტექსტის წყაროს** — წაკითხვა/ჩაწერის
ცოდნის ბაზას, რომელსაც აგენტები ჩაშენებული MCP სერვერის მეშვეობით უკავშირდებიან. Notion-ის
ინტეგრაციის ტოკენის კონფიგურაციის შემდეგ, MCP ინსტრუმენტები LLM-ს აძლევს გვერდებისა და მონაცემთა ბაზების
ძიების, გვერდის შიგთავსისა და ბლოკების ხეების წაკითხვის, მონაცემთა ბაზებში ფილტრებით/დახარისხებით მოთხოვნების
შესრულებისა და ახალი ბლოკების დამატების საშუალებას — ყველა მოთხოვნა გადის OmniRoute-ის გავლით (ხელახალი ცდით,
მოლოდინის ვადითა და შეცდომების კლასიფიკაციით), რათა მოდელი პირდაპირ არასოდეს დაუკავშირდეს Notion API-ს.

ინტეგრაცია წარმოადგენს ოფიციალური Notion REST API-ის
(`https://api.notion.com/v1`, `Notion-Version: 2026-03-11`) მსუბუქ, გამძლეობაზე ორიენტირებულ გარსს. კლიენტი
(`src/lib/notion/api.ts`) ამატებს:

- **ხელახალ ცდას ექსპონენციალური დაყოვნებით** (`429`-ისა და `5xx`-ისთვის მაქსიმუმ 3 მცდელობა).
- **მოთხოვნის 55-წამიან მოლოდინის ვადას** `AbortController`-ის მეშვეობით.
- **ტიპიზებულ შეცდომათა კლასიფიკაციას** — `NotionAuthError` (401/403),
  `NotionNotFoundError` (404), `NotionRateLimitError` (429, ითვალისწინებს `retry after`
  მითითებებს), `NotionValidationError` (400/409), `NotionServerError` (5xx),
  `NotionTimeoutError`.
- **შეტყობინებების გასუფთავებას**, რომელიც მომხმარებლისთვის ჩვენებამდე შლის სტეკ-ტრასის მსგავს ფრაგმენტებს.

## დაყენება

Notion-ის ტოკენისთვის **გარემოს ცვლადი არ არსებობს** — იგი
`src/lib/db/notion.ts`-ის მეშვეობით ინახება SQLite-ის `key_value` ცხრილში (სახელთა სივრცე `notion`, გასაღები `integration_token`).
მისი კონფიგურაცია შესაძლებელია Endpoint-ის მართვის პანელის **Context Sources** ჩანართიდან
(`ObsidianSourceCard`-ის გვერდით მდებარე `NotionSourceCard`), ან პარამეტრების REST API-ის მეშვეობით.

> [!NOTE]
> ტოკენი არის **Notion-ის შიდა ინტეგრაციის ტოკენი**. შექმენით ინტეგრაცია მისამართზე
> <https://www.notion.com/my-integrations>, შემდეგ კი ამ ინტეგრაციას გაუზიარეთ გვერდები/მონაცემთა ბაზები, რომლებზეც
> OmniRoute-ს წვდომა უნდა ჰქონდეს (Notion-ის ნებართვების მოდელი გაზიარებაზეა დაფუძნებული
> და არა მთელ სამუშაო სივრცეზე).

### კონფიგურაცია REST-ის მეშვეობით

```bash
# ინტეგრაციის ტოკენის შენახვა + ვალიდაცია (POST ვალიდაციას სატესტო ძიების გაგზავნით ასრულებს)
curl -X POST http://localhost:20128/api/settings/notion \
  -H "Content-Type: application/json" \
  -d '{"token":"ntn_xxx"}'

# კავშირის სტატუსის შემოწმება
curl http://localhost:20128/api/settings/notion

# გათიშვა (შენახული ტოკენის გასუფთავება)
curl -X DELETE http://localhost:20128/api/settings/notion
```

სამივე მეთოდი მართვის პანელის ავტორიზაციას (`isAuthenticated`) საჭიროებს. `POST`-ის დროს
OmniRoute ინახავს ტოკენს და დაუყოვნებლივ ასრულებს 1-შედეგიან სატესტო ძიებას; თუ Notion
შეცდომის ობიექტს დააბრუნებს, ტოკენი წაიშლება და გამოძახება `400` შეცდომით დასრულდება.

## MCP ინსტრუმენტები (6)

განსაზღვრულია `open-sse/mcp-server/tools/notionTools.ts`-ში. ტოკენი გამოძახების
დროს მიიღება `getNotionToken()`-ის მეშვეობით; თუ იგი კონფიგურირებული არ არის, ინსტრუმენტი გამოიტანს შეცდომას
`"Notion integration token not configured. Set it in Settings > Context Sources."`

| ინსტრუმენტი                  | წვდომის სფერო  | აღწერა                                                                                                                           |
| ---------------------------- | -------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `notion_search`              | `read:notion`  | გვერდებისა და მონაცემთა ბაზების ძიება ტექსტური მოთხოვნით (აბრუნებს სათაურებს, ID-ებსა და URL-ებს). გვერდებად დაყოფილი.           |
| `notion_get_page`            | `read:notion`  | გვერდის შიგთავსისა და მეტამონაცემების მიღება მისი ID-ით.                                                                         |
| `notion_list_block_children` | `read:notion`  | ბლოკის ან გვერდის ყველა შვილობილი ბლოკის სიის მიღება (ბლოკების ხე). გვერდებად დაყოფილი.                                          |
| `notion_query_database`      | `read:notion`  | მონაცემთა ბაზაში მოთხოვნის შესრულება არასავალდებულო `filter` + `sorts` პარამეტრებით (Notion API-ის ფორმატი). გვერდებად დაყოფილი. |
| `notion_get_database`        | `read:notion`  | მონაცემთა ბაზის სქემის/მეტამონაცემების მიღება ID-ით.                                                                             |
| `notion_append_blocks`       | `write:notion` | შვილობილი ბლოკების დამატება არსებულ ბლოკში ან გვერდზე (მაქსიმუმ 100 ბლოკი თითო მოთხოვნაზე).                                      |

### შეყვანის პარამეტრები

- `notion_search` — `query` (1–500 სიმბოლო), `pageSize` (1–100, ნაგულისხმევად 20),
  `startCursor` (არასავალდებულო).
- `notion_get_page` — `pageId` (32-სიმბოლოიანი თექვსმეტობითი მნიშვნელობა ან UUID).
- `notion_list_block_children` — `blockId`, `pageSize` (1–100, ნაგულისხმევად 50),
  `startCursor` (არასავალდებულო).
- `notion_query_database` — `databaseId`, `filter` (არასავალდებულო, Notion-ის ფილტრის ფორმატი),
  `sorts` (არასავალდებულო მასივი), `pageSize` (1–100, ნაგულისხმევად 50), `startCursor` (არასავალდებულო).
- `notion_get_database` — `databaseId`.
- `notion_append_blocks` — `blockId`, `children` (ბლოკის ობიექტების მასივი),
  `after` (არასავალდებულო პოზიცია).

### წვდომის სფეროები

წაკითხვის ინსტრუმენტებს სჭირდება `read:notion`, ხოლო ჩაწერის ინსტრუმენტს — `write:notion`.
წვდომის სფეროებს `open-sse/mcp-server/server.ts`-ში არსებული `withScopeEnforcement()` აღასრულებს
მხოლოდ მაშინ, როცა `OMNIROUTE_MCP_ENFORCE_SCOPES=true`; გამომძახებლისთვის ნებადართული წვდომის სფეროები მიიღება
`OMNIROUTE_MCP_SCOPES`-იდან (მძიმით გამოყოფილი) ან ავტორიზებული API გასაღების წვდომის სფეროს კონტექსტიდან.
წვდომის სფეროების სრული მოდელისთვის იხილეთ [MCP-SERVER.md](./MCP-SERVER.md).

## გამოყენების შემთხვევები

- **ცოდნაზე დაფუძნებული პასუხები** — მიეცით აგენტს საშუალება, პასუხის გაცემამდე `notion_search`-ით მოძებნოს სამუშაო სივრცეში და `notion_get_page`-ით მიიღოს საუკეთესო შედეგი, რათა პასუხებში რეალური შიდა დოკუმენტები იყოს ციტირებული.
- **მონაცემთა ბაზაზე დაფუძნებული სამუშაო პროცესები** — `notion_query_database`-ით გამოკითხეთ ამოცანების/CRM-ის მონაცემთა ბაზა ფილტრებისა და დალაგების გამოყენებით, შემდეგ კი შეაჯამეთ ან პრიორიტეტებად დაახარისხეთ სტრიქონები.
- **უკან ჩაწერა / ჟურნალის წარმოება** — გამოიყენეთ `notion_append_blocks`, რათა არსებულ გვერდს დაუმატოთ შეხვედრის ჩანაწერები, გაშვების შეჯამებები ან აგენტის შედეგები (მხოლოდ დამატება; დესტრუქციული ცვლილებების გარეშე).
- **სტრუქტურის შესწავლა** — გამოიყენეთ `notion_list_block_children` გვერდის ბლოკების ხის გასავლელად, ან `notion_get_database` მონაცემთა ბაზის თვისებების სქემის აღმოსაჩენად მის გამოკითხვამდე.
