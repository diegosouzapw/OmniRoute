## რას წარმოადგენს

OmniRoute უკავშირდება **Obsidian**-ის საცავს, როგორც **კონტექსტის წყაროს** — ლოკალურ Markdown
ცოდნის ბაზას, რომელსაც აგენტები ჩაშენებული MCP სერვერის მეშვეობით კითხულობენ და მასში წერენ.
ინტეგრაცია უკავშირდება დესკტოპის აპლიკაციაში გაშვებულ, საზოგადოების მიერ შექმნილ
**Obsidian Local REST API** მოდულს, ამიტომ აგენტებს შეუძლიათ ჩანაწერების ძიება,
ფაილების წაკითხვა/ჩაწერა/ნაწილობრივი შეცვლა, საცავის შიგთავსის ჩამოთვლა, ყოველდღიურ/ყოველკვირეულ
პერიოდულ ჩანაწერებთან მუშაობა, ტეგების მართვა, Obsidian-ის ბრძანებების გაშვება და
(სურვილისამებრ) დესკტოპსა და მობილურ მოწყობილობას შორის საცავის ორმხრივი სინქრონიზაციის
კოორდინირება.

კლიენტი (`src/lib/obsidian/api.ts`) Local REST API-ს შემდეგი შესაძლებლობებით ავსებს:

- დროებითი `5xx` შეცდომებისთვის **ხელახალი ცდა მზარდი დაყოვნებით**, `AbortController`-ის მეშვეობით **30-წამიანი ლოდინის ვადა**.
- **ტიპიზებული შეცდომების კლასიფიკაცია** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- გასაგები მინიშნება **„Obsidian-თან დაკავშირება ვერ ხერხდება“**, რომელიც ყურადღებას ამახვილებს
  პორტის გავრცელებულ შეცდომაზე (HTTP `27123`-ზე, და **არა** MCP საბოლოო წერტილი `27124`-ზე)
  და Tailscale-ის ფორმატზე.
- საცავის მიმართ ფარდობითი **ბილიკების კოდირება**, რათა გამოტოვებებისა და დახრილი ხაზების შემცველი ჩანაწერების ბილიკები უსაფრთხო იყოს.

## გამართვა

Obsidian-ის ტოკენისა და საბაზო URL-ისთვის **გარემოს ცვლადი არ არსებობს** — ორივე ინახება
SQLite-ის `key_value` ცხრილში (`obsidian` სახელთა სივრცე) `src/lib/db/obsidian.ts`-ის მეშვეობით.
ტოკენი **დაშიფრული სახით ინახება** (AES-256-GCM, უკუთავსებადობისთვის დაუშიფრავ ტექსტზე
სათადარიგო გადასვლით). კონფიგურაცია შეასრულეთ Endpoint-ის მართვის პანელის
**Context Sources** ჩანართიდან (`ObsidianSourceCard`) ან პარამეტრების REST API-ის მეშვეობით.

> [!IMPORTANT]
> **Obsidian Local REST API** მოდული დაყენებული და გაშვებული უნდა იყოს. მისი REST
> ინტერფეისი უსმენს **HTTP `127.0.0.1:27123`**-ზე (ნაგულისხმევი საბაზო URL). პორტი `27124`
> არის _ცალკე_ MCP/HTTPS საბოლოო წერტილი და პარამეტრების მარშრუტი მას პირდაპირ უარყოფს.
> სხვა მოწყობილობიდან დაკავშირებისას გამოიყენეთ `http://<tailscale-ip>:27123`.

### კონფიგურაციის გასაღებები (SQLite `key_value`, სახელთა სივრცე `obsidian`)

| გასაღები          | დანიშნულება                                                     | დაშიფრულია |
| ----------------- | --------------------------------------------------------------- | ---------- |
| `api_key`         | Local REST API-ის bearer-ტოკენი                                 | დიახ       |
| `base_url`        | REST-ის საბაზო URL (ნაგულისხმევად `http://127.0.0.1:27123`)     | არა        |
| `vault_path`      | საცავის დირექტორიის აბსოლუტური ბილიკი (სინქრონიზაციისთვის)      | არა        |
| `webdav_username` | გენერირებული WebDAV მომხმარებლის სახელი (საცავის სინქრონიზაცია) | არა        |
| `webdav_password` | გენერირებული WebDAV პაროლი (საცავის სინქრონიზაცია)              | დიახ       |
| `webdav_enabled`  | ჩართულია თუ არა WebDAV საცავის სინქრონიზაცია                    | არა        |

### კონფიგურაცია REST-ის მეშვეობით

```bash
# Local REST API-ის ტოკენის შენახვა + შემოწმება (POST მას სტატუსის შემოწმებით ამოწმებს)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# კავშირის სტატუსის შემოწმება (აბრუნებს connected, hasToken, baseUrl, vaultPath მნიშვნელობებს)
curl http://localhost:20128/api/settings/obsidian

# კავშირის გაწყვეტა (შენახულ ტოკენს ასუფთავებს)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

ყველა მეთოდი მართვის პანელის ავთენტიფიკაციას მოითხოვს. `POST` უარყოფს `27124` პორტზე
მითითებულ ნებისმიერ URL-ს და შენახვამდე ტოკენს Local REST API-ის სტატუსის საბოლოო
წერტილის გამოძახებით ამოწმებს.

### WebDAV საცავის სინქრონიზაცია

`src/app/api/settings/obsidian/webdav/route.ts` მართავს WebDAV-ზე დაფუძნებულ არჩევით
საცავის სინქრონიზაციას (რომელსაც `src/lib/obsidianSync.ts` ამუშავებს). მისი ჩართვისას
OmniRoute მიემართება საცავის ლოკალურ დირექტორიაზე და ქმნის შემთხვევით WebDAV
მომხმარებლის სახელსა და პაროლს:

```bash
# საცავის დირექტორიისთვის WebDAV სინქრონიზაციის ჩართვა (ქმნის მომხმარებლის სახელს/პაროლს)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# WebDAV სინქრონიზაციის სტატუსის მიღება (მონაცემები ბრუნდება მხოლოდ მაშინ, როცა ფუნქცია ჩართულია)
curl http://localhost:20128/api/settings/obsidian/webdav

# WebDAV სინქრონიზაციის გამორთვა (ასუფთავებს მონაცემებს + მართულ .stignore-ს)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### კონტექსტის წყარო თითოეული API გასაღებისთვის (არჩევითი)

Obsidian-ის კონფიგურაციის წვდომის სფერო შეიძლება განისაზღვროს **თითოეული API გასაღებისთვის**
`api_key_context_sources` ცხრილის მეშვეობით (`src/lib/db/apiKeyContextSources.ts`).
როდესაც MCP გამოძახება შეიცავს ავთენტიფიცირებული API გასაღების იდენტიფიკატორს,
`getObsidianConfigForApiKey()` უპირატესობას ანიჭებს ამ გასაღების საკუთარ
ტოკენს/საბაზო URL-ს/საცავის ბილიკს (`source: "api_key"`), ხოლო მათი არარსებობის შემთხვევაში
იყენებს გლობალურ კონფიგურაციას (`source: "global"`).

## MCP ინსტრუმენტები (22)

თითოეული გამოძახებისთვის (ჯერ თითოეული API გასაღებისთვის, შემდეგ გლობალურად). ინსტრუმენტები, რომლებიც OmniRoute-ის **სინქრონიზაციის სერვერს**

| `obsidian_get_note_metadata` | frontmatter-ის, ტეგების, ბმულებისა და სიმბოლოების/სიტყვების რაოდენობის მიღება სრული შიგთავსის გარეშე.                              |
| `obsidian_get_active_file`   | Obsidian-ში ამჟამად აქტიური ფაილის ბილიკისა და შიგთავსის მიღება.                                                                   |
| `obsidian_get_periodic_note` | თარიღისთვის დღიური/კვირეული/თვიური პერიოდული ჩანაწერის მიღება (თუ გამოტოვებულია — დღევანდელი).                                     |
| `obsidian_get_tags`          | საცავის ყველა ტეგის ჩამონათვალი მათი სიხშირეებით.                                                                                  |
| `obsidian_list_commands`     | Obsidian-ის ხელმისაწვდომი ბრძანებების ID-ების ჩამონათვალი (გამოიყენეთ `obsidian_execute_command`-თან ერთად).                       |
| `obsidian_sync_status`       | OmniRoute-ის სინქრონიზაციის სერვერის სტატუსი: გაშვებულია თუ არა, საცავის სახელი, პორტი, მუშაობის ხანგრძლივობა, ბოლო სინქრონიზაცია. |
| `obsidian_sync_conflicts`    | მოუგვარებელი სინქრონიზაციის კონფლიქტების ჩამონათვალი (ბილიკი, კონფლიქტის ბილიკი, აღმოჩენის დრო).                                   |

### ჩაწერის ინსტრუმენტები (`write:obsidian`)

| ინსტრუმენტი                      | აღწერა                                                                                                |
| -------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | მოცემული Markdown შიგთავსით ჩანაწერის შექმნა ან გადაწერა.                                             |
| `obsidian_append_note`           | ჩანაწერში შიგთავსის დამატება; სურვილისამებრ, კონკრეტულ სათაურში/ბლოკში.                               |
| `obsidian_patch_note`            | სათაურში, ბლოკში ან frontmatter ველში ზუსტად განსაზღვრული დამატება/წინ ჩამატება/ჩანაცვლება.           |
| `obsidian_delete_note`           | ჩანაწერის სამუდამოდ წაშლა საცავიდან.                                                                  |
| `obsidian_move_note`             | ჩანაწერის გადატანა ან სახელის შეცვლა საცავის ფარგლებში.                                               |
| `obsidian_execute_command`       | Obsidian-ის ბრძანების შესრულება მისი ბრძანების ID-ით.                                                 |
| `obsidian_open_file`             | ფაილის გახსნა Obsidian-ში (ქმნის მას, თუ არ არსებობს).                                                |
| `obsidian_sync_trigger`          | ორმხრივი desktop↔mobile საცავის დაუყოვნებელი სინქრონიზაციის გაშვება.                                  |
| `obsidian_sync_resolve_conflict` | სინქრონიზაციის კონფლიქტის მოგვარება: `local` (mobile), `remote` (desktop) ან `keep-both` შენარჩუნება. |

> [!NOTE]
> `obsidian_patch_note`-ის სამიზნეებში `targetType` იღებს მნიშვნელობებს `heading | block | frontmatter`,
> ხოლო `operation` — `append | prepend | replace`, სურვილისამებრ
> `createTargetIfMissing`-ით. ოთხი `obsidian_sync_*` ინსტრუმენტი უკავშირდება ლოკალურ სინქრონიზაციის
> სერვერს (ნაგულისხმევად `http://127.0.0.1:27781`) და საჭიროებს სინქრონიზაციის ტოკენს.

### წვდომის სფეროები

წაკითხვის ინსტრუმენტები საჭიროებს `read:obsidian`-ს; ჩაწერის ინსტრუმენტები — `write:obsidian`-ს. აღსრულება
Notion-ის იდენტურია — მას ამუშავებს `withScopeEnforcement()` ფუნქცია
`open-sse/mcp-server/server.ts`-ში, რომელიც აქტიურდება `OMNIROUTE_MCP_ENFORCE_SCOPES=true`-ის შემთხვევაში, ხოლო
ნებადართული წვდომის სფეროები მიიღება `OMNIROUTE_MCP_SCOPES`-იდან ან API გასაღების წვდომის სფეროს კონტექსტიდან. იხილეთ
[MCP-SERVER.md](./MCP-SERVER.md).

## გამოყენების შემთხვევები

- **საცავის მონაცემებზე დაფუძნებული პასუხები** — `obsidian_search_simple` / `obsidian_search_structured`,
  შემდეგ `obsidian_read_note`, რათა აგენტმა თქვენი რეალური ჩანაწერებიდან უპასუხოს.
- **ჩანაწერების შექმნა / დღიურის წარმოება** — `obsidian_write_note`, `obsidian_append_note`, ან
  ზუსტი `obsidian_patch_note`, რათა აგენტის შედეგები, შეჯამებები ან ყოველდღიური ჩანაწერები
  (`obsidian_get_periodic_note`) საცავში ჩაიწეროს.
- **საცავში ნავიგაცია** — `obsidian_list_vault`, `obsidian_get_document_map` და
  `obsidian_get_tags` სტრუქტურის შესასწავლად წაკითხვამდე/ჩაწერამდე.
- **Obsidian-ის ავტომატიზაცია** — `obsidian_list_commands` + `obsidian_execute_command`
  პლაგინების/ბრძანებების აგენტიდან სამართავად; `obsidian_open_file` ჩანაწერის UI-ში საჩვენებლად.
- **მობილური სინქრონიზაცია** — ჩართეთ WebDAV სინქრონიზაცია, შემდეგ გამოიყენეთ `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  დესკტოპსა და მობილურს შორის სინქრონიზაციის კოორდინირებისა და კონფლიქტების მოსაგვარებლად.
