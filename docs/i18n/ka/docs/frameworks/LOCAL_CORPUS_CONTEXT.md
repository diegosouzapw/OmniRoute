## რას წარმოადგენს

Local Corpus ოპერატორს საშუალებას აძლევს, ტექსტური ფაილების ერთი, აშკარად დამტკიცებული დირექტორია
OmniRoute-ის MCP სერვერისთვის ხელმისაწვდომი გახადოს. ფაილები თავდაპირველ დირექტორიაში რჩება: OmniRoute
SQLite-ში მხოლოდ კანონიკურ ძირეულ ბილიკს ინახავს და მეხსიერებაში საძიებო ინდექსს მართავს. ის
კორპუსის შიგთავსს არც რეპოზიტორიაში და არც მონაცემთა ბაზაში არ აკოპირებს.

ინდექსი ინკრემენტულად ახლდება. უცვლელი ფაილები მათი ზომისა და ცვლილების
დროის მიხედვით ხელახლა გამოიყენება, შეცვლილი ფაილები თავიდან იკითხება და SHA-256-ით ჰეშირდება,
ხოლო წაშლილი ფაილები ამოიშლება. ძიება 30 წამზე ძველ ინდექსს აახლებს; გამომძახებებს ასევე შეუძლიათ
დაუყოვნებელი განახლების მოთხოვნა.

## წყაროს კონფიგურაცია

პარამეტრების მარშრუტი მართვის იმავე ავთენტიფიკაციას მოითხოვს, რომელსაც პარამეტრების სხვა API-ები.
გადაცემული ბილიკი უკვე უნდა არსებობდეს და დირექტორიის აბსოლუტური ბილიკი უნდა იყოს.

```bash
# დამტკიცებული დირექტორიის დაკავშირება
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# კონფიგურაციისა და ინდექსის სტატუსის შემოწმება
curl http://localhost:20128/api/settings/local-corpus

# წყაროს ფაილების შეუცვლელად გათიშვა
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## MCP ინსტრუმენტები

სამივე ინსტრუმენტისთვის საჭიროა `read:local-corpus`. ინსტრუმენტების პასუხები აჩვენებს ფარდობით ბილიკებსა და
ძირეული დირექტორიის საბაზო სახელს, მაგრამ არასდროს — მის აბსოლუტურ ბილიკს.

| ინსტრუმენტი           | აღწერა                                                                                                   |
| :-------------------- | :------------------------------------------------------------------------------------------------------- |
| `local_corpus_status` | კონფიგურაციის მდგომარეობის, ინდექსის ზომის, ლიმიტებისა და ბოლო განახლების დროის ჩვენება                  |
| `local_corpus_search` | ინდექსირებულ ტექსტში ძიება და შეზღუდული, სტრიქონებით განსაზღვრული ფრაგმენტების დაბრუნება (20-მდე შედეგი) |
| `local_corpus_read`   | კორპუსის ერთ ნებადართულ ფარდობით ფაილში სტრიქონების შეზღუდული დიაპაზონის წაკითხვა                        |

MCP-ის შესატანი მონაცემების მაგალითები:

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## უსაფრთხოების საზღვრები

- ნებადართული გაფართოებების სია ტექსტურ ფორმატებზეა ორიენტირებული: `.cfg`, `.csv`, `.geojson`, `.htm`, `.html`, `.ini`,
  `.js`, `.json`, `.jsonl`, `.jsx`, `.log`, `.md`, `.mjs`, `.ps1`, `.py`, `.sh`,
  `.sql`, `.toml`, `.ts`, `.tsx`, `.txt`, `.xml`, `.yaml` და `.yml`.
- სიმბოლური ბმულები გამოტოვებულია. წაკითხვის ბილიკები კანონიკალიზდება და კონფიგურირებული
  ძირეული დირექტორიის ფარგლებში უნდა დარჩეს; აბსოლუტური ბილიკები და დირექტორიებიდან გასვლის მცდელობები უარყოფილია.
- სენსიტიური და გენერირებული დირექტორიების სახელები გამორიცხულია: `.build`, `.codex`, `.env`,
  `.git`, `.next`, `.omniroute`, `.ssh`, `coverage`, `dist`, `node_modules` და
  `secrets`.
- ნაგულისხმევი ლიმიტებია 5,000 ფაილი, 1 MiB თითო ფაილზე, ინდექსირებული შიგთავსის ჯამურად 64 MiB,
  დაახლოებით 4,000 სიმბოლო თითო საძიებო ფრაგმენტზე და 400 სტრიქონი თითო წაკითხვაზე.
- NUL-ის შემცველი ფაილები არატექსტურად მიიჩნევა და გამოტოვებული ან უარყოფილია.

ბინარული დოკუმენტები, როგორიცაა PDF, DOCX, სურათები და არქივები, განზრახ არ არის მხარდაჭერილი.
ინდექსირებამდე ისინი კონფიგურირებულ დირექტორიაში ნებადართულ ტექსტურ ფორმატად გარდაქმენით.

## საოპერაციო შენიშვნები

- კონფიგურირებული ძირეული დირექტორიის შეცვლა ან წაშლა მეხსიერებაში არსებულ საერთო ინდექსს ასუფთავებს.
- პროცესის ხელახლა გაშვება ინდექსს აუქმებს; შემდეგი ძიება მას კონფიგურირებული
  წყაროდან თავიდან ააგებს.
- `local_corpus_status` სკანირებას იძულებით არ იწყებს. როდესაც დაუყოვნებელი ხელახალი სკანირებაა საჭირო, გამოიყენეთ
  `local_corpus_search` პარამეტრით `refresh: true`.
- სკანირებისა და წაკითხვის წარუმატებლობები აღირიცხება ან გასუფთავებული შეცდომების სახით ბრუნდება; წყაროს ფაილები
  არასდროს იცვლება.
