1. არსებული ერთ-გასაღებიანი სემაფორის კონტრაქტი და ახალი ატომური მრავალგასაღებიანი
   კონტრაქტი დააფიქსირეთ მიზნობრივი ტესტებით: ნაწილობრივი რეზერვაციების გარეშე, FIFO რიგში ჩაყენება, გაუქმება,
   დროის ამოწურვა, რიგის შევსება, იდემპოტენტური გათავისუფლება, სტატისტიკა და გასუფთავება.
2. არსებული ანგარიშის სემაფორი ადგილზე განაზოგადეთ. შეინარჩუნეთ `acquire()`, როგორც
   `acquireMany()`-ის გარშემო თავსებადობის გარსი; ნუ დაამატებთ მეორე დამგეგმავს
   ან დამოკიდებულებას.
3. `chatCore`-ში მხოლოდ ანგარიშისთვის განკუთვნილი დაკავება ჩაანაცვლეთ ერთი კუმულაციური
   გლობალური/პროვაიდერის/ანგარიშის დაკავებით უშუალოდ `withRateLimit`-ის წინ.
   ხელახლა დაიკავეთ მთელი ნაკრები ყოველთვის, როცა ანგარიშის როტაცია კავშირს შეცვლის,
   და გათავისუფლება სტრიმინგის დასრულებამდე შეაყოვნეთ.
4. გააფართოეთ მდგრადობის პარამეტრების არსებული დამუშავების ჯაჭვი (ტიპები, ნაგულისხმევი მნიშვნელობები,
   ნორმალიზაცია, სქემა, API პასუხი, UI და თარგმანები) გლობალური
   და პროვაიდერის ლიმიტებით. ძველ Bottleneck კონკურენტულობის კონტროლს გადაარქვით
   კავშირის/კვოტის მასშტაბის კონკურენტულობა, რათა მისი რეალური მოქმედების მასშტაბი ცხადი იყოს.
5. გაუშვით მიზნობრივი ტესტები, ლინტინგი, ტიპების შემოწმება, სტატიკური შემოწმებები და სრული სატესტო ნაკრები;
   ქცევითი ცვლილება ცვლილებების ჟურნალში დააფიქსირეთ.

განზრახ შენარჩუნებული ქცევა: ნულოვანი/null კონკურენტულობა ბარიერს გვერდს უვლის,
მხოლოდ ანგარიშზე მომუშავე გამომძახებლები კვლავ `acquire()`-ს იყენებენ, დაბლოკილი ანგარიშების მართვის
მექანიზმები ინარჩუნებენ გასაღების ფორმატსა და API-ს, ხოლო პროვაიდერის სიჩქარის შეზღუდვის რიგის ქცევა
უცვლელი რჩება.
