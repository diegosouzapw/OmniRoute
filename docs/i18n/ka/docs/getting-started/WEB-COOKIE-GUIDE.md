Web Cookie პროვაიდერები OmniRoute-ს საშუალებას აძლევს, API გასაღების ნაცვლად, AI სერვისი თქვენი არსებული ბრაუზერის სესიის მეშვეობით გამოიყენოს. ისინი სასარგებლოა, როდესაც სერვისზე უკვე გაქვთ წვდომა მისი ვებსაიტის მეშვეობით და გსურთ, რომ OmniRoute-მა იგივე ავტორიზებული სესია გამოიყენოს.

API გასაღებზე დაფუძნებული პროვაიდერებისგან განსხვავებით, Web Cookie პროვაიდერები ავთენტიფიკაციისთვის იყენებენ ავტორიზაციის მონაცემებს, რომლებსაც თქვენი ბრაუზერი ვებსაიტს უგზავნის.

# დაწყებამდე

> **მნიშვნელოვანია:** ავტორიზაციის მონაცემები ყოველთვის დააკოპირეთ **აქტიური ქსელური მოთხოვნიდან** და **არა** თქვენი ბრაუზერის cookie-ების საცავიდან.

ავთენტიფიკაციის მრავალი პრობლემა გამოწვეულია cookie-ების არასწორი ადგილიდან კოპირებით.

## არ დააკოპიროთ Cookie Storage-დან

ბრაუზერების უმეტესობაში შენახული cookie-ები ხელმისაწვდომია შემდეგი გზით:

```
DevTools
→ Application (ან Storage)
→ Cookies
```

მიუხედავად იმისა, რომ ეს cookie-ები შეიძლება სწორად გამოიყურებოდეს, ისინი შესაძლოა იყოს:

- მოძველებული
- არასრული
- ავთენტიფიცირებულ მოთხოვნებზე გაგზავნილი ზოგიერთი cookie-ის გარეშე

ამ მნიშვნელობების გამოყენებამ შეიძლება ავთენტიფიკაციის შეცდომები გამოიწვიოს, მაშინაც კი, თუ ისინი მართებულად გამოიყურება.

## დააკოპირეთ აქტიური მოთხოვნიდან

ამის ნაცვლად, გამოიყენეთ წარმატებული მოთხოვნის cookie-ები:

```
DevTools
→ Network
→ განაახლეთ გვერდი
→ გახსენით ჩატის ან საუბრის მოთხოვნა
→ Request Headers
→ Cookie
```

`Cookie` მოთხოვნის სათაური შეიცავს ზუსტად იმ საავთენტიფიკაციო ინფორმაციას, რომელიც თქვენმა ბრაუზერმა წარმატებით გამოიყენა.

Web Cookie პროვაიდერების უმეტესობისთვის, სწორედ ეს მნიშვნელობა უნდა ჩასვათ OmniRoute-ში.

# ზოგადი დაყენება

დაყენების პროცესი Web Cookie პროვაიდერების უმეტესობისთვის ერთნაირია.

1. შედით პროვაიდერის ვებსაიტზე.
2. გახსენით ბრაუზერის Developer Tools.
3. გახსენით **Network** ჩანართი.
4. განაახლეთ გვერდი.
5. გახსენით ავთენტიფიცირებული ჩატის ან საუბრის მოთხოვნა.
6. დააკოპირეთ საჭირო საავთენტიფიკაციო მონაცემები.
7. გახსენით OmniRoute.
8. გადადით **Providers → Add Provider**.
9. აირჩიეთ თქვენი Web Cookie პროვაიდერი.
10. ჩასვით ავტორიზაციის მონაცემები.
11. დააწკაპუნეთ **Test Connection**.
12. შეინახეთ პროვაიდერი.

საჭირო ავტორიზაციის მონაცემები კონკრეტულ პროვაიდერზეა დამოკიდებული.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) არის მომხმარებლებისთვის განკუთვნილი უფასო ჩატის პლატფორმა, რომელიც რეგისტრაციას არ საჭიროებს — სესია ანონიმურად იქმნება პირველი ვიზიტისას და ნარჩუნდება სამი cookie-ს მეშვეობით: `uid`, `si_usr_id` და `si_ses_id`. OmniRoute იმავე `/api/dispatch` საბოლოო წერტილს ერთი მოდელის id-ის (`notrack-c`, alias `ntw`) მეშვეობით პროქსირებს.

### დაკავშირების ნაბიჯები

1. გახსენით [notrack.ai](https://notrack.ai) თქვენს ბრაუზერში და დაელოდეთ ანონიმური სესიის cookie-ს დაყენებას.
2. გახსენით **DevTools → Network**, განაახლეთ გვერდი და დააწკაპუნეთ ნებისმიერ `/api` მოთხოვნაზე.
3. **Request Headers** განყოფილებაში დააკოპირეთ `Cookie` სათაურის სრული მნიშვნელობა.
4. OmniRoute-ში გადადით **Providers → Add Provider → NoTrack Web (Free)**.
5. ჩასვით cookie-ს სტრიქონი `apiKey` ველში და დააჭირეთ **Save**-ს.

OmniRoute ჩასმული სტრიქონიდან გამოყოფს `uid`, `si_usr_id` და `si_ses_id` მნიშვნელობებს და თავიდან აგებს სუფთა `Cookie` სათაურს, რომელიც მხოლოდ ამ წყვილებს შეიცავს — აგრეთვე `nt_session`-ს (`ntk_…` ტოკენს, რომელიც ავტორიზებული ანგარიშებისთვის არის დაყენებული), თუ ის არსებობს. თუ ამ სამიდან რომელიმე აკლია, ჩასმული დაუმუშავებელი სტრიქონი უცვლელად გადაიგზავნება, რათა ოპერატორებმა ალტერნატიული ფორმატების გამოცდა შეძლონ.

### მოდელების id-ები

| მოდელის id  | საჩვენებელი სახელი | შენიშვნები                                                     |
| ----------- | ------------------ | -------------------------------------------------------------- |
| `notrack-c` | NoTrack C          | ნაგულისხმევი — ზედა დონის dispatch მოდელი `C`.                 |
| `C`         | NoTrack C          | `notrack-c`-ის alias (ზედა დონის დაუმუშავებელი dispatch კოდი). |
| `notrack`   | NoTrack C          | `notrack-c`-ის alias.                                          |
| `ntw`       | NoTrack C          | `notrack-c`-ის მოკლე alias.                                    |

ოთხივე მოდელის id აისახება ერთსა და იმავე ზედა დონის dispatch მოდელზე (`C`).

### მოთხოვნის პარამეტრები

შემსრულებელი მოთხოვნის სხეულში იღებს შემდეგ არასავალდებულო ველებს:

| სხეულის ველი          | ნაგულისხმევი | დანიშნულება                                                                    |
| --------------------- | ------------ | ------------------------------------------------------------------------------ |
| `notrack_mode`        | `usual`      | dispatch რეჟიმი (ნებისმიერი ფორმის სტრიქონი; ზედა დონე იღებს `usual`-ს, …)     |
| `notrack_max_turns`   | `6`          | შიდა ნაბიჯების რაოდენობა, რომელთა შესრულებაც ზედა დონეს პასუხამდე შეუძლია.     |
| `notrack_chat_id`     | `null`       | არსებული ზედა დონის ჩატის გაგრძელება (ახალი ჩატისთვის გამოტოვეთ).              |
| `notrack_attachments` | `[]`         | ზედა დონის დანართების აღმწერების უცვლელად გადასაცემი მასივი.                   |
| `notrack_regenerate`  | `false`      | წინა ნაბიჯისთვის პასუხის ხელახლა გენერირების მოთხოვნის მიზნით დააყენეთ `true`. |

### შესაძლებლობები

- ჩატის დასრულებები **ნაკადურ და არანაკადურ რეჟიმებში**.
- **ინსტრუმენტების გამოძახება** — მოთხოვნაში მიუთითეთ `tools: [...]`; შემსრულებელი მათ ინსტრუმენტის გამოძახების კონვერტის კონტრაქტის ფორმატში სერიალიზებს და მოდელის პასუხებს კვლავ OpenAI-ის `tool_calls` ფორმატში გარდაქმნის.
- **`response_format`** — მხარდაჭერილია `json_object` და `json_schema`. შემსრულებელი მოდელის პასუხიდან პირველ JSON ობიექტს ამოიღებს და დაბრუნებამდე სტრიქონად გარდაქმნის.
- **მსჯელობის მინიშნება** — როდესაც ზედა დონე `thinking` მოვლენას აგზავნის, შემსრულებელი `reasoning` დელტას გამოსცემს.

### შეზღუდვები

- ზედა დონე ანონიმური გამოყენების კვოტებს აწესებს — მათი გადაჭარბებისას შემსრულებელი აბრუნებს 429-ს გასაგები შეტყობინებით.
- ყველა მოდელის id ერთსა და იმავე ზედა დონის dispatch მოდელზე მიუთითებს; ცალკეული მოდელის დონეზე გადართვა შეუძლებელია.
- შემსრულებელი ზედა დონის `/api/chats` საბოლოო წერტილს არ იძახებს, ამიტომ ჩატის ისტორია / სესიები ავტომატურად არ იმართება. არსებული ზედა დონის ჩატის გასაგრძელებლად გამოიყენეთ `notrack_chat_id`.

# რა შეუძლიათ და რა არ შეუძლიათ Web Cookie პროვაიდერებს

Web Cookie პროვაიდერები ვებსაიტის ჩატის ინტერფეისს ხელახლა იყენებენ. ისინი ოფიციალური API-ების იდენტურ შესაძლებლობებს **არ** უზრუნველყოფენ.

## მხარდაჭერილია

- ავთენტიფიკაცია ბრაუზერის არსებული სესიის გამოყენებით
- თქვენს ანგარიშზე ხელმისაწვდომ მოდელებზე წვდომა
- ჩატის პასუხების ნაკადურ რეჟიმში მიღება
- API გასაღები საჭირო არ არის

## არ არის მხარდაჭერილი

- ფუნქციების გამოძახება
- ხელსაწყოების გამოძახება
- ფაილების ავტომატური რედაქტირება
- აგენტური IDE სამუშაო პროცესები
- მხოლოდ API-ით ხელმისაწვდომი ფუნქციები

ეს მოსალოდნელი ქცევაა და **არ არის** შეცდომა.

თუ გჭირდებათ ხელსაწყოების შესრულება, ფაილების ავტომატური რედაქტირება ან სხვა აგენტური სამუშაო პროცესები, Web Cookie პროვაიდერის ნაცვლად გამოიყენეთ **API გასაღების პროვაიდერი**.

# ვალიდაციასთან დაკავშირებული შენიშვნა

წარმატებული **Test Connection** ან cookie-ს ვალიდაცია მხოლოდ იმას ადასტურებს, რომ მოწოდებული ავტორიზაციის მონაცემები მოსალოდნელ ფორმატს შეესაბამება.

Issue #7857-ის გადაჭრამდე წარმატებული ვალიდაცია **არ იძლევა გარანტიას**, რომ პროვაიდერი ავთენტიფიკაციას წარმატებით გაივლის.

თუ ავთენტიფიკაცია კვლავ ვერ ხერხდება, დარწმუნდით, რომ ავტორიზაციის მონაცემები დააკოპირეთ აქტიური ქსელური მოთხოვნიდან და არა ბრაუზერის cookie-ების საცავიდან.

ზოგიერთი პროვაიდერი შეიცავს cookie-ებს, რომლებიც მხოლოდ ავთენტიფიცირებული მოთხოვნების დროს იგზავნება.

საუბრის წარმატებით გახსნის შემდეგ ავტორიზაციის მონაცემები ხელახლა დააკოპირეთ ახალი ქსელური მოთხოვნიდან.

## სესიის ვადა ამოიწურა

Web Cookie პროვაიდერები ბრაუზერის თქვენს არსებულ სესიას იყენებენ.

თუ ბრაუზერის სესიის ვადა ამოიწურება ან ანგარიშიდან გამოხვალთ, ავტორიზაციის მონაცემების ახალი ნაკრები უნდა დააკოპიროთ. მხარდაჭერილი ვებ-პროვაიდერებისთვის cookie-ების განახლების ავტომატიზაციის შესახებ იხილეთ თანმხლები ხელსაწყო [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md).
