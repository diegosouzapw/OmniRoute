## `claude-web`

`claude-web` OpenAI-ის ფორმატის ჩატის მოთხოვნებს ავტორიზებული `claude.ai` ბრაუზერის სესიის მეშვეობით აგზავნის. შემსრულებელი ახდენს მიწოდებული cookie-ის ნორმალიზებას, განსაზღვრავს ერთ ავტორიზებულ ორგანიზაციას, ამზადებს საუბრის მდგომარეობას, ირჩევს პირდაპირ ან ბრაუზერულ ტრანსპორტს და მკაცრად გარდაქმნის ზედა დონის SSE პასუხს. ორკესტრაცია განთავსებულია
`open-sse/executors/claude-web.ts:320`-ში.

> **პირველად იყენებთ Web Cookie პროვაიდერებს?**
>
> ამ პროვაიდერის სპეციფიკური სახელმძღვანელოს შესრულებამდე, ზოგადი დაყენების პროცესის, ავტორიზაციის მითითებების, შეზღუდვებისა და პრობლემების აღმოფხვრის შესახებ წაიკითხეთ **`docs/getting-started/WEB-COOKIE-GUIDE.md`**.

ამ პროვაიდერისთვის მოდელების დინამიკური აღმოჩენა დანერგილი არ არის. ზემოთ მოცემული სია შესრულების გარემოს კატალოგია.

### ავტორიზაციის მონაცემები და ორგანიზაციის განსაზღვრა

მიუთითეთ ან სრული `claude.ai` Cookie სათაური, ან მხოლოდ სესიის მნიშვნელობა. მხოლოდ მნიშვნელობის მითითებისას ის ნორმალიზდება როგორც `sessionKey`; მიწოდების შემთხვევაში სხვა cookie-ები შენარჩუნდება. შემსრულებელი cookie-ს იღებს `cookie`-ის ან `apiKey`-ის მეშვეობით და კავშირის მონაცემებიდან კითხულობს არასავალდებულო `deviceId` და `orgId` მნიშვნელობებს
(`open-sse/executors/claude-web.ts:72`).

თუ `orgId` არ არის მითითებული, შემსრულებელი იძახებს `GET https://claude.ai/api/organizations`-ს და იყენებს ავტორიზებული Claude Web სესიის მიერ დაბრუნებულ პირველ ორგანიზაციას
(`open-sse/executors/claude-web.ts:141`). თუ ვალიდური ორგანიზაცია არ დაბრუნდა, იგი უსაფრთხოდ წყვეტს მუშაობას, უარყოფილ სესიის ავტორიზაციას ასახავს როგორც 401-ს და განასხვავებს Cloudflare-ის გამოწვევას ავტორიზაციის წარუმატებლობისგან.

### საუბრის ოპერაციები

ზედა დონის არასავალდებულო `claude_web` ობიექტი მკაცრია. უცნობი ველები უარყოფილია. მისი დასაშვები ველები განსაზღვრულია `open-sse/executors/claude-web/session.ts:50`-ში:

| ველი                  | მნიშვნელობა                                                                           |
| --------------------- | ------------------------------------------------------------------------------------- |
| `operation`           | ნაგულისხმევად `completion`; განმეორებითი სვლისთვის გამოიყენეთ `retry`                 |
| `conversation_id`     | არსებული საუბრის აშკარად მითითებული UUID                                              |
| `parent_message_uuid` | მშობელი ასისტენტის შეტყობინების აშკარად მითითებული UUID                               |
| `timezone`            | ვალიდური IANA დროის სარტყლის სახელი                                                   |
| `locale`              | სტრუქტურულად ვალიდური ლოკალი                                                          |
| `tool_states`         | ანგარიშის ინსტრუმენტების მდგომარეობების არასავალდებულო მასივი, მაქსიმუმ 128 ჩანაწერით |

მომზადებული მოთხოვნები ზედა დონის ორი საბოლოო წერტილიდან ერთ-ერთს იყენებს
(`open-sse/executors/claude-web.ts:203`):

- ახალი ან შემდგომი სვლა იგზავნება მისამართზე
  `POST https://claude.ai/api/organizations/{orgId}/chat_conversations/{conversationId}/completion`.
- განმეორებითი მცდელობა იგზავნება მისამართზე
  `POST https://claude.ai/api/organizations/{orgId}/chat_conversations/{conversationId}/retry_completion`.

ახალი სვლა შეიცავს `create_conversation_params`-ს. ქეშირებული ან აშკარად დაკავშირებული შემდგომი სვლა შეიცავს `parent_message_uuid`-ს და გამოტოვებს `create_conversation_params`-ს. განმეორებითი მცდელობისთვის აუცილებელია როგორც საუბრის, ისე მშობელი შეტყობინების მდგომარეობა და მოთხოვნა პრომპტის გარეშე იგზავნება
(`open-sse/executors/claude-web/session.ts:254`). ახალი საუბრები ავტორიზებულ UI-ს `/new` მისამართზე ხსნის; ქეშირებული ან აშკარად დაკავშირებული შემდგომი სვლები საუბრის ზუსტ გვერდს ხსნის
(`open-sse/executors/claude-web/session.ts:324`).

საუბრის მდგომარეობა არის მეხსიერებაში შენახული ქეში, რომლის გასაღებიც SHA-256 ანგარიშის არეალითა და გამომძახებლის კანონიკური ტრანსკრიპტით განისაზღვრება. ჩანაწერებს ვადა 30 წუთის შემდეგ გასდით, ხოლო ქეში მაქსიმუმ 5,000 ჩანაწერითაა შეზღუდული
(`open-sse/executors/claude-web/session.ts:12`). მდგომარეობა ფიქსირდება მხოლოდ მას შემდეგ, რაც მკაცრი ნაკადის პარსერი დააფიქსირებს `message_stop`-ს; პროცესის გადატვირთვა მას შლის. ქეშში აცდენისას, მრავალშეტყობინებიანი მოთხოვნა ერთ აღდგენის პრომპტად სერიალიზდება, ნაცვლად იმისა, რომ ადრინდელი შეტყობინებები უხმოდ გაუქმდეს.

ლოკალისა და დროის სარტყლისთვის გამოიყენება შემდეგი პრიორიტეტი: მოთხოვნის `claude_web` მნიშვნელობა, კავშირის მნიშვნელობა, შესრულების გარემოს მნიშვნელობა, შემდეგ `en-US` ლოკალისთვის ან `UTC` დროის სარტყლისთვის
(`open-sse/executors/claude-web/session.ts:218`).

### ინსტრუმენტები და მოთხოვნის სასარგებლო დატვირთვები

პირდაპირი მოთხოვნები გარდაქმნის მხოლოდ გამომძახებლის მიერ მიწოდებულ, სტრუქტურულად ვალიდურ OpenAI ფუნქციის ინსტრუმენტებს. გამოგონილი სტატიკური ნაგულისხმევი ინსტრუმენტების სია არ არსებობს
(`open-sse/executors/claude-web/payload.ts:102`).

ამის ნაცვლად, ბრაუზერული მოთხოვნები იჭერს ავტორიზებული UI-ის მოთხოვნას და ინარჩუნებს მის ანგარიშის ინსტრუმენტებს, ინსტრუმენტების მდგომარეობებსა და პერსონალიზებულ სტილებს. მომზადებული საუბრის, მოდელის, მსჯელობის, პრომპტისა და შეტყობინების UUID ველები კვლავ გადაწერს დაჭერილ მოთხოვნას
(`open-sse/executors/claude-web/browserTransport.ts:175`). ბრაუზერის შაბლონების არეალი განისაზღვრება ანგარიშის, ორგანიზაციის, cookie-ის, ლოკალისა და დროის სარტყლის ჰეშით და მათ ვადა 30 წუთის შემდეგ გასდით
(`open-sse/executors/claude-web/browserTransport.ts:11`,
`open-sse/executors/claude-web/browserTransport.ts:158`). როდესაც პირდაპირ მოთხოვნას გამომძახებლის ინსტრუმენტები არ გააჩნია, მას შეუძლია ხელახლა გამოიყენოს ამ არეალის შაბლონი; გამომძახებლის აშკარად მითითებულ ინსტრუმენტებს უპირატესობა ენიჭება
(`open-sse/executors/claude-web/browserTransport.ts:214`).

### ტრანსპორტის არჩევა

ნაგულისხმევი გზაა `sendClaudeWebDirect()`, რომელიც კონფიგურირებული Chrome 146 პროფილითა და მიწოდებული cookie-ით იძახებს `tlsFetchClaude()`-ს (`open-sse/services/claudeTlsClient.ts:23`). იგი არც ამომხსნელს უშვებს და არც შემცვლელ cookie-ს ქმნის.

დააყენეთ `WEB_COOKIE_USE_BROWSER` მნიშვნელობაზე `1`, `true` ან `on`, რათა ანგარიშის ფარგლებში მოქმედი ბრაუზერის ადაპტერი ძირითად ტრანსპორტად იქცეს. დააყენეთ `OMNIROUTE_BROWSER_POOL` იმავე მნიშვნელობებიდან ერთ-ერთზე, რათა Cloudflare-ის ამოცნობილი 403 გამოწვევის შემთხვევაში პირდაპირი ტრანსპორტიდან ბრაუზერის ადაპტერზე სარეზერვო გადართვა იყოს შესაძლებელი (`open-sse/executors/claude-web.ts:195`). სხვა HTTP შეცდომები ამგვარ გადართვას არ იწვევს.

ბრაუზერის ადაპტერი cookie-ებს იმავე გაერთიანებულ Playwright კონტექსტში ინახავს, იყენებს ზემოთ აღწერილ, მოქმედების სფეროთი შეზღუდულ ჰეშირებულ გასაღებს და დასრულებულ პასუხს ამ კონტექსტიდან აგზავნის (`open-sse/executors/claude-web/browserTransport.ts:444`). ის ბრაუზერის მიერ მიღებულ cookie-ს პირდაპირ TLS კლიენტში არასოდეს გაიტანს. ბრაუზერში განმეორებითი მცდელობებისთვის საჭიროა ვადაგაუსვლელი UI შაბლონი, რომელიც იმავე რეალურ Playwright კონტექსტთანაა მიბმული (`open-sse/executors/claude-web/browserTransport.ts:467`). ბრაუზერის პასუხები ავტორიზებულ გვერდზე ეტაპობრივად იკითხება, ითვალისწინებს მოთხოვნის გაუქმებას და ზედა დონის პასუხის სხეულს აუქმებს, როგორც კი მისი ზომა 16 MiB-ს გადააჭარბებს (`open-sse/executors/claude-web/browserTransport.ts:259`).

შემსრულებელი გაზიარებულ მოთხოვნათა ჟურნალში რედაქტირებულ აუდიტის პროექციას აბრუნებს: ორგანიზაციის, საუბრისა და შეტყობინების UUID-ები, მოთხოვნის ტექსტი, ხელსაწყოების განსაზღვრებები, cookie-ები და მოწყობილობის იდენტიფიკატორები გამორიცხულია (`open-sse/executors/claude-web.ts:237`, `open-sse/executors/claude-web.ts:252`). ტრანსპორტის გამონაკლისები ასევე აბრუნებს კავშირის ზოგად შეცდომას და არა გამოტანილ შეტყობინებას.

### SSE-ის ქცევა

`createClaudeWebResponse()` ამუშავებს LF ან CRLF ჩარჩოებსა და მრავალხაზიან `data:` ველებს. ის ტექსტურ დელტებს `content`-ში, მსჯელობის დელტებს `reasoning_content`-ში, ხოლო ცნობილ მეტამონაცემთა მოვლენებს პასუხის `claude_web` გაფართოებაში ასახავს. თითოეული მეტამონაცემთა მოვლენა საკუთარი ველების დასაშვები სიის მეშვეობით პროეცირდება (`open-sse/executors/claude-web/stream.ts:37`). საუბრის, მშობელი შეტყობინების, ასისტენტის შეტყობინებისა და ოპერაციის მეტამონაცემები ასევე ბრუნდება `X-OmniRoute-Claude-Web-*` სათაურებში (`open-sse/executors/claude-web/stream.ts:364`).

პარსერი უსაფრთხოების მიზნით მუშაობას წყვეტს არასწორი JSON-ის, ზედა დონის `error` მოვლენების, უცნობი მოვლენის ტიპების, არასწორი თანმიმდევრობის, შიგთავსის ბლოკების შეუსაბამობის ან `message_stop`-მდე EOF-ის შემთხვევაში. ნაკადური გამომავალი გასცემს დასრულების ერთ ფრაგმენტსა და ერთ `[DONE]`-ს; ბუფერიზებული გამომავალი იმავე პარსერს იყენებს. პარსერი `message_stop`-ს დაუყოვნებლივ მიიჩნევს ტერმინალურად, აუქმებს ზედა დონიდან შემდგომ მონაცემებს და ქვედა დონის გაუქმებას ზედა დონის წამკითხველს გადასცემს (`open-sse/executors/claude-web/stream.ts:461`, `open-sse/executors/claude-web/stream.ts:563`). დაუსრულებელი SSE ხაზებისა და დაგროვილი მოვლენების ზომა შეზღუდულია 1 MiB-მდე (`open-sse/executors/claude-web/stream.ts:17`, `open-sse/executors/claude-web/stream.ts:62`).

### დაყენება

1. გაუშვით OmniRoute ბრძანებით `npm run dev` ან აწყობილი ინსტალაციიდან.

3. აირჩიეთ Web Cookie კატეგორია და Claude Web.
4. ჩასვით ავტორიზებული `claude.ai` მოთხოვნიდან დაკოპირებული სრული Cookie სათაური.
