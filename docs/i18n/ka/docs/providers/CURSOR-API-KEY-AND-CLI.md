Cursor-ის OmniRoute-ის უკან IDE სესიის გარეშე განთავსების ორი გზა:

1. **`cursor-api` პროვაიდერი** (ბარათი „Cursor API“, ფსევდონიმი `cua`): API გასაღებზე
   დაფუძნებული პროვაიდერი, რომელიც ინახავს Cursor-ის მომხმარებლის API გასაღებს (`crsr_…`,
   გენერირდება მისამართზე `https://cursor.com/dashboard/api`). შემდეგ OmniRoute-ის ნებისმიერ
   კლიენტს შეუძლია Cursor-ის მოდელებთან წვდომა `/v1/chat/completions`-ის გავლით,
   `cursor-api/<model>`-ის ან `cua/<model>`-ის სახით, კვოტის, სარეზერვო გადართვისა და
   ჟურნალებში ჩაწერის სტანდარტული შრეებით. IDE პროვაიდერი (`cursor`, OAuth/IDE სესია)
   უცვლელია.
2. **Cursor CLI-ის გამჭოლი გადაცემა**: მიმართეთ Cursor CLI (`agent`) OmniRoute-ზე, რათა
   CLI-ის მიერ შესრულებული ყოველი RPC ავთენტიფიცირდეს OmniRoute-ის API გასაღებით,
   გადაეგზავნოს Cursor-ს `cursor-api` კავშირის ავტორიზაციის მონაცემებით და აღირიცხოს
   Logs გვერდზე.

## რატომ ხდება გასაღების გაცვლა

`api2.cursor.sh` უარყოფს დაუმუშავებელ `crsr_…` გასაღებს Bearer ტოკენის სახით (401). Cursor
CLI თავდაპირველად POST მოთხოვნით აგზავნის გასაღებს `/auth/exchange_user_api_key`-ზე და იღებს
სესიის JWT-ს, რომელსაც ვადა ერთი საათის შემდეგ გასდის; დაბრუნებულ `refreshToken`-ს იგივე
`exp` აქვს, ამიტომ განახლება გასაღების ხელახლა გაცვლას ნიშნავს.
`open-sse/services/cursorApiKeyAuth.ts` ასრულებს ამ გაცვლას, თითოეული გასაღებისთვის
ქეშში ინახავს ერთ სესიის ტოკენს, ვადის გასვლამდე ხუთი წუთით ადრე ხელახლა ცვლის მას და
Cursor-ისგან 401 პასუხის მიღებისას ქეშირებულ ტოკენს შლის. `CursorExecutor` მას იძახებს
`cursor-api` კავშირებისთვის ზედა დონის ნაკადის გახსნამდე უშუალოდ.

## `cursor-api` პროვაიდერი

რეესტრი: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, იგივე `format`, `baseUrl` და
`models`, რაც `cursor`-ს აქვს). კატალოგის ბარათი:
`src/shared/constants/providers/apikey/specialty-media.ts`. შემსრულებლების რუკა:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

მართვის პანელი: Providers → Cursor API → Add API key.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

შემდეგ:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

შენიშვნები:

- `cursor-api`-ის მოდელების სია მიიღება Cursor-ის სტატიკური რეესტრიდან (იგივე
  სია, რომელსაც IDE პროვაიდერი სარეზერვოდ იყენებს); OmniRoute-ის ჰოსტზე
  `cursor-agent`-ის დაყენება საჭირო არ არის.
- `POST /api/providers/{id}/refresh-cursor` განკუთვნილია მხოლოდ `cursor` IDE
  პროვაიდერისთვის; `cursor-api` კავშირებს გასაახლებელი IDE სესია არ აქვთ.

## Cursor CLI-ის გამჭოლი გადაცემა

მარშრუტი: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. პრეფიქსი `/api/cursor-cli/`
რეგისტრირებულია `src/shared/constants/publicApiRoutes.ts`-ში, რადგან დამმუშავებელი
საკუთარ ავთენტიფიკაციას თავად ახორციელებს:

| გზა                                                                                                                        | CLI-სგან მოსალოდნელი ავთენტიფიკაცია | რას აკეთებს OmniRoute                                                                                                                                                    |
| -------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `POST /auth/exchange_user_api_key`                                                                                         | `Bearer <OmniRoute API key>`        | ამოწმებს გასაღებს, ქმნის 1-საათიან HS256 JWT-ს (`JWT_SECRET`-ით ხელმოწერილს) და აბრუნებს მას                                                                             |
| ყველა სხვა გზა (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`                 | ამოწმებს გამომცემელს/აუდიტორიას/ვადას, ირჩევს აქტიურ `cursor-api` კავშირს, Authorization სათაურს ანაცვლებს გაცვლილი Cursor ტოკენით და პასუხს ნაკადის სახით უკან აგზავნის |

CLI მიღებული ნებისმიერი ტოკენიდან დეკოდირებს `exp`-ს, ამიტომ გაუმჭვირვალე
ტოკენის გადაცემა აიძულებს მას, თითქმის ყოველი მოთხოვნის წინ ხელახლა შეასრულოს გაცვლა;
შექმნილი JWT ამას თავიდან იცილებს. OmniRoute-ისგან მიღებული 401 CLI-ს აიძულებს,
გაცვლა ხელახლა შეასრულოს.

### გამართვა

1. შექმენით OmniRoute-ის API გასაღები (Dashboard → API keys) და `cursor-api`
   კავშირი.
2. მიუთითეთ CLI-ს, გამოიყენოს HTTP/1.1 აგენტის ნაკადისთვის.
   `~/.cursor/cli-config.json`-ში:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   ამის გარეშე CLI აგენტის სვლას HTTP/2-ის მეშვეობით ხსნის ცალკე
   კონფიგურირებულ აგენტის ჰოსტზე და endpoint-ის გავლით მხოლოდ მართვის სიბრტყის RPC-ები
   გადის.

3. გაუშვით CLI OmniRoute-ის მისამართით:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

ყოველი გადასვლა ხვდება Logs-ში პროვაიდერით `cursor-api`, მოთხოვნის ტიპით `cursor-cli`,
გზით `/api/cursor-cli/<rpc>` და მიეწერება OmniRoute-ის API გასაღებსა და იმ
კავშირს, რომელმაც მას მოემსახურა.

### შეცდომის შემთხვევები

| სიტუაცია                                            | პასუხი CLI-სთვის                                 |
| --------------------------------------------------- | ------------------------------------------------ |
| უცნობი OmniRoute გასაღები და `REQUIRE_API_KEY=true` | გაცვლისას 401 `unauthenticated`                  |
| `REQUIRE_API_KEY=false`                             | ანონიმური სესია (იმეორებს `/v1/*`-ის ქცევას)     |
| ვადაგასული / უცხო / შეცვლილი სესიის JWT             | 401, CLI ხელახლა ახორციელებს გაცვლას             |
| გაცვლის შემდეგ გაუქმებული OmniRoute API გასაღები    | 401 მომდევნო RPC-ზე                              |
| აქტიური `cursor-api` კავშირი არ არის                | 503 `unavailable`                                |
| Cursor უარყოფს კავშირის გასაღებს                    | 401 `unauthenticated`, ქეშირებული სესია წაიშლება |
| ზედა დონის სერვისი მიუწვდომელია                     | 502 `unavailable` (გასუფთავებული შეტყობინება)    |
| `JWT_SECRET` არ არის დაყენებული                     | გაცვლისას 503                                    |
