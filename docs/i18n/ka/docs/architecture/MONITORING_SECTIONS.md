## მონიტორინგის სექცია (რეორგანიზებული)

მონიტორინგის სექციაში ახლა **აქტივობა ზედა ნაწილშია**, რასაც მოჰყვება **3 ქვეჯგუფი**:

```
მონიტორინგი
├── აქტივობა             ← ქრონოლოგიური ლენტი (ზედა დონის ელემენტი)
├── ჟურნალების ჯგუფი
│   ├── ჟურნალები (ყველა)
│   ├── პროქსის ჟურნალები
│   └── კონსოლის ჟურნალები
├── აუდიტის ჯგუფი
│   ├── აუდიტის ჟურნალი
│   ├── MCP აუდიტი
│   └── A2A აუდიტი
└── სისტემის ჯგუფი
    ├── მდგომარეობა
    └── შესრულების გარემო
```

### მაღალი დონის მოქმედებების ნებადართული სია

განსაზღვრულია `src/lib/audit/highLevelActions.ts`-ში. აკონტროლებს, რომელი მოვლენები
გამოჩნდება აქტივობის ლენტში. ნებადართული სია მოიცავს:

- პროვაიდერის დამატების/წაშლის/ტესტირების მოვლენებს
- კომბოს შექმნას/განახლებას/წაშლას
- API გასაღების სასიცოცხლო ციკლს (შექმნა, გაუქმება, როტაცია)
- ბიუჯეტის ზღვრული მნიშვნელობის მიღწევას
- ავთენტიფიკაციისას სისტემაში შესვლას/გასვლას
- ღრუბლოვანი აგენტის სესიის შექმნას
- MCP ხელსაწყოს რეგისტრაციას
- ვებჰუკის შექმნას/წაშლას
- კვოტის პულის/გეგმის ცვლილებებს (`quota.*` მოქმედებები, B ჯგუფი)
- პლატფორმის მოვლენებს (განახლება, განთავსება)
- უნარის ინსტალაციას/წაშლას

ამ სიაში არშემავალი მოვლენები მხოლოდ აუდიტის ჟურნალში გამოჩნდება.

### ახალი მაღალი დონის მოქმედების დამატება

დაარედაქტირეთ `src/lib/audit/highLevelActions.ts` და დაამატეთ მოქმედების სტრიქონი
`HIGH_LEVEL_ACTIONS`-ში. ამისთვის საჭიროა PR (სია კოდშია და არა DB-ის საშუალებით კონფიგურირებადი).
შესაბამისი ხატულა შეგიძლიათ დაამატოთ `src/lib/audit/activityIcons.ts`-ში.

## გადამისამართება: `/dashboard/logs/activity`

ძველი ბილიკი `/dashboard/logs/activity` სამუდამოდ გადამისამართდება (HTTP 308)
`/dashboard/activity`-ზე `permanentRedirect()`-ის მეშვეობით
`src/app/(dashboard)/dashboard/logs/activity/page.tsx`-ში.

გვერდითი ზოლის მოძველებული ID `logs-activity` შენარჩუნებულია `HIDEABLE_SIDEBAR_ITEM_IDS`-ში
(მაგრამ ამოღებულია `SIDEBAR_DEFINITIONS`-იდან), რათა არ დაზიანდეს მომხმარებელთა ის წინასწარი
პარამეტრები, რომლებიც ძველ ID-ს ეყრდნობა.
