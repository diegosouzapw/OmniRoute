`devin-cli-agentic` საშუალებას აძლევს რეალურ Claude Code-ის გარემოს, გამოიყენოს OmniRoute-ის ლოკალური Anthropic
Messages-ის endpoint, მაშინ როცა ოფიციალური Devin CLI მოდელის პასუხებს ACP stdio-ის მეშვეობით აწვდის. ის
არ ცვლის არსებულ Anthropic, Claude OAuth, Claude Web ან `devin-cli` პროვაიდერებს.

> **მიმდინარე სტატუსი: Claude Code დაფიქსირებულია ვერსიაზე `2.1.258`; ოფლაინ და რეალური გარემოს ვალიდაცია ბოლოს
> დაფიქსირდა ვერსიაზე `2.1.220`.** `2.1.220`-ზე დაფიქსირებულმა ვერსიამ დაასრულა სამი იზოლირებული სცენარი Devin CLI-ის
> `3000.2.17` ვერსიისა და `swe-1-7-lightning` მოდელის მეშვეობით; ამ საბოლოო რეალურმა გაშვებამ დაადასტურა კლიენტის მიერ მართული `Read`,
> `Edit` და `Bash` ოპერაციები, `npm test`-ის წარმატებული შედეგები, პროექტის ბრძანებებისა და უნარების
> აღმოჩენა, მხოლოდ Devin-ზე მარშრუტიზაცია და Claude-ისკენ ნულოვანი გამავალი ტრაფიკი. ამის შემდეგ დაფიქსირებული ვერსია განახლდა `2.1.258`-მდე
> (CLI-ის თაობა, რომელსაც OmniRoute-ის Claude-ის იდენტობა განასახიერებს, და პირველი ხაზი, რომელსაც
> Fable 5.1 დონე ნატიურად მოჰყვება). ახალ დაფიქსირებულ ვერსიაზე ინსტალაციის შრე და `claude --version`
> შემოწმდა დაფიქსირებულ საბაზისო image-ზე, ხოლო ხიდის unit-ტესტების ნაკრები, `compose config` და
> სტატიკური იზოლაციის მტკიცებულება წარმატებით სრულდება — თუმცა ოფლაინ mock-სცენარი და რეალური სამსცენარიანი
> ნაკრები ჯერ ხელახლა არ გაშვებულა. ხიდის ამ დაფიქსირებული ვერსიით გამოყენებამდე ხელახლა გაუშვით ისინი
> (იხილეთ "დაფიქსირებული ხელსაწყოების განახლება").

## არქიტექტურა

```text
Claude Code 2.1.258 (იზოლირებული არა-root Linux-კონტეინერი)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-ის ფორმატი, ავთენტიფიკაციის გარეშე პროვაიდერი)
  -> devin acp --agent-type summarizer (ოფიციალური ACP stdio, Devin-ის ხელსაწყოების გარეშე)
  -> Devin-ის ანგარიში გამოყოფილ devin-auth ტომში
```

ოფიციალური CLI-ის ნაგულისხმევ ACP აგენტს საკუთარი ხელსაწყოების შესრულება შეუძლია, ამიტომ ეს ხიდი მას
არ იყენებს. ის უშვებს ფიქსირებულ `summarizer` ACP აგენტს, რომლის ოფიციალურ CLI რეჟიმსაც ხელსაწყოები არ აქვს, და
სერიალიზებულ Anthropic მოთხოვნას შესრულების კვალის სახით აფორმებს. როდესაც Claude-ის მიერ მართული სხვა
ქმედებაა საჭირო, პასუხი ზუსტად ერთ კლიენტის ხელსაწყოს კონვერტს უნდა შეიცავდეს. ნებისმიერი ACP
`tool_call` ან `tool_call_update` უარყოფილია მანამ, სანამ პასუხი წარმატებულად
ჩაითვლება.

სერიალიზატორი `open-sse/executors/devin-agentic/serializer.ts`-ში ინარჩუნებს `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` და Claude Code-ის მიერ
მიწოდებულ ხელსაწყოებს. სურათები და უცნობი ბლოკები ცალსახა შეცდომით სრულდება. ხელსაწყოების დიდი შედეგები
იყენებს ხილულ შეკვეცის მარკერს.

პარსერი მოდელის თითოეული პასუხისთვის იღებს ერთ დამოუკიდებელ `<tool>{...}</tool>` კონვერტს. ის ამოწმებს
სახელს მოთხოვნის ხელსაწყოების სიასთან, არგუმენტებს ამ ხელსაწყოს JSON
Schema-ს მიხედვით ამოწმებს, უარყოფს თხრობისა და ქმედებების შერევას და უშვებს ერთ შეზღუდულ შესწორებას. შემდეგ Claude Code
მიღებულ Anthropic `tool_use`-ს ლოკალურად ასრულებს და `tool_result`-ს OmniRoute-ის გავლით
უკან აგზავნის.

## იზოლაცია და საფრთხეების მოდელი

ჰოსტის Claude-ის ინსტალაცია, ანგარიში და კონფიგურაცია განხილვის ფარგლებს მიღმაა და
აკრძალულად განიხილება. Compose სერვისები:

- მუშაობენ UID/GID `10001:10001`-ით, მხოლოდ წაკითხვადი root-ფაილური სისტემით, ჩამოშორებული შესაძლებლობებითა და
  `no-new-privileges` რეჟიმით;
- იყენებენ კერძო `/home/bridge`-ს, გამოყოფილ Claude-ის კონფიგურაციის ტომს, იზოლირებულ OmniRoute-ის მონაცემებს
  და ცალკე `devin-auth` ტომს;
- ამონტაჟებენ მხოლოდ დროებით `.sandbox` სამუშაო სივრცეებს/მტკიცებულებებს;
- არ ამონტაჟებენ ჰოსტის home-ს, Keychain-ს, SSH-ს, ღრუბლოვან ავტორიზაციის მონაცემებს ან Docker-ის სოკეტს;
- ქმნიან ცალსახად განსაზღვრულ გარემოებს და შლიან Anthropic API/OAuth/მარშრუტიზაციის ცვლადებს;
- Claude Code-ის ინფერენციას მიმართავენ მხოლოდ `http://omniroute:20128`-ზე, მხოლოდ ლოკალური გასაღებით.

ოფლაინ პროფილი შიდა ქსელს იყენებს. რეალურ პროფილში OmniRoute ოფიციალურ
Devin-ის endpoint-ებს მხოლოდ `network-guard`-ის გავლით უკავშირდება; დაუკავშირებელი დანიშნულების მისამართები იბლოკება.
Claude Code-ს აქვს ცალკე, ყველა გამავალი კავშირის ამკრძალავი დამცავი და `NO_PROXY`-ის მეშვეობით მხოლოდ ლოკალურ OmniRoute
სერვისთან დაკავშირება შეუძლია. დამცავის აუდიტის ფაილები მხოლოდ შესაბამისი დამცავი პროცესის მიერ არის დამონტაჟებული.
სკრიპტები ამოწმებს ფაილის მფლობელობას, რეჟიმს, ბმულების რაოდენობასა და ყველა გადაწყვეტილებას, სანამ
ტოკენებისგან თავისუფალ მტკიცებულებებს ექსპორტზე გაიტანს.

იზოლაციის მტკიცებულება დამოუკიდებლად გაუშვით:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

ის ამოწმებს ტოპოლოგიას, სახელდებულ mount-ებს, არა-root/მხოლოდ წაკითხვად პარამეტრებს, ცალსახა ლოკალურ მარშრუტიზაციას,
სენსიტიური გარემოს ცვლადების არარსებობას, Docker-ის სოკეტის არარსებობას, `api.anthropic.com`-სა და `claude.ai`-ზე
წვდომის დაბლოკვას, მხოლოდ Devin-ის პროვაიდერის არჩევას და ცალსახა წარუმატებლობას, როდესაც
ACP backend მიუწვდომელია.

## პირველი დაყენება და ჩვეულებრივი გამოყენება

ააგეთ ფიქსირებულ ვერსიებზე მიბმული image:

```bash
./scripts/devin-bridge/build
```

ავთენტიფიკაცია გაიარეთ მხოლოდ იზოლირებულ Devin volume-ში:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

შესვლის ბრძანება იყენებს ოფიციალურ, ხელით შეყვანად token-ზე დაფუძნებულ პროცესს, რომელიც განკუთვნილია დისტანციური/container გარემოებისთვის. მნიშვნელობა უშუალოდ CLI-ის მოთხოვნაში შეიყვანება; ის არ გადაიცემა პროცესის არგუმენტად, არ იწერება Git-ში და არ კოპირდება ჰოსტიდან.

გაუშვით იზოლირებული Claude Code runtime:

```bash
./scripts/devin-bridge/launch
```

`launch` container-ში გაშვებული Claude Code-ის დაწყებამდე ხელახლა ამოწმებს იზოლაციას, Devin-ის ავთენტიფიკაციასა და მოდელების აღმოჩენას. ის არასოდეს უშვებს ჰოსტის Claude-ის executable ფაილს. მოდელების alias-ები შეიძლება განისაზღვროს `.env.devin-bridge`-ში; თითოეულმა კონფიგურირებულმა მნიშვნელობამ უნდა შეინარჩუნოს `devin-cli-agentic/` პრეფიქსი.

## ვალიდაციის ბრძანებები

კვლავწარმოებადი ოფლაინ-გზა არ საჭიროებს Devin-ის ანგარიშს და runtime-ის დროს ინტერნეტთან წვდომა არ აქვს:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

ავთენტიფიცირებული, ნებაყოფლობით ჩასართავი რეალური გზა არის:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

## ფიქსირებულ ვერსიებზე მიბმული ხელსაწყოების განახლება

image-ში Node-ის, Claude Code-ისა და Devin CLI-ის ვერსიები ფიქსირებულია `docker/devin-bridge/Dockerfile`-ში. განახლებისთვის:

1. შეცვალეთ ცხადად მითითებული ვერსიები;
2. არქიტექტურების მიხედვით განსაზღვრული Devin-ის არქივის ორივე checksum ჩაანაცვლეთ ოფიციალური არტეფაქტის შესაბამისი მნიშვნელობებით;
3. ხელახლა ააგეთ და გაუშვით ოფლაინ-ვალიდაციის ყველა ბრძანება;
4. დაადასტურეთ image-ში არსებული ვერსიები;
5. ხელახლა გაუშვით ავთენტიფიცირებული, სამსცენარიანი რეალური ტესტების ნაკრები.

ნუ დააყენებთ არცერთ CLI-ს გლობალურად ჰოსტზე და ნუ ჩაანაცვლებთ checksum-ის შემოწმებას შეუმოწმებელი ჩამოტვირთვით.
