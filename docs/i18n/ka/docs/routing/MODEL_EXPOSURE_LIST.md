> ამიტომ `/v1/models` კატალოგი და ყოველი `auto/*` კანდიდატთა ნაკრები ბაიტურად იდენტური რჩება). ეს არის
> `hidePaidModels`/`hideAutoCombos`-ის მონათესავე პარამეტრი (`src/lib/db/settings.ts`) იმ ოპერატორებისთვის, რომლებსაც
> სურთ მოდელების კურირებული სია ღირებულებასთან სრულიად დაუკავშირებელი მიზეზებით.

## რატომ არსებობს ეს

`hidePaidModels` პასუხობს კითხვას „არის თუ არა ეს მოდელი უფასო?“, ხოლო `hideAutoCombos` — „უნდა გამოჩნდეს თუ არა

> საერთოდ `auto/*` ვირტუალური id-ები?“ — თუმცა არცერთი მათგანი არ აძლევს ოპერატორს მოდელების ნებისმიერი ქვესიმრავლის
> კურირების საშუალებას (მაგ., ზუსტად იმ მოდელების ჩვენებას, რომლებიც კონკრეტულმა Claude Code / OpenCode კლიენტმა უნდა
> იხილოს, ფასისგან დამოუკიდებლად). #11481 ამას ამატებს ორი დამოუკიდებელი, ნებაყოფლობით ჩასართავი სტრიქონების მასივის პარამეტრის სახით.

## პარამეტრები

| გასაღები                   | ტიპი       | ნაგულისხმევი მნიშვნელობა | მნიშვნელობა                                                                     |
| -------------------------- | ---------- | ------------------------ | ------------------------------------------------------------------------------- |
| `modelVisibilityDenylist`  | `string[]` | `[]`                     | კანდიდატთან შესატყვისი ჩანაწერები მას კატალოგიდან/კანდიდატთა ნაკრებიდან მალავს. |
| `modelVisibilityAllowlist` | `string[]` | `[]`                     | როდესაც ცარიელი არ არის, ხილული რჩება მხოლოდ კანდიდატთან შესატყვისი ჩანაწერები. |

ორივე იღებს მაქსიმუმ 500 ჩანაწერს, თითოეული მაქსიმუმ 200 სიმბოლოთი (Zod-ის მეშვეობით ვალიდირდება
`src/shared/validation/settingsSchemas.ts`-ში). ჩანაწერი არის ერთ-ერთი შემდეგიდან:

- კატალოგის ზუსტი id — `"gpt-4o"` (მოდელის უბრალო id) ან `"openai/gpt-4o"` (პროვაიდერის პრეფიქსით), ან
- `*`/`?`-ის გამოყენებით შედგენილი glob-შაბლონი — მაგ., `"openai/gpt-4*"` ან `"anthropic/*"` — რომელიც მუშავდება
  იმავე საერთო `globToRegex()` შემდარებლის (`src/shared/utils/globPattern.ts`) მეშვეობით, რომელსაც უკვე იყენებს
  `ModelRoutingSection`-ის თითოეული მოდელის combo-შესაბამისობები და `freeModels.ts::matchesOnlyPaidModels`.

პრიორიტეტი: თავდაპირველად მოწმდება აკრძალვის სია (აკრძალული ჩანაწერი ყოველთვის დამალულია, მაშინაც კი, თუ ის
ნებართვის სიასაც ემთხვევა); როდესაც ნებართვის სია ცარიელი არ არის, გადარჩება მხოლოდ მასთან შესატყვისი ჩანაწერები.

## ორი საკონტროლო წერტილი და არა ერთი

#6512-იდან მიღებული გაკვეთილი (მხოლოდ `hidePaidModels`-ზე დაფუძნებული კატალოგის ფილტრი კვლავ აძლევდა `auto/*`-ს
ფასიან მოდელზე მარშრუტიზაციის საშუალებას, რადგან combo-ს კანდიდატთა ნაკრები დამოუკიდებლად იქმნებოდა) აქაც ზუსტად
იგივე სახით ვრცელდება. შესატყვისობის პრედიკატი `isModelExposureAllowed()` (`src/shared/utils/modelExposureList.ts`)
გამოიძახება ორივე ადგილიდან:

- `src/app/api/v1/models/catalog.ts` — თავად `/v1/models` სია, იმავე 5, თითოეულ წყაროზე არსებულ
  საკონტროლო წერტილში, რომლებსაც უკვე აკონტროლებს `shouldHidePaid()` (სტატიკური `PROVIDER_MODELS`, სინქრონიზებული პროვაიდერის ჩანაწერები,
  მორგებული ჩანაწერები, alias-ზე დაფუძნებული ჩანაწერები, მართული fallback-ჩანაწერები).
- `open-sse/services/autoCombo/modelExposureFilter.ts::filterModelExposureCandidates()` — გამოიძახება
  `virtualFactory.ts::buildPreparedPool`-იდან, შესაბამისი `filterPaidOnlyCandidates()` გამოძახებისთანავე,
  ამიტომ აკრძალული მოდელი ვერც `auto/*` კანდიდატთა ნაკრებში მოხვდება შესარჩევად.

## რა არ იფილტრება

ეს იმეორებს `hideAutoCombos`-ის არსებულ ქცევას: **ცხადად** გაგზავნილი მოდელის id (არა `auto/*`-ის მეშვეობით
და არა კატალოგის სიაში აღმოჩენის გზით) dispatch-ის ეტაპზე არასოდეს იბლოკება — იფილტრება მხოლოდ
გამოქვეყნება/კანდიდატთა ნაკრების წევრობა. ეს `hidePaidModels`-ისგან დამოუკიდებელია;
ოპერატორს შეიძლება სურდეს კურირებული ნაკრები ღირებულებასთან სრულიად დაუკავშირებელი მიზეზებით, ამიტომ ორივე
პარამეტრი ერთიანდება როგორც დამოუკიდებელი AND-ით დაკავშირებული ფილტრები, ისევე როგორც არსებული მრავალი დროშის კომპოზიცია
`catalog.ts`-ში.

პარამეტრების ექსპორტი (`GET /api/settings/export-json`) ორივე მასივს უცვლელად მოიცავს, როგორც პარამეტრების ნებისმიერ სხვა
ველს — `hidePaidModels`-ის combo-ნაბიჯის ექსპორტის ფილტრისგან განსხვავებით, აქ ხელახალი ჰიდრატაციის
რისკი არ არსებობს: ექსპორტირებულ combo-ნაბიჯში ჩაშენებული აკრძალული id ოპერატორის მიერ ცხადად არჩეული მარშრუტიზაციაა
და არა ის, რაც ექსპორტის საზღვარმა უნდა ამოიღოს.
