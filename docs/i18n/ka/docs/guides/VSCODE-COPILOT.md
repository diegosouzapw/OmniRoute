## გამართვა

1. **გაუშვით OmniRoute** — `npm install -g omniroute && omniroute` (მართვის პანელი მისამართზე `http://localhost:20128`).
2. **დააინსტალირეთ გაფართოება** — Extensions ხედში მოძებნეთ "OmniRoute".
3. **აირჩიეთ მოდელი** — Copilot Chat → მოდელების ამომრჩეველი → **მოდელების მართვა…** → **OmniRoute**, შემდეგ მონიშნეთ
   სასურველი მოდელები.

როდესაც OmniRoute ნაგულისხმევ პორტზე მუშაობს, კონფიგურაცია საჭირო არ არის. დისტანციური ინსტანციისთვის გახსენით
**OmniRoute-ის ხატულა Activity Bar-ში** (ან გაუშვით `OmniRoute: Manage Connection`) და მიუთითეთ:

- **სერვერის URL** — სერვერის ძირეული მისამართი, მაგალითად `http://192.168.0.15:20128`. სუფიქსს `/v1`
  გაფართოება თავად დაამატებს; ნუ მიუთითებთ მას.
- **API გასაღები** — მხოლოდ მაშინ, როდესაც სერვერზე დაყენებულია `REQUIRE_API_KEY`. ინახება ოპერაციული სისტემის გასაღებების საცავში VS
  Code SecretStorage-ის მეშვეობით და არასოდეს — `settings.json`-ში.

## რას აჩვენებს ამომრჩეველი

გაფართოება პირდაპირ არ აჩვენებს `GET /v1/models` მოთხოვნის დაუმუშავებელ პასუხს — ის მას ამუშავებს, ამიტომ ნაჩვენები
რაოდენობა კატალოგის ზომაზე ნაკლებია ორი წინასწარგანზრახული მიზეზის გამო.

### თითოეული მოდელისთვის ის ერთ id-ს ითხოვს

`MODELS_CATALOG_PREFIX_MODE`-ის ნაგულისხმევი მნიშვნელობაა **`dual`**, რომელიც თითოეულ მოდელს ორჯერ აქვეყნებს — ერთხელ
მოკლე ფსევდონიმის პრეფიქსით და ერთხელ პროვაიდერის კანონიკური პრეფიქსით — რათა ძველი კლიენტების
კონფიგურაციებმა ორივე ფორმის ამოცნობა განაგრძონ:

```
cc/claude-sonnet-4-6        ← ფსევდონიმის პრეფიქსი
claude/claude-sonnet-4-6    ← კანონიკური პრეფიქსი, იგივე მოდელი
```

გაფართოება აგზავნის მოთხოვნას **`GET /v1/models?prefix=alias`**, რათა თითოეულ მოდელზე ერთი id მიიღოს,
თქვენი სხვა კლიენტებისთვის სერვერის საერთო პარამეტრის შეცვლის გარეშე. საცნობარო ინსტანციაზე ამან
**2345 ჩანაწერი 1396-მდე შეამცირა — 949 დუბლიკატი, დაკარგული მოდელების გარეშე.**

თუ გსურთ, ეს სერვერის დონეზე _ყველა_ კლიენტისთვის გამოასწოროთ,
მართვის პანელში `MODELS_CATALOG_PREFIX_MODE` ფუნქციის ალამს მნიშვნელობად `alias` მიანიჭეთ. იხილეთ
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix), სადაც აღწერილია
მოთხოვნის პარამეტრი და თითოეული რეჟიმის ცხრილი.

### ის მალავს მოდელებს, რომლებსაც ჩატი არ შეუძლიათ

კატალოგში ასევე ჩამოთვლილია გამოსახულების, ვიდეოს, აუდიოს, რერანჟირების, embedding-ისა და მოდერაციის მოდელები. ჩატის მოთხოვნისას
ისინი ნებისმიერ შემთხვევაში უარყოფილი იქნება:

```
HTTP 400 — Model '<id>' is an image-generation model and cannot be used on
/v1/chat/completions. Use POST /v1/images/generations instead.
```

ამიტომ ამომრჩევლამდე მისვლამდე ისინი `type` ველის მიხედვით იფილტრება. **Responses-API-ის
მოდელები შენარჩუნებულია** — Codex / GPT-5.x-ის თითოეული ჩანაწერი აცხადებს `supported_endpoints: ["responses"]`,
ხოლო OmniRoute მათ `/v1/chat/completions`-ისთვის გარდაქმნის, ამიტომ მათი გამოყენება სრულად შესაძლებელია.

### პროვაიდერები, რომლებიც არასოდეს დაგიკონფიგურირებიათ

კატალოგში ჩამოთვლილია მოდელები **აქტიური კავშირის** მქონე პროვაიდერებიდან და ასევე ყველა **noAuth**
პროვაიდერიდან — გასაღების არმომთხოვნი პროვაიდერები, რომლებიც უფასო დონის დიდ ნაწილს შეადგენს. ეს წინასწარგანზრახული ქცევაა. მათ დასამალად
მართვის პანელის პარამეტრებში დაამატეთ ისინი `blockedProviders`-ში; გაფართოებაში არაფერი შეიცვლება.

## დაფა VS Code-ის ჩანართში

`omnicopilot.dashboardOpen: "editor"` OmniRoute-ის დაფას გარე ბრაუზერის ნაცვლად, Simple Browser-ის საშუალებით, რედაქტორის ჩანართში ასახავს. ჩაშენება **სერვერზე ცალკე უნდა ჩაირთოს** `DASHBOARD_ALLOW_EMBED=vscode`-ის მეშვეობით, რის შედეგადაც HTML გვერდები ნაგულისხმევი `frame-ancestors 'none'` + `X-Frame-Options: DENY`-ის ნაცვლად `frame-ancestors 'self' vscode-webview:`-ით მიეწოდება. API-ის ზედაპირი (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) ორივე შემთხვევაში მკაცრ სათაურებს ინარჩუნებს.

> ⚠️ **ეს აგების დროის დროშაა და არა შესრულების დროის.** Next.js `headers()`-ს მარშრუტების
> მანიფესტში აკომპილირებს, ამიტომ `next.config.mjs` ცვლადს პაკეტის აგებისას კითხულობს
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> უკვე აგებული სერვერის გაშვებამდე მისი ექსპორტირება არაფერს შეცვლის — სათაურები უკვე ჩაშენებულია.

```bash
# ცვლადი BUILD ბრძანების შესრულებისას უნდა იყოს მითითებული
DASHBOARD_ALLOW_EMBED=vscode npm run build        # ან npm run build:release
npm start
```

| ინსტალაციის მეთოდი         | შეგიძლიათ ჩაშენების ჩართვა?                                                                                                                                 |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| საწყისი კოდიდან            | ✅ მიუთითეთ ცვლადი აგების ბრძანებაში, როგორც ზემოთაა ნაჩვენები                                                                                              |
| `npm install -g omniroute` | ❌ გამოქვეყნებული პაკეტი წინასწარ აგებულ პაკეტს შეიცავს — ამის ნაცვლად ააგეთ საწყისი კოდიდან                                                                |
| Docker-ის იმიჯი            | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — Docker Hub-ზე განთავსებულ წინასწარ აგებულ იმიჯში ჩაშენება ჩართული არ არის |

ჩაშენების მხარდაჭერით აგებული ვერსიის გარეშე გვერდი ფრეიმში გახსნაზე უარს ამბობს; გაფართოება ამას პასუხის სათაურებიდან ამოიცნობს და გარე ბრაუზერზე გადაერთვება — არაფერი გაფუჭდება და გაფართოება ამის შესახებ ერთხელ შეგატყობინებთ.

## სხვა ხელსაწყოების კონფიგურაცია VS Code-იდან

**`OmniRoute: Configure Coding CLI`** `omniroute` CLI-ს მართავს და Codex CLI-სთვის, Claude Code-ისთვის, Cline-ისთვის, Continue-ისთვის, Cursor-ისთვის, Aider-ისთვის, OpenCode-ისთვის, Goose-ისთვის, Crush-ისთვის, Qwen Code-ისთვის, Kilo-სა და Roo-სთვის გამოსაყენებლად გამზადებულ პროფილებს ქმნის — ეს იგივე კონფიგურაციებია, რომლებიც აღწერილია
[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md)-ში. API-ის გასაღები CLI-ს `OMNIROUTE_API_KEY` გარემოს ცვლადის მეშვეობით გადაეცემა და არასდროს — ბრძანების სტრიქონიდან.
