მიუთითეთ **Claude Code** CLI-ს (`claude`) OmniRoute-ზე — ლოკალურად ან დისტანციურ VPS-ზე —
თითოეული მოდელისთვის ცალკე პროფილებით, Codex-ის კონფიგურაციის ანალოგიურად.

---

## სწრაფი დაწყება

```bash
# Claude Code-ის გაშვება ლოკალურ OmniRoute-ზე (აქტიურ კონტექსტს ავტომატურად ამოიცნობს)
omniroute launch

# დისტანციურ OmniRoute-ზე (`omniroute connect <host>`-ის შემდეგ ეს ავტომატურად ხდება)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# თითოეული მოდელისთვის პროფილების გენერირება, შემდეგ ერთ-ერთის გაშვება
omniroute setup-claude            # წერს ~/.claude/profiles/<name>/settings.json-ში
omniroute launch --profile glm52  # Claude Code, რომელიც OmniRoute-ის გავლით glm/glm-5.2-ს იყენებს
```

## როგორ უკავშირდება Claude Code კარიბჭეს

Claude Code იყენებს **Anthropic Messages API**-ს და მომხმარებლის მიერ მითითებულ
endpoint-ს გარემოს ცვლადების მეშვეობით უკავშირდება (მას `--base-url` პარამეტრი არ აქვს):

| ცვლადი                                       | დანიშნულება                                                                                                   |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `ANTHROPIC_BASE_URL`                         | კარიბჭის ძირეული URL (Claude Code ამატებს `/v1/messages`-ს). **`/v1` სუფიქსის გარეშე.**                       |
| `ANTHROPIC_AUTH_TOKEN`                       | იგზავნება როგორც `Authorization: Bearer …` — გამოიყენეთ თქვენი OmniRoute-ის წვდომის ტოკენი / API გასაღები     |
| `ANTHROPIC_API_KEY`                          | ალტერნატივა: იგზავნება როგორც `x-api-key`. თუ ორივეა მითითებული, უპირატესობა `ANTHROPIC_AUTH_TOKEN`-ს ენიჭება |
| `ANTHROPIC_MODEL`                            | კონკრეტული მოდელის იძულებით გამოყენება (`/model` ამრჩევის ნაგულისხმევ მნიშვნელობას ანაცვლებს)                 |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` → ჩაშენებული `/model` ამრჩევი `/v1/models`-დან ჩამოთვლის `claude*`/`anthropic*` მოდელებს                  |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`              | თითოეულ პასუხზე გამომავალი ტოკენების მაქსიმუმის შეზღუდვა (მაგ. `65536`)                                       |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`            | ტოკენების ზღვარი ავტომატური კომპაქტაციისთვის                                                                  |

> გარემოს ცვლადები იკითხება **მხოლოდ ერთხელ, გაშვებისას** — მათი შეცვლის შემდეგ გადატვირთეთ Claude Code.

`omniroute launch` ამ ყველაფერს თქვენთვის აკონფიგურირებს: ის აქტიური კონტექსტიდან
განსაზღვრავს საბაზისო URL-სა და ტოკენს (ამიტომ `omniroute connect <vps>`-ის, შემდეგ კი
`omniroute launch`-ის გაშვება პირდაპირ მუშაობს), ამოწმებს სერვერის მდგომარეობას და უშვებს `claude`-ს.

## აღმოჩენის ალიასები — არა-Claude მოდელების ჩვენება `/model` ამრჩევში

Claude Code-ის კარიბჭის მოდელების აღმოჩენის ფუნქცია ჩამოთვლის მხოლოდ იმ id-ებს, რომლებიც
იწყება `claude`-ით ან `anthropic`-ით, ამიტომ `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`-ის
შემთხვევაში ჩაშენებული `/model` ამრჩევი ჩვეულებრივ აჩვენებს OmniRoute-ის **მხოლოდ**
Claude/Anthropic მოდელებს — `kimi/kimi-k2.6` ან `glm/glm-5.2` არასოდეს გამოჩნდება,
მიუხედავად იმისა, რომ მათი მარშრუტიზაცია გამართულად მუშაობს.

OmniRoute-ს შეუძლია ნებისმიერი ჩართული მოდელი (და კომბინაცია) ასახოს `claude/…` id-ის ქვეშ,
რათა მან ეს ფილტრი გაიაროს და ამრჩევში გამოჩნდეს:

```
kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<კომბინაცია "custo-otimizado"> →  claude/combo/custo-otimizado
```

როდესაც Claude Code-ში ერთ-ერთ მათგანს ირჩევთ, OmniRoute მარშრუტიზაციამდე აშორებს
`claude/` გარსს და აღადგენს რეალურ id-ს — ნამდვილი `claude/<real-claude-model>` id
(რეალური Claude OAuth პროვაიდერი) ყოველთვის უცვლელი რჩება.

**ეს ფუნქცია ნაგულისხმევად გამორთულია** და იმართება სამდონიანი მექანიზმით (უფრო
კონკრეტულ დონეს უპირატესობა ენიჭება), ამიტომ ჩვეულებრივი OmniRoute არ აორმაგებს
კატალოგს იმ კლიენტებისთვის, რომლებიც Claude Code-ს არ იყენებენ:

| დონე       | მდებარეობა                                                                                 |
| ---------- | ------------------------------------------------------------------------------------------ |
| მოდელი     | პროვაიდერის დეტალების გვერდი → თითოეული მოდელის "Expose in Claude Code" გადამრთველი        |
| პროვაიდერი | პროვაიდერის დეტალების გვერდი → პროვაიდერის დონის გადამრთველი (მოიცავს მის ყველა მოდელს)    |
| გლობალური  | პარამეტრები → ფუნქციების ალმები → `EXPOSE_CC_DISCOVERY_ALIASES` (ნაგულისხმევად გამორთულია) |

`EXPOSE_CC_DISCOVERY_ALIASES` გარემოს ცვლადი გლობალურ დონეს იძულებით რთავს
და დაფიდან განსაზღვრულ მნიშვნელობაზე უპირატესობა აქვს (ფუნქციების ალმების ეკრანი
აჩვენებს შენიშვნას „აქტიურია გარემოს ცვლადის მეშვეობით“, როდესაც ეს ასეა).
თითოეული პროვაიდერისა და თითოეული მოდელის გადამრთველები იქიდან უფრო ზუსტად აკონკრეტებს
ქცევას — მაგალითად, თუ გლობალური დონე გამორთულია, ხოლო Kimi-ის პროვაიდერი ჩართულია,
ხელმისაწვდომი იქნება მხოლოდ Kimi-ის მოდელები.

> ⚠️ **ფანჯრის შეუსაბამობა არა-Claude მოდელებზე.** Claude Code მისთვის უცნობი ნებისმიერი
> id-ისთვის 200K-იან კონტექსტურ ფანჯარას ვარაუდობს (მას `/v1/models`-დან რეალური ფანჯრის
> წაკითხვა არ შეუძლია). უფრო დიდი ფანჯრის მქონე მოდელისთვის (მაგ. Kimi K2-ის 256K)
> დააყენეთ `CLAUDE_CODE_AUTO_COMPACT_WINDOW` მოდელის რეალურ ფანჯარაზე ნაკლებ მნიშვნელობაზე,
> რათა ავტომატური კომპაქტაცია ნაადრევად არ ამოქმედდეს. ზემოთ გენერირებული პროფილები ამას
> უკვე თითოეული მოდელისთვის ცალ-ცალკე აკეთებს.

## საწყისი კონფიგურაციის ბლოკი მართვის პანელზე

Claude-ის ხელსაწყოს ბარათი (**მართვის პანელი → CLI Code**) ამ ინსტანციისთვის განკუთვნილ ზუსტ `settings.json` ფრაგმენტს
აჩვენებს აღმოჩენის ფსევდონიმის საინფორმაციო ღილაკის გვერდით, კოპირების ღილაკთან ერთად:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<თქვენი OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<თქვენი OmniRoute API გასაღები>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}
```

საბაზისო URL არის ბარათის მიერ განსაზღვრული მისამართი (მათ შორის, თქვენ მიერ შეყვანილი მორგებული მნიშვნელობა), რომელიც უკვე
ნორმალიზებულია — `/v1` სუფიქსისა და ბოლოში დახრილი ხაზის გარეშე. **გასაღები არასდროს გამოისახება**: ბლოკი შეიცავს
ჩასანაცვლებელ ტექსტს, ამიტომ ეკრანის ანაბეჭდით ან ჩასმული ფრაგმენტით მისი გაჟონვა შეუძლებელია. მის ნაცვლად ჩასვით თქვენი გასაღები.

დაამატეთ `CLAUDE_CODE_AUTO_COMPACT_WINDOW` იმავე `env` ბლოკში ნებისმიერი მოდელისთვის, რომლის რეალური
კონტექსტის ფანჯარა 200K არ არის — Claude Code ყველა მისთვის უცნობი id-ისთვის 200K-ს ვარაუდობს, ამიტომ
წინააღმდეგ შემთხვევაში ავტომატური შეკუმშვა არასწორ მომენტში ამოქმედდება (იხილეთ გაფრთხილება წინა სექციაში).
ფრაგმენტის შემქმნელი ამ მნიშვნელობასაც იღებს, ამიტომ გამომძახებელს, რომელმაც სამიზნე მოდელის ფანჯრის ზომა იცის,
შეუძლია ის პირდაპირ გამოიტანოს.

წყარო: `src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet` (სუფთა
შემქმნელი, დაფარულია მოდულური ტესტებით), რომელსაც `ClaudeGatewayOnboardingBlock` გამოისახავს.

## პროფილები (`CLAUDE_CONFIG_DIR`)

Claude Code-ს **პროფილების ჩაშენებული ფაილები არ გააჩნია** (Codex-ის `~/.codex/<name>.config.toml`-ისგან განსხვავებით).
რეკომენდებული მექანიზმია `CLAUDE_CONFIG_DIR` — ცალკე კონფიგურაციის დირექტორია თითოეული
პროფილისთვის, რომელთაგან თითოეულს საკუთარი `settings.json`, ავტორიზაციის მონაცემები, ისტორია და კეში აქვს.

`omniroute setup-claude` იღებს აქტიურ `/v1/models` კატალოგს და თითოეული
მოდელისთვის ქმნის პროფილს მისამართზე `~/.claude/profiles/<name>/settings.json`, იმავე
სახელების გამოყენებით, რომლებსაც **`setup-codex` იყენებს** (`glm52`, `kimi-k27`, `deepseek-pro`, …):

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}
```

> **ავტორიზაციის ტოკენი პროფილში არასდროს იწერება.** გაუშვით
> `omniroute launch --profile <name>` (ის აქტიური კონტექსტიდან `ANTHROPIC_AUTH_TOKEN`-ს ჩასვამს),
> ან თავად გაიტანეთ `ANTHROPIC_AUTH_TOKEN` გარემოში და გაუშვით
> `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude`.

**ავტომატური სინქრონიზაცია მოდელების აღმოჩენის შემდეგ (სურვილისამებრ).** OmniRoute-ს შეუძლია იგივე
`~/.claude/profiles/<name>/settings.json` ფაილების ავტომატურად ხელახლა გენერირება ყოველ ჯერზე, როცა პროვაიდერის მოდელების
სინქრონიზაცია აქტიურ კატალოგს ცვლის — შედეგად, ახალი ან სახელგადარქმეული მოდელები პროფილებს ბრძანების ხელახლა
გაშვების გარეშე მიიღებენ. ეს **ნაგულისხმევად გამორთულია**: ჩართეთ **CLI Code-ის მართვის პანელიდან** („CLI პროფილების
ავტომატური სინქრონიზაცია“ → Claude Code), ან დააყენეთ `OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true` (ის ასევე ითვალისწინებს
`CLI_ALLOW_CONFIG_WRITES`-ს, რომელიც ნაგულისხმევად ჩართულია). ჩართვისას ის მხოლოდ პროფილის ფაილებს წერს; ის არასდროს
ცვლის თქვენს აქტიურ/ნაგულისხმევ Claude-ის კონფიგურაციას, ავტორიზაციას ან `~/.claude/settings.json`-ს.

### პროფილების გენერირება და გამოყენება

```bash
# ლოკალური OmniRoute
omniroute setup-claude

# დისტანციური VPS (VPS-ის URL-ს ყველა პროფილში ამატებს)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# მხოლოდ ზოგიერთი პროვაიდერი
omniroute setup-claude --only glm,kimi

# წინასწარი დათვალიერება ჩაწერის გარეშე
omniroute setup-claude --dry-run

# პროფილის გაშვება
omniroute launch --profile kimi-k27
```

## მოდელის დონეები (არასავალდებულო)

Claude Code მოთხოვნებს შესაძლებლობების დონეების მიხედვით ანაწილებს. თუ თითოეული დონისთვის სხვადასხვა პროვაიდერის გამოყენება გსურთ, env-ის /
პარამეტრების მეშვეობით თითოეული მათგანი OmniRoute-ის მოდელთან დააკავშირეთ:

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm/glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="kmc/kimi-k2.6"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="glm/glm-4.7-flash"
```

წინააღმდეგ შემთხვევაში, ყველაფრისთვის გამოიყენება ერთი `ANTHROPIC_MODEL` (რომელსაც პროფილები ადგენენ).

## დისტანციური რეჟიმი

მას შემდეგ, რაც გაუშვებთ `omniroute connect <host>`-ს (იხილეთ
[დისტანციური რეჟიმი](./REMOTE-MODE.md)), `omniroute launch` და `omniroute setup-claude`
ავტომატურად მიემართება ამ დისტანციურ სერვერს და გამოიყენებს მის შესაბამისი მოქმედების არეალის მქონე წვდომის ტოკენს — დამატებითი
დროშები საჭირო არ არის. კონკრეტული გამოძახებისთვის პარამეტრები ჩაანაცვლეთ `--remote` / `--api-key`-ის მეშვეობით.

## პრობლემების აღმოფხვრა

**Claude Code უგულებელყოფს კარიბჭეს** — დარწმუნდით, რომ `ANTHROPIC_BASE_URL` **არ
შეიცავს `/v1`-ს** და ხელახლა გაუშვით `claude` (env მხოლოდ ერთხელ, გაშვებისას იკითხება). `omniroute launch`
ამას თქვენთვის უზრუნველყოფს.

**`/model`-ის არჩევის სია ცარიელია / კარიბჭის მოდელები აკლია** — საჭიროა Claude Code
v2.1.219+ და `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`. არჩევის სიაში მხოლოდ `claude*` /
`anthropic*` მოდელის ID-ები გამოჩნდება; ნებისმიერი სხვა მოდელის იძულებით გამოსაყენებლად მიუთითეთ
`ANTHROPIC_MODEL=<id>` (პროფილები სწორედ ამას აკეთებენ).

**`400 Ambiguous model 'claude-…'`** — Claude Code ყოველთვის აგზავნის **პრეფიქსის გარეშე**
მოდელის ID-ებს (მაგ., `claude-opus-4-8`), ამიტომ, როდესაც დაკავშირებულია როგორც Claude Code-ის (`cc/…`), ისე
Claude-ის (`claude/…`) პროვაიდერები, პრეფიქსის გარეშე ID ორ მარშრუტს ემთხვევა და
OmniRoute გამოცნობაზე უარს ამბობს. ეს ორი გზით შეგიძლიათ გამოასწოროთ: პრეფიქსიანი ID დააფიქსირეთ
`ANTHROPIC_MODEL=cc/claude-opus-4-8`-ის მეშვეობით, ან ჩართეთ **Claude-ის პრეფიქსის გარეშე მოდელებისთვის უპირატესობა Claude Code-ს მიანიჭეთ** — Claude-ის პროვაიდერის გვერდზე არსებული გადამრთველი, ან
`OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true` (ნაგულისხმევად გამორთულია;
იხილეთ [გარემო](../reference/ENVIRONMENT.md)) — რის შედეგადაც პრეფიქსის გარეშე `claude-*`
ID-ები Claude Code-ისკენ მარშრუტდება. პროვაიდერის ცალსახად მითითებულ პრეფიქსებს ყოველთვის უპირატესობა ენიჭება.

**ავთენტიფიკაციის შეცდომები** — პროფილი ტოკენს არ შეიცავს. გამოიყენეთ `omniroute launch --profile`
(რომელიც მას ჩასვამს) ან გაიტანეთ `ANTHROPIC_AUTH_TOKEN`.

**პროფილები იზოლირებული არ არის** — თითოეულ პროფილს განსხვავებული `CLAUDE_CONFIG_DIR` აქვს;
სესიის შიგნით `echo $CLAUDE_CONFIG_DIR`-ით გადაამოწმეთ, რომ ის
`~/.claude/profiles/<name>`-ზე მიუთითებს.
