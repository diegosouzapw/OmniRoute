## რა არის ეს (და რა არ არის)

OmniRoute თითოეულ დასრულებულ მოთხოვნას ანიჭებს აშშ დოლარებში გამოსახულ ღირებულებას, რისთვისაც ტოკენების
რაოდენობას მოდელის ფასებზე ამრავლებს. ეს რიცხვები გამოიყენება **ხარჯების** მართვის პანელში,
`omniroute cost` / `omniroute usage` CLI-ში, CSV/JSON ექსპორტებში და თითოეული API-გასაღების ბიუჯეტებში.

> **მართვის პანელზე ნაჩვენები „ღირებულება“ დანაზოგის მაჩვენებელია და არა გადასახადი.** OmniRoute თანხას არასდროს ჩამოგაჭრით
> — ის თქვენს მოთხოვნებს მარშრუტიზაციას უკეთებს უკვე დაკავშირებულ პროვაიდერებთან (თქვენს საკუთარ
> გამოწერებთან, უფასო ტარიფებთან და API-გასაღებებთან). უფასო მოდელებზე სრულად დაგროვილი „$290 ჯამური ღირებულება“
> ნიშნავს, რომ ფასიანი API-ს გამოყენების შემთხვევაში დაახლოებით **$290-ის გადახდა _არ_ მოგიწიათ**. ეს მაჩვენებელი არის
> _შეფასება_ იმისა, თუ რა ეღირებოდა იგივე ტრაფიკი სტანდარტული კატალოგური ფასებით, რათა დაინახოთ,
> სად არის კონცენტრირებული თქვენი მოხმარება და რამდენ თანხას ზოგავთ უფრო იაფ/უფასო პროვაიდერებზე მარშრუტიზაციით.

ეს განმარტება პირდაპირ არის მოცემული პროექტის [README](../../README.md)-ში („მართვის პანელზე ნაჩვენები
„ღირებულება“ დანაზოგის მაჩვენებელია და არა გადასახადი“).

რადგან ეს რიცხვი შეფასებაა:

- ის დამოკიდებულია ფასების ცხრილზე, რომელიც OmniRoute-ს თითოეული მოდელისთვის აქვს. მოდელი, რომლისთვისაც ფასის
  ჩანაწერი არ არსებობს, ხარჯში `0`-ს შეიტანს (მიმომხილველში ის გამოჩნდება როგორც „მოძველებული / უფასო“ სტრიქონი).
- უფასო ტარიფისა და გამოწერის ტრაფიკისთვისაც გროვდება _სავარაუდო_ ღირებულება — ეს არის
  თანხა, რომელსაც ზოგავთ და არა გადასახდელი თანხა.

## როგორ ფასდება ხარჯები

### ფასების წყარო

ხარჯები განისაზღვრება ფასების ცხრილიდან, წყაროების პრიორიტეტულობის შემდეგი თანმიმდევრობით
([`src/lib/pricingSync.ts`](../../src/lib/pricingSync.ts)):

1. **მომხმარებლის ჩანაცვლებები** — ფასები, რომლებსაც მართვის პანელში / `PATCH /api/pricing`-ის მეშვეობით ადგენთ.
2. **სინქრონიზებული გარე ფასები** — სინქრონიზაციის ჩართვისას მიიღება LiteLLM-ის საჯარო
   `model_prices_and_context_window.json`-დან (ინახება ცალკე `pricing_synced` სახელთა სივრცეში,
   ამიტომ თქვენს ჩანაცვლებებს არასდროს გადააწერს).
3. **კოდში ჩაშენებული ნაგულისხმევი მნიშვნელობები** — მოჰყვება OmniRoute-ს.

გარე ფასების სინქრონიზაცია **არჩევითია** და ნაგულისხმევად გამორთულია. შესაბამისი გარემოს ცვლადები
(იხილეთ [`.env.example`](../../.env.example)):

| გარემოს ცვლადი          | ნაგულისხმევი | დანიშნულება                                                                |
| ----------------------- | ------------ | -------------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`      | გაშვებისას LiteLLM-ის ფასების ფონური სინქრონიზაციის ჩართვა.                |
| `PRICING_SYNC_INTERVAL` | `86400`      | სინქრონიზაციის ინტერვალი **წამებში** (ნაგულისხმევად ყოველდღიურად).         |
| `PRICING_SYNC_SOURCES`  | `litellm`    | მძიმით გამოყოფილი წყაროების სია (დღეს მხოლოდ `litellm` არის მხარდაჭერილი). |

### ღირებულების ფორმულა

ღირებულება თითოეული მოთხოვნისთვის გამოითვლება ტოკენების რაოდენობისა და მილიონ ტოკენზე განსაზღვრული ტარიფების მიხედვით
[`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts)-ში
(`computeCostFromPricing` / `calculateCost`):

- **შეყვანის ტოკენები** (ქეშიდან წაკითხვისა და ქეშის შექმნის ტოკენების გამოკლებით) × `input` ტარიფი.
- **ქეშიდან წაკითხვის ტოკენები** × `cached` ტარიფი (არარსებობის შემთხვევაში გამოიყენება შეყვანის ტარიფი).
- **ქეშის შექმნის ტოკენები** × `cache_creation` ტარიფი (არარსებობის შემთხვევაში გამოიყენება შეყვანის ტარიფი).
- **გამოტანის ტოკენები** × `output` ტარიფი.
- **მსჯელობის ტოკენები** × `reasoning` ტარიფი (არარსებობის შემთხვევაში გამოიყენება გამოტანის ტარიფი).

ყველა ტარიფი ინტერპრეტირებულია, როგორც აშშ დოლარი 1,000,000 ტოკენზე. Codex-ის „fast“/„priority“ ან
„flex“ მომსახურების დონე იყენებს ღირებულების მულტიპლიკატორს (`getCodexFastCostMultiplier`) — მაგალითად, flex-ის
შემთხვევაში ტოკენებზე 50%-იანი ფასდაკლება მოქმედებს, რაც მართვის პანელში ნაჩვენებია როგორც **flex-ის დანაზოგი**.

თავდაპირველად მოდელების სახელები ნორმალიზდება (პროვაიდერის გზის პრეფიქსები, როგორიცაა `openai/` ან
`accounts/fireworks/models/`, იშლება), რათა ისტორიული სტრიქონები კვლავ დაემთხვეს შესაბამის ფასს.

### როგორ აღირიცხება ხარჯი

- თითოეული მოთხოვნის ღირებულება პასუხის მიღების შემდეგ გამოითვლება და პასუხის მოლოდინის გარეშე აღირიცხება, რათა
  კლიენტისთვის დაყოვნება არასდროს გაიზარდოს. საერთო კვოტის მოხმარება ღონისძიებების ციკლის შემდეგ
  იტერაციაზე იგეგმება [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts)-ის მეშვეობით.
- API-გასაღების ხარჯი ბუფერში გროვდება და ჯგუფურად ჩაიწერება
  [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts)-ის მიერ (ნაგულისხმევი ჩაწერის ინტერვალია 60 წამი,
  ბუფერის ზომა კი — 1,000 ჩანაწერი). რეგულირება შესაძლებელია შემდეგი ცვლადებით:

  | გარემოს ცვლადი                      | ნაგულისხმევი | დანიშნულება                                                        |
  | ----------------------------------- | ------------ | ------------------------------------------------------------------ |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000`      | ჩაწერის ინტერვალი მილიწამებში.                                     |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`       | ბუფერში ჩაწერის მოლოდინში მყოფი ჩანაწერების მაქსიმალური რაოდენობა. |

მართვის პანელზე ნაჩვენები ხარჯის მაჩვენებლები **არ** იკითხება თითოეულ სტრიქონში შენახული დოლარის ოდენობიდან — ისინი
ტოკენების რაოდენობისა და ფასების მიმდინარე ცხრილის მიხედვით თავიდან გამოითვლება ყოველ ჯერზე, როდესაც
ანალიტიკის საბოლოო წერტილი სრულდება. ეს ნიშნავს, რომ არასწორი ფასის გასწორება (და ხელახლა სინქრონიზაცია)
ისტორიული ხარჯების შეფასებებსაც უკუქცევით განაახლებს.

## დაფა: ხარჯების გვერდი

**ხარჯების** გვერდი მდებარეობს მისამართზე `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`).
მისი მთავარი ხედი არის ჩანართი **ხარჯების მიმოხილვა**
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`),
რომელიც ყველა მონაცემს `GET /api/usage/analytics`-დან ტვირთავს.

რას აჩვენებს:

- **დანახარჯების ბარათები** — სავარაუდო დანახარჯი პერიოდებისთვის _დღეს (1d)_, _7d_, _30d_ და არჩეული
  დროის შუალედი. დიაპაზონის ამომრჩევი: `7d`, `30d`, `90d`, `all`.

## CLI

OmniRoute-ის CLI გთავაზობთ ღირებულების, გამოყენებისა და ფასების ბრძანებებს (რეგისტრირებულია
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)-ში).

### `omniroute cost`

ღირებულების ანგარიში, აგრეგირებული `/api/usage/analytics`-დან.

```bash
omniroute cost                          # ბოლო 30 დღე, დაჯგუფებული პროვაიდერის მიხედვით
omniroute cost --period 7d              # ბოლო 7 დღე
omniroute cost --group-by model         # დაჯგუფება: provider | model | combo | api-key | day
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

სვეტები: ჯგუფი, მოთხოვნები, შემავალი/გამავალი ტოკენები, ღირებულება (USD) და საერთო
ღირებულების %. საბოლოოდ იბეჭდება ჯამური შედეგის სტრიქონი (ითიშება `--quiet`-ით ან
`--output json`-ით).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # ღირებულების შეჯამება თითოეული პროვაიდერისთვის
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# ბიუჯეტები
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` კითხულობს `GET /api/pricing/defaults`-ს. ცალკეული მოდელების
> ფასების შესაცვლელად გამოიყენეთ მართვის პანელის **Pricing** გვერდი ან `PATCH /api/pricing`.
