## 1. Antigravity და Antigravity CLI (agy)

ორივე პროვაიდერი იყენებს **Google-ის ერთსა და იმავე ბეკენდს** — იდენტურ OAuth კლიენტს, ტოკენის განახლებას, ბოლო წერტილებსა და Google ანგარიშებს. განსხვავება იმაშია, თუ რომელ მოდელებს ხედავთ.

> Google-ის ოფიციალური შედარებისთვის იხილეთ [Antigravity CLI-ის ანონსი](https://antigravity.google/blog/introducing-google-antigravity-cli).

| ასპექტი                                | `antigravity` (IDE)                                    | `agy` (CLI)                                                            |
| -------------------------------------- | ------------------------------------------------------ | ---------------------------------------------------------------------- |
| **Google-ის პროდუქტი**                 | Antigravity 2.0 / Antigravity IDE                      | Antigravity CLI                                                        |
| **ბეკენდი**                            | იგივე Google Cloud Code API                            | იგივე Google Cloud Code API                                            |
| **OAuth / ტოკენი**                     | იგივე კლიენტი, იგივე განახლება                         | იგივე კლიენტი, იგივე განახლება                                         |
| **მოდელების კატალოგი**                 | სტატიკური, შერჩეული სია (OmniRoute-ში მყარად გაწერილი) | Google-იდან `:fetchAvailableModels`-ის მეშვეობით რეალურ დროში მიღებული |
| **Claude-ის მოდელები**                 | Sonnet 4.6, Opus 4.6 (თითოეულის 4 ვარიანტი)            | Sonnet 4.6, Opus 4.6 (თითოეულის 4 ვარიანტი)                            |
| **Gemini-ის სახელდება**                | მარტივი ნიშნულები (Low/Medium/High)                    | საწყისი სისტემის ID-ები (extra-low/low/agent)                          |
| **დამატებითი მოდელები**                | `gpt-oss-120b-medium`                                  | შესაძლოა მოიცავდეს Google-ის დამატებით მოდელებს                        |
| **ნაგულისხმევი გამოყენების შემთხვევა** | IDE-სთან ინტეგრაცია (VS Code, JetBrains)               | CLI / API-ზე წვდომა                                                    |
| **კვოტა**                              | გაზიარებულია agy-სთან (იგივე Google ანგარიში)          | გაზიარებულია antigravity-სთან (იგივე Google ანგარიში)                  |

**ხელმისაწვდომი მოდელები (დადასტურებულია ექსპერიმენტით, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (აზროვნების სხვადასხვა დონე)
- Claude: Sonnet 4.6, Opus 4.6 (თითოეული default/low/medium/high ვარიანტებით)
- სხვა: GPT-OSS 120B Medium
- **Claude Sonnet 5 ხელმისაწვდომი არ არის** — მხარდაჭერილია მხოლოდ 4.6-ის ვარიანტები

**რატომ განსხვავდება მოდელების კატალოგი**: Google-ის CLI „ოპტიმიზებულია სისწრაფისა და დაბალი ზედნადები ხარჯისთვის“ და „თანაოპტიმიზებულია Gemini-ის მოდელებთან“ (Google-ის ოფიციალური ბლოგის მიხედვით). Web/IDE პროდუქტი „ოპტიმიზებულია ამომწურავობისთვის“. CLI მოდელების დინამიკურად აღმოსაჩენად იყენებს `:fetchAvailableModels`-ს, ხოლო IDE — სტატიკურ, შერჩეულ სიას.

**პრაქტიკაში**: Gemini-ის მოდელებისთვის გამოიყენეთ `agy/` პრეფიქსი (მაგ., `agy/gemini-3.7-flash-high`). სტატიკური, შერჩეული სიისთვის გამოიყენეთ `antigravity/`. ორივე იყენებს Google-ის ერთსა და იმავე ბეკენდს, თუმცა მოდელების სახელებს განსხვავებულად წარმოადგენს. კვოტა გაზიარებულია — ნებისმიერი პროვაიდერის გამოყენება Google-ის იმავე ანგარიშის ლიმიტებში ჩაითვლება.

## 2. Google One AI Pro: კვოტების სისტემა

> კვოტების ოფიციალური დეტალებისთვის იხილეთ [Antigravity-ის დოკუმენტაცია: გეგმები](https://antigravity.google/docs/plans), ხოლო ფასების უახლესი ცვლილებებისთვის — [Antigravity-ის გეგმების ცვლილებები](https://antigravity.google/blog/changes-to-antigravity-plans).

Google Antigravity იყენებს **ორსაფეხურიან კვოტას**, რომელიც ეფუძნება „შესრულებულ სამუშაოს“ (გამოთვლით დატვირთვას) და არა შეტყობინებების რაოდენობას.

### ორი საფეხური

| საფეხური                     | რას წარმოადგენს                        | განახლების ციკლი                                                                                    |
| ---------------------------- | -------------------------------------- | --------------------------------------------------------------------------------------------------- |
| **5-საათიანი სპრინტი**       | „შესრულებული სამუშაოს“ მყისიერი მარაგი | სესიის პირველი მოთხოვნიდან 5 საათის შემდეგ ნულდება                                                  |
| **7-დღიანი საბაზისო ზღვარი** | ყოველკვირეული მკაცრი ლიმიტი            | მიღწევის შემთხვევაში უგულებელყოფს 5-საათიან განახლებას; წვდომა იბლოკება მომდევნო 7-დღიან პერიოდამდე |

**როგორ გამოითვლება „შესრულებული სამუშაო“**: აგენტზე ინტენსიურად დამოკიდებული ამოცანები (მაგ., „მთელი ეს რეპოზიტორია გადაამუშავე“) კვოტას გაცილებით სწრაფად ხარჯავს, ვიდრე მარტივი ამოცანები (მაგ., „ეს ფუნქცია შეასწორე“). მოხმარების მაჩვენებელი რეალურ დროში ხელმისაწვდომი არ არის.

### Gemini და არა-Gemini მოდელები

- **Gemini მოდელები** (Flash + Pro): იზიარებენ ერთიან სიხშირის ლიმიტს, რომელიც API-ის ფასების შესაბამისად იხარჯება. თუ Flash Pro-ზე 8-ჯერ იაფია, მიიღებთ 8-ჯერ მეტ Flash ტოკენს.
- **არა-Gemini მოდელები** (Claude, GPT-OSS): აქვთ **ცალკეული** სიხშირის ლიმიტები. ისინი შეიძლება ხელმისაწვდომი დარჩეს მაშინაც კი, როდესაც Gemini დაბლოკილია.

### AI კრედიტები (ლიმიტის გადაჭარბება)

> კრედიტების მუშაობის შესახებ იხილეთ [Google One AI კრედიტები](https://support.google.com/googleone/answer/14534406).

როდესაც საბაზისო კვოტა ამოიწურება:

- **არასდროს**: დაელოდეთ კვოტის განახლებას; გამოჩნდება „საბაზისო მოდელის კვოტა მიღწეულია“
- **ყოველთვის**: AI კრედიტები ავტომატურად გამოიყენება; საბაზისო კვოტის განახლების შემდეგ სისტემა მასზე დაბრუნდება

კრედიტები ცალკე შეიძინება და სტანდარტული API ფასების მიხედვით ჩამოიჭრება.

### ძირითადი დეტალები

- კვოტა **ანგარიშის დონეზე საზიაროა** — Antigravity IDE-ში, CLI-სა და OmniRoute-ში გამოყენებული ერთი და იგივე Google ანგარიში კვოტის ერთსა და იმავე მარაგს იზიარებს
- თითოეულ Google ანგარიშს საკუთარი დამოუკიდებელი კვოტა აქვს — რამდენიმე ანგარიში = კვოტის რამდენიმე მარაგი
- AI Pro-ის მომხმარებლები ყოველკვირეული საბაზისო ზღვრის მიღწევისას 5-საათიანი განახლების ნაცვლად **7-დღიანი დაბლოკვის** შემთხვევებს აფიქსირებენ (Google-მა დაადასტურა, რომ მაღალი მოთხოვნის პირობებში ეს განზრახაა)

**როდესაც თქვენი ანგარიშის კვოტა ამოიწურება**: OmniRoute ავტომატურად იმეორებს მოთხოვნას კომბინირებულ მარშრუტში არსებული შემდეგი ხელმისაწვდომი ანგარიშით. ხელით ჩარევა საჭირო არ არის.

## 3. როგორ მივიღოთ projectId

ყოველი antigravity/agy კავშირისთვის საჭიროა Google Cloud Code-ის `projectId`. მის გარეშე `/v1internal:models` საბოლოო წერტილი 404-ს აბრუნებს.

### მეთოდი A: ავტომატური (რეკომენდებული)

OmniRoute ამას ავტომატურად ამუშავებს. როდესაც Dashboard OAuth-ის საშუალებით ახალ Google ანგარიშს დაამატებთ:

1. OmniRoute განაახლებს ტოკენს
2. projectId-ის აღმოსაჩენად გამოიძახებს `loadCodeAssist`-ს
3. თუ პროექტი არ არსებობს, მის შესაქმნელად გამოიძახებს `onboardUser`-ს
4. ახლად შექმნილი projectId-ის მისაღებად ხელახლა გამოიძახებს `loadCodeAssist`-ს
5. შეინახავს მას მონაცემთა ბაზაში

**ეს ანგარიშების უმეტესობისთვის მუშაობს** — ხელით შესრულება საჭირო არ არის.

### მეთოდი B: ხელით, agy CLI-ის საშუალებით

თუ ავტომატური აღმოჩენა ვერ მოხერხდება (ამის შესაძლო მიზეზებისთვის იხილეთ სექცია 5):

```bash
# დააინსტალირეთ agy CLI (თუ ჯერ არ არის დაინსტალირებული)
npm install -g @anthropic-ai/agy

# შედით თქვენი Google ანგარიშით
agy login

# აირჩიეთ ანგარიში, რომლის რეგისტრაციაც საჭიროა
# ეს ააქტიურებს Cloud Code-ის რეგისტრაციას და ანიჭებს projectId-ს
```

`agy login`-ის წარმატებით დასრულების შემდეგ განაახლეთ ტოკენი OmniRoute Dashboard-ში. projectId ავტომატურად იქნება აღმოჩენილი.

### როგორ გადავამოწმოთ

შეამოწმეთ მონაცემთა ბაზა:

```bash
# OmniRoute-ის კონტეინერში
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

ან შეამოწმეთ ჟურნალები:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. OAuth-ის გადამისამართების URI

### პრობლემა

Google OAuth მოითხოვს მოქმედ გადამისამართების URI-ს. OmniRoute ნაგულისხმევად იყენებს `http://127.0.0.1:20128/callback`-ს (loopback). ეს მუშაობს ლოკალური აგებების შემთხვევაში, მაგრამ **არ მუშაობს დისტანციური განთავსებებისას** (მაგალითად, სერვერზე, რომელზეც წვდომა LAN IP-ით ხორციელდება).

Google უარყოფს გადამისამართების URI-ებს, რომლებიც:

- იყენებს IP მისამართებს (აუცილებელია დომენი, რომელიც მთავრდება `.com`-ით, `.org`-ით და ა.შ.)
- არ ემთხვევა OAuth კლიენტის კონფიგურაციაში რეგისტრირებულ გადამისამართების URI-ებს

### გადაწყვეტა

**ვარიანტი A: გამოიყენეთ ჩაშენებული OAuth ნაკადი (ნაგულისხმევი)**

- მუშაობს, როდესაც OmniRoute-ზე წვდომისთვის იყენებთ `localhost`-ს ან `127.0.0.1`-ს
- კონფიგურაცია საჭირო არ არის

**ვარიანტი B: მორგებული OAuth ავტორიზაციის მონაცემები**

- თქვენს გარემოში დააყენეთ `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web`
- მიუთითეთ თქვენი Google OAuth ავტორიზაციის მონაცემები:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Google Cloud Console-ში დაარეგისტრირეთ `https://your-domain.com/callback`, როგორც ავტორიზებული გადამისამართების URI

**ვარიანტი C: საწყისი შესვლისთვის გამოიყენეთ agy CLI**

- გაუშვით `agy login` იმ კომპიუტერზე, რომლითაც OmniRoute-ზე წვდომას აპირებთ
- OAuth ნაკადი ლოკალურად სრულდება და ტოკენები ინახება
- Dashboard-ის მეშვეობით კავშირი OmniRoute-ში შემოიტანეთ

### შეზღუდვები

- მორგებული OAuth ავტორიზაციის მონაცემებისთვის საჭიროა დომენის სახელი (Google არ იღებს IP მისამართებს გადამისამართების URI-ებად)
- თუ დომენი არ გაქვთ, გამოიყენეთ ვარიანტი A ან C

## 5. პრობლემების მოგვარება: როდესაც ავტომატური დაყენება ვერ ხერხდება

OmniRoute ანგარიშების უმეტესობისთვის projectId-ის აღმოჩენასა და საწყის რეგისტრაციას ავტომატურად ამუშავებს. წარუმატებლობის შემთხვევაში ძირეული მიზეზი, როგორც წესი, ერთ-ერთი შემდეგია:

### ანგარიშის რეგიონი დაბლოკილია

**სიმპტომი**: `agy login` აბრუნებს შეტყობინებას „უფლებამოსილების შემოწმება ვერ მოხერხდა: თქვენი მიმდინარე ანგარიში ვერ გამოიყენებს Antigravity-ს, რადგან ის ამჟამად თქვენს მდებარეობაში ხელმისაწვდომი არ არის.“

**ძირეული მიზეზი**: Google ანგარიშებს აქვთ სერვერის მხარეს არსებული ველი „Country Association“, რომელიც რეგისტრაციისას დგინდება. agy CLI და Cloud Code API ამ ველს მკაცრად ამოწმებს — განსხვავებით Gemini-ის ვებვერსიისგან, რომელიც მხოლოდ თქვენს მიმდინარე IP-ს ამოწმებს.

> თქვენს ანგარიშთან დაკავშირებული რეგიონის შესამოწმებლად ან შესაცვლელად ეწვიეთ [Google-ის ქვეყნის მიბმის ფორმას](https://policies.google.com/country-association-form).

**რატომ მუშაობს Gemini-ის ვებვერსია, ხოლო agy — არა**:

- Gemini-ის ვებვერსია / Google One: ამოწმებს მხოლოდ მიმდინარე IP-ს (პროქსი საკმარისია)
- agy CLI / Cloud Code API: კითხულობს სერვერის მხარეს არსებულ Country Association ველს (პროქსი არ შველის)

**გამოსწორება**:

1. აშშ-ის IP-ის გამოყენებისას ეწვიეთ [Google-ის ქვეყნის მიბმის ფორმას](https://policies.google.com/country-association-form)
2. გაგზავნეთ რეგიონის შეცვლის მოთხოვნა (აირჩიეთ „მე სხვა ქვეყანაში ვცხოვრობ“)
3. დაელოდეთ 1-24 საათს, სანამ Google მოთხოვნას დაამუშავებს და ელფოსტით შეგატყობინებთ
4. ამის შემდეგ `agy login` წარმატებით უნდა შესრულდეს

### ანგარიშს Cloud Code პროექტი არ აქვს

**სიმპტომი**: ჟურნალებში ნაჩვენებია `loadCodeAssist returned no project id` და `onboardUser failed (400)`.

**ძირეული მიზეზი**: ანგარიში Google Cloud Code-ში არასდროს დარეგისტრირებულა და ავტომატური საწყისი რეგისტრაცია ვერ განხორციელდა.

**გამოსწორება**: Cloud Code-ში რეგისტრაციის გასააქტიურებლად ხელით გაუშვით `agy login`, შემდეგ კი OmniRoute Dashboard-ში ტოკენი განაახლეთ.

### ტოკენის ვადა ამოიწურა ან ის გაუქმდა

**სიმპტომი**: ჟურნალებში ჩანს 401 შეცდომები ან შეტყობინებები „ტოკენის ვადა ამოიწურა“.

**გამოსწორება**: განაახლეთ ტოკენი შემდეგი გზით: Dashboard → Providers → agy → დააწკაპუნეთ განახლების ხატულაზე. თუ თავად განახლების ტოკენი გაუქმებულია, OAuth-ის მეშვეობით ავტორიზაცია ხელახლა უნდა გაიაროთ.
