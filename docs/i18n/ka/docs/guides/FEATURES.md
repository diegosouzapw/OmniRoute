## 🔌 პროვაიდერები

Kiro-ს ანგარიშები მოიცავს კრედიტების ბალანსის მონიტორინგს — დარჩენილი კრედიტები, საერთო ლიმიტი და განახლების თარიღი ხელმისაწვდომია დაფაზე → გამოყენება.

OpenRouter-ის კავშირებს გაფართოებულ პარამეტრებში თითოეული კავშირისთვის `preset`-ის შენახვა შეუძლია. მისი დაყენებისას OmniRoute მას OpenRouter-ის მოთხოვნის ზედა დონის ველად აგზავნის, მაგალითად, `"preset": "email-copywriter"`, თუ კლიენტის მოთხოვნაში საკუთარი `preset` უკვე მითითებული არ არის.

## 🎨 კომბოები

შექმენით მოდელების მარშრუტიზაციის კომბოები 19 საჯარო სტრატეგიით: priority, weighted, round-robin, context-relay, fill-first, p2c (ორი ვარიანტიდან არჩევა), random, least-used, cost-optimized, reset-aware, reset-window, headroom, strict-random, auto, lkgp (ბოლო ცნობილი გამართული პროვაიდერი), context-optimized, cache-optimized, **fusion** (მოთხოვნის პარალელურად გაგზავნა მოდელების ჯგუფისთვის, შემდეგ კი ერთი პასუხის სინთეზირება შემფასებლის მეშვეობით) და **pipeline**. თითოეული კომბო რამდენიმე მოდელს აკავშირებს ავტომატური სარეზერვო გადართვით და მოიცავს სწრაფ შაბლონებსა და მზადყოფნის შემოწმებებს.

კომბოების ბოლო გაუმჯობესებები:

- **კომბოს სტრუქტურირებული კონსტრუქტორი** — შექმენით თითოეული ნაბიჯი პროვაიდერის, მოდელისა და კონკრეტული ანგარიშის/კავშირის არჩევით
- **განმეორებითი პროვაიდერების მხარდაჭერა** — ერთ კომბოში ერთი და იგივე პროვაიდერი რამდენჯერმე გამოიყენეთ, თუ `(provider, model, connection)` კორტეჟი უნიკალურია
- **კომბოს სამიზნეების მდგომარეობა** — ანალიტიკისა და მდგომარეობის ინტერფეისები ახლა კომბოს ცალკეულ სამიზნეებს/ნაბიჯებს ერთმანეთისგან განასხვავებს, ნაცვლად იმისა, რომ ყველაფერი მოდელის სტრიქონებში გააერთიანოს
- **შედგენილი დონეების მიმდევრობა** — `defaultTier -> fallbackTier` ახლა გავლენას ახდენს ზედა დონის კომბოს ნაბიჯების შესრულებისა და სარეზერვო გადართვის მიმდევრობაზე გაშვების დროს
- **სისტემური მოთხოვნის შაბლონები** — კომბოს `system_message` მხარს უჭერს სერვერის მხარეს
  `{{MODEL_ID}}`, `{{PROVIDER_ID}}`, `{{ACCOUNT}}` და `{{FINGERPRINT}}`
  ჩანაცვლების ნიშნებს, რომლებიც გაგზავნამდე უშუალოდ რეალურად მარშრუტიზებული სამიზნის მონაცემებით იშლება.
  დაშვებულია მხოლოდ ნებადართული ნიშნები და რეკურსია არ გამოიყენება; უცნობი ჩანაცვლების ნიშნები უცვლელი რჩება; ცარიელი მნიშვნელობები
  ცარიელ სტრიქონად იშლება; კლიენტის სისტემური მოთხოვნები არასოდეს გადაიწერება. `{{FINGERPRINT}}`
  მნიშვნელობას იღებს მხოლოდ fingerprint-ზე დაფუძნებული უფასო პროვაიდერებისთვის, რომლებსაც დაფიქსირებული ან
  ავტომატურად როტირებული fingerprint აქვთ — სხვა შემთხვევებში ის ცარიელ სტრიქონად იშლება (მაგ.
  ერთი fingerprint-ის მქონე კავშირები, fingerprint-ის არმქონე პროვაიდერები). ჩანაცვლების ნიშნების დამუშავება მოიცავს
  გაგზავნის სტანდარტულ ციკლს, round-robin-სა და დაფიქსირებულ context-cache სესიებს;
  fusion, chaos, pipeline და nested-execute სტრატეგიები ჩანაცვლების ნიშნებს
  ჯერ არ ამუშავებს.

## ⚙️ პარამეტრები

პარამეტრების სრულყოფილი პანელი **7 ჩანართით**:

- **ზოგადი** — სისტემური საცავი, სარეზერვო ასლების მართვა (მონაცემთა ბაზის ექსპორტი/იმპორტი)
- **გარეგნობა** — თემის ამრჩევი (მუქი/ნათელი/სისტემური), ფერთა თემების წინასწარი ვარიანტები და მორგებული ფერები, მდგომარეობის ჟურნალის ხილვადობა, გვერდითი ზოლის ელემენტებისა და ჯგუფების გამყოფების ხილვადობის მართვა, endpoint-ის გვირაბების ხილვადობის მართვა
- **AI** — AI ასისტენტის ფუნქციები, ნაგულისხმევი მარშრუტიზაციის წინასწარი პარამეტრები (Auto Combo `auto/coding`, `auto/fast`, `auto/cheap`, `auto/smart`), მსჯელობის განმეორებითი გამოყენების კეში და უნარების/მეხსიერების გადამრთველები
- **უსაფრთხოება** — API endpoint-ის დაცვა, მორგებული პროვაიდერების დაბლოკვა, IP-ფილტრაცია, სესიის ინფორმაცია
- **მარშრუტიზაცია** — მოდელების ფსევდონიმები, ფონური ამოცანების დეგრადაცია, მანიფესტის გათვალისწინებით დონეებზე მარშრუტიზაცია (W1–W4), `fallbackDelayMs`, თითოეული სესიისთვის ფიქსირებული მარშრუტიზაცია
- **მდგრადობა** — სიხშირის ლიმიტის შენარჩუნება, circuit breaker-ის მორგება, დაბლოკილი ანგარიშების ავტომატურად გათიშვა, პროვაიდერის მოქმედების ვადის მონიტორინგი, **Context Relay**-ის გადაცემის ზღვარი და შემაჯამებელი მოდელის კონფიგურაცია, თითოეული პროვაიდერისთვის 429-ის კლასიფიკაცია და `useUpstream429BreakerHints` გადამრთველი, მოდელების მოცდის პერიოდები
- **გაფართოებული** — კონფიგურაციის გადაფარვები, კონფიგურაციის აუდიტის ჟურნალი, სარეზერვო დეგრადაციის რეჟიმი, Responses API-ის ფონური რეჟიმის დეგრადაცია

## 🔗 კონტექსტის გადაცემა _(v3.5.5+)_

კომბინირებული სტრატეგია, რომელიც საუბრის მიმდინარეობისას ანგარიშების როტაციის შემთხვევაში სესიის უწყვეტობას ინარჩუნებს. აქტიური ანგარიშის რესურსის ამოწურვამდე OmniRoute ფონურ რეჟიმში ქმნის გადაცემისთვის განკუთვნილ სტრუქტურირებულ შეჯამებას. როდესაც შემდეგი მოთხოვნა სხვა ანგარიშზე გადამისამართდება, შეჯამება სისტემური შეტყობინების სახით ჩაემატება, რათა ახალმა ანგარიშმა სრული კონტექსტით განაგრძოს მუშაობა.

კონფიგურირება შესაძლებელია კომბინაციის დონის ან გლობალური პარამეტრებით:

## 🌐 V1 WebSocket ხიდი _(v3.6.6+)_

OmniRoute ახლა `/v1/ws` განახლების საბოლოო წერტილის მეშვეობით მხარს უჭერს **OpenAI-თან თავსებად WebSocket კლიენტებს**. მორგებული `scripts/dev/v1-ws-bridge.mjs` სერვერი Next.js-ს გარსში აქცევს და WS კავშირებს სრულ ორმხრივ ნაკადურ სესიებად გარდაქმნის. ავთენტიფიკაციისთვის გამოიყენება იგივე API გასაღები ან სესიის cookie, რაც HTTP მოთხოვნებისთვის.

ძირითადი ქცევები:

- კავშირის დამყარებამდე WS განახლება მოწმდება `src/lib/ws/handshake.ts`-ის მიერ
- სესიის დახურვის ან ზედა დონის წყაროს შეცდომისას ნაკადები კორექტულად წყდება
- ერთდროულად მუშაობს არსებულ HTTP+SSE ნაკადურ მარშრუტთან ერთად

## 🔑 სინქრონიზაციის ტოკენები და კონფიგურაციის პაკეტი _(v3.6.6+)_

მრავალმოწყობილობიანი და გარე ოპერატორებისთვის წვდომა ახლა შესაძლებელია **წვდომის ფარგლებით შეზღუდული სინქრონიზაციის ტოკენების** მეშვეობით:

- **`POST /api/sync/tokens`** — ახალი სინქრონიზაციის ტოკენის გაცემა (წვდომის განსაზღვრული ფარგლებითა და არასავალდებულო ვადის გასვლით)
- **`DELETE /api/sync/tokens/:id`** — ტოკენის გაუქმება
- **`GET /api/sync/bundle`** — ყველა არასენსიტიური პარამეტრის ვერსირებული, ETag-ით იდენტიფიცირებული JSON-სურათის ჩამოტვირთვა (პაროლები დაფარულია)

კონფიგურაციის პაკეტი იქმნება `src/lib/sync/bundle.ts`-ის მიერ. ცვლილებების სრული მონაცემების ხელახლა ჩამოტვირთვის გარეშე აღმოსაჩენად მომხმარებლები პასუხის `ETag` სათაურს ადარებენ.

## 🧠 GLM Thinking-ის წინასწარი პარამეტრი _(v3.6.6+)_

**GLM Thinking (`glmt`)** ახლა რეგისტრირებული სრულფასოვანი პროვაიდერია: გამომავალი ტოკენების მაქსიმუმი — 65 536, მსჯელობის ბიუჯეტი — 24 576, ნაგულისხმევი დროის ამოწურვა — 900 წმ, Claude-თან თავსებადი API ფორმატი და გამოყენების საერთო სინქრონიზაცია GLM ოჯახთან.

v3.6.6-ში ასევე დაემატა **ტოკენების ჰიბრიდული დათვლა**: როდესაც Claude-თან თავსებადი პროვაიდერი ხელმისაწვდომს ხდის `/messages/count_tokens`-ს, OmniRoute დიდი მოთხოვნების გაგზავნამდე მას იძახებს, ხოლო წარუმატებლობის შემთხვევაში შეუფერხებლად გადადის შეფასებაზე.

## 🛡️ უსაფრთხო გამავალი მოთხოვნები და SSRF-ისგან დაცვა _(v3.6.6+)_

პროვაიდერის ვალიდაციისა და მოდელების აღმოჩენის ყველა გამოძახება ახლა გამავალი მოთხოვნების ორეტაპიან დაცვას გადის:

1. **URL-ის დამცავი** (`src/shared/network/outboundUrlGuard.ts`) — სოკეტის გახსნამდე ბლოკავს კერძო/ლუპბექ/ლოკალური ბმულის IP დიაპაზონებს.
2. **უსაფრთხო მოთხოვნის გარსი** (`src/shared/network/safeOutboundFetch.ts`) — იყენებს URL-ის დამცავს, ახდენს დროის ამოწურვის პარამეტრების ნორმალიზებას და დროებითი შეცდომებისას მოთხოვნას ექსპონენციალური დაყოვნებით იმეორებს.

დამცავის დარღვევები ბრუნდება HTTP 422-ის სახით (`URL_GUARD_BLOCKED`) და `providerAudit.ts`-ის მეშვეობით შესაბამისობის აუდიტის ჟურნალში იწერება.

## 🔄 დაყოვნების პერიოდის გათვალისწინებით განმეორებითი მცდელობები _(v3.6.6+)_

ჩატის მოთხოვნები ახლა **ავტომატურად მეორდება**, როდესაც ზედა დონის პროვაიდერი კონკრეტული მოდელისთვის დაყოვნების პერიოდს აბრუნებს. კონფიგურირდება `REQUEST_RETRY`-ის (ნაგულისხმევი: 2) და `MAX_RETRY_INTERVAL_SEC`-ის (ნაგულისხმევი: 30 წმ) მეშვეობით. სიხშირის შეზღუდვის სათაურების შესწავლა გაუმჯობესდა `x-ratelimit-reset-requests`-ის, `x-ratelimit-reset-tokens`-ისა და `Retry-After`-ის მიხედვით — თითოეული მოდელის დაყოვნების პერიოდის მდგომარეობა ხილულია მდგრადობის საინფორმაციო დაფაზე.
