OmniRoute 352 მხარდაჭერილ პროვაიდერს 3 ეკონომიკურ დონედ აჯგუფებს. თითოეული
მოთხოვნა მათ თანმიმდევრულად გადის, სანამ რომელიმე წარმატებით არ უპასუხებს —
ამგვარად, სარეზერვო ლოგიკის კოდის დაწერის გარეშე იღებთ ყველაზე იაფ მისაღებ პასუხს.

## დონე 1 — გამოწერა

**პროვაიდერები, რომლებშიც უკვე იხდით.** OmniRoute კვოტის თითოეულ ერთეულს
ვადის ამოწურვამდე იყენებს.

| პროვაიდერი                         | რატომ დონე 1                                                  |
| ---------------------------------- | ------------------------------------------------------------- |
| Claude Code OAuth                  | Anthropic Pro/Team — ფიქსირებული ტარიფი, ხშირად გამოუყენებელი |
| OpenAI Codex (ChatGPT-ის გამოწერა) | Plus/Team მოიცავს Codex-ის კვოტას                             |
| GitHub Copilot                     | თითო მომხმარებელზე — კვოტა ყოველთვიურად ნულდება               |
| Cursor IDE                         | Pro გეგმის კვოტა                                              |
| Antigravity / Devin Desktop        | ჩაშენებული კვოტები                                            |

**სტრატეგია**: ყველა მოთხოვნა, რომელიც მოდელის ძლიერ მხარეებს შეესაბამება,
ჯერ აქ გადაამისამართეთ. კვოტის ტრეკერი მოახლოებულ განულებებს აკონტროლებს,
ხოლო `reset-aware` კომბინირებული სტრატეგია პრიორიტეტებს შესაბამისად ანაწილებს.
იმისთვის, რომ მოთხოვნები ჯერ დონე 1-ზე გადაამისამართოთ და ფასიან დონეებზე
მხოლოდ კვოტის ამოწურვისას გადახვიდეთ, გამოიყენეთ `auto/thrifty` id — ან
`auto/subscription`, რათა გეგმით გათვალისწინებული სიმძლავრის ფარგლებში დარჩეთ
და მის ამოწურვისას მოთხოვნა უარყოთ. იხილეთ
[გამოწერაზე პრიორიტეტული მარშრუტიზაცია](../routing/SUBSCRIPTION_LADDER.md).

## დონე 3 — უფასო

**ნულოვანი ღირებულების პროვაიდერები** — უფასო დონეები, საკრედიტო პროგრამები,
OAuth-ის ყოველდღიური კვოტები.

| ---------------- | ------------------------------------------------------------- |

| OpenCode Free    | ავტორიზაციის გარეშე, მოთხოვნების სიხშირის გულუხვი ლიმიტები    |
| Qoder            | უფასო OAuth                                                   |

**სტრატეგია**: ბიუჯეტის ლიმიტის მქონე კომბინაცია `auto` მოთხოვნებს აქ
ამისამართებს, როდესაც დონეები 1+2 ვერ პასუხობს ან დაყენებულია
`useFreeOnly=true`. უფასო პროვაიდერებს ხშირად მოთხოვნების სიხშირის უფრო მკაცრი
ლიმიტები აქვთ — circuit breaker მათ განმეორებითი მცდელობის დაყოვნების შემდეგ
აღადგენს.

## დონეების კონფიგურაცია

Dashboard → **Tiers** → მიანიჭეთ თქვენი პროვაიდერები. ნაგულისხმევი პარამეტრები
(`tierDefaults.json`-დან) გონივრულადაა შერჩეული; შეცვალეთ ისინი, როდესაც
კონკრეტული გამოწერებისთვის პრიორიტეტის მინიჭება ან გარკვეული პროვაიდერების
გამორიცხვა გსურთ.

Auto-Combo-ს 16-ფაქტორიანი შეფასება დონესაც ითვალისწინებს. იხილეთ
[`docs/routing/AUTO-COMBO.md`](../routing/AUTO-COMBO.md).

## ტელემეტრია

Dashboard → **Usage** აჩვენებს თითოეულ დონეზე დღიურად დახარჯული ტოკენების
რაოდენობას. გამოიყენეთ ეს შემდეგისთვის:

- დაადასტურეთ, რომ დონე 1 სრულად გამოიყენება (წინააღმდეგ შემთხვევაში გამოწერის ღირებულებას ფლანგავთ)
- განსაზღვრეთ, დონე 2-ის რომელი მოდელები ირჩევა ყველაზე ხშირად (შეამცირეთ 1-2-მდე)
- შეამოწმეთ, რომ დონე 3 სატესტო/საძიებო სამუშაოებზე თანხას ზოგავს

## გავრცელებული სქემები

### მხოლოდ უფასო სამუშაო დატვირთვა

```json
{
  "strategy": "auto",
  "config": { "auto": { "weights": { "costInv": 0.5, "tierPriority": 0.3 } } }
}
```

მოთხოვნებს მკვეთრად მიმართავს დონე 3-ისკენ; დონე 2-ს მხოლოდ მაშინ იყენებს,
თუ დონე 3 მიუწვდომელია.

### ჯერ გამოწერა, შემდეგ იაფი სარეზერვო ვარიანტი

```json
{
  "strategy": "priority",
  "targets": [
    { "provider": "claude-code-oauth", "weight": 1 },
    { "provider": "deepseek", "weight": 1 },
    { "provider": "kiro", "weight": 1 }
  ]
}
```

ცხადად განსაზღვრული დალაგებული სია, რომელიც შეესაბამება დონე 1 → დონე 2 → დონე 3-ს.
