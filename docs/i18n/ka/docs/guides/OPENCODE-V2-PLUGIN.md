`@omniroute/opencode-plugin-v2` თქვენს სრულ OmniRoute კატალოგს — მოდელებს, კომბინაციებსა და
ავტოკომბინაციებს — ამატებს OpenCode v2-ის მოდელების ამრჩევში, საჩვენებელ სახელებთან, ფასებთან და უფასო დონის
ლიმიტებთან ერთად.

ეს `@omniroute/opencode-plugin`-ისგან ცალკე პაკეტია, რადგან OpenCode v1 და v2
პლაგინებს განსხვავებული კონტრაქტებით ტვირთავს. აირჩიეთ თქვენი OpenCode-ის ძირითად ვერსიასთან შესაბამისი ვარიანტი;
მათ შორის არაფერია გაზიარებული, ამიტომ ერთის განახლება არასოდეს მოითხოვს მეორის განახლებას.

## მოთხოვნები

- OpenCode v2.
- ხელმისაწვდომი OmniRoute-ის კარიბჭე (ნაგულისხმევად `http://localhost:20128`).
- Node.js 22 ან 24.

## ინსტალაცია

დაამატეთ პლაგინი `opencode.json`-ში:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

ამის შემდეგ მოდელები გამოჩნდება ფორმატით `omniroute/<provider>/<model>`; `providerId` განსაზღვრავს ამ პრეფიქსსა და
იმ ინტეგრაციის id-ს, რომლის ქვეშაც OpenCode ავტორიზაციის მონაცემებს ინახავს.

## ავტორიზაციის მონაცემები

პლაგინი კარიბჭის გასაღებს შემდეგ სამ ადგილას, ამ თანმიმდევრობით ეძებს:

1. **OpenCode-ში დაკავშირებული ავტორიზაციის მონაცემები.** პლაგინი ინტეგრაციას არეგისტრირებს, ამიტომ
   OpenCode-ის საკუთარ ავტორიზაციის პროცესს შეუძლია გასაღების შენახვა. `opencode.json`-ში არაფერი იწერება — უპირატესობა ამ ვარიანტს მიანიჭეთ.
2. `apiKey` პლაგინის პარამეტრებში, კონკრეტული პროექტისთვის განსაზღვრული ჩანაცვლებისთვის. ამ შემთხვევაში გასაღები ინახება ფაილში,
   რომელიც შესაძლოა რეპოზიტორიაში ატვირთოთ.
3. გარემოში განსაზღვრული `OMNIROUTE_API_KEY`.

თუ არცერთი მათგანი არ არის მითითებული, კატალოგი ცარიელი იქნება და პლაგინი გაშვებისას ამის შესახებ ერთხელ შეგატყობინებთ,
ნაცვლად იმისა, რომ უხმოდ ცარიელი ამრჩევი დაგიტოვოთ.

### მართვის ტოკენი სხვა გასაღებია

კომბინაციები, პროვაიდერების მდგომარეობა და გამდიდრებული მონაცემები (საჩვენებელი სახელები, ფასები, უფასო დონის ლიმიტები) მიიღება
კარიბჭის `/api/*` საბოლოო წერტილებიდან, რომლებსაც განთავსებების უმეტესობა **მართვის** ტოკენით იცავს
და არა ინფერენციის გასაღებით:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<management read token>"
}
```

თუ `managementReadToken` მითითებული არ არის, სათადარიგოდ `apiKey` გამოიყენება. როდესაც კარიბჭე ამ სათადარიგო ვარიანტს
უარყოფს, კატალოგი მაინც ქვეყნდება, თუმცა საჩვენებელი სახელების ნაცვლად მოდელების დაუმუშავებელი id-ებით,
კანონიკური ფსევდონიმების დუბლიკატების მოცილების, ფასებისა და კომბინაციების გარეშე. როდესაც ეს ხდება, პლაგინი თითოეული საბოლოო წერტილისთვის ერთხელ
გასცემს გაფრთხილებას, სადაც ასახელებს საბოლოო წერტილს და დაკარგულ შესაძლებლობებს — ამიტომ შეზღუდული ამრჩევის მიზეზი ყოველთვის ნათელია.

| `managementReadToken`            | სათადარიგოდ იყენებს `apiKey`-ს                                  | გასაღები `/api/*`-ისთვის — ჩვეულებრივ, **არა** იგივე გასაღები                                                                         |
| `displayName`                    | `"OmniRoute"`                                                   | პროვაიდერის სახელი ამრჩევში                                                                                                           |

| `timeouts`                       | სათადარიგოდ იყენებს `timeoutMs`-ს                               | თითოეული საბოლოო წერტილის დროის ლიმიტები მწ-ში: `models`, `combos`, `autoCombos`, `enrichment`                                        |
| `enrichment`                     | `true`                                                          | სახელების, ფასებისა და უფასო დონის ლიმიტების მიღება                                                                                   |
| `providerTag`                    | `true`                                                          | საჩვენებელ სახელს წინ დაურთეთ ზედა დონის პროვაიდერი, რომლისკენაც მოთხოვნა მარშრუტდება                                                 |

## როგორ ინარჩუნებს კატალოგი განახლებულობას

კატალოგის მიღება ხდება საჭიროებისას და ის ქეშირდება `modelCacheTtlMs`-ის განმავლობაში, ხოლო დისკზე შენახული ანაბეჭდი უზრუნველყოფს, რომ ბოლო ცნობილი კატალოგი ხელმისაწვდომი დარჩეს მაშინაც, როდესაც კარიბჭე მიუწვდომელია — შეფერხებისას მხოლოდ განახლებულობას კარგავთ. მოდელები და კომბინაციები გამოქვეყნდება მიღებისთანავე; ავტომატური კომბინაციები, პროვაიდერების სია და გამდიდრების ზედნადები ფენა ინტეგრირდება მათი მიღებისთანავე, ამიტომ ერთი ნელი საბოლოო წერტილი მთელ ამომრჩეველს ვერ შეაფერხებს.

სახელები შეიცავს კარიბჭისთვის ცნობილ ინფორმაციას: ზემდგომ პროვაიდერს, რომელთანაც მოდელი მარშრუტდება, `[Free]` მონიშვნას და შესაბამის ბიუჯეტს — ასე რომ, ერთი და იმავე მოდელის გამყიდველი ორი კავშირი ერთმანეთისგან გარჩევადი რჩება. პრეფიქსის გამოსართავად გამოიყენეთ `"providerTag": false`.

ხელით განახლების ბრძანება არ არსებობს: OpenCode v2-ის ბრძანებები მოთხოვნის შაბლონებია და არა უკუგამოძახებები, ამიტომ პლაგინი ასეთ ბრძანებას ვერ გამოიტანს. განახლებები TTL-ს მიჰყვება; ჰოსტს ხელახალი ჩატვირთვა მხოლოდ მაშინ მოეთხოვება, როდესაც კატალოგი ან ზედნადები ფენა რეალურად შეიცვალა და არა ყოველი განახლებისას.

## ხელსაწყოების გამოძახება Gemini-ზე

Gemini მთლიანად უარყოფს მოთხოვნას, თუ მისი ხელსაწყოების დეკლარაციები შეიცავს `$schema`-ს ან
`additionalProperties`-ს და პასუხობს `400 INVALID_ARGUMENT`-ით. პლაგინი ამ პროვაიდერის Gemini მოდელისთვის განკუთვნილი ხელსაწყოების სქემებიდან ამ საკვანძო სიტყვებს შლის, ხოლო ყველა სხვა მოთხოვნას უცვლელად ტოვებს.
`$ref`-ის შემცველი ხელსაწყო წაშლის ნაცვლად უცვლელად გადაიგზავნება, რადგან მითითების ამოღება სქემას გააფართოებდა „ნებისმიერი რამის მიღებამდე“.
ამის გამოსართავად დააყენეთ `"geminiSanitization": false`.
