Caveman-ის შეკუმშვას ჩაშენებული ინგლისური წესების გარდა ენისთვის სპეციფიკური წესების პაკეტების ჩატვირთვაც შეუძლია.
ეს ინარჩუნებს ძირითადი ძრავის სტაბილურობას და, ამავდროულად, პორტუგალიური, ესპანური, გერმანული, ფრანგული, იტალიური, იაპონური და
სამომავლო ენების პაკეტებს დამოუკიდებლად განვითარების საშუალებას აძლევს.

## მდებარეობა

ენების პაკეტები განთავსებულია აქ:

```txt
open-sse/services/compression/rules/<language>/
```

ამჟამად მოწოდებული პაკეტები (გადამოწმებულია `rules/` დირექტორიის შიგთავსთან):

| ენა                     | დირექტორია     | არსებული წესების კატეგორიები                        |
| ----------------------- | -------------- | --------------------------------------------------- |
| ინგლისური               | `rules/en/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| ესპანური                | `rules/es/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| პორტუგალიური (ბრაზილია) | `rules/pt-BR/` | `context`, `dedup`, `filler`, `structural`, `ultra` |
| ინდონეზიური             | `rules/id/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| იტალიური                | `rules/it/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| გერმანული               | `rules/de/`    | `context`, `filler`, `structural`                   |
| ფრანგული                | `rules/fr/`    | `context`, `filler`, `structural`                   |
| იაპონური                | `rules/ja/`    | `context`, `filler`, `structural`                   |

> **შესაბამისობის შენიშვნა:** `en`, `es`, `pt-BR`, `id` და `it` პაკეტები ხუთივე სრულ კატეგორიას შეიცავს; `de`, `fr`, `ja` კი 3 კატეგორიით ვრცელდება. არარსებული `dedup` და `ultra` კატეგორიების შემთხვევაში სისტემა უხმაუროდ იყენებს ჩაშენებულ ინგლისურ წესებს. მცირე პაკეტებისთვის `dedup.json`-ისა და `ultra.json`-ის დამატებაში წვლილის შეტანა მისასალმებელია.
>
> `pt-BR` პაკეტი ეფუძნება Lenine Júnior-ის **[Troglodita](https://github.com/leninejunior/troglodita)**-ს — შეკუმშვის სისტემას, რომელიც თავიდანვე ბრაზილიური პორტუგალიურის გრამატიკისთვის შეიქმნა (პლეონაზმის შემცირება, PT-BR შემავსებელი სიტყვების მოცილება, ტექნიკური აბრევიატურები ბრაზილიელი დეველოპერების საზოგადოებისთვის).
>
> კატეგორიების კანონიკური სია და თითოეული კატეგორიის სქემა მოცემულია [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json)-ში (JSON Schema-ის მონახაზი 2020-12).

## ენის ამოცნობა

`languageDetector.ts` პრომპტის ტექსტიდან ენის დასადგენად მსუბუქ ევრისტიკებს იყენებს. კონფიგურაციაში
მითითებული ნაგულისხმევი ენა კვლავ გათვალისწინებულია, ხოლო ზუსტი კონტროლის საჭიროების შემთხვევაში
ამოცნობა კონფიგურაციიდან შეიძლება გაითიშოს.

ამოცნობის შედეგი მხოლოდ წესების პაკეტების ასარჩევად გამოიყენება. ის არ ცვლის პროვაიდერის მარშრუტიზაციას, ლოკალის
არჩევას ან მომხმარებლის ინტერფეისის ენას.

## კონფიგურაციის სტრუქტურა

შეკუმშვის პარამეტრები შეიძლება შეიცავდეს:

```json
{
  "languageConfig": {
    "enabled": true,
    "defaultLanguage": "en",
    "autoDetect": true,
    "enabledPacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  },
  "cavemanConfig": {
    "language": "en",
    "autoDetectLanguage": true,
    "enabledLanguagePacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  }
}
```

`languageConfig` მართავს დაფის/წინასწარი გადახედვის ნაგულისხმევ პარამეტრებს. `cavemanConfig` არის შესრულების დროის ძრავის კონფიგურაცია,
რომელიც გამოიყენება, როდესაც Caveman შეტყობინების ტექსტს კუმშავს.

## ენის პაკეტის დამატება

1. შექმენით `open-sse/services/compression/rules/<language>/<pack>.json`.
2. გამოიყენეთ Caveman-ის წესების ფორმატი ფაილიდან `docs/compression/COMPRESSION_RULES_FORMAT.md`.
3. ჩანაცვლებები კონსერვატიული უნდა იყოს და არ უნდა შეცვალოს კოდი, იდენტიფიკატორები, URL-ები ან JSON.
4. დაამატეთ ან განაახლეთ ტესტები ენის შერჩევისა და ჩანაცვლების ქცევისთვის.
5. თუ ენა UI-ის სელექტორებში გამოჩნდება, ხელმისაწვდომი გახადეთ ახალი dashboard/i18n-ჭდეები.

## API

ხელმისაწვდომი პაკეტების მოთხოვნა შესაძლებელია შემდეგი ბრძანებით:

```bash
curl http://localhost:20128/api/compression/language-packs
```

წინასწარი გადახედვის endpoint იღებს ენის კონფიგურაციის გადაფარვებს:

```bash
curl -X POST http://localhost:20128/api/compression/preview \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "standard",
    "text": "Por favor, eu gostaria que voce basicamente resumisse isso.",
    "config": {
      "languageConfig": {
        "defaultLanguage": "pt-BR",
        "autoDetect": true
      }
    }
  }'
```

## SHARED_BOUNDARIES (v3.8.0)

v3.8.0-ში ექვსივე ენის პაკეტს დაემატა `SHARED_BOUNDARIES`-ის პირობა, რომელიც Caveman-ის
ინტენსივობის ყველა დონეზე (LITE, FULL, ULTRA) გამოიყენება. ის ძრავას ავალებს, უცვლელად შეინარჩუნოს
ეს შაბლონები, მათ ირგვლივ არსებული შემავსებელი ტექსტის მოცილების მიუხედავად:

| შაბლონის ტიპი                            | მაგალითი                               |
| ---------------------------------------- | -------------------------------------- |
| შემოსაზღვრული კოდის ბლოკები              | ` ```python\n...\n``` `                |
| სტრიქონშიდა კოდი                         | `` `my_var` ``                         |
| URL-ები                                  | `https://example.com/path`             |
| ფაილის ბილიკები (აბსოლუტური + ფარდობითი) | `/etc/hosts`, `./src/index.ts`         |
| შეცდომის სათაურები                       | `Error:`, `TypeError:`, `SyntaxError:` |
| სტეკის კვალის სტრიქონები                 | `  at functionName (file.ts:12:3)`     |

ეს შაბლონები განთავსებულია `DEFAULT_CAVEMAN_CONFIG.preservePatterns`-ში (ადრე იყო `[]`).
კონსტანტა მდებარეობს `open-sse/services/compression/types.ts`-ში.

### რატომ არის ეს მნიშვნელოვანი

SHARED_BOUNDARIES-ის გარეშე Caveman-ის აგრესიულ რეჟიმებს შეეძლოთ ისეთი შიგთავსის წაშლა, რომელიც
განმეორებად პროზას ჰგავდა, თუმცა სინამდვილეში კოდის ფრაგმენტი, ფაილის ბილიკი ან შეცდომის სტეკი იყო.
SHARED_BOUNDARIES მოქმედებს როგორც ენისგან დამოუკიდებელი დამცავი მექანიზმი, რომელიც შემავსებელი
ტექსტის წესების შესრულებამდე გამოიყენება.

### preservePatterns-ის მორგება

დამატებითი შაბლონების დამატება შესრულების დროს შეკუმშვის პარამეტრების მეშვეობით შეიძლება:

````json
{
  "cavemanConfig": {
    "preservePatterns": [
      "```[\\s\\S]*?```",
      "`[^`]+`",
      "https?://\\S+",
      "(?:/|\\./)[^\\s]+",
      "\\b(?:Error|TypeError|SyntaxError|RangeError):",
      "\\s+at\\s+\\S+\\s+\\(\\S+:\\d+:\\d+\\)"
    ]
  }
}
````

მორგებული შაბლონები ექვს ნაგულისხმევ შაბლონს აფართოებს (და არ ანაცვლებს).

## საოპერაციო შენიშვნები

- როდესაც ენის პაკეტი არ არსებობს, სარეზერვო ვარიანტად ინგლისურის ჩაშენებული წესები რჩება.
- არასწორი ჩაშენებული JSON-პაკეტები ვალიდაციას ვერ გაივლის, რათა რელიზის რესურსების ხარისხი შეუმჩნევლად არ გაუარესდეს.
- წესების პაკეტები მხოლოდ მონაცემებს უნდა შეიცავდეს და არ უნდა ახდენდეს კოდის იმპორტს ან თვითნებური ლოგიკის შესრულებას.
- შეკუმშვის ანალიტიკის ფენა აღრიცხავს არჩეულ რეჟიმსა და ძრავას, მაგრამ არა მოთხოვნის სრულ ტექსტს.
