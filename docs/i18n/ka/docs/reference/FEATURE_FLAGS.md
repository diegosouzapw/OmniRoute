## რა არის ფუნქციური დროშები

ფუნქციური დროშა არის სახელდებული გადამრთველი (boolean ან enum), რომლის მნიშვნელობაც შეიძლება შეიცვალოს
შესრულების დროს და შენარჩუნდეს მონაცემთა ბაზაში, პროცესის ხელახლა განთავსების საჭიროების გარეშე. თითოეული
დროშა აღწერილია `FeatureFlagDefinition`-ით, რომელსაც აქვს `key`, `label`,
`description`, `category`, `defaultValue`, `type` და `requiresRestart` მინიშნება.

### მნიშვნელობის განსაზღვრის რიგითობა

დროშის **ეფექტური მნიშვნელობა** განისაზღვრება
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts)-ის მიერ შემდეგი
პრიორიტეტით (იმარჯვებს ყველაზე მაღალი):

1. **DB გადაფარვა** — `key_value` ცხრილში, `feature_flags`
   სახელთა სივრცეში შენახული მნიშვნელობა (დაყენებული მართვის პანელიდან ან REST API-დან).
2. **გარემოს ცვლადი** — `process.env[<KEY>]`, თუ დაყენებულია და ცარიელი არ არის.
3. **განსაზღვრების ნაგულისხმევი მნიშვნელობა** — `defaultValue` ფაილიდან `featureFlagDefinitions.ts`.

boolean დროშა **ჩართულად** ითვლება, როცა მისი ეფექტური მნიშვნელობაა `"true"`,
`"1"` ან `"yes"` (იხილეთ `isFeatureFlagEnabled()`).

> [!NOTE]
> დროშების უმეტესობას ასევე აქვს **იმავე სახელის** შესაბამისი გარემოს ცვლადი,
> რომელიც დოკუმენტირებულია [`ENVIRONMENT.md`](./ENVIRONMENT.md)-ში. დროშის DB გადაფარვას
> ამ გარემოს ცვლადზე მაღალი პრიორიტეტი აქვს. დროშა, რომელსაც აქვს
> `requiresRestart: true`, დაუყოვნებლივ ინახება, მაგრამ ხელახლა მხოლოდ პროცესის
> გაშვებისას იკითხება — მისი გადართვისას მართვის პანელში გამოჩნდება ბანერი **"სერვერის გადატვირთვა"**.

- თითოეული ალმისთვის **წყაროს ნიშანს** — `DB`, `ENV` ან `DEF` — რომელიც აჩვენებს, საიდან არის
  მიღებული მოქმედი მნიშვნელობა.
- **ჩამოყრის** ღილაკს (ნაჩვენებია მხოლოდ `DB` წყაროს მქონე ალმებისთვის) გადაფარვის მოსაშორებლად,
  და ქვედა ნაწილში ღილაკს **ყველა გადაფარვის ჩამოყრა**.
- ბანერს **სერვერის გადატვირთვა**, როდესაც იცვლება `requiresRestart` ალამი.

### REST API

ყველა ოპერაცია სრულდება ერთი მარშრუტის მეშვეობით:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
თითოეული მეთოდი მოითხოვს მართვის პანელის ავთენტიფიცირებულ სესიას (წინააღმდეგ შემთხვევაში — `401`).

#### `GET /api/settings/feature-flags`

აბრუნებს ყველა ალამს მისი მოქმედი მნიშვნელობით, წყაროთი და შეჯამებით.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... სულ 75 ალამი
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

ერთი გადაფარვის დაყენება ან წაშლა. მოთხოვნის სხეული: `{ key: string; value?: string }`.
`value`-ის გამოტოვება წაშლის გადაფარვას (აღადგენს env / ნაგულისხმევ მნიშვნელობას).

```bash
# DB გადაფარვის დაყენება
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# გადაფარვის წაშლა ("value"-ის გარეშე)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

პასუხი იმეორებს ახალ `effectiveValue`/`source`-ს, `previousValue`/
`previousSource`-ს და `requiresRestart`-ს. უცნობი გასაღებები და დასაშვებ დიაპაზონს გარეთ არსებული ჩამონათვლის
მნიშვნელობები უარყოფილია `400`-ით.

#### `DELETE /api/settings/feature-flags`

ერთდროულად ასუფთავებს **ყველა** DB გადაფარვას და თითოეულ ალამს უბრუნებს მის env / ნაგულისხმევ
მნიშვნელობას. აბრუნებს `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> ალმები, რომელთა `requiresRestart: true`, ძალაში შედის მხოლოდ პროცესის ხელახლა ჩატვირთვის შემდეგ.
> მართვის პანელის გადატვირთვის პროცესი იძახებს `POST /api/restart`-ს და შემდეგ პერიოდულად ამოწმებს
> `GET /api/health/ping`-ს, სანამ სერვერი კვლავ არ ამუშავდება.

## ბიუჯეტის საგანგებო სარეზერვო მექანიზმი

`OMNIROUTE_EMERGENCY_FALLBACK` (კატეგორია `runtime`, ნაგულისხმევი მნიშვნელობა `true`) მართავს
უფასო საგანგებო სარეზერვო გზას ფაილში
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
როდესაც ის ჩართულია, მოთხოვნები, რომლებიც სრულად ამოწურავს თავის ბიუჯეტს, პირდაპირი წარუმატებლობის
ნაცვლად გადამისამართდება უფასო სარეზერვო პროვაიდერთან/მოდელთან. ამ ქცევის გასათიშად და ბიუჯეტამოწურული მოთხოვნების
წარუმატებლად დასასრულებლად დააყენეთ `false` (ან `0`) — მართვის პანელის გადამრთველის, DB უგულებელყოფის ან
`OMNIROUTE_EMERGENCY_FALLBACK` გარემოს ცვლადის მეშვეობით. (მართვის პანელის გადამრთველის სახით დამატებულია PR-ებში #3741 / #3752.)
