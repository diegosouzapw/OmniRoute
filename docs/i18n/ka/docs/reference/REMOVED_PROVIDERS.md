ზოგიერთი სერვისი OmniRoute-ში იყო ინტეგრირებული, მოგვიანებით კი წაიშალა, რადგან მათმა
ოპერატორებმა ეს მოითხოვეს. ეს გვერდი ამ წაშლილი ინტეგრაციების მუდმივი ჩანაწერია. მისი ერთადერთი
მიზანია, თავიდან აიცილოს მათი შემთხვევით დაბრუნება: კონტრიბუტორს, რომელიც ძველ fork-ს, ქეშირებულ npm
tarball-ს, დაარქივებულ საკითხს ან „აღადგინეთ პროვაიდერი X“ მოთხოვნას იპოვის, უნდა ჰქონდეს ერთი ადგილი,
სადაც ნათქვამია: **ხელახლა არ დაამატოთ**.

ეს გვერდი **არ არის** გაუქმებული ან მუშაობაშეწყვეტილი სერვისების სია. ისინი აღრიცხულია
[`FREE_TIERS.md`](FREE_TIERS.md)-ში („წაშლილი / უფასო ტარიფის გარეშე“) და შეიძლება დაბრუნდნენ, თუ თავად
სერვისიც დაბრუნდება. ქვემოთ მოცემული ჩანაწერები შეიძლება დაბრუნდეს მხოლოდ მოთხოვნაში დასახელებული
ოპერატორის წერილობითი ნებართვით, ხოლო ამ ნებართვის ბმული ჩანაწერს უნდა დაერთოს.

## პოლიტიკა

1. **სერვისის ოპერატორის წაშლის მოთხოვნა სრულდება და განხილვას არ ექვემდებარება.** OmniRoute
   არცერთ გარე სერვისთან არ არის დაკავშირებული. როდესაც სერვისის ოპერატორი ინტეგრაციის წაშლას
   ითხოვს, ის იშლება, მიუხედავად იმისა, იყენებდა თუ არა ინტეგრაცია ოფიციალურ API-ს.
2. **„წაშლილი“ ნიშნავს OmniRoute-ის მიერ კონტროლირებად ყველა ზედაპირს.** შემსრულებელი, რეესტრის
   ჩანაწერი, პროვაიდერის id და alias, მოდელების სია, endpoints, გარემოს ცვლადები, ხატულა, dashboard-ის
   ბარათები, გენერირებული პროვაიდერის ცნობარი, `FREE_TIERS.md`, გარემოს ცნობარი, README-ში მოცემული
   რაოდენობები, `llm.txt` ასლები, სპეციალური ტესტები და golden snapshots, კოდის კომენტარები, CHANGELOG-ის
   პუნქტები (რეესტრში დაფიქსირებული შეჯერებით, იხილეთ `config/release/changelog-reconciliations.json`),
   GitHub Releases-ის შენიშვნები, wiki და GitHub-ის საკითხები, დისკუსიები და pull request-ები, რომელთა
   თემაც ეს პროვაიდერი იყო (საკითხები და დისკუსიები იშლება; pull request-ებს სათაური ეცვლება, მათი
   აღწერა ჩანაცვლდება და განხილვის თემა იკეტება, რადგან GitHub-ს pull request-ების წაშლა არ შეუძლია).
3. **არასოდეს დაამატოთ ხელახლა ამ გვერდზე არსებული ჩანაწერი წერილობითი ნებართვის გარეშე.** ეს მოიცავს
   id-ის ან alias-ის ნებისმიერ პროვაიდერთა კატალოგში დაბრუნებას, დომენების შემსრულებელში დამატებას,
   კონტრიბუტორის PR-ის მიღებას, რომელიც მას „აღადგენს“, მის უფასო მოდელების კატალოგში დამატებას ან
   OmniRoute-ის მეშვეობით მასთან დაკავშირების ხელით შესასრულებელი გზის დოკუმენტირებას. ასეთი PR-ები
   და საკითხები დახურეთ ამ გვერდის ბმულის მითითებით.
4. **ჩანაწერი მინიმალური უნდა იყოს.** აღრიცხეთ მხოლოდ ის, რაც მიმომხილველს ხელახალი დამატების
   ამოსაცნობად სჭირდება: იდენტიფიკატორები, დომენები, თარიღები და pull request, რომელმაც წაშლა
   განახორციელა. არ აღწეროთ, როგორ მუშაობდა ინტეგრაცია.
5. **რეგრესიისგან დამცავი ტესტია `tests/unit/removed-providers-blocklist.test.ts`.** ის წარუმატებლად
   სრულდება, თუ ქვემოთ მოცემული რომელიმე იდენტიფიკატორი ან დომენი კვლავ გამოჩნდება პროვაიდერთა
   კატალოგებში, შემსრულებლის რუკაში ან პროვაიდერთა რეესტრის წყაროებში. ახალი იდენტიფიკატორები ამ
   ტესტს იმავე PR-ში დაამატეთ, რომელშიც აქ ახალ სტრიქონს ამატებთ.

## ჩანაწერის დამატება

როდესაც წაშლის ახალი მოთხოვნა შემოვა:

1. დაადასტურეთ, რომ მოთხოვნა სერვისის ოპერატორისგან მოდის (მათი მხარდაჭერის მისამართიდან ან მათ მიერ
   კონტროლირებადი დომენიდან) და შეტყობინება კონფიდენციალურად შეინახეთ.
2. წაშალეთ ინტეგრაცია პოლიტიკის მე-2 პუნქტში მოცემული საკონტროლო სიის შესაბამისად. გასაღების არმქონე
   პროვაიდერისთვის ნიმუშად გამოიყენეთ [#12440](https://github.com/diegosouzapw/OmniRoute/pull/12440),
   ხოლო შენახული კავშირების მქონე API-გასაღების პროვაიდერისთვის — [#10210](https://github.com/diegosouzapw/OmniRoute/pull/10210)
   (დაამატეთ მიგრაცია).
3. ზემოთ მოცემულ ცხრილს ერთი სტრიქონი, ხოლო იდენტიფიკატორები
   `tests/unit/removed-providers-blocklist.test.ts`-ს იმავე PR-ში დაამატეთ.
4. PR-ის შერწყმის შემდეგ ოპერატორს უპასუხეთ და ჩამოთვალეთ, რა წაიშალა და რისი შეცვლა არ შეუძლია
   OmniRoute-ს (უკვე გამოქვეყნებული npm და Docker ვერსიები, git-ის ისტორია, მესამე მხარის fork-ები).
