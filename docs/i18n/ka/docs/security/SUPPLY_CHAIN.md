OmniRoute აქვეყნებს npm + Docker არტეფაქტებს. ეს ბარიერები უზრუნველყოფს წარმოშობის დადასტურებას,
ინვენტარიზაციას (SBOM) და CVE სკანირებას; ყველა მათგანი OSS-ია და ინტეგრირებულია გამოშვების სამუშაო პროცესებში.
**პირველ რიგში სარეკომენდაციო** მიდგომა — ამჟამად ისინი მხოლოდ ანგარიშს ქმნიან, ხოლო პირველი
წარმატებული გამოშვების შემდეგ დამბლოკავ რეჟიმზე გადავლენ.

| ბარიერი                | ხელსაწყო                                       | სად                                | ბლოკავს?                         | შედეგი                                                     |
| ---------------------- | ---------------------------------------------- | ---------------------------------- | -------------------------------- | ---------------------------------------------------------- |
| SLSA წარმოშობა (npm)   | `npm --provenance` (OIDC)                      | `npm-publish.yml`                  | მხოლოდ გამოქვეყნების ჩავარდნისას | npmjs ნიშანი / `npm audit signatures`                      |
| npm-ის SBOM            | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`                  | მხოლოდ გენერირების ჩავარდნისას   | გამოშვების რესურსი + არტეფაქტი                             |
| იმიჯის SBOM            | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (გაერთიანება) | სარეკომენდაციო                   | CycloneDX არტეფაქტი                                        |
| Trivy CVE (SARIF)      | `aquasecurity/trivy-action`                    | `docker-publish.yml` (გაერთიანება) | სარეკომენდაციო                   | SARIF (HIGH+CRITICAL) → უსაფრთხოების ჩანართი               |
| Trivy CRITICAL ბარიერი | `aquasecurity/trivy-action`                    | `docker-publish.yml` (გაერთიანება) | **დამბლოკავი**                   | `exit-code: '1'` გამოსწორებად CRITICAL-ზე                  |
| osv vulnCount          | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`)      | **დამბლოკავი**                   | `metrics.vulnCount`-ის ზღვარს ამკაცრებს (`direction:down`) |
| OpenSSF Scorecard      | `ossf/scorecard-action`                        | `scorecard.yml` (cron)             | სარეკომენდაციო                   | SARIF → უსაფრთხოება + ნიშანი                               |

იმიჯის CVE ზღვრის თანდათან გამკაცრება `docker-publish.yml`-ში **ორ ნაბიჯს** იყენებს: SARIF ნაბიჯი
(`HIGH,CRITICAL`, `exit-code: 0`) HIGH+CRITICAL დონეებს უსაფრთხოების ჩანართში ხილულად
ტოვებს დაბლოკვის გარეშე; _CRITICAL ბარიერის_ ნაბიჯი (`severity: CRITICAL`, `ignore-unfixed: true`,
`exit-code: 1`) გამოშვებას აჩერებს CRITICAL CVE-ის შემთხვევაში, **თუ გამოსწორება ხელმისაწვდომია**. `ignore-unfixed`
არ აძლევს ბარიერს საშუალებას, დაბლოკოს გამოშვება საბაზისო იმიჯის CVE-ის გამო, რომლისთვისაც ზედა დონის მომწოდებელს
ჯერ პატჩი არ გამოუქვეყნებია.

## ⚠️ CVE-ის ცვალებადობა (დამბლოკავი osv/Trivy ბარიერები)

osv და Trivy დამოკიდებულებებს ადარებენ CVE მონაცემთა ბაზებს, რომლებიც **უწყვეტად იზრდება**. PR,
რომელიც **არცერთ დამოკიდებულებას არ ცვლის**, შეიძლება მოულოდნელად გაწითლდეს, რადგან არსებულ
დამოკიდებულებაში ახალი CVE გამოქვეყნდა (osv: გაზომილი `vulnCount` > საბაზისო მნიშვნელობა; Trivy: იმიჯში
ახალი გამოსწორებადი CRITICAL). **ეს დამბლოკავი CVE ბარიერის მოსალოდნელი საოპერაციო ქცევაა
და არა პროდუქტის რეგრესია.**

როდესაც osv ან Trivy ახლად გამოქვეყნებული CVE-ის გამო წითლდება, გამოსავალია:

1. **განაახლეთ დაზიანებული დამოკიდებულება** (სასურველია) — გადადით დაპატჩილ ვერსიაზე `package.json`-ის
   `overrides`-ის მეშვეობით (ტრანზიტიული დამოკიდებულებებისთვის), ან ხელახლა ააგეთ იმიჯი დაპატჩილ საბაზისო იმიჯზე.
2. **თუ ზედა დონის მომწოდებლისგან გამოსწორება არ არსებობს:**
   - **osv:** ხელახლა დააყენეთ `metrics.vulnCount`-ის საბაზისო მნიშვნელობა `config/quality/quality-baseline.json`-ში
     (`npm run quality:ratchet -- --update` გამოყოფილ ბარიერებს არ მოიცავს — მნიშვნელობა
     ხელით შეცვალეთ, `direction:down`) დასაბუთების შენიშვნით + თვალყურის სადევნებელი საკითხით.
   - **Trivy:** `.trivyignore`-ში დაამატეთ ჩანაწერი (თითო ხაზზე თითო CVE-ID) დასაბუთების
     კომენტარით + თვალყურის სადევნებელი საკითხით. `ignore-unfixed: true` უკვე ავტომატურად
     ფარავს CVE-ებს, რომლებისთვისაც პატჩები არ არსებობს.

ორივე ბარიერი **კორექტულად გამოტოვებს** შემოწმებას (exit 0), როდესაც ხელსაწყო არ არის ხელმისაწვდომი ან გაზომვა
ვერ სრულდება (osv-scanner არ არის PATH-ში, osv.dev/ქსელი მიუწვდომელია, JSON არასწორია) —
**გაზომვის** ჩავარდნა არასოდეს ბლოკავს; ბლოკავს მხოლოდ **გაზომილი** რეგრესია.
