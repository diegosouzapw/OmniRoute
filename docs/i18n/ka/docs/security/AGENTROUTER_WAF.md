`agentrouter`-ის ზედა დონის კარიბჭე `messages[].content`-ზე საკვანძო სიტყვებზე დაფუძნებულ შიგთავსის ფილტრს იყენებს. ფილტრი ნაწილობრივ დეტერმინისტულია (გარკვეულ ფრაზებს ყოველთვის ბლოკავს), ნაწილობრივ კი ალბათური (მოთხოვნების ნაკადზე მგრძნობიარეა — სწრაფი მოთხოვნების შემდეგ უფრო აგრესიული ხდება, ხოლო დაყოვნების პერიოდის შემდეგ აღდგება).

როდესაც WAF მოთხოვნას ბლოკავს, ის აბრუნებს:

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## ფილტრის მოქმედების სფერო

WAF ამოწმებს მხოლოდ `messages[].content`-ს. ის **არ** ამოწმებს:

- `system` მოთხოვნას
- სტრუქტურირებული შიგთავსის ბლოკებს (`tool_result`, `tool_use`, `thinking`, `image`)
- ხელსაწყოს `description` და `input_schema` ველებს
- მოთხოვნის მეტამონაცემებს, სათაურებს ან მოდელის id-ს

## ყოველთვის დაბლოკილი შაბლონები (რეგისტრის გაუთვალისწინებლად)

| შაბლონი                              | შენიშვნები                                           |
| ------------------------------------ | ---------------------------------------------------- |
| `Lorem ipsum`-ის ნებისმიერი ვარიანტი | სრული ლათინური lorem ლექსიკა იბლოკება                |
| `language model` (ცალკე)             | "the language model" და "large language model" გადის |
| `virtual assistant`                  | "AI assistant" გადის                                 |
| `I'm here to help`                   | ცალკე "here to help"-ც იბლოკება                      |
| `Claude, made by Anthropic`          | მხოლოდ სრული ფრაზა                                   |

## თითქმის ყოველთვის დაბლოკილი შაბლონები

| შაბლონი                                                       | შენიშვნები                                                |
| ------------------------------------------------------------- | --------------------------------------------------------- |
| `placeholder`                                                 | როდესაც ის ცალკე დგას (და არა პარამეტრის სახელად და ა.შ.) |
| `dummy data`                                                  | ფიქსტურებისთვის გავრცელებული საწყისი ფრაზა                |
| `foo bar baz`                                                 | კანონიკური ჩამნაცვლებელი ფრაზა                            |
| განმეორებადი მოკლე ტოკენები (`AAA BBB CCC`, `test test test`) | საკვანძო სიტყვებით გადავსების დეტექტორი                   |

## ქცევა დატვირთვისას

მოკლე დროის შუალედში დაახლოებით 5 სწრაფი მოთხოვნის შემდეგ WAF იწყებს ისეთი შიგთავსის დაბლოკვას, რომელიც ჩვეულებრივ გაივლიდა. ბაკეტი დაახლოებით 5–10 წამის უმოქმედობის შემდეგ თავისუფლდება. ეს არის იგივე IP-სა და გასაღებზე მიბმული სიხშირის შემზღუდველი, რომელიც წყვეტილ `400 content-blocked` შეცდომებს იწვევს, როდესაც Claude Code ან Codex CLI ერთმანეთის მიყოლებით სწრაფად ასრულებს ხელსაწყოს გამოყენების / შეტყობინების გაგზავნის რამდენიმე გამოძახებას.

## OmniRoute-ში უკვე გამოყენებული შემამსუბუქებელი ზომები

1. **`open-sse/services/wafRateLimit.ts`** — მოთხოვნების ნაკადის შემზღუდველი, რომელიც ნებისმიერ `agentrouter:*` URL-ზე გამავალ მოთხოვნებს შორის მინიმუმ 500 ms-იან ინტერვალს უზრუნველყოფს. ეს ინტერვალი ადამიანის მიერ დაყოვნების აღქმის ზღვარზე ბევრად დაბალია და ნორმალური ტრაფიკის დროს WAF-ის გააქტიურებას ხელს უშლის.

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — როდესაც ზედა დონის სერვისი აბრუნებს `400 content-blocked`-ს, შემსრულებელი იმავე URL-ზე მოთხოვნას ექსპონენციალური დაყოვნებით იმეორებს (1.5 s, 3.0 s, მაქსიმუმ 2 მცდელობა). ამ დაყოვნების შემდეგ WAF ჩვეულებრივ თავისუფლდება და განმეორებითი მოთხოვნა წარმატებით სრულდება.

3. **`tests/unit/compression/harness.test.ts`** — სატესტო ფიქსტურა `longInput` შეიცვალა `"lorem ipsum dolor sit amet ".repeat(40)`-დან `"example content for testing purposes ".repeat(40)`-ზე, რათა Claude Code-ის მიერ ამ ფაილის `Read` ხელსაწყოთი წაკითხვისას ფაილის შიგთავსი `tool_result` ბლოკის გავლით უკან არ დაბრუნდეს და WAF არ გაააქტიუროს.

## მითითებები მოთხოვნებისა და ხელსაწყოს შედეგებისთვის

თუ Claude Code-ის ან Codex CLI-ის სესია განმეორებით იღებს `400 content-blocked`-ს, შეამოწმეთ მომხმარებლის უახლესი შეტყობინება და ხელსაწყოს უახლესი შედეგი ზემოთ ჩამოთვლილი შაბლონების არსებობაზე და სხვაგვარად ჩამოაყალიბეთ. გავრცელებული გამოსავლებია:

- ჩაანაცვლეთ `Lorem ipsum …` ფრაზით `example text …` ან ფაქტობრივი შიგთავსით, რომლის მოდელირებასაც ტესტი ან ფიქსტურა ცდილობს.
- ჩაანაცვლეთ `placeholder` (როდესაც ცალკე დგას) ფრაზით `example value`, `sample value` ან რეალური მნიშვნელობით.
- ჩაანაცვლეთ `language model` ფრაზით `large language model` ან `the model`.
- ჩაანაცვლეთ `dummy data` ფრაზით `sample data` ან რეალისტური საწყისი მნიშვნელობებით.
- ჩაანაცვლეთ `I'm here to help` / `here to help` უფრო კონკრეტული შესავლით (მაგ., "I'll review the file you mentioned").

## ცრუ დადებითი შედეგების ზედა დონის სერვისისთვის შეტყობინება

მიმდინარე ფილტრი ზედმეტად აგრესიულია — ის `tool_result` ბლოკებში "Lorem ipsum"-ს ბლოკავს, მიუხედავად იმისა, რომ ოპერატორს აშკარად არ განუზრახავს მოთხოვნის ინექცია. ოპერატორები, რომლებსაც პრობლემის წყაროშივე გამოსწორება სურთ, ცრუ დადებითი შედეგების შესატყობინებლად `agentrouter.org`-ს უნდა დაუკავშირდნენ. ზემოთ მოცემული ბლოკირების სია 2026-08-03-ის მდგომარეობით ზედა დონის სერვისის ემპირიული შემოწმების შედეგია.
