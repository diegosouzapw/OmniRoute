## 💰 ~1.62B मोफत टोकन्स / महिना

</div>

> मोफत स्तर एकत्रितपणे हाताळणे त्रासदायक आहे — डझनभर SDKs, डझनभर दरमर्यादा आणि प्रत्यक्षात तुमच्याकडे किती उपलब्ध आहे याची कल्पनाच नसते. OmniRoute **35 आवर्ती पूल कीजमधील 491 मोफत-स्तर नोंदींची** सूची तयार करते आणि सामायिक पूलनुसार डिड्युप्लिकेट करून, **प्रकाशित सकारात्मक मासिक बजेट असलेले 17 पूल आणि प्रत्येक मॉडेलसाठी पाच Groq मर्यादा** यांच्या आधारे टोकनची ठळक संख्या मोजते. ज्या कोटा केवळ प्रादेशिक ओळख पडताळणीनंतर उपलब्ध होतात (सध्या: ModelScope), ते स्वतंत्रपणे दाखवले जातात—प्रादेशिक ओळख पडताळणीमागे +~6M—आणि ठळक संख्येत कधीही जोडले जात नाहीत. हा निकाल डॅशबोर्डवर (`/dashboard/free-tiers`) कायम दृश्यमान राहतो.

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="OmniRoute मोफत-स्तर बजेट कार्ड: दरमहा सातत्याने ~1.62B मोफत टोकन्स, साइनअप क्रेडिट्ससह पहिल्या महिन्यात कमाल ~2.22B, एका एंडपॉइंटमागे 491 सूचीबद्ध मोफत-स्तर नोंदी समाविष्ट करणाऱ्या 35 दस्तऐवजीकृत आवर्ती पूल कीजमधून. प्रामाणिक पूल-डिड्युप्लिकेट केलेली गणना — प्रत्येक सामायिक पूल केवळ एकदाच मोजला जातो; यात प्रकाशित सकारात्मक मासिक टोकन बजेट असलेले 17 आवर्ती पूल आणि प्रत्येक मॉडेलसाठी पाच Groq मर्यादा समाविष्ट आहेत; अटींशी संबंधित जोखीम सूचीमध्ये 13 प्रदात्यांना टाळावे असे चिन्हांकित केले आहे, जेणेकरून तुम्ही निर्णय घेऊ शकता. बजेट बारमध्ये Mistral 1B, Nara 210M, LLM7 150M, xKiro 150M, Groq 30M (प्रत्येक मॉडेलसाठी पाच मर्यादा) आणि लहान पूल समाविष्ट आहेत; तसेच पहिल्या महिन्यातील साइनअप क्रेडिट्स आणि कायमस्वरूपी मोफत, टोकन-मर्यादा नसलेले प्रदाते स्वतंत्रपणे दर्शवले जातात, जेणेकरून ते ठळक संख्या कृत्रिमरीत्या वाढवणार नाहीत. /dashboard/free-tiers वर थेट वापरलेले/शिल्लक."/>

> थेट `/dashboard/free-tiers` पृष्ठाचा अॅनिमेटेड सारांश. संपूर्ण कार्यपद्धती (पूल डिड्युप्लिकेशन, क्रेडिट स्तर, प्रदात्यांच्या अटी): **[docs/reference/FREE_TIERS.md](docs/reference/FREE_TIERS.md)**.
>
> <sub>या आकड्यांचे थेट सूचीच्या तुलनेत दर दोन आठवड्यांनी पुन्हा परीक्षण केले जाते आणि ते **दोन्ही दिशांनी बदलतात** — एखादा प्रदाता मोफत स्तर बंद करतो तेव्हा संख्या कमी होते; नवीन स्तर उपलब्ध झाल्यास ती वाढते. सूची प्रत्यक्षात जी गणना करते तेच आम्ही प्रकाशित करतो, सर्वोत्तम शक्य परिस्थिती गृहीत धरून वाढवलेला आकडा कधीही देत नाही.</sub>

<img src="./docs/diagrams/works-zero-config.svg" width="100%" alt="इंस्टॉल करताच लगेच कार्यरत — शून्य कॉन्फिग. तीन पायऱ्या: 1. इंस्टॉल करा — npm i -g omniroute, सर्व्हर localhost:20128 वर सुरू होतो. 2. तुमचे साधन http://localhost:20128/v1 कडे निर्देशित करा — कोणतेही OpenAI-सुसंगत साधन (Claude Code, Cursor, Cline). 3. ते उत्तर देते — कोणत्याही API की, नोंदणी किंवा कॉन्फिगरेशनशिवाय त्वरित उत्तरासाठी auto मॉडेल कॉल करा. कीविरहित प्रदाता OpenCode Free हा auto कॉम्बोमध्ये आधीपासून जोडलेला आहे, त्यामुळे नवीन इंस्टॉलेशन कोणत्याही अतिरिक्त सेटअपशिवाय प्रतिसाद देते."/>

```bash
# नवीन इंस्टॉलेशन, शून्य क्रेडेन्शियल्स — `auto` आधीपासूनच कार्यरत आहे:
```

## 📡 OmniRoute Radar

वरील दस्तऐवजीकृत, पूलमधील पुनरावृत्ती वगळलेल्या कॅटलॉगमधून मिळणारी मुख्य मोफत-स्तर मर्यादा **~1.62B टोकन/महिना** इतकीच आहे. प्रदात्यांकडून नोंदणीसाठी तात्पुरते मिळणारे क्रेडिट स्वतंत्रपणे पहिल्या महिन्याची मर्यादा **~2.22B** पर्यंत वाढवू शकते. OmniRoute च्या आवृत्त्यांदरम्यान मोफत मॉडेल्सच्या उपलब्धतेबद्दल अधिक अद्ययावत माहिती हवी असलेल्या लोकांसाठी Radar हा एक पर्यायी, स्वाक्षरीकृत कॅटलॉग ओव्हरले आहे; समुदाय कॅटलॉग आणि सध्या अस्तित्वात असलेली प्रत्येक मोफत सुविधा विनामूल्यच राहते.

समर्थकांना लाइव्ह कॅटलॉग आणि प्रदात्यांच्या अतिरिक्त संधी मिळू शकतात. प्रदात्यांच्या उपलब्धतेनुसार, त्याची स्वतंत्र आणि बदलणारी कमाल मर्यादा **जास्तीत जास्त अंदाजे 3B टोकन/महिना** आहे. ही कमाल मर्यादा हमी नाही: प्रदाते कोणत्याही वेळी कोटा, पात्रता, मॉडेल्स किंवा प्रदेश बदलू शकतात.

Radar वापरणे ऐच्छिक असून तो केवळ GET वापरतो. OmniRoute क्लायंट प्रॉम्प्ट्स, ट्रॅफिक, प्रदाता कॉन्फिगरेशन, वापरासंबंधी टेलिमेट्री किंवा स्थानिक घोषणा-डिसमिस स्थिती अपलोड करत नाही. पात्रता आणि सध्याच्या कॅटलॉगबद्दल **[radar.omniroute.online/planos](https://radar.omniroute.online/planos)** येथे जाणून घ्या.

```bash
omniroute run claude   --model openai/gpt-5.4          # Claude Code
omniroute run codex    --model glm/glm-5.2             # OpenAI Codex CLI
omniroute run aider    --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose    --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"
omniroute run qwen     --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini   --model glm/glm-5.2 -- --skip-trust -p "reply OK"

# किंवा provider+model परस्परसंवादी पद्धतीने निवडा आणि साधनाचे स्वतःचे कॉन्फिग लिहा:
omniroute configure codex          # हेही: claude opencode qwen aider goose gemini cline continue kilo
```

प्रत्येक कमांड सक्रिय रिमोट संदर्भाचे (`omniroute connect <host>`) पालन करते, `--dry-run`

OmniRoute सर्व्हरवर आहे? **त्याच CLI** द्वारे तुमच्या लॅपटॉपवरून ते चालवा. स्कोप केलेल्या अॅक्सेस टोकनने एकदा

## 🗜️ 15–95% टोकन्स वाचवा — स्वयंचलितपणे

</div>

### 📖 हे कसे कार्य करते — पाइपलाइन, आर्किटेक्चर आणि बचतीचे गणित

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute कॉम्प्रेशन पाइपलाइन: उदाहरणादाखल 10,000-टोकनची क्लायंट विनंती 12 संयोजनीय इंजिनांमधून जाते — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra आणि OmniGlyph — आणि दस्तऐवजीकरणातील स्टॅक केलेल्या उदाहरणात सुमारे 1,080 टोकन्ससह प्रदात्यापर्यंत पोहोचू शकते. संरचित सामग्रीचे संरक्षण जतन-सुरक्षा आणि प्रत्येक टप्प्यावरील अचूकता गेट्सद्वारे केले जाते; स्पष्टपणे निवडलेले हानीकारक किंवा प्रायोगिक मोड पात्र सामग्रीचे रूपांतर करू शकतात."/>

डीफॉल्ट स्टॅक केलेले संयोजन `RTK → Caveman` चालवते. दोन्ही एकाच टूल/कॉन्टेक्स्ट पेलोडवर कार्य करतात तेव्हा बचत चक्रवाढ पद्धतीने वाढते:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

कोड ब्लॉक्स, URLs, JSON आणि संरचित डेटा जतन इंजिनद्वारे **नेहमी संरक्षित** केले जातात.

> **थोड्या टोकन्समध्ये काम होत असताना अनेक टोकन्स का वापरायचे?** प्रत्येक विनंती OmniRoute च्या कॉम्प्रेशन पाइपलाइनमधून **पारदर्शकपणे** जाते — क्लायंटमध्ये कोणतेही बदल आवश्यक नाहीत. आता हा **12 संयोजनीय इंजिनांचा स्टॅक** आहे, जो क्रमाने चालतो आणि प्रत्येक राउटिंग संयोजनानुसार घटक एकत्रित करतो — [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K+), [LLMLingua-2](https://github.com/microsoft/LLMLingua), आणि [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR) यांच्या कल्पनांवर आधारित.

### 🧱 12-इंजिनांचा स्टॅक

### 🎚️ इंजिनांच्या पलीकडे — आउटपुट शैली, अनुकूलनीय डायल आणि प्रत्येक विनंतीनुसार नियंत्रण

वरील 12 इंजिने आत जाणारा मजकूर संक्षिप्त करतात. आणखी तीन स्तर **कसे**, **केव्हा**, आणि **काय बाहेर येते** हे ठरवतात:

- **🪄 आउटपुट शैली** _(आउटपुट-अक्ष नियंत्रण)_ — निर्धारक, कॅश-सुरक्षित प्रतिसाद-आकारणी सूचना अंतर्भूत करतात; एकत्र वापरता येतात, प्रत्येकाची तीव्रता `lite` / `full` / `ultra` असते. शैली जोडण्यासाठी रजिस्ट्रीमध्ये केवळ एका ओळीची नोंद पुरेशी आहे:
  - **संक्षिप्त गद्य** — अनावश्यक मजकूर / उपपदे / संदिग्धता काढा; तांत्रिक आशय अचूक ठेवा.
  - **कमी कोड** — "आळशी वरिष्ठ विकसक" YAGNI: सर्वात छोटा कार्यरत बदल, न मागितलेली पूर्वरचना नाही.
  - **पोनीटेल (आळशी वरिष्ठ विकसक)** — YAGNI पायरी चढा, मूळ कारण दुरुस्त करा, सर्वात छोटा कार्यरत फरक ठेवा.
  - **मला ADHD आहे (कृती-प्रथम)** — पुढील कृती सर्वप्रथम, क्रमांकित पायऱ्या, एक ठोस पुढील पाऊल, प्रस्तावना नाही.
  - **संक्षिप्त CJK (文言)** — अभिजात-चिनी अतिसंक्षिप्त शैली (`zh` स्थानिकेसाठी मर्यादित).
- **🎯 अनुकूलनीय संदर्भ-बजेट** _(डायल)_ — एकाच चालू/बंद टोकन मर्यादेऐवजी, **मॉडेलच्या संदर्भ विंडोमध्ये बसण्यासाठी** आवश्यक तेवढ्याच प्रमाणात सर्वात स्वस्त, कमीतकमी माहिती गमावणारी इंजिने सक्रिय करा. धोरण: `reserve-output` (डीफॉल्ट, मॉडेल-जागरूक) · `percentage` · `absolute`. मोड: `floor` (बसण्याची हमी) · `replace-autotrigger` (तुमची स्पष्ट निवड प्राधान्याने लागू) · `off` (जुनी मर्यादा).
- **🎛️ संक्षेपण कुठे ठरवले जाते** _(प्राधान्यक्रम, उच्च → निम्न)_ — प्रत्येक विनंतीचा `x-omniroute-compression` हेडर › राउटिंग-कॉम्बो ओव्हरराइड › सक्रिय नामित प्रोफाइल › अनुकूलनीय / स्वयं-ट्रिगर › पॅनेल डीफॉल्ट › बंद. लागू केलेली योजना `X-OmniRoute-Compression: <mode>; source=<source>` प्रतिसाद हेडरमध्ये परत दर्शवली जाते.

टोकन मर्यादेनुसार स्वयं-ट्रिगर करा, अनुकूलनीय डायल चालू करा, नामित प्रोफाइल निश्चित करा, प्रत्येक विनंतीसाठी एकदाच सेट करा किंवा प्रत्येक राउटिंग कॉम्बोसाठी पाइपलाइन नेमा — कार्यभाराला जे योग्य असेल ते वापरा. बदल लागू करण्यापूर्वी, निवड-वैकल्पिक ऑफलाइन **मूल्यांकन हार्नेस** (`npm run eval:compression`) निश्चित कॉर्पसवर अचूकता विरुद्ध बचत यांचे गुणांकन करते.

## 📦 इंस्टॉल करण्याच्या आणखी पद्धती — Docker, सोर्स, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

`:latest` हे सर्वाधिक आवृत्तीच्या **प्रकाशित** स्थिर SemVer चे अनुसरण करते. ते git `main` चे अनुसरण करत नाही. GitOps साठी `:X.Y.Z` निश्चित करा. [Docker प्रकाशन चॅनेल](docs/guides/DOCKER_GUIDE.md#release-channels) पहा. या इमेजमध्ये **`OMNIROUTE_MEMORY_MB=1024`** निश्चित केलेले आहे. डॅशबोर्ड आणि हलक्या चॅटसाठी ते पुरेसे आहे. **कोडिंग एजंट्सना** (Claude Code, Codex, Grok, … कडून `POST /v1/responses`) यापेक्षा खूप मोठ्या V8 heap ची आवश्यकता असते; अन्यथा दोन दीर्घ संदर्भ एकाच वेळी चालू असताना सुमारे 12 GiB वर प्रक्रियेत `FATAL ERROR` येतो. कंटेनरचा आकार heap पेक्षा मोठा ठेवा (नेटिव्ह बफर्स V8 च्या बाहेर असतात):

| कार्यभार                            | Heap (`-e OMNIROUTE_MEMORY_MB`) | कंटेनर (`--memory`) |
| ----------------------------------- | ------------------------------- | ------------------- |
| डॅशबोर्ड / हलकी चॅट                 | `1024` (इमेज डीफॉल्ट)           | ≥2 g                |
| एक कोडिंग एजंट                      | `8192`                          | ≥10 g               |
| एकाच वेळी दोन दीर्घ `/v1/responses` | `10240`–`12288`                 | ≥12–16 g            |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

**🥟 Bun**

Bun रनटाइम शोधाद्वारे मानक `bun install` आणि जागतिक इंस्टॉलेशन (`bun install -g omniroute`) समर्थित आहेत:

- **अंगभूत `bun:sqlite`**: Bun अंतर्गत चालत असताना OmniRoute, Bun चा अंगभूत `bun:sqlite` ड्रायव्हर वापरतो आणि Node.js वर `better-sqlite3` किंवा `sql.js` चा पर्याय म्हणून वापर करतो.
- **डेव्हलपमेंटमध्ये स्वयंचलित Webpack बंडलर निवड**: नेटिव्ह V8 बाइंडिंग विसंगती टाळण्यासाठी डेव्हलपमेंट (`bun run dev`) आपोआप Bun शोधते आणि Webpack च्या बाजूने Turbopack अक्षम करते. प्रॉडक्शन बिल्ड (`bun run build`) Node प्रमाणेच `OMNIROUTE_USE_TURBOPACK` चे तंतोतंत अनुसरण करतात: डीफॉल्टनुसार Turbopack, तर Webpack सह बिल्ड करण्यासाठी `OMNIROUTE_USE_TURBOPACK=0` (`Dockerfile.bun` ते `--build-arg` म्हणून उपलब्ध करून देते).
- **समर्पित Bun Dockerfile**: नेटिव्ह Bun प्रॉडक्शन डिप्लॉयमेंटसाठी मल्टी-स्टेज `Dockerfile.bun` (`docker build -f Dockerfile.bun -t omniroute:bun .`).

```bash
bun run dev
```

**⚡ अधिक जलद / हलके इंस्टॉलेशन (नेटिव्ह बिल्ड वगळा)**

नेटिव्ह SQLite इंजिन (`better-sqlite3`) हे **पर्यायी** अवलंबित्व आहे, त्यामुळे जागतिक
इंस्टॉलेशन सोर्समधून कंपाइल होण्याची प्रतीक्षा करत थांबत नाही: तुमच्या प्लॅटफॉर्म/Node शी जुळल्यास ते पूर्व-बिल्ड केलेली बायनरी वापरते
आणि अन्यथा पारदर्शकपणे शुद्ध-JS इंजिनकडे जाते
(Node 22+ वर `node:sqlite`, अन्यथा बंडल केलेले `sql.js` WASM) — कोणत्याही बिल्ड साधनांची आवश्यकता नाही.

इंस्टॉलेशननंतरचे नेटिव्ह वॉर्म-अप पूर्णपणे वगळण्यासाठी (CI, हेडलेस किंवा धीमी यंत्रे):

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 देखील ते वगळते
```

सर्वात जलद इंस्टॉलेशनसाठी **pnpm** ला प्राधान्य द्या (कंटेंट-अॅड्रेस्ड स्टोअर + हार्ड लिंक्स — वरील माहिती पहा).
डॅशबोर्डविरहित, हेडलेस रनटाइमसाठी Docker `base` प्रोफाइल (वरील) किंवा
[Termux मार्गदर्शक](docs/guides/TERMUX_GUIDE.md) वापरा. CLI आणि वेब डॅशबोर्ड एकाच प्रक्रियेद्वारे
एकाच पोर्टवर उपलब्ध केले जातात, त्यामुळे सध्या स्वतंत्र CLI-मात्र पॅकेज नाही.
