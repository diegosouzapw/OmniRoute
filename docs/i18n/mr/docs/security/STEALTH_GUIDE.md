OmniRoute अशा प्रदात्यांसोबत एकत्रित होते ज्यांच्या एज प्रणाली अनधिकृत क्लायंटचे सक्रियपणे फिंगरप्रिंटिंग करतात (TLS JA3/JA4, हेडर क्रम, JSON बॉडीची रचना, इंटेग्रिटी टोकन). हे पृष्ठ OmniRoute उपलब्ध करून देत असलेल्या स्टेल्थ पृष्ठभागांचे आणि त्यांच्या अंमलबजावणीच्या स्थानांचे दस्तऐवजीकरण करते.

## कायदेशीर आणि नैतिक सूचना

स्टेल्थ वैशिष्ट्ये यासाठी अस्तित्वात आहेत, जेणेकरून OmniRoute वापरकर्त्याच्या मालकीची अधिकृत खाती (Claude Code CLI, Codex, Antigravity, Cursor, इ.) आणि OmniRoute चे एकीकृत API यांच्यात सुसंगतता स्तर म्हणून काम करू शकेल. ती फसवणूक शोध प्रणाली चुकवण्यासाठी, क्रेडेन्शियल्स सामायिक करण्यासाठी किंवा प्रदात्याच्या सेवा अटींचे उल्लंघन करण्यासाठी **नाहीत**. देखभालकर्त्यांची अपेक्षा आहे की ऑपरेटर खाती तयार करताना त्यांनी मान्य केलेल्या अपस्ट्रीम ToS चे पालन करतील.

## TLS फिंगरप्रिंटिंग स्तर

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

प्रत्येक खाते-व्याप्ती आणि निराकरण केलेल्या प्रॉक्सीसाठी कायमस्वरूपी `wreq-js` सत्रे आवश्यकतेनुसार विलंबित रीतीने तयार केली जातात. संपूर्ण प्रक्रियेत वापरला जाणारा `TlsClient`, Cloudflare मागे असलेल्या अपस्ट्रीमसाठी **macOS वरील Chrome 124** ची नक्कल करणारी कमाल 128 सत्रे पूलमध्ये ठेवतो. नेटिव्ह रनटाइम उपलब्ध नसताना `TlsClient.fetch()` सुरक्षितपणे अपयशी ठरतो; कॉलर या रॅपरबाहेर स्पष्टपणे फॉलबॅक निवडू शकतो.

- सत्र प्रोफाइल: `browser: "chrome_124", os: "macos"`
- प्रॉक्सी निराकरण (प्राधान्यक्रम): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (लोअर-केस रूपेही)
- टाइमआउट: `TLS_CLIENT_TIMEOUT_MS` (`FETCH_TIMEOUT_MS` कडून वारशाने मिळतो, डीफॉल्ट 600000)
- `wreq-js` Response हे fetch-सुसंगत आहे (`headers`, `text()`, `json()`, `clone()`, `body`).
- प्रथम-बाइट वॉचडॉग (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656): अपस्ट्रीम हेडर्स येताच `TlsClient.fetch()`
  निराकरण होते, त्यामुळे केवळ `TLS_CLIENT_TIMEOUT_MS` कधीही पहिला बाइट न देणाऱ्या
  बॉडीला मर्यादित करू शकत नाही. `guardTlsFirstByte()` बॉडीच्या पहिल्या `read()` ची
  `TLS_FIRST_BYTE_WATCHDOG_MS` सोबत शर्यत लावते (डीफॉल्ट `10000`, `0` ते अक्षम करते); निरोगी बॉडीवर
  परिणाम होत नाही, तर अडकलेली बॉडी wreq रीडर रद्द करते आणि `proxyFetch` चे विद्यमान
  TLS-फॉलबॅक लॉजिक थेट/प्रॉक्सी डिस्पॅचरकडे पुढे जाऊ देते (रीप्ले-सुरक्षित नसलेली विनंती, उदा.
  बॉडी असलेली POST, मूकपणे पुन्हा प्रयत्न करण्याऐवजी तरीही त्रुटी फेकते).

### वेब-कुकी प्रदाता ट्रान्सपोर्ट — wreq-js 3.2.0

`open-sse/services/tlsClientBase.ts` हा खालील पाच विशेषीकृत
वेब-कुकी ट्रान्सपोर्टसाठी सामायिक अॅडॅप्टर आहे. प्रत्येक साधा प्रदाता रॅपर ब्राउझर/OS प्रोफाइल निवडतो. हा अॅडॅप्टर
`open-sse/utils/tlsClient.ts` मधील एकमेव wreq रनटाइम लोडर आणि ट्रान्सपोर्ट पूल वापरतो, ज्याची की
प्रोफाइल + OS + निराकरण केलेला प्रॉक्सी अशी असते, तर प्रत्येक विनंती `cookieMode: "ephemeral"` वापरते. त्यामुळे खाती आणि
विनंत्या ट्रान्सपोर्ट-स्तरीय कनेक्शन्स सामायिक करतात, परंतु wreq सत्र किंवा कुकी जार कधीही सामायिक करत नाहीत.

| प्रदाता    | प्रोफाइल      | अनुकरण केलेली OS | स्ट्रीम EOF धोरण                      |
| ---------- | ------------- | ---------------- | ------------------------------------- |
| Claude     | `chrome_146`  | Linux            | `[DONE]` समाविष्ट करा                 |
| Perplexity | `firefox_148` | macOS            | `event: end_of_stream` समाविष्ट करा   |
| Grok       | `chrome_146`  | Linux            | `[DONE]` वगळा                         |
| Notion     | `chrome_146`  | Windows          | `[DONE]` समाविष्ट करा                 |
| LMArena    | `chrome_146`  | Windows          | सेंटिनेल नाही; नेटिव्ह EOF वर बंद करा |

- स्ट्रीमिंग थेट नेटिव्ह प्रतिसाद `ReadableStream` वापरते; कोणतीही तात्पुरती फाइल किंवा साइडकार
  तयार केला जात नाही.
- स्ट्रीम उघड करण्यापूर्वी प्रारंभिक कमाल 256 बाइट्स तपासले जातात. SSE प्रदाते SSE नसलेल्या
  त्रुटी बफर करतात; Grok/LMArena Cloudflare आव्हानांना `403` आणि HTML इंटरस्टिशियल्सना `502` मध्ये मॅप करतात.
- नेटिव्ह विनंती टाइमआउटभोवती निरपेक्ष JS हार्ड डेडलाइनचे आवरण कायम राहते. हँग झाल्यास
  फक्त प्रभावित प्रोफाइल/OS/प्रॉक्सी ट्रान्सपोर्ट अवैध ठरवून बंद केला जातो आणि पुढील विनंती तो पुन्हा तयार करते.
- प्रॉक्सी निराकरणाचा प्राधान्यक्रम प्रत्येक कॉलसाठी `proxyUrl` → विनंती-व्याप्त खाते/डॅशबोर्ड संदर्भ →
  `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (लोअरकेस रूपांसह) असा आहे. निराकरणातील त्रुटी थेट कनेक्शन
  लीक करण्याऐवजी सुरक्षितपणे अपयशी ठरतात. LMArena जाणीवपूर्वक `arena.ai` च्या संदर्भात निराकरण करते.
- `byteResponse`, UTF-8 भ्रष्ट न करता सामग्री-प्रकारयुक्त `data:` URL परत करते.
- सर्व 128 मर्यादित प्रोफाइल/OS/प्रॉक्सी स्लॉट सक्रिय किंवा बंद होत असताना त्रुटी अनुक्रमे
  `TlsClientUnavailableError` (पॅकेज/अॅडऑन अनुपलब्ध), `TlsClientHangError`
  (डेडलाइन ओलांडली), आणि `WreqTransportCapacityError` (सामायिक सत्र-क्षमता त्रुटी कोड)
  अशा असतात.

वरील जेनेरिक `TlsClient` सत्र कायमस्वरूपी ब्राउझर-समर्थित कुकी
स्थितीसाठी विशेषीकृत राहते. दोन्ही मार्ग एकाच कॅश केलेल्या wreq मॉड्यूल लोडरचा आणि प्रक्रिया जीवनचक्र हुकचा पुनर्वापर करतात; त्यांचे पूल
स्वतंत्र राहतात, कारण त्यांच्या कुकींचे आयुर्मान हेतुपुरस्सर वेगवेगळे आहे.

ही प्रोफाइल्स पिन केलेल्या पॅकेजद्वारे समर्थित आहेत, परंतु वास्तविक WAF स्वीकृती स्थानिक
करार चाचण्यांपासून स्वतंत्रपणे बदलू शकते. अपस्ट्रीम ब्राउझरशी समतुल्यता असल्याचा दावा करण्यापूर्वी, स्पष्टपणे अधिकृत केलेल्या लाइव्ह खात्यावर
फिंगरप्रिंट बदल सत्यापित करा.

## Claude Code स्टेल्थ बंडल

`cliCompatMode` सुरू असताना, OmniRoute बाहेर जाणाऱ्या Claude विनंत्यांना अशा प्रकारे पुनर्रचित करते की त्या `claude-cli` ट्रॅफिकपासून वेगळ्या ओळखता येत नाहीत. तीन मॉड्यूल्स एकत्रितपणे कार्य करतात:

### `claudeCodeFingerprint.ts`

बिलिंग हेडरमध्ये एम्बेड केलेला 3-वर्णांचा `cc_version` फिंगरप्रिंट मोजते:

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (हार्डकोड केलेले; अधिकृत क्लायंटशी जुळते)
- इनपुट्स: पहिल्या वापरकर्ता संदेशाच्या मजकुरातील इंडेक्स 4, 7, 20 वरील वर्ण + आवृत्ती स्ट्रिंग
- आउटपुट: 3-वर्णांचा हेक्स प्रीफिक्स

### `claudeCodeCCH.ts` (क्लायंट सामग्री हॅश)

अधिकृत Claude Code CLI द्वारे Bun/Zig वापरून केली जाणारी सर्व्हर-साइड अखंडता तपासणी. OmniRoute तिची `xxhash-wasm` वापरून पुनर्अंमलबजावणी करते:

1. बॉडीला `cch=00000;` प्लेसहोल्डरसह सिरियलाइझ करा
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. शून्यांनी पॅड केलेला 5-वर्णांचा लोअरकेस हेक्स
4. `cch=00000;` च्या जागी मोजलेले टोकन ठेवा

स्थिरांक:

- सीड: `0x6e52736ac806831e`
- पॅटर्न: `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

"संवेदनशील" क्लायंट नावांच्या पहिल्या वर्णानंतर Unicode **झिरो-विड्थ जॉइनर** (`U+200D`) घालते, जेणेकरून अपस्ट्रीम फिल्टर्सना `grep` वापरून ती शोधता येणार नाहीत. डीफॉल्ट शब्दसूची:

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

यावर लागू होते: `system` ब्लॉक्स, सर्व `messages[].content`, आणि `tools[].description` / `tools[].function.description`. ऑपरेटर `setSensitiveWords()` द्वारे हे ओव्हरराइड करू शकतो.

### `claudeCodeCompatible.ts` — `anthropic-compatible-cc-*` प्रोव्हायडर्स

केवळ "खरे Claude Code" ट्रॅफिक स्वीकारणाऱ्या तृतीय-पक्षीय Anthropic रिलेसाठी:

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.258 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- डीफॉल्टनुसार `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"`
- प्रत्येक कनेक्शनसाठी असलेले "Enable redact-thinking beta" टॉगल, CC Compatible अपस्ट्रीमला विशेषतः रिडॅक्ट केलेले थिंकिंग स्ट्रीम्स आवश्यक असताना `redact-thinking-2026-02-12` जोडते

## Antigravity स्टेल्थ

Antigravity विनंत्या कॉलरचा मजकूर बाइट-टू-बाइट जसाच्या तसा जतन करतात. IDE क्लायंटचे अनुकरण करण्यासाठी OmniRoute प्रॉम्प्ट्समध्ये झिरो-विड्थ वर्ण घालत नाही किंवा टूल्सची नावे बदलत/इंजेक्ट करत नाही.

### `antigravityHeaderScrub.ts`

फॉरवर्ड करण्यापूर्वी Stainless SDK मार्कर्स (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`) काढून टाकते.

### ⚠️ धोका: `ANTIGRAVITY_CREDITS=always` (खाते-बंदीचा अतिसंवेदनशील मुद्दा)

`ANTIGRAVITY_CREDITS=always` (`open-sse/executors/antigravity.ts` द्वारे वापरले जाते) Google च्या फ्री-टियर कोटाला विनंत्या नियंत्रित करू देण्याऐवजी **प्रत्येक** विनंती Antigravity AI Credit Overages (सशुल्क Google क्रेडिट्स) द्वारे रूट करते. हे वैशिष्ट्य म्हणून दस्तऐवजीकृत आहे, पण **आम्हाला दिसणारा हा ToS उल्लंघनाचा सर्वांत सामान्य अहवाल आहे** — `=always` सह काही तास चालवल्यानंतर अनेक Google Ultra खात्यांवर `403 / "service disabled for ToS violation" / insufficient_quota` सह बंदी घालण्यात आली आहे.

अपस्ट्रीम अंमलबजावणी **Google च्या बाजूला** होते; OmniRoute ती रोखू शकत नाही. एन्व्हायर्नमेंट व्हेरिएबलचे नाव आणि विद्यमान दस्तऐवज यामुळे हे सक्रिय करणे सुरक्षित आहे असे वाटते; प्रत्यक्षात तसे नाही.

**केवळ फ्री-टियर वापराच्या तुलनेत यामुळे गैरवापर शोध अधिक आक्रमकपणे का सक्रिय होतो:**

- एका Google खात्यावरून होणारा सातत्यपूर्ण स्वयंचलित खर्च, फ्री-टियरची मर्यादा गाठून थांबणाऱ्या वापरापेक्षा वेगळ्या प्रकारे फ्लॅग केला जातो.
- क्रेडिट ओव्हरेजवर दराची कमाल मर्यादा नसते, त्यामुळे चुकीच्या पद्धतीने कॉन्फिगर केलेला क्लायंट काही मिनिटांत शेकडो USD खर्च करू शकतो आणि हे API-की पुनर्विक्री किंवा बॉट ट्रॅफिकसारखे दिसू शकते.
- एकाच बाह्य IP वरून अनेक OmniRoute वापरकर्त्यांनी समांतरपणे ओव्हरेज क्रेडिट्स वापरल्यास हा संकेत अधिक तीव्र होतो.

**शिफारस केलेली भूमिका:**

1. ऑपरेटरने सशुल्क क्रेडिट आणि खाते-अंमलबजावणीचा धोका स्पष्टपणे स्वीकारलेला नसल्यास डीफॉल्ट `ANTIGRAVITY_CREDITS=off` कायम ठेवा. `retry` प्रथम सामान्य विनंती पाठवते आणि पात्र कोटा 429 मिळाल्यानंतर जास्तीत जास्त एकदाच क्रेडिट्स इंजेक्ट करते; `always` पहिल्याच विनंतीमध्ये क्रेडिट्स इंजेक्ट करते.
2. एकाच Antigravity खात्याची क्षमता पूर्णपणे वापरण्याऐवजी **Auto-Combo द्वारे प्रोव्हायडर्समध्ये लोड वितरित करा** (`model: "auto"` किंवा `kr/glm/etc`-combo).
3. Antigravity प्रोव्हायडरच्या संपादन पृष्ठावर **प्रत्येक कनेक्शनसाठी RPM मर्यादा सेट करा** (Dashboard → Providers → Antigravity → connection → rate limit). सातत्यपूर्ण वापरासाठी 30–60 RPM ही समर्थनीय कमाल मर्यादा आहे.
4. **स्थिर, ऑपरेटर-नियंत्रित अपस्ट्रीम नेटवर्किंग वापरा** आणि असंबंधित वापरकर्ते किंवा वर्कलोड्समध्ये एकच खाते सामायिक करणे टाळा.
5. **बंदी घातली गेल्यास**: Google ने पाठवलेल्या अचूक `quota_exceeded` / `service disabled` प्रतिसाद बॉडीसह `support.google.com` → "Restore Workspace/Account access" द्वारे अपील करा. खाते पुनर्संचयित होईल याची हमी नाही.

एन्व्हायर्नमेंट संदर्भामध्ये प्रत्येक क्रेडिट्स मोडचे खाते आणि खर्चाशी संबंधित परिणाम दस्तऐवजीकृत आहेत.

संबंधित ठिकाणे:

- `open-sse/executors/antigravity.ts` — `process.env.ANTIGRAVITY_CREDITS` वाचते
- `src/lib/oauth/providers/antigravity.ts` — क्रेडेन्शियल प्लंबिंग
- मूळ घटना अहवाल: चर्चा [#1183](https://github.com/diegosouzapw/OmniRoute/discussions/1183)

## CLI फिंगरप्रिंट नोंदणी — `open-sse/config/cliFingerprints.ts`

अधिकृत CLI च्या mitmproxy ट्रेसमधून नोंदवलेला **अचूक** हेडर क्रम आणि JSON बॉडी फील्ड क्रम निश्चित करणारे, प्रत्येक प्रदात्यासाठी स्वतंत्र टेबल. सध्या नोंदणीकृत: `codex`, `claude`, तसेच `antigravity` आणि `github` साठी `providerHeaderProfiles.ts` मधील रनटाइमवरून मिळवलेली प्रोफाइल.

```ts
interface CliFingerprint {
  headerOrder: string[]; // केस-संवेदी
  bodyFieldOrder: string[]; // शीर्ष-स्तरीय JSON की
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

env द्वारे प्रत्येक प्रदात्यासाठी स्वतंत्रपणे टॉगल करा (खाली पाहा). अक्षम केल्यावर, Node/JSON ने दिलेल्या कोणत्याही क्रमाने हेडर/बॉडी की दिसतात — त्यामुळे फिंगरप्रिंट करणे सोपे होते.

## MITM प्रॉक्सी (Antigravity, Linux/macOS/Windows)

ज्या CLI च्या बायनरी `OPENAI_BASE_URL` द्वारे पुनर्निर्देशित करता येत नाहीत, त्यांच्यासाठी OmniRoute स्थानिक TLS-टर्मिनेटिंग प्रॉक्सी चालवते. एंडपॉइंट `src/app/api/cli-tools/antigravity-mitm/` अंतर्गत आहेत.

| पद्धत  | एंडपॉइंट                                | उद्देश                                               |
| ------ | --------------------------------------- | ---------------------------------------------------- |
| GET    | `/api/cli-tools/antigravity-mitm`       | स्थिती — चालू आहे का, pid, dnsConfigured, certExists |
| POST   | `/api/cli-tools/antigravity-mitm`       | MITM सुरू करा (`apiKey` + `sudoPassword` आवश्यक)     |
| DELETE | `/api/cli-tools/antigravity-mitm`       | MITM थांबवा                                          |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | मॉडेल उपनावे सूचीबद्ध करा                            |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | साधनासाठी मॉडेल उपनावे जतन करा                       |

इंटरसेप्ट केलेले लक्ष्य होस्ट: **`daily-cloudcode-pa.googleapis.com`** (Antigravity चे अपस्ट्रीम).

### प्रारंभ क्रम (`src/mitm/manager.ts::startMitm`)

1. `selfsigned` द्वारे स्व-स्वाक्षरित प्रमाणपत्र तयार करा (RSA-2048, SHA-256, 1y) — `cert/generate.ts`
2. प्रणालीच्या ट्रस्ट स्टोअरमध्ये प्रमाणपत्र स्थापित करा — `cert/install.ts`
3. होस्ट्स नोंद `127.0.0.1 daily-cloudcode-pa.googleapis.com` जोडा — `dns/dnsConfig.ts`
4. `ROUTER_API_KEY` + `MITM_LOCAL_PORT` (डीफॉल्ट `443`) सह `src/mitm/server.cjs` स्पॉन करा
5. PID `<DATA_DIR>/mitm/.mitm.pid` मध्ये कायमस्वरूपी जतन करा

### Linux डायनॅमिक ट्रस्ट-स्टोअर शोध — `cert/install.ts`

`getLinuxCertConfig()` प्राधान्यक्रमानुसार सूची तपासते आणि अस्तित्वात असलेली पहिली डिरेक्टरी निवडते:

| डिस्ट्रो कुटुंब          | डिरेक्टरी                                   | अपडेट कमांड              |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

प्रमाणपत्र फाइलचे नाव: `omniroute-mitm.crt`. `getCertFingerprint()` द्वारे फिंगरप्रिंट जुळवणी (DER चे SHA-1).

याव्यतिरिक्त, `certutil` उपलब्ध असताना `updateNssDatabases()` प्रत्येक वापरकर्त्याच्या NSS DB मध्ये स्थापित करते: `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, सर्व Firefox प्रोफाइल (snap सह), **`OmniRoute MITM Root CA`** या टोपणनावाखाली.

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** उन्नत-अधिकार असलेले PowerShell → `certutil -addstore Root`

### प्रमाणीकरण

सर्व MITM एंडपॉइंटना व्यवस्थापन प्रमाणीकरण (`requireCliToolsAuth`) आवश्यक आहे. sudo पासवर्ड मॉड्यूल स्कोपमध्ये कॅश केला जातो (`globalThis` मध्ये कधीही नाही) आणि `stopMitm()` वर साफ केला जातो.

## इनबाउंड हेडर स्वच्छता

OmniRoute फॉरवर्ड करण्यापूर्वी इनबाउंड क्लायंट हेडर्स साफ करते, त्यामुळे Cursor कडून आलेल्या विनंतीमधील `User-Agent: Cursor/X.Y.Z` Claude अपस्ट्रीमकडे लीक होत नाही. Zod स्कीमा आणि युनिट चाचण्यांशी समक्रमित ठेवलेल्या डिनायलिस्टसाठी `src/shared/constants/upstreamHeaders.ts` पहा.

## प्रदाता बदल करतो तेव्हा फिंगरप्रिंट्स अपडेट करणे

1. `mitmproxy` वापरून अधिकृत CLI ट्रॅफिक कॅप्चर करा (TLS इंटरसेप्शन + डंप)
2. JA3/JA4 आणि हेडर्सचा अक्षरशः क्रम एक्स्ट्रॅक्ट करा
3. संबंधित `CLI_FINGERPRINTS[...]` एंट्री अपडेट करा
4. `.env.example` मधील जुळणारे `*_USER_AGENT` डीफॉल्ट अपडेट करा
5. TLS हँडशेक स्वतः बदलला असल्यास, संबंधित प्रदाता रॅपर किंवा wreq-js `browser:` पर्याय अपडेट करा
6. प्रदाता-विशिष्ट TLS चाचण्या आणि प्रत्यक्ष प्रदात्याविरुद्ध मॅन्युअल कॅनरी चालवा
7. पॅच रिलीजमध्ये पाठवा; `CHANGELOG.md` मध्ये दस्तऐवजीकरण करा
