OmniRoute npm + Docker आर्टिफॅक्ट्स प्रकाशित करते. ही गेट्स उगमाचा पुरावा,
इन्व्हेंटरी (SBOM) आणि CVE स्कॅनिंग प्रदान करतात; ही सर्व OSS असून रिलीज वर्कफ्लोजमध्ये जोडलेली आहेत.
**सल्ला-प्रथम** भूमिका — सध्या ती केवळ अहवाल देतात आणि पहिल्या
यशस्वी रिलीजनंतर ब्लॉकिंग म्हणून पदोन्नत केली जातात.

| गेट                      | साधन                                           | कुठे                             | ब्लॉक करते?               | आउटपुट                                             |
| ------------------------ | ---------------------------------------------- | -------------------------------- | ------------------------- | -------------------------------------------------- |
| SLSA उगमाचा पुरावा (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`                | प्रकाशन अयशस्वी झाल्यासच  | npmjs बॅज / `npm audit signatures`                 |
| SBOM npm                 | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`                | निर्मिती अयशस्वी झाल्यासच | रिलीज अॅसेट + आर्टिफॅक्ट                           |
| SBOM इमेज                | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (विलीनीकरण) | सल्लात्मक                 | CycloneDX आर्टिफॅक्ट                               |
| Trivy CVE (SARIF)        | `aquasecurity/trivy-action`                    | `docker-publish.yml` (विलीनीकरण) | सल्लात्मक                 | SARIF (HIGH+CRITICAL) → Security टॅब               |
| Trivy CRITICAL गेट       | `aquasecurity/trivy-action`                    | `docker-publish.yml` (विलीनीकरण) | **ब्लॉकिंग**              | दुरुस्त करता येणाऱ्या CRITICAL वर `exit-code: '1'` |
| osv vulnCount            | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`)    | **ब्लॉकिंग**              | `metrics.vulnCount` रॅचेट करते (दिशा: खाली)        |
| OpenSSF Scorecard        | `ossf/scorecard-action`                        | `scorecard.yml` (cron)           | सल्लात्मक                 | SARIF → Security + बॅज                             |

इमेज CVE रॅचेट `docker-publish.yml` मध्ये **दोन पायऱ्या** वापरते: SARIF पायरी
(`HIGH,CRITICAL`, `exit-code: 0`) ब्लॉक न करता HIGH+CRITICAL समस्या Security टॅबमध्ये
दृश्यमान ठेवते; _CRITICAL गेट_ पायरी (`severity: CRITICAL`, `ignore-unfixed: true`,
`exit-code: 1`) **दुरुस्ती उपलब्ध असलेला** CRITICAL CVE आढळल्यास रिलीज अयशस्वी करते. `ignore-unfixed`
मुळे अपस्ट्रीम पॅच नसलेल्या बेस-इमेज CVE साठी रिलीज ब्लॉक होत नाही.

## ⚠️ CVE तफावत (ब्लॉकिंग osv/Trivy गेट्स)

osv आणि Trivy अवलंबित्वांची तुलना **सतत वाढणाऱ्या** CVE डेटाबेसेसशी करतात. कोणत्याही
अवलंबित्वात **बदल न करणारा** PR अचानक लाल होऊ शकतो, कारण विद्यमान अवलंबित्वामध्ये
नवीन CVE जाहीर झालेला असू शकतो (osv: मोजलेला `vulnCount` > बेसलाइन; Trivy: इमेजमध्ये
नवीन दुरुस्त करता येणारा CRITICAL). **हे ब्लॉकिंग CVE गेटचे अपेक्षित कार्यान्वयन वर्तन आहे,
उत्पादनातील रिग्रेशन नाही.**

नवीन जाहीर झालेल्या CVE मुळे osv किंवा Trivy लाल झाल्यास, उपाय असा आहे:

1. **प्रभावित अवलंबित्वाची आवृत्ती वाढवा** (प्राधान्यक्रमाने) — `package.json`
   मधील `overrides` (ट्रान्झिटिव्ह अवलंबित्वे) वापरून पॅच केलेल्या आवृत्तीवर अपग्रेड करा किंवा पॅच केलेल्या बेसवर इमेज पुन्हा बिल्ड करा.
2. **अपस्ट्रीम दुरुस्ती उपलब्ध नसल्यास:**
   - **osv:** `config/quality/quality-baseline.json` मधील `metrics.vulnCount` पुन्हा बेसलाइन करा
     (`npm run quality:ratchet -- --update` स्वतंत्र गेट्सना लागू होत नाही — समर्थनार्थ नोंद + ट्रॅकिंग इश्यूसह
     मूल्य हाताने संपादित करा, `direction:down`).
   - **Trivy:** समर्थनार्थ टिप्पणी + ट्रॅकिंग इश्यूसह `.trivyignore` मध्ये नोंद जोडा
     (प्रत्येक ओळीत एक CVE-ID). `ignore-unfixed: true` पॅच नसलेले CVEs आधीच
     स्वयंचलितपणे हाताळते.

साधन उपलब्ध नसल्यास किंवा मोजमाप अयशस्वी झाल्यास, दोन्ही गेट्स **सुरळीतपणे SKIP**
(exit 0) करतात (osv-scanner PATH मध्ये नसणे, osv.dev/नेटवर्क उपलब्ध नसणे, अवैध JSON) —
**मोजमापातील** अपयश कधीही ब्लॉक करत नाही; फक्त **मोजलेले** रिग्रेशन ब्लॉक करते.
