`agentrouter` अपस्ट्रीम गेटवे `messages[].content` वर कीवर्ड-आधारित सामग्री फिल्टर चालवतो. हा फिल्टर अंशतः निर्धारक आहे (काही विशिष्ट वाक्यांशांना नेहमी ब्लॉक करतो) आणि अंशतः संभाव्यताधारित आहे (बर्स्ट-संवेदनशील — झपाट्याने विनंत्या आल्यानंतर अधिक आक्रमक होतो आणि कूलडाउननंतर पूर्ववत होतो).

WAF एखादी विनंती ब्लॉक करतो तेव्हा तो पुढील प्रतिसाद देतो:

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## फिल्टरची व्याप्ती

WAF फक्त `messages[].content` तपासतो. तो पुढील गोष्टी तपासत **नाही**:

- `system` प्रॉम्प्ट
- संरचित सामग्री ब्लॉक्स (`tool_result`, `tool_use`, `thinking`, `image`)
- टूलची `description` आणि `input_schema` फील्ड्स
- विनंतीचे मेटाडेटा, हेडर्स किंवा मॉडेल आयडी

## नेहमी ब्लॉक होणारे नमुने (अक्षरांचा आकार विचारात न घेता)

| नमुना                           | नोंदी                                                           |
| ------------------------------- | --------------------------------------------------------------- |
| `Lorem ipsum` चा कोणताही प्रकार | संपूर्ण लॅटिन lorem शब्दसंग्रह ब्लॉक केला जातो                  |
| `language model` (एकटा)         | "the language model" आणि "large language model" स्वीकारले जातात |
| `virtual assistant`             | "AI assistant" स्वीकारले जाते                                   |
| `I'm here to help`              | फक्त "here to help" असले तरी तेही ब्लॉक होते                    |
| `Claude, made by Anthropic`     | फक्त पूर्ण वाक्यांश                                             |

## जवळजवळ नेहमी ब्लॉक होणारे नमुने

| नमुना                                                          | नोंदी                                                                     |
| -------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `placeholder`                                                  | जेव्हा तो स्वतंत्रपणे वापरलेला असतो (पॅरामीटरचे नाव इत्यादी म्हणून नव्हे) |
| `dummy data`                                                   | फिक्स्चर्ससाठी सामान्य सीड वाक्यांश                                       |
| `foo bar baz`                                                  | प्रमाणित प्लेसहोल्डर वाक्यांश                                             |
| वारंवार वापरलेली लहान टोकन्स (`AAA BBB CCC`, `test test test`) | कीवर्ड स्टफिंग शोधण्यासाठीचा डिटेक्टर                                     |

## लोडअंतर्गत वर्तन

कमी कालावधीत सलग ~5 विनंत्या आल्यानंतर, WAF सामान्यतः स्वीकारली जाणारी सामग्रीही ब्लॉक करू लागतो. ~5–10 सेकंद निष्क्रिय राहिल्यानंतर बकेट शिथिल होते. हा तोच IP-आणि-की-बद्ध रेट लिमिटर आहे, ज्यामुळे Claude Code किंवा Codex CLI कडून अनेक टूल-वापर / संदेश-पाठवण्याचे कॉल झपाट्याने झाल्यावर मधूनमधून `400 content-blocked` त्रुटी येतात.

## OmniRoute मध्ये आधीच लागू केलेले उपाय

1. **`open-sse/services/wafRateLimit.ts`** — कोणत्याही `agentrouter:*` URL कडे जाणाऱ्या आउटबाउंड विनंत्यांमध्ये किमान 500 ms चे अंतर सक्तीने लागू करणारा बर्स्ट गार्ड. हे अंतर मानवी विलंब-जाणिवेच्या मर्यादेपेक्षा खूप कमी आहे आणि सामान्य ट्रॅफिकमध्ये WAF सक्रिय होण्यापासून प्रतिबंध करते.

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — अपस्ट्रीमकडून `400 content-blocked` परत आल्यास, एक्झिक्युटर त्याच URL साठी एक्स्पोनेन्शियल बॅकऑफसह पुन्हा प्रयत्न करतो (1.5 s, 3.0 s, कमाल 2 प्रयत्न). बॅकऑफनंतर WAF सहसा शिथिल होतो आणि पुनर्प्रयत्न यशस्वी होतो.

3. **`tests/unit/compression/harness.test.ts`** — चाचणी फिक्स्चर `longInput` हे `"lorem ipsum dolor sit amet ".repeat(40)` वरून `"example content for testing purposes ".repeat(40)` असे बदलण्यात आले, जेणेकरून Claude Code ने `Read` टूलद्वारे ही फाइल वाचल्यावर फाइलमधील सामग्री `tool_result` ब्लॉकमधून परत प्रवाहित होऊन WAF सक्रिय होणार नाही.

## प्रॉम्प्ट्स आणि टूल आउटपुटसाठी मार्गदर्शन

Claude Code किंवा Codex CLI सत्रामध्ये वारंवार `400 content-blocked` येत असल्यास, सर्वात अलीकडील वापरकर्ता संदेश आणि सर्वात अलीकडील टूल निकालामध्ये वरीलपैकी कोणताही नमुना आहे का ते तपासा आणि मजकूराची पुनर्मांडणी करा. सामान्य पर्याय:

- `Lorem ipsum …` ऐवजी `example text …` किंवा चाचणी अथवा फिक्स्चरद्वारे प्रतिरूपित केली जाणारी वास्तविक सामग्री वापरा.
- स्वतंत्रपणे वापरलेला `placeholder` हा शब्द `example value`, `sample value` किंवा वास्तविक मूल्याने बदला.
- `language model` ऐवजी `large language model` किंवा `the model` वापरा.
- `dummy data` ऐवजी `sample data` किंवा वास्तववादी सीड मूल्ये वापरा.
- `I'm here to help` / `here to help` ऐवजी अधिक विशिष्ट सुरुवातीचे वाक्य वापरा (उदा. "I'll review the file you mentioned").

## चुकीचे पॉझिटिव्ह निकाल अपस्ट्रीमकडे नोंदवणे

सध्याचा फिल्टर अतिशय आक्रमक आहे — ऑपरेटरचा स्पष्टपणे प्रॉम्प्ट इंजेक्ट करण्याचा हेतू नसतानाही तो `tool_result` ब्लॉक्समधील "Lorem ipsum" ब्लॉक करतो. ज्यांना ही समस्या मूळ स्रोतावरच दुरुस्त करून घ्यायची आहे अशा ऑपरेटर्सनी चुकीचे पॉझिटिव्ह निकाल नोंदवण्यासाठी `agentrouter.org` शी संपर्क साधावा. वरील ब्लॉकलिस्ट ही 2026-08-03 रोजी अपस्ट्रीमची तपासणी करून मिळालेला अनुभवाधारित निकाल आहे.
