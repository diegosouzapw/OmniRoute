Caveman compression अंगभूत इंग्रजी नियमांव्यतिरिक्त भाषाविशिष्ट नियम-पॅक लोड करू शकते.
यामुळे Portuguese, Spanish, German, French, Italian, Japanese आणि भविष्यातील भाषा-पॅक स्वतंत्रपणे विकसित होऊ शकतात, तर मुख्य इंजिन स्थिर राहते.

## स्थान

भाषा-पॅक येथे असतात:

```txt
open-sse/services/compression/rules/<language>/
```

सध्या समाविष्ट केलेले पॅक (`rules/` निर्देशिकेतील सामग्रीशी पडताळलेले):

| भाषा                | निर्देशिका     | उपलब्ध नियम-श्रेणी                                  |
| ------------------- | -------------- | --------------------------------------------------- |
| इंग्रजी             | `rules/en/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| स्पॅनिश             | `rules/es/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| पोर्तुगीज (ब्राझील) | `rules/pt-BR/` | `context`, `dedup`, `filler`, `structural`, `ultra` |
| इंडोनेशियन          | `rules/id/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| इटालियन             | `rules/it/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| जर्मन               | `rules/de/`    | `context`, `filler`, `structural`                   |
| फ्रेंच              | `rules/fr/`    | `context`, `filler`, `structural`                   |
| जपानी               | `rules/ja/`    | `context`, `filler`, `structural`                   |

> **समानता टीप:** `en`, `es`, `pt-BR`, `id` आणि `it` पॅकमध्ये सर्व 5 श्रेणी आहेत; `de`, `fr`, `ja` मध्ये 3 श्रेणी समाविष्ट आहेत. अनुपस्थित `dedup` आणि `ultra` श्रेणींसाठी कोणतीही सूचना न देता अंगभूत इंग्रजी नियम वापरले जातात. लहान पॅकसाठी `dedup.json` आणि `ultra.json` जोडण्याकरिता योगदानांचे स्वागत आहे.
>
> `pt-BR` पॅक Lenine Júnior यांच्या **[Troglodita](https://github.com/leninejunior/troglodita)** वर आधारित आहे — ही ब्राझिलियन पोर्तुगीज व्याकरणासाठी सुरुवातीपासून तयार केलेली compression प्रणाली आहे (अनावश्यक पुनरुक्ती कमी करणे, PT-BR मधील निरर्थक भराव काढून टाकणे, dev BR समुदायासाठी तांत्रिक संक्षिप्त रूपे).
>
> प्रमाणित श्रेणी-सूची आणि प्रत्येक श्रेणीची schema [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) मध्ये उपलब्ध आहे (JSON Schema draft 2020-12).

## भाषा शोध

`languageDetector.ts` प्रॉम्प्टच्या मजकुरातून भाषा ओळखण्यासाठी हलक्या heuristic पद्धती वापरते. कॉन्फिगर केलेल्या डीफॉल्ट भाषेचा तरीही आदर केला जातो आणि अचूक नियंत्रण आवश्यक असल्यास config द्वारे शोध अक्षम करता येतो.

शोधाचे आउटपुट केवळ नियम-पॅक निवडण्यासाठी वापरले जाते. ते provider routing, locale निवड किंवा UI भाषा बदलत नाही.

## Config संरचना

Compression सेटिंग्जमध्ये पुढील गोष्टी समाविष्ट करता येतात:

```json
{
  "languageConfig": {
    "enabled": true,
    "defaultLanguage": "en",
    "autoDetect": true,
    "enabledPacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  },
  "cavemanConfig": {
    "language": "en",
    "autoDetectLanguage": true,
    "enabledLanguagePacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  }
}
```

`languageConfig` dashboard/preview ची डीफॉल्ट मूल्ये नियंत्रित करते. `cavemanConfig` हा Caveman संदेशाचा मजकूर compress करताना वापरला जाणारा runtime engine config आहे.

## भाषा पॅक जोडणे

1. `open-sse/services/compression/rules/<language>/<pack>.json` तयार करा.
2. `docs/compression/COMPRESSION_RULES_FORMAT.md` मधील Caveman नियम स्वरूप वापरा.
3. बदल मर्यादित ठेवा आणि कोड, आयडेंटिफायर, URLs किंवा JSON बदलणे टाळा.
4. भाषा निवड आणि बदलण्याच्या वर्तनासाठी चाचण्या जोडा किंवा अद्ययावत करा.
5. भाषा UI निवडकांमध्ये दिसत असल्यास नवीन dashboard/i18n लेबले उपलब्ध करा.

## API

उपलब्ध पॅक्सची पुढीलप्रमाणे चौकशी करता येते:

```bash
curl http://localhost:20128/api/compression/language-packs
```

पूर्वावलोकन एंडपॉइंट भाषा कॉन्फिगरेशन ओव्हरराइड्स स्वीकारतो:

```bash
curl -X POST http://localhost:20128/api/compression/preview \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "standard",
    "text": "Por favor, eu gostaria que voce basicamente resumisse isso.",
    "config": {
      "languageConfig": {
        "defaultLanguage": "pt-BR",
        "autoDetect": true
      }
    }
  }'
```

## SHARED_BOUNDARIES (v3.8.0)

v3.8.0 मध्ये सर्व 6 भाषा पॅक्सना `SHARED_BOUNDARIES` कलम मिळाले, जे प्रत्येक
Caveman तीव्रतेवर (LITE, FULL, ULTRA) लागू केले जाते. आसपासचे अनावश्यक शब्द काढले जात असले तरी,
हे नमुने जसेच्या तसे जतन करण्याची सूचना ते इंजिनला देते:

| नमुन्याचा प्रकार                | उदाहरण                                 |
| ------------------------------- | -------------------------------------- |
| फेन्स्ड कोड ब्लॉक्स             | ` ```python\n...\n``` `                |
| इनलाइन कोड                      | `` `my_var` ``                         |
| URLs                            | `https://example.com/path`             |
| फाइल पाथ्स (निरपेक्ष + सापेक्ष) | `/etc/hosts`, `./src/index.ts`         |
| त्रुटी हेडर्स                   | `Error:`, `TypeError:`, `SyntaxError:` |
| स्टॅक ट्रेस ओळी                 | `  at functionName (file.ts:12:3)`     |

हे नमुने `DEFAULT_CAVEMAN_CONFIG.preservePatterns` मध्ये समाविष्ट केलेले आहेत (पूर्वी `[]`). हा
कॉन्स्टंट `open-sse/services/compression/types.ts` मध्ये आहे.

### हे महत्त्वाचे का आहे

SHARED_BOUNDARIES शिवाय, आक्रमक Caveman मोड्स पुनरावृत्ती होणाऱ्या गद्यासारखा दिसणारा,
पण प्रत्यक्षात कोड स्निपेट, फाइल पाथ किंवा त्रुटी स्टॅक असलेला मजकूर काढून टाकू शकतात. SHARED_BOUNDARIES हे
अनावश्यक शब्दांचे नियम चालण्यापूर्वी लागू होणारे, भाषेपासून स्वतंत्र सुरक्षा जाळे म्हणून कार्य करते.

### preservePatterns सानुकूलित करणे

कॉम्प्रेशन सेटिंग्जद्वारे रनटाइमवेळी अतिरिक्त नमुने जोडता येतात:

````json
{
  "cavemanConfig": {
    "preservePatterns": [
      "```[\\s\\S]*?```",
      "`[^`]+`",
      "https?://\\S+",
      "(?:/|\\./)[^\\s]+",
      "\\b(?:Error|TypeError|SyntaxError|RangeError):",
      "\\s+at\\s+\\S+\\s+\\(\\S+:\\d+:\\d+\\)"
    ]
  }
}
````

सानुकूल नमुने 6 डीफॉल्ट नमुन्यांचा विस्तार करतात (त्यांची जागा घेत नाहीत).

## कार्यान्वयनविषयक नोंदी

- भाषा पॅक उपलब्ध नसताना अंगभूत इंग्रजी नियम फॉलबॅक म्हणून कायम राहतात.
- अवैध अंगभूत JSON पॅक्स प्रमाणीकरणात अयशस्वी होतात, ज्यामुळे रिलीज अॅसेट्सची गुणवत्ता नकळत कमी होत नाही.
- नियम पॅक्स केवळ डेटा असतात आणि त्यांनी कोड इंपोर्ट करू नये किंवा मनमानी लॉजिक चालवू नये.
- कॉम्प्रेशन अॅनालिटिक्स स्तर पूर्ण प्रॉम्प्ट मजकूर नव्हे, तर निवडलेला मोड आणि इंजिन नोंदवतो.
