भाषा पॅक्स आणि RTK कमांड फिल्टर्सचे इंजिन कोड न बदलता पुनरावलोकन करता येईल.

> खालील उदाहरणे केवळ स्पष्टीकरणासाठी आहेत — शंका असल्यास, तुमचा पॅक `_schema.json` च्या आधारे प्रमाणित करा.

## Caveman नियम पॅक्स

Caveman नियम पॅक्स येथे असतात:

```txt
open-sse/services/compression/rules/<language>/<pack>.json
```

प्रत्येक पॅकमध्ये संरक्षित भाग वेगळे केल्यानंतर सामान्य गद्यावर लागू होणाऱ्या प्रतिस्थापनांचा समावेश असतो.

```json
{
  "language": "en",
  "category": "filler",
  "rules": [
    {
      "name": "question_to_directive",
      "pattern": "\\b(?:Can you explain why|Could you show me how)\\b\\s*",
      "replacement": "Explain why ",
      "replacementMap": {
        "can you explain why": "Explain why ",
        "could you show me how": "Show how "
      },
      "flags": "gi",
      "context": "all",
      "category": "context",
      "minIntensity": "lite",
      "description": "Convert verbose questions into direct requests."
    }
  ]
}
```

### Caveman फील्ड्स

| फील्ड                    | आवश्यक | वर्णन                                                                                   |
| ------------------------ | ------ | --------------------------------------------------------------------------------------- |
| `language`               | होय    | `en`, `pt-BR`, `es` यांसारखी BCP-47-सदृश भाषा की                                        |
| `category`               | होय    | पॅक श्रेणीचे फाइलनाव/श्रेणी, उदाहरणार्थ `filler` किंवा `dedup`                          |
| `rules`                  | होय    | regex प्रतिस्थापन नियमांचा अॅरे                                                         |
| `rules[].name`           | होय    | स्थिर नियम नाव                                                                          |
| `rules[].pattern`        | होय    | JavaScript regex स्रोत                                                                  |
| `rules[].flags`          | नाही   | JavaScript regex फ्लॅग्स; डीफॉल्ट `gi`                                                  |
| `rules[].replacement`    | नाही   | प्रतिस्थापन स्ट्रिंग किंवा `replacementMap` मध्ये जुळणारे मूल्य नसल्यास वापरायचे फॉलबॅक |
| `rules[].replacementMap` | नाही   | सामान्यीकृत जुळलेल्या मजकुरानुसार की केलेली जुळणी-विशिष्ट प्रतिस्थापने                  |
| `rules[].context`        | नाही   | `all`, `user`, `assistant`, किंवा `system`; डीफॉल्ट `all`                               |
| `rules[].category`       | नाही   | `filler`, `context`, `structural`, `dedup`, `terse`, किंवा `ultra`                      |
| `rules[].minIntensity`   | नाही   | `lite`, `full`, किंवा `ultra`; डीफॉल्ट `lite`                                           |
| `rules[].description`    | नाही   | मानवी-वाचनीय नियमाचा सारांश                                                             |

केस-संवेदी जुळणी महत्त्वाची असताना `flags` वापरा, उदाहरणार्थ `the OpenAI API` मधील `the` न काढता
लहान अक्षरांनी सुरू होणाऱ्या गद्यापूर्वीचा आर्टिकल काढण्यासाठी. एका regex मध्ये अनेक पर्याय असतील आणि
त्यांना वेगवेगळे आउटपुट आवश्यक असतील तेव्हा `replacementMap` वापरा; यामुळे अधिक समृद्ध अंगभूत
TypeScript प्रतिस्थापन फंक्शन्सचे वर्तन जतन करत JSON नियम पॅक्स केवळ-डेटा स्वरूपात राहतात.

## RTK फिल्टर पॅक्स

RTK फिल्टर्स येथे असतात:

```txt
open-sse/services/compression/engines/rtk/filters/<filter>.json
```

प्रत्येक फिल्टर कमांड-आउटपुटच्या विशिष्ट प्रकाराला कसे ओळखायचे आणि संक्षिप्त करायचे हे स्पष्ट करतो.

```json
{
  "id": "test-vitest",
  "label": "Vitest output",
  "category": "test",
  "priority": 92,
  "match": {
    "outputTypes": ["test-vitest"],
    "commands": ["vitest", "npm test", "npm run test"],
    "patterns": ["\\bFAIL\\b", "\\bPASS\\b", "\\bTest Files\\b"]
  },
  "rules": {
    "stripAnsi": true,
    "replace": [{ "pattern": "\\s+\\[[0-9]+ms\\]", "replacement": "" }],
    "matchOutput": [
      {
        "pattern": "All tests passed",
        "message": "vitest: ok",
        "unless": "FAIL|Error:"
      }
    ],
    "includePatterns": ["FAIL", "Error:", "Test Files", "Tests"],
    "dropPatterns": ["^\\s*$", "Duration\\s+\\d+"],
    "collapsePatterns": ["^\\s+at "],
    "deduplicate": true,
    "truncateLineAt": 240,
    "maxLines": 160,
    "headLines": 24,
    "tailLines": 40,
    "onEmpty": "vitest: ok",
    "filterStderr": false
  },
  "preserve": {
    "errorPatterns": ["FAIL", "Error:", "AssertionError"],
    "summaryPatterns": ["Test Files", "Tests", "Snapshots"]
  },
  "tests": [
    {
      "name": "keeps failing tests",
      "command": "vitest",
      "input": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed",
      "expected": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed"
    }
  ]
}
```

### RTK फील्ड्स

| फील्ड                      | आवश्यक | वर्णन                                                                          |
| -------------------------- | ------ | ------------------------------------------------------------------------------ |
| `id`                       | होय    | स्थिर फिल्टर आयडी                                                              |
| `label`                    | होय    | डॅशबोर्डवर वाचता येणारे नाव                                                    |
| `category`                 | होय    | फिल्टर प्रकार: git, test, build, shell, docker, package, infra, cloud, generic |
| `priority`                 | नाही   | एकापेक्षा अधिक फिल्टर्स जुळल्यास उच्च प्राधान्याचा फिल्टर निवडला जातो          |
| `match.outputTypes`        | नाही   | हा फिल्टर निवडणारे डिटेक्टर आउटपुट आयडी                                        |
| `match.commands`           | नाही   | हा फिल्टर निवडणारी कमांड टोकन्स                                                |
| `match.patterns`           | नाही   | आउटपुट मजकुरावरून हा फिल्टर निवडणारे रेगेक्स पॅटर्न्स                          |
| `rules.stripAnsi`          | नाही   | रेगेक्स टप्प्यांपूर्वी ANSI एस्केप सिक्वेन्सेस काढून टाका                      |
| `rules.replace`            | नाही   | प्रत्येक ओळीवर क्रमाने लागू होणारी रेगेक्स प्रतिस्थापने                        |
| `rules.matchOutput`        | नाही   | पर्यायी `unless` गार्डसह शॉर्ट-सर्किट आउटपुट नियम                              |
| `rules.includePatterns`    | नाही   | जतन करण्यास प्राधान्य द्यायच्या ओळी                                            |
| `rules.dropPatterns`       | नाही   | अनावश्यक म्हणून काढून टाकायच्या ओळी                                            |
| `rules.collapsePatterns`   | नाही   | संक्षिप्त करता येणाऱ्या वारंवार जुळणाऱ्या ओळी                                  |
| `rules.deduplicate`        | नाही   | एकसारख्या नॉर्मलाइझ केलेल्या ओळी संक्षिप्त करा                                 |
| `rules.truncateLineAt`     | नाही   | प्रत्येक ओळीसाठी युनिकोड-सुरक्षित वर्णमर्यादा                                  |
| `rules.maxLines`           | नाही   | शेवटच्या ओळी जतन करण्यापूर्वी ठेवायच्या ओळींची कमाल संख्या                     |
| `rules.headLines`          | नाही   | ट्रंकेशनदरम्यान जतन केलेल्या सुरुवातीच्या ओळी                                  |
| `rules.tailLines`          | नाही   | अलीकडील संदर्भासाठी जतन केलेल्या शेवटच्या ओळी                                  |
| `rules.onEmpty`            | नाही   | फिल्टरिंगमुळे सर्व मजकूर काढला गेल्यास वापरायचा पर्यायी संदेश                  |
| `rules.filterStderr`       | नाही   | पुढील फिल्टरिंग टप्प्यांपूर्वी सामान्य stderr उपसर्ग नॉर्मलाइझ करा             |
| `preserve.errorPatterns`   | नाही   | ट्रंकेशननंतरही जतन केल्या जाणाऱ्या त्रुटीच्या ओळी                              |
| `preserve.summaryPatterns` | नाही   | ट्रंकेशननंतरही जतन केल्या जाणाऱ्या सारांशाच्या ओळी                             |
| `tests[]`                  | नाही   | RTK पडताळणी गेटद्वारे वापरले जाणारे इनलाइन सत्यापन नमुने                       |

RTK घोषणात्मक टप्पे या क्रमाने लागू करते: `stripAnsi`, `filterStderr`, `replace`,
`matchOutput`, `dropPatterns`/`includePatterns`, `truncateLineAt`, `headLines`/`tailLines`,
`maxLines`, आणि `onEmpty`.

सानुकूल फिल्टर्स येथून लोड करता येतात:

1. जुळणारा `.rtk/trust.json` हॅश उपलब्ध झाल्यानंतरच किंवा
   `trustProjectFilters` सक्षम असल्यास प्रोजेक्टमधील `.rtk/filters.json` फाइल्स.
2. ग्लोबल `DATA_DIR/rtk/filters.json`.
3. अंगभूत फिल्टर्स.

प्रोजेक्ट/ग्लोबल सानुकूल फाइल्समध्ये एक फिल्टर ऑब्जेक्ट किंवा फिल्टर ऑब्जेक्ट्सचा अॅरे असू शकतो. अवैध
सानुकूल फिल्टर्स निदान संदेशांसह वगळले जातात; अवैध अंगभूत फिल्टर्समुळे सत्यापन अयशस्वी होते.

प्रोजेक्ट ट्रस्ट फाइल:

```json
{
  "filtersSha256": "0123456789abcdef..."
}
```

एन्व्हायर्नमेंट ओव्हरराइड `OMNIROUTE_RTK_TRUST_PROJECT_FILTERS=1` हॅशशिवाय प्रोजेक्ट फिल्टर्सवर विश्वास ठेवते
आणि त्याचा वापर नियंत्रित स्थानिक विकासापुरताच मर्यादित ठेवला पाहिजे.

## सुरक्षिततेचे नियम

- नियम आयडेम्पोटंट ठेवा: समान फिल्टर दोनदा चालवल्याने आउटपुट खराब होऊ नये.
- शक्य असेल तिथे त्रुटीचा अचूक मजकूर, फाइल पाथ, ओळ क्रमांक आणि कमांडचे सारांश जसेच्या तसे ठेवा.
- कोड ब्लॉक्स, JSON पेलोड्स, URLs किंवा गोपनीय माहितीमध्ये बदल करणारे नियम टाळा.
- डिटेक्टर/फिल्टर चाचण्यांमध्ये नवीन कमांड फॅमिलींसाठी युनिट कव्हरेज जोडा.
- प्रत्येक अंगभूत फिल्टरमध्ये आणि सामायिक कस्टम फिल्टर्समध्ये `tests[]` नमुने जोडा.

## प्रमाणीकरण

वापरण्यापूर्वी नियम पॅक्सचे प्रमाणीकरण केले जाते. अंगभूत Caveman पॅक्स आणि अंगभूत RTK फिल्टर्सच्या प्रमाणीकरणादरम्यान त्रुटी आल्यास प्रक्रिया त्वरित अयशस्वी होते, ज्यामुळे सदोष रिलीज अॅसेट्स वितरणापूर्वीच आढळतात. पार्सिंग किंवा विश्वासार्हतेचे प्रमाणीकरण अयशस्वी झाल्यास कस्टम RTK फिल्टर्स निदान माहितीसह वगळले जातात.

केंद्रित प्रमाणीकरण:

```bash
node --import tsx/esm --test tests/unit/compression/rule-loader.test.ts tests/unit/compression/language-packs.test.ts
node --import tsx/esm --test tests/unit/compression/rtk-verify.test.ts tests/unit/compression/rtk-dsl-pipeline.test.ts
```
