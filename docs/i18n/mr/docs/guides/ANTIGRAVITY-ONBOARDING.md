## 1. Antigravity विरुद्ध Antigravity CLI (agy)

दोन्ही प्रदाते **समान Google बॅकएंड** वापरतात — एकसारखे OAuth क्लायंट, टोकन रीफ्रेश, एंडपॉइंट्स आणि Google खाती. तुम्हाला कोणती मॉडेल्स दिसतात, एवढाच फरक आहे.

> Google ची अधिकृत तुलना पाहण्यासाठी [Antigravity CLI घोषणा](https://antigravity.google/blog/introducing-google-antigravity-cli) पहा.

| पैलू                 | `antigravity` (IDE)                                | `agy` (CLI)                                             |
| -------------------- | -------------------------------------------------- | ------------------------------------------------------- |
| **Google उत्पादन**   | Antigravity 2.0 / Antigravity IDE                  | Antigravity CLI                                         |
| **बॅकएंड**           | समान Google Cloud Code API                         | समान Google Cloud Code API                              |
| **OAuth / टोकन**     | समान क्लायंट, समान रीफ्रेश                         | समान क्लायंट, समान रीफ्रेश                              |
| **मॉडेल सूची**       | स्थिर निवडक सूची (OmniRoute मध्ये हार्डकोड केलेली) | Google कडून `:fetchAvailableModels` द्वारे थेट तपासलेली |
| **Claude मॉडेल्स**   | Sonnet 4.6, Opus 4.6 (प्रत्येकी 4 प्रकार)          | Sonnet 4.6, Opus 4.6 (प्रत्येकी 4 प्रकार)               |
| **Gemini नामकरण**    | सुटसुटीत लेबले (निम्न/मध्यम/उच्च)                  | अपस्ट्रीम IDs (extra-low/low/agent)                     |
| **अतिरिक्त मॉडेल्स** | `gpt-oss-120b-medium`                              | Google कडील अतिरिक्त मॉडेल्सचा समावेश असू शकतो          |
| **डीफॉल्ट वापर**     | IDE एकत्रीकरण (VS Code, JetBrains)                 | CLI / API प्रवेश                                        |
| **कोटा**             | agy सोबत सामायिक (समान Google खाते)                | antigravity सोबत सामायिक (समान Google खाते)             |

**उपलब्ध मॉडेल्स (प्रयोगाद्वारे सत्यापित, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (विचारक्षमतेचे विविध स्तर)
- Claude: Sonnet 4.6, Opus 4.6 (प्रत्येकी default/low/medium/high प्रकारांसह)
- इतर: GPT-OSS 120B Medium
- **Claude Sonnet 5 उपलब्ध नाही** — केवळ 4.6 प्रकार समर्थित आहेत

**मॉडेल सूची वेगळी का आहे**: Google चे CLI हे "वेग आणि कमी ओव्हरहेडसाठी अनुकूलित" तसेच "Gemini मॉडेल्ससह संयुक्तपणे अनुकूलित" आहे (Google च्या अधिकृत ब्लॉगनुसार). Web/IDE उत्पादन "सर्वसमावेशकतेसाठी अनुकूलित" आहे. CLI मॉडेल्सचा गतिशीलपणे शोध घेण्यासाठी `:fetchAvailableModels` वापरते, तर IDE स्थिर निवडक सूची वापरते.

**प्रत्यक्ष वापरात**: Gemini मॉडेल्ससाठी `agy/` उपसर्ग वापरा (उदा. `agy/gemini-3.7-flash-high`). स्थिर निवडक सूचीसाठी `antigravity/` वापरा. दोन्ही समान Google बॅकएंड वापरतात, परंतु मॉडेल्सचे वेगवेगळे नामकरण उपलब्ध करतात. कोटा सामायिक असतो — कोणताही प्रदाता वापरल्यास वापर समान Google खात्याच्या मर्यादांमध्ये मोजला जातो.

- **Non-Gemini मॉडेल्स** (Claude, GPT-OSS): यांना **स्वतंत्र** रेट लिमिट्स असतात. Gemini चा प्रवेश बंद झाल्यानंतरही ती उपलब्ध राहू शकतात.

### AI क्रेडिट्स (अतिरिक्त वापर)

> क्रेडिट्स कसे कार्य करतात यासाठी [Google One AI credits](https://support.google.com/googleone/answer/14534406) पहा.

आधारभूत कोटा संपल्यानंतर:

- **Never**: कोटा रीफ्रेश होईपर्यंत प्रतीक्षा करा; "Baseline model quota reached" असे दर्शवते
- **Always**: AI क्रेडिट्सचा स्वयंचलितपणे वापर करा; आधारभूत कोटा रीफ्रेश झाल्यानंतर पुन्हा त्यावर स्विच होते

क्रेडिट्स स्वतंत्रपणे खरेदी केले जातात आणि मानक API किंमतीनुसार वजा होतात.

### महत्त्वाचे तपशील

- कोटा **खाते-स्तरावर सामायिक** असतो — Antigravity IDE, CLI आणि OmniRoute मध्ये वापरलेले तेच Google खाते एकच कोटा पूल सामायिक करते
- प्रत्येक Google खात्याचा स्वतःचा स्वतंत्र कोटा असतो — अनेक खाती = अनेक कोटा पूल्स
- साप्ताहिक आधारमर्यादा गाठल्यानंतर AI Pro वापरकर्त्यांनी 5-तासांच्या रीसेटऐवजी **7-दिवसांचा प्रवेशबंदी कालावधी** अनुभवल्याचे नोंदवले आहे (उच्च मागणीसाठी हे रचनेनुसारच असल्याची पुष्टी Google ने केली आहे)

**तुमच्या खात्याचा कोटा संपल्यानंतर**: OmniRoute कॉम्बो रूटमधील पुढील उपलब्ध खात्यासह स्वयंचलितपणे पुन्हा प्रयत्न करते. कोणत्याही मॅन्युअल हस्तक्षेपाची आवश्यकता नाही.

## 3. projectId कसा मिळवायचा

प्रत्येक antigravity/agy कनेक्शनला Google Cloud Code `projectId` आवश्यक असतो. त्याशिवाय `/v1internal:models` एंडपॉइंट 404 प्रतिसाद देतो.

### पद्धत A: स्वयंचलित (शिफारस केलेली)

OmniRoute हे स्वयंचलितपणे हाताळते. Dashboard OAuth द्वारे नवीन Google खाते जोडल्यावर:

1. OmniRoute टोकन रीफ्रेश करते
2. projectId शोधण्यासाठी `loadCodeAssist` कॉल करते
3. कोणताही प्रोजेक्ट अस्तित्वात नसल्यास, तो तयार करण्यासाठी `onboardUser` कॉल करते
4. नव्याने तयार केलेला projectId मिळवण्यासाठी `loadCodeAssist` चा पुन्हा प्रयत्न करते
5. तो डेटाबेसमध्ये जतन करते

**हे बहुतांश खात्यांसाठी कार्य करते** — कोणत्याही मॅन्युअल पायऱ्यांची आवश्यकता नाही.

### पद्धत B: agy CLI द्वारे मॅन्युअल

स्वयंचलित शोध अयशस्वी झाल्यास (हे कधी घडते यासाठी विभाग 5 पहा):

```bash
# agy CLI इंस्टॉल करा (आधीपासून इंस्टॉल केलेले नसल्यास)
npm install -g @anthropic-ai/agy

# तुमच्या Google खात्याने लॉग इन करा
agy login

# ऑनबोर्डिंग आवश्यक असलेले खाते निवडा
# यामुळे Cloud Code नोंदणी सुरू होते आणि projectId नियुक्त केला जातो
```

`agy login` यशस्वी झाल्यानंतर, OmniRoute Dashboard मध्ये टोकन रीफ्रेश करा. projectId स्वयंचलितपणे शोधला जाईल.

### पडताळणी कशी करावी

डेटाबेस तपासा:

```bash
# OmniRoute कंटेनरच्या आत
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

किंवा लॉग्स तपासा:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. OAuth रीडायरेक्ट URI

### समस्या

Google OAuth साठी वैध रीडायरेक्ट URI आवश्यक आहे. OmniRoute मध्ये डीफॉल्टनुसार `http://127.0.0.1:20128/callback` (लूपबॅक) वापरला जातो. हे स्थानिक बिल्डसाठी कार्य करते, परंतु **रिमोट डिप्लॉयमेंटसाठी अयशस्वी ठरते** (उदा., LAN IP द्वारे अॅक्सेस केला जाणारा सर्व्हर).

Google खालील प्रकारचे रीडायरेक्ट URI नाकारते:

- IP पत्ते वापरणारे (`.com`, `.org` इत्यादींनी समाप्त होणारे डोमेन असणे आवश्यक आहे)
- OAuth क्लायंट कॉन्फिगमध्ये नोंदणीकृत रीडायरेक्ट URI शी न जुळणारे

### उपाय

**पर्याय A: अंगभूत OAuth फ्लो वापरा (डीफॉल्ट)**

- तुम्ही `localhost` किंवा `127.0.0.1` वरून OmniRoute अॅक्सेस करता तेव्हा कार्य करतो
- कोणतेही कॉन्फिगरेशन आवश्यक नाही

**पर्याय B: कस्टम OAuth क्रेडेन्शियल्स**

- तुमच्या एन्व्हायर्नमेंटमध्ये `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` सेट करा
- तुमची स्वतःची Google OAuth क्रेडेन्शियल्स द्या:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Google Cloud Console मध्ये `https://your-domain.com/callback` ची अधिकृत रीडायरेक्ट URI म्हणून नोंदणी करा

**पर्याय C: प्रारंभिक लॉगिनसाठी agy CLI वापरा**

- OmniRoute अॅक्सेस करणाऱ्या मशीनवर `agy login` चालवा
- OAuth फ्लो स्थानिकरीत्या पूर्ण होतो आणि टोकन संग्रहित केले जातात
- Dashboard द्वारे कनेक्शन OmniRoute मध्ये इम्पोर्ट करा

### मर्यादा

- कस्टम OAuth क्रेडेन्शियल्ससाठी डोमेन नाव आवश्यक आहे (Google रीडायरेक्ट URI म्हणून IP पत्ते स्वीकारत नाही)
- तुमच्याकडे डोमेन नसल्यास, त्याऐवजी पर्याय A किंवा C वापरा

## 5. समस्यानिवारण: स्वयंचलित सेटअप अयशस्वी झाल्यास

OmniRoute बहुतेक खात्यांसाठी projectId शोधणे आणि ऑनबोर्डिंग स्वयंचलितपणे हाताळते. ते अयशस्वी झाल्यास, मूळ कारण सहसा खालीलपैकी एक असते:

### खात्याचा प्रदेश ब्लॉक केलेला आहे

**लक्षण**: `agy login` खालील संदेश परत करते: "पात्रता तपासणी अयशस्वी झाली: तुमचे सध्याचे खाते Antigravity साठी पात्र नाही, कारण ते सध्या तुमच्या स्थानावर उपलब्ध नाही."

**मूळ कारण**: Google खात्यांमध्ये नोंदणीच्या वेळी सेट केलेले बॅकएंड "Country Association" फील्ड असते. agy CLI आणि Cloud Code API हे फील्ड काटेकोरपणे तपासतात — याउलट, वेब Gemini फक्त तुमचा सध्याचा IP तपासते.

> तुमच्या खात्याशी संबंधित प्रदेश तपासण्यासाठी किंवा बदलण्यासाठी, [Google Country Association Form](https://policies.google.com/country-association-form) ला भेट द्या.

**वेब Gemini कार्य करते, पण agy का कार्य करत नाही**:

- वेब Gemini / Google One: फक्त सध्याचा IP तपासते (प्रॉक्सीमुळे तपासणी पार होते)
- agy CLI / Cloud Code API: बॅकएंड Country Association फील्ड वाचते (प्रॉक्सीचा उपयोग होत नाही)

**निराकरण**:

1. US IP वापरत असताना [Google Country Association Form](https://policies.google.com/country-association-form) ला भेट द्या
2. प्रदेश बदलण्याची विनंती सबमिट करा ("I live in a different country" निवडा)
3. Google कडून प्रक्रिया पूर्ण होण्यासाठी आणि ईमेल सूचना मिळण्यासाठी 1-24 तास प्रतीक्षा करा
4. त्यानंतर `agy login` यशस्वी झाले पाहिजे

### खात्यामध्ये Cloud Code प्रोजेक्ट नाही

**लक्षण**: लॉगमध्ये `loadCodeAssist returned no project id` आणि `onboardUser failed (400)` दिसते.

**मूळ कारण**: खाते यापूर्वी कधीही Google Cloud Code सोबत नोंदणीकृत केलेले नाही आणि स्वयंचलित ऑनबोर्डिंग अयशस्वी झाले.

**निराकरण**: Cloud Code नोंदणी सुरू करण्यासाठी `agy login` मॅन्युअली चालवा, त्यानंतर OmniRoute Dashboard मध्ये टोकन रिफ्रेश करा.

### टोकन कालबाह्य किंवा रद्द झाले आहे

**लक्षण**: लॉगमध्ये 401 त्रुटी किंवा "टोकन कालबाह्य झाले आहे" असे संदेश दिसतात.

**निराकरण**: Dashboard → Providers → agy → रिफ्रेश आयकॉनवर क्लिक करा येथे टोकन रिफ्रेश करा. रिफ्रेश टोकनच रद्द झाले असल्यास, तुम्हाला OAuth द्वारे पुन्हा प्रमाणीकरण करावे लागेल.

```
खाते कार्यरत नाही?
│
├─ डेटाबेसमध्ये त्याचा projectId आहे का?
│  ├─ होय → समस्या इतरत्र आहे (टोकन कालबाह्य, दर मर्यादा इ.)
│  └─ नाही ↓
│
├─ खात्याचे देशाशी संलग्नन प्रतिबंधित प्रदेशावर सेट केले आहे का?
│  ├─ होय → Google Country Association Form वर प्रदेश बदला
│  │         (https://policies.google.com/country-association-form)
│  │         1-24 तास प्रतीक्षा करा, त्यानंतर पुन्हा प्रयत्न करा
│  └─ नाही ↓
│
├─ खात्याकडे Google One AI Pro सदस्यता आहे का?
│  ├─ नाही → प्रथम one.google.com वर सदस्यता घ्या
│  └─ होय ↓
│
├─ स्वयंचलित शोधाचा प्रयत्न करा (Dashboard मध्ये टोकन रिफ्रेश करा)
│  ├─ कार्य करते → पूर्ण
│  └─ तरीही अयशस्वी ↓
│
└─ मॅन्युअल: मशीनवर `agy login` चालवा
   ├─ कार्य करते → Dashboard मध्ये टोकन रिफ्रेश करा, projectId सापडला
   └─ अयशस्वी → त्रुटी संदेश तपासा; बहुधा प्रदेश किंवा सदस्यतेशी संबंधित समस्या
```
