## स्थापना पद्धती

### npm (शिफारस केलेले)

```bash
npm install -g omniroute
omniroute
```

डॅशबोर्ड `http://localhost:20128` येथे उघडतो आणि API चा मूळ URL `http://localhost:20128/v1` आहे.

### pnpm

```bash
pnpm add -g omniroute@latest --allow-build=better-sqlite3 --allow-build=@swc/core
omniroute
```

> **pnpm वापरकर्ते:** `better-sqlite3` आणि `@swc/core` साठी नेटिव्ह बिल्ड स्क्रिप्ट सक्षम करण्यासाठी `--allow-build` फ्लॅग आवश्यक आहे. pnpm v11 वरील ग्लोबल स्थापनांसाठी `pnpm approve-builds -g` कमांड समर्थित नाही.

### Arch Linux (AUR)

```bash
yay -S omniroute-bin
systemctl --user enable --now omniroute.service
```

[AUR पॅकेज](https://aur.archlinux.org/packages/omniroute-bin) OmniRoute स्थापित करते आणि systemd वापरकर्ता सेवा पुरवते.

### स्रोतापासून

```bash
npm install
PORT=20128 DASHBOARD_PORT=20129 NEXT_PUBLIC_BASE_URL=http://localhost:20129 npm run dev
```

> **Windows नोंद:** जुनी `%USERPROFILE%\.omniroute` डिरेक्टरी अस्तित्वात नसल्यास, डीफॉल्टनुसार OmniRoute `%APPDATA%\omniroute` वापरते. वेगळे डेटा-डिरेक्टरी स्थान निवडण्यासाठी `DATA_DIR` सेट करा.

> **नोंद:** प्रथमच चालवताना `npm install`, `.env.example` पासून `.env` स्वयंचलितपणे तयार करते. त्यानंतरच्या स्थापना विद्यमान `.env` अधिलिखित करणार नाहीत, त्यामुळे सानुकूलने जतन केली जातात. पुन्हा प्रारंभिक मूल्ये भरण्यासाठी, कमांड पुन्हा चालवण्यापूर्वी `.env` हटवा.

### Docker

Compose प्रोफाइल्स आणि Caddy HTTPS सह संपूर्ण Docker सेटअपसाठी [Docker मार्गदर्शक](./DOCKER_GUIDE.md) पहा.

### डेस्कटॉप ॲप (Electron)

OmniRoute मध्ये Electron 41 + electron-builder 26.10 वर तयार केलेले डेस्कटॉप रॅपर समाविष्ट आहे. उपलब्ध स्क्रिप्ट्स (वर्कस्पेस रूट):

```bash
npm run electron:dev          # हॉट-रिलोडसह डेस्कटॉप चालवा
npm run electron:build        # सध्याच्या OS साठी बिल्ड करा (स्वयंचलितपणे ओळखले जाते)
npm run electron:build:win    # Windows इंस्टॉलर (NSIS + पोर्टेबल)
npm run electron:build:mac    # macOS (dmg + zip, arm64+x64)
npm run electron:build:linux  # Linux (AppImage + deb + rpm)
npm run electron:smoke:packaged  # पॅकेज केलेल्या बिल्डची स्मोक चाचणी करा
```

डेस्कटॉप इंस्टॉलर्सचे रिलीज GitHub Releases शी संलग्न केलेले असतात. Electron विषयी संपूर्ण सखोल माहितीसाठी (साइनिंग, IPC ब्रिज, डिस्ट्रोज), [`ELECTRON_GUIDE.md`](./ELECTRON_GUIDE.md) पहा _(नंतरच्या टप्प्यात तयार केलेले)_.

### हेडलेस सर्व्हर (CI/ऑटोमेशन)

देखरेखीशिवाय चालणाऱ्या सेटअपसाठी (Docker, Kubernetes, CI), हे वापरा:

```bash
omniroute setup --non-interactive
omniroute providers test-batch
```

env vars (`INITIAL_PASSWORD`, `OMNIROUTE_WS_BRIDGE_SECRET`, इत्यादी) सोबत वापरल्यास, याद्वारे तुम्ही पूर्णपणे स्क्रिप्ट करता येणारे OmniRoute इन्स्टन्स सुरू करू शकता.

### CLI पर्याय

| कमांड                   | वर्णन                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------- |
| `omniroute`             | सर्व्हर सुरू करा (`PORT=20128`, API आणि डॅशबोर्ड एकाच पोर्टवर)                        |
| `omniroute setup`       | पासवर्ड आणि पहिल्या प्रोव्हायडरसाठी मार्गदर्शित CLI ऑनबोर्डिंग                        |
| `omniroute doctor`      | सर्व्हर सुरू न करता स्थानिक आरोग्य तपासण्या चालवा                                     |
| `omniroute providers`   | CLI मधून प्रोव्हायडर्स शोधा, सूचीबद्ध करा, सत्यापित करा आणि तपासा                     |
| `omniroute config`      | CLI साधन कॉन्फिगरेशन — कॉन्फिग्स सूचीबद्ध करा, मिळवा, सेट करा आणि सत्यापित करा        |
| `omniroute status`      | ऑफलाइन स्थिती डॅशबोर्ड — आवृत्ती, DB, साधने, कॉन्फिगरेशन                              |
| `omniroute logs`        | API मधून वापर लॉग्स प्रवाहित करा (`--follow` समर्थित)                                 |
| `omniroute update`      | OmniRoute अद्यतने तपासा किंवा लागू करा                                                |
| `omniroute provider`    | प्रोव्हायडर कनेक्शन्स व्यवस्थापित करा — जोडा, सूचीबद्ध करा, काढा, तपासा, डीफॉल्ट ठरवा |
| `omniroute --port 3000` | कॅनॉनिकल/API पोर्ट 3000 वर सेट करा                                                    |
| `omniroute --mcp`       | MCP सर्व्हर सुरू करा (stdio ट्रान्सपोर्ट)                                             |
| `omniroute --no-open`   | ब्राउझर स्वयंचलितपणे उघडू नका                                                         |
| `omniroute --help`      | मदत दाखवा                                                                             |

हेडलेस सेटअप फ्लॅग्स किंवा एन्व्हायर्नमेंट व्हेरिएबल्स वापरून स्क्रिप्ट केला जाऊ शकतो:

```bash
omniroute setup --non-interactive --password "$OMNIROUTE_PASSWORD"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY" --test-provider
```

डॅशबोर्ड न उघडता स्थानिक निदान चालवा:

```bash
omniroute doctor
omniroute doctor --json
omniroute doctor --no-liveness
```

डॅशबोर्ड न उघडता SSH किंवा स्क्रिप्ट्समधून प्रोव्हायडर्स व्यवस्थापित करा:

```bash
omniroute providers available
omniroute providers available --search openai
omniroute providers available --category api-key
omniroute providers list
omniroute providers test <id-or-name>
omniroute providers test-all
omniroute providers validate
```

## CLI साधन कॉन्फिगरेशन

### 1) प्रदाते कनेक्ट करा आणि API की तयार करा

1. Dashboard → `Providers` उघडा आणि किमान एक प्रदाता (OAuth किंवा API की) कनेक्ट करा.
2. Dashboard → `Endpoints` उघडा आणि API की तयार करा.
3. (पर्यायी) Dashboard → `Combos` उघडा आणि तुमची फॉलबॅक साखळी सेट करा.

### 2) तुमचे कोडिंग साधन निर्देशित करा

```txt
Base URL: http://localhost:20128/v1
API Key:  [Endpoint पृष्ठावरून कॉपी करा]
Model:    if/qwen3.8-max-preview (किंवा कोणताही provider/model प्रीफिक्स)
```

तुमचा एडिटर `Authorization: Bearer ...` पाठवू शकत नसल्यास, त्याऐवजी टोकनयुक्त सुसंगतता बेस वापरा:

```txt
Base URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/
Models URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/models
Chat URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/chat/completions
Ollama Tags URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/api/tags
```

Claude Code, Codex CLI, Cursor, Cline, OpenClaw, OpenCode आणि OpenAI-सुसंगत SDKs सोबत कार्य करते.

#### `setup-*` वापरून स्वयंचलितपणे कॉन्फिगर करा

बेस URL आणि की हाताने पेस्ट करण्याऐवजी, OmniRoute ला लाइव्ह मॉडेल कॅटलॉगमधून प्रत्येक साधनाचे
स्वतःचे कॉन्फिगरेशन लिहू द्या. प्रत्येक साधनासाठी एक कमांड:

```bash
omniroute setup-codex        # ~/.codex/<name>.config.toml प्रोफाइल्स
omniroute setup-claude       # ~/.claude/profiles/<name>/settings.json
omniroute setup-opencode     # ~/.config/opencode/opencode.json (openai-सुसंगत)
omniroute setup-cline        # Cline CLI + VS Code एक्स्टेंशन सेटिंग्ज
omniroute setup-kilo         # Kilo Code
omniroute setup-continue     # ~/.continue/config.yaml (Continue / cn)
omniroute setup-cursor       # Cursor मधील अॅप-अंतर्गत पायऱ्या प्रिंट करते
omniroute setup-roo          # Roo Code इम्पोर्ट + autoImport पॉइंटर
omniroute setup-crush        # ~/.config/crush/crush.json
omniroute setup-goose        # ~/.config/goose/config.yaml
omniroute setup-aider        # ~/.aider.conf.yml
omniroute setup-qwen         # ~/.qwen/settings.json + ~/.qwen/.env
```

स्थानिक साधन **रिमोट** OmniRoute विरुद्ध कॉन्फिगर करण्यासाठी प्रत्येक कमांड `--remote <url> --api-key <key>` स्वीकारते, तसेच पूर्वावलोकनासाठी `--dry-run` स्वीकारते. योग्य
env अंतर्भूत करून आणि कोणतेही कॉन्फिगरेशन अजिबात न लिहिता CLI सुरू करण्यासाठी, सामान्य लाँचर
`omniroute run <target>` (claude, codex, aider, goose, opencode, qwen, gemini) वापरा;
प्रति-साधन जुने लाँचर `omniroute launch` (Claude Code) आणि
`omniroute launch-codex` (Codex) अजूनही उपलब्ध आहेत.

संपूर्ण तक्त्यासाठी (प्रत्येक कमांड काय लिहिते, प्रत्येक फ्लॅग, स्थानिक विरुद्ध रिमोट, बेस-URL
`/v1` पद्धती), **[CLI एकत्रीकरणे](./CLI-INTEGRATIONS.md)** पहा.

प्रत्येक साधनाच्या तपशीलवार कॉन्फिगरेशनसाठी (Claude Code, Codex CLI, Cursor, Cline, OpenClaw, Kilo Code, Copilot आणि इतर), समर्पित **[CLI साधने मार्गदर्शक](../reference/CLI-TOOLS.md)** पहा.

## प्रोटोकॉल सेटअप (MCP + A2A)

### MCP सेटअप (Model Context Protocol)

stdio मोडमध्ये MCP ट्रान्सपोर्ट सुरू करा:

```bash
omniroute --mcp
```

शिफारस केलेला प्रमाणीकरण प्रवाह:

```bash
# 1. MCP सर्व्हर सुरू करा
omniroute --mcp

# 2. तुमच्या MCP क्लायंटमधून, कॉल करा:
omniroute_get_health        # सिस्टमची स्थिती परत केली पाहिजे
omniroute_list_combos       # सक्रिय कॉम्बोज परत केले पाहिजेत

# 3. किंवा संपूर्ण E2E संच चालवा:
npm run test:protocols:e2e
```

#### MCP क्लायंट कॉन्फिगरेशन

**Claude Code:**

```bash
claude mcp add-server omniroute --type http --url http://localhost:20128/api/mcp/stream
```

**Cursor / Cline:**

तुमच्या MCP सेटिंग्जमध्ये जोडा:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"],
      "env": {}
    }
  }
}
```

**संपूर्ण MCP दस्तऐवजीकरण:** [MCP Server README](../../open-sse/mcp-server/README.md) — 110 साधने, IDE कॉन्फिगरेशन्स, Python/TS/Go क्लायंट्स.

### A2A सेटअप (Agent-to-Agent Protocol)

Agent Card सत्यापित करा:

```bash
curl http://localhost:20128/.well-known/agent.json
```

टास्क पाठवा:

```bash
curl -X POST http://localhost:20128/a2a \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":"quickstart","method":"message/send","params":{"skill":"quota-management","messages":[{"role":"user","content":"Give me a short quota summary."}]}}'
```

**संपूर्ण A2A दस्तऐवजीकरण:** [A2A Server README](../../src/lib/a2a/README.md) — JSON-RPC 2.0, कौशल्ये, स्ट्रीमिंग, टास्क जीवनचक्र.

## टाइमआउट कॉन्फिगरेशन

### मूलभूत टाइमआउट्स

बहुतेक डिप्लॉयमेंट्ससाठी, तुम्हाला केवळ या दोन व्हेरिएबल्सची आवश्यकता असते:

| व्हेरिएबल                | डीफॉल्ट                                   | उद्देश                                                                                                                                                            |
| ------------------------ | ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `REQUEST_TIMEOUT_MS`     | `600000`                                  | अपस्ट्रीम प्रतिसाद सुरू होण्याचा टाइमआउट, लपवलेले Undici टाइमआउट्स, TLS फिंगरप्रिंट विनंत्या आणि API ब्रिज विनंती/प्रॉक्सी टाइमआउट्स यांच्यासाठी सामायिक आधाररेषा |
| `STREAM_IDLE_TIMEOUT_MS` | `REQUEST_TIMEOUT_MS` कडून वारशाने प्राप्त | OmniRoute ने SSE स्ट्रीम रद्द करण्यापूर्वी स्ट्रीमिंग चंक्समधील कमाल अंतर                                                                                         |

बॅकवर्ड कंपॅटिबिलिटी जतन केली जाते: विद्यमान `FETCH_TIMEOUT_MS`, `API_BRIDGE_PROXY_TIMEOUT_MS` आणि इतर प्रत्येक स्तरासाठी असलेले टाइमआउट व्हेरिएबल्स अजूनही कार्य करतात आणि सामायिक आधाररेषेला ओव्हरराइड करतात.

### प्रोव्हायडर-विशिष्ट नोंदी

Claude Code-सुसंगत अपस्ट्रीम्ससाठी (`anthropic-compatible-cc-*`), OmniRoute निर्धारित फेच टाइमआउटवरून आउटबाउंड `X-Stainless-Timeout` हेडर मिळवते, जेणेकरून प्रोव्हायडरच्या बाजूचे रीड टाइमआउट्स तुमच्या env कॉन्फिगरेशनशी संरेखित राहतील.

तृतीय-पक्ष Claude Code-सुसंगत रिव्हर्स प्रॉक्सींसाठी, OmniRoute डीफॉल्ट `anthropic-beta` संच मर्यादित ठेवते आणि `Client Cache Control` हे `Auto` वर ठेवलेले असताना, फक्त क्लायंटने प्रदान केलेले `cache_control` मार्कर्स फॉरवर्ड करते. अपस्ट्रीमला विशेषतः संपादित Claude विचारप्रवाहांची आवश्यकता असेल तेव्हाच प्रत्येक कनेक्शनसाठी असलेले "Enable redact-thinking beta" टॉगल सक्षम करा.

### प्रगत टाइमआउट ओव्हरराइड्स

| व्हेरिएबल                                | डीफॉल्ट                                                  | उद्देश                                                                                   |
| ---------------------------------------- | -------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `FETCH_TIMEOUT_MS`                       | `REQUEST_TIMEOUT_MS` कडून वारशाने प्राप्त                | प्रतिसाद हेडर्स प्राप्त होईपर्यंत वापरला जाणारा अपस्ट्रीम प्रतिसाद सुरू होण्याचा टाइमआउट |
| `FETCH_HEADERS_TIMEOUT_MS`               | `FETCH_TIMEOUT_MS` कडून वारशाने प्राप्त                  | अपस्ट्रीम प्रतिसाद हेडर्स प्राप्त करण्यासाठी Undici ची कालमर्यादा                        |
| `FETCH_BODY_TIMEOUT_MS`                  | `FETCH_TIMEOUT_MS` कडून वारशाने प्राप्त                  | अपस्ट्रीम बॉडी चंक्समधील Undici ची कालमर्यादा (`0` ती अक्षम करते)                        |
| `FETCH_CONNECT_TIMEOUT_MS`               | `30000`                                                  | Undici TCP कनेक्ट टाइमआउट                                                                |
| `FETCH_KEEPALIVE_TIMEOUT_MS`             | `4000`                                                   | Undici निष्क्रिय keep-alive सॉकेट टाइमआउट                                                |
| `TLS_CLIENT_TIMEOUT_MS`                  | `FETCH_TIMEOUT_MS` कडून वारशाने प्राप्त                  | `wreq-js` द्वारे केलेल्या TLS फिंगरप्रिंट विनंत्यांसाठी टाइमआउट                          |
| `API_BRIDGE_PROXY_TIMEOUT_MS`            | `REQUEST_TIMEOUT_MS` किंवा `600000` कडून वारशाने प्राप्त | API पोर्टवरून डॅशबोर्ड पोर्टकडे `/v1` प्रॉक्सी फॉरवर्डिंगसाठी टाइमआउट                    |
| `API_BRIDGE_SERVER_REQUEST_TIMEOUT_MS`   | `max(API_BRIDGE_PROXY_TIMEOUT_MS, 300000)`               | API ब्रिज सर्व्हरवरील इनकमिंग विनंती टाइमआउट                                             |
| `API_BRIDGE_SERVER_HEADERS_TIMEOUT_MS`   | `60000`                                                  | API ब्रिज सर्व्हरवरील इनकमिंग हेडर टाइमआउट                                               |
| `API_BRIDGE_SERVER_KEEPALIVE_TIMEOUT_MS` | `5000`                                                   | API ब्रिज सर्व्हरवरील keep-alive टाइमआउट                                                 |
| `API_BRIDGE_SERVER_SOCKET_TIMEOUT_MS`    | `0`                                                      | API ब्रिज सर्व्हरवरील सॉकेट निष्क्रियता टाइमआउट (`0` तो अक्षम करते)                      |

> **टीप:** स्ट्रीमिंग विनंत्यांसाठी, `FETCH_TIMEOUT_MS` फक्त कनेक्शन सेटअप / पहिल्या अपस्ट्रीम प्रतिसादाची प्रतीक्षा करण्याचा कालावधी समाविष्ट करतो. स्ट्रीम सक्रिय झाल्यानंतर, OmniRoute फक्त प्रत्यक्ष अडथळा (`STREAM_IDLE_TIMEOUT_MS`) किंवा Undici बॉडी निष्क्रियता (`FETCH_BODY_TIMEOUT_MS`) आल्यावरच तो रद्द करेल.

### रिव्हर्स प्रॉक्सी सुसंगतता

तुम्ही OmniRoute हे Nginx, Caddy, Cloudflare किंवा अन्य रिव्हर्स प्रॉक्सीमागे चालवत असल्यास, प्रॉक्सी टाइमआउट्सदेखील तुमच्या OmniRoute स्ट्रीम/फेच टाइमआउट्सपेक्षा जास्त असल्याची खात्री करा.

## Void Linux (`xbps-src`) टेम्पलेट

Void Linux वापरकर्ते `xbps-src` वापरून नेटिव्ह पॅकेज बिल्ड करू शकतात. हा ब्लॉक `srcpkgs/omniroute/template` म्हणून जतन करा:

```bash
# 'omniroute' साठी टेम्पलेट फाइल
pkgname=omniroute
version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"
maintainer="zenobit <zenobit@disroot.org>"
license="MIT"
homepage="https://github.com/diegosouzapw/OmniRoute"
distfiles="https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz"
# प्रत्येक रिलीझसाठी चेकसम पुन्हा तयार करण्यासाठी:
#   curl -L -o /tmp/omniroute.tar.gz "https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz" && sha256sum /tmp/omniroute.tar.gz
checksum=PLACEHOLDER_REGENERATE_PER_RELEASE
system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	NODE_ENV=development npm ci --ignore-scripts
	npm run build
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	rm -rf .next/standalone/node_modules/@img

	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
		touch "${DESTDIR}/usr/lib/omniroute/${_d}/.keep"
	done

	cat > "${WRKDIR}/omniroute" <<'EOF'
#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"
mkdir -p "${DATA_DIR}"
exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```
