OmniRoute प्रत्येक विनंतीच्या खर्चाचा अंदाज कसा लावते, त्याची नोंद कशी करते आणि त्याचा अहवाल कसा देते — तसेच
डॅशबोर्डवरील आकडा बिल नसून **बचत ट्रॅकर** का आहे.

हेही पहा: [वापरकर्ता मार्गदर्शिका](./USER_GUIDE.md) · [वैशिष्ट्यांची गॅलरी](./FEATURES.md)

## हे काय आहे (आणि काय नाही)

OmniRoute टोकनची संख्या मॉडेलच्या किंमत-दरांनी गुणून प्रत्येक पूर्णत्वासाठी प्रत्येक-विनंतीचा USD खर्च निर्धारित करते.
हे आकडे **खर्च** डॅशबोर्ड,
`omniroute cost` / `omniroute usage` CLI, CSV/JSON निर्याती आणि प्रत्येक API कीसाठीचे बजेट यांना आधार देतात.

> **डॅशबोर्डवरील "खर्च" हा बचत ट्रॅकर आहे, बिल नाही.** OmniRoute तुमच्याकडून कधीही शुल्क आकारत नाही
> — ती तुमच्या विनंत्या तुम्ही आधीच जोडलेल्या प्रदात्यांकडे (तुमच्या स्वतःच्या
> सदस्यता, मोफत श्रेणी आणि API की) रूट करते. पूर्णपणे मोफत
> मॉडेल्सवर जमा झालेला "$290 एकूण खर्च" म्हणजे साधारणपणे **तुम्ही सशुल्क API ला न भरलेले $290**.
> समान ट्रॅफिकसाठी प्रमाणित सूची-किंमतींनुसार किती खर्च आला असता याचा हा एक _अंदाज_ आहे,
> ज्यामुळे तुमचा वापर कुठे केंद्रित आहे आणि स्वस्त/मोफत प्रदात्यांकडे रूट केल्यामुळे तुमची किती बचत होत आहे हे तुम्ही पाहू शकता.

ही मांडणी प्रकल्पाच्या [README](../../README.md) मध्ये थेट नमूद केली आहे ("डॅशबोर्डवरील
'खर्च' हा बचत ट्रॅकर आहे, बिल नाही").

हा आकडा अंदाज असल्यामुळे:

- तो प्रत्येक मॉडेलसाठी OmniRoute कडे असलेल्या किंमत-तक्त्यावर अवलंबून असतो. किंमतीची
  नोंद नसलेले मॉडेल `0` खर्चात योगदान देते (एक्सप्लोररमध्ये ते "वारसा / मोफत" पंक्ती म्हणून दिसते).
- मोफत श्रेणी आणि सदस्यता ट्रॅफिकसाठीही _अंदाजित_ खर्च जमा होतो — ती
  तुम्ही वाचवत असलेली रक्कम आहे, देय रक्कम नाही.

## खर्चांचा अंदाज कसा लावला जातो

### किंमतींचा स्रोत

खर्च खालील प्राधान्यक्रमाने निर्धारित केलेल्या किंमत-तक्त्यातून येतात
([`src/lib/pricingSync.ts`](../../src/lib/pricingSync.ts)):

1. **वापरकर्ता अधिलिखित मूल्ये** — तुम्ही डॅशबोर्डमध्ये / `PATCH /api/pricing` द्वारे सेट केलेल्या किंमती.
2. **समक्रमित बाह्य किंमती** — समक्रमण सक्षम असताना LiteLLM च्या सार्वजनिक
   `model_prices_and_context_window.json` मधून आणलेल्या (स्वतंत्र
   `pricing_synced` नेमस्पेसमध्ये साठवल्या जातात, त्यामुळे त्या तुमची अधिलिखित मूल्ये कधीही बदलत नाहीत).
3. **हार्डकोड केलेली डीफॉल्ट मूल्ये** — OmniRoute सोबत पुरवली जातात.

बाह्य किंमत-समक्रमण **ऐच्छिक** आहे आणि डीफॉल्टनुसार अक्षम असते. संबंधित पर्यावरण चल
([`.env.example`](../../.env.example) पहा):

| पर्यावरण चल             | डीफॉल्ट   | उद्देश                                                               |
| ----------------------- | --------- | -------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`   | स्टार्टअपवेळी पार्श्वभूमीतील LiteLLM किंमत-समक्रमण सक्षम करा.        |
| `PRICING_SYNC_INTERVAL` | `86400`   | समक्रमण मध्यांतर **सेकंदांमध्ये** (डीफॉल्टनुसार दररोज).              |
| `PRICING_SYNC_SOURCES`  | `litellm` | स्वल्पविरामाने विभक्त स्रोत-सूची (सध्या फक्त `litellm` समर्थित आहे). |

### खर्चाचे सूत्र

प्रत्येक विनंतीचा खर्च टोकनची संख्या आणि प्रति-दशलक्ष-टोकन दरांवरून
[`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts)
(`computeCostFromPricing` / `calculateCost`) मध्ये मोजला जातो:

- **इनपुट टोकन** (कॅश वाचन आणि कॅश-निर्मिती टोकन वगळून) × `input` दर.
- **कॅश-वाचन टोकन** × `cached` दर (उपलब्ध नसल्यास इनपुट दर वापरला जातो).
- **कॅश-निर्मिती टोकन** × `cache_creation` दर (उपलब्ध नसल्यास इनपुट दर वापरला जातो).
- **आउटपुट टोकन** × `output` दर.
- **तर्क टोकन** × `reasoning` दर (उपलब्ध नसल्यास आउटपुट दर वापरला जातो).

सर्व दर प्रति 1,000,000 टोकनसाठी USD म्हणून वापरले जातात. Codex "fast"/"priority" किंवा
"flex" सेवा श्रेणीसाठी खर्च गुणक (`getCodexFastCostMultiplier`) लागू होतो — उदा. flex
साठी टोकनवर 50% सवलतीने शुल्क आकारले जाते आणि ती डॅशबोर्डमध्ये **flex बचत** म्हणून दाखवली जाते.

मॉडेलची नावे प्रथम सामान्यीकृत केली जातात (`openai/` किंवा
`accounts/fireworks/models/` यांसारखे प्रदाता-पथ उपसर्ग काढले जातात), त्यामुळे ऐतिहासिक पंक्त्यांनाही योग्य किंमत लागू होते.

### खर्चाची नोंद कशी केली जाते

- प्रत्येक विनंतीचा खर्च प्रतिसादानंतर मोजला जातो आणि प्रतिसादाची वाट न पाहता नोंदवला जातो, त्यामुळे
  क्लायंटच्या विलंबात कधीही भर पडत नाही. सामायिक-कोटा वापर पुढील
  इव्हेंट-लूप टिकवर [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts) द्वारे नियोजित केला जातो.
- API-की खर्च बफर केला जातो आणि
  [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) द्वारे बॅचमध्ये फ्लश केला जातो (डीफॉल्ट 60s फ्लश मध्यांतर,
  1,000-नोंद बफर). खालीलद्वारे समायोजित करता येते:

  | पर्यावरण चल                         | डीफॉल्ट | उद्देश                                |
  | ----------------------------------- | ------- | ------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000` | मिलिसेकंदांमधील फ्लश मध्यांतर.        |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`  | फ्लश करण्यापूर्वीच्या कमाल बफर नोंदी. |

डॅशबोर्डवरील खर्चाचे आकडे साठवलेल्या प्रत्येक-पंक्तीच्या डॉलर रकमेतून **वाचले जात नाहीत** — प्रत्येक वेळी
विश्लेषण एंडपॉइंट चालताना ते टोकनची संख्या आणि सध्याचा किंमत-तक्ता वापरून तत्काळ पुन्हा मोजले जातात.
याचा अर्थ चुकीची किंमत दुरुस्त केल्यावर (आणि पुन्हा समक्रमित केल्यावर)
ऐतिहासिक खर्च-अंदाज पूर्वलक्षी प्रभावाने अद्ययावत होतात.

## डॅशबोर्ड: खर्च पृष्ठ

**खर्च** पृष्ठ `/dashboard/costs` येथे आहे
(`src/app/(dashboard)/dashboard/costs/`).
त्याचे मुख्य दृश्य **खर्चाचा आढावा** टॅब आहे
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`),
जो `GET /api/usage/analytics` मधून सर्वकाही लोड करतो.

त्यामध्ये काय दिसते:

- **खर्च टाइल्स** — _आज (1d)_, _7d_, _30d_ आणि निवडलेल्या
  कालावधीसाठी अंदाजित खर्च. कालावधी निवडक: `7d`, `30d`, `90d`, `all`.
- **प्रमुख मेट्रिक्स** — कालावधीतील विनंत्या, सक्रिय प्रदाते, सक्रिय मॉडेल्स, प्रति
  विनंती सरासरी खर्च.
- **खर्च एक्सप्लोरर** — **प्रदाता**, **मॉडेल**,
  **API की**, **खाते** किंवा **सेवा स्तर** यानुसार गटबद्ध केलेले, क्रमवारी लावता/फिल्टर करता येणारे टेबल; यामध्ये खर्च, विनंत्या, टोकन्स, सरासरी
  खर्च/विनंती आणि एकूणातील वाटा % समाविष्ट असतो.
- **टोकन वापर** — एकूण / इनपुट / आउटपुट टोकन्स आणि इनपुट:आउटपुट गुणोत्तर.
- **राउटिंग कार्यक्षमता** — फॉलबॅक संख्या, फॉलबॅक दर आणि विनंती केलेल्या मॉडेलचे कव्हरेज.
- **मासिक अंदाज** — अलीकडील दैनिक सरासरीवरून महिनाअखेरीच्या खर्चाचा अंदाज लावतो.
- **कालावधी तुलना** — कालावधीच्या पहिल्या आणि दुसऱ्या अर्ध्यामधील % बदल.
- **चार्ट्स** — दैनिक खर्च कल, प्रदात्याचा वाटा (पाय), सर्वोच्च प्रदाते, सर्वोच्च मॉडेल्स, API
  कीनुसार खर्च, खात्यानुसार खर्च, साप्ताहिक वापर पॅटर्न आणि क्रियाकलाप हीटमॅप.
- **निर्यात** — सध्याचा कालावधी **CSV** किंवा **JSON** म्हणून डाउनलोड करा (शून्यापेक्षा जास्त खर्चाचा डेटा
  उपलब्ध झाल्यावर बटणे दिसतात).

किंमत निर्धारित केलेली ट्रॅफिक नसल्यास, `$0` ऐवजी पंक्ती "लेगसी / मोफत" लेबल म्हणून रेंडर होतात,
जे बचत-ट्रॅकर मॉडेल प्रतिबिंबित करते.

### संबंधित खर्च उपपृष्ठे

खर्च विभागामध्ये पुढील पृष्ठेदेखील आहेत (सर्व `/dashboard/costs/` अंतर्गत):

- **किंमत निर्धारण** (`/dashboard/costs/pricing`) — प्रति-मॉडेल किंमती पहा आणि ओव्हरराइड करा (सामायिक
  किंमत निर्धारण टॅब रेंडर करतो).
- **बजेट** (`/dashboard/costs/budget`) — प्रति-व्याप्ती खर्च मर्यादा सेट करा (सामायिक
  बजेट टॅब रेंडर करतो).
- **कोटा शेअर** (`/dashboard/costs/quota-share`) — सामायिक-कोटा पूल्स आणि वापर-दर
  दृश्ये.

## API एंडपॉइंट्स

नमूद केले नसल्यास, या सर्वांसाठी व्यवस्थापन प्रमाणीकरण (`requireManagementAuth` द्वारे लूपबॅक/JWT)
आवश्यक आहे.

### वापर आणि खर्च विश्लेषण

| पद्धत | एंडपॉइंट                 | उद्देश                                                                                                                                               |
| ----- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET` | `/api/usage/analytics`   | संपूर्ण खर्च/वापर विश्लेषण: सारांश, दैनिक कल, प्रदाता/मॉडेल/API की/खाते/स्तरानुसार. क्वेरी: `range`, `startDate`, `endDate`, `apiKeyIds`, `presets`. |
| `GET` | `/api/usage/utilization` | कालांतराने प्रति-प्रदाता कोटा वापर. क्वेरी: `range` (`1h`/`24h`/`7d`/`30d`), `provider`.                                                             |
| `GET` | `/api/usage/history`     | रॉ वापर इतिहास पंक्ती.                                                                                                                               |
| `GET` | `/api/usage/call-logs`   | प्रति-विनंती कॉल लॉग्स (मॉडेल, टोकन्स, खर्च, विलंब, स्थिती).                                                                                         |
| `GET` | `/api/usage/quota`       | प्रदाता कोटाची स्थिती.                                                                                                                               |
| `GET` | `/api/usage/proxy-logs`  | प्रॉक्सी विनंती लॉग्स.                                                                                                                               |

### बजेट्स

| पद्धत  | एंडपॉइंट                 | उद्देश                                                                        |
| ------ | ------------------------ | ----------------------------------------------------------------------------- |
| `GET`  | `/api/usage/budget`      | एका API कीसाठी खर्च सारांश + बजेट तपासणी (`apiKeyId` क्वेरी पॅरामीटर आवश्यक). |
| `POST` | `/api/usage/budget`      | API कीसाठी दैनिक/साप्ताहिक/मासिक USD मर्यादा + चेतावणी थ्रेशोल्ड सेट करा.     |
| `GET`  | `/api/usage/budget/bulk` | सर्व API कीजसाठी बल्क बजेट सारांश.                                            |

> बजेट API ची व्याप्ती प्रति-**API की** (`apiKeyId`) आहे. `GET /api/usage/budget`
> द्वारे परत केलेल्या मर्यादांमध्ये `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`,
> `warningThreshold` आणि चालू एकूण रकमा (`totalCostToday`, `totalCostMonth`, …) समाविष्ट आहेत.

### किंमत निर्धारण

| पद्धत    | एंडपॉइंट                | उद्देश                                                                                                               |
| -------- | ----------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/pricing`          | सध्याची एकत्रित किंमत (वापरकर्ता + सिंक केलेली + डीफॉल्ट्स). प्रत्येक नोंदीचा स्रोत पाहण्यासाठी `?includeSources=1`. |
| `PATCH`  | `/api/pricing`          | `{ provider: { model: { input, output, cached, … } } }` साठी किंमत ओव्हरराइड करा.                                    |
| `DELETE` | `/api/pricing`          | किंमत डीफॉल्ट्सवर रीसेट करा (पर्यायाने `?provider=&model=` द्वारे व्याप्ती निर्धारित करा).                           |
| `GET`    | `/api/pricing/defaults` | डीफॉल्ट प्रति-1M फॉलबॅक दर दाखवा.                                                                                    |
| `GET`    | `/api/pricing/models`   | मॉडेलनुसार की केलेली किंमत.                                                                                          |
| `POST`   | `/api/pricing/sync`     | बाह्य स्रोतांमधून (LiteLLM) मॅन्युअल सिंक ट्रिगर करा.                                                                |
| `GET`    | `/api/pricing/sync`     | सध्याची सिंक स्थिती.                                                                                                 |
| `DELETE` | `/api/pricing/sync`     | सिंक केलेला सर्व किंमत डेटा साफ करा.                                                                                 |

### खर्चाशी संबंधित इतर एंडपॉइंट्स

| पद्धत | एंडपॉइंट                      | उद्देश                                                                      |
| ----- | ----------------------------- | --------------------------------------------------------------------------- |
| `GET` | `/api/free-tier/summary`      | मोफत-मॉडेल टोकनची एकूण संख्या, या महिन्यातील वापर आणि उर्वरित मोफत मर्यादा. |
| `GET` | `/api/quota/pools/[id]/usage` | सामायिक-कोटा पूलचा वापर.                                                    |

## CLI

OmniRoute चे CLI खर्च, वापर आणि किंमत आदेश उपलब्ध करून देते (यांची नोंदणी
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs) मध्ये केली आहे).

### `omniroute cost`

`/api/usage/analytics` मधून एकत्रित केलेला खर्च अहवाल.

```bash
omniroute cost                          # मागील 30d, प्रदात्यानुसार गटबद्ध
omniroute cost --period 7d              # मागील 7 दिवस
omniroute cost --group-by model         # provider | model | combo | api-key | day यानुसार गटबद्ध करा
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

स्तंभ: गट, विनंत्या, इनपुट/आउटपुट टोकन, खर्च (USD) आणि एकूण खर्चाची टक्केवारी. शेवटी
एकूण बेरजेची ओळ दर्शवली जाते (`--quiet` किंवा `--output json` वापरल्यास ती वगळली जाते).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # प्रत्येक प्रदात्याच्या खर्चाचा सारांश
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# बजेट
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show`, `GET /api/pricing/defaults` मधून माहिती वाचते. त्याऐवजी स्वतंत्र मॉडेलच्या
> किंमती संपादित करण्यासाठी **Pricing** डॅशबोर्ड पृष्ठ किंवा `PATCH /api/pricing` वापरा.

## समस्यानिवारण

- **सर्व खर्च $0 / "Legacy / Free" असे दिसतात.** वापरात असलेल्या मॉडेलसाठी किंमतीची नोंद उपलब्ध नाही.
  बाह्य समक्रमण सक्षम करा (`PRICING_SYNC_ENABLED=true`) आणि `omniroute pricing sync` चालवा किंवा
  Pricing पृष्ठ / `PATCH /api/pricing` द्वारे किंमती व्यक्तिचलितपणे सेट करा.
- **ऐतिहासिक मॉडेलची किंमत चुकीची आहे.** किंमत दुरुस्त करा (अधिलिखित करा किंवा पुन्हा समक्रमित करा) — प्रत्येक वेळी विश्लेषण डेटा वाचताना
  टोकन संख्यांवरून खर्चाची पुनर्गणना केली जाते, त्यामुळे अंदाज पूर्वलक्षी प्रभावाने अद्ययावत होतात.
- **खर्चाची माहिती प्रत्यक्ष वेळेपेक्षा उशिराने दिसते.** प्रत्येक कीचा खर्च बॅचमध्ये प्रक्रिया केला जातो; अधिक अद्ययावत आकडे हवे असल्यास
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` चे मूल्य कमी करा.
