**Claude Code** CLI (`claude`) ला OmniRoute कडे निर्देशित करा — स्थानिक किंवा दूरस्थ VPS —
Codex सेटअपप्रमाणे, प्रत्येक मॉडेलसाठी स्वतंत्र प्रोफाइलसह.

---

## झटपट सुरुवात

```bash
# स्थानिक OmniRoute सोबत Claude Code सुरू करा (सक्रिय संदर्भ आपोआप शोधला जातो)
omniroute launch

# दूरस्थ OmniRoute सोबत (`omniroute connect <host>` नंतर, हे स्वयंचलित होते)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# प्रत्येक मॉडेलसाठी प्रोफाइल तयार करा, त्यानंतर त्यापैकी एक सुरू करा
omniroute setup-claude            # ~/.claude/profiles/<name>/settings.json लिहिते
omniroute launch --profile glm52  # OmniRoute द्वारे glm/glm-5.2 वापरणारे Claude Code
```

## Claude Code गेटवेशी कसे कनेक्ट होते

Claude Code **Anthropic Messages API** शी संवाद साधते आणि पर्यावरण चलांद्वारे सानुकूल
एंडपॉइंटकडे निर्देशित केले जाते (त्यात `--base-url` फ्लॅग नाही):

| चल                                           | उद्देश                                                                                          |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `ANTHROPIC_BASE_URL`                         | गेटवेचे मूळ URL (Claude Code त्याला `/v1/messages` जोडते). **`/v1` प्रत्यय देऊ नका.**           |
| `ANTHROPIC_AUTH_TOKEN`                       | `Authorization: Bearer …` म्हणून पाठवले जाते — तुमचा OmniRoute प्रवेश टोकन / API की वापरा       |
| `ANTHROPIC_API_KEY`                          | पर्याय: `x-api-key` म्हणून पाठवले जाते. दोन्ही सेट असल्यास, `ANTHROPIC_AUTH_TOKEN` प्रभावी ठरते |
| `ANTHROPIC_MODEL`                            | विशिष्ट मॉडेल सक्तीने वापरा (`/model` निवडकर्त्याच्या डीफॉल्टला अधिलिखित करते)                  |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` → मूळ `/model` निवडकर्ता `/v1/models` मधील `claude*`/`anthropic*` मॉडेल सूचीबद्ध करतो       |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`              | प्रत्येक प्रतिसादासाठी आउटपुट टोकनची कमाल मर्यादा (उदा. `65536`)                                |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`            | स्वयंचलित संक्षेपणासाठी टोकन मर्यादा                                                            |

> पर्यावरण चल **प्रारंभाच्या वेळी फक्त एकदाच** वाचले जातात — ते बदलल्यानंतर Claude Code रीस्टार्ट करा.

`omniroute launch` हे सर्व तुमच्यासाठी सेट करते: ते सक्रिय संदर्भातून मूळ URL + टोकन
निश्चित करते (त्यामुळे `omniroute connect <vps>` आणि नंतर `omniroute launch`
थेट कार्य करते), सर्व्हरची स्थिती तपासते आणि `claude` कार्यान्वित करते.

## शोध उपनामे — `/model` निवडकर्त्यामध्ये Claude-व्यतिरिक्त मॉडेल दाखवा

Claude Code चे गेटवे मॉडेल शोध वैशिष्ट्य फक्त `claude` किंवा `anthropic` ने सुरू होणारे
आयडी सूचीबद्ध करते, त्यामुळे `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` असताना मूळ
`/model` निवडकर्ता साधारणपणे OmniRoute ची **फक्त** Claude/Anthropic मॉडेल दाखवतो —
`kimi/kimi-k2.6` किंवा `glm/glm-5.2` कधीही दिसत नाही, जरी त्याचे राउटिंग व्यवस्थित होत असले तरीही.

OmniRoute कोणत्याही सक्षम मॉडेलचे (आणि कॉम्बोचे) `claude/…` आयडीखाली प्रतिबिंब तयार करू शकते,
जेणेकरून ते त्या फिल्टरमधून पास होऊन निवडकर्त्यामध्ये दिसेल:

```
kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<कॉम्बो "custo-otimizado"> →  claude/combo/custo-otimizado
```

Claude Code मध्ये तुम्ही यापैकी एखादे निवडता तेव्हा, OmniRoute राउटिंगपूर्वी `claude/` आवरण
काढून मूळ आयडी वापरते — अस्सल `claude/<real-claude-model>` आयडी
(प्रत्यक्ष Claude OAuth प्रदाता) नेहमी जसाच्या तसा ठेवला जातो.

**हे डीफॉल्टनुसार बंद असते** आणि तीन-स्तरीय नियंत्रणाद्वारे व्यवस्थापित केले जाते (सर्वाधिक विशिष्ट
नियंत्रण प्रभावी ठरते), त्यामुळे Claude Code न वापरणाऱ्या क्लायंटसाठी साधे OmniRoute
आपला कॅटलॉग दुप्पट करत नाही:

| स्तर    | स्थान                                                                         |
| ------- | ----------------------------------------------------------------------------- |
| मॉडेल   | प्रदाता तपशील पृष्ठ → प्रत्येक मॉडेलसाठी "Claude Code मध्ये दाखवा" टॉगल       |
| प्रदाता | प्रदाता तपशील पृष्ठ → प्रदाता-स्तरीय टॉगल (त्याची सर्व मॉडेल समाविष्ट)        |
| जागतिक  | सेटिंग्ज → वैशिष्ट्य फ्लॅग → `EXPOSE_CC_DISCOVERY_ALIASES` (डीफॉल्टनुसार बंद) |

`EXPOSE_CC_DISCOVERY_ALIASES` पर्यावरण चल जागतिक स्तर सक्तीने सुरू करते
आणि डॅशबोर्ड अधिलिखनापेक्षा त्याला प्राधान्य मिळते (असे झाल्यास वैशिष्ट्य फ्लॅग स्क्रीनवर
"पर्यावरण चलाद्वारे सक्रिय" अशी नोंद दिसते). प्रत्येक प्रदाता आणि प्रत्येक मॉडेलचे
टॉगल त्यानंतर अधिक नेमके नियंत्रण देतात — उदा. जागतिक स्तर बंद + Kimi प्रदाता सुरू असल्यास
फक्त Kimi ची मॉडेल दाखवली जातात.

> ⚠️ **Claude-व्यतिरिक्त मॉडेलवरील विंडो विसंगती.** Claude Code त्याला न ओळखता येणाऱ्या
> कोणत्याही आयडीसाठी 200K संदर्भ विंडो गृहीत धरते (`/v1/models` मधून प्रत्यक्ष विंडो
> वाचता येत नाही). अधिक मोठी विंडो असलेल्या मॉडेलसाठी (उदा. Kimi K2 ची 256K),
> `CLAUDE_CODE_AUTO_COMPACT_WINDOW` चे मूल्य मॉडेलच्या प्रत्यक्ष विंडोपेक्षा कमी सेट करा,
> जेणेकरून स्वयंचलित संक्षेपण अकाली सुरू होणार नाही. वर तयार केलेली प्रोफाइल हे प्रत्येक
> मॉडेलसाठी आधीपासूनच करतात.

## डॅशबोर्डवरील ऑनबोर्डिंग ब्लॉक

Claude टूल कार्ड (**Dashboard → CLI Code**) या इंस्टन्ससाठीचा अचूक `settings.json` खंड
डिस्कव्हरी-अलियास माहिती बटणाच्या शेजारी, कॉपी बटणासह दाखवते:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}
```

बेस URL हा कार्डने निश्चित केलेला URL असतो (तुम्ही टाइप केलेल्या कस्टम ओव्हरराइडसह), आणि तो आधीच
सामान्यीकृत केलेला असतो — `/v1` प्रत्यय नाही, शेवटी स्लॅश नाही. **की कधीही दाखवली जात नाही**: ब्लॉकमध्ये
प्लेसहोल्डर दिलेला असतो, त्यामुळे स्क्रीनशॉट किंवा पेस्ट केलेल्या स्निपेटमधून की लीक होऊ शकत नाही. त्याऐवजी तुमची की पेस्ट करा.

ज्या मॉडेलची वास्तविक कॉन्टेक्स्ट विंडो 200K नाही, त्यासाठी त्याच `env` ब्लॉकखाली
`CLAUDE_CODE_AUTO_COMPACT_WINDOW` जोडा — Claude Code त्याला न ओळखता येणाऱ्या प्रत्येक id साठी 200K गृहीत धरते, त्यामुळे
अन्यथा ऑटो-कॉम्पॅक्शन चुकीच्या वेळी सुरू होते (मागील विभागातील इशारा पाहा).
स्निपेट बिल्डरदेखील हे मूल्य स्वीकारतो, त्यामुळे लक्ष्य मॉडेलची विंडो माहीत असलेला कॉलर
ते थेट तयार करू शकतो.

स्रोत: `src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet` (शुद्ध
बिल्डर, युनिट-चाचणी केलेला), `ClaudeGatewayOnboardingBlock` द्वारे रेंडर केला जातो.

## प्रोफाइल्स (`CLAUDE_CONFIG_DIR`)

Claude Code मध्ये **मूळ प्रोफाइल फाइल्स नाहीत** (Codex च्या `~/.codex/<name>.config.toml` पेक्षा वेगळे).
प्रचलित यंत्रणा म्हणजे `CLAUDE_CONFIG_DIR` — प्रत्येक प्रोफाइलसाठी स्वतंत्र कॉन्फिगरेशन डायरेक्टरी,
आणि प्रत्येकामध्ये त्याची स्वतःची `settings.json`, क्रेडेन्शियल्स, इतिहास आणि कॅश असते.

`omniroute setup-claude` लाइव्ह `/v1/models` कॅटलॉग मिळवते आणि
`~/.claude/profiles/<name>/settings.json` येथे प्रत्येक मॉडेलसाठी एक प्रोफाइल लिहिते, तसेच
**`setup-codex` मधील तीच नावे** (`glm52`, `kimi-k27`, `deepseek-pro`, …) पुन्हा वापरते:

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}
```

> **ऑथ टोकन प्रोफाइलमध्ये कधीही लिहिले जात नाही.** `omniroute launch --profile <name>` वापरून
> लाँच करा (ते सक्रिय कॉन्टेक्स्टमधून `ANTHROPIC_AUTH_TOKEN` अंतर्भूत करते), किंवा स्वतः
> `ANTHROPIC_AUTH_TOKEN` एक्सपोर्ट करा आणि `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude` चालवा.

**मॉडेल डिस्कव्हरीनंतर ऑटो-सिंक (निवड केल्यास).** प्रोव्हायडर मॉडेल
सिंकमुळे लाइव्ह कॅटलॉग बदलल्यावर OmniRoute याच `~/.claude/profiles/<name>/settings.json`
फाइल्स आपोआप पुन्हा तयार करू शकते — त्यामुळे कमांड पुन्हा न चालवता नवीन/पुनर्नामित मॉडेल्ससाठी प्रोफाइल्स तयार होतात.
हे **डीफॉल्टनुसार बंद असते**: ते **CLI Code डॅशबोर्ड** वरून टॉगल करा ("CLI profile
auto-sync" → Claude Code), किंवा `OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true` सेट करा (ते
`CLI_ALLOW_CONFIG_WRITES` चाही आदर करते, जे डीफॉल्टनुसार सुरू असते). सक्षम केल्यावर ते फक्त प्रोफाइल फाइल्स लिहिते; ते कधीही
तुमचे सक्रिय/डीफॉल्ट Claude कॉन्फिगरेशन, ऑथ किंवा `~/.claude/settings.json` बदलत नाही.

### प्रोफाइल्स तयार करणे + वापरणे

```bash
# स्थानिक OmniRoute
omniroute setup-claude

# रिमोट VPS (प्रत्येक प्रोफाइलमध्ये VPS URL समाविष्ट करते)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# फक्त काही प्रोव्हायडर्स
omniroute setup-claude --only glm,kimi

# न लिहिता पूर्वावलोकन
omniroute setup-claude --dry-run

# प्रोफाइल लाँच करा
omniroute launch --profile kimi-k27
```

## मॉडेल स्तर (पर्यायी)

Claude Code क्षमतेच्या स्तरांकडे विनंत्या रूट करते. प्रत्येक स्तरासाठी वेगळे प्रदाते हवे असल्यास env /
सेटिंग्जद्वारे तो OmniRoute मॉडेलशी मॅप करा:

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm/glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="kmc/kimi-k2.6"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="glm/glm-4.7-flash"
```

अन्यथा सर्व गोष्टींसाठी एकच `ANTHROPIC_MODEL` (जो प्रोफाइलद्वारे सेट केला जातो) वापरला जातो.

## रिमोट मोड

तुम्ही `omniroute connect <host>` चालवल्यानंतर ([रिमोट मोड](./REMOTE-MODE.md) पहा),
`omniroute launch` आणि `omniroute setup-claude` आपोआप त्या रिमोट सर्व्हरला
लक्ष्य करतात आणि त्याचे स्कोप केलेले ॲक्सेस टोकन वापरतात — अतिरिक्त फ्लॅगची
गरज नाही. प्रत्येक आवाहनासाठी `--remote` / `--api-key` वापरून हे अधिलिखित करा.

## समस्या निवारण

**Claude Code गेटवेकडे दुर्लक्ष करते** — `ANTHROPIC_BASE_URL` मध्ये **`/v1`
नाही** याची खात्री करा आणि `claude` रीस्टार्ट करा (env स्टार्टअपवेळी एकदाच वाचले जाते). `omniroute launch`
हे तुमच्यासाठी हाताळते.

**`/model` निवडक रिकामा आहे / गेटवे मॉडेल्स दिसत नाहीत** — Claude Code
v2.1.219+ आणि `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` आवश्यक आहेत. निवडकमध्ये फक्त `claude*` /
`anthropic*` मॉडेल IDs दिसतात; इतर कोणतेही मॉडेल वापरणे सक्तीचे करण्यासाठी
`ANTHROPIC_MODEL=<id>` वापरा (प्रोफाइल्स हेच करतात).

**`400 Ambiguous model 'claude-…'`** — Claude Code नेहमी **उपसर्ग नसलेले**
मॉडेल IDs (उदा. `claude-opus-4-8`) पाठवते, त्यामुळे Claude Code (`cc/…`) आणि
Claude (`claude/…`) हे दोन्ही प्रदाते कनेक्ट केलेले असताना, साधा id दोन रूट्सशी जुळतो आणि
OmniRoute अंदाज लावण्यास नकार देते. यापैकी कोणत्याही प्रकारे ते दुरुस्त करा: उपसर्ग असलेला id
`ANTHROPIC_MODEL=cc/claude-opus-4-8` वापरून पिन करा, किंवा **उपसर्ग नसलेल्या Claude मॉडेल्ससाठी Claude Code ला
प्राधान्य द्या** सक्षम करा — Claude प्रदाता पृष्ठावरील टॉगल, किंवा
`OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true` (डीफॉल्टनुसार बंद;
[पर्यावरण](../reference/ENVIRONMENT.md) पहा) — यामुळे साधे `claude-*`
IDs त्याऐवजी Claude Code कडे रूट केले जातात. स्पष्ट प्रदाता उपसर्गांना नेहमीच प्राधान्य मिळते.

**प्रमाणीकरण त्रुटी** — प्रोफाइलमध्ये कोणतेही टोकन नसते. `omniroute launch --profile`
वापरा (ते टोकन अंतःक्षेपित करते) किंवा `ANTHROPIC_AUTH_TOKEN` एक्सपोर्ट करा.

**प्रोफाइल्स विलगीकरण करत नाहीत** — प्रत्येक प्रोफाइल एक स्वतंत्र `CLAUDE_CONFIG_DIR` आहे;
सत्रामध्ये `echo $CLAUDE_CONFIG_DIR` चालवून ते
`~/.claude/profiles/<name>` कडे निर्देश करत असल्याची खात्री करा.
