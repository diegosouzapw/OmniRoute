OmniRoute हे OpenAI Codex वापरण्याचे **दोन** मार्ग उपलब्ध करून देते:

| प्रदाता                | ते OpenAI शी कसे संवाद साधते                                                                                                                                                                      | वापरासंबंधी सूचना                                             |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| **`codex`**            | तुमचे ChatGPT/OpenAI OAuth टोकन थेट Responses API कडे पुन्हा पाठवते                                                                                                                               | **होय** — अधिकृत सत्राला proxy/router वापरासाठी अधिकृतता नाही |
| **`codex-app-server`** | JSON-RPC/WebSocket वरून **Codex CLI चे स्वतःचे `codex app-server`** चालवते; परस्परसंवादी `codex` सत्राप्रमाणेच CLI स्वतःच्या OAuth ची (`~/.codex/auth.json`) मालकी घेते आणि ते स्वतः रीफ्रेश करते | **नाही** — OmniRoute कधीही API कडे टोकन पुन्हा पाठवत नाही     |

`codex-app-server` कधीही टोकन पुन्हा पाठवत नसल्यामुळे, त्याला
सत्र-पुनर्प्रेषणाच्या वापरासंबंधी सूचना लागू होत नाही. मात्र, **कॉन्फिगर केलेल्या
app-server URL वर उपलब्ध असलेले Codex CLI** आवश्यक आहे आणि त्या CLI मध्ये
**साइन इन केलेले** असणे आवश्यक आहे.

---

## 1. आर्किटेक्चर

```
┌─ OmniRoute ॲप ──────────────────┐        ┌─ codex-app-server साइडकार ─────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ क्षमता टोकन)                 │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  OpenAI OAuth स्वतः व्यवस्थापित करते │
└──────────────────────────────────┘        │  (~/.codex/auth.json, स्वयं-रीफ्रेश) │
        │ शेअर करते (compose volumes)       └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → WS क्षमता टोकन (दोन्ही ते माउंट करतात)
  codex-appserver-home    → ~/.codex (dashboard द्वारे लिहिलेले auth.json,
                             साइडकारच्या codex app-server द्वारे वाचले जाते)
```

- साइडकार क्षमता टोकनमागील अंतर्गत compose नेटवर्कवर
  (`ws://codex-app-server:1456`) **फक्त** ऐकते. ते होस्ट किंवा इंटरनेटवर
  **कधीही** प्रकाशित केले जात नाही.
- Codex CLI हे `omniroute:base` मध्येच समाविष्ट केलेले असल्यामुळे, साइडकार
  चालवताना होस्टवर किंवा वापरकर्त्याच्या मशीनवर codex इंस्टॉल करण्याची गरज नाही.

## 2. ते सुरू करा

```bash
# codex app-server साइडकार प्रोफाइलसह स्टॅक सुरू करा:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

पहिल्यांदा बूट होताना साइडकार स्वतःचे WS क्षमता टोकन तयार करते (शेअर केलेल्या
`codex-appserver-token` volume मध्ये) आणि ॲप तेच टोकन
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE` द्वारे वाचते. टोकनची हाताने जोडणी
करण्याची गरज नाही.

## 3. कनेक्ट करा + साइन इन करा

1. dashboard मध्ये **OpenAI Codex (App-Server)** साठी कनेक्शन जोडा. कोणतीही API
   key किंवा token आवश्यक नाही (हा no-auth प्रदाता आहे — प्रमाणीकरणाची मालकी
   साइडकारकडे असते).
2. साइडकारच्या Codex CLI मध्ये **अद्याप साइन इन केलेले नसल्यास**, कनेक्शनची
   स्थिती तपासणी _"चालू आहे, परंतु साइन इन केलेले नाही"_ असे दर्शवते (लाल
   प्रमाणीकरण त्रुटी नव्हे). **ChatGPT सह साइन इन करा** वापरा: हे तुमच्या
   browser मध्ये मानक Codex device-OAuth चालवते आणि नंतर **Apply auth** द्वारे
   शेअर केलेल्या volume मध्ये `~/.codex/auth.json` लिहिते (एकाच login द्वारे
   `codex` आणि `codex-app-server` हे दोन्ही प्रदाते वापरता येतात).
3. साइन इन केल्यानंतर स्थिती तपासणी हिरवी होते (ती `/readyz` **आणि**
   `account/read` या दोन्हींची पडताळणी करते — म्हणजे सेवा चालू _आणि_
   प्रमाणीकृत आहे) आणि कार्य सुरू होते.

dashboard निरोगी आणि आधीपासून अस्तित्वात असलेली `~/.codex/auth.json` फाइल
कधीही अधिलिखित करत नाही — फाइल अनुपस्थित असेल किंवा तिचे token कालबाह्य झाले
असेल, तेव्हाच ती लिहिली जाते (नेहमी backup घेतला जातो).

## 4. डिप्लॉयमेंट परिस्थिती

- **आधीपासून प्रमाणीकृत Codex CLI असलेला ऑपरेटर** — तुमच्या होस्टवरील
  `~/.codex` साइडकारमध्ये (`codex-appserver-home`) माउंट करा आणि साइन-इनची
  पायरी वगळा.
- **सार्वजनिक वापरकर्ता, स्थानिकरीत्या codex इंस्टॉल केलेले नाही** — त्याचा
  संबंध नाही: साइडकारमध्ये CLI आहे. वापरकर्ता फक्त dashboard द्वारे प्रमाणीकरण
  करतो.
- **Bare-metal OmniRoute (साइडकार नाही, होस्टवरील codex)** — तुमच्या स्वतःच्या
  `codex app-server` कडे `OMNIROUTE_CODEX_APPSERVER_WS` निर्देशित करा आणि
  होस्टवरील codex मध्ये साइन इन केलेले असल्याची खात्री करा; binary उपलब्ध
  नसल्यास "codex इंस्टॉल केलेले नाही" ही सूचना दिसते.

## 5. निवासी / UDP निर्गमन (ऑपरेटरसाठी अतिरिक्त, वितरणात समाविष्ट नाही)

वरील सर्वसाधारण साइडकार container च्या सामान्य नेटवर्कवरून निर्गमन करते.
Codex traffic **निवासी exit** द्वारे (उदा. TCP + UDP/QUIC वाहून नेणारा TUN
tailscale साइडकार) बाहेर पाठवण्याची आवश्यकता असलेला ऑपरेटर ते स्वतंत्र compose
override म्हणून चालवतो; ते हेतुपुरस्सर वितरित केलेल्या `codex-app-server`
प्रोफाइलचा भाग **नाही**. त्या सेटअपसाठी अंतर्गत operations runbook पहा.
