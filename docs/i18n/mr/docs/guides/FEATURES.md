## 🔌 प्रदाते

AI प्रदाता कनेक्शन्स व्यवस्थापित करा: OAuth प्रदाते (Claude Code, Codex), API की प्रदाते (Groq, DeepSeek, OpenRouter), आणि विनामूल्य प्रदाते (Qoder, Kiro). Kiro खात्यांमध्ये क्रेडिट शिल्लक ट्रॅकिंग समाविष्ट आहे — उर्वरित क्रेडिट्स, एकूण मंजूर मर्यादा आणि नूतनीकरणाची तारीख Dashboard → Usage मध्ये दिसते.

OpenRouter कनेक्शन्स Advanced Settings मध्ये प्रत्येक कनेक्शनसाठी स्वतंत्र `preset` संग्रहित करू शकतात. तो सेट केलेला असल्यास, क्लायंटच्या विनंतीने स्वतःचा `preset` आधीच दिलेला नसेल तर OmniRoute तो OpenRouter च्या शीर्ष-स्तरीय विनंती फील्डच्या स्वरूपात पाठवते, उदाहरणार्थ `"preset": "email-copywriter"`.

## 🎨 कॉम्बोज

19 सार्वजनिक धोरणांसह मॉडेल राउटिंग कॉम्बोज तयार करा: priority, weighted, round-robin, context-relay, fill-first, p2c (power-of-two choices), random, least-used, cost-optimized, reset-aware, reset-window, headroom, strict-random, auto, lkgp (last-known-good-provider), context-optimized, cache-optimized, **fusion** (मॉडेल्सच्या पॅनेलकडे समांतरपणे विनंत्या पाठवून, त्यानंतर एका निर्णायक मॉडेलद्वारे एकच उत्तर संश्लेषित करणे), आणि **pipeline**. प्रत्येक कॉम्बो स्वयंचलित फॉलबॅकसह अनेक मॉडेल्सची साखळी तयार करतो आणि त्यामध्ये झटपट टेम्पलेट्स व तत्परता तपासण्या समाविष्ट असतात.

कॉम्बोमधील अलीकडील सुधारणा:

- **संरचित कॉम्बो बिल्डर** — प्रदाता, मॉडेल आणि नेमके खाते/कनेक्शन निवडून प्रत्येक पायरी तयार करा
- **प्रदाता पुनर्वापरासाठी समर्थन** — `(provider, model, connection)` ट्युपल अद्वितीय असेपर्यंत एकाच कॉम्बोमध्ये तोच प्रदाता अनेकदा पुन्हा वापरा
- **कॉम्बो लक्ष्याचे आरोग्य** — आता विश्लेषण आणि आरोग्य पृष्ठभाग सर्वकाही मॉडेल स्ट्रिंग्समध्ये एकत्रित करण्याऐवजी स्वतंत्र कॉम्बो लक्ष्ये/पायऱ्या वेगळ्या ओळखतात
- **संमिश्र टियर क्रमवारी** — आता `defaultTier -> fallbackTier` शीर्ष-स्तरीय कॉम्बो पायऱ्यांसाठी रनटाइम अंमलबजावणी/फॉलबॅक क्रमावर प्रभाव टाकते
- **सिस्टम प्रॉम्प्ट टेम्पलेट्स** — कॉम्बो `system_message` सर्व्हर-साइड
  `{{MODEL_ID}}`, `{{PROVIDER_ID}}`, `{{ACCOUNT}}` आणि `{{FINGERPRINT}}`
  प्लेसहोल्डर्सना समर्थन देते; डिस्पॅचच्या अगदी आधी प्रत्यक्षात रूट केलेल्या लक्ष्यापासून त्यांचा विस्तार केला जातो.
  हे अनुमत-सूचीबद्ध आणि पुनरावर्ती नसतात; अज्ञात प्लेसहोल्डर्स अक्षरशः तसेच राहतात; रिक्त मूल्यांचा
  विस्तार रिक्त स्वरूपात होतो; क्लायंट सिस्टम प्रॉम्प्ट्स कधीही पुन्हा लिहिले जात नाहीत. `{{FINGERPRINT}}`
  फक्त पिन केलेला किंवा स्वयंचलितपणे रोटेट केलेला फिंगरप्रिंट असलेल्या फिंगरप्रिंट-आधारित विनामूल्य प्रदात्यांसाठीच
  रिझॉल्व्ह होतो — इतर ठिकाणी त्याचा विस्तार रिक्त स्वरूपात होतो (उदा.
  एकल-फिंगरप्रिंट कनेक्शन्स, non-fp प्रदाते). विस्तारामध्ये
  मानक डिस्पॅच लूप, round-robin आणि पिन केलेली context-cache सत्रे समाविष्ट आहेत;
  fusion, chaos, pipeline आणि nested-execute धोरणे अद्याप
  प्लेसहोल्डर्सचा विस्तार करत नाहीत.

## 🗜️ प्रॉम्प्ट संक्षेपण _(v3.7.9+)_

Context & Cache आता Caveman, RTK आणि Compression Combos साठी समर्पित पृष्ठे उपलब्ध करून देते:

- **Caveman** — भाषेची जाणीव असलेले नियम-संच, पूर्वावलोकन, आउटपुट-मोड नियंत्रणे आणि विश्लेषण
- **RTK** — shell, git, test, build, package, Docker, infra, JSON आणि स्टॅक-ट्रेस आउटपुटसाठी कमांडची जाणीव असलेले संक्षेपण
- **Compression Combos** — राउटिंग कॉम्बोंना नियुक्त केलेल्या `rtk -> caveman` सारख्या नामांकित पाइपलाइन; दोन्ही इंजिने लागू झाल्यास डीफॉल्ट स्टॅक्ड गणनेद्वारे सरासरी `~89%` आणि पात्र-संदर्भामध्ये `78-95%` बचत मिळते
- **कच्च्या आउटपुटची पुनर्प्राप्ती** — संक्षेपित अपयश डीबग करण्यासाठी वैकल्पिकरित्या संवेदनशील माहिती काढून टाकलेले RTK कच्च्या-आउटपुटचे पॉइंटर

[संक्षेपण मार्गदर्शिका](../compression/COMPRESSION_GUIDE.md), [RTK संक्षेपण](../compression/RTK_COMPRESSION.md) आणि
[संक्षेपण इंजिने](../compression/COMPRESSION_ENGINES.md) पहा.

## 🖥️ Desktop Application

Windows, macOS आणि Linux साठी native Electron desktop app. System tray integration, offline support, auto-update आणि one-click install सह OmniRoute स्वतंत्र application म्हणून चालवा.

प्रमुख वैशिष्ट्ये:

- Server readiness polling (cold start वेळी रिकामी screen दिसत नाही)
- Port management सह system tray
- Content Security Policy
- Single-instance lock
- Restart केल्यावर auto-update
- Platform-conditional UI (macOS traffic lights, Windows/Linux default titlebar)
- अधिक सुरक्षित Electron build packaging — standalone bundle मधील symlink केलेले `node_modules` packaging करण्यापूर्वी शोधून नाकारले जाते, ज्यामुळे build machine वरील runtime dependency टाळली जाते (v2.5.5+)
- **सुरळीत shutdown** — Electron `before-quit`, Next.js स्वच्छपणे बंद करते आणि SQLite WAL database locks टाळते (v3.6.2+)

📖 संपूर्ण दस्तऐवजीकरणासाठी [`electron/README.md`](../../electron/README.md) पहा.

## 🌐 V1 WebSocket Bridge _(v3.6.6+)_

OmniRoute आता `/v1/ws` upgrade endpoint द्वारे **OpenAI-सुसंगत WebSocket clients** ना समर्थन देते. सानुकूल `scripts/dev/v1-ws-bridge.mjs` server, Next.js ला wrap करतो आणि WS connections ना पूर्ण द्विदिशात्मक streaming sessions मध्ये upgrade करतो. Authentication साठी HTTP requests प्रमाणेच API key किंवा session cookie वापरली जाते.

प्रमुख वर्तन:

- Connection प्रस्थापित होण्यापूर्वी `src/lib/ws/handshake.ts` द्वारे WS upgrade प्रमाणित केले जाते
- Session बंद झाल्यावर किंवा upstream error आल्यास streams स्वच्छपणे समाप्त केले जातात
- विद्यमान HTTP+SSE streaming path सोबत एकाच वेळी कार्य करते

## 🔑 सिंक टोकन आणि कॉन्फिग बंडल _(v3.6.6+)_

आता **व्याप्ती-निर्धारित सिंक टोकन** वापरून एकाधिक उपकरणांवरून आणि बाह्य ऑपरेटरना प्रवेश देणे शक्य आहे:

- **`POST /api/sync/tokens`** — नवीन सिंक टोकन जारी करा (व्याप्ती-निर्धारित, पर्यायी कालबाह्यतेसह)
- **`DELETE /api/sync/tokens/:id`** — टोकन रद्द करा
- **`GET /api/sync/bundle`** — सर्व असंवेदनशील सेटिंग्जचा आवृत्तीकृत, ETag-कळयुक्त JSON स्नॅपशॉट डाउनलोड करा (पासवर्ड लपवलेले)

कॉन्फिग बंडल `src/lib/sync/bundle.ts` द्वारे तयार केले जाते. संपूर्ण पेलोड पुन्हा डाउनलोड न करता बदल ओळखण्यासाठी ग्राहक `ETag` प्रतिसाद हेडरची तुलना करतात.

## 🛡️ सुरक्षित आउटबाउंड फेच आणि SSRF गार्ड _(v3.6.6+)_

प्रदात्याचे सर्व प्रमाणीकरण आणि मॉडेल शोध कॉल आता द्विस्तरीय आउटबाउंड गार्डमधून जातात:

1. **URL गार्ड** (`src/shared/network/outboundUrlGuard.ts`) — सॉकेट उघडण्यापूर्वी खाजगी/लूपबॅक/लिंक-लोकल IP श्रेणी अवरोधित करतो.
2. **सुरक्षित फेच रॅपर** (`src/shared/network/safeOutboundFetch.ts`) — URL गार्ड लागू करतो, टाइमआउट प्रमाणित करतो आणि तात्पुरत्या त्रुटींनंतर एक्स्पोनेन्शियल बॅकऑफसह पुन्हा प्रयत्न करतो.

गार्ड उल्लंघने HTTP 422 (`URL_GUARD_BLOCKED`) म्हणून दर्शवली जातात आणि `providerAudit.ts` द्वारे अनुपालन ऑडिट लॉगमध्ये लिहिली जातात.

## 🔄 कूलडाउन-जागरूक पुनर्प्रयत्न _(v3.6.6+)_

अपस्ट्रीम प्रदात्याने मॉडेल-व्याप्त कूलडाउन परत केल्यास चॅट विनंत्या आता **आपोआप पुन्हा प्रयत्न करतात**. हे `REQUEST_RETRY` (डीफॉल्ट: 2) आणि `MAX_RETRY_INTERVAL_SEC` (डीफॉल्ट: 30 s) द्वारे कॉन्फिगर करता येते. `x-ratelimit-reset-requests`, `x-ratelimit-reset-tokens` आणि `Retry-After` मध्ये दर-मर्यादा हेडरचे आकलन सुधारले आहे — प्रत्येक मॉडेलची कूलडाउन स्थिती Resilience डॅशबोर्डमध्ये दृश्यमान आहे.
