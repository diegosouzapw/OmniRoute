> **थोडक्यात**: OmniRoute त्याच्या **विनामूल्य** प्रदात्यांना मॉडेलच्या गुणवत्तेनुसार **Arena AI
> (LMArena-शैलीतील) ELO गुणांचा** वापर करून क्रमवारी देतो. तुमच्या कामासाठी कोणते विनामूल्य प्रदाते
> सर्वात सक्षम मॉडेल्स देतात हे पाहण्यासाठी डॅशबोर्डमधील **विनामूल्य प्रदाता क्रमवारी** पृष्ठ उघडा —
> एकूण क्रमवारी किंवा श्रेणीनुसार फिल्टर केलेली क्रमवारी (कोडिंग, पुनरावलोकन, दस्तऐवजीकरण, डीबगिंग).

## हे काय आहे

OmniRoute 329 प्रदात्यांची नोंदणी करतो, ज्यामध्ये **विनामूल्य/प्रमाणीकरणाची आवश्यकता नसलेले** म्हणून चिन्हांकित केलेल्या 155 कॅटलॉग नोंदींचा समावेश आहे
(प्रमाणीकरणाची आवश्यकता नसलेले,
विनामूल्य-स्तर OAuth किंवा विनामूल्य-स्तर API की —
[विनामूल्य स्तर मार्गदर्शक](../getting-started/FREE-TIERS-GUIDE.md) आणि संपूर्ण
[विनामूल्य स्तर निर्देशिका](../reference/FREE_TIERS.md) पाहा). अडचण अशी आहे: विनामूल्य प्रदात्यांच्या
मॉडेल गुणवत्तेत प्रचंड फरक असतो. आघाडीचे मॉडेल पुरवणारा प्रमाणीकरणाची आवश्यकता नसलेला प्रदाता
लहान जुने मॉडेल पुरवणाऱ्या प्रदात्यापेक्षा कितीतरी अधिक उपयुक्त असतो.

**विनामूल्य प्रदाता क्रमवारी** प्रत्येक विनामूल्य प्रदात्याचा कॅटलॉग **Arena AI क्रमवारी फलकावरील**
**समुदायाकडून मिळवलेल्या गुणवत्ता गुणांशी** जोडून "**कोणता विनामूल्य प्रदाता मला सर्वोत्तम मॉडेल देतो?**"
या प्रश्नाचे उत्तर देते (मानवी पसंतीवर आधारित ELO, म्हणजेच LMArena
चॅटबॉट अरीनामागील तीच संकल्पना). त्यानंतर प्रदात्यांना त्यांच्या **सर्वोत्तम विनामूल्य मॉडेलच्या**
क्षमतेनुसार क्रमवारी दिली जाते.

ही क्रमवारी तीन वास्तविक स्रोतांमधून मोजली जाते:

1. विनामूल्य प्रदात्यांच्या याद्या — `NOAUTH_PROVIDERS`, तसेच `hasFree` ध्वजांकित केलेल्या
   `OAUTH_PROVIDERS` / `APIKEY_PROVIDERS` नोंदी
   (`src/shared/constants/providers.ts`).
2. प्रदाता रजिस्ट्रीमधील प्रत्येक प्रदात्याचा मॉडेल कॅटलॉग
   (`open-sse/config/providerRegistry.ts`).
3. Arena ELO समक्रमण इंजिनद्वारे (`src/lib/arenaEloSync.ts`)
   `model_intelligence` DB तक्त्यामध्ये साठवलेले ELO-व्युत्पन्न कार्य-अनुरूपता गुण.

जोडणीचे तर्कशास्त्र `src/lib/freeProviderRankings.ts` मध्ये आहे.

## प्रवेश कसा करावा

### डॅशबोर्ड पृष्ठ

डॅशबोर्ड उघडा आणि **खर्च → विनामूल्य प्रदाता क्रमवारी** येथे जा किंवा थेट येथे नेव्हिगेट करा:

```
/dashboard/free-provider-rankings
```

हे पृष्ठ (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) पुढील गोष्टी दाखवते:

- सर्वोच्च क्रमवारीतील विनामूल्य प्रदात्यांचा **शीर्ष-3 पोडियम** (🥇 🥈 🥉).
- पुढील स्तंभांसह संपूर्ण **क्रमवारी तक्ता**: **क्रमांक**, **प्रदाता**, **सर्वोत्तम मॉडेल**,
  **गुण**, **सरासरी गुण**, **मॉडेल्स**, **प्रकार**.
- **श्रेणी फिल्टर बटणे**: _सर्व श्रेण्या_, _डीफॉल्ट_, _कोडिंग_, _पुनरावलोकन_,
  _दस्तऐवजीकरण_, _डीबगिंग_.

प्रत्येक प्रदात्याचा **प्रकार** बॅज तो कशा प्रकारे विनामूल्य आहे हे सांगतो:

| बॅज      | अर्थ                                                      |
| -------- | --------------------------------------------------------- |
| `NOAUTH` | नेहमी विनामूल्य, कोणत्याही क्रेडेन्शियल्सची आवश्यकता नाही |
| `OAUTH`  | विनामूल्य स्तर (`hasFree`) असलेला OAuth प्रदाता           |
| `APIKEY` | विनामूल्य स्तर (`hasFree`) असलेला API-की प्रदाता          |

गुण मूळ संख्यांऐवजी मानवाला सहज समजणाऱ्या लेबलांच्या स्वरूपात (उदा. _सर्वोच्च_, _उत्कृष्ट_, _अतिशय चांगले_,
_चांगले_, _सरासरी_) दाखवले जातात, कारण अंतर्निहित मूल्य ही सापेक्ष क्रमवारी गुणवत्ता आहे,
टक्केवारी नाही.

### API एंडपॉइंट

या पृष्ठाला सार्वजनिक वाचन एंडपॉइंटचा आधार आहे
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

क्वेरी पॅरामीटर्स (Zod वापरून वैध केलेले):

| पॅरामीटर   | प्रकार | डीफॉल्ट       | नोंदी                                                                                              |
| ---------- | ------ | ------------- | -------------------------------------------------------------------------------------------------- |
| `category` | string | (काहीही नाही) | `default`, `coding`, `review`, `documentation`, `debugging` यांपैकी एक. एकत्रित क्रमवारीसाठी वगळा. |
| `limit`    | number | `50`          | `1–100` या मर्यादेत सीमित केले जाते.                                                               |

प्रतिसादाची रचना:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` हे मूळ Arena ELO मूल्य आहे; `score` हे सामान्यीकृत कार्य-अनुरूपता मूल्य आहे
(खाली पाहा). गुण दिलेली मॉडेल्स नसलेले प्रदाते प्रतिसादातून वगळले जातात.

## स्कोअर कसे कार्य करतात

### स्रोत: Arena AI लीडरबोर्ड

Arena ELO सिंक इंजिन (`src/lib/arenaEloSync.ts`) Arena AI लीडरबोर्ड API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) वरून दोन लीडरबोर्ड — `text`
आणि `code` — प्राप्त करते. प्रत्येक लीडरबोर्ड नोंदीमध्ये मॉडेलचे नाव, विक्रेता, ELO `score`, विश्वास अंतराल आणि मतांची संख्या असते.

लीडरबोर्ड श्रेणी OmniRoute कार्य श्रेणींशी अशा प्रकारे जुळतात:

| Arena लीडरबोर्ड | OmniRoute कार्य श्रेणी                            |
| --------------- | ------------------------------------------------- |
| `text`          | `default`, `review`, `documentation`, `debugging` |
| `code`          | `coding`                                          |

### सामान्यीकरण (कार्य-अनुरूपता स्कोअर)

कच्चे ELO स्कोअर प्रत्येक लीडरबोर्डसाठी **`[0.4, 0.98]` मधील कार्य-अनुरूपता मूल्यात** सामान्यीकृत केले जातात:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

स्कोअर कधीही `0` किंवा `1` पर्यंत पोहोचत नाही, ज्यामुळे वापरकर्त्याने केलेल्या अधिलिखनांसाठी अतिरिक्त वाव राहतो. API प्रतिसादात दिसणारे `score` फील्ड आणि डॅशबोर्डवर दाखवलेले लेबल हेच आहे.

### विश्वास पातळी

Arena मतांच्या संख्येनुसार प्रत्येक नोंदीला एक विश्वास पातळी दिली जाते:

| विश्वास पातळी | मते     |
| ------------- | ------- |
| `high`        | ≥ 5,000 |
| `medium`      | ≥ 1,000 |
| `low`         | < 1,000 |

### संचयन आणि ताजेपणा

सामान्यीकृत नोंदी `source = "arena_elo"` सह `model_intelligence` DB तक्त्यात लिहिल्या जातात (`src/lib/db/modelIntelligence.ts`). नोंदींची मुदत **7 दिवसांनंतर संपते**, त्यामुळे सिंक करणे थांबवणारा प्रदाता कालबाह्य डेटा पुरवण्याऐवजी कालांतराने यादीतून वगळला जातो.

सिंक **डीफॉल्टनुसार सुरू** असते:

- ते सर्व्हर सुरू होताना एकदा आणि त्यानंतर नियतकालिक टाइमरवर चालते
  (`src/lib/arenaEloSync.ts`, `src/instrumentation-node.ts` मधून जोडलेले).
- ते **नॉन-ब्लॉकिंग असून कधीही घातक ठरत नाही** — अपस्ट्रीम फेच अयशस्वी झाल्यास, OmniRoute चालू राहते आणि क्रमवारीमध्ये फक्त शेवटचा योग्य डेटा (किंवा रिकामी स्थिती) दाखवला जातो.

दोन पर्यावरण चल त्याचे नियंत्रण करतात ([`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md) मध्ये दस्तऐवजीकृत):

| चल                        | डीफॉल्ट       | उद्देश                                                 |
| ------------------------- | ------------- | ------------------------------------------------------ |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | आउटबाउंड सिंकमधून बाहेर पडण्यासाठी `false` वर सेट करा. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | सिंक मध्यांतर, सेकंदांमध्ये.                           |

### मॅन्युअल सिंक / स्थिती / साफ करणे

ऑपरेटरसाठी, प्रमाणीकरण केलेला व्यवस्थापन एंडपॉइंट मॅन्युअल नियंत्रण उपलब्ध करून देतो (`src/app/api/intelligence/sync/route.ts` — व्यवस्थापन प्रमाणीकरण आवश्यक):

```
GET    /api/intelligence/sync          # सध्याची सिंक स्थिती (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # मॅन्युअल सिंक ट्रिगर करा; न लिहिता पूर्वावलोकन करण्यासाठी बॉडी: { "dryRun": true }
DELETE /api/intelligence/sync          # सिंक केलेल्या सर्व arena_elo इंटेलिजन्स नोंदी साफ करा
```

क्रमवारी पृष्ठ रिकामे असल्यास, मॅन्युअल `POST /api/intelligence/sync` (किंवा फक्त सर्व्हर रीस्टार्ट करणे) ते पुन्हा भरते.

### मॉडेल्सना लीडरबोर्डशी जुळवणे

रेजिस्ट्रीमधील मॉडेल IDs आणि Arena मॉडेलची नावे नेहमी तंतोतंत जुळत नाहीत. क्रमवारीमध्ये लवचिक जुळणी वापरली जाते (`src/lib/freeProviderRankings.ts` मधील `findMatchingIntelligence`):

1. सामान्यीकृत मॉडेल ID वर तंतोतंत जुळणी.
2. शेवटचा आवृत्ती प्रत्यय काढल्यानंतर जुळणी (उदा. `kimi-k2.6` → `kimi-k2`).
3. उपसर्ग जुळणी (लीडरबोर्डवरील मॉडेलचे नाव रेजिस्ट्री ID चा उपसर्ग असतो).

सिंकच्या बाजूला, ज्ञात विक्रेता उपसर्ग (`anthropic/`, `openai/`, `google/`, …) काढून टाकले जातात आणि एक लहान उपनाव नकाशा प्रमाणित नावे OmniRoute अंतर्गत वापरत असलेल्या प्रकारांमध्ये विस्तारित करतो, त्यामुळे मॉडेल कोणत्याही नावाखाली शोधता येतात.

### प्रदात्याची क्रमवारी कशी ठरवली जाते

प्रत्येक विनामूल्य प्रदात्यासाठी, इंजिन त्याच्या कॅटलॉगमधील प्रत्येक मॉडेलला स्कोअर देते, त्यानंतर:

- **सर्वोत्तम मॉडेल** = प्रदात्याचे सर्वाधिक स्कोअर असलेले मॉडेल.
- **सरासरी स्कोअर** = त्या प्रदात्याच्या स्कोअर मिळालेल्या सर्व मॉडेल्सच्या स्कोअरची सरासरी.
- **मॉडेल्स** = प्रदात्याच्या किती मॉडेल्सना Arena स्कोअर होता.

प्रदात्यांची क्रमवारी प्रथम **सर्वोत्तम-मॉडेल स्कोअरनुसार**, त्यानंतर सरासरी स्कोअरनुसार लावली जाते. यामुळे किमान एक तरी सक्षम विनामूल्य मॉडेल पुरवणाऱ्या प्रदात्याला प्राधान्य मिळते.

## मोफत प्रदाते निवडण्यासाठी याचा वापर

1. **योग्य श्रेणी निवडा.** एजंटिक/कोड वर्कलोडसाठी **Coding** फिल्टर वापरा किंवा
   सामान्य चॅटसाठी **All Categories** / **Default** निवडलेले राहू द्या. प्रत्येक लीडरबोर्डनुसार
   त्याचे सर्वोत्तम मॉडेल वेगळे असल्यामुळे एकाच प्रदात्याचे स्थान विविध श्रेणींमध्ये
   वेगवेगळे असू शकते.
2. **एकदाच करावयाच्या सेटअपसाठी पोडियमवरील प्रदात्यांना प्राधान्य द्या.** तुम्हाला फक्त एक किंवा दोन मोफत
   प्रदाते जोडायचे असल्यास, तुमच्या श्रेणीतील सर्वोच्च स्थानावरील प्रदात्यांपासून सुरुवात करा.
3. **Type बॅज तपासा.** `NOAUTH` प्रदाते जोडण्यासाठी सर्वात जलद आहेत (कोणतीही
   क्रेडेन्शियल्स आवश्यक नाहीत). `OAUTH` / `APIKEY` मोफत टियरसाठी झटपट साइन-अप करावे लागते, परंतु त्यांमध्ये अनेकदा
   अधिक सक्षम मॉडेल्स उपलब्ध असतात. जोडणीच्या चरणांसाठी [मोफत टियर मार्गदर्शक](../getting-started/FREE-TIERS-GUIDE.md)
   पहा.
4. **अनेक प्रदाते जोडा आणि Auto-Combo ला निर्णय घेऊ द्या.** या पृष्ठाला चालना देणारा हाच Arena ELO डेटा
   Auto-Combo स्कोअरिंग इंजिनच्या **कार्य-योग्यता घटकासाठीही** वापरला जातो
   (`open-sse/services/autoCombo/taskFitness.ts`, निराकरण क्रम
   `user_override → arena_elo → models_dev_tier → static table`). त्यामुळे सर्वोच्च मोफत प्रदाते
   जोडल्यानंतर, `model: "auto"` (उदा. `auto/coding`) सह रूटिंग केल्यास
   प्रत्येक विनंतीसाठी उच्च-गुणवत्तेच्या मोफत मॉडेल्सना आपोआप प्राधान्य दिले जाईल. संपूर्ण 16-घटक स्कोअरिंगसाठी
   [Auto-Combo](../routing/AUTO-COMBO.md) पहा.
