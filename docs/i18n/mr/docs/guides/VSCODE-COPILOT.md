**OmniCopilot** आपल्या OmniRoute द्वारे उपलब्ध करून दिलेले प्रत्येक मॉडेल _मूळ_ GitHub Copilot Chat
मॉडेल निवडकात आणते. दुसरी साइडबार नाही, वेगळा चॅट UI नाही — Copilot चा एजंट मोड, टूल कॉलिंग,
MCP सर्व्हर आणि सानुकूल सूचना हे सर्व पूर्वीप्रमाणेच कार्यरत राहतात; फक्त आपण निवडलेल्या मॉडेलवर चालतात.

> embeddings-आधारित वैशिष्ट्ये प्रदाता API च्या बाहेर राहतात आणि त्यांना अजूनही Copilot आवश्यक आहे.

## सेटअप

1. **OmniRoute चालवा** — `npm install -g omniroute && omniroute` (`http://localhost:20128` वर डॅशबोर्ड).
2. **विस्तार स्थापित करा** — Extensions दृश्यात "OmniRoute" शोधा.
3. **मॉडेल निवडा** — Copilot Chat → मॉडेल निवडक → **Manage Models…** → **OmniRoute**, त्यानंतर
   आपल्याला हवी असलेली मॉडेल निवडा.

OmniRoute डीफॉल्ट पोर्टवर चालत असताना काहीही कॉन्फिगर करण्याची आवश्यकता नाही. दूरस्थ इन्स्टन्ससाठी,
**Activity Bar मधील OmniRoute चिन्ह** उघडा (किंवा `OmniRoute: Manage Connection` चालवा) आणि पुढील गोष्टी सेट करा:

- **सर्व्हर URL** — सर्व्हरचे मूळ, उदा. `http://192.168.0.15:20128`. `/v1` प्रत्यय
  विस्ताराद्वारे जोडला जातो; तो समाविष्ट करू नका.
- **API की** — सर्व्हरने `REQUIRE_API_KEY` सेट केले असेल तेव्हाच. VS Code SecretStorage द्वारे
  OS कीचेनमध्ये संग्रहित केली जाते; `settings.json` मध्ये कधीही नाही.

## निवडकात काय दिसेल

विस्तार कच्चा `GET /v1/models` पेलोड दाखवत नाही — तो त्याला योग्य स्वरूप देतो आणि आपल्याला
दिसणारी संख्या कॅटलॉगच्या आकारापेक्षा कमी असते, यामागे दोन जाणीवपूर्वक कारणे आहेत.

### तो प्रत्येक मॉडेलसाठी एक id मागतो

`MODELS_CATALOG_PREFIX_MODE` चे डीफॉल्ट मूल्य **`dual`** आहे, जे प्रत्येक मॉडेलची दोनदा जाहिरात करते — एकदा
लहान उपनाम उपसर्गाखाली आणि एकदा अधिकृत प्रदाता उपसर्गाखाली — जेणेकरून जुन्या क्लायंट
कॉन्फिगरेशनमध्ये दोन्ही रूपे योग्यरीत्या वापरता येतील:

```
cc/claude-sonnet-4-6        ← उपनाम उपसर्ग
claude/claude-sonnet-4-6    ← अधिकृत उपसर्ग, तेच मॉडेल
```

विस्तार **`GET /v1/models?prefix=alias`** ची विनंती करतो, त्यामुळे आपल्या इतर क्लायंटसाठी
सर्व्हर-व्यापी सेटिंग न बदलता प्रत्येक मॉडेलसाठी एक id मिळतो. संदर्भ इन्स्टन्सवर यामुळे
**2345 नोंदी 1396 पर्यंत कमी झाल्या — 949 डुप्लिकेट, एकही मॉडेल गमावले नाही.**

हे _प्रत्येक_ क्लायंटसाठी सर्व्हर-व्यापी स्तरावर दुरुस्त करायचे असल्यास, डॅशबोर्डमध्ये
`MODELS_CATALOG_PREFIX_MODE` फीचर फ्लॅग `alias` वर सेट करा. क्वेरी पॅरामीटर आणि प्रत्येक मोडच्या
तक्त्यासाठी [API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) पहा.

### चॅट करू न शकणारी मॉडेल तो लपवतो

कॅटलॉगमध्ये प्रतिमा, व्हिडिओ, ऑडिओ, री-रँक, एम्बेडिंग आणि मॉडरेशन मॉडेलही सूचीबद्ध असतात. चॅट
विनंती केल्यास ती कोणत्याही परिस्थितीत नाकारली जातात:

```
HTTP 400 — मॉडेल '<id>' हे प्रतिमा-निर्मिती मॉडेल आहे आणि ते
/v1/chat/completions वर वापरता येत नाही. त्याऐवजी POST /v1/images/generations वापरा.
```

म्हणून निवडकापर्यंत पोहोचण्यापूर्वी ती त्यांच्या `type` फील्डनुसार फिल्टर केली जातात. **Responses-API
मॉडेल कायम ठेवली जातात** — प्रत्येक Codex / GPT-5.x नोंद `supported_endpoints: ["responses"]` ची जाहिरात करते,
आणि OmniRoute त्यांचे `/v1/chat/completions` साठी भाषांतर करते, त्यामुळे ती पूर्णपणे वापरण्यायोग्य आहेत.

### आपण कधीही कॉन्फिगर न केलेले प्रदाते

कॅटलॉगमध्ये **सक्रिय कनेक्शन** असलेल्या प्रदात्यांची मॉडेल _तसेच_ प्रत्येक **noAuth**
प्रदात्याची मॉडेल सूचीबद्ध केली जातात — हे कीविरहित प्रदाते विनामूल्य स्तराचा मोठा भाग बनवतात. हे जाणीवपूर्वक केलेले आहे. त्यांना
लपवण्यासाठी, डॅशबोर्ड सेटिंग्जमधील `blockedProviders` मध्ये त्यांना जोडा; विस्तारात
काहीही बदलत नाही.

## VS Code टॅबमधील Dashboard

`omnicopilot.dashboardOpen: "editor"` बाह्य ब्राउझरऐवजी Simple Browser द्वारे OmniRoute dashboard एडिटर टॅबमध्ये रेंडर करते. एम्बेडिंग हे सर्व्हरवर `DASHBOARD_ALLOW_EMBED=vscode` द्वारे **निवडून सक्षम करावे लागते**, ज्यामुळे HTML पृष्ठे डीफॉल्ट `frame-ancestors 'none'` + `X-Frame-Options: DENY` ऐवजी `frame-ancestors 'self' vscode-webview:` सह सर्व्ह केली जातात. API पृष्ठभाग (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) दोन्ही परिस्थितींमध्ये कठोर हेडर्स कायम ठेवतो.

> ⚠️ **हा build-time फ्लॅग आहे, runtime फ्लॅग नाही.** Next.js हे `headers()` रूट मॅनिफेस्टमध्ये कंपाइल करते, त्यामुळे बंडल बिल्ड होत असताना `next.config.mjs` हे व्हेरिएबल वाचते
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> आधीच बिल्ड केलेल्या सर्व्हरसमोर ते एक्सपोर्ट केल्याने काहीही बदलत नाही — हेडर्स आधीच अंतर्भूत केलेले असतात.

```bash
# हे व्हेरिएबल BUILD कमांडवर उपस्थित असणे आवश्यक आहे
DASHBOARD_ALLOW_EMBED=vscode npm run build        # किंवा npm run build:release
npm start
```

| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| स्रोतापासून                | ✅ वर दाखवल्याप्रमाणे, build कमांडवर व्हेरिएबल सेट करा                                                                                        |
