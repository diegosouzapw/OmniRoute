काही सेवा OmniRoute मध्ये एकात्मिक केल्या गेल्या होत्या आणि नंतर त्या चालवणाऱ्या व्यक्तींनी विनंती केल्यामुळे काढून टाकण्यात आल्या. हे पृष्ठ त्या काढून टाकण्यांची कायमस्वरूपी नोंद आहे. त्या चुकून पुन्हा जोडल्या जाऊ नयेत, हाच याचा एकमेव उद्देश आहे: एखाद्या योगदानकर्त्याला जुना fork, cache केलेला npm tarball, संग्रहित issue किंवा "provider X पुनर्स्थापित करा" अशी विनंती आढळल्यास, **पुन्हा  
जोडू नका** असे सांगणारे एक ठिकाण आवश्यक आहे.

हे पृष्ठ बंद पडलेल्या किंवा बंद करण्यात आलेल्या सेवांची यादी **नाही**. त्यांचा मागोवा
[`FREE_TIERS.md`](FREE_TIERS.md) ("काढून टाकलेले / मोफत स्तर नाही") मध्ये घेतला जातो आणि सेवा पुन्हा उपलब्ध झाल्यास त्या परत येऊ शकतात. खालील नोंदी केवळ विनंतीमध्ये नमूद केलेल्या ऑपरेटरच्या लेखी परवानगीनेच पुन्हा जोडता येतील आणि त्या परवानगीचा दुवा नोंदीमध्ये समाविष्ट केलेला असणे आवश्यक आहे.

## धोरण

1. **सेवा ऑपरेटरकडून आलेली काढून टाकण्याची विनंती मान्य केली जाते, तिच्यावर वाटाघाटी केल्या जात नाहीत.** OmniRoute चा कोणत्याही upstream सेवेशी संबंध नाही. एखाद्या सेवेचा ऑपरेटर एकात्मीकरण काढून टाकण्यास सांगतो तेव्हा ते काढून टाकले जाते, मग त्या एकात्मीकरणाने अधिकृत API वापरला असो वा नसो.
2. **"काढून टाकलेले" म्हणजे OmniRoute नियंत्रित करत असलेली प्रत्येक पृष्ठभागावरील बाब.** Executor, registry नोंद, provider id आणि alias, model यादी, endpoints, environment variables, icon, dashboard cards, व्युत्पन्न केलेला provider संदर्भ, `FREE_TIERS.md`, environment संदर्भ, README मधील संख्या, `llm.txt` mirrors, समर्पित tests आणि golden snapshots, code comments, CHANGELOG bullets
   (नोंदवहीतील ताळमेळासह, `config/release/changelog-reconciliations.json` पहा),
   GitHub Releases notes, wiki आणि ज्या GitHub issues, discussions व pull requests चा विषय तो provider होता ते सर्व (issues आणि discussions हटवले जातात; pull requests ची शीर्षके बदलली जातात, त्यांचे वर्णन बदलले जाते आणि thread lock केला जातो, कारण GitHub वर pull requests हटवता येत नाहीत).
3. **लेखी परवानगीशिवाय या पृष्ठावरील कोणतीही नोंद पुन्हा जोडू नका.** यामध्ये कोणत्याही provider catalog मध्ये id किंवा alias पुन्हा जोडणे, executor मध्ये domains जोडणे, ते "पुनर्स्थापित" करणारा contributor PR स्वीकारणे, free-model catalog मध्ये ते जोडणे किंवा OmniRoute द्वारे त्यापर्यंत पोहोचण्याचा manual मार्ग दस्तऐवजीकृत करणे यांचा समावेश होतो. अशा PRs आणि issues या पृष्ठाचा दुवा देऊन बंद करा.
4. **नोंद कमीत कमी ठेवा.** पुन्हा जोडलेली बाब ओळखण्यासाठी reviewer ला आवश्यक असलेली माहितीच नोंदवा: identifiers, domains, dates आणि काढून टाकण्याचे काम करणारा pull request. एकात्मीकरण कसे कार्य करत होते याचे वर्णन करू नका.
5. **Regression guard म्हणजे `tests/unit/removed-providers-blocklist.test.ts`.** खालीलपैकी कोणताही identifier किंवा domain provider catalogs, executor map किंवा provider registry sources मध्ये पुन्हा दिसल्यास तो अयशस्वी होतो. येथे row जोडणाऱ्या त्याच PR मध्ये त्या test मध्ये नवीन identifiers जोडा.

## नोंद जोडणे

नवीन काढून टाकण्याची विनंती आल्यावर:

1. विनंती सेवेच्या ऑपरेटरकडून (त्यांचा support address किंवा त्यांच्या नियंत्रणातील
   domain) आली असल्याची खात्री करा आणि संदेश खाजगीरीत्या जतन करा.
2. धोरणातील मुद्दा 2 मधील checklist नुसार एकात्मीकरण काढून टाका.
   Keyless provider साठी [#12440](https://github.com/diegosouzapw/OmniRoute/pull/12440) आणि
   संग्रहित connections असलेल्या API-key provider साठी [#10210](https://github.com/diegosouzapw/OmniRoute/pull/10210) संदर्भ म्हणून वापरा (migration जोडा).
3. वरील table मध्ये एक row आणि
   `tests/unit/removed-providers-blocklist.test.ts` मध्ये identifiers त्याच PR मध्ये जोडा.
4. PR merge झाल्यानंतर ऑपरेटरला उत्तर द्या आणि काय काढून टाकले गेले तसेच OmniRoute काय बदलू शकत नाही (आधीच प्रकाशित झालेल्या npm आणि Docker versions, git history, third-party forks) याची यादी द्या.
