> पुनर्नियोजनाशिवाय OmniRoute चे वर्तन बदलणारी रनटाइम टॉगल्स.
> येथे सूचीबद्ध केलेला प्रत्येक फ्लॅग
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> मध्ये परिभाषित केला आहे — हा सत्याचा एकमेव स्रोत आहे. डॅशबोर्ड आणि REST API दोन्ही
> त्या फाइलमधून वाचतात, त्यामुळे खालील तक्ता त्याच्याशी 1:1 जुळण्यासाठी व्युत्पन्न केला आहे.

## फीचर फ्लॅग म्हणजे काय

फीचर फ्लॅग हा नाव दिलेला टॉगल (boolean किंवा enum) असतो, ज्याचे मूल्य रनटाइमच्या
वेळी बदलता येते आणि डेटाबेसमध्ये कायमस्वरूपी साठवता येते; यासाठी प्रक्रिया पुन्हा
नियोजित करण्याची आवश्यकता नसते. प्रत्येक फ्लॅगचे वर्णन `FeatureFlagDefinition`
द्वारे केले जाते, ज्यामध्ये `key`, `label`, `description`, `category`,
`defaultValue`, `type` आणि `requiresRestart` संकेत असतो.

### निर्धारणाचा क्रम

फ्लॅगचे **प्रभावी मूल्य**
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) द्वारे पुढील
प्राधान्यक्रमानुसार निर्धारित केले जाते (सर्वोच्च प्राधान्याचे मूल्य लागू होते):

1. **DB ओव्हरराइड** — `feature_flags` नेमस्पेसअंतर्गत `key_value` तक्त्यामध्ये
   साठवलेले मूल्य (डॅशबोर्ड किंवा REST API द्वारे सेट केलेले).
2. **पर्यावरण चल** — सेट केलेले आणि रिक्त नसल्यास `process.env[<KEY>]`.
3. **परिभाषेतील डीफॉल्ट** — `featureFlagDefinitions.ts` मधील `defaultValue`.

boolean फ्लॅगचे प्रभावी मूल्य `"true"`, `"1"` किंवा `"yes"` असेल तेव्हा तो
**सक्षम** मानला जातो (`isFeatureFlagEnabled()` पहा).

> [!NOTE]
> बहुतांश फ्लॅगसाठी [`ENVIRONMENT.md`](./ENVIRONMENT.md) मध्ये दस्तऐवजीकरण केलेले,
> **समान नावाचे** जुळणारे पर्यावरण चलदेखील असते. फ्लॅगच्या DB ओव्हरराइडला त्या
> पर्यावरण चलापेक्षा प्राधान्य असते. `requiresRestart: true` असलेला फ्लॅग
> त्वरित कायमस्वरूपी साठवला जातो, परंतु प्रक्रिया सुरू होताना तो पुन्हा वाचला जातो
> — तो टॉगल केल्यावर डॅशबोर्डमध्ये **"सर्व्हर रीस्टार्ट करा"** बॅनर दिसतो.

## फ्लॅग टॉगल करणे

### डॅशबोर्ड

**डॅशबोर्ड → सेटिंग्ज → फीचर फ्लॅग** (`/dashboard/settings/feature-flags`) येथे नेव्हिगेट करा. ग्रिड
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`) खालील गोष्टींना सपोर्ट करते:

- की किंवा वर्णनानुसार **शोध** आणि श्रेणीनुसार **फिल्टर** (अधिक एक सिंथेटिक **पुन्हा सुरू करणे आवश्यक आहे** दृश्य).
- बुलियन फ्लॅगसाठी एक **टॉगल** आणि एनम फ्लॅगसाठी एक **ड्रॉपडाउन**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- प्रत्येक फ्लॅगसाठी एक **स्रोत बॅज** — `DB`, `ENV`, किंवा `DEF` — प्रभावी मूल्य कुठून आले हे दर्शवितो.
- ओव्हरराइड रद्द करण्यासाठी एक **रीसेट** बटण (फक्त `DB`-स्रोत फ्लॅगसाठी दर्शविले जाते), आणि तळाशी एक **सर्व ओव्हरराइड रीसेट करा** बटण.
- जेव्हा `requiresRestart` फ्लॅग बदलला जातो तेव्हा एक **सर्व्हर रीस्टार्ट करा** बॅनर.

### REST API

सर्व ऑपरेशन्स एकाच राउटमधून जातात:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
प्रत्येक पद्धतीसाठी प्रमाणीकृत डॅशबोर्ड सत्राची आवश्यकता असते (`401` अन्यथा).

#### `GET /api/settings/feature-flags`

प्रत्येक फ्लॅग त्याच्या प्रभावी मूल्य, स्रोत आणि सारांशासह परत करतो.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... सर्व 77 फ्लॅग
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

एकच ओव्हरराइड सेट करा किंवा काढून टाका. बॉडी: `{ key: string; value?: string }`.
`value` वगळल्यास ओव्हरराइड काढून टाकले जाते (env / default पुनर्संचयित करते).

```bash
# DB ओव्हरराइड सेट करा
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# ओव्हरराइड काढून टाका (कोणतेही "value" नाही)
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

प्रतिसाद नवीन `effectiveValue`/`source`, `previousValue`/
`previousSource`, आणि `requiresRestart` दर्शवतो. अज्ञात की आणि श्रेणीबाहेरील एनम मूल्ये `400` सह नाकारली जातात.

#### `DELETE /api/settings/feature-flags`

एकाच वेळी **सर्व** DB ओव्हरराइड्स साफ करते, प्रत्येक फ्लॅगला त्याच्या env / default मूल्यावर पुनर्संचयित करते. `{ cleared: <count>, message: "..." }` परत करते.

> [!NOTE]
> `requiresRestart: true` असलेले फ्लॅग प्रक्रिया रीलोड झाल्यानंतरच प्रभावी होतात.
> डॅशबोर्डचा रीस्टार्ट फ्लो `POST /api/restart` ला कॉल करतो आणि नंतर सर्व्हर पुन्हा सुरू होईपर्यंत `GET /api/health/ping` ला पोल करतो.

## आपत्कालीन बजेट फॉलबॅक

`OMNIROUTE_EMERGENCY_FALLBACK` (`runtime` श्रेणी, डीफॉल्ट `true`) हे
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)
मधील आपत्कालीन मोफत-फॉलबॅक मार्ग नियंत्रित करते.
ते सक्षम असताना, बजेट संपवणाऱ्या विनंत्या थेट अयशस्वी होण्याऐवजी मोफत फॉलबॅक
प्रदाता/मॉडेलकडे पाठवल्या जातात. हे वर्तन अक्षम करण्यासाठी आणि बजेट संपलेल्या विनंत्या
अयशस्वी होऊ देण्यासाठी, डॅशबोर्ड टॉगल, DB ओव्हरराइड किंवा
`OMNIROUTE_EMERGENCY_FALLBACK` पर्यावरण चलाद्वारे ते `false` (किंवा `0`) वर सेट करा.
(PRs #3741 / #3752 मध्ये डॅशबोर्ड टॉगल म्हणून उपलब्ध केले आहे.)

या फॉलबॅकद्वारे दिलेल्या प्रतिसादामध्ये
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>` असते,
त्यामुळे क्लायंटला त्याच्या विनंतीशी `X-OmniRoute-Provider` ची तुलना न करताही विनंती
पुन्हा मार्गित करण्यात आली होती हे समजू शकते. इतर प्रत्येक प्रतिसादामध्ये हे हेडर
अनुपस्थित असते.
