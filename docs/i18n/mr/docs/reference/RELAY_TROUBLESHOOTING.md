रिले (Vercel, Deno, Cloudflare) सर्व्हरलेस बॅकएंडवर अपस्ट्रीम कनेक्शन समाप्त करतात, जेणेकरून प्रदात्याची API की सर्व्हरवरच ठेवून OmniRoute स्थिर प्रदेशातून आउटबाउंड ट्रॅफिक पाठवू शकेल. या दस्तऐवजात ऑपरेटरना प्रॉडक्शनमध्ये आढळणाऱ्या दोन बिघाड पद्धती आणि प्रत्येकासाठी OmniRoute द्वारे उपलब्ध करून दिलेले पुनर्प्राप्ती मार्ग समाविष्ट आहेत.

## रिले प्रमाणीकरण कसे संग्रहित केले जाते

तुम्ही **Settings → Proxy Pool → Deploy Relay** मधून रिले डिप्लॉय करता तेव्हा, डिप्लॉय प्रवाह रिलेचा प्रमाणीकरण टोकन प्रॉक्सीच्या `notes` JSON फील्डमध्ये संग्रहित करतो:

- `STORAGE_ENCRYPTION_KEY` सेट केलेली असल्यास, टोकन `relayAuthEnc` म्हणून लिहिले जाते
  (संग्रहित अवस्थेत AES-एन्क्रिप्ट केलेले).
- अन्यथा ते साध्या मजकुरात `relayAuth` म्हणून लिहिले जाते.

विनंतीच्या वेळी `extractRelayAuth(notes)` उपलब्ध असलेले रूप परत करते, त्यामुळे रीस्टार्टनंतरही रिले कार्यरत राहतो.

## बिघाड पद्धत 1 — की रोटेशननंतर डिक्रिप्ट न करता येणारा टोकन

**लक्षण:** पूर्वी कार्यरत असलेले रिले आता `STORAGE_ENCRYPTION_KEY` च्या एन्व्हायर्नमेंट किंवा सीक्रेट-मॅनेजर रोटेशननंतर अपस्ट्रीम `401`/प्रमाणीकरण त्रुटी परत करतात. संग्रहित `relayAuthEnc` ब्लॉब यापुढे डिक्रिप्ट करता येत नाही, त्यामुळे `extractRelayAuth` रिकामी स्ट्रिंग परत करते आणि रिले कोणतेही प्रमाणीकरण पाठवत नाही.

**पुनर्प्राप्ती — त्याच ठिकाणी दुरुस्ती करा (पुन्हा डिप्लॉय करण्याची आवश्यकता नाही):**

1. **Settings → Proxy Pool** उघडा.
2. ज्या रिले पंक्तींमध्ये प्रमाणीकरण उपलब्ध नाही, त्यांमध्ये पिवळा `auth missing` बॅज आणि
   **Repair** बटण दिसते.
3. **Repair** वर क्लिक करा. OmniRoute
   `POST /api/settings/proxies/[id]/repair-relay` कॉल करते, जे:
   - **सध्याच्या** कीने `relayAuthEnc` डिक्रिप्ट करते,
   - साध्या मजकुरातील `relayAuth` परत `notes` मध्ये लिहिते,
   - `{ repaired: true, mode: "recovered" }` परत करते.

कोणतीही डिप्लॉय क्रेडेन्शियल्स पुन्हा प्रविष्ट न करता रिले सेवा देणे पुन्हा सुरू करतो.

सध्याची `STORAGE_ENCRYPTION_KEY` अद्याप ब्लॉब डिक्रिप्ट करू शकत असेल तरच हे कार्य करते. तुम्ही माइग्रेशन **न करता** की रोटेट केली असल्यास, ब्लॉब पुनर्प्राप्त करता येणार नाही.

## बिघाड पद्धत 2 — पुनर्प्राप्त न करता येणारा टोकन (जुनी की रोटेट करून काढून टाकली)

**लक्षण:** तुम्ही **Repair** वर क्लिक केले आणि
`{ repaired: false, mode: "redeploy", status: 409 }` मिळाले.

**पुनर्प्राप्ती — पुन्हा डिप्लॉय करा:**

संग्रहित टोकन सध्याच्या कीने पुनर्प्राप्त करता येत नाही. तुम्ही मूळतः वापरलेल्या त्याच मोडलमधून रिले पुन्हा डिप्लॉय करा (**Deploy Relay** मेनू → Vercel / Deno / Cloudflare). डिप्लॉय प्रवाह एक नवीन टोकन लिहितो (सध्याच्या कीने एन्क्रिप्ट केलेला) आणि पंक्तीवरील `auth missing` बॅज हटतो.

टोकन पुनर्प्राप्त न करता येण्यासारखा असल्यास, UI मधील **Repair** बटणच पुन्हा डिप्लॉय करण्यासाठी मोडल उघडते, त्यामुळे तुम्हाला ते स्वतः शोधावे लागत नाही.

## बिघाड पद्धत 3 — रिलेपर्यंत पोहोचता येते, परंतु तो निरोगी नाही

**लक्षण:** प्रॉक्सी चाचणी (`speed` बटण) रिले कार्यरत असल्याचे दाखवते, परंतु विनंत्या तरीही अधूनमधून अयशस्वी होतात.

OmniRoute च्या स्वयंचलित चाचणी प्रोबद्वारे परत केलेले रिले-जागरूकता हेडर्स तपासा
(**Settings → Proxy Pool** आणि `relayTested` / `relayAlive` काउंटर पहा):

- `x-relay-url` — कोणत्या रिले बॅकएंडने प्रतिसाद दिला.
- `x-relay-mode` — त्या विनंतीसाठी `ts` | `bifrost` | `auto`.
- `x-relay-attempts` — यश मिळण्यापूर्वी किती रिले हॉप्स वापरून पाहिले गेले.
- `x-relay-fallback` — विनंती प्राधान्य दिलेल्या बॅकएंडवरून TypeScript रिलेवर फॉलबॅक झाली असल्यास `true`.

कमी `relayAlive` सह `x-relay-fallback` चे प्रमाण जास्त असल्यास, साइडकार बॅकएंड निरोगी नाही आणि तुम्ही तो दुरुस्त करावा किंवा रिले बॅकएंड धोरण `ts` वर स्विच करावे (`RELAY_BACKEND_STRATEGY.md` पहा).

## API संदर्भ

| पद्धत  | पाथ                                       | बॉडी                    | यश                                                                                                                                              | अपयश                                                                                                   |
| ------ | ----------------------------------------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `POST` | `/api/settings/proxies/[id]/repair-relay` | `{ "id": "<proxyId>" }` | पुन्हा प्राप्त केल्यावर `200 { repaired: true, mode: "recovered" }`; साधा मजकूर आधीपासून उपलब्ध असल्यास `200 { repaired: false, mode: "noop" }` | पुनर्प्राप्त करता येत नसल्यास `409 { mode: "redeploy" }`; रिले प्रकार नसल्यास `400`; न सापडल्यास `404` |

लिस्ट रूट `GET /api/settings/proxies` प्रत्येक आयटमला सीक्रेट-मुक्त
`relayInfo: { isRelay, authMissing, repairMode }` जोडतो, जेणेकरून टोकन कधीही उघड न करता डॅशबोर्ड दुरुस्तीचा पर्याय प्रदर्शित करू शकेल.
