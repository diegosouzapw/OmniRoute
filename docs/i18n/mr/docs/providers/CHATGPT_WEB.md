`chatgpt-web-codex` (उपनाव `cgpt-codex`) प्रमाणीकृत ChatGPT ब्राउझर सत्राद्वारे Codex Responses टर्न्सना जोडतो. हा निवृत्त केलेल्या सामान्य `chatgpt-web` प्रोव्हायडरपासून स्वतंत्र आहे आणि `open-sse/vendor/codex-chatgpt-web/` अंतर्गत MIT सूचनेसह असलेले अंमलबजावणी रूप वापरतो, जे अपस्ट्रीम v4.0.7 कमिट `b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494` पर्यंत अद्ययावत केले आहे.

## सामान्य प्रोव्हायडरची निवृत्ती

पूर्वीचे सामान्य प्रोव्हायडर ID `chatgpt-web` आणि `cgpt-web` आता वितरित केले जात नाहीत, कारण त्यांच्या pre-key/proof-of-work अंमलबजावणीचा उगम स्पष्ट करता आला नाही. स्लॅशने सुरू होणारे मॉडेल ID आणि जतन केलेली उपनावे यांसह, यापैकी कोणत्याही ID साठी केलेल्या स्पष्ट विनंत्या कोणतीही अपस्ट्रीम विनंती करण्यापूर्वी HTTP `410` आणि **PROVIDER_RETIRED** कोडसह बंद पद्धतीने अयशस्वी होतात.

मायग्रेशन `168_retire_chatgpt_web.sql` जुळणाऱ्या प्रोव्हायडर कनेक्शन्सना टूमस्टोन करते आणि त्यांचे सक्रिय सत्र लीझ अवैध करते. ते कनेक्शन इतिहास आणि API-key अनुमतीसूच्या जतन करते; ते अनुमतीसूचीमध्ये पर्यायी प्रवेश जोडत नाही. Codex प्रोव्हायडर आणि त्याची कनेक्शन्स या निवृत्तीशी जुळवली जात नाहीत.

## पूर्वापेक्षा

- साइन-इन केलेल्या ChatGPT सत्राचा संपूर्ण Cookie हेडर;
- npm, systemd आणि PM2 इंस्टॉलेशन्ससाठी Chrome किंवा Chromium तसेच ग्राफिकल सत्र किंवा Xvfb डिस्प्ले;
- Docker `web` प्रोफाइलसह, `docker-compose.yml` मधील अंतर्गत Chromium सेवा;
- स्थानिक Codex साधनांसाठी OpenAI `tunnel-client` v0.0.13 आणि ChatGPT कस्टम कनेक्टर.

टनल केवळ टूल टर्न्ससाठी आवश्यक आहे. `pro` सह सूचीबद्ध केलेला प्रत्येक रूट, टनल आणि कनेक्टर कॉन्फिगर केलेले असताना समान टर्न-बाउंड स्थानिक टूल क्षमता वापरू शकतो.

## डॅशबोर्ड सेटअप

1. **ChatGPT Web (Codex)** प्रोव्हायडर उघडा आणि कनेक्शन जोडा.
2. संपूर्ण ChatGPT Cookie हेडर, टनल ID, रनटाइम की आणि कस्टम कनेक्टरचे नाव पेस्ट करा. नवीन टूल-क्षम सेटअप्सनी `OmniRoute Codex v2` याच अचूक नावाने नव्याने तयार केलेला कनेक्टर वापरणे आवश्यक आहे, ज्यामध्ये Authentication हे None आणि Permissions हे Allow all actions असे सेट केलेले असावे.
3. कनेक्शन तपासणी चालवा. OmniRoute ब्राउझर-आधारित Temporary Chat उघडतो आणि खात्यासाठी Sol व Pro उपलब्ध आहेत की नाही हे शोधतो.
4. कनेक्शन जतन करा. OmniRoute पेस्ट केलेल्या कुकीच्या जागी सत्यापित Playwright स्टोरेज स्टेट ठेवतो आणि एनक्रिप्टेड क्रेडेन्शियल अॅब्स्ट्रॅक्शनद्वारे ते रनटाइम कीसह संग्रहित करतो.

यशस्वीरीत्या जतन केल्यानंतर मूळ कुकी राखून ठेवली जात नाही. सत्र कालबाह्य झाल्यावर, कनेक्शन उघडा, नवीन संपूर्ण Cookie हेडर पेस्ट करा आणि तपासणी पुन्हा चालवा. संपादन संवादातील डॉक्टर स्थिती ब्राउझर, स्टोरेज स्टेट, साइन-इन, Temporary Chat, टनल, कनेक्टर आणि टूल राउंड-ट्रिप यांचा अहवाल स्वतंत्रपणे देते.

> वास्तविक कुकी, रनटाइम की, स्टोरेज स्टेट किंवा क्षमता टोकन कधीही कमिट करू नका. चाचणी आणि
> दस्तऐवजीकरणातील मूल्ये नेहमी प्लेसहोल्डर्स असली पाहिजेत.

## मॉडेल्स आणि कॉम्बोज

निश्चित मॉडेल रूट्स पुढीलप्रमाणे आहेत:

- `chatgpt-web-codex/luna` — GPT-5.6 Luna, कमी प्रयत्न
- `chatgpt-web-codex/think` — GPT-5.6 Luna, मध्यम प्रयत्न
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

इतर कोणत्याही मॉडेलप्रमाणे त्यांपैकी एक कॉम्बोमध्ये जोडा. Codex अॅप नियमित Responses एंडपॉइंट `/v1/responses` कडे कॉम्बोचे नाव `model` म्हणून पाठवते; स्वतंत्र Codex एंडपॉइंट किंवा मोड स्विच नाही.

Free/Go खाती Luna रूट्स उपलब्ध करून देतात. Sol-क्षम खाती Instant ते High उपलब्ध करून देतात आणि Pro-क्षम खाती याव्यतिरिक्त Extra High व Pro उपलब्ध करून देतात. प्रत्येक रूटमध्ये निश्चित बॅकएंड मॉडेल आणि रीझनिंग प्रयत्न असतो; त्याच्याशी विसंगत असलेला स्पष्ट Responses प्रयत्न निवडलेला ब्राउझर मोड गुपचूप बदलण्याऐवजी बंद पद्धतीने अयशस्वी होतो.

जुन्या `Codex Native` किंवा `OmniRoute Codex` कनेक्टरचे नाव बदलू नका किंवा तो पुन्हा वापरू नका. ChatGPT कनेक्टरच्या ओळखीनुसार सार्वजनिक MCP करार कॅश करते, तर अद्ययावत ब्रिज नवीन थेट टर्न-टोकन करार वापरतो. रनटाइम त्या लेगसी ओळखी नाकारतो आणि नवीन `OmniRoute Codex v2` कनेक्टर आवश्यक ठरवतो.

## सुरक्षा मॉडेल

- मूळ पथासाठी Responses विनंती, मान्यताप्राप्त Codex क्लायंट आणि जुळणाऱ्या
  थ्रेड व टर्न ओळखी आवश्यक आहेत.
- Workspace, sandbox, मंजुरी धोरण आणि टूल कॅटलॉग हे मूळ Codex shell मधून येतात;
  त्यांच्यासाठी मुक्त-स्वरूपातील प्रॉम्प्ट मजकूर अधिकृत मानला जात नाही.
- ChatGPT ला प्रत्येक टर्नसाठी केवळ अल्पकालीन क्षमता मिळते. MCP broker फक्त
  त्याच टर्नमध्ये Codex ने उपलब्ध करून दिलेली टूल्स स्वीकारतो.
- **Allow once** ची स्वयंचलित पुष्टी केल्याने केवळ टूल विनंती Codex कडे परत पाठवली जाते. मंजुरी आणि अंमलबजावणीबाबतचा
  निर्णय फक्त Codex घेतो.
- पहिल्या आउटपुटपूर्वी, कॉम्बो दुसऱ्या सुसंगत लक्ष्याकडे परत जाऊ शकतो. आउटपुट
  सुरू झाल्यानंतर, टर्न पूर्ण होईपर्यंत provider, model, connection आणि browser turn निश्चित राहतात.
- Cookies, runtime keys, storage state आणि capability tokens हे provider च्या
  प्रतिसादांमध्ये किंवा विनंती लॉगमध्ये दिसत नाहीत.

## डिस्प्लेविरहित VPS आणि Docker

npm, systemd आणि PM2 इंस्टॉलेशन्ससाठी, OmniRoute सामान्य Chrome आणि Chromium पथ शोधतो.
पर्याय म्हणून, `CHATGPT_WEB_CODEX_CHROME_PATH` सेट करा. Runtime टर्न्समध्ये जाणीवपूर्वक दृश्यमान
Chrome वापरले जाते, कारण ChatGPT खऱ्या headless browser ची रचना नाकारतो. त्यामुळे डिस्प्लेविरहित होस्टने
OmniRoute खाजगी Xvfb डिस्प्लेसह चालवणे आवश्यक आहे; केवळ Chrome पथ सेट केल्याने डिस्प्ले उपलब्ध होत नाही.

Docker चे `web` प्रोफाइल अंतर्गत Compose
नेटवर्कवर `chatgpt-web-codex-browser` सुरू करते. Sidecar, Xvfb मध्ये दृश्यमान Chrome चालवतो, त्यामुळे कोणत्याही भौतिक डिस्प्लेची आवश्यकता नसते. त्याचा CDP
पोर्ट होस्टवर प्रकाशित केला जात नाही. संरक्षित browser profile volume हा
OmniRoute data volume पासून वेगळा असतो आणि browser ला पुरेशी shared memory मिळते. अंतर्गत CDP proxy
Compose नेटवर्कमध्ये फक्त `9223` पोर्टवर ऐकतो; sidecar मध्ये Chrome loopback शीच बांधलेला राहतो.

`DATA_DIR` अंतर्गत असलेला supervisor lease एकाच tunnel आणि broker state ची मालकी
अनेक OmniRoute प्रक्रियांकडे जाण्यापासून प्रतिबंधित करतो. doctor द्वारे संघर्ष नोंदवला जातो.

## परस्परसंवादी पुनर्प्राप्ती

स्वयंचलित Docker पथामध्ये होस्टवर दिसणारी विंडो नसते, परंतु खाजगी
Xvfb डिस्प्लेमध्ये Chrome स्वतः दृश्यमान असतो. ChatGPT ला परस्परसंवादी sign-in किंवा challenge आवश्यक असल्यास, पुनर्प्राप्तीसाठी विद्यमान VNC
browser पायाभूत सुविधा वापरता येतात. Browser UI आणि CDP हे फक्त
loopback, प्रमाणीकृत व्यवस्थापन कनेक्शन किंवा SSH tunnel द्वारेच उपलब्ध राहिले पाहिजेत; सामान्य कार्यवाहीदरम्यान noVNC अक्षमच राहते.

## WebSocket फॉलबॅक

जेव्हा कॉम्बोमध्ये ChatGPT Web (Codex) समाविष्ट असते, तेव्हा Responses WebSocket bridge upstream शी कनेक्ट होण्यापूर्वी
HTTP/SSE फॉलबॅकची विनंती करतो. त्यानंतर हस्तांतरण
`/v1/responses` मधून होते.
