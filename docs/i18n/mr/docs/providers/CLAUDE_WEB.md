## `claude-web`

`claude-web` प्रमाणीकृत `claude.ai` ब्राउझर सत्राद्वारे OpenAI-स्वरूपातील चॅट विनंत्या पाठवते. एक्झिक्युटर दिलेली कुकी सामान्यीकृत करतो, एक प्रमाणीकृत संस्था निर्धारित करतो, संभाषण स्थिती तयार करतो, थेट किंवा ब्राउझर ट्रान्सपोर्ट निवडतो आणि अपस्ट्रीम SSE प्रतिसादाचे काटेकोरपणे रूपांतर करतो. ऑर्केस्ट्रेशन `open-sse/executors/claude-web.ts:320` मध्ये आहे.

> **Web Cookie प्रदाते वापरण्यास नवीन आहात?**
>
> हे प्रदाता-विशिष्ट मार्गदर्शक वापरण्यापूर्वी सर्वसाधारण सेटअप प्रक्रिया, प्रमाणीकरण मार्गदर्शन, मर्यादा आणि समस्यानिवारणासाठी **`docs/getting-started/WEB-COOKIE-GUIDE.md`** वाचा.

(`open-sse/config/providers/registry/claude/web/index.ts:11`):

| मॉडेल ID                    | प्रदर्शित नाव           |

| `claude-fable-5`            | Claude Fable 5 (वेब)    |

या प्रदात्यासाठी डायनॅमिक मॉडेल शोध लागू केलेला नाही. वरील सूची हा रनटाइम कॅटलॉग आहे.

### क्रेडेन्शियल्स आणि संस्था निर्धारण

संपूर्ण `claude.ai` Cookie हेडर किंवा फक्त सत्र मूल्य द्या. फक्त मूल्य दिल्यास ते `sessionKey` म्हणून सामान्यीकृत केले जाते; इतर कुकी दिल्या असल्यास त्या जतन केल्या जातात. एक्झिक्युटर `cookie` किंवा `apiKey` द्वारे कुकी स्वीकारतो आणि कनेक्शन डेटामधून पर्यायी `deviceId` आणि `orgId` मूल्ये वाचतो
(`open-sse/executors/claude-web.ts:72`).

`orgId` नसल्यास, एक्झिक्युटर `GET https://claude.ai/api/organizations` कॉल करतो आणि प्रमाणीकृत Claude Web सत्राने परत केलेली पहिली संस्था वापरतो
(`open-sse/executors/claude-web.ts:141`). कोणतीही वैध संस्था परत न मिळाल्यास तो सुरक्षितपणे अपयशी ठरतो, नाकारलेल्या सत्र प्रमाणीकरणाची 401 म्हणून नोंद करतो आणि Cloudflare आव्हान व प्रमाणीकरण अपयश यांमध्ये फरक करतो.

### संभाषण ऑपरेशन्स

पर्यायी शीर्ष-स्तरीय `claude_web` ऑब्जेक्ट काटेकोर आहे. अज्ञात फील्ड नाकारली जातात. त्याची स्वीकारली जाणारी फील्ड `open-sse/executors/claude-web/session.ts:50` मध्ये परिभाषित केली आहेत:

| फील्ड                 | अर्थ                                                                  |
| --------------------- | --------------------------------------------------------------------- |
| `operation`           | डीफॉल्टनुसार `completion`; पुन्हा प्रयत्नाच्या टर्नसाठी `retry` वापरा |
| `conversation_id`     | विद्यमान संभाषणासाठी स्पष्ट UUID                                      |
| `parent_message_uuid` | पालक असिस्टंट संदेशासाठी स्पष्ट UUID                                  |
| `timezone`            | वैध IANA टाइम-झोन नाव                                                 |
| `locale`              | संरचनात्मकदृष्ट्या वैध लोकेल                                          |
| `tool_states`         | पर्यायी खाते टूल-स्थिती अॅरे, 128 नोंदींपर्यंत मर्यादित               |

तयार केलेल्या विनंत्या दोन अपस्ट्रीम एंडपॉइंटपैकी एक वापरतात
(`open-sse/executors/claude-web.ts:203`):

- नवीन किंवा पुढील टर्न
  `POST https://claude.ai/api/organizations/{orgId}/chat_conversations/{conversationId}/completion` येथे पोस्ट केला जातो.
- पुन्हा प्रयत्न
  `POST https://claude.ai/api/organizations/{orgId}/chat_conversations/{conversationId}/retry_completion` येथे पोस्ट केला जातो.

नवीन टर्नमध्ये `create_conversation_params` समाविष्ट असते. कॅश केलेल्या किंवा स्पष्टपणे लिंक केलेल्या पुढील टर्नमध्ये `parent_message_uuid` समाविष्ट असते आणि `create_conversation_params` वगळले जाते. पुन्हा प्रयत्नासाठी संभाषण आणि पालक-संदेश स्थिती दोन्ही आवश्यक असतात आणि कोणताही प्रॉम्प्ट पाठवला जात नाही
(`open-sse/executors/claude-web/session.ts:254`). नवीन संभाषणे प्रमाणीकृत UI `/new` येथे उघडतात; कॅश केलेले किंवा स्पष्टपणे लिंक केलेले पुढील टर्न अचूक संभाषण पृष्ठ उघडतात
(`open-sse/executors/claude-web/session.ts:324`).

संभाषण स्थिती ही SHA-256 खाते व्याप्ती आणि कॉलरच्या प्रमाणित ट्रान्सक्रिप्टनुसार की केलेली इन-मेमरी कॅश आहे. नोंदी 30 मिनिटांनंतर कालबाह्य होतात आणि कॅश 5,000 नोंदींपर्यंत मर्यादित आहे
(`open-sse/executors/claude-web/session.ts:12`). काटेकोर स्ट्रीम पार्सरला `message_stop` आढळल्यानंतरच स्थिती कमिट केली जाते; प्रक्रिया रीस्टार्ट झाल्यास ती हटवली जाते. कॅश मिस झाल्यास, आधीचे संदेश गुपचूप वगळण्याऐवजी बहु-संदेश विनंती एका पुनर्प्राप्ती प्रॉम्प्टमध्ये क्रमबद्ध केली जाते.

लोकेल आणि टाइम झोनसाठी हा प्राधान्यक्रम वापरला जातो: विनंतीतील `claude_web` मूल्य, कनेक्शन मूल्य, रनटाइम मूल्य आणि त्यानंतर लोकेलसाठी `en-US` किंवा टाइम झोनसाठी `UTC`
(`open-sse/executors/claude-web/session.ts:218`).

### टूल्स आणि विनंती पेलोड

थेट विनंत्या कॉलरने पुरवलेल्या केवळ संरचनात्मकदृष्ट्या वैध OpenAI फंक्शन टूल्सचे रूपांतर करतात. कृत्रिमरीत्या तयार केलेली स्थिर डीफॉल्ट टूल सूची नाही
(`open-sse/executors/claude-web/payload.ts:102`).

त्याऐवजी ब्राउझर विनंत्या प्रमाणीकृत UI विनंती कॅप्चर करतात आणि तिची खाते टूल्स, टूल स्थिती आणि वैयक्तिकृत शैली जतन करतात. तयार केलेले संभाषण, मॉडेल, रिझनिंग, प्रॉम्प्ट आणि संदेश UUID फील्ड तरीही कॅप्चर केलेल्या विनंतीतील संबंधित मूल्ये ओव्हरराइड करतात
(`open-sse/executors/claude-web/browserTransport.ts:175`). ब्राउझर टेम्पलेट्स खाते, संस्था, कुकी, लोकेल आणि टाइम झोन यांच्या हॅशनुसार स्कोप केली जातात आणि 30 मिनिटांनंतर कालबाह्य होतात
(`open-sse/executors/claude-web/browserTransport.ts:11`,
`open-sse/executors/claude-web/browserTransport.ts:158`). थेट विनंतीमध्ये कॉलर टूल्स नसताना, ती स्कोप केलेले टेम्पलेट पुन्हा वापरू शकते; स्पष्टपणे दिलेल्या कॉलर टूल्सना प्राधान्य असते
(`open-sse/executors/claude-web/browserTransport.ts:214`).

### ट्रान्सपोर्ट निवड

डीफॉल्ट मार्ग `sendClaudeWebDirect()` आहे, जो कॉन्फिगर केलेली Chrome 146 प्रोफाइल आणि दिलेली कुकी वापरून `tlsFetchClaude()` कॉल करतो (`open-sse/services/claudeTlsClient.ts:23`). तो सॉल्वर सुरू करत नाही किंवा पर्यायी कुकी तयार करत नाही.

खाते-व्याप्त ब्राउझर अडॅप्टरला प्राथमिक ट्रान्सपोर्ट बनवण्यासाठी `WEB_COOKIE_USE_BROWSER` हे `1`, `true`, किंवा `on` वर सेट करा. ओळखले गेलेले Cloudflare 403 आव्हान आल्यास थेट ट्रान्सपोर्टवरून ब्राउझर अडॅप्टरकडे फॉलबॅक करण्याची परवानगी देण्यासाठी `OMNIROUTE_BROWSER_POOL` हे त्याच मूल्यांपैकी एका मूल्यावर सेट करा (`open-sse/executors/claude-web.ts:195`). इतर HTTP अपयशांमुळे तो फॉलबॅक ट्रिगर होत नाही.

ब्राउझर अडॅप्टर त्याच पूल केलेल्या Playwright संदर्भामध्ये कुकीज ठेवतो, वर वर्णन केलेली व्याप्तीयुक्त हॅश केलेली की वापरतो आणि त्या संदर्भातून पूर्णता पाठवतो (`open-sse/executors/claude-web/browserTransport.ts:444`). तो ब्राउझरने सोडवलेली कुकी कधीही थेट TLS क्लायंटमध्ये निर्यात करत नाही. ब्राउझर पुनर्प्रयत्नांसाठी त्याच प्रत्यक्ष Playwright संदर्भाशी बांधलेला आणि कालबाह्य न झालेला UI टेम्पलेट आवश्यक असतो (`open-sse/executors/claude-web/browserTransport.ts:467`). ब्राउझर प्रतिसादाचे वाचन प्रमाणीकरण केलेल्या पृष्ठामध्ये क्रमवर्धित रीतीने चालते, विनंती रद्द करण्याचा मान राखते आणि आकार 16 MiB पेक्षा जास्त होताच अपस्ट्रीम बॉडी रद्द करते (`open-sse/executors/claude-web/browserTransport.ts:259`).

एक्झिक्युटर सामायिक विनंती लॉगरला संवेदनशील माहिती लपवलेले ऑडिट प्रोजेक्शन परत करतो: संस्था, संभाषण आणि संदेश UUIDs, प्रॉम्प्ट मजकूर, टूल व्याख्या, कुकीज आणि डिव्हाइस ओळखचिन्हे वगळली जातात (`open-sse/executors/claude-web.ts:237`,
`open-sse/executors/claude-web.ts:252`). ट्रान्सपोर्ट अपवादांमध्येही थ्रो केलेल्या संदेशाऐवजी सामान्य कनेक्शन त्रुटी परत केली जाते.

### SSE वर्तन

`createClaudeWebResponse()` हे LF किंवा CRLF फ्रेमिंग आणि बहु-ओळी `data:` फील्ड हाताळते. ते मजकूर डेल्टांना `content`, विचार डेल्टांना `reasoning_content` आणि ज्ञात मेटाडेटा इव्हेंट्सना `claude_web` प्रतिसाद एक्स्टेंशनशी मॅप करते. प्रत्येक मेटाडेटा इव्हेंट त्याच्या स्वतःच्या फील्ड अनुमतीसूचीद्वारे प्रोजेक्ट केला जातो (`open-sse/executors/claude-web/stream.ts:37`). संभाषण, पालक-संदेश, सहाय्यक-संदेश आणि ऑपरेशन मेटाडेटा देखील `X-OmniRoute-Claude-Web-*` हेडर्समध्ये परत केला जातो (`open-sse/executors/claude-web/stream.ts:364`).

विकृत JSON, अपस्ट्रीम `error` इव्हेंट्स, अज्ञात इव्हेंट प्रकार, अवैध क्रम, कंटेंट-ब्लॉक विसंगती किंवा `message_stop` पूर्वी EOF आल्यास पार्सर सुरक्षितपणे अपयशी ठरतो. स्ट्रीमिंग आउटपुट एक समाप्ती चंक आणि एक `[DONE]` उत्सर्जित करते; बफर केलेले आउटपुट हाच पार्सर वापरते. पार्सर `message_stop` ला त्वरित अंतिम स्थिती मानतो, त्यानंतरचा अपस्ट्रीम डेटा रद्द करतो आणि डाउनस्ट्रीम रद्दीकरण अपस्ट्रीम रीडरपर्यंत प्रसारित करतो (`open-sse/executors/claude-web/stream.ts:461`,
`open-sse/executors/claude-web/stream.ts:563`). समाप्त न झालेल्या SSE ओळी आणि संचित इव्हेंट्सना 1 MiB ची मर्यादा आहे (`open-sse/executors/claude-web/stream.ts:17`,
`open-sse/executors/claude-web/stream.ts:62`).

`tests/unit/claude-web-auto-refresh.test.ts` मधील Playwright-अवलंबित प्रकरणे स्पष्टपणे वगळली आहेत. हे रिपॉझिटरी सध्या क्रेडेन्शियल्स वापरणारी Claude Web थेट-चाचणी स्क्रिप्ट परिभाषित करत नाही, त्यामुळे वगळलेली ती प्रकरणे रनटाइम पुरावा नाहीत.

### सेटअप

1. `npm run dev` वापरून किंवा बिल्ट इन्स्टॉलेशनद्वारे OmniRoute सुरू करा.
2. Dashboard → Providers → Add Provider उघडा.
3. Web Cookie श्रेणी आणि Claude Web निवडा.
4. प्रमाणीकरण केलेल्या `claude.ai` विनंतीमधून कॉपी केलेला संपूर्ण Cookie हेडर पेस्ट करा.
