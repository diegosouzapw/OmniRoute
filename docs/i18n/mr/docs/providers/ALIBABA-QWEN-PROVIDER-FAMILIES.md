हा दस्तऐवज
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854) साठीचा अंमलबजावणी निर्णय नोंदवतो. सार्वजनिक उत्पादने चार प्रदाता कुटुंबांच्या स्वरूपात दर्शवली आहेत. प्रदेश हा कनेक्शन डेटा आहे, स्वतंत्र उत्पादन नाही.

## निर्णय

| प्रदाता कुटुंब                              | OmniRoute ID            | जागतिक प्रदेश | चीन प्रदेश |
| ------------------------------------------- | ----------------------- | ------------- | ---------- |
| Alibaba Cloud Model Studio (वापरानुसार देय) | `alibaba`               | सिंगापूर      | बीजिंग     |
| Alibaba Cloud Token Plan                    | `bailian-coding-plan`   | सिंगापूर      | बीजिंग     |
| Qwen Cloud (वापरानुसार देय)                 | `qwen-cloud`            | जागतिक        | बीजिंग     |
| Qwen Cloud Token Plan                       | `qwen-cloud-token-plan` | सिंगापूर      | बीजिंग     |

विद्यमान `alibaba-cn` ID जतन केलेली कनेक्शने, मॉडेल रूट्स, कॉम्बोज आणि ऐतिहासिक वापर यांच्यासाठी रनटाइम सुसंगतता उपनाव म्हणून कायम राहतो. त्याचे डॅशबोर्ड कार्ड `alibaba` मध्ये समाविष्ट केले आहे; डेटाबेस पुनर्लेखनाची आवश्यकता नाही.

Qwen Cloud चे वापरानुसार देय उत्पादन आणि Alibaba Cloud Model Studio सध्या DashScope-सुसंगत रनटाइम होस्ट सामायिक करतात, परंतु वापरकर्ते वेगवेगळ्या उत्पादन इंटरफेसद्वारे की मिळवतात आणि खाती व्यवस्थापित करतात, त्यामुळे त्यांच्या प्रदाता ओळखी स्वतंत्र राहतात. Alibaba आणि Qwen Cloud Token Plan उत्पादने भिन्न एंडपॉइंट कुटुंबे वापरतात, त्यामुळे चारही उत्पादने स्वतंत्र प्रदाता ID म्हणून कायम राहतात.

## एंडपॉइंट मॅट्रिक्स

| प्रदाता कुटुंब          | `global-sg`                                                              | `china-beijing`                                                      | वायर स्वरूप |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ----------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI      |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic   |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI      |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI      |

API की आणि एंडपॉइंट एकाच उत्पादनाचे आणि प्रदेशाचे असणे आवश्यक आहे. प्रदेश निवडल्याने प्रमाणीकरण आणि सामान्य विनंत्यांसाठी वापरला जाणारा पूर्वनियोजित एंडपॉइंट बदलतो.

## कनेक्शन करार

नवीन कनेक्शने स्थिर प्रदेश की `providerSpecificData` मध्ये संग्रहित करतात:

```json
{
  "region": "global-sg"
}
```

अनुमत मूल्ये `global-sg` आणि `china-beijing` आहेत. एंडपॉइंट हा प्रदाता ID आणि प्रदेशावरून मध्यवर्तीरीत्या निर्धारित केला जातो. पूर्वनियोजित नसलेला `providerSpecificData.baseUrl` स्पष्ट ऑपरेटर अधिलिखित मूल्य म्हणून कायम राहतो आणि त्याला प्राधान्य दिले जाते, तर जुने जतन केलेले पूर्वनियोजित URL पुन्हा प्रादेशिक मॅट्रिक्सनुसार सामान्यीकृत केले जातात.

यामुळे कनेक्शन स्कीमा विस्तारक्षम राहते: दुसरे प्रदाता कार्ड तयार न करता किंवा जतन केलेले प्रदाता ID न बदलता रिझॉल्वरमध्ये आणखी एक प्रदेश जोडता येतो.

## सुसंगतता आणि रोलआउट

1. प्रादेशिक एंडपॉइंट रिझॉल्वर जोडा आणि सध्याची जागतिक डीफॉल्ट्स कायम ठेवा.
2. `alibaba`, त्याचा `alibaba-cn` सुसंगतता ID आणि `qwen-cloud` यांच्यासाठी थेट प्रादेशिक DashScope `/models` डिस्कव्हरी वापरा. त्यांच्या प्रतिसादांवर प्रथम एक मजकूर-निर्मिती फिल्टर लागू होतो, कारण जेनेरिक एंडपॉइंट प्रतिमा, व्हिडिओ, ऑडिओ, एम्बेडिंग आणि इतर नॉन-चॅट मॉडेल्सदेखील परत करतो. त्यानंतर `qwen-cloud` त्याच्या प्रदाता रजिस्ट्रीमध्ये घोषित केलेली व्यवस्थापित अनुमतीसूची लागू करतो. Alibaba Model Studio आणि Qwen Cloud सध्या समान रनटाइम होस्ट वापरत असले, तरी ते स्वतंत्रपणे क्युरेट केलेले कॅटलॉग राखतात.
3. सध्याच्या Token Plan मजकूर-मॉडेल अनुमतीसूचीसह `qwen-cloud-token-plan` नोंदणीकृत करा.
4. कनेक्शन जोडण्याच्या/संपादित करण्याच्या संवादांमध्ये टाइप केलेला प्रदेश निवडक जोडा.
5. डुप्लिकेट `alibaba-cn` कार्ड लपवा आणि त्याची विद्यमान कनेक्शन्स `alibaba` प्रदाता पृष्ठावर समाविष्ट करा.
6. प्रगत आणि कार्यक्षेत्र-विशिष्ट डिप्लॉयमेंट्ससाठी सानुकूल एंडपॉइंट ओव्हरराइड्स उपलब्ध ठेवा.

Token Plan मीडिया मॉडेल्स चॅट कॅटलॉगच्या बाहेर राहतात, कारण ते समर्पित एंडपॉइंट्स वापरतात.
`wan2.7-image` आणि `wan2.7-image-pro` यांची `open-sse/config/imageRegistry.ts` मध्ये नोंदणी केली आहे;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, आणि `happyhorse-1.1-r2v` यांची
`open-sse/config/videoRegistry.ts` मध्ये नोंदणी केली आहे. दोन्ही रजिस्ट्री `qwen-cloud-token-plan` कनेक्शन
ओळख आणि त्याची प्रदेश-विशिष्ट क्रेडेन्शियल्स पुन्हा वापरतात.

नियमित Qwen Cloud मध्ये `qwen-cloud` ओळखीअंतर्गत स्वतंत्र वापरानुसार-देय प्रतिमा आणि व्हिडिओ कॅटलॉग आहेत.
त्याची प्रतिमा मॉडेल्स `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03`, आणि `z-image-turbo` आहेत. त्याची व्हिडिओ
मॉडेल्स `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12`, आणि
`wan2.7-videoedit` आहेत. ही मॉडेल्स केवळ नियमित `qwen-cloud` कनेक्शन आणि प्रादेशिक
DashScope मीडिया एंडपॉइंट पुन्हा वापरतात. Token Plan आणि वापरानुसार-देय रजिस्ट्री एकमेकांच्या
मॉडेल सूची वारशाने घेत नाहीत किंवा विलीन करत नाहीत.

`bailian-coding-plan` ओळखीच्याही स्वतःच्या मीडिया अनुमतीसूची आहेत:
प्रतिमा निर्मितीसाठी `wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0`, आणि `qwen-image-2.0-pro`,
तसेच व्हिडिओ निर्मितीसाठी
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, आणि `happyhorse-1.1-r2v`.
ती केवळ Bailian Coding Plan कनेक्शन आणि प्रादेशिक Coding Plan एंडपॉइंट वापरते.
तिच्या प्रतिमा आणि व्हिडिओ रजिस्ट्री कोणत्याही Qwen Cloud प्रदात्याकडून वारसा घेत नाहीत किंवा त्यांच्याशी विलीन होत नाहीत.

नियमित `alibaba` ओळखीमध्ये स्वतंत्र प्रतिमा आणि व्हिडिओ अनुमतीसूची आहेत. तिची प्रतिमा मॉडेल्स
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo`, आणि `wan2.6-t2i` आहेत. तिची जोडलेली व्हिडिओ मॉडेल्स `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12`, आणि `wan2.7-videoedit` आहेत. ही मॉडेल्स केवळ Alibaba Model Studio
कनेक्शन आणि त्याचा निवडलेला प्रादेशिक मीडिया एंडपॉइंट वापरतात; ती कोणत्याही Coding Plan किंवा Qwen
Cloud रजिस्ट्रीमध्ये जोडली जात नाहीत.

Qwen Cloud Token Plan चॅट कॅटलॉग Individual प्लॅनच्या तंतोतंत-स्ट्रिंग मजकूर अनुमतीसूचीचे अनुसरण करतो:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2`, आणि
`deepseek-v4-pro`. Wan आणि HappyHorse नोंदी स्वतंत्र प्रतिमा/व्हिडिओ निर्मिती API मध्ये येतात.

Alibaba Token Plan त्याच्या Anthropic-सुसंगत एंडपॉइंटद्वारे तेच सहा सध्याचे मजकूर-निर्मिती मॉडेल ID उपलब्ध करतो.
त्याचा Singapore पर्याय विद्यमान `global-sg` प्रदेश की संग्रहित करतो;
केवळ वापरकर्त्याला दिसणारे लेबल, प्रदेशाला Global म्हणणाऱ्या प्रदाता कुटुंबांपेक्षा वेगळे आहे.

नियमित Qwen Cloud चॅट कॅटलॉग जाणीवपूर्वक संपूर्ण थेट मजकूर प्रतिसादापेक्षा मर्यादित आहे. त्याची
व्यवस्थापित अनुमतीसूची `open-sse/config/providers/registry/qwen-cloud/index.ts` मध्ये आहे; थेट
डिस्कव्हरी केवळ अपस्ट्रीम प्रतिसाद आणि त्या रजिस्ट्री सूची या दोन्हींमध्ये उपस्थित असलेले ID परत करते.
