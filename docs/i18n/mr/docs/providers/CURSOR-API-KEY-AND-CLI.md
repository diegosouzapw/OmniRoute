IDE सत्राशिवाय Cursor ला OmniRoute च्या मागे ठेवण्याचे दोन मार्ग:

1. **`cursor-api` provider** (कार्ड "Cursor API", उपनाव `cua`): Cursor वापरकर्ता API key (`crsr_…`, `https://cursor.com/dashboard/api` येथे व्युत्पन्न केलेली) धारण करणारा API-key provider. त्यानंतर कोणताही OmniRoute client नेहमीच्या quota, fallback आणि logging स्तरांसह `/v1/chat/completions` द्वारे `cursor-api/<model>` किंवा `cua/<model>` म्हणून Cursor models पर्यंत पोहोचतो. IDE provider (`cursor`, OAuth/IDE session) अपरिवर्तित आहे.
2. **Cursor CLI passthrough**: Cursor CLI (`agent`) ला OmniRoute कडे निर्देशित करा, जेणेकरून CLI ने केलेला प्रत्येक RPC OmniRoute API key द्वारे प्रमाणीकृत होईल, `cursor-api` connection चे credential वापरून Cursor कडे अग्रेषित केला जाईल आणि Logs पृष्ठावर नोंदवला जाईल.

## key ची अदलाबदल का केली जाते

`api2.cursor.sh` कच्चा `crsr_…` key Bearer token म्हणून नाकारते (401). Cursor CLI प्रथम key ला `/auth/exchange_user_api_key` वर POST करते आणि एका तासानंतर कालबाह्य होणारा session JWT प्राप्त करते; परत मिळालेल्या `refreshToken` मध्येही तोच `exp` असतो, त्यामुळे refresh करणे म्हणजे key ची पुन्हा अदलाबदल करणे.
`open-sse/services/cursorApiKeyAuth.ts` ही अदलाबदल करते, प्रत्येक key साठी एक session token cache करते, कालबाह्य होण्याच्या पाच मिनिटे आधी पुन्हा अदलाबदल करते आणि Cursor कडून 401 प्रतिसाद मिळाल्यास cache केलेला token काढून टाकते. `CursorExecutor`, `cursor-api` connections साठी upstream stream उघडण्याच्या अगदी आधी त्याला call करते.

## `cursor-api` provider

Registry: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, `cursor` प्रमाणेच `format`, `baseUrl` आणि
`models`). Catalog कार्ड:
`src/shared/constants/providers/apikey/specialty-media.ts`. Executor map:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

Dashboard: Providers → Cursor API → Add API key.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

त्यानंतर:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

टीपा:

- `cursor-api` साठी model सूची स्थिर Cursor registry मधून येते (IDE provider fallback म्हणून वापरते तीच सूची); OmniRoute host वर `cursor-agent` install करण्याची आवश्यकता नाही.
- `POST /api/providers/{id}/refresh-cursor` केवळ `cursor` IDE provider साठी आहे; `cursor-api` connections कडे renew करण्यासाठी IDE session नसते.

## Cursor CLI passthrough

Route: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. `/api/cursor-cli/` हा prefix
`src/shared/constants/publicApiRoutes.ts` मध्ये नोंदणीकृत आहे, कारण handler स्वतःचे authentication लागू करतो:

| Path                                                                                                                          | CLI कडून अपेक्षित auth       | OmniRoute काय करते                                                                                                                                                |
| ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                            | `Bearer <OmniRoute API key>` | key validate करते, 1h HS256 JWT (`JWT_SECRET` ने signed) तयार करते आणि तो परत करते                                                                                |
| प्रत्येक इतर path (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`          | issuer/audience/expiry verify करते, सक्रिय `cursor-api` connection निवडते, Authorization header exchanged Cursor token ने बदलते आणि प्रतिसादाचा stream परत पाठवते |

CLI तिला प्राप्त होणाऱ्या कोणत्याही token मधून `exp` decode करते, त्यामुळे तिला opaque token दिल्यास ती जवळपास प्रत्येक request पूर्वी पुन्हा अदलाबदल करते; तयार केलेला JWT हे टाळतो. OmniRoute कडून 401 मिळाल्यास CLI पुन्हा अदलाबदल करते.

### Setup

1. OmniRoute API key (Dashboard → API keys) आणि `cursor-api` connection तयार करा.
2. agent stream साठी HTTP/1.1 वापरण्याची सूचना CLI ला द्या.
   `~/.cursor/cli-config.json` मध्ये:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   याशिवाय CLI स्वतंत्रपणे configure केलेल्या agent host कडे HTTP/2 द्वारे agent turn उघडते आणि केवळ control-plane RPCs endpoint मधून जातात.

3. OmniRoute विरुद्ध CLI चालवा:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

प्रत्येक hop ची Logs मध्ये provider `cursor-api`, request type `cursor-cli`,
path `/api/cursor-cli/<rpc>` म्हणून नोंद होते आणि त्याचे श्रेय OmniRoute API key व ते serve करणाऱ्या connection ला दिले जाते.

### अपयशाचे प्रकार

| परिस्थिती                                      | CLI ला प्रतिसाद                                    |
| ---------------------------------------------- | -------------------------------------------------- |
| अज्ञात OmniRoute की आणि `REQUIRE_API_KEY=true` | एक्सचेंजवर 401 `unauthenticated`                   |
| `REQUIRE_API_KEY=false`                        | अनामिक सत्र (`/v1/*` च्या वर्तनाशी सुसंगत)         |
| कालबाह्य / परकीय / छेडछाड केलेला सत्र JWT      | 401, CLI पुन्हा एक्सचेंज करते                      |
| एक्सचेंजनंतर OmniRoute API की रद्द केली        | पुढील RPC वर 401                                   |
| सक्रिय `cursor-api` कनेक्शन नाही               | 503 `unavailable`                                  |
| Cursor ने कनेक्शनची की नाकारली                 | 401 `unauthenticated`, कॅश केलेले सत्र काढून टाकले |
| अपस्ट्रीम अगम्य                                | 502 `unavailable` (निर्जंतुक केलेला संदेश)         |
| `JWT_SECRET` सेट केलेले नाही                   | एक्सचेंजवर 503                                     |
