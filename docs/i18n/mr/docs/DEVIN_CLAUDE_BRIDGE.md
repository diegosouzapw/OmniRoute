`devin-cli-agentic` मुळे वास्तविक Claude Code runtime ला OmniRoute चा स्थानिक Anthropic
Messages endpoint वापरता येतो, तर अधिकृत Devin CLI हा ACP stdio वरून मॉडेल प्रतिसाद पुरवतो. हे
विद्यमान Anthropic, Claude OAuth, Claude Web किंवा `devin-cli` providers मध्ये बदल करत नाही.

> **सद्यस्थिती: Claude Code `2.1.258` वर पिन केलेले; offline आणि live प्रमाणीकरणाची शेवटची नोंद
> `2.1.220` वर झाली.** `2.1.220` pin ने Devin CLI
> `3000.2.17` आणि मॉडेल `swe-1-7-lightning` द्वारे तीन विलग scenarios पूर्ण केले; त्या अंतिम live run ने client च्या मालकीचे `Read`,
> `Edit`, आणि `Bash` turns, यशस्वी `npm test` परिणाम, project command आणि skill
> discovery, फक्त Devin routing, आणि शून्य Claude egress सिद्ध केले. त्यानंतर pin `2.1.258`
> पर्यंत वाढवण्यात आला (OmniRoute ची Claude identity ज्या CLI generation चे रूप धारण करते आणि
> Fable 5.1 tier मूळ स्वरूपात पुरवणारी पहिली line). नवीन pin वर install layer आणि `claude --version` हे
> pinned base image वर सत्यापित करण्यात आले, तसेच bridge unit suite, `compose config` आणि
> static isolation proof उत्तीर्ण झाले — पण offline mock scenario आणि live तीन-scenario
> suite अजून पुन्हा चालवलेले नाहीत. या pin सह bridge वर अवलंबून राहण्यापूर्वी ते पुन्हा चालवा
> ("Updating pinned tools" पहा).

## आर्किटेक्चर

```text
Claude Code 2.1.258 (विलग non-root Linux container)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-format, no-auth provider)
  -> devin acp --agent-type summarizer (अधिकृत ACP stdio, Devin tools नाहीत)
  -> समर्पित devin-auth volume मधील Devin account
```

अधिकृत CLI चा default ACP agent स्वतःची tools कार्यान्वित करू शकतो, त्यामुळे हा bridge त्याचा वापर
करत नाही. तो निश्चित `summarizer` ACP agent सुरू करतो, ज्याच्या अधिकृत CLI mode मध्ये tools नसतात, आणि
serialized Anthropic request ला execution trace म्हणून frame करतो. Claude च्या मालकीची दुसरी
action आवश्यक असल्यास, response मध्ये नेमका एक client tool envelope असणे आवश्यक आहे. कोणताही ACP
`tool_call` किंवा `tool_call_update` हा response यशस्वी म्हणून नोंदवण्यापूर्वी नाकारला जातो.

`open-sse/executors/devin-agentic/serializer.ts` मधील serializer `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice`, आणि
Claude Code ने पुरवलेली tools जतन करतो. Images आणि अज्ञात blocks स्पष्टपणे अयशस्वी होतात. मोठे tool results
दृश्यमान truncation marker वापरतात.

Parser प्रत्येक model turn साठी एक स्वतंत्र `<tool>{...}</tool>` envelope स्वीकारतो. तो
request च्या tool list शी name पडताळतो, त्या tool च्या JSON
Schema नुसार arguments validate करतो, मिश्र narrative/actions नाकारतो आणि एक मर्यादित repair करण्याची परवानगी देतो. त्यानंतर Claude Code
परिणामी Anthropic `tool_use` स्थानिकरीत्या कार्यान्वित करतो आणि `tool_result` परत
OmniRoute द्वारे पाठवतो.

## विलगीकरण आणि धोक्याचे मॉडेल

Host वरील Claude installation, account आणि configuration हे scope च्या बाहेर आहेत आणि
निषिद्ध मानले जातात. Compose services:

- UID/GID `10001:10001` म्हणून, read-only root filesystem, काढून टाकलेल्या capabilities आणि
  `no-new-privileges` सह चालतात;
- खाजगी `/home/bridge`, समर्पित Claude config volume, विलग OmniRoute data,
  आणि स्वतंत्र `devin-auth` volume वापरतात;
- फक्त तात्पुरते `.sandbox` workspaces/evidence mount करतात;
- host home, Keychain, SSH, cloud credentials किंवा Docker socket mount करत नाहीत;
- स्पष्ट environments तयार करतात आणि Anthropic API/OAuth/routing variables काढून टाकतात;
- Claude Code inference फक्त `http://omniroute:20128` कडे local-only key सह निर्देशित करतात.

Offline profile internal network वापरतो. Live profile मध्ये OmniRoute फक्त
`network-guard` द्वारे अधिकृत Devin endpoints पर्यंत पोहोचतो; असंबंधित destinations नाकारली जातात.
Claude Code साठी स्वतंत्र deny-all egress guard आहे आणि तो `NO_PROXY` द्वारे फक्त स्थानिक OmniRoute
service पर्यंत पोहोचू शकतो. Guard audit files फक्त त्यांच्या guard process द्वारे mount केल्या जातात. Scripts
token-free evidence export करण्यापूर्वी file ownership, mode, link count आणि प्रत्येक decision सत्यापित करतात.

Isolation proof स्वतंत्रपणे चालवा:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

हे topology, named mounts, non-root/read-only settings, स्पष्ट local routing,
संवेदनशील environment variables ची अनुपस्थिती, Docker socket ची अनुपस्थिती,
`api.anthropic.com` आणि `claude.ai` वरील blocked access, फक्त Devin provider selection आणि
ACP backend अनुपलब्ध असताना स्पष्ट failure validate करते.

## प्रथमच सेटअप आणि सामान्य वापर

पिन केलेली इमेज बिल्ड करा:

```bash
./scripts/devin-bridge/build
```

फक्त विलगीकृत Devin व्हॉल्यूमसाठी प्रमाणीकरण करा:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

लॉगिन कमांड रिमोट/कंटेनर वातावरणांसाठी असलेला अधिकृत मॅन्युअल-टोकन प्रवाह वापरते. मूल्य थेट CLI प्रॉम्प्टमध्ये प्रविष्ट केले जाते; ते प्रोसेस आर्ग्युमेंट म्हणून पाठवले जात नाही, Git मध्ये लिहिले जात नाही किंवा होस्टवरून कॉपी केले जात नाही.

विलगीकृत Claude Code रनटाइम सुरू करा:

```bash
./scripts/devin-bridge/launch
```

`launch` कंटेनराइझ्ड Claude Code सुरू करण्यापूर्वी विलगीकरण, Devin प्रमाणीकरण आणि मॉडेल डिस्कव्हरी पुन्हा तपासते. ते होस्टचे Claude एक्झिक्युटेबल कधीही चालवत नाही. मॉडेल उपनावे `.env.devin-bridge` मध्ये सेट करता येतात; कॉन्फिगर केलेल्या प्रत्येक मूल्यामध्ये `devin-cli-agentic/` उपसर्ग असणे आवश्यक आहे.

## प्रमाणीकरण कमांड्स

पुनरुत्पादनीय ऑफलाइन मार्गासाठी Devin खाते आवश्यक नाही आणि त्याला रनटाइम इंटरनेट प्रवेश नसतो:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

प्रमाणीकृत, स्वेच्छेने सक्षम करावयाचा लाइव्ह मार्ग असा आहे:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

एकाच वेळी मोठ्या संख्येने ACP सेशन्स उघडणे टाळण्यासाठी लाइव्ह रनर प्रत्येक परिदृश्यादरम्यान प्रतीक्षा करतो आणि मजकूररूपी दाव्यांवर विश्वास ठेवण्याऐवजी संरचित Claude स्ट्रीम इव्हेंट्सचे प्रमाणीकरण करतो. त्याची तीन परिदृश्ये पुढील बाबी सिद्ध करतात:

1. थेट प्रोजेक्ट रीड्स आणि दोष विश्लेषण;
2. प्रत्यक्ष `Edit`, क्लायंटच्या मालकीचे `Bash` `npm test` आणि टर्मिनल परिणाम;
3. `/bridge-check` तसेच `bridge-proof` डिस्कव्हरी, प्रोजेक्ट रीड्स, क्लायंटच्या मालकीचे आणखी एक यशस्वी `npm test` आणि कोणतेही काम प्रलंबित न ठेवता पूर्णता.

अंतिम गेट Devin नेटवर्क ऑडिटही तपासते आणि Claude इग्रेस ऑडिट रिकामे राहणे आवश्यक ठरवते.

## पिन केलेली साधने अपडेट करणे

इमेजमध्ये Node, Claude Code आणि Devin CLI यांच्या आवृत्त्या `docker/devin-bridge/Dockerfile` मध्ये पिन केल्या आहेत. अपडेट करण्यासाठी:

1. स्पष्टपणे नमूद केलेल्या आवृत्त्या बदला;
2. दोन्ही आर्किटेक्चर-विशिष्ट Devin आर्काइव्ह चेकसम्स अधिकृत आर्टिफॅक्टच्या मूल्यांनी बदला;
3. पुन्हा बिल्ड करा आणि प्रत्येक ऑफलाइन प्रमाणीकरण कमांड चालवा;
4. इमेजमधील आवृत्त्यांची पुष्टी करा;
5. प्रमाणीकृत तीन-परिदृश्य लाइव्ह संच पुन्हा चालवा.

कोणतेही CLI होस्टवर ग्लोबली इन्स्टॉल करू नका किंवा चेकसम पडताळणीच्या जागी पडताळणी न केलेले डाउनलोड वापरू नका.

## निदान आणि साफसफाई

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  स्थानिक राउटिंग आणि निर्जंतुक केलेल्या एक्झिक्युटर त्रुटी दाखवते.
- `.sandbox/evidence/mock-acp.jsonl` निर्धारक मॉक ACP क्रियांची नोंद ठेवते.
- `.sandbox/evidence/claude-stream.jsonl` प्रत्यक्ष Claude Code ऑफलाइन रनची नोंद ठेवते.
- `.sandbox/evidence/live-*.jsonl` तीन प्रमाणीकरण केलेल्या लाइव्ह स्ट्रीम्सची नोंद ठेवते.
- `.sandbox/evidence/egress.jsonl` आणि `.sandbox/evidence/claude-egress.jsonl` या गार्ड ऑडिट्सच्या प्रमाणीकरण केलेल्या, टोकन-मुक्त प्रती आहेत.

लॉगिन/कॉन्फिग व्हॉल्यूम्स जतन करून, मालकीचे कंटेनर्स आणि नेटवर्क्स थांबवा:

```bash
./scripts/devin-bridge/clean
```

नेम्ड व्हॉल्यूम्ससह ब्रिजच्या मालकीचे संपूर्ण वातावरण काढून टाका:

```bash
./scripts/devin-bridge/clean --all
```

## मर्यादा

- हा ब्रिज निश्चित, साधने नसलेल्या `summarizer` भूमिकेवर अवलंबून आहे, कारण Devin CLI `3000.2.17`
  तटस्थ, साधने नसलेला ACP एजंट उपलब्ध करून देत नाही. अॅडॅप्टर सारांशासारख्या
  मध्यवर्ती प्रतिसादांची भरपाई करतो, परंतु मर्यादित दुरुस्तीचा एक प्रयत्न तरीही स्पष्टपणे अयशस्वी होऊ शकतो.
- प्रत्यक्ष ACP कॉल्समधून तात्पुरते `502`/`504` प्रतिसाद मिळू शकतात. हार्नेस परिस्थितींमध्ये अंतर ठेवतो;
  सातत्यपूर्ण अपयश झाल्यास तो बंदच राहतो आणि दुसरा प्रदाता कधीही निवडत नाही.
- प्रत्येक Anthropic विनंतीवरून ACP संदर्भाची पुनर्रचना केली जाते; कोणतीही प्रक्रिया/सत्र
  संलग्नता नसते.
- प्रत्येक मॉडेल प्रतिसादामध्ये एका साधन कॉलला समर्थन आहे; समांतर कॉल्स नाकारले जातात.
