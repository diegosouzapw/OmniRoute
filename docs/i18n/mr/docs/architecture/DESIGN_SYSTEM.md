> **स्थिती:** संदर्भ — येथे वर्णन केलेले प्रमाणीकरण **अंमलात आणले आहे** (टप्पे 1–6: ग्रिड वॉलपेपर, प्रिमिटिव्ह्ज, स्थिती-रंग केंद्रीकरण, मोनो टोकन, DataTable टोकन स्थलांतर, focus-ring → accent, Checkbox/Textarea प्रिमिटिव्ह्ज, `cn()` → tailwind-merge, प्रत्येक स्वतंत्र स्क्रीनवर ग्रिड, फ्लुइड 4K कंटेंट शेल, अपारदर्शक डेटा-टेबल पृष्ठभाग). हा दस्तऐवज डॅशबोर्डच्या डिझाइन टोकन्स, घटक आणि पद्धतींचे प्रमाणित वर्णन आहे; प्रत्येक निर्णयामागील कारणमीमांसा म्हणून खालील टप्प्यांची मांडणी कायम ठेवली आहे.
> **व्याप्ती:** OmniRoute डॅशबोर्ड (`src/`) आणि मार्केटिंग साइट (`_mono_repo/omnirouteSite/`) यांची **एकच दृश्य ओळख** आहे — समान ग्राफ-पेपर ग्रिड पार्श्वभूमी (32px), समान रंग टोकन्स आणि प्रमाणित घटक.
>
> देखभालकर्त्यांसाठी व्यावहारिक नोंदी:
>
> - उरलेली काही हार्डकोड केलेली हेक्स मूल्ये **हेतुपुरस्सर** आहेत (नेहमी-गडद कन्सोल टर्मिनल, ReactFlow SVG स्ट्रोक्स) आणि त्यांचे टोकन्समध्ये स्थलांतर **करू नये**.
> - चालू इन्स्टन्सवरील "मोठे" ग्रिड हे जुन्या बिल्डमुळे दिसते, कोडमुळे नाही — ग्रिडचा आकार 32px आहे आणि तो साइटसारखाच आहे.
> - गडद थीममधील `--table-*` मूल्ये स्थलांतरापूर्वीच्या हार्डकोड केलेल्या rgba मूल्यांशी बाइट-टू-बाइट समान आहेत; फिकट थीम दुरुस्त केली आहे (निष्प्रभ `var()` फॉलबॅक्समुळे ती त्रुटीपूर्वक नेहमी गडद होती).

## 1. उद्देश

मार्केटिंग साइट (`viral.omniroute.online`, `why.omniroute.online`, `omniroute.online`) आणि उत्पादन डॅशबोर्ड हे **एकाच उत्पादनासारखे** दिसले पाहिजेत. साइटने तिची रंगसंगती आधीच डॅशबोर्डवरून घेतली आहे — तिच्या `css/tokens.css` मध्ये तर _"रंगसंगती OmniRoute डॅशबोर्डचे प्रतिबिंब आहे (src/app/globals.css)"_ असेही म्हटले आहे. त्यामुळे रंगांच्या पातळीवर दोन्ही आधीच सुमारे 80% सुसंगत आहेत. डॅशबोर्डमध्ये पुढील गोष्टींची कमतरता आहे:

1. साइट प्रत्येक पृष्ठावर वापरत असलेला **ग्राफ-पेपर ग्रिड वॉलपेपर**.
2. साइटवर असलेले, पण डॅशबोर्डमध्ये नसलेले काही **सामायिक डिझाइन टोकन्स** (त्रिज्या श्रेणी, ब्रँड ग्रेडियंट, `surface-2`, मोनो फॉन्ट).
3. **घटक-स्तरीय सुसंगतता** — डॅशबोर्डमधील अनेक घटक हार्डकोड केलेल्या हेक्स/rgba मूल्यांमुळे थीम टोकन्सना वगळतात.

हा दस्तऐवज विश्लेषण आणि योजना आहे.

## 2. तत्त्वे

- **सत्याचा एकमेव स्रोत = `src/app/globals.css`.** साइट नेहमी डॅशबोर्डचे प्रतिबिंब ठेवते, उलट नाही. नवीन टोकन्स प्रथम `globals.css` मध्ये जोडले जातात.
- **लिटरल्स नव्हे, नेहमी टोकन्स.** घटक कच्च्या `#hex` ऐवजी अर्थपूर्ण टोकन्स (`bg-surface`, `text-primary`, `border-border`) वापरतात.
- **सूक्ष्म, भडक नाही.** ग्रिड हा कंटेंटच्या मागे असलेला हलका वॉलपेपर आहे — त्याने मजकुराचा कॉन्ट्रास्ट कधीही कमी होता कामा नये किंवा UI शी स्पर्धा करता कामा नये.
- **थीम-जागरूक.** सर्व काही `.dark` (उत्पादनाची वैशिष्ट्यपूर्ण दृश्यशैली) आणि फिकट अशा दोन्ही थीममध्ये कार्य करते.
- **नेमकी टप्प्याटप्प्याने अंमलबजावणी.** प्रथम ग्रिड + टोकन्स (कमी जोखीम, उच्च दृश्य परिणाम) प्रकाशित करा, त्यानंतर घटकांची सुधारणा टप्प्याटप्प्याने करा.

### 3.3 थीमिंगची कार्यपद्धती (जेणेकरून आपण काहीही बिघडवणार नाही)

- **Tailwind v4, CSS-प्रथम** (`tailwind.config.*` नाही). टोकन्स `:root`/`.dark` मध्ये परिभाषित केले आहेत आणि `@theme inline` द्वारे युटिलिटीजसाठी उपलब्ध केले आहेत (`globals.css:130-179`).
- `<html>` वरील **`.dark` क्लासद्वारे गडद थीम** (`globals.css:22` येथे `@custom-variant dark`), कस्टम Zustand स्टोअरद्वारे (`src/store/themeStore.ts`) टॉगल केली जाते, डीफॉल्ट थीम = `system` (`src/shared/constants/appConfig.ts:11`). त्याऐवजी साइट `html[data-theme="light"]` वापरते — **कार्यपद्धती वेगळ्या आहेत आणि त्यांचा कधीही परस्पर संबंध येत नाही** (स्वतंत्र origins), त्यामुळे कोणताही संघर्ष नाही. आपण डॅशबोर्डची `.dark` कार्यपद्धती कायम ठेवतो.
- **रनटाइम प्राथमिक ओव्हरराइड** उपलब्ध आहे (`themeStore.ts:85-97`, `COLOR_THEMES` मधील प्रीसेट्स) — वापरकर्ते `--color-primary` बदलू शकतात. `--color-primary` चा संदर्भ देणारे कोणतेही नवीन टोकन (ग्रेडियंट इ.) हे ओव्हरराइड्स आपोआप वारशाने प्राप्त करते. ✅
- **Tailwind v4 मधील आरक्षित त्रिज्या नावे:** `--radius-sm/md/lg/...` ही `rounded-*` युटिलिटीजना आधार देतात. त्यांची पुनर्व्याख्या केल्यास अस्तित्वातील प्रत्येक `rounded-*` पूर्वलक्षी प्रभावाने बदलते (उदा. `rounded-sm` 12 फाइल्समध्ये वापरले आहे). म्हणून लहान-त्रिज्या मूल्य आणि घटक पुनर्निर्देशन जाणीवपूर्वक टप्पा 2 पर्यंत पुढे ढकलले आहे, जिथे वापरकर्तेही त्याचवेळी बदलतील.

## 4. भाग A — ग्राफ-पेपर ग्रिड पार्श्वभूमी (मुख्य मागणी) — अंमलात आणले (टप्पा 1)

### 4.1 हे काय आहे

साइटवरील अचूक कृती (`_mono_repo/omnirouteSite/css/base.css`): दोन 1px रेषीय ग्रेडियंट रेखाटणारा, सर्व सामग्रीच्या मागे `z-index:-1` वर असलेला **स्थिर, संपूर्ण-व्ह्यूपोर्ट pseudo-element**.

```css
body::before {
  content: "";
  position: fixed;
  inset: 0;
  z-index: -1;
  pointer-events: none;
  background-image:
    linear-gradient(to right, var(--grid-line) 1px, transparent 1px),
    linear-gradient(to bottom, var(--grid-line) 1px, transparent 1px);
  background-size: var(--grid-size) var(--grid-size);
}
```

**`body` चा `background-color` अपारदर्शक असूनही हे का कार्य करते:** `z-index:-1` असलेला `::before`, एलिमेंटच्या स्वतःच्या पार्श्वभूमीच्या _वर_, पण त्याच्या इन-फ्लो सामग्रीच्या _खाली_ रेखाटला जातो. त्यामुळे `--color-bg` हा मूलभूत भराव असतो, त्यावर ग्रिडचा थर असतो आणि ॲप ग्रिडच्या वर रेंडर होते.

### 4.2 कोडबेसमध्ये आधीपासून असलेला दाखला

`src/app/landing/page.tsx:16-26` **आधीपासूनच प्रत्येक पृष्ठावर हाच ग्रिड अंमलात आणते** — पण **लाल** रेषांसह (`#E54D5E`, अपारदर्शकता `0.06`), **50px** अंतरावर, तसेच ॲनिमेटेड गोलकांसह. त्यामुळे हा पॅटर्न उत्पादनात सिद्ध झालेला आहे; हे काम त्याला **जागतिक, थीम-जागरूक** वॉलपेपरमध्ये रूपांतरित करते.

- **D9 — अपारदर्शक डेटा टेबल्स (टप्पा 6):** dashboard चे content क्षेत्र आता पारदर्शक असल्यामुळे (जेणेकरून ग्रिड वॉलपेपर आरपार दिसतो, टप्पा 5), ज्यांचा container अपारदर्शक पृष्ठभाग नव्हता अशा डेटा टेबल्सच्या पारदर्शक सम-पंक्ती / कमी-alpha zebra मधून ग्रिड आरपार दिसत होता. ✅ **पूर्ण** — प्रत्येक card-विरहित टेबल आता `bg-surface` रंगवते (किंवा `<DataTable>` मूलभूत घटकाच्या बाबतीत, त्याच्या scroll container वर `background: var(--color-surface)`). दुरुस्त केलेले: `DataTable` (मूलभूत घटक), `ProxyLogger`/`RequestLoggerV2` (त्यांच्या `<Card>` चा `bg-black/5 dark:bg-black/20` tint, tailwind-merge मुळे Card च्या `bg-surface` वर प्राधान्य मिळवत होता → ~95% पारदर्शक), `BatchListTab`/`FilesListTab`/`CacheEntriesTab`/`ReasoningCacheTab`/`cache page`/`FreePoolTab`/`ModelMappingTable`/`HeaderTable`, तसेच cache views मधील दोन CSS-grid "टेबल्स" (`bg-surface/35` → `bg-surface`). आधीपासून `<Card>`/Modal मध्ये असलेली टेबल्स अपारदर्शक असल्याचे पडताळले आणि हेतुपुरस्सर अस्पर्शित ठेवले (तेथील bg-surface ही अनावश्यक no-op आहे). ग्रिडमध्ये स्वतः **कोणताही बदल आवश्यक नव्हता** — dashboard `body::before` साइटशी byte-identical आहे (`--grid-size: 32px`); चालू instance वर दिसणारा कोणताही "मोठा ग्रिड" हा कोड नसून `#4143`-पूर्वीचा शिळा build आहे. `tests/unit/design-grid-background.test.ts` द्वारे संरक्षित (टप्पा 6 ब्लॉक).
