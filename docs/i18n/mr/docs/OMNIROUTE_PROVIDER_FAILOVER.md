पुनर्प्रयत्नाचे निर्णय घेण्यापूर्वी अपयशांचे वर्गीकरण केले जाते.

टाइमआउट, नेटवर्क त्रुटी, दर मर्यादा आणि प्रदात्याचे 5xx प्रतिसाद यांसारख्या तात्पुरत्या अपयशांमध्ये पर्यायी प्रदात्याकडे प्रक्रिया वळवली जाऊ शकते. प्रमाणीकरण त्रुटी, परवानगी त्रुटी, अवैध विनंत्या, अनुपलब्ध मॉडेल्स आणि अज्ञात अपयशांसाठी आंधळेपणाने पुनर्प्रयत्न केले जात नाहीत.

डीफॉल्ट क्रॉस-प्रोव्हायडर धोरण जास्तीत जास्त तीन प्रदाता-प्रयत्नांना अनुमती देते, दर मर्यादा आणि टाइमआउटसाठी पुनर्प्रयत्न करते आणि प्रशासकीय अक्षमकरण तात्पुरत्या सर्किट स्थितीपासून वेगळे ठेवते.

सर्किटच्या स्थिती `closed`, `open` आणि `half_open` अशा आहेत. कूलडाउननंतर मर्यादित तपासणी नियोजित केली जाते; यशस्वी तपासणी सर्किट बंद करते आणि अयशस्वी तपासणी ते पुन्हा उघडते.
