1. विद्यमान एकल-की सेमाफोर करार आणि नवीन अणुस्वरूपी बहु-की करार यांना लक्षित चाचण्यांनी सुनिश्चित करा: अंशतः आरक्षणे नसणे, FIFO रांगेत लावणे, रद्द करणे, कालबाह्यता, रांग पूर्ण असणे, पुनरावृत्ती-सुरक्षित मुक्तता, आकडेवारी आणि स्वच्छता.
2. विद्यमान खाते सेमाफोरचे त्याच ठिकाणी सामान्यीकरण करा. `acquire()` ला `acquireMany()` भोवती सुसंगतता आवरण म्हणून कायम ठेवा; दुसरा शेड्युलर किंवा अवलंबित्व जोडू नका.
3. `chatCore` मधील केवळ-खाते अधिग्रहणाऐवजी `withRateLimit` च्या त्वरित आधी एक संचयी जागतिक/प्रदाता/खाते अधिग्रहण वापरा. खाते रोटेशनमुळे कनेक्शन बदलल्यास प्रत्येक वेळी संपूर्ण संच पुन्हा अधिग्रहित करा आणि स्ट्रीमिंग पूर्ण होईपर्यंत मुक्तता रोखून ठेवा.
4. विद्यमान लवचिकता सेटिंग्ज पाइपलाइनमध्ये (प्रकार, डीफॉल्ट्स, सामान्यीकरण, स्कीमा, API प्रतिसाद, UI आणि भाषांतरे) जागतिक आणि प्रदाता मर्यादा जोडा. जुन्या Bottleneck समवर्ती नियंत्रणाला कनेक्शन/कोटा-व्याप्ती समवर्ती नियंत्रण असे नवीन लेबल द्या, जेणेकरून त्याची वास्तविक व्याप्ती स्पष्ट होईल.
5. लक्षित चाचण्या, लिंट, प्रकार-तपासणी, स्थिर तपासण्या आणि संपूर्ण चाचणी संच चालवा; वर्तनातील बदलाची चेंजलॉगमध्ये नोंद करा.

जाणीवपूर्वक जतन केलेले वर्तन: शून्य/null समवर्ती मर्यादा गेटला वगळते, केवळ-खाते कॉलर `acquire()` वापरणे सुरू ठेवतात, अवरोधित-खाते नियंत्रणे त्यांचे की स्वरूप आणि API कायम ठेवतात आणि प्रदाता दर-मर्यादा रांगेचे वर्तन अपरिवर्तित राहते.
