## 1. सेवेबाबतचे अधिकृत सत्य (अधिकृत दस्तऐवज, परस्पर पडताळलेले)

- बेस URL: `https://api.anysearch.com` (REST) + `POST /mcp` (MCP, JSON-RPC 2.0).
- `POST /v1/search` - पॅरामीटर्स: `query` (आवश्यक), `max_results` (1-10, डीफॉल्ट 10), `tag` (`{domain}.{sub_domain}` अनुलंब रूटिंग), `zone` (cn/intl), `language`, `params` (संरचित अनुलंब फील्ड्स), `format` (json/markdown).
- `GET /v1/sub-domains?domain=...` - क्षमता कॅटलॉग, कोट्यामध्ये मोजले जात नाही.
- `POST /v1/extract` - `{url, title, content}` फेच/एक्स्ट्रॅक्ट करते; कठोर JSON बॉडी, 16 KiB मर्यादा.
- `POST /v1/auth/email/register` - एकाच कॉलमध्ये नोंदणी, एकदाच वापरता येणारी साध्या मजकुरातील की `as_sk_...` परत करते.
- प्रमाणीकरण: पर्यायी `Authorization: Bearer <as_sk_...>`; अनामिक वापर प्रति-IP मर्यादांपर्यंत अवनत होतो आणि दैनंदिन मोफत कोटा वापरतो; अवैध की असल्यास कोणत्याही मूक अनामिक फॉलबॅकशिवाय 401/403 परत येते.
- मोफत स्तर: दररोज 1000 विनंत्या, प्रति की 20 QPS. सशुल्क स्तर: किंमत अद्याप निश्चित नाही (लवकरच उपलब्ध).
- प्रतिसाद आवरण: यशस्वी `{code: 0, message: "success", request_id, data}`; अयशस्वी `{code: -1, message}`. प्रमाणीकरण/कोटा त्रुटींमध्ये संरचित `error_code` नसतो (`message` मजकूर हाच संकेत असतो); एक्स्ट्रॅक्ट-विशिष्ट त्रुटींमध्ये `error_code` असतो (`invalid_extract_url`, `extract_failed`). 429 प्रतिसादावर `Retry-After` हेडर नसतो.

## 3. निर्णय (सर्व 2026-08-26 रोजी घेतले)

1. **राउटिंग धोरण: `fallbackOnly`.** कारण: शून्य खर्चाचा मोफत प्रदाता स्वयंचलित खर्च-आधारित राउटिंगमध्ये कधीही वरचढ ठरू नये; स्पष्ट निवड आणि फेलओव्हरनंतर परत येण्याची प्रक्रिया अप्रभावित राहते. पूर्वोदाहरण: विलीन केलेली xquik नोंद.
2. **व्याप्ती: v1 मध्ये `POST /v1/extract` द्वारे webSearch + webFetch.** tavily/exa च्या दुहेरी-क्षमता मानसिक मॉडेलशी सुसंगत. उभ्या विभागांशी संबंधित पृष्ठभाग (`tag`, `sub-domains`, `batch_search`) व्याप्तीबाहेर राहतील — सध्या उभ्या विभागांच्या पॅरामीटर्ससाठी कोणतेही IR उपलब्ध नाही.
3. **कोटा प्रदर्शन: `freeMonthlyQuota: 0`** (xquik-शैलीतील सावध प्रदर्शन). वास्तविक मर्यादा (दररोज 1000 विनंत्या, दररोज रीसेट) त्याऐवजी UI कॅटलॉगमधील `authHint` मजकुरात दिली जाते. कारण: कोटा प्रदर्शन रीसेटच्या अर्थपद्धतीशी जुळले पाहिजे; दैनिक मर्यादेचे मासिक-समतुल्य मूल्यात (30000) रूपांतर करणे हे UI पूर्ण करू शकत नसलेले खोटे आश्वासन ठरेल.
4. **searchTypes: फक्त `["web"]`.** AnySearch API मध्ये बातम्या/प्रतिमांसाठी स्वतंत्र उभा विभाग असल्याचा कोणताही सार्वजनिक पुरावा नाही; दस्तऐवजीकरण नसलेल्या उभ्या विभागासह API समाकलित करणारे गेटवे (उदा. Google Custom Search) news -> web चे मूक मॅपिंग करण्याऐवजी फक्त web उपलब्ध करतात.
5. **कीविषयक धोरण:** कीशिवाय वापर चालतो; अवैध कीमुळे 401/403 प्रतिसाद मिळतो आणि तो कधीही मूकपणे अनामिक प्रवेशात अवनत केला जात नाही (अपस्ट्रीम कराराशी सुसंगत).
6. **जाणीवपूर्वक वगळलेले घटक:** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (चॅट इंटरसेप्शन firecrawl/jina/tavily वरच राहते); `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (अनामिक रिमोट एंडपॉइंट्स प्रत्येक ईग्रेस IP साठी एकच IP-मर्यादित पूल सामायिक करतात, त्यामुळे कीशिवाय extract वापरणे निवडाधारित आहे, स्वयंचलित राउटिंगसाठी उमेदवार नाही); `QUOTA_STATUS_PROVIDERS` (AnySearch कोट्याची स्थिती 402/403 स्टेटसद्वारे नव्हे, तर 429/एन्व्हलपद्वारे दर्शवते).
