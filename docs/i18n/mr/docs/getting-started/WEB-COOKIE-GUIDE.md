Web Cookie प्रदाते OmniRoute ला API key ऐवजी तुमच्या विद्यमान ब्राउझर सत्राद्वारे AI सेवा वापरण्याची परवानगी देतात. तुम्हाला एखाद्या सेवेच्या वेबसाइटद्वारे आधीपासूनच प्रवेश असेल आणि OmniRoute ने तेच प्रमाणीकृत सत्र वापरावे असे वाटत असेल, तेव्हा हे उपयुक्त ठरतात.

API-key प्रदात्यांपेक्षा वेगळे, Web Cookie प्रदाते तुमचा ब्राउझर वेबसाइटला पाठवत असलेल्या क्रेडेन्शियल्सचा वापर करून प्रमाणीकरण करतात.

# सुरुवात करण्यापूर्वी

> **महत्त्वाचे:** क्रेडेन्शियल्स नेहमी **सक्रिय नेटवर्क विनंतीमधून** कॉपी करा, तुमच्या ब्राउझरच्या cookie storage मधून **नाही**.

चुकीच्या ठिकाणाहून cookies कॉपी केल्यामुळे प्रमाणीकरणाशी संबंधित अनेक समस्या उद्भवतात.

## Cookie Storage मधून कॉपी करू नका

बहुतेक ब्राउझरमध्ये संग्रहित cookies पुढील मार्गाने पाहता येतात:

```
DevTools
→ Application (किंवा Storage)
→ Cookies
```

या cookies योग्य दिसत असल्या, तरी त्या पुढीलप्रमाणे असू शकतात:

- कालबाह्य
- अपूर्ण
- केवळ प्रमाणीकृत विनंत्यांसोबत पाठवल्या जाणाऱ्या cookies नसलेल्या

ही मूल्ये वापरल्यास ती वैध दिसत असली, तरी प्रमाणीकरण अयशस्वी होऊ शकते.

## सक्रिय विनंतीमधून कॉपी करा

त्याऐवजी, यशस्वी विनंतीमधील cookies वापरा:

```
DevTools
→ Network
→ पृष्ठ रीफ्रेश करा
→ chat किंवा conversation विनंती उघडा
→ Request Headers
→ Cookie
```

`Cookie` request header मध्ये तुमच्या ब्राउझरने यशस्वीरीत्या वापरलेली नेमकी प्रमाणीकरण माहिती असते.

बहुतेक Web Cookie प्रदात्यांसाठी, हेच मूल्य OmniRoute मध्ये पेस्ट केले पाहिजे.

# सर्वसाधारण सेटअप

बहुतेक Web Cookie प्रदात्यांसाठी सेटअप प्रक्रिया सारखीच असते.

1. प्रदात्याच्या वेबसाइटवर साइन इन करा.
2. ब्राउझरचे Developer Tools उघडा.
3. **Network** टॅब उघडा.
4. पृष्ठ रीफ्रेश करा.
5. प्रमाणीकृत chat किंवा conversation विनंती उघडा.
6. आवश्यक प्रमाणीकरण क्रेडेन्शियल्स कॉपी करा.
7. OmniRoute उघडा.
8. **Providers → Add Provider** येथे जा.
9. तुमचा Web Cookie प्रदाता निवडा.
10. क्रेडेन्शियल्स पेस्ट करा.
11. **Test Connection** वर क्लिक करा.
12. प्रदाता जतन करा.

आवश्यक असलेली नेमकी क्रेडेन्शियल्स प्रदात्यावर अवलंबून असतात.

# प्रदात्यांच्या क्रेडेन्शियलचे स्वरूप

वेगवेगळ्या वेबसाइट्स प्रमाणीकरणाची माहिती वेगवेगळ्या प्रकारे संग्रहित करतात. काहींना केवळ cookies आवश्यक असतात, तर इतरांना अतिरिक्त headers किंवा tokens आवश्यक असू शकतात.

| प्रदाता                         | क्रेडेन्शियलचे स्वरूप         | प्रदाता मार्गदर्शक               |
| ------------------------------- | ----------------------------- | -------------------------------- |
| Claude Web                      | संपूर्ण Cookie request header | `docs/providers/CLAUDE_WEB.md`   |
| ChatGPT Web (Codex)             | संपूर्ण Cookie header         | `docs/providers/CHATGPT_WEB.md`  |
| Gemini Web                      | _(पडताळा)_                    |                                  |
| Copilot Web                     | _(पडताळा)_                    | `docs/providers/COPILOT-M365.md` |
| Microsoft 365 Copilot (BizChat) | WS access_token + chathubPath | `docs/providers/COPILOT-M365.md` |
| Grok Web                        | _(पडताळा)_                    |                                  |
| ...                             | ...                           | ...                              |

> नवीन Web Cookie प्रदाते जोडले गेल्यावर किंवा विद्यमान प्रदात्यांच्या प्रमाणीकरण आवश्यकता बदलल्यावर हा तक्ता अद्ययावत करा.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) हे नोंदणीची आवश्यकता नसलेले एक विनामूल्य ग्राहक चॅट प्लॅटफॉर्म आहे — पहिल्या भेटीवेळी सत्र अनामिकपणे तयार केले जाते आणि ते `uid`, `si_usr_id`, व `si_ses_id` या तीन कुकीजद्वारे कायम राहते. OmniRoute एकाच मॉडेल आयडीद्वारे (`notrack-c`, उपनाव `ntw`) समान `/api/dispatch` एंडपॉइंट प्रॉक्सी करते.

### कनेक्ट करण्याच्या पायऱ्या

1. तुमच्या ब्राउझरमध्ये [notrack.ai](https://notrack.ai) उघडा आणि अनामिक सत्र कुकी सेट होऊ द्या.
2. **DevTools → Network** उघडा, पृष्ठ रिफ्रेश करा आणि कोणत्याही `/api` विनंतीवर क्लिक करा.
3. **Request Headers** मध्ये, संपूर्ण `Cookie` हेडरचे मूल्य कॉपी करा.
4. OmniRoute मध्ये, **Providers → Add Provider → NoTrack Web (Free)** येथे जा.
5. कुकी स्ट्रिंग `apiKey` फील्डमध्ये पेस्ट करा आणि **Save** करा.

OmniRoute पेस्ट केलेल्या स्ट्रिंगमधून `uid`, `si_usr_id`, आणि `si_ses_id` काढते व केवळ त्या जोड्यांसह स्वच्छ `Cookie` हेडर पुन्हा तयार करते — तसेच उपलब्ध असल्यास `nt_session` (लॉग-इन केलेल्या खात्यांसाठी सेट केलेले `ntk_…` टोकन) जोडते. या तिघांपैकी कोणतेही एक गहाळ असल्यास, ऑपरेटरना पर्यायी स्वरूपांसह प्रयोग करता यावा म्हणून पेस्ट केलेली मूळ स्ट्रिंग कोणताही बदल न करता पुढे पाठवली जाते.

### मॉडेल आयडी

| मॉडेल आयडी  | प्रदर्शित नाव | नोंदी                                               |
| ----------- | ------------- | --------------------------------------------------- |
| `notrack-c` | NoTrack C     | डीफॉल्ट — अपस्ट्रीम डिस्पॅच मॉडेल `C`.              |
| `C`         | NoTrack C     | `notrack-c` साठी उपनाव (मूळ अपस्ट्रीम डिस्पॅच कोड). |
| `notrack`   | NoTrack C     | `notrack-c` साठी उपनाव.                             |
| `ntw`       | NoTrack C     | `notrack-c` साठी संक्षिप्त उपनाव.                   |

सर्व चार मॉडेल आयडी एकाच अपस्ट्रीम डिस्पॅच मॉडेलशी (`C`) मॅप होतात.

### विनंती पर्याय

एक्झिक्युटर विनंती बॉडीमध्ये पुढील पर्यायी फील्ड स्वीकारतो:

| बॉडी फील्ड            | डीफॉल्ट | उद्देश                                                                    |
| --------------------- | ------- | ------------------------------------------------------------------------- |
| `notrack_mode`        | `usual` | डिस्पॅच मोड (मुक्त-स्वरूप स्ट्रिंग; अपस्ट्रीम `usual`, … स्वीकारते)       |
| `notrack_max_turns`   | `6`     | उत्तर देण्यापूर्वी अपस्ट्रीम घेऊ शकणाऱ्या अंतर्गत टर्न्सची संख्या.        |
| `notrack_chat_id`     | `null`  | विद्यमान अपस्ट्रीम चॅट पुन्हा सुरू करा (नवीन चॅटसाठी वगळा).               |
| `notrack_attachments` | `[]`    | अपस्ट्रीम अटॅचमेंट वर्णनकर्त्यांचा पास-थ्रू अॅरे.                         |
| `notrack_regenerate`  | `false` | मागील टर्नसाठी पुन्हा व्युत्पन्न केलेले उत्तर मागण्यासाठी `true` सेट करा. |

### क्षमता

- **स्ट्रीमिंग आणि नॉन-स्ट्रीमिंग** चॅट पूर्णता.
- **टूल कॉलिंग** — विनंतीवर `tools: [...]` सेट करा; एक्झिक्युटर त्यांना टूल-कॉल एन्व्हलप करारामध्ये क्रमबद्ध करतो आणि मॉडेलचे प्रतिसाद पुन्हा OpenAI `tool_calls` मध्ये पार्स करतो.
- **`response_format`** — `json_object` आणि `json_schema` समर्थित आहेत. एक्झिक्युटर मॉडेलच्या उत्तरामधून पहिला JSON ऑब्जेक्ट काढतो आणि परत करण्यापूर्वी त्याचे स्ट्रिंगमध्ये रूपांतर करतो.
- **रीझनिंग संकेत** — अपस्ट्रीमने `thinking` इव्हेंट पाठवल्यावर एक्झिक्युटर `reasoning` डेल्टा उत्सर्जित करतो.

### मर्यादा

- अपस्ट्रीम अनामिक वापरासाठी कोटा लागू करते — तो ओलांडल्यास, एक्झिक्युटर सोप्या संदेशासह 429 दर्शवतो.
- सर्व मॉडेल आयडी एकाच अपस्ट्रीम डिस्पॅच मॉडेलमध्ये निराकरण होतात; प्रत्येक मॉडेलसाठी स्वतंत्र स्विच उपलब्ध नाही.
- एक्झिक्युटर अपस्ट्रीमच्या `/api/chats` एंडपॉइंटला कॉल करत नाही, त्यामुळे चॅट इतिहास / सत्रे स्वयंचलितपणे व्यवस्थापित केली जात नाहीत. विद्यमान अपस्ट्रीम चॅट पुन्हा सुरू करण्यासाठी `notrack_chat_id` वापरा.

# वेब कुकी प्रदाते काय करू शकतात आणि काय करू शकत नाहीत

वेब कुकी प्रदाते वेबसाइटचा चॅट इंटरफेस पुन्हा वापरतात. ते अधिकृत API सारख्या **समान** क्षमता पुरवत नाहीत.

## समर्थित

- आपल्या विद्यमान ब्राउझर सत्राचा वापर करून प्रमाणीकरण करणे
- आपल्या खात्यामार्फत उपलब्ध असलेल्या मॉडेल्समध्ये प्रवेश करणे
- चॅट प्रतिसाद प्रवाहित करणे
- API की आवश्यक नाही

## असमर्थित

- फंक्शन कॉलिंग
- टूल कॉलिंग
- स्वयंचलित फाइल संपादन
- एजंटिक IDE कार्यप्रवाह
- केवळ API द्वारे उपलब्ध वैशिष्ट्ये

हे अपेक्षित वर्तन आहे आणि हा **बग नाही**.

आपल्याला टूल कार्यान्वयन, स्वयंचलित फाइल संपादन किंवा इतर एजंट कार्यप्रवाहांची आवश्यकता असल्यास, Web Cookie प्रदात्याऐवजी **API-key प्रदाता** वापरा.

# प्रमाणीकरणासंबंधी मर्यादा

यशस्वी **Test Connection** किंवा कुकी प्रमाणीकरण केवळ इतकेच पडताळते की प्रदान केलेली क्रेडेन्शियल्स अपेक्षित स्वरूपात असल्याचे दिसते.

Issue #7857 चे निराकरण होईपर्यंत, यशस्वी प्रमाणीकरणामुळे प्रदाता यशस्वीरीत्या प्रमाणीकरण करेल याची **हमी मिळत नाही**.

प्रमाणीकरण तरीही अयशस्वी होत असल्यास, आपण क्रेडेन्शियल्स ब्राउझरच्या कुकी स्टोरेजऐवजी थेट नेटवर्क विनंतीमधून कॉपी केली आहेत याची खात्री करा.

---

# समस्यानिवारण

## प्रमाणीकरण अयशस्वी होते

क्रेडेन्शियल्स येथून कॉपी केली आहेत याची खात्री करा:

```
Network
→ Request Headers
→ Cookie
```

आणि येथून **नाही**:

```
Application
→ Cookies
```

---

## कुकी ब्राउझरमध्ये कार्य करते, परंतु OmniRoute मध्ये नाही

काही प्रदाते अशा कुकीज समाविष्ट करतात ज्या केवळ प्रमाणीकृत विनंत्यांदरम्यान पाठवल्या जातात.

संभाषण यशस्वीरीत्या उघडल्यानंतर नवीन नेटवर्क विनंतीमधून क्रेडेन्शियल्स पुन्हा कॉपी करा.

---

## सत्र कालबाह्य झाले

Web Cookie प्रदाते आपले विद्यमान ब्राउझर सत्र वापरतात.

आपले ब्राउझर सत्र कालबाह्य झाल्यास किंवा आपण साइन आउट केल्यास, आपल्याला क्रेडेन्शियल्सचा नवीन संच कॉपी करावा लागेल. समर्थित वेब प्रदात्यांसाठी कुकी नूतनीकरण स्वयंचलित करण्याकरिता, [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md) हे सहयोगी टूल पहा.

---

## Test Connection यशस्वी होते, परंतु विनंत्या अयशस्वी होतात

Issue #7857 चे निराकरण होईपर्यंत, प्रमाणीकरण यशस्वी झाल्यामुळे प्रमाणीकरण विनंती यशस्वी होईल याची हमी मिळत नाही.

पुढील समस्यानिवारण करण्यापूर्वी नवीन प्रमाणीकृत विनंतीमधून आपली क्रेडेन्शियल्स पुन्हा कॉपी करा.

---

# प्रदात्याचे उदाहरण

विशिष्ट प्रदात्यासाठी संपूर्ण चरण-दर-चरण मार्गदर्शक पाहण्यासाठी:

- **Claude Web** — `docs/providers/CLAUDE_WEB.md`

Claude Web मार्गदर्शक Web Cookie प्रदात्यासाठी संपूर्ण सेटअप प्रक्रिया दर्शवतो आणि संदर्भ अंमलबजावणी म्हणून वापरला जातो.

---

# सर्वोत्तम पद्धती

- नवीन प्रमाणीकृत विनंतीमधून क्रेडेन्शियल्स कॉपी करा.
- जुन्या कुकीज पुन्हा वापरणे टाळा.
- Web Cookie प्रदाते वापरताना आपले ब्राउझर सत्र सक्रिय ठेवा.
- कॉपी केलेल्या कुकीजना संवेदनशील क्रेडेन्शियल्स समजा.
- आपल्याला फंक्शन कॉलिंग किंवा एजंट कार्यप्रवाहांची आवश्यकता असल्यास API-key प्रदाते वापरा.
