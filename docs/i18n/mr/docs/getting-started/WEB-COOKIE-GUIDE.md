Web Cookie प्रदाते OmniRoute ला API key ऐवजी तुमच्या विद्यमान ब्राउझर सत्राद्वारे AI सेवा वापरण्याची अनुमती देतात. जेव्हा तुम्हाला एखाद्या सेवेच्या वेबसाइटद्वारे आधीपासूनच प्रवेश उपलब्ध असतो आणि OmniRoute ने तेच प्रमाणीकृत सत्र वापरावे असे तुम्हाला वाटते, तेव्हा ते उपयुक्त ठरतात.

API-key प्रदात्यांपेक्षा वेगळे, Web Cookie प्रदाते तुमचा ब्राउझर वेबसाइटला पाठवत असलेल्या क्रेडेन्शियल्सचा वापर करून प्रमाणीकरण करतात.

---

# सुरू करण्यापूर्वी

> **महत्त्वाचे:** क्रेडेन्शियल्स नेहमी **सक्रिय नेटवर्क विनंतीमधून** कॉपी करा, तुमच्या ब्राउझरच्या cookie storage मधून **नाही**.

चुकीच्या ठिकाणाहून cookies कॉपी केल्यामुळे प्रमाणीकरणाच्या अनेक समस्या उद्भवतात.

## Cookie Storage मधून कॉपी करू नका

बहुतेक ब्राउझर संग्रहित cookies पुढील ठिकाणी दाखवतात:

```
DevTools
→ Application (किंवा Storage)
→ Cookies
```

हे cookies योग्य दिसत असले, तरी ते पुढीलप्रमाणे असू शकतात:

- कालबाह्य
- अपूर्ण
- केवळ प्रमाणीकृत विनंत्यांमध्ये पाठवले जाणारे cookies नसलेले

ही मूल्ये वापरल्यास, ती वैध दिसत असली तरी प्रमाणीकरण अयशस्वी होऊ शकते.

## सक्रिय विनंतीमधून कॉपी करा

त्याऐवजी, यशस्वी विनंतीमधील cookies वापरा:

```
DevTools
→ Network
→ पृष्ठ रीफ्रेश करा
→ chat किंवा conversation विनंती उघडा
→ Request Headers
→ Cookie
```

`Cookie` request header मध्ये तुमच्या ब्राउझरने यशस्वीरित्या वापरलेली नेमकी प्रमाणीकरण माहिती असते.

बहुतेक Web Cookie प्रदात्यांसाठी, हेच मूल्य OmniRoute मध्ये पेस्ट केले पाहिजे.

---

# सामान्य सेटअप

बहुतेक Web Cookie प्रदात्यांसाठी सेटअप प्रक्रिया सारखीच असते.

1. प्रदात्याच्या वेबसाइटवर sign in करा.
2. ब्राउझरचे Developer Tools उघडा.
3. **Network** tab उघडा.
4. पृष्ठ रीफ्रेश करा.
5. प्रमाणीकृत chat किंवा conversation विनंती उघडा.
6. आवश्यक प्रमाणीकरण क्रेडेन्शियल्स कॉपी करा.
7. OmniRoute उघडा.
8. **Providers → Add Provider** येथे जा.
9. तुमचा Web Cookie प्रदाता निवडा.
10. क्रेडेन्शियल्स पेस्ट करा.
11. **Test Connection** वर क्लिक करा.
12. प्रदाता जतन करा.

आवश्यक असलेली नेमकी क्रेडेन्शियल्स प्रदात्यावर अवलंबून असतात.

# Web Cookie प्रदाते काय करू शकतात आणि काय करू शकत नाहीत

Web Cookie प्रदाते वेबसाइटचा chat interface पुन्हा वापरतात. ते अधिकृत APIs सारख्या क्षमता प्रदान करत **नाहीत**.

## समर्थित

- तुमचे विद्यमान ब्राउझर सत्र वापरून प्रमाणीकरण करणे
- तुमच्या खात्याद्वारे उपलब्ध असलेल्या models मध्ये प्रवेश करणे
- chat प्रतिसाद stream करणे
- API key आवश्यक नाही

## समर्थित नाही

- Function calling
- Tool calling
- स्वयंचलित file editing
- Agentic IDE workflows
- केवळ API द्वारे उपलब्ध असलेली वैशिष्ट्ये

हे अपेक्षित वर्तन आहे आणि हा bug **नाही**.

तुम्हाला tool execution, स्वयंचलित file editing किंवा इतर agent workflows आवश्यक असल्यास, Web Cookie प्रदात्याऐवजी **API-key provider** वापरा.

# प्रमाणीकरणासंबंधी मर्यादा

यशस्वी **Test Connection** किंवा cookie validation केवळ एवढेच सत्यापित करते की पुरवलेली क्रेडेन्शियल्स अपेक्षित स्वरूपात असल्याचे दिसते.

Issue #7857 चे निराकरण होईपर्यंत, यशस्वी validation मुळे प्रदाता यशस्वीरित्या प्रमाणीकरण करेल याची **हमी मिळत नाही**.

प्रमाणीकरण तरीही अयशस्वी झाल्यास, तुम्ही क्रेडेन्शियल्स browser cookie storage ऐवजी सक्रिय network request मधून कॉपी केली आहेत याची खात्री करा.

---

# समस्यानिवारण

## प्रमाणीकरण अयशस्वी होते

क्रेडेन्शियल्स पुढील ठिकाणाहून कॉपी केली आहेत याची खात्री करा:

```
Network
→ Request Headers
→ Cookie
```

आणि पुढील ठिकाणाहून **नाही**:

```
Application
→ Cookies
```

---

## Cookie ब्राउझरमध्ये कार्य करते, पण OmniRoute मध्ये नाही

काही प्रदात्यांमध्ये केवळ प्रमाणीकृत विनंत्यांदरम्यान पाठवले जाणारे cookies समाविष्ट असतात.

conversation यशस्वीरित्या उघडल्यानंतर नवीन network request मधून क्रेडेन्शियल्स पुन्हा कॉपी करा.

---

## सत्र कालबाह्य झाले

Web Cookie प्रदाते तुमचे विद्यमान ब्राउझर सत्र वापरतात.

तुमचे ब्राउझर सत्र कालबाह्य झाल्यास किंवा तुम्ही sign out केल्यास, तुम्हाला क्रेडेन्शियल्सचा नवीन संच कॉपी करावा लागेल.

---

## Test Connection यशस्वी होते, पण विनंत्या अयशस्वी होतात

Issue #7857 चे निराकरण होईपर्यंत, validation यशस्वी झाल्यामुळे प्रमाणीकरण विनंती यशस्वी होईल याची हमी मिळत नाही.

पुढील समस्यानिवारण करण्यापूर्वी, नवीन प्रमाणीकृत विनंतीमधून तुमची क्रेडेन्शियल्स पुन्हा कॉपी करा.

# प्रदात्याचे उदाहरण

प्रदात्यासाठी विशिष्ट असलेल्या संपूर्ण चरण-दर-चरण मार्गदर्शिकेसाठी, हे पहा:

- **Claude Web** — `docs/providers/CLAUDE_WEB.md`

Claude Web मार्गदर्शिका Web Cookie प्रदात्यासाठी संपूर्ण सेटअप प्रक्रिया दाखवते आणि संदर्भ अंमलबजावणी म्हणून काम करते.

# सर्वोत्तम पद्धती

- नवीन प्रमाणीकृत विनंतीमधून क्रेडेन्शियल्स कॉपी करा.
- जुने cookies पुन्हा वापरणे टाळा.
- Web Cookie प्रदाते वापरताना तुमचे ब्राउझर सत्र सक्रिय ठेवा.
- कॉपी केलेल्या cookies ना संवेदनशील क्रेडेन्शियल्स समजा.
- तुम्हाला function calling किंवा agent workflows आवश्यक असतील, तेव्हा API-key प्रदाते वापरा.
