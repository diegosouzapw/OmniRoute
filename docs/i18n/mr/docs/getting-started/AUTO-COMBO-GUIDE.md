> **थोडक्यात**: तुमचे मॉडेल `auto` वर सेट करा आणि OmniRoute प्रत्येक विनंतीसाठी सर्वोत्तम AI प्रदाता आपोआप निवडेल. कोणतेही कॉन्फिगरेशन आवश्यक नाही.

---

## हे काय करते

विशिष्ट AI मॉडेल (जसे GPT-4o किंवा Claude) निवडण्याऐवजी, तुम्ही OmniRoute ला प्रत्येक विनंतीसाठी **सर्वोत्तम मॉडेल आपोआप निवडू** देऊ शकता. ते पुढील बाबी विचारात घेते:

- **स्थिती** — प्रदाता सध्या कार्यरत आहे का?
- **वेग** — तो किती वेगवान आहे?
- **खर्च** — त्याचा खर्च किती आहे?
- **गुणवत्ता** — या प्रकारच्या कार्यासाठी तो चांगला आहे का?
- **क्षमता** — त्याचा काही कोटा शिल्लक आहे का?

OmniRoute तुमच्या सर्व कनेक्ट केलेल्या प्रदात्यांना गुण देते आणि सर्वोत्तम प्रदाता निवडते. तो अयशस्वी झाल्यास, ते आपोआप पुढील प्रदात्याचा प्रयत्न करते.

---

## झटपट सुरुवात

**पायरी 1**: तुमच्या IDE किंवा CLI मध्ये तुमचे मॉडेल `auto` वर सेट करा:

```
model: "auto"
```

**पायरी 2**: एवढेच! बाकी सर्व OmniRoute हाताळते.

**पायरी 3** (पर्यायी): विशिष्ट कार्यांसाठी एखादा प्रकार वापरा:

```
model: "auto/coding"    # कोडसाठी सर्वोत्तम
model: "auto/fast"      # सर्वांत जलद प्रतिसाद
model: "auto/cheap"     # सर्वांत स्वस्त पर्याय
```

## मी कोणते "auto" वापरावे?

| तुम्हाला हे हवे असल्यास...  | हे वापरा       | यासाठी सर्वोत्तम       | हे कसे कार्य करते                          |
| --------------------------- | -------------- | ---------------------- | ------------------------------------------ |
| **एकूणच सर्वोत्तम**         | `auto`         | सर्वसाधारण प्रश्न, चॅट | वेग, खर्च आणि गुणवत्ता यांचा समतोल साधते   |
| **सर्वोत्तम कोड**           | `auto/coding`  | कोड लिहिणे, डीबगिंग    | कोडिंग कार्यांसाठी चांगली मॉडेल्स निवडते   |
| **सर्वांत जलद प्रतिसाद**    | `auto/fast`    | झटपट उत्तरे, कमी विलंब | इतर सर्व बाबींपेक्षा वेगाला प्राधान्य देते |
| **सर्वांत स्वस्त पर्याय**   | `auto/cheap`   | पैसे वाचवणे            | सर्वांत स्वस्त प्रदाता निवडते              |
| **सर्वांत बुद्धिमान मॉडेल** | `auto/smart`   | गुंतागुंतीची कार्ये    | गुणवत्तेला प्राधान्य + नवीन मॉडेल्सचा शोध  |
| **सर्वाधिक उपलब्ध**         | `auto/offline` | प्रदाते व्यस्त असताना  | सर्वाधिक क्षमता असलेले प्रदाते निवडते      |

### उदाहरणे

```bash
# सर्वसाधारण चॅट — संतुलित

  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'

# कोड निर्मिती — गुणवत्तेला प्राधान्य

  -H "Content-Type: application/json" \
  -d '{"model":"auto/coding","messages":[{"role":"user","content":"Write a Python function"}]}'

# झटपट उत्तर — वेगाला प्राधान्य
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/fast","messages":[{"role":"user","content":"What is 2+2?"}]}'
```

## हे कसे कार्य करते (सोपी आवृत्ती)

तुम्ही `model: "auto"` सह विनंती पाठवता तेव्हा, OmniRoute:

1. **तुमच्या सर्व कनेक्ट केलेल्या प्रदात्यांकडे पाहते** — तुम्ही जोडलेला प्रत्येक प्रदाता (OpenAI, Anthropic, Google इ.)
2. **प्रत्येकाला गुण देते**, यामध्ये पुढील बाबींना महत्त्व दिले जाते:
   - तो कार्यरत आहे का? (स्थिती)
   - त्याच्याकडे क्षमता आहे का? (कोटा)
   - त्याचा खर्च किती आहे? (किंमत)
   - तो किती वेगवान आहे? (वेग)
   - तो या कार्यासाठी चांगला आहे का? (गुणवत्ता)
3. **सर्वोत्तम प्रदाता निवडते** — सर्वाधिक गुण मिळालेल्या प्रदात्याकडे तुमची विनंती जाते
4. **आपोआप पुनर्प्राप्ती करते** — तो अयशस्वी झाल्यास, OmniRoute आपोआप पुढील प्रदात्याचा प्रयत्न करते

### गुणांकन प्रणाली

प्रत्येक प्रदात्याला 0 ते 1 पर्यंत गुण मिळतात. गुण जितके जास्त, तितका तो अधिक योग्य.

| घटक               | वजन | त्याचा अर्थ                                      |
| ----------------- | --- | ------------------------------------------------ |
| स्थिती            | 20% | प्रदाता कार्यरत आहे का? (सर्किट ब्रेकरची स्थिती) |
| कोटा              | 15% | त्याच्याकडे काही क्षमता शिल्लक आहे का?           |
| खर्च              | 15% | तो किती महाग आहे? (स्वस्त = जास्त गुण)           |
| वेग               | 12% | तो किती वेगवान आहे? (कमी विलंब = जास्त गुण)      |
| कार्याशी अनुरूपता | 8%  | तो या प्रकारच्या कार्यासाठी चांगला आहे का?       |
| स्थिरता           | 5%  | तो सातत्यपूर्ण आहे का? (कमी त्रुटी दर)           |
| स्तर              | 5%  | खात्याचा स्तर (Ultra > Pro > Free)               |
| इतर               | 20% | संदर्भ अनुरूपता, कनेक्शन घनता इ.                 |

### प्रकारांनुसार गुणांकन कसे बदलते

प्रत्येक प्रकार वेगवेगळी वजने वापरतो:

| प्रकार         | कशाला प्राधान्य देते | प्रमुख वजने                     |
| -------------- | -------------------- | ------------------------------- |
| `auto`         | संतुलन               | health=20%, quota=15%, cost=15% |
| `auto/coding`  | गुणवत्ता             | taskFit=37%, stability=15%      |
| `auto/fast`    | वेग                  | latency=32%, health=28%         |
| `auto/cheap`   | खर्च                 | cost=37%                        |
| `auto/smart`   | गुणवत्ता + शोध       | taskFit=37%, exploration=10%    |
| `auto/offline` | क्षमता               | quota=37%, health=28%           |

## अपयश कसे हाताळले जाते

OmniRoute मध्ये **संरक्षणाचे तीन स्तर** आहेत:

### 1. स्वयंचलित फॉलबॅक

सर्वोत्तम प्रदाता अयशस्वी झाल्यास, OmniRoute स्वयंचलितपणे पुढील प्रदात्याचा प्रयत्न करते. तुम्हाला काहीही करण्याची आवश्यकता नाही.

### 2. स्वयंचलित दोषनिवारण

एखादा प्रदाता वारंवार अयशस्वी होत असल्यास:

- **स्कोअर < 0.2** → 5 मिनिटांसाठी वगळला जातो
- **सर्किट ब्रेकर उघडा** → स्वयंचलितपणे वगळला जातो
- **50% पेक्षा जास्त प्रदाते अनुपलब्ध** → घटना मोड (कोणतेही अन्वेषण नाही)

### 3. आपत्कालीन फॉलबॅक

सर्व प्रदाते अयशस्वी झाल्यास, शेवटचा पर्याय म्हणून OmniRoute विनंत्या स्थिर मोफत प्रदात्यांकडे (जसे की Kiro किंवा Qoder) रूट करते.

## एकाधिक खात्यांसाठी समर्थन

एकाच प्रदात्यासाठी तुमच्याकडे एकाधिक खाती असल्यास (उदा., दोन OpenAI की), OmniRoute प्रत्येक खात्याला **स्वतंत्र उमेदवार** मानते. याचा अर्थ:

- खाते A चा कोटा शिल्लक आहे → ते वापरा
- खाते B वर दर-मर्यादा लागू आहे → ते वगळा
- खाते C स्वस्त आहे → त्याला प्राधान्य द्या

प्रत्येक खात्याचे आरोग्य, कोटा आणि वेग यांच्या आधारे स्वतंत्रपणे गुणांकन केले जाते.

## बँडिट अन्वेषण

अधिक चांगले पर्याय शोधण्यासाठी OmniRoute अधूनमधून नवीन प्रदात्यांचे **अन्वेषण** करते:

- **डीफॉल्ट**: 5% विनंत्या यादृच्छिक प्रदात्यांकडे जातात
- **Auto/smart**: 10% अन्वेषण दर
- 50% पेक्षा जास्त प्रदाते अस्वस्थ असताना **अक्षम**

यामुळे तुमच्या वापराच्या पद्धतींसाठी कोणते प्रदाते सर्वोत्तम कार्य करतात, हे शिकण्यास OmniRoute ला मदत होते.

## सामान्य प्रश्न

### "ते नेहमी सर्वांत महाग मॉडेल निवडेल का?"

**नाही.** डीफॉल्टनुसार किंमत ही स्कोअरच्या केवळ 15% असते. स्वस्त, जलद आणि निरोगी प्रदाता महाग प्रदात्यापेक्षा सरस ठरू शकतो. किंमतीला आणखी प्राधान्य द्यायचे असल्यास `auto/cheap` वापरा.

### "एखादा प्रदाता अनुपलब्ध झाल्यास काय होते?"

OmniRoute त्याला स्वयंचलितपणे वगळते आणि पुढील प्रदात्याचा प्रयत्न करते. एखादा प्रदाता वारंवार अयशस्वी झाल्यास, त्याला तात्पुरते (5-30 मिनिटांसाठी) वगळले जाते. तुम्हाला काहीही करण्याची आवश्यकता नाही.

### "कोणता प्रदाता वापरला गेला हे मला पाहता येईल का?"

प्रतिसाद हेडर तपासा — OmniRoute प्रत्येक प्रतिसादामध्ये वापरलेला प्रदाता आणि मॉडेल समाविष्ट करते.

### "ते माझ्या वापरातून शिकते का?"

होय! कालांतराने अधिक चांगले निर्णय घेण्यासाठी गुणांकन प्रणाली ऐतिहासिक डेटा (विलंब, त्रुटी दर, यश दर) वापरते.

### "`auto` आणि `auto/smart` यांमध्ये काय फरक आहे?"

- `auto` — संतुलित, 5% अन्वेषण
- `auto/smart` — गुणवत्तेला प्राधान्य (`auto/coding` सारखेच भार), 10% अन्वेषण

तुम्हाला सर्वोत्तम गुणवत्ता हवी असेल आणि अधूनमधून होणारे अन्वेषण मान्य असेल, तेव्हा `auto/smart` वापरा.

### "मी एखादा विशिष्ट प्रदाता वापरण्यास भाग पाडू शकतो का?"

होय! `auto` ऐवजी `priority` धोरण असलेला कॉम्बो वापरा, त्यानंतर कॉम्बोचे **अचूक नाव** `model` फील्ड म्हणून पाठवा (उदा. `model: "my-combo"` — `auto` नाही). तपशीलांसाठी [तांत्रिक संदर्भ](../routing/AUTO-COMBO.md) पहा.

### "हे राउंड-रॉबिनपेक्षा कसे वेगळे आहे?"

राउंड-रॉबिन प्रदात्यांचा क्रमाने वापर करते. Auto-combo **प्रत्येक प्रदात्याला गुण देते** आणि सर्वोत्तम प्रदाता निवडते. ते अधिक बुद्धिमान आहे — ते आरोग्य, वेग, किंमत आणि गुणवत्ता विचारात घेते.
