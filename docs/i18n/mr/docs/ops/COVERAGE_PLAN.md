## नियम

- कव्हरेजची उद्दिष्टे सोर्स फाइल्सना लागू होतात, `tests/**` ला नाही.
- `open-sse/**` हा उत्पादनाचा भाग आहे आणि तो व्याप्तीत राहिलाच पाहिजे.
- नवीन कोडमुळे स्पर्श केलेल्या भागांतील कव्हरेज कमी होऊ नये.
- अंमलबजावणीच्या तपशीलांपेक्षा वर्तन आणि ब्रँच परिणामांची चाचणी करण्यास प्राधान्य द्या.
- `src/lib/db/**` साठी व्यापक मॉक्सऐवजी तात्पुरते SQLite डेटाबेस आणि लहान फिक्स्चर्सना प्राधान्य द्या.

## सध्याचा कमांड संच

- `npm run test:coverage`
  - युनिट टेस्ट संचासाठी मुख्य सोर्स कव्हरेज गेट
  - `text-summary`, `html`, `json-summary`, आणि `lcov` तयार करते
- `npm run coverage:report`
  - सर्वात अलीकडील रनमधून फाइलनिहाय तपशीलवार अहवाल
- `npm run test:coverage:legacy`
  - फक्त ऐतिहासिक तुलनेसाठी

सध्याची कव्हरेज कमांड मुख्य Node युनिट संचाचे मापन करते आणि त्यातून पोहोचलेल्या स्रोताचा समावेश करते, ज्यात `open-sse` देखील समाविष्ट आहे. ती अद्याप Vitest कव्हरेज एका एकत्रित अहवालात विलीन करत नाही. हे विलीनीकरण नंतर करणे उपयुक्त ठरेल, परंतु 60% -> 80% पर्यंतची प्रगती सुरू करण्यासाठी ते अडथळा नाही.
