Cloudflare द्वारे व्यवस्थापित केलेल्या डोमेनसह VM (VPS) वर OmniRoute स्थापित आणि कॉन्फिगर करण्यासाठी संपूर्ण मार्गदर्शक.

---

## पूर्वआवश्यकता

| घटक        | किमान                   | शिफारस केलेले    |
| ---------- | ----------------------- | ---------------- |
| **CPU**    | 1 vCPU                  | 2 vCPU           |
| **RAM**    | 1 GB                    | 2 GB             |
| **डिस्क**  | 10 GB SSD               | 25 GB SSD        |
| **OS**     | Ubuntu 22.04 LTS        | Ubuntu 24.04 LTS |
| **डोमेन**  | Cloudflare वर नोंदणीकृत | —                |
| **Docker** | Docker Engine 24+       | Docker 27+       |

**चाचणी केलेले प्रदाते**: Akamai (Linode), DigitalOcean, Vultr, Hetzner, AWS Lightsail.

## 1. VM कॉन्फिगर करा

### 1.1 इन्स्टन्स तयार करा

तुमच्या पसंतीच्या VPS प्रदात्यावर:

- Ubuntu 24.04 LTS निवडा
- किमान प्लॅन (1 vCPU / 1 GB RAM) निवडा
- मजबूत root पासवर्ड सेट करा किंवा SSH की कॉन्फिगर करा
- **सार्वजनिक IP** नोंदवून ठेवा (उदा., `203.0.113.10`)

### 1.2 SSH द्वारे कनेक्ट करा

```bash
ssh root@203.0.113.10
```

### 1.3 सिस्टम अपडेट करा

```bash
apt update && apt upgrade -y
```

### 1.4 Docker इंस्टॉल करा

```bash
# अवलंबित्वे इंस्टॉल करा
apt install -y ca-certificates curl gnupg

# अधिकृत Docker रेपॉझिटरी जोडा
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
chmod a+r /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $ (. /etc/os-release && echo "$VERSION_CODENAME") stable" | tee /etc/apt/sources.list.d/docker.list > /dev/null
apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

### 1.5 nginx इंस्टॉल करा

```bash
apt install -y nginx
```

### 1.6 फायरवॉल (UFW) कॉन्फिगर करा

```bash
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp    # SSH
ufw allow 80/tcp    # HTTP (रीडायरेक्ट)
ufw allow 443/tcp   # HTTPS
ufw enable
```

> **टीप**: कमाल सुरक्षिततेसाठी, पोर्ट 80 आणि 443 वरील प्रवेश केवळ Cloudflare IP पुरता मर्यादित करा. [प्रगत सुरक्षा](#advanced-security) विभाग पाहा.

## 2. OmniRoute इंस्टॉल करा

### 2.1 कॉन्फिगरेशन डिरेक्टरी तयार करा

```bash
mkdir -p /opt/omniroute
```

### 2.2 एन्व्हायर्नमेंट व्हेरिएबल्सची फाइल तयार करा

```bash
cat > /opt/omniroute/.env << 'EOF'
# === सुरक्षा ===
JWT_SECRET=CHANGE-TO-A-UNIQUE-64-CHAR-SECRET-KEY
INITIAL_PASSWORD=YourSecurePassword123!
API_KEY_SECRET=REPLACE-WITH-ANOTHER-SECRET-KEY
STORAGE_ENCRYPTION_KEY=REPLACE-WITH-THIRD-SECRET-KEY
STORAGE_ENCRYPTION_KEY_VERSION=v1
MACHINE_ID_SALT=CHANGE-TO-A-UNIQUE-SALT
OMNIROUTE_WS_BRIDGE_SECRET=REPLACE-WITH-WS-BRIDGE-SECRET  # उत्पादनामध्ये आवश्यक: Codex Responses WS ब्रिजद्वारे वापरले जाते

# === ॲप ===
PORT=20128
NODE_ENV=production
HOSTNAME=0.0.0.0
DATA_DIR=/app/data
APP_LOG_TO_FILE=true
AUTH_COOKIE_SECURE=true
REQUIRE_API_KEY=false

# === URLs (तुमच्या डोमेननुसार बदला) ===
# शेड्यूल केलेल्या जॉब्स / सेल्फ-फेचसाठी अंतर्गत सर्व्हर-टू-सर्व्हर बेस URL.
BASE_URL=http://127.0.0.1:20128
# OAuth कॉलबॅक, डॅशबोर्ड लिंक आणि व्युत्पन्न सार्वजनिक URLs साठी वापरला जाणारा ब्राउझर-दृश्यमान URL.
NEXT_PUBLIC_BASE_URL=https://llms.seudominio.com
# व्युत्पन्न सार्वजनिक ॲसेट URLs साठी पर्यायी स्पष्ट सार्वजनिक ओरिजिन ओव्हरराइड.
# OMNIROUTE_PUBLIC_BASE_URL=https://llms.seudominio.com

# === क्लाउड सिंक (पर्यायी) ===
# CLOUD_URL=https://cloud.omniroute.online
# NEXT_PUBLIC_CLOUD_URL=https://cloud.omniroute.online
EOF
```

> ⚠️ **महत्त्वाचे**: अद्वितीय गुप्त कीज व्युत्पन्न करा! प्रत्येक कीसाठी `openssl rand -hex 32` वापरा.

### 2.3 कंटेनर सुरू करा

```bash
docker pull diegosouzapw/omniroute:latest

docker run -d \
  --name omniroute \
  --restart unless-stopped \
  --env-file /opt/omniroute/.env \
  -p 20128:20128 \
  -v omniroute-data:/app/data \
  diegosouzapw/omniroute:latest
```

### 2.4 ते सुरू असल्याची खात्री करा

```bash
docker ps | grep omniroute
docker logs omniroute --tail 20
```

यात पुढील मजकूर दिसला पाहिजे: `[DB] SQLite database ready` आणि `listening on port 20128`.

## 3. nginx कॉन्फिगर करा (रिव्हर्स प्रॉक्सी)

### 3.1 SSL प्रमाणपत्र तयार करा (Cloudflare Origin)

Cloudflare डॅशबोर्डमध्ये:

1. **SSL/TLS → Origin Server** वर जा
2. **Create Certificate** वर क्लिक करा
3. डीफॉल्ट मूल्ये कायम ठेवा (15 वर्षे, \*.yourdomain.com)
4. **Origin Certificate** आणि **Private Key** कॉपी करा

```bash
mkdir -p /etc/nginx/ssl

# प्रमाणपत्र पेस्ट करा
nano /etc/nginx/ssl/origin.crt

# खाजगी की पेस्ट करा
nano /etc/nginx/ssl/origin.key

chmod 600 /etc/nginx/ssl/origin.key
```

### 3.2 Nginx कॉन्फिगरेशन

```bash
cat > /etc/nginx/sites-available/omniroute << 'NGINX'
# डीफॉल्ट सर्व्हर — IP द्वारे थेट प्रवेश अवरोधित करतो
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    listen 443 ssl default_server;
    listen [::]:443 ssl default_server;
    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    server_name _;
    return 444;
}

# OmniRoute — HTTPS
server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name llms.yourdomain.com;  # तुमच्या डोमेननुसार बदला

    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    client_max_body_size 100M;

    location / {
        proxy_pass http://127.0.0.1:20128;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket समर्थन
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # SSE (सर्व्हरने पाठवलेले इव्हेंट्स) — AI प्रतिसादांचे स्ट्रीमिंग
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }
}

# HTTP → HTTPS पुनर्निर्देशन
server {
    listen 80;
    listen [::]:80;
    server_name llms.yourdomain.com;
    return 301 https://$server_name$request_uri;
}
NGINX
```

रिव्हर्स-प्रॉक्सी स्ट्रीम टाइमआउट तुमच्या OmniRoute टाइमआउट env vars शी सुसंगत ठेवा. तुम्ही
`FETCH_TIMEOUT_MS` / `STREAM_IDLE_TIMEOUT_MS` वाढवल्यास, `proxy_read_timeout` / `proxy_send_timeout`
त्याच मर्यादेपेक्षा अधिक वाढवा.

OAuth कॉलबॅक आणि व्युत्पन्न केलेल्या सार्वजनिक लिंक्ससाठी OmniRoute ब्राउझरला दिसणारा अधिकृत ओरिजिन म्हणून `NEXT_PUBLIC_BASE_URL` वापरते. प्रमाणीकरण केलेल्या डॅशबोर्ड राइट्समध्ये समान-ओरिजिन विनंत्यांसह सत्राशी बांधलेले CSRF संरक्षण वापरले जाते, त्यामुळे त्यांना स्थिर सार्वजनिक बेस URL ची आवश्यकता नसते. वरील `X-Forwarded-*` हेडर्स तरीही उपयुक्त राउटिंग मेटाडेटा आहेत, परंतु OAuth किंवा व्युत्पन्न केलेल्या ब्राउझर लिंक्सना स्पष्ट सार्वजनिक URL आवश्यक असताना ते तो सेट करण्याचा पर्याय नाहीत. OmniRoute क्लायंटना थेट उपलब्ध नसेल आणि तुमचा प्रॉक्सी येणारे फॉरवर्डेड हेडर्स काढून टाकत/पुन्हा तयार करत असेल, तरच `OMNIROUTE_TRUST_PROXY` सक्षम करा.

### 3.3 सक्षम करा आणि चाचणी करा

```bash
# डीफॉल्ट कॉन्फिगरेशन काढून टाका
rm -f /etc/nginx/sites-enabled/default

# OmniRoute सक्षम करा
ln -sf /etc/nginx/sites-available/omniroute /etc/nginx/sites-enabled/omniroute

# चाचणी करा आणि पुन्हा लोड करा
nginx -t && systemctl reload nginx
```

## कमी मेमरी / लहान VPS साठी ऑप्टिमायझेशन

लहान VPS इंस्टन्सवरील (1 GB RAM किंवा त्यापेक्षा कमी) डिप्लॉयमेंटसाठी:

- **पार्श्वभूमी सेवा अक्षम करा** — scheduler, MCP server आणि नियतकालिक देखभाल कार्ये वगळण्यासाठी `OMNIROUTE_DISABLE_BACKGROUND_SERVICES=1` सेट करा. `docs/reference/ENVIRONMENT.md` पहा.
- **SQLite WAL मोड वापरा** — हा डीफॉल्टनुसार सक्षम असतो आणि समांतर वाचनादरम्यान कमाल मेमरी वापर कमी करतो.
- **V8 heap मर्यादित करा** — runtime ने VM पेक्षा मोठी कमाल मर्यादा निर्धारित करू नये यासाठी `OMNIROUTE_MEMORY_MB` (उदा. `512`) सेट करा. `docs/reference/ENVIRONMENT.md` पहा.
- **जड विनंत्यांचा प्रवेश heap मर्यादेनुसार आपोआप समायोजित होतो** -- वरीलप्रमाणे `OMNIROUTE_MEMORY_MB` सेट केल्यानंतर, ingest byte budget (`OMNIROUTE_CHAT_MAX_INFLIGHT_BYTES`) त्याच कमाल मर्यादेवरून आपोआप निर्धारित होतो. त्यामुळे मेमरी-मर्यादित VM ला अतिरिक्त ट्यूनिंगशिवाय समांतर विनंत्यांसाठी कमी budget मिळतो; अतिरिक्त विनंत्या मेमरीसाठी स्पर्धा करण्याऐवजी `Retry-After` सह पुन्हा प्रयत्न करता येण्याजोगा `503` प्रतिसाद प्राप्त करतात. त्याव्यतिरिक्त विनंत्यांच्या संख्येवर कठोर कमाल मर्यादा आवश्यक असल्यासच जुनी `OMNIROUTE_CHAT_MAX_HEAVY_IN_FLIGHT` मर्यादा सेट करा.
- **VPS वर `next build` टाळा** — स्थानिक पातळीवर build करा आणि standalone output (`.next/standalone/`) डिप्लॉय करा.
- **`top` / `free -m` वापरून निरीक्षण करा** — 1 GB VM वर निष्क्रिय असताना OmniRoute साधारणपणे 200-400 MB RSS वापरते.
