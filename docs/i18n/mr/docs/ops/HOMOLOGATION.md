होमोलोगेशन VPS वर चालणाऱ्या OmniRoute डिप्लॉयचे प्रत्यक्ष-वातावरणातील E2E प्रमाणीकरण
(`HOMOLOG_BASE_URL`, उदा. `http://192.168.0.15:20128`). एकच कमांड मॅन्युअल
रिलीज STOP #2 तपासणीसूचीची जागा स्वयंचलित, पुरावे निर्माण करणाऱ्या रनने घेते.

मूल्यांकन नाही. AI चा वापर केवळ भविष्यातील देखभाल कार्यात होईल (खालील रोडमॅप पहा).

## पूर्वआवश्यकता

1. `.env.homolog.example` ची प्रत `.env.homolog` मध्ये तयार करा (gitignored — ते कधीही commit करू नका) आणि पुढील माहिती भरा:
   - `HOMOLOG_BASE_URL` — लक्ष्य deploy, उदा. `http://192.168.0.15:20128`.
   - `HOMOLOG_ADMIN_PASSWORD` — त्या deploy साठी dashboard व्यवस्थापनाचा password.
   - `HOMOLOG_CRITICAL_PROVIDERS` — स्वल्पविरामाने विभक्त केलेले provider prefixes, ज्यांना प्रत्यक्ष
     smoke chat request पाठवली जाते (उदा. `openai,anthropic,gemini,codex,grok,glm,deepseek,openrouter`).
   - `HOMOLOG_API_KEY` — सामान्य runs मध्ये रिकामे ठेवा; suite स्वतःची तात्पुरती key तयार करून रद्द करते.
     एखादा स्वतंत्र layer वेगळा ठेवून debug करण्यासाठीच हे सेट करा.
2. repo मध्ये `npm install` चालवा (suite च्या dependencies — `httpyac`, `promptfoo`,
   `playwright-ctrf-json-reporter`, `junit-to-ctrf`, `ctrf` — या नेहमीच्या devDependencies आहेत).
3. browser binaries आधीपासून उपलब्ध नसल्यास `npx playwright install` चालवा.

## कसे चालवावे

```bash
npm run homolog
```

ज्या deploy ची version स्थानिक `package.json` शी जुळत नाही त्याविरुद्ध पडताळणी करण्यासाठी
(उदा. अजूनही मागील patch release वर असलेला homologation box), अपेक्षित version स्पष्टपणे
override करा:

```bash
HOMOLOG_EXPECT_VERSION=3.8.47 npm run homolog
```

कोणताही layer अयशस्वी झाल्यास run non-zero स्थितीसह समाप्त होतो आणि अपयश आले तरीही त्याने
तयार केलेली तात्पुरती API key रद्द करण्याचा नेहमी प्रयत्न करतो (`scripts/homolog/run.mjs` मधील `finally` block).

## report वाचणे

सर्व output `homolog-report/` मध्ये साठवले जाते (gitignored):

- `summary.md` — stdout वर print केलेला तोच table, प्रत्येक layer साठी एक row (✅/❌ + तपशील).
- `homolog-ctrf.json` — एकत्रित CTRF report (API/SSE, provider-smoke आणि
  UI results यांचे merge) — release STOP #2 checklist ला जोडायचा हा artifact आहे.
- `httpyac-junit.xml`, `api-ctrf.json`, `providers-ctrf.json`, `ui-ctrf.json` — प्रत्येक
  layer चे raw/intermediate reports.
- `promptfooconfig.yaml`, `provider-misses.json` — सध्याच्या run साठी तयार केलेले promptfoo config आणि
  live catalog मधून गहाळ असलेले कोणतेही critical providers.

L0 अयशस्वी झाल्यास run त्वरित थांबतो (तात्पुरती key तयार केली जात नाही), कारण version/health
mismatch चा अर्थ असा होतो की प्रत्येक downstream layer चुकीच्या deploy ची पडताळणी करत असेल.

## UI मध्ये वैध बदल झाल्यावर baseline पुन्हा निश्चित करणे

L4b (route smoke) आणि L4c (API-key UI flow) हे snapshots ऐवजी प्रत्यक्ष DOM locators द्वारे
चालवले जातात, त्यामुळे बहुतेक वैध UI बदलांसाठी suite update करण्याची आवश्यकता नसते. एखाद्या बदलामुळे
locator काम करेनासा झाल्यास (उदा. button label चे नाव बदलले किंवा settings page दुसरीकडे हलवली):

1. सध्याच्या source शी locator पुन्हा पडताळा (प्रत्येक locator कोणत्या file/line शी पडताळला गेला
   हे specs मध्ये आधीच नोंदवले आहे — त्याच पद्धतीचे अनुसरण करा, अंदाज लावू नका).
2. `tests/homolog/ui/` मधील spec update करा.
3. दुरुस्तीची खात्री करण्यासाठी VPS विरुद्ध `npm run homolog` (किंवा फक्त प्रभावित Playwright spec)
   पुन्हा चालवा आणि नंतर commit करा.

या suite मध्ये कोणताही visual/pixel baseline नाही (F1) — त्यासाठी Roadmap पाहा.

## Roadmap (F2 / F3)

Design आणि टप्प्याटप्प्याने rollout करण्याची माहिती अंतर्गत planning spec
`_tasks/superpowers/specs/2026-07-13-homolog-e2e-suite-design.md` मध्ये आहे (link केलेले नाही — हा अंतर्गत
`_tasks/` artifact आहे, या repo च्या tracked docs चा भाग नाही). सारांश:

- **F2** — संपूर्ण walkthrough recording → Playwright Test Agents (`planner`/`generator`)
  त्याचे flow specs मध्ये रूपांतर करतात (combo तयार करणे, provider ची चाचणी करणे, settings संपादित करणे, MCP tools) +
  dynamic data (metrics, timestamps, logs) वर masks असलेला visual regression baseline (Lost Pixel) +
  प्रत्येक release साठी `healer` maintenance routine.
- **F3** — resilience/contract/wiring coverage: devbox वर toxiproxy + बनावट OpenAI-compatible
  provider, त्याकडे निर्देश करणारा VPS वरील `homolog-resilience` combo
  (injected timeout → fallback + circuit breaker open/close यांची
  `/api/monitoring/health` द्वारे खात्री करणे); `docs/openapi.yaml` विरुद्ध gated Schemathesis contract testing
  (कमी `--max-examples`, निश्चित seeds, फक्त non-LLM endpoints); आणि
  `npm run homolog` + त्यातील `summary.md` यांना `/generate-release` STOP #2 phase मध्ये जोडणे.
