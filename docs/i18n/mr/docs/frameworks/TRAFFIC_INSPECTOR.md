Traffic Inspector हा OmniRoute चा अंगभूत HTTPS ट्रॅफिक डीबगर आहे — Charles Proxy / mitmweb / HTTP Toolkit सारखे साधन, जे **LLM-aware** आणि **agent-aware** आहे. ते `/dashboard/tools/traffic-inspector` येथे उपलब्ध आहे आणि एकाच वेळी कमाल 5 कॅप्चर स्रोतांकडून थेट ट्रॅफिक प्राप्त करते.

**डॅशबोर्डमधील स्थान:** `/dashboard/tools/traffic-inspector`
**साइडबार गट:** साधने (AgentBridge नंतर)
**हे देखील पहा:** [`AGENTBRIDGE.md`](./AGENTBRIDGE.md) — AgentBridge हा कॅप्चर मोड 1 आहे.

### एका परिच्छेदात आर्किटेक्चर

`TrafficBuffer` (`src/mitm/inspector/buffer.ts`) हा सामायिक इन-मेमरी रिंग बफर आहे (डीफॉल्टनुसार 1000 नोंदी, `INSPECTOR_BUFFER_SIZE` द्वारे कॉन्फिगर करण्यायोग्य). सर्व कॅप्चर स्रोत `push()` द्वारे त्यात डेटा लिहितात. बफर `kindDetector.ts` वापरून प्रत्येक नोंदीचे वर्गीकरण करतो (ती LLM विनंती आहे का हे ठरवतो), `contextKey` ची गणना करतो (सिस्टम प्रॉम्प्टचा SHA-256 फिंगरप्रिंट), आणि `globalTrafficBuffer.subscribe()` द्वारे सर्व WebSocket सदस्यांना प्रसारित करतो. डॅशबोर्ड `GET /api/tools/traffic-inspector/ws` द्वारे कनेक्ट होतो आणि कनेक्ट झाल्यावर स्नॅपशॉट प्राप्त करतो, त्यानंतर `new`/`update`/`clear` इव्हेंट्स प्राप्त होतात.

## §2 कॅप्चर मोड

Traffic Inspector **5 एकाचवेळी कॅप्चर स्रोतांना** समर्थन देतो. प्रत्येक स्रोत स्वतंत्रपणे चालू किंवा बंद करता येतो. प्रत्येक `InterceptedRequest` (`src/mitm/inspector/types.ts`) मधील `source` फील्ड हे `"agent-bridge"`, `"custom-host"`, `"http-proxy"`, `"system-proxy"`, किंवा `"tproxy"` यांपैकी एक असते.

### मोड 1 — AgentBridge (डीफॉल्ट, नेहमी चालू)

**स्रोत:** AgentBridge हँडलर्स (`src/mitm/handlers/base.ts`)
**यंत्रणा:** `MitmHandlerBase` मधील प्रत्येक `intercept()` कॉल, फॉरवर्ड करण्यापूर्वी `hookBufferStart()` आणि पूर्ण झाल्यावर `hookBufferUpdate()` कॉल करतो. कोणतेही अतिरिक्त कॉन्फिगरेशन आवश्यक नाही — AgentBridge सुरू होताच हे कार्य करते.
**व्याप्ती:** AgentBridge मध्ये कॉन्फिगर केलेले 9 IDE एजंट
**टीप:** `InterceptedRequest` मधील `source` फील्ड = `"agent-bridge"`

### मोड 2 — कस्टम होस्ट्स (DNS रीडायरेक्ट)

**स्रोत:** वापरकर्त्याने परिभाषित केलेली होस्ट सूची (`inspector_custom_hosts` टेबल)
**यंत्रणा:** UI द्वारे होस्ट जोडल्यास `/etc/hosts` मध्ये `127.0.0.1 <host>` जोडले जाते (sudo आवश्यक). विद्यमान AgentBridge MITM सर्व्हर (पोर्ट 443) नवीन होस्टसाठी डायनॅमिक पद्धतीने SNI प्रमाणपत्र तयार करतो.
**व्याप्ती:** जोडलेला होस्ट वापरणारे कोणतेही ॲप्लिकेशन — ॲपच्या कॉन्फिगरेशनमध्ये बदल आवश्यक नाही
**टीप:** `source` = `"custom-host"`

वापराची उदाहरणे:

- Python स्क्रिप्टमधून `api.openai.com` चे निरीक्षण करणे
- `my-internal-llm.company.com` डीबग करणे
- त्याच नेटवर्कवरील मोबाइल डिव्हाइसेसमधून ट्रॅफिक कॅप्चर करणे (ARP स्पूफिंगद्वारे — प्रगत)

### मोड 3 — HTTP_PROXY लिसनर (पोर्ट 8080)

**स्रोत:** `HTTP_PROXY`/`HTTPS_PROXY` पर्यावरणीय चल वापरणारी ॲप्लिकेशन्स
**यंत्रणा:** पोर्ट 8080 वरील दुय्यम लिसनर (`src/mitm/inspector/httpProxyServer.ts`), जो मानक स्पष्ट HTTP/HTTPS प्रॉक्सी म्हणून कार्य करतो. `CONNECT` टनेल्स (HTTPS) आणि थेट HTTP विनंत्या स्वीकारतो.
**व्याप्ती:** `HTTP_PROXY` पर्यावरणीय चलाचा वापर करणारे कोणतेही ॲप्लिकेशन — DNS बदल किंवा sudo आवश्यक नाही
**टीप:** `source` = `"http-proxy"`

```bash
# एकाच कमांडसाठी जलद कॅप्चर:
HTTPS_PROXY=http://127.0.0.1:8080 curl https://api.openai.com/v1/models

# शेल सत्रामध्ये कायमस्वरूपी कॅप्चर:
export HTTP_PROXY=http://127.0.0.1:8080
export HTTPS_PROXY=http://127.0.0.1:8080
```

**TLS मर्यादा:** HTTPS `CONNECT` टनेल्स डीफॉल्टनुसार केवळ मेटाडेटा म्हणून कॅप्चर केले जातात (होस्ट, पोर्ट, वेळ) — TLS बॉडी डिक्रिप्ट केली जात नाही. संपूर्ण बॉडी तपासणीसाठी "प्रॉक्सी मोडमध्ये HTTPS डिक्रिप्ट करा" टॉगल सक्षम करा (ऐच्छिक, AgentBridge प्रमाणपत्र विश्वसनीय असणे आवश्यक).

**पोर्ट संघर्ष:** पोर्ट 8080 वापरात असल्यास, AgentBridge संरचित त्रुटीसह 409 परत करतो. `INSPECTOR_HTTP_PROXY_PORT` पर्यावरणीय चलाद्वारे पोर्ट बदला.

### मोड 4 — संपूर्ण प्रणालीसाठी प्रॉक्सी (प्रगत, ऐच्छिक)

**स्रोत:** OS-स्तरीय प्रॉक्सी सेटिंग्ज (मशीनवरील सर्व ॲप्सना लागू)
**यंत्रणा:** सर्व HTTP/HTTPS ट्रॅफिक HTTP_PROXY लिसनरद्वारे रीडायरेक्ट करण्यासाठी OS API वापरतो:

- **macOS:** `networksetup -setwebproxy / -setsecurewebproxy`
- **Linux:** `gsettings set org.gnome.system.proxy` + `/etc/environment`
- **Windows:** `netsh winhttp set proxy 127.0.0.1:8080`
  **व्याप्ती:** प्रणालीच्या प्रॉक्सी सेटिंग्ज वापरणारे मशीनवरील प्रत्येक ॲप्लिकेशन
  **टीप:** `source` = `"system-proxy"`

**सुरक्षा यंत्रणा:**

- स्वयंचलितपणे बंद करण्याचा टाइमर (डीफॉल्ट 30 मिनिटे, `INSPECTOR_SYSTEM_PROXY_GUARD_MINUTES` द्वारे कॉन्फिगर करता येतो)
- मागील प्रणाली प्रॉक्सी स्थिती DB मध्ये जतन केली जाते आणि पूर्ववत करताना पुनर्स्थापित केली जाते
- सक्रिय असताना वापरकर्ता दुसरीकडे नेव्हिगेट केल्यास डॅशबोर्ड "प्रणाली प्रॉक्सी पूर्ववत करत आहे" प्रॉम्प्ट दाखवतो
- UI मध्ये `⚠ प्रगत` बॅज + स्पष्ट पुष्टीकरण चेकबॉक्स दाखवला जातो

### मोड 5 — TPROXY पारदर्शक डिक्रिप्शन (Linux, root, ऐच्छिक)

**स्रोत:** कर्नल TPROXY + पॉलिसी रूटिंग (`src/mitm/tproxy/`)
**यंत्रणा:** `mangle OUTPUT` मध्ये लक्ष्य पोर्टकडे (डीफॉल्ट `443`) जाणाऱ्या नवीन स्थानिक आउटबाउंड TCP कनेक्शन्सना चिन्हांकित करतो, `ip rule` चिन्हांकित पॅकेट्स स्थानिक डिलिव्हरीकडे पुन्हा रूट करतो आणि `mangle PREROUTING` चे `TPROXY` लक्ष्य ती पारदर्शक (**IP_TRANSPARENT**) लिसनरकडे (डीफॉल्ट पोर्ट `8443`) सुपूर्द करते. लिसनर, डायनॅमिक CA कडून **प्रत्येक SNI होस्टनेमनुसार मागणीनुसार** जारी केलेल्या लीफ प्रमाणपत्रासह TLS समाप्त करतो, डिक्रिप्ट केलेल्या देवाणघेवाणीचे कॅप्चर करतो आणि विनंती पुन्हा एन्क्रिप्ट करून मूळ गंतव्याकडे फॉरवर्ड करतो.
**व्याप्ती:** लक्ष्य पोर्टवरील **कोणतेही** गंतव्य होस्ट — `/etc/hosts` स्पूफ नाही, `HTTP_PROXY` पर्यावरणीय चल नाही आणि संपूर्ण प्रणालीच्या प्रॉक्सीमध्ये बदल नाही. इंटरसेप्ट केलेल्या प्रक्रियेस कोणत्याही कॉन्फिगरेशन बदलाची आवश्यकता नसते, परंतु तिने डायनॅमिक CA वर विश्वास ठेवणे आवश्यक आहे.
**टीप:** `source` = `"tproxy"`

**आवश्यकता:** फक्त Linux (**IP_TRANSPARENT** केवळ Linux वर उपलब्ध आहे), **CAP_NET_ADMIN** क्षमता (root) आणि C टूलचेनसह बिल्ड करणे आवश्यक असलेले नेटिव्ह N-API ॲडऑन (`npm run build:native:tproxy`). हे उपलब्ध नसल्यास, डॅशबोर्ड टॉगल "TPROXY डिक्रिप्शनसाठी Linux + root + नेटिव्ह ॲडऑन आवश्यक आहे" या टूलटिपसह अक्षम केला जातो. फायरवॉल नियम व्यवहारात्मक पद्धतीने लागू/पूर्ववत होतात (क्रॅश झाल्यास कोणताही `mangle` नियम मागे राहत नाही) आणि रीबूट झाल्यावर साफ केले जातात. SO_MARK-आधारित अँटी-लूपमुळे प्रॉक्सीचे स्वतःचे पुन्हा एन्क्रिप्ट केलेले फॉरवर्ड पुन्हा इंटरसेप्ट होण्यापासून रोखले जाते.

ही एक व्यापक उपप्रणाली असून तिचे स्वतंत्र समर्पित ऑपरेटर मार्गदर्शक आहे — संपूर्ण फायरवॉल रेसिपी, प्रत्येक SNI साठी डायनॅमिक CA + ट्रस्ट-स्टोअर इंस्टॉलर, फक्त स्थानिक रूट, अँटी-लूप तपशील आणि कॉन्फिगरेशन स्कीमा यांसाठी `docs/security/MITM-TPROXY-DECRYPT.md` (git; `/docs` मध्ये कंपाइल केलेले नाही) पहा. टॉगल `GET / POST / DELETE /api/tools/agent-bridge/tproxy` द्वारे नियंत्रित केला जातो (टीप: रूट Traffic Inspector प्रिफिक्सऐवजी AgentBridge प्रिफिक्सअंतर्गत आहे).

## §4 LLM-जागरूक वैशिष्ट्ये

### 4.1 प्रकार शोधक (`src/mitm/inspector/kindDetector.ts`)

4 संकेतांचा वापर करून प्रत्येक विनंतीचे `"llm"`, `"app"`, किंवा `"unknown"` असे वर्गीकरण करतो:

1. **होस्ट नोंदणी** — ~18 ज्ञात LLM API होस्टनावे (OpenAI, Anthropic, Gemini, Groq, Mistral, Together, Fireworks, Cohere, Perplexity, Hugging Face, OpenRouter, xAI, Moonshot, इ.)
2. **पथ नमुने** — `/v1/chat/completions`, `/v1/messages`, `/generateContent`, `/v1/responses`, इ.
3. **बॉडीची रचना** — `messages[]` (OpenAI/Claude), `contents[]` (Gemini), `prompt`, `input` फील्ड शोधतो
4. **यूजर-एजंट संकेत** — UA स्ट्रिंगमधील `codex`, `claude`, `gemini`, `antigravity`, `kiro`, `copilot`, `cursor`

Mode 2 द्वारे जोडलेले सानुकूल होस्ट त्यांचा `kind` फॉर्म इनपुटमधून प्राप्त करतात (डीफॉल्ट `"custom"`).

### 4.2 SSE विलीनकर्ता (`src/mitm/inspector/sseMerger.ts`)

**स्वतंत्र क्लीन-रूम अंमलबजावणी.** इव्हेंट पार्सिंग
[WHATWG server-sent events algorithm](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream)
चे अनुसरण करते, तर पुनर्रचना सार्वजनिक [OpenAI](https://platform.openai.com/docs/api-reference/chat/create),
[Anthropic](https://platform.claude.com/docs/en/build-with-claude/streaming), आणि
[Gemini](https://ai.google.dev/api/generate-content#method:-models.streamgeneratecontent)
स्ट्रीमिंग स्कीमांचे अनुसरण करते.

कच्च्या SSE डेल्टा इव्हेंटमधून अंतिम सहाय्यक संदेशाची पुनर्रचना करतो:

- **Anthropic**: निर्देशांकानुसार `content_block_delta` जमा करतो; `text_delta`, `input_json_delta` (टूल कॉल), `thinking_delta` हाताळतो
- **OpenAI**: Chat Completions मधील पर्याय/टूल कॉल आणि Responses API आउटपुट आयटम
  निर्देशांकानुसार जमा करतो
- **Gemini**: `candidates[i].content.parts` जमा करतो
- **अज्ञात**: कच्चे इव्हेंट जसेच्या तसे परत करतो

Response टॅबमध्ये टॉगल दिसतो: **"कच्चे इव्हेंट ↔ विलीन केलेले"**.

### 4.3 संभाषण सामान्यीकारक (`src/mitm/inspector/conversationNormalizer.ts`)

**स्वतंत्र क्लीन-रूम अंमलबजावणी.** सामान्यीकरण स्थानिक ब्लॅक-बॉक्स
करार आणि सार्वजनिक OpenAI, Anthropic, आणि Gemini संदेश स्कीमांद्वारे परिभाषित केले आहे; कोणत्याही अपस्ट्रीम
अंमलबजावणीचा स्रोत वापरलेला नाही.

रेंडरिंगपूर्वी OpenAI, Anthropic, आणि Gemini संदेश स्वरूपांना एका `NormalizedConversation` मध्ये रूपांतरित करतो:

```ts
interface NormalizedConversation {
  request: NormalizedTurn[]; // विनंतीच्या बॉडीमधील messages / contents / prompt
  response: NormalizedTurn[]; // सहाय्यकाचा प्रतिसाद (sseMerger द्वारे विलीन केलेला)
  contextKey: string | null; // सिस्टम-प्रॉम्प्टचा SHA-256 फिंगरप्रिंट
}
```

ब्लॉक प्रकार: `text`, `tool_use`, `tool_result`. प्रदाता कोणताही असला तरी Conversation टॅब हीच रचना वापरतो.

### 4.4 संदर्भ कीचे रंगीकरण (`src/mitm/inspector/contextKey.ts`)

- सिस्टम प्रॉम्प्टचे `SHA-256` मोजतो (पहिला `role:system` संदेश, किंवा `system` फील्ड, किंवा Gemini `systemInstruction`)
- 12-अक्षरी हेक्स उपसर्ग परत करतो (`"a3f9c2..."`)
- डाव्या सीमारेषेच्या पट्टीसाठी फ्रंटएंड ही की निश्चित HSL रंगाशी मॅप करतो
- **"समान संदर्भ" फिल्टर**: `ctx #a3f` चिपवर क्लिक केल्याने केवळ समान फिंगरप्रिंट असलेल्या विनंत्या दाखवण्यासाठी फिल्टर जोडला जातो

यामुळे एकाच एजंट सत्रात चालणाऱ्या वेगवेगळ्या "व्यक्तिमत्त्वांमध्ये" किंवा कार्यांमध्ये दृश्यात्मक फरक करणे सोपे होते.

### 4.5 LLM मेटाडेटा निष्कर्षण

LLM विनंत्यांसाठी, LLM Details टॅब पुढील माहिती काढतो:

```ts
interface LlmMetadata {
  provider: string | null; // "openai" | "anthropic" | "gemini" | ...
  apiKind: string | null; // "chat.completions" | "messages" | "embeddings" | ...
  model: string | null; // विनंतीच्या बॉडीमधून किंवा प्रतिसादातून
  messages: number; // टर्नची संख्या
  tokensIn: number | null; // usage.prompt_tokens / usage.input_tokens
  tokensOut: number | null; // usage.completion_tokens / usage.output_tokens
  streamed: boolean; // SSE प्रतिसाद असल्यास true
  mappedTo: string | null; // x-omniroute-mapped हेडर
  costEstimateUsd: number | null; // OmniRoute किंमतीवर आधारित अंदाजित खर्च
}
```

### 4.6 थेट प्रलंबित विनंती फिल्टर

विनंतीचे `status` फील्ड `number | "in-flight" | "error"` असते — विनंती सुरू होताच नोंद
`"in-flight"` म्हणून जोडली जाते आणि प्रतिसाद (किंवा त्रुटी) आल्यावर **त्याच ठिकाणी अद्ययावत**
केली जाते. टूलबारचा **"Live"** टॉगल
(`liveOnly`, i18n की `trafficInspector.liveOnly`) सूची केवळ अशा नोंदींपुरती
मर्यादित करतो ज्यांचे `status === "in-flight"` आहे, ज्यामुळे तुम्ही खुली कनेक्शन्स रिअल टाइममध्ये पाहू शकता.

हा फिल्टर
`src/lib/inspector/matchesTrafficFilter.ts` मधील शुद्ध, क्लायंट-साइड प्रेडिकेट आहे:

```ts
if (f.liveOnly && req.status !== "in-flight") return false;
```

टॉगलची स्थिती `useTrafficFilters` (इन्स्पेक्टर डॅशबोर्ड हुक्स) मध्ये राहते आणि
इतर फिल्टर्ससह (प्रोफाइल, होस्ट, एजंट, स्रोत, स्थिती, संदर्भ) एकत्रित होते.

### 4.7 प्रक्रिया विशेषण (Linux)

Linux वर, प्रत्येक इंटरसेप्ट केलेली विनंती **मूळ स्थानिक
प्रक्रियेशी** जोडली जाऊ शकते. `InterceptedRequest` मध्ये दोन पर्यायी फील्ड जोडली जातात:

```ts
pid?: number;          // मूळ प्रक्रियेचा आयडी (फक्त Linux)
processName?: string;  // मूळ प्रक्रियेचे नाव (फक्त Linux)
```

`src/mitm/inspector/processAttribution.ts` कनेक्शनचा _क्लायंट_
तात्पुरता पोर्ट PID + नावाशी पुढीलप्रमाणे मॅप करतो:

1. पोर्टसाठी सॉकेट inode शोधण्याकरिता `/proc/net/tcp` आणि `/proc/net/tcp6` वाचणे
   (`parseProcNetTcpForInode`, एक शुद्ध फिक्स्चर-चाचणीयोग्य पार्सर).
2. `socket:[<inode>]` कडे निर्देश करणाऱ्या सिमलिंकसाठी `/proc/<pid>/fd/` स्कॅन करणे.
3. `/proc/<pid>/comm` मधून प्रक्रियेचे नाव वाचणे.

1-सेकंदाचा TTL कॅश लोड असताना procfs स्कॅनचा खर्च मर्यादित ठेवतो. विशेषण
**सर्वोत्तम-प्रयत्नावर आधारित** आहे — कोणतेही अपयश `null` मध्ये निराकरण होते आणि कॅप्चरला कधीही अवरोधित करत नाही.
macOS/Windows वर हे फंक्शन `null` परत करते (स्टब; `lsof`/`GetExtendedTcpTable`
समर्थन हे पुढील काम आहे).

## §5 सत्रे

### 5.1 सत्र रेकॉर्ड करणे

1. साधनपट्टीतील **"● सत्र रेकॉर्ड करा"** वर क्लिक करा → नाव प्रविष्ट करा (पर्यायी)
2. लाइव्ह टेल नेहमीप्रमाणे सुरू राहते; लाल रंगाचा स्पंदित निर्देशक `◉ REC · <name> · 00:42 · 23 विनंत्या` दाखवतो
3. **"⏹ थांबवा"** वर क्लिक करा → सत्राचा स्नॅपशॉट `inspector_sessions` + `inspector_session_requests` मध्ये जतन केला जातो

### 5.2 रेकॉर्ड केलेले सत्र पाहणे

साधनपट्टीतील **सत्रे** ड्रॉपडाउन जतन केलेली सत्रे सूचीबद्ध करते. एखादे सत्र निवडल्यावर:

- सत्राचा स्नॅपशॉट लोड होतो (स्थिर स्थिती)
- बॅनर दाखवतो: `रेकॉर्ड केलेले सत्र "<name>" पाहत आहात — [लाइव्ह दृश्याकडे परत जा]`
- Recharts एकत्रित आकडेवारीसह आकडेवारी टॅब उपलब्ध होतो

### 5.3 निर्यात स्वरूपे

प्रत्येक सत्र पुढील स्वरूपांत निर्यात करता येते:

| स्वरूप                     | वापर                                                                               |
| -------------------------- | ---------------------------------------------------------------------------------- |
| **HAR** (HTTP Archive 1.2) | Chrome DevTools, Charles, Fiddler यांच्याशी सुसंगत — ऑफलाइन विश्लेषणासाठी आयात करा |
| **JSONL**                  | प्रत्येक ओळीत एक `InterceptedRequest` — `llm-interceptor` स्वरूपाशी सुसंगत         |

`GET /api/tools/traffic-inspector/sessions/{id}/export.har` द्वारे किंवा सत्रे ड्रॉपडाउनमधील ⬇ बटण वापरून निर्यात करा.

## §6 सुरक्षितता

Traffic Inspector **सर्व इंटरसेप्ट केलेली HTTPS वाहतूक** दाखवतो, ज्यामध्ये प्राधिकरण हेडर आणि विनंती बॉडी समाविष्ट असतात. पुढील नियंत्रणे लागू आहेत:

| नियंत्रण                                | तपशील                                                                                                                                                                                  |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LOCAL_ONLY**                          | सर्व रूट आणि WebSocket एंडपॉइंट केवळ लूपबॅकवर उपलब्ध आहेत (प्रमाणीकरणापूर्वी `routeGuard.ts` मध्ये लागू केलेले)                                                                        |
| **गुपिते लपवणे**                        | रेषीय `maskSecret()` स्कॅनर `TrafficBuffer.push()` पूर्वी RFC 6750 Bearer क्रेडेन्शियल्स, प्रदाता-उपसर्ग असलेल्या की आणि लांब अपारदर्शक टोकन संपादित करतो                              |
| **बॉडी आकार मर्यादा**                   | `INSPECTOR_MAX_BODY_KB` पेक्षा मोठ्या बॉडी (डीफॉल्ट 1024 KB) `"(कार्यक्षमतेसाठी संक्षिप्त केले)"` सूचनेसह संक्षिप्त केल्या जातात                                                       |
| **हेडर निर्जंतुकीकरण**                  | नावे लोअरकेसमध्ये रूपांतरित केली जातात; फ्रेमिंग/हॉप-बाय-हॉप आणि प्रॉक्सी-ऑथ हेडर वगळले जातात; कुकी पूर्णपणे संपादित केल्या जातात; क्रेडेन्शियल मूल्ये `maskSecret()` कडे सोपवली जातात |
| **CSP**                                 | इंजेक्ट केलेल्या प्रतिसाद बॉडीद्वारे होणारा XSS टाळण्यासाठी Traffic Inspector पृष्ठांवर कठोर Content Security Policy                                                                   |
| **डीफॉल्टनुसार कायमस्वरूपी संचयन नाही** | `TrafficBuffer` मेमरीमध्ये असतो आणि सर्व्हर रीस्टार्ट झाल्यावर नष्ट होतो. सत्रे स्पष्टपणे रेकॉर्ड केली असतील तेव्हाच कायमस्वरूपी जतन केली जातात                                        |

### लागू केलेले कठोर नियम

| नियम                              | अंमलबजावणी                                                                                |
| --------------------------------- | ----------------------------------------------------------------------------------------- |
| **#12** `sanitizeErrorMessage`    | Traffic Inspector रूटमधील सर्व HTTP त्रुटी प्रतिसाद निर्जंतुक केले जातात                  |
| **#15 + #17** `isLocalOnlyPath()` | `/api/tools/traffic-inspector/` हे LOCAL_ONLY + SPAWN_CAPABLE आहे (सिस्टम प्रॉक्सी कमांड) |

### ज्ञात मर्यादा

- **संपूर्ण-सिस्टम प्रॉक्सी मोड** VPN क्लायंट आणि SSO सह मशीनवरील सर्व अनुप्रयोगांवर परिणाम करतो. नेहमी स्वयं-अक्षम टाइमरसह वापरा. सामायिक मशीनवर वापरू नका.
- **CONNECT टनेल HTTPS**: TLS इंटरसेप्शन सक्षम नसल्यास मोड 3 (HTTP_PROXY) HTTPS गंतव्यांसाठी केवळ टनेल मेटाडेटा कॅप्चर करतो. हे हेतुपुरस्सर आहे — AgentBridge प्रमाणपत्रावर विश्वास नसताना पारदर्शक कॅप्चर केल्यास त्या ॲप्सचे TLS सत्यापन अयशस्वी होईल.
- **काही घटकांमधील हार्डकोड केलेल्या स्ट्रिंग्स**: काही UI घटकांमध्ये (F7/F8) अद्याप i18n कीद्वारे समाविष्ट नसलेल्या काही हार्डकोड केलेल्या स्ट्रिंग्स आहेत. i18n तफावत अहवालात यांची ज्ञात मर्यादा म्हणून नोंद केली आहे; पुढील टप्प्यात त्यांचे स्थलांतर केले जाईल. प्रभावित स्ट्रिंग्स या UI सजावटी लेबल्स आहेत, ज्यांना कार्यात्मक वापरासाठी भाषांतराची आवश्यकता नाही.

## §7 समस्या निवारण

### WebSocket कनेक्शन खंडित होणे

लाइव्ह टेलमध्ये "कनेक्शन खंडित झाले" असे दिसल्यास:

1. सर्व्हर अजूनही चालू आहे का ते तपासा: `GET /api/tools/traffic-inspector/capture-modes`
2. पृष्ठ पुन्हा लोड करा — WebSocket पुन्हा कनेक्ट होते आणि नवीन स्नॅपशॉट प्राप्त करते
3. सर्व्हर रीस्टार्ट केला असल्यास, इन-मेमरी बफर साफ झालेला असेल — सत्र रेकॉर्ड केले नसल्यास जुन्या नोंदी उपलब्ध राहणार नाहीत

### पोर्ट 8080 संघर्ष

HTTP_PROXY मोड सुरू होऊ शकत नसल्यास:

```bash
lsof -i :8080    # प्रक्रिया शोधा
```

पोर्ट बदला:

```bash
# .env
INSPECTOR_HTTP_PROXY_PORT=8888
```

### सिस्टम प्रॉक्सी पूर्ववत न होणे

सिस्टम-व्यापी प्रॉक्सी मोड सक्रिय असताना OmniRoute क्रॅश झाल्यास:

**macOS:**

```bash
networksetup -setwebproxystate Wi-Fi off
networksetup -setsecurewebproxystate Wi-Fi off
```

**Linux (GNOME):**

```bash
gsettings set org.gnome.system.proxy mode 'none'
```

**Windows:**

```cmd
netsh winhttp reset proxy
```

पुढील वेळी डॅशबोर्ड लोड झाल्यावर, DB स्थितीमध्ये प्रॉक्सी सक्रिय असल्याचे आढळल्यास तो "सिस्टम प्रॉक्सी पूर्ववत करा" हा पर्यायही देईल.

### बफर पूर्ण

बफर `INSPECTOR_BUFFER_SIZE` (डीफॉल्ट 1000) पर्यंत पोहोचल्यावर, नवीन नोंदींमुळे सर्वांत जुन्या नोंदी काढल्या जातात. महत्त्वाच्या विनंत्या गमावल्या जात असल्यास:

- `INSPECTOR_BUFFER_SIZE` वाढवा (उदा., 5000) — यामुळे अधिक नोंदी टिकवण्यासाठी जास्त मेमरी वापरली जाते
- संबंधित कालावधी DB मध्ये कायम ठेवण्यासाठी सत्र रेकॉर्ड करा
