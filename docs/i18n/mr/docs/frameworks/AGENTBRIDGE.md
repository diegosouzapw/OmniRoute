AgentBridge हा OmniRoute चा MITM (Man-in-the-Middle) प्रॉक्सी आहे, जो IDE AI एजंट्सकडील HTTPS ट्रॅफिकमध्ये हस्तक्षेप करतो आणि ते OmniRoute च्या एकीकृत रूटिंग इंजिनद्वारे पुनर्निर्देशित करतो. तो **10 IDE एजंट्सना** समर्थन देतो — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code आणि Trae (तपास सुरू आहे) — ज्यामुळे OmniRoute हा बाजारातील AI कोडिंग सहाय्यकांसाठी सर्वाधिक व्यापक कव्हरेज असलेला MITM प्रॉक्सी ठरतो.

**डॅशबोर्डचे स्थान:** `/dashboard/tools/agent-bridge`
**साइडबार गट:** साधने (Cloud Agents नंतर)
**हे देखील पहा:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — हस्तक्षेप केलेल्या सर्व ट्रॅफिकचे रिअल-टाइममध्ये निरीक्षण करा; `docs/security/MITM-TPROXY-DECRYPT.md` (git; `/docs` मध्ये संकलित केलेले नाही) — `/api/tools/agent-bridge/tproxy` रूटद्वारे चालवला जाणारा Linux TPROXY पारदर्शक-डिक्रिप्ट कॅप्चर मोड.

## §1 आढावा

### AgentBridge म्हणजे काय?

जेव्हा एखादा IDE एजंट (उदा., GitHub Copilot, Cursor, Claude Code) API कॉल करतो, तेव्हा तो थेट अपस्ट्रीम AI प्रदात्याशी (OpenAI, Anthropic इ.) कनेक्ट होतो. AgentBridge कोणताही एजंट कॉन्फिगरेशन बदल न करता — TLS स्तरावर त्या कनेक्शनमध्ये पारदर्शकपणे हस्तक्षेप करतो — आणि विनंती OmniRoute द्वारे पुनर्लेखित करतो.

याचा अर्थ तुम्ही पुढील गोष्टी करू शकता:

- **कोणताही एजंट कोणत्याही प्रदात्याकडे पुनर्निर्देशित करा**: Copilot OpenAI शी संवाद साधत आहे? त्याला Anthropic Claude, Gemini किंवा OmniRoute च्या 352 प्रदात्यांपैकी कोणत्याही प्रदात्याकडे पुनर्निर्देशित करा.
- **मॉडेल मॅपिंग लागू करा**: हँडलर स्तरावर पारदर्शकपणे `gemini-3-flash` → `claude-sonnet-4.7`.
- **सर्व एजंट ट्रॅफिकचे निरीक्षण करा**: हस्तक्षेप केलेली प्रत्येक विनंती [Traffic Inspector](./TRAFFIC_INSPECTOR.md) वर प्रकाशित केली जाते.
- **OmniRoute ची लवचिकता लागू करा**: कॉम्बो रूटिंग, सर्किट ब्रेकर्स, फॉलबॅक्स आणि खर्च ट्रॅकिंग IDE एजंट ट्रॅफिकसाठीही कार्य करतात.

## §2 आर्किटेक्चर

### 2.1 घटकांचा आढावा

```
IDE एजंट (VS Code / Cursor / इत्यादी)
    │  HTTPS (पोर्ट 443)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← DNS पुनर्निर्देशन
    │
    ▼
src/mitm/server.cjs  (पोर्ट 443, CJS चाइल्ड प्रोसेस)
    │  Host हेडर SNI द्वारे लक्ष्य निर्धारित करतो
    │  AgentBridge CA ने स्वाक्षरी केलेले प्रत्येक-SNI साठी TLS प्रमाणपत्र तयार करतो
    ├── बायपास सूचीशी जुळते? → TCP पासथ्रू (डिक्रिप्शन नाही)
    ├── लक्ष्याशी जुळते? → fetch → OmniRoute राउटर (पोर्ट 20128)
    │       └── handler.intercept() — TypeScript
    │               ├── विनंतीच्या बॉडी/हेडर्सवर maskSecrets()
    │               ├── TrafficBuffer.push() — Traffic Inspector वर प्रकाशित करते
    │               └── fetchRouter() → /v1/chat/completions
    └── जुळत नाही? → TCP पासथ्रू (डिक्रिप्शन नाही)
```

### 2.2 MITM सर्व्हर (`src/mitm/server.cjs`)

मुख्य MITM सर्व्हर Node.js CJS चाइल्ड प्रोसेस म्हणून चालतो (विद्यमान CJS कोडबेस पुन्हा लिहिणे टाळण्यासाठी). तो:

- पोर्ट 443 वर ऐकतो (विशेषाधिकार किंवा `authbind`/`setcap` आवश्यक)
- OS कडून CONNECT टनेल्स प्राप्त करतो (`/etc/hosts` DNS पुनर्निर्देशनाद्वारे)
- AgentBridge CA (`DATA_DIR/mitm/ca.crt`) ने स्वाक्षरी केलेली प्रत्येक-SNI साठी TLS प्रमाणपत्रे तयार करतो
- `targets/index.ts` रजिस्ट्रीद्वारे Host हेडरच्या आधारे लक्ष्य एजंट निर्धारित करतो
- `http://127.0.0.1:20128` वर HTTP द्वारे TypeScript हँडलर स्तराकडे पाठवतो

`TARGET_HOSTS`, `DATA_DIR/mitm/targets.json` मधून लोड केले जाते (`targets/index.ts` द्वारे बूटच्या वेळी लिहिले जाते), ज्यामुळे CJS सर्व्हर रीस्टार्ट न करता डायनॅमिक अद्यतने करता येतात.

> **रूट-CA मॉडेल (#6684).** वर दिलेले CA-द्वारे-स्वाक्षरी केलेल्या प्रत्येक-SNI-प्रमाणपत्राचे वर्णन
> हे #6684 मध्ये जोडलेले पर्सिस्टेड रूट-CA मॉडेल आहे (`src/mitm/cert/rootCa.ts` +
> `src/mitm/_internal/rootCaShim.cjs`, `src/mitm/tproxy/dynamicCert.ts` मध्ये TPROXY साठी
> आधीच सिद्ध झालेले CA/लीफ क्रिप्टो पुन्हा वापरते) — ते जुन्या एकल स्थिर
> स्व-स्वाक्षरीकृत लीफची (`src/mitm/cert/generate.ts`, अजूनही केवळ antigravity होस्टपुरती
> मर्यादित) जागा घेते, जी डिस्कवरील `server.crt`/`server.key` जोडीने सूचित होते.
> **स्थलांतर वर्तन**: नवीन इंस्टॉलेशनला (पूर्वीचे `server.crt` नसल्यास) रूट-CA मॉडेल
> आपोआप मिळते; जुन्या स्थिर लीफवर आधीच विश्वास ठेवणारे इंस्टॉलेशन ऑपरेटरने
> `MITM_ROOT_CA_ENABLED=true` सेट करून ब्रिज रीस्टार्ट करेपर्यंत तेच वापरत राहते
> (`src/mitm/cert/migration.ts` हे शुद्ध निर्णय फंक्शन आहे — **कोणत्याही** होस्टसाठी
> लीफवर स्वाक्षरी करू शकणारा विश्वासार्ह MITM CA जुन्या निश्चित-SAN लीफपेक्षा प्रत्यक्षात
> अधिक शक्तिशाली असतो, त्यामुळे आधीच विश्वासार्ह असलेल्या इंस्टॉलेशनसाठी हे स्विच
> कधीही मूकपणे केले जात नाही). CA प्रमाणपत्र जुन्या लीफने वापरलेल्या त्याच
> `omniroute-mitm.crt` ट्रस्ट-स्टोअर स्लॉटमध्ये इंस्टॉल होते
> (`cert/install.ts::installCaCert`) — दुहेरी-विश्वास स्वच्छतेची आवश्यकता नाही.

### 2.3 हँडलर बेस (`src/mitm/handlers/base.ts`)

सर्व एजंट हँडलर्स `MitmHandlerBase` विस्तारित करतात:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // संरक्षित सहाय्यक: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

प्रत्येक हँडलर प्रॉक्सी करण्यापूर्वी `hookBufferStart()` आणि पूर्ण झाल्यावर `hookBufferUpdate()` कॉल करतो. हे `InterceptedRequest` नोंदी `globalTrafficBuffer` मध्ये पुश करतात ([Traffic Inspector](./TRAFFIC_INSPECTOR.md) §4 पहा).

### 2.4 लक्ष्य रजिस्ट्री (`src/mitm/targets/`)

प्रत्येक एजंटची एक घोषणात्मक लक्ष्य फाइल असते:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

रजिस्ट्री (`targets/index.ts`) `ALL_TARGETS` एक्सपोर्ट करते आणि बूटच्या वेळी `DATA_DIR/mitm/targets.json` तयार करते.

### 2.5 पासथ्रू आणि बायपास सूची (`src/mitm/passthrough.ts`)

**बायपास सूची** (लक्ष्य जुळणीपेक्षा प्राधान्य देऊन प्रथम तपासली जाते):

- डीफॉल्ट पॅटर्न्स: बँकिंग होस्ट्स, `.gov.`, OAuth/SSO प्रदाते (Okta, Auth0), इत्यादी
- वापरकर्ता पॅटर्न्स: DB टेबल `agent_bridge_bypass` मध्ये संग्रहित
- बायपास केलेल्या होस्ट्सना पारदर्शक TCP टनेल मिळते — TLS **कधीही डिक्रिप्ट केले जात नाही**

**पासथ्रू डीफॉल्ट** (लक्ष्याशी जुळत नाही आणि बायपासमध्येही नाही):

- यालाही TCP टनेल मिळते — कनेक्शन्स कधीही खंडित केली जात नाहीत
- AgentBridge मुळे सर्वसाधारण सिस्टीम HTTPS ट्रॅफिकमध्ये व्यत्यय येण्यापासून प्रतिबंधित करते

राउटिंग प्राधान्य:

```
बायपास सूची → लक्ष्य जुळणी → पासथ्रू
```

### 2.6 अपस्ट्रीम CA प्रमाणपत्र (`src/mitm/upstreamTrust.ts`)

कस्टम CA असलेल्या कॉर्पोरेट नेटवर्क वातावरणांसाठी:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

सेट केल्यावर, अतिरिक्त CA प्रमाणपत्रासह `undici` चा ग्लोबल डिस्पॅचर कॉन्फिगर केला जातो, ज्यामुळे AgentBridge ला कॉर्पोरेट TLS टर्मिनेशन प्रॉक्सींद्वारे अपस्ट्रीम प्रदात्यांपर्यंत पोहोचता येते.

### 2.7 गुपिते लपवणे (`src/mitm/maskSecrets.ts`)

स्वतंत्र क्लीन-रूम स्कॅनर, विनंती बॉडीज आणि क्रेडेन्शियल हेडर्स Traffic Inspector बफर किंवा कोणत्याही लॉगमध्ये प्रवेश करण्यापूर्वी त्यांच्यावर लागू केला जातो. तो एकच रेषीय पास करतो:

- `sk-` / `ak-` / `pk-` उपसर्ग असलेली टोकेन्स (OpenAI/Anthropic-शैली)
- RFC 6750 `Authorization: Bearer <token>` क्रेडेन्शियल्स, संपूर्ण-टोकन प्राधान्यासह
- सर्वसाधारण लांब अपारदर्शक टोकेन्स (≥40 वर्ण), ज्यात डॉटयुक्त आणि पॅडेड स्वरूपांचा समावेश आहे

`sanitizeHeaders()` कायम ठेवलेली नावे लोअरकेसमध्ये रूपांतरित करते, अॅरे मूल्ये निर्धारक पद्धतीने जोडते, सामायिक हॉप-बाय-हॉप/फ्रेमिंग डिनायलिस्ट (प्रॉक्सी प्रमाणीकरणासह) वगळते, `cookie` आणि `set-cookie` पूर्णपणे लपवते आणि क्रेडेन्शियल मूल्ये स्कॅनरकडे सोपवते.

| प्रमाणपत्र डाउनलोड करा        | मॅन्युअल इंस्टॉलेशनसाठी `ca.crt` डाउनलोड करते                                   |

### 3.2 प्रमाणपत्रावर विश्वास ठेवणे

IDE नी MITM कनेक्शन स्वीकारण्यापूर्वी AgentBridge CA प्रमाणपत्रावर OS ने विश्वास ठेवणे आवश्यक आहे.

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Keychain):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

किंवा डॅशबोर्डमधील "प्रमाणपत्रावर विश्वास ठेवा" बटण वापरा (हे तुमच्या OS साठी योग्य कमांड चालवते आणि आवश्यक असल्यास sudo प्रॉम्प्ट दाखवते).

#### Electron-आधारित IDE, OS ट्रस्ट स्टोअरकडे (`NODE_EXTRA_CA_CERTS`) दुर्लक्ष करतात

काही IDE — विशेषतः **Antigravity IDE** आणि इतर Electron / VS Code-व्युत्पन्न अॅप्स — स्वतःचा
Node.js रनटाइम समाविष्ट करतात, जो आउटबाउंड `fetch`/HTTPS साठी **OS ट्रस्ट स्टोअर तपासत नाही**.
OS/NSS स्तरावर CA वर विश्वास ठेवणे IDE च्या मूळ **बॅकएंडसाठी** पुरेसे असते
(उदा. Go लँग्वेज सर्व्हर, जो OS CA बंडल वापरतो), परंतु **Electron फ्रंटएंडमध्ये**
TLS तरीही अयशस्वी होईल — MITM लॉगमध्ये बॅकएंडचे बूटस्ट्रॅप कॉल `200` परत करत असल्याचे
दिसत असले, तरी अॅपमध्ये _लॉग आउट झालेले_ दिसते किंवा _"कनेक्शन त्रुटी"_ दाखवली जाते.
दोन पायऱ्या आवश्यक आहेत आणि दोन्ही महत्त्वाच्या आहेत:

1. रनटाइमला CA स्पष्टपणे निर्देशित करा:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **त्या शेलमधून IDE सुरू करा.** डेस्कटॉप आयकॉन / Dock / Start मेनूमधून ते सुरू केल्यास
   शेल एक्सपोर्ट्स वारशाने मिळत **नाहीत**, आणि `~/.config/environment.d/*.conf` फक्त
   नव्याने ग्राफिकल लॉगिन केल्यानंतरच लागू होते. आधी IDE पूर्णपणे बंद करा — Electron च्या
   सिंगलटन लॉकमुळे दुसऱ्यांदा सुरू केल्यास फक्त विद्यमान प्रोसेसवर फोकस होते आणि नवीन एन्व्हायर्नमेंट दुर्लक्षित केले जाते.

वरील OS-trust + NSS पायरी अजूनही आवश्यक आहे (काही प्रमाणीकरण प्रवाहांद्वारे वापरला जाणारा Chromium
नेटवर्क स्टॅक प्रति-वापरकर्ता NSS स्टोअर वाचतो आणि `*.googleapis.com` साठी त्याचे स्वतःचे स्थिर पिन
असतात, ज्यांना स्थानिकरीत्या विश्वासार्ह CA अधिलिखित करते). याव्यतिरिक्त `NODE_EXTRA_CA_CERTS` हे
Node `fetch` मार्गासाठी लागू होते.

### 3.3 DNS राउटिंग

तुम्हाला इंटरसेप्ट करायच्या प्रत्येक एजंटसाठी, त्याचे API होस्ट `127.0.0.1` वर रिझॉल्व्ह झाले पाहिजेत. तुम्ही Setup Wizard मध्ये एखाद्या एजंटसाठी DNS टॉगल करता तेव्हा AgentBridge `/etc/hosts` नोंदी स्वयंचलितपणे व्यवस्थापित करते.

GitHub Copilot साठी `/etc/hosts` नोंदींचे उदाहरण:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 मॉडेल मॅपिंग

स्रोत → लक्ष्य मॅपिंग परिभाषित करण्यासाठी प्रत्येक एजंट कार्डमधील मॉडेल मॅपिंग तक्ता वापरा:

| स्रोत मॉडेल (एजंटचे मूळ) | लक्ष्य मॉडेल (OmniRoute) |
| ------------------------ | ------------------------ |
| `gpt-4o`                 | `claude-sonnet-4.7`      |
| `*` (वाइल्डकार्ड)        | `claude-haiku-4.7`       |

वाइल्डकार्ड `*` कोणतेही न ओळखलेले मॉडेल निर्दिष्ट लक्ष्याशी मॅप करते. हे `agent_bridge_mappings` तक्त्यात कायमस्वरूपी जतन केले जाते.

> **टीप — एजंटचे वास्तविक मॉडेल ID शोधा.** एखादे IDE त्याच्या UI लेबलांपेक्षा वेगळी मॉडेल नावे
> पाठवू शकते आणि ती प्रमुख आवृत्त्यांदरम्यान बदलू शकतात. उदाहरणार्थ, **Antigravity 2**
> नेटवर्कवरून `gemini-3.1-pro-low`, `gemini-pro-agent`, आणि `gemini-3.1-flash-lite` पाठवते —
> जुन्या दस्तऐवजांमध्ये दाखवलेले `gemini-2.5-pro` नाही. जुळणारे मॅपिंग नसताना एक चॅट पाठवा:
> MITM अचूक इनकमिंग `model:` लॉग करते आणि विनंती पुढे पाठवते. त्या अक्षरशः मूल्याचे मॅपिंग करा;
> त्यानंतर पुढील विनंती इंटरसेप्ट केली जाते आणि तुमच्या लक्ष्याकडे रूट केली जाते.

### 3.5 जोखमीची सूचना

AgentBridge ती क्रेडेन्शियल्स (OAuth टोकन, API की) इंटरसेप्ट करते जी IDE अपस्ट्रीम प्रदात्यांकडे प्रमाणीकरण करण्यासाठी वापरते. लॉगिंग करण्यापूर्वी ती **मास्क केली जातात** (§2.7 पहा), परंतु OmniRoute च्या MITM स्तराला ती दृश्यमान असतात. प्रत्येक एजंट प्रथमच सक्रिय केल्यावर बंद करता येणारा जोखमीच्या सूचनेचा मोडल दिसतो.

### 3.6 देखभाल आणि निदान

डॅशबोर्डमध्ये **देखभाल आणि निदान** कार्ड (`AgentBridgeMaintenanceCard`, `src/app/(dashboard)/dashboard/tools/agent-bridge/components/` मध्ये) उपलब्ध आहे, जे यापूर्वी UI नसलेले कार्यात्मक MITM रूट्स दाखवते. त्याचे उपशीर्षक: _"कॅप्चर पाइपलाइनची स्व-चाचणी करा, शिल्लक राहिलेली सिस्टम स्थिती पूर्ववत करा आणि तुमचा सेटअप मशीनदरम्यान हलवा."_ कार्डचे क्लायंट हेल्पर्स `src/lib/inspector/agentBridgeMaintenanceApi.ts` मध्ये आहेत.

| बटण                     | रूट                                    | ते काय करते                                                                                                                                                                                                    |
| ----------------------- | -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **निदान करा**           | `GET /api/tools/agent-bridge/diagnose` | कॅप्चर-पाइपलाइनची स्व-चाचणी चालवते आणि प्रत्येक तपासणीचा अहवाल दाखवते (✓/✗ + निराकरणाची सूचना).                                                                                                                |
| **दुरुस्ती करा**        | `POST /api/tools/agent-bridge/repair`  | क्रॅश किंवा SIGKILL मुळे मागे राहिलेली अनाथ MITM प्रणाली स्थिती (DNS स्पूफ नोंदी, रूट CA, सिस्टम प्रॉक्सी) पूर्ववत करते. आयडेम्पोटंट — स्थिती स्वच्छ असल्यास "दुरुस्त करण्यासारखे काहीही नाही" असा अहवाल देते. |
| **CA काढून टाका**       | `DELETE /api/tools/agent-bridge/cert`  | OS ट्रस्ट स्टोअरमधून MITM रूट CA वरील विश्वास काढून ते हटवते (स्पष्ट, आयडेम्पोटंट). CA सध्या विश्वसनीय असेल तेव्हाच दाखवले जाते; इनलाइन "CA काढून टाकायचे?" पुष्टीकरण आवश्यक असते.                             |
| **कॉन्फिग निर्यात करा** | `GET /api/tools/agent-bridge/config`   | पोर्टेबल कॉन्फिग JSON डाउनलोड करते (§3.7 पहा).                                                                                                                                                                 |
| **कॉन्फिग आयात करा**    | `POST /api/tools/agent-bridge/config`  | यापूर्वी निर्यात केलेला कॉन्फिग JSON अपलोड करते (§3.7 पहा).                                                                                                                                                    |

**निदान तपासण्या** (`src/mitm/inspector/diagnostics.ts` मधील `summarizeDiagnostics()`). रूट प्रत्येकासाठी परिणामकारक प्रोब चालवतो आणि बूलियन मूल्ये शुद्ध सारांशकाराकडे पाठवतो; एकच `healthy` निकाल आणि प्रत्येक अपयशासाठी सूचना परत केली जाते:

| तपासणीचे नाव       | ते काय सत्यापित करते                                        | अपयश आल्यास सूचना                                                                                                                                                |
| ------------------ | ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server-running`   | MITM सर्व्हर प्रक्रिया सक्रिय आहे                           | "MITM सर्व्हर चालू नाही. तो AgentBridge टॅबमधून सुरू करा."                                                                                                       |
| `server-reachable` | MITM सर्व्हर त्याच्या पोर्टवर कनेक्शन स्वीकारतो (TCP प्रोब) | "MITM सर्व्हर त्याच्या पोर्टवर कनेक्शन स्वीकारत नाही. पोर्ट मोकळा आहे आणि त्याच्याशी बाइंड करण्यासाठी आपल्याकडे विशेषाधिकार आहेत याची खात्री करा."               |
| `cert-exists`      | MITM प्रमाणपत्र डिस्कवर निर्माण केले गेले आहे               | "अद्याप कोणतेही MITM प्रमाणपत्र निर्माण केलेले नाही. AgentBridge टॅबमधून एक प्रमाणपत्र निर्माण करा."                                                             |
| `cert-trusted`     | MITM रूट CA OS ट्रस्ट स्टोअरमध्ये आहे                       | "MITM रूट CA वर OS स्टोअरचा विश्वास नाही, त्यामुळे TLS इंटरसेप्शन अयशस्वी होईल. AgentBridge टॅबमधून प्रमाणपत्रावर विश्वास ठेवा."                                 |
| `dns-configured`   | लक्ष्य होस्टनावे `/etc/hosts` मध्ये स्पूफ केलेली आहेत       | "लक्ष्य होस्टनावे /etc/hosts मध्ये स्पूफ केलेली नाहीत, त्यामुळे ट्रॅफिक प्रॉक्सीपर्यंत कधीच पोहोचत नाही. आपण कॅप्चर करू इच्छित असलेल्या एजंटसाठी DNS सक्षम करा." |

**अनाथ स्थितीचा बॅनर:** पृष्ठाला क्रॅशमुळे मागे राहिलेली स्थिती (DNS स्पूफ / CA / सिस्टम प्रॉक्सी) आढळल्यास, कार्डवर अंबर रंगाचा बॅनर दिसतो — _"मागील सत्राने प्रणाली स्थिती मागे सोडली आहे (DNS स्पूफ, CA किंवा सिस्टम प्रॉक्सी). ती साफ करण्यासाठी दुरुस्ती चालवा."_ — आणि **दुरुस्ती करा** बटण ठळक केले जाते. `Repair` हे ProxyBridge च्या `--cleanup` फ्लॅगचे ॲप्लिकेशन-स्तरीय समतुल्य आहे (ते `src/mitm/manager.ts` मधील `repairMitm()` कडे कार्य सोपवते).

> वारंवार sudo प्रॉम्प्ट टाळण्यासाठी MITM रूट CA थांबवणे/सुरू करणे यांदरम्यानही स्थापित ठेवला जातो
> (mitmproxy/Charles प्रमाणेच वर्तन), त्यामुळे तो काढणे ही थांबवल्यावर
> आपोआप घडणारी गोष्ट नसून स्पष्ट **CA काढून टाका** क्रिया आहे.

### 3.7 पोर्टेबल कॉन्फिग आयात/निर्यात

AgentBridge **ऑपरेटरद्वारे समायोजित करता येणारी** स्थिती आवृत्तीयुक्त JSON ब्लॉबमध्ये क्रमबद्ध करू शकते, ज्यामुळे सेटअपची इतर मशीनवर प्रतिकृती तयार करता येते. सिरियलायझर `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`) आहे, ज्याचे प्रमाणीकरण `AgentBridgeConfigSchema` द्वारे केले जाते.

निर्यातीमध्ये नेमके तीन भाग समाविष्ट असतात (अंगभूत डीफॉल्ट्स हेतुपुरस्सर निर्यात केले जात **नाहीत**, त्यामुळे आयात केल्याने त्यांची कधीही पुनरावृत्ती होत नाही किंवा त्यांच्याशी संघर्ष होत नाही):

| फील्ड            | स्रोत                                                               | नोंदी                                                                   |
| ---------------- | ------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `bypassPatterns` | वापरकर्त्याने परिभाषित केलेले बायपास पॅटर्न (`agent_bridge_bypass`) | डीफॉल्ट bank/gov/okta पॅटर्न वगळले जातात                                |
| `customHosts`    | Traffic Inspector कस्टम होस्ट (`inspector_custom_hosts`)            | प्रत्येक: `{ host, kind: "llm"\|"app"\|"custom", label? }`              |
| `agentMappings`  | प्रत्येक एजंटसाठी मॉडेल मॅपिंग (`agent_bridge_mappings`)            | मॅपिंग असलेल्या प्रत्येक एजंटसाठी `{ [agentId]: [{ source, target }] }` |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**आयात वर्तन** (`POST /api/tools/agent-bridge/config`): बायपास पॅटर्न आणि प्रत्येक एजंटसाठीची मॅपिंग **पूर्णपणे बदलली जातात**; कस्टम होस्ट **आयडेम्पोटंट पद्धतीने** जोडले जातात (`INSERT OR IGNORE`). प्रत्येक प्रकारातील किती लागू केले गेले हे प्रतिसादात कळवले जाते:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

कॉन्फिगमध्ये काय **नाही**: सर्व्हर चालू असल्याची स्थिती, प्रमाणपत्र पथ, प्रत्येक एजंटची DNS स्थिती, अपस्ट्रीम CA पथ आणि TPROXY सेटिंग्ज — या होस्ट/रनटाइम स्थिती आहेत, पोर्टेबल प्राधान्ये नाहीत.

### संवेदनशील होस्टसाठी बायपास सूची

बायपास सूचीमुळे वित्तीय संस्था, OAuth/SSO प्रदाते आणि इतर संवेदनशील होस्ट **कधीही डिक्रिप्ट केले जात नाहीत**. त्यांची TLS वाहतूक पारदर्शक TCP टनेलद्वारे जाते — OmniRoute ला प्लेनटेक्स्ट कधीही दिसत नाही.

डीफॉल्ट बायपास पॅटर्नमध्ये पुढील गोष्टी समाविष्ट आहेत:

- `*.bank.*`, `*.gov.*` (वित्तीय/सरकारी)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/ओळख)
- `*.apple.com`, `*.icloud.com` (Apple प्रणाली सेवा)

वापरकर्त्याने जोडलेले बायपास पॅटर्न `agent_bridge_bypass` तक्त्यात साठवले जातात आणि त्यांना इतर सर्व गोष्टींपेक्षा प्राधान्य दिले जाते.

### गुपिते मास्क करणे

`src/mitm/maskSecrets.ts` मधील `maskSecrets()` लागू केले जाते:

- `TrafficBuffer.push()` पूर्वी प्रत्येक विनंती बॉडीवर
- लॉगिंग किंवा ब्रॉडकास्टिंगपूर्वी प्रत्येक हेडरवर

पॅटर्न: `sk-`/`ak-`/`pk-` उपसर्ग असलेली टोकन, `Bearer` टोकन आणि ≥40 वर्णांची सामान्य टोकन.

### अपस्ट्रीम CA प्रमाणपत्र

`AGENTBRIDGE_UPSTREAM_CA_CERT` सेट केलेले असताना, स्टार्टअपवेळी फाइल वाचली जाते. पाथ अस्तित्वात असेल, परंतु फाइल वाचता येत नसेल, तर AgentBridge स्पष्ट त्रुटी लॉग करतो आणि सुरू होण्यास नकार देतो (कॉर्पोरेट वातावरणातील दुर्लक्षित TLS अपयश टाळतो).

### ज्ञात मर्यादा

- **पोर्ट 443 साठी विशेषाधिकार आवश्यक आहेत**: Linux वर, AgentBridge ला Node बायनरीवर `setcap 'cap_net_bind_service=+ep'` आवश्यक आहे किंवा तो `authbind` द्वारे चालवावा लागतो. सेटअप विझार्ड OS-विशिष्ट सूचना दाखवतो.
- **IDE रीस्टार्ट आवश्यक आहे**: DNS पुनर्निर्देशनानंतर, नवीन होस्ट रिझोल्यूशन प्रभावी होण्यासाठी IDE रीस्टार्ट करणे आवश्यक आहे.
- **हार्डकोड केलेली OAuth टोकन**: काही एजंट (Kiro, Antigravity) OAuth रिफ्रेश टोकन स्थानिकरीत्या साठवतात. ही AgentBridge साठी पारदर्शक असतात — प्रत्येक विनंतीमध्ये त्याला Bearer टोकन दिसते, जे लॉगिंगपूर्वी मास्क केले जाते.
- **Electron फ्रंटएंडना `NODE_EXTRA_CA_CERTS` आवश्यक आहे**: बंडल केलेल्या Node/Electron रनटाइमवर चालणारा फ्रंटएंड असलेले IDE, OS/NSS ट्रस्ट स्टोअरकडे दुर्लक्ष करतात आणि `NODE_EXTRA_CA_CERTS` सेट केलेल्या शेलमधून लाँच करणे आवश्यक असते (§3.2 पहा). ते नसल्याचे लक्षण: IDE बॅकएंड प्रमाणीकरण करतो (MITM मध्ये `200` दिसतात), परंतु UI लॉगआउटच राहतो.
- **एकाच IDE ची अनेक इन्स्टॉलेशन स्वतंत्र असतात**: सिस्टम इन्स्टॉलेशन (उदा. `/usr/share/antigravity/antigravity`) आणि वापरकर्ता-स्थानिक "Full" इन्स्टॉलेशन (उदा. `~/AntigravityIDE_Full/antigravity-ide`) या स्वतःच्या रनटाइमसह स्वतंत्र प्रक्रिया आहेत — प्रत्येक प्रक्रिया CA इंजेक्ट करून पुन्हा लाँच करणे आवश्यक आहे. पुन्हा लाँच करण्यापूर्वी कोणती प्रक्रिया चालू आहे, हे तिच्या बायनरी पाथवरून ओळखा.
- **ओळख रूट केलेल्या मॉडेलद्वारे नव्हे, तर एजंटच्या सिस्टम प्रॉम्प्टद्वारे सेट केली जाते**: तुम्ही एजंटचे मॉडेल वेगळ्या प्रदात्याकडे रीमॅप केल्यावरही, प्रतिसाद एजंटची मूळ ओळख सांगतो (उदा. Antigravity उत्तर देते, "मी Gemini द्वारे समर्थित आहे"), कारण IDE ती माहिती सिस्टम प्रॉम्प्टमध्ये इंजेक्ट करतो. वास्तविक बॅकएंडची पुष्टी मॉडेलला ते कोण आहे असे विचारून नव्हे, तर `call_logs` / `proxy_logs` (`provider`, `model`, `target_format`) मध्ये करा.

## §6 समस्यांचे निवारण

### पोर्ट 443 संघर्ष

जर दुसरी प्रक्रिया आधीच पोर्ट 443 वर ऐकत असेल (वेब सर्व्हर, VPN इ.):

```bash
lsof -i :443          # प्रक्रिया शोधा
sudo fuser -k 443/tcp  # सक्तीने बंद करा (काळजीपूर्वक वापरा)
```

पर्याय म्हणून, AgentBridge सेटिंग्जमध्ये विशेषाधिकारांची आवश्यकता नसलेला पोर्ट कॉन्फिगर करा आणि `iptables` / `pf` पुनर्निर्देशन नियम सेट करा.

### प्रमाणपत्र विश्वसनीय नाही

AgentBridge सुरू केल्यानंतर IDE मध्ये TLS त्रुटी दिसत असल्यास:

1. प्रमाणपत्र स्थापित झाले आहे याची पडताळणी करा: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) किंवा `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. काही ॲप्स त्यांचे स्वतःचे विश्वसनीयता भांडार राखतात (Firefox, Linux वरील Chrome). "Trust Cert" पुन्हा चालवा आणि NSS/Firefox-विशिष्ट प्रमाणपत्र भांडार तपासा.
3. प्रमाणपत्र विश्वसनीय केल्यानंतर IDE रीस्टार्ट करा — सध्या सुरू असलेली TLS सत्रे जुनी विश्वसनीयता स्थिती वापरतात.

### विश्वसनीय CA असूनही IDE मधून लॉग आउट / "connection error"

लक्षण: DNS पुनर्निर्देशित केल्यानंतर आणि CA विश्वसनीय केल्यानंतर, Electron-आधारित IDE (उदा. Antigravity)
**लॉग आउट केलेल्या** स्थितीत उघडते किंवा प्रमाणीकरण/कनेक्शन त्रुटी दाखवते, तरीही MITM लॉगमध्ये
बूटस्ट्रॅप कॉल (`loadCodeAssist`, `fetchAvailableModels`, …) `200` परत करताना दिसतात.

कारण: IDE चा **अंतर्भूत Node/Electron रनटाइम OS विश्वसनीयता भांडाराकडे दुर्लक्ष करतो**. नेटिव्ह
बॅकएंड (Go भाषा सर्व्हर) OS CA वर विश्वास ठेवतो आणि प्रमाणीकरण करतो, परंतु Electron फ्रंटएंड
तसे करत नाही — त्यामुळे UI ला ते ऑफलाइन असल्याचे वाटते.

उपाय (दोन्ही पायऱ्या): `NODE_EXTRA_CA_CERTS=<ca.crt>` एक्सपोर्ट करा **आणि त्याच
शेलमधून IDE पुन्हा सुरू करा**, डेस्कटॉप आयकॉनमधून नाही. प्रथम IDE पूर्णपणे बंद करा — Electron च्या सिंगलटन लॉकमुळे
दुसऱ्यांदा सुरू केल्यास फक्त विद्यमान प्रक्रियेवर लक्ष केंद्रित होते आणि नवीन वातावरण दुर्लक्षित केले जाते. §3.2 पहा.
हे एका खुल्या अपस्ट्रीम अहवालासारखेच आहे, ज्यामध्ये स्वतंत्र एजंट MITM मधून कार्य करतो, परंतु IDE
प्रकार समान सेटअपमध्ये अयशस्वी होतो.

### DNS प्रसारित झालेले नाही

`/etc/hosts` अद्ययावत झाले आहे का ते तपासा:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

DNS कॅशे रिकामा करा:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### IDE आढळले नाही

स्वयं-शोध सामान्य स्थापना पथ वापरतो. शोध अयशस्वी झाला, परंतु IDE स्थापित असल्यास:

- IDE बायनरी मानक नसलेल्या स्थानावर आहे का ते तपासा
- Setup Wizard तरीही कार्य करतो — शोध अयशस्वी झाल्याचा अर्थ फक्त बॅजमध्ये स्थापना पथ दिसणार नाही

### हँडलर त्रुटी (अपस्ट्रीम फेच अयशस्वी)

AgentBridge विनंत्या इंटरसेप्ट करत असेल, परंतु सर्व विनंत्या अयशस्वी होत असल्यास:

1. `/dashboard/providers` येथे किमान एक प्रदाता कनेक्ट केलेला आहे याची पडताळणी करा
2. OmniRoute सर्व्हर लॉग तपासा: `.env` मध्ये `APP_LOG_LEVEL=debug`
3. `OMNIROUTE_BASE_URL` योग्य राउटर एंडपॉइंटकडे निर्देश करत असल्याची पडताळणी करा (डीफॉल्ट: `http://127.0.0.1:20128`)

## §8 भावी आराखडा

### Trae चा तपास

Trae हा तुलनेने नवीन AI कोडिंग सहाय्यक आहे. हँडलर अंमलात आणण्यापूर्वी:

1. VS Code / JetBrains मार्केटप्लेसमध्ये किंवा स्वतंत्र ॲप म्हणून बायनरी/एक्स्टेंशन ओळखा
2. API होस्ट आणि एंडपॉइंटची संरचना शोधण्यासाठी mitmproxy वापरून ट्रॅफिक कॅप्चर करा
3. प्रमाणीकरण यंत्रणा निश्चित करा
4. TOS आणि API शोधसुलभतेच्या आधारे पुढे जावे की नाही याचे मूल्यांकन करा

तपास पूर्ण होईपर्यंत, डॅशबोर्डमधील Trae कार्डवर "तपास सुरू आहे" असा बॅज आणि "व्यवहार्यता नोंदवा" ही लिंक दिसते. `src/mitm/handlers/trae.ts` येथील हँडलर स्टब संरचित `अद्याप अंमलात आणलेले नाही` त्रुटी निर्माण करतो.

### अनुशेषातील एजंट (MITM आवश्यक — सानुकूल बेस URL समर्थन नाही)

खालील साधने त्यांच्या सध्याच्या आवृत्त्यांमध्ये सानुकूल बेस URL ना समर्थन देत नाहीत, त्यामुळे MITM हाच इंटरसेप्शनचा एकमेव मार्ग ठरतो. व्यवहार्यता मूल्यांकन प्रलंबित आहे:

- **Windsurf** (Codeium/Cognition)
- **Amp** (Sourcegraph)
- **Amazon Q / Kiro CLI** (AWS Bedrock — Kiro IDE पेक्षा वेगळे)
- **Cowork** (Anthropic डेस्कटॉप)

टीप: GitHub Copilot CLI ≥v1.0.19 हे `COPILOT_PROVIDER_BASE_URL` ला समर्थन देते — त्या साधनासाठी MITM ऐवजी थेट कॉन्फिगरेशन वापरा.
