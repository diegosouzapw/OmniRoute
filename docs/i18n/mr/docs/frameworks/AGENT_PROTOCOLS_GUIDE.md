OmniRoute एजंटशी संबंधित तीन वेगवेगळे पृष्ठभाग उपलब्ध करून देते. प्रथमदर्शनी ते सारखे दिसतात, परंतु ते वेगवेगळ्या समस्या सोडवतात. योग्य पर्याय निवडण्यासाठी हे पृष्ठ वापरा.

## थोडक्यात

| पृष्ठभाग                     | यासाठी सर्वोत्तम                                                                                                                      | वाहतूक माध्यम                 | मानक                       |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- | -------------------------- |
| **A2A — एजंट-टू-एजंट**       | A2A प्रोटोकॉल वापरणाऱ्या समकक्ष एजंटसोबत आंतर-एजंट सहकार्य                                                                            | HTTP वर JSON-RPC 2.0          | A2A v0.3 (खुले विनिर्देशन) |
| **ACP — CLI एजंट रजिस्ट्री** | वापरकर्त्याच्या मशीनवर स्थापित CLI कोडिंग एजंट शोधणे / नोंदणी करणे / सुरू करणे (Cursor, Cline, Codex CLI, Claude Code, Aider इत्यादी) | HTTP REST                     | OmniRoute-विशिष्ट          |
| **क्लाउड एजंट**              | बाह्य क्लाउड सेवांना दीर्घकाळ चालणारी कोडिंग कार्ये सादर करणे (Codex Cloud, Devin, Jules, Cursor Cloud)                               | HTTP REST + DB-समर्थित कार्ये | OmniRoute-विशिष्ट          |

हे तिन्ही स्वतंत्र आहेत — त्यांपैकी कोणताही उपसंच निवडा.

## निर्णय-वृक्ष

```
या मशीनच्या बाहेर काम करण्यासाठी तुम्हाला क्लाउड सेवेची आवश्यकता आहे का (Codex Cloud / Cursor Cloud / Devin / Jules)?
├─ होय → क्लाउड एजंट (POST /api/v1/agents/tasks)
└─ नाही → पुढे जा

    ├─ होय → A2A (POST /a2a)
    └─ नाही → पुढे जा
        │
        स्थानिकरीत्या स्थापित CLI कोडिंग एजंटची सूची पाहणे / संरचना करणे आवश्यक आहे का?
        ├─ होय → ACP (GET /api/acp/agents)
        └─ नाही → साधे /v1/chat/completions वापरा
```

## 1. A2A — एजंट-टू-एजंट

**विनिर्देशन:** [A2A v0.3](https://a2a-protocol.org)
**OmniRoute एंडपॉइंट:** `POST /a2a` (JSON-RPC 2.0)
**एजंट कार्ड:** `GET /.well-known/agent.json`

### कधी वापरावे

- OmniRoute हा समकक्षांपैकी एक असलेली मल्टी-एजंट प्रणाली तयार करताना
- Google ADK किंवा सर्वसाधारण एजंट मेश यांसारख्या फ्रेमवर्कमधील एजंटना OmniRoute ची राउटिंग बुद्धिमत्ता (स्मार्ट राउटिंग, कोटा व्यवस्थापन इत्यादी) उपलब्ध करून देताना
- मानक शोध + आवाहन पृष्ठभागामागे OmniRoute गुंडाळताना

### पद्धती

- `message/send` — संदेश सादर करा आणि समकालिक प्रतिसाद मिळवा
- `message/stream` — संदेश सादर करा आणि SSE-प्रवाहित प्रगती इव्हेंट मिळवा
- `tasks/get` — ID द्वारे कार्य वाचा
- `tasks/cancel` — चालू असलेले कार्य रद्द करा

### अंगभूत कौशल्ये (6)

- `smart-routing` — प्रॉम्प्टला सर्वोत्तम कॉम्बोद्वारे रूट करा
- `quota-management` — प्रत्येक प्रदात्यानुसार कोट्याची स्थिती नोंदवा
- `provider-discovery` — स्थापित प्रदाते आणि त्यांच्या क्षमता सूचीबद्ध करा
- `cost-analysis` — विनंतीचा/संभाषणाचा खर्च अंदाजित करा
- `health-report` — प्रत्येक प्रदात्यानुसार ब्रेकर/कूलडाउन/लॉकआउट स्थिती एकत्रित करा
- `list-capabilities` — एजंटची उपलब्ध कौशल्ये आणि मेटाडेटा सूचीबद्ध करा

### सविस्तर माहिती

वाहतूक तपशील, एजंट कार्डची रचना, कार्य TTL संरचना आणि नवीन कौशल्ये जोडण्यासाठीचा साचा यांसाठी [A2A-SERVER.md](./A2A-SERVER.md) पहा.

## 2. ACP — CLI एजंट्स रजिस्ट्री

**OmniRoute एंडपॉइंट:** `GET /api/acp/agents`
**स्रोत:** `src/lib/acp/{index,manager,registry}.ts`

### हे काय आहे

ACP ही OmniRoute ची **स्थानिक CLI एजंट सूची** आहे. ती होस्टवर कोणते कोडिंग CLI स्थापित आहेत (Cursor, Cline, Claude Code, Codex CLI, Continue इ.) हे शोधते, त्यांच्या आवृत्त्या निश्चित करते आणि त्या डॅशबोर्डवर दाखवते, ज्यामुळे वापरकर्ता प्रत्येक CLI ला OmniRoute कडे निर्देशित करू शकतो.

हा बाह्य प्रोटोकॉल नाही — ही एक अंतर्गत रजिस्ट्री आहे जी "CLI Tools" UI आणि CLI फिंगरप्रिंट ट्रॅकिंगला समर्थित करते ([CLI-TOOLS.md](../reference/CLI-TOOLS.md) पहा).

### हे काय करते

- स्थापित CLI बायनरींसाठी होस्टची तपासणी करते (OS नुसार `which` / `where` वापरते)
- प्रत्येक CLI ची आवृत्ती वाचते (`<bin> --version` कॉल करते)
- वैकल्पिकरित्या वापरकर्त्याने परिभाषित केलेले कस्टम एजंट्स स्वीकारते (बायनरी पथ + आवृत्ती तपासणी + स्पॉन आर्ग्युमेंट्स)
- कस्टम एजंट्स सेटिंग्जमध्ये कायमस्वरूपी जतन करते
- एकत्रित सूची डॅशबोर्डला परत करते

### REST API

| एंडपॉइंट          | पद्धत | वर्णन                                                                  | प्रमाणीकरण |
| ----------------- | ----- | ---------------------------------------------------------------------- | ---------- |
| `/api/acp/agents` | GET   | शोधलेले + कस्टम एजंट्स सूचीबद्ध करते (स्थापित/एकूण संख्या)             | API की     |
| `/api/acp/agents` | POST  | कस्टम एजंट जोडते/अद्ययावत करते/काढते (बॉडीमध्ये अॅक्शन डिस्क्रिमिनेटर) | API की     |

POST साठी बॉडीची रचना (`src/app/api/acp/agents/route.ts` मधील `customAgentBodySchema`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### वापराची प्रकरणे

- डॅशबोर्डचे "CLI Tools" पृष्ठ काय स्थापित आहे याची सूची दाखवते आणि प्रत्येकाला OmniRoute कडे निर्देशित करण्यात मदत करते
- कस्टम एजंट्समुळे प्रगत वापरकर्ते OmniRoute ला डीफॉल्टनुसार माहीत नसलेले अंतर्गत/मालकी हक्काचे CLI नोंदणीकृत करू शकतात
- शोधाचा परिणाम `cli-tools` फिंगरप्रिंट मॅट्रिक्सला माहिती पुरवतो

### ACP कधी वापरू नये

- ACP कार्ये _चालवत_ नाही. ते फक्त CLI शोधते + कॉन्फिगर करते. प्रत्यक्षात CLI वापरण्यासाठी, OmniRoute ने पुरवलेल्या env vars सह तुम्ही ते स्वतः सुरू करता (`OPENAI_BASE_URL`, `OPENAI_API_KEY` इ.).

## 3. क्लाउड एजंट्स

**OmniRoute एंडपॉइंट्स:** `/api/v1/agents/tasks/*` (जीवनचक्र) + `/api/cloud/*` (अंतर्गत जोडणी)
**स्रोत:** `src/lib/cloudAgent/`

### हे काय आहे

तृतीय-पक्ष क्लाउड कोडिंग एजंट्ससाठी एकसमान इंटरफेस. तुम्ही प्रॉम्प्ट + रेपो URL सबमिट करता, OmniRoute ते योग्य क्लाउड एजंटकडे पाठवते, स्थितीची वेळोवेळी तपासणी करते आणि परिणाम परत करते.

### समर्थित एजंट्स (4, सर्व `src/lib/cloudAgent/agents/` मध्ये पुष्टी केलेले)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### जीवनचक्र

```
POST /api/v1/agents/tasks
  → प्रत्येक एजंट क्लाससाठी BaseAgent.createTask()
  → बाह्य सेवा काम सुरू करते
  → DB मध्ये कार्याची रकानानिर्मिती होते (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → प्रदात्याकडून आवश्यकतेनुसार स्थिती समक्रमित केली जाते
  → सद्यस्थिती + योजना + क्रियाकलाप लॉग परत करते
  ↓
POST /api/v1/agents/tasks/[id]   (कृती: "approve" | "message" | "cancel")
  → प्रदात्याकडे अग्रेषित करते (किंवा स्थानिकरीत्या रद्द म्हणून चिन्हांकित करते)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → स्थानिक रद्दीकरण
```

### प्रमाणीकरण

⚠️ **सर्व `/api/v1/agents/tasks/*` एंडपॉइंट्सना व्यवस्थापन प्रमाणीकरण आवश्यक आहे** (commit `588a0333`). v3.8.0 पासून केवळ Bearer वापरणाऱ्या कॉलर्सना 401 प्रतिसाद मिळतो.

### सखोल माहिती

`CloudAgentBase` करार, प्रत्येक एजंटचे तपशील, स्कीमा तपशील आणि क्रेडेन्शियल जोडणी एंडपॉइंट्ससाठी [CLOUD_AGENT.md](./CLOUD_AGENT.md) पहा.

## तुलना: A2A विरुद्ध Cloud Agents

दोन्हींमध्ये "दीर्घकाळ चालणारी कार्ये" असतात, परंतु वेगवेगळ्या स्तरांवर:

| पैलू             | A2A                                                                                 | Cloud Agents                                 |
| ---------------- | ----------------------------------------------------------------------------------- | -------------------------------------------- |
| मानक             | खुले A2A v0.3                                                                       | OmniRoute-विशिष्ट                            |
| संगणन कुठे चालते | OmniRoute अंतर्गत (कॉन्फिगर केलेले कॉम्बो वापरते)                                   | बाह्य (Codex / Devin / Jules सर्व्हर)        |
| कार्याचा कालावधी | डीफॉल्ट TTL 5 मिनिटे (`TaskManager` मध्ये कॉन्फिगर करता येतो)                       | काही मिनिटांपासून काही तासांपर्यंत           |
| रेपो-जागरूक      | नाही (केवळ प्रॉम्प्ट पाठवते)                                                        | होय (रेपो URL + ब्रँच)                       |
| वापराचे प्रकरण   | क्रॉस-एजंट सहयोग, सेवा म्हणून स्मार्ट रूटिंग                                        | "रेपो Y मध्ये वैशिष्ट्य X अंमलात आणा" सोपवणे |

## एकत्रीकरणाची उदाहरणे

### OmniRoute च्या A2A क्षमता शोधा

```bash
curl http://localhost:20128/.well-known/agent.json
```

सर्व 6 कौशल्ये, ट्रान्सपोर्ट्स आणि आवृत्ती असलेले Agent Card परत करते.

### OmniRoute ला A2A एजंट म्हणून कॉल करा

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### ACP द्वारे इंस्टॉल केलेल्या CLI एजंटची सूची मिळवा

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### सानुकूल CLI एजंट जोडा

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### Cloud Agent कार्य सबमिट करा

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### क्लाउड कार्याची स्थिती नियमितपणे तपासा

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## काय कधी वापरावे

- **चॅटबॉट / कोपायलट फ्रंटएंड** → `/v1/chat/completions` (OpenAI-सुसंगत — एजंट प्रोटोकॉल नाही)
- **मल्टी-एजंट सहयोग** → A2A
- **डॅशबोर्डमध्ये स्थानिक CLI ची सूची दाखवणे** → ACP
- **दीर्घकाळ चालणारी कोडिंग कार्ये क्लाउड सेवांना सोपवणे** → Cloud Agents
