Det här dokumentet redovisar implementeringsbeslutet för
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854). De publika produkterna
representeras som fyra leverantörsfamiljer. Region är anslutningsdata, inte en separat produkt.

## Beslut

| Leverantörsfamilj                                  | OmniRoute-ID            | Global region | Kina-region |
| -------------------------------------------------- | ----------------------- | ------------- | ----------- |
| Alibaba Cloud Model Studio (betala per användning) | `alibaba`               | Singapore     | Peking      |
| Alibaba Cloud Token Plan                           | `bailian-coding-plan`   | Singapore     | Peking      |
| Qwen Cloud (betala per användning)                 | `qwen-cloud`            | Globalt       | Peking      |
| Qwen Cloud Token Plan                              | `qwen-cloud-token-plan` | Singapore     | Peking      |

Det befintliga ID:t `alibaba-cn` förblir ett kompatibilitetsalias vid körning för sparade anslutningar, modellrutter, kombinationer och historisk användning. Dess kort på kontrollpanelen slås ihop med `alibaba`; ingen omskrivning av databasen krävs.

Qwen Cloud med betalning per användning och Alibaba Cloud Model Studio delar för närvarande de DashScope-kompatibla körningsvärdarna, men de förblir separata leverantörsidentiteter eftersom användarna hämtar nycklar och hanterar konton via olika produktytor. Produkterna Alibaba och Qwen Cloud Token Plan använder olika endpoint-familjer, så alla fyra produkterna förblir separata leverantörs-ID:n.

## Endpoint-matris

| Leverantörsfamilj       | `global-sg`                                                              | `china-beijing`                                                      | Trådformat |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ---------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI     |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic  |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI     |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI     |

API-nyckeln och endpointen måste tillhöra samma produkt och region. När en region väljs ändras den förinställda endpoint som används vid validering och vanliga anrop.

## Anslutningskontrakt

Nya anslutningar lagrar den stabila regionnyckeln i `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

Tillåtna värden är `global-sg` och `china-beijing`. Endpointen härleds centralt från leverantörs-ID:t och regionen. Ett icke-förinställt `providerSpecificData.baseUrl` förblir en uttrycklig operatörsåsidosättning och har företräde, medan gamla sparade förinställda URL:er normaliseras tillbaka till den regionala matrisen.

Detta håller anslutningsschemat utbyggbart: ytterligare en region kan läggas till i resolvern utan att skapa ett nytt leverantörskort eller ändra sparade leverantörs-ID:n.

## Kompatibilitet och utrullning

1. Lägg till matchning av regionala slutpunkter och behåll de nuvarande globala standardvärdena.
2. Använd direkt regional DashScope-identifiering via `/models` för `alibaba`, dess kompatibilitets-ID
   `alibaba-cn` och `qwen-cloud`. Deras svar passerar först ett filter för textgenerering eftersom den
   generiska slutpunkten även returnerar modeller för bilder, video, ljud, inbäddningar och andra
   modeller som inte är avsedda för chatt. `qwen-cloud` tillämpar därefter den underhållna tillåtelselista
   som deklareras i dess leverantörsregister. Alibaba Model Studio och Qwen Cloud behåller separata
   kurerade kataloger även om de för närvarande delar körningsvärdar.
3. Registrera `qwen-cloud-token-plan` med den aktuella tillåtelselistan för textmodeller i Token Plan.
4. Lägg till en typad regionväljare i dialogrutorna för att lägga till och redigera anslutningar.
5. Dölj det duplicerade `alibaba-cn`-kortet och inkludera dess befintliga anslutningar på
   leverantörssidan för `alibaba`.
6. Behåll möjligheten att åsidosätta anpassade slutpunkter för avancerade och arbetsytespecifika
   driftsättningar.

Mediamodeller för Token Plan förblir utanför chattkatalogen eftersom de använder dedikerade
slutpunkter. `wan2.7-image` och `wan2.7-image-pro` registreras i `open-sse/config/imageRegistry.ts`;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` och `happyhorse-1.1-r2v` registreras i
`open-sse/config/videoRegistry.ts`. Båda registren återanvänder anslutningsidentiteten
`qwen-cloud-token-plan` och dess regionspecifika autentiseringsuppgifter.

Vanliga Qwen Cloud har separata bild- och videokataloger med betalning efter användning under
identiteten `qwen-cloud`. Dess bildmodeller är `wan2.7-image-pro`, `wan2.7-image`,
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` och
`z-image-turbo`. Dess videomodeller är `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`,
`happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`,
`wan2.7-r2v-2026-06-12` och `wan2.7-videoedit`. Dessa modeller återanvänder endast den vanliga
`qwen-cloud`-anslutningen och den regionala DashScope-medieslutpunkten. Registren för Token Plan
och betalning efter användning ärver eller slår inte samman varandras modellistor.

Identiteten `bailian-coding-plan` har också egna tillåtelselistor för media:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` och `qwen-image-2.0-pro` för
bildgenerering samt
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` och `happyhorse-1.1-r2v` för
videogenerering. Den använder endast anslutningen för Bailian Coding Plan och den regionala
slutpunkten för Coding Plan. Dess bild- och videoregister ärver inte från och slås inte samman med
någon av Qwen Cloud-leverantörerna.

Den vanliga identiteten `alibaba` har separata tillåtelselistor för bilder och video. Dess bildmodeller
är `qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` och `wan2.6-t2i`. Dess tillagda videomodeller är `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` och `wan2.7-videoedit`. Dessa modeller använder endast anslutningen
för Alibaba Model Studio och dess valda regionala medieslutpunkt; de läggs inte till i något register
för Coding Plan eller Qwen Cloud.

Chattkatalogen för Qwen Cloud Token Plan följer Individual-planens texttillåtelselista med exakt
strängmatchning: `qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`,
`glm-5.2` och `deepseek-v4-pro`. Poster för Wan och HappyHorse tillhör de separata API:erna för
bild- och videogenerering.

Alibaba Token Plan exponerar samma sex aktuella modell-ID:n för textgenerering via sin
Anthropic-kompatibla slutpunkt. Dess Singapore-alternativ lagrar den befintliga regionnyckeln
`global-sg`; endast den användarorienterade etiketten skiljer sig från leverantörsfamiljer som kallar
regionen Global.

Den vanliga chattkatalogen för Qwen Cloud är avsiktligt snävare än det fullständiga direktsvaret för
text. Dess underhållna tillåtelselista finns i `open-sse/config/providers/registry/qwen-cloud/index.ts`;
direkt identifiering returnerar endast ID:n som finns både i det uppströms svaret och i registerlistan.

Alibaba Model Studio följer samma regel för direkt skärning med sin oberoende underhållna
tillåtelselista i `open-sse/config/providers/registry/alibaba/index.ts`. Kompatibilitetsleverantören
`alibaba-cn` återanvänder den katalogen samtidigt som identifieringen matchas mot slutpunkten i
Peking.
