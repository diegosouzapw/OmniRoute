> **Sanningskälla:** `src/lib/obsidian/api.ts` (REST- och synkroniseringsklient),
> `src/lib/db/obsidian.ts` (persistens för token/bas-URL/WebDAV),
> `src/lib/obsidianSync.ts` (WebDAV-synkronisering av valv), `open-sse/mcp-server/tools/obsidianTools.ts`
> (22 MCP-verktyg), `src/app/api/settings/obsidian/route.ts` +
> `src/app/api/settings/obsidian/webdav/route.ts` (inställnings-API:er). Verktygsregistrering
> och scope-koppling finns i `open-sse/mcp-server/server.ts`.

## Vad det är

OmniRoute ansluter till ett **Obsidian**-valv som en **kontextkälla** – en lokal
kunskapsbas i Markdown som agenter läser och skriver via den inbyggda MCP-servern.
Integrationen kommunicerar med community-pluginet **Obsidian Local REST API** som körs
i skrivbordsappen, så att agenter kan söka bland anteckningar, läsa/skriva/patcha filer,
lista valvet, arbeta med dagliga/veckovisa periodiska anteckningar, hantera taggar, köra
Obsidian-kommandon och (valfritt) samordna en dubbelriktad valvsynkronisering mellan
skrivbord och mobil.

Klienten (`src/lib/obsidian/api.ts`) kapslar in Local REST API med:

- **Återförsök med stegvis ökande väntetid** för tillfälliga `5xx`, **30 sekunders timeout** via `AbortController`.
- **Typad felklassificering** – `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- En **lättförståelig ledtråd om att Obsidian inte kan nås** som uppmärksammar det vanliga portfelet
  (HTTP på `27123`, **inte** MCP-slutpunkten på `27124`) och Tailscale-formatet.
- Valvrelativ **sökvägskodning** så att anteckningssökvägar med blanksteg/snedstreck hanteras säkert.

## Konfiguration

Det finns **ingen miljövariabel** för Obsidian-token eller bas-URL – båda lagras
i SQLite-tabellen `key_value` (namnrymd `obsidian`) via
`src/lib/db/obsidian.ts`. Token är **krypterad vid lagring** (AES-256-GCM, med
bakåtkompatibel reservlösning för klartext). Konfigurera från fliken **Kontextkällor** i
slutpunktsinstrumentpanelen (`ObsidianSourceCard`) eller via REST-API:t för inställningar.

> [!IMPORTANT]
> Pluginet **Obsidian Local REST API** måste vara installerat och köras. Dess REST-
> gränssnitt lyssnar på **HTTP `127.0.0.1:27123`** (standardbas-URL:en). Port `27124`
> är en _separat_ MCP-/HTTPS-slutpunkt och avvisas uttryckligen av inställningsrutten.
> Om du ansluter från en annan enhet använder du `http://<tailscale-ip>:27123`.

### Konfigurationsnycklar (SQLite `key_value`, namnrymd `obsidian`)

| Nyckel            | Syfte                                                  | Krypterad |
| ----------------- | ------------------------------------------------------ | --------- |
| `api_key`         | Bearer-token för Local REST API                        | ja        |
| `base_url`        | REST-bas-URL (standard `http://127.0.0.1:27123`)       | nej       |
| `vault_path`      | Absolut sökväg till valvkatalogen (för synkronisering) | nej       |
| `webdav_username` | Genererat WebDAV-användarnamn (valvsynkronisering)     | nej       |
| `webdav_password` | Genererat WebDAV-lösenord (valvsynkronisering)         | ja        |
| `webdav_enabled`  | Om WebDAV-synkronisering av valvet är aktiverad        | nej       |

### Konfigurera via REST

```bash
# Spara och validera Local REST API-token (POST validerar via en statuskontroll)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Kontrollera anslutningsstatus (returnerar connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# Koppla från (rensar lagrad token)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Alla metoder kräver autentisering för instrumentpanelen. `POST` avvisar alla URL:er på port `27124`
och validerar token genom att anropa status-slutpunkten i Local REST API innan den sparas.

### WebDAV-synkronisering av valv

`src/app/api/settings/obsidian/webdav/route.ts` hanterar en valfri WebDAV-baserad
valvsynkronisering (som drivs av `src/lib/obsidianSync.ts`). När den aktiveras pekar OmniRoute på en
lokal valvkatalog och genererar ett slumpmässigt par med WebDAV-användarnamn och lösenord:

```bash
# Aktivera WebDAV-synkronisering för en valvkatalog (genererar användarnamn/lösenord)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# Hämta status för WebDAV-synkronisering (autentiseringsuppgifter returneras endast när den är aktiverad)
curl http://localhost:20128/api/settings/obsidian/webdav

# Inaktivera WebDAV-synkronisering (rensar autentiseringsuppgifter + hanterad .stignore)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Kontextkälla per API-nyckel (valfritt)

Obsidian-konfigurationen kan begränsas **per API-nyckel** via tabellen `api_key_context_sources`
(`src/lib/db/apiKeyContextSources.ts`). När ett MCP-anrop innehåller ett autentiserat API-
nyckel-id föredrar `getObsidianConfigForApiKey()` nyckelns egen token/bas-URL/valvsökväg
(`source: "api_key"`) och faller annars tillbaka på den globala konfigurationen (`source: "global"`).

## MCP-verktyg (22)

Definieras i `open-sse/mcp-server/tools/obsidianTools.ts`. Token/bas-URL löses
per anrop (först per API-nyckel, därefter globalt). Verktyg som anropar OmniRoutes **synkroniseringsserver**
(de fyra `obsidian_sync_*`-verktygen) kräver dessutom den autentiseringstoken för synkronisering som konfigurerats
i OmniRoute-inställningarna.

### Läsverktyg (`read:obsidian`)

| Verktyg                      | Beskrivning                                                                                          |
| ---------------------------- | ---------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Kontrollera om Local REST API är nåbart och autentiserat.                                            |
| `obsidian_search_simple`     | Fulltextsökning i anteckningsinnehåll; returnerar utdrag med filsökvägar.                            |
| `obsidian_search_structured` | Sök med ett JSON Logic-uttryck (and/or/regex/path-filter).                                           |
| `obsidian_read_note`         | Läs en anteckning via en valvrelativ sökväg; valfritt en specifik rubrik/block/frontmatter.          |
| `obsidian_list_vault`        | Lista filer och kataloger i valvet (träd med poster).                                                |
| `obsidian_get_document_map`  | Hämta anteckningens rubrikstruktur som en mappning av rubriker → radnummer.                          |
| `obsidian_get_note_metadata` | Hämta frontmatter, taggar, länkar samt tecken-/ordantal utan hela innehållet.                        |
| `obsidian_get_active_file`   | Hämta sökväg + innehåll för den fil som för närvarande är aktiv i Obsidian.                          |
| `obsidian_get_periodic_note` | Hämta den dagliga/veckovisa/månatliga periodiska anteckningen för ett datum (idag om det utelämnas). |
| `obsidian_get_tags`          | Lista alla valvtaggar med deras frekvenser.                                                          |
| `obsidian_list_commands`     | Lista tillgängliga Obsidian-kommando-ID:n (använd med `obsidian_execute_command`).                   |
| `obsidian_sync_status`       | Status för OmniRoutes synkroniseringsserver: körs, valvnamn, port, drifttid, senaste synkronisering. |
| `obsidian_sync_conflicts`    | Lista olösta synkroniseringskonflikter (sökväg, konfliktsökväg, tidpunkt då de upptäcktes).          |

### Skrivverktyg (`write:obsidian`)

| Verktyg                          | Beskrivning                                                                                      |
| -------------------------------- | ------------------------------------------------------------------------------------------------ |
| `obsidian_write_note`            | Skapa eller skriv över en anteckning med angivet Markdown-innehåll.                              |
| `obsidian_append_note`           | Lägg till innehåll i en anteckning; valfritt under en specifik rubrik/ett specifikt block.       |
| `obsidian_patch_note`            | Lägg selektivt till före/efter eller ersätt vid en rubrik, ett block eller ett frontmatter-fält. |
| `obsidian_delete_note`           | Ta bort en anteckning permanent från valvet.                                                     |
| `obsidian_move_note`             | Flytta eller byt namn på en anteckning i valvet.                                                 |
| `obsidian_execute_command`       | Kör ett Obsidian-kommando via dess kommando-ID.                                                  |
| `obsidian_open_file`             | Öppna en fil i Obsidian (skapar den om den inte finns).                                          |
| `obsidian_sync_trigger`          | Utlös omedelbar dubbelriktad synkronisering av valvet mellan dator↔mobil.                        |
| `obsidian_sync_resolve_conflict` | Lös en synkroniseringskonflikt: behåll `local` (mobil), `remote` (dator) eller `keep-both`.      |

> [!NOTE]
> Mål för `obsidian_patch_note` accepterar `targetType` av typen `heading | block | frontmatter`
> och `operation` av typen `append | prepend | replace`, med en valfri
> `createTargetIfMissing`. De fyra `obsidian_sync_*`-verktygen kommunicerar med den lokala synkroniseringsservern
> (`http://127.0.0.1:27781` som standard) och kräver synkroniseringstoken.

### Behörighetsomfång

Läsverktyg kräver `read:obsidian`; skrivverktyg kräver `write:obsidian`. Tillämpningen
är identisk med Notion — hanteras av `withScopeEnforcement()` i
`open-sse/mcp-server/server.ts`, styrs av `OMNIROUTE_MCP_ENFORCE_SCOPES=true`, med
tillåtna behörighetsomfång hämtade från `OMNIROUTE_MCP_SCOPES` eller API-nyckelns kontext för behörighetsomfång. Se
[MCP-SERVER.md](./MCP-SERVER.md).

## Slutpunkter

| Metod    | Sökväg                          | Syfte                                                                     |
| -------- | ------------------------------- | ------------------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | Returnerar `{ connected, hasToken, baseUrl, vaultPath }`.                 |
| `POST`   | `/api/settings/obsidian`        | Sparar och validerar token (avvisar port `27124`).                        |
| `DELETE` | `/api/settings/obsidian`        | Kopplar från (rensar lagrad token).                                       |
| `GET`    | `/api/settings/obsidian/webdav` | WebDAV-synkroniseringsstatus och autentiseringsuppgifter (när aktiverat). |
| `POST`   | `/api/settings/obsidian/webdav` | Aktiverar WebDAV-synkronisering för en valvkatalog.                       |
| `DELETE` | `/api/settings/obsidian/webdav` | Inaktiverar WebDAV-synkronisering.                                        |

> Dessa är inställningsrutter för kontrollpanelen. Själva valvet nås via Obsidians
> lokala REST API (den konfigurerade `base_url`) och via MCP-verktygen ovan — det finns
> ingen offentlig Obsidian-proxyslutpunkt under `/v1`.

## Användningsfall

- **Svar baserade på valvet** — `obsidian_search_simple` / `obsidian_search_structured`
  följt av `obsidian_read_note`, så att en agent svarar utifrån dina faktiska anteckningar.
- **Skapa anteckningar/journalföra** — `obsidian_write_note`, `obsidian_append_note` eller
  det precisa `obsidian_patch_note` för att logga agentutdata, sammanfattningar eller dagliga anteckningar
  (`obsidian_get_periodic_note`) i valvet.
- **Navigera i valvet** — `obsidian_list_vault`, `obsidian_get_document_map` och
  `obsidian_get_tags` för att utforska strukturen innan läsning/skrivning.
- **Obsidian-automatisering** — `obsidian_list_commands` + `obsidian_execute_command` för att
  styra insticksprogram/kommandon från en agent; `obsidian_open_file` för att visa en anteckning i användargränssnittet.
- **Mobilsynkronisering** — aktivera WebDAV-synkronisering och använd sedan `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  för att samordna dator↔mobil och lösa konflikter.
