## Vad det är

Local Corpus låter en operatör göra en uttryckligen godkänd katalog med textfiler
tillgänglig för OmniRoutes MCP-server. Filerna ligger kvar i sin ursprungliga katalog:
OmniRoute lagrar endast den kanoniska rotsökvägen i SQLite och upprätthåller ett
sökindex i minnet. Korpusinnehållet kopieras inte till kodförrådet eller databasen.

Indexuppdateringen är inkrementell. Oförändrade filer återanvänds baserat på storlek och
ändringstid, ändrade filer läses om och hashberäknas med SHA-256 och borttagna filer
avlägsnas. Vid sökning uppdateras ett index som är äldre än 30 sekunder; anropare kan
även begära en omedelbar uppdatering.

## Konfigurera källan

Inställningsrutten kräver samma administrationsautentisering som andra
inställnings-API:er. Den angivna sökvägen måste redan finnas och måste vara en absolut
katalogsökväg.

```bash
# Anslut en godkänd katalog
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# Kontrollera konfiguration och indexstatus
curl http://localhost:20128/api/settings/local-corpus

# Koppla från utan att ändra källfiler
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## MCP-verktyg

Alla tre verktygen kräver `read:local-corpus`. Verktygssvaren visar relativa sökvägar
och rotkatalogens basnamn, aldrig dess absoluta sökväg.

| Verktyg               | Beskrivning                                                                                   |
| :-------------------- | :-------------------------------------------------------------------------------------------- |
| `local_corpus_status` | Rapporterar konfigurationsstatus, indexstorlek, gränser och tidpunkt för senaste uppdatering  |
| `local_corpus_search` | Söker i indexerad text och returnerar begränsade, radavgränsade utdrag (upp till 20 resultat) |
| `local_corpus_read`   | Läser ett begränsat radintervall från en tillåten korpusrelativ fil                           |

Exempel på MCP-indata:

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## Säkerhetsgränser

- Tillåtelselistan är textorienterad: `.cfg`, `.csv`, `.geojson`, `.htm`, `.html`, `.ini`,
  `.js`, `.json`, `.jsonl`, `.jsx`, `.log`, `.md`, `.mjs`, `.ps1`, `.py`, `.sh`,
  `.sql`, `.toml`, `.ts`, `.tsx`, `.txt`, `.xml`, `.yaml` och `.yml`.
- Symboliska länkar hoppas över. Läsökvägar kanoniseras och måste förbli inom den
  konfigurerade roten; absoluta sökvägar och försök till katalogtraversering avvisas.
- Känsliga och genererade katalognamn undantas: `.build`, `.codex`, `.env`,
  `.git`, `.next`, `.omniroute`, `.ssh`, `coverage`, `dist`, `node_modules` och
  `secrets`.
- Standardgränserna är 5 000 filer, 1 MiB per fil, totalt 64 MiB indexerat innehåll,
  cirka 4 000 tecken per söksegment och 400 rader per läsning.
- Filer som innehåller NUL behandlas som icke-text och hoppas över eller avvisas.

Binära dokument som PDF, DOCX, bilder och arkiv stöds avsiktligt inte. Konvertera dem
till ett godkänt textformat i den konfigurerade katalogen före indexering.

## Driftinformation

- Om den konfigurerade roten ändras eller tas bort rensas det delade indexet i minnet.
- Vid omstart av processen kasseras indexet; nästa sökning bygger upp det på nytt från
  den konfigurerade källan.
- `local_corpus_status` framtvingar ingen genomsökning. Använd `local_corpus_search` med
  `refresh: true` när en omedelbar ny genomsökning krävs.
- Genomsöknings- och läsfel räknas eller returneras som sanerade fel; källfilerna
  ändras aldrig.
