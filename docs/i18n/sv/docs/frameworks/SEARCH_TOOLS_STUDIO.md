## Översikt

Search Tools Studio omvandlar `/dashboard/search-tools` från en enkel testmiljö för sökning till en
Studio med tre flikar som förenar webbsökning, webbskrapning och jämförelse av leverantörer sida vid sida.

```
┌ Sökverktyg ────────────────────────────────────────────────────────────┐
│ [🔍 Sök] [📄 Skrapa] [⚖ Jämför]                142ms · $0.001  </>    │
│ ⓘ [Guide till modaliteter]                                             │
├──────────────────────────────────────────┬─────────────────────────────┤
│  {innehåll i aktiv flik}                 │ ─ Konfiguration             │
│                                          │ Leverantör [auto ∨]         │
│                                          │   🟢 Serper  $0.001         │
│                                          │   🟢 Tavily  $0.008         │
│                                          │   🔥 Firecrawl (hämtning)   │
│                                          │ Typ    [web | news]         │
│                                          │ Hela sidan [ ] (skrapning)  │
│                                          │ Format [md|text|html]       │
│                                          │ Omrankningsmodell [∨]       │
└──────────────────────────────────────────┴─────────────────────────────┘
```

## Flikar

### Sökfliken

Vidareutvecklar befintliga `SearchForm` + `ResultsPanel` + `RerankPanel` till en flik:

- Fråga → resultat (titel, URL, utdrag, relevanspoäng).
- Leverantörsmetadata i konfigurationspanelen (kostnad, kvot, status).
- Omrankningsavsnitt: välj en omrankningsmodell, ordna om resultaten och visa `positionDelta`.
- Tomt tillstånd med uppmaning när inga sökleverantörer har konfigurerats.
- Sökhistorik via `SearchHistory.tsx`.
- Anropar `POST /v1/search` (befintlig slutpunkt, inga ändringar).

### Skrapningsfliken

Ny flik för att extrahera innehåll från en URL via `POST /v1/web/fetch` (skapad i plan 05):

- Indata: URL + växlingsknapp för hela sidan + formatväljare (markdown/text/HTML).
- Skicka → hämta → rendera `ScrapeResult.tsx`.
- `ScrapeResult` renderar en förhandsgranskning av markdown samt en växlingsknapp för rådata.
- Gräns: om svarstexten är större än **256 kB** visar gränssnittet `(avkortad, visa rådata)` och öppnar rådata i en Monaco-modal (D21).
- Metadatapanel: leverantör (firecrawl/jina-reader/tavily-search/tinyfish/nimble-search/anysearch-search), latens, kostnad, svarsstorlek, antal länkar.
- Använder hooken `useScrapeFetch.ts`.

### Jämförelsefliken

Kör samma fråga/URL parallellt hos upp till **4 leverantörer** (D22):

- Kolumner sida vid sida för varje leverantör.
- Mätvärden: latens, kostnad, antal resultat, svarsstorlek.
- Beräkning av URL-överlappning för sökning (antalet delade URL:er jämfört med det ursprungliga resultatet).
- Anropar `POST /v1/search` (sökning) eller `POST /v1/web/fetch` (skrapning) för varje leverantör.

## Konfigurationspanel (delad)

`SearchToolsConfigPane.tsx` — alltid synlig, kan fällas ihop.

| Fält              | Kommentarer                                                                                |
| ----------------- | ------------------------------------------------------------------------------------------ |
| Leverantör        | Listruta med statusindikator (konfigurerad/saknas/hastighetsbegränsad)                     |
| Typ               | `web` eller `news` (endast sökning)                                                        |
| Hela sidan        | Växlingsknapp för skrapning — hämtar hela sidan i stället för det först synliga innehållet |
| Format            | `markdown`, `text` eller `html` (endast skrapning)                                         |
| Omrankningsmodell | Valfri modell för omrankning efter sökning                                                 |
| Historik          | Hopfällbart avsnitt med sökhistorik                                                        |

## SearchConceptCard

`SearchConceptCard.tsx` — alltid synligt, komprimerbart dragspel. Förklarar:

| Koncept              | Kortfattad beskrivning                                                               |
| -------------------- | ------------------------------------------------------------------------------------ |
| **Sökning**          | Hämtar en lista med webbresultat (titel, URL, utdrag, relevanspoäng)                 |
| **Skrapning**        | Extraherar det fullständiga innehållet från en URL (markdown, text eller HTML)       |
| **Jämförelse**       | Kör samma sökfråga parallellt hos N leverantörer                                     |
| **Omrankning**       | Ändrar ordningen på resultaten via en LLM för att förbättra relevansen för sökfrågan |
| **Auto (billigast)** | Väljer automatiskt den billigaste tillgängliga leverantören                          |

## Leverantörskatalog

`ProviderCatalog.tsx` visar den fullständiga leverantörslistan från `GET /api/search/providers`
(utökad i F4 för att inkludera hämtningsleverantörer):

| `kind` | `"search"` (20 leverantörer) eller `"fetch"` (firecrawl, jina-reader, tavily-search, tinyfish, nimble-search, anysearch-search) |

Statusen **härleds vid tidpunkten för begäran** genom att kontrollera om autentiseringsuppgifter finns och om
alla nycklar för närvarande befinner sig i en vänteperiod.

## Exportera kod

`ExportCodeModal` (importerad från Playground Studio) + `codeExport.ts` genererar
curl-/Python-/TypeScript-kodexempel för anrop till både `/v1/search` och `/v1/web/fetch`.
Platshållaren för API-nyckeln är alltid `$OMNIROUTE_API_KEY` (D11, delas med Playground Studio).

## Ändringar i backend

Endast en ändring i backend krävdes för den här funktionen:

### Utökad `GET /api/search/providers`

`src/app/api/search/providers/route.ts` utökades för att:

- Inkludera samtliga 6 hämtningsleverantörer (`firecrawl`, `jina-reader`, `tavily-search`, `tinyfish`, `nimble-search`, `anysearch-search`) i arrayen.
- Lägga till `kind: "search" | "fetch"` för varje objekt.
- Lägga till `status: "configured" | "missing" | "rate_limited"`, härledd från aktuella autentiseringsuppgifter.
- Bibehålla bakåtkompatibilitet — befintliga fält (`id`, `name` osv.) är oförändrade.

## Felsökning

| Symptom                                               | Orsak                                          | Lösning                                                                                                                      |
| ----------------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Fliken Skrapa visar "slutpunkten är inte tillgänglig" | `/v1/web/fetch` är inte ansluten               | Kontrollera att plan 05 har slagits samman och att `src/app/api/v1/web/fetch/route.ts` finns                                 |
| Leverantörskatalogen visar alla som "saknas"          | Autentiseringsuppgifter har inte konfigurerats | Lägg till autentiseringsuppgifter i `/dashboard/providers`                                                                   |
| Skrapat innehåll är trunkerat                         | Svaret överskrider gränsen på 256 KB           | Förväntat beteende (D21). Använd knappen "visa rådata" för att se hela innehållet                                            |
| Fliken Jämför visar endast 2 leverantörer             | Hastighetsbegränsning är aktiv                 | Två eller fler leverantörer kan befinna sig i en nedkylningsperiod – kontrollera leverantörsstatusen i panelen Konfiguration |
| "Storlek" visas som en rå nyckel i tabellen           | i18n-nyckel saknas                             | Kontrollera att `search.size` finns i språkfilen och bygg om i18n                                                            |
