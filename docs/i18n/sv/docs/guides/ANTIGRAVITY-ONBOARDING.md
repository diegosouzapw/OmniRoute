## 1. Antigravity jämfört med Antigravity CLI (agy)

Båda leverantörerna delar **samma Google-backend** — identisk OAuth-klient, tokenförnyelse, slutpunkter och Google-konton. Skillnaden är vilka modeller du ser.

> Se [tillkännagivandet av Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli) för Googles officiella jämförelse.

| Aspekt                 | `antigravity` (IDE)                            | `agy` (CLI)                                              |
| ---------------------- | ---------------------------------------------- | -------------------------------------------------------- |
| **Google-produkt**     | Antigravity 2.0 / Antigravity IDE              | Antigravity CLI                                          |
| **Backend**            | Samma Google Cloud Code API                    | Samma Google Cloud Code API                              |
| **OAuth/token**        | Samma klient, samma förnyelse                  | Samma klient, samma förnyelse                            |
| **Modellkatalog**      | Statisk, kurerad lista (hårdkodad i OmniRoute) | Hämtas i realtid från Google via `:fetchAvailableModels` |
| **Claude-modeller**    | Sonnet 4.6, Opus 4.6 (4 varianter vardera)     | Sonnet 4.6, Opus 4.6 (4 varianter vardera)               |
| **Gemini-namngivning** | Tydliga etiketter (Low/Medium/High)            | Uppströms-ID:n (extra-low/low/agent)                     |
| **Extra modeller**     | `gpt-oss-120b-medium`                          | Kan inkludera ytterligare modeller från Google           |
| **Standardanvändning** | IDE-integration (VS Code, JetBrains)           | CLI-/API-åtkomst                                         |
| **Kvot**               | Delas med agy (samma Google-konto)             | Delas med antigravity (samma Google-konto)               |

**Tillgängliga modeller (verifierat genom experiment, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (olika nivåer av tänkande)
- Claude: Sonnet 4.6, Opus 4.6 (vardera med varianterna default/low/medium/high)
- Övriga: GPT-OSS 120B Medium
- **Claude Sonnet 5 är INTE tillgänglig** — endast 4.6-varianter stöds

**Varför modellkatalogen skiljer sig**: Googles CLI är ”optimerat för hastighet och låg overhead” och ”samoptimerat med Gemini-modeller” (enligt Googles officiella blogg). Webb-/IDE-produkten är ”optimerad för heltäckande funktionalitet”. CLI använder `:fetchAvailableModels` för att dynamiskt identifiera modeller, medan IDE använder en statisk, kurerad lista.

**I praktiken**: Använd prefixet `agy/` för Gemini-modeller (t.ex. `agy/gemini-3.7-flash-high`). Använd `antigravity/` för den statiska, kurerade listan. Båda använder samma Google-backend men exponerar olika modellnamn. Kvoten delas — användning av endera leverantören räknas mot samma Google-kontos gränser.

## 2. Google One AI Pro: Kvotsystem

> Se [Antigravity-dokumentationen: Abonnemang](https://antigravity.google/docs/plans) för officiell information om kvoter och [Ändringar i Antigravity-abonnemangen](https://antigravity.google/blog/changes-to-antigravity-plans) för de senaste prisuppdateringarna.

Google Antigravity använder en **kvot i två nivåer** baserad på ”Utfört arbete” (beräkningsvikt), inte antalet meddelanden.

### De två nivåerna

| Nivå                 | Vad den är                         | Uppdateringscykel                                                                    |
| -------------------- | ---------------------------------- | ------------------------------------------------------------------------------------ |
| **5-timmarssprint**  | Omedelbar pott med ”utfört arbete” | Återställs 5 timmar efter den första begäran i en session                            |
| **7-dagarsbaslinje** | Fast veckotak                      | Åsidosätter 5-timmarsåterställningen om taket nås; spärrar till nästa 7-dagarsperiod |

**Så beräknas ”Utfört arbete”**: Agentintensiva uppgifter (t.ex. ”Refaktorera hela det här kodarkivet”) förbrukar kvoten mycket snabbare än enkla uppgifter (t.ex. ”Åtgärda den här funktionen”). Det finns ingen realtidsöversikt som visar förbrukningen.

### Abonnemangsnivåer

| Abonnemang   | Pris        | Kvot                                    | Veckogräns                                   |
| ------------ | ----------- | --------------------------------------- | -------------------------------------------- |
| Free         | $0          | Betydande kvot, uppdateras varje vecka  | Ja                                           |
| AI Pro       | $19.99/mån  | Hög kvot, rullande 5-timmarsuppdatering | Ja (åsidosätter 5-timmarsgränsen om den nås) |
| AI Ultra 5x  | $99.99/mån  | 5x Pro-kvoten                           | Ingen veckogräns                             |
| AI Ultra 20x | $199.99/mån | 20x Pro-kvoten                          | Ingen veckogräns                             |

### Gemini-modeller jämfört med andra modeller

- **Gemini-modeller** (Flash + Pro): Delar en gemensam hastighetsgräns som förbrukas enligt API-prissättningen. Om Flash är 8x billigare än Pro får du 8x fler Flash-token.
- **Andra modeller än Gemini** (Claude, GPT-OSS): Har **separata** hastighetsgränser. De kan fortfarande vara tillgängliga även när Gemini är spärrat.

### AI-krediter (överförbrukning)

> Se [Google One AI-krediter](https://support.google.com/googleone/answer/14534406) för information om hur krediter fungerar.

När baslinjekvoten är förbrukad:

- **Aldrig**: Vänta på att kvoten ska uppdateras; visar ”Baslinjemodellens kvot har nåtts”
- **Alltid**: Använd AI-krediter automatiskt; växlar tillbaka till baslinjen när den uppdateras

Krediter köps separat och dras av enligt API-standardprissättningen.

### Viktig information

- Kvoten **delas på kontonivå** — samma Google-konto i Antigravity IDE, CLI och OmniRoute delar en gemensam kvotpott
- Varje Google-konto har en egen oberoende kvot — flera konton = flera kvotpotter
- AI Pro-användare har rapporterat **7-dagarsspärrar** i stället för 5-timmarsåterställningar när veckans baslinje nås (Google har bekräftat att detta är avsiktligt vid hög efterfrågan)

**När kontots kvot är förbrukad**: OmniRoute försöker automatiskt igen med nästa tillgängliga konto i kombinationsrutten. Ingen manuell åtgärd krävs.

## 3. Så skaffar du ett projectId

Varje antigravity/agy-anslutning behöver ett Google Cloud Code-`projectId`. Utan detta returnerar ändpunkten `/v1internal:models` 404.

### Metod A: Automatisk (rekommenderas)

OmniRoute hanterar detta automatiskt. När du lägger till ett nytt Google-konto via OAuth i kontrollpanelen:

1. OmniRoute uppdaterar token
2. Anropar `loadCodeAssist` för att identifiera projectId
3. Om inget projekt finns anropas `onboardUser` för att skapa ett
4. Försöker anropa `loadCodeAssist` igen för att hämta det nyskapade projectId
5. Sparar det i databasen

**Detta fungerar för de flesta konton** — inga manuella steg krävs.

### Metod B: Manuellt via agy CLI

Om den automatiska identifieringen misslyckas (se avsnitt 5 för när detta inträffar):

```bash
# Installera agy CLI (om det inte redan är installerat)
npm install -g @anthropic-ai/agy

# Logga in med ditt Google-konto
agy login

# Välj kontot som behöver introduceras
# Detta utlöser Cloud Code-registreringen och tilldelar ett projectId
```

När `agy login` har slutförts uppdaterar du token i OmniRoute-kontrollpanelen. projectId identifieras automatiskt.

### Så verifierar du

Kontrollera databasen:

```bash
# Inuti OmniRoute-containern
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Eller kontrollera loggarna:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. OAuth-omdirigerings-URI

### Problemet

Google OAuth kräver en giltig omdirigerings-URI. OmniRoutes standardinställning använder `http://127.0.0.1:20128/callback` (loopback). Detta fungerar för lokala byggen men **misslyckas för fjärrdistributioner** (t.ex. en server som nås via en LAN-IP-adress).

Google avvisar omdirigerings-URI:er som:

- Använder IP-adresser (måste vara en domän som slutar på `.com`, `.org` osv.)
- Inte matchar de registrerade omdirigerings-URI:erna i OAuth-klientkonfigurationen

### Lösningen

**Alternativ A: Använd det inbyggda OAuth-flödet (standard)**

- Fungerar när du öppnar OmniRoute från `localhost` eller `127.0.0.1`
- Ingen konfiguration krävs

**Alternativ B: Anpassade OAuth-autentiseringsuppgifter**

- Ange `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` i din miljö
- Ange dina egna Google OAuth-autentiseringsuppgifter:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Registrera `https://your-domain.com/callback` som en auktoriserad omdirigerings-URI i Google Cloud Console

**Alternativ C: Använd agy CLI för den första inloggningen**

- Kör `agy login` på den dator som ska komma åt OmniRoute
- OAuth-flödet slutförs lokalt och tokens lagras
- Importera anslutningen till OmniRoute via Dashboard

### Begränsningar

- Anpassade OAuth-autentiseringsuppgifter kräver ett domännamn (Google accepterar inte IP-adresser som omdirigerings-URI:er)
- Om du inte har en domän använder du alternativ A eller C i stället

## 5. Felsökning: När den automatiska konfigurationen misslyckas

OmniRoute hanterar identifiering av projectId och introduktionsprocessen automatiskt för de flesta konton. När detta misslyckas är grundorsaken vanligtvis något av följande:

### Kontots region är blockerad

**Symptom**: `agy login` returnerar "Eligibility check failed: Your current account is not eligible for Antigravity, because it is not currently available in your location."

**Grundorsak**: Google-konton har ett serverbaserat fält för "Country Association" som anges vid registreringen. agy CLI och Cloud Code API kontrollerar detta fält strikt – till skillnad från Gemini på webben, som endast kontrollerar din aktuella IP-adress.

> Om du vill kontrollera eller ändra regionen som är kopplad till ditt konto besöker du [Google-formuläret för landkoppling](https://policies.google.com/country-association-form).

**Varför Gemini på webben fungerar men inte agy**:

- Gemini på webben/Google One: kontrollerar endast aktuell IP-adress (proxy fungerar)
- agy CLI/Cloud Code API: läser det serverbaserade fältet för Country Association (proxy hjälper inte)

**Åtgärd**:

1. Besök [Google-formuläret för landkoppling](https://policies.google.com/country-association-form) medan du använder en amerikansk IP-adress
2. Skicka in en begäran om regionändring (välj "I live in a different country")
3. Vänta 1–24 timmar på att Google ska behandla begäran och skicka ett e-postmeddelande
4. Därefter bör `agy login` lyckas

### Kontot har inget Cloud Code-projekt

**Symptom**: Loggarna visar `loadCodeAssist returned no project id` och `onboardUser failed (400)`.

**Grundorsak**: Kontot har aldrig registrerats hos Google Cloud Code och den automatiska introduktionsprocessen misslyckades.

**Åtgärd**: Kör `agy login` manuellt för att utlösa Cloud Code-registreringen och uppdatera sedan token i OmniRoute Dashboard.

### Token har löpt ut eller återkallats

**Symptom**: 401-fel i loggarna eller meddelanden om "Token has expired".

**Åtgärd**: Uppdatera token i Dashboard → Providers → agy → Klicka på uppdateringsikonen. Om själva uppdateringstoken har återkallats måste du autentisera dig på nytt via OAuth.

## Beslutsflöde

```
Fungerar inte kontot?
│
├─ Har det ett projectId i databasen?
│  ├─ JA → Problemet finns någon annanstans (token har upphört att gälla, hastighetsgräns osv.)
│  └─ NEJ ↓
│
├─ Är kontots landsanknytning inställd på en begränsad region?
│  ├─ JA → Ändra region via Googles formulär för landsanknytning
│  │         (https://policies.google.com/country-association-form)
│  │         Vänta 1–24 timmar och försök sedan igen
│  └─ NEJ ↓
│
├─ Har kontot en Google One AI Pro-prenumeration?
│  ├─ NEJ → Prenumerera först på one.google.com
│  └─ JA ↓
│
├─ Försök med automatisk identifiering (uppdatera token i kontrollpanelen)
│  ├─ Fungerar → Klart
│  └─ Misslyckas fortfarande ↓
│
└─ Manuellt: Kör `agy login` på datorn
   ├─ Fungerar → Uppdatera token i kontrollpanelen, projectId identifieras
   └─ Misslyckas → Kontrollera felmeddelandet, troligen ett region- eller prenumerationsproblem
```
