`@omniroute/opencode-plugin-v2` gör hela din OmniRoute-katalog — modeller, kombinationer och
automatiska kombinationer — tillgänglig i OpenCode v2:s modellväljare, med visningsnamn, priser och
budgetar för kostnadsfria nivåer.

Det är ett separat paket från `@omniroute/opencode-plugin` eftersom OpenCode v1 och v2 läser in
plugin-program via olika kontrakt. Välj det som motsvarar din huvudversion av OpenCode; inget
delas mellan dem, så en uppgradering av det ena tvingar aldrig fram en uppgradering av det andra.

## Krav

- OpenCode v2.
- En nåbar OmniRoute-gateway (`http://localhost:20128` som standard).
- Node.js 22 eller 24.

## Installation

Lägg till plugin-programmet i `opencode.json`:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

Modeller visas sedan som `omniroute/<provider>/<model>`; `providerId` avgör detta prefix och
id:t för integrationen där OpenCode lagrar autentiseringsuppgiften.

## Autentiseringsuppgifter

Plugin-programmet letar efter en gateway-nyckel på tre platser, i denna ordning:

1. **Autentiseringsuppgiften som du anslöt i OpenCode.** Plugin-programmet registrerar en integration så att
   OpenCodes eget autentiseringsflöde kan lagra nyckeln. Inget hamnar i `opencode.json` — detta rekommenderas.
2. `apiKey` i plugin-alternativen, för en projektspecifik åsidosättning. Då placeras nyckeln i en fil som du
   eventuellt checkar in.
3. `OMNIROUTE_API_KEY` i miljön.

Om ingen av de tre finns är katalogen tom, och plugin-programmet meddelar detta en gång vid start i stället för
att lämna dig med en tom modellväljare utan förklaring.

### Hanteringstoken är en annan nyckel

Kombinationer, leverantörshälsa och metadata (visningsnamn, priser och budgetar för kostnadsfria nivåer) hämtas från
gatewayens `/api/*`-endpoints, som i de flesta installationer skyddas av en **hanterings**token
i stället för inferensnyckeln:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<läsningstoken för hantering>"
}
```

Om `managementReadToken` inte anges används `apiKey` som reserv. När en gateway avvisar detta alternativ
publiceras katalogen ändå, men med råa modell-id:n i stället för visningsnamn, utan deduplicering av
kanoniska alias, utan priser och utan kombinationer. Plugin-programmet varnar en gång per endpoint när detta händer
och anger endpointen och vad som gick förlorat — så en försämrad modellväljare är aldrig ett mysterium.

## Alternativ

| Nyckel                           | Standard                                                  | Anmärkningar                                                                                                       |
| -------------------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `providerId`                     | `"omniroute"`                                             | Leverantörs-id, integrations-id och prefixet som modeller visas under                                              |
| `baseURL`                        | obligatoriskt                                             | Gateway-rot, endast `http(s)`; suffixet `/v1` läggs till där det behövs                                            |
| `apiKey`                         | ansluten autentiseringsuppgift, sedan `OMNIROUTE_API_KEY` | Chattnyckel för `/v1/*`                                                                                            |
| `managementReadToken`            | använder `apiKey` som reserv                              | Nyckel för `/api/*` — vanligtvis **inte** samma nyckel                                                             |
| `displayName`                    | `"OmniRoute"`                                             | Leverantörsnamn i modellväljaren                                                                                   |
| `timeoutMs`                      | `10000`                                                   | Tidsgräns per endpoint vid hämtning (automatiska kombinationer använder 5 s)                                       |
| `modelCacheTtlMs`                | `300000`                                                  | TTL för katalogcachen; en ögonblicksbild på disk snabbar upp kallstarter                                           |
| `timeouts`                       | använder `timeoutMs` som reserv                           | Tidsbudgetar per endpoint i ms: `models`, `combos`, `autoCombos`, `enrichment`                                     |
| `enrichment`                     | `true`                                                    | Hämta namn, priser och budgetar för kostnadsfria nivåer                                                            |
| `providerTag`                    | `true`                                                    | Lägg till den vidarebefordrade leverantören som prefix i visningsnamnet                                            |
| `usableOnly`                     | `false`                                                   | Behåll endast leverantörer som gatewayen rapporterar som konfigurerade                                             |
| `visibleModels` / `hiddenModels` | `[]`                                                      | Tillåtelselistor med exakt matchning eller suffixmatchning; nekande regler har företräde                           |
| `geminiSanitization`             | `true`                                                    | Ta bort JSON-Schema-nyckelord som Gemini avvisar från verktygsscheman (`$ref`-verktyg vidarebefordras oförändrade) |
| `apiFormat.allowAnthropic`       | `false`                                                   | Dirigera tillåtelselistade id:n via Anthropic API-blocket                                                          |
| `apiFormat.anthropicModels`      | `[]`                                                      | Fullständiga modell-id:n som dirigeras till Anthropic                                                              |
| `logLevel` / `startupDebug`      | `warn` / `false`                                          | Loggningsnivå                                                                                                      |

## Så hålls katalogen aktuell

Katalogen hämtas vid behov och cachelagras under `modelCacheTtlMs`, och en ögonblicksbild på disk håller den
senast kända katalogen tillgänglig när gatewayen inte kan nås — ett avbrott kostar dig inget annat än
aktualitet. Modeller och kombinationer publiceras så snart de anländer; automatiska kombinationer, leverantörslistan
och berikningsöverlagret infogas när de blir tillgängliga, så en långsam slutpunkt kan inte hålla hela
modellväljaren som gisslan.

Namnen innehåller det som gatewayen känner till: den uppströmsleverantör som en modell dirigeras till, en `[Free]`-markering
och den budget som följer med den — så att två anslutningar som säljer samma modell förblir
särskiljbara. Stäng av prefixet med `"providerTag": false`.

Det finns inget manuellt uppdateringskommando: OpenCode v2-kommandon är promptmallar, inte återanrop,
så ett insticksprogram kan inte tillhandahålla ett sådant. Uppdateringar följer TTL-värdet; värdprogrammet ombeds endast att läsa in på nytt när
katalogen eller överlagret faktiskt har ändrats, aldrig en gång per uppdatering.

## Verktygsanrop i Gemini

Gemini avvisar en hel begäran vars verktygsdeklarationer innehåller `$schema` eller
`additionalProperties` och svarar med `400 INVALID_ARGUMENT`. Insticksprogrammet tar bort dessa nyckelord från
verktygsscheman som är avsedda för en Gemini-modell från denna leverantör och lämnar alla andra begäranden orörda.
Ett verktyg som innehåller en `$ref` vidarebefordras orört i stället för att rensas, eftersom borttagning av
referensen skulle utöka schemat till att "acceptera vad som helst".
Ange `"geminiSanitization": false` för att stänga av detta.

## Felsökning

| Symptom                                          | Orsak                                                                                                                   |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| Modellväljaren visar ingen OmniRoute-modell      | Ingen nyckel kunde hittas (kontrollera varningen vid start), eller så kan gatewayen inte nås                            |
| Råa modell-id:n, inga kombinationer, inga priser | Hanteringsslutpunkterna nekade token — ange `managementReadToken`                                                       |
| En session är låst till `opencode-<id>/…`        | v1-insticksprogrammet publicerade `opencode-<id>`; v2 publicerar enbart `<id>`, så välj modellen på nytt under `<id>/…` |
