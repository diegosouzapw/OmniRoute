**OmniCopilot** placerar alla modeller som din OmniRoute tillhandahåller i den _inbyggda_ modellväljaren för GitHub Copilot Chat. Ingen extra sidopanel, inget separat chattgränssnitt — Copilots agentläge, verktygsanrop, MCP-servrar och anpassade instruktioner fortsätter att fungera, men körs med den modell du väljer.

|                               |                                                                                                                                                 |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Installera (VS Code)**      | [Marketplace → `diegosouzapw.omnicopilot`](https://marketplace.visualstudio.com/items?itemName=diegosouzapw.omnicopilot)                        |
| **Installera (förgreningar)** | [Open VSX](https://open-vsx.org/extension/diegosouzapw/omnicopilot) — Cursor, Windsurf, VSCodium, Theia, code-server, Gitpod, Antigravity, Kiro |
| **Källkod/problem**           | [github.com/diegosouzapw/OmniCopilot](https://github.com/diegosouzapw/OmniCopilot) (MIT)                                                        |
| **Kräver**                    | VS Code 1.104+                                                                                                                                  |

> **Ingen Copilot-prenumeration behövs.** Sedan VS Code 1.122 fungerar en språkmodellsleverantör
> utan GitHub-inloggning och utan någon Copilot-plan. Funktionen för infogade kompletteringar och
> funktioner baserade på inbäddningar ligger utanför leverantörs-API:et och kräver fortfarande Copilot.

## Konfiguration

1. **Kör OmniRoute** — `npm install -g omniroute && omniroute` (instrumentpanelen finns på `http://localhost:20128`).
2. **Installera tillägget** — sök efter "OmniRoute" i tilläggsvyn.
3. **Välj en modell** — Copilot Chat → modellväljaren → **Hantera modeller…** → **OmniRoute**, markera sedan
   det du vill använda.

Inget behöver konfigureras när OmniRoute körs på standardporten. För en fjärrinstans öppnar du
**OmniRoute-ikonen i aktivitetsfältet** (eller kör `OmniRoute: Manage Connection`) och anger:

- **Server-URL** — serverns rotadress, t.ex. `http://192.168.0.15:20128`. Suffixet `/v1`
  läggs till av tillägget; inkludera det inte.
- **API-nyckel** — endast när servern ställer in `REQUIRE_API_KEY`. Lagras i operativsystemets nyckelring via VS
  Code SecretStorage, aldrig i `settings.json`.

## Vad modellväljaren visar

Tillägget visar inte den råa nyttolasten från `GET /v1/models` — det bearbetar den, och antalet du
ser är lägre än katalogens storlek av två avsiktliga skäl.

### Det begär ett id per modell

`MODELS_CATALOG_PREFIX_MODE` har standardvärdet **`dual`**, vilket exponerar varje modell två gånger — en gång
med det korta aliasprefixet och en gång med det kanoniska leverantörsprefixet — så att äldre klientkonfigurationer
fortsätter att kunna matcha båda formerna:

```
cc/claude-sonnet-4-6        ← aliasprefix
claude/claude-sonnet-4-6    ← kanoniskt prefix, samma modell
```

Tillägget begär **`GET /v1/models?prefix=alias`** så att ett id tas emot per modell, utan att
ändra den serverövergripande inställningen för dina andra klienter. På en referensinstans minskade detta
**2345 poster till 1396 — 949 dubbletter, inga modeller förlorade.**

Om du hellre vill åtgärda detta serverövergripande för _varje_ klient ställer du in funktionsflaggan
`MODELS_CATALOG_PREFIX_MODE` på `alias` i instrumentpanelen. Se
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) för
frågeparametern och tabellen för respektive läge.

### Det döljer modeller som inte kan chatta

Katalogen innehåller även modeller för bild, video, ljud, omrankning, inbäddning och moderering. Dessa
avvisas ändå vid en chattbegäran:

```
HTTP 400 — Modellen '<id>' är en bildgenereringsmodell och kan inte användas för
/v1/chat/completions. Använd POST /v1/images/generations i stället.
```

Därför filtreras de bort utifrån sitt `type`-fält innan de når modellväljaren. **Modeller för Responses-API
behålls** — varje Codex-/GPT-5.x-post exponerar `supported_endpoints: ["responses"]`,
och OmniRoute översätter dessa för `/v1/chat/completions`, så de kan användas utan problem.

### Leverantörer som du aldrig har konfigurerat

Katalogen listar modeller från leverantörer med en **aktiv anslutning** _plus_ alla **noAuth**-leverantörer
— de nyckelfria leverantörerna som utgör en stor del av kostnadsfria nivån. Det är avsiktligt. Om du vill dölja
dem lägger du till dem i `blockedProviders` i instrumentpanelens inställningar; inget ändras i
tillägget.

## Kontrollpanel i en VS Code-flik

`omnicopilot.dashboardOpen: "editor"` visar OmniRoute-kontrollpanelen i en redigeringsflik via
Simple Browser i stället för i en extern webbläsare. Inbäddning måste **aktiveras explicit på servern** via
`DASHBOARD_ALLOW_EMBED=vscode`, vilket levererar HTML-sidorna med
`frame-ancestors 'self' vscode-webview:` i stället för standardinställningen `frame-ancestors 'none'` +
`X-Frame-Options: DENY`. API-ytan (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) behåller de
strikta rubrikerna oavsett inställning.

> ⚠️ **Det är en flagga för byggtid, inte för körning.** Next.js kompilerar `headers()` till ruttmanifestet,
> så `next.config.mjs` läser variabeln när paketet byggs
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> Att exportera den innan en redan byggd server startas ändrar ingenting – rubrikerna är inbakade.

```bash
# variabeln måste finnas i byggkommandot
DASHBOARD_ALLOW_EMBED=vscode npm run build        # eller npm run build:release
npm start
```

| Installationsmetod         | Kan du aktivera inbäddning?                                                                                                                              |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Från källkod               | ✅ ange variabeln i byggkommandot enligt ovan                                                                                                            |
| `npm install -g omniroute` | ❌ det publicerade paketet levereras med ett förbyggt paket – bygg från källkod i stället                                                                |
| Docker-avbildning          | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` – den förbyggda avbildningen på Docker Hub har inte inbäddning aktiverad |

Utan ett bygge med aktiverad inbäddning vägrar sidan att visas i en ram. Tillägget upptäcker detta via
svarsrubrikerna och återgår till den externa webbläsaren – ingenting slutar fungera, och ett meddelande om detta visas en gång.
Se [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) och ärende
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273).

## Konfigurera dina andra verktyg inifrån VS Code

**`OmniRoute: Configure Coding CLI`** använder kommandoradsverktyget `omniroute` för att skapa färdiga profiler
för Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code,
Kilo och Roo – samma konfigurationer som beskrivs i
[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md). API-nyckeln överförs till kommandoradsverktyget via
miljövariabeln `OMNIROUTE_API_KEY`, aldrig via kommandoraden.

## Felsökning

| Symptom                                                   | Orsak/åtgärd                                                                                                                                                                                                                                             |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Inga OmniRoute-modeller i väljaren                        | Servern kan inte nås. Punkten i statusfältet blir grå. Kör `OmniRoute: Check Connection`. Identifieringen är avsiktligt tyst och lägger inte till några modeller i stället för att visa en uppmaning.                                                    |
| Varje modell visas två gånger                             | Du använder en version av OmniCopilot som är äldre än 1.0.1 – uppdatera. Tillägget begär nu `?prefix=alias`.                                                                                                                                             |
| En bild-/ljudmodell som tidigare visades är borta         | Avsiktligt sedan 1.0.1 – den kunde aldrig svara på en chattförfrågan.                                                                                                                                                                                    |
| Panelen saknas i aktivitetsfältet                         | VS Code flyttar extra vybehållare till menyn **"…"** längst ned i aktivitetsfältet, och en behållare som dolts via högerklick förblir dold. Högerklicka på aktivitetsfältet → markera **OmniRoute**, eller öppna den med `OmniRoute: Manage Connection`. |
| Kontrollpanelen öppnas i webbläsaren trots läget `editor` | Servern **byggdes** inte med `DASHBOARD_ALLOW_EMBED=vscode` (se ovan) – att ange den vid start för en förbyggd installation har ingen effekt. Reservlösningen är avsiktlig.                                                                              |
| Modellistan är inaktuell efter byte av leverantörer       | `OmniRoute: Refresh Models`, eller länken ↻ i panelen.                                                                                                                                                                                                   |
