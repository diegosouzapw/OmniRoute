> Körtidsväxlar som ändrar OmniRoutes beteende **utan en ny driftsättning**.
> Varje flagga som anges här definieras i
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> — den enda sanningskällan. Instrumentpanelen och REST-API:et läser båda från
> den filen, så tabellen nedan genereras för att överensstämma med den exakt.

---

## Vad funktionsflaggor är

En funktionsflagga är en namngiven växel (boolesk eller enum) vars värde kan ändras
under körning och sparas i databasen, utan att processen behöver driftsättas på nytt. Varje
flagga beskrivs av en `FeatureFlagDefinition` med en `key`, `label`,
`description`, `category`, `defaultValue`, `type` och en `requiresRestart`-indikering.

### Prioritetsordning

Det **effektiva värdet** för en flagga fastställs av
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) enligt denna
prioritetsordning (högst prioritet gäller):

1. **Databasåsidosättning** — ett värde som lagras i tabellen `key_value` under
   namnrymden `feature_flags` (anges via instrumentpanelen eller REST-API:et).
2. **Miljövariabel** — `process.env[<KEY>]`, om den har angetts och inte är tom.
3. **Definitionens standardvärde** — `defaultValue` från `featureFlagDefinitions.ts`.

En boolesk flagga anses vara **aktiverad** när dess effektiva värde är `"true"`,
`"1"` eller `"yes"` (se `isFeatureFlagEnabled()`).

> [!NOTE]
> De flesta flaggor har också en motsvarande miljövariabel med **samma namn**
> som dokumenteras i [`ENVIRONMENT.md`](./ENVIRONMENT.md). Flaggans databasåsidosättning
> har företräde framför den miljövariabeln. En flagga med
> `requiresRestart: true` sparas omedelbart men läses endast in på nytt när processen
> startas — när den växlas visas en **"Starta om servern"**-banderoll i instrumentpanelen.

## Växla flaggor

### Kontrollpanel

Gå till **Kontrollpanel → Inställningar → Funktionsflaggor**
(`/dashboard/settings/feature-flags`). Rutnätet
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
stöder:

- **Sökning** efter nyckel eller beskrivning och **filtrering** efter kategori (samt en syntetisk
  vy för **Kräver omstart**).
- En **växlingsknapp** för booleska flaggor och en **rullgardinsmeny** för uppräkningsflaggor
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- Ett **källmärke** per flagga — `DB`, `ENV` eller `DEF` — som visar varifrån det
  effektiva värdet kommer.
- En **Återställ**-knapp (visas endast för flaggor med `DB` som källa) för att ta bort åsidosättningen
  samt en **Återställ alla åsidosättningar**-knapp längst ned.
- En **Starta om servern**-banderoll när en flagga med `requiresRestart` ändras.

### REST-API

Alla åtgärder går via en enda route:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Varje metod kräver en autentiserad kontrollpanelsession (`401` annars).

#### `GET /api/settings/feature-flags`

Returnerar varje flagga med dess effektiva värde, källa och en sammanfattning.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... alla 75 flaggor
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Ange eller ta bort en enskild åsidosättning. Brödtext: `{ key: string; value?: string }`.
Om `value` utelämnas tas åsidosättningen bort (och miljö-/standardvärdet återställs).

```bash
# Ange en DB-åsidosättning
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Ta bort åsidosättningen (inget "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Svaret återger det nya `effectiveValue`/`source`, `previousValue`/
`previousSource` samt `requiresRestart`. Okända nycklar och uppräkningsvärden
utanför det tillåtna intervallet avvisas med `400`.

#### `DELETE /api/settings/feature-flags`

Rensar **alla** DB-åsidosättningar samtidigt och återställer varje flagga till dess miljö-/
standardvärde. Returnerar `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> Flaggor med `requiresRestart: true` börjar gälla först efter att processen har startats om.
> Kontrollpanelens omstartsflöde anropar `POST /api/restart` och avfrågar sedan
> `GET /api/health/ping` tills servern är igång igen.

## Reservlösning vid akut budgetbrist

`OMNIROUTE_EMERGENCY_FALLBACK` (kategori `runtime`, standardvärde `true`) styr den
kostnadsfria reservvägen vid akuta situationer i
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
När den är aktiverad dirigeras förfrågningar som förbrukat hela sin budget till en kostnadsfri
reservleverantör/-modell i stället för att misslyckas direkt. Ange den som `false` (eller `0`) — via
kontrollpanelens växlingsknapp, en DB-åsidosättning eller miljövariabeln
`OMNIROUTE_EMERGENCY_FALLBACK` — för att inaktivera beteendet och låta förfrågningar
som förbrukat sin budget misslyckas. (Exponerades som en växlingsknapp i kontrollpanelen i PR:erna #3741 / #3752.)
