Komprimeringsregler är JSON-filer som läses in vid körning. De är avsiktligt endast databaserade, så att nya språkpaket och RTK-kommandofilter kan granskas utan att motorkoden ändras.

> **Kanoniskt schema (sanningskälla):** [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) (JSON Schema-utkast 2020-12).
> Exemplen nedan är illustrativa — validera paketet mot `_schema.json` om du är osäker.

## Caveman-regelpaket

Caveman-regelpaket finns under:

```txt
open-sse/services/compression/rules/<language>/<pack>.json
```

Varje paket innehåller ersättningar som tillämpas på vanlig prosa efter att skyddade områden har isolerats.

```json
{
  "language": "en",
  "category": "filler",
  "rules": [
    {
      "name": "question_to_directive",
      "pattern": "\\b(?:Can you explain why|Could you show me how)\\b\\s*",
      "replacement": "Explain why ",
      "replacementMap": {
        "can you explain why": "Explain why ",
        "could you show me how": "Show how "
      },
      "flags": "gi",
      "context": "all",
      "category": "context",
      "minIntensity": "lite",
      "description": "Convert verbose questions into direct requests."
    }
  ]
}
```

### Caveman-fält

| Fält                     | Obligatoriskt | Beskrivning                                                              |
| ------------------------ | ------------- | ------------------------------------------------------------------------ |
| `language`               | ja            | BCP-47-liknande språknyckel, exempelvis `en`, `pt-BR`, `es`              |
| `category`               | ja            | Paketets kategorifilnamn/kategori, exempelvis `filler` eller `dedup`     |
| `rules`                  | ja            | Matris med regler för ersättning via reguljära uttryck                   |
| `rules[].name`           | ja            | Stabilt regelnamn                                                        |
| `rules[].pattern`        | ja            | JavaScript-källkod för reguljärt uttryck                                 |
| `rules[].flags`          | nej           | JavaScript-flaggor för reguljära uttryck; standardvärde `gi`             |
| `rules[].replacement`    | nej           | Ersättningssträng eller reservvärde när `replacementMap` saknar en träff |
| `rules[].replacementMap` | nej           | Träffspecifika ersättningar, indexerade efter normaliserad matchad text  |
| `rules[].context`        | nej           | `all`, `user`, `assistant` eller `system`; standardvärde `all`           |
| `rules[].category`       | nej           | `filler`, `context`, `structural`, `dedup`, `terse` eller `ultra`        |
| `rules[].minIntensity`   | nej           | `lite`, `full` eller `ultra`; standardvärde `lite`                       |
| `rules[].description`    | nej           | Människoläsbar regelsammanfattning                                       |

Använd `flags` när skiftlägeskänslig matchning är viktig, exempelvis för borttagning av artiklar före prosa med gemener utan att ta bort `the OpenAI API`. Använd `replacementMap` när ett reguljärt uttryck har flera alternativ som behöver olika utdata; detta gör att JSON-regelpaketen förblir helt databaserade samtidigt som beteendet hos de mer avancerade inbyggda TypeScript-ersättningsfunktionerna bevaras.

## RTK-filterpaket

RTK-filter finns under:

```txt
open-sse/services/compression/engines/rtk/filters/<filter>.json
```

Varje filter beskriver hur en familj av kommandoutdata identifieras och komprimeras.

```json
{
  "id": "test-vitest",
  "label": "Vitest-utdata",
  "category": "test",
  "priority": 92,
  "match": {
    "outputTypes": ["test-vitest"],
    "commands": ["vitest", "npm test", "npm run test"],
    "patterns": ["\\bFAIL\\b", "\\bPASS\\b", "\\bTest Files\\b"]
  },
  "rules": {
    "stripAnsi": true,
    "replace": [{ "pattern": "\\s+\\[[0-9]+ms\\]", "replacement": "" }],
    "matchOutput": [
      {
        "pattern": "All tests passed",
        "message": "vitest: ok",
        "unless": "FAIL|Error:"
      }
    ],
    "includePatterns": ["FAIL", "Error:", "Test Files", "Tests"],
    "dropPatterns": ["^\\s*$", "Duration\\s+\\d+"],
    "collapsePatterns": ["^\\s+at "],
    "deduplicate": true,
    "truncateLineAt": 240,
    "maxLines": 160,
    "headLines": 24,
    "tailLines": 40,
    "onEmpty": "vitest: ok",
    "filterStderr": false
  },
  "preserve": {
    "errorPatterns": ["FAIL", "Error:", "AssertionError"],
    "summaryPatterns": ["Test Files", "Tests", "Snapshots"]
  },
  "tests": [
    {
      "name": "bevarar misslyckade tester",
      "command": "vitest",
      "input": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed",
      "expected": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed"
    }
  ]
}
```

### RTK-fält

| Fält                       | Obligatoriskt | Beskrivning                                                                   |
| -------------------------- | ------------- | ----------------------------------------------------------------------------- |
| `id`                       | ja            | Stabil identifierare för filtret                                              |
| `label`                    | ja            | Namn som kan läsas på instrumentpanelen                                       |
| `category`                 | ja            | Filterfamilj: git, test, build, shell, docker, package, infra, cloud, generic |
| `priority`                 | nej           | Högre prioritet vinner när flera filter matchar                               |
| `match.outputTypes`        | nej           | Identifierare för detektorutdata som väljer detta filter                      |
| `match.commands`           | nej           | Kommandotoken som väljer detta filter                                         |
| `match.patterns`           | nej           | Regexmönster som väljer detta filter från utdatatexten                        |
| `rules.stripAnsi`          | nej           | Tar bort ANSI-escape-sekvenser före regexstegen                               |
| `rules.replace`            | nej           | Ordnade regexersättningar som tillämpas rad för rad                           |
| `rules.matchOutput`        | nej           | Regler för kortsluten utdata med valfri `unless`-kontroll                     |
| `rules.includePatterns`    | nej           | Rader som i första hand ska bevaras                                           |
| `rules.dropPatterns`       | nej           | Rader som ska tas bort som brus                                               |
| `rules.collapsePatterns`   | nej           | Upprepade matchande rader som kan slås samman                                 |
| `rules.deduplicate`        | nej           | Slår samman dubblerade normaliserade rader                                    |
| `rules.truncateLineAt`     | nej           | Unicode-säker teckengräns per rad                                             |
| `rules.maxLines`           | nej           | Maximalt antal bevarade rader innan slutet bevaras                            |
| `rules.headLines`          | nej           | Inledande rader som bevaras vid trunkering                                    |
| `rules.tailLines`          | nej           | Avslutande rader som bevaras för aktuell kontext                              |
| `rules.onEmpty`            | nej           | Reservmeddelande när filtreringen tar bort allt innehåll                      |
| `rules.filterStderr`       | nej           | Normaliserar vanliga stderr-prefix före senare filtreringssteg                |
| `preserve.errorPatterns`   | nej           | Felrader som ska överleva trunkering                                          |
| `preserve.summaryPatterns` | nej           | Sammanfattningsrader som ska överleva trunkering                              |
| `tests[]`                  | nej           | Inbäddade verifieringsexempel som används av RTK:s verifieringsgrind          |

RTK tillämpar deklarativa steg i denna ordning: `stripAnsi`, `filterStderr`, `replace`,
`matchOutput`, `dropPatterns`/`includePatterns`, `truncateLineAt`, `headLines`/`tailLines`,
`maxLines` och `onEmpty`.

Anpassade filter kan läsas in från:

1. Projektets `.rtk/filters.json`-filer endast efter att en matchande hash finns i `.rtk/trust.json` eller
   `trustProjectFilters` är aktiverat.
2. Globala `DATA_DIR/rtk/filters.json`.
3. Inbyggda filter.

Anpassade projektfiler/globala filer kan innehålla ett filterobjekt eller en array med filterobjekt. Ogiltiga
anpassade filter hoppas över med diagnostik; ogiltiga inbyggda filter gör att valideringen misslyckas.

Projektets förtroendefil:

```json
{
  "filtersSha256": "0123456789abcdef..."
}
```

Miljöåsidosättningen `OMNIROUTE_RTK_TRUST_PROJECT_FILTERS=1` gör att projektfilter betros utan en
hash och bör begränsas till kontrollerad lokal utveckling.

## Säkerhetsregler

- Håll regler idempotenta: att köra samma filter två gånger ska inte förvanska utdata.
- Bevara exakt feltext, filsökvägar, radnummer och kommandosammanfattningar där det är möjligt.
- Undvik regler som ändrar kodblock, JSON-nyttolaster, URL:er eller hemligheter.
- Lägg till enhetstesttäckning för nya kommandofamiljer i detektor-/filtertester.
- Lägg till `tests[]`-exempel i varje inbyggt filter och i delade anpassade filter.

## Validering

Regelpaket valideras före användning. Inbyggda Caveman-paket och inbyggda RTK-filter avbryts omedelbart
under valideringen så att felaktiga versionsartefakter upptäcks före leverans. Anpassade RTK-filter
hoppas över med diagnostik när parsningen eller tillitsvalideringen misslyckas.

Fokuserad validering:

```bash
node --import tsx/esm --test tests/unit/compression/rule-loader.test.ts tests/unit/compression/language-packs.test.ts
node --import tsx/esm --test tests/unit/compression/rtk-verify.test.ts tests/unit/compression/rtk-dsl-pipeline.test.ts
```
