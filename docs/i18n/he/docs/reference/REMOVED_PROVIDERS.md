שירותים מסוימים שולבו ב-OmniRoute ולאחר מכן הוסרו משום שהאנשים שמפעילים
אותם ביקשו זאת. דף זה הוא התיעוד הקבוע של הסרות אלה. מטרתו היחידה היא
למנוע את החזרתם בטעות: תורם שמוצא פיצול ישן, חבילת npm שמורה במטמון,
סוגיה שהועברה לארכיון או בקשה מסוג "שחזרו את ספק X" זקוק למקום אחד שמבהיר **אין
להחזיר אותם**.

דף זה **אינו** רשימה של שירותים שהושבתו או הופסקו. אלה מתועדים
ב-[`FREE_TIERS.md`](FREE_TIERS.md) ("הוסרו / ללא מסלול חינמי") ויכולים לחזור אם השירות
יחזור. הרשומות שלהלן יכולות לחזור רק באישור בכתב מהמפעיל המצוין
בבקשה, ויש לקשר לאישור זה מתוך הרשומה.

## מדיניות

1. **בקשת הסרה ממפעיל שירות מכובדת ואינה נתונה למשא ומתן.** OmniRoute
   אינו משויך לשום שירות חיצוני. כאשר מפעיל של שירות מבקש להסיר את
   השילוב, הוא מוסר, בין אם השילוב השתמש ב-API רשמי ובין אם לאו.
2. **"הוסר" פירושו מכל משטח שנמצא בשליטת OmniRoute.** מנגנון ההפעלה, רשומת המרשם, מזהה
   הספק והכינוי, רשימת המודלים, נקודות הקצה, משתני הסביבה, הסמל, כרטיסי לוח המחוונים,
   מסמך העזר לספק שנוצר אוטומטית, `FREE_TIERS.md`, מסמך העזר לסביבה, הספירות ב-README,
   עותקי `llm.txt`, בדיקות ייעודיות ותצלומי מצב מאושרים, הערות קוד, סעיפי CHANGELOG
   (עם התאמה מתועדת, ראו `config/release/changelog-reconciliations.json`),
   הערות GitHub Releases, הוויקי, וכן הסוגיות, הדיונים ובקשות המשיכה ב-GitHub
   שנושאם היה אותו ספק (סוגיות ודיונים נמחקים; שמות בקשות המשיכה משתנים, התיאור שלהן
   מוחלף והשרשור ננעל, משום ש-GitHub אינו מאפשר למחוק בקשות משיכה).
3. **לעולם אין להחזיר רשומה מדף זה ללא אישור בכתב.** הדבר כולל
   הוספה מחדש של המזהה או הכינוי לקטלוג ספקים כלשהו, הוספת הדומיינים למנגנון הפעלה,
   קבלת PR מתורם ש"משחזר" אותו, הוספתו לקטלוג המודלים החינמיים, או
   תיעוד דרך ידנית להגיע אליו באמצעות OmniRoute. יש לסגור בקשות משיכה וסוגיות כאלה עם
   קישור לדף זה.
4. **יש לשמור על הרשומה מצומצמת.** יש לתעד רק את מה שבודק צריך כדי לזהות
   החזרה: מזהים, דומיינים, תאריכים ובקשת המשיכה שביצעה את ההסרה.
   אין לתאר כיצד השילוב פעל.
5. **מנגנון ההגנה מפני רגרסיה הוא `tests/unit/removed-providers-blocklist.test.ts`.** הוא נכשל כאשר
   מזהה או דומיין כלשהם מהרשימה שלהלן מופיעים שוב בקטלוגי הספקים, במפת מנגנון ההפעלה או
   במקורות מרשם הספקים. יש להוסיף את המזהים החדשים לבדיקה זו באותו PR שבו
   נוספת שורה כאן.

## הוספת רשומה

כאשר מתקבלת בקשת הסרה חדשה:

1. יש לוודא שהבקשה מגיעה ממפעיל השירות (מכתובת התמיכה שלו או
   מדומיין שבשליטתו), ולשמור את ההודעה באופן פרטי.
2. יש להסיר את השילוב בהתאם לרשימת הבדיקה בסעיף 2 של המדיניות. השתמשו
   ב-[#12440](https://github.com/diegosouzapw/OmniRoute/pull/12440) כדוגמה לספק
   ללא מפתח וב-[#10210](https://github.com/diegosouzapw/OmniRoute/pull/10210) עבור
   ספק מבוסס מפתח API עם חיבורים שמורים (יש להוסיף העברה).
3. יש להוסיף שורה אחת לטבלה שלעיל ואת המזהים ל-
   `tests/unit/removed-providers-blocklist.test.ts`, באותו PR.
4. יש להשיב למפעיל לאחר מיזוג ה-PR, תוך פירוט מה הוסר ומה OmniRoute
   אינו יכול לשנות (גרסאות npm ו-Docker שכבר פורסמו, היסטוריית git, פיצולים של צדדים שלישיים).
