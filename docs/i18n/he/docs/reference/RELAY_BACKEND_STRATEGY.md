## סיכום

OmniRoute תומך כעת בשלושה מצבי ממסר עבור `/api/v1/relay/chat/completions`:

- `ts`: שימוש בממסר TypeScript בתוך התהליך.
- `bifrost`: כפיית השימוש בשער Bifrost.
- `auto`: העדפת Bifrost כאשר הוא זמין, עם חזרה ל-TypeScript במקרה של כשל.

כאשר המערכת פועלת בקצב בקשות גבוה (מספר גדול של טוקנים ביום, תפוקה כמעט רציפה), האסטרטגיה הטובה ביותר היא לשמור על נתיב החזרה מפורש ומהיר, כדי שהנתיב הפעיל לעולם לא ייחסם עקב תהליך sidecar שאינו מגיב.

## התנהגות המצבים

- `ts`
  - המורכבות התפעולית הנמוכה ביותר.
  - כל הניתוב והאימות מתבצעים ב-Node.
  - הזמינות אינה תלויה ב-sidecar.
- `bifrost`
  - כפיית העברת כל הבקשות דרך שער ה-sidecar.
  - אין חזרה אוטומטית.
  - שימושי רק כאשר תקינות ה-sidecar וזמן ההשהיה שלו מובטחים.
- `auto`
  - נעשה שימוש ב-sidecar כאשר ניתן להגיע אליו וכאשר הוא מופעל.
  - ניסיונות שנכשלו מפעילים כותרות חזרה ומחזירים את התעבורה אל TS, כך שהצלחת הבקשות נשארת מוגבלת בזמן.
  - מצב זה הוא הבחירה הבטוחה ביותר לסביבת ייצור כאשר זמן הפעילות חשוב יותר מניתוב קפדני דרך ה-sidecar בלבד.

## 9router לעומת CLIPROXYAPI כיום

9router ו-CLIPROXYAPI הם שילובים שסיפקו באופן מסורתי נתיבי תאימות לספקים במעלה הזרם.

- 9router הוא נתיב מוטמע לתזמור במעלה הזרם ולהתנהגות תאימות.
- CLIPROXYAPI הוא גשר API מסוג proxy עבור תעבורה בסגנון CLI / SDK.
- Bifrost עובר תהליך ייצוב כנתיב החיצוני לשימוש כאשר נדרשת תחנה ייעודית דמוית sidecar ושליחה מקומית בהשהיה נמוכה.

אם אתם משווים כעת בין 9router ל-CLIPROXYAPI:

- השאירו את חתימת הבקשות, בדיקות רשימת ההיתרים ושערי המדיניות של מסד הנתונים בנתיב ה-API לפני ההעברה.
- אם תהליך עבודה דורש התנהגות sidecar קפדנית ושונות נמוכה יותר בין בקשות, השתמשו ב-`OMNIROUTE_RELAY_BACKEND=bifrost`.
- אם נדרשת עמידות של ה-sidecar עם התדרדרות הדרגתית בתנאי תקלה, השתמשו ב-`OMNIROUTE_RELAY_BACKEND=auto`.

## חוזה הגבול של הקצה האחורי

גבול המוצר היציב הוא API הממסר של OmniRoute, ולא מימוש לוח הבקרה. לוח הבקרה של Next.js רשאי להתקין, להגדיר ולפקח על שירותים מקומיים, אך ניתוב הבקשות צריך להיכנס דרך API הממסר ולהימסר מאחורי גבול זה.

אפשרויות ארוכות טווח לקצה האחורי:

- השאירו את ממסר TypeScript כנתיב המדיניות והחזרה שבתוך התהליך. אימות, רשימות היתרים, נרמול בקשות, מדידה ובדיקות בטיחות נשארים כאן לפני כל העברה לקצה אחורי.
- השתמשו ב-Bifrost כ-sidecar המועדף בעל התפוקה הגבוהה בשכבה Tier-1 כאשר הפריסה דורשת שונות ניתוב נמוכה יותר, רוטציה מרוכזת של ספקים או הרחבה על פני מספר מופעים של OmniRoute.
- השאירו את 9router ואת CLIPROXYAPI כשירותי תאימות מוטמעים. הם פועלים כתהליכים מקומיים מפוקחים ושימושיים כאשר התנהגות הספק/CLI שלהם היא המתאם הרצוי, אך הם אינם אמורים להפוך למנוע הניתוב המוגדר כברירת מחדל בשכבה Tier-1.
- אל תאפשרו ללוח הבקרה להעביר כתובות URL שרירותיות של שירותים אל הנתיב הפעיל. כתובות URL שמספק ממשק המשתמש הן קלטי תצורה; קוד הניתוב צריך לאתר קצוות אחוריים רשומים שעברו בדיקות תקינות מתוך הגדרות בצד השרת ומצב המפקח.
- כיום עדיף להשתמש ב-HTTP דרך ממשק loopback עבור שירותים מפוקחים, משום שהתהליכים המנוהלים כבר חושפים ממשקי API תואמי HTTP, מגן הנתיב יכול לבצע ביקורת על הגבול, והתנהגות הכשל/החזרה גלויה ביומני הבקשות. כדאי להוסיף בעתיד תעבורה דרך SDK או socket רק אם היא מפחיתה באופן מדיד את השהיית הניתוב ב-p99 מבלי להחליש את הבידוד או את סמנטיקת החזרה.

לכן, עבור פריסה בעלת תפוקה גבוהה מאוד, ברירת המחדל המומלצת היא `auto` כאשר Bifrost מופעל: השתמשו ב-sidecar המבוסס על Go בנתיב הפעיל, תוך שמירה על החזרה ל-TypeScript כדי לשמר את שיעור ההצלחה. השתמשו ב-`bifrost` רק כאשר התנהגות קפדנית דרך ה-sidecar בלבד חשובה יותר מהתדרדרות הדרגתית.

## הנחיות לתפוקה גבוהה

עבור RPM/RPS גבוה ומתמשך ו-SLO הצלחה קפדני:

1. השתמשו ב-`auto` עם פרק צינון מעשי וטלמטריית כשלים.
2. השאירו את אימות התעבורה במעלה הזרם ואת בדיקות מפתחות ה-API בגבול נתיב TypeScript.
3. הפעילו כותרות/מונים מפורשים כדי שמערכת ההתראות שלכם תזהה את תדירות החזרה ואת הסיבות לה.
4. כווננו את זמני הקצוב של ה-sidecar כך שייכשל במהירות, במקום להמתין ללא הגבלה.
5. שמרו על תקינות ההפעלה מחדש האוטומטית של השירות ועל לולאת טלמטריית התקינות, כדי שהחזרה תהיה באמת חריגה.

## תצורת בסיס מוצעת

- `OMNIROUTE_RELAY_BACKEND=auto`
- `BIFROST_ENABLED=1`
- השאירו את בדיקות מפתחות ה-API, רשימת ההיתרים, מנקה הקלט והגבלת הקצב מופעלות במטפלי הנתיבים (הן תמיד מתבצעות לפני ההעברה במורד הזרם).
- יצאו מדדי חזרה מה-reverse proxy ומיומני הבקשות, כדי שהשבתות של ה-sidecar יהיו גלויות בתוך דקה אחת.

הבטוח לשימוש ב-JSON, במקום להסתמך על הפרטים הפנימיים של מבצע TypeScript. ראו
