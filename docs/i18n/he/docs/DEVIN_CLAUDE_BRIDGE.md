`devin-cli-agentic` מאפשר לזמן הריצה האמיתי של Claude Code להשתמש בנקודת הקצה המקומית של OmniRoute
עבור Anthropic Messages, בזמן שה-CLI הרשמי של Devin מספק תגובות מודל דרך ACP stdio. הוא
אינו משנה את הספקים הקיימים של Anthropic,‏ Claude OAuth,‏ Claude Web או `devin-cli`.

> **מצב נוכחי: Claude Code מקובע לגרסה `2.1.258`; האימות הלא-מקוון והחי תועד לאחרונה
> בגרסה `2.1.220`.** הקיבוע לגרסה `2.1.220` השלים שלושה תרחישים מבודדים באמצעות Devin CLI
> `3000.2.17` והמודל `swe-1-7-lightning`; ההרצה החיה הסופית הוכיחה תורות `Read`,
> `Edit` ו-`Bash` שבבעלות הלקוח, תוצאות מוצלחות של `npm test`, גילוי פקודות ומיומנויות
> של הפרויקט, ניתוב ל-Devin בלבד ואפס תעבורה יוצאת אל Claude. לאחר מכן הועלה הקיבוע לגרסה `2.1.258`
> (דור ה-CLI שזהות Claude של OmniRoute מתחזה אליו, והשורה הראשונה הכוללת
> תמיכה מובנית ברמת Fable 5.1). בקיבוע החדש אומתו שכבת ההתקנה ו-`claude --version`
> בתמונת הבסיס המקובעת, וחבילת בדיקות היחידה של הגשר, `compose config`
> והוכחת הבידוד הסטטית עוברות — אך תרחיש ההדמיה הלא-מקוון וחבילת שלושת התרחישים
> החיה טרם הורצו מחדש. הריצו אותם מחדש (ראו "עדכון כלים מקובעים") לפני הסתמכות על
> הגשר עם קיבוע זה.

## ארכיטקטורה

```text
Claude Code 2.1.258 (קונטיינר Linux מבודד שאינו root)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (ספק בפורמט Claude, ללא אימות)
  -> devin acp --agent-type summarizer (ACP stdio רשמי, ללא כלי Devin)
  -> חשבון Devin באמצעי האחסון הייעודי devin-auth
```

סוכן ה-ACP המוגדר כברירת מחדל של ה-CLI הרשמי יכול להפעיל את הכלים שלו עצמו, ולכן גשר זה אינו משתמש
בו. הוא מפעיל את סוכן ה-ACP הקבוע `summarizer`, שבמצב ה-CLI הרשמי שלו אין כלים, וממסגר
את בקשת Anthropic שעברה סריאליזציה כעקבת ביצוע. כאשר נדרשת פעולה נוספת בבעלות Claude,
התגובה חייבת להכיל מעטפת כלי לקוח אחת בדיוק. כל `tool_call` או `tool_call_update` של ACP
נדחים לפני שניתן לדווח על תגובה כמוצלחת.

הסריאלייזר ב-`open-sse/executors/devin-agentic/serializer.ts` משמר את `system`,
`text`,‏ `tool_use`,‏ `tool_result`,‏ `thinking`,‏ `redacted_thinking`,‏ `tool_choice` ואת
הכלים שסופקו על ידי Claude Code. תמונות ובלוקים בלתי מוכרים נכשלים באופן מפורש. תוצאות כלי גדולות
משתמשות בסמן קיטוע גלוי.

המנתח מקבל מעטפת `<tool>{...}</tool>` עצמאית אחת בכל תור מודל. הוא בודק
את השם מול רשימת הכלים של הבקשה, מאמת את הארגומנטים מול JSON Schema של הכלי,
דוחה שילוב של טקסט סיפורי ופעולות ומתיר ניסיון תיקון מוגבל אחד. לאחר מכן Claude Code
מפעיל מקומית את `tool_use` של Anthropic שנוצר ושולח את `tool_result` בחזרה דרך
OmniRoute.

## בידוד ומודל איומים

התקנת Claude, החשבון והתצורה של המארח נמצאים מחוץ לתחום ונחשבים
אסורים. שירותי Compose:

- פועלים כ-UID/GID‏ `10001:10001`, עם מערכת קבצים שורשית לקריאה בלבד, יכולות שהוסרו
  ו-`no-new-privileges`;
- משתמשים ב-`/home/bridge` פרטי, באמצעי אחסון ייעודי לתצורת Claude, בנתוני OmniRoute מבודדים
  ובאמצעי אחסון נפרד מסוג `devin-auth`;
- מעגנים רק סביבות עבודה/ראיות חד-פעמיות מסוג `.sandbox`;
- אינם מעגנים את תיקיית הבית של המארח, Keychain,‏ SSH, פרטי גישה לענן או את שקע Docker;
- בונים סביבות מפורשות ומסירים משתני API/OAuth/ניתוב של Anthropic;
- מפנים את ההסקה של Claude Code רק אל `http://omniroute:20128` באמצעות מפתח מקומי בלבד.

הפרופיל הלא-מקוון משתמש ברשת פנימית. בפרופיל החי, OmniRoute מגיע לנקודות הקצה
הרשמיות של Devin רק דרך `network-guard`; יעדים שאינם קשורים נדחים.
ל-Claude Code יש מגן תעבורה יוצאת נפרד שחוסם הכול, והוא יכול להגיע רק לשירות OmniRoute
המקומי דרך `NO_PROXY`. קובצי הביקורת של המגנים מעוגנים רק על ידי תהליך המגן שלהם.
הסקריפטים מאמתים בעלות על קבצים, מצב הרשאות, מספר קישורים וכל החלטה לפני ייצוא
ראיות נטולות אסימונים.

הריצו את הוכחת הבידוד באופן עצמאי:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

היא מאמתת טופולוגיה, עיגונים בעלי שם, הגדרות שאינן root/קריאה בלבד, ניתוב מקומי מפורש,
היעדר משתני סביבה רגישים, היעדר שקע Docker, חסימת גישה אל
`api.anthropic.com` ו-`claude.ai`, בחירת ספק Devin בלבד וכשל מפורש כאשר
קצה ה-ACP האחורי אינו זמין.

## הגדרה ראשונית ושימוש שוטף

בנו את האימג' המקובע:

```bash
./scripts/devin-bridge/build
```

בצעו אימות רק עבור ה-volume המבודד של Devin:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

פקודת ההתחברות משתמשת בתהליך הידני הרשמי באמצעות טוקן, המיועד לסביבות מרוחקות/קונטיינרים. הערך מוזן ישירות בהנחיית ה-CLI; הוא אינו מועבר כארגומנט לתהליך, נכתב ל-Git או מועתק מהמארח.

הפעילו את סביבת זמן הריצה המבודדת של Claude Code:

```bash
./scripts/devin-bridge/launch
```

`launch` בודקת מחדש את הבידוד, את האימות של Devin ואת גילוי המודלים לפני הפעלת Claude Code בתוך קונטיינר. היא לעולם אינה מפעילה את קובץ ההרצה של Claude במארח. ניתן להגדיר כינויי מודלים ב-`.env.devin-bridge`; כל ערך שמוגדר חייב לשמור על הקידומת `devin-cli-agentic/`.

## פקודות אימות

המסלול הלא-מקוון הניתן לשחזור אינו דורש חשבון Devin ואין בו גישה לאינטרנט בזמן ריצה:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

המסלול החי המאומת, המופעל באופן יזום, הוא:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

מריץ הבדיקות החיות ממתין בין תרחישים כדי להימנע מפתיחת הפעלות ACP ברצף מהיר, ומאמת אירועי זרם מובנים של Claude במקום להסתמך על טענות טקסטואליות. שלושת התרחישים שלו מוכיחים:

1. קריאה ישירה מהפרויקט וניתוח ליקויים;
2. פעולת `Edit` אמיתית, פקודת `Bash` מסוג `npm test` שבבעלות הלקוח ותוצאה סופית;
3. גילוי של `/bridge-check` ושל `bridge-proof`, קריאה מהפרויקט, הרצה מוצלחת נוספת של `npm test` שבבעלות הלקוח, והשלמה ללא עבודה ממתינה.

שער האימות הסופי בודק גם את ביקורת הרשת של Devin ודורש שביקורת תעבורת היציאה של Claude תישאר ריקה.

## עדכון כלים מקובעים

האימג' מקבע את Node, את Claude Code ואת Devin CLI בקובץ `docker/devin-bridge/Dockerfile`. כדי לעדכן:

1. שנו את הגרסאות המפורשות;
2. החליפו את שני סכומי הבדיקה של ארכיוני Devin, הספציפיים לכל ארכיטקטורה, בערכים המתאימים לארטיפקט הרשמי;
3. בנו מחדש והריצו כל פקודת אימות לא-מקוונת;
4. ודאו את הגרסאות בתוך האימג';
5. הריצו מחדש את חבילת שלושת התרחישים החיים והמאומתים.

אל תתקינו אף אחד מכלי ה-CLI באופן גלובלי במארח, ואל תחליפו את אימות סכום הבדיקה בהורדה שאינה מאומתת.

## אבחון וניקוי

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  מציגה ניתוב מקומי ושגיאות מבצע שעברו טיוב.
- `.sandbox/evidence/mock-acp.jsonl` מתעד פעולות ACP מדומות ודטרמיניסטיות.
- `.sandbox/evidence/claude-stream.jsonl` מתעד את ההרצה הלא-מקוונת האמיתית של Claude Code.
- `.sandbox/evidence/live-*.jsonl` מתעד את שלושת הזרמים החיים שאומתו.
- `.sandbox/evidence/egress.jsonl` ו-`.sandbox/evidence/claude-egress.jsonl` הם עותקים מאומתים ונקיים מטוקנים של ביקורות מנגנון ההגנה.

עצרו קונטיינרים ורשתות שבבעלות המערכת, תוך שימור volumes של התחברות/תצורה:

```bash
./scripts/devin-bridge/clean
```

הסירו את כל הסביבה שבבעלות הגשר, כולל volumes בעלי שם:

```bash
./scripts/devin-bridge/clean --all
```

## מגבלות

- הגשר מסתמך על תפקיד ה-`summarizer` הקבוע ללא כלים, משום ש-Devin CLI `3000.2.17`
  אינו חושף סוכן ACP ניטרלי ללא כלים. המתאם מפצה על תגובות ביניים
  בעלות מבנה של סיכום, אך גם ניסיון תיקון מוגבל יחיד עדיין עלול להיכשל באופן מפורש.
- קריאות ACP חיות עשויות להחזיר תגובות `502`/`504` זמניות. רתמת הבדיקה מרווחת בין תרחישים;
  כשל מתמשך עדיין מטופל בגישת fail-closed ולעולם אינו גורם לבחירת ספק אחר.
- ההקשר של ACP נבנה מחדש מכל בקשת Anthropic; אין שיוך
  לתהליך/הפעלה.
- נתמכת קריאת כלי אחת לכל תגובת מודל; קריאות מקבילות נדחות.
- תמונות אינן נתמכות במפורש. יכולות ראייה, פלט חשיבה, בקרות מאמץ וחלון הקשר של 1M
  אינם מוצגים כנתמכים.
- SSE משתמש באירועי מחזור חיים תקינים של Anthropic, אך נפלט לאחר השלמת איסוף סבב ה-ACP
  המוגבל; מקטעי ACP אינם מועברים באופן הדרגתי.
