> **מקור האמת:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/`, וכן
> `src/app/(dashboard)/dashboard/plugins/`
> **עדכון אחרון:** 2026-06-28 — v3.8.40

OmniRoute מגיעה עם מערכת תוספים בסגנון WordPress. תוספים הם תיקיות עצמאיות —
כל אחת כוללת מניפסט `plugin.json` וקובץ כניסה — שמתחברות לצינור עיבוד הבקשות
(`onRequest` / `onResponse` / `onError`) ולאירועי מחזור החיים
(`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`).

**שוק התוספים** הוא שכבת הגילוי שנבנתה מעל מערכת זו. הוא מציג קטלוג שניתן
לעיין בו של תוספים זמינים להתקנה. כברירת מחדל, הקטלוג הוא מאגר אתחול מובנה
וקטן; מפעיל יכול להפנות אותו לכתובת URL של מאגר מרוחק מותאם אישית, ובמקרה
זה השליפה מוקשחת באמצעות מנגנון הגנה מפני SSRF שמבצע פתרון DNS
(ראו [אבטחה](#security)).

כל נתיבי התוספים הם **ל-loopback בלבד** (רמה 1 — `LOCAL_ONLY`): תוספים
טוענים ומריצים קוד בתהליכי צאצא, ולכן הנתיבים אינם נגישים ממקור שאינו
loopback, ללא קשר לאימות. ראו
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md).

## כיצד הכול משתלב

```
לוח הבקרה (/dashboard/plugins)
  ├─ הלשונית "מותקנים"  → GET /api/plugins            (listPlugins)
  │                        POST /api/plugins/scan      (pluginManager.scan)
  │                        POST /api/plugins/{name}/activate|deactivate
  │                        DELETE /api/plugins/{name}   (הסרה)
  └─ הלשונית "שוק"       → GET /api/plugins/marketplace
                             → listMarketplacePlugins()
                               ├─ ללא URL מותאם אישית → SEED_REGISTRY מובנה
                               └─ URL מותאם אישית → מנגנון הגנת SSRF מסוג isSafeMarketplaceUrl()
                                                   → safeOutboundFetch(guard:"public-only")
```

- **שכבת המאגר** — `src/lib/plugins/marketplace.ts`: מציגה את הקטלוג / מחפשת
  בו, וחוזרת למאגר האתחול במקרה של כשל כלשהו.
- **שכבת מחזור החיים** — `src/lib/plugins/manager.ts` (מופע יחיד של
  `pluginManager`): התקנה, שדרוג, הפעלה, השבתה, הסרה, סריקה וטעינה בעת ההפעלה.
- **שכבת המניפסט** — `src/lib/plugins/manifest.ts`: סכמת Zod + ערכי ברירת מחדל
  עבור `plugin.json`.
- **סורק** — `src/lib/plugins/scanner.ts`: מגלה תוספים בדיסק תחת תיקיית
  התוספים.
- **טוען** — `src/lib/plugins/loader.ts`: יוצר עבור כל תוסף תהליך צאצא מבודד
  ומתווך קריאות hook באמצעות IPC.

## קטלוג השוק

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) מחזירה רשימה של
אובייקטי `MarketplaceEntry`:

| שדה           | סוג      | הערות                                     |
| ------------- | -------- | ----------------------------------------- |
| `name`        | string   | שם התוסף בתבנית kebab-case                |
| `version`     | string   | semver                                    |
| `description` | string   | תיאור קצר                                 |
| `author`      | string   | מחבר / ארגון                              |
| `license`     | string   | מזהה רישיון בסגנון SPDX                   |
| `downloadUrl` | string   | כתובת URL להורדת המקור (עשויה להיות ריקה) |
| `repository`  | string?  | כתובת URL אופציונלית של המאגר             |
| `tags`        | string[] | תגיות לחיפוש/סינון                        |
| `downloads`   | number   | מספר הורדות                               |
| `rating`      | number   | 0–5                                       |
| `verified`    | boolean  | האם הרשומה מסומנת כמאומתת                 |
| `lastUpdated` | string   | מחרוזת תאריך דמוית ISO                    |

כאשר לא מוגדרת כתובת URL של מאגר מותאם אישית, הקטלוג הוא `SEED_REGISTRY`
המובנה (כיום `request-logger`, `rate-limiter`, `cost-tracker` ו-
`theme-manager`). מאגר האתחול זמין תמיד — אם מאגר מרוחק מוגדר אינו נגיש,
מחזיר סטטוס שאינו `200`, או מחזיר גוף שאינו מזוהה, `listMarketplacePlugins()`
רושמת אזהרה וחוזרת לרשימת האתחול.

> הערה: **קטלוג** השוק (עיון/חיפוש) מחובר מקצה לקצה, אך **התקנה** בלחיצה אחת
> מתוך הקטלוג עדיין אינה ממומשת — הכפתור "התקנה" בלוח הבקרה עבור רשומה בשוק
> מציג כרגע הודעת "בקרוב". כיום ההתקנה מתבצעת באמצעות תהליך ההתקנה מנתיב מקומי
> (`POST /api/plugins`) וגילוי בדיסק (`POST /api/plugins/scan`).

## API מסוג REST

כל נקודות הקצה דורשות אימות ניהולי (`requireManagementAuth`) **וגם**
מוגבלות ל-loopback בלבד — הנתיבים `/api/plugins` ו-`/api/plugins/` מופיעים
ב-`LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`).

| נקודת קצה                        | שיטה   | תיאור                                             |
| -------------------------------- | ------ | ------------------------------------------------- |
| `/api/plugins`                   | GET    | הצגת התוספים המותקנים (מסנן `?status=` אופציונלי) |
| `/api/plugins`                   | POST   | התקנת תוסף מנתיב מקומי מוחלט                      |
| `/api/plugins/scan`              | POST   | סריקת ספריית התוספים ורישום תוספים חדשים          |
| `/api/plugins/marketplace`       | GET    | הצגת רשומות קטלוג זירת התוספים                    |
| `/api/plugins/[name]`            | GET    | קבלת פרטי תוסף מותקן                              |
| `/api/plugins/[name]`            | DELETE | הסרת התקנה של תוסף                                |
| `/api/plugins/[name]/activate`   | POST   | הפעלה (טעינה + רישום hooks)                       |
| `/api/plugins/[name]/deactivate` | POST   | השבתה (הפעלת `onDeactivate`, ביטול רישום hooks)   |
| `/api/plugins/[name]/config`     | GET    | קבלת תצורת התוסף + סכמת התצורה                    |
| `/api/plugins/[name]/config`     | PUT    | עדכון תצורת התוסף (עם אימות מול הסכמה)            |

המסנן `status` של `GET /api/plugins` מקבל אחד מהערכים
`installed` / `active` / `inactive` / `error`. ערך לא חוקי מחזיר `400`.

### הצגת התוספים המותקנים

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### התקנה מנתיב מקומי

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

הנתיב `path` חייב להיות **מוחלט**, ואסור שיכיל מקטעי מעבר `..` או
בתי null (נאכף באמצעות Zod). ספריית המקור חייבת להכיל קובץ
`plugin.json` חוקי (או להיות ספריית אב של ספרייה המכילה אותו). במקרה של הצלחה, התגובה היא `201` עם
רשומת התוסף שהותקן.

### עיון בזירת התוספים

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### עדכון תצורת תוסף

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

הנתיב `PUT .../config` מאמת כל ערך שסופק מול
`configSchema` של התוסף (המוצהרת במניפסט): שדות `number` מכבדים את `min`/`max`,
ושדות `select` חייבים להתאים ל-`enum` המוצהר. מפתחות שאינם קיימים בסכמה
מורשים לעבור.

## הגדרות

### ספריית התוספים

התוספים נמצאים תחת ספריית הנתונים של OmniRoute:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (או כל קובץ אחר שאליו manifest.main מצביע)
```

הפונקציה `getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) פותרת את מיקום הספרייה
בשלושה שלבים:

1. **`OMNIROUTE_PLUGINS_DIR`**, כאשר הוא מוגדר — נעשה בו שימוש כפי שהוא, ללא תלות בערך של `HOME`. זהו
   המנגנון המפורש עבור Docker/K8s, שבהם עץ התוספים ממופה באמצעות bind mount לנתיב
   שבדרך כלל אינו קשור כלל לספריית הבית של הקונטיינר (#11827).
2. `<home>/.omniroute/plugins`, כאשר `<home>` מגיע ממשתני הסביבה `HOME` / `USERPROFILE`.
3. `/tmp/.omniroute/plugins`, כאשר התהליך אינו מייצא ספריית בית כלל.

הספרייה שנפתרה נרשמת פעם אחת ביומן בעת האתחול בתור `scanner.dir_resolved`, תוך ציון
הקלט שנבחר (`OMNIROUTE_PLUGINS_DIR`, `home` או `no-home-fallback`) — כך ש-image
שמגיע בשקט לשלב 3 מציין זאת, במקום לדווח רק על רשימת תוספים ריקה.
`POST /api/plugins/scan` מגלה כל תת-ספרייה שם שמכילה
`plugin.json` חוקי ורושם אותה; אותה ספרייה היא גם השורש שאליו
`pluginManager.install()` מעתיק תוספים, כך שדריסה מעבירה יחד את מנגנוני הגילוי
וההתקנה.

> **`OMNIROUTE_PLUGINS_DIR` אינו `OMNIROUTE_PLUGIN_PATH`.** האחרון נקרא רק על ידי
> טוען תוספי הפקודות של ה-CLI (`bin/cli/plugins.mjs`) כדי למצוא חבילות npm מסוג `omniroute-cmd-*`
> שמוסיפות פקודות משנה ל-`omniroute` — אין לו כל השפעה על סורק זמן הריצה
> המתואר כאן. ראו [PLUGINS.md](./PLUGINS.md) למידע על צד זה.

### כתובת URL מותאמת אישית של רישום זירת התוספים

מקור הקטלוג של זירת התוספים נקרא מההגדרה `pluginMarketplaceUrl`
(`src/lib/plugins/marketplace.ts` קורא את `settings.pluginMarketplaceUrl`). כאשר
היא מוגדרת לכתובת URL מסוג `http(s)`, הפונקציה `listMarketplacePlugins()` מושכת את הכתובת ומקבלת
מערך JSON של רשומות ברמה העליונה או אובייקט עם מערך `plugins`;
רשומות ללא `name` מסוג מחרוזת מסוננות החוצה. כאשר ההגדרה אינה מוגדרת (או כאשר השליפה
נכשלת בבדיקת ה-SSRF / מחזירה תגובה לא תקינה), נעשה שימוש ברישום הבסיס
המובנה.

הלשונית "זירת התוספים" בלוח הבקרה מציגה שדה עבור כתובת URL זו (שנקראת בחזרה דרך
`GET /api/settings`).

> הערת מימוש: פעולת "שמירה" בלוח הבקרה שולחת את
> `pluginMarketplaceUrl` אל `PATCH /api/settings`. נכון למועד הכתיבה,
> מפתח זה אינו מוצהר ב-`updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`), לכן יש לוודא שהשמירה המתמשכת פועלת בגרסה שלכם
> לפני שמסתמכים עליה — נתיב ה**קריאה** (`getSettings()` ←
> `listMarketplacePlugins()`) מכבד את המפתח לאחר שהוא קיים במאגר
> ההגדרות.

## אבטחה

### רמת נתיב — לולאה מקומית בלבד

תוספים מריצים קוד בתהליכי־צאצא שנוצרים בנפרד, ולכן כל הממשק `/api/plugins`
מסווג כ־`LOCAL_ONLY` (רמה 1). אכיפת הלולאה המקומית מתבצעת
ללא תנאי **לפני** כל בדיקת אימות, כך שגם אסימון ניהול שדלף ומגיע
למכונה דרך מנהרה עדיין אינו יכול להתקין, להפעיל או להסיר תוסף.
ראו [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) וכן
כללים קשיחים מס' 15 / מס' 17.

### הגנת SSRF עבור מאגר ה־Marketplace

כתובת URL מותאמת אישית של מאגר היא הגדרה שתוקף יכול להשפיע עליה, ולכן לפני
שליפתה `listMarketplacePlugins()` מעבירה אותה דרך שתי שכבות:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - דוחה כל דבר שאינו `http:` / `https:`.
   - דוחה מארחים מפורשים מסוג פרטי/לולאה מקומית/link-local/ULA ‏(IPv4 **וגם** IPv6,
     לרבות IPv4 ממופה) באמצעות `isPrivateHost` הקנוני
     (`src/shared/network/outboundUrlGuard.ts`).
   - פותר רשומות `A` **וגם** `AAAA`, ודוחה אם כתובת **כלשהי** שהתקבלה
     היא פרטית — ובכך סוגר את המעקף של שם מארח ציבורי → כתובת IP פרטית.
   - **נכשל באופן סגור**: כשל בפתרון DNS גורם לדחיית כתובת ה־URL.
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`**
   (`src/shared/network/safeOutboundFetch.ts`): מחיל מחדש בזמן השליפה את הגנת כתובות ה־URL
   המוגבלת לכתובות ציבוריות, ו**חוסם הפניות מחדש** (ללא ציר `30x`
   מציבורי → פרטי).

כתובת URL שנכשלת באחת מהשכבות אינה מבטלת את הבקשה — ה־Marketplace
חוזר בשקט למאגר האתחול המובנה ורושם אזהרה ביומן.

> הגנה זו חוזקה ב־PR #3774 במיוחד כדי לפתור רשומות A + AAAA ולהשתמש
> ב־`isPrivateHost` הקנוני במקום בבדיקה המוגבלת ל־IPv4 בלבד.

### בידוד הרצת תוספים

- **בידוד תהליכים** — `loadPlugin()` (`src/lib/plugins/loader.ts`) מפעילה
  כל תוסף בתהליך־צאצא נפרד של Node.js ומתקשרת באמצעות IPC.
  לקריאות hook יש זמן קצוב, עם הסלמה מ־`SIGTERM` ל־`SIGKILL`.
- **רשימת היתרים למשתני סביבה** — תהליך־הצאצא מקבל רק קבוצה מאושרת של משתני
  סביבה; הקבוצה הרחבה יותר ניתנת רק כאשר המניפסט מבקש את ההרשאה
  `env`.
- **הגבלת נתיבים** — התקנה/שדרוג/הסרה מוודאים שתיקיית התוסף
  ו־`manifest.main` נפתרים לנתיב שנמצא **בתוך** שורש התוספים המנוהל,
  לפני כל העתקה או מחיקה רקורסיבית (הגנה מפני נתיבי מסד נתונים ששונו בזדון ומפני
  חציית `../` בתוך `manifest.main`). ההפעלה פותרת קישורים סמליים באמצעות
  `realpath` ומסרבת לטעון נקודת כניסה שחורגת מתיקיית
  התוסף.
- **קיבוע תקינות אופציונלי** — מניפסט יכול להצהיר על שדה `integrity`
  (`sha256-<base64>`, בתבנית SRI). כאשר השדה קיים, הטוען מאמת את גיבוב
  קובץ הכניסה בזמן הטעינה ומסרב להפעיל במקרה של אי־התאמה. זהו
  מנגנון אופציונלי לזיהוי שינויים, **לא** גבול אבטחה — ניתוב המוגבל ללולאה מקומית
  ומודל ההרשאות הם הגבולות האמיתיים.

| `requires`         | object?   | `{ omniroute?, permissions[] }`                            |
| `hooks`            | object?   | ערכים בוליאניים המצהירים אילו hooks התוסף מממש             |
| `skills`           | object[]? | הגדרות מיומנויות אופציונליות                               |

ההרשאות נלקחות מה־enum
`network` / `file-read` / `file-write` / `env` / `exec`.

## זרימת מחזור החיים

```
התקנה (POST /api/plugins, נתיב)
  → סריקה/אימות של המניפסט → העתקה לאזור ההיערכות → וידוא שהקובץ הראשי נמצא בתוך התיקייה
  → שינוי שם אטומי אל ~/.omniroute/plugins/<name> → הוספת רשומה למסד הנתונים
  → הפעלת onInstall → אם enabledByDefault: הפעלה

הפעלה (POST /api/plugins/{name}/activate)
  → בדיקת הכלה באמצעות realpath → loadPlugin() (יצירת תהליך בן)
  → רישום ה-hooks המוצהרים → status = "active" → הפעלת onActivate

השבתה (POST /api/plugins/{name}/deactivate)
  → הפעלת onDeactivate (לפני ביטול הרישום) → ביטול רישום ה-hooks
  → סיום תהליך הבן → status = "inactive"

הסרת התקנה (DELETE /api/plugins/{name})
  → השבתה אם פעיל → הפעלת onUninstall
  → מחיקה רקורסיבית של תיקיית התוסף לאחר בדיקת הכלה → מחיקת הרשומה ממסד הנתונים
```

הרצה מחדש של `install` על תיקייה שגרסת המניפסט שלה **חדשה יותר באופן מוחלט**
מהגרסה המותקנת מבצעת שדרוג אוטומטי (התקנה מחדש ונקייה; התצורה מתאפסת
לערכי ברירת המחדל). גרסה זהה או ישנה יותר נדחית.

## לוח הבקרה

דף לוח הבקרה ב-`/dashboard/plugins`
‏(`src/app/(dashboard)/dashboard/plugins/page.tsx`) מספק שתי כרטיסיות:

- **מותקנים** — מציגה את התוספים המותקנים עם ה-hooks המוצהרים שלהם, מתג
  הפעלה/השבתה, כפתור הסרת התקנה ופעולת "סריקת תוספים"
  (`POST /api/plugins/scan`).
- **זירת התוספים** — מציגה את הקטלוג מ-`GET /api/plugins/marketplace` עם
  שדה להגדרת כתובת URL מותאמת אישית של מאגר הרישום.

דף תצורה ייעודי לכל תוסף נמצא ב-`/dashboard/plugins/[name]/config`
‏(`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`).
