## מה זה

Local Corpus מאפשר למפעיל לחשוף לסביבת MCP של OmniRoute ספרייה אחת של קובצי טקסט שאושרה במפורש.
הקבצים נשארים בספרייה המקורית שלהם: OmniRoute שומר ב-SQLite רק את נתיב השורש הקנוני ומתחזק אינדקס חיפוש בזיכרון. הוא אינו מעתיק את תוכן הקורפוס למאגר או למסד הנתונים.

רענון האינדקס מתבצע באופן מצטבר. נעשה שימוש חוזר בקבצים שלא השתנו על סמך הגודל וזמן השינוי, קבצים שהשתנו נקראים מחדש ומגובבים באמצעות SHA-256, וקבצים שנמחקו מוסרים.
בעת חיפוש, אינדקס שגילו עולה על 30 שניות מרוענן; גורמים קוראים יכולים גם לבקש רענון מיידי.

## הגדרת המקור

נתיב ההגדרות דורש את אותו אימות ניהולי כמו ממשקי API אחרים של הגדרות.
הנתיב שנשלח חייב להיות קיים ולהיות נתיב מוחלט של ספרייה.

```bash
# חיבור ספרייה מאושרת
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# בדיקת התצורה ומצב האינדקס
curl http://localhost:20128/api/settings/local-corpus

# ניתוק ללא שינוי קובצי המקור
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## כלי MCP

כל שלושת הכלים דורשים `read:local-corpus`. תגובות הכלים חושפות נתיבים יחסיים ואת שם הבסיס של ספריית השורש, ולעולם לא את הנתיב המוחלט שלה.

| כלי                   | תיאור                                                                      |
| :-------------------- | :------------------------------------------------------------------------- |
| `local_corpus_status` | דיווח על מצב התצורה, גודל האינדקס, המגבלות ומועד הרענון האחרון             |
| `local_corpus_search` | חיפוש בטקסט המאונדקס והחזרת קטעים מוגבלים לפי שורות (עד 20 תוצאות)         |
| `local_corpus_read`   | קריאת טווח שורות מוגבל מקובץ אחד שמותר לגשת אליו באמצעות נתיב יחסי לקורפוס |

דוגמאות לקלט MCP:

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## גבולות בטיחות

- רשימת ההיתרים מיועדת לקובצי טקסט: `.cfg`, `.csv`, `.geojson`, `.htm`, `.html`, `.ini`,
  `.js`, `.json`, `.jsonl`, `.jsx`, `.log`, `.md`, `.mjs`, `.ps1`, `.py`, `.sh`,
  `.sql`, `.toml`, `.ts`, `.tsx`, `.txt`, `.xml`, `.yaml`, ו-`.yml`.
- המערכת מדלגת על קישורים סמליים. נתיבי קריאה עוברים קנוניזציה וחייבים להישאר בתוך
  השורש המוגדר; נתיבים מוחלטים וניסיונות מעבר מחוץ לספרייה נדחים.
- שמות של ספריות רגישות ונוצרות מוחרגים: `.build`, `.codex`, `.env`,
  `.git`, `.next`, `.omniroute`, `.ssh`, `coverage`, `dist`, `node_modules`, ו-
  `secrets`.
- מגבלות ברירת המחדל הן 5,000 קבצים, 1 MiB לכל קובץ, 64 MiB של תוכן מאונדקס בסך הכול,
  כ-4,000 תווים לכל מקטע חיפוש ו-400 שורות לכל קריאה.
- קבצים המכילים NUL נחשבים לקבצים שאינם טקסט, והמערכת מדלגת עליהם או דוחה אותם.

מסמכים בינאריים כגון PDF, DOCX, תמונות וארכיונים אינם נתמכים במכוון.
לפני האינדוקס, יש להמיר אותם לפורמט טקסט מאושר בתוך הספרייה המוגדרת.

## הערות תפעוליות

- שינוי או מחיקה של השורש המוגדר מנקים את האינדקס המשותף שבזיכרון.
- הפעלה מחדש של התהליך מוחקת את האינדקס; החיפוש הבא בונה אותו מחדש מהמקור המוגדר.
- `local_corpus_status` אינו כופה סריקה. כאשר נדרשת סריקה מיידית מחדש, יש להשתמש ב-`local_corpus_search` עם
  `refresh: true`.
- כשלי סריקה וקריאה נספרים או מוחזרים כשגיאות שעברו טיהור; קובצי המקור לעולם אינם משתנים.
