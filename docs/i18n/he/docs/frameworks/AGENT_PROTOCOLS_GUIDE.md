> **מקור:** `src/lib/{a2a,acp,cloudAgent}/`, `src/app/api/{a2a,acp,cloud}/`, `src/app/api/v1/agents/`
> **עדכון אחרון:** 2026-06-28 — v3.8.40

OmniRoute חושף שלושה ממשקים שונים הקשורים לסוכנים. במבט ראשון הם נראים דומים, אך הם פותרים בעיות שונות. השתמשו בדף זה כדי לבחור את הממשק המתאים.

## בקצרה

| ממשק                     | מתאים במיוחד עבור                                                                                                       | תעבורה                                | תקן                  |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------- | -------------------- |
| **A2A — סוכן-לסוכן**     | שיתוף פעולה בין סוכנים עם סוכנים עמיתים שתומכים בפרוטוקול A2A                                                           | JSON-RPC 2.0 מעל HTTP                 | A2A v0.3 (מפרט פתוח) |
| **ACP — מרשם סוכני CLI** | זיהוי / רישום / הפעלה של סוכני תכנות מסוג CLI המותקנים במחשב המשתמש (Cursor, Cline, Codex CLI, Claude Code, Aider וכו׳) | HTTP REST                             | ייחודי ל-OmniRoute   |
| **סוכני ענן**            | שליחת משימות תכנות ממושכות לשירותי ענן חיצוניים (Codex Cloud, Devin, Jules, Cursor Cloud)                               | HTTP REST + משימות מגובות במסד נתונים | ייחודי ל-OmniRoute   |

שלושת הממשקים בלתי תלויים זה בזה — ניתן לבחור כל תת-קבוצה שלהם.

## עץ החלטה

```
האם אתם זקוקים לשירות ענן שיבצע עבודה מחוץ למחשב זה (Codex Cloud / Cursor Cloud / Devin / Jules)?
├─ כן → סוכני ענן (POST /api/v1/agents/tasks)
└─ לא → המשיכו
    │
    האם יש לכם סוכן עמית שתומך ב-A2A ומעוניין לשתף פעולה?
    ├─ כן → A2A (POST /a2a)
    └─ לא → המשיכו
        │
        האם עליכם להציג / להגדיר סוכני תכנות מסוג CLI המותקנים מקומית?
        ├─ כן → ACP (GET /api/acp/agents)
        └─ לא → השתמשו ב-/v1/chat/completions הרגיל
```

## 1. A2A — סוכן-לסוכן

**מפרט:** [A2A v0.3](https://a2a-protocol.org)
**נקודת הקצה של OmniRoute:** `POST /a2a` (JSON-RPC 2.0)
**כרטיס סוכן:** `GET /.well-known/agent.json`

### מתי להשתמש

- בעת בניית מערכת מרובת סוכנים שבה OmniRoute הוא אחד מהעמיתים
- בעת חשיפת יכולות הניתוב החכמות של OmniRoute (`smart-routing`, `quota-management` וכו׳) לסוכנים במסגרות כמו Google ADK או ברשתות סוכנים כלליות
- בעת עטיפת OmniRoute מאחורי ממשק תקני לגילוי ולהפעלה

### שיטות

- `message/send` — שליחת הודעה וקבלת תגובה סינכרונית
- `message/stream` — שליחה וקבלת אירועי התקדמות בהזרמה באמצעות SSE
- `tasks/get` — קריאת משימה לפי מזהה
- `tasks/cancel` — ביטול משימה פעילה

### יכולות מובנות (6)

- `smart-routing` — ניתוב הנחיה דרך השילוב המיטבי
- `quota-management` — דיווח על מצב המכסה של כל ספק
- `provider-discovery` — הצגת הספקים המותקנים והיכולות שלהם
- `cost-analysis` — הערכת העלות של בקשה/שיחה
- `health-report` — צבירת מצב מפסק המעגל/תקופת הצינון/הנעילה של כל ספק
- `list-capabilities` — פירוט היכולות הזמינות של הסוכן והמטא-נתונים שלהן

### צלילה לעומק

ראו [A2A-SERVER.md](./A2A-SERVER.md) לפרטים על התעבורה, מבנה כרטיס הסוכן, הגדרת TTL למשימות והתבנית להוספת יכולות חדשות.

## 2. ACP — מרשם סוכני CLI

**נקודת הקצה של OmniRoute:** `GET /api/acp/agents`
**מקור:** `src/lib/acp/{index,manager,registry}.ts`

### מה זה

ACP הוא **מלאי סוכני ה-CLI המקומיים** של OmniRoute. הוא מזהה אילו כלי CLI לתכנות מותקנים במארח (Cursor, Cline, Claude Code, Codex CLI, Continue וכו׳), מאתר את הגרסאות שלהם ומציג אותם בלוח המחוונים, כדי שהמשתמש יוכל להגדיר כל CLI כך שיפנה אל OmniRoute.

זהו אינו פרוטוקול חיצוני — זהו מרשם פנימי שמפעיל את ממשק המשתמש „CLI Tools” ואת מעקב טביעות האצבע של כלי CLI (ראו [CLI-TOOLS.md](../reference/CLI-TOOLS.md)).

### מה הוא עושה

- סורק את המארח לאיתור קובצי CLI בינאריים מותקנים (משתמש ב-`which` / `where` בהתאם למערכת ההפעלה)
- קורא את הגרסה של כל CLI (מריץ `<bin> --version`)
- מאפשר, באופן אופציונלי, סוכנים מותאמים אישית שהוגדרו על ידי המשתמש (נתיב לקובץ בינארי + בדיקת גרסה + ארגומנטים להפעלה)
- שומר סוכנים מותאמים אישית בהגדרות
- מחזיר ללוח המחוונים את הרשימה המאוחדת

### REST API

| נקודת קצה         | שיטה | תיאור                                                         | אימות    |
| ----------------- | ---- | ------------------------------------------------------------- | -------- |
| `/api/acp/agents` | GET  | הצגת סוכנים שזוהו + סוכנים מותאמים אישית (מספר מותקנים/כולל)  | מפתח API |
| `/api/acp/agents` | POST | הוספה/עדכון/הסרה של סוכן מותאם אישית (מבחין פעולה בגוף הבקשה) | מפתח API |

מבנה גוף הבקשה עבור POST (`customAgentBodySchema` בקובץ `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### תרחישי שימוש

- הדף „CLI Tools” בלוח המחוונים מציג מה מותקן ומסייע להפנות כל כלי אל OmniRoute
- סוכנים מותאמים אישית מאפשרים למשתמשים מתקדמים לרשום כלי CLI פנימיים/קנייניים ש-OmniRoute אינו מכיר כברירת מחדל
- תוצאת הזיהוי מזינה את מטריצת טביעות האצבע `cli-tools`

### מתי לא להשתמש ב-ACP

- ACP אינו _מריץ_ משימות. הוא רק מזהה ומגדיר כלי CLI. כדי להפעיל CLI בפועל, יש להפעיל אותו עצמאית באמצעות משתני הסביבה שמספק OmniRoute (`OPENAI_BASE_URL`, `OPENAI_API_KEY` וכו׳).

## 3. סוכני ענן

**נקודות הקצה של OmniRoute:** `/api/v1/agents/tasks/*` (מחזור חיים) + `/api/cloud/*` (תשתית)
**מקור:** `src/lib/cloudAgent/`

### מה זה

ממשק אחיד מעל סוכני תכנות בענן של צדדים שלישיים. שולחים הנחיה + כתובת URL של מאגר, OmniRoute מעביר אותם לסוכן הענן המתאים, בודק את הסטטוס ומחזיר תוצאות.

### סוכנים נתמכים (3, כולם מאומתים ב-`src/lib/cloudAgent/agents/`)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### מחזור חיים

```
POST /api/v1/agents/tasks
  → BaseAgent.createTask() לפי מחלקת הסוכן
  → השירות החיצוני מתחיל לעבוד
  → רשומת משימה נוצרת במסד הנתונים (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → סנכרון סטטוס עצל מהספק
  → מחזיר את הסטטוס הנוכחי + תוכנית + יומן פעילות
  ↓
POST /api/v1/agents/tasks/[id]   (action: "approve" | "message" | "cancel")
  → מועבר לספק (או מסומן כמבוטל באופן מקומי)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → ביטול מקומי
```

### אימות

⚠️ **כל נקודות הקצה `/api/v1/agents/tasks/*` דורשות אימות ניהולי** (קומיט `588a0333`). פונים המשתמשים ב-Bearer בלבד מקבלים 401 החל מ-v3.8.0.

### העמקה

ראו [CLOUD_AGENT.md](./CLOUD_AGENT.md) לפרטים על החוזה `CloudAgentBase`, המאפיינים הייחודיים לכל סוכן, פרטי הסכמה ונקודות הקצה של תשתית פרטי ההזדהות.

## השוואה: A2A לעומת סוכני ענן

לשניהם יש "משימות ארוכות־טווח", אך בשכבות שונות:

| היבט              | A2A                                                                                      | סוכני ענן                           |
| ----------------- | ---------------------------------------------------------------------------------------- | ----------------------------------- |
| תקן               | Open A2A v0.3                                                                            | ייעודי ל-OmniRoute                  |
| היכן מתבצע החישוב | בתוך OmniRoute (משתמש בשילובים שהוגדרו)                                                  | חיצוני (שרתי Codex / Devin / Jules) |
| משך המשימה        | TTL ברירת מחדל של 5 דקות (ניתן להגדרה ב-`TaskManager`)                                   | דקות עד שעות                        |
| מודעות למאגר      | לא (מעביר הנחיות בלבד)                                                                   | כן (כתובת URL של המאגר + ענף)       |
| תרחיש שימוש       | שיתוף פעולה בין סוכנים, ניתוב חכם כשירות                                                 | האצלת "ממש את תכונה X במאגר Y"      |
| אימות             | `OMNIROUTE_API_KEY` אופציונלי עבור `/a2a`; אימות ניהולי עבור מסייעי REST של `/api/a2a/*` | תמיד אימות ניהולי                   |

## דוגמאות לשילוב

### גילוי יכולות ה-A2A של OmniRoute

```bash
curl http://localhost:20128/.well-known/agent.json
```

מחזיר את כרטיס הסוכן עם כל 6 המיומנויות, אמצעי התעבורה והגרסה.

### קריאה ל-OmniRoute כסוכן A2A

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "נתב את ההנחיה הזו"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### הצגת סוכני CLI מותקנים באמצעות ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### הוספת סוכן CLI מותאם אישית

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "ה-CLI המותאם אישית שלי",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### שליחת משימה לסוכן ענן

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "ממש את תכונה X במאגר Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### בדיקה מחזורית של מצב משימת הענן

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## מתי להשתמש במה

- **ממשק צ'אטבוט / טייס־משנה** → `/v1/chat/completions` (תואם OpenAI — אינו פרוטוקול סוכנים)
- **שיתוף פעולה בין מספר סוכנים** → A2A
- **הצגת ממשקי CLI מקומיים בלוח הבקרה** → ACP
- **האצלת משימות תכנות ארוכות־טווח לשירותי ענן** → סוכני ענן
