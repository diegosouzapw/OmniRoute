## 1. מחסנית טכנולוגית

| תחום            | בחירה                                                                                                                          |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| מסגרת ווב       | **Next.js 16** ‏(App Router, פלט עצמאי, ללא middleware גלובלי)                                                                 |
| שפה             | **TypeScript 6.0+** — יעד `ES2022`,‏ `module: esnext`,‏ `moduleResolution: bundler`,‏ `strict: false`                          |
| זמן ריצה        | **Node.js** `>=22.22.2 <23` או `>=24.0.0 <27` (נאכף באמצעות `engines` + `SUPPORTED_NODE_RANGE`)                                |
| מסד נתונים      | **SQLite** באמצעות `better-sqlite3` (מופע יחיד, רישום WAL)                                                                     |
| שולחן עבודה     | **Electron 41** + `electron-builder` 26.10 (סביבת עבודה נפרדת תחת `electron/`)                                                 |
| בדיקות          | **מריץ הבדיקות המובנה של Node** (יחידה/אינטגרציה), **Vitest** ‏(MCP,‏ autoCombo, מטמון), **Playwright** ‏(e2e + protocols-e2e) |
| בנייה           | Next.js עצמאי באמצעות `scripts/build/build-next-isolated.mjs`                                                                  |
| ניתוח קוד/עיצוב | תצורה שטוחה של ESLint + ‏Prettier ‏(`lint-staged` באמצעות Husky לפני commit)                                                   |
| מערכת מודולים   | ESM בכל מקום (`"type": "module"`)                                                                                              |
| סביבות עבודה    | סביבת עבודה של npm — ‏`open-sse` היא סביבת העבודה המשנית היחידה                                                                |

כינויי נתיבים (`tsconfig.json`):

- `@/*` → `src/*`
- `@omniroute/open-sse` → `open-sse/index.ts`
- `@omniroute/open-sse/*` → `open-sse/*`

יציאת HTTP כברירת מחדל: **`20128`** (ה-API ולוח הבקרה חולקים את אותו תהליך). תיקיית
הנתונים מוגדרת באמצעות משתנה הסביבה `DATA_DIR`, וברירת המחדל שלה היא `~/.omniroute/`.

### 3.1 `src/app/` — App Router

ה-App Router חושף הן את ממשק המשתמש של לוח הבקרה והן את ה-HTTP API הציבורי/לניהול.
**אין middleware גלובלי** — היירוט מתבצע עבור כל נתיב בנפרד.

המקטעים ברמה העליונה תחת `src/app/`:

| נתיב                                                                          | מטרה                                                    |
| ----------------------------------------------------------------------------- | ------------------------------------------------------- |
| `api/`                                                                        | כל נתיבי ה-HTTP API (ראו פירוט להלן)                    |
| `a2a/`                                                                        | נקודת קצה של A2A JSON-RPC 2.0 (`POST /a2a`)             |
| `.well-known/agent.json/`                                                     | מסמך גילוי Agent Card של A2A                            |
| `(dashboard)/`                                                                | ממשק המשתמש של לוח הבקרה (קבוצת נתיבים, ללא קידומת URL) |
| `auth/`, `login/`, `forgot-password/`, `callback/`                            | תהליכי אימות                                            |
| `landing/`                                                                    | דף שיווק/נחיתה                                          |
| `docs/`                                                                       | מציג תיעוד API מוטמע                                    |
| `status/`, `maintenance/`, `offline/`                                         | דפי תפעול                                               |
| `privacy/`, `terms/`                                                          | דפים משפטיים                                            |
| `400/`, `401/`, `403/`, `408/`, `429/`, `500/`, `502/`, `503/`                | דפי שגיאה סטטיים                                        |
| `error.tsx`, `global-error.tsx`, `not-found.tsx`, `forbidden/`, `loading.tsx` | גבולות שגיאה/טעינה של ה-framework                       |
| `layout.tsx`, `page.tsx`, `globals.css`, `manifest.ts`                        | מעטפת הבסיס                                             |

#### 3.1.2a `src/app/api/services/` — ניהול שירותים מוטמעים

נתיבים להתקנה, להפעלה, לעצירה ולניטור של 9Router ושל CLIProxyAPI.
כל הנתיבים מסווגים כ-**LOCAL_ONLY** (לולאת משוב בלבד, כלל קשיח #17), מכיוון שהם
יכולים להפעיל את `npm install` וליצור תהליכי צאצא.

```
src/app/api/services/
├── 9router/
│   ├── _lib.ts             פונקציית העזר getOrInitSupervisor()
│   ├── install/route.ts    POST — npm install באמצעות execFile
│   ├── start/route.ts      POST — supervisor.start()
│   ├── stop/route.ts       POST — supervisor.stop()
│   ├── restart/route.ts    POST — supervisor.restart()
│   ├── update/route.ts     POST — npm install של גרסה חדשה יותר
│   ├── rotate-key/route.ts POST — יצירת מפתח API חדש + הפעלה מחדש
│   ├── status/route.ts     GET  — מצב בזמן אמת + מצב מסד הנתונים + מטא-נתוני גרסה
│   └── auto-start/route.ts POST — החלפת מצב הדגל auto_start
├── cliproxy/
│   ├── _lib.ts             פונקציית העזר getOrInitSupervisor()
│   ├── install/route.ts    POST — npm install
│   ├── start/route.ts      POST — supervisor.start()
│   ├── stop/route.ts       POST — supervisor.stop()

└── [name]/
    └── logs/route.ts       GET  — זנב יומן SSE (משותף לכל השירותים)
```

ממשק המשתמש התואם בלוח הבקרה:
`src/app/(dashboard)/dashboard/providers/services/` — דף בעל שתי לשוניות (CLIProxyAPI + 9Router).

`src/app/(dashboard)/dashboard/providers/services/[name]/embed/[[...path]]/route.ts`

העמקה: `docs/frameworks/EMBEDDED-SERVICES.md`

1. רשמו אותו ב-`src/shared/constants/providers.ts` (מאומת באמצעות Zod בעת הטעינה).

1. צרו את `src/app/api/your-route/route.ts`.
2. פעלו לפי התבנית: CORS → אימות גוף הבקשה באמצעות Zod → אימות זהות → האצלת הטיפול.

4. אם הנתיב מיועד לניהול בלבד: הוסיפו אותו ל-`src/shared/constants/publicApiRoutes.ts`
   (רשימת חסימה עבור ממשק ה-API הציבורי).

6. עדכנו את `docs/reference/API_REFERENCE.md` ואת `docs/openapi.yaml`.

3. אם יש טבלאות חדשות: הוסיפו מיגרציה תחת `src/lib/db/migrations/`, עם מספור

## 11. מוסכמות

- **סגנון קוד**: הזחה של 2 רווחים, מירכאות כפולות, רוחב של 100 תווים, נקודה-פסיק,
  פסיקים סופיים בסגנון `es5` — נאכף על ידי Prettier באמצעות `lint-staged`.
- **ייבואים**: חיצוניים → פנימיים (`@/`, `@omniroute/open-sse`) → יחסיים.
- **מתן שמות**: קבצים ב-`camelCase` או `kebab-case`, רכיבים ב-`PascalCase`,
  קבועים ב-`UPPER_SNAKE`.
- **ESLint**:‏ `no-eval`,‏ `no-implied-eval`,‏ `no-new-func` =‏ `error` בכל מקום;
  `no-explicit-any` =‏ `warn` ב-`open-sse/` וב-`tests/`, ושגיאה במקומות אחרים.
- **TypeScript**:‏ `strict: false` (מצב תאימות למערכת ותיקה). העדיפו טיפוסים מפורשים על פני
  הסקת טיפוסים בגבולות שבין מודולים.
- **מסד נתונים**: לעולם אל תכתבו SQL גולמי בנתיבים או במטפלים — עברו תמיד דרך
  המודולים שב-`src/lib/db/`. לעולם אל תייבאו דרך barrel — השתמשו ישירות במודולי `src/lib/db/*` ספציפיים.
- **טיפוס ישויות מסד נתונים (#3512)**: פונקציה שכותבת או קוראת מבנה שורה של
  טבלת מסד נתונים צריכה לקבל/להחזיר ממשק TS בעל שם המשקף את עמודות הטבלה
  ביחס 1:1, ולא `any` או טיפוס אנונימי מוטבע בנקודת הקריאה. מקמו
  את הממשק לצד הפונקציה (למשל `export interface UsageEntry` בתוך
  `src/lib/usage/usageHistory.ts` מעל `saveRequestUsage`), השאירו שדות בודדים
  כאופציונליים/ניתנים ל-null כאשר כותבים שונים מאכלסים את השורה
  בהדרגה, והעדיפו `unknown` על פני `any` עבור שדה שמבנהו
  משתנה בין קוראים (מתועד בשדה, למשל `UsageEntry.tokens`
  מקבל הן נתוני שימוש גולמיים במבנה הספק והן את המבנה המנורמל). לאחר שמספר מופעי
  `any` בקובץ מגיע כך לאפס, הוסיפו אותו לרשימת ההיתרים של
  `check:any-budget:t11`‏ (`scripts/check/check-t11-any-budget.mjs`,
  `maxAny: 0`) כדי למנוע נסיגה. זוהי מוסכמה עבור השלב הראשוני — הניקוי
  הרחב יותר של "`any` אנונימי אסור" מתבצע באופן הדרגתי בשאר
  בסיס הקוד.
- **שגיאות**: השתמשו ב-try/catch עם טיפוסי שגיאות ספציפיים ורשמו ביומן עם הקשר של pino. לעולם אל
  תבלעו שגיאות ללא דיווח בזרמי SSE; השתמשו באותות ביטול לצורך ניקוי.
- **אבטחה**: לעולם אל תשתמשו ב-`eval()` / `new Function()` / הפעלה משתמעת של eval. אמתו
  את כל הקלטים באמצעות Zod. הצפינו פרטי גישה במנוחה (AES-256-GCM). שמרו על
  התאמה בין רשימת החסימה `src/shared/constants/upstreamHeaders.ts` לבין
  שכבת הטיהור/האימות.
- **קומיטים**: Conventional Commits —‏ `feat(scope): subject`. ההיקפים המותרים:
  `db`, `sse`, `oauth`, `dashboard`, `api`, `cli`, `docker`, `ci`, `mcp`,
  `a2a`, `memory`, `skills`.
- **ענפים**: הקידומות `feat/`, `fix/`, `refactor/`, `docs/`, `test/`,
  `chore/`. לעולם אל תבצעו commit ישירות ל-`main`.
- **Husky**: לפני commit מופעלים `lint-staged` +‏ `check:docs-sync` +

## 12. כללים מחייבים (מתוך CLAUDE.md)

1. לעולם אין לבצע commit של סודות או פרטי גישה.

3. לעולם אין להשתמש ב-`eval()` / `new Function()` / eval משתמע.
4. לעולם אין לבצע commit ישירות אל `main`.
5. לעולם אין לכתוב SQL גולמי בנתיבים — יש לעבוד תמיד דרך המודולים שב-`src/lib/db/`.

7. יש לאמת תמיד קלטים באמצעות סכמות Zod.
8. יש לכלול תמיד בדיקות בעת שינוי קוד ייצור.
9. הכיסוי חייב להישאר ≥ 60% (פקודות, שורות, פונקציות, הסתעפויות).
