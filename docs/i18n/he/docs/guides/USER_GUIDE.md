## 🎯 תרחישי שימוש

### תרחיש 1: "יש לי מינוי Claude Pro"

**בעיה:** המכסה פוקעת בלי שנעשה בה שימוש, ויש מגבלות קצב במהלך עבודת תכנות אינטנסיבית

```
שילוב: "maximize-claude"
  1. cc/claude-opus-4-7        (ניצול מלא של המינוי)
  2. glm/glm-4.7               (גיבוי זול כשהמכסה נגמרת)
  3. if/qwen3.8-max-preview       (חלופת חירום חינמית)

עלות חודשית: $20 (מינוי) + כ-$5 (גיבוי) = $25 בסך הכול
לעומת $20 + הגעה למגבלות = תסכול
```

### תרחיש 2: "אני רוצה עלות אפסית"

**בעיה:** אין לי אפשרות לממן מינויים, ונדרש לי AI אמין לתכנות

```
שילוב: "zero-cost"
  1. if/kimi-k2.7-code          (מופיעה גישה חינמית; ייתכן שיחולו מגבלות קצב)
  2. kr/qwen3-coder-next        (חלופה חינמית של Kiro)

עלות חודשית: $0
איכות: יש לבדוק את המודל, המגבלות, הפרטיות וה-SLA עבור עומס העבודה שלכם
```

### תרחיש 3: "אני צריך תכנות 24/7, ללא הפרעות"

**בעיה:** יש מועדי הגשה, ואין לי אפשרות להרשות זמני השבתה

```
שילוב: "always-on"
  1. cc/claude-opus-4-7        (האיכות הטובה ביותר)
  2. cx/gpt-5.5                (מינוי שני)
  3. glm/glm-4.7               (זול, מתאפס מדי יום)
  4. minimax/MiniMax-M2.1      (הזול ביותר, מתאפס לאחר 5 שעות)

תוצאה: 5 שכבות חלופיות משפרות את העמידות; זמינות השירותים במעלה הזרם אינה מובטחת
עלות חודשית: $20-200 (מינויים) + $10-20 (גיבוי)
```

## 📖 הגדרת ספקים

כדי להוסיף בכמות גדולה חיבורי מפתחות API מקובץ CSV או JSON, השתמשו ב-**לוח הבקרה → ספקים → ייבוא מקובץ**. העמודות מבוססות על מיקום (`provider,name,apiKey,baseUrl,priority`); הערך `provider` חייב להיות ספק מנוהל קיים או צומת תואם. ראו [ייבוא ספקים מקובץ CSV או JSON](../providers/CSV-IMPORT.md).

### 🔐 ספקי מנוי

#### Claude Code (Pro/Max)

```bash
לוח הבקרה → ספקים → חיבור Claude Code
→ כניסה באמצעות OAuth → רענון אוטומטי של האסימון
→ מעקב אחר מכסה ל-5 שעות + מכסה שבועית

מודלים:
  cc/claude-opus-4-7
  cc/claude-sonnet-4-6
  cc/claude-haiku-4-5-20251001
```

**טיפ מקצועי:** השתמשו ב-Opus למשימות מורכבות וב-Sonnet למהירות. OmniRoute עוקב אחר המכסה לכל מודל!

אין דפדפן במארח של OmniRoute? הפעילו את `claude setup-token` בכל מקום שבו Claude Code מחובר, והדביקו את האסימון לשנה בלשונית **אסימון הגדרה**. ראו [Claude Code עם אסימון הגדרה](../providers/CLAUDE_CODE_SETUP_TOKEN.md).

נתיבים התואמים ל-Claude ול-Claude Code שומרים על מאמץ החשיבה `max` עבור מודלי Opus ו-Sonnet. מודלי Haiku אינם מקבלים את רמת המאמץ `max`, ולכן OmniRoute מוריד בקשה זו לתקציב חשיבה גבוה לפני שליחתה לספק במעלה הזרם.

#### OpenAI Codex (Plus/Pro)

```bash
לוח הבקרה → ספקים → חיבור Codex
→ כניסה באמצעות OAuth (יציאה 1455)
→ איפוס לאחר 5 שעות + איפוס שבועי

מודלים:
  cx/gpt-5.5
  cx/gpt-5.4
  cx/gpt-5.3-codex
  cx/gpt-5.3-codex-spark
```

#### GitHub Copilot

```bash
לוח הבקרה → ספקים → חיבור GitHub
→ OAuth באמצעות GitHub
→ איפוס חודשי (ב-1 בחודש)

מודלים:
  gh/gpt-5.5
  gh/gpt-5.4
  gh/claude-sonnet-4.6
  gh/claude-opus-4.7
  gh/gemini-3.1-pro-preview
```

### 💰 ספקים זולים

#### GLM-4.7 (איפוס יומי, $0.6/1M)

1. הירשמו: [Zhipu AI](https://open.bigmodel.cn)
2. קבלו מפתח API מתוכנית Coding Plan
3. לוח הבקרה → הוספת מפתח API: ספק: `glm`, מפתח API: `your-key`

**שימוש:** `glm/glm-4.7` — **טיפ מקצועי:** תוכנית Coding Plan מציעה מכסה גדולה פי 3 בשביעית מהעלות! האיפוס מתבצע מדי יום בשעה 10:00 בבוקר.

#### MiniMax M2.1 (איפוס לאחר 5 שעות, $0.20/1M)

1. הירשמו: [MiniMax](https://www.minimax.io)
2. קבלו מפתח API → לוח הבקרה → הוספת מפתח API

**שימוש:** `minimax/MiniMax-M2.1` — **טיפ מקצועי:** האפשרות הזולה ביותר להקשר ארוך (מיליון אסימונים)!

#### Kimi K2 (מחיר קבוע של $9 לחודש)

1. הירשמו למנוי: [Moonshot AI](https://platform.kimi.ai?aff=omniroute)
2. קבלו מפתח API → לוח הבקרה → הוספת מפתח API

**שימוש:** `kimi/kimi-k2.5` — **טיפ מקצועי:** מחיר קבוע של $9 לחודש עבור 10 מיליון אסימונים = עלות אפקטיבית של $0.90/1M!

#### Baidu Qianfan / ERNIE

## 🚀 פריסה

### התקנת npm גלובלית (מומלץ)

```bash
npm install -g omniroute

# יצירת תיקיית תצורה
mkdir -p ~/.omniroute

# יצירת קובץ .env (ראו .env.example)
cp .env.example ~/.omniroute/.env

# הפעלת השרת
omniroute
# או עם יציאה מותאמת אישית:
omniroute --port 3000
```

ה-CLI טוען אוטומטית את `.env` מתוך `~/.omniroute/.env` או `./.env`.

### מצב מגש מערכת

הפעילו את OmniRoute במגש המערכת:

```bash
omniroute serve --tray
```

הפקודה מסתיימת לאחר שהשרת ומגש המערכת מוכנים.

השרת ממשיך לפעול ללא המסוף.

מצב מגש המערכת נתמך ב-macOS, ב-Windows ובהפעלות Linux גרפיות. מצב מגש המערכת אינו פותח את לוח הבקרה באופן אוטומטי.

השתמשו בתפריט מגש המערכת עבור הפעולות הבאות:

- פתיחת לוח הבקרה.
- פתיחת `/dashboard/logs`.
- שינוי ההפעלה האוטומטית.
- עצירת OmniRoute.

אין לשלב את `--tray` עם האפשרויות הבאות:

- `--daemon`
- `--log`
- `--no-recovery`

מצבים אלה דורשים בעלות שונה על התהליך.

הפעילו את OmniRoute בעת הכניסה הבאה למחשב:

```bash
omniroute autostart enable
```

ההפעלה האוטומטית משתמשת במצב מגש המערכת ב-macOS, ב-Windows ובהפעלות Linux גרפיות. Linux ללא ממשק גרפי משתמש בשירות המשתמש הקיים של systemd.

השביתו הפעלה בעת הכניסה:

```bash
omniroute autostart disable
```

### הסרת התקנה

כאשר OmniRoute אינו נחוץ עוד, אנו מספקים שני סקריפטים מהירים להסרה נקייה:

| פקודה                    | פעולה                                                                                    |
| ------------------------ | ---------------------------------------------------------------------------------------- |
| `npm run uninstall`      | מסירה את יישום המערכת, אך **שומרת את מסד הנתונים ואת ההגדרות שלכם** בתוך `~/.omniroute`. |
| `npm run uninstall:full` | מסירה את היישום וגם **מוחקת לצמיתות את כל ההגדרות, המפתחות ומסדי הנתונים**.              |

> הערה: כדי להריץ פקודות אלה, עברו לתיקיית הפרויקט של OmniRoute (אם שיבטתם אותו) והפעילו אותן. לחלופין, אם הוא הותקן באופן גלובלי, ניתן פשוט להריץ `npm uninstall -g omniroute`.

### Void Linux (xbps-src)

משתמשי Void Linux יכולים לארוז ולהתקין את OmniRoute באופן מקורי באמצעות מסגרת ההידור הצולב `xbps-src`. מסגרת זו הופכת לאוטומטיים את בניית החבילה העצמאית של Node.js ואת הקישורים המקוריים הנדרשים של `better-sqlite3`.

## 🧩 תכונות מתקדמות

### מודלים מותאמים אישית

הוסיפו מזהה מודל כלשהו לכל ספק, בלי להמתין לעדכון של האפליקציה:

```bash
# באמצעות API
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# הצגה: curl http://localhost:20128/api/provider-models?provider=openai
# הסרה: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

לחלופין, השתמשו בלוח הבקרה: **ספקים → [ספק] → מודלים מותאמים אישית**.

הערות:

- ספקים תואמי OpenRouter ו-OpenAI/Anthropic מנוהלים רק מתוך **מודלים זמינים**. הוספה ידנית, ייבוא וסנכרון אוטומטי מתווספים כולם לאותה רשימת מודלים זמינים, ולכן אין עבור ספקים אלה מקטע נפרד של מודלים מותאמים אישית.
- המקטע **מודלים מותאמים אישית** מיועד לספקים שאינם מציעים ייבוא מנוהל של מודלים זמינים.

### ספקים מותאמים אישית תואמי OpenAI

כל שער שתומך ב-OpenAI API (פרוקסי באירוח עצמי, vLLM או מאגד של צד שלישי)
ניתן להוספה כצומת ספק עצמאי:

1. **ספקים → הוספת ספק תואם OpenAI**.
2. **שם**: תווית התצוגה של הצומת.
3. **קידומת**: שם הניתוב. לקוחות פונים למודלים בתבנית `<prefix>/<model>`, ולכן צומת עם
   הקידומת `mygw` משרת את `mygw/gpt-4o-mini`. שדה חובה; אין הגבלה על התווים.
4. **סוג API**: משפחת נקודות הקצה שהשער משרת (השלמות צ'אט, תגובות,
   הטמעות, שמע, תמונות).
5. **כתובת URL בסיסית**: שורש ה-API, עד `/v1` וכולל (לדוגמה
   `https://gateway.example.com/v1`), ולא הנתיב המלא `/chat/completions`. בשערים עם
   נתיבים לא סטנדרטיים, הגדירו אותם תחת **הגדרות מתקדמות** (נתיב צ'אט, נתיב מודלים).
6. השדה **מפתח API (לבדיקה)** בודק רק את החיבור. לאחר יצירת הצומת,
   פתחו אותו והשתמשו באפשרות **הוספת חיבור** כדי לשמור את המפתח שבו ישתמשו הבקשות.

לצומת מוקצה מזהה פנימי בתבנית `openai-compatible-<apiType>-<uuid>`; לעולם אין
צורך להקליד אותו, משום שהקידומת היא השם הציבורי.

#### קידומות שמורות

קידומת אינה יכולה להיות המזהה או הכינוי של ספק מובנה (לדוגמה `openai`,‏ `cf`), וגם לא
המזהה של ספק שיצא משימוש. פותר המודלים בודק מזהים וכינויים מובנים לפני
צמתים מותאמים אישית, ולכן צומת המשתמש באחת מהקידומות האלה לעולם לא יקבל תעבורה:
`<prefix>/model` ינותב במקום זאת לספק המובנה, או ייחסם אם הספק
יצא משימוש. ניסיון ליצור או לערוך צומת עם קידומת כזו נדחה עם ההודעה:

```text
prefix: "<prefix>" היא קידומת ספק שמורה — יש לבחור קידומת אחרת (לא ניתן להשתמש במזהים/כינויים שמורים עבור צמתים מותאמים אישית, משום שבקשות כגון <prefix>/model מנותבות לספק מובנה או נחסמות כאשר הוא יצא משימוש)
```

בחרו קידומת ייחודית (`mygw`,‏ `acme-proxy`). אם בקשות לצומת מותאם אישית נכשלות עם
שגיאה המציינת ספק מובנה או את פרטי הגישה שלו, בדקו אם קידומת הצומת
שמורה: צמתים שנשמרו לפני שהכלל הזה נוסף עדיין מאוחסנים, אך הקידומת שלהם מנותבת
לספק המובנה. ערכו את הצומת והקצו לו קידומת חדשה.

### שרשור עמיתי OmniRoute

ניתן להוסיף שער OmniRoute נוסף כספק **מותאם אישית תואם OpenAI**. השתמשו בכתובת
ה-URL הבסיסית `/v1` של העמית ובמפתח API ייעודי בעל הרשאות מזעריות שהונפק על ידו.

עבור שרשראות הדדיות או מרובות קפיצות, הפעילו את מנגנון ההגנה האופציונלי מפני לולאות בכל שער:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

רק בקשות שנשלחות לכתובת URL של עמית אשר נכללת במפורש ברשימת ההרשאות מקבלות את הכותרת
`X-OmniRoute-Peer-Trace`. שער דוחה מזהה מופע חוזר או מיצוי של תקציב הקפיצות
באמצעות HTTP `508 Loop Detected`; ספקים רגילים במעלה הזרם אינם מקבלים מטא-נתונים של עמיתים.

שרשור עמיתים אינו שכפול מסד נתונים או מעבר לגיבוי בעת כשל של מארח. כל שער מחזיק מצב
SQLite, מטמונים, מוני קצב והפעלות עצמאיים. השתמשו בפרוקסי הפוך עם בדיקות תקינות או במעבר
לגיבוי מצד הלקוח לצורך זמינות אקטיבית/פסיבית או אקטיבית/אקטיבית, ולעולם אל תעגנו מסד נתונים
אחד של SQLite בכמה מופעי OmniRoute פועלים.

### מנהרה מהירה של Cloudflare

- זמין ב-**Dashboard → Endpoints** עבור Docker ופריסות אחרות באירוח עצמי
- יוצר כתובת URL זמנית מסוג `https://*.trycloudflare.com`, שמעבירה תעבורה לנקודת הקצה הנוכחית שלך, התואמת ל-OpenAI, בנתיב `/v1`
- בהפעלה הראשונה, `cloudflared` מותקן רק בעת הצורך; הפעלות מחדש בהמשך משתמשות שוב באותו קובץ בינארי מנוהל
- מנהרות מהירות אינן משוחזרות אוטומטית לאחר הפעלה מחדש של OmniRoute או של הקונטיינר; יש להפעיל אותן מחדש מלוח הבקרה בעת הצורך
- כתובות ה-URL של המנהרות הן זמניות ומשתנות בכל פעם שעוצרים או מפעילים את המנהרה
- מנהרות מהירות מנוהלות משתמשות כברירת מחדל בתעבורת HTTP/2, כדי להימנע מאזהרות רועשות לגבי מאגר UDP של QUIC בקונטיינרים מוגבלים
- הגדירו את `CLOUDFLARED_PROTOCOL=quic` או `auto` אם ברצונכם לעקוף את בחירת התעבורה המנוהלת
- הגדירו את `CLOUDFLARED_BIN` אם אתם מעדיפים להשתמש בקובץ בינארי של `cloudflared` שכבר מותקן, במקום בהורדה המנוהלת
- ניתן להציג או להסתיר את החלוניות של Cloudflare Quick Tunnel, Tailscale Funnel ו-ngrok Tunnel דרך **Settings → Appearance**. הסתרת חלונית אינה עוצרת מנהרה פעילה.

### מודיעין שער LLM (שלב 9)

- **מטמון סמנטי** — שומר אוטומטית במטמון תגובות שאינן מוזרמות ושבהן temperature=0 (ניתן לעקוף באמצעות `X-OmniRoute-No-Cache: true`)
- **אידמפוטנטיות של בקשות** — מסיר כפילויות של בקשות בתוך 5 שניות באמצעות הכותרת `Idempotency-Key` או `X-Request-Id`
- **מעקב התקדמות** — אירועי SSE מסוג `event: progress`, הניתנים להפעלה לפי בחירה באמצעות הכותרת `X-OmniRoute-Progress: true`

### אסטרטגיות ניתוב

ההגדרה מתבצעת דרך **Dashboard → Settings → Routing**. לוח הבקרה מציג את שש האסטרטגיות הנפוצות ביותר; שילובים והנתב האוטומטי תומכים באופן פנימי במבחר רחב יותר.

**אסטרטגיות המוצגות בלוח הבקרה (ניתוב ברמת החשבון):**

| אסטרטגיה                         | תיאור                                                                                         |
| -------------------------------- | --------------------------------------------------------------------------------------------- |
| **מילוי הראשון**                 | משתמש בחשבונות לפי סדר עדיפות — החשבון הראשי מטפל בכל הבקשות עד שאינו זמין                    |
| **סבב מחזורי**                   | עובר במחזוריות בין כל החשבונות, עם מגבלת הצמדה הניתנת להגדרה (ברירת מחדל: 3 קריאות לכל חשבון) |
| **P2C (הטוב מבין שתי אפשרויות)** | בוחר 2 חשבונות אקראיים ומנתב לחשבון התקין יותר — מאזן עומס תוך התחשבות בתקינות                |
| **אקראי**                        | בוחר חשבון אקראי לכל בקשה באמצעות ערבוב Fisher-Yates                                          |
| **הכי פחות בשימוש**              | מנתב לחשבון בעל חותמת הזמן `lastUsedAt` הישנה ביותר, וכך מפזר את התעבורה באופן שווה           |
| **מיטוב עלויות**                 | מנתב לחשבון בעל ערך העדיפות הנמוך ביותר, לצורך מיטוב עבור הספקים הזולים ביותר                 |

**אסטרטגיות מתקדמות לשילובים ולניתוב אוטומטי** (ניתנות להגדרה לכל שילוב או באמצעות קידומות `auto/*` — ראו [AUTO-COMBO.md](../routing/AUTO-COMBO.md)):

- `priority` — סדר מחמיר, ללא סבב מחזורי
- `weighted` — חלוקת תעבורה יחסית לפי משקלים לכל מודל
- `fill-first` — מיצוי המודל הראשון עד להגעה למגבלות
- `round-robin` / `strict-random` / `random`
- `p2c` (הטוב מבין שתי אפשרויות)
- `least-used` ו-`cost-optimized`
- `auto` — מונע על ידי ניקוד על פני כל המועמדים
- `lkgp` (הספק התקין האחרון הידוע) — נצמד לספק האחרון שהצליח, ולאחר מכן חוזר לכללי הגיבוי
- `context-optimized` — בוחר את המודל בעל חלון ההקשר הפנוי הגדול ביותר
- `context-relay` — משרשר מודלים בעלי הקשר ארוך עבור סבבי המשך

#### כותרת חיצונית להצמדת הפעלה

לצורך שיוך חיצוני להפעלה (לדוגמה, סוכני Claude Code/Codex מאחורי שרתי פרוקסי הפוך), שלחו:

```http
X-Session-Id: your-session-key
```

OmniRoute מקבל גם את `x_session_id` ומחזיר את מפתח ההפעלה בפועל ב-`X-OmniRoute-Session-Id`.

אם אתם משתמשים ב-Nginx ושולחים כותרות המכילות קווים תחתונים, הפעילו:

```nginx
underscores_in_headers on;
```

#### כינויים למודלים עם תווים כלליים

צרו תבניות עם תווים כלליים כדי למפות מחדש שמות מודלים:

```
תבנית: claude-sonnet-*     →  יעד: cc/claude-sonnet-4-6
תבנית: gpt-*               →  יעד: gh/gpt-5.3-codex
```

תווים כלליים תומכים ב-`*` (תווים כלשהם) וב-`?` (תו יחיד).

#### שרשראות גיבוי

הגדירו שרשראות גיבוי גלובליות שיחולו על כל הבקשות:

```
שרשרת: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### עמידות ומפסקי זרם

הגדירו דרך **לוח הבקרה → הגדרות → עמידות**.

OmniRoute מממש עמידות ברמת הספק באמצעות חמישה רכיבים:

1. **תור בקשות וקציבת קצב** — עיצוב תעבורת בקשות ברמת המערכת:
   - **בקשות לדקה (RPM)** — מספר הבקשות המרבי לדקה לכל חשבון
   - **זמן מינימלי בין בקשות** — המרווח המינימלי באלפיות שנייה בין בקשות
   - **מספר מרבי של בקשות מקביליות** — מספר הבקשות המרבי שיכולות להתבצע בו־זמנית לכל חשבון

2. **תקופת צינון לחיבור** — תצורה לפי סוג אימות עבור חיבור יחיד לאחר כשלים שניתן לנסות מחדש:
   - **תקופת צינון בסיסית** — חלון ברירת המחדל לצינון לאחר כשלים שניתן לנסות מחדש אצל ספק במעלה הזרם
   - **שימוש בהנחיות ניסיון חוזר מספק במעלה הזרם** — מכבד הנחיות מוסמכות מסוג `Retry-After` או הנחיות איפוס, כאשר הן מסופקות
   - **מספר מרבי של שלבי השהיה** — רמת ההשהיה המעריכית המרבית עבור כשלים חוזרים

3. **מפסק זרם של ספק** — עוקב אחר כשלים מקצה לקצה אצל הספק, מסמן ספק כפועל באופן ירוד כאשר מגיעים לסף האזהרה שהוגדר, ופותח את המפסק כאשר מגיעים לסף הכשלים שהוגדר:
   - **סף ירידה בביצועים** — מספר כשלי הספק הרצופים לפני מעבר למצב `DEGRADED`
   - **סף כשלים** — מספר כשלי הספק הרצופים לפני מעבר למצב `OPEN`
   - **פסק זמן לאיפוס** — חלון הזמן לפני שהספק נבדק שוב
   - **CLOSED** (תקין) — הבקשות זורמות כרגיל
   - **DEGRADED** — הבקשות ממשיכות לזרום בזמן שמתבצע מעקב אחר ריבוי הכשלים
   - **OPEN** — הספק נחסם זמנית לאחר כשלים חוזרים
   - **HALF_OPEN** — בדיקה אם הספק התאושש

   מגבלות קצב `429` ברמת החיבור נשארות תחת **תקופת צינון לחיבור** ואינן נספרות במפסק הספק.

   מצב זמן הריצה של מפסק הספק מוצג רק תחת **לוח הבקרה → תקינות**.

4. **המתנה לתום תקופת הצינון** — אם כל החיבורים המועמדים כבר נמצאים בתקופת צינון, OmniRoute יכול להמתין לסיום תקופת הצינון המוקדמת ביותר ולנסות שוב באופן אוטומטי את אותה בקשת לקוח.

5. **זיהוי אוטומטי של מגבלת קצב** — כאשר ספקים במעלה הזרם מחזירים חלונות המתנה מפורשים, הנחיות אלה גוברות על תקופת הצינון המקומית של החיבור כאשר ההגדרה מופעלת.

**טיפ מקצועי:** השתמשו בדף **תקינות** כדי לבדוק ולאפס מפסקי ספקים פעילים לאחר השבתה. דף העמידות משנה רק את התצורה.

### ייצוא / ייבוא של מסד הנתונים

נהלו גיבויים של מסד הנתונים דרך **לוח הבקרה → הגדרות → מערכת ואחסון**.

| פעולה                    | תיאור                                                                                                                    |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| **ייצוא מסד הנתונים**    | הורדת מסד הנתונים הנוכחי של SQLite כקובץ `.sqlite`                                                                       |
| **ייצוא הכול (.tar.gz)** | הורדת ארכיון גיבוי מלא הכולל: מסד נתונים, הגדרות, קומבינציות, חיבורי ספקים (ללא פרטי גישה), מטא־נתונים של מפתחות API     |
| **ייבוא מסד נתונים**     | העלאת קובץ `.sqlite` להחלפת מסד הנתונים הנוכחי. גיבוי טרום־ייבוא נוצר אוטומטית, אלא אם `DISABLE_SQLITE_AUTO_BACKUP=true` |

```bash
# API: ייצוא מסד הנתונים
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: ייצוא הכול (ארכיון מלא)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: ייבוא מסד הנתונים
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**אימות הייבוא:** הקובץ המיובא עובר אימות תקינות (בדיקת pragma של SQLite), בדיקת הטבלאות הנדרשות (`provider_connections`, `provider_nodes`, `combos`, `api_keys`) ובדיקת גודל (עד 100MB).

**מקרי שימוש:**

- העברת OmniRoute בין מחשבים
- יצירת גיבויים חיצוניים להתאוששות מאסון
- שיתוף תצורות בין חברי צוות (ייצוא הכול → שיתוף הארכיון)

### לוח בקרת ההגדרות

דף ההגדרות מאורגן ב־**7 כרטיסיות** לניווט קל:

| לשונית     | תוכן                                                                                                                                                               |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

| **מראה**   | בקרות ערכת נושא (בהירה/כהה/מערכת), נראות סרגל הצד, מתגים להצגת כרטיסי מנהרות Cloudflare/Tailscale/ngrok                                                            |
| **AI**     | תקציב חשיבה (העברה כפי שהוא / הסרה אוטומטית / מותאם אישית / מסתגל — ראו [THINKING_BUDGET.md](./THINKING_BUDGET.md)), הנחיית מערכת גלובלית, סטטיסטיקות מטמון הנחיות |
| **אבטחה**  | הגדרות כניסה/סיסמה, בקרת גישה לפי IP, אימות API עבור `/models`, חסימת ספקים, הגנה מפני הזרקת הנחיות                                                                |
| **ניתוב**  | אסטרטגיית ניתוב גלובלית (מילוי ראשון / סבב / P2C / אקראי / הכי פחות בשימוש / מיטוב עלויות), כינויי מודלים עם תווים כלליים, שרשראות גיבוי, ברירות מחדל לשילובים     |
| **עמידות** | תור בקשות, זמן צינון חיבור, תצורת מפסק ספקים והתנהגות המתנה לסיום זמן הצינון                                                                                       |
| **מתקדם**  | תצורת Proxy גלובלית (HTTP/SOCKS5), דריסות Proxy לכל ספק                                                                                                            |

הלשונית כללי אינה משכפלת עוד הערות לקריאה בלבד בנוגע לרישום ולמטמון. הגדרות שמירת מסד הנתונים
והמיטוב נשמרות דרך `/api/settings/database`; ניקוי מטמון ידני מתבצע באמצעות
`DELETE /api/cache`. המגבלות על מספר השורות ביומני בקשות ו-Proxy נשלטות באמצעות
`CALL_LOGS_TABLE_MAX_ROWS` ו-`PROXY_LOGS_TABLE_MAX_ROWS`.

### אסטרטגיות איזון לשילובים

הגדירו איזון לכל שילוב דרך **לוח הבקרה ← שילובים ← יצירה/עריכה ← אסטרטגיה**.

| אסטרטגיה            | תיאור                                                                 |
| ------------------- | --------------------------------------------------------------------- |
| **סבב**             | מעבר בין המודלים בזה אחר זה                                           |
| **עדיפות**          | ניסיון להשתמש תמיד במודל הראשון; מעבר לגיבוי רק במקרה של שגיאה        |
| **אקראי**           | בחירת מודל אקראי מהשילוב עבור כל בקשה                                 |
| **משוקלל**          | ניתוב יחסי על סמך המשקלים שהוקצו לכל מודל                             |
| **הכי פחות בשימוש** | ניתוב למודל עם מספר הבקשות האחרונות הנמוך ביותר (באמצעות מדדי השילוב) |
| **מיטוב עלויות**    | ניתוב למודל הזמין הזול ביותר (באמצעות טבלת התמחור)                    |

ניתן להגדיר ברירות מחדל גלובליות לשילובים דרך **לוח הבקרה ← הגדרות ← ניתוב ← ברירות מחדל לשילובים**.
כברירת מחדל, זמני הקצוב של יעדי השילוב יורשים את זמן הקצוב הנוכחי של הבקשה. השתמשו ב-**זמן קצוב
ליעד (שניות)** בברירות המחדל של השילובים או בשילוב מסוים רק כאשר מגבלה קצרה יותר לכל יעד אמורה
להפעיל מעבר מהיר יותר לגיבוי.

מיטובי שילוב ללא השהיה מופעלים רק במפורש. השאירו את **מיטובים ללא השהיה** מושבתים כדי
למנוע מתכונות השהיה אלה להתחרות ביעדי גיבוי, לדלג על יעדים על סמך היסטוריית TTFT
או לדחוס בקשות גיבוי; הפעלת האפשרות מאפשרת גידור מוגדר, דילוגים חזויים לפי TTFT
ודחיסה יזומה של גיבויים, תוך ויתור מסוים על נאמנות הניתוב/הבקשה לטובת השהיית זנב
נמוכה יותר.

השביתו את **מאגר אסימוני החשיבה** כאשר ספקים במעלה הזרם דורשים מגבלות מחמירות של
`max_tokens` / `maxOutputTokens`. כאשר הוא מופעל, ניתוב משולב מוסיף מרווח לאסימוני חשיבה רק
עבור מודלים בעלי תקרת פלט ידועה, ומשאיר את מגבלת האסימונים של הלקוח ללא שינוי כאשר הערך הבטוח
עם המאגר יחרוג מתקרה זו. אם מגבלת הלקוח כבר גבוהה מתקרה ידועה, OmniRoute מגביל אותה לתקרה זו
לפני שליחת הבקשה לספק במעלה הזרם.

הגישה מתבצעת דרך **לוח הבקרה → תקינות**. סקירה בזמן אמת של תקינות המערכת באמצעות 6 כרטיסים:

| כרטיס              | מה הוא מציג                                                             |
| ------------------ | ----------------------------------------------------------------------- |

| **תקינות הספקים**  | מצב זמן הריצה של מפסק הזרם הגלובלי עבור ספקים                           |
| **מגבלות קצב**     | תקופות צינון פעילות של חיבורים לכל חשבון, כולל הזמן שנותר               |

## 🤖 ניתוב אוטומטי (ללא הגדרות)

OmniRoute מגיע עם **נתב אוטומטי מבוסס-ניקוד** שבוחר את המודל הטוב ביותר לכל בקשה מכל הספקים המחוברים — ללא צורך בתחזוקת שילובים. פשוט שלחו את הבקשה עם אחת מהקידומות `auto/*`, ו-OmniRoute ירכיב שילוב וירטואלי באופן דינמי, תוך דירוג המועמדים לפי זמן השהיה, עלות, שיעור הצלחה, התאמה לחלון ההקשר, התאמת המודל למשימה, תקלות אחרונות, מכסה ומצב מפסק הזרם.

| קידומת         | מיטוב עבור                                                                            |
| -------------- | ------------------------------------------------------------------------------------- |
| `auto`         | ברירת מחדל מאוזנת (זמן השהיה × עלות × שיעור הצלחה)                                    |
| `auto/coding`  | משימות תכנות: העדפה ל-Claude, GPT-5, GLM, Kimi, Qwen Coder ולמודלי התכנות של DeepSeek |
| `auto/cheap`   | העלות הנמוכה ביותר לטוקן, עם נכונות לקבל זמן השהיה גבוה יותר                          |
| `auto/fast`    | זמן ההשהיה הנמוך ביותר, ללא התחשבות בעלות                                             |
| `auto/offline` | ספקים מקומיים בלבד (Ollama, vLLM, llama.cpp) — שימושי לסביבות מבודדות מהרשת           |
| `auto/smart`   | איכות הסקת מסקנות בעדיפות ראשונה (Opus, GPT-5 xhigh, R1, הסקת המסקנות של GLM 5.1)     |
| `auto/lkgp`    | "הספק התקין האחרון הידוע" — נצמד לספק האחרון שהצליח, ולאחר מכן חוזר לכללי ברירת המחדל |

דוגמה:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "Refactor this Python function" }],
    "stream": true
  }'
```

הנתב האוטומטי מתואר במלואו ב-[AUTO-COMBO.md](../routing/AUTO-COMBO.md) — כולל האופן שבו ניתן לכוונן את משקלי הניקוד, להוסיף ספקים לרשימה שחורה ולבחון החלטות ניתוב תחת **לוח הבקרה → שילוב אוטומטי**.

## 🔌 שילוב MCP ו-A2A

OmniRoute הוא גם **שרת MCP** (פרוטוקול הקשר למודל) וגם **שרת A2A**‏ (Agent-to-Agent JSON-RPC 2.0). כל סביבת פיתוח או מארח סוכנים התואמים ל-MCP יכולים לקרוא ישירות לכלים של OmniRoute — ללא צורך במעטפת נוספת.

### תעבורות MCP

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **HTTP ניתן להזרמה**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (עבור תוספי סביבת פיתוח שמעדיפים stdio)

### חיבור Claude Desktop

ערכו את `~/Library/Application Support/Claude/claude_desktop_config.json` (ב-macOS) או את הקובץ המקביל ב-Windows/Linux:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### חיבור Cursor / Continue / VS Code MCP

השתמשו בכתובת ה-SSE‏ `http://localhost:20128/api/mcp/sse` ובמפתח API מסוג Bearer שנוצר תחת **לוח הבקרה → מפתחות API**.

### תחומי הרשאה

MCP מגדיר כעת 32 תחומי הרשאה בעלי שם. ניתן להגביל כל מפתח Bearer לתחומי הרשאה מסוימים — ראו [MCP-SERVER.md](../frameworks/MCP-SERVER.md) לקבלת הרשימה המוסמכת של תחומי ההרשאה והכלים, ואת [A2A-SERVER.md](../frameworks/A2A-SERVER.md) לקבלת סכמת JSON-RPC.

OmniRoute חושפת **מסגרת מיומנויות הניתנת להרחבה** (`src/lib/skills/`), כדי שסוכנים ונקודת הקצה A2A יוכלו להריץ תהליכים ייעודיים לתחומים מסוימים (למשל `code-review`, `summarize`, `extract-facts`, `web-research`).

- **מיומנויות מותאמות אישית** — הוסיפו קובץ TypeScript אל `src/lib/a2a/skills/`, רשמו אותו, והוא יהיה זמין מיד להפעלה דרך A2A

## 🔔 Webhooks

הירשמו לאירועי OmniRoute לצורך ניטור ואוטומציה בזמן אמת.

- צרו webhook דרך **לוח הבקרה → Webhooks** עם כתובת URL יעד וסוד חתימה מסוג HMAC
- אירועים זמינים: `request.completed`, `request.failed`, `provider.unavailable`, `budget.exceeded`, `combo.switched`, `circuit_breaker.opened`, `circuit_breaker.closed`
- כל מטען נתונים כולל את `X-OmniRoute-Signature` (HMAC-SHA256) לצורך אימות
- ניסיונות חוזרים: 3 ניסיונות עם השהיה מעריכית, ולאחר מכן העברה לתור הודעות כושלות

הסכמה המלאה נמצאת ב-[WEBHOOKS.md](../frameworks/WEBHOOKS.md).

## 🛠️ ניהול תכנותי

ניתן לנהל כל משאב של OmniRoute (ספקים, שילובים, מפתחות, הגדרות) באמצעות HTTP, תוך שימוש ב**מפתח Bearer עם התחום `manage`**.

צרו את המפתח דרך **לוח הבקרה → מפתחות API → מפתח חדש → תחום: manage**, ולאחר מכן:

```bash
# הצגת רשימת הספקים
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# הוספת חיבור לספק
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# יצירת שילוב
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# הצגה/יצירה של מפתחות API
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

ראו [API_REFERENCE.md](../reference/API_REFERENCE.md) לקטלוג המלא של נקודות הקצה ולסכמות הבקשות/התגובות.

## 💻 CLI פנימי

OmniRoute כולל CLI פנימי (`omniroute …`) להגדרה, לאבחון ולשליטה בזמן ריצה. הוא **נפרד מהעמוד "כלי CLI" בלוח הבקרה**, שמגדיר כלי CLI של צד שלישי (Claude Code, Cursor, Codex, Cline, …) כדי שיוכלו לתקשר עם OmniRoute.

```bash
omniroute setup                    # אשף אינטראקטיבי (סיסמה, ספקים, שילובים)
omniroute setup --non-interactive  # מתאים ל-CI
omniroute doctor                   # אבחון תקינות (ספריית נתונים, מסד נתונים, ספקים, יציאות)
omniroute providers available      # הצגת הספקים הנתמכים
omniroute providers list           # הצגת החיבורים המוגדרים
omniroute providers test <id>      # בדיקה חיה של חיבור לספק
omniroute combos list              # הצגת שילובים
omniroute combos switch <name>     # הגדרת שילוב ברירת המחדל
omniroute models                   # הצגת המודלים הזמינים (--json, --search)
omniroute keys add | list | remove # ניהול מפתחות API מהמסוף
omniroute backup                   # יצירת תמונת מצב של התצורה ומסד הנתונים
omniroute restore [<timestamp>]    # שחזור מתמונת מצב
omniroute health                   # מצב תקינות מפורט (מנתקי מעגל, מטמון, זיכרון)
omniroute quota                    # שימוש במכסת הספק
omniroute mcp status               # מצב שרת MCP
omniroute a2a status               # מצב שרת A2A
omniroute tunnel list|create|stop  # מנהרות Cloudflare/Tailscale/ngrok
omniroute reset-password           # איפוס סיסמת מנהל המערכת
omniroute --mcp                    # הפעלת שרת MCP דרך stdio
omniroute --port 3000              # הפעלת השרת ביציאה מותאמת אישית
```

טיפ: שלבו את `omniroute doctor --json` עם כלי הניטור שלכם כדי לקבל התראות על חיבורים לא תקינים לספקים.

# מתוך הספרייה electron:
