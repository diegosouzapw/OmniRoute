`@omniroute/opencode-plugin-v2` מכניסה את כל קטלוג OmniRoute שלכם — מודלים, שילובים
ושילובים אוטומטיים — לבורר המודלים של OpenCode v2, עם שמות תצוגה, תמחור ומכסות
למסלול החינמי.

זוהי חבילה נפרדת מ-`@omniroute/opencode-plugin`, משום ש-OpenCode v1 ו-v2 טוענות
תוספים באמצעות ממשקים שונים. בחרו בזו שתואמת לגרסה הראשית של OpenCode שלכם; דבר אינו
משותף ביניהן, ולכן שדרוג של אחת לעולם אינו מחייב שדרוג של האחרת.

## דרישות

- OpenCode v2.
- שער OmniRoute נגיש (`http://localhost:20128` כברירת מחדל).
- Node.js 22 או 24.

## התקנה

הוסיפו את התוסף ל-`opencode.json`:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

לאחר מכן, המודלים מופיעים בתבנית `omniroute/<provider>/<model>`; הערך `providerId` קובע את התחילית הזו ואת
מזהה האינטגרציה שתחתיו OpenCode שומרת את פרטי הגישה.

## פרטי גישה

התוסף מחפש מפתח לשער בשלושה מקומות, לפי הסדר הבא:

1. **פרטי הגישה שחיברתם ב-OpenCode.** התוסף רושם אינטגרציה, כך
   שתהליך האימות המובנה של OpenCode יכול לשמור את המפתח. דבר אינו נשמר ב-`opencode.json` — זו האפשרות המועדפת.
2. `apiKey` באפשרויות התוסף, לצורך דריסה ברמת הפרויקט. אפשרות זו שומרת את המפתח בקובץ שאתם
   עשויים לבצע לו commit.
3. `OMNIROUTE_API_KEY` בסביבה.

אם אף אחד מהשלושה אינו מוגדר, הקטלוג ריק והתוסף מודיע על כך פעם אחת בעת ההפעלה, במקום
להשאיר אתכם עם בורר ריק ללא הסבר.

### אסימון הניהול הוא מפתח אחר

שילובים, תקינות ספקים והעשרה (שמות תצוגה, תמחור ומכסות למסלול החינמי) מגיעים
מנקודות הקצה `/api/*` של השער, שברוב הפריסות מוגנות באמצעות אסימון **ניהול**
ולא באמצעות מפתח ההסקה:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<management read token>"
}
```

כאשר `managementReadToken` אינו מוגדר, נעשה שימוש ב-`apiKey` כחלופה. כאשר שער דוחה חלופה זו,
הקטלוג עדיין מתפרסם, אך עם מזהי מודלים גולמיים במקום שמות תצוגה, ללא הסרת כפילויות של
כינויים קנוניים, ללא תמחור וללא שילובים. התוסף מזהיר פעם אחת לכל נקודת קצה כשזה קורה,
תוך ציון נקודת הקצה ומה אבד — כך שבורר שפועל באופן חלקי לעולם אינו בגדר תעלומה.

## אפשרויות

| מפתח                             | ברירת מחדל                                   | הערות                                                                                    |
| -------------------------------- | -------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `providerId`                     | `"omniroute"`                                | מזהה הספק, מזהה האינטגרציה והתחילית שתחתיה מופיעים המודלים                               |
| `baseURL`                        | חובה                                         | שורש השער, `http(s)` בלבד; הסיומת `/v1` מתווספת לפי הצורך                                |
| `apiKey`                         | פרטי הגישה המחוברים, ואז `OMNIROUTE_API_KEY` | מפתח צ'אט עבור `/v1/*`                                                                   |
| `managementReadToken`            | חוזר ל-`apiKey`                              | מפתח עבור `/api/*` — בדרך כלל **לא** אותו מפתח                                           |
| `displayName`                    | `"OmniRoute"`                                | שם הספק בבורר                                                                            |
| `timeoutMs`                      | `10000`                                      | זמן קצוב לכל נקודת קצה (שילובים אוטומטיים משתמשים ב-5 שניות)                             |
| `modelCacheTtlMs`                | `300000`                                     | זמן החיים של מטמון הקטלוג; תמונת מצב בדיסק מאיצה הפעלות קרות                             |
| `timeouts`                       | חוזר ל-`timeoutMs`                           | מכסות זמן לכל נקודת קצה באלפיות שנייה: `models`, `combos`, `autoCombos`, `enrichment`    |
| `enrichment`                     | `true`                                       | אחזור שמות, תמחור ומכסות למסלול החינמי                                                   |
| `providerTag`                    | `true`                                       | הוספת הספק המקורי שאליו מתבצע הניתוב כתחילית לשם התצוגה                                  |
| `usableOnly`                     | `false`                                      | שמירה רק של ספקים שהשער מדווח כי הוקצו                                                   |
| `visibleModels` / `hiddenModels` | `[]`                                         | רשימות הרשאה בהתאמה מדויקת או לפי סיומת; חסימה גוברת על הרשאה                            |
| `geminiSanitization`             | `true`                                       | הסרת מילות המפתח של JSON-Schema ש-Gemini דוחה מסכמות כלים (כלי `$ref` מועברים ללא שינוי) |
| `apiFormat.allowAnthropic`       | `false`                                      | ניתוב מזהים מרשימת ההרשאה דרך בלוק ה-API של Anthropic                                    |
| `apiFormat.anthropicModels`      | `[]`                                         | מזהי מודלים מלאים המנותבים ל-Anthropic                                                   |
| `logLevel` / `startupDebug`      | `warn` / `false`                             | רמת הפירוט של יומן הרישום                                                                |

## כיצד הקטלוג נשאר עדכני

הקטלוג נשלף באופן עצל ונשמר במטמון למשך `modelCacheTtlMs`, ותמונת מצב בדיסק שומרת את
הקטלוג האחרון שהיה ידוע כזמין כאשר לא ניתן להגיע לשער — תקלה אינה עולה לכם בדבר מלבד
עדכניות. מודלים ושילובים מתפרסמים ברגע שהם מגיעים; שילובים אוטומטיים, רשימת הספקים
ושכבת ההעשרה משולבים עם הגעתם, כך שנקודת קצה איטית אחת אינה יכולה לעכב את
כל בורר המודלים.

השמות כוללים את מה שידוע לשער: הספק במעלה הזרם שאליו מנותב מודל, סמן `[Free]`
והתקציב הנלווה אליו — כך ששני חיבורים שמציעים את אותו מודל נשארים
ניתנים להבחנה. השביתו את התחילית באמצעות `"providerTag": false`.

אין פקודת רענון ידנית: פקודות OpenCode v2 הן תבניות הנחיה, לא פונקציות חזרה,
ולכן תוסף אינו יכול לחשוף פקודה כזו. הרענונים מתבצעים בהתאם ל-TTL; המארח מתבקש לטעון מחדש רק כאשר
הקטלוג או שכבת העל השתנו בפועל, ולעולם לא פעם אחת בכל רענון.

## קריאה לכלים ב-Gemini

Gemini דוחה בקשה שלמה שהצהרות הכלים שלה כוללות `$schema` או
`additionalProperties`, ומחזיר `400 INVALID_ARGUMENT`. התוסף מסיר מילות מפתח אלה
מסכמות כלים המיועדות למודל Gemini של ספק זה, ומשאיר כל בקשה אחרת ללא שינוי.
כלי שמכיל `$ref` מועבר ללא שינוי במקום לעבור הסרה, מכיוון שהסרת
ההפניה תרחיב את הסכמה לכדי "קבלת כל דבר".
הגדירו `"geminiSanitization": false` כדי להשבית זאת.

| ------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| הבורר אינו מציג מודל OmniRoute              | לא נמצא מפתח (בדקו את אזהרת האתחול), או שלא ניתן להגיע לשער                                          |
| מזהי מודלים גולמיים, ללא שילובים וללא תמחור | נקודות הקצה הניהוליות דחו את האסימון — הגדירו `managementReadToken`                                  |
