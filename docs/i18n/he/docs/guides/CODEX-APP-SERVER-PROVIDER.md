OmniRoute מציעה **שתי** דרכים להשתמש ב-OpenAI Codex:

| ספק                    | כיצד הוא מתקשר עם OpenAI                                                                                                                                                          | הסתייגות בנוגע לשימוש                                      |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| **`codex`**            | מעביר מחדש את אסימון ה-OAuth של ChatGPT/OpenAI ישירות אל Responses API                                                                                                            | **כן** — ההפעלה הרשמית אינה מורשית לשימוש דרך proxy/router |
| **`codex-app-server`** | מפעיל את **`codex app-server` של Codex CLI עצמו** באמצעות JSON-RPC/WebSocket; ה-CLI מנהל ומרענן בעצמו את ה-OAuth שלו (`~/.codex/auth.json`), בדיוק כמו הפעלת `codex` אינטראקטיבית | **לא** — OmniRoute לעולם אינה מעבירה מחדש אסימון אל ה-API  |

מכיוון ש-`codex-app-server` לעולם אינו מעביר מחדש אסימון, הסתייגת השימוש
הנוגעת להעברה מחדש של הפעלה אינה חלה עליו. הוא כן דורש **Codex CLI נגיש בכתובת
ה-URL המוגדרת של ה-app-server**, ועל ה-CLI הזה להיות **מחובר לחשבון**.

## 1. ארכיטקטורה

```
┌─ אפליקציית OmniRoute ────────────┐        ┌─ שירות צד codex-app-server ─────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ אסימון יכולת)                │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  מנהל בעצמו את ה-OAuth של OpenAI   │
└──────────────────────────────────┘        │  (~/.codex/auth.json, רענון אוטומטי)│
        │ משותף (אמצעי אחסון של compose)     └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → אסימון יכולת ה-WS (שניהם מעגנים אותו)
  codex-appserver-home    → ~/.codex (ה-dashboard כותב את auth.json,
                             וה-codex app-server של שירות הצד קורא אותו)
```

- שירות הצד מאזין **רק** ברשת compose הפנימית
  (`ws://codex-app-server:1456`), מאחורי אסימון יכולת. הוא **לעולם אינו**
  נחשף במארח או באינטרנט.
- ה-Codex CLI מובנה בתוך `omniroute:base`, ולכן אין צורך להתקין את codex
  במארח או במחשב המשתמש בעת הפעלת שירות הצד.

## 2. הפעלה

```bash
# הפעילו את המערך עם פרופיל שירות הצד codex app-server:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

שירות הצד יוצר את אסימון יכולת ה-WS שלו באתחול הראשון (בתוך אמצעי האחסון המשותף
`codex-appserver-token`), והאפליקציה קוראת את אותו האסימון באמצעות
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE`. אין צורך בהגדרה ידנית של האסימון.

## 3. התחברות + כניסה לחשבון

1. ב-dashboard, הוסיפו חיבור עבור **OpenAI Codex (App-Server)**. אין צורך במפתח
   API או באסימון (זהו ספק ללא אימות — שירות הצד אחראי לאימות).
2. אם ה-Codex CLI של שירות הצד **עדיין אינו מחובר לחשבון**, בדיקת תקינות
   החיבור מדווחת _"פועל אך לא מחובר לחשבון"_ (ולא שגיאת אימות אדומה). השתמשו
   באפשרות **כניסה באמצעות ChatGPT**: פעולה זו מפעילה בדפדפן את תהליך
   ה-device-OAuth הרגיל של Codex, ולאחר מכן כותבת את `~/.codex/auth.json` לתוך
   אמצעי האחסון המשותף באמצעות **החלת אימות** (אותה כניסה משרתת הן את ספק
   `codex` והן את ספק `codex-app-server`).
3. לאחר הכניסה לחשבון, בדיקת התקינות הופכת לירוקה (היא מאמתת גם את `/readyz`
   **וגם** את `account/read` — כלומר, שהשירות פעיל _וגם_ מאומת) ומתחילה לעבוד.

ה-dashboard לעולם אינו דורס קובץ `~/.codex/auth.json` קיים ותקין — הוא כותב
רק כאשר הקובץ חסר או כאשר האסימון שלו מיושן (תמיד נוצר גיבוי).

## 4. תרחישי פריסה

- **מפעיל עם Codex CLI שכבר מחובר לחשבון** — עגנו את `~/.codex` מהמארח
  אל שירות הצד (`codex-appserver-home`) ודלגו על שלב הכניסה לחשבון.
- **משתמש ציבורי ללא התקנה מקומית של codex** — לא רלוונטי: שירות הצד כולל את
  ה-CLI. המשתמש מבצע אימות רק דרך ה-dashboard.
- **OmniRoute על bare-metal (ללא שירות צד, עם codex במארח)** — הגדירו את
  `OMNIROUTE_CODEX_APPSERVER_WS` כך שיצביע אל `codex app-server` משלכם, וודאו
  שה-codex במארח מחובר לחשבון; הרמז "codex אינו מותקן" מופיע אם קובץ ההרצה
  חסר.

## 5. תעבורה יוצאת ביתית / UDP (תוספת למפעיל, אינה כלולה)

שירות הצד הגנרי שלעיל מוציא תעבורה דרך הרשת הרגילה של הקונטיינר. מפעיל
שזקוק לכך שתעבורת Codex תצא דרך **נקודת יציאה ביתית** (למשל שירות צד מסוג TUN
של tailscale שמעביר TCP + UDP/QUIC) מפעיל זאת כדריסת compose נפרדת; היא
**אינה** חלק מפרופיל `codex-app-server` המסופק, במכוון. עיינו בספר הנהלים
הפנימי לתפעול לקבלת פרטים על הגדרה זו.
