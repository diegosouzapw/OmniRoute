> **לוח בקרה:** הגדרות ← **AI** ← תקציב חשיבה  
> **API:** `GET` / `PUT` `/api/settings/thinking-budget`  
> **מקור:** `open-sse/services/thinkingBudget.ts`

תקציב החשיבה קובע אם OmniRoute **משכתב פרמטרים של חשיבה/הסקה שנשלחו מהלקוח** בדרכם לספקים. הוא **אינו** מפעיל או מכבה דחיסה, ניתוב או מטמון פרומפטים.

## מצבים

| מצב                            | מה OmniRoute עושה                                                                                                          | מתי להשתמש                                                                                                                         |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **`passthrough`** (ברירת מחדל) | משאיר את שדות הלקוח ללא שינוי (`reasoning`, `reasoning_effort`, ‏`thinking` של Claude, ‏`thinking_config` של Gemini וכו'). | **Codex / Desktop / כל לקוח שאמור לשלוט ברמת המאמץ ובסיכומי ההסקה.** נדרש להצגת חלוניות חשיבה כאשר הלקוח מבקש `reasoning.summary`. |
| **`auto`**                     | **מסיר את כל** שדות החשיבה/ההסקה מגוף הבקשה לפני העברתה לשירות החיצוני.                                                    | רק כאשר רוצים במכוון שה**ספק** יקבע ערכי ברירת מחדל, ואין צורך בחשיבה הנשלטת בידי הלקוח. **אין** פירושו „הצג חשיבה אוטומטית”.      |
| **`custom`**                   | מחליף את הערכים בכל בקשה בתקציב קבוע של אסימוני חשיבה.                                                                     | הגבלה קשיחה של אסימוני החשיבה לכל התעבורה.                                                                                         |
| **`adaptive`**                 | מתאים את התקציב מרמת מאמץ בסיסית לפי מספר ההודעות, הכלים ואורך הפרומפט.                                                    | בקרה גמישה על האסימונים בלי להסיר לחלוטין את כוונת הלקוח.                                                                          |

### מה `auto` מסיר

כאשר המצב הוא `auto`, הפונקציה `stripThinkingConfig()` מוחקת (בין היתר):

- OpenAI / Responses: ‏`reasoning`, ‏`reasoning_effort`
- Claude: ‏`thinking`, וגם `output_config.effort` כאשר הוא קיים
- Gemini: ‏`generationConfig.thinking_config` / ‏`thinkingConfig`

אם לקוח (למשל Codex Desktop) שלח `reasoning: { effort: "ultra", summary: "detailed" }`, מצב **auto מסיר את האובייקט הזה**. השירות החיצוני עדיין עשוי לחייב עבור אסימוני הסקה מסוימים, אך לעיתים קרובות הוא מחזיר פריטי הסקה **ריקים או מוצפנים בלבד** — ולכן ממשק המשתמש אינו מציג זרם חשיבה שימושי.

## מה זה **לא**

| תכונה                                       | קשר                                                                                                                     |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| **דחיסה** (Caveman, RTK, stacked, …)        | צינור עיבוד נפרד. פועל בכל מצב של תקציב חשיבה.                                                                          |
| **מטמון פרומפטים / מטמון סמנטי**            | נפרד. אינו מושפע ממצב תקציב החשיבה.                                                                                     |
| **ניתוב משולב / חלופות**                    | נפרד. אינו מושפע.                                                                                                       |
| **מגבלות אסימונים למפתח API / תקציבי עלות** | נפרד. אינו מושפע.                                                                                                       |
| **מטמון הפעלה חוזרת של הסקה**               | הזרקה מחדש מרובת סבבים עבור ספקים מחמירים (DeepSeek, Kimi, Qwen-thinking, …). אינו זהה ל„הצגת חשיבה” ב-Desktop.         |
| **פענוח `encrypted_content`**               | **בלתי אפשרי.** נתוני ההסקה הפרטיים של OpenAI/Codex הם אטומים. OmniRoute לעולם אינו מפענח אותם (#7095 / #7176 / #7304). |

## חשיבה גלויה (לקוחות Codex / Responses)

כדי שלקוח יציג טקסט חשיבה, נדרשים **כל** התנאים הבאים:

1. מצב תקציב החשיבה = **`passthrough`** (או `custom`/`adaptive` שעדיין משאיר את בקשות הסיכום ללא שינוי במידה מספקת לנתיב שבו אתם משתמשים).
2. הלקוח מבקש סיכום, לדוגמה Codex עם `model_reasoning_summary = "detailed"` / `auto` (ולא `none`).
3. השירות במעלה הזרם אכן מזרים `response.reasoning_summary_text.*` (או `reasoning.summary` שאינו ריק בפריט).

אם אתם מקבלים רק „חשיבה פרטית מוצפנת”, הסיבה היא אחת מהבאות:

- המצב היה **`auto`** (בקשת הלקוח הוסרה), או
- השירות במעלה הזרם החזיר `encrypted_content` ללא טקסט סיכום (מגבלה של הספק; OmniRoute יכול להציג רק מציין מקום, לא טקסט גלוי).

## דוגמאות API

```bash
# קריאה
curl -sS https://localhost:20128/api/settings/thinking-budget \
  -H "Authorization: Bearer $OMNIROUTE_TOKEN"

# מומלץ לנראות החשיבה ב-Codex / Desktop
curl -sS -X PUT https://localhost:20128/api/settings/thinking-budget \
  -H "Authorization: Bearer $OMNIROUTE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"mode":"passthrough","customBudget":10240,"effortLevel":"medium"}'
```

סכמה (`updateThinkingBudgetSchema`): ‏`mode` ∈ `passthrough|auto|custom|adaptive`; אופציונליים: `customBudget`,‏ `effortLevel`,‏ `baseBudget`,‏ `complexityMultiplier`.

### התמדה / הפעלה מחדש

הערך נשמר תחת מפתח ההגדרות `thinkingBudget` ונטען בעת הפעלת התהליך (`hydrateThinkingBudgetConfig`). לאחר שינוי דרך מסד הנתונים או דרך נתיבים מסוימים שאינם API, יש **להפעיל מחדש את תהליך OmniRoute** כדי שמופע היחיד בזיכרון יתאים לערך שבדיסק.
