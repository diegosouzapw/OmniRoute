## 1. Antigravity לעומת Antigravity CLI (agy)

שני הספקים משתמשים באותו **צד שרת של Google** — לקוח OAuth זהה, רענון אסימונים זהה, נקודות קצה זהות ואותם חשבונות Google. ההבדל הוא אילו מודלים מוצגים לכם.

> להשוואה הרשמית של Google, ראו את [ההכרזה על Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli).

| היבט                       | `antigravity` (IDE)                                 | `agy` (CLI)                                              |
| -------------------------- | --------------------------------------------------- | -------------------------------------------------------- |
| **מוצר Google**            | Antigravity 2.0 / Antigravity IDE                   | Antigravity CLI                                          |
| **צד שרת**                 | אותו Google Cloud Code API                          | אותו Google Cloud Code API                               |
| **OAuth / אסימון**         | אותו לקוח, אותו רענון                               | אותו לקוח, אותו רענון                                    |
| **קטלוג מודלים**           | רשימה סטטית שנבחרה מראש (מקודדת ישירות ב-OmniRoute) | נבדק בזמן אמת מול Google באמצעות `:fetchAvailableModels` |
| **מודלי Claude**           | Sonnet 4.6,‏ Opus 4.6 (ארבע גרסאות לכל אחד)         | Sonnet 4.6,‏ Opus 4.6 (ארבע גרסאות לכל אחד)              |
| **שמות Gemini**            | תוויות נקיות (נמוכה/בינונית/גבוהה)                  | מזהים ממערכת המקור (extra-low/low/agent)                 |
| **מודלים נוספים**          | `gpt-oss-120b-medium`                               | עשוי לכלול מודלים נוספים מ-Google                        |
| **תרחיש שימוש ברירת מחדל** | שילוב ב-IDE ‏(VS Code,‏ JetBrains)                  | גישה דרך CLI / API                                       |
| **מכסה**                   | משותפת עם agy (אותו חשבון Google)                   | משותפת עם antigravity (אותו חשבון Google)                |

**מודלים זמינים (אומתו בניסוי, 2026-07-29)**:

- Gemini:‏ 3.6 Flash,‏ 3.5 Flash,‏ 3.1 Pro,‏ 3 Flash,‏ 2.5 Flash (רמות חשיבה שונות)
- Claude:‏ Sonnet 4.6,‏ Opus 4.6 (כל אחד עם גרסאות default/low/medium/high)
- אחרים: GPT-OSS 120B Medium
- **Claude Sonnet 5 אינו זמין** — רק גרסאות 4.6 נתמכות

**מדוע קטלוג המודלים שונה**: ה-CLI של Google "מותאם למהירות ולתקורה נמוכה" ו"עבר מיטוב משותף עם מודלי Gemini" (לפי הבלוג הרשמי של Google). מוצר ה-Web/IDE "מותאם למקיפות". ה-CLI משתמש ב-`:fetchAvailableModels` כדי לגלות מודלים באופן דינמי, בעוד שה-IDE משתמש ברשימה סטטית שנבחרה מראש.

**בפועל**: השתמשו בקידומת `agy/` עבור מודלי Gemini (לדוגמה, `agy/gemini-3.7-flash-high`). השתמשו ב-`antigravity/` עבור הרשימה הסטטית שנבחרה מראש. שניהם פונים לאותו צד שרת של Google, אך מציגים שמות מודלים שונים. המכסה משותפת — שימוש בכל אחד מהספקים נחשב במסגרת המגבלות של אותו חשבון Google.

## 2. Google One AI Pro: מערכת מכסות

> לפרטים רשמיים על המכסות, ראו [מסמכי Antigravity: תוכניות](https://antigravity.google/docs/plans), ולעדכוני התמחור האחרונים ראו [שינויים בתוכניות Antigravity](https://antigravity.google/blog/changes-to-antigravity-plans).

Google Antigravity משתמשת ב**מכסה דו-שכבתית** המבוססת על "עבודה שבוצעה" (משקל חישובי), ולא על מספר ההודעות.

### שתי השכבות

| שכבה               | מהי                          | מחזור רענון                                                             |
| ------------------ | ---------------------------- | ----------------------------------------------------------------------- |
| **מקבץ של 5 שעות** | מאגר מיידי של "עבודה שבוצעה" | מתאפס 5 שעות לאחר הבקשה הראשונה בהפעלה                                  |
| **בסיס של 7 ימים** | תקרה שבועית קשיחה            | גובר על הרענון של 5 השעות אם התקרה הושגה; חוסם עד לתקופה הבאה של 7 ימים |

**כיצד מחושבת "עבודה שבוצעה"**: משימות עתירות-סוכנים (למשל, "שכתב את כל המאגר הזה") מנצלות את המכסה מהר הרבה יותר ממשימות פשוטות (למשל, "תקן את הפונקציה הזאת"). אין לוח מחוונים בזמן אמת שמציג את הצריכה.

### רמות תוכנית

| תוכנית       | מחיר          | מכסה                               | מגבלה שבועית                               |
| ------------ | ------------- | ---------------------------------- | ------------------------------------------ |
| חינם         | $0            | מכסה משמעותית, מתרעננת מדי שבוע    | כן                                         |

### מודלי Gemini לעומת מודלים שאינם Gemini

- **מודלי Gemini**‏ (Flash + Pro): חולקים מגבלת קצב אחת, המנוצלת בהתאם לתמחור ה-API. אם Flash זול פי 8 מ-Pro, תקבלו פי 8 יותר אסימוני Flash.
- **מודלים שאינם Gemini**‏ (Claude, GPT-OSS): כוללים מגבלות קצב **נפרדות**. הם עשויים להישאר זמינים גם כאשר Gemini חסום.

### נקודות זכות ל-AI (חריגה)

> למידע על אופן הפעולה של נקודות הזכות, ראו [נקודות זכות ל-AI ב-Google One](https://support.google.com/googleone/answer/14534406).

כאשר מכסת הבסיס מוצתה:

- **לעולם לא**: יש להמתין לרענון המכסה; מוצגת ההודעה "הגעת למכסת מודל הבסיס"
- **תמיד**: שימוש אוטומטי בנקודות זכות ל-AI; חזרה למכסת הבסיס כאשר היא מתרעננת

נקודות הזכות נרכשות בנפרד ומנוכות בהתאם לתמחור ה-API הרגיל.

### פרטים מרכזיים

- המכסה **משותפת ברמת החשבון** — אותו חשבון Google ב-Antigravity IDE, ב-CLI וב-OmniRoute חולק מאגר מכסה אחד
- לכל חשבון Google יש מכסה עצמאית משלו — מספר חשבונות = מספר מאגרי מכסה
- משתמשי AI Pro דיווחו על **חסימות למשך 7 ימים** במקום איפוס לאחר 5 שעות כאשר מכסת הבסיס השבועית הושגה (Google אישרה שזה מכוון בתקופות של ביקוש גבוה)

**כאשר המכסה בחשבון שלכם מוצתה**: OmniRoute מנסה שוב באופן אוטומטי באמצעות החשבון הזמין הבא בנתיב המשולב. אין צורך בהתערבות ידנית.

## 3. כיצד להשיג projectId

כל חיבור antigravity/agy זקוק ל-`projectId` של Google Cloud Code. בלעדיו, נקודת הקצה `/v1internal:models` מחזירה 404.

### שיטה א׳: אוטומטית (מומלץ)

OmniRoute מטפל בכך באופן אוטומטי. כאשר מוסיפים חשבון Google חדש באמצעות OAuth בלוח המחוונים:

1. OmniRoute מרענן את האסימון
2. קורא ל-`loadCodeAssist` כדי לגלות את ה-projectId
3. אם לא קיים פרויקט, קורא ל-`onboardUser` כדי ליצור אחד
4. מנסה שוב את `loadCodeAssist` כדי לקבל את ה-projectId החדש שנוצר
5. שומר אותו במסד הנתונים

**שיטה זו פועלת ברוב החשבונות** — אין צורך בצעדים ידניים.

### שיטה ב׳: ידנית באמצעות agy CLI

אם הגילוי האוטומטי נכשל (ראו סעיף 5 כדי להבין מתי זה קורה):

```bash
# התקנת agy CLI (אם הוא עדיין לא מותקן)
npm install -g @anthropic-ai/agy

# התחברות באמצעות חשבון Google שלכם
agy login

# בחירת החשבון שצריך לצרף
# פעולה זו מפעילה את הרישום ל-Cloud Code ומקצה projectId
```

לאחר שהפקודה `agy login` מסתיימת בהצלחה, רעננו את האסימון בלוח המחוונים של OmniRoute. ה-projectId יתגלה באופן אוטומטי.

### כיצד לאמת

בדקו את מסד הנתונים:

```bash
# בתוך הקונטיינר של OmniRoute
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

לחלופין, בדקו את היומנים:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. URI להפניה מחדש של OAuth

### הבעיה

Google OAuth דורש URI תקין להפניה מחדש. ברירת המחדל של OmniRoute משתמשת ב-`http://127.0.0.1:20128/callback` (לולאה חוזרת). הגדרה זו פועלת עבור גרסאות build מקומיות, אך **נכשלת בפריסות מרוחקות** (למשל, שרת שניגשים אליו באמצעות כתובת IP ברשת LAN).

Google דוחה כתובות URI להפניה מחדש אשר:

- משתמשות בכתובות IP (חובה להשתמש בדומיין שמסתיים ב-`.com`, ב-`.org` וכו')
- אינן תואמות לכתובות ה-URI להפניה מחדש הרשומות בתצורת לקוח ה-OAuth

### הפתרון

**אפשרות A: שימוש בתהליך ה-OAuth המובנה (ברירת המחדל)**

- פועל כאשר ניגשים ל-OmniRoute דרך `localhost` או `127.0.0.1`
- אין צורך בהגדרה

**אפשרות B: פרטי זיהוי מותאמים אישית של OAuth**

- הגדירו `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` בסביבה שלכם
- ספקו פרטי זיהוי משלכם עבור Google OAuth:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- רשמו את `https://your-domain.com/callback` כ-URI מורשה להפניה מחדש ב-Google Cloud Console

**אפשרות C: שימוש ב-CLI של agy להתחברות הראשונית**

- הריצו `agy login` במחשב שממנו תתבצע הגישה ל-OmniRoute
- תהליך ה-OAuth יושלם באופן מקומי והאסימונים יישמרו
- ייבאו את החיבור אל OmniRoute באמצעות לוח הבקרה

### מגבלות

- פרטי זיהוי מותאמים אישית של OAuth דורשים שם דומיין (Google אינה מקבלת כתובות IP ככתובות URI להפניה מחדש)
- אם אין לכם דומיין, השתמשו במקום זאת באפשרות A או C

## 5. פתרון בעיות: כאשר ההגדרה האוטומטית נכשלת

OmniRoute מטפל באופן אוטומטי באיתור projectId ובקליטה הראשונית עבור רוב החשבונות. כאשר התהליך נכשל, הסיבה העיקרית היא בדרך כלל אחת מהבאות:

### אזור החשבון חסום

**תסמין**: `agy login` מחזיר "בדיקת הזכאות נכשלה: החשבון הנוכחי שלך אינו זכאי ל-Antigravity, מכיוון שהוא אינו זמין כעת במיקומך."

**סיבה עיקרית**: לחשבונות Google יש שדה "Country Association" בצד השרת, המוגדר בעת ההרשמה. ה-CLI של agy וה-API של Cloud Code בודקים שדה זה באופן מחמיר — בשונה מגרסת האינטרנט של Gemini, שבודקת רק את כתובת ה-IP הנוכחית שלכם.

> כדי לבדוק או לשנות את האזור המשויך לחשבון שלכם, בקרו ב-[טופס שיוך המדינה של Google](https://policies.google.com/country-association-form).

**מדוע גרסת האינטרנט של Gemini פועלת אך agy אינו פועל**:

- גרסת האינטרנט של Gemini / Google One: בודקת רק את כתובת ה-IP הנוכחית (Proxy עובר את הבדיקה)
- ה-CLI של agy / ה-API של Cloud Code: קוראים את השדה Country Association בצד השרת (Proxy אינו עוזר)

**תיקון**:

1. בקרו ב-[טופס שיוך המדינה של Google](https://policies.google.com/country-association-form) כאשר אתם משתמשים בכתובת IP אמריקאית
2. שלחו בקשה לשינוי אזור (בחרו "אני גר במדינה אחרת")
3. המתינו 1-24 שעות לעיבוד הבקשה על ידי Google ולקבלת הודעה בדוא"ל
4. לאחר מכן, `agy login` אמור להצליח

### לחשבון אין פרויקט Cloud Code

**תסמין**: ביומנים מופיעות ההודעות `loadCodeAssist returned no project id` ו-`onboardUser failed (400)`.

**סיבה עיקרית**: החשבון מעולם לא נרשם ב-Google Cloud Code, והקליטה האוטומטית נכשלה.

**תיקון**: הריצו את `agy login` באופן ידני כדי להפעיל את הרישום ל-Cloud Code, ולאחר מכן רעננו את האסימון בלוח הבקרה של OmniRoute.

### תוקף האסימון פג או שהוא בוטל

**תסמין**: שגיאות 401 ביומנים, או הודעות "תוקף האסימון פג".

**תיקון**: רעננו את האסימון דרך לוח הבקרה → ספקים → agy → לחצו על סמל הרענון. אם אסימון הרענון עצמו בוטל, יהיה עליכם לבצע אימות מחדש באמצעות OAuth.

## תרשים זרימת החלטות

```
החשבון לא עובד?
│
├─ האם יש לו projectId במסד הנתונים?
│  ├─ כן → הבעיה נמצאת במקום אחר (תוקף האסימון פג, מגבלת קצב וכו')
│  └─ לא ↓
│
├─ האם שיוך המדינה של החשבון מוגדר לאזור מוגבל?
│  ├─ כן → יש לשנות את האזור בטופס שיוך המדינה של Google
│  │         (https://policies.google.com/country-association-form)
│  │         יש להמתין 1-24 שעות ולאחר מכן לנסות שוב
│  └─ לא ↓
│
├─ האם לחשבון יש מינוי Google One AI Pro?
│  ├─ לא → תחילה יש להירשם ב-one.google.com
│  └─ כן ↓
│
├─ יש לנסות גילוי אוטומטי (רענון האסימון בלוח הבקרה)
│  ├─ עובד → הושלם
│  └─ עדיין נכשל ↓
│
└─ באופן ידני: יש להריץ `agy login` במחשב
   ├─ עובד → יש לרענן את האסימון בלוח הבקרה, וה-projectId יתגלה
   └─ נכשל → יש לבדוק את הודעת השגיאה; סביר להניח שמדובר בבעיה באזור או במינוי
```
