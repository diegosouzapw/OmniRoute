כיצד OmniRoute מעריך, מתעד ומדווח על העלות של כל בקשה — ומדוע המספר
בלוח המחוונים הוא **מדד לחיסכון**, ולא חשבון לתשלום.

ראו גם: [מדריך למשתמש](./USER_GUIDE.md) · [גלריית התכונות](./FEATURES.md)

## מה זה (ומה זה לא)

OmniRoute מייחס עלות בדולר ארה״ב לכל בקשה שהושלמה, באמצעות הכפלת מספר
הטוקנים בתעריפי המודל. מספרים אלה משמשים את לוח המחוונים **עלויות**, את פקודות
ה-CLI‏ `omniroute cost` / `omniroute usage`, את ייצואי ה-CSV/JSON ואת התקציבים לכל מפתח API.

> **ה״עלות״ בלוח המחוונים היא מדד לחיסכון, ולא חשבון לתשלום.** OmniRoute לעולם אינו מחייב אתכם
> — הוא מנתב את הבקשות שלכם לספקים שכבר חיברתם (המינויים שלכם,
> מסלולים חינמיים ומפתחות API). ״עלות כוללת של $290״ שנצברה כולה במודלים חינמיים
> פירושה בקירוב **$290 שלא שילמתם** ל-API בתשלום. הנתון הוא _אומדן_
> של העלות שהייתה לאותה תעבורה לפי מחירי המחירון הרגילים, כדי שתוכלו לראות היכן
> מרוכז השימוש שלכם וכמה אתם חוסכים באמצעות ניתוב לספקים זולים או חינמיים יותר.

הסבר זה מופיע ישירות ב-[README](../../README.md) של הפרויקט (״ה׳עלות׳ בלוח המחוונים
היא מדד לחיסכון, ולא חשבון לתשלום״).

מכיוון שהמספר הוא אומדן:

- הוא תלוי בטבלת התמחור של OmniRoute עבור כל מודל. מודל ללא רשומת תמחור
  תורם עלות של `0` (הוא מופיע כשורת ״ישן / חינמי״ בסייר).
- תעבורה במסלול חינמי או במסגרת מינוי עדיין צוברת עלות _משוערת_ — זהו
  הסכום שאתם חוסכים, ולא סכום שאתם חייבים.

## כיצד העלויות מוערכות

### מקור התמחור

העלויות מגיעות מטבלת תמחור שנבחרת לפי סדר העדיפויות הבא
([`src/lib/pricingSync.ts`](../../src/lib/pricingSync.ts)):

1. **דריסות משתמש** — מחירים שאתם מגדירים בלוח המחוונים / באמצעות `PATCH /api/pricing`.
2. **תמחור חיצוני מסונכרן** — נמשך מהקובץ הציבורי
   `model_prices_and_context_window.json` של LiteLLM כאשר הסנכרון מופעל (נשמר במרחב שמות נפרד
   `pricing_synced`, כך שלעולם אינו דורס את ההגדרות שלכם).
3. **ברירות מחדל מקודדות מראש** — מסופקות עם OmniRoute.

סנכרון תמחור חיצוני הוא **אופציונלי**, ומושבת כברירת מחדל. משתני הסביבה הרלוונטיים
(ראו [`.env.example`](../../.env.example)):

| משתנה סביבה             | ברירת מחדל | מטרה                                                  |
| ----------------------- | ---------- | ----------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`    | הפעלת סנכרון התמחור של LiteLLM ברקע בעת ההפעלה.       |
| `PRICING_SYNC_INTERVAL` | `86400`    | מרווח הסנכרון ב**שניות** (ברירת המחדל היא פעם ביום).  |
| `PRICING_SYNC_SOURCES`  | `litellm`  | רשימת מקורות מופרדת בפסיקים (כיום נתמך רק `litellm`). |

### נוסחת העלות

העלות מחושבת לכל בקשה לפי מספרי הטוקנים והתעריפים למיליון טוקנים המוגדרים ב-
[`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts)
(`computeCostFromPricing` / `calculateCost`):

- **טוקני קלט** (בניכוי קריאות מהמטמון וטוקנים ליצירת מטמון) × תעריף `input`.
- **טוקנים שנקראו מהמטמון** × תעריף `cached` (אם אינו מוגדר, נעשה שימוש בתעריף הקלט).
- **טוקנים ליצירת מטמון** × תעריף `cache_creation` (אם אינו מוגדר, נעשה שימוש בתעריף הקלט).
- **טוקני פלט** × תעריף `output`.
- **טוקני חשיבה** × תעריף `reasoning` (אם אינו מוגדר, נעשה שימוש בתעריף הפלט).

כל התעריפים מפורשים כדולר ארה״ב לכל 1,000,000 טוקנים. שכבת שירות Codex מסוג `"fast"`/`"priority"` או
`"flex"` מחילה מכפיל עלות (`getCodexFastCostMultiplier`) — לדוגמה, flex
מחויב בהנחה של 50% על הטוקנים, המוצגת כ**חיסכון flex** בלוח המחוונים.

שמות המודלים מנורמלים תחילה (תחיליות של נתיבי ספק, כגון `openai/` או
`accounts/fireworks/models/`, מוסרות), כך שגם שורות היסטוריות עדיין מותאמות למחיר.

### כיצד ההוצאה מתועדת

- העלות לכל בקשה מחושבת לאחר התגובה ומתועדת בשיטת שגר ושכח, כך שהיא
  לעולם אינה מוסיפה השהיה ללקוח. צריכת מכסה משותפת מתוזמנת לאיטרציה הבאה
  של לולאת האירועים באמצעות [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts).
- ההוצאה לפי מפתח API נאגרת ונכתבת בקבוצות באמצעות
  [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (מרווח כתיבה של 60 שניות כברירת מחדל,
  ומאגר של 1,000 רשומות). ניתן לכוונן זאת באמצעות:

  | משתנה סביבה                         | ברירת מחדל | מטרה                                 |
  | ----------------------------------- | ---------- | ------------------------------------ |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000`    | מרווח הכתיבה באלפיות שנייה.          |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`     | מספר הרשומות המרבי במאגר לפני כתיבה. |

נתוני העלות בלוח המחוונים **אינם** נקראים מסכום דולרי השמור בכל שורה — הם
מחושבים מחדש בזמן אמת על בסיס מספרי הטוקנים וטבלת התמחור הנוכחית בכל פעם
שנקודת הקצה לניתוח נתונים מופעלת. משמעות הדבר היא שתיקון מחיר שגוי (וסנכרון מחדש) מעדכן
בדיעבד את אומדני העלות ההיסטוריים.

## לוח הבקרה: דף העלויות

הדף **עלויות** נמצא ב-`/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`).
התצוגה הראשית שלו היא הלשונית **סקירת עלויות**
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`),
שטוענת את כל הנתונים מ-`GET /api/usage/analytics`.

מה מוצג בו:

- **אריחי הוצאות** — הוצאה משוערת עבור _היום (1d)_, _7d_, _30d_ וטווח הזמן
  שנבחר. בורר טווח: `7d`, `30d`, `90d`, `all`.
- **מדדים מרכזיים** — בקשות בטווח הזמן, ספקים פעילים, מודלים פעילים ועלות ממוצעת
  לבקשה.
- **סייר העלויות** — טבלה הניתנת למיון ולסינון, המקובצת לפי **ספק**, **מודל**,
  **מפתח API**, **חשבון** או **רמת שירות**, ומציגה עלות, בקשות, טוקנים, עלות ממוצעת
  לבקשה ואחוז מסך העלות.
- **שימוש בטוקנים** — סך הכול / טוקני קלט / טוקני פלט ויחס קלט:פלט.
- **יעילות ניתוב** — מספר המעברים לחלופה, שיעור המעברים לחלופה וכיסוי המודל המבוקש.
- **תחזית חודשית** — חוזה את ההוצאה בסוף החודש לפי הממוצע היומי האחרון.
- **השוואת תקופות** — אחוז השינוי בין המחצית הראשונה למחצית השנייה של טווח הזמן.
- **תרשימים** — מגמת עלות יומית, נתח לפי ספק (תרשים עוגה), ספקים מובילים, מודלים מובילים, עלות
  לפי מפתח API, עלות לפי חשבון, דפוס שימוש שבועי ומפת חום של פעילות.
- **ייצוא** — הורדת טווח הזמן הנוכחי כ-**CSV** או כ-**JSON** (הכפתורים מופיעים
  ברגע שקיימים נתוני עלות שאינם אפס).

כאשר אין תעבורה מתומחרת, השורות מוצגות עם התווית "ישן / חינם" במקום `$0`,
בהתאם למודל מעקב החיסכון.

### דפי משנה קשורים של עלויות

אזור העלויות כולל גם את הדפים הבאים (כולם תחת `/dashboard/costs/`):

- **תמחור** (`/dashboard/costs/pricing`) — הצגה ודריסה של מחירים לכל מודל (מציג
  את לשונית התמחור המשותפת).
- **תקציב** (`/dashboard/costs/budget`) — הגדרת מגבלות הוצאה לכל תחום (מציג את לשונית
  התקציב המשותפת).
- **שיתוף מכסה** (`/dashboard/costs/quota-share`) — מאגרי מכסות משותפות ותצוגות של קצב
  ניצול.

## נקודות קצה של API

כל אלה דורשים אימות ניהול (loopback/JWT, באמצעות `requireManagementAuth`), אלא אם
צוין אחרת.

### ניתוח שימוש ועלויות

| שיטה  | נקודת קצה                | מטרה                                                                                                                                            |
| ----- | ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET` | `/api/usage/analytics`   | ניתוח מלא של עלויות/שימוש: סיכום, מגמה יומית, לפי ספק/מודל/מפתח API/חשבון/רמה. שאילתה: `range`, `startDate`, `endDate`, `apiKeyIds`, `presets`. |
| `GET` | `/api/usage/utilization` | ניצול מכסה לאורך זמן לכל ספק. שאילתה: `range` (`1h`/`24h`/`7d`/`30d`), `provider`.                                                              |
| `GET` | `/api/usage/history`     | רשומות גולמיות של היסטוריית שימוש.                                                                                                              |
| `GET` | `/api/usage/call-logs`   | יומני קריאות לכל בקשה (מודל, טוקנים, עלות, השהיה, סטטוס).                                                                                       |
| `GET` | `/api/usage/quota`       | מצב מכסת הספק.                                                                                                                                  |
| `GET` | `/api/usage/proxy-logs`  | יומני בקשות Proxy.                                                                                                                              |

### תקציבים

| שיטה   | נקודת קצה                | מטרה                                                                          |
| ------ | ------------------------ | ----------------------------------------------------------------------------- |
| `GET`  | `/api/usage/budget`      | סיכום עלויות + בדיקת תקציב עבור מפתח API אחד (נדרש פרמטר השאילתה `apiKeyId`). |
| `POST` | `/api/usage/budget`      | הגדרת מגבלות יומיות/שבועיות/חודשיות בדולר ארה״ב + סף אזהרה עבור מפתח API.     |
| `GET`  | `/api/usage/budget/bulk` | סיכומי תקציב מרוכזים עבור מפתחות API.                                         |

> ה-API של התקציב מוגדר לכל **מפתח API** (`apiKeyId`). המגבלות שמוחזרות על ידי
> `GET /api/usage/budget` כוללות את `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`,
> את `warningThreshold` ואת הסכומים המצטברים (`totalCostToday`, `totalCostMonth`, …).

### תמחור

| שיטה     | נקודת קצה               | מטרה                                                                                                               |
| -------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `GET`    | `/api/pricing`          | התמחור הממוזג הנוכחי (משתמש + מסונכרן + ברירות מחדל). השתמשו ב-`?includeSources=1` כדי לראות את המקור של כל רשומה. |

| `DELETE` | `/api/pricing`          | איפוס התמחור לברירות המחדל (אפשר להגביל באמצעות `?provider=&model=`).                                              |
| `GET`    | `/api/pricing/defaults` | הצגת תעריפי ברירת המחדל החלופיים לכל מיליון.                                                                       |
| `GET`    | `/api/pricing/models`   | תמחור לפי מודל.                                                                                                    |
| `POST`   | `/api/pricing/sync`     | הפעלת סנכרון ידני ממקורות חיצוניים (LiteLLM).                                                                      |
| `GET`    | `/api/pricing/sync`     | מצב הסנכרון הנוכחי.                                                                                                |
| `DELETE` | `/api/pricing/sync`     | מחיקת כל נתוני התמחור המסונכרנים.                                                                                  |

### נקודות קצה נוספות הרלוונטיות לעלויות

| שיטה  | נקודת קצה                     | מטרה                                                           |

## CLI

ממשק שורת הפקודה של OmniRoute מספק פקודות לעלויות, שימוש ותמחור (הרשומות בקובץ
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)).

### `omniroute cost`

דוח עלויות מצטבר מ-`/api/usage/analytics`.

```bash
omniroute cost                          # 30 הימים האחרונים, מקובצים לפי ספק
omniroute cost --period 7d              # 7 הימים האחרונים
omniroute cost --group-by model         # קיבוץ לפי provider | model | combo | api-key | day
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

עמודות: קבוצה, בקשות, אסימוני קלט/פלט, עלות (USD) ואחוז מהסכום הכולל. שורת סיכום כוללת
מודפסת בסוף (אלא אם משתמשים ב-`--quiet` או ב-`--output json`).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # סיכום עלויות לפי ספק
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# תקציבים
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` קוראת את `GET /api/pricing/defaults`. כדי לערוך מחירים של מודלים
> בודדים במקום זאת, השתמשו בדף **תמחור** בלוח הבקרה או ב-`PATCH /api/pricing`.

## פתרון בעיות

- **כל העלויות מוצגות כ-$0 / "Legacy / Free".** למודלים שבשימוש אין רשומת תמחור.
  הפעילו סנכרון חיצוני (`PRICING_SYNC_ENABLED=true`) והריצו `omniroute pricing sync`, או
  הגדירו מחירים ידנית דרך דף התמחור / `PATCH /api/pricing`.
- **התמחור של מודל היסטורי שגוי.** תקנו את המחיר (באמצעות דריסה או סנכרון מחדש) — העלות
  מחושבת מחדש לפי מספר האסימונים בכל קריאה של נתוני הניתוח, כך שההערכות מתעדכנות רטרואקטיבית.
- **נתוני ההוצאה מפגרים אחרי הזמן האמיתי.** ההוצאות לכל מפתח מעובדות באצוות; הנמיכו את
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` אם דרושים לכם נתונים עדכניים יותר.
