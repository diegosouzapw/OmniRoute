`chatgpt-web-codex` (כינוי `cgpt-codex`) מגשר בין תורות של Codex Responses באמצעות
הפעלת דפדפן מאומתת של ChatGPT. הוא בלתי תלוי בספק המשותף `chatgpt-web`
שיצא משימוש, ומשתמש במימוש הכולל הודעת MIT תחת
`open-sse/vendor/codex-chatgpt-web/`, שעודכן בהתאם לגרסה v4.0.7 במעלה הזרם, בקומיט
`b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494`.

## הוצאת הספק המשותף משימוש

מזהי הספק המשותף הקודמים `chatgpt-web` ו-`cgpt-web` אינם נכללים עוד, מכיוון שלא
ניתן היה לאשר את מקור המימוש שלהם למפתח מקדים/הוכחת עבודה. בקשות מפורשות
לאחד מהמזהים, כולל מזהי מודלים עם קו נטוי בתחילתם וכינויים שמורים, נכשלות
באופן סגור עם HTTP `410` והקוד **PROVIDER_RETIRED** לפני כל בקשה למעלה הזרם.

המיגרציה `168_retire_chatgpt_web.sql` מסמנת כקברים חיבורי ספק תואמים
ומבטלת את חכירוֹת ההפעלה הפעילות שלהם. היא שומרת את היסטוריית החיבורים ואת
רשימות ההרשאה של מפתחות ה-API; היא אינה מוסיפה גישת תחליף לרשימת הרשאה. ספק Codex
והחיבורים שלו אינם נכללים בהוצאה זו משימוש.

## דרישות מוקדמות

- כותרת Cookie מלאה מהפעלת ChatGPT מחוברת;
- Chrome או Chromium, יחד עם הפעלה גרפית או תצוגת Xvfb, עבור התקנות npm,‏ systemd ו-PM2;
- עם פרופיל `web` של Docker, שירות Chromium הפנימי מתוך
  `docker-compose.yml`;
- ‏OpenAI `tunnel-client` v0.0.13 ומחבר מותאם אישית של ChatGPT עבור כלי Codex מקומיים.

המנהרה נדרשת רק עבור תורות הכוללים כלים. כל נתיב שמופיע ברשימה, כולל `pro`, יכול להשתמש
באותה יכולת כלי מקומית התחומה לתור, כאשר המנהרה והמחבר מוגדרים.

## הגדרה בלוח הבקרה

1. פתחו את הספק **ChatGPT Web (Codex)** והוסיפו חיבור.
2. הדביקו את כותרת ה-Cookie המלאה של ChatGPT, מזהה המנהרה, מפתח זמן הריצה ושם המחבר
   המותאם אישית. הגדרות חדשות התומכות בכלים חייבות להשתמש במחבר חדש שנוצר ושמו בדיוק
   `OmniRoute Codex v2`, כאשר Authentication מוגדר ל-None ו-Permissions מוגדר ל-Allow all
   actions.
3. הפעילו את בדיקת החיבור. OmniRoute פותח Temporary Chat מבוסס דפדפן ומזהה
   אם Sol ו-Pro זמינים עבור החשבון.
4. שמרו את החיבור. OmniRoute מחליף את קובץ ה-Cookie שהודבק במצב האחסון המאומת של
   Playwright ושומר אותו עם מפתח זמן הריצה באמצעות הפשטת פרטי הכניסה המוצפנים.

קובץ ה-Cookie הגולמי אינו נשמר לאחר שמירה מוצלחת. כאשר תוקף ההפעלה פג, פתחו
את החיבור, הדביקו כותרת Cookie מלאה ועדכנית והפעילו שוב את הבדיקה. מצב האבחון
בתיבת הדו-שיח לעריכה מדווח בנפרד על הדפדפן, מצב האחסון, ההתחברות, Temporary Chat, המנהרה,
המחבר והסבב המלא של הכלי.

> לעולם אין לבצע commit של קובץ Cookie אמיתי, מפתח זמן ריצה, מצב אחסון או אסימון יכולת. ערכי בדיקה
> ותיעוד חייבים תמיד להיות מצייני מיקום.

## מודלים ושילובים

נתיבי המודלים הקבועים הם:

- `chatgpt-web-codex/luna` — ‏GPT-5.6 Luna, מאמץ נמוך
- `chatgpt-web-codex/think` — ‏GPT-5.6 Luna, מאמץ בינוני
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

הוסיפו אחד מהם לשילוב כמו כל מודל אחר. אפליקציית Codex שולחת את שם השילוב בתור
`model` לנקודת הקצה הרגילה של Responses,‏ `/v1/responses`; אין נקודת קצה נפרדת של Codex
או מתג מצב.

חשבונות Free/Go חושפים את נתיבי Luna. חשבונות בעלי יכולת Sol חושפים את Instant עד
High, וחשבונות בעלי יכולת Pro חושפים בנוסף את Extra High ואת Pro. לכל נתיב יש
מודל קצה אחורי ורמת מאמץ חשיבה קבועים; מאמץ Responses מפורש שמתנגש בהם נכשל
באופן סגור במקום לשנות בשקט את מצב הדפדפן שנבחר.

אין לשנות את שמו של מחבר ישן מסוג `Codex Native` או `OmniRoute Codex`, או להשתמש בו מחדש. ChatGPT
שומר במטמון את חוזה MCP הציבורי לפי זהות המחבר, בעוד שהגשר המעודכן משתמש
בחוזה חדש של אסימון ישיר לכל תור. זמן הריצה דוחה את הזהויות המיושנות האלה ודורש
מחבר חדש מסוג `OmniRoute Codex v2`.

## מודל אבטחה

- הנתיב המקורי דורש בקשת Responses, לקוח Codex מוכר וזהויות תואמות של שרשור ותור.
- סביבת העבודה, ארגז החול, מדיניות האישור וקטלוג הכלים מגיעים ממעטפת Codex המקורית; טקסט חופשי בהנחיה אינו מקור סמכות עבורם.
- ChatGPT מקבל רק הרשאת גישה קצרת־מועד לכל תור. מתווך ה־MCP מקבל רק כלים ש־Codex הציע באותו תור בדיוק.
- אישור אוטומטי של **אפשר פעם אחת** רק מחזיר את בקשת הכלי ל־Codex. רק Codex מחליט על אישור ועל ביצוע.
- לפני הפלט הראשון, שילוב עשוי לעבור ליעד תואם אחר. לאחר תחילת הפלט, הספק, המודל, החיבור ותור הדפדפן נשארים מקובעים עד להשלמת התור.
- קובצי Cookie, מפתחות זמן ריצה, מצב אחסון ואסימוני הרשאה אינם מופיעים בתגובות הספק או ביומני הבקשות.

## VPS ללא תצוגה ו־Docker

בהתקנות npm, systemd ו־PM2, ‏OmniRoute מזהה נתיבים נפוצים של Chrome ושל Chromium.
לחלופין, הגדירו את `CHATGPT_WEB_CODEX_CHROME_PATH`. תורים בזמן ריצה משתמשים במכוון ב־Chrome
עם ממשק גרפי, משום ש־ChatGPT דוחה את תצורת הדפדפן נטול־הממשק האמיתית. לכן, מארח ללא תצוגה חייב
להריץ את OmniRoute עם תצוגת Xvfb פרטית; הגדרת הנתיב של Chrome בלבד אינה מספקת תצוגה כזו.

פרופיל ה־`web` של Docker מפעיל את `chatgpt-web-codex-browser` ברשת Compose
הפנימית. ה־sidecar מפעיל את Chrome עם ממשק גרפי בתוך Xvfb, ולכן אין צורך בתצוגה פיזית. יציאת ה־CDP
שלו אינה מתפרסמת במארח. אמצעי האחסון של פרופיל הדפדפן המוגן נפרד מאמצעי האחסון של נתוני
OmniRoute, והדפדפן מקבל די זיכרון משותף. שרת ה־proxy הפנימי של CDP
מאזין רק ביציאה `9223` בתוך רשת Compose; ‏Chrome נשאר מקושר לממשק הלולאה החוזרת בתוך ה־sidecar.

חכירת מפקח תחת `DATA_DIR` מונעת מתהליכי OmniRoute מרובים להיות בעלים של
אותם מצבי מנהרה ומתווך. התנגשות מדווחת על ידי כלי האבחון.

## שחזור אינטראקטיבי

לנתיב Docker האוטומטי אין חלון הגלוי במארח, אך Chrome עצמו פועל עם ממשק גרפי בתוך
תצוגת Xvfb הפרטית. כאשר ChatGPT דורש כניסה אינטראקטיבית או אתגר, ניתן להשתמש בתשתית דפדפן
ה־VNC הקיימת לצורך שחזור. ממשק המשתמש של הדפדפן ו־CDP חייבים להישאר נגישים רק דרך
ממשק הלולאה החוזרת, חיבור ניהול מאומת או מנהרת SSH; ‏noVNC נשאר מושבת
במהלך פעולה רגילה.

## מעבר גיבוי ל־WebSocket

כאשר שילוב מכיל את ChatGPT Web (Codex), גשר ה־WebSocket של Responses מבקש את
המעבר החלופי ל־HTTP/SSE לפני ההתחברות למעלה הזרם. לאחר מכן, ההעברה מתבצעת דרך
`/v1/responses`.
