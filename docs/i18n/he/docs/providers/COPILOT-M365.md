`copilot-m365-web` (כינוי `m365copilot`) שולח בקשות צ'אט בפורמט OpenAI דרך סשן דפדפן מאומת של Microsoft 365 Copilot BizChat בכתובת
`m365.cloud.microsoft/chat`. זהו שילוב לא רשמי.

> **חדשים בשימוש בספקי Web Cookie?**
>
> קראו את **`docs/getting-started/WEB-COOKIE-GUIDE.md`** לקבלת מידע על תהליך ההגדרה הכללי, הנחיות אימות, מגבלות ופתרון בעיות, לפני שתמשיכו למדריך ייעודי זה עבור הספק.
>
> **חשוב:** פרטי ההתחברות עבור ספק זה **אינם קובץ Cookie**. אין להעתיק
> קובצי Cookie מ-`m365.cloud.microsoft`. פרטי ההתחברות הם פרמטר שאילתה בכתובת URL של WebSocket
> ומקטע נתיב, ושניהם נקראים מכרטיסיית Network של DevTools.

## דרישות מוקדמות

- חשבון Microsoft 365 עם גישה ל-BizChat בכתובת `m365.cloud.microsoft/chat`
- דפדפן המבוסס על Chromium‏ (Chrome, Edge) לצורך בדיקת WebSocket באמצעות DevTools
- רישיון M365 Copilot (כלול בתוכניות רבות של Microsoft 365 Business/Enterprise)

## לכידת פרטי ההתחברות (שיטת WebSocket)

1. היכנסו לחשבון בכתובת `https://m365.cloud.microsoft/chat` והתחילו שיחה.
2. פתחו את **DevTools → Network**.
3. סננו לפי **WS**‏ (WebSocket).
4. לחצו על חיבור ה-WebSocket של Chathub. חפשו כתובת URL שמתחילה ב-
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. מתוך **Request URL** שלה, העתיקו:
   - את הערך של פרמטר השאילתה `access_token`‏ (JWT קצר-טווח).
   - את מקטע הנתיב של Chathub שמופיע לאחר `/Chathub/` (לדוגמה, `<oid>@<tenant>`).

מבנה כתובת ה-URL המלאה הוא:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. ב-OmniRoute, עברו אל **Providers → Add Provider**, בחרו באפשרות **Microsoft 365 Copilot
   (BizChat)** והדביקו את פרטי ההתחברות בפורמט הבא:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. לחצו על **Test Connection** ולאחר מכן על **Save**.

## לכידת פרטי ההתחברות (ייבוא HAR)

במקום להעתיק ידנית ערכים מכתובת ה-URL של ה-WebSocket, ניתן לייצא קובץ HAR
מ-DevTools:

1. פתחו את **DevTools → Network**.
2. התחילו שיחת BizChat או המשיכו שיחה קיימת (פעולה זו מפעילה את חיבור ה-WebSocket).
3. לחצו לחיצה ימנית בחלונית Network ובחרו באפשרות **Save all as HAR with content**.
4. ב-OmniRoute, השתמשו בלחצן **Import .har file** בתיבת הדו-שיח של חיבור הספק.

OmniRoute סורק את ה-HAR כדי לאתר את כתובת ה-URL של Chathub WebSocket, מחלץ את
`access_token` ואת `chathubPath`, וממלא אוטומטית את שדות פרטי ההתחברות. ייבוא
ה-HAR מפענח את מועד התפוגה של ה-JWT ומציג את הזמן שנותר עד לתפוגת האסימון.

> **לעולם אין לבצע commit לייצוא HAR אמיתי, לאסימון גישה או לאסימון רענון.** ערכי בדיקה
> ותיעוד חייבים תמיד להיות מצייני מקום.

## משך חיי האסימון ורענון

ה-`access_token` הוא קצר-טווח (בדרך כלל **~75 דקות**). לאחר תפוגתו, הספק
מדווח על שגיאת חיבור ויש ללכוד מחדש את פרטי ההתחברות.

### רענון אוטומטי באמצעות `refreshToken`

כדי להימנע מלכידה ידנית חוזרת, ניתן לאחסן אסימון רענון של Microsoft בתוך
**Advanced Settings → providerSpecificData** של החיבור:

| שדה            | תיאור                                                                    |
| -------------- | ------------------------------------------------------------------------ |
| `refreshToken` | אסימון רענון של Microsoft OAuth עבור ההיקף `substrate.office.com/sydney` |
| `tier`         | `individual` (ברירת מחדל), `edu` או `enterprise`                         |

השיגו את אסימון הרענון מתהליך קוד מכשיר או קוד הרשאה של Microsoft
שהיקפו `substrate.office.com/sydney`. כאשר `refreshToken` מוגדר, OmniRoute
מרענן מראש את `access_token` לפני כל בקשה, כך שאין צורך
ללכוד אותו מחדש לאחר כל תפוגה של כ-75 דקות.

אם `refreshToken` אינו מוגדר, יש ללכוד מחדש את פרטי ההתחברות של ה-WebSocket באופן ידני
לאחר כל תפוגה.

### בחירת רמה

| רמה          | כינוי          | ממשק                 |
| ------------ | -------------- | -------------------- |
| `individual` | _(ברירת מחדל)_ | M365 Copilot לצרכנים |
| `edu`        | `included`     | M365 Copilot לחינוך  |
| `enterprise` | `work`         | M365 Copilot לעבודה  |

הגדירו את הרמה תחת **Advanced Settings → providerSpecificData → tier**. הרמה משפיעה
על ניתוב BizChat ועל הגישה למודלים.

## מודל אבטחה

- **אינטגרציה לא רשמית.** ספק זה מבוסס על הנדסה לאחור של פרוטוקול ה-WebSocket של BizChat. הוא עלול להפסיק לפעול ללא הודעה מוקדמת כאשר Microsoft משנה את נקודת הקצה.
- הדגל `subscriptionRisk: true` מציין שהאינטגרציה מסתמכת על נקודת קצה שאינה מתועדת. ייתכן שיוטלו הגבלות על החשבון, אך הדבר לא אושר.
- אסימון הגישה הוא JWT קצר-תוקף. התייחסו אליו כמו לסיסמה: אין לבצע לו commit, לתעד אותו ביומנים או לשתף אותו.
- אסימון הרענון מעניק גישה ארוכת טווח לממשק BizChat. אחסנו אותו באותה רמת זהירות כמו מפתח API.

## פתרון בעיות

### האימות נכשל באופן מיידי

- ודאו שהעתקתם מ-**כתובת ה-URL של ה-WebSocket**, ולא מבקשת XHR/Fetch. פרטי האימות נמצאים בפרמטר השאילתה `access_token` של חיבור ה-WebSocket של Chathub — ולא בכותרת `Authorization: Bearer`.
- ודאו שה-`chathubPath` כולל את המקטע המלא `<oid>@<tenant>` מנתיב ה-URL.

### תוקף האסימון פג לאחר כ-75 דקות

זוהי התנהגות צפויה. ללא `refreshToken`, אסימון הגישה הוא קצר-תוקף. ניתן:

- ללכוד מחדש את פרטי האימות מ-DevTools, או
- להגדיר `refreshToken` בהגדרות המתקדמות לצורך רענון אוטומטי.

### בדיקת החיבור מצליחה, אך הצ'אט מחזיר 401

ייתכן שתוקף האסימון פג בין האימות לבין הבקשה הראשונה. לכדו מחדש פרטי אימות עדכניים.

### Copilot אינו מופיע ברשימת הספקים

ודאו ש-`copilot-m365-web` מופעל תחת **לוח הבקרה → ספקים**. הספק עשוי להיות מוסתר כברירת מחדל בחלק מרמות השירות.
