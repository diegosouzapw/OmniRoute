ספקי Web Cookie מאפשרים ל-OmniRoute להשתמש בשירות AI דרך הפעלת הדפדפן הקיימת שלכם במקום באמצעות מפתח API. הם שימושיים כאשר כבר יש לכם גישה לשירות דרך אתר האינטרנט שלו, ואתם רוצים ש-OmniRoute ישתמש באותה הפעלה מאומתת.

בניגוד לספקים המבוססים על מפתח API, ספקי Web Cookie מבצעים אימות באמצעות פרטי ההזדהות שהדפדפן שלכם שולח לאתר האינטרנט.

---

# לפני שמתחילים

> **חשוב:** העתיקו תמיד את פרטי ההזדהות מתוך **בקשת רשת פעילה**, **ולא** מאחסון קובצי ה-Cookie של הדפדפן.

בעיות אימות רבות נגרמות מהעתקת קובצי Cookie מהמקום הלא נכון.

## אין להעתיק מאחסון קובצי ה-Cookie

רוב הדפדפנים מציגים את קובצי ה-Cookie המאוחסנים דרך:

```
DevTools
→ Application (או Storage)
→ Cookies
```

אף שקובצי Cookie אלה נראים תקינים, הם עשויים להיות:

- מיושנים
- חלקיים
- חסרים קובצי Cookie שנשלחים רק בבקשות מאומתות

שימוש בערכים אלה עלול לגרום לכשלי אימות, גם אם הם נראים תקפים.

## העתיקו מבקשה פעילה

במקום זאת, השתמשו בקובצי ה-Cookie מבקשה שהצליחה:

```
DevTools
→ Network
→ רעננו את הדף
→ פתחו בקשת צ'אט או שיחה
→ Request Headers
→ Cookie
```

כותרת הבקשה `Cookie` מכילה את פרטי האימות המדויקים שבהם הדפדפן שלכם השתמש בהצלחה.

עבור רוב ספקי Web Cookie, זהו הערך שיש להדביק ב-OmniRoute.

# הגדרה כללית

תהליך ההגדרה זהה עבור רוב ספקי Web Cookie.

1. היכנסו לאתר האינטרנט של הספק.
2. פתחו את כלי הפיתוח של הדפדפן.
3. פתחו את הכרטיסייה **Network**.
4. רעננו את הדף.
5. פתחו בקשת צ'אט או שיחה מאומתת.
6. העתיקו את פרטי האימות הנדרשים.
7. פתחו את OmniRoute.
8. עברו אל **Providers → Add Provider**.
9. בחרו את ספק ה-Web Cookie שלכם.
10. הדביקו את פרטי ההזדהות.
11. לחצו על **Test Connection**.
12. שמרו את הספק.

פרטי ההזדהות המדויקים הנדרשים תלויים בספק.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) היא פלטפורמת צ'אט חינמית לצרכנים שאינה דורשת הרשמה — ההפעלה נוצרת באופן אנונימי בביקור הראשון ונשמרת באמצעות שלוש עוגיות: `uid`,‏ `si_usr_id` ו-`si_ses_id`.‏ OmniRoute מתווכת לאותה נקודת קצה `/api/dispatch` באמצעות מזהה מודל יחיד (`notrack-c`, כינוי `ntw`).

### שלבי התחברות

1. פתחו את [notrack.ai](https://notrack.ai) בדפדפן ואפשרו להגדיר את עוגיית ההפעלה האנונימית.
2. פתחו את **כלי המפתחים → רשת**, רעננו את הדף ולחצו על בקשה כלשהי אל `/api`.
3. תחת **כותרות הבקשה**, העתיקו את הערך המלא של הכותרת `Cookie`.
4. ב-OmniRoute, עברו אל **ספקים → הוספת ספק → NoTrack Web (חינם)**.
5. הדביקו את מחרוזת העוגייה בשדה `apiKey` ולחצו על **שמירה**.

OmniRoute מחלצת את `uid`,‏ `si_usr_id` ו-`si_ses_id` מהמחרוזת שהודבקה, ובונה מחדש כותרת `Cookie` נקייה המכילה רק את הזוגות האלה — וכן את `nt_session` (אסימון `ntk_…` שמוגדר עבור חשבונות מחוברים), כאשר הוא קיים. אם אחד מהשלושה חסר, המחרוזת הגולמית שהודבקה מועברת ללא שינוי, כדי שמפעילים יוכלו להתנסות במבנים חלופיים.

### מזהי מודלים

| מזהה מודל   | שם תצוגה  | הערות                                                  |
| ----------- | --------- | ------------------------------------------------------ |
| `notrack-c` | NoTrack C | ברירת המחדל — מודל הניתוב במעלה הזרם `C`.              |
| `C`         | NoTrack C | כינוי עבור `notrack-c` (קוד הניתוב הגולמי במעלה הזרם). |
| `notrack`   | NoTrack C | כינוי עבור `notrack-c`.                                |
| `ntw`       | NoTrack C | כינוי מקוצר עבור `notrack-c`.                          |

כל ארבעת מזהי המודלים ממופים לאותו מודל ניתוב במעלה הזרם (`C`).

### אפשרויות בקשה

המבצע מקבל את השדות האופציונליים הבאים בגוף הבקשה:

| שדה בגוף              | ברירת מחדל | מטרה                                                               |
| --------------------- | ---------- | ------------------------------------------------------------------ |
| `notrack_mode`        | `usual`    | מצב ניתוב (מחרוזת חופשית; השירות במעלה הזרם מקבל `usual`, …)       |
| `notrack_max_turns`   | `6`        | מספר הסבבים הפנימיים שהשירות במעלה הזרם רשאי לבצע לפני מתן תשובה.  |
| `notrack_chat_id`     | `null`     | המשך צ'אט קיים במעלה הזרם (יש להשמיט עבור צ'אט חדש).               |
| `notrack_attachments` | `[]`       | מערך המועבר כפי שהוא ובו מתארי קבצים מצורפים של השירות במעלה הזרם. |
| `notrack_regenerate`  | `false`    | הגדירו `true` כדי לבקש תשובה מחודשת עבור הסבב הקודם.               |

### יכולות

- השלמות צ'אט **בהזרמה וללא הזרמה**.
- **קריאה לכלים** — הגדירו `tools: [...]` בבקשה; המבצע מסדר אותם בהתאם לחוזה מעטפת לקריאה לכלים ומנתח את תגובות המודל בחזרה ל-`tool_calls` של OpenAI.
- **`response_format`** — קיימת תמיכה ב-`json_object` וב-`json_schema`. המבצע מחלץ את אובייקט ה-JSON הראשון מתשובת המודל וממיר אותו למחרוזת לפני ההחזרה.
- **רמז הנמקה** — המבצע פולט מקטע `reasoning` כאשר השירות במעלה הזרם שולח אירוע `thinking`.

### מגבלות

- השירות במעלה הזרם אוכף מכסות שימוש אנונימי — כאשר המכסה נחרגת, המבצע מחזיר שגיאת 429 עם הודעה ידידותית.
- כל מזהי המודלים מפנים לאותו מודל ניתוב במעלה הזרם; אין אפשרות מעבר נפרדת לכל מודל.
- המבצע אינו קורא לנקודת הקצה `/api/chats` של השירות במעלה הזרם, ולכן היסטוריית הצ'אט וההפעלות אינן מנוהלות אוטומטית. השתמשו ב-`notrack_chat_id` כדי להמשיך צ'אט קיים במעלה הזרם.

# מה ספקי Web Cookie יכולים ואינם יכולים לעשות

ספקי Web Cookie עושים שימוש חוזר בממשק הצ'אט של אתר אינטרנט. הם **אינם** מספקים את אותן יכולות כמו ממשקי API רשמיים.

## נתמך

- אימות באמצעות סשן הדפדפן הקיים שלכם
- גישה למודלים הזמינים דרך החשבון שלכם
- הזרמת תגובות צ'אט
- אין צורך במפתח API

## לא נתמך

- קריאה לפונקציות
- קריאה לכלים
- עריכת קבצים אוטומטית
- תהליכי עבודה סוכניתיים בסביבת פיתוח משולבת (IDE)
- תכונות הזמינות רק דרך API

זוהי התנהגות צפויה וזו **אינה** תקלה.

אם אתם זקוקים להפעלת כלים, לעריכת קבצים אוטומטית או לתהליכי עבודה סוכניתיים אחרים, השתמשו ב**ספק עם מפתח API** במקום בספק Web Cookie.

# הסתייגות לגבי האימות

הצלחה ב**בדיקת החיבור** או באימות קובצי ה-Cookie רק מאשרת שפרטי הגישה שסופקו נראים בפורמט הצפוי.

עד לפתרון Issue #7857, אימות מוצלח **אינו מבטיח** שהספק יצליח לבצע אימות זהות.

אם אימות הזהות עדיין נכשל, ודאו שהעתקתם את פרטי הגישה מבקשת רשת פעילה ולא מאחסון קובצי ה-Cookie בדפדפן.

---

# פתרון בעיות

## אימות הזהות נכשל

ודאו שפרטי הגישה הועתקו מתוך:

```
רשת
→ כותרות הבקשה
→ Cookie
```

ו**לא** מתוך:

```
יישום
→ קובצי Cookie
```

---

## קובץ ה-Cookie פועל בדפדפן אך לא ב-OmniRoute

חלק מהספקים כוללים קובצי Cookie שנשלחים רק במהלך בקשות מאומתות.

העתיקו מחדש את פרטי הגישה מבקשת רשת חדשה לאחר שפתחתם שיחה בהצלחה.

---

## הסשן פג

ספקי Web Cookie משתמשים בסשן הדפדפן הקיים שלכם.

אם סשן הדפדפן שלכם פג או אם התנתקתם, עליכם להעתיק קבוצה חדשה של פרטי גישה. כדי להפוך את חידוש קובצי ה-Cookie לאוטומטי עבור ספקי אינטרנט נתמכים, עיינו בכלי הנלווה [תוסף סנכרון סשן הדפדפן](../guides/SESSION-SYNC-EXTENSION.md).

---

## בדיקת החיבור עוברת אך הבקשות נכשלות

עד לפתרון Issue #7857, מעבר מוצלח של האימות אינו מבטיח שבקשת אימות הזהות תצליח.

העתיקו מחדש את פרטי הגישה מבקשה מאומתת חדשה לפני שתמשיכו בפתרון הבעיה.

# שיטות עבודה מומלצות

- העתיקו פרטי גישה מבקשה מאומתת חדשה.
- הימנעו משימוש חוזר בקובצי Cookie ישנים.
- השאירו את סשן הדפדפן שלכם פעיל בזמן השימוש בספקי Web Cookie.
- התייחסו לקובצי Cookie שהועתקו כאל פרטי גישה רגישים.
- השתמשו בספקים עם מפתח API כאשר אתם זקוקים לקריאה לפונקציות או לתהליכי עבודה סוכניתיים.
