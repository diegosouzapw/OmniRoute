ספקי Web Cookie מאפשרים ל-OmniRoute להשתמש בשירות AI דרך הפעלת הדפדפן הקיימת שלכם במקום באמצעות מפתח API. הם שימושיים כאשר כבר יש לכם גישה לשירות דרך אתר האינטרנט שלו, ואתם רוצים ש-OmniRoute ישתמש באותה הפעלה מאומתת.

בניגוד לספקים המשתמשים במפתחות API, ספקי Web Cookie מבצעים אימות באמצעות פרטי ההזדהות שהדפדפן שלכם שולח לאתר.

---

# לפני שמתחילים

> **חשוב:** העתיקו תמיד את פרטי ההזדהות מתוך **בקשת רשת פעילה**, ו**לא** מאחסון קובצי ה-Cookie של הדפדפן.

בעיות אימות רבות נגרמות מהעתקת קובצי Cookie מהמקום הלא נכון.

## אין להעתיק מאחסון קובצי Cookie

רוב הדפדפנים מציגים את קובצי ה-Cookie המאוחסנים דרך:

```
כלי הפיתוח
→ יישום (או אחסון)
→ קובצי Cookie
```

אף על פי שקובצי Cookie אלה עשויים להיראות תקינים, הם עלולים להיות:

- לא עדכניים
- חלקיים
- ללא קובצי Cookie שנשלחים רק בבקשות מאומתות

שימוש בערכים אלה עלול לגרום לכשלי אימות, גם אם הם נראים תקינים.

## העתיקו מבקשה פעילה

במקום זאת, השתמשו בקובצי ה-Cookie מתוך בקשה שהושלמה בהצלחה:

```
כלי הפיתוח
→ רשת
→ רענון הדף
→ פתיחת בקשת צ'אט או שיחה
→ כותרות הבקשה
→ Cookie
```

כותרת הבקשה `Cookie` מכילה את פרטי האימות המדויקים שבהם השתמש הדפדפן שלכם בהצלחה.

עבור רוב ספקי Web Cookie, זהו הערך שיש להדביק ב-OmniRoute.

# הגדרה כללית

תהליך ההגדרה זהה עבור רוב ספקי Web Cookie.

1. היכנסו לאתר של הספק.
2. פתחו את כלי הפיתוח של הדפדפן.
3. פתחו את הכרטיסייה **רשת**.
4. רעננו את הדף.
5. פתחו בקשת צ'אט או שיחה מאומתת.
6. העתיקו את פרטי האימות הנדרשים.
7. פתחו את OmniRoute.
8. עברו אל **ספקים → הוספת ספק**.
9. בחרו את ספק ה-Web Cookie שלכם.
10. הדביקו את פרטי ההזדהות.
11. לחצו על **בדיקת חיבור**.
12. שמרו את הספק.

פרטי ההזדהות המדויקים הנדרשים תלויים בספק.

# מה ספקי Web Cookie יכולים ולא יכולים לעשות

ספקי Web Cookie משתמשים מחדש בממשק הצ'אט של אתר אינטרנט. הם **אינם** מספקים את אותן היכולות כמו ממשקי API רשמיים.

## נתמך

- אימות באמצעות הפעלת הדפדפן הקיימת שלכם
- גישה למודלים הזמינים דרך החשבון שלכם
- הזרמת תגובות צ'אט
- אין צורך במפתח API

## לא נתמך

- קריאה לפונקציות
- קריאה לכלים
- עריכה אוטומטית של קבצים
- תהליכי עבודה סוכניים בסביבת IDE
- תכונות הזמינות רק דרך API

זוהי התנהגות צפויה וזו **אינה** תקלה.

אם אתם זקוקים להפעלת כלים, לעריכה אוטומטית של קבצים או לתהליכי עבודה סוכניים אחרים, השתמשו ב**ספק עם מפתח API** במקום בספק Web Cookie.

# הסתייגות בנוגע לאימות

השלמה מוצלחת של **בדיקת חיבור** או אימות קובצי Cookie מאשרת רק שפרטי ההזדהות שסופקו נראים תואמים לתבנית הצפויה.

עד לפתרון תקלה #7857, אימות מוצלח **אינו מבטיח** שהספק יצליח לבצע אימות.

אם האימות עדיין נכשל, ודאו שהעתקתם את פרטי ההזדהות מבקשת רשת פעילה ולא מאחסון קובצי ה-Cookie של הדפדפן.

---

# פתרון בעיות

## האימות נכשל

ודאו שפרטי ההזדהות הועתקו מתוך:

```
רשת
→ כותרות הבקשה
→ Cookie
```

ו**לא** מתוך:

```
יישום
→ קובצי Cookie
```

---

## קובץ ה-Cookie פועל בדפדפן אך לא ב-OmniRoute

חלק מהספקים כוללים קובצי Cookie שנשלחים רק במהלך בקשות מאומתות.

העתיקו מחדש את פרטי ההזדהות מבקשת רשת חדשה לאחר פתיחה מוצלחת של שיחה.

---

## תוקף ההפעלה פג

ספקי Web Cookie משתמשים בהפעלת הדפדפן הקיימת שלכם.

אם תוקף הפעלת הדפדפן שלכם פג או אם אתם מתנתקים, עליכם להעתיק קבוצה חדשה של פרטי הזדהות.

---

## בדיקת החיבור מצליחה אך הבקשות נכשלות

עד לפתרון תקלה #7857, הצלחה באימות אינה מבטיחה שבקשת האימות תצליח.

לפני שתמשיכו בפתרון הבעיה, העתיקו מחדש את פרטי ההזדהות מבקשה מאומתת חדשה.

# שיטות עבודה מומלצות

- העתיקו פרטי הזדהות מבקשה מאומתת חדשה.
- הימנעו משימוש חוזר בקובצי Cookie ישנים.
- השאירו את הפעלת הדפדפן שלכם פעילה בעת שימוש בספקי Web Cookie.
- התייחסו לקובצי Cookie שהועתקו כאל פרטי הזדהות רגישים.
- השתמשו בספקים עם מפתח API כאשר אתם זקוקים לקריאה לפונקציות או לתהליכי עבודה סוכניים.
