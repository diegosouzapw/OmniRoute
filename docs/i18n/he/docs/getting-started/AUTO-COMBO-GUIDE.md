> **בקצרה**: הגדירו את המודל שלכם כ-`auto`, ו-OmniRoute יבחר אוטומטית את ספק הבינה המלאכותית הטוב ביותר לכל בקשה. אין צורך בהגדרות נוספות.

---

## מה זה עושה

במקום לבחור מודל בינה מלאכותית מסוים (כמו GPT-4o או Claude), תוכלו לאפשר ל-OmniRoute **לבחור אוטומטית את המודל הטוב ביותר** לכל בקשה. הוא מביא בחשבון:

- **תקינות** — האם הספק פועל כרגע?
- **מהירות** — עד כמה הוא מהיר?
- **עלות** — כמה הוא עולה?
- **איכות** — האם הוא טוב בסוג המשימה הזה?
- **קיבולת** — האם נותרה לו מכסה?

OmniRoute מעניק ציון לכל הספקים המחוברים שלכם ובוחר את הטוב ביותר. אם הוא נכשל, המערכת מנסה אוטומטית את הספק הבא.

---

## התחלה מהירה

**שלב 1**: הגדירו את המודל כ-`auto` ב-IDE או ב-CLI שלכם:

```
model: "auto"
```

**שלב 2**: זה הכול! OmniRoute מטפל בכל השאר.

**שלב 3** (אופציונלי): השתמשו בווריאנט עבור משימות מסוימות:

```
model: "auto/coding"    # הטוב ביותר לקוד
model: "auto/fast"      # התגובה המהירה ביותר
model: "auto/cheap"     # האפשרות הזולה ביותר
```

## באיזה "auto" כדאי להשתמש?

| אם אתם רוצים...           | השתמשו בזה     | המתאים ביותר עבור          | איך זה עובד                               |
| ------------------------- | -------------- | -------------------------- | ----------------------------------------- |
| **הטוב ביותר באופן כללי** | `auto`         | שאלות כלליות, צ'אט         | מאזן בין מהירות, עלות ואיכות              |
| **הטוב ביותר לקוד**       | `auto/coding`  | כתיבת קוד, ניפוי שגיאות    | בוחר מודלים שטובים במשימות תכנות          |
| **התגובה המהירה ביותר**   | `auto/fast`    | תשובות מהירות, השהיה נמוכה | נותן עדיפות למהירות על פני כל השאר        |
| **האפשרות הזולה ביותר**   | `auto/cheap`   | חיסכון בכסף                | בוחר את הספק הזול ביותר                   |
| **המודל החכם ביותר**      | `auto/smart`   | משימות מורכבות             | איכות בעדיפות ראשונה + בחינת מודלים חדשים |
| **הזמין ביותר**           | `auto/offline` | כאשר הספקים עמוסים         | בוחר ספקים בעלי הקיבולת הגדולה ביותר      |

## איך זה עובד (גרסה פשוטה)

כאשר אתם שולחים בקשה עם `model: "auto"`,‏ OmniRoute:

1. **בוחן את כל הספקים המחוברים שלכם** — כל ספק שהוספתם (OpenAI,‏ Anthropic,‏ Google וכו')
2. **מעניק ציון לכל אחד מהם**, תוך שקלול, בין היתר, של:
   - האם הוא פועל? (תקינות)
   - האם יש לו קיבולת? (מכסה)
   - כמה הוא עולה? (מחיר)
   - עד כמה הוא מהיר? (מהירות)
   - האם הוא טוב במשימה הזאת? (איכות)
3. **בוחר את הטוב ביותר** — הספק בעל הציון הגבוה ביותר מקבל את הבקשה שלכם
4. **מתאושש אוטומטית** — אם הוא נכשל, OmniRoute מנסה אוטומטית את הספק הבא

### מערכת הניקוד

כל ספק מקבל ציון בין 0 ל-1. ככל שהציון גבוה יותר, כך ההתאמה טובה יותר.

| גורם         | משקל | משמעות                                               |
| ------------ | ---- | ---------------------------------------------------- |
| תקינות       | 20%  | האם הספק פועל? (מצב מפסק הזרם)                       |
| מכסה         | 15%  | האם נותרה לו קיבולת?                                 |
| עלות         | 15%  | כמה הוא יקר? (זול יותר = ציון גבוה יותר)             |
| מהירות       | 12%  | עד כמה הוא מהיר? (השהיה נמוכה יותר = ציון גבוה יותר) |
| התאמה למשימה | 8%   | האם הוא טוב בסוג המשימה הזה?                         |
| יציבות       | 5%   | האם הוא עקבי? (שיעור שגיאות נמוך)                    |
| דרגה         | 5%   | דרגת החשבון (Ultra > Pro > Free)                     |
| אחר          | 20%  | זיקה להקשר, צפיפות חיבורים וכו'                      |

### כיצד הווריאנטים משנים את הניקוד

כל וריאנט משתמש במשקלים שונים:

| וריאנט         | נותן עדיפות ל- | משקלים מרכזיים                  |
| -------------- | -------------- | ------------------------------- |
| `auto`         | איזון          | health=20%, quota=15%, cost=15% |
| `auto/coding`  | איכות          | taskFit=37%, stability=15%      |
| `auto/fast`    | מהירות         | latency=32%, health=28%         |
| `auto/cheap`   | עלות           | cost=37%                        |
| `auto/smart`   | איכות + חקירה  | taskFit=37%, exploration=10%    |
| `auto/offline` | קיבולת         | quota=37%, health=28%           |

## כיצד המערכת מתמודדת עם כשלים

ל-OmniRoute יש **שלוש שכבות הגנה**:

### 1. מעבר אוטומטי לספק חלופי

אם הספק הטוב ביותר נכשל, OmniRoute מנסה אוטומטית את הספק הבא. אין צורך לעשות דבר.

### 2. התאוששות עצמית

אם ספק ממשיך להיכשל:

- **ציון < 0.2** → מוחרג למשך 5 דקות
- **מפסק המעגל פתוח** → מוחרג אוטומטית
- **יותר מ-50% מהספקים מושבתים** → מצב תקרית (ללא בדיקת חלופות)

### 3. חלופת חירום

אם כל הספקים נכשלים, OmniRoute מנתב לספקים חינמיים ויציבים (כמו Kiro או Qoder) כמוצא אחרון.

## תמיכה במספר חשבונות

אם יש לכם מספר חשבונות אצל אותו ספק (למשל, שני מפתחות OpenAI), OmniRoute מתייחס לכל אחד מהם כאל **מועמד נפרד**. כלומר:

- בחשבון A נותרה מכסה → להשתמש בו
- חשבון B מוגבל בקצב הבקשות → לדלג עליו
- חשבון C זול יותר → להעדיף אותו

כל חשבון מקבל ציון באופן עצמאי, על סמך התקינות, המכסה והמהירות שלו.

---

## בחינת חלופות באמצעות Bandit

OmniRoute **בוחן** מדי פעם ספקים חדשים כדי לגלות אפשרויות טובות יותר:

- **ברירת מחדל**: 5% מהבקשות מועברות לספקים אקראיים
- **Auto/smart**: שיעור בחינה של 10%
- **מושבת** כאשר יותר מ-50% מהספקים אינם תקינים

כך OmniRoute לומד אילו ספקים מתאימים ביותר לדפוסי השימוש שלכם.

## שאלות נפוצות

### "האם המערכת תמיד תבחר במודל היקר ביותר?"

**לא.** כברירת מחדל, העלות מהווה רק 15% מהציון. ספק זול, מהיר ותקין יכול לגבור על ספק יקר. השתמשו ב-`auto/cheap` אם ברצונכם לתת עדיפות גבוהה עוד יותר לעלות.

### "מה קורה אם ספק מושבת?"

OmniRoute מדלג עליו אוטומטית ומנסה את הספק הבא. אם ספק ממשיך להיכשל, הוא מוחרג באופן זמני (למשך 5–30 דקות). אין צורך לעשות דבר.

### "האם אפשר לראות באיזה ספק נעשה שימוש?"

בדקו את כותרות התגובה — OmniRoute כולל בכל תגובה את הספק והמודל שבהם נעשה שימוש.

### "האם המערכת לומדת מהשימוש שלי?"

כן! מערכת הניקוד משתמשת בנתונים היסטוריים (זמן השהיה, שיעורי שגיאות ושיעורי הצלחה) כדי לקבל החלטות טובות יותר לאורך זמן.

### "מה ההבדל בין `auto` ל-`auto/smart`?"

- `auto` — מאוזן, 5% בחינה
- `auto/smart` — איכות בעדיפות ראשונה (אותם משקלים כמו `auto/coding`), 10% בחינה

השתמשו ב-`auto/smart` כאשר אתם מעוניינים באיכות הטובה ביותר ומוכנים לבחינה מזדמנת של חלופות.

### "האם אפשר לאלץ שימוש בספק מסוים?"

כן! השתמשו בשילוב עם אסטרטגיית `priority` במקום `auto`, ולאחר מכן שלחו את **השם המדויק** של השילוב בשדה `model` (למשל `model: "my-combo"` — לא `auto`). לפרטים, ראו את [המסמך הטכני](../routing/AUTO-COMBO.md).

### "במה זה שונה מ-round-robin?"

Round-robin עובר בין הספקים לפי הסדר. Auto-combo **מעניק ציון לכל ספק** ובוחר בספק הטוב ביותר. הוא חכם יותר — הוא מביא בחשבון תקינות, מהירות, עלות ואיכות.
