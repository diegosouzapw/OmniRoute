# 🚀 OmniRoute — שער ה-AI החינמי

<img src="./docs/diagrams/readme-hero.svg" width="100%" alt="OmniRoute — לעולם אל תפסיקו לתכנת. כל כלי AI ← 359 ספקים — 150+ בחינם — דרך נקודת קצה אחת. Claude Code, Codex, Cursor, Cline, Copilot ו-Antigravity אל Claude / GPT / Gemini בחינם עם מעבר אוטומטי במקרה של כשל. דחיסה משולבת של RTK + Caveman חוסכת 15–95% מהטוקנים (~89% בממוצע) — לעולם אל תגיעו למגבלות. 359 ספקי AI · 150+ מסלולים חינמיים · ~1.62 מיליארד טוקנים חינמיים בחודש · 19 אסטרטגיות ניתוב · $0 להתחלה."/>

## 💰 ~1.62 מיליארד טוקנים בחינם / חודש

</div>

> שילוב ידני של מסלולים חינמיים הוא משימה מתישה — עשרות ערכות SDK, עשרות מגבלות קצב, ואין שום דרך לדעת כמה באמת עומד לרשותכם. OmniRoute מקטלגת **489 רשומות של מסלולים חינמיים על פני 35 מפתחות מאגרים מתחדשים**, ומחשבת את נתון הטוקנים הראשי מתוך **17 המאגרים בעלי תקציב חודשי חיובי שפורסם, בתוספת חמש מכסות Groq נפרדות לכל מודל**, תוך מניעת ספירה כפולה לפי מאגר משותף. מכסות שנפתחות רק לאחר אימות זהות אזורי (כיום: ModelScope) מוצגות בנפרד, +~6M מאחורי אימות זהות אזורי, ולעולם אינן נכללות בנתון הראשי. התוצאה נשארת גלויה בלוח הבקרה (`/dashboard/free-tiers`).

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="כרטיס תקציב המסלול החינמי של OmniRoute: כ־1.62 מיליארד טוקנים חינמיים בחודש באופן שוטף, ועד כ־2.22 מיליארד בחודש הראשון עם קרדיטים להרשמה, מתוך 35 מפתחות מתועדים של מאגרים מתחדשים, המכסים 489 רשומות מסלול חינמי מקוטלגות מאחורי נקודת קצה אחת. חישוב אמין ללא ספירה כפולה של מאגרים — כל מאגר משותף נספר פעם אחת, כולל 17 מאגרים מתחדשים בעלי תקציב טוקנים חודשי חיובי שפורסם, בתוספת חמש מכסות Groq נפרדות לכל מודל; 13 ספקים מסומנים כהימנעות מומלצת בקטלוג סיכוני התנאים, כדי שאתם תחליטו. סרגל התקציב כולל Mistral 1B,‏ Nara 210M,‏ LLM7 150M,‏ xKiro 150M,‏ Groq 30M (חמש מכסות נפרדות לכל מודל) ומאגרים קטנים יותר, לצד קרדיטים להרשמה בחודש הראשון וספקים חינמיים לצמיתות ללא מגבלת טוקנים, המוצגים בנפרד כדי שלעולם לא ינפחו את הנתון הראשי. נתוני שימוש ויתרה בזמן אמת ב־/dashboard/free-tiers."/>

> תקציר מונפש של העמוד החי `/dashboard/free-tiers`. המתודולוגיה המלאה (מניעת ספירה כפולה של מאגרים, רמות קרדיט, תנאי ספקים): **[docs/reference/FREE_TIERS.md](docs/reference/FREE_TIERS.md)**.
>
> <sub>הנתונים האלה נבדקים מחדש מדי שבועיים מול הקטלוג החי, ו**נעים בשני הכיוונים** — ספק מסיים מסלול חינמי והמספר יורד; ספק חדש מצטרף והמספר עולה. אנחנו מפרסמים את מה שהקטלוג מחשב בפועל, ולעולם לא תרחיש מיטבי שעוגל כלפי מעלה.</sub>

# 🤔 למה OmniRoute?

</div>

<img src="./docs/diagrams/why-pain-fix.svg" width="100%" alt="למה OmniRoute — מפסיקים לתמרן בין 10 לוחות בקרה, מפתחות API לא תקינים וחשבונות מפתיעים. עשרה כאבים יומיומיים לעומת פתרונות: מכסה שפגה בלי שנוצלה → מיצוי מרבי של מינויים; מגבלות קצב באמצע כתיבת קוד → מעבר אוטומטי בן 4 שכבות בעת כשל (מינוי → API → זול → חינם); פלטי כלים ששורפים טוקנים → דחיסת RTK + Caveman‏ (15–95%); ממשקי API יקרים → ניתוב ממוטב עלויות; הגדרה נפרדת לכל כלי → נקודת קצה אחת, לוח בקרה אחד; בינה מלאכותית חסומה → פרוקסי ב-3 רמות + הסוואת TLS; מפתחות לא תקינים → עמידות ב-3 שכבות (מפסקי זרם, תקופת צינון למפתחות, נעילת מודלים); צוות שחולק מינוי אחד → מאגרי מפתחות עם מכסות בחלוקה הוגנת; הנחיות שעוברות דרך הענן של מישהו אחר → גישה מקומית תחילה עם מפתחות מוצפנים ב-AES-256-GCM; היעדר נראות להוצאות → ניתוח נתונים בזמן אמת (שימוש, מכסה, חיסכון, זמן אחזור p95)."/>

<div align="center">

<img src="./docs/diagrams/tier-cascade.svg" width="100%" alt="זרימת הבקשות של OmniRoute: סביבת הפיתוח או ה-CLI שלכם (Claude Code, Cursor, Cline…) פונים לנקודת קצה מקומית אחת (http://localhost:20128/v1); הנתב החכם של OmniRoute‏ (דחיסת RTK + Caveman,‏ 19 אסטרטגיות ניתוב, מפסקי זרם, הסוואת TLS,‏ MCP,‏ A2A, מנגנוני הגנה) יכול לעבור בין 4 שכבות ספקים בעת כשל כל עוד נשאר יעד תקין ומתאים — שכבה 1 מינוי, שכבה 2 מפתח API, שכבה 3 זול ושכבה 4 חינם."/>

## 📡 מכ"ם OmniRoute

הכותרת המרכזית של המסלול החינמי נותרת **כ־1.62 מיליארד טוקנים בחודש**, בהתאם לקטלוג המתועד לעיל, לאחר הסרת כפילויות בין המאגרים. קרדיטים זמניים שמעניקים ספקים בעת ההרשמה יכולים להגדיל בנפרד את המכסה בחודש הראשון ל־**כ־2.22 מיליארד**. Radar הוא שכבת־על אופציונלית וחתומה לקטלוג, המיועדת למי שמעוניינים במידע עדכני יותר על זמינות מודלים חינמיים בין מהדורות OmniRoute; הקטלוג הקהילתי וכל התכונות החינמיות הקיימות יישארו בחינם.

תומכים יכולים לקבל את הקטלוג החי והזדמנויות נוספות מספקים. התקרה הנפרדת והמשתנה שלו היא **לכל היותר כ־3 מיליארד טוקנים בחודש**, בהתאם לזמינות אצל הספקים. תקרה זו אינה מובטחת: ספקים יכולים לשנות מכסות, תנאי זכאות, מודלים או אזורים בכל עת.

Radar הוא שירות אופציונלי המבוסס על GET בלבד. לקוח OmniRoute אינו מעלה פרומפטים, תעבורה, הגדרות ספקים, נתוני טלמטריה על השימוש או את מצב הסגירה המקומי של הודעות. למידע על תנאי הזכאות ועל הקטלוג הנוכחי, בקרו ב־**[radar.omniroute.online/planos](https://radar.omniroute.online/planos)**.

**הפעילו כל CLI נתמך דרך OmniRoute בפקודה אחת** — ללא כתיבת קובצי תצורה,
האישורים מוזרקים לכל תהליך, ו־Qwen/Gemini מקבלים תיקיית בית מבודדת וזמנית:

```bash
omniroute run claude   --model openai/gpt-5.4          # Claude Code
omniroute run codex    --model glm/glm-5.2             # OpenAI Codex CLI
omniroute run aider    --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose    --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"
omniroute run qwen     --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini   --model glm/glm-5.2 -- --skip-trust -p "reply OK"

# לחלופין, בחרו ספק+מודל באופן אינטראקטיבי וכתבו את התצורה של הכלי עצמו:
omniroute configure codex          # גם: claude opencode qwen aider goose gemini cline continue kilo
```

כל פקודה מכבדת את ההקשר המרוחק הפעיל (`omniroute connect <host>`), האפשרות `--dry-run`
מציגה תצוגה מקדימה של משתני הסביבה/הארגומנטים המדויקים ללא ביצוע, והאפשרות `--api-key-env NAME` מונעת מסודות
להופיע בהיסטוריית המעטפת שלכם. → [שילובי CLI](docs/guides/CLI-INTEGRATIONS.md)

## 🔌 CLI מלא + A2A ו-MCP

</div>

> מעבר לשרת, OmniRoute הוא **תא פיקוד מלא משורת הפקודה** עם **יותר מ-80 פקודות**, וכן פרוטוקולים פתוחים לסוכנים, כך שסוכן AI יכול להפעיל אותו **בכוחות עצמו**.

### ⌨️ CLI אמיתי (לא רק `start`)

```bash
omniroute               # הפעלת השער ולוח המחוונים (יציאה 20128)
omniroute chat          # לקוח צ'אט TUI אינטראקטיבי (פקודות לוכסן: /model /combo /skill /memory)
omniroute setup         # אשף מודרך להפעלה הראשונה
omniroute doctor        # אבחון ספקים, יציאות ותלויות מקוריות
```

### 🛰️ מצב מרוחק — הפעילו את ה-CLI כאן ואת OmniRoute ב-VPS

OmniRoute פועל בשרת? הפעילו אותו מהמחשב הנייד באמצעות **אותו CLI**. התחברו פעם אחת
באמצעות אסימון גישה מוגבל היקף; לאחר מכן כל פקודה תפנה לשרת המרוחק.

```bash
omniroute connect 192.168.0.15            # סיסמה ← אסימון מוגבל היקף, שנשמר כהקשר
omniroute models list                     # ← מופעל מול השרת המרוחק
omniroute configure codex                 # ← בוחר מודל מרוחק וכותב פרופיל Codex מקומי
omniroute tokens create --name ci --scope read   # הנפקת אסימונים מצומצמים יותר למכונות אחרות
omniroute contexts use default            # ← חזרה לשרת המקומי
```

היקפי האסימונים הם `read` / `write` / `admin`; נתיבים שמפעילים תהליכים נותרים מוגבלים ל-loopback בלבד.

### 🎚️ מעבר למנועים — סגנונות פלט, הבורר האדפטיבי ושליטה לכל בקשה

12 המנועים שלעיל מצמצמים את מה שנכנס **פנימה**. שלוש שכבות נוספות מעצבות **איך**, **מתי** ומה יוצא **החוצה**:

- **🪄 סגנונות פלט** _(הכוונה בציר הפלט)_ — הזרקת הוראות דטרמיניסטיות ובטוחות למטמון לעיצוב התגובה; ניתנות לשילוב, כל אחת בעוצמת `lite` / `full` / `ultra`. הוספת סגנון היא רשומה בת שורה אחת ברישום:
  - **ניסוח תמציתי** — הסרת מלל מיותר / תוויות / הסתייגויות; שמירה מדויקת על המהות הטכנית.
  - **פחות קוד** — YAGNI בסגנון "מפתח בכיר עצלן": השינוי הפעיל הקטן ביותר, ללא תשתית שלא התבקשה.
  - **Ponytail (מפתח בכיר עצלן)** — התקדמות בסולם YAGNI, תיקון שורש הבעיה, ה-diff הפעיל הקטן ביותר.
  - **יש לי ADHD (פעולה תחילה)** — הפעולה הבאה מופיעה ראשונה, השלבים ממוספרים, צעד המשך קונקרטי אחד, ללא הקדמה.
  - **CJK תמציתי (文言)** — סגנון סינית קלאסית תמציתי במיוחד (מוגבל לאזור `zh`).
- **🎯 תקציב הקשר אדפטיבי** _(הבורר)_ — במקום סף טוקנים יחיד של הפעלה/כיבוי, מופעלים בהדרגה רק המנועים הזולים ביותר ובעלי אובדן המידע הנמוך ביותר, ורק במידה הנדרשת כדי **להתאים לחלון ההקשר של המודל**. מדיניות: `reserve-output` (ברירת המחדל, מודעת למודל) · `percentage` · `absolute`. מצב: `floor` (הבטחת התאמה) · `replace-autotrigger` (הבחירה המפורשת שלך גוברת) · `off` (סף מהגרסה הקודמת).
- **🎛️ היכן נקבעת הדחיסה** _(קדימות, מגבוה → לנמוך)_ — כותרת `x-omniroute-compression` לכל בקשה › עקיפה של שילוב ניתוב › פרופיל פעיל בעל שם › אדפטיבי / הפעלה אוטומטית › ברירת המחדל בלוח הבקרה › כבוי. התוכנית שהוחלה מוחזרת בכותרת התגובה `X-OmniRoute-Compression: <mode>; source=<source>`.

אפשר להגדיר הפעלה אוטומטית לפי סף טוקנים, להפעיל את הבורר האדפטיבי, להצמיד פרופיל בעל שם, לקבוע הגדרה חד-פעמית לכל בקשה או להקצות צינור עיבוד לכל שילוב ניתוב — לפי צורכי עומס העבודה. **ערכת הערכה** לא מקוונת ואופציונלית (`npm run eval:compression`) מעניקה ציונים לנאמנות מול החיסכון על קורפוס מוצמד, לפני שמקדמים שינוי.

## 📦 שיטות התקנה נוספות — Docker, קוד מקור, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

התגית `:latest` עוקבת אחר גרסת ה-SemVer היציבה **שפורסמה** הגבוהה ביותר. היא אינה עוקבת אחר `main` ב-git. עבור GitOps, קבעו גרסה באמצעות `:X.Y.Z`. ראו [ערוצי הפצה של Docker](docs/guides/DOCKER_GUIDE.md#release-channels).התמונה מקבעת את **`OMNIROUTE_MEMORY_MB=1024`**. זה מספיק ללוח הבקרה ולצ'אט קל. **סוכני קידוד** (`POST /v1/responses` מ-Claude Code, Codex, Grok, …) זקוקים לערמת V8 גדולה בהרבה, אחרת התהליך נתקל ב-`FATAL ERROR` בסביבות 12 GiB כאשר שני הקשרים ארוכים חופפים. הקצו למכולה יותר זיכרון מגודל הערמה (מאגרים טבעיים נמצאים מחוץ ל-V8):

| עומס עבודה                              | ערמה (`-e OMNIROUTE_MEMORY_MB`) | מכולה (`--memory`) |
| --------------------------------------- | ------------------------------- | ------------------ |
| לוח בקרה / צ'אט קל                      | `1024` (ברירת המחדל של התמונה)  | ≥2 g               |
| סוכן קידוד אחד                          | `8192`                          | ≥10 g              |
| שתי בקשות `/v1/responses` ארוכות במקביל | `10240`–`12288`                 | ≥12–16 g           |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

הטבלה המלאה: [מדריך Docker — זיכרון RAM בזמן ריצה](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

**🥟 Bun**

התקנה רגילה באמצעות `bun install` והתקנה גלובלית (`bun install -g omniroute`) נתמכות באמצעות זיהוי סביבת הריצה Bun:

- **`bun:sqlite` מובנה**: בעת ריצה תחת Bun, ‏OmniRoute משתמש במנהל ההתקן `bun:sqlite` המובנה של Bun, ובמקרה הצורך חוזר ל-`better-sqlite3` ב-Node.js או ל-`sql.js`.
- **בחירה אוטומטית ב-Webpack לפיתוח**: סביבת הפיתוח (`bun run dev`) מזהה את Bun באופן אוטומטי ומשביתה את Turbopack לטובת Webpack, כדי למנוע אי-תאימויות עם קישורי V8 טבעיים. בניות לייצור (`bun run build`) פועלות בדיוק בהתאם ל-`OMNIROUTE_USE_TURBOPACK`, כמו ב-Node: ‏Turbopack כברירת מחדל, או `OMNIROUTE_USE_TURBOPACK=0` לבנייה באמצעות Webpack (`Dockerfile.bun` חושף אותו כ-`--build-arg`).
- **Dockerfile ייעודי ל-Bun**: הקובץ הרב-שלבי `Dockerfile.bun` מיועד לפריסות ייצור טבעיות של Bun (`docker build -f Dockerfile.bun -t omniroute:bun .`).

📖 [מדריך Docker](docs/guides/DOCKER_GUIDE.md) — פרופילי Compose, ‏HTTPS באמצעות Caddy ומנהרות Cloudflare.

**🦭 Podman**

```bash
# 1. הכנת ספריית הנתונים המחוברת באמצעות bind mount
mkdir -p data

# 2. רק ב-Linux וב-Podman מקומי ללא root (לעולם לא בלקוח מרוחק של Podman Machine):
podman unshare chown 1000:1000 ./data

# 3. הגדרת רמז סביבת הריצה, בניית תמונת Compose המקומית והפעלה
echo "CONTAINER_HOST=podman" >> .env
podman compose --profile base up -d --build
```

ב-macOS או ב-Windows, ‏Podman משתמש ב-Podman Machine מרוחק: דלגו על `podman unshare`
ופעלו לפי [ההנחיות לספריית הנתונים בהתאם לטופולוגיה](contrib/podman/README.md#data-directory-permissions-by-topology).

📖 [מדריך Podman](contrib/podman/README.md) — בניות Compose, ‏Podman Machine והגדרת
Quadlet עם Linux/systemd.

**⚡ התקנה מהירה / רזה יותר (דילוג על הבנייה הטבעית)**

מנוע SQLite הטבעי (`better-sqlite3`) הוא תלות **אופציונלית**, ולכן התקנה גלובלית
לעולם אינה נתקעת בהידור מקוד המקור: היא משתמשת בקובץ בינארי שנבנה מראש כאשר הוא תואם
לפלטפורמה/Node שלכם, ובמקרה אחר חוזרת באופן שקוף למנוע JavaScript טהור
(`node:sqlite` ב-Node 22 ומעלה, או `sql.js` WASM המצורף) — ללא צורך בכלי בנייה.

כדי לדלג לחלוטין על החימום הטבעי שלאחר ההתקנה (CI, מערכת ללא ממשק גרפי או מחשבים איטיים):

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # גם CI=1 מדלג עליו
```

להתקנות המהירות ביותר, העדיפו את **pnpm** (אחסון ממוען-תוכן + קישורים קשיחים — ראו לעיל).
לסביבת ריצה ללא לוח בקרה וללא ממשק גרפי, השתמשו בפרופיל Docker בשם `base` (לעיל) או
ב[מדריך Termux](docs/guides/TERMUX_GUIDE.md). ממשק שורת הפקודה ולוח הבקרה האינטרנטי מסופקים על ידי
אותו תהליך ביציאה אחת, ולכן כיום אין חבילה נפרדת לממשק שורת הפקודה בלבד.

### כיצד לתרום

1. צרו fork של המאגר
2. צרו ענף מקצה `release/vX.Y.Z` **הפעיל** (לא מ-`main`) — ראו [מודל הענפים והגרסאות](docs/ops/BRANCHING_MODEL.md)
3. צרו את ענף התכונה שלכם (`git checkout -b feat/amazing-feature`)
4. בצעו commit לשינויים שלכם (`git commit -m 'feat: add amazing feature'`)
5. דחפו לענף (`git push origin feat/amazing-feature`)
6. פתחו בקשת משיכה כאשר **הבסיס = אותו ענף `release/vX.Y.Z`**
