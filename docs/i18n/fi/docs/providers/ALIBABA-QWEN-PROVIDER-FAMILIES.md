Tämä asiakirja dokumentoi toteutuspäätöksen, joka koskee
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854):ää. Julkiset tuotteet on
esitetty neljänä palveluntarjoajaperheenä. Alue on yhteystietoa, ei erillinen tuote.

## Päätös

| Palveluntarjoajaperhe                      | OmniRoute-tunnus        | Globaali alue | Kiinan alue |
| ------------------------------------------ | ----------------------- | ------------- | ----------- |
| Alibaba Cloud Model Studio (käytön mukaan) | `alibaba`               | Singapore     | Beijing     |
| Alibaba Cloud Token Plan                   | `bailian-coding-plan`   | Singapore     | Beijing     |
| Qwen Cloud (käytön mukaan)                 | `qwen-cloud`            | Global        | Beijing     |
| Qwen Cloud Token Plan                      | `qwen-cloud-token-plan` | Singapore     | Beijing     |

Nykyinen `alibaba-cn`-tunnus säilyy ajonaikaisena yhteensopivuusaliaksena tallennetuille yhteyksille, mallireiteille, yhdistelmille ja historiallisille käyttötiedoille. Sen hallintapaneelikortti yhdistetään `alibaba`-korttiin; tietokannan uudelleenkirjoitusta ei tarvita.

Qwen Cloudin käytön mukaan veloitettava palvelu ja Alibaba Cloud Model Studio käyttävät tällä hetkellä samoja DashScope-yhteensopivia ajonaikaisia palvelinosoitteita, mutta ne säilyvät erillisinä palveluntarjoajaidentiteetteinä, koska käyttäjät hankkivat avaimet ja hallitsevat tilejä eri tuotenäkymien kautta. Alibaban ja Qwen Cloudin Token Plan -tuotteet käyttävät eri päätepisteperheitä, joten kaikki neljä tuotetta säilyvät erillisinä palveluntarjoajatunnuksina.

## Päätepistematriisi

| Palveluntarjoajaperhe   | `global-sg`                                                              | `china-beijing`                                                      | Siirtomuoto |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ----------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI      |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic   |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI      |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI      |

API-avaimen ja päätepisteen on kuuluttava samaan tuotteeseen ja alueeseen. Alueen valitseminen muuttaa esiasetettua päätepistettä, jota käytetään validoinnissa ja tavallisissa pyynnöissä.

## Yhteyssopimus

Uudet yhteydet tallentavat vakaan alueavaimen `providerSpecificData`-kenttään:

```json
{
  "region": "global-sg"
}
```

Sallitut arvot ovat `global-sg` ja `china-beijing`. Päätepiste johdetaan keskitetysti palveluntarjoajatunnuksesta ja alueesta. Muuhun kuin esiasetettuun päätepisteeseen viittaava `providerSpecificData.baseUrl` säilyy eksplisiittisenä ylläpitäjän ohituksena ja on etusijalla, kun taas vanhat tallennetut esiasetetut URL-osoitteet normalisoidaan takaisin alueelliseen matriisiin.

Näin yhteysskeema pysyy laajennettavana: resolveriin voidaan lisätä uusi alue luomatta uutta palveluntarjoajakorttia tai muuttamatta tallennettuja palveluntarjoajatunnuksia.

## Yhteensopivuus ja käyttöönotto

1. Lisää alueellinen päätepisteen selvitystoiminto ja säilytä nykyiset globaalit oletusarvot.
2. Käytä reaaliaikaista alueellista DashScope `/models` -hakua palvelulle `alibaba`, sen `alibaba-cn`-yhteensopivuustunnukselle
   sekä palvelulle `qwen-cloud`. Niiden vastaukset kulkevat ensin tekstinluontisuodattimen läpi, koska yleinen
   päätepiste palauttaa myös kuva-, video-, ääni-, upotus- ja muita kuin keskustelumalleja. `qwen-cloud`
   soveltaa sen jälkeen palveluntarjoajarekisterissään määritettyä ylläpidettyä sallittujen mallien luetteloa. Alibaba Model Studio
   ja Qwen Cloud säilyttävät erilliset kuratoidut luettelot, vaikka ne käyttävät tällä hetkellä samoja suorituksenaikaisia isäntiä.
3. Rekisteröi `qwen-cloud-token-plan` nykyisellä Token Plan -tekstimalleja koskevalla sallittujen mallien luettelolla.
4. Lisää tyypitetty aluevalitsin yhteyksien lisäys- ja muokkausvalintaikkunoihin.
5. Piilota `alibaba-cn`-kortin kaksoiskappale ja sisällytä sen nykyiset yhteydet `alibaba`-palveluntarjoajan sivulle.
6. Pidä mukautetut päätepisteiden ohitukset käytettävissä edistyneitä ja työtilakohtaisia käyttöönottoja varten.

Token Plan -mediamallit pysyvät keskusteluluettelon ulkopuolella, koska ne käyttävät erillisiä päätepisteitä.
`wan2.7-image` ja `wan2.7-image-pro` on rekisteröity tiedostossa `open-sse/config/imageRegistry.ts`;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` ja `happyhorse-1.1-r2v` on rekisteröity tiedostossa
`open-sse/config/videoRegistry.ts`. Molemmat rekisterit käyttävät uudelleen `qwen-cloud-token-plan`-yhteyden
identiteettiä ja sen aluekohtaisia tunnistetietoja.

Tavallisella Qwen Cloudilla on erilliset käytön mukaan laskutettavat kuva- ja videoluettelot `qwen-cloud`-
identiteetin alla. Sen kuvamallit ovat `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` ja `z-image-turbo`. Sen video-
mallit ovat `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` ja
`wan2.7-videoedit`. Nämä mallit käyttävät uudelleen vain tavallista `qwen-cloud`-yhteyttä ja alueellista
DashScope-mediapäätepistettä. Token Plan- ja käytön mukaan laskutettavat rekisterit eivät peri tai yhdistä
toistensa malliluetteloita.

Myös `bailian-coding-plan`-identiteetillä on omat mediasallintaluettelonsa:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` ja `qwen-image-2.0-pro` kuvien
luontiin sekä
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` ja `happyhorse-1.1-r2v` videoiden
luontiin. Se käyttää vain Bailian Coding Plan -yhteyttä ja alueellista Coding Plan -päätepistettä.
Sen kuva- ja videorekisterit eivät peri tietoja kummaltakaan Qwen Cloud -palveluntarjoajalta eivätkä yhdisty niihin.

Tavallisella `alibaba`-identiteetillä on erilliset kuva- ja videosallintaluettelot. Sen kuvamallit ovat
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` ja `wan2.6-t2i`. Sen lisätyt videomallit ovat `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` ja `wan2.7-videoedit`. Nämä mallit käyttävät vain Alibaba Model Studio
-yhteyttä ja sen valittua alueellista mediapäätepistettä; niitä ei lisätä mihinkään Coding Plan- tai Qwen
Cloud -rekisteriin.

Qwen Cloud Token Plan -keskusteluluettelo noudattaa Individual-paketin täsmällisiin merkkijonoihin perustuvaa tekstimallien sallintaluetteloa:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` ja
`deepseek-v4-pro`. Wan- ja HappyHorse-merkinnät kuuluvat erillisiin kuvien ja videoiden luonnin ohjelmointirajapintoihin.

Alibaba Token Plan tarjoaa samat kuusi nykyistä tekstinluontimallitunnusta Anthropic-yhteensopivan
päätepisteensä kautta. Sen Singapore-vaihtoehto tallentaa nykyisen `global-sg`-alueavaimen;
vain käyttäjälle näkyvä selite eroaa palveluntarjoajaperheistä, jotka kutsuvat aluetta Global-nimellä.

Tavallisen Qwen Cloudin keskusteluluettelo on tarkoituksellisesti suppeampi kuin koko reaaliaikainen tekstivastaus. Sen
ylläpidetty sallintaluettelo sijaitsee tiedostossa `open-sse/config/providers/registry/qwen-cloud/index.ts`; reaaliaikainen
haku palauttaa vain tunnukset, jotka sisältyvät sekä ylävirran vastaukseen että kyseiseen rekisteriluetteloon.

Alibaba Model Studio noudattaa samaa reaaliaikaista leikkaussääntöä oman, itsenäisesti ylläpidetyn
sallintaluettelonsa kanssa tiedostossa `open-sse/config/providers/registry/alibaba/index.ts`. `alibaba-cn`-yhteensopivuuspalveluntarjoaja
käyttää samaa luetteloa uudelleen mutta kohdistaa haun Beijing-päätepisteeseen.
