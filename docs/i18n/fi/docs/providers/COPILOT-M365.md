`copilot-m365-web` (alias `m365copilot`) lähettää OpenAI-muotoisia keskustelupyyntöjä todennetun Microsoft 365 Copilot BizChat -selainistunnon kautta osoitteessa `m365.cloud.microsoft/chat`. Tämä on epävirallinen integraatio.

> **Ovatko Web Cookie -palveluntarjoajat sinulle uusi asia?**
>
> Lue yleiset määritysohjeet, todentamista koskevat ohjeet, rajoitukset ja vianmääritysohjeet tiedostosta **`docs/getting-started/WEB-COOKIE-GUIDE.md`** ennen tämän palveluntarjoajakohtaisen oppaan noudattamista.
>
> **Tärkeää:** Tämän palveluntarjoajan tunnistetieto **ei ole eväste**. Älä kopioi
> evästeitä osoitteesta `m365.cloud.microsoft`. Tunnistetieto koostuu WebSocket-URL-osoitteen kyselyparametrista
> ja polkusegmentistä, jotka molemmat luetaan DevToolsin Network-välilehdeltä.

## Edellytykset

- Microsoft 365 -tili, jolla on pääsy BizChatiin osoitteessa `m365.cloud.microsoft/chat`
- Chromium-pohjainen selain (Chrome, Edge) WebSocket-yhteyksien tarkastelemiseen DevToolsissa
- M365 Copilot -lisenssi (sisältyy moniin Microsoft 365 Business- ja Enterprise-palvelupaketteihin)

## Tunnistetiedon tallentaminen (WebSocket-menetelmä)

1. Kirjaudu sisään osoitteessa `https://m365.cloud.microsoft/chat` ja aloita keskustelu.
2. Avaa **DevTools → Network**.
3. Suodata valitsemalla **WS** (WebSocket).
4. Napsauta Chathub-WebSocket-yhteyttä. Etsi URL-osoite, joka alkaa merkkijonolla
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Kopioi sen **Request URL** -kentästä:
   - `access_token`-kyselyparametrin arvo (lyhytikäinen JWT).
   - Chathub-polkusegmentti kohdan `/Chathub/` jälkeen (esim. `<oid>@<tenant>`).

Täydellinen URL-osoite on muotoa:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. Siirry OmniRoutessa kohtaan **Providers → Add Provider**, valitse **Microsoft 365 Copilot
   (BizChat)** ja liitä tunnistetieto seuraavassa muodossa:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Napsauta **Test Connection** ja **Save**.

## Tunnistetiedon tallentaminen (HAR-tuonti)

Sen sijaan, että kopioisit arvot manuaalisesti WebSocket-URL-osoitteesta, voit viedä DevToolsista HAR-tiedoston:

1. Avaa **DevTools → Network**.
2. Aloita BizChat-keskustelu tai jatka sitä (tämä käynnistää WebSocket-yhteyden).
3. Napsauta Network-paneelia hiiren kakkospainikkeella ja valitse **Save all as HAR with content**.
4. Käytä OmniRouten palveluntarjoajan yhteysikkunassa **Import .har file** -painiketta.

OmniRoute etsii HAR-tiedostosta Chathub-WebSocket-URL-osoitteen, poimii
`access_token`- ja `chathubPath`-arvot ja täyttää tunnistetietokentät automaattisesti.
HAR-tuonti purkaa JWT:n vanhenemisajan ja näyttää tunnisteen jäljellä olevan voimassaoloajan.

> **Älä koskaan tallenna oikeaa HAR-vientiä, käyttöoikeustunnistetta tai päivitystunnistetta versionhallintaan.** Testi- ja
> dokumentaatioarvojen on aina oltava paikkamerkkejä.

## Tunnisteen voimassaoloaika ja päivittäminen

`access_token` on lyhytikäinen (tavallisesti **~75 minuuttia**). Sen vanhennuttua palveluntarjoaja
ilmoittaa yhteysvirheestä, ja tunnistetieto on tallennettava uudelleen.

### Automaattinen päivittäminen `refreshToken`-arvolla

Voit välttää manuaalisen uudelleentallennuksen tallentamalla Microsoftin päivitystunnisteen yhteyden
**Advanced Settings → providerSpecificData** -kohtaan:

| Kenttä         | Kuvaus                                                                               |
| -------------- | ------------------------------------------------------------------------------------ |
| `refreshToken` | Microsoft OAuth -päivitystunniste `substrate.office.com/sydney`-käyttöaluetta varten |
| `tier`         | `individual` (oletus), `edu` tai `enterprise`                                        |

Hanki päivitystunniste Microsoftin laitekoodi- tai valtuutuskoodiprosessilla,
jonka käyttöalueena on `substrate.office.com/sydney`. Kun `refreshToken` on asetettu, OmniRoute
päivittää `access_token`-arvon ennakoivasti ennen jokaista pyyntöä, joten tunnistetietoa ei tarvitse
tallentaa uudelleen jokaisen noin 75 minuutin vanhenemisen jälkeen.

Jos `refreshToken`-arvoa ei ole asetettu, WebSocket-tunnistetieto on tallennettava manuaalisesti uudelleen
jokaisen vanhenemisen jälkeen.

### Tason valinta

| Taso         | Alias      | Käyttöympäristö          |
| ------------ | ---------- | ------------------------ |
| `individual` | _(oletus)_ | Kuluttajien M365 Copilot |
| `edu`        | `included` | Koulutuksen M365 Copilot |
| `enterprise` | `work`     | M365 Copilot for Work    |

Aseta taso kohdassa **Advanced Settings → providerSpecificData → tier**. Taso vaikuttaa
BizChat-reititykseen ja mallien käyttöoikeuksiin.

## Suojausmalli

- **Epävirallinen integraatio.** Tämä palveluntarjoaja perustuu BizChatin WebSocket-
  protokollan takaisinmallinnukseen. Se voi lakata toimimasta ilman ennakkoilmoitusta, kun Microsoft muuttaa päätepistettä.
- `subscriptionRisk: true`-merkintä ilmaisee, että integraatio käyttää
  dokumentoimatonta päätepistettä. Tiliin kohdistuvat rajoitukset ovat mahdollisia, mutta niitä ei ole vahvistettu.
- Käyttöoikeustunnus on lyhytikäinen JWT. Käsittele sitä kuin salasanaa: älä tallenna sitä versionhallintaan,
  kirjaa sitä lokiin tai jaa sitä.
- Päivitystunnus antaa pitkäaikaisen käyttöoikeuden BizChat-palveluun. Säilytä sitä
  yhtä huolellisesti kuin API-avainta.

## Vianmääritys

### Todennus epäonnistuu välittömästi

- Varmista, että kopioit tunnistetiedon **WebSocket-URL-osoitteesta**, et XHR/Fetch-pyynnöstä. Tunnistetieto
  on Chathub-WebSocket-yhteyden `access_token`-kyselyparametrissa
  — ei `Authorization: Bearer`-otsakkeessa.
- Varmista, että `chathubPath` sisältää URL-polun koko
  `<oid>@<tenant>`-osuuden.

### Tunnus vanhenee noin 75 minuutin kuluttua

Tämä on odotettua. Ilman `refreshToken`-tunnusta käyttöoikeustunnus on lyhytikäinen. Voit joko:

- Kaapata tunnistetiedon uudelleen DevToolsista tai
- määrittää `refreshToken`-tunnuksen lisäasetuksissa automaattista uusimista varten.

### Yhteystesti onnistuu, mutta keskustelu palauttaa 401-virheen

Tunnus on saattanut vanhentua vahvistuksen ja ensimmäisen pyynnön välillä. Kaappaa
uusi tunnistetieto.

### Copilot ei näy palveluntarjoajien luettelossa

Varmista, että `copilot-m365-web` on käytössä kohdassa **Hallintapaneeli → Palveluntarjoajat**. Palveluntarjoaja voi
olla oletusarvoisesti piilotettu joillakin tilaustasoilla.
