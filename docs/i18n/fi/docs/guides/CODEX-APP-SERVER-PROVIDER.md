OmniRoute tarjoaa **kaksi** tapaa käyttää OpenAI Codexia:

| Palveluntarjoaja       | Miten se kommunikoi OpenAI:n kanssa                                                                                                                                                                                                           | Käyttöä koskeva varaus                                                                                    |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| **`codex`**            | Välittää ChatGPT/OpenAI OAuth -tunnuksesi suoraan Responses API:lle                                                                                                                                                                           | **Kyllä** — virallista istuntoa ei ole valtuutettu käytettäväksi välityspalvelimen tai reitittimen kautta |
| **`codex-app-server`** | Ohjaa **Codex CLI:n omaa `codex app-server` -palvelinta** JSON-RPC:n ja WebSocketin kautta; CLI hallitsee OAuth-tunnistautumistaan ja päivittää sen automaattisesti (`~/.codex/auth.json`) täsmälleen kuten vuorovaikutteinen `codex`-istunto | **Ei** — OmniRoute ei koskaan välitä tunnusta API:lle                                                     |

Koska `codex-app-server` ei koskaan välitä tunnusta, siihen ei liity
istunnon uudelleenvälitystä koskevaa käyttövarausta. Se kuitenkin edellyttää,
että **Codex CLI on tavoitettavissa määritetyssä app-server-URL-osoitteessa**
ja että CLI:hin on **kirjauduttu sisään**.

---

## 1. Arkkitehtuuri

```
┌─ OmniRoute-sovellus ────────────┐        ┌─ codex-app-server-sivukontti ───────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ ominaisuustunnus)            │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  hallitsee OpenAI OAuthia itse      │
└──────────────────────────────────┘        │  (~/.codex/auth.json, autom. päivitys)│
        │ jakaa (compose-taltiot)            └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → WS-ominaisuustunnus (molemmat liittävät sen)
  codex-appserver-home    → ~/.codex (koontinäytön kirjoittama auth.json,
                             jota sivukontin codex app-server lukee)
```

- Sivukontti kuuntelee **vain** sisäisessä compose-verkossa
  (`ws://codex-app-server:1456`) ominaisuustunnuksen suojaamana. Sitä **ei
  koskaan** julkaista isäntäkoneelle tai internetiin.
- Codex CLI sisältyy valmiiksi `omniroute:base`-kuvaan, joten Codexia ei tarvitse
  asentaa isäntäkoneelle tai käyttäjän koneelle sivukonttia käytettäessä.

## 2. Käynnistys

```bash
# Käynnistä kokonaisuus codex app-server -sivukonttiprofiilin KANSSA:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

Sivukontti luo WS-ominaisuustunnuksensa ensimmäisellä käynnistyskerralla
(jaettuun `codex-appserver-token`-taltioon), ja sovellus lukee saman tunnuksen
muuttujan `OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE` kautta. Tunnusta ei tarvitse
kytkeä manuaalisesti.

## 3. Yhdistäminen ja sisäänkirjautuminen

1. Lisää koontinäytössä yhteys palveluntarjoajalle **OpenAI Codex (App-Server)**.
   API-avainta tai tunnusta ei tarvita (palveluntarjoaja ei käytä erillistä
   tunnistautumista, sillä sivukontti hallitsee sitä).
2. Jos sivukontin Codex CLI:hin **ei ole vielä kirjauduttu sisään**, yhteyden
   kuntotarkistus ilmoittaa _"käynnissä, mutta ei kirjautuneena"_ (ei punaista
   tunnistautumisvirhettä). Käytä toimintoa **Kirjaudu sisään ChatGPT:llä**:
   tämä suorittaa tavallisen Codexin laite-OAuth-tunnistautumisen selaimessasi
   ja kirjoittaa sitten tiedoston `~/.codex/auth.json` jaettuun taltioon
   **Ota tunnistautuminen käyttöön** -toiminnolla (sama kirjautuminen palvelee
   sekä `codex`- että `codex-app-server`-palveluntarjoajia).
3. Sisäänkirjautumisen jälkeen kuntotarkistus muuttuu vihreäksi (se tarkistaa
   sekä `/readyz`-päätepisteen **että** `account/read`-kutsun eli sen, että
   palvelu on käynnissä _ja_ tunnistautunut), ja yhteys alkaa toimia.

Koontinäyttö ei koskaan korvaa toimivaa olemassa olevaa
`~/.codex/auth.json`-tiedostoa — se kirjoittaa tiedoston vain, kun tiedostoa ei
ole tai sen tunnus on vanhentunut (varmuuskopio luodaan aina).

## 4. Käyttöönottotilanteet

- **Operaattori, jolla on jo tunnistautunut Codex CLI** — liitä isäntäkoneesi
  `~/.codex` sivukonttiin (`codex-appserver-home`) ja ohita kirjautumisvaihe.
- **Julkinen käyttäjä, jonka koneelle Codexia ei ole asennettu** — tällä ei ole
  merkitystä, sillä CLI sisältyy sivukonttiin. Käyttäjä tunnistautuu vain
  koontinäytön kautta.
- **OmniRoute suoraan palvelimella (ei sivukonttia, Codex isäntäkoneella)** —
  aseta `OMNIROUTE_CODEX_APPSERVER_WS` osoittamaan omaan
  `codex app-server` -palvelimeesi ja varmista, että isäntäkoneen Codexiin on
  kirjauduttu sisään; jos suoritettava tiedosto puuttuu, näytetään
  "Codexia ei ole asennettu" -vihje.

## 5. Kotitalousliittymän / UDP:n kautta lähtevä liikenne (operaattorin lisäominaisuus, ei mukana toimituksessa)

Yleinen sivukontti ohjaa lähtevän liikenteen yllä kuvatulla tavalla kontin
tavallisen verkon kautta. Operaattori, jonka on ohjattava Codex-liikenne
**kotitalousliittymän kautta** (esimerkiksi TUN-pohjaisen tailscale-sivukontin
kautta, joka välittää TCP- ja UDP/QUIC-liikenteen), ottaa sen käyttöön erillisellä
compose-ohituksella. Se **ei tarkoituksellisesti** kuulu toimitettavaan
`codex-app-server`-profiiliin. Katso kyseisen kokoonpanon ohjeet sisäisestä
ylläpidon käsikirjasta.
