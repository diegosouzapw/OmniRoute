> **TL;DR**: OmniRoute seuraa jokaisen pyynnön tokenien käyttöä, laskee kustannukset, valvoo API-avainkohtaisia kiintiöitä ja näyttää analytiikan hallintapaneelissa. Tässä oppaassa selitetään, miten tämä kaikki toimii.

**Lähteet:**

- `open-sse/services/usage.ts` (~70KB) — käytön pääasiallinen seuranta
- `src/lib/usageAnalytics.ts` (~10KB) — tietojen koostaminen hallintapaneelia varten
- `src/lib/db/quotaSnapshots.ts` — historialliset kiintiötiedot
- `src/lib/db/usage*.ts` — useita käyttöön liittyviä tietokantamoduuleja

## Yleiskatsaus

Jokainen OmniRouten kautta kulkeva pyyntö luo **käyttötietueen**, johon tallennetaan:

- **Tunnistetiedot**: API-avain, palveluntarjoaja, malli ja yhdistelmä
- **Tokenit**: kehotetokenit, vastaustokenit, välimuistissa olevat tokenit ja kokonaismäärä
- **Kustannus**: määrä Yhdysvaltain dollareina (lasketaan hinnoittelutiedoista)
- **Ajoitus**: viive sekä aloitus- ja lopetusaikaleimat
- **Tila**: onnistunut, virhe, nopeusrajoitettu jne.

Nämä tietueet koostetaan **analytiikaksi**, tallennetaan pysyvästi **kiintiövedoksina** ja niitä käytetään **avainkohtaisten budjettirajojen** valvontaan.

```
Pyyntö ──▶ chatCore ──▶ usage.record() ──▶ SQLite
                                  │
                          ┌───────┼───────┐
                          ▼       ▼       ▼
                    analytiikka kiintiö laskutus
                    (hallintapaneeli) (valvonta) (vienti)
```

## Mitä tallennetaan

`usage.ts`-palvelu tallentaa jokaisesta pyynnöstä **käyttötapahtuman**:

| Kenttä             | Tyyppi  | Lähde                                                        |
| ------------------ | ------- | ------------------------------------------------------------ |
| `id`               | string  | Tietuetta luotaessa generoitu UUID                           |
| `apiKeyId`         | string  | Pyynnön käynnistänyt API-avain                               |
| `provider`         | string  | Palveluntarjoajan tunnus (openai, anthropic jne.)            |
| `model`            | string  | Mallin tunnus (gpt-5, claude-opus-4-6 jne.)                  |
| `comboId`          | string? | Yhdistelmän tunnus, jos reititys tehtiin yhdistelmän kautta  |
| `promptTokens`     | number  | Ylävirran vastauksesta                                       |
| `completionTokens` | number  | Ylävirran vastauksesta                                       |
| `cachedTokens`     | number  | Välimuistiosuman tokenit (Anthropicin kehotevälimuisti jne.) |
| `totalTokens`      | number  | kehote + vastaus                                             |
| `costUsd`          | number  | Laskettu hinnoittelutiedoista                                |
| `latencyMs`        | number  | Pyynnön kokonaiskesto                                        |
| `status`           | enum    | `success`, `error`, `rate_limited`, `timeout`, `cancelled`   |
| `errorClass`       | string? | Virheluokka, jos tila != onnistunut                          |
| `timestamp`        | string  | ISO 8601 UTC                                                 |
| `metadata`         | object  | Liitännäisen lisäämät mukautetut tiedot                      |

### Mistä tokenit tulevat

Tokenit poimitaan ylävirran palveluntarjoajan vastauksesta **vastauskäsittelijässä**:

```ts
// Tiedostosta open-sse/handlers/chatCore.ts
const response = await providerExecutor.execute(provider, request);
const usage = response.usage || {
  prompt_tokens: 0,
  completion_tokens: 0,
  cached_tokens: 0,
};
```

Jos palveluntarjoaja ei palauta käyttötietoja (esimerkiksi jotkin verkkoevästeitä käyttävät palveluntarjoajat), OmniRoute **arvioi** tokenien määrän heuristiikalla `~4 merkkiä tokenia kohden` (katso `open-sse/services/autoCombo/pipelineRouter.ts`).

### Välimuistissa olevat tokenit

OmniRoute seuraa `cached_tokens`-tokeneita erillään `prompt_tokens`-tokeneista, koska:

- Anthropicin kehotevälimuistissa olevista tokeneista veloitetaan alennettu hinta (10 % normaalihinnasta)
- Jotkin palveluntarjoajat palauttavat `cache_read_input_tokens`-arvon, joka pitää hinnoitella eri tavalla
- Analytiikka voi näyttää **välimuistin osumaprosentin** = `cached_tokens / prompt_tokens`

## Kustannusten laskenta

Kustannukset lasketaan LiteLLM:stä synkronoitujen **hinnoittelutietojen** perusteella (`src/lib/pricingSync.ts`):

| Malli             | Syöte $/1M | Tuloste $/1M | Välimuistista $/1M |
| ----------------- | ---------- | ------------ | ------------------ |
| gpt-5             | $2.50      | $10.00       | —                  |
| claude-opus-4-6   | $15.00     | $75.00       | $1.50              |
| claude-sonnet-4-5 | $3.00      | $15.00       | $0.30              |
| gemini-2.5-pro    | $1.25      | $10.00       | —                  |

Kustannuskaava (`src/lib/usage/costCalculator.ts`):

```ts
cost =
  (prompt_tokens - cached_tokens) * input_price +
  cached_tokens * cached_price +
  completion_tokens * output_price;
```

> **Miksi välimuistista haetut tokenit vähennetään kehotteen tokeneista?** Välimuistista haettu osuus hinnoitellaan erikseen. Syötehinnan veloittaminen koko kehotteesta johtaisi kustannusten laskemiseen liian suuriksi.

### Hinnoittelun synkronointi

Hinnoittelutiedot synkronoidaan automaattisesti LiteLLM:stä `/api/pricing/sync`-päätepisteen kautta (sisäänrakennettu cron-tehtävä käynnistää synkronoinnin, ei käyttäjälle tarkoitettu ympäristömuuttuja):

```bash
# Manuaalinen käynnistys
curl -X POST http://localhost:20128/api/pricing/sync
```

Malleille, joille ei ole saatavilla hinnoittelutietoja, OmniRoute **arvioi kustannukset** käyttäen sisäisiä keskimääräisiä hintoja (jotka perustuvat LiteLLM:n hinnoittelutietoihin).

## Päivämäärävälin aggregointi

`usageAnalytics.ts`-moduuli laskee hallintapaneelin pienoissovellusten tiedot raaoista käyttötiedoista. Se tukee seitsemää aikaväliä:

| Aikaväli | Ajanjakso                                   | Käyttötapaus                                |
| -------- | ------------------------------------------- | ------------------------------------------- |
| `1d`     | Viimeiset 24 tuntia                         | Tuntikohtaisten kustannuspiikkien tunnistus |
| `7d`     | Viimeiset 7 päivää                          | Viikoittainen tarkastelu                    |
| `30d`    | Viimeiset 30 päivää                         | Kuukausittainen laskutus                    |
| `90d`    | Viimeiset 90 päivää                         | Neljännesvuosittainen analyysi              |
| `ytd`    | Kuluvan vuoden tammikuun 1. päivästä alkaen | Vuosibudjetin seuranta                      |
| `all`    | Koko ajalta                                 | Kaikkien aikojen tilastot                   |
| `custom` | Käyttäjän määrittämä alku ja loppu          | Tarkastukset ja ad hoc -kyselyt             |

### Laskettavat hallintapaneelin pienoissovellukset

Analytiikkakerros laskee mille tahansa päivämäärävälille seuraavat tiedot:

| Pienoissovellus                        | Kuvaus                                                                |
| -------------------------------------- | --------------------------------------------------------------------- |
| **Yhteenvetokortit**                   | Pyyntöjen, kustannusten ja tokenien kokonaismäärä sekä onnistumisaste |
| **Päivittäinen trendikaavio**          | Päiväkohtaiset kustannukset ja tokenit malleittain pinottuina         |
| **Aktiivisuuden lämpökartta**          | Kellonaika × viikonpäivä -ruudukko, väri = pyyntöjen määrä            |
| **Mallikohtainen erittely**            | Ympyräkaavio kustannuksista malleittain                               |
| **Palveluntarjoajakohtainen erittely** | Pylväskaavio pyynnöistä palveluntarjoajittain                         |
| **Suosituimmat API-avaimet**           | Taulukko kymmenestä kustannuksiltaan suurimmasta avaimesta            |
| **Virheanalyysi**                      | Virheaste ajan kuluessa ja yleisimmät virheluokat                     |

### Ohjelmallinen käyttö

````ts
import { computeAnalytics } from "@/lib/usageAnalytics";

const analytics = await computeAnalytics(
  history,              // käyttöhistoriatietueet
  "7d",                 // aikaväli: "1d" | "7d" | "30d" | "90d" | "ytd" | "all" | "custom"
  connectionMap,        // palveluntarjoajayhteyksien kartta (connectionId → tilin nimi)
  {
    startDate: "2025-01-01",  // valinnainen: "custom"-aikaväliä varten
    endDate: "2025-06-01",   // valinnainen: "custom"-aikaväliä varten
  }
);

console.log(analytics.summary.totalCost);   // 12.34 (senttiä)
console.log(analytics.byModel[0]);           // { model, cost, requests, promptTokens, completionTokens }

## Kiintiön valvonta

API-avainkohtainen kiintiö valvotaan kahdessa kohdassa:

1. **Pehmeä raja** (`quotaWarnAt`): hallintapaneelissa näytetään varoitus, kun käyttö ylittää raja-arvon
2. **Kova raja** (`quotaLimit`): pyyntö hylätään HTTP 429 -vastauksella, kun raja ylittyy

### Määritys

```ts
// API-avainkohtainen
await updateApiKey(keyId, {
  quotaWarnAt: 5_00,    // 5,00 $ — näytä varoitus
  quotaLimit: 10_00,    // 10,00 $ — ehdoton raja
  quotaWindow: "month", // "day" | "week" | "month" | "all"
});
````

### Valvonnan kulku

```
Pyyntö ──▶ quotaCheck()
             │
             ├── Rajan sisällä? ──▶ salli
             │
             └── Raja ylitetty? ──▶ 429 Too Many Requests
                                      Retry-After-otsakkeen kanssa
```

### Kiintiön tilannevedokset

`quotaSnapshots`-taulu tallentaa **kiintiön historiallisen tilan** trendianalyysiä varten:

| Kenttä | Kuvaus |
| ----------- | ----------------------------------------- | ------ | ------- |
| `apiKeyId` | Seurattava avain |
| `window` | "day" | "week" | "month" |
| `used` | Tässä ikkunassa käytetty summa (sentteinä) |
| `limit` | Raja (sentteinä) |
| `resetAt` | Ajankohta, jolloin ikkuna nollautuu |
| `createdAt` | Ajankohta, jolloin tilannevedos otettiin |

Tilannevedos otetaan **jokaisesta pyynnöstä**, jonka kustannus on > 0, ja niitä käytetään seuraaviin tarkoituksiin:

- Kiintiön edistymispalkin näyttäminen hallintapaneelissa
- Kiintiön 30 päivän trendikaavioiden näyttäminen
- Hälytysten käynnistäminen käytön lähestyessä rajaa

## Säilytys ja puhdistus

Käyttödata kasvaa noin 1–10 kt jokaista pyyntöä kohden. Suuressa mittakaavassa määrä voi olla merkittävä.

### Säilytysasetukset

Käyttöhistorian säilytys määritetään käyttöliittymän tietokanta-asetuksissa tai `/api/settings/database`-rajapinnan kautta.

Oletusarvoisesti käyttöhistoria säilytetään **90 päivän ajan**.

### Puhdistus

Vanhat tietueet puhdistaa `src/lib/db/cleanup.ts`:

- Taustalla toimiva cron-prosessi käynnistää puhdistuksen
- Poistaa `usage_history`-taulusta tietueet, jotka ovat määritettyä `usageHistory`-säilytysasetusta vanhempia

### Tallennustilan arvio

| Pyyntömäärä           | Tallennustila 30 päivälle | Tallennustila 90 päivälle |
| --------------------- | ------------------------- | ------------------------- |
| 100 pyyntöä/päivä     | ~3 Mt                     | ~9 Mt                     |
| 1 000 pyyntöä/päivä   | ~30 Mt                    | ~90 Mt                    |
| 10 000 pyyntöä/päivä  | ~300 Mt                   | ~900 Mt                   |
| 100 000 pyyntöä/päivä | ~3 Gt                     | ~9 Gt                     |

Erittäin suurilla liikennemäärillä kannattaa harkita seuraavia:

- Lyhennä säilytysaikaa tietokanta-asetuksissa
- Käytä raakatietueiden sijaan `aggregated_metrics`-tietoja (vain analytiikkaan)

## Vinkkejä kustannusten optimointiin

### 1. Käytä oikeaa mallia

```bash
# Nopea vastaus — käytä edullista ja nopeaa
curl -d '{"model":"auto/fast","messages":[...]}'

# Monimutkainen tehtävä — panosta laatuun
curl -d '{"model":"auto/smart","messages":[...]}'
```

### 2. Ota välimuisti käyttöön

Anthropicin kehotevälimuisti säästää **90 % toistuvan kontekstin kustannuksista**:

```ts
// Välimuisti toimii automaattisesti — sisällytä vain sama suuri järjestelmäkehote
const response = await openai.chat({
  model: "claude-sonnet-4-5",
  system: longSystemPrompt, // Tallennetaan automaattisesti välimuistiin
  messages: [{ role: "user", content: "..." }],
});
```

### 3. Käytä pakkausta

RTK + Caveman -pakkaus säästää **15–95 % paljon työkaluja käyttävissä istunnoissa**:

```ts
const config = {
  compression: {
    engine: "rtk",
    intensity: "aggressive",
  },
};
```

### 4. Aseta avainkohtaiset kiintiöt

Aseta aina `quotaLimit`, jotta kustannukset eivät kasva hallitsemattomasti:

```ts
await updateApiKey(keyId, { quotaLimit: 10_00 }); // 10 dollarin kuukausiraja
```

### 5. Tarkista eniten kuluttavat käyttäjät

Ryhmittele API-avaimen mukaan ja lajittele kustannuksen perusteella hallintapaneelissa tai **`/api/usage/analytics`**-rajapinnan avulla:

```bash
GET /api/usage/analytics?groupBy=apiKey
```

## Vianmääritys

### "Kustannukset ovat odotettua suuremmat"

1. Tarkista **`/api/usage/analytics?groupBy=model`** — etsi kallis malli
2. Tarkista **`/api/usage/analytics?groupBy=apiKey`** — etsi paljon kuluttava käyttäjä
3. Varmista, että hintatiedot ovat ajan tasalla: `POST /api/pricing/sync`

### "Tietueita puuttuu"

- Tarkista tietokannan säilytysasetukset kohdasta Hallintapaneeli → Tietokanta → Puhdistus — ajoittainen puhdistustehtävä (`src/lib/db/cleanup.ts`) poistaa vanhat tietueet
- Tarkista virheet tiedostoista `src/lib/db/usage*.ts` — tietokantaan kirjoittamisen virheet kirjataan lokiin, mutta niitä ei tuoda näkyviin
- Varmista, että pyyntö todella saavutti `chatCore`-toiminnon — tarkista yhdistelmäreititys

### "Kiintiötä ei valvota"

- Tarkista avaimen `quotaLimit`-asetus
- Varmista, että `quotaWindow` on asetettu oikein
- Etsi `quotaSnapshots`-tietueita — niitä pitäisi luoda jokaisen pyynnön yhteydessä
