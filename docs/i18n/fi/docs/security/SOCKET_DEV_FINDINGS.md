> **Laajuushuomautus:** `socket.yml` määrittää Socket.dev-palvelun rekisteripuolella julkaisun jälkeen suoritettavan npm-artefaktin tarkistuksen (ohitettavat polut pakettiin kuulumattomalle sisällölle, kuten `tests/`, `docs/` ja koontiraportit). Se ei määritä CI-/PR-yhdistämisporttia — mikään `.github/workflows`-hakemiston työnkulku, `package.json`-komentosarja tai `Makefile`-kohde ei kutsu Socket.dev-palvelua.

Tämä asiakirja on ylläpitäjän laatima vakuutus kuudesta
`AI-detected potential malware` -havainnosta, jotka tehtiin paketista `omniroute@3.8.5`, sekä
versiossa `omniroute@3.8.6` toteutetuista lievennyksistä. Sen tarkoituksena on, että:

1. Tietoturvaputkien ylläpitäjillä on yksi viite, johon vedota, kun heidän on
   arvioitava havaintoja suhteessa todelliseen lähdekoodiin.
2. Tulevat tekoälyskannerit voivat tunnistaa ylläpitäjän allekirjoittaman vakuutuksen siitä, että jokainen
   merkitty polku on tarkoituksellinen, erikseen käyttöön otettava ja dokumentoitu.
3. Meillä on kirjallinen tieto siitä, _miksi_ kukin kutsukohta on toteutettu juuri kyseisellä tavalla —
   jotta tuleva refaktorointi ei vahingossa palauta tunnusjälkeä, joka
   poistettiin tarkoituksella.

Jos ylläpidätte skanneria, joka merkitsee jonkin alla olevista kutsukohdista uudelleen sen jälkeen, kun
v3.8.6-version lievennykset on julkaistu, avatkaa ongelmaraportti ja liittäkää mukaan tarkistuksen jäljitystiedot,
niin täydennämme tätä vakuutusta.

## §1 — MITM-juurivarmenteen asennus (`77484.js`)

**Lähdetiedostot**:

- `src/mitm/cert/install.ts` — julkiset `installCert()` / `uninstallCert()`,
  alustakohtaiset `installCertWindows/Mac/Linux`.
- `src/mitm/systemCommands.ts` — asennuspolkujen käyttämät yhteiset `execFile`- / `spawn`- / PowerShell-
  apufunktiot.

**Käynnistin**: käyttäjä napsauttaa paikallisen hallintapaneelin
`/dashboard/cli-tools/mitm`-sivulla kohtaa "Ota MITM-välityspalvelin käyttöön". Reitti on käytettävissä vain takaisinkytkentärajapinnan kautta — katso ehdoton sääntö #17 tiedostossa
`CLAUDE.md` ja `src/server/authz/routeGuard.ts::isLocalOnlyPath()`. Tunnelin kautta paljastunut
JWT **ei voi** käynnistää tätä koodipolkua.

**Suoritettavat etuoikeutetut toiminnot (alustoittain)**:

| Käyttöjärjestelmä      | Komennot                                                                                                          |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | `certutil -addstore Root <cert>` UAC:n kautta                                                                     |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | profiilikohtainen NSS-tietokannan päivitys komennolla `certutil -d sql:<profile>`                                 |

Nämä ovat samat komennot, joita `mitmproxy`, Charles Proxy, Fiddler ja
Caddy käyttävät. Niiden sisältyminen OmniRouteen on dokumentoitu tiedostossa
`docs/security/STEALTH_GUIDE.md`.

**Version v3.8.6 lievennys**:

- `runElevatedPowerShell()` ei enää käytä parametria `-EncodedCommand <base64utf16le>`.
  Korotetuilla oikeuksilla suoritettava hyötykuorma kirjoitetaan kutsukohtaiseen väliaikaiseen `.ps1`-tiedostoon (tila 0o600,
  yksityisen `mkdtempSync`-hakemiston sisällä), ja siihen viitataan parametrilla `-File`.
  Tiedoston linkitys poistetaan `finally`-lohkossa. Tämä poistaa Socket.dev-palvelun tekoälyluokittelijan merkitsemän tyypillisen
  PowerShellin kautta tapahtuvan base64-koodatun oikeuksien korottamisen sormenjäljen.
- `installCertWindows` sisältää koodinsisäisen `SECURITY-AUDITOR-NOTE:`-lohkon,
  joka viittaa tähän asiakirjaan.

**Miksi säilytämme sen**: MITM-välityspalvelin on dokumentoitu ominaisuus, jota
`docs/security/STEALTH_GUIDE.md` ja `docs/frameworks/MITM-PROXY.md` hyödyntävät. Sen poistaminen
rikkoisi agenttisiltaominaisuudet.

## §2 — Zed-tunnistetietojen tuonti (`app/api/providers/zed/import/route.js`)

**Lähdetiedostot**:

- `src/app/api/providers/zed/discover/route.ts` _(uusi versiossa v3.8.6)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(uusi versiossa v3.8.6)_

**Käynnistin**: käyttäjä napsauttaa paikallisen hallintapaneelin Palveluntarjoajat-sivulla "Tuo Zedistä". Päätepiste on suojattu `requireManagementAuth`-tarkistuksella. Zed-editori itse tallentaa palveluntarjoajiensa API-avaimet käyttöjärjestelmän avainnippuun dokumentoiduilla palvelunimillä — katso https://zed.dev/docs/ai/llm-providers.

**v3.8.5:n toiminta (jonka Socket.dev merkitsi)**:

`POST /import` etsi tunnistetiedot ja tallensi ne automaattisesti paikalliseen SQLite-tietovarastoon yhdellä edestakaisella pyynnöllä. Ei tilikohtaista vahvistusta eikä sormenjälkeä, vain "löydettiin N tunnusta, kaikki tuotiin."

**v3.8.6:n lievennys — 2-vaiheinen vahvistus**:

1. **`POST /api/providers/zed/discover`** palauttaa
   `{ candidates: [{ provider, service, account, fingerprint }] }`. Raakatunnusta
   **ei koskaan** välitetä. Sormenjälki on
   `sha256(service|account|token).slice(0,16)`.
2. Hallintapaneeli näyttää ehdokasluettelon, operaattori valitsee tuotavat
   tunnistetiedot ja lähettää arvon `{ confirmedAccounts: [{ service, account, fingerprint }] }`
   päätepisteeseen **`POST /api/providers/zed/import`**.
3. Tuontipäätepiste **lukee palvelimen avainnipun uudelleen** ja suodattaa
   tulokset yhdistelmän `(service, account, fingerprint)` perusteella. Muokattu tai
   uudelleentoistettu etsintävastaus ei voi huijata tuontipäätepistettä tallentamaan
   asiaankuulumatonta tunnusta — jos aktiivinen tunnus on muuttunut etsinnän jälkeen,
   sormenjälki ei enää täsmää ja tunnistetieto ohitetaan.

Ympäristömuuttuja `OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` säilyttää v3.8.5:n
toiminnan operaattoreille, jotka eivät ole vielä päivittäneet automaatiotaan. Se
poistetaan versiossa v3.9.

**Miksi säilytämme sen**: Zed-tuonti on käyttäjäystävällisin aloitustapa
käyttäjille, jotka jo käyttävät Zediä ja haluavat kopioida palveluntarjoajiensa
avaimet OmniRouteen syöttämättä niitä uudelleen.

## §3 — `execFile` / `spawn` / korotetuilla oikeuksilla suoritettava PowerShell (`21843.js`)

**Lähdetiedostot**: `src/mitm/systemCommands.ts`.

**Miksi merkitty**: lohko vie uudelleen `execFileWithPassword`- ja
`runElevatedPowerShell`-toiminnot sekä jaetun `quotePowerShell`-aputoiminnon. Socket.dev:n
tekoälyluokittelija tulkitsee ne yleiskäyttöiseksi "isäntäjärjestelmän komentojen suoritus- ja
käyttöoikeuksien korotustyökaluksi". OmniRoutessa niitä käytetään vain MITM-varmenteen
asennuspolulla (§1) ja `execFileWithPassword`-toiminnossa `sudo`-komentojen suorittamiseen.

**v3.8.6:n lievennys**:

- `runElevatedPowerShell`-toiminnon refaktorointi (katso §1).
- Sekä `runElevatedPowerShell`- että `execFileWithPassword`-toiminnon yhteydessä oleva
  sisäinen `SECURITY-AUDITOR-NOTE:`-lohko dokumentoi sallittujen kutsujien
  luettelon ja kiinteän suoritettavien tiedostojen luettelon.
- `execFileWithPassword`-toiminnon `spawn()`-kutsu sisältää `nosemgrep`-merkinnän sekä
  luettelon suoritettavista tiedostoista, joita aputoiminto saa vastaanottaa —
  käyttäjän syötteestä **ei ole polkua kohteisiin `finalCommand`/`finalArgs`**.

## §4 / §6 — 9router-palvelun valvoja (`api/services/9router/{start,restart}/route.js`)

**Lähdetiedostot**:

- `src/app/api/services/9router/_lib.ts` — valvojan tehdas.
- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`.
- `src/lib/services/ServiceSupervisor.ts` — yleiskäyttöinen prosessin käynnistys / kuntotarkistuskysely / lokipuskuri.

**Käynnistin**: käyttäjä napsauttaa paikallisen hallintapaneelin upotettujen
palvelujen sivulla "Asenna" / "Käynnistä".

**Jo käytössä olevat suojaukset**:

- Kaikki `/api/services/*`-reitit ovat LOCAL_ONLY-reittejä tiedoston
  `src/server/authz/routeGuard.ts` mukaisesti (ehdoton sääntö #17). Loopback-rajoitus
  tehdään ennen mitään todennustarkistusta — vuotanut JWT ei pääse niihin käsiksi.
- 9router-tietokantariville alustetaan arvot `status='not_installed', auto_start=0` (katso
  `src/lib/db/migrations/071_services.sql:19`). Palvelu **ei** käynnisty
  ensimmäisellä käynnistyskerralla.
- `spawn()` kutsutaan binääripolulla, jonka
  `resolveSpawnArgs(apiKey, PORT)` palauttaa tiedostossa `src/lib/services/installers/ninerouter.ts`;
  kyseessä on kiinteä luettelo tuetuista binääreistä.
- Stdout/stderr puskuroidaan muistiin (5 MB:n raja, katso `_lib.ts`) — levylle
  ei kirjoiteta, ellei käyttäjä ota lokitusta käyttöön hallintapaneelista.

**v3.8.6:n lievennys**: ei toiminnallisia muutoksia. Minimaalinen koontiprofiili
(`OMNIROUTE_BUILD_PROFILE=minimal`) korvaa tiedoston
`src/lib/services/installers/ninerouter.ts` tynkäversiolla käyttäjille, jotka haluavat
poistaa korotettuja oikeuksia käyttävät polut fyysisesti paketista.

**Miksi säilytämme sen**: 9router on valinnainen, paikallisesti asennettava kumppanipalvelu
(ajattele WordPress-tyylistä lisäosaa) — käyttöön vain nimenomaisella suostumuksella.

## §5 — OmniRoute Cloud Sync -tunnistetietojen takaisinkirjoitus (`api/keys/[id]/route.js`)

**Lähdetiedostot**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`.
- `src/app/api/keys/[id]/route.ts` — kutsuu funktiota `syncKeysToCloudIfEnabled()`.

**Laukaisin**: `isCloudEnabled()` palauttaa arvon `true` (määritetään hallintapaneelista) **ja**
`CLOUD_URL` on määritetty. Kun molemmat ovat poissa käytöstä, Cloud-päätepisteeseen
ei tehdä lähtevää verkkokutsua.

**Version v3.8.5 toiminta (virhe, jonka Socket.dev havaitsi oikein)**:

`updateLocalTokens()` korvasi `accessToken`-, `refreshToken`- ja
`providerSpecificData`-arvot Cloud-vastauksesta, kun
`cloudUpdatedAt > localUpdatedAt`. Ei HMAC-tarkistusta, ei allekirjoitusta, ei tarkistussummaa.
Virheellisesti määritetty tai vihamielinen `CLOUD_URL` (tai kanavalla toimiva MITM-hyökkääjä)
saattoi vaihtaa palveluntarjoajan OAuth-tokenit huomaamatta.

**Version v3.8.6 lievennys**:

1. **HMAC-tarkistus**: `verifyCloudSignature(rawBody, sigHeader)` tarkistaa
   `X-Cloud-Sig`-otsakkeen (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`) ennen JSON-jäsennystä. Jos salaisuus on asetettu, allekirjoitus
   vaaditaan. Jos sitä ei ole asetettu (vanha yhteensopivuustila), varoitus kirjataan
   lokiin ja vastaus hyväksytään — salaisuus on pakollinen versiossa v3.9.
2. **Salaisten kenttien erillinen käyttöönotto**: `accessToken` / `refreshToken` /
   `providerSpecificData` korvataan **vain**, kun
   `OMNIROUTE_CLOUD_SYNC_SECRETS=true`. Oletustila synkronoi vain
   metatiedot, jotka eivät ole tunnistetietoja (`expiresAt`, `status`, `lastError*`,
   `rateLimitedUntil`, `updatedAt`). Tämä on **yhteensopivuutta rikkova muutos**
   käyttäjille, jotka luottivat etätokenien synkronointiin — heidän on otettava se
   nimenomaisesti käyttöön.

**Miksi säilytämme sen**: Cloud Sync on OmniRoute Cloud -vuokraajan ainoa tapa
keskittää tiimin tunnistetiedot. Korjaus tekee uhkamallista rehellisen:
"palvelin allekirjoittaa, asiakas tarkistaa, operaattori ottaa käyttöön."

## Koontiprofiili: `minimal`

Käyttäjät, jotka tarvitsevat Socket-yhteensopivan artefaktin, voivat koota sen komennolla:

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

Webpackin `NormalModuleReplacementPlugin` määrittää neljälle moduulille stub-korvikkeet:

| Moduuli                                     | Stub                                             |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

Kukin stub vie saman rajapinnan, mutta jokainen funktio heittää suorituksen aikana
`featureDisabledError(name)`-virheen. Käytöstä poistetusta moduulista riippuvat
reitit palauttavat HTTP 503 -vastauksen ja selkeän viestin sen sijaan, että
arkaluonteinen koodipolku aktivoitaisiin.

Tuloksena syntyvä paketti on tarkoitus julkaista nimellä `omniroute-secure`. Katso
julkaisuohjeet tiedostosta `docs/ops/PUBLISHING_SECURE.md`.

moduuleihin. Katso seurantaan liittyvä issue GitHubin issue-seurannan v4-virstanpylväästä.
