Traffic Inspector on OmniRouten sisäänrakennettu HTTPS-liikenteen vianmääritystyökalu — Charles Proxya / mitmwebiä / HTTP Toolkitia muistuttava työkalu, joka on **LLM-tietoinen** ja **agenttitietoinen**. Se sijaitsee osoitteessa `/dashboard/tools/traffic-inspector` ja vastaanottaa reaaliaikaista liikennettä enintään viidestä samanaikaisesta kaappauslähteestä.

**Sijainti hallintapaneelissa:** `/dashboard/tools/traffic-inspector`
**Sivupalkin ryhmä:** Työkalut (AgentBridgen jälkeen)
**Katso myös:** [`AGENTBRIDGE.md`](./AGENTBRIDGE.md) — AgentBridge on kaappaustila 1.

### Arkkitehtuuri yhdessä kappaleessa

`TrafficBuffer` (`src/mitm/inspector/buffer.ts`) on jaettu muistissa oleva rengaspuskuri (oletusarvoisesti 1000 merkintää, määritettävissä `INSPECTOR_BUFFER_SIZE`-ympäristömuuttujalla). Kaikki kaappauslähteet kirjoittavat siihen `push()`-menetelmällä. Puskuri luokittelee jokaisen merkinnän `kindDetector.ts`-tiedoston avulla (määrittää, onko kyseessä LLM-pyyntö), laskee `contextKey`-arvon (järjestelmäkehotteen SHA-256-sormenjälki) ja lähettää merkinnän kaikille WebSocket-tilaajille `globalTrafficBuffer.subscribe()`-menetelmän kautta. Hallintapaneeli muodostaa yhteyden osoitteeseen `GET /api/tools/traffic-inspector/ws` ja vastaanottaa yhteyden muodostamisen yhteydessä tilannekuvan, jota seuraavat `new`-/`update`-/`clear`-tapahtumat.

## §2 Kaappaustilat

Traffic Inspector tukee **viittä samanaikaista kaappauslähdettä**. Kukin niistä voidaan ottaa käyttöön tai poistaa käytöstä itsenäisesti. Jokaisen `InterceptedRequest`-objektin (`src/mitm/inspector/types.ts`) `source`-kentän arvo on jokin seuraavista: `"agent-bridge"`, `"custom-host"`, `"http-proxy"`, `"system-proxy"` tai `"tproxy"`.

### Tila 1 — AgentBridge (oletus, aina käytössä)

**Lähde:** AgentBridge-käsittelijät (`src/mitm/handlers/base.ts`)
**Mekanismi:** Jokainen `MitmHandlerBase`-luokan `intercept()`-kutsu kutsuu `hookBufferStart()`-funktiota ennen välitystä ja `hookBufferUpdate()`-funktiota valmistumisen yhteydessä. Lisämäärityksiä ei tarvita — toimii heti, kun AgentBridge on käynnissä.
**Kattavuus:** AgentBridgeen määritetyt 9 IDE-agenttia
**Huomautus:** `InterceptedRequest`-objektin `source`-kenttä = `"agent-bridge"`

### Tila 2 — Mukautetut isännät (DNS-uudelleenohjaus)

**Lähde:** Käyttäjän määrittämä isäntäluettelo (`inspector_custom_hosts`-taulu)
**Mekanismi:** Isännän lisääminen käyttöliittymässä lisää rivin `127.0.0.1 <host>` tiedostoon `/etc/hosts` (vaatii sudo-oikeudet). Nykyinen AgentBridge-MITM-palvelin (portti 443) luo uudelle isännälle dynaamisesti SNI-varmenteen.
**Kattavuus:** Kaikki lisättyä isäntää käyttävät sovellukset — sovelluksen määrityksiä ei tarvitse muuttaa
**Huomautus:** `source` = `"custom-host"`

Esimerkkejä käyttötapauksista:

- `api.openai.com`-liikenteen valvonta Python-skripteistä
- `my-internal-llm.company.com`-palvelun virheenkorjaus
- Samassa verkossa olevien mobiililaitteiden liikenteen kaappaus (ARP-huijauksen avulla — edistynyt)

### Tila 3 — HTTP_PROXY-kuuntelija (portti 8080)

**Lähde:** `HTTP_PROXY`/`HTTPS_PROXY`-ympäristömuuttujia käyttävät sovellukset
**Mekanismi:** Portissa 8080 toimiva toissijainen kuuntelija (`src/mitm/inspector/httpProxyServer.ts`), joka toimii tavallisena eksplisiittisenä HTTP/HTTPS-välityspalvelimena. Hyväksyy `CONNECT`-tunnelit (HTTPS) ja suorat HTTP-pyynnöt.
**Kattavuus:** Kaikki `HTTP_PROXY`-ympäristömuuttujaa noudattavat sovellukset — ei DNS-muutoksia eikä sudo-oikeuksia
**Huomautus:** `source` = `"http-proxy"`

```bash
# Yksittäisen komennon nopea kaappaus:
HTTPS_PROXY=http://127.0.0.1:8080 curl https://api.openai.com/v1/models

# Jatkuva kaappaus komentotulkki-istunnossa:
export HTTP_PROXY=http://127.0.0.1:8080
export HTTPS_PROXY=http://127.0.0.1:8080
```

**TLS-rajoitus:** HTTPS-`CONNECT`-tunneleista kaapataan oletusarvoisesti vain metatiedot (isäntä, portti ja ajoitus) — TLS-sisältöä ei pureta. Ota käyttöön "Pura HTTPS-salaus välityspalvelintilassa" -valitsin (valinnainen, edellyttää, että AgentBridge-varmenteeseen luotetaan), jotta koko sisältö voidaan tarkastaa.

**Porttiristiriita:** Jos portti 8080 on käytössä, AgentBridge palauttaa 409-vastauksen ja jäsennellyn virheen. Vaihda portti `INSPECTOR_HTTP_PROXY_PORT`-ympäristömuuttujan avulla.

### Tila 4 — Järjestelmänlaajuinen välityspalvelin (edistynyt, valinnainen)

**Lähde:** Käyttöjärjestelmätason välityspalvelinasetukset (koskee koneen kaikkia sovelluksia)
**Mekanismi:** Ohjaa kaiken HTTP/HTTPS-liikenteen HTTP_PROXY-kuuntelijan kautta käyttöjärjestelmän rajapintojen avulla:

- **macOS:** `networksetup -setwebproxy / -setsecurewebproxy`
- **Linux:** `gsettings set org.gnome.system.proxy` + `/etc/environment`
- **Windows:** `netsh winhttp set proxy 127.0.0.1:8080`
  **Kattavuus:** Kaikki koneen sovellukset, jotka noudattavat järjestelmän välityspalvelinasetuksia
  **Huomautus:** `source` = `"system-proxy"`

**Turvamekanismit:**

- Automaattisen käytöstäpoiston ajastin (oletusarvoisesti 30 min, määritettävissä `INSPECTOR_SYSTEM_PROXY_GUARD_MINUTES`-ympäristömuuttujalla)
- Järjestelmän välityspalvelimen aiempi tila tallennetaan tietokantaan ja palautetaan kumoamisen yhteydessä
- Koontinäyttö näyttää "Palautetaan järjestelmän välityspalvelinta" -kehotteen, jos käyttäjä siirtyy pois sen ollessa aktiivinen
- Käyttöliittymä näyttää `⚠ Edistynyt` -merkin ja erillisen vahvistusvalintaruudun

### Tila 5 — Läpinäkyvä TPROXY-salauksen purku (Linux, root, valinnainen)

**Lähde:** Ytimen TPROXY + käytäntöpohjainen reititys (`src/mitm/tproxy/`)
**Mekanismi:** Merkitsee uudet paikalliset lähtevät TCP-yhteydet kohdeporttiin (oletus `443`) `mangle OUTPUT`-ketjussa, minkä jälkeen `ip rule` uudelleenreitittää merkityt paketit paikalliseen toimitukseen ja `mangle PREROUTING`-ketjun `TPROXY`-kohde luovuttaa ne läpinäkyvälle (**IP_TRANSPARENT**) kuuntelijalle (oletusportti `8443`). Kuuntelija päättää TLS-yhteyden dynaamisen varmentajan **kullekin SNI-isäntänimelle tarvittaessa myöntämällä** loppuvarmenteella, kaappaa salaamattoman tiedonsiirron ja välittää pyynnön uudelleen salattuna alkuperäiseen kohteeseen.
**Kattavuus:** **Mielivaltaiset** kohdeisännät kohdeportissa — ei `/etc/hosts`-huijausta, ei `HTTP_PROXY`-ympäristömuuttujaa eikä järjestelmänlaajuisen välityspalvelimen muuttamista. Siepattavan prosessin määrityksiä ei tarvitse muuttaa, mutta sen on luotettava dynaamiseen varmentajaan.
**Huomautus:** `source` = `"tproxy"`

**Vaatimukset:** Vain Linux (**IP_TRANSPARENT** on saatavilla vain Linuxissa), **CAP_NET_ADMIN**-ominaisuus (root) ja natiivi N-API-lisäosa, joka on koostettava C-työkaluketjulla (`npm run build:native:tproxy`). Kun vaatimukset eivät täyty, koontinäytön valitsin poistetaan käytöstä ja sen työkaluvihjeenä näytetään "TPROXY-salauksen purku vaatii Linuxin, root-oikeudet ja natiivin lisäosan". Palomuurisäännöt otetaan käyttöön ja kumotaan transaktionaalisesti (kaatuminen ei koskaan jätä `mangle`-sääntöä jäljelle), ja ne tyhjennetään uudelleenkäynnistyksen yhteydessä. SO_MARK-pohjainen silmukanesto estää välityspalvelimen omaa uudelleen salattua välitystä joutumasta uudelleen siepatuksi.

Tämä on laaja alijärjestelmä, jolla on oma erillinen ylläpitäjän oppaansa — täydellinen palomuurimääritys, SNI-kohtainen dynaaminen varmentaja ja luottamussäilön asennusohjelma, vain paikallinen reitti, silmukaneston tiedot sekä määritysskeema ovat tiedostossa `docs/security/MITM-TPROXY-DECRYPT.md` (git; ei koosteta osaksi `/docs`-hakemistoa). Valitsinta ohjataan reiteillä `GET / POST / DELETE /api/tools/agent-bridge/tproxy` (huomautus: reitti sijaitsee AgentBridge-etuliitteen, ei Traffic Inspector -etuliitteen alla).

### 3.2 Pyyntöluettelo (vasen paneeli)

- **Virtualisoitu** (`useVirtualList` + `ResizeObserver`): käsittelee 1 000 kohdetta jumiutumatta
- **Automaattinen vieritys**, jonka voi keskeyttää tarkastelun ajaksi
- **Värikoodattu tila**: vihreä (2xx), keltainen (3xx), punainen (4xx/5xx), harmaa (kesken)
- **Agentin emoji**: 🔵 Antigravity, 🟢 Copilot, 🟠 Kiro, 🟣 Codex, 🔷 Cursor, 🟤 Zed, 🟡 Claude Code, ⚫ Open Code, 🌐 mukautettu isäntä
- **Kontekstin väripalkki**: 1 px:n vasen reunus, jonka väri määräytyy `contextKey`-arvon perusteella (järjestelmäkehotteen SHA-256) — ryhmittelee toisiinsa liittyvät keskustelut visuaalisesti
- **Rungon laiska lataus**: vain valitun pyynnön runko materialisoidaan tietoruudun välilehdille (näin vältetään 1 000 × 1 Mt:n runkojen renderöinti)

| **Reaaliaikainen** suodatin | Näytä vain keskeneräiset (avoimet) pyynnöt — `liveOnly`-valitsin (katso §4.6) |

### 3.5 Paneelien koon muuttaminen

- Luettelon ja tietoruudun erottaa vetokahva
- Luettelon leveys: vähintään 280 px, enintään 720 px; tallennetaan `localStorage`-tallennustilaan (`inspector.listWidth`)
- Voidaan kutistaa 48 px:n palkiksi (vain kuvakkeet); laajenna napsauttamalla palkin riviä

## §4 LLM-tietoiset ominaisuudet

### 4.1 Tyypin tunnistin (`src/mitm/inspector/kindDetector.ts`)

Luokittelee jokaisen pyynnön arvoksi `"llm"`, `"app"` tai `"unknown"` käyttämällä neljää signaalia:

1. **Isäntärekisteri** — noin 18 tunnettua LLM-rajapinnan isäntänimeä (OpenAI, Anthropic, Gemini, Groq, Mistral, Together, Fireworks, Cohere, Perplexity, Hugging Face, OpenRouter, xAI, Moonshot jne.)
2. **Polkumallit** — `/v1/chat/completions`, `/v1/messages`, `/generateContent`, `/v1/responses` jne.
3. **Rungon rakenne** — tunnistaa kentät `messages[]` (OpenAI/Claude), `contents[]` (Gemini), `prompt` ja `input`
4. **User-agent-vihjeet** — UA-merkkijonossa esiintyvät `codex`, `claude`, `gemini`, `antigravity`, `kiro`, `copilot` ja `cursor`

Tilan 2 kautta lisätyt mukautetut isännät perivät `kind`-arvonsa lomakkeen syötteestä (oletusarvo on `"custom"`).

### 4.2 SSE-yhdistin (`src/mitm/inspector/sseMerger.ts`)

**Itsenäinen clean-room-toteutus.** Tapahtumien jäsennys noudattaa
[WHATWG:n palvelimen lähettämien tapahtumien algoritmia](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream),
kun taas rekonstruointi noudattaa julkisia [OpenAI:n](https://platform.openai.com/docs/api-reference/chat/create),
[Anthropicin](https://platform.claude.com/docs/en/build-with-claude/streaming) ja
[Geminin](https://ai.google.dev/api/generate-content#method:-models.streamgeneratecontent)
suoratoistoskeemoja.

Rekonstruoi lopullisen avustajaviestin raaoista SSE-deltatapahtumista:

- **Anthropic**: kokoaa `content_block_delta`-tapahtumat indeksin mukaan; käsittelee tyypit `text_delta`, `input_json_delta` (työkalukutsut) ja `thinking_delta`
- **OpenAI**: kokoaa Chat Completions -valinnat ja työkalukutsut sekä Responses API -tulostekohteet
  indeksin mukaan
- **Gemini**: kokoaa osat `candidates[i].content.parts`
- **Tuntematon**: palauttaa raa'at tapahtumat sellaisinaan

Response-välilehdellä näkyy vaihtopainike: **"Raakatapahtumat ↔ Yhdistetty"**.

### 4.3 Keskustelun normalisoija (`src/mitm/inspector/conversationNormalizer.ts`)

**Itsenäinen clean-room-toteutus.** Normalisointi määritellään paikallisilla black-box-sopimuksilla
sekä julkisilla OpenAI-, Anthropic- ja Gemini-viestiskeemoilla; mitään ulkopuolisen
toteutuksen lähdekoodia ei käytetä.

Muuntaa OpenAI-, Anthropic- ja Gemini-viestimuodot yhdeksi `NormalizedConversation`-rakenteeksi ennen hahmontamista:

```ts
interface NormalizedConversation {
  request: NormalizedTurn[]; // pyynnön rungon viestit / sisällöt / kehote
  response: NormalizedTurn[]; // avustajan vastaus (yhdistetty sseMerger-toiminnolla)
  contextKey: string | null; // järjestelmäkehotteen SHA-256-sormenjälki
}
```

Lohkotyypit: `text`, `tool_use`, `tool_result`. Conversation-välilehti käyttää tätä rakennetta palveluntarjoajasta riippumatta.

### 4.4 Kontekstiavaimen väritys (`src/mitm/inspector/contextKey.ts`)

- Laskee järjestelmäkehotteen `SHA-256`-tiivisteen (ensimmäinen `role:system`-viesti, `system`-kenttä tai Geminin `systemInstruction`)
- Palauttaa 12 merkin heksadesimaalietuliitteen (`"a3f9c2..."`)
- Käyttöliittymä yhdistää avaimen deterministiseen HSL-väriin vasemman reunan palkkia varten
- **Suodatin "sama konteksti"**: `ctx #a3f` -tunnisteen napsauttaminen lisää suodattimen, joka näyttää vain samaa sormenjälkeä käyttävät pyynnöt

Tämän avulla samassa agentti-istunnossa suoritettavat erilaiset "persoonat" tai tehtävät on helppo erottaa visuaalisesti toisistaan.

### 4.5 LLM-metatietojen poiminta

LLM-pyyntöjen LLM Details -välilehti poimii seuraavat tiedot:

```ts
interface LlmMetadata {
  provider: string | null; // "openai" | "anthropic" | "gemini" | ...
  apiKind: string | null; // "chat.completions" | "messages" | "embeddings" | ...
  model: string | null; // pyynnön rungosta tai vastauksesta
  messages: number; // vuorojen määrä
  tokensIn: number | null; // usage.prompt_tokens / usage.input_tokens
  tokensOut: number | null; // usage.completion_tokens / usage.output_tokens
  streamed: boolean; // true, jos vastaus on SSE
  mappedTo: string | null; // x-omniroute-mapped-otsake
  costEstimateUsd: number | null; // OmniRoute-hinnoitteluun perustuva arvioitu kustannus
}
```

### 4.6 Käynnissä olevien pyyntöjen reaaliaikainen suodatin

Pyynnön `status`-kentän tyyppi on `number | "in-flight" | "error"` — kohde
lisätään arvolla `"in-flight"` heti pyynnön alkaessa, ja se **päivitetään paikallaan**
vastauksen (tai virheen) saapuessa. Työkalupalkin **"Live"**-vaihtopainike
(`liveOnly`, i18n-avain `trafficInspector.liveOnly`) rajaa luettelon kohteisiin,
joiden `status === "in-flight"`, joten avoimia yhteyksiä voi seurata reaaliajassa.

Suodatin on puhdas asiakaspuolen predikaatti tiedostossa
`src/lib/inspector/matchesTrafficFilter.ts`:

```ts
if (f.liveOnly && req.status !== "in-flight") return false;
```

Vaihtopainikkeen tila sijaitsee `useTrafficFilters`-koukussa (tarkastelunäkymän koukut), ja
se yhdistyy muihin suodattimiin (profiili, isäntä, agentti, lähde, tila, konteksti).

### 4.7 Prosessin kohdistaminen (Linux)

Linuxissa jokainen siepattu pyyntö voidaan kohdistaa sen **lähettäneeseen paikalliseen
prosessiin**. `InterceptedRequest`-rakenteeseen lisätään kaksi valinnaista kenttää:

```ts
pid?: number;          // lähettäneen prosessin tunnus (vain Linux)
processName?: string;  // lähettäneen prosessin nimi (vain Linux)
```

`src/mitm/inspector/processAttribution.ts` yhdistää yhteyden _asiakkaan_
tilapäisen portin PID-tunnukseen ja nimeen seuraavasti:

1. Lukee tiedostot `/proc/net/tcp` ja `/proc/net/tcp6` löytääkseen portin
   pistokkeen inode-tunnuksen (`parseProcNetTcpForInode`, puhdas testisyötteillä testattava jäsennin).
2. Etsii hakemistoista `/proc/<pid>/fd/` symbolista linkkiä kohteeseen `socket:[<inode>]`.
3. Lukee prosessin nimen tiedostosta `/proc/<pid>/comm`.

Yhden sekunnin TTL-välimuisti rajoittaa procfs-tarkistuksen kustannuksia kuormituksen aikana. Kohdistaminen on
**best effort** -periaatteella toimiva — kaikki virheet tuottavat arvon `null` eivätkä koskaan estä sieppausta.
macOSissa/Windowsissa funktio palauttaa arvon `null` (tynkä; `lsof`-/`GetExtendedTcpTable`-tuki
lisätään myöhemmin).

## §5 Istunnot

### 5.1 Istunnon tallentaminen

1. Napsauta työkalupalkissa **"● Tallenna istunto"** → anna nimi (valinnainen)
2. Reaaliaikainen seuranta jatkuu normaalisti; punainen sykkivä ilmaisin näyttää `◉ REC · <name> · 00:42 · 23 pyyntöä`
3. Napsauta **"⏹ Pysäytä"** → istunnon tilannevedos tallennetaan tauluihin `inspector_sessions` + `inspector_session_requests`

### 5.2 Tallennetun istunnon tarkasteleminen

Työkalupalkin **Istunnot**-pudotusvalikossa näkyvät tallennetut istunnot. Kun istunto valitaan:

- Palkissa näkyy: `Tarkastellaan tallennettua istuntoa "<name>" — [Takaisin reaaliaikaiseen näkymään]`
- Tilastot-välilehti ja sen Recharts-koosteet tulevat käyttöön

### 5.3 Vientimuodot

Jokainen istunto voidaan viedä seuraavissa muodoissa:

| Muoto                      | Käyttötarkoitus                                                                              |

| **HAR** (HTTP Archive 1.2) | Yhteensopiva Chrome DevToolsin, Charlesin ja Fiddlerin kanssa — tuo offline-analyysiä varten |

## §6 Tietoturva

Traffic Inspector näyttää **kaiken siepatun HTTPS-liikenteen**, mukaan lukien valtuutusotsakkeet ja pyyntöjen rungot. Käytössä ovat seuraavat hallintakeinot:

| Hallintakeino                    | Tiedot                                                                                                                                                                                                    |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LOCAL_ONLY**                   | Kaikki reitit ja WebSocket-päätepiste ovat käytettävissä vain loopback-osoitteesta (pakotetaan tiedostossa `routeGuard.ts` ennen todennusta)                                                              |
| **Salaisuuksien peittäminen**    | Lineaarinen `maskSecret()`-skanneri peittää RFC 6750 Bearer -tunnistetiedot, palveluntarjoajan etuliitteellä varustetut avaimet ja pitkät läpinäkymättömät tunnisteet ennen `TrafficBuffer.push()`-kutsua |
| **Rungon kokorajoitus**          | Rungot, joiden koko on yli `INSPECTOR_MAX_BODY_KB` (oletusarvo 1024 KB), katkaistaan ja niihin lisätään ilmoitus `"(katkaistu suorituskyvyn vuoksi)"`                                                     |
| **Otsakkeiden puhdistus**        | Nimet muunnetaan pieniksi kirjaimiksi; kehystys-, hyppykohtaiset ja välityspalvelimen todennusotsakkeet poistetaan; evästeet peitetään kokonaan; tunnistetietoarvot välitetään `maskSecret()`-funktiolle  |
| **CSP**                          | Traffic Inspector -sivuilla käytetään tiukkaa Content Security Policy -käytäntöä, joka estää injektoitujen vastausrunkojen kautta tehtävät XSS-hyökkäykset                                                |
| **Ei oletusarvoista pysyvyyttä** | `TrafficBuffer` säilytetään muistissa ja menetetään palvelimen uudelleenkäynnistyksen yhteydessä. Istunnot tallennetaan pysyvästi vain, kun tallennus käynnistetään erikseen                              |

### Sovellettavat ehdottomat säännöt

| Sääntö                            | Soveltaminen                                                                                         |
| --------------------------------- | ---------------------------------------------------------------------------------------------------- |
| **#12** `sanitizeErrorMessage`    | Kaikki Traffic Inspector -reittien HTTP-virhevastaukset puhdistetaan                                 |
| **#15 + #17** `isLocalOnlyPath()` | `/api/tools/traffic-inspector/` on LOCAL_ONLY + SPAWN_CAPABLE (järjestelmän välityspalvelinkomennot) |

### Tunnetut rajoitukset

- **Järjestelmänlaajuinen välityspalvelintila** vaikuttaa kaikkiin koneen sovelluksiin, mukaan lukien VPN-asiakasohjelmat ja kertakirjautuminen. Käytä sitä aina automaattisen käytöstäpoistoajastimen kanssa. Älä käytä sitä jaetuilla koneilla.
- **CONNECT-tunnelin HTTPS**: Tila 3 (HTTP_PROXY) tallentaa HTTPS-kohteista vain tunnelin metatiedot, ellei TLS-sieppausta ole otettu käyttöön. Tämä on tarkoituksellista — läpinäkyvä tallennus ilman, että kyseiset sovellukset luottavat AgentBridge-varmenteeseen, rikkoisi niiden TLS-varmennuksen.
- **Kovakoodatut merkkijonot joissakin komponenteissa**: Joissakin käyttöliittymäkomponenteissa (F7/F8) on pieni määrä kovakoodattuja merkkijonoja, joita i18n-avaimet eivät vielä kata. Ne on dokumentoitu tunnetuksi rajoitukseksi i18n-puuteraportissa, ja ne siirretään myöhemmällä päivityskierroksella. Kyseiset merkkijonot ovat käyttöliittymän koristeellisia tunnisteita, joiden kääntäminen ei ole toiminnallisen käytön kannalta tarpeen.

## §7 Vianmääritys

### WebSocket-yhteyden katkeaminen

Jos reaaliaikainen seuranta näyttää tekstin "Yhteys katkaistu":

1. Tarkista, että palvelin on edelleen käynnissä: `GET /api/tools/traffic-inspector/capture-modes`
2. Lataa sivu uudelleen — WebSocket muodostaa yhteyden uudelleen ja vastaanottaa uuden tilannevedoksen
3. Jos palvelin käynnistettiin uudelleen, muistissa oleva puskuri tyhjennettiin — vanhat merkinnät ovat poissa, ellei istuntoa tallennettu

### Portin 8080 ristiriita

Jos HTTP_PROXY-tilan käynnistäminen epäonnistuu:

```bash
lsof -i :8080    # etsi prosessi
```

Vaihda portti:

```bash
# .env
INSPECTOR_HTTP_PROXY_PORT=8888
```

### Järjestelmän välityspalvelinasetuksia ei palautettu

Jos OmniRoute kaatuu järjestelmänlaajuisen välityspalvelintilan ollessa käytössä:

**macOS:**

```bash
networksetup -setwebproxystate Wi-Fi off
networksetup -setsecurewebproxystate Wi-Fi off
```

**Linux (GNOME):**

```bash
gsettings set org.gnome.system.proxy mode 'none'
```

**Windows:**

```cmd
netsh winhttp reset proxy
```

Hallintapaneeli tarjoaa seuraavalla latauskerralla myös toiminnon "Palauta järjestelmän välityspalvelinasetukset", jos se havaitsee tietokannan tilan osoittavan välityspalvelimen olleen aktiivinen.

### Puskuri täynnä

Kun puskuri saavuttaa `INSPECTOR_BUFFER_SIZE`-koon (oletus 1000), uudet merkinnät syrjäyttävät vanhimmat. Jos tärkeitä pyyntöjä menetetään:

- Suurenna `INSPECTOR_BUFFER_SIZE`-arvoa (esim. 5000) — tämä parantaa säilyvyyttä muistin kulutuksen kustannuksella
- Tallenna istunto, jotta olennainen aikaväli säilytetään tietokannassa
