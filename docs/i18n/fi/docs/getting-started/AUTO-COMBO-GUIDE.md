> **TL;DR**: Aseta malliksi `auto`, niin OmniRoute valitsee automaattisesti parhaan tekoälypalveluntarjoajan jokaista pyyntöä varten. Määrityksiä ei tarvita.

---

## Mitä se tekee

Sen sijaan, että valitsisit tietyn tekoälymallin (kuten GPT-4o:n tai Clauden), voit antaa OmniRouten **valita automaattisesti parhaan mallin** jokaista pyyntöä varten. Se ottaa huomioon seuraavat tekijät:

- **Toimintakunto** — Toimiiko palveluntarjoaja juuri nyt?
- **Nopeus** — Kuinka nopea se on?
- **Hinta** — Kuinka paljon se maksaa?
- **Laatu** — Soveltuuko se hyvin tämäntyyppiseen tehtävään?
- **Kapasiteetti** — Onko sillä kiintiötä jäljellä?

OmniRoute pisteyttää kaikki yhdistetyt palveluntarjoajasi ja valitsee niistä parhaan. Jos se epäonnistuu, OmniRoute kokeilee automaattisesti seuraavaa.

---

## Pika-aloitus

**Vaihe 1**: Aseta malliksi `auto` IDE:ssäsi tai CLI:ssäsi:

```
model: "auto"
```

**Vaihe 2**: Siinä kaikki! OmniRoute hoitaa loput.

**Vaihe 3** (valinnainen): Käytä tiettyihin tehtäviin sopivaa varianttia:

```
model: "auto/coding"    # Paras koodaukseen
model: "auto/fast"      # Nopein vastaus
model: "auto/cheap"     # Edullisin vaihtoehto
```

## Mitä "auto"-vaihtoehtoa kannattaa käyttää?

| Jos haluat...                | Käytä tätä     | Sopii parhaiten                       | Toimintaperiaate                                           |
| ---------------------------- | -------------- | ------------------------------------- | ---------------------------------------------------------- |
| **Parhaan kokonaisuuden**    | `auto`         | Yleiset kysymykset, keskustelu        | Tasapainottaa nopeuden, hinnan ja laadun                   |
| **Parhaan koodin**           | `auto/coding`  | Koodin kirjoittaminen, virheenkorjaus | Valitsee koodaustehtävissä hyvät mallit                    |
| **Nopeimman vastauksen**     | `auto/fast`    | Nopeat vastaukset, pieni viive        | Asettaa nopeuden kaiken muun edelle                        |
| **Edullisimman vaihtoehdon** | `auto/cheap`   | Rahan säästäminen                     | Valitsee edullisimman palveluntarjoajan                    |
| **Älykkäimmän mallin**       | `auto/smart`   | Monimutkaiset tehtävät                | Laatu etusijalla + kokeilee uusia malleja                  |
| **Parhaan saatavuuden**      | `auto/offline` | Kun palveluntarjoajat ovat ruuhkaisia | Valitsee palveluntarjoajat, joilla on eniten kapasiteettia |

### Esimerkkejä

```bash
# Yleinen keskustelu — tasapainotettu
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'

# Koodin generointi — laatu etusijalla
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/coding","messages":[{"role":"user","content":"Write a Python function"}]}'

# Nopea vastaus — nopeus etusijalla
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/fast","messages":[{"role":"user","content":"What is 2+2?"}]}'
```

## Näin se toimii (yksinkertaistettu versio)

Kun lähetät pyynnön, jossa on `model: "auto"`, OmniRoute:

1. **Tarkastelee kaikkia yhdistettyjä palveluntarjoajiasi** — Kaikkia lisäämiäsi palveluntarjoajia (OpenAI, Anthropic, Google jne.)
2. **Pisteyttää jokaisen** huomioiden muun muassa seuraavat asiat:
   - Toimiiko se? (toimintakunto)
   - Onko sillä kapasiteettia? (kiintiö)
   - Kuinka paljon se maksaa? (hinta)
   - Kuinka nopea se on? (nopeus)
   - Soveltuuko se hyvin tähän tehtävään? (laatu)
3. **Valitsee parhaan** — Eniten pisteitä saanut palveluntarjoaja käsittelee pyyntösi
4. **Palautuu automaattisesti häiriöistä** — Jos se epäonnistuu, OmniRoute kokeilee automaattisesti seuraavaa

### Pisteytysjärjestelmä

Jokainen palveluntarjoaja saa pistemäärän väliltä 0–1. Mitä korkeampi pistemäärä, sitä paremmin palveluntarjoaja sopii tehtävään.

| Tekijä          | Painoarvo | Merkitys                                                    |
| --------------- | --------- | ----------------------------------------------------------- |
| Toimintakunto   | 20%       | Toimiiko palveluntarjoaja? (circuit breaker -tila)          |
| Kiintiö         | 15%       | Onko sillä kapasiteettia jäljellä?                          |
| Hinta           | 15%       | Kuinka kallis se on? (edullisempi = korkeampi pistemäärä)   |
| Nopeus          | 12%       | Kuinka nopea se on? (pienempi viive = korkeampi pistemäärä) |
| Tehtäväsopivuus | 8%        | Soveltuuko se hyvin tämäntyyppiseen tehtävään?              |
| Vakaus          | 5%        | Onko se johdonmukainen? (matala virheprosentti)             |
| Taso            | 5%        | Tilitaso (Ultra > Pro > Free)                               |
| Muut            | 20%       | Kontekstisidonnaisuus, yhteystiheys jne.                    |

### Miten variantit muuttavat pisteytystä

Jokainen variantti käyttää eri painoarvoja:

| Variantti      | Painottaa              | Tärkeimmät painoarvot           |
| -------------- | ---------------------- | ------------------------------- |
| `auto`         | Tasapaino              | health=20%, quota=15%, cost=15% |
| `auto/coding`  | Laatu                  | taskFit=37%, stability=15%      |
| `auto/fast`    | Nopeus                 | latency=32%, health=28%         |
| `auto/cheap`   | Hinta                  | cost=37%                        |
| `auto/smart`   | Laatu + uusien kokeilu | taskFit=37%, exploration=10%    |
| `auto/offline` | Kapasiteetti           | quota=37%, health=28%           |

## Miten se käsittelee häiriöitä

OmniRoutessa on **kolme suojaustasoa**:

### 1. Automaattinen varajärjestely

Jos paras palveluntarjoaja epäonnistuu, OmniRoute yrittää automaattisesti seuraavaa. Sinun ei tarvitse tehdä mitään.

### 2. Itsekorjautuvuus

Jos palveluntarjoajan toiminta epäonnistuu jatkuvasti:

- **Pistemäärä < 0.2** → Suljetaan pois 5 minuutiksi
- **Katkaisija avoinna** → Suljetaan pois automaattisesti
- **Yli 50 % palveluntarjoajista poissa käytöstä** → Häiriötila (ei kokeilua)

### 3. Varajärjestely hätätilanteessa

Jos kaikki palveluntarjoajat epäonnistuvat, OmniRoute reitittää pyynnöt viimeisenä keinona vakaille ilmaisille palveluntarjoajille (kuten Kiro tai Qoder).

---

## Useiden tilien tuki

Jos sinulla on useita tilejä samalle palveluntarjoajalle (esimerkiksi kaksi OpenAI-avainta), OmniRoute käsittelee jokaista niistä **erillisenä ehdokkaana**. Tämä tarkoittaa seuraavaa:

- Tilillä A on kiintiötä jäljellä → käytä sitä
- Tiliin B kohdistuu nopeusrajoitus → ohita se
- Tili C on edullisempi → suosi sitä

Jokainen tili pisteytetään erikseen sen oman toimintakunnon, kiintiön ja nopeuden perusteella.

---

## Bandit-kokeilu

OmniRoute **kokeilee** ajoittain uusia palveluntarjoajia löytääkseen parempia vaihtoehtoja:

- **Oletus**: 5 % pyynnöistä lähetetään satunnaisille palveluntarjoajille
- **Auto/smart**: 10 %:n kokeiluaste
- **Poistetaan käytöstä**, kun yli 50 % palveluntarjoajista on epäkunnossa

Tämä auttaa OmniRoutea oppimaan, mitkä palveluntarjoajat toimivat parhaiten käyttötavoillasi.

## Yleisiä kysymyksiä

### "Valitseeko se aina kalleimman mallin?"

**Ei.** Kustannuksen osuus pistemäärästä on oletuksena vain 15 %. Edullinen, nopea ja toimintakuntoinen palveluntarjoaja voi päihittää kalliin vaihtoehdon. Käytä `auto/cheap`-asetusta, jos haluat painottaa kustannuksia vielä enemmän.

### "Mitä tapahtuu, jos palveluntarjoaja lakkaa toimimasta?"

OmniRoute ohittaa sen automaattisesti ja yrittää seuraavaa. Jos palveluntarjoajan toiminta epäonnistuu jatkuvasti, se suljetaan tilapäisesti pois (5–30 minuutiksi). Sinun ei tarvitse tehdä mitään.

### "Voinko nähdä, mitä palveluntarjoajaa käytettiin?"

Tarkista vastauksen otsakkeet — OmniRoute ilmoittaa jokaisessa vastauksessa käytetyn palveluntarjoajan ja mallin.

### "Oppiiko se käytöstäni?"

Kyllä! Pisteytysjärjestelmä käyttää historiatietoja (viiveitä, virheprosentteja ja onnistumisprosentteja) tehdäkseen ajan myötä parempia päätöksiä.

### "Mitä eroa on asetuksilla `auto` ja `auto/smart`?"

- `auto` — Tasapainotettu, 5 % kokeilua
- `auto/smart` — Laatu etusijalla (samat painotukset kuin asetuksessa `auto/coding`), 10 % kokeilua

Käytä `auto/smart`-asetusta, kun haluat parhaan laadun ja satunnainen kokeilu sopii sinulle.

### "Voinko pakottaa tietyn palveluntarjoajan käytön?"

Kyllä! Käytä `auto`-strategian sijaan yhdistelmää, jossa on `priority`-strategia, ja lähetä sitten yhdistelmän **täsmällinen nimi** `model`-kentässä (esim. `model: "my-combo"` — ei `auto`). Katso lisätietoja [teknisestä viitteestä](../routing/AUTO-COMBO.md).

### "Miten tämä eroaa vuorottelusta?"

Vuorottelu käy palveluntarjoajat läpi järjestyksessä. Auto-combo **pisteyttää jokaisen palveluntarjoajan** ja valitsee parhaan. Se on älykkäämpi — se huomioi toimintakunnon, nopeuden, kustannukset ja laadun.
