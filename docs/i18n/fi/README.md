## 💰 ~1,47 mrd ilmaista tokenia / kuukausi

</div>

> Ilmaistasojen kokoaminen käsin on työlästä — kymmeniä SDK:ita, kymmeniä nopeusrajoituksia eikä mitään käsitystä siitä, kuinka paljon kapasiteettia sinulla todellisuudessa on. OmniRoute luetteloi **452 ilmaistason merkintää 34 toistuvan resurssipoolin avaimessa** ja laskee tokenien otsikkoluvun **16 poolista, joille on julkaistu positiivinen kuukausibudjetti, sekä viidestä mallikohtaisesta Groq-rajasta**, poistaen jaettujen poolien kaksoislaskennan. Kiintiöt, jotka avautuvat vasta alueellisen henkilöllisyyden tarkistuksen jälkeen (tällä hetkellä ModelScope), näytetään erikseen: +~6 milj. alueellisen henkilöllisyyden vahvistamisen takana, eikä niitä koskaan lasketa mukaan otsikkolukuun. Tulos pysyy näkyvissä hallintapaneelissa (`/dashboard/free-tiers`).

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="OmniRouten ilmaistasobudjetin kortti: jatkuvasti ~1,47 mrd ilmaista tokenia kuukaudessa ja rekisteröitymiskrediittien ansiosta jopa ~2,07 mrd ensimmäisen kuukauden aikana, yhdestä päätepisteestä saatavilla olevista 34 dokumentoidusta toistuvan resurssipoolin avaimesta, jotka kattavat 452 luetteloitua ilmaistason merkintää. Rehellinen, poolien kaksoislaskennan poistava laskenta — jokainen jaettu pooli lasketaan vain kerran, mukaan lukien 16 toistuvaa poolia, joille on julkaistu positiivinen kuukausittainen token-budjetti, sekä viisi mallikohtaista Groq-rajaa; 13 palveluntarjoajaa on merkitty käyttöehtoriskien luettelossa vältettäviksi, joten päätös on sinun. Budjettipalkki sisältää Mistral 1 mrd, Nara 210 milj., LLM7 150 milj., Groq 30 milj. (viisi mallikohtaista rajaa) sekä pienempiä pooleja. Lisäksi ensimmäisen kuukauden rekisteröitymiskrediitit ja pysyvästi ilmaiset palveluntarjoajat, joilla ei ole token-rajaa, esitetään erikseen, jotta ne eivät koskaan kasvata otsikkolukua keinotekoisesti. Reaaliaikainen käytetty ja jäljellä oleva määrä osoitteessa /dashboard/free-tiers."/>

> Animoitu yhteenveto reaaliaikaisesta `/dashboard/free-tiers`-sivusta. Täydellinen menetelmäkuvaus (poolien kaksoislaskennan poisto, krediittitasot, palveluntarjoajien ehdot): **[docs/reference/FREE_TIERS.md](docs/reference/FREE_TIERS.md)**.
>
> <sub>Nämä luvut tarkastetaan uudelleen kahden viikon välein reaaliaikaista luetteloa vasten, ja ne **voivat muuttua kumpaankin suuntaan** — jos palveluntarjoaja lopettaa ilmaistason, luku pienenee; uuden ilmaistason myötä se kasvaa. Julkaisemme aina sen, mitä luettelo todellisuudessa laskee, emmekä koskaan ylöspäin pyöristettyä parasta mahdollista arviota.</sub>

<img src="./docs/diagrams/works-zero-config.svg" width="100%" alt="Toimii heti asennuksen jälkeen — ilman määrityksiä. Kolme vaihetta: 1. Ohjaa työkalusi osoitteeseen http://localhost:20128/v1 — mikä tahansa OpenAI-yhteensopiva työkalu (Claude Code, Cursor, Cline). 3. # Tuore asennus, ei tunnistetietoja — `auto` toimii jo:
```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

## 📡 OmniRoute Radar

Maksuttoman tason tärkein arvio on edelleen **~1.47B tokenia/kuukausi** yllä dokumentoidusta,
resurssipoolien osalta deduplikoidusta luettelosta. Palveluntarjoajien väliaikaiset rekisteröitymishyvitykset voivat lisäksi nostaa ensimmäisen
kuukauden määrän tasolle **~2.07B**. Radar on valinnainen, allekirjoitettu luettelokerros käyttäjille, jotka haluavat ajantasaisempia
tietoja maksuttomien mallien saatavuudesta OmniRoute-julkaisujen välillä. Yhteisöluettelo ja kaikki nykyiset maksuttomat
ominaisuudet säilyvät maksuttomina.

Tukijat voivat saada reaaliaikaisen luettelon ja pääsyn palveluntarjoajien lisämahdollisuuksiin. Sen erillinen,
muuttuva enimmäismäärä on **enintään noin 3B tokenia/kuukausi** palveluntarjoajien saatavuuden mukaan.
Tämä enimmäismäärä ei ole takuu: palveluntarjoajat voivat muuttaa kiintiöitä, kelpoisuusehtoja, malleja tai alueita
milloin tahansa.

Radar on valinnainen ja käyttää vain GET-pyyntöjä. OmniRoute-asiakasohjelma ei lähetä kehotteita, liikennettä, palveluntarjoajien
määrityksiä, käyttötelemetriaa eikä paikallista ilmoitusten ohitustilaa. Lisätietoja kelpoisuudesta ja
nykyisestä luettelosta on osoitteessa **[radar.omniroute.online/planos](https://radar.omniroute.online/planos)**.

## 🔌 Täysi komentorivityökalu + A2A & MCP

</div>

> Palvelimen lisäksi OmniRoute on **täysiverinen komentoriviohjaamo**, jossa on **yli 80 komentoa**, sekä avoimet agenttiprotokollat, joiden avulla tekoälyagentti voi käyttää sitä **itsenäisesti**.

### ⌨️ Oikea komentorivityökalu (ei pelkkä `start`)

```bash
omniroute               # käynnistä yhdyskäytävä + hallintapaneeli (portti 20128)
omniroute chat          # interaktiivinen TUI-keskusteluasiakas (vinoviivakomennot: /model /combo /skill /memory)
omniroute setup         # ohjattu ensimmäisen käyttökerran määritys
omniroute doctor        # diagnosoi palveluntarjoajat, portit ja natiiviriippuvuudet
```

### 🛰️ Etätila — suorita komentorivityökalu täällä ja OmniRoute VPS-palvelimella

Onko OmniRoute palvelimella? Ohjaa sitä kannettavaltasi **samalla komentorivityökalulla**. Kirjaudu kerran
rajatulla käyttöoikeustunnuksella, minkä jälkeen jokainen komento kohdistuu etäpalvelimeen.

```bash
omniroute connect 192.168.0.15            # salasana → rajattu tunnus, tallennetaan kontekstina
omniroute models list                     # ← suoritetaan ETÄPALVELIMELLA
omniroute configure codex                 # ← valitsee etämallin ja kirjoittaa paikallisen Codex-profiilin
omniroute tokens create --name ci --scope read   # luo käyttöoikeuksiltaan rajatumpia tunnuksia muille koneille
omniroute contexts use default            # ← vaihda takaisin paikalliseen palvelimeen
```

Tunnusten käyttöalueet ovat `read` / `write` / `admin`; prosesseja käynnistävät reitit pysyvät vain loopback-rajapinnan käytettävissä.

### 📖 Näin se toimii — putki, arkkitehtuuri ja säästöjen laskenta

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute-pakkausputki: havainnollinen 10 000 tokenin asiakaspyyntö kulkee 12 yhdisteltävän moottorin läpi — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra ja OmniGlyph — ja voi dokumentoidussa pinotussa esimerkissä saavuttaa palveluntarjoajan noin 1 080 tokenin kokoisena. Rakenteinen sisältö suojataan säilytyssuojauksilla ja vaihekohtaisilla eheysporteilla; erikseen käyttöön otetut häviölliset tai kokeelliset tilat voivat muuntaa soveltuvaa sisältöä."/>

Pinottu oletusyhdistelmä suorittaa vaiheet `RTK → Caveman`. Kun molemmat käsittelevät samaa työkalu-/kontekstihyötykuormaa, säästöt kertautuvat:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

Koodilohkot, URL-osoitteet, JSON ja rakenteinen data ovat säilytysmoottorin **aina suojaamia**.

> **Miksi käyttää paljon tokeneita, kun vähemmätkin riittävät?** Jokainen pyyntö kulkee OmniRouten pakkausputken läpi **läpinäkyvästi** — asiakasohjelmaan ei tarvita muutoksia. Se on nyt **12 yhdisteltävän moottorin pino**, joka suoritetaan järjestyksessä ja jota voidaan yhdistellä reititysyhdistelmäkohtaisesti — pohjautuen projekteista [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K+), [LLMLingua-2](https://github.com/microsoft/LLMLingua) ja [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR) saatuihin ideoihin.

### 🎚️ Moottoreita pidemmälle — tulostyylit, mukautuva säädin ja pyyntökohtainen hallinta

Yllä olevat 12 moottoria pienentävät **syötettä**. Kolme muuta kerrosta määrittävät, **miten**, **milloin** ja mitä tulee **ulos**:

- **🪄 Tulostyylit** _(tulostusakselin ohjaus)_ — lisää deterministisiä, välimuistiturvallisia ohjeita vastauksen muotoiluun; tyylejä voi yhdistellä, ja jokaisella on `lite`- / `full`- / `ultra`-intensiteetti. Tyylin lisääminen vaatii vain yhden rivin rekisterimerkinnän:
  - **Tiivis teksti** — poista täytesanat / artikkelit / varaukset; säilytä tekninen sisältö täsmällisenä.
  - **Vähemmän koodia** — ”laiska seniorikehittäjä” -YAGNI: pienin toimiva muutos, ei pyytämättömiä runkorakenteita.
  - **Ponytail (laiska seniorikehittäjä)** — etene YAGNI-portaita, korjaa juurisyy, tee pienin toimiva diffi.
  - **Minulla on ADHD (toiminta ensin)** — seuraava toimenpide ensin, numeroidut vaiheet, yksi konkreettinen seuraava askel, ei johdantoa.
  - **Tiivis CJK (文言)** — klassisen kiinan äärimmäisen tiivis tyyli (käytössä vain `zh`-alueasetuksella).
- **🎯 Mukautuva kontekstibudjetti** _(säädin)_ — yhden päälle/pois-tokenrajan sijaan halvimpia ja vähiten tietoa hukkaavia moottoreita otetaan käyttöön vain niin pitkälle kuin on tarpeen, jotta sisältö **mahtuu mallin konteksti-ikkunaan**. Käytäntö: `reserve-output` (oletus, mallitietoinen) · `percentage` · `absolute`. Tila: `floor` (takaa mahtumisen) · `replace-autotrigger` (nimenomainen valintasi on etusijalla) · `off` (vanha raja-arvo).
- **🎛️ Missä pakkauksesta päätetään** _(etusijajärjestys, korkea → matala)_ — pyyntökohtainen `x-omniroute-compression`-otsake › reititysyhdistelmän ohitus › aktiivinen nimetty profiili › mukautuva / automaattinen laukaisu › paneelin oletus › pois käytöstä. Käytetty suunnitelma palautetaan `X-OmniRoute-Compression: <mode>; source=<source>`-vastausotsakkeessa.

Käytä automaattista laukaisua tokenrajan perusteella, ota mukautuva säädin käyttöön, kiinnitä nimetty profiili, määritä kertaluonteinen pyyntökohtainen asetus tai liitä käsittelyputki reititysyhdistelmään — valitse työkuormaan sopivin vaihtoehto. Valinnainen offline-**arviointikehys** (`npm run eval:compression`) pisteyttää tarkkuuden suhteessa säästöihin kiinnitetyllä aineistolla ennen muutoksen käyttöönottoa.

# ⚡ Pika-aloitus

</div>

**1) Asenna ja suorita**

```bash
npm install -g omniroute
omniroute
```

> 💡 Näetkö `npm warn ERESOLVE`-ilmoituksen tai vertaisriippuvuusvaroituksia? [Ne ovat harmittomia](docs/guides/TROUBLESHOOTING.md#npm-install-warnings-eresolve--peer--deprecated).

Hallintapaneeli osoitteessa `http://localhost:20128` · API osoitteessa `http://localhost:20128/v1`.

**2) Yhdistä ILMAINEN palveluntarjoaja (ei rekisteröitymistä)**

Hallintapaneeli → **Palveluntarjoajat** → yhdistä **Kiro AI** (ilmainen Claude, ~50 krediittiä kuukaudessa tiliä kohden) tai **OpenCode Free** (ei todennusta) → valmis.

**3) Määritä koodaustyökalusi**

```txt
Perus-URL:   http://localhost:20128/v1
API-avain:   [kopioi kohdasta Hallintapaneeli → Päätepisteet]
Malli:       auto            (älykäs reititys ilman määrityksiä — tai mikä tahansa palveluntarjoaja/malli)
```

**4) Varmista toiminta**

```bash
curl http://localhost:20128/v1/models -H "Authorization: Bearer YOUR_KEY"
```

Yhdistettyjen malliesi pitäisi näkyä luettelossa. 🎉 Siinä kaikki — aloita koodaaminen, niin OmniRoute reitittää pyynnöt automaattisesti ja vaihtaa tarvittaessa varavaihtoehtoon.

Jos asiakasohjelmasi ei voi lähettää mukautettuja otsakkeita, OmniRoute tarjoaa myös tokenisoituja yhteensopivuusaliaksia:

```txt
OpenAI-luettelo:   http://localhost:20128/vscode/YOUR_KEY/
OpenAI-mallit:     http://localhost:20128/vscode/YOUR_KEY/models
OpenAI-keskustelu: http://localhost:20128/vscode/YOUR_KEY/chat/completions
OpenAI-vastaukset: http://localhost:20128/vscode/YOUR_KEY/responses
Ollama-keskustelu: http://localhost:20128/vscode/YOUR_KEY/api/chat
Ollama-tunnisteet: http://localhost:20128/vscode/YOUR_KEY/api/tags
```

Käytä näitä vain asiakasohjelmissa, jotka eivät voi lisätä `Authorization: Bearer ...`-otsaketta. Otsaketodennus on edelleen suositeltava tapa.

## 📦 Lisää asennustapoja — Docker, lähdekoodi, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

`:latest` seuraa korkeinta **julkaistua** vakaata SemVer-versiota. Se ei seuraa git-haaraa `main`. Kiinnitä GitOps-käyttöä varten versioon `:X.Y.Z`. Katso [Docker-julkaisukanavat](docs/guides/DOCKER_GUIDE.md#release-channels). Levykuva määrittää arvoksi **`OMNIROUTE_MEMORY_MB=1024`**. Se riittää hallintapaneelille ja kevyeen keskusteluun. **Koodausagentit** (Claude Coden, Codexin, Grokin jne. tekemät `POST /v1/responses` -pyynnöt) tarvitsevat huomattavasti suuremman V8-keon, tai prosessi päätyy `FATAL ERROR` -virheeseen noin 12 GiB:n kohdalla kahden päällekkäisen pitkän kontekstin aikana. Mitoita säilö kekoa suuremmaksi (natiivipuskurit sijaitsevat V8:n ulkopuolella):

| Kuormitus                                          | Keko (`-e OMNIROUTE_MEMORY_MB`) | Säilö (`--memory`) |
| -------------------------------------------------- | ------------------------------- | ------------------ |
| Hallintapaneeli / kevyt keskustelu                 | `1024` (levykuvan oletusarvo)   | ≥2 g               |
| Yksi koodausagentti                                | `8192`                          | ≥10 g              |
| Kaksi samanaikaista pitkää `/v1/responses`-pyyntöä | `10240`–`12288`                 | ≥12–16 g           |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

Koko taulukko: [Docker-opas — käytönaikainen RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

**⚡ Nopeampi / kevyempi asennus (ohita natiivikoonti)**

Natiivi SQLite-moottori (`better-sqlite3`) on **valinnainen** riippuvuus, joten yleinen
asennus ei koskaan pysähdy odottamaan lähdekoodista kääntämistä: se käyttää esikäännettyä binääritiedostoa, kun sellainen vastaa
alustaasi ja Node-versiotasi, ja muussa tapauksessa siirtyy läpinäkyvästi puhdasta JavaScriptiä käyttävään moottoriin
(`node:sqlite` Node 22+:ssa, muussa tapauksessa pakettiin sisältyvä `sql.js` WASM) — koontityökaluja ei tarvita.

Voit ohittaa asennuksen jälkeisen natiivin esilämmityksen kokonaan (CI-ympäristöt, käyttöliittymättömät ympäristöt tai hitaat laitteet):

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # Myös CI=1 ohittaa sen
```

Nopeimpiin asennuksiin kannattaa käyttää **pnpm**:ää (sisältöosoitteinen varasto + kovat linkit — katso edellä).
Käytä ilman hallintapaneelia toimivaan käyttöliittymättömään ajoympäristöön Dockerin `base`-profiilia (edellä) tai
[Termux-opasta](docs/guides/TERMUX_GUIDE.md). CLI ja verkkohallintapaneeli tarjotaan saman
prosessin kautta yhdessä portissa, joten erillistä vain CLI:n sisältävää pakettia ei tällä hetkellä ole.

### Osallistumisohjeet

1. Forkkaa repositorio
2. Luo haara **aktiivisen** `release/vX.Y.Z`-haaran viimeisimmästä commitista (ei `main`-haarasta) — katso [Haarautumis- ja julkaisumalli](docs/ops/BRANCHING_MODEL.md)
3. Luo ominaisuushaarasi (`git checkout -b feat/amazing-feature`)
4. Commitoi muutoksesi (`git commit -m 'feat: add amazing feature'`)
5. Pushaa haaraan (`git push origin feat/amazing-feature`)
6. Avaa Pull Request, jonka **base = kyseinen `release/vX.Y.Z`-haara**

Katso yksityiskohtaiset ohjeet tiedostosta [CONTRIBUTING.md](CONTRIBUTING.md).
