Hai cách để đưa Cursor chạy phía sau OmniRoute mà không cần phiên IDE:

1. **Nhà cung cấp `cursor-api`** (thẻ "Cursor API", bí danh `cua`): một nhà cung cấp dùng khóa API, lưu khóa API người dùng Cursor (`crsr_…`, được tạo tại `https://cursor.com/dashboard/api`). Sau đó, mọi ứng dụng khách OmniRoute đều có thể truy cập các mô hình Cursor qua `/v1/chat/completions` dưới dạng `cursor-api/<model>` hoặc `cua/<model>`, với các lớp hạn ngạch, dự phòng và ghi nhật ký thông thường. Nhà cung cấp IDE (`cursor`, phiên OAuth/IDE) không thay đổi.
2. **Chuyển tiếp Cursor CLI**: trỏ Cursor CLI (`agent`) đến OmniRoute để mọi RPC do CLI thực hiện đều được xác thực bằng khóa API OmniRoute, chuyển tiếp đến Cursor bằng thông tin xác thực của một kết nối `cursor-api`, và được ghi lại trên trang Logs.

## Tại sao khóa được trao đổi

`api2.cursor.sh` từ chối khóa `crsr_…` thô khi được dùng làm Bearer token (401). Trước tiên, Cursor CLI gửi yêu cầu POST chứa khóa đến `/auth/exchange_user_api_key` và nhận về một JWT phiên hết hạn sau một giờ; `refreshToken` được trả về có cùng `exp`, vì vậy làm mới đồng nghĩa với việc trao đổi lại khóa.
`open-sse/services/cursorApiKeyAuth.ts` thực hiện việc trao đổi đó, lưu vào bộ nhớ đệm một token phiên cho mỗi khóa, trao đổi lại năm phút trước khi hết hạn và loại bỏ token đã lưu trong bộ nhớ đệm khi Cursor trả về 401. `CursorExecutor` gọi thành phần này ngay trước khi mở luồng ngược dòng cho các kết nối `cursor-api`.

## Nhà cung cấp `cursor-api`

Registry: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, cùng `format`, `baseUrl` và
`models` như `cursor`). Thẻ danh mục:
`src/shared/constants/providers/apikey/specialty-media.ts`. Ánh xạ executor:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

Bảng điều khiển: Providers → Cursor API → Add API key.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

Sau đó:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

Lưu ý:

- Danh sách mô hình cho `cursor-api` đến từ registry Cursor tĩnh (cùng danh sách mà nhà cung cấp IDE sử dụng làm phương án dự phòng); không cần cài đặt `cursor-agent` trên máy chủ OmniRoute.
- `POST /api/providers/{id}/refresh-cursor` chỉ dành cho nhà cung cấp IDE `cursor`; các kết nối `cursor-api` không có phiên IDE cần gia hạn.

## Chuyển tiếp Cursor CLI

Tuyến: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. Tiền tố `/api/cursor-cli/` được đăng ký trong `src/shared/constants/publicApiRoutes.ts` vì trình xử lý tự thực thi cơ chế xác thực riêng:

| Đường dẫn                                                                                                                      | Xác thực mà CLI phải cung cấp | Việc OmniRoute thực hiện                                                                                                                                                |
| ------------------------------------------------------------------------------------------------------------------------------ | ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                             | `Bearer <OmniRoute API key>`  | Xác thực khóa, tạo JWT HS256 có thời hạn 1 giờ (được ký bằng `JWT_SECRET`) và trả về                                                                                    |
| mọi đường dẫn khác (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`           | Xác minh nhà phát hành/đối tượng/thời hạn, chọn một kết nối `cursor-api` đang hoạt động, thay tiêu đề Authorization bằng token Cursor đã trao đổi và truyền phản hồi về |

CLI giải mã `exp` từ bất kỳ token nào nhận được, vì vậy việc cung cấp cho nó một token không trong suốt sẽ khiến nó trao đổi lại trước hầu hết mọi yêu cầu; JWT được tạo giúp tránh điều đó. Phản hồi 401 từ OmniRoute khiến CLI thực hiện trao đổi lại.

### Thiết lập

1. Tạo khóa API OmniRoute (Dashboard → API keys) và một kết nối `cursor-api`.
2. Yêu cầu CLI sử dụng HTTP/1.1 cho luồng agent. Trong
   `~/.cursor/cli-config.json`:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   Nếu không có thiết lập này, CLI sẽ mở lượt agent qua HTTP/2 đến một máy chủ agent được cấu hình riêng và chỉ các RPC của mặt phẳng điều khiển mới đi qua endpoint.

3. Chạy CLI với OmniRoute:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

Mỗi chặng đều xuất hiện trong Logs với nhà cung cấp `cursor-api`, loại yêu cầu `cursor-cli`, đường dẫn `/api/cursor-cli/<rpc>`, được quy cho khóa API OmniRoute và kết nối đã phục vụ yêu cầu đó.

### Các chế độ lỗi

| Tình huống                                              | Phản hồi cho CLI                                                |
| ------------------------------------------------------- | --------------------------------------------------------------- |
| Khóa OmniRoute không xác định và `REQUIRE_API_KEY=true` | 401 `unauthenticated` khi trao đổi                              |
| `REQUIRE_API_KEY=false`                                 | phiên ẩn danh (tương tự hành vi của `/v1/*`)                    |
| JWT phiên hết hạn / từ nguồn khác / bị giả mạo          | 401, CLI thực hiện trao đổi lại                                 |
| Khóa API OmniRoute bị thu hồi sau khi trao đổi          | 401 ở RPC tiếp theo                                             |
| Không có kết nối `cursor-api` đang hoạt động            | 503 `unavailable`                                               |
| Cursor từ chối khóa của kết nối                         | 401 `unauthenticated`, phiên được lưu đệm bị xóa                |
| Không thể kết nối đến dịch vụ thượng nguồn              | 502 `unavailable` (thông báo đã được lược bỏ chi tiết nhạy cảm) |
| Chưa đặt `JWT_SECRET`                                   | 503 khi trao đổi                                                |
