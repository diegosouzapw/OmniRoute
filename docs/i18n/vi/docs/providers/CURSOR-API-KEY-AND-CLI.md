Hai cách để đặt Cursor phía sau OmniRoute mà không cần phiên IDE:

1. **Nhà cung cấp `cursor-api`** (thẻ "Cursor API", bí danh `cua`): một nhà cung cấp
   dùng khóa API, lưu khóa API người dùng Cursor (`crsr_…`, được tạo tại
   `https://cursor.com/dashboard/api`). Sau đó, mọi máy khách OmniRoute đều có thể truy cập
   các mô hình Cursor thông qua `/v1/chat/completions` dưới dạng `cursor-api/<model>` hoặc
   `cua/<model>`, với các lớp hạn ngạch, dự phòng và ghi nhật ký thông thường. Nhà cung cấp IDE
   (`cursor`, phiên OAuth/IDE) không thay đổi.
2. **Chuyển tiếp trực tiếp Cursor CLI**: trỏ Cursor CLI (`agent`) đến OmniRoute để
   mọi RPC mà CLI thực hiện đều được xác thực bằng khóa API OmniRoute, được chuyển tiếp
   đến Cursor bằng thông tin xác thực của một kết nối `cursor-api` và được ghi lại trên
   trang Logs.

## Lý do khóa được trao đổi

`api2.cursor.sh` từ chối khóa `crsr_…` thô khi dùng làm Bearer token (401). Cursor
CLI trước tiên POST khóa đến `/auth/exchange_user_api_key` và nhận về một JWT
phiên hết hạn sau một giờ; `refreshToken` được trả về có cùng `exp`, vì vậy việc
làm mới đồng nghĩa với trao đổi lại khóa.
`open-sse/services/cursorApiKeyAuth.ts` thực hiện việc trao đổi đó, lưu vào bộ nhớ đệm một token
phiên cho mỗi khóa, trao đổi lại năm phút trước khi hết hạn và xóa token đã lưu
khỏi bộ nhớ đệm khi Cursor trả về 401. `CursorExecutor` gọi hàm này ngay trước khi mở
luồng ngược dòng cho các kết nối `cursor-api`.

## Nhà cung cấp `cursor-api`

Registry: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, có cùng `format`, `baseUrl` và
`models` như `cursor`). Thẻ danh mục:
`src/shared/constants/providers/apikey/specialty-media.ts`. Ánh xạ executor:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

Bảng điều khiển: Providers → Cursor API → Add API key.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

Sau đó:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

Lưu ý:

- Danh sách mô hình cho `cursor-api` được lấy từ registry Cursor tĩnh (cùng
  danh sách mà nhà cung cấp IDE sử dụng làm phương án dự phòng); không cần cài đặt
  `cursor-agent` trên máy chủ OmniRoute.
- `POST /api/providers/{id}/refresh-cursor` chỉ dành cho nhà cung cấp IDE `cursor`;
  các kết nối `cursor-api` không có phiên IDE để gia hạn.

## ID mô hình gốc và mức độ nỗ lực

Đối với `cursor` / `cu` và `cursor-api` / `cua`, bộ chuẩn hóa mức độ nỗ lực Claude dùng chung
giữ nguyên ID mô hình được yêu cầu. Cursor có thể công bố một hậu tố như
`-low` như một phần của ID mô hình thực, thay vì dưới dạng bí danh mức độ nỗ lực của OmniRoute.
Executor Cursor bảo toàn một kết quả khớp chính xác trong danh mục trực tiếp; khi không có
kết quả khớp, trình phân giải mô hình hiện có của nó sẽ xử lý việc chuyển đổi hậu tố thành tham số.

Điều này không thay đổi quá trình chuẩn hóa mức độ nỗ lực đối với các tuyến Claude trực tiếp,
tương thích với Claude hoặc Vertex. Tính khả dụng vẫn phụ thuộc vào danh mục và quyền hạn
của tài khoản Cursor được chọn.

## Chuyển tiếp Cursor CLI

Tuyến: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. Tiền tố `/api/cursor-cli/` được
đăng ký trong `src/shared/constants/publicApiRoutes.ts` vì trình xử lý
tự thực thi cơ chế xác thực:

| Đường dẫn                                                                                                                      | Xác thực mà CLI yêu cầu      | OmniRoute thực hiện                                                                                                                                                                  |
| ------------------------------------------------------------------------------------------------------------------------------ | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `POST /auth/exchange_user_api_key`                                                                                             | `Bearer <OmniRoute API key>` | Xác thực khóa, tạo JWT HS256 có thời hạn 1 giờ (được ký bằng `JWT_SECRET`) và trả về JWT đó                                                                                          |
| mọi đường dẫn khác (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`          | Xác minh tổ chức phát hành/đối tượng/thời hạn, chọn một kết nối `cursor-api` đang hoạt động, thay header Authorization bằng token Cursor đã trao đổi và truyền trực tiếp phản hồi về |

CLI giải mã `exp` từ bất kỳ token nào nhận được, vì vậy việc cung cấp một token
không trong suốt khiến CLI thực hiện trao đổi lại trước hầu hết mọi yêu cầu; JWT
được tạo sẽ tránh điều đó. Phản hồi 401 từ OmniRoute khiến CLI trao đổi lại.

### Thiết lập

1. Tạo một khóa API OmniRoute (Dashboard → API keys) và một kết nối
   `cursor-api`.
2. Yêu cầu CLI sử dụng HTTP/1.1 cho luồng agent. Trong
   `~/.cursor/cli-config.json`:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   Nếu không có cấu hình này, CLI sẽ mở lượt agent qua HTTP/2 đến một máy chủ
   agent được cấu hình riêng và chỉ các RPC của mặt phẳng điều khiển mới đi qua
   endpoint.

3. Chạy CLI với OmniRoute:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

Mỗi lượt chuyển tiếp đều xuất hiện trong Logs với provider là `cursor-api`, loại
yêu cầu là `cursor-cli`, đường dẫn `/api/cursor-cli/<rpc>`, được quy cho khóa API
OmniRoute và kết nối đã phục vụ yêu cầu đó.

### Các trường hợp lỗi

| Tình huống                                              | Phản hồi cho CLI                                 |
| ------------------------------------------------------- | ------------------------------------------------ |
| Khóa OmniRoute không xác định và `REQUIRE_API_KEY=true` | 401 `unauthenticated` khi trao đổi               |
| `REQUIRE_API_KEY=false`                                 | phiên ẩn danh (tương tự hành vi của `/v1/*`)     |
| JWT phiên hết hạn / từ bên ngoài / bị giả mạo           | 401, CLI thực hiện trao đổi lại                  |
| Khóa API OmniRoute bị thu hồi sau khi trao đổi          | 401 ở RPC tiếp theo                              |
| Không có kết nối `cursor-api` nào đang hoạt động        | 503 `unavailable`                                |
| Cursor từ chối khóa của kết nối                         | 401 `unauthenticated`, phiên được lưu đệm bị xóa |
| Không thể kết nối đến upstream                          | 502 `unavailable` (thông báo đã được làm sạch)   |
| Chưa thiết lập `JWT_SECRET`                             | 503 khi trao đổi                                 |
