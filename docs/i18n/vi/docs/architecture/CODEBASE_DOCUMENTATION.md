## 1. Ngăn xếp công nghệ

| Khía cạnh                       | Lựa chọn                                                                                                                              |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Framework web                   | **Next.js 16** (App Router, đầu ra độc lập, không có middleware toàn cục)                                                             |
| Ngôn ngữ                        | **TypeScript 6.0+** — target `ES2022`, `module: esnext`, `moduleResolution: bundler`, `strict: false`                                 |
| Runtime                         | **Node.js** `>=22.22.2 <23` hoặc `>=24.0.0 <27` (được bắt buộc thông qua `engines` + `SUPPORTED_NODE_RANGE`)                          |
| Cơ sở dữ liệu                   | **SQLite** thông qua `better-sqlite3` (singleton, ghi nhật ký WAL)                                                                    |
| Máy tính để bàn                 | **Electron 41** + `electron-builder` 26.10 (workspace riêng tại `electron/`)                                                          |
| Kiểm thử                        | **Trình chạy kiểm thử gốc của Node** (đơn vị/tích hợp), **Vitest** (MCP, autoCombo, bộ nhớ đệm), **Playwright** (e2e + protocols-e2e) |
| Build                           | Next.js độc lập thông qua `scripts/build/build-next-isolated.mjs`                                                                     |
| Kiểm tra định dạng/định dạng mã | Cấu hình phẳng ESLint + Prettier (`lint-staged` thông qua Husky pre-commit)                                                           |
| Hệ thống mô-đun                 | ESM ở mọi nơi (`"type": "module"`)                                                                                                    |
| Workspace                       | npm workspace — `open-sse` là workspace con duy nhất                                                                                  |

Bí danh đường dẫn (`tsconfig.json`):

- `@/*` → `src/*`
- `@omniroute/open-sse` → `open-sse/index.ts`
- `@omniroute/open-sse/*` → `open-sse/*`

Cổng HTTP mặc định: **`20128`** (API và bảng điều khiển dùng chung một tiến trình). Thư mục
dữ liệu được chỉ định bởi biến môi trường `DATA_DIR`, mặc định là `~/.omniroute/`.

### 3.1 `src/app/` — App Router

App Router cung cấp cả giao diện bảng điều khiển lẫn API HTTP công khai/quản lý.
**Không có middleware toàn cục** — việc chặn và xử lý được thực hiện theo từng tuyến.

Các phân đoạn cấp cao nhất trong `src/app/`:

| Đường dẫn                                                                     | Mục đích                                                     |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `api/`                                                                        | Tất cả các tuyến API HTTP (xem phân tích bên dưới)           |
| `a2a/`                                                                        | Điểm cuối A2A JSON-RPC 2.0 (`POST /a2a`)                     |
| `.well-known/agent.json/`                                                     | Tài liệu khám phá A2A Agent Card                             |
| `(dashboard)/`                                                                | Giao diện bảng điều khiển (nhóm tuyến, không có tiền tố URL) |
| `auth/`, `login/`, `forgot-password/`, `callback/`                            | Các luồng xác thực                                           |
| `landing/`                                                                    | Trang tiếp thị/trang đích                                    |
| `docs/`                                                                       | Trình xem tài liệu API được nhúng                            |
| `status/`, `maintenance/`, `offline/`                                         | Các trang vận hành                                           |
| `privacy/`, `terms/`                                                          | Các trang pháp lý                                            |
| `400/`, `401/`, `403/`, `408/`, `429/`, `500/`, `502/`, `503/`                | Các trang lỗi tĩnh                                           |
| `error.tsx`, `global-error.tsx`, `not-found.tsx`, `forbidden/`, `loading.tsx` | Các ranh giới lỗi/tải của framework                          |
| `layout.tsx`, `page.tsx`, `globals.css`, `manifest.ts`                        | Khung gốc                                                    |

#### 3.1.2a `src/app/api/services/` — Quản lý dịch vụ nhúng

Các tuyến dùng để cài đặt, khởi động, dừng và giám sát 9Router cùng CLIProxyAPI.
Tất cả các đường dẫn đều được phân loại là **LOCAL_ONLY** (chỉ loopback, quy tắc cứng số 17) vì chúng
có thể gọi `npm install` và tạo các tiến trình con.

```
src/app/api/services/
├── 9router/
│   ├── _lib.ts             hàm trợ giúp getOrInitSupervisor()
│   ├── install/route.ts    POST — npm install thông qua execFile
│   ├── start/route.ts      POST — supervisor.start()
│   ├── stop/route.ts       POST — supervisor.stop()
│   ├── restart/route.ts    POST — supervisor.restart()
│   ├── update/route.ts     POST — npm install phiên bản mới hơn
│   ├── rotate-key/route.ts POST — tạo API key mới + khởi động lại
│   ├── status/route.ts     GET  — trạng thái trực tiếp + trạng thái DB + siêu dữ liệu phiên bản
│   └── auto-start/route.ts POST — bật/tắt cờ auto_start
├── cliproxy/
│   ├── _lib.ts             hàm trợ giúp getOrInitSupervisor()
│   ├── install/route.ts    POST — npm install
│   ├── start/route.ts      POST — supervisor.start()
│   ├── stop/route.ts       POST — supervisor.stop()
│   ├── restart/route.ts    POST — supervisor.restart()
│   ├── update/route.ts     POST — npm install phiên bản mới hơn
│   ├── status/route.ts     GET  — trạng thái trực tiếp + trạng thái DB + siêu dữ liệu phiên bản
│   └── auto-start/route.ts POST — bật/tắt cờ auto_start
└── [name]/
    └── logs/route.ts       GET  — luồng nhật ký SSE (dùng chung cho tất cả dịch vụ)
```

Giao diện bảng điều khiển tương ứng:
`src/app/(dashboard)/dashboard/providers/services/` — trang gồm hai tab (CLIProxyAPI + 9Router).
Proxy ngược cho giao diện nhúng của 9Router:
`src/app/(dashboard)/dashboard/providers/services/[name]/embed/[[...path]]/route.ts`

Tìm hiểu chuyên sâu: `docs/frameworks/EMBEDDED-SERVICES.md`

Mọi tệp route đều tuân theo cùng một mẫu:

```
Route → kiểm tra sơ bộ CORS → xác thực nội dung bằng Zod → xác thực tùy chọn
      → thực thi chính sách API key → ủy quyền cho trình xử lý (open-sse)
```

`v1beta/` là bề mặt tương thích theo phong cách Gemini (một lớp bao mỏng chuyển đổi sang
cùng pipeline `open-sse/handlers/`).

## 10. Cách đóng góp

### Thêm nhà cung cấp mới

1. Đăng ký trong `src/shared/constants/providers.ts` (được Zod xác thực khi tải).
2. Thêm một executor trong `open-sse/executors/` nếu cần logic tùy chỉnh
   (mở rộng `BaseExecutor`).
3. Thêm một translator trong `open-sse/translator/` nếu nhà cung cấp không sử dụng định dạng OpenAI.
4. Nếu dựa trên OAuth, hãy thêm cấu hình trong `src/lib/oauth/providers/` và
   `src/lib/oauth/services/`.
5. Đăng ký các model trong `open-sse/config/providerRegistry.ts` (hoặc registry dành riêng cho định dạng
   trong `open-sse/config/`).
6. Viết kiểm thử trong `tests/unit/`.

### Thêm route API mới

1. Tạo `src/app/api/your-route/route.ts`.
2. Tuân theo mẫu: CORS → xác thực body bằng Zod → xác thực danh tính → ủy quyền cho handler.
3. Nếu có cấu trúc request mới: thêm schema Zod vào `src/shared/validation/schemas.ts`.
4. Nếu chỉ dành cho quản trị: thêm đường dẫn vào `src/shared/constants/publicApiRoutes.ts`
   (danh sách từ chối cho bề mặt API công khai).
5. Thêm kiểm thử trong `tests/unit/`.
6. Cập nhật `docs/reference/API_REFERENCE.md` và `docs/openapi.yaml`.

### Thêm mô-đun DB mới

1. Tạo `src/lib/db/yourModule.ts` và import `getDbInstance()` từ `./core.ts`.
2. Export các hàm CRUD cho miền nghiệp vụ của bạn.
3. Nếu có bảng mới: thêm migration trong `src/lib/db/migrations/`, được đánh số
   tuần tự, có tính lũy đẳng và giao dịch.
4. Các mô-đun sử dụng phải import trực tiếp từ `@/lib/db/yourModule` (không dùng barrel — lớp tái export `localDb.ts` cũ đã bị xóa).
5. Thêm kiểm thử trong `tests/unit/`.

### Thêm công cụ MCP mới

1. Thêm định nghĩa công cụ trong `open-sse/mcp-server/tools/` (hoặc mở rộng
   `open-sse/mcp-server/schemas/tools.ts`).
2. Gán phạm vi phù hợp trong `src/shared/constants/mcpScopes.ts`.
3. Đăng ký công cụ trong `open-sse/mcp-server/server.ts`.
4. Thêm kiểm thử trong `open-sse/mcp-server/__tests__/`.
5. Cập nhật [MCP-SERVER.md](../frameworks/MCP-SERVER.md).

### Thêm kỹ năng A2A mới

## 11. Quy ước

- **Kiểu mã nguồn**: thụt lề 2 khoảng trắng, dấu ngoặc kép, chiều rộng 100 ký tự, dấu chấm phẩy,
  dấu phẩy cuối kiểu `es5` — được Prettier thực thi thông qua `lint-staged`.
- **Import**: bên ngoài → nội bộ (`@/`, `@omniroute/open-sse`) → tương đối.
- **Đặt tên**: tệp dùng `camelCase` hoặc `kebab-case`, component dùng `PascalCase`,
  hằng số dùng `UPPER_SNAKE`.
- **ESLint**: `no-eval`, `no-implied-eval`, `no-new-func` = `error` ở mọi nơi;
  `no-explicit-any` = `warn` trong `open-sse/` và `tests/`, là lỗi ở nơi khác.
- **TypeScript**: `strict: false` (tư thế tương thích mã cũ). Ưu tiên kiểu tường minh hơn
  suy luận kiểu tại các ranh giới giữa mô-đun.
- **Cơ sở dữ liệu**: không bao giờ viết SQL thô trong route hoặc handler — luôn truy cập thông qua
  các mô-đun `src/lib/db/`. Không bao giờ import kiểu barrel — hãy sử dụng trực tiếp các mô-đun `src/lib/db/*` cụ thể.
- **Định kiểu thực thể DB (#3512)**: một hàm ghi hoặc đọc cấu trúc hàng của bảng DB
  phải nhận/trả về một interface TS có tên phản ánh tương ứng 1:1 với các cột của bảng đó,
  không dùng `any` hoặc kiểu ẩn danh nội tuyến tại vị trí gọi. Đặt
  interface ngay cạnh hàm (ví dụ: `export interface UsageEntry` trong
  `src/lib/usage/usageHistory.ts` phía trên `saveRequestUsage`), giữ từng
  trường ở trạng thái tùy chọn/có thể null khi các trình ghi khác nhau điền dữ liệu vào hàng
  theo từng bước, đồng thời ưu tiên `unknown` hơn `any` cho trường có cấu trúc
  khác nhau giữa các bên gọi (được ghi chú trên trường, ví dụ: `UsageEntry.tokens`
  chấp nhận cả dữ liệu sử dụng thô theo cấu trúc của nhà cung cấp và cấu trúc đã chuẩn hóa). Khi số lượng
  `any` của một tệp đạt mức không theo cách này, hãy thêm tệp đó vào danh sách cho phép
  `check:any-budget:t11` (`scripts/check/check-t11-any-budget.mjs`,
  `maxAny: 0`) để ngăn việc tái diễn. Đây là quy ước cho giai đoạn đầu — việc
  dọn dẹp rộng hơn theo nguyên tắc "không dùng `any` ẩn danh" được thực hiện lặp lại trên phần còn lại của
  cơ sở mã.
- **Lỗi**: dùng try/catch với các kiểu lỗi cụ thể, ghi log với ngữ cảnh pino. Không bao giờ
  âm thầm bỏ qua lỗi trong luồng SSE; sử dụng tín hiệu hủy để dọn dẹp.
- **Bảo mật**: không bao giờ sử dụng `eval()` / `new Function()` / eval ngầm định. Xác thực
  mọi đầu vào bằng Zod. Mã hóa thông tin xác thực khi lưu trữ (AES-256-GCM). Giữ
  danh sách từ chối `src/shared/constants/upstreamHeaders.ts` đồng bộ với
  lớp làm sạch/xác thực.
- **Commit**: Conventional Commits — `feat(scope): subject`. Các phạm vi được phép:
  `db`, `sse`, `oauth`, `dashboard`, `api`, `cli`, `docker`, `ci`, `mcp`,
  `a2a`, `memory`, `skills`.
- **Nhánh**: các tiền tố `feat/`, `fix/`, `refactor/`, `docs/`, `test/`,
  `chore/`. Không bao giờ commit trực tiếp vào `main`.
- **Husky**: pre-commit chạy `lint-staged` + `check:docs-sync` +
  `check:any-budget:t11`; pre-push chạy `check:any-budget:t11` + `check:tracked-artifacts` (các cổng kiểm tra nhanh; loại trừ `test:unit`).

## 12. Quy tắc bắt buộc (từ CLAUDE.md)

1. Không bao giờ commit bí mật hoặc thông tin xác thực.
2. Không bao giờ sử dụng barrel import — hãy sử dụng trực tiếp các module `src/lib/db/*` cụ thể.
3. Không bao giờ sử dụng `eval()` / `new Function()` / eval ngầm định.
4. Không bao giờ commit trực tiếp vào `main`.
5. Không bao giờ viết SQL thô trong các route — luôn thông qua các module `src/lib/db/`.
6. Không bao giờ âm thầm bỏ qua lỗi trong các luồng SSE.
7. Luôn xác thực đầu vào bằng các schema Zod.
8. Luôn bổ sung kiểm thử khi thay đổi mã production.
9. Độ bao phủ phải duy trì ≥ 60% (câu lệnh, dòng, hàm, nhánh).
