**OmniCopilot** đưa mọi mô hình mà OmniRoute của bạn cung cấp vào trình chọn mô hình _gốc_ của GitHub Copilot Chat.
Không có thanh bên thứ hai, không có giao diện trò chuyện riêng — chế độ agent của Copilot, khả năng gọi công cụ,
máy chủ MCP và hướng dẫn tùy chỉnh đều tiếp tục hoạt động, chỉ khác là chạy trên mô hình bạn chọn.

> **Không cần đăng ký Copilot.** Kể từ VS Code 1.122, nhà cung cấp mô hình ngôn ngữ hoạt động
> mà không cần đăng nhập GitHub và không cần bất kỳ gói Copilot nào. Tính năng hoàn thành nội tuyến và
> các tính năng dựa trên embedding nằm ngoài API của nhà cung cấp và vẫn yêu cầu Copilot.

## Thiết lập

1. **Chạy OmniRoute** — `npm install -g omniroute && omniroute` (bảng điều khiển tại `http://localhost:20128`).
2. **Cài đặt tiện ích mở rộng** — tìm kiếm "OmniRoute" trong chế độ xem Extensions.
3. **Chọn mô hình** — Copilot Chat → trình chọn mô hình → **Manage Models…** → **OmniRoute**, sau đó đánh dấu
   những mô hình bạn muốn.

Không cần cấu hình gì khi OmniRoute chạy trên cổng mặc định. Với một phiên bản từ xa, hãy mở
**biểu tượng OmniRoute trên Activity Bar** (hoặc chạy `OmniRoute: Manage Connection`) và thiết lập:

- **URL máy chủ** — URL gốc của máy chủ, ví dụ: `http://192.168.0.15:20128`. Hậu tố `/v1` được
  tiện ích mở rộng tự động thêm vào; đừng đưa nó vào.
- **Khóa API** — chỉ khi máy chủ thiết lập `REQUIRE_API_KEY`. Được lưu trữ trong chuỗi khóa của hệ điều hành thông qua VS
  Code SecretStorage, không bao giờ nằm trong `settings.json`.

## Nội dung trình chọn sẽ hiển thị

Tiện ích mở rộng không hiển thị trực tiếp payload `GET /v1/models` — nó định hình dữ liệu này, và số lượng bạn
thấy thấp hơn kích thước danh mục vì hai lý do có chủ đích.

### Tiện ích yêu cầu một id cho mỗi mô hình

`MODELS_CATALOG_PREFIX_MODE` mặc định là **`dual`**, chế độ này quảng bá mỗi mô hình hai lần — một lần
dưới tiền tố bí danh ngắn và một lần dưới tiền tố nhà cung cấp chuẩn — để các cấu hình máy khách cũ
tiếp tục phân giải được cả hai dạng:

```
cc/claude-sonnet-4-6        ← tiền tố bí danh
claude/claude-sonnet-4-6    ← tiền tố chuẩn, cùng một mô hình
```

Tiện ích mở rộng yêu cầu **`GET /v1/models?prefix=alias`** để nhận một id cho mỗi mô hình mà không
thay đổi thiết lập toàn máy chủ dành cho các máy khách khác của bạn. Trên một phiên bản tham chiếu, thao tác này đã rút gọn
**2345 mục xuống còn 1396 — loại bỏ 949 mục trùng lặp, không mất mô hình nào.**

Nếu bạn muốn khắc phục vấn đề này trên toàn máy chủ cho _mọi_ máy khách, hãy đặt cờ tính năng
`MODELS_CATALOG_PREFIX_MODE` thành `alias` trong bảng điều khiển. Xem
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) để biết
tham số truy vấn và bảng cho từng chế độ.

### Tiện ích ẩn các mô hình không thể trò chuyện

Danh mục cũng liệt kê các mô hình hình ảnh, video, âm thanh, xếp hạng lại, embedding và kiểm duyệt. Dù sao thì những mô hình này
cũng bị từ chối khi gửi yêu cầu trò chuyện:

```
HTTP 400 — Mô hình '<id>' là mô hình tạo hình ảnh và không thể sử dụng trên
/v1/chat/completions. Thay vào đó, hãy sử dụng POST /v1/images/generations.
```

vì vậy, chúng được lọc dựa trên trường `type` trước khi xuất hiện trong trình chọn. **Các mô hình Responses-API
vẫn được giữ lại** — mọi mục Codex / GPT-5.x đều quảng bá `supported_endpoints: ["responses"]`,
và OmniRoute chuyển đổi chúng cho `/v1/chat/completions`, vì vậy chúng hoàn toàn có thể sử dụng được.

### Các nhà cung cấp bạn chưa từng cấu hình

Danh mục liệt kê các mô hình từ những nhà cung cấp có **kết nối đang hoạt động** _cùng với_ mọi nhà cung cấp **noAuth**
— những nhà cung cấp không cần khóa, chiếm phần lớn tầng miễn phí. Đây là hành vi có chủ đích. Để ẩn
chúng, hãy thêm chúng vào `blockedProviders` trong phần cài đặt của bảng điều khiển; tiện ích mở rộng
không thay đổi gì.

## Bảng điều khiển bên trong tab VS Code

`omnicopilot.dashboardOpen: "editor"` hiển thị bảng điều khiển OmniRoute trong một tab trình soạn thảo thông qua
Simple Browser thay vì trình duyệt bên ngoài. Việc nhúng phải được **chủ động bật trên máy chủ** thông qua
`DASHBOARD_ALLOW_EMBED=vscode`, khi đó các trang HTML sẽ được phục vụ với
`frame-ancestors 'self' vscode-webview:` thay vì thiết lập mặc định `frame-ancestors 'none'` +
`X-Frame-Options: DENY`. Bề mặt API (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) vẫn giữ
các header nghiêm ngặt trong cả hai trường hợp.

> ⚠️ **Đây là cờ tại thời điểm build, không phải tại thời điểm chạy.** Next.js biên dịch `headers()` vào manifest
> định tuyến, vì vậy `next.config.mjs` đọc biến này trong khi bundle được build
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> Việc export biến này trước khi chạy một máy chủ đã được build sẵn sẽ không thay đổi gì — các header đã được đóng gói cố định.

```bash
# biến phải hiện diện trong lệnh BUILD
DASHBOARD_ALLOW_EMBED=vscode npm run build        # hoặc npm run build:release
npm start
```

| Cách bạn cài đặt           | Có thể bật tính năng nhúng không?                                                                                                                |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Từ mã nguồn                | ✅ đặt biến trong lệnh build như trên                                                                                                            |
| `npm install -g omniroute` | ❌ package đã phát hành đi kèm bundle được build sẵn — hãy build từ mã nguồn thay thế                                                            |
| Image Docker               | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — image build sẵn trên Docker Hub không được bật tính năng nhúng |

Nếu không có bản build đã bật tính năng nhúng, trang sẽ từ chối được đóng khung; extension phát hiện điều đó từ
các header phản hồi và chuyển sang dùng trình duyệt bên ngoài — không có gì bị lỗi và extension sẽ thông báo một lần.
Xem [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) và issue
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273).

## Cấu hình các công cụ khác của bạn từ bên trong VS Code

**`OmniRoute: Configure Coding CLI`** điều khiển CLI `omniroute` để ghi các profile sẵn sàng sử dụng
cho Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code,
Kilo và Roo — các cấu hình tương tự được mô tả trong
[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md). Khóa API được chuyển cho CLI thông qua biến môi trường
`OMNIROUTE_API_KEY`, không bao giờ được truyền trên dòng lệnh.

## Khắc phục sự cố

| Triệu chứng                                                         | Nguyên nhân / cách khắc phục                                                                                                                                                                                                                                      |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Không có model OmniRoute trong trình chọn                           | Không thể kết nối đến máy chủ. Dấu chấm trên thanh trạng thái chuyển sang màu xám; chạy `OmniRoute: Check Connection`. Theo thiết kế, quá trình khám phá diễn ra âm thầm và không cung cấp model nào thay vì hiển thị lời nhắc.                                   |
| Mỗi model xuất hiện hai lần                                         | Bạn đang dùng phiên bản OmniCopilot cũ hơn 1.0.1 — hãy cập nhật. Extension hiện yêu cầu `?prefix=alias`.                                                                                                                                                          |
| Một model hình ảnh/âm thanh từng được liệt kê nhưng nay đã biến mất | Đây là thay đổi có chủ đích kể từ 1.0.1 — model đó vốn không thể phản hồi yêu cầu trò chuyện.                                                                                                                                                                     |
| Bảng điều khiển bị thiếu trên Activity Bar                          | VS Code chuyển các container khung nhìn bổ sung vào mục tràn **"…"** ở cuối Activity Bar, và container bị ẩn bằng thao tác nhấp chuột phải sẽ tiếp tục bị ẩn. Nhấp chuột phải vào Activity Bar → chọn **OmniRoute**, hoặc mở bằng `OmniRoute: Manage Connection`. |
| Bảng điều khiển mở trong trình duyệt dù đang ở chế độ `editor`      | Máy chủ chưa được **build** với `DASHBOARD_ALLOW_EMBED=vscode` (xem ở trên) — việc đặt biến này khi khởi động một bản cài đặt được build sẵn không có tác dụng. Việc chuyển sang phương án dự phòng là có chủ đích.                                               |
| Danh sách model đã lỗi thời sau khi thay đổi provider               | Chạy `OmniRoute: Refresh Models` hoặc nhấp vào liên kết ↻ trong bảng điều khiển.                                                                                                                                                                                  |
