OmniRoute cung cấp **hai** cách để sử dụng OpenAI Codex:

| Nhà cung cấp           | Cách giao tiếp với OpenAI                                                                                                                                                          | Lưu ý về việc sử dụng                                                      |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| **`codex`**            | Phát lại trực tiếp token OAuth ChatGPT/OpenAI của bạn tới Responses API                                                                                                            | **Có** — phiên chính thức không được cấp quyền để sử dụng qua proxy/router |
| **`codex-app-server`** | Điều khiển **`codex app-server` của chính Codex CLI** qua JSON-RPC/WebSocket; CLI sở hữu và tự làm mới OAuth của mình (`~/.codex/auth.json`) giống hệt một phiên `codex` tương tác | **Không** — OmniRoute không bao giờ phát lại token tới API                 |

Vì `codex-app-server` không bao giờ phát lại token nên không có lưu ý hạn chế
sử dụng liên quan đến việc phát lại phiên. Tuy nhiên, nó yêu cầu phải có **Codex CLI
có thể truy cập được tại URL app-server đã cấu hình**, và CLI đó phải **được đăng nhập**.

## 1. Kiến trúc

```
┌─ Ứng dụng OmniRoute ─────────────┐        ┌─ Sidecar codex-app-server ──────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ token khả năng truy cập)      │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  tự quản lý OpenAI OAuth            │
└──────────────────────────────────┘        │  (~/.codex/auth.json, tự động làm mới)│
        │ được chia sẻ (volume compose)      └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → token khả năng truy cập WS (cả hai đều gắn volume này)
  codex-appserver-home    → ~/.codex (auth.json do dashboard ghi,
                             được codex app-server của sidecar đọc)
```

- Sidecar **chỉ** lắng nghe trên mạng compose nội bộ
  (`ws://codex-app-server:1456`) và được bảo vệ bằng token khả năng truy cập. Nó **không bao giờ**
  được công bố ra máy chủ host hoặc internet.
- Codex CLI được tích hợp sẵn trong `omniroute:base`, vì vậy không cần cài đặt codex trên
  host hoặc máy của người dùng khi chạy sidecar.

## 2. Khởi chạy

```bash
# Khởi động stack CÙNG profile sidecar codex app-server:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

Sidecar tạo token khả năng truy cập WS trong lần khởi động đầu tiên (vào volume
`codex-appserver-token` dùng chung), và ứng dụng đọc chính token đó qua
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE`. Không cần kết nối token thủ công.

## 3. Kết nối + đăng nhập

1. Trong dashboard, thêm kết nối cho **OpenAI Codex (App-Server)**. Không yêu cầu
   khóa API hoặc token (đây là nhà cung cấp không cần xác thực — sidecar quản lý việc xác thực).
2. Nếu Codex CLI của sidecar **chưa được đăng nhập**, kiểm tra tình trạng kết nối
   sẽ báo _"đang chạy nhưng chưa đăng nhập"_ (không phải lỗi xác thực màu đỏ). Hãy dùng
   **Đăng nhập bằng ChatGPT**: thao tác này chạy quy trình OAuth thiết bị tiêu chuẩn của Codex trong
   trình duyệt, sau đó ghi `~/.codex/auth.json` vào volume dùng chung thông qua
   **Áp dụng thông tin xác thực** (một lần đăng nhập này dùng cho cả hai nhà cung cấp `codex` và
   `codex-app-server`).
3. Sau khi đăng nhập, kiểm tra tình trạng sẽ chuyển sang màu xanh lục (nó xác minh cả `/readyz` **và**
   `account/read` — tức là vừa hoạt động _vừa_ được xác thực) và bắt đầu hoạt động.

Dashboard không bao giờ ghi đè lên một `~/.codex/auth.json` hiện có và hợp lệ — nó chỉ ghi
khi tệp không tồn tại hoặc token đã cũ (luôn tạo bản sao lưu).

## 4. Các kịch bản triển khai

- **Nhà vận hành đã có Codex CLI được xác thực** — gắn
  `~/.codex` trên host của bạn vào sidecar (`codex-appserver-home`) và bỏ qua bước đăng nhập.
- **Người dùng công khai, không cài codex cục bộ** — không thành vấn đề: sidecar đã có
  CLI. Người dùng chỉ cần xác thực thông qua dashboard.
- **OmniRoute trên máy vật lý (không có sidecar, dùng codex trên host)** — trỏ
  `OMNIROUTE_CODEX_APPSERVER_WS` tới `codex app-server` của riêng bạn và đảm bảo
  codex trên host đã được đăng nhập; gợi ý "codex chưa được cài đặt" sẽ xuất hiện nếu thiếu
  tệp nhị phân.

## 5. Lưu lượng đi qua mạng dân dụng / UDP (tùy chọn bổ sung cho nhà vận hành, không được phân phối)

Sidecar tổng quát ở trên định tuyến lưu lượng đi qua mạng thông thường của container. Một
nhà vận hành cần lưu lượng Codex đi qua **điểm thoát mạng dân dụng** (ví dụ: sidecar TUN
tailscale truyền TCP + UDP/QUIC) sẽ chạy cấu hình đó dưới dạng một tệp ghi đè compose
riêng biệt; cấu hình này chủ ý **không** nằm trong profile `codex-app-server`
được phân phối. Hãy xem tài liệu vận hành nội bộ để biết cách thiết lập.
