## 🎯 Các trường hợp sử dụng

### Trường hợp 1: "Tôi có gói đăng ký Claude Pro"

**Vấn đề:** Hạn mức hết hạn khi chưa sử dụng, bị giới hạn tốc độ trong lúc lập trình cường độ cao

```
Combo: "maximize-claude"
  1. cc/claude-opus-4-7        (tận dụng tối đa gói đăng ký)
  2. glm/glm-4.7               (phương án dự phòng giá rẻ khi hết hạn mức)
  3. if/qwen3.8-max-preview       (phương án dự phòng khẩn cấp miễn phí)

Chi phí hằng tháng: $20 (gói đăng ký) + ~$5 (dự phòng) = tổng cộng $25
so với $20 + chạm giới hạn = bực bội
```

### Trường hợp 2: "Tôi muốn chi phí bằng không"

**Vấn đề:** Không đủ khả năng chi trả cho các gói đăng ký, cần AI lập trình đáng tin cậy

```
Combo: "zero-cost"
  1. if/kimi-k2.7-code          (được liệt kê là có quyền truy cập miễn phí; có thể áp dụng giới hạn tốc độ)
  2. kr/qwen3-coder-next        (phương án dự phòng Kiro miễn phí)

Chi phí hằng tháng: $0
Chất lượng: hãy xác minh mô hình, giới hạn, quyền riêng tư và SLA cho khối lượng công việc của bạn
```

### Trường hợp 3: "Tôi cần lập trình 24/7, không bị gián đoạn"

**Vấn đề:** Có thời hạn gấp, không thể chấp nhận thời gian ngừng hoạt động

```
Combo: "always-on"
  1. cc/claude-opus-4-7        (chất lượng tốt nhất)
  2. cx/gpt-5.5                (gói đăng ký thứ hai)
  3. glm/glm-4.7               (giá rẻ, đặt lại hằng ngày)
  4. minimax/MiniMax-M2.1      (rẻ nhất, đặt lại sau 5 giờ)
  5. if/deepseek-v4-flash       (được liệt kê là có quyền truy cập miễn phí; có thể áp dụng giới hạn tốc độ)

Kết quả: 5 lớp dự phòng giúp tăng khả năng phục hồi; tính khả dụng của dịch vụ đầu nguồn không được đảm bảo
Chi phí hằng tháng: $20-200 (gói đăng ký) + $10-20 (dự phòng)
```

### Trường hợp 4: "Tôi muốn AI MIỄN PHÍ trong OpenClaw"

**Vấn đề:** Cần trợ lý AI trong các ứng dụng nhắn tin, hoàn toàn miễn phí

```
Combo: "openclaw-free"
  1. if/qwen3.8-max-preview     (được liệt kê là có quyền truy cập miễn phí; có thể áp dụng giới hạn tốc độ)
  2. if/deepseek-v4-flash       (được liệt kê là có quyền truy cập miễn phí; có thể áp dụng giới hạn tốc độ)
  3. if/kimi-k2.7-code          (được liệt kê là có quyền truy cập miễn phí; có thể áp dụng giới hạn tốc độ)

Chi phí hằng tháng: $0
Truy cập qua: WhatsApp, Telegram, Slack, Discord, iMessage, Signal...
```

## 📖 Thiết lập nhà cung cấp

Để thêm hàng loạt kết nối khóa API từ tệp CSV hoặc JSON, hãy sử dụng **Bảng điều khiển → Nhà cung cấp → Nhập từ tệp**. Các cột được xác định theo vị trí (`provider,name,apiKey,baseUrl,priority`); `provider` phải tồn tại sẵn dưới dạng nhà cung cấp được quản lý hoặc nút tương thích. Xem [Nhập nhà cung cấp từ tệp CSV hoặc JSON](../providers/CSV-IMPORT.md).

### 🔐 Nhà cung cấp theo gói đăng ký

#### Claude Code (Pro/Max)

```bash
Bảng điều khiển → Nhà cung cấp → Kết nối Claude Code
→ Đăng nhập OAuth → Tự động làm mới token
→ Theo dõi hạn mức 5 giờ + hàng tuần

Mô hình:
  cc/claude-opus-4-7
  cc/claude-sonnet-4-6
  cc/claude-haiku-4-5-20251001
```

**Mẹo chuyên nghiệp:** Dùng Opus cho các tác vụ phức tạp, Sonnet khi cần tốc độ. OmniRoute theo dõi hạn mức theo từng mô hình!

Các tuyến Claude và tương thích với Claude Code duy trì mức nỗ lực suy luận `max` cho các mô hình Opus và Sonnet. Các mô hình Haiku không chấp nhận mức nỗ lực `max`, vì vậy OmniRoute hạ yêu cầu đó xuống ngân sách suy luận cao trước khi gửi đến nhà cung cấp thượng nguồn.

#### OpenAI Codex (Plus/Pro)

```bash
Bảng điều khiển → Nhà cung cấp → Kết nối Codex
→ Đăng nhập OAuth (cổng 1455)
→ Đặt lại sau 5 giờ + hàng tuần

Mô hình:
  cx/gpt-5.5
  cx/gpt-5.4
  cx/gpt-5.3-codex
  cx/gpt-5.3-codex-spark
```

#### GitHub Copilot

```bash
Bảng điều khiển → Nhà cung cấp → Kết nối GitHub
→ OAuth qua GitHub
→ Đặt lại hàng tháng (ngày 1 mỗi tháng)

Mô hình:
  gh/gpt-5.5
  gh/gpt-5.4
  gh/claude-sonnet-4.6
  gh/claude-opus-4.7
  gh/gemini-3.1-pro-preview
```

### 💰 Nhà cung cấp giá rẻ

2. Lấy khóa API từ Coding Plan

**Sử dụng:** `glm/glm-4.7` — **Mẹo chuyên nghiệp:** Coding Plan cung cấp hạn mức gấp 3 lần với chi phí bằng 1/7! Đặt lại hàng ngày lúc 10:00 sáng.

## 🚀 Triển khai

### Cài đặt npm toàn cục (Khuyến nghị)

```bash
npm install -g omniroute

# Tạo thư mục cấu hình
mkdir -p ~/.omniroute

# Tạo tệp .env (xem .env.example)
cp .env.example ~/.omniroute/.env

# Khởi động máy chủ
omniroute
# Hoặc với cổng tùy chỉnh:
omniroute --port 3000
```

CLI tự động tải `.env` từ `~/.omniroute/.env` hoặc `./.env`.

### Chế độ khay hệ thống

Khởi động OmniRoute trong khay hệ thống:

```bash
omniroute serve --tray
```

Lệnh sẽ kết thúc sau khi máy chủ và khay hệ thống sẵn sàng.

Máy chủ tiếp tục chạy mà không cần cửa sổ dòng lệnh.

Chế độ khay hệ thống hỗ trợ macOS, Windows và các phiên Linux có giao diện đồ họa. Chế độ khay hệ thống không tự động mở bảng điều khiển.

Sử dụng menu khay hệ thống cho các thao tác sau:

- Mở bảng điều khiển.
- Mở `/dashboard/logs`.
- Thay đổi chế độ tự động khởi động.
- Dừng OmniRoute.

Không kết hợp `--tray` với các tùy chọn sau:

- `--daemon`
- `--log`
- `--no-recovery`

Các chế độ này yêu cầu quyền sở hữu tiến trình khác nhau.

Bật khởi động cùng hệ thống vào lần đăng nhập máy tính tiếp theo:

```bash
omniroute autostart enable
```

Tính năng tự động khởi động sử dụng chế độ khay hệ thống trên macOS, Windows và các phiên Linux có giao diện đồ họa. Linux không có giao diện đồ họa sử dụng dịch vụ người dùng systemd hiện có.

Tắt khởi động cùng hệ thống khi đăng nhập:

```bash
omniroute autostart disable
```

### Gỡ cài đặt

Khi không còn cần OmniRoute, chúng tôi cung cấp hai tập lệnh nhanh để gỡ bỏ sạch sẽ:

| Lệnh                     | Hành động                                                                                           |
| ------------------------ | --------------------------------------------------------------------------------------------------- |
| `npm run uninstall`      | Gỡ ứng dụng khỏi hệ thống nhưng **giữ lại cơ sở dữ liệu và cấu hình của bạn** trong `~/.omniroute`. |

### Void Linux (xbps-src)

Người dùng Void Linux có thể đóng gói và cài đặt OmniRoute theo cách nguyên bản bằng framework biên dịch chéo `xbps-src`. Quy trình này tự động hóa việc xây dựng bản độc lập Node.js cùng với các liên kết native `better-sqlite3` bắt buộc.

<summary><b>Xem template xbps-src</b></summary>

```bash
# Tệp template cho 'omniroute'
pkgname=omniroute
version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"

checksum=009400afee90a9f32599d8fe734145cfd84098140b7287990183dde45ae2245b
system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	# Xác định kiến trúc CPU đích cho node-gyp
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	# 1) Cài đặt tất cả dependency – bỏ qua script
	NODE_ENV=development npm ci --ignore-scripts

	# 2) Xây dựng gói độc lập Next.js
	npm run build

	# 3) Sao chép tài nguyên tĩnh vào gói độc lập
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	# 4) Biên dịch liên kết native better-sqlite3
	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	# 5) Đặt liên kết đã biên dịch vào gói độc lập
	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	# 6) Xóa các gói sharp dành riêng cho từng kiến trúc
	rm -rf .next/standalone/node_modules/@img

	# 7) Sao chép các dependency runtime của pino bị quá trình phân tích tĩnh Next.js bỏ sót:
	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	# Ngăn hook sau cài đặt xóa các thư mục app router Next.js trống
	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
		touch "${DESTDIR}/usr/lib/omniroute/${_d}/.keep"
	done

#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"
mkdir -p "${DATA_DIR}"
exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```

| Biến                                    | Mặc định                             | Mô tả                                                                                                                              |
| --------------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| `JWT_SECRET`                            | `omniroute-default-secret-change-me` | Khóa bí mật dùng để ký JWT (**phải thay đổi trong môi trường production**)                                                         |
| `INITIAL_PASSWORD`                      | `CHANGEME`                           | Mật khẩu đăng nhập lần đầu                                                                                                         |
| `DATA_DIR`                              | `~/.omniroute`                       | Thư mục dữ liệu (cơ sở dữ liệu, mức sử dụng, nhật ký)                                                                              |
| `PORT`                                  | mặc định của framework               | Cổng dịch vụ (`20128` trong các ví dụ)                                                                                             |
| `HOSTNAME`                              | mặc định của framework               | Máy chủ để liên kết (Docker mặc định là `0.0.0.0`)                                                                                 |
| `NODE_ENV`                              | mặc định của runtime                 | Đặt thành `production` khi triển khai                                                                                              |
| `NEXT_PUBLIC_BASE_URL`                  | `http://localhost:20128`             | URL cơ sở công khai được cung cấp cho bảng điều khiển và máy chủ (thay thế `BASE_URL` cũ)                                          |
| `NEXT_PUBLIC_CLOUD_URL`                 | `https://omniroute.dev`              | URL cơ sở của điểm cuối đồng bộ đám mây (thay thế `CLOUD_URL` cũ)                                                                  |
| `API_KEY_SECRET`                        | `endpoint-proxy-api-key-secret`      | Khóa bí mật HMAC dành cho các khóa API được tạo                                                                                    |
| `REQUIRE_API_KEY`                       | `false`                              | Bắt buộc sử dụng khóa API Bearer trên `/v1/*`                                                                                      |
| `ALLOW_API_KEY_REVEAL`                  | `false`                              | Cho phép người dùng bảng điều khiển đã xác thực xem toàn bộ giá trị khóa API được lưu trữ khi có yêu cầu                           |

| `AUTH_COOKIE_SECURE`                    | `false`                              | Bắt buộc cookie xác thực có thuộc tính `Secure` (khi đặt sau proxy ngược HTTPS)                                                    |
| `CLOUDFLARED_BIN`                       | chưa đặt                             | Sử dụng tệp nhị phân `cloudflared` hiện có thay vì tải xuống bản được quản lý                                                      |

### Mô hình tùy chỉnh

Thêm bất kỳ ID mô hình nào vào bất kỳ nhà cung cấp nào mà không cần chờ cập nhật ứng dụng:

```bash
# Qua API
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# Liệt kê: curl http://localhost:20128/api/provider-models?provider=openai
# Xóa: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

Hoặc sử dụng Bảng điều khiển: **Nhà cung cấp → [Nhà cung cấp] → Mô hình tùy chỉnh**.

Lưu ý:

- Các nhà cung cấp tương thích với OpenRouter và OpenAI/Anthropic chỉ được quản lý từ **Mô hình có sẵn**. Việc thêm thủ công, nhập và tự động đồng bộ đều đưa mô hình vào cùng một danh sách mô hình có sẵn, vì vậy không có phần Mô hình tùy chỉnh riêng cho các nhà cung cấp đó.
- Phần **Mô hình tùy chỉnh** dành cho các nhà cung cấp không hỗ trợ nhập mô hình có sẵn được quản lý.

### Kết nối chuỗi các nút ngang hàng OmniRoute

Có thể thêm một cổng OmniRoute khác làm nhà cung cấp **Tùy chỉnh tương thích với OpenAI**. Sử dụng URL cơ sở `/v1` của
nút ngang hàng và một khóa API chuyên dụng với đặc quyền tối thiểu do nút ngang hàng đó cấp.

Đối với các chuỗi hai chiều hoặc nhiều chặng, hãy bật cơ chế bảo vệ vòng lặp tùy chọn trên mọi cổng:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

Chỉ các yêu cầu được gửi đến URL nút ngang hàng nằm trong danh sách cho phép rõ ràng mới nhận được
header `X-OmniRoute-Peer-Trace`. Cổng sẽ từ chối ID phiên bản bị lặp lại hoặc khi ngân sách số chặng
đã cạn bằng HTTP `508 Loop Detected`; các nhà cung cấp thượng nguồn thông thường không nhận được siêu dữ liệu về nút ngang hàng.

Kết nối chuỗi nút ngang hàng không phải là sao chép cơ sở dữ liệu hay chuyển đổi dự phòng máy chủ. Mỗi cổng duy trì độc lập
trạng thái SQLite, bộ nhớ đệm, bộ đếm giới hạn tốc độ và phiên. Hãy sử dụng reverse proxy có kiểm tra tình trạng hoặc cơ chế
chuyển đổi dự phòng phía máy khách để đạt khả năng sẵn sàng chủ động/thụ động hoặc chủ động/chủ động, và tuyệt đối không gắn một cơ sở dữ liệu SQLite
vào nhiều phiên bản OmniRoute đang chạy.

### Cấu hình proxy mạng

```bash
# Thiết lập proxy toàn cục
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"global": {"type":"http","host":"proxy.example.com","port":"8080"}}'

# Proxy theo từng nhà cung cấp
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"providers": {"openai": {"type":"socks5","host":"proxy.example.com","port":"1080"}}}'

# Kiểm tra proxy
curl -X POST http://localhost:20128/api/settings/proxy/test \
  -d '{"proxy":{"type":"socks5","host":"proxy.example.com","port":"1080"}}'
```

**Thứ tự ưu tiên:** Theo khóa → Theo tổ hợp → Theo nhà cung cấp → Toàn cục → Môi trường.

- Có sẵn trong **Bảng điều khiển → Điểm cuối** dành cho Docker và các bản triển khai tự lưu trữ khác
- Tạo URL `https://*.trycloudflare.com` tạm thời chuyển tiếp đến điểm cuối `/v1` hiện tại tương thích với OpenAI
- Lần bật đầu tiên chỉ cài đặt `cloudflared` khi cần; các lần khởi động lại sau sẽ tái sử dụng cùng tệp nhị phân được quản lý
- Quick Tunnel không tự động được khôi phục sau khi OmniRoute hoặc container khởi động lại; hãy bật lại từ bảng điều khiển khi cần
- URL đường hầm là tạm thời và thay đổi mỗi khi bạn dừng/khởi động đường hầm
- Quick Tunnel được quản lý mặc định sử dụng giao thức truyền tải HTTP/2 để tránh các cảnh báo ồn ào về bộ đệm UDP của QUIC trong những container bị giới hạn tài nguyên

- Đặt `CLOUDFLARED_BIN` nếu bạn muốn sử dụng tệp nhị phân `cloudflared` được cài đặt sẵn thay vì bản tải xuống được quản lý
- Có thể hiển thị hoặc ẩn các bảng Cloudflare Quick Tunnel, Tailscale Funnel và ngrok Tunnel trong **Cài đặt → Giao diện**. Việc ẩn một bảng không dừng đường hầm đang chạy.

### Chiến lược định tuyến

Cấu hình qua **Bảng điều khiển → Cài đặt → Định tuyến**. Bảng điều khiển hiển thị sáu chiến lược được sử dụng nhiều nhất; các tổ hợp và bộ định tuyến tự động hỗ trợ nội bộ một tập hợp rộng hơn.

**Các chiến lược hiển thị trên bảng điều khiển (định tuyến cấp tài khoản):**

| Chiến lược                          | Mô tả                                                                                                                        |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **Ưu tiên tài khoản đầu tiên**      | Sử dụng các tài khoản theo thứ tự ưu tiên — tài khoản chính xử lý tất cả yêu cầu cho đến khi không khả dụng                  |
| **Luân phiên**                      | Luân chuyển qua tất cả tài khoản với giới hạn bám dính có thể cấu hình (mặc định: 3 lượt gọi cho mỗi tài khoản)              |
| **P2C (Sức mạnh của hai lựa chọn)** | Chọn ngẫu nhiên 2 tài khoản và định tuyến đến tài khoản có trạng thái tốt hơn — cân bằng tải có xét đến tình trạng hoạt động |
| **Ngẫu nhiên**                      | Chọn ngẫu nhiên một tài khoản cho mỗi yêu cầu bằng thuật toán xáo trộn Fisher-Yates                                          |
| **Ít được sử dụng nhất**            | Định tuyến đến tài khoản có dấu thời gian `lastUsedAt` cũ nhất, giúp phân phối lưu lượng đồng đều                            |
| **Tối ưu hóa chi phí**              | Định tuyến đến tài khoản có giá trị ưu tiên thấp nhất, tối ưu hóa cho các nhà cung cấp có chi phí thấp nhất                  |

**Các chiến lược tổ hợp nâng cao và tự động** (có thể cấu hình cho từng tổ hợp hoặc qua tiền tố `auto/*` — xem [AUTO-COMBO.md](../routing/AUTO-COMBO.md)):

- `priority` — thứ tự nghiêm ngặt, không bao giờ luân phiên
- `weighted` — phân chia lưu lượng theo tỷ lệ dựa trên trọng số của từng mô hình
- `fill-first` — sử dụng hết mô hình đầu tiên cho đến khi đạt giới hạn
- `round-robin` / `strict-random` / `random`
- `p2c` (Sức mạnh của hai lựa chọn)
- `least-used` và `cost-optimized`
- `auto` — định tuyến dựa trên điểm số giữa tất cả ứng viên
- `lkgp` (Nhà cung cấp hoạt động tốt gần nhất) — cố định vào nhà cung cấp thành công gần nhất, sau đó chuyển về các quy tắc dự phòng
- `context-optimized` — chọn mô hình có cửa sổ ngữ cảnh còn trống lớn nhất
- `context-relay` — kết nối chuỗi các mô hình có ngữ cảnh dài cho những lượt trao đổi tiếp theo

```http
X-Session-Id: your-session-key
```

OmniRoute cũng chấp nhận `x_session_id` và trả về khóa phiên thực tế trong `X-OmniRoute-Session-Id`.

Nếu bạn sử dụng Nginx và gửi các header có dạng dấu gạch dưới, hãy bật:

```nginx
underscores_in_headers on;
```

#### Bí danh mô hình có ký tự đại diện

Tạo các mẫu ký tự đại diện để ánh xạ lại tên mô hình:

```
Mẫu: claude-sonnet-*     →  Đích: cc/claude-sonnet-4-6
Mẫu: gpt-*               →  Đích: gh/gpt-5.3-codex
```

Ký tự đại diện hỗ trợ `*` (bất kỳ chuỗi ký tự nào) và `?` (một ký tự duy nhất).

#### Chuỗi dự phòng

Xác định các chuỗi dự phòng toàn cục áp dụng cho tất cả yêu cầu:

```
Chuỗi: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### Khả năng phục hồi & Bộ ngắt mạch

Cấu hình qua **Bảng điều khiển → Cài đặt → Khả năng phục hồi**.

OmniRoute triển khai khả năng phục hồi cấp nhà cung cấp với năm thành phần:

1. **Hàng đợi yêu cầu & Điều tiết nhịp độ** — Điều tiết yêu cầu ở cấp hệ thống:
   - **Số yêu cầu mỗi phút (RPM)** — Số yêu cầu tối đa mỗi phút cho mỗi tài khoản
   - **Thời gian tối thiểu giữa các yêu cầu** — Khoảng cách tối thiểu tính bằng mili giây giữa các yêu cầu
   - **Số yêu cầu đồng thời tối đa** — Số yêu cầu đồng thời tối đa cho mỗi tài khoản

2. **Thời gian chờ kết nối** — Cấu hình theo từng loại xác thực cho một kết nối sau các lỗi có thể thử lại:
   - **Thời gian chờ cơ sở** — Khoảng thời gian chờ mặc định cho các lỗi từ dịch vụ ngược dòng có thể thử lại
   - **Sử dụng gợi ý thử lại từ dịch vụ ngược dòng** — Tuân thủ `Retry-After` có thẩm quyền hoặc các gợi ý đặt lại khi được cung cấp
   - **Số bước tăng thời gian chờ tối đa** — Mức tăng thời gian chờ theo cấp số nhân tối đa cho các lỗi lặp lại

3. **Bộ ngắt mạch nhà cung cấp** — Theo dõi các lỗi đầu cuối của nhà cung cấp, đánh dấu nhà cung cấp là suy giảm khi đạt ngưỡng cảnh báo đã cấu hình và mở bộ ngắt mạch khi đạt ngưỡng lỗi đã cấu hình:
   - **Ngưỡng suy giảm** — Số lỗi liên tiếp của nhà cung cấp trước khi chuyển sang `DEGRADED`
   - **Ngưỡng lỗi** — Số lỗi liên tiếp của nhà cung cấp trước khi chuyển sang `OPEN`
   - **Thời gian chờ đặt lại** — Khoảng thời gian trước khi nhà cung cấp được kiểm tra lại
   - **CLOSED** (Hoạt động tốt) — Các yêu cầu được xử lý bình thường
   - **DEGRADED** — Các yêu cầu vẫn được xử lý trong khi hệ thống theo dõi mức lỗi gia tăng
   - **OPEN** — Nhà cung cấp tạm thời bị chặn sau khi xảy ra lỗi lặp lại
   - **HALF_OPEN** — Kiểm tra xem nhà cung cấp đã phục hồi hay chưa

   Các giới hạn tốc độ `429` trong phạm vi kết nối vẫn nằm trong **Thời gian chờ kết nối** và không được tính vào bộ ngắt mạch nhà cung cấp.

   Trạng thái thời gian chạy của bộ ngắt mạch nhà cung cấp chỉ được hiển thị tại **Bảng điều khiển → Tình trạng hoạt động**.

4. **Chờ hết thời gian tạm ngưng** — Nếu mọi kết nối ứng viên đều đang trong thời gian tạm ngưng, OmniRoute có thể chờ đến khi thời gian tạm ngưng sớm nhất kết thúc rồi tự động thử lại chính yêu cầu đó của máy khách.

5. **Tự động phát hiện giới hạn tốc độ** — Khi các nhà cung cấp ngược dòng trả về khoảng thời gian chờ rõ ràng, những gợi ý này sẽ ghi đè thời gian tạm ngưng kết nối cục bộ nếu cài đặt này được bật.

**Mẹo hữu ích:** Sử dụng trang **Tình trạng hoạt động** để kiểm tra và đặt lại các bộ ngắt mạch nhà cung cấp đang hoạt động sau sự cố gián đoạn. Trang Khả năng phục hồi chỉ thay đổi cấu hình.

### Xuất / Nhập cơ sở dữ liệu

Quản lý các bản sao lưu cơ sở dữ liệu tại **Bảng điều khiển → Cài đặt → Hệ thống & Lưu trữ**.

| Hành động                 | Mô tả                                                                                                                                                  |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Xuất cơ sở dữ liệu**    | Tải xuống cơ sở dữ liệu SQLite hiện tại dưới dạng tệp `.sqlite`                                                                                        |
| **Xuất tất cả (.tar.gz)** | Tải xuống kho lưu trữ sao lưu đầy đủ bao gồm: cơ sở dữ liệu, cài đặt, combo, kết nối nhà cung cấp (không có thông tin xác thực), siêu dữ liệu khóa API |
| **Nhập cơ sở dữ liệu**    | Tải lên tệp `.sqlite` để thay thế cơ sở dữ liệu hiện tại. Bản sao lưu trước khi nhập được tự động tạo trừ khi `DISABLE_SQLITE_AUTO_BACKUP=true`        |

```bash
# API: Xuất cơ sở dữ liệu
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: Xuất tất cả (kho lưu trữ đầy đủ)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: Nhập cơ sở dữ liệu
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**Xác thực dữ liệu nhập:** Tệp được nhập sẽ được xác thực về tính toàn vẹn (kiểm tra pragma của SQLite), các bảng bắt buộc (`provider_connections`, `provider_nodes`, `combos`, `api_keys`) và kích thước (tối đa 100MB).

**Trường hợp sử dụng:**

- Di chuyển OmniRoute giữa các máy
- Tạo bản sao lưu bên ngoài để khôi phục sau thảm họa
- Chia sẻ cấu hình giữa các thành viên trong nhóm (xuất tất cả → chia sẻ kho lưu trữ)

### Chiến lược cân bằng combo

Cấu hình cân bằng cho từng combo trong **Bảng điều khiển → Combo → Tạo/Chỉnh sửa → Chiến lược**.

| Chiến lược         | Mô tả                                                                          |
| ------------------ | ------------------------------------------------------------------------------ |
| **Luân phiên**     | Lần lượt xoay vòng qua các mô hình                                             |
| **Ưu tiên**        | Luôn thử mô hình đầu tiên; chỉ chuyển sang mô hình dự phòng khi xảy ra lỗi     |
| **Ngẫu nhiên**     | Chọn một mô hình ngẫu nhiên từ tổ hợp cho mỗi yêu cầu                          |
| **Theo trọng số**  | Định tuyến theo tỷ lệ dựa trên trọng số được gán cho từng mô hình              |
| **Ít dùng nhất**   | Định tuyến đến mô hình có ít yêu cầu gần đây nhất (sử dụng số liệu của tổ hợp) |
| **Tối ưu chi phí** | Định tuyến đến mô hình khả dụng có chi phí thấp nhất (sử dụng bảng giá)        |

Có thể đặt các giá trị mặc định chung cho tổ hợp tại **Bảng điều khiển → Cài đặt → Định tuyến → Mặc định của tổ hợp**.
Theo mặc định, thời gian chờ của mục tiêu trong tổ hợp kế thừa thời gian chờ của yêu cầu hiện tại. Chỉ sử dụng **Thời gian chờ của mục tiêu
(giây)** trong phần mặc định của tổ hợp hoặc cho một tổ hợp riêng lẻ khi cần giới hạn ngắn hơn cho từng mục tiêu để
kích hoạt chuyển sang phương án dự phòng nhanh hơn.

Các tối ưu hóa tổ hợp không độ trễ là tính năng tùy chọn. Hãy để **Tối ưu hóa không độ trễ** ở trạng thái tắt để
ngăn các tính năng độ trễ này chạy đua giữa các mục tiêu dự phòng, bỏ qua mục tiêu dựa trên lịch sử
TTFT hoặc nén các yêu cầu dự phòng; khi bật, tính năng này cho phép phòng ngừa theo cấu hình, bỏ qua dựa trên dự đoán TTFT
và chủ động nén phương án dự phòng để đánh đổi độ trung thực của việc định tuyến/yêu cầu lấy độ trễ phần đuôi
thấp hơn.

Tắt **Bộ đệm token suy luận** khi các nhà cung cấp thượng nguồn yêu cầu giới hạn nghiêm ngặt đối với
`max_tokens` / `maxOutputTokens`. Khi được bật, định tuyến tổ hợp chỉ bổ sung dung lượng dự phòng cho mô hình suy luận
đối với các mô hình có giới hạn đầu ra đã biết và giữ nguyên giới hạn token của máy khách khi giá trị an toàn sau khi thêm bộ đệm
vượt quá giới hạn đó. Nếu giới hạn của máy khách đã cao hơn một giới hạn đã biết,
OmniRoute sẽ giảm giới hạn đó xuống mức trần trước khi gửi yêu cầu lên thượng nguồn.

## 🤖 Tự động định tuyến (Không cần cấu hình)

OmniRoute tích hợp sẵn một **bộ tự động định tuyến dựa trên điểm số**, giúp chọn mô hình tốt nhất cho từng yêu cầu trên tất cả các nhà cung cấp đã kết nối — không cần duy trì tổ hợp nào. Chỉ cần gửi yêu cầu với một trong các tiền tố `auto/*`, OmniRoute sẽ tự động tạo một tổ hợp ảo, chấm điểm các ứng viên dựa trên độ trễ, chi phí, tỷ lệ thành công, mức độ phù hợp với ngữ cảnh, mức độ phù hợp của mô hình với tác vụ, các lỗi gần đây, hạn ngạch và trạng thái bộ ngắt mạch.

| Tiền tố        | Tiêu chí tối ưu hóa                                                                                          |
| -------------- | ------------------------------------------------------------------------------------------------------------ |
| `auto`         | Mặc định cân bằng (độ trễ × chi phí × tỷ lệ thành công)                                                      |
| `auto/coding`  | Tác vụ lập trình: ưu tiên Claude, GPT-5, GLM, Kimi, Qwen Coder, các mô hình lập trình DeepSeek               |
| `auto/cheap`   | Chi phí $/token thấp nhất, chấp nhận độ trễ cao hơn                                                          |
| `auto/fast`    | Độ trễ thấp nhất, bỏ qua chi phí                                                                             |
| `auto/offline` | Chỉ dùng nhà cung cấp cục bộ (Ollama, vLLM, llama.cpp) — hữu ích cho các hệ thống cách ly mạng               |
| `auto/smart`   | Ưu tiên chất lượng suy luận (Opus, GPT-5 xhigh, R1, suy luận GLM 5.1)                                        |
| `auto/lkgp`    | "Nhà cung cấp tốt gần nhất" — cố định vào nhà cung cấp thành công gần nhất, sau đó dự phòng theo các quy tắc |

Ví dụ:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
```

## 🔌 Tích hợp MCP & A2A

OmniRoute vừa là một **máy chủ MCP** (Giao thức Ngữ cảnh Mô hình), vừa là một **máy chủ A2A** (JSON-RPC 2.0 từ tác nhân đến tác nhân). Mọi IDE hoặc máy chủ tác nhân tương thích với MCP đều có thể gọi trực tiếp các công cụ OmniRoute — không cần lớp bao bọc bổ sung.

### Các phương thức truyền tải MCP

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **HTTP có thể phát luồng**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (dành cho các plugin IDE ưu tiên stdio)

### Kết nối Claude Desktop

Chỉnh sửa `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) hoặc tệp tương đương trên Windows/Linux:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### Kết nối Cursor / Continue / VS Code MCP

Sử dụng URL SSE `http://localhost:20128/api/mcp/sse` và khóa API Bearer được tạo trong **Bảng điều khiển → Khóa API**.

### Phạm vi

MCP hiện định nghĩa 32 phạm vi có tên. Mỗi khóa Bearer có thể được giới hạn ở các phạm vi cụ thể — xem [MCP-SERVER.md](../frameworks/MCP-SERVER.md) để biết danh sách phạm vi và công cụ chính thức, cũng như [A2A-SERVER.md](../frameworks/A2A-SERVER.md) để biết lược đồ JSON-RPC.

## 💾 Hệ thống bộ nhớ

OmniRoute lưu trữ **bộ nhớ hội thoại dài hạn** bằng cơ chế truy xuất kết hợp:

- **SQLite FTS5** để tìm kiếm từ khóa trong các lượt hội thoại trước đây
- **Kho vector Qdrant** (tùy chọn) để truy hồi theo ngữ nghĩa
- **Tự động trích xuất dữ kiện** — các thực thể, tùy chọn và quyết định được tóm tắt sau mỗi phiên rồi lưu vào bảng `memory_facts`
- Bộ nhớ được phân tách theo từng API key và từng phiên

Quản lý bộ nhớ trong **Dashboard → Memory** (tìm kiếm, chỉnh sửa, xuất, xóa sạch). Giao diện HTTP (`/api/memory/*`) cho phép các agent gửi và truy vấn dữ kiện theo chương trình — xem [MEMORY.md](../frameworks/MEMORY.md).

## 🔔 Webhook

Đăng ký nhận các sự kiện OmniRoute để giám sát và tự động hóa theo thời gian thực.

- Tạo webhook trong **Dashboard → Webhooks** với URL đích và khóa bí mật ký HMAC
- Các sự kiện khả dụng: `request.completed`, `request.failed`, `provider.unavailable`, `budget.exceeded`, `combo.switched`, `circuit_breaker.opened`, `circuit_breaker.closed`
- Mỗi payload đều bao gồm `X-OmniRoute-Signature` (HMAC-SHA256) để xác minh
- Thử lại: 3 lần với thời gian chờ tăng theo cấp số nhân, sau đó chuyển vào hàng đợi thư lỗi

Schema đầy đủ có trong [WEBHOOKS.md](../frameworks/WEBHOOKS.md).

## 🛠️ Quản lý theo chương trình

Bạn có thể quản lý mọi tài nguyên OmniRoute (nhà cung cấp, combo, khóa, cài đặt) qua HTTP bằng **khóa Bearer có phạm vi `manage`**.

Tạo khóa trong **Dashboard → API Keys → New Key → Scope: manage**, sau đó:

```bash
# Liệt kê các nhà cung cấp
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# Thêm kết nối nhà cung cấp
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# Tạo combo
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# Liệt kê/tạo API key
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

Xem [API_REFERENCE.md](../reference/API_REFERENCE.md) để biết danh mục endpoint đầy đủ cùng các schema yêu cầu/phản hồi.

## 💻 CLI nội bộ

OmniRoute cung cấp một CLI nội bộ (`omniroute …`) để thiết lập, chẩn đoán và kiểm soát thời gian chạy. CLI này **tách biệt với trang "Công cụ CLI" trong bảng điều khiển**, nơi cấu hình các CLI của bên thứ ba (Claude Code, Cursor, Codex, Cline, …) để chúng có thể giao tiếp với OmniRoute.

```bash
omniroute setup                    # Trình hướng dẫn tương tác (mật khẩu, nhà cung cấp, tổ hợp)
omniroute setup --non-interactive  # Phù hợp với CI
omniroute doctor                   # Chẩn đoán tình trạng (thư mục dữ liệu, DB, nhà cung cấp, cổng)
omniroute providers available      # Liệt kê các nhà cung cấp được hỗ trợ
omniroute providers list           # Liệt kê các kết nối đã cấu hình
omniroute providers test <id>      # Kiểm tra trực tiếp kết nối với nhà cung cấp
omniroute combos list              # Liệt kê các tổ hợp
omniroute combos switch <name>     # Đặt tổ hợp mặc định
omniroute models                   # Liệt kê các mô hình khả dụng (--json, --search)
omniroute keys add | list | remove # Quản lý khóa API từ terminal
omniroute backup                   # Tạo bản chụp nhanh cấu hình + DB
omniroute restore [<timestamp>]    # Khôi phục từ bản chụp nhanh
omniroute health                   # Tình trạng chi tiết (bộ ngắt mạch, bộ nhớ đệm, bộ nhớ)
omniroute quota                    # Mức sử dụng hạn ngạch của nhà cung cấp
omniroute mcp status               # Trạng thái máy chủ MCP
omniroute a2a status               # Trạng thái máy chủ A2A
omniroute tunnel list|create|stop  # Đường hầm Cloudflare/Tailscale/ngrok
omniroute reset-password           # Đặt lại mật khẩu quản trị viên
omniroute --mcp                    # Khởi động máy chủ MCP qua stdio
omniroute --port 3000              # Khởi động máy chủ trên một cổng tùy chỉnh
```

Mẹo: kết hợp `omniroute doctor --json` với công cụ giám sát của bạn để cảnh báo khi kết nối với nhà cung cấp gặp sự cố.

## 🖥️ Ứng dụng máy tính (Electron)

OmniRoute có sẵn dưới dạng ứng dụng máy tính gốc dành cho Windows, macOS và Linux.

### Cài đặt

```bash
# Từ thư mục electron:
cd electron
npm install

# Chế độ phát triển (kết nối với máy chủ phát triển Next.js đang chạy):
npm run dev

# Chế độ sản xuất (sử dụng bản dựng độc lập):
npm start
```

### Tạo bộ cài đặt

```bash
cd electron
npm run build          # Nền tảng hiện tại
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg universal)
npm run build:linux    # Linux (.AppImage)
```

Đầu ra → `electron/dist-electron/`

### Các tính năng chính

| Tính năng                       | Mô tả                                                               |
| ------------------------------- | ------------------------------------------------------------------- |
| **Mức độ sẵn sàng của máy chủ** | Thăm dò máy chủ trước khi hiển thị cửa sổ (không có màn hình trống) |
| **Khay hệ thống**               | Thu nhỏ vào khay, thay đổi cổng, thoát từ menu khay                 |
| **Quản lý cổng**                | Thay đổi cổng máy chủ từ khay (tự động khởi động lại máy chủ)       |
| **Chính sách bảo mật nội dung** | CSP hạn chế thông qua các tiêu đề phiên                             |
| **Một phiên bản duy nhất**      | Mỗi lần chỉ có thể chạy một phiên bản ứng dụng                      |
| **Chế độ ngoại tuyến**          | Máy chủ Next.js đi kèm hoạt động mà không cần internet              |

### Biến môi trường

| Biến                  | Mặc định | Mô tả                                   |
| --------------------- | -------- | --------------------------------------- |
| `OMNIROUTE_PORT`      | `20128`  | Cổng máy chủ                            |
| `OMNIROUTE_MEMORY_MB` | `512`    | Giới hạn heap của Node.js (64–16384 MB) |
