> **Nguồn chính xác:** `src/lib/obsidian/api.ts` (REST + ứng dụng khách đồng bộ),
> `src/lib/db/obsidian.ts` (lưu trữ token / URL cơ sở / WebDAV),
> `src/lib/obsidianSync.ts` (đồng bộ kho ghi chú WebDAV), `open-sse/mcp-server/tools/obsidianTools.ts`
> (22 công cụ MCP), `src/app/api/settings/obsidian/route.ts` +
> `src/app/api/settings/obsidian/webdav/route.ts` (các API cài đặt). Việc đăng ký công cụ
> và nối kết phạm vi nằm trong `open-sse/mcp-server/server.ts`.

## Đây là gì

OmniRoute kết nối với một kho ghi chú **Obsidian** dưới dạng **nguồn ngữ cảnh** — một cơ sở
tri thức Markdown cục bộ mà các tác nhân đọc và ghi thông qua máy chủ MCP tích hợp sẵn.
Tích hợp này giao tiếp với plugin cộng đồng **Obsidian Local REST API** đang chạy bên trong
ứng dụng máy tính, nhờ đó các tác nhân có thể tìm kiếm ghi chú, đọc/ghi/vá tệp, liệt kê kho
ghi chú, làm việc với ghi chú định kỳ hằng ngày/hằng tuần, quản lý thẻ, chạy các lệnh
Obsidian và (tùy chọn) điều phối quá trình đồng bộ kho ghi chú hai chiều giữa máy tính↔di động.

Ứng dụng khách (`src/lib/obsidian/api.ts`) bao bọc Local REST API với:

- **Thử lại với thời gian chờ tăng dần** cho các lỗi `5xx` tạm thời, **thời gian chờ 30 giây** thông qua `AbortController`.
- **Phân loại lỗi có kiểu** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- Một **gợi ý thân thiện "không thể kết nối tới Obsidian"** nêu rõ lỗi cổng phổ biến
  (HTTP trên `27123`, **không phải** điểm cuối MCP trên `27124`) và dạng địa chỉ Tailscale.
- **Mã hóa đường dẫn** tương đối với kho ghi chú để các đường dẫn ghi chú có dấu cách/dấu gạch chéo được xử lý an toàn.

## Thiết lập

**Không có biến môi trường** cho token hoặc URL cơ sở của Obsidian — cả hai đều được
lưu trong bảng SQLite `key_value` (không gian tên `obsidian`) thông qua
`src/lib/db/obsidian.ts`. Token được **mã hóa khi lưu trữ** (AES-256-GCM, với cơ chế
dự phòng tương thích ngược bằng văn bản thuần). Hãy cấu hình từ tab **Nguồn ngữ cảnh** của
bảng điều khiển Điểm cuối (`ObsidianSourceCard`), hoặc thông qua API REST cài đặt.

> [!IMPORTANT]
> Plugin **Obsidian Local REST API** phải được cài đặt và đang chạy. Giao diện REST của
> plugin lắng nghe trên **HTTP `127.0.0.1:27123`** (URL cơ sở mặc định). Cổng `27124`
> là một điểm cuối MCP/HTTPS _riêng biệt_ và bị tuyến cài đặt từ chối rõ ràng.
> Nếu kết nối từ một thiết bị khác, hãy dùng `http://<tailscale-ip>:27123`.

### Các khóa cấu hình (SQLite `key_value`, không gian tên `obsidian`)

| Khóa              | Mục đích                                                 | Được mã hóa |
| ----------------- | -------------------------------------------------------- | ----------- |
| `api_key`         | Token mang xác thực của Local REST API                   | có          |
| `base_url`        | URL cơ sở REST (mặc định `http://127.0.0.1:27123`)       | không       |
| `vault_path`      | Đường dẫn tuyệt đối tới thư mục kho ghi chú (để đồng bộ) | không       |
| `webdav_username` | Tên người dùng WebDAV được tạo (đồng bộ kho ghi chú)     | không       |
| `webdav_password` | Mật khẩu WebDAV được tạo (đồng bộ kho ghi chú)           | có          |
| `webdav_enabled`  | Liệu đồng bộ kho ghi chú WebDAV có được bật hay không    | không       |

### Cấu hình qua REST

```bash
# Lưu + xác thực token Local REST API (POST xác thực thông qua kiểm tra trạng thái)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Kiểm tra trạng thái kết nối (trả về connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# Ngắt kết nối (xóa token đã lưu)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Tất cả phương thức đều yêu cầu xác thực bảng điều khiển. `POST` từ chối mọi URL trên cổng
`27124` và xác thực token bằng cách gọi điểm cuối trạng thái của Local REST API trước khi lưu.

### Đồng bộ kho ghi chú WebDAV

`src/app/api/settings/obsidian/webdav/route.ts` quản lý tính năng đồng bộ kho ghi chú
dựa trên WebDAV (do `src/lib/obsidianSync.ts` điều khiển). Khi bật, tính năng này trỏ
OmniRoute tới một thư mục kho ghi chú cục bộ và tạo một cặp tên người dùng/mật khẩu
WebDAV ngẫu nhiên:

```bash
# Bật đồng bộ WebDAV cho một thư mục kho ghi chú (tạo tên người dùng/mật khẩu)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# Lấy trạng thái đồng bộ WebDAV (thông tin xác thực chỉ được trả về khi đang bật)
curl http://localhost:20128/api/settings/obsidian/webdav

# Tắt đồng bộ WebDAV (xóa thông tin xác thực + .stignore được quản lý)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Nguồn ngữ cảnh theo từng khóa API (tùy chọn)

Cấu hình Obsidian có thể được đặt phạm vi **theo từng khóa API** thông qua bảng
`api_key_context_sources` (`src/lib/db/apiKeyContextSources.ts`). Khi một lệnh gọi MCP
mang id khóa API đã được xác thực, `getObsidianConfigForApiKey()` ưu tiên
token/URL cơ sở/đường dẫn kho ghi chú riêng của khóa đó (`source: "api_key"`) và nếu không
có thì dùng cấu hình toàn cục làm phương án dự phòng (`source: "global"`).

## Công cụ MCP (22)

Được định nghĩa trong `open-sse/mcp-server/tools/obsidianTools.ts`. Token/base-URL được phân giải
cho từng lệnh gọi (ưu tiên theo API key, sau đó mới đến cấu hình toàn cục). Các công cụ truy cập **máy chủ đồng bộ**
OmniRoute (bốn công cụ `obsidian_sync_*`) còn yêu cầu token xác thực đồng bộ được cấu hình
trong phần cài đặt OmniRoute.

### Công cụ đọc (`read:obsidian`)

| Công cụ                      | Mô tả                                                                                                        |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `obsidian_check_status`      | Kiểm tra xem Local REST API có thể truy cập được và đã xác thực hay chưa.                                    |
| `obsidian_search_simple`     | Tìm kiếm toàn văn trong nội dung ghi chú; trả về các đoạn trích kèm đường dẫn tệp.                           |
| `obsidian_search_structured` | Tìm kiếm bằng biểu thức JSON Logic (các bộ lọc and/or/regex/path).                                           |
| `obsidian_read_note`         | Đọc ghi chú theo đường dẫn tương đối với vault; có thể chỉ định heading/block/frontmatter cụ thể.            |
| `obsidian_list_vault`        | Liệt kê các tệp và thư mục trong vault (dạng cây mục nhập).                                                  |
| `obsidian_get_document_map`  | Lấy cấu trúc heading của ghi chú dưới dạng ánh xạ heading → số dòng.                                         |
| `obsidian_get_note_metadata` | Lấy frontmatter, thẻ, liên kết và số ký tự/từ mà không cần toàn bộ nội dung.                                 |
| `obsidian_get_active_file`   | Lấy đường dẫn + nội dung của tệp hiện đang hoạt động trong Obsidian.                                         |
| `obsidian_get_periodic_note` | Lấy ghi chú định kỳ hằng ngày/hằng tuần/hằng tháng cho một ngày (mặc định là hôm nay nếu bỏ qua).            |
| `obsidian_get_tags`          | Liệt kê tất cả thẻ trong vault cùng tần suất xuất hiện.                                                      |
| `obsidian_list_commands`     | Liệt kê các ID lệnh Obsidian hiện có (dùng với `obsidian_execute_command`).                                  |
| `obsidian_sync_status`       | Trạng thái máy chủ đồng bộ OmniRoute: đang chạy, tên vault, cổng, thời gian hoạt động, lần đồng bộ gần nhất. |
| `obsidian_sync_conflicts`    | Liệt kê các xung đột đồng bộ chưa được giải quyết (đường dẫn, đường dẫn xung đột, thời điểm phát hiện).      |

### Công cụ ghi (`write:obsidian`)

| Công cụ                          | Mô tả                                                                                              |
| -------------------------------- | -------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Tạo hoặc ghi đè một ghi chú bằng nội dung Markdown được cung cấp.                                  |
| `obsidian_append_note`           | Nối thêm nội dung vào ghi chú; có thể chỉ định một heading/block cụ thể.                           |
| `obsidian_patch_note`            | Nối thêm/chèn trước/thay thế chính xác tại một heading, block hoặc trường frontmatter.             |
| `obsidian_delete_note`           | Xóa vĩnh viễn một ghi chú khỏi vault.                                                              |
| `obsidian_move_note`             | Di chuyển hoặc đổi tên một ghi chú trong vault.                                                    |
| `obsidian_execute_command`       | Thực thi một lệnh Obsidian theo ID lệnh của lệnh đó.                                               |
| `obsidian_open_file`             | Mở một tệp trong Obsidian (tạo tệp nếu chưa tồn tại).                                              |
| `obsidian_sync_trigger`          | Kích hoạt ngay quá trình đồng bộ vault hai chiều giữa máy tính↔thiết bị di động.                   |
| `obsidian_sync_resolve_conflict` | Giải quyết xung đột đồng bộ: giữ `local` (thiết bị di động), `remote` (máy tính) hoặc `keep-both`. |

> [!NOTE]
> Các đích của `obsidian_patch_note` chấp nhận `targetType` là `heading | block | frontmatter`
> và `operation` là `append | prepend | replace`, cùng tùy chọn
> `createTargetIfMissing`. Bốn công cụ `obsidian_sync_*` giao tiếp với máy chủ đồng bộ cục bộ
> (`http://127.0.0.1:27781` theo mặc định) và yêu cầu token đồng bộ.

### Phạm vi quyền

Các công cụ đọc yêu cầu `read:obsidian`; các công cụ ghi yêu cầu `write:obsidian`. Cơ chế thực thi
giống hệt Notion — được xử lý bởi `withScopeEnforcement()` trong
`open-sse/mcp-server/server.ts`, được kiểm soát bởi `OMNIROUTE_MCP_ENFORCE_SCOPES=true`, với
các phạm vi được phép lấy từ `OMNIROUTE_MCP_SCOPES` hoặc ngữ cảnh phạm vi của API key. Xem
[MCP-SERVER.md](./MCP-SERVER.md).

## Điểm cuối

| Phương thức | Đường dẫn                       | Mục đích                                                       |
| ----------- | ------------------------------- | -------------------------------------------------------------- |
| `GET`       | `/api/settings/obsidian`        | Trả về `{ connected, hasToken, baseUrl, vaultPath }`.          |
| `POST`      | `/api/settings/obsidian`        | Lưu + xác thực token (từ chối cổng `27124`).                   |
| `DELETE`    | `/api/settings/obsidian`        | Ngắt kết nối (xóa token đã lưu).                               |
| `GET`       | `/api/settings/obsidian/webdav` | Trạng thái đồng bộ WebDAV + thông tin xác thực (khi được bật). |
| `POST`      | `/api/settings/obsidian/webdav` | Bật đồng bộ WebDAV cho một thư mục vault.                      |
| `DELETE`    | `/api/settings/obsidian/webdav` | Tắt đồng bộ WebDAV.                                            |

> Đây là các route cài đặt của dashboard. Bản thân vault được truy cập thông qua Obsidian
> Local REST API (`base_url` đã cấu hình) và thông qua các công cụ MCP ở trên — không có
> điểm cuối proxy Obsidian `/v1` công khai.

## Trường hợp sử dụng

- **Câu trả lời dựa trên vault** — `obsidian_search_simple` / `obsidian_search_structured`
  rồi đến `obsidian_read_note` để một tác tử trả lời dựa trên các ghi chú thực tế của bạn.
- **Soạn ghi chú / viết nhật ký** — `obsidian_write_note`, `obsidian_append_note`, hoặc
  `obsidian_patch_note` có khả năng chỉnh sửa chính xác để ghi đầu ra của tác tử, bản tóm tắt hoặc ghi chú hằng ngày
  (`obsidian_get_periodic_note`) vào vault.
- **Điều hướng vault** — `obsidian_list_vault`, `obsidian_get_document_map` và
  `obsidian_get_tags` để khám phá cấu trúc trước khi đọc/ghi.
- **Tự động hóa Obsidian** — `obsidian_list_commands` + `obsidian_execute_command` để
  điều khiển plugin/lệnh từ một tác tử; `obsidian_open_file` để hiển thị một ghi chú trong giao diện người dùng.
- **Đồng bộ di động** — bật đồng bộ WebDAV, sau đó dùng `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  để điều phối quá trình đồng bộ máy tính↔thiết bị di động và giải quyết xung đột.
