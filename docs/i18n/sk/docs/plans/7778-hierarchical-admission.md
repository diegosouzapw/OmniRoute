1. Zabezpečte existujúci kontrakt semafora s jedným kľúčom a nový atómový kontrakt s viacerými kľúčmi cielenými testami: žiadne čiastočné rezervácie, radenie FIFO, prerušenie, časový limit, plný rad, idempotentné uvoľnenie, štatistiky a čistenie.
2. Zovšeobecnite existujúci semafor účtov priamo na mieste. Zachovajte `acquire()` ako kompatibilný obal nad `acquireMany()`; nepridávajte druhý plánovač ani závislosť.
3. Nahraďte získavanie iba pre účet v `chatCore` jedným kumulatívnym získaním pre globálnu úroveň, poskytovateľa a účet bezprostredne pred `withRateLimit`. Vždy, keď rotácia účtu zmení pripojenie, znova získajte celú množinu a uvoľnenie odložte až do dokončenia streamovania.
4. Rozšírte existujúci proces spracovania nastavení odolnosti (typy, predvolené hodnoty, normalizáciu, schému, odpoveď API, používateľské rozhranie a preklady) o globálne limity a limity poskytovateľa. Premenujte staré riadenie súbežnosti Bottleneck na súbežnosť v rozsahu pripojenia/kvóty, aby bol jeho skutočný rozsah explicitný.
5. Spustite cielené testy, lint, kontrolu typov, statické kontroly a kompletnú testovaciu sadu; zdokumentujte zmenu správania v changelogu.

Zámerne zachované správanie: nulová hodnota alebo hodnota null pre súbežnosť obchádza bránu, volajúci pracujúci iba s účtom naďalej používajú `acquire()`, ovládacie prvky blokovaných účtov si zachovávajú formát kľúčov a API a správanie radu pri obmedzení rýchlosti poskytovateľa zostáva nezmenené.
