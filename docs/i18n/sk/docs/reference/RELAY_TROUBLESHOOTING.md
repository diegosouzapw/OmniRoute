Relé (Vercel, Deno, Cloudflare) ukončujú upstreamové pripojenie na
bezserverovom backende, takže OmniRoute môže odosielať prevádzku zo stabilného regiónu, pričom
API kľúč poskytovateľa zostáva na strane servera. Tento dokument opisuje dva režimy zlyhania,
s ktorými sa operátori stretávajú v produkcii, a postupy obnovy, ktoré OmniRoute poskytuje
pre každý z nich.

## Ako sa ukladá autentifikácia relé

Keď nasadíte relé cez **Nastavenia → Fond proxy → Nasadiť relé**,
proces nasadenia uloží autentifikačný token relé do JSON poľa `notes` proxy:

- Ak je nastavená premenná `STORAGE_ENCRYPTION_KEY`, token sa uloží ako `relayAuthEnc`
  (v úložisku zašifrovaný pomocou AES).
- V opačnom prípade sa uloží ako nešifrovaný text `relayAuth`.

Pri spracovaní požiadavky funkcia `extractRelayAuth(notes)` vráti tú formu, ktorá je dostupná,
takže relé zostane funkčné aj po reštartoch.

## Režim zlyhania 1 — token sa po rotácii kľúča nedá dešifrovať

**Príznak:** relé, ktoré predtým fungovali, teraz vracajú upstreamové chyby
`401`/chyby autentifikácie po rotácii premennej
`STORAGE_ENCRYPTION_KEY` v prostredí alebo správcovi tajomstiev. Uložený blok `relayAuthEnc`
už nie je možné dešifrovať, takže `extractRelayAuth` vráti prázdny reťazec a relé
neodošle žiadne autentifikačné údaje.

**Obnova — oprava na mieste (bez opätovného nasadenia):**

1. Otvorte **Nastavenia → Fond proxy**.
2. Riadky relé s chýbajúcimi autentifikačnými údajmi zobrazujú žltý odznak `chýbajúca autentifikácia` a
   tlačidlo **Opraviť**.
3. Kliknite na **Opraviť**. OmniRoute zavolá
   `POST /api/settings/proxies/[id]/repair-relay`, ktorý:
   - dešifruje `relayAuthEnc` pomocou **aktuálneho** kľúča,
   - zapíše nešifrovanú hodnotu `relayAuth` späť do `notes`,
   - vráti `{ repaired: true, mode: "recovered" }`.

Relé obnoví prevádzku bez nutnosti opätovne zadávať akékoľvek prihlasovacie údaje na nasadenie.

Tento postup funguje iba vtedy, ak aktuálny `STORAGE_ENCRYPTION_KEY` stále dokáže dešifrovať
uložený blok. Ak ste kľúč rotovali **bez** migrácie, blok nie je možné
obnoviť.

## Režim zlyhania 2 — neobnoviteľný token (pôvodný kľúč už nie je dostupný)

**Príznak:** klikli ste na **Opraviť** a dostali ste
`{ repaired: false, mode: "redeploy", status: 409 }`.

**Obnova — opätovné nasadenie:**

Uložený token nie je možné pomocou aktuálneho kľúča obnoviť. Znova nasaďte relé
prostredníctvom rovnakého modálneho okna, ktoré ste použili pôvodne (ponuka **Nasadiť relé** → Vercel / Deno
/ Cloudflare). Proces nasadenia zapíše nový token (zašifrovaný aktuálnym
kľúčom) a odznak `chýbajúca autentifikácia` v danom riadku zmizne.

V používateľskom rozhraní samotné tlačidlo **Opraviť** otvorí modálne okno na opätovné nasadenie, ak
token nie je možné obnoviť, takže ho nikdy nemusíte hľadať manuálne.

## Režim zlyhania 3 — relé je dostupné, ale nie je v poriadku

**Príznak:** test proxy (tlačidlo `speed`) ukazuje, že relé je dostupné, ale požiadavky
napriek tomu občas zlyhávajú.

Skontrolujte hlavičky s informáciami o relé, ktoré vracia automatická testovacia sonda OmniRoute
(pozrite si **Nastavenia → Fond proxy** a počítadlá `relayTested` / `relayAlive`):

- `x-relay-url` — ktorý backend relé odpovedal.
- `x-relay-mode` — `ts` | `bifrost` | `auto` pre danú požiadavku.
- `x-relay-attempts` — koľko skokov cez relé sa vyskúšalo pred úspešným spracovaním.
- `x-relay-fallback` — `true`, keď požiadavka prešla z preferovaného
  backendu na záložné relé TypeScript.

Vysoký podiel `x-relay-fallback` spolu s nízkou hodnotou `relayAlive` znamená, že backend
sprievodnej služby nie je v poriadku a mali by ste ho opraviť alebo prepnúť stratégiu backendu relé
na `ts` (pozrite si `RELAY_BACKEND_STRATEGY.md`).

## Referenčná príručka API

| Metóda | Cesta                                     | Telo                    | Úspech                                                                                                                                      | Zlyhanie                                                                                 |
| ------ | ----------------------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `POST` | `/api/settings/proxies/[id]/repair-relay` | `{ "id": "<proxyId>" }` | `200 { repaired: true, mode: "recovered" }` pri opätovnom odvodení; `200 { repaired: false, mode: "noop" }` ak už existuje nešifrovaný text | `409 { mode: "redeploy" }` nie je možné obnoviť; `400` nejde o typ relé; `404` nenájdené |

Trasa zoznamu `GET /api/settings/proxies` pridáva ku každej položke údaje bez tajomstiev
`relayInfo: { isRelay, authMissing, repairMode }`, aby informačný panel
mohol zobraziť možnosť opravy bez toho, aby bol token kedykoľvek odhalený.
