## 1. Technologický zásobník

| Oblasť                  | Voľba                                                                                                                                             |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Webový framework        | **Next.js 16** (App Router, samostatný výstup, bez globálneho middleware)                                                                         |
| Jazyk                   | **TypeScript 6.0+** — cieľ `ES2022`, `module: esnext`, `moduleResolution: bundler`, `strict: false`                                               |
| Behové prostredie       | **Node.js** `>=22.22.2 <23` alebo `>=24.0.0 <27` (vynútené prostredníctvom `engines` + `SUPPORTED_NODE_RANGE`)                                    |
| Databáza                | **SQLite** prostredníctvom `better-sqlite3` (singleton, žurnálovanie WAL)                                                                         |
| Desktop                 | **Electron 41** + `electron-builder` 26.10 (samostatný pracovný priestor v `electron/`)                                                           |
| Testy                   | **Natívny testovací nástroj Node** (jednotkové/integračné), **Vitest** (MCP, autoCombo, vyrovnávacia pamäť), **Playwright** (e2e + protocols-e2e) |
| Zostavenie              | Samostatné zostavenie Next.js prostredníctvom `scripts/build/build-next-isolated.mjs`                                                             |
| Lintovanie/formátovanie | Plochá konfigurácia ESLint + Prettier (`lint-staged` prostredníctvom Husky pre-commit)                                                            |
| Systém modulov          | ESM všade (`"type": "module"`)                                                                                                                    |
| Pracovné priestory      | Pracovný priestor npm — `open-sse` je jediný podradený pracovný priestor                                                                          |

Aliasy ciest (`tsconfig.json`):

- `@/*` → `src/*`
- `@omniroute/open-sse` → `open-sse/index.ts`
- `@omniroute/open-sse/*` → `open-sse/*`

Predvolený port HTTP: **`20128`** (API a ovládací panel zdieľajú rovnaký proces). Dátový
adresár určuje premenná prostredia `DATA_DIR`, pričom predvolená hodnota je `~/.omniroute/`.

### 3.1 `src/app/` — App Router

App Router sprístupňuje používateľské rozhranie ovládacieho panela aj verejné/spravovacie HTTP API.
Neexistuje **žiadny globálny middleware** — zachytávanie sa vykonáva pre každú trasu samostatne.

Segmenty najvyššej úrovne v `src/app/`:

| Cesta                                                                         | Účel                                                                       |
| ----------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `api/`                                                                        | Všetky trasy HTTP API (pozri rozpis nižšie)                                |
| `a2a/`                                                                        | Koncový bod A2A JSON-RPC 2.0 (`POST /a2a`)                                 |
| `.well-known/agent.json/`                                                     | Dokument na vyhľadanie karty agenta A2A                                    |
| `(dashboard)/`                                                                | Používateľské rozhranie ovládacieho panela (skupina trás, bez prefixu URL) |
| `auth/`, `login/`, `forgot-password/`, `callback/`                            | Toky autentifikácie                                                        |
| `landing/`                                                                    | Marketingová/vstupná stránka                                               |
| `docs/`                                                                       | Vstavaný prehliadač dokumentácie API                                       |
| `status/`, `maintenance/`, `offline/`                                         | Prevádzkové stránky                                                        |
| `privacy/`, `terms/`                                                          | Právne stránky                                                             |
| `400/`, `401/`, `403/`, `408/`, `429/`, `500/`, `502/`, `503/`                | Statické chybové stránky                                                   |
| `error.tsx`, `global-error.tsx`, `not-found.tsx`, `forbidden/`, `loading.tsx` | Hranice chýb/načítavania frameworku                                        |
| `layout.tsx`, `page.tsx`, `globals.css`, `manifest.ts`                        | Koreňový obal                                                              |

#### 3.1.2a `src/app/api/services/` — Správa vstavaných služieb

Trasy na inštaláciu, spúšťanie, zastavovanie a monitorovanie 9Router a CLIProxyAPI.
Všetky cesty sú klasifikované ako **LOCAL_ONLY** (iba loopback, pevné pravidlo č. 17), pretože môžu
spustiť `npm install` a vytvárať podradené procesy.

```
src/app/api/services/
├── 9router/
│   ├── _lib.ts             pomocná funkcia getOrInitSupervisor()
│   ├── install/route.ts    POST — npm install prostredníctvom execFile
│   ├── start/route.ts      POST — supervisor.start()
│   ├── stop/route.ts       POST — supervisor.stop()
│   ├── restart/route.ts    POST — supervisor.restart()
│   ├── update/route.ts     POST — npm install novšej verzie
│   ├── rotate-key/route.ts POST — vygenerovanie nového kľúča API + reštart
│   ├── status/route.ts     GET  — aktuálny stav + stav databázy + metadáta verzie
│   └── auto-start/route.ts POST — prepnutie príznaku auto_start
├── cliproxy/
│   ├── _lib.ts             pomocná funkcia getOrInitSupervisor()
│   ├── install/route.ts    POST — npm install
│   ├── start/route.ts      POST — supervisor.start()
│   ├── stop/route.ts       POST — supervisor.stop()
│   ├── restart/route.ts    POST — supervisor.restart()
│   ├── update/route.ts     POST — npm install novšej verzie
│   ├── status/route.ts     GET  — aktuálny stav + stav databázy + metadáta verzie
│   └── auto-start/route.ts POST — prepnutie príznaku auto_start
└── [name]/
    └── logs/route.ts       GET  — priebežné protokoly SSE (zdieľané všetkými službami)
```

Zodpovedajúce používateľské rozhranie ovládacieho panela:
`src/app/(dashboard)/dashboard/providers/services/` — stránka s dvoma kartami (CLIProxyAPI + 9Router).
Reverzný proxy server pre vložené používateľské rozhranie 9Router:
`src/app/(dashboard)/dashboard/providers/services/[name]/embed/[[...path]]/route.ts`

Podrobný rozbor: `docs/frameworks/EMBEDDED-SERVICES.md`

Každý súbor trasy používa rovnaký vzor:


rovnakého spracovateľského reťazca `open-sse/handlers/`).

## 10. Ako prispievať

### Pridanie nového poskytovateľa

1. Zaregistrujte ho v `src/shared/constants/providers.ts` (pri načítaní sa overuje pomocou Zod).
2. Ak je potrebná vlastná logika, pridajte vykonávací modul do `open-sse/executors/`
   (rozšírte `BaseExecutor`).
3. Ak nepoužíva formát OpenAI, pridajte prekladač do `open-sse/translator/`.
4. Ak je založený na OAuth, pridajte konfiguráciu do `src/lib/oauth/providers/` a
   `src/lib/oauth/services/`.
5. Zaregistrujte modely v `open-sse/config/providerRegistry.ts` (alebo v registri
   príslušného formátu v `open-sse/config/`).
6. Napíšte testy v `tests/unit/`.

### Pridanie novej API trasy

1. Vytvorte `src/app/api/your-route/route.ts`.
2. Dodržte vzor: CORS → validácia tela pomocou Zod → autentifikácia → delegovanie obslužnej funkcii.
3. Ak ide o nový tvar požiadavky, pridajte schému Zod do `src/shared/validation/schemas.ts`.
4. Ak je trasa určená iba na správu, pridajte cestu do `src/shared/constants/publicApiRoutes.ts`
   (zoznam zakázaných ciest pre verejné API).
5. Pridajte testy do `tests/unit/`.
6. Aktualizujte `docs/reference/API_REFERENCE.md` a `docs/openapi.yaml`.

### Pridanie nového DB modulu

1. Vytvorte `src/lib/db/yourModule.ts` a importujte `getDbInstance()` z `./core.ts`.
2. Exportujte funkcie CRUD pre svoju doménu.
3. Ak pridávate nové tabuľky, pridajte migráciu do `src/lib/db/migrations/`, očíslovanú
   postupne, idempotentnú a transakčnú.
4. Importujúce moduly používajú priame importy z `@/lib/db/yourModule` (bez súhrnného exportu — stará reexportná vrstva `localDb.ts` bola odstránená).
5. Pridajte testy do `tests/unit/`.

### Pridanie nového nástroja MCP

1. Pridajte definíciu nástroja do `open-sse/mcp-server/tools/` (alebo rozšírte
   `open-sse/mcp-server/schemas/tools.ts`).
2. Priraďte príslušný rozsah alebo rozsahy v `src/shared/constants/mcpScopes.ts`.
3. Zaregistrujte nástroj v `open-sse/mcp-server/server.ts`.
4. Pridajte testy do `open-sse/mcp-server/__tests__/`.
5. Aktualizujte [MCP-SERVER.md](../frameworks/MCP-SERVER.md).

### Pridanie novej zručnosti A2A

Pozrite si [A2A-SERVER.md § Pridanie novej zručnosti](../frameworks/A2A-SERVER.md). Zručnosti sa nachádzajú v
`src/lib/a2a/skills/` a registrujú sa prostredníctvom správcu úloh A2A.

## 11. Konvencie

- **Štýl kódu**: odsadenie 2 medzerami, dvojité úvodzovky, šírka 100 znakov, bodkočiarky,
  koncové čiarky `es5` — vynucuje Prettier prostredníctvom `lint-staged`.
- **Importy**: externé → interné (`@/`, `@omniroute/open-sse`) → relatívne.
- **Pomenovanie**: súbory `camelCase` alebo `kebab-case`, komponenty `PascalCase`,
  konštanty `UPPER_SNAKE`.
- **ESLint**: `no-eval`, `no-implied-eval`, `no-new-func` = `error` všade;
  `no-explicit-any` = `warn` v `open-sse/` a `tests/`, inde `error`.
- **TypeScript**: `strict: false` (zdedené nastavenie). Na hraniciach medzi modulmi uprednostňujte explicitné typy pred
  inferenciou.
- **Databáza**: nikdy nepíšte nespracované SQL v trasách ani obslužných funkciách — vždy používajte
  moduly v `src/lib/db/`. Nikdy neimportujte zo súhrnných exportov — používajte priamo konkrétne moduly `src/lib/db/*`.
- **Typovanie DB entít (#3512)**: funkcia, ktorá zapisuje alebo číta tvar
  riadka DB tabuľky, by mala prijímať/vracať pomenované rozhranie TS, ktoré zrkadlí
  stĺpce danej tabuľky v pomere 1:1, nie `any` ani anonymný typ vložený priamo na mieste volania. Umiestnite
  rozhranie vedľa funkcie (napr. `export interface UsageEntry` v
  `src/lib/usage/usageHistory.ts` nad `saveRequestUsage`), ponechajte jednotlivé
  polia voliteľné alebo s možnosťou hodnoty null, keď rôzne zapisujúce funkcie vypĺňajú riadok
  postupne, a pre pole, ktorého tvar sa medzi volajúcimi líši, uprednostnite `unknown` pred `any`
  (zdokumentujte to pri poli, napr. `UsageEntry.tokens`
  prijíma nespracované údaje o použití v tvare poskytovateľa aj normalizovaný tvar). Keď sa týmto
  spôsobom počet výskytov `any` v súbore zníži na nulu, pridajte ho do zoznamu povolených súborov
  `check:any-budget:t11` (`scripts/check/check-t11-any-budget.mjs`,
  `maxAny: 0`), aby nedošlo k regresii. Toto je konvencia pre prvú čiastkovú fázu — širšie
  odstraňovanie „anonymného `any`“ prebieha iteratívne vo zvyšku
  kódovej základne.
- **Chyby**: používajte try/catch s konkrétnymi typmi chýb a zaznamenávajte ich s kontextom pino. Nikdy
  potichu neignorujte chyby v prúdoch SSE; na vyčistenie používajte signály prerušenia.
- **Bezpečnosť**: nikdy nepoužívajte `eval()` / `new Function()` / implicitné vyhodnocovanie. Všetky
  vstupy overujte pomocou Zod. Prihlasovacie údaje uložené v úložisku šifrujte (AES-256-GCM). Udržiavajte
  zoznam zakázaných položiek `src/shared/constants/upstreamHeaders.ts` zosúladený s
  vrstvou sanitizácie/validácie.
- **Commity**: Conventional Commits — `feat(scope): subject`. Povolené rozsahy:
  `db`, `sse`, `oauth`, `dashboard`, `api`, `cli`, `docker`, `ci`, `mcp`,
  `a2a`, `memory`, `skills`.
- **Vetvy**: predpony `feat/`, `fix/`, `refactor/`, `docs/`, `test/`,
  `chore/`. Nikdy nevytvárajte commity priamo do `main`.
- **Husky**: pred commitom spúšťa `lint-staged` + `check:docs-sync` +
  `check:any-budget:t11`; pred odoslaním zmien spúšťa `check:any-budget:t11` + `check:tracked-artifacts` (rýchle kontroly; nezahŕňajú `test:unit`).

## 12. Striktné pravidlá (z CLAUDE.md)

1. Nikdy neukladajte tajné údaje ani prihlasovacie údaje do repozitára.
2. Nikdy nepoužívajte súhrnné importy — používajte priamo konkrétne moduly `src/lib/db/*`.
3. Nikdy nepoužívajte `eval()` / `new Function()` / implicitný eval.
4. Nikdy nevykonávajte commity priamo do vetvy `main`.
5. Nikdy nepíšte nespracované SQL v routách — vždy používajte moduly `src/lib/db/`.
6. Nikdy potichu nepotláčajte chyby v prúdoch SSE.
7. Vstupy vždy validujte pomocou schém Zod.
8. Pri zmene produkčného kódu vždy zahrňte testy.
9. Pokrytie musí zostať ≥ 60 % (príkazy, riadky, funkcie, vetvy).
