> **TL;DR**: `open-sse/` je základný streamovací engine, ktorý zabezpečuje každú požiadavku na LLM v OmniRoute. Obsahuje približne 1 400 súborov implementujúcich spracovanie požiadaviek, exekútory, služby, server MCP a prekladovú vrstvu. Táto príručka vysvetľuje, ako jednotlivé časti spolupracujú.

**Zdroj:** `open-sse/` (balík pracovného priestoru, približne 1 440 netestovacích súborov `.ts`)

---

## Prečo samostatný balík pracovného priestoru?

`open-sse/` je **samostatný pracovný priestor** v monorepozitári OmniRoute z niekoľkých dôvodov:

1. **Opätovná použiteľnosť** — `open-sse` je publikovaný na npm ako `@omniroute/open-sse`, takže ho môžu nezávisle používať aj iné projekty
2. **Jasné hranice** — streamovací engine je oddelený od vrstvy používateľského rozhrania/databázy špecifickej pre OmniRoute
3. **Výkon** — engine nemá žiadne závislosti od Next.js, čo umožňuje rýchlejšie studené štarty v prostrediach CLI/serverless
4. **Verzovanie** — `open-sse` môže vydávať nové verzie podľa vlastného harmonogramu

```json
// package.json
"workspaces": ["open-sse"]
```

## Spracovanie požiadavky

Každá požiadavka na LLM prechádza **5-fázovým procesom**:

```
                              ┌──────────────┐
   HTTP požiadavka             │  1. SMEROVAŤ│   rozlíšenie kombinácie, výber modelu
   (trasa Next.js)             └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  2. PRELOŽIŤ │   konverzia formátu (OpenAI ↔ Claude ↔ Gemini)
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  3. VYKONAŤ  │   exekútor poskytovateľa, HTTP, opakovanie, istič
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  4. STREAMOVAŤ│  transformácia SSE, spätný tlak
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  5. ZAZNAMENAŤ│  sledovanie využitia, záznam volania, klasifikácia chýb
                              └──────┬───────┘
                                     │
                                     ▼
                              HTTP odpoveď (SSE alebo JSON)
```

### Fáza 1: Smerovanie (services/combo.ts)

**Vstupný bod**: `handleComboChat()` v `services/combo.ts`

Prevedie požiadavku na konkrétnu n-ticu `(provider, model, account, credentials)`:

- Vyhľadá kombináciu podľa ID (alebo vytvorí virtuálnu kombináciu pre modely `auto/*`)
- Použije stratégiu smerovania (prioritná, vážená, cyklická atď.)
- Odfiltruje poskytovateľov, ktorí nie sú v poriadku (istič)
- Vyberie ďalší použiteľný cieľ

Pre modely `auto/*` táto fáza tiež:

- Spustí **16-faktorový bodovací** algoritmus (`services/autoCombo/`)
- Vyberie dvojicu `provider+model` na základe stavu, ceny, latencie atď.

### Fáza 2: Preklad (translator/)

Ak sa zdrojový formát (napr. OpenAI) líši od cieľového formátu (napr. Claude), požiadavka sa **preloží**:

- Systémová výzva → systémová správa
- Definície nástrojov → formát nástrojov špecifický pre poskytovateľa
- Parametre uvažovania/premýšľania → ekvivalenty špecifické pre poskytovateľa
- Normalizácia rolí správ (`developer` → `system` pre systémy iné ako OpenAI)

Súbor `translator/index.ts` sprístupňuje:

```ts
translateRequest(body, sourceFormat, targetFormat): TranslatedRequest
needsTranslation(source, target): boolean
```

### Fáza 3: Vykonanie (executors/)

**Vstupný bod**: `getExecutor(providerId).execute(request, options)`

Všetci poskytovatelia používajú `DefaultExecutor` (`executors/default.ts`) prostredníctvom záložného mechanizmu továrne `getExecutor()`. Exekútor:

- Zostaví nadradenú URL adresu (`buildUrl()`)
- Pridá hlavičky špecifické pre poskytovateľa (`buildHeaders()`)
- Transformuje telo požiadavky (`transformRequest()`)
- Odošle HTTP požiadavku s opakovaním a exponenciálnym predlžovaním intervalov
- V prípade potreby spracuje obnovenie autentifikácie (poskytovatelia OAuth)

Všetky exekútory rozširujú `BaseExecutor` (`executors/base.ts`, 1170 riadkov kódu), ktorý poskytuje:

- Spoločnú logiku opakovania
- Integráciu proxy
- Integráciu ističa
- Hooky na zaznamenávanie využitia

### Fáza 4: Streamovanie (utils/stream.ts)

Pri streamovaných odpovediach exekútor vráti **ReadableStream**. Obslužná rutina:

- Presmeruje dáta cez transformáciu SSE (`createSSETransformStreamWithLogger`)
- Používa kontrolné signály heartbeat na detekciu neaktívnych pripojení
- Korektne spracuje odpojenie klienta (`pipeWithDisconnect`)
- Transformuje SSE → JSON pre klientov bez podpory streamovania

Pri nestreamovaných odpovediach exekútor vráti spracovaný objekt JSON, ktorý sa ďalej odovzdá bez zmien.

### Fáza 5: Zaznamenanie (services/usage.ts)

Po odpovedi (úspešnej alebo neúspešnej) sa zaznamenajú údaje o použití:

- `prompt_tokens`, `completion_tokens`, `cached_tokens` z odpovede
- `cost_usd` vypočítané z cenových údajov
- `latency_ms`, `status`, `error_class` v prípade zlyhania
- Uložené v tabuľke `usage_history`

Artefakty protokolov volaní (ak sú povolené) sa zapisujú do `${DATA_DIR}/call_logs/`.

## Hlbkový pohľad na kľúčové súbory

### chatCore.ts (5977 riadkov)

**Hlavný spracovateľ požiadaviek**. Napriek svojej veľkosti má jasnú štruktúru:

```ts
// Pseudoštruktúra chatCore.ts
export async function handleChat(request: NextRequest) {
  // 1. Autentifikácia + CORS
  await authenticateRequest(request);
  applyCorsHeaders(response);

  // 2. Validácia tela požiadavky
  const body = await parseRequestBody(request);

  // 3. Detekcia formátu + preklad
  const sourceFormat = detectFormat(request);
  const targetFormat = getTargetFormat(providerId);
  if (needsTranslation(sourceFormat, targetFormat)) {
    body = translateRequest(body, sourceFormat, targetFormat);
  }

  // 4. Smerovanie combo
  const targets = await resolveComboTargets(comboId, body);
  for (const target of targets) {
    try {
      const result = await executeOnTarget(target, body);
      await recordUsage(result);
      return result;
    } catch (err) {
      // Pokračovať na ďalší cieľ
    }
  }

  // 5. Núdzový fallback
  return await emergencyFallback(body);
}
```

Hoci ide o jednu obrovskú funkciu, je členená do **komentovaných sekcií**, ktoré zodpovedajú 5-stupňovému pipeline.

### combo.ts (4456 LOC)

**Smerovací engine**, ktorý prevádza combo na usporiadané ciele.

```ts
// services/combo.ts
export async function handleComboChat(body, comboId): Promise<ChatResult> {
  const targets = await resolveComboTargets(comboId, body);
  for (const target of targets) {
    try {
      return await handleSingleModel(target, body);
    } catch (err) {
      log.warn("target failed, trying next", { target, err });
    }
  }
  throw new ComboExhaustedError("All targets failed");
}
```

### base.ts (1170 LOC)

**Abstraktný exekútor**, ktorý rozširuje každá trieda exekútora (priamo alebo prostredníctvom `DefaultExecutor` a ďalších podtried). Obsahuje:

- `buildHeaders()` — predvolené hlavičky (autentifikácia, content-type)

- `execute()` — hlavná HTTP slučka s retry/backoff/breaker

// open-sse/executors/default.ts

  // Spracováva všetkých poskytovateľov kompatibilných s OpenAI/Anthropic

Správanie špecifické pre poskytovateľa (autentifikačné hlavičky, základná URL, hlavičky verzie) sa konfiguruje prostredníctvom registra poskytovateľov, nie samostatnými triedami exekútorov.

````

## Exekutory (150 modulov)

Prevažne jeden súbor na poskytovateľa. Všetky triedy exekutorov rozširujú `BaseExecutor` a prepisujú to, čím sa líšia; ostatné moduly sú pomocníci pre jednotlivých poskytovateľov (schémy nástrojov, fetch/TTS adaptéry, handlery špecialít).

### Bežné vzory

Poskytovatelia sa rozlíšujú cez `getExecutor(providerId)`, ktorá vráti nakonfigurovaný exekutor. Poskytovatelia kompatibilní s OpenAI/Anthropic používajú `DefaultExecutor` (`executors/default.ts`). Správanie špecifické pre poskytovateľa (základná URL, auth hlavičky, verzia API) sa konfiguruje v `open-sse/config/providers/`, zatiaľ čo transformácie tela požiadavky sa spracúvajú v `open-sse/translator/`.

**Vlastná URL** sa nastavuje cez konfiguráciu poskytovateľa:

```ts
// Konfigurácia poskytovateľa v open-sse/config/providers/
export default {
  id: "together",
  baseURL: "https://api.together.xyz/v1/chat/completions",
}
````

**Vlastná autentifikácia** sa spracúva cez auth konfiguráciu registra poskytovateľov (API kľúč, OAuth, profily hlavičiek).

**Transformácie vlastného tela požiadavky** (napr. Anthropic oddeľuje `system` od `messages`) sú registrované pre každého poskytovateľa v `open-sse/translator/`.

````

### Továreň exekutorov

`executors/index.ts` exportuje `getExecutor(providerId)`:

```ts
import { getExecutor } from "@omniroute/open-sse/executors";

const executor = getExecutor("anthropic");
const result = await executor.execute({
  model: "claude-sonnet-4-5",
  messages: [...],
});
````

Rozlíšenie prebieha cez `ExecutorRegistry` (`executors/registry.ts`): každý špecializovaný exekutor je deklarovaný vo vstavanaj tabuľke `executors/index.ts` a registrovaný cez `registerExecutor(alias, instance)` pri načítaní modulu; `getExecutor()` konzultuje register a pre každého poskytovateľa bez špecializovaného záznamu použije memoizovaný `DefaultExecutor`. Úplné mapovanie alias → exekutor charakterizuje golden test `tests/unit/executor-map-golden.test.ts`.

## Prekladače

Preklad medzi **3 formátmi**: OpenAI, Anthropic, Gemini a navyše nové Responses API.

### Kedy dochádza k prekladu

```ts
import { needsTranslation, translateRequest } from "@omniroute/open-sse/translator";

if (needsTranslation(sourceFormat, targetFormat)) {
  body = translateRequest(body, sourceFormat, targetFormat);
}
```

Bežné preklady:

- `OpenAI → Anthropic`: samostatné pole `system`, hlavička `x-api-key`
- `OpenAI → Gemini`: `contents` namiesto `messages`, `systemInstruction`
- `OpenAI → Responses API`: pole `input`, stav `previous_response_id`

### Ošetrené okrajové prípady

- rola `developer` → `system` pre iné systémy ako OpenAI
- rola `system` → zlúčená do prvej správy používateľa pre GLM/ERNIE
- `json_schema` → `responseMimeType` + `responseSchema` systému Gemini
- `tools` → formát nástrojov špecifický pre poskytovateľa
- Parametre uvažovania (o1, Claude) → ekvivalenty špecifické pre poskytovateľa

## Server MCP

`open-sse/mcp-server/` implementuje server protokolu **Model Context Protocol**:

- **110 nástrojov** (správa poskytovateľov, kombinácie, pamäť, vyrovnávacia pamäť, kompresia, proxy, zručnosti, gamifikácia, pluginy, Notion, Obsidian, lokálny korpus)
- **3 transporty**: stdio, SSE, Streamable HTTP
- **33 rozsahov** na jemne odstupňovanú autorizáciu

### Registrácia nástrojov

Nástroje sú registrované ako samostatné súbory v `open-sse/mcp-server/tools/`, pričom každý exportuje názov, schému, obslužnú funkciu a rozsah:

```ts
// open-sse/mcp-server/tools/getHealth.ts
import { z } from "zod";
export default {
  name: "omniroute_get_health",
  description: "Získať snímku stavu systému",
  scope: "read:health",
  inputSchema: z.object({}),
  handler: async (_args, ctx) => {
    return await getSystemHealth();
  },
};
```

### Transporty

```ts
// stdio (použitie v CLI)
startMcpStdio(server);

// SSE (streamovanie založené na HTTP)
startMcpSse(server, port);

// Streamovateľné HTTP (moderné MCP)
startMcpStreamable(server, port);
```

### Autorizácia

Každé volanie nástroja prechádza kontrolami rozsahu (`open-sse/mcp-server/auth/`):

```ts
if (!hasScope(apiKey, "providers:read")) {
  throw new Error("Nedostatočný rozsah");
}
```

## Transformátory

`open-sse/transformer/` konvertuje medzi formátmi **Chat Completions** a **Responses API**.

### Prečo samostatný transformátor?

Responses API je nový formát OpenAI so **stavovými konverzáciami** (`previous_response_id`). Keď klient odošle požiadavku Responses, OmniRoute:

1. Interne konvertuje Responses → Chat Completions
2. Odošle ju poskytovateľovi (ľubovoľnému poskytovateľovi, ktorý podporuje Chat Completions)
3. Konvertuje odpoveď späť do formátu Responses
4. Streamuje konvertovanú odpoveď klientovi

Transformátor (`transformer/responsesTransformer.ts`) poskytuje:

```ts
createResponsesApiTransformStream(): TransformStream
```

Ten spracováva:

- udalosti `response.output_item.added`
- udalosti `response.output_text.delta`
- udalosť `response.completed`
- Mapovanie volaní nástrojov (`function_call` ↔ `tool_calls`)

## Výkonnostné obmedzenia

Smerovací engine má prísne výkonnostné limity:

| Operácia                                               | Cieľ  | Meranie                                |
| ------------------------------------------------------ | ----- | -------------------------------------- |
| Vyhodnotenie kombinácie                                | <10ms | Pre 50 cieľov                          |
| Kontrola obmedzenia frekvencie                         | <1ms  | Token bucket v pamäti                  |
| Záložný výber rodiny modelov                           | <5ms  | Definície rodín vo vyrovnávacej pamäti |
| Odoslanie požiadavky na smerovanie                     | <2ms  | Kritická cesta                         |
| **Žiadne blokujúce I/O na kritickej ceste smerovania** | —     | Všetko asynchrónne                     |

## Antivzory

❌ **Synchrónne volania databázy v `combo.ts`** — vykonajte predbežný výpočet a použite vyrovnávaciu pamäť
❌ **Logika opakovania v obslužných rutinách** — použite `retry()` zo služby odolnosti
❌ **Priamy prístup ku konfigurácii poskytovateľa** — použite gettery `providerRegistry`
❌ **Natvrdo zakódované reťazce záložných možností** — definujte ich v `modelFamilyFallback.ts`
❌ **Mutácie stavu medzi súbežnými požiadavkami** — používajte iba kontext viazaný na požiadavku

## Pridanie nového komponentu

### Pridanie novej služby

1. Vytvorte `open-sse/services/[serviceName].ts` s jasne vymedzenou zodpovednosťou
2. Exportujte hlavnú obslužnú funkciu a všetky konštanty
3. Pridajte jednotkové testy do `tests/unit/services/[serviceName].test.mjs`
4. Integrujte službu do procesu spracovania požiadaviek v `handlers/chatCore.ts` (ak súvisí so smerovaním)
5. Ak služba ovplyvňuje výber cieľa, aktualizujte logiku smerovania v `combo.ts`
6. Zdokumentujte ju v tomto súbore

### Pridanie nového vykonávateľa

1. Vytvorte `open-sse/executors/[provider].ts`, ktorý rozširuje `BaseExecutor`
2. Zaregistrujte ho v `config/providerRegistry.ts`
3. Pridajte ho do továrne v `executors/index.ts`
4. Pridajte jednotkové testy vykonávateľa
5. Zdokumentujte ho v `docs/architecture/ARCHITECTURE.md`

### Pridanie nového nástroja MCP

1. Vytvorte alebo aktualizujte `open-sse/mcp-server/tools/[category]Tools.ts`
2. Definujte schému Zod pre vstupy
3. Zaregistrujte nástroj v `mcp-server/index.ts`
4. Pridajte ho do matice rozsahov v `mcp-server/auth/`
5. Pridajte jednotkové testy
