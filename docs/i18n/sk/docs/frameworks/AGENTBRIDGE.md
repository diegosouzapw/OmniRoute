AgentBridge je MITM (Man-in-the-Middle) proxy server OmniRoute, ktorý zachytáva HTTPS komunikáciu AI agentov v IDE a presmerúva ju cez zjednotený smerovací mechanizmus OmniRoute. Podporuje **10 agentov IDE** — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code a Trae (vo fáze skúmania) — vďaka čomu je OmniRoute MITM proxy serverom s najširším pokrytím pre AI asistentov programovania na trhu.

**Umiestnenie na ovládacom paneli:** `/dashboard/tools/agent-bridge`
**Skupina na bočnom paneli:** Nástroje (za Cloud Agents)
**Pozrite tiež:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — monitorovanie všetkej zachytenej komunikácie v reálnom čase; `docs/security/MITM-TPROXY-DECRYPT.md` (git; nie je zahrnutý v zostavení `/docs`) — režim transparentného zachytávania a dešifrovania pomocou TPROXY v systéme Linux, ovládaný trasou `/api/tools/agent-bridge/tproxy`.

## §1 Prehľad

### Čo je AgentBridge?

Keď agent IDE (napr. GitHub Copilot, Cursor alebo Claude Code) vykoná volanie API, pripojí sa priamo k nadradenému poskytovateľovi AI (OpenAI, Anthropic atď.). AgentBridge toto pripojenie transparentne zachytí na úrovni TLS — bez nutnosti meniť konfiguráciu agenta — a presmeruje požiadavku cez OmniRoute.

To znamená, že môžete:

- **Presmerovať ľubovoľného agenta k ľubovoľnému poskytovateľovi**: Komunikuje Copilot s OpenAI? Presmerujte ho na Anthropic Claude, Gemini alebo ktoréhokoľvek z 352 poskytovateľov OmniRoute.
- **Použiť mapovania modelov**: `gemini-3-flash` → `claude-sonnet-4.7` transparentne na úrovni obslužnej rutiny.
- **Sledovať všetku komunikáciu agentov**: každá zachytená požiadavka sa zverejňuje v nástroji [Traffic Inspector](./TRAFFIC_INSPECTOR.md).
- **Využiť odolnosť OmniRoute**: kombinované smerovanie, ističe, záložné mechanizmy a sledovanie nákladov fungujú aj pre komunikáciu agentov IDE.

## §2 Architektúra

### 2.1 Prehľad komponentov

```
Agent IDE (VS Code / Cursor / atď.)
    │  HTTPS (port 443)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← presmerovanie DNS
    │
    ▼
src/mitm/server.cjs  (port 443, podradený proces CJS)
    │  zisťuje cieľ podľa SNI hlavičky Host
    │  generuje certifikát TLS pre každé SNI podpísaný CA AgentBridge
    ├── Zhoda so zoznamom obídení? → prechod TCP (bez dešifrovania)
    ├── Zhoda s cieľom? → fetch → smerovač OmniRoute (port 20128)
    │       └── handler.intercept() — TypeScript
    │               ├── maskSecrets() v tele/hlavičkách požiadavky
    │               ├── TrafficBuffer.push() — publikuje do Inšpektora prevádzky
    │               └── fetchRouter() → /v1/chat/completions
    └── Bez zhody? → prechod TCP (bez dešifrovania)
```

### 2.2 Server MITM (`src/mitm/server.cjs`)

Základný server MITM beží ako podradený proces Node.js CJS (aby nebolo potrebné prepisovať existujúcu kódovú základňu CJS). Vykonáva tieto činnosti:

- Počúva na porte 443 (vyžaduje oprávnenie alebo `authbind`/`setcap`)
- Prijíma tunely CONNECT z operačného systému (prostredníctvom presmerovania DNS v `/etc/hosts`)
- Generuje certifikáty TLS pre jednotlivé SNI podpísané CA AgentBridge (`DATA_DIR/mitm/ca.crt`)
- Vyhľadáva cieľového agenta podľa hlavičky Host prostredníctvom registra `targets/index.ts`
- Odosiela požiadavky do vrstvy obsluhy TypeScript cez HTTP na `http://127.0.0.1:20128`

`TARGET_HOSTS` sa načítava zo súboru `DATA_DIR/mitm/targets.json` (ktorý pri spustení zapisuje `targets/index.ts`), čo umožňuje dynamické aktualizácie bez reštartovania servera CJS.

> **Model koreňovej CA (#6684).** Vyššie uvedený opis certifikátov pre jednotlivé SNI
> podpísaných CA predstavuje perzistentný model koreňovej CA pridaný v #6684 (`src/mitm/cert/rootCa.ts` +
> `src/mitm/_internal/rootCaShim.cjs`, ktorý opätovne používa kryptografiu CA/koncových certifikátov už
> overenú pre TPROXY v `src/mitm/tproxy/dynamicCert.ts`) — nahrádza
> starší jediný statický samopodpísaný koncový certifikát (`src/mitm/cert/generate.ts`, ktorý je stále
> obmedzený iba na hostiteľov antigravity), na ktorý poukazuje samotná dvojica
> `server.crt`/`server.key` na disku. **Správanie pri migrácii**: nová inštalácia (bez predchádzajúceho
> súboru `server.crt`) automaticky získa model koreňovej CA; inštalácia, ktorá už
> dôveruje starému statickému koncovému certifikátu, ho bude naďalej používať, kým operátor nenastaví
> `MITM_ROOT_CA_ENABLED=true` a nereštartuje most (`src/mitm/cert/migration.ts`
> je čistá rozhodovacia funkcia — dôveryhodná CA pre MITM, ktorá dokáže podpísať koncový certifikát pre
> **ľubovoľného** hostiteľa, má podstatne väčšie oprávnenia než starý koncový certifikát s pevne určenými SAN, takže
> pri už dôveryhodnej inštalácii nikdy nedôjde k prepnutiu bez upozornenia). Certifikát CA sa nainštaluje
> do rovnakého umiestnenia `omniroute-mitm.crt` v úložisku dôveryhodných certifikátov, ktoré používal starý koncový certifikát
> (`cert/install.ts::installCaCert`) — nie je potrebné čistenie dvojitej dôvery.

### 2.3 Základ obsluhy (`src/mitm/handlers/base.ts`)

Všetky obslužné moduly agentov rozširujú `MitmHandlerBase`:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // Chránené pomocné metódy: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

Každý obslužný modul pred sprostredkovaním volá `hookBufferStart()` a po dokončení volá `hookBufferUpdate()`. Tieto metódy vkladajú položky `InterceptedRequest` do `globalTrafficBuffer` (pozrite si [Inšpektor prevádzky](./TRAFFIC_INSPECTOR.md) §4).

### 2.4 Register cieľov (`src/mitm/targets/`)

Každý agent má deklaratívny súbor cieľa:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

Register (`targets/index.ts`) exportuje `ALL_TARGETS` a pri spustení generuje `DATA_DIR/mitm/targets.json`.

### 2.5 Prechod a zoznam obídení (`src/mitm/passthrough.ts`)

**Zoznam obídení** (kontroluje sa ako prvý a má prednosť pred zhodou s cieľom):

- Predvolené vzory: hostitelia bánk, `.gov.`, poskytovatelia OAuth/SSO (Okta, Auth0) atď.
- Používateľské vzory: uložené v databázovej tabuľke `agent_bridge_bypass`
- Obídení hostitelia dostanú transparentný tunel TCP — TLS sa **nikdy nedešifruje**

**Predvolený prechod** (bez zhody s cieľom a bez zhody v zozname obídení):

- Taktiež dostane tunel TCP — spojenia sa nikdy neprerušia
- Zabraňuje tomu, aby AgentBridge narúšal všeobecnú systémovú prevádzku HTTPS

Poradie smerovania:

```
zoznam obídení → zhoda s cieľom → prechod
```

### 2.6 Certifikát nadradenej CA (`src/mitm/upstreamTrust.ts`)

Pre podnikové sieťové prostredia s vlastnou CA:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

Ak je nastavená, nakonfiguruje globálny dispečer balíka `undici` s dodatočným certifikátom CA, čím umožní AgentBridge pristupovať k nadradeným poskytovateľom cez podnikové proxy ukončujúce TLS.

### 2.7 Maskovanie tajných údajov (`src/mitm/maskSecrets.ts`)

Nezávislý skener vytvorený metódou čistého priestoru sa aplikuje na telá požiadaviek a hlavičky s prihlasovacími údajmi
**predtým**, než vstúpia do vyrovnávacej pamäte Inšpektora prevádzky alebo akéhokoľvek protokolu. Vykonáva jeden lineárny priechod:

- Tokeny s predponou `sk-` / `ak-` / `pk-` (v štýle OpenAI/Anthropic)
- Prihlasovacie údaje `Authorization: Bearer <token>` podľa RFC 6750, pričom celý token má prednosť
- Všeobecné dlhé nepriehľadné tokeny (≥40 znakov) vrátane bodkovaných foriem a foriem s výplňou

`sanitizeHeaders()` prevádza ponechané názvy na malé písmená, deterministicky spája hodnoty polí, odstraňuje
zdieľaný zoznam zakázaných hlavičiek pre jednotlivé skoky a rámcovanie (vrátane autentifikácie proxy), úplne rediguje `cookie` a
`set-cookie` a hodnoty prihlasovacích údajov odovzdáva skeneru.

## §3 Nastavenie

### 3.1 Spustenie/zastavenie servera MITM

Použite kartu servera AgentBridge na adrese `/dashboard/tools/agent-bridge`:

| Akcia                 | Popis                                                                                 |
| --------------------- | ------------------------------------------------------------------------------------- |
| Spustiť server        | Spustí `src/mitm/server.cjs` na porte 443                                             |
| Zastaviť server       | Korektne ukončí podriadený proces                                                     |
| Reštartovať server    | Zastaví a spustí server (načíta zmeny cieľov)                                         |
| Dôverovať certifikátu | Nainštaluje `DATA_DIR/mitm/ca.crt` do systémového úložiska dôveryhodných certifikátov |
| Stiahnuť certifikát   | Stiahne `ca.crt` na manuálnu inštaláciu                                               |
| Obnoviť certifikát    | Vytvorí nový pár kľúčov CA (všetky existujúce certifikáty agentov sa zneplatnia)      |

### 3.2 Nastavenie dôveryhodnosti certifikátu

Certifikát CA služby AgentBridge musí byť pre operačný systém dôveryhodný, aby IDE prijali pripojenie MITM.

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Kľúčenka):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

Prípadne použite tlačidlo „Dôverovať certifikátu“ na ovládacom paneli (spustí príslušný príkaz pre váš operačný systém a v prípade potreby zobrazí výzvu sudo).

#### IDE založené na Electrone ignorujú systémové úložisko dôveryhodných certifikátov (`NODE_EXTRA_CA_CERTS`)

Niektoré IDE — najmä **Antigravity IDE** a ďalšie aplikácie odvodené od Electronu / VS Code — obsahujú
vlastné prostredie Node.js, ktoré pri odchádzajúcich požiadavkách
`fetch`/HTTPS **nepoužíva systémové úložisko dôveryhodných certifikátov**. Nastavenie dôveryhodnosti CA na úrovni OS/NSS postačuje pre natívny **backend**
IDE (napr. jazykový server v jazyku Go, ktorý používa systémový balík CA), ale v **rozhraní Electron**
bude TLS naďalej zlyhávať — prejaví sa to ako _odhlásenie_ aplikácie alebo _„chyba pripojenia“_,
hoci protokol MITM uvádza, že inicializačné volania backendu vracajú stav `200`. Vyžadujú sa
dva kroky a oba sú dôležité:

1. Explicitne nasmerujte prostredie na CA:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **Spustite IDE z daného shellu.** Spustenie pomocou ikony na pracovnej ploche, Docku alebo ponuky Štart
   **nezdedí** exportované premenné shellu a `~/.config/environment.d/*.conf` sa použije až po
   novom grafickom prihlásení. Najskôr IDE úplne ukončite — zámok jednej inštancie Electronu spôsobí, že druhé
   spustenie iba aktivuje existujúci proces a nové prostredie sa ignoruje.

Vyššie uvedený krok nastavenia dôveryhodnosti na úrovni OS a NSS je naďalej potrebný (sieťová vrstva Chromium používaná niektorými
tokmi overovania číta používateľské úložisko NSS a má vlastné statické pripnutia pre `*.googleapis.com`, ktoré
lokálne dôveryhodná CA prepíše). `NODE_EXTRA_CA_CERTS` navyše pokrýva cestu Node `fetch`.

### 3.3 Smerovanie DNS

Pre každého agenta, ktorého chcete zachytávať, sa musia jeho hostitelia API prekladať na `127.0.0.1`. AgentBridge spravuje záznamy v `/etc/hosts` automaticky, keď v Sprievodcovi nastavením prepnete DNS pre daného agenta.

Príklad záznamov v `/etc/hosts` pre GitHub Copilot:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 Mapovanie modelov

Pomocou tabuľky mapovania modelov na karte každého agenta definujte mapovania zdroj → cieľ:

| Zdrojový model (natívny pre agenta) | Cieľový model (OmniRoute) |
| ----------------------------------- | ------------------------- |
| `gpt-4o`                            | `claude-sonnet-4.7`       |
| `*` (zástupný znak)                 | `claude-haiku-4.7`        |

Zástupný znak `*` mapuje každý nerozpoznaný model na určený cieľ. Mapovanie sa uchováva v tabuľke `agent_bridge_mappings`.

> **Tip — zistite skutočné ID modelov agenta.** IDE môže odosielať názvy modelov, ktoré sa líšia od
> označení v jeho používateľskom rozhraní a menia sa medzi hlavnými verziami. Napríklad **Antigravity 2** odosiela
> `gemini-3.1-pro-low`, `gemini-pro-agent` a `gemini-3.1-flash-lite` — nie
> `gemini-2.5-pro` uvedený v staršej dokumentácii. Odošlite jednu správu chatu bez zodpovedajúceho mapovania: MITM
> zaznamená presnú prichádzajúcu hodnotu `model:` a požiadavku prepustí ďalej. Namapujte túto doslovnú hodnotu a
> nasledujúca požiadavka sa zachytí a presmeruje na váš cieľ.

### 3.5 Upozornenie na riziko

AgentBridge zachytáva prihlasovacie údaje (tokeny OAuth, kľúče API), ktoré IDE používa na overenie voči nadradeným poskytovateľom. Pred zaznamenaním do protokolu sa **maskujú** (pozrite §2.7), sú však viditeľné pre vrstvu MITM systému OmniRoute. Pri prvej aktivácii každého agenta sa zobrazí zatvárateľné modálne okno s upozornením na riziko.

### 3.6 Údržba a diagnostika

Ovládací panel obsahuje kartu **Údržba a diagnostika** (`AgentBridgeMaintenanceCard`, v `src/app/(dashboard)/dashboard/tools/agent-bridge/components/`), ktorá sprístupňuje prevádzkové trasy MITM, ktoré predtým nemali používateľské rozhranie. Jej podnadpis znie: _„Otestujte si kanál zachytávania, odstráňte zvyškový stav systému a preneste svoje nastavenie medzi zariadeniami.“_ Pomocné funkcie klienta pre túto kartu sa nachádzajú v `src/lib/inspector/agentBridgeMaintenanceApi.ts`.

| Tlačidlo                    | Trasa                                  | Čo robí                                                                                                                                                                                                                            |
| --------------------------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Diagnostikovať**          | `GET /api/tools/agent-bridge/diagnose` | Spustí samočinný test zaznamenávacieho reťazca a zobrazí správu pre každú kontrolu (✓/✗ + odporúčanie na nápravu).                                                                                                                 |
| **Opraviť**                 | `POST /api/tools/agent-bridge/repair`  | Odstráni osirelý systémový stav MITM (položky falšovania DNS, koreňovú CA, systémový proxy server), ktorý zostal po páde alebo signáli SIGKILL. Operácia je idempotentná — ak je stav čistý, oznámi „Nie je čo opraviť“.           |
| **Odstrániť CA**            | `DELETE /api/tools/agent-bridge/cert`  | Zruší dôveru a odstráni koreňovú CA MITM z úložiska dôveryhodných certifikátov operačného systému (explicitne, idempotentne). | Názov kontroly     | Čo overuje                                                   | Odporúčanie pri zlyhaní                                                                                                                                                    |
| ------------------ | ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server-running`   | Proces servera MITM je aktívny                               | „Server MITM nie je spustený. Spustite ho na karte AgentBridge.“                                                                                                           |

Spustením opravy ho vyčistite.“_ — a zvýrazní tlačidlo **Opraviť**. `Repair` je ekvivalent príznaku `--cleanup` nástroja ProxyBridge na aplikačnej vrstve (deleguje na `repairMitm()` v `src/mitm/manager.ts`).

> opakovaným výzvam sudo (rovnaké správanie ako pri mitmproxy/Charles), takže jej odstránenie je explicitná
> akcia **Odstrániť CA**, a nie niečo, čo sa vykoná automaticky pri zastavení.

### 3.7 Import/export prenosnej konfigurácie

AgentBridge dokáže serializovať stav **nastaviteľný operátorom** do verzovaného objektu JSON, aby bolo možné rovnaké nastavenie replikovať medzi počítačmi. Serializátor je `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`) a validuje ho `AgentBridgeConfigSchema`.

Export obsahuje presne tri časti (zabudované predvolené hodnoty sa zámerne **NEEXPORTUJÚ**, takže ich import nikdy neduplikuje ani s nimi nekoliduje):

| Pole             | Zdroj                                                                   | Poznámky                                                                     |
| ---------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `bypassPatterns` | používateľom definované vzory obídenia (`agent_bridge_bypass`)          | predvolené vzory pre bank/gov/okta sú vylúčené                               |
| `customHosts`    | vlastné hostitele nástroja Traffic Inspector (`inspector_custom_hosts`) | každý: `{ host, kind: "llm"\|"app"\|"custom", label? }`                      |
| `agentMappings`  | mapovania modelov jednotlivých agentov (`agent_bridge_mappings`)        | `{ [agentId]: [{ source, target }] }` pre každého agenta, ktorý má mapovania |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**Správanie pri importe** (`POST /api/tools/agent-bridge/config`): vzory obídenia a mapovania jednotlivých agentov sa **úplne nahradia**; vlastné hostitele sa pridávajú **idempotentne** (`INSERT OR IGNORE`). Odpoveď uvádza, koľko položiek každého typu bolo použitých:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

Čo sa **NENACHÁDZA** v konfigurácii: stav spusteného servera, cesty k certifikátom, stav DNS jednotlivých agentov, cesta k nadradenej CA a nastavenia TPROXY — ide o stav hostiteľa alebo behového prostredia, nie o prenosné preferencie.

## §5 Zabezpečenie

### Použité pevné pravidlá

| Pravidlo                               | Použitie                                                                                             |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| **#12** `sanitizeErrorMessage`         | Všetky chyby obslužných rutín sa pred odpoveďou alebo zápisom do vyrovnávacej pamäte sanitizujú      |

### Zoznam výnimiek pre citlivých hostiteľov

Zoznam výnimiek zabezpečuje, že finančné inštitúcie, poskytovatelia OAuth/SSO a ďalší citliví hostitelia sa **nikdy nedešifrujú**. Ich prenos TLS prechádza cez transparentný tunel TCP — OmniRoute nikdy neuvidí nezašifrovaný obsah.

Predvolené vzory výnimiek zahŕňajú:

- `*.bank.*`, `*.gov.*` (finančné/verejná správa)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/identita)
- `*.apple.com`, `*.icloud.com` (systémové služby Apple)

Vzory výnimiek pridané používateľom sa ukladajú do tabuľky `agent_bridge_bypass` a majú prednosť pred všetkým ostatným.

### Maskovanie tajných údajov

Používa sa `maskSecrets()` zo súboru `src/mitm/maskSecrets.ts`:

- Na každé telo požiadavky pred `TrafficBuffer.push()`
- Na každú hlavičku pred zaznamenaním alebo vysielaním

Vzory: tokeny s predponou `sk-`/`ak-`/`pk-`, tokeny `Bearer` a všeobecné tokeny s dĺžkou ≥40 znakov.

### Certifikát upstream CA

Keď je nastavená premenná `AGENTBRIDGE_UPSTREAM_CA_CERT`, súbor sa načíta pri spustení. Ak cesta existuje, ale súbor nemožno prečítať, AgentBridge zaznamená zrozumiteľnú chybu a odmietne sa spustiť (zabráni sa tým tichým zlyhaniam TLS v podnikových prostrediach).

### Známe obmedzenia

- **Port 443 vyžaduje oprávnenie**: V systéme Linux potrebuje AgentBridge na binárnom súbore Node nastavenie `setcap 'cap_net_bind_service=+ep'` alebo musí byť spustený cez `authbind`. Sprievodca nastavením zobrazuje pokyny špecifické pre operačný systém.
- **Vyžaduje sa reštart IDE**: Po presmerovaní DNS sa musí IDE reštartovať, aby sa nové prekladanie názvov hostiteľov prejavilo.
- **Pevne uložené tokeny OAuth**: Niektorí agenti (Kiro, Antigravity) ukladajú obnovovacie tokeny OAuth lokálne. Pre AgentBridge sú transparentné — v každej požiadavke vidí token Bearer, ktorý sa pred zaznamenaním zamaskuje.
- **Klientske aplikácie Electron potrebujú `NODE_EXTRA_CA_CERTS`**: IDE, ktorých klientska časť beží v pribalenom prostredí Node/Electron, ignorujú úložisko dôveryhodných certifikátov operačného systému/NSS a musia sa spustiť zo shellu s nastavenou premennou `NODE_EXTRA_CA_CERTS` (pozrite si §3.2). Príznak pri jej absencii: backend IDE sa autentifikuje (MITM zobrazuje odpovede `200`), ale používateľské rozhranie zostáva odhlásené.
- **Viaceré inštalácie rovnakého IDE sú nezávislé**: systémová inštalácia (napr. `/usr/share/antigravity/antigravity`) a používateľská lokálna inštalácia „Full“ (napr. `~/AntigravityIDE_Full/antigravity-ide`) sú samostatné procesy s vlastnými runtime prostrediami — každá z nich sa musí znova spustiť s vloženou CA. Pred opätovným spustením identifikujte podľa cesty k binárnemu súboru, ktorá inštalácia je spustená.
- **Identitu určuje systémová výzva agenta, nie smerovaný model**: keď premapujete model agenta na iného poskytovateľa, odpoveď stále uvádza natívnu identitu agenta (napr. Antigravity odpovie „Používam Gemini“), pretože IDE ju vkladá do systémovej výzvy. Skutočný backend overte v `call_logs` / `proxy_logs` (`provider`, `model`, `target_format`), nie otázkou modelu, kým je.

## §6 Riešenie problémov

### Konflikt na porte 443

Ak na porte 443 už počúva iný proces (webový server, VPN atď.):

```bash
lsof -i :443          # vyhľadanie procesu
sudo fuser -k 443/tcp  # vynútené ukončenie (používajte opatrne)
```

Prípadne v nastaveniach AgentBridge nakonfigurujte neprivilegovaný port a nastavte pravidlá presmerovania `iptables` / `pf`.

### Certifikát nie je dôveryhodný

Ak IDE po spustení AgentBridge zobrazuje chyby TLS:

1. Overte, či bol certifikát nainštalovaný: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) alebo `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. Niektoré aplikácie používajú vlastné úložisko dôveryhodných certifikátov (Firefox, Chrome v systéme Linux). Znova spustite „Trust Cert“ a skontrolujte úložisko certifikátov špecifické pre NSS/Firefox.
3. Po pridaní certifikátu medzi dôveryhodné reštartujte IDE — prebiehajúce relácie TLS používajú predchádzajúci stav dôveryhodnosti.

### IDE je odhlásené / „chyba pripojenia“ napriek dôveryhodnej CA

Príznak: po presmerovaní DNS a pridaní CA medzi dôveryhodné sa IDE založené na Electron (napr. Antigravity)
otvorí **odhlásené** alebo zobrazí chybu overenia či pripojenia, hoci protokol MITM ukazuje, že
úvodné volania (`loadCodeAssist`, `fetchAvailableModels`, …) vracajú stav `200`.

Príčina: **runtime Node/Electron dodávaný spolu s IDE ignoruje systémové úložisko dôveryhodných certifikátov**. Natívny
backend (jazykový server v Go) dôveruje systémovej CA a úspešne sa overí, no frontend Electron
nie — používateľské rozhranie preto predpokladá, že je offline.

Riešenie (oba kroky): exportujte `NODE_EXTRA_CA_CERTS=<ca.crt>` **a znova spustite IDE z daného
shellu**, nie pomocou ikony na pracovnej ploche. Najprv IDE úplne ukončite — zámok jedinej inštancie Electron spôsobí,
že druhé spustenie iba aktivuje existujúci proces a nové prostredie sa ignoruje. Pozrite si §3.2.
Toto zodpovedá otvorenému hláseniu v nadradenom projekte, podľa ktorého samostatný agent funguje cez MITM, ale variant
IDE pri rovnakom nastavení zlyhá.

### DNS sa nepropagovalo

Skontrolujte, či bol súbor `/etc/hosts` aktualizovaný:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

Vyprázdnite vyrovnávaciu pamäť DNS:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### IDE nebolo rozpoznané

Automatická detekcia používa bežné cesty inštalácie. Ak detekcia zlyhá, ale IDE je nainštalované:

- Skontrolujte, či sa binárny súbor IDE nenachádza v neštandardnom umiestnení
- Sprievodca nastavením bude naďalej fungovať — zlyhanie detekcie znamená iba to, že odznak nezobrazí cestu inštalácie

### Chyby obslužného programu (načítanie z nadradeného servera zlyhá)

Ak AgentBridge zachytáva požiadavky, ale všetky zlyhajú:

1. Overte, či je na `/dashboard/providers` pripojený aspoň jeden poskytovateľ
2. Skontrolujte protokoly servera OmniRoute: `APP_LOG_LEVEL=debug` v `.env`
3. Overte, či `OMNIROUTE_BASE_URL` odkazuje na správny koncový bod smerovača (predvolené: `http://127.0.0.1:20128`)

Nasledujúce nástroje vo svojich aktuálnych verziách nepodporujú vlastné základné adresy URL, takže MITM je jediným spôsobom zachytávania. Posúdenie realizovateľnosti zatiaľ nebolo dokončené:
