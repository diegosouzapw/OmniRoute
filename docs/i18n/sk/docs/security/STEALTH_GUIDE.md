OmniRoute sa integruje s poskytovateľmi, ktorých okrajová infraštruktúra aktívne identifikuje neoficiálnych klientov podľa digitálnych odtlačkov (TLS JA3/JA4, poradie hlavičiek, štruktúra tela JSON, tokeny integrity). Táto stránka dokumentuje stealth rozhrania, ktoré OmniRoute poskytuje, a miesta ich implementácie.

## Právne a etické upozornenie

Stealth funkcie existujú preto, aby OmniRoute mohol slúžiť ako vrstva kompatibility medzi oficiálnymi účtami vo vlastníctve používateľov (Claude Code CLI, Codex, Antigravity, Cursor atď.) a zjednoteným API OmniRoute. **Nie sú** určené na obchádzanie detekcie podvodov, zdieľanie prihlasovacích údajov ani porušovanie zmluvných podmienok poskytovateľov. Správcovia očakávajú, že prevádzkovatelia budú dodržiavať podmienky používania nadradených služieb, s ktorými súhlasili pri vytváraní účtov.

## Vrstva identifikácie podľa odtlačku TLS

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

Perzistentné relácie `wreq-js` sa vytvárajú lenivým spôsobom pre každý rozsah účtu a vyriešený proxy server. Fond `TlsClient` platný pre celý proces obsahuje najviac 128 relácií, ktoré pre nadradené služby chránené službou Cloudflare napodobňujú **Chrome 124 v systéme macOS**. `TlsClient.fetch()` zlyhá bezpečným spôsobom, keď natívne runtime prostredie nie je dostupné; volajúci môže explicitne zvoliť záložný mechanizmus mimo tohto obalu.

- Profil relácie: `browser: "chrome_124", os: "macos"`
- Rozlíšenie proxy servera (priorita): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (aj varianty s malými písmenami)
- Časový limit: `TLS_CLIENT_TIMEOUT_MS` (preberá hodnotu z `FETCH_TIMEOUT_MS`, predvolená hodnota 600000)
- Response z `wreq-js` je kompatibilná s fetch (`headers`, `text()`, `json()`, `clone()`, `body`).
- Strážny mechanizmus prvého bajtu (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656): `TlsClient.fetch()`
  sa dokončí hneď po doručení hlavičiek z nadradenej služby, takže samotný `TLS_CLIENT_TIMEOUT_MS` nedokáže obmedziť
  telo, ktoré nikdy neposkytne prvý bajt. `guardTlsFirstByte()` súbežne spustí prvé `read()` tela
  a časový limit `TLS_FIRST_BYTE_WATCHDOG_MS` (predvolená hodnota `10000`, hodnota `0` ho deaktivuje); zdravé telo
  to neovplyvní, zatiaľ čo pri zaseknutom tele zruší čítačku wreq a umožní existujúcej
  logike záložného TLS mechanizmu v `proxyFetch` prejsť na priamy/proxy dispečer (požiadavka, ktorú nemožno bezpečne zopakovať, napr.
  POST s telom, aj naďalej vyvolá chybu namiesto toho, aby sa bez upozornenia zopakovala).

### Prenos poskytovateľov s webovými cookies — wreq-js 3.2.0

`open-sse/services/tlsClientBase.ts` je spoločný adaptér pre päť špecializovaných
prenosov s webovými cookies uvedených nižšie. Každý tenký obal poskytovateľa vyberá profil prehliadača/operačného systému. Adaptér
používa jediný načítavač runtime prostredia wreq a fond prenosov v `open-sse/utils/tlsClient.ts`, kľúčovaný podľa
profilu + OS + vyriešeného proxy servera, pričom každá požiadavka používa `cookieMode: "ephemeral"`. Účty a
požiadavky preto zdieľajú pripojenia na úrovni prenosu, ale nikdy nie reláciu wreq ani úložisko cookies.

| Poskytovateľ | Profil        | Emulovaný OS | Pravidlo EOF streamu                     |
| ------------ | ------------- | ------------ | ---------------------------------------- |
| Claude       | `chrome_146`  | Linux        | zahrnúť `[DONE]`                         |
| Perplexity   | `firefox_148` | macOS        | zahrnúť `event: end_of_stream`           |
| Grok         | `chrome_146`  | Linux        | vylúčiť `[DONE]`                         |
| Notion       | `chrome_146`  | Windows      | zahrnúť `[DONE]`                         |
| LMArena      | `chrome_146`  | Windows      | bez sentinelu; zatvoriť pri natívnom EOF |

- Streamovanie spotrebúva natívny `ReadableStream` odpovede priamo; nevytvára sa žiadny dočasný súbor ani
  pomocný proces.
- Pred sprístupnením streamu sa skontroluje najviac 256 úvodných bajtov. Poskytovatelia SSE ukladajú chyby, ktoré nie sú SSE, do vyrovnávacej pamäte;
  Grok/LMArena mapujú výzvy Cloudflare na `403` a prechodné stránky HTML na `502`.
- Časový limit natívnej požiadavky zostáva ohraničený absolútnym pevným termínom v JS. Zaseknutie zneplatní
  a zatvorí iba dotknutý prenos pre kombináciu profil/OS/proxy server; ďalšia požiadavka ho následne znova vytvorí.
- Priorita rozlíšenia proxy servera je `proxyUrl` pre jednotlivé volanie → kontext účtu/ovládacieho panela v rozsahu požiadavky →
  `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (vrátane variantov s malými písmenami). Chyby rozlíšenia spôsobia
  bezpečné zlyhanie namiesto úniku priameho pripojenia. LMArena zámerne vykonáva rozlíšenie voči `arena.ai`.
- `byteResponse` vracia URL `data:` s typom obsahu bez poškodenia UTF-8.
- Chyby sú `TlsClientUnavailableError` (balík/doplnok nie je dostupný), `TlsClientHangError`
  (prekročený termín) a `WreqTransportCapacityError` (zdieľaný kód chyby kapacity relácií),
  keď je všetkých 128 ohraničených slotov pre kombinácie profil/OS/proxy server aktívnych alebo sa zatvára.

Vyššie uvedená všeobecná relácia `TlsClient` zostáva špecializovaná na perzistentný stav cookies spravovaný prehliadačom.
Obe cesty opakovane používajú jeden načítavač modulu wreq uložený vo vyrovnávacej pamäti a jeden hák životného cyklu procesu; ich fondy zostávajú
oddelené, pretože životnosti ich cookies sú zámerne odlišné.

Pripnutý balík tieto profily podporuje, ale skutočné prijatie zo strany WAF sa môže meniť nezávisle
od lokálnych zmluvných testov. Pred vyhlásením zhody s nadradeným prehliadačom overte zmeny odtlačkov
pomocou explicitne autorizovaného živého účtu.

## Balík utajenia Claude Code

Keď je zapnutý režim `cliCompatMode`, OmniRoute upravuje odchádzajúce požiadavky Claude tak, aby boli nerozoznateľné od prevádzky `claude-cli`. Spolupracujú na tom tri moduly:

### `claudeCodeFingerprint.ts`

Vypočítava 3-znakový odtlačok `cc_version` vložený do fakturačnej hlavičky:

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (pevne zakódované; zodpovedá oficiálnemu klientovi)
- Vstupy: znaky na indexoch 4, 7 a 20 textu prvej správy používateľa + reťazec verzie
- Výstup: 3-znakový hexadecimálny prefix

### `claudeCodeCCH.ts` (hash obsahu klienta)

Kontrola integrity na strane servera, ktorú oficiálne CLI Claude Code vypočítava prostredníctvom Bun/Zig. OmniRoute ju opätovne implementuje pomocou `xxhash-wasm`:

1. Serializuje telo so zástupným reťazcom `cch=00000;`
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. 5-znakový hexadecimálny reťazec malými písmenami doplnený nulami
4. Nahradí `cch=00000;` vypočítaným tokenom

Konštanty:

- Počiatočná hodnota: `0x6e52736ac806831e`
- Vzor: `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

Vkladá znak Unicode **spojovník s nulovou šírkou** (`U+200D`) za prvý znak „citlivých“ názvov klientov, aby ich nadradené filtre nemohli vyhľadať pomocou grep. Predvolený zoznam slov:

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

Používa sa na: bloky `system`, celý obsah `messages[].content` a `tools[].description` / `tools[].function.description`. Operátor ho môže prepísať pomocou `setSensitiveWords()`.

### `claudeCodeCompatible.ts` — poskytovatelia `anthropic-compatible-cc-*`

Pre relé Anthropic tretích strán, ktoré akceptujú iba prevádzku „skutočného Claude Code“:

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.258 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"` v predvolenom nastavení
- Prepínač „Povoliť beta verziu redact-thinking“ pre jednotlivé pripojenia pridáva `redact-thinking-2026-02-12`, keď nadradená služba kompatibilná s CC výslovne vyžaduje redigované prúdy uvažovania
- Prepínač „Povoliť zobrazenie zhrnutého uvažovania“ pre jednotlivé pripojenia uloží `providerSpecificData.requestDefaults.summarizeThinking` a pridá `display: "summarized"` k požiadavkám uvažovania kompatibilným s CC, ktoré ešte nemajú nastavený režim zobrazenia
- `CONTEXT_1M_BETA_HEADER = "context-1m-2025-08-07"` (rodina Opus/Sonnet 4.x)
- Predvolená cesta: `/v1/messages?beta=true`

Súvisiace moduly v rovnakom balíku:

- `claudeCodeConstraints.ts` — pravidlá teploty a riadenia vyrovnávacej pamäte
- `claudeCodeToolRemapper.ts` — premapovanie názvov nástrojov
- `claudeCodeExtraRemap.ts` — dodatočná normalizácia dátovej časti

## Utajenie Antigravity

Požiadavky Antigravity zachovávajú text volajúceho presne po bajtoch. OmniRoute nevkladá do promptov znaky s nulovou šírkou ani nepremenúva či nevkladá nástroje s cieľom napodobniť klienta IDE.

### `antigravityHeaderScrub.ts`

Pred preposlaním odstraňuje značky SDK Stainless (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`).

### ⚠️ Riziko: `ANTIGRAVITY_CREDITS=always` (častý dôvod zablokovania účtu)

`ANTIGRAVITY_CREDITS=always` (spracovávané súborom `open-sse/executors/antigravity.ts`) smeruje **každú** požiadavku cez nadlimitné kredity Antigravity AI Credit Overages (platené kredity Google) namiesto toho, aby prístup obmedzovala kvóta bezplatnej úrovne Google. Je to zdokumentované ako funkcia, ale ide o **jednoznačne najčastejšie hlásené porušenie zmluvných podmienok, s ktorým sa stretávame** — po niekoľkohodinovej prevádzke s nastavením `=always` bolo zablokovaných viacero účtov Google Ultra s chybou `403 / "service disabled for ToS violation" / insufficient_quota`.

Vynucovanie vykonáva **Google**, nie je to niečo, čomu by OmniRoute mohol zabrániť. Názov premennej prostredia a existujúca dokumentácia vyvolávajú dojem, že ide o bezpečný prepínač; nie je to tak.

**Prečo to spúšťa detekciu zneužitia agresívnejšie než používanie iba bezplatnej úrovne:**

- Nepretržité automatizované výdavky na jednom účte Google sa vyhodnocujú inak než bezplatná úroveň, ktorá dosiahne kvótu a zastaví sa.
- Nadlimitné kredity nemajú strop frekvencie požiadaviek, takže nesprávne nakonfigurovaný klient môže za niekoľko minút minúť stovky USD a vyzerať ako ďalší predaj API kľúčov alebo prevádzka botov.
- Ak viacero používateľov OmniRoute súbežne čerpá nadlimitné kredity z rovnakej externej IP adresy, tento signál sa zosilňuje.

**Odporúčaný postup:**

1. Ponechajte predvolené nastavenie `ANTIGRAVITY_CREDITS=off`, pokiaľ operátor výslovne neakceptuje riziko platených kreditov a sankcií voči účtu. Režim `retry` najprv odošle bežnú požiadavku a kredity vloží najviac raz po oprávnenej chybe kvóty 429; režim `always` vloží kredity už pri prvej požiadavke.
2. **Rozložte záťaž medzi poskytovateľov pomocou Auto-Combo** (`model: "auto"` alebo kombinácie `kr/glm/etc`) namiesto preťažovania jedného účtu Antigravity.
3. **Nastavte limity RPM pre jednotlivé pripojenia** na stránke úprav poskytovateľa Antigravity (Dashboard → Providers → Antigravity → pripojenie → limit frekvencie). Hodnota 30–60 RPM je obhájiteľnou hornou hranicou pri nepretržitom používaní.
4. **Používajte stabilnú nadradenú sieť spravovanú operátorom** a vyhnite sa zdieľaniu jedného účtu medzi nesúvisiacimi používateľmi alebo pracovnými záťažami.
5. **V prípade zablokovania**: podajte odvolanie cez `support.google.com` → „Restore Workspace/Account access“ s presným telom odpovede `quota_exceeded` / `service disabled`, ktoré odoslal Google. Obnovenie nie je zaručené.

Referenčná dokumentácia prostredia opisuje vplyv každého režimu kreditov na účet a výdavky.

Dotknuté miesta:

- `open-sse/executors/antigravity.ts` — číta `process.env.ANTIGRAVITY_CREDITS`
- `src/lib/oauth/providers/antigravity.ts` — spracovanie prihlasovacích údajov
- Pôvodné hlásenie incidentu: diskusia [#1183](https://github.com/diegosouzapw/OmniRoute/discussions/1183)

## Register odtlačkov CLI — `open-sse/config/cliFingerprints.ts`

Tabuľka pre jednotlivých poskytovateľov, ktorá určuje **presné** poradie hlavičiek a polí v tele JSON zachytené zo záznamov mitmproxy oficiálnych CLI. Aktuálne sú registrované: `codex`, `claude` a profily odvodené za behu v `providerHeaderProfiles.ts` pre `antigravity` a `github`.

```ts
interface CliFingerprint {
  headerOrder: string[]; // rozlišuje veľké a malé písmená
  bodyFieldOrder: string[]; // JSON kľúče najvyššej úrovne
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

Prepína sa pre každého poskytovateľa prostredníctvom premenných prostredia (pozri nižšie). Keď je táto funkcia zakázaná, hlavičky/kľúče tela sa zobrazia v ľubovoľnom poradí, v akom ich poskytol Node/JSON — takže sa dajú ľahko identifikovať podľa odtlačku.

## MITM proxy (Antigravity, Linux/macOS/Windows)

Pre CLI, ktorých binárne súbory nemožno presmerovať pomocou `OPENAI_BASE_URL`, OmniRoute spúšťa lokálny proxy server ukončujúci TLS. Koncové body sa nachádzajú v `src/app/api/cli-tools/antigravity-mitm/`.

| Metóda | Koncový bod                             | Účel                                              |
| ------ | --------------------------------------- | ------------------------------------------------- |
| GET    | `/api/cli-tools/antigravity-mitm`       | Stav — spustený, pid, dnsConfigured, certExists   |
| POST   | `/api/cli-tools/antigravity-mitm`       | Spustiť MITM (vyžaduje `apiKey` + `sudoPassword`) |
| DELETE | `/api/cli-tools/antigravity-mitm`       | Zastaviť MITM                                     |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | Zobraziť aliasy modelov                           |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | Uložiť aliasy modelov pre nástroj                 |

Cieľový zachytávaný hostiteľ: **`daily-cloudcode-pa.googleapis.com`** (upstream služby Antigravity).

### Postup spustenia (`src/mitm/manager.ts::startMitm`)

1. Vygenerovať certifikát s vlastným podpisom pomocou `selfsigned` (RSA-2048, SHA-256, 1 rok) — `cert/generate.ts`
2. Nainštalovať certifikát do systémového úložiska dôveryhodných certifikátov — `cert/install.ts`
3. Pridať záznam hostiteľa `127.0.0.1 daily-cloudcode-pa.googleapis.com` — `dns/dnsConfig.ts`
4. Spustiť `src/mitm/server.cjs` s `ROUTER_API_KEY` + `MITM_LOCAL_PORT` (predvolene `443`)
5. Uložiť PID do `<DATA_DIR>/mitm/.mitm.pid`

### Dynamická detekcia úložiska dôveryhodných certifikátov v Linuxe — `cert/install.ts`

`getLinuxCertConfig()` prechádza zoznam podľa priority a vyberie prvý existujúci adresár:

| Rodina distribúcií       | Adresár                                     | Príkaz na aktualizáciu   |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

Názov súboru certifikátu: `omniroute-mitm.crt`. Zhoda odtlačku prostredníctvom `getCertFingerprint()` (SHA-1 údajov DER).

Okrem toho `updateNssDatabases()` nainštaluje certifikát do databáz NSS jednotlivých používateľov, keď je k dispozícii `certutil`: `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, všetky profily Firefoxu (vrátane verzie snap), pod prezývkou **`OmniRoute MITM Root CA`**.

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** PowerShell spustený so zvýšenými oprávneniami → `certutil -addstore Root`

### Autentifikácia

Všetky koncové body MITM vyžadujú autentifikáciu pre správu (`requireCliToolsAuth`). Heslo sudo sa ukladá do vyrovnávacej pamäte v rozsahu modulu (nikdy nie v `globalThis`) a vymaže sa pri volaní `stopMitm()`.

## Sanitizácia prichádzajúcich hlavičiek

OmniRoute pred odoslaním ďalej odstraňuje hlavičky prichádzajúce od klienta, aby požiadavka prijatá z Cursor neprezradila nadradenému serveru Claude hlavičku `User-Agent: Cursor/X.Y.Z`. Zoznam zakázaných hlavičiek nájdete v `src/shared/constants/upstreamHeaders.ts`; udržiava sa synchronizovaný so schémami Zod a jednotkovými testami.

## Aktualizácia odtlačkov pri ich zmene poskytovateľom

1. Zachyťte oficiálnu komunikáciu CLI pomocou `mitmproxy` (zachytenie TLS + výpis)
2. Extrahujte JA3/JA4 a doslovné poradie hlavičiek
3. Aktualizujte príslušnú položku `CLI_FINGERPRINTS[...]`
4. Aktualizujte zodpovedajúcu predvolenú hodnotu `*_USER_AGENT` v `.env.example`
5. Ak sa zmenilo samotné nadviazanie spojenia TLS, aktualizujte príslušný adaptér poskytovateľa alebo možnosť `browser:` knižnice wreq-js
6. Spustite testy TLS špecifické pre poskytovateľa a manuálny kanárikový test voči živému poskytovateľovi
7. Vydať ako opravnú verziu; zdokumentovať v `CHANGELOG.md`
