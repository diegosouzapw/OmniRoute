Tento dokument predstavuje potvrdenie autora a správcu k šiestim zisteniam
`AI-detected potential malware` nahláseným pre `omniroute@3.8.5` a
k zmierneniam implementovaným v `omniroute@3.8.6`. Existuje preto, aby:

1. Prevádzkovatelia bezpečnostných pipeline mali jednotný referenčný dokument,
   na ktorý sa môžu odvolať pri vyhodnocovaní zistení voči skutočnému zdrojovému kódu.
2. Budúce AI skenery mohli zachytiť správcom podpísané vyhlásenie, že každá
   označená cesta je zámerná, voliteľná a zdokumentovaná.
3. Sme mali písomný záznam o tom, _prečo_ má každé miesto volania danú podobu —
   aby budúci refaktoring náhodou znovu nezaviedol odtlačok, ktorý bol
   zámerne odstránený.

Ak prevádzkujete skener, ktorý po vydaní zmiernení vo v3.8.6 opätovne označí
ktorékoľvek z nižšie uvedených miest volania, otvorte problém so záznamom
skenovania a toto potvrdenie doplníme.

## §1 — Inštalácia koreňovej CA pre MITM (`77484.js`)

**Zdrojové súbory**:

- `src/mitm/cert/install.ts` — verejné `installCert()` / `uninstallCert()`,
  funkcie `installCertWindows/Mac/Linux` pre jednotlivé platformy.
- `src/mitm/systemCommands.ts` — zdieľané pomocné funkcie `execFile` / `spawn` /
  PowerShell používané inštalačnými cestami.

**Spúšťač**: používateľ klikne na „Povoliť MITM proxy“ v lokálnom ovládacom paneli
na adrese `/dashboard/cli-tools/mitm`. Trasa je dostupná iba cez loopback —
pozrite si pevné pravidlo č. 17 v `CLAUDE.md` a
`src/server/authz/routeGuard.ts::isLocalOnlyPath()`. Uniknutý JWT sprístupnený
prostredníctvom tunela **nemôže** spustiť túto cestu kódu.

**Vykonávané privilegované operácie (podľa platformy)**:

| OS                     | Príkaz(-y)                                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | `certutil -addstore Root <cert>` cez UAC                                                                          |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | aktualizácia databázy NSS pre každý profil pomocou `certutil -d sql:<profile>`                                    |

Ide o rovnaké príkazy, aké používajú `mitmproxy`, Charles Proxy, Fiddler a
Caddy. Skutočnosť, že sa nachádzajú v OmniRoute, je zdokumentovaná v
`docs/security/STEALTH_GUIDE.md`.

**Zmiernenie vo v3.8.6**:

- `runElevatedPowerShell()` už nepoužíva `-EncodedCommand <base64utf16le>`.
  Privilegovaný obsah sa zapisuje do dočasného súboru `.ps1` pre každé volanie
  (režim 0o600, v súkromnom adresári `mkdtempSync`) a odkazuje sa naň
  prostredníctvom `-File`. Súbor sa odstráni v bloku `finally`. Tým sa
  odstraňuje typický odtlačok eskalácie oprávnení cez PowerShell pomocou base64,
  ktorý označil AI klasifikátor Socket.dev.
- `installCertWindows` obsahuje vložený blok `SECURITY-AUDITOR-NOTE:`,
  ktorý odkazuje na tento dokument.

**Prečo túto funkcionalitu zachovávame**: MITM proxy je zdokumentovaná funkcia
používaná v `docs/security/STEALTH_GUIDE.md` a
`docs/frameworks/MITM-PROXY.md`. Jej odstránenie by narušilo súbor funkcií
agent-bridge.

## §2 — Import prihlasovacích údajov zo Zed (`app/api/providers/zed/import/route.js`)

**Zdrojové súbory**:

- `src/app/api/providers/zed/discover/route.ts` _(nové vo v3.8.6)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(nové vo v3.8.6)_

**Spúšťač**: používateľ klikne na „Importovať zo Zed“ na stránke Poskytovatelia v lokálnom ovládacom paneli. Koncový bod je chránený pomocou `requireManagementAuth`. Samotný editor Zed zapisuje API kľúče svojich poskytovateľov do systémovej kľúčenky pod zdokumentovanými názvami služieb — pozrite si https://zed.dev/docs/ai/llm-providers.

**Správanie vo v3.8.5 (ktoré označil Socket.dev)**:

`POST /import` vyhľadal prihlasovacie údaje a automaticky ich uložil do lokálneho úložiska SQLite v rámci jediného cyklu požiadavky a odpovede. Žiadne potvrdenie pre jednotlivé účty, žiadny odtlačok, iba „nájdených N tokenov, všetky importované“.

**Zmiernenie vo v3.8.6 — dvojkrokové potvrdenie**:

1. **`POST /api/providers/zed/discover`** vráti
   `{ candidates: [{ provider, service, account, fingerprint }] }`. Nespracovaný
   token sa **nikdy** neprenáša. Odtlačok je
   `sha256(service|account|token).slice(0,16)`.
2. Ovládací panel zobrazí zoznam kandidátov, operátor vyberie, ktoré z nich sa
   majú importovať, a odošle `{ confirmedAccounts: [{ service, account, fingerprint }] }`
   na **`POST /api/providers/zed/import`**.
3. Koncový bod importu **opätovne načíta kľúčenku na serveri** a filtruje podľa
   `(service, account, fingerprint)`. Pozmenená alebo opakovane použitá odpoveď
   z vyhľadávania nemôže oklamať koncový bod importu tak, aby uložil nesúvisiaci
   token — ak sa aktuálny token od vyhľadania zmenil, odtlačok sa už nezhoduje
   a prihlasovací údaj sa preskočí.

Príznak prostredia `OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` zachováva
správanie z v3.8.5 pre operátorov, ktorí ešte neaktualizovali svoju automatizáciu.
Vo v3.9 bude odstránený.

**Prečo to zachovávame**: import zo Zed je najjednoduchší spôsob úvodného
nastavenia pre používateľov, ktorí už používajú Zed a chcú skopírovať kľúče
svojich poskytovateľov do OmniRoute bez ich opätovného vkladania.

## §3 — `execFile` / `spawn` / PowerShell so zvýšenými oprávneniami (`21843.js`)

**Zdrojové súbory**: `src/mitm/systemCommands.ts`.

**Prečo to bolo označené**: balík opätovne exportuje `execFileWithPassword`,
`runElevatedPowerShell` a zdieľanú pomocnú funkciu `quotePowerShell`. Klasifikátor
AI služby Socket.dev ich považuje za všeobecnú „sadu nástrojov na vykonávanie
príkazov na hostiteľovi a zvyšovanie oprávnení“. V rámci OmniRoute sa používajú
iba v procese inštalácie certifikátu MITM (§1) a prostredníctvom
`execFileWithPassword` na vykonávanie príkazov `sudo`.

**Zmiernenie vo v3.8.6**:

- Refaktorizácia `runElevatedPowerShell` (pozrite §1).
- Vložený blok `SECURITY-AUDITOR-NOTE:` pri `runElevatedPowerShell` aj
  `execFileWithPassword` dokumentuje volajúcich na zozname povolených položiek
  a pevne určený zoznam spustiteľných súborov.
- Volanie `spawn()` v `execFileWithPassword` obsahuje značku `nosemgrep` so
  zoznamom povolených spustiteľných súborov, ktoré môže pomocná funkcia prijať —
  **neexistuje žiadna cesta z používateľského vstupu do `finalCommand`/`finalArgs`**.

## §4 / §6 — Správca služby 9router (`api/services/9router/{start,restart}/route.js`)

**Zdrojové súbory**:

- `src/app/api/services/9router/_lib.ts` — vytváracia funkcia správcu.
- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`.
- `src/lib/services/ServiceSupervisor.ts` — všeobecné spúšťanie / kontrola stavu / vyrovnávacia pamäť protokolov.

**Spúšťač**: používateľ klikne na „Inštalovať“ / „Spustiť“ na stránke vstavaných
služieb v lokálnom ovládacom paneli.

**Už implementované ochranné opatrenia**:

- Všetky trasy `/api/services/*` sú podľa
  `src/server/authz/routeGuard.ts` nastavené ako LOCAL_ONLY (pevné pravidlo č. 17).
  Vynútenie spätnej slučky prebehne pred akoukoľvek kontrolou autentifikácie —
  uniknutý token JWT sa k nim nedostane.
- Riadok 9router v databáze je inicializovaný ako `status='not_installed', auto_start=0`
  (pozrite `src/lib/db/migrations/071_services.sql:19`). Služba sa pri prvom
  spustení **nespustí**.
- Funkcia `spawn()` sa volá s cestou k binárnemu súboru, ktorú vráti
  `resolveSpawnArgs(apiKey, PORT)` v `src/lib/services/installers/ninerouter.ts`,
  čo je pevný zoznam podporovaných binárnych súborov.
- Stdout/stderr sa ukladajú do vyrovnávacej pamäte v operačnej pamäti (limit 5 MB,
  pozrite `_lib.ts`) — bez zápisu na disk, pokiaľ používateľ nepovolí
  protokolovanie v ovládacom paneli.

**Zmiernenie vo v3.8.6**: bez funkčnej zmeny. Minimálny profil zostavenia
(`OMNIROUTE_BUILD_PROFILE=minimal`) nahrádza
`src/lib/services/installers/ninerouter.ts` zástupnou implementáciou pre
používateľov, ktorí chcú privilegované cesty fyzicky odstrániť z balíka.

**Prečo to zachovávame**: 9router je voliteľná, lokálne inštalovateľná sprievodná
služba (predstavte si doplnok v štýle WordPressu) — výhradne na základe
výslovného súhlasu.

## §5 — Spätný zápis prihlasovacích údajov OmniRoute Cloud Sync (`api/keys/[id]/route.js`)

**Zdrojové súbory**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`.
- `src/app/api/keys/[id]/route.ts` — volá `syncKeysToCloudIfEnabled()`.

**Spúšťač**: `isCloudEnabled()` vráti `true` (nastavuje sa z ovládacieho panela) **a zároveň**
je nakonfigurovaná premenná `CLOUD_URL`. Ak sú obe možnosti vypnuté, na
koncový bod služby Cloud sa nevykoná žiadne odchádzajúce sieťové volanie.

**Správanie vo v3.8.5 (chyba, ktorú Socket.dev správne zachytil)**:

`updateLocalTokens()` prepísala hodnoty `accessToken`, `refreshToken` a
`providerSpecificData` z odpovede služby Cloud, keď platilo
`cloudUpdatedAt > localUpdatedAt`. Bez HMAC, bez podpisu, bez kontrolného súčtu.
Nesprávne nakonfigurovaná alebo škodlivá hodnota `CLOUD_URL` (prípadne útok
MITM na komunikačný kanál) mohla nepozorovane zameniť tokeny OAuth
poskytovateľa.

**Zmierenie rizika vo v3.8.6**:

1. **Overenie HMAC**: `verifyCloudSignature(rawBody, sigHeader)` kontroluje
   hlavičku `X-Cloud-Sig` (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`) pred spracovaním JSON. Ak je tajný kľúč nastavený, podpis je
   povinný. Ak nastavený nie je (starší režim), zaznamená sa upozornenie a
   odpoveď sa prijme — vo v3.9 bude tajný kľúč povinný.
2. **Výslovné povolenie tajných polí**: `accessToken` / `refreshToken` /
   `providerSpecificData` sa prepíšu **iba** vtedy, keď
   `OMNIROUTE_CLOUD_SYNC_SECRETS=true`. Predvolený režim synchronizuje iba
   metadáta, ktoré nie sú prihlasovacími údajmi (`expiresAt`, `status`,
   `lastError*`, `rateLimitedUntil`, `updatedAt`). Ide o **nekompatibilnú
   zmenu** pre používateľov, ktorí sa spoliehali na vzdialenú synchronizáciu
   tokenov — musia ju výslovne povoliť.

**Prečo túto funkciu zachovávame**: Cloud Sync je jediný spôsob, ako môže
nájomník OmniRoute Cloud centralizovať tímové prihlasovacie údaje. Oprava
otvorene definuje model hrozieb: „server podpisuje, klient overuje,
prevádzkovateľ výslovne povoľuje“.

## Profil zostavenia: `minimal`

Používatelia, ktorí potrebujú artefakt kompatibilný so službou Socket, ho
môžu zostaviť pomocou:

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

Webpackový doplnok `NormalModuleReplacementPlugin` nahrádza štyri moduly ich
zástupnými implementáciami:

| Modul                                       | Zástupná implementácia                           |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

Každá zástupná implementácia exportuje rovnaké rozhranie, ale každá funkcia
počas behu vyvolá `featureDisabledError(name)`. Trasy závislé od zakázaného
modulu vrátia HTTP 503 s jasnou správou namiesto aktivovania citlivej cesty
kódu.

Výsledný balík je určený na publikovanie ako `omniroute-secure`. Postup
publikovania nájdete v súbore `docs/ops/PUBLISHING_SECURE.md`.

## Rozdelenie pluginu (sledované pre v4)

Z dlhodobého hľadiska plánujeme rozdeliť balík npm na samostatne auditovateľné
moduly. Príslušný problém nájdete v míľniku v4 v nástroji na sledovanie problémov
na GitHube.
