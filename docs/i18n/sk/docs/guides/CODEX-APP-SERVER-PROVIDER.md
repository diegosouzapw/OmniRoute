---

OmniRoute ponúka **dva** spôsoby používania OpenAI Codex:

| Poskytovateľ           | Ako komunikuje s OpenAI                                                                                                                                                                        | Upozornenie týkajúce sa používania                                             |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| **`codex`**            | Odosiela váš OAuth token ChatGPT/OpenAI priamo do Responses API                                                                                                                                | **Áno** — oficiálna relácia nie je autorizovaná na použitie cez proxy/smerovač |
| **`codex-app-server`** | Ovláda **vlastný `codex app-server` rozhrania Codex CLI** cez JSON-RPC/WebSocket; CLI vlastní a samo obnovuje svoje OAuth údaje (`~/.codex/auth.json`) presne ako interaktívna relácia `codex` | **Nie** — OmniRoute nikdy neodosiela token do API                              |

Keďže `codex-app-server` nikdy neodosiela token, nevzťahuje sa naň
upozornenie týkajúce sa používania opakovaným odosielaním relácie. Vyžaduje však
**Codex CLI dostupné na nakonfigurovanej URL adrese app-servera** a toto CLI musí
byť **prihlásené**.

---

## 1. Architektúra

```
┌─ Aplikácia OmniRoute ────────────┐        ┌─ Sprievodný kontajner codex-app-server ┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                      │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456            │
│  (+ token oprávnenia)            │  JSON  │  --ws-auth capability-token            │
│                                  │  RPC   │  samostatne spravuje OpenAI OAuth       │
└──────────────────────────────────┘        │  (~/.codex/auth.json, automatická obnova)│
        │ zdieľa (zväzky compose)            └────────────────────────────────────────┘
        ▼
  codex-appserver-token   → token oprávnenia WS (pripájajú ho oba kontajnery)
  codex-appserver-home    → ~/.codex (auth.json zapisovaný ovládacím panelom,
                             čítaný procesom codex app-server v sprievodnom kontajneri)
```

- Sprievodný kontajner počúva **iba** v internej sieti compose
  (`ws://codex-app-server:1456`) a je chránený tokenom oprávnenia. **Nikdy**
  nie je sprístupnený hostiteľovi ani internetu.
- Codex CLI je zabudované do `omniroute:base`, takže pri spustení sprievodného
  kontajnera nie je potrebné inštalovať codex na hostiteľovi ani v zariadení
  používateľa.

## 2. Spustenie

```bash
# Spustenie zostavy S profilom sprievodného kontajnera codex app-server:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

Sprievodný kontajner pri prvom spustení vytvorí svoj token oprávnenia WS (v
zdieľanom zväzku `codex-appserver-token`) a aplikácia načíta rovnaký token
prostredníctvom `OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE`. Nie je potrebné
žiadne manuálne nastavovanie tokenu.

## 3. Pripojenie a prihlásenie

1. V ovládacom paneli pridajte pripojenie pre **OpenAI Codex (App-Server)**.
   Nevyžaduje sa žiadny API kľúč ani token (ide o poskytovateľa bez autentifikácie
   — autentifikáciu spravuje sprievodný kontajner).
2. Ak Codex CLI sprievodného kontajnera **ešte nie je prihlásené**, kontrola
   stavu pripojenia hlási _„spustené, ale neprihlásené“_ (nejde o červenú chybu
   autentifikácie). Použite možnosť **Prihlásiť sa pomocou ChatGPT**: tým sa vo
   vašom prehliadači spustí štandardný proces Codex device-OAuth a následne sa
   prostredníctvom možnosti **Použiť autentifikačné údaje** zapíše
   `~/.codex/auth.json` do zdieľaného zväzku (jedno prihlásenie slúži
   poskytovateľom `codex` aj `codex-app-server`).
3. Po prihlásení sa kontrola stavu zmení na zelenú (overuje `/readyz` **aj**
   `account/read` — teda či je služba spustená _aj_ autentifikovaná) a služba
   začne fungovať.

Ovládací panel nikdy neprepíše funkčný existujúci súbor
`~/.codex/auth.json` — zapisuje ho iba vtedy, keď súbor neexistuje alebo je jeho
token zastaraný (vždy sa vytvorí záloha).

## 4. Scenáre nasadenia

- **Prevádzkovateľ s už autentifikovaným Codex CLI** — pripojte svoje
  hostiteľské `~/.codex` do sprievodného kontajnera (`codex-appserver-home`) a
  preskočte krok prihlásenia.
- **Verejný používateľ bez lokálne nainštalovaného codex** — na tom nezáleží:
  sprievodný kontajner obsahuje CLI. Používateľ sa autentifikuje iba
  prostredníctvom ovládacieho panela.
- **OmniRoute na fyzickom serveri (bez sprievodného kontajnera, codex na
  hostiteľovi)** — nastavte `OMNIROUTE_CODEX_APPSERVER_WS` na svoj vlastný
  `codex app-server` a uistite sa, že codex na hostiteľovi je prihlásený; ak
  binárny súbor chýba, zobrazí sa upozornenie „codex nie je nainštalovaný“.

## 5. Rezidenčný odchádzajúci prenos / UDP (doplnok prevádzkovateľa, nie je súčasťou distribúcie)

Vyššie uvedený všeobecný sprievodný kontajner smeruje odchádzajúci prenos cez
bežnú sieť kontajnera. Prevádzkovateľ, ktorý potrebuje smerovať prenos Codex cez
**rezidenčný výstupný uzol** (napr. sprievodný kontajner tailscale s rozhraním
TUN prenášajúci TCP + UDP/QUIC), ho spustí ako samostatné prepísanie compose;
zámerne **nie je** súčasťou distribuovaného profilu `codex-app-server`. Postup
nastavenia nájdete v internej prevádzkovej príručke.
