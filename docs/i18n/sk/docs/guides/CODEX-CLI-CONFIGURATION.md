Kompletný návod na používanie Codex CLI nasmerovaného na OmniRoute ako backend kompatibilný s OpenAI.

---

> **TOML je jediný funkčný formát.** Moderný Codex načítava výhradne
> `~/.codex/config.toml` (overené s codex-cli 0.147.0: `codex --help` uvádza,
> že prepísania `-c/--config` sa „načítavajú z `~/.codex/config.toml`“). Starý
> `~/.codex/config.yaml` patril k staršiemu npm CLI a je bez upozornenia ignorovaný.
> Generátor na ovládacom paneli (`/api/cli-tools/apply`, nástroj `codex`) zapisuje TOML
> s konzervatívnym zlúčením — existujúce kľúče a bloky ostatných poskytovateľov sa
> zachovajú, kľúč API zostane v `OMNIROUTE_API_KEY` (nikdy nie v súbore) a prípadný
> pozostatok staršieho súboru `config.yaml` sa uvedie v poznámke k migrácii bez toho,
> aby sa zmenil.

## config.toml pripravený na vloženie

Nahraďte `<YOUR_HOST>` a `<YOUR_KEY>` svojimi hodnotami:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # limit ukladania histórie na jedno volanie nástroja

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc alebo ~/.zshrc — skutočná hodnota kľúča, nikdy nie v config.toml
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: Codex zabalený v aplikácii ChatGPT

Ak ste Codex nainštalovali prostredníctvom desktopovej aplikácie ChatGPT, binárny
súbor `codex` sa môže nachádzať iba v balíku aplikácie a zatiaľ nemusí byť vo vašej
premennej `PATH` shellu. Pridajte adresár zdrojov do spúšťacieho súboru shellu:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

Otvorte nový shell a potom overte:

```bash
command -v codex
codex --version
```

### Lokálny OmniRoute bez overovania: stačí zástupný kľúč

Codex overuje, či premenná prostredia určená hodnotou `env_key` existuje,
**predtým**, než prvá požiadavka opustí CLI. Ak vaša **lokálna** inštancia
OmniRoute nevyžaduje overovanie, postačí akákoľvek neprázdna zástupná hodnota:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

Ak je váš server OmniRoute chránený alebo vzdialený, použite namiesto nej skutočný kľúč.

> **Bežné možnosti hostiteľa**
>
> | Prístup      | URL                           |
> | ------------ | ----------------------------- |
> | Lokálna sieť | `http://192.168.0.1:20128/v1` |
> | Tailscale    | `http://100.x.x.x:20128/v1`   |
> | Slučka       | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — prečo funguje pre všetky modely

Codex CLI vo februári 2026 označil `wire_api = "chat"` (Chat Completions) za zastarané a teraz **vyžaduje** `wire_api = "responses"` (OpenAI Responses API). Nastavenie `wire_api = "chat"` spôsobuje od verzie v0.138 okamžité zlyhanie pri spustení.

Mnohí poskytovatelia vrátane GLM a Kimi stále ponúkajú iba koncový bod Chat Completions. DeepSeek V4 teraz ponúka natívne Responses API, ako aj koncový bod kompatibilný s Anthropic; OmniRoute predvolene používa Responses a každému pripojeniu DeepSeek umožňuje vybrať kompatibilitu s Anthropic.

**OmniRoute to rieši transparentne:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute vyberie natívny protokol poskytovateľa a v prípade potreby ho preloží
    → POST /responses (DeepSeek V4) alebo /chat/completions (Mistral / GLM / Kimi / ostatné)
```

Pri používaní OmniRoute nikdy nepotrebujete samostatný prekladový proxy server. **Všetky modely používajú `wire_api = "responses"`** — OmniRoute sa postará o zvyšok.

> **`wire_api` je predvolené nastavenie** — predvolená hodnota poľa je `"responses"` a z `config.toml` ho možno úplne vynechať. Explicitne ho nastavte iba vtedy, ak chcete zdokumentovať zámer.

## Kontextové okno a kompakcia

### Polia konfigurácie tokenov

| Pole                             | Popis                                                                                                                                                                                                    |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model_context_window`           | Celkový rozpočet tokenov pre aktívny model. Nastavte ho na limit uvádzaný pre daný model.                                                                                                                |
| `model_auto_compact_token_limit` | Prahová hodnota, ktorá spustí automatickú kompakciu histórie. **Maximum: 90 % z `model_context_window`** — hodnoty nad 90 % sa bez upozornenia ignorujú.                                                 |
| `tool_output_token_limit`        | Limit tokenov uložených v histórii pre výstup každého volania nástroja. Zabraňuje tomu, aby jediná veľká odpoveď nástroja zaplnila okno. **Nejde o maximálny výstup** — je to limit uloženia v histórii. |
| `compact_prompt`                 | Priame prepísanie systémovej výzvy použitej počas kompakcie (v0.138+).                                                                                                                                   |

> **Poznámka k `model_max_output_tokens`**: Toto pole **nie je súčasťou konfiguračnej schémy Codex CLI** (v kódovej báze Codex Rust sa nenachádza). Ak ho nastavíte, bez upozornenia sa ignoruje. Nespoliehajte sa naň — na riadenie množstva výstupu nástroja uloženého v histórii použite `tool_output_token_limit`.

## Prefix modelu: `cx/`

Všetky modely Codex v OmniRoute používajú prefix `cx/`:

| Názov v Codex CLI       | Model OmniRoute    |
| ----------------------- | ------------------ |
| `cx/gpt-5.5`            | GPT-5.5 štandardný |
| `cx/gpt-5.4`            | GPT-5.4 štandardný |
| `cx/gpt-5.4-mini`       | GPT-5.4 mini       |
| `cx/gpt-5.1-codex-mini` | GPT-5.1 Codex mini |

Ostatní poskytovatelia používajú vlastný prefix (`kmc/`, `glm/`, `ds/`, `ollamacloud/`, `opencode-go/`, `mistral/`) — prefix zodpovedá aliasu poskytovateľa v OmniRoute.

## Intenzita uvažovania

Určuje, koľko model pred odpoveďou „premýšľa“.

| Hodnota  | Použite na                                          |
| -------- | --------------------------------------------------- |
| `none`   | Bez uvažovania — priama odpoveď                     |
| `low`    | Triviálne úlohy (premenovanie, formátovanie)        |
| `medium` | **Predvolené nastavenie servera**, ak nie je určené |
| `high`   | Stredne náročné úlohy (refaktoring, ladenie)        |
| `xhigh`  | Architektúra, hĺbková analýza, komplexné problémy   |

```bash
# Prepísanie nastavenia pre jednotlivé spustenie
codex -c model_reasoning_effort=low "premenuj premennú x na count"
codex -c model_reasoning_effort=xhigh "navrhni autentifikačný modul"
```

Nastavte tiež **súhrn** uvažovania, aby Desktop dokázal zobraziť text premýšľania (nielen šifrované bloky):

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # alebo ultra, ak je podporované
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### Rozpočet uvažovania OmniRoute (nastavenie servera)

Na hostiteľovi OmniRoute musí byť položka **Settings → AI → Thinking Budget** nastavená na **`passthrough`**, aby sa intenzita a súhrn uvažovania Codex preniesli k upstream poskytovateľovi. Režim **`auto` odstraňuje** všetky klientske polia `reasoning` / `reasoning_effort` a spôsobí, že panely uvažovania zostanú prázdne, aj keď je Codex nakonfigurovaný správne.

Úplná príručka: [THINKING_BUDGET.md](./THINKING_BUDGET.md).

Kompresia a vyrovnávacia pamäť promptov sú nezávislé a v režime `passthrough` naďalej fungujú.

## Profily — pomenované konfigurácie pre jednotlivé modely/pracovné postupy

Profily umožňujú prepínať model a kontextové okno pomocou jediného prepínača. Každý profil je samostatný súbor
`~/.codex/<name>.config.toml`, ktorého nastavenia sa aplikujú na základný súbor `config.toml`.

> **Pravidlo pomenovania (Codex CLI v0.137+):** súbor musí mať názov `~/.codex/<name>.config.toml` — **bez prefixu `profile-`**.
> CLI preloží `-p kimi-k27` na `~/.codex/kimi-k27.config.toml`. Ak súbor nenájde, bez upozornenia použije predvolené nastavenie.

```bash
codex --profile kimi-k27 "analyzuj 10-tisíc riadkov tejto kódovej základne"
codex -p glm52 "posúď architektúru"
codex --profile deepseek-flash "premenuj premennú"   # rýchly, lacný
```

### Profily intenzity (rovnaký model, odlišná intenzita)

```bash
codex -p low      # cx/gpt-5.5, intenzita=low
codex -p medium   # cx/gpt-5.5, intenzita=medium
codex -p high     # cx/gpt-5.5, intenzita=high
codex -p xhigh    # cx/gpt-5.5, intenzita=xhigh (predvolené)
codex -p chat     # cx/gpt-5.5, intenzita nie je nastavená (predvolené nastavenie servera)
```

## Automatické generovanie profilov pomocou `omniroute setup-codex`

Ak OmniRoute prevádzkujete na VPS, môžete automaticky generovať súbory profilov zo živého katalógu modelov:

```bash
# Z VPS (používa lokálny OmniRoute na porte 20128)
omniroute setup-codex

# Z ľubovoľného počítača — zadajte adresu svojho VPS
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# Náhľad bez zapisovania súborov
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# Generovať iba profily GLM a Kimi
omniroute setup-codex --only glm,kimi

# Zapísať do vlastného adresára
omniroute setup-codex --codex-home /path/to/.codex
```

Príkaz načíta `/v1/models`, použije vyladené profily pre známe modely, pri ostatných kompatibilných textových modeloch použije ako náhradné riešenie metadáta katalógu a pre každý z nich zapíše `~/.codex/<name>.config.toml`. Je idempotentný — možno ho bezpečne spustiť opakovane.

OmniRoute môže tieto isté súbory profilov tiež **automaticky synchronizovať** po úspešnom vyhľadaní/importovaní modelov poskytovateľa, ktoré zmení živý katalóg. Táto funkcia je **voliteľná a predvolene vypnutá**: zapnite ju v **CLI Code dashboard** („CLI profile auto-sync“ → Codex) alebo nastavte `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` (rešpektuje aj `CLI_ALLOW_CONFIG_WRITES`, ktoré je predvolene zapnuté). Keď je táto funkcia zapnutá, zapisuje iba samostatné súbory profilov `~/.codex/*.config.toml`; nikdy nemení aktívny/predvolený súbor `~/.codex/config.toml`, nastavenia Codex-lb, autentifikáciu ani výber poskytovateľa.

## Dlhotrvajúce úlohy

Dve predvolené nastavenia OmniRoute môžu nenápadne narušiť viachodinové relácie Codex CLI. Ani jedno nie je nastavením Codex CLI — obe sa nachádzajú na strane OmniRoute. Používatelia, ktorí migrujú konfiguráciu z upstream proxy serverov, ktoré viažu relácie na konkrétne účty a vypínajú limity nečinnosti, často narazia na oba problémy a dospejú k záveru, že OmniRoute „nedokáže udržať dlhú reláciu“.

| Príznak                                                                                                     | Pravdepodobná príčina                                                     | Nastavenie               |
| ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- | ------------------------ |
| Relácia neustále prepína účty / medzi jednotlivými kolami sa stráca kontinuita vyrovnávacej pamäte promptov | TTL afinity relácie je `0` (vypnutá)                                      | `sessionAffinityTtlMs`   |
| Pripojenie sa preruší uprostred uvažovania bez výzvy zobrazenej klientovi                                   | Kontrola nečinnosti streamu sa spustila po 10 minútach bez upstream časti | `STREAM_IDLE_TIMEOUT_MS` |

Súvisiace diskusie: [#7126](https://github.com/diegosouzapw/OmniRoute/discussions/7126) (prerušenia dlhých úloh), [#5718](https://github.com/diegosouzapw/OmniRoute/discussions/5718) (prečo je afinita predvolene vypnutá). Sledovanie: [#7287](https://github.com/diegosouzapw/OmniRoute/issues/7287).

### 1. Afinita relácie — priradenie jednej konverzácie k jednému účtu

**Predvolené nastavenie:** `sessionAffinityTtlMs = 0` (vypnutá).

**Kde ju nastaviť**

- Ovládací panel → **Nastavenia → Smerovanie** → **Afinita relácie** → **TTL afinity (sekundy)** (`ComboDefaultsTab`)
- Alebo aktualizujte nastavenia pomocou PATCH s `sessionAffinityTtlMs` v **milisekundách** (rozsah Zod `0`–`86_400_000`, t. j. najviac 24 hodín)

> V #7274 bolo nastavenie premenované z `codexSessionAffinityTtlMs`, ktoré bolo určené iba pre Codex. Pôvodný kľúč je naďalej akceptovaný ako alias iba na čítanie; nové konfigurácie by mali používať `sessionAffinityTtlMs`. Afinita sa teraz po nastavení TTL nad `0` vzťahuje na **ľubovoľného** poskytovateľa, nielen na Codex — pozrite si [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → Afinita relácie.

**Čo prestane fungovať, keď hodnota zostane na 0**

Každé kolo viackolovej konverzácie Codex je smerované nezávisle podľa aktívnej kombinovanej stratégie a môže byť v každom kole priradené k **inému účtu**. Tým sa naruší kontinuita upstream relácie alebo vyrovnávacej pamäte promptov. OmniRoute zohľadňuje hlavičky relácie Codex (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) a polia tela, ako sú `prompt_cache_key` / `session_id`, iba vtedy, keď je TTL väčšie ako `0` (`extractSessionAffinityKey` v `src/sse/services/auth.ts`).

**Odporúčanie pre jednu viachodinovú úlohu**

Nastavte TTL na hodnotu **vyššiu ako očakávané trvanie úlohy podľa hodín** (maximum používateľského rozhrania je **86400 sekúnd** = 24 hodín):

| Očakávané trvanie úlohy | TTL afinity (používateľské rozhranie, sekundy) | `sessionAffinityTtlMs` |
| ----------------------- | ---------------------------------------------- | ---------------------- |
| Niekoľko hodín          | `14400` (4 h)                                  | `14400000`             |
| Cez noc / ~12 h         | `43200` (12 h)                                 | `43200000`             |
| Celý deň                | `86400` (24 h, maximum)                        | `86400000`             |

Aktivácia je zámerne voliteľná: vypnutie afinity uprednostňuje vyvažovanie záťaže medzi účtami; jej zapnutie uprednostňuje kontinuitu jednej dlhej relácie agenta. Táto príručka **nemení** predvolené nastavenie — prevádzkovatelia spúšťajúci dlhé úlohy Codex ju musia zapnúť.

### 2. Časový limit nečinnosti streamu — neukončujte tiché kolá uvažovania

**Predvolené nastavenie:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 minút). Ak nie je nastavené, dedí sa z `REQUEST_TIMEOUT_MS`; spoločná základná hodnota je tiež 600000. Pozrite si [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → Časové limity.

**Čo prestane fungovať pri predvolenom nastavení**

Turn uvažovania / nástroja Codex, ktorý zostane tichý dlhšie než 10 minút bez **akejkoľvek skutočnej dátovej časti z upstreamu**, je násilne ukončený strážcom nečinnosti SSE (`open-sse/utils/stream.ts`). Klient často zaznamená iba prerušenie pripojenia — čo zodpovedá správaniu „automaticky sa zastavilo bez akéhokoľvek upozornenia“.

Kritický detail: syntetický SSE **heartbeat služby OmniRoute nevynuluje** časovač nečinnosti. `lastChunkTime` aktualizuje iba skutočná časť tela odpovede z upstreamu. Tichý model, ktorý stále „premýšľa“, vyzerá z pohľadu strážcu rovnako ako zaseknutý upstream.

Súvisiaca nečinnosť tela Undici: `FETCH_BODY_TIMEOUT_MS` (predvolene tiež používa rovnakú základnú hodnotu 10 minút; hodnota `0` ju deaktivuje). Pri streamovaní sa `FETCH_TIMEOUT_MS` vzťahuje iba na nadviazanie spojenia / prvé hlavičky — po aktivácii streamu sa zaseknutia riadia premennými `STREAM_IDLE_TIMEOUT_MS` a `FETCH_BODY_TIMEOUT_MS`.

**Odporúčanie pre jednu úlohu trvajúcu niekoľko hodín**

V prostredí procesu OmniRoute (`.env` / compose / systemd):

```bash
# Deaktivujte limity nečinnosti streamu a tela pre dlhé turny uvažovania
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

Prípadne ich zvýšte nad najdlhšiu očakávanú dobu ticha (hodnoty sú v milisekundách):

```bash
# Príklad: povoľte až 2 hodiny ticha medzi dátovými časťami z upstreamu
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

Po zmene týchto premenných prostredia reštartujte OmniRoute.

### Konkrétny postup — niekoľkohodinová úloha Codex

1. **Pripnite účet:** Dashboard → Settings → Routing → Session affinity → Affinity TTL = `43200` (12 h) alebo `86400` (maximum 24 h).
2. **Zvýšte / deaktivujte limity nečinnosti** v prostredí OmniRoute:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. Zachovajte bežný súbor Codex `config.toml` (`wire_api = "responses"`, správna hodnota `base_url`, `OMNIROUTE_API_KEY`) — na strane Codex neexistujú nastavenia afinity ani nečinnosti pre tieto dve správania.
4. Reštartujte OmniRoute a potom spustite dlhú úlohu Codex.

### Rozhodnutie o predvolených hodnotách (#7287)

| Nastavenie               | Dodávaná predvolená hodnota | Zmeniť v tejto príručke?                                                                                                |
| ------------------------ | --------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (vypnuté)               | **Nie** — zostáva voliteľné (vyvažovanie záťaže vs. kontinuita; pozrite Diskusiu #5718)                                 |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 min)           | **Nie** — pre bežnú prevádzku zostáva 10 minút; prevádzkovatelia dlhých úloh Codex túto hodnotu zvýšia alebo deaktivujú |

Globálna zmena ktorejkoľvek predvolenej hodnoty by ovplyvnila správanie každého klienta danej inštancie, nielen Codex. Zdokumentujte tieto nastavenia; predvolené hodnoty ponechajte bez zmeny, kým výslovné rozhodnutie prevádzkovateľa neurčí inak.

### Diagnostika ukončení z dôvodu nečinnosti

Keď sa aktivuje strážca nečinnosti, OmniRoute zapíše do logu riadok v tomto tvare:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

Vyhľadajte pomocou grep reťazec `Idle timeout: no data from` (alebo kód `stream_idle_timeout` / názov chyby `StreamIdleTimeoutError`). Segment poskytovateľa zodpovedá tomu, čo OmniRoute použil pre danú požiadavku (`codex`, identifikátor iného poskytovateľa alebo `provider`, ak nie je známy) — nejde vždy doslova o reťazec `codex`.

## Riešenie problémov

**`Error: wire_api = "chat" už nie je podporované`**
Odstráňte `wire_api = "chat"` zo svojej konfigurácie. Nastavte `wire_api = "responses"` alebo toto pole vynechajte (od verzie v0.138 je predvolená hodnota `"responses"`).

**`Error: model sa nenašiel`**
Overte, či model existuje v OmniRoute so správnou predponou. Použite `omniroute models list` alebo otvorte `/dashboard/providers/<provider>`.

**`Chyba autentifikácie`**
Skontrolujte, či je premenná `OMNIROUTE_API_KEY` exportovaná: `echo $OMNIROUTE_API_KEY`.

**`ERROR: Chýbajúca premenná prostredia: OMNIROUTE_API_KEY`**
Codex pred odoslaním prvej požiadavky overuje, či premenná prostredia existuje. Exportujte
skutočný kľúč pre chránené servery alebo neprázdnu zástupnú hodnotu, napríklad
`OMNIROUTE_API_KEY=local`, ak vaša **lokálna** inštancia OmniRoute nevyžaduje
autentifikáciu. Ak ste ju pridali do `~/.bashrc` alebo `~/.zshrc`, reštartujte shell.

**`Pripojenie odmietnuté`**
Overte, či je OmniRoute spustený a či sú hostiteľ/port v `base_url` správne pre vašu sieť (lokálna vs. Tailscale vs. VPS).

**Relácia zlyháva blízko limitu kontextu**
Nastavte explicitne `model_context_window` a `model_auto_compact_token_limit`. Pozrite si tabuľku kontextových okien vyššie.

**Kompaktácia sa spúšťa príliš neskoro**
Znížte `model_auto_compact_token_limit` na 80–85 % veľkosti okna. Nikdy nenastavujte hodnotu nad 90 %.

**Profil sa nenačítava (`-p <name>` sa bez upozornenia ignoruje)**
Skontrolujte, či súbor existuje v umiestnení `~/.codex/<name>.config.toml` (bez predpony `profile-`). Spustite `ls ~/.codex/*.config.toml`.

**Dlhá úloha Codexu sa počas behu preruší / medzi jednotlivými interakciami prepína účty**
Pozrite si [Dlhodobé úlohy](#long-running-tasks). Povoľte afinitu relácie (TTL dlhšie ako trvanie úlohy) a zvýšte alebo vypnite `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS`. V protokoloch OmniRoute vyhľadajte pomocou grep reťazec `Idle timeout: no data from`.
