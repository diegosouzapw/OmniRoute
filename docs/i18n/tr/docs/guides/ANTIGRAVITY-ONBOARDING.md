## 1. Antigravity ve Antigravity CLI (agy) karşılaştırması

Her iki sağlayıcı da **aynı Google arka ucunu** paylaşır — aynı OAuth istemcisi, token yenileme, uç noktalar ve Google hesapları. Aralarındaki fark, hangi modelleri gördüğünüzdür.

> Google'ın resmî karşılaştırması için [Antigravity CLI duyurusuna](https://antigravity.google/blog/introducing-google-antigravity-cli) bakın.

| Unsur                   | `antigravity` (IDE)                         | `agy` (CLI)                                                 |
| ----------------------- | ------------------------------------------- | ----------------------------------------------------------- |
| **Google ürünü**        | Antigravity 2.0 / Antigravity IDE           | Antigravity CLI                                             |
| **Arka uç**             | Aynı Google Cloud Code API                  | Aynı Google Cloud Code API                                  |
| **OAuth / Token**       | Aynı istemci, aynı yenileme                 | Aynı istemci, aynı yenileme                                 |
| **Model kataloğu**      | Statik, seçilmiş liste (OmniRoute'a gömülü) | Google'dan `:fetchAvailableModels` aracılığıyla canlı sorgu |
| **Claude modelleri**    | Sonnet 4.6, Opus 4.6 (her biri 4 varyant)   | Sonnet 4.6, Opus 4.6 (her biri 4 varyant)                   |
| **Gemini adlandırması** | Sade etiketler (Low/Medium/High)            | Üst kaynak kimlikleri (extra-low/low/agent)                 |
| **Ek modeller**         | `gpt-oss-120b-medium`                       | Google'dan ek modeller içerebilir                           |
| **Varsayılan kullanım** | IDE entegrasyonu (VS Code, JetBrains)       | CLI / API erişimi                                           |
| **Kota**                | agy ile paylaşılır (aynı Google hesabı)     | antigravity ile paylaşılır (aynı Google hesabı)             |

**Kullanılabilir modeller (deneyle doğrulandı, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (çeşitli düşünme düzeyleri)
- Claude: Sonnet 4.6, Opus 4.6 (her biri default/low/medium/high varyantlarıyla)
- Diğer: GPT-OSS 120B Medium
- **Claude Sonnet 5 kullanılamaz** — yalnızca 4.6 varyantları desteklenir

**Model kataloğunun farklı olmasının nedeni**: Google'ın resmî bloguna göre Google'ın CLI'ı "hız ve düşük ek yük için optimize edilmiştir" ve "Gemini modelleriyle birlikte optimize edilmiştir." Web/IDE ürünü ise "kapsamlılık için optimize edilmiştir." CLI, modelleri dinamik olarak keşfetmek için `:fetchAvailableModels` kullanırken IDE, statik ve seçilmiş bir liste kullanır.

**Pratikte**: Gemini modelleri için `agy/` önekini kullanın (ör. `agy/gemini-3.7-flash-high`). Statik, seçilmiş liste için `antigravity/` kullanın. Her ikisi de aynı Google arka ucuna ulaşır ancak farklı model adlandırmaları sunar. Kota paylaşılır — sağlayıcılardan herhangi birini kullanmak, aynı Google hesabının sınırlarına dâhil edilir.

## 2. Google One AI Pro: Kota Sistemi

> Resmî kota ayrıntıları için [Antigravity Dokümanları: Planlar](https://antigravity.google/docs/plans), en güncel fiyatlandırma değişiklikleri için [Antigravity Planlarındaki Değişiklikler](https://antigravity.google/blog/changes-to-antigravity-plans) sayfasına bakın.

Google Antigravity, mesaj sayısına değil, "Yapılan İş"e (hesaplama ağırlığına) dayalı **iki katmanlı bir kota** kullanır.

### İki Katman

| Katman              | Nedir?                    | Yenilenme döngüsü                                                                               |
| ------------------- | ------------------------- | ----------------------------------------------------------------------------------------------- |
| **5 saatlik dönem** | Anlık "yapılan iş" havuzu | Bir oturumdaki ilk istekten 5 saat sonra sıfırlanır                                             |
| **7 günlük taban**  | Haftalık kesin üst sınır  | Ulaşılırsa 5 saatlik yenilenmeyi geçersiz kılar; sonraki 7 günlük döneme kadar erişimi engeller |

**"Yapılan İş" nasıl hesaplanır?** Yoğun aracı kullanımı gerektiren görevler (ör. "Bu deponun tamamını yeniden düzenle"), basit görevlere (ör. "Bu fonksiyonu düzelt") kıyasla kotayı çok daha hızlı tüketir. Tüketimi gösteren gerçek zamanlı bir kontrol paneli yoktur.

### Plan Katmanları

| Plan         | Fiyat      | Kota                                     | Haftalık sınır                                         |
| ------------ | ---------- | ---------------------------------------- | ------------------------------------------------------ |
| Ücretsiz     | $0         | Anlamlı kota, haftalık yenilenir         | Evet                                                   |
| AI Pro       | $19.99/ay  | Yüksek kota, 5 saatlik sürekli yenilenme | Evet (ulaşılırsa 5 saatlik yenilenmeyi geçersiz kılar) |
| AI Ultra 5x  | $99.99/ay  | Pro kotasının 5 katı                     | Haftalık sınır yok                                     |
| AI Ultra 20x | $199.99/ay | Pro kotasının 20 katı                    | Haftalık sınır yok                                     |

### Gemini ve Gemini Olmayan Modeller

- **Gemini modelleri** (Flash + Pro): API fiyatlandırmasına göre tüketilen tek bir hız sınırını paylaşır. Flash, Pro'dan 8 kat daha ucuzsa 8 kat daha fazla Flash token'ı alırsınız.
- **Gemini olmayan modeller** (Claude, GPT-OSS): **Ayrı** hız sınırlarına sahiptir. Gemini erişimi engellendiğinde bile kullanılabilir durumda kalabilirler.

### AI Kredileri (Kota Aşımı)

> Kredilerin nasıl çalıştığını öğrenmek için [Google One AI kredileri](https://support.google.com/googleone/answer/14534406) sayfasına bakın.

Taban kota tükendiğinde:

- **Asla**: Kotanın yenilenmesini bekler; "Taban model kotasına ulaşıldı" mesajını gösterir
- **Her zaman**: AI kredilerini otomatik olarak kullanır; taban kota yenilendiğinde tekrar ona geçer

Krediler ayrı olarak satın alınır ve standart API fiyatlandırmasına göre düşülür.

### Önemli Ayrıntılar

- Kota **hesap düzeyinde paylaşılır** — Antigravity IDE, CLI ve OmniRoute'ta kullanılan aynı Google hesabı tek bir kota havuzunu paylaşır
- Her Google hesabının kendine ait bağımsız bir kotası vardır — birden fazla hesap = birden fazla kota havuzu
- AI Pro kullanıcıları, haftalık taban sınıra ulaşıldığında 5 saatlik sıfırlamalar yerine **7 günlük erişim engellemeleri** yaşandığını bildirmiştir (Google, yüksek talep nedeniyle bunun tasarım gereği olduğunu doğrulamıştır)

**Hesabınızın kotası tükendiğinde**: OmniRoute, birleşik rotadaki bir sonraki kullanılabilir hesapla otomatik olarak yeniden dener. Manuel müdahale gerekmez.

## 3. projectId Nasıl Alınır?

Her antigravity/agy bağlantısı için bir Google Cloud Code `projectId` gerekir. Bu olmadan `/v1internal:models` uç noktası 404 döndürür.

### Yöntem A: Otomatik (Önerilen)

OmniRoute bunu otomatik olarak gerçekleştirir. Kontrol Paneli OAuth'u aracılığıyla yeni bir Google hesabı eklediğinizde:

1. OmniRoute token'ı yeniler
2. projectId'yi bulmak için `loadCodeAssist` çağrısı yapar
3. Hiçbir proje yoksa bir proje oluşturmak için `onboardUser` çağrısı yapar
4. Yeni oluşturulan projectId'yi almak için `loadCodeAssist` çağrısını yeniden dener
5. Bunu veritabanına kaydeder

**Bu, çoğu hesapta çalışır** — manuel adım gerekmez.

### Yöntem B: agy CLI ile Manuel

Otomatik bulma başarısız olursa (bunun hangi durumlarda gerçekleştiği için Bölüm 5'e bakın):

```bash
# agy CLI'ı yükleyin (henüz yüklü değilse)
npm install -g @anthropic-ai/agy

# Google hesabınızla oturum açın
agy login

# İlk katılım işlemi gereken hesabı seçin
# Bu işlem Cloud Code kaydını tetikler ve bir projectId atar
```

`agy login` başarıyla tamamlandıktan sonra OmniRoute Kontrol Paneli'nde token'ı yenileyin. projectId otomatik olarak bulunacaktır.

### Doğrulama

Veritabanını kontrol edin:

```bash
# OmniRoute konteynerinin içinde
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Alternatif olarak günlükleri kontrol edin:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. OAuth Yönlendirme URI'si

### Sorun

Google OAuth, geçerli bir yönlendirme URI'si gerektirir. OmniRoute varsayılan olarak `http://127.0.0.1:20128/callback` (geri döngü) adresini kullanır. Bu, yerel derlemelerde çalışır ancak **uzak dağıtımlarda başarısız olur** (ör. LAN IP'si üzerinden erişilen bir sunucu).

Google, aşağıdaki özelliklere sahip yönlendirme URI'lerini reddeder:

- IP adresi kullanır (`.com`, `.org` vb. ile biten bir alan adı olmalıdır)
- OAuth istemci yapılandırmasında kayıtlı yönlendirme URI'leriyle eşleşmez

### Çözüm

**Seçenek A: Yerleşik OAuth akışını kullanın (varsayılan)**

- OmniRoute'a `localhost` veya `127.0.0.1` üzerinden eriştiğinizde çalışır
- Yapılandırma gerekmez

**Seçenek B: Özel OAuth kimlik bilgileri**

- Ortamınızda `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` ayarını yapın
- Kendi Google OAuth kimlik bilgilerinizi sağlayın:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Google Cloud Console'da `https://your-domain.com/callback` adresini yetkili yönlendirme URI'si olarak kaydedin

**Seçenek C: İlk oturum açma için agy CLI'ı kullanın**

- OmniRoute'a erişecek makinede `agy login` komutunu çalıştırın
- OAuth akışı yerel olarak tamamlanır ve belirteçler saklanır
- Bağlantıyı Dashboard üzerinden OmniRoute'a aktarın

### Sınırlamalar

- Özel OAuth kimlik bilgileri bir alan adı gerektirir (Google, IP adreslerini yönlendirme URI'si olarak kabul etmez)
- Bir alan adınız yoksa bunun yerine Seçenek A veya C'yi kullanın

## 5. Sorun Giderme: Otomatik Kurulum Başarısız Olduğunda

OmniRoute, çoğu hesap için projectId keşfini ve ilk kullanım sürecini otomatik olarak yönetir. Başarısız olduğunda temel neden genellikle aşağıdakilerden biridir:

### Hesap bölgesi engellenmiş

**Belirti**: `agy login`, "Eligibility check failed: Your current account is not eligible for Antigravity, because it is not currently available in your location." hatasını döndürür.

**Temel neden**: Google hesaplarında, kayıt sırasında ayarlanan arka uçtaki bir "Ülke İlişkilendirmesi" alanı bulunur. agy CLI ve Cloud Code API, yalnızca mevcut IP'nizi kontrol eden web Gemini'ın aksine bu alanı katı biçimde kontrol eder.

> Hesabınızla ilişkilendirilmiş bölgeyi kontrol etmek veya değiştirmek için [Google Ülke İlişkilendirme Formu'nu](https://policies.google.com/country-association-form) ziyaret edin.

**Web Gemini çalışırken agy neden çalışmıyor**:

- Web Gemini / Google One: yalnızca mevcut IP'yi kontrol eder (proxy yeterlidir)
- agy CLI / Cloud Code API: arka uçtaki Ülke İlişkilendirmesi alanını okur (proxy yardımcı olmaz)

**Düzeltme**:

1. ABD IP'si kullanırken [Google Ülke İlişkilendirme Formu'nu](https://policies.google.com/country-association-form) ziyaret edin
2. Bölge değişikliği talebi gönderin ("Farklı bir ülkede yaşıyorum" seçeneğini belirleyin)
3. Google'ın işlemi tamamlaması ve e-posta bildirimi göndermesi için 1-24 saat bekleyin
4. Ardından `agy login` başarılı olmalıdır

### Hesabın Cloud Code projesi yok

**Belirti**: Günlüklerde `loadCodeAssist returned no project id` ve `onboardUser failed (400)` gösterilir.

**Temel neden**: Hesap daha önce Google Cloud Code'a hiç kaydedilmemiştir ve otomatik ilk kullanım süreci başarısız olmuştur.

**Düzeltme**: Cloud Code kaydını tetiklemek için `agy login` komutunu manuel olarak çalıştırın, ardından OmniRoute Dashboard'da belirteci yenileyin.

### Belirtecin süresi dolmuş veya belirteç iptal edilmiş

**Belirti**: Günlüklerde 401 hataları veya "Token has expired" mesajları görünür.

**Düzeltme**: Dashboard → Providers → agy bölümüne gidip yenileme simgesine tıklayarak belirteci yenileyin. Yenileme belirtecinin kendisi iptal edilmişse OAuth aracılığıyla yeniden kimlik doğrulaması yapmanız gerekir.

