**OmniCopilot**, OmniRoute tarafından sunulan tüm modelleri _yerel_ GitHub Copilot Chat
model seçicisine ekler. İkinci bir kenar çubuğu veya ayrı bir sohbet arayüzü yoktur — Copilot'ın ajan modu, araç çağırma,
MCP sunucuları ve özel talimatları çalışmaya devam eder; yalnızca seçtiğiniz model üzerinde çalışırlar.

| **Yükleme (çatallar)** | [Open VSX](https://open-vsx.org/extension/diegosouzapw/omnicopilot) — Cursor, Windsurf, VSCodium, Theia, code-server, Gitpod, Antigravity, Kiro |

| **Gereksinim**         | VS Code 1.104+                                                                                                                                  |

> **Copilot aboneliği gerekmez.** VS Code 1.122 sürümünden itibaren bir dil modeli sağlayıcısı,
> GitHub oturumu açılmadan ve herhangi bir Copilot planı olmadan çalışır. Satır içi tamamlamalar ve
> embedding tabanlı özellikler sağlayıcı API'sinin dışında kalır ve hâlâ Copilot gerektirir.

## Kurulum

1. **OmniRoute'u çalıştırın** — `npm install -g omniroute && omniroute` (kontrol paneli: `http://localhost:20128`).
2. **Uzantıyı yükleyin** — Uzantılar görünümünde "OmniRoute" ifadesini arayın.
3. **Bir model seçin** — Copilot Chat → model seçici → **Modelleri Yönet…** → **OmniRoute**, ardından
   istediğiniz modelleri işaretleyin.

OmniRoute varsayılan portta çalıştığında yapılandırılacak hiçbir şey yoktur. Uzak bir örnek için
**Etkinlik Çubuğu'ndaki OmniRoute simgesini** açın (veya `OmniRoute: Manage Connection` komutunu çalıştırın) ve şunları ayarlayın:

- **Sunucu URL'si** — sunucu kökü; örneğin `http://192.168.0.15:20128`. `/v1` son eki
  uzantı tarafından eklenir; bunu dahil etmeyin.
- **API anahtarı** — yalnızca sunucuda `REQUIRE_API_KEY` ayarlandığında gerekir. VS
  Code SecretStorage aracılığıyla işletim sistemi anahtar zincirinde saklanır; asla `settings.json` içinde saklanmaz.

## Seçicide gösterilecekler

Uzantı, ham `GET /v1/models` yükünü göstermez — onu biçimlendirir ve gördüğünüz sayı,
iki bilinçli nedenden dolayı katalog boyutundan daha düşüktür.

### Her model için tek bir kimlik ister

`MODELS_CATALOG_PREFIX_MODE` varsayılan olarak **`dual`** değerini kullanır ve her modeli iki kez tanıtır — bir kez
kısa takma ad önekiyle, bir kez de standart sağlayıcı önekiyle — böylece eski istemci
yapılandırmaları her iki biçimi de çözümlemeye devam eder:

```
cc/claude-sonnet-4-6        ← takma ad öneki
claude/claude-sonnet-4-6    ← standart önek, aynı model
```

Uzantı, sunucu genelindeki diğer istemcilerinize yönelik ayarı değiştirmeden model başına tek bir
kimlik gelmesi için **`GET /v1/models?prefix=alias`** isteğinde bulunur. Bir referans örnekte bu işlem
**2345 girdiyi 1396 girdiye düşürdü — 949 yinelenen girdi kaldırıldı, hiçbir model kaybolmadı.**

Bunu _her_ istemci için sunucu genelinde düzeltmeyi tercih ederseniz kontrol panelinde
`MODELS_CATALOG_PREFIX_MODE` özellik bayrağını `alias` olarak ayarlayın. Sorgu parametresi ve
modlara göre tablo için [API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) bölümüne bakın.

### Sohbet edemeyen modelleri gizler

Katalog ayrıca görüntü, video, ses, yeniden sıralama, embedding ve moderasyon modellerini listeler. Bunlar
zaten sohbet isteğinde reddedilir:

```
HTTP 400 — '<id>' modeli bir görüntü oluşturma modelidir ve
/v1/chat/completions üzerinde kullanılamaz. Bunun yerine POST /v1/images/generations kullanın.
```

Bu nedenle seçiciye ulaşmadan önce `type` alanlarına göre filtrelenirler. **Responses-API
modelleri korunur** — her Codex / GPT-5.x girdisi `supported_endpoints: ["responses"]` özelliğini tanıtır
ve OmniRoute bunları `/v1/chat/completions` için dönüştürdüğünden tamamen kullanılabilirler.

### Hiç yapılandırmadığınız sağlayıcılar

Katalog, **etkin bağlantısı** olan sağlayıcıların modellerinin yanı sıra tüm **noAuth**
sağlayıcılarını da listeler — bunlar ücretsiz katmanın büyük kısmını oluşturan anahtarsız sağlayıcılardır. Bu bilinçli bir tercihtir. Bunları gizlemek için
kontrol paneli ayarlarında `blockedProviders` alanına ekleyin; uzantıda hiçbir şey değişmez.

## Bir VS Code sekmesi içinde Dashboard

`omnicopilot.dashboardOpen: "editor"`, OmniRoute Dashboard'u harici bir tarayıcı yerine Simple Browser aracılığıyla bir düzenleyici sekmesinde görüntüler. Gömme özelliği, HTML sayfalarını varsayılan `frame-ancestors 'none'` + `X-Frame-Options: DENY` yerine `frame-ancestors 'self' vscode-webview:` ile sunan `DASHBOARD_ALLOW_EMBED=vscode` aracılığıyla **sunucuda isteğe bağlı olarak etkinleştirilir**. API yüzeyi (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) her iki durumda da katı üstbilgileri korur.

> ⚠️ **Bu bir çalışma zamanı değil, derleme zamanı bayrağıdır.** Next.js, `headers()` işlevini rota
> manifestine derlediğinden `next.config.mjs`, paket derlenirken değişkeni okur
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> Değişkeni önceden derlenmiş bir sunucunun başlatma komutunun önünde dışa aktarmak hiçbir şeyi değiştirmez — üstbilgiler derlemeye gömülüdür.

```bash
# değişkenin BUILD komutunda mevcut olması gerekir
DASHBOARD_ALLOW_EMBED=vscode npm run build        # veya npm run build:release
npm start
```

| Nasıl yüklediniz           | Gömme özelliğini etkinleştirebilir misiniz?                                                                                                     |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Kaynak koddan              | ✅ değişkeni yukarıdaki gibi derleme komutunda ayarlayın                                                                                        |
| `npm install -g omniroute` | ❌ yayımlanan paket önceden derlenmiş bir paket içerir — bunun yerine kaynak koddan derleyin                                                    |
| Docker imajı               | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — Docker Hub'daki önceden derlenmiş imajda gömme etkin değildir |

Gömme özelliği etkinleştirilmiş bir derleme olmadığında sayfa çerçeve içinde görüntülenmeyi reddeder; uzantı bunu yanıt üstbilgilerinden algılar ve harici tarayıcıya geri döner — hiçbir şey bozulmaz ve bu durumu bir kez bildirir. Bkz. [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) ve sorun
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273).

## Diğer araçlarınızı VS Code içinden yapılandırma

## Sorun giderme

| Belirti                                                        | Neden / çözüm                                                                                                                                                                                                                                                             |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Seçicide OmniRoute modeli yok                                  | Sunucuya erişilemiyor. Durum çubuğu noktası griye döner; `OmniRoute: Check Connection` komutunu çalıştırın. Keşif, tasarım gereği sessizdir ve istem göstermek yerine hiçbir model sağlamaz.                                                                              |
| Her model iki kez görünüyor                                    | 1.0.1 sürümünden eski bir OmniCopilot kullanıyorsunuz — güncelleyin. Uzantı artık `?prefix=alias` talep ediyor.                                                                                                                                                           |
| Daha önce listelenen bir görüntü/ses modeli artık yok          | 1.0.1 sürümünden bu yana kasıtlıdır — bu model hiçbir zaman sohbet isteğine yanıt veremiyordu.                                                                                                                                                                            |
| Etkinlik Çubuğu'nda panel eksik                                | VS Code, ek görünüm kapsayıcılarını Etkinlik Çubuğu'nun altındaki **"…"** taşma menüsüne taşır ve sağ tıklamayla gizlenen bir kapsayıcı gizli kalır. Etkinlik Çubuğu'na sağ tıklayın → **OmniRoute** seçeneğini işaretleyin veya `OmniRoute: Manage Connection` ile açın. |
| Dashboard, `editor` moduna rağmen tarayıcıda açılıyor          | Sunucu `DASHBOARD_ALLOW_EMBED=vscode` ile **derlenmemiştir** (yukarıya bakın) — bunu önceden derlenmiş bir kurulumda başlatma sırasında ayarlamak hiçbir şeyi değiştirmez. Harici tarayıcıya geri dönüş kasıtlıdır.                                                       |
| Sağlayıcılar değiştirildikten sonra model listesi eski kalıyor | `OmniRoute: Refresh Models` komutunu veya paneldeki ↻ bağlantısını kullanın.                                                                                                                                                                                              |
