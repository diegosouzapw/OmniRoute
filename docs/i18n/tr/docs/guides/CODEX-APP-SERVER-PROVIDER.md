---

OmniRoute, OpenAI Codex'i kullanmak için **iki** yöntem sunar:

| Sağlayıcı              | OpenAI ile nasıl iletişim kurar                                                                                                                                                                                     | Kullanım uyarısı                                                     |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| **`codex`**            | ChatGPT/OpenAI OAuth token'ınızı doğrudan Responses API'ye yeniden gönderir                                                                                                                                         | **Evet** — resmi oturumun proxy/router kullanımı için yetkisi yoktur |
| **`codex-app-server`** | **Codex CLI'ın kendi `codex app-server`** sürecini JSON-RPC/WebSocket üzerinden çalıştırır; CLI, OAuth'unu (`~/.codex/auth.json`) etkileşimli bir `codex` oturumunda olduğu gibi yönetir ve otomatik olarak yeniler | **Hayır** — OmniRoute hiçbir zaman API'ye token göndermez            |

`codex-app-server` hiçbir zaman token'ı yeniden göndermediğinden, oturumu yeniden
göndermeye ilişkin kullanım uyarısı onun için geçerli değildir. Ancak
**yapılandırılmış app-server URL'sinden erişilebilen bir Codex CLI** gerektirir
ve bu CLI'da **oturum açılmış** olmalıdır.

---

## 1. Mimari

```
┌─ OmniRoute uygulaması ───────────┐        ┌─ codex-app-server yardımcı konteyneri ┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                     │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456           │
│  (+ yetenek token'ı)             │  JSON  │  --ws-auth capability-token           │
│                                  │  RPC   │  OpenAI OAuth'u kendi yönetir          │
└──────────────────────────────────┘        │  (~/.codex/auth.json, otomatik yenileme)│
        │ paylaşır (compose birimleri)       └────────────────────────────────────────┘
        ▼
  codex-appserver-token   → WS yetenek token'ı (her ikisi de bağlar)
  codex-appserver-home    → ~/.codex (auth.json dashboard tarafından yazılır,
                             yardımcı konteynerdeki codex app-server tarafından okunur)
```

- Yardımcı konteyner, bir yetenek token'ının arkasında **yalnızca** dahili compose
  ağını (`ws://codex-app-server:1456`) dinler. Ana makineye veya internete
  **hiçbir zaman** yayımlanmaz.
- Codex CLI, `omniroute:base` imajına dahil edilmiştir; dolayısıyla yardımcı
  konteyneri çalıştırdığınızda ana makineye veya kullanıcının cihazına codex
  kurulması gerekmez.

## 2. Çalıştırma

```bash
# Yığını codex app-server yardımcı konteyner profiliyle BİRLİKTE başlatın:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

Yardımcı konteyner, ilk açılışta WS yetenek token'ını oluşturur (paylaşılan
`codex-appserver-token` birimine yazar) ve uygulama aynı token'ı
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE` aracılığıyla okur. Token'ın manuel
olarak bağlanması gerekmez.

## 3. Bağlanma + oturum açma

1. Dashboard'da **OpenAI Codex (App-Server)** için bir bağlantı ekleyin. API
   anahtarı veya token gerekmez (kimlik doğrulamasız bir sağlayıcıdır — kimlik
   doğrulamayı yardımcı konteyner yönetir).
2. Yardımcı konteynerin Codex CLI'ında **henüz oturum açılmamışsa**, bağlantı
   durumu denetimi _"çalışıyor ancak oturum açılmamış"_ sonucunu bildirir (kırmızı
   bir kimlik doğrulama hatası değildir). **ChatGPT ile oturum aç** seçeneğini
   kullanın: bu işlem, tarayıcınızda standart Codex cihaz OAuth akışını çalıştırır
   ve ardından **Kimlik doğrulamayı uygula** aracılığıyla `~/.codex/auth.json`
   dosyasını paylaşılan birime yazar (aynı oturum açma işlemi hem `codex` hem de
   `codex-app-server` sağlayıcılarına hizmet eder).
3. Oturum açıldıktan sonra durum denetimi yeşile döner (hem `/readyz` **hem de**
   `account/read` doğrulanır; yani sistem hem çalışır durumdadır _hem de_ kimliği
   doğrulanmıştır) ve çalışmaya başlar.

Dashboard, mevcut ve sağlıklı bir `~/.codex/auth.json` dosyasının üzerine hiçbir
zaman yazmaz; yalnızca dosya yoksa veya token eskiyse yazar (her zaman bir yedek
alınır).

## 4. Dağıtım senaryoları

- **Codex CLI'ında zaten kimliği doğrulanmış operatör** — ana makinenizdeki
  `~/.codex` dizinini yardımcı konteynere (`codex-appserver-home`) bağlayın ve
  oturum açma adımını atlayın.
- **Herkese açık kullanıcı, yerel olarak codex kurulu değil** — önemli değildir:
  CLI yardımcı konteynerde bulunur. Kullanıcı yalnızca dashboard üzerinden kimlik
  doğrulaması yapar.
- **Bare-metal OmniRoute (yardımcı konteyner yok, ana makinede codex var)** —
  `OMNIROUTE_CODEX_APPSERVER_WS` değişkenini kendi `codex app-server` örneğinize
  yönlendirin ve ana makinedeki codex'te oturum açıldığından emin olun; binary
  eksikse "codex kurulu değil" ipucu görüntülenir.

## 5. Konut / UDP çıkışı (operatör eklentisi, birlikte sunulmaz)

Yukarıdaki genel yardımcı konteyner, trafiği konteynerin normal ağı üzerinden
dışarı gönderir. Codex trafiğini bir **konut çıkışı** üzerinden (ör. TCP +
UDP/QUIC taşıyan bir TUN tailscale yardımcı konteyneri) göndermesi gereken bir
operatör, bunu ayrı bir compose geçersiz kılma yapılandırması olarak çalıştırır;
bu yapılandırma kasıtlı olarak birlikte sunulan `codex-app-server` profilinin
parçası değildir. Bu kurulum için dahili operasyon çalışma kılavuzuna bakın.
