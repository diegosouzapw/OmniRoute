AgentBridge, IDE AI ajanlarından gelen HTTPS trafiğini yakalayan ve OmniRoute'un birleşik yönlendirme motoru üzerinden yeniden yönlendiren OmniRoute'un MITM (Ortadaki Adam) proxy'sidir. **10 IDE ajanını** destekler — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code ve Trae (araştırılıyor) — böylece OmniRoute, piyasadaki AI kodlama asistanları için en geniş kapsama sahip MITM proxy'si olur.

**Pano konumu:** `/dashboard/tools/agent-bridge`
**Kenar çubuğu grubu:** Araçlar (Cloud Agents'tan sonra)
**Ayrıca bkz.:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — yakalanan tüm trafiği gerçek zamanlı olarak izleyin; `docs/security/MITM-TPROXY-DECRYPT.md` (git; `/docs` içine derlenmez) — `/api/tools/agent-bridge/tproxy` rotası tarafından yönetilen Linux TPROXY şeffaf şifre çözme yakalama modu.

## §1 Genel Bakış

### AgentBridge nedir?

Bir IDE ajanı (ör. GitHub Copilot, Cursor, Claude Code) API çağrısı yaptığında doğrudan üst akış AI sağlayıcısına (OpenAI, Anthropic vb.) bağlanır. AgentBridge, herhangi bir ajan yapılandırma değişikliği gerektirmeden bu bağlantıyı TLS düzeyinde şeffaf bir şekilde yakalar ve isteği OmniRoute üzerinden yeniden yazar.

Bu sayede şunları yapabilirsiniz:

- **Herhangi bir ajanı herhangi bir sağlayıcıya yeniden yönlendirin**: Copilot, OpenAI ile mi iletişim kuruyor? Onu Anthropic Claude, Gemini veya OmniRoute'un 352 sağlayıcısından herhangi birine yönlendirin.
- **Model eşlemeleri uygulayın**: `gemini-3-flash` → `claude-sonnet-4.7` eşlemesini işleyici düzeyinde şeffaf olarak uygulayın.
- **Tüm ajan trafiğini gözlemleyin**: Yakalanan her istek [Trafik Denetleyicisi](./TRAFFIC_INSPECTOR.md) aracına yayımlanır.
- **OmniRoute dayanıklılığını uygulayın**: Birleşik yönlendirme, devre kesiciler, geri dönüşler ve maliyet takibi IDE ajan trafiği için de çalışır.

## §2 Mimari

### 2.1 Bileşenlere genel bakış

```
IDE Aracısı (VS Code / Cursor / vb.)
    │  HTTPS (443 numaralı bağlantı noktası)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← DNS yönlendirmesi
    │
    ▼
src/mitm/server.cjs  (443 numaralı bağlantı noktası, CJS alt süreci)
    │  hedefi Host üstbilgisi SNI değerine göre çözümler
    │  AgentBridge CA tarafından imzalanmış, SNI başına TLS sertifikası oluşturur
    ├── Atlatma listesiyle eşleşme? → TCP doğrudan geçişi (şifre çözme yok)
    ├── Hedefle eşleşme? → fetch → OmniRoute yönlendiricisi (20128 numaralı bağlantı noktası)
    │       └── handler.intercept() — TypeScript
    │               ├── istek gövdesinde/üstbilgilerinde maskSecrets()
    │               ├── TrafficBuffer.push() — Trafik İnceleyicisi'nde yayımlar
    │               └── fetchRouter() → /v1/chat/completions
    └── Eşleşme yok? → TCP doğrudan geçişi (şifre çözme yok)
```

### 2.2 MITM sunucusu (`src/mitm/server.cjs`)

Temel MITM sunucusu, mevcut CJS kod tabanını yeniden yazmaktan kaçınmak için bir Node.js CJS alt süreci olarak çalışır. Şunları yapar:

- 443 numaralı bağlantı noktasını dinler (ayrıcalık veya `authbind`/`setcap` gerektirir)
- İşletim sisteminden (`/etc/hosts` DNS yönlendirmesi aracılığıyla) CONNECT tünellerini alır
- AgentBridge CA (`DATA_DIR/mitm/ca.crt`) tarafından imzalanmış, SNI başına TLS sertifikaları oluşturur
- Hedef aracıyı `targets/index.ts` kayıt defteri aracılığıyla Host üstbilgisine göre çözümler
- `http://127.0.0.1:20128` adresine HTTP üzerinden TypeScript işleyici katmanına yönlendirir

`TARGET_HOSTS`, `DATA_DIR/mitm/targets.json` dosyasından yüklenir (başlangıçta `targets/index.ts` tarafından yazılır); bu da CJS sunucusunu yeniden başlatmadan dinamik güncellemelere olanak tanır.

> **Kök CA modeli (#6684).** Yukarıda açıklanan, CA tarafından imzalanmış SNI başına sertifika
> modeli, #6684 kapsamında eklenen kalıcı kök CA modelidir (`src/mitm/cert/rootCa.ts` +
> `src/mitm/_internal/rootCaShim.cjs`; `src/mitm/tproxy/dynamicCert.ts` içinde TPROXY için
> doğrulanmış CA/yaprak şifreleme altyapısını yeniden kullanır) — bu model, diskte yalnızca
> bir `server.crt`/`server.key` çiftinin bulunduğunu gösteren, eski tek statik kendinden
> imzalı yaprak sertifikanın (`src/mitm/cert/generate.ts`, hâlâ yalnızca antigravity
> ana makineleriyle sınırlıdır) yerini alır. **Geçiş davranışı**: yeni bir kurulum (önceden
> `server.crt` yoksa) kök CA modelini otomatik olarak kullanır; eski statik yaprağa zaten
> güvenen bir kurulum ise operatör `MITM_ROOT_CA_ENABLED=true` ayarını yapıp köprüyü yeniden
> başlatana kadar bunu kullanmaya devam eder (`src/mitm/cert/migration.ts` saf karar
> işlevidir — **herhangi bir** ana makine için yaprak sertifika imzalayabilen güvenilir bir
> MITM CA, eski sabit SAN'lı yapraktan önemli ölçüde daha güçlüdür; bu nedenle zaten
> güvenilen bir kurulumda geçiş hiçbir zaman sessizce yapılmaz). CA sertifikası, eski yaprağın
> kullandığı aynı `omniroute-mitm.crt` güven deposu yuvasına kurulur
> (`cert/install.ts::installCaCert`) — çift güven temizliği gerekmez.

### 2.3 İşleyici tabanı (`src/mitm/handlers/base.ts`)

Tüm aracı işleyicileri `MitmHandlerBase` sınıfını genişletir:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // Korumalı yardımcılar: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

Her işleyici, proxy işleminden önce `hookBufferStart()` ve tamamlandığında `hookBufferUpdate()` çağrısını yapar. Bunlar, `InterceptedRequest` girdilerini `globalTrafficBuffer` içine gönderir (bkz. [Trafik İnceleyicisi](./TRAFFIC_INSPECTOR.md) §4).

### 2.4 Hedefler kayıt defteri (`src/mitm/targets/`)

Her aracının bildirimsel bir hedef dosyası vardır:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

Kayıt defteri (`targets/index.ts`), `ALL_TARGETS` değerini dışa aktarır ve başlangıçta `DATA_DIR/mitm/targets.json` dosyasını oluşturur.

### 2.5 Doğrudan geçiş ve atlatma listesi (`src/mitm/passthrough.ts`)

**Atlatma listesi** (ilk olarak denetlenir ve hedef eşleşmesine göre önceliklidir):

- Varsayılan kalıplar: bankacılık ana makineleri, `.gov.`, OAuth/SSO sağlayıcıları (Okta, Auth0) vb.
- Kullanıcı kalıpları: `agent_bridge_bypass` veritabanı tablosunda saklanır
- Atlanan ana makineler şeffaf bir TCP tüneli alır — TLS şifresi **hiçbir zaman çözülmez**

**Varsayılan doğrudan geçiş** (hedef eşleşmesi yoksa ve atlatma listesinde değilse):

- Bu bağlantılar da bir TCP tüneli alır — bağlantılar hiçbir zaman kesilmez
- AgentBridge'in genel sistem HTTPS trafiğini bozmasını önler

Yönlendirme önceliği:

```
atlatma listesi → hedef eşleşmesi → doğrudan geçiş
```

### 2.6 Yukarı akış CA sertifikası (`src/mitm/upstreamTrust.ts`)

Özel CA kullanan kurumsal ağ ortamları için:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

Ayarlandığında `undici`'nin genel dağıtıcısını ek CA sertifikasıyla yapılandırır ve AgentBridge'in kurumsal TLS sonlandırma proxy'leri üzerinden yukarı akış sağlayıcılarına ulaşmasına olanak tanır.

### 2.7 Gizli bilgi maskeleme (`src/mitm/maskSecrets.ts`)

Bağımsız ve temiz ortamda geliştirilmiş tarayıcı, istek gövdelerine ve kimlik bilgisi üstbilgilerine
Trafik İnceleyicisi arabelleğine veya herhangi bir günlüğe girmelerinden **önce** uygulanır. Tek bir doğrusal geçiş gerçekleştirir:

- `sk-` / `ak-` / `pk-` önekli belirteçler (OpenAI/Anthropic tarzı)
- RFC 6750 `Authorization: Bearer <token>` kimlik bilgileri; tam belirteç önceliklidir
- Noktalı ve dolgulu biçimler dâhil olmak üzere genel uzun opak belirteçler (≥40 karakter)

`sanitizeHeaders()`, korunan adları küçük harfe dönüştürür, dizi değerlerini belirleyici biçimde birleştirir,
proxy kimlik doğrulaması dâhil olmak üzere paylaşılan atlama-atlama/çerçeveleme engelleme listesini çıkarır,
`cookie` ve `set-cookie` değerlerini tamamen sansürler ve kimlik bilgisi değerlerini tarayıcıya devreder.

## §3 Kurulum

### 3.1 MITM sunucusunu başlatma/durdurma

`/dashboard/tools/agent-bridge` adresindeki AgentBridge Sunucu Kartını kullanın:

| Eylem                       | Açıklama                                                                              |
| --------------------------- | ------------------------------------------------------------------------------------- |
| Sunucuyu Başlat             | 443 numaralı bağlantı noktasında `src/mitm/server.cjs` işlemini başlatır              |
| Sunucuyu Durdur             | Alt işlemi düzgün bir şekilde sonlandırır                                             |
| Sunucuyu Yeniden Başlat     | Durdurur + başlatır (hedef değişikliklerini uygular)                                  |
| Sertifikaya Güven           | `DATA_DIR/mitm/ca.crt` dosyasını işletim sisteminin güven deposuna yükler             |
| Sertifikayı İndir           | Elle yüklemek üzere `ca.crt` dosyasını indirir                                        |
| Sertifikayı Yeniden Oluştur | Yeni bir CA anahtar çifti oluşturur (mevcut tüm aracı sertifikaları geçersiz kılınır) |

### 3.2 Sertifikaya güvenme

IDE'lerin MITM bağlantısını kabul edebilmesi için işletim sisteminin AgentBridge CA sertifikasına güvenmesi gerekir.

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Anahtar Zinciri):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

Alternatif olarak panodaki "Sertifikaya Güven" düğmesini kullanın (işletim sisteminize uygun komutu çalıştırır ve gerekirse sudo istemini gösterir).

#### Electron tabanlı IDE'ler işletim sisteminin güven deposunu yok sayar (`NODE_EXTRA_CA_CERTS`)

Bazı IDE'ler — özellikle **Antigravity IDE** ve diğer Electron / VS Code türevi uygulamalar —
giden `fetch`/HTTPS istekleri için **işletim sisteminin güven deposuna başvurmayan** kendi
Node.js çalışma zamanlarını paketler. CA'ya işletim sistemi/NSS düzeyinde güvenmek, IDE'nin yerel
**arka ucu** (ör. işletim sistemi CA paketini kullanan bir Go dil sunucusu) için yeterlidir; ancak
**Electron ön ucu** yine de TLS hatası verir — MITM günlüğü arka ucun başlangıç çağrılarının `200`
döndürdüğünü gösterse bile bu durum uygulamada _oturum kapatılmış_ olarak veya bir _"bağlantı hatası"_
şeklinde görünür. İki adım gereklidir ve ikisi de önemlidir:

1. Çalışma zamanını açıkça CA'ya yönlendirin:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **IDE'yi bu kabuktan başlatın.** Masaüstü simgesinden / Dock'tan / Başlat menüsünden
   başlatıldığında kabuk dışa aktarımları **devralınmaz** ve `~/.config/environment.d/*.conf`
   yalnızca yeni bir grafiksel oturum açıldıktan sonra uygulanır. Önce IDE'den tamamen çıkın —
   Electron'ın tekil örnek kilidi nedeniyle ikinci bir başlatma yalnızca mevcut işleme odaklanır
   ve yeni ortam yok sayılır.

Yukarıdaki işletim sistemi güveni + NSS adımı yine de gereklidir (bazı kimlik doğrulama
akışlarının kullandığı Chromium ağ yığını, kullanıcıya özel NSS deposunu okur ve
`*.googleapis.com` için yerel olarak güvenilen bir CA'nın geçersiz kıldığı kendi statik
sabitlemelerine sahiptir). `NODE_EXTRA_CA_CERTS`, buna ek olarak Node `fetch` yolunu kapsar.

### 3.3 DNS yönlendirmesi

Müdahale etmek istediğiniz her aracı için API ana bilgisayarlarının `127.0.0.1` adresine çözümlenmesi gerekir. AgentBridge, Kurulum Sihirbazı'nda bir aracı için DNS'yi etkinleştirdiğinizde `/etc/hosts` girdilerini otomatik olarak yönetir.

GitHub Copilot için örnek `/etc/hosts` girdileri:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 Model eşlemesi

Kaynak → hedef eşlemelerini tanımlamak için her aracı kartındaki Model Eşleme Tablosunu kullanın:

| Kaynak model (aracının yerel modeli) | Hedef model (OmniRoute) |
| ------------------------------------ | ----------------------- |
| `gpt-4o`                             | `claude-sonnet-4.7`     |
| `*` (joker karakter)                 | `claude-haiku-4.7`      |

`*` joker karakteri, tanınmayan herhangi bir modeli belirtilen hedefle eşler. `agent_bridge_mappings` tablosunda kalıcı olarak saklanır.

> **İpucu — aracının gerçek model kimliklerini keşfedin.** Bir IDE, kullanıcı arayüzündeki
> etiketlerden farklı olan ve ana sürümler arasında değişen model adları gönderebilir. Örneğin
> **Antigravity 2**, ağ üzerinden eski belgelerde gösterilen `gemini-2.5-pro` yerine
> `gemini-3.1-pro-low`, `gemini-pro-agent` ve `gemini-3.1-flash-lite` gönderir. Eşleşen bir
> eşleme olmadan tek bir sohbet gönderin: MITM, gelen tam `model:` değerini günlüğe kaydeder ve
> isteği doğrudan geçirir. Bu değişmez değeri eşleyin; ardından sonraki istek yakalanarak
> hedefinize yönlendirilir.

### 3.5 Risk bildirimi

AgentBridge, IDE'nin yukarı akış sağlayıcılarıyla kimlik doğrulamak için kullandığı kimlik bilgilerine (OAuth belirteçleri, API anahtarları) müdahale eder. Bunlar **günlüğe kaydedilmeden önce maskelenir** (bkz. §2.7), ancak OmniRoute'un MITM katmanı tarafından görülebilir. Her aracının ilk kez etkinleştirilmesi sırasında kapatılabilir bir risk bildirimi penceresi gösterilir.

### 3.6 Bakım ve Tanılama

Pano, daha önce kullanıcı arayüzü bulunmayan operasyonel MITM rotalarını gösteren bir **Bakım ve Tanılama** kartı (`AgentBridgeMaintenanceCard`, `src/app/(dashboard)/dashboard/tools/agent-bridge/components/` içinde) sunar. Alt başlığı: _"Yakalama işlem hattını kendi kendine test edin, kalan sistem durumunu geri alın ve kurulumunuzu makineler arasında taşıyın."_ Kartın istemci yardımcıları `src/lib/inspector/agentBridgeMaintenanceApi.ts` içinde bulunur.

| Düğme                         | Rota                                   | İşlevi                                                                                                                                                                                                                   |
| ----------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Tanıla**                    | `GET /api/tools/agent-bridge/diagnose` | Yakalama işlem hattının öz sınamasını çalıştırır ve her denetim için bir rapor gösterir (✓/✗ + düzeltme ipucu).                                                                                                          |
| **Onar**                      | `POST /api/tools/agent-bridge/repair`  | Bir çökme veya SIGKILL sonrasında geride kalan sahipsiz MITM sistem durumunu (DNS yanıltma girdileri, kök CA, sistem proxy'si) geri alır. İdempotenttir — durum temiz olduğunda "Onarılacak bir şey yok" bildirir.       |
| **CA'yı kaldır**              | `DELETE /api/tools/agent-bridge/cert`  | MITM kök CA'sına duyulan güveni kaldırır ve CA'yı işletim sisteminin güven deposundan siler (açık, idempotent). Yalnızca CA hâlihazırda güvenilir olduğunda gösterilir; satır içi "CA kaldırılsın mı?" onayı gerektirir. |

| Denetim adı        | Doğruladığı şey                                                           | Hata durumundaki ipucu                                                                                                                                              |
| ------------------ | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server-running`   | MITM sunucu işleminin etkin olması                                        | "MITM sunucusu çalışmıyor. AgentBridge sekmesinden başlatın."                                                                                                       |
| `server-reachable` | MITM sunucusunun kendi portunda bağlantıları kabul etmesi (TCP yoklaması) | "MITM sunucusu kendi portunda bağlantıları kabul etmiyor. Portun boş olduğunu ve bu porta bağlanmak için gerekli ayrıcalıklara sahip olduğunuzu kontrol edin."      |

**Sahipsiz durum başlığı:** sayfa, bir çökme sonrasında geride kalan durumu (DNS yanıltma / CA / sistem proxy'si) algıladığında kartta kehribar renkli bir başlık gösterilir — _"Önceki bir oturum geride sistem durumu bıraktı (DNS yanıltma, CA veya sistem proxy'si). Temizlemek için Onar'ı çalıştırın."_ — ve **Onar** düğmesi vurgulanır. `Repair`, ProxyBridge'in `--cleanup` bayrağının uygulama katmanındaki karşılığıdır (`src/mitm/manager.ts` içindeki `repairMitm()` işlevine devreder).

> MITM kök CA'sı, tekrarlanan sudo istemlerini önlemek için durdurma/başlatma
> işlemleri boyunca yüklü tutulur (mitmproxy/Charles ile aynı davranış); dolayısıyla kaldırılması,
> durdurma sırasında otomatik olarak gerçekleşen bir işlem değil, açık bir
> **CA'yı kaldır** eylemidir.

### 3.7 Taşınabilir yapılandırmayı içe/dışa aktarma

AgentBridge, bir kurulumun makineler arasında çoğaltılabilmesi için **operatör tarafından ayarlanabilen** durumu sürümlü bir JSON blobu hâlinde serileştirebilir. Serileştirici `src/lib/inspector/configPortability.ts` dosyasıdır (`exportConfig()` / `importConfig()`) ve `AgentBridgeConfigSchema` tarafından doğrulanır.

Dışa aktarma tam olarak üç parça içerir (yerleşik varsayılanlar kasıtlı olarak dışa **AKTARILMAZ**; böylece içe aktarma işlemi bunları hiçbir zaman çoğaltmaz veya bunlarla çakışmaz):

| Alan             | Kaynak                                                           | Notlar                                                                  |
| ---------------- | ---------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `bypassPatterns` | kullanıcı tanımlı atlama desenleri (`agent_bridge_bypass`)       | varsayılan banka/devlet/okta desenleri hariç tutulur                    |
| `customHosts`    | Traffic Inspector özel ana makineleri (`inspector_custom_hosts`) | her biri: `{ host, kind: "llm"\|"app"\|"custom", label? }`              |
| `agentMappings`  | aracı başına model eşlemeleri (`agent_bridge_mappings`)          | eşlemeleri bulunan her aracı için `{ [agentId]: [{ source, target }] }` |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**İçe aktarma davranışı** (`POST /api/tools/agent-bridge/config`): atlama desenleri ve aracı başına eşlemeler **toptan değiştirilir**; özel ana makineler **idempotent olarak** eklenir (`INSERT OR IGNORE`). Yanıt, her birinden kaç tanesinin uygulandığını bildirir:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

Yapılandırmaya **DAHİL OLMAYANLAR**: sunucunun çalışma durumu, sertifika yolları, aracı bazında DNS durumu, üst CA yolu ve TPROXY ayarları — bunlar taşınabilir tercihler değil, ana makine/çalışma zamanı durumudur.

### Hassas ana makineler için atlama listesi

Atlama listesi; finans kuruluşlarının, OAuth/SSO sağlayıcılarının ve diğer hassas ana makinelerin şifrelerinin **asla çözülmemesini** sağlar. Bunların TLS trafiği, şeffaf bir TCP tüneli üzerinden geçer — OmniRoute düz metni hiçbir zaman görmez.

Varsayılan atlama kalıpları şunları içerir:

- `*.bank.*`, `*.gov.*` (finans/devlet)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/kimlik)
- `*.apple.com`, `*.icloud.com` (Apple sistem hizmetleri)

Kullanıcı tarafından eklenen atlama kalıpları `agent_bridge_bypass` tablosunda saklanır ve diğer her şeyden önceliklidir.

### Gizli bilgi maskeleme

`src/mitm/maskSecrets.ts` içindeki `maskSecrets()` uygulanır:

- `TrafficBuffer.push()` öncesinde her istek gövdesine
- Günlüğe kaydetme veya yayınlama öncesinde her üstbilgiye

Kalıplar: `sk-`/`ak-`/`pk-` önekli belirteçler, `Bearer` belirteçleri ve ≥40 karakterlik genel belirteçler.

### Üst akış CA sertifikası

`AGENTBRIDGE_UPSTREAM_CA_CERT` ayarlandığında dosya başlangıçta okunur. Yol mevcut olduğu hâlde dosya okunamıyorsa AgentBridge anlaşılır bir hata kaydeder ve başlamayı reddeder (kurumsal ortamlarda sessiz TLS hatalarını önler).

### Bilinen sınırlamalar

- **443 numaralı bağlantı noktası ayrıcalık gerektirir**: Linux'ta AgentBridge, Node ikili dosyasında `setcap 'cap_net_bind_service=+ep'` ayarına ihtiyaç duyar veya `authbind` aracılığıyla çalıştırılmalıdır. Kurulum Sihirbazı, işletim sistemine özgü talimatları gösterir.
- **IDE'nin yeniden başlatılması gerekir**: DNS yönlendirmesinden sonra yeni ana makine çözümlemesinin etkinleşmesi için IDE yeniden başlatılmalıdır.
- **Sabit kodlanmış OAuth belirteçleri**: Bazı aracılar (Kiro, Antigravity) OAuth yenileme belirteçlerini yerel olarak saklar. Bunlar AgentBridge için şeffaftır — AgentBridge her istekteki Bearer belirtecini görür ve bu belirteç, günlüğe kaydedilmeden önce maskelenir.
- **Electron ön yüzleri `NODE_EXTRA_CA_CERTS` gerektirir**: Ön yüzü paketlenmiş bir Node/Electron çalışma zamanında çalışan IDE'ler, işletim sistemi/NSS güven deposunu yok sayar ve `NODE_EXTRA_CA_CERTS` ayarlanmış bir kabuktan başlatılmalıdır (bkz. §3.2). Eksik olduğundaki belirti: IDE arka ucu kimlik doğrulaması yapar (MITM, `200` yanıtlarını gösterir) ancak kullanıcı arayüzü oturum kapalı durumda kalır.
- **Aynı IDE'nin birden fazla kurulumu birbirinden bağımsızdır**: Bir sistem kurulumu (ör. `/usr/share/antigravity/antigravity`) ile kullanıcıya özel bir "Full" kurulum (ör. `~/AntigravityIDE_Full/antigravity-ide`), kendi çalışma zamanlarına sahip ayrı işlemlerdir — her biri CA eklenerek yeniden başlatılmalıdır. Yeniden başlatmadan önce hangisinin çalıştığını ikili dosya yolundan belirleyin.
- **Kimlik, yönlendirilen model tarafından değil aracının sistem istemi tarafından belirlenir**: Bir aracının modelini farklı bir sağlayıcıya yeniden eşlediğinizde yanıt yine aracının yerel kimliğini öne sürer (ör. Antigravity, "Gemini tarafından destekleniyorum" şeklinde yanıt verir), çünkü IDE bunu sistem istemine ekler. Gerçek arka ucu modele kim olduğunu sorarak değil, `call_logs` / `proxy_logs` içindeki (`provider`, `model`, `target_format`) alanlarından doğrulayın.

## §6 Sorun Giderme

### 443 numaralı port çakışması

Başka bir işlem zaten 443 numaralı portu dinliyorsa (web sunucusu, VPN vb.):

```bash
lsof -i :443          # işlemi bulun
sudo fuser -k 443/tcp  # zorla sonlandırın (dikkatli kullanın)
```

Alternatif olarak, AgentBridge ayarlarında ayrıcalıksız bir port yapılandırın ve `iptables` / `pf` yönlendirme kuralları oluşturun.

### Sertifikaya güvenilmiyor

AgentBridge başlatıldıktan sonra IDE TLS hataları gösteriyorsa:

1. Sertifikanın yüklendiğini doğrulayın: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) veya `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. Bazı uygulamalar kendi güven depolarını kullanır (Firefox, Linux'ta Chrome). "Trust Cert" işlemini yeniden çalıştırın ve NSS/Firefox'a özgü sertifika deposunu kontrol edin.
3. Güven sağladıktan sonra IDE'yi yeniden başlatın — devam eden TLS oturumları eski güven durumunu kullanır.

### Güvenilir bir CA'ya rağmen IDE oturumu kapalı / "bağlantı hatası"

Belirti: DNS yönlendirildikten ve CA'ya güven sağlandıktan sonra Electron tabanlı bir IDE (ör. Antigravity)
**oturumu kapalı** olarak açılır veya bir kimlik doğrulama/bağlantı hatası gösterir; ancak MITM günlüğü,
önyükleme çağrılarının (`loadCodeAssist`, `fetchAvailableModels`, …) `200` döndürdüğünü gösterir.

Neden: IDE'nin **pakete dahil Node/Electron çalışma zamanı, işletim sisteminin güven deposunu yok sayar**. Yerel
arka uç (bir Go dil sunucusu), işletim sistemi CA'sına güvenir ve kimlik doğrulaması yapar; ancak Electron ön ucu
bunu yapmaz — bu nedenle kullanıcı arayüzü çevrimdışı olduğunu düşünür.

Çözüm (her iki adım da gereklidir): `NODE_EXTRA_CA_CERTS=<ca.crt>` değişkenini dışa aktarın **ve IDE'yi masaüstü
simgesinden değil, aynı kabuktan yeniden başlatın**. Önce IDE'den tamamen çıkın — Electron'un tekil örnek kilidi,
ikinci bir başlatmanın yalnızca mevcut işleme odaklanmasına ve yeni ortamın yok sayılmasına neden olur. Bkz. §3.2.
Bu durum, bağımsız bir aracının MITM üzerinden çalışırken IDE
varyantının aynı kurulum altında başarısız olduğu açık bir upstream raporuyla örtüşür.

### DNS yayılmadı

`/etc/hosts` dosyasının güncellendiğini kontrol edin:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

DNS önbelleğini temizleyin:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### IDE algılanmadı

Otomatik algılama, yaygın kurulum yollarını kullanır. Algılama başarısız olmasına rağmen IDE yüklüyse:

- IDE ikili dosyasının standart dışı bir konumda olup olmadığını kontrol edin
- Kurulum Sihirbazı yine de çalışır — algılama hatası yalnızca rozetin kurulum yolunu göstermeyeceği anlamına gelir

### İşleyici hataları (upstream getirme işlemi başarısız)

AgentBridge istekleri yakalıyor ancak tüm istekler başarısız oluyorsa:

1. `/dashboard/providers` konumunda en az bir sağlayıcının bağlı olduğunu doğrulayın
2. OmniRoute sunucu günlüklerini kontrol edin: `.env` içinde `APP_LOG_LEVEL=debug`
3. `OMNIROUTE_BASE_URL` değişkeninin doğru yönlendirici uç noktasını gösterdiğini doğrulayın (varsayılan: `http://127.0.0.1:20128`)

## §8 Yol Haritası

### Trae araştırması

Trae nispeten yeni bir yapay zekâ kodlama asistanıdır. Bir işleyici uygulamadan önce:

1. VS Code / JetBrains mağazalarında veya bağımsız bir uygulama olarak ikili dosyayı/uzantıyı belirleyin
2. API ana makinelerini ve uç nokta yapılarını keşfetmek için trafiği mitmproxy ile yakalayın
3. Kimlik doğrulama mekanizmasını belirleyin
4. Kullanım Koşulları ve API'nin keşfedilebilirliğine göre devam etme/devam etmeme değerlendirmesi yapın

Araştırma tamamlanana kadar kontrol panelindeki Trae kartında, "Uygulanabilirliği bildir" bağlantısıyla birlikte "Araştırılıyor" rozeti gösterilir. `src/mitm/handlers/trae.ts` konumundaki işleyici taslağı, yapılandırılmış bir `Henüz uygulanmadı` hatası oluşturur.
