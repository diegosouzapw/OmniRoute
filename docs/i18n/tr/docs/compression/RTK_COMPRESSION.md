RTK sıkıştırması, terminal ve araç çıktıları için OmniRoute'un komut farkındalığına sahip sıkıştırma motorudur. Bağlam büyümesinin büyük bölümünün test günlüklerinden, derleme çıktılarından, paket yöneticisi gürültüsünden, kabuk dökümlerinden, Docker çıktılarından, git çıktılarından ve yığın izlerinden kaynaklandığı kodlama aracısı oturumları için tasarlanmıştır.

RTK, doğrudan `defaultMode: "rtk"` ile veya genellikle aşağıdaki gibi yığınlanmış bir işlem hattının ilk adımı olarak çalışabilir:

```txt
rtk -> caveman
```

Bu sıralama önce gürültülü makine çıktısını sıkıştırır, ardından Caveman'in kalan düz yazıyı yoğunlaştırmasını sağlar.

Üst kaynak RTK, komut çıktısında `%60-90` tasarruf bildirmektedir. README dosyasındaki örnek oturum, `~118,000` standart tokendan `~23,900` RTK tokenına düşerek `%79.7` (`~%80`) tasarruf sağlamaktadır. OmniRoute, Caveman girdi sıkıştırmasıyla birlikte yığınlanmış tasarruf hesaplaması için bu üst kaynak ortalamasını kullanır:

```txt
RTK ortalaması:  %80 tasarruf
Caveman girdisi: %46 tasarruf
Yığınlanmış:     1 - (1 - 0.80) * (1 - 0.46) = %89.2 tasarruf
Aralık:          1 - (1 - 0.60..0.90) * (1 - 0.46) = %78.4-94.6
```

## Filtre Çözümleme

RTK filtreleri şu sırayla yükler:

1. Yalnızca güvenildiğinde `.rtk/filters.toml` ve `.rtk/filters.json` içindeki proje filtreleri.
2. `DATA_DIR/rtk/filters.toml` ve `DATA_DIR/rtk/filters.json` içindeki global filtreler.
3. `open-sse/services/compression/engines/rtk/filters/` içindeki yerleşik filtreler.

Aynı kapsam içinde RTK TOML şema v1 filtreleri, OmniRoute JSON filtrelerine göre önceliklidir. İçe aktarılmış komuta özgü bir filtrenin o kapsamdaki daha geniş bir filtreyi geçersiz kılabilmesi için TOML `match_command` ifadeleri, komut türü eşleştirmesinden önce kontrol edilir. Dosya biçiminden bağımsız olarak proje kapsamı, global kapsama göre her zaman önceliklidir.

Düzenli ifade filtreleri, araç çıktısının aracılara nasıl gösterildiğini değiştirebildiğinden proje filtreleri kasıtlı olarak güven denetimine tabidir. Aşağıdakilerden biri doğru olduğunda proje filtre dosyası kabul edilir:

- `rtkConfig.trustProjectFilters`, `true` değerindedir.
- `OMNIROUTE_RTK_TRUST_PROJECT_FILTERS=1` ayarlanmıştır.
- `.rtk/trust.json`, proje filtre dosyasının eşleşen SHA-256 karmasını içerir.

Güven dosyası örneği:

```json
{
  "filtersSha256": "0123456789abcdef...",
  "filtersTomlSha256": "fedcba9876543210..."
}
```

Karmalar ayrıdır: `filtersSha256`, `.rtk/filters.json` dosyasına güvenirken `filtersTomlSha256`, `.rtk/filters.toml` dosyasına güvenir. Herhangi bir dosyanın düzenlenmesi yalnızca kendi güven girdisini geçersiz kılar. Global dosyalar yönetici tarafından yüklenir ve mevcut global filtre güven davranışını kullanır.

Özel filtreler, tek bir filtre nesnesi veya filtre nesneleri dizisi olabilir. Geçersiz özel filtreler atlanır ve `/api/context/rtk/filters` tanılamaları tarafından bildirilir. Geçersiz yerleşik filtreler işlemi hemen başarısız kılar.

## RTK TOML şeması v1 uyumluluğu

OmniRoute, RTK TOML şeması v1'i kullanarak bildirimsel filtre dosyalarını ayrıştırabilir, doğrulayabilir, test edebilir ve yükleyebilir.
Desteklenen alanlar şunlardır: `description`, `match_command`, `strip_ansi`, `filter_stderr`,
`strip_lines_matching`, `keep_lines_matching`, `replace`, `match_output`, `truncate_lines_at`,
`head_lines`, `tail_lines`, `max_lines`, `on_empty` ve `[[tests.<filter>]]` satır içi testleri.
Bilinmeyen alanlar, geçersiz veya güvenli olmayan düzenli ifadeler, eş zamanlı kaldırma/tutma kuralları, 1 MiB'tan
büyük dosyalar ve bilinmeyen filtrelere yapılan başvurular reddedilir. Satır içi testleri başarısız olan bir dosya,
incelenmek üzere doğrulanabilir ancak yüklenemez veya kullanıma alınamaz. Özel dosya yükleme hatalarında
açık kalma davranışı korunur: geçersiz dosya atlanır ve kalan filtreler çalışmaya devam eder.

OmniRoute, araç çıktısını istemci zaten yakaladıktan sonra alır; bu nedenle `filter_stderr = true`
işlem çıktısının yakalanma biçimini değiştiremez. Alan, işlem yapmayan bir ayar olarak kabul edilir ve doğrulama bir uyarı döndürür.
Bu özellik kasıtlı olarak RTK yürütülebilir dosyası, kabuk kancaları, Rust komut uygulamaları veya güven deposu düzeniyle
tam uyumluluk şeklinde değil, **RTK TOML şeması v1 uyumluluğu** şeklinde tanımlanır.

Kontrol panelinin gelişmiş RTK görünümü, yapıştırılan veya yüklenen TOML içeriğini kabul eder. Doğrulama salt okunurdur.
Yükleme işlemi, `DATA_DIR/rtk/filters.toml` dosyasını kısıtlayıcı izinlerle atomik olarak yazar ve
canlı filtre kataloğunu yeniden başlatma gerektirmeden yeniler. Mevcut bir dosyanın değiştirilmesi, açık bir `overwrite`
onayı gerektirir ve önce `DATA_DIR/rtk/filters.toml.bak` dosyasını oluşturur.

## Filtre DSL'i

Filtreler, [Sıkıştırma Kuralları Biçimi](./COMPRESSION_RULES_FORMAT.md) belgesinde açıklanan JSON şemasını kullanır.
Çalışma zamanı bu aşamaları sırasıyla uygular:

```txt
stripAnsi -> filterStderr -> replace -> matchOutput -> drop/include lines
  -> truncateLineAt -> head/tail/maxLines -> onEmpty
```

Önemli alanlar:

| Alan                         | Amaç                                                                        |
| ---------------------------- | --------------------------------------------------------------------------- |
| `rules.stripAnsi`            | Eşleştirmeden önce terminal renk/kontrol dizilerini kaldırır                |
| `rules.filterStderr`         | Eşleştirme/filtreleme öncesinde yaygın stderr öneklerini normalleştirir     |
| `rules.replace`              | Sıralı düzenli ifade değiştirmelerini uygular                               |
| `rules.matchOutput`          | Çıktı bilinen bir koşulla eşleştiğinde kısa bir özet döndürür               |
| `rules.matchOutput[].unless` | Bir hata/başarısızlık örüntüsü mevcutsa kısayolu atlar                      |
| `rules.dropPatterns`         | Gereksiz satırları kaldırır                                                 |
| `rules.includePatterns`      | İşlem yapılabilir satırlara öncelik verir                                   |
| `rules.collapsePatterns`     | Yinelenen eşleşen satırları daraltır                                        |
| `rules.deduplicate`          | Filtre bazında isteğe bağlıdır: art arda gelen yinelenen satırları daraltır |
| `rules.truncateLineAt`       | Unicode açısından güvenli, satır bazında kısaltma uygular                   |
| `rules.onEmpty`              | Tüm satırlar filtrelenirse yedek bir ileti sağlar                           |
| `tests[]`                    | Doğrulama geçidinde kullanılan satır içi örnekler                           |

Yerleşik filtrelerin satır içi `tests[]` örneklerini içermesi beklenir. Özellikle projeler arasında
paylaşıldıklarında, özel filtreler de bunları içermelidir.

## Satır Tekilleştirme (iki katman)

RTK, yinelenen satırları birbirinden bağımsız iki katmanda birleştirir:

1. **Filtre başına `deduplicate` (isteğe bağlı, varsayılan `false`).** Bir filtre, kesme işleminden önce _o filtrenin eşleşen çıktısındaki_ art arda yinelenen satırları birleştirmek için `rules.deduplicate: true` ayarını kullanabilir.
   Bu işlem `lineFilter.ts` içinde yürütülür. Eski filtrelerde, filtre `collapsePatterns` tanımladığında otomatik olarak etkinleştirilir. Şema:
   `open-sse/services/compression/engines/rtk/filterSchema.ts` içindeki `deduplicate: z.boolean().default(false)`.
2. **Motor genelinde `deduplicateThreshold` (varsayılan `3`).** Tüm filtreler çalıştıktan sonra motor, sonucun tamamında art arda gelen aynı satırlardan oluşan ve uzunluğu `>= deduplicateThreshold` olan tüm dizileri birleştirir
   (`deduplicateRepeatedLines`, `engines/rtk/index.ts` içinde uygulanır). Normalleştirme sırasında değer 2–100 aralığıyla sınırlandırılır.

Filtre başına geçiş önce (filtrenin içinde), motor genelindeki geçiş ise en son (birleştirilmiş çıktı üzerinde) çalışır; böylece iki işlem, çift sayım yapmadan birlikte uygulanır.

## Satır Gruplama (`enableGrouping`)

`rtkConfig.enableGrouping`, `true` olduğunda (varsayılan `false`), RTK tekilleştirme sonrası sonuç üzerinde, art arda gelen _neredeyse eşdeğer_ (bayt düzeyinde aynı olmayan) satır dizilerini birleştiren ek bir `groupSimilarLines` geçişi çalıştırır. `rtkConfig.groupingThreshold` (varsayılan `3`), gruplamayı tetikleyen en düşük dizi uzunluğudur. Bu, `deduplicateThreshold` ayarının yapısal karşılığıdır: tekilleştirme tam tekrarları, gruplama ise "küçük farklılıklarla aynı yapıya sahip" satırları işler. Her iki bayrak da `key_value` tablosunda kalıcı olarak saklanan `rtkConfig` JSON'unun bir parçasıdır (yukarıdaki Yapılandırma bölümüne bakın); dolayısıyla ayar yeniden başlatmalardan sonra korunur.

## Kod Yorumlarını Kaldırma (`stripCodeComments` / `preserveDocstrings`)

`rtkConfig.applyToCodeBlocks` etkinleştirildiğinde RTK, çitle çevrili kod bloklarındaki yorumları da kaldırabilir:

- `stripCodeComments` (varsayılan `false`) — isteğe bağlıdır. `true` olduğunda RTK, JavaScript ve TypeScript çitli bloklarındaki yorumları kaldırır. Geçmişte bu bayrak okunuyor ancak hiç uygulanmıyordu; bu nedenle üretim ortamında sessiz bir değişiklik yapılmasını önlemek için varsayılan değer "koru" olarak kalır.
- `preserveDocstrings` (varsayılan `true`) — yorumlar kaldırılırken JSDoc/`/** … */` blok yorumları korunur (bunlar, kapladıkları baytlardan daha değerli API belgeleri içerir). Bunları da kaldırmak için `false` olarak ayarlayın.

Yorum kaldırma işlemi `open-sse/services/compression/engines/rtk/codeStripper.ts` içinde uygulanır. Dizelerin, şablonların ve düzenli ifade değişmezlerinin hiçbir zaman yorumlarla karıştırılmaması için **TypeScript ayrıştırıcısını** (regex değil) kullanır ve JSX algılandığında işlemi tamamen iptal eder (böylece JSX ifade kapsayıcılarındaki yorumlar hiçbir zaman bozulmaz). Yorum kaldırma şu anda yalnızca **JavaScript ve TypeScript** için uygulanır — kaldırıcının `CodeLanguage` kümesindeki diğer dillerde (Python, Rust, Go, Ruby, Java) boş satırlar ve boşluklar birleştirilir, ancak yorumlar kaldırılmaz. Kaldırma işlemi uygulanmış blok çalışması, `rulesApplied` içinde `rtk:code-strip` olarak etiketlenir.

> **Not — GCF / tablo biçimli kodlama ayrı bir motordur.** RTK, "GCF"
> (Graph Compact Format) tablo biçimli/sütunlu JSON kodlayıcısını **içermez**. Daha eski bir
> `omni-tabular` kodlayıcısının yerini alan bu kodlayıcı, **headroom** motorunda bulunur
> (`open-sse/services/compression/engines/headroom/`; paketlenmiş codec ise
> `headroom/gcf/` altındadır). Burada belgelenen RTK filtre işlem hattıyla ilişkili değildir.

## Yapılandırma

Genel ayarlara `/api/settings/compression` üzerinden erişilebilir. RTK'ye özgü ayarlara da
`/api/context/rtk/config` üzerinden erişilebilir.

```json
{
  "defaultMode": "stacked",
  "autoTriggerMode": "stacked",
  "autoTriggerTokens": 32000,
  "stackedPipeline": [
    { "engine": "rtk", "intensity": "standard" },
    { "engine": "caveman", "intensity": "full" }
  ],
  "rtkConfig": {
    "enabled": true,
    "intensity": "standard",
    "applyToToolResults": true,
    "applyToCodeBlocks": false,
    "applyToAssistantMessages": false,
    "enabledFilters": [],
    "disabledFilters": [],
    "maxLinesPerResult": 120,
    "maxCharsPerResult": 12000,
    "deduplicateThreshold": 3,
    "customFiltersEnabled": true,
    "trustProjectFilters": false,
    "rawOutputRetention": "never",
    "rawOutputMaxBytes": 1048576,
    "enableGrouping": false,
    "groupingThreshold": 3,
    "stripCodeComments": false,
    "preserveDocstrings": true
  }
}
```

`enabledFilters` ve `disabledFilters`, örneğin `test-vitest` veya `git-diff` gibi filtre kimliklerini kullanır.

Tam `rtkConfig` yapısı, `open-sse/services/compression/types.ts` içindeki `RtkConfig` / `DEFAULT_RTK_CONFIG` tarafından tanımlanır. Nesnenin tamamı, SQLite `key_value` tablosunda `namespace = "compression"`, `key = "rtkConfig"` altında (`src/lib/db/compression.ts`) tek bir JSON değeri olarak kalıcılaştırılır ve okuma sırasında `normalizeRtkConfig` tarafından normalleştirilir. Dolayısıyla aşağıdaki her alan — `enableGrouping`, `groupingThreshold`, `stripCodeComments` ve `preserveDocstrings` dâhil — aynı depoda gidiş-dönüş yapar ve yeniden başlatmadan sonra korunur.

| Anahtar                | Varsayılan | Amaç                                                                                          |
| ---------------------- | ---------- | --------------------------------------------------------------------------------------------- |
| `deduplicateThreshold` | `3`        | Motor genelinde: daraltılacak minimum ardışık özdeş satır sayısı (2–100 aralığında)           |
| `enableGrouping`       | `false`    | İsteğe bağlı: birbirine yakın ardışık satır dizilerini daraltır                               |
| `groupingThreshold`    | `3`        | Gruplandırmayı tetikleyen minimum ardışık benzer satır dizisi                                 |
| `stripCodeComments`    | `false`    | İsteğe bağlı: çitle çevrili kod bloklarından yorumları kaldırır (`applyToCodeBlocks` gerekir) |
| `preserveDocstrings`   | `true`     | Yorumlar kaldırılırken JSDoc/`/** … */` bloklarını korur                                      |

```json
{
  "command": "npm test",
  "text": "FAIL tests/example.test.ts\nAssertionError: expected true\nTest Files 1 failed",
  "config": {
    "intensity": "standard"
  }
}
```

Sıkıştırma önizleme yükü:

```json
{
  "mode": "stacked",
  "messages": [
    {
      "role": "tool",
      "content": "FAIL tests/example.test.ts\nAssertionError: expected true\nTest Files 1 failed"
    }
  ],
  "config": {
    "rtkConfig": {
      "rawOutputRetention": "failures"
    }
  }
}
```

Yönetim rotaları, pano yönetimi kimlik doğrulaması veya eşleşen API anahtarı politikasını gerektirir.

RTK TOML doğrulama yükü:

```json
{
  "action": "validate",
  "content": "schema_version = 1\n\n[filters.my-tool]\nmatch_command = \"^my-tool\\\\b\"\nmax_lines = 20\n"
}
```

Doğrulanan dosyayı genel olarak yüklemek için `"action": "install"` kullanın. `"overwrite": true` seçeneğini yalnızca mevcut bir genel dosyanın değiştirilmesini inceleyip onayladıktan sonra ekleyin.

## Ham Çıktı Kurtarma

RTK normalde yalnızca sıkıştırılmış metni döndürür. Hata ayıklama amacıyla `rawOutputRetention`, redakte edilmiş
ham çıktının saklanmasını sağlayabilir:

| Değer      | Davranış                                                      |
| ---------- | ------------------------------------------------------------- |
| `never`    | Ham çıktıyı saklama                                           |
| `failures` | Yalnızca muhtemel hata çıktılarını sakla                      |
| `always`   | Redaksiyondan sonra sıkıştırılmış her RTK ham çıktısını sakla |

Saklanan dosyalar şuraya yazılır:

```txt
DATA_DIR/rtk/raw-output/
```

Yaygın bearer token'ları, API anahtarları, Slack token'ları,
AWS erişim anahtarları ve atama biçimindeki `token=...`, `secret=...`, `password=...` değerleri dahil olmak üzere gizli bilgiler kalıcı olarak kaydedilmeden önce redakte edilir. Analitik,
yalnızca işaretçi kimliğini, boyutu ve hash meta verilerini saklar.

## Doğrulama Geçidi

Odaklanmış doğrulama geçidi, harici komutları shell üzerinden çalıştırmadan yerleşik satır içi filtre testlerini çalıştırır:

```bash

```

Daha kapsamlı RTK geçidi şöyledir:

```bash

  tests/unit/compression/rtk-*.test.ts \

  tests/unit/compression/context-compression-api.test.ts
```

Sürüm yayımlamadan önce kapsamlı sıkıştırma geçidini çalıştırın:

```bash

  tests/golden-set/*.test.ts \

```

## RTK'yi Genişletme

1. Bir filtre JSON dosyası ekleyin veya güncelleyin.
2. Önemli davranışı doğrulayan en az bir `tests[]` örneği ekleyin.
3. Yeni komut aileleri için `tests/unit/compression/fixtures/rtk/` altında bir fixture ekleyin.
4. Yeni bir çıktı sınıfı eklerken komut algılama kapsamı ekleyin.
5. Doğrulama ve kapsamlı RTK geçitlerini çalıştırın.
6. Filtre projeye özelse `.rtk/filters.json` dosyasını commit edin ve `.rtk/trust.json` dosyasını yalnızca incelemeden sonra yenileyin.

## Yoğunluk Seviyeleri (v3.8.16+)

RTK, **sıkıştırma agresifliği** ile **güvenlik** arasında denge kuran **3 yoğunluk seviyesini** destekler. Seviye, motor yapılandırmasındaki `config.intensity` aracılığıyla ayarlanır.

### 3 Seviye

| Seviye                  | Kısaltma eşiği        | Token tasarrufu | Risk      | En uygun kullanım                     |
| ----------------------- | --------------------- | --------------- | --------- | ------------------------------------- |
| `minimal`               | Bölüm başına 24 satır | ~20-40%         | Çok düşük | Kritik bağlam içeren üretim ortamları |
| `standard` (varsayılan) | Bölüm başına 24 satır | ~50-70%         | Düşük     | Günlük kodlama oturumları             |
| `aggressive`            | Bölüm başına 16 satır | ~70-90%         | Orta      | Uzun oturumlar, maksimum tasarruf     |

### Kısaltmanın Gerçekleştiği Yer

Kısaltma eşiği `lineFilter.ts` dosyasını etkiler:

```ts
// Kaynak: open-sse/services/compression/engines/rtk/index.ts:329-330
config.intensity === "aggressive" ? 16 : 24,
config.intensity === "aggressive" ? 16 : 24,
```

Her bölümün hem **başı** hem de **sonu** korunur; kısaltma devreye girdiğinde ortadaki içerik çıkarılır.

### Neler Kalır, Neler Kesilir

| İçerik                       | minimal       | standard      | aggressive    |
| ---------------------------- | ------------- | ------------- | ------------- |
| Hatalar / stack trace'ler    | ✅ korunur    | ✅ korunur    | ✅ korunur    |
| Test başarısızlıkları        | ✅ korunur    | ✅ korunur    | ✅ korunur    |
| Derleme hataları             | ✅ korunur    | ✅ korunur    | ✅ korunur    |
| Başarılı testler (ayrıntılı) | ✅ korunur    | 🟡 daraltılır | 🟡 daraltılır |
| Rutin çıktı (bilgi log'ları) | 🟡 daraltılır | 🟡 daraltılır | ❌ çıkarılır  |
| İlerleme çubukları           | 🟡 daraltılır | ❌ çıkarılır  | ❌ çıkarılır  |
| Banner / ASCII sanatı        | 🟡 daraltılır | ❌ çıkarılır  | ❌ çıkarılır  |

### Doğru Yoğunluğu Seçme

```
                  Bağlam kaybı felaketle sonuçlanır mı?
                  │
      ┌───────────┼───────────┐
      │           │           │
    EVET        HAYIR       EMİN DEĞİLİM
      │           │           │
      ▼           │           │
   minimal        │           │
      │           │           │
      │           ▼           ▼
      │      Verim ne kadar   Önce `standard` deneyin
      │      kritik?          (vakaların %80'inde
      │           │           işe yarar)
      │      ┌────┴────┐
      │      │         │
      │    DÜŞÜK     YÜKSEK
      │      │         │
      │      ▼         ▼
      │   standard   aggressive
      │      │         │
      └──────┴─────────┘
```

### Yoğunluğu Yapılandırma

**Kombinasyon başına** (kombinasyon yapılandırmasında):

```json
{
  "combo": "my-coding-combo",
  "routing": {/* ... */},
  "compression": {
    "engine": "rtk",
    "intensity": "aggressive"
  }
}
```

**Program aracılığıyla**:

`rtkEngine` (`@omniroute/open-sse/services/compression/engines/rtk`) bir
`CompressionEngine`'dir ve `updateConfig` metoduna sahip değildir. Bunun yerine motorun yapılandırmasını
registry yardımcısı aracılığıyla güncelleyin:

```ts
import { updateEngineConfig } from "@omniroute/open-sse/services/compression/engines/registry";

updateEngineConfig("rtk", { intensity: "aggressive" });
```

### Etkiyi Doğrulama

Filtrenizin seçtiğiniz yoğunlukta güvenli olduğunu doğrulamak için **Doğrulama Geçidi**ni (aşağıya bakın) kullanın:

```ts
import { runRtkFilterTests } from "omniroute/compression/engines/rtk/verify";

const result = runRtkFilterTests({ intensity: "aggressive" });
if (!result.passed) {
  console.error("Filters failed at aggressive intensity");
}
```

## Özel Filtre Geliştirme (v3.8.16+)

`engines/rtk/filters/` dizini, **49'dan fazla yerleşik filtre JSON dosyası** içerir. Varsayılanların kapsamadığı özel araçların çıktısını sıkıştırmak için kendi filtrelerinizi ekleyebilirsiniz.

### Filtre Şeması (Zod)

```ts
{
  "id": "string",                      // Zorunlu. Filtre tanımlayıcısı (kebab-case, ör. "python-traceback")
  "label": "string",                   // Zorunlu. İnsan tarafından okunabilir filtre adı
  "description": "string",             // İsteğe bağlı (varsayılan: ""). Filtrenin ne yaptığına ilişkin kısa açıklama
  "category": "git|test|build|shell|docker|package|infra|cloud|generic",
  "priority": number,                  // İsteğe bağlı (0-100, varsayılan: 50). Yürütme sırası (daha yüksek = önce)
  "match": {
    "commands": ["string"],            // Eşleştirilecek komut adları (ör. "python", "pytest")
    "patterns": ["string"],            // Çıktıyla eşleştirilecek regex kalıpları
    "outputTypes": ["string"]          // Algılanan çıktı sınıfları (ör. "test-failure")
  },
  "rules": {
    "stripAnsi": boolean,              // İsteğe bağlı (varsayılan: false). ANSI renk kodlarını kaldır
    "replace": [                       // Bul ve değiştir kuralları (varsayılan: [])
      { "pattern": "regex", "replacement": "..." }
    ],
    "matchOutput": [                   // Kalıp eşleşmesinde kısa devre yap (varsayılan: [])
      {
        "pattern": "regex",
        "message": "short summary",
        "unless": "regex"              // Bu kalıp eşleşirse atla
      }
    ],
    "includePatterns": ["string"],     // Korunacak satırlar (regex kalıpları, varsayılan: [])
    "dropPatterns": ["string"],        // Kaldırılacak satırlar (regex kalıpları, varsayılan: [])
    "collapsePatterns": ["string"],    // Tek örneğe indirgenecek satırlar (varsayılan: [])
    "deduplicate": boolean,            // İsteğe bağlı (varsayılan: false). Yinelenen satırları kaldır
    "truncateLineAt": number,          // İsteğe bağlı (varsayılan: 0). Satırları maksimum karakter sayısına göre kısalt
    "maxLines": number,                // İsteğe bağlı (varsayılan: 0). Toplam satır sayısı için kesin üst sınır
    "headLines": number,               // İsteğe bağlı (varsayılan: 20). Eşleşen çıktının ilk N satırını koru
    "tailLines": number,               // İsteğe bağlı (varsayılan: 20). Eşleşen çıktının son N satırını koru
    "onEmpty": "string",               // İsteğe bağlı (varsayılan: ""). Tüm satırlar filtrelenirse kullanılacak yedek mesaj
    "filterStderr": boolean            // İsteğe bağlı (varsayılan: false). stderr çıktısını da filtrele
  },
  "preserve": {
    "errorPatterns": ["string"],       // Her zaman korunması gereken kalıplar (varsayılan: [])
    "summaryPatterns": ["string"]      // Son özet satırı için kalıplar (varsayılan: [])
  },
  "tests": [                           // Doğrulama için satır içi testler (varsayılan: [])
    {
      "name": "string",               // Zorunlu. Test adı
      "input": "sample output",        // Zorunlu. Örnek girdi metni
      "expected": "expected output",   // Zorunlu. Beklenen sıkıştırılmış çıktı
      "command": "optional command"    // İsteğe bağlı. Komut bağlamı
    }
  ]
}
```

```json
{
  "id": "python-traceback",
  "label": "Python Traceback Filter",
  "description": "Compresses Python tracebacks to essential file/line locations and error type",
  "category": "test",
  "priority": 60,
  "match": {
    "commands": ["python", "python3", "pytest", "uv", "poetry"],
    "patterns": ["Traceback \\(most recent call last\\)", "Error", "Exception"],
    "outputTypes": ["error-traceback"]
  },
  "rules": {
    "stripAnsi": true,
    "includePatterns": [
      "Traceback \\(most recent call last\\)",

    ],
    "dropPatterns": ["site-packages/", "^\\s+[a-z_]+\\([^)]*\\)$"],
    "headLines": 5,

  },

    "errorPatterns": ["Error:", "Exception:", "Traceback"],

  },

    {
      "name": "preserves-error-type-and-location",

    }
  ]

```

### Özel Filtreleri Yükleme

Dosyayı tanınan bir konuma yerleştirin:

```
~/.omniroute/rtk/filters/my-filter.json     # Kullanıcı düzeyi
<project>/.rtk/filters/my-filter.json      # Proje düzeyi
```

Filtreler, başlangıçta `open-sse/services/compression/engines/rtk/filterLoader.ts` içindeki `loadRtkFilters()` aracılığıyla otomatik olarak yüklenir. Yükleyici, filtreleri şu konumlarda arar:

- Yerleşik katalog: `open-sse/services/compression/engines/rtk/filters/`
- Kullanıcı dizini: `~/.omniroute/rtk/filters/`
- Proje dizini: `<project>/.rtk/filters/`

Filtreleri program aracılığıyla yüklemek için:

```ts
import { loadRtkFilters } from "@omniroute/open-sse/services/compression/engines/rtk/filterLoader";

// Seçenekler: customFiltersEnabled (kullanıcı/proje filtrelerini yükler, varsayılan olarak açık),
// trustProjectFilters, refresh.
const filters = loadRtkFilters({ customFiltersEnabled: true });
```

### Doğrulama

Filtreler, yükleme sırasında Zod şemasına göre doğrulanır. Yapısı hatalı olan bir filtre yüklenemez ve bir hata günlüğe kaydedilir:

```
RTK_FILTER_LOADER: "my-filter" filtresi doğrulamayı geçemedi:
  - rules.replace.0.pattern: Geçersiz regex
  - match.commands: boş olmamalıdır
```

Yüklü tüm filtreleri doğrulamak için `open-sse/services/compression/engines/rtk/verify.ts` dosyasından dışa aktarılan `runRtkFilterTests()` fonksiyonunu çağırın.

### En İyi Uygulamalar

1. **Her zaman `tests[]` ekleyin** — filtrenizin çalıştığını kanıtlar ve gerilemeleri önler
2. **Kısa devreler için `matchOutput` kullanın** — tek bir satır durumu anlatmaya yetiyorsa tüm bloğu değiştirin
3. **`strip` yerine `keep` tercih edin** — açıkça belirtilen "her zaman koru" kuralları, "her zaman kaldır" kurallarından daha güvenlidir
4. **3 yoğunluk düzeyinin tamamında test edin** — `minimal` etkisiz olmalı, `aggressive` ise hataları yine de korumalıdır
5. **`unless` alanını kullanın** — kısa devreleri "X mevcutsa tetikleme" koşuluyla koruyun

## Ham Çıktıyı Kurtarma ve Doğrulama Geçidi

RTK çıktıyı agresif bir şekilde sıkıştırdığında hata ayıklama, denetim veya yeniden yürütme amacıyla **orijinal metni kurtarabilirsiniz**.

### Ham Çıktıyı Kurtarma Nasıl Çalışır?

```
Orijinal çıktı (10K token)
        │
        ▼
RTK sıkıştırması (rawOutput.enabled=true ile)
        │
        ├─▶ Sıkıştırılmış çıktı (2K token)  ──▶ LLM'ye
        │
        └─▶ Orijinal çıktı (10K token)      ──▶ DB'de saklanır
                                                  (request_id ile bağlantılıdır)
```

### Ham Çıktı Depolamayı Etkinleştirme

**İstek başına** (combo yapılandırmasında):

```json
{
  "compression": {
    "engine": "rtk",
    "intensity": "aggressive",
    "rawOutput": {
      "enabled": true,
      "maxBytes": 1048576 // 1MB sınır
    }
  }
}
```

**Varsayılan**: `rawOutput.enabled: false` (depolama alanından tasarruf sağlar).

### Depolama Maliyeti

| İstek başına                 | 1MB sınır    | 10MB sınır    |
| ---------------------------- | ------------ | ------------- |
| Ortalama sıkıştırılmış çıktı | ~5KB         | ~5KB          |
| Saklanan ham çıktı           | ~50-500KB    | ~500KB-5MB    |
| Günde 1000 istekle           | 50-500MB/gün | 500MB-5GB/gün |

> **Öneri**: Ham çıktıyı sürekli olarak değil, yalnızca **hata ayıklama oturumları** veya **örneklemeli denetim** için etkinleştirin.

### Orijinali Kurtarma

```ts
import { readRtkRawOutput } from "omniroute/compression/engines/rtk/rawOutput";

const raw = readRtkRawOutput(pointerId); // sıkıştırma istatistiklerindeki pointerId
if (raw) {
  console.log("Original output:", raw);
}
```

`pointerId`, sıkıştırmadan sonra `CompressionStats.rtkRawOutputPointers[]` içinde döndürülür.
Fonksiyon imzası için `open-sse/services/compression/engines/rtk/rawOutput.ts:102` dosyasına bakın.

### Doğrulama Geçidi

**RTK Filtre Doğrulaması** (`open-sse/services/compression/engines/rtk/verify.ts`), tüm filtreleri kendi `tests[]` dizilerine göre doğrular ve davranışın 3 yoğunluk düzeyinin tamamında doğru olmasını sağlar.

Doğrulamayı çalıştırmak için **`runRtkFilterTests()` çağrısı yapın**:

```ts
import { runRtkFilterTests } from "open-sse/services/compression/engines/rtk/verify";

const result = runRtkFilterTests();
console.log(`Passed: ${result.outcomes.filter((o) => o.passed).length}`);
console.log(`Failed: ${result.outcomes.filter((o) => !o.passed).length}`);
if (!result.passed) {
  console.error("Filters failed verification");
  result.outcomes
    .filter((o) => !o.passed)
    .forEach((o) => {
      console.error(
        `  - ${o.filterId} / ${o.testName}: expected "${o.expected}", got "${o.actual}"`
      );
    });
}
```

**Doğruladığı noktalar**:

1. Her filtre yüklenir ve şema doğrulamasından geçer
2. Her `tests[]` girdisi beklenen çıktıyı üretir
3. `minimal` yoğunluk hiçbir işlem yapmaz (orijinali korur, yalnızca yapısal filtreleri uygular)
4. `aggressive` yoğunluk hataları, başarısız testleri ve yığın izlerini korur
5. Sıkıştırılmış çıktı hiçbir zaman orijinal girdiden daha büyük olmaz

- Kaynak: `open-sse/services/compression/engines/rtk/` (63 dosya, ~70KB)

- **Bir filtre değişikliğini birleştirmeden önce** — her zaman testlerin geçtiğinden emin olun
- **RTK motorunu yükselttikten sonra** — şema değişmiş olabilir
- **İzleme kapsamında periyodik olarak** — test fikstürlerindeki sapmalara karşı koruma sağlar
- **Yeni bir araç/komut ailesi eklerken** — yeni filtrenin çalıştığını kanıtlar
