`chatgpt-web-codex` (alias `cgpt-codex`) relaie les tours Codex Responses via une
session de navigateur ChatGPT authentifiée. Il est indépendant de l’ancien fournisseur
commun `chatgpt-web`, désormais retiré, et utilise l’implémentation avec mention MIT située dans
`open-sse/vendor/codex-chatgpt-web/`, mise à jour jusqu’au commit v4.0.7 en amont
`b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494`.

## Retrait du fournisseur commun

Les anciens identifiants de fournisseur `chatgpt-web` et `cgpt-web` ne sont plus distribués, car
la provenance de leur implémentation de pré-clé/preuve de travail n’a pas pu être établie. Les
requêtes explicites vers l’un ou l’autre identifiant, y compris les identifiants de modèle préfixés par une barre oblique et les alias persistants, échouent
de manière fermée avec le statut HTTP `410` et le code **PROVIDER_RETIRED** avant toute requête en amont.

La migration `168_retire_chatgpt_web.sql` marque comme supprimées les connexions de fournisseur correspondantes et
invalide leurs baux de session actifs. Elle préserve l’historique des connexions et les listes d’autorisation
de clés API ; elle n’ajoute aucun accès de remplacement à une liste d’autorisation. Le fournisseur Codex et
ses connexions ne sont pas concernés par ce retrait.

## Prérequis

- un en-tête Cookie complet provenant d’une session ChatGPT connectée ;
- Chrome ou Chromium ainsi qu’une session graphique ou un affichage Xvfb pour les installations npm, systemd et PM2 ;
- avec le profil Docker `web`, le service Chromium interne défini dans
  `docker-compose.yml` ;
- OpenAI `tunnel-client` v0.0.13 et un connecteur personnalisé ChatGPT pour les outils Codex locaux.

Le tunnel n’est nécessaire que pour les tours utilisant des outils. Chaque route répertoriée, y compris `pro`, peut utiliser la
même capacité d’outil locale liée au tour lorsque le tunnel et le connecteur sont configurés.

## Configuration dans le tableau de bord

1. Ouvrez le fournisseur **ChatGPT Web (Codex)** et ajoutez une connexion.
2. Collez l’en-tête Cookie ChatGPT complet, l’identifiant du tunnel, la clé d’exécution et le nom du connecteur
   personnalisé. Les nouvelles configurations prenant en charge les outils doivent utiliser un connecteur nouvellement créé, nommé exactement
   `OmniRoute Codex v2`, avec Authentication défini sur None et Permissions défini sur Allow all
   actions.
3. Exécutez la vérification de la connexion. OmniRoute ouvre une conversation temporaire soutenue par un navigateur et détecte
   si Sol et Pro sont disponibles pour le compte.
4. Enregistrez la connexion. OmniRoute remplace le cookie collé par l’état de stockage Playwright
   vérifié et le stocke avec la clé d’exécution via l’abstraction chiffrée
   des identifiants.

Le cookie brut n’est pas conservé après un enregistrement réussi. Lorsque la session expire, ouvrez
la connexion, collez un nouvel en-tête Cookie complet et relancez la vérification. L’état du diagnostic
dans la boîte de dialogue de modification indique séparément l’état du navigateur, de l’état de stockage, de la connexion au compte, de la conversation temporaire, du tunnel,
du connecteur et de l’aller-retour de l’outil.

> Ne validez jamais dans le dépôt un cookie, une clé d’exécution, un état de stockage ou un jeton de capacité réel. Les valeurs de test et de
> documentation doivent toujours être des espaces réservés.

## Modèles et combinaisons

Les routes de modèle fixes sont :

- `chatgpt-web-codex/luna` — GPT-5.6 Luna, faible effort
- `chatgpt-web-codex/think` — GPT-5.6 Luna, effort moyen
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

Ajoutez l’une d’elles à une combinaison comme n’importe quel autre modèle. L’application Codex envoie le nom de la combinaison comme
`model` au point de terminaison Responses standard, `/v1/responses` ; il n’existe aucun point de terminaison Codex
distinct ni aucun changement de mode.

Les comptes Free/Go donnent accès aux routes Luna. Les comptes compatibles avec Sol donnent accès aux routes Instant à
High, tandis que les comptes compatibles avec Pro donnent également accès à Extra High et Pro. Chaque route possède un
modèle de backend et un niveau d’effort de raisonnement fixes ; un effort Responses explicite incompatible échoue
de manière fermée au lieu de modifier silencieusement le mode de navigateur sélectionné.

Ne renommez pas et ne réutilisez pas un ancien connecteur `Codex Native` ou `OmniRoute Codex`. ChatGPT
met en cache le contrat MCP public selon l’identité du connecteur, tandis que la passerelle mise à jour utilise un
nouveau contrat direct de jeton de tour. L’environnement d’exécution rejette ces identités obsolètes et exige
un nouveau connecteur `OmniRoute Codex v2`.

## Modèle de sécurité

- Le chemin natif nécessite une requête Responses, un client Codex reconnu et des identités
  de fil et de tour correspondantes.
- L’espace de travail, le bac à sable, la politique d’approbation et le catalogue d’outils proviennent du shell Codex natif ;
  le texte libre de l’invite ne fait pas autorité pour les définir.
- ChatGPT ne reçoit qu’une capacité à courte durée de vie par tour. Le courtier MCP n’accepte que
  les outils proposés par Codex au cours de ce tour précis.
- La confirmation automatique de **Autoriser une fois** renvoie uniquement la demande d’outil à Codex. Codex seul
  décide de son approbation et de son exécution.
- Avant la première sortie, une combinaison peut basculer vers une autre cible compatible. Une fois
  la sortie commencée, le fournisseur, le modèle, la connexion et le tour du navigateur restent épinglés jusqu’à la
  fin du tour.
- Les cookies, les clés d’exécution, l’état du stockage et les jetons de capacité n’apparaissent pas dans les réponses
  du fournisseur ni dans les journaux de requêtes.

## VPS sans affichage et Docker

Pour les installations npm, systemd et PM2, OmniRoute détecte les chemins Chrome et Chromium courants.
Vous pouvez également définir `CHATGPT_WEB_CODEX_CHROME_PATH`. Les tours d’exécution utilisent délibérément Chrome
avec interface graphique, car ChatGPT rejette la configuration d’un navigateur réellement sans interface. Un hôte sans affichage doit donc
exécuter OmniRoute avec un affichage Xvfb privé ; définir uniquement le chemin de Chrome n’en fournit pas.

Le profil Docker `web` démarre `chatgpt-web-codex-browser` sur le réseau Compose
interne. Le conteneur auxiliaire exécute Chrome avec interface graphique dans Xvfb ; aucun affichage physique n’est donc nécessaire. Son port CDP
n’est pas publié sur l’hôte. Le volume protégé du profil du navigateur est distinct du volume de données
d’OmniRoute, et le navigateur dispose d’une quantité suffisante de mémoire partagée. Le proxy CDP interne
écoute uniquement sur le port `9223` au sein du réseau Compose ; Chrome reste lié à l’interface de bouclage dans le
conteneur auxiliaire.

Un bail de supervision sous `DATA_DIR` empêche plusieurs processus OmniRoute de posséder
le même état de tunnel et de courtier. Tout conflit est signalé par le diagnostic.

## Récupération interactive

Le parcours Docker automatisé ne comporte aucune fenêtre visible depuis l’hôte, mais Chrome s’exécute bien avec une interface graphique dans
l’affichage Xvfb privé. Lorsque ChatGPT exige une connexion ou un défi interactif, l’infrastructure de navigateur VNC
existante peut être utilisée pour la récupération. L’interface du navigateur et CDP doivent rester accessibles uniquement
via l’interface de bouclage, une connexion de gestion authentifiée ou un tunnel SSH ; noVNC reste désactivé
pendant le fonctionnement normal.

## Solution de repli WebSocket

Lorsqu’une combinaison contient ChatGPT Web (Codex), le pont WebSocket de Responses demande la
solution de repli HTTP/SSE avant de se connecter au service en amont. Le transfert passe ensuite par
`/v1/responses`.
