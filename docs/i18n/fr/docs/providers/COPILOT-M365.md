`copilot-m365-web` (alias `m365copilot`) envoie des requêtes de conversation au format OpenAI via une
session de navigateur Microsoft 365 Copilot BizChat authentifiée sur
`m365.cloud.microsoft/chat`. Il s’agit d’une intégration non officielle.

> **Vous découvrez les fournisseurs utilisant des cookies Web ?**
>
> Consultez **`docs/getting-started/WEB-COOKIE-GUIDE.md`** pour connaître le processus général de configuration, les recommandations d’authentification, les limitations et les procédures de dépannage avant de suivre ce guide propre au fournisseur.
>
> **Important :** l’identifiant de connexion de ce fournisseur **n’est pas un cookie**. Ne copiez pas
> les cookies de `m365.cloud.microsoft`. L’identifiant de connexion se compose d’un paramètre de requête d’URL WebSocket
> et d’un segment de chemin, tous deux récupérés depuis l’onglet Réseau des outils de développement.

## Prérequis

- Un compte Microsoft 365 ayant accès à BizChat sur `m365.cloud.microsoft/chat`
- Un navigateur basé sur Chromium (Chrome, Edge) pour inspecter les WebSockets dans les outils de développement
- Une licence M365 Copilot (incluse dans de nombreuses offres Microsoft 365 Business/Enterprise)

## Récupération de l’identifiant de connexion (méthode WebSocket)

1. Connectez-vous sur `https://m365.cloud.microsoft/chat` et démarrez une conversation.
2. Ouvrez **Outils de développement → Réseau**.
3. Filtrez par **WS** (WebSocket).
4. Cliquez sur la connexion WebSocket Chathub. Recherchez une URL commençant par
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Depuis son **URL de requête**, copiez :
   - La valeur du paramètre de requête `access_token` (un JWT à durée de vie limitée).
   - Le segment de chemin Chathub situé après `/Chathub/` (par exemple `<oid>@<tenant>`).

L’URL complète se présente sous la forme suivante :

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. Dans OmniRoute, accédez à **Fournisseurs → Ajouter un fournisseur**, sélectionnez **Microsoft 365 Copilot
   (BizChat)**, puis collez l’identifiant de connexion au format suivant :

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Cliquez sur **Tester la connexion**, puis sur **Enregistrer**.

## Récupération de l’identifiant de connexion (importation HAR)

Au lieu de copier manuellement les valeurs depuis l’URL WebSocket, vous pouvez exporter un fichier HAR
depuis les outils de développement :

1. Ouvrez **Outils de développement → Réseau**.
2. Démarrez ou poursuivez une conversation BizChat (cela déclenche la connexion WebSocket).
3. Faites un clic droit dans le panneau Réseau, puis sélectionnez **Enregistrer tout au format HAR avec le contenu**.
4. Dans OmniRoute, utilisez le bouton **Importer un fichier .har** dans la boîte de dialogue de connexion au fournisseur.

OmniRoute recherche l’URL WebSocket Chathub dans le fichier HAR, extrait
`access_token` et `chathubPath`, puis renseigne automatiquement les champs de l’identifiant de connexion. L’importation
HAR décode la date d’expiration du JWT et affiche la durée de validité restante du jeton.

> **Ne validez jamais dans un dépôt une véritable exportation HAR, un jeton d’accès ou un jeton d’actualisation.** Les valeurs utilisées dans les tests et
> la documentation doivent toujours être des valeurs substitutives.

## Durée de validité et actualisation du jeton

La durée de validité de `access_token` est limitée (généralement **environ 75 minutes**). Après son expiration, le fournisseur
signale une erreur de connexion et vous devez récupérer à nouveau l’identifiant de connexion.

### Actualisation automatique avec `refreshToken`

Pour éviter de devoir récupérer manuellement l’identifiant, vous pouvez stocker un jeton d’actualisation Microsoft dans les
**Paramètres avancés → providerSpecificData** de la connexion :

| Champ          | Description                                                                        |
| -------------- | ---------------------------------------------------------------------------------- |
| `refreshToken` | Jeton d’actualisation Microsoft OAuth pour la portée `substrate.office.com/sydney` |
| `tier`         | `individual` (par défaut), `edu` ou `enterprise`                                   |

Obtenez le jeton d’actualisation à partir d’un flux Microsoft de code d’appareil ou de code d’autorisation
utilisant la portée `substrate.office.com/sydney`. Lorsque `refreshToken` est défini, OmniRoute
actualise de manière préventive `access_token` avant chaque requête. Vous n’avez donc pas besoin de
récupérer à nouveau l’identifiant après chaque expiration d’environ 75 minutes.

Si `refreshToken` n’est pas défini, vous devez récupérer manuellement l’identifiant de connexion WebSocket
après chaque expiration.

### Sélection du niveau

| Niveau       | Alias          | Interface                    |
| ------------ | -------------- | ---------------------------- |
| `individual` | _(par défaut)_ | M365 Copilot grand public    |
| `edu`        | `included`     | M365 Copilot Éducation       |
| `enterprise` | `work`         | M365 Copilot pour le travail |

Définissez le niveau dans **Paramètres avancés → providerSpecificData → tier**. Le niveau affecte
le routage de BizChat et l’accès aux modèles.

## Modèle de sécurité

- **Intégration non officielle.** Ce fournisseur utilise la rétro-ingénierie du protocole
  WebSocket de BizChat. Il peut cesser de fonctionner sans préavis si Microsoft modifie le point de terminaison.
- L’indicateur `subscriptionRisk: true` reflète le fait que l’intégration repose sur un
  point de terminaison non documenté. Des restrictions de compte sont possibles, mais non confirmées.
- Le jeton d’accès est un JWT à courte durée de vie. Traitez-le comme un mot de passe : ne le validez pas dans un dépôt,
  ne le consignez pas dans des journaux et ne le partagez pas.
- Le jeton d’actualisation accorde un accès à long terme à l’interface BizChat. Stockez-le avec les
  mêmes précautions qu’une clé d’API.

## Dépannage

### L’authentification échoue immédiatement

- Vérifiez que vous avez copié les informations depuis l’**URL WebSocket**, et non depuis une requête XHR/Fetch. Les
  identifiants se trouvent dans le paramètre de requête `access_token` de la connexion WebSocket
  Chathub — et non dans un en-tête `Authorization: Bearer`.
- Assurez-vous que `chathubPath` inclut le segment `<oid>@<tenant>` complet provenant du chemin de
  l’URL.

### Le jeton expire après environ 75 minutes

Ce comportement est attendu. Sans `refreshToken`, le jeton d’accès a une courte durée de vie. Vous pouvez :

- Récupérer de nouveau les identifiants depuis DevTools, ou
- Configurer un `refreshToken` dans les paramètres avancés afin d’activer l’actualisation automatique.

### Le test de connexion réussit, mais le chat renvoie une erreur 401

Le jeton a peut-être expiré entre la validation et la première requête. Récupérez de nouveau des
identifiants valides.

### Copilot n’apparaît pas dans la liste des fournisseurs

Assurez-vous que `copilot-m365-web` est activé dans **Tableau de bord → Fournisseurs**. Le fournisseur peut
être masqué par défaut dans certaines offres.
