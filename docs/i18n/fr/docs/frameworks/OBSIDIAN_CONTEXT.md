> `src/app/api/settings/obsidian/webdav/route.ts` (API de paramètres). L’enregistrement
> des outils et la configuration des portées se trouvent dans `open-sse/mcp-server/server.ts`.

## Présentation

OmniRoute se connecte à un coffre **Obsidian** en tant que **source de contexte** — une
base de connaissances Markdown locale que les agents lisent et modifient au moyen du
serveur MCP intégré. L’intégration communique avec l’extension communautaire
**Obsidian Local REST API** exécutée dans l’application de bureau, ce qui permet aux
agents de rechercher des notes, de lire/écrire/corriger des fichiers, de parcourir le
coffre, de travailler avec des notes périodiques quotidiennes/hebdomadaires, de gérer
les étiquettes, d’exécuter des commandes Obsidian et, éventuellement, de coordonner
une synchronisation bidirectionnelle du coffre entre ordinateur et appareil mobile.

Le client (`src/lib/obsidian/api.ts`) encapsule la Local REST API avec :

- **Nouvelle tentative avec délai progressif** pour les erreurs transitoires `5xx` et
  **délai d’expiration de 30 secondes** via `AbortController`.
- **Classification typée des erreurs** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- Une **indication claire en cas d’impossibilité de joindre Obsidian**, qui signale
  l’erreur de port courante (HTTP sur `27123`, **et non** le point de terminaison MCP
  sur `27124`) ainsi que le format Tailscale.
- **Encodage des chemins** relatifs au coffre afin de gérer de façon sûre les chemins
  de notes contenant des espaces ou des barres obliques.

## Configuration

Il n’existe **aucune variable d’environnement** pour le jeton Obsidian ou l’URL de
base — tous deux sont stockés dans la table SQLite `key_value` (espace de noms
`obsidian`) via `src/lib/db/obsidian.ts`. Le jeton est **chiffré au repos**
(AES-256-GCM, avec solution de repli rétrocompatible en texte brut). Effectuez la
configuration depuis l’onglet **Sources de contexte** du tableau de bord Endpoint
(`ObsidianSourceCard`), ou via l’API REST des paramètres.

> [!IMPORTANT]
> L’extension **Obsidian Local REST API** doit être installée et en cours d’exécution.
> Son interface REST écoute sur **HTTP `127.0.0.1:27123`** (l’URL de base par défaut).
> Le port `27124` est un point de terminaison MCP/HTTPS _distinct_ et est explicitement
> refusé par la route des paramètres. Pour vous connecter depuis un autre appareil,
> utilisez `http://<tailscale-ip>:27123`.

### Clés de configuration (table SQLite `key_value`, espace de noms `obsidian`)

| Clé               | Fonction                                                             | Chiffrée |
| ----------------- | -------------------------------------------------------------------- | -------- |
| `api_key`         | Jeton Bearer de la Local REST API                                    | oui      |
| `base_url`        | URL de base REST (par défaut `http://127.0.0.1:27123`)               | non      |
| `vault_path`      | Chemin absolu vers le répertoire du coffre (pour la synchronisation) | non      |
| `webdav_username` | Nom d’utilisateur WebDAV généré (synchronisation du coffre)          | non      |
| `webdav_password` | Mot de passe WebDAV généré (synchronisation du coffre)               | oui      |
| `webdav_enabled`  | Indique si la synchronisation du coffre via WebDAV est activée       | non      |

### Configuration via REST

```bash
# Enregistrer et valider le jeton de la Local REST API (POST effectue la validation au moyen d’une vérification d’état)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Vérifier l’état de la connexion (renvoie connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# Se déconnecter (efface le jeton stocké)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Toutes les méthodes nécessitent une authentification auprès du tableau de bord. `POST`
refuse toute URL utilisant le port `27124` et valide le jeton en appelant le point de
terminaison d’état de la Local REST API avant de le conserver.

### Synchronisation du coffre via WebDAV

`src/app/api/settings/obsidian/webdav/route.ts` gère une synchronisation facultative
du coffre reposant sur WebDAV (pilotée par `src/lib/obsidianSync.ts`). Son activation
dirige OmniRoute vers un répertoire de coffre local et génère une paire aléatoire de
nom d’utilisateur et de mot de passe WebDAV :

```bash
# Activer la synchronisation WebDAV pour un répertoire de coffre (génère un nom d’utilisateur et un mot de passe)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# Obtenir l’état de la synchronisation WebDAV (les identifiants ne sont renvoyés que lorsqu’elle est activée)
curl http://localhost:20128/api/settings/obsidian/webdav

# Désactiver la synchronisation WebDAV (efface les identifiants et le fichier .stignore géré)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Source de contexte par clé API (facultatif)

La configuration Obsidian peut être définie **par clé API** au moyen de la table
`api_key_context_sources` (`src/lib/db/apiKeyContextSources.ts`). Lorsqu’un appel MCP
contient l’identifiant d’une clé API authentifiée, `getObsidianConfigForApiKey()`
privilégie le jeton, l’URL de base et le chemin du coffre propres à cette clé
(`source: "api_key"`) et, à défaut, utilise la configuration globale
(`source: "global"`).

## Outils MCP (22)

Définis dans `open-sse/mcp-server/tools/obsidianTools.ts`. Le jeton et l’URL de base sont déterminés
à chaque appel (d’abord ceux propres à la clé API, puis ceux définis globalement). Les outils qui interrogent le **serveur de synchronisation**
OmniRoute (les quatre outils `obsidian_sync_*`) nécessitent également le jeton d’authentification de synchronisation configuré
dans les paramètres d’OmniRoute.

### Outils de lecture (`read:obsidian`)

| Outil                        | Description                                                                                                                             |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Vérifie si l’API REST locale est accessible et authentifiée.                                                                            |
| `obsidian_search_simple`     | Effectue une recherche en texte intégral dans le contenu des notes et renvoie des extraits avec les chemins des fichiers.               |
| `obsidian_search_structured` | Effectue une recherche à l’aide d’une expression JSON Logic (filtres and/or/regex/path).                                                |
| `obsidian_read_note`         | Lit une note à partir de son chemin relatif au coffre, éventuellement à un titre/bloc/frontmatter précis.                               |
| `obsidian_list_vault`        | Répertorie les fichiers et les répertoires du coffre (arborescence d’entrées).                                                          |
| `obsidian_get_document_map`  | Récupère la structure des titres de la note sous forme de correspondance titres → numéros de ligne.                                     |
| `obsidian_get_note_metadata` | Récupère le frontmatter, les étiquettes, les liens et le nombre de caractères/mots sans le contenu intégral.                            |
| `obsidian_get_active_file`   | Récupère le chemin et le contenu du fichier actuellement actif dans Obsidian.                                                           |
| `obsidian_get_periodic_note` | Récupère la note périodique quotidienne/hebdomadaire/mensuelle pour une date donnée (aujourd’hui si elle est omise).                    |
| `obsidian_get_tags`          | Répertorie toutes les étiquettes du coffre avec leur fréquence.                                                                         |
| `obsidian_list_commands`     | Répertorie les identifiants des commandes Obsidian disponibles (à utiliser avec `obsidian_execute_command`).                            |
| `obsidian_sync_status`       | État du serveur de synchronisation OmniRoute : fonctionnement, nom du coffre, port, durée de disponibilité et dernière synchronisation. |
| `obsidian_sync_conflicts`    | Répertorie les conflits de synchronisation non résolus (chemin, chemin du conflit, date de détection).                                  |

### Outils d’écriture (`write:obsidian`)

| Outil                            | Description                                                                                                     |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Crée ou remplace une note avec le contenu Markdown fourni.                                                      |
| `obsidian_append_note`           | Ajoute du contenu à une note, éventuellement à un titre/bloc précis.                                            |
| `obsidian_patch_note`            | Ajoute, insère ou remplace précisément du contenu au niveau d’un titre, d’un bloc ou d’un champ de frontmatter. |
| `obsidian_delete_note`           | Supprime définitivement une note du coffre.                                                                     |
| `obsidian_move_note`             | Déplace ou renomme une note dans le coffre.                                                                     |
| `obsidian_execute_command`       | Exécute une commande Obsidian à partir de son identifiant.                                                      |
| `obsidian_open_file`             | Ouvre un fichier dans Obsidian (le crée s’il n’existe pas).                                                     |
| `obsidian_sync_trigger`          | Déclenche immédiatement une synchronisation bidirectionnelle du coffre entre ordinateur et appareil mobile.     |
| `obsidian_sync_resolve_conflict` | Résout un conflit de synchronisation : conserver `local` (mobile), `remote` (ordinateur) ou `keep-both`.        |

> [!NOTE]
> Les cibles de `obsidian_patch_note` acceptent un `targetType` parmi `heading | block | frontmatter`
> et une `operation` parmi `append | prepend | replace`, avec un paramètre facultatif
> `createTargetIfMissing`. Les quatre outils `obsidian_sync_*` communiquent avec le serveur
> de synchronisation local (`http://127.0.0.1:27781` par défaut) et nécessitent le jeton de synchronisation.

### Portées

Les outils de lecture nécessitent `read:obsidian` ; les outils d’écriture nécessitent `write:obsidian`. L’application
est identique à celle de Notion — elle est gérée par `withScopeEnforcement()` dans
`open-sse/mcp-server/server.ts`, conditionnée par `OMNIROUTE_MCP_ENFORCE_SCOPES=true`, les
portées autorisées provenant de `OMNIROUTE_MCP_SCOPES` ou du contexte de portée de la clé API. Voir
[MCP-SERVER.md](./MCP-SERVER.md).

## Points de terminaison

| Méthode  | Chemin                          | Objectif                                                        |
| -------- | ------------------------------- | --------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | Renvoie `{ connected, hasToken, baseUrl, vaultPath }`.          |
| `POST`   | `/api/settings/obsidian`        | Enregistre et valide le jeton (rejette le port `27124`).        |
| `DELETE` | `/api/settings/obsidian`        | Déconnecte (supprime le jeton enregistré).                      |
| `GET`    | `/api/settings/obsidian/webdav` | État de la synchronisation WebDAV et identifiants (si activée). |
| `POST`   | `/api/settings/obsidian/webdav` | Active la synchronisation WebDAV pour un répertoire de coffre.  |
| `DELETE` | `/api/settings/obsidian/webdav` | Désactive la synchronisation WebDAV.                            |

> Il s'agit des routes de configuration du tableau de bord. Le coffre lui-même est accessible via l'API
> REST locale d'Obsidian (la `base_url` configurée) et via les outils MCP ci-dessus — il n'existe
> aucun point de terminaison proxy Obsidian `/v1` public.

## Cas d'utilisation

- **Réponses fondées sur le coffre** — `obsidian_search_simple` / `obsidian_search_structured`
  puis `obsidian_read_note`, afin qu'un agent réponde à partir de vos véritables notes.
- **Rédaction de notes / tenue d'un journal** — `obsidian_write_note`, `obsidian_append_note` ou
  la commande précise `obsidian_patch_note` pour consigner les résultats d'un agent, des résumés ou des notes quotidiennes
  (`obsidian_get_periodic_note`) dans le coffre.
- **Navigation dans le coffre** — `obsidian_list_vault`, `obsidian_get_document_map` et
  `obsidian_get_tags` pour explorer la structure avant toute lecture ou écriture.
- **Automatisation d'Obsidian** — `obsidian_list_commands` + `obsidian_execute_command` pour
  piloter les plugins/commandes depuis un agent ; `obsidian_open_file` pour afficher une note dans l'interface utilisateur.
- **Synchronisation mobile** — activez la synchronisation WebDAV, puis utilisez `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  pour coordonner la synchronisation ordinateur↔mobile et résoudre les conflits.
