## Présentation

Local Corpus permet à un opérateur d’exposer au serveur MCP d’OmniRoute un répertoire de fichiers texte explicitement approuvé. Les fichiers restent dans leur répertoire d’origine : OmniRoute stocke uniquement le chemin racine canonique dans SQLite et maintient un index de recherche en mémoire. Il ne copie pas le contenu du corpus dans le dépôt ni dans la base de données.

L’actualisation de l’index est incrémentielle. Les fichiers inchangés sont réutilisés en fonction de leur taille et de leur date de modification, les fichiers modifiés sont relus et hachés avec SHA-256, et les fichiers supprimés sont retirés. Une recherche actualise tout index datant de plus de 30 secondes ; les appelants peuvent également demander une actualisation immédiate.

## Configurer la source

La route des paramètres requiert la même authentification de gestion que les autres API de paramètres. Le chemin fourni doit déjà exister et correspondre au chemin absolu d’un répertoire.

```bash
# Connecter un répertoire approuvé
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# Vérifier la configuration et l’état de l’index
curl http://localhost:20128/api/settings/local-corpus

# Déconnecter sans modifier les fichiers sources
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## Outils MCP

Les trois outils requièrent `read:local-corpus`. Les réponses des outils exposent des chemins relatifs et le nom de base du répertoire racine, mais jamais son chemin absolu.

| Outil                 | Description                                                                                                    |
| :-------------------- | :------------------------------------------------------------------------------------------------------------- |
| `local_corpus_status` | Indiquer l’état de la configuration, la taille de l’index, les limites et l’heure de la dernière actualisation |
| `local_corpus_search` | Rechercher dans le texte indexé et renvoyer des extraits limités, délimités par ligne (jusqu’à 20 résultats)   |
| `local_corpus_read`   | Lire une plage de lignes limitée dans un fichier autorisé dont le chemin est relatif au corpus                 |

Exemples d’entrées MCP :

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## Limites de sécurité

- La liste d’autorisation est orientée texte : `.cfg`, `.csv`, `.geojson`, `.htm`, `.html`, `.ini`,
  `.js`, `.json`, `.jsonl`, `.jsx`, `.log`, `.md`, `.mjs`, `.ps1`, `.py`, `.sh`,
  `.sql`, `.toml`, `.ts`, `.tsx`, `.txt`, `.xml`, `.yaml` et `.yml`.
- Les liens symboliques sont ignorés. Les chemins de lecture sont canonisés et doivent rester dans la
  racine configurée ; les chemins absolus et les tentatives de traversée sont rejetés.
- Les noms de répertoires sensibles ou générés sont exclus : `.build`, `.codex`, `.env`,
  `.git`, `.next`, `.omniroute`, `.ssh`, `coverage`, `dist`, `node_modules` et
  `secrets`.
- Les limites par défaut sont de 5 000 fichiers, 1 Mio par fichier, 64 Mio de contenu indexé au total,
  environ 4 000 caractères par fragment de recherche et 400 lignes par lecture.
- Les fichiers contenant des caractères NUL sont considérés comme non textuels et sont ignorés ou rejetés.

Les documents binaires tels que les PDF, les DOCX, les images et les archives ne sont volontairement pas pris en charge. Convertissez-les dans un format texte approuvé au sein du répertoire configuré avant l’indexation.

## Remarques opérationnelles

- La modification ou la suppression de la racine configurée efface l’index partagé en mémoire.
- Le redémarrage d’un processus supprime l’index ; la recherche suivante le reconstruit à partir de la
  source configurée.
- `local_corpus_status` ne force pas l’analyse. Utilisez `local_corpus_search` avec
  `refresh: true` lorsqu’une nouvelle analyse immédiate est nécessaire.
- Les échecs d’analyse et de lecture sont comptabilisés ou renvoyés sous forme d’erreurs épurées ; les fichiers sources ne sont jamais modifiés.
