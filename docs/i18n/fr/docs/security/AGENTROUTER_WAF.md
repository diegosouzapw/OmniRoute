La passerelle en amont `agentrouter` exécute un filtre de contenu basé sur des mots-clés sur
`messages[].content`. Le filtre est en partie déterministe (il bloque toujours
certaines expressions) et en partie probabiliste (sensible aux rafales — il devient
plus agressif après des requêtes rapides et récupère après un délai de récupération).

Lorsque le WAF bloque une requête, il renvoie :

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## Périmètre du filtre

Le WAF inspecte uniquement `messages[].content`. Il **n’inspecte pas** :

- Le prompt `system`
- Les blocs de contenu structurés (`tool_result`, `tool_use`, `thinking`, `image`)
- Les champs `description` et `input_schema` des outils
- Les métadonnées de la requête, les en-têtes ou l’identifiant du modèle

## Motifs toujours bloqués (insensibles à la casse)

| Motif                           | Remarques                                              |
| ------------------------------- | ------------------------------------------------------ |
| Toute variante de `Lorem ipsum` | L’intégralité du vocabulaire latin lorem est bloquée   |
| `language model` (seul)         | "the language model" et "large language model" passent |
| `virtual assistant`             | "AI assistant" passe                                   |
| `I'm here to help`              | "here to help" seul est également bloqué               |
| `Claude, made by Anthropic`     | Expression complète uniquement                         |

## Motifs presque toujours bloqués

| Motif                                                   | Remarques                                                     |
| ------------------------------------------------------- | ------------------------------------------------------------- |
| `placeholder`                                           | Lorsqu’il apparaît seul (et non comme nom de paramètre, etc.) |
| `dummy data`                                            | Expression d’initialisation courante pour les fixtures        |
| `foo bar baz`                                           | Expression de substitution canonique                          |
| Jetons courts répétés (`AAA BBB CCC`, `test test test`) | Détecteur de bourrage de mots-clés                            |

## Comportement sous charge

Après environ 5 requêtes rapides dans un court intervalle, le WAF commence à bloquer du contenu
qui passerait normalement. Le quota s’assouplit après environ 5 à 10 secondes
d’inactivité. Il s’agit du même limiteur de débit lié à l’adresse IP et à la clé qui provoque
des erreurs intermittentes `400 content-blocked` lorsque Claude Code ou Codex CLI
effectue plusieurs appels d’utilisation d’outil ou d’envoi de message en succession rapide.

## Mesures d’atténuation déjà appliquées dans OmniRoute

1. **`open-sse/services/wafRateLimit.ts`** — protection contre les rafales imposant un
   intervalle minimal de 500 ms entre les requêtes sortantes vers toute URL `agentrouter:*`.
   Cet intervalle est largement inférieur au seuil de perception humaine de la latence et empêche
   l’activation du WAF sur le trafic normal.

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — lorsqu’un service en amont renvoie
   `400 content-blocked`, l’exécuteur réessaie la même URL avec un
   délai exponentiel (1,5 s, 3,0 s, 2 tentatives au maximum). Après ce délai,
   le WAF s’assouplit généralement et la nouvelle tentative réussit.

3. **`tests/unit/compression/harness.test.ts`** — la fixture de test
   `longInput` a été modifiée de `"lorem ipsum dolor sit amet ".repeat(40)`
   à `"example content for testing purposes ".repeat(40)` afin que, lorsque
   Claude Code lit ce fichier au moyen de l’outil `Read`, son contenu
   ne soit pas retransmis dans un bloc `tool_result` et ne déclenche pas le WAF.

## Recommandations pour les prompts et la sortie des outils

Si une session Claude Code ou Codex CLI rencontre à plusieurs reprises
`400 content-blocked`, vérifiez si le message utilisateur le plus récent et le
résultat d’outil le plus récent contiennent l’un des motifs ci-dessus, puis reformulez-les. Solutions
de contournement courantes :

- Remplacez `Lorem ipsum …` par `example text …` ou par le contenu réel
  que le test ou la fixture tente de modéliser.
- Remplacez `placeholder` (lorsqu’il apparaît seul) par `example value`,
  `sample value` ou par la valeur réelle.
- Remplacez `language model` par `large language model` ou `the model`.
- Remplacez `dummy data` par `sample data` ou par des valeurs d’initialisation réalistes.
- Remplacez `I'm here to help` / `here to help` par une introduction plus précise
  (par exemple, "I'll review the file you mentioned").

## Signalement des faux positifs au service en amont

Le filtre actuel est trop agressif — il bloque "Lorem ipsum" dans les
blocs `tool_result`, même si l’opérateur n’avait manifestement pas l’intention
d’injecter un prompt. Les opérateurs souhaitant que ce problème soit corrigé à la source doivent
contacter `agentrouter.org` pour signaler les faux positifs. La liste de blocage
ci-dessus constitue le résultat empirique de tests effectués sur le service en amont au 2026-08-03.
