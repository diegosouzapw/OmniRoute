## 1. Source de vérité du service (documentation officielle, vérifiée par recoupement)

- URL de base : `https://api.anysearch.com` (REST) + `POST /mcp` (MCP, JSON-RPC 2.0).
- `POST /v1/search` - paramètres : `query` (obligatoire), `max_results` (1-10, 10 par défaut), `tag` (routage vertical `{domain}.{sub_domain}`), `zone` (cn/intl), `language`, `params` (champs verticaux structurés), `format` (json/markdown).
- `GET /v1/sub-domains?domain=...` - catalogue des fonctionnalités, n'est PAS décompté du quota.
- `POST /v1/extract` - récupère/extrait `{url, title, content}` ; corps JSON strict, limite de 16 Kio.
- `POST /v1/auth/email/register` - inscription en un seul appel, renvoie une clé en texte brut à usage unique `as_sk_...`.
- Authentification : `Authorization: Bearer <as_sk_...>` facultatif ; le mode anonyme est soumis à des limites par adresse IP qui consomment le quota gratuit quotidien ; une clé invalide renvoie une erreur 401/403 SANS repli silencieux vers le mode anonyme.
- Offre gratuite : 1 000 requêtes/jour, 20 QPS par clé. Offre payante : tarif non communiqué (prochainement).
- Enveloppe de réponse : succès `{code: 0, message: "success", request_id, data}` ; échec `{code: -1, message}`. Les erreurs d'authentification/de quota ne comportent pas d'`error_code` structuré (le texte du message sert de signal) ; les erreurs propres à l'extraction comportent bien un `error_code` (`invalid_extract_url`, `extract_failed`). Aucun en-tête `Retry-After` en cas d'erreur 429.

## 3. Décisions (toutes prises le 2026-08-26)

1. **Politique de routage : `fallbackOnly`.** Justification : un fournisseur gratuit de coût 0 ne doit jamais dominer le routage automatique fondé sur les coûts ; la sélection explicite et le retour en cas de basculement restent inchangés. Précédent : entrée xquik fusionnée.
2. **Périmètre : webSearch + webFetch via `POST /v1/extract` dans la v1.** Aligné sur le modèle mental à double capacité de tavily/exa. Les surfaces verticales (`tag`, `sub-domains`, `batch_search`) restent hors périmètre — il n’existe actuellement aucune IR pour les paramètres verticaux.
3. **Affichage du quota : `freeMonthlyQuota: 0`** (affichage prudent de type xquik). L’allocation réelle (1 000 requêtes/jour, réinitialisation quotidienne) est indiquée à la place dans le texte `authHint` du catalogue de l’interface utilisateur. Justification : l’affichage du quota doit correspondre à la sémantique de réinitialisation ; convertir un plafond quotidien en équivalent mensuel (30 000) constitue une fausse promesse que l’interface utilisateur ne peut pas honorer.
4. **searchTypes : `["web"]` uniquement.** Il n’existe aucune preuve publique d’une verticale actualités/images dans l’API AnySearch ; les passerelles intégrant des API dépourvues de verticale documentée (par ex. Google Custom Search) exposent uniquement le web plutôt que d’associer silencieusement actualités -> web.
5. **Politique relative aux clés :** le fonctionnement sans clé est pris en charge ; une clé non valide renvoie 401/403 et n’entraîne jamais de rétrogradation silencieuse vers un accès anonyme (conformément au contrat du service en amont).
6. **Exclusions délibérées :** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (l’interception des conversations reste limitée à firecrawl/jina/tavily) ; `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (les points de terminaison distants anonymes partagent un même pool limité par IP pour chaque IP de sortie ; l’extraction sans clé est donc optionnelle et ne constitue pas une candidate au routage automatique) ; `QUOTA_STATUS_PROVIDERS` (AnySearch signale le quota via 429/une enveloppe, et non via un statut 402/403).
