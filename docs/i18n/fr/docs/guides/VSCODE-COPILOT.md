**OmniCopilot** ajoute tous les modèles servis par votre OmniRoute au sélecteur de modèles _natif_ de GitHub Copilot Chat.
Aucune seconde barre latérale, aucune interface de chat distincte — le mode agent de Copilot, les appels d’outils,
les serveurs MCP et les instructions personnalisées continuent tous de fonctionner, simplement avec le modèle que vous choisissez.

|                             |                                                                                                                                                 |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Installation (VS Code)**  | [Marketplace → `diegosouzapw.omnicopilot`](https://marketplace.visualstudio.com/items?itemName=diegosouzapw.omnicopilot)                        |
| **Installation (forks)**    | [Open VSX](https://open-vsx.org/extension/diegosouzapw/omnicopilot) — Cursor, Windsurf, VSCodium, Theia, code-server, Gitpod, Antigravity, Kiro |
| **Code source / problèmes** | [github.com/diegosouzapw/OmniCopilot](https://github.com/diegosouzapw/OmniCopilot) (MIT)                                                        |
| **Prérequis**               | VS Code 1.104+                                                                                                                                  |

> **Aucun abonnement Copilot requis.** Depuis VS Code 1.122, un fournisseur de modèles de langage fonctionne
> sans connexion à GitHub et sans aucun forfait Copilot. Les complétions en ligne et les
> fonctionnalités basées sur les embeddings restent en dehors de l’API du fournisseur et nécessitent toujours Copilot.

## Configuration

1. **Lancez OmniRoute** — `npm install -g omniroute && omniroute` (tableau de bord sur `http://localhost:20128`).
2. **Installez l’extension** — recherchez « OmniRoute » dans la vue Extensions.
3. **Choisissez un modèle** — Copilot Chat → sélecteur de modèles → **Gérer les modèles…** → **OmniRoute**, puis cochez
   ceux que vous souhaitez utiliser.

Aucune configuration n’est nécessaire lorsqu’OmniRoute s’exécute sur le port par défaut. Pour une instance distante, ouvrez
**l’icône OmniRoute dans la barre d’activité** (ou exécutez `OmniRoute: Manage Connection`) et définissez :

- **URL du serveur** — la racine du serveur, par exemple `http://192.168.0.15:20128`. Le suffixe `/v1` est
  ajouté par l’extension ; ne l’incluez pas.
- **Clé API** — uniquement lorsque le serveur définit `REQUIRE_API_KEY`. Elle est stockée dans le trousseau du système d’exploitation via
  SecretStorage de VS Code, jamais dans `settings.json`.

## Ce que le sélecteur affichera

L’extension n’affiche pas la charge utile brute de `GET /v1/models` — elle la met en forme, et le nombre que vous
voyez est inférieur à la taille du catalogue pour deux raisons intentionnelles.

### Elle demande un identifiant par modèle

`MODELS_CATALOG_PREFIX_MODE` utilise **`dual`** par défaut, ce qui publie chaque modèle deux fois — une fois
sous le préfixe court de l’alias et une fois sous le préfixe canonique du fournisseur — afin que les anciennes configurations
des clients puissent continuer à résoudre les deux formes :

```
cc/claude-sonnet-4-6        ← préfixe d’alias
claude/claude-sonnet-4-6    ← préfixe canonique, même modèle
```

L’extension demande **`GET /v1/models?prefix=alias`** afin de recevoir un identifiant par modèle, sans
modifier le paramètre global du serveur pour vos autres clients. Sur une instance de référence, cela a réduit
**2345 entrées à 1396 — 949 doublons, aucun modèle perdu.**

Si vous préférez corriger ce comportement à l’échelle du serveur pour _tous_ les clients, définissez l’indicateur de fonctionnalité
`MODELS_CATALOG_PREFIX_MODE` sur `alias` dans le tableau de bord. Consultez
[API_REFERENCE → préfixe](../reference/API_REFERENCE.md#model-id-prefixes-prefix) pour le
paramètre de requête et le tableau correspondant à chaque mode.

### Elle masque les modèles qui ne peuvent pas converser

Le catalogue répertorie également des modèles d’image, de vidéo, d’audio, de reclassement, d’embedding et de modération. Ceux-ci sont
de toute façon rejetés lors d’une requête de chat :

```
HTTP 400 — Le modèle '<id>' est un modèle de génération d’images et ne peut pas être utilisé sur
/v1/chat/completions. Utilisez plutôt POST /v1/images/generations.
```

ils sont donc filtrés selon leur champ `type` avant d’atteindre le sélecteur. **Les modèles de l’API Responses
sont conservés** — chaque entrée Codex / GPT-5.x publie `supported_endpoints: ["responses"]`,
et OmniRoute les traduit pour `/v1/chat/completions`, ils sont donc parfaitement utilisables.

### Fournisseurs que vous n’avez jamais configurés

Le catalogue répertorie les modèles des fournisseurs disposant d’une **connexion active**, ainsi que ceux de tous les fournisseurs **noAuth**
— ceux qui ne nécessitent aucune clé et qui constituent une grande partie de l’offre gratuite. C’est intentionnel. Pour les masquer,
ajoutez-les à `blockedProviders` dans les paramètres du tableau de bord ; rien ne change dans
l’extension.

## Tableau de bord dans un onglet VS Code

`omnicopilot.dashboardOpen: "editor"` affiche le tableau de bord OmniRoute dans un onglet de l’éditeur via le
Simple Browser plutôt que dans un navigateur externe. L’intégration est **activée explicitement côté serveur** via
`DASHBOARD_ALLOW_EMBED=vscode`, ce qui sert les pages HTML avec
`frame-ancestors 'self' vscode-webview:` au lieu de la valeur par défaut `frame-ancestors 'none'` +
`X-Frame-Options: DENY`. La surface de l’API (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) conserve les
en-têtes stricts dans tous les cas.

> ⚠️ **Il s’agit d’un indicateur de compilation, et non d’exécution.** Next.js compile `headers()` dans le manifeste
> des routes ; `next.config.mjs` lit donc la variable lors de la compilation du bundle
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> L’exporter avant le lancement d’un serveur déjà compilé ne change rien : les en-têtes sont intégrés au bundle.

```bash
# la variable doit être présente lors de la commande de COMPILATION
DASHBOARD_ALLOW_EMBED=vscode npm run build        # ou npm run build:release
npm start
```

| Méthode d’installation     | Pouvez-vous activer l’intégration ?                                                                                                             |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Depuis les sources         | ✅ définissez la variable dans la commande de compilation, comme ci-dessus                                                                      |
| `npm install -g omniroute` | ❌ le paquet publié contient un bundle précompilé — compilez plutôt depuis les sources                                                          |
| Image Docker               | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — l’image précompilée sur Docker Hub n’active pas l’intégration |

Sans une compilation autorisant l’intégration, la page refuse d’être affichée dans un cadre ; l’extension le détecte à partir des
en-têtes de réponse et revient au navigateur externe — rien ne se casse, et elle le signale une fois.
Consultez [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) et l’issue
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273).

## Configuration de vos autres outils depuis VS Code

**`OmniRoute: Configure Coding CLI`** utilise la CLI `omniroute` pour générer des profils prêts à l’emploi
pour Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code,
Kilo et Roo — les mêmes configurations que celles décrites dans
[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md). La clé d’API est transmise à la CLI au moyen de la
variable d’environnement `OMNIROUTE_API_KEY`, jamais sur la ligne de commande.

## Dépannage

| Symptôme                                                                 | Cause / solution                                                                                                                                                                                                                                                                                    |
| ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Aucun modèle OmniRoute dans le sélecteur                                 | Le serveur est inaccessible. Le point de la barre d’état devient gris ; exécutez `OmniRoute: Check Connection`. La découverte est silencieuse par conception et n’ajoute aucun modèle plutôt que d’afficher une invite.                                                                             |
| Chaque modèle apparaît deux fois                                         | Vous utilisez une version d’OmniCopilot antérieure à 1.0.1 — effectuez une mise à jour. L’extension demande désormais `?prefix=alias`.                                                                                                                                                              |
| Un modèle d’image/audio auparavant répertorié a disparu                  | Ce comportement est intentionnel depuis la version 1.0.1 — il ne pouvait de toute façon jamais répondre à une requête de chat.                                                                                                                                                                      |
| Le panneau est absent de la barre d’activité                             | VS Code déplace les conteneurs de vues supplémentaires dans le menu de débordement **"…"** en bas de la barre d’activité, et un conteneur masqué par un clic droit le reste. Faites un clic droit sur la barre d’activité → cochez **OmniRoute**, ou ouvrez-le avec `OmniRoute: Manage Connection`. |
| Le tableau de bord s’ouvre dans le navigateur malgré le mode `editor`    | Le serveur n’a pas été **compilé** avec `DASHBOARD_ALLOW_EMBED=vscode` (voir ci-dessus) — définir cette variable au démarrage d’une installation précompilée ne change rien. Le repli est intentionnel.                                                                                             |
| La liste des modèles est obsolète après la modification des fournisseurs | `OmniRoute: Refresh Models`, ou le lien ↻ dans le panneau.                                                                                                                                                                                                                                          |
