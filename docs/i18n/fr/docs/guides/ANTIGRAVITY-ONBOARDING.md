## 1. Antigravity et Antigravity CLI (agy)

Les deux fournisseurs partagent le **même backend Google** — client OAuth, actualisation des jetons, points de terminaison et comptes Google identiques. La différence réside dans les modèles auxquels vous avez accès.

> Consultez [l’annonce d’Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli) pour connaître la comparaison officielle de Google.

| Aspect                      | `antigravity` (IDE)                                    | `agy` (CLI)                                                        |
| --------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------ |
| **Produit Google**          | Antigravity 2.0 / Antigravity IDE                      | Antigravity CLI                                                    |
| **Backend**                 | Même API Google Cloud Code                             | Même API Google Cloud Code                                         |
| **OAuth / Jeton**           | Même client, même actualisation                        | Même client, même actualisation                                    |
| **Catalogue de modèles**    | Liste statique organisée (codée en dur dans OmniRoute) | Détecté en temps réel auprès de Google via `:fetchAvailableModels` |
| **Modèles Claude**          | Sonnet 4.6, Opus 4.6 (4 variantes chacun)              | Sonnet 4.6, Opus 4.6 (4 variantes chacun)                          |
| **Nommage Gemini**          | Libellés explicites (Faible/Moyen/Élevé)               | Identifiants en amont (extra-low/low/agent)                        |
| **Modèles supplémentaires** | `gpt-oss-120b-medium`                                  | Peut inclure des modèles supplémentaires de Google                 |
| **Cas d’usage par défaut**  | Intégration IDE (VS Code, JetBrains)                   | Accès CLI / API                                                    |
| **Quota**                   | Partagé avec agy (même compte Google)                  | Partagé avec antigravity (même compte Google)                      |

**Modèles disponibles (vérifiés expérimentalement, 2026-07-29)** :

- Gemini : 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (différents niveaux de raisonnement)
- Claude : Sonnet 4.6, Opus 4.6 (chacun avec les variantes par défaut/faible/moyen/élevé)
- Autre : GPT-OSS 120B Medium
- **Claude Sonnet 5 n’est PAS disponible** — seules les variantes 4.6 sont prises en charge

**Pourquoi le catalogue de modèles diffère** : la CLI de Google est « optimisée pour la vitesse et une faible surcharge » et « co-optimisée avec les modèles Gemini » (selon le blog officiel de Google). Le produit Web/IDE est « optimisé pour l’exhaustivité ». La CLI utilise `:fetchAvailableModels` pour découvrir dynamiquement les modèles, tandis que l’IDE utilise une liste statique organisée.

**En pratique** : utilisez le préfixe `agy/` pour les modèles Gemini (par exemple `agy/gemini-3.7-flash-high`). Utilisez `antigravity/` pour la liste statique organisée. Les deux utilisent le même backend Google, mais présentent des conventions de nommage différentes pour les modèles. Le quota est partagé — l’utilisation de l’un ou l’autre fournisseur est décomptée des limites du même compte Google.

## 2. Google One AI Pro : système de quotas

> Consultez [Documentation Antigravity : forfaits](https://antigravity.google/docs/plans) pour obtenir les détails officiels sur les quotas et [Modifications apportées aux forfaits Antigravity](https://antigravity.google/blog/changes-to-antigravity-plans) pour connaître les dernières mises à jour tarifaires.

Google Antigravity utilise un **quota à deux niveaux** basé sur le « travail effectué » (poids computationnel), et non sur le nombre de messages.

### Les deux niveaux

| Niveau                               | Description                               | Cycle de renouvellement                                                                                            |
| ------------------------------------ | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **Cycle de 5 heures**                | Réserve immédiate de « travail effectué » | Se réinitialise 5 heures après la première requête d’une session                                                   |
| **Plafond de référence sur 7 jours** | Plafond hebdomadaire strict               | Prévaut sur le renouvellement de 5 heures s’il est atteint ; bloque l’accès jusqu’à la période suivante de 7 jours |

**Calcul du « travail effectué »** : les tâches faisant un usage intensif des agents (par exemple, « Refactoriser l’intégralité de ce dépôt ») épuisent le quota beaucoup plus rapidement que les tâches simples (par exemple, « Corriger cette fonction »). Aucun tableau de bord en temps réel n’affiche la consommation.

### Niveaux de forfait

| Forfait      | Prix       | Quota                                            | Limite hebdomadaire                                 |
| ------------ | ---------- | ------------------------------------------------ | --------------------------------------------------- |
| Gratuit      | $0         | Quota conséquent, renouvelé chaque semaine       | Oui                                                 |
| AI Pro       | $19.99/mo  | Quota élevé, renouvellement glissant de 5 heures | Oui (prévaut sur les 5 heures si elle est atteinte) |
| AI Ultra 5x  | $99.99/mo  | 5x le quota Pro                                  | Aucune limite hebdomadaire                          |
| AI Ultra 20x | $199.99/mo | 20x le quota Pro                                 | Aucune limite hebdomadaire                          |

### Modèles Gemini et non-Gemini

- **Modèles Gemini** (Flash + Pro) : partagent une même limite de débit, consommée selon la tarification de l’API. Si Flash est 8x moins cher que Pro, vous obtenez 8x plus de jetons Flash.
- **Modèles non-Gemini** (Claude, GPT-OSS) : disposent de limites de débit **distinctes**. Ils peuvent rester disponibles même lorsque Gemini est bloqué.

### Crédits IA (dépassement)

> Consultez [Crédits IA Google One](https://support.google.com/googleone/answer/14534406) pour comprendre le fonctionnement des crédits.

Lorsque le quota de référence est épuisé :

- **Jamais** : attend le renouvellement du quota ; affiche « Quota de référence du modèle atteint »
- **Toujours** : utilise automatiquement les crédits IA ; revient au quota de référence lorsqu’il est renouvelé

Les crédits sont achetés séparément et déduits selon la tarification standard de l’API.

### Informations importantes

- Le quota est **partagé au niveau du compte** — un même compte Google utilisé dans l’IDE Antigravity, la CLI et OmniRoute partage une seule réserve de quota
- Chaque compte Google dispose de son propre quota indépendant — plusieurs comptes = plusieurs réserves de quota
- Des utilisateurs d’AI Pro ont signalé des **blocages de 7 jours** au lieu de réinitialisations après 5 heures lorsque le plafond hebdomadaire de référence est atteint (Google a confirmé que ce comportement est intentionnel afin de gérer une forte demande)

**Lorsque le quota de votre compte est épuisé** : OmniRoute réessaie automatiquement avec le prochain compte disponible dans la route combinée. Aucune intervention manuelle n’est nécessaire.

## 3. Comment obtenir un projectId

Chaque connexion antigravity/agy nécessite un `projectId` Google Cloud Code. Sans celui-ci, le point de terminaison `/v1internal:models` renvoie une erreur 404.

### Méthode A : automatique (recommandée)

OmniRoute s’en charge automatiquement. Lorsque vous ajoutez un nouveau compte Google via l’authentification OAuth du tableau de bord :

1. OmniRoute actualise le jeton
2. Appelle `loadCodeAssist` pour découvrir le projectId
3. Si aucun projet n’existe, appelle `onboardUser` pour en créer un
4. Réessaie `loadCodeAssist` pour obtenir le projectId nouvellement créé
5. L’enregistre dans la base de données

**Cela fonctionne pour la plupart des comptes** — aucune étape manuelle n’est nécessaire.

### Méthode B : manuelle via la CLI agy

Si la découverte automatique échoue (consultez la section 5 pour savoir dans quels cas cela se produit) :

```bash
# Installer la CLI agy (si ce n’est pas déjà fait)
npm install -g @anthropic-ai/agy

# Se connecter avec votre compte Google
agy login

# Sélectionner le compte qui doit être intégré
# Cela déclenche l’inscription à Cloud Code et attribue un projectId
```

Une fois la commande `agy login` exécutée avec succès, actualisez le jeton dans le tableau de bord OmniRoute. Le projectId sera découvert automatiquement.

### Comment vérifier

Consultez la base de données :

```bash
# Dans le conteneur OmniRoute
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Ou consultez les journaux :

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. URI de redirection OAuth

### Le problème

Google OAuth exige un URI de redirection valide. OmniRoute utilise par défaut `http://127.0.0.1:20128/callback` (adresse de bouclage). Cela fonctionne pour les déploiements locaux, mais **échoue pour les déploiements distants** (par exemple, un serveur accessible via une adresse IP du réseau local).

Google refuse les URI de redirection qui :

- Utilisent des adresses IP (un domaine se terminant par `.com`, `.org`, etc. est requis)
- Ne correspondent pas aux URI de redirection enregistrés dans la configuration du client OAuth

### La solution

**Option A : utiliser le flux OAuth intégré (par défaut)**

- Fonctionne lorsque vous accédez à OmniRoute depuis `localhost` ou `127.0.0.1`
- Aucune configuration requise

**Option B : utiliser des identifiants OAuth personnalisés**

- Définissez `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` dans votre environnement
- Fournissez vos propres identifiants Google OAuth :
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Enregistrez `https://your-domain.com/callback` comme URI de redirection autorisé dans Google Cloud Console

**Option C : utiliser l’interface en ligne de commande agy pour la connexion initiale**

- Exécutez `agy login` sur la machine qui accédera à OmniRoute
- Le flux OAuth s’effectue localement et les jetons sont stockés
- Importez la connexion dans OmniRoute via le tableau de bord

### Limitations

- Les identifiants OAuth personnalisés nécessitent un nom de domaine (Google n’accepte pas les adresses IP comme URI de redirection)
- Si vous ne disposez pas d’un domaine, utilisez plutôt l’option A ou C

## 5. Résolution des problèmes : lorsque la configuration automatique échoue

OmniRoute gère automatiquement la détection de projectId et l’intégration pour la plupart des comptes. En cas d’échec, la cause première est généralement l’une des suivantes :

### La région du compte est bloquée

**Symptôme** : `agy login` renvoie « Échec de la vérification de l’éligibilité : votre compte actuel n’est pas éligible à Antigravity, car ce service n’est pas encore disponible dans votre région. »

**Cause première** : les comptes Google possèdent un champ interne « Association de pays » défini lors de l’inscription. L’interface en ligne de commande agy et l’API Cloud Code vérifient strictement ce champ, contrairement à Gemini sur le Web, qui vérifie uniquement votre adresse IP actuelle.

> Pour vérifier ou modifier la région associée à votre compte, consultez le [formulaire d’association de pays de Google](https://policies.google.com/country-association-form).

**Pourquoi Gemini sur le Web fonctionne, mais pas agy** :

- Gemini sur le Web / Google One : vérifie uniquement l’adresse IP actuelle (le proxy fonctionne)
- Interface en ligne de commande agy / API Cloud Code : lit le champ interne « Association de pays » (le proxy ne change rien)

**Solution** :

1. Accédez au [formulaire d’association de pays de Google](https://policies.google.com/country-association-form) avec une adresse IP située aux États-Unis
2. Envoyez une demande de changement de région (sélectionnez « Je vis dans un autre pays »)
3. Attendez entre 1 et 24 heures que Google traite la demande et vous envoie une notification par e-mail
4. Ensuite, `agy login` devrait fonctionner

### Le compte ne possède aucun projet Cloud Code

**Symptôme** : les journaux affichent `loadCodeAssist returned no project id` et `onboardUser failed (400)`.

**Cause première** : le compte n’a jamais été enregistré auprès de Google Cloud Code et l’intégration automatique a échoué.

**Solution** : exécutez manuellement `agy login` pour déclencher l’enregistrement auprès de Cloud Code, puis actualisez le jeton dans le tableau de bord OmniRoute.

### Le jeton a expiré ou a été révoqué

**Symptôme** : erreurs 401 dans les journaux ou messages « Le jeton a expiré ».

**Solution** : actualisez le jeton dans Tableau de bord → Fournisseurs → agy → Cliquez sur l’icône d’actualisation. Si le jeton d’actualisation lui-même a été révoqué, vous devrez vous authentifier à nouveau via OAuth.

## Organigramme décisionnel

```
Le compte ne fonctionne pas ?
│
├─ Possède-t-il un projectId dans la base de données ?
│  ├─ OUI → Le problème se situe ailleurs (jeton expiré, limite de débit, etc.)
│  └─ NON ↓
│
├─ L'association de pays du compte est-elle définie sur une région restreinte ?
│  ├─ OUI → Modifiez la région dans le formulaire d'association de pays de Google
│  │         (https://policies.google.com/country-association-form)
│  │         Attendez 1 à 24 heures, puis réessayez
│  └─ NON ↓
│
├─ Le compte dispose-t-il d'un abonnement Google One AI Pro ?
│  ├─ NON → Abonnez-vous d'abord sur one.google.com
│  └─ OUI ↓
│
├─ Essayez la détection automatique (actualisez le jeton dans le tableau de bord)
│  ├─ Fonctionne → Terminé
│  └─ Échec persistant ↓
│
└─ Méthode manuelle : exécutez `agy login` sur la machine
   ├─ Fonctionne → Actualisez le jeton dans le tableau de bord, projectId est détecté
   └─ Échec → Consultez le message d'erreur ; il s'agit probablement d'un problème de région ou d'abonnement
```
