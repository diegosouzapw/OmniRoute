`@omniroute/opencode-plugin-v2` ajoute l’intégralité de votre catalogue OmniRoute — modèles, combos et
auto-combos — au sélecteur de modèles d’OpenCode v2, avec les noms d’affichage, les tarifs et les
budgets du niveau gratuit.

Il s’agit d’un package distinct de `@omniroute/opencode-plugin`, car OpenCode v1 et v2 chargent
les plugins selon des contrats différents. Choisissez celui qui correspond à la version majeure de votre OpenCode ;
ils ne partagent rien, donc la mise à niveau de l’un n’impose jamais celle de l’autre.

## Prérequis

- OpenCode v2.
- Une passerelle OmniRoute accessible (`http://localhost:20128` par défaut).
- Node.js 22 ou 24.

## Installation

Ajoutez le plugin à `opencode.json` :

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

Les modèles apparaissent alors sous la forme `omniroute/<provider>/<model>` ; `providerId` détermine ce préfixe ainsi que
l’identifiant de l’intégration sous lequel OpenCode stocke l’identifiant d’accès.

## Identifiants d’accès

Le plugin recherche une clé de passerelle à trois emplacements, dans cet ordre :

1. **L’identifiant d’accès que vous avez connecté dans OpenCode.** Le plugin enregistre une intégration, ce qui permet
   au flux d’authentification propre à OpenCode de stocker la clé. Rien n’est enregistré dans `opencode.json` — privilégiez cette méthode.
2. `apiKey` dans les options du plugin, pour une substitution propre au projet. Cette méthode place la clé dans un fichier que vous
   êtes susceptible de versionner.
3. `OMNIROUTE_API_KEY` dans l’environnement.

En l’absence de ces trois éléments, le catalogue est vide et le plugin le signale une fois au démarrage, au lieu de
vous laisser avec un sélecteur vide sans explication.

### Le jeton de gestion est une clé différente

Les combos, l’état des fournisseurs et l’enrichissement (noms d’affichage, tarifs, budgets du niveau gratuit) proviennent
des endpoints `/api/*` de la passerelle, que la plupart des déploiements protègent avec un jeton de **gestion**
plutôt qu’avec la clé d’inférence :

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<jeton de lecture de gestion>"
}
```

S’il n’est pas défini, `managementReadToken` utilise `apiKey` comme valeur de repli. Lorsqu’une passerelle refuse cette solution de repli,
le catalogue est tout de même publié, mais avec les identifiants bruts des modèles au lieu des noms d’affichage, sans
déduplication des alias canoniques, sans tarifs et sans combos. Le plugin émet un avertissement unique pour chaque endpoint concerné,
en indiquant son nom et les informations perdues — ainsi, un sélecteur dégradé n’est jamais inexplicable.

## Options

| Clé                              | Valeur par défaut                              | Remarques                                                                                                                      |
| -------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `providerId`                     | `"omniroute"`                                  | Identifiant du fournisseur, identifiant de l’intégration et préfixe sous lequel les modèles apparaissent                       |
| `baseURL`                        | obligatoire                                    | Racine de la passerelle, `http(s)` uniquement ; le suffixe `/v1` est ajouté si nécessaire                                      |
| `apiKey`                         | identifiant connecté, puis `OMNIROUTE_API_KEY` | Clé de chat pour `/v1/*`                                                                                                       |
| `managementReadToken`            | utilise `apiKey` comme valeur de repli         | Clé pour `/api/*` — généralement **différente**                                                                                |
| `displayName`                    | `"OmniRoute"`                                  | Nom du fournisseur dans le sélecteur                                                                                           |
| `timeoutMs`                      | `10000`                                        | Délai d’expiration de récupération par endpoint (les auto-combos utilisent 5 s)                                                |
| `modelCacheTtlMs`                | `300000`                                       | Durée de vie du cache du catalogue ; un instantané sur disque accélère les démarrages à froid                                  |
| `timeouts`                       | utilise `timeoutMs` comme valeur de repli      | Délais en ms par endpoint : `models`, `combos`, `autoCombos`, `enrichment`                                                     |
| `enrichment`                     | `true`                                         | Récupère les noms, les tarifs et les budgets du niveau gratuit                                                                 |
| `providerTag`                    | `true`                                         | Préfixe un nom d’affichage avec le fournisseur en amont vers lequel il est acheminé                                            |
| `usableOnly`                     | `false`                                        | Conserve uniquement les fournisseurs que la passerelle signale comme configurés                                                |
| `visibleModels` / `hiddenModels` | `[]`                                           | Listes d’autorisation par correspondance exacte ou par suffixe ; l’exclusion est prioritaire                                   |
| `geminiSanitization`             | `true`                                         | Supprime des schémas d’outils les mots-clés JSON Schema rejetés par Gemini (les outils `$ref` sont transmis sans modification) |
| `apiFormat.allowAnthropic`       | `false`                                        | Achemine les identifiants autorisés via le bloc d’API Anthropic                                                                |
| `apiFormat.anthropicModels`      | `[]`                                           | Identifiants complets des modèles acheminés vers Anthropic                                                                     |
| `logLevel` / `startupDebug`      | `warn` / `false`                               | Niveau de verbosité du journal                                                                                                 |

## Comment le catalogue reste à jour

Le catalogue est récupéré de manière différée et mis en cache pendant `modelCacheTtlMs`, tandis qu’un instantané sur disque permet de conserver le dernier catalogue connu lorsque la passerelle est inaccessible — une panne ne vous coûte donc que de la fraîcheur. Les modèles et les combinaisons sont publiés dès leur arrivée ; les combinaisons automatiques, la liste des fournisseurs et la couche d’enrichissement sont intégrées lorsqu’elles arrivent, afin qu’un point de terminaison lent ne puisse pas bloquer l’ensemble du sélecteur.

Les noms reflètent ce que la passerelle connaît : le fournisseur en amont vers lequel un modèle est acheminé, un marqueur `[Free]` et le budget qui l’accompagne — ainsi, deux connexions proposant le même modèle restent différenciables. Désactivez le préfixe avec `"providerTag": false`.

Il n’existe aucune commande d’actualisation manuelle : les commandes OpenCode v2 sont des modèles de prompt, et non des rappels, de sorte qu’un plugin ne peut pas en exposer une. Les actualisations suivent le TTL ; l’hôte n’est invité à recharger que lorsque le catalogue ou la couche d’enrichissement a réellement changé, jamais à chaque actualisation.

## Appel d’outils avec Gemini

Gemini rejette toute requête dont les déclarations d’outils contiennent `$schema` ou `additionalProperties`, en répondant `400 INVALID_ARGUMENT`. Le plugin retire ces mots-clés des schémas d’outils destinés à un modèle Gemini de ce fournisseur et laisse toutes les autres requêtes intactes. Un outil contenant un `$ref` est transmis tel quel au lieu d’être nettoyé, car la suppression de la référence élargirait le schéma pour qu’il « accepte n’importe quoi ».
Définissez `"geminiSanitization": false` pour désactiver ce comportement.

## Dépannage

| Symptôme                                                       | Cause                                                                                                                        |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Le sélecteur n’affiche aucun modèle OmniRoute                  | Aucune clé n’a été trouvée (vérifiez l’avertissement au démarrage), ou la passerelle est inaccessible                        |
| Identifiants de modèles bruts, aucune combinaison, aucun tarif | Les points de terminaison de gestion ont refusé le jeton — définissez `managementReadToken`                                  |
| Une session épinglée à `opencode-<id>/…`                       | Le plugin v1 publiait `opencode-<id>` ; la v2 publie directement `<id>`, sélectionnez donc à nouveau le modèle sous `<id>/…` |
