ಪಥ, `cp -al` node_modules, ತೆರವುಗೊಳಿಸುವ ನಿಯಮಗಳು) `AGENTS.md` → Git ಕಾರ್ಯಪ್ರವಾಹ → "Worktree
ಪ್ರತ್ಯೇಕತೆ" ನಲ್ಲಿ ಇದೆ. Claude-Code-ನಿರ್ದಿಷ್ಟ ಅಂಶಗಳು:

- ನಿರ್ವಾಹಕರು ಈಗಾಗಲೇ ತಿಳಿಸಿರದಿದ್ದರೆ, `AskUserQuestion` ಮೂಲಕ ಮೂಲ ಶಾಖೆಯನ್ನು ದೃಢೀಕರಿಸಿ (ಕಠಿಣ ನಿಯಮ #19).

  (ಅಧಿಕೃತ ಪಥ) ಅಡಿಯಲ್ಲಿ worktreeಗಳನ್ನು ರಚಿಸುತ್ತದೆ. ದಾಖಲಿಸಲಾದ `git
worktree add` ಕಮಾಂಡ್ನೊಂದಿಗೆ worktree ರಚಿಸಿ, ನಂತರ ಅದರ `path` ಬಳಸಿ `EnterWorktree` ಅನ್ನು ಕರೆ ಮಾಡಿ.

## ಸೆಷನ್ಗಳ ನಡುವಿನ ಸುರಕ್ಷತೆ — Claude Code ವಿಶೇಷತೆಗಳು

ಕಠಿಣ ನಿಯಮಗಳು #19/#21/#22 (`AGENTS.md` ನಲ್ಲಿ) ಸಮಾಂತರ ಸೆಷನ್ಗಳನ್ನು ನಿಯಂತ್ರಿಸುತ್ತವೆ. ಈ
ಹಾರ್ನೆಸ್ಗಾಗಿ ಕಾರ್ಯಾಚರಣಾತ್ಮಕ ಜ್ಞಾಪನೆಗಳು:

- **git ಅನ್ನು ಬಳಸುವ ಪ್ರತಿಯೊಂದು ಉಪಏಜೆಂಟ್ನ ಪ್ರಾಂಪ್ಟ್ನಲ್ಲಿ `git stash` ನಿಷೇಧವನ್ನು ಯಥಾವತ್ತಾಗಿ ಪುನರಾವರ್ತಿಸಿ**
  (Agent ಪರಿಕರ / Workflow ಸ್ಕ್ರಿಪ್ಟ್ಗಳು) — ಉಪಏಜೆಂಟ್ಗಳು ಈ ಫೈಲ್ ಅನ್ನು ಆನುವಂಶಿಕವಾಗಿ ಪಡೆಯುವುದಿಲ್ಲ, ಮತ್ತು ದಾಖಲಾದ
  stash ಘಟನೆಯ ಮರುಕಳಿಕೆಯು ಉಪಏಜೆಂಟ್ ಮೂಲಕವೇ ಸಂಭವಿಸಿತು.
- _ಈ ಸೆಷನ್ನಲ್ಲಿ_ ನೀವು ರಚಿಸದ ಯಾವುದೇ PR ಅನ್ನು ವಿಲೀನಗೊಳಿಸುವ ಅಥವಾ push ಮಾಡುವ ಮೊದಲು, `git worktree list`
  ಅನ್ನು ಚಲಾಯಿಸಿ ಮತ್ತು `gh pr view <N> --json state,headRefOid` ಅನ್ನು ಮರುಪರಿಶೀಲಿಸಿ (ಕಠಿಣ ನಿಯಮ #22b).
- ಪ್ರತಿ ಸೆಷನ್ ಅನ್ನು ಮುಖ್ಯ checkout ಅದು ಆರಂಭಗೊಂಡ ಶಾಖೆಯಲ್ಲಿಯೇ ಇರುವಂತೆ ಮುಗಿಸಿ.

## Superpowers / ಯೋಜನಾ ಆರ್ಟಿಫ್ಯಾಕ್ಟ್ಗಳು — ಪಥದ ಅತಿಕ್ರಮಣಗಳು

`_tasks/` ಸಂಪ್ರದಾಯವನ್ನು `AGENTS.md` → "ಯೋಜನೆ ಮತ್ತು ಸಂಶೋಧನಾ ಆರ್ಟಿಫ್ಯಾಕ್ಟ್ಗಳು" ನಲ್ಲಿ ವ್ಯಾಖ್ಯಾನಿಸಲಾಗಿದೆ.
superpowers ಕೌಶಲ್ಯಗಳೊಂದಿಗೆ ಬರುವ ಡೀಫಾಲ್ಟ್ಗಳು `docs/…` ಕಡೆಗೆ ಸೂಚಿಸುತ್ತವೆ — ಆ ಡೀಫಾಲ್ಟ್ಗಳನ್ನು **ಇಲ್ಲಿ
ಅತಿಕ್ರಮಿಸಲಾಗಿದೆ**. superpowers ಕೌಶಲ್ಯವು "saved to `docs/superpowers/plans/…`" ಎಂಬಂತಹ ಪಥವನ್ನು ಪ್ರಕಟಿಸಿದಾಗ,
ಬರೆಯುವ ಮೊದಲು ಅದನ್ನು ಸಮಾನವಾದ `_tasks/…` ಪಥಕ್ಕೆ ಮರುಬರೆಯಿರಿ:

| ಆರ್ಟಿಫ್ಯಾಕ್ಟ್ (ಕೌಶಲ್ಯ)                     | ಡೀಫಾಲ್ಟ್ (ಬಳಸಬೇಡಿ)        | ಬದಲಾಗಿ ಇಲ್ಲಿ ಉಳಿಸಿ                                            |
| ------------------------------------------ | ------------------------- | ------------------------------------------------------------- |
| ಯೋಜನೆಗಳು (`writing-plans`)                 | `docs/superpowers/plans/` | `_tasks/superpowers/plans/YYYY-MM-DD-<feature>.md`            |
| ನಿರ್ದಿಷ್ಟತೆಗಳು / ವಿನ್ಯಾಸ (`brainstorming`) | `docs/superpowers/specs/` | `_tasks/superpowers/specs/YYYY-MM-DD-<topic>-design.md`       |
| ಸಂಶೋಧನೆ (`deep-research`, ತಾತ್ಕಾಲಿಕ)       | `docs/research/`          | `_tasks/research/…`                                           |
| ಹಸ್ತಾಂತರಗಳು (`/handoff`)                   | —                         | `_tasks/hands-off/<YYYY-MM-DD>_<branch>_v<versão>_sess-<id>/` |

ಆ ಆರ್ಟಿಫ್ಯಾಕ್ಟ್ಗಳನ್ನು `_tasks/` repo ಒಳಗೆ commit ಮಾಡಿ (`git -C _tasks …`), ಮುಖ್ಯ repoದಲ್ಲಿ ಎಂದಿಗೂ ಮಾಡಬೇಡಿ.

## Scratch / ತಾತ್ಕಾಲಿಕ ಫೈಲ್ಗಳು — `/tmp` ಅಲ್ಲ, `_artifacts/` ಬಳಸಿ

ಈ ಪ್ರಾಜೆಕ್ಟ್ ಹಾರ್ನೆಸ್ನ ಡೀಫಾಲ್ಟ್ ಸೆಷನ್ scratchpad (`/tmp/claude-*/…`) ಅನ್ನು ಅತಿಕ್ರಮಿಸುತ್ತದೆ. ತಾತ್ಕಾಲಿಕ/ಕಾರ್ಯನಿರತ
ಫೈಲ್ಗಳನ್ನು — exports, ರಚಿಸಲಾದ zips, ಒಮ್ಮೆ ಮಾತ್ರ ಬಳಸುವ ಮಧ್ಯಂತರ outputs, ಸಾಮಾನ್ಯವಾಗಿ ನೀವು
`/tmp` ನಲ್ಲಿ ಇರಿಸುವ ಯಾವುದೇ ವಸ್ತುವನ್ನು — ಬದಲಾಗಿ `/home/diegosouzapw/dev/proxys/OmniRoute/_artifacts/` ಗೆ ಬರೆಯಿರಿ.

- `_artifacts/` ಒಂದು ಮೂಲ `_*` ಪಥವಾಗಿದೆ: ಈಗಾಗಲೇ gitignore ಮಾಡಲಾಗಿದೆ (`AGENTS.md` → "ಮೂಲ `_*` ಪಥಗಳು"), ಕೇವಲ
  ಡಿಸ್ಕ್ನಲ್ಲಿ ಇರುತ್ತದೆ, ಎಂದಿಗೂ track ಮಾಡಲಾಗುವುದಿಲ್ಲ.
- ಕಾರಣ: scratch output ಅನ್ನು ಪ್ರಾಜೆಕ್ಟ್ ಒಳಗೇ (`/tmp` ಬದಲು) ಇರಿಸುವುದರಿಂದ, ಅಸ್ತಿತ್ವ ಕಳೆದುಕೊಳ್ಳುವ ಅಥವಾ track ಮಾಡದೆಯೇ
  ಸಂಗ್ರಹಗೊಳ್ಳುವ ತಾತ್ಕಾಲಿಕ ಸೆಷನ್-ನಿರ್ದಿಷ್ಟ `/tmp` ಡೈರೆಕ್ಟರಿಗಳಾದ್ಯಂತ ಹುಡುಕಾಡುವ ಬದಲು, ನಿರ್ವಾಹಕರು
  ಎಲ್ಲಾ ತಾತ್ಕಾಲಿಕ ವಸ್ತುಗಳನ್ನು ಒಂದೇ ಸ್ಥಳದಲ್ಲಿ ಸುಲಭವಾಗಿ ಹುಡುಕಿ ಅಳಿಸಬಹುದು.
- ಇದನ್ನು `_tasks/` ನೊಂದಿಗೆ **ಗೊಂದಲಪಡಿಸಬೇಡಿ** (ಕಠಿಣ ನಿಯಮ #23, ಶಾಶ್ವತ
  ಯೋಜನೆಗಳು/ನಿರ್ದಿಷ್ಟತೆಗಳು/ಸಂಶೋಧನೆ/ಹಸ್ತಾಂತರಗಳಿಗಾಗಿ ಅದರದೇ ಖಾಸಗಿ git repo) — `_artifacts/` ಕೇವಲ ಬಿಸಾಡಬಹುದಾದ ಕಾರ್ಯನಿರತ ಫೈಲ್ಗಳಿಗಾಗಿ;
  ಇಲ್ಲಿರುವ ಯಾವುದೂ ಉಳಿಯಬೇಕಾಗಿಲ್ಲ ಅಥವಾ ಆವೃತ್ತೀಕರಣಗೊಳ್ಳಬೇಕಾಗಿಲ್ಲ.

## PRಗಳನ್ನು ತೆರೆಯುವ ಮೊದಲು Base-green

ಶಾಖೆಯನ್ನು ರಚಿಸುವ ಅಥವಾ PR ತೆರೆಯುವ ಮೊದಲು, base-green ಪರಿಶೀಲನೆಯನ್ನು ಚಲಾಯಿಸಿ (`AGENTS.md` → Git ಕಾರ್ಯಪ್ರವಾಹ →
"Base-green ಪರಿಶೀಲನೆ"; ಪ್ರಾಜೆಕ್ಟ್ ಕೌಶಲ್ಯಗಳು ಇದನ್ನು `.agents/skills/_shared/base-green.md` ಎಂದು ಉಲ್ಲೇಖಿಸುತ್ತವೆ). ಮೂಲದ tip
ಕೆಂಪಾಗಿರುವಾಗ ತೆರೆಯಲಾದ PR ತನ್ನ bodyಯಲ್ಲಿ `⚠️ base-red inherited: #<issue>` ಅನ್ನು ಹೊಂದಿರಬೇಕು. ಸಂಗ್ರಹಗೊಂಡಿರುವ
ಕೆಂಪು ಸ್ಥಿತಿಯನ್ನು (ಮೂಲದ tip + ಕೆಂಪು PRಗಳು) ನಿವಾರಿಸಲು, `/sweep-reds` ಕೌಶಲ್ಯವನ್ನು ಬಳಸಿ.
