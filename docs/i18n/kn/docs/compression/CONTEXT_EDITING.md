ನಿಯೋಜಿತ **Context Editing** ಎಂಬುದು Claude-ಗೆ ಮಾತ್ರ ಸೀಮಿತವಾದ ಸಂದರ್ಭ-ನಿರ್ವಹಣಾ ವೈಶಿಷ್ಟ್ಯವಾಗಿದೆ. OmniRoute-ನ ಸ್ಥಳೀಯ
ಸಂಕುಚನ ಎಂಜಿನ್ಗಳಿಗಿಂತ (Caveman, RTK, LLMLingua, stacked pipelines) ಭಿನ್ನವಾಗಿ — ಅವು ವಿನಂತಿಯ ಭಾಗವನ್ನು
ಪ್ರಾಕ್ಸಿಯಿಂದ ಹೊರಹೋಗುವ _ಮೊದಲು_ ಮರುಬರೆಯುತ್ತವೆ — Context Editing, ಅದರ ಸ್ವಂತ ಚಾಲನೆಯಲ್ಲಿರುವ ಸಂದರ್ಭ ವಿಂಡೋದಿಂದ ಹಳೆಯ
tool-use / tool-result ಬ್ಲಾಕ್ಗಳನ್ನು ತೆರವುಗೊಳಿಸುವಂತೆ **provider**-ಗೆ ಕೇಳುತ್ತದೆ. OmniRoute ಕೇವಲ ಭಾಗದ
ಪ್ಯಾರಾಮೀಟರ್ ಅನ್ನು (`context_management.edits[]`) ಲಗತ್ತಿಸುತ್ತದೆ; Claude ತನ್ನ ಸ್ವಂತ ಟೋಕನೈಜರ್ಗೆ ಅನುಗುಣವಾಗಿ ನಿಜವಾದ ತೆರವುಗೊಳಿಸುವಿಕೆಯನ್ನು ಮಾಡುತ್ತದೆ.

ಇದು ಸ್ವಭಾವತಃ ನಿಯೋಜಿತ ಸಾಮರ್ಥ್ಯವಾಗಿದೆ: ಇತರ ಪ್ರೊವೈಡರ್ಗಳು ಈ ಪ್ಯಾರಾಮೀಟರ್ ಅನ್ನು ತಿರಸ್ಕರಿಸುತ್ತಾರೆ, ಆದ್ದರಿಂದ OmniRoute ಇದನ್ನು
Claude ಮತ್ತು Claude-Code-ಹೊಂದಾಣಿಕೆಯ ರಿಲೇಗಳಿಗೆ ಕಟ್ಟುನಿಟ್ಟಾಗಿ ಸೀಮಿತಗೊಳಿಸುತ್ತದೆ.

ಅಧಿಕೃತ ಮೂಲ: `open-sse/config/contextEditing.ts` (ತಂತ್ರದ ಐಡಿಗಳು, ಭಾಗದ ಒಳಸೇರಿಕೆ, ಟೆಲಿಮೆಟ್ರಿ
ಹೊರತೆಗೆಯುವಿಕೆ), `open-sse/executors/base.ts` (ಒಳಸೇರಿಕೆ ಗೇಟ್ + 400-ಫಾಲ್ಬ್ಯಾಕ್), ಮತ್ತು
`open-sse/services/compression/types.ts` (ಕಾನ್ಫಿಗ್ ರಚನೆ + ಡೀಫಾಲ್ಟ್).

## `clear_tool_uses` ಏನು ಮಾಡುತ್ತದೆ

OmniRoute ಹೊರಹೋಗುವ Anthropic Messages ಭಾಗದಲ್ಲಿ ಒಂದೇ ಎಡಿಟ್ ಅನ್ನು ಒಳಸೇರಿಸುತ್ತದೆ:

```json
{
  "context_management": {
    "edits": [
      {
        "type": "clear_tool_uses_20250919",
        "trigger": { "type": "input_tokens", "value": 100000 },
        "keep": { "type": "tool_uses", "value": 3 }
      }
    ]
  }
}
```

- `type: "clear_tool_uses_20250919"` — ದಿನಾಂಕಿತ Anthropic ತಂತ್ರದ ಐಡಿ (`CLEAR_TOOL_USES_STRATEGY`).
- `trigger.value: 100000` — ವಿನಂತಿಯ ಇನ್ಪುಟ್ ಟೋಕನ್ಗಳು ಈ ಮಿತಿಯನ್ನು ಮೀರಿದ ನಂತರ, Claude ಹಳೆಯ
  tool-use/result ಜೋಡಿಗಳನ್ನು ತೆರವುಗೊಳಿಸಲು ಪ್ರಾರಂಭಿಸುತ್ತದೆ (`CONTEXT_EDITING_DEFAULT_TRIGGER_TOKENS`, Anthropic-ನ ಡೀಫಾಲ್ಟ್).
- `keep.value: 3` — ಇತ್ತೀಚಿನ N tool-use/result ಜೋಡಿಗಳನ್ನು ಮುಟ್ಟದೆ ಉಳಿಸಲಾಗುತ್ತದೆ
  (`CONTEXT_EDITING_DEFAULT_KEEP_TOOL_USES`).

ಬೀಟಾವನ್ನು `anthropic-beta: context-management-2025-06-27` ಹೆಡರ್ ಮೂಲಕ ಪ್ರಕಟಿಸಲಾಗುತ್ತದೆ, ಇದನ್ನು
OmniRoute ಈಗಾಗಲೇ Claude ವಿನಂತಿಗಳಲ್ಲಿ ಹೊರಸೂಸುತ್ತದೆ.

ಒಳಸೇರಿಕೆಯನ್ನು `applyContextEditingToBody()` ನಿರ್ವಹಿಸುತ್ತದೆ ಮತ್ತು ಇದು **idempotent** ಆಗಿದೆ: `clear_tool_uses`
ಎಡಿಟ್ ಈಗಾಗಲೇ ಭಾಗದಲ್ಲಿ ಇದ್ದರೆ (ಹಿಂದಿನ ಕರೆ ಮೂಲಕ ಸೇರಿಸಲ್ಪಟ್ಟಿದ್ದರೆ ಅಥವಾ ಕ್ಲೈಂಟ್ ಒದಗಿಸಿದ್ದರೆ), ಭಾಗವನ್ನು
ಯಥಾಸ್ಥಿತಿಯಲ್ಲಿ ಬಿಡಲಾಗುತ್ತದೆ. `clear_thinking_20251015` ಎಡಿಟ್ ಕೂಡ ಇದ್ದರೆ, OmniRoute
`clear_thinking` ಎಡಿಟ್ ಅನ್ನು ಮುಂಭಾಗಕ್ಕೆ ಸ್ಥಿರವಾಗಿ ವಿಂಗಡಿಸುತ್ತದೆ, ಏಕೆಂದರೆ `edits[]` ಅರೇಯಲ್ಲಿ
`clear_thinking`, `clear_tool_uses`-ಗಿಂತ ಮೊದಲು ಇರಬೇಕೆಂದು Anthropic ಕಡ್ಡಾಯಗೊಳಿಸುತ್ತದೆ.

## ಪ್ರತಿ-ಕಾಂಬೋ ಸಕ್ರಿಯಗೊಳಿಸುವ ಟಾಗಲ್

Context Editing **ಡೀಫಾಲ್ಟ್ ಆಗಿ ಆಫ್** ಇರುತ್ತದೆ ಮತ್ತು ಆಯ್ಕೆಮಾಡಿ ಸಕ್ರಿಯಗೊಳಿಸಬೇಕಾಗುತ್ತದೆ. ಈ ಟಾಗಲ್ ಸಂಕುಚನ
ಕಾನ್ಫಿಗ್ನಲ್ಲಿ ಸಾಗುವ ಏಕೈಕ ಬೂಲಿಯನ್ ಆಗಿದೆ:

- ಸೆಟ್ಟಿಂಗ್ ಕೀ: `contextEditing.enabled` (camelCase — `context_editing` / `context-editing` **ಅಲ್ಲ**).
- ಪ್ರಕಾರ: `open-sse/services/compression/types.ts`-ನಲ್ಲಿ
  `ContextEditingConfig { enabled: boolean }`.
- ಡೀಫಾಲ್ಟ್: `DEFAULT_CONTEXT_EDITING_CONFIG = { enabled: false }`.
- Zod ಸ್ಕೀಮಾ: `src/shared/validation/compressionConfigSchemas.ts`-ನಲ್ಲಿ `contextEditingConfigSchema`.
- ಸಂಗ್ರಹಣೆ: ಉಳಿದ ಸಂಕುಚನ ಸೆಟ್ಟಿಂಗ್ಗಳೊಂದಿಗೆ ಸ್ಥಿರವಾಗಿ ಉಳಿಸಲಾಗುತ್ತದೆ (
  `src/lib/db/compression.ts`-ನಲ್ಲಿ ಸಾಮಾನ್ಯೀಕರಿಸಲಾಗಿದೆ).

ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿ ಈ ಟಾಗಲ್ ಸಂಕುಚನ ಹಬ್ನಲ್ಲಿ
(`src/app/(dashboard)/dashboard/context/combos/CompressionHub.tsx`) ಇರುತ್ತದೆ ಮತ್ತು
`saveSettings()` ಮೂಲಕ `{ contextEditing: { enabled: … } }` ಅನ್ನು ಮರಳಿ ಬರೆಯುತ್ತದೆ. ಇದು
ಸಂಕುಚನ-ಸೆಟ್ಟಿಂಗ್ಗಳ ಆಬ್ಜೆಕ್ಟ್ನಲ್ಲಿಯೇ ಸಾಗುವುದರಿಂದ, ಸಂಪೂರ್ಣ ಸ್ವತಂತ್ರ ಮೇಲ್ಮೈಯಾಗಿರುವ ಬದಲು ಪ್ರತಿ-ಕಾಂಬೋ
ಸಂಕುಚನ ಪ್ರೊಫೈಲ್ನೊಂದಿಗೆ ಸಂಯೋಜಿತವಾಗುತ್ತದೆ — ಕಾನ್ಫಿಗ್ ಕೇವಲ ಆನ್/ಆಫ್ ಫ್ಲ್ಯಾಗ್ ಅನ್ನು ಹೊಂದಿರುತ್ತದೆ; ಎಲ್ಲಾ ಮಿತಿಗಳು (`trigger`,
`keep`) ಮೇಲೆ ದಾಖಲಿಸಲಾದ ಸ್ಥಿರಾಂಕಗಳಾಗಿವೆ.

## Claude-ಮಾತ್ರ ಗೇಟಿಂಗ್

ಇಂಜೆಕ್ಷನ್ ನೈಜ Claude ಅಥವಾ Claude-Code-ಹೊಂದಾಣಿಕೆಯ ರಿಲೇಗಳಿಗೆ ಮಾತ್ರ ನಡೆಯುತ್ತದೆ.
`open-sse/executors/base.ts` ನಲ್ಲಿರುವ ಗೇಟ್ ಹೀಗಿದೆ:

```ts
if (
  (this.provider === "claude" || isClaudeCodeCompatible(this.provider)) &&
  contextEditing?.enabled &&
  !contextEditingDisabled
) {
  applyContextEditingToBody(transformedBody, { enabled: true });
}
```

- `this.provider === "claude"` — ನೈಜ Anthropic ಕೀ/OAuth.
- `isClaudeCodeCompatible(this.provider)` — `anthropic-compatible-cc-` ಪೂರ್ವಪ್ರತ್ಯಯದಿಂದ ಪ್ರಾರಂಭವಾಗುವ provider id ಹೊಂದಿರುವ ರಿಲೇಗಳು (ಅವು Claude Code ಹೊಂದಾಣಿಕೆಯನ್ನು ಪ್ರಕಟಿಸುತ್ತವೆ, ಆದ್ದರಿಂದ ಬೀಟಾವನ್ನು ಸ್ವೀಕರಿಸುವ ಸಾಧ್ಯತೆ ಅತಿ ಹೆಚ್ಚಿರುವ ರಿಲೇಗಳು ಇವೇ). `open-sse/services/provider.ts` ನೋಡಿ.

ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ **ಹೊರಗಿಡಲಾಗಿದೆ**:

- `claude-web` — `context_management` ಅನ್ನು ಎಂದಿಗೂ ನೋಡದ `create_conversation_params` ವಿನಂತಿ ಸ್ವರೂಪವನ್ನು ಹೊಂದಿರುವ ಬ್ರೌಸರ್ ರಿಲೇ.
- ಸಾಮಾನ್ಯ `anthropic-compatible-*` ರಿಲೇಗಳು (`-cc-` ಪೂರ್ವಪ್ರತ್ಯಯವಿಲ್ಲದೆ) — ಬೀಟಾ ಬೆಂಬಲ ಅನಿಶ್ಚಿತವಾಗಿರುವ ತೃತೀಯ-ಪಕ್ಷ endpointಗಳು.

ಟಾಗಲ್ ಆನ್ ಆಗಿದ್ದರೂ Claude ಅಲ್ಲದ providerಗಳು `context_management` ಪ್ಯಾರಾಮೀಟರ್ ಅನ್ನು ಎಂದಿಗೂ ಸ್ವೀಕರಿಸುವುದಿಲ್ಲ.

## 400-fallback / ರಿಲೇ ವ್ಯಾಪ್ತಿ

Claude-ಹೊಂದಾಣಿಕೆಯ ರಿಲೇ ಬೀಟಾವನ್ನು ಪ್ರಕಟಿಸಬಹುದು, ಆದರೆ `context_management` ಪ್ಯಾರಾಮೀಟರ್ ಅನ್ನು HTTP 400 ನೊಂದಿಗೆ ತಿರಸ್ಕರಿಸಬಹುದು. ವಿನಂತಿಯನ್ನು ವಿಫಲಗೊಳಿಸುವ ಬದಲು ಸುಗಮವಾಗಿ ಪರ್ಯಾಯಕ್ಕೆ ಇಳಿಯಲು, executor ಪ್ಯಾರಾಮೀಟರ್ ಅನ್ನು ತೆಗೆದುಹಾಕಿ ಅದೇ URL ಅನ್ನು **ಒಮ್ಮೆ** ಮರುಪ್ರಯತ್ನಿಸುತ್ತದೆ:

```ts
if (
  response.status === HTTP_STATUS.BAD_REQUEST &&
  contextEditing?.enabled &&
  !contextEditingDisabled &&
  transformedBody?.context_management !== undefined
) {
  const errText = await response
    .clone()
    .text()
    .catch(() => "");
  if (/context[_-]management|context editing/i.test(errText)) {
    contextEditingDisabled = true;
    delete transformedBody.context_management;
    let retryBody = JSON.stringify(transformedBody);
    if (isClaudeCodeCompatible(this.provider) || this.provider === "claude") {
      retryBody = await signRequestBody(retryBody);
    }
    response = await fetch(url, { ...fetchOptions, body: retryBody });
  }
}
```

ವರ್ತನೆ:

1. ಸಂದರ್ಭ ಸಂಪಾದನೆ ಸಕ್ರಿಯವಾಗಿರುವಾಗ, body ನಿಜವಾಗಿಯೂ `context_management` ಅನ್ನು ಹೊಂದಿರುವಾಗ, ಮತ್ತು `400` ಬಂದಾಗ ಮಾತ್ರ ಇದು ಚಾಲನೆಯಾಗುತ್ತದೆ.
2. ಹೊಂದಿಕೆಯಾಗದ ಮಾರ್ಗಕ್ಕಾಗಿ ಮೂಲ response ಹಾಗೆಯೇ ಉಳಿಯುವಂತೆ 400 body ಅನ್ನು `clone()` ಮೂಲಕ ಓದಲಾಗುತ್ತದೆ.
3. ದೋಷ ಪಠ್ಯವು `/context[_-]management|context editing/i` ಗೆ ಹೊಂದಿಕೆಯಾಗಬೇಕು — ಸಂಬಂಧವಿಲ್ಲದ 400 (ಉದಾ. `max_tokens must be >= 1`) fallback ಅನ್ನು ಪ್ರಚೋದಿಸುವುದಿಲ್ಲ; ಮೂಲ ದೋಷವೇ ಮುಂದಕ್ಕೆ ಪ್ರಸಾರವಾಗುತ್ತದೆ.
4. ಹೊಂದಿಕೆಯಾದಾಗ ಇದು `contextEditingDisabled = true` ಅನ್ನು ಹೊಂದಿಸುತ್ತದೆ (ಇದರಿಂದ retry/fallback URL ಗಾಗಿ ನಂತರ ಹೊಸ `transformedBody` ನಿರ್ಮಿಸಿದರೆ ಮರು-ಇಂಜೆಕ್ಷನ್ ತಡೆಯಲ್ಪಡುತ್ತದೆ), `context_management` ಅನ್ನು ಅಳಿಸುತ್ತದೆ, Claude / Claude-Code-ಹೊಂದಾಣಿಕೆಯ ರಿಲೇಗಳಿಗಾಗಿ body ಗೆ (`signRequestBody`) ಮರು-ಸಹಿ ಮಾಡುತ್ತದೆ ಮತ್ತು ಅದೇ URL ಅನ್ನು ಒಮ್ಮೆ ಮರುಪ್ರಯತ್ನಿಸುತ್ತದೆ.

ನೈಜ Claude ಬೀಟಾವನ್ನು `ANTHROPIC_BETA_BASE` ನಲ್ಲಿ ಹೊಂದಿರುತ್ತದೆ ಮತ್ತು ಈ fallback ಮಾರ್ಗವನ್ನು ತಲುಪುವುದಿಲ್ಲ.

## `applied_edits` ಟೆಲಿಮೆಟ್ರಿ

Claude response ನಂತರ, provider ವಾಸ್ತವವಾಗಿ ಎಷ್ಟು ಸಂದರ್ಭವನ್ನು ತೆರವುಗೊಳಿಸಿದೆ ಎಂಬುದನ್ನು OmniRoute ದಾಖಲಿಸುತ್ತದೆ. ಇದನ್ನು **stream ಮಾಡಲಾಗುವುದಿಲ್ಲ** — ಇದನ್ನು non-streaming response body ಯಿಂದ best-effort ಆಧಾರದಲ್ಲಿ ಹೊರತೆಗೆಯಲಾಗುತ್ತದೆ ಮತ್ತು ಇದು response ಮೇಲೆ ಎಂದಿಗೂ ಪರಿಣಾಮ ಬೀರುವುದಿಲ್ಲ (ಟೆಲಿಮೆಟ್ರಿ ವೈಫಲ್ಯಗಳನ್ನು ನಿರ್ಲಕ್ಷಿಸಲಾಗುತ್ತದೆ).

- ಹೊರತೆಗೆಯುವಿಕೆ: `open-sse/config/contextEditing.ts` ನಲ್ಲಿರುವ `extractContextEditingTelemetry(responseBody)`.
  ಇದು response ಸ್ವರೂಪದ ವ್ಯತ್ಯಾಸಗಳನ್ನು ರಕ್ಷಣಾತ್ಮಕವಾಗಿ ನಿಭಾಯಿಸಲು ಮೂರು ಸ್ಥಳಗಳಲ್ಲಿ `applied_edits` ಅನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ:
  - `context_management.applied_edits`
  - `usage.context_management.applied_edits`
  - `usage.applied_edits`
- ಪ್ರತಿ edit entry ಯಿಂದ ಓದಲಾಗುವ ಕ್ಷೇತ್ರಗಳು: `cleared_input_tokens` ಮತ್ತು `cleared_tool_uses`
  (snake_case, Anthropic-native), ಜೊತೆಗೆ `clearedInputTokens` / `clearedToolUses` camelCase fallbackಗಳು.
- ಯಾವುದೇ `applied_edits` array ಕಂಡುಬರದಿದ್ದರೆ ಅಥವಾ ವಾಸ್ತವವಾಗಿ ಏನನ್ನೂ ತೆರವುಗೊಳಿಸದಿದ್ದರೆ `null` ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ.

receipt ಸ್ವರೂಪವು `ContextEditingTelemetry { editCount, clearedInputTokens, clearedToolUses }` ಆಗಿದೆ.
`recordContextEditingTelemetry()` (`src/lib/db/compressionAnalytics.ts`) ಮೂಲಕ `open-sse/handlers/chatCore.ts` ನಲ್ಲಿ (`provider === "claude"` ಗೆ ಗೇಟ್ ಮಾಡಲಾಗಿದೆ) ದಾಖಲಿಸುವಿಕೆ ನಡೆಯುತ್ತದೆ; ಇದು ಈ ಟ್ಯಾಗ್ಗಳನ್ನು ಹೊಂದಿರುವ compression analytics row ಅನ್ನು ಬರೆಯುತ್ತದೆ:

- `mode: "context-editing"`
- `engine: "context-editing"`
- `tokens_saved` / `original_tokens` = ತೆರವುಗೊಳಿಸಲಾದ input-token ಎಣಿಕೆ
- `request_id` ಗೆ `::context-editing` ಪ್ರತ್ಯಯವನ್ನು ಸೇರಿಸಲಾಗುತ್ತದೆ

ಹೀಗಾಗಿ ನಿಯೋಜಿತ ತೆರವುಗೊಳಿಸುವಿಕೆಯು ಸ್ಥಳೀಯ engineಗಳ ಜೊತೆಗೆ compression analytics ನಲ್ಲಿ `context-editing` engine label ಅಡಿಯಲ್ಲಿ ಕಾಣಿಸಿಕೊಳ್ಳುತ್ತದೆ ಮತ್ತು RTK/Caveman/LLMLingua ಉಳಿತಾಯಗಳಿಂದ ಅದನ್ನು ಪ್ರತ್ಯೇಕವಾಗಿ ಗುರುತಿಸಬಹುದು.

| ---------------------- | ------------------------------------------------------ | -------------------------------------------------------- |
| ಎಲ್ಲಿ ರನ್ ಆಗುತ್ತದೆ     | ವಿನಂತಿಯು ಪ್ರಾಕ್ಸಿಯಿಂದ ಹೊರಹೋಗುವ ಮೊದಲು OmniRoute ನಲ್ಲಿ   | ಪ್ರೊವೈಡರ್ನಲ್ಲಿ (Claude), ಸರ್ವರ್ ಬದಿಯಲ್ಲಿ                 |
| ಏನನ್ನು ಎಡಿಟ್ ಮಾಡುತ್ತದೆ | ಪ್ರಾಂಪ್ಟ್ / ಕಾಂಟೆಕ್ಸ್ಟ್ / ಟೂಲ್-ರಿಸಲ್ಟ್ ಪಠ್ಯ            | ಹಳೆಯ ಟೂಲ್-ಯೂಸ್ / ಟೂಲ್-ರಿಸಲ್ಟ್ ಬ್ಲಾಕ್ಗಳು                  |
