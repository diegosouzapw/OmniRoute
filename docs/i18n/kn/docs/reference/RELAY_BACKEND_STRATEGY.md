## ಸಾರಾಂಶ

OmniRoute ಈಗ `/api/v1/relay/chat/completions` ಗಾಗಿ ಮೂರು ರಿಲೇ ಮೋಡ್ಗಳನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ:

- `ts`: ಪ್ರಕ್ರಿಯೆಯೊಳಗೇ TypeScript ರಿಲೇಯನ್ನು ಬಳಸಿ.
- `bifrost`: Bifrost ಗೇಟ್ವೇಯನ್ನು ಕಡ್ಡಾಯವಾಗಿ ಬಳಸಿ.
- `auto`: ಲಭ್ಯವಿದ್ದಾಗ Bifrostಗೆ ಆದ್ಯತೆ ನೀಡಿ; ವೈಫಲ್ಯವಾದಾಗ TypeScriptಗೆ ಹಿಂತಿರುಗಿ.

ನೀವು ಹೆಚ್ಚಿನ ವಿನಂತಿ ದರದಲ್ಲಿ (ದಿನಕ್ಕೆ ಹೆಚ್ಚಿನ ಸಂಖ್ಯೆಯ ಟೋಕನ್ಗಳು, ಬಹುತೇಕ ನಿರಂತರ ಥ್ರೂಪುಟ್) ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತಿರುವಾಗ, ಕಾರ್ಯನಿರ್ವಹಿಸದ ಸೈಡ್ಕಾರ್ನಿಂದಾಗಿ ಹಾಟ್ ಪಾತ್ ಎಂದಿಗೂ ನಿರ್ಬಂಧಗೊಳ್ಳದಂತೆ ಫಾಲ್ಬ್ಯಾಕ್ ಪಾತ್ ಅನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ಮತ್ತು ವೇಗವಾಗಿ ಇರಿಸುವುದೇ ಉತ್ತಮ ಕಾರ್ಯತಂತ್ರ.

## ಮೋಡ್ನ ವರ್ತನೆ

- `ts`
  - ಅತ್ಯಂತ ಕಡಿಮೆ ಕಾರ್ಯಾಚರಣಾ ಸಂಕೀರ್ಣತೆ.
  - ಎಲ್ಲಾ ರೂಟಿಂಗ್ ಮತ್ತು ಮೌಲ್ಯೀಕರಣವು Node ನಲ್ಲಿ ನಡೆಯುತ್ತದೆ.
  - ಲಭ್ಯತೆಗಾಗಿ ಸೈಡ್ಕಾರ್ ಅವಲಂಬನೆ ಇಲ್ಲ.
- `bifrost`
  - ಎಲ್ಲಾ ವಿನಂತಿಗಳನ್ನು ಸೈಡ್ಕಾರ್ ಗೇಟ್ವೇ ಮೂಲಕ ಕಡ್ಡಾಯವಾಗಿ ಕಳುಹಿಸುತ್ತದೆ.
  - ಸ್ವಯಂಚಾಲಿತ ಫಾಲ್ಬ್ಯಾಕ್ ಇಲ್ಲ.
  - ಸೈಡ್ಕಾರ್ನ ಸುಸ್ಥಿತಿ ಮತ್ತು ಲೇಟೆನ್ಸಿ ಖಾತರಿಯಾಗಿರುವಾಗ ಮಾತ್ರ ಉಪಯುಕ್ತ.
- `auto`
  - ಸೈಡ್ಕಾರ್ ಅನ್ನು ತಲುಪಲು ಸಾಧ್ಯವಿದ್ದು ಅದು ಸಕ್ರಿಯಗೊಂಡಿರುವಾಗ ಅದನ್ನು ಬಳಸಲಾಗುತ್ತದೆ.
  - ವಿಫಲ ಪ್ರಯತ್ನಗಳು ಫಾಲ್ಬ್ಯಾಕ್ ಹೆಡರ್ಗಳನ್ನು ಪ್ರಚೋದಿಸುತ್ತವೆ ಮತ್ತು ಟ್ರಾಫಿಕ್ ಅನ್ನು TSಗೆ ಹಿಂತಿರುಗಿಸುತ್ತವೆ; ಇದರಿಂದ ವಿನಂತಿಯ ಯಶಸ್ಸು ಮಿತಿಯೊಳಗೆ ಉಳಿಯುತ್ತದೆ.
  - ಕಟ್ಟುನಿಟ್ಟಾದ ಸೈಡ್ಕಾರ್-ಮಾತ್ರ ರೂಟಿಂಗ್ಗಿಂತ ಅಪ್ಟೈಮ್ ಹೆಚ್ಚು ಮುಖ್ಯವಾಗಿರುವಾಗ, ಪ್ರೊಡಕ್ಷನ್ಗಾಗಿ ಈ ಮೋಡ್ ಅತ್ಯಂತ ಸುರಕ್ಷಿತ ಆಯ್ಕೆಯಾಗಿದೆ.

## ಇಂದಿನ 9router ಮತ್ತು CLIPROXYAPI ಹೋಲಿಕೆ

9router ಮತ್ತು CLIPROXYAPI ಎರಡೂ ಐತಿಹಾಸಿಕವಾಗಿ ಅಪ್ಸ್ಟ್ರೀಮ್ ಪೂರೈಕೆದಾರರಿಗೆ ಹೊಂದಾಣಿಕೆಯ ಪಾತ್ಗಳನ್ನು ಒದಗಿಸಿದ ಇಂಟಿಗ್ರೇಶನ್ಗಳಾಗಿವೆ.

- 9router ಅಪ್ಸ್ಟ್ರೀಮ್ ಆರ್ಕೆಸ್ಟ್ರೇಶನ್ ಮತ್ತು ಹೊಂದಾಣಿಕೆ ವರ್ತನೆಗಾಗಿ ಎಂಬೆಡ್ ಮಾಡಲಾದ ಪಾತ್ ಆಗಿದೆ.
- CLIPROXYAPI ಎಂಬುದು CLI / SDK ಶೈಲಿಯ ಟ್ರಾಫಿಕ್ಗಾಗಿ ಪ್ರಾಕ್ಸಿ API ಬ್ರಿಡ್ಜ್ ಆಗಿದೆ.
- ಮೀಸಲಾದ ಸೈಡ್ಕಾರ್ನಂತಹ ಹಾಪ್ ಮತ್ತು ಕಡಿಮೆ-ಲೇಟೆನ್ಸಿಯ ಸ್ಥಳೀಯ ಡಿಸ್ಪ್ಯಾಚ್ ಅಗತ್ಯವಿರುವಾಗ ಬಳಸುವ ಬಾಹ್ಯೀಕೃತ ಪಾತ್ ಆಗಿ Bifrost ಅನ್ನು ಸ್ಥಿರಗೊಳಿಸಲಾಗುತ್ತಿದೆ.

ನೀವು ಪ್ರಸ್ತುತ 9router/CLIPROXYAPI ಅನ್ನು ಹೋಲಿಸುತ್ತಿದ್ದರೆ:

- ಹಸ್ತಾಂತರಿಸುವ ಮೊದಲು API ರೂಟ್ನಲ್ಲಿಯೇ ವಿನಂತಿ ಸಹಿ, ಅಲೋಲಿಸ್ಟ್ ಪರಿಶೀಲನೆಗಳು ಮತ್ತು DB ನೀತಿ ಗೇಟ್ಗಳನ್ನು ಇರಿಸಿ.
- ವರ್ಕ್ಫ್ಲೋಗೆ ಕಟ್ಟುನಿಟ್ಟಾದ ಸೈಡ್ಕಾರ್ ವರ್ತನೆ ಮತ್ತು ಪ್ರತಿ ವಿನಂತಿಗೆ ಕಡಿಮೆ ವ್ಯತ್ಯಾಸ ಅಗತ್ಯವಿದ್ದರೆ, `OMNIROUTE_RELAY_BACKEND=bifrost` ಬಳಸಿ.
- ಇನ್ಸಿಡೆಂಟ್ ಪರಿಸ್ಥಿತಿಗಳಲ್ಲಿ ಸುಗಮ ಡಿಗ್ರೇಡೇಶನ್ನೊಂದಿಗೆ ಸೈಡ್ಕಾರ್ ಸ್ಥಿತಿಸ್ಥಾಪಕತ್ವ ಅಗತ್ಯವಿದ್ದರೆ, `OMNIROUTE_RELAY_BACKEND=auto` ಬಳಸಿ.

## ಬ್ಯಾಕೆಂಡ್ ಗಡಿ ಒಪ್ಪಂದ

ಸ್ಥಿರವಾದ ಉತ್ಪನ್ನ ಗಡಿಯು OmniRoute ರಿಲೇ API ಆಗಿದೆಯೇ ಹೊರತು ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಅನುಷ್ಠಾನವಲ್ಲ. Next.js ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಸ್ಥಳೀಯ ಸೇವೆಗಳನ್ನು ಸ್ಥಾಪಿಸಬಹುದು, ಕಾನ್ಫಿಗರ್ ಮಾಡಬಹುದು ಮತ್ತು ಮೇಲ್ವಿಚಾರಣೆ ಮಾಡಬಹುದು; ಆದರೆ ವಿನಂತಿ ರೂಟಿಂಗ್ ರಿಲೇ API ಮೂಲಕ ಪ್ರವೇಶಿಸಿ, ಆ ಗಡಿಯ ಹಿಂದೆ ಹಸ್ತಾಂತರಗೊಳ್ಳಬೇಕು.

ದೀರ್ಘಾವಧಿಯ ಬ್ಯಾಕೆಂಡ್ ಆಯ್ಕೆಗಳು:

- TypeScript ರಿಲೇಯನ್ನು ಪ್ರಕ್ರಿಯೆಯೊಳಗಿನ ನೀತಿ ಮತ್ತು ಫಾಲ್ಬ್ಯಾಕ್ ಪಾತ್ ಆಗಿ ಉಳಿಸಿಕೊಳ್ಳಿ. ಯಾವುದೇ ಬ್ಯಾಕೆಂಡ್ ಹಸ್ತಾಂತರಕ್ಕೂ ಮೊದಲು ದೃಢೀಕರಣ, ಅಲೋಲಿಸ್ಟ್ಗಳು, ವಿನಂತಿ ಸಾಮಾನ್ಯೀಕರಣ, ಲೆಕ್ಕಪತ್ರ ಮತ್ತು ಸುರಕ್ಷತಾ ಪರಿಶೀಲನೆಗಳು ಇಲ್ಲಿಯೇ ಉಳಿಯುತ್ತವೆ.
- ಡಿಪ್ಲಾಯ್ಮೆಂಟ್ಗೆ ಕಡಿಮೆ ರೂಟಿಂಗ್ ವ್ಯತ್ಯಾಸ, ಕೇಂದ್ರೀಕೃತ ಪೂರೈಕೆದಾರ ರೊಟೇಶನ್ ಅಥವಾ ಅನೇಕ OmniRoute ರೆಪ್ಲಿಕಾಗಳಾದ್ಯಂತ ಸ್ಕೇಲ್-ಔಟ್ ಅಗತ್ಯವಿರುವಾಗ, Bifrost ಅನ್ನು ಆದ್ಯತೆಯ ಅಧಿಕ-ಥ್ರೂಪುಟ್ Tier-1 ಸೈಡ್ಕಾರ್ ಆಗಿ ಬಳಸಿ.
- 9router ಮತ್ತು CLIPROXYAPI ಅನ್ನು ಎಂಬೆಡ್ ಮಾಡಲಾದ ಹೊಂದಾಣಿಕೆ ಸೇವೆಗಳಾಗಿ ಇರಿಸಿ. ಅವು ಮೇಲ್ವಿಚಾರಿತ ಸ್ಥಳೀಯ ಪ್ರಕ್ರಿಯೆಗಳಾಗಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತವೆ ಮತ್ತು ಅವುಗಳ ಪೂರೈಕೆದಾರ/CLI ವರ್ತನೆಯೇ ಅಪೇಕ್ಷಿತ ಅಡಾಪ್ಟರ್ ಆಗಿರುವಾಗ ಉಪಯುಕ್ತವಾಗಿವೆ; ಆದರೆ ಅವು ಡೀಫಾಲ್ಟ್ Tier-1 ರೂಟಿಂಗ್ ಎಂಜಿನ್ ಆಗಬಾರದು.
- ಹಾಟ್ ಪಾತ್ಗೆ ಅನಿಯಂತ್ರಿತ ಸೇವಾ URLಗಳನ್ನು ರವಾನಿಸಲು ಡ್ಯಾಶ್ಬೋರ್ಡ್ಗೆ ಅವಕಾಶ ನೀಡಬೇಡಿ. UI ಒದಗಿಸಿದ URLಗಳು ಕಾನ್ಫಿಗರೇಶನ್ ಇನ್ಪುಟ್ಗಳಾಗಿವೆ; ರೂಟಿಂಗ್ ಕೋಡ್ ಸರ್ವರ್-ಸೈಡ್ ಸೆಟ್ಟಿಂಗ್ಗಳು ಮತ್ತು ಮೇಲ್ವಿಚಾರಕ ಸ್ಥಿತಿಯಿಂದ ನೋಂದಾಯಿತ, ಸುಸ್ಥಿತಿ ಪರಿಶೀಲಿತ ಬ್ಯಾಕೆಂಡ್ಗಳನ್ನು ಪರಿಹರಿಸಬೇಕು.
- ಮೇಲ್ವಿಚಾರಿತ ಸೇವೆಗಳಿಗಾಗಿ ಇಂದು ಲೂಪ್ಬ್ಯಾಕ್ HTTPಗೆ ಆದ್ಯತೆ ನೀಡಿ; ಏಕೆಂದರೆ ನಿರ್ವಹಿತ ಪ್ರಕ್ರಿಯೆಗಳು ಈಗಾಗಲೇ HTTP-ಹೊಂದಾಣಿಕೆಯ APIಗಳನ್ನು ಒದಗಿಸುತ್ತವೆ, ರೂಟ್ ಗಾರ್ಡ್ ಗಡಿಯನ್ನು ಆಡಿಟ್ ಮಾಡಬಹುದು ಮತ್ತು ವೈಫಲ್ಯ/ಫಾಲ್ಬ್ಯಾಕ್ ವರ್ತನೆಯು ವಿನಂತಿ ಲಾಗ್ಗಳಲ್ಲಿ ಗೋಚರಿಸುತ್ತದೆ. ಪ್ರತ್ಯೇಕತೆ ಅಥವಾ ಫಾಲ್ಬ್ಯಾಕ್ ಅರ್ಥವ್ಯವಸ್ಥೆಯನ್ನು ದುರ್ಬಲಗೊಳಿಸದೆ p99 ರೂಟಿಂಗ್ ಲೇಟೆನ್ಸಿಯನ್ನು ಅಳೆಯಬಹುದಾದಷ್ಟು ಕಡಿಮೆ ಮಾಡಿದರೆ ಮಾತ್ರ ಭವಿಷ್ಯದ SDK ಅಥವಾ ಸಾಕೆಟ್ ಟ್ರಾನ್ಸ್ಪೋರ್ಟ್ ಸೇರಿಸುವುದು ಸಮಂಜಸ.

ಅತ್ಯಂತ ಅಧಿಕ-ಥ್ರೂಪುಟ್ ಡಿಪ್ಲಾಯ್ಮೆಂಟ್ಗಾಗಿ, ಆದ್ದರಿಂದ Bifrost ಸಕ್ರಿಯಗೊಳಿಸಿದ `auto` ಡೀಫಾಲ್ಟ್ ಉತ್ತರವಾಗಿದೆ: ಯಶಸ್ಸಿನ ದರಕ್ಕಾಗಿ TypeScript ಫಾಲ್ಬ್ಯಾಕ್ ಅನ್ನು ಉಳಿಸಿಕೊಂಡು ಹಾಟ್ ಪಾತ್ನಲ್ಲಿ Go ಸೈಡ್ಕಾರ್ ಬಳಸಿ. ಸುಗಮ ಡಿಗ್ರೇಡೇಶನ್ಗಿಂತ ಕಟ್ಟುನಿಟ್ಟಾದ ಸೈಡ್ಕಾರ್-ಮಾತ್ರ ವರ್ತನೆ ಹೆಚ್ಚು ಮುಖ್ಯವಾಗಿರುವಾಗ ಮಾತ್ರ `bifrost` ಬಳಸಿ.

## ಅಧಿಕ-ಥ್ರೂಪುಟ್ ಮಾರ್ಗದರ್ಶನ

ನಿರಂತರ ಅಧಿಕ RPM/RPS ಮತ್ತು ಕಟ್ಟುನಿಟ್ಟಾದ ಯಶಸ್ಸಿನ SLOಗಾಗಿ:

1. ಪ್ರಾಯೋಗಿಕ ಕೂಲ್ಡೌನ್ ಮತ್ತು ವೈಫಲ್ಯ ಟೆಲಿಮೆಟ್ರಿಯೊಂದಿಗೆ `auto` ಬಳಸಿ.
2. ಅಪ್ಸ್ಟ್ರೀಮ್ ಮೌಲ್ಯೀಕರಣ ಮತ್ತು API-ಕೀ ಪರಿಶೀಲನೆಗಳನ್ನು TypeScript ರೂಟ್ ಗಡಿಯಲ್ಲಿಯೇ ಇರಿಸಿ.
3. ನಿಮ್ಮ ಎಚ್ಚರಿಕೆ ವ್ಯವಸ್ಥೆಯು ಫಾಲ್ಬ್ಯಾಕ್ ಆವರ್ತನ ಮತ್ತು ಕಾರಣಗಳನ್ನು ಗುರುತಿಸುವಂತೆ ಸ್ಪಷ್ಟ ಹೆಡರ್ಗಳು/ಕೌಂಟರ್ಗಳನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ.
4. ಶಾಶ್ವತವಾಗಿ ಕಾಯದೆ ವೇಗವಾಗಿ ವಿಫಲಗೊಳ್ಳುವಂತೆ ಸೈಡ್ಕಾರ್ ಟೈಮ್ಔಟ್ಗಳನ್ನು ಟ್ಯೂನ್ ಮಾಡಿ.
5. ಫಾಲ್ಬ್ಯಾಕ್ ನಿಜವಾಗಿಯೂ ಅಪರೂಪದ ಘಟನೆಯಾಗಿರುವಂತೆ ಸೇವೆಯ ಸ್ವಯಂ-ಮರುಪ್ರಾರಂಭ ಮತ್ತು ಸುಸ್ಥಿತಿ ಟೆಲಿಮೆಟ್ರಿ ಲೂಪ್ ಅನ್ನು ಆರೋಗ್ಯಕರವಾಗಿ ಇರಿಸಿ.

## ಸೂಚಿಸಲಾದ ಬೇಸ್ಲೈನ್

- `OMNIROUTE_RELAY_BACKEND=auto`
- `BIFROST_ENABLED=1`
- API ಕೀಗಳು, ಅಲೋಲಿಸ್ಟ್, ಸ್ಯಾನಿಟೈಸರ್ ಮತ್ತು ದರ-ಮಿತಿ ಪರಿಶೀಲನೆಗಳನ್ನು ರೂಟ್ ಹ್ಯಾಂಡ್ಲರ್ಗಳಲ್ಲಿ ಸಕ್ರಿಯವಾಗಿರಿಸಿ (ಡೌನ್ಸ್ಟ್ರೀಮ್ ಫಾರ್ವರ್ಡಿಂಗ್ಗಿಂತ ಮೊದಲು ಅವು ಯಾವಾಗಲೂ ರನ್ ಆಗುತ್ತವೆ).
- ನಿಮ್ಮ ರಿವರ್ಸ್ ಪ್ರಾಕ್ಸಿ ಮತ್ತು ವಿನಂತಿ ಲಾಗ್ಗಳಿಂದ ಫಾಲ್ಬ್ಯಾಕ್ ಮೆಟ್ರಿಕ್ಗಳನ್ನು ಎಕ್ಸ್ಪೋರ್ಟ್ ಮಾಡಿ; ಇದರಿಂದ ಸೈಡ್ಕಾರ್ ಔಟೇಜ್ಗಳು ಒಂದು ನಿಮಿಷದೊಳಗೆ ಗೋಚರಿಸುತ್ತವೆ.
