OmniRoute ಅನ್ನು Termux ಮೂಲಕ Android ನಲ್ಲಿ ಹೆಡ್ಲೆಸ್ ಸರ್ವರ್ ಆಗಿ ಚಲಾಯಿಸಬಹುದು. Electron ಡೆಸ್ಕ್ಟಾಪ್ ಆ್ಯಪ್ಗೆ Termux ನಲ್ಲಿ ಬೆಂಬಲವಿಲ್ಲ, ಆದರೆ ವೆಬ್ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಮತ್ತು OpenAI-ಹೊಂದಾಣಿಕೆಯ API ಸ್ಥಳೀಯ ಬ್ರೌಸರ್ನಿಂದ ಅಥವಾ ಅದೇ ನೆಟ್ವರ್ಕ್ನಲ್ಲಿರುವ ಇತರ ಸಾಧನಗಳಿಂದ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತವೆ.

## ಪೂರ್ವಾಪೇಕ್ಷಿತಗಳು

F-Droid ಅಥವಾ GitHub ಬಿಡುಗಡೆಗಳಿಂದ Termux ಅನ್ನು ಸ್ಥಾಪಿಸಿ, ನಂತರ ಪ್ಯಾಕೇಜ್ಗಳನ್ನು ಅಪ್ಡೇಟ್ ಮಾಡಿ ಮತ್ತು `better-sqlite3` ನಂತಹ ಸ್ಥಳೀಯ ಅವಲಂಬನೆಗಳಿಗೆ ಅಗತ್ಯವಿರುವ ಬಿಲ್ಡ್ ಪರಿಕರಗಳನ್ನು ಸ್ಥಾಪಿಸಿ.

```bash
pkg update
pkg upgrade
pkg install nodejs python build-essential git
```

> **Node.js ಆವೃತ್ತಿ:** OmniRoute ಗೆ Node `>=22.22.2 <23 || >=24.0.0 <27` ಅಗತ್ಯವಿದೆ (`package.json` / `SUPPORTED_NODE_RANGE` ನಲ್ಲಿನ `engines` ಗೆ ಹೊಂದಿಕೆಯಾಗುತ್ತದೆ). Termux ನ `nodejs-lts` ಸಾಮಾನ್ಯವಾಗಿ Node 20 LTS ಅನ್ನು ಒದಗಿಸುತ್ತದೆ, ಅದಕ್ಕೆ **ಇನ್ನು ಮುಂದೆ ಬೆಂಬಲವಿಲ್ಲ** — ಬದಲಿಗೆ `pkg install nodejs` (ಪ್ರಸ್ತುತ) ಅನ್ನು ಸ್ಥಾಪಿಸಿ ಮತ್ತು `node --version` 22.x/24.x+ ಶ್ರೇಣಿಯನ್ನು ವರದಿ ಮಾಡುತ್ತದೆ ಎಂಬುದನ್ನು ಪರಿಶೀಲಿಸಿ.

ಸ್ಥಳೀಯ ಪ್ಯಾಕೇಜ್ ಕಂಪೈಲೇಶನ್ ವಿಫಲವಾದರೆ, ಮೇಲಿನ `pkg install` ಕಮಾಂಡ್ ಅನ್ನು ಮತ್ತೊಮ್ಮೆ ಚಲಾಯಿಸಿ ಮತ್ತು ನಂತರ OmniRoute ಸ್ಥಾಪನೆಯನ್ನು ಮರುಪ್ರಯತ್ನಿಸಿ.

## ಸ್ಥಾಪನೆ

ಇತ್ತೀಚಿನ ಪ್ರಕಟಿತ ಪ್ಯಾಕೇಜ್ ಅನ್ನು ನೇರವಾಗಿ ಚಲಾಯಿಸಿ:

```bash
npx -y omniroute@latest
```

ನೀವು ಅದನ್ನು ಜಾಗತಿಕವಾಗಿಯೂ ಸ್ಥಾಪಿಸಬಹುದು:

```bash
npm install -g omniroute
omniroute
```

## ಚಲಾಯಿಸುವುದು

OmniRoute ಅನ್ನು ಹೆಡ್ಲೆಸ್ ಸರ್ವರ್ ಮೋಡ್ನಲ್ಲಿ ಪ್ರಾರಂಭಿಸಿ:

```bash
omniroute
```

ಅಥವಾ:

```bash
npx omniroute
```

ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಇಲ್ಲಿ ಆಲಿಸುತ್ತದೆ:

```text
http://localhost:20128
```

Android ಬ್ರೌಸರ್ನಲ್ಲಿ ಆ URL ಅನ್ನು ತೆರೆಯಿರಿ. ನೀವು Termux ಒಳಗೆ ಕ್ಲೈಂಟ್ಗಳನ್ನು ಚಲಾಯಿಸುತ್ತಿದ್ದರೆ, OpenAI-ಹೊಂದಾಣಿಕೆಯ ಮೂಲ URL ಆಗಿ ಅದೇ ಹೋಸ್ಟ್ ಮತ್ತು ಪೋರ್ಟ್ ಅನ್ನು ಬಳಸಿ.

## ಹಿನ್ನೆಲೆ ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆ

ಸರಳ ಹಿನ್ನೆಲೆ ಪ್ರಕ್ರಿಯೆಗಾಗಿ:

```bash
nohup omniroute > omniroute.log 2>&1 &
```

ಅದನ್ನು ನಿಲ್ಲಿಸಲು:

```bash
pkill -f omniroute
```

ಸಾಧನ ಬೂಟ್ ಆದ ನಂತರ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಪ್ರಾರಂಭಿಸಲು, Termux:Boot ಆಡ್-ಆನ್ ಅನ್ನು ಸ್ಥಾಪಿಸಿ ಮತ್ತು ಬೂಟ್ ಸ್ಕ್ರಿಪ್ಟ್ ರಚಿಸಿ:

```bash
mkdir -p ~/.termux/boot
cat > ~/.termux/boot/omniroute.sh <<'EOF'
#!/data/data/com.termux/files/usr/bin/sh
cd "$HOME"
nohup omniroute > "$HOME/omniroute.log" 2>&1 &
EOF
chmod +x ~/.termux/boot/omniroute.sh
```

Android ಬ್ಯಾಟರಿ ಆಪ್ಟಿಮೈಸೇಶನ್ ದೀರ್ಘಕಾಲ ಚಲಿಸುವ ಹಿನ್ನೆಲೆ ಪ್ರಕ್ರಿಯೆಗಳನ್ನು ನಿಲ್ಲಿಸಬಹುದು. ಸರ್ವರ್ ಆನ್ಲೈನ್ನಲ್ಲಿಯೇ ಉಳಿಯಬೇಕೆಂದಿದ್ದರೆ, Termux ಗಾಗಿ ಬ್ಯಾಟರಿ ಆಪ್ಟಿಮೈಸೇಶನ್ ಅನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿ.

## ಇತರ ಸಾಧನಗಳಿಂದ ಪ್ರವೇಶಿಸುವುದು

WiFi ನೆಟ್ವರ್ಕ್ನಲ್ಲಿ ಫೋನ್ನ IP ವಿಳಾಸವನ್ನು ಕಂಡುಹಿಡಿಯಿರಿ:

```bash
ip addr show wlan0
```

ನಂತರ ಇನ್ನೊಂದು ಸಾಧನದಿಂದ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ತೆರೆಯಿರಿ:

```text
http://PHONE_IP:20128
```

ಉದಾಹರಣೆಗೆ:

```text
http://192.168.1.50:20128
```

ಫೋನ್ ಮತ್ತು ಕ್ಲೈಂಟ್ ಅನ್ನು ಒಂದೇ ವಿಶ್ವಾಸಾರ್ಹ ನೆಟ್ವರ್ಕ್ನಲ್ಲಿ ಇರಿಸಿ. ನೀವು OmniRoute ಅನ್ನು ಫೋನ್ನ ಹೊರಗೆ ಬಹಿರಂಗಪಡಿಸಿದರೆ, API ಕೀಗಳು ಮತ್ತು ಡ್ಯಾಶ್ಬೋರ್ಡ್ ದೃಢೀಕರಣವನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ.

## ಡೇಟಾ ಡೈರೆಕ್ಟರಿ

ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ OmniRoute, Linux ನಲ್ಲಿ ಬಳಸುವ ಅದೇ ಸರ್ವರ್-ಸೈಡ್ ಡೇಟಾ ಪಥದ ವರ್ತನೆಯನ್ನು ಅನುಸರಿಸಿ, Termux ಹೋಮ್ ಡೈರೆಕ್ಟರಿಯ ಅಡಿಯಲ್ಲಿ ಡೇಟಾವನ್ನು ಸಂಗ್ರಹಿಸುತ್ತದೆ. ಡೇಟಾಬೇಸ್ ಅನ್ನು ನಿರ್ದಿಷ್ಟ ಸ್ಥಳದಲ್ಲಿ ಇರಿಸಲು:

```bash
export DATA_DIR="$HOME/.omniroute"
omniroute
```

## ಮಿತಿಗಳು

- Electron, Termux ನಲ್ಲಿ ಕಾರ್ಯನಿರ್ವಹಿಸುವುದಿಲ್ಲ.
- ಸಿಸ್ಟಂ ಟ್ರೇ ಅಥವಾ ಡೆಸ್ಕ್ಟಾಪ್ ಏಕೀಕರಣವಿಲ್ಲ.
- ಈ ಸೆಟಪ್ ಸರ್ವರ್ಗೆ ಮಾತ್ರ: ಬ್ರೌಸರ್ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಬಳಸಿ.
- ಸ್ಥಳೀಯ ಅವಲಂಬನೆಗಳಿಗೆ ಸ್ಥಳೀಯ ಕಂಪೈಲೇಶನ್ ಅಗತ್ಯವಾಗಬಹುದು.
- ಕಡಿಮೆ ಮೆಮೊರಿಯ Android ಸಾಧನಗಳಲ್ಲಿ ಏಕಕಾಲೀನ ವಿನಂತಿಗಳ ಸಂಖ್ಯೆಯನ್ನು ಕಡಿಮೆ ಮಾಡಬೇಕಾಗಬಹುದು.
- MITM/ಸಿಸ್ಟಂ ಪ್ರಮಾಣಪತ್ರ ವೈಶಿಷ್ಟ್ಯಗಳಿಗೆ Termux ಹೊರಗೆ Android-ಮಟ್ಟದ ಟ್ರಸ್ಟ್-ಸ್ಟೋರ್ ಕೆಲಸ ಅಗತ್ಯವಾಗಬಹುದು.

## ಸಮಸ್ಯೆ ನಿವಾರಣೆ

### ಬೆಂಬಲಿಸದ ಪ್ಲಾಟ್ಫಾರ್ಮ್: android (ಪ್ರತಿ ವಿನಂತಿಯೂ HTTP 500 ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ)

**ಲಕ್ಷಣ:** `omniroute` / `omniroute serve`, `✔ OmniRoute is running!` ಎಂದು ಮುದ್ರಿಸುತ್ತದೆ, ಆದರೆ ಪ್ರತಿಯೊಂದು ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಅಥವಾ API ವಿನಂತಿಯೂ ಸರಳವಾದ `500 Internal Server Error` ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ. `~/.omniroute/logs/application/app.log` ಖಾಲಿಯಾಗಿಯೇ ಇರುತ್ತದೆ, `APP_LOG_LEVEL=debug` ಉಪಯುಕ್ತವಾದ ಯಾವುದನ್ನೂ ಮುದ್ರಿಸುವುದಿಲ್ಲ ಮತ್ತು ಪ್ರತಿಕ್ರಿಯೆಯ ಬಾಡಿಯು ಯಾವುದೇ JSON ವಿವರಗಳಿಲ್ಲದ ಸರಳ ಪಠ್ಯವಾಗಿರುತ್ತದೆ (`Internal Server Error`).

**ಕಾರಣ:** ಕೆಲವು Termux/Node ಬಿಲ್ಡ್ಗಳು `process.platform === "android"` ಎಂದು ವರದಿ ಮಾಡುತ್ತವೆ. Next.js ನ `getCacheDirectory()` ಆ ಪ್ಲಾಟ್ಫಾರ್ಮ್ ಅನ್ನು ನಿರ್ವಹಿಸುವುದಿಲ್ಲ: ಅದಕ್ಕೆ `~/.cache` (ಅಥವಾ ಸಾಮಾನ್ಯ tmp ಡೈರೆಕ್ಟರಿ) _ಈಗಾಗಲೇ_ ಅಸ್ತಿತ್ವದಲ್ಲಿರಬೇಕು; ಇಲ್ಲದಿದ್ದರೆ, ಇನ್ಸ್ಟ್ರುಮೆಂಟೇಶನ್ ಹುಕ್ ಅನ್ನು ಲೋಡ್ ಮಾಡುವಾಗ ಈ ದೋಷದೊಂದಿಗೆ ವಿಫಲವಾಗುತ್ತದೆ:

```text
Error: An error occurred while loading instrumentation hook: Unsupported platform: android
```

ಹುಕ್ ಎಂದಿಗೂ ಲೋಡ್ ಆಗದಿರುವುದರಿಂದ, ಲಾಗಿಂಗ್ ಪ್ರಾರಂಭವಾಗುವುದೇ ಇಲ್ಲ — ಇದರಿಂದ 500 ದೋಷವು ಸಂಪೂರ್ಣವಾಗಿ ರೋಗನಿರ್ಣಯ ಮಾಡಲು ಅಸಾಧ್ಯವೆಂದು ತೋರುತ್ತದೆ. Next.js ಪ್ರಾರಂಭವಾಗುವ ಮೊದಲು OmniRoute, CLI ಎಂಟ್ರಿಪಾಯಿಂಟ್ನಲ್ಲಿ `~/.cache` ಅನ್ನು ರಚಿಸುತ್ತದೆ (ಮತ್ತು ಹೊಂದಿಸದಿದ್ದಾಗ `XDG_CACHE_HOME` ಅನ್ನು ಹೊಂದಿಸುತ್ತದೆ), ಹೀಗಾಗಿ ಈ ಪರಿಶೀಲನೆಯು Android/Termux ನಲ್ಲಿ ಯಶಸ್ವಿಯಾಗುತ್ತದೆ.

**ಬೆಂಬಲಿತ ಪರಿಹಾರ (ಪ್ಯಾಕೇಜ್ ಪ್ಯಾಚಿಂಗ್ ಇಲ್ಲದೆ):**

```bash
mkdir -p ~/.cache
omniroute serve
```

ಪ್ರಸ್ತುತ OmniRoute ಬಿಲ್ಡ್ಗಳಲ್ಲಿ CLI ಇದನ್ನು Android/Termux ನಲ್ಲಿ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಮಾಡುತ್ತದೆ — ಹೊಸ `npx -y omniroute@latest` / ಜಾಗತಿಕ ಸ್ಥಾಪನೆಗೆ ಹಸ್ತಚಾಲಿತ ಹಂತವು ಅಗತ್ಯವಿರಬಾರದು. ಅಪ್ಗ್ರೇಡ್ ಮಾಡಿದ ನಂತರವೂ ನಿಮಗೆ ದೋಷ ಕಾಣಿಸಿದರೆ, ಮೇಲಿನಂತೆ ಒಮ್ಮೆ `~/.cache` ಅನ್ನು ರಚಿಸಿ ಮತ್ತು ಮರುಪ್ರಾರಂಭಿಸಿ.

`process.platform = "linux"` ಅನ್ನು ಬಲವಂತಪಡಿಸಲು `dist/server.js` ಅನ್ನು ಪ್ಯಾಚ್ **ಮಾಡಬೇಡಿ**. ಆ ರೀತಿಯ ಪ್ಯಾಕೇಜ್ ಪ್ಯಾಚ್ ಪ್ರತಿ ಮರುಸ್ಥಾಪನೆ/ಅಪ್ಗ್ರೇಡ್ನಲ್ಲಿ ಮೇಲ್ಬರೆಯಲ್ಪಡುತ್ತದೆ ಮತ್ತು ಕ್ಯಾಶ್ ಡೈರೆಕ್ಟರಿ ಅಸ್ತಿತ್ವದಲ್ಲಿದ್ದ ನಂತರ ಅದು ಅನಗತ್ಯವಾಗುತ್ತದೆ.

### better-sqlite3 ಬಿಲ್ಡ್ ದೋಷಗಳು

Termux ಬಿಲ್ಡ್ ಟೂಲ್ಚೈನ್ ಅನ್ನು ಸ್ಥಾಪಿಸಿ:

pkg install nodejs python build-essential
```

ನಂತರ ಮತ್ತೆ ಚಲಾಯಿಸಿ:

npx -y omniroute@latest
```

### ಪೋರ್ಟ್ ಈಗಾಗಲೇ ಬಳಕೆಯಲ್ಲಿದೆ

ಪೂರ್ವನಿಯೋಜಿತ ಪೋರ್ಟ್ನಲ್ಲಿ ಯಾವುದನ್ನು ಆಲಿಸಲಾಗುತ್ತಿದೆ ಎಂಬುದನ್ನು ಪರಿಶೀಲಿಸಿ:

```bash
ss -ltnp | grep 20128
```

ಹಳೆಯ ಪ್ರಕ್ರಿಯೆಯನ್ನು ನಿಲ್ಲಿಸಿ:

```bash
pkill -f omniroute
```

### ಇನ್ನೊಂದು ಸಾಧನದಿಂದ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ತಲುಪಲು ಸಾಧ್ಯವಾಗುತ್ತಿಲ್ಲ

ಎರಡೂ ಸಾಧನಗಳು ಒಂದೇ WiFi ನೆಟ್ವರ್ಕ್ನಲ್ಲಿವೆ ಎಂಬುದನ್ನು ಪರಿಶೀಲಿಸಿ, ನಂತರ Termux ನಿಂದ ಪರೀಕ್ಷಿಸಿ:

```bash
curl http://localhost:20128
```

ಸ್ಥಳೀಯ ಪ್ರವೇಶವು ಕಾರ್ಯನಿರ್ವಹಿಸಿದರೂ LAN ಪ್ರವೇಶವು ಕಾರ್ಯನಿರ್ವಹಿಸದಿದ್ದರೆ, Android ಹಾಟ್ಸ್ಪಾಟ್/WiFi ಐಸೊಲೇಶನ್ ಮತ್ತು ಫೋನ್ನಲ್ಲಿರುವ ಯಾವುದೇ ಫೈರ್ವಾಲ್ ಅಥವಾ VPN ಪ್ರೊಫೈಲ್ ಅನ್ನು ಪರಿಶೀಲಿಸಿ.
