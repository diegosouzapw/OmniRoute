## 1. Antigravity ಮತ್ತು Antigravity CLI (agy) ನಡುವಿನ ವ್ಯತ್ಯಾಸ

ಎರಡೂ ಪೂರೈಕೆದಾರರು **ಒಂದೇ Google ಬ್ಯಾಕೆಂಡ್** ಅನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತಾರೆ — ಒಂದೇ OAuth ಕ್ಲೈಂಟ್, ಟೋಕನ್ ನವೀಕರಣ, ಎಂಡ್ಪಾಯಿಂಟ್ಗಳು ಮತ್ತು Google ಖಾತೆಗಳು. ನಿಮಗೆ ಯಾವ ಮಾದರಿಗಳು ಕಾಣಿಸುತ್ತವೆ ಎಂಬುದೇ ವ್ಯತ್ಯಾಸ.

> Google ನ ಅಧಿಕೃತ ಹೋಲಿಕೆಗಾಗಿ [Antigravity CLI ಪ್ರಕಟಣೆ](https://antigravity.google/blog/introducing-google-antigravity-cli) ನೋಡಿ.

| ಅಂಶ                       | `antigravity` (IDE)                                | `agy` (CLI)                                           |
| ------------------------- | -------------------------------------------------- | ----------------------------------------------------- |
| **Google ಉತ್ಪನ್ನ**        | Antigravity 2.0 / Antigravity IDE                  | Antigravity CLI                                       |
| **ಬ್ಯಾಕೆಂಡ್**             | ಅದೇ Google Cloud Code API                          | ಅದೇ Google Cloud Code API                             |
| **OAuth / ಟೋಕನ್**         | ಅದೇ ಕ್ಲೈಂಟ್, ಅದೇ ನವೀಕರಣ                            | ಅದೇ ಕ್ಲೈಂಟ್, ಅದೇ ನವೀಕರಣ                               |
| **ಮಾದರಿ ಕ್ಯಾಟಲಾಗ್**       | ಸ್ಥಿರವಾಗಿ ಆಯ್ದ ಪಟ್ಟಿ (OmniRoute hardcoded)         | `:fetchAvailableModels` ಮೂಲಕ Google ನಿಂದ ನೇರ ಪರಿಶೀಲನೆ |
| **Claude ಮಾದರಿಗಳು**       | Sonnet 4.6, Opus 4.6 (ಪ್ರತಿಯೊಂದರಲ್ಲೂ 4 ರೂಪಾಂತರಗಳು) | Sonnet 4.6, Opus 4.6 (ಪ್ರತಿಯೊಂದರಲ್ಲೂ 4 ರೂಪಾಂತರಗಳು)    |
| **Gemini ಹೆಸರಿಸುವಿಕೆ**    | ಸ್ಪಷ್ಟ ಲೇಬಲ್ಗಳು (Low/Medium/High)                  | ಅಪ್ಸ್ಟ್ರೀಮ್ IDಗಳು (extra-low/low/agent)               |
| **ಹೆಚ್ಚುವರಿ ಮಾದರಿಗಳು**    | `gpt-oss-120b-medium`                              | Google ನಿಂದ ಹೆಚ್ಚುವರಿ ಮಾದರಿಗಳನ್ನು ಒಳಗೊಂಡಿರಬಹುದು       |
| **ಡೀಫಾಲ್ಟ್ ಬಳಕೆಯ ಸಂದರ್ಭ** | IDE ಏಕೀಕರಣ (VS Code, JetBrains)                    | CLI / API ಪ್ರವೇಶ                                      |
| **ಕೋಟಾ**                  | agy ಜೊತೆಗೆ ಹಂಚಿಕೊಳ್ಳಲಾಗಿದೆ (ಅದೇ Google ಖಾತೆ)       | antigravity ಜೊತೆಗೆ ಹಂಚಿಕೊಳ್ಳಲಾಗಿದೆ (ಅದೇ Google ಖಾತೆ)  |

**ಲಭ್ಯವಿರುವ ಮಾದರಿಗಳು (ಪ್ರಯೋಗದ ಮೂಲಕ ಪರಿಶೀಲಿಸಲಾಗಿದೆ, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (ವಿವಿಧ ಚಿಂತನಾ ಮಟ್ಟಗಳು)
- Claude: Sonnet 4.6, Opus 4.6 (ಪ್ರತಿಯೊಂದಕ್ಕೂ default/low/medium/high ರೂಪಾಂತರಗಳು)
- ಇತರೆ: GPT-OSS 120B Medium
- **Claude Sonnet 5 ಲಭ್ಯವಿಲ್ಲ** — ಕೇವಲ 4.6 ರೂಪಾಂತರಗಳು ಬೆಂಬಲಿತವಾಗಿವೆ

**ಮಾದರಿ ಕ್ಯಾಟಲಾಗ್ ಏಕೆ ಭಿನ್ನವಾಗಿದೆ**: Google ನ ಅಧಿಕೃತ ಬ್ಲಾಗ್ ಪ್ರಕಾರ, Google ನ CLI ಅನ್ನು "ವೇಗ ಮತ್ತು ಕಡಿಮೆ ಓವರ್ಹೆಡ್ಗಾಗಿ ಆಪ್ಟಿಮೈಸ್ ಮಾಡಲಾಗಿದೆ" ಮತ್ತು "Gemini ಮಾದರಿಗಳೊಂದಿಗೆ ಸಹ-ಆಪ್ಟಿಮೈಸ್ ಮಾಡಲಾಗಿದೆ." Web/IDE ಉತ್ಪನ್ನವನ್ನು "ಸಮಗ್ರತೆಗಾಗಿ ಆಪ್ಟಿಮೈಸ್ ಮಾಡಲಾಗಿದೆ." CLI ಮಾದರಿಗಳನ್ನು ಕ್ರಿಯಾತ್ಮಕವಾಗಿ ಪತ್ತೆಹಚ್ಚಲು `:fetchAvailableModels` ಅನ್ನು ಬಳಸುತ್ತದೆ, ಆದರೆ IDE ಸ್ಥಿರವಾಗಿ ಆಯ್ದ ಪಟ್ಟಿಯನ್ನು ಬಳಸುತ್ತದೆ.

**ಪ್ರಾಯೋಗಿಕವಾಗಿ**: Gemini ಮಾದರಿಗಳಿಗೆ `agy/` ಪೂರ್ವಪ್ರತ್ಯಯವನ್ನು ಬಳಸಿ (ಉದಾ. `agy/gemini-3.7-flash-high`). ಸ್ಥಿರವಾಗಿ ಆಯ್ದ ಪಟ್ಟಿಗಾಗಿ `antigravity/` ಬಳಸಿ. ಎರಡೂ ಅದೇ Google ಬ್ಯಾಕೆಂಡ್ ಅನ್ನು ಬಳಸುತ್ತವೆ, ಆದರೆ ವಿಭಿನ್ನ ಮಾದರಿ ಹೆಸರಿಸುವಿಕೆಯನ್ನು ಒದಗಿಸುತ್ತವೆ. ಕೋಟಾವನ್ನು ಹಂಚಿಕೊಳ್ಳಲಾಗುತ್ತದೆ — ಯಾವುದೇ ಪೂರೈಕೆದಾರರನ್ನು ಬಳಸಿದರೂ ಅದು ಅದೇ Google ಖಾತೆಯ ಮಿತಿಗಳಲ್ಲಿ ಲೆಕ್ಕವಾಗುತ್ತದೆ.

## 2. Google One AI Pro: ಕೋಟಾ ವ್ಯವಸ್ಥೆ

> ಅಧಿಕೃತ ಕೋಟಾ ವಿವರಗಳಿಗಾಗಿ [Antigravity Docs: Plans](https://antigravity.google/docs/plans) ಮತ್ತು ಇತ್ತೀಚಿನ ಬೆಲೆ ನವೀಕರಣಗಳಿಗಾಗಿ [Changes to Antigravity Plans](https://antigravity.google/blog/changes-to-antigravity-plans) ನೋಡಿ.

Google Antigravity ಸಂದೇಶಗಳ ಸಂಖ್ಯೆಯ ಬದಲಿಗೆ "ಪೂರ್ಣಗೊಳಿಸಿದ ಕೆಲಸ" (ಗಣನಾತ್ಮಕ ತೂಕ) ಆಧಾರಿತ **ದ್ವಿ-ಪದರ ಕೋಟಾ**ವನ್ನು ಬಳಸುತ್ತದೆ.

### ಎರಡು ಪದರಗಳು

| ಪದರ                   | ಅದು ಏನು                            | ನವೀಕರಣ ಚಕ್ರ                                                                                              |
| --------------------- | ---------------------------------- | -------------------------------------------------------------------------------------------------------- |
| **5-ಗಂಟೆಯ ಸ್ಪ್ರಿಂಟ್** | "ಪೂರ್ಣಗೊಳಿಸಿದ ಕೆಲಸ"ದ ತಕ್ಷಣದ ಸಂಗ್ರಹ | ಸೆಷನ್ನಲ್ಲಿನ ಮೊದಲ ವಿನಂತಿಯ 5 ಗಂಟೆಗಳ ನಂತರ ಮರುಹೊಂದಿಸಲಾಗುತ್ತದೆ                                                |
| **7-ದಿನಗಳ ಮೂಲಮಿತಿ**   | ವಾರದ ಕಟ್ಟುನಿಟ್ಟಿನ ಗರಿಷ್ಠ ಮಿತಿ      | ಮಿತಿ ತಲುಪಿದರೆ 5-ಗಂಟೆಯ ನವೀಕರಣವನ್ನು ಅತಿಕ್ರಮಿಸುತ್ತದೆ; ಮುಂದಿನ 7-ದಿನಗಳ ಅವಧಿಯವರೆಗೆ ಪ್ರವೇಶವನ್ನು ನಿರ್ಬಂಧಿಸುತ್ತದೆ |

**"ಪೂರ್ಣಗೊಳಿಸಿದ ಕೆಲಸ"ವನ್ನು ಹೇಗೆ ಲೆಕ್ಕಹಾಕಲಾಗುತ್ತದೆ**: ಏಜೆಂಟ್-ಕೇಂದ್ರಿತ ಕಾರ್ಯಗಳು (ಉದಾ. "ಈ ಸಂಪೂರ್ಣ ರೆಪೊಸಿಟರಿಯನ್ನು ರಿಫ್ಯಾಕ್ಟರ್ ಮಾಡಿ") ಸರಳ ಕಾರ್ಯಗಳಿಗಿಂತ (ಉದಾ. "ಈ ಫಂಕ್ಷನ್ ಅನ್ನು ಸರಿಪಡಿಸಿ") ಹೆಚ್ಚು ವೇಗವಾಗಿ ಕೋಟಾವನ್ನು ಬಳಸುತ್ತವೆ. ಬಳಕೆಯನ್ನು ತೋರಿಸುವ ಯಾವುದೇ ನೈಜ-ಸಮಯದ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಇಲ್ಲ.

### Gemini ಮತ್ತು Gemini ಅಲ್ಲದ ಮಾಡೆಲ್ಗಳು

- **Gemini ಮಾಡೆಲ್ಗಳು** (Flash + Pro): API ಬೆಲೆ ಆಧಾರವಾಗಿ ಕಡಿಮೆಯಾಗುವ ಒಂದೇ ದರ ಮಿತಿಯನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತವೆ. Flash, Pro ಗಿಂತ 8x ಅಗ್ಗವಾಗಿದ್ದರೆ, ನಿಮಗೆ 8x ಹೆಚ್ಚು Flash ಟೋಕನ್ಗಳು ಸಿಗುತ್ತವೆ.
- **Gemini ಅಲ್ಲದ ಮಾಡೆಲ್ಗಳು** (Claude, GPT-OSS): **ಪ್ರತ್ಯೇಕ** ದರ ಮಿತಿಗಳನ್ನು ಹೊಂದಿರುತ್ತವೆ. Gemini ಪ್ರವೇಶ ನಿರ್ಬಂಧಿತವಾಗಿದ್ದರೂ ಇವು ಲಭ್ಯವಿರಬಹುದು.

### AI ಕ್ರೆಡಿಟ್ಗಳು (ಮಿತಿ ಮೀರಿದ ಬಳಕೆ)

> ಕ್ರೆಡಿಟ್ಗಳು ಹೇಗೆ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತವೆ ಎಂಬುದಕ್ಕಾಗಿ [Google One AI credits](https://support.google.com/googleone/answer/14534406) ನೋಡಿ.

ಮೂಲ ಕೋಟಾ ಖಾಲಿಯಾದಾಗ:

- **ಎಂದಿಗೂ ಬೇಡ**: ಕೋಟಾ ನವೀಕರಣಗೊಳ್ಳುವವರೆಗೆ ಕಾಯಿರಿ; "Baseline model quota reached" ಎಂದು ತೋರಿಸುತ್ತದೆ
- **ಯಾವಾಗಲೂ**: AI ಕ್ರೆಡಿಟ್ಗಳನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಬಳಸಿ; ಮೂಲ ಕೋಟಾ ನವೀಕರಣಗೊಂಡಾಗ ಮತ್ತೆ ಅದಕ್ಕೆ ಬದಲಾಗುತ್ತದೆ

ಕ್ರೆಡಿಟ್ಗಳನ್ನು ಪ್ರತ್ಯೇಕವಾಗಿ ಖರೀದಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಪ್ರಮಾಣಿತ API ಬೆಲೆಯಂತೆ ಕಡಿತಗೊಳಿಸಲಾಗುತ್ತದೆ.

### ಪ್ರಮುಖ ವಿವರಗಳು

- ಕೋಟಾವು **ಖಾತೆ-ಮಟ್ಟದಲ್ಲಿ ಹಂಚಿಕೆಯಾಗಿರುತ್ತದೆ** — Antigravity IDE, CLI ಮತ್ತು OmniRouteನಲ್ಲಿ ಬಳಸುವ ಒಂದೇ Google ಖಾತೆಯು ಒಂದೇ ಕೋಟಾ ಸಂಗ್ರಹವನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತದೆ
- ಪ್ರತಿಯೊಂದು Google ಖಾತೆಯೂ ತನ್ನದೇ ಆದ ಸ್ವತಂತ್ರ ಕೋಟಾವನ್ನು ಹೊಂದಿರುತ್ತದೆ — ಹಲವು ಖಾತೆಗಳು = ಹಲವು ಕೋಟಾ ಸಂಗ್ರಹಗಳು
- ವಾರದ ಮೂಲಮಿತಿಯನ್ನು ತಲುಪಿದಾಗ 5-ಗಂಟೆಗಳ ಮರುಹೊಂದಿಸುವಿಕೆಯ ಬದಲಿಗೆ **7-ದಿನಗಳ ಪ್ರವೇಶ ನಿರ್ಬಂಧಗಳು** ಉಂಟಾಗಿವೆ ಎಂದು AI Pro ಬಳಕೆದಾರರು ವರದಿ ಮಾಡಿದ್ದಾರೆ (ಹೆಚ್ಚಿನ ಬೇಡಿಕೆಯನ್ನು ನಿರ್ವಹಿಸಲು ಇದು ಉದ್ದೇಶಪೂರ್ವಕ ವಿನ್ಯಾಸವೆಂದು Google ದೃಢಪಡಿಸಿದೆ)

**ನಿಮ್ಮ ಖಾತೆಯ ಕೋಟಾ ಖಾಲಿಯಾದಾಗ**: ಕಾಂಬೊ ರೂಟ್ನಲ್ಲಿ ಲಭ್ಯವಿರುವ ಮುಂದಿನ ಖಾತೆಯೊಂದಿಗೆ OmniRoute ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಮರುಪ್ರಯತ್ನಿಸುತ್ತದೆ. ಯಾವುದೇ ಹಸ್ತಚಾಲಿತ ಹಸ್ತಕ್ಷೇಪದ ಅಗತ್ಯವಿಲ್ಲ.

## 3. projectId ಅನ್ನು ಪಡೆಯುವುದು ಹೇಗೆ

ಪ್ರತಿ antigravity/agy ಸಂಪರ್ಕಕ್ಕೂ Google Cloud Code `projectId` ಅಗತ್ಯವಿದೆ. ಅದು ಇಲ್ಲದಿದ್ದರೆ, `/v1internal:models` ಎಂಡ್ಪಾಯಿಂಟ್ 404 ಅನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ.

### ವಿಧಾನ A: ಸ್ವಯಂಚಾಲಿತ (ಶಿಫಾರಸು ಮಾಡಲಾಗಿದೆ)

OmniRoute ಇದನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ನಿರ್ವಹಿಸುತ್ತದೆ. Dashboard OAuth ಮೂಲಕ ನೀವು ಹೊಸ Google ಖಾತೆಯನ್ನು ಸೇರಿಸಿದಾಗ:

1. OmniRoute ಟೋಕನ್ ಅನ್ನು ನವೀಕರಿಸುತ್ತದೆ
2. projectId ಅನ್ನು ಪತ್ತೆಹಚ್ಚಲು `loadCodeAssist` ಅನ್ನು ಕರೆ ಮಾಡುತ್ತದೆ
3. ಯಾವುದೇ ಪ್ರಾಜೆಕ್ಟ್ ಅಸ್ತಿತ್ವದಲ್ಲಿಲ್ಲದಿದ್ದರೆ, ಒಂದನ್ನು ರಚಿಸಲು `onboardUser` ಅನ್ನು ಕರೆ ಮಾಡುತ್ತದೆ
4. ಹೊಸದಾಗಿ ರಚಿಸಲಾದ projectId ಅನ್ನು ಪಡೆಯಲು `loadCodeAssist` ಅನ್ನು ಮರುಪ್ರಯತ್ನಿಸುತ್ತದೆ
5. ಅದನ್ನು ಡೇಟಾಬೇಸ್ಗೆ ಉಳಿಸುತ್ತದೆ

**ಇದು ಹೆಚ್ಚಿನ ಖಾತೆಗಳಿಗೆ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ** — ಯಾವುದೇ ಹಸ್ತಚಾಲಿತ ಹಂತಗಳ ಅಗತ್ಯವಿಲ್ಲ.

### ವಿಧಾನ B: agy CLI ಮೂಲಕ ಹಸ್ತಚಾಲಿತವಾಗಿ

ಸ್ವಯಂಚಾಲಿತ ಪತ್ತೆ ವಿಫಲವಾದರೆ (ಇದು ಯಾವಾಗ ಸಂಭವಿಸುತ್ತದೆ ಎಂಬುದಕ್ಕಾಗಿ ವಿಭಾಗ 5 ನೋಡಿ):

```bash

npm install -g @anthropic-ai/agy

# ಇದು Cloud Code ನೋಂದಣಿಯನ್ನು ಪ್ರಚೋದಿಸುತ್ತದೆ ಮತ್ತು projectId ಅನ್ನು ನಿಯೋಜಿಸುತ್ತದೆ
```

## 4. OAuth ಮರುನಿರ್ದೇಶನ URI

### ಸಮಸ್ಯೆ

Google OAuth ಗೆ ಮಾನ್ಯವಾದ ಮರುನಿರ್ದೇಶನ URI ಅಗತ್ಯವಿದೆ. OmniRoute ನ ಡೀಫಾಲ್ಟ್ `http://127.0.0.1:20128/callback` (ಲೂಪ್ಬ್ಯಾಕ್) ಅನ್ನು ಬಳಸುತ್ತದೆ. ಇದು ಸ್ಥಳೀಯ ಬಿಲ್ಡ್ಗಳಿಗೆ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ, ಆದರೆ **ದೂರಸ್ಥ ನಿಯೋಜನೆಗಳಲ್ಲಿ ವಿಫಲವಾಗುತ್ತದೆ** (ಉದಾ., LAN IP ಮೂಲಕ ಪ್ರವೇಶಿಸುವ ಸರ್ವರ್).

ಈ ಕೆಳಗಿನ ಸಂದರ್ಭಗಳಲ್ಲಿ Google ಮರುನಿರ್ದೇಶನ URI ಗಳನ್ನು ತಿರಸ್ಕರಿಸುತ್ತದೆ:

- IP ವಿಳಾಸಗಳನ್ನು ಬಳಸಿದರೆ (`.com`, `.org` ಮುಂತಾದವುಗಳಲ್ಲಿ ಅಂತ್ಯಗೊಳ್ಳುವ ಡೊಮೇನ್ ಆಗಿರಬೇಕು)
- OAuth ಕ್ಲೈಂಟ್ ಸಂರಚನೆಯಲ್ಲಿ ನೋಂದಾಯಿಸಲಾದ ಮರುನಿರ್ದೇಶನ URI ಗಳಿಗೆ ಹೊಂದಿಕೆಯಾಗದಿದ್ದರೆ

### ಪರಿಹಾರ

**ಆಯ್ಕೆ A: ಅಂತರ್ನಿರ್ಮಿತ OAuth ಹರಿವನ್ನು ಬಳಸಿ (ಡೀಫಾಲ್ಟ್)**

- ನೀವು `localhost` ಅಥವಾ `127.0.0.1` ನಿಂದ OmniRoute ಅನ್ನು ಪ್ರವೇಶಿಸಿದಾಗ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ
- ಯಾವುದೇ ಸಂರಚನೆ ಅಗತ್ಯವಿಲ್ಲ

**ಆಯ್ಕೆ B: ಕಸ್ಟಮ್ OAuth ರುಜುವಾತುಗಳು**

- ನಿಮ್ಮ ಪರಿಸರದಲ್ಲಿ `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` ಅನ್ನು ಹೊಂದಿಸಿ
- ನಿಮ್ಮದೇ Google OAuth ರುಜುವಾತುಗಳನ್ನು ಒದಗಿಸಿ:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Google Cloud Console ನಲ್ಲಿ `https://your-domain.com/callback` ಅನ್ನು ಅಧಿಕೃತ ಮರುನಿರ್ದೇಶನ URI ಆಗಿ ನೋಂದಾಯಿಸಿ

**ಆಯ್ಕೆ C: ಆರಂಭಿಕ ಲಾಗಿನ್ಗಾಗಿ agy CLI ಬಳಸಿ**

- OmniRoute ಅನ್ನು ಪ್ರವೇಶಿಸಲಿರುವ ಯಂತ್ರದಲ್ಲಿ `agy login` ಅನ್ನು ಚಲಾಯಿಸಿ
- OAuth ಹರಿವು ಸ್ಥಳೀಯವಾಗಿ ಪೂರ್ಣಗೊಳ್ಳುತ್ತದೆ ಮತ್ತು ಟೋಕನ್ಗಳನ್ನು ಸಂಗ್ರಹಿಸಲಾಗುತ್ತದೆ
- ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಮೂಲಕ ಸಂಪರ್ಕವನ್ನು OmniRoute ಗೆ ಆಮದು ಮಾಡಿ

### ಮಿತಿಗಳು

- ಕಸ್ಟಮ್ OAuth ರುಜುವಾತುಗಳಿಗೆ ಡೊಮೇನ್ ಹೆಸರು ಅಗತ್ಯವಿದೆ (Google ಮರುನಿರ್ದೇಶನ URI ಗಳಾಗಿ IP ವಿಳಾಸಗಳನ್ನು ಸ್ವೀಕರಿಸುವುದಿಲ್ಲ)
- ನಿಮ್ಮ ಬಳಿ ಡೊಮೇನ್ ಇಲ್ಲದಿದ್ದರೆ, ಬದಲಿಗೆ ಆಯ್ಕೆ A ಅಥವಾ C ಬಳಸಿ

## 5. ಸಮಸ್ಯೆ ನಿವಾರಣೆ: ಸ್ವಯಂಚಾಲಿತ ಸೆಟಪ್ ವಿಫಲವಾದಾಗ

ಬಹುತೇಕ ಖಾತೆಗಳಿಗೆ `projectId` ಪತ್ತೆಹಚ್ಚುವಿಕೆ ಮತ್ತು ಆನ್ಬೋರ್ಡಿಂಗ್ ಅನ್ನು OmniRoute ಸ್ವಯಂಚಾಲಿತವಾಗಿ ನಿರ್ವಹಿಸುತ್ತದೆ. ಅದು ವಿಫಲವಾದಾಗ, ಮೂಲ ಕಾರಣವು ಸಾಮಾನ್ಯವಾಗಿ ಈ ಕೆಳಗಿನವುಗಳಲ್ಲಿ ಒಂದಾಗಿರುತ್ತದೆ:

### ಖಾತೆಯ ಪ್ರದೇಶವನ್ನು ನಿರ್ಬಂಧಿಸಲಾಗಿದೆ

**ಲಕ್ಷಣ**: `agy login` "ಅರ್ಹತಾ ಪರಿಶೀಲನೆ ವಿಫಲವಾಗಿದೆ: Antigravity ಪ್ರಸ್ತುತ ನಿಮ್ಮ ಸ್ಥಳದಲ್ಲಿ ಲಭ್ಯವಿಲ್ಲದ ಕಾರಣ, ನಿಮ್ಮ ಪ್ರಸ್ತುತ ಖಾತೆಯು ಅದಕ್ಕೆ ಅರ್ಹವಾಗಿಲ್ಲ." ಎಂದು ತೋರಿಸುತ್ತದೆ.

**ಮೂಲ ಕಾರಣ**: ನೋಂದಣಿ ಸಮಯದಲ್ಲಿ Google ಖಾತೆಗಳಿಗೆ ಬ್ಯಾಕೆಂಡ್ನ "ದೇಶದ ಸಂಯೋಜನೆ" ಕ್ಷೇತ್ರವನ್ನು ಹೊಂದಿಸಲಾಗುತ್ತದೆ. ವೆಬ್ Gemini ನಿಮ್ಮ ಪ್ರಸ್ತುತ IP ಅನ್ನು ಮಾತ್ರ ಪರಿಶೀಲಿಸುವುದಕ್ಕೆ ವಿರುದ್ಧವಾಗಿ, agy CLI ಮತ್ತು Cloud Code API ಈ ಕ್ಷೇತ್ರವನ್ನು ಕಟ್ಟುನಿಟ್ಟಾಗಿ ಪರಿಶೀಲಿಸುತ್ತವೆ.

> ನಿಮ್ಮ ಖಾತೆಗೆ ಸಂಯೋಜಿತವಾಗಿರುವ ಪ್ರದೇಶವನ್ನು ಪರಿಶೀಲಿಸಲು ಅಥವಾ ಬದಲಾಯಿಸಲು, [Google Country Association Form](https://policies.google.com/country-association-form) ಗೆ ಭೇಟಿ ನೀಡಿ.

**ವೆಬ್ Gemini ಕಾರ್ಯನಿರ್ವಹಿಸಿದರೂ agy ಏಕೆ ಕಾರ್ಯನಿರ್ವಹಿಸುವುದಿಲ್ಲ**:

- ವೆಬ್ Gemini / Google One: ಪ್ರಸ್ತುತ IP ಅನ್ನು ಮಾತ್ರ ಪರಿಶೀಲಿಸುತ್ತದೆ (ಪ್ರಾಕ್ಸಿ ಮೂಲಕ ಸಾಧ್ಯವಾಗುತ್ತದೆ)
- agy CLI / Cloud Code API: ಬ್ಯಾಕೆಂಡ್ನ ದೇಶದ ಸಂಯೋಜನೆ ಕ್ಷೇತ್ರವನ್ನು ಓದುತ್ತದೆ (ಪ್ರಾಕ್ಸಿಯಿಂದ ಪ್ರಯೋಜನವಿಲ್ಲ)

**ಪರಿಹಾರ**:

1. US IP ಬಳಸುತ್ತಿರುವಾಗ [Google Country Association Form](https://policies.google.com/country-association-form) ಗೆ ಭೇಟಿ ನೀಡಿ
2. ಪ್ರದೇಶ ಬದಲಾವಣೆಯ ವಿನಂತಿಯನ್ನು ಸಲ್ಲಿಸಿ ("ನಾನು ಬೇರೆ ದೇಶದಲ್ಲಿ ವಾಸಿಸುತ್ತೇನೆ" ಎಂಬುದನ್ನು ಆಯ್ಕೆಮಾಡಿ)
3. Google ಪ್ರಕ್ರಿಯೆ ಪೂರ್ಣಗೊಳಿಸಿ ಇಮೇಲ್ ಅಧಿಸೂಚನೆ ಕಳುಹಿಸಲು 1-24 ಗಂಟೆಗಳವರೆಗೆ ಕಾಯಿರಿ
4. ನಂತರ `agy login` ಯಶಸ್ವಿಯಾಗಬೇಕು

### ಖಾತೆಯಲ್ಲಿ Cloud Code ಪ್ರಾಜೆಕ್ಟ್ ಇಲ್ಲ

**ಲಕ್ಷಣ**: ಲಾಗ್ಗಳು `loadCodeAssist returned no project id` ಮತ್ತು `onboardUser failed (400)` ಅನ್ನು ತೋರಿಸುತ್ತವೆ.

**ಮೂಲ ಕಾರಣ**: ಖಾತೆಯನ್ನು Google Cloud Code ನಲ್ಲಿ ಎಂದಿಗೂ ನೋಂದಾಯಿಸಲಾಗಿಲ್ಲ ಮತ್ತು ಸ್ವಯಂಚಾಲಿತ ಆನ್ಬೋರ್ಡಿಂಗ್ ವಿಫಲವಾಗಿದೆ.

**ಪರಿಹಾರ**: Cloud Code ನೋಂದಣಿಯನ್ನು ಪ್ರಚೋದಿಸಲು `agy login` ಅನ್ನು ಹಸ್ತಚಾಲಿತವಾಗಿ ಚಲಾಯಿಸಿ, ನಂತರ OmniRoute ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿ ಟೋಕನ್ ಅನ್ನು ರಿಫ್ರೆಶ್ ಮಾಡಿ.

### ಟೋಕನ್ನ ಅವಧಿ ಮುಗಿದಿದೆ ಅಥವಾ ಅದನ್ನು ಹಿಂತೆಗೆದುಕೊಳ್ಳಲಾಗಿದೆ

**ಲಕ್ಷಣ**: ಲಾಗ್ಗಳಲ್ಲಿ 401 ದೋಷಗಳು ಅಥವಾ "ಟೋಕನ್ನ ಅವಧಿ ಮುಗಿದಿದೆ" ಎಂಬ ಸಂದೇಶಗಳು ಕಾಣಿಸುತ್ತವೆ.

**ಪರಿಹಾರ**: ಡ್ಯಾಶ್ಬೋರ್ಡ್ → ಪೂರೈಕೆದಾರರು → agy → ರಿಫ್ರೆಶ್ ಐಕಾನ್ ಕ್ಲಿಕ್ ಮಾಡಿ ಎಂಬ ಮಾರ್ಗದಲ್ಲಿ ಟೋಕನ್ ಅನ್ನು ರಿಫ್ರೆಶ್ ಮಾಡಿ. ರಿಫ್ರೆಶ್ ಟೋಕನ್ ಅನ್ನೇ ಹಿಂತೆಗೆದುಕೊಳ್ಳಲಾಗಿದ್ದರೆ, OAuth ಮೂಲಕ ನೀವು ಮತ್ತೆ ದೃಢೀಕರಿಸಬೇಕಾಗುತ್ತದೆ.
