## ಇದು ಏನು (ಮತ್ತು ಏನಲ್ಲ)

OmniRoute ಟೋಕನ್ಗಳ ಸಂಖ್ಯೆಯನ್ನು ಮಾದರಿಯ ಬೆಲೆ ದರಗಳಿಂದ ಗುಣಿಸುವ ಮೂಲಕ ಪ್ರತಿ completionಗೆ
ಪ್ರತಿ-ವಿನಂತಿಯ USD ವೆಚ್ಚವನ್ನು ನಿಗದಿಪಡಿಸುತ್ತದೆ. ಈ ಸಂಖ್ಯೆಗಳು **ವೆಚ್ಚಗಳು** ಡ್ಯಾಶ್ಬೋರ್ಡ್,
`omniroute cost` / `omniroute usage` CLI, CSV/JSON ರಫ್ತುಗಳು ಮತ್ತು ಪ್ರತಿ-API-key ಬಜೆಟ್ಗಳಿಗೆ
ಆಧಾರವಾಗಿವೆ.

> **ಡ್ಯಾಶ್ಬೋರ್ಡ್ನ "ವೆಚ್ಚ" ಒಂದು ಉಳಿತಾಯ ಟ್ರ್ಯಾಕರ್, ಬಿಲ್ ಅಲ್ಲ.** OmniRoute ನಿಮಗೆ ಎಂದಿಗೂ
> ಶುಲ್ಕ ವಿಧಿಸುವುದಿಲ್ಲ — ನೀವು ಈಗಾಗಲೇ ಸಂಪರ್ಕಿಸಿರುವ ಪೂರೈಕೆದಾರರಿಗೆ (ನಿಮ್ಮ ಸ್ವಂತ
> ಚಂದಾದಾರಿಕೆಗಳು, ಉಚಿತ ಶ್ರೇಣಿಗಳು ಮತ್ತು API ಕೀಲಿಗಳು) ಅದು ನಿಮ್ಮ ವಿನಂತಿಗಳನ್ನು ರೂಟ್ ಮಾಡುತ್ತದೆ.
> ಸಂಪೂರ್ಣವಾಗಿ ಉಚಿತ ಮಾದರಿಗಳಲ್ಲಿ ಸಂಚಿತವಾದ "$290 ಒಟ್ಟು ವೆಚ್ಚ" ಎಂದರೆ, ಪಾವತಿಸಬೇಕಾದ API ಒಂದಕ್ಕೆ
> ನೀವು ಸರಿಸುಮಾರು **$290 ಪಾವತಿಸಿಲ್ಲ** ಎಂದರ್ಥ. ಈ ಅಂಕಿಯು ಅದೇ ಟ್ರಾಫಿಕ್ಗೆ ಪ್ರಮಾಣಿತ ಪಟ್ಟಿ
> ಬೆಲೆಗಳ ಪ್ರಕಾರ ಎಷ್ಟು ವೆಚ್ಚವಾಗುತ್ತಿತ್ತು ಎಂಬುದರ _ಅಂದಾಜು_ ಆಗಿದೆ; ಇದರಿಂದ ನಿಮ್ಮ ಬಳಕೆ ಎಲ್ಲಿ
> ಕೇಂದ್ರೀಕೃತವಾಗಿದೆ ಮತ್ತು ಕಡಿಮೆ-ವೆಚ್ಚದ/ಉಚಿತ ಪೂರೈಕೆದಾರರಿಗೆ ರೂಟ್ ಮಾಡುವುದರಿಂದ ನೀವು ಎಷ್ಟು
> ಉಳಿಸುತ್ತಿದ್ದೀರಿ ಎಂಬುದನ್ನು ನೋಡಬಹುದು.

ಈ ವಿವರಣೆಯನ್ನು ಯೋಜನೆಯ [README](../../README.md) ನಲ್ಲಿಯೂ ನೇರವಾಗಿ ಹೇಳಲಾಗಿದೆ ("ಡ್ಯಾಶ್ಬೋರ್ಡ್ನ
'ವೆಚ್ಚ' ಒಂದು ಉಳಿತಾಯ ಟ್ರ್ಯಾಕರ್, ಬಿಲ್ ಅಲ್ಲ").

ಈ ಸಂಖ್ಯೆಯು ಅಂದಾಜಾಗಿರುವುದರಿಂದ:

- ಇದು ಪ್ರತಿ ಮಾದರಿಗಾಗಿ OmniRoute ಹೊಂದಿರುವ ಬೆಲೆ ಪಟ್ಟಿಯನ್ನು ಅವಲಂಬಿಸಿದೆ. ಬೆಲೆ ನಮೂದು ಇಲ್ಲದ
  ಮಾದರಿಯು `0` ವೆಚ್ಚವನ್ನು ನೀಡುತ್ತದೆ (ಎಕ್ಸ್ಪ್ಲೋರರ್ನಲ್ಲಿ ಅದು "ಹಳೆಯದು / ಉಚಿತ" ಸಾಲಾಗಿ ಕಾಣಿಸುತ್ತದೆ).
- ಉಚಿತ-ಶ್ರೇಣಿ ಮತ್ತು ಚಂದಾದಾರಿಕೆ ಟ್ರಾಫಿಕ್ಗೂ _ಅಂದಾಜಿತ_ ವೆಚ್ಚ ಸಂಚಿತವಾಗುತ್ತದೆ — ಅದು ನೀವು
  ಉಳಿಸುತ್ತಿರುವ ಮೊತ್ತವೇ ಹೊರತು ಪಾವತಿಸಬೇಕಾದ ಮೊತ್ತವಲ್ಲ.

## ವೆಚ್ಚಗಳನ್ನು ಹೇಗೆ ಅಂದಾಜಿಸಲಾಗುತ್ತದೆ

### ಬೆಲೆ ಮೂಲ

ವೆಚ್ಚಗಳು ಈ ಕೆಳಗಿನ ಆದ್ಯತಾ ಕ್ರಮದಲ್ಲಿ ಪರಿಹರಿಸಲಾಗುವ ಬೆಲೆ ಪಟ್ಟಿಯಿಂದ ಬರುತ್ತವೆ
([`src/lib/pricingSync.ts`](../../src/lib/pricingSync.ts)):

1. **ಬಳಕೆದಾರರ ಅತಿಕ್ರಮಣಗಳು** — ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿ / `PATCH /api/pricing` ಮೂಲಕ ನೀವು ಹೊಂದಿಸುವ ಬೆಲೆಗಳು.
2. **ಸಿಂಕ್ ಮಾಡಿದ ಬಾಹ್ಯ ಬೆಲೆಗಳು** — ಸಿಂಕ್ ಸಕ್ರಿಯವಾಗಿರುವಾಗ LiteLLM ನ ಸಾರ್ವಜನಿಕ
   `model_prices_and_context_window.json` ನಿಂದ ಪಡೆಯಲಾಗುತ್ತದೆ (ಪ್ರತ್ಯೇಕ
   `pricing_synced` ನೇಮ್ಸ್ಪೇಸ್ನಲ್ಲಿ ಸಂಗ್ರಹಿಸಲಾಗುತ್ತದೆ; ಆದ್ದರಿಂದ ಅದು ನಿಮ್ಮ ಅತಿಕ್ರಮಣಗಳನ್ನು
   ಎಂದಿಗೂ ಬದಲಿಸುವುದಿಲ್ಲ).
3. **ಹಾರ್ಡ್ಕೋಡ್ ಮಾಡಿದ ಡೀಫಾಲ್ಟ್ಗಳು** — OmniRoute ಜೊತೆಗೆ ಒದಗಿಸಲಾಗುತ್ತದೆ.

ಬಾಹ್ಯ ಬೆಲೆ ಸಿಂಕ್ **ಆಯ್ಕೆಯಾಧಾರಿತ**ವಾಗಿದ್ದು, ಡೀಫಾಲ್ಟ್ ಆಗಿ ನಿಷ್ಕ್ರಿಯವಾಗಿದೆ. ಸಂಬಂಧಿತ env vars
([`.env.example`](../../.env.example) ನೋಡಿ):

| Env var                 | ಡೀಫಾಲ್ಟ್  | ಉದ್ದೇಶ                                                                |
| ----------------------- | --------- | --------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`   | ಪ್ರಾರಂಭದ ಸಮಯದಲ್ಲಿ ಹಿನ್ನೆಲೆ LiteLLM ಬೆಲೆ ಸಿಂಕ್ ಅನ್ನು ಸಕ್ರಿಯಗೊಳಿಸುವುದು. |
| `PRICING_SYNC_INTERVAL` | `86400`   | **ಸೆಕೆಂಡ್ಗಳಲ್ಲಿ** ಸಿಂಕ್ ಮಧ್ಯಂತರ (ಡೀಫಾಲ್ಟ್ ಆಗಿ ಪ್ರತಿದಿನ).              |
| `PRICING_SYNC_SOURCES`  | `litellm` | ಅಲ್ಪವಿರಾಮದಿಂದ ಬೇರ್ಪಡಿಸಿದ ಮೂಲಗಳ ಪಟ್ಟಿ (ಇಂದು `litellm` ಮಾತ್ರ ಬೆಂಬಲಿತ).  |

### ವೆಚ್ಚದ ಸೂತ್ರ

[`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts) ನಲ್ಲಿನ
ಟೋಕನ್ ಎಣಿಕೆಗಳು ಮತ್ತು ಪ್ರತಿ-ಮಿಲಿಯನ್-ಟೋಕನ್ ದರಗಳಿಂದ ಪ್ರತಿ ವಿನಂತಿಯ ವೆಚ್ಚವನ್ನು ಲೆಕ್ಕಹಾಕಲಾಗುತ್ತದೆ
(`computeCostFromPricing` / `calculateCost`):

- **ಇನ್ಪುಟ್ ಟೋಕನ್ಗಳು** (ಕ್ಯಾಶ್ ರೀಡ್ಗಳು ಮತ್ತು ಕ್ಯಾಶ್-ರಚನೆ ಟೋಕನ್ಗಳನ್ನು ಹೊರತುಪಡಿಸಿ) × `input` ದರ.
- **ಕ್ಯಾಶ್-ರೀಡ್ ಟೋಕನ್ಗಳು** × `cached` ದರ (ಇಲ್ಲದಿದ್ದರೆ ಇನ್ಪುಟ್ ದರವನ್ನು ಬಳಸುತ್ತದೆ).
- **ಕ್ಯಾಶ್-ರಚನೆ ಟೋಕನ್ಗಳು** × `cache_creation` ದರ (ಇಲ್ಲದಿದ್ದರೆ ಇನ್ಪುಟ್ ದರವನ್ನು ಬಳಸುತ್ತದೆ).
- **ಔಟ್ಪುಟ್ ಟೋಕನ್ಗಳು** × `output` ದರ.
- **ತಾರ್ಕಿಕ ಟೋಕನ್ಗಳು** × `reasoning` ದರ (ಇಲ್ಲದಿದ್ದರೆ ಔಟ್ಪುಟ್ ದರವನ್ನು ಬಳಸುತ್ತದೆ).

ಎಲ್ಲಾ ದರಗಳನ್ನು 1,000,000 ಟೋಕನ್ಗಳಿಗೆ USD ಎಂದು ಪರಿಗಣಿಸಲಾಗುತ್ತದೆ. Codex "fast"/"priority" ಅಥವಾ
"flex" ಸೇವಾ ಶ್ರೇಣಿಯು ವೆಚ್ಚ ಗುಣಕವನ್ನು (`getCodexFastCostMultiplier`) ಅನ್ವಯಿಸುತ್ತದೆ — ಉದಾಹರಣೆಗೆ,
flex ಗೆ ಟೋಕನ್ ವೆಚ್ಚದಲ್ಲಿ 50% ರಿಯಾಯಿತಿ ವಿಧಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಇದನ್ನು ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿ
**flex ಉಳಿತಾಯ** ಎಂದು ತೋರಿಸಲಾಗುತ್ತದೆ.

ಮಾದರಿಯ ಹೆಸರುಗಳನ್ನು ಮೊದಲು ಸಾಮಾನ್ಯೀಕರಿಸಲಾಗುತ್ತದೆ (`openai/` ಅಥವಾ
`accounts/fireworks/models/` ನಂತಹ ಪೂರೈಕೆದಾರ-ಪಥದ ಪೂರ್ವಪ್ರತ್ಯಯಗಳನ್ನು ತೆಗೆದುಹಾಕಲಾಗುತ್ತದೆ);
ಹೀಗಾಗಿ ಐತಿಹಾಸಿಕ ಸಾಲುಗಳು ಇನ್ನೂ ಬೆಲೆಯೊಂದಿಗೆ ಹೊಂದಾಣಿಕೆಯಾಗುತ್ತವೆ.

### ವೆಚ್ಚವನ್ನು ಹೇಗೆ ದಾಖಲಿಸಲಾಗುತ್ತದೆ

- ಪ್ರತಿ-ವಿನಂತಿಯ ವೆಚ್ಚವನ್ನು ಪ್ರತಿಕ್ರಿಯೆಯ ನಂತರ ಲೆಕ್ಕಹಾಕಲಾಗುತ್ತದೆ ಮತ್ತು client ಗೆ ಎಂದಿಗೂ
  ವಿಳಂಬ ಉಂಟುಮಾಡದಂತೆ fire-and-forget ವಿಧಾನದಲ್ಲಿ ದಾಖಲಿಸಲಾಗುತ್ತದೆ. ಹಂಚಿಕೆಯ-ಕೋಟಾ ಬಳಕೆಯನ್ನು
  [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts) ಮೂಲಕ ಮುಂದಿನ
  event-loop tick ನಲ್ಲಿ ನಿಗದಿಪಡಿಸಲಾಗುತ್ತದೆ.
- API-key ವೆಚ್ಚವನ್ನು ಬಫರ್ ಮಾಡಲಾಗುತ್ತದೆ ಮತ್ತು
  [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) ಮೂಲಕ ಬ್ಯಾಚ್ಗಳಲ್ಲಿ ಫ್ಲಶ್ ಮಾಡಲಾಗುತ್ತದೆ
  (ಡೀಫಾಲ್ಟ್ 60s ಫ್ಲಶ್ ಮಧ್ಯಂತರ, 1,000-ನಮೂದು ಬಫರ್). ಇವುಗಳ ಮೂಲಕ ಹೊಂದಿಸಬಹುದು:

  | Env var                             | ಡೀಫಾಲ್ಟ್ | ಉದ್ದೇಶ                                        |
  | ----------------------------------- | -------- | --------------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000`  | ಮಿಲಿಸೆಕೆಂಡ್ಗಳಲ್ಲಿ ಫ್ಲಶ್ ಮಧ್ಯಂತರ.              |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`   | ಫ್ಲಶ್ಗೆ ಮುನ್ನ ಬಫರ್ ಮಾಡಬಹುದಾದ ಗರಿಷ್ಠ ನಮೂದುಗಳು. |

ಡ್ಯಾಶ್ಬೋರ್ಡ್ನ ವೆಚ್ಚದ ಅಂಕಿಗಳನ್ನು ಸಂಗ್ರಹಿಸಿದ ಪ್ರತಿ-ಸಾಲಿನ ಡಾಲರ್ ಮೊತ್ತದಿಂದ **ಓದಲಾಗುವುದಿಲ್ಲ** —
analytics endpoint ಪ್ರತಿ ಬಾರಿ ರನ್ ಆದಾಗ ಟೋಕನ್ ಎಣಿಕೆಗಳು ಮತ್ತು ಪ್ರಸ್ತುತ ಬೆಲೆ ಪಟ್ಟಿಯಿಂದ ಅವುಗಳನ್ನು
ತಕ್ಷಣವೇ ಮರುಲೆಕ್ಕಹಾಕಲಾಗುತ್ತದೆ. ಅಂದರೆ ತಪ್ಪಾದ ಬೆಲೆಯನ್ನು ಸರಿಪಡಿಸುವುದರಿಂದ (ಮತ್ತು ಮರು-ಸಿಂಕ್ ಮಾಡುವುದರಿಂದ)
ಐತಿಹಾಸಿಕ ವೆಚ್ಚದ ಅಂದಾಜುಗಳು ಪೂರ್ವಾನ್ವಯವಾಗಿ ನವೀಕರಿಸಲ್ಪಡುತ್ತವೆ.

## ಡ್ಯಾಶ್ಬೋರ್ಡ್: ವೆಚ್ಚಗಳ ಪುಟ

**ವೆಚ್ಚಗಳು** ಪುಟವು `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`) ನಲ್ಲಿ ಇದೆ.
ಇದರ ಮುಖ್ಯ ನೋಟವು **ವೆಚ್ಚದ ಅವಲೋಕನ** ಟ್ಯಾಬ್
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`) ಆಗಿದ್ದು,
ಇದು `GET /api/usage/analytics` ನಿಂದ ಎಲ್ಲವನ್ನೂ ಲೋಡ್ ಮಾಡುತ್ತದೆ.

ಇದು ತೋರಿಸುವ ವಿಷಯಗಳು:

- **ವೆಚ್ಚದ ಟೈಲ್ಗಳು** — _ಇಂದು (1d)_, _7d_, _30d_ ಮತ್ತು ಆಯ್ಕೆಮಾಡಿದ
  ಅವಧಿಯ ಅಂದಾಜು ವೆಚ್ಚ. ವ್ಯಾಪ್ತಿ ಆಯ್ಕೆಗಾರ: `7d`, `30d`, `90d`, `all`.
- **ಪ್ರಮುಖ ಮೆಟ್ರಿಕ್ಗಳು** — ಅವಧಿಯಲ್ಲಿನ ವಿನಂತಿಗಳು, ಸಕ್ರಿಯ ಪೂರೈಕೆದಾರರು, ಸಕ್ರಿಯ ಮಾದರಿಗಳು, ಪ್ರತಿ
  ವಿನಂತಿಯ ಸರಾಸರಿ ವೆಚ್ಚ.
- **ವೆಚ್ಚ ಅನ್ವೇಷಕ** — **ಪೂರೈಕೆದಾರ**, **ಮಾದರಿ**,
  **API ಕೀ**, **ಖಾತೆ**, ಅಥವಾ **ಸೇವಾ ಶ್ರೇಣಿ** ಆಧಾರದಲ್ಲಿ ಗುಂಪು ಮಾಡಲಾದ, ವಿಂಗಡಿಸಬಹುದಾದ/ಫಿಲ್ಟರ್ ಮಾಡಬಹುದಾದ ಕೋಷ್ಟಕ; ಇದರಲ್ಲಿ ವೆಚ್ಚ, ವಿನಂತಿಗಳು, ಟೋಕನ್ಗಳು, ಪ್ರತಿ
  ವಿನಂತಿಯ ಸರಾಸರಿ ವೆಚ್ಚ ಮತ್ತು ಒಟ್ಟು ವೆಚ್ಚದಲ್ಲಿನ ಪಾಲಿನ % ಇರುತ್ತವೆ.
- **ಟೋಕನ್ ಬಳಕೆ** — ಒಟ್ಟು / ಇನ್ಪುಟ್ / ಔಟ್ಪುಟ್ ಟೋಕನ್ಗಳು ಮತ್ತು ಇನ್ಪುಟ್:ಔಟ್ಪುಟ್ ಅನುಪಾತ.
- **ರೂಟಿಂಗ್ ದಕ್ಷತೆ** — ಫಾಲ್ಬ್ಯಾಕ್ ಎಣಿಕೆ, ಫಾಲ್ಬ್ಯಾಕ್ ದರ ಮತ್ತು ವಿನಂತಿಸಿದ-ಮಾದರಿಯ ವ್ಯಾಪ್ತಿ.
- **ಮಾಸಿಕ ಮುನ್ಸೂಚನೆ** — ಇತ್ತೀಚಿನ ದೈನಂದಿನ ಸರಾಸರಿಯಿಂದ ತಿಂಗಳ ಅಂತ್ಯದ ವೆಚ್ಚವನ್ನು ಅಂದಾಜಿಸುತ್ತದೆ.
- **ಅವಧಿ ಹೋಲಿಕೆ** — ಅವಧಿಯ ಮೊದಲ ಮತ್ತು ಎರಡನೇ ಅರ್ಧದ ನಡುವಿನ % ಬದಲಾವಣೆ.
- **ಚಾರ್ಟ್ಗಳು** — ದೈನಂದಿನ ವೆಚ್ಚದ ಪ್ರವೃತ್ತಿ, ಪೂರೈಕೆದಾರರ ಪಾಲು (ಪೈ), ಪ್ರಮುಖ ಪೂರೈಕೆದಾರರು, ಪ್ರಮುಖ ಮಾದರಿಗಳು, API ಕೀ
  ಪ್ರಕಾರ ವೆಚ್ಚ, ಖಾತೆ ಪ್ರಕಾರ ವೆಚ್ಚ, ವಾರದ ಬಳಕೆಯ ಮಾದರಿ ಮತ್ತು ಚಟುವಟಿಕೆಯ ಹೀಟ್ಮ್ಯಾಪ್.
- **ರಫ್ತು** — ಪ್ರಸ್ತುತ ಅವಧಿಯನ್ನು **CSV** ಅಥವಾ **JSON** ಆಗಿ ಡೌನ್ಲೋಡ್ ಮಾಡಿ (ಶೂನ್ಯಕ್ಕಿಂತ ಹೆಚ್ಚಿನ ವೆಚ್ಚದ ಡೇಟಾ
  ಇದ್ದಾಗ ಬಟನ್ಗಳು ಕಾಣಿಸಿಕೊಳ್ಳುತ್ತವೆ).

ಬೆಲೆ ನಿಗದಿಪಡಿಸಿದ ಟ್ರಾಫಿಕ್ ಇಲ್ಲದಿದ್ದಾಗ, ಉಳಿತಾಯ-ಟ್ರ್ಯಾಕರ್ ಮಾದರಿಯನ್ನು ಪ್ರತಿಬಿಂಬಿಸುವಂತೆ ಸಾಲುಗಳು `$0`
ಬದಲಿಗೆ "ಹಳೆಯದು / ಉಚಿತ" ಲೇಬಲ್ನೊಂದಿಗೆ ಪ್ರದರ್ಶಿಸಲ್ಪಡುತ್ತವೆ.

### ಸಂಬಂಧಿತ ವೆಚ್ಚಗಳ ಉಪ-ಪುಟಗಳು

ವೆಚ್ಚಗಳ ಪ್ರದೇಶವು ಇವುಗಳನ್ನೂ ಒಳಗೊಂಡಿದೆ (ಎಲ್ಲವೂ `/dashboard/costs/` ಅಡಿಯಲ್ಲಿ):

- **ಬೆಲೆ ನಿಗದಿ** (`/dashboard/costs/pricing`) — ಪ್ರತಿ-ಮಾದರಿಯ ಬೆಲೆಗಳನ್ನು ವೀಕ್ಷಿಸಿ ಮತ್ತು ಅತಿಕ್ರಮಿಸಿ (ಹಂಚಿಕೆಯ
  ಬೆಲೆ ನಿಗದಿ ಟ್ಯಾಬ್ ಅನ್ನು ಪ್ರದರ್ಶಿಸುತ್ತದೆ).
- **ಬಜೆಟ್** (`/dashboard/costs/budget`) — ಪ್ರತಿ-ವ್ಯಾಪ್ತಿಯ ವೆಚ್ಚ ಮಿತಿಗಳನ್ನು ಹೊಂದಿಸಿ (ಹಂಚಿಕೆಯ
  ಬಜೆಟ್ ಟ್ಯಾಬ್ ಅನ್ನು ಪ್ರದರ್ಶಿಸುತ್ತದೆ).
- **ಕೋಟಾ ಹಂಚಿಕೆ** (`/dashboard/costs/quota-share`) — ಹಂಚಿಕೆಯ-ಕೋಟಾ ಪೂಲ್ಗಳು ಮತ್ತು ಬಳಕೆ-ದರದ
  ನೋಟಗಳು.

## CLI

OmniRoute ನ CLI ವೆಚ್ಚ, ಬಳಕೆ ಮತ್ತು ಬೆಲೆ ನಿಗದಿ ಆದೇಶಗಳನ್ನು ಒದಗಿಸುತ್ತದೆ (ಇವುಗಳನ್ನು
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs) ನಲ್ಲಿ ನೋಂದಾಯಿಸಲಾಗಿದೆ).

### `omniroute cost`

`/api/usage/analytics` ನಿಂದ ಒಟ್ಟುಗೂಡಿಸಿದ ವೆಚ್ಚದ ವರದಿ.

```bash
omniroute cost                          # ಕಳೆದ 30d, ಪೂರೈಕೆದಾರರ ಪ್ರಕಾರ ಗುಂಪು ಮಾಡಲಾಗಿದೆ
omniroute cost --period 7d              # ಕಳೆದ 7 ದಿನಗಳು
omniroute cost --group-by model         # provider | model | combo | api-key | day ಪ್ರಕಾರ ಗುಂಪು ಮಾಡಿ
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

ಕಾಲಮ್ಗಳು: ಗುಂಪು, ವಿನಂತಿಗಳು, ಇನ್/ಔಟ್ ಟೋಕನ್ಗಳು, ವೆಚ್ಚ (USD), ಮತ್ತು ಒಟ್ಟು ಮೊತ್ತದ %. ಕೊನೆಯಲ್ಲಿ
ಒಟ್ಟಾರೆ ಮೊತ್ತದ ಸಾಲನ್ನು ಮುದ್ರಿಸಲಾಗುತ್ತದೆ (`--quiet` ಅಥವಾ `--output json` ಬಳಸಿದಾಗ ಇದನ್ನು ತೋರಿಸಲಾಗುವುದಿಲ್ಲ).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # ಪ್ರತಿ ಪೂರೈಕೆದಾರರ ವೆಚ್ಚದ ಸಾರಾಂಶ
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# ಬಜೆಟ್ಗಳು
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` ಆದೇಶವು `GET /api/pricing/defaults` ಅನ್ನು ಓದುತ್ತದೆ. ಇದರ ಬದಲಿಗೆ ಪ್ರತ್ಯೇಕ ಮಾದರಿಗಳ
> ಬೆಲೆಗಳನ್ನು ಸಂಪಾದಿಸಲು, **ಬೆಲೆ ನಿಗದಿ** ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಪುಟ ಅಥವಾ `PATCH /api/pricing` ಬಳಸಿ.

## ಸಮಸ್ಯೆ ಪರಿಹಾರ

- **ಎಲ್ಲಾ ವೆಚ್ಚಗಳು $0 / "Legacy / Free" ಎಂದು ತೋರಿಸುತ್ತವೆ.** ಬಳಕೆಯಲ್ಲಿರುವ ಮಾದರಿಗಳಿಗೆ ಬೆಲೆ ನಿಗದಿ ನಮೂದು ಇಲ್ಲ.
  ಬಾಹ್ಯ ಸಿಂಕ್ ಅನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ (`PRICING_SYNC_ENABLED=true`) ಮತ್ತು `omniroute pricing sync` ಚಲಾಯಿಸಿ, ಅಥವಾ
  ಬೆಲೆ ನಿಗದಿ ಪುಟ / `PATCH /api/pricing` ಮೂಲಕ ಬೆಲೆಗಳನ್ನು ಹಸ್ತಚಾಲಿತವಾಗಿ ಹೊಂದಿಸಿ.
- **ಐತಿಹಾಸಿಕ ಮಾದರಿಯ ಬೆಲೆ ತಪ್ಪಾಗಿದೆ.** ಬೆಲೆಯನ್ನು ಸರಿಪಡಿಸಿ (ಅತಿಕ್ರಮಿಸಿ ಅಥವಾ ಮರು-ಸಿಂಕ್ ಮಾಡಿ) — ಪ್ರತಿ ವಿಶ್ಲೇಷಣಾ ಓದುವಿಕೆಯಲ್ಲೂ
  ಟೋಕನ್ ಎಣಿಕೆಗಳಿಂದ ವೆಚ್ಚವನ್ನು ಮರುಲೆಕ್ಕಾಚಾರ ಮಾಡಲಾಗುತ್ತದೆ, ಆದ್ದರಿಂದ ಅಂದಾಜುಗಳು ಹಿಂದಿನ ಅವಧಿಗಳಿಗೂ ಅನ್ವಯಿಸುವಂತೆ ನವೀಕರಣಗೊಳ್ಳುತ್ತವೆ.
- **ವೆಚ್ಚದ ಮಾಹಿತಿ ನೈಜ ಸಮಯಕ್ಕಿಂತ ವಿಳಂಬವಾಗಿರುತ್ತದೆ.** ಪ್ರತಿ ಕೀಗೆ ಸಂಬಂಧಿಸಿದ ವೆಚ್ಚವನ್ನು ಬ್ಯಾಚ್ಗಳಲ್ಲಿ ಸಂಸ್ಕರಿಸಲಾಗುತ್ತದೆ; ಹೆಚ್ಚು ನವೀನ ಅಂಕಿಗಳು
  ಬೇಕಿದ್ದರೆ `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` ಅನ್ನು ಕಡಿಮೆ ಮಾಡಿ.
