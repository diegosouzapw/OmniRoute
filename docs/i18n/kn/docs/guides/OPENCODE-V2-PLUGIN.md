`@omniroute/opencode-plugin-v2` ನಿಮ್ಮ ಸಂಪೂರ್ಣ OmniRoute ಕ್ಯಾಟಲಾಗ್ — models, combos ಮತ್ತು
auto-combos — ಅನ್ನು ಪ್ರದರ್ಶನ ಹೆಸರುಗಳು, ಬೆಲೆ ವಿವರಗಳು ಮತ್ತು ಉಚಿತ-ಶ್ರೇಣಿಯ
ಬಜೆಟ್ಗಳೊಂದಿಗೆ OpenCode v2 ನ ಮಾದರಿ ಆಯ್ಕೆಗೆ ಸೇರಿಸುತ್ತದೆ.

ಇದು `@omniroute/opencode-plugin` ನಿಂದ ಪ್ರತ್ಯೇಕವಾದ ಪ್ಯಾಕೇಜ್ ಆಗಿದೆ, ಏಕೆಂದರೆ OpenCode v1 ಮತ್ತು v2
ಪ್ಲಗಿನ್ಗಳನ್ನು ವಿಭಿನ್ನ ಒಪ್ಪಂದಗಳ ಮೂಲಕ ಲೋಡ್ ಮಾಡುತ್ತವೆ. ನಿಮ್ಮ OpenCode ಪ್ರಮುಖ ಆವೃತ್ತಿಗೆ ಹೊಂದಿಕೆಯಾಗುವ
ಪ್ಯಾಕೇಜ್ ಅನ್ನು ಆಯ್ಕೆಮಾಡಿ; ಅವುಗಳ ನಡುವೆ ಯಾವುದನ್ನೂ ಹಂಚಿಕೊಳ್ಳುವುದಿಲ್ಲ, ಆದ್ದರಿಂದ ಒಂದನ್ನು ನವೀಕರಿಸುವುದರಿಂದ
ಇನ್ನೊಂದನ್ನು ನವೀಕರಿಸುವ ಅಗತ್ಯ ಎಂದಿಗೂ ಬರುವುದಿಲ್ಲ.

## ಅವಶ್ಯಕತೆಗಳು

- OpenCode v2.
- ಸಂಪರ್ಕಿಸಬಹುದಾದ OmniRoute ಗೇಟ್ವೇ (ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ `http://localhost:20128`).
- Node.js 22 ಅಥವಾ 24.

## ಸ್ಥಾಪನೆ

ಪ್ಲಗಿನ್ ಅನ್ನು `opencode.json` ಗೆ ಸೇರಿಸಿ:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

ನಂತರ ಮಾದರಿಗಳು `omniroute/<provider>/<model>` ರೂಪದಲ್ಲಿ ಕಾಣಿಸಿಕೊಳ್ಳುತ್ತವೆ; `providerId` ಆ ಪೂರ್ವಪ್ರತ್ಯಯವನ್ನು
ಮತ್ತು OpenCode ರುಜುವಾತನ್ನು ಸಂಗ್ರಹಿಸುವ ಇಂಟಿಗ್ರೇಶನ್ನ id ಅನ್ನು ನಿರ್ಧರಿಸುತ್ತದೆ.

## ರುಜುವಾತುಗಳು

ಪ್ಲಗಿನ್ ಗೇಟ್ವೇ ಕೀಲಿಯನ್ನು ಈ ಕ್ರಮದಲ್ಲಿ ಮೂರು ಸ್ಥಳಗಳಲ್ಲಿ ಹುಡುಕುತ್ತದೆ:

1. **ನೀವು OpenCode ನಲ್ಲಿ ಸಂಪರ್ಕಿಸಿರುವ ರುಜುವಾತು.** ಪ್ಲಗಿನ್ ಒಂದು ಇಂಟಿಗ್ರೇಶನ್ ಅನ್ನು ನೋಂದಾಯಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ
   OpenCode ನ ಸ್ವಂತ ದೃಢೀಕರಣ ಪ್ರಕ್ರಿಯೆಯು ಕೀಲಿಯನ್ನು ಸಂಗ್ರಹಿಸಬಹುದು. `opencode.json` ನಲ್ಲಿ ಏನೂ ಸಂಗ್ರಹವಾಗುವುದಿಲ್ಲ — ಇದನ್ನೇ ಆದ್ಯತೆಯಿಂದ ಬಳಸಿ.
2. ಪ್ರತಿ ಯೋಜನೆಗೆ ಪ್ರತ್ಯೇಕ ಅತಿಕ್ರಮಣಕ್ಕಾಗಿ ಪ್ಲಗಿನ್ ಆಯ್ಕೆಗಳಲ್ಲಿನ `apiKey`. ಇದು ನೀವು
   ಕಮಿಟ್ ಮಾಡಬಹುದಾದ ಫೈಲ್ನಲ್ಲಿ ಕೀಲಿಯನ್ನು ಇರಿಸುತ್ತದೆ.
3. ಪರಿಸರದಲ್ಲಿನ `OMNIROUTE_API_KEY`.

ಈ ಮೂರರಲ್ಲಿ ಯಾವುದೂ ಇಲ್ಲದಿದ್ದರೆ, ಕ್ಯಾಟಲಾಗ್ ಖಾಲಿಯಾಗಿರುತ್ತದೆ ಮತ್ತು ಮೌನವಾದ ಖಾಲಿ ಆಯ್ಕೆಪಟ್ಟಿಯನ್ನು
ನಿಮಗೆ ತೋರಿಸುವ ಬದಲು, ಪ್ರಾರಂಭಿಸುವಾಗ ಪ್ಲಗಿನ್ ಇದನ್ನು ಒಮ್ಮೆ ತಿಳಿಸುತ್ತದೆ.

### ನಿರ್ವಹಣಾ ಟೋಕನ್ ಬೇರೊಂದು ಕೀಲಿಯಾಗಿದೆ

Combos, ಪೂರೈಕೆದಾರರ ಸ್ಥಿತಿ ಮತ್ತು ಪುಷ್ಟೀಕರಣ (ಪ್ರದರ್ಶನ ಹೆಸರುಗಳು, ಬೆಲೆ ವಿವರಗಳು, ಉಚಿತ-ಶ್ರೇಣಿಯ ಬಜೆಟ್ಗಳು)
ಗೇಟ್ವೇಯ `/api/*` ಎಂಡ್ಪಾಯಿಂಟ್ಗಳಿಂದ ಬರುತ್ತವೆ. ಹೆಚ್ಚಿನ ನಿಯೋಜನೆಗಳು ಇವುಗಳನ್ನು inference ಕೀಲಿಯ ಬದಲು
**ನಿರ್ವಹಣಾ** ಟೋಕನ್ನಿಂದ ರಕ್ಷಿಸುತ್ತವೆ:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<management read token>"
}
```

`managementReadToken` ಅನ್ನು ಹೊಂದಿಸದೆ ಬಿಟ್ಟರೆ, ಅದು `apiKey` ಗೆ ಹಿಂತಿರುಗುತ್ತದೆ. ಗೇಟ್ವೇ ಆ ಪರ್ಯಾಯವನ್ನು
ತಿರಸ್ಕರಿಸಿದಾಗಲೂ ಕ್ಯಾಟಲಾಗ್ ಪ್ರಕಟವಾಗುತ್ತದೆ, ಆದರೆ ಪ್ರದರ್ಶನ ಹೆಸರುಗಳ ಬದಲು ಮೂಲ model ids ಮಾತ್ರ ಇರುತ್ತವೆ,
canonical alias ನಕಲು ನಿವಾರಣೆ ಇರುವುದಿಲ್ಲ, ಬೆಲೆ ವಿವರಗಳು ಇರುವುದಿಲ್ಲ ಮತ್ತು combos ಇರುವುದಿಲ್ಲ. ಇದು ಸಂಭವಿಸಿದಾಗ
ಪ್ಲಗಿನ್ ಪ್ರತಿ ಎಂಡ್ಪಾಯಿಂಟ್ಗೆ ಒಮ್ಮೆ ಎಚ್ಚರಿಕೆ ನೀಡುತ್ತದೆ ಮತ್ತು ಎಂಡ್ಪಾಯಿಂಟ್ ಹಾಗೂ ಕಳೆದುಹೋದದ್ದನ್ನು ಹೆಸರಿಸುತ್ತದೆ —
ಆದ್ದರಿಂದ ಸಾಮರ್ಥ್ಯ ಕಡಿಮೆಯಾದ ಆಯ್ಕೆಪಟ್ಟಿ ಎಂದಿಗೂ ನಿಗೂಢವಾಗಿ ಉಳಿಯುವುದಿಲ್ಲ.

| `logLevel` / `startupDebug`      | `warn` / `false`                            | ಲಾಗರ್ ವಿವರದ ಮಟ್ಟ                                                                                                              |

## ಕ್ಯಾಟಲಾಗ್ ಹೇಗೆ ತಾಜಾವಾಗಿರುತ್ತದೆ

ಕ್ಯಾಟಲಾಗ್ ಅನ್ನು ಅಗತ್ಯವಿದ್ದಾಗ ಮಾತ್ರ ಪಡೆದು `modelCacheTtlMs` ಅವಧಿಯವರೆಗೆ ಕ್ಯಾಶ್ ಮಾಡಲಾಗುತ್ತದೆ, ಮತ್ತು ಗೇಟ್ವೇ ಸಂಪರ್ಕಿಸಲಾಗದಿದ್ದಾಗ ಕೊನೆಯದಾಗಿ ತಿಳಿದಿರುವ ಕ್ಯಾಟಲಾಗ್ ಲಭ್ಯವಿರುವಂತೆ ಡಿಸ್ಕ್ ಸ್ನ್ಯಾಪ್ಶಾಟ್ ನೋಡಿಕೊಳ್ಳುತ್ತದೆ — ಸೇವಾ ವ್ಯತ್ಯಯದಿಂದ ನಿಮಗೆ ತಾಜಾತನದ ಕೊರತೆಯ ಹೊರತು ಬೇರೇನೂ ನಷ್ಟವಾಗುವುದಿಲ್ಲ. ಮಾಡೆಲ್ಗಳು ಮತ್ತು ಕಾಂಬೊಗಳು ಬಂದ ತಕ್ಷಣವೇ ಪ್ರಕಟವಾಗುತ್ತವೆ; ಸ್ವಯಂ-ಕಾಂಬೊಗಳು, ಪೂರೈಕೆದಾರರ ಪಟ್ಟಿ ಮತ್ತು ಎನ್ರಿಚ್ಮೆಂಟ್ ಓವರ್ಲೇ ಬಂದಾಗ ಅವುಗಳನ್ನು ಸೇರಿಸಲಾಗುತ್ತದೆ, ಆದ್ದರಿಂದ ನಿಧಾನವಾದ ಒಂದೇ ಎಂಡ್ಪಾಯಿಂಟ್ ಇಡೀ ಪಿಕರ್ ಅನ್ನು ತಡೆಹಿಡಿಯಲು ಸಾಧ್ಯವಿಲ್ಲ.

ಹೆಸರುಗಳು ಗೇಟ್ವೇಗೆ ತಿಳಿದಿರುವ ಮಾಹಿತಿಯನ್ನು ಒಳಗೊಂಡಿರುತ್ತವೆ: ಮಾಡೆಲ್ ಅನ್ನು ರೂಟ್ ಮಾಡುವ ಅಪ್ಸ್ಟ್ರೀಮ್ ಪೂರೈಕೆದಾರ, `[Free]` ಗುರುತು ಮತ್ತು ಅದರೊಂದಿಗೆ ದೊರೆಯುವ ಬಜೆಟ್ — ಹೀಗಾಗಿ ಒಂದೇ ಮಾಡೆಲ್ ಅನ್ನು ಒದಗಿಸುವ ಎರಡು ಸಂಪರ್ಕಗಳನ್ನು ಪ್ರತ್ಯೇಕವಾಗಿ ಗುರುತಿಸಬಹುದು. `"providerTag": false` ಮೂಲಕ ಪ್ರಿಫಿಕ್ಸ್ ಅನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿ.

ಯಾವುದೇ ಹಸ್ತಚಾಲಿತ ರಿಫ್ರೆಶ್ ಕಮಾಂಡ್ ಇಲ್ಲ: OpenCode v2 ಕಮಾಂಡ್ಗಳು ಪ್ರಾಂಪ್ಟ್ ಟೆಂಪ್ಲೇಟ್ಗಳಾಗಿವೆ, ಕಾಲ್ಬ್ಯಾಕ್ಗಳಲ್ಲ, ಆದ್ದರಿಂದ ಪ್ಲಗಿನ್ ಅಂತಹ ಕಮಾಂಡ್ ಅನ್ನು ಒದಗಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ. ರಿಫ್ರೆಶ್ಗಳು TTL ಅನ್ನು ಅನುಸರಿಸುತ್ತವೆ; ಕ್ಯಾಟಲಾಗ್ ಅಥವಾ ಓವರ್ಲೇ ನಿಜವಾಗಿಯೂ ಬದಲಾದಾಗ ಮಾತ್ರ ಹೋಸ್ಟ್ಗೆ ಮರುಲೋಡ್ ಮಾಡಲು ಕೇಳಲಾಗುತ್ತದೆ, ಪ್ರತಿ ರಿಫ್ರೆಶ್ನಲ್ಲೂ ಅಲ್ಲ.

## Gemini ನಲ್ಲಿ ಟೂಲ್ ಕಾಲಿಂಗ್

ಟೂಲ್ ಡಿಕ್ಲರೇಶನ್ಗಳು `$schema` ಅಥವಾ `additionalProperties` ಅನ್ನು ಹೊಂದಿರುವ ಸಂಪೂರ್ಣ ವಿನಂತಿಯನ್ನು Gemini ತಿರಸ್ಕರಿಸಿ, `400 INVALID_ARGUMENT` ಎಂದು ಉತ್ತರಿಸುತ್ತದೆ. ಈ ಪ್ಲಗಿನ್ ಈ ಪೂರೈಕೆದಾರರ Gemini ಮಾಡೆಲ್ಗೆ ಕಳುಹಿಸಲಾಗುವ ಟೂಲ್ ಸ್ಕೀಮಾಗಳಿಂದ ಆ ಕೀವರ್ಡ್ಗಳನ್ನು ತೆಗೆದುಹಾಕುತ್ತದೆ ಮತ್ತು ಇತರ ಎಲ್ಲ ವಿನಂತಿಗಳನ್ನು ಬದಲಾಯಿಸದೆ ಬಿಡುತ್ತದೆ. `$ref` ಹೊಂದಿರುವ ಟೂಲ್ ಅನ್ನು ತೆಗೆದುಹಾಕುವಿಕೆ ಮಾಡದೆ ಹಾಗೆಯೇ ಫಾರ್ವರ್ಡ್ ಮಾಡಲಾಗುತ್ತದೆ, ಏಕೆಂದರೆ ರೆಫರೆನ್ಸ್ ಅನ್ನು ತೆಗೆದುಹಾಕುವುದರಿಂದ ಸ್ಕೀಮಾ "ಯಾವುದನ್ನಾದರೂ ಸ್ವೀಕರಿಸುವ" ಮಟ್ಟಿಗೆ ವಿಸ್ತರಿಸುತ್ತದೆ.
ಇದನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಲು `"geminiSanitization": false` ಅನ್ನು ಹೊಂದಿಸಿ.
