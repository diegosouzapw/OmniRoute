## ✨ v3.8.0 ಮುಖ್ಯಾಂಶಗಳು

v3.7.x → v3.8.0 ಆವೃತ್ತಿ ಚಕ್ರವು ಶೂನ್ಯ-ಸಂರಚನೆಯ ಸ್ವಯಂ ರೂಟಿಂಗ್, ಹೊಸ ಪೂರೈಕೆದಾರರು, OAuth ಹರಿವುಗಳು, ಹೆಚ್ಚಿನ ಸ್ಥಿತಿಸ್ಥಾಪಕತೆ ಮತ್ತು ಇನ್ನಷ್ಟು ಸಮೃದ್ಧವಾದ CLI ಅನುಭವವನ್ನು ಸೇರಿಸಿದೆ. ಪ್ರಮುಖ ವೈಶಿಷ್ಟ್ಯಗಳು ಕೆಳಗಿವೆ — ಸಂಪೂರ್ಣ ವಿವರಗಳು ಈ ದಸ್ತಾವೇಜಿನಲ್ಲಿ ಮುಂದೆ ಮತ್ತು ಲಿಂಕ್ ಮಾಡಲಾದ ನಿರ್ದಿಷ್ಟತೆಗಳಲ್ಲಿ ಲಭ್ಯವಿವೆ.

- 🤖 **Auto Combo / ಶೂನ್ಯ-ಸಂರಚನೆಯ ಸ್ವಯಂ-ರೂಟಿಂಗ್** — `auto/coding`, `auto/fast`, `auto/cheap`, `auto/offline`, `auto/smart`, `auto/lkgp`, `auto/chaos` ಪೂರ್ವಪ್ರತ್ಯಯಗಳನ್ನು ಬಳಸಿ. 16-ಅಂಶಗಳ ಸ್ಕೋರಿಂಗ್ ಎಂಜಿನ್ ಮತ್ತು ಆಯ್ದ 6 **ಮೋಡ್ ಪ್ಯಾಕ್ಗಳು** (ship-fast, cost-saver, quality-first, offline-friendly, reliability-first, chaos-mode) ಇದರ ಆಧಾರವಾಗಿವೆ
- 🆕 **Command Code ಪೂರೈಕೆದಾರ** (#2199) — ಮಾದರಿ ಕ್ಯಾಟಲಾಗ್ ಮತ್ತು ಕೋಟಾ ಟ್ರ್ಯಾಕಿಂಗ್ನೊಂದಿಗೆ ಪ್ರಥಮ ದರ್ಜೆಯ ನೋಂದಣಿ
- 🆕 **Z.AI ಪೂರೈಕೆದಾರ** — ಕೋಟಾ ಲೇಬಲ್ಗಳನ್ನು ಹೊಂದಿರುವ ಹೊಸ ಉಚಿತ-ಹಂತದ ಪೂರೈಕೆದಾರ
- 🎬 **KIE ಮಾಧ್ಯಮ ವಿಸ್ತರಣೆ** — ವೀಡಿಯೊ ರಚನೆ ಮಾದರಿಗಳನ್ನು ಒಳಗೊಂಡ ವಿಸ್ತೃತ ಕ್ಯಾಟಲಾಗ್
- 🔐 **Devin ದೃಢೀಕರಣ** — Desktop ಈಗಾಗಲೇ ಇರುವ Devin API ಕೀಲಿಯನ್ನು ಆಮದು ಮಾಡಿಕೊಳ್ಳುತ್ತದೆ; CLI ಸ್ಥಳೀಯ `devin auth login` ರುಜುವಾತುಗಳನ್ನು ಬಳಸುತ್ತದೆ
- 🆓 **8 ಹೊಸ ಉಚಿತ ಪೂರೈಕೆದಾರರು** — LLM7, Lepton, UncloseAI, BazaarLink, Completions, Enally, FreeTheAi, Command Code
- 🎯 **ಮ್ಯಾನಿಫೆಸ್ಟ್-ಅರಿವುಳ್ಳ ಹಂತದ ರೂಟಿಂಗ್ W1–W4** — ಪೂರೈಕೆದಾರ ಮ್ಯಾನಿಫೆಸ್ಟ್ಗಳು ತೂಕ ನೀಡಲಾದ ಹಂತದ ಆಯ್ಕೆಯನ್ನು ನಿಯಂತ್ರಿಸುತ್ತವೆ
- 🎨 **Cursor ಸಂಪೂರ್ಣ OpenAI ಸಮಾನತೆ** — ಟೂಲ್ ಕರೆಗಳು, ಸ್ಟ್ರೀಮಿಂಗ್ ಮತ್ತು ಸೆಷನ್ ನಿರ್ವಹಣೆಗೆ ಆರಂಭದಿಂದ ಅಂತ್ಯದವರೆಗೆ ಬೆಂಬಲ
- 📊 **Cursor Pro ಯೋಜನೆಯ ಬಳಕೆ** — ಪೂರೈಕೆದಾರ-ಮಿತಿಗಳ ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿ ಕೋಟಾ ಮತ್ತು ಚಕ್ರದ ಡೇಟಾವನ್ನು ಪ್ರದರ್ಶಿಸಲಾಗುತ್ತದೆ
- ⚡ **ಸೇವಾ ಹಂತದ ವಿಭಜನೆ / Codex ವೇಗದ ಹಂತದ ವಿಶ್ಲೇಷಣೆ** — ಪ್ರತಿ ಹಂತದ ಬಳಕೆಯ ಗೋಚರತೆ
- 📌 **ಪ್ರತಿ-ಸೆಷನ್ ಸ್ಥಿರ ರೂಟಿಂಗ್** — ಸರದಿಗಳ ನಡುವೆ Codex ಸೆಷನ್ಗಳು ಅದೇ ಖಾತೆಗೆ ಸ್ಥಿರವಾಗಿ ಜೋಡಿಸಲ್ಪಡುತ್ತವೆ
- 🔊 **Inworld TTS ಸುಧಾರಣೆಗಳು** — ಧ್ವನಿ ಕ್ಯಾಟಲಾಗ್ಗಳು, ಸ್ಟ್ರೀಮಿಂಗ್ ಮತ್ತು ಲೇಟೆನ್ಸಿ ಸುಧಾರಣೆಗಳು
- 🔑 **Kiro ಹೆಡ್ಲೆಸ್ ದೃಢೀಕರಣ** — ಸ್ಥಳೀಯ `kiro-cli` SQLite ಸಂಗ್ರಹದ ಮೂಲಕ ಲಾಗಿನ್ ಮಾಡಿ, ಬ್ರೌಸರ್ ಅಗತ್ಯವಿಲ್ಲ
- 📉 **DeepSeek ಕೋಟಾ ಮತ್ತು ಮಿತಿ ಮೇಲ್ವಿಚಾರಣೆ** — ದೈನಂದಿನ/ಮಾಸಿಕ ಬಳಕೆಯನ್ನು ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಮೂಲಕ ಪ್ರದರ್ಶಿಸಲಾಗುತ್ತದೆ
- 🔄 **ಮರುಹೊಂದಿಕೆ-ಅರಿವುಳ್ಳ ರೂಟಿಂಗ್ ತಂತ್ರ** — ಈಗ ಕಾಂಬೊಗಳು ಕೋಟಾ ಅವಧಿ ಅತಿ ಶೀಘ್ರದಲ್ಲಿ ಮರುಹೊಂದುವ ಖಾತೆಗಳಿಗೆ ಆದ್ಯತೆ ನೀಡುತ್ತವೆ

## 🔌 ಪೂರೈಕೆದಾರರು

AI ಪೂರೈಕೆದಾರರ ಸಂಪರ್ಕಗಳನ್ನು ನಿರ್ವಹಿಸಿ: OAuth ಪೂರೈಕೆದಾರರು (Claude Code, Codex), API ಕೀ ಪೂರೈಕೆದಾರರು (Groq, DeepSeek, OpenRouter), ಮತ್ತು ಉಚಿತ ಪೂರೈಕೆದಾರರು (Qoder, Kiro). Kiro ಖಾತೆಗಳು ಕ್ರೆಡಿಟ್ ಬಾಕಿ ಟ್ರ್ಯಾಕಿಂಗ್ ಅನ್ನು ಒಳಗೊಂಡಿವೆ — ಉಳಿದಿರುವ ಕ್ರೆಡಿಟ್ಗಳು, ಒಟ್ಟು ಮಿತಿ ಮತ್ತು ನವೀಕರಣ ದಿನಾಂಕವನ್ನು ಡ್ಯಾಶ್ಬೋರ್ಡ್ → ಬಳಕೆಯಲ್ಲಿ ನೋಡಬಹುದು.

OpenRouter ಸಂಪರ್ಕಗಳು ಸುಧಾರಿತ ಸೆಟ್ಟಿಂಗ್ಗಳಲ್ಲಿ ಪ್ರತಿ ಸಂಪರ್ಕಕ್ಕೆ ಒಂದು `preset` ಅನ್ನು ಸಂಗ್ರಹಿಸಬಹುದು. ಅದನ್ನು ಹೊಂದಿಸಿದಾಗ, ಕ್ಲೈಂಟ್ ವಿನಂತಿಯು ಈಗಾಗಲೇ ತನ್ನದೇ ಆದ `preset` ಅನ್ನು ಒದಗಿಸಿರದ ಹೊರತು, OmniRoute ಅದನ್ನು OpenRouter ಉನ್ನತ-ಮಟ್ಟದ ವಿನಂತಿ ಕ್ಷೇತ್ರವಾಗಿ ಕಳುಹಿಸುತ್ತದೆ, ಉದಾಹರಣೆಗೆ `"preset": "email-copywriter"`.

## 🎨 ಕಾಂಬೊಗಳು

19 ಸಾರ್ವಜನಿಕ ಕಾರ್ಯತಂತ್ರಗಳೊಂದಿಗೆ ಮಾದರಿ ರೂಟಿಂಗ್ ಕಾಂಬೊಗಳನ್ನು ರಚಿಸಿ: priority, weighted, round-robin, context-relay, fill-first, p2c (ಎರಡು ಆಯ್ಕೆಗಳ ಶಕ್ತಿ), random, least-used, cost-optimized, reset-aware, reset-window, headroom, strict-random, auto, lkgp (ಕೊನೆಯದಾಗಿ ಯಶಸ್ವಿಯಾದ ಪೂರೈಕೆದಾರ), context-optimized, cache-optimized, **fusion** (ಮಾದರಿಗಳ ಪ್ಯಾನೆಲ್ಗೆ ಸಮಾನಾಂತರವಾಗಿ ವಿನಂತಿಗಳನ್ನು ಕಳುಹಿಸಿ, ನಂತರ ನಿರ್ಣಾಯಕ ಮಾದರಿಯ ಮೂಲಕ ಒಂದೇ ಉತ್ತರವನ್ನು ಸಂಶ್ಲೇಷಿಸುವುದು), ಮತ್ತು **pipeline**. ಪ್ರತಿಯೊಂದು ಕಾಂಬೊ ಸ್ವಯಂಚಾಲಿತ ಫಾಲ್ಬ್ಯಾಕ್ನೊಂದಿಗೆ ಅನೇಕ ಮಾದರಿಗಳನ್ನು ಸರಪಳಿಯಾಗಿ ಜೋಡಿಸುತ್ತದೆ ಮತ್ತು ತ್ವರಿತ ಟೆಂಪ್ಲೇಟ್ಗಳು ಹಾಗೂ ಸನ್ನದ್ಧತಾ ಪರಿಶೀಲನೆಗಳನ್ನು ಒಳಗೊಂಡಿರುತ್ತದೆ.

- **ಸಾಮಾನ್ಯ** — ಸಿಸ್ಟಮ್ ಸಂಗ್ರಹಣೆ, ಬ್ಯಾಕಪ್ ನಿರ್ವಹಣೆ (ಡೇಟಾಬೇಸ್ ರಫ್ತು/ಆಮದು)
- **ಗೋಚರತೆ** — ಥೀಮ್ ಆಯ್ಕೆಗಾರ (ಡಾರ್ಕ್/ಲೈಟ್/ಸಿಸ್ಟಮ್), ಬಣ್ಣದ ಥೀಮ್ ಪೂರ್ವನಿಗದಿಗಳು ಮತ್ತು ಕಸ್ಟಮ್ ಬಣ್ಣಗಳು, ಸ್ಥಿತಿ ಲಾಗ್ ಗೋಚರತೆ, ಸೈಡ್ಬಾರ್ ಐಟಂ ಮತ್ತು ಗುಂಪು ವಿಭಜಕದ ಗೋಚರತೆ ನಿಯಂತ್ರಣಗಳು, ಎಂಡ್ಪಾಯಿಂಟ್ ಟನಲ್ ಗೋಚರತೆ ನಿಯಂತ್ರಣಗಳು
- **AI** — AI ಸಹಾಯಕ ವೈಶಿಷ್ಟ್ಯಗಳು, ಡೀಫಾಲ್ಟ್ ರೂಟಿಂಗ್ ಪೂರ್ವನಿಗದಿಗಳು (ಆಟೋ ಕಾಂಬೊ `auto/coding`, `auto/fast`, `auto/cheap`, `auto/smart`), ರೀಸನಿಂಗ್ ರೀಪ್ಲೇ ಕ್ಯಾಶ್ ಮತ್ತು ಕೌಶಲ್ಯ/ಮೆಮೊರಿ ಟಾಗಲ್ಗಳು
- **ಭದ್ರತೆ** — API ಎಂಡ್ಪಾಯಿಂಟ್ ರಕ್ಷಣೆ, ಕಸ್ಟಮ್ ಪೂರೈಕೆದಾರ ನಿರ್ಬಂಧಿಸುವಿಕೆ, IP ಫಿಲ್ಟರಿಂಗ್, ಸೆಷನ್ ಮಾಹಿತಿ
- **ರೂಟಿಂಗ್** — ಮಾಡೆಲ್ ಅಲಿಯಾಸ್ಗಳು, ಹಿನ್ನೆಲೆ ಕಾರ್ಯದ ಗುಣಮಟ್ಟ ಇಳಿಕೆ, ಮ್ಯಾನಿಫೆಸ್ಟ್-ಅವೇರ್ ಟಿಯರ್ ರೂಟಿಂಗ್ (W1–W4), `fallbackDelayMs`, ಪ್ರತಿ-ಸೆಷನ್ ಸ್ಟಿಕ್ಕಿ ರೂಟಿಂಗ್
- **ಸ್ಥಿತಿಸ್ಥಾಪಕತೆ** — ರೇಟ್ ಲಿಮಿಟ್ ಸ್ಥಿರತೆ, ಸರ್ಕ್ಯೂಟ್ ಬ್ರೇಕರ್ ಟ್ಯೂನಿಂಗ್, ನಿಷೇಧಿತ ಖಾತೆಗಳ ಸ್ವಯಂ-ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವಿಕೆ, ಪೂರೈಕೆದಾರರ ಅವಧಿ ಮುಕ್ತಾಯ ಮೇಲ್ವಿಚಾರಣೆ, **ಕಾಂಟೆಕ್ಸ್ಟ್ ರಿಲೇ** ಹ್ಯಾಂಡ್ಆಫ್ ಮಿತಿ ಮತ್ತು ಸಾರಾಂಶ ಮಾಡೆಲ್ ಸಂರಚನೆ, ಪ್ರತಿ-ಪೂರೈಕೆದಾರ 429 ವರ್ಗೀಕರಣ ಮತ್ತು `useUpstream429BreakerHints` ಟಾಗಲ್, ಮಾಡೆಲ್ ಕೂಲ್ಡೌನ್ಗಳು
- **ಸುಧಾರಿತ** — ಸಂರಚನಾ ಅತಿಕ್ರಮಣಗಳು, ಸಂರಚನಾ ಆಡಿಟ್ ಟ್ರೇಲ್, ಫಾಲ್ಬ್ಯಾಕ್ ಗುಣಮಟ್ಟ ಇಳಿಕೆ ಮೋಡ್, Responses API ಗಾಗಿ ಹಿನ್ನೆಲೆ ಮೋಡ್ ಗುಣಮಟ್ಟ ಇಳಿಕೆ

## 🤖 CLI ಏಜೆಂಟ್ಗಳು _(v2.0.11+)_

CLI ಏಜೆಂಟ್ಗಳನ್ನು ಪತ್ತೆಹಚ್ಚಲು ಮತ್ತು ನಿರ್ವಹಿಸಲು ಡ್ಯಾಶ್ಬೋರ್ಡ್. 16 ಅಂತರ್ನಿರ್ಮಿತ ಏಜೆಂಟ್ಗಳ (Codex, Claude, Goose, OpenClaw, Aider, OpenCode, Cline, ForgeCode, Amazon Q, Open Interpreter, Cursor CLI, Warp, **Windsurf**, **Devin CLI**, **Kimi Coding**, **Command Code**) ಗ್ರಿಡ್ ಅನ್ನು ಈ ಕೆಳಗಿನವುಗಳೊಂದಿಗೆ ತೋರಿಸುತ್ತದೆ:

- **ಇನ್ಸ್ಟಾಲೇಶನ್ ಸ್ಥಿತಿ** — ಆವೃತ್ತಿ ಪತ್ತೆಯೊಂದಿಗೆ ಇನ್ಸ್ಟಾಲ್ ಆಗಿದೆ / ಕಂಡುಬಂದಿಲ್ಲ
- **ಪ್ರೋಟೋಕಾಲ್ ಬ್ಯಾಡ್ಜ್ಗಳು** — stdio, HTTP, ಇತ್ಯಾದಿ.
- **ಕಸ್ಟಮ್ ಏಜೆಂಟ್ಗಳು** — ಫಾರ್ಮ್ ಮೂಲಕ ಯಾವುದೇ CLI ಪರಿಕರವನ್ನು ನೋಂದಾಯಿಸಿ (ಹೆಸರು, ಬೈನರಿ, ಆವೃತ್ತಿ ಕಮಾಂಡ್, ಸ್ಪಾನ್ ಆರ್ಗ್ಯುಮೆಂಟ್ಗಳು)
- **CLI ಫಿಂಗರ್ಪ್ರಿಂಟ್ ಹೊಂದಾಣಿಕೆ** — ಪ್ರಾಕ್ಸಿ IP ಅನ್ನು ಉಳಿಸಿಕೊಂಡೇ ನಿಷೇಧದ ಅಪಾಯವನ್ನು ಕಡಿಮೆ ಮಾಡಲು, ಮೂಲ CLI ವಿನಂತಿ ಸಿಗ್ನೇಚರ್ಗಳಿಗೆ ಹೊಂದಾಣಿಕೆ ಮಾಡುವ ಪ್ರತಿ-ಪೂರೈಕೆದಾರ ಟಾಗಲ್
- **ಸ್ಥಳೀಯ Devin ದೃಢೀಕರಣ** — Devin CLI `devin auth login` ಅನ್ನು ಬಳಸುತ್ತದೆ; ಯಾವುದೇ ಬ್ರೌಸರ್ OAuth ಪ್ರಕ್ರಿಯೆಯ ಅಗತ್ಯವಿಲ್ಲ

## 🔗 ಸಂದರ್ಭ ರಿಲೇ _(v3.5.5+)_

ಸಂಭಾಷಣೆಯ ಮಧ್ಯದಲ್ಲಿ ಖಾತೆ ಬದಲಾವಣೆ ಸಂಭವಿಸಿದಾಗಲೂ ಸೆಷನ್ನ ನಿರಂತರತೆಯನ್ನು ಕಾಪಾಡುವ ಕಾಂಬೊ ತಂತ್ರ. ಸಕ್ರಿಯ ಖಾತೆಯ ಕೋಟಾ ಮುಗಿಯುವ ಮೊದಲು, OmniRoute ಹಿನ್ನೆಲೆಯಲ್ಲಿ ರಚನಾತ್ಮಕ ಹಸ್ತಾಂತರ ಸಾರಾಂಶವನ್ನು ಸೃಷ್ಟಿಸುತ್ತದೆ. ಮುಂದಿನ ವಿನಂತಿಯು ಬೇರೆ ಖಾತೆಗೆ ಪರಿಹರಿಸಲ್ಪಟ್ಟ ನಂತರ, ಹೊಸ ಖಾತೆಯು ಸಂಪೂರ್ಣ ಸಂದರ್ಭದೊಂದಿಗೆ ಮುಂದುವರಿಯುವಂತೆ ಸಾರಾಂಶವನ್ನು ಸಿಸ್ಟಮ್ ಸಂದೇಶವಾಗಿ ಸೇರಿಸಲಾಗುತ್ತದೆ.

ಕಾಂಬೊ-ಮಟ್ಟದ ಅಥವಾ ಜಾಗತಿಕ ಸೆಟ್ಟಿಂಗ್ಗಳ ಮೂಲಕ ಕಾನ್ಫಿಗರ್ ಮಾಡಬಹುದು:

- **ಹಸ್ತಾಂತರ ಮಿತಿ** — ಸಾರಾಂಶ ರಚನೆಯನ್ನು ಪ್ರಚೋದಿಸುವ ಕೋಟಾ ಬಳಕೆಯ ಶೇಕಡಾವಾರು (ಡೀಫಾಲ್ಟ್ 85%)
- **ಸಾರಾಂಶಕ್ಕಾಗಿ ಗರಿಷ್ಠ ಸಂದೇಶಗಳು** — ಇತ್ತೀಚಿನ ಇತಿಹಾಸದಲ್ಲಿ ಎಷ್ಟು ಭಾಗವನ್ನು ಸಂಕ್ಷಿಪ್ತಗೊಳಿಸಬೇಕು
- **ಸಾರಾಂಶ ಮಾದರಿ** — ಹಸ್ತಾಂತರ ಸಾರಾಂಶವನ್ನು ರಚಿಸಲು ಐಚ್ಛಿಕ ಪರ್ಯಾಯ ಮಾದರಿ

ಪ್ರಸ್ತುತ Codex ಖಾತೆ ಬದಲಾವಣೆಯನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ. [ಸಂದರ್ಭ ರಿಲೇ ದಸ್ತಾವೇಜು](../architecture/ARCHITECTURE.md) ನೋಡಿ.

## 🗜️ ಪ್ರಾಂಪ್ಟ್ ಸಂಕುಚನ _(v3.7.9+)_

ಸಂದರ್ಭ ಮತ್ತು ಕ್ಯಾಶ್ ಈಗ Caveman, RTK ಮತ್ತು ಸಂಕುಚನ ಕಾಂಬೊಗಳಿಗೆ ಮೀಸಲಾದ ಪುಟಗಳನ್ನು ಒದಗಿಸುತ್ತದೆ:

- **Caveman** — ಭಾಷೆ-ಅರಿತ ನಿಯಮ ಪ್ಯಾಕ್ಗಳು, ಮುನ್ನೋಟ, ಔಟ್ಪುಟ್-ಮೋಡ್ ನಿಯಂತ್ರಣಗಳು ಮತ್ತು ವಿಶ್ಲೇಷಣೆ
- **RTK** — ಶೆಲ್, git, ಪರೀಕ್ಷೆ, ಬಿಲ್ಡ್, ಪ್ಯಾಕೇಜ್, Docker, ಇನ್ಫ್ರಾ, JSON ಮತ್ತು ಸ್ಟ್ಯಾಕ್-ಟ್ರೇಸ್ ಔಟ್ಪುಟ್ಗಾಗಿ ಕಮಾಂಡ್-ಅರಿತ ಸಂಕುಚನ
- **ಸಂಕುಚನ ಕಾಂಬೊಗಳು** — ರೂಟಿಂಗ್ ಕಾಂಬೊಗಳಿಗೆ ನಿಯೋಜಿಸಲಾದ `rtk -> caveman` ನಂತಹ ಹೆಸರಿಸಲಾದ ಪೈಪ್ಲೈನ್ಗಳು; ಎರಡೂ ಎಂಜಿನ್ಗಳು ಅನ್ವಯಿಸಿದಾಗ ಡೀಫಾಲ್ಟ್ ಸ್ಟ್ಯಾಕ್ ಮಾಡಿದ ಲೆಕ್ಕಾಚಾರವು ಸರಾಸರಿ `~89%` ಮತ್ತು ಅರ್ಹ ಸಂದರ್ಭದ `78-95%` ಉಳಿತಾಯವನ್ನು ತಲುಪುತ್ತದೆ
- **ಕಚ್ಚಾ ಔಟ್ಪುಟ್ ಮರುಪಡೆಯುವಿಕೆ** — ಸಂಕುಚಿತ ವೈಫಲ್ಯಗಳನ್ನು ಡೀಬಗ್ ಮಾಡಲು ಐಚ್ಛಿಕವಾಗಿ ಪರಿಷ್ಕರಿಸಲಾದ RTK ಕಚ್ಚಾ-ಔಟ್ಪುಟ್ ಪಾಯಿಂಟರ್ಗಳು

[ಸಂಕುಚನ ಮಾರ್ಗದರ್ಶಿ](../compression/COMPRESSION_GUIDE.md), [RTK ಸಂಕುಚನ](../compression/RTK_COMPRESSION.md), ಮತ್ತು
[ಸಂಕುಚನ ಎಂಜಿನ್ಗಳು](../compression/COMPRESSION_ENGINES.md) ನೋಡಿ.

## 🛡️ ಪ್ರಾಕ್ಸಿ ಬಲಪಡಿಸುವಿಕೆ _(v3.5.5+)_

ಸಂಪೂರ್ಣ ವಿನಂತಿ ಪೈಪ್ಲೈನ್ನಾದ್ಯಂತ ಸಮಗ್ರ ಪ್ರಾಕ್ಸಿ ಕಾನ್ಫಿಗರೇಶನ್ ಜಾರಿಗೊಳಿಸುವಿಕೆ:

- **ಟೋಕನ್ ಸ್ಥಿತಿ ಪರಿಶೀಲನೆ** — ಹಿನ್ನೆಲೆಯ OAuth ರಿಫ್ರೆಶ್ ಈಗ ಪ್ರತಿ ಸಂಪರ್ಕಕ್ಕೂ ಪ್ರಾಕ್ಸಿ ಕಾನ್ಫಿಗರೇಶನ್ ಅನ್ನು ಪರಿಹರಿಸುತ್ತದೆ, ಇದರಿಂದ ಪ್ರಾಕ್ಸಿ ಅಗತ್ಯವಿರುವ ಪರಿಸರಗಳಲ್ಲಿ ವೈಫಲ್ಯಗಳನ್ನು ತಡೆಯುತ್ತದೆ
- **API ಕೀ ಮೌಲ್ಯೀಕರಣ** — ಪ್ರೊವೈಡರ್ ಕೀ ಮೌಲ್ಯೀಕರಣವು (`POST /api/providers/validate`) `runWithProxyContext` ಮೂಲಕ ರೂಟ್ ಆಗುತ್ತದೆ ಹಾಗೂ ಪ್ರೊವೈಡರ್-ಮಟ್ಟದ ಮತ್ತು ಜಾಗತಿಕ ಪ್ರಾಕ್ಸಿ ಸೆಟ್ಟಿಂಗ್ಗಳನ್ನು ಗೌರವಿಸುತ್ತದೆ
- **undici ಡಿಸ್ಪ್ಯಾಚರ್ ಸರಿಪಡಿಕೆ** — ಪ್ರಾಕ್ಸಿ ಡಿಸ್ಪ್ಯಾಚರ್ಗಳು Nodeನ ಅಂತರ್ನಿರ್ಮಿತ fetch ಬದಲಿಗೆ undiciಯ ಸ್ವಂತ fetch ಅನುಷ್ಠಾನವನ್ನು ಬಳಸುತ್ತವೆ, ಇದರಿಂದ Node.js 22ನಲ್ಲಿ ಉಂಟಾಗುವ `invalid onRequestStart method` ದೋಷಗಳು ಪರಿಹಾರವಾಗುತ್ತವೆ
- **Node.js ಆವೃತ್ತಿ ಪತ್ತೆ** — ಲಾಗಿನ್ ಪುಟವು ಹೊಂದಾಣಿಕೆಯಾಗದ Node.js ಆವೃತ್ತಿಗಳನ್ನು (24+) ಮುಂಚಿತವಾಗಿ ಪತ್ತೆಹಚ್ಚಿ, Node 22 LTS ಬಳಸುವ ಸೂಚನೆಗಳಿರುವ ಎಚ್ಚರಿಕೆ ಬ್ಯಾನರ್ ಅನ್ನು ಪ್ರದರ್ಶಿಸುತ್ತದೆ

- **ಪ್ರತಿ-ಮಾದರಿ ಗೋಚರತೆ ಟಾಗಲ್** (👁 ಐಕಾನ್) — ಮರೆಮಾಡಿದ ಮಾದರಿಗಳು ಮಸುಕಾಗಿ ಕಾಣಿಸುತ್ತವೆ ಮತ್ತು `/v1/models` ಕ್ಯಾಟಲಾಗ್ನಿಂದ ಹೊರಗಿಡಲ್ಪಡುತ್ತವೆ
- **ಸಕ್ರಿಯ-ಎಣಿಕೆ ಬ್ಯಾಡ್ಜ್** (`N/M active`) — ಒಟ್ಟು ಮಾದರಿಗಳಿಗೆ ಹೋಲಿಸಿದರೆ ಎಷ್ಟು ಮಾದರಿಗಳನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಲಾಗಿದೆ ಎಂಬುದನ್ನು ಒಂದು ನೋಟದಲ್ಲೇ ತೋರಿಸುತ್ತದೆ

- ಸರ್ವರ್ ಸಿದ್ಧತೆಯ ಪೋಲಿಂಗ್ (ಕೋಲ್ಡ್ ಸ್ಟಾರ್ಟ್ನಲ್ಲಿ ಖಾಲಿ ಪರದೆ ಇರುವುದಿಲ್ಲ)

- ವಿಷಯ ಭದ್ರತಾ ನೀತಿ
- ಏಕ-ಇನ್ಸ್ಟೆನ್ಸ್ ಲಾಕ್
- ಮರುಪ್ರಾರಂಭಿಸಿದಾಗ ಸ್ವಯಂ-ನವೀಕರಣ
- ಪ್ಲಾಟ್ಫಾರ್ಮ್-ಷರತ್ತುಬದ್ಧ UI (macOS ಟ್ರಾಫಿಕ್ ಲೈಟ್ಗಳು, Windows/Linux ಡೀಫಾಲ್ಟ್ ಶೀರ್ಷಿಕೆಪಟ್ಟಿ)
- ಬಲಪಡಿಸಿದ Electron ಬಿಲ್ಡ್ ಪ್ಯಾಕೇಜಿಂಗ್ — ಸ್ವತಂತ್ರ ಬಂಡಲ್ನಲ್ಲಿರುವ ಸಿಮ್ಲಿಂಕ್ ಮಾಡಲಾದ `node_modules` ಅನ್ನು ಪ್ಯಾಕೇಜಿಂಗ್ಗೆ ಮೊದಲು ಪತ್ತೆಹಚ್ಚಿ ತಿರಸ್ಕರಿಸಲಾಗುತ್ತದೆ, ಇದರಿಂದ ಬಿಲ್ಡ್ ಯಂತ್ರದ ಮೇಲಿನ ರನ್ಟೈಮ್ ಅವಲಂಬನೆಯನ್ನು ತಡೆಯಲಾಗುತ್ತದೆ (v2.5.5+)

## 🌐 V1 WebSocket ಬ್ರಿಡ್ಜ್ _(v3.6.6+)_

OmniRoute ಈಗ `/v1/ws` ಅಪ್ಗ್ರೇಡ್ ಎಂಡ್ಪಾಯಿಂಟ್ ಮೂಲಕ **OpenAI-ಹೊಂದಾಣಿಕೆಯ WebSocket ಕ್ಲೈಂಟ್ಗಳನ್ನು** ಬೆಂಬಲಿಸುತ್ತದೆ. ಕಸ್ಟಮ್ `scripts/dev/v1-ws-bridge.mjs` ಸರ್ವರ್ Next.js ಅನ್ನು ರ್ಯಾಪ್ ಮಾಡುತ್ತದೆ ಮತ್ತು WS ಸಂಪರ್ಕಗಳನ್ನು ಸಂಪೂರ್ಣ ದ್ವಿಮುಖ ಸ್ಟ್ರೀಮಿಂಗ್ ಸೆಷನ್ಗಳಿಗೆ ಅಪ್ಗ್ರೇಡ್ ಮಾಡುತ್ತದೆ. ದೃಢೀಕರಣವು HTTP ವಿನಂತಿಗಳಲ್ಲಿರುವ ಅದೇ API ಕೀ ಅಥವಾ ಸೆಷನ್ ಕುಕೀಯನ್ನು ಬಳಸುತ್ತದೆ.

ಪ್ರಮುಖ ನಡವಳಿಕೆಗಳು:

- ಸಂಪರ್ಕ ಸ್ಥಾಪನೆಯಾಗುವ ಮೊದಲು WS ಅಪ್ಗ್ರೇಡ್ ಅನ್ನು `src/lib/ws/handshake.ts` ಮೂಲಕ ಮೌಲ್ಯೀಕರಿಸಲಾಗುತ್ತದೆ
- ಸೆಷನ್ ಮುಚ್ಚಿದಾಗ ಅಥವಾ ಅಪ್ಸ್ಟ್ರೀಮ್ ದೋಷ ಸಂಭವಿಸಿದಾಗ ಸ್ಟ್ರೀಮ್ಗಳನ್ನು ಸಮರ್ಪಕವಾಗಿ ಕೊನೆಗೊಳಿಸಲಾಗುತ್ತದೆ
- ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ HTTP+SSE ಸ್ಟ್ರೀಮಿಂಗ್ ಪಥದೊಂದಿಗೆ ಏಕಕಾಲದಲ್ಲಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ

## 🔑 ಸಿಂಕ್ ಟೋಕನ್ಗಳು ಮತ್ತು ಕಾನ್ಫಿಗ್ ಬಂಡಲ್ _(v3.6.6+)_

ಈಗ **ವ್ಯಾಪ್ತಿ-ನಿರ್ದಿಷ್ಟ ಸಿಂಕ್ ಟೋಕನ್ಗಳ** ಮೂಲಕ ಬಹು-ಸಾಧನ ಮತ್ತು ಬಾಹ್ಯ ಆಪರೇಟರ್ ಪ್ರವೇಶ ಸಾಧ್ಯ:

- **`POST /api/sync/tokens`** — ಹೊಸ ಸಿಂಕ್ ಟೋಕನ್ ನೀಡಿ (ವ್ಯಾಪ್ತಿ-ನಿರ್ದಿಷ್ಟ, ಐಚ್ಛಿಕ ಅವಧಿ ಮುಕ್ತಾಯದೊಂದಿಗೆ)
- **`DELETE /api/sync/tokens/:id`** — ಟೋಕನ್ ಅನ್ನು ಹಿಂಪಡೆಯಿರಿ
- **`GET /api/sync/bundle`** — ಎಲ್ಲಾ ಸೂಕ್ಷ್ಮವಲ್ಲದ ಸೆಟ್ಟಿಂಗ್ಗಳ ಆವೃತ್ತೀಕರಿಸಿದ, ETag-ಕೀಲಿಯ JSON ಸ್ನ್ಯಾಪ್ಶಾಟ್ ಅನ್ನು ಡೌನ್ಲೋಡ್ ಮಾಡಿ (ಪಾಸ್ವರ್ಡ್ಗಳನ್ನು ಮರೆಮಾಡಲಾಗಿದೆ)

ಕಾನ್ಫಿಗ್ ಬಂಡಲ್ ಅನ್ನು `src/lib/sync/bundle.ts` ನಿರ್ಮಿಸುತ್ತದೆ. ಪೂರ್ಣ ಪೇಲೋಡ್ ಅನ್ನು ಮರು-ಡೌನ್ಲೋಡ್ ಮಾಡದೆಯೇ ಬದಲಾವಣೆಗಳನ್ನು ಪತ್ತೆಹಚ್ಚಲು ಬಳಕೆದಾರ ಅಪ್ಲಿಕೇಶನ್ಗಳು `ETag` ಪ್ರತಿಕ್ರಿಯೆ ಹೆಡರ್ ಅನ್ನು ಹೋಲಿಸುತ್ತವೆ.

## 🧠 GLM ಥಿಂಕಿಂಗ್ ಪೂರ್ವನಿಗದಿ _(v3.6.6+)_

## 🛡️ ಸುರಕ್ಷಿತ ಔಟ್ಬೌಂಡ್ ಫೆಚ್ ಮತ್ತು SSRF ರಕ್ಷಣೆ _(v3.6.6+)_

ಎಲ್ಲಾ ಪೂರೈಕೆದಾರ ಮೌಲ್ಯೀಕರಣ ಮತ್ತು ಮಾಡೆಲ್ ಅನ್ವೇಷಣೆ ಕರೆಗಳು ಈಗ ಎರಡು-ಪದರದ ಔಟ್ಬೌಂಡ್ ರಕ್ಷಣೆಯ ಮೂಲಕ ಸಾಗುತ್ತವೆ:

1. **URL ರಕ್ಷಣೆ** (`src/shared/network/outboundUrlGuard.ts`) — ಸಾಕೆಟ್ ತೆರೆಯುವ ಮೊದಲು ಖಾಸಗಿ/ಲೂಪ್ಬ್ಯಾಕ್/ಲಿಂಕ್-ಲೋಕಲ್ IP ಶ್ರೇಣಿಗಳನ್ನು ನಿರ್ಬಂಧಿಸುತ್ತದೆ.
2. **ಸುರಕ್ಷಿತ ಫೆಚ್ ರ್ಯಾಪರ್** (`src/shared/network/safeOutboundFetch.ts`) — URL ರಕ್ಷಣೆಯನ್ನು ಅನ್ವಯಿಸುತ್ತದೆ, ಕಾಲಮಿತಿಗಳನ್ನು ಸಾಮಾನ್ಯೀಕರಿಸುತ್ತದೆ ಮತ್ತು ಘಾತೀಯ ಬ್ಯಾಕ್ಆಫ್ನೊಂದಿಗೆ ತಾತ್ಕಾಲಿಕ ದೋಷಗಳಿಗೆ ಮರುಪ್ರಯತ್ನಿಸುತ್ತದೆ.

ರಕ್ಷಣೆ ಉಲ್ಲಂಘನೆಗಳು HTTP 422 (`URL_GUARD_BLOCKED`) ರೂಪದಲ್ಲಿ ಗೋಚರಿಸುತ್ತವೆ ಮತ್ತು `providerAudit.ts` ಮೂಲಕ ಅನುಸರಣೆ ಆಡಿಟ್ ಲಾಗ್ಗೆ ಬರೆಯಲ್ಪಡುತ್ತವೆ.

## 🔄 ಕೂಲ್ಡೌನ್-ಅರಿವಿನ ಮರುಪ್ರಯತ್ನಗಳು _(v3.6.6+)_

ಅಪ್ಸ್ಟ್ರೀಮ್ ಪೂರೈಕೆದಾರರು ಮಾಡೆಲ್-ವ್ಯಾಪ್ತಿಯ ಕೂಲ್ಡೌನ್ ಅನ್ನು ಹಿಂದಿರುಗಿಸಿದಾಗ, ಚಾಟ್ ವಿನಂತಿಗಳು ಈಗ **ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಮರುಪ್ರಯತ್ನಿಸುತ್ತವೆ**. `REQUEST_RETRY` (ಡೀಫಾಲ್ಟ್: 2) ಮತ್ತು `MAX_RETRY_INTERVAL_SEC` (ಡೀಫಾಲ್ಟ್: 30 s) ಮೂಲಕ ಕಾನ್ಫಿಗರ್ ಮಾಡಬಹುದು. `x-ratelimit-reset-requests`, `x-ratelimit-reset-tokens` ಮತ್ತು `Retry-After` ಗಳಾದ್ಯಂತ ದರ-ಮಿತಿ ಹೆಡರ್ ಕಲಿಕೆಯನ್ನು ಸುಧಾರಿಸಲಾಗಿದೆ — ಪ್ರತಿ-ಮಾಡೆಲ್ ಕೂಲ್ಡೌನ್ ಸ್ಥಿತಿಯು Resilience ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿ ಗೋಚರಿಸುತ್ತದೆ.

## 📋 ಅನುಸರಣೆ ಆಡಿಟ್ v2 _(v3.6.6+)_

ಕರ್ಸರ್-ಆಧಾರಿತ ಪುಟೀಕರಣ, ವಿನಂತಿ ಸಂದರ್ಭ ಪುಷ್ಟೀಕರಣ (ವಿನಂತಿ ID, ಬಳಕೆದಾರ ಏಜೆಂಟ್, IP), ರಚನಾತ್ಮಕ ದೃಢೀಕರಣ ಘಟನೆಗಳು, ವ್ಯತ್ಯಾಸ ಸಂದರ್ಭದೊಂದಿಗೆ ಪೂರೈಕೆದಾರ CRUD ಘಟನೆಗಳು ಮತ್ತು SSRF-ನಿರ್ಬಂಧಿತ ಮೌಲ್ಯೀಕರಣ ಲಾಗಿಂಗ್ನೊಂದಿಗೆ ಆಡಿಟ್ ಲಾಗ್ ಅನ್ನು ವಿಸ್ತರಿಸಲಾಗಿದೆ. ಹೊಸ ಘಟನೆಗಳನ್ನು `src/lib/compliance/providerAudit.ts` ಹೊರಸೂಸುತ್ತದೆ.
