> **ಸಂಕ್ಷಿಪ್ತವಾಗಿ**: OmniRoute ಪ್ರತಿ ವಿನಂತಿಯ ಟೋಕನ್ ಬಳಕೆಯನ್ನು ಟ್ರ್ಯಾಕ್ ಮಾಡುತ್ತದೆ, ವೆಚ್ಚವನ್ನು ಲೆಕ್ಕಾಚಾರ ಮಾಡುತ್ತದೆ, ಪ್ರತಿ API ಕೀಗೆ ಕೋಟಾವನ್ನು ಜಾರಿಗೊಳಿಸುತ್ತದೆ ಮತ್ತು ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿ ವಿಶ್ಲೇಷಣೆಯನ್ನು ಪ್ರದರ್ಶಿಸುತ್ತದೆ. ಇವೆಲ್ಲವೂ ಹೇಗೆ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತವೆ ಎಂಬುದನ್ನು ಈ ಮಾರ್ಗದರ್ಶಿ ವಿವರಿಸುತ್ತದೆ.

**ಮೂಲಗಳು:**

- `open-sse/services/usage.ts` (~70KB) — ಮುಖ್ಯ ಬಳಕೆ ಟ್ರ್ಯಾಕಿಂಗ್
- `src/lib/usageAnalytics.ts` (~10KB) — ಡ್ಯಾಶ್ಬೋರ್ಡ್ಗಾಗಿ ಒಟ್ಟುಗೂಡಿಸುವಿಕೆ
- `src/lib/db/quotaSnapshots.ts` — ಐತಿಹಾಸಿಕ ಕೋಟಾ ಡೇಟಾ
- `src/lib/db/usage*.ts` — ಬಳಕೆಗೆ ಸಂಬಂಧಿಸಿದ ಹಲವು DB ಮಾಡ್ಯೂಲ್ಗಳು

## ಅವಲೋಕನ

OmniRoute ಮೂಲಕ ಸಾಗುವ ಪ್ರತಿಯೊಂದು ವಿನಂತಿಯೂ ಈ ವಿವರಗಳನ್ನು ದಾಖಲಿಸುವ **ಬಳಕೆ ದಾಖಲೆ**ಯನ್ನು ರಚಿಸುತ್ತದೆ:

- **ಗುರುತು**: ಯಾವ API ಕೀ, ಪೂರೈಕೆದಾರ, ಮಾದರಿ, ಕಾಂಬೊ
- **ಟೋಕನ್ಗಳು**: ಪ್ರಾಂಪ್ಟ್ ಟೋಕನ್ಗಳು, ಪೂರ್ಣಗೊಳಿಸುವಿಕೆ ಟೋಕನ್ಗಳು, ಕ್ಯಾಶ್ ಮಾಡಿದ ಟೋಕನ್ಗಳು, ಒಟ್ಟು
- **ವೆಚ್ಚ**: USD ಮೊತ್ತ (ಬೆಲೆ ಡೇಟಾದಿಂದ ಲೆಕ್ಕಾಚಾರ ಮಾಡಲಾಗಿದೆ)
- **ಸಮಯ**: ವಿಳಂಬ, ಪ್ರಾರಂಭ/ಅಂತ್ಯದ ಟೈಮ್ಸ್ಟ್ಯಾಂಪ್ಗಳು
- **ಸ್ಥಿತಿ**: ಯಶಸ್ಸು, ದೋಷ, ದರ-ಮಿತಿಗೊಳಿಸಲಾಗಿದೆ, ಇತ್ಯಾದಿ.

ಈ ದಾಖಲೆಗಳನ್ನು **ವಿಶ್ಲೇಷಣೆ**ಯಾಗಿ ಒಟ್ಟುಗೂಡಿಸಲಾಗುತ್ತದೆ, **ಕೋಟಾ ಸ್ನ್ಯಾಪ್ಶಾಟ್ಗಳು** ಆಗಿ ಉಳಿಸಲಾಗುತ್ತದೆ ಮತ್ತು **ಪ್ರತಿ-ಕೀ ಬಜೆಟ್ ಮಿತಿಗಳನ್ನು** ಜಾರಿಗೊಳಿಸಲು ಬಳಸಲಾಗುತ್ತದೆ.

```
ವಿನಂತಿ ──▶ chatCore ──▶ usage.record() ──▶ SQLite
                                  │
                          ┌───────┼───────┐
                          ▼       ▼       ▼
                    ವಿಶ್ಲೇಷಣೆ   ಕೋಟಾ    ಬಿಲ್ಲಿಂಗ್
                   (ಡ್ಯಾಶ್ಬೋರ್ಡ್) (ಜಾರಿ) (ರಫ್ತು)
```

## ಏನೇನು ದಾಖಲಿಸಲಾಗುತ್ತದೆ

`usage.ts` ಸೇವೆಯು ಪ್ರತಿಯೊಂದು ವಿನಂತಿಗೂ ಒಂದು **ಬಳಕೆ ಈವೆಂಟ್** ಅನ್ನು ದಾಖಲಿಸುತ್ತದೆ:

| ಫೀಲ್ಡ್             | ಪ್ರಕಾರ  | ಮೂಲ                                                           |
| ------------------ | ------- | ------------------------------------------------------------- |
| `id`               | string  | ದಾಖಲಿಸುವಾಗ ರಚಿಸಲಾದ UUID                                       |
| `apiKeyId`         | string  | ವಿನಂತಿಯನ್ನು ಪ್ರಾರಂಭಿಸಿದ API ಕೀ                                |
| `provider`         | string  | ಪೂರೈಕೆದಾರ ID (openai, anthropic, ಇತ್ಯಾದಿ)                     |
| `model`            | string  | ಮಾದರಿ ID (gpt-5, claude-opus-4-6, ಇತ್ಯಾದಿ)                    |
| `comboId`          | string? | ಕಾಂಬೊ ಮೂಲಕ ರೂಟ್ ಮಾಡಿದ್ದರೆ ಕಾಂಬೊ ID                            |
| `promptTokens`     | number  | ಅಪ್ಸ್ಟ್ರೀಮ್ ಪ್ರತಿಕ್ರಿಯೆಯಿಂದ                                   |
| `completionTokens` | number  | ಅಪ್ಸ್ಟ್ರೀಮ್ ಪ್ರತಿಕ್ರಿಯೆಯಿಂದ                                   |
| `cachedTokens`     | number  | ಕ್ಯಾಶ್ ಹಿಟ್ ಟೋಕನ್ಗಳು (Anthropic ಪ್ರಾಂಪ್ಟ್ ಕ್ಯಾಶಿಂಗ್, ಇತ್ಯಾದಿ) |
| `totalTokens`      | number  | ಪ್ರಾಂಪ್ಟ್ + ಪೂರ್ಣಗೊಳಿಸುವಿಕೆ                                   |
| `costUsd`          | number  | ಬೆಲೆ ಡೇಟಾದಿಂದ ಲೆಕ್ಕಾಚಾರ ಮಾಡಲಾಗಿದೆ                             |
| `latencyMs`        | number  | ಆರಂಭದಿಂದ ಅಂತ್ಯದವರೆಗಿನ ವಿನಂತಿಯ ಅವಧಿ                            |
| `status`           | enum    | `success`, `error`, `rate_limited`, `timeout`, `cancelled`    |
| `errorClass`       | string? | status != success ಆಗಿದ್ದರೆ ದೋಷದ ವರ್ಗ                          |
| `timestamp`        | string  | ISO 8601 UTC                                                  |
| `metadata`         | object  | ಕಸ್ಟಮ್ ಪ್ಲಗಿನ್ ಸೇರಿಸಿದ ಡೇಟಾ                                   |

### ಟೋಕನ್ಗಳು ಎಲ್ಲಿಂದ ಬರುತ್ತವೆ

**ಪ್ರತಿಕ್ರಿಯೆ ಹ್ಯಾಂಡ್ಲರ್**ನಲ್ಲಿ ಅಪ್ಸ್ಟ್ರೀಮ್ ಪೂರೈಕೆದಾರರ ಪ್ರತಿಕ್ರಿಯೆಯಿಂದ ಟೋಕನ್ಗಳನ್ನು ಹೊರತೆಗೆಯಲಾಗುತ್ತದೆ:

```ts
// open-sse/handlers/chatCore.ts ನಿಂದ
const response = await providerExecutor.execute(provider, request);
const usage = response.usage || {
  prompt_tokens: 0,
  completion_tokens: 0,
  cached_tokens: 0,
};
```

ಬಳಕೆಯ ವಿವರಗಳನ್ನು ಹಿಂತಿರುಗಿಸದ ಪೂರೈಕೆದಾರರಿಗಾಗಿ (ಕೆಲವು ವೆಬ್-ಕುಕೀ ಪೂರೈಕೆದಾರರು), OmniRoute `~4 chars per token` ಹ್ಯೂರಿಸ್ಟಿಕ್ ಬಳಸಿ ಟೋಕನ್ಗಳನ್ನು **ಅಂದಾಜಿಸುತ್ತದೆ** (`open-sse/services/autoCombo/pipelineRouter.ts` ನೋಡಿ).

### ಕ್ಯಾಶ್ ಮಾಡಿದ ಟೋಕನ್ಗಳು

OmniRoute `cached_tokens` ಅನ್ನು `prompt_tokens` ನಿಂದ ಪ್ರತ್ಯೇಕವಾಗಿ ಟ್ರ್ಯಾಕ್ ಮಾಡುತ್ತದೆ, ಏಕೆಂದರೆ:

- Anthropic ಪ್ರಾಂಪ್ಟ್ ಕ್ಯಾಶಿಂಗ್, ಕ್ಯಾಶ್ ಮಾಡಿದ ಟೋಕನ್ಗಳಿಗೆ ಕಡಿಮೆ ದರವನ್ನು ವಿಧಿಸುತ್ತದೆ (ಸಾಮಾನ್ಯ ದರದ 10%)
- ಕೆಲವು ಪೂರೈಕೆದಾರರು ವಿಭಿನ್ನವಾಗಿ ಬೆಲೆ ನಿಗದಿಪಡಿಸಬೇಕಾದ `cache_read_input_tokens` ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತಾರೆ
- ವಿಶ್ಲೇಷಣೆಯು **ಕ್ಯಾಶ್ ಹಿಟ್ ದರ** = `cached_tokens / prompt_tokens` ಅನ್ನು ತೋರಿಸಬಹುದು

## ವೆಚ್ಚದ ಲೆಕ್ಕಾಚಾರ

LiteLLM ನಿಂದ ಸಿಂಕ್ ಮಾಡಲಾದ **ಬೆಲೆ ದತ್ತಾಂಶ** (`src/lib/pricingSync.ts`) ಬಳಸಿ ವೆಚ್ಚಗಳನ್ನು ಲೆಕ್ಕಹಾಕಲಾಗುತ್ತದೆ:

| ಮಾದರಿ             | ಇನ್ಪುಟ್ $/1M | ಔಟ್ಪುಟ್ $/1M | ಕ್ಯಾಶ್ ಮಾಡಿದ $/1M |
| ----------------- | ------------ | ------------ | ----------------- |
| gpt-5             | $2.50        | $10.00       | —                 |
| claude-opus-4-6   | $15.00       | $75.00       | $1.50             |
| claude-sonnet-4-5 | $3.00        | $15.00       | $0.30             |
| gemini-2.5-pro    | $1.25        | $10.00       | —                 |

ವೆಚ್ಚದ ಸೂತ್ರ (`src/lib/usage/costCalculator.ts`):

```ts
cost =
  (prompt_tokens - cached_tokens) * input_price +
  cached_tokens * cached_price +
  completion_tokens * output_price;
```

> **ಪ್ರಾಂಪ್ಟ್ನಿಂದ ಕ್ಯಾಶ್ ಮಾಡಲಾದ ಭಾಗವನ್ನು ಏಕೆ ಕಳೆಯಬೇಕು?** ಕ್ಯಾಶ್ ಮಾಡಲಾದ ಭಾಗಕ್ಕೆ ಪ್ರತ್ಯೇಕವಾಗಿ ಬೆಲೆ ನಿಗದಿಪಡಿಸಲಾಗುತ್ತದೆ; ಸಂಪೂರ್ಣ ಪ್ರಾಂಪ್ಟ್ಗೆ ಇನ್ಪುಟ್ ಬೆಲೆಯನ್ನು ವಿಧಿಸಿದರೆ ಹೆಚ್ಚುವರಿಯಾಗಿ ಲೆಕ್ಕ ಹಾಕಿದಂತಾಗುತ್ತದೆ.

### ಬೆಲೆ ಸಿಂಕ್

ಅಂತರ್ನಿರ್ಮಿತ cron ಕಾರ್ಯದಿಂದ ಪ್ರಚೋದಿಸಲ್ಪಡುವ `/api/pricing/sync` ಎಂಡ್ಪಾಯಿಂಟ್ ಮೂಲಕ LiteLLM ನಿಂದ ಬೆಲೆ ದತ್ತಾಂಶವು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಸಿಂಕ್ ಆಗುತ್ತದೆ (ಇದು ಬಳಕೆದಾರರಿಗೆ ಲಭ್ಯವಿರುವ env var ಅಲ್ಲ):

```bash
# ಹಸ್ತಚಾಲಿತ ಪ್ರಚೋದನೆ
curl -X POST http://localhost:20128/api/pricing/sync
```

ಬೆಲೆ ದತ್ತಾಂಶವಿಲ್ಲದ ಮಾದರಿಗಳಿಗೆ, ಆಂತರಿಕ ಸರಾಸರಿ ದರಗಳನ್ನು (LiteLLM ನ ಬೆಲೆ ದತ್ತಾಂಶದಿಂದ ಪಡೆದವು) ಬಳಸಿಕೊಂಡು **ವೆಚ್ಚವನ್ನು ಅಂದಾಜಿಸುವುದಕ್ಕೆ** OmniRoute ಹಿಂತಿರುಗುತ್ತದೆ.

## ದಿನಾಂಕ ವ್ಯಾಪ್ತಿಯ ಒಟ್ಟುಗೂಡಿಸುವಿಕೆ

`usageAnalytics.ts` ಮಾಡ್ಯೂಲ್ ಕಚ್ಚಾ ಬಳಕೆಯ ದತ್ತಾಂಶದಿಂದ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ವಿಜೆಟ್ಗಳನ್ನು ಲೆಕ್ಕಹಾಕುತ್ತದೆ. ಇದು 7 ಸಮಯ ವ್ಯಾಪ್ತಿಗಳನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ:

| ವ್ಯಾಪ್ತಿ | ಅವಧಿ                                  | ಬಳಕೆಯ ಸಂದರ್ಭ                                         |
| -------- | ------------------------------------- | ---------------------------------------------------- |
| `1d`     | ಕಳೆದ 24 ಗಂಟೆಗಳು                       | ಗಂಟೆಗೊಮ್ಮೆ ಸಂಭವಿಸುವ ವೆಚ್ಚದ ಏರಿಕೆಯನ್ನು ಪತ್ತೆಹಚ್ಚುವುದು |
| `7d`     | ಕಳೆದ 7 ದಿನಗಳು                         | ಸಾಪ್ತಾಹಿಕ ಪರಿಶೀಲನೆ                                   |
| `30d`    | ಕಳೆದ 30 ದಿನಗಳು                        | ಮಾಸಿಕ ಬಿಲ್ಲಿಂಗ್                                      |
| `90d`    | ಕಳೆದ 90 ದಿನಗಳು                        | ತ್ರೈಮಾಸಿಕ ವಿಶ್ಲೇಷಣೆ                                  |
| `ytd`    | ಪ್ರಸಕ್ತ ವರ್ಷದ ಜನವರಿ 1ರಿಂದ             | ವಾರ್ಷಿಕ ಬಜೆಟ್ ಮೇಲ್ವಿಚಾರಣೆ                            |
| `all`    | ಸಂಪೂರ್ಣ ಅವಧಿ                          | ಜೀವಮಾನ ಅಂಕಿಅಂಶಗಳು                                    |
| `custom` | ಬಳಕೆದಾರರು ವ್ಯಾಖ್ಯಾನಿಸಿದ ಪ್ರಾರಂಭ/ಅಂತ್ಯ | ಲೆಕ್ಕಪರಿಶೋಧನೆಗಳು, ತಾತ್ಕಾಲಿಕ ಪ್ರಶ್ನೆಗಳು               |

### ಲೆಕ್ಕಹಾಕಲಾಗುವ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ವಿಜೆಟ್ಗಳು

ಯಾವುದೇ ದಿನಾಂಕ ವ್ಯಾಪ್ತಿಗೆ, ಅನಾಲಿಟಿಕ್ಸ್ ಪದರವು ಇವುಗಳನ್ನು ಲೆಕ್ಕಹಾಕುತ್ತದೆ:

| ವಿಜೆಟ್                        | ವಿವರಣೆ                                                   |
| ----------------------------- | -------------------------------------------------------- |
| **ಸಾರಾಂಶ ಕಾರ್ಡ್ಗಳು**          | ಒಟ್ಟು ವಿನಂತಿಗಳು, ಒಟ್ಟು ವೆಚ್ಚ, ಒಟ್ಟು ಟೋಕನ್ಗಳು, ಯಶಸ್ಸಿನ ದರ |
| **ದೈನಂದಿನ ಪ್ರವೃತ್ತಿಯ ಚಾರ್ಟ್** | ಪ್ರತಿ ದಿನದ ವೆಚ್ಚ + ಟೋಕನ್ಗಳು, ಮಾದರಿಯ ಪ್ರಕಾರ ಜೋಡಿಸಲಾಗಿದೆ   |
| **ಚಟುವಟಿಕೆಯ ಹೀಟ್ಮ್ಯಾಪ್**      | ದಿನದ ಗಂಟೆ × ವಾರದ ದಿನದ ಗ್ರಿಡ್, ಬಣ್ಣ = ವಿನಂತಿಗಳ ಸಂಖ್ಯೆ     |
| **ಮಾದರಿ ವಿಭಜನೆ**              | ಮಾದರಿಯ ಪ್ರಕಾರ ವೆಚ್ಚದ ಪೈ ಚಾರ್ಟ್                           |
| **ಪೂರೈಕೆದಾರರ ವಿಭಜನೆ**         | ಪೂರೈಕೆದಾರರ ಪ್ರಕಾರ ವಿನಂತಿಗಳ ಬಾರ್ ಚಾರ್ಟ್                   |
| **ಪ್ರಮುಖ API ಕೀಗಳು**          | ವೆಚ್ಚದ ಪ್ರಕಾರ ಅಗ್ರ 10 ಕೀಗಳ ಕೋಷ್ಟಕ                        |
| **ದೋಷ ವಿಶ್ಲೇಷಣೆ**             | ಕಾಲಾನಂತರದ ದೋಷದ ದರ, ಪ್ರಮುಖ ದೋಷ ವರ್ಗಗಳು                    |

### ಪ್ರೋಗ್ರಾಮ್ಯಾಟಿಕ್ ಪ್ರವೇಶ

````ts
import { computeAnalytics } from "@/lib/usageAnalytics";

const analytics = await computeAnalytics(
  history,              // ಬಳಕೆಯ ಇತಿಹಾಸದ ದಾಖಲೆಗಳು
  "7d",                 // ಸಮಯ ವ್ಯಾಪ್ತಿ: "1d" | "7d" | "30d" | "90d" | "ytd" | "all" | "custom"
  connectionMap,        // ಪೂರೈಕೆದಾರರ ಸಂಪರ್ಕ ಮ್ಯಾಪ್ (connectionId → ಖಾತೆಯ ಹೆಸರು)
  {
    startDate: "2025-01-01",  // ಐಚ್ಛಿಕ: "custom" ವ್ಯಾಪ್ತಿಗಾಗಿ
    endDate: "2025-06-01",   // ಐಚ್ಛಿಕ: "custom" ವ್ಯಾಪ್ತಿಗಾಗಿ
  }
);

console.log(analytics.summary.totalCost);   // 12.34 (ಸೆಂಟ್ಗಳು)
console.log(analytics.byModel[0]);           // { model, cost, requests, promptTokens, completionTokens }

## ಕೋಟಾ ಜಾರಿಗೊಳಿಸುವಿಕೆ

ಪ್ರತಿ API ಕೀಗೂ ಕೋಟಾವನ್ನು ಎರಡು ಸ್ಥಳಗಳಲ್ಲಿ ಜಾರಿಗೊಳಿಸಲಾಗುತ್ತದೆ:

1. **ಮೃದು ಮಿತಿ** (`quotaWarnAt`): ಬಳಕೆ ಮಿತಿಯನ್ನು ಮೀರಿದಾಗ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಎಚ್ಚರಿಕೆ
2. **ಕಠಿಣ ಮಿತಿ** (`quotaLimit`): ಮಿತಿಯನ್ನು ಮೀರಿದಾಗ ವಿನಂತಿಯನ್ನು HTTP 429 ನೊಂದಿಗೆ ತಿರಸ್ಕರಿಸಲಾಗುತ್ತದೆ

### ಸಂರಚನೆ

```ts
// ಪ್ರತಿ API ಕೀಗಾಗಿ
await updateApiKey(keyId, {
  quotaWarnAt: 5_00,    // $5.00 — ಎಚ್ಚರಿಕೆಯನ್ನು ತೋರಿಸಿ
  quotaLimit: 10_00,    // $10.00 — ಸಂಪೂರ್ಣ ಸ್ಥಗಿತ
  quotaWindow: "month", // "day" | "week" | "month" | "all"
});
````

### ಜಾರಿಗೊಳಿಸುವಿಕೆಯ ಹರಿವು

```
ವಿನಂತಿ ──▶ quotaCheck()
              │
              ├── ಮಿತಿಯೊಳಗಿದೆಯೇ?  ──▶ ಅನುಮತಿಸಿ
              │
              └── ಮಿತಿ ಮೀರಿದೆಯೇ?  ──▶ 429 Too Many Requests
                                       Retry-After ಹೆಡರ್ನೊಂದಿಗೆ
```

### ಕೋಟಾ ಸ್ನ್ಯಾಪ್ಶಾಟ್ಗಳು

ಪ್ರವೃತ್ತಿ ವಿಶ್ಲೇಷಣೆಗಾಗಿ `quotaSnapshots` ಟೇಬಲ್ **ಐತಿಹಾಸಿಕ ಕೋಟಾ ಸ್ಥಿತಿಯನ್ನು** ಸಂಗ್ರಹಿಸುತ್ತದೆ:

| ಫೀಲ್ಡ್ | ವಿವರಣೆ |
| ----------- | -------------------------------- | ------ | ------- |
| `apiKeyId` | ಟ್ರ್ಯಾಕ್ ಮಾಡಲಾಗುತ್ತಿರುವ ಕೀ |
| `window` | "day" | "week" | "month" |
| `used` | ಈ ವಿಂಡೋದಲ್ಲಿ ಬಳಸಿದ ವೆಚ್ಚ (ಸೆಂಟ್ಗಳಲ್ಲಿ) |
| `limit` | ಮಿತಿ (ಸೆಂಟ್ಗಳಲ್ಲಿ) |
| `resetAt` | ವಿಂಡೋ ಮರುಹೊಂದುವ ಸಮಯ |
| `createdAt` | ಸ್ನ್ಯಾಪ್ಶಾಟ್ ತೆಗೆದ ಸಮಯ |

> 0 ವೆಚ್ಚವನ್ನು ಬಳಸುವ **ಪ್ರತಿ ವಿನಂತಿಯಲ್ಲೂ** ಸ್ನ್ಯಾಪ್ಶಾಟ್ಗಳನ್ನು ತೆಗೆದುಕೊಳ್ಳಲಾಗುತ್ತದೆ ಮತ್ತು ಅವುಗಳನ್ನು ಈ ಕೆಳಗಿನವುಗಳಿಗಾಗಿ ಬಳಸಲಾಗುತ್ತದೆ:

- ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿ ಕೋಟಾ ಪ್ರಗತಿ ಪಟ್ಟಿಯನ್ನು ಪ್ರದರ್ಶಿಸಲು
- 30-ದಿನಗಳ ಕೋಟಾ ಪ್ರವೃತ್ತಿ ಚಾರ್ಟ್ಗಳನ್ನು ತೋರಿಸಲು
- ಬಳಕೆ ಮಿತಿಯನ್ನು ಸಮೀಪಿಸಿದಾಗ ಎಚ್ಚರಿಕೆಗಳನ್ನು ಪ್ರಚೋದಿಸಲು

## ಉಳಿಸಿಕೆ ಮತ್ತು ಸ್ವಚ್ಛಗೊಳಿಸುವಿಕೆ

ಪ್ರತಿ ವಿನಂತಿಗೆ ಬಳಕೆಯ ಡೇಟಾ ~1-10KB ರಷ್ಟು ಹೆಚ್ಚಾಗುತ್ತದೆ. ದೊಡ್ಡ ಪ್ರಮಾಣದಲ್ಲಿ, ಇದು ಗಮನಾರ್ಹವಾಗಬಹುದು.

### ಉಳಿಸಿಕೆ ಸೆಟ್ಟಿಂಗ್ಗಳು

ಬಳಕೆಯ ಇತಿಹಾಸದ ಉಳಿಸಿಕೆಯನ್ನು UI ನಲ್ಲಿನ Database Settings ಮೂಲಕ ಅಥವಾ `/api/settings/database` ಮೂಲಕ ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾಗುತ್ತದೆ.

ಡೀಫಾಲ್ಟ್ ಆಗಿ, ಬಳಕೆಯ ಇತಿಹಾಸವನ್ನು **90 ದಿನಗಳವರೆಗೆ** ಉಳಿಸಿಕೊಳ್ಳಲಾಗುತ್ತದೆ.

### ಸ್ವಚ್ಛಗೊಳಿಸುವಿಕೆ

ಹಳೆಯ ದಾಖಲೆಗಳನ್ನು `src/lib/db/cleanup.ts` ಮೂಲಕ ಸ್ವಚ್ಛಗೊಳಿಸಲಾಗುತ್ತದೆ:

- ಹಿನ್ನೆಲೆಯ cron ಪ್ರಕ್ರಿಯೆಯಿಂದ ಪ್ರಚೋದಿಸಲಾಗುತ್ತದೆ
- ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾದ `usageHistory` ಉಳಿಸಿಕೆ ಸೆಟ್ಟಿಂಗ್ಗಿಂತ ಹಳೆಯ `usage_history` ದಾಖಲೆಗಳನ್ನು ಅಳಿಸುತ್ತದೆ

### ಸಂಗ್ರಹಣೆಯ ಅಂದಾಜು

| ವಿನಂತಿಗಳ ದರ           | 30-ದಿನಗಳ ಸಂಗ್ರಹಣೆ | 90-ದಿನಗಳ ಸಂಗ್ರಹಣೆ |
| --------------------- | ----------------- | ----------------- |
| 100 ವಿನಂತಿಗಳು/ದಿನ     | ~3MB              | ~9MB              |
| 1,000 ವಿನಂತಿಗಳು/ದಿನ   | ~30MB             | ~90MB             |
| 10,000 ವಿನಂತಿಗಳು/ದಿನ  | ~300MB            | ~900MB            |
| 100,000 ವಿನಂತಿಗಳು/ದಿನ | ~3GB              | ~9GB              |

ಅತಿ ಹೆಚ್ಚು ಟ್ರಾಫಿಕ್ಗಾಗಿ, ಇವುಗಳನ್ನು ಪರಿಗಣಿಸಿ:

- Database Settings ಮೂಲಕ ಉಳಿಸಿಕೆ ಅವಧಿಯನ್ನು ಕಡಿಮೆ ಮಾಡುವುದು
- ಕಚ್ಚಾ ದಾಖಲೆಗಳ ಬದಲಿಗೆ `aggregated_metrics` ಬಳಸುವುದು (ವಿಶ್ಲೇಷಣೆಗಾಗಿ ಮಾತ್ರ)

## ವೆಚ್ಚ ಆಪ್ಟಿಮೈಸೇಶನ್ ಸಲಹೆಗಳು

### 1. ಸರಿಯಾದ ಮಾಡೆಲ್ ಬಳಸಿ

```bash
# ತ್ವರಿತ ಉತ್ತರ — ಅಗ್ಗದ + ವೇಗದ ಆಯ್ಕೆಯನ್ನು ಬಳಸಿ
curl -d '{"model":"auto/fast","messages":[...]}'

# ಸಂಕೀರ್ಣ ಕಾರ್ಯ — ಗುಣಮಟ್ಟದ ಆಯ್ಕೆಯನ್ನು ಬಳಸಿ
curl -d '{"model":"auto/smart","messages":[...]}'
```

### 2. ಕ್ಯಾಶಿಂಗ್ ಸಕ್ರಿಯಗೊಳಿಸಿ

Anthropic ಪ್ರಾಂಪ್ಟ್ ಕ್ಯಾಶಿಂಗ್, **ಪುನರಾವರ್ತಿತ ಸಂದರ್ಭದ ವೆಚ್ಚದಲ್ಲಿ 90% ಉಳಿಸುತ್ತದೆ**:

```ts
// ಕ್ಯಾಶಿಂಗ್ ಸ್ವಯಂಚಾಲಿತವಾಗಿದೆ — ಅದೇ ದೊಡ್ಡ ಸಿಸ್ಟಮ್ ಪ್ರಾಂಪ್ಟ್ ಅನ್ನು ಸೇರಿಸಿದರೆ ಸಾಕು
const response = await openai.chat({
  model: "claude-sonnet-4-5",
  system: longSystemPrompt, // ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಕ್ಯಾಶ್ ಮಾಡಲಾಗುತ್ತದೆ
  messages: [{ role: "user", content: "..." }],
});
```

### 3. ಸಂಕುಚನ ಬಳಸಿ

RTK + Caveman ಸಂಕುಚನವು **ಟೂಲ್-ಹೆವಿ ಸೆಷನ್ಗಳಲ್ಲಿ 15-95% ಉಳಿಸುತ್ತದೆ**:

```ts
const config = {
  compression: {
    engine: "rtk",
    intensity: "aggressive",
  },
};
```

### 4. ಪ್ರತಿ ಕೀಗೆ ಕೋಟಾಗಳನ್ನು ಹೊಂದಿಸಿ

ಅನಿಯಂತ್ರಿತ ವೆಚ್ಚಗಳನ್ನು ತಡೆಯಲು ಯಾವಾಗಲೂ `quotaLimit` ಹೊಂದಿಸಿ:

```ts
await updateApiKey(keyId, { quotaLimit: 10_00 }); // $10/ತಿಂಗಳ ಮಿತಿ
```

### 5. ಅತಿ ಹೆಚ್ಚು ಬಳಕೆದಾರರನ್ನು ಪರಿಶೋಧಿಸಿ

API ಕೀ ಆಧಾರದಲ್ಲಿ ಗುಂಪು ಮಾಡಲು ಮತ್ತು ವೆಚ್ಚದ ಆಧಾರದಲ್ಲಿ ವಿಂಗಡಿಸಲು ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಅಥವಾ **`/api/usage/analytics`** ಬಳಸಿ:

```bash
GET /api/usage/analytics?groupBy=apiKey
```

---

## ಸಮಸ್ಯೆ ಪರಿಹಾರ

### "ವೆಚ್ಚ ನಿರೀಕ್ಷೆಗಿಂತ ಹೆಚ್ಚಾಗಿದೆ"

1. **`/api/usage/analytics?groupBy=model`** ಪರಿಶೀಲಿಸಿ — ದುಬಾರಿ ಮಾಡೆಲ್ ಅನ್ನು ಪತ್ತೆಹಚ್ಚಿ
2. **`/api/usage/analytics?groupBy=apiKey`** ಪರಿಶೀಲಿಸಿ — ಹೆಚ್ಚು ಬಳಕೆ ಮಾಡುವವರನ್ನು ಪತ್ತೆಹಚ್ಚಿ
3. ದರದ ಡೇಟಾ ನವೀಕೃತವಾಗಿದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸಿ: `POST /api/pricing/sync`

### "ದಾಖಲೆಗಳು ಕಾಣೆಯಾಗಿವೆ"

- Dashboard → Database → Cleanup ಅಡಿಯಲ್ಲಿ DB ಉಳಿಸಿಕೆ ಸೆಟ್ಟಿಂಗ್ಗಳನ್ನು ಪರಿಶೀಲಿಸಿ — ಹಳೆಯ ದಾಖಲೆಗಳನ್ನು ಆವರ್ತಕ ಸ್ವಚ್ಛಗೊಳಿಸುವಿಕೆ ಕಾರ್ಯವು (`src/lib/db/cleanup.ts`) ಅಳಿಸುತ್ತದೆ
- `src/lib/db/usage*.ts` ನಲ್ಲಿ ದೋಷಗಳಿವೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸಿ — DB ಬರವಣಿಗೆಯ ವೈಫಲ್ಯಗಳನ್ನು ಲಾಗ್ ಮಾಡಲಾಗುತ್ತದೆ, ಆದರೆ ಪ್ರದರ್ಶಿಸಲಾಗುವುದಿಲ್ಲ
- ವಿನಂತಿಯು ನಿಜವಾಗಿಯೂ `chatCore` ಅನ್ನು ತಲುಪಿದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸಿ — ಕಾಂಬೊ ರೂಟಿಂಗ್ ಪರಿಶೀಲಿಸಿ

### "ಕೋಟಾ ಜಾರಿಯಾಗುತ್ತಿಲ್ಲ"

- ಕೀಯ `quotaLimit` ಸೆಟ್ಟಿಂಗ್ ಪರಿಶೀಲಿಸಿ
- `quotaWindow` ಅನ್ನು ಸರಿಯಾಗಿ ಹೊಂದಿಸಲಾಗಿದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸಿ
- `quotaSnapshots` ದಾಖಲೆಗಳಿಗಾಗಿ ನೋಡಿ — ಪ್ರತಿ ವಿನಂತಿಯಲ್ಲೂ ಅವು ರಚನೆಯಾಗಬೇಕು
