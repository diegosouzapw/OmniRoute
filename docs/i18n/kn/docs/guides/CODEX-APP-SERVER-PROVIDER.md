OmniRoute, OpenAI Codex ಅನ್ನು ಬಳಸಲು **ಎರಡು** ವಿಧಾನಗಳನ್ನು ಒದಗಿಸುತ್ತದೆ:

| ಪೂರೈಕೆದಾರ              | ಇದು OpenAI ಜೊತೆಗೆ ಹೇಗೆ ಸಂವಹನ ನಡೆಸುತ್ತದೆ                                                                                                                                                          | ಬಳಕೆಯ ಮುನ್ನೆಚ್ಚರಿಕೆ                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------- |
| **`codex`**            | ನಿಮ್ಮ ChatGPT/OpenAI OAuth ಟೋಕನ್ ಅನ್ನು ನೇರವಾಗಿ Responses API ಗೆ ಮರುಪ್ರಸಾರ ಮಾಡುತ್ತದೆ                                                                                                              | **ಹೌದು** — ಅಧಿಕೃತ ಸೆಷನ್ಗೆ ಪ್ರಾಕ್ಸಿ/ರೂಟರ್ ಬಳಕೆಗೆ ಅನುಮತಿ ಇಲ್ಲ          |
| **`codex-app-server`** | JSON-RPC/WebSocket ಮೂಲಕ **Codex CLI ಯ ಸ್ವಂತ `codex app-server`** ಅನ್ನು ನಿಯಂತ್ರಿಸುತ್ತದೆ; ಸಂವಾದಾತ್ಮಕ `codex` ಸೆಷನ್ನಂತೆಯೇ CLI ತನ್ನ OAuth (`~/.codex/auth.json`) ಅನ್ನು ಸ್ವತಃ ನಿರ್ವಹಿಸಿ ನವೀಕರಿಸುತ್ತದೆ | **ಇಲ್ಲ** — OmniRoute ಎಂದಿಗೂ ಟೋಕನ್ ಅನ್ನು API ಗೆ ಮರುಪ್ರಸಾರ ಮಾಡುವುದಿಲ್ಲ |

`codex-app-server` ಎಂದಿಗೂ ಟೋಕನ್ ಅನ್ನು ಮರುಪ್ರಸಾರ ಮಾಡದ ಕಾರಣ, ಇದಕ್ಕೆ
ಸೆಷನ್-ಮರುಪ್ರಸಾರದ ಬಳಕೆಯ ಮುನ್ನೆಚ್ಚರಿಕೆ ಅನ್ವಯಿಸುವುದಿಲ್ಲ. ಇದಕ್ಕೆ ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾದ
app-server URL ನಲ್ಲಿ **ತಲುಪಬಹುದಾದ Codex CLI** ಅಗತ್ಯವಿದ್ದು, ಆ CLI ನಲ್ಲಿ
**ಸೈನ್ ಇನ್ ಆಗಿರಬೇಕು**.

## 1. ಆರ್ಕಿಟೆಕ್ಚರ್

```
┌─ OmniRoute ಆ್ಯಪ್ ────────────────┐        ┌─ codex-app-server ಸೈಡ್ಕಾರ್ ────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ ಸಾಮರ್ಥ್ಯ ಟೋಕನ್)              │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  OpenAI OAuth ಅನ್ನು ಸ್ವತಃ ನಿರ್ವಹಿಸುತ್ತದೆ │
└──────────────────────────────────┘        │  (~/.codex/auth.json, ಸ್ವಯಂ-ನವೀಕರಣ) │
        │ ಹಂಚಿಕೊಳ್ಳುತ್ತದೆ (compose ವಾಲ್ಯೂಮ್ಗಳು) └─────────────────────────────────┘
        ▼
  codex-appserver-token   → WS ಸಾಮರ್ಥ್ಯ ಟೋಕನ್ (ಎರಡೂ ಇದನ್ನು ಮೌಂಟ್ ಮಾಡುತ್ತವೆ)
  codex-appserver-home    → ~/.codex (ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಿಂದ ಬರೆಯಲ್ಪಡುವ auth.json,
                             ಸೈಡ್ಕಾರ್ನ codex app-server ನಿಂದ ಓದಲ್ಪಡುತ್ತದೆ)
```

- ಸೈಡ್ಕಾರ್ ಸಾಮರ್ಥ್ಯ ಟೋಕನ್ನ ಹಿಂದೆ ಆಂತರಿಕ compose ನೆಟ್ವರ್ಕ್ನಲ್ಲಿ
  (`ws://codex-app-server:1456`) **ಮಾತ್ರ** ಆಲಿಸುತ್ತದೆ. ಇದನ್ನು ಹೋಸ್ಟ್ ಅಥವಾ
  ಇಂಟರ್ನೆಟ್ಗೆ **ಎಂದಿಗೂ** ಪ್ರಕಟಿಸಲಾಗುವುದಿಲ್ಲ.
- Codex CLI ಅನ್ನು `omniroute:base` ನಲ್ಲೇ ಸೇರಿಸಲಾಗಿದೆ, ಆದ್ದರಿಂದ ಸೈಡ್ಕಾರ್ ಅನ್ನು
  ಚಲಾಯಿಸುವಾಗ ಹೋಸ್ಟ್ ಅಥವಾ ಬಳಕೆದಾರರ ಯಂತ್ರದಲ್ಲಿ codex ಸ್ಥಾಪಿಸುವ ಅಗತ್ಯವಿಲ್ಲ.

## 2. ಇದನ್ನು ಚಾಲನೆ ಮಾಡಿ

```bash
# codex app-server ಸೈಡ್ಕಾರ್ ಪ್ರೊಫೈಲ್ನೊಂದಿಗೆ ಸ್ಟ್ಯಾಕ್ ಅನ್ನು ಪ್ರಾರಂಭಿಸಿ:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

ಮೊದಲ ಬೂಟ್ನಲ್ಲಿ ಸೈಡ್ಕಾರ್ ತನ್ನ WS ಸಾಮರ್ಥ್ಯ ಟೋಕನ್ ಅನ್ನು ರಚಿಸುತ್ತದೆ (ಹಂಚಿಕೆಯ
`codex-appserver-token` ವಾಲ್ಯೂಮ್ನಲ್ಲಿ) ಮತ್ತು ಆ್ಯಪ್ ಅದೇ ಟೋಕನ್ ಅನ್ನು
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE` ಮೂಲಕ ಓದುತ್ತದೆ. ಟೋಕನ್ ಅನ್ನು ಕೈಯಾರೆ
ಜೋಡಿಸುವ ಅಗತ್ಯವಿಲ್ಲ.

## 3. ಸಂಪರ್ಕಿಸಿ + ಸೈನ್ ಇನ್ ಮಾಡಿ

1. ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿ **OpenAI Codex (App-Server)** ಗಾಗಿ ಸಂಪರ್ಕವೊಂದನ್ನು ಸೇರಿಸಿ.
   ಯಾವುದೇ API ಕೀ ಅಥವಾ ಟೋಕನ್ ಅಗತ್ಯವಿಲ್ಲ (ಇದು ದೃಢೀಕರಣವಿಲ್ಲದ ಪೂರೈಕೆದಾರ —
   ದೃಢೀಕರಣವನ್ನು ಸೈಡ್ಕಾರ್ ನಿರ್ವಹಿಸುತ್ತದೆ).
2. ಸೈಡ್ಕಾರ್ನ Codex CLI ನಲ್ಲಿ **ಇನ್ನೂ ಸೈನ್ ಇನ್ ಆಗಿಲ್ಲದಿದ್ದರೆ**, ಸಂಪರ್ಕದ ಆರೋಗ್ಯ
   ಪರಿಶೀಲನೆಯು _"ಚಾಲನೆಯಲ್ಲಿದೆ, ಆದರೆ ಸೈನ್ ಇನ್ ಆಗಿಲ್ಲ"_ ಎಂದು ವರದಿ ಮಾಡುತ್ತದೆ
   (ಕೆಂಪು ದೃಢೀಕರಣ ದೋಷವಲ್ಲ). **ChatGPT ಮೂಲಕ ಸೈನ್ ಇನ್ ಮಾಡಿ** ಅನ್ನು ಬಳಸಿ: ಇದು
   ನಿಮ್ಮ ಬ್ರೌಸರ್ನಲ್ಲಿ ಪ್ರಮಾಣಿತ Codex device-OAuth ಅನ್ನು ಚಲಾಯಿಸಿ, ನಂತರ
   **ದೃಢೀಕರಣವನ್ನು ಅನ್ವಯಿಸಿ** ಮೂಲಕ ಹಂಚಿಕೆಯ ವಾಲ್ಯೂಮ್ಗೆ `~/.codex/auth.json` ಅನ್ನು
   ಬರೆಯುತ್ತದೆ (ಒಂದೇ ಲಾಗಿನ್ `codex` ಮತ್ತು `codex-app-server` ಪೂರೈಕೆದಾರಗಳೆರಡಕ್ಕೂ
   ಸೇವೆ ಒದಗಿಸುತ್ತದೆ).
3. ಸೈನ್ ಇನ್ ಆದ ನಂತರ, ಆರೋಗ್ಯ ಪರಿಶೀಲನೆ ಹಸಿರು ಬಣ್ಣಕ್ಕೆ ತಿರುಗುತ್ತದೆ (ಇದು `/readyz`
   **ಮತ್ತು** `account/read` ಎರಡನ್ನೂ ಪರಿಶೀಲಿಸುತ್ತದೆ — ಅಂದರೆ ಚಾಲನೆಯಲ್ಲಿರುವುದು
   _ಮತ್ತು_ ದೃಢೀಕರಿಸಲ್ಪಟ್ಟಿರುವುದು) ಮತ್ತು ಕೆಲಸ ಮಾಡಲು ಪ್ರಾರಂಭಿಸುತ್ತದೆ.

ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಆರೋಗ್ಯಕರ `~/.codex/auth.json` ಅನ್ನು ಎಂದಿಗೂ
ತಿದ್ದಿ ಹಾಳು ಮಾಡುವುದಿಲ್ಲ — ಫೈಲ್ ಇಲ್ಲದಿದ್ದಾಗ ಅಥವಾ ಅದರ ಟೋಕನ್ ಹಳೆಯದಾಗಿದ್ದಾಗ ಮಾತ್ರ
ಅದು ಬರೆಯುತ್ತದೆ (ಯಾವಾಗಲೂ ಬ್ಯಾಕಪ್ ತೆಗೆದುಕೊಳ್ಳಲಾಗುತ್ತದೆ).

## 4. ನಿಯೋಜನೆ ಸನ್ನಿವೇಶಗಳು

- **ಈಗಾಗಲೇ ದೃಢೀಕರಿಸಲಾದ Codex CLI ಹೊಂದಿರುವ ನಿರ್ವಾಹಕರು** — ನಿಮ್ಮ ಹೋಸ್ಟ್ನ
  `~/.codex` ಅನ್ನು ಸೈಡ್ಕಾರ್ಗೆ (`codex-appserver-home`) ಮೌಂಟ್ ಮಾಡಿ ಮತ್ತು
  ಸೈನ್-ಇನ್ ಹಂತವನ್ನು ಬಿಟ್ಟುಬಿಡಿ.
- **ಸಾರ್ವಜನಿಕ ಬಳಕೆದಾರ, ಸ್ಥಳೀಯವಾಗಿ codex ಸ್ಥಾಪಿಸಿಲ್ಲ** — ಇದು ಅಪ್ರಸ್ತುತ:
  ಸೈಡ್ಕಾರ್ನಲ್ಲಿ CLI ಇದೆ. ಬಳಕೆದಾರರು ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಮೂಲಕ ಮಾತ್ರ ದೃಢೀಕರಿಸುತ್ತಾರೆ.
- **ಬೇರ್-ಮೆಟಲ್ OmniRoute (ಸೈಡ್ಕಾರ್ ಇಲ್ಲ, ಹೋಸ್ಟ್ codex)** — ನಿಮ್ಮ ಸ್ವಂತ
  `codex app-server` ಕಡೆಗೆ `OMNIROUTE_CODEX_APPSERVER_WS` ಅನ್ನು ಸೂಚಿಸಿ ಮತ್ತು
  ಹೋಸ್ಟ್ codex ನಲ್ಲಿ ಸೈನ್ ಇನ್ ಆಗಿರುವುದನ್ನು ಖಚಿತಪಡಿಸಿಕೊಳ್ಳಿ; ಬೈನರಿ ಇಲ್ಲದಿದ್ದರೆ
  "codex ಸ್ಥಾಪಿಸಲಾಗಿಲ್ಲ" ಎಂಬ ಸುಳಿವು ಕಾಣಿಸಿಕೊಳ್ಳುತ್ತದೆ.

## 5. ವಸತಿ / UDP ಹೊರಹರಿವು (ನಿರ್ವಾಹಕರ ಹೆಚ್ಚುವರಿ ವ್ಯವಸ್ಥೆ, ವಿತರಣೆಯಲ್ಲಿ ಸೇರಿಲ್ಲ)

ಮೇಲಿನ ಸಾಮಾನ್ಯ ಸೈಡ್ಕಾರ್, ಕಂಟೇನರ್ನ ಸಾಮಾನ್ಯ ನೆಟ್ವರ್ಕ್ ಮೂಲಕ ಹೊರಹರಿಯುತ್ತದೆ.
**ವಸತಿ ನಿರ್ಗಮನ**ದ ಮೂಲಕ Codex ಟ್ರಾಫಿಕ್ ಹೊರಹರಿಯಬೇಕಾದ ನಿರ್ವಾಹಕರು (ಉದಾ. TCP +
UDP/QUIC ಸಾಗಿಸುವ TUN tailscale ಸೈಡ್ಕಾರ್) ಅದನ್ನು ಪ್ರತ್ಯೇಕ compose override ಆಗಿ
ಚಲಾಯಿಸುತ್ತಾರೆ; ಇದನ್ನು ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ವಿತರಿಸಲಾದ `codex-app-server`
ಪ್ರೊಫೈಲ್ನ ಭಾಗವನ್ನಾಗಿ ಮಾಡಿಲ್ಲ. ಆ ಸೆಟಪ್ಗಾಗಿ ಆಂತರಿಕ ಕಾರ್ಯಾಚರಣೆಗಳ ರನ್ಬುಕ್ ನೋಡಿ.
