OmniRoute ನಲ್ಲಿ ನಿರ್ವಹಣಾ ಮಾರ್ಗಗಳನ್ನು ಅಧಿಕೃತಗೊಳಿಸಬಹುದಾದ **ನಾಲ್ಕು ರುಜುವಾತು ಕುಟುಂಬಗಳಿವೆ**.
ಅವುಗಳನ್ನು ಪರಸ್ಪರ ಬದಲಿಸಿ ಬಳಸಲಾಗುವುದಿಲ್ಲ. ಇನ್ಫರೆನ್ಸ್ API ಕೀಗಳಿಗೆ (`sk-…`) ಸ್ಪಷ್ಟವಾಗಿ `manage` ಅಥವಾ `admin` ಸ್ಕೋಪ್ ನೀಡಿರದಿದ್ದರೆ, ಅವು ಸರ್ವರ್ ಅನ್ನು ನಿರ್ವಹಿಸುವುದಿಲ್ಲ.

ಅಧಿಕೃತ ಅನುಷ್ಠಾನ: `src/lib/api/requireManagementAuth.ts`.

| ರುಜುವಾತು                    | ಸಾಮಾನ್ಯ ಸ್ವರೂಪ                          | ರಚಿಸುವ ಸ್ಥಳ                                                  | ಉದ್ದೇಶಿತ ಬಳಕೆ                 | ನಿರ್ವಹಣಾ ಸಾಮರ್ಥ್ಯ                                                                          |
| --------------------------- | --------------------------------------- | ------------------------------------------------------------ | ----------------------------- | ------------------------------------------------------------------------------------------ |
| ಡ್ಯಾಶ್ಬೋರ್ಡ್ JWT ಸೆಷನ್      | `auth_token` ಕುಕಿ                       | ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಲಾಗಿನ್                                          | ಬ್ರೌಸರ್ UI                    | CSRF, ಸ್ಥಳೀಯತೆ ಮತ್ತು ಯಾವಾಗಲೂ-ರಕ್ಷಿತ-ಮಾರ್ಗದ ನಿಯಮಗಳಿಗೆ ಒಳಪಟ್ಟು ಸಂಪೂರ್ಣ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ನಿರ್ವಹಣೆ |
| CLI machine-id ಟೋಕನ್        | ಆಂತರಿಕ / ಸ್ಥಳೀಯ                         | CLI ಬೂಟ್ಸ್ಟ್ರ್ಯಾಪ್ (ಅದೇ ಯಂತ್ರದಲ್ಲಿ `omniroute`)              | ಸ್ಥಳೀಯ CLI                    | ಸ್ಥಳೀಯ ನಿರ್ವಹಣೆ ಮಾತ್ರ                                                                      |
| ಸ್ಕೋಪ್ ಹೊಂದಿದ ಆಕ್ಸೆಸ್ ಟೋಕನ್ | `oma_live_…`                            | **ಸೆಟ್ಟಿಂಗ್ಗಳು → ಆಕ್ಸೆಸ್ ಟೋಕನ್ಗಳು** ಅಥವಾ `omniroute connect` | ರಿಮೋಟ್ CLI ಮತ್ತು ನಿರ್ವಹಣಾ API | ಮಾರ್ಗಕ್ಕೆ ಅಗತ್ಯವಿರುವ `read`, `write`, ಅಥವಾ `admin` ಸ್ಕೋಪ್ ಅನ್ನು ಪೂರೈಸಬೇಕು                  |
| ಇನ್ಫರೆನ್ಸ್ API ಕೀ           | `sk-…` (ಮತ್ತು ಇತರ API-ಕೀ ಪ್ರಿಫಿಕ್ಸ್ಗಳು) | **API ಮ್ಯಾನೇಜರ್ / API ಕೀಗಳು**                                | `/v1/*` ಇನ್ಫರೆನ್ಸ್            | ಕೀ ಮೆಟಾಡೇಟಾದಲ್ಲಿ `manage` ಅಥವಾ `admin` ಸೇರಿರದಿದ್ದರೆ **ಯಾವುದೂ ಇಲ್ಲ**                        |

`oma_` ರುಜುವಾತುಗಳು ನಿರ್ವಹಣಾ/CLI ರುಜುವಾತುಗಳಾಗಿವೆ. ಅವು ಇನ್ಫರೆನ್ಸ್ API ಕೀಗಳಲ್ಲ.

ಸರ್ವರ್ಗಾಗಿ ಲಾಗಿನ್/API-ಕೀ ದೃಢೀಕರಣವನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿದ್ದರೆ, ಕೆಲವು ನಿರ್ವಹಣಾ ಮಾರ್ಗಗಳು ದೃಢೀಕರಿಸದ ಕರೆಗಳನ್ನು ಸ್ವೀಕರಿಸಬಹುದು. ಸ್ಥಳೀಯ-ಮಾತ್ರ ಮತ್ತು ಯಾವಾಗಲೂ-ರಕ್ಷಿತ ಮಾರ್ಗಗಳು ಇನ್ನೂ ತಮ್ಮದೇ ನಿಯಮಗಳನ್ನು ಅನ್ವಯಿಸುತ್ತವೆ. ಆದ್ದರಿಂದ, ಈ ರುಜುವಾತುಗಳಲ್ಲಿ ಒಂದನ್ನು ಒದಗಿಸುವುದು ಎಲ್ಲ ಸಂದರ್ಭಗಳಲ್ಲಿಯೂ ಕಡ್ಡಾಯವಲ್ಲ; ಹಾಗೆಯೇ ಅಗತ್ಯ ಸ್ಕೋಪ್ ಮತ್ತು ಮಾರ್ಗದ ಸ್ಥಳೀಯತೆ ಇಲ್ಲದೆ ಅದನ್ನು ಹೊಂದಿರುವುದಷ್ಟೇ ಎಲ್ಲ ಸಂದರ್ಭಗಳಲ್ಲಿಯೂ ಸಾಕಾಗುವುದಿಲ್ಲ.

ಸಂಬಂಧಿತ: [ರಿಮೋಟ್ ಮೋಡ್](./REMOTE-MODE.md) (ರಿಮೋಟ್ CLI ಗಾಗಿ `oma_live_…` ಅನ್ನು ಹೇಗೆ ರಚಿಸಲಾಗುತ್ತದೆ).

## ಸ್ಕೋಪ್ ಮ್ಯಾಟ್ರಿಕ್ಸ್ಗಳು

ಈ ಎರಡು ಸ್ಕೋಪ್ ಶಬ್ದಕೋಶಗಳು **ಬೇರೆಯಾಗಿವೆ**. ಅವುಗಳನ್ನು ಬೆರೆಸಬೇಡಿ.

### ಆಕ್ಸೆಸ್ ಟೋಕನ್ ಸ್ಕೋಪ್ಗಳು (`oma_live_…`)

| ಸ್ಕೋಪ್  | ಸಾಮಾನ್ಯ ಕಾರ್ಯಾಚರಣೆಗಳು                                                                  |
| ------- | -------------------------------------------------------------------------------------- |
| `read`  | ಟೋಕನ್ಗೆ ನೋಡಲು ಅನುಮತಿ ಇರುವ ಪಟ್ಟಿ/ಸ್ಥಿತಿ GET ವಿನಂತಿಗಳು                                   |
| `write` | admin ಗಿಂತ ಕೆಳಗಿನ ಬದಲಾವಣೆಗಳು (ರಚಿಸುವುದು/ನವೀಕರಿಸುವುದು/ಅಳಿಸುವುದು)                        |
| `admin` | ಸಂಪೂರ್ಣ ರಿಮೋಟ್ CLI / ಸಂಪರ್ಕ ಟೋಕನ್ (ಪಾಸ್ವರ್ಡ್ ಬೂಟ್ಸ್ಟ್ರ್ಯಾಪ್ ಇಲ್ಲಿ ಡೀಫಾಲ್ಟ್ ಆಗಿರುತ್ತದೆ) |

`read` ಹೊಂದಿರುವ ಟೋಕನ್ `write` ಮಾರ್ಗವನ್ನು ಕರೆಯಲು ಸಾಧ್ಯವಿಲ್ಲ. ರನ್ಟೈಮ್ ಸಂದೇಶದ ಸ್ವರೂಪ:
`Access token scope '<have>' is insufficient; '<need>' required.`

### API-ಕೀ ನಿರ್ವಹಣಾ ಸ್ಕೋಪ್ಗಳು

| ಸ್ಕೋಪ್        | ಅರ್ಥ                                                                                     |
| ------------- | ---------------------------------------------------------------------------------------- |
| (ಯಾವುದೂ ಇಲ್ಲ) | ಇನ್ಫರೆನ್ಸ್ ಮಾತ್ರ. ನಿರ್ವಹಣಾ ಮಾರ್ಗಗಳು 403 ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತವೆ.                          |
| `manage`      | ನಿರ್ವಹಣಾ API (`requireManagementAuth` API-ಕೀ ಶಾಖೆಯಂತೆಯೇ ಅದೇ ಗೇಟ್)                        |
| `admin`       | `hasManageScope` ಅನ್ನು ಸಹ ಪೂರೈಸುತ್ತದೆ (ನಿರ್ವಹಣಾ ಸಾಮರ್ಥ್ಯ ಹೊಂದಿರುವುದಾಗಿ ಪರಿಗಣಿಸಲಾಗುತ್ತದೆ) |

API ಕೀಗಳು / API ಮ್ಯಾನೇಜರ್ UI ನಲ್ಲಿ ಕೀಗಾಗಿ `manage` ಅನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ. ನೀವು ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ಆ ಸ್ಕೋಪ್ ನೀಡಿರದಿದ್ದರೆ, ಆಟೊಮೇಶನ್ಗಾಗಿ ಚಾಟ್ ಕ್ಲೈಂಟ್ ಕೀಯನ್ನು ಮರುಬಳಸಬೇಡಿ.

## ರಚಿಸುವುದು ಮತ್ತು ಹಿಂಪಡೆಯುವುದು ಹೇಗೆ

### ಡ್ಯಾಶ್ಬೋರ್ಡ್ JWT ಸೆಷನ್

1. `/login` ತೆರೆಯಿರಿ, ನಿರ್ವಹಣಾ ಪಾಸ್ವರ್ಡ್ನೊಂದಿಗೆ ಸೈನ್ ಇನ್ ಮಾಡಿ (ಮೊದಲ ಬೂಟ್ನಲ್ಲಿ `INITIAL_PASSWORD`).
2. `auth_token` ಕುಕಿ HttpOnly ಆಗಿದೆ. ಬ್ರೌಸರ್ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಅದನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಬಳಸುತ್ತದೆ.
3. `/api/auth/logout` ಮೂಲಕ ಲಾಗ್ ಔಟ್ ಮಾಡಿ. ನಕಲಿಸಲು ದೀರ್ಘಾವಧಿಯ ರಹಸ್ಯವಿಲ್ಲ.

### CLI machine-id ಟೋಕನ್

1. ಸರ್ವರ್ ಇರುವ **ಅದೇ ಹೋಸ್ಟ್ನಲ್ಲಿ** (ಲೂಪ್ಬ್ಯಾಕ್) `omniroute` ಅನ್ನು ರನ್ ಮಾಡಿ.
2. CLI, `~/.omniroute/` ಅಡಿಯಲ್ಲಿ machine-id ಟೋಕನ್ ಅನ್ನು ಬೂಟ್ಸ್ಟ್ರ್ಯಾಪ್ ಮಾಡುತ್ತದೆ (chmod 600).
3. ಇದು ಮತ್ತೊಂದು ಯಂತ್ರದಿಂದ ಕಾರ್ಯನಿರ್ವಹಿಸುವುದಿಲ್ಲ. ರಿಮೋಟ್ CLI ಗಾಗಿ ಆಕ್ಸೆಸ್ ಟೋಕನ್ ಬಳಸಿ.

### ಸ್ಕೋಪ್ ಹೊಂದಿದ ಆಕ್ಸೆಸ್ ಟೋಕನ್ (`oma_live_…`)

1. ಡ್ಯಾಶ್ಬೋರ್ಡ್: **ಸೆಟ್ಟಿಂಗ್ಗಳು → ಆಕ್ಸೆಸ್ ಟೋಕನ್ಗಳು** → ರಚಿಸಿ (ಹೆಸರು + ಸ್ಕೋಪ್). **ರಹಸ್ಯವನ್ನು ಒಮ್ಮೆ ಮಾತ್ರ ತೋರಿಸಲಾಗುತ್ತದೆ.**
2. ಅಥವಾ CLI: `omniroute connect <host>` (ಪಾಸ್ವರ್ಡ್ → ಟೋಕನ್). [ರಿಮೋಟ್ ಮೋಡ್](./REMOTE-MODE.md) ನೋಡಿ.
3. ಹೆಡರ್: `Authorization: Bearer oma_live_…`
4. ಅದೇ ಆಕ್ಸೆಸ್ ಟೋಕನ್ಗಳ ಪುಟದಿಂದ ಹಿಂಪಡೆಯಿರಿ (ಅಥವಾ CLI ಕಾಂಟೆಕ್ಸ್ಟ್ ಅನ್ನು ಅಳಿಸಿ).
5. ಸರ್ವರ್ ಹ್ಯಾಶ್ ಅನ್ನು ಮಾತ್ರ ಸಂಗ್ರಹಿಸುತ್ತದೆ. ಪ್ಲೇನ್ಟೆಕ್ಸ್ಟ್ ಅನ್ನು ಪಾಸ್ವರ್ಡ್ನಂತೆ ಪರಿಗಣಿಸಿ.

### `manage` ಸ್ಕೋಪ್ ಹೊಂದಿದ API ಕೀ

1. ಡ್ಯಾಶ್ಬೋರ್ಡ್: **API ಮ್ಯಾನೇಜರ್ / API ಕೀಗಳು** → ಕೀಯನ್ನು ರಚಿಸಿ ಅಥವಾ ಸಂಪಾದಿಸಿ → `manage` (ಅಥವಾ `admin`) ಅನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ.
2. ಹೆಡರ್: `Authorization: Bearer sk-…` (ಕೀಗೆ ನಿಜವಾಗಿ ಇರುವ ಪ್ರಿಫಿಕ್ಸ್).
3. ಅದೇ UI ನಲ್ಲಿ ಕೀಯನ್ನು ಹಿಂಪಡೆಯಿರಿ ಅಥವಾ `manage` ಅನ್ನು ತೆಗೆದುಹಾಕಿ.
4. CLI ಅಲ್ಲದ ಆಟೊಮೇಶನ್ಗಾಗಿ ಕನಿಷ್ಠ ಸವಲತ್ತನ್ನು ಬಳಸಿ: GET-ಮಾತ್ರ ಕೆಲಸಗಳಿಗೆ `read` ಆಕ್ಸೆಸ್ ಟೋಕನ್ಗೆ ಆದ್ಯತೆ ನೀಡಿ; ಕರೆ ಮಾಡುವ ಘಟಕವು `/v1` ಮತ್ತು ನಿರ್ವಹಣೆ ಎರಡರೊಂದಿಗೂ ಸಂವಹನ ನಡೆಸಬೇಕಾದಾಗ ಮಾತ್ರ API ಕೀಯಲ್ಲಿ `manage` ಬಳಸಿ.

## ಹೆಡರ್ ಸ್ವರೂಪ

```http
Authorization: Bearer oma_live_<secret>
Authorization: Bearer sk-<secret>
Cookie: auth_token=<dashboard-jwt>
```

ನಿರ್ವಹಣಾ ರುಜುವಾತುಗಳನ್ನು URL ಪಥದಲ್ಲಿ ಅಥವಾ ಕ್ವೆರಿ ಸ್ಟ್ರಿಂಗ್ನಲ್ಲಿ ಇರಿಸಬೇಡಿ. ನಿರ್ವಹಣಾ
ದೃಢೀಕರಣವು ಹೆಡರ್/ಕುಕಿಗೆ ಮಾತ್ರ ಸೀಮಿತವಾಗಿದೆ.

## ನಕಲಿಸಿ-ಅಂಟಿಸಬಹುದಾದ ಉದಾಹರಣೆಗಳು

ಓದಲು ಮಾತ್ರ (ಪ್ರದಾತರನ್ನು ಪಟ್ಟಿ ಮಾಡುವುದು). `read` ಪ್ರವೇಶ ಟೋಕನ್ ಬಳಸಿ:

```bash
curl -sS "$OMNIROUTE_URL/api/providers" \
  -H "Authorization: Bearer oma_live_<read-token>"
```

ಮಾರ್ಪಡಿಸುವುದು (ಪ್ರದಾತ ಸಂಪರ್ಕವನ್ನು ರಚಿಸುವುದು). `write`/`admin` ಪ್ರವೇಶ ಟೋಕನ್ ಅಥವಾ
`manage` ವ್ಯಾಪ್ತಿಯ API ಕೀ ಬಳಸಿ:

```bash
curl -sS -X POST "$OMNIROUTE_URL/api/providers" \
  -H "Authorization: Bearer oma_live_<write-or-admin-token>" \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","apiKey":"<upstream-key>"}'
```

ಇನ್ಫರೆನ್ಸ್ (ನಿರ್ವಹಣೆ ಅಲ್ಲ). ಸಾಮಾನ್ಯ API ಕೀ; `manage` ಅಗತ್ಯವಿಲ್ಲ:

```bash
curl -sS "$OMNIROUTE_URL/v1/models" \
  -H "Authorization: Bearer sk-<inference-key>"
```

## ಪ್ರಸ್ತುತ ರನ್ಟೈಮ್ ದೋಷಗಳು (ರಹಸ್ಯಗಳನ್ನು ಪ್ರತಿಧ್ವನಿಸಬೇಡಿ)

| ಸಂದರ್ಭ                                   | ಸಾಮಾನ್ಯ ಸ್ಥಿತಿ | ಸಂದೇಶ (ಸೂಕ್ಷ್ಮ ಮಾಹಿತಿ ತೆಗೆದುಹಾಕಲಾಗಿದೆ)                                                |
| ---------------------------------------- | -------------- | ------------------------------------------------------------------------------------- |
| ರುಜುವಾತು ಇಲ್ಲ                            | 401            | `ದೃಢೀಕರಣ ಅಗತ್ಯವಿದೆ`                                                                   |
| ಅಮಾನ್ಯ/ಅವಧಿ ಮೀರಿದ `oma_live_…`           | 401            | `ಅಮಾನ್ಯ ಅಥವಾ ಅವಧಿ ಮೀರಿದ ಪ್ರವೇಶ ಟೋಕನ್`                                                 |
| `manage`/`admin` ಇಲ್ಲದ ಮಾನ್ಯ API ಕೀ      | 403            | `API ಕೀಯಲ್ಲಿ 'manage' ವ್ಯಾಪ್ತಿ ಇಲ್ಲ. API ಕೀಗಳ ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿ ಅದನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ.` |
| ನಿರ್ವಹಣಾ ರೂಟ್ನಲ್ಲಿ ಅಮಾನ್ಯ ಸಾಮಾನ್ಯ API ಕೀ | 403            | `ಅಮಾನ್ಯ ನಿರ್ವಹಣಾ ಟೋಕನ್`                                                               |
| ಪ್ರವೇಶ ಟೋಕನ್ ವ್ಯಾಪ್ತಿ ತುಂಬಾ ಕಡಿಮೆ        | 403            | `ಪ್ರವೇಶ ಟೋಕನ್ ವ್ಯಾಪ್ತಿ '<have>' ಸಾಕಾಗುವುದಿಲ್ಲ; '<need>' ಅಗತ್ಯವಿದೆ.`                   |

"ಅಮಾನ್ಯ ನಿರ್ವಹಣಾ ಟೋಕನ್" ಎಂದರೆ ಬೇರರ್ ಅನ್ನು ನಿರ್ವಹಣಾ ರುಜುವಾತಾಗಿ
**ಸ್ವೀಕರಿಸಲಾಗಿಲ್ಲ** ಎಂದರ್ಥ. ಯಾವ ಕುಟುಂಬದ ಟೋಕನ್ ರಚಿಸಬೇಕು ಎಂಬುದನ್ನು ಇದು **ತಿಳಿಸುವುದಿಲ್ಲ**. ಮೇಲಿನ ಕೋಷ್ಟಕವನ್ನು ಬಳಸಿ:
ಇನ್ಫರೆನ್ಸ್ ಕೀಗಳಿಗೆ `manage` ವ್ಯಾಪ್ತಿ ಅಗತ್ಯವಿದೆ; ರಿಮೋಟ್ CLIಗೆ `oma_live_…` ಅಗತ್ಯವಿದೆ; ಡ್ಯಾಶ್ಬೋರ್ಡ್
ಸೆಷನ್ ಕುಕಿಯನ್ನು ಬಳಸುತ್ತದೆ.
