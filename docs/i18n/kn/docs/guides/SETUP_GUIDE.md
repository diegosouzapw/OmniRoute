## ಇನ್ಸ್ಟಾಲ್ ಮಾಡುವ ವಿಧಾನಗಳು

### npm (ಶಿಫಾರಸು ಮಾಡಲಾಗಿದೆ)

```bash
npm install -g omniroute
omniroute
```

ಡ್ಯಾಶ್ಬೋರ್ಡ್ `http://localhost:20128`ನಲ್ಲಿ ತೆರೆಯುತ್ತದೆ ಮತ್ತು API ಮೂಲ URL `http://localhost:20128/v1` ಆಗಿರುತ್ತದೆ.

### pnpm

```bash
pnpm add -g omniroute@latest --allow-build=better-sqlite3 --allow-build=@swc/core
omniroute
```

> **pnpm ಬಳಕೆದಾರರು:** `better-sqlite3` ಮತ್ತು `@swc/core`ಗಾಗಿ ಸ್ಥಳೀಯ ಬಿಲ್ಡ್ ಸ್ಕ್ರಿಪ್ಟ್ಗಳನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಲು `--allow-build` ಫ್ಲ್ಯಾಗ್ ಅಗತ್ಯವಿದೆ. pnpm v11ನಲ್ಲಿ ಜಾಗತಿಕ ಇನ್ಸ್ಟಾಲ್ಗಳಿಗೆ `pnpm approve-builds -g` ಕಮಾಂಡ್ ಬೆಂಬಲಿತವಾಗಿಲ್ಲ.

### Arch Linux (AUR)

```bash
yay -S omniroute-bin
systemctl --user enable --now omniroute.service
```

[AUR ಪ್ಯಾಕೇಜ್](https://aur.archlinux.org/packages/omniroute-bin) OmniRoute ಅನ್ನು ಇನ್ಸ್ಟಾಲ್ ಮಾಡುತ್ತದೆ ಮತ್ತು systemd ಬಳಕೆದಾರ ಸೇವೆಯನ್ನು ಒದಗಿಸುತ್ತದೆ.

### ಮೂಲದಿಂದ

```bash
npm install
PORT=20128 DASHBOARD_PORT=20129 NEXT_PUBLIC_BASE_URL=http://localhost:20129 npm run dev
```

> **Windows ಸೂಚನೆ:** ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ, ಹಳೆಯ `%USERPROFILE%\.omniroute` ಡೈರೆಕ್ಟರಿ ಇಲ್ಲದಿದ್ದಾಗ OmniRoute `%APPDATA%\omniroute` ಅನ್ನು ಬಳಸುತ್ತದೆ. ಬೇರೆ ಡೇಟಾ-ಡೈರೆಕ್ಟರಿ ಸ್ಥಳವನ್ನು ಆಯ್ಕೆ ಮಾಡಲು `DATA_DIR` ಅನ್ನು ಹೊಂದಿಸಿ.

> **ಸೂಚನೆ:** ಮೊದಲ ಚಾಲನೆಯಲ್ಲಿ `npm install`, `.env.example`ನಿಂದ `.env` ಅನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ರಚಿಸುತ್ತದೆ. ನಂತರದ ಇನ್ಸ್ಟಾಲ್ಗಳು ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ `.env` ಅನ್ನು ಓವರ್ರೈಟ್ ಮಾಡುವುದಿಲ್ಲ, ಆದ್ದರಿಂದ ಕಸ್ಟಮೈಸೇಶನ್ಗಳು ಉಳಿಯುತ್ತವೆ. ಪುನಃ ಪ್ರಾರಂಭಿಕ ಮೌಲ್ಯಗಳನ್ನು ತುಂಬಲು, ಮತ್ತೊಮ್ಮೆ ಚಾಲನೆ ಮಾಡುವ ಮೊದಲು `.env` ಅನ್ನು ಅಳಿಸಿ.

### Docker

Compose ಪ್ರೊಫೈಲ್ಗಳು ಮತ್ತು Caddy HTTPS ಸೇರಿದಂತೆ ಸಂಪೂರ್ಣ Docker ಸೆಟಪ್ಗಾಗಿ [Docker ಮಾರ್ಗದರ್ಶಿ](./DOCKER_GUIDE.md) ನೋಡಿ.

### ಡೆಸ್ಕ್ಟಾಪ್ ಆ್ಯಪ್ (Electron)

OmniRoute, Electron 41 + electron-builder 26.10 ಆಧಾರದಲ್ಲಿ ನಿರ್ಮಿಸಲಾದ ಡೆಸ್ಕ್ಟಾಪ್ ರ್ಯಾಪರ್ನೊಂದಿಗೆ ಬರುತ್ತದೆ. ಲಭ್ಯವಿರುವ ಸ್ಕ್ರಿಪ್ಟ್ಗಳು (ಕಾರ್ಯಸ್ಥಳದ ರೂಟ್):

```bash
npm run electron:dev          # ಹಾಟ್-ರೀಲೋಡ್ನೊಂದಿಗೆ ಡೆಸ್ಕ್ಟಾಪ್ ಅನ್ನು ಚಲಾಯಿಸಿ
npm run electron:build        # ಪ್ರಸ್ತುತ OSಗಾಗಿ ಬಿಲ್ಡ್ ಮಾಡಿ (ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಪತ್ತೆಹಚ್ಚಲಾಗುತ್ತದೆ)
npm run electron:build:win    # Windows ಇನ್ಸ್ಟಾಲರ್ (NSIS + ಪೋರ್ಟಬಲ್)
npm run electron:build:mac    # macOS (dmg + zip, arm64+x64)
npm run electron:build:linux  # Linux (AppImage + deb + rpm)
npm run electron:smoke:packaged  # ಪ್ಯಾಕೇಜ್ ಮಾಡಿದ ಬಿಲ್ಡ್ನ ಸ್ಮೋಕ್-ಟೆಸ್ಟ್
```

ಡೆಸ್ಕ್ಟಾಪ್ ಇನ್ಸ್ಟಾಲರ್ಗಳ ಬಿಡುಗಡೆಗಳನ್ನು GitHub Releasesಗೆ ಲಗತ್ತಿಸಲಾಗಿದೆ. Electron ಕುರಿತು ಸಂಪೂರ್ಣ ಆಳವಾದ ಮಾಹಿತಿಗಾಗಿ (ಸಹಿ ಮಾಡುವುದು, IPC ಬ್ರಿಡ್ಜ್, ವಿತರಣೆಗಳು), [`ELECTRON_GUIDE.md`](./ELECTRON_GUIDE.md) ನೋಡಿ _(ನಂತರದ ಹಂತದಲ್ಲಿ ರಚಿಸಲಾಗಿದೆ)_.

### ಹೆಡ್ಲೆಸ್ ಸರ್ವರ್ (CI/ಸ್ವಯಂಚಾಲನೆ)

ಮಾನವ ಹಸ್ತಕ್ಷೇಪವಿಲ್ಲದ ಸೆಟಪ್ಗಳಿಗಾಗಿ (Docker, Kubernetes, CI), ಇದನ್ನು ಬಳಸಿ:

```bash
omniroute setup --non-interactive
omniroute providers test-batch
```

ಎನ್ವಿರಾನ್ಮೆಂಟ್ ವೇರಿಯಬಲ್ಗಳೊಂದಿಗೆ (`INITIAL_PASSWORD`, `OMNIROUTE_WS_BRIDGE_SECRET`, ಇತ್ಯಾದಿ) ಸಂಯೋಜಿಸಿದಾಗ, ಇದು ಸಂಪೂರ್ಣವಾಗಿ ಸ್ಕ್ರಿಪ್ಟ್ ಮಾಡಬಹುದಾದ OmniRoute ಇನ್ಸ್ಟನ್ಸ್ ಅನ್ನು ಪ್ರಾರಂಭಿಸಲು ನಿಮಗೆ ಅನುಮತಿಸುತ್ತದೆ.

### CLI ಆಯ್ಕೆಗಳು

| ಕಮಾಂಡ್                  | ವಿವರಣೆ                                                                                         |
| ----------------------- | ---------------------------------------------------------------------------------------------- |
| `omniroute`             | ಸರ್ವರ್ ಪ್ರಾರಂಭಿಸಿ (`PORT=20128`, API ಮತ್ತು ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಒಂದೇ ಪೋರ್ಟ್ನಲ್ಲಿ)                      |
| `omniroute setup`       | ಪಾಸ್ವರ್ಡ್ ಮತ್ತು ಮೊದಲ ಪ್ರೊವೈಡರ್ಗಾಗಿ ಮಾರ್ಗದರ್ಶಿತ CLI ಆನ್ಬೋರ್ಡಿಂಗ್                                |
| `omniroute doctor`      | ಸರ್ವರ್ ಪ್ರಾರಂಭಿಸದೆ ಸ್ಥಳೀಯ ಆರೋಗ್ಯ ತಪಾಸಣೆಗಳನ್ನು ಚಲಾಯಿಸಿ                                          |
| `omniroute providers`   | CLIಯಿಂದ ಪ್ರೊವೈಡರ್ಗಳನ್ನು ಅನ್ವೇಷಿಸಿ, ಪಟ್ಟಿ ಮಾಡಿ, ಮೌಲ್ಯೀಕರಿಸಿ ಮತ್ತು ಪರೀಕ್ಷಿಸಿ                     |
| `omniroute config`      | CLI ಪರಿಕರ ಸಂರಚನೆ — ಸಂರಚನೆಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡಿ, ಪಡೆಯಿರಿ, ಹೊಂದಿಸಿ ಮತ್ತು ಮೌಲ್ಯೀಕರಿಸಿ                 |
| `omniroute status`      | ಆಫ್ಲೈನ್ ಸ್ಥಿತಿ ಡ್ಯಾಶ್ಬೋರ್ಡ್ — ಆವೃತ್ತಿ, DB, ಪರಿಕರಗಳು, ಸಂರಚನೆ                                    |
| `omniroute logs`        | APIಯಿಂದ ಬಳಕೆಯ ಲಾಗ್ಗಳನ್ನು ಸ್ಟ್ರೀಮ್ ಮಾಡಿ (`--follow` ಬೆಂಬಲಿಸುತ್ತದೆ)                              |
| `omniroute update`      | OmniRoute ಅಪ್ಡೇಟ್ಗಳಿಗಾಗಿ ಪರಿಶೀಲಿಸಿ ಅಥವಾ ಅವುಗಳನ್ನು ಅನ್ವಯಿಸಿ                                     |
| `omniroute provider`    | ಪ್ರೊವೈಡರ್ ಸಂಪರ್ಕಗಳನ್ನು ನಿರ್ವಹಿಸಿ — ಸೇರಿಸಿ, ಪಟ್ಟಿ ಮಾಡಿ, ತೆಗೆದುಹಾಕಿ, ಪರೀಕ್ಷಿಸಿ, ಡೀಫಾಲ್ಟ್ ಹೊಂದಿಸಿ |
| `omniroute --port 3000` | ಕ್ಯಾನಾನಿಕಲ್/API ಪೋರ್ಟ್ ಅನ್ನು 3000ಗೆ ಹೊಂದಿಸಿ                                                    |
| `omniroute --mcp`       | MCP ಸರ್ವರ್ ಪ್ರಾರಂಭಿಸಿ (stdio ಸಾರಿಗೆ)                                                           |
| `omniroute --no-open`   | ಬ್ರೌಸರ್ ಅನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ತೆರೆಯಬೇಡಿ                                                         |
| `omniroute --help`      | ಸಹಾಯವನ್ನು ತೋರಿಸಿ                                                                               |

ಹೆಡ್ಲೆಸ್ ಸೆಟಪ್ ಅನ್ನು ಫ್ಲ್ಯಾಗ್ಗಳು ಅಥವಾ ಎನ್ವಿರಾನ್ಮೆಂಟ್ ವೇರಿಯಬಲ್ಗಳೊಂದಿಗೆ ಸ್ಕ್ರಿಪ್ಟ್ ಮಾಡಬಹುದು:

```bash
omniroute setup --non-interactive --password "$OMNIROUTE_PASSWORD"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY" --test-provider
```

ಡ್ಯಾಶ್ಬೋರ್ಡ್ ತೆರೆಯದೆ ಸ್ಥಳೀಯ ಡಯಾಗ್ನೋಸ್ಟಿಕ್ಸ್ ಅನ್ನು ಚಲಾಯಿಸಿ:

```bash
omniroute doctor
omniroute doctor --json
omniroute doctor --no-liveness
```

ಡ್ಯಾಶ್ಬೋರ್ಡ್ ತೆರೆಯದೆ SSH ಅಥವಾ ಸ್ಕ್ರಿಪ್ಟ್ಗಳಿಂದ ಪ್ರೊವೈಡರ್ಗಳನ್ನು ನಿರ್ವಹಿಸಿ:

```bash
omniroute providers available
omniroute providers available --search openai
omniroute providers available --category api-key
omniroute providers list
omniroute providers test <id-or-name>
omniroute providers test-all
omniroute providers validate
```

## CLI ಪರಿಕರ ಸಂರಚನೆ

### 1) ಪೂರೈಕೆದಾರರನ್ನು ಸಂಪರ್ಕಿಸಿ ಮತ್ತು API ಕೀಲಿಯನ್ನು ರಚಿಸಿ

1. ಡ್ಯಾಶ್ಬೋರ್ಡ್ → `Providers` ತೆರೆಯಿರಿ ಮತ್ತು ಕನಿಷ್ಠ ಒಬ್ಬ ಪೂರೈಕೆದಾರರನ್ನು (OAuth ಅಥವಾ API ಕೀಲಿ) ಸಂಪರ್ಕಿಸಿ.
2. ಡ್ಯಾಶ್ಬೋರ್ಡ್ → `Endpoints` ತೆರೆಯಿರಿ ಮತ್ತು API ಕೀಲಿಯನ್ನು ರಚಿಸಿ.
3. (ಐಚ್ಛಿಕ) ಡ್ಯಾಶ್ಬೋರ್ಡ್ → `Combos` ತೆರೆಯಿರಿ ಮತ್ತು ನಿಮ್ಮ ಪರ್ಯಾಯ ಸರಪಳಿಯನ್ನು ಹೊಂದಿಸಿ.

### 2) ನಿಮ್ಮ ಕೋಡಿಂಗ್ ಪರಿಕರವನ್ನು ಸಂರಚಿಸಿ

```txt
ಮೂಲ URL: http://localhost:20128/v1
API ಕೀಲಿ:  [Endpoint ಪುಟದಿಂದ ನಕಲಿಸಿ]
ಮಾದರಿ:    if/qwen3.8-max-preview (ಅಥವಾ ಯಾವುದೇ ಪೂರೈಕೆದಾರ/ಮಾದರಿ ಪೂರ್ವಪ್ರತ್ಯಯ)
```

ನಿಮ್ಮ ಎಡಿಟರ್ಗೆ `Authorization: Bearer ...` ಕಳುಹಿಸಲು ಸಾಧ್ಯವಾಗದಿದ್ದರೆ, ಬದಲಿಗೆ ಟೋಕನೀಕರಿಸಿದ ಹೊಂದಾಣಿಕೆ ಮೂಲವನ್ನು ಬಳಸಿ:

```txt
ಮೂಲ URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/
ಮಾದರಿಗಳ URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/models
ಚಾಟ್ URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/chat/completions
Ollama ಟ್ಯಾಗ್ಗಳ URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/api/tags
```

Claude Code, Codex CLI, Cursor, Cline, OpenClaw, OpenCode ಮತ್ತು OpenAI-ಹೊಂದಾಣಿಕೆಯ SDKಗಳೊಂದಿಗೆ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ.

#### `setup-*` ಬಳಸಿ ಸ್ವಯಂ-ಸಂರಚಿಸಿ

ಮೂಲ URL ಮತ್ತು ಕೀಲಿಯನ್ನು ಕೈಯಾರೆ ಅಂಟಿಸುವ ಬದಲು, ಲೈವ್ ಮಾದರಿ ಕ್ಯಾಟಲಾಗ್ನಿಂದ ಪ್ರತಿ ಪರಿಕರದ
ಸ್ವಂತ ಸಂರಚನೆಯನ್ನು OmniRoute ಬರೆಯಲು ಬಿಡಿ. ಪ್ರತಿ ಪರಿಕರಕ್ಕೆ ಒಂದು ಕಮಾಂಡ್:

```bash
omniroute setup-codex        # ~/.codex/<name>.config.toml ಪ್ರೊಫೈಲ್ಗಳು
omniroute setup-claude       # ~/.claude/profiles/<name>/settings.json
omniroute setup-opencode     # ~/.config/opencode/opencode.json (openai-ಹೊಂದಾಣಿಕೆ)
omniroute setup-cline        # Cline CLI + VS Code ವಿಸ್ತರಣೆಯ ಸೆಟ್ಟಿಂಗ್ಗಳು
omniroute setup-kilo         # Kilo Code
omniroute setup-continue     # ~/.continue/config.yaml (Continue / cn)
omniroute setup-cursor       # Cursorನ ಆ್ಯಪ್ನೊಳಗಿನ ಹಂತಗಳನ್ನು ಮುದ್ರಿಸುತ್ತದೆ
omniroute setup-roo          # Roo Code ಆಮದು + autoImport ಪಾಯಿಂಟರ್
omniroute setup-crush        # ~/.config/crush/crush.json
omniroute setup-goose        # ~/.config/goose/config.yaml
omniroute setup-aider        # ~/.aider.conf.yml
omniroute setup-qwen         # ~/.qwen/settings.json + ~/.qwen/.env
```

ಸ್ಥಳೀಯ ಪರಿಕರವನ್ನು **ದೂರಸ್ಥ** OmniRouteಗೆ ಸಂರಚಿಸಲು ಪ್ರತಿಯೊಂದೂ `--remote <url> --api-key <key>` ಅನ್ನು ಮತ್ತು ಪೂರ್ವವೀಕ್ಷಣೆಗಾಗಿ `--dry-run` ಅನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ. ಸರಿಯಾದ
env ಅನ್ನು ಸೇರಿಸಿ, ಯಾವುದೇ ಸಂರಚನೆಯನ್ನು ಬರೆಯದೆಯೇ CLI ಅನ್ನು ಪ್ರಾರಂಭಿಸಲು ಸಾಮಾನ್ಯ ಲಾಂಚರ್
`omniroute run <target>` (claude, codex, aider, goose, opencode, qwen, gemini) ಬಳಸಿ;
ಹಳೆಯ ಪ್ರತಿ-ಪರಿಕರ ಲಾಂಚರ್ಗಳಾದ `omniroute launch` (Claude Code) ಮತ್ತು
`omniroute launch-codex` (Codex) ಇನ್ನೂ ಲಭ್ಯವಿವೆ.

ಸಂಪೂರ್ಣ ಕೋಷ್ಟಕಕ್ಕಾಗಿ (ಪ್ರತಿ ಕಮಾಂಡ್ ಏನನ್ನು ಬರೆಯುತ್ತದೆ, ಪ್ರತಿಯೊಂದು ಫ್ಲ್ಯಾಗ್, ಸ್ಥಳೀಯ ಮತ್ತು ದೂರಸ್ಥ, ಮೂಲ-URL
`/v1` ಸಂಪ್ರದಾಯಗಳು), **[CLI ಏಕೀಕರಣಗಳು](./CLI-INTEGRATIONS.md)** ನೋಡಿ.

ಪ್ರತಿ ಪರಿಕರದ ವಿವರವಾದ ಸಂರಚನೆಗಾಗಿ (Claude Code, Codex CLI, Cursor, Cline, OpenClaw, Kilo Code, Copilot ಮತ್ತು ಇನ್ನಷ್ಟು), ಮೀಸಲಾದ **[CLI ಪರಿಕರಗಳ ಮಾರ್ಗದರ್ಶಿ](../reference/CLI-TOOLS.md)** ನೋಡಿ.

## ಪ್ರೋಟೋಕಾಲ್ ಸೆಟಪ್ (MCP + A2A)

### MCP ಸೆಟಪ್ (ಮಾದರಿ ಸಂದರ್ಭ ಪ್ರೋಟೋಕಾಲ್)

stdio ಮೋಡ್ನಲ್ಲಿ MCP ಸಾರಿಗೆಯನ್ನು ಪ್ರಾರಂಭಿಸಿ:

```bash
omniroute --mcp
```

ಶಿಫಾರಸು ಮಾಡಿದ ಮೌಲ್ಯೀಕರಣ ಪ್ರಕ್ರಿಯೆ:

```bash
# 1. MCP ಸರ್ವರ್ ಅನ್ನು ಪ್ರಾರಂಭಿಸಿ
omniroute --mcp

# 2. ನಿಮ್ಮ MCP ಕ್ಲೈಂಟ್ನಿಂದ, ಇವುಗಳನ್ನು ಕರೆ ಮಾಡಿ:
omniroute_get_health        # ಸಿಸ್ಟಮ್ ಆರೋಗ್ಯವನ್ನು ಹಿಂದಿರುಗಿಸಬೇಕು
omniroute_list_combos       # ಸಕ್ರಿಯ ಕಾಂಬೊಗಳನ್ನು ಹಿಂದಿರುಗಿಸಬೇಕು

# 3. ಅಥವಾ ಸಂಪೂರ್ಣ E2E ಸೂಟ್ ಅನ್ನು ಚಲಾಯಿಸಿ:
npm run test:protocols:e2e
```

#### MCP ಕ್ಲೈಂಟ್ ಸಂರಚನೆ

**Claude Code:**

```bash
claude mcp add-server omniroute --type http --url http://localhost:20128/api/mcp/stream
```

**Cursor / Cline:**

ನಿಮ್ಮ MCP ಸೆಟ್ಟಿಂಗ್ಗಳಿಗೆ ಸೇರಿಸಿ:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"],
      "env": {}

**ಸಂಪೂರ್ಣ MCP ದಸ್ತಾವೇಜು:** [MCP ಸರ್ವರ್ README](../../open-sse/mcp-server/README.md) — 110 ಪರಿಕರಗಳು, IDE ಸಂರಚನೆಗಳು, Python/TS/Go ಕ್ಲೈಂಟ್ಗಳು.

### A2A ಸೆಟಪ್ (ಏಜೆಂಟ್-ನಿಂದ-ಏಜೆಂಟ್ ಪ್ರೋಟೋಕಾಲ್)

## ಕಾಲಾವಧಿ ಮೀರಿಕೆ ಸಂರಚನೆ

### ಮೂಲಭೂತ ಕಾಲಾವಧಿ ಮೀರಿಕೆಗಳು

ಹೆಚ್ಚಿನ ನಿಯೋಜನೆಗಳಿಗೆ, ನಿಮಗೆ ಈ ಎರಡು ವೇರಿಯೇಬಲ್ಗಳು ಮಾತ್ರ ಅಗತ್ಯವಿರುತ್ತವೆ:

| ವೇರಿಯೇಬಲ್                | ಡೀಫಾಲ್ಟ್                                           | ಉದ್ದೇಶ                                                                                                                                                                                |
| ------------------------ | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `REQUEST_TIMEOUT_MS`     | `600000`                                           | ಅಪ್ಸ್ಟ್ರೀಮ್ ಪ್ರತಿಕ್ರಿಯೆ ಪ್ರಾರಂಭದ ಕಾಲಾವಧಿ ಮೀರಿಕೆ, ಅಡಗಿರುವ Undici ಕಾಲಾವಧಿ ಮೀರಿಕೆಗಳು, TLS ಫಿಂಗರ್ಪ್ರಿಂಟ್ ವಿನಂತಿಗಳು ಮತ್ತು API ಬ್ರಿಡ್ಜ್ ವಿನಂತಿ/ಪ್ರಾಕ್ಸಿ ಕಾಲಾವಧಿ ಮೀರಿಕೆಗಳಿಗೆ ಹಂಚಿಕೆಯ ಮೂಲಮಟ್ಟ |
| `STREAM_IDLE_TIMEOUT_MS` | `REQUEST_TIMEOUT_MS` ಅನ್ನು ಆನುವಂಶಿಕವಾಗಿ ಪಡೆಯುತ್ತದೆ | OmniRoute SSE ಸ್ಟ್ರೀಮ್ ಅನ್ನು ಸ್ಥಗಿತಗೊಳಿಸುವ ಮೊದಲು ಸ್ಟ್ರೀಮಿಂಗ್ ಚಂಕ್ಗಳ ನಡುವಿನ ಗರಿಷ್ಠ ಅಂತರ                                                                                                |

ಹಿಂದಿನ ಆವೃತ್ತಿಗಳೊಂದಿಗಿನ ಹೊಂದಾಣಿಕೆಯನ್ನು ಉಳಿಸಲಾಗಿದೆ: ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ `FETCH_TIMEOUT_MS`, `API_BRIDGE_PROXY_TIMEOUT_MS` ಮತ್ತು ಇತರ ಪ್ರತಿ-ಲೇಯರ್ ಕಾಲಾವಧಿ ಮೀರಿಕೆ ವೇರಿಯೇಬಲ್ಗಳು ಈಗಲೂ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತವೆ ಹಾಗೂ ಹಂಚಿಕೆಯ ಮೂಲಮಟ್ಟವನ್ನು ಅತಿಕ್ರಮಿಸುತ್ತವೆ.

### ಪ್ರೊವೈಡರ್-ನಿರ್ದಿಷ್ಟ ಟಿಪ್ಪಣಿಗಳು

Claude Code-ಹೊಂದಾಣಿಕೆಯ ಅಪ್ಸ್ಟ್ರೀಮ್ಗಳಿಗಾಗಿ (`anthropic-compatible-cc-*`), ಪ್ರೊವೈಡರ್ ಬದಿಯ ಓದುವ ಕಾಲಾವಧಿ ಮೀರಿಕೆಗಳು ನಿಮ್ಮ env ಸಂರಚನೆಯೊಂದಿಗೆ ಹೊಂದಾಣಿಕೆಯಲ್ಲಿ ಉಳಿಯುವಂತೆ, ಪರಿಹರಿಸಲಾದ ಫೆಚ್ ಕಾಲಾವಧಿ ಮೀರಿಕೆಯಿಂದ OmniRoute ಹೊರಹೋಗುವ `X-Stainless-Timeout` ಹೆಡರ್ ಅನ್ನು ನಿರ್ಧರಿಸುತ್ತದೆ.

ಮೂರನೇ-ಪಕ್ಷದ Claude Code-ಹೊಂದಾಣಿಕೆಯ ರಿವರ್ಸ್ ಪ್ರಾಕ್ಸಿಗಳಿಗಾಗಿ, OmniRoute ಡೀಫಾಲ್ಟ್ `anthropic-beta` ಸೆಟ್ ಅನ್ನು ಮಿತವಾಗಿರಿಸುತ್ತದೆ ಮತ್ತು `Client Cache Control` ಅನ್ನು `Auto` ಸ್ಥಿತಿಯಲ್ಲೇ ಬಿಟ್ಟಾಗ, ಕ್ಲೈಂಟ್ ಒದಗಿಸಿದ `cache_control` ಮಾರ್ಕರ್ಗಳನ್ನು ಮಾತ್ರ ಫಾರ್ವರ್ಡ್ ಮಾಡುತ್ತದೆ. ಅಪ್ಸ್ಟ್ರೀಮ್ಗೆ ರಿಡ್ಯಾಕ್ಟ್ ಮಾಡಲಾದ Claude ಚಿಂತನಾ ಸ್ಟ್ರೀಮ್ಗಳು ನಿರ್ದಿಷ್ಟವಾಗಿ ಅಗತ್ಯವಿದ್ದಾಗ ಮಾತ್ರ ಪ್ರತಿ-ಸಂಪರ್ಕದ "ರಿಡ್ಯಾಕ್ಟ್-ಥಿಂಕಿಂಗ್ ಬೀಟಾವನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ" ಟಾಗಲ್ ಅನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ.

| `API_BRIDGE_SERVER_KEEPALIVE_TIMEOUT_MS` | `5000`                                                           | API ಬ್ರಿಡ್ಜ್ ಸರ್ವರ್ನ ಕೀಪ್-ಅಲೈವ್ ಕಾಲಾವಧಿ ಮೀರಿಕೆ                                           |
| `API_BRIDGE_SERVER_SOCKET_TIMEOUT_MS`    | `0`                                                              | API ಬ್ರಿಡ್ಜ್ ಸರ್ವರ್ನ ಸಾಕೆಟ್ ನಿಷ್ಕ್ರಿಯತೆ ಕಾಲಾವಧಿ ಮೀರಿಕೆ (`0` ಅದನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುತ್ತದೆ) |

> **ಟಿಪ್ಪಣಿ:** ಸ್ಟ್ರೀಮಿಂಗ್ ವಿನಂತಿಗಳಿಗಾಗಿ, `FETCH_TIMEOUT_MS` ಸಂಪರ್ಕ ಸ್ಥಾಪನೆ / ಮೊದಲ ಅಪ್ಸ್ಟ್ರೀಮ್ ಪ್ರತಿಕ್ರಿಯೆಗಾಗಿ ಕಾಯುವುದನ್ನು ಮಾತ್ರ ಒಳಗೊಳ್ಳುತ್ತದೆ. ಸ್ಟ್ರೀಮ್ ಸಕ್ರಿಯವಾದ ನಂತರ, ನೈಜ ಸ್ಥಗಿತ (`STREAM_IDLE_TIMEOUT_MS`) ಅಥವಾ Undici ಬಾಡಿ ನಿಷ್ಕ್ರಿಯತೆ (`FETCH_BODY_TIMEOUT_MS`) ಸಂಭವಿಸಿದಾಗ ಮಾತ್ರ OmniRoute ಅದನ್ನು ಸ್ಥಗಿತಗೊಳಿಸುತ್ತದೆ.

### ರಿವರ್ಸ್ ಪ್ರಾಕ್ಸಿ ಹೊಂದಾಣಿಕೆ

ನೀವು OmniRoute ಅನ್ನು Nginx, Caddy, Cloudflare ಅಥವಾ ಮತ್ತೊಂದು ರಿವರ್ಸ್ ಪ್ರಾಕ್ಸಿಯ ಹಿಂದೆ ಚಲಾಯಿಸುತ್ತಿದ್ದರೆ, ಪ್ರಾಕ್ಸಿ ಕಾಲಾವಧಿ ಮೀರಿಕೆಗಳೂ ಸಹ ನಿಮ್ಮ OmniRoute ಸ್ಟ್ರೀಮ್/ಫೆಚ್ ಕಾಲಾವಧಿ ಮೀರಿಕೆಗಳಿಗಿಂತ ಹೆಚ್ಚಿರುವುದನ್ನು ಖಚಿತಪಡಿಸಿಕೊಳ್ಳಿ.

## ಸ್ಪ್ಲಿಟ್-ಪೋರ್ಟ್ ಮೋಡ್

ಸುಧಾರಿತ ಸನ್ನಿವೇಶಗಳಿಗಾಗಿ (ರಿವರ್ಸ್ ಪ್ರಾಕ್ಸಿ, ಕಂಟೇನರ್ ನೆಟ್ವರ್ಕಿಂಗ್) API ಮತ್ತು ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಅನ್ನು ಪ್ರತ್ಯೇಕ ಪೋರ್ಟ್ಗಳಲ್ಲಿ ಚಲಾಯಿಸಿ:

PORT=20128 DASHBOARD_PORT=20129 omniroute
# API:       http://localhost:20128/v1
# ಡ್ಯಾಶ್ಬೋರ್ಡ್: http://localhost:20129
```

## Void Linux (xbps-src) ಟೆಂಪ್ಲೇಟ್

Void Linux ಬಳಕೆದಾರರು `xbps-src` ಬಳಸಿ ಸ್ಥಳೀಯ ಪ್ಯಾಕೇಜ್ ಅನ್ನು ನಿರ್ಮಿಸಬಹುದು. ಈ ಬ್ಲಾಕ್ ಅನ್ನು `srcpkgs/omniroute/template` ಆಗಿ ಉಳಿಸಿ:

```bash
# 'omniroute' ಗಾಗಿನ ಟೆಂಪ್ಲೇಟ್ ಫೈಲ್
pkgname=omniroute
version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"
maintainer="zenobit <zenobit@disroot.org>"
license="MIT"
homepage="https://github.com/diegosouzapw/OmniRoute"
distfiles="https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz"
# ಪ್ರತಿ ಬಿಡುಗಡೆಯ checksum ಅನ್ನು ಈ ಕೆಳಗಿನಂತೆ ಮರುರಚಿಸಿ:
#   curl -L -o /tmp/omniroute.tar.gz "https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz" && sha256sum /tmp/omniroute.tar.gz
checksum=PLACEHOLDER_REGENERATE_PER_RELEASE
system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	NODE_ENV=development npm ci --ignore-scripts
	npm run build
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	rm -rf .next/standalone/node_modules/@img

	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
		touch "${DESTDIR}/usr/lib/omniroute/${_d}/.keep"
	done

	cat > "${WRKDIR}/omniroute" <<'EOF'
#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"
mkdir -p "${DATA_DIR}"
exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```
