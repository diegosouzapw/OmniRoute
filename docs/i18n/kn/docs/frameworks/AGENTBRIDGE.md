AgentBridge ಎಂಬುದು OmniRoute ನ MITM (ಮ್ಯಾನ್-ಇನ್-ದ-ಮಿಡಲ್) ಪ್ರಾಕ್ಸಿಯಾಗಿದ್ದು, IDE AI ಏಜೆಂಟ್ಗಳಿಂದ ಬರುವ HTTPS ಟ್ರಾಫಿಕ್ ಅನ್ನು ತಡೆಹಿಡಿದು, ಅದನ್ನು OmniRoute ನ ಏಕೀಕೃತ ರೂಟಿಂಗ್ ಎಂಜಿನ್ ಮೂಲಕ ಮರುಮಾರ್ಗಗೊಳಿಸುತ್ತದೆ. ಇದು **10 IDE ಏಜೆಂಟ್ಗಳನ್ನು** ಬೆಂಬಲಿಸುತ್ತದೆ — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code, ಮತ್ತು Trae (ತನಿಖೆಯಲ್ಲಿದೆ) — ಇದರಿಂದ OmniRoute ಮಾರುಕಟ್ಟೆಯಲ್ಲಿನ AI ಕೋಡಿಂಗ್ ಸಹಾಯಕಗಳಿಗಾಗಿ ಅತ್ಯಂತ ವ್ಯಾಪಕ ವ್ಯಾಪ್ತಿಯ MITM ಪ್ರಾಕ್ಸಿಯಾಗಿದೆ.

**ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಸ್ಥಳ:** `/dashboard/tools/agent-bridge`
**ಸೈಡ್ಬಾರ್ ಗುಂಪು:** ಪರಿಕರಗಳು (Cloud Agents ನಂತರ)
**ಇದನ್ನೂ ನೋಡಿ:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — ತಡೆಹಿಡಿಯಲಾದ ಎಲ್ಲಾ ಟ್ರಾಫಿಕ್ ಅನ್ನು ನೈಜ ಸಮಯದಲ್ಲಿ ಮೇಲ್ವಿಚಾರಣೆ ಮಾಡಿ; `docs/security/MITM-TPROXY-DECRYPT.md` (git; `/docs` ಗೆ ಕಂಪೈಲ್ ಮಾಡಲಾಗಿಲ್ಲ) — `/api/tools/agent-bridge/tproxy` ಮಾರ್ಗದಿಂದ ಚಾಲಿತವಾಗುವ Linux TPROXY ಪಾರದರ್ಶಕ-ಡೀಕ್ರಿಪ್ಟ್ ಕ್ಯಾಪ್ಚರ್ ಮೋಡ್.

## §1 ಅವಲೋಕನ

### AgentBridge ಎಂದರೇನು?

IDE ಏಜೆಂಟ್ (ಉದಾ., GitHub Copilot, Cursor, Claude Code) API ಕರೆಯನ್ನು ಮಾಡಿದಾಗ, ಅದು ನೇರವಾಗಿ ಅಪ್ಸ್ಟ್ರೀಮ್ AI ಪೂರೈಕೆದಾರರಿಗೆ (OpenAI, Anthropic, ಇತ್ಯಾದಿ) ಸಂಪರ್ಕಿಸುತ್ತದೆ. ಯಾವುದೇ ಏಜೆಂಟ್ ಕಾನ್ಫಿಗರೇಶನ್ ಬದಲಾವಣೆಯ ಅಗತ್ಯವಿಲ್ಲದೆ — AgentBridge ಆ ಸಂಪರ್ಕವನ್ನು TLS ಹಂತದಲ್ಲಿ ಪಾರದರ್ಶಕವಾಗಿ ತಡೆಹಿಡಿದು, ವಿನಂತಿಯನ್ನು OmniRoute ಮೂಲಕ ಮರುಬರೆಯುತ್ತದೆ.

ಇದರರ್ಥ ನೀವು ಹೀಗೆ ಮಾಡಬಹುದು:

- **ಯಾವುದೇ ಏಜೆಂಟ್ ಅನ್ನು ಯಾವುದೇ ಪೂರೈಕೆದಾರರಿಗೆ ಮರುಮಾರ್ಗಗೊಳಿಸಿ**: Copilot OpenAI ಜೊತೆಗೆ ಸಂವಹನ ನಡೆಸುತ್ತಿದೆಯೇ? ಅದನ್ನು Anthropic Claude, Gemini, ಅಥವಾ OmniRoute ನ 352 ಪೂರೈಕೆದಾರರಲ್ಲಿ ಯಾರಿಗಾದರೂ ಮರುನಿರ್ದೇಶಿಸಿ.
- **ಮಾದರಿ ಮ್ಯಾಪಿಂಗ್ಗಳನ್ನು ಅನ್ವಯಿಸಿ**: ಹ್ಯಾಂಡ್ಲರ್ ಹಂತದಲ್ಲಿ ಪಾರದರ್ಶಕವಾಗಿ `gemini-3-flash` → `claude-sonnet-4.7`.
- **ಎಲ್ಲಾ ಏಜೆಂಟ್ ಟ್ರಾಫಿಕ್ ಅನ್ನು ವೀಕ್ಷಿಸಿ**: ತಡೆಹಿಡಿಯಲಾದ ಪ್ರತಿಯೊಂದು ವಿನಂತಿಯನ್ನೂ [ಟ್ರಾಫಿಕ್ ಇನ್ಸ್ಪೆಕ್ಟರ್](./TRAFFIC_INSPECTOR.md) ಗೆ ಪ್ರಕಟಿಸಲಾಗುತ್ತದೆ.
- **OmniRoute ಸ್ಥಿತಿಸ್ಥಾಪಕತೆಯನ್ನು ಅನ್ವಯಿಸಿ**: ಕಾಂಬೊ ರೂಟಿಂಗ್, ಸರ್ಕ್ಯೂಟ್ ಬ್ರೇಕರ್ಗಳು, ಫಾಲ್ಬ್ಯಾಕ್ಗಳು ಮತ್ತು ವೆಚ್ಚ ಟ್ರ್ಯಾಕಿಂಗ್ IDE ಏಜೆಂಟ್ ಟ್ರಾಫಿಕ್ಗೂ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತವೆ.

## §2 ವಾಸ್ತುಶಿಲ್ಪ

### 2.1 ಘಟಕಗಳ ಅವಲೋಕನ

```
IDE ಏಜೆಂಟ್ (VS Code / Cursor / ಇತ್ಯಾದಿ)
    │  HTTPS (ಪೋರ್ಟ್ 443)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← DNS ಮರುನಿರ್ದೇಶನ
    │
    ▼
src/mitm/server.cjs  (ಪೋರ್ಟ್ 443, CJS ಉಪ ಪ್ರಕ್ರಿಯೆ)
    │  Host ಹೆಡರ್ SNI ಮೂಲಕ ಗುರಿಯನ್ನು ನಿರ್ಧರಿಸುತ್ತದೆ
    │  AgentBridge CA ಸಹಿ ಮಾಡಿದ ಪ್ರತಿ-SNI TLS ಪ್ರಮಾಣಪತ್ರವನ್ನು ರಚಿಸುತ್ತದೆ
    ├── ಬೈಪಾಸ್ ಪಟ್ಟಿಗೆ ಹೊಂದಿಕೆಯಾಗುತ್ತದೆಯೇ? → TCP ಪಾಸ್ಥ್ರೂ (ಡೀಕ್ರಿಪ್ಟ್ ಇಲ್ಲ)
    ├── ಗುರಿಗೆ ಹೊಂದಿಕೆಯಾಗುತ್ತದೆಯೇ? → fetch → OmniRoute ರೌಟರ್ (ಪೋರ್ಟ್ 20128)
    │       └── handler.intercept() — TypeScript
    │               ├── ವಿನಂತಿಯ ಬಾಡಿ/ಹೆಡರ್ಗಳ ಮೇಲೆ maskSecrets()
    │               ├── TrafficBuffer.push() — Traffic Inspector ಗೆ ಪ್ರಕಟಿಸುತ್ತದೆ
    │               └── fetchRouter() → /v1/chat/completions
    └── ಹೊಂದಿಕೆ ಇಲ್ಲವೇ? → TCP ಪಾಸ್ಥ್ರೂ (ಡೀಕ್ರಿಪ್ಟ್ ಇಲ್ಲ)
```

### 2.2 MITM ಸರ್ವರ್ (`src/mitm/server.cjs`)

ಪ್ರಮುಖ MITM ಸರ್ವರ್ Node.js CJS ಉಪ ಪ್ರಕ್ರಿಯೆಯಾಗಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ (ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ CJS ಕೋಡ್ಬೇಸ್ ಅನ್ನು ಮರುಬರೆಯುವುದನ್ನು ತಪ್ಪಿಸಲು). ಇದು:

- ಪೋರ್ಟ್ 443 ನಲ್ಲಿ ಆಲಿಸುತ್ತದೆ (ವಿಶೇಷಾಧಿಕಾರ ಅಥವಾ `authbind`/`setcap` ಅಗತ್ಯವಿದೆ)
- OS ನಿಂದ CONNECT ಟನಲ್ಗಳನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ (`/etc/hosts` DNS ಮರುನಿರ್ದೇಶನದ ಮೂಲಕ)
- AgentBridge CA (`DATA_DIR/mitm/ca.crt`) ಸಹಿ ಮಾಡಿದ ಪ್ರತಿ-SNI TLS ಪ್ರಮಾಣಪತ್ರಗಳನ್ನು ರಚಿಸುತ್ತದೆ
- `targets/index.ts` ರಿಜಿಸ್ಟ್ರಿಯ ಮೂಲಕ Host ಹೆಡರ್ ಆಧರಿಸಿ ಗುರಿ ಏಜೆಂಟ್ ಅನ್ನು ನಿರ್ಧರಿಸುತ್ತದೆ
- HTTP ಮೂಲಕ `http://127.0.0.1:20128` ಗೆ TypeScript ಹ್ಯಾಂಡ್ಲರ್ ಪದರಕ್ಕೆ ರವಾನಿಸುತ್ತದೆ

`TARGET_HOSTS` ಅನ್ನು `DATA_DIR/mitm/targets.json` ನಿಂದ ಲೋಡ್ ಮಾಡಲಾಗುತ್ತದೆ (ಬೂಟ್ ಸಮಯದಲ್ಲಿ `targets/index.ts` ಬರೆಯುತ್ತದೆ), ಇದರಿಂದ CJS ಸರ್ವರ್ ಅನ್ನು ಮರುಪ್ರಾರಂಭಿಸದೆಯೇ ಡೈನಾಮಿಕ್ ನವೀಕರಣಗಳನ್ನು ಮಾಡಲು ಸಾಧ್ಯವಾಗುತ್ತದೆ.

> **ರೂಟ್-CA ಮಾದರಿ (#6684).** ಮೇಲೆ ವಿವರಿಸಿದ CA-ಸಹಿ-ಮಾಡಿದ-ಪ್ರತಿ-SNI-ಪ್ರಮಾಣಪತ್ರ
> ಮಾದರಿಯು #6684 ರಲ್ಲಿ ಸೇರಿಸಲಾದ ಶಾಶ್ವತ ರೂಟ್-CA ಮಾದರಿಯಾಗಿದೆ (`src/mitm/cert/rootCa.ts` +
> `src/mitm/_internal/rootCaShim.cjs`, `src/mitm/tproxy/dynamicCert.ts` ನಲ್ಲಿ TPROXY ಗಾಗಿ
> ಈಗಾಗಲೇ ಸಾಬೀತಾಗಿರುವ CA/ಲೀಫ್ ಕ್ರಿಪ್ಟೊವನ್ನು ಮರುಬಳಕೆ ಮಾಡುತ್ತದೆ) — ಇದು ಡಿಸ್ಕ್ನಲ್ಲಿರುವ ಕೇವಲ
> `server.crt`/`server.key` ಜೋಡಿ ಸೂಚಿಸುವ ಹಳೆಯ ಏಕೈಕ ಸ್ಥಿರ ಸ್ವಯಂ-ಸಹಿ ಮಾಡಿದ ಲೀಫ್
> (`src/mitm/cert/generate.ts`, ಇನ್ನೂ antigravity ಹೋಸ್ಟ್ಗಳಿಗೆ ಮಾತ್ರ ಸೀಮಿತವಾಗಿದೆ) ಅನ್ನು
> ಬದಲಿಸುತ್ತದೆ. **ವಲಸೆ ನಡವಳಿಕೆ**: ಹೊಸ ಸ್ಥಾಪನೆಯು (ಹಿಂದಿನ `server.crt` ಇಲ್ಲದಿದ್ದರೆ)
> ರೂಟ್-CA ಮಾದರಿಯನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಪಡೆಯುತ್ತದೆ; ಹಳೆಯ ಸ್ಥಿರ ಲೀಫ್ ಅನ್ನು ಈಗಾಗಲೇ ನಂಬಿರುವ
> ಸ್ಥಾಪನೆಯು, ನಿರ್ವಾಹಕರು `MITM_ROOT_CA_ENABLED=true` ಹೊಂದಿಸಿ ಬ್ರಿಡ್ಜ್ ಅನ್ನು ಮರುಪ್ರಾರಂಭಿಸುವವರೆಗೆ
> ಅದನ್ನೇ ಬಳಸುವುದನ್ನು ಮುಂದುವರಿಸುತ್ತದೆ (`src/mitm/cert/migration.ts` ಶುದ್ಧ ನಿರ್ಧಾರ ಫಂಕ್ಷನ್ ಆಗಿದೆ —
> **ಯಾವುದೇ** ಹೋಸ್ಟ್ಗೆ ಲೀಫ್ಗೆ ಸಹಿ ಮಾಡಬಲ್ಲ ವಿಶ್ವಾಸಾರ್ಹ MITM CA, ಹಳೆಯ ಸ್ಥಿರ-SAN ಲೀಫ್ಗಿಂತ
> ಗಣನೀಯವಾಗಿ ಹೆಚ್ಚು ಶಕ್ತಿಶಾಲಿಯಾಗಿದೆ; ಆದ್ದರಿಂದ ಈಗಾಗಲೇ ವಿಶ್ವಾಸಾರ್ಹವಾಗಿರುವ ಸ್ಥಾಪನೆಗೆ ಬದಲಾವಣೆಯು
> ಎಂದಿಗೂ ಮೌನವಾಗಿ ನಡೆಯುವುದಿಲ್ಲ). CA ಪ್ರಮಾಣಪತ್ರವನ್ನು ಹಳೆಯ ಲೀಫ್ ಬಳಸುತ್ತಿದ್ದ ಅದೇ
> `omniroute-mitm.crt` ಟ್ರಸ್ಟ್-ಸ್ಟೋರ್ ಸ್ಲಾಟ್ನಲ್ಲಿ ಸ್ಥಾಪಿಸಲಾಗುತ್ತದೆ
> (`cert/install.ts::installCaCert`) — ದ್ವಂದ್ವ-ವಿಶ್ವಾಸದ ಸ್ವಚ್ಛಗೊಳಿಸುವಿಕೆ ಅಗತ್ಯವಿಲ್ಲ.

### 2.3 ಹ್ಯಾಂಡ್ಲರ್ ಬೇಸ್ (`src/mitm/handlers/base.ts`)

ಎಲ್ಲ ಏಜೆಂಟ್ ಹ್ಯಾಂಡ್ಲರ್ಗಳು `MitmHandlerBase` ಅನ್ನು ವಿಸ್ತರಿಸುತ್ತವೆ:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // ಸಂರಕ್ಷಿತ ಸಹಾಯಕಗಳು: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

ಪ್ರತಿ ಹ್ಯಾಂಡ್ಲರ್ ಪ್ರಾಕ್ಸಿ ಮಾಡುವ ಮೊದಲು `hookBufferStart()` ಅನ್ನು ಮತ್ತು ಪೂರ್ಣಗೊಂಡಾಗ `hookBufferUpdate()` ಅನ್ನು ಕರೆಯುತ್ತದೆ. ಇವು `InterceptedRequest` ನಮೂದುಗಳನ್ನು `globalTrafficBuffer` ಗೆ ಪುಶ್ ಮಾಡುತ್ತವೆ ([Traffic Inspector](./TRAFFIC_INSPECTOR.md) §4 ನೋಡಿ).

### 2.4 ಗುರಿಗಳ ರಿಜಿಸ್ಟ್ರಿ (`src/mitm/targets/`)

ಪ್ರತಿ ಏಜೆಂಟ್ಗೆ ಘೋಷಣಾತ್ಮಕ ಗುರಿ ಫೈಲ್ ಇರುತ್ತದೆ:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

ರಿಜಿಸ್ಟ್ರಿಯು (`targets/index.ts`) `ALL_TARGETS` ಅನ್ನು ರಫ್ತು ಮಾಡುತ್ತದೆ ಮತ್ತು ಬೂಟ್ ಸಮಯದಲ್ಲಿ `DATA_DIR/mitm/targets.json` ಅನ್ನು ರಚಿಸುತ್ತದೆ.

### 2.5 ಪಾಸ್ಥ್ರೂ ಮತ್ತು ಬೈಪಾಸ್ ಪಟ್ಟಿ (`src/mitm/passthrough.ts`)

**ಬೈಪಾಸ್ ಪಟ್ಟಿ** (ಗುರಿ ಹೊಂದಾಣಿಕೆಗಿಂತ ಆದ್ಯತೆಯೊಂದಿಗೆ ಮೊದಲು ಪರಿಶೀಲಿಸಲಾಗುತ್ತದೆ):

- ಡೀಫಾಲ್ಟ್ ಮಾದರಿಗಳು: ಬ್ಯಾಂಕಿಂಗ್ ಹೋಸ್ಟ್ಗಳು, `.gov.`, OAuth/SSO ಪೂರೈಕೆದಾರರು (Okta, Auth0), ಇತ್ಯಾದಿ.
- ಬಳಕೆದಾರರ ಮಾದರಿಗಳು: DB ಟೇಬಲ್ `agent_bridge_bypass` ನಲ್ಲಿ ಸಂಗ್ರಹಿಸಲಾಗುತ್ತದೆ
- ಬೈಪಾಸ್ ಮಾಡಿದ ಹೋಸ್ಟ್ಗಳು ಪಾರದರ್ಶಕ TCP ಟನಲ್ ಅನ್ನು ಪಡೆಯುತ್ತವೆ — TLS ಅನ್ನು **ಎಂದಿಗೂ ಡೀಕ್ರಿಪ್ಟ್ ಮಾಡುವುದಿಲ್ಲ**

**ಡೀಫಾಲ್ಟ್ ಪಾಸ್ಥ್ರೂ** (ಗುರಿಗೆ ಹೊಂದಾಣಿಕೆ ಇಲ್ಲ ಮತ್ತು ಬೈಪಾಸ್ನಲ್ಲಿಯೂ ಇಲ್ಲ):

- ಇದೂ TCP ಟನಲ್ ಅನ್ನು ಪಡೆಯುತ್ತದೆ — ಸಂಪರ್ಕಗಳನ್ನು ಎಂದಿಗೂ ಮುರಿಯುವುದಿಲ್ಲ
- AgentBridge ಸಾಮಾನ್ಯ ಸಿಸ್ಟಮ್ HTTPS ಸಂಚಾರಕ್ಕೆ ಅಡ್ಡಿಪಡಿಸುವುದನ್ನು ತಡೆಯುತ್ತದೆ

ರೂಟಿಂಗ್ ಆದ್ಯತೆ:

```
ಬೈಪಾಸ್ ಪಟ್ಟಿ → ಗುರಿ ಹೊಂದಾಣಿಕೆ → ಪಾಸ್ಥ್ರೂ
```

### 2.6 ಅಪ್ಸ್ಟ್ರೀಮ್ CA ಪ್ರಮಾಣಪತ್ರ (`src/mitm/upstreamTrust.ts`)

ಕಸ್ಟಮ್ CA ಹೊಂದಿರುವ ಕಾರ್ಪೊರೇಟ್ ನೆಟ್ವರ್ಕ್ ಪರಿಸರಗಳಿಗಾಗಿ:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

ಇದನ್ನು ಹೊಂದಿಸಿದಾಗ, ಹೆಚ್ಚುವರಿ CA ಪ್ರಮಾಣಪತ್ರದೊಂದಿಗೆ `undici` ಯ ಗ್ಲೋಬಲ್ ಡಿಸ್ಪ್ಯಾಚರ್ ಅನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡುತ್ತದೆ; ಇದರಿಂದ AgentBridge ಕಾರ್ಪೊರೇಟ್ TLS ಟರ್ಮಿನೇಷನ್ ಪ್ರಾಕ್ಸಿಗಳ ಮೂಲಕ ಅಪ್ಸ್ಟ್ರೀಮ್ ಪೂರೈಕೆದಾರರನ್ನು ತಲುಪಬಹುದು.

### 2.7 ರಹಸ್ಯ ಮರೆಮಾಚುವಿಕೆ (`src/mitm/maskSecrets.ts`)

ಸ್ವತಂತ್ರ ಕ್ಲೀನ್-ರೂಮ್ ಸ್ಕ್ಯಾನರ್ ಅನ್ನು ವಿನಂತಿಯ ಬಾಡಿಗಳು ಮತ್ತು ರುಜುವಾತು ಹೆಡರ್ಗಳು
Traffic Inspector ಬಫರ್ ಅಥವಾ ಯಾವುದೇ ಲಾಗ್ಗೆ ಪ್ರವೇಶಿಸುವ **ಮೊದಲು** ಅನ್ವಯಿಸಲಾಗುತ್ತದೆ. ಇದು ಒಂದೇ ರೇಖೀಯ ಪಾಸ್ ಅನ್ನು ನಿರ್ವಹಿಸುತ್ತದೆ:

- `sk-` / `ak-` / `pk-` ಪೂರ್ವಪ್ರತ್ಯಯದ ಟೋಕನ್ಗಳು (OpenAI/Anthropic-ಶೈಲಿ)
- RFC 6750 `Authorization: Bearer <token>` ರುಜುವಾತುಗಳು, ಸಂಪೂರ್ಣ-ಟೋಕನ್ ಆದ್ಯತೆಯೊಂದಿಗೆ
- ಸಾಮಾನ್ಯ ಉದ್ದನೆಯ ಅಪಾರದರ್ಶಕ ಟೋಕನ್ಗಳು (≥40 ಅಕ್ಷರಗಳು), ಚುಕ್ಕೆಗಳು ಮತ್ತು ಪ್ಯಾಡಿಂಗ್ ಹೊಂದಿರುವ ರೂಪಗಳೂ ಸೇರಿದಂತೆ

`sanitizeHeaders()` ಉಳಿಸಿಕೊಂಡ ಹೆಸರುಗಳನ್ನು ಸಣ್ಣಕ್ಷರಕ್ಕೆ ಪರಿವರ್ತಿಸುತ್ತದೆ, ಅರೆ ಮೌಲ್ಯಗಳನ್ನು ನಿರ್ಣಾಯಕವಾಗಿ ಜೋಡಿಸುತ್ತದೆ,
ಹಂಚಿಕೆಯ ಹಾಪ್-ಬೈ-ಹಾಪ್/ಫ್ರೇಮಿಂಗ್ ನಿರಾಕರಣೆ ಪಟ್ಟಿಯನ್ನು (ಪ್ರಾಕ್ಸಿ ದೃಢೀಕರಣವೂ ಸೇರಿದಂತೆ) ತೆಗೆದುಹಾಕುತ್ತದೆ, `cookie` ಮತ್ತು
`set-cookie` ಅನ್ನು ಸಂಪೂರ್ಣವಾಗಿ ಮರೆಮಾಚುತ್ತದೆ ಮತ್ತು ರುಜುವಾತು ಮೌಲ್ಯಗಳನ್ನು ಸ್ಕ್ಯಾನರ್ಗೆ ನಿಯೋಜಿಸುತ್ತದೆ.

### 3.1 MITM ಸರ್ವರ್ ಅನ್ನು ಪ್ರಾರಂಭಿಸಿ/ನಿಲ್ಲಿಸಿ

`/dashboard/tools/agent-bridge` ನಲ್ಲಿರುವ AgentBridge ಸರ್ವರ್ ಕಾರ್ಡ್ ಅನ್ನು ಬಳಸಿ:

| ಕ್ರಿಯೆ                   | ವಿವರಣೆ                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------ |
| ಸರ್ವರ್ ಪ್ರಾರಂಭಿಸಿ        | ಪೋರ್ಟ್ 443 ರಲ್ಲಿ `src/mitm/server.cjs` ಅನ್ನು ಪ್ರಾರಂಭಿಸುತ್ತದೆ                               |
| ಸರ್ವರ್ ನಿಲ್ಲಿಸಿ          | ಉಪ ಪ್ರಕ್ರಿಯೆಯನ್ನು ಸುರಕ್ಷಿತವಾಗಿ ಸ್ಥಗಿತಗೊಳಿಸುತ್ತದೆ                                           |
| ಸರ್ವರ್ ಮರುಪ್ರಾರಂಭಿಸಿ     | ನಿಲ್ಲಿಸಿ + ಪ್ರಾರಂಭಿಸಿ (ಗುರಿ ಬದಲಾವಣೆಗಳನ್ನು ಅನ್ವಯಿಸುತ್ತದೆ)                                   |
| ಪ್ರಮಾಣಪತ್ರವನ್ನು ನಂಬಿ     | `DATA_DIR/mitm/ca.crt` ಅನ್ನು OS ವಿಶ್ವಾಸಾರ್ಹ ಸಂಗ್ರಹದಲ್ಲಿ ಸ್ಥಾಪಿಸುತ್ತದೆ                      |
| ಪ್ರಮಾಣಪತ್ರ ಡೌನ್ಲೋಡ್ ಮಾಡಿ | ಹಸ್ತಚಾಲಿತ ಸ್ಥಾಪನೆಗಾಗಿ `ca.crt` ಅನ್ನು ಡೌನ್ಲೋಡ್ ಮಾಡುತ್ತದೆ                                    |
| ಪ್ರಮಾಣಪತ್ರ ಮರುರಚಿಸಿ      | ಹೊಸ CA ಕೀಲಿಜೋಡಿಯನ್ನು ರಚಿಸುತ್ತದೆ (ಈಗಿರುವ ಎಲ್ಲ ಪ್ರತಿ-ಏಜೆಂಟ್ ಪ್ರಮಾಣಪತ್ರಗಳು ಅಮಾನ್ಯಗೊಳ್ಳುತ್ತವೆ) |

### 3.2 ಪ್ರಮಾಣಪತ್ರವನ್ನು ನಂಬಿ

IDEಗಳು MITM ಸಂಪರ್ಕವನ್ನು ಸ್ವೀಕರಿಸುವ ಮೊದಲು AgentBridge CA ಪ್ರಮಾಣಪತ್ರವನ್ನು OS ನಂಬಿರಬೇಕು.

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Keychain):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

ಅಥವಾ ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿರುವ "ಪ್ರಮಾಣಪತ್ರವನ್ನು ನಂಬಿ" ಬಟನ್ ಬಳಸಿ (ಇದು ನಿಮ್ಮ OS ಗೆ ಸೂಕ್ತವಾದ ಕಮಾಂಡ್ ಅನ್ನು ಚಲಾಯಿಸುತ್ತದೆ ಮತ್ತು ಅಗತ್ಯವಿದ್ದರೆ sudo ಪ್ರಾಂಪ್ಟ್ ತೋರಿಸುತ್ತದೆ).

#### Electron-ಆಧಾರಿತ IDEಗಳು OS ವಿಶ್ವಾಸಾರ್ಹ ಸಂಗ್ರಹವನ್ನು ನಿರ್ಲಕ್ಷಿಸುತ್ತವೆ (`NODE_EXTRA_CA_CERTS`)

ಕೆಲವು IDEಗಳು — ವಿಶೇಷವಾಗಿ **Antigravity IDE**, ಮತ್ತು ಇತರ Electron / VS Code-ಆಧಾರಿತ ಆ್ಯಪ್ಗಳು — ಹೊರಹೋಗುವ
`fetch`/HTTPS ಗಾಗಿ **OS ವಿಶ್ವಾಸಾರ್ಹ ಸಂಗ್ರಹವನ್ನು ಪರಿಶೀಲಿಸದ** ತಮ್ಮದೇ Node.js ರನ್ಟೈಮ್ ಅನ್ನು ಒಳಗೊಂಡಿರುತ್ತವೆ.
OS/NSS ಹಂತದಲ್ಲಿ CA ಅನ್ನು ನಂಬುವುದು IDEಯ ಸ್ಥಳೀಯ **ಬ್ಯಾಕೆಂಡ್ಗೆ**
(ಉದಾ. OS CA ಬಂಡಲ್ ಬಳಸುವ Go ಭಾಷಾ ಸರ್ವರ್) ಸಾಕಾಗುತ್ತದೆ, ಆದರೆ **Electron ಫ್ರಂಟ್ಎಂಡ್ನಲ್ಲಿ**
TLS ಇನ್ನೂ ವಿಫಲವಾಗುತ್ತದೆ — MITM ಲಾಗ್ನಲ್ಲಿ ಬ್ಯಾಕೆಂಡ್ನ ಬೂಟ್ಸ್ಟ್ರ್ಯಾಪ್ ಕರೆಗಳು `200` ಅನ್ನು ಮರಳಿಸುತ್ತಿರುವುದು
ಕಂಡುಬಂದರೂ, ಆ್ಯಪ್ _ಲಾಗ್ ಔಟ್ ಆಗಿರುವಂತೆ_ ಅಥವಾ _"ಸಂಪರ್ಕ ದೋಷ"_ ತೋರಿಸುವಂತೆ ಇದು ಗೋಚರಿಸುತ್ತದೆ. ಎರಡು ಹಂತಗಳು
ಅಗತ್ಯವಿವೆ ಮತ್ತು ಎರಡೂ ಮುಖ್ಯ:

1. ರನ್ಟೈಮ್ಗೆ CA ಅನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ಸೂಚಿಸಿ:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **ಆ ಶೆಲ್ನಿಂದ IDE ಅನ್ನು ಪ್ರಾರಂಭಿಸಿ.** ಡೆಸ್ಕ್ಟಾಪ್ ಐಕಾನ್ / Dock / Start ಮೆನುವಿನಿಂದ ಅದನ್ನು ಪ್ರಾರಂಭಿಸಿದರೆ
   ಶೆಲ್ ಎಕ್ಸ್ಪೋರ್ಟ್ಗಳು ಆನುವಂಶಿಕವಾಗಿ ದೊರೆಯುವುದಿಲ್ಲ ಮತ್ತು ಹೊಸ ಗ್ರಾಫಿಕಲ್ ಲಾಗಿನ್ ನಂತರವೇ `~/.config/environment.d/*.conf`
   ಅನ್ವಯಿಸುತ್ತದೆ. ಮೊದಲು IDEಯಿಂದ ಸಂಪೂರ್ಣವಾಗಿ ನಿರ್ಗಮಿಸಿ — Electronನ ಸಿಂಗಲ್ಟನ್ ಲಾಕ್ನಿಂದಾಗಿ ಎರಡನೇ
   ಪ್ರಾರಂಭವು ಈಗಿರುವ ಪ್ರಕ್ರಿಯೆಯನ್ನೇ ಫೋಕಸ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ಹೊಸ ಪರಿಸರವನ್ನು ನಿರ್ಲಕ್ಷಿಸಲಾಗುತ್ತದೆ.

ಮೇಲಿನ OS-ವಿಶ್ವಾಸ + NSS ಹಂತವು ಇನ್ನೂ ಅಗತ್ಯವಾಗಿದೆ (ಕೆಲವು ದೃಢೀಕರಣ ಹರಿವುಗಳು ಬಳಸುವ Chromium ನೆಟ್ವರ್ಕ್ ಸ್ಟ್ಯಾಕ್
ಪ್ರತಿ-ಬಳಕೆದಾರ NSS ಸಂಗ್ರಹವನ್ನು ಓದುತ್ತದೆ ಮತ್ತು `*.googleapis.com` ಗಾಗಿ ತನ್ನದೇ ಸ್ಥಿರ ಪಿನ್ಗಳನ್ನು ಹೊಂದಿದ್ದು, ಅವುಗಳನ್ನು
ಸ್ಥಳೀಯವಾಗಿ ವಿಶ್ವಾಸಾರ್ಹವಾಗಿಸಿದ CA ಅತಿಕ್ರಮಿಸುತ್ತದೆ). ಇದರ ಜೊತೆಗೆ Node `fetch` ಮಾರ್ಗವನ್ನು `NODE_EXTRA_CA_CERTS` ಒಳಗೊಳ್ಳುತ್ತದೆ.

### 3.3 DNS ರೂಟಿಂಗ್

ನೀವು ಪ್ರತಿಬಂಧಿಸಲು ಬಯಸುವ ಪ್ರತಿ ಏಜೆಂಟ್ಗಾಗಿ, ಅದರ API ಹೋಸ್ಟ್(ಗಳು) `127.0.0.1` ಗೆ ರಿಸಾಲ್ವ್ ಆಗಬೇಕು. ಸೆಟಪ್ ವಿಜರ್ಡ್ನಲ್ಲಿ ಏಜೆಂಟ್ಗಾಗಿ DNS ಅನ್ನು ಟಾಗಲ್ ಮಾಡಿದಾಗ AgentBridge `/etc/hosts` ನಮೂದುಗಳನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ನಿರ್ವಹಿಸುತ್ತದೆ.

GitHub Copilot ಗಾಗಿನ `/etc/hosts` ನಮೂದುಗಳ ಉದಾಹರಣೆ:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 ಮಾದರಿ ಮ್ಯಾಪಿಂಗ್

ಮೂಲ → ಗುರಿ ಮ್ಯಾಪಿಂಗ್ಗಳನ್ನು ವ್ಯಾಖ್ಯಾನಿಸಲು ಪ್ರತಿ ಏಜೆಂಟ್ ಕಾರ್ಡ್ನಲ್ಲಿರುವ ಮಾದರಿ ಮ್ಯಾಪಿಂಗ್ ಕೋಷ್ಟಕವನ್ನು ಬಳಸಿ:

| ಮೂಲ ಮಾದರಿ (ಏಜೆಂಟ್ನ ಸ್ಥಳೀಯ) | ಗುರಿ ಮಾದರಿ (OmniRoute) |
| -------------------------- | ---------------------- |
| `gpt-4o`                   | `claude-sonnet-4.7`    |
| `*` (ವೈಲ್ಡ್ಕಾರ್ಡ್)         | `claude-haiku-4.7`     |

ವೈಲ್ಡ್ಕಾರ್ಡ್ `*` ಗುರುತಿಸಲಾಗದ ಯಾವುದೇ ಮಾದರಿಯನ್ನು ನಿರ್ದಿಷ್ಟಪಡಿಸಿದ ಗುರಿಗೆ ಮ್ಯಾಪ್ ಮಾಡುತ್ತದೆ. ಇದನ್ನು `agent_bridge_mappings` ಕೋಷ್ಟಕದಲ್ಲಿ ಉಳಿಸಲಾಗುತ್ತದೆ.

> **ಸಲಹೆ — ಏಜೆಂಟ್ನ ನಿಜವಾದ ಮಾದರಿ IDಗಳನ್ನು ಕಂಡುಹಿಡಿಯಿರಿ.** IDE ತನ್ನ UI ಲೇಬಲ್ಗಳಿಗಿಂತ ಭಿನ್ನವಾಗಿರುವ ಮತ್ತು
> ಪ್ರಮುಖ ಆವೃತ್ತಿಗಳ ನಡುವೆ ಬದಲಾಗುವ ಮಾದರಿ ಹೆಸರುಗಳನ್ನು ಕಳುಹಿಸಬಹುದು. ಉದಾಹರಣೆಗೆ **Antigravity 2** ವೈರ್ ಮೂಲಕ
> `gemini-3.1-pro-low`, `gemini-pro-agent`, ಮತ್ತು `gemini-3.1-flash-lite` ಅನ್ನು ಕಳುಹಿಸುತ್ತದೆ — ಹಳೆಯ
> ದಸ್ತಾವೇಜುಗಳಲ್ಲಿ ತೋರಿಸಿರುವ `gemini-2.5-pro` ಅನ್ನು ಅಲ್ಲ. ಹೊಂದಾಣಿಕೆಯಾಗುವ ಯಾವುದೇ ಮ್ಯಾಪಿಂಗ್ ಇಲ್ಲದೆ ಒಂದು ಚಾಟ್ ಕಳುಹಿಸಿ: MITM
> ಒಳಬರುವ ನಿಖರವಾದ `model:` ಅನ್ನು ಲಾಗ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ವಿನಂತಿಯನ್ನು ಮುಂದಕ್ಕೆ ಕಳುಹಿಸುತ್ತದೆ. ಆ ಅಕ್ಷರಶಃ ಮೌಲ್ಯವನ್ನು ಮ್ಯಾಪ್ ಮಾಡಿ, ನಂತರ
> ಮುಂದಿನ ವಿನಂತಿಯನ್ನು ಪ್ರತಿಬಂಧಿಸಿ ನಿಮ್ಮ ಗುರಿಗೆ ರೂಟ್ ಮಾಡಲಾಗುತ್ತದೆ.

### 3.5 ಅಪಾಯದ ಸೂಚನೆ

ಅಪ್ಸ್ಟ್ರೀಮ್ ಪೂರೈಕೆದಾರರೊಂದಿಗೆ ದೃಢೀಕರಿಸಲು IDE ಬಳಸುವ ರುಜುವಾತುಗಳನ್ನು (OAuth ಟೋಕನ್ಗಳು, API ಕೀಲಿಗಳು) AgentBridge ಪ್ರತಿಬಂಧಿಸುತ್ತದೆ. ಇವುಗಳನ್ನು **ಲಾಗ್ ಮಾಡುವ ಮೊದಲು ಮರೆಮಾಡಲಾಗುತ್ತದೆ** (§2.7 ನೋಡಿ), ಆದರೆ OmniRouteನ MITM ಪದರಕ್ಕೆ ಗೋಚರಿಸುತ್ತವೆ. ಪ್ರತಿ ಏಜೆಂಟ್ನ ಮೊದಲ ಸಕ್ರಿಯಗೊಳಿಸುವಿಕೆಯು ಮುಚ್ಚಬಹುದಾದ ಅಪಾಯದ ಸೂಚನೆಯ ಮೋಡಲ್ ಅನ್ನು ತೋರಿಸುತ್ತದೆ.

### 3.6 ನಿರ್ವಹಣೆ & ರೋಗನಿರ್ಣಯ

ಈ ಹಿಂದೆ UI ಹೊಂದಿರದ ಕಾರ್ಯಾಚರಣಾ MITM ಮಾರ್ಗಗಳನ್ನು ಪ್ರದರ್ಶಿಸುವ **ನಿರ್ವಹಣೆ & ರೋಗನಿರ್ಣಯ** ಕಾರ್ಡ್ ಅನ್ನು (`AgentBridgeMaintenanceCard`, `src/app/(dashboard)/dashboard/tools/agent-bridge/components/` ನಲ್ಲಿ) ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಒದಗಿಸುತ್ತದೆ. ಅದರ ಉಪಶೀರ್ಷಿಕೆ: _"ಕ್ಯಾಪ್ಚರ್ ಪೈಪ್ಲೈನ್ ಅನ್ನು ಸ್ವಯಂ-ಪರೀಕ್ಷಿಸಿ, ಉಳಿದಿರುವ ಸಿಸ್ಟಮ್ ಸ್ಥಿತಿಯನ್ನು ರದ್ದುಗೊಳಿಸಿ ಮತ್ತು ನಿಮ್ಮ ಸೆಟಪ್ ಅನ್ನು ಯಂತ್ರಗಳ ನಡುವೆ ಸ್ಥಳಾಂತರಿಸಿ."_ ಕಾರ್ಡ್ ಕ್ಲೈಂಟ್ ಸಹಾಯಕಗಳು `src/lib/inspector/agentBridgeMaintenanceApi.ts` ನಲ್ಲಿವೆ.

| ಬಟನ್                   | ರೂಟ್                                   | ಇದು ಏನು ಮಾಡುತ್ತದೆ                                                                                                                                                                                                  |
| ---------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

**ರೋಗನಿರ್ಣಯ ಪರಿಶೀಲನೆಗಳು** (`src/mitm/inspector/diagnostics.ts`ನಲ್ಲಿರುವ `summarizeDiagnostics()`). ರೂಟ್ ಪ್ರತಿಯೊಂದಕ್ಕೂ ಪರಿಣಾಮವುಳ್ಳ ಪ್ರೋಬ್ ಅನ್ನು ಚಲಾಯಿಸಿ, ಬೂಲಿಯನ್ ಮೌಲ್ಯಗಳನ್ನು ಪ್ಯೂರ್ ಸಾರಾಂಶಕಾರಕಕ್ಕೆ ಒದಗಿಸುತ್ತದೆ; ಒಂದೇ `healthy` ತೀರ್ಪಿನ ಜೊತೆಗೆ ಪ್ರತಿ ವೈಫಲ್ಯಕ್ಕೂ ಒಂದು ಸೂಚನೆಯನ್ನು ಹಿಂತಿರುಗಿಸಲಾಗುತ್ತದೆ:

| ಪರಿಶೀಲನೆ ಹೆಸರು     | ಇದು ಏನನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ                                             | ವೈಫಲ್ಯದ ಸಂದರ್ಭದ ಸೂಚನೆ                                                                                                                                                      |
| ------------------ | --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server-running`   | MITM ಸರ್ವರ್ ಪ್ರಕ್ರಿಯೆಯು ಸಕ್ರಿಯವಾಗಿದೆ                                  | "MITM ಸರ್ವರ್ ಚಾಲನೆಯಲ್ಲಿಲ್ಲ. ಅದನ್ನು AgentBridge ಟ್ಯಾಬ್ನಿಂದ ಪ್ರಾರಂಭಿಸಿ."                                                                                                     |
| `server-reachable` | MITM ಸರ್ವರ್ ತನ್ನ ಪೋರ್ಟ್ನಲ್ಲಿ ಸಂಪರ್ಕಗಳನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ (TCP ಪ್ರೋಬ್) | "MITM ಸರ್ವರ್ ತನ್ನ ಪೋರ್ಟ್ನಲ್ಲಿ ಸಂಪರ್ಕಗಳನ್ನು ಸ್ವೀಕರಿಸುತ್ತಿಲ್ಲ. ಪೋರ್ಟ್ ಮುಕ್ತವಾಗಿದೆಯೇ ಮತ್ತು ಅದಕ್ಕೆ ಬೈಂಡ್ ಮಾಡಲು ನಿಮಗೆ ಸವಲತ್ತುಗಳಿವೆಯೇ ಎಂಬುದನ್ನು ಪರಿಶೀಲಿಸಿ."                      |
| `cert-exists`      | MITM ಪ್ರಮಾಣಪತ್ರವನ್ನು ಡಿಸ್ಕ್ನಲ್ಲಿ ರಚಿಸಲಾಗಿದೆ                           | "ಇನ್ನೂ ಯಾವುದೇ MITM ಪ್ರಮಾಣಪತ್ರವನ್ನು ರಚಿಸಲಾಗಿಲ್ಲ. AgentBridge ಟ್ಯಾಬ್ನಿಂದ ಒಂದನ್ನು ರಚಿಸಿ."                                                                                     |

| `dns-configured`   | ಗುರಿ ಹೋಸ್ಟ್ಹೆಸರುಗಳನ್ನು `/etc/hosts`ನಲ್ಲಿ ಸ್ಪೂಫ್ ಮಾಡಲಾಗಿದೆ             | "ಗುರಿ ಹೋಸ್ಟ್ಹೆಸರುಗಳನ್ನು /etc/hostsನಲ್ಲಿ ಸ್ಪೂಫ್ ಮಾಡಿಲ್ಲ, ಆದ್ದರಿಂದ ಟ್ರಾಫಿಕ್ ಎಂದಿಗೂ ಪ್ರಾಕ್ಸಿಯನ್ನು ತಲುಪುವುದಿಲ್ಲ. ನೀವು ಕ್ಯಾಪ್ಚರ್ ಮಾಡಲು ಬಯಸುವ ಏಜೆಂಟ್(ಗಳು)ಗಾಗಿ DNS ಸಕ್ರಿಯಗೊಳಿಸಿ." |

**ಅನಾಥ-ಸ್ಥಿತಿ ಬ್ಯಾನರ್:** ಕ್ರ್ಯಾಶ್ನಿಂದ ಉಳಿದ ಸ್ಥಿತಿಯನ್ನು (DNS ಸ್ಪೂಫ್ / CA / ಸಿಸ್ಟಮ್ ಪ್ರಾಕ್ಸಿ) ಪುಟ ಪತ್ತೆಹಚ್ಚಿದಾಗ, ಕಾರ್ಡ್ ಅಂಬರ್ ಬಣ್ಣದ ಬ್ಯಾನರ್ ಅನ್ನು ತೋರಿಸುತ್ತದೆ — _"ಹಿಂದಿನ ಸೆಷನ್ ಸಿಸ್ಟಮ್ ಸ್ಥಿತಿಯನ್ನು ಉಳಿಸಿದೆ (DNS ಸ್ಪೂಫ್, CA ಅಥವಾ ಸಿಸ್ಟಮ್ ಪ್ರಾಕ್ಸಿ). ಅದನ್ನು ಸ್ವಚ್ಛಗೊಳಿಸಲು ದುರಸ್ತಿಯನ್ನು ಚಲಾಯಿಸಿ."_ — ಮತ್ತು **ದುರಸ್ತಿ** ಬಟನ್ ಅನ್ನು ಹೈಲೈಟ್ ಮಾಡುತ್ತದೆ. `Repair` ಎಂಬುದು ProxyBridgeನ `--cleanup` ಫ್ಲ್ಯಾಗ್ನ ಅಪ್ಲಿಕೇಶನ್-ಲೇಯರ್ ಸಮಾನರೂಪವಾಗಿದೆ (ಇದು `src/mitm/manager.ts`ನಲ್ಲಿರುವ `repairMitm()`ಗೆ ಕಾರ್ಯವನ್ನು ನಿಯೋಜಿಸುತ್ತದೆ).

> ಪುನರಾವರ್ತಿತ sudo ಪ್ರಾಂಪ್ಟ್ಗಳನ್ನು ತಪ್ಪಿಸಲು MITM ರೂಟ್ CA ಅನ್ನು ನಿಲ್ಲಿಸುವಿಕೆ/ಪ್ರಾರಂಭಿಸುವಿಕೆಯಾದ್ಯಂತ ಸ್ಥಾಪಿತವಾಗಿಯೇ
> ಇರಿಸಲಾಗುತ್ತದೆ (mitmproxy/Charlesನಂತೆಯೇ ಅದೇ ವರ್ತನೆ), ಆದ್ದರಿಂದ ಅದನ್ನು ತೆಗೆದುಹಾಕುವುದು ನಿಲ್ಲಿಸಿದಾಗ ಸ್ವಯಂಚಾಲಿತವಾಗಿ
> ಸಂಭವಿಸುವ ಕ್ರಿಯೆಯ ಬದಲು ಸ್ಪಷ್ಟವಾದ **CA ತೆಗೆದುಹಾಕಿ** ಕ್ರಿಯೆಯಾಗಿದೆ.

### 3.7 ಪೋರ್ಟಬಲ್ ಕಾನ್ಫಿಗ್ ಆಮದು/ರಫ್ತು

ಸೆಟಪ್ ಅನ್ನು ಯಂತ್ರಗಳಾದ್ಯಂತ ಪುನರಾವರ್ತಿಸಲು ಸಾಧ್ಯವಾಗುವಂತೆ AgentBridge **ಆಪರೇಟರ್-ಹೊಂದಿಸಬಹುದಾದ** ಸ್ಥಿತಿಯನ್ನು ಆವೃತ್ತಿಗೊಳಿಸಿದ JSON ಬ್ಲಾಬ್ ಆಗಿ ಸೀರಿಯಲೈಸ್ ಮಾಡಬಹುದು. ಸೀರಿಯಲೈಜರ್ `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`), ಇದನ್ನು `AgentBridgeConfigSchema` ಮೌಲ್ಯೀಕರಿಸುತ್ತದೆ.

ರಫ್ತು ನಿಖರವಾಗಿ ಮೂರು ಭಾಗಗಳನ್ನು ಒಳಗೊಂಡಿರುತ್ತದೆ (ಅಂತರ್ನಿರ್ಮಿತ ಡಿಫಾಲ್ಟ್ಗಳನ್ನು ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ರಫ್ತು **ಮಾಡಲಾಗುವುದಿಲ್ಲ**, ಆದ್ದರಿಂದ ಆಮದು ಮಾಡುವಿಕೆಯು ಎಂದಿಗೂ ಅವುಗಳನ್ನು ನಕಲಿಸುವುದಿಲ್ಲ ಅಥವಾ ಅವುಗಳೊಂದಿಗೆ ಸಂಘರ್ಷಿಸುವುದಿಲ್ಲ):

| ಫೀಲ್ಡ್           | ಮೂಲ                                                             | ಟಿಪ್ಪಣಿಗಳು                                                                           |
| ---------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `bypassPatterns` | ಬಳಕೆದಾರ-ವ್ಯಾಖ್ಯಾನಿತ ಬೈಪಾಸ್ ಪ್ಯಾಟರ್ನ್ಗಳು (`agent_bridge_bypass`) | ಡಿಫಾಲ್ಟ್ bank/gov/okta ಪ್ಯಾಟರ್ನ್ಗಳನ್ನು ಹೊರಗಿಡಲಾಗಿದೆ                                  |
| `customHosts`    | Traffic Inspector ಕಸ್ಟಮ್ ಹೋಸ್ಟ್ಗಳು (`inspector_custom_hosts`)   | ಪ್ರತಿಯೊಂದು: `{ host, kind: "llm"\|"app"\|"custom", label? }`                         |
| `agentMappings`  | ಪ್ರತಿ-ಏಜೆಂಟ್ ಮಾಡೆಲ್ ಮ್ಯಾಪಿಂಗ್ಗಳು (`agent_bridge_mappings`)      | ಮ್ಯಾಪಿಂಗ್ಗಳನ್ನು ಹೊಂದಿರುವ ಪ್ರತಿಯೊಂದು ಏಜೆಂಟ್ಗಾಗಿ `{ [agentId]: [{ source, target }] }` |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**ಆಮದು ವರ್ತನೆ** (`POST /api/tools/agent-bridge/config`): ಬೈಪಾಸ್ ಪ್ಯಾಟರ್ನ್ಗಳು ಮತ್ತು ಪ್ರತಿ-ಏಜೆಂಟ್ ಮ್ಯಾಪಿಂಗ್ಗಳು **ಸಂಪೂರ್ಣವಾಗಿ ಬದಲಾಗುತ್ತವೆ**; ಕಸ್ಟಮ್ ಹೋಸ್ಟ್ಗಳನ್ನು **ಐಡೆಂಪೊಟೆಂಟ್ ಆಗಿ** ಸೇರಿಸಲಾಗುತ್ತದೆ (`INSERT OR IGNORE`). ಪ್ರತಿಯೊಂದರಲ್ಲಿ ಎಷ್ಟನ್ನು ಅನ್ವಯಿಸಲಾಗಿದೆ ಎಂಬುದನ್ನು ಪ್ರತಿಕ್ರಿಯೆಯು ವರದಿ ಮಾಡುತ್ತದೆ:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

ಕಾನ್ಫಿಗ್ನಲ್ಲಿ **ಇಲ್ಲದಿರುವುದು**: ಸರ್ವರ್ ಚಾಲನೆಯ ಸ್ಥಿತಿ, ಪ್ರಮಾಣಪತ್ರದ ಪಥಗಳು, ಪ್ರತಿ-ಏಜೆಂಟ್ DNS ಸ್ಥಿತಿ, ಅಪ್ಸ್ಟ್ರೀಮ್ CA ಪಥ ಮತ್ತು TPROXY ಸೆಟ್ಟಿಂಗ್ಗಳು — ಅವು ಹೋಸ್ಟ್/ರನ್ಟೈಮ್ ಸ್ಥಿತಿಯಾಗಿವೆ, ಪೋರ್ಟಬಲ್ ಆದ್ಯತೆಗಳಲ್ಲ.

### ಸೆಟಪ್ ವಿಝಾರ್ಡ್ ಹಂತಗಳು (ಪ್ರತಿ ಏಜೆಂಟ್ಗೆ)

ಪ್ರತಿಯೊಂದು ಏಜೆಂಟ್ ಕಾರ್ಡ್ 3-ಹಂತದ ಸೆಟಪ್ ವಿಝಾರ್ಡ್ ಅನ್ನು ಹೊಂದಿದೆ:

1. **ಪೂರ್ವಾಪೇಕ್ಷೆಗಳನ್ನು ಪರಿಶೀಲಿಸಿ** — ಸರ್ವರ್ ಚಾಲನೆಯಲ್ಲಿದೆಯೇ? ಪ್ರಮಾಣಪತ್ರ ವಿಶ್ವಾಸಾರ್ಹವಾಗಿದೆಯೇ? IDE ಸ್ಥಾಪಿಸಲಾಗಿದೆಯೇ (ಸ್ವಯಂ-ಪತ್ತೆ)?
2. **DNS ಸಕ್ರಿಯಗೊಳಿಸಿ** — `/etc/hosts` ನಮೂದುಗಳನ್ನು ಸೇರಿಸುತ್ತದೆ (sudo ಅಗತ್ಯವಿದೆ). ನಿಖರವಾಗಿ ಯಾವ ಸಾಲುಗಳನ್ನು ಸೇರಿಸಲಾಗುತ್ತದೆ ಎಂಬುದನ್ನು ತೋರಿಸುತ್ತದೆ.
3. **ಮಾದರಿಗಳನ್ನು ಮ್ಯಾಪ್ ಮಾಡಿ** — ಐಚ್ಛಿಕ ಮಾದರಿ ಮ್ಯಾಪಿಂಗ್ ಕೋಷ್ಟಕ. ವೈಲ್ಡ್ಕಾರ್ಡ್ಗಳನ್ನು ಸ್ವೀಕರಿಸಲಾಗುತ್ತದೆ.

### ಏಜೆಂಟ್ ಪತ್ತೆ

ಏಜೆಂಟ್ಗಳು 1–8 ಗಾಗಿ, AgentBridge IDE ಸ್ಥಾಪನೆಯನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಪತ್ತೆಹಚ್ಚಲು ಪ್ರಯತ್ನಿಸುತ್ತದೆ:

```ts
export async function detectAgent(agentId: AgentId): Promise<DetectionResult>;
// ಹಿಂತಿರುಗಿಸುತ್ತದೆ: { installed: boolean, version?: string, path?: string }
```

ಪತ್ತೆಹಚ್ಚುವಿಕೆಯು OS-ನಿರ್ದಿಷ್ಟ ಮಾರ್ಗಗಳು ಮತ್ತು ಬೈನರಿ ಪರಿಶೀಲನೆಗಳನ್ನು ಬಳಸುತ್ತದೆ (ಉದಾ., Copilot ಗಾಗಿ `code --list-extensions | grep github.copilot`, Antigravity ಗಾಗಿ `~/.config/antigravity/`).

### ಸೂಕ್ಷ್ಮ ಹೋಸ್ಟ್ಗಳಿಗಾಗಿ ಬೈಪಾಸ್ ಪಟ್ಟಿ

ಬೈಪಾಸ್ ಪಟ್ಟಿಯು ಹಣಕಾಸು ಸಂಸ್ಥೆಗಳು, OAuth/SSO ಪೂರೈಕೆದಾರರು ಮತ್ತು ಇತರ ಸೂಕ್ಷ್ಮ ಹೋಸ್ಟ್ಗಳನ್ನು **ಎಂದಿಗೂ ಡೀಕ್ರಿಪ್ಟ್ ಮಾಡಲಾಗುವುದಿಲ್ಲ** ಎಂಬುದನ್ನು ಖಚಿತಪಡಿಸುತ್ತದೆ. ಅವುಗಳ TLS ಟ್ರಾಫಿಕ್ ಪಾರದರ್ಶಕ TCP ಟನಲ್ ಮೂಲಕ ಹಾದುಹೋಗುತ್ತದೆ — OmniRoute ಎಂದಿಗೂ ಪ್ಲೇನ್ಟೆಕ್ಸ್ಟ್ ಅನ್ನು ನೋಡುವುದಿಲ್ಲ.

ಡೀಫಾಲ್ಟ್ ಬೈಪಾಸ್ ಮಾದರಿಗಳು ಇವುಗಳನ್ನು ಒಳಗೊಂಡಿವೆ:

- `*.bank.*`, `*.gov.*` (ಹಣಕಾಸು/ಸರ್ಕಾರಿ)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/ಗುರುತು)
- `*.apple.com`, `*.icloud.com` (Apple ಸಿಸ್ಟಮ್ ಸೇವೆಗಳು)

ಬಳಕೆದಾರರು ಸೇರಿಸಿದ ಬೈಪಾಸ್ ಮಾದರಿಗಳನ್ನು `agent_bridge_bypass` ಕೋಷ್ಟಕದಲ್ಲಿ ಸಂಗ್ರಹಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಅವು ಎಲ್ಲಕ್ಕಿಂತ ಆದ್ಯತೆ ಪಡೆಯುತ್ತವೆ.

### ರಹಸ್ಯ ಮರೆಮಾಚುವಿಕೆ

`src/mitm/maskSecrets.ts` ನಲ್ಲಿರುವ `maskSecrets()` ಅನ್ನು ಅನ್ವಯಿಸಲಾಗುತ್ತದೆ:

- `TrafficBuffer.push()` ಗಿಂತ ಮೊದಲು ಪ್ರತಿ ವಿನಂತಿಯ ಬಾಡಿಗೆ
- ಲಾಗ್ ಮಾಡುವ ಅಥವಾ ಪ್ರಸಾರ ಮಾಡುವ ಮೊದಲು ಪ್ರತಿ ಹೆಡರ್ಗೆ

ಮಾದರಿಗಳು: `sk-`/`ak-`/`pk-` ಪೂರ್ವಪ್ರತ್ಯಯದ ಟೋಕನ್ಗಳು, `Bearer` ಟೋಕನ್ಗಳು ಮತ್ತು ≥40 ಅಕ್ಷರಗಳ ಸಾಮಾನ್ಯ ಟೋಕನ್ಗಳು.

### ಅಪ್ಸ್ಟ್ರೀಮ್ CA ಪ್ರಮಾಣಪತ್ರ

`AGENTBRIDGE_UPSTREAM_CA_CERT` ಹೊಂದಿಸಿದಾಗ, ಪ್ರಾರಂಭದ ವೇಳೆ ಫೈಲ್ ಅನ್ನು ಓದಲಾಗುತ್ತದೆ. ಮಾರ್ಗವು ಅಸ್ತಿತ್ವದಲ್ಲಿದ್ದರೂ ಫೈಲ್ ಅನ್ನು ಓದಲಾಗದಿದ್ದರೆ, AgentBridge ಸ್ಪಷ್ಟ ದೋಷವನ್ನು ಲಾಗ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ಪ್ರಾರಂಭಿಸಲು ನಿರಾಕರಿಸುತ್ತದೆ (ಕಾರ್ಪೊರೇಟ್ ಪರಿಸರಗಳಲ್ಲಿ ಮೌನ TLS ವೈಫಲ್ಯಗಳನ್ನು ತಡೆಯುತ್ತದೆ).

### ತಿಳಿದಿರುವ ಮಿತಿಗಳು

- **ಪೋರ್ಟ್ 443 ಗೆ ವಿಶೇಷಾಧಿಕಾರ ಅಗತ್ಯವಿದೆ**: Linux ನಲ್ಲಿ, AgentBridge ಗೆ Node ಬೈನರಿಯ ಮೇಲೆ `setcap 'cap_net_bind_service=+ep'` ಅಗತ್ಯವಿದೆ, ಅಥವಾ ಅದನ್ನು `authbind` ಮೂಲಕ ಚಲಾಯಿಸಬೇಕು. ಸೆಟಪ್ ವಿಝಾರ್ಡ್ OS-ನಿರ್ದಿಷ್ಟ ಸೂಚನೆಗಳನ್ನು ಪ್ರದರ್ಶಿಸುತ್ತದೆ.
- **IDE ಮರುಪ್ರಾರಂಭ ಅಗತ್ಯವಿದೆ**: DNS ಮರುನಿರ್ದೇಶನದ ನಂತರ, ಹೊಸ ಹೋಸ್ಟ್ ರೆಸಲ್ಯೂಷನ್ ಪರಿಣಾಮಕಾರಿಯಾಗಲು IDE ಅನ್ನು ಮರುಪ್ರಾರಂಭಿಸಬೇಕು.
- **ಹಾರ್ಡ್ಕೋಡ್ ಮಾಡಿದ OAuth ಟೋಕನ್ಗಳು**: ಕೆಲವು ಏಜೆಂಟ್ಗಳು (Kiro, Antigravity) OAuth ರಿಫ್ರೆಶ್ ಟೋಕನ್ಗಳನ್ನು ಸ್ಥಳೀಯವಾಗಿ ಸಂಗ್ರಹಿಸುತ್ತವೆ. ಇವು AgentBridge ಗೆ ಪಾರದರ್ಶಕವಾಗಿವೆ — ಇದು ಪ್ರತಿ ವಿನಂತಿಯಲ್ಲಿನ Bearer ಟೋಕನ್ ಅನ್ನು ನೋಡುತ್ತದೆ, ಲಾಗ್ ಮಾಡುವ ಮೊದಲು ಅದನ್ನು ಮರೆಮಾಚಲಾಗುತ್ತದೆ.
- **Electron ಫ್ರಂಟ್ಎಂಡ್ಗಳಿಗೆ `NODE_EXTRA_CA_CERTS` ಅಗತ್ಯವಿದೆ**: ಬಂಡಲ್ ಮಾಡಿದ Node/Electron ರನ್ಟೈಮ್ನಲ್ಲಿ ಫ್ರಂಟ್ಎಂಡ್ ಕಾರ್ಯನಿರ್ವಹಿಸುವ IDE ಗಳು OS/NSS ಟ್ರಸ್ಟ್ ಸ್ಟೋರ್ ಅನ್ನು ನಿರ್ಲಕ್ಷಿಸುತ್ತವೆ ಮತ್ತು `NODE_EXTRA_CA_CERTS` ಹೊಂದಿಸಲಾದ ಶೆಲ್ನಿಂದ ಅವುಗಳನ್ನು ಪ್ರಾರಂಭಿಸಬೇಕು (§3.2 ನೋಡಿ). ಇದು ಇಲ್ಲದಿರುವಾಗ ಕಾಣುವ ಲಕ್ಷಣ: IDE ಬ್ಯಾಕ್ಎಂಡ್ ದೃಢೀಕರಿಸುತ್ತದೆ (MITM `200` ಗಳನ್ನು ತೋರಿಸುತ್ತದೆ), ಆದರೆ UI ಲಾಗ್ ಔಟ್ ಆಗಿಯೇ ಉಳಿಯುತ್ತದೆ.
- **ಒಂದೇ IDE ಯ ಬಹು ಸ್ಥಾಪನೆಗಳು ಸ್ವತಂತ್ರವಾಗಿರುತ್ತವೆ**: ಸಿಸ್ಟಮ್ ಸ್ಥಾಪನೆ (ಉದಾ. `/usr/share/antigravity/antigravity`) ಮತ್ತು ಬಳಕೆದಾರ-ಸ್ಥಳೀಯ "Full" ಸ್ಥಾಪನೆ (ಉದಾ. `~/AntigravityIDE_Full/antigravity-ide`) ತಮ್ಮದೇ ರನ್ಟೈಮ್ಗಳನ್ನು ಹೊಂದಿರುವ ಪ್ರತ್ಯೇಕ ಪ್ರಕ್ರಿಯೆಗಳಾಗಿವೆ — ಪ್ರತಿಯೊಂದನ್ನೂ CA ಸೇರಿಸಿ ಮರುಪ್ರಾರಂಭಿಸಬೇಕು. ಮರುಪ್ರಾರಂಭಿಸುವ ಮೊದಲು ಅದರ ಬೈನರಿ ಮಾರ್ಗದ ಮೂಲಕ ಯಾವುದು ಚಾಲನೆಯಲ್ಲಿದೆ ಎಂಬುದನ್ನು ಗುರುತಿಸಿ.
- **ಗುರುತನ್ನು ರೂಟ್ ಮಾಡಿದ ಮಾದರಿಯಲ್ಲ, ಏಜೆಂಟ್ನ ಸಿಸ್ಟಮ್ ಪ್ರಾಂಪ್ಟ್ ನಿರ್ಧರಿಸುತ್ತದೆ**: ಏಜೆಂಟ್ನ ಮಾದರಿಯನ್ನು ಬೇರೆ ಪೂರೈಕೆದಾರರಿಗೆ ಮರುಮ್ಯಾಪ್ ಮಾಡಿದಾಗಲೂ, ಪ್ರತಿಕ್ರಿಯೆಯು ಏಜೆಂಟ್ನ ಮೂಲ ಗುರುತನ್ನೇ ಹೇಳಿಕೊಳ್ಳುತ್ತದೆ (ಉದಾ. Antigravity "ನಾನು Gemini ನಿಂದ ಚಾಲಿತನಾಗಿದ್ದೇನೆ" ಎಂದು ಉತ್ತರಿಸುತ್ತದೆ), ಏಕೆಂದರೆ IDE ಅದನ್ನು ಸಿಸ್ಟಮ್ ಪ್ರಾಂಪ್ಟ್ಗೆ ಸೇರಿಸುತ್ತದೆ. ನಿಜವಾದ ಬ್ಯಾಕ್ಎಂಡ್ ಅನ್ನು ಮಾದರಿಗೆ ಅದು ಯಾರು ಎಂದು ಕೇಳುವ ಮೂಲಕವಲ್ಲ, `call_logs` / `proxy_logs` (`provider`, `model`, `target_format`) ನಲ್ಲಿ ದೃಢೀಕರಿಸಿ.

## §6 ಸಮಸ್ಯೆ ಪರಿಹಾರ

### ಪೋರ್ಟ್ 443 ಸಂಘರ್ಷ

ಮತ್ತೊಂದು ಪ್ರಕ್ರಿಯೆಯು ಈಗಾಗಲೇ ಪೋರ್ಟ್ 443ರಲ್ಲಿ ಆಲಿಸುತ್ತಿದ್ದರೆ (ವೆಬ್ ಸರ್ವರ್, VPN, ಇತ್ಯಾದಿ):

```bash
lsof -i :443          # ಪ್ರಕ್ರಿಯೆಯನ್ನು ಪತ್ತೆಮಾಡಿ
sudo fuser -k 443/tcp  # ಬಲವಂತವಾಗಿ ಸ್ಥಗಿತಗೊಳಿಸಿ (ಎಚ್ಚರಿಕೆಯಿಂದ ಬಳಸಿ)
```

ಪರ್ಯಾಯವಾಗಿ, AgentBridge ಸೆಟ್ಟಿಂಗ್ಗಳಲ್ಲಿ ವಿಶೇಷಾಧಿಕಾರ ಅಗತ್ಯವಿಲ್ಲದ ಪೋರ್ಟ್ ಅನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡಿ ಮತ್ತು `iptables` / `pf` ಮರುನಿರ್ದೇಶನ ನಿಯಮಗಳನ್ನು ಹೊಂದಿಸಿ.

### ಪ್ರಮಾಣಪತ್ರ ವಿಶ್ವಾಸಾರ್ಹವಾಗಿಲ್ಲ

AgentBridge ಅನ್ನು ಪ್ರಾರಂಭಿಸಿದ ನಂತರ IDEಯು TLS ದೋಷಗಳನ್ನು ತೋರಿಸಿದರೆ:

1. ಪ್ರಮಾಣಪತ್ರವನ್ನು ಸ್ಥಾಪಿಸಲಾಗಿದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸಿ: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) ಅಥವಾ `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. ಕೆಲವು ಆ್ಯಪ್ಗಳು ತಮ್ಮದೇ ಆದ ವಿಶ್ವಾಸ ಸಂಗ್ರಹವನ್ನು ನಿರ್ವಹಿಸುತ್ತವೆ (Firefox, Linuxನಲ್ಲಿನ Chrome). "Trust Cert" ಅನ್ನು ಮತ್ತೆ ಚಲಾಯಿಸಿ ಮತ್ತು NSS/Firefox-ನಿರ್ದಿಷ್ಟ ಪ್ರಮಾಣಪತ್ರ ಸಂಗ್ರಹವನ್ನು ಪರಿಶೀಲಿಸಿ.
3. ವಿಶ್ವಾಸಾರ್ಹಗೊಳಿಸಿದ ನಂತರ IDEಯನ್ನು ಮರುಪ್ರಾರಂಭಿಸಿ — ಈಗಾಗಲೇ ಪ್ರಗತಿಯಲ್ಲಿರುವ TLS ಸೆಷನ್ಗಳು ಹಳೆಯ ವಿಶ್ವಾಸ ಸ್ಥಿತಿಯನ್ನು ಬಳಸುತ್ತವೆ.

### ವಿಶ್ವಾಸಾರ್ಹ CA ಇದ್ದರೂ IDEಯಿಂದ ಲಾಗ್ ಔಟ್ ಆಗಿದೆ / "connection error"

ಲಕ್ಷಣ: DNS ಅನ್ನು ಮರುನಿರ್ದೇಶಿಸಿ CA ಅನ್ನು ವಿಶ್ವಾಸಾರ್ಹಗೊಳಿಸಿದ ನಂತರ, Electron-ಆಧಾರಿತ IDE (ಉದಾ. Antigravity)
**ಲಾಗ್ ಔಟ್ ಆಗಿರುವ** ಸ್ಥಿತಿಯಲ್ಲಿ ತೆರೆಯುತ್ತದೆ ಅಥವಾ ದೃಢೀಕರಣ/ಸಂಪರ್ಕ ದೋಷವನ್ನು ತೋರಿಸುತ್ತದೆ; ಆದರೂ MITM ಲಾಗ್ನಲ್ಲಿ
ಬೂಟ್ಸ್ಟ್ರ್ಯಾಪ್ ಕರೆಗಳು (`loadCodeAssist`, `fetchAvailableModels`, …) `200` ಅನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತಿರುವುದು ಕಾಣಿಸುತ್ತದೆ.

ಕಾರಣ: IDEಯ **ಬಂಡಲ್ ಮಾಡಲಾದ Node/Electron ರನ್ಟೈಮ್ OS ವಿಶ್ವಾಸ ಸಂಗ್ರಹವನ್ನು ನಿರ್ಲಕ್ಷಿಸುತ್ತದೆ**. ಸ್ಥಳೀಯ
ಬ್ಯಾಕೆಂಡ್ (Go ಭಾಷಾ ಸರ್ವರ್) OS CA ಅನ್ನು ವಿಶ್ವಾಸಾರ್ಹವೆಂದು ಪರಿಗಣಿಸಿ ದೃಢೀಕರಿಸುತ್ತದೆ, ಆದರೆ Electron ಫ್ರಂಟ್ಎಂಡ್
ಹಾಗೆ ಮಾಡುವುದಿಲ್ಲ — ಆದ್ದರಿಂದ UI ತಾನು ಆಫ್ಲೈನ್ನಲ್ಲಿದೆ ಎಂದು ಭಾವಿಸುತ್ತದೆ.

ಪರಿಹಾರ (ಎರಡೂ ಹಂತಗಳು): `NODE_EXTRA_CA_CERTS=<ca.crt>` ಅನ್ನು ರಫ್ತು ಮಾಡಿ **ಮತ್ತು ಅದೇ
ಶೆಲ್ನಿಂದ IDEಯನ್ನು ಮರುಪ್ರಾರಂಭಿಸಿ**, ಡೆಸ್ಕ್ಟಾಪ್ ಐಕಾನ್ನಿಂದ ಅಲ್ಲ. ಮೊದಲು IDEಯನ್ನು ಸಂಪೂರ್ಣವಾಗಿ ಮುಚ್ಚಿ — Electronನ ಸಿಂಗಲ್ಟನ್ ಲಾಕ್ನಿಂದಾಗಿ
ಎರಡನೇ ಬಾರಿ ಪ್ರಾರಂಭಿಸುವುದು ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಪ್ರಕ್ರಿಯೆಯತ್ತ ಮಾತ್ರ ಗಮನ ಕೇಂದ್ರೀಕರಿಸುತ್ತದೆ ಮತ್ತು ಹೊಸ ಪರಿಸರವನ್ನು ನಿರ್ಲಕ್ಷಿಸಲಾಗುತ್ತದೆ. §3.2 ನೋಡಿ.
ಇದು ಸ್ವತಂತ್ರ ಏಜೆಂಟ್ ಒಂದು MITM ಮೂಲಕ ಕಾರ್ಯನಿರ್ವಹಿಸಿದರೂ, ಅದೇ ಸೆಟಪ್ನಲ್ಲಿ IDE
ಆವೃತ್ತಿಯು ವಿಫಲವಾಗುತ್ತದೆ ಎಂದು ತಿಳಿಸುವ ಮುಕ್ತ ಅಪ್ಸ್ಟ್ರೀಮ್ ವರದಿಗೆ ಹೊಂದಿಕೆಯಾಗುತ್ತದೆ.

### DNS ಪ್ರಸರಣಗೊಂಡಿಲ್ಲ

`/etc/hosts` ಅನ್ನು ನವೀಕರಿಸಲಾಗಿದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸಿ:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

DNS ಕ್ಯಾಶ್ ಅನ್ನು ತೆರವುಗೊಳಿಸಿ:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### IDE ಪತ್ತೆಯಾಗಿಲ್ಲ

ಸ್ವಯಂ-ಪತ್ತೆಹಚ್ಚುವಿಕೆಯು ಸಾಮಾನ್ಯ ಸ್ಥಾಪನಾ ಪಥಗಳನ್ನು ಬಳಸುತ್ತದೆ. ಪತ್ತೆಹಚ್ಚುವಿಕೆ ವಿಫಲವಾದರೂ IDE ಸ್ಥಾಪಿತವಾಗಿದ್ದರೆ:

- IDE ಬೈನರಿಯು ಪ್ರಮಾಣಿತವಲ್ಲದ ಸ್ಥಳದಲ್ಲಿದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸಿ
- ಸೆಟಪ್ ವಿಝಾರ್ಡ್ ಇನ್ನೂ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ — ಪತ್ತೆಹಚ್ಚುವಿಕೆಯ ವೈಫಲ್ಯವೆಂದರೆ ಬ್ಯಾಡ್ಜ್ನಲ್ಲಿ ಸ್ಥಾಪನಾ ಪಥವು ಕಾಣಿಸುವುದಿಲ್ಲ ಎಂದಷ್ಟೇ

### ಹ್ಯಾಂಡ್ಲರ್ ದೋಷಗಳು (ಅಪ್ಸ್ಟ್ರೀಮ್ ಪಡೆಯುವಿಕೆ ವಿಫಲವಾಗಿದೆ)

AgentBridge ವಿನಂತಿಗಳನ್ನು ಪ್ರತಿಬಂಧಿಸುತ್ತಿದ್ದರೂ ಎಲ್ಲಾ ವಿನಂತಿಗಳು ವಿಫಲವಾದರೆ:

1. `/dashboard/providers` ನಲ್ಲಿ ಕನಿಷ್ಠ ಒಬ್ಬ ಪೂರೈಕೆದಾರರು ಸಂಪರ್ಕಗೊಂಡಿದ್ದಾರೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸಿ
2. OmniRoute ಸರ್ವರ್ ಲಾಗ್ಗಳನ್ನು ಪರಿಶೀಲಿಸಿ: `.env` ನಲ್ಲಿ `APP_LOG_LEVEL=debug`
3. `OMNIROUTE_BASE_URL` ಸರಿಯಾದ ರೌಟರ್ ಎಂಡ್ಪಾಯಿಂಟ್ಗೆ ಸೂಚಿಸುತ್ತಿದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸಿ (ಡೀಫಾಲ್ಟ್: `http://127.0.0.1:20128`)

## §8 ಮಾರ್ಗಸೂಚಿ

### Trae ಪರಿಶೀಲನೆ

Trae ತುಲನಾತ್ಮಕವಾಗಿ ಹೊಸ AI ಕೋಡಿಂಗ್ ಸಹಾಯಕವಾಗಿದೆ. ಹ್ಯಾಂಡ್ಲರ್ ಅನ್ನು ಅನುಷ್ಠಾನಗೊಳಿಸುವ ಮೊದಲು:

1. VS Code / JetBrains ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ಗಳಲ್ಲಿ ಅಥವಾ ಸ್ವತಂತ್ರ ಆ್ಯಪ್ ಆಗಿ ಬೈನರಿ/ಎಕ್ಸ್ಟೆನ್ಶನ್ ಅನ್ನು ಗುರುತಿಸಿ
2. API ಹೋಸ್ಟ್ಗಳು ಮತ್ತು ಎಂಡ್ಪಾಯಿಂಟ್ ವಿನ್ಯಾಸಗಳನ್ನು ಕಂಡುಹಿಡಿಯಲು mitmproxy ಮೂಲಕ ಟ್ರಾಫಿಕ್ ಅನ್ನು ಸೆರೆಹಿಡಿಯಿರಿ
3. ದೃಢೀಕರಣ ಕಾರ್ಯವಿಧಾನವನ್ನು ನಿರ್ಧರಿಸಿ
4. TOS ಮತ್ತು API ಅನ್ವೇಷಣೀಯತೆಯ ಆಧಾರದ ಮೇಲೆ ಮುಂದುವರಿಯಬೇಕೇ/ಬೇಡವೇ ಎಂಬುದನ್ನು ಮೌಲ್ಯಮಾಪನ ಮಾಡಿ

ಪರಿಶೀಲನೆ ಪೂರ್ಣಗೊಳ್ಳುವವರೆಗೆ, ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿರುವ Trae ಕಾರ್ಡ್ "ಕಾರ್ಯಸಾಧ್ಯತೆಯನ್ನು ವರದಿ ಮಾಡಿ" ಲಿಂಕ್ನೊಂದಿಗೆ "ಪರಿಶೀಲಿಸಲಾಗುತ್ತಿದೆ" ಬ್ಯಾಡ್ಜ್ ಅನ್ನು ತೋರಿಸುತ್ತದೆ. `src/mitm/handlers/trae.ts` ನಲ್ಲಿರುವ ಹ್ಯಾಂಡ್ಲರ್ ಸ್ಟಬ್ ರಚನಾತ್ಮಕ `ಇನ್ನೂ ಅನುಷ್ಠಾನಗೊಳಿಸಲಾಗಿಲ್ಲ` ದೋಷವನ್ನು ಎಸೆಯುತ್ತದೆ.

### ಬಾಕಿ ಇರುವ ಏಜೆಂಟ್ಗಳು (MITM ಅಗತ್ಯ — ಕಸ್ಟಮ್ ಬೇಸ್ URL ಬೆಂಬಲವಿಲ್ಲ)

ಕೆಳಗಿನ ಪರಿಕರಗಳು ತಮ್ಮ ಪ್ರಸ್ತುತ ಆವೃತ್ತಿಗಳಲ್ಲಿ ಕಸ್ಟಮ್ ಬೇಸ್ URLಗಳನ್ನು ಬೆಂಬಲಿಸುವುದಿಲ್ಲ, ಆದ್ದರಿಂದ MITM ಮಾತ್ರವೇ ಇಂಟರ್ಸೆಪ್ಷನ್ ಮಾರ್ಗವಾಗಿದೆ. ಕಾರ್ಯಸಾಧ್ಯತೆಯ ಮೌಲ್ಯಮಾಪನ ಬಾಕಿ ಇದೆ:

- **Windsurf** (Codeium/Cognition)
- **Amp** (Sourcegraph)
- **Amazon Q / Kiro CLI** (AWS Bedrock — Kiro IDE ಯಿಂದ ಪ್ರತ್ಯೇಕ)
- **Cowork** (Anthropic ಡೆಸ್ಕ್ಟಾಪ್)

ಸೂಚನೆ: GitHub Copilot CLI ≥v1.0.19 `COPILOT_PROVIDER_BASE_URL` ಅನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ — ಆ ಪರಿಕರಕ್ಕೆ MITM ಬದಲಿಗೆ ನೇರ ಕಾನ್ಫಿಗರೇಶನ್ ಬಳಸಿ.
