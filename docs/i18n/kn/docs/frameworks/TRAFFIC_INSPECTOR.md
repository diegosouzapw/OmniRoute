Traffic Inspector ಎಂಬುದು OmniRouteನ ಅಂತರ್ನಿರ್ಮಿತ HTTPS ಟ್ರಾಫಿಕ್ ಡೀಬಗ್ಗರ್ ಆಗಿದೆ — ಇದು Charles Proxy / mitmweb / HTTP Toolkitನಂತಹ ಸಾಧನವಾಗಿದ್ದು, **LLM-aware** ಮತ್ತು **agent-aware** ಆಗಿದೆ. ಇದು `/dashboard/tools/traffic-inspector` ನಲ್ಲಿ ಲಭ್ಯವಿದ್ದು, ಏಕಕಾಲದಲ್ಲಿ ಗರಿಷ್ಠ 5 ಕ್ಯಾಪ್ಚರ್ ಮೂಲಗಳಿಂದ ಲೈವ್ ಟ್ರಾಫಿಕ್ ಸ್ವೀಕರಿಸುತ್ತದೆ.

**ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಸ್ಥಳ:** `/dashboard/tools/traffic-inspector`
**ಸೈಡ್ಬಾರ್ ಗುಂಪು:** ಪರಿಕರಗಳು (AgentBridge ನಂತರ)
**ಇದನ್ನೂ ನೋಡಿ:** [`AGENTBRIDGE.md`](./AGENTBRIDGE.md) — AgentBridge ಎಂಬುದು ಕ್ಯಾಪ್ಚರ್ ಮೋಡ್ 1 ಆಗಿದೆ.

### ಒಂದು ಪ್ಯಾರಾಗ್ರಾಫ್ನಲ್ಲಿ ಆರ್ಕಿಟೆಕ್ಚರ್

`TrafficBuffer` (`src/mitm/inspector/buffer.ts`) ಎಂಬುದು ಹಂಚಿಕೊಳ್ಳಲಾದ ಇನ್-ಮೆಮೊರಿ ರಿಂಗ್ ಬಫರ್ ಆಗಿದೆ (ಡೀಫಾಲ್ಟ್ ಆಗಿ 1000 ನಮೂದುಗಳು, `INSPECTOR_BUFFER_SIZE` ಮೂಲಕ ಕಾನ್ಫಿಗರ್ ಮಾಡಬಹುದು). ಎಲ್ಲಾ ಕ್ಯಾಪ್ಚರ್ ಮೂಲಗಳು `push()` ಮೂಲಕ ಇದಕ್ಕೆ ಬರೆಯುತ್ತವೆ. ಬಫರ್ ಪ್ರತಿಯೊಂದು ನಮೂದನ್ನೂ `kindDetector.ts` ಬಳಸಿ ವರ್ಗೀಕರಿಸುತ್ತದೆ (ಅದು LLM ವಿನಂತಿಯೇ ಎಂಬುದನ್ನು ನಿರ್ಧರಿಸುತ್ತದೆ), `contextKey` ಅನ್ನು ಲೆಕ್ಕಿಸುತ್ತದೆ (ಸಿಸ್ಟಮ್ ಪ್ರಾಂಪ್ಟ್ನ SHA-256 ಫಿಂಗರ್ಪ್ರಿಂಟ್), ಮತ್ತು `globalTrafficBuffer.subscribe()` ಮೂಲಕ ಎಲ್ಲಾ WebSocket ಚಂದಾದಾರರಿಗೆ ಪ್ರಸಾರ ಮಾಡುತ್ತದೆ. ಡ್ಯಾಶ್ಬೋರ್ಡ್ `GET /api/tools/traffic-inspector/ws` ಮೂಲಕ ಸಂಪರ್ಕಿಸುತ್ತದೆ ಮತ್ತು ಸಂಪರ್ಕಗೊಂಡಾಗ ಒಂದು ಸ್ನ್ಯಾಪ್ಶಾಟ್ ಅನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ; ಅದರ ನಂತರ `new`/`update`/`clear` ಈವೆಂಟ್ಗಳನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ.

## §2 ಕ್ಯಾಪ್ಚರ್ ಮೋಡ್ಗಳು

Traffic Inspector **5 ಏಕಕಾಲಿಕ ಕ್ಯಾಪ್ಚರ್ ಮೂಲಗಳನ್ನು** ಬೆಂಬಲಿಸುತ್ತದೆ. ಪ್ರತಿಯೊಂದನ್ನೂ ಸ್ವತಂತ್ರವಾಗಿ ಆನ್ ಅಥವಾ ಆಫ್ ಮಾಡಬಹುದು. ಪ್ರತಿ `InterceptedRequest` (`src/mitm/inspector/types.ts`) ನಲ್ಲಿರುವ `source` ಕ್ಷೇತ್ರವು `"agent-bridge"`, `"custom-host"`, `"http-proxy"`, `"system-proxy"`, ಅಥವಾ `"tproxy"` ಇವುಗಳಲ್ಲಿ ಒಂದಾಗಿರುತ್ತದೆ.

### ಮೋಡ್ 1 — AgentBridge (ಡೀಫಾಲ್ಟ್, ಯಾವಾಗಲೂ ಆನ್)

**ಮೂಲ:** AgentBridge ಹ್ಯಾಂಡ್ಲರ್ಗಳು (`src/mitm/handlers/base.ts`)
**ಕಾರ್ಯವಿಧಾನ:** `MitmHandlerBase` ನಲ್ಲಿರುವ ಪ್ರತಿ `intercept()` ಕರೆ ಫಾರ್ವರ್ಡ್ ಮಾಡುವ ಮೊದಲು `hookBufferStart()` ಅನ್ನು ಮತ್ತು ಪೂರ್ಣಗೊಂಡಾಗ `hookBufferUpdate()` ಅನ್ನು ಕರೆಯುತ್ತದೆ. ಯಾವುದೇ ಹೆಚ್ಚುವರಿ ಕಾನ್ಫಿಗರೇಶನ್ ಅಗತ್ಯವಿಲ್ಲ — AgentBridge ಚಾಲನೆಯಾದ ತಕ್ಷಣವೇ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ.
**ವ್ಯಾಪ್ತಿ:** AgentBridge ನಲ್ಲಿ ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾದ 9 IDE ಏಜೆಂಟ್ಗಳು
**ಟಿಪ್ಪಣಿ:** `InterceptedRequest` ನಲ್ಲಿನ `source` ಕ್ಷೇತ್ರ = `"agent-bridge"`

### ಮೋಡ್ 2 — ಕಸ್ಟಮ್ ಹೋಸ್ಟ್ಗಳು (DNS ಮರುನಿರ್ದೇಶನ)

**ಮೂಲ:** ಬಳಕೆದಾರರು ವ್ಯಾಖ್ಯಾನಿಸಿದ ಹೋಸ್ಟ್ ಪಟ್ಟಿ (`inspector_custom_hosts` ಟೇಬಲ್)
**ಕಾರ್ಯವಿಧಾನ:** UI ಮೂಲಕ ಹೋಸ್ಟ್ ಸೇರಿಸಿದಾಗ `/etc/hosts` ಗೆ `127.0.0.1 <host>` ಸೇರಿಸಲಾಗುತ್ತದೆ (sudo ಅಗತ್ಯವಿದೆ). ಈಗಾಗಲೇ ಇರುವ AgentBridge MITM ಸರ್ವರ್ (ಪೋರ್ಟ್ 443) ಹೊಸ ಹೋಸ್ಟ್ಗಾಗಿ SNI ಪ್ರಮಾಣಪತ್ರವನ್ನು ಡೈನಾಮಿಕ್ ಆಗಿ ರಚಿಸುತ್ತದೆ.
**ವ್ಯಾಪ್ತಿ:** ಸೇರಿಸಲಾದ ಹೋಸ್ಟ್ ಬಳಸುವ ಯಾವುದೇ ಅಪ್ಲಿಕೇಶನ್ — ಅಪ್ಲಿಕೇಶನ್ ಕಾನ್ಫಿಗರೇಶನ್ ಬದಲಾವಣೆ ಅಗತ್ಯವಿಲ್ಲ
**ಟಿಪ್ಪಣಿ:** `source` = `"custom-host"`

ಉದಾಹರಣೆಯ ಬಳಕೆಯ ಸಂದರ್ಭಗಳು:

- Python ಸ್ಕ್ರಿಪ್ಟ್ಗಳಿಂದ `api.openai.com` ಅನ್ನು ಮೇಲ್ವಿಚಾರಣೆ ಮಾಡುವುದು
- `my-internal-llm.company.com` ಅನ್ನು ಡೀಬಗ್ ಮಾಡುವುದು
- ಅದೇ ನೆಟ್ವರ್ಕ್ನಲ್ಲಿರುವ ಮೊಬೈಲ್ ಸಾಧನಗಳಿಂದ ಟ್ರಾಫಿಕ್ ಅನ್ನು ಕ್ಯಾಪ್ಚರ್ ಮಾಡುವುದು (ARP ಸ್ಪೂಫಿಂಗ್ ಮೂಲಕ — ಸುಧಾರಿತ)

### ಮೋಡ್ 3 — HTTP_PROXY ಲಿಸನರ್ (ಪೋರ್ಟ್ 8080)

**ಮೂಲ:** `HTTP_PROXY`/`HTTPS_PROXY` ಪರಿಸರ ಚರಾಂಶಗಳನ್ನು ಬಳಸುವ ಅಪ್ಲಿಕೇಶನ್ಗಳು
**ಕಾರ್ಯವಿಧಾನ:** ಪೋರ್ಟ್ 8080 ರಲ್ಲಿನ ದ್ವಿತೀಯ ಲಿಸನರ್ (`src/mitm/inspector/httpProxyServer.ts`) ಪ್ರಮಾಣಿತ ಸ್ಪಷ್ಟ HTTP/HTTPS ಪ್ರಾಕ್ಸಿಯಾಗಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ. `CONNECT` ಟನಲ್ಗಳು (HTTPS) ಮತ್ತು ನೇರ HTTP ವಿನಂತಿಗಳನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ.
**ವ್ಯಾಪ್ತಿ:** `HTTP_PROXY` ಪರಿಸರ ಚರಾಂಶವನ್ನು ಗೌರವಿಸುವ ಯಾವುದೇ ಅಪ್ಲಿಕೇಶನ್ — DNS ಬದಲಾವಣೆ ಇಲ್ಲ, sudo ಅಗತ್ಯವಿಲ್ಲ
**ಟಿಪ್ಪಣಿ:** `source` = `"http-proxy"`

```bash
# ಒಂದೇ ಕಮಾಂಡ್ಗಾಗಿ ತ್ವರಿತ ಕ್ಯಾಪ್ಚರ್:
HTTPS_PROXY=http://127.0.0.1:8080 curl https://api.openai.com/v1/models

# ಶೆಲ್ ಸೆಷನ್ನಲ್ಲಿ ನಿರಂತರ ಕ್ಯಾಪ್ಚರ್:
export HTTP_PROXY=http://127.0.0.1:8080
export HTTPS_PROXY=http://127.0.0.1:8080
```

**TLS ಮಿತಿ:** HTTPS `CONNECT` ಟನಲ್ಗಳನ್ನು ಮೆಟಾಡೇಟಾ ರೂಪದಲ್ಲಿ ಮಾತ್ರ ಕ್ಯಾಪ್ಚರ್ ಮಾಡಲಾಗುತ್ತದೆ (ಹೋಸ್ಟ್, ಪೋರ್ಟ್, ಸಮಯ) — ಡೀಫಾಲ್ಟ್ ಆಗಿ TLS ಬಾಡಿಯನ್ನು ಡೀಕ್ರಿಪ್ಟ್ ಮಾಡಲಾಗುವುದಿಲ್ಲ. ಸಂಪೂರ್ಣ ಬಾಡಿ ಪರಿಶೀಲನೆಗಾಗಿ "ಪ್ರಾಕ್ಸಿ ಮೋಡ್ನಲ್ಲಿ HTTPS ಅನ್ನು ಡೀಕ್ರಿಪ್ಟ್ ಮಾಡಿ" ಟಾಗಲ್ ಅನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ (ಐಚ್ಛಿಕ, AgentBridge ಪ್ರಮಾಣಪತ್ರವನ್ನು ವಿಶ್ವಾಸಾರ್ಹವೆಂದು ಗುರುತಿಸಿರುವುದು ಅಗತ್ಯ).

**ಪೋರ್ಟ್ ಸಂಘರ್ಷ:** ಪೋರ್ಟ್ 8080 ಬಳಕೆಯಲ್ಲಿದ್ದರೆ, AgentBridge ರಚನಾತ್ಮಕ ದೋಷದೊಂದಿಗೆ 409 ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ. `INSPECTOR_HTTP_PROXY_PORT` ಪರಿಸರ ಚರಾಂಶದ ಮೂಲಕ ಪೋರ್ಟ್ ಅನ್ನು ಬದಲಾಯಿಸಿ.

### ಮೋಡ್ 4 — ಸಿಸ್ಟಮ್-ವೈಡ್ ಪ್ರಾಕ್ಸಿ (ಸುಧಾರಿತ, ಐಚ್ಛಿಕ)

**ಮೂಲ:** OS-ಮಟ್ಟದ ಪ್ರಾಕ್ಸಿ ಸೆಟ್ಟಿಂಗ್ಗಳು (ಯಂತ್ರದಲ್ಲಿನ ಎಲ್ಲಾ ಅಪ್ಲಿಕೇಶನ್ಗಳಿಗೆ ಅನ್ವಯಿಸುತ್ತದೆ)
**ಕಾರ್ಯವಿಧಾನ:** ಎಲ್ಲಾ HTTP/HTTPS ಟ್ರಾಫಿಕ್ ಅನ್ನು HTTP_PROXY ಲಿಸನರ್ ಮೂಲಕ ಮರುನಿರ್ದೇಶಿಸಲು OS API ಗಳನ್ನು ಬಳಸುತ್ತದೆ:

- **macOS:** `networksetup -setwebproxy / -setsecurewebproxy`
- **Linux:** `gsettings set org.gnome.system.proxy` + `/etc/environment`
- **Windows:** `netsh winhttp set proxy 127.0.0.1:8080`
  **ವ್ಯಾಪ್ತಿ:** ಸಿಸ್ಟಮ್ ಪ್ರಾಕ್ಸಿ ಸೆಟ್ಟಿಂಗ್ಗಳನ್ನು ಗೌರವಿಸುವ ಯಂತ್ರದಲ್ಲಿನ ಪ್ರತಿಯೊಂದು ಅಪ್ಲಿಕೇಶನ್
  **ಟಿಪ್ಪಣಿ:** `source` = `"system-proxy"`

**ಸುರಕ್ಷತಾ ಕಾರ್ಯವಿಧಾನಗಳು:**

- ಸ್ವಯಂಚಾಲಿತವಾಗಿ ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವ ಟೈಮರ್ (ಡೀಫಾಲ್ಟ್ 30 ನಿಮಿಷ, `INSPECTOR_SYSTEM_PROXY_GUARD_MINUTES` ಮೂಲಕ ಕಾನ್ಫಿಗರ್ ಮಾಡಬಹುದು)
- ಹಿಂದಿನ ಸಿಸ್ಟಮ್ ಪ್ರಾಕ್ಸಿ ಸ್ಥಿತಿಯನ್ನು DB ಯಲ್ಲಿ ಉಳಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಹಿಮ್ಮರಳಿಸುವಾಗ ಮರುಸ್ಥಾಪಿಸಲಾಗುತ್ತದೆ
- ಸಕ್ರಿಯವಾಗಿರುವಾಗ ಬಳಕೆದಾರರು ಬೇರೆಡೆಗೆ ನ್ಯಾವಿಗೇಟ್ ಮಾಡಿದರೆ ಡ್ಯಾಶ್ಬೋರ್ಡ್ "ಸಿಸ್ಟಮ್ ಪ್ರಾಕ್ಸಿಯನ್ನು ಹಿಮ್ಮರಳಿಸಲಾಗುತ್ತಿದೆ" ಪ್ರಾಂಪ್ಟ್ ಅನ್ನು ತೋರಿಸುತ್ತದೆ
- UI `⚠ ಸುಧಾರಿತ` ಬ್ಯಾಡ್ಜ್ + ಸ್ಪಷ್ಟ ದೃಢೀಕರಣ ಚೆಕ್ಬಾಕ್ಸ್ ಅನ್ನು ತೋರಿಸುತ್ತದೆ

### ಮೋಡ್ 5 — TPROXY ಪಾರದರ್ಶಕ ಡೀಕ್ರಿಪ್ಷನ್ (Linux, root, ಐಚ್ಛಿಕ)

**ಮೂಲ:** ಕರ್ನಲ್ TPROXY + ಪಾಲಿಸಿ ರೂಟಿಂಗ್ (`src/mitm/tproxy/`)
**ಕಾರ್ಯವಿಧಾನ:** `mangle OUTPUT` ನಲ್ಲಿ ಗುರಿ ಪೋರ್ಟ್ಗೆ (ಡೀಫಾಲ್ಟ್ `443`) ಹೋಗುವ ಹೊಸ ಸ್ಥಳೀಯ ಔಟ್ಬೌಂಡ್ TCP ಸಂಪರ್ಕಗಳನ್ನು ಗುರುತಿಸುತ್ತದೆ, ಒಂದು `ip rule` ಗುರುತಿಸಲಾದ ಪ್ಯಾಕೆಟ್ಗಳನ್ನು ಸ್ಥಳೀಯ ಡೆಲಿವರಿಗೆ ಮರುರೂಟ್ ಮಾಡುತ್ತದೆ ಮತ್ತು `mangle PREROUTING` ನ `TPROXY` ಗುರಿಯು ಅವುಗಳನ್ನು ಪಾರದರ್ಶಕ (**IP_TRANSPARENT**) ಲಿಸನರ್ಗೆ (ಡೀಫಾಲ್ಟ್ ಪೋರ್ಟ್ `8443`) ಹಸ್ತಾಂತರಿಸುತ್ತದೆ. ಲಿಸನರ್ ಡೈನಾಮಿಕ್ CA ಮೂಲಕ **ಪ್ರತಿ SNI ಹೋಸ್ಟ್ಹೆಸರಿಗೆ ಬೇಡಿಕೆಯ ಮೇರೆಗೆ** ನೀಡಲಾದ ಲೀಫ್ ಪ್ರಮಾಣಪತ್ರದೊಂದಿಗೆ TLS ಅನ್ನು ಟರ್ಮಿನೇಟ್ ಮಾಡುತ್ತದೆ, ಡೀಕ್ರಿಪ್ಟ್ ಮಾಡಿದ ವಿನಿಮಯವನ್ನು ಕ್ಯಾಪ್ಚರ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ವಿನಂತಿಯನ್ನು ಮರು-ಎನ್ಕ್ರಿಪ್ಟ್ ಮಾಡಿ ಮೂಲ ಗಮ್ಯಸ್ಥಾನಕ್ಕೆ ಫಾರ್ವರ್ಡ್ ಮಾಡುತ್ತದೆ.
**ವ್ಯಾಪ್ತಿ:** ಗುರಿ ಪೋರ್ಟ್ನಲ್ಲಿರುವ **ಯಾವುದೇ** ಗಮ್ಯಸ್ಥಾನ ಹೋಸ್ಟ್ಗಳು — `/etc/hosts` ಸ್ಪೂಫ್ ಇಲ್ಲ, `HTTP_PROXY` ಪರಿಸರ ಚರಾಂಶ ಇಲ್ಲ, ಸಿಸ್ಟಮ್-ವೈಡ್ ಪ್ರಾಕ್ಸಿ ಮ್ಯೂಟೇಶನ್ ಇಲ್ಲ. ಇಂಟರ್ಸೆಪ್ಟ್ ಮಾಡಲಾದ ಪ್ರಕ್ರಿಯೆಗೆ ಯಾವುದೇ ಕಾನ್ಫಿಗರೇಶನ್ ಬದಲಾವಣೆ ಅಗತ್ಯವಿಲ್ಲ, ಆದರೆ ಅದು ಡೈನಾಮಿಕ್ CA ಅನ್ನು ವಿಶ್ವಾಸಿಸಬೇಕು.
**ಟಿಪ್ಪಣಿ:** `source` = `"tproxy"`

**ಅವಶ್ಯಕತೆಗಳು:** Linux ಮಾತ್ರ (**IP_TRANSPARENT** Linux ಗೆ ಮಾತ್ರ ಲಭ್ಯ), **CAP_NET_ADMIN** ಸಾಮರ್ಥ್ಯ (root), ಮತ್ತು C ಟೂಲ್ಚೈನ್ನೊಂದಿಗೆ ನಿರ್ಮಿಸಬೇಕಾದ ಸ್ಥಳೀಯ N-API ಆಡ್ಆನ್ (`npm run build:native:tproxy`). ಇದು ಲಭ್ಯವಿಲ್ಲದಿದ್ದಾಗ, "TPROXY ಡೀಕ್ರಿಪ್ಷನ್ಗೆ Linux + root + ಸ್ಥಳೀಯ ಆಡ್ಆನ್ ಅಗತ್ಯವಿದೆ" ಎಂಬ ಟೂಲ್ಟಿಪ್ನೊಂದಿಗೆ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಟಾಗಲ್ ಅನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಲಾಗುತ್ತದೆ. ಫೈರ್ವಾಲ್ ನಿಯಮಗಳನ್ನು ಟ್ರಾನ್ಸಾಕ್ಷನಲ್ ಆಗಿ ಅನ್ವಯಿಸಲಾಗುತ್ತದೆ/ಹಿಮ್ಮರಳಿಸಲಾಗುತ್ತದೆ (ಕ್ರ್ಯಾಶ್ ಎಂದಿಗೂ `mangle` ನಿಯಮವನ್ನು ಉಳಿಸುವುದಿಲ್ಲ) ಮತ್ತು ರೀಬೂಟ್ ಆದಾಗ ಅವುಗಳನ್ನು ಫ್ಲಷ್ ಮಾಡಲಾಗುತ್ತದೆ. SO_MARK-ಆಧಾರಿತ ಆಂಟಿ-ಲೂಪ್, ಪ್ರಾಕ್ಸಿಯ ಸ್ವಂತ ಮರು-ಎನ್ಕ್ರಿಪ್ಟ್ ಮಾಡಿದ ಫಾರ್ವರ್ಡ್ ಮತ್ತೆ ಇಂಟರ್ಸೆಪ್ಟ್ ಆಗುವುದನ್ನು ತಡೆಯುತ್ತದೆ.

ಇದು ತನ್ನದೇ ಆದ ಮೀಸಲಾದ ಆಪರೇಟರ್ ಮಾರ್ಗದರ್ಶಿಯನ್ನು ಹೊಂದಿರುವ ಗಣನೀಯ ಉಪವ್ಯವಸ್ಥೆಯಾಗಿದೆ — ಸಂಪೂರ್ಣ ಫೈರ್ವಾಲ್ ವಿಧಾನ, ಪ್ರತಿ-SNI ಡೈನಾಮಿಕ್ CA + ಟ್ರಸ್ಟ್-ಸ್ಟೋರ್ ಇನ್ಸ್ಟಾಲರ್, ಸ್ಥಳೀಯ-ಮಾತ್ರ ರೂಟ್, ಆಂಟಿ-ಲೂಪ್ ವಿವರಗಳು ಮತ್ತು ಕಾನ್ಫಿಗರೇಶನ್ ಸ್ಕೀಮಾಗಾಗಿ `docs/security/MITM-TPROXY-DECRYPT.md` ಅನ್ನು ನೋಡಿ (git; `/docs` ಗೆ ಕಂಪೈಲ್ ಮಾಡಲಾಗಿಲ್ಲ). ಟಾಗಲ್ ಅನ್ನು `GET / POST / DELETE /api/tools/agent-bridge/tproxy` ಮೂಲಕ ನಿಯಂತ್ರಿಸಲಾಗುತ್ತದೆ (ಟಿಪ್ಪಣಿ: ರೂಟ್ Traffic Inspector ಪ್ರಿಫಿಕ್ಸ್ ಅಡಿಯಲ್ಲಿ ಅಲ್ಲ, AgentBridge ಪ್ರಿಫಿಕ್ಸ್ ಅಡಿಯಲ್ಲಿ ಇದೆ).

- **ಏಜೆಂಟ್ ಇಮೋಜಿ**: 🔵 Antigravity, 🟢 Copilot, 🟠 Kiro, 🟣 Codex, 🔷 Cursor, 🟤 Zed, 🟡 Claude Code, ⚫ Open Code, 🌐 ಕಸ್ಟಮ್ ಹೋಸ್ಟ್
- **ಸಂದರ್ಭದ ಬಣ್ಣದ ಪಟ್ಟಿ**: `contextKey` (ಸಿಸ್ಟಮ್ ಪ್ರಾಂಪ್ಟ್ನ SHA-256) ಪ್ರಕಾರ ಬಣ್ಣ ಹೊಂದಿರುವ 1px ಎಡ ಅಂಚು — ಸಂಬಂಧಿತ ಸಂಭಾಷಣೆಗಳನ್ನು ದೃಶ್ಯಾತ್ಮಕವಾಗಿ ಗುಂಪು ಮಾಡುತ್ತದೆ
- **ಲೇಜಿ ಬಾಡಿ**: ಆಯ್ಕೆಮಾಡಿದ ವಿನಂತಿಯ ಬಾಡಿಯನ್ನು ಮಾತ್ರ ವಿವರ ಟ್ಯಾಬ್ಗಳಲ್ಲಿ ರಚಿಸಲಾಗುತ್ತದೆ (1000 × 1MB ಬಾಡಿಗಳನ್ನು ರೆಂಡರ್ ಮಾಡುವುದನ್ನು ತಪ್ಪಿಸುತ್ತದೆ)

## §4 LLM-ಅರಿವುಳ್ಳ ವೈಶಿಷ್ಟ್ಯಗಳು

### 4.1 ಪ್ರಕಾರ ಪತ್ತೆಗಾರ (`src/mitm/inspector/kindDetector.ts`)

4 ಸಂಕೇತಗಳನ್ನು ಬಳಸಿಕೊಂಡು ಪ್ರತಿಯೊಂದು ವಿನಂತಿಯನ್ನು `"llm"`, `"app"`, ಅಥವಾ `"unknown"` ಎಂದು ವರ್ಗೀಕರಿಸುತ್ತದೆ:

1. **ಹೋಸ್ಟ್ ನೋಂದಣಿ** — ~18 ಪರಿಚಿತ LLM API ಹೋಸ್ಟ್ಹೆಸರುಗಳು (OpenAI, Anthropic, Gemini, Groq, Mistral, Together, Fireworks, Cohere, Perplexity, Hugging Face, OpenRouter, xAI, Moonshot, ಇತ್ಯಾದಿ)
2. **ಪಥ ಮಾದರಿಗಳು** — `/v1/chat/completions`, `/v1/messages`, `/generateContent`, `/v1/responses`, ಇತ್ಯಾದಿ
3. **ಬಾಡಿ ವಿನ್ಯಾಸ** — `messages[]` (OpenAI/Claude), `contents[]` (Gemini), `prompt`, `input` ಕ್ಷೇತ್ರಗಳನ್ನು ಪತ್ತೆಹಚ್ಚುತ್ತದೆ
4. **ಬಳಕೆದಾರ-ಏಜೆಂಟ್ ಸುಳಿವುಗಳು** — UA ಸ್ಟ್ರಿಂಗ್ನಲ್ಲಿರುವ `codex`, `claude`, `gemini`, `antigravity`, `kiro`, `copilot`, `cursor`

Mode 2 ಮೂಲಕ ಸೇರಿಸಲಾದ ಕಸ್ಟಮ್ ಹೋಸ್ಟ್ಗಳು ಫಾರ್ಮ್ ಇನ್ಪುಟ್ನಿಂದ ತಮ್ಮ `kind` ಅನ್ನು ಪಡೆದುಕೊಳ್ಳುತ್ತವೆ (ಡೀಫಾಲ್ಟ್ ಆಗಿ `"custom"`).

### 4.2 SSE ವಿಲೀನಕಾರಕ (`src/mitm/inspector/sseMerger.ts`)

**ಸ್ವತಂತ್ರ ಕ್ಲೀನ್-ರೂಮ್ ಅನುಷ್ಠಾನ.** ಈವೆಂಟ್ ಪಾರ್ಸಿಂಗ್
[WHATWG ಸರ್ವರ್-ಸೆಂಟ್ ಈವೆಂಟ್ಗಳ ಅಲ್ಗಾರಿದಮ್](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream)
ಅನ್ನು ಅನುಸರಿಸುತ್ತದೆ, ಹಾಗೆಯೇ ಪುನರ್ನಿರ್ಮಾಣವು ಸಾರ್ವಜನಿಕ [OpenAI](https://platform.openai.com/docs/api-reference/chat/create),
[Anthropic](https://platform.claude.com/docs/en/build-with-claude/streaming), ಮತ್ತು
[Gemini](https://ai.google.dev/api/generate-content#method:-models.streamgeneratecontent)
ಸ್ಟ್ರೀಮಿಂಗ್ ಸ್ಕೀಮಾಗಳನ್ನು ಅನುಸರಿಸುತ್ತದೆ.

ಕಚ್ಚಾ SSE ಡೆಲ್ಟಾ ಈವೆಂಟ್ಗಳಿಂದ ಅಂತಿಮ ಸಹಾಯಕ ಸಂದೇಶವನ್ನು ಪುನರ್ನಿರ್ಮಿಸುತ್ತದೆ:

- **Anthropic**: ಸೂಚ್ಯಂಕದ ಪ್ರಕಾರ `content_block_delta` ಅನ್ನು ಸಂಗ್ರಹಿಸುತ್ತದೆ; `text_delta`, `input_json_delta` (ಟೂಲ್ ಕರೆಗಳು), `thinking_delta` ಅನ್ನು ನಿರ್ವಹಿಸುತ್ತದೆ
- **OpenAI**: Chat Completions ಆಯ್ಕೆಗಳು/ಟೂಲ್ ಕರೆಗಳು ಮತ್ತು Responses API ಔಟ್ಪುಟ್ ಐಟಂಗಳನ್ನು ಸೂಚ್ಯಂಕದ ಪ್ರಕಾರ ಸಂಗ್ರಹಿಸುತ್ತದೆ
- **Gemini**: `candidates[i].content.parts` ಅನ್ನು ಸಂಗ್ರಹಿಸುತ್ತದೆ
- **ಅಜ್ಞಾತ**: ಕಚ್ಚಾ ಈವೆಂಟ್ಗಳನ್ನು ಇರುವಂತೆಯೇ ಹಿಂದಿರುಗಿಸುತ್ತದೆ

Response ಟ್ಯಾಬ್ ಒಂದು ಟಾಗಲ್ ಅನ್ನು ತೋರಿಸುತ್ತದೆ: **"ಕಚ್ಚಾ ಈವೆಂಟ್ಗಳು ↔ ವಿಲೀನಗೊಳಿಸಿದವು"**.

### 4.3 ಸಂಭಾಷಣೆ ಸಾಮಾನ್ಯೀಕಾರಕ (`src/mitm/inspector/conversationNormalizer.ts`)

**ಸ್ವತಂತ್ರ ಕ್ಲೀನ್-ರೂಮ್ ಅನುಷ್ಠಾನ.** ಸಾಮಾನ್ಯೀಕರಣವನ್ನು ಸ್ಥಳೀಯ ಬ್ಲ್ಯಾಕ್-ಬಾಕ್ಸ್
ಒಪ್ಪಂದಗಳು ಮತ್ತು ಸಾರ್ವಜನಿಕ OpenAI, Anthropic, ಹಾಗೂ Gemini ಸಂದೇಶ ಸ್ಕೀಮಾಗಳಿಂದ ವ್ಯಾಖ್ಯಾನಿಸಲಾಗಿದೆ; ಯಾವುದೇ ಅಪ್ಸ್ಟ್ರೀಮ್
ಅನುಷ್ಠಾನದ ಮೂಲವನ್ನು ಬಳಸಿಲ್ಲ.

ರೆಂಡರ್ ಮಾಡುವ ಮೊದಲು OpenAI, Anthropic, ಮತ್ತು Gemini ಸಂದೇಶ ಸ್ವರೂಪಗಳನ್ನು ಒಂದೇ `NormalizedConversation` ಆಗಿ ಪರಿವರ್ತಿಸುತ್ತದೆ:

```ts
interface NormalizedConversation {
  request: NormalizedTurn[]; // ವಿನಂತಿಯ ಬಾಡಿಯಿಂದ messages / contents / prompt
  response: NormalizedTurn[]; // ಸಹಾಯಕ ಪ್ರತಿಕ್ರಿಯೆ (sseMerger ಮೂಲಕ ವಿಲೀನಗೊಳಿಸಲಾಗಿದೆ)
  contextKey: string | null; // SHA-256 ಸಿಸ್ಟಂ-ಪ್ರಾಂಪ್ಟ್ ಫಿಂಗರ್ಪ್ರಿಂಟ್
}
```

ಬ್ಲಾಕ್ ಪ್ರಕಾರಗಳು: `text`, `tool_use`, `tool_result`. ಪೂರೈಕೆದಾರರನ್ನು ಲೆಕ್ಕಿಸದೆ Conversation ಟ್ಯಾಬ್ ಈ ವಿನ್ಯಾಸವನ್ನು ಬಳಸುತ್ತದೆ.

### 4.4 ಸಂದರ್ಭ ಕೀಲಿಯ ಬಣ್ಣೀಕರಣ (`src/mitm/inspector/contextKey.ts`)

- ಸಿಸ್ಟಂ ಪ್ರಾಂಪ್ಟ್ನ `SHA-256` ಅನ್ನು ಲೆಕ್ಕಾಚಾರ ಮಾಡುತ್ತದೆ (ಮೊದಲ `role:system` ಸಂದೇಶ, ಅಥವಾ `system` ಕ್ಷೇತ್ರ, ಅಥವಾ Gemini `systemInstruction`)
- 12-ಅಕ್ಷರಗಳ ಹೆಕ್ಸ್ ಪೂರ್ವಪ್ರತ್ಯಯವನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ (`"a3f9c2..."`)
- ಮುಂಭಾಗವು ಎಡ-ಅಂಚಿನ ಪಟ್ಟಿಗಾಗಿ ಕೀಲಿಯನ್ನು ನಿರ್ಧಾರಾತ್ಮಕ HSL ಬಣ್ಣಕ್ಕೆ ಮ್ಯಾಪ್ ಮಾಡುತ್ತದೆ
- **"ಅದೇ ಸಂದರ್ಭ" ಫಿಲ್ಟರ್**: `ctx #a3f` ಚಿಪ್ ಅನ್ನು ಕ್ಲಿಕ್ ಮಾಡುವುದರಿಂದ ಅದೇ ಫಿಂಗರ್ಪ್ರಿಂಟ್ ಹೊಂದಿರುವ ವಿನಂತಿಗಳನ್ನು ಮಾತ್ರ ತೋರಿಸಲು ಫಿಲ್ಟರ್ ಸೇರುತ್ತದೆ

ಒಂದೇ ಏಜೆಂಟ್ ಸೆಷನ್ನಲ್ಲಿ ಚಾಲನೆಯಲ್ಲಿರುವ ವಿಭಿನ್ನ "ವ್ಯಕ್ತಿತ್ವಗಳು" ಅಥವಾ ಕಾರ್ಯಗಳನ್ನು ದೃಷ್ಟಿಗೋಚರವಾಗಿ ಪ್ರತ್ಯೇಕಿಸಲು ಇದು ಸುಲಭಗೊಳಿಸುತ್ತದೆ.

### 4.5 LLM ಮೆಟಾಡೇಟಾ ಹೊರತೆಗೆಯುವಿಕೆ

LLM ವಿನಂತಿಗಳಿಗಾಗಿ, LLM Details ಟ್ಯಾಬ್ ಈ ಕೆಳಗಿನವುಗಳನ್ನು ಹೊರತೆಗೆಯುತ್ತದೆ:

```ts
interface LlmMetadata {
  provider: string | null; // "openai" | "anthropic" | "gemini" | ...
  apiKind: string | null; // "chat.completions" | "messages" | "embeddings" | ...
  model: string | null; // ವಿನಂತಿಯ ಬಾಡಿ ಅಥವಾ ಪ್ರತಿಕ್ರಿಯೆಯಿಂದ
  messages: number; // ಸಂವಾದ ಸರದಿಗಳ ಸಂಖ್ಯೆ
  tokensIn: number | null; // usage.prompt_tokens / usage.input_tokens
  tokensOut: number | null; // usage.completion_tokens / usage.output_tokens
  streamed: boolean; // SSE ಪ್ರತಿಕ್ರಿಯೆಯಾಗಿದ್ದರೆ true
  mappedTo: string | null; // x-omniroute-mapped ಹೆಡರ್
  costEstimateUsd: number | null; // OmniRoute ದರಗಳ ಆಧಾರದ ಮೇಲೆ ಅಂದಾಜು ವೆಚ್ಚ
}
```

### 4.6 ಲೈವ್ ಪ್ರಗತಿಯಲ್ಲಿರುವ ವಿನಂತಿ ಫಿಲ್ಟರ್

ವಿನಂತಿಯ `status` ಕ್ಷೇತ್ರವು `number | "in-flight" | "error"` ಆಗಿರುತ್ತದೆ — ವಿನಂತಿಯು
ಪ್ರಾರಂಭವಾದ ಕ್ಷಣದಲ್ಲೇ ನಮೂದನ್ನು `"in-flight"` ಆಗಿ ಸೇರಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಪ್ರತಿಕ್ರಿಯೆ
(ಅಥವಾ ದೋಷ) ಬಂದಾಗ **ಅದೇ ಸ್ಥಳದಲ್ಲಿ ನವೀಕರಿಸಲಾಗುತ್ತದೆ**. ಟೂಲ್ಬಾರ್ನ **"ಲೈವ್"** ಟಾಗಲ್
(`liveOnly`, i18n ಕೀಲಿ `trafficInspector.liveOnly`) ಪಟ್ಟಿಯನ್ನು `status === "in-flight"`
ಇರುವ ನಮೂದುಗಳಿಗೆ ಸೀಮಿತಗೊಳಿಸಿ, ತೆರೆದ ಸಂಪರ್ಕಗಳನ್ನು ನೈಜ ಸಮಯದಲ್ಲಿ ವೀಕ್ಷಿಸಲು ನಿಮಗೆ ಅವಕಾಶ ನೀಡುತ್ತದೆ.

ಫಿಲ್ಟರ್ `src/lib/inspector/matchesTrafficFilter.ts` ನಲ್ಲಿರುವ ಶುದ್ಧ, ಕ್ಲೈಂಟ್-ಸೈಡ್ ಪ್ರೆಡಿಕೇಟ್ ಆಗಿದೆ:

```ts
if (f.liveOnly && req.status !== "in-flight") return false;
```

ಟಾಗಲ್ ಸ್ಥಿತಿಯು `useTrafficFilters` ನಲ್ಲಿ (ಇನ್ಸ್ಪೆಕ್ಟರ್ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಹುಕ್ಗಳು) ಇರುತ್ತದೆ ಮತ್ತು
ಇತರ ಫಿಲ್ಟರ್ಗಳೊಂದಿಗೆ (ಪ್ರೊಫೈಲ್, ಹೋಸ್ಟ್, ಏಜೆಂಟ್, ಮೂಲ, ಸ್ಥಿತಿ, ಸಂದರ್ಭ) ಸಂಯೋಜಿತವಾಗುತ್ತದೆ.

### 4.7 ಪ್ರಕ್ರಿಯೆ ಗುಣಲಕ್ಷಣ ನಿರ್ಧಾರ (Linux)

Linux ನಲ್ಲಿ, ತಡೆಹಿಡಿಯಲಾದ ಪ್ರತಿಯೊಂದು ವಿನಂತಿಯನ್ನು **ಮೂಲ ಸ್ಥಳೀಯ
ಪ್ರಕ್ರಿಯೆಗೆ** ಸಂಬಂಧಿಸಬಹುದು. `InterceptedRequest` ಗೆ ಎರಡು ಐಚ್ಛಿಕ ಕ್ಷೇತ್ರಗಳನ್ನು ಸೇರಿಸಲಾಗಿದೆ:

```ts
pid?: number;          // ಮೂಲ ಪ್ರಕ್ರಿಯೆಯ ಐಡಿ (Linux ಮಾತ್ರ)
processName?: string;  // ಮೂಲ ಪ್ರಕ್ರಿಯೆಯ ಹೆಸರು (Linux ಮಾತ್ರ)
```

`src/mitm/inspector/processAttribution.ts` ಸಂಪರ್ಕದ _ಕ್ಲೈಂಟ್_
ಅಲ್ಪಕಾಲಿಕ ಪೋರ್ಟ್ ಅನ್ನು PID + ಹೆಸರಿಗೆ ಈ ರೀತಿ ಮ್ಯಾಪ್ ಮಾಡುತ್ತದೆ:

1. ಪೋರ್ಟ್ಗೆ ಸಂಬಂಧಿಸಿದ ಸಾಕೆಟ್ inode ಅನ್ನು ಕಂಡುಹಿಡಿಯಲು `/proc/net/tcp` ಮತ್ತು `/proc/net/tcp6` ಅನ್ನು
   ಓದುತ್ತದೆ (`parseProcNetTcpForInode`, ಶುದ್ಧ ಫಿಕ್ಸ್ಚರ್-ಪರೀಕ್ಷಿಸಬಹುದಾದ ಪಾರ್ಸರ್).
2. `socket:[<inode>]` ಗೆ ಸಿಮ್ಲಿಂಕ್ಗಾಗಿ `/proc/<pid>/fd/` ಅನ್ನು ಸ್ಕ್ಯಾನ್ ಮಾಡುತ್ತದೆ.
3. `/proc/<pid>/comm` ನಿಂದ ಪ್ರಕ್ರಿಯೆಯ ಹೆಸರನ್ನು ಓದುತ್ತದೆ.

1-ಸೆಕೆಂಡ್ TTL ಕ್ಯಾಶ್ ಲೋಡ್ನಲ್ಲಿರುವಾಗ procfs ಸ್ಕ್ಯಾನ್ ವೆಚ್ಚವನ್ನು ಮಿತಿಗೊಳಿಸುತ್ತದೆ. ಗುಣಲಕ್ಷಣ ನಿರ್ಧಾರವು
**ಸಾಧ್ಯವಾದಷ್ಟರ ಮಟ್ಟಿಗೆ** ನಡೆಯುತ್ತದೆ — ಯಾವುದೇ ವೈಫಲ್ಯವು `null` ಗೆ ಪರಿಹಾರಗೊಳ್ಳುತ್ತದೆ ಮತ್ತು ಕ್ಯಾಪ್ಚರ್ ಅನ್ನು ಎಂದಿಗೂ ತಡೆಯುವುದಿಲ್ಲ.
macOS/Windows ನಲ್ಲಿ ಫಂಕ್ಷನ್ `null` ಅನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ (ಸ್ಟಬ್; `lsof`/`GetExtendedTcpTable`
ಬೆಂಬಲವು ಮುಂದಿನ ಹಂತವಾಗಿದೆ).

## §5 ಸೆಷನ್ಗಳು

### 5.1 ಸೆಷನ್ವೊಂದನ್ನು ರೆಕಾರ್ಡ್ ಮಾಡುವುದು

1. ಟೂಲ್ಬಾರ್ನಲ್ಲಿರುವ **"● ಸೆಷನ್ ರೆಕಾರ್ಡ್ ಮಾಡಿ"** ಅನ್ನು ಕ್ಲಿಕ್ ಮಾಡಿ → ಹೆಸರೊಂದನ್ನು ನಮೂದಿಸಿ (ಐಚ್ಛಿಕ)
2. ಲೈವ್ ಟೇಲ್ ಎಂದಿನಂತೆ ಮುಂದುವರಿಯುತ್ತದೆ; ಕೆಂಪು ಬಣ್ಣದಲ್ಲಿ ಮಿಡಿಯುವ ಸೂಚಕವು `◉ REC · <name> · 00:42 · 23 reqs` ಅನ್ನು ತೋರಿಸುತ್ತದೆ
3. **"⏹ ನಿಲ್ಲಿಸಿ"** ಅನ್ನು ಕ್ಲಿಕ್ ಮಾಡಿ → ಸೆಷನ್ ಸ್ನ್ಯಾಪ್ಶಾಟ್ ಅನ್ನು `inspector_sessions` + `inspector_session_requests` ಗೆ ಉಳಿಸಲಾಗುತ್ತದೆ

### 5.2 ರೆಕಾರ್ಡ್ ಮಾಡಿದ ಸೆಷನ್ವೊಂದನ್ನು ವೀಕ್ಷಿಸುವುದು

ಟೂಲ್ಬಾರ್ನಲ್ಲಿರುವ **ಸೆಷನ್ಗಳು** ಡ್ರಾಪ್ಡೌನ್ ಉಳಿಸಿದ ಸೆಷನ್ಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ. ಒಂದನ್ನು ಆಯ್ಕೆ ಮಾಡಿದಾಗ:

- ಸೆಷನ್ನ ಸ್ನ್ಯಾಪ್ಶಾಟ್ ಅನ್ನು ಲೋಡ್ ಮಾಡುತ್ತದೆ (ಸ್ಥಗಿತ ಸ್ಥಿತಿ)
- ಬ್ಯಾನರ್ ಹೀಗೆ ತೋರಿಸುತ್ತದೆ: `ರೆಕಾರ್ಡ್ ಮಾಡಿದ ಸೆಷನ್ "<name>" ಅನ್ನು ವೀಕ್ಷಿಸಲಾಗುತ್ತಿದೆ — [ಲೈವ್ಗೆ ಹಿಂತಿರುಗಿ]`
- Recharts ಒಟ್ಟುಮಾಡಿದ ದತ್ತಾಂಶದೊಂದಿಗೆ ಅಂಕಿಅಂಶಗಳ ಟ್ಯಾಬ್ ಲಭ್ಯವಾಗುತ್ತದೆ

### 5.3 ರಫ್ತು ಸ್ವರೂಪಗಳು

ಪ್ರತಿ ಸೆಷನ್ ಅನ್ನು ಈ ಕೆಳಗಿನಂತೆ ರಫ್ತು ಮಾಡಬಹುದು:

| ಸ್ವರೂಪ                     | ಬಳಕೆ                                                                                        |
| -------------------------- | ------------------------------------------------------------------------------------------- |
| **HAR** (HTTP ಆರ್ಕೈವ್ 1.2) | Chrome DevTools, Charles, Fiddler ಜೊತೆಗೆ ಹೊಂದಿಕೊಳ್ಳುತ್ತದೆ — ಆಫ್ಲೈನ್ ವಿಶ್ಲೇಷಣೆಗಾಗಿ ಆಮದು ಮಾಡಿ |
| **JSONL**                  | ಪ್ರತಿ ಸಾಲಿಗೆ ಒಂದು `InterceptedRequest` — `llm-interceptor` ಸ್ವರೂಪದೊಂದಿಗೆ ಹೊಂದಿಕೊಳ್ಳುತ್ತದೆ   |

`GET /api/tools/traffic-inspector/sessions/{id}/export.har` ಮೂಲಕ ಅಥವಾ ಸೆಷನ್ಗಳು ಡ್ರಾಪ್ಡೌನ್ನಲ್ಲಿರುವ ⬇ ಬಟನ್ ಮೂಲಕ ರಫ್ತು ಮಾಡಿ.

## §6 ಭದ್ರತೆ

ಟ್ರಾಫಿಕ್ ಇನ್ಸ್ಪೆಕ್ಟರ್ ದೃಢೀಕರಣ ಹೆಡರ್ಗಳು ಮತ್ತು ವಿನಂತಿ ಬಾಡಿಗಳನ್ನು ಒಳಗೊಂಡಂತೆ **ತಡೆಹಿಡಿದ ಎಲ್ಲಾ HTTPS ಟ್ರಾಫಿಕ್ ಅನ್ನು** ತೋರಿಸುತ್ತದೆ. ಕೆಳಗಿನ ನಿಯಂತ್ರಣಗಳನ್ನು ಅಳವಡಿಸಲಾಗಿದೆ:

| ನಿಯಂತ್ರಣ                             | ವಿವರಗಳು                                                                                                                                                                                                             |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LOCAL_ONLY**                       | ಎಲ್ಲಾ ರೂಟ್ಗಳು ಮತ್ತು WebSocket ಎಂಡ್ಪಾಯಿಂಟ್ ಲೂಪ್ಬ್ಯಾಕ್ಗೆ ಮಾತ್ರ ಸೀಮಿತವಾಗಿವೆ (ದೃಢೀಕರಣಕ್ಕೂ ಮೊದಲು `routeGuard.ts` ನಲ್ಲಿ ಜಾರಿಗೊಳಿಸಲಾಗಿದೆ)                                                                                  |
| **ರಹಸ್ಯ ಮರೆಮಾಚುವಿಕೆ**                | ರೇಖೀಯ `maskSecret()` ಸ್ಕ್ಯಾನರ್ RFC 6750 Bearer ದೃಢೀಕರಣ ವಿವರಗಳು, ಪೂರೈಕೆದಾರ-ಪೂರ್ವಪ್ರತ್ಯಯದ ಕೀಗಳು ಮತ್ತು ಉದ್ದವಾದ ಅಪಾರದರ್ಶಕ ಟೋಕನ್ಗಳನ್ನು `TrafficBuffer.push()` ಗಿಂತ ಮೊದಲು ಮರೆಮಾಡುತ್ತದೆ                                    |
| **ಬಾಡಿ ಗಾತ್ರದ ಮಿತಿ**                 | `INSPECTOR_MAX_BODY_KB` ಗಿಂತ ದೊಡ್ಡ ಬಾಡಿಗಳನ್ನು (ಡೀಫಾಲ್ಟ್ 1024 KB) `"(ಕಾರ್ಯಕ್ಷಮತೆಗಾಗಿ ಮೊಟಕುಗೊಳಿಸಲಾಗಿದೆ)"` ಸೂಚನೆಯೊಂದಿಗೆ ಮೊಟಕುಗೊಳಿಸಲಾಗುತ್ತದೆ                                                                            |
| **ಹೆಡರ್ ಸ್ವಚ್ಛಗೊಳಿಸುವಿಕೆ**           | ಹೆಸರುಗಳನ್ನು ಸಣ್ಣಕ್ಷರಕ್ಕೆ ಪರಿವರ್ತಿಸಲಾಗುತ್ತದೆ; ಫ್ರೇಮಿಂಗ್/ಹಾಪ್-ಬೈ-ಹಾಪ್ ಮತ್ತು ಪ್ರಾಕ್ಸಿ-ದೃಢೀಕರಣ ಹೆಡರ್ಗಳನ್ನು ಕೈಬಿಡಲಾಗುತ್ತದೆ; ಕುಕಿಗಳನ್ನು ಸಂಪೂರ್ಣವಾಗಿ ಮರೆಮಾಡಲಾಗುತ್ತದೆ; ರುಜುವಾತು ಮೌಲ್ಯಗಳನ್ನು `maskSecret()` ಗೆ ವಹಿಸಲಾಗುತ್ತದೆ |
| **CSP**                              | ಸೇರಿಸಲಾದ ಪ್ರತಿಕ್ರಿಯೆ ಬಾಡಿಗಳ ಮೂಲಕ XSS ಆಗುವುದನ್ನು ತಡೆಯಲು ಟ್ರಾಫಿಕ್ ಇನ್ಸ್ಪೆಕ್ಟರ್ ಪುಟಗಳಲ್ಲಿ ಕಟ್ಟುನಿಟ್ಟಾದ ಕಂಟೆಂಟ್ ಸೆಕ್ಯುರಿಟಿ ಪಾಲಿಸಿ                                                                                       |

### ತಿಳಿದಿರುವ ಮಿತಿಗಳು

- **ಸಿಸ್ಟಮ್-ವ್ಯಾಪಿ ಪ್ರಾಕ್ಸಿ ಮೋಡ್** VPN ಕ್ಲೈಂಟ್ಗಳು ಮತ್ತು SSO ಸೇರಿದಂತೆ ಯಂತ್ರದಲ್ಲಿರುವ ಎಲ್ಲಾ ಅಪ್ಲಿಕೇಶನ್ಗಳ ಮೇಲೆ ಪರಿಣಾಮ ಬೀರುತ್ತದೆ. ಯಾವಾಗಲೂ ಸ್ವಯಂ-ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವ ಟೈಮರ್ನೊಂದಿಗೆ ಬಳಸಿ. ಹಂಚಿಕೆಯ ಯಂತ್ರಗಳಲ್ಲಿ ಬಳಸಬೇಡಿ.
- **CONNECT ಟನಲ್ HTTPS**: TLS ಇಂಟರ್ಸೆಪ್ಷನ್ ಸಕ್ರಿಯಗೊಳಿಸದ ಹೊರತು, ಮೋಡ್ 3 (HTTP_PROXY) HTTPS ಗಮ್ಯಸ್ಥಾನಗಳಿಗಾಗಿ ಟನಲ್ ಮೆಟಾಡೇಟಾವನ್ನು ಮಾತ್ರ ಸೆರೆಹಿಡಿಯುತ್ತದೆ. ಇದು ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿದೆ — AgentBridge ಪ್ರಮಾಣಪತ್ರವನ್ನು ವಿಶ್ವಾಸಾರ್ಹವೆಂದು ಪರಿಗಣಿಸದೆ ಪಾರದರ್ಶಕವಾಗಿ ಸೆರೆಹಿಡಿದರೆ, ಆ ಅಪ್ಲಿಕೇಶನ್ಗಳ TLS ಪರಿಶೀಲನೆಯು ವಿಫಲವಾಗುತ್ತದೆ.
- **ಕೆಲವು ಕಾಂಪೊನೆಂಟ್ಗಳಲ್ಲಿ ಹಾರ್ಡ್ಕೋಡ್ ಮಾಡಿದ ಸ್ಟ್ರಿಂಗ್ಗಳು**: ಕೆಲವು UI ಕಾಂಪೊನೆಂಟ್ಗಳಲ್ಲಿ (F7/F8) ಇನ್ನೂ i18n ಕೀಗಳ ವ್ಯಾಪ್ತಿಗೆ ಒಳಪಡದ ಕೆಲವು ಹಾರ್ಡ್ಕೋಡ್ ಮಾಡಿದ ಸ್ಟ್ರಿಂಗ್ಗಳಿವೆ. ಇವುಗಳನ್ನು i18n ಅಂತರ ವರದಿಯಲ್ಲಿ ತಿಳಿದಿರುವ ಮಿತಿಯಾಗಿ ದಾಖಲಿಸಲಾಗಿದೆ; ನಂತರದ ಪರಿಷ್ಕರಣೆಯಲ್ಲಿ ಅವುಗಳನ್ನು ಸ್ಥಳಾಂತರಿಸಲಾಗುತ್ತದೆ. ಪರಿಣಾಮಕ್ಕೊಳಗಾದ ಸ್ಟ್ರಿಂಗ್ಗಳು ಕಾರ್ಯಾತ್ಮಕ ಬಳಕೆಗೆ ಅನುವಾದ ಅಗತ್ಯವಿಲ್ಲದ UI ಅಲಂಕಾರಿಕ ಲೇಬಲ್ಗಳಾಗಿವೆ.

## §7 ದೋಷನಿವಾರಣೆ

### WebSocket ಸಂಪರ್ಕ ಕಡಿತ

ಲೈವ್ ಟೇಲ್ನಲ್ಲಿ "ಸಂಪರ್ಕ ಕಡಿತಗೊಂಡಿದೆ" ಎಂದು ತೋರಿಸಿದರೆ:

1. ಸರ್ವರ್ ಇನ್ನೂ ಚಾಲನೆಯಲ್ಲಿದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸಿ: `GET /api/tools/traffic-inspector/capture-modes`
2. ಪುಟವನ್ನು ಮರುಲೋಡ್ ಮಾಡಿ — WebSocket ಮರುಸಂಪರ್ಕಗೊಂಡು ಹೊಸ ಸ್ನ್ಯಾಪ್ಶಾಟ್ ಅನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ
3. ಸರ್ವರ್ ಅನ್ನು ಮರುಪ್ರಾರಂಭಿಸಿದ್ದರೆ, ಇನ್-ಮೆಮೊರಿ ಬಫರ್ ತೆರವುಗೊಂಡಿರುತ್ತದೆ — ಸೆಷನ್ ಅನ್ನು ದಾಖಲಿಸಿರದಿದ್ದರೆ ಹಳೆಯ ನಮೂದುಗಳು ಲಭ್ಯವಿರುವುದಿಲ್ಲ

### ಪೋರ್ಟ್ 8080 ಸಂಘರ್ಷ

HTTP_PROXY ಮೋಡ್ ಪ್ರಾರಂಭಗೊಳ್ಳಲು ವಿಫಲವಾದರೆ:

```bash
lsof -i :8080    # ಪ್ರಕ್ರಿಯೆಯನ್ನು ಪತ್ತೆಮಾಡಿ
```

ಪೋರ್ಟ್ ಅನ್ನು ಬದಲಾಯಿಸಿ:

```bash
# .env
INSPECTOR_HTTP_PROXY_PORT=8888
```

### ಸಿಸ್ಟಮ್ ಪ್ರಾಕ್ಸಿಯನ್ನು ಹಿಂದಿನ ಸ್ಥಿತಿಗೆ ಮರಳಿಸಲಾಗಿಲ್ಲ

ಸಿಸ್ಟಮ್-ವೈಡ್ ಪ್ರಾಕ್ಸಿ ಮೋಡ್ ಸಕ್ರಿಯವಾಗಿರುವಾಗ OmniRoute ಕ್ರ್ಯಾಶ್ ಆದರೆ:

**macOS:**

```bash
networksetup -setwebproxystate Wi-Fi off
networksetup -setsecurewebproxystate Wi-Fi off
```

**Linux (GNOME):**

```bash
gsettings set org.gnome.system.proxy mode 'none'
```

**Windows:**

```cmd
netsh winhttp reset proxy
```

ಪ್ರಾಕ್ಸಿ ಸಕ್ರಿಯವಾಗಿತ್ತು ಎಂದು DB ಸ್ಥಿತಿಯು ಸೂಚಿಸುವುದನ್ನು ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಪತ್ತೆಮಾಡಿದರೆ, ಮುಂದಿನ ಬಾರಿ ಲೋಡ್ ಆಗುವಾಗ ಅದು "ಸಿಸ್ಟಮ್ ಪ್ರಾಕ್ಸಿಯನ್ನು ಹಿಂದಿನ ಸ್ಥಿತಿಗೆ ಮರಳಿಸಿ" ಆಯ್ಕೆಯನ್ನೂ ನೀಡುತ್ತದೆ.

### ಬಫರ್ ತುಂಬಿದೆ

ಬಫರ್ `INSPECTOR_BUFFER_SIZE` (ಡೀಫಾಲ್ಟ್ 1000) ಅನ್ನು ತಲುಪಿದಾಗ, ಹೊಸ ನಮೂದುಗಳು ಅತ್ಯಂತ ಹಳೆಯ ನಮೂದುಗಳನ್ನು ಹೊರಹಾಕುತ್ತವೆ. ಪ್ರಮುಖ ವಿನಂತಿಗಳು ಕಳೆದುಹೋಗುತ್ತಿದ್ದರೆ:

- `INSPECTOR_BUFFER_SIZE` ಅನ್ನು ಹೆಚ್ಚಿಸಿ (ಉದಾ., 5000) — ಇದು ಹೆಚ್ಚು ಕಾಲ ಉಳಿಸಿಕೊಳ್ಳಲು ಹೆಚ್ಚಿನ ಮೆಮೊರಿಯನ್ನು ಬಳಸುತ್ತದೆ
- ಸಂಬಂಧಿತ ಸಮಯಾವಧಿಯನ್ನು DB ಯಲ್ಲಿ ಶಾಶ್ವತವಾಗಿ ಉಳಿಸಲು ಸೆಷನ್ ಅನ್ನು ದಾಖಲಿಸಿ
