OmniRoute ಸ್ಥಳೀಯ-ಪ್ರಥಮ ಗೇಮಿಫಿಕೇಶನ್ ಪದರವನ್ನು ಒಳಗೊಂಡಿದ್ದು, ಪ್ಲಾಟ್ಫಾರ್ಮ್ನೊಂದಿಗೆ
ತೊಡಗಿಸಿಕೊಳ್ಳುವುದಕ್ಕಾಗಿ ಬಳಕೆದಾರರಿಗೆ ಬಹುಮಾನ ನೀಡುತ್ತದೆ — ವಿನಂತಿಗಳನ್ನು ಮಾಡುವುದು, ಪೂರೈಕೆದಾರರನ್ನು ಬದಲಾಯಿಸುವುದು,
ಕಾಂಬೊಗಳನ್ನು ರಚಿಸುವುದು, ಟೋಕನ್ಗಳನ್ನು ಹಂಚಿಕೊಳ್ಳುವುದು ಮತ್ತು ಸಮುದಾಯಕ್ಕೆ ಕೊಡುಗೆ ನೀಡುವುದು. ಎಲ್ಲಾ ಸ್ಥಿತಿಯೂ
SQLiteನಲ್ಲಿ ಇರುತ್ತದೆ; ಸಮುದಾಯ ಸರ್ವರ್ಗಳೊಂದಿಗಿನ ಫೆಡರೇಶನ್ ಐಚ್ಛಿಕವಾಗಿದ್ದು ಪುಶ್-ಆಧಾರಿತವಾಗಿದೆ.

ಈ ವ್ಯವಸ್ಥೆಯನ್ನು **ಹಾಟ್ ಪಾತ್ನಲ್ಲಿ ಶೂನ್ಯ-ವಿಳಂಬ ಹೊಂದಿರುವಂತೆ** ವಿನ್ಯಾಸಗೊಳಿಸಲಾಗಿದೆ — ಗೇಮಿಫಿಕೇಶನ್
ಈವೆಂಟ್ಗಳನ್ನು ವಿನಂತಿ ಪೈಪ್ಲೈನ್ನಿಂದ ಕಳುಹಿಸಿ-ಮರೆತುಬಿಡುವ ವಿಧಾನದಲ್ಲಿ ರವಾನಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಅವು ಎಂದಿಗೂ
LLM ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ನಿರ್ಬಂಧಿಸುವುದಿಲ್ಲ.

## ಅವಲೋಕನ

### ಉದ್ದೇಶ

ಗೋಚರ ಪ್ರಗತಿ (XP, ಹಂತಗಳು, ಬ್ಯಾಡ್ಜ್ಗಳು), ಸಾಮಾಜಿಕ ಪುರಾವೆ (ಲೀಡರ್ಬೋರ್ಡ್ಗಳು) ಮತ್ತು ಆರ್ಥಿಕ ಪ್ರೋತ್ಸಾಹಗಳನ್ನು (ಟೋಕನ್
ಹಂಚಿಕೆ, ಆಹ್ವಾನ ಬಹುಮಾನಗಳು) ಒದಗಿಸುವ ಮೂಲಕ ಬಳಕೆದಾರರ ತೊಡಗಿಸಿಕೊಳ್ಳುವಿಕೆ ಮತ್ತು ಉಳಿಸಿಕೊಳ್ಳುವಿಕೆಯನ್ನು ಹೆಚ್ಚಿಸುವುದು.

### ವಿನ್ಯಾಸ ತತ್ವಗಳು

1. **ಸ್ಥಳೀಯ-ಪ್ರಥಮ** — ಎಲ್ಲಾ ಸ್ಥಿತಿಯೂ SQLiteನಲ್ಲಿ ಇರುತ್ತದೆ, ಯಾವುದೇ ಬಾಹ್ಯ ಸೇವೆಗಳ ಅಗತ್ಯವಿಲ್ಲ.
2. **ನಿರ್ಬಂಧಿಸದ** — ಈವೆಂಟ್ಗಳನ್ನು ಕಳುಹಿಸಿ-ಮರೆತುಬಿಡುವ ವಿಧಾನದಲ್ಲಿ ರವಾನಿಸಲಾಗುತ್ತದೆ; LLM ಪ್ರತಿಕ್ರಿಯೆಯ ಪಥವು
   ಗೇಮಿಫಿಕೇಶನ್ ತರ್ಕದಿಂದ ಎಂದಿಗೂ ವಿಳಂಬಗೊಳ್ಳುವುದಿಲ್ಲ.
3. **ಸರ್ವರ್-ಅಧಿಕೃತ** — XP ಅನ್ನು ಸರ್ವರ್ ಬದಿಯಲ್ಲಿ ಮಾತ್ರ ಲೆಕ್ಕಹಾಕಲಾಗುತ್ತದೆ; ಕ್ಲೈಂಟ್ಗಳು
   ಸ್ಕೋರ್ಗಳನ್ನು ಕೃತಕವಾಗಿ ಹೆಚ್ಚಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ.
4. **ಗೌಪ್ಯತೆಗೆ ಗೌರವ ನೀಡುವ** — ಲೀಡರ್ಬೋರ್ಡ್ನಲ್ಲಿ ಭಾಗವಹಿಸುವುದು ಐಚ್ಛಿಕವಾಗಿದೆ; ಬಳಕೆದಾರರು
   ತಮ್ಮ ಪ್ರೊಫೈಲ್ ಅನ್ನು ಮರೆಮಾಡಬಹುದು.
5. **ಫೆಡರೇಶನ್ಗೆ ಸಿದ್ಧ** — ಸಮುದಾಯ ಸರ್ವರ್ಗಳು ಸಹಿ ಮಾಡಿದ API ಮೂಲಕ ಸ್ಕೋರ್ಗಳನ್ನು ಪುಶ್ ಮಾಡಬಹುದು;
   ಸಿಂಕ್ ಮೇಲ್ಬರಹ ಮಾಡುತ್ತದೆ, ಸಂಕಲನ ಮಾಡುವುದಿಲ್ಲ.


## ಡೇಟಾ ಪದರ

### ಡೇಟಾಬೇಸ್ ಕೋಷ್ಟಕಗಳು

ಎಲ್ಲಾ ಕೋಷ್ಟಕಗಳು ಮುಖ್ಯ OmniRoute SQLite ಡೇಟಾಬೇಸ್ನಲ್ಲಿದ್ದು, ಅವುಗಳನ್ನು
`060_create_gamification.sql` ವಲಸೆಯ ಮೂಲಕ ರಚಿಸಲಾಗಿದೆ. WAL ಜರ್ನಲಿಂಗ್ ಅನ್ನು
`src/lib/db/core.ts` ನಲ್ಲಿರುವ ಸಿಂಗಲ್ಟನ್ `getDbInstance()` ನಿಂದ ಆನುವಂಶಿಕವಾಗಿ ಪಡೆಯಲಾಗುತ್ತದೆ.

```
┌─────────────────────────┐     ┌──────────────────────────┐
```

### ಬಹುಮಾನ ನೀಡುವ ಪ್ರಕ್ರಿಯೆ

```typescript
export async function awardXp(
  apiKeyId: string,
  action: XpAction,
  metadata?: Record<string, unknown>
): Promise<{ xp: number; level: number; title: string; levelUp: boolean }>;
```

1. XP ಮೊತ್ತವನ್ನು ಪಡೆಯಲು `XP_REWARDS[action]` ಅನ್ನು ಪರಿಶೀಲಿಸಿ.
2. `checkRateLimit()` ಮೂಲಕ ಹಾದುಹೋಗಿ (ಮೋಸ-ವಿರೋಧಿ: ಪ್ರತಿ ಕೀಗೆ ಗರಿಷ್ಠ 1000 XP/ನಿಮಿಷ).
3. ವಹಿವಾಟನ್ನು ತೆರೆಯಿರಿ:
   - ಪ್ರಸ್ತುತ `user_levels` ಸಾಲನ್ನು ಓದಿ.
   - XP ಸೇರಿಸಿ; `levelFromXp(totalXp)` ಮೂಲಕ ಹಂತವನ್ನು ಮರುಲೆಕ್ಕಾಚಾರ ಮಾಡಿ.
   - ಹಂತ ಬದಲಾಗಿದ್ದರೆ, `levelUp = true` ಹೊಂದಿಸಿ.
   - `user_levels` ಸಾಲನ್ನು ನವೀಕರಿಸಿ.
   - `xp_audit_log` ಗೆ ಸೇರಿಸಿ.
4. ಫಲಿತಾಂಶವನ್ನು ಹಿಂತಿರುಗಿಸಿ. ಕರೆ ಮಾಡುವ ಘಟಕವು ಅಧಿಸೂಚನೆಗಳನ್ನು ನಿರ್ವಹಿಸುತ್ತದೆ.

### ಸಹಾಯಕ: `levelFromXp(totalXp)`

ಒಟ್ಟು XP `totalXp` ಅನ್ನು ಮೀರುವವರೆಗೆ `xp_for_level(n)` ಅನ್ನು ಕೂಡಿಸುತ್ತಾ,
1..100 ಹಂತಗಳ ಮೂಲಕ ಪುನರಾವರ್ತಿಸುತ್ತದೆ. ಮಿತಿ ತಲುಪಿರುವ ಅತ್ಯುನ್ನತ ಹಂತವನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ.
ಇದು O(100) — ಹಂತಗಳು 100ಕ್ಕೆ ಸೀಮಿತವಾಗಿರುವುದರಿಂದ ಸ್ವೀಕಾರಾರ್ಹವಾಗಿದೆ.

### ಮೌಲ್ಯಮಾಪನ ಪ್ರಕ್ರಿಯೆ

```
emitGamificationEvent(event)
  → evaluateBadges(apiKeyId, event)
    → getBadgeDefinitions()           # ಎಲ್ಲಾ ವ್ಯಾಖ್ಯಾನಗಳು
    → getUserBadges(apiKeyId)         # ಈಗಾಗಲೇ ಗಳಿಸಿರುವವು (ಬಿಟ್ಟುಬಿಡಿ)
    → ಗಳಿಸದಿರುವ ಪ್ರತಿಯೊಂದು ಬ್ಯಾಡ್ಜ್ಗೆ:
       → matchesCriteria(badge, event, userState)
       → ಹೊಂದಿಕೆಯಾದರೆ: awardBadge(apiKeyId, badgeId)
         → ಅಧಿಸೂಚನೆಯ ಪೇಲೋಡ್ ಅನ್ನು ಹಿಂತಿರುಗಿಸಿ
```

ಮೌಲ್ಯಮಾಪನವು **ಘಟನೆ-ಚಾಲಿತವಾಗಿದೆ** — ಇದು ಪ್ರತಿ ಗೇಮಿಫಿಕೇಶನ್ ಘಟನೆಯ ನಂತರ ಚಲಿಸುತ್ತದೆ, ಆದರೆ
ಘಟನೆಯ ಕ್ರಿಯೆಗೆ ಹೊಂದಿಕೆಯಾಗುವ `criteria.type` ಹೊಂದಿರುವ ಬ್ಯಾಡ್ಜ್ಗಳನ್ನು ಮಾತ್ರ ಪರಿಶೀಲಿಸುತ್ತದೆ. ಇದರಿಂದ
ಮೌಲ್ಯಮಾಪನವು ವೇಗವಾಗಿ ಉಳಿಯುತ್ತದೆ (ಹೆಚ್ಚಿನ ಘಟನೆಗಳಿಗೆ < 5ms).

### `matchesCriteria(badge, event, userState)`

| ಮಾನದಂಡದ ಪ್ರಕಾರ | ಪರಿಶೀಲನೆ                                                       |
| -------------- | -------------------------------------------------------------- |
| `action_count` | `getActionCount(apiKeyId, action) >= count`                    |
| `streak`       | `getCurrentStreak(apiKeyId) >= days`                           |

## ಸ್ಟ್ರೀಕ್ ಟ್ರ್ಯಾಕರ್

**ಫೈಲ್:** `src/lib/gamification/streaks.ts`

### ಡೇಟಾ ಮಾದರಿ

ಸ್ಟ್ರೀಕ್ಗಳನ್ನು `key_value` ಕೋಷ್ಟಕದಲ್ಲಿ (ಹಂಚಿಕೆಯ ಉಪಯುಕ್ತತಾ ಕೋಷ್ಟಕ) ನೇಮ್ಸ್ಪೇಸ್ ಮಾಡಿದ ಕೀಲಿಗಳ ಅಡಿಯಲ್ಲಿ ಸಂಗ್ರಹಿಸಲಾಗುತ್ತದೆ:

| ಕೀ                            | ಮೌಲ್ಯ                            | ವಿವರಣೆ               |
| ----------------------------- | -------------------------------- | -------------------- |
| `gamification:streak:{keyId}` | `{current},{longest},{lastDate}` | ಸಕ್ರಿಯ ಸ್ಟ್ರೀಕ್ ಡೇಟಾ |

### ತರ್ಕ

```typescript
export async function updateStreak(
  apiKeyId: string
): Promise<{ current: number; longest: number; milestone: boolean }>;
```

1. `key_value` ನಿಂದ ಸ್ಟ್ರೀಕ್ ದಾಖಲೆಯನ್ನು ಓದಿ.
2. `{current}`, `{longest}`, `{lastDate}` (ISO ದಿನಾಂಕ ಸ್ಟ್ರಿಂಗ್) ಅನ್ನು ಪಾರ್ಸ್ ಮಾಡಿ.
3. `lastDate === today` ಆಗಿದ್ದರೆ — ಯಾವುದೇ ಬದಲಾವಣೆ ಇಲ್ಲ (ಇಂದು ಈಗಾಗಲೇ ಎಣಿಸಲಾಗಿದೆ).
4. `lastDate === yesterday` ಆಗಿದ್ದರೆ — `current` ಅನ್ನು ಹೆಚ್ಚಿಸಿ; ಅಗತ್ಯವಿದ್ದರೆ `longest` ಅನ್ನು ನವೀಕರಿಸಿ.
5. `lastDate < yesterday` ಆಗಿದ್ದರೆ — `current = 1` ಎಂದು ಮರುಹೊಂದಿಸಿ (ಸ್ಟ್ರೀಕ್ ಮುರಿದಿದೆ).
6. ನವೀಕರಿಸಿದ ದಾಖಲೆಯನ್ನು ಬರೆಯಿರಿ.
7. ಮೈಲಿಗಲ್ಲುಗಳನ್ನು ಪರಿಶೀಲಿಸಿ: 7, 14, 30, 60, 90, 180, 365 ದಿನಗಳು. ಅವುಗಳಲ್ಲಿ ಯಾವುದನ್ನಾದರೂ ದಾಟಿದ್ದರೆ,
   `milestone = true` ಎಂದು ಹೊಂದಿಸಿ (ಕಾಲರ್ XP ನೀಡುತ್ತದೆ ಮತ್ತು ಬ್ಯಾಡ್ಜ್ಗಳನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ).

### ಅಂಚಿನ ಸಂದರ್ಭಗಳು

- **ಸಮಯ ವಲಯ**: ಸ್ಟ್ರೀಕ್ಗಳು UTC ದಿನಾಂಕಗಳನ್ನು ಬಳಸುತ್ತವೆ (`new Date().toISOString().slice(0, 10)`).
  ಇದು ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿದೆ — ಏಕೈಕ ಅಂಗೀಕೃತ ಸಮಯ ವಲಯವು ಸಮಯ ವಲಯಗಳನ್ನು ಬದಲಾಯಿಸುವ ಮೂಲಕ
  ವ್ಯವಸ್ಥೆಯನ್ನು ದುರುಪಯೋಗಪಡಿಸಿಕೊಳ್ಳುವುದನ್ನು ತಡೆಯುತ್ತದೆ.
- **ಹೊಸ ಬಳಕೆದಾರರು**: ಯಾವುದೇ ಸ್ಟ್ರೀಕ್ ದಾಖಲೆ ಇರುವುದಿಲ್ಲ; ಮೊದಲ ವಿನಂತಿಯು ಅದನ್ನು
  `current=1, longest=1, lastDate=today` ನೊಂದಿಗೆ ರಚಿಸುತ್ತದೆ.
- **ದಿನಕ್ಕೆ ಹಲವು ವಿನಂತಿಗಳು**: UTC ದಿನದ ಮೊದಲ ವಿನಂತಿ ಮಾತ್ರ
  ಸ್ಟ್ರೀಕ್ ಅನ್ನು ಹೆಚ್ಚಿಸುತ್ತದೆ.

```typescript
export async function getLeaderboard(
  scope: LeaderboardScope,
  period: string,
  limit: number,
  offset: number
```

ಕ್ವೆರಿ ಮಾದರಿ:

```sql
SELECT api_key_id, score,

LIMIT ? OFFSET ?
```

   `leaderboard_archive` ಗೆ ನಕಲಿಸಿ.

## ಟೋಕನ್ ಹಂಚಿಕೆ

**ಫೈಲ್:** `src/lib/gamification/sharing.ts`

### ದ್ವಿ-ನಮೂದು ಲೆಡ್ಜರ್

ಪ್ರತಿ ವರ್ಗಾವಣೆಯು `token_ledger` ನಲ್ಲಿ ಎರಡು ಸಾಲುಗಳನ್ನು ರಚಿಸುತ್ತದೆ:

| ಸಾಲು     | `from_key_id` | `to_key_id`   | `amount` |
| -------- | ------------- | ------------- | -------- |
| ಡೆಬಿಟ್   | ಕಳುಹಿಸುವವರು   | ಸ್ವೀಕರಿಸುವವರು | +amount  |
| ಕ್ರೆಡಿಟ್ | ಸ್ವೀಕರಿಸುವವರು | ಕಳುಹಿಸುವವರು   | -amount  |

ನಿರೀಕ್ಷಿಸಿ — ರೂಢಿಯು ಹೀಗಿದೆ:

| ಸಾಲು          | `from_key_id` | `to_key_id`   | `amount` | ಅರ್ಥ                    |
| ------------- | ------------- | ------------- | -------- | ----------------------- |
| ಕಳುಹಿಸುವಿಕೆ   | ಕಳುಹಿಸುವವರು   | ಸ್ವೀಕರಿಸುವವರು | +amount  | ಕಳುಹಿಸುವವರಿಂದ ಹೊರಹರಿವು  |
| ಸ್ವೀಕರಿಸುವಿಕೆ | ಸ್ವೀಕರಿಸುವವರು | ಕಳುಹಿಸುವವರು   | +amount  | ಸ್ವೀಕರಿಸುವವರಿಗೆ ಒಳಹರಿವು |

ಬ್ಯಾಲೆನ್ಸ್ ಅನ್ನು ಹೀಗೆ ಲೆಕ್ಕಹಾಕಲಾಗುತ್ತದೆ:

```sql
SELECT
  COALESCE(SUM(CASE WHEN to_key_id = ? THEN amount ELSE 0 END), 0)
  - COALESCE(SUM(CASE WHEN from_key_id = ? THEN amount ELSE 0 END), 0)
  AS balance
FROM token_ledger
WHERE from_key_id = ? OR to_key_id = ?
```

### ವರ್ಗಾವಣೆ ಪ್ರಕ್ರಿಯೆ

```typescript
export async function transferTokens(
  fromKeyId: string,
  toKeyId: string,
  amount: number,
  idempotencyKey: string
): Promise<{ success: boolean; balance: number }>;
```

1. **ಮೌಲ್ಯೀಕರಿಸಿ**: `amount > 0`, `fromKeyId !== toKeyId`.
2. **ಐಡೆಂಪೊಟೆನ್ಸಿ**: ಲೆಡ್ಜರ್ನಲ್ಲಿ `idempotency_key` ಈಗಾಗಲೇ ಅಸ್ತಿತ್ವದಲ್ಲಿದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸಿ.
   ಹೌದಾದರೆ, ಕ್ಯಾಶ್ ಮಾಡಲಾದ ಫಲಿತಾಂಶವನ್ನು ಹಿಂತಿರುಗಿಸಿ.
3. **ವಹಿವಾಟು** (ಒಂದೇ SQLite ವಹಿವಾಟು):
   a. ಕಳುಹಿಸುವವರ ಬ್ಯಾಲೆನ್ಸ್ ಅನ್ನು ಲೆಕ್ಕಹಾಕಿ.
   b. `balance < amount` ಆಗಿದ್ದರೆ, ಸ್ಥಗಿತಗೊಳಿಸಿ (ಸಾಕಷ್ಟು ನಿಧಿಗಳಿಲ್ಲ).
   c. ಕಳುಹಿಸುವ ಸಾಲನ್ನು ಸೇರಿಸಿ (`from=sender,` ಅನ್ನು ಹಿಂತಿರುಗಿಸಿ.

### ದರ ಮಿತಿಗೊಳಿಸುವಿಕೆ

- ಪ್ರತಿ API ಕೀಗೆ ಪ್ರತಿ ನಿಮಿಷ ಗರಿಷ್ಠ 10 ವರ್ಗಾವಣೆಗಳು.
- ಒಂದೇ ವರ್ಗಾವಣೆಯಲ್ಲಿ ಗರಿಷ್ಠ 10,000 ಟೋಕನ್ಗಳು.
- ಪ್ರತಿ API ಕೀಗೆ ದಿನಕ್ಕೆ ಗರಿಷ್ಠ 100,000 ಟೋಕನ್ಗಳ ವರ್ಗಾವಣೆ.

## ಆಹ್ವಾನ ಮತ್ತು ಟೋಕನ್ಗಳ ರಿಡೀಮ್

**ಫೈಲ್:** `src/lib/gamification/invites.ts`

### ಕೋಡ್ ಸ್ವರೂಪ

- **ಕೋಡ್**: 8-ಅಕ್ಷರಗಳ ಅಕ್ಷರ-ಅಂಕೀಯ ಕೋಡ್ (ಉದಾ., `A3K9-X7M2`), ಮನುಷ್ಯರು ಓದಬಹುದಾದದ್ದು,
  ಬಳಕೆದಾರರಿಗೆ ಪ್ರದರ್ಶಿಸಲಾಗುತ್ತದೆ.
- **ಟೋಕನ್**: 32-ಬೈಟ್ ಯಾದೃಚ್ಛಿಕ ಟೋಕನ್, SHA-256 ಹ್ಯಾಶ್ ರೂಪದಲ್ಲಿ ಸಂಗ್ರಹಿಸಲಾಗುತ್ತದೆ.
  ಪ್ರೋಗ್ರಾಮ್ಯಾಟಿಕ್ ರಿಡೆಂಪ್ಶನ್ಗಾಗಿ (ಉದಾ., URL ಲಿಂಕ್ಗಳು) ಬಳಸಲಾಗುತ್ತದೆ.

### ಸಂಗ್ರಹಣೆ

| ಕಾಲಮ್        | ಮೌಲ್ಯ                         |
| ------------ | ----------------------------- |
| `code`       | `A3K9X7M2` (ಅನನ್ಯ, ಸೂಚ್ಯಂಕಿತ) |
| `token_hash` | SHA-256(raw_token)            |

ರಚನೆಯ ಸಮಯದಲ್ಲಿ ಮೂಲ ಟೋಕನ್ ಅನ್ನು ಬಳಕೆದಾರರಿಗೆ ನಿಖರವಾಗಿ ಒಮ್ಮೆ ಮಾತ್ರ ಹಿಂತಿರುಗಿಸಲಾಗುತ್ತದೆ. OmniRoute
ಅದನ್ನು ಮತ್ತೆಂದೂ ಸಂಗ್ರಹಿಸುವುದಿಲ್ಲ ಅಥವಾ ಪ್ರದರ್ಶಿಸುವುದಿಲ್ಲ — ಹ್ಯಾಶ್ ಮಾತ್ರ ಉಳಿಯುತ್ತದೆ.

### ಸ್ವಯಂ-ರೆಫರಲ್ ತಡೆಗಟ್ಟುವಿಕೆ

ಬಳಕೆದಾರರು ಕೋಡ್ ಅನ್ನು ರಿಡೀಮ್ ಮಾಡಿದಾಗ, ಸಿಸ್ಟಮ್ ಇವುಗಳನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ:

1. ಕೋಡ್ ಬೇರೆ `api_key_id` ಗೆ ಸೇರಿದೆ.
2. ರಿಡೀಮ್ ಮಾಡುವ ಬಳಕೆದಾರರು ಇದೇ ರೆಫರರ್ನ ಯಾವುದೇ ಕೋಡ್ ಅನ್ನು ಈ ಹಿಂದೆ ರಿಡೀಮ್ ಮಾಡಿಲ್ಲ
   (`invite_tokens` + ರಿಡೆಂಪ್ಶನ್ ಲಾಗ್ನಲ್ಲಿ ಜಾಯಿನ್ ಮಾಡಲಾಗುತ್ತದೆ).

ಯಾವುದಾದರೂ ಪರಿಶೀಲನೆ ವಿಫಲವಾದರೆ, ಸ್ಪಷ್ಟ ದೋಷ ಸಂದೇಶದೊಂದಿಗೆ ರಿಡೆಂಪ್ಶನ್ ಅನ್ನು ತಿರಸ್ಕರಿಸಲಾಗುತ್ತದೆ.

### ಅವಧಿ ಮುಕ್ತಾಯ ಮತ್ತು ಮಿತಿಗಳು

- ಡೀಫಾಲ್ಟ್ `max_uses`: 10 (ರಚಿಸುವಾಗ ಕಾನ್ಫಿಗರ್ ಮಾಡಬಹುದು).
- ಡೀಫಾಲ್ಟ್ `expires_at`: ರಚನೆಯಿಂದ 30 ದಿನಗಳು.
- ಅವಧಿ ಮುಗಿದ ಅಥವಾ ಬಳಕೆಯ ಮಿತಿ ತಲುಪಿದ ಕೋಡ್ಗಳು HTTP 410 Gone ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತವೆ.

## ಸಮುದಾಯ ಸರ್ವರ್ ಫೆಡರೇಶನ್

**ಫೈಲ್:** `src/lib/gamification/servers.ts`

### ಸಂಪರ್ಕ

ರಿಮೋಟ್ ಸರ್ವರ್ ನೀಡುವ ಆಹ್ವಾನ ಟೋಕನ್ ಮೂಲಕ ಸಮುದಾಯ ಸರ್ವರ್ ಅನ್ನು ನೋಂದಾಯಿಸಲಾಗುತ್ತದೆ. ಸ್ಥಳೀಯ ಇನ್ಸ್ಟೆನ್ಸ್:

1. ಆಹ್ವಾನ ಟೋಕನ್ ಅನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ (ಉದಾ., ಡ್ಯಾಶ್ಬೋರ್ಡ್ಗೆ ಅಂಟಿಸಿದ್ದು).
2. ಟೋಕನ್ ಅನ್ನು ಮೌಲ್ಯೀಕರಿಸಲು ಮತ್ತು ಪ್ರಸ್ತುತ ಲೀಡರ್ಬೋರ್ಡ್ ಅನ್ನು ಪಡೆಯಲು ರಿಮೋಟ್ ಸರ್ವರ್ನಲ್ಲಿ `POST /api/gamification/federation/leaderboard` ಅನ್ನು ಕರೆ ಮಾಡುತ್ತದೆ.
3. ಸರ್ವರ್ ದಾಖಲೆಯನ್ನು `status: connected` ಜೊತೆಗೆ ಸಂಗ್ರಹಿಸುತ್ತದೆ.

### ಸಿಂಕ್ ಮಾದರಿ

ಫೆಡರೇಶನ್ **ಓವರ್ರೈಟ್ ಸಿಂಕ್** ಅನ್ನು ಬಳಸುತ್ತದೆ, ಸಂಕಲನಾತ್ಮಕ ಸಿಂಕ್ ಅಲ್ಲ:

```
ಸ್ಥಳೀಯ ಇನ್ಸ್ಟೆನ್ಸ್                 ಸಮುದಾಯ ಸರ್ವರ್
     │                              │
     ├── ಸ್ಕೋರ್ ಪುಶ್ ──────────────►│  POST /federation/score
     │   { api_key_id, score }      │  (ಸರ್ವರ್ ಟೋಕನ್ ಹ್ಯಾಶ್ ಅನ್ನು ಮೌಲ್ಯೀಕರಿಸುತ್ತದೆ)
     │                              │
     ├── ಲೀಡರ್ಬೋರ್ಡ್ ಪುಲ್ ─────────►│  GET /federation/leaderboard
     │◄── ಅಗ್ರ-N ನಮೂದುಗಳು ─────────┤  (ಸ್ಥಳೀಯ ಕ್ಯಾಶ್ ಅನ್ನು ಓವರ್ರೈಟ್ ಮಾಡುತ್ತದೆ)
     │                              │
     └── ಆರೋಗ್ಯ ಪರಿಶೀಲನೆ ─────────►│  GET /federation/health
         (ಪ್ರತಿ 60s, ಕಾಲಾವಧಿ 5s)    │
```

### ದೃಢೀಕರಣ

ಫೆಡರೇಶನ್ ವಿನಂತಿಗಳು ಇವುಗಳನ್ನು ಒಳಗೊಂಡಿರುತ್ತವೆ:

```
Authorization: Bearer <raw_token>
X-Federation-Version: 1
```

ರಿಮೋಟ್ ಸರ್ವರ್ ಟೋಕನ್ ಅನ್ನು ಹ್ಯಾಶ್ ಮಾಡಿ, ಹೊಂದಾಣಿಕೆಯಾಗುವ `community_servers` ಸಾಲನ್ನು ಹುಡುಕುತ್ತದೆ. ಇದು ಸಂಗ್ರಹಿಸಿದ ಹ್ಯಾಶ್ ಅನ್ನು ರವಾನಿಸುವುದನ್ನು ತಪ್ಪಿಸುತ್ತದೆ.

### ಆರೋಗ್ಯ ಮೇಲ್ವಿಚಾರಣೆ

ಪ್ರತಿಯೊಂದು ಸರ್ವರ್ ದಾಖಲೆಯು ಇವುಗಳನ್ನು ಟ್ರ್ಯಾಕ್ ಮಾಡುತ್ತದೆ:

| ಕ್ಷೇತ್ರ     | ವಿವರಣೆ                                 |
| ----------- | -------------------------------------- |
| `status`    | `connected`, `degraded`, `unreachable` |
| `last_sync` | ಕೊನೆಯ ಯಶಸ್ವಿ ಸಿಂಕ್ನ ISO ಸಮಯಮುದ್ರೆ      |
| `failures`  | ಸತತ ಆರೋಗ್ಯ ಪರಿಶೀಲನೆ ವೈಫಲ್ಯಗಳು          |

ಸತತ 5 ವೈಫಲ್ಯಗಳ ನಂತರ, ಸ್ಥಿತಿಯು `unreachable` ಗೆ ಬದಲಾಗುತ್ತದೆ ಮತ್ತು ಹಸ್ತಚಾಲಿತ ಆರೋಗ್ಯ ಪರಿಶೀಲನೆ ಯಶಸ್ವಿಯಾಗುವವರೆಗೆ ಸಿಂಕ್ ಅನ್ನು ವಿರಾಮಗೊಳಿಸಲಾಗುತ್ತದೆ.

## ವಂಚನೆ-ತಡೆ

**ಫೈಲ್:** `src/lib/gamification/antiCheat.ts`

### ಸರ್ವರ್-ಬದಿಯ ಸ್ಕೋರಿಂಗ್

ಎಲ್ಲಾ XP ಲೆಕ್ಕಾಚಾರಗಳು `src/lib/gamification/xp.ts` ನಲ್ಲಿ ನಡೆಯುತ್ತವೆ. ಕ್ಲೈಂಟ್ಗಳು ಎಂದಿಗೂ ಸ್ಕೋರ್ ಅನ್ನು ಸಲ್ಲಿಸುವುದಿಲ್ಲ — ಅವು ಕ್ರಿಯೆಗಳನ್ನು ಸಲ್ಲಿಸುತ್ತವೆ ಮತ್ತು ಸರ್ವರ್ XP ಅನ್ನು ಲೆಕ್ಕಾಚಾರ ಮಾಡುತ್ತದೆ. `leaderboard.score` ಕಾಲಮ್ ಅನ್ನು ಸರ್ವರ್-ಬದಿಯ ಕೋಡ್ ಮಾತ್ರ ಬರೆಯಬಹುದು.

### ದರ ಮಿತಿಗೊಳಿಸುವಿಕೆ

| ಮಿತಿ                               | ಮೌಲ್ಯ   | ವ್ಯಾಪ್ತಿ         |
| ---------------------------------- | ------- | ---------------- |
| ಪ್ರತಿ ನಿಮಿಷಕ್ಕೆ ಗರಿಷ್ಠ XP          | 1,000   | ಪ್ರತಿ API ಕೀಗೆ   |
| ಪ್ರತಿ ನಿಮಿಷಕ್ಕೆ ಗರಿಷ್ಠ ವರ್ಗಾವಣೆಗಳು | 10      | ಪ್ರತಿ API ಕೀಗೆ   |
| ಗರಿಷ್ಠ ವರ್ಗಾವಣೆ ಮೊತ್ತ              | 10,000  | ಪ್ರತಿ ವರ್ಗಾವಣೆಗೆ |
| ಗರಿಷ್ಠ ದೈನಂದಿನ ವರ್ಗಾವಣೆಗಳು         | 100,000 | ಪ್ರತಿ API ಕೀಗೆ   |

ದರ ಮಿತಿಗಳು ಇನ್-ಮೆಮೊರಿ ಸ್ಲೈಡಿಂಗ್ ವಿಂಡೋವನ್ನು ಬಳಸುತ್ತವೆ (`open-sse/services/` ನಲ್ಲಿನ `RateLimitManager` ಮಾದರಿಯನ್ನೇ ಬಳಸುತ್ತವೆ). ಪ್ರಕ್ರಿಯೆಯು ಮರುಪ್ರಾರಂಭಗೊಂಡರೆ SQLite-ಬೆಂಬಲಿತ ಕೌಂಟರ್ಗಳಿಗೆ ಹಿಂತಿರುಗುತ್ತದೆ.

### Z-ಸ್ಕೋರ್ ಅಸಂಗತತೆ ಪತ್ತೆ

ಪ್ರತಿಯೊಂದು API ಕೀಗಾಗಿ, ಪ್ರತಿ ಗಂಟೆಗೆ ಗಳಿಸಿದ XP ಯ ರೋಲಿಂಗ್ 7-ದಿನಗಳ ವಿಂಡೋವನ್ನು ಸಿಸ್ಟಂ ನಿರ್ವಹಿಸುತ್ತದೆ. ಪ್ರತಿಯೊಂದು XP ಪ್ರದಾನದ ಸಮಯದಲ್ಲಿ:

1. ಬಳಕೆದಾರರ ಪ್ರಸ್ತುತ ಗಂಟೆಯ XP ದರವನ್ನು ಲೆಕ್ಕಾಚಾರ ಮಾಡಿ.
2. ಸಮೂಹದ ಸರಾಸರಿ ಮತ್ತು ಪ್ರಮಾಣಿತ ವಿಚಲನವನ್ನು ಲೆಕ್ಕಾಚಾರ ಮಾಡಿ.
3. `z = (user_rate - mean) / stddev` ಅನ್ನು ಲೆಕ್ಕಾಚಾರ ಮಾಡಿ.
4. `z > 3.0` (3 ಪ್ರಮಾಣಿತ ವಿಚಲನಗಳು) ಆಗಿದ್ದರೆ, ಅದನ್ನು ಅಸಂಗತತೆ ಎಂದು ಗುರುತಿಸಿ.

ಅಸಂಗತತೆಗಳನ್ನು `action = 'anomaly_detected'` ಜೊತೆಗೆ `xp_audit_log` ಗೆ ಲಾಗ್ ಮಾಡಲಾಗುತ್ತದೆ ಮತ್ತು ನಿರ್ವಾಹಕ ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿ ಪ್ರದರ್ಶಿಸಲಾಗುತ್ತದೆ.

### ಆಡಿಟ್ ಟ್ರೇಲ್

ಪ್ರತಿಯೊಂದು XP ಪ್ರದಾನ, ವರ್ಗಾವಣೆ, ಬ್ಯಾಡ್ಜ್ ಗಳಿಕೆ ಮತ್ತು ಅಸಂಗತತೆ ಪತ್ತೆಯನ್ನು `xp_audit_log` ಗೆ ಈ ಕೆಳಗಿನವುಗಳೊಂದಿಗೆ ಲಾಗ್ ಮಾಡಲಾಗುತ್ತದೆ:

| ಕ್ಷೇತ್ರ      | ವಿವರಣೆ                                       |
| ------------ | -------------------------------------------- |
| `api_key_id` | ಯಾರು                                         |
| `action`     | ಏನಾಯಿತು (xp_award, transfer, anomaly, …)     |
| `xp_awarded` | ಮೊತ್ತ (XP ಅಲ್ಲದ ಈವೆಂಟ್ಗಳಿಗೆ 0)               |
| `metadata`   | ಸಂದರ್ಭದೊಂದಿಗೆ JSON (ಕ್ರಿಯೆಯ ಪ್ರಕಾರ, ಗುರಿ, …) |
| `created_at` | ಯಾವಾಗ (ISO 8601)                             |

ನಿರ್ವಾಹಕರು `GET /api/gamification/anomalies` ಮೂಲಕ ಸಂಪೂರ್ಣ ಆಡಿಟ್ ಟ್ರೇಲ್ ಅನ್ನು ಕ್ವೆರಿ ಮಾಡಬಹುದು.

## API ಮಾರ್ಗಗಳು

ಎಲ್ಲಾ ಮಾರ್ಗಗಳು ಪ್ರಮಾಣಿತ OmniRoute ಮಾದರಿಯನ್ನು ಅನುಸರಿಸುತ್ತವೆ:

```
ಮಾರ್ಗ → CORS ಪೂರ್ವಪರಿಶೀಲನೆ → ವಿನಂತಿಯ ವಿಷಯದ ಮೌಲ್ಯಮಾಪನ (Zod) → ದೃಢೀಕರಣ (extractApiKey)
  → ಹ್ಯಾಂಡ್ಲರ್
```

### ಎಂಡ್ಪಾಯಿಂಟ್ಗಳು

| ವಿಧಾನ  | ಮಾರ್ಗ                                      | ವಿವರಣೆ                                           | ದೃಢೀಕರಣ    |
| ------ | ------------------------------------------ | ------------------------------------------------ | ---------- |
| GET    | `/api/gamification/leaderboard`            | ಲೀಡರ್ಬೋರ್ಡ್ ಪಡೆಯಿರಿ (ವ್ಯಾಪ್ತಿ, ಅವಧಿ, ಪುಟವಿಂಗಡಣೆ) | ಐಚ್ಛಿಕ     |

## ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಪುಟಗಳು

### `/dashboard/leaderboard`

- ಪೋಡಿಯಂ ಪ್ರದರ್ಶನ (ಅವತಾರಗಳು ಮತ್ತು XP ಜೊತೆಗೆ ಅಗ್ರ 3).
- ವ್ಯಾಪ್ತಿ ಆಯ್ಕೆಕಾರಕ: ಜಾಗತಿಕ / ಸಾಪ್ತಾಹಿಕ / ಮಾಸಿಕ / ಹಂಚಿಕೊಂಡ ಟೋಕನ್ಗಳು / ಕೊಡುಗೆಗಳು.
- ಶ್ರೇಣಿ, ಹೆಸರು, ಸ್ಕೋರ್, ಹಂತ ಮತ್ತು ಶೀರ್ಷಿಕೆಯೊಂದಿಗೆ ಪುಟೀಕರಿಸಿದ ಕೋಷ್ಟಕ (ಪ್ರತಿ ಪುಟಕ್ಕೆ 25).
- SSE ನೈಜ-ಸಮಯದ ನವೀಕರಣಗಳು — ಶ್ರೇಣಿ ಬದಲಾವಣೆಗಳು ಅನಿಮೇಟ್ ಆಗುತ್ತವೆ.
- ಪ್ರಸ್ತುತ ಬಳಕೆದಾರರನ್ನು ಕೋಷ್ಟಕದಲ್ಲಿ "ನಿಮ್ಮ ಶ್ರೇಣಿ" ಸ್ಥಿರ ಸಾಲಿನೊಂದಿಗೆ ಹೈಲೈಟ್ ಮಾಡಲಾಗುತ್ತದೆ.

### `/dashboard/profile`

- ಪ್ರಸ್ತುತ ಹಂತ ಮತ್ತು ಮುಂದಿನ ಹಂತದ ಮಿತಿಯೊಂದಿಗೆ XP ಪ್ರಗತಿ ಪಟ್ಟಿ.
- ಶೀರ್ಷಿಕೆ ಬ್ಯಾಡ್ಜ್ ಅನ್ನು ಪ್ರಮುಖವಾಗಿ ಪ್ರದರ್ಶಿಸಲಾಗುತ್ತದೆ.
- ಬ್ಯಾಡ್ಜ್ ಗ್ಯಾಲರಿ — ಗಳಿಸಿದ ದಿನಾಂಕದೊಂದಿಗೆ ಗಳಿಸಿದ ಬ್ಯಾಡ್ಜ್ಗಳು, ಗಳಿಸದ ಬ್ಯಾಡ್ಜ್ಗಳನ್ನು ಬೂದು ಬಣ್ಣದಲ್ಲಿ ತೋರಿಸಲಾಗುತ್ತದೆ
  (ಮರೆಮಾಡಿದ ಬ್ಯಾಡ್ಜ್ಗಳನ್ನು ಗಳಿಸುವವರೆಗೆ "???" ಎಂದು ತೋರಿಸಲಾಗುತ್ತದೆ).
- ಜ್ವಾಲೆಯ ಐಕಾನ್ನೊಂದಿಗೆ ಸರಣಿ ಎಣಿಕೆ; ಸರಣಿ ಕ್ಯಾಲೆಂಡರ್ (ಕಳೆದ 30 ದಿನಗಳು).
- XP ಇತಿಹಾಸ ಚಾರ್ಟ್ (ಕಳೆದ 30 ದಿನಗಳ ದೈನಂದಿನ XP).

### `/dashboard/tokens`

- ಟೋಕನ್ ಬ್ಯಾಲೆನ್ಸ್ (ಪ್ರಮುಖವಾಗಿ, ಪುಟದ ಮೇಲ್ಭಾಗದಲ್ಲಿ).
- ವರ್ಗಾವಣೆ ಫಾರ್ಮ್: ಸ್ವೀಕರಿಸುವವರು, ಮೊತ್ತ, ದೃಢೀಕರಣ ಸಂವಾದ.
- ಫಿಲ್ಟರ್ಗಳೊಂದಿಗೆ ವರ್ಗಾವಣೆ ಇತಿಹಾಸ ಕೋಷ್ಟಕ (ಕಳುಹಿಸಿದ/ಸ್ವೀಕರಿಸಿದ/ಎಲ್ಲಾ).
- ಆಹ್ವಾನ ವಿಭಾಗ: ಸಕ್ರಿಯ ಕೋಡ್ಗಳು, ಹೊಸದನ್ನು ರಚಿಸುವುದು, ಲಿಂಕ್ ಹಂಚಿಕೊಳ್ಳುವುದು.
- ಸಮುದಾಯ ಸರ್ವರ್ಗಳು: ಆರೋಗ್ಯ ಸ್ಥಿತಿಯೊಂದಿಗೆ ಪಟ್ಟಿ, ಸಂಪರ್ಕಿಸಿ/ಸಂಪರ್ಕ ಕಡಿತಗೊಳಿಸಿ.

### `/dashboard/gamification/admin`

- ತೀವ್ರತೆ, ಬಳಕೆದಾರ, ಸಮಯಮುದ್ರೆ ಮತ್ತು z-ಸ್ಕೋರ್ನೊಂದಿಗೆ ಅಸಂಗತತೆ ಪಟ್ಟಿ.
- ಫಿಲ್ಟರ್ಗಳೊಂದಿಗೆ ಆಡಿಟ್ ಲಾಗ್ ವೀಕ್ಷಕ (ಕ್ರಿಯೆಯ ಪ್ರಕಾರ, ಬಳಕೆದಾರ, ದಿನಾಂಕ ವ್ಯಾಪ್ತಿ).
- ಸಿಸ್ಟಂ ಅಂಕಿಅಂಶಗಳು: ನೀಡಲಾದ ಒಟ್ಟು XP, ಸಕ್ರಿಯ ಬಳಕೆದಾರರು, ಬ್ಯಾಡ್ಜ್ ಗಳಿಕೆ ದರಗಳು.
- ಫೆಡರೇಶನ್ ಸರ್ವರ್ ಆರೋಗ್ಯದ ಅವಲೋಕನ.

## ಪೈಪ್ಲೈನ್ ಏಕೀಕರಣ

### ಏಕೀಕರಣ ಬಿಂದು

ಗೇಮಿಫಿಕೇಶನ್ ವಿನಂತಿ ಪೈಪ್ಲೈನ್ನ `open-sse/handlers/chatCore.ts` ನಲ್ಲಿರುವ ಒಂದೇ ಬಿಂದುವಿನಲ್ಲಿ
ಸಂಪರ್ಕಗೊಳ್ಳುತ್ತದೆ:

```typescript
// ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಕ್ಲೈಂಟ್ಗೆ ಕಳುಹಿಸಿದ ನಂತರ:
setImmediate(() => {
  emitGamificationEvent({
    type: "request.completed",
    apiKeyId,
    metadata: {
      provider: selectedProvider,
      model: selectedModel,
      comboId: resolvedCombo?.id,
      compressionUsed: compressionStats?.applied,
      skillUsed: skillExecution?.name,
    },
  }).catch(() => {
    // ಕಳುಹಿಸಿ-ಮರೆತುಬಿಡಿ: ಲಾಗ್ ಮಾಡಿ, ಆದರೆ ಎಂದಿಗೂ ಕ್ಲೈಂಟ್ಗೆ ಪ್ರಸಾರ ಮಾಡಬೇಡಿ
  });
});
```

### ಈವೆಂಟ್ ಪ್ರಕಾರಗಳು

| ಈವೆಂಟ್ ಪ್ರಕಾರ       | ಯಾವಾಗ ಹೊರಸೂಸಲಾಗುತ್ತದೆ                                      |
| ------------------- | ---------------------------------------------------------- |
| `request.completed` | ಯಶಸ್ವಿ LLM ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಕಳುಹಿಸಿದಾಗ                     |
| `provider.switch`   | ಪೂರೈಕೆದಾರರು ಬದಲಾದಾಗ (ಕಾಂಬೊ ಫಾಲ್ಬ್ಯಾಕ್ಗಳನ್ನೂ ಎಣಿಸಲಾಗುತ್ತದೆ) |
| `combo.created`     | ಹೊಸ ಕಾಂಬೊ ಸಂರಚನೆಯನ್ನು ಉಳಿಸಿದಾಗ                             |
| `combo.used`        | ಕಾಂಬೊ ಗುರಿಯನ್ನು ಯಶಸ್ವಿಯಾಗಿ ತಲುಪಿದಾಗ                        |
| `badge.earned`      | ಬ್ಯಾಡ್ಜ್ ಮೌಲ್ಯಮಾಪನವು ಹೊಂದಾಣಿಕೆಯನ್ನು ಕಂಡಾಗ                  |
| `streak.milestone`  | ಸರಣಿ ಮಿತಿಯನ್ನು ದಾಟಿದಾಗ                                     |
| `transfer.sent`     | ಟೋಕನ್ ವರ್ಗಾವಣೆ ಪೂರ್ಣಗೊಂಡಾಗ                                 |
| `referral.redeemed` | ಆಹ್ವಾನ ಕೋಡ್ ಅನ್ನು ಯಶಸ್ವಿಯಾಗಿ ಬಳಸಿದಾಗ                       |
| `compression.used`  | ಪ್ರಾಂಪ್ಟ್ ಸಂಕುಚನವನ್ನು ಅನ್ವಯಿಸಿದಾಗ                          |
| `skill.executed`    | ಕೌಶಲ್ಯ ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆ ಪೂರ್ಣಗೊಂಡಾಗ                       |
| `model.first_use`   | ಕಳೆದ 7 ದಿನಗಳಲ್ಲಿ ಮಾಡೆಲ್ ಅನ್ನು ಬಳಸದೇ ಇದ್ದಾಗ                 |

### ತಡೆಯದಿರುವಿಕೆಯ ಖಾತರಿ

`setImmediate` + `.catch(() => {})` ಮಾದರಿಯು ಇವುಗಳನ್ನು ಖಚಿತಪಡಿಸುತ್ತದೆ:

1. ಗೇಮಿಫಿಕೇಶನ್ ಚಾಲನೆಯಾಗುವ ಮೊದಲು ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಸಂಪೂರ್ಣವಾಗಿ ಕಳುಹಿಸಲಾಗುತ್ತದೆ.
2. ಗೇಮಿಫಿಕೇಶನ್ ದೋಷಗಳು ಎಂದಿಗೂ ಕ್ಲೈಂಟ್ಗೆ ಕಾಣಿಸುವುದಿಲ್ಲ.
3. ಈವೆಂಟ್ ಪ್ರಕ್ರಿಯೆಯು ಇನ್ಲೈನ್ನಲ್ಲಿ ಅಲ್ಲದೆ ಮುಂದಿನ ಮೈಕ್ರೋಟಾಸ್ಕ್ನಲ್ಲಿ ಚಾಲನೆಯಾಗುತ್ತದೆ.

### ದೃಢೀಕರಣದ ಅವಶ್ಯಕತೆಗಳು

- **ಸಾರ್ವಜನಿಕ** (ದೃಢೀಕರಣವಿಲ್ಲ): `GET /leaderboard`, `GET /stream` (ಓದಲು ಮಾತ್ರವಾದ
  ಲೀಡರ್ಬೋರ್ಡ್ಗಳು).
- **API ಕೀ ಅಗತ್ಯವಿದೆ**: ಎಲ್ಲಾ ಬರವಣಿಗೆ ಕಾರ್ಯಾಚರಣೆಗಳು, ಪ್ರೊಫೈಲ್, ವರ್ಗಾವಣೆಗಳು, ಆಹ್ವಾನಗಳು.
- **ನಿರ್ವಾಹಕರಿಗೆ ಮಾತ್ರ**: ಅಸಂಗತತೆ ಡ್ಯಾಶ್ಬೋರ್ಡ್, ಆಡಿಟ್ ಲಾಗ್ ವೀಕ್ಷಕ.
- **ಫೆಡರೇಶನ್**: `Authorization` ಹೆಡರ್ನಲ್ಲಿ ಮೂಲ ಟೋಕನ್ ಬಳಸುವ ಪ್ರತ್ಯೇಕ ದೃಢೀಕರಣ ಮಾರ್ಗ,
  ಸಂಗ್ರಹಿಸಿದ SHA-256 ಹ್ಯಾಶ್ನೊಂದಿಗೆ ಮೌಲ್ಯೀಕರಿಸಲಾಗುತ್ತದೆ.

- **ಲೀಡರ್ಬೋರ್ಡ್ API**: ಮೂರನೇ-ಪಕ್ಷದ ಏಕೀಕರಣಗಳಿಗಾಗಿ ಸಾರ್ವಜನಿಕ API.
