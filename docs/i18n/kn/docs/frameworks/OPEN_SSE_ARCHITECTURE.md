> **TL;DR**: `open-sse/` ಎಂಬುದು OmniRouteನ ಪ್ರತಿಯೊಂದು LLM ವಿನಂತಿಗೂ ಶಕ್ತಿ ನೀಡುವ ಪ್ರಮುಖ ಸ್ಟ್ರೀಮಿಂಗ್ ಎಂಜಿನ್ ಆಗಿದೆ. ಇದು ವಿನಂತಿ ಪೈಪ್ಲೈನ್, ಎಕ್ಸಿಕ್ಯೂಟರ್ಗಳು, ಸೇವೆಗಳು, MCP ಸರ್ವರ್ ಮತ್ತು ಅನುವಾದ ಪದರವನ್ನು ಅನುಷ್ಠಾನಗೊಳಿಸುವ ~1,400 ಫೈಲ್ಗಳನ್ನು ಒಳಗೊಂಡಿದೆ. ಈ ಮಾರ್ಗದರ್ಶಿ ಈ ಘಟಕಗಳು ಹೇಗೆ ಒಟ್ಟಿಗೆ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತವೆ ಎಂಬುದನ್ನು ವಿವರಿಸುತ್ತದೆ.

**ಮೂಲ:** `open-sse/` (ವರ್ಕ್ಸ್ಪೇಸ್ ಪ್ಯಾಕೇಜ್, ~1,440 ಪರೀಕ್ಷೆಯೇತರ `.ts` ಫೈಲ್ಗಳು)

## ಪ್ರತ್ಯೇಕ ವರ್ಕ್ಸ್ಪೇಸ್ ಪ್ಯಾಕೇಜ್ ಏಕೆ?

ಹಲವಾರು ಕಾರಣಗಳಿಗಾಗಿ `open-sse/` OmniRoute ಮೊನೊರೆಪೊದಲ್ಲಿನ **ಸ್ವತಂತ್ರ ವರ್ಕ್ಸ್ಪೇಸ್** ಆಗಿದೆ:

1. **ಮರುಬಳಕೆ** — `open-sse` ಅನ್ನು npm ನಲ್ಲಿ `@omniroute/open-sse` ಆಗಿ ಪ್ರಕಟಿಸಲಾಗುತ್ತದೆ, ಆದ್ದರಿಂದ ಇತರ ಪ್ರಾಜೆಕ್ಟ್ಗಳು ಅದನ್ನು ಸ್ವತಂತ್ರವಾಗಿ ಬಳಸಬಹುದು
2. **ಸ್ಪಷ್ಟ ಗಡಿಗಳು** — ಸ್ಟ್ರೀಮಿಂಗ್ ಎಂಜಿನ್ ಅನ್ನು OmniRoute-ನಿರ್ದಿಷ್ಟ UI/DB ಪದರದಿಂದ ಬೇರ್ಪಡಿಸಲಾಗಿದೆ
3. **ಕಾರ್ಯಕ್ಷಮತೆ** — ಎಂಜಿನ್ ಯಾವುದೇ Next.js ಅವಲಂಬನೆಗಳನ್ನು ಹೊಂದಿಲ್ಲ, ಹೀಗಾಗಿ CLI/serverless ಸಂದರ್ಭಗಳಲ್ಲಿ ವೇಗವಾದ ಕೋಲ್ಡ್ ಸ್ಟಾರ್ಟ್ಗಳನ್ನು ಸಾಧ್ಯವಾಗಿಸುತ್ತದೆ
4. **ಆವೃತ್ತಿ ನಿರ್ವಹಣೆ** — `open-sse` ತನ್ನದೇ ವೇಳಾಪಟ್ಟಿಗೆ ಅನುಗುಣವಾಗಿ ಬಿಡುಗಡೆಗಳನ್ನು ಮಾಡಬಹುದು

```json
// package.json
"workspaces": ["open-sse"]
```

## ವಿನಂತಿ ಪೈಪ್ಲೈನ್

ಪ್ರತಿಯೊಂದು LLM ವಿನಂತಿಯೂ **5-ಹಂತದ ಪೈಪ್ಲೈನ್** ಮೂಲಕ ಸಾಗುತ್ತದೆ:

```
   (Next.js ರೂಟ್)             └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  2. ಅನುವಾದ   │   ಸ್ವರೂಪ ಪರಿವರ್ತನೆ (OpenAI ↔ Claude ↔ Gemini)
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  3. ಕಾರ್ಯಗತ  │   ಪ್ರೊವೈಡರ್ ಎಕ್ಸಿಕ್ಯೂಟರ್, HTTP, ಮರುಪ್ರಯತ್ನ, ಬ್ರೇಕರ್
                              └──────┬───────┘

                              └──────┬───────┘
```

### ಹಂತ 1: ರೂಟ್ (services/combo.ts)

**ಪ್ರವೇಶ ಬಿಂದು**: `services/combo.ts` ನಲ್ಲಿನ `handleComboChat()`

ವಿನಂತಿಯನ್ನು ನಿರ್ದಿಷ್ಟ `(provider, model, account, credentials)` ಟ್ಯೂಪಲ್ಗೆ ನಿರ್ಧರಿಸುತ್ತದೆ:

- ID ಮೂಲಕ ಕಾಂಬೊವನ್ನು ಹುಡುಕಿ (ಅಥವಾ `auto/*` ಮಾದರಿಗಳಿಗಾಗಿ ವರ್ಚುವಲ್ ಕಾಂಬೊ ನಿರ್ಮಿಸಿ)
- ರೂಟಿಂಗ್ ತಂತ್ರವನ್ನು ಅನ್ವಯಿಸಿ (ಆದ್ಯತೆ, ತೂಕಾಧಾರಿತ, ರೌಂಡ್-ರಾಬಿನ್, ಇತ್ಯಾದಿ)
- ಅಸ್ವಸ್ಥ ಪ್ರೊವೈಡರ್ಗಳನ್ನು ಹೊರಗಿಡಿ (ಸರ್ಕ್ಯೂಟ್ ಬ್ರೇಕರ್)
- ಮುಂದಿನ ಕಾರ್ಯಸಾಧ್ಯ ಗುರಿಯನ್ನು ಆಯ್ಕೆಮಾಡಿ

`auto/*` ಮಾದರಿಗಳಿಗಾಗಿ, ಈ ಹಂತವು ಇವುಗಳನ್ನೂ ಮಾಡುತ್ತದೆ:

- **16-ಅಂಶಗಳ ಸ್ಕೋರಿಂಗ್** ಅಲ್ಗಾರಿದಮ್ ಅನ್ನು ಚಲಾಯಿಸುತ್ತದೆ (`services/autoCombo/`)
- ಆರೋಗ್ಯ, ವೆಚ್ಚ, ಲೇಟೆನ್ಸಿ ಮುಂತಾದವುಗಳ ಆಧಾರದ ಮೇಲೆ `provider+model` ಜೋಡಿಯನ್ನು ಆಯ್ಕೆಮಾಡುತ್ತದೆ

### ಹಂತ 2: ಅನುವಾದ (translator/)

ಮೂಲ ಸ್ವರೂಪವು (ಉದಾ., OpenAI) ಗುರಿ ಸ್ವರೂಪದಿಂದ (ಉದಾ., Claude) ಭಿನ್ನವಾಗಿದ್ದರೆ, ವಿನಂತಿಯನ್ನು **ಅನುವಾದಿಸಲಾಗುತ್ತದೆ**:

- ಸಿಸ್ಟಮ್ ಪ್ರಾಂಪ್ಟ್ → ಸಿಸ್ಟಮ್ ಸಂದೇಶ
- ಟೂಲ್ ವ್ಯಾಖ್ಯಾನಗಳು → ಪ್ರೊವೈಡರ್-ನಿರ್ದಿಷ್ಟ ಟೂಲ್ ಸ್ವರೂಪ
- ರೀಸನಿಂಗ್/ಥಿಂಕಿಂಗ್ ನಿಯತಾಂಕಗಳು → ಪ್ರೊವೈಡರ್-ನಿರ್ದಿಷ್ಟ ಸಮಾನಾರ್ಥಕಗಳು
- ಸಂದೇಶ ಪಾತ್ರದ ಸಾಮಾನ್ಯೀಕರಣ (OpenAI ಅಲ್ಲದವುಗಳಿಗಾಗಿ `developer` → `system`)

`translator/index.ts` ಇವುಗಳನ್ನು ಒದಗಿಸುತ್ತದೆ:

```ts
translateRequest(body, sourceFormat, targetFormat): TranslatedRequest
needsTranslation(source, target): boolean
```

### ಹಂತ 3: ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆ (executors/)

**ಪ್ರವೇಶ ಬಿಂದು**: `getExecutor(providerId).execute(request, options)`

ಎಲ್ಲಾ ಪ್ರೊವೈಡರ್ಗಳು `getExecutor()` ಫ್ಯಾಕ್ಟರಿಯ ಫಾಲ್ಬ್ಯಾಕ್ ಮೂಲಕ `DefaultExecutor` (`executors/default.ts`) ಅನ್ನು ಬಳಸುತ್ತವೆ. ಎಕ್ಸಿಕ್ಯೂಟರ್:

- ಅಪ್ಸ್ಟ್ರೀಮ್ URL ಅನ್ನು ನಿರ್ಮಿಸುತ್ತದೆ (`buildUrl()`)
- ಪ್ರೊವೈಡರ್-ನಿರ್ದಿಷ್ಟ ಹೆಡರ್ಗಳನ್ನು ಸೇರಿಸುತ್ತದೆ (`buildHeaders()`)
- ವಿನಂತಿಯ ಬಾಡಿಯನ್ನು ಪರಿವರ್ತಿಸುತ್ತದೆ (`transformRequest()`)
- ಮರುಪ್ರಯತ್ನ + ಎಕ್ಸ್ಪೊನೆನ್ಷಿಯಲ್ ಬ್ಯಾಕ್ಆಫ್ನೊಂದಿಗೆ HTTP ವಿನಂತಿಯನ್ನು ಕಳುಹಿಸುತ್ತದೆ
- ಅಗತ್ಯವಿದ್ದರೆ ದೃಢೀಕರಣವನ್ನು ರಿಫ್ರೆಶ್ ಮಾಡುತ್ತದೆ (OAuth ಪ್ರೊವೈಡರ್ಗಳು)

ಎಲ್ಲಾ ಎಕ್ಸಿಕ್ಯೂಟರ್ಗಳು `BaseExecutor` (`executors/base.ts`, 1170 LOC) ಅನ್ನು ವಿಸ್ತರಿಸುತ್ತವೆ, ಇದು ಇವುಗಳನ್ನು ಒದಗಿಸುತ್ತದೆ:

- ಸಾಮಾನ್ಯ ಮರುಪ್ರಯತ್ನ ತರ್ಕ
- ಪ್ರಾಕ್ಸಿ ಏಕೀಕರಣ
- ಸರ್ಕ್ಯೂಟ್ ಬ್ರೇಕರ್ ಏಕೀಕರಣ
- ಬಳಕೆ ದಾಖಲಿಸುವ ಹುಕ್ಗಳು

### ಹಂತ 4: ಸ್ಟ್ರೀಮ್ (utils/stream.ts)

ಸ್ಟ್ರೀಮಿಂಗ್ ಪ್ರತಿಕ್ರಿಯೆಗಳಿಗಾಗಿ, ಎಕ್ಸಿಕ್ಯೂಟರ್ ಒಂದು **ReadableStream** ಅನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ. ಹ್ಯಾಂಡ್ಲರ್:

- SSE ಟ್ರಾನ್ಸ್ಫಾರ್ಮ್ ಮೂಲಕ ಪೈಪ್ ಮಾಡುತ್ತದೆ (`createSSETransformStreamWithLogger`)
- ನಿಷ್ಕ್ರಿಯ ಸಂಪರ್ಕಗಳನ್ನು ಪತ್ತೆಹಚ್ಚಲು ಹಾರ್ಟ್ಬೀಟ್ ಪಿಂಗ್ಗಳನ್ನು ಅನ್ವಯಿಸುತ್ತದೆ
- ಕ್ಲೈಂಟ್ ಸಂಪರ್ಕ ಕಡಿತವನ್ನು ಸಮರ್ಪಕವಾಗಿ ನಿರ್ವಹಿಸುತ್ತದೆ (`pipeWithDisconnect`)
- ಸ್ಟ್ರೀಮಿಂಗ್ ಅಲ್ಲದ ಕ್ಲೈಂಟ್ಗಳಿಗಾಗಿ SSE → JSON ಅನ್ನು ಪರಿವರ್ತಿಸುತ್ತದೆ

ಸ್ಟ್ರೀಮಿಂಗ್ ಅಲ್ಲದ ಪ್ರತಿಕ್ರಿಯೆಗಳಿಗಾಗಿ, ಎಕ್ಸಿಕ್ಯೂಟರ್ ಪಾರ್ಸ್ ಮಾಡಿದ JSON ಆಬ್ಜೆಕ್ಟ್ ಅನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ ಮತ್ತು ಅದನ್ನು ಯಾವುದೇ ಬದಲಾವಣೆಯಿಲ್ಲದೆ ರವಾನಿಸಲಾಗುತ್ತದೆ.

### ಹಂತ 5: ದಾಖಲೆ (services/usage.ts)

ಪ್ರತಿಕ್ರಿಯೆಯ ನಂತರ (ಯಶಸ್ಸು ಅಥವಾ ವೈಫಲ್ಯ), ಬಳಕೆಯನ್ನು ದಾಖಲಿಸಲಾಗುತ್ತದೆ:

- ಪ್ರತಿಕ್ರಿಯೆಯಿಂದ `prompt_tokens`, `completion_tokens`, `cached_tokens`
- ಬೆಲೆ ನಿಗದಿ ದತ್ತಾಂಶದಿಂದ ಲೆಕ್ಕಹಾಕಿದ `cost_usd`
- ವಿಫಲವಾದಲ್ಲಿ `latency_ms`, `status`, `error_class`
- `usage_history` ಕೋಷ್ಟಕದಲ್ಲಿ ಉಳಿಸಲಾಗುತ್ತದೆ

ಕಾಲ್ ಲಾಗ್ ಆರ್ಟಿಫ್ಯಾಕ್ಟ್ಗಳನ್ನು (ಸಕ್ರಿಯಗೊಳಿಸಿದ್ದರೆ) `${DATA_DIR}/call_logs/` ಗೆ ಬರೆಯಲಾಗುತ್ತದೆ.

### chatCore.ts (5977 ಸಾಲುಗಳು)

**ಮುಖ್ಯ ವಿನಂತಿ ಹ್ಯಾಂಡ್ಲರ್**. ಇದರ ಗಾತ್ರ ದೊಡ್ಡದಾಗಿದ್ದರೂ, ಇದು ಸ್ಪಷ್ಟವಾದ ರಚನೆಯನ್ನು ಹೊಂದಿದೆ:

```ts
// chatCore.ts ನ ಹುಸಿ-ರಚನೆ
export async function handleChat(request: NextRequest) {
  // 1. ದೃಢೀಕರಣ + CORS
  await authenticateRequest(request);
  applyCorsHeaders(response);

  // 2. ಬಾಡಿ ಮೌಲ್ಯೀಕರಣ
  const body = await parseRequestBody(request);

  // 3. ಸ್ವರೂಪ ಪತ್ತೆ + ಅನುವಾದ
  const sourceFormat = detectFormat(request);
  const targetFormat = getTargetFormat(providerId);
  if (needsTranslation(sourceFormat, targetFormat)) {
    body = translateRequest(body, sourceFormat, targetFormat);
  }

  // 4. ಕಾಂಬೊ ರೂಟಿಂಗ್
  const targets = await resolveComboTargets(comboId, body);
  for (const target of targets) {
    try {
      const result = await executeOnTarget(target, body);
      await recordUsage(result);
      return result;
    } catch (err) {
      // ಮುಂದಿನ ಗುರಿಗೆ ಮುಂದುವರಿಯಿರಿ
    }
  }

  // 5. ತುರ್ತು ಫಾಲ್ಬ್ಯಾಕ್
  return await emergencyFallback(body);
}
```

ಇದು ಒಂದು ಬೃಹತ್ ಫಂಕ್ಷನ್ ಆಗಿದ್ದರೂ, 5-ಹಂತದ ಪೈಪ್ಲೈನ್ಗೆ ಹೊಂದಿಕೆಯಾಗುವಂತೆ **ಕಾಮೆಂಟ್ಗಳನ್ನು ಹೊಂದಿರುವ ವಿಭಾಗಗಳಾಗಿ** ಸಂಘಟಿಸಲಾಗಿದೆ.

### base.ts (1170 LOC)

ಎಲ್ಲಾ 107 ಎಕ್ಸಿಕ್ಯೂಟರ್ಗಳು ವಿಸ್ತರಿಸುವ **ಅಮೂರ್ತ ಎಕ್ಸಿಕ್ಯೂಟರ್**. ಇದು ಇವುಗಳನ್ನು ಒಳಗೊಂಡಿದೆ:

- `execute()` — ಮರುಪ್ರಯತ್ನ/ಬ್ಯಾಕ್ಆಫ್/ಬ್ರೇಕರ್ ಹೊಂದಿರುವ ಮುಖ್ಯ HTTP ಲೂಪ್

````
## ಎಕ್ಸಿಕ್ಯೂಟರ್ಗಳು (75+ ಫೈಲ್ಗಳು)

ಪ್ರತಿ ಪ್ರೊವೈಡರ್ಗೆ ಒಂದು ಫೈಲ್. ಅವೆಲ್ಲವೂ `BaseExecutor` ಅನ್ನು ವಿಸ್ತರಿಸುತ್ತವೆ ಮತ್ತು ಭಿನ್ನವಾಗಿರುವ ಅಂಶಗಳನ್ನು ಓವರ್ರೈಡ್ ಮಾಡುತ್ತವೆ.

### ಸಾಮಾನ್ಯ ಮಾದರಿಗಳು

ಪ್ರೊವೈಡರ್ಗಳನ್ನು `getExecutor(providerId)` ಮೂಲಕ ಪರಿಹರಿಸಲಾಗುತ್ತದೆ; ಇದು ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾದ ಎಕ್ಸಿಕ್ಯೂಟರ್ ಅನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ. OpenAI/Anthropic-ಹೊಂದಾಣಿಕೆಯ ಪ್ರೊವೈಡರ್ಗಳು `DefaultExecutor` (`executors/default.ts`) ಅನ್ನು ಬಳಸುತ್ತವೆ. ಪ್ರೊವೈಡರ್-ನಿರ್ದಿಷ್ಟ ವರ್ತನೆಯನ್ನು (ಮೂಲ URL, ದೃಢೀಕರಣ ಹೆಡರ್ಗಳು, API ಆವೃತ್ತಿ) `open-sse/config/providers/` ನಲ್ಲಿ ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾಗುತ್ತದೆ, ಹಾಗೆಯೇ ವಿನಂತಿಯ ಬಾಡಿ ರೂಪಾಂತರಗಳನ್ನು `open-sse/translator/` ನಲ್ಲಿ ನಿರ್ವಹಿಸಲಾಗುತ್ತದೆ.

**ಕಸ್ಟಮ್ URL** ಅನ್ನು ಪ್ರೊವೈಡರ್ ಕಾನ್ಫಿಗರೇಶನ್ ಮೂಲಕ ಹೊಂದಿಸಲಾಗುತ್ತದೆ:

```ts
// open-sse/config/providers/ ನಲ್ಲಿರುವ ಪ್ರೊವೈಡರ್ ಕಾನ್ಫಿಗ್
export default {
  id: "together",
  baseURL: "https://api.together.xyz/v1/chat/completions",
}
````

**ಕಸ್ಟಮ್ ದೃಢೀಕರಣವನ್ನು** ಪ್ರೊವೈಡರ್ ರಿಜಿಸ್ಟ್ರಿಯ ದೃಢೀಕರಣ ಕಾನ್ಫಿಗರೇಶನ್ (API ಕೀ, OAuth, ಹೆಡರ್ ಪ್ರೊಫೈಲ್ಗಳು) ಮೂಲಕ ನಿರ್ವಹಿಸಲಾಗುತ್ತದೆ.

**ಕಸ್ಟಮ್ ವಿನಂತಿ ಬಾಡಿ** ರೂಪಾಂತರಗಳನ್ನು (ಉದಾ., Anthropic `system` ಅನ್ನು `messages` ನಿಂದ ಪ್ರತ್ಯೇಕಿಸುವುದು) ಪ್ರತಿ ಪ್ರೊವೈಡರ್ಗೆ `open-sse/translator/` ನಲ್ಲಿ ನೋಂದಾಯಿಸಲಾಗುತ್ತದೆ.

````

### ಎಕ್ಸಿಕ್ಯೂಟರ್ ಫ್ಯಾಕ್ಟರಿ

`executors/index.ts`, `getExecutor(providerId)` ಅನ್ನು ಎಕ್ಸ್ಪೋರ್ಟ್ ಮಾಡುತ್ತದೆ:

```ts
import { getExecutor } from "@omniroute/open-sse/executors";

const executor = getExecutor("anthropic");
const result = await executor.execute({
  model: "claude-sonnet-4-5",
  messages: [...],
});
````

ಪರಿಹಾರ ಪ್ರಕ್ರಿಯೆಯು `ExecutorRegistry` (`executors/registry.ts`) ಮೂಲಕ ಸಾಗುತ್ತದೆ: ಪ್ರತಿಯೊಂದು ವಿಶೇಷೀಕೃತ ಎಕ್ಸಿಕ್ಯೂಟರ್ ಅನ್ನು `executors/index.ts` ನ ಅಂತರ್ನಿರ್ಮಿತ ಕೋಷ್ಟಕದಲ್ಲಿ ಘೋಷಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಮಾಡ್ಯೂಲ್ ಲೋಡ್ ಆಗುವಾಗ `registerExecutor(alias, instance)` ಮೂಲಕ ನೋಂದಾಯಿಸಲಾಗುತ್ತದೆ; `getExecutor()` ರಿಜಿಸ್ಟ್ರಿಯನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ ಮತ್ತು ವಿಶೇಷೀಕೃತ ನಮೂದು ಇಲ್ಲದ ಯಾವುದೇ ಪ್ರೊವೈಡರ್ಗಾಗಿ ಮೆಮೊಯೈಸ್ ಮಾಡಲಾದ `DefaultExecutor` ಗೆ ಫಾಲ್ಬ್ಯಾಕ್ ಆಗುತ್ತದೆ. ಸಂಪೂರ್ಣ ಅಲಿಯಾಸ್ → ಎಕ್ಸಿಕ್ಯೂಟರ್ ಮ್ಯಾಪಿಂಗ್ ಅನ್ನು ಗೋಲ್ಡನ್ ಟೆಸ್ಟ್ `tests/unit/executor-map-golden.test.ts` ನಿರೂಪಿಸುತ್ತದೆ.

## ಅನುವಾದಕಗಳು

**3 ಸ್ವರೂಪಗಳ** ನಡುವೆ ಅನುವಾದಿಸಿ: OpenAI, Anthropic, Gemini, ಜೊತೆಗೆ ಹೊಸ Responses API.

### ಅನುವಾದ ಯಾವಾಗ ನಡೆಯುತ್ತದೆ

```ts
import { needsTranslation, translateRequest } from "@omniroute/open-sse/translator";

if (needsTranslation(sourceFormat, targetFormat)) {
  body = translateRequest(body, sourceFormat, targetFormat);
}
```

ಸಾಮಾನ್ಯ ಅನುವಾದಗಳು:

- `OpenAI → Anthropic`: ಪ್ರತ್ಯೇಕ `system` ಕ್ಷೇತ್ರ, `x-api-key` ಹೆಡರ್
- `OpenAI → Gemini`: `messages` ಬದಲಿಗೆ `contents`, `systemInstruction`
- `OpenAI → Responses API`: `input` ಅರೆ, `previous_response_id` ಸ್ಥಿತಿ

### ನಿರ್ವಹಿಸಲಾಗುವ ವಿಶೇಷ ಸಂದರ್ಭಗಳು

- `developer` ಪಾತ್ರ → OpenAI ಅಲ್ಲದವುಗಳಿಗೆ `system`
- `system` ಪಾತ್ರ → GLM/ERNIE ಗಾಗಿ ಮೊದಲ ಬಳಕೆದಾರ ಸಂದೇಶದೊಂದಿಗೆ ವಿಲೀನಗೊಳಿಸಲಾಗುತ್ತದೆ
- `json_schema` → Gemini ಯ `responseMimeType` + `responseSchema`
- `tools` → ಪೂರೈಕೆದಾರ-ನಿರ್ದಿಷ್ಟ ಉಪಕರಣ ಸ್ವರೂಪ
- ಚಿಂತನಾ ನಿಯತಾಂಕಗಳು (o1, Claude) → ಪೂರೈಕೆದಾರ-ನಿರ್ದಿಷ್ಟ ಸಮಾನಾರ್ಥಕಗಳು

## MCP ಸರ್ವರ್

`open-sse/mcp-server/` **Model Context Protocol** ಸರ್ವರ್ ಅನ್ನು ಅನುಷ್ಠಾನಗೊಳಿಸುತ್ತದೆ:

- **110 ಉಪಕರಣಗಳು** (ಪೂರೈಕೆದಾರ ನಿರ್ವಹಣೆ, ಸಂಯೋಜನೆಗಳು, ಮೆಮೊರಿ, ಕ್ಯಾಶ್, ಸಂಕೋಚನ, ಪ್ರಾಕ್ಸಿ, ಕೌಶಲ್ಯಗಳು, ಗೇಮಿಫಿಕೇಶನ್, ಪ್ಲಗಿನ್ಗಳು, Notion, Obsidian, ಸ್ಥಳೀಯ ಕಾರ್ಪಸ್)
- **3 ಸಾರಿಗೆಗಳು**: stdio, SSE, Streamable HTTP
- ಸೂಕ್ಷ್ಮ-ಮಟ್ಟದ ಅಧಿಕಾರ ನೀಡುವಿಕೆಗಾಗಿ **33 ವ್ಯಾಪ್ತಿಗಳು**

### ಉಪಕರಣ ನೋಂದಣಿ

ಉಪಕರಣಗಳನ್ನು `open-sse/mcp-server/tools/` ನಲ್ಲಿ ಸ್ವತಂತ್ರ ಫೈಲ್ಗಳಾಗಿ ನೋಂದಾಯಿಸಲಾಗುತ್ತದೆ; ಪ್ರತಿಯೊಂದೂ ಹೆಸರು, ಸ್ಕೀಮಾ, ಹ್ಯಾಂಡ್ಲರ್ ಮತ್ತು ವ್ಯಾಪ್ತಿಯನ್ನು ರಫ್ತು ಮಾಡುತ್ತದೆ:

```ts
// open-sse/mcp-server/tools/getHealth.ts
import { z } from "zod";
export default {
  name: "omniroute_get_health",
  description: "ಸಿಸ್ಟಮ್ ಆರೋಗ್ಯದ ಸ್ನ್ಯಾಪ್ಶಾಟ್ ಪಡೆಯಿರಿ",
  scope: "read:health",
  inputSchema: z.object({}),
  handler: async (_args, ctx) => {
    return await getSystemHealth();
  },
};
```

### ಸಾರಿಗೆಗಳು

```ts
// stdio (CLI ಬಳಕೆ)
startMcpStdio(server);

// SSE (HTTP-ಆಧಾರಿತ ಸ್ಟ್ರೀಮಿಂಗ್)
startMcpSse(server, port);

// Streamable HTTP (ಆಧುನಿಕ MCP)
startMcpStreamable(server, port);
```

### ಅಧಿಕಾರ ನೀಡುವಿಕೆ

ಪ್ರತಿ ಉಪಕರಣದ ಕರೆ ವ್ಯಾಪ್ತಿ ಪರಿಶೀಲನೆಗಳ ಮೂಲಕ ಸಾಗುತ್ತದೆ (`open-sse/mcp-server/auth/`):

```ts
if (!hasScope(apiKey, "providers:read")) {
  throw new Error("ಅಪರ್ಯಾಪ್ತ ವ್ಯಾಪ್ತಿ");
}
```

## ಪರಿವರ್ತಕಗಳು

`open-sse/transformer/` **Chat Completions** ಮತ್ತು **Responses API** ಸ್ವರೂಪಗಳ ನಡುವೆ ಪರಿವರ್ತಿಸುತ್ತದೆ.

### ಪ್ರತ್ಯೇಕ ಪರಿವರ್ತಕ ಏಕೆ?

Responses API ಎಂಬುದು **ಸ್ಥಿತಿಯುಕ್ತ ಸಂಭಾಷಣೆಗಳನ್ನು** (`previous_response_id`) ಹೊಂದಿರುವ OpenAI ಯ ಹೊಸ ಸ್ವರೂಪವಾಗಿದೆ. ಕ್ಲೈಂಟ್ ಒಂದು Responses ವಿನಂತಿಯನ್ನು ಕಳುಹಿಸಿದಾಗ, OmniRoute:

1. ಆಂತರಿಕವಾಗಿ Responses → Chat Completions ಗೆ ಪರಿವರ್ತಿಸುತ್ತದೆ
2. ಪೂರೈಕೆದಾರರಿಗೆ ಕಳುಹಿಸುತ್ತದೆ (Chat Completions ಅನ್ನು ಬೆಂಬಲಿಸುವ ಯಾವುದೇ ಪೂರೈಕೆದಾರ)
3. ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಮತ್ತೆ Responses ಸ್ವರೂಪಕ್ಕೆ ಪರಿವರ್ತಿಸುತ್ತದೆ
4. ಪರಿವರ್ತಿತ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಕ್ಲೈಂಟ್ಗೆ ಸ್ಟ್ರೀಮ್ ಮಾಡುತ್ತದೆ

ಪರಿವರ್ತಕವು (`transformer/responsesTransformer.ts`) ಇದನ್ನು ಒದಗಿಸುತ್ತದೆ:

```ts
createResponsesApiTransformStream(): TransformStream
```

ಇದು ಇವುಗಳನ್ನು ನಿರ್ವಹಿಸುತ್ತದೆ:

- `response.output_item.added` ಘಟನೆಗಳು
- `response.output_text.delta` ಘಟನೆಗಳು
- `response.completed` ಘಟನೆ
- ಉಪಕರಣ ಕರೆ ಮ್ಯಾಪಿಂಗ್ (`function_call` ↔ `tool_calls`)

## ಸಂರಚನೆ

`open-sse/config/` ಸಂರಚನಾ ಪದರವನ್ನು ಹೊಂದಿರುತ್ತದೆ:

| ಫೈಲ್                          | ಉದ್ದೇಶ                                               |
| ----------------------------- | ---------------------------------------------------- |
| `providerRegistry.ts`         | 352-ಪೂರೈಕೆದಾರರ ಕ್ಯಾಟಲಾಗ್ ಮೇಲಿನ ಚಾಟ್-ಮಾದರಿ ರಿಜಿಸ್ಟ್ರಿ |
| `providerModels.ts`           | ಮಾದರಿ ಅಲಿಯಾಸ್ಗಳು, ಸ್ವರೂಪ ಮ್ಯಾಪಿಂಗ್                   |

```ts
interface ProviderConfig {
```

ಮಾಡ್ಯೂಲ್ ಲೋಡ್ ಆಗುವಾಗ ನಡೆಯುವ Zod ಮೌಲ್ಯೀಕರಣವು ಎಲ್ಲ ಪೂರೈಕೆದಾರ ಸಂರಚನೆಗಳು ಮಾನ್ಯವಾಗಿವೆ ಎಂಬುದನ್ನು ಖಚಿತಪಡಿಸುತ್ತದೆ.

❌ **`combo.ts`ನಲ್ಲಿ ಸಿಂಕ್ರೊನಸ್ DB ಕರೆಗಳು** — ಪೂರ್ವ-ಲೆಕ್ಕಾಚಾರ ಮಾಡಿ ಕ್ಯಾಶ್ನಲ್ಲಿ ಇರಿಸಿ

## ಹೊಸ ಕಾಂಪೊನೆಂಟ್ ಸೇರಿಸುವುದು

### ಹೊಸ ಸೇವೆಯನ್ನು ಸೇರಿಸುವುದು

1. ನಿರ್ದಿಷ್ಟ ಜವಾಬ್ದಾರಿಯೊಂದಿಗೆ `open-sse/services/[serviceName].ts` ರಚಿಸಿ
2. ಮುಖ್ಯ ಹ್ಯಾಂಡ್ಲರ್ ಫಂಕ್ಷನ್ ಮತ್ತು ಯಾವುದೇ ಸ್ಥಿರಾಂಕಗಳನ್ನು ಎಕ್ಸ್ಪೋರ್ಟ್ ಮಾಡಿ
3. `tests/unit/services/[serviceName].test.mjs`ನಲ್ಲಿ ಯೂನಿಟ್ ಪರೀಕ್ಷೆಗಳನ್ನು ಸೇರಿಸಿ
4. `handlers/chatCore.ts`ನಲ್ಲಿನ ವಿನಂತಿ ಪೈಪ್ಲೈನ್ಗೆ ಸಂಯೋಜಿಸಿ (ರೂಟಿಂಗ್ಗೆ ಸಂಬಂಧಿಸಿದ್ದರೆ)
5. ಸೇವೆಯು ಗುರಿ ಆಯ್ಕೆಯ ಮೇಲೆ ಪರಿಣಾಮ ಬೀರಿದರೆ `combo.ts`ನಲ್ಲಿನ ರೂಟಿಂಗ್ ತರ್ಕವನ್ನು ನವೀಕರಿಸಿ
6. ಈ ಫೈಲ್ನಲ್ಲಿ ದಾಖಲಿಸಿ

### ಹೊಸ ಎಕ್ಸಿಕ್ಯೂಟರ್ ಸೇರಿಸುವುದು

1. `BaseExecutor` ಅನ್ನು ವಿಸ್ತರಿಸುವ `open-sse/executors/[provider].ts` ರಚಿಸಿ
2. `config/providerRegistry.ts`ನಲ್ಲಿ ನೋಂದಾಯಿಸಿ
3. `executors/index.ts` ಫ್ಯಾಕ್ಟರಿಗೆ ಸೇರಿಸಿ
4. ಎಕ್ಸಿಕ್ಯೂಟರ್ಗಾಗಿ ಯೂನಿಟ್ ಪರೀಕ್ಷೆಗಳನ್ನು ಸೇರಿಸಿ
5. `docs/architecture/ARCHITECTURE.md`ನಲ್ಲಿ ದಾಖಲಿಸಿ

### ಹೊಸ MCP ಟೂಲ್ ಸೇರಿಸುವುದು

1. `open-sse/mcp-server/tools/[category]Tools.ts` ರಚಿಸಿ ಅಥವಾ ನವೀಕರಿಸಿ
2. ಇನ್ಪುಟ್ಗಳಿಗಾಗಿ Zod ಸ್ಕೀಮಾವನ್ನು ವ್ಯಾಖ್ಯಾನಿಸಿ
3. ಟೂಲ್ ಅನ್ನು `mcp-server/index.ts`ನಲ್ಲಿ ನೋಂದಾಯಿಸಿ
4. `mcp-server/auth/`ನಲ್ಲಿನ ಸ್ಕೋಪ್ ಮ್ಯಾಟ್ರಿಕ್ಸ್ಗೆ ಸೇರಿಸಿ
5. ಯೂನಿಟ್ ಪರೀಕ್ಷೆಗಳನ್ನು ಸೇರಿಸಿ
