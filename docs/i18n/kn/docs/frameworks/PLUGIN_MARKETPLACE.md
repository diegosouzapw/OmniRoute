> **ಸತ್ಯದ ಮೂಲ:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/`, ಮತ್ತು
> `src/app/(dashboard)/dashboard/plugins/`
> **ಕೊನೆಯದಾಗಿ ನವೀಕರಿಸಿದ್ದು:** 2026-06-28 — v3.8.40

OmniRoute, WordPress-ಶೈಲಿಯ ಪ್ಲಗಿನ್ ವ್ಯವಸ್ಥೆಯೊಂದಿಗೆ ಬರುತ್ತದೆ. ಪ್ಲಗಿನ್ಗಳು ಸ್ವಯಂಪೂರ್ಣ
ಡೈರೆಕ್ಟರಿಗಳಾಗಿವೆ — ಪ್ರತಿಯೊಂದೂ `plugin.json` ಮ್ಯಾನಿಫೆಸ್ಟ್ ಮತ್ತು ಪ್ರವೇಶ ಕಡತವನ್ನು ಹೊಂದಿರುತ್ತದೆ — ಇವು
ವಿನಂತಿ ಪೈಪ್ಲೈನ್ಗೆ (`onRequest` / `onResponse` / `onError`) ಮತ್ತು
ಜೀವನಚಕ್ರದ ಈವೆಂಟ್ಗಳಿಗೆ (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`)
ಹುಕ್ ಆಗುತ್ತವೆ.

**ಪ್ಲಗಿನ್ ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್** ಆ ವ್ಯವಸ್ಥೆಯ ಮೇಲಿರುವ ಅನ್ವೇಷಣಾ ಪದರವಾಗಿದೆ. ಇದು
ಸ್ಥಾಪಿಸಬಹುದಾದ ಪ್ಲಗಿನ್ಗಳ ಬ್ರೌಸ್ ಮಾಡಬಹುದಾದ ಕ್ಯಾಟಲಾಗ್ ಅನ್ನು ಒದಗಿಸುತ್ತದೆ. ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ಕ್ಯಾಟಲಾಗ್
ಚಿಕ್ಕ ಅಂತರ್ನಿರ್ಮಿತ ಸೀಡ್ ರಿಜಿಸ್ಟ್ರಿಯಾಗಿದೆ; ನಿರ್ವಾಹಕರು ಅದನ್ನು ಕಸ್ಟಮ್ ದೂರಸ್ಥ
ರಿಜಿಸ್ಟ್ರಿ URL ಕಡೆಗೆ ನಿರ್ದೇಶಿಸಬಹುದು. ಅಂತಹ ಸಂದರ್ಭದಲ್ಲಿ ಫೆಚ್ ಅನ್ನು DNS-ಪರಿಹರಿಸುವ SSRF ಗಾರ್ಡ್ ಮೂಲಕ
ಬಲಪಡಿಸಲಾಗುತ್ತದೆ ([ಭದ್ರತೆ](#security) ನೋಡಿ).

ಪ್ರತಿಯೊಂದು ಪ್ಲಗಿನ್ ರೂಟ್ **ಲೂಪ್ಬ್ಯಾಕ್ಗೆ ಮಾತ್ರ ಸೀಮಿತವಾಗಿದೆ** (ಶ್ರೇಣಿ 1 — `LOCAL_ONLY`): ಪ್ಲಗಿನ್ಗಳು
ಚೈಲ್ಡ್ ಪ್ರೊಸೆಸ್ಗಳಲ್ಲಿ ಕೋಡ್ ಅನ್ನು ಲೋಡ್ ಮಾಡಿ ಕಾರ್ಯಗತಗೊಳಿಸುತ್ತವೆ, ಆದ್ದರಿಂದ ದೃಢೀಕರಣವಿದ್ದರೂ
ಲೂಪ್ಬ್ಯಾಕ್ ಅಲ್ಲದ ಮೂಲದಿಂದ ಈ ರೂಟ್ಗಳನ್ನು ತಲುಪಲಾಗುವುದಿಲ್ಲ. ನೋಡಿ:
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md).

## ಇದು ಹೇಗೆ ಒಟ್ಟಾಗಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ

```
ಡ್ಯಾಶ್ಬೋರ್ಡ್ (/dashboard/plugins)
  ├─ "ಸ್ಥಾಪಿತ" ಟ್ಯಾಬ್  → GET /api/plugins            (listPlugins)
  │                     POST /api/plugins/scan      (pluginManager.scan)
  │                     POST /api/plugins/{name}/activate|deactivate
  │                     DELETE /api/plugins/{name}   (ಅಸ್ಥಾಪನೆ)
  └─ "ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್" ಟ್ಯಾಬ್ → GET /api/plugins/marketplace
                          → listMarketplacePlugins()
                            ├─ ಕಸ್ಟಮ್ URL ಇಲ್ಲ → ಅಂತರ್ನಿರ್ಮಿತ SEED_REGISTRY
                            └─ ಕಸ್ಟಮ್ URL → isSafeMarketplaceUrl() SSRF ಗಾರ್ಡ್
                                          → safeOutboundFetch(guard:"public-only")
```

- **ರಿಜಿಸ್ಟ್ರಿ ಪದರ** — `src/lib/plugins/marketplace.ts`: ಕ್ಯಾಟಲಾಗ್ ಅನ್ನು ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ /
  ಹುಡುಕುತ್ತದೆ ಮತ್ತು ಯಾವುದೇ ವೈಫಲ್ಯದ ಸಂದರ್ಭದಲ್ಲಿ ಸೀಡ್ ರಿಜಿಸ್ಟ್ರಿಗೆ ಹಿಂತಿರುಗುತ್ತದೆ.
- **ಜೀವನಚಕ್ರ ಪದರ** — `src/lib/plugins/manager.ts` (`pluginManager` ಸಿಂಗಲ್ಟನ್):
  ಸ್ಥಾಪನೆ, ಅಪ್ಗ್ರೇಡ್, ಸಕ್ರಿಯಗೊಳಿಸುವಿಕೆ, ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವಿಕೆ, ಅಸ್ಥಾಪನೆ, ಸ್ಕ್ಯಾನ್, ಪ್ರಾರಂಭದ ವೇಳೆ ಲೋಡ್.
- **ಮ್ಯಾನಿಫೆಸ್ಟ್ ಪದರ** — `src/lib/plugins/manifest.ts`: `plugin.json` ಗಾಗಿ Zod ಸ್ಕೀಮಾ +
  ಪೂರ್ವನಿಯೋಜಿತ ಮೌಲ್ಯಗಳು.
- **ಸ್ಕ್ಯಾನರ್** — `src/lib/plugins/scanner.ts`: ಪ್ಲಗಿನ್ ಡೈರೆಕ್ಟರಿಯ ಅಡಿಯಲ್ಲಿರುವ
  ಡಿಸ್ಕ್ನ ಪ್ಲಗಿನ್ಗಳನ್ನು ಪತ್ತೆಮಾಡುತ್ತದೆ.
- **ಲೋಡರ್** — `src/lib/plugins/loader.ts`: ಪ್ರತಿಯೊಂದು ಪ್ಲಗಿನ್ ಅನ್ನು ಪ್ರತ್ಯೇಕಿಸಲಾದ
  ಚೈಲ್ಡ್ ಪ್ರೊಸೆಸ್ನಲ್ಲಿ ಪ್ರಾರಂಭಿಸಿ, IPC ಮೂಲಕ ಹುಕ್ ಕರೆಗಳಿಗೆ ಮಧ್ಯಸ್ಥಿಕೆ ವಹಿಸುತ್ತದೆ.

## ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ ಕ್ಯಾಟಲಾಗ್

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`), `MarketplaceEntry`
ಆಬ್ಜೆಕ್ಟ್ಗಳ ಪಟ್ಟಿಯನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ:

| ಕ್ಷೇತ್ರ       | ಪ್ರಕಾರ   | ಟಿಪ್ಪಣಿಗಳು                                   |
| ------------- | -------- | -------------------------------------------- |
| `name`        | string   | kebab-case ಪ್ಲಗಿನ್ ಹೆಸರು                     |
| `version`     | string   | semver                                       |
| `description` | string   | ಸಂಕ್ಷಿಪ್ತ ಸಾರಾಂಶ                             |
| `author`      | string   | ಲೇಖಕರು / ಸಂಸ್ಥೆ                              |
| `license`     | string   | SPDX-ಶೈಲಿಯ ಪರವಾನಗಿ ಐಡಿ                       |
| `downloadUrl` | string   | ಮೂಲ ಡೌನ್ಲೋಡ್ URL (ಖಾಲಿಯಾಗಿರಬಹುದು)            |
| `repository`  | string?  | ಐಚ್ಛಿಕ ರೆಪೊಸಿಟರಿ URL                         |
| `tags`        | string[] | ಹುಡುಕಾಟ/ಫಿಲ್ಟರ್ ಟ್ಯಾಗ್ಗಳು                    |
| `downloads`   | number   | ಡೌನ್ಲೋಡ್ಗಳ ಸಂಖ್ಯೆ                            |
| `rating`      | number   | 0–5                                          |
| `verified`    | boolean  | ನಮೂದನ್ನು ಪರಿಶೀಲಿಸಲಾಗಿದೆ ಎಂದು ಗುರುತಿಸಲಾಗಿದೆಯೇ |
| `lastUpdated` | string   | ISO-ರೀತಿಯ ದಿನಾಂಕ ಸ್ಟ್ರಿಂಗ್                   |

ಯಾವುದೇ ಕಸ್ಟಮ್ ರಿಜಿಸ್ಟ್ರಿ URL ಅನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡದಿದ್ದಾಗ, ಕ್ಯಾಟಲಾಗ್ ಅಂತರ್ನಿರ್ಮಿತ
`SEED_REGISTRY` ಆಗಿರುತ್ತದೆ (ಪ್ರಸ್ತುತ `request-logger`, `rate-limiter`, `cost-tracker`, ಮತ್ತು
`theme-manager`). ಸೀಡ್ ರಿಜಿಸ್ಟ್ರಿ ಯಾವಾಗಲೂ ಲಭ್ಯವಿರುತ್ತದೆ — ಕಾನ್ಫಿಗರ್ ಮಾಡಿದ ದೂರಸ್ಥ
ರಿಜಿಸ್ಟ್ರಿಯನ್ನು ತಲುಪಲು ಸಾಧ್ಯವಾಗದಿದ್ದರೆ, ಅದು `200` ಅಲ್ಲದ ಸ್ಥಿತಿಯನ್ನು ಹಿಂದಿರುಗಿಸಿದರೆ ಅಥವಾ ಗುರುತಿಸಲಾಗದ
ಬಾಡಿಯನ್ನು ಹಿಂದಿರುಗಿಸಿದರೆ, `listMarketplacePlugins()` ಎಚ್ಚರಿಕೆಯನ್ನು ಲಾಗ್ ಮಾಡಿ ಸೀಡ್ ಪಟ್ಟಿಗೆ ಹಿಂತಿರುಗುತ್ತದೆ.

> ಗಮನಿಸಿ: ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ **ಕ್ಯಾಟಲಾಗ್** (ಬ್ರೌಸ್/ಹುಡುಕಾಟ) ಆರಂಭದಿಂದ ಅಂತ್ಯದವರೆಗೆ ಸಂಪರ್ಕಿಸಲಾಗಿದೆ, ಆದರೆ
> ಕ್ಯಾಟಲಾಗ್ನಿಂದ ಒಂದು ಕ್ಲಿಕ್ನ ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ **ಸ್ಥಾಪನೆ** ಇನ್ನೂ ಅನುಷ್ಠಾನಗೊಂಡಿಲ್ಲ — ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ ನಮೂದಿನ
> ಮೇಲಿರುವ ಡ್ಯಾಶ್ಬೋರ್ಡ್ನ "ಸ್ಥಾಪಿಸು" ಬಟನ್ ಪ್ರಸ್ತುತ "ಶೀಘ್ರದಲ್ಲೇ ಬರಲಿದೆ" ಎಂಬ ಸೂಚನೆಯನ್ನು
> ತೋರಿಸುತ್ತದೆ. ಪ್ರಸ್ತುತ ಸ್ಥಾಪನೆಯು ಸ್ಥಳೀಯ-ಪಥದ ಸ್ಥಾಪನಾ ಹರಿವು (`POST /api/plugins`) ಮತ್ತು
> ಡಿಸ್ಕ್ನಲ್ಲಿನ ಅನ್ವೇಷಣೆ (`POST /api/plugins/scan`) ಮೂಲಕ ನಡೆಯುತ್ತದೆ.

## REST API

ಎಲ್ಲಾ ಎಂಡ್ಪಾಯಿಂಟ್ಗಳಿಗೆ ನಿರ್ವಹಣಾ ದೃಢೀಕರಣ (`requireManagementAuth`) **ಅಗತ್ಯವಿದೆ** ಮತ್ತು ಅವು
ಲೂಪ್ಬ್ಯಾಕ್ಗೆ ಮಾತ್ರ ಸೀಮಿತವಾಗಿವೆ — `/api/plugins` ಮತ್ತು `/api/plugins/` ಅನ್ನು
`LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`) ನಲ್ಲಿ ಪಟ್ಟಿ ಮಾಡಲಾಗಿದೆ.

| ಎಂಡ್ಪಾಯಿಂಟ್                      | ವಿಧಾನ  | ವಿವರಣೆ                                                                    |
| -------------------------------- | ------ | ------------------------------------------------------------------------- |
| `/api/plugins`                   | GET    | ಸ್ಥಾಪಿಸಲಾದ ಪ್ಲಗಿನ್ಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡಿ (ಐಚ್ಛಿಕ `?status=` ಫಿಲ್ಟರ್)           |
| `/api/plugins`                   | POST   | ನಿರಪೇಕ್ಷ ಸ್ಥಳೀಯ ಪಥದಿಂದ ಪ್ಲಗಿನ್ ಅನ್ನು ಸ್ಥಾಪಿಸಿ                             |
| `/api/plugins/scan`              | POST   | ಪ್ಲಗಿನ್ ಡೈರೆಕ್ಟರಿಯನ್ನು ಸ್ಕ್ಯಾನ್ ಮಾಡಿ ಮತ್ತು ಹೊಸ ಪ್ಲಗಿನ್ಗಳನ್ನು ನೋಂದಾಯಿಸಿ    |
| `/api/plugins/marketplace`       | GET    | ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ ಕ್ಯಾಟಲಾಗ್ ನಮೂದುಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡಿ                           |
| `/api/plugins/[name]`            | GET    | ಸ್ಥಾಪಿಸಲಾದ ಪ್ಲಗಿನ್ ವಿವರಗಳನ್ನು ಪಡೆಯಿರಿ                                     |
| `/api/plugins/[name]`            | DELETE | ಪ್ಲಗಿನ್ ಅನ್ನು ಅಸ್ಥಾಪಿಸಿ                                                   |
| `/api/plugins/[name]/activate`   | POST   | ಸಕ್ರಿಯಗೊಳಿಸಿ (ಲೋಡ್ ಮಾಡಿ + ಹುಕ್ಗಳನ್ನು ನೋಂದಾಯಿಸಿ)                           |
| `/api/plugins/[name]/deactivate` | POST   | ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿ (`onDeactivate` ಅನ್ನು ಚಲಾಯಿಸಿ, ಹುಕ್ಗಳ ನೋಂದಣಿ ರದ್ದುಗೊಳಿಸಿ) |
| `/api/plugins/[name]/config`     | GET    | ಪ್ಲಗಿನ್ ಕಾನ್ಫಿಗ್ + ಕಾನ್ಫಿಗ್ ಸ್ಕೀಮಾವನ್ನು ಪಡೆಯಿರಿ                           |
| `/api/plugins/[name]/config`     | PUT    | ಪ್ಲಗಿನ್ ಕಾನ್ಫಿಗ್ ಅನ್ನು ನವೀಕರಿಸಿ (ಸ್ಕೀಮಾ ವಿರುದ್ಧ ಮೌಲ್ಯೀಕರಿಸಲಾಗಿದೆ)         |

`GET /api/plugins` ನ `status` ಫಿಲ್ಟರ್
`installed` / `active` / `inactive` / `error` ಇವುಗಳಲ್ಲಿ ಒಂದನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ. ಅಮಾನ್ಯ ಮೌಲ್ಯವು `400` ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ.

### ಸ್ಥಾಪಿಸಲಾದ ಪ್ಲಗಿನ್ಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡುವುದು

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### ಸ್ಥಳೀಯ ಪಥದಿಂದ ಸ್ಥಾಪಿಸುವುದು

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` **ನಿರಪೇಕ್ಷ**ವಾಗಿರಬೇಕು ಮತ್ತು `..` ಟ್ರಾವರ್ಸಲ್ ಸೆಗ್ಮೆಂಟ್ಗಳು ಅಥವಾ
ಶೂನ್ಯ ಬೈಟ್ಗಳನ್ನು ಹೊಂದಿರಬಾರದು (Zod ಮೂಲಕ ಜಾರಿಗೊಳಿಸಲಾಗಿದೆ). ಮೂಲ ಡೈರೆಕ್ಟರಿಯು ಮಾನ್ಯವಾದ
`plugin.json` ಅನ್ನು ಹೊಂದಿರಬೇಕು (ಅಥವಾ ಅದನ್ನು ಹೊಂದಿರುವ ಪೇರೆಂಟ್ ಆಗಿರಬೇಕು). ಯಶಸ್ವಿಯಾದಾಗ, ಪ್ರತಿಕ್ರಿಯೆಯು `201` ಜೊತೆಗೆ
ಸ್ಥಾಪಿಸಲಾದ ಪ್ಲಗಿನ್ ಸಾಲನ್ನು ಒಳಗೊಂಡಿರುತ್ತದೆ.

### ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ ಬ್ರೌಸ್ ಮಾಡುವುದು

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### ಪ್ಲಗಿನ್ ಕಾನ್ಫಿಗ್ ನವೀಕರಿಸುವುದು

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` ಒದಗಿಸಲಾದ ಪ್ರತಿಯೊಂದು ಮೌಲ್ಯವನ್ನು ಪ್ಲಗಿನ್ನ
`configSchema` (ಮ್ಯಾನಿಫೆಸ್ಟ್ನಲ್ಲಿ ಘೋಷಿಸಲಾಗಿದೆ) ವಿರುದ್ಧ ಮೌಲ್ಯೀಕರಿಸುತ್ತದೆ: `number` ಫೀಲ್ಡ್ಗಳು `min`/`max` ಅನ್ನು ಪಾಲಿಸುತ್ತವೆ,
`select` ಫೀಲ್ಡ್ಗಳು ಘೋಷಿಸಲಾದ `enum` ಗೆ ಹೊಂದಿಕೆಯಾಗಬೇಕು. ಸ್ಕೀಮಾದಲ್ಲಿ ಇಲ್ಲದ ಕೀಗಳನ್ನು
ಅನುಮತಿಸಲಾಗುತ್ತದೆ.

## ಕಾನ್ಫಿಗರೇಶನ್

### ಪ್ಲಗಿನ್ ಡೈರೆಕ್ಟರಿ

ಪ್ಲಗಿನ್ಗಳು OmniRoute ಡೇಟಾ ಡೈರೆಕ್ಟರಿಯ ಅಡಿಯಲ್ಲಿ ಇರುತ್ತವೆ:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (ಅಥವಾ manifest.main ಯಾವುದನ್ನು ಸೂಚಿಸುತ್ತದೆಯೋ ಅದು)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) ಆ ಡೈರೆಕ್ಟರಿಯನ್ನು
ಮೂರು ಹಂತಗಳಲ್ಲಿ ನಿರ್ಧರಿಸುತ್ತದೆ:

1. **`OMNIROUTE_PLUGINS_DIR`**, ಹೊಂದಿಸಿದಾಗ — `HOME` ಏನು ಹೇಳುತ್ತದೆ ಎಂಬುದನ್ನು ಲೆಕ್ಕಿಸದೆ, ಯಥಾವತ್ತಾಗಿ ಬಳಸಲಾಗುತ್ತದೆ. ಇದು
   Docker/K8s ಗಾಗಿ ಇರುವ ಸ್ಪಷ್ಟ ನಿಯಂತ್ರಣವಾಗಿದೆ; ಅಲ್ಲಿ ಪ್ಲಗಿನ್ ಟ್ರೀಯನ್ನು ಸಾಮಾನ್ಯವಾಗಿ ಕಂಟೇನರ್ನ ಹೋಮ್ ಡೈರೆಕ್ಟರಿಯೊಂದಿಗೆ
   ಯಾವುದೇ ಸಂಬಂಧವಿಲ್ಲದ ಪಥದಲ್ಲಿ ಬೈಂಡ್-ಮೌಂಟ್ ಮಾಡಲಾಗುತ್ತದೆ (#11827).
2. `<home>/.omniroute/plugins`, ಇಲ್ಲಿ `<home>` ಅನ್ನು `HOME` / `USERPROFILE`
   ಪರಿಸರ ವೇರಿಯಬಲ್ಗಳಿಂದ ಪಡೆಯಲಾಗುತ್ತದೆ.
3. `/tmp/.omniroute/plugins`, ಪ್ರಕ್ರಿಯೆಯು ಯಾವುದೇ ಹೋಮ್ ಅನ್ನು ಎಕ್ಸ್ಪೋರ್ಟ್ ಮಾಡದಿದ್ದಾಗ.

ನಿರ್ಧರಿಸಲಾದ ಡೈರೆಕ್ಟರಿಯನ್ನು ಸ್ಟಾರ್ಟ್ಅಪ್ ವೇಳೆ `scanner.dir_resolved` ಎಂದು ಒಮ್ಮೆ ಲಾಗ್ ಮಾಡಲಾಗುತ್ತದೆ ಮತ್ತು
ಆಯ್ಕೆಯಾದ ಇನ್ಪುಟ್ನ ಹೆಸರನ್ನು (`OMNIROUTE_PLUGINS_DIR`, `home`, ಅಥವಾ `no-home-fallback`) ನಮೂದಿಸಲಾಗುತ್ತದೆ — ಹೀಗಾಗಿ ಯಾವುದಾದರೂ ಇಮೇಜ್
ಮೌನವಾಗಿ ಹಂತ 3ಕ್ಕೆ ತಲುಪಿದರೆ, ಕೇವಲ ಖಾಲಿ ಪ್ಲಗಿನ್ ಪಟ್ಟಿಯನ್ನು ವರದಿ ಮಾಡುವ ಬದಲು ಅದನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ತಿಳಿಸುತ್ತದೆ.
`POST /api/plugins/scan` ಅಲ್ಲಿ ಮಾನ್ಯವಾದ
`plugin.json` ಹೊಂದಿರುವ ಯಾವುದೇ ಉಪಡೈರೆಕ್ಟರಿಯನ್ನು ಪತ್ತೆಹಚ್ಚಿ ನೋಂದಾಯಿಸುತ್ತದೆ; ಅದೇ ಡೈರೆಕ್ಟರಿಯು
`pluginManager.install()` ಪ್ಲಗಿನ್ಗಳನ್ನು ನಕಲಿಸುವ ರೂಟ್ ಕೂಡ ಆಗಿರುವುದರಿಂದ, ಓವರ್ರೈಡ್ ಡಿಸ್ಕವರಿ ಮತ್ತು
ಸ್ಥಾಪನೆ ಎರಡನ್ನೂ ಒಟ್ಟಿಗೆ ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ.

> **`OMNIROUTE_PLUGINS_DIR`, `OMNIROUTE_PLUGIN_PATH` ಅಲ್ಲ.** ಎರಡನೆಯದನ್ನು
> CLI ಕಮಾಂಡ್-ಪ್ಲಗಿನ್ ಲೋಡರ್ (`bin/cli/plugins.mjs`) ಮಾತ್ರ `omniroute` ಉಪಕಮಾಂಡ್ಗಳನ್ನು ಸೇರಿಸುವ `omniroute-cmd-*` npm
> ಪ್ಯಾಕೇಜ್ಗಳನ್ನು ಹುಡುಕಲು ಓದುತ್ತದೆ — ಇಲ್ಲಿ ವಿವರಿಸಲಾದ ರನ್ಟೈಮ್ ಸ್ಕ್ಯಾನರ್ ಮೇಲೆ ಅದು ಯಾವುದೇ ಪರಿಣಾಮ ಬೀರುವುದಿಲ್ಲ.
> ಆ ಭಾಗಕ್ಕಾಗಿ [PLUGINS.md](./PLUGINS.md) ನೋಡಿ.

### ಕಸ್ಟಮ್ ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ ರಿಜಿಸ್ಟ್ರಿ URL

ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ ಕ್ಯಾಟಲಾಗ್ ಮೂಲವನ್ನು `pluginMarketplaceUrl` ಸೆಟ್ಟಿಂಗ್ನಿಂದ
ಓದಲಾಗುತ್ತದೆ (`src/lib/plugins/marketplace.ts` ನಲ್ಲಿ `settings.pluginMarketplaceUrl` ಅನ್ನು ಓದಲಾಗುತ್ತದೆ).
ಇದನ್ನು `http(s)` URL ಗೆ ಹೊಂದಿಸಿದಾಗ, `listMarketplacePlugins()` ಆ URL ಅನ್ನು ಫೆಚ್ ಮಾಡುತ್ತದೆ ಮತ್ತು
ಎಂಟ್ರಿಗಳ ಟಾಪ್-ಲೆವೆಲ್ JSON ಅರೇ ಅಥವಾ `plugins` ಅರೇ ಹೊಂದಿರುವ ಆಬ್ಜೆಕ್ಟ್ ಅನ್ನು
ಸ್ವೀಕರಿಸುತ್ತದೆ; ಸ್ಟ್ರಿಂಗ್ `name` ಇಲ್ಲದ ಎಂಟ್ರಿಗಳನ್ನು ಫಿಲ್ಟರ್ ಮಾಡಲಾಗುತ್ತದೆ. ಇದನ್ನು ಹೊಂದಿಸದಿದ್ದಾಗ (ಅಥವಾ ಫೆಚ್
SSRF ಗಾರ್ಡ್ನಲ್ಲಿ ವಿಫಲವಾದಾಗ / ಕೆಟ್ಟ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಹಿಂತಿರುಗಿಸಿದಾಗ), ಅಂತರ್ನಿರ್ಮಿತ ಸೀಡ್ ರಿಜಿಸ್ಟ್ರಿಯನ್ನು
ಬಳಸಲಾಗುತ್ತದೆ.

ಡ್ಯಾಶ್ಬೋರ್ಡ್ನ "Marketplace" ಟ್ಯಾಬ್ ಈ URL ಗಾಗಿ ಒಂದು ಫೀಲ್ಡ್ ಅನ್ನು ಒದಗಿಸುತ್ತದೆ (`GET /api/settings` ನಿಂದ
ಮತ್ತೆ ಓದಲಾಗುತ್ತದೆ).

> ಅನುಷ್ಠಾನ ಟಿಪ್ಪಣಿ: ಡ್ಯಾಶ್ಬೋರ್ಡ್ನ "Save" ಕ್ರಿಯೆಯು
> `pluginMarketplaceUrl` ಅನ್ನು `PATCH /api/settings` ಗೆ ಕಳುಹಿಸುತ್ತದೆ. ಇದನ್ನು ಬರೆಯುವ ಸಮಯದಲ್ಲಿ ಈ
> ಕೀಯನ್ನು `updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`) ನಲ್ಲಿ ಘೋಷಿಸಲಾಗಿಲ್ಲ, ಆದ್ದರಿಂದ ಇದನ್ನು ಅವಲಂಬಿಸುವ ಮೊದಲು ನಿಮ್ಮ
> ಬಿಡುಗಡೆಯಲ್ಲಿ ಪರ್ಸಿಸ್ಟೆನ್ಸ್ ಅನ್ನು ಪರಿಶೀಲಿಸಿ — ಸೆಟ್ಟಿಂಗ್ಸ್
> ಸ್ಟೋರ್ನಲ್ಲಿ ಕೀ ಒಮ್ಮೆ ಅಸ್ತಿತ್ವದಲ್ಲಿದ್ದರೆ **ರೀಡ್** ಪಥವು (`getSettings()` →
> `listMarketplacePlugins()`) ಅದನ್ನು ಗೌರವಿಸುತ್ತದೆ.

### ರೂಟ್ ಹಂತ — ಲೂಪ್ಬ್ಯಾಕ್ ಮಾತ್ರ

ಪ್ಲಗಿನ್ಗಳು ಸ್ಪಾನ್ ಮಾಡಿದ ಚೈಲ್ಡ್ ಪ್ರಕ್ರಿಯೆಗಳಲ್ಲಿ ಕೋಡ್ ಅನ್ನು ಕಾರ್ಯಗತಗೊಳಿಸುತ್ತವೆ, ಆದ್ದರಿಂದ ಸಂಪೂರ್ಣ `/api/plugins`
ಮೇಲ್ಮೈಯನ್ನು `LOCAL_ONLY` (ಹಂತ 1) ಎಂದು ವರ್ಗೀಕರಿಸಲಾಗಿದೆ. ಲೂಪ್ಬ್ಯಾಕ್ ಜಾರಿಗೊಳಿಸುವಿಕೆಯು
ಯಾವುದೇ ದೃಢೀಕರಣ ಪರಿಶೀಲನೆಗಿಂತ **ಮೊದಲು** ಬೇಷರತ್ತಾಗಿ ನಡೆಯುತ್ತದೆ. ಆದ್ದರಿಂದ ಟನಲ್ ಮೂಲಕ
ಯಂತ್ರವನ್ನು ತಲುಪುವ ಸೋರಿಕೆಯಾದ ನಿರ್ವಹಣಾ ಟೋಕನ್ ಕೂಡ ಪ್ಲಗಿನ್ ಅನ್ನು ಸ್ಥಾಪಿಸಲು, ಸಕ್ರಿಯಗೊಳಿಸಲು
ಅಥವಾ ಅಸ್ಥಾಪಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ.
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) ಮತ್ತು
ಕಠಿಣ ನಿಯಮಗಳು #15 / #17 ನೋಡಿ.

### ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ ರಿಜಿಸ್ಟ್ರಿ SSRF ರಕ್ಷಣೆ

ಕಸ್ಟಮ್ ರಿಜಿಸ್ಟ್ರಿ URL ಆಕ್ರಮಣಕಾರರಿಂದ ಪ್ರಭಾವಿತವಾಗಬಹುದಾದ ಸಂರಚನೆಯಾಗಿದೆ. ಆದ್ದರಿಂದ
ಅದನ್ನು ಪಡೆಯುವ ಮೊದಲು `listMarketplacePlugins()` ಅದನ್ನು ಎರಡು ಹಂತಗಳ ಮೂಲಕ ಪರಿಶೀಲಿಸುತ್ತದೆ:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - `http:` / `https:` ಅಲ್ಲದ ಯಾವುದನ್ನೂ ತಿರಸ್ಕರಿಸುತ್ತದೆ.
   - ಪ್ರಮಾಣಿತ `isPrivateHost`
     (`src/shared/network/outboundUrlGuard.ts`) ಮೂಲಕ ನೇರ ಖಾಸಗಿ/ಲೂಪ್ಬ್ಯಾಕ್/ಲಿಂಕ್-ಲೋಕಲ್/ULA ಹೋಸ್ಟ್ಗಳನ್ನು (IPv4-ಮ್ಯಾಪ್ ಮಾಡಿದವುಗಳನ್ನು ಒಳಗೊಂಡಂತೆ IPv4 **ಮತ್ತು** IPv6)
     ತಿರಸ್ಕರಿಸುತ್ತದೆ.
   - **`A` ಮತ್ತು `AAAA` ಎರಡೂ** ದಾಖಲೆಗಳನ್ನು ಪರಿಹರಿಸುತ್ತದೆ ಮತ್ತು ಪರಿಹರಿಸಲಾದ
     ವಿಳಾಸಗಳಲ್ಲಿ **ಯಾವುದಾದರೂ ಒಂದು** ಖಾಸಗಿಯಾಗಿದ್ದರೆ ತಿರಸ್ಕರಿಸುತ್ತದೆ — ಈ ಮೂಲಕ ಸಾರ್ವಜನಿಕ-ಹೋಸ್ಟ್ಹೆಸರು → ಖಾಸಗಿ-IP ಬೈಪಾಸ್ ಅನ್ನು ಮುಚ್ಚುತ್ತದೆ.
   - **ವಿಫಲವಾದಾಗ ನಿರಾಕರಿಸುತ್ತದೆ**: DNS ಪರಿಹಾರ ವಿಫಲವಾದರೆ URL ಅನ್ನು ತಿರಸ್ಕರಿಸುತ್ತದೆ.
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`**
   (`src/shared/network/safeOutboundFetch.ts`): ಫೆಚ್ ಮಾಡುವ ಸಮಯದಲ್ಲಿ ಸಾರ್ವಜನಿಕ-ಮಾತ್ರ URL
   ರಕ್ಷಣೆಯನ್ನು ಪುನಃ ಅನ್ವಯಿಸುತ್ತದೆ ಮತ್ತು **ಮರುನಿರ್ದೇಶನಗಳನ್ನು ನಿರ್ಬಂಧಿಸುತ್ತದೆ** (ಸಾರ್ವಜನಿಕ → ಖಾಸಗಿ `30x`
   ಪಿವಟ್ಗೆ ಅವಕಾಶವಿಲ್ಲ).

ಯಾವುದೇ ಒಂದು ಹಂತದಲ್ಲಿ ವಿಫಲವಾಗುವ URL ವಿನಂತಿಯನ್ನು ರದ್ದುಗೊಳಿಸುವುದಿಲ್ಲ — ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್
ಯಾವುದೇ ಸೂಚನೆ ನೀಡದೆ ಅಂತರ್ನಿರ್ಮಿತ ಸೀಡ್ ರಿಜಿಸ್ಟ್ರಿಗೆ ಹಿಂತಿರುಗುತ್ತದೆ ಮತ್ತು ಎಚ್ಚರಿಕೆಯನ್ನು ಲಾಗ್ ಮಾಡುತ್ತದೆ.

> ಈ ರಕ್ಷಣೆಯನ್ನು PR #3774 ರಲ್ಲಿ ನಿರ್ದಿಷ್ಟವಾಗಿ A + AAAA ಪರಿಹರಿಸಲು ಮತ್ತು
> IPv4-ಮಾತ್ರ ಪರಿಶೀಲನೆಯ ಬದಲಿಗೆ ಪ್ರಮಾಣಿತ `isPrivateHost` ಬಳಸಲು ಬಲಪಡಿಸಲಾಗಿದೆ.

### ಪ್ಲಗಿನ್ ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆಯ ಪ್ರತ್ಯೇಕತೆ

- **ಪ್ರಕ್ರಿಯೆ ಪ್ರತ್ಯೇಕತೆ** — `loadPlugin()` (`src/lib/plugins/loader.ts`) ಪ್ರತಿ
  ಪ್ಲಗಿನ್ ಅನ್ನು ಪ್ರತ್ಯೇಕ Node.js ಚೈಲ್ಡ್ ಪ್ರಕ್ರಿಯೆಯಲ್ಲಿ ಸ್ಪಾನ್ ಮಾಡುತ್ತದೆ ಮತ್ತು IPC ಮೂಲಕ ಸಂವಹನ ನಡೆಸುತ್ತದೆ.
  ಹುಕ್ ಕರೆಗಳು `SIGTERM` → `SIGKILL` ತೀವ್ರಗೊಳಿಸುವಿಕೆಯೊಂದಿಗೆ ಕಾಲಮಿತಿಯನ್ನು ಹೊಂದಿರುತ್ತವೆ.
- **ಪರಿಸರ ಅನುಮತಿ ಪಟ್ಟಿ** — ಚೈಲ್ಡ್ ಅನುಮತಿ ಪಟ್ಟಿಯಲ್ಲಿರುವ ಪರಿಸರ
  ವೇರಿಯಬಲ್ಗಳ ಗುಚ್ಛವನ್ನು ಮಾತ್ರ ಸ್ವೀಕರಿಸುತ್ತದೆ; ಮ್ಯಾನಿಫೆಸ್ಟ್ `env` ಅನುಮತಿಯನ್ನು ಕೋರಿದಾಗ ಮಾತ್ರ
  ವಿಶಾಲವಾದ ಗುಚ್ಛವನ್ನು ನೀಡಲಾಗುತ್ತದೆ.
- **ಪಥದ ಮಿತಿಗೊಳಿಸುವಿಕೆ** — ಯಾವುದೇ ನಕಲು ಅಥವಾ ಪುನರಾವರ್ತಿತ ಅಳಿಸುವಿಕೆಗೆ ಮೊದಲು, ಸ್ಥಾಪನೆ/ಅಪ್ಗ್ರೇಡ್/ಅಸ್ಥಾಪನೆ ಪ್ರಕ್ರಿಯೆಗಳು ಪ್ಲಗಿನ್
  ಡೈರೆಕ್ಟರಿ ಮತ್ತು `manifest.main` ನಿರ್ವಹಿತ ಪ್ಲಗಿನ್ ರೂಟ್ನ **ಒಳಗೇ** ಪರಿಹಾರವಾಗುತ್ತವೆ ಎಂದು ಖಚಿತಪಡಿಸುತ್ತವೆ (ತಿರುಚಲ್ಪಟ್ಟ DB ಪಥಗಳು ಮತ್ತು
  `manifest.main` ನಲ್ಲಿನ `../` ಟ್ರಾವರ್ಸಲ್ ವಿರುದ್ಧ ರಕ್ಷಿಸುತ್ತದೆ). ಸಕ್ರಿಯಗೊಳಿಸುವಿಕೆಯು
  `realpath` ಮೂಲಕ ಸಿಮ್ಲಿಂಕ್ಗಳನ್ನು ಪರಿಹರಿಸುತ್ತದೆ ಮತ್ತು ಪ್ಲಗಿನ್
  ಡೈರೆಕ್ಟರಿಯಿಂದ ಹೊರಹೋಗುವ ಪ್ರವೇಶ ಬಿಂದುವನ್ನು ಲೋಡ್ ಮಾಡಲು ನಿರಾಕರಿಸುತ್ತದೆ.
- **ಐಚ್ಛಿಕ ಸಮಗ್ರತಾ ಪಿನ್** — ಮ್ಯಾನಿಫೆಸ್ಟ್ ಒಂದು `integrity`
  (`sha256-<base64>`, SRI ಸ್ವರೂಪ) ಕ್ಷೇತ್ರವನ್ನು ಘೋಷಿಸಬಹುದು. ಅದು ಇದ್ದಾಗ, ಲೋಡರ್
  ಲೋಡ್ ಮಾಡುವ ಸಮಯದಲ್ಲಿ ಪ್ರವೇಶ ಫೈಲ್ನ ಹ್ಯಾಶ್ ಅನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ ಮತ್ತು ಹೊಂದಾಣಿಕೆಯಾಗದಿದ್ದರೆ ಸಕ್ರಿಯಗೊಳಿಸಲು ನಿರಾಕರಿಸುತ್ತದೆ. ಇದು
  ಆಯ್ಕೆಮಾಡಿಕೊಳ್ಳಬಹುದಾದ ತಿದ್ದುಪಡಿ-ಪತ್ತೆ ವ್ಯವಸ್ಥೆಯೇ ಹೊರತು, **ಭದ್ರತಾ ಗಡಿಯಲ್ಲ** — ಲೂಪ್ಬ್ಯಾಕ್-ಮಾತ್ರ ರೂಟಿಂಗ್
  ಮತ್ತು ಅನುಮತಿ ಮಾದರಿಯೇ ನಿಜವಾದ ಗಡಿಗಳು.

## ಜೀವನಚಕ್ರದ ಹರಿವು

```
ಸ್ಥಾಪನೆ (POST /api/plugins, ಪಥ)
  → ಮ್ಯಾನಿಫೆಸ್ಟ್ ಸ್ಕ್ಯಾನ್/ಮೌಲ್ಯೀಕರಣ → ಸ್ಟೇಜಿಂಗ್ಗೆ ನಕಲಿಸಿ → main ಡೈರೆಕ್ಟರಿಯೊಳಗಿದೆ ಎಂದು ಖಚಿತಪಡಿಸಿ
  → ~/.omniroute/plugins/<name> ಗೆ ಅಟಾಮಿಕ್ ಮರುಹೆಸರಿಕೆ → DB ಸಾಲನ್ನು ಸೇರಿಸಿ
  → onInstall ಅನ್ನು ಪ್ರಚೋದಿಸಿ → enabledByDefault ಆಗಿದ್ದರೆ: ಸಕ್ರಿಯಗೊಳಿಸಿ

ಸಕ್ರಿಯಗೊಳಿಸುವಿಕೆ (POST /api/plugins/{name}/activate)
  → realpath ಒಳಗೊಳ್ಳುವಿಕೆ ಪರಿಶೀಲನೆ → loadPlugin() (ಚೈಲ್ಡ್ ಪ್ರೊಸೆಸ್ ಅನ್ನು ಪ್ರಾರಂಭಿಸಿ)
  → ಘೋಷಿತ ಹುಕ್ಗಳನ್ನು ನೋಂದಾಯಿಸಿ → ಸ್ಥಿತಿ = "active" → onActivate ಅನ್ನು ಪ್ರಚೋದಿಸಿ

ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವಿಕೆ (POST /api/plugins/{name}/deactivate)
  → onDeactivate ಅನ್ನು ಪ್ರಚೋದಿಸಿ (ನೋಂದಣಿ ರದ್ದುಗೊಳಿಸುವುದಕ್ಕೆ ಮೊದಲು) → ಹುಕ್ಗಳ ನೋಂದಣಿ ರದ್ದುಗೊಳಿಸಿ
  → ಚೈಲ್ಡ್ ಪ್ರೊಸೆಸ್ ಅನ್ನು ಸ್ಥಗಿತಗೊಳಿಸಿ → ಸ್ಥಿತಿ = "inactive"

ಅಸ್ಥಾಪನೆ (DELETE /api/plugins/{name})
  → ಸಕ್ರಿಯವಾಗಿದ್ದರೆ ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿ → onUninstall ಅನ್ನು ಪ್ರಚೋದಿಸಿ
  → ಒಳಗೊಳ್ಳುವಿಕೆ ಪರಿಶೀಲಿಸಿದ plugin ಡೈರೆಕ್ಟರಿಯನ್ನು ಪುನರಾವರ್ತಿತವಾಗಿ ಅಳಿಸಿ → DB ಸಾಲನ್ನು ಅಳಿಸಿ
```

ಸ್ಥಾಪಿತ ಆವೃತ್ತಿಗಿಂತ ಮ್ಯಾನಿಫೆಸ್ಟ್ ಆವೃತ್ತಿಯು **ಕಟ್ಟುನಿಟ್ಟಾಗಿ
ಹೊಸದಾಗಿರುವ** ಡೈರೆಕ್ಟರಿಯ ವಿರುದ್ಧ `install` ಅನ್ನು ಮರು-ಚಲಾಯಿಸುವುದು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಅಪ್ಗ್ರೇಡ್ ಮಾಡುತ್ತದೆ (ಸ್ವಚ್ಛ ಮರುಸ್ಥಾಪನೆ; ಕಾನ್ಫಿಗ್
ಡೀಫಾಲ್ಟ್ಗಳಿಗೆ ಮರುಹೊಂದಿಸಲಾಗುತ್ತದೆ). ಅದೇ ಅಥವಾ ಹಳೆಯ ಆವೃತ್ತಿಯನ್ನು ತಿರಸ್ಕರಿಸಲಾಗುತ್ತದೆ.

## ಡ್ಯಾಶ್ಬೋರ್ಡ್

`/dashboard/plugins` ನಲ್ಲಿರುವ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಪುಟ
(`src/app/(dashboard)/dashboard/plugins/page.tsx`) ಎರಡು ಟ್ಯಾಬ್ಗಳನ್ನು ಒದಗಿಸುತ್ತದೆ:

- **ಸ್ಥಾಪಿತ** — ಸ್ಥಾಪಿತ pluginಗಳನ್ನು ಅವುಗಳ ಘೋಷಿತ ಹುಕ್ಗಳು, ಸಕ್ರಿಯಗೊಳಿಸುವಿಕೆ/ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವಿಕೆ ಟಾಗಲ್, ಅಸ್ಥಾಪನೆ ಬಟನ್ ಮತ್ತು "Pluginಗಳಿಗಾಗಿ ಸ್ಕ್ಯಾನ್ ಮಾಡಿ"
  ಕ್ರಿಯೆಯೊಂದಿಗೆ (`POST /api/plugins/scan`) ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ.
- **ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್** — ಕಸ್ಟಮ್ ರಿಜಿಸ್ಟ್ರಿ URL ಅನ್ನು ಹೊಂದಿಸುವ
  ಫೀಲ್ಡ್ನೊಂದಿಗೆ `GET /api/plugins/marketplace` ನ ಕ್ಯಾಟಲಾಗ್ ಅನ್ನು ತೋರಿಸುತ್ತದೆ.

ಪ್ರತಿ-plugin ಕಾನ್ಫಿಗ್ ಪುಟವು `/dashboard/plugins/[name]/config`
(`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`) ನಲ್ಲಿ ಇದೆ.
