OmniRoute ಮೂರು ವಿಭಿನ್ನ ಏಜೆಂಟ್-ಸಂಬಂಧಿತ ಇಂಟರ್ಫೇಸ್ಗಳನ್ನು ಒದಗಿಸುತ್ತದೆ. ಮೊದಲ ನೋಟಕ್ಕೆ ಅವು ಒಂದೇ ರೀತಿಯಾಗಿ ಕಾಣಿಸಿದರೂ, ವಿಭಿನ್ನ ಸಮಸ್ಯೆಗಳನ್ನು ಪರಿಹರಿಸುತ್ತವೆ. ಸರಿಯಾದುದನ್ನು ಆಯ್ಕೆ ಮಾಡಲು ಈ ಪುಟವನ್ನು ಬಳಸಿ.

## ಸಂಕ್ಷಿಪ್ತವಾಗಿ

| ಇಂಟರ್ಫೇಸ್                         | ಇದಕ್ಕೆ ಅತ್ಯುತ್ತಮ                                                                                                                                              | ಸಂವಹನ ವಿಧಾನ                    | ಮಾನದಂಡ                       |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------ | ---------------------------- |
| **A2A — ಏಜೆಂಟ್ನಿಂದ ಏಜೆಂಟ್ಗೆ**     | A2A ಪ್ರೋಟೋಕಾಲ್ ಬಳಸುವ ಸಹ ಏಜೆಂಟ್ಗಳೊಂದಿಗೆ ಅಂತರ-ಏಜೆಂಟ್ ಸಹಯೋಗ                                                                                                      | HTTP ಮೂಲಕ JSON-RPC 2.0         | A2A v0.3 (ಮುಕ್ತ ನಿರ್ದಿಷ್ಟತೆ) |
| **ACP — CLI ಏಜೆಂಟ್ಗಳ ರಿಜಿಸ್ಟ್ರಿ** | ಬಳಕೆದಾರರ ಗಣಕದಲ್ಲಿ ಸ್ಥಾಪಿಸಲಾದ CLI ಕೋಡಿಂಗ್ ಏಜೆಂಟ್ಗಳನ್ನು (Cursor, Cline, Codex CLI, Claude Code, Aider, ಇತ್ಯಾದಿ) ಪತ್ತೆಹಚ್ಚುವುದು / ನೋಂದಾಯಿಸುವುದು / ಪ್ರಾರಂಭಿಸುವುದು | HTTP REST                      | OmniRoute-ನಿರ್ದಿಷ್ಟ          |
| **ಕ್ಲೌಡ್ ಏಜೆಂಟ್ಗಳು**              | ಬಾಹ್ಯ ಕ್ಲೌಡ್ ಸೇವೆಗಳಿಗೆ (Codex Cloud, Devin, Jules, Cursor Cloud) ದೀರ್ಘಾವಧಿಯ ಕೋಡಿಂಗ್ ಕಾರ್ಯಗಳನ್ನು ಸಲ್ಲಿಸುವುದು                                                   | HTTP REST + DB-ಆಧಾರಿತ ಕಾರ್ಯಗಳು | OmniRoute-ನಿರ್ದಿಷ್ಟ          |

ಈ ಮೂರೂ ಸ್ವತಂತ್ರವಾಗಿವೆ — ಯಾವುದೇ ಉಪಸಮೂಹವನ್ನು ಆಯ್ಕೆಮಾಡಿ.

```
    ├─ ಹೌದು → A2A (POST /a2a)
```

## 1. A2A — ಏಜೆಂಟ್ನಿಂದ ಏಜೆಂಟ್ಗೆ

**ನಿರ್ದಿಷ್ಟತೆ:** [A2A v0.3](https://a2a-protocol.org)
**OmniRoute ಅಂತ್ಯಬಿಂದು:** `POST /a2a` (JSON-RPC 2.0)
**ಏಜೆಂಟ್ ಕಾರ್ಡ್:** `GET /.well-known/agent.json`

### ಯಾವಾಗ ಬಳಸಬೇಕು

- OmniRoute ಸಹ ಏಜೆಂಟ್ಗಳಲ್ಲಿ ಒಂದಾಗಿರುವ ಬಹು-ಏಜೆಂಟ್ ವ್ಯವಸ್ಥೆಯನ್ನು ನಿರ್ಮಿಸುವಾಗ
- OmniRouteನ ರೂಟಿಂಗ್ ಬುದ್ಧಿಮತ್ತೆಯನ್ನು (smart-routing, quota-management, ಇತ್ಯಾದಿ) Google ADK ಅಥವಾ ಸಾಮಾನ್ಯ ಏಜೆಂಟ್ ಮೆಶ್ಗಳಂತಹ ಫ್ರೇಮ್ವರ್ಕ್ಗಳಲ್ಲಿನ ಏಜೆಂಟ್ಗಳಿಗೆ ಒದಗಿಸುವಾಗ
- ಪ್ರಮಾಣಿತ ಅನ್ವೇಷಣೆ + ಆಹ್ವಾನ ಇಂಟರ್ಫೇಸ್ನ ಹಿಂದೆ OmniRoute ಅನ್ನು ಸುತ್ತುವರಿಯುವಾಗ

### ವಿಧಾನಗಳು

- `message/send` — ಸಂದೇಶವನ್ನು ಸಲ್ಲಿಸಿ, ಸಿಂಕ್ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಸ್ವೀಕರಿಸಿ
- `message/stream` — ಸಂದೇಶವನ್ನು ಸಲ್ಲಿಸಿ + SSE ಮೂಲಕ ಸ್ಟ್ರೀಮ್ ಮಾಡಲಾದ ಪ್ರಗತಿ ಈವೆಂಟ್ಗಳನ್ನು ಸ್ವೀಕರಿಸಿ
- `tasks/get` — ID ಮೂಲಕ ಕಾರ್ಯವನ್ನು ಓದಿ
- `tasks/cancel` — ಚಾಲನೆಯಲ್ಲಿರುವ ಕಾರ್ಯವನ್ನು ರದ್ದುಮಾಡಿ

### ಅಂತರ್ನಿರ್ಮಿತ ಕೌಶಲ್ಯಗಳು (6)

- `smart-routing` — ಪ್ರಾಂಪ್ಟ್ ಅನ್ನು ಅತ್ಯುತ್ತಮ ಸಂಯೋಜನೆಯ ಮೂಲಕ ರೂಟ್ ಮಾಡಿ
- `quota-management` — ಪ್ರತಿ ಪೂರೈಕೆದಾರರ ಕೋಟಾ ಸ್ಥಿತಿಯನ್ನು ವರದಿ ಮಾಡಿ
- `provider-discovery` — ಸಾಮರ್ಥ್ಯಗಳೊಂದಿಗೆ ಸ್ಥಾಪಿಸಲಾದ ಪೂರೈಕೆದಾರರನ್ನು ಪಟ್ಟಿ ಮಾಡಿ
- `cost-analysis` — ವಿನಂತಿ/ಸಂಭಾಷಣೆಯ ವೆಚ್ಚವನ್ನು ಅಂದಾಜಿಸಿ
- `health-report` — ಪ್ರತಿ ಪೂರೈಕೆದಾರರ breaker/cooldown/lockout ಸ್ಥಿತಿಯನ್ನು ಒಟ್ಟುಗೂಡಿಸಿ
- `list-capabilities` — ಏಜೆಂಟ್ಗೆ ಲಭ್ಯವಿರುವ ಕೌಶಲ್ಯಗಳು ಮತ್ತು ಮೆಟಾಡೇಟಾವನ್ನು ಪಟ್ಟಿ ಮಾಡಿ

### ವಿವರವಾದ ಮಾಹಿತಿ

ಸಂವಹನದ ವಿವರಗಳು, ಏಜೆಂಟ್ ಕಾರ್ಡ್ ರಚನೆ, ಕಾರ್ಯದ TTL ಸಂರಚನೆ ಮತ್ತು ಹೊಸ ಕೌಶಲ್ಯಗಳನ್ನು ಸೇರಿಸುವ ಟೆಂಪ್ಲೇಟ್ಗಾಗಿ [A2A-SERVER.md](./A2A-SERVER.md) ನೋಡಿ.

## 2. ACP — CLI ಏಜೆಂಟ್ಗಳ ರಿಜಿಸ್ಟ್ರಿ

**OmniRoute ಎಂಡ್ಪಾಯಿಂಟ್:** `GET /api/acp/agents`
**ಮೂಲ:** `src/lib/acp/{index,manager,registry}.ts`

### ಇದು ಏನು

ACP ಎಂಬುದು OmniRoute ನ **ಸ್ಥಳೀಯ CLI ಏಜೆಂಟ್ ಇನ್ವೆಂಟರಿ** ಆಗಿದೆ. ಹೋಸ್ಟ್ನಲ್ಲಿ ಯಾವ ಕೋಡಿಂಗ್ CLI ಗಳು ಇನ್ಸ್ಟಾಲ್ ಆಗಿವೆ (Cursor, Cline, Claude Code, Codex CLI, Continue, ಇತ್ಯಾದಿ) ಎಂಬುದನ್ನು ಇದು ಪತ್ತೆಹಚ್ಚುತ್ತದೆ, ಅವುಗಳ ಆವೃತ್ತಿಗಳನ್ನು ನಿರ್ಧರಿಸುತ್ತದೆ ಮತ್ತು ಅವುಗಳನ್ನು ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿ ಪ್ರದರ್ಶಿಸುತ್ತದೆ; ಇದರಿಂದ ಬಳಕೆದಾರರು ಪ್ರತಿಯೊಂದು CLI ಯನ್ನೂ OmniRoute ಕಡೆಗೆ ಸೂಚಿಸುವಂತೆ ಸಂಪರ್ಕಿಸಬಹುದು.

ಇದು ಬಾಹ್ಯ ಪ್ರೋಟೋಕಾಲ್ ಅಲ್ಲ — ಇದು "CLI Tools" UI ಮತ್ತು CLI ಫಿಂಗರ್ಪ್ರಿಂಟ್ ಟ್ರ್ಯಾಕಿಂಗ್ಗೆ ಆಧಾರವಾಗಿರುವ ಆಂತರಿಕ ರಿಜಿಸ್ಟ್ರಿಯಾಗಿದೆ ([CLI-TOOLS.md](../reference/CLI-TOOLS.md) ನೋಡಿ).

### ಇದು ಏನು ಮಾಡುತ್ತದೆ

- ಇನ್ಸ್ಟಾಲ್ ಆಗಿರುವ CLI ಬೈನರಿಗಳಿಗಾಗಿ ಹೋಸ್ಟ್ ಅನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ (OS ಗೆ ಅನುಗುಣವಾಗಿ `which` / `where` ಬಳಸುತ್ತದೆ)
- ಪ್ರತಿಯೊಂದು CLI ಯ ಆವೃತ್ತಿಯನ್ನು ಓದುತ್ತದೆ (`<bin> --version` ಅನ್ನು ಕರೆ ಮಾಡುತ್ತದೆ)
- ಐಚ್ಛಿಕವಾಗಿ ಬಳಕೆದಾರರು ವ್ಯಾಖ್ಯಾನಿಸಿದ ಕಸ್ಟಮ್ ಏಜೆಂಟ್ಗಳನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ (ಬೈನರಿ ಪಥ + ಆವೃತ್ತಿ ಪರಿಶೀಲನೆ + ಸ್ಪಾನ್ ಆರ್ಗ್ಯುಮೆಂಟ್ಗಳು)
- ಕಸ್ಟಮ್ ಏಜೆಂಟ್ಗಳನ್ನು ಸೆಟ್ಟಿಂಗ್ಗಳಲ್ಲಿ ಶಾಶ್ವತವಾಗಿ ಉಳಿಸುತ್ತದೆ
- ಏಕೀಕೃತ ಪಟ್ಟಿಯನ್ನು ಡ್ಯಾಶ್ಬೋರ್ಡ್ಗೆ ಹಿಂತಿರುಗಿಸುತ್ತದೆ

### REST API

| ಎಂಡ್ಪಾಯಿಂಟ್       | ವಿಧಾನ | ವಿವರಣೆ                                                                    | ದೃಢೀಕರಣ |
| ----------------- | ----- | ------------------------------------------------------------------------- | ------- |
| `/api/acp/agents` | GET   | ಪತ್ತೆಯಾದ + ಕಸ್ಟಮ್ ಏಜೆಂಟ್ಗಳ ಪಟ್ಟಿ (ಇನ್ಸ್ಟಾಲ್ ಆಗಿರುವ/ಒಟ್ಟು ಸಂಖ್ಯೆಗಳು)       | API ಕೀ  |
| `/api/acp/agents` | POST  | ಕಸ್ಟಮ್ ಏಜೆಂಟ್ ಅನ್ನು ಸೇರಿಸಿ/ನವೀಕರಿಸಿ/ತೆಗೆದುಹಾಕಿ (ಬಾಡಿಯಲ್ಲಿ ಕ್ರಿಯೆಯ ವಿಭೇದಕ) | API ಕೀ  |

POST ಗಾಗಿನ ಬಾಡಿ ರಚನೆ (`src/app/api/acp/agents/route.ts` ನಲ್ಲಿರುವ `customAgentBodySchema`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### ಬಳಕೆಯ ಸಂದರ್ಭಗಳು

- ಡ್ಯಾಶ್ಬೋರ್ಡ್ನ "CLI Tools" ಪುಟವು ಇನ್ಸ್ಟಾಲ್ ಆಗಿರುವ ಪರಿಕರಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ ಮತ್ತು ಪ್ರತಿಯೊಂದನ್ನೂ OmniRoute ಕಡೆಗೆ ಸೂಚಿಸಲು ನಿಮಗೆ ಸಹಾಯ ಮಾಡುತ್ತದೆ
- OmniRoute ಗೆ ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ತಿಳಿದಿಲ್ಲದ ಆಂತರಿಕ/ಸ್ವಾಮ್ಯದ CLI ಗಳನ್ನು ನೋಂದಾಯಿಸಲು ಕಸ್ಟಮ್ ಏಜೆಂಟ್ಗಳು ಪರಿಣತ ಬಳಕೆದಾರರಿಗೆ ಅವಕಾಶ ನೀಡುತ್ತವೆ
- ಪತ್ತೆಹಚ್ಚುವಿಕೆಯ ಫಲಿತಾಂಶವು `cli-tools` ಫಿಂಗರ್ಪ್ರಿಂಟ್ ಮ್ಯಾಟ್ರಿಕ್ಸ್ಗೆ ದತ್ತಾಂಶ ಒದಗಿಸುತ್ತದೆ

### ACP ಅನ್ನು ಯಾವಾಗ ಬಳಸಬಾರದು

- ACP ಕಾರ್ಯಗಳನ್ನು _ಚಾಲನೆ ಮಾಡುವುದಿಲ್ಲ_. ಇದು CLI ಗಳನ್ನು ಪತ್ತೆಹಚ್ಚುತ್ತದೆ + ಕಾನ್ಫಿಗರ್ ಮಾಡುತ್ತದೆ ಅಷ್ಟೇ. CLI ಯನ್ನು ನಿಜವಾಗಿ ಆಹ್ವಾನಿಸಲು, OmniRoute ಒದಗಿಸುವ env vars (`OPENAI_BASE_URL`, `OPENAI_API_KEY`, ಇತ್ಯಾದಿ) ಜೊತೆಗೆ ನೀವೇ ಅದನ್ನು ಪ್ರಾರಂಭಿಸಬೇಕು.

## 3. ಕ್ಲೌಡ್ ಏಜೆಂಟ್ಗಳು

**OmniRoute ಎಂಡ್ಪಾಯಿಂಟ್ಗಳು:** `/api/v1/agents/tasks/*` (ಜೀವನಚಕ್ರ) + `/api/cloud/*` (ಮೂಲ ಸಂಪರ್ಕ ವ್ಯವಸ್ಥೆ)
**ಮೂಲ:** `src/lib/cloudAgent/`

### ಇದು ಏನು

ಮೂರನೇ-ಪಕ್ಷದ ಕ್ಲೌಡ್ ಕೋಡಿಂಗ್ ಏಜೆಂಟ್ಗಳ ಮೇಲಿನ ಏಕರೂಪದ ಇಂಟರ್ಫೇಸ್. ನೀವು ಪ್ರಾಂಪ್ಟ್ + ರೆಪೊ URL ಅನ್ನು ಸಲ್ಲಿಸುತ್ತೀರಿ, OmniRoute ಅದನ್ನು ಸೂಕ್ತವಾದ ಕ್ಲೌಡ್ ಏಜೆಂಟ್ಗೆ ರವಾನಿಸುತ್ತದೆ, ಸ್ಥಿತಿಯನ್ನು ನಿಯತವಾಗಿ ಪರಿಶೀಲಿಸುತ್ತದೆ ಮತ್ತು ಫಲಿತಾಂಶಗಳನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ.

### ಬೆಂಬಲಿತ ಏಜೆಂಟ್ಗಳು (4, ಎಲ್ಲವೂ `src/lib/cloudAgent/agents/` ನಲ್ಲಿ ದೃಢೀಕರಿಸಲಾಗಿದೆ)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### ಜೀವನಚಕ್ರ

```
POST /api/v1/agents/tasks
  → ಪ್ರತಿ ಏಜೆಂಟ್ ಕ್ಲಾಸ್ಗಾಗಿ BaseAgent.createTask()
  → ಬಾಹ್ಯ ಸೇವೆಯು ಕೆಲಸವನ್ನು ಪ್ರಾರಂಭಿಸುತ್ತದೆ
  → DB ಯಲ್ಲಿ ಕಾರ್ಯದ ಸಾಲನ್ನು ರಚಿಸಲಾಗುತ್ತದೆ (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → ಪೂರೈಕೆದಾರರಿಂದ ಅಗತ್ಯವಿದ್ದಾಗ ಸ್ಥಿತಿ ಸಿಂಕ್
  → ಪ್ರಸ್ತುತ ಸ್ಥಿತಿ + ಯೋಜನೆ + ಚಟುವಟಿಕೆಯ ಲಾಗ್ ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ
  ↓
POST /api/v1/agents/tasks/[id]   (ಕ್ರಿಯೆ: "approve" | "message" | "cancel")
  → ಪೂರೈಕೆದಾರರಿಗೆ ರವಾನಿಸುತ್ತದೆ (ಅಥವಾ ಸ್ಥಳೀಯವಾಗಿ ರದ್ದುಗೊಂಡಿದೆ ಎಂದು ಗುರುತಿಸುತ್ತದೆ)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → ಸ್ಥಳೀಯವಾಗಿ ರದ್ದುಗೊಳಿಸುತ್ತದೆ
```

### ದೃಢೀಕರಣ

⚠️ **ಎಲ್ಲಾ `/api/v1/agents/tasks/*` ಎಂಡ್ಪಾಯಿಂಟ್ಗಳಿಗೆ ನಿರ್ವಹಣಾ ದೃಢೀಕರಣದ ಅಗತ್ಯವಿದೆ** (ಕಮಿಟ್ `588a0333`). v3.8.0 ರಿಂದ ಕೇವಲ Bearer ಬಳಸುವ ಕರೆಗಾರರು 401 ಅನ್ನು ಸ್ವೀಕರಿಸುತ್ತಾರೆ.

### ಆಳವಾದ ವಿವರಣೆ

`CloudAgentBase` ಒಪ್ಪಂದ, ಪ್ರತಿ ಏಜೆಂಟ್ಗೆ ಸಂಬಂಧಿಸಿದ ನಿರ್ದಿಷ್ಟ ವಿವರಗಳು, ಸ್ಕೀಮಾ ವಿವರಗಳು ಮತ್ತು ಕ್ರೆಡೆನ್ಶಿಯಲ್ ಸಂಪರ್ಕ ವ್ಯವಸ್ಥೆಯ ಎಂಡ್ಪಾಯಿಂಟ್ಗಳಿಗಾಗಿ [CLOUD_AGENT.md](./CLOUD_AGENT.md) ನೋಡಿ.

## ಹೋಲಿಕೆ: A2A ಮತ್ತು Cloud Agents

ಎರಡರಲ್ಲೂ "ದೀರ್ಘಕಾಲ ನಡೆಯುವ ಕಾರ್ಯಗಳು" ಇವೆ, ಆದರೆ ವಿಭಿನ್ನ ಪದರಗಳಲ್ಲಿ:

| ಅಂಶ              | A2A                                                                                 | Cloud Agents                                                |
| ---------------- | ----------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| ಮಾನದಂಡ           | ಮುಕ್ತ A2A v0.3                                                                      | OmniRoute-ನಿರ್ದಿಷ್ಟ                                         |
| ಗಣನೆ ನಡೆಯುವ ಸ್ಥಳ | OmniRoute ಒಳಗೆ (ಕಾನ್ಫಿಗರ್ ಮಾಡಿದ ಕಾಂಬೊಗಳನ್ನು ಬಳಸುತ್ತದೆ)                              | ಬಾಹ್ಯ (Codex / Devin / Jules ಸರ್ವರ್ಗಳು)                     |
| ಕಾರ್ಯದ ಅವಧಿ      | ಡೀಫಾಲ್ಟ್ TTL 5 ನಿಮಿಷಗಳು (`TaskManager`-ನಲ್ಲಿ ಕಾನ್ಫಿಗರ್ ಮಾಡಬಹುದು)                    | ನಿಮಿಷಗಳಿಂದ ಗಂಟೆಗಳವರೆಗೆ                                      |
| ರೆಪೊ-ಅರಿವು       | ಇಲ್ಲ (ಪ್ರಾಂಪ್ಟ್ಗಳನ್ನು ಮಾತ್ರ ರವಾನಿಸುತ್ತದೆ)                                           | ಹೌದು (ರೆಪೊ URL + ಬ್ರಾಂಚ್)                                   |
| ಬಳಕೆಯ ಸಂದರ್ಭ     | ಏಜೆಂಟ್ಗಳ ನಡುವಿನ ಸಹಯೋಗ, ಸೇವೆಯಾಗಿ ಸ್ಮಾರ್ಟ್ ರೂಟಿಂಗ್                                    | "ರೆಪೊ Y-ನಲ್ಲಿ ವೈಶಿಷ್ಟ್ಯ X ಅನುಷ್ಠಾನಗೊಳಿಸಿ" ಎಂದು ನಿಯೋಜಿಸುವುದು |
| ದೃಢೀಕರಣ          | `/a2a`-ಗೆ ಐಚ್ಛಿಕ `OMNIROUTE_API_KEY`; `/api/a2a/*` REST ಸಹಾಯಕಗಳಿಗೆ ನಿರ್ವಹಣಾ ದೃಢೀಕರಣ | ಯಾವಾಗಲೂ ನಿರ್ವಹಣಾ ದೃಢೀಕರಣ                                    |

## ಏಕೀಕರಣದ ಉದಾಹರಣೆಗಳು

### OmniRoute-ನ A2A ಸಾಮರ್ಥ್ಯಗಳನ್ನು ಅನ್ವೇಷಿಸಿ

```bash
curl http://localhost:20128/.well-known/agent.json
```

ಎಲ್ಲಾ 6 ಕೌಶಲ್ಯಗಳು, ಟ್ರಾನ್ಸ್ಪೋರ್ಟ್ಗಳು ಮತ್ತು ಆವೃತ್ತಿಯನ್ನು ಒಳಗೊಂಡ Agent Card ಅನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ.

### OmniRoute ಅನ್ನು A2A ಏಜೆಂಟ್ ಆಗಿ ಕರೆ ಮಾಡಿ

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],

    },
    "id": 1
  }'
```
