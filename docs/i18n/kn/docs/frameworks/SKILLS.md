> **ಅಧಿಕೃತ ಮೂಲ:** `src/lib/skills/` ಮತ್ತು `src/app/api/skills/`
> **ಕೊನೆಯ ನವೀಕರಣ:** 2026-06-28 — v3.8.40

OmniRoute ವಿಸ್ತರಿಸಬಹುದಾದ Skills ಚೌಕಟ್ಟನ್ನು ಒದಗಿಸುತ್ತದೆ. ಇದು ಭಾಷಾ ಮಾದರಿಗಳು (ಮತ್ತು ನಿರ್ವಾಹಕರು) ಮರುಬಳಕೆ ಮಾಡಬಹುದಾದ ಸಾಮರ್ಥ್ಯಗಳನ್ನು ಸಂಯೋಜಿಸಲು ಅನುವು ಮಾಡಿಕೊಡುತ್ತದೆ — ಫೈಲ್ಸಿಸ್ಟಮ್ ಓದುವಿಕೆ ಮತ್ತು HTTP ವಿನಂತಿಗಳಿಂದ ಹಿಡಿದು ಸ್ಯಾಂಡ್ಬಾಕ್ಸ್ ಮಾಡಿದ ಕೋಡ್ ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆ ಮತ್ತು ಆಯ್ದ ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ ಸ್ಕಿಲ್ಗಳವರೆಗೆ.

ಸ್ಕಿಲ್ ಎಂದರೆ ಆವೃತ್ತೀಕರಿಸಿದ, ಸ್ಕೀಮಾ-ನಿರ್ದಿಷ್ಟಪಡಿಸಿದ ಕಾರ್ಯದ ಘಟಕ. OmniRoute ಹೊರಹೋಗುವ ವಿನಂತಿಗಳಲ್ಲಿ ಸ್ಕಿಲ್ಗಳನ್ನು ಟೂಲ್ ವ್ಯಾಖ್ಯಾನಗಳಾಗಿ ಸೇರಿಸಬಹುದು, ಮಾದರಿಯಿಂದ ಮರಳಿ ಬರುವ ಟೂಲ್ ಕರೆಗಳನ್ನು ಪ್ರತಿಬಂಧಿಸಬಹುದು, ಹೊಂದಾಣಿಕೆಯ ಹ್ಯಾಂಡ್ಲರ್ ಅನ್ನು ಚಲಾಯಿಸಬಹುದು ಮತ್ತು ಸಂಭಾಷಣೆಯು ಮುಂದುವರಿಯುವಂತೆ ಫಲಿತಾಂಶವನ್ನು ಮಾದರಿಗೆ ಮರಳಿ ಒದಗಿಸಬಹುದು. ಮಾದರಿಯು ಅನುಷ್ಠಾನವನ್ನು ಎಂದಿಗೂ ನೋಡುವುದಿಲ್ಲ — ಅದು ಟೂಲ್ ಇಂಟರ್ಫೇಸ್ ಅನ್ನು ಮಾತ್ರ ನೋಡುತ್ತದೆ.

## Agent Skills ಮತ್ತು Omni Skills

OmniRoute ಎರಡು ಪ್ರತ್ಯೇಕವಾದರೂ ಪರಸ್ಪರ ಪೂರಕವಾದ ಸ್ಕಿಲ್ ವ್ಯವಸ್ಥೆಗಳನ್ನು ಹೊಂದಿದೆ:

| ಆಯಾಮ            | **Omni Skills** (ಈ ದಸ್ತಾವೇಜು)                                                     | **Agent Skills**                                                                              |
| :-------------- | :-------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------- |
| ಉದ್ದೇಶ          | LLM ಟೂಲ್ ಸೇರಿಸುವಿಕೆ + ಸ್ಯಾಂಡ್ಬಾಕ್ಸ್ ಮಾಡಿದ ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆ                       | ಬಾಹ್ಯ ಏಜೆಂಟ್ಗಳು ಅನ್ವೇಷಿಸಲು ಮತ್ತು ಬಳಸಲು SKILL.md ಕ್ಯಾಟಲಾಗ್                                     |
| ಅಧಿಕೃತ ಮೂಲ      | `src/lib/skills/` + ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್                                                | `src/lib/agentSkills/` + `skills/` ಡೈರೆಕ್ಟರಿ                                                  |
| ರನ್ಟೈಮ್ ಮೋಡ್    | ಹೊರಹೋಗುವ ವಿನಂತಿಗಳಲ್ಲಿ ಸೇರಿಸಲಾಗುತ್ತದೆ, ಟೂಲ್-ಕರೆ ಈವೆಂಟ್ಗಳಲ್ಲಿ ಕಾರ್ಯಗತಗೊಳಿಸಲಾಗುತ್ತದೆ | ಸ್ಥಿರ ಮಾರ್ಕ್ಡೌನ್ ಕ್ಯಾಟಲಾಗ್ + REST/MCP/A2A ಅನ್ವೇಷಣಾ ಎಂಡ್ಪಾಯಿಂಟ್ಗಳು                             |
| ಇದನ್ನು ಬಳಸುವವರು | OmniRoute ಸ್ವತಃ (ಕಾಂಬೊ ರೂಟಿಂಗ್, ಒಳಬರುವ LLM ಕರೆಗಳು)                                | ಬಾಹ್ಯ ಏಜೆಂಟ್ಗಳು, MCP ಕ್ಲೈಂಟ್ಗಳು, A2A ಆರ್ಕೆಸ್ಟ್ರೇಟರ್ಗಳು                                        |
| ಸಂಖ್ಯೆ          | ಬದಲಾಗುವಂತಹದ್ದು (ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್-ಚಾಲಿತ)                                             | 45 ಕ್ಯಾಟಲಾಗ್ ನಮೂದುಗಳು (23 API + 21 CLI + 1 ಕಾನ್ಫಿಗ್)                                          |
| ಸ್ವರೂಪ          | ಟೂಲ್ ಸ್ಕೀಮಾ + ಹ್ಯಾಂಡ್ಲರ್ ಹೊಂದಿರುವ `SkillDefinition`                               | `SKILL.md` ಫ್ರಂಟ್ಮ್ಯಾಟರ್ + ಮಾರ್ಕ್ಡೌನ್ ಬಾಡಿ                                                    |
| ಅನ್ವೇಷಣೆ        | `/api/skills/*` REST + `omniroute_skills_*` MCP ಟೂಲ್ಗಳು                           | `/api/agent-skills/*` REST + `omniroute_agent_skills_*` MCP ಟೂಲ್ಗಳು + A2A `list-capabilities` |

**Omni Skills** ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆ ಎಂಜಿನ್ ಆಗಿವೆ — LLM ಒಂದು ಟೂಲ್ ಅನ್ನು ಆಹ್ವಾನಿಸಿದಾಗ OmniRoute _ಏನು ಮಾಡಬಹುದು_ ಎಂಬುದನ್ನು ಅವು ನಿರ್ಧರಿಸುತ್ತವೆ.

**Agent Skills** ದಸ್ತಾವೇಜೀಕರಣ ಕ್ಯಾಟಲಾಗ್ ಆಗಿವೆ — ಏಜೆಂಟ್ ಪ್ರಾಂಪ್ಟ್ಗಳಿಗೆ ನೇರವಾಗಿ ಒದಗಿಸಬಹುದಾದ ರಚನಾತ್ಮಕ SKILL.md ಫೈಲ್ಗಳ ಮೂಲಕ, OmniRoute ನ REST API ಮತ್ತು CLI ಅನ್ನು _ಹೇಗೆ ಬಳಸಬೇಕು_ ಎಂಬುದನ್ನು ಅವು ಬಾಹ್ಯ ಏಜೆಂಟ್ಗಳಿಗೆ ವಿವರಿಸುತ್ತವೆ.

Agent Skills ಕ್ಯಾಟಲಾಗ್, ಜನರೇಟರ್, MCP ಟೂಲ್ಗಳು ಮತ್ತು A2A ಸ್ಕಿಲ್ಗಾಗಿ, [docs/frameworks/AGENT-SKILLS.md](./AGENT-SKILLS.md) ನೋಡಿ.

## ಪರಿಕಲ್ಪನೆಗಳು

### ಸ್ಕಿಲ್ ಮೂಲಗಳು

ಸ್ಕಿಲ್ಗಳ ಮೂರು ಮೂಲಗಳು ಒಂದೇ ರಿಜಿಸ್ಟ್ರಿಯಲ್ಲಿ ಸಹಅಸ್ತಿತ್ವದಲ್ಲಿವೆ:

1. **ಅಂತರ್ನಿರ್ಮಿತ ಸ್ಕಿಲ್ಗಳು** (`src/lib/skills/builtins.ts`) — OmniRoute ಜೊತೆಗೆ ರವಾನಿಸಲಾಗುತ್ತವೆ. ಸಾಮಾನ್ಯ ಬಳಕೆಯ ಸಂದರ್ಭಗಳನ್ನು ಒಳಗೊಂಡಿವೆ:
   - `file_read`, `file_write` — `<DATA_DIR>/skills/workspaces/<hashed-key>/` ಅಡಿಯಲ್ಲಿ ಪ್ರತಿ-API-ಕೀ ಸ್ಯಾಂಡ್ಬಾಕ್ಸ್ ಕಾರ್ಯಸ್ಥಳ
   - `http_request` — `guard: "public-only"` ಜೊತೆಗೆ `safeOutboundFetch` ಮೂಲಕ ಹೊರಹೋಗುವ HTTP
   - `web_search` — ಕ್ಯಾಶಿಂಗ್ ಹೊಂದಿರುವ ಪ್ಲಗ್ ಮಾಡಬಹುದಾದ ಹುಡುಕಾಟ ಪೂರೈಕೆದಾರ (`executeWebSearch`)
   - `eval_code` — Docker-ಸ್ಯಾಂಡ್ಬಾಕ್ಸ್ ಮಾಡಿದ `node` ಅಥವಾ `python` ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆ
   - `execute_command` — Docker-ಸ್ಯಾಂಡ್ಬಾಕ್ಸ್ ಮಾಡಿದ ಶೆಲ್ ಕಮಾಂಡ್
   - `browser` — Playwright-ಆಧಾರಿತ ಸ್ಕ್ಯಾಫೋಲ್ಡಿಂಗ್, ಡೀಫಾಲ್ಟ್ ಆಗಿ ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಲಾಗಿದೆ (`builtin/browser.ts`)
2. **SkillsMP** (OmniRoute ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್) — `https://skillsmp.com/api/v1/skills/search` ನಿಂದ ಪಡೆಯಲಾಗುತ್ತದೆ. Settings ನಲ್ಲಿ `skillsmpApiKey` ಅಗತ್ಯವಿದೆ.
3. **SkillsSH** (`skills.sh` ಸಮುದಾಯ ಕ್ಯಾಟಲಾಗ್) — `https://skills.sh/api/search` ನಿಂದ ಪಡೆಯಲಾಗುತ್ತದೆ. ದೃಢೀಕರಣದ ಅಗತ್ಯವಿಲ್ಲ; SKILL.md ವಿಷಯವನ್ನು GitHub raw ನಿಂದ ಪಡೆಯಲಾಗುತ್ತದೆ.

ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಯಾವ ಕ್ಯಾಟಲಾಗ್ನಿಂದ ಸ್ಥಾಪಿಸುತ್ತದೆ ಎಂಬುದನ್ನು ಒಂದೇ "ಸಕ್ರಿಯ ಪೂರೈಕೆದಾರ" ನಿಯಂತ್ರಿಸುತ್ತದೆ (`src/lib/skills/providerSettings.ts`). ಇದನ್ನು **Settings → Memory & Skills** ಅಡಿಯಲ್ಲಿ ಬದಲಾಯಿಸಿ. ಡೀಫಾಲ್ಟ್: `skillsmp`.

### ಸ್ಕಿಲ್ ಗುರುತು

ಇನ್-ಮೆಮೊರಿ ರಿಜಿಸ್ಟ್ರಿಯಲ್ಲಿ (`src/lib/skills/registry.ts`) ಸ್ಕಿಲ್ಗಳನ್ನು `name@version` ಮೂಲಕ ಗುರುತಿಸಲಾಗುತ್ತದೆ. ಆವೃತ್ತಿಯು semver (`^\d+\.\d+\.\d+$`) ಆಗಿರಬೇಕು. `resolveVersion()` ಎಂಬುದು `^`, `~`, `>`, `>=`, `<`, `<=`, `==` ಮತ್ತು ನಿಖರ-ಹೊಂದಾಣಿಕೆಯ ನಿರ್ಬಂಧಗಳನ್ನು ಅರ್ಥಮಾಡಿಕೊಳ್ಳುತ್ತದೆ.

### ಸ್ಕಿಲ್ ಮೋಡ್

ಪ್ರತಿ ಸ್ಕಿಲ್ ಅನ್ನು ಯಾವಾಗ ಸೇರಿಸಬೇಕು ಎಂಬುದನ್ನು ನಿಯಂತ್ರಿಸುವ ರನ್ಟೈಮ್ ಮೋಡ್ ಅದಕ್ಕಿರುತ್ತದೆ:

| ಮೋಡ್   | ವರ್ತನೆ                                                                                                          |
| ------ | --------------------------------------------------------------------------------------------------------------- |
| `on`   | ಯಾವಾಗಲೂ ಟೂಲ್ ವ್ಯಾಖ್ಯಾನವಾಗಿ ಸೇರಿಸಲಾಗುತ್ತದೆ                                                                       |
| `off`  | ಎಂದಿಗೂ ಸೇರಿಸಲಾಗುವುದಿಲ್ಲ, ಎಂದಿಗೂ ಕಾರ್ಯಗತಗೊಳಿಸಲಾಗುವುದಿಲ್ಲ                                                         |
| `auto` | ಒಳಬರುವ ವಿನಂತಿಯೊಂದಿಗೆ ಹೋಲಿಸಿ ಅಂಕ ನೀಡಲಾಗುತ್ತದೆ; ಅಂಕ ≥ `AUTO_MIN_SCORE` ಆಗಿದ್ದರೆ ಮಾತ್ರ ಸೇರಿಸಲಾಗುತ್ತದೆ (ಡೀಫಾಲ್ಟ್ 3) |

ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ನಿಂದ ಸ್ಥಾಪಿಸಲಾದ ಸ್ಕಿಲ್ಗಳಿಗೆ `auto` ಡೀಫಾಲ್ಟ್ ಆಗಿದೆ. `enabled=true` ಮತ್ತು `mode="off"` ಒಟ್ಟಿಗೆ ಇದ್ದರೆ "ನೋಂದಾಯಿಸಲಾಗಿದೆ ಆದರೆ ನಿಷ್ಕ್ರಿಯವಾಗಿದೆ" ಎಂದರ್ಥ — ಹಳೆಯ ಕೋಡ್ಪಾತ್ಗಳು ಸ್ಥಿರವಾಗಿರಲು ಲೆಗಸಿ ಕಾಲಮ್ ಮೂಲಕ `enabled` ಅನ್ನು ಟಾಗಲ್ ಮಾಡುವುದರಿಂದ `mode` ಕೂಡ ಬದಲಾಗುತ್ತದೆ (`src/app/api/skills/[id]/route.ts`).

### ಸ್ಥಿತಿ (ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆಗಳು)

ಸ್ಕಿಲ್ ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆಗಳನ್ನು ಈ ಕೆಳಗಿನ ಸ್ಥಿತಿಗಳೊಂದಿಗೆ `skill_executions` ಟೇಬಲ್ನಲ್ಲಿ ಟ್ರ್ಯಾಕ್ ಮಾಡಲಾಗುತ್ತದೆ (`src/lib/skills/types.ts`):

```ts
enum SkillStatus {
  PENDING = "pending",
  RUNNING = "running",
  SUCCESS = "success",
  ERROR = "error",
  TIMEOUT = "timeout",
}
```

### ರಿಜಿಸ್ಟ್ರಿ ಕ್ಯಾಶ್

`SkillRegistry` ಎಂಬುದು 60-ಸೆಕೆಂಡ್ TTL ಕ್ಯಾಶ್ ಹೊಂದಿರುವ ಸಿಂಗಲ್ಟನ್ ಆಗಿದೆ (`registry.ts:14`). `loadFromDatabase()` ಐಡೆಂಪೊಟೆಂಟ್ ಆಗಿದ್ದು, `pendingLoad` ಮೂಲಕ ಏಕಕಾಲಿಕ ಕರೆಗಳಿಂದ ಉಂಟಾಗುವ ನಕಲುಗಳನ್ನು ತೆಗೆದುಹಾಕುತ್ತದೆ. ಯಾವುದೇ ಬರವಣಿಗೆ (`register`/`unregister`/`unregisterById`) ಕ್ಯಾಶ್ ಅನ್ನು ಅಮಾನ್ಯಗೊಳಿಸುತ್ತದೆ. `getSkillVersions(name)` ಮತ್ತು `resolveVersion(name, constraint)` ಮೂಲಕ ಆವೃತ್ತಿಗಳನ್ನು ಹುಡುಕಿ.

### ಪೂರೈಕೆದಾರ-ಅರಿವಿನ ಸೇರಿಸುವಿಕೆ

`src/lib/skills/injection.ts` ನಲ್ಲಿರುವ `injectSkills()` ನೋಂದಾಯಿತ ಸ್ಕಿಲ್ಗಳನ್ನು ಪೂರೈಕೆದಾರ-ನಿರ್ದಿಷ್ಟ ಟೂಲ್ ವ್ಯಾಖ್ಯಾನಗಳಾಗಿ ಪರಿವರ್ತಿಸುವ ಪ್ರವೇಶ ಬಿಂದುವಾಗಿದೆ:

- **OpenAI** — `{ type: "function", function: { name, description, parameters } }`
- **Anthropic** — `{ name, description, input_schema }`
- **Google (Gemini)** — `{ name, description, parameters }`

ಮಾದರಿಯು ಅದನ್ನು ಮರಳಿ ಕರೆ ಮಾಡಿದಾಗ ಹ್ಯಾಂಡ್ಲರ್ ಸರಿಯಾದ ಆವೃತ್ತಿಯನ್ನು ಆಯ್ಕೆಮಾಡಲು, ಪರಿಕರದ ಹೆಸರನ್ನು `name@version` ರೂಪದಲ್ಲಿ ಎನ್ಕೋಡ್ ಮಾಡಲಾಗಿದೆ.

### AUTO ಸ್ಕೋರಿಂಗ್

`mode="auto"` ಆಗಿರುವಾಗ, ಪ್ರತಿ ಅಭ್ಯರ್ಥಿ ಸ್ಕಿಲ್ ಅನ್ನು ವಿನಂತಿಯ ಸಂದರ್ಭದ ಆಧಾರದಲ್ಲಿ ಸ್ಕೋರ್ ಮಾಡಲಾಗುತ್ತದೆ (`injection.ts` ನಲ್ಲಿನ `scoreAutoSkill()`):

| ಸಂಕೇತ                                                                  | ಅಂಕಗಳು           |
| ---------------------------------------------------------------------- | ---------------- |
| ಸ್ಕಿಲ್ ಹೆಸರು ಸಂದರ್ಭದಲ್ಲಿ ಯಥಾವತ್ತಾಗಿ ಕಾಣಿಸಿಕೊಳ್ಳುತ್ತದೆ                  | +6               |
| ಪ್ರತಿಯೊಂದು ಹೆಸರಿನ ಟೋಕನ್ ಸಂದರ್ಭದ ಟೋಕನ್ಗೆ ಹೊಂದಿಕೆಯಾಗುತ್ತದೆ               | +2               |
| ಪ್ರತಿಯೊಂದು ಟ್ಯಾಗ್ ಉಪಸ್ಟ್ರಿಂಗ್ ಸಂದರ್ಭಕ್ಕೆ ಹೊಂದಿಕೆಯಾಗುತ್ತದೆ              | +3               |
| ಪ್ರತಿಯೊಂದು ವಿವರಣೆಯ ಟೋಕನ್ ಸಂದರ್ಭಕ್ಕೆ ಹೊಂದಿಕೆಯಾಗುತ್ತದೆ                   | +1               |
| ಹಿನ್ನೆಲೆಯ ಕಾರಣವು ಹೆಸರಿನ ಟೋಕನ್ಗೆ ಹೊಂದಿಕೆಯಾಗುತ್ತದೆ                       | ಪ್ರತಿ ಟೋಕನ್ಗೆ +2 |
| ಹಿನ್ನೆಲೆಯ ಕಾರಣವು ಟ್ಯಾಗ್ಗೆ ಹೊಂದಿಕೆಯಾಗುತ್ತದೆ                             | ಪ್ರತಿ ಟೋಕನ್ಗೆ +2 |
| ಟ್ಯಾಗ್ಗಳಲ್ಲಿನ ಪೂರೈಕೆದಾರರ ಸುಳಿವು ವಿನಂತಿಯ ಪೂರೈಕೆದಾರರಿಗೆ ಹೊಂದಿಕೆಯಾಗುತ್ತದೆ | +2 / −2          |

`score >= AUTO_MIN_SCORE = 3` ಹೊಂದಿರುವ ಅಗ್ರ `AUTO_MAX_SKILLS = 5` ಸ್ಕಿಲ್ಗಳನ್ನು ಇಂಜೆಕ್ಟ್ ಮಾಡಲಾಗುತ್ತದೆ. ಸಮ ಅಂಕಗಳಿದ್ದರೆ, ಮೊದಲು `installCount` (ಅವರೋಹಣ ಕ್ರಮ), ನಂತರ ವರ್ಣಮಾಲೆಯ ಹೆಸರಿನ (`injection.ts:225-235`) ಆಧಾರದಲ್ಲಿ ಕ್ರಮ ನಿರ್ಧರಿಸಲಾಗುತ್ತದೆ.

### ಪರಿಕರ ಕರೆ ತಡೆಹಿಡಿಯುವಿಕೆ

ಅಪ್ಸ್ಟ್ರೀಮ್ ಪರಿಕರ-ಕರೆ ಮಾಡುವ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಮರಳಿಸಿದ ನಂತರ, ಚಾಟ್ ಹ್ಯಾಂಡ್ಲರ್ನಿಂದ `src/lib/skills/interception.ts` ನಲ್ಲಿನ `handleToolCallExecution()` ಅನ್ನು ಆಹ್ವಾನಿಸಲಾಗುತ್ತದೆ:

1. `extractToolCalls()` ಪೂರೈಕೆದಾರ-ನಿರ್ದಿಷ್ಟ ಸ್ವರೂಪಗಳನ್ನು ಓದುತ್ತದೆ (OpenAI `tool_calls` / Responses `function_call`, Anthropic `tool_use`, Gemini `functionCalls`).
2. ಅಂತರ್ನಿರ್ಮಿತ ಪರಿಕರ ಅಲಿಯಾಸ್ಗಳನ್ನು (ಉದಾ. `omniroute_web_search` → `web_search`) ಮೊದಲು ಪರಿಹರಿಸಲಾಗುತ್ತದೆ. ಅಂತರ್ನಿರ್ಮಿತ ಹ್ಯಾಂಡ್ಲರ್ಗಳು ಇನ್ಲೈನ್ನಲ್ಲಿ ರನ್ ಆಗುತ್ತವೆ.
3. ಉಳಿದ ಎಲ್ಲವೂ `skillExecutor.execute(name@version, args, { apiKeyId, sessionId })` ಮೂಲಕ ರೂಟ್ ಆಗುತ್ತದೆ.
4. ಫಲಿತಾಂಶಗಳನ್ನು ಸೂಕ್ತವಾದ ರೀತಿಯಲ್ಲಿ ಪ್ರತಿಕ್ರಿಯೆಯೊಳಗೆ ಮತ್ತೆ ಸೇರಿಸಲಾಗುತ್ತದೆ — `tool_results`, `function_call_output` ಐಟಂಗಳು, ಅಥವಾ Anthropic `tool_result` ಬ್ಲಾಕ್ಗಳು.

ಬಳಕೆದಾರರು ವ್ಯಾಖ್ಯಾನಿಸಿದ ಹ್ಯಾಂಡ್ಲರ್ಗಳನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವ ವಿನಂತಿ ಮಾರ್ಗಗಳಲ್ಲಿ, ಕೇವಲ ಅಂತರ್ನಿರ್ಮಿತ ತಡೆಹಿಡಿಯುವಿಕೆಯನ್ನು ಅನುಮತಿಸಲು ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆ ಸಂದರ್ಭದಲ್ಲಿ `customSkillExecutionEnabled` ಅನ್ನು `false` ಗೆ ಹೊಂದಿಸಬಹುದು.

## Docker ಸ್ಯಾಂಡ್ಬಾಕ್ಸ್

ಅಂತರ್ನಿರ್ಮಿತವಲ್ಲದ ಕೋಡ್ ಮಾರ್ಗಗಳು (`eval_code`, `execute_command`) `SandboxRunner` (`src/lib/skills/sandbox.ts`) ಮೂಲಕ Docker ಒಳಗೆ ರನ್ ಆಗುತ್ತವೆ. ಪ್ರತಿ ಕಂಟೇನರ್ ಅನ್ನು ಈ ಕೆಳಗಿನವುಗಳೊಂದಿಗೆ ಪ್ರಾರಂಭಿಸಲಾಗುತ್ತದೆ:

```
--rm --network none|bridge --cap-drop ALL
--security-opt no-new-privileges --pids-limit 100
--cpus <cpuLimit/1000> --memory <memoryLimit>m
--tmpfs /tmp:rw,noexec,nosuid,size=64m
--tmpfs /workspace:rw,noexec,nosuid,size=64m
--read-only (readOnly=true ಆಗಿರುವಾಗ)
```

ಡೀಫಾಲ್ಟ್ಗಳು (`SandboxRunner.DEFAULT_CONFIG`):

| ಕ್ಷೇತ್ರ          | ಡೀಫಾಲ್ಟ್        | ಟಿಪ್ಪಣಿಗಳು                                                |
| ---------------- | --------------- | --------------------------------------------------------- |
| `cpuLimit`       | 100 (= 0.1 CPU) | `--cpus` ಗೆ ರವಾನಿಸುವ ಮೊದಲು 1000 ರಿಂದ ಭಾಗಿಸಲಾಗುತ್ತದೆ       |
| `memoryLimit`    | 256 MB          | ಕಟ್ಟುನಿಟ್ಟಿನ ಮಿತಿ                                         |
| `timeout`        | 30000 ms        | `SIGTERM` + `docker kill` ಮೂಲಕ ಸಾಫ್ಟ್ ಕಿಲ್                |
| `networkEnabled` | `false`         | `--network none` ಆಗುತ್ತದೆ                                 |
| `readOnly`       | `true`          | ರೂಟ್ FS ಓದಲು ಮಾತ್ರ; `/tmp` ಮತ್ತು `/workspace` tmpfs ಆಗಿವೆ |

ಸ್ಥಗಿತಗೊಳಿಸುವಿಕೆಗಾಗಿ `SandboxRunner.kill(id)` ಮತ್ತು `killAll()` ಅನ್ನು ಬಹಿರಂಗಪಡಿಸಲಾಗಿದೆ; ಚಾಲನೆಯಲ್ಲಿರುವ ಕಂಟೇನರ್ಗಳನ್ನು `runningContainers: Map<string, ChildProcess>` ನಲ್ಲಿ ಟ್ರ್ಯಾಕ್ ಮಾಡಲಾಗುತ್ತದೆ.

### ಸ್ಯಾಂಡ್ಬಾಕ್ಸ್ ಪರಿಸರ ಚರಗಳು

`src/lib/skills/builtins.ts` ನಲ್ಲಿ `process.env` ಮೂಲಕ ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾಗಿದೆ:

| ಪರಿಸರ ಚರ                          | ಡೀಫಾಲ್ಟ್         | ಉದ್ದೇಶ                                                                                 |
| --------------------------------- | ---------------- | -------------------------------------------------------------------------------------- |
| `SKILLS_MAX_FILE_BYTES`           | `1048576` (1 MB) | `file_read` ಮತ್ತು `file_write` ಗಾಗಿ ಮಿತಿ                                               |
| `SKILLS_MAX_HTTP_RESPONSE_BYTES`  | `256000`         | `http_request` ಪ್ರತಿಕ್ರಿಯೆಯ ಬಾಡಿಗೆ ಮಿತಿ                                                |
| `SKILLS_MAX_SANDBOX_OUTPUT_CHARS` | `100000`         | ಕರೆ ಮಾಡಿದವರಿಗೆ ಮರಳಿಸಲಾದ stdout/stderr ಗಾಗಿ ಮಿತಿ                                        |
| `SKILLS_SANDBOX_TIMEOUT_MS`       | `10000`          | ಸ್ಯಾಂಡ್ಬಾಕ್ಸ್ ಮಾಡಿದ ಕಮಾಂಡ್ಗಳಿಗೆ ಡೀಫಾಲ್ಟ್ ಸಮಯಮಿತಿ; 60 s ಗೆ ಸೀಮಿತ                        |
| `SKILLS_SANDBOX_NETWORK_ENABLED`  | `false`          | ಹೊರಹೋಗುವಿಕೆಗೆ ಮಾಸ್ಟರ್ ಗೇಟ್. ಪ್ರತಿ ಕರೆಯ ಆಯ್ಕೆಯನ್ನು ಅನುಮತಿಸಲು `1` ಅಥವಾ `true` ಗೆ ಹೊಂದಿಸಿ |
| `SKILLS_ALLOWED_SANDBOX_IMAGES`   | (ಕೆಳಗೆ ನೋಡಿ)     | Docker ಇಮೇಜ್ಗಳ ಅಲ್ಪವಿರಾಮದಿಂದ ಪ್ರತ್ಯೇಕಿಸಲಾದ ಅನುಮತಿಪಟ್ಟಿ                                 |

ಡೀಫಾಲ್ಟ್ ಆಗಿ ಅನುಮತಿಸಲಾದ ಇಮೇಜ್ಗಳು: `alpine:3.20`, `node:22-alpine`, `python:3.12-alpine`. `SKILLS_ALLOWED_SANDBOX_IMAGES` ಮೂಲಕ ಮಾಡುವ ಯಾವುದೇ ಸೇರ್ಪಡೆಗಳನ್ನು ಡೀಫಾಲ್ಟ್ಗಳೊಂದಿಗೆ ವಿಲೀನಗೊಳಿಸಲಾಗುತ್ತದೆ; ಅಪರಿಚಿತ ಇಮೇಜ್ಗಳನ್ನು `normalizeImage()` ತಿರಸ್ಕರಿಸುತ್ತದೆ.

> ಗಮನಿಸಿ: ಪ್ರತ್ಯೇಕ `SKILLS_EXECUTION_TIMEOUT_MS` ಪರಿಸರ ಚರ ಇಲ್ಲ. ಸ್ಯಾಂಡ್ಬಾಕ್ಸ್ ಅಲ್ಲದ ಹ್ಯಾಂಡ್ಲರ್ ಸಮಯಮಿತಿಯನ್ನು `SkillExecutor` (`executor.ts:13`) ನಲ್ಲಿ 30 s ಗೆ ಹಾರ್ಡ್-ಕೋಡ್ ಮಾಡಲಾಗಿದೆ, ಆದರೆ ರನ್ಟೈಮ್ನಲ್ಲಿ `skillExecutor.setTimeout(ms)` ಮೂಲಕ ಅದನ್ನು ಬದಲಾಯಿಸಬಹುದು.

### ಕಾರ್ಯಸ್ಥಳ ಪ್ರತ್ಯೇಕೀಕರಣ

`file_read` ಮತ್ತು `file_write` ಪ್ರತಿ ಮಾರ್ಗವನ್ನು `<DATA_DIR>/skills/workspaces/<sha256(apiKeyId).slice(0,24)>/` ನಲ್ಲಿರುವ ಪ್ರತಿ API ಕೀಗೆ ಪ್ರತ್ಯೇಕವಾದ ಕಾರ್ಯಸ್ಥಳಕ್ಕೆ ಸಂಬಂಧಿಸಿ ಪರಿಹರಿಸುತ್ತವೆ. ಯಾವುದೇ ಡಿಸ್ಕ್ I/O ಗೂ ಮೊದಲು ಪಥ ಸಂಚರಣೆ (`..`) ಮತ್ತು ನಿಷೇಧಿತ ವಿಭಾಗಗಳನ್ನು (`.env`, `.git`, `.ssh`, `.omniroute`, `.codex`, `secrets`) ತಿರಸ್ಕರಿಸಲಾಗುತ್ತದೆ.

### HTTP ಬಲಪಡಿಸುವಿಕೆ

`http_request` (`builtins.ts:257`):

- ವಿಧಾನ ಅನುಮತಿಪಟ್ಟಿ: `GET, HEAD, POST, PUT, PATCH, DELETE`
- ನಿರ್ಬಂಧಿಸಲಾದ ಹೊರಹೋಗುವ ಹೆಡರ್ಗಳು: `host, connection, content-length, cookie, set-cookie, authorization, proxy-authorization`
- ಮರುನಿರ್ದೇಶನಗಳನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಲಾಗಿದೆ (`allowRedirect: false`)
- `guard: "public-only"` ಜೊತೆಗೆ `safeOutboundFetch` ಮೂಲಕ ರೂಟ್ ಮಾಡಲಾಗಿದೆ (ಖಾಸಗಿ/ಲೂಪ್ಬ್ಯಾಕ್ ಶ್ರೇಣಿಗಳನ್ನು ನಿರ್ಬಂಧಿಸಲಾಗಿದೆ)
- ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು `SKILLS_MAX_HTTP_RESPONSE_BYTES` ನಲ್ಲಿ ಮೊಟಕುಗೊಳಿಸಲಾಗುತ್ತದೆ; ಕ್ಲೈಂಟ್ಗೆ `truncated: true` ಕಾಣಿಸುತ್ತದೆ

## ಹೈಬ್ರಿಡ್ ಎಕ್ಸಿಕ್ಯೂಟರ್ (ಪೂರ್ವವೀಕ್ಷಣೆ)

`src/lib/skills/hybrid.ts` ಪ್ರತಿ ಕರೆಯಲ್ಲೂ `direct` (ಪ್ರಕ್ರಿಯೆಯೊಳಗಿನ) ಮತ್ತು `sandbox` ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆಯ ನಡುವೆ ಆಯ್ಕೆ ಮಾಡುವ `HybridExecutor` ಅನ್ನು ವ್ಯಾಖ್ಯಾನಿಸುತ್ತದೆ; ಸಮಯ ಮೀರಿದಾಗ/ಮೆಮೊರಿ ದೋಷಗಳು ಸಂಭವಿಸಿದಾಗ `autoUpgrade` ಮರುಪ್ರಯತ್ನ ಮಾರ್ಗವನ್ನೂ ಇದು ಹೊಂದಿದೆ. ಸಂಪರ್ಕಿಸಲಾದ `directExecutor` / `sandboxRunner` ಅನುಷ್ಠಾನಗಳು ಸ್ಟಬ್ಗಳಾಗಿವೆ (`executeDirect`, `executeInSandbox` ಪ್ಲೇಸ್ಹೋಲ್ಡರ್ ಆಬ್ಜೆಕ್ಟ್ಗಳನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತವೆ) — ಈ ಮಾಡ್ಯೂಲ್ ಅನ್ನು ನಿರ್ಮಾಣ ಹಂತದಲ್ಲಿರುವ ಒಪ್ಪಂದವೆಂದು ಪರಿಗಣಿಸಿ. ನೈಜ ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆ ಇನ್ನೂ `skillExecutor` + `SandboxRunner` ಮೂಲಕವೇ ನಡೆಯುತ್ತದೆ.

## ಸಂಗ್ರಹಣೆ

ಸ್ಕೀಮಾ ಎರಡು ಮೈಗ್ರೇಷನ್ಗಳಲ್ಲಿದೆ:

- `src/lib/db/migrations/016_create_skills.sql` — ಮೂಲ `skills` ಮತ್ತು `skill_executions` ಟೇಬಲ್ಗಳು, `(api_key_id, name)` ಮತ್ತು `(skill_id, status, created_at)` ಮೇಲೆ ಇಂಡೆಕ್ಸ್ಗಳೊಂದಿಗೆ.

`skill_executions.status` ಅನ್ನು ಡೇಟಾಬೇಸ್ ಮಟ್ಟದಲ್ಲಿ ನಿರ್ಬಂಧಿಸಲಾಗಿದೆ: `CHECK(status IN ('pending', 'running', 'success', 'error', 'timeout'))`.

## REST API

ಎಲ್ಲಾ ಎಂಡ್ಪಾಯಿಂಟ್ಗಳು `src/app/api/skills/` ಅಡಿಯಲ್ಲಿ ಇವೆ. ನಿರ್ವಹಣಾ ಎಂಡ್ಪಾಯಿಂಟ್ಗಳಿಗೆ (`/api/skills`, `/api/skills/[id]`, `/api/skills/install`) `requireManagementAuth()` ಮೂಲಕ **ನಿರ್ವಹಣಾ ದೃಢೀಕರಣ** ಅಗತ್ಯವಿದೆ. ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್/ಇನ್ಸ್ಟಾಲ್ ಹರಿವುಗಳು ಹೆಚ್ಚು ಸರಳವಾದ `isAuthenticated()` ಅನ್ನು (ಸೆಷನ್ ಅಥವಾ API ಕೀ) ಬಳಸುತ್ತವೆ.

| ಎಂಡ್ಪಾಯಿಂಟ್ | ವಿಧಾನ | ಉದ್ದೇಶ |
| --------------------------------- | ------ | ------------------------------------------------------------------------ | --- | ------------------------ | -------- | ------------------ |

| `/api/skills/[id]` | PUT | `enabled` ಅಥವಾ `mode` ಅನ್ನು ನವೀಕರಿಸುತ್ತದೆ |
| `/api/skills/[id]` | DELETE | id ಮೂಲಕ ನೋಂದಣಿ ರದ್ದುಗೊಳಿಸುತ್ತದೆ |

| `/api/skills/skillssh` | GET | skills.sh ಕ್ಯಾಟಲಾಗ್ನಲ್ಲಿ ಹುಡುಕುತ್ತದೆ (`?q=&limit=`, ಗರಿಷ್ಠ 100ಕ್ಕೆ ಸೀಮಿತ) |

### ಉದಾಹರಣೆ: ಕಸ್ಟಮ್ ಸ್ಕಿಲ್ ಅನ್ನು ಇನ್ಸ್ಟಾಲ್ ಮಾಡುವುದು

```bash
curl -X POST http://localhost:20128/api/skills/install \
  -H "Authorization: Bearer $OMNIROUTE_MGMT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "reverse-text",
    "version": "1.0.0",
    "description": "Reverses a string",
    "schema": {
      "input":  { "type": "object", "properties": { "text": { "type": "string" } }, "required": ["text"] },
      "output": { "type": "object", "properties": { "reversed": { "type": "string" } } }
    },
    "handlerCode": "echo-handler",
    "apiKeyId": "your-api-key-id"
  }'
```

`handlerCode` ಸ್ಟ್ರಿಂಗ್ ಒಂದು **ಹ್ಯಾಂಡ್ಲರ್ ಹೆಸರಿನ ಲುಕ್ಅಪ್** ಆಗಿದೆ — ಕಾರ್ಯಗತಗೊಳಿಸಬಹುದಾದ ಕೋಡ್ ಅಲ್ಲ. ಎಕ್ಸಿಕ್ಯೂಟರ್ ಅದನ್ನು `skillExecutor.registerHandler(name, fn)` ಮೂಲಕ ಮ್ಯಾಪ್ ಮಾಡುತ್ತದೆ (`executor.ts:25`). ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ ಇನ್ಸ್ಟಾಲ್ಗಳು SKILL.md ಪಠ್ಯವನ್ನು ಈ ಫೀಲ್ಡ್ನಲ್ಲಿ ದಸ್ತಾವೇಜೀಕರಣವಾಗಿ ಸಂಗ್ರಹಿಸುತ್ತವೆ ಮತ್ತು ಮಾದರಿಯಿಂದ ರಚಿಸಲಾದ ಟೂಲ್ ಕರೆಗಳ ಮೂಲಕ ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆಯನ್ನು ರೂಟ್ ಮಾಡುತ್ತವೆ. ಬಳಕೆದಾರರು ಒದಗಿಸಿದ ಅನಿಯಂತ್ರಿತ ಮೂಲ ಕೋಡ್ ಅನ್ನು eval ಮಾಡಲಾಗುವುದಿಲ್ಲ.

## ಹೊಸ ಅಂತರ್ನಿರ್ಮಿತ ಕೌಶಲ್ಯವನ್ನು ಸೇರಿಸುವುದು

1. **ಹ್ಯಾಂಡ್ಲರ್ ಅನ್ನು ವ್ಯಾಖ್ಯಾನಿಸಿ** `src/lib/skills/builtins.ts` ನಲ್ಲಿ (ಅಥವಾ `src/lib/skills/builtin/` ಅಡಿಯಲ್ಲಿರುವ ಸಹೋದರ ಫೈಲ್ನಲ್ಲಿ). ಸಹಿ: `(input, { apiKeyId, sessionId }) => Promise<output>`.
2. **ಸ್ಯಾಂಡ್ಬಾಕ್ಸ್ ಮಾಡಿದ ಕೋಡ್ ಮಾರ್ಗವೇ?** `sandboxRunner.run(image, command, env, sandboxConfig({...}))` ಅನ್ನು ಕರೆ ಮಾಡಿ. ಅನುಮತಿ ಪಟ್ಟಿಯೊಂದಿಗೆ `normalizeImage()` ಬಳಸಿ.
3. **ಫೈಲ್ಸಿಸ್ಟಮ್ ಮಾರ್ಗವೇ?** ಡಿಸ್ಕ್ ಅನ್ನು ಪ್ರವೇಶಿಸುವ ಮೊದಲು ಯಾವಾಗಲೂ `resolveWorkspacePath(input, context)` ಮೂಲಕ ಹಾದುಹೋಗಿಸಿ.
4. **ನೆಟ್ವರ್ಕ್ ಕರೆಯೇ?** `guard: "public-only"` ಜೊತೆಗೆ `safeOutboundFetch` ಬಳಸಿ; `sanitizeHeaders()` ಮೂಲಕ ಹೆಡರ್ಗಳನ್ನು ಸ್ವಚ್ಛಗೊಳಿಸಿ.
5. **ನೋಂದಾಯಿಸಿ** `builtinSkills` ಗೆ ನಮೂದನ್ನು ಸೇರಿಸುವ ಮೂಲಕ (ಅಥವಾ ಬೂಟ್ ಸಮಯದಲ್ಲಿ `registerBrowserSkill(executor)` ಶೈಲಿಯಲ್ಲಿ ಕರೆ ಮಾಡುವ ಮೂಲಕ).
6. ಅಪ್ಸ್ಟ್ರೀಮ್ ಮಾದರಿಯು ಬೇರೆ ಹೆಸರನ್ನು ಹೊರಸೂಸಿದರೆ, **ಅಂತರ್ನಿರ್ಮಿತ ಪರಿಕರ ಅಲಿಯಾಸ್ಗಳನ್ನು ಜೋಡಿಸಿ** (ಐಚ್ಛಿಕ) `BUILTIN_TOOL_ALIASES` (`interception.ts:23`) ನಲ್ಲಿ.
7. **ಪರೀಕ್ಷೆಗಳು** `src/lib/skills/__tests__/` ನಲ್ಲಿ (Vitest).

## ಕಾರ್ಯಾಚರಣಾ ಸಲಹೆಗಳು

- **ಮುಖ್ಯ ಸ್ವಿಚ್:** `settings.skillsEnabled = false` ಎಲ್ಲಾ ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆಯನ್ನು ತಡೆಯುತ್ತದೆ ಮತ್ತು `/api/skills/executions` ನಲ್ಲಿ HTTP `503` ಹಿಂತಿರುಗಿಸುತ್ತದೆ. ರಿಜಿಸ್ಟ್ರಿ ಲೋಡ್ ಆಗುವುದನ್ನು ಮುಂದುವರಿಸುತ್ತದೆ.
- **ಹೊರಹರಿವನ್ನು ನಿರ್ಬಂಧಿಸಿ:** ಸಂಪೂರ್ಣವಾಗಿ ಏರ್-ಗ್ಯಾಪ್ ಮಾಡಿದ ಸ್ಯಾಂಡ್ಬಾಕ್ಸಿಂಗ್ಗಾಗಿ `SKILLS_SANDBOX_NETWORK_ENABLED` ಅನ್ನು ಹೊಂದಿಸದೆ ಬಿಡಿ (ಡೀಫಾಲ್ಟ್). ಪ್ರತಿ ಕರೆಗೆ `networkEnabled: true` ಇದ್ದರೂ ಮುಖ್ಯ ಗೇಟ್ನ ಅನುಮತಿ ಇನ್ನೂ ಅಗತ್ಯವಿರುತ್ತದೆ.
- **ನಿರ್ದಿಷ್ಟ ಇಮೇಜ್ಗಳನ್ನು ಅನುಮತಿಸಿ:** ಅನುಮತಿ ಪಟ್ಟಿಯನ್ನು ವಿಸ್ತರಿಸಲು `SKILLS_ALLOWED_SANDBOX_IMAGES="myorg/sandbox:1.0,node:22-alpine"` ಹೊಂದಿಸಿ.
- **ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆಗಳನ್ನು ಲೆಕ್ಕಪರಿಶೋಧಿಸಿ:** `/dashboard/skills/executions` ಮತ್ತು `omniroute_skills_executions` ಎರಡೂ `skill_executions` ಅನ್ನು ಕ್ವೆರಿ ಮಾಡುತ್ತವೆ. ಯಶಸ್ವಿ ರನ್ಗಳು `durationMs` ಅನ್ನು ಒಳಗೊಂಡಿರುತ್ತವೆ; ವಿಫಲತೆಗಳು `errorMessage` ಅನ್ನು ಒಳಗೊಂಡಿರುತ್ತವೆ.
- **ಕ್ಯಾಶ್ ಅಮಾನ್ಯೀಕರಣ:** ಕೈಯಾರೆ DB ಸಂಪಾದನೆಗಳ ನಂತರ `skillRegistry.invalidateCache()` ಅನ್ನು ಕರೆ ಮಾಡಿ; ಇಲ್ಲದಿದ್ದರೆ 60 s ಕಾಯಿರಿ.
- **ಅನಾಮಧೇಯ ವರ್ಕ್ಸ್ಪೇಸ್:** `apiKeyId` ಖಾಲಿಯಾಗಿರುವಾಗ, ಎಲ್ಲಾ ಕರೆಗಳು ಒಂದೇ `"anonymous"` ವರ್ಕ್ಸ್ಪೇಸ್ಗೆ ಹ್ಯಾಶ್ ಆಗುತ್ತವೆ — ಹಂಚಿಕೆ-ಅರಿವಿನ ಕೋಡ್ ಯಾವಾಗಲೂ ನೈಜ ಕೀಲಿಯನ್ನು ರವಾನಿಸಬೇಕು.

## ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆಯ ಜೀವನಚಕ್ರ (v3.8.16+)

`SkillExecutor` (`src/lib/skills/executor.ts`) ಎಂಬುದು ಪ್ರತಿಯೊಂದು ಕೌಶಲ್ಯ ಆಹ್ವಾನವನ್ನು ನಿರ್ವಹಿಸುವ **ಸಿಂಗಲ್ಟನ್** ಆಗಿದೆ. ಕಾಲಮಿತಿಗಳು, ಮರುಪ್ರಯತ್ನಗಳು ಮತ್ತು ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆಯ ಸ್ಥಿತಿಯನ್ನು ಡೀಬಗ್ ಮಾಡಲು ಅದರ ಜೀವನಚಕ್ರವನ್ನು ಅರ್ಥಮಾಡಿಕೊಳ್ಳುವುದು ಅತ್ಯಂತ ಮುಖ್ಯವಾಗಿದೆ.

### 5-ಹಂತದ ಜೀವನಚಕ್ರ

```
   execute() ಅನ್ನು ಕರೆಮಾಡಲಾಗಿದೆ
        │
        ▼
  ┌─────────────┐
  │  PENDING    │  ← ಸರದಿಯಲ್ಲಿದೆ, ಇನ್ನೂ ಪ್ರಾರಂಭವಾಗಿಲ್ಲ (DB ಸಾಲು ರಚಿಸಲಾಗಿದೆ)
  └──────┬──────┘
         │ ಹ್ಯಾಂಡ್ಲರ್ ಪ್ರಾರಂಭಿಸಿ
         ▼
  ┌─────────────┐
  │  RUNNING    │  ← ಕಾಲಮಿತಿಯೊಂದಿಗೆ ಹ್ಯಾಂಡ್ಲರ್ ಅನ್ನು ಆಹ್ವಾನಿಸಲಾಗಿದೆ
  └──────┬──────┘
         │
    ┌────┴────┬──────────┬──────────┐
    │         │          │          │
    ▼         ▼          ▼          ▼
  SUCCESS   ERROR     TIMEOUT   (ಬೇರೆ ಮಾರ್ಗವಿಲ್ಲ — ಪೇರೆಂಟ್ನಿಂದ ಸ್ಥಗಿತಗೊಳಿಸಲಾಗಿದೆ)
    │         │          │
    └────┬────┴──────────┘
         │
         ▼
   ಸ್ಥಿತಿ, ಔಟ್ಪುಟ್, durationMs ನೊಂದಿಗೆ DB ಸಾಲನ್ನು ನವೀಕರಿಸಲಾಗಿದೆ
```

### ಡೀಫಾಲ್ಟ್ ಕಾನ್ಫಿಗರೇಶನ್

| ಸೆಟ್ಟಿಂಗ್    | ಡೀಫಾಲ್ಟ್       | ಇದರ ಮೂಲಕ ಕಾನ್ಫಿಗರ್ ಮಾಡಬಹುದು          |
| ------------ | -------------- | ------------------------------------ |
| `timeout`    | `30000` (30ಸೆ) | `skillExecutor.setTimeout(ms)`       |
| `maxRetries` | `3`            | `skillExecutor.setMaxRetries(count)` |

> **ಮುಖ್ಯ**: ಎಕ್ಸಿಕ್ಯೂಟರ್ ಒಂದು ಸಿಂಗಲ್ಟನ್ ಆಗಿದೆ — `setTimeout()` ಅನ್ನು ಕರೆಮಾಡುವುದು ನಂತರದ ಎಲ್ಲಾ ಆಹ್ವಾನಗಳ ಮೇಲೆ ಜಾಗತಿಕವಾಗಿ ಪರಿಣಾಮ ಬೀರುತ್ತದೆ. ಪ್ರತಿ-ಕೌಶಲ್ಯದ ಕಾಲಮಿತಿಗಳಿಗೆ ಪ್ರಸ್ತುತ ಬೆಂಬಲವಿಲ್ಲ; ಪ್ರತಿ ಕೌಶಲ್ಯಕ್ಕೂ ವಿಭಿನ್ನ ಕಾಲಮಿತಿಗಳು ಅಗತ್ಯವಿದ್ದರೆ, ಪ್ರತ್ಯೇಕ ಪ್ರಕ್ರಿಯೆಗಳನ್ನು ಸಲ್ಲಿಸಿ ಅಥವಾ ಎಕ್ಸಿಕ್ಯೂಟರ್ ಅನ್ನು ಫೋರ್ಕ್ ಮಾಡಿ.

### ಸ್ಥಿತಿ ಮೌಲ್ಯಗಳು

`src/lib/skills/types.ts` ನಿಂದ:

```ts
enum SkillStatus {
  PENDING = "pending", // ಸರದಿಯಲ್ಲಿದೆ, ಇನ್ನೂ ಪ್ರಾರಂಭವಾಗಿಲ್ಲ
  RUNNING = "running", // ಹ್ಯಾಂಡ್ಲರ್ ಅನ್ನು ಆಹ್ವಾನಿಸಲಾಗಿದೆ
  SUCCESS = "success", // ಹ್ಯಾಂಡ್ಲರ್ ಮಾನ್ಯವಾದ ಔಟ್ಪುಟ್ ಅನ್ನು ಹಿಂದಿರುಗಿಸಿದೆ
  ERROR = "error", // ಹ್ಯಾಂಡ್ಲರ್ ಒಂದು ಎಕ್ಸೆಪ್ಶನ್ ಅನ್ನು ಎಸೆದಿದೆ
  TIMEOUT = "timeout", // ಎಕ್ಸಿಕ್ಯೂಟರ್ನ ಕಾಲಮಿತಿಯನ್ನು ಮೀರಿದೆ
}
```

> **ಗಮನಿಸಿ**: `TIMEOUT` ಸ್ಥಿತಿಯನ್ನು enum ನಲ್ಲಿ ವ್ಯಾಖ್ಯಾನಿಸಲಾಗಿದೆ, ಆದರೆ ಪ್ರಸ್ತುತ ಎಕ್ಸಿಕ್ಯೂಟರ್ ಅನುಷ್ಠಾನವು ಅದನ್ನು **ವಾಸ್ತವವಾಗಿ DBಗೆ ಬರೆಯುವುದಿಲ್ಲ** — ಕಾಲಮಿತಿಗಳು `"Skill execution timed out"` ಸಂದೇಶದೊಂದಿಗೆ `ERROR` ಆಗಿ ಕಾಣಿಸಿಕೊಳ್ಳುತ್ತವೆ. ಸ್ಥಿತಿ enum ಅನ್ನು ಭವಿಷ್ಯದ ಬಳಕೆಗಾಗಿ ಕಾಯ್ದಿರಿಸಲಾಗಿದೆ.

### ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆಗಳನ್ನು ಪರಿಶೀಲಿಸುವುದು

```ts
import { skillExecutor } from "omniroute/skills/executor";

// ID ಮೂಲಕ ನಿರ್ದಿಷ್ಟ ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆಯನ್ನು ಪಡೆಯಿರಿ
const exec = skillExecutor.getExecution("exec-uuid-123");
if (exec) {
  console.log(`${exec.skillName}: ${exec.status} in ${exec.durationMs}ms`);
}

// API ಕೀಗಾಗಿ ಇತ್ತೀಚಿನ ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡಿ
const recent = skillExecutor.listExecutions("api-key-id", 50, 0);
for (const e of recent) {
  console.log(`${e.skillName} → ${e.status} (${e.durationMs}ms)`);
}

// ಒಟ್ಟು ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆಗಳ ಸಂಖ್ಯೆಯನ್ನು ಎಣಿಸಿ
const total = skillExecutor.countExecutions("api-key-id");
```

### ಮರುಪ್ರಯತ್ನದ ನಡವಳಿಕೆ

`maxRetries` ಸೆಟ್ಟಿಂಗ್ ಅನ್ನು ಸಂಗ್ರಹಿಸಲಾಗುತ್ತದೆ, ಆದರೆ ಎಕ್ಸಿಕ್ಯೂಟರ್ನ `execute()` ವಿಧಾನವು ಅದನ್ನು **ಪ್ರಸ್ತುತ ಬಳಸುವುದಿಲ್ಲ** — ಅದು ಒಂದೇ ಪ್ರಯತ್ನವನ್ನು ಮಾತ್ರ ಮಾಡುತ್ತದೆ. ಭವಿಷ್ಯದ ಅನುಷ್ಠಾನಕ್ಕಾಗಿ ಮತ್ತು ಅದನ್ನು ಓದಲು ಬಯಸುವ ಹುಕ್ಗಳಿಗಾಗಿ `maxRetries` ಮೌಲ್ಯವನ್ನು ಬಹಿರಂಗಪಡಿಸಲಾಗಿದೆ.

ಸದ್ಯಕ್ಕೆ, ಮರುಪ್ರಯತ್ನಗಳನ್ನು ಕೌಶಲ್ಯ ಹ್ಯಾಂಡ್ಲರ್ನಲ್ಲಿಯೇ ಅನುಷ್ಠಾನಗೊಳಿಸಬೇಕು. ಅಂತರ್ನಿರ್ಮಿತ
ಕೌಶಲ್ಯಗಳನ್ನು ಎಕ್ಸಿಕ್ಯೂಟರ್ನಲ್ಲಿ ನೋಂದಾಯಿಸಲಾಗುತ್ತದೆ (ಉದಾ. `registerBuiltinSkills(executor)`
/ `registerBrowserSkill(executor)` ಅನ್ನು `src/lib/skills/builtin/` ನಲ್ಲಿ); ನೀವು ನೋಂದಾಯಿಸುವ ಯಾವುದೇ ಹ್ಯಾಂಡ್ಲರ್
ತನ್ನದೇ ಆದ ಮರುಪ್ರಯತ್ನ ಲೂಪ್ ಅನ್ನು ಸುತ್ತುವರಿಯಬಹುದು:

```ts
// ಕೌಶಲ್ಯ ಹ್ಯಾಂಡ್ಲರ್ನ ಒಳಗೆ
async function handler(input, ctx) {
  const maxRetries = 3;
  let lastError: Error | null = null;

  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      return await fetchSomething(input);
    } catch (err) {
      lastError = err as Error;
      if (attempt < maxRetries) {
        await new Promise((r) => setTimeout(r, 1000 * attempt));
      }
    }
  }
  throw lastError;
}
```

## SkillMode ವಿವರವಾಗಿ

`SkillMode` enum (`src/lib/skills/types.ts`) ಕೌಶಲ್ಯಗಳನ್ನು **ಯಾವಾಗ ಮತ್ತು ಹೇಗೆ** ಆಹ್ವಾನಿಸಲಾಗುತ್ತದೆ ಎಂಬುದನ್ನು ನಿಯಂತ್ರಿಸುತ್ತದೆ:

```ts
enum SkillMode {
  AUTO = "auto", // ಕೌಶಲ್ಯವನ್ನು ಯಾವಾಗ ಕರೆಯಬೇಕೆಂದು LLM ನಿರ್ಧರಿಸುತ್ತದೆ
  MANUAL = "manual", // ಬಳಕೆದಾರರ ಸ್ಪಷ್ಟ ವಿನಂತಿಯಿಂದ ಮಾತ್ರ ಆಹ್ವಾನಿಸಲಾಗುತ್ತದೆ
  HYBRID = "hybrid", // AUTO ಸ್ಕೋರಿಂಗ್ + ಹಸ್ತಚಾಲಿತ ಅತಿಕ್ರಮಣ
}
```

> **ಗಮನಿಸಿ**: ಕೋಡ್ಬೇಸ್ `SkillMode` ಅನ್ನು (AUTO/MANUAL/HYBRID) ವ್ಯಾಖ್ಯಾನಿಸುತ್ತದೆ, ಆದರೆ `Skill.mode` ಕ್ಷೇತ್ರವು ಬೇರೆ ಸ್ವರೂಪವನ್ನು (`"on" | "off" | "auto"`) ಬಳಸುತ್ತದೆ. ಅವು ಪರಸ್ಪರ ಸಂಬಂಧಿಸಿವೆ, ಆದರೆ ಒಂದೇ ಅಲ್ಲ — `SkillMode` ಕಾರ್ಯನಿರ್ವಾಹಕ ನೀತಿಗಾಗಿ ಮತ್ತು `Skill.mode` ಪ್ರತಿ ಕೌಶಲ್ಯದ ಸಕ್ರಿಯಗೊಳಿಸುವಿಕೆಗಾಗಿ ಬಳಸಲಾಗುತ್ತದೆ.

### ಪ್ರತಿಯೊಂದು ಮೋಡ್ ಅನ್ನು ಯಾವಾಗ ಬಳಸಬೇಕು

| ಮೋಡ್     | LLM ನಡವಳಿಕೆ                                                                                     | ಬಳಕೆಯ ಸಂದರ್ಭ                                             |
| -------- | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| `AUTO`   | ಅಗತ್ಯವೆಂದು ಪರಿಗಣಿಸಿದಾಗ LLM ಕೌಶಲ್ಯವನ್ನು ಕರೆಯಬಹುದು                                                | ಸಾಮಾನ್ಯ ಉದ್ದೇಶದ ಕೌಶಲ್ಯಗಳು (ಫೈಲ್ ಓದುವಿಕೆ, HTTP ವಿನಂತಿಗಳು) |
| `MANUAL` | LLM ಕೌಶಲ್ಯವನ್ನು ಕರೆಯಲು ಸಾಧ್ಯವಿಲ್ಲ; ಸ್ಪಷ್ಟವಾದ `executeSkill` API ಕರೆ ಮಾತ್ರ ಅದನ್ನು ಆಹ್ವಾನಿಸುತ್ತದೆ | ಸೂಕ್ಷ್ಮ ಕಾರ್ಯಾಚರಣೆಗಳು (ಡೇಟಾಬೇಸ್ ಬರವಣಿಗೆಗಳು, ಪಾವತಿಗಳು)    |
| `HYBRID` | LLM ಕೌಶಲ್ಯವನ್ನು ಸೂಚಿಸಬಹುದು; ಬಳಕೆದಾರರು ದೃಢೀಕರಿಸಬೇಕು                                              | ಅಡ್ಡ ಪರಿಣಾಮಗಳನ್ನು ಹೊಂದಿದ್ದರೂ ಅಪಾಯಕಾರಿಯಲ್ಲದ ಕೌಶಲ್ಯಗಳು     |

### AUTO ಸ್ಕೋರಿಂಗ್

`AUTO` ಮೋಡ್ ಸಕ್ರಿಯವಾಗಿರುವಾಗ, ಪ್ರತಿ ಅಭ್ಯರ್ಥಿ ಕೌಶಲ್ಯವನ್ನು ವಿನಂತಿಯ
ಸಂದರ್ಭದೊಂದಿಗೆ `src/lib/skills/injection.ts` ನಲ್ಲಿರುವ `scoreAutoSkill()` ಮೂಲಕ ಹೋಲಿಸಿ ಸ್ಕೋರ್ ಮಾಡಲಾಗುತ್ತದೆ — ಇದು ಸಂಯೋಜಕ
ಪೂರ್ಣಾಂಕ ಅಂಕಗಳ ವ್ಯವಸ್ಥೆಯಾಗಿದೆ (ಕೌಶಲ್ಯ-ಹೆಸರಿನ ಹೊಂದಾಣಿಕೆ, ಹೆಸರು/ಟ್ಯಾಗ್/ವಿವರಣೆಯ ಟೋಕನ್ ಅತಿವ್ಯಾಪ್ತಿ,
ಹಿನ್ನೆಲೆ-ಕಾರಣದ ಸುಳಿವುಗಳು, ಪೂರೈಕೆದಾರ-ಸುಳಿವಿನ ಬೋನಸ್/ದಂಡ). `score >= AUTO_MIN_SCORE = 3` ಹೊಂದಿರುವ ಅಗ್ರ
`AUTO_MAX_SKILLS = 5` ಕೌಶಲ್ಯಗಳನ್ನು ಕರೆಮಾಡಬಹುದಾದ ಪರಿಕರಗಳಾಗಿ
ಸೇರಿಸಲಾಗುತ್ತದೆ; ಸಮ ಅಂಕಗಳಿದ್ದರೆ ಮೊದಲು `installCount`, ನಂತರ ಹೆಸರಿನ ಆಧಾರದಲ್ಲಿ ನಿರ್ಧರಿಸಲಾಗುತ್ತದೆ. ಸಂಪೂರ್ಣ ಅಂಕಪಟ್ಟಿಗಾಗಿ ಈ ದಸ್ತಾವೇಜಿನ ಹಿಂದಿನ
[**ಪರಿಕರ ಸ್ಕೀಮಾ ರಚನೆ → AUTO ಸ್ಕೋರಿಂಗ್**](#auto-scoring) ವಿಭಾಗವನ್ನು ನೋಡಿ;
ಯಾವುದೇ float `0.6`-ಶೈಲಿಯ ಮಿತಿ ಇಲ್ಲ ಮತ್ತು `registry.ts` ಸ್ಕೋರಿಂಗ್ ಇಲ್ಲ.

## ಅಂತರ್ನಿರ್ಮಿತ ಕೌಶಲ್ಯಗಳ ಕ್ಯಾಟಲಾಗ್

OmniRoute, `src/lib/skills/builtin/` ನಲ್ಲಿ ಸಂಗ್ರಹಿಸಲಾದ ಆಯ್ದ ಅಂತರ್ನಿರ್ಮಿತ ಕೌಶಲ್ಯಗಳ ಗುಂಪಿನೊಂದಿಗೆ ಬರುತ್ತದೆ. ಹೆಚ್ಚು ಸಾಮಾನ್ಯವಾದವುಗಳು:

### ಬ್ರೌಸರ್ ಸ್ವಯಂಚಾಲನಾ ಕೌಶಲ್ಯ

ಬ್ರೌಸರ್ ಕೌಶಲ್ಯವು (`src/lib/skills/builtin/browser.ts`) Playwright/Puppeteer ಮೂಲಕ ಹೆಡ್ಲೆಸ್ ಬ್ರೌಸರ್ ಸ್ವಯಂಚಾಲನೆಯನ್ನು ಒದಗಿಸುತ್ತದೆ. **ಇದನ್ನು ಅನುಷ್ಠಾನಗೊಳಿಸಲಾಗಿದೆ, ಆದರೆ ಡೀಫಾಲ್ಟ್ ಕೌಶಲ್ಯಗಳ ಕ್ಯಾಟಲಾಗ್ನಲ್ಲಿ ಸೇರಿಸಲಾಗಿಲ್ಲ** — ಇದನ್ನು ಬಳಸಲು, ಬ್ರೌಸರ್ ವಿಸ್ತರಣೆಯ ಪ್ಲಗಿನ್ ಅನ್ನು ಪ್ರತ್ಯೇಕವಾಗಿ ಸ್ಥಾಪಿಸಿ.

```ts
// ನಿಮ್ಮ ಸಂರಚನೆಯಲ್ಲಿ ಸಕ್ರಿಯಗೊಳಿಸಿ
const config: SkillConfig = {
  enabled: true,
  mode: SkillMode.MANUAL, // ಯಾವಾಗಲೂ ಸ್ಪಷ್ಟವಾದ ಆಹ್ವಾನವನ್ನು ಅಗತ್ಯಪಡಿಸಿ
  allowedSkills: ["browser"],
  timeout: 60000, // ಪುಟ ಲೋಡ್ಗಳಿಗೆ 60s
  maxRetries: 1,
};
```

### ಇತರ ಅಂತರ್ನಿರ್ಮಿತ ವರ್ಗಗಳು

| ವರ್ಗ                   | ಕೌಶಲ್ಯಗಳು                                                     | ಮೋಡ್   |
| ---------------------- | ------------------------------------------------------------- | ------ |
| ಫೈಲ್ I/O               | `file_read`, `file_write`                                     | AUTO   |
| HTTP                   | `http_request`                                                | AUTO   |
| ಹುಡುಕಾಟ                | `web_search`                                                  | AUTO   |
| ಕೋಡ್ ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆ | `eval_code` (ಸ್ಯಾಂಡ್ಬಾಕ್ಸ್ ಮಾಡಿದ JavaScript/Python)           | HYBRID |
| ಸಿಸ್ಟಮ್                | `execute_command` (ಸ್ಯಾಂಡ್ಬಾಕ್ಸ್ ಮಾಡಿದ CLI ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆ) | MANUAL |

### ಕಸ್ಟಮ್ ಕೌಶಲ್ಯವನ್ನು ಸೇರಿಸುವುದು

ಪ್ಲಗಿನ್ ವ್ಯವಸ್ಥೆಯ ಮೂಲಕ ಕಸ್ಟಮ್ ಕೌಶಲ್ಯವನ್ನು ಹೇಗೆ ಸೇರಿಸುವುದು ಎಂಬುದಕ್ಕಾಗಿ [ಪ್ಲಗಿನ್ SDK ಮತ್ತು ಕೌಶಲ್ಯಗಳ ಏಕೀಕರಣ](./PLUGIN_SDK.md) ಅನ್ನು ನೋಡಿ.
