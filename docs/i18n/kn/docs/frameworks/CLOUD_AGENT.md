> **ಅಧಿಕೃತ ಮೂಲ:** `src/lib/cloudAgent/` ಮತ್ತು `src/app/api/v1/agents/tasks/`
> **ಕೊನೆಯದಾಗಿ ನವೀಕರಿಸಿದ್ದು:** 2026-06-28 — v3.8.40 (frontmatter ನವೀಕರಣ; cursor-cloud ಸೇರಿದಂತೆ 4 ಏಜೆಂಟ್ಗಳು)

OmniRoute ಮೂರನೇ-ಪಕ್ಷದ ಕ್ಲೌಡ್-ಹೋಸ್ಟ್ ಮಾಡಲಾದ ಕೋಡಿಂಗ್ ಏಜೆಂಟ್ಗಳನ್ನು (Codex Cloud, Cursor,
Devin, Jules) ದೀರ್ಘಾವಧಿಯ ಕಾರ್ಯಗಳಾಗಿ ಸಂಯೋಜಿಸುತ್ತದೆ. ಪ್ರತಿ ಏಜೆಂಟ್ ಅನ್ನು ಏಕರೂಪದ ಇಂಟರ್ಫೇಸ್ನ ಹಿಂದೆ ಸುತ್ತಿಡಲಾಗಿದೆ, ಇದರಿಂದ
ಕ್ಲೈಂಟ್ಗಳು ಪೂರೈಕೆದಾರ-ನಿರ್ದಿಷ್ಟ API ಗಳನ್ನು ನಿರ್ವಹಿಸದೆಯೇ ಪ್ರಾಂಪ್ಟ್ + ರೆಪೊ URL ಅನ್ನು ಸಲ್ಲಿಸಿ ಫಲಿತಾಂಶಗಳನ್ನು
ಪಡೆಯಬಹುದು.

Cloud Agent ಕಾರ್ಯವು ಸಾಮಾನ್ಯ ಚಾಟ್ ಪೂರ್ಣಗೊಳಿಸುವಿಕೆ **ಅಲ್ಲ**. ಇದು ನಿಮಿಷಗಳಿಂದ ಗಂಟೆಗಳವರೆಗೆ
ತೆಗೆದುಕೊಳ್ಳಬಹುದಾದ, Pull Request ಅನ್ನು ತನ್ನ ಕಲಾಕೃತಿಯಾಗಿ ರಚಿಸಬಹುದಾದ, ಅನುಸರಣೆ ಸಂದೇಶಗಳನ್ನು ಮತ್ತು
(ಕೆಲವು ಪೂರೈಕೆದಾರರಲ್ಲಿ) ಯೋಜನೆ ಅನುಮೋದನೆಯ ಹಂತಗಳನ್ನು ಬೆಂಬಲಿಸುವ ದೀರ್ಘಕಾಲ ಉಳಿಯುವ, ಬಹು-ಹಂತದ ಕೆಲಸದ ಘಟಕವಾಗಿದೆ.

| ಪೂರೈಕೆದಾರ ID   | ಕ್ಲಾಸ್             | ಮೂಲ                                   | ಅಪ್ಸ್ಟ್ರೀಮ್ ಮೂಲ URL                     | ಯೋಜನೆ ಅನುಮೋದನೆ |
| -------------- | ------------------ | ------------------------------------- | --------------------------------------- | -------------- |
| `jules`        | `JulesAgent`       | `src/lib/cloudAgent/agents/jules.ts`  | `https://jules.googleapis.com/v1alpha`  | ಹೌದು           |
| `devin`        | `DevinAgent`       | `src/lib/cloudAgent/agents/devin.ts`  | `https://api.devin.ai/v1`               | ಹೌದು           |
| `codex-cloud`  | `CodexCloudAgent`  | `src/lib/cloudAgent/agents/codex.ts`  | `https://api.openai.com/v1/codex/cloud` | ಇಲ್ಲ (ಸ್ವಯಂ)   |
| `cursor-cloud` | `CursorCloudAgent` | `src/lib/cloudAgent/agents/cursor.ts` | `https://api.cursor.com/v0`             | ಇಲ್ಲ (ಸ್ವಯಂ)   |

ರೆಜಿಸ್ಟ್ರಿ: `src/lib/cloudAgent/registry.ts` — `getAgent(providerId)`,
`getAvailableAgents()`, ಮತ್ತು `isCloudAgentProvider(providerId)` ಅನ್ನು ಎಕ್ಸ್ಪೋರ್ಟ್ ಮಾಡುತ್ತದೆ. ರೆಜಿಸ್ಟ್ರಿಯು
ಮಾಡ್ಯೂಲ್ ಲೋಡ್ ಆಗುವಾಗ ಭರ್ತಿಯಾಗುವ ಸರಳ ಇನ್-ಮೆಮೊರಿ `Record<string, CloudAgentBase>` ಆಗಿದೆ.

## ವಾಸ್ತುಶಿಲ್ಪ

```
ಕ್ಲೈಂಟ್ (ಡ್ಯಾಶ್ಬೋರ್ಡ್ / CLI / API)
  → POST /api/v1/agents/tasks (ನಿರ್ವಹಣಾ ದೃಢೀಕರಣ ಅಗತ್ಯ)
    → CreateCloudAgentTaskSchema ಮೌಲ್ಯೀಕರಣ (Zod)
    → registry.getAgent(providerId)
    → getCloudAgentCredentials(providerId)
      └─ getProviderConnections({ provider, isActive: true }) ನಿಂದ ಪಡೆಯುತ್ತದೆ
         (ಮೊದಲು apiKey, ಪರ್ಯಾಯವಾಗಿ accessToken)
    → agent.createTask({ prompt, source, options }, credentials)
      └─ ಅಪ್ಸ್ಟ್ರೀಮ್ ಪೂರೈಕೆದಾರ API ಗೆ HTTP POST
      └─ ಆಂತರಿಕ id + externalId ಹೊಂದಿರುವ CloudAgentTask ಅನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ
    → cloud_agent_tasks (SQLite) ಗೆ insertCloudAgentTask(...)

ಪೋಲಿಂಗ್ (ಓದುವಾಗ ಲೇಜಿ ಸಿಂಕ್):
  GET /api/v1/agents/tasks/[id]
    → getCloudAgentTaskById(id)
    → agent.getStatus(externalId, credentials)  // ಸ್ಥಿತಿ + ಚಟುವಟಿಕೆಗಳನ್ನು ನವೀಕರಿಸುತ್ತದೆ
    → ಹೊಸ ಸ್ಥಿತಿ, ಫಲಿತಾಂಶ, completed_at ಬಳಸಿ updateCloudAgentTask(...)
    → ಸೀರಿಯಲೈಸ್ ಮಾಡಿದ ಕಾರ್ಯವನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ

ಸಂವಹನಗಳು:
  POST /api/v1/agents/tasks/[id]  body: { action: "approve" | "message" | "cancel" }
    → agent.approvePlan(externalId, credentials)        "approve" ಗಾಗಿ
    → agent.sendMessage(externalId, message, credentials) "message" ಗಾಗಿ
    → ಸ್ಥಿತಿಯು "cancelled" ಗೆ ಬದಲಾಗುತ್ತದೆ                       "cancel" ಗಾಗಿ (ಸ್ಥಳೀಯವಾಗಿ ಮಾತ್ರ)
```

ಸಿಂಕ್ **ಲೇಜಿ** ಆಗಿದೆ: ಪ್ರತಿ `GET /tasks/[id]` ಕೋರಿಕೆಯಲ್ಲೂ ಸ್ಥಿತಿಯನ್ನು ಅಪ್ಸ್ಟ್ರೀಮ್ನಿಂದ ನವೀಕರಿಸಲಾಗುತ್ತದೆ.
ಯಾವುದೇ ಹಿನ್ನೆಲೆ ಪೋಲರ್ ಇಲ್ಲ. ತಾಜಾ ಸ್ಥಿತಿ ಅಗತ್ಯವಿರುವ ಡ್ಯಾಶ್ಬೋರ್ಡ್ಗಳು GET
ಎಂಡ್ಪಾಯಿಂಟ್ ಅನ್ನು ಸೂಕ್ತ ಮಧ್ಯಂತರದಲ್ಲಿ ಪೋಲ್ ಮಾಡಬೇಕು.

## `CloudAgentBase` ಇಂಟರ್ಫೇಸ್

ಮೂಲ: `src/lib/cloudAgent/baseAgent.ts`

```typescript
export interface AgentCredentials {
  apiKey: string;
  baseUrl?: string;
}

export interface CreateTaskParams {
  prompt: string;
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
}

export interface GetStatusResult {
  status: CloudAgentStatus;
  externalId?: string;
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
}

export abstract class CloudAgentBase {
  abstract readonly providerId: string;
  abstract readonly baseUrl: string;

  abstract createTask(p: CreateTaskParams, c: AgentCredentials): Promise<CloudAgentTask>;
  abstract getStatus(externalId: string, c: AgentCredentials): Promise<GetStatusResult>;
  abstract approvePlan(externalId: string, c: AgentCredentials): Promise<void>;
  abstract sendMessage(
    externalId: string,
    message: string,
    c: AgentCredentials
  ): Promise<CloudAgentActivity>;
  abstract listSources(
    c: AgentCredentials
  ): Promise<{ name: string; url: string; branch?: string }[]>;

  protected mapStatus(raw: string): CloudAgentStatus; // ಹ್ಯೂರಿಸ್ಟಿಕ್ ಅಪ್ಸ್ಟ್ರೀಮ್-ಸ್ಟ್ರಿಂಗ್ → enum
  protected generateTaskId(): string; // `task_<ts>_<rand>`
  protected generateActivityId(): string; // `act_<ts>_<rand>`
}
```

`CodexCloudAgent.approvePlan` ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ದೋಷವನ್ನು ಎಸೆಯುತ್ತದೆ — Codex Cloud ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಯೋಜಿಸುತ್ತದೆ ಮತ್ತು
ಇದರಲ್ಲಿ ಅನುಮೋದನಾ ಗೇಟ್ ಇಲ್ಲ. `CodexCloudAgent.listSources` `[]` ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ.

`CursorCloudAgent`, Cursorನ Background / Cloud Agents ಅನ್ನು ಅದರ ಅಧಿಕೃತ REST
API (`api.cursor.com/v0`) ಮೂಲಕ **ಬಳಕೆದಾರ ಅಥವಾ ಸೇವಾ-ಖಾತೆಯ API ಕೀ** ಬಳಸಿ ನಿರ್ವಹಿಸುತ್ತದೆ — ಇದು Cursor IDEಯ OAuth ಸೆಷನ್ ಅನ್ನು ಮರುಬಳಕೆ ಮಾಡುವುದಕ್ಕಿಂತ ಸುರಕ್ಷಿತವಾದ,
ಪ್ರಥಮ-ಪಕ್ಷದ ಪರ್ಯಾಯವಾಗಿದೆ (ನಿಷೇಧದ ಅಪಾಯದ ಎಚ್ಚರಿಕೆಯನ್ನು ಹೊಂದಿರುವ ಪ್ರೊವೈಡರ್ `cursor`).
ಇದು ಸರಳ REST ಅಡಾಪ್ಟರ್ ಆಗಿದೆ (`@cursor/sdk` ಮೂಲಭೂತ
ಅವಲಂಬನೆ ಇಲ್ಲ). `approvePlan` ದೋಷವನ್ನು ಎಸೆಯುತ್ತದೆ (Cursor ಏಜೆಂಟ್ಗಳು ಸ್ವಾಯತ್ತವಾಗಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತವೆ); `listSources` ಕೀ ಮೂಲಕ
ತಲುಪಬಹುದಾದ ರೆಪೊಸಿಟರಿಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ. Cursor ದೊಡ್ಡಕ್ಷರದ ಸ್ಥಿತಿ enumಗಳನ್ನು
(`CREATING`/`RUNNING`/`FINISHED`/`ERROR`) ಹಿಂತಿರುಗಿಸುತ್ತದೆ, ಇವುಗಳನ್ನು ಹಂಚಿಕೊಂಡಿರುವ
`CloudAgentStatus`ಗೆ ಸ್ಪಷ್ಟವಾಗಿ ಮ್ಯಾಪ್ ಮಾಡಲಾಗುತ್ತದೆ. `baseUrl` ಅನ್ನು ಪ್ರತಿ ಕ್ರೆಡೆನ್ಶಿಯಲ್ಗೆ ಅತಿಕ್ರಮಿಸಬಹುದಾಗಿರುವುದರಿಂದ, ಕೋಡ್ ಬದಲಾವಣೆಯಿಲ್ಲದೆ
API ಆವೃತ್ತಿ/ಪಥವನ್ನು ಸರಿಪಡಿಸಬಹುದು.

## ಡೊಮೇನ್ ಪ್ರಕಾರಗಳು

ಮೂಲ: `src/lib/cloudAgent/types.ts`

```typescript
export const CLOUD_AGENT_STATUS = {
  QUEUED: "queued",
  RUNNING: "running",
  AWAITING_APPROVAL: "awaiting_approval",
  COMPLETED: "completed",
  FAILED: "failed",
  CANCELLED: "cancelled",
} as const;

export interface CloudAgentSource {
  repoName: string;
  repoUrl: string; // ಮಾನ್ಯ URL ಆಗಿರಬೇಕು
  branch?: string;
}

export interface CloudAgentResult {
  prUrl?: string;
  prNumber?: number;
  commitMessage?: string;
  diffUrl?: string;
  summary?: string;
  duration?: number; // ಸೆಕೆಂಡುಗಳು, ಧನಾತ್ಮಕ ಪೂರ್ಣಾಂಕ
  cost?: number; // ಧನಾತ್ಮಕ ದಶಮಾಂಶ ಸಂಖ್ಯೆ
}

export interface CloudAgentActivity {
  id: string;
  type: "plan" | "command" | "code_change" | "message" | "error" | "completion";
  content: string;
  timestamp: string; // ISO 8601
  metadata?: Record<string, unknown>;
}

export interface CloudAgentTask {
  id: string; // ಆಂತರಿಕ `task_...` id
  providerId: "jules" | "devin" | "codex-cloud" | "cursor-cloud";
  externalId?: string; // ಅಪ್ಸ್ಟ್ರೀಮ್ ಪ್ರೊವೈಡರ್ನ id
  status: CloudAgentStatus;
  prompt: string; // 1..10000 ಅಕ್ಷರಗಳು
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
  createdAt: string;
  updatedAt: string;
  completedAt?: string;
}
```

ಮೌಲ್ಯೀಕರಣ ಸ್ಕೀಮಾಗಳನ್ನು (`CreateCloudAgentTaskSchema`, `UpdateCloudAgentTaskSchema`)
ಪ್ರಕಾರಗಳ ಜೊತೆಗೆ ರಫ್ತು ಮಾಡಲಾಗುತ್ತದೆ ಮತ್ತು ಅವುಗಳನ್ನು ರೂಟ್ ಹ್ಯಾಂಡ್ಲರ್ಗಳು ಬಳಸುತ್ತವೆ.

## ಡೇಟಾಬೇಸ್

ಮೂಲ: `src/lib/cloudAgent/db.ts` — ಟೇಬಲ್ ಅನ್ನು
`createCloudAgentTaskTable()` ಮೂಲಕ ಅಗತ್ಯವಿದ್ದಾಗ ರಚಿಸಲಾಗುತ್ತದೆ (`src/lib/cloudAgent/index.ts` ನಿಂದ
ಮಾಡ್ಯೂಲ್ ಆಮದು ಮಾಡುವಾಗಲೂ ಇದನ್ನು ಕರೆಯಲಾಗುತ್ತದೆ).

```sql
CREATE TABLE IF NOT EXISTS cloud_agent_tasks (
  id           TEXT PRIMARY KEY,
  provider_id  TEXT NOT NULL,
  external_id  TEXT,
  status       TEXT NOT NULL DEFAULT 'queued',
  prompt       TEXT NOT NULL,
  source       TEXT NOT NULL,             -- JSON
  options      TEXT DEFAULT '{}',         -- JSON
  result       TEXT,                       -- JSON
  activities   TEXT DEFAULT '[]',          -- JSON
  error        TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_provider ON cloud_agent_tasks(provider_id);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_status   ON cloud_agent_tasks(status);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_created  ON cloud_agent_tasks(created_at DESC);
```

SQL ಇಂಜೆಕ್ಷನ್ ತಡೆಯಲು `updateCloudAgentTask` ಒಂದು **ಕಾಲಮ್ ಶ್ವೇತಪಟ್ಟಿಯನ್ನು** ಕಡ್ಡಾಯಗೊಳಿಸುತ್ತದೆ:
`status`, `prompt`, `source`, `options`, `result`, `activities`, `error`,
`completed_at`. ಭಾಗಶಃ ಅಪ್ಡೇಟ್ನಲ್ಲಿರುವ ಯಾವುದೇ ಇತರ ಕೀಲಿಯನ್ನು ಯಾವುದೇ ಸೂಚನೆಯಿಲ್ಲದೆ ಕೈಬಿಡಲಾಗುತ್ತದೆ.

## REST API — ಕಾರ್ಯದ ಜೀವನಚಕ್ರ

**ದೃಢೀಕರಣ:** ಎಲ್ಲಾ `/api/v1/agents/tasks*` ಎಂಡ್ಪಾಯಿಂಟ್ಗಳಿಗೆ **ನಿರ್ವಹಣಾ ದೃಢೀಕರಣ**
ಅಗತ್ಯವಿದೆ (`requireCloudAgentManagementAuth`, `src/lib/api/requireManagementAuth` ನಲ್ಲಿರುವ
`requireManagementAuth` ಅನ್ನು ಸುತ್ತುವರಿಯುತ್ತದೆ). commit `588a0333`
(_"fix(auth): require management auth for agent and cooldown APIs"_) ನಂತರ ಇದನ್ನು ಕಡ್ಡಾಯಗೊಳಿಸಲಾಗಿದೆ.

| ವಿಧಾನ   | ಮಾರ್ಗ                         | ಉದ್ದೇಶ                                                                    |
| ------- | ----------------------------- | ------------------------------------------------------------------------- |
| OPTIONS | `/api/v1/agents/tasks`        | CORS ಪೂರ್ವಪರಿಶೀಲನೆ                                                        |

| POST    | `/api/v1/agents/tasks`        | ಕಾರ್ಯವನ್ನು ರಚಿಸುವುದು (ಅಪ್ಸ್ಟ್ರೀಮ್ಗೆ ಕಳುಹಿಸಿ + ಉಳಿಸುತ್ತದೆ)                 |

| POST    | `/api/v1/agents/tasks/[id]`   | ಕ್ರಿಯೆ: `approve` / `message` / `cancel`                                  |

ಬಿಲ್ಲಿಂಗ್ ನಿಲ್ಲಿಸಲು, ಪೂರೈಕೆದಾರರ ಸ್ವಂತ ಕನ್ಸೋಲ್ನಲ್ಲಿ ಕಾರ್ಯವನ್ನು ಮುಕ್ತಾಯಗೊಳಿಸಿ.

## REST API — ಕ್ಲೌಡ್ ಪೂರೈಕೆದಾರ ಪ್ಲಂಬಿಂಗ್

`src/app/api/cloud/` ಅಡಿಯಲ್ಲಿರುವ ಈ ಸಹಾಯಕ ಎಂಡ್ಪಾಯಿಂಟ್ಗಳನ್ನು ದೂರಸ್ಥ ಕ್ಲೈಂಟ್ಗಳು
(CLI, Electron ಆ್ಯಪ್ ಅಥವಾ ಸಿಂಕ್ ವರ್ಕರ್ಗಳು) ಪೂರೈಕೆದಾರರ ಸಂಪರ್ಕ ಮೆಟಾಡೇಟಾವನ್ನು ಓದಲು
ಮತ್ತು ಮಾದರಿ ಅಲಿಯಾಸ್ಗಳನ್ನು ಪರಿಹರಿಸಲು ಬಳಸುತ್ತವೆ. ಇವು ಕಾರ್ಯ ಎಂಡ್ಪಾಯಿಂಟ್ಗಳು ಬಳಸುವ ನಿರ್ವಹಣಾ ದೃಢೀಕರಣವನ್ನಲ್ಲ, **ಸಾಮಾನ್ಯ API ಕೀ** ಮೂಲಕ
(`validateApiKey` ಬಳಸಿ) ದೃಢೀಕರಿಸಲ್ಪಡುತ್ತವೆ.

| ವಿಧಾನ | ಪಥ                              | ಉದ್ದೇಶ                                                                                  |
| ----- | ------------------------------- | --------------------------------------------------------------------------------------- |
| POST  | `/api/cloud/auth`               | API ಕೀಯನ್ನು ಮೌಲ್ಯೀಕರಿಸಿ, ಮರೆಮಾಡಿದ ಸಂಪರ್ಕ ಮೆಟಾಡೇಟಾ + ಮಾದರಿ ಅಲಿಯಾಸ್ಗಳನ್ನು ಹಿಂತಿರುಗಿಸುವುದು |
| PUT   | `/api/cloud/credentials/update` | `accessToken` / `refreshToken` / `expiresAt` ಅನ್ನು ನವೀಕರಿಸುವುದು                         |
| POST  | `/api/cloud/model/resolve`      | ಮಾದರಿ ಅಲಿಯಾಸ್ ಅನ್ನು `{ provider, model }` ಗೆ ಪರಿಹರಿಸುವುದು                               |
| GET   | `/api/cloud/models/alias`       | ಎಲ್ಲಾ ಮಾದರಿ ಅಲಿಯಾಸ್ಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡುವುದು                                                |
| PUT   | `/api/cloud/models/alias`       | ಮಾದರಿ ಅಲಿಯಾಸ್ ಅನ್ನು ಹೊಂದಿಸುವುದು (ಮತ್ತು ಸಕ್ರಿಯಗೊಳಿಸಿದ್ದರೆ ಕ್ಲೌಡ್ಗೆ ಸ್ವಯಂ-ಸಿಂಕ್ ಮಾಡುವುದು) |

`/api/cloud/auth` ಎಂದಿಗೂ ಮೂಲ `apiKey` / `accessToken` / `refreshToken` ಅನ್ನು ಹಿಂತಿರುಗಿಸುವುದಿಲ್ಲ. ಇದು
`hasApiKey`, `hasAccessToken`, `hasRefreshToken` ಮತ್ತು ಮರೆಮಾಡಿದ ಮುನ್ನೋಟವನ್ನು
(`maskedApiKey`: ಮೊದಲ 4 + `****` + ಕೊನೆಯ 4) ಹಿಂತಿರುಗಿಸುತ್ತದೆ.

## ರುಜುವಾತುಗಳ ಪರಿಹಾರ

`src/lib/cloudAgent/api.ts` ನಲ್ಲಿರುವ `getCloudAgentCredentials(providerId)`:

1. `getProviderConnections({ provider: providerId, isActive: true })` ಮೂಲಕ ಸಕ್ರಿಯ ಪೂರೈಕೆದಾರ ಸಂಪರ್ಕಗಳನ್ನು ಲೋಡ್ ಮಾಡುತ್ತದೆ.
2. ಪ್ರತಿ ಸಂಪರ್ಕಕ್ಕೂ `apiKey`ಗೆ (ಟ್ರಿಮ್ ಮಾಡಲಾದ) ಆದ್ಯತೆ ನೀಡುತ್ತದೆ. ಇಲ್ಲದಿದ್ದರೆ `accessToken` ಅನ್ನು ಬಳಸುತ್ತದೆ.
3. ಮೊದಲ ಖಾಲಿಯಲ್ಲದ ಟೋಕನ್ ಅನ್ನು `{ apiKey: token }` ರೂಪದಲ್ಲಿ ಹಿಂತಿರುಗಿಸುತ್ತದೆ.
4. ಬಳಸಬಹುದಾದ ಟೋಕನ್ ಕಂಡುಬರದಿದ್ದರೆ `null` ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ — API ಈ ಸಂದೇಶದೊಂದಿಗೆ `400` ಅನ್ನು ಪ್ರತಿಕ್ರಿಯಿಸುತ್ತದೆ:
   `"ಕ್ಲೌಡ್ ಏಜೆಂಟ್ ಪೂರೈಕೆದಾರಕ್ಕಾಗಿ ಯಾವುದೇ ಸಕ್ರಿಯ ರುಜುವಾತುಗಳನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾಗಿಲ್ಲ: <id>"`.

ಇದರರ್ಥ ಕ್ಲೌಡ್ ಏಜೆಂಟ್ಗಳು ಸಾಮಾನ್ಯ LLM ಪೂರೈಕೆದಾರರಂತೆಯೇ ಅದೇ ಪೂರೈಕೆದಾರ ಸಂಪರ್ಕ ಕೋಷ್ಟಕವನ್ನು
ಮರುಬಳಕೆ ಮಾಡುತ್ತವೆ. Jules ಅನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಲು, `provider: "jules"` ಮತ್ತು ಭರ್ತಿ ಮಾಡಲಾದ
`apiKey` ಹೊಂದಿರುವ ಸಕ್ರಿಯ ಸಂಪರ್ಕವನ್ನು ರಚಿಸಿ.

## ಡ್ಯಾಶ್ಬೋರ್ಡ್

ಮೂಲ: `src/app/(dashboard)/dashboard/cloud-agents/page.tsx`

ಈ ಕೆಳಗಿನ ಕಾರ್ಯಗಳನ್ನು ಮಾಡುವ `"use client"` React ಪುಟ:

- ಕಾರ್ಯಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡುತ್ತದೆ (`GET /api/v1/agents/tasks` ಮೂಲಕ ನಿಯತಕಾಲಿಕವಾಗಿ ಪರಿಶೀಲಿಸಲಾಗುತ್ತದೆ).
- `CreateCloudAgentTaskSchema` ಗೆ ಮ್ಯಾಪ್ ಆಗುವ ಫಾರ್ಮ್ ಮೂಲಕ ಹೊಸ ಕಾರ್ಯಗಳನ್ನು ಸಲ್ಲಿಸುತ್ತದೆ.
- ಸ್ಥಿತಿ ಬ್ಯಾಡ್ಜ್ಗಳನ್ನು (`queued`, `running`, `awaiting_approval`, `completed`,
  `failed`, `cancelled`) ತೋರಿಸುತ್ತದೆ ಮತ್ತು `activities[]` ಕಾಲರೇಖೆಯನ್ನು ರೆಂಡರ್ ಮಾಡುತ್ತದೆ.
- `status === "completed"` ಆಗಿರುವಾಗ `result.prUrl` / `commitMessage` / `summary` ಅನ್ನು ಪ್ರದರ್ಶಿಸುತ್ತದೆ.

## A2A ಜೊತೆ ಏಕೀಕರಣ

A2A ಕೌಶಲ್ಯವೊಂದನ್ನು ನೋಂದಾಯಿಸುವ ಮೂಲಕ ಕ್ಲೌಡ್ ಏಜೆಂಟ್ಗಳನ್ನು A2A ಕೌಶಲ್ಯಗಳಾಗಿ ಬಹಿರಂಗಪಡಿಸಬಹುದು. ಆ ಕೌಶಲ್ಯವು
ತನ್ನ `tasks/send` ಹ್ಯಾಂಡ್ಲರ್ ಅನ್ನು `getAgent(...).createTask(...)` ಗೆ ನಿಯೋಜಿಸುತ್ತದೆ ಮತ್ತು A2A ಕಾರ್ಯದ
ಸ್ಥಿತಿ ಈವೆಂಟ್ಗಳನ್ನು JSON-RPC 2.0 ಪ್ರೋಟೋಕಾಲ್ಗೆ ಅನುವಾದಿಸುತ್ತದೆ. [A2A-SERVER.md](./A2A-SERVER.md) ನೋಡಿ.

## ಹೊಸ ಕ್ಲೌಡ್ ಏಜೆಂಟ್ ಸೇರಿಸುವುದು

1. `CloudAgentBase` ಅನ್ನು ವಿಸ್ತರಿಸುವ `src/lib/cloudAgent/agents/<name>.ts` ಅನ್ನು ರಚಿಸಿ.
2. `createTask`, `getStatus`, `approvePlan` (ಅನ್ವಯಿಸದಿದ್ದರೆ ದೋಷ ಎಸೆಯಿರಿ),
   `sendMessage`, `listSources` ಅನ್ನು ಅನುಷ್ಠಾನಗೊಳಿಸಿ. ಸ್ಥಿತಿ ಸಾಮಾನ್ಯೀಕರಣಕ್ಕಾಗಿ `this.mapStatus(...)` ಬಳಸಿ.
3. ಸ್ಥಿರವಾದ `providerId` ಅಡಿಯಲ್ಲಿ `src/lib/cloudAgent/registry.ts` ನಲ್ಲಿ ನೋಂದಾಯಿಸಿ.
4. `src/lib/cloudAgent/types.ts` ನಲ್ಲಿರುವ `providerId` ಲಿಟರಲ್ ಯೂನಿಯನ್ ಅನ್ನು ವಿಸ್ತರಿಸಿ
   (`CloudAgentTask.providerId` ಮತ್ತು `CreateCloudAgentTaskSchema`).
5. ಪೂರೈಕೆದಾರನಿಗೆ ಸಂಪರ್ಕ ದಾಖಲೆ ಅಗತ್ಯವಿದ್ದರೆ ಅದನ್ನು `src/shared/constants/providers.ts` ಗೆ ಸೇರಿಸಿ.
   OAuth-ಆಧಾರಿತ ಪೂರೈಕೆದಾರರಿಗೆ `src/lib/oauth/providers/` ಸಹ ಅಗತ್ಯವಿದೆ.
6. `tests/unit/cloud-agent-*.test.ts` ಅಡಿಯಲ್ಲಿ ಪರೀಕ್ಷೆಗಳನ್ನು ಸೇರಿಸಿ.
7. ಈ ದಾಖಲೆಯನ್ನು ಮತ್ತು ಡ್ಯಾಶ್ಬೋರ್ಡ್ನ `CLOUD_AGENTS` ಸ್ಥಿರಾಂಕವನ್ನು ನವೀಕರಿಸಿ.
