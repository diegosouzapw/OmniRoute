> ಆಯ್ಕೆಮಾಡಿ ಸಕ್ರಿಯಗೊಳಿಸಬೇಕಾದದ್ದು, ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ನಿಷ್ಕ್ರಿಯವಾಗಿದೆ (`modelVisibilityAllowlist`/`modelVisibilityDenylist` ಎರಡೂ ಖಾಲಿಯಾಗಿದ್ದರೆ
> `/v1/models` ಕ್ಯಾಟಲಾಗ್ ಮತ್ತು ಪ್ರತಿಯೊಂದು `auto/*` ಅಭ್ಯರ್ಥಿ ಪೂಲ್ ಬೈಟ್-ಮಟ್ಟದಲ್ಲಿ ಒಂದೇ ಆಗಿರುತ್ತವೆ). ವೆಚ್ಚಕ್ಕೆ
> ಯಾವುದೇ ಸಂಬಂಧವಿಲ್ಲದ ಕಾರಣಗಳಿಗಾಗಿ ಆಯ್ದ ಮಾದರಿ ಪಟ್ಟಿಯನ್ನು ಬಯಸುವ ನಿರ್ವಾಹಕರಿಗೆ ಇದು
> `hidePaidModels`/`hideAutoCombos` (`src/lib/db/settings.ts`) ನ ಸಹೋದರ ವೈಶಿಷ್ಟ್ಯವಾಗಿದೆ.

## ಇದು ಏಕೆ ಅಸ್ತಿತ್ವದಲ್ಲಿದೆ

`hidePaidModels` "ಈ ಮಾದರಿ ಉಚಿತವೇ?" ಎಂಬುದಕ್ಕೆ ಉತ್ತರಿಸುತ್ತದೆ ಮತ್ತು `hideAutoCombos` "`auto/*`
ವರ್ಚುವಲ್ ಐಡಿಗಳನ್ನು ಜಾಹೀರಾತು ಮಾಡಬೇಕೇ?" ಎಂಬುದಕ್ಕೆ ಉತ್ತರಿಸುತ್ತದೆ — ಆದರೆ ಇವೆರಡರಲ್ಲಿ ಯಾವುದೂ ನಿರ್ವಾಹಕರಿಗೆ
ಮಾದರಿಗಳ ಅನಿಯಂತ್ರಿತ ಉಪಸಮೂಹವನ್ನು ಆಯ್ಕೆಮಾಡಲು ಅವಕಾಶ ನೀಡುವುದಿಲ್ಲ (ಉದಾ. ಬೆಲೆ ನಿಗದಿಯಿಂದ ಸ್ವತಂತ್ರವಾಗಿ,
ನಿರ್ದಿಷ್ಟ Claude Code / OpenCode ಕ್ಲೈಂಟ್ ನೋಡಬೇಕಾದ ಮಾದರಿಗಳನ್ನು ಮಾತ್ರ ನಿಖರವಾಗಿ ಪ್ರಸ್ತುತಪಡಿಸುವುದು).
#11481 ಇದನ್ನು ಎರಡು ಸ್ವತಂತ್ರ, ಆಯ್ಕೆಮಾಡಿ ಸಕ್ರಿಯಗೊಳಿಸಬೇಕಾದ ಸ್ಟ್ರಿಂಗ್-ಅರೇ ಸೆಟ್ಟಿಂಗ್ಗಳಾಗಿ ಸೇರಿಸುತ್ತದೆ.

## ಸೆಟ್ಟಿಂಗ್ಗಳು

| ಕೀ                         | ಪ್ರಕಾರ     | ಪೂರ್ವನಿಯೋಜಿತ | ಅರ್ಥ                                                                              |
| -------------------------- | ---------- | ------------ | --------------------------------------------------------------------------------- |
| `modelVisibilityDenylist`  | `string[]` | `[]`         | ಅಭ್ಯರ್ಥಿಗೆ ಹೊಂದಿಕೆಯಾಗುವ ನಮೂದುಗಳು ಅದನ್ನು ಕ್ಯಾಟಲಾಗ್/ಅಭ್ಯರ್ಥಿ ಪೂಲ್ನಿಂದ ಮರೆಮಾಡುತ್ತವೆ. |
| `modelVisibilityAllowlist` | `string[]` | `[]`         | ಖಾಲಿಯಿಲ್ಲದಿದ್ದಾಗ, ಅಭ್ಯರ್ಥಿಗೆ ಹೊಂದಿಕೆಯಾಗುವ ನಮೂದುಗಳು ಮಾತ್ರ ಗೋಚರವಾಗಿ ಉಳಿಯುತ್ತವೆ.     |

ಎರಡೂ ತಲಾ 200 ಅಕ್ಷರಗಳವರೆಗಿನ ಗರಿಷ್ಠ 500 ನಮೂದುಗಳನ್ನು ಸ್ವೀಕರಿಸುತ್ತವೆ
(`src/shared/validation/settingsSchemas.ts` ನಲ್ಲಿ Zod ಮೂಲಕ ಮೌಲ್ಯೀಕರಿಸಲಾಗಿದೆ). ಒಂದು ನಮೂದು ಇವುಗಳಲ್ಲಿ ಒಂದಾಗಿರುತ್ತದೆ:

- ನಿಖರವಾದ ಕ್ಯಾಟಲಾಗ್ ಐಡಿ — `"gpt-4o"` (ಸರಳ ಮಾದರಿ ಐಡಿ) ಅಥವಾ `"openai/gpt-4o"` (ಪೂರೈಕೆದಾರ-ಪೂರ್ವಪ್ರತ್ಯಯ ಹೊಂದಿರುವುದು), ಅಥವಾ
- `*`/`?` ಬಳಸುವ ಗ್ಲಾಬ್ ಮಾದರಿ — ಉದಾ. `"openai/gpt-4*"` ಅಥವಾ `"anthropic/*"` — ಇದನ್ನು ಈಗಾಗಲೇ
  `ModelRoutingSection` ನ ಪ್ರತಿ-ಮಾದರಿ ಕಾಂಬೊ ಮ್ಯಾಪಿಂಗ್ಗಳು ಮತ್ತು `freeModels.ts::matchesOnlyPaidModels` ಬಳಸುತ್ತಿರುವ
  ಅದೇ ಹಂಚಿಕೆಯ `globToRegex()` ಹೊಂದಾಣಿಕೆ ಸಾಧನ (`src/shared/utils/globPattern.ts`) ಮೂಲಕ ಪರಿಹರಿಸಲಾಗುತ್ತದೆ.

ಆದ್ಯತೆ: ಡಿನೈಲಿಸ್ಟ್ ಅನ್ನು ಮೊದಲು ಪರಿಶೀಲಿಸಲಾಗುತ್ತದೆ (ನಿರಾಕರಿಸಲಾದ ನಮೂದು ಅಲೌಲಿಸ್ಟ್ಗೂ
ಹೊಂದಿಕೆಯಾದರೂ ಯಾವಾಗಲೂ ಮರೆಮಾಡಲ್ಪಡುತ್ತದೆ); ಅಲೌಲಿಸ್ಟ್ ಖಾಲಿಯಿಲ್ಲದಿದ್ದಾಗ, ಅದಕ್ಕೆ ಹೊಂದಿಕೆಯಾಗುವ ನಮೂದುಗಳು ಮಾತ್ರ ಉಳಿಯುತ್ತವೆ.

## ಒಂದು ಅಲ್ಲ, ಎರಡು ತಡೆಬಿಂದುಗಳು

#6512 ನಿಂದ ಕಲಿತ ಪಾಠವು (ಕೇವಲ `hidePaidModels` ಕ್ಯಾಟಲಾಗ್ ಫಿಲ್ಟರ್ ಇದ್ದರೂ `auto/*` ಪಾವತಿಸಬೇಕಾದ
ಮಾದರಿಗೆ ರೂಟ್ ಮಾಡಲು ಅವಕಾಶವಿತ್ತು, ಏಕೆಂದರೆ ಕಾಂಬೊ ಅಭ್ಯರ್ಥಿ ಪೂಲ್ ಅನ್ನು ಸ್ವತಂತ್ರವಾಗಿ ನಿರ್ಮಿಸಲಾಗುತ್ತಿತ್ತು) ಇಲ್ಲಿಯೂ
ಅದೇ ರೀತಿ ಅನ್ವಯಿಸುತ್ತದೆ. ಹೊಂದಾಣಿಕೆ ಪ್ರೆಡಿಕೇಟ್ `isModelExposureAllowed()` (`src/shared/utils/modelExposureList.ts`) ಅನ್ನು
ಈ ಎರಡೂ ಸ್ಥಳಗಳಿಂದ ಕರೆ ಮಾಡಲಾಗುತ್ತದೆ:

- `src/app/api/v1/models/catalog.ts` — `/v1/models` ಪಟ್ಟಿಯೇ, `shouldHidePaid()` ಈಗಾಗಲೇ ನಿಯಂತ್ರಿಸುವ ಅದೇ 5 ಪ್ರತಿ-ಮೂಲ
  ತಡೆಬಿಂದುಗಳಲ್ಲಿ (ಸ್ಥಿರ `PROVIDER_MODELS`, ಸಿಂಕ್ ಮಾಡಿದ ಪೂರೈಕೆದಾರ ಸಾಲುಗಳು,
  ಕಸ್ಟಮ್ ಸಾಲುಗಳು, ಅಲಿಯಾಸ್-ಆಧಾರಿತ ಸಾಲುಗಳು, ನಿರ್ವಹಿತ-ಫಾಲ್ಬ್ಯಾಕ್ ಸಾಲುಗಳು).
- `open-sse/services/autoCombo/modelExposureFilter.ts::filterModelExposureCandidates()` — ಸಮಾನವಾದ
  `filterPaidOnlyCandidates()` ಕರೆಯ ನಂತರ ತಕ್ಷಣವೇ `virtualFactory.ts::buildPreparedPool` ನಿಂದ ಕರೆ ಮಾಡಲಾಗುತ್ತದೆ,
  ಹೀಗಾಗಿ ನಿರಾಕರಿಸಲಾದ ಮಾದರಿಯನ್ನು `auto/*` ಅಭ್ಯರ್ಥಿ ಪೂಲ್ಗೆ ಎಂದಿಗೂ ಆಯ್ಕೆ ಮಾಡಲು ಸಾಧ್ಯವಿಲ್ಲ.

## ಯಾವುದನ್ನು ಫಿಲ್ಟರ್ ಮಾಡಲಾಗುವುದಿಲ್ಲ

`hideAutoCombos` ನ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ವರ್ತನೆಯನ್ನು ಪ್ರತಿಬಿಂಬಿಸುತ್ತದೆ: **ಸ್ಪಷ್ಟವಾಗಿ** ಕಳುಹಿಸಲಾದ ಮಾದರಿ ಐಡಿಯನ್ನು
(`auto/*` ಮೂಲಕ ಅಲ್ಲ, ಮತ್ತು ಕ್ಯಾಟಲಾಗ್ ಪಟ್ಟಿಯ ಮೂಲಕ ಪತ್ತೆಹಚ್ಚಲಾಗಿಲ್ಲ) ಡಿಸ್ಪ್ಯಾಚ್ ಸಮಯದಲ್ಲಿ ಎಂದಿಗೂ ನಿರ್ಬಂಧಿಸಲಾಗುವುದಿಲ್ಲ —
ಜಾಹೀರಾತು/ಅಭ್ಯರ್ಥಿ-ಪೂಲ್ ಸದಸ್ಯತ್ವವನ್ನು ಮಾತ್ರ ಫಿಲ್ಟರ್ ಮಾಡಲಾಗುತ್ತದೆ. ಇದು `hidePaidModels` ನಿಂದ ಸ್ವತಂತ್ರವಾಗಿದೆ;
ವೆಚ್ಚಕ್ಕೆ ಯಾವುದೇ ಸಂಬಂಧವಿಲ್ಲದ ಕಾರಣಗಳಿಗಾಗಿ ನಿರ್ವಾಹಕರು ಆಯ್ದ ಸಮೂಹವನ್ನು ಬಯಸಬಹುದು, ಆದ್ದರಿಂದ ಎರಡೂ ಸೆಟ್ಟಿಂಗ್ಗಳು
`catalog.ts` ನಲ್ಲಿರುವ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಬಹು-ಫ್ಲ್ಯಾಗ್ ಸಂಯೋಜನೆಯಂತೆಯೇ, ಸ್ವತಂತ್ರವಾಗಿ AND ಮಾಡಲಾದ ಫಿಲ್ಟರ್ಗಳಾಗಿ ಸಂಯೋಜಿತವಾಗುತ್ತವೆ.

ಸೆಟ್ಟಿಂಗ್ಗಳ ರಫ್ತು (`GET /api/settings/export-json`) ಯಾವುದೇ ಇತರ ಸೆಟ್ಟಿಂಗ್ಗಳ ಕ್ಷೇತ್ರದಂತೆಯೇ ಎರಡೂ ಅರೇಗಳನ್ನು
ಯಥಾವತ್ತಾಗಿ ಒಳಗೊಂಡಿರುತ್ತದೆ — `hidePaidModels` ನ ಕಾಂಬೊ-ಹಂತದ ರಫ್ತು ಫಿಲ್ಟರ್ಗಿಂತ ಭಿನ್ನವಾಗಿ, ಇಲ್ಲಿ ಮರು-ಹೈಡ್ರೇಶನ್
ಅಪಾಯವಿಲ್ಲ: ರಫ್ತು ಮಾಡಿದ ಕಾಂಬೊ ಹಂತದಲ್ಲಿ ಅಡಕವಾಗಿರುವ ನಿರಾಕರಿಸಲಾದ ಐಡಿ ನಿರ್ವಾಹಕರ ಸ್ವಂತ ಸ್ಪಷ್ಟ ರೂಟಿಂಗ್
ಆಯ್ಕೆಯಾಗಿದ್ದು, ರಫ್ತು ಗಡಿಯು ತೆಗೆದುಹಾಕಬೇಕಾದ ಯಾವುದೂ ಅಲ್ಲ.
