OmniRoute ತನ್ನ ಸ್ಥಳೀಯ ಸರ್ವರ್ ಅನ್ನು (`http://localhost:20128`) ಮೂರು ಟನಲ್ ಬ್ಯಾಕೆಂಡ್ಗಳ ಮೂಲಕ ಸಾರ್ವಜನಿಕ
ಇಂಟರ್ನೆಟ್ಗೆ ತೆರೆದಿಡಬಹುದು. ಇದು ಈ ಕೆಳಗಿನವುಗಳಿಗೆ ಉಪಯುಕ್ತವಾಗಿದೆ:

- ಸಾರ್ವಜನಿಕವಾಗಿ ಪ್ರವೇಶಿಸಬಹುದಾದ ಮರುನಿರ್ದೇಶನ URL ಅಗತ್ಯವಿರುವ ಕ್ಲೌಡ್ ಪೂರೈಕೆದಾರಗಳ
  (Antigravity, Gemini, Cursor) OAuth ಕಾಲ್ಬ್ಯಾಕ್ಗಳು.
- VM ಅನ್ನು ನಿಯೋಜಿಸದೆಯೇ ನಿಮ್ಮ ಸ್ಥಳೀಯ ಇನ್ಸ್ಟೆನ್ಸ್ ಅನ್ನು ತಂಡದ ಸದಸ್ಯರೊಂದಿಗೆ ಹಂಚಿಕೊಳ್ಳುವುದು.
- ಮೊಬೈಲ್, ದೂರಸ್ಥ ಅಥವಾ ನೆಟ್ವರ್ಕ್ಗಳ ನಡುವಿನ ಪರೀಕ್ಷೆ.

ಎಲ್ಲಾ ಮೂರು ಬ್ಯಾಕೆಂಡ್ಗಳನ್ನು ಪ್ರಕ್ರಿಯೆಯೊಳಗೇ ನಿರ್ವಹಿಸಲಾಗುತ್ತದೆ — OmniRoute ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಅಥವಾ REST API ಮೂಲಕ
ಆಧಾರವಾಗಿರುವ ಬೈನರಿ ಅಥವಾ SDK ಅನ್ನು ಪ್ರಾರಂಭಿಸುತ್ತದೆ/ನಿಲ್ಲಿಸುತ್ತದೆ. ಯಾವುದೇ ರಿವರ್ಸ್-ಪ್ರಾಕ್ಸಿ ಅಥವಾ systemd ಸಂರಚನೆ
ಅಗತ್ಯವಿಲ್ಲ.

| --------------------------- | ----------------------------------------------------------------- | ---------------------------- | ----------------------------------------------------------- |
| **Cloudflare Quick Tunnel** | ತಾತ್ಕಾಲಿಕ (ಪ್ರತಿ ಮರುಪ್ರಾರಂಭದಲ್ಲೂ URL ಬದಲಾಗುತ್ತದೆ)                 | ಉಚಿತ                         | ಏನೂ ಇಲ್ಲ — `cloudflared` ಅನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಸ್ಥಾಪಿಸುತ್ತದೆ |
| **ngrok**                   | ಪಾವತಿಸಿದ ಯೋಜನೆ ಅಥವಾ ಸ್ಥಿರ ಡೊಮೇನ್ ಸಂರಚಿಸಿರುವವರೆಗೆ ಸ್ಥಿರವಾಗಿರುತ್ತದೆ | ಉಚಿತ ಶ್ರೇಣಿ + ಪಾವತಿಸಿದ ಯೋಜನೆ | ngrok ಖಾತೆ + authtoken ಅಗತ್ಯವಿದೆ                            |
| **Tailscale Funnel**        | ನಿಮ್ಮ tailnet ಒಳಗೆ ಪ್ರತಿ ನೋಡ್ಗೆ ಸ್ಥಿರವಾಗಿರುತ್ತದೆ                  | ವೈಯಕ್ತಿಕ ಬಳಕೆಗೆ ಉಚಿತ         | Tailscale ಸ್ಥಾಪನೆ + ಲಾಗಿನ್ + Funnel ACL ಅಗತ್ಯವಿದೆ           |

`targetUrl`, ಮತ್ತು `lastError` ಕ್ಷೇತ್ರಗಳನ್ನು ಹೊಂದಿರುವ ಒಂದೇ ಸ್ವರೂಪದ `status` ಆಬ್ಜೆಕ್ಟ್ ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತವೆ, ಆದ್ದರಿಂದ
ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಅವುಗಳನ್ನು ಏಕರೂಪವಾಗಿ ಪ್ರದರ್ಶಿಸಬಹುದು.

## 1. Cloudflare Tunnel (Quick Tunnel + Named Tunnel)

`src/lib/cloudflaredTunnel.ts`, `cloudflared` ಅನ್ನು ಚೈಲ್ಡ್ ಪ್ರಕ್ರಿಯೆಯಾಗಿ ಚಲಾಯಿಸುತ್ತದೆ. ಹೆಸರಿಸಲಾದ-ಟನಲ್ ಸಂರಚನೆಯನ್ನು
ಒದಗಿಸಲಾಗಿದೆಯೇ ಎಂಬುದರ ಆಧಾರದ ಮೇಲೆ ಆಯ್ಕೆಮಾಡಲಾಗುವ ಎರಡು ಮೋಡ್ಗಳನ್ನು ಇದು ಬೆಂಬಲಿಸುತ್ತದೆ:

- **ಕ್ವಿಕ್ ಟನಲ್ (ಡೀಫಾಲ್ಟ್).** `cloudflared tunnel --url
http://localhost:<apiPort>` ಅನ್ನು ಚಲಾಯಿಸುತ್ತದೆ ಮತ್ತು stdout ನಿಂದ ನಿಯೋಜಿಸಲಾದ `*.trycloudflare.com` URL ಅನ್ನು
  ಪಾರ್ಸ್ ಮಾಡುತ್ತದೆ. URL ಗಳು ತಾತ್ಕಾಲಿಕವಾಗಿದ್ದು ಪ್ರತಿ ಮರುಪ್ರಾರಂಭದಲ್ಲೂ ಬದಲಾಗುತ್ತವೆ.
- **ಹೆಸರಿಸಲಾದ ಟನಲ್ (ಐಚ್ಛಿಕ).** `CLOUDFLARED_CONFIG` ಸ್ಥಳೀಯವಾಗಿ ನಿರ್ವಹಿಸಲಾದ
  cloudflared `config.yml` ಅನ್ನು ಸೂಚಿಸಿದಾಗ, OmniRoute `cloudflared tunnel --no-autoupdate
--config <path> run` ಅನ್ನು ಚಲಾಯಿಸುತ್ತದೆ, ಇದರಿಂದ ನಿಮಗೆ **ಸ್ಥಿರವಾದ, ಹೆಸರಿಸಲಾದ ಹೋಸ್ಟ್ನೇಮ್** ದೊರೆಯುತ್ತದೆ. ಸಂರಚನೆಯು
  ಟನಲ್ UUID, `credentials-file`, ಮತ್ತು `ingress` ರೂಟಿಂಗ್ ಅನ್ನು ಒದಗಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಯಾವುದೇ
  `--url` ಅನ್ನು ರವಾನಿಸಲಾಗುವುದಿಲ್ಲ ಮತ್ತು Zero Trust ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಟೋಕನ್ ಅಗತ್ಯವಿರುವುದಿಲ್ಲ. `run`, ಸಂರಚನೆಯ
  ಸಂಪೂರ್ಣ `credentials-file` ಪಥದಿಂದ ರುಜುವಾತುಗಳನ್ನು ಓದುತ್ತದೆ — `cert.pem`
  ಅಗತ್ಯವಿಲ್ಲ (ಅದನ್ನು ಟನಲ್ನ ಜೀವನಚಕ್ರ ನಿರ್ವಹಣೆಗೆ ಮಾತ್ರ ಬಳಸಲಾಗುತ್ತದೆ).

ಪ್ರಮುಖ ವರ್ತನೆಗಳು:

- **ಸ್ವಯಂ-ಸ್ಥಾಪನೆ.** ಮೊದಲ ಬಳಕೆಯಲ್ಲಿ, OmniRoute ಅಧಿಕೃತ GitHub ಬಿಡುಗಡೆಗಳಿಂದ ಇತ್ತೀಚಿನ `cloudflared`
  ಬೈನರಿಯನ್ನು ಡೌನ್ಲೋಡ್ ಮಾಡುತ್ತದೆ (ನಿರ್ವಹಿತ ಸ್ಥಾಪನೆಯು
  `DATA_DIR/cloudflared/` ಅಡಿಯಲ್ಲಿ ಇರುತ್ತದೆ). ಕಾರ್ಯಗತಗೊಳಿಸುವ ಮೊದಲು ಡೌನ್ಲೋಡ್ ಮಾಡಿದ ಅಸೆಟ್ನ SHA256 ಅನ್ನು
  ಬಿಡುಗಡೆ ಮ್ಯಾನಿಫೆಸ್ಟ್ಗೆ ಹೋಲಿಸಿ ಪರಿಶೀಲಿಸಲಾಗುತ್ತದೆ.
- **ಪ್ರಕ್ರಿಯೆ ಮೇಲ್ವಿಚಾರಣೆ.** ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಮರುಲೋಡ್ಗಳ ನಂತರವೂ ಸ್ಥಿತಿಯನ್ನು ಮುಂದುವರಿಸಲು cloudflared PID ಮತ್ತು ಪರಿಹರಿಸಲಾದ URL ಅನ್ನು
  `quick-tunnel-state.json` ನಲ್ಲಿ ಉಳಿಸಲಾಗುತ್ತದೆ.

### ಹೆಸರಿಸಲಾದ ಟನಲ್ ಸಂರಚನೆ (ಸ್ಥಿರ ಹೋಸ್ಟ್ನೇಮ್)

1. cloudflared CLI ಬಳಸಿ ಸ್ಥಳೀಯವಾಗಿ ನಿರ್ವಹಿಸಲಾದ ಟನಲ್ ಅನ್ನು ರಚಿಸಿ (ಒಮ್ಮೆ ಮಾತ್ರ):

   ```bash
   cloudflared tunnel login
   cloudflared tunnel create omniroute
   cloudflared tunnel route dns omniroute ai.example.com
   ```

2. ನಿಮ್ಮ ಹೋಸ್ಟ್ನೇಮ್ ಅನ್ನು OmniRoute ನ ಸ್ಥಳೀಯ
   API ಪೋರ್ಟ್ಗೆ (ಡೀಫಾಲ್ಟ್ 20128) ರೂಟ್ ಮಾಡುವ `~/.cloudflared/config.yml` ಅನ್ನು ಬರೆಯಿರಿ:

   ```yaml
   tunnel: <UUID-from-create>
   credentials-file: /home/you/.cloudflared/<UUID>.json
   ingress:
     - hostname: ai.example.com
       service: http://127.0.0.1:20128
     - service: http_status:404
   ```

3. OmniRoute ಅನ್ನು ಸಂರಚನೆಯತ್ತ ಸೂಚಿಸಿ ಮತ್ತು ಟನಲ್ ಅನ್ನು (ಮರು)ಪ್ರಾರಂಭಿಸಿ:

   ```bash
   export CLOUDFLARED_CONFIG="/home/you/.cloudflared/config.yml"
   # ಐಚ್ಛಿಕ — OmniRoute ವರದಿ ಮಾಡುವ ಹೋಸ್ಟ್ನೇಮ್ ಅನ್ನು ಅತಿಕ್ರಮಿಸುತ್ತದೆ; ಇಲ್ಲದಿದ್ದರೆ
   # ಸಂರಚನೆಯ ಮೊದಲ ingress ನಿಯಮದಿಂದ ಓದಲಾಗುತ್ತದೆ:
   # export CLOUDFLARED_HOSTNAME="ai.example.com"
   ```

   ಕ್ವಿಕ್ ಟನಲ್ನಂತೆಯೇ ಟನಲ್ ಅನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ (ಕೆಳಗಿನ REST / ಡ್ಯಾಶ್ಬೋರ್ಡ್ / CLI
   ಮೂಲಕ). ಹೆಸರಿಸಲಾದ ಟನಲ್ ಸ್ಕ್ರೇಪ್ ಮಾಡಲು ಯಾವುದೇ ಸಾರ್ವಜನಿಕ URL ಅನ್ನು ಹೊರಸೂಸುವುದಿಲ್ಲ, ಆದ್ದರಿಂದ ಸಿದ್ಧತೆಯನ್ನು
   cloudflared ನ ನೋಂದಾಯಿತ ಎಡ್ಜ್ ಸಂಪರ್ಕದಿಂದ ಪತ್ತೆಹಚ್ಚಲಾಗುತ್ತದೆ ಮತ್ತು `publicUrl`/`apiUrl` ಅನ್ನು
   `CLOUDFLARED_HOSTNAME` ನಿಂದ (ಅಥವಾ ಸಂರಚನೆಯ ಮೊದಲ ingress ಹೋಸ್ಟ್ನೇಮ್ನಿಂದ) ವರದಿ ಮಾಡಲಾಗುತ್ತದೆ.

### REST ಮೂಲಕ ಸಕ್ರಿಯಗೊಳಿಸಿ / ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿ

ಈ ಎಂಡ್ಪಾಯಿಂಟ್ ಪ್ರತ್ಯೇಕ `start`/`stop` ಪಥಗಳ ಬದಲು `{action: "enable" | "disable"}` ಬಾಡಿಯನ್ನು
ಬಳಸುತ್ತದೆ. ನಿರ್ವಹಣಾ ದೃಢೀಕರಣ (ನಿರ್ವಾಹಕ ಸೆಷನ್ ಅಥವಾ ನಿರ್ವಾಹಕ API ಕೀ)
ಅಗತ್ಯವಿದೆ.

```bash
# ಸಕ್ರಿಯಗೊಳಿಸಿ
curl -X POST http://localhost:20128/api/tunnels/cloudflared \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"enable"}'

# ಸ್ಥಿತಿ
curl http://localhost:20128/api/tunnels/cloudflared \
  -H "Cookie: auth_token=..."

# ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿ
curl -X POST http://localhost:20128/api/tunnels/cloudflared \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"disable"}'
```

ಅಥವಾ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಮೂಲಕ: **Settings → Tunnels → Cloudflare**.

### ಐಚ್ಛಿಕ env vars

| ವೇರಿಯಬಲ್                                             | ಉದ್ದೇಶ                                                                                                                                                                            |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CLOUDFLARED_BIN`                                    | ಬೈನರಿ ಪಥವನ್ನು ಅತಿಕ್ರಮಿಸುತ್ತದೆ. ಇದನ್ನು ಹೊಂದಿಸಲಾಗಿದ್ದು ಮಾನ್ಯವಾಗಿದ್ದರೆ, ಡೌನ್ಲೋಡ್ ಮಾಡುವ ಬದಲು OmniRoute ಅದನ್ನು ಬಳಸುತ್ತದೆ.                                                              |
| `CLOUDFLARED_PROTOCOL` / `TUNNEL_TRANSPORT_PROTOCOL` | ಸಾರಿಗೆ ಪ್ರೋಟೋಕಾಲ್ (ಪೂರ್ವನಿಯೋಜಿತ `http2`; `quic`, `auto` ಸಹ ಲಭ್ಯ).                                                                                                                 |
| `CLOUDFLARED_CONFIG`                                 | ಸ್ಥಳೀಯವಾಗಿ ನಿರ್ವಹಿಸಲಾದ cloudflared `config.yml` ಗೆ ಪಥ. ಇದನ್ನು ಹೊಂದಿಸಿದಾಗ, ತ್ವರಿತ ಟನಲ್ ಬದಲು OmniRoute **ಹೆಸರಿಸಲಾದ/ನಿರಂತರ** ಟನಲ್ ಅನ್ನು (`tunnel --config <path> run`) ಚಲಾಯಿಸುತ್ತದೆ. |
| `CLOUDFLARED_HOSTNAME`                               | ಹೆಸರಿಸಲಾದ ಟನಲ್ ವರದಿ ಮಾಡುವ ಸಾರ್ವಜನಿಕ ಹೋಸ್ಟ್ಹೆಸರನ್ನು ಅತಿಕ್ರಮಿಸುತ್ತದೆ (ಉದಾ. `ai.example.com`). ಇದನ್ನು ಹೊಂದಿಸದಿದ್ದರೆ, ಕಾನ್ಫಿಗ್ನ ಮೊದಲ `ingress` ಹೋಸ್ಟ್ಹೆಸರಿನಿಂದ ಓದಲಾಗುತ್ತದೆ.           |

## 2. ngrok

`src/lib/ngrokTunnel.ts` **`@ngrok/ngrok` SDK** ಅನ್ನು ಬಳಸುತ್ತದೆ (ಪ್ರಕ್ರಿಯೆಯೊಳಗೆಯೇ, CLI
ಉಪಪ್ರಕ್ರಿಯೆ ಇಲ್ಲದೆ). ಪೂರ್ವನಿರ್ಮಿತ ಬೈನರಿಗಳಿಲ್ಲದ ಪ್ಲಾಟ್ಫಾರ್ಮ್ಗಳಲ್ಲಿ ಆ್ಯಪ್ ಬೂಟ್ ಆಗುವಾಗ
ವಿಫಲವಾಗದಂತೆ, ಮೊದಲ ಪ್ರಾರಂಭದ ವೇಳೆ ಮಾತ್ರ ಸ್ಥಳೀಯ ಮಾಡ್ಯೂಲ್ ಅನ್ನು ಆಮದು ಮಾಡಲಾಗುತ್ತದೆ.

### ಪೂರ್ವಾಪೇಕ್ಷಿತಗಳು

1. <https://ngrok.com> ನಲ್ಲಿ ನೋಂದಾಯಿಸಿ.
2. ngrok ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಿಂದ ನಿಮ್ಮ authtoken ಅನ್ನು ನಕಲಿಸಿ.
3. ಅದನ್ನು ಈ ಕೆಳಗಿನ ಯಾವುದಾದರೂ ವಿಧಾನದ ಮೂಲಕ ಒದಗಿಸಿ:
   - `.env`: `NGROK_AUTHTOKEN=<token>`, ಅಥವಾ
   - ಡ್ಯಾಶ್ಬೋರ್ಡ್: **Settings → Tunnels → ngrok**, ಅಥವಾ
   - REST ಬಾಡಿ (ಒಂದು ಬಾರಿ): `{"action":"enable","authToken":"<token>"}`.

ಯಾವುದನ್ನೂ ಕಾನ್ಫಿಗರ್ ಮಾಡದಿದ್ದರೆ, ಸ್ಥಿತಿಯು `phase: "needs_auth"` ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ.

### REST ಮೂಲಕ ಸಕ್ರಿಯಗೊಳಿಸುವುದು / ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವುದು

```bash
# ಸಕ್ರಿಯಗೊಳಿಸಿ (env ನಿಂದ NGROK_AUTHTOKEN ಅನ್ನು ಬಳಸುತ್ತದೆ)
curl -X POST http://localhost:20128/api/tunnels/ngrok \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"enable"}'

# ಇನ್ಲೈನ್ ಟೋಕನ್ನೊಂದಿಗೆ ಸಕ್ರಿಯಗೊಳಿಸಿ
curl -X POST http://localhost:20128/api/tunnels/ngrok \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"enable","authToken":"2abc..."}'

# ಸ್ಥಿತಿ
curl http://localhost:20128/api/tunnels/ngrok \
  -H "Cookie: auth_token=..."

# ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿ
curl -X POST http://localhost:20128/api/tunnels/ngrok \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"disable"}'
```

ಪ್ರತಿಕ್ರಿಯೆಯು ನಿಯೋಜಿಸಲಾದ `publicUrl` ಅನ್ನು ಒಳಗೊಂಡಿರುತ್ತದೆ (ಉದಾ.
`https://abcd-1234.ngrok-free.app`). ಕಸ್ಟಮ್ ಡೊಮೇನ್ಗಳು, ಪ್ರದೇಶಗಳು ಮತ್ತು ನೀತಿ ನಿಯಮಗಳನ್ನು
ngrok ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿ ಕಾನ್ಫಿಗರ್ ಮಾಡಬೇಕು — OmniRoute ಸ್ವತಃ ಸ್ಥಳೀಯ ಗುರಿ URL ಅನ್ನು
SDK ಗೆ ಫಾರ್ವರ್ಡ್ ಮಾಡುವುದಷ್ಟೇ ಮಾಡುತ್ತದೆ.

## 3. Tailscale Funnel

`src/lib/tailscaleTunnel.ts`, ಸ್ಥಳೀಯ API ಪೋರ್ಟ್ ಅನ್ನು **Funnel** (ಸರ್ವ್ಗಾಗಿ Tailscale ನ
ಸಾರ್ವಜನಿಕ-ಇಂಟರ್ನೆಟ್ ಎಗ್ರೆಸ್) ಮೂಲಕ ಬಹಿರಂಗಪಡಿಸಲು ಸಿಸ್ಟಮ್ನ `tailscale` CLI ಅನ್ನು
ನಿರ್ವಹಿಸುತ್ತದೆ. ಇದು ಸಂಪೂರ್ಣ ಜೀವನಚಕ್ರವನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ: ಸ್ಥಾಪನೆ, ಲಾಗಿನ್, ಡೀಮನ್ ಪ್ರಾರಂಭ,
ಸಕ್ರಿಯಗೊಳಿಸುವಿಕೆ, ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವಿಕೆ.

ಅನುಷ್ಠಾನವು `tailscale funnel --bg <port>` (ಹಿನ್ನೆಲೆ ಮೋಡ್) ಅನ್ನು ಆಹ್ವಾನಿಸುತ್ತದೆ.
ಸಾರ್ವಜನಿಕ URL `https://<machine>.<tailnet>.ts.net/` ರೂಪದಲ್ಲಿರುತ್ತದೆ.

### ಪೂರ್ವಾಪೇಕ್ಷಿತಗಳು

1. Tailscale ಅನ್ನು ಸ್ಥಾಪಿಸಿ (ಅಥವಾ OmniRoute ಅದನ್ನು ಮಾಡಲು ಬಿಡಿ — ಕೆಳಗಿನ `install` ಎಂಡ್ಪಾಯಿಂಟ್ ನೋಡಿ).
2. ಸೈನ್ ಇನ್ ಮಾಡಿ (`tailscale login` ಅಥವಾ OmniRoute ನ `login` ಎಂಡ್ಪಾಯಿಂಟ್ ಮೂಲಕ).
3. Tailscale ನಿರ್ವಾಹಕ ಕನ್ಸೋಲ್ನಲ್ಲಿ ನಿಮ್ಮ tailnet ಗಾಗಿ Funnel ಅನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ:
   <https://login.tailscale.com/admin/settings/features>.

Linux ಮತ್ತು macOS ನಲ್ಲಿ ಡೀಮನ್ (`tailscaled`) ಅನ್ನು ನಿಯಂತ್ರಿಸಲು `sudo` ಅಗತ್ಯವಿದೆ.
POST ಎಂಡ್ಪಾಯಿಂಟ್ಗಳು ಐಚ್ಛಿಕ `sudoPassword` ಕ್ಷೇತ್ರವನ್ನು ಸ್ವೀಕರಿಸುತ್ತವೆ; ಕರೆಯ ಅವಧಿಗೆ
ಅದನ್ನು OmniRoute ನ MITM ಪಾಸ್ವರ್ಡ್ ಕ್ಯಾಶ್ಗೆ (`getCachedPassword` / `setCachedPassword`)
ಫಾರ್ವರ್ಡ್ ಮಾಡಲಾಗುತ್ತದೆ. Windows ನಲ್ಲಿ `C:\Program Files\Tailscale\tailscale.exe` ನಲ್ಲಿರುವ
ಡೀಫಾಲ್ಟ್ ಸೇವಾ ಸ್ಥಾಪನೆಯನ್ನು ಬಳಸಲಾಗುತ್ತದೆ.

### REST ಎಂಡ್ಪಾಯಿಂಟ್ಗಳು

ಸ್ಥಾಪನೆ, ಲಾಗಿನ್, ಡೀಮನ್ ಮತ್ತು ಟನಲ್ ಪ್ರತ್ಯೇಕ ವಿಷಯಗಳಾಗಿರುವುದರಿಂದ Tailscale ಇತರ
ಬ್ಯಾಕೆಂಡ್ಗಳಿಗಿಂತ ಹೆಚ್ಚು ಸಮೃದ್ಧವಾದ ಕಾರ್ಯವ್ಯಾಪ್ತಿಯನ್ನು ಹೊಂದಿದೆ.

| ಎಂಡ್ಪಾಯಿಂಟ್                           | ವಿಧಾನ  | ಉದ್ದೇಶ                                                                                  |
| ------------------------------------- | ------ | --------------------------------------------------------------------------------------- |
| `/api/tunnels/tailscale`              | `GET`  | ಒಟ್ಟುಗೂಡಿಸಿದ ಟನಲ್ ಸ್ಥಿತಿ (`phase`, `tunnelUrl`, `apiUrl`, ಇತ್ಯಾದಿ)                      |
| `/api/tunnels/tailscale/check`        | `GET`  | ಕೆಳಮಟ್ಟದ ಪರಿಶೀಲನೆ: ಸ್ಥಾಪಿಸಲಾಗಿದೆಯೇ? ಲಾಗಿನ್ ಆಗಿದೆಯೇ? ಡೀಮನ್ ಚಾಲನೆಯಲ್ಲಿದೆಯೇ?               |
| `/api/tunnels/tailscale/install`      | `POST` | Tailscale ಸ್ಥಾಪಿಸಿ (SSE ಮೂಲಕ ಸ್ಟ್ರೀಮ್ ಮಾಡಲಾದ ಪ್ರಗತಿ ಈವೆಂಟ್ಗಳು) — Linux/macOS            |
| `/api/tunnels/tailscale/start-daemon` | `POST` | Linux/macOS ನಲ್ಲಿ `tailscaled` ಅನ್ನು ಪ್ರಾರಂಭಿಸಿ                                         |
| `/api/tunnels/tailscale/login`        | `POST` | ಲಾಗಿನ್ ಪ್ರಕ್ರಿಯೆಯನ್ನು ಪ್ರಾರಂಭಿಸಿ; ಬ್ರೌಸರ್ನಲ್ಲಿ ತೆರೆಯಲು `authUrl` ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ |
| `/api/tunnels/tailscale/enable`       | `POST` | API ಪೋರ್ಟ್ಗಾಗಿ Funnel ಅನ್ನು ಪ್ರಾರಂಭಿಸಿ                                                  |
| `/api/tunnels/tailscale/disable`      | `POST` | Funnel ಅನ್ನು ನಿಲ್ಲಿಸಿ                                                                   |

ಎಲ್ಲಾ Tailscale ಎಂಡ್ಪಾಯಿಂಟ್ಗಳಿಗೆ ನಿರ್ವಹಣಾ ದೃಢೀಕರಣ ಅಗತ್ಯವಿದೆ (`routeUtils.ts ::
requireTailscaleAuth` ನೋಡಿ).

ಸಕ್ರಿಯಗೊಳಿಸುವಿಕೆಯ ಉದಾಹರಣೆ:

```bash
curl -X POST http://localhost:20128/api/tunnels/tailscale/enable \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"sudoPassword":"<linux-pwd>","port":20128}'
```

ನಿರ್ವಾಹಕ ಕನ್ಸೋಲ್ನಲ್ಲಿ Funnel ಸಕ್ರಿಯಗೊಳಿಸದಿದ್ದರೆ, ಪ್ರತಿಕ್ರಿಯೆಯು
`funnelNotEnabled: true` ಜೊತೆಗೆ ಬ್ರೌಸರ್ನಲ್ಲಿ ತೆರೆಯಲು `enableUrl` ಅನ್ನು ಒಳಗೊಂಡಿರುತ್ತದೆ.

## OAuth ಕಾಲ್ಬ್ಯಾಕ್ ಪರಿಗಣನೆಗಳು

ನೀವು OmniRoute ಅನ್ನು ಟನಲ್ ಮೂಲಕ ಬಹಿರಂಗಪಡಿಸಿದಾಗ, ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಮತ್ತು OAuth ಹರಿವುಗಳು
ಕಾಲ್ಬ್ಯಾಕ್ URL ಗಳನ್ನು `localhost` ವಿರುದ್ಧವಲ್ಲ, **ಸಾರ್ವಜನಿಕ** ಹೋಸ್ಟ್ನೇಮ್ ವಿರುದ್ಧ
ನಿರ್ಮಿಸಬೇಕು. ಇಲ್ಲವಾದರೆ OAuth ಪೂರೈಕೆದಾರರು ಬಳಕೆದಾರರನ್ನು ತಮ್ಮ ಸರ್ವರ್ಗಳು ತಲುಪಲು
ಸಾಧ್ಯವಾಗದ URL ಗೆ ಮರಳಿ ಮರುನಿರ್ದೇಶಿಸುತ್ತಾರೆ ಮತ್ತು ಹ್ಯಾಂಡ್ಶೇಕ್ ವಿಫಲವಾಗುತ್ತದೆ.

ಡ್ಯಾಶ್ಬೋರ್ಡ್ ತಿದ್ದುಪಡಿಗಳು ಮತ್ತು ಸೆಟ್ಟಿಂಗ್ಗಳ ಉಳಿಸುವಿಕೆಗೆ ಟನಲ್ ಹೋಸ್ಟ್ನೇಮ್ ಅನ್ನು
`NEXT_PUBLIC_BASE_URL` ನಲ್ಲಿ ಸ್ಥಿರಗೊಳಿಸುವ ಅಗತ್ಯವಿಲ್ಲ. ದೃಢೀಕೃತ ಡ್ಯಾಶ್ಬೋರ್ಡ್,
ಸೆಷನ್ಗೆ ಬದ್ಧವಾದ CSRF ಟೋಕನ್ನೊಂದಿಗೆ ಅದೇ ಮೂಲದ ಅಸುರಕ್ಷಿತ ವಿನಂತಿಗಳನ್ನು ಕಳುಹಿಸುತ್ತದೆ.
ಆದ್ದರಿಂದ ಲಾಗಿನ್ ಮಾಡಿದ ನಂತರ ಸಾಮಾನ್ಯ UI ನಿರ್ವಹಣೆಗೆ ಕ್ಷಣಿಕ Cloudflare Quick Tunnel
ಹೋಸ್ಟ್ಗಳನ್ನು ಇನ್ನೂ ಬಳಸಬಹುದು.

ಹೀಗೆ ಹೊಂದಿಸಿ:

```bash
NEXT_PUBLIC_BASE_URL=https://<your-tunnel-host>
```

ಮತ್ತು OAuth ಪ್ರಾರಂಭಿಸುವ ಮೊದಲು OmniRoute ಅನ್ನು ಮರುಪ್ರಾರಂಭಿಸಿ. ಕ್ಷಣಿಕ Cloudflare Quick
Tunnels ಗಳಲ್ಲಿ ಪ್ರತಿ ಮರುಪ್ರಾರಂಭದ ನಂತರ URL ಬದಲಾಗುತ್ತದೆ. ಆದ್ದರಿಂದ ಉತ್ಪಾದನಾ OAuth
ಬಳಕೆಗಾಗಿ ಕಾಯ್ದಿರಿಸಿದ ಡೊಮೇನ್ನೊಂದಿಗೆ ngrok ಅಥವಾ Tailscale Funnel ಗೆ ಆದ್ಯತೆ ನೀಡಿ.

## ಆರೋಗ್ಯ ಮತ್ತು ಮೇಲ್ವಿಚಾರಣೆ

ಡ್ಯಾಶ್ಬೋರ್ಡ್ **ಸೆಟ್ಟಿಂಗ್ಗಳು → ಟನಲ್ಗಳು** ಅಡಿಯಲ್ಲಿ ಟನಲ್ ಸ್ಥಿತಿಯನ್ನು ತೋರಿಸುತ್ತದೆ:

- ಸಕ್ರಿಯ ಬ್ಯಾಕೆಂಡ್(ಗಳು) ಮತ್ತು ಪ್ರಸ್ತುತ `phase` (`stopped`, `starting`, `running`,
  `needs_auth`, `error`).
- ಪ್ರಸ್ತುತ ಸಾರ್ವಜನಿಕ URL ಮತ್ತು ಅದರಿಂದ ಪಡೆದ API URL (`<publicUrl>/v1`).
- ಟನಲ್ ಫಾರ್ವರ್ಡ್ ಮಾಡುತ್ತಿರುವ ಸ್ಥಳೀಯ ಗುರಿ URL.
- ಯಾವುದಾದರೂ ಇದ್ದರೆ, ಕೊನೆಯ ದೋಷ ಸಂದೇಶ.

ಪ್ರೋಗ್ರಾಮ್ಯಾಟಿಕ್ ಮೇಲ್ವಿಚಾರಣೆಗಾಗಿ ಪ್ರತಿ ಬ್ಯಾಕೆಂಡ್ನ `GET` ಎಂಡ್ಪಾಯಿಂಟ್ಗಳನ್ನು
ನಿಯಮಿತವಾಗಿ ಪೋಲ್ ಮಾಡಿ. ಒಂದೇ ಸಮಯದಲ್ಲಿ ಒಂದಕ್ಕಿಂತ ಹೆಚ್ಚು ಬ್ಯಾಕೆಂಡ್ಗಳನ್ನು ಚಲಾಯಿಸಲು
ಅನುಮತಿ ಇದೆ; OmniRoute ಪ್ರತಿಯೊಂದನ್ನೂ ಸ್ವತಂತ್ರವಾಗಿ ಟ್ರ್ಯಾಕ್ ಮಾಡುತ್ತದೆ.

## ಸಮಸ್ಯೆ ನಿವಾರಣೆ

### "cloudflared ಬೈನರಿ ಕಂಡುಬಂದಿಲ್ಲ"

ಮೊದಲ ಬಳಕೆಯಲ್ಲಿ OmniRoute ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಸ್ಥಾಪಿಸಲು ಪ್ರಯತ್ನಿಸುತ್ತದೆ. ಸ್ಥಾಪನೆಯನ್ನು
ನಿರ್ಬಂಧಿಸಿದ್ದರೆ (ನಿರ್ಬಂಧಿತ ನೆಟ್ವರ್ಕ್, GitHub ಪ್ರವೇಶವಿಲ್ಲ), `cloudflared` ಅನ್ನು
<https://github.com/cloudflare/cloudflared/releases> ನಿಂದ ಕೈಯಾರೆ ಡೌನ್ಲೋಡ್ ಮಾಡಿ
ಮತ್ತು `CLOUDFLARED_BIN=/path/to/cloudflared` ಹೊಂದಿಸಿ.

### "ngrok: authtoken ಅಗತ್ಯವಿದೆ"

`phase: "needs_auth"` ಎಂದರೆ ಯಾವುದೇ authtoken ಕಂಡುಬಂದಿಲ್ಲ. `.env` ನಲ್ಲಿ
`NGROK_AUTHTOKEN` ಹೊಂದಿಸಿ, ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಮೂಲಕ ಅದನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡಿ ಅಥವಾ ಸಕ್ರಿಯಗೊಳಿಸುವ
POST ಬಾಡಿಯಲ್ಲಿ `authToken` ಅನ್ನು ರವಾನಿಸಿ.

### "tailscale: funnel ಸಕ್ರಿಯಗೊಂಡಿಲ್ಲ"

ಸಕ್ರಿಯಗೊಳಿಸುವಿಕೆಯ ಪ್ರತಿಕ್ರಿಯೆಯಲ್ಲಿ `funnelNotEnabled: true` ಇದ್ದಾಗ, ನಿಮ್ಮ tailnet ಗಾಗಿ
Funnel ನಿಷ್ಕ್ರಿಯಗೊಂಡಿರುತ್ತದೆ. ಹಿಂತಿರುಗಿಸಲಾದ `enableUrl` ಅನ್ನು (ಅಥವಾ ನಿರ್ವಾಹಕ
ಕನ್ಸೋಲ್ನ ವೈಶಿಷ್ಟ್ಯ ಪುಟವನ್ನು) ತೆರೆಯಿರಿ ಮತ್ತು Funnel ಅನ್ನು ಆನ್ ಮಾಡಿ.

### ಟನಲ್ URL ಬದಲಾವಣೆಗಳು OAuth ಅನ್ನು ಹಾಳುಮಾಡುತ್ತವೆ

ಕಾಯ್ದಿರಿಸಿದ ಡೊಮೇನ್ನೊಂದಿಗೆ ngrok ಅಥವಾ Tailscale Funnel ಅನ್ನು ಬಳಸಿ (ಎರಡೂ ಪ್ರತಿ
ನೋಡ್ಗೆ ಸ್ಥಿರವಾಗಿರುತ್ತವೆ). Cloudflare Quick Tunnels ವಿನ್ಯಾಸತಃ ಕ್ಷಣಿಕವಾಗಿದ್ದು,
ದೀರ್ಘಾವಧಿಯ OAuth ಕಾಲ್ಬ್ಯಾಕ್ಗಳಿಗೆ ಶಿಫಾರಸು ಮಾಡಲಾಗುವುದಿಲ್ಲ.

### Tailscale ಗಾಗಿ Linux/macOS ನಲ್ಲಿ ಅನುಮತಿ ನಿರಾಕರಿಸಲಾಗಿದೆ

`tailscaled` ಗೆ root ಅಗತ್ಯವಿದೆ. ಸಂಬಂಧಿತ POST ಎಂಡ್ಪಾಯಿಂಟ್ಗೆ `sudoPassword` ಒದಗಿಸಿ
ಅಥವಾ ಡೀಮನ್ ಅನ್ನು ನೀವೇ ಚಲಾಯಿಸಿ (`sudo systemctl start tailscaled`).
