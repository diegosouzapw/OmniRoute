ಈ ದಸ್ತಾವೇಜು Fly.io ನಲ್ಲಿ OmniRoute ಅನ್ನು ನಿಯೋಜಿಸುವ ನೈಜ ಪ್ರಕ್ರಿಯೆಯನ್ನು ವಿವರಿಸುತ್ತದೆ ಮತ್ತು ಈ ಕೆಳಗಿನ ಸನ್ನಿವೇಶಗಳನ್ನು ಒಳಗೊಂಡಿದೆ:

- ಪ್ರಸ್ತುತ ಪ್ರಾಜೆಕ್ಟ್ ಅನ್ನು ಮೊದಲ ಬಾರಿಗೆ Fly.io ಗೆ ನಿಯೋಜಿಸುವುದು
- ನಂತರದ ಕೋಡ್ ನವೀಕರಣಗಳನ್ನು ಪ್ರಕಟಿಸುವುದು
- ಇದೇ ನಿಯೋಜನಾ ಕಾರ್ಯವಿಧಾನವನ್ನು ಅನುಸರಿಸುವ ಹೊಸ ಪ್ರಾಜೆಕ್ಟ್ಗಳು

ಈ ಮಾರ್ಗದರ್ಶಿಯು ಪ್ರಸ್ತುತ ಪ್ರಾಜೆಕ್ಟ್ಗಾಗಿ ಪರಿಶೀಲಿಸಲಾದ ಮತ್ತು ಕಾರ್ಯನಿರ್ವಹಿಸುವ ಸಂರಚನೆಯನ್ನು ಆಧರಿಸಿದೆ. ಅಪ್ಲಿಕೇಶನ್ನ ಹೆಸರು `omniroute` ಆಗಿದೆ.

---

## 1. ನಿಯೋಜನೆಯ ಗುರಿಗಳು

- ಪ್ಲಾಟ್ಫಾರ್ಮ್: Fly.io
- ನಿಯೋಜನೆ ವಿಧಾನ: ಸ್ಥಳೀಯ `flyctl` ನೇರ ಪ್ರಕಟಣೆ
- ರನ್ಟೈಮ್: ರೆಪೊಸಿಟರಿಯಲ್ಲಿರುವ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ `Dockerfile` ಮತ್ತು `fly.toml` ಅನ್ನು ಬಳಸುವುದು
- ಡೇಟಾ ಸ್ಥಿರತೆ: `/data` ಗೆ ಮೌಂಟ್ ಮಾಡಲಾದ Fly Volume
- ಪ್ರವೇಶ URL: `https://omniroute.fly.dev/`

---

## 2. ಪ್ರಸ್ತುತ ಪ್ರಾಜೆಕ್ಟ್ನ ಪ್ರಮುಖ ಕಾನ್ಫಿಗರೇಶನ್

ಪ್ರಸ್ತುತ ರೆಪೊಸಿಟರಿಯಲ್ಲಿರುವ `fly.toml` ಈ ಕೆಳಗಿನ ಪ್ರಮುಖ ಅಂಶಗಳನ್ನು ಒಳಗೊಂಡಿದೆ ಎಂಬುದು ದೃಢೀಕರಿಸಲಾಗಿದೆ:

```toml
app = 'omniroute'
primary_region = 'sin'

[[mounts]]
  source = 'data'
  destination = '/data'

[processes]
  app = 'node run-standalone.mjs'

[http_service]
  internal_port = 20128

[env]
  TZ = "Asia/Shanghai"
  HOST = "0.0.0.0"
  HOSTNAME = "0.0.0.0"
  BIND = "0.0.0.0"
```

ಟಿಪ್ಪಣಿಗಳು:

- `app = 'omniroute'` ನಿಯೋಜನೆಯು ಯಾವ Fly ಅಪ್ಲಿಕೇಶನ್ ಅನ್ನು ಗುರಿಯಾಗಿಸಬೇಕು ಎಂಬುದನ್ನು ನಿರ್ಧರಿಸುತ್ತದೆ
- `destination = '/data'` ಶಾಶ್ವತ ವಾಲ್ಯೂಮ್ ಮೌಂಟ್ ಡೈರೆಕ್ಟರಿಯನ್ನು ನಿರ್ಧರಿಸುತ್ತದೆ
- ಈ ಪ್ರಾಜೆಕ್ಟ್ನಲ್ಲಿ `DATA_DIR=/data` ಅನ್ನು ಹೊಂದಿಸಲೇಬೇಕು; ಇಲ್ಲದಿದ್ದರೆ ಡೇಟಾಬೇಸ್ ಮತ್ತು ಕೀಗಳನ್ನು ಕಂಟೇನರ್ನ ತಾತ್ಕಾಲಿಕ ಡೈರೆಕ್ಟರಿಗೆ ಬರೆಯಲಾಗುತ್ತದೆ

## 3. ಪೂರ್ವಾಪೇಕ್ಷಿತಗಳು

### 3.1 Fly CLI ಅನ್ನು ಸ್ಥಾಪಿಸುವುದು

Windows PowerShell:

```powershell
pwsh -Command "iwr https://fly.io/install.ps1 -useb | iex"
```

ನಿಮ್ಮ ಪರಿಸರದಲ್ಲಿ ಅನುಸ್ಥಾಪನಾ ಸ್ಕ್ರಿಪ್ಟ್ ವಿಫಲವಾದರೆ, ನೀವು `flyctl` ಬೈನರಿಯನ್ನು ಹಸ್ತಚಾಲಿತವಾಗಿ ಡೌನ್ಲೋಡ್ ಮಾಡಿ ಅದನ್ನು ನಿಮ್ಮ `PATH` ಗೆ ಸೇರಿಸಬಹುದು.

### 3.2 ನಿಮ್ಮ Fly ಖಾತೆಗೆ ಲಾಗಿನ್ ಮಾಡುವುದು

```powershell
flyctl auth login
```

### 3.3 ಲಾಗಿನ್ ಸ್ಥಿತಿಯನ್ನು ಪರಿಶೀಲಿಸುವುದು

```powershell
flyctl auth whoami
flyctl version
```

## 4. ಪ್ರಸ್ತುತ ಪ್ರಾಜೆಕ್ಟ್ನ ಮೊದಲ ನಿಯೋಜನೆ

### 4.1 ಕೋಡ್ ಅನ್ನು ಕ್ಲೋನ್ ಮಾಡಿ ಮತ್ತು ಡೈರೆಕ್ಟರಿಯನ್ನು ತೆರೆಯಿರಿ

```powershell
git clone https://github.com/diegosouzapw/OmniRoute.git
cd OmniRoute
```

### 4.2 ಅಪ್ಲಿಕೇಶನ್ ಹೆಸರನ್ನು ದೃಢೀಕರಿಸಿ

`fly.toml` ಅನ್ನು ತೆರೆಯಿರಿ ಮತ್ತು ಈ ಕೆಳಗಿನ ಸಾಲನ್ನು ಪರಿಶೀಲಿಸಿ:

```toml
app = 'omniroute'
```

ನೀವು ನಿಮ್ಮದೇ ಹೊಸ ಅಪ್ಲಿಕೇಶನ್ಗೆ ನಿಯೋಜಿಸುತ್ತಿದ್ದರೆ, ಅದನ್ನು ಜಾಗತಿಕವಾಗಿ ಅನನ್ಯವಾದ ಹೆಸರಿಗೆ ಬದಲಾಯಿಸಬಹುದು, ಉದಾಹರಣೆಗೆ:

```toml
app = 'omniroute-yourname'
```

ಟಿಪ್ಪಣಿ:

- ಕನ್ಸೋಲ್ನಲ್ಲಿ ನೀವು ಕಾಣುವ ಅಪ್ಲಿಕೇಶನ್ ಹೆಸರು `fly.toml` ನಲ್ಲಿರುವ `app` ಮೌಲ್ಯಕ್ಕೆ ಹೊಂದಿಕೆಯಾಗುವುದನ್ನು ಖಚಿತಪಡಿಸಿಕೊಳ್ಳಿ
- ನೀವು ಈ ಹಿಂದೆ `oroute` ನಂತಹ ಬೇರೆ ಹೆಸರನ್ನು ಬಳಸಿದ್ದರೆ, ಅದನ್ನು `omniroute` ಜೊತೆಗೆ ಗೊಂದಲಗೊಳಿಸಬೇಡಿ

### 4.3 ಅಪ್ಲಿಕೇಶನ್ ರಚಿಸಿ

ಅಪ್ಲಿಕೇಶನ್ ಇನ್ನೂ ಅಸ್ತಿತ್ವದಲ್ಲಿಲ್ಲದಿದ್ದರೆ:

```powershell
flyctl apps create omniroute
```

ನೀವು ಅಪ್ಲಿಕೇಶನ್ ಹೆಸರನ್ನು ಬದಲಾಯಿಸಿದ್ದರೆ, `omniroute` ಬದಲಿಗೆ ನೀವು ಆಯ್ಕೆ ಮಾಡಿದ ಹೆಸರನ್ನು ಬಳಸಿ.

### 4.4 ಮೊದಲ ನಿಯೋಜನೆ

```powershell
flyctl deploy
```

## 5. ಅಗತ್ಯವಿರುವ ಪ್ಯಾರಾಮೀಟರ್ಗಳು

ಈ ಪ್ರಾಜೆಕ್ಟ್ಗಾಗಿ Fly.io ನಲ್ಲಿ ಕನಿಷ್ಠ ಈ ಕೆಳಗಿನ ಪ್ಯಾರಾಮೀಟರ್ಗಳನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡಲು ಶಿಫಾರಸು ಮಾಡಲಾಗಿದೆ.

### 5.1 ಪರಿಶೀಲಿಸಲಾದ ಪ್ಯಾರಾಮೀಟರ್ಗಳು

ಪ್ರಸ್ತುತ `omniroute` ಅಪ್ಲಿಕೇಶನ್ನ ವಾಸ್ತವಿಕ ನಿಯೋಜನೆಗಳಲ್ಲಿ ಈ ಪ್ಯಾರಾಮೀಟರ್ಗಳನ್ನು ಬಳಸಲಾಗಿದೆ:

- `API_KEY_SECRET`
- `DATA_DIR`
- `JWT_SECRET`
- `MACHINE_ID_SALT`
- `NEXT_PUBLIC_BASE_URL`
- `OMNIROUTE_WS_BRIDGE_SECRET` (ಪ್ರೊಡಕ್ಷನ್ನಲ್ಲಿ ಅಗತ್ಯವಿದೆ — WebSocket ಬ್ರಿಡ್ಜ್ ದೃಢೀಕರಣಕ್ಕಾಗಿ ಬಳಸಲಾಗುತ್ತದೆ)
- `STORAGE_ENCRYPTION_KEY`

### 5.2 `INITIAL_PASSWORD` ಕುರಿತು

ಈ ನಿಯೋಜನೆಗೆ `INITIAL_PASSWORD` ಅಗತ್ಯವಿಲ್ಲದ ಕಾರಣ ಪ್ರಸ್ತುತ ಪ್ರಾಜೆಕ್ಟ್ನಲ್ಲಿ ಅದನ್ನು ಹೊಂದಿಸಲಾಗಿಲ್ಲ.

ಅದನ್ನು ಹೊಂದಿಸದಿದ್ದರೆ:

- ಡೀಫಾಲ್ಟ್ ಪಾಸ್ವರ್ಡ್ `CHANGEME` ಆಗಿದೆ ಎಂದು ಸ್ಟಾರ್ಟ್ಅಪ್ ಲಾಗ್ ಸೂಚಿಸುತ್ತದೆ
- ನಿಯೋಜನೆಯ ನಂತರ ಸಾಧ್ಯವಾದಷ್ಟು ಬೇಗ ಸಿಸ್ಟಮ್ ಸೆಟ್ಟಿಂಗ್ಗಳಲ್ಲಿ ಲಾಗಿನ್ ಪಾಸ್ವರ್ಡ್ ಅನ್ನು ಬದಲಾಯಿಸಬೇಕು

ಹಸ್ತಕ್ಷೇಪವಿಲ್ಲದೆ ಬ್ಯಾಕೆಂಡ್ ಪಾಸ್ವರ್ಡ್ ಅನ್ನು ಪ್ರಾರಂಭಿಸಲು ನೀವು ಬಯಸಿದರೆ, ಅದನ್ನು ನಂತರ ಸೇರಿಸಬಹುದು:

- `INITIAL_PASSWORD`

## 6. ಶಿಫಾರಸು ಮಾಡಲಾದ ನಿಯತಾಂಕಗಳು

### 6.1 ರಹಸ್ಯಗಳ ಸಂರಚನೆ

Fly Secretsಗಾಗಿ ಕೆಳಗಿನ ವೇರಿಯೇಬಲ್ಗಳನ್ನು ಶಿಫಾರಸು ಮಾಡಲಾಗಿದೆ:

| ವೇರಿಯೇಬಲ್                    | ಶಿಫಾರಸು                  | ವಿವರಣೆ                                                                |
| ---------------------------- | ------------------------ | --------------------------------------------------------------------- |
| `API_KEY_SECRET`             | ಅಗತ್ಯ                    | API Key ರಚನೆ ಮತ್ತು ಮೌಲ್ಯೀಕರಣಕ್ಕಾಗಿ ಬಳಸಲಾಗುತ್ತದೆ                       |
| `JWT_SECRET`                 | ಅಗತ್ಯ                    | ಲಾಗಿನ್ ಸೆಷನ್ಗಳು ಮತ್ತು JWT ಸಹಿ ಮಾಡುವಿಕೆಗೆ ಬಳಸಲಾಗುತ್ತದೆ                 |
| `OMNIROUTE_WS_BRIDGE_SECRET` | ಪ್ರೊಡಕ್ಷನ್ನಲ್ಲಿ ಅಗತ್ಯ    | WebSocket ಬ್ರಿಡ್ಜ್ ದೃಢೀಕರಣದ ರಹಸ್ಯ                                     |
| `STORAGE_ENCRYPTION_KEY`     | ಬಲವಾಗಿ ಶಿಫಾರಸು ಮಾಡಲಾಗಿದೆ | ಸಂಗ್ರಹದಲ್ಲಿರುವ ಸೂಕ್ಷ್ಮ ಸಂಪರ್ಕ ಮಾಹಿತಿಯನ್ನು ಎನ್ಕ್ರಿಪ್ಟ್ ಮಾಡುತ್ತದೆ       |
| `MACHINE_ID_SALT`            | ಶಿಫಾರಸು ಮಾಡಲಾಗಿದೆ        | ಸ್ಥಿರವಾದ ಯಂತ್ರ ಗುರುತಿಸುವಿಕೆಯನ್ನು ರಚಿಸುತ್ತದೆ                           |
| `INITIAL_PASSWORD`           | ಐಚ್ಛಿಕ                   | ಮೊದಲ ಡಿಪ್ಲಾಯ್ಮೆಂಟ್ನಲ್ಲಿ ಆರಂಭಿಕ ಬ್ಯಾಕೆಂಡ್ ಪಾಸ್ವರ್ಡ್ ಅನ್ನು ಹೊಂದಿಸುತ್ತದೆ |
| OAuth/API ಖಾಸಗಿ ರುಜುವಾತುಗಳು  | ಅಗತ್ಯಕ್ಕೆ ತಕ್ಕಂತೆ        | ಬಾಹ್ಯ ಪ್ಲಾಟ್ಫಾರ್ಮ್ ದೃಢೀಕರಣ ಸಂರಚನೆ                                     |

### 6.2 ಪ್ರಸ್ತುತ ಪ್ರಾಜೆಕ್ಟ್ಗಾಗಿ ಶಿಫಾರಸು ಮಾಡಲಾದ ಮೌಲ್ಯಗಳು

| ವೇರಿಯೇಬಲ್              | ಶಿಫಾರಸು ಮಾಡಲಾದ ಮೌಲ್ಯ        |
| ---------------------- | --------------------------- |
| `DATA_DIR`             | `/data`                     |
| `NEXT_PUBLIC_BASE_URL` | `https://omniroute.fly.dev` |

ಟಿಪ್ಪಣಿಗಳು:

- `DATA_DIR=/data` ಅತ್ಯಂತ ಮುಖ್ಯವಾಗಿದ್ದು, Fly Volume ಮೌಂಟ್ ಪಾಯಿಂಟ್ಗೆ ಹೊಂದಿಕೆಯಾಗಲೇಬೇಕು
- `NEXT_PUBLIC_BASE_URL` ಅನ್ನು ಶೆಡ್ಯೂಲರ್, ಫ್ರಂಟ್ಎಂಡ್ ಕಾಲ್ಬ್ಯಾಕ್ಗಳು ಮತ್ತು ಇದೇ ರೀತಿಯ ಸಂದರ್ಭಗಳಲ್ಲಿ ಬಳಸಲಾಗುತ್ತದೆ

### 6.3 OAuth ಕಾಲ್ಬ್ಯಾಕ್ URL ಸಂರಚನೆ

Fly.io ಡಿಪ್ಲಾಯ್ಮೆಂಟ್ನಲ್ಲಿ OAuth-ಆಧಾರಿತ ಪೂರೈಕೆದಾರರನ್ನು (ಉದಾ. Antigravity, Gemini, Cursor) ಸಕ್ರಿಯಗೊಳಿಸಬೇಕಾದರೆ, ಕೆಳಗಿನ ಎರಡು ಅಂಶಗಳನ್ನು ಖಚಿತಪಡಿಸಿಕೊಳ್ಳಿ:

1. **`NEXT_PUBLIC_BASE_URL` ಅನ್ನು ನಿಮ್ಮ ಸಾರ್ವಜನಿಕ HTTPS ಡೊಮೇನ್ಗೆ ಹೊಂದಿಸಿ**

   ```powershell
   flyctl secrets set NEXT_PUBLIC_BASE_URL=https://omniroute.fly.dev -a omniroute
   ```

   ನೀವು ಕಸ್ಟಮ್ ಡೊಮೇನ್ ಬಳಸುತ್ತಿದ್ದರೆ, ಅದನ್ನು ಸಂಬಂಧಿತ ಡೊಮೇನ್ನೊಂದಿಗೆ ಬದಲಾಯಿಸಿ (ಉದಾ. `https://omniroute.yourdomain.com`).

2. **ಪೂರೈಕೆದಾರರ ಕನ್ಸೋಲ್ನಲ್ಲಿ ಕಾಲ್ಬ್ಯಾಕ್ URL ಅನ್ನು ಸಂರಚಿಸಿ**

   ಎಲ್ಲಾ OAuth ಪೂರೈಕೆದಾರರೂ ಒಂದೇ ಕಾಲ್ಬ್ಯಾಕ್ ಪಥವಾದ `/callback` ಅನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತಾರೆ — ಪ್ರತಿ ಪೂರೈಕೆದಾರರಿಗೆ ಪ್ರತ್ಯೇಕ ಕಾಲ್ಬ್ಯಾಕ್ ರೂಟ್ ಇಲ್ಲ:

   ```text
   <NEXT_PUBLIC_BASE_URL>/callback
   ```

   ಉದಾಹರಣೆಗೆ, Gemini, Antigravity, Cursor ಅಥವಾ GitLab Duo ಯಾವುದಾಗಿದ್ದರೂ:
   - `https://omniroute.fly.dev/callback`

   `NEXT_PUBLIC_BASE_URL` ಪೂರೈಕೆದಾರರ ಬಳಿ ನೋಂದಾಯಿಸಲಾದ ಕಾಲ್ಬ್ಯಾಕ್ URLಗೆ ಹೊಂದಿಕೆಯಾಗದಿದ್ದರೆ, ಬ್ರೌಸರ್ ಮರುನಿರ್ದೇಶನ ಹಂತದಲ್ಲಿ OAuth ಪ್ರಕ್ರಿಯೆಯು ವಿಫಲಗೊಳ್ಳುತ್ತದೆ.

## 7. ಒಂದೇ ಕಮಾಂಡ್ನಲ್ಲಿ ರಹಸ್ಯಗಳ ಸೆಟಪ್

ಕೆಳಗಿನ ಕಮಾಂಡ್ಗಳು ಸುರಕ್ಷಿತ ಯಾದೃಚ್ಛಿಕ ಮೌಲ್ಯಗಳನ್ನು ರಚಿಸಿ, ಪ್ರಸ್ತುತ ಪ್ರಾಜೆಕ್ಟ್ಗೆ ಅಗತ್ಯವಿರುವ ಎಲ್ಲಾ ನಿಯತಾಂಕಗಳನ್ನು ಒಂದೇ ಹಂತದಲ್ಲಿ Fly Secretsಗೆ ಬರೆಯುತ್ತವೆ.

ಟಿಪ್ಪಣಿಗಳು:

- `INITIAL_PASSWORD` ಅನ್ನು ಒಳಗೊಂಡಿಲ್ಲ
- ಪ್ರಸ್ತುತ `omniroute` ಪ್ರಾಜೆಕ್ಟ್ಗಾಗಿ ಉದ್ದೇಶಿಸಲಾಗಿದೆ

```powershell
$apiKeySecret = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$jwtSecret = [Convert]::ToHexString((1..64 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$machineIdSalt = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$storageKey = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$wsBridgeSecret = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()

flyctl secrets set `
  API_KEY_SECRET=$apiKeySecret `
  JWT_SECRET=$jwtSecret `
  MACHINE_ID_SALT=$machineIdSalt `
  STORAGE_ENCRYPTION_KEY=$storageKey `
  OMNIROUTE_WS_BRIDGE_SECRET=$wsBridgeSecret `
  DATA_DIR=/data `
  NEXT_PUBLIC_BASE_URL=https://omniroute.fly.dev `
  -a omniroute
```

Linux / macOSನಲ್ಲಿ, ನೀವು `openssl rand -hex 32` ಅನ್ನು ಸಹ ಬಳಸಬಹುದು:

```bash
flyctl secrets set OMNIROUTE_WS_BRIDGE_SECRET=$(openssl rand -hex 32) -a omniroute
```

ಟಿಪ್ಪಣಿಗಳು:

- `OMNIROUTE_WS_BRIDGE_SECRET` ಪ್ರೊಡಕ್ಷನ್ನಲ್ಲಿ ಅಗತ್ಯವಾಗಿದೆ; ಅದು ಇಲ್ಲದಿದ್ದರೆ WebSocket ಬ್ರಿಡ್ಜ್ ಹ್ಯಾಂಡ್ಶೇಕ್ ವಿಫಲಗೊಳ್ಳುತ್ತದೆ

ನೀವು ಆರಂಭಿಕ ಪಾಸ್ವರ್ಡ್ ಅನ್ನು ಸಹ ಹೊಂದಿಸಲು ಬಯಸಿದರೆ:

```powershell
flyctl secrets set INITIAL_PASSWORD=your-strong-password -a omniroute
```

## 8. ಪ್ರಸ್ತುತ ಪ್ಯಾರಾಮೀಟರ್ಗಳನ್ನು ವೀಕ್ಷಿಸುವುದು

```powershell
flyctl secrets list -a omniroute
```

ಕನ್ಸೋಲ್ನಲ್ಲಿರುವ `Secrets` ಪುಟವು ನಿರೀಕ್ಷಿತ ವೇರಿಯಬಲ್ಗಳನ್ನು ತೋರಿಸದಿದ್ದರೆ, ಇವುಗಳನ್ನು ಪರಿಶೀಲಿಸಿ:

- ನೀವು `omniroute` ಅಪ್ಲಿಕೇಶನ್ ಅನ್ನು ವೀಕ್ಷಿಸುತ್ತಿದ್ದೀರಿ ಎಂಬುದನ್ನು
- `fly.toml` ನಲ್ಲಿರುವ `app` ಮೌಲ್ಯವು ಕನ್ಸೋಲ್ನಲ್ಲಿರುವ ಅಪ್ಲಿಕೇಶನ್ಗೆ ಹೊಂದಿಕೆಯಾಗುತ್ತದೆ ಎಂಬುದನ್ನು

## 9. ನಂತರದ ನವೀಕರಣಗಳು ಮತ್ತು ಬಿಡುಗಡೆಗಳು

ಕೋಡ್ ನವೀಕರಣಗಳ ನಂತರ, ಬಿಡುಗಡೆ ಪ್ರಕ್ರಿಯೆಯು ಸರಳವಾಗಿದೆ:

```powershell
git pull
flyctl deploy
```

ಕೋಡ್ ಬದಲಾಯಿಸದೆ ಕೇವಲ ಪ್ಯಾರಾಮೀಟರ್ಗಳನ್ನು ನವೀಕರಿಸಬೇಕಾದರೆ:

```powershell
flyctl secrets set KEY=value -a omniroute
```

Fly ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಯಂತ್ರಗಳ ರೋಲಿಂಗ್ ನವೀಕರಣವನ್ನು ನಿರ್ವಹಿಸುತ್ತದೆ.

### 9.1 ನಿಮ್ಮ ಫೋರ್ಕ್ನ `fly.toml` ಅನ್ನು ಉಳಿಸಿಕೊಂಡು ಅಪ್ಸ್ಟ್ರೀಮ್ ರೆಪೊಸಿಟರಿ ನವೀಕರಣಗಳನ್ನು ಅನುಸರಿಸುವುದು

ಪ್ರಸ್ತುತ ರೆಪೊಸಿಟರಿಯು ಫೋರ್ಕ್ ಆಗಿದ್ದರೆ ಮತ್ತು ಅಪ್ಸ್ಟ್ರೀಮ್ `https://github.com/diegosouzapw/OmniRoute` ನಿಂದ ನವೀಕರಣಗಳನ್ನು ಸಿಂಕ್ ಮಾಡಲು ನೀವು ಬಯಸಿದರೆ, ಕೆಳಗಿನ ಕಾರ್ಯಪ್ರವಾಹವನ್ನು ಅನುಸರಿಸಿ.

ಮೊದಲು, ನಿಮ್ಮ ರಿಮೋಟ್ಗಳನ್ನು ಪರಿಶೀಲಿಸಿ:

```powershell
git remote -v
```

ನೀವು ಕನಿಷ್ಠ ಇವುಗಳನ್ನು ನೋಡಬೇಕು:

- ನಿಮ್ಮ ಸ್ವಂತ ಫೋರ್ಕ್ಗೆ ಸೂಚಿಸುವ `origin`
- ಮೂಲ ರೆಪೊಸಿಟರಿಗೆ ಸೂಚಿಸುವ `upstream`

`upstream` ಅನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡದಿದ್ದರೆ, ಅದನ್ನು ಸೇರಿಸಿ:

```powershell
git remote add upstream https://github.com/diegosouzapw/OmniRoute.git
```

ಅಪ್ಸ್ಟ್ರೀಮ್ನೊಂದಿಗೆ ಸಿಂಕ್ ಮಾಡುವ ಮೊದಲು, ಇತ್ತೀಚಿನ ಕಮಿಟ್ಗಳು ಮತ್ತು ಟ್ಯಾಗ್ಗಳನ್ನು ಪಡೆದುಕೊಳ್ಳಿ:

```powershell
git fetch upstream --tags
```

ಪ್ರಸ್ತುತ ಆವೃತ್ತಿ ಮತ್ತು ಅಪ್ಸ್ಟ್ರೀಮ್ ಟ್ಯಾಗ್ಗಳನ್ನು ಪರಿಶೀಲಿಸಿ:

```powershell
git describe --tags --always
git show --no-patch --oneline v3.4.7
```

> ಗಮನಿಸಿ: ಪ್ರಸ್ತುತ ಪ್ರಾಜೆಕ್ಟ್ ಆವೃತ್ತಿಯು `v3.8.0` ಆಗಿದೆ. ಕೆಳಗಿನ `v3.4.7` ಉಲ್ಲೇಖಗಳನ್ನು ಐತಿಹಾಸಿಕ ಉದಾಹರಣೆಗಳಾಗಿ ಮಾತ್ರ ಉಳಿಸಲಾಗಿದೆ. ನೈಜ ಬಿಡುಗಡೆಗಳಿಗಾಗಿ, `:latest` ಅಥವಾ ಪ್ರಸ್ತುತ ಆವೃತ್ತಿಯ ಟ್ಯಾಗ್ ಅನ್ನು ಬಳಸಿ (ಉದಾ. `:v3.8.0`).

ನಿಮ್ಮ ಫೋರ್ಕ್ನ `fly.toml` ಅನ್ನು ಕಡ್ಡಾಯವಾಗಿ ಉಳಿಸಿಕೊಂಡು, ಇತ್ತೀಚಿನ ಅಪ್ಸ್ಟ್ರೀಮ್ `main` ಅನ್ನು ವಿಲೀನಗೊಳಿಸಲು ನೀವು ಬಯಸಿದರೆ, ಈ ಕಾರ್ಯಪ್ರವಾಹವನ್ನು ಅನುಸರಿಸಿ:

```powershell
git merge upstream/main
git checkout HEAD~1 -- fly.toml
git add -- fly.toml
git commit -m "chore(deploy): keep fork fly.toml"
git push origin main
```

ಟಿಪ್ಪಣಿಗಳು:

- `git merge upstream/main` ಮೂಲ ರೆಪೊಸಿಟರಿಯಿಂದ ಇತ್ತೀಚಿನ ಕೋಡ್ ಅನ್ನು ಸಿಂಕ್ ಮಾಡುತ್ತದೆ
- `git checkout HEAD~1 -- fly.toml` ವಿಲೀನಕ್ಕೂ ಮೊದಲಿನ ನಿಮ್ಮ ಫೋರ್ಕ್ನ ಸ್ವಂತ `fly.toml` ಅನ್ನು ಮರುಸ್ಥಾಪಿಸುತ್ತದೆ
- ಅಪ್ಸ್ಟ್ರೀಮ್ `fly.toml` ಅನ್ನು ಮಾರ್ಪಡಿಸದಿದ್ದರೆ, ಈ ಹಂತವು ಯಾವುದೇ ವ್ಯತ್ಯಾಸಗಳನ್ನು ಉಂಟುಮಾಡುವುದಿಲ್ಲ
- ಅಪ್ಸ್ಟ್ರೀಮ್ `fly.toml` ಅನ್ನು ಮಾರ್ಪಡಿಸಿದ್ದರೆ, ಈ ಹಂತವು ನಿಮ್ಮ Fly ಅಪ್ಲಿಕೇಶನ್ ಹೆಸರು, ವಾಲ್ಯೂಮ್ ಮೌಂಟ್, ಪ್ರದೇಶ ಮತ್ತು ಇತರ ಫೋರ್ಕ್-ನಿರ್ದಿಷ್ಟ ನಿಯೋಜನಾ ಕಾನ್ಫಿಗರೇಶನ್ಗಳು ತಿದ್ದಿಬರೆಯಲ್ಪಡದಂತೆ ಖಚಿತಪಡಿಸುತ್ತದೆ

ನಿರ್ದಿಷ್ಟ ಬಿಡುಗಡೆ ಟ್ಯಾಗ್ನೊಂದಿಗೆ (ಉದಾ. `v3.4.7`) ಹೊಂದಾಣಿಕೆ ಮಾಡಲು ನೀವು ಬಯಸಿದರೆ, ಮೊದಲು ಆ ಟ್ಯಾಗ್ ಈಗಾಗಲೇ `upstream/main` ನಲ್ಲಿ ಸೇರಿದೆ ಎಂಬುದನ್ನು ಪರಿಶೀಲಿಸಿ:

```powershell
git merge-base --is-ancestor v3.4.7 upstream/main
```

ಯಶಸ್ವಿ ಫಲಿತಾಂಶ ಎಂದರೆ `upstream/main` ಈಗಾಗಲೇ ಆ ಆವೃತ್ತಿಯನ್ನು ಒಳಗೊಂಡಿದೆ; ನೀವು ಸರಳವಾಗಿ `upstream/main` ಅನ್ನು ವಿಲೀನಗೊಳಿಸಬಹುದು.

### 9.2 ಅಪ್ಸ್ಟ್ರೀಮ್ ಸಿಂಕ್ ಮಾಡಿದ ನಂತರದ ಪ್ರಮಾಣಿತ ಬಿಡುಗಡೆ ಅನುಕ್ರಮ

ಮೂಲ ರೆಪೊಸಿಟರಿಯೊಂದಿಗೆ ಸಿಂಕ್ ಮಾಡಿದ ನಂತರ, ಶಿಫಾರಸು ಮಾಡಲಾದ ಈ ಬಿಡುಗಡೆ ಕ್ರಮವನ್ನು ಅನುಸರಿಸಿ:

1. `git fetch upstream --tags`
2. `git merge upstream/main`
3. ಫೋರ್ಕ್ನ `fly.toml` ಅನ್ನು ಮರುಸ್ಥಾಪಿಸಿ
4. `git push origin main`
5. `flyctl deploy`
6. `flyctl status -a omniroute`
7. `flyctl logs --no-tail -a omniroute`

ಪ್ರಸ್ತುತ ಪ್ರಾಜೆಕ್ಟ್ ಅನ್ನು `v3.4.7` ಗೆ ಅಪ್ಗ್ರೇಡ್ ಮಾಡುವಾಗ ಬಳಸಲಾದ ನೈಜ ಕಾರ್ಯಪ್ರವಾಹ ಇದೇ ಆಗಿದೆ (ಈ ಉದಾಹರಣೆಯು ಐತಿಹಾಸಿಕ ಆವೃತ್ತಿಯನ್ನು ಉಲ್ಲೇಖಿಸುತ್ತದೆ; ಪ್ರಸ್ತುತ ನೈಜ ಆವೃತ್ತಿಯು `v3.8.0` ಆಗಿದೆ).

### 10.2 ಪ್ರಾರಂಭದ ಲಾಗ್ಗಳನ್ನು ವೀಕ್ಷಿಸಿ


### 10.3 ಸೈಟ್ ಪ್ರವೇಶಸಾಧ್ಯತೆಯನ್ನು ಪರಿಶೀಲಿಸಿ

```powershell
try {
  (Invoke-WebRequest -Uri "https://omniroute.fly.dev" -MaximumRedirection 5 -UseBasicParsing).StatusCode
} catch {
  if ($_.Exception.Response) {
    $_.Exception.Response.StatusCode.value__
  } else {
    throw
  }
}
```

`200` ಮರುಮೌಲ್ಯವು ಸೈಟ್ ಸಾಮಾನ್ಯವಾಗಿ ಪ್ರತಿಕ್ರಿಯಿಸುತ್ತಿದೆ ಎಂಬುದನ್ನು ಸೂಚಿಸುತ್ತದೆ.

---

## 11. ಯಶಸ್ಸಿನ ಸೂಚಕಗಳು

ಯಶಸ್ವಿ ನಿಯೋಜನೆಯ ನಂತರ, ಲಾಗ್ಗಳು ಈ ಕೆಳಗಿನಂತಿರುವ ವಿಷಯವನ್ನು ತೋರಿಸಬೇಕು:

```text
[bootstrap] Secrets persisted to: /data/server.env
[DB] SQLite database ready: /data/storage.sqlite
```

ಈ ಎರಡು ಅಂಶಗಳು ಅತ್ಯಂತ ಮುಖ್ಯವಾಗಿವೆ:

- `/data/server.env` ರನ್ಟೈಮ್ ರಹಸ್ಯಗಳನ್ನು ಶಾಶ್ವತ ವಾಲ್ಯೂಮ್ಗೆ ಬರೆಯಲಾಗಿದೆ ಎಂಬುದನ್ನು ದೃಢಪಡಿಸುತ್ತದೆ
- `/data/storage.sqlite` ಡೇಟಾಬೇಸ್ ಅನ್ನು ಶಾಶ್ವತ ವಾಲ್ಯೂಮ್ಗೆ ಬರೆಯಲಾಗಿದೆ ಎಂಬುದನ್ನು ದೃಢಪಡಿಸುತ್ತದೆ

ಬದಲಿಗೆ `/app/data/...` ಕಾಣಿಸಿದರೆ, `DATA_DIR` ಅನ್ನು ತಪ್ಪಾಗಿ ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾಗಿದೆ ಮತ್ತು ಅದನ್ನು ತಕ್ಷಣವೇ ಸರಿಪಡಿಸಬೇಕು.

---

## 12. ಸಾಮಾನ್ಯ ಸಮಸ್ಯೆಗಳು

### 12.1 `Secrets` ಪುಟ ಖಾಲಿಯಾಗಿದೆ

ಸಾಮಾನ್ಯವಾಗಿ ಇದಕ್ಕೆ ಎರಡು ಕಾರಣಗಳಿರುತ್ತವೆ:

- ನೀವು ಇನ್ನೂ `flyctl secrets set` ಅನ್ನು ಚಲಾಯಿಸಿಲ್ಲ
- ನೀವು ಬೇರೆ ಅಪ್ಲಿಕೇಶನ್ ಅನ್ನು ವೀಕ್ಷಿಸುತ್ತಿದ್ದೀರಿ (ಉದಾ. `omniroute` ಬದಲಿಗೆ `oroute`)

### 12.2 `flyctl deploy`, `app not found` ಎಂದು ವರದಿ ಮಾಡುತ್ತದೆ

ಮೊದಲು ಅಪ್ಲಿಕೇಶನ್ ಅನ್ನು ರಚಿಸಿ:

```powershell
flyctl apps create omniroute
```

### 12.3 `fly.toml` ಪಾರ್ಸಿಂಗ್ ವಿಫಲವಾಗುತ್ತದೆ

ಕೆಳಗಿನವುಗಳನ್ನು ಪರಿಶೀಲಿಸಿ:

- ಕಾಮೆಂಟ್ಗಳಲ್ಲಿ ಅಸ್ಪಷ್ಟ ಅಥವಾ ದೋಷಪೂರಿತ ಅಕ್ಷರಗಳಿವೆಯೇ
- TOML ಉದ್ಧರಣ ಚಿಹ್ನೆಗಳು ಮತ್ತು ಇಂಡೆಂಟೇಶನ್ ಸರಿಯಾಗಿವೆಯೇ

### 12.4 ಡೇಟಾ ಶಾಶ್ವತವಾಗಿ ಉಳಿಯುತ್ತಿಲ್ಲ

ಕೆಳಗಿನ ಎರಡನ್ನೂ ಪರಿಶೀಲಿಸಿ:

- `fly.toml` ನಲ್ಲಿ `destination = '/data'` ಇದೆ
- `DATA_DIR` ಅನ್ನು `/data` ಗೆ ಹೊಂದಿಸಲಾಗಿದೆ

### 12.5 `INITIAL_PASSWORD` ಇಲ್ಲದೆ ಇದನ್ನು ಚಲಾಯಿಸಬಹುದೇ?

ಹೌದು, ಇದನ್ನು ಚಲಾಯಿಸಬಹುದು. ಇದು ಡೀಫಾಲ್ಟ್ `CHANGEME` ಪಾಸ್ವರ್ಡ್ಗೆ ಹಿಂತಿರುಗುತ್ತದೆ. ಪ್ರೊಡಕ್ಷನ್ನಲ್ಲಿ ಬ್ಯಾಕೆಂಡ್ ಪಾಸ್ವರ್ಡ್ ಅನ್ನು ಸಾಧ್ಯವಾದಷ್ಟು ಬೇಗ ಬದಲಾಯಿಸುವುದು ಶಿಫಾರಸು ಮಾಡಲಾಗಿದೆ.

---

## 13. ಹೊಸ ಪ್ರಾಜೆಕ್ಟ್ಗಳಿಗಾಗಿ ಮರುಬಳಕೆ

ಈ ಡಾಕ್ಯುಮೆಂಟ್ ಅನ್ನು ಅನುಸರಿಸಿ ನೀವು ಹೊಸ ಪ್ರಾಜೆಕ್ಟ್ ಅನ್ನು ನಿಯೋಜಿಸುತ್ತಿದ್ದರೆ, ಈ ಅಂಶಗಳನ್ನು ಮಾತ್ರ ಬದಲಾಯಿಸಬೇಕಾಗುತ್ತದೆ:

1. `fly.toml` ನಲ್ಲಿನ `app` ಮೌಲ್ಯವನ್ನು ಬದಲಾಯಿಸಿ
2. `NEXT_PUBLIC_BASE_URL` ಅನ್ನು ಬದಲಾಯಿಸಿ
3. `DATA_DIR=/data` ಅನ್ನು ಹಾಗೆಯೇ ಉಳಿಸಿ
4. `API_KEY_SECRET`, `JWT_SECRET`, `MACHINE_ID_SALT`, ಮತ್ತು `STORAGE_ENCRYPTION_KEY` ಅನ್ನು ಪುನರುತ್ಪಾದಿಸಿ
5. ಮೊದಲ ನಿಯೋಜನೆಯ ನಂತರ, ಲಾಗ್ಗಳನ್ನು `/data` ಗೆ ಬರೆಯಲಾಗುತ್ತಿದೆ ಎಂಬುದನ್ನು ಪರಿಶೀಲಿಸಿ

ಹಿಂದಿನ ಪ್ರಾಜೆಕ್ಟ್ನ ಕೀಗಳನ್ನು ಮರುಬಳಕೆ ಮಾಡಬೇಡಿ.

---

## 14. ಪ್ರಸ್ತುತ ಪ್ರಾಜೆಕ್ಟ್ಗಾಗಿ ಕನಿಷ್ಠ ಬಿಡುಗಡೆ ಪರಿಶೀಲನಾಪಟ್ಟಿ

ನಂತರದ ಬಿಡುಗಡೆಗಳಿಗಾಗಿ ಸಾಮಾನ್ಯವಾಗಿ ಬಳಸುವ ಕಮಾಂಡ್ಗಳು:

```powershell
flyctl auth whoami
flyctl status -a omniroute
flyctl secrets list -a omniroute
flyctl deploy
flyctl logs --no-tail -a omniroute
```

ಸಾಮಾನ್ಯ ಬಿಡುಗಡೆಗಾಗಿ, ಮುಖ್ಯ ಕಮಾಂಡ್ ಸರಳವಾಗಿ:

```powershell
flyctl deploy
```

ಹೊಸ ಪರಿಸರದಲ್ಲಿ ಮೊದಲ ಬಾರಿಯ ನಿಯೋಜನೆಗಾಗಿ, ಮುಖ್ಯ ಹಂತಗಳು:

1. `flyctl auth login`
2. `flyctl apps create omniroute`
3. `flyctl secrets set ... -a omniroute`
4. `flyctl deploy`
5. `flyctl logs --no-tail -a omniroute`
