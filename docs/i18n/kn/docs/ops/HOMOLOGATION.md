ಹೋಮೋಲೊಗೇಶನ್ VPS ನಲ್ಲಿ ಚಾಲನೆಯಲ್ಲಿರುವ OmniRoute ಡಿಪ್ಲಾಯ್ನ ನೈಜ-ಪರಿಸರ E2E ಮೌಲ್ಯೀಕರಣ
(`HOMOLOG_BASE_URL`, ಉದಾ. `http://192.168.0.15:20128`). ಒಂದು ಕಮಾಂಡ್ ಹಸ್ತಚಾಲಿತ
ಬಿಡುಗಡೆ STOP #2 ಪರಿಶೀಲನಾಪಟ್ಟಿಯನ್ನು ಸ್ವಯಂಚಾಲಿತ, ಸಾಕ್ಷ್ಯ-ಉತ್ಪಾದಿಸುವ ಚಾಲನೆಯಿಂದ ಬದಲಾಯಿಸುತ್ತದೆ.

## ಪೂರ್ವಾಪೇಕ್ಷಿತಗಳು

1. `.env.homolog.example` ಅನ್ನು `.env.homolog` ಗೆ ನಕಲಿಸಿ (gitignored — ಅದನ್ನು ಎಂದಿಗೂ commit ಮಾಡಬೇಡಿ) ಮತ್ತು ಇವುಗಳನ್ನು ಭರ್ತಿ ಮಾಡಿ:
   - `HOMOLOG_BASE_URL` — ಗುರಿ deploy, ಉದಾ. `http://192.168.0.15:20128`.
   - `HOMOLOG_ADMIN_PASSWORD` — ಆ deploy ಗಾಗಿ dashboard ನಿರ್ವಹಣಾ password.
   - `HOMOLOG_CRITICAL_PROVIDERS` — ನೈಜ smoke chat request ಪಡೆಯುವ, comma ಮೂಲಕ ಬೇರ್ಪಡಿಸಿದ provider prefixes (ಉದಾ. `openai,anthropic,gemini,codex,grok,glm,deepseek,openrouter`).
   - `HOMOLOG_API_KEY` — ಸಾಮಾನ್ಯ runs ನಲ್ಲಿ ಖಾಲಿ ಬಿಡಿ; suite ತನ್ನದೇ ಅಲ್ಪಕಾಲಿಕ key ಅನ್ನು ರಚಿಸಿ ಹಿಂಪಡೆಯುತ್ತದೆ. ಒಂದೇ layer ಅನ್ನು ಪ್ರತ್ಯೇಕವಾಗಿ debug ಮಾಡಲು ಮಾತ್ರ ಇದನ್ನು ಹೊಂದಿಸಿ.
2. repo ದಲ್ಲಿ `npm install` ಚಲಾಯಿಸಿ (suite ನ dependencies — `httpyac`, `promptfoo`, `playwright-ctrf-json-reporter`, `junit-to-ctrf`, `ctrf` — ಸಾಮಾನ್ಯ devDependencies ಆಗಿವೆ).
3. browser binaries ಈಗಾಗಲೇ ಇಲ್ಲದಿದ್ದರೆ `npx playwright install` ಚಲಾಯಿಸಿ.

## ಚಲಾಯಿಸುವ ವಿಧಾನ

```bash
npm run homolog
```

ಸ್ಥಳೀಯ `package.json` ನೊಂದಿಗೆ version ಹೊಂದಿಕೆಯಾಗದ deploy ವಿರುದ್ಧ ಮೌಲ್ಯೀಕರಿಸಲು
(ಉದಾ. ಇನ್ನೂ ಹಿಂದಿನ patch release ನಲ್ಲಿರುವ homologation box), ನಿರೀಕ್ಷಿತ
version ಅನ್ನು ಸ್ಪಷ್ಟವಾಗಿ override ಮಾಡಿ:

```bash
HOMOLOG_EXPECT_VERSION=3.8.47 npm run homolog
```

ಯಾವುದೇ layer ವಿಫಲವಾದರೆ run non-zero ಸ್ಥಿತಿಯೊಂದಿಗೆ ನಿರ್ಗಮಿಸುತ್ತದೆ ಮತ್ತು ವಿಫಲವಾದಾಗಲೂ ಸಹ ತಾನು ರಚಿಸಿದ ಅಲ್ಪಕಾಲಿಕ
API key ಅನ್ನು ಹಿಂಪಡೆಯಲು ಯಾವಾಗಲೂ ಪ್ರಯತ್ನಿಸುತ್ತದೆ (`scripts/homolog/run.mjs` ನಲ್ಲಿನ `finally` block).

## ವರದಿಯನ್ನು ಓದುವುದು

ಎಲ್ಲಾ output ಗಳು `homolog-report/` ನಲ್ಲಿ ಸೇರುತ್ತವೆ (gitignored):

- `summary.md` — stdout ಗೆ print ಮಾಡಲಾದ ಅದೇ table, ಪ್ರತಿ layer ಗೆ ಒಂದು row (✅/❌ + ವಿವರ).
- `homolog-ctrf.json` — ಏಕೀಕೃತ CTRF report (API/SSE, provider-smoke ಮತ್ತು
  UI results ಗಳ merge) — release STOP #2 checklist ಗೆ ಲಗತ್ತಿಸಬೇಕಾದ artifact ಇದು.
- `httpyac-junit.xml`, `api-ctrf.json`, `providers-ctrf.json`, `ui-ctrf.json` — ಪ್ರತಿ
  layer ನ raw/intermediate reports.
- `promptfooconfig.yaml`, `provider-misses.json` — ಪ್ರಸ್ತುತ run ಗಾಗಿ ರಚಿಸಲಾದ promptfoo config ಮತ್ತು live catalog ನಲ್ಲಿ ಕಾಣೆಯಾಗಿದ್ದ ಯಾವುದೇ critical providers.

L0 ವಿಫಲವಾದರೆ ತಕ್ಷಣವೇ ಸ್ಥಗಿತಗೊಳ್ಳುತ್ತದೆ (ಯಾವುದೇ ಅಲ್ಪಕಾಲಿಕ key ರಚಿಸಲಾಗುವುದಿಲ್ಲ), ಏಕೆಂದರೆ version/health
ಹೊಂದಿಕೆಯಾಗದಿದ್ದರೆ downstream ನ ಪ್ರತಿಯೊಂದು layer ತಪ್ಪು deploy ಅನ್ನು ಮೌಲ್ಯೀಕರಿಸುತ್ತದೆ.

## UI ನ್ಯಾಯಸಮ್ಮತವಾಗಿ ಬದಲಾದಾಗ baseline ಅನ್ನು ಮರುಹೊಂದಿಸುವುದು

L4b (route smoke) ಮತ್ತು L4c (API-key UI flow) ಗಳು snapshots ಬದಲಿಗೆ ನೈಜ DOM locators ನಿಂದ
ನಿರ್ವಹಿಸಲ್ಪಡುತ್ತವೆ, ಆದ್ದರಿಂದ ಹೆಚ್ಚಿನ ನ್ಯಾಯಸಮ್ಮತ UI ಬದಲಾವಣೆಗಳಿಗೆ ಯಾವುದೇ suite update ಅಗತ್ಯವಿಲ್ಲ. ಬದಲಾವಣೆಯೊಂದು
locator ಅನ್ನು ಹಾಳುಮಾಡಿದಾಗ (ಉದಾ. ಮರುಹೆಸರಿಸಿದ button label ಅಥವಾ ಸ್ಥಳಾಂತರಿಸಿದ settings page):

1. ಪ್ರಸ್ತುತ source ವಿರುದ್ಧ locator ಅನ್ನು ಪುನಃ ದೃಢೀಕರಿಸಿ (ಪ್ರತಿ locator ಅನ್ನು ಯಾವ
   file/line ವಿರುದ್ಧ ದೃಢೀಕರಿಸಲಾಗಿದೆ ಎಂಬುದನ್ನು specs ಈಗಾಗಲೇ ದಾಖಲಿಸುತ್ತವೆ — ಅದೇ ಮಾದರಿಯನ್ನು ಅನುಸರಿಸಿ, ಊಹಿಸಬೇಡಿ).
2. `tests/homolog/ui/` ನಲ್ಲಿನ spec ಅನ್ನು update ಮಾಡಿ.
3. ಸರಿಪಡಿಸುವಿಕೆಯನ್ನು ದೃಢೀಕರಿಸಲು VPS ವಿರುದ್ಧ `npm run homolog` ಅನ್ನು (ಅಥವಾ ಪರಿಣಾಮಕ್ಕೊಳಗಾದ Playwright spec ಅನ್ನು ಮಾತ್ರ) ಪುನಃ ಚಲಾಯಿಸಿ, ನಂತರ commit ಮಾಡಿ.

ಈ suite ನಲ್ಲಿ ಯಾವುದೇ visual/pixel baseline ಇಲ್ಲ (F1) — ಅದಕ್ಕಾಗಿ Roadmap ನೋಡಿ.
