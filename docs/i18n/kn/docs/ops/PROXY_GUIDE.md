> **ಭೌಗೋಳಿಕ ನಿರ್ಬಂಧಗಳನ್ನು ಬೈಪಾಸ್ ಮಾಡಿ, ನಿಮ್ಮ ಗುರುತನ್ನು ರಕ್ಷಿಸಿ ಮತ್ತು ಯಾವುದೇ ಪ್ರಾಕ್ಸಿ ಮೂಲಕ AI ಟ್ರಾಫಿಕ್ ಅನ್ನು ರೂಟ್ ಮಾಡಿ — ಯಾವುದೇ ಸಂರಚನಾ ಸಂಕೀರ್ಣತೆಯಿಲ್ಲದೆ.**

OmniRoute, HTTP, HTTPS ಅಥವಾ SOCKS5 ಪ್ರಾಕ್ಸಿಗಳ ಮೂಲಕ ಅಪ್ಸ್ಟ್ರೀಮ್ AI ಪೂರೈಕೆದಾರರ ಟ್ರಾಫಿಕ್ ಅನ್ನು ರೂಟ್ ಮಾಡಲು ನಿಮಗೆ ಅನುವು ಮಾಡಿಕೊಡುವ ಸಂಪೂರ್ಣ ವೈಶಿಷ್ಟ್ಯಗಳ ಪ್ರಾಕ್ಸಿ ನಿರ್ವಹಣಾ ವ್ಯವಸ್ಥೆಯನ್ನು ಒಳಗೊಂಡಿದೆ. ನೀವು ನಿರ್ಬಂಧಿತ ಪ್ರದೇಶದಲ್ಲಿರಲಿ, IP ರೊಟೇಶನ್ ಅಗತ್ಯವಿರಲಿ ಅಥವಾ ಗುಪ್ತ ಫಿಂಗರ್ಪ್ರಿಂಟಿಂಗ್ ಬಯಸುತ್ತಿರಲಿ — ಈ ಮಾರ್ಗದರ್ಶಿಯು ಎಲ್ಲವನ್ನೂ ಒಳಗೊಂಡಿದೆ.

## ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಏಕೆ ಬಳಸಬೇಕು?

ಅನೇಕ AI ಪೂರೈಕೆದಾರರು ಭೌಗೋಳಿಕ ಪ್ರದೇಶದ ಆಧಾರದ ಮೇಲೆ ಪ್ರವೇಶವನ್ನು ನಿರ್ಬಂಧಿಸುತ್ತಾರೆ. **ರಷ್ಯಾ, ಚೀನಾ, ಇರಾನ್, ಕ್ಯೂಬಾ, ಟರ್ಕಿ** ಮತ್ತು ಇತರ ದೇಶಗಳ ಡೆವಲಪರ್ಗಳು ಈ ಕೆಳಗಿನಂತಹ ದೋಷಗಳನ್ನು ಎದುರಿಸುತ್ತಾರೆ:

```
unsupported_country_region_territory
```

ನಿರ್ಬಂಧಿತ ಪ್ರದೇಶಗಳ ಹೊರಗೆಯೂ ಪ್ರಾಕ್ಸಿಗಳು ಈ ಕೆಳಗಿನ ಸಂದರ್ಭಗಳಲ್ಲಿ ಉಪಯುಕ್ತವಾಗಿವೆ:

| ಬಳಕೆಯ ಸಂದರ್ಭ       | ವಿವರಣೆ                                                               |
| ------------------ | -------------------------------------------------------------------- |
| **ಭೌಗೋಳಿಕ ಬೈಪಾಸ್** | ನಿರ್ಬಂಧಿತ ದೇಶಗಳಿಂದ OpenAI, Anthropic, Codex, Copilot ಅನ್ನು ಪ್ರವೇಶಿಸಿ |
| **IP ರೊಟೇಶನ್**     | ದರ ಮಿತಿಯನ್ನು ತಪ್ಪಿಸಲು ವಿನಂತಿಗಳನ್ನು ಅನೇಕ IPಗಳಾದ್ಯಂತ ವಿತರಿಸಿ           |
| **ಗೌಪ್ಯತೆ**        | ಅಪ್ಸ್ಟ್ರೀಮ್ ಪೂರೈಕೆದಾರರಿಂದ ನಿಮ್ಮ ನೈಜ IPಯನ್ನು ಮರೆಮಾಡಿ                  |
| **ಅನುಸರಣೆ**        | ನಿರ್ದಿಷ್ಟ ನ್ಯಾಯವ್ಯಾಪ್ತಿಗಳ ಮೂಲಕ ಟ್ರಾಫಿಕ್ ಅನ್ನು ರೂಟ್ ಮಾಡಿ              |
| **ಪರೀಕ್ಷೆ**        | ವಿಭಿನ್ನ ಪ್ರದೇಶಗಳಿಂದ ಬರುವ ವಿನಂತಿಗಳನ್ನು ಅನುಕರಿಸಿ                       |

## 4-ಹಂತದ ಪ್ರಾಕ್ಸಿ ವ್ಯವಸ್ಥೆ

OmniRoute ಪ್ರಾಕ್ಸಿ ಸಂರಚನೆಯನ್ನು **ನಾಲ್ಕು ಸ್ವತಂತ್ರ ವ್ಯಾಪ್ತಿಗಳಲ್ಲಿ** ಬೆಂಬಲಿಸುತ್ತದೆ, ಆದ್ಯತೆಯ ಕ್ರಮದಲ್ಲಿ ಅವುಗಳನ್ನು ಪರಿಹರಿಸಲಾಗುತ್ತದೆ:

```
ಆದ್ಯತೆ ಪರಿಹಾರ ಕ್ರಮ (ಅತ್ಯಧಿಕ → ಅತ್ಯಂತ ಕಡಿಮೆ):

  1. 🔵 ಖಾತೆ/ಸಂಪರ್ಕ ಪ್ರಾಕ್ಸಿ  →  ಪ್ರತಿ API ಕೀ / OAuth ಸಂಪರ್ಕಕ್ಕೆ
  2. 🟡 ಪೂರೈಕೆದಾರ ಪ್ರಾಕ್ಸಿ    →  ಪ್ರತಿ ಪೂರೈಕೆದಾರರಿಗೆ (ಉದಾ., ಎಲ್ಲಾ OpenAI ಟ್ರಾಫಿಕ್)
  3. 🟠 ಕಾಂಬೊ ಪ್ರಾಕ್ಸಿ        →  ಪ್ರತಿ ಕಾಂಬೊ/ರೂಟಿಂಗ್ ಸಂರಚನೆಗೆ
  4. 🟢 ಜಾಗತಿಕ ಪ್ರಾಕ್ಸಿ       →  ಎಲ್ಲಾ ಟ್ರಾಫಿಕ್, ಎಲ್ಲಾ ಪೂರೈಕೆದಾರರು
```

### ಪರಿಹಾರವು ಹೇಗೆ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ

OmniRoute ಅಪ್ಸ್ಟ್ರೀಮ್ ಪೂರೈಕೆದಾರರಿಗೆ ವಿನಂತಿಯನ್ನು ಕಳುಹಿಸಿದಾಗ, ಅದು `resolveProxyForConnectionFromRegistry()` ಅನ್ನು ಕರೆದು ಪ್ರತಿಯೊಂದು ಹಂತವನ್ನೂ ಕ್ರಮವಾಗಿ ಪರಿಶೀಲಿಸುತ್ತದೆ:

1. **ಖಾತೆ-ಹಂತ** — ಈ ನಿರ್ದಿಷ್ಟ ಸಂಪರ್ಕ IDಗೆ ಪ್ರಾಕ್ಸಿಯನ್ನು ನಿಯೋಜಿಸಲಾಗಿದೆಯೇ?
2. **ಪೂರೈಕೆದಾರ-ಹಂತ** — ಈ ಪೂರೈಕೆದಾರರಿಗೆ (ಉದಾ., `openai`) ಪ್ರಾಕ್ಸಿಯನ್ನು ನಿಯೋಜಿಸಲಾಗಿದೆಯೇ?
3. **ಜಾಗತಿಕ-ಹಂತ** — ಜಾಗತಿಕ ಪ್ರಾಕ್ಸಿಯನ್ನು ಸಂರಚಿಸಲಾಗಿದೆಯೇ?
4. **ಪ್ರಾಕ್ಸಿ ಇಲ್ಲ** — ಪೂರೈಕೆದಾರರಿಗೆ ನೇರ ಸಂಪರ್ಕ.

ಮೊದಲ ಹೊಂದಾಣಿಕೆಗೆ ಆದ್ಯತೆ ಸಿಗುತ್ತದೆ. ಇದರರ್ಥ ನೀವು ಜಾಗತಿಕ ಪ್ರಾಕ್ಸಿಯನ್ನು ಪರ್ಯಾಯ ಆಯ್ಕೆಯಾಗಿ ಹೊಂದಿಸಬಹುದು, ಆದರೆ ನಿರ್ದಿಷ್ಟ ಪೂರೈಕೆದಾರರು ಅಥವಾ ಸಂಪರ್ಕಗಳಿಗಾಗಿ ಅದನ್ನು ಅತಿಕ್ರಮಿಸಬಹುದು.

| ಸಂಪರ್ಕ ಪರೀಕ್ಷೆಗಳು       | ✅                       | "ಸಂಪರ್ಕವನ್ನು ಪರೀಕ್ಷಿಸಿ" ಬಟನ್ ಪ್ರಾಕ್ಸಿಯನ್ನು ಬಳಸುತ್ತದೆ             |
| ಟೋಕನ್ ನವೀಕರಣ            | ✅                       | ಹಿನ್ನೆಲೆ OAuth ನವೀಕರಣ                                            |
| ಮಾದರಿ ಸಿಂಕ್             | ✅                       | ಮಾದರಿ ಪಟ್ಟಿ ಮತ್ತು ಅನ್ವೇಷಣೆ                                       |

## ಪ್ರಾಕ್ಸಿ ರಿಜಿಸ್ಟ್ರಿ (CRUD)

ಪ್ರಾಕ್ಸಿ ರಿಜಿಸ್ಟ್ರಿಯು ನಿಮ್ಮ ಎಲ್ಲಾ ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಸಂಗ್ರಹಿಸುವ SQLite ಕೋಷ್ಟಕ (`proxy_registry`) ಆಗಿದೆ. ಪ್ರತಿಯೊಂದು ಪ್ರಾಕ್ಸಿಯು ಈ ಕೆಳಗಿನವುಗಳನ್ನು ಹೊಂದಿರುತ್ತದೆ:

| ಕ್ಷೇತ್ರ    | ಪ್ರಕಾರ    | ವಿವರಣೆ                                                            |
| ---------- | --------- | ----------------------------------------------------------------- |
| `id`       | UUID      | ಅನನ್ಯ ಗುರುತಿಸುವಿಕೆ                                                |
| `name`     | ಸ್ಟ್ರಿಂಗ್ | ಮನುಷ್ಯರು ಓದಬಹುದಾದ ಲೇಬಲ್                                           |
| `type`     | ಸ್ಟ್ರಿಂಗ್ | ಪ್ರೋಟೋಕಾಲ್: `http`, `https`, `socks5`                             |
| `host`     | ಸ್ಟ್ರಿಂಗ್ | ಪ್ರಾಕ್ಸಿ ಹೋಸ್ಟ್ಹೆಸರು ಅಥವಾ IP                                      |
| `port`     | ಪೂರ್ಣಾಂಕ  | ಪೋರ್ಟ್ ಸಂಖ್ಯೆ                                                     |
| `username` | ಸ್ಟ್ರಿಂಗ್ | ದೃಢೀಕರಣ ಬಳಕೆದಾರಹೆಸರು (ಸಂಗ್ರಹಿತ ಸ್ಥಿತಿಯಲ್ಲಿ ಎನ್ಕ್ರಿಪ್ಟ್ ಮಾಡಲಾಗಿದೆ) |
| `password` | ಸ್ಟ್ರಿಂಗ್ | ದೃಢೀಕರಣ ಪಾಸ್ವರ್ಡ್ (ಸಂಗ್ರಹಿತ ಸ್ಥಿತಿಯಲ್ಲಿ ಎನ್ಕ್ರಿಪ್ಟ್ ಮಾಡಲಾಗಿದೆ)    |
| `region`   | ಸ್ಟ್ರಿಂಗ್ | ಭೌಗೋಳಿಕ ಪ್ರದೇಶದ ಲೇಬಲ್                                             |
| `notes`    | ಸ್ಟ್ರಿಂಗ್ | ಮುಕ್ತ-ಪಠ್ಯ ಟಿಪ್ಪಣಿಗಳು                                             |
| `status`   | ಸ್ಟ್ರಿಂಗ್ | `active` ಅಥವಾ `inactive`                                          |
| `source`   | ಸ್ಟ್ರಿಂಗ್ | `manual` ಅಥವಾ `oneproxy`                                          |

### ಪ್ರಾಕ್ಸಿಯನ್ನು ರಚಿಸುವುದು

**ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಮೂಲಕ:**

1. **ಸೆಟ್ಟಿಂಗ್ಗಳು → ಪ್ರಾಕ್ಸಿ**ಗೆ ಹೋಗಿ
2. **ಪ್ರಾಕ್ಸಿ ಸೇರಿಸಿ** ಕ್ಲಿಕ್ ಮಾಡಿ
3. ಪ್ರಕಾರ, ಹೋಸ್ಟ್, ಪೋರ್ಟ್ ಮತ್ತು ಐಚ್ಛಿಕ ದೃಢೀಕರಣ ರುಜುವಾತುಗಳನ್ನು ಭರ್ತಿ ಮಾಡಿ
4. ಉಳಿಸಿ

**API ಮೂಲಕ:**

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "US Proxy",
    "type": "http",
    "host": "proxy.example.com",
    "port": 8080,
    "username": "user",
    "password": "pass",
    "region": "US"
  }'
```

### ಪ್ರಾಕ್ಸಿಯನ್ನು ನವೀಕರಿಸುವುದು

```bash
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "id": "proxy-uuid-here",
    "host": "new-proxy.example.com",
    "port": 9090
  }'
```

> **ಗಮನಿಸಿ:** ನೀವು ಖಾಲಿಯಲ್ಲದ ಬದಲಿ ಮೌಲ್ಯಗಳನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ಕಳುಹಿಸದ ಹೊರತು ರುಜುವಾತುಗಳನ್ನು ಉಳಿಸಿಕೊಳ್ಳಲಾಗುತ್ತದೆ. `username`/`password`ಗಾಗಿ ಖಾಲಿ ಸ್ಟ್ರಿಂಗ್ಗಳನ್ನು ಕಳುಹಿಸಿದರೆ ಸಂಗ್ರಹಿತ ಮೌಲ್ಯಗಳನ್ನು ಹಾಗೆಯೇ ಉಳಿಸಿಕೊಳ್ಳಲಾಗುತ್ತದೆ.

### ಪ್ರಾಕ್ಸಿಯನ್ನು ಅಳಿಸುವುದು

```bash
# ಪ್ರಾಕ್ಸಿಯನ್ನು ಯಾವುದೇ ವ್ಯಾಪ್ತಿಗೆ ನಿಯೋಜಿಸಿದ್ದರೆ ವಿಫಲವಾಗುತ್ತದೆ
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid"

# ಬಲವಂತವಾಗಿ ಅಳಿಸಿ (ನಿಯೋಜನೆಗಳನ್ನೂ ತೆಗೆದುಹಾಕುತ್ತದೆ)
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid&force=1"
```

### ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡುವುದು

```bash
curl "http://localhost:20128/api/v1/management/proxies?limit=50&offset=0"
```

### ವ್ಯಾಪ್ತಿಗಳಿಗೆ ಪ್ರಾಕ್ಸಿಗಳನ್ನು ನಿಯೋಜಿಸುವುದು

```bash
# ಜಾಗತಿಕ ವ್ಯಾಪ್ತಿಗೆ ನಿಯೋಜಿಸಿ
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "global", "proxy": {"type":"http","host":"proxy.example.com","port":8080}}'

# ನಿರ್ದಿಷ್ಟ ಪೂರೈಕೆದಾರರಿಗೆ ನಿಯೋಜಿಸಿ
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "provider", "id": "openai", "proxy": {"type":"socks5","host":"socks.example.com","port":1080}}'

# ನಿರ್ದಿಷ್ಟ ಸಂಪರ್ಕ/ಕೀಗೆ ನಿಯೋಜಿಸಿ
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "key", "id": "connection-uuid", "proxy": {"type":"http","host":"key-proxy.com","port":3128}}'
```

### ಪರಿಣಾಮಕಾರಿ ಪ್ರಾಕ್ಸಿಯನ್ನು ಪರಿಹರಿಸುವುದು

ನಿರ್ದಿಷ್ಟ ಸಂಪರ್ಕಕ್ಕಾಗಿ ಯಾವ ಪ್ರಾಕ್ಸಿಯನ್ನು ಬಳಸಲಾಗುತ್ತದೆ ಎಂಬುದನ್ನು ಪರಿಶೀಲಿಸಿ:

```bash
curl "http://localhost:20128/api/settings/proxy?resolve=connection-uuid"
```

ಇದು ಪರಿಹರಿಸಲಾದ ಪ್ರಾಕ್ಸಿಯನ್ನು ಅದರ ಹಂತ (`account`, `provider`, ಅಥವಾ `global`) ಮತ್ತು ಮೂಲದೊಂದಿಗೆ ಹಿಂತಿರುಗಿಸುತ್ತದೆ.

### ಸಾಮೂಹಿಕ ನಿಯೋಜನೆ

ಒಂದು ಪ್ರಾಕ್ಸಿಯನ್ನು ಅನೇಕ ಪೂರೈಕೆದಾರರು ಅಥವಾ ಸಂಪರ್ಕಗಳಿಗೆ ಒಂದೇ ಬಾರಿಗೆ ನಿಯೋಜಿಸಿ:

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies/bulk-assign \
  -H "Content-Type: application/json" \
  -d '{
    "scope": "provider",
    "scopeIds": ["openai", "anthropic", "codex"],
    "proxyId": "proxy-uuid"
  }'
```

### ಆಮದು/ರಫ್ತು

ಪ್ರಾಕ್ಸಿಗಳನ್ನು **ಬ್ಯಾಕಪ್/ಮರುಸ್ಥಾಪನೆ** ವ್ಯವಸ್ಥೆಯಲ್ಲಿ ಸೇರಿಸಲಾಗಿದೆ. ನೀವು ನಿಮ್ಮ OmniRoute ಸಂರಚನೆಯನ್ನು ರಫ್ತು ಮಾಡುವಾಗ:

1. **ಡ್ಯಾಶ್ಬೋರ್ಡ್ → ಸೆಟ್ಟಿಂಗ್ಗಳು → ಬ್ಯಾಕಪ್**ಗೆ ಹೋಗಿ
2. **ರಫ್ತು** ಕ್ಲಿಕ್ ಮಾಡಿ — ಪ್ರಾಕ್ಸಿ ರಿಜಿಸ್ಟ್ರಿ ಮತ್ತು ನಿಯೋಜನೆಗಳನ್ನು ಸೇರಿಸಲಾಗುತ್ತದೆ
3. ಮರುಸ್ಥಾಪಿಸಲು, **ಆಮದು** ಕ್ಲಿಕ್ ಮಾಡಿ ಮತ್ತು ಬ್ಯಾಕಪ್ ಫೈಲ್ ಅನ್ನು ಅಪ್ಲೋಡ್ ಮಾಡಿ

ಪ್ರಾಕ್ಸಿ ರಿಜಿಸ್ಟ್ರಿಯು **host+port ಆಧಾರಿತ upsert** ಅನ್ನೂ ಬೆಂಬಲಿಸುತ್ತದೆ — ಈಗಾಗಲೇ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಪ್ರಾಕ್ಸಿಯನ್ನು (ಅದೇ ಹೋಸ್ಟ್ ಮತ್ತು ಪೋರ್ಟ್) ನೀವು ಆಮದು ಮಾಡಿದರೆ, ನಕಲನ್ನು ರಚಿಸುವ ಬದಲು ಅದನ್ನು ನವೀಕರಿಸುತ್ತದೆ.

### ಹಳೆಯ ವ್ಯವಸ್ಥೆಯಿಂದ ವಲಸೆ

ನೀವು ಹಳೆಯ ಆವೃತ್ತಿಯಲ್ಲಿ (ರೆಜಿಸ್ಟ್ರಿಗೂ ಹಿಂದಿನದು) ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡಿದ್ದರೆ, OmniRoute ಅವುಗಳನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ:

```
ಹಳೆಯ key_value ಸಂಗ್ರಹ → proxy_registry + proxy_assignments
```

ಅಪ್ಗ್ರೇಡ್ ಮಾಡಿದ ನಂತರ ಮೊದಲ ಬಾರಿಗೆ ಪ್ರಾರಂಭಿಸುವಾಗ ಇದು ಒಮ್ಮೆ ನಡೆಯುತ್ತದೆ. ಪುನಃ ಚಲಾಯಿಸಲು `migrateLegacyProxyConfigToRegistry({ force: true })` ಬಳಸಿ.

## 1proxy ಉಚಿತ ಪ್ರಾಕ್ಸಿ ಮಾರುಕಟ್ಟೆ

> 🆕 **[@oyi77](https://github.com/oyi77) ಅವರ ಕೊಡುಗೆ** — PR [#1847](https://github.com/diegosouzapw/OmniRoute/pull/1847) (ಸಮಸ್ಯೆ [#1788](https://github.com/diegosouzapw/OmniRoute/issues/1788))

ವಿಶ್ವದಾದ್ಯಂತ ಲಭ್ಯವಿರುವ **ನೂರಾರು ಉಚಿತ, ಮೌಲ್ಯೀಕರಿಸಿದ ಪ್ರಾಕ್ಸಿಗಳಿಗೆ** ಪ್ರವೇಶ ಒದಗಿಸಲು OmniRoute, **[1proxy](https://1proxy-api.aitradepulse.com)** ಸಮುದಾಯ ವೇದಿಕೆಯೊಂದಿಗೆ ಸಂಯೋಜನೆಗೊಳ್ಳುತ್ತದೆ. ಸ್ವಂತ ಪ್ರಾಕ್ಸಿ ಮೂಲಸೌಕರ್ಯವನ್ನು ಹೊಂದಿರದ ಬಳಕೆದಾರರಿಗೆ ಇದು ಅತ್ಯುತ್ತಮವಾಗಿದೆ.

### ಇದು ಹೇಗೆ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ

```
┌─────────────┐  ಸಿಂಕ್ ಮಾಡು  ┌─────────────────┐  ಪರ್ಯಾಯವಾಗಿ ಬಳಸು  ┌────────────┐
│  1proxy API │ ────────────▶ │  proxy_registry  │ ────────────────▶ │ ಪೂರೈಕೆದಾರರ │
│   (ಬಾಹ್ಯ)    │  500 ವರೆಗೆ   │  source=oneproxy │  ಗುಣಮಟ್ಟದ ಆಧಾರದಲ್ಲಿ │    API     │
└─────────────┘  ಪ್ರಾಕ್ಸಿಗಳು   └─────────────────┘                   └────────────┘
```

1. **ಸಿಂಕ್** — OmniRoute, 1proxy API ಯಿಂದ ಮೌಲ್ಯೀಕರಿಸಿದ ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಪಡೆಯುತ್ತದೆ
2. **ಸಂಗ್ರಹಣೆ** — ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಅದೇ `proxy_registry` ಕೋಷ್ಟಕದಲ್ಲಿ `source = 'oneproxy'` ಜೊತೆಗೆ ಉಳಿಸಲಾಗುತ್ತದೆ
3. **ಫಿಲ್ಟರ್** — ಪ್ರೋಟೋಕಾಲ್, ದೇಶ ಮತ್ತು ಗುಣಮಟ್ಟದ ಅಂಕದ ಆಧಾರದಲ್ಲಿ ಫಿಲ್ಟರ್ ಮಾಡಿ
4. **ಪರ್ಯಾಯ ಬಳಕೆ** — ಗುಣಮಟ್ಟ, ಯಾದೃಚ್ಛಿಕ ಅಥವಾ ಅನುಕ್ರಮ ತಂತ್ರಗಳನ್ನು ಬಳಸಿಕೊಂಡು ಅತ್ಯುತ್ತಮ ಪ್ರಾಕ್ಸಿಯನ್ನು ಆರಿಸಿ
5. **ಸ್ವಯಂ-ಅವನತಿ** — ವಿಫಲವಾದ ಪ್ರಾಕ್ಸಿಗಳ ಗುಣಮಟ್ಟದ ಅಂಕವನ್ನು ಕಡಿಮೆ ಮಾಡಲಾಗುತ್ತದೆ; ಮಿತಿಗಿಂತ ಕಡಿಮೆಯಾದರೆ → ನಿಷ್ಕ್ರಿಯವೆಂದು ಗುರುತಿಸಲಾಗುತ್ತದೆ

### ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಸಿಂಕ್ ಮಾಡುವುದು

**ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಮೂಲಕ:**

1. **Settings → 1proxy** ಟ್ಯಾಬ್ಗೆ ಹೋಗಿ
2. **"ಈಗ ಸಿಂಕ್ ಮಾಡಿ"** ಕ್ಲಿಕ್ ಮಾಡಿ
3. ಅಂಕಿಅಂಶಗಳನ್ನು ವೀಕ್ಷಿಸಿ: ಒಟ್ಟು ಪ್ರಾಕ್ಸಿಗಳು, ಸಕ್ರಿಯ ಪ್ರಾಕ್ಸಿಗಳ ಸಂಖ್ಯೆ, ಸರಾಸರಿ ಗುಣಮಟ್ಟ ಮತ್ತು ದೇಶವಾರು ವಿವರ

**API ಮೂಲಕ:**

```bash
# ಸಿಂಕ್ ಪ್ರಾರಂಭಿಸಿ
curl -X POST http://localhost:20128/api/settings/oneproxy \
  -H "Content-Type: application/json" \
  -d '{}'

# ಪ್ರತಿಕ್ರಿಯೆ:
# { "success": true, "added": 127, "updated": 45, "failed": 2, "total": 172 }
```

### ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಫಿಲ್ಟರ್ ಮಾಡುವುದು

```bash
# ಪ್ರೋಟೋಕಾಲ್ ಆಧಾರದಲ್ಲಿ ಫಿಲ್ಟರ್ ಮಾಡಿ
curl "http://localhost:20128/api/settings/oneproxy?protocol=socks5"

# ದೇಶದ ಆಧಾರದಲ್ಲಿ ಫಿಲ್ಟರ್ ಮಾಡಿ
curl "http://localhost:20128/api/settings/oneproxy?countryCode=US"

# ಕನಿಷ್ಠ ಗುಣಮಟ್ಟದ ಅಂಕದ ಆಧಾರದಲ್ಲಿ ಫಿಲ್ಟರ್ ಮಾಡಿ
curl "http://localhost:20128/api/settings/oneproxy?minQuality=80"

# ಫಿಲ್ಟರ್ಗಳನ್ನು ಸಂಯೋಜಿಸಿ
curl "http://localhost:20128/api/settings/oneproxy?protocol=http&countryCode=DE&minQuality=70"
```

### ಪ್ರಾಕ್ಸಿ ಗುಣಮಟ್ಟದ ಅಂಕಗಳು

ಪ್ರತಿಯೊಂದು 1proxy ಪ್ರಾಕ್ಸಿಯೂ ಮೆಟಾಡೇಟಾದೊಂದಿಗೆ ಬರುತ್ತದೆ:

| ಕ್ಷೇತ್ರ         | ವಿವರಣೆ                                     |
| --------------- | ------------------------------------------ |
| `qualityScore`  | 1proxy ಮೌಲ್ಯೀಕರಣದಿಂದ ಪಡೆದ 0-100 ರೇಟಿಂಗ್    |
| `latencyMs`     | ಅಳೆಯಲಾದ ನೆಟ್ವರ್ಕ್ ವಿಳಂಬ                    |
| `anonymity`     | `transparent`, `anonymous`, ಅಥವಾ `elite`   |
| `googleAccess`  | ಪ್ರಾಕ್ಸಿಯು Google ಸೇವೆಗಳನ್ನು ಪ್ರವೇಶಿಸಬಹುದೇ |
| `countryCode`   | ಎರಡು ಅಕ್ಷರಗಳ ISO ದೇಶದ ಕೋಡ್                 |
| `lastValidated` | ಕೊನೆಯ ಮೌಲ್ಯೀಕರಣದ ಸಮಯಮುದ್ರೆ                 |

ಗುಣಮಟ್ಟದ ಅಂಕಗಳನ್ನು ಕ್ರಿಯಾತ್ಮಕವಾಗಿ ಹೊಂದಿಸಲಾಗುತ್ತದೆ:

- **ವಿಫಲವಾದ ವಿನಂತಿಗಳು** ಅಂಕವನ್ನು 10 ಪಾಯಿಂಟ್ಗಳಷ್ಟು ಕಡಿಮೆ ಮಾಡುತ್ತವೆ
- **ಅಂಕವು ≤10 ಕ್ಕೆ ಇಳಿದರೆ** → ಪ್ರಾಕ್ಸಿಯನ್ನು `inactive` ಎಂದು ಗುರುತಿಸಲಾಗುತ್ತದೆ
- ನಿಷ್ಕ್ರಿಯ ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಪರ್ಯಾಯ ಬಳಕೆಯಿಂದ ಹೊರಗಿಡಲಾಗುತ್ತದೆ

### ಪರ್ಯಾಯ ಬಳಕೆಯ ತಂತ್ರಗಳು

```bash
# ಗುಣಮಟ್ಟದ ಆಧಾರದಲ್ಲಿ ಪರ್ಯಾಯವಾಗಿ ಬಳಸಿ (ಅತ್ಯುತ್ತಮ ಪ್ರಾಕ್ಸಿ ಮೊದಲು) — ಡೀಫಾಲ್ಟ್
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -H "Content-Type: application/json" \
  -d '{"strategy": "quality"}'

# ಯಾದೃಚ್ಛಿಕ ಪರ್ಯಾಯ ಬಳಕೆ
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -d '{"strategy": "random"}'

# ಅನುಕ್ರಮವಾಗಿ (ಇತ್ತೀಚೆಗೆ ಮೌಲ್ಯೀಕರಿಸದ ಪ್ರಾಕ್ಸಿ ಮೊದಲು)
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -d '{"strategy": "sequential"}'
```

### ಸರ್ಕ್ಯೂಟ್ ಬ್ರೇಕರ್

1proxy ಸಿಂಕ್ ಅಂತರ್ನಿರ್ಮಿತ ಸರ್ಕ್ಯೂಟ್ ಬ್ರೇಕರ್ ಅನ್ನು ಹೊಂದಿದೆ:

- **ಸತತ 5 ಸಿಂಕ್ ವೈಫಲ್ಯಗಳ** ನಂತರ, ಮುಂದಿನ ಸಿಂಕ್ ಪ್ರಯತ್ನಗಳನ್ನು ನಿರ್ಬಂಧಿಸಲಾಗುತ್ತದೆ
- ಇದನ್ನು ಮರುಹೊಂದಿಸಲು: `resetOneproxyCircuitBreaker()` ಬಳಸಿ ಅಥವಾ ಸರ್ವರ್ ಅನ್ನು ಮರುಪ್ರಾರಂಭಿಸಿ
- ಸಿಂಕ್ ಸ್ಥಿತಿಯು `GET /api/settings/oneproxy?action=status` ನಲ್ಲಿ ಲಭ್ಯವಿದೆ

### 1proxy ಪ್ರಾಕ್ಸಿಗಳನ್ನು ತೆರವುಗೊಳಿಸುವುದು

```bash
# ಒಂದೇ 1proxy ಪ್ರಾಕ್ಸಿಯನ್ನು ಅಳಿಸಿ
curl -X DELETE "http://localhost:20128/api/settings/oneproxy?id=proxy-uuid"

# ಎಲ್ಲಾ 1proxy ಪ್ರಾಕ್ಸಿಗಳನ್ನು ತೆರವುಗೊಳಿಸಿ (ಹಸ್ತಚಾಲಿತ ಪ್ರಾಕ್ಸಿಗಳು ಬದಲಾಗುವುದಿಲ್ಲ)
curl -X DELETE "http://localhost:20128/api/settings/oneproxy?clearAll=1"
```

## ಪತ್ತೆ-ತಡೆಗಟ್ಟುವಿಕೆ & ಗೌಪ್ಯತೆ

OmniRoute ಟ್ರಾಫಿಕ್ ಅನ್ನು ಕೇವಲ ಪ್ರಾಕ್ಸಿ ಮೂಲಕ ರೂಟ್ ಮಾಡುವುದಷ್ಟೇ ಅಲ್ಲ — ಅದು ಟ್ರಾಫಿಕ್ ನ್ಯಾಯಸಮ್ಮತವಾಗಿ ಕಾಣುವಂತೆಯೂ ಮಾಡುತ್ತದೆ:

### TLS ಫಿಂಗರ್ಪ್ರಿಂಟ್ ಸ್ಪೂಫಿಂಗ್

ಬ್ರೌಸರ್ನಂತಹ TLS ಫಿಂಗರ್ಪ್ರಿಂಟ್ಗಳನ್ನು ರಚಿಸಲು `wreq-js` ಅನ್ನು ಬಳಸುತ್ತದೆ ಮತ್ತು ಬ್ರೌಸರ್ ಅಲ್ಲದ TLS ಹ್ಯಾಂಡ್ಶೇಕ್ಗಳನ್ನು ಗುರುತಿಸುವ ಬಾಟ್ ಪತ್ತೆ ವ್ಯವಸ್ಥೆಗಳನ್ನು ತಪ್ಪಿಸುತ್ತದೆ.

### CLI ಫಿಂಗರ್ಪ್ರಿಂಟ್ ಹೊಂದಾಣಿಕೆ

**CLI ಫಿಂಗರ್ಪ್ರಿಂಟ್ ಟಾಗಲ್** (`ಸೆಟ್ಟಿಂಗ್ಗಳು → ಭದ್ರತೆ`) ಸ್ಥಳೀಯ CLI ಬೈನರಿಗಳ (Claude Code, Codex, ಇತ್ಯಾದಿ) ನಿಖರವಾದ ಸಿಗ್ನೇಚರ್ಗೆ ಹೊಂದುವಂತೆ HTTP ಹೆಡರ್ಗಳು ಮತ್ತು JSON ಬಾಡಿ ಫೀಲ್ಡ್ಗಳನ್ನು ಮರುಕ್ರಮಗೊಳಿಸುತ್ತದೆ. ಇದು ಪ್ರಾಕ್ಸಿಯ **ಜೊತೆಯಲ್ಲೇ ಹೆಚ್ಚುವರಿಯಾಗಿ** ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ:

```
ನಿಮ್ಮ IP (ನಿರ್ಬಂಧಿತ) → ಪ್ರಾಕ್ಸಿ IP (US) → ಪೂರೈಕೆದಾರ API
                        + TLS ಸ್ಪೂಫ್
                        + CLI ಫಿಂಗರ್ಪ್ರಿಂಟ್
```

ನೀವು ಏಕಕಾಲದಲ್ಲಿ **IP ಮರೆಮಾಚುವಿಕೆ** ಮತ್ತು **ವಿನಂತಿಯ ನೈಜತೆ** ಎರಡನ್ನೂ ಪಡೆಯುತ್ತೀರಿ.

### ಪ್ರಾಕ್ಸಿ IP ಸಂರಕ್ಷಣೆ

ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿರುವ ಬಣ್ಣ-ಸಂಕೇತಿತ ಬ್ಯಾಡ್ಜ್ಗಳು ಯಾವ ಪ್ರಾಕ್ಸಿ ಹಂತ ಸಕ್ರಿಯವಾಗಿದೆ ಎಂಬುದನ್ನು ತೋರಿಸುತ್ತವೆ:

| ಬ್ಯಾಡ್ಜ್ | ಹಂತ       | ಅರ್ಥ                                                |
| -------- | --------- | --------------------------------------------------- |
| 🟢       | ಜಾಗತಿಕ    | ಎಲ್ಲಾ ಟ್ರಾಫಿಕ್ ಈ ಪ್ರಾಕ್ಸಿ ಮೂಲಕ ಸಾಗುತ್ತದೆ            |
| 🟡       | ಪೂರೈಕೆದಾರ | ಈ ಪೂರೈಕೆದಾರರ ಟ್ರಾಫಿಕ್ ಮಾತ್ರ ಪ್ರಾಕ್ಸಿ ಮೂಲಕ ಸಾಗುತ್ತದೆ |
| 🔵       | ಸಂಪರ್ಕ    | ಈ ನಿರ್ದಿಷ್ಟ ಕೀ/ಖಾತೆಯು ಈ ಪ್ರಾಕ್ಸಿಯನ್ನು ಬಳಸುತ್ತದೆ     |

ಪರಿಶೀಲನೆಗಾಗಿ ಬ್ಯಾಡ್ಜ್ ಪರಿಹರಿಸಲಾದ ಪ್ರಾಕ್ಸಿ IP ಅನ್ನು ಸಹ ತೋರಿಸುತ್ತದೆ.

## ಅಪ್ಸ್ಟ್ರೀಮ್ ಪ್ರಾಕ್ಸಿ ಮೋಡ್ಗಳು

CLIProxyAPI ಮಾದರಿಯನ್ನು ಬಳಸುವ ಪೂರೈಕೆದಾರರಿಗೆ, OmniRoute ಮೂರು ಅಪ್ಸ್ಟ್ರೀಮ್ ಪ್ರಾಕ್ಸಿ ಮೋಡ್ಗಳನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ:

| ಮೋಡ್          | ವಿವರಣೆ                                                             |
| ------------- | ------------------------------------------------------------------ |
| `native`      | OmniRoute ಪ್ರಾಕ್ಸಿ ರೂಟಿಂಗ್ ಅನ್ನು ನೇರವಾಗಿ ನಿರ್ವಹಿಸುತ್ತದೆ (ಡೀಫಾಲ್ಟ್) |
| `cliproxyapi` | ಬಾಹ್ಯ CLIProxyAPI ಇನ್ಸ್ಟೆನ್ಸ್ಗೆ ನಿಯೋಜಿಸುತ್ತದೆ                      |
| `fallback`    | ಮೊದಲು ಸ್ಥಳೀಯ ವಿಧಾನವನ್ನು ಪ್ರಯತ್ನಿಸಿ, ನಂತರ CLIProxyAPI ಬಳಸುತ್ತದೆ     |

ಪ್ರತಿ ಪೂರೈಕೆದಾರರಿಗೆ ಕಾನ್ಫಿಗರ್ ಮಾಡಿ:

```bash
curl -X PUT "http://localhost:20128/api/upstream-proxy/openai" \
  -H "Content-Type: application/json" \
  -d '{"mode": "native", "enabled": true}'
```

## ಡ್ಯಾಶ್ಬೋರ್ಡ್ UI

### ಸೆಟ್ಟಿಂಗ್ಗಳು → ಪ್ರಾಕ್ಸಿ ಟ್ಯಾಬ್

- **ಜಾಗತಿಕ ಪ್ರಾಕ್ಸಿ** ಕಾನ್ಫಿಗರೇಶನ್ (ಎಲ್ಲಾ ಟ್ರಾಫಿಕ್ಗಾಗಿ ಒಮ್ಮೆ ಹೊಂದಿಸಿ)
- **ಪ್ರತಿ ಪೂರೈಕೆದಾರರ ಪ್ರಾಕ್ಸಿ** ಅತಿಕ್ರಮಣಗಳು
- **ಪ್ರತಿ ಸಂಪರ್ಕದ ಪ್ರಾಕ್ಸಿ** ನಿಯೋಜನೆಗಳು
- ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾದ ಪ್ರಾಕ್ಸಿ ಮೂಲಕ **ಸಂಪರ್ಕ ಪರೀಕ್ಷೆ**
- ಸಕ್ರಿಯ ಪ್ರಾಕ್ಸಿ ಹಂತವನ್ನು ತೋರಿಸುವ **ಬಣ್ಣ-ಸಂಕೇತಿತ ಬ್ಯಾಡ್ಜ್ಗಳು**

### ಸೆಟ್ಟಿಂಗ್ಗಳು → 1proxy ಟ್ಯಾಬ್

- ಉಚಿತ ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಪಡೆಯಲು **ಈಗ ಸಿಂಕ್ ಮಾಡಿ** ಬಟನ್
- **ಅಂಕಿಅಂಶಗಳ ಕಾರ್ಡ್ಗಳು**: ಒಟ್ಟು, ಸಕ್ರಿಯ, ಸರಾಸರಿ ಗುಣಮಟ್ಟ, ಕೊನೆಯ ಸಿಂಕ್
- **ಫಿಲ್ಟರ್ಗಳು**: ಪ್ರೋಟೋಕಾಲ್, ದೇಶದ ಕೋಡ್, ಕನಿಷ್ಠ ಗುಣಮಟ್ಟ
- ಹೋಸ್ಟ್, ಪ್ರೋಟೋಕಾಲ್, ದೇಶ, ಗುಣಮಟ್ಟದ ಸ್ಕೋರ್, ಲೇಟೆನ್ಸಿ, ಅನಾಮಧೇಯತೆ, Google ಪ್ರವೇಶವನ್ನು ಹೊಂದಿರುವ **ಪ್ರಾಕ್ಸಿ ಕೋಷ್ಟಕ**
- ಯಶಸ್ಸು/ವೈಫಲ್ಯ ಟ್ರ್ಯಾಕಿಂಗ್ ಮತ್ತು ಸತತ ವೈಫಲ್ಯಗಳ ಸಂಖ್ಯೆಯನ್ನು ಹೊಂದಿರುವ **ಸಿಂಕ್ ಸ್ಥಿತಿ** ಫಲಕ
- ಎಲ್ಲಾ 1proxy ನಮೂದುಗಳನ್ನು ತೆಗೆದುಹಾಕಲು **ಎಲ್ಲವನ್ನೂ ತೆರವುಗೊಳಿಸಿ**

## ಸಮಸ್ಯೆ ಪರಿಹಾರ

### "SOCKS5 ಪ್ರಾಕ್ಸಿಯನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಲಾಗಿದೆ"

ನಿಮ್ಮ `.env` ಫೈಲ್ನಲ್ಲಿ `ENABLE_SOCKS5_PROXY=true` ಹೊಂದಿಸಿ ಮತ್ತು ಮರುಪ್ರಾರಂಭಿಸಿ.

### ಪ್ರಾಕ್ಸಿ ಮೂಲಕ "socket hang up" ದೋಷಗಳು

ನಿಷ್ಕ್ರಿಯ ಸಂಪರ್ಕಗಳನ್ನು ಕಡಿತಗೊಳಿಸುವ ಅಗ್ಗದ ಪ್ರಾಕ್ಸಿಗಳಲ್ಲಿ ಇದು ಸಹಜ. OmniRoute ಈಗಾಗಲೇ ಇದನ್ನು ಈ ರೀತಿಯಲ್ಲಿ ನಿರ್ವಹಿಸುತ್ತದೆ:

- ಪ್ರಾಕ್ಸಿ ಸಂಪರ್ಕಗಳಲ್ಲಿ keep-alive ಅನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವುದು (`keepAliveTimeout: 1`)
- ಪೈಪ್ಲೈನಿಂಗ್ ಅನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವುದು (`pipelining: 0`)
- ಪುನರಾವರ್ತಿತ ಹ್ಯಾಂಡ್ಶೇಕ್ಗಳನ್ನು ತಪ್ಪಿಸಲು ಡಿಸ್ಪ್ಯಾಚರ್ಗಳನ್ನು ಕ್ಯಾಶ್ ಮಾಡುವುದು

ಸಮಸ್ಯೆ ಮುಂದುವರಿದರೆ, ಬೇರೆ ಪ್ರಾಕ್ಸಿಯನ್ನು ಪ್ರಯತ್ನಿಸಿ ಅಥವಾ 1proxy ರೊಟೇಶನ್ ವೈಶಿಷ್ಟ್ಯವನ್ನು ಬಳಸಿ.

### OAuth ಸಮಯದಲ್ಲಿ "unsupported_country_region_territory"

OAuth ಹರಿವನ್ನು ಪ್ರಾರಂಭಿಸುವುದಕ್ಕೆ **ಮೊದಲು** ಪ್ರಾಕ್ಸಿಯನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾಗಿದೆಯೇ ಎಂಬುದನ್ನು ಖಚಿತಪಡಿಸಿಕೊಳ್ಳಿ. OmniRoute, OAuth ಟೋಕನ್ ವಿನಿಮಯವನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡಿದ ಪ್ರಾಕ್ಸಿ ಮೂಲಕ ರೂಟ್ ಮಾಡುತ್ತದೆ. ಮೊದಲು ಜಾಗತಿಕ ಅಥವಾ ಪೂರೈಕೆದಾರ-ಮಟ್ಟದ ಪ್ರಾಕ್ಸಿಯನ್ನು ಹೊಂದಿಸಿ, ನಂತರ ಸಂಪರ್ಕಿಸಿ.

### ಪ್ರಾಕ್ಸಿಯನ್ನು ಬಳಸಲಾಗುತ್ತಿಲ್ಲ

ರೆಸಲ್ಯೂಶನ್ ಕ್ರಮವನ್ನು ಪರಿಶೀಲಿಸಿ:

1. `GET /api/settings/proxy?resolve=your-connection-id` ಮೂಲಕ ಪರಿಶೀಲಿಸಿ
2. ಪ್ರಾಕ್ಸಿಯ `status`, `active` ಆಗಿದೆಯೇ (`inactive` ಅಲ್ಲ) ಎಂದು ಪರಿಶೀಲಿಸಿ
3. ಪ್ರಾಕ್ಸಿ ನಿಯೋಜನೆಯ ವ್ಯಾಪ್ತಿಯು ನಿಮ್ಮ ಸಂಪರ್ಕಕ್ಕೆ ಹೊಂದಿಕೆಯಾಗುವುದನ್ನು ಖಚಿತಪಡಿಸಿಕೊಳ್ಳಿ

### 1proxy ಸಿಂಕ್ ವಿಫಲವಾಗುತ್ತಿದೆ

ಸಿಂಕ್ ಸ್ಥಿತಿಯನ್ನು ಪರಿಶೀಲಿಸಿ:

```bash
curl "http://localhost:20128/api/settings/oneproxy?action=status"
```

`consecutiveFailures >= 5` ಆಗಿದ್ದರೆ, ಸರ್ಕ್ಯೂಟ್ ಬ್ರೇಕರ್ ಟ್ರಿಪ್ ಆಗಿದೆ. ಮರುಹೊಂದಿಸಲು ಸರ್ವರ್ ಅನ್ನು ಮರುಪ್ರಾರಂಭಿಸಿ ಅಥವಾ ಹಸ್ತಚಾಲಿತ ಮರುಹೊಂದಿಸುವಿಕೆಗಾಗಿ ಕಾಯಿರಿ.

## ಪ್ರಾಕ್ಸಿ ಸ್ಥಿತಿ ಪರಿಶೀಲನೆ (v3.8.16+)

OmniRoute ನ **ಪ್ರಾಕ್ಸಿ ಫಾಸ್ಟ್-ಫೇಲ್** ಕಾರ್ಯವಿಧಾನವು (`src/lib/proxyHealth.ts`) ತ್ವರಿತ TCP ಸಂಪರ್ಕ ಪರಿಶೀಲನೆಯ ಮೂಲಕ <2s ಒಳಗೆ ಕಾರ್ಯನಿರ್ವಹಿಸದ ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಪತ್ತೆಹಚ್ಚುತ್ತದೆ; ನಂತರ ಪ್ರತಿ ವಿನಂತಿಯ ಹೆಚ್ಚುವರಿ ವೆಚ್ಚವನ್ನು ತಪ್ಪಿಸಲು **ಫಲಿತಾಂಶವನ್ನು ಕ್ಯಾಶ್ ಮಾಡುತ್ತದೆ**.

### ಇದು ಹೇಗೆ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ

```
ವಿನಂತಿ ──▶ ProxyHealthCache.get(url)
             │
             ├─ ಕ್ಯಾಶ್ ಹಿಟ್ + ತಾಜಾ?  ──▶ ಕ್ಯಾಶ್ ಮಾಡಿದ ಸ್ಥಿತಿಯನ್ನು ಹಿಂತಿರುಗಿಸಿ
             │
             └─ ಕ್ಯಾಶ್ ಮಿಸ್ / ಹಳೆಯದು?  ──▶ host:port ಗೆ TCP ಸಂಪರ್ಕಿಸಿ
                                          (ಕಾಲಾವಧಿ ಮೀರುವಿಕೆ: FAST_FAIL_TIMEOUT_MS)
                                          ──▶ HEALTH_CACHE_TTL_MS ವರೆಗೆ ಕ್ಯಾಶ್ ಮಾಡಿ
                                          ──▶ ಫಲಿತಾಂಶವನ್ನು ಹಿಂತಿರುಗಿಸಿ
```

ಇದು ಇಲ್ಲದಿದ್ದರೆ, ಕಾರ್ಯನಿರ್ವಹಿಸದ ಪ್ರಾಕ್ಸಿಯು ವಿಫಲಗೊಳ್ಳುವ ಮೊದಲು ಪೂರ್ಣ `PROXY_TIMEOUT_MS` ಅವಧಿಯವರೆಗೆ (ಡೀಫಾಲ್ಟ್ 30s) ಪ್ರತಿಯೊಂದು ವಿನಂತಿಯನ್ನೂ ನಿರ್ಬಂಧಿಸುತ್ತದೆ.

### ಸರಿಹೊಂದಿಸಬಹುದಾದ ಪರಿಸರ ಚರಾಂಶಗಳು

| ಚರಾಂಶ                        | ಡೀಫಾಲ್ಟ್ | ಉದ್ದೇಶ                                               |
| ---------------------------- | -------- | ---------------------------------------------------- |
| `PROXY_FAST_FAIL_TIMEOUT_MS` | `2000`   | ಪ್ರತಿ ಸ್ಥಿತಿ ಪರಿಶೀಲನೆಗೆ TCP ಸಂಪರ್ಕದ ಕಾಲಾವಧಿ ಮೀರುವಿಕೆ |
| `PROXY_HEALTH_CACHE_TTL_MS`  | `30000`  | ಸ್ಥಿತಿ ಫಲಿತಾಂಶವನ್ನು ಎಷ್ಟು ಕಾಲ ಕ್ಯಾಶ್ ಮಾಡಬೇಕು         |

**ಶಿಫಾರಸು ಮಾಡಲಾದ ಮೌಲ್ಯಗಳು:**

| ಸನ್ನಿವೇಶ                      | ಫಾಸ್ಟ್-ಫೇಲ್ ಕಾಲಾವಧಿ ಮೀರುವಿಕೆ | ಕ್ಯಾಶ್ TTL | ಕಾರಣ                                                                    |
| ----------------------------- | ---------------------------- | ---------- | ----------------------------------------------------------------------- |
| ಹೆಚ್ಚಿನ-ಥ್ರೂಪುಟ್ API ಗೇಟ್ವೇ   | 1500ms                       | 60000ms    | ಆಕ್ರಮಣಕಾರಿ ಫೇಲ್-ಫಾಸ್ಟ್, ಪರಿಶೀಲನೆಗಳನ್ನು ಕಡಿಮೆ ಮಾಡಲು ದೀರ್ಘ ಕ್ಯಾಶ್         |
| ಭೌಗೋಳಿಕವಾಗಿ ವಿತರಿಸಲಾದ ನೋಡ್ಗಳು | 3000ms                       | 15000ms    | ನಿಧಾನ ನೆಟ್ವರ್ಕ್ಗಳಿಗೆ ಹೆಚ್ಚಿನ ಸಮಯ ಬೇಕು; ತ್ವರಿತ ಫೇಲ್ಓವರ್ಗಾಗಿ ಕಡಿಮೆ ಕ್ಯಾಶ್ |
| ಡೆವ್ / ಪರೀಕ್ಷೆ                | 1000ms                       | 10000ms    | ಸ್ಥಳೀಯ ಪ್ರಾಕ್ಸಿಗಳಲ್ಲಿ ತ್ವರಿತ ಪುನರಾವರ್ತನೆ                                |
| ಸ್ಟೆಲ್ತ್ / ಪತ್ತೆ-ವಿರೋಧಿ       | 2500ms                       | 45000ms    | ದರ ಮಿತಿಗಳನ್ನು ಪ್ರಚೋದಿಸಬಹುದಾದ ಕ್ಷಿಪ್ರ ಪ್ರೋಬಿಂಗ್ ಅನ್ನು ತಪ್ಪಿಸುವುದು        |

### ಪ್ರಾಕ್ಸಿ ಸ್ಥಿತಿಯನ್ನು ಪರಿಶೀಲಿಸುವುದು

```ts
import { getAllProxyHealthStatuses, invalidateProxyHealth } from "omniroute/proxyHealth";

const statuses = getAllProxyHealthStatuses();
for (const s of statuses) {
  console.log(`${s.proxyUrl} → healthy=${s.healthy}, stale=${s.stale}`);
}

// ನಿರ್ದಿಷ್ಟ ಪ್ರಾಕ್ಸಿಯನ್ನು ಬಲವಂತವಾಗಿ ಮರುಪರಿಶೀಲಿಸಿ
invalidateProxyHealth("http://user:pass@203.0.113.7:8080");
```

ಕ್ಯಾಶ್ ನಮೂದು `HEALTH_CACHE_TTL_MS` ಅನ್ನು ಮೀರಿದಾಗ `stale` ಫ್ಲ್ಯಾಗ್ `true` ಆಗಿರುತ್ತದೆ ಮತ್ತು ಮುಂದಿನ ವಿನಂತಿಯು ಹೊಸ ಪರಿಶೀಲನೆಯನ್ನು ಪ್ರಚೋದಿಸುತ್ತದೆ.

### ಪ್ರತಿ-ಪ್ರಾಕ್ಸಿ ಪ್ರಕಾರದ ಡೀಫಾಲ್ಟ್ಗಳು

ಸ್ಥಿತಿ ಪರಿಶೀಲನೆಯು URL ಸ್ಕೀಮ್ ಆಧರಿಸಿ ಸಮಂಜಸವಾದ ಡೀಫಾಲ್ಟ್ಗಳನ್ನು ಬಳಸುತ್ತದೆ:

| ಸ್ಕೀಮ್                     | ಡೀಫಾಲ್ಟ್ ಪೋರ್ಟ್ |
| -------------------------- | --------------- |
| `http://`                  | 8080            |
| `https://`                 | 443             |
| `socks5://` / `socks5h://` | 1080            |

URL ನಲ್ಲಿರುವ ಕಸ್ಟಮ್ ಪೋರ್ಟ್ಗಳು (`http://host:9999`) ಯಾವಾಗಲೂ ಸ್ಕೀಮ್ ಡೀಫಾಲ್ಟ್ಗಿಂತ ಆದ್ಯತೆ ಪಡೆಯುತ್ತವೆ.

ರೂಟಿಂಗ್ ಮಾದರಿಗಳು, ಲೇಟೆನ್ಸಿ ಏರಿಕೆಗಳು ಮತ್ತು ಮರುಕಳಿಸುವ ವೈಫಲ್ಯಗಳನ್ನು ನಿರ್ಣಯಿಸಲು ಆಪರೇಟರ್ಗಳಿಗೆ ಸಹಾಯ ಮಾಡುವುದಕ್ಕಾಗಿ OmniRoute ಪ್ರತಿ ಪ್ರಾಕ್ಸಿಯ ಬಳಕೆಯನ್ನು ಟ್ರ್ಯಾಕ್ ಮಾಡುತ್ತದೆ.

### ಏನೆಲ್ಲ ಟ್ರ್ಯಾಕ್ ಮಾಡಲಾಗುತ್ತದೆ

ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾದ ಪ್ರಾಕ್ಸಿ ಮೂಲಕ ಹಾದುಹೋಗುವ ಪ್ರತಿಯೊಂದು ವಿನಂತಿಗೂ, OmniRoute ಈ ಕೆಳಗಿನವುಗಳನ್ನು ದಾಖಲಿಸುತ್ತದೆ:

| ಮೆಟ್ರಿಕ್     | ವಿವರಣೆ                                                          |
| ------------ | --------------------------------------------------------------- |
| `proxy_url`  | ಸಂಪೂರ್ಣ ಪ್ರಾಕ್ಸಿ URL (ದೃಢೀಕರಣ ರುಜುವಾತುಗಳನ್ನು ಮರೆಮಾಡಲಾಗಿರುತ್ತದೆ) |
| `provider`   | ಅಪ್ಸ್ಟ್ರೀಮ್ ಪೂರೈಕೆದಾರ ID (openai, anthropic, ಇತ್ಯಾದಿ)           |
| `latency_ms` | ಪ್ರಾಕ್ಸಿ ಹ್ಯಾಂಡ್ಶೇಕ್ ಸೇರಿದಂತೆ ಒಟ್ಟು ರೌಂಡ್-ಟ್ರಿಪ್ ಸಮಯ            |
| `connect_ms` | TCP ಸಂಪರ್ಕ ಸಮಯ ಮಾತ್ರ                                            |
| `status`     | ಅಪ್ಸ್ಟ್ರೀಮ್ನಿಂದ ಬಂದ HTTP ಸ್ಥಿತಿ ಕೋಡ್                            |
| `error`      | ವಿನಂತಿ ವಿಫಲವಾದರೆ ದೋಷದ ವರ್ಗ                                      |
| `timestamp`  | ISO 8601 UTC                                                    |

curl -H "Authorization: Bearer $OMNIROUTE_KEY" \

ನಿಜವಾದ ಎಂಡ್ಪಾಯಿಂಟ್ `/api/usage/proxy-logs` ಆಗಿದೆ (`src/app/api/usage/proxy-logs/route.ts` ನೋಡಿ). ಈ ಎಂಡ್ಪಾಯಿಂಟ್ ಈ ಕೆಳಗಿನವುಗಳನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ:

- `GET /api/usage/proxy-logs` — ಪ್ರಾಕ್ಸಿ ಲಾಗ್ಗಳನ್ನು ಹಿಂಪಡೆಯಿರಿ
- `DELETE /api/usage/proxy-logs` — ಎಲ್ಲಾ ಪ್ರಾಕ್ಸಿ ಲಾಗ್ಗಳನ್ನು ತೆರವುಗೊಳಿಸಿ

ಅಗತ್ಯವಿದ್ದರೆ, ಒಟ್ಟುಗೂಡಿಸಿದ ಅಂಕಿಅಂಶಗಳನ್ನು SQL ಮೂಲಕ `proxy_logs` ಕೋಷ್ಟಕದಿಂದ ನೇರವಾಗಿ ಕ್ವೆರಿ ಮಾಡಬಹುದು. ಡ್ಯಾಶ್ಬೋರ್ಡ್ UI ಒಟ್ಟುಗೂಡಿಸಿದ ವೀಕ್ಷಣೆಗಳನ್ನು ಒದಗಿಸಬಹುದು.

### ಸಾಮಾನ್ಯ ಮಾದರಿಗಳು

**ಅಸ್ಥಿರ ಪ್ರಾಕ್ಸಿಯನ್ನು ಪತ್ತೆಮಾಡಿ** (ಯಶಸ್ಸು/ವೈಫಲ್ಯದ ನಡುವೆ ಪರ್ಯಾಯವಾಗಿ ಬದಲಾಗುತ್ತದೆ):

```sql
SELECT proxy_url,
       COUNT(*) AS total,
       SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) AS errors,
       ROUND(100.0 * SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) / COUNT(*), 1) AS error_pct
FROM proxy_logs
WHERE timestamp > datetime('now', '-1 hour')
GROUP BY proxy_url
HAVING error_pct > 5
ORDER BY error_pct DESC;
```

**ನಿಧಾನವಾದ ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಹುಡುಕಿ** (p95 ಲೇಟೆನ್ಸಿ > 2s):

```sql
WITH ranked AS (
  SELECT proxy_url, latency_ms,
         PERCENT_RANK() OVER (PARTITION BY proxy_url ORDER BY latency_ms) AS pct
  FROM proxy_logs
  WHERE timestamp > datetime('now', '-24 hour')
)
SELECT proxy_url, latency_ms
FROM ranked
WHERE pct >= 0.95
ORDER BY latency_ms DESC;
```

## ರೊಟೇಶನ್ ಕಾರ್ಯತಂತ್ರದ ನಿರ್ಧಾರ ವೃಕ್ಷ

ಒಂದು ವ್ಯಾಪ್ತಿಗೆ ಹಲವು ಪ್ರಾಕ್ಸಿಗಳನ್ನು ನಿಯೋಜಿಸಿದಾಗ, ಪ್ರತಿ ವಿನಂತಿಗೆ ಯಾವುದನ್ನು ಬಳಸಬೇಕೆಂದು ಆಯ್ಕೆ ಮಾಡಲು OmniRoute ಒಂದು **ರೊಟೇಶನ್ ಕಾರ್ಯತಂತ್ರವನ್ನು** ಬಳಸುತ್ತದೆ. ಕಾರ್ಯತಂತ್ರವನ್ನು ವ್ಯಾಪ್ತಿಯ ಮಟ್ಟದಲ್ಲಿ ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾಗುತ್ತದೆ (ಜಾಗತಿಕ, ಪ್ರತಿ ಪೂರೈಕೆದಾರ, ಪ್ರತಿ ಖಾತೆ, ಪ್ರತಿ ಸಂಯೋಜನೆ).

### ಲಭ್ಯವಿರುವ ಕಾರ್ಯತಂತ್ರಗಳು

| ಕಾರ್ಯತಂತ್ರ           | ಯಾವಾಗ ಬಳಸಬೇಕು                            | ರಾಜಿ                                                                                     |
| -------------------- | ---------------------------------------- | ---------------------------------------------------------------------------------------- |
| `quality` (ಡೀಫಾಲ್ಟ್) | ಮಿಶ್ರ-ಗುಣಮಟ್ಟದ ಪ್ರಾಕ್ಸಿಗಳಿರುವ ಪ್ರೊಡಕ್ಷನ್ | ಹೆಚ್ಚಿನ ರೇಟಿಂಗ್ನ ಪ್ರಾಕ್ಸಿಗಳಿಗೆ ಆದ್ಯತೆ ನೀಡುತ್ತದೆ; ಕಡಿಮೆ ರೇಟಿಂಗ್ನವುಗಳಿಗೆ ಅವಕಾಶ ಸಿಗದಿರಬಹುದು |

| `sequential`         | ಡೀಬಗಿಂಗ್, ನಿರ್ಣಾಯಕ ಪರೀಕ್ಷೆ               | ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಕ್ರಮವಾಗಿ ಆವರ್ತಿಸುತ್ತದೆ; ಅರ್ಥಮಾಡಿಕೊಳ್ಳಲು ಸುಲಭ                              |

## ನಿಮ್ಮ ಸ್ವಂತ ಪ್ರಾಕ್ಸಿಗಳಿಗೆ ಸ್ವಯಂಚಾಲಿತ ವೈಫಲ್ಯ ಹೊರಗಿಡುವಿಕೆ

1proxy ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ ಪೂಲ್ ಈಗಾಗಲೇ ವಿಫಲವಾದ ಪ್ರಾಕ್ಸಿಗಳ ಸ್ಥಿತಿಯನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ತಗ್ಗಿಸುತ್ತದೆ (ನೋಡಿ
[ಪ್ರಾಕ್ಸಿ ಗುಣಮಟ್ಟದ ಸ್ಕೋರ್ಗಳು](#proxy-quality-scores)). ನೋಂದಾವಣೆಗೆ **ನೀವು** ಸೇರಿಸಿದ
ಪ್ರಾಕ್ಸಿಗಳಿಗೆ, ಹಿನ್ನೆಲೆ ಆರೋಗ್ಯ ಶೆಡ್ಯೂಲರ್
(`src/lib/proxyHealth/scheduler.ts`) ಏನನ್ನೂ ಅಳಿಸದೆಯೇ ಅದೇ ರೀತಿಯ "ಕಾರ್ಯನಿರ್ವಹಿಸದ
ಸದಸ್ಯನನ್ನು ಚೈನ್ನಿಂದ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಹೊರಗಿಡುವ" ವರ್ತನೆಯನ್ನು ಒದಗಿಸುತ್ತದೆ:

```bash
# .env — ಸತತವಾಗಿ 3 ಪ್ರೋಬ್ಗಳು ವಿಫಲವಾದ ನಂತರ ಪ್ರಾಕ್ಸಿಯನ್ನು ತಾತ್ಕಾಲಿಕವಾಗಿ ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿ,
# ಅದು ಮತ್ತೆ ಪ್ರೋಬ್ಗಳಿಗೆ ಪ್ರತಿಕ್ರಿಯಿಸಲು ಪ್ರಾರಂಭಿಸಿದ ಕೂಡಲೇ ಅದನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಮರುಸಕ್ರಿಯಗೊಳಿಸಿ.
PROXY_AUTO_DISABLE=true
PROXY_AUTO_REMOVE_AFTER=3
```

ಬಹು-ಪ್ರಾಕ್ಸಿ ಚೈನ್ನಲ್ಲಿ ಇದು ಕಾರ್ಯನಿರ್ವಹಿಸುವ ವಿಧಾನ:

1. ಶೆಡ್ಯೂಲರ್ ಪ್ರತಿ `PROXY_HEALTH_INTERVAL_MS` ಅವಧಿಗೆ ನೋಂದಾಯಿತ ಪ್ರತಿಯೊಂದು ಪ್ರಾಕ್ಸಿಯನ್ನು
   ಪ್ರೋಬ್ ಮಾಡುತ್ತದೆ (ಡೀಫಾಲ್ಟ್ 10 ನಿಮಿಷ; ಕನಿಷ್ಠ 1 ನಿಮಿಷ).
2. `PROXY_AUTO_REMOVE_AFTER` ಸತತ **ನಿರ್ಣಾಯಕ** ವೈಫಲ್ಯಗಳ ನಂತರ (ನಿಜವಾದ
   ಸಂಪರ್ಕ ವೈಫಲ್ಯ — ಟೈಮ್ಔಟ್ ಅಥವಾ ಪ್ರೋಬ್ ಗುರಿಯ ಸ್ವಂತ 5xx ಅನ್ನು ಎಂದಿಗೂ ಪರಿಗಣಿಸಲಾಗುವುದಿಲ್ಲ, ನೋಡಿ
   [ಪ್ರಾಕ್ಸಿ ಆರೋಗ್ಯ ಪರಿಶೀಲನೆ](#proxy-health-checking-v3816)), ಪ್ರಾಕ್ಸಿಯ `status` ಅನ್ನು
   `dead` ಎಂದು ಹೊಂದಿಸಲಾಗುತ್ತದೆ.
3. ಪೂಲ್/ರೊಟೇಶನ್ ರೆಸಲ್ಯೂಶನ್ ಬಳಸುವ ಜೀವಂತ-ಸ್ಥಿತಿ ಫಿಲ್ಟರ್ ಹೊರಗಿಡುವ ಸ್ಥಿತಿಗಳಲ್ಲಿ
   `dead` ಕೂಡ ಒಂದಾಗಿದೆ; ಆದ್ದರಿಂದ ಸ್ಕೋಪ್ನ ರೊಟೇಶನ್ (ರೌಂಡ್-ರಾಬಿನ್ / ಯಾದೃಚ್ಛಿಕ / ಸ್ಟಿಕ್ಕಿ /
   ಲೇಟೆನ್ಸಿ — ನೋಡಿ [ರೊಟೇಶನ್ ತಂತ್ರದ ನಿರ್ಧಾರ ವೃಕ್ಷ](#rotation-strategy-decision-tree))
   ಆ ಪ್ರಾಕ್ಸಿಯನ್ನು ಹೊಸ ವಿನಂತಿಗಳಿಗೆ ನೀಡುವುದನ್ನು ತಕ್ಷಣವೇ ನಿಲ್ಲಿಸುತ್ತದೆ. ಪೂಲ್ನಲ್ಲಿರುವ ಬೇರೆ ಯಾವುದೇ
   ಪ್ರಾಕ್ಸಿಗಳ ಮೇಲೆ ಪರಿಣಾಮ ಬೀರುವುದಿಲ್ಲ ಮತ್ತು ಸಂಪೂರ್ಣ ಪೂಲ್ ಎಂದಿಗೂ ನೇರ ಸಂಪರ್ಕಕ್ಕೆ
   ಮೌನವಾಗಿ ಹಿಂತಿರುಗುವುದಿಲ್ಲ — ಫೇಲ್-ಕ್ಲೋಸ್ಡ್ ರಕ್ಷಣೆಯ ವಿವರಗಳಿಗಾಗಿ
   [4-ಹಂತದ ಪ್ರಾಕ್ಸಿ ವ್ಯವಸ್ಥೆ](#4-level-proxy-system) ನೋಡಿ.
4. ಶೆಡ್ಯೂಲರ್ ಅದೇ ಅವಧಿಯಲ್ಲಿ `dead` ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಪ್ರೋಬ್ ಮಾಡುವುದನ್ನು ಮುಂದುವರಿಸುತ್ತದೆ. ಮುಂದಿನ
   ಯಶಸ್ವಿ ಪ್ರೋಬ್ `status` ಅನ್ನು ಮತ್ತೆ `active` ಗೆ ಬದಲಾಯಿಸುತ್ತದೆ ಮತ್ತು ಪ್ರಾಕ್ಸಿ ರೊಟೇಶನ್ಗೆ
   ಮರುಪ್ರವೇಶಿಸುತ್ತದೆ — ಹಸ್ತಚಾಲಿತವಾಗಿ ಮತ್ತೆ ಸೇರಿಸುವ ಅಗತ್ಯವಿಲ್ಲ.

ಇದು ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ **ಆಯ್ಕೆಮಾಡಿ ಸಕ್ರಿಯಗೊಳಿಸಬೇಕಾದ ಮತ್ತು ವಿನಾಶಕಾರಿಯಲ್ಲದ** ವೈಶಿಷ್ಟ್ಯವಾಗಿದೆ:
ಡೀಫಾಲ್ಟ್ ಆಗಿ ಶೆಡ್ಯೂಲರ್ ವೈಫಲ್ಯಗಳನ್ನು ಎಣಿಸಿ ಲಾಗ್ ಮಾಡುತ್ತದೆ ಮಾತ್ರ (`decision.ts` ನಲ್ಲಿನ ನೀತಿ C ನೋಡಿ),
ಮತ್ತು `PROXY_AUTO_DISABLE` ಎಂದಿಗೂ ಯಾವುದೇ ಸಾಲನ್ನು ಅಳಿಸುವುದಿಲ್ಲ — ಅದಕ್ಕಾಗಿ ಪ್ರತ್ಯೇಕವಾದ,
ಹೆಚ್ಚು ಆಕ್ರಮಣಕಾರಿ `PROXY_AUTO_REMOVE` ಫ್ಲ್ಯಾಗ್ ಇದೆ. ಎರಡನ್ನೂ `true` ಗೆ ಹೊಂದಿಸಿದರೆ,
`PROXY_AUTO_REMOVE` ಮೇಲುಗೈ ಸಾಧಿಸುತ್ತದೆ (ಅಳಿಸಲಿರುವ ಪ್ರಾಕ್ಸಿಯನ್ನು ಮಧ್ಯದಲ್ಲಿ ತಾತ್ಕಾಲಿಕವಾಗಿ
ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುವುದರಿಂದ ಯಾವುದೇ ಪ್ರಯೋಜನವಿಲ್ಲ). ವೇರಿಯೇಬಲ್ಗಳ ಸಂಪೂರ್ಣ ಪಟ್ಟಿಗಾಗಿ
[ಪರಿಸರ ಸಂರಚನೆ](../reference/ENVIRONMENT.md) ಉಲ್ಲೇಖವನ್ನು ನೋಡಿ.
