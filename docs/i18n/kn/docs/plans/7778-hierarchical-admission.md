1. ಈಗಿರುವ ಏಕ-ಕೀ ಸೆಮಾಫೋರ್ ಒಪ್ಪಂದ ಮತ್ತು ಹೊಸ ಅಣುಸ್ವರೂಪಿ ಬಹು-ಕೀ ಒಪ್ಪಂದವನ್ನು ಕೇಂದ್ರೀಕೃತ ಪರೀಕ್ಷೆಗಳ ಮೂಲಕ ಸ್ಥಿರಗೊಳಿಸಿ: ಭಾಗಶಃ ಕಾಯ್ದಿರಿಸುವಿಕೆಗಳಿಲ್ಲದಿರುವುದು, FIFO ಸರದೀಕರಣ, ಸ್ಥಗಿತಗೊಳಿಸುವಿಕೆ, ಕಾಲಮಿತಿ ಮೀರುವಿಕೆ, ಸರದಿ-ತುಂಬಿರುವಿಕೆ, ಐಡೆಂಪೋಟೆಂಟ್ ಬಿಡುಗಡೆ, ಅಂಕಿಅಂಶಗಳು ಮತ್ತು ಸ್ವಚ್ಛಗೊಳಿಸುವಿಕೆ.
2. ಈಗಿರುವ ಖಾತೆ ಸೆಮಾಫೋರ್ ಅನ್ನು ಅದೇ ಸ್ಥಳದಲ್ಲಿ ಸಾಮಾನ್ಯೀಕರಿಸಿ. `acquire()` ಅನ್ನು `acquireMany()` ಸುತ್ತಲಿನ ಹೊಂದಾಣಿಕೆ ರ್ಯಾಪರ್ ಆಗಿ ಉಳಿಸಿ; ಎರಡನೇ ಶೆಡ್ಯೂಲರ್ ಅಥವಾ ಅವಲಂಬನೆಯನ್ನು ಸೇರಿಸಬೇಡಿ.
3. `chatCore` ನಲ್ಲಿನ ಖಾತೆ-ಮಾತ್ರ ಸ್ವಾಧೀನಪಡಿಸಿಕೊಳ್ಳುವಿಕೆಯನ್ನು, `withRateLimit` ಗೆ ತಕ್ಷಣ ಮೊದಲು ನಡೆಯುವ ಒಂದೇ ಸಂಚಿತ ಜಾಗತಿಕ/ಪೂರೈಕೆದಾರ/ಖಾತೆ ಸ್ವಾಧೀನಪಡಿಸಿಕೊಳ್ಳುವಿಕೆಯಿಂದ ಬದಲಾಯಿಸಿ. ಖಾತೆ ರೊಟೇಶನ್ ಸಂಪರ್ಕವನ್ನು ಬದಲಾಯಿಸಿದಾಗಲೆಲ್ಲ ಸಂಪೂರ್ಣ ಕೀಗಳ ಗುಚ್ಛವನ್ನು ಪುನಃ ಸ್ವಾಧೀನಪಡಿಸಿಕೊಳ್ಳಿ ಮತ್ತು ಸ್ಟ್ರೀಮಿಂಗ್ ಪೂರ್ಣಗೊಳ್ಳುವವರೆಗೆ ಬಿಡುಗಡೆಯನ್ನು ತಡೆಹಿಡಿಯಿರಿ.
4. ಈಗಿರುವ ಸ್ಥಿತಿಸ್ಥಾಪಕತ್ವದ ಸೆಟ್ಟಿಂಗ್ಗಳ ಪೈಪ್ಲೈನ್ ಅನ್ನು (ಪ್ರಕಾರಗಳು, ಡೀಫಾಲ್ಟ್ಗಳು, ಸಾಮಾನ್ಯೀಕರಣ, ಸ್ಕೀಮಾ, API ಪ್ರತಿಕ್ರಿಯೆ, UI ಮತ್ತು ಅನುವಾದಗಳು) ಜಾಗತಿಕ ಮತ್ತು ಪೂರೈಕೆದಾರ ಮಿತಿಗಳೊಂದಿಗೆ ವಿಸ್ತರಿಸಿ. ಹಳೆಯ Bottleneck ಏಕಕಾಲಿಕತೆ ನಿಯಂತ್ರಣದ ನೈಜ ವ್ಯಾಪ್ತಿ ಸ್ಪಷ್ಟವಾಗುವಂತೆ ಅದನ್ನು ಸಂಪರ್ಕ/ಕೋಟಾ-ವ್ಯಾಪ್ತಿ ಏಕಕಾಲಿಕತೆ ಎಂದು ಮರುಲೇಬಲ್ ಮಾಡಿ.
5. ಕೇಂದ್ರೀಕೃತ ಪರೀಕ್ಷೆಗಳು, ಲಿಂಟ್, ಪ್ರಕಾರ ಪರಿಶೀಲನೆ, ಸ್ಥಿರ ಪರಿಶೀಲನೆಗಳು ಮತ್ತು ಸಂಪೂರ್ಣ ಪರೀಕ್ಷಾ ಸೂಟ್ ಅನ್ನು ಚಲಾಯಿಸಿ; ವರ್ತನೆಯ ಬದಲಾವಣೆಯನ್ನು ಚೇಂಜ್ಲಾಗ್ನಲ್ಲಿ ದಾಖಲಿಸಿ.

ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ಉಳಿಸಿರುವ ವರ್ತನೆ: ಶೂನ್ಯ/null ಏಕಕಾಲಿಕತೆಯು ಗೇಟ್ ಅನ್ನು ಬಿಟ್ಟುಹೋಗುತ್ತದೆ, ಖಾತೆ-ಮಾತ್ರ ಕರೆಗಾರರು `acquire()` ಅನ್ನು ಬಳಸುವುದನ್ನು ಮುಂದುವರಿಸುತ್ತಾರೆ, ನಿರ್ಬಂಧಿತ-ಖಾತೆ ನಿಯಂತ್ರಣಗಳು ತಮ್ಮ ಕೀ ಸ್ವರೂಪ ಮತ್ತು API ಅನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತವೆ ಮತ್ತು ಪೂರೈಕೆದಾರರ ದರ-ಮಿತಿ ಸರದಿ ವರ್ತನೆಯು ಬದಲಾಗದೆ ಉಳಿಯುತ್ತದೆ.
