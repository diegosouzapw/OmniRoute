`devin-cli-agentic`, ನೈಜ Claude Code ರನ್ಟೈಮ್ಗೆ OmniRoute ನ ಸ್ಥಳೀಯ Anthropic
Messages ಎಂಡ್ಪಾಯಿಂಟ್ ಬಳಸಲು ಅವಕಾಶ ನೀಡುತ್ತದೆ; ಇದೇ ವೇಳೆ ಅಧಿಕೃತ Devin CLI, ACP stdio ಮೂಲಕ ಮಾದರಿ ಪ್ರತಿಕ್ರಿಯೆಗಳನ್ನು ಒದಗಿಸುತ್ತದೆ. ಇದು
ಈಗಾಗಲೇ ಇರುವ Anthropic, Claude OAuth, Claude Web, ಅಥವಾ `devin-cli` ಪೂರೈಕೆದಾರರನ್ನು ಮಾರ್ಪಡಿಸುವುದಿಲ್ಲ.

> **ಪ್ರಸ್ತುತ ಸ್ಥಿತಿ: Claude Code `2.1.258` ಗೆ ಪಿನ್ ಮಾಡಲಾಗಿದೆ; ಆಫ್ಲೈನ್ ಮತ್ತು ಲೈವ್ ಮೌಲ್ಯಮಾಪನವನ್ನು ಕೊನೆಯದಾಗಿ
> `2.1.220` ನಲ್ಲಿ ದಾಖಲಿಸಲಾಗಿದೆ.** `2.1.220` ಪಿನ್, Devin CLI
> `3000.2.17` ಮತ್ತು `swe-1-7-lightning` ಮಾದರಿಯ ಮೂಲಕ ಮೂರು ಪ್ರತ್ಯೇಕ ಸನ್ನಿವೇಶಗಳನ್ನು ಪೂರ್ಣಗೊಳಿಸಿದೆ; ಆ ಅಂತಿಮ ಲೈವ್ ರನ್ ಕ್ಲೈಂಟ್-ನಿಯಂತ್ರಿತ `Read`,
> `Edit`, ಮತ್ತು `Bash` ಸರದಿಗಳು, ಯಶಸ್ವಿ `npm test` ಫಲಿತಾಂಶಗಳು, ಪ್ರಾಜೆಕ್ಟ್ ಕಮಾಂಡ್ ಮತ್ತು ಸ್ಕಿಲ್
> ಪತ್ತೆ, Devin-ಮಾತ್ರದ ರೂಟಿಂಗ್, ಹಾಗೂ ಶೂನ್ಯ Claude ಎಗ್ರೆಸ್ ಅನ್ನು ದೃಢಪಡಿಸಿದೆ. ನಂತರ ಪಿನ್ ಅನ್ನು `2.1.258` ಗೆ ಹೆಚ್ಚಿಸಲಾಯಿತು
> (OmniRoute ನ Claude ಗುರುತು ಅನುಕರಿಸುವ CLI ತಲೆಮಾರು ಮತ್ತು Fable 5.1 ಶ್ರೇಣಿಯನ್ನು
> ಸ್ವಾಭಾವಿಕವಾಗಿ ಒಳಗೊಂಡಿರುವ ಮೊದಲ ಲೈನ್). ಹೊಸ ಪಿನ್ನಲ್ಲಿ, ಪಿನ್ ಮಾಡಿದ ಬೇಸ್ ಇಮೇಜ್ನಲ್ಲಿ ಇನ್ಸ್ಟಾಲ್ ಲೇಯರ್ ಮತ್ತು `claude --version` ಅನ್ನು
> ಪರಿಶೀಲಿಸಲಾಗಿದೆ, ಹಾಗೂ ಬ್ರಿಡ್ಜ್ ಯೂನಿಟ್ ಸೂಟ್, `compose config` ಮತ್ತು
> ಸ್ಥಿರ ಐಸೊಲೇಶನ್ ಪುರಾವೆಗಳು ಪಾಸ್ ಆಗಿವೆ — ಆದರೆ ಆಫ್ಲೈನ್ ಮಾಕ್ ಸನ್ನಿವೇಶ ಮತ್ತು ಲೈವ್ ಮೂರು-ಸನ್ನಿವೇಶಗಳ
> ಸೂಟ್ ಅನ್ನು ಇನ್ನೂ ಮರುಚಾಲನೆ ಮಾಡಿಲ್ಲ. ಈ ಪಿನ್ನೊಂದಿಗೆ ಬ್ರಿಡ್ಜ್ ಮೇಲೆ ಅವಲಂಬಿಸುವ ಮೊದಲು ಅವುಗಳನ್ನು ಮರುಚಾಲನೆ ಮಾಡಿ
> ("ಪಿನ್ ಮಾಡಿದ ಪರಿಕರಗಳನ್ನು ನವೀಕರಿಸುವುದು" ನೋಡಿ).

## ಆರ್ಕಿಟೆಕ್ಚರ್

```text
Claude Code 2.1.258 (ಪ್ರತ್ಯೇಕಿಸಿದ non-root Linux ಕಂಟೇನರ್)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-ಫಾರ್ಮ್ಯಾಟ್, ದೃಢೀಕರಣವಿಲ್ಲದ ಪೂರೈಕೆದಾರ)
  -> devin acp --agent-type summarizer (ಅಧಿಕೃತ ACP stdio, Devin ಪರಿಕರಗಳಿಲ್ಲ)
  -> ಮೀಸಲಾದ devin-auth ವಾಲ್ಯೂಮ್ನಲ್ಲಿರುವ Devin ಖಾತೆ
```

ಅಧಿಕೃತ CLI ಯ ಡೀಫಾಲ್ಟ್ ACP ಏಜೆಂಟ್ ತನ್ನದೇ ಪರಿಕರಗಳನ್ನು ಕಾರ್ಯಗತಗೊಳಿಸಬಹುದು, ಆದ್ದರಿಂದ ಈ ಬ್ರಿಡ್ಜ್ ಅದನ್ನು
ಬಳಸುವುದಿಲ್ಲ. ಇದು ಯಾವುದೇ ಪರಿಕರಗಳಿಲ್ಲದ ಅಧಿಕೃತ CLI ಮೋಡ್ ಹೊಂದಿರುವ ಸ್ಥಿರ `summarizer` ACP ಏಜೆಂಟ್ ಅನ್ನು ಪ್ರಾರಂಭಿಸಿ,
ಸೀರಿಯಲೈಸ್ ಮಾಡಿದ Anthropic ವಿನಂತಿಯನ್ನು ಎಕ್ಸಿಕ್ಯೂಷನ್ ಟ್ರೇಸ್ ಆಗಿ ಫ್ರೇಮ್ ಮಾಡುತ್ತದೆ. Claude-ನಿಯಂತ್ರಿತ ಮತ್ತೊಂದು
ಕ್ರಿಯೆ ಅಗತ್ಯವಿದ್ದಾಗ, ಪ್ರತಿಕ್ರಿಯೆಯು ನಿಖರವಾಗಿ ಒಂದು ಕ್ಲೈಂಟ್ ಟೂಲ್ ಎನ್ವಲಪ್ ಅನ್ನು ಒಳಗೊಂಡಿರಬೇಕು. ಯಾವುದೇ ACP
`tool_call` ಅಥವಾ `tool_call_update` ಅನ್ನು, ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಯಶಸ್ವಿಯೆಂದು ವರದಿ ಮಾಡುವ ಮೊದಲೇ ತಿರಸ್ಕರಿಸಲಾಗುತ್ತದೆ.

`open-sse/executors/devin-agentic/serializer.ts` ನಲ್ಲಿರುವ ಸೀರಿಯಲೈಸರ್ `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice`, ಮತ್ತು
Claude Code ಒದಗಿಸಿದ ಪರಿಕರಗಳನ್ನು ಸಂರಕ್ಷಿಸುತ್ತದೆ. ಚಿತ್ರಗಳು ಮತ್ತು ಅಜ್ಞಾತ ಬ್ಲಾಕ್ಗಳು ಸ್ಪಷ್ಟವಾಗಿ ವಿಫಲಗೊಳ್ಳುತ್ತವೆ. ದೊಡ್ಡ ಪರಿಕರ ಫಲಿತಾಂಶಗಳು
ಗೋಚರಿಸುವ ಟ್ರಂಕೇಶನ್ ಗುರುತನ್ನು ಬಳಸುತ್ತವೆ.

ಪಾರ್ಸರ್ ಪ್ರತಿ ಮಾದರಿ ಸರದಿಗೆ ಒಂದು ಸ್ವತಂತ್ರ `<tool>{...}</tool>` ಎನ್ವಲಪ್ ಅನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ. ಇದು
ವಿನಂತಿಯ ಪರಿಕರ ಪಟ್ಟಿಯ ವಿರುದ್ಧ ಹೆಸರನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ, ಆ ಪರಿಕರದ JSON
Schema ವಿರುದ್ಧ ಆರ್ಗ್ಯುಮೆಂಟ್ಗಳನ್ನು ಮೌಲ್ಯೀಕರಿಸುತ್ತದೆ, ಮಿಶ್ರ ನಿರೂಪಣೆ/ಕ್ರಿಯೆಗಳನ್ನು ತಿರಸ್ಕರಿಸುತ್ತದೆ, ಮತ್ತು ಒಂದು ಮಿತಿಗೊಳಿಸಿದ ದುರಸ್ತಿಗೆ ಅನುಮತಿಸುತ್ತದೆ. ನಂತರ Claude Code
ಪರಿಣಾಮವಾಗಿ ದೊರಕಿದ Anthropic `tool_use` ಅನ್ನು ಸ್ಥಳೀಯವಾಗಿ ಕಾರ್ಯಗತಗೊಳಿಸಿ, `tool_result` ಅನ್ನು OmniRoute ಮೂಲಕ
ಮರಳಿ ಕಳುಹಿಸುತ್ತದೆ.

## ಐಸೊಲೇಶನ್ ಮತ್ತು ಅಪಾಯ ಮಾದರಿ

ಹೋಸ್ಟ್ನ Claude ಇನ್ಸ್ಟಾಲೇಶನ್, ಖಾತೆ ಮತ್ತು ಸಂರಚನೆ ವ್ಯಾಪ್ತಿಯ ಹೊರಗಿದ್ದು, ಅವುಗಳನ್ನು
ನಿಷಿದ್ಧವೆಂದು ಪರಿಗಣಿಸಲಾಗುತ್ತದೆ. Compose ಸೇವೆಗಳು:

- UID/GID `10001:10001` ಆಗಿ, ಓದಲು-ಮಾತ್ರವಾದ ರೂಟ್ ಫೈಲ್ಸಿಸ್ಟಮ್, ತೆಗೆದುಹಾಕಿದ ಸಾಮರ್ಥ್ಯಗಳು ಮತ್ತು
  `no-new-privileges` ಜೊತೆಗೆ ರನ್ ಆಗುತ್ತವೆ;
- ಖಾಸಗಿ `/home/bridge`, ಮೀಸಲಾದ Claude ಸಂರಚನಾ ವಾಲ್ಯೂಮ್, ಪ್ರತ್ಯೇಕ OmniRoute ಡೇಟಾ,
  ಮತ್ತು ಪ್ರತ್ಯೇಕ `devin-auth` ವಾಲ್ಯೂಮ್ ಅನ್ನು ಬಳಸುತ್ತವೆ;
- ತಾತ್ಕಾಲಿಕ `.sandbox` ವರ್ಕ್ಸ್ಪೇಸ್ಗಳು/ಪುರಾವೆಗಳನ್ನು ಮಾತ್ರ ಮೌಂಟ್ ಮಾಡುತ್ತವೆ;
- ಹೋಸ್ಟ್ ಹೋಮ್, Keychain, SSH, ಕ್ಲೌಡ್ ರುಜುವಾತುಗಳು ಅಥವಾ Docker ಸಾಕೆಟ್ ಅನ್ನು ಮೌಂಟ್ ಮಾಡುವುದಿಲ್ಲ;
- ಸ್ಪಷ್ಟ ಪರಿಸರಗಳನ್ನು ರಚಿಸಿ, Anthropic API/OAuth/ರೂಟಿಂಗ್ ವೇರಿಯಬಲ್ಗಳನ್ನು ತೆಗೆದುಹಾಕುತ್ತವೆ;
- ಸ್ಥಳೀಯ-ಮಾತ್ರದ ಕೀಲಿಯೊಂದಿಗೆ Claude Code ಇನ್ಫರೆನ್ಸ್ ಅನ್ನು `http://omniroute:20128` ಗೆ ಮಾತ್ರ ನಿರ್ದೇಶಿಸುತ್ತವೆ.

ಆಫ್ಲೈನ್ ಪ್ರೊಫೈಲ್ ಆಂತರಿಕ ನೆಟ್ವರ್ಕ್ ಅನ್ನು ಬಳಸುತ್ತದೆ. ಲೈವ್ ಪ್ರೊಫೈಲ್ನಲ್ಲಿ, OmniRoute ಅಧಿಕೃತ
Devin ಎಂಡ್ಪಾಯಿಂಟ್ಗಳನ್ನು `network-guard` ಮೂಲಕ ಮಾತ್ರ ತಲುಪುತ್ತದೆ; ಸಂಬಂಧವಿಲ್ಲದ ಗಮ್ಯಸ್ಥಾನಗಳನ್ನು ನಿರಾಕರಿಸಲಾಗುತ್ತದೆ.
Claude Code ಪ್ರತ್ಯೇಕವಾದ deny-all ಎಗ್ರೆಸ್ ಗಾರ್ಡ್ ಹೊಂದಿದ್ದು, `NO_PROXY` ಮೂಲಕ ಸ್ಥಳೀಯ OmniRoute
ಸೇವೆಯನ್ನು ಮಾತ್ರ ತಲುಪಬಹುದು. ಗಾರ್ಡ್ ಆಡಿಟ್ ಫೈಲ್ಗಳನ್ನು ಅವುಗಳ ಗಾರ್ಡ್ ಪ್ರಕ್ರಿಯೆ ಮಾತ್ರ ಮೌಂಟ್ ಮಾಡುತ್ತದೆ. ಸ್ಕ್ರಿಪ್ಟ್ಗಳು
ಟೋಕನ್-ರಹಿತ ಪುರಾವೆಗಳನ್ನು ರಫ್ತು ಮಾಡುವ ಮೊದಲು ಫೈಲ್ ಮಾಲೀಕತ್ವ, ಮೋಡ್, ಲಿಂಕ್ ಎಣಿಕೆ ಮತ್ತು ಪ್ರತಿಯೊಂದು ನಿರ್ಧಾರವನ್ನು ಪರಿಶೀಲಿಸುತ್ತವೆ.

ಐಸೊಲೇಶನ್ ಪುರಾವೆಯನ್ನು ಸ್ವತಂತ್ರವಾಗಿ ಚಲಾಯಿಸಿ:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

ಇದು ಟೊಪಾಲಜಿ, ಹೆಸರಿಸಲಾದ ಮೌಂಟ್ಗಳು, non-root/ಓದಲು-ಮಾತ್ರ ಸೆಟ್ಟಿಂಗ್ಗಳು, ಸ್ಪಷ್ಟ ಸ್ಥಳೀಯ ರೂಟಿಂಗ್,
ಸಂವೇದನಶೀಲ ಎನ್ವಿರಾನ್ಮೆಂಟ್ ವೇರಿಯಬಲ್ಗಳ ಅನುಪಸ್ಥಿತಿ, Docker ಸಾಕೆಟ್ನ ಅನುಪಸ್ಥಿತಿ, `api.anthropic.com`
ಮತ್ತು `claude.ai` ಗೆ ನಿರ್ಬಂಧಿತ ಪ್ರವೇಶ, Devin-ಮಾತ್ರದ ಪೂರೈಕೆದಾರ ಆಯ್ಕೆ, ಹಾಗೂ ACP ಬ್ಯಾಕೆಂಡ್
ಲಭ್ಯವಿಲ್ಲದಾಗ ಉಂಟಾಗುವ ಸ್ಪಷ್ಟ ವೈಫಲ್ಯವನ್ನು ಮೌಲ್ಯೀಕರಿಸುತ್ತದೆ.

## ಮೊದಲ ಬಾರಿಯ ಸೆಟಪ್ ಮತ್ತು ಸಾಮಾನ್ಯ ಬಳಕೆ

ನಿಗದಿತ ಇಮೇಜ್ ಅನ್ನು ಬಿಲ್ಡ್ ಮಾಡಿ:

```bash
./scripts/devin-bridge/build
```

ಪ್ರತ್ಯೇಕಿಸಲಾದ Devin ವಾಲ್ಯೂಮ್ ಅನ್ನು ಮಾತ್ರ ದೃಢೀಕರಿಸಿ:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

ಲಾಗಿನ್ ಕಮಾಂಡ್ ದೂರಸ್ಥ/ಕಂಟೈನರ್ ಪರಿಸರಗಳಿಗಾಗಿ ಉದ್ದೇಶಿಸಲಾದ ಅಧಿಕೃತ ಮ್ಯಾನುಯಲ್-ಟೋಕನ್ ಪ್ರಕ್ರಿಯೆಯನ್ನು ಬಳಸುತ್ತದೆ. ಮೌಲ್ಯವನ್ನು ನೇರವಾಗಿ CLI ಪ್ರಾಂಪ್ಟ್ನಲ್ಲಿ ನಮೂದಿಸಲಾಗುತ್ತದೆ; ಅದನ್ನು ಪ್ರಕ್ರಿಯೆಯ ಆರ್ಗ್ಯುಮೆಂಟ್ ಆಗಿ ರವಾನಿಸಲಾಗುವುದಿಲ್ಲ, Gitಗೆ ಬರೆಯಲಾಗುವುದಿಲ್ಲ ಅಥವಾ ಹೋಸ್ಟ್ನಿಂದ ನಕಲಿಸಲಾಗುವುದಿಲ್ಲ.

ಪ್ರತ್ಯೇಕಿಸಲಾದ Claude Code ರನ್ಟೈಮ್ ಅನ್ನು ಪ್ರಾರಂಭಿಸಿ:

```bash
./scripts/devin-bridge/launch
```

ಕಂಟೈನರೀಕೃತ Claude Code ಅನ್ನು ಪ್ರಾರಂಭಿಸುವ ಮೊದಲು `launch` ಪ್ರತ್ಯೇಕತೆ, Devin ದೃಢೀಕರಣ ಮತ್ತು ಮಾಡೆಲ್ ಅನ್ವೇಷಣೆಯನ್ನು ಮರುಪರಿಶೀಲಿಸುತ್ತದೆ. ಇದು ಹೋಸ್ಟ್ನ Claude ಎಕ್ಸಿಕ್ಯೂಟಬಲ್ ಅನ್ನು ಎಂದಿಗೂ ಚಲಾಯಿಸುವುದಿಲ್ಲ. ಮಾಡೆಲ್ ಅಲಿಯಾಸ್ಗಳನ್ನು `.env.devin-bridge` ನಲ್ಲಿ ಹೊಂದಿಸಬಹುದು; ಕಾನ್ಫಿಗರ್ ಮಾಡಿದ ಪ್ರತಿಯೊಂದು ಮೌಲ್ಯವೂ `devin-cli-agentic/` ಪೂರ್ವಪ್ರತ್ಯಯವನ್ನು ಉಳಿಸಿಕೊಳ್ಳಬೇಕು.

## ಮೌಲ್ಯೀಕರಣ ಕಮಾಂಡ್ಗಳು

ಪುನರುತ್ಪಾದಿಸಬಹುದಾದ ಆಫ್ಲೈನ್ ಮಾರ್ಗಕ್ಕೆ Devin ಖಾತೆಯ ಅಗತ್ಯವಿಲ್ಲ ಮತ್ತು ರನ್ಟೈಮ್ ಇಂಟರ್ನೆಟ್ ಪ್ರವೇಶವೂ ಇಲ್ಲ:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

ದೃಢೀಕರಿಸಿದ, ಆಯ್ಕೆಯಾಧಾರಿತ ಲೈವ್ ಮಾರ್ಗ ಹೀಗಿದೆ:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

ACP ಸೆಷನ್ಗಳನ್ನು ಏಕಾಏಕಿ ತೆರೆಯುವುದನ್ನು ತಪ್ಪಿಸಲು ಲೈವ್ ರನ್ನರ್ ಸನ್ನಿವೇಶಗಳ ನಡುವೆ ಕಾಯುತ್ತದೆ ಮತ್ತು ಪಠ್ಯರೂಪದ ಪ್ರತಿಪಾದನೆಗಳನ್ನು ನಂಬುವ ಬದಲು ರಚನಾತ್ಮಕ Claude ಸ್ಟ್ರೀಮ್ ಈವೆಂಟ್ಗಳನ್ನು ಮೌಲ್ಯೀಕರಿಸುತ್ತದೆ. ಅದರ ಮೂರು ಸನ್ನಿವೇಶಗಳು ಇವುಗಳನ್ನು ಸಾಬೀತುಪಡಿಸುತ್ತವೆ:

1. ನೇರ ಪ್ರಾಜೆಕ್ಟ್ ಓದುವಿಕೆ ಮತ್ತು ದೋಷ ವಿಶ್ಲೇಷಣೆ;
2. ನೈಜ `Edit`, ಕ್ಲೈಂಟ್-ಸ್ವಾಮ್ಯದ `Bash` `npm test`, ಮತ್ತು ಟರ್ಮಿನಲ್ ಫಲಿತಾಂಶ;
3. `/bridge-check` ಜೊತೆಗೆ `bridge-proof` ಅನ್ವೇಷಣೆ, ಪ್ರಾಜೆಕ್ಟ್ ಓದುವಿಕೆ, ಮತ್ತೊಂದು ಯಶಸ್ವಿ ಕ್ಲೈಂಟ್-ಸ್ವಾಮ್ಯದ `npm test`, ಮತ್ತು ಬಾಕಿ ಕೆಲಸವಿಲ್ಲದೆ ಪೂರ್ಣಗೊಳಿಸುವಿಕೆ.

ಅಂತಿಮ ಗೇಟ್ Devin ನೆಟ್ವರ್ಕ್ ಆಡಿಟ್ ಅನ್ನು ಸಹ ಪರಿಶೀಲಿಸುತ್ತದೆ ಮತ್ತು Claude ಎಗ್ರೆಸ್ ಆಡಿಟ್ ಖಾಲಿಯಾಗಿಯೇ ಉಳಿಯುವುದನ್ನು ಕಡ್ಡಾಯಗೊಳಿಸುತ್ತದೆ.

## ನಿಗದಿತ ಪರಿಕರಗಳನ್ನು ನವೀಕರಿಸುವುದು

ಇಮೇಜ್ನಲ್ಲಿ Node, Claude Code ಮತ್ತು Devin CLI ಆವೃತ್ತಿಗಳನ್ನು `docker/devin-bridge/Dockerfile` ನಲ್ಲಿ ನಿಗದಿಪಡಿಸಲಾಗಿದೆ. ನವೀಕರಿಸಲು:

1. ಸ್ಪಷ್ಟವಾಗಿ ನಮೂದಿಸಿದ ಆವೃತ್ತಿಗಳನ್ನು ಬದಲಾಯಿಸಿ;
2. ಎರಡೂ ಆರ್ಕಿಟೆಕ್ಚರ್-ನಿರ್ದಿಷ್ಟ Devin ಆರ್ಕೈವ್ ಚೆಕ್ಸಮ್ಗಳನ್ನು ಅಧಿಕೃತ ಆರ್ಟಿಫ್ಯಾಕ್ಟ್ನ ಮೌಲ್ಯಗಳಿಂದ ಬದಲಾಯಿಸಿ;
3. ಮರುಬಿಲ್ಡ್ ಮಾಡಿ ಮತ್ತು ಪ್ರತಿಯೊಂದು ಆಫ್ಲೈನ್ ಮೌಲ್ಯೀಕರಣ ಕಮಾಂಡ್ ಅನ್ನು ಚಲಾಯಿಸಿ;
4. ಇಮೇಜ್ನೊಳಗಿನ ಆವೃತ್ತಿಗಳನ್ನು ದೃಢೀಕರಿಸಿ;
5. ದೃಢೀಕರಿಸಿದ ಮೂರು-ಸನ್ನಿವೇಶಗಳ ಲೈವ್ ಸೂಟ್ ಅನ್ನು ಮರುಚಲಾಯಿಸಿ.

ಎರಡೂ CLI ಗಳಲ್ಲಿ ಯಾವುದನ್ನೂ ಹೋಸ್ಟ್ನಲ್ಲಿ ಗ್ಲೋಬಲ್ ಆಗಿ ಇನ್ಸ್ಟಾಲ್ ಮಾಡಬೇಡಿ ಅಥವಾ ಚೆಕ್ಸಮ್ ಪರಿಶೀಲನೆಯನ್ನು ಪರಿಶೀಲಿಸದ ಡೌನ್ಲೋಡ್ನಿಂದ ಬದಲಾಯಿಸಬೇಡಿ.

## ರೋಗನಿರ್ಣಯ ಮತ್ತು ಸ್ವಚ್ಛಗೊಳಿಸುವಿಕೆ

  ಸ್ಥಳೀಯ ರೂಟಿಂಗ್ ಮತ್ತು ಶುದ್ಧೀಕರಿಸಿದ ಎಕ್ಸಿಕ್ಯೂಟರ್ ದೋಷಗಳನ್ನು ತೋರಿಸುತ್ತದೆ.

- `.sandbox/evidence/live-*.jsonl` ಮೌಲ್ಯೀಕರಿಸಿದ ಮೂರು ಲೈವ್ ಸ್ಟ್ರೀಮ್ಗಳನ್ನು ದಾಖಲಿಸುತ್ತದೆ.

ಲಾಗಿನ್/ಕಾನ್ಫಿಗ್ ವಾಲ್ಯೂಮ್ಗಳನ್ನು ಉಳಿಸಿಕೊಂಡು ಸ್ವಾಮ್ಯದಲ್ಲಿರುವ ಕಂಟೈನರ್ಗಳು ಮತ್ತು ನೆಟ್ವರ್ಕ್ಗಳನ್ನು ನಿಲ್ಲಿಸಿ:


ಹೆಸರಿಸಲಾದ ವಾಲ್ಯೂಮ್ಗಳನ್ನು ಒಳಗೊಂಡಂತೆ ಬ್ರಿಡ್ಜ್-ಸ್ವಾಮ್ಯದ ಸಂಪೂರ್ಣ ಪರಿಸರವನ್ನು ತೆಗೆದುಹಾಕಿ:

## ಮಿತಿಗಳು

- Devin CLI `3000.2.17` ತಟಸ್ಥವಾದ, ಯಾವುದೇ ಪರಿಕರಗಳಿಲ್ಲದ ACP ಏಜೆಂಟ್ ಅನ್ನು ಒದಗಿಸದ ಕಾರಣ, ಬ್ರಿಡ್ಜ್ ಸ್ಥಿರವಾದ ಪರಿಕರಗಳಿಲ್ಲದ `summarizer` ಪಾತ್ರವನ್ನು ಅವಲಂಬಿಸಿದೆ. ಅಡಾಪ್ಟರ್ ಸಾರಾಂಶ-ರೂಪದ ಮಧ್ಯಂತರ ಪ್ರತಿಕ್ರಿಯೆಗಳನ್ನು ಸರಿದೂಗಿಸುತ್ತದೆ, ಆದರೆ ಒಂದು ಮಿತಿಗೊಳಿಸಿದ ದುರಸ್ತಿ ಪ್ರಯತ್ನವು ಇನ್ನೂ ಸ್ಪಷ್ಟವಾಗಿ ವಿಫಲವಾಗಬಹುದು.
- ಲೈವ್ ACP ಕರೆಗಳು ತಾತ್ಕಾಲಿಕ `502`/`504` ಪ್ರತಿಕ್ರಿಯೆಗಳನ್ನು ಹಿಂದಿರುಗಿಸಬಹುದು. ಹಾರ್ನೆಸ್ ಸನ್ನಿವೇಶಗಳ ನಡುವೆ ವಿರಾಮವನ್ನು ಇರಿಸುತ್ತದೆ; ನಿರಂತರ ವೈಫಲ್ಯದ ಸಂದರ್ಭದಲ್ಲಿ ವ್ಯವಸ್ಥೆಯು ವಿಫಲತೆಯಲ್ಲೇ ಮುಚ್ಚಿಕೊಳ್ಳುತ್ತದೆ ಮತ್ತು ಮತ್ತೊಂದು ಪೂರೈಕೆದಾರರನ್ನು ಎಂದಿಗೂ ಆಯ್ಕೆ ಮಾಡುವುದಿಲ್ಲ.
- ಪ್ರತಿ Anthropic ವಿನಂತಿಯಿಂದ ACP ಸಂದರ್ಭವನ್ನು ಮರುರಚಿಸಲಾಗುತ್ತದೆ; ಪ್ರಕ್ರಿಯೆ/ಸೆಷನ್ ಅಫಿನಿಟಿ ಇರುವುದಿಲ್ಲ.
- ಪ್ರತಿ ಮಾದರಿ ಪ್ರತಿಕ್ರಿಯೆಗೆ ಒಂದು ಪರಿಕರ ಕರೆಯನ್ನು ಬೆಂಬಲಿಸಲಾಗುತ್ತದೆ; ಸಮಾನಾಂತರ ಕರೆಗಳನ್ನು ತಿರಸ್ಕರಿಸಲಾಗುತ್ತದೆ.
- ಚಿತ್ರಗಳನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ಬೆಂಬಲಿಸಲಾಗುವುದಿಲ್ಲ. ವಿಷನ್, ಚಿಂತನಾ ಔಟ್ಪುಟ್, ಪ್ರಯತ್ನ ನಿಯಂತ್ರಣಗಳು ಮತ್ತು 1M ಸಂದರ್ಭ ವಿಂಡೋವನ್ನು ಜಾಹೀರಾತು ಮಾಡುವುದಿಲ್ಲ.
- SSE ಮಾನ್ಯವಾದ Anthropic ಜೀವನಚಕ್ರ ಈವೆಂಟ್ಗಳನ್ನು ಬಳಸುತ್ತದೆ, ಆದರೆ ಮಿತಿಗೊಳಿಸಿದ ACP ಟರ್ನ್ ಅನ್ನು ಸಂಗ್ರಹಿಸಿದ ನಂತರ ಅದನ್ನು ಹೊರಸೂಸಲಾಗುತ್ತದೆ; ACP ಚಂಕ್ಗಳನ್ನು ಹಂತ ಹಂತವಾಗಿ ಫಾರ್ವರ್ಡ್ ಮಾಡುವುದಿಲ್ಲ.
