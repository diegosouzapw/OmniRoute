ವೆಬ್ ಕುಕಿ ಪೂರೈಕೆದಾರಗಳು API ಕೀ ಬದಲಿಗೆ ನಿಮ್ಮ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಬ್ರೌಸರ್ ಸೆಷನ್ ಮೂಲಕ AI ಸೇವೆಯನ್ನು ಬಳಸಲು OmniRouteಗೆ ಅವಕಾಶ ನೀಡುತ್ತವೆ. ನೀವು ಈಗಾಗಲೇ ಒಂದು ಸೇವೆಯ ವೆಬ್ಸೈಟ್ ಮೂಲಕ ಅದಕ್ಕೆ ಪ್ರವೇಶವನ್ನು ಹೊಂದಿದ್ದು, ಅದೇ ದೃಢೀಕೃತ ಸೆಷನ್ ಅನ್ನು OmniRoute ಬಳಸಬೇಕೆಂದು ಬಯಸಿದಾಗ ಅವು ಉಪಯುಕ್ತವಾಗಿವೆ.

API-ಕೀ ಪೂರೈಕೆದಾರಗಳಿಗಿಂತ ಭಿನ್ನವಾಗಿ, ವೆಬ್ ಕುಕಿ ಪೂರೈಕೆದಾರಗಳು ನಿಮ್ಮ ಬ್ರೌಸರ್ ವೆಬ್ಸೈಟ್ಗೆ ಕಳುಹಿಸುವ ರುಜುವಾತುಗಳನ್ನು ಬಳಸಿಕೊಂಡು ದೃಢೀಕರಿಸುತ್ತವೆ.

# ಪ್ರಾರಂಭಿಸುವ ಮೊದಲು

> **ಪ್ರಮುಖ:** ರುಜುವಾತುಗಳನ್ನು ಯಾವಾಗಲೂ **ಸಕ್ರಿಯ ನೆಟ್ವರ್ಕ್ ವಿನಂತಿಯಿಂದ** ನಕಲಿಸಿ, ನಿಮ್ಮ ಬ್ರೌಸರ್ನ ಕುಕಿ ಸಂಗ್ರಹಣೆಯಿಂದ **ಅಲ್ಲ**.

ತಪ್ಪಾದ ಸ್ಥಳದಿಂದ ಕುಕಿಗಳನ್ನು ನಕಲಿಸುವುದರಿಂದ ಅನೇಕ ದೃಢೀಕರಣ ಸಮಸ್ಯೆಗಳು ಉಂಟಾಗುತ್ತವೆ.

## ಕುಕಿ ಸಂಗ್ರಹಣೆಯಿಂದ ನಕಲಿಸಬೇಡಿ

ಹೆಚ್ಚಿನ ಬ್ರೌಸರ್ಗಳು ಸಂಗ್ರಹಿಸಿದ ಕುಕಿಗಳನ್ನು ಈ ಮೂಲಕ ತೋರಿಸುತ್ತವೆ:

```
DevTools
→ Application (ಅಥವಾ Storage)
→ Cookies
```

ಈ ಕುಕಿಗಳು ಸರಿಯಾಗಿ ಕಾಣಿಸಿದರೂ, ಅವು:

- ಹಳೆಯದಾಗಿರಬಹುದು
- ಅಪೂರ್ಣವಾಗಿರಬಹುದು
- ದೃಢೀಕೃತ ವಿನಂತಿಗಳಲ್ಲಿ ಮಾತ್ರ ಕಳುಹಿಸಲಾಗುವ ಕುಕಿಗಳನ್ನು ಹೊಂದಿರದಿರಬಹುದು

ಈ ಮೌಲ್ಯಗಳನ್ನು ಬಳಸುವುದರಿಂದ ಅವು ಮಾನ್ಯವಾಗಿ ಕಂಡರೂ ಸಹ ದೃಢೀಕರಣ ವಿಫಲವಾಗಬಹುದು.

## ಸಕ್ರಿಯ ವಿನಂತಿಯಿಂದ ನಕಲಿಸಿ

ಬದಲಾಗಿ, ಯಶಸ್ವಿ ವಿನಂತಿಯ ಕುಕಿಗಳನ್ನು ಬಳಸಿ:

```
DevTools
→ Network
→ ಪುಟವನ್ನು ರಿಫ್ರೆಶ್ ಮಾಡಿ
→ ಚಾಟ್ ಅಥವಾ ಸಂಭಾಷಣೆ ವಿನಂತಿಯನ್ನು ತೆರೆಯಿರಿ
→ Request Headers
→ Cookie
```

`Cookie` ವಿನಂತಿ ಹೆಡರ್ ನಿಮ್ಮ ಬ್ರೌಸರ್ ಯಶಸ್ವಿಯಾಗಿ ಬಳಸಿದ ನಿಖರವಾದ ದೃಢೀಕರಣ ಮಾಹಿತಿಯನ್ನು ಒಳಗೊಂಡಿರುತ್ತದೆ.

ಹೆಚ್ಚಿನ ವೆಬ್ ಕುಕಿ ಪೂರೈಕೆದಾರಗಳಿಗಾಗಿ, ಇದೇ OmniRouteನಲ್ಲಿ ಅಂಟಿಸಬೇಕಾದ ಮೌಲ್ಯವಾಗಿದೆ.

# ಸಾಮಾನ್ಯ ಸೆಟಪ್

ಹೆಚ್ಚಿನ ವೆಬ್ ಕುಕಿ ಪೂರೈಕೆದಾರಗಳಿಗೆ ಸೆಟಪ್ ಪ್ರಕ್ರಿಯೆ ಒಂದೇ ಆಗಿರುತ್ತದೆ.

1. ಪೂರೈಕೆದಾರರ ವೆಬ್ಸೈಟ್ಗೆ ಸೈನ್ ಇನ್ ಮಾಡಿ.
2. ಬ್ರೌಸರ್ನ ಡೆವಲಪರ್ ಟೂಲ್ಗಳನ್ನು ತೆರೆಯಿರಿ.
3. **Network** ಟ್ಯಾಬ್ ತೆರೆಯಿರಿ.
4. ಪುಟವನ್ನು ರಿಫ್ರೆಶ್ ಮಾಡಿ.
5. ದೃಢೀಕೃತ ಚಾಟ್ ಅಥವಾ ಸಂಭಾಷಣೆ ವಿನಂತಿಯನ್ನು ತೆರೆಯಿರಿ.
6. ಅಗತ್ಯವಿರುವ ದೃಢೀಕರಣ ರುಜುವಾತುಗಳನ್ನು ನಕಲಿಸಿ.
7. OmniRoute ತೆರೆಯಿರಿ.
8. **Providers → Add Provider** ಗೆ ಹೋಗಿ.
9. ನಿಮ್ಮ ವೆಬ್ ಕುಕಿ ಪೂರೈಕೆದಾರರನ್ನು ಆಯ್ಕೆಮಾಡಿ.
10. ರುಜುವಾತುಗಳನ್ನು ಅಂಟಿಸಿ.
11. **Test Connection** ಕ್ಲಿಕ್ ಮಾಡಿ.
12. ಪೂರೈಕೆದಾರರನ್ನು ಉಳಿಸಿ.

ಅಗತ್ಯವಿರುವ ನಿಖರವಾದ ರುಜುವಾತುಗಳು ಪೂರೈಕೆದಾರರನ್ನು ಅವಲಂಬಿಸಿರುತ್ತವೆ.

# ವೆಬ್ ಕುಕಿ ಪೂರೈಕೆದಾರರು ಏನು ಮಾಡಬಹುದು ಮತ್ತು ಏನು ಮಾಡಲು ಸಾಧ್ಯವಿಲ್ಲ

ವೆಬ್ ಕುಕಿ ಪೂರೈಕೆದಾರರು ವೆಬ್ಸೈಟ್ನ ಚಾಟ್ ಇಂಟರ್ಫೇಸ್ ಅನ್ನು ಮರುಬಳಕೆ ಮಾಡುತ್ತಾರೆ. ಅವು ಅಧಿಕೃತ APIಗಳಂತೆಯೇ ಅದೇ ಸಾಮರ್ಥ್ಯಗಳನ್ನು ಒದಗಿಸುವುದಿಲ್ಲ.

## ಬೆಂಬಲಿತ

- ನಿಮ್ಮ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಬ್ರೌಸರ್ ಸೆಷನ್ ಬಳಸಿ ದೃಢೀಕರಿಸುವುದು
- ನಿಮ್ಮ ಖಾತೆಯ ಮೂಲಕ ಲಭ್ಯವಿರುವ ಮಾದರಿಗಳನ್ನು ಪ್ರವೇಶಿಸುವುದು
- ಚಾಟ್ ಪ್ರತಿಕ್ರಿಯೆಗಳನ್ನು ಸ್ಟ್ರೀಮ್ ಮಾಡುವುದು
- API ಕೀ ಅಗತ್ಯವಿಲ್ಲ

## ಬೆಂಬಲಿತವಲ್ಲ

- ಫಂಕ್ಷನ್ ಕಾಲಿಂಗ್
- ಟೂಲ್ ಕಾಲಿಂಗ್
- ಸ್ವಯಂಚಾಲಿತ ಫೈಲ್ ಸಂಪಾದನೆ
- ಸ್ವಾಯತ್ತ ಏಜೆಂಟ್ ಆಧಾರಿತ IDE ಕಾರ್ಯಪ್ರವಾಹಗಳು
- APIಗೆ ಮಾತ್ರ ಸೀಮಿತವಾದ ವೈಶಿಷ್ಟ್ಯಗಳು

ಇದು ನಿರೀಕ್ಷಿತ ನಡವಳಿಕೆಯಾಗಿದೆ ಮತ್ತು ಇದು ದೋಷ **ಅಲ್ಲ**.

ನಿಮಗೆ ಟೂಲ್ ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆ, ಸ್ವಯಂಚಾಲಿತ ಫೈಲ್ ಸಂಪಾದನೆ ಅಥವಾ ಇತರ ಏಜೆಂಟ್ ಕಾರ್ಯಪ್ರವಾಹಗಳು ಅಗತ್ಯವಿದ್ದರೆ, ವೆಬ್ ಕುಕಿ ಪೂರೈಕೆದಾರರ ಬದಲಿಗೆ **API-ಕೀ ಪೂರೈಕೆದಾರರನ್ನು** ಬಳಸಿ.

# ಮೌಲ್ಯೀಕರಣದ ಮಿತಿ

ಯಶಸ್ವಿಯಾದ **Test Connection** ಅಥವಾ ಕುಕಿ ಮೌಲ್ಯೀಕರಣವು ಒದಗಿಸಿದ ರುಜುವಾತುಗಳು ನಿರೀಕ್ಷಿತ ಸ್ವರೂಪದಲ್ಲಿರುವಂತೆ ಕಾಣುತ್ತವೆ ಎಂಬುದನ್ನು ಮಾತ್ರ ಪರಿಶೀಲಿಸುತ್ತದೆ.

Issue #7857 ಪರಿಹಾರವಾಗುವವರೆಗೆ, ಯಶಸ್ವಿ ಮೌಲ್ಯೀಕರಣವು ಪೂರೈಕೆದಾರರು ಯಶಸ್ವಿಯಾಗಿ ದೃಢೀಕರಿಸುತ್ತಾರೆ ಎಂಬುದಕ್ಕೆ **ಖಾತರಿ ನೀಡುವುದಿಲ್ಲ**.

ದೃಢೀಕರಣ ಇನ್ನೂ ವಿಫಲವಾದರೆ, ನೀವು ರುಜುವಾತುಗಳನ್ನು ಬ್ರೌಸರ್ ಕುಕಿ ಸಂಗ್ರಹಣೆಯಿಂದ ನಕಲಿಸುವ ಬದಲು ಸಕ್ರಿಯ ನೆಟ್ವರ್ಕ್ ವಿನಂತಿಯಿಂದ ನಕಲಿಸಿದ್ದೀರಿ ಎಂಬುದನ್ನು ಪರಿಶೀಲಿಸಿ.

---

# ಸಮಸ್ಯೆ ಪರಿಹಾರ

## ದೃಢೀಕರಣ ವಿಫಲವಾಗುತ್ತದೆ

ರುಜುವಾತುಗಳನ್ನು ಇಲ್ಲಿಂದ ನಕಲಿಸಲಾಗಿದೆ ಎಂಬುದನ್ನು ಪರಿಶೀಲಿಸಿ:

```
Network
→ Request Headers
→ Cookie
```

ಮತ್ತು ಇಲ್ಲಿಂದ **ಅಲ್ಲ**:

```
Application
→ Cookies
```

---

## ಕುಕಿ ಬ್ರೌಸರ್ನಲ್ಲಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ ಆದರೆ OmniRouteನಲ್ಲಿ ಅಲ್ಲ

ಕೆಲವು ಪೂರೈಕೆದಾರರು ದೃಢೀಕೃತ ವಿನಂತಿಗಳ ಸಮಯದಲ್ಲಿ ಮಾತ್ರ ಕಳುಹಿಸಲಾಗುವ ಕುಕಿಗಳನ್ನು ಒಳಗೊಂಡಿರುತ್ತಾರೆ.

ಸಂಭಾಷಣೆಯನ್ನು ಯಶಸ್ವಿಯಾಗಿ ತೆರೆದ ನಂತರ, ಹೊಸ ನೆಟ್ವರ್ಕ್ ವಿನಂತಿಯಿಂದ ರುಜುವಾತುಗಳನ್ನು ಮತ್ತೊಮ್ಮೆ ನಕಲಿಸಿ.

---

## ಸೆಷನ್ ಅವಧಿ ಮುಗಿದಿದೆ

ವೆಬ್ ಕುಕಿ ಪೂರೈಕೆದಾರರು ನಿಮ್ಮ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಬ್ರೌಸರ್ ಸೆಷನ್ ಅನ್ನು ಬಳಸುತ್ತಾರೆ.

ನಿಮ್ಮ ಬ್ರೌಸರ್ ಸೆಷನ್ ಅವಧಿ ಮುಗಿದರೆ ಅಥವಾ ನೀವು ಸೈನ್ ಔಟ್ ಮಾಡಿದರೆ, ನೀವು ಹೊಸ ರುಜುವಾತುಗಳ ಸಮೂಹವನ್ನು ನಕಲಿಸಬೇಕು.

# ಅತ್ಯುತ್ತಮ ಅಭ್ಯಾಸಗಳು

- ಹೊಸ ದೃಢೀಕೃತ ವಿನಂತಿಯಿಂದ ರುಜುವಾತುಗಳನ್ನು ನಕಲಿಸಿ.
- ಹಳೆಯ ಕುಕಿಗಳನ್ನು ಮರುಬಳಕೆ ಮಾಡುವುದನ್ನು ತಪ್ಪಿಸಿ.
- ವೆಬ್ ಕುಕಿ ಪೂರೈಕೆದಾರರನ್ನು ಬಳಸುವಾಗ ನಿಮ್ಮ ಬ್ರೌಸರ್ ಸೆಷನ್ ಅನ್ನು ಸಕ್ರಿಯವಾಗಿರಿಸಿ.
- ನಕಲಿಸಿದ ಕುಕಿಗಳನ್ನು ಸೂಕ್ಷ್ಮ ರುಜುವಾತುಗಳಾಗಿ ಪರಿಗಣಿಸಿ.
- ನಿಮಗೆ ಫಂಕ್ಷನ್ ಕಾಲಿಂಗ್ ಅಥವಾ ಏಜೆಂಟ್ ಕಾರ್ಯಪ್ರವಾಹಗಳು ಅಗತ್ಯವಿದ್ದಾಗ API-ಕೀ ಪೂರೈಕೆದಾರರನ್ನು ಬಳಸಿ.
