Web Cookie ಪೂರೈಕೆದಾರಗಳು API ಕೀಲಿಯ ಬದಲಿಗೆ ನಿಮ್ಮ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಬ್ರೌಸರ್ ಸೆಷನ್ ಮೂಲಕ AI ಸೇವೆಯನ್ನು ಬಳಸಲು OmniRoute ಗೆ ಅವಕಾಶ ನೀಡುತ್ತವೆ. ನೀವು ಈಗಾಗಲೇ ಒಂದು ಸೇವೆಯ ವೆಬ್ಸೈಟ್ ಮೂಲಕ ಅದಕ್ಕೆ ಪ್ರವೇಶ ಹೊಂದಿದ್ದು, ಅದೇ ದೃಢೀಕೃತ ಸೆಷನ್ ಅನ್ನು OmniRoute ಬಳಸಬೇಕೆಂದು ಬಯಸಿದಾಗ ಅವು ಉಪಯುಕ್ತವಾಗಿವೆ.

API-ಕೀ ಪೂರೈಕೆದಾರಗಳಿಗಿಂತ ಭಿನ್ನವಾಗಿ, Web Cookie ಪೂರೈಕೆದಾರಗಳು ನಿಮ್ಮ ಬ್ರೌಸರ್ ವೆಬ್ಸೈಟ್ಗೆ ಕಳುಹಿಸುವ ರುಜುವಾತುಗಳನ್ನು ಬಳಸಿಕೊಂಡು ದೃಢೀಕರಿಸುತ್ತವೆ.

# ಪ್ರಾರಂಭಿಸುವ ಮೊದಲು

> **ಪ್ರಮುಖ:** ಯಾವಾಗಲೂ ರುಜುವಾತುಗಳನ್ನು **ಸಕ್ರಿಯ ನೆಟ್ವರ್ಕ್ ವಿನಂತಿಯಿಂದಲೇ** ನಕಲಿಸಿ, ನಿಮ್ಮ ಬ್ರೌಸರ್ನ cookie ಸಂಗ್ರಹದಿಂದ **ಅಲ್ಲ**.

ತಪ್ಪಾದ ಸ್ಥಳದಿಂದ cookies ನಕಲಿಸುವುದರಿಂದ ಅನೇಕ ದೃಢೀಕರಣ ಸಮಸ್ಯೆಗಳು ಉಂಟಾಗುತ್ತವೆ.

## Cookie ಸಂಗ್ರಹದಿಂದ ನಕಲಿಸಬೇಡಿ

ಹೆಚ್ಚಿನ ಬ್ರೌಸರ್ಗಳು ಸಂಗ್ರಹಿಸಲಾದ cookies ಅನ್ನು ಈ ಮಾರ್ಗದ ಮೂಲಕ ತೋರಿಸುತ್ತವೆ:

```
DevTools
→ Application (ಅಥವಾ Storage)
→ Cookies
```

ಈ cookies ಸರಿಯಾಗಿರುವಂತೆ ಕಂಡರೂ, ಅವು:

- ಹಳೆಯದಾಗಿರಬಹುದು
- ಅಪೂರ್ಣವಾಗಿರಬಹುದು
- ದೃಢೀಕೃತ ವಿನಂತಿಗಳಲ್ಲಿ ಮಾತ್ರ ಕಳುಹಿಸಲಾಗುವ cookies ಅನ್ನು ಒಳಗೊಂಡಿರದೇ ಇರಬಹುದು

ಈ ಮೌಲ್ಯಗಳು ಮಾನ್ಯವಾಗಿ ಕಂಡರೂ, ಅವುಗಳನ್ನು ಬಳಸುವುದರಿಂದ ದೃಢೀಕರಣ ವಿಫಲವಾಗಬಹುದು.

## ಸಕ್ರಿಯ ವಿನಂತಿಯಿಂದ ನಕಲಿಸಿ

ಬದಲಾಗಿ, ಯಶಸ್ವಿ ವಿನಂತಿಯ cookies ಅನ್ನು ಬಳಸಿ:

```
DevTools
→ Network
→ ಪುಟವನ್ನು ರಿಫ್ರೆಶ್ ಮಾಡಿ
→ ಚಾಟ್ ಅಥವಾ ಸಂಭಾಷಣೆ ವಿನಂತಿಯನ್ನು ತೆರೆಯಿರಿ
→ Request Headers
→ Cookie
```

`Cookie` ವಿನಂತಿ ಹೆಡರ್ ನಿಮ್ಮ ಬ್ರೌಸರ್ ಯಶಸ್ವಿಯಾಗಿ ಬಳಸಿದ ನಿಖರವಾದ ದೃಢೀಕರಣ ಮಾಹಿತಿಯನ್ನು ಒಳಗೊಂಡಿರುತ್ತದೆ.

ಹೆಚ್ಚಿನ Web Cookie ಪೂರೈಕೆದಾರರಿಗೆ, OmniRoute ನಲ್ಲಿ ಅಂಟಿಸಬೇಕಾದ ಮೌಲ್ಯ ಇದೇ ಆಗಿರುತ್ತದೆ.

# ಸಾಮಾನ್ಯ ಸೆಟಪ್

ಹೆಚ್ಚಿನ Web Cookie ಪೂರೈಕೆದಾರರಿಗೆ ಸೆಟಪ್ ಪ್ರಕ್ರಿಯೆ ಒಂದೇ ಆಗಿರುತ್ತದೆ.

1. ಪೂರೈಕೆದಾರರ ವೆಬ್ಸೈಟ್ಗೆ ಸೈನ್ ಇನ್ ಮಾಡಿ.
2. ಬ್ರೌಸರ್ನ Developer Tools ತೆರೆಯಿರಿ.
3. **Network** ಟ್ಯಾಬ್ ತೆರೆಯಿರಿ.
4. ಪುಟವನ್ನು ರಿಫ್ರೆಶ್ ಮಾಡಿ.
5. ದೃಢೀಕೃತ ಚಾಟ್ ಅಥವಾ ಸಂಭಾಷಣೆ ವಿನಂತಿಯನ್ನು ತೆರೆಯಿರಿ.
6. ಅಗತ್ಯವಿರುವ ದೃಢೀಕರಣ ರುಜುವಾತುಗಳನ್ನು ನಕಲಿಸಿ.
7. OmniRoute ತೆರೆಯಿರಿ.
8. **Providers → Add Provider** ಗೆ ಹೋಗಿ.
9. ನಿಮ್ಮ Web Cookie ಪೂರೈಕೆದಾರರನ್ನು ಆಯ್ಕೆಮಾಡಿ.
10. ರುಜುವಾತುಗಳನ್ನು ಅಂಟಿಸಿ.
11. **Test Connection** ಕ್ಲಿಕ್ ಮಾಡಿ.
12. ಪೂರೈಕೆದಾರರನ್ನು ಉಳಿಸಿ.

ಅಗತ್ಯವಿರುವ ನಿಖರವಾದ ರುಜುವಾತುಗಳು ಪೂರೈಕೆದಾರರನ್ನು ಅವಲಂಬಿಸಿರುತ್ತವೆ.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) ಯಾವುದೇ ಸೈನ್ಅಪ್ ಅಗತ್ಯವಿಲ್ಲದ ಉಚಿತ ಗ್ರಾಹಕ ಚಾಟ್ ವೇದಿಕೆಯಾಗಿದೆ — ಮೊದಲ ಭೇಟಿಯಲ್ಲಿ ಸೆಷನ್ ಅನ್ನು ಅನಾಮಧೇಯವಾಗಿ ರಚಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಅದು ಮೂರು ಕುಕಿಗಳ ಮೂಲಕ ಉಳಿಯುತ್ತದೆ: `uid`, `si_usr_id`, ಮತ್ತು `si_ses_id`. OmniRoute ಅದೇ `/api/dispatch` ಎಂಡ್ಪಾಯಿಂಟ್ ಅನ್ನು ಒಂದೇ ಮಾದರಿ ಐಡಿ (`notrack-c`, ಅಲಿಯಾಸ್ `ntw`) ಮೂಲಕ ಪ್ರಾಕ್ಸಿ ಮಾಡುತ್ತದೆ.

### ಸಂಪರ್ಕಿಸುವ ಹಂತಗಳು

1. ನಿಮ್ಮ ಬ್ರೌಸರ್ನಲ್ಲಿ [notrack.ai](https://notrack.ai) ತೆರೆಯಿರಿ ಮತ್ತು ಅನಾಮಧೇಯ ಸೆಷನ್ ಕುಕಿಯನ್ನು ಹೊಂದಿಸಲು ಬಿಡಿ.
2. **DevTools → Network** ತೆರೆಯಿರಿ, ಪುಟವನ್ನು ರಿಫ್ರೆಶ್ ಮಾಡಿ, ಮತ್ತು ಯಾವುದೇ `/api` ವಿನಂತಿಯನ್ನು ಕ್ಲಿಕ್ ಮಾಡಿ.
3. **Request Headers** ನಲ್ಲಿ, ಸಂಪೂರ್ಣ `Cookie` ಹೆಡರ್ ಮೌಲ್ಯವನ್ನು ನಕಲಿಸಿ.
4. OmniRoute ನಲ್ಲಿ, **Providers → Add Provider → NoTrack Web (Free)** ಗೆ ಹೋಗಿ.
5. ಕುಕಿ ಸ್ಟ್ರಿಂಗ್ ಅನ್ನು `apiKey` ಕ್ಷೇತ್ರದಲ್ಲಿ ಅಂಟಿಸಿ ಮತ್ತು **Save** ಮಾಡಿ.

OmniRoute ಅಂಟಿಸಿದ ಸ್ಟ್ರಿಂಗ್ನಿಂದ `uid`, `si_usr_id`, ಮತ್ತು `si_ses_id` ಅನ್ನು ಹೊರತೆಗೆಯುತ್ತದೆ ಮತ್ತು ಆ ಜೋಡಿಗಳನ್ನು ಮಾತ್ರ ಒಳಗೊಂಡ ಸ್ವಚ್ಛ `Cookie` ಹೆಡರ್ ಅನ್ನು ಮರುನಿರ್ಮಿಸುತ್ತದೆ — ಜೊತೆಗೆ, ಲಭ್ಯವಿದ್ದಾಗ `nt_session` (ಲಾಗಿನ್ ಮಾಡಿದ ಖಾತೆಗಳಿಗಾಗಿ ಹೊಂದಿಸಲಾದ `ntk_…` ಟೋಕನ್) ಅನ್ನು ಸೇರಿಸುತ್ತದೆ. ಈ ಮೂರರಲ್ಲಿ ಯಾವುದಾದರೂ ಇಲ್ಲದಿದ್ದರೆ, ಪರ್ಯಾಯ ಸ್ವರೂಪಗಳೊಂದಿಗೆ ಆಪರೇಟರ್ಗಳು ಪ್ರಯೋಗಿಸಲು ಸಾಧ್ಯವಾಗುವಂತೆ ಅಂಟಿಸಿದ ಮೂಲ ಸ್ಟ್ರಿಂಗ್ ಅನ್ನು ಬದಲಾಯಿಸದೆ ಫಾರ್ವರ್ಡ್ ಮಾಡಲಾಗುತ್ತದೆ.

### ಮಾದರಿ ಐಡಿಗಳು

| ಮಾದರಿ ಐಡಿ   | ಪ್ರದರ್ಶನ ಹೆಸರು | ಟಿಪ್ಪಣಿಗಳು                                                |
| ----------- | -------------- | --------------------------------------------------------- |
| `notrack-c` | NoTrack C      | ಡೀಫಾಲ್ಟ್ — ಅಪ್ಸ್ಟ್ರೀಮ್ ಡಿಸ್ಪ್ಯಾಚ್ ಮಾದರಿ `C`.              |
| `C`         | NoTrack C      | `notrack-c` ಗೆ ಅಲಿಯಾಸ್ (ಮೂಲ ಅಪ್ಸ್ಟ್ರೀಮ್ ಡಿಸ್ಪ್ಯಾಚ್ ಕೋಡ್). |
| `notrack`   | NoTrack C      | `notrack-c` ಗೆ ಅಲಿಯಾಸ್.                                   |
| `ntw`       | NoTrack C      | `notrack-c` ಗೆ ಸಂಕ್ಷಿಪ್ತ ಅಲಿಯಾಸ್.                         |

ಎಲ್ಲಾ ನಾಲ್ಕು ಮಾದರಿ ಐಡಿಗಳು ಅದೇ ಅಪ್ಸ್ಟ್ರೀಮ್ ಡಿಸ್ಪ್ಯಾಚ್ ಮಾದರಿಗೆ (`C`) ಮ್ಯಾಪ್ ಆಗುತ್ತವೆ.

### ವಿನಂತಿ ಆಯ್ಕೆಗಳು

ಎಕ್ಸಿಕ್ಯೂಟರ್ ವಿನಂತಿಯ ಬಾಡಿಯಲ್ಲಿ ಈ ಐಚ್ಛಿಕ ಕ್ಷೇತ್ರಗಳನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ:

| ಬಾಡಿ ಕ್ಷೇತ್ರ          | ಡೀಫಾಲ್ಟ್ | ಉದ್ದೇಶ                                                                                 |
| --------------------- | -------- | -------------------------------------------------------------------------------------- |
| `notrack_mode`        | `usual`  | ಡಿಸ್ಪ್ಯಾಚ್ ಮೋಡ್ (ಮುಕ್ತ-ಸ್ವರೂಪದ ಸ್ಟ್ರಿಂಗ್; ಅಪ್ಸ್ಟ್ರೀಮ್ `usual`, … ಅನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ) |
| `notrack_max_turns`   | `6`      | ಉತ್ತರಿಸುವ ಮೊದಲು ಅಪ್ಸ್ಟ್ರೀಮ್ ತೆಗೆದುಕೊಳ್ಳಬಹುದಾದ ಆಂತರಿಕ ಟರ್ನ್ಗಳ ಸಂಖ್ಯೆ.                   |
| `notrack_chat_id`     | `null`   | ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಅಪ್ಸ್ಟ್ರೀಮ್ ಚಾಟ್ ಅನ್ನು ಮುಂದುವರಿಸಿ (ಹೊಸ ಚಾಟ್ಗಾಗಿ ಬಿಟ್ಟುಬಿಡಿ).          |
| `notrack_attachments` | `[]`     | ಅಪ್ಸ್ಟ್ರೀಮ್ ಅಟ್ಯಾಚ್ಮೆಂಟ್ ಡಿಸ್ಕ್ರಿಪ್ಟರ್ಗಳ ಪಾಸ್-ಥ್ರೂ ಅರೇ.                                |
| `notrack_regenerate`  | `false`  | ಹಿಂದಿನ ಟರ್ನ್ಗೆ ಮರುರಚಿಸಿದ ಉತ್ತರವನ್ನು ವಿನಂತಿಸಲು `true` ಹೊಂದಿಸಿ.                          |

### ಸಾಮರ್ಥ್ಯಗಳು

- **ಸ್ಟ್ರೀಮಿಂಗ್ ಮತ್ತು ನಾನ್-ಸ್ಟ್ರೀಮಿಂಗ್** ಚಾಟ್ ಪೂರ್ಣಗೊಳಿಸುವಿಕೆಗಳು.
- **ಟೂಲ್ ಕಾಲಿಂಗ್** — ವಿನಂತಿಯಲ್ಲಿ `tools: [...]` ಹೊಂದಿಸಿ; ಎಕ್ಸಿಕ್ಯೂಟರ್ ಅವುಗಳನ್ನು ಟೂಲ್-ಕಾಲ್ ಎನ್ವಲಪ್ ಒಪ್ಪಂದಕ್ಕೆ ಸೀರಿಯಲೈಸ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ಮಾದರಿಯ ಪ್ರತಿಕ್ರಿಯೆಗಳನ್ನು ಮತ್ತೆ OpenAI `tool_calls` ಆಗಿ ಪಾರ್ಸ್ ಮಾಡುತ್ತದೆ.
- **`response_format`** — `json_object` ಮತ್ತು `json_schema` ಬೆಂಬಲಿತವಾಗಿವೆ. ಎಕ್ಸಿಕ್ಯೂಟರ್ ಮಾದರಿಯ ಉತ್ತರದಿಂದ ಮೊದಲ JSON ಆಬ್ಜೆಕ್ಟ್ ಅನ್ನು ಹೊರತೆಗೆದು, ಹಿಂದಿರುಗಿಸುವ ಮೊದಲು ಅದನ್ನು ಸ್ಟ್ರಿಂಗ್ ಆಗಿ ಪರಿವರ್ತಿಸುತ್ತದೆ.
- **ರೀಸನಿಂಗ್ ಸುಳಿವು** — ಅಪ್ಸ್ಟ್ರೀಮ್ `thinking` ಈವೆಂಟ್ ಕಳುಹಿಸಿದಾಗ ಎಕ್ಸಿಕ್ಯೂಟರ್ `reasoning` ಡೆಲ್ಟಾವನ್ನು ಹೊರಸೂಸುತ್ತದೆ.

### ಮಿತಿಗಳು

- ಅಪ್ಸ್ಟ್ರೀಮ್ ಅನಾಮಧೇಯ ಬಳಕೆಯ ಕೋಟಾಗಳನ್ನು ಜಾರಿಗೊಳಿಸುತ್ತದೆ — ಅವು ಮೀರಿದಾಗ, ಎಕ್ಸಿಕ್ಯೂಟರ್ ಬಳಕೆದಾರ ಸ್ನೇಹಿ ಸಂದೇಶದೊಂದಿಗೆ 429 ಅನ್ನು ಪ್ರದರ್ಶಿಸುತ್ತದೆ.
- ಎಲ್ಲಾ ಮಾದರಿ ಐಡಿಗಳು ಅದೇ ಅಪ್ಸ್ಟ್ರೀಮ್ ಡಿಸ್ಪ್ಯಾಚ್ ಮಾದರಿಗೆ ರಿಸಾಲ್ವ್ ಆಗುತ್ತವೆ; ಪ್ರತಿ ಮಾದರಿಗೆ ಪ್ರತ್ಯೇಕ ಸ್ವಿಚ್ ಇಲ್ಲ.
- ಎಕ್ಸಿಕ್ಯೂಟರ್ ಅಪ್ಸ್ಟ್ರೀಮ್ನ `/api/chats` ಎಂಡ್ಪಾಯಿಂಟ್ ಅನ್ನು ಕರೆ ಮಾಡುವುದಿಲ್ಲ, ಆದ್ದರಿಂದ ಚಾಟ್ ಇತಿಹಾಸ / ಸೆಷನ್ಗಳು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ನಿರ್ವಹಿಸಲ್ಪಡುವುದಿಲ್ಲ. ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಅಪ್ಸ್ಟ್ರೀಮ್ ಚಾಟ್ ಅನ್ನು ಮುಂದುವರಿಸಲು `notrack_chat_id` ಬಳಸಿ.

# ವೆಬ್ ಕುಕಿ ಪ್ರೊವೈಡರ್ಗಳು ಏನು ಮಾಡಬಹುದು ಮತ್ತು ಏನು ಮಾಡಲು ಸಾಧ್ಯವಿಲ್ಲ

ವೆಬ್ ಕುಕಿ ಪ್ರೊವೈಡರ್ಗಳು ವೆಬ್ಸೈಟ್ನ ಚಾಟ್ ಇಂಟರ್ಫೇಸ್ ಅನ್ನು ಮರುಬಳಕೆ ಮಾಡುತ್ತವೆ. ಅವು ಅಧಿಕೃತ API ಗಳಂತೆಯೇ **ಅದೇ ಸಾಮರ್ಥ್ಯಗಳನ್ನು ಒದಗಿಸುವುದಿಲ್ಲ**.

## ಬೆಂಬಲಿತವಾಗಿದೆ

- ನಿಮ್ಮ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಬ್ರೌಸರ್ ಸೆಷನ್ ಬಳಸಿ ದೃಢೀಕರಿಸುವುದು
- ನಿಮ್ಮ ಖಾತೆಯ ಮೂಲಕ ಲಭ್ಯವಿರುವ ಮಾದರಿಗಳನ್ನು ಪ್ರವೇಶಿಸುವುದು
- ಚಾಟ್ ಪ್ರತಿಕ್ರಿಯೆಗಳನ್ನು ಸ್ಟ್ರೀಮ್ ಮಾಡುವುದು
- API ಕೀ ಅಗತ್ಯವಿಲ್ಲ

## ಬೆಂಬಲಿತವಾಗಿಲ್ಲ

- ಫಂಕ್ಷನ್ ಕಾಲಿಂಗ್
- ಟೂಲ್ ಕಾಲಿಂಗ್
- ಸ್ವಯಂಚಾಲಿತ ಫೈಲ್ ಎಡಿಟಿಂಗ್
- ಏಜೆಂಟ್ ಆಧಾರಿತ IDE ವರ್ಕ್ಫ್ಲೋಗಳು
- API-ಮಾತ್ರ ವೈಶಿಷ್ಟ್ಯಗಳು

ಇದು ನಿರೀಕ್ಷಿತ ನಡವಳಿಕೆಯಾಗಿದ್ದು, **ಬಗ್ ಅಲ್ಲ**.

ನಿಮಗೆ ಟೂಲ್ ಎಕ್ಸಿಕ್ಯೂಷನ್, ಸ್ವಯಂಚಾಲಿತ ಫೈಲ್ ಎಡಿಟಿಂಗ್ ಅಥವಾ ಇತರ ಏಜೆಂಟ್ ವರ್ಕ್ಫ್ಲೋಗಳು ಅಗತ್ಯವಿದ್ದರೆ, Web Cookie ಪೂರೈಕೆದಾರರ ಬದಲಿಗೆ **API-key ಪೂರೈಕೆದಾರರನ್ನು** ಬಳಸಿ.

# ಮೌಲ್ಯೀಕರಣದ ಮಿತಿ

ಯಶಸ್ವಿಯಾದ **Test Connection** ಅಥವಾ ಕುಕೀ ಮೌಲ್ಯೀಕರಣವು ಒದಗಿಸಿದ ರುಜುವಾತುಗಳು ನಿರೀಕ್ಷಿತ ಸ್ವರೂಪದಲ್ಲಿರುವಂತೆ ಕಾಣುತ್ತವೆ ಎಂಬುದನ್ನು ಮಾತ್ರ ಪರಿಶೀಲಿಸುತ್ತದೆ.

Issue #7857 ಪರಿಹಾರವಾಗುವವರೆಗೆ, ಯಶಸ್ವಿ ಮೌಲ್ಯೀಕರಣವು ಪೂರೈಕೆದಾರರು ಯಶಸ್ವಿಯಾಗಿ ದೃಢೀಕರಿಸುತ್ತಾರೆ ಎಂಬುದನ್ನು **ಖಾತರಿಪಡಿಸುವುದಿಲ್ಲ**.

ದೃಢೀಕರಣವು ಇನ್ನೂ ವಿಫಲವಾದರೆ, ಬ್ರೌಸರ್ ಕುಕೀ ಸಂಗ್ರಹದಿಂದ ಅಲ್ಲದೆ ಸಕ್ರಿಯ ನೆಟ್ವರ್ಕ್ ವಿನಂತಿಯಿಂದ ರುಜುವಾತುಗಳನ್ನು ನಕಲಿಸಿದ್ದೀರಿ ಎಂಬುದನ್ನು ಪರಿಶೀಲಿಸಿ.

# ಸಮಸ್ಯೆ ನಿವಾರಣೆ

## ದೃಢೀಕರಣ ವಿಫಲವಾಗುತ್ತದೆ

ರುಜುವಾತುಗಳನ್ನು ಇಲ್ಲಿಂದ ನಕಲಿಸಲಾಗಿದೆ ಎಂಬುದನ್ನು ಪರಿಶೀಲಿಸಿ:

```
Network
→ Request Headers
→ Cookie
```

ಮತ್ತು ಇಲ್ಲಿಂದ **ಅಲ್ಲ**:

```
Application
→ Cookies
```

## ಕುಕೀ ಬ್ರೌಸರ್ನಲ್ಲಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ, ಆದರೆ OmniRoute ನಲ್ಲಿ ಕಾರ್ಯನಿರ್ವಹಿಸುವುದಿಲ್ಲ

ಕೆಲವು ಪೂರೈಕೆದಾರರು ದೃಢೀಕೃತ ವಿನಂತಿಗಳ ಸಮಯದಲ್ಲಿ ಮಾತ್ರ ಕಳುಹಿಸಲಾಗುವ ಕುಕೀಗಳನ್ನು ಒಳಗೊಂಡಿರುತ್ತಾರೆ.

ಸಂಭಾಷಣೆಯನ್ನು ಯಶಸ್ವಿಯಾಗಿ ತೆರೆದ ನಂತರ, ಹೊಸ ನೆಟ್ವರ್ಕ್ ವಿನಂತಿಯಿಂದ ರುಜುವಾತುಗಳನ್ನು ಮತ್ತೆ ನಕಲಿಸಿ.

---

## ಸೆಷನ್ ಅವಧಿ ಮುಗಿದಿದೆ

Web Cookie ಪೂರೈಕೆದಾರರು ನಿಮ್ಮ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಬ್ರೌಸರ್ ಸೆಷನ್ ಅನ್ನು ಬಳಸುತ್ತಾರೆ.

ನಿಮ್ಮ ಬ್ರೌಸರ್ ಸೆಷನ್ ಅವಧಿ ಮುಗಿದರೆ ಅಥವಾ ನೀವು ಸೈನ್ ಔಟ್ ಮಾಡಿದರೆ, ಹೊಸ ರುಜುವಾತುಗಳ ಗುಚ್ಛವನ್ನು ನಕಲಿಸಬೇಕು. ಬೆಂಬಲಿತ ವೆಬ್ ಪೂರೈಕೆದಾರರಿಗೆ ಕುಕೀ ನವೀಕರಣವನ್ನು ಸ್ವಯಂಚಾಲಿತಗೊಳಿಸಲು, ಸಹಾಯಕ ಸಾಧನವಾದ [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md) ಅನ್ನು ನೋಡಿ.

Issue #7857 ಪರಿಹಾರವಾಗುವವರೆಗೆ, ಮೌಲ್ಯೀಕರಣದಲ್ಲಿ ಉತ್ತೀರ್ಣವಾಗುವುದು ದೃಢೀಕರಣ ವಿನಂತಿ ಯಶಸ್ವಿಯಾಗುತ್ತದೆ ಎಂಬುದನ್ನು ಖಾತರಿಪಡಿಸುವುದಿಲ್ಲ.

ಮುಂದಿನ ಸಮಸ್ಯೆ ನಿವಾರಣೆಗೆ ಮುನ್ನ, ಹೊಸ ದೃಢೀಕೃತ ವಿನಂತಿಯಿಂದ ನಿಮ್ಮ ರುಜುವಾತುಗಳನ್ನು ಮತ್ತೆ ನಕಲಿಸಿ.

# ಉತ್ತಮ ಅಭ್ಯಾಸಗಳು

- ಹೊಸ ದೃಢೀಕೃತ ವಿನಂತಿಯಿಂದ ರುಜುವಾತುಗಳನ್ನು ನಕಲಿಸಿ.
- ಹಳೆಯ ಕುಕೀಗಳನ್ನು ಮರುಬಳಕೆ ಮಾಡುವುದನ್ನು ತಪ್ಪಿಸಿ.
- Web Cookie ಪೂರೈಕೆದಾರರನ್ನು ಬಳಸುವಾಗ ನಿಮ್ಮ ಬ್ರೌಸರ್ ಸೆಷನ್ ಅನ್ನು ಸಕ್ರಿಯವಾಗಿರಿಸಿ.
- ನಕಲಿಸಿದ ಕುಕೀಗಳನ್ನು ಸೂಕ್ಷ್ಮ ರುಜುವಾತುಗಳಂತೆ ಪರಿಗಣಿಸಿ.
- ನಿಮಗೆ ಫಂಕ್ಷನ್ ಕಾಲಿಂಗ್ ಅಥವಾ ಏಜೆಂಟ್ ವರ್ಕ್ಫ್ಲೋಗಳು ಅಗತ್ಯವಿದ್ದಾಗ API-key ಪೂರೈಕೆದಾರರನ್ನು ಬಳಸಿ.
