ಈ ಡಾಕ್ಯುಮೆಂಟ್
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854) ಗಾಗಿ ಅನುಷ್ಠಾನ ನಿರ್ಧಾರವನ್ನು ದಾಖಲಿಸುತ್ತದೆ. ಸಾರ್ವಜನಿಕ ಉತ್ಪನ್ನಗಳನ್ನು ನಾಲ್ಕು ಪೂರೈಕೆದಾರ ಕುಟುಂಬಗಳಾಗಿ ಪ್ರತಿನಿಧಿಸಲಾಗಿದೆ. ಪ್ರದೇಶವು ಸಂಪರ್ಕ ಡೇಟಾ ಆಗಿದ್ದು, ಪ್ರತ್ಯೇಕ ಉತ್ಪನ್ನವಲ್ಲ.

## ನಿರ್ಧಾರ

| ಪೂರೈಕೆದಾರ ಕುಟುಂಬ                            | OmniRoute ID            | ಜಾಗತಿಕ ಪ್ರದೇಶ | ಚೀನಾ ಪ್ರದೇಶ |
| ------------------------------------------- | ----------------------- | ------------- | ----------- |
| Alibaba Cloud Model Studio (ಬಳಕೆಯಂತೆ ಪಾವತಿ) | `alibaba`               | ಸಿಂಗಾಪುರ      | ಬೀಜಿಂಗ್     |
| Alibaba Cloud Token Plan                    | `bailian-coding-plan`   | ಸಿಂಗಾಪುರ      | ಬೀಜಿಂಗ್     |
| Qwen Cloud (ಬಳಕೆಯಂತೆ ಪಾವತಿ)                 | `qwen-cloud`            | ಜಾಗತಿಕ        | ಬೀಜಿಂಗ್     |
| Qwen Cloud Token Plan                       | `qwen-cloud-token-plan` | ಸಿಂಗಾಪುರ      | ಬೀಜಿಂಗ್     |

ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ `alibaba-cn` ID, ಉಳಿಸಿದ ಸಂಪರ್ಕಗಳು, ಮಾದರಿ ಮಾರ್ಗಗಳು, ಕಾಂಬೊಗಳು ಮತ್ತು ಹಿಂದಿನ ಬಳಕೆಗಾಗಿ ರನ್ಟೈಮ್ ಹೊಂದಾಣಿಕೆ ಅಲಿಯಾಸ್ ಆಗಿ ಉಳಿಯುತ್ತದೆ. ಅದರ ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಕಾರ್ಡ್ ಅನ್ನು `alibaba` ಒಳಗೆ ವಿಲೀನಗೊಳಿಸಲಾಗಿದೆ; ಯಾವುದೇ ಡೇಟಾಬೇಸ್ ಮರುಬರಹದ ಅಗತ್ಯವಿಲ್ಲ.

Qwen Cloud ಬಳಕೆಯಂತೆ ಪಾವತಿ ಮತ್ತು Alibaba Cloud Model Studio ಪ್ರಸ್ತುತ DashScope-ಹೊಂದಾಣಿಕೆಯ ರನ್ಟೈಮ್ ಹೋಸ್ಟ್ಗಳನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತವೆ, ಆದರೆ ಬಳಕೆದಾರರು ವಿಭಿನ್ನ ಉತ್ಪನ್ನ ಮೇಲ್ಮೈಗಳ ಮೂಲಕ ಕೀಲಿಗಳನ್ನು ಪಡೆದು ಖಾತೆಗಳನ್ನು ನಿರ್ವಹಿಸುವುದರಿಂದ ಅವು ಪ್ರತ್ಯೇಕ ಪೂರೈಕೆದಾರ ಗುರುತುಗಳಾಗಿಯೇ ಉಳಿಯುತ್ತವೆ. Alibaba ಮತ್ತು Qwen Cloud Token Plan ಉತ್ಪನ್ನಗಳು ವಿಭಿನ್ನ ಎಂಡ್ಪಾಯಿಂಟ್ ಕುಟುಂಬಗಳನ್ನು ಬಳಸುವುದರಿಂದ, ಎಲ್ಲಾ ನಾಲ್ಕು ಉತ್ಪನ್ನಗಳು ಪ್ರತ್ಯೇಕ ಪೂರೈಕೆದಾರ ID ಗಳಾಗಿಯೇ ಉಳಿಯುತ್ತವೆ.

## ಎಂಡ್ಪಾಯಿಂಟ್ ಮ್ಯಾಟ್ರಿಕ್ಸ್

| ಪೂರೈಕೆದಾರ ಕುಟುಂಬ        | `global-sg`                                                              | `china-beijing`                                                      | ವೈರ್ ಸ್ವರೂಪ |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ----------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI      |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic   |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI      |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI      |

API ಕೀ ಮತ್ತು ಎಂಡ್ಪಾಯಿಂಟ್ ಒಂದೇ ಉತ್ಪನ್ನ ಮತ್ತು ಪ್ರದೇಶಕ್ಕೆ ಸೇರಿರಬೇಕು. ಪ್ರದೇಶವನ್ನು ಆಯ್ಕೆ ಮಾಡುವುದರಿಂದ ಮೌಲ್ಯೀಕರಣ ಮತ್ತು ಸಾಮಾನ್ಯ ವಿನಂತಿಗಳು ಬಳಸುವ ಪೂರ್ವನಿಗದಿತ ಎಂಡ್ಪಾಯಿಂಟ್ ಬದಲಾಗುತ್ತದೆ.

## ಸಂಪರ್ಕ ಒಪ್ಪಂದ

ಹೊಸ ಸಂಪರ್ಕಗಳು ಸ್ಥಿರ ಪ್ರದೇಶ ಕೀಲಿಯನ್ನು `providerSpecificData` ನಲ್ಲಿ ಸಂಗ್ರಹಿಸುತ್ತವೆ:

```json
{
  "region": "global-sg"
}
```

ಅನುಮತಿಸಲಾದ ಮೌಲ್ಯಗಳು `global-sg` ಮತ್ತು `china-beijing`. ಎಂಡ್ಪಾಯಿಂಟ್ ಅನ್ನು ಪೂರೈಕೆದಾರ ID ಮತ್ತು ಪ್ರದೇಶದಿಂದ ಕೇಂದ್ರೀಯವಾಗಿ ಪಡೆಯಲಾಗುತ್ತದೆ. ಪೂರ್ವನಿಗದಿತವಲ್ಲದ `providerSpecificData.baseUrl` ಸ್ಪಷ್ಟ ಆಪರೇಟರ್ ಅತಿಕ್ರಮಣವಾಗಿ ಉಳಿದು ಆದ್ಯತೆ ಪಡೆಯುತ್ತದೆ, ಆದರೆ ಹಿಂದೆ ಉಳಿಸಲಾದ ಪೂರ್ವನಿಗದಿತ URL ಗಳನ್ನು ಮತ್ತೆ ಪ್ರಾದೇಶಿಕ ಮ್ಯಾಟ್ರಿಕ್ಸ್ಗೆ ಸಾಮಾನ್ಯೀಕರಿಸಲಾಗುತ್ತದೆ.

ಇದು ಸಂಪರ್ಕ ಸ್ಕೀಮಾವನ್ನು ವಿಸ್ತರಿಸಬಹುದಾದಂತೆ ಇರಿಸುತ್ತದೆ: ಮತ್ತೊಂದು ಪೂರೈಕೆದಾರ ಕಾರ್ಡ್ ರಚಿಸದೆ ಅಥವಾ ಉಳಿಸಿದ ಪೂರೈಕೆದಾರ ID ಗಳನ್ನು ಬದಲಾಯಿಸದೆ ರಿಸಾಲ್ವರ್ಗೆ ಮತ್ತೊಂದು ಪ್ರದೇಶವನ್ನು ಸೇರಿಸಬಹುದು.

## ಹೊಂದಾಣಿಕೆ ಮತ್ತು ಹಂತ ಹಂತದ ಬಿಡುಗಡೆ

1. ಪ್ರಾದೇಶಿಕ ಎಂಡ್ಪಾಯಿಂಟ್ ಪರಿಹಾರಕವನ್ನು ಸೇರಿಸಿ ಮತ್ತು ಪ್ರಸ್ತುತ ಜಾಗತಿಕ ಡೀಫಾಲ್ಟ್ಗಳನ್ನು ಉಳಿಸಿಕೊಳ್ಳಿ.
2. `alibaba`, ಅದರ `alibaba-cn` ಹೊಂದಾಣಿಕೆ ID ಮತ್ತು `qwen-cloud` ಗಾಗಿ ಲೈವ್ ಪ್ರಾದೇಶಿಕ DashScope `/models` ಅನ್ವೇಷಣೆಯನ್ನು ಬಳಸಿ. ಸಾಮಾನ್ಯ ಎಂಡ್ಪಾಯಿಂಟ್ ಚಿತ್ರ, ವೀಡಿಯೊ, ಆಡಿಯೊ, ಎಂಬೆಡಿಂಗ್ ಮತ್ತು ಇತರ ಚಾಟ್ ಅಲ್ಲದ ಮಾದರಿಗಳನ್ನೂ ಹಿಂದಿರುಗಿಸುವುದರಿಂದ, ಅವುಗಳ ಪ್ರತಿಕ್ರಿಯೆಗಳು ಮೊದಲು ಒಂದು ಪಠ್ಯ-ರಚನೆ ಫಿಲ್ಟರ್ ಮೂಲಕ ಹಾದುಹೋಗುತ್ತವೆ. ನಂತರ `qwen-cloud`, ಅದರ ಪೂರೈಕೆದಾರ ರಿಜಿಸ್ಟ್ರಿಯಲ್ಲಿ ಘೋಷಿಸಲಾದ ನಿರ್ವಹಿತ ಅನುಮತಿ ಪಟ್ಟಿಯನ್ನು ಅನ್ವಯಿಸುತ್ತದೆ. Alibaba Model Studio ಮತ್ತು Qwen Cloud ಪ್ರಸ್ತುತ ಒಂದೇ ರನ್ಟೈಮ್ ಹೋಸ್ಟ್ಗಳನ್ನು ಹಂಚಿಕೊಂಡಿದ್ದರೂ, ಪ್ರತ್ಯೇಕವಾಗಿ ಕ್ಯೂರೇಟ್ ಮಾಡಲಾದ ಕ್ಯಾಟಲಾಗ್ಗಳನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತವೆ.
3. ಪ್ರಸ್ತುತ Token Plan ಪಠ್ಯ-ಮಾದರಿ ಅನುಮತಿ ಪಟ್ಟಿಯೊಂದಿಗೆ `qwen-cloud-token-plan` ಅನ್ನು ನೋಂದಾಯಿಸಿ.
4. ಸಂಪರ್ಕವನ್ನು ಸೇರಿಸುವ/ಸಂಪಾದಿಸುವ ಡೈಲಾಗ್ಗಳಿಗೆ ಟೈಪ್ ಮಾಡಿದ ಪ್ರದೇಶ ಆಯ್ಕೆಕಾರಕವನ್ನು ಸೇರಿಸಿ.
5. ನಕಲಿ `alibaba-cn` ಕಾರ್ಡ್ ಅನ್ನು ಮರೆಮಾಡಿ ಮತ್ತು ಅದರ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಸಂಪರ್ಕಗಳನ್ನು `alibaba` ಪೂರೈಕೆದಾರ ಪುಟದಲ್ಲಿ ಸೇರಿಸಿ.
6. ಸುಧಾರಿತ ಮತ್ತು ಕಾರ್ಯಸ್ಥಳ-ನಿರ್ದಿಷ್ಟ ನಿಯೋಜನೆಗಳಿಗಾಗಿ ಕಸ್ಟಮ್ ಎಂಡ್ಪಾಯಿಂಟ್ ಓವರ್ರೈಡ್ಗಳನ್ನು ಲಭ್ಯವಾಗಿರಿಸಿ.

Token Plan ಮಾಧ್ಯಮ ಮಾದರಿಗಳು ಸಮರ್ಪಿತ ಎಂಡ್ಪಾಯಿಂಟ್ಗಳನ್ನು ಬಳಸುವುದರಿಂದ ಅವು ಚಾಟ್ ಕ್ಯಾಟಲಾಗ್ನ ಹೊರಗೇ ಉಳಿಯುತ್ತವೆ.
`wan2.7-image` ಮತ್ತು `wan2.7-image-pro` ಅನ್ನು `open-sse/config/imageRegistry.ts` ನಲ್ಲಿ ನೋಂದಾಯಿಸಲಾಗಿದೆ;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, ಮತ್ತು `happyhorse-1.1-r2v` ಅನ್ನು
`open-sse/config/videoRegistry.ts` ನಲ್ಲಿ ನೋಂದಾಯಿಸಲಾಗಿದೆ. ಎರಡೂ ರಿಜಿಸ್ಟ್ರಿಗಳು `qwen-cloud-token-plan` ಸಂಪರ್ಕ
ಗುರುತನ್ನು ಮತ್ತು ಅದರ ಪ್ರದೇಶ-ನಿರ್ದಿಷ್ಟ ರುಜುವಾತುಗಳನ್ನು ಮರುಬಳಕೆ ಮಾಡುತ್ತವೆ.

ಸಾಮಾನ್ಯ Qwen Cloud, `qwen-cloud` ಗುರುತಿನ ಅಡಿಯಲ್ಲಿ ಪ್ರತ್ಯೇಕ ಬಳಕೆಯಷ್ಟಕ್ಕೆ ಪಾವತಿಸುವ ಚಿತ್ರ ಮತ್ತು ವೀಡಿಯೊ ಕ್ಯಾಟಲಾಗ್ಗಳನ್ನು ಹೊಂದಿದೆ. ಅದರ ಚಿತ್ರ ಮಾದರಿಗಳು `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03`, ಮತ್ತು `z-image-turbo`. ಅದರ ವೀಡಿಯೊ
ಮಾದರಿಗಳು `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12`, ಮತ್ತು
`wan2.7-videoedit`. ಈ ಮಾದರಿಗಳು ಸಾಮಾನ್ಯ `qwen-cloud` ಸಂಪರ್ಕ ಮತ್ತು ಪ್ರಾದೇಶಿಕ
DashScope ಮಾಧ್ಯಮ ಎಂಡ್ಪಾಯಿಂಟ್ ಅನ್ನು ಮಾತ್ರ ಮರುಬಳಕೆ ಮಾಡುತ್ತವೆ. Token Plan ಮತ್ತು ಬಳಕೆಯಷ್ಟಕ್ಕೆ ಪಾವತಿಸುವ ರಿಜಿಸ್ಟ್ರಿಗಳು ಪರಸ್ಪರರ ಮಾದರಿ ಪಟ್ಟಿಗಳನ್ನು ಆನುವಂಶಿಕವಾಗಿ ಪಡೆಯುವುದಿಲ್ಲ ಅಥವಾ ವಿಲೀನಗೊಳಿಸುವುದಿಲ್ಲ.

`bailian-coding-plan` ಗುರುತು ತನ್ನದೇ ಆದ ಮಾಧ್ಯಮ ಅನುಮತಿ ಪಟ್ಟಿಗಳನ್ನೂ ಹೊಂದಿದೆ:
ಚಿತ್ರ ರಚನೆಗಾಗಿ `wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0`, ಮತ್ತು `qwen-image-2.0-pro`,
ಜೊತೆಗೆ ವೀಡಿಯೊ ರಚನೆಗಾಗಿ
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, ಮತ್ತು `happyhorse-1.1-r2v`.
ಇದು Bailian Coding Plan ಸಂಪರ್ಕ ಮತ್ತು ಪ್ರಾದೇಶಿಕ Coding Plan ಎಂಡ್ಪಾಯಿಂಟ್ ಅನ್ನು ಮಾತ್ರ ಬಳಸುತ್ತದೆ.
ಅದರ ಚಿತ್ರ ಮತ್ತು ವೀಡಿಯೊ ರಿಜಿಸ್ಟ್ರಿಗಳು ಯಾವುದೇ Qwen Cloud ಪೂರೈಕೆದಾರದಿಂದ ಆನುವಂಶಿಕವಾಗಿ ಪಡೆಯುವುದಿಲ್ಲ ಅಥವಾ ಅವುಗಳೊಂದಿಗೆ ವಿಲೀನಗೊಳ್ಳುವುದಿಲ್ಲ.

ಸಾಮಾನ್ಯ `alibaba` ಗುರುತು ಪ್ರತ್ಯೇಕ ಚಿತ್ರ ಮತ್ತು ವೀಡಿಯೊ ಅನುಮತಿ ಪಟ್ಟಿಗಳನ್ನು ಹೊಂದಿದೆ. ಅದರ ಚಿತ್ರ ಮಾದರಿಗಳು
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo`, ಮತ್ತು `wan2.6-t2i`. ಅದಕ್ಕೆ ಸೇರಿಸಲಾದ ವೀಡಿಯೊ ಮಾದರಿಗಳು `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12`, ಮತ್ತು `wan2.7-videoedit`. ಈ ಮಾದರಿಗಳು Alibaba Model Studio
ಸಂಪರ್ಕ ಮತ್ತು ಅದರಲ್ಲಿ ಆಯ್ಕೆಮಾಡಿದ ಪ್ರಾದೇಶಿಕ ಮಾಧ್ಯಮ ಎಂಡ್ಪಾಯಿಂಟ್ ಅನ್ನು ಮಾತ್ರ ಬಳಸುತ್ತವೆ; ಅವುಗಳನ್ನು ಯಾವುದೇ Coding Plan ಅಥವಾ Qwen
Cloud ರಿಜಿಸ್ಟ್ರಿಗೆ ಸೇರಿಸಲಾಗುವುದಿಲ್ಲ.

Qwen Cloud Token Plan ಚಾಟ್ ಕ್ಯಾಟಲಾಗ್ Individual ಯೋಜನೆಯ ನಿಖರ-ಸ್ಟ್ರಿಂಗ್ ಪಠ್ಯ ಅನುಮತಿ ಪಟ್ಟಿಯನ್ನು ಅನುಸರಿಸುತ್ತದೆ:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2`, ಮತ್ತು
`deepseek-v4-pro`. Wan ಮತ್ತು HappyHorse ನಮೂದುಗಳು ಪ್ರತ್ಯೇಕ ಚಿತ್ರ/ವೀಡಿಯೊ ರಚನೆ API ಗಳಿಗೆ ಸೇರಿವೆ.

Alibaba Token Plan ತನ್ನ Anthropic-ಹೊಂದಾಣಿಕೆಯ ಎಂಡ್ಪಾಯಿಂಟ್ ಮೂಲಕ ಅದೇ ಆರು ಪ್ರಸ್ತುತ ಪಠ್ಯ-ರಚನೆ ಮಾದರಿ ID ಗಳನ್ನು ಒದಗಿಸುತ್ತದೆ. ಅದರ Singapore ಆಯ್ಕೆಯು ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ `global-sg` ಪ್ರದೇಶ ಕೀಲಿಯನ್ನು ಸಂಗ್ರಹಿಸುತ್ತದೆ;
ಪ್ರದೇಶವನ್ನು Global ಎಂದು ಕರೆಯುವ ಪೂರೈಕೆದಾರ ಕುಟುಂಬಗಳಿಗೆ ಹೋಲಿಸಿದರೆ ಬಳಕೆದಾರರಿಗೆ ಕಾಣಿಸುವ ಲೇಬಲ್ ಮಾತ್ರ ಭಿನ್ನವಾಗಿರುತ್ತದೆ.

ಸಾಮಾನ್ಯ Qwen Cloud ಚಾಟ್ ಕ್ಯಾಟಲಾಗ್ ಅನ್ನು ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ಸಂಪೂರ್ಣ ಲೈವ್ ಪಠ್ಯ ಪ್ರತಿಕ್ರಿಯೆಗಿಂತ ಸೀಮಿತಗೊಳಿಸಲಾಗಿದೆ. ಅದರ
ನಿರ್ವಹಿತ ಅನುಮತಿ ಪಟ್ಟಿ `open-sse/config/providers/registry/qwen-cloud/index.ts` ನಲ್ಲಿ ಇದೆ; ಲೈವ್
ಅನ್ವೇಷಣೆಯು ಅಪ್ಸ್ಟ್ರೀಮ್ ಪ್ರತಿಕ್ರಿಯೆ ಮತ್ತು ಆ ರಿಜಿಸ್ಟ್ರಿ ಪಟ್ಟಿ ಎರಡರಲ್ಲೂ ಇರುವ ID ಗಳನ್ನು ಮಾತ್ರ ಹಿಂದಿರುಗಿಸುತ್ತದೆ.

Alibaba Model Studio ತನ್ನ ಸ್ವತಂತ್ರವಾಗಿ ನಿರ್ವಹಿಸಲಾದ
`open-sse/config/providers/registry/alibaba/index.ts` ಅನುಮತಿ ಪಟ್ಟಿಯೊಂದಿಗೆ ಇದೇ ಲೈವ್-ಛೇದನ ನಿಯಮವನ್ನು ಅನುಸರಿಸುತ್ತದೆ. `alibaba-cn` ಹೊಂದಾಣಿಕೆ
ಪೂರೈಕೆದಾರವು Beijing ಎಂಡ್ಪಾಯಿಂಟ್ಗೆ ವಿರುದ್ಧವಾಗಿ ಅನ್ವೇಷಣೆಯನ್ನು ಪರಿಹರಿಸುವಾಗ ಆ ಕ್ಯಾಟಲಾಗ್ ಅನ್ನು ಮರುಬಳಕೆ ಮಾಡುತ್ತದೆ.
