`chatgpt-web-codex` (`cgpt-codex` ಎಂಬ ಉಪನಾಮ) ದೃಢೀಕೃತ ChatGPT ಬ್ರೌಸರ್ ಸೆಷನ್ ಮೂಲಕ Codex Responses ಟರ್ನ್ಗಳನ್ನು ಸಂಪರ್ಕಿಸುತ್ತದೆ. ಇದು ನಿವೃತ್ತಗೊಳಿಸಲಾದ ಸಾಮಾನ್ಯ `chatgpt-web` ಪ್ರೊವೈಡರ್ನಿಂದ ಸ್ವತಂತ್ರವಾಗಿದೆ ಮತ್ತು `open-sse/vendor/codex-chatgpt-web/` ಅಡಿಯಲ್ಲಿರುವ MIT ಸೂಚನೆಯ ಅನುಷ್ಠಾನವನ್ನು ಬಳಸುತ್ತದೆ; ಇದನ್ನು ಅಪ್ಸ್ಟ್ರೀಮ್ v4.0.7 ಕಮಿಟ್ `b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494` ಮೂಲಕ ನವೀಕರಿಸಲಾಗಿದೆ.

## ಸಾಮಾನ್ಯ ಪ್ರೊವೈಡರ್ ನಿವೃತ್ತಿ

ಹಿಂದಿನ ಸಾಮಾನ್ಯ ಪ್ರೊವೈಡರ್ IDಗಳಾದ `chatgpt-web` ಮತ್ತು `cgpt-web` ಇನ್ನು ಮುಂದೆ ವಿತರಿಸಲ್ಪಡುವುದಿಲ್ಲ, ಏಕೆಂದರೆ ಅವುಗಳ pre-key/proof-of-work ಅನುಷ್ಠಾನದ ಮೂಲವನ್ನು ದೃಢೀಕರಿಸಲಾಗಲಿಲ್ಲ. ಸ್ಲ್ಯಾಶ್ ಪೂರ್ವಪ್ರತ್ಯಯ ಹೊಂದಿರುವ ಮಾಡೆಲ್ IDಗಳು ಮತ್ತು ಉಳಿಸಲಾದ ಉಪನಾಮಗಳನ್ನು ಒಳಗೊಂಡಂತೆ, ಈ ಎರಡರಲ್ಲಿ ಯಾವುದಾದರೂ IDಗೆ ಮಾಡುವ ಸ್ಪಷ್ಟ ವಿನಂತಿಗಳು ಯಾವುದೇ ಅಪ್ಸ್ಟ್ರೀಮ್ ವಿನಂತಿಗೂ ಮೊದಲು HTTP `410` ಮತ್ತು **PROVIDER_RETIRED** ಕೋಡ್ನೊಂದಿಗೆ ಸುರಕ್ಷಿತವಾಗಿ ವಿಫಲಗೊಳ್ಳುತ್ತವೆ.

ಮೈಗ್ರೇಶನ್ `168_retire_chatgpt_web.sql` ಹೊಂದಿಕೆಯಾಗುವ ಪ್ರೊವೈಡರ್ ಸಂಪರ್ಕಗಳನ್ನು ಟೂಂಬ್ಸ್ಟೋನ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ಅವುಗಳ ಸಕ್ರಿಯ ಸೆಷನ್ ಲೀಸ್ಗಳನ್ನು ಅಮಾನ್ಯಗೊಳಿಸುತ್ತದೆ. ಇದು ಸಂಪರ್ಕ ಇತಿಹಾಸ ಮತ್ತು API-ಕೀ ಅನುಮತಿ ಪಟ್ಟಿಗಳನ್ನು ಉಳಿಸುತ್ತದೆ; ಬದಲಿ ಪ್ರವೇಶವನ್ನು ಅನುಮತಿ ಪಟ್ಟಿಗೆ ಸೇರಿಸುವುದಿಲ್ಲ. ಈ ನಿವೃತ್ತಿಯು Codex ಪ್ರೊವೈಡರ್ ಮತ್ತು ಅದರ ಸಂಪರ್ಕಗಳಿಗೆ ಅನ್ವಯಿಸುವುದಿಲ್ಲ.

## ಪೂರ್ವಾಪೇಕ್ಷಿತಗಳು

- ಸೈನ್ ಇನ್ ಮಾಡಲಾದ ChatGPT ಸೆಷನ್ನ ಸಂಪೂರ್ಣ Cookie ಹೆಡರ್;
- npm, systemd ಮತ್ತು PM2 ಸ್ಥಾಪನೆಗಳಿಗಾಗಿ Chrome ಅಥವಾ Chromium ಜೊತೆಗೆ ಗ್ರಾಫಿಕಲ್ ಸೆಷನ್ ಅಥವಾ Xvfb ಡಿಸ್ಪ್ಲೇ;
- Docker `web` ಪ್ರೊಫೈಲ್ನೊಂದಿಗೆ, `docker-compose.yml` ನಲ್ಲಿರುವ ಆಂತರಿಕ Chromium ಸೇವೆ;
- ಸ್ಥಳೀಯ Codex ಪರಿಕರಗಳಿಗಾಗಿ OpenAI `tunnel-client` v0.0.13 ಮತ್ತು ChatGPT ಕಸ್ಟಮ್ ಕನೆಕ್ಟರ್.

ಟೂಲ್ ಟರ್ನ್ಗಳಿಗೆ ಮಾತ್ರ ಟನಲ್ ಅಗತ್ಯವಿದೆ. ಟನಲ್ ಮತ್ತು ಕನೆಕ್ಟರ್ ಅನ್ನು ಸಂರಚಿಸಿದಾಗ, `pro` ಸೇರಿದಂತೆ ಪಟ್ಟಿ ಮಾಡಲಾದ ಪ್ರತಿಯೊಂದು ರೂಟ್ ಕೂಡ ಅದೇ ಟರ್ನ್ಗೆ ಬದ್ಧವಾದ ಸ್ಥಳೀಯ ಟೂಲ್ ಸಾಮರ್ಥ್ಯವನ್ನು ಬಳಸಬಹುದು.

## ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಸೆಟಪ್

1. **ChatGPT Web (Codex)** ಪ್ರೊವೈಡರ್ ತೆರೆಯಿರಿ ಮತ್ತು ಸಂಪರ್ಕವೊಂದನ್ನು ಸೇರಿಸಿ.
2. ಸಂಪೂರ್ಣ ChatGPT Cookie ಹೆಡರ್, ಟನಲ್ ID, ರನ್ಟೈಮ್ ಕೀ ಮತ್ತು ಕಸ್ಟಮ್ ಕನೆಕ್ಟರ್ ಹೆಸರನ್ನು ಅಂಟಿಸಿ. ಟೂಲ್ ಸಾಮರ್ಥ್ಯವುಳ್ಳ ಹೊಸ ಸೆಟಪ್ಗಳು ನಿಖರವಾಗಿ `OmniRoute Codex v2` ಎಂದು ಹೆಸರಿಸಲಾದ ಹೊಸದಾಗಿ ರಚಿಸಿದ ಕನೆಕ್ಟರ್ ಅನ್ನು ಬಳಸಬೇಕು; ಇದರಲ್ಲಿ Authentication ಅನ್ನು None ಆಗಿ ಮತ್ತು Permissions ಅನ್ನು Allow all actions ಆಗಿ ಹೊಂದಿಸಬೇಕು.
3. ಸಂಪರ್ಕ ಪರಿಶೀಲನೆಯನ್ನು ಚಲಾಯಿಸಿ. OmniRoute ಬ್ರೌಸರ್ ಬೆಂಬಲಿತ Temporary Chat ಅನ್ನು ತೆರೆಯುತ್ತದೆ ಮತ್ತು ಖಾತೆಗೆ Sol ಹಾಗೂ Pro ಲಭ್ಯವಿದೆಯೇ ಎಂಬುದನ್ನು ಪತ್ತೆಹಚ್ಚುತ್ತದೆ.
4. ಸಂಪರ್ಕವನ್ನು ಉಳಿಸಿ. OmniRoute ಅಂಟಿಸಲಾದ ಕುಕಿಯನ್ನು ಪರಿಶೀಲಿಸಿದ Playwright ಸ್ಟೋರೇಜ್ ಸ್ಟೇಟ್ನಿಂದ ಬದಲಾಯಿಸುತ್ತದೆ ಮತ್ತು ಎನ್ಕ್ರಿಪ್ಟ್ ಮಾಡಿದ ಕ್ರೆಡೆನ್ಶಿಯಲ್ ಅಬ್ಸ್ಟ್ರಾಕ್ಷನ್ ಮೂಲಕ ಅದನ್ನು ರನ್ಟೈಮ್ ಕೀ ಜೊತೆಗೆ ಸಂಗ್ರಹಿಸುತ್ತದೆ.

ಯಶಸ್ವಿಯಾಗಿ ಉಳಿಸಿದ ನಂತರ ಕಚ್ಚಾ ಕುಕಿಯನ್ನು ಉಳಿಸಿಕೊಳ್ಳಲಾಗುವುದಿಲ್ಲ. ಸೆಷನ್ ಅವಧಿ ಮುಗಿದಾಗ, ಸಂಪರ್ಕವನ್ನು ತೆರೆಯಿರಿ, ಹೊಸ ಸಂಪೂರ್ಣ Cookie ಹೆಡರ್ ಅನ್ನು ಅಂಟಿಸಿ ಮತ್ತು ಪರಿಶೀಲನೆಯನ್ನು ಮತ್ತೆ ಚಲಾಯಿಸಿ. ಎಡಿಟ್ ಡೈಲಾಗ್ನಲ್ಲಿರುವ ಡಾಕ್ಟರ್ ಸ್ಥಿತಿಯು ಬ್ರೌಸರ್, ಸ್ಟೋರೇಜ್ ಸ್ಟೇಟ್, ಸೈನ್-ಇನ್, Temporary Chat, ಟನಲ್, ಕನೆಕ್ಟರ್ ಮತ್ತು ಟೂಲ್ ರೌಂಡ್-ಟ್ರಿಪ್ ಅನ್ನು ಪ್ರತ್ಯೇಕವಾಗಿ ವರದಿ ಮಾಡುತ್ತದೆ.

> ನೈಜ ಕುಕಿ, ರನ್ಟೈಮ್ ಕೀ, ಸ್ಟೋರೇಜ್ ಸ್ಟೇಟ್ ಅಥವಾ ಸಾಮರ್ಥ್ಯ ಟೋಕನ್ ಅನ್ನು ಎಂದಿಗೂ ಕಮಿಟ್ ಮಾಡಬೇಡಿ. ಪರೀಕ್ಷೆ ಮತ್ತು
> ದಸ್ತಾವೇಜೀಕರಣದ ಮೌಲ್ಯಗಳು ಯಾವಾಗಲೂ ಪ್ಲೇಸ್ಹೋಲ್ಡರ್ಗಳಾಗಿರಬೇಕು.

## ಮಾಡೆಲ್ಗಳು ಮತ್ತು ಕಾಂಬೊಗಳು

ಸ್ಥಿರ ಮಾಡೆಲ್ ರೂಟ್ಗಳು ಹೀಗಿವೆ:

- `chatgpt-web-codex/luna` — GPT-5.6 Luna, ಕಡಿಮೆ ಪ್ರಯತ್ನ
- `chatgpt-web-codex/think` — GPT-5.6 Luna, ಮಧ್ಯಮ ಪ್ರಯತ್ನ
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

ಇತರ ಯಾವುದೇ ಮಾಡೆಲ್ನಂತೆಯೇ ಇವುಗಳಲ್ಲಿ ಒಂದನ್ನು ಕಾಂಬೊಗೆ ಸೇರಿಸಿ. Codex ಆ್ಯಪ್ ಕಾಂಬೊ ಹೆಸರನ್ನು ಸಾಮಾನ್ಯ Responses ಎಂಡ್ಪಾಯಿಂಟ್ `/v1/responses` ಗೆ `model` ಆಗಿ ಕಳುಹಿಸುತ್ತದೆ; ಯಾವುದೇ ಪ್ರತ್ಯೇಕ Codex ಎಂಡ್ಪಾಯಿಂಟ್ ಅಥವಾ ಮೋಡ್ ಸ್ವಿಚ್ ಇಲ್ಲ.

Free/Go ಖಾತೆಗಳು Luna ರೂಟ್ಗಳನ್ನು ಒದಗಿಸುತ್ತವೆ. Sol ಸಾಮರ್ಥ್ಯವುಳ್ಳ ಖಾತೆಗಳು Instant ನಿಂದ High ವರೆಗಿನ ರೂಟ್ಗಳನ್ನು ಒದಗಿಸುತ್ತವೆ ಮತ್ತು Pro ಸಾಮರ್ಥ್ಯವುಳ್ಳ ಖಾತೆಗಳು ಹೆಚ್ಚುವರಿಯಾಗಿ Extra High ಮತ್ತು Pro ಅನ್ನು ಒದಗಿಸುತ್ತವೆ. ಪ್ರತಿಯೊಂದು ರೂಟ್ ಸ್ಥಿರ ಬ್ಯಾಕೆಂಡ್ ಮಾಡೆಲ್ ಮತ್ತು ರೀಸನಿಂಗ್ ಪ್ರಯತ್ನವನ್ನು ಹೊಂದಿರುತ್ತದೆ; ಸಂಘರ್ಷಿಸುವ ಸ್ಪಷ್ಟ Responses ಪ್ರಯತ್ನವು ಆಯ್ಕೆಮಾಡಿದ ಬ್ರೌಸರ್ ಮೋಡ್ ಅನ್ನು ಮೌನವಾಗಿ ಬದಲಾಯಿಸುವ ಬದಲು ಸುರಕ್ಷಿತವಾಗಿ ವಿಫಲಗೊಳ್ಳುತ್ತದೆ.

ಹಳೆಯ `Codex Native` ಅಥವಾ `OmniRoute Codex` ಕನೆಕ್ಟರ್ನ ಹೆಸರನ್ನು ಬದಲಾಯಿಸಬೇಡಿ ಅಥವಾ ಅದನ್ನು ಮರುಬಳಕೆ ಮಾಡಬೇಡಿ. ChatGPT ಸಾರ್ವಜನಿಕ MCP ಒಪ್ಪಂದವನ್ನು ಕನೆಕ್ಟರ್ ಗುರುತಿನ ಆಧಾರದಲ್ಲಿ ಕ್ಯಾಶ್ ಮಾಡುತ್ತದೆ, ಆದರೆ ನವೀಕರಿಸಿದ ಬ್ರಿಡ್ಜ್ ಹೊಸ ನೇರ ಟರ್ನ್-ಟೋಕನ್ ಒಪ್ಪಂದವನ್ನು ಬಳಸುತ್ತದೆ. ರನ್ಟೈಮ್ ಆ ಲೆಗಸಿ ಗುರುತುಗಳನ್ನು ತಿರಸ್ಕರಿಸುತ್ತದೆ ಮತ್ತು ಹೊಸ `OmniRoute Codex v2` ಕನೆಕ್ಟರ್ ಅನ್ನು ಕಡ್ಡಾಯಗೊಳಿಸುತ್ತದೆ.

## ಭದ್ರತಾ ಮಾದರಿ

- ನೇಟಿವ್ ಪಾತ್ಗೆ Responses ವಿನಂತಿ, ಗುರುತಿಸಲಾದ Codex ಕ್ಲೈಂಟ್ ಹಾಗೂ ಹೊಂದಾಣಿಕೆಯಾಗುವ
  ಥ್ರೆಡ್ ಮತ್ತು ಟರ್ನ್ ಗುರುತುಗಳು ಅಗತ್ಯವಿವೆ.
- ವರ್ಕ್ಸ್ಪೇಸ್, ಸ್ಯಾಂಡ್ಬಾಕ್ಸ್, ಅನುಮೋದನಾ ನೀತಿ ಮತ್ತು ಟೂಲ್ ಕ್ಯಾಟಲಾಗ್ ನೇಟಿವ್ Codex ಶೆಲ್ನಿಂದ ಬರುತ್ತವೆ;
  ಮುಕ್ತ-ರೂಪದ ಪ್ರಾಂಪ್ಟ್ ಪಠ್ಯವು ಅವುಗಳ ಮೇಲೆ ಅಧಿಕಾರ ಹೊಂದಿರುವುದಿಲ್ಲ.
- ಪ್ರತಿ ಟರ್ನ್ಗೆ ChatGPT ಅಲ್ಪಾವಧಿಯ ಸಾಮರ್ಥ್ಯವನ್ನು ಮಾತ್ರ ಸ್ವೀಕರಿಸುತ್ತದೆ. ಅದೇ ಟರ್ನ್ನಲ್ಲಿ
  Codex ನೀಡಿದ ಟೂಲ್ಗಳನ್ನು ಮಾತ್ರ MCP ಬ್ರೋಕರ್ ಸ್ವೀಕರಿಸುತ್ತದೆ.
- **Allow once** ಅನ್ನು ಸ್ವಯಂ-ದೃಢೀಕರಿಸುವುದು ಟೂಲ್ ವಿನಂತಿಯನ್ನು Codexಗೆ ಮರಳಿಸುತ್ತದೆ ಅಷ್ಟೇ. ಅನುಮೋದನೆ
  ಮತ್ತು ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆಯನ್ನು Codex ಮಾತ್ರ ನಿರ್ಧರಿಸುತ್ತದೆ.
- ಮೊದಲ ಔಟ್ಪುಟ್ಗೆ ಮೊದಲು, ಒಂದು ಕಾಂಬೊ ಮತ್ತೊಂದು ಹೊಂದಾಣಿಕೆಯ ಟಾರ್ಗೆಟ್ಗೆ ಫಾಲ್ಬ್ಯಾಕ್ ಆಗಬಹುದು. ಔಟ್ಪುಟ್
  ಪ್ರಾರಂಭವಾದ ನಂತರ, ಟರ್ನ್ ಪೂರ್ಣಗೊಳ್ಳುವವರೆಗೆ ಪ್ರೊವೈಡರ್, ಮಾಡೆಲ್, ಕನೆಕ್ಷನ್ ಮತ್ತು ಬ್ರೌಸರ್ ಟರ್ನ್ ಸ್ಥಿರವಾಗಿರುತ್ತವೆ.
- ಕುಕಿಗಳು, ರನ್ಟೈಮ್ ಕೀಗಳು, ಸ್ಟೋರೇಜ್ ಸ್ಥಿತಿ ಮತ್ತು ಸಾಮರ್ಥ್ಯ ಟೋಕನ್ಗಳು ಪ್ರೊವೈಡರ್
  ಪ್ರತಿಕ್ರಿಯೆಗಳಲ್ಲಿ ಅಥವಾ ವಿನಂತಿ ಲಾಗ್ಗಳಲ್ಲಿ ಕಾಣಿಸುವುದಿಲ್ಲ.

## ಡಿಸ್ಪ್ಲೇ ರಹಿತ VPS ಮತ್ತು Docker

npm, systemd ಮತ್ತು PM2 ಇನ್ಸ್ಟಾಲ್ಗಳಿಗಾಗಿ, OmniRoute ಸಾಮಾನ್ಯ Chrome ಮತ್ತು Chromium ಪಾತ್ಗಳನ್ನು ಪತ್ತೆಹಚ್ಚುತ್ತದೆ.
ಪರ್ಯಾಯವಾಗಿ, `CHATGPT_WEB_CODEX_CHROME_PATH` ಅನ್ನು ಹೊಂದಿಸಿ. ChatGPT ನಿಜವಾದ ಹೆಡ್ಲೆಸ್ ಬ್ರೌಸರ್ ಸ್ವರೂಪವನ್ನು
ತಿರಸ್ಕರಿಸುವುದರಿಂದ, ರನ್ಟೈಮ್ ಟರ್ನ್ಗಳು ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ಹೆಡೆಡ್ Chrome ಅನ್ನು ಬಳಸುತ್ತವೆ. ಆದ್ದರಿಂದ ಡಿಸ್ಪ್ಲೇ ರಹಿತ ಹೋಸ್ಟ್
ಖಾಸಗಿ Xvfb ಡಿಸ್ಪ್ಲೇಯೊಂದಿಗೆ OmniRoute ಅನ್ನು ರನ್ ಮಾಡಬೇಕು; Chrome ಪಾತ್ ಅನ್ನು ಮಾತ್ರ ಹೊಂದಿಸುವುದರಿಂದ ಡಿಸ್ಪ್ಲೇ ದೊರೆಯುವುದಿಲ್ಲ.

Docker `web` ಪ್ರೊಫೈಲ್ ಆಂತರಿಕ Compose ನೆಟ್ವರ್ಕ್ನಲ್ಲಿ `chatgpt-web-codex-browser` ಅನ್ನು ಪ್ರಾರಂಭಿಸುತ್ತದೆ.
ಸೈಡ್ಕಾರ್ Xvfb ಒಳಗೆ ಹೆಡೆಡ್ Chrome ಅನ್ನು ರನ್ ಮಾಡುವುದರಿಂದ, ಭೌತಿಕ ಡಿಸ್ಪ್ಲೇ ಅಗತ್ಯವಿಲ್ಲ. ಅದರ CDP
ಪೋರ್ಟ್ ಅನ್ನು ಹೋಸ್ಟ್ನಲ್ಲಿ ಪ್ರಕಟಿಸಲಾಗುವುದಿಲ್ಲ. ಸಂರಕ್ಷಿತ ಬ್ರೌಸರ್ ಪ್ರೊಫೈಲ್ ವಾಲ್ಯೂಮ್ ಅನ್ನು
OmniRoute ಡೇಟಾ ವಾಲ್ಯೂಮ್ನಿಂದ ಪ್ರತ್ಯೇಕಿಸಲಾಗಿರುತ್ತದೆ ಮತ್ತು ಬ್ರೌಸರ್ಗೆ ಸಾಕಷ್ಟು ಹಂಚಿಕೆಯ ಮೆಮೊರಿ ದೊರೆಯುತ್ತದೆ. ಆಂತರಿಕ CDP ಪ್ರಾಕ್ಸಿ
Compose ನೆಟ್ವರ್ಕ್ನೊಳಗೆ `9223` ಪೋರ್ಟ್ನಲ್ಲಿ ಮಾತ್ರ ಆಲಿಸುತ್ತದೆ; ಸೈಡ್ಕಾರ್ನಲ್ಲಿ Chrome ಲೂಪ್ಬ್ಯಾಕ್ಗೆ ಬದ್ಧವಾಗಿರುತ್ತದೆ.

`DATA_DIR` ಅಡಿಯಲ್ಲಿ ಇರುವ ಸೂಪರ್ವೈಸರ್ ಲೀಸ್, ಅನೇಕ OmniRoute ಪ್ರಕ್ರಿಯೆಗಳು ಒಂದೇ
ಟನೆಲ್ ಮತ್ತು ಬ್ರೋಕರ್ ಸ್ಥಿತಿಯ ಮಾಲೀಕತ್ವ ಪಡೆಯುವುದನ್ನು ತಡೆಯುತ್ತದೆ. ಸಂಘರ್ಷವನ್ನು ಡಾಕ್ಟರ್ ವರದಿ ಮಾಡುತ್ತದೆ.

## ಸಂವಾದಾತ್ಮಕ ಮರುಪಡೆಯುವಿಕೆ

ಸ್ವಯಂಚಾಲಿತ Docker ಪಾತ್ನಲ್ಲಿ ಹೋಸ್ಟ್ಗೆ ಗೋಚರಿಸುವ ವಿಂಡೋ ಇರುವುದಿಲ್ಲ, ಆದರೆ ಖಾಸಗಿ Xvfb ಡಿಸ್ಪ್ಲೇಯೊಳಗೆ
Chrome ಸ್ವತಃ ಹೆಡೆಡ್ ಆಗಿರುತ್ತದೆ. ChatGPT ಸಂವಾದಾತ್ಮಕ ಸೈನ್-ಇನ್ ಅಥವಾ ಚಾಲೆಂಜ್ ಅನ್ನು ಕೇಳಿದಾಗ, ಮರುಪಡೆಯುವಿಕೆಗಾಗಿ ಈಗಿರುವ VNC
ಬ್ರೌಸರ್ ಮೂಲಸೌಕರ್ಯವನ್ನು ಬಳಸಬಹುದು. ಬ್ರೌಸರ್ UI ಮತ್ತು CDP ಲೂಪ್ಬ್ಯಾಕ್, ದೃಢೀಕೃತ ನಿರ್ವಹಣಾ ಕನೆಕ್ಷನ್
ಅಥವಾ SSH ಟನೆಲ್ ಮೂಲಕ ಮಾತ್ರ ತಲುಪಬಹುದಾಗಿರಬೇಕು; ಸಾಮಾನ್ಯ ಕಾರ್ಯಾಚರಣೆಯ ಸಮಯದಲ್ಲಿ noVNC ನಿಷ್ಕ್ರಿಯವಾಗಿರುತ್ತದೆ.
