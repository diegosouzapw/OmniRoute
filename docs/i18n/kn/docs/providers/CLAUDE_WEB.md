## `claude-web`

`claude-web`, ದೃಢೀಕರಿಸಿದ `claude.ai` ಬ್ರೌಸರ್ ಸೆಷನ್ ಮೂಲಕ OpenAI-ಸ್ವರೂಪದ ಚಾಟ್ ವಿನಂತಿಗಳನ್ನು ಕಳುಹಿಸುತ್ತದೆ. ಎಕ್ಸಿಕ್ಯೂಟರ್ ಒದಗಿಸಲಾದ ಕುಕಿಯನ್ನು ಸಾಮಾನ್ಯೀಕರಿಸುತ್ತದೆ, ದೃಢೀಕರಿಸಿದ ಒಂದು ಸಂಸ್ಥೆಯನ್ನು ನಿರ್ಧರಿಸುತ್ತದೆ, ಸಂಭಾಷಣೆಯ ಸ್ಥಿತಿಯನ್ನು ಸಿದ್ಧಪಡಿಸುತ್ತದೆ, ನೇರ ಅಥವಾ ಬ್ರೌಸರ್ ಟ್ರಾನ್ಸ್ಪೋರ್ಟ್ ಅನ್ನು ಆಯ್ಕೆ ಮಾಡುತ್ತದೆ ಮತ್ತು ಅಪ್ಸ್ಟ್ರೀಮ್ SSE ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಕಟ್ಟುನಿಟ್ಟಾಗಿ ಪರಿವರ್ತಿಸುತ್ತದೆ. ಆರ್ಕೆಸ್ಟ್ರೇಶನ್ `open-sse/executors/claude-web.ts:320` ನಲ್ಲಿದೆ.

> **Web Cookie ಪೂರೈಕೆದಾರರಿಗೆ ಹೊಸಬರೇ?**
>
> ಈ ಪೂರೈಕೆದಾರ-ನಿರ್ದಿಷ್ಟ ಮಾರ್ಗದರ್ಶಿಯನ್ನು ಅನುಸರಿಸುವ ಮೊದಲು ಸಾಮಾನ್ಯ ಸೆಟಪ್ ಪ್ರಕ್ರಿಯೆ, ದೃಢೀಕರಣ ಮಾರ್ಗದರ್ಶನ, ಮಿತಿಗಳು ಮತ್ತು ದೋಷನಿವಾರಣೆಗಾಗಿ **`docs/getting-started/WEB-COOKIE-GUIDE.md`** ಓದಿ.

### ಮಾದರಿ ಕ್ಯಾಟಲಾಗ್

ಪೂರೈಕೆದಾರರ ರಿಜಿಸ್ಟ್ರಿಯು ಪ್ರಸ್ತುತ ನಿಖರವಾಗಿ ಈ ಏಳು ಸ್ಥಿರ ಮಾದರಿ IDಗಳನ್ನು ಬಹಿರಂಗಪಡಿಸುತ್ತದೆ
(`open-sse/config/providers/registry/claude/web/index.ts:11`):

| ಮಾದರಿ ID                    | ಪ್ರದರ್ಶನ ಹೆಸರು           |
| --------------------------- | ------------------------ |
| `claude-fable-5`            | Claude Fable 5 (ವೆಬ್)    |
| `claude-opus-4-8`           | Claude Opus 4.8 (ವೆಬ್)   |
| `claude-sonnet-5`           | Claude Sonnet 5 (ವೆಬ್)   |
| `claude-haiku-4-5-20251001` | Claude Haiku 4.5 (ವೆಬ್)  |
| `claude-opus-4-7`           | Claude Opus 4.7 (ವೆಬ್)   |
| `claude-opus-4-6`           | Claude Opus 4.6 (ವೆಬ್)   |
| `claude-sonnet-4-6`         | Claude Sonnet 4.6 (ವೆಬ್) |

ಈ ಪೂರೈಕೆದಾರರಿಗೆ ಡೈನಾಮಿಕ್ ಮಾದರಿ ಅನ್ವೇಷಣೆಯನ್ನು ಅಳವಡಿಸಲಾಗಿಲ್ಲ. ಮೇಲಿನ ಪಟ್ಟಿಯೇ ರನ್ಟೈಮ್ ಕ್ಯಾಟಲಾಗ್ ಆಗಿದೆ.

### ರುಜುವಾತುಗಳು ಮತ್ತು ಸಂಸ್ಥೆಯ ನಿರ್ಧಾರ

ಪೂರ್ಣ `claude.ai` Cookie ಹೆಡರ್ ಅಥವಾ ಕೇವಲ ಸೆಷನ್ ಮೌಲ್ಯವನ್ನು ಒದಗಿಸಿ. ಕೇವಲ ಮೌಲ್ಯಗಳನ್ನು `sessionKey` ಆಗಿ ಸಾಮಾನ್ಯೀಕರಿಸಲಾಗುತ್ತದೆ; ಇತರ ಕುಕಿಗಳನ್ನು ಒದಗಿಸಿದ್ದರೆ ಅವುಗಳನ್ನು ಉಳಿಸಿಕೊಳ್ಳಲಾಗುತ್ತದೆ. ಎಕ್ಸಿಕ್ಯೂಟರ್ ಕುಕಿಯನ್ನು `cookie` ಅಥವಾ `apiKey` ಮೂಲಕ ಸ್ವೀಕರಿಸುತ್ತದೆ ಮತ್ತು ಸಂಪರ್ಕ ಡೇಟಾದಿಂದ ಐಚ್ಛಿಕ `deviceId` ಮತ್ತು `orgId` ಮೌಲ್ಯಗಳನ್ನು ಓದುತ್ತದೆ
(`open-sse/executors/claude-web.ts:72`).

`orgId` ಇಲ್ಲದಿದ್ದರೆ, ಎಕ್ಸಿಕ್ಯೂಟರ್ `GET https://claude.ai/api/organizations` ಅನ್ನು ಕರೆದು, ದೃಢೀಕರಿಸಿದ Claude Web ಸೆಷನ್ ಹಿಂದಿರುಗಿಸುವ ಮೊದಲ ಸಂಸ್ಥೆಯನ್ನು ಬಳಸುತ್ತದೆ
(`open-sse/executors/claude-web.ts:141`). ಯಾವುದೇ ಮಾನ್ಯ ಸಂಸ್ಥೆ ಹಿಂದಿರುಗದಿದ್ದಾಗ ಅದು ಮುಚ್ಚಿದ ಸ್ಥಿತಿಯಲ್ಲಿ ವಿಫಲಗೊಳ್ಳುತ್ತದೆ, ತಿರಸ್ಕರಿಸಲಾದ ಸೆಷನ್ ದೃಢೀಕರಣವನ್ನು 401 ಎಂದು ವರದಿ ಮಾಡುತ್ತದೆ ಮತ್ತು Cloudflare ಸವಾಲನ್ನು ದೃಢೀಕರಣ ವೈಫಲ್ಯದಿಂದ ಪ್ರತ್ಯೇಕಿಸುತ್ತದೆ.

### ಸಂಭಾಷಣೆ ಕಾರ್ಯಾಚರಣೆಗಳು

ಐಚ್ಛಿಕ ಉನ್ನತ-ಮಟ್ಟದ `claude_web` ಆಬ್ಜೆಕ್ಟ್ ಕಟ್ಟುನಿಟ್ಟಾಗಿದೆ. ಅಜ್ಞಾತ ಫೀಲ್ಡ್ಗಳನ್ನು ತಿರಸ್ಕರಿಸಲಾಗುತ್ತದೆ. ಅದು ಸ್ವೀಕರಿಸುವ ಫೀಲ್ಡ್ಗಳನ್ನು `open-sse/executors/claude-web/session.ts:50` ನಲ್ಲಿ ವ್ಯಾಖ್ಯಾನಿಸಲಾಗಿದೆ:

| ಫೀಲ್ಡ್                | ಅರ್ಥ                                                             |
| --------------------- | ---------------------------------------------------------------- |
| `operation`           | ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ `completion`; ಮರುಪ್ರಯತ್ನದ ಸರದಿಗಾಗಿ `retry` ಬಳಸಿ |
| `conversation_id`     | ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಸಂಭಾಷಣೆಗೆ ಸ್ಪಷ್ಟ UUID                           |
| `parent_message_uuid` | ಮೂಲ ಸಹಾಯಕ ಸಂದೇಶಕ್ಕೆ ಸ್ಪಷ್ಟ UUID                                  |
| `timezone`            | ಮಾನ್ಯ IANA ಸಮಯ-ವಲಯದ ಹೆಸರು                                        |
| `locale`              | ರಚನಾತ್ಮಕವಾಗಿ ಮಾನ್ಯವಾದ ಲೊಕೇಲ್                                     |
| `tool_states`         | ಐಚ್ಛಿಕ ಖಾತೆ ಟೂಲ್-ಸ್ಥಿತಿ ಅರೇ, 128 ನಮೂದುಗಳಿಗೆ ಸೀಮಿತವಾಗಿದೆ          |

ಸಿದ್ಧಪಡಿಸಿದ ವಿನಂತಿಗಳು ಎರಡು ಅಪ್ಸ್ಟ್ರೀಮ್ ಎಂಡ್ಪಾಯಿಂಟ್ಗಳಲ್ಲಿ ಒಂದನ್ನು ಬಳಸುತ್ತವೆ
(`open-sse/executors/claude-web.ts:203`):

- ಹೊಸ ಅಥವಾ ಫಾಲೋ-ಅಪ್ ಸರದಿಯನ್ನು
  `POST https://claude.ai/api/organizations/{orgId}/chat_conversations/{conversationId}/completion` ಗೆ ಪೋಸ್ಟ್ ಮಾಡಲಾಗುತ್ತದೆ.
- ಮರುಪ್ರಯತ್ನವನ್ನು
  `POST https://claude.ai/api/organizations/{orgId}/chat_conversations/{conversationId}/retry_completion` ಗೆ ಪೋಸ್ಟ್ ಮಾಡಲಾಗುತ್ತದೆ.

ಹೊಸ ಸರದಿಯು `create_conversation_params` ಅನ್ನು ಒಳಗೊಂಡಿರುತ್ತದೆ. ಕ್ಯಾಶ್ ಮಾಡಿದ ಅಥವಾ ಸ್ಪಷ್ಟವಾಗಿ ಲಿಂಕ್ ಮಾಡಿದ ಫಾಲೋ-ಅಪ್ `parent_message_uuid` ಅನ್ನು ಒಳಗೊಂಡಿರುತ್ತದೆ ಮತ್ತು `create_conversation_params` ಅನ್ನು ಬಿಟ್ಟುಬಿಡುತ್ತದೆ. ಮರುಪ್ರಯತ್ನಕ್ಕೆ ಸಂಭಾಷಣೆ ಮತ್ತು ಮೂಲ-ಸಂದೇಶ ಸ್ಥಿತಿ ಎರಡೂ ಅಗತ್ಯವಿದ್ದು, ಯಾವುದೇ ಪ್ರಾಂಪ್ಟ್ ಅನ್ನು ಕಳುಹಿಸುವುದಿಲ್ಲ
(`open-sse/executors/claude-web/session.ts:254`). ಹೊಸ ಸಂಭಾಷಣೆಗಳು ದೃಢೀಕರಿಸಿದ UI ಅನ್ನು `/new` ನಲ್ಲಿ ತೆರೆಯುತ್ತವೆ; ಕ್ಯಾಶ್ ಮಾಡಿದ ಅಥವಾ ಸ್ಪಷ್ಟವಾಗಿ ಲಿಂಕ್ ಮಾಡಿದ ಫಾಲೋ-ಅಪ್ಗಳು ನಿಖರವಾದ ಸಂಭಾಷಣೆ ಪುಟವನ್ನು ತೆರೆಯುತ್ತವೆ
(`open-sse/executors/claude-web/session.ts:324`).

ಸಂಭಾಷಣೆ ಸ್ಥಿತಿಯು SHA-256 ಖಾತೆ ವ್ಯಾಪ್ತಿ ಮತ್ತು ಕಾಲರ್ನ ಕ್ಯಾನಾನಿಕಲ್ ಟ್ರಾನ್ಸ್ಕ್ರಿಪ್ಟ್ ಮೂಲಕ ಕೀ ಮಾಡಲಾದ ಇನ್-ಮೆಮೊರಿ ಕ್ಯಾಶ್ ಆಗಿದೆ. ನಮೂದುಗಳು 30 ನಿಮಿಷಗಳ ನಂತರ ಅವಧಿ ಮೀರುತ್ತವೆ ಮತ್ತು ಕ್ಯಾಶ್ ಅನ್ನು 5,000 ನಮೂದುಗಳಿಗೆ ಮಿತಿಗೊಳಿಸಲಾಗಿದೆ
(`open-sse/executors/claude-web/session.ts:12`). ಕಟ್ಟುನಿಟ್ಟಾದ ಸ್ಟ್ರೀಮ್ ಪಾರ್ಸರ್ `message_stop` ಅನ್ನು ಗಮನಿಸಿದ ನಂತರವೇ ಸ್ಥಿತಿಯನ್ನು ಕಮಿಟ್ ಮಾಡಲಾಗುತ್ತದೆ; ಪ್ರಕ್ರಿಯೆಯ ಮರುಪ್ರಾರಂಭಗಳು ಅದನ್ನು ತ್ಯಜಿಸುತ್ತವೆ. ಕ್ಯಾಶ್ ಮಿಸ್ ಆದಾಗ, ಹಿಂದಿನ ಸಂದೇಶಗಳನ್ನು ಮೌನವಾಗಿ ಕೈಬಿಡುವ ಬದಲು ಬಹು-ಸಂದೇಶದ ವಿನಂತಿಯನ್ನು ಒಂದೇ ಮರುಪಡೆಯುವಿಕೆ ಪ್ರಾಂಪ್ಟ್ ಆಗಿ ಸೀರಿಯಲೈಸ್ ಮಾಡಲಾಗುತ್ತದೆ.

ಲೊಕೇಲ್ ಮತ್ತು ಸಮಯ ವಲಯವು ಈ ಆದ್ಯತೆಯನ್ನು ಬಳಸುತ್ತವೆ: ವಿನಂತಿಯ `claude_web` ಮೌಲ್ಯ, ಸಂಪರ್ಕ ಮೌಲ್ಯ, ರನ್ಟೈಮ್ ಮೌಲ್ಯ, ನಂತರ ಲೊಕೇಲ್ಗಾಗಿ `en-US` ಅಥವಾ ಸಮಯ ವಲಯಕ್ಕಾಗಿ `UTC`
(`open-sse/executors/claude-web/session.ts:218`).

### ಟೂಲ್ಗಳು ಮತ್ತು ವಿನಂತಿ ಪೇಲೋಡ್ಗಳು

ನೇರ ವಿನಂತಿಗಳು ಕಾಲರ್ ಒದಗಿಸಿದ ರಚನಾತ್ಮಕವಾಗಿ ಮಾನ್ಯವಾದ OpenAI ಫಂಕ್ಷನ್ ಟೂಲ್ಗಳನ್ನು ಮಾತ್ರ ಪರಿವರ್ತಿಸುತ್ತವೆ. ಕೃತಕವಾಗಿ ರಚಿಸಲಾದ ಸ್ಥಿರ ಪೂರ್ವನಿಯೋಜಿತ ಟೂಲ್ ಪಟ್ಟಿ ಇರುವುದಿಲ್ಲ
(`open-sse/executors/claude-web/payload.ts:102`).

ಇದಕ್ಕೆ ಬದಲಾಗಿ ಬ್ರೌಸರ್ ವಿನಂತಿಗಳು ದೃಢೀಕರಿಸಿದ UI ವಿನಂತಿಯನ್ನು ಸೆರೆಹಿಡಿದು, ಅದರ ಖಾತೆ ಟೂಲ್ಗಳು, ಟೂಲ್ ಸ್ಥಿತಿಗಳು ಮತ್ತು ವೈಯಕ್ತೀಕರಿಸಿದ ಶೈಲಿಗಳನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತವೆ. ಸಿದ್ಧಪಡಿಸಿದ ಸಂಭಾಷಣೆ, ಮಾದರಿ, ತಾರ್ಕಿಕತೆ, ಪ್ರಾಂಪ್ಟ್ ಮತ್ತು ಸಂದೇಶ UUID ಫೀಲ್ಡ್ಗಳು ಸೆರೆಹಿಡಿದ ವಿನಂತಿಯನ್ನು ಇನ್ನೂ ಅತಿಕ್ರಮಿಸುತ್ತವೆ
(`open-sse/executors/claude-web/browserTransport.ts:175`). ಬ್ರೌಸರ್ ಟೆಂಪ್ಲೇಟ್ಗಳನ್ನು ಖಾತೆ, ಸಂಸ್ಥೆ, ಕುಕಿ, ಲೊಕೇಲ್ ಮತ್ತು ಸಮಯ ವಲಯದ ಹ್ಯಾಶ್ ಮೂಲಕ ವ್ಯಾಪ್ತಿಗೊಳಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಅವು 30 ನಿಮಿಷಗಳ ನಂತರ ಅವಧಿ ಮೀರುತ್ತವೆ
(`open-sse/executors/claude-web/browserTransport.ts:11`,
`open-sse/executors/claude-web/browserTransport.ts:158`). ನೇರ ವಿನಂತಿಯಲ್ಲಿ ಕಾಲರ್ ಟೂಲ್ಗಳು ಇಲ್ಲದಿದ್ದಾಗ, ಅದು ಆ ವ್ಯಾಪ್ತಿಗೊಳಿಸಿದ ಟೆಂಪ್ಲೇಟ್ ಅನ್ನು ಮರುಬಳಕೆ ಮಾಡಬಹುದು; ಸ್ಪಷ್ಟ ಕಾಲರ್ ಟೂಲ್ಗಳಿಗೆ ಆದ್ಯತೆ ಇರುತ್ತದೆ
(`open-sse/executors/claude-web/browserTransport.ts:214`).

### ಟ್ರಾನ್ಸ್ಪೋರ್ಟ್ ಆಯ್ಕೆ

ಪೂರ್ವನಿಯೋಜಿತ ಮಾರ್ಗವು `sendClaudeWebDirect()` ಆಗಿದ್ದು, ಇದು ಕಾನ್ಫಿಗರ್ ಮಾಡಿದ Chrome 146 ಪ್ರೊಫೈಲ್ ಮತ್ತು ಒದಗಿಸಲಾದ ಕುಕಿಯೊಂದಿಗೆ `tlsFetchClaude()` ಅನ್ನು ಕರೆಯುತ್ತದೆ (`open-sse/services/claudeTlsClient.ts:23`). ಇದು ಸಾಲ್ವರ್ ಅನ್ನು ಪ್ರಾರಂಭಿಸುವುದಿಲ್ಲ ಅಥವಾ ಬದಲಿ ಕುಕಿಯನ್ನು ರಚಿಸುವುದಿಲ್ಲ.

ಖಾತೆ-ವ್ಯಾಪ್ತಿಯ browser adapter ಅನ್ನು ಪ್ರಾಥಮಿಕ transport ಆಗಿಸಲು `WEB_COOKIE_USE_BROWSER` ಅನ್ನು `1`, `true`, ಅಥವಾ `on` ಗೆ ಹೊಂದಿಸಿ. ಗುರುತಿಸಲಾದ Cloudflare 403 challenge ಸಂದರ್ಭದಲ್ಲಿ direct transport ನಿಂದ browser adapter ಗೆ fallback ಮಾಡಲು ಅನುಮತಿಸಲು `OMNIROUTE_BROWSER_POOL` ಅನ್ನು ಇದೇ ಮೌಲ್ಯಗಳಲ್ಲಿ ಒಂದಕ್ಕೆ ಹೊಂದಿಸಿ (`open-sse/executors/claude-web.ts:195`). ಇತರ HTTP ವೈಫಲ್ಯಗಳು ಆ fallback ಅನ್ನು ಪ್ರಚೋದಿಸುವುದಿಲ್ಲ.

browser adapter ಅದೇ pooled Playwright context ಒಳಗೆ cookies ಅನ್ನು ಇರಿಸುತ್ತದೆ, ಮೇಲೆ ವಿವರಿಸಿದ scoped hashed key ಅನ್ನು ಬಳಸುತ್ತದೆ ಮತ್ತು ಆ context ನಿಂದ completion ಅನ್ನು ಕಳುಹಿಸುತ್ತದೆ (`open-sse/executors/claude-web/browserTransport.ts:444`). browser ಮೂಲಕ ಪರಿಹರಿಸಲಾದ cookie ಅನ್ನು ಅದು ಎಂದಿಗೂ direct TLS client ಗೆ export ಮಾಡುವುದಿಲ್ಲ. browser retries ಗಾಗಿ ಅದೇ ನೈಜ Playwright context ಗೆ ಬದ್ಧವಾಗಿರುವ, ಅವಧಿ ಮುಗಿಯದ UI template ಅಗತ್ಯವಿದೆ (`open-sse/executors/claude-web/browserTransport.ts:467`). browser response reads ದೃಢೀಕರಿಸಲಾದ page ನಲ್ಲಿ ಹಂತಹಂತವಾಗಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತವೆ, request cancellation ಅನ್ನು ಗೌರವಿಸುತ್ತವೆ ಮತ್ತು ಗಾತ್ರವು 16 MiB ಮೀರಿದ ಕೂಡಲೇ upstream body ಅನ್ನು cancel ಮಾಡುತ್ತವೆ (`open-sse/executors/claude-web/browserTransport.ts:259`).

executor ಹಂಚಿಕೊಂಡ request logger ಗೆ ತಿದ್ದುಪಡಿ ಮಾಡಿದ audit projection ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ: organization, conversation ಮತ್ತು message UUIDs, prompt text, tool definitions, cookies ಮತ್ತು device identifiers ಅನ್ನು ಹೊರಗಿಡಲಾಗುತ್ತದೆ (`open-sse/executors/claude-web.ts:237`,
`open-sse/executors/claude-web.ts:252`). Transport exceptions ಸಹ ಎಸೆಯಲ್ಪಟ್ಟ message ಬದಲಿಗೆ ಸಾಮಾನ್ಯ connection error ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತವೆ.

### SSE ನಡವಳಿಕೆ

`createClaudeWebResponse()` LF ಅಥವಾ CRLF framing ಹಾಗೂ ಬಹುಸಾಲಿನ `data:` fields ಅನ್ನು ನಿರ್ವಹಿಸುತ್ತದೆ. ಇದು text deltas ಅನ್ನು `content` ಗೆ, thinking deltas ಅನ್ನು `reasoning_content` ಗೆ ಮತ್ತು ತಿಳಿದಿರುವ metadata events ಅನ್ನು `claude_web` response extension ಗೆ map ಮಾಡುತ್ತದೆ. ಪ್ರತಿ metadata event ಅನ್ನು ಅದರದೇ field allowlist ಮೂಲಕ project ಮಾಡಲಾಗುತ್ತದೆ (`open-sse/executors/claude-web/stream.ts:37`). conversation, parent-message, assistant-message ಮತ್ತು operation metadata ಅನ್ನು `X-OmniRoute-Claude-Web-*` headers ನಲ್ಲಿಯೂ ಹಿಂತಿರುಗಿಸಲಾಗುತ್ತದೆ (`open-sse/executors/claude-web/stream.ts:364`).

ದೋಷಪೂರಿತ JSON, upstream `error` events, ತಿಳಿದಿಲ್ಲದ event types, ಅಮಾನ್ಯ ordering, content-block mismatches ಅಥವಾ `message_stop` ಗಿಂತ ಮೊದಲು EOF ಎದುರಾದರೆ parser ಮುಚ್ಚಿದ ಸ್ಥಿತಿಯಲ್ಲಿ ವಿಫಲಗೊಳ್ಳುತ್ತದೆ. Streaming output ಒಂದು finish chunk ಮತ್ತು ಒಂದು `[DONE]` ಅನ್ನು emit ಮಾಡುತ್ತದೆ; buffered output ಅದೇ parser ಅನ್ನು ಬಳಸುತ್ತದೆ. parser `message_stop` ಅನ್ನು ತಕ್ಷಣವೇ terminal ಎಂದು ಪರಿಗಣಿಸುತ್ತದೆ, ನಂತರ ಬರುವ upstream data ಅನ್ನು cancel ಮಾಡುತ್ತದೆ ಮತ್ತು downstream cancellation ಅನ್ನು upstream reader ಗೆ propagate ಮಾಡುತ್ತದೆ (`open-sse/executors/claude-web/stream.ts:461`,
`open-sse/executors/claude-web/stream.ts:563`). ಅಂತ್ಯಗೊಳಿಸದ SSE lines ಮತ್ತು ಸಂಗ್ರಹಿಸಲಾದ events ಅನ್ನು 1 MiB ಗೆ ಮಿತಿಗೊಳಿಸಲಾಗಿದೆ (`open-sse/executors/claude-web/stream.ts:17`,
`open-sse/executors/claude-web/stream.ts:62`).
