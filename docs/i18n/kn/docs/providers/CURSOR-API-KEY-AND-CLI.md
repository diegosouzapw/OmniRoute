IDE ಸೆಷನ್ ಇಲ್ಲದೆ Cursor ಅನ್ನು OmniRoute ಹಿಂದೆ ಇರಿಸಲು ಎರಡು ಮಾರ್ಗಗಳು:

1. **`cursor-api` ಪ್ರೊವೈಡರ್** (ಕಾರ್ಡ್ "Cursor API", ಅಲಿಯಾಸ್ `cua`): Cursor ಬಳಕೆದಾರ API ಕೀಲಿಯನ್ನು (`crsr_…`, `https://cursor.com/dashboard/api` ನಲ್ಲಿ ರಚಿಸಲಾಗಿದೆ) ಹೊಂದಿರುವ API-ಕೀ ಪ್ರೊವೈಡರ್. ನಂತರ ಯಾವುದೇ OmniRoute ಕ್ಲೈಂಟ್ ಸಾಮಾನ್ಯ ಕೋಟಾ, ಫಾಲ್ಬ್ಯಾಕ್ ಮತ್ತು ಲಾಗಿಂಗ್ ಪದರಗಳೊಂದಿಗೆ `/v1/chat/completions` ಮೂಲಕ `cursor-api/<model>` ಅಥವಾ `cua/<model>` ಆಗಿ Cursor ಮಾದರಿಗಳನ್ನು ತಲುಪುತ್ತದೆ. IDE ಪ್ರೊವೈಡರ್ (`cursor`, OAuth/IDE ಸೆಷನ್) ಬದಲಾಗಿಲ್ಲ.
2. **Cursor CLI ಪಾಸ್ಥ್ರೂ**: Cursor CLI (`agent`) ಅನ್ನು OmniRoute ಕಡೆಗೆ ನಿರ್ದೇಶಿಸಿ, ಇದರಿಂದ CLI ಮಾಡುವ ಪ್ರತಿಯೊಂದು RPC ಅನ್ನು OmniRoute API ಕೀಲಿಯಿಂದ ದೃಢೀಕರಿಸಲಾಗುತ್ತದೆ, `cursor-api` ಸಂಪರ್ಕದ ಕ್ರೆಡೆನ್ಷಿಯಲ್ನೊಂದಿಗೆ Cursor ಗೆ ಫಾರ್ವರ್ಡ್ ಮಾಡಲಾಗುತ್ತದೆ ಮತ್ತು Logs ಪುಟದಲ್ಲಿ ದಾಖಲಿಸಲಾಗುತ್ತದೆ.

## ಕೀಲಿಯನ್ನು ಏಕೆ ವಿನಿಮಯ ಮಾಡಲಾಗುತ್ತದೆ

`api2.cursor.sh` ಕಚ್ಚಾ `crsr_…` ಕೀಲಿಯನ್ನು Bearer ಟೋಕನ್ ಆಗಿ ತಿರಸ್ಕರಿಸುತ್ತದೆ (401). Cursor CLI ಮೊದಲು ಕೀಲಿಯನ್ನು `/auth/exchange_user_api_key` ಗೆ POST ಮಾಡುತ್ತದೆ ಮತ್ತು ಒಂದು ಗಂಟೆಯ ನಂತರ ಅವಧಿ ಮುಗಿಯುವ ಸೆಷನ್ JWT ಅನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ; ಹಿಂತಿರುಗಿಸಲಾದ `refreshToken` ಅದೇ `exp` ಅನ್ನು ಹೊಂದಿರುತ್ತದೆ, ಆದ್ದರಿಂದ ರಿಫ್ರೆಶ್ ಮಾಡುವುದು ಎಂದರೆ ಕೀಲಿಯನ್ನು ಪುನಃ ವಿನಿಮಯ ಮಾಡುವುದು.
`open-sse/services/cursorApiKeyAuth.ts` ಆ ವಿನಿಮಯವನ್ನು ಮಾಡುತ್ತದೆ, ಪ್ರತಿ ಕೀಲಿಗೆ ಒಂದು ಸೆಷನ್ ಟೋಕನ್ ಅನ್ನು ಕ್ಯಾಶ್ ಮಾಡುತ್ತದೆ, ಅವಧಿ ಮುಗಿಯುವುದಕ್ಕೆ ಐದು ನಿಮಿಷಗಳ ಮೊದಲು ಪುನಃ ವಿನಿಮಯ ಮಾಡುತ್ತದೆ ಮತ್ತು Cursor 401 ಎಂದು ಉತ್ತರಿಸಿದಾಗ ಕ್ಯಾಶ್ ಮಾಡಿದ ಟೋಕನ್ ಅನ್ನು ತೆಗೆದುಹಾಕುತ್ತದೆ. `CursorExecutor`, `cursor-api` ಸಂಪರ್ಕಗಳಿಗಾಗಿ ಅಪ್ಸ್ಟ್ರೀಮ್ ಸ್ಟ್ರೀಮ್ ತೆರೆಯುವ ಮುನ್ನವೇ ಅದನ್ನು ಕರೆಯುತ್ತದೆ.

## `cursor-api` ಪ್ರೊವೈಡರ್

ರಿಜಿಸ್ಟ್ರಿ: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, `cursor` ನಂತೆಯೇ ಅದೇ `format`, `baseUrl` ಮತ್ತು `models`). ಕ್ಯಾಟಲಾಗ್ ಕಾರ್ಡ್:
`src/shared/constants/providers/apikey/specialty-media.ts`. ಎಕ್ಸಿಕ್ಯೂಟರ್ ಮ್ಯಾಪ್:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

ಡ್ಯಾಶ್ಬೋರ್ಡ್: Providers → Cursor API → Add API key.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

ನಂತರ:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

ಟಿಪ್ಪಣಿಗಳು:

- `cursor-api` ಗಾಗಿ ಮಾದರಿ ಪಟ್ಟಿಯು ಸ್ಥಿರ Cursor ರಿಜಿಸ್ಟ್ರಿಯಿಂದ ಬರುತ್ತದೆ (IDE ಪ್ರೊವೈಡರ್ ಫಾಲ್ಬ್ಯಾಕ್ ಆಗಿ ಬಳಸುವ ಅದೇ ಪಟ್ಟಿ); OmniRoute ಹೋಸ್ಟ್ನಲ್ಲಿ `cursor-agent` ಇನ್ಸ್ಟಾಲ್ ಮಾಡುವ ಅಗತ್ಯವಿಲ್ಲ.
- `POST /api/providers/{id}/refresh-cursor` ಕೇವಲ `cursor` IDE ಪ್ರೊವೈಡರ್ಗಾಗಿ; `cursor-api` ಸಂಪರ್ಕಗಳಲ್ಲಿ ನವೀಕರಿಸಲು IDE ಸೆಷನ್ ಇರುವುದಿಲ್ಲ.

## Cursor CLI ಪಾಸ್ಥ್ರೂ

ರೂಟ್: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. `/api/cursor-cli/` ಪ್ರಿಫಿಕ್ಸ್ ಅನ್ನು `src/shared/constants/publicApiRoutes.ts` ನಲ್ಲಿ ನೋಂದಾಯಿಸಲಾಗಿದೆ, ಏಕೆಂದರೆ ಹ್ಯಾಂಡ್ಲರ್ ತನ್ನದೇ ದೃಢೀಕರಣವನ್ನು ಜಾರಿಗೊಳಿಸುತ್ತದೆ:

| ಪಥ                                                                                                                             | CLI ಯಿಂದ ನಿರೀಕ್ಷಿಸಲಾದ ದೃಢೀಕರಣ | OmniRoute ಏನು ಮಾಡುತ್ತದೆ                                                                                                                                                                                                  |
| ------------------------------------------------------------------------------------------------------------------------------ | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `POST /auth/exchange_user_api_key`                                                                                             | `Bearer <OmniRoute API key>`  | ಕೀಲಿಯನ್ನು ಮೌಲ್ಯೀಕರಿಸುತ್ತದೆ, 1h HS256 JWT ಅನ್ನು (`JWT_SECRET` ನೊಂದಿಗೆ ಸಹಿ ಮಾಡಲಾಗಿದೆ) ರಚಿಸಿ ಹಿಂತಿರುಗಿಸುತ್ತದೆ                                                                                                               |
| ಇತರೆ ಪ್ರತಿಯೊಂದು ಪಥ (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`           | ಇಷ್ಯೂವರ್/ಆಡಿಯನ್ಸ್/ಅವಧಿ ಮುಕ್ತಾಯವನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ, ಸಕ್ರಿಯ `cursor-api` ಸಂಪರ್ಕವನ್ನು ಆಯ್ಕೆಮಾಡುತ್ತದೆ, Authorization ಹೆಡರ್ ಅನ್ನು ವಿನಿಮಯ ಮಾಡಿದ Cursor ಟೋಕನ್ನಿಂದ ಬದಲಾಯಿಸುತ್ತದೆ ಮತ್ತು ಪ್ರತ್ಯುತ್ತರವನ್ನು ಮರಳಿ ಸ್ಟ್ರೀಮ್ ಮಾಡುತ್ತದೆ |

CLI ತಾನು ಸ್ವೀಕರಿಸುವ ಯಾವುದೇ ಟೋಕನ್ನಿಂದ `exp` ಅನ್ನು ಡಿಕೋಡ್ ಮಾಡುತ್ತದೆ, ಆದ್ದರಿಂದ ಅದಕ್ಕೆ ಅಪಾರದರ್ಶಕ ಟೋಕನ್ ನೀಡುವುದರಿಂದ ಬಹುತೇಕ ಪ್ರತಿಯೊಂದು ವಿನಂತಿಗೂ ಮುನ್ನ ಅದು ಪುನಃ ವಿನಿಮಯ ಮಾಡುತ್ತದೆ; ರಚಿಸಲಾದ JWT ಇದನ್ನು ತಪ್ಪಿಸುತ್ತದೆ. OmniRoute ನಿಂದ ಬರುವ 401, CLI ಮತ್ತೆ ವಿನಿಮಯ ಮಾಡುವಂತೆ ಮಾಡುತ್ತದೆ.

### ಸೆಟಪ್

1. OmniRoute API ಕೀಲಿಯನ್ನು (Dashboard → API keys) ಮತ್ತು `cursor-api` ಸಂಪರ್ಕವನ್ನು ರಚಿಸಿ.
2. ಏಜೆಂಟ್ ಸ್ಟ್ರೀಮ್ಗಾಗಿ HTTP/1.1 ಬಳಸುವಂತೆ CLI ಗೆ ಸೂಚಿಸಿ. `~/.cursor/cli-config.json` ನಲ್ಲಿ:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   ಇದಿಲ್ಲದೆ CLI ಪ್ರತ್ಯೇಕವಾಗಿ ಕಾನ್ಫಿಗರ್ ಮಾಡಿದ ಏಜೆಂಟ್ ಹೋಸ್ಟ್ಗೆ HTTP/2 ಮೂಲಕ ಏಜೆಂಟ್ ಟರ್ನ್ ಅನ್ನು ತೆರೆಯುತ್ತದೆ ಮತ್ತು ಕೇವಲ ಕಂಟ್ರೋಲ್-ಪ್ಲೇನ್ RPC ಗಳು ಮಾತ್ರ ಎಂಡ್ಪಾಯಿಂಟ್ ಮೂಲಕ ಸಾಗುತ್ತವೆ.

3. OmniRoute ವಿರುದ್ಧ CLI ಅನ್ನು ಚಲಾಯಿಸಿ:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

ಪ್ರತಿಯೊಂದು ಹಾಪ್ ಕೂಡ `cursor-api` ಪ್ರೊವೈಡರ್, `cursor-cli` ವಿನಂತಿ ಪ್ರಕಾರ ಮತ್ತು `/api/cursor-cli/<rpc>` ಪಥದೊಂದಿಗೆ Logs ನಲ್ಲಿ ದಾಖಲಾಗುತ್ತದೆ ಹಾಗೂ ಅದನ್ನು ಪೂರೈಸಿದ OmniRoute API ಕೀ ಮತ್ತು ಸಂಪರ್ಕಕ್ಕೆ ಸಂಬಂಧಿಸಲಾಗುತ್ತದೆ.

### ವೈಫಲ್ಯ ವಿಧಾನಗಳು

| ಪರಿಸ್ಥಿತಿ                                        | CLIಗೆ ಪ್ರತಿಕ್ರಿಯೆ                                            |
| ------------------------------------------------ | ------------------------------------------------------------ |
| ಅಜ್ಞಾತ OmniRoute ಕೀ ಮತ್ತು `REQUIRE_API_KEY=true` | ವಿನಿಮಯದಲ್ಲಿ 401 `unauthenticated`                            |
| `REQUIRE_API_KEY=false`                          | ಅನಾಮಧೇಯ ಸೆಷನ್ (`/v1/*` ನಡವಳಿಕೆಯನ್ನು ಪ್ರತಿಬಿಂಬಿಸುತ್ತದೆ)       |
| ಅವಧಿ ಮೀರಿದ / ಬಾಹ್ಯ / ತಿರುಚಲಾದ ಸೆಷನ್ JWT          | 401, CLI ಮರು-ವಿನಿಮಯ ಮಾಡುತ್ತದೆ                                |
| ವಿನಿಮಯದ ನಂತರ OmniRoute API ಕೀ ಹಿಂಪಡೆಯಲಾಗಿದೆ      | ಮುಂದಿನ RPCಯಲ್ಲಿ 401                                          |
