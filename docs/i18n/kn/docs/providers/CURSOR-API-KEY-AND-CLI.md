IDE ಸೆಷನ್ ಇಲ್ಲದೆ Cursor ಅನ್ನು OmniRoute ಹಿಂದೆ ಇರಿಸಲು ಎರಡು ಮಾರ್ಗಗಳಿವೆ:

1. **`cursor-api` ಪ್ರೊವೈಡರ್** (ಕಾರ್ಡ್ "Cursor API", ಅಲಿಯಾಸ್ `cua`): Cursor ಬಳಕೆದಾರ API ಕೀ (`crsr_…`, `https://cursor.com/dashboard/api` ನಲ್ಲಿ ರಚಿಸಲಾಗಿದೆ) ಹೊಂದಿರುವ API-ಕೀ ಪ್ರೊವೈಡರ್. ನಂತರ ಯಾವುದೇ OmniRoute ಕ್ಲೈಂಟ್ ಸಾಮಾನ್ಯ ಕೋಟಾ, ಫಾಲ್ಬ್ಯಾಕ್ ಮತ್ತು ಲಾಗಿಂಗ್ ಲೇಯರ್ಗಳೊಂದಿಗೆ `/v1/chat/completions` ಮೂಲಕ `cursor-api/<model>` ಅಥವಾ `cua/<model>` ಆಗಿ Cursor ಮಾಡೆಲ್ಗಳನ್ನು ಪ್ರವೇಶಿಸುತ್ತದೆ. IDE ಪ್ರೊವೈಡರ್ (`cursor`, OAuth/IDE ಸೆಷನ್) ಬದಲಾಗಿಲ್ಲ.
2. **Cursor CLI ಪಾಸ್ಥ್ರೂ**: Cursor CLI (`agent`) ಅನ್ನು OmniRoute ಕಡೆಗೆ ನಿರ್ದೇಶಿಸಿ; ಇದರಿಂದ CLI ಮಾಡುವ ಪ್ರತಿಯೊಂದು RPC ಅನ್ನು OmniRoute API ಕೀಯೊಂದಿಗೆ ದೃಢೀಕರಿಸಲಾಗುತ್ತದೆ, `cursor-api` ಸಂಪರ್ಕದ ಕ್ರೆಡೆನ್ಶಿಯಲ್ನೊಂದಿಗೆ Cursor ಗೆ ಫಾರ್ವರ್ಡ್ ಮಾಡಲಾಗುತ್ತದೆ ಮತ್ತು Logs ಪುಟದಲ್ಲಿ ದಾಖಲಿಸಲಾಗುತ್ತದೆ.

## ಕೀಯನ್ನು ಏಕೆ ವಿನಿಮಯ ಮಾಡಲಾಗುತ್ತದೆ

`api2.cursor.sh` ಕಚ್ಚಾ `crsr_…` ಕೀಯನ್ನು Bearer ಟೋಕನ್ ಆಗಿ ತಿರಸ್ಕರಿಸುತ್ತದೆ (401). Cursor CLI ಮೊದಲು ಕೀಯನ್ನು `/auth/exchange_user_api_key` ಗೆ POST ಮಾಡುತ್ತದೆ ಮತ್ತು ಒಂದು ಗಂಟೆಯ ನಂತರ ಅವಧಿ ಮುಗಿಯುವ ಸೆಷನ್ JWT ಅನ್ನು ಪಡೆಯುತ್ತದೆ; ಹಿಂದಿರುಗಿಸಲಾದ `refreshToken` ಅದೇ `exp` ಅನ್ನು ಹೊಂದಿರುವುದರಿಂದ, ರಿಫ್ರೆಶ್ ಮಾಡುವುದು ಎಂದರೆ ಕೀಯನ್ನು ಮರು-ವಿನಿಮಯ ಮಾಡುವುದು.
`open-sse/services/cursorApiKeyAuth.ts` ಆ ವಿನಿಮಯವನ್ನು ಮಾಡುತ್ತದೆ, ಪ್ರತಿ ಕೀಗೆ ಒಂದು ಸೆಷನ್ ಟೋಕನ್ ಅನ್ನು ಕ್ಯಾಶ್ ಮಾಡುತ್ತದೆ, ಅವಧಿ ಮುಗಿಯುವ ಐದು ನಿಮಿಷಗಳ ಮೊದಲು ಮರು-ವಿನಿಮಯ ಮಾಡುತ್ತದೆ ಮತ್ತು Cursor 401 ಉತ್ತರಿಸಿದಾಗ ಕ್ಯಾಶ್ ಮಾಡಿದ ಟೋಕನ್ ಅನ್ನು ತೆಗೆದುಹಾಕುತ್ತದೆ. `CursorExecutor`, `cursor-api` ಸಂಪರ್ಕಗಳಿಗೆ ಅಪ್ಸ್ಟ್ರೀಮ್ ಸ್ಟ್ರೀಮ್ ತೆರೆಯುವ ಸ್ವಲ್ಪ ಮೊದಲು ಅದನ್ನು ಕರೆಯುತ್ತದೆ.

## `cursor-api` ಪ್ರೊವೈಡರ್

ರಿಜಿಸ್ಟ್ರಿ: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, `cursor` ನಂತೆಯೇ ಅದೇ `format`, `baseUrl` ಮತ್ತು
`models`). ಕ್ಯಾಟಲಾಗ್ ಕಾರ್ಡ್:
`src/shared/constants/providers/apikey/specialty-media.ts`. ಎಕ್ಸಿಕ್ಯೂಟರ್ ಮ್ಯಾಪ್:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

ಡ್ಯಾಶ್ಬೋರ್ಡ್: Providers → Cursor API → Add API key.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

ನಂತರ:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

ಟಿಪ್ಪಣಿಗಳು:

- `cursor-api` ಗಾಗಿ ಮಾಡೆಲ್ ಪಟ್ಟಿ ಸ್ಥಿರ Cursor ರಿಜಿಸ್ಟ್ರಿಯಿಂದ ಬರುತ್ತದೆ (IDE ಪ್ರೊವೈಡರ್ ಫಾಲ್ಬ್ಯಾಕ್ ಆಗಿ ಬಳಸುವ ಅದೇ ಪಟ್ಟಿ); OmniRoute ಹೋಸ್ಟ್ನಲ್ಲಿ `cursor-agent` ಇನ್ಸ್ಟಾಲ್ ಮಾಡುವ ಅಗತ್ಯವಿಲ್ಲ.
- `POST /api/providers/{id}/refresh-cursor` ಕೇವಲ `cursor` IDE ಪ್ರೊವೈಡರ್ಗಾಗಿ; `cursor-api` ಸಂಪರ್ಕಗಳು ನವೀಕರಿಸಲು IDE ಸೆಷನ್ ಹೊಂದಿರುವುದಿಲ್ಲ.

## ಮೂಲ ಮಾಡೆಲ್ IDಗಳು ಮತ್ತು ಪ್ರಯತ್ನದ ಮಟ್ಟ

`cursor` / `cu` ಮತ್ತು `cursor-api` / `cua` ಗಾಗಿ, ಹಂಚಿಕೆಯ Claude-effort ನಾರ್ಮಲೈಸರ್ ವಿನಂತಿಸಿದ ಮಾಡೆಲ್ ID ಅನ್ನು ಹಾಗೆಯೇ ಉಳಿಸುತ್ತದೆ. OmniRoute ಪ್ರಯತ್ನದ ಅಲಿಯಾಸ್ ಆಗಿರುವುದಕ್ಕಿಂತ ಭಿನ್ನವಾಗಿ, Cursor ನೈಜ ಮಾಡೆಲ್ IDಯ ಭಾಗವಾಗಿ `-low` ನಂತಹ ಸಫಿಕ್ಸ್ ಅನ್ನು ಪ್ರಕಟಿಸಬಹುದು.
Cursor ಎಕ್ಸಿಕ್ಯೂಟರ್ ನಿಖರವಾದ ಲೈವ್-ಕ್ಯಾಟಲಾಗ್ ಹೊಂದಾಣಿಕೆಯನ್ನು ಉಳಿಸುತ್ತದೆ; ಹೊಂದಾಣಿಕೆ ಇಲ್ಲದಿದ್ದಾಗ, ಅದರ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಮಾಡೆಲ್ ರಿಸಾಲ್ವರ್ ಸಫಿಕ್ಸ್ನಿಂದ ಪ್ಯಾರಾಮೀಟರ್ಗೆ ಫಾಲ್ಬ್ಯಾಕ್ ಅನ್ನು ನಿರ್ವಹಿಸುತ್ತದೆ.

ಇದು ನೇರ Claude, Claude-ಹೊಂದಾಣಿಕೆಯ ಅಥವಾ Vertex ರೂಟ್ಗಳ ಪ್ರಯತ್ನದ ನಾರ್ಮಲೈಸೇಶನ್ ಅನ್ನು ಬದಲಾಯಿಸುವುದಿಲ್ಲ. ಲಭ್ಯತೆಯು ಇನ್ನೂ ಆಯ್ಕೆಮಾಡಿದ Cursor ಖಾತೆಯ ಕ್ಯಾಟಲಾಗ್ ಮತ್ತು ಅರ್ಹತೆಯ ಮೇಲೆ ಅವಲಂಬಿತವಾಗಿರುತ್ತದೆ.

## Cursor CLI ಪಾಸ್ಥ್ರೂ

ರೂಟ್: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. `/api/cursor-cli/` ಪೂರ್ವಪ್ರತ್ಯಯವನ್ನು
`src/shared/constants/publicApiRoutes.ts` ನಲ್ಲಿ ನೋಂದಾಯಿಸಲಾಗಿದೆ, ಏಕೆಂದರೆ ಹ್ಯಾಂಡ್ಲರ್
ತನ್ನದೇ ದೃಢೀಕರಣವನ್ನು ಜಾರಿಗೊಳಿಸುತ್ತದೆ:

| ಪಥ                                                                                                                            | CLI ನಿಂದ ನಿರೀಕ್ಷಿತ ದೃಢೀಕರಣ   | OmniRoute ಏನು ಮಾಡುತ್ತದೆ                                                                                                                                                                         |
| ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                            | `Bearer <OmniRoute API key>` | ಕೀಲಿಯನ್ನು ಮೌಲ್ಯೀಕರಿಸಿ, 1 ಗಂಟೆಯ HS256 JWT ಅನ್ನು (`JWT_SECRET` ಬಳಸಿ ಸಹಿ ಮಾಡಲಾದ) ರಚಿಸಿ ಅದನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ                                                                                     |
| ಇತರ ಪ್ರತಿಯೊಂದು ಪಥ (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`          | ವಿತರಕ/ಪ್ರೇಕ್ಷಕರು/ಅವಧಿ ಮುಕ್ತಾಯವನ್ನು ಪರಿಶೀಲಿಸಿ, ಸಕ್ರಿಯ `cursor-api` ಸಂಪರ್ಕವನ್ನು ಆಯ್ಕೆಮಾಡಿ, Authorization ಹೆಡರ್ ಅನ್ನು ವಿನಿಮಯಗೊಂಡ Cursor ಟೋಕನ್ನಿಂದ ಬದಲಿಸಿ, ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು ಮರಳಿ ಸ್ಟ್ರೀಮ್ ಮಾಡುತ್ತದೆ |

CLI ತಾನು ಸ್ವೀಕರಿಸುವ ಯಾವುದೇ ಟೋಕನ್ನಿಂದ `exp` ಅನ್ನು ಡಿಕೋಡ್ ಮಾಡುತ್ತದೆ, ಆದ್ದರಿಂದ ಅದಕ್ಕೆ ಅಪಾರದರ್ಶಕ
ಟೋಕನ್ ನೀಡಿದರೆ ಬಹುತೇಕ ಪ್ರತಿಯೊಂದು ವಿನಂತಿಗೂ ಮೊದಲು ಅದು ಮರು-ವಿನಿಮಯ ಮಾಡುತ್ತದೆ; ರಚಿಸಲಾದ JWT
ಇದನ್ನು ತಪ್ಪಿಸುತ್ತದೆ. OmniRoute ನಿಂದ ಬರುವ 401 CLI ಮತ್ತೆ ವಿನಿಮಯ ಮಾಡುವಂತೆ ಮಾಡುತ್ತದೆ.

### ಸೆಟಪ್

1. OmniRoute API ಕೀಲಿಯನ್ನು (Dashboard → API keys) ಮತ್ತು `cursor-api`
   ಸಂಪರ್ಕವನ್ನು ರಚಿಸಿ.
2. ಏಜೆಂಟ್ ಸ್ಟ್ರೀಮ್ಗಾಗಿ HTTP/1.1 ಬಳಸುವಂತೆ CLI ಗೆ ಸೂಚಿಸಿ.
   `~/.cursor/cli-config.json` ನಲ್ಲಿ:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   ಇದು ಇಲ್ಲದಿದ್ದರೆ, CLI ಪ್ರತ್ಯೇಕವಾಗಿ ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾದ ಏಜೆಂಟ್ ಹೋಸ್ಟ್ಗೆ HTTP/2 ಮೂಲಕ
   ಏಜೆಂಟ್ ಟರ್ನ್ ಅನ್ನು ತೆರೆಯುತ್ತದೆ ಮತ್ತು ಕಂಟ್ರೋಲ್-ಪ್ಲೇನ್ RPC ಗಳು ಮಾತ್ರ
   ಎಂಡ್ಪಾಯಿಂಟ್ ಮೂಲಕ ಸಾಗುತ್ತವೆ.

3. OmniRoute ವಿರುದ್ಧ CLI ಅನ್ನು ಚಲಾಯಿಸಿ:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

ಪ್ರತಿಯೊಂದು ಹಾಪ್ Logs ನಲ್ಲಿ ಪೂರೈಕೆದಾರ `cursor-api`, ವಿನಂತಿ ಪ್ರಕಾರ `cursor-cli`,
ಪಥ `/api/cursor-cli/<rpc>` ಆಗಿ ದಾಖಲಾಗುತ್ತದೆ ಮತ್ತು ಅದಕ್ಕೆ OmniRoute API ಕೀಲಿ ಹಾಗೂ
ಅದನ್ನು ನಿರ್ವಹಿಸಿದ ಸಂಪರ್ಕವನ್ನು ಹೊಂದಿಸಲಾಗುತ್ತದೆ.
