> **ಪ್ರತಿ ಪ್ರಾಕ್ಸಿಗೆ ಹೊರಹೋಗುವ ಟ್ರಾಫಿಕ್ ಅನ್ನು ಒಂದೇ IP ಕುಟುಂಬಕ್ಕೆ — `auto`, `ipv4`, ಅಥವಾ `ipv6` — ಪಿನ್ ಮಾಡಿ, ಇದರಿಂದ IPv6-ಮಾತ್ರದ ಎಗ್ರೆಸ್ ಎಂದಿಗೂ ಸದ್ದಿಲ್ಲದೆ IPv4ಗೆ ಮರಳಿ ಸೋರಿಕೆಯಾಗುವುದಿಲ್ಲ.**

> **ಅಧಿಕೃತ ಮೂಲ:** `open-sse/utils/proxyFamily.ts`, `open-sse/utils/proxyDispatcher.ts`, `open-sse/utils/proxyFetch.ts`, `open-sse/utils/socksConnectorWithFamily.ts`, `open-sse/utils/proxyFamilyResolve.ts`, `src/shared/validation/schemas.ts`, `src/lib/db/proxies.ts`, `src/lib/db/upstreamProxy.ts`, `src/lib/db/migrations/099_proxy_family.sql`

OmniRoute ಪ್ರತಿ ಪ್ರಾಕ್ಸಿಗೂ ಒಂದು **ವಿಳಾಸ-ಕುಟುಂಬ ಎಗ್ರೆಸ್ ನಿರ್ದೇಶನ** ಹೊಂದಲು ಅವಕಾಶ ನೀಡುತ್ತದೆ. ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ OS IPv4 ಅಥವಾ IPv6 ಅನ್ನು ಆಯ್ಕೆಮಾಡುತ್ತದೆ (ಡ್ಯುಯಲ್-ಸ್ಟ್ಯಾಕ್, "Happy Eyeballs"). ನೀವು ನಿರ್ದೇಶನವನ್ನು `ipv4` ಅಥವಾ `ipv6`ಗೆ ಹೊಂದಿಸಿದಾಗ, OmniRoute ಆ ಪ್ರಾಕ್ಸಿ ಮೂಲಕದ ಪ್ರತಿಯೊಂದು ಸಂಪರ್ಕವನ್ನೂ ಆಯ್ಕೆಮಾಡಿದ ಕುಟುಂಬಕ್ಕೆ ಪಿನ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ಇನ್ನೊಂದು ಕುಟುಂಬಕ್ಕೆ ಹಿಂತಿರುಗುವ ಬದಲು **ವಿಫಲವಾದಾಗ ಮುಚ್ಚುತ್ತದೆ**.

ಈ ಪುಟವು ನಿರ್ದೇಶನ ಎಂದರೇನು, ಅದು ಏಕೆ ಅಸ್ತಿತ್ವದಲ್ಲಿದೆ, ಅದನ್ನು ಎಲ್ಲಿ ಸಂರಚಿಸಬೇಕು ಮತ್ತು ರನ್ಟೈಮ್ ಅದನ್ನು ಹೇಗೆ ಪರಿಹರಿಸುತ್ತದೆ ಎಂಬುದನ್ನು ದಾಖಲಿಸುತ್ತದೆ.

## ಇದು ಏನು

ರಿಜಿಸ್ಟ್ರಿಯಲ್ಲಿನ ಪ್ರತಿಯೊಂದು ಪ್ರಾಕ್ಸಿಯೂ ಮೂರು ಸಂಭಾವ್ಯ ಮೌಲ್ಯಗಳನ್ನು ಹೊಂದಿರುವ `family` ಕ್ಷೇತ್ರವನ್ನು ಹೊಂದಿದೆ; ಇದನ್ನು Zod enum ಮೂಲಕ ಮೌಲ್ಯೀಕರಿಸಲಾಗುತ್ತದೆ:

```ts
// src/shared/validation/schemas.ts
family: z.enum(["auto", "ipv4", "ipv6"]).optional().default("auto"),
```

ಈ ಕ್ಷೇತ್ರದ ಪೂರ್ವನಿಯೋಜಿತ ಮೌಲ್ಯ `"auto"` ಆಗಿದ್ದು, ಇದು ಹಿಂದಿನ ಡ್ಯುಯಲ್-ಸ್ಟ್ಯಾಕ್ ನಡವಳಿಕೆಯನ್ನು ಉಳಿಸುತ್ತದೆ. ಇದನ್ನು `ipv4` ಅಥವಾ `ipv6`ಗೆ ಹೊಂದಿಸುವುದರಿಂದ ಆ ಪ್ರಾಕ್ಸಿಯ ಸಂಪರ್ಕ ಕುಟುಂಬವು ಪಿನ್ ಆಗುತ್ತದೆ.

ಯಾವುದೇ ಅಪರಿಚಿತ ಮೌಲ್ಯವು `auto`ಗೆ ಸಂಕುಚಿತವಾಗುವಂತೆ, ನಿರ್ದೇಶನವನ್ನು ಎಲ್ಲೆಡೆಯೂ ಒಂದೇ ಸಹಾಯಕದ ಮೂಲಕ ಸಾಮಾನ್ಯೀಕರಿಸಲಾಗುತ್ತದೆ:

```ts
// open-sse/utils/proxyFamily.ts
export type ProxyFamily = "auto" | "ipv4" | "ipv6";

export function parseProxyFamily(value: unknown): ProxyFamily {
  return value === "ipv4" || value === "ipv6" ? value : "auto";
}
```

## ಇದು ಏಕೆ ಅಸ್ತಿತ್ವದಲ್ಲಿದೆ

PR [#3777](https://github.com/diegosouzapw/OmniRoute/pull/3777)ನಲ್ಲಿ ಪರಿಚಯಿಸಲಾಗಿದೆ. ಇದಕ್ಕೆ ಪ್ರೇರಣೆಯಾದ ಸಮಸ್ಯೆಗಳು:

| ಸಮಸ್ಯೆ                                         | ನಿರ್ದೇಶನವು ಸರಿಪಡಿಸುವುದು                                                                                                                                                                                                                                                                                                                                  |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **IPv6-ಮಾತ್ರದ ಎಗ್ರೆಸ್ IPv4ಗೆ ಸೋರಿಕೆಯಾಗುವುದು**  | ಪ್ರಾಕ್ಸಿ ಹೋಸ್ಟ್ A ಮತ್ತು AAAA ದಾಖಲೆಗಳೆರಡನ್ನೂ ಹೊಂದಿರುವಾಗ (ಅಥವಾ OS IPv4ಗೆ ಆದ್ಯತೆ ನೀಡಿದಾಗ), ನೀವು IPv6-ಮಾತ್ರದ ಮಾರ್ಗವನ್ನು ಉದ್ದೇಶಿಸಿದ್ದರೂ Happy Eyeballs IPv4 ಮೂಲಕ ಹೊರಹೋಗುವ ಸಂಪರ್ಕವನ್ನು ಸ್ಥಾಪಿಸಬಹುದು. `ipv6`ಗೆ ಪಿನ್ ಮಾಡುವುದರಿಂದ ಆ ಸೋರಿಕೆ ನಿವಾರಣೆಯಾಗುತ್ತದೆ.                                                                                                      |
| **ಹಂಚಿಕೊಂಡ ಎಗ್ರೆಸ್ ವೈಪರೀತ್ಯದಿಂದ ಹಿಂಪಡೆಯುವಿಕೆ** | ಅನೇಕ ಖಾತೆಗಳು ಹೆಚ್ಚಿನ ಪ್ರಮಾಣದಲ್ಲಿ **ಒಂದೇ** IP ಮೂಲಕ ಹೊರಹೋದಾಗ, ರೊಟೇಟಿಂಗ್ ಪೂರೈಕೆದಾರರು (codex/openai) ಟೋಕನ್ಗಳನ್ನು ಹಿಂಪಡೆಯುತ್ತಾರೆ. ಖಾತೆಗಳನ್ನು ಪ್ರತ್ಯೇಕವಾದ, ಊಹಿಸಬಹುದಾದ ಎಗ್ರೆಸ್ ಮಾರ್ಗಗಳಲ್ಲಿ ಇರಿಸುವುದರ ಒಂದು ಭಾಗವೇ ಎಗ್ರೆಸ್ ಕುಟುಂಬವನ್ನು ನಿಯಂತ್ರಿಸುವುದು (ಇದರೊಂದಿಗೆ ಬಳಸುವ ಎಗ್ರೆಸ್-IP ರೋಗನಿರ್ಣಯಗಳಿಗಾಗಿ [`src/lib/proxyEgress.ts`](../../src/lib/proxyEgress.ts) ನೋಡಿ). |
| **ಅನುಸರಣೆ/ಪರೀಕ್ಷೆಗಾಗಿ ನಿರ್ಣಾಯಕ ಎಗ್ರೆಸ್**       | ಟ್ರಾಫಿಕ್ ನಿರ್ದಿಷ್ಟ ಕುಟುಂಬದ ಮೂಲಕವೇ ಹೊರಹೋಗುತ್ತದೆ ಎಂದು ನೀವು ಖಾತರಿಪಡಿಸಬೇಕಾದಾಗ, `auto` ಸಾಕಾಗುವುದಿಲ್ಲ.                                                                                                                                                                                                                                                         |

ಈ ನಿರ್ದೇಶನವು ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ **ಪ್ರತಿ-ಪ್ರಾಕ್ಸಿಗೆ** ಅನ್ವಯಿಸುತ್ತದೆ, ಜಾಗತಿಕವಾಗಿ ಅಲ್ಲ — ನಿಮ್ಮ ಪೂಲ್ನಲ್ಲಿರುವ ವಿಭಿನ್ನ ಪ್ರಾಕ್ಸಿಗಳು ವಿಭಿನ್ನ ನೀತಿಗಳನ್ನು ಹೊಂದಿರಬಹುದು.

## ಇದನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡುವುದು ಹೇಗೆ

### ಡ್ಯಾಶ್ಬೋರ್ಡ್

ಸೆಲೆಕ್ಟರ್ **Proxy Pool** ಟ್ಯಾಬ್ನ ಪ್ರಾಕ್ಸಿ ಫಾರ್ಮ್ನಲ್ಲಿದೆ:

1. **Dashboard → Settings → Proxy → Proxy Pool** ತೆರೆಯಿರಿ
2. ಪ್ರಾಕ್ಸಿಯನ್ನು ಸೇರಿಸಿ ಅಥವಾ ಸಂಪಾದಿಸಿ
3. **IP ಫ್ಯಾಮಿಲಿ** ಡ್ರಾಪ್ಡೌನ್ ಅನ್ನು `ಸ್ವಯಂ (ಡ್ಯುಯಲ್-ಸ್ಟ್ಯಾಕ್)`, `IPv4 ಮಾತ್ರ`, ಅಥವಾ `IPv6 ಮಾತ್ರ` ಎಂದು ಹೊಂದಿಸಿ
4. ಉಳಿಸಿ

ಈ ಕಂಟ್ರೋಲ್ ಅನ್ನು `ProxyRegistryManager.tsx` ರೆಂಡರ್ ಮಾಡುತ್ತದೆ (`proxy/ProxyPoolTab.tsx` ನಲ್ಲಿ ಮೌಂಟ್ ಮಾಡಲಾಗಿದೆ).

### API

`family` ಫೀಲ್ಡ್ ಪ್ರಾಕ್ಸಿ ರಿಜಿಸ್ಟ್ರಿ ರಚನೆ/ನವೀಕರಣ ಪೇಲೋಡ್ಗಳ ಭಾಗವಾಗಿದ್ದು, `createProxyRegistrySchema` / `updateProxyRegistrySchema` (`src/shared/validation/schemas.ts`) ಮೂಲಕ ಮೌಲ್ಯೀಕರಿಸಲ್ಪಡುತ್ತದೆ ಮತ್ತು `POST` / `PATCH /api/v1/management/proxies` ಮೂಲಕ ನಿರ್ವಹಿಸಲ್ಪಡುತ್ತದೆ:

```bash
# IPv6-ಮಾತ್ರ ಪ್ರಾಕ್ಸಿಯನ್ನು ರಚಿಸಿ
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "IPv6 egress",
    "type": "socks5",
    "host": "proxy.example.com",
    "port": 1080,
    "family": "ipv6"
  }'

# ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಪ್ರಾಕ್ಸಿಯನ್ನು IPv4-ಮಾತ್ರಕ್ಕೆ ಬದಲಾಯಿಸಿ
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{ "id": "proxy-uuid-here", "family": "ipv4" }'
```

ಅಪ್ಸ್ಟ್ರೀಮ್-ಪ್ರಾಕ್ಸಿ ನಮೂದುಗಳಿಗಾಗಿ ಬಳಸುವ ಇನ್ಲೈನ್ ಪ್ರಾಕ್ಸಿ ಕಾನ್ಫಿಗ್ ಆಬ್ಜೆಕ್ಟ್ನಲ್ಲಿಯೂ ಇದೇ ಫೀಲ್ಡ್ ಅನ್ನು ಸ್ವೀಕರಿಸಲಾಗುತ್ತದೆ (`upstream_proxy_config.family`, [ಡೇಟಾ ಮಾದರಿ](#data-model) ನೋಡಿ).

ಉಳಿದ ಪ್ರಾಕ್ಸಿ CRUD/ನಿಯೋಜನೆ API ಕುರಿತು ತಿಳಿಯಲು, [PROXY_GUIDE.md](../ops/PROXY_GUIDE.md) ನೋಡಿ.

## `auto` ಹೇಗೆ ಪರಿಹರಿಸುತ್ತದೆ

`family` ಎಂಬುದು `auto` ಆಗಿದ್ದಾಗ, OmniRoute ಯಾವುದೇ ಡೈರೆಕ್ಟಿವ್ ಅನ್ನು ಸೇರಿಸುವುದಿಲ್ಲ — ಪ್ರಾಕ್ಸಿ URL ಅನ್ನು ಇದ್ದಂತೆಯೇ ಬಳಸಲಾಗುತ್ತದೆ ಮತ್ತು ಸಂಪರ್ಕ ಫ್ಯಾಮಿಲಿಯನ್ನು ಅಂತರ್ಗತವಾಗಿ ನಿರ್ಧರಿಸಲಾಗುತ್ತದೆ.

URL ನಿರ್ಮಾಣದ ಸಮಯದಲ್ಲಿ (`open-sse/utils/proxyDispatcher.ts` ನಲ್ಲಿನ `proxyConfigToUrl` / `normalizeProxyUrl`), `auto` ಪ್ರಾಕ್ಸಿಯು ಯಾವುದೇ ಮಾರ್ಕರ್ ಇಲ್ಲದ ಸರಳ URL ಅನ್ನು ನೀಡುತ್ತದೆ:

```ts
// open-sse/utils/proxyDispatcher.ts
const fam = parseProxyFamily(config.family);
const normalized = normalizeProxyUrl(proxyUrlStr, "context proxy", {
  allowSocks5,
});
return fam === "auto" ? normalized : `${normalized}?family=${fam}`;
```

ಡಿಸ್ಪ್ಯಾಚ್ ಸಮಯದಲ್ಲಿ (`resolveDispatcherFamily`), `auto` ಎಂಬುದು IP-ಲಿಟರಲ್ ಹೋಸ್ಟ್ನ ಅಂತರ್ಗತ ಫ್ಯಾಮಿಲಿಗೆ, ಅಥವಾ ಹೋಸ್ಟ್ನೇಮ್ಗಾಗಿ `null` ಗೆ (OS ನಿರ್ಧರಿಸಲು ಬಿಡಿ) ಪರಿಹರಿಸುತ್ತದೆ:

```ts
// open-sse/utils/proxyDispatcher.ts
function resolveDispatcherFamily(parsed: URL): 4 | 6 | null {
  const directive = parseProxyFamily(parsed.searchParams.get("family") ?? undefined);
  const literal = detectIpLiteralFamily(parsed.hostname);
  if (directive === "auto") return literal; // ಹೋಸ್ಟ್ನೇಮ್ಗೆ null → OS ಆಯ್ಕೆಮಾಡುತ್ತದೆ
  // ...
}
```

ಆದ್ದರಿಂದ:

- `auto` + IP-ಲಿಟರಲ್ ಹೋಸ್ಟ್ (`192.0.2.1` / `[2001:db8::1]`) → ಆ ಲಿಟರಲ್ನ ಫ್ಯಾಮಿಲಿ.
- `auto` + ಹೋಸ್ಟ್ನೇಮ್ → `null` → ಪ್ರಮಾಣಿತ ಡ್ಯುಯಲ್-ಸ್ಟ್ಯಾಕ್ OS ಪರಿಹಾರ.

## `ipv4` / `ipv6` ಅನ್ನು ಹೇಗೆ ಜಾರಿಗೊಳಿಸಲಾಗುತ್ತದೆ

`auto` ಅಲ್ಲದ ನಿರ್ದೇಶನವು ಒಂದೇ ಸಂಶ್ಲೇಷಿತ ಕ್ವೆರಿ ಮಾರ್ಕರ್ ಆಗಿ ಸಾಗುತ್ತದೆ — `?family=ipv4` ಅಥವಾ `?family=ipv6` — ಇದನ್ನು ಸಾಮಾನ್ಯೀಕರಿಸಿದ ಪ್ರಾಕ್ಸಿ URLಗೆ ಒಮ್ಮೆ ಸೇರಿಸಲಾಗುತ್ತದೆ. ಪೋರ್ಟ್ ಪಾರ್ಸಿಂಗ್ ಎಂದಿಗೂ ಹಾಳಾಗದಂತೆ `normalizeProxyUrl` ಈ ಮಾರ್ಕರ್ ಅನ್ನು ನಿಖರವಾಗಿ ಒಮ್ಮೆ ತೆಗೆದುಹಾಕಿ, ಮತ್ತೆ ಸೇರಿಸುವಲ್ಲಿ ಎಚ್ಚರಿಕೆ ವಹಿಸುತ್ತದೆ.

ಡಿಸ್ಪ್ಯಾಚರ್ ಅನ್ನು ನಿರ್ಮಿಸಿದಾಗ, ಮಾರ್ಕರ್ ಅನ್ನು ಓದಿ ನಿರ್ದಿಷ್ಟ ಸಂಪರ್ಕ ಫ್ಯಾಮಿಲಿಯಾಗಿ ಪರಿವರ್ತಿಸಲಾಗುತ್ತದೆ. ಹೋಸ್ಟ್ **ವಿರುದ್ಧ** ಫ್ಯಾಮಿಲಿಯ IP ಲಿಟರಲ್ ಆಗಿದ್ದರೆ, OmniRoute ದೋಷವನ್ನು ಎಸೆಯುತ್ತದೆ (ವಿರೋಧಾಭಾಸವನ್ನು fail-closed ಆಗಿ ನಿರ್ವಹಿಸಲಾಗುತ್ತದೆ):

```ts
// open-sse/utils/proxyDispatcher.ts
const want = directive === "ipv6" ? 6 : 4;
if (literal !== null && literal !== want) {
  throw new Error(
    `[ProxyDispatcher] Proxy family directive ${directive} contradicts ${literal === 6 ? "IPv6" : "IPv4"} literal host`
  );
}
```

ನಂತರ ನಿರ್ದಿಷ್ಟ ಫ್ಯಾಮಿಲಿಯನ್ನು ಕನೆಕ್ಟರ್ನಲ್ಲಿ ಸ್ಥಿರಗೊಳಿಸಲಾಗುತ್ತದೆ:

- **HTTP/HTTPS ಪ್ರಾಕ್ಸಿಗಳು** (`ProxyAgent`): `proxyTls: { family, autoSelectFamily: false }` — Happy Eyeballs ಅನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಆಯ್ಕೆಮಾಡಿದ ಫ್ಯಾಮಿಲಿಗೆ ಮಾತ್ರ ಸಂಪರ್ಕಿಸಲು ಪ್ರಯತ್ನಿಸಲಾಗುತ್ತದೆ.
- **SOCKS5 ಪ್ರಾಕ್ಸಿಗಳು**: ಕಸ್ಟಮ್ ಕನೆಕ್ಟರ್ವೊಂದು `socket_options: { family, autoSelectFamily: false }` ಅನ್ನು SOCKS ಕ್ಲೈಂಟ್ಗೆ ರವಾನಿಸುತ್ತದೆ ([SOCKS5 ಹೊಂದಾಣಿಕೆ](#socks5-compatibility) ನೋಡಿ).

## SOCKS5 ಹೊಂದಾಣಿಕೆ

ಫ್ಯಾಮಿಲಿ ಸ್ಥಿರೀಕರಣವು SOCKS5 ಪ್ರಾಕ್ಸಿಗಳೊಂದಿಗೆ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ, ಆದರೆ ಪ್ರಾಕ್ಸಿ ಹಾಪ್ನ ಫ್ಯಾಮಿಲಿಯನ್ನು ಸ್ಥಿರಗೊಳಿಸಲು ಅಗತ್ಯವಾದ ಸಾಕೆಟ್ ಆಯ್ಕೆಗಳನ್ನು ಮೂಲ `fetch-socks` ಬಹಿರಂಗಪಡಿಸುವುದಿಲ್ಲ. ಅದಕ್ಕಾಗಿ OmniRoute ತನ್ನದೇ ಕನೆಕ್ಟರ್ ಅನ್ನು ಒದಗಿಸುತ್ತದೆ:

```ts
// open-sse/utils/socksConnectorWithFamily.ts
export function buildSocksFamilySocketOptions(family: 4 | 6 | null): Record<string, unknown> {
  if (family === 6) return { family: 6, autoSelectFamily: false };
  if (family === 4) return { family: 4, autoSelectFamily: false };
  return {};
}
```

`family` ಏನೇ ಇದ್ದರೂ (ಹೋಸ್ಟ್ನೇಮ್ ಮೂಲಕ `null` / `auto` ಸೇರಿದಂತೆ), ಎಲ್ಲಾ SOCKS5 ಡಿಸ್ಪ್ಯಾಚ್ಗಳು `createSocksDispatcherWithFamily` ಮೂಲಕ ಸಾಗುತ್ತವೆ: `buildSocksFamilySocketOptions(null)` `{}` ಅನ್ನು ನೀಡುತ್ತದೆ ಮತ್ತು IPv6-ಮಾತ್ರದ ಎಗ್ರೆಸ್ ನೀತಿಗೆ Happy Eyeballs IPv4 ಅನ್ನು ಆಯ್ಕೆಮಾಡದಂತೆ, ಅದೇ `SocksClient.createConnection` + TLS `buildConnector` ಮಾರ್ಗವನ್ನು `socket_options` ಸ್ಥಿರೀಕರಣದೊಂದಿಗೆ ಬಳಸಲಾಗುತ್ತದೆ.

SOCKS5 ಬೆಂಬಲವು ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ಸಕ್ರಿಯವಾಗಿದೆ (`ENABLE_SOCKS5_PROXY=false` ಮೂಲಕ ಹೊರಗುಳಿಯಬಹುದು); [PROXY_GUIDE.md → ಪರಿಸರ ಚರಗಳು](../ops/PROXY_GUIDE.md#environment-variables) ನೋಡಿ.

## Fail-Closed ನಡವಳಿಕೆ

ತಪ್ಪು ಫ್ಯಾಮಿಲಿಗೆ ಸದ್ದಿಲ್ಲದೆ ಹಿಂತಿರುಗುವ ಬದಲು ಅದನ್ನು **ನಿರಾಕರಿಸುವುದೇ** ಈ ನಿರ್ದೇಶನದ ಸಂಪೂರ್ಣ ಉದ್ದೇಶ. ಎರಡು ರಕ್ಷಣಾ ಕ್ರಮಗಳು ಇದನ್ನು ಜಾರಿಗೊಳಿಸುತ್ತವೆ:

1. **ಲಿಟರಲ್ ವಿರೋಧಾಭಾಸ** — IP-ಲಿಟರಲ್ ಹೋಸ್ಟ್ಗೆ ವಿರುದ್ಧವಾಗಿರುವ ನಿರ್ದೇಶನವು ಡಿಸ್ಪ್ಯಾಚರ್ ನಿರ್ಮಾಣದ ಸಮಯದಲ್ಲಿ ದೋಷವನ್ನು ಎಸೆಯುತ್ತದೆ (ಮೇಲೆ ತೋರಿಸಿರುವ `resolveDispatcherFamily`).

2. **ಹೋಸ್ಟ್ನೇಮ್ ಪೂರ್ವ-ಪ್ರಯಾಣ DNS ಪರಿಶೀಲನೆ** — ಸ್ಥಿರಗೊಳಿಸಿದ ಫ್ಯಾಮಿಲಿಯ ಹೋಸ್ಟ್ನೇಮ್ ಪ್ರಾಕ್ಸಿಗಾಗಿ, ಎಗ್ರೆಸ್ ಮಾಡುವ **ಮೊದಲೇ** ಅಗತ್ಯವಿರುವ ಫ್ಯಾಮಿಲಿಯಲ್ಲಿ ಆ ಹೋಸ್ಟ್ನೇಮ್ ನಿಜವಾಗಿಯೂ ದಾಖಲೆಯನ್ನು ಹೊಂದಿದೆಯೇ ಎಂಬುದನ್ನು `proxyFetch.ts`, `assertHostnameSupportsFamily` ಮೂಲಕ ಪರಿಶೀಲಿಸುತ್ತದೆ:

   ```ts
   // open-sse/utils/proxyFamilyResolve.ts
   const hasFamily = records.some((r) => r.family === family);
   if (!hasFamily) {
     throw new Error(
       `[ProxyFamily] Proxy host ${host} has no ${family === 6 ? "IPv6 (AAAA)" : "IPv4 (A)"} record; ` +
         `refusing ${family === 6 ? "IPv6" : "IPv4"}-only egress (fail-closed)`
     );
   }
   ```

   ವಿಫಲವಾದಾಗ, `proxyFetch.ts` ದೋಷಕ್ಕೆ `code = "PROXY_FAMILY_UNAVAILABLE"` ಮತ್ತು `statusCode = 503` ಎಂದು ಟ್ಯಾಗ್ ಮಾಡುತ್ತದೆ. DNS ರೆಸಲ್ಯೂಷನ್ ವೈಫಲ್ಯವನ್ನೂ ಇದೇ ರೀತಿ fail-closed ಆಗಿ ಪರಿಗಣಿಸಲಾಗುತ್ತದೆ (ಎಗ್ರೆಸ್ ಮಾಡಲು ನಿರಾಕರಿಸಲಾಗುತ್ತದೆ).

IP-ಲಿಟರಲ್ ಹೋಸ್ಟ್ಗಳಿಗೆ DNS ಪೂರ್ವ-ಪ್ರಯಾಣ ಪರಿಶೀಲನೆಯು ಯಾವುದೇ ಕಾರ್ಯ ಮಾಡುವುದಿಲ್ಲ — ಅವುಗಳ ಫ್ಯಾಮಿಲಿ ಅಂತರ್ಗತವಾಗಿರುವುದರಿಂದ ಲುಕ್ಅಪ್ ಅಗತ್ಯವಿಲ್ಲ.

## ಡೇಟಾ ಮಾದರಿ

`099_proxy_family.sql` ಮೈಗ್ರೇಶನ್ ಮೂಲಕ `family` ಕಾಲಮ್ ಅನ್ನು **ಎರಡು** ಟೇಬಲ್ಗಳಿಗೆ ಸೇರಿಸಲಾಗಿದೆ:

```sql
-- src/lib/db/migrations/099_proxy_family.sql
ALTER TABLE proxy_registry ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
ALTER TABLE upstream_proxy_config ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
```

- `proxy_registry.family` — ರಿಜಿಸ್ಟ್ರಿ ನಮೂದುಗಳಿಗಾಗಿ ಪ್ರತಿ-ಪ್ರಾಕ್ಸಿ ನಿರ್ದೇಶನ (`src/lib/db/proxies.ts`). ರೆಸಲ್ಯೂಶನ್ ಕ್ವೆರಿಗಳು ಇತರ ಪ್ರಾಕ್ಸಿ ಕಾಲಮ್ಗಳ ಜೊತೆಗೆ `family` ಅನ್ನು ಆಯ್ಕೆ ಮಾಡುತ್ತವೆ ಮತ್ತು ಕಾಣೆಯಾದ/ಸ್ಟ್ರಿಂಗ್ ಅಲ್ಲದ ಮೌಲ್ಯವನ್ನು `"auto"` ಆಗಿ ಪರಿವರ್ತಿಸಲಾಗುತ್ತದೆ.
- `upstream_proxy_config.family` — ಅಪ್ಸ್ಟ್ರೀಮ್-ಪ್ರಾಕ್ಸಿ ನಮೂದುಗಳಿಗಾಗಿ ನಿರ್ದೇಶನ (`src/lib/db/upstreamProxy.ts`), ಅದೇ `"auto"` ಡೀಫಾಲ್ಟ್ನೊಂದಿಗೆ.

ರೆಸಾಲ್ವ್ ಮಾಡಲಾದ ಪ್ರಾಕ್ಸಿ ಆಬ್ಜೆಕ್ಟ್ನಲ್ಲಿ `auto` ಅಲ್ಲದ `family` ಇದ್ದಾಗ, ಪಿನ್ ಡಿಸ್ಪ್ಯಾಚರ್ವರೆಗೆ ಉಳಿಯುವುದನ್ನು ಖಚಿತಪಡಿಸಲು `proxyConfigToUrl` ಎಂಬುದು `?family=` ಮಾರ್ಕರ್ ಅನ್ನು ಸೇರಿಸುತ್ತದೆ.
