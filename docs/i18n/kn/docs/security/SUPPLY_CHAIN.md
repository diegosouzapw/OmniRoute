OmniRoute npm + Docker ಆರ್ಟಿಫ್ಯಾಕ್ಟ್ಗಳನ್ನು ಪ್ರಕಟಿಸುತ್ತದೆ. ಈ ಗೇಟ್ಗಳು ಪ್ರಾವೆನೆನ್ಸ್, ಇನ್ವೆಂಟರಿ (SBOM) ಮತ್ತು CVE ಸ್ಕ್ಯಾನಿಂಗ್ ಅನ್ನು ಒದಗಿಸುತ್ತವೆ, ಇವೆಲ್ಲವೂ OSS ಆಗಿದ್ದು, ಬಿಡುಗಡೆ ವರ್ಕ್ಫ್ಲೋಗಳಿಗೆ ಸಂಪರ್ಕಗೊಂಡಿವೆ. **ಸಲಹಾ-ಮೊದಲ** ನಿಲುವು — ಅವು ಈಗ ವರದಿ ಮಾಡುತ್ತವೆ, ಮೊದಲ ಹಸಿರು ಬಿಡುಗಡೆಯ ನಂತರ ನಿರ್ಬಂಧಿಸಲು ಪ್ರಚಾರ ಮಾಡುತ್ತವೆ.

| ಗೇಟ್                  | ಟೂಲ್                                           | ಎಲ್ಲಿದೆ                       | ನಿರ್ಬಂಧಿಸುತ್ತದೆಯೇ?       | ಔಟ್ಪುಟ್                                                     |
| --------------------- | ---------------------------------------------- | ----------------------------- | ------------------------ | ----------------------------------------------------------- |
| SLSA provenance (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | ಪ್ರಕಟಣೆ ವಿಫಲವಾದರೆ ಮಾತ್ರ  | ಬ್ಯಾಡ್ಜ್ npmjs / `npm audit signatures`                     |
| SBOM npm              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | ಉತ್ಪಾದನೆ ವಿಫಲವಾದರೆ ಮಾತ್ರ | ಬಿಡುಗಡೆ ಆಸ್ತಿ + ಆರ್ಟಿಫ್ಯಾಕ್ಟ್                               |
| SBOM image            | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (merge)  | ಸಲಹಾ                     | CycloneDX ಆರ್ಟಿಫ್ಯಾಕ್ಟ್                                     |
| Trivy CVE (SARIF)     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | ಸಲಹಾ                     | SARIF (HIGH+CRITICAL) → ಭದ್ರತಾ ಟ್ಯಾಬ್                       |
| Trivy CRITICAL gate   | `aquasecurity/trivy-action`                    | `docker-publish.yml` (merge)  | **ನಿರ್ಬಂಧಿಸುವಿಕೆ**       | ಸರಿಪಡಿಸಬಹುದಾದ CRITICAL ನಲ್ಲಿ `exit-code: '1'`               |
| osv vulnCount         | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **ನಿರ್ಬಂಧಿಸುವಿಕೆ**       | `metrics.vulnCount` ಅನ್ನು ರಾಚೆಟ್ ಮಾಡುತ್ತದೆ (direction:down) |
| OpenSSF Scorecard     | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | ಸಲಹಾ                     | SARIF → ಭದ್ರತೆ + ಬ್ಯಾಡ್ಜ್                                   |

ಇಮೇಜ್ CVE ರಾಚೆಟ್ `docker-publish.yml` ನಲ್ಲಿ **ಎರಡು ಹಂತಗಳನ್ನು** ಬಳಸುತ್ತದೆ: SARIF ಹಂತ (`HIGH,CRITICAL`, `exit-code: 0`) HIGH+CRITICAL ಅನ್ನು ನಿರ್ಬಂಧಿಸದೆ ಭದ್ರತಾ ಟ್ಯಾಬ್ನಲ್ಲಿ ಗೋಚರಿಸುವಂತೆ ಮಾಡುತ್ತದೆ; _CRITICAL ಗೇಟ್_ ಹಂತ (`severity: CRITICAL`, `ignore-unfixed: true`, `exit-code: 1`) **ಪರಿಹಾರ ಲಭ್ಯವಿರುವ** CRITICAL CVE ಯಲ್ಲಿ ಬಿಡುಗಡೆಯನ್ನು ವಿಫಲಗೊಳಿಸುತ್ತದೆ. `ignore-unfixed` ಅಪ್ಸ್ಟ್ರೀಮ್ ಪ್ಯಾಚ್ ಇಲ್ಲದೆ ಬೇಸ್-ಇಮೇಜ್ CVE ಗಾಗಿ ಬಿಡುಗಡೆಯನ್ನು ನಿರ್ಬಂಧಿಸುವುದನ್ನು ತಡೆಯುತ್ತದೆ.

## ⚠️ CVE ವ್ಯತ್ಯಾಸ (osv/Trivy ಗೇಟ್ಗಳನ್ನು ನಿರ್ಬಂಧಿಸುವುದು)

osv ಮತ್ತು Trivy ಅವಲಂಬನೆಗಳನ್ನು **ನಿರಂತರವಾಗಿ ಬೆಳೆಯುವ** CVE ಡೇಟಾಬೇಸ್ಗಳ ವಿರುದ್ಧ ಹೋಲಿಸುತ್ತವೆ. **ಯಾವುದೇ ಅವಲಂಬನೆಗಳನ್ನು ಸ್ಪರ್ಶಿಸದ** PR ಇದ್ದಕ್ಕಿದ್ದಂತೆ ಕೆಂಪು ಬಣ್ಣಕ್ಕೆ ತಿರುಗಬಹುದು ಏಕೆಂದರೆ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಅವಲಂಬನೆಯಲ್ಲಿ ಹೊಸ CVE ಬಹಿರಂಗಗೊಂಡಿದೆ (osv: ಅಳತೆ ಮಾಡಿದ `vulnCount` > ಬೇಸ್ಲೈನ್; Trivy: ಇಮೇಜ್ನಲ್ಲಿ ಹೊಸ ಸರಿಪಡಿಸಬಹುದಾದ CRITICAL). **ಇದು ನಿರ್ಬಂಧಿಸುವ CVE ಗೇಟ್ನ ನಿರೀಕ್ಷಿತ ಕಾರ್ಯಾಚರಣೆಯ ನಡವಳಿಕೆಯಾಗಿದೆ, ಉತ್ಪನ್ನದ ಹಿನ್ನಡೆಯಲ್ಲ.**

ಹೊಸದಾಗಿ ಬಹಿರಂಗಗೊಂಡ CVE ಕಾರಣದಿಂದ osv ಅಥವಾ Trivy ಕೆಂಪು ಬಣ್ಣಕ್ಕೆ ತಿರುಗಿದಾಗ, ಪರಿಹಾರ ಹೀಗಿದೆ:

1.  **ಪರಿಣಾಮಕ್ಕೊಳಗಾದ ಅವಲಂಬನೆಯನ್ನು ಅಪ್ಗ್ರೇಡ್ ಮಾಡಿ** (ಆದ್ಯತೆ) — `package.json` `overrides` (ಸಂಕ್ರಮಣ ಅವಲಂಬನೆಗಳು) ಮೂಲಕ ಪ್ಯಾಚ್ ಮಾಡಿದ ಆವೃತ್ತಿಗೆ ಅಪ್ಗ್ರೇಡ್ ಮಾಡಿ ಅಥವಾ ಪ್ಯಾಚ್ ಮಾಡಿದ ಬೇಸ್ನಲ್ಲಿ ಇಮೇಜ್ ಅನ್ನು ಮರುನಿರ್ಮಾಣ ಮಾಡಿ.
2.  **ಅಪ್ಸ್ಟ್ರೀಮ್ ಪರಿಹಾರವಿಲ್ಲದಿದ್ದರೆ:**
    - **osv:** `config/quality/quality-baseline.json` ನಲ್ಲಿ `metrics.vulnCount` ಅನ್ನು ಮರು-ಬೇಸ್ಲೈನ್ ಮಾಡಿ (`npm run quality:ratchet -- --update` ಮೀಸಲಾದ ಗೇಟ್ಗಳನ್ನು ಒಳಗೊಂಡಿರುವುದಿಲ್ಲ — ಮೌಲ್ಯವನ್ನು ಕೈಯಾರೆ ಸಂಪಾದಿಸಿ, `direction:down`) ಸಮರ್ಥನೆ ಟಿಪ್ಪಣಿ + ಟ್ರ್ಯಾಕಿಂಗ್ ಸಮಸ್ಯೆಯೊಂದಿಗೆ.
    - **Trivy:** `.trivyignore` ನಲ್ಲಿ (ಪ್ರತಿ ಸಾಲಿಗೆ CVE-ID) ಸಮರ್ಥನೆ ಕಾಮೆಂಟ್ + ಟ್ರ್ಯಾಕಿಂಗ್ ಸಮಸ್ಯೆಯೊಂದಿಗೆ ನಮೂದನ್ನು ಸೇರಿಸಿ. `ignore-unfixed: true` ಈಗಾಗಲೇ ಪ್ಯಾಚ್ಗಳಿಲ್ಲದ CVE ಗಳನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಒಳಗೊಂಡಿದೆ.

ಟೂಲ್ ಇಲ್ಲದಿದ್ದಾಗ ಅಥವಾ ಅಳತೆ ವಿಫಲವಾದಾಗ (PATH ನಲ್ಲಿ osv-scanner ಇಲ್ಲ, osv.dev/network ತಲುಪಲಾಗುವುದಿಲ್ಲ, ಅಮಾನ್ಯ JSON) ಎರಡೂ ಗೇಟ್ಗಳು **ಸೌಜನ್ಯದಿಂದ SKIP** (exit 0) ಆಗುತ್ತವೆ — **ಅಳತೆ** ವೈಫಲ್ಯವು ಎಂದಿಗೂ ನಿರ್ಬಂಧಿಸುವುದಿಲ್ಲ, **ಅಳತೆ ಮಾಡಿದ** ಹಿನ್ನಡೆ ಮಾತ್ರ ನಿರ್ಬಂಧಿಸುತ್ತದೆ.

## ತಿಳಿದಿರುವ ಸ್ವೀಕೃತ ಅಪಾಯಗಳು

### extract-zip 2.0.1 — GHSA-7pqw-9j4j-h8q3 / GHSA-jmr9-qjv8-65gv (#14482)

`extract-zip@2.0.1` ಎರಡು ಪ್ಯಾಚ್ ಮಾಡದ ಹೆಚ್ಚಿನ-ತೀವ್ರತೆಯ ಸಿಮ್ಲಿಂಕ್-ಟ್ರಾವರ್ಸಲ್ ಸಲಹೆಗಳನ್ನು ಹೊಂದಿದೆ.
ಮೇಲಿನ CVE ವೇರಿಯನ್ಸ್ ಪರಿಹಾರದ "ಅಪ್ಸ್ಟ್ರೀಮ್ ಫಿಕ್ಸ್ ಇಲ್ಲ" ಶಾಖೆಯ ಪ್ರಕಾರ, ಇದು **ಸ್ವೀಕೃತ ಅಪಾಯ**, ಬಂಪ್ ಅಲ್ಲ:

- **ಸರಪಳಿ:** `promptfoo` (devDependency) → `@openai/codex-security` → `extract-zip@2.0.1`.
  `package-lock.json` ಮೂಲಕ ದೃಢೀಕರಿಸಲಾಗಿದೆ — ಸಂಪೂರ್ಣ ಡಿಪೆಂಡೆನ್ಸಿ ಟ್ರೀನಲ್ಲಿ ಕೇವಲ ಒಂದು ಪ್ಯಾಕೇಜ್ (`@openai/codex-security`) `extract-zip` ಅನ್ನು ಘೋಷಿಸುತ್ತದೆ, ಮತ್ತು ಕೇವಲ ಒಂದು ಪ್ಯಾಕೇಜ್ (`promptfoo`) `@openai/codex-security` ಅನ್ನು ಘೋಷಿಸುತ್ತದೆ.
- **ಸರಪಳಿಯಲ್ಲಿ ಎಲ್ಲಿಯೂ ಯಾವುದೇ ಸ್ಥಿರ ಬಿಡುಗಡೆ ಅಸ್ತಿತ್ವದಲ್ಲಿಲ್ಲ.** `extract-zip@2.0.1` (2020 ರಲ್ಲಿ ಪ್ರಕಟವಾಯಿತು) ಪ್ಯಾಕೇಜ್ನ ಅಂತಿಮ ಬಿಡುಗಡೆಯಾಗಿದೆ — ಇದನ್ನು ನಿರ್ವಹಿಸಲಾಗುತ್ತಿಲ್ಲ. `@openai/codex-security` ನ ಪ್ರಸ್ತುತ npm-latest (`0.1.29`) ಇನ್ನೂ `extract-zip@2.0.1` ಅನ್ನು ಎಳೆಯುತ್ತದೆ.
- **ಉತ್ಪಾದನೆಯಿಂದ ತಲುಪಲಾಗುವುದಿಲ್ಲ.** `promptfoo` ಕೇವಲ devDependency ಆಗಿದೆ (`dependencies` ಅಡಿಯಲ್ಲಿ ಎಂದಿಗೂ ಪಟ್ಟಿ ಮಾಡಲಾಗಿಲ್ಲ), ಮತ್ತು `src/`, `open-sse/`, ಅಥವಾ `bin/` ಅಡಿಯಲ್ಲಿ ಯಾವುದೇ ಫೈಲ್ `extract-zip` npm ಪ್ಯಾಕೇಜ್ ಅನ್ನು ಆಮದು ಮಾಡಿಕೊಳ್ಳುವುದಿಲ್ಲ — OmniRoute ನ ಸ್ವಂತ `extractZip()` ಸಹಾಯಕ (`src/lib/versionManager/binaryManager.ts:93`) ಸ್ಥಳೀಯ `unzip`/`tar` ಗೆ ಶೆಲ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ಸಂಬಂಧಿಸಿಲ್ಲ. `@openai/codex-security` ಸಹ extract-zip ನ onEntry ಕಾಲ್ಬ್ಯಾಕ್ನ ಮೇಲೆ ತನ್ನದೇ ಆದ ಸಿಮ್ಲಿಂಕ್-ಟ್ರಾವರ್ಸಲ್ ಗಾರ್ಡ್ ಅನ್ನು ರವಾನಿಸುತ್ತದೆ.
- `package.json` `overrides` ಮೂಲಕ `extract-zip` ಅನ್ನು ಅಲಿಯಾಸ್ **ಮಾಡಬೇಡಿ** — ಏಕೈಕ ಕಾರ್ಯಸಾಧ್ಯವಾದ ಡ್ರಾಪ್-ಇನ್ ಬದಲಿ ಎಲೆಕ್ಟ್ರಾನ್-ಆರ್ಗ್-ಇಂಟರ್ನಲ್ ಆಗಿದೆ ಮತ್ತು `@openai/codex-security` ನ ಸ್ವಂತ onEntry/defaultDirMode/defaultFileMode ಚೆಕ್ಗಳೊಂದಿಗೆ API-ಹೊಂದಾಣಿಕೆಯಾಗುವುದಿಲ್ಲ; ಅದನ್ನು ಅತಿಕ್ರಮಿಸುವುದರಿಂದ ಆ ಪ್ಯಾಕೇಜ್ನ ಭದ್ರತಾ ಪರಿಶೀಲನೆಗಳು ಮೌನವಾಗಿ ಮುರಿಯುತ್ತವೆ.
- **ಬೇಸ್ಲೈನ್:** ಅಳತೆ ಮಾಡಿದ osv `vulnCount` (3) ಈಗಾಗಲೇ ಸ್ಥಿರವಾದ `config/quality/quality-baseline.json` ಬೇಸ್ಲೈನ್ (27) ಗಿಂತ ಕಡಿಮೆಯಿದೆ — ಯಾವುದೇ ರಾಟ್ಚೆಟ್ ಬದಲಾವಣೆ ಅಗತ್ಯವಿಲ್ಲ.
- **ರಿಗ್ರೆಷನ್ ಗಾರ್ಡ್:** `tests/unit/extract-zip-14482-exposure.test.ts` ಮೇಲಿನ ಸರಪಳಿ ಮತ್ತು ಉತ್ಪಾದನೆ-ಆಮದು-ಇಲ್ಲದ ಇನ್ವೇರಿಯಂಟ್ ಅನ್ನು ದೃಢೀಕರಿಸುತ್ತದೆ; ಇವುಗಳಲ್ಲಿ ಯಾವುದಾದರೂ ಮುರಿದರೆ (ಉದಾಹರಣೆಗೆ, ಭವಿಷ್ಯದ PR `extract-zip` ಅನ್ನು ಉತ್ಪಾದನೆಯಿಂದ ತಲುಪುವಂತೆ ಮಾಡಿದರೆ) ಅದು CI ಅನ್ನು ವಿಫಲಗೊಳಿಸುತ್ತದೆ.
- **ಟ್ರ್ಯಾಕಿಂಗ್:** ಇಶ್ಯೂ #14482.

## ಬ್ಯಾಕ್ಲಾಗ್: ಸ್ಕೋರ್ಕಾರ್ಡ್ ಸಲಹೆ → ನಿರ್ಬಂಧಿಸುವುದು

ಸ್ಕೋರ್ಕಾರ್ಡ್ ವರದಿ ಮಾಡುವಿಕೆಯೊಂದಿಗೆ 1 ನೇ ಹಸಿರು ಬಿಡುಗಡೆಯ ನಂತರ:

- ಸ್ಕೋರ್ಕಾರ್ಡ್: ಸ್ಕೋರ್ ರಾಟ್ಚೆಟ್ (ಅಳತೆ ಮಾಡಿದ ಸ್ಕೋರ್ ಅನ್ನು ಸ್ಥಿರಗೊಳಿಸುತ್ತದೆ; ಕಡಿಮೆಯಾಗಲು ಸಾಧ್ಯವಿಲ್ಲ).

ಫೇಸ್ 7 ಗೇಟ್ಗಳನ್ನು (osv-scanner, gitleaks, actionlint+zizmor) ಪೂರೈಸುತ್ತದೆ: zizmor ವರ್ಕ್ಫ್ಲೋಗಳನ್ನು ಆಡಿಟ್ ಮಾಡುತ್ತದೆ; ಸ್ಕೋರ್ಕಾರ್ಡ್ ರೆಪೊ ಭಂಗಿಯನ್ನು ಒಟ್ಟಾರೆಯಾಗಿ ಅಳೆಯುತ್ತದೆ.
