OmniRoute npm + Docker ಆರ್ಟಿಫ್ಯಾಕ್ಟ್ಗಳನ್ನು ಪ್ರಕಟಿಸುತ್ತದೆ. ಈ ಗೇಟ್ಗಳು ಮೂಲದ ಪುರಾವೆ,
ಇನ್ವೆಂಟರಿ (SBOM) ಮತ್ತು CVE ಸ್ಕ್ಯಾನಿಂಗ್ ಅನ್ನು ಒದಗಿಸುತ್ತವೆ; ಇವೆಲ್ಲವೂ OSS ಆಗಿದ್ದು, ಬಿಡುಗಡೆ ಕಾರ್ಯಪ್ರವಾಹಗಳಿಗೆ ಜೋಡಿಸಲ್ಪಟ್ಟಿವೆ.
**ಮೊದಲು-ಸಲಹೆ** ನಿಲುವು — ಅವು ಈಗ ವರದಿ ಮಾಡುತ್ತವೆ ಮತ್ತು 1ನೇ
ಯಶಸ್ವಿ ಬಿಡುಗಡೆಯ ನಂತರ ನಿರ್ಬಂಧಿಸುವ ಸ್ಥಿತಿಗೆ ಬಡ್ತಿ ಪಡೆಯುತ್ತವೆ.

| ಗೇಟ್                   | ಪರಿಕರ                                          | ಎಲ್ಲಿ                         | ನಿರ್ಬಂಧಿಸುವುದೇ?         | ಔಟ್ಪುಟ್                                                     |
| ---------------------- | ---------------------------------------------- | ----------------------------- | ----------------------- | ----------------------------------------------------------- |
| SLSA ಮೂಲದ ಪುರಾವೆ (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | ಪ್ರಕಟಣೆ ವಿಫಲವಾದರೆ ಮಾತ್ರ | ಬ್ಯಾಡ್ಜ್ npmjs / `npm audit signatures`                     |
| SBOM npm               | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | ರಚನೆ ವಿಫಲವಾದರೆ ಮಾತ್ರ    | ಬಿಡುಗಡೆ ಅಸೆಟ್ + ಆರ್ಟಿಫ್ಯಾಕ್ಟ್                               |
| SBOM ಇಮೇಜ್             | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (ವಿಲೀನ)  | ಸಲಹಾತ್ಮಕ                | CycloneDX ಆರ್ಟಿಫ್ಯಾಕ್ಟ್                                     |
| Trivy CVE (SARIF)      | `aquasecurity/trivy-action`                    | `docker-publish.yml` (ವಿಲೀನ)  | ಸಲಹಾತ್ಮಕ                | SARIF (HIGH+CRITICAL) → ಭದ್ರತಾ ಟ್ಯಾಬ್                       |
| Trivy CRITICAL ಗೇಟ್    | `aquasecurity/trivy-action`                    | `docker-publish.yml` (ವಿಲೀನ)  | **ನಿರ್ಬಂಧಿಸುವುದು**      | ಸರಿಪಡಿಸಬಹುದಾದ CRITICAL ಸಂದರ್ಭದಲ್ಲಿ `exit-code: '1'`         |
| osv vulnCount          | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **ನಿರ್ಬಂಧಿಸುವುದು**      | `metrics.vulnCount` ಅನ್ನು ರ್ಯಾಚೆಟ್ ಮಾಡುತ್ತದೆ (ದಿಕ್ಕು:ಕೆಳಗೆ) |
| OpenSSF Scorecard      | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | ಸಲಹಾತ್ಮಕ                | SARIF → ಭದ್ರತೆ + ಬ್ಯಾಡ್ಜ್                                   |

ಇಮೇಜ್ CVE ರ್ಯಾಚೆಟ್ `docker-publish.yml` ನಲ್ಲಿ **ಎರಡು ಹಂತಗಳನ್ನು** ಬಳಸುತ್ತದೆ: SARIF ಹಂತವು
(`HIGH,CRITICAL`, `exit-code: 0`) ನಿರ್ಬಂಧಿಸದೆಯೇ HIGH+CRITICAL ಅನ್ನು ಭದ್ರತಾ ಟ್ಯಾಬ್ನಲ್ಲಿ
ಗೋಚರವಾಗಿರಿಸುತ್ತದೆ; _CRITICAL ಗೇಟ್_ ಹಂತವು (`severity: CRITICAL`, `ignore-unfixed: true`,
`exit-code: 1`) **ಪರಿಹಾರ ಲಭ್ಯವಿರುವ** CRITICAL CVE ಸಂದರ್ಭದಲ್ಲಿ ಬಿಡುಗಡೆಯನ್ನು ವಿಫಲಗೊಳಿಸುತ್ತದೆ. `ignore-unfixed`
ಅಪ್ಸ್ಟ್ರೀಮ್ ಪ್ಯಾಚ್ ಇಲ್ಲದ ಬೇಸ್-ಇಮೇಜ್ CVE ಕಾರಣದಿಂದ ಬಿಡುಗಡೆ ನಿರ್ಬಂಧಿಸಲ್ಪಡುವುದನ್ನು ತಡೆಯುತ್ತದೆ.

## ⚠️ CVE ವ್ಯತ್ಯಾಸ (ನಿರ್ಬಂಧಿಸುವ osv/Trivy ಗೇಟ್ಗಳು)

osv ಮತ್ತು Trivy ಅವಲಂಬನೆಗಳನ್ನು **ನಿರಂತರವಾಗಿ ಬೆಳೆಯುವ** CVE ಡೇಟಾಬೇಸ್ಗಳೊಂದಿಗೆ ಹೋಲಿಸುತ್ತವೆ. ಯಾವುದೇ
ಅವಲಂಬನೆಗಳನ್ನು **ಬದಲಾಯಿಸದ** PR ಕೂಡ ಹೊಸ CVE ಒಂದು ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಅವಲಂಬನೆಯಲ್ಲಿ
ಬಹಿರಂಗಗೊಂಡ ಕಾರಣ ಹಠಾತ್ತನೆ ಕೆಂಪಾಗಬಹುದು (osv: ಅಳೆಯಲಾದ `vulnCount` > ಬೇಸ್ಲೈನ್; Trivy: ಇಮೇಜ್ನಲ್ಲಿ
ಹೊಸ ಸರಿಪಡಿಸಬಹುದಾದ CRITICAL). **ಇದು ನಿರ್ಬಂಧಿಸುವ CVE ಗೇಟ್ನ ನಿರೀಕ್ಷಿತ ಕಾರ್ಯಾಚರಣಾ
ವರ್ತನೆಯೇ ಹೊರತು ಉತ್ಪನ್ನದ ಹಿಂಜರಿತವಲ್ಲ.**

ಹೊಸದಾಗಿ ಬಹಿರಂಗಗೊಂಡ CVE ಕಾರಣದಿಂದ osv ಅಥವಾ Trivy ಕೆಂಪಾದಾಗ, ಪರಿಹಾರ ಹೀಗಿದೆ:

1. **ಪರಿಣಾಮಿತ ಅವಲಂಬನೆಯ ಆವೃತ್ತಿಯನ್ನು ಹೆಚ್ಚಿಸಿ** (ಆದ್ಯತೆ) — `package.json`
   `overrides` (ಪರೋಕ್ಷ ಅವಲಂಬನೆಗಳು) ಮೂಲಕ ಪ್ಯಾಚ್ ಮಾಡಿದ ಆವೃತ್ತಿಗೆ ಅಪ್ಗ್ರೇಡ್ ಮಾಡಿ ಅಥವಾ ಪ್ಯಾಚ್ ಮಾಡಿದ ಬೇಸ್ನಲ್ಲಿ ಇಮೇಜ್ ಅನ್ನು ಮರುನಿರ್ಮಿಸಿ.
2. **ಅಪ್ಸ್ಟ್ರೀಮ್ ಪರಿಹಾರ ಇಲ್ಲದಿದ್ದರೆ:**
   - **osv:** `config/quality/quality-baseline.json` ನಲ್ಲಿ `metrics.vulnCount` ಅನ್ನು ಮರು-ಬೇಸ್ಲೈನ್ ಮಾಡಿ
     (`npm run quality:ratchet -- --update` ಮೀಸಲಾದ ಗೇಟ್ಗಳನ್ನು ಒಳಗೊಳ್ಳುವುದಿಲ್ಲ — ಸಮರ್ಥನಾ ಟಿಪ್ಪಣಿ + ಟ್ರ್ಯಾಕಿಂಗ್ ಸಮಸ್ಯೆಯೊಂದಿಗೆ
     ಮೌಲ್ಯವನ್ನು ಕೈಯಾರೆ ಸಂಪಾದಿಸಿ, `direction:down`).
   - **Trivy:** ಸಮರ್ಥನಾ ಕಾಮೆಂಟ್ + ಟ್ರ್ಯಾಕಿಂಗ್ ಸಮಸ್ಯೆಯೊಂದಿಗೆ `.trivyignore` ನಲ್ಲಿ ಒಂದು ನಮೂದನ್ನು
     ಸೇರಿಸಿ (ಪ್ರತಿ ಸಾಲಿಗೆ CVE-ID). ಪ್ಯಾಚ್ಗಳಿಲ್ಲದ CVEಗಳನ್ನು `ignore-unfixed: true` ಈಗಾಗಲೇ
     ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಒಳಗೊಳ್ಳುತ್ತದೆ.

ಪರಿಕರ ಲಭ್ಯವಿಲ್ಲದಾಗ ಅಥವಾ ಮಾಪನ ವಿಫಲವಾದಾಗ ಎರಡೂ ಗೇಟ್ಗಳು **ಸಮರ್ಪಕವಾಗಿ SKIP ಮಾಡುತ್ತವೆ**
(exit 0) (PATH ನಲ್ಲಿ osv-scanner ಇಲ್ಲದಿರುವುದು, osv.dev/ನೆಟ್ವರ್ಕ್ ತಲುಪಲಾಗದಿರುವುದು, ಅಮಾನ್ಯ JSON) —
**ಮಾಪನ** ವೈಫಲ್ಯವು ಎಂದಿಗೂ ನಿರ್ಬಂಧಿಸುವುದಿಲ್ಲ; **ಅಳೆಯಲಾದ** ಹಿಂಜರಿತ ಮಾತ್ರ ನಿರ್ಬಂಧಿಸುತ್ತದೆ.
