ಈ ದಸ್ತಾವೇಜು `omniroute@3.8.5` ವಿರುದ್ಧ ವರದಿಯಾದ ಆರು
`AI-detected potential malware` ಪತ್ತೆಗಳು ಮತ್ತು `omniroute@3.8.6` ನಲ್ಲಿ
ಅನ್ವಯಿಸಲಾದ ತಗ್ಗಿಸುವಿಕೆಗಳ ಕುರಿತು ನಿರ್ವಹಣಾಕಾರರು ರಚಿಸಿದ ದೃಢೀಕರಣವಾಗಿದೆ. ಇದು ಇರುವುದರ ಉದ್ದೇಶಗಳು:

1. ಭದ್ರತಾ-ಪೈಪ್ಲೈನ್ ನಿರ್ವಾಹಕರು ಪತ್ತೆಗಳನ್ನು ನೈಜ ಮೂಲದೊಂದಿಗೆ
   ಮೌಲ್ಯಮಾಪನ ಮಾಡಬೇಕಾದಾಗ ಉಲ್ಲೇಖಿಸಲು ಒಂದೇ ಆಧಾರವನ್ನು ಹೊಂದಿರುವುದು.
2. ಗುರುತಿಸಲಾದ ಪ್ರತಿಯೊಂದು ಪಥವೂ ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿದೆ, ಆಯ್ಕೆಮಾಡಿದಾಗ ಮಾತ್ರ ಸಕ್ರಿಯವಾಗುತ್ತದೆ ಮತ್ತು
   ದಾಖಲಿಸಲಾಗಿದೆ ಎಂಬ ನಿರ್ವಹಣಾಕಾರರು ಸಹಿ ಮಾಡಿದ ಹೇಳಿಕೆಯನ್ನು ಭವಿಷ್ಯದ AI ಸ್ಕ್ಯಾನರ್ಗಳು ಗುರುತಿಸಲು ಸಾಧ್ಯವಾಗುವುದು.
3. ಪ್ರತಿಯೊಂದು ಕರೆ ಸ್ಥಳವನ್ನೂ _ಏಕೆ_ ಆ ರೀತಿಯಲ್ಲಿ ರೂಪಿಸಲಾಗಿದೆ ಎಂಬುದರ ಲಿಖಿತ ದಾಖಲೆಯನ್ನು ಹೊಂದಿರುವುದು —
   ಇದರಿಂದ ಭವಿಷ್ಯದ ರಿಫ್ಯಾಕ್ಟರಿಂಗ್ ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ತೆಗೆದುಹಾಕಲಾದ ಗುರುತುಚಿಹ್ನೆಯನ್ನು
   ಆಕಸ್ಮಿಕವಾಗಿ ಮತ್ತೆ ಪರಿಚಯಿಸುವುದಿಲ್ಲ.

v3.8.6 ತಗ್ಗಿಸುವಿಕೆಗಳನ್ನು ಬಿಡುಗಡೆ ಮಾಡಿದ ನಂತರ ಕೆಳಗಿನ ಯಾವುದೇ ಕರೆ ಸ್ಥಳಗಳನ್ನು
ಮತ್ತೆ ಗುರುತಿಸುವ ಸ್ಕ್ಯಾನರ್ ಅನ್ನು ನೀವು ನಿರ್ವಹಿಸುತ್ತಿದ್ದರೆ, ದಯವಿಟ್ಟು ಸ್ಕ್ಯಾನ್ ಟ್ರೇಸ್ನೊಂದಿಗೆ ಸಮಸ್ಯೆಯೊಂದನ್ನು ತೆರೆಯಿರಿ ಮತ್ತು
ನಾವು ಇಲ್ಲಿ ದೃಢೀಕರಣವನ್ನು ವಿಸ್ತರಿಸುತ್ತೇವೆ.

## §1 — MITM ರೂಟ್-CA ಸ್ಥಾಪನೆ (`77484.js`)

**ಮೂಲ ಫೈಲ್ಗಳು**:

- `src/mitm/cert/install.ts` — ಸಾರ್ವಜನಿಕ `installCert()` / `uninstallCert()`,
  ಪ್ರತಿ ಪ್ಲಾಟ್ಫಾರ್ಮ್ಗೆ `installCertWindows/Mac/Linux`.
- `src/mitm/systemCommands.ts` — ಸ್ಥಾಪನಾ ಪಥಗಳು ಬಳಸುವ ಹಂಚಿಕೆಯ `execFile` / `spawn` / PowerShell
  ಸಹಾಯಕಗಳು.

**ಪ್ರಚೋದಕ**: ಬಳಕೆದಾರರು ಸ್ಥಳೀಯ ಡ್ಯಾಶ್ಬೋರ್ಡ್ನ
`/dashboard/cli-tools/mitm` ನಲ್ಲಿ "MITM ಪ್ರಾಕ್ಸಿಯನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ" ಅನ್ನು ಕ್ಲಿಕ್ ಮಾಡುತ್ತಾರೆ. ಈ ಮಾರ್ಗವು ಲೂಪ್ಬ್ಯಾಕ್ಗೆ ಮಾತ್ರ ಸೀಮಿತವಾಗಿದೆ — `CLAUDE.md` ನಲ್ಲಿನ ಕಠಿಣ ನಿಯಮ #17 ಮತ್ತು
`src/server/authz/routeGuard.ts::isLocalOnlyPath()` ಅನ್ನು ನೋಡಿ. ಟನಲ್ ಮೂಲಕ ಬಹಿರಂಗಗೊಂಡ
JWT ಈ ಕೋಡ್ ಪಥವನ್ನು ಪ್ರಚೋದಿಸಲು **ಸಾಧ್ಯವಿಲ್ಲ**.

**ನಿರ್ವಹಿಸಲಾದ ವಿಶೇಷಾಧಿಕಾರದ ಕಾರ್ಯಾಚರಣೆಗಳು (ಪ್ರತಿ ಪ್ಲಾಟ್ಫಾರ್ಮ್ಗೆ)**:

| OS                     | ಆದೇಶ(ಗಳು)                                                                                                         |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | UAC ಮೂಲಕ `certutil -addstore Root <cert>`                                                                         |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | `certutil -d sql:<profile>` ಮೂಲಕ ಪ್ರತಿ-ಪ್ರೊಫೈಲ್ NSS DB ನವೀಕರಣ                                                     |

ಇವು `mitmproxy`, Charles Proxy, Fiddler ಮತ್ತು
Caddy ಬಳಸುವ ಅದೇ ಆದೇಶಗಳಾಗಿವೆ. ಅವು OmniRoute ನಲ್ಲಿ ಅಸ್ತಿತ್ವದಲ್ಲಿವೆ ಎಂಬುದು
`docs/security/STEALTH_GUIDE.md` ನಲ್ಲಿ ದಾಖಲಿಸಲಾಗಿದೆ.

**v3.8.6 ತಗ್ಗಿಸುವಿಕೆ**:

- `runElevatedPowerShell()` ಇನ್ನು ಮುಂದೆ `-EncodedCommand <base64utf16le>` ಅನ್ನು ಬಳಸುವುದಿಲ್ಲ.
  ಉನ್ನತಾಧಿಕಾರದ ಪೇಲೋಡ್ ಅನ್ನು ಪ್ರತಿ-ಕರೆಗೆ ತಾತ್ಕಾಲಿಕ `.ps1` ಫೈಲ್ಗೆ (mode 0o600,
  ಖಾಸಗಿ `mkdtempSync` ಡೈರೆಕ್ಟರಿಯೊಳಗೆ) ಬರೆಯಲಾಗುತ್ತದೆ ಮತ್ತು `-File` ಮೂಲಕ ಉಲ್ಲೇಖಿಸಲಾಗುತ್ತದೆ. ಆ
  ಫೈಲ್ ಅನ್ನು `finally` ನಲ್ಲಿ ಅನ್ಲಿಂಕ್ ಮಾಡಲಾಗುತ್ತದೆ. ಇದು Socket.dev ನ AI
  ವರ್ಗೀಕರಣಕಾರ ಗುರುತಿಸಿದ PowerShell ಮೂಲಕ base64-ಉನ್ನತೀಕರಣದ ಪಠ್ಯಪುಸ್ತಕದಂತಹ ಗುರುತುಚಿಹ್ನೆಯನ್ನು ತೆಗೆದುಹಾಕುತ್ತದೆ.
- `installCertWindows` ಇಲ್ಲಿ ಸೂಚಿಸುವ ಇನ್ಲೈನ್ `SECURITY-AUDITOR-NOTE:` ಬ್ಲಾಕ್ ಅನ್ನು
  ಹೊಂದಿದೆ.

**ನಾವು ಇದನ್ನು ಏಕೆ ಉಳಿಸಿಕೊಂಡಿದ್ದೇವೆ**: MITM ಪ್ರಾಕ್ಸಿಯು
`docs/security/STEALTH_GUIDE.md` ಮತ್ತು `docs/frameworks/MITM-PROXY.md` ಬಳಸುವ ದಾಖಲಿತ ವೈಶಿಷ್ಟ್ಯವಾಗಿದೆ. ಅದನ್ನು ತೆಗೆದುಹಾಕುವುದರಿಂದ
ಏಜೆಂಟ್-ಬ್ರಿಡ್ಜ್ ವೈಶಿಷ್ಟ್ಯಗಳ ಸಮೂಹವು ಕಾರ್ಯನಿರ್ವಹಿಸುವುದಿಲ್ಲ.

## §2 — Zed ರುಜುವಾತು ಆಮದು (`app/api/providers/zed/import/route.js`)

**ಮೂಲ ಫೈಲ್ಗಳು**:

- `src/app/api/providers/zed/discover/route.ts` _(v3.8.6 ರಲ್ಲಿ ಹೊಸದು)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(v3.8.6 ರಲ್ಲಿ ಹೊಸದು)_

**ಪ್ರಚೋದಕ**: ಸ್ಥಳೀಯ ಡ್ಯಾಶ್ಬೋರ್ಡ್ನ Providers ಪುಟದಲ್ಲಿ ಬಳಕೆದಾರರು "Zed ನಿಂದ ಆಮದು ಮಾಡಿ" ಎಂಬುದನ್ನು ಕ್ಲಿಕ್ ಮಾಡುತ್ತಾರೆ. ಎಂಡ್ಪಾಯಿಂಟ್ಗೆ `requireManagementAuth` ಮೂಲಕ ಪ್ರವೇಶ ನಿಯಂತ್ರಿಸಲಾಗಿದೆ. Zed ಎಡಿಟರ್ ಸ್ವತಃ ತನ್ನ ಪ್ರೊವೈಡರ್ API ಕೀಲಿಗಳನ್ನು ದಾಖಲಿತ ಸೇವಾ ಹೆಸರುಗಳ ಅಡಿಯಲ್ಲಿ OS ಕೀಚೇನ್ಗೆ ಬರೆಯುತ್ತದೆ — https://zed.dev/docs/ai/llm-providers ನೋಡಿ.

**v3.8.5 ನಡವಳಿಕೆ (Socket.dev ಗುರುತಿಸಿದ್ದು)**:

`POST /import` ರುಜುವಾತುಗಳನ್ನು ಪತ್ತೆಹಚ್ಚಿ, ಒಂದೇ ವಿನಂತಿ-ಪ್ರತಿಕ್ರಿಯೆ ಸುತ್ತಿನಲ್ಲಿ ಅವುಗಳನ್ನು ಸ್ಥಳೀಯ SQLite ಸಂಗ್ರಹಕ್ಕೆ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಉಳಿಸುತ್ತಿತ್ತು. ಪ್ರತಿ ಖಾತೆಗೆ ಪ್ರತ್ಯೇಕ ದೃಢೀಕರಣವಾಗಲಿ, ಫಿಂಗರ್ಪ್ರಿಂಟ್ ಆಗಲಿ ಇರಲಿಲ್ಲ; ಕೇವಲ "N ಟೋಕನ್ಗಳು ಕಂಡುಬಂದವು, ಎಲ್ಲವನ್ನೂ ಆಮದು ಮಾಡಲಾಗಿದೆ."

**v3.8.6 ತಗ್ಗಿಸುವಿಕೆ — 2-ಹಂತದ ದೃಢೀಕರಣ**:

1. **`POST /api/providers/zed/discover`**
   `{ candidates: [{ provider, service, account, fingerprint }] }` ಅನ್ನು ಹಿಂತಿರುಗಿಸುತ್ತದೆ. ಮೂಲ
   ಟೋಕನ್ ಅನ್ನು **ಎಂದಿಗೂ** ರವಾನಿಸಲಾಗುವುದಿಲ್ಲ. ಫಿಂಗರ್ಪ್ರಿಂಟ್
   `sha256(service|account|token).slice(0,16)` ಆಗಿದೆ.
2. ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಅಭ್ಯರ್ಥಿಗಳ ಪಟ್ಟಿಯನ್ನು ಪ್ರದರ್ಶಿಸುತ್ತದೆ, ಆಪರೇಟರ್ ಆಮದು ಮಾಡಬೇಕಾದವುಗಳನ್ನು ಆಯ್ಕೆಮಾಡುತ್ತಾರೆ ಮತ್ತು `{ confirmedAccounts: [{ service, account, fingerprint }] }` ಅನ್ನು
   **`POST /api/providers/zed/import`** ಗೆ ಪೋಸ್ಟ್ ಮಾಡುತ್ತಾರೆ.
3. ಆಮದು ಎಂಡ್ಪಾಯಿಂಟ್ **ಸರ್ವರ್ನಲ್ಲಿ ಕೀಚೇನ್ ಅನ್ನು ಮರು-ಓದುತ್ತದೆ** ಮತ್ತು
   `(service, account, fingerprint)` ಆಧಾರದಲ್ಲಿ ಫಿಲ್ಟರ್ ಮಾಡುತ್ತದೆ. ತಿದ್ದುಪಡಿ ಮಾಡಲಾದ ಅಥವಾ ಮರುಬಳಸಲಾದ discover
   ಪ್ರತಿಕ್ರಿಯೆಯು ಸಂಬಂಧವಿಲ್ಲದ ಟೋಕನ್ ಅನ್ನು ಉಳಿಸುವಂತೆ ಆಮದು ಎಂಡ್ಪಾಯಿಂಟ್ ಅನ್ನು ವಂಚಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ —
   discover ನಂತರ ನೇರ ಟೋಕನ್ ಬದಲಾಗಿದ್ದರೆ, ಫಿಂಗರ್ಪ್ರಿಂಟ್ ಇನ್ನು ಮುಂದೆ
   ಹೊಂದಿಕೆಯಾಗುವುದಿಲ್ಲ ಮತ್ತು ಆ ರುಜುವಾತನ್ನು ಬಿಟ್ಟುಬಿಡಲಾಗುತ್ತದೆ.

ತಮ್ಮ ಸ್ವಯಂಚಾಲನೆಯನ್ನು ಇನ್ನೂ ನವೀಕರಿಸದ ಆಪರೇಟರ್ಗಳಿಗಾಗಿ `OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` env ಫ್ಲ್ಯಾಗ್ v3.8.5
ನಡವಳಿಕೆಯನ್ನು ಉಳಿಸುತ್ತದೆ. ಇದನ್ನು v3.9 ರಲ್ಲಿ ತೆಗೆದುಹಾಕಲಾಗುತ್ತದೆ.

**ನಾವು ಇದನ್ನು ಏಕೆ ಉಳಿಸಿಕೊಂಡಿದ್ದೇವೆ**: ಈಗಾಗಲೇ Zed ಬಳಸುತ್ತಿರುವ ಮತ್ತು ಪುನಃ ಅಂಟಿಸದೆಯೇ ತಮ್ಮ ಪ್ರೊವೈಡರ್ ಕೀಲಿಗಳನ್ನು OmniRoute ಗೆ ಪ್ರತಿಬಿಂಬಿಸಲು ಬಯಸುವ ಬಳಕೆದಾರರಿಗೆ Zed ಆಮದು ಅತ್ಯಂತ ಸುಲಭವಾದ ಆರಂಭಿಕ ಸಂರಚನಾ ಮಾರ್ಗವಾಗಿದೆ.

## §3 — `execFile` / `spawn` / ಉನ್ನತಾಧಿಕಾರದ PowerShell (`21843.js`)

**ಮೂಲ ಫೈಲ್ಗಳು**: `src/mitm/systemCommands.ts`.

**ಗುರುತಿಸಲು ಕಾರಣ**: ಈ ಚಂಕ್ `execFileWithPassword`,
`runElevatedPowerShell` ಮತ್ತು ಹಂಚಿದ `quotePowerShell` ಸಹಾಯಕವನ್ನು ಮರು-ರಫ್ತು ಮಾಡುತ್ತದೆ. Socket.dev ನ
AI ವರ್ಗೀಕರಣ ಸಾಧನವು ಅವುಗಳನ್ನು ಸಾಮಾನ್ಯವಾದ "ಹೋಸ್ಟ್ ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆ + ವಿಶೇಷಾಧಿಕಾರ ಉನ್ನತೀಕರಣ
ಟೂಲ್ಕಿಟ್" ಎಂದು ಪರಿಗಣಿಸುತ್ತದೆ. OmniRoute ಒಳಗೆ ಅವುಗಳನ್ನು MITM ಪ್ರಮಾಣಪತ್ರ ಸ್ಥಾಪನೆ ಮಾರ್ಗ (§1) ಮತ್ತು `sudo` ಕಮಾಂಡ್ ಕಾರ್ಯಗತಗೊಳಿಸಲು `execFileWithPassword` ಮೂಲಕ ಮಾತ್ರ ಬಳಸಲಾಗುತ್ತದೆ.

**v3.8.6 ತಗ್ಗಿಸುವಿಕೆ**:

- `runElevatedPowerShell` ಮರುರಚನೆ (§1 ನೋಡಿ).
- `runElevatedPowerShell` ಮತ್ತು `execFileWithPassword` ಎರಡರಲ್ಲಿಯೂ ಇರುವ ಇನ್ಲೈನ್ `SECURITY-AUDITOR-NOTE:` ಬ್ಲಾಕ್ ಅನುಮತಿ ಪಟ್ಟಿಯಲ್ಲಿರುವ ಕರೆಗಾರರು ಮತ್ತು ನಿಗದಿತ executable ಪಟ್ಟಿಯನ್ನು ದಾಖಲಿಸುತ್ತದೆ.
- `execFileWithPassword` ನ `spawn()` ಕರೆ, ಸಹಾಯಕವು ಸ್ವೀಕರಿಸಲು ಅನುಮತಿಸಲಾದ executable ಗಳ ಅನುಮತಿ ಪಟ್ಟಿಯೊಂದಿಗೆ `nosemgrep` ಮಾರ್ಕರ್ ಅನ್ನು ಹೊಂದಿದೆ — ಬಳಕೆದಾರರ ಇನ್ಪುಟ್ನಿಂದ `finalCommand`/`finalArgs` ಗೆ **ಯಾವುದೇ ಮಾರ್ಗವಿಲ್ಲ**.

## §4 / §6 — 9router ಸೇವಾ ಮೇಲ್ವಿಚಾರಕ (`api/services/9router/{start,restart}/route.js`)

**ಮೂಲ ಫೈಲ್ಗಳು**:

- `src/app/api/services/9router/_lib.ts` — ಮೇಲ್ವಿಚಾರಕ ಫ್ಯಾಕ್ಟರಿ.
- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`.
- `src/lib/services/ServiceSupervisor.ts` — ಸಾಮಾನ್ಯ spawn / ಆರೋಗ್ಯ-ಪೋಲಿಂಗ್ / ಲಾಗ್-ಬಫರ್.

**ಪ್ರಚೋದಕ**: ಸ್ಥಳೀಯ ಡ್ಯಾಶ್ಬೋರ್ಡ್ನ ಎಂಬೆಡ್ ಮಾಡಿದ ಸೇವೆಗಳ ಪುಟದಲ್ಲಿ ಬಳಕೆದಾರರು "ಸ್ಥಾಪಿಸಿ" / "ಪ್ರಾರಂಭಿಸಿ" ಎಂಬುದನ್ನು ಕ್ಲಿಕ್ ಮಾಡುತ್ತಾರೆ.

**ಈಗಾಗಲೇ ಜಾರಿಯಲ್ಲಿರುವ ರಕ್ಷಣೆಗಳು**:

- `src/server/authz/routeGuard.ts` ಪ್ರಕಾರ ಎಲ್ಲಾ `/api/services/*` ರೂಟ್ಗಳು LOCAL_ONLY ಆಗಿವೆ
  (ಕಟ್ಟುನಿಟ್ಟಿನ ನಿಯಮ #17). ಯಾವುದೇ ದೃಢೀಕರಣ ಪರಿಶೀಲನೆಗೂ ಮೊದಲು ಲೂಪ್ಬ್ಯಾಕ್ ಜಾರಿಗೊಳಿಸುವಿಕೆ ನಡೆಯುತ್ತದೆ — ಸೋರಿಕೆಯಾದ JWT ಕೂಡ ಅವುಗಳನ್ನು ತಲುಪಲು ಸಾಧ್ಯವಿಲ್ಲ.
- 9router DB ಸಾಲನ್ನು `status='not_installed', auto_start=0` ಆಗಿ ಸೀಡ್ ಮಾಡಲಾಗಿದೆ (`src/lib/db/migrations/071_services.sql:19` ನೋಡಿ). ಮೊದಲ ಪ್ರಾರಂಭದಲ್ಲೇ ಸೇವೆಯು **ಪ್ರಾರಂಭವಾಗುವುದಿಲ್ಲ**.
- `src/lib/services/installers/ninerouter.ts` ನಲ್ಲಿರುವ `resolveSpawnArgs(apiKey, PORT)` ಹಿಂತಿರುಗಿಸುವ ಬೈನರಿ ಪಥದೊಂದಿಗೆ `spawn()` ಅನ್ನು ಕರೆಯಲಾಗುತ್ತದೆ; ಇದು ಬೆಂಬಲಿತ ಬೈನರಿಗಳ ಸ್ಥಿರ ಅನುಮತಿ ಪಟ್ಟಿಯಾಗಿದೆ.
- Stdout/stderr ಅನ್ನು ಮೆಮೊರಿಯಲ್ಲಿ ಬಫರ್ ಮಾಡಲಾಗುತ್ತದೆ (5 MB ಮಿತಿ, `_lib.ts` ನೋಡಿ) — ಬಳಕೆದಾರರು ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಿಂದ ಲಾಗಿಂಗ್ ಸಕ್ರಿಯಗೊಳಿಸದ ಹೊರತು ಡಿಸ್ಕ್ಗೆ ಬರೆಯಲಾಗುವುದಿಲ್ಲ.

**v3.8.6 ತಗ್ಗಿಸುವಿಕೆ**: ಯಾವುದೇ ಕ್ರಿಯಾತ್ಮಕ ಬದಲಾವಣೆ ಇಲ್ಲ. ವಿಶೇಷಾಧಿಕಾರದ ಮಾರ್ಗಗಳನ್ನು ಬಂಡಲ್ನಿಂದ ಭೌತಿಕವಾಗಿ ತೆಗೆದುಹಾಕಲು ಬಯಸುವ ಬಳಕೆದಾರರಿಗಾಗಿ ಕನಿಷ್ಠ ಬಿಲ್ಡ್ ಪ್ರೊಫೈಲ್
(`OMNIROUTE_BUILD_PROFILE=minimal`), `src/lib/services/installers/ninerouter.ts` ಅನ್ನು ಸ್ಟಬ್ನಿಂದ ಬದಲಾಯಿಸುತ್ತದೆ.

**ನಾವು ಇದನ್ನು ಏಕೆ ಉಳಿಸಿಕೊಂಡಿದ್ದೇವೆ**: 9router ಒಂದು ಐಚ್ಛಿಕವಾದ, ಸ್ಥಳೀಯವಾಗಿ ಸ್ಥಾಪಿಸಬಹುದಾದ ಸಹವರ್ತಿ ಸೇವೆಯಾಗಿದೆ (WordPress-ಶೈಲಿಯ ಪ್ಲಗಿನ್ ಎಂದು ಪರಿಗಣಿಸಿ) — ಕಟ್ಟುನಿಟ್ಟಾಗಿ ಸ್ವಯಂ-ಆಯ್ಕೆಯ ಮೂಲಕ ಮಾತ್ರ.

## §5 — OmniRoute Cloud Sync ರುಜುವಾತು ರೈಟ್-ಬ್ಯಾಕ್ (`api/keys/[id]/route.js`)

**ಮೂಲ ಫೈಲ್ಗಳು**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`.
- `src/app/api/keys/[id]/route.ts` — `syncKeysToCloudIfEnabled()` ಅನ್ನು ಆಹ್ವಾನಿಸುತ್ತದೆ.

**ಪ್ರಚೋದಕ**: `isCloudEnabled()` `true` ಅನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ (ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಿಂದ ಹೊಂದಿಸಲಾಗಿದೆ) **ಮತ್ತು**
`CLOUD_URL` ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾಗಿದೆ. ಎರಡೂ ಆಫ್ ಆಗಿದ್ದರೆ, Cloud ಎಂಡ್ಪಾಯಿಂಟ್ಗೆ ಯಾವುದೇ ಹೊರಹೋಗುವ ನೆಟ್ವರ್ಕ್ ಕರೆ ಮಾಡಲಾಗುವುದಿಲ್ಲ.

**v3.8.5 ನಡವಳಿಕೆ (Socket.dev ಸರಿಯಾದ ರೀತಿಯಲ್ಲಿ ಪತ್ತೆಹಚ್ಚಿದ ದೋಷ)**:

`cloudUpdatedAt > localUpdatedAt` ಆಗಿದ್ದಾಗ, Cloud ಪ್ರತಿಕ್ರಿಯೆಯಿಂದ
`accessToken`, `refreshToken`, ಮತ್ತು `providerSpecificData` ಅನ್ನು
`updateLocalTokens()` ತಿದ್ದಿ ಬರೆಯುತ್ತಿತ್ತು. HMAC ಇಲ್ಲ, ಸಹಿ ಇಲ್ಲ, ಚೆಕ್ಸಮ್ ಇಲ್ಲ. ತಪ್ಪಾಗಿ ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾದ ಅಥವಾ ದುರುದ್ದೇಶಪೂರಿತ `CLOUD_URL` (ಅಥವಾ ಚಾನಲ್ನಲ್ಲಿರುವ MITM) ಪ್ರೊವೈಡರ್ OAuth ಟೋಕನ್ಗಳನ್ನು ಸದ್ದಿಲ್ಲದೆ ಬದಲಾಯಿಸಬಹುದಾಗಿತ್ತು.

**v3.8.6 ಪರಿಹಾರ ಕ್ರಮ**:

1. **HMAC ಪರಿಶೀಲನೆ**: JSON ಅನ್ನು ಪಾರ್ಸ್ ಮಾಡುವ ಮೊದಲು `verifyCloudSignature(rawBody, sigHeader)`,
   `X-Cloud-Sig` ಹೆಡರ್ ಅನ್ನು (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`) ಪರಿಶೀಲಿಸುತ್ತದೆ. ಸೀಕ್ರೆಟ್ ಹೊಂದಿಸಿದ್ದರೆ, ಸಹಿ ಕಡ್ಡಾಯವಾಗಿರುತ್ತದೆ.
   ಹೊಂದಿಸದಿದ್ದರೆ (ಲೆಗಸಿ ಮೋಡ್), ಎಚ್ಚರಿಕೆಯನ್ನು ಲಾಗ್ ಮಾಡಿ ಪ್ರತಿಕ್ರಿಯೆಯನ್ನು
   ಸ್ವೀಕರಿಸಲಾಗುತ್ತದೆ — v3.9 ನಲ್ಲಿ ಸೀಕ್ರೆಟ್ ಕಡ್ಡಾಯವಾಗುತ್ತದೆ.
2. **ಸೀಕ್ರೆಟ್ ಫೀಲ್ಡ್ ಆಯ್ಕೆ**: `accessToken` / `refreshToken` /
   `providerSpecificData` ಅನ್ನು `OMNIROUTE_CLOUD_SYNC_SECRETS=true` ಆಗಿದ್ದಾಗ
   **ಮಾತ್ರ** ತಿದ್ದಿ ಬರೆಯಲಾಗುತ್ತದೆ. ಡೀಫಾಲ್ಟ್ ಮೋಡ್ ರುಜುವಾತೇತರ ಮೆಟಾಡೇಟಾವನ್ನು
   (`expiresAt`, `status`, `lastError*`, `rateLimitedUntil`, `updatedAt`) ಮಾತ್ರ
   ಸಿಂಕ್ ಮಾಡುತ್ತದೆ. ರಿಮೋಟ್ ಟೋಕನ್ ಸಿಂಕ್ ಅನ್ನು ಅವಲಂಬಿಸಿದ್ದ ಬಳಕೆದಾರರಿಗೆ ಇದು
   **ಬ್ರೇಕಿಂಗ್ ಬದಲಾವಣೆ** — ಅವರು ಸ್ಪಷ್ಟವಾಗಿ ಆಯ್ಕೆ ಮಾಡಬೇಕು.

**ನಾವು ಇದನ್ನು ಏಕೆ ಉಳಿಸಿಕೊಳ್ಳುತ್ತೇವೆ**: OmniRoute Cloud ಟೆನೆಂಟ್ಗೆ ತಂಡದ ರುಜುವಾತುಗಳನ್ನು ಕೇಂದ್ರೀಕರಿಸಲು Cloud Sync ಏಕೈಕ ಮಾರ್ಗವಾಗಿದೆ. ಈ ಪರಿಹಾರವು ಅಪಾಯದ ಮಾದರಿಯನ್ನು ಪ್ರಾಮಾಣಿಕವಾಗಿಸುತ್ತದೆ:
"ಸರ್ವರ್ ಸಹಿ ಮಾಡುತ್ತದೆ, ಕ್ಲೈಂಟ್ ಪರಿಶೀಲಿಸುತ್ತದೆ, ಆಪರೇಟರ್ ಆಯ್ಕೆ ಮಾಡುತ್ತಾರೆ."

## ಬಿಲ್ಡ್ ಪ್ರೊಫೈಲ್: `minimal`

Socket-ಸ್ನೇಹಿ ಆರ್ಟಿಫ್ಯಾಕ್ಟ್ ಅಗತ್ಯವಿರುವ ಬಳಕೆದಾರರು ಹೀಗೆ ಬಿಲ್ಡ್ ಮಾಡಿ:

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

webpack `NormalModuleReplacementPlugin` ನಾಲ್ಕು ಮಾಡ್ಯೂಲ್ಗಳನ್ನು ಸ್ಟಬ್ಗಳಿಗೆ ಅಲಿಯಾಸ್ ಮಾಡುತ್ತದೆ:

| ಮಾಡ್ಯೂಲ್                                    | ಸ್ಟಬ್                                            |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

ಪ್ರತಿಯೊಂದು ಸ್ಟಬ್ ಒಂದೇ ಇಂಟರ್ಫೇಸ್ ಅನ್ನು ಎಕ್ಸ್ಪೋರ್ಟ್ ಮಾಡುತ್ತದೆ, ಆದರೆ ಪ್ರತಿಯೊಂದು ಫಂಕ್ಷನ್ ರನ್ಟೈಮ್ನಲ್ಲಿ
`featureDisabledError(name)` ಅನ್ನು ಥ್ರೋ ಮಾಡುತ್ತದೆ. ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಲಾದ
ಮಾಡ್ಯೂಲ್ ಅನ್ನು ಅವಲಂಬಿಸಿರುವ ರೂಟ್ಗಳು ಸೂಕ್ಷ್ಮ ಕೋಡ್ ಪಥವನ್ನು ಸಕ್ರಿಯಗೊಳಿಸುವ ಬದಲು,
ಸ್ಪಷ್ಟ ಸಂದೇಶದೊಂದಿಗೆ HTTP 503 ಅನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತವೆ.

ಪರಿಣಾಮವಾಗಿ ದೊರೆಯುವ ಬಂಡಲ್ ಅನ್ನು `omniroute-secure` ಆಗಿ ಪ್ರಕಟಿಸಲು ಉದ್ದೇಶಿಸಲಾಗಿದೆ. ಪ್ರಕಟಣೆಯ ವಿಧಾನಕ್ಕಾಗಿ
`docs/ops/PUBLISHING_SECURE.md` ನೋಡಿ.
