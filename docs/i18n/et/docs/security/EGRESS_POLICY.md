> **Kinnita väljaminev liiklus iga puhverserveri puhul ühele IP-perekonnale — `auto`, `ipv4` või `ipv6` —, et ainult IPv6-t kasutav väljundliiklus ei kanduks kunagi märkamatult tagasi IPv4-le.**

> **Tõeallikas:** `open-sse/utils/proxyFamily.ts`, `open-sse/utils/proxyDispatcher.ts`, `open-sse/utils/proxyFetch.ts`, `open-sse/utils/socksConnectorWithFamily.ts`, `open-sse/utils/proxyFamilyResolve.ts`, `src/shared/validation/schemas.ts`, `src/lib/db/proxies.ts`, `src/lib/db/upstreamProxy.ts`, `src/lib/db/migrations/099_proxy_family.sql`

OmniRoute võimaldab määrata igale puhverserverile **aadressiperekonna väljundliikluse direktiivi**. Vaikimisi valib operatsioonisüsteem IPv4 või IPv6 (kaksikpinu, „Happy Eyeballs“). Kui määrate direktiiviks `ipv4` või `ipv6`, kinnitab OmniRoute kõik selle puhverserveri kaudu loodavad ühendused valitud perekonnale ja **katkestab turvaliselt**, selle asemel et minna üle teisele perekonnale.

Sellel lehel kirjeldatakse, mis see direktiiv on, miks see olemas on, kus seda seadistada ja kuidas käituskeskkond selle väärtuse lahendab.

## Mis see on

Igal registris oleval puhverserveril on väli `family`, millel on kolm võimalikku väärtust ja mida valideeritakse Zodi loendiga:

```ts
// src/shared/validation/schemas.ts
family: z.enum(["auto", "ipv4", "ipv6"]).optional().default("auto"),
```

Välja vaikeväärtus on `"auto"`, mis säilitab varasema kaksikpinu käitumise. Väärtuse `ipv4` või `ipv6` määramine kinnitab selle puhverserveri ühenduse loomisel kasutatava perekonna.

Direktiiv normaliseeritakse kõikjal ühe abifunktsiooni kaudu, nii et iga tundmatu väärtus taandub väärtusele `auto`:

```ts
// open-sse/utils/proxyFamily.ts
export type ProxyFamily = "auto" | "ipv4" | "ipv6";

export function parseProxyFamily(value: unknown): ProxyFamily {
  return value === "ipv4" || value === "ipv6" ? value : "auto";
}
```

## Miks see olemas on

Lisatud PR-is [#3777](https://github.com/diegosouzapw/OmniRoute/pull/3777). Peamised ajendid:

| Probleem                                                             | Mida direktiiv parandab                                                                                                                                                                                                                                                                                                                                                  |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Ainult IPv6-t kasutava väljundliikluse lekkimine IPv4-le**         | Kui puhverserveri hostil on nii A- kui ka AAAA-kirjed (või operatsioonisüsteem eelistab IPv4-t), võib Happy Eyeballs luua väljamineva ühenduse IPv4 kaudu isegi siis, kui soovite kasutada ainult IPv6-teed. Väärtusele `ipv6` kinnitamine kõrvaldab selle lekke.                                                                                                        |
| **Jagatud väljundliikluse anomaaliast tingitud tühistamine**         | Pöörlevad teenusepakkujad (codex/openai) tühistavad pääsuloake, kui paljude kontode väljundliiklus liigub suurel hulgal läbi **sama** IP-aadressi. Väljundliikluse perekonna juhtimine aitab hoida kontosid eraldiseisvatel ja prognoositavatel väljundteedel (sellega seotud väljund-IP diagnostika kohta vt [`src/lib/proxyEgress.ts`](../../src/lib/proxyEgress.ts)). |
| **Deterministlik väljundliiklus nõuetele vastavuse/testimise jaoks** | Kui peate tagama, et liiklus väljub kindla perekonna kaudu, ei piisa väärtusest `auto`.                                                                                                                                                                                                                                                                                  |

Direktiiv on teadlikult **puhverserveripõhine**, mitte globaalne — teie kogumi eri puhverserveritel võivad olla erinevad reeglid.

## Kolm väärtust

| Väärtus | Kasutajaliidese silt      | Käitumine                                                                                                                                                                              |
| ------- | ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`  | `Automaatne (kaksikpinu)` | OS valib aadressiperekonna. IP-literaalist puhverserveri hosti korral määrab aadressiperekonna literaal ise; hostinime korral sobivad mõlemad aadressiperekonnad. See on vaikeväärtus. |
| `ipv4`  | `Ainult IPv4`             | Seob ühenduse IPv4-ga. Ühendust ei looda, kui puhverserveri hostil puudub IPv4 (A) kirje.                                                                                              |
| `ipv6`  | `Ainult IPv6`             | Seob ühenduse IPv6-ga. Ühendust ei looda, kui puhverserveri hostil puudub IPv6 (AAAA) kirje.                                                                                           |

Kasutajaliidese stringid asuvad failis `src/i18n/messages/en.json` (`labelFamily`, `familyAuto`, `familyIpv4`, `familyIpv6`, `familyHint`).

## Seadistamine

### Töölaud

Valik asub vahekaardi **Puhverserverite kogum** puhverserveri vormil:

1. Avage **Töölaud → Seaded → Puhverserver → Puhverserverite kogum**
2. Lisage puhverserver või muutke olemasolevat
3. Määrake rippmenüü **IP-aadressiperekond** väärtuseks `Automaatne (kaksikpinu)`, `Ainult IPv4` või `Ainult IPv6`
4. Salvestage

Juhtelemendi renderdab `ProxyRegistryManager.tsx` (ühendatud failis `proxy/ProxyPoolTab.tsx`).

### API

Väli `family` kuulub puhverserveriregistri loomise ja uuendamise päringukehadesse, seda valideerivad `createProxyRegistrySchema` / `updateProxyRegistrySchema` (`src/shared/validation/schemas.ts`) ning töötlevad `POST` / `PATCH /api/v1/management/proxies`:

```bash
# Loo ainult IPv6 kasutav puhverserver
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "IPv6 egress",
    "type": "socks5",
    "host": "proxy.example.com",
    "port": 1080,
    "family": "ipv6"
  }'

# Muuda olemasolev puhverserver ainult IPv4 kasutavaks
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{ "id": "proxy-uuid-here", "family": "ipv4" }'
```

Sama välja aktsepteerib ka ülesvoolu puhverserveri kirjete jaoks kasutatav tekstisisene puhverserveri konfiguratsiooniobjekt (`upstream_proxy_config.family`, vt [Andmemudel](#data-model)).

Ülejäänud puhverserveri loomise, lugemise, uuendamise, kustutamise ja määramise API kohta vt [PROXY_GUIDE.md](../ops/PROXY_GUIDE.md).

## Kuidas `auto` lahendatakse

Kui `family` väärtus on `auto`, siis OmniRoute **ei** lisa ühtegi direktiivi — puhverserveri URL-i kasutatakse muutmata kujul ja ühenduse aadressiperekond määratakse olemuslikult.

URL-i koostamise ajal (`proxyConfigToUrl` / `normalizeProxyUrl` failis `open-sse/utils/proxyDispatcher.ts`) annab `auto` puhverserver tavalise URL-i ilma markerita:

```ts
// open-sse/utils/proxyDispatcher.ts
const fam = parseProxyFamily(config.family);
const normalized = normalizeProxyUrl(proxyUrlStr, "context proxy", {
  allowSocks5,
});
return fam === "auto" ? normalized : `${normalized}?family=${fam}`;
```

Edastamise ajal (`resolveDispatcherFamily`) lahendatakse `auto` IP-literaalist hosti olemuslikuks aadressiperekonnaks või hostinime korral väärtuseks `null` (valiku teeb OS):

```ts
// open-sse/utils/proxyDispatcher.ts
function resolveDispatcherFamily(parsed: URL): 4 | 6 | null {
  const directive = parseProxyFamily(parsed.searchParams.get("family") ?? undefined);
  const literal = detectIpLiteralFamily(parsed.hostname);
  if (directive === "auto") return literal; // hostinime korral null → valiku teeb OS
  // ...
}
```

Seega:

- `auto` + IP-literaalist host (`192.0.2.1` / `[2001:db8::1]`) → selle literaali aadressiperekond.
- `auto` + hostinimi → `null` → OS-i tavapärane kaksikpinu nimelahendus.

## Kuidas `ipv4` / `ipv6` jõustatakse

Mitte-`auto` direktiiv liigub ühe sünteetilise päringuparameetrina — `?family=ipv4` või `?family=ipv6` —, mis lisatakse normaliseeritud puhverserveri URL-ile üks kord. `normalizeProxyUrl` eemaldab selle parameetri hoolikalt ja lisab selle uuesti täpselt üks kord, et see ei rikuks kunagi pordi sõelumist.

Dispetšeri loomisel loetakse parameeter ja teisendatakse konkreetseks ühenduse aadressipereks. Kui host on **vastupidise** aadressipere IP-literaal, väljastab OmniRoute erindi (vastuolu korral rakendatakse fail-closed-põhimõtet):

```ts
// open-sse/utils/proxyDispatcher.ts
const want = directive === "ipv6" ? 6 : 4;
if (literal !== null && literal !== want) {
  throw new Error(
    `[ProxyDispatcher] Proxy family directive ${directive} contradicts ${literal === 6 ? "IPv6" : "IPv4"} literal host`
  );
}
```

Seejärel fikseeritakse konkreetne aadressipere konnektoris:

- **HTTP/HTTPS-puhverserverid** (`ProxyAgent`): `proxyTls: { family, autoSelectFamily: false }` — keelab Happy Eyeballsi, nii et ühendus luuakse ainult valitud aadressiperega.
- **SOCKS5-puhverserverid**: kohandatud konnektor edastab SOCKS-kliendile `socket_options: { family, autoSelectFamily: false }` (vt [SOCKS5 ühilduvus](#socks5-ühilduvus)).

## SOCKS5 ühilduvus

Aadressipere fikseerimine töötab SOCKS5-puhverserveritega, kuid standardne `fetch-socks` ei avalda soklisuvandeid, mida on vaja puhverserverihüppe aadressipere fikseerimiseks. OmniRoute sisaldab selleks oma konnektorit:

```ts
// open-sse/utils/socksConnectorWithFamily.ts
export function buildSocksFamilySocketOptions(family: 4 | 6 | null): Record<string, unknown> {
  if (family === 6) return { family: 6, autoSelectFamily: false };
  if (family === 4) return { family: 4, autoSelectFamily: false };
  return {};
}
```

Kõik SOCKS5-dispetšid läbivad `createSocksDispatcherWithFamily`, olenemata `family` väärtusest (sealhulgas `null` / `auto` hostinime korral): `buildSocksFamilySocketOptions(null)` tagastab `{}` ning kasutatakse sama `SocksClient.createConnection` + TLS-i `buildConnector` teed koos `socket_options` fikseerimisega, et Happy Eyeballs ei saaks ainult IPv6-väljundliikluse poliitika korral valida IPv4.

SOCKS5 tugi on vaikimisi sisse lülitatud (sellest saab loobuda määranguga `ENABLE_SOCKS5_PROXY=false`); vt [PROXY_GUIDE.md → Keskkonnamuutujad](../ops/PROXY_GUIDE.md#environment-variables).

## Fail-closed-käitumine

Direktiivi peamine eesmärk on valele aadressiperele vaikimisi tagasilangemise asemel sellest **keelduda**. Seda jõustavad kaks kontrolli:

1. **Literaali vastuolu** — IP-literaalist hostiga vastuolus olev direktiiv väljastab dispetšeri loomise ajal erindi (`resolveDispatcherFamily`, näidatud eespool).

2. **Hostinime ühenduseelne DNS-kontroll** — fikseeritud aadressiperega hostinimelise puhverserveri korral kontrollib `proxyFetch.ts` funktsiooni `assertHostnameSupportsFamily` abil **enne** väljundliiklust, kas hostinimel on nõutava aadressipere kirje:

   ```ts
   // open-sse/utils/proxyFamilyResolve.ts
   const hasFamily = records.some((r) => r.family === family);
   if (!hasFamily) {
     throw new Error(
       `[ProxyFamily] Proxy host ${host} has no ${family === 6 ? "IPv6 (AAAA)" : "IPv4 (A)"} record; ` +
         `refusing ${family === 6 ? "IPv6" : "IPv4"}-only egress (fail-closed)`
     );
   }
   ```

   Tõrke korral lisab `proxyFetch.ts` veale `code = "PROXY_FAMILY_UNAVAILABLE"` ja `statusCode = 503`. DNS-i lahendamise tõrget käsitletakse samuti fail-closed-põhimõttel (väljundliiklusest keeldutakse).

IP-literaalist hostide puhul DNS-i ühenduseelne kontroll midagi ei tee — nende aadressipere on olemuslik ega vaja nimeotsingut.

## Andmemudel

Veerg `family` lisati migratsiooniga `099_proxy_family.sql` **kahte** tabelisse:

```sql
-- src/lib/db/migrations/099_proxy_family.sql
ALTER TABLE proxy_registry ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
ALTER TABLE upstream_proxy_config ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
```

- `proxy_registry.family` — registrikirjete puhverserveripõhine direktiiv (`src/lib/db/proxies.ts`). Lahenduspäringud valivad veeru `family` koos teiste puhverserveri veergudega ning puuduv või mittesõneline väärtus teisendatakse väärtuseks `"auto"`.
- `upstream_proxy_config.family` — ülesvoolu puhverserveri kirjete direktiiv (`src/lib/db/upstreamProxy.ts`), millel on sama vaikeväärtus `"auto"`.

Kui lahendatud puhverserveri objekti `family` väärtus ei ole `auto`, lisab `proxyConfigToUrl` markeri `?family=`, et fikseeritud väärtus säiliks kuni dispetšerini.
