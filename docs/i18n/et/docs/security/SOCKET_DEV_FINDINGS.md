> **Käsitlusala märkus:** `socket.yml` konfigureerib Socket.dev-i registripoolse npm-i artefakti avaldamisjärgse kontrolli (eiratud teed paketti mittekuuluva sisu jaoks, näiteks `tests/`, `docs/` ja koostearuanded). See ei seadista CI/PR-i ühendamise kontrollväravat — ükski töövoog kataloogis `.github/workflows`, ükski `package.json`-i skript ega ükski `Makefile`-i sihtmärk ei käivita Socket.dev-i.

See dokument on hooldaja koostatud kinnitus kuue
`AI tuvastatud potentsiaalse pahavara` leiu kohta, mis tuvastati versioonis `omniroute@3.8.5`, ning
versioonis `omniroute@3.8.6` rakendatud leevendusmeetmete kohta. Selle eesmärgid on järgmised:

1. Turbekonveieri haldajatel on üks viiteallikas, millele osutada, kui neil on vaja
   hinnata leide tegeliku lähtekoodi põhjal.
2. Tulevased tehisintellektil põhinevad skannerid saavad tuvastada hooldaja allkirjastatud kinnituse, et iga
   märgistatud tee on tahtlik, vabatahtlikult kasutatav ja dokumenteeritud.
3. Meil on kirjalik ülevaade sellest, _miks_ iga väljakutsekoht on just sellise kujuga —
   et tulevane refaktoreerimine ei tooks kogemata uuesti sisse tunnusmustrit, mis
   teadlikult eemaldati.

Kui haldate skannerit, mis märgistab pärast v3.8.6 leevendusmeetmete avaldamist mõne
alltoodud väljakutsekoha uuesti, avage palun probleem koos kontrollijäljega ja
me täiendame siinset kinnitust.

## §1 — MITM-i juur-CA installimine (`77484.js`)

**Lähtefailid**:

- `src/mitm/cert/install.ts` — avalikud `installCert()` / `uninstallCert()`,
  platvormipõhised `installCertWindows/Mac/Linux`.
- `src/mitm/systemCommands.ts` — ühised `execFile` / `spawn` / PowerShelli
  abifunktsioonid, mida installimisteed kasutavad.

**Käivitaja**: kasutaja klõpsab kohalikul juhtpaneelil aadressil
`/dashboard/cli-tools/mitm` valikut „Luba MITM-puhverserver“. Marsruut on juurdepääsetav ainult tagasisideaadressilt — vt ranget reeglit nr 17 failis
`CLAUDE.md` ja `src/server/authz/routeGuard.ts::isLocalOnlyPath()`. Tunneli kaudu lekkinud
JWT **ei saa** seda kooditeed käivitada.

**Tehtavad privilegeeritud toimingud (platvormide kaupa)**:

| OS                     | Käsk/käsud                                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | `certutil -addstore Root <cert>` UAC kaudu                                                                        |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | profiilipõhine NSS-i andmebaasi uuendamine käsuga `certutil -d sql:<profile>`                                     |

Need on samad käsud, mida kasutavad `mitmproxy`, Charles Proxy, Fiddler ja
Caddy. Nende olemasolu OmniRoute'is on dokumenteeritud failis
`docs/security/STEALTH_GUIDE.md`.

**v3.8.6 leevendusmeede**:

- `runElevatedPowerShell()` ei kasuta enam argumenti `-EncodedCommand <base64utf16le>`.
  Kõrgendatud õigustega käivitatav sisu kirjutatakse iga väljakutse jaoks eraldi ajutisse `.ps1` faili (režiim 0o600,
  privaatses `mkdtempSync` kataloogis) ja sellele viidatakse argumendiga `-File`. Fail
  kustutatakse plokis `finally`. See eemaldab Socket.dev-i tehisintellekti
  klassifikaatori märgistatud tüüpilise
  PowerShelli kaudu base64-kodeeringuga õiguste tõstmise signatuuri.
- `installCertWindows` sisaldab tekstisisest `SECURITY-AUDITOR-NOTE:` plokki,
  mis viitab siia.

**Miks me selle säilitame**: MITM-puhverserver on dokumenteeritud funktsioon, mida kasutatakse failides
`docs/security/STEALTH_GUIDE.md` ja `docs/frameworks/MITM-PROXY.md`. Selle eemaldamine
rikuks agendisilla funktsioonikomplekti.

## §2 — Zedi autentimisteabe import (`app/api/providers/zed/import/route.js`)

**Lähtefailid**:

- `src/app/api/providers/zed/discover/route.ts` _(uus versioonis v3.8.6)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(uus versioonis v3.8.6)_

**Käivitaja**: kasutaja klõpsab kohaliku töölaua teenusepakkujate lehel nuppu „Impordi Zedist“. Pääsupunkt on kaitstud funktsiooniga `requireManagementAuth`. Zedi redaktor ise kirjutab oma teenusepakkujate API-võtmed operatsioonisüsteemi võtmehoidlasse dokumenteeritud teenusenimede alla — vt https://zed.dev/docs/ai/llm-providers.

**v3.8.5 käitumine (mille Socket.dev märgistas)**:

`POST /import` tuvastas autentimisteabe ja salvestas selle automaatselt ühe päringu-vastuse tsükliga kohalikku SQLite'i hoidlasse. Kontopõhist kinnitamist ega sõrmejälge ei olnud, vaid „leiti N luba, kõik imporditi“.

**v3.8.6 leevendus — kaheastmeline kinnitamine**:

1. **`POST /api/providers/zed/discover`** tagastab
   `{ candidates: [{ provider, service, account, fingerprint }] }`. Toortokenit
   **ei edastata kunagi**. Sõrmejälg on
   `sha256(service|account|token).slice(0,16)`.
2. Töölaud kuvab kandidaatide loendi, operaator valib imporditavad kirjed ja
   saadab päringu `{ confirmedAccounts: [{ service, account, fingerprint }] }`
   aadressile **`POST /api/providers/zed/import`**.
3. Impordi pääsupunkt **loeb võtmehoidla serveris uuesti** ja filtreerib väärtuste
   `(service, account, fingerprint)` alusel. Manipuleeritud või taasesitatud
   tuvastusvastus ei saa panna impordi pääsupunkti salvestama asjassepuutumatut
   tokenit — kui aktiivne token on pärast tuvastamist muutunud, ei vasta
   sõrmejälg enam ja autentimisteave jäetakse vahele.

Keskkonnalipp `OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` säilitab v3.8.5
käitumise operaatoritele, kes pole oma automatiseerimist veel värskendanud. See
eemaldatakse versioonis v3.9.

**Miks me selle alles jätame**: Zedist importimine on kõige kasutajasõbralikum
alustamisviis kasutajatele, kes juba kasutavad Zedi ja soovivad kopeerida oma
teenusepakkujate võtmed OmniRoute'i ilma neid uuesti kleepimata.

## §3 — `execFile` / `spawn` / kõrgendatud õigustega PowerShell (`21843.js`)

**Lähtefailid**: `src/mitm/systemCommands.ts`.

**Miks märgistati**: koodijupp reekspordib funktsioonid `execFileWithPassword`,
`runElevatedPowerShell` ja ühise abifunktsiooni `quotePowerShell`. Socket.devi
tehisintellektil põhinev klassifikaator käsitleb neid üldotstarbelise
„hostis käivitamise ja õiguste kõrgendamise tööriistakomplektina“. OmniRoute'is
kasutatakse neid ainult MITM-sertifikaadi installimise protsessis (§1) ning
funktsiooni `execFileWithPassword` puhul `sudo`-käsu käivitamiseks.

**v3.8.6 leevendus**:

- Funktsiooni `runElevatedPowerShell` refaktoreerimine (vt §1).
- Nii `runElevatedPowerShell` kui ka `execFileWithPassword` sisaldavad
  tekstisisest plokki `SECURITY-AUDITOR-NOTE:`, mis dokumenteerib lubatud
  kutsujad ja fikseeritud täitmisfailide loendi.
- Funktsiooni `execFileWithPassword` väljakutse `spawn()` sisaldab markerit
  `nosemgrep` koos lubatud täitmisfailide loendiga, mida abifunktsioon tohib
  vastu võtta — kasutaja sisendist **ei ole teed väärtusteni
  `finalCommand`/`finalArgs`**.

## §4 / §6 — 9routeri teenusejärelevalve (`api/services/9router/{start,restart}/route.js`)

**Lähtefailid**:

- `src/app/api/services/9router/_lib.ts` — järelevalve tehasefunktsioon.
- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`.
- `src/lib/services/ServiceSupervisor.ts` — üldotstarbeline protsessi käivitamine / seisundikontroll / logipuhver.

**Käivitaja**: kasutaja klõpsab kohaliku töölaua manustatud teenuste lehel nuppu
„Installi“ / „Käivita“.

**Juba rakendatud kaitsemeetmed**:

- Kõik marsruudid `/api/services/*` on faili
  `src/server/authz/routeGuard.ts` kohaselt `LOCAL_ONLY` (range reegel nr 17).
  Tagasisideaadressi nõude jõustamine toimub enne mis tahes autentimiskontrolli
  — lekkinud JWT-ga ei ole neile võimalik ligi pääseda.
- 9routeri andmebaasirida luuakse väärtustega `status='not_installed', auto_start=0`
  (vt `src/lib/db/migrations/071_services.sql:19`). Teenus **ei käivitu**
  esmakordsel käivitamisel.
- Funktsiooni `spawn()` kutsutakse binaarfaili teega, mille tagastab
  `resolveSpawnArgs(apiKey, PORT)` failis `src/lib/services/installers/ninerouter.ts`;
  see funktsioon kasutab toetatud binaarfailide fikseeritud lubatud loendit.
- Standardväljund ja standardveavoog puhverdatakse mälus (5 MB piirang, vt
  `_lib.ts`) — kettale ei kirjutata midagi, välja arvatud juhul, kui kasutaja
  lubab töölaualt logimise.

**v3.8.6 leevendus**: funktsionaalseid muudatusi pole. Minimaalne koostamisprofiil
(`OMNIROUTE_BUILD_PROFILE=minimal`) asendab faili
`src/lib/services/installers/ninerouter.ts` tühifunktsiooniga nende kasutajate
jaoks, kes soovivad kõrgendatud õigustega kooditeed paketist füüsiliselt
eemaldada.

**Miks me selle alles jätame**: 9router on valikuline kohalikult installitav
kaasteenus (analoogne WordPressi pistikprogrammiga) — rangelt nõusolekupõhine.

## §5 — OmniRoute Cloud Synci autentimisteabe tagasikirjutus (`api/keys/[id]/route.js`)

**Lähtefailid**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`.
- `src/app/api/keys/[id]/route.ts` — kutsub välja `syncKeysToCloudIfEnabled()`.

**Käivitustingimus**: `isCloudEnabled()` tagastab `true` (määratakse juhtpaneelilt) **ja**
`CLOUD_URL` on seadistatud. Kui mõlemad on välja lülitatud, ei tehta Cloudi
lõpp-punktile ühtegi väljaminevat võrgupäringut.

**Versiooni v3.8.5 käitumine (viga, mille Socket.dev õigesti tuvastas)**:

`updateLocalTokens()` kirjutas Cloudi vastusest üle väljad `accessToken`,
`refreshToken` ja `providerSpecificData`, kui
`cloudUpdatedAt > localUpdatedAt`. Ei HMAC-i, allkirja ega kontrollsummat.
Valesti seadistatud või pahatahtlik `CLOUD_URL` (või kanali MITM-rünne) võis
teenusepakkuja OAuthi pääsmikud märkamatult välja vahetada.

**Versiooni v3.8.6 leevendusmeetmed**:

1. **HMAC-kontroll**: `verifyCloudSignature(rawBody, sigHeader)` kontrollib
   enne JSON-i parsimist päist `X-Cloud-Sig` (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`). Kui saladus on määratud, on allkiri kohustuslik. Kui seda pole
   (pärandrežiim), logitakse hoiatus ja vastus võetakse vastu — alates versioonist
   v3.9 on saladus kohustuslik.
2. **Salajaste väljade lubamine**: `accessToken` / `refreshToken` /
   `providerSpecificData` kirjutatakse üle **ainult** siis, kui
   `OMNIROUTE_CLOUD_SYNC_SECRETS=true`. Vaikerežiim sünkroonib ainult
   autentimisteabeta metaandmeid (`expiresAt`, `status`, `lastError*`,
   `rateLimitedUntil`, `updatedAt`). See on **ühilduvust murdev muudatus**
   kasutajatele, kes sõltusid pääsmike kaugsünkroonimisest — nad peavad selle
   selgesõnaliselt lubama.

**Miks me selle alles jätame**: Cloud Sync on OmniRoute Cloudi rentniku jaoks
ainus võimalus meeskonna autentimisteavet tsentraalselt hallata. Parandus muudab
ohumudeli ausaks: „server allkirjastab, klient kontrollib, operaator lubab“.

## Koosteprofiil: `minimal`

Kasutajad, kes vajavad Socketiga ühilduvat artefakti, saavad selle koostada käsuga:

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

Webpacki `NormalModuleReplacementPlugin` seob neli moodulit pseudomoodulitega:

| Moodul                                      | Pseudomoodul                                     |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

Iga pseudomoodul ekspordib sama liidese, kuid iga funktsioon viskab käitusajal
`featureDisabledError(name)` vea. Keelatud moodulist sõltuvad marsruudid
tagastavad HTTP 503 koos selge sõnumiga, selle asemel et tundlikku
kooditeed aktiveerida.

Saadud komplekt on mõeldud avaldamiseks nimega `omniroute-secure`. Avaldamisjuhised
leiate failist `docs/ops/PUBLISHING_SECURE.md`.

## Plugina eraldamine (jälgitakse v4 jaoks)

Pikas perspektiivis kavatseme jagada npm-paketi eraldi auditeeritavateks
mooduliteks. Jälgimisprobleemi leiate GitHubi probleemijälgija v4 verstapostist.
