TPROXY läbipaistev dekrüptimine on OmniRoute'i **5. liikluse hõiverežiim**
[Traffic Inspectori](../frameworks/TRAFFIC_INSPECTOR.md) / [AgentBridge'i](../frameworks/AGENTBRIDGE.md)
MITM-pinu jaoks. See püüab Linuxis kinni ja **dekrüptib** kohaliku väljamineva HTTPS-liikluse,
kasutades kerneli TPROXY-d ning reeglipõhist marsruutimist — **ilma** `/etc/hosts`-i võltsimata ja
**ilma** kogu operatsioonisüsteemi hõlmavaid süsteemse puhverserveri seadeid muutmata. See sobib
ilma graafilise liideseta keskkondadesse (puhastamist vajavaid DNS-i muudatusi pole) ning tulemüürireeglid
eemaldatakse taaskäivitamisel automaatselt.

Erinevalt teistest hõiverežiimidest ei vaja TPROXY hostipõhist seadistamist: see püüab läbipaistvalt
kinni sihtpordi **suvaliste** sihthostide liikluse, lõpetab TLS-i käigult iga SNI-hostinime jaoks
väljastatud lõppsertifikaadiga, hõivab dekrüptitud andmevahetuse ning krüptib päringu algsele
sihtkohale saatmiseks uuesti.

> **Ainult Linuxile, ainult root-kasutajale, kasutaja aktiveeritav.** See režiim nõuab Linuxit,
> C-tööriistaahelaga kompileeritud omalisandmoodulit ja võimekust **CAP_NET_ADMIN** (tavaliselt root).
> Selle kasutamine on piiratud ainult tagasisideaadressilt ligipääsetava AgentBridge'i API-ga ning see on
> vaikimisi keelatud. Usaldatud MITM-i CA, mis saab allkirjastada mis tahes hosti sertifikaadi, on võimas
> võimekus — vt [§6 Turvalisus](#6-security).

**Lähtekood:** `src/mitm/tproxy/`
**API marsruut:** `GET / POST / DELETE /api/tools/agent-bridge/tproxy`
**Juhtpaneeli lüliti:** Traffic Inspector → hõiverežiimide tööriistariba → **"TPROXY dekrüptimine"** ⚠
**Vt ka:** [`docs/frameworks/TRAFFIC_INSPECTOR.md`](../frameworks/TRAFFIC_INSPECTOR.md),
[`docs/frameworks/AGENTBRIDGE.md`](../frameworks/AGENTBRIDGE.md)

## §1 Mis see on ja millal seda kasutada

Kõigil ülejäänud neljal hõiverežiimil on oma piirang:

| Režiim                 | Kuidas liiklust suunatakse                                      | Piirang                                                  |
| ---------------------- | --------------------------------------------------------------- | -------------------------------------------------------- |
| AgentBridge            | fikseeritud hostikomplekti DNS-i võltsimine failis `/etc/hosts` | ainult registreeritud IDE-agendi hostid                  |
| Kohandatud hostid      | hostipõhine DNS-i võltsimine failis `/etc/hosts`                | üks kirje hosti kohta; hostide muutmiseks on vaja sudo-t |
| HTTP_PROXY             | `HTTP_PROXY`/`HTTPS_PROXY` keskkonnamuutuja                     | ainult keskkonnamuutujat arvestavad rakendused           |
| Süsteemne puhverserver | operatsioonisüsteemi puhverserveri seaded                       | muudab globaalset olekut; vajab tagasipööramist          |

TPROXY läbipaistev dekrüptimine suunab liiklust selle asemel **kerneli** tasandil. See
märgistab `mangle OUTPUT`-ahelas sihtporti (vaikimisi `443`) suunduvad uued kohalikud
väljaminevad TCP-ühendused, `ip rule` marsruudib märgistatud paketid ümber kohalikku
kohaletoimetusse ning uuesti sisenemisel annab `mangle PREROUTING`-ahela `TPROXY`-sihtmärk
need üle **IP_TRANSPARENT**-kuulajale, mis seejärel lõpetab TLS-i ja hõivab lihtteksti.

Kasutage seda, kui soovite hõivata ja dekrüptida liiklust protsessilt, mis:

- suhtleb hostiga, mida AgentBridge ei registreeri, ja
- ei arvesta muutujat `HTTP_PROXY`, ning
- mille tööd te ei soovi süsteemse puhverserveri muudatusega häirida.

Kuna kinnipüüdmine toimub kernelis, ei vaja lähteprotsess **ühtegi konfiguratsioonimuudatust**,
kuid protsess peab usaldama OmniRoute'i installitud dünaamilist CA-d
(vt [§4](#4-the-per-sni-dynamic-ca-and-trust-store-installer)).

## §3 Natiivne IP_TRANSPARENT lisamoodul

Node'i `net` moodul ei saa kutsuda `setsockopt(IP_TRANSPARENT)` _enne_ funktsiooni `bind()`, mida
TPROXY nõuab (vastasel juhul hülgab kernel ümbersuunatud paketid). Lisamoodul
(`src/mitm/tproxy/native/transparent.c`, kompileeritakse faili `binding.gyp` kaudu) on väike N-API
moodul, mis pakub kolme funktsiooni, mida kasutatakse faili `transparentSocket.ts` kaudu:

| Lisamooduli funktsioon                | Pistikupesa toimingud                                                                              | Kasutusotstarve                                                                           |
| ------------------------------------- | -------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `createTransparentListener(ip, port)` | `socket()` + **SO_REUSEADDR** + **IP_TRANSPARENT** + `bind()` + `listen()`, tagastab töötlemata fd | läbipaistev hõivekuulaja (Node võtab fd kasutusele funktsiooniga `server.listen({ fd })`) |
| `setSocketMark(fd, mark)`             | `setsockopt` **SO_MARK** olemasoleval fd-l                                                         | silmuse vältimine (proksi enda pistikupesade märgistamine)                                |
| `connectMarked(ip, port, mark)`       | `socket()` + **SO_MARK** **enne** mitteblokeerivat `connect()` kutset, tagastab fd                 | taaskrüptitud edastus ülesvoolu (SYN kannab märgist)                                      |

Algne sihtkoht loetakse väärtustest `socket.localAddress`/`localPort` — TPROXY
säilitab selle, seega pole **SO_ORIGINAL_DST**/NAT otsingut vaja.

### Lisamooduli kompileerimine

```bash
npm run build:native:tproxy      # cd src/mitm/tproxy/native && node-gyp rebuild
                                 # -> native/build/Release/transparent.node
```

- Käsu `npm run build` ajal käivitab `scripts/build/build-tproxy-native.mjs` käsu `node-gyp
rebuild`. See on **ainult Linuxile ja mittesurmav** — puuduv tööriistaahel jätab
  hõiverežiimi lihtsalt kättesaamatuks.
- `assembleStandalone.mjs` kopeerib faili `build/Release/transparent.node`
  autonoomsesse paketti; `transparentSocket.ts` leiab selle nii mooduli suhtes kui ka
  cwd suhtes (`<cwd>/src/mitm/tproxy/native/...`).
- `build/` ja `prebuilds/` on git'is ignoreeritud — binaarfail **kompileeritakse, kuid seda ei
  salvestata kunagi hoidlasse**.

Laadija kontrollib prioriteedijärjekorras:
`native/build/Release/transparent.node`, seejärel `native/prebuilds/transparent.node`
(mõlemat nii mooduli suhtes kui ka kataloogi `<cwd>/src/mitm/tproxy/` all).

## §4 SNI-põhine dünaamiline CA ja usaldushoidla paigaldaja

> **#6684 värskendus:** AgentBridge'i staatiline server (`src/mitm/server.cjs`) kasutab nüüd
> sama CA/leaf-arhitektuuri mustrit ühe staatilise
> iseallkirjastatud leaf-sertifikaadi asemel. See kasutab **eraldi** CA-eksemplari
> (`src/mitm/cert/rootCa.ts`, püsivalt asukohas `<DATA_DIR>/mitm/ca.key`/`ca.crt`)
> ja paigaldatakse olemasolevasse `omniroute-mitm.crt` usaldushoidla pessa
> (asendades seal vana üksiku leaf-sertifikaadi — topeltusalduse puhastamist pole vaja),
> jäädes allpool toodud TPROXY enda `omniroute-tproxy-ca.crt` pesast täielikult
> eraldatuks. Uued AgentBridge'i paigaldused saavad CA-mudeli automaatselt; paigaldus,
> mis juba usaldab vana staatilist leaf-sertifikaati, jätkab selle kasutamist, kuni operaator
> lubab uue mudeli muutujaga `MITM_ROOT_CA_ENABLED=true` (vt
> `src/mitm/cert/migration.ts`) — usaldatud MITM CA, mis saab allkirjastada
> leaf-sertifikaadi **mis tahes** hostile, on oluliselt võimsam kui vana fikseeritud
> SAN-idega leaf-sertifikaat, mistõttu ei tehta juba usaldatud paigalduse puhul
> üleminekut kunagi vaikimisi.

Ajalooliselt töötas staatiline AgentBridge'i MITM-sertifikaat ainult seetõttu, et
AgentBridge võltsib DNS-i **fikseeritud** hostikomplekti jaoks (mis on nüüd
alltoodud mudeliga ühtlustatud). TPROXY püüab kinni **suvaliste** hostide liiklust,
seega peab selle kuular esitama kehtiva leaf-sertifikaadi iga kliendi küsitud
SNI jaoks — sama nõue kehtib nüüd AgentBridge'ile kogu `MITM_TOOL_HOSTS`
komplekti (9 tööriistakirjet), mitte ainult 4 antigravity hosti puhul.

### Dünaamiline CA (`src/mitm/tproxy/dynamicCert.ts`)

`DynamicCertStore` käitab kohalikku CA-d (mis põhineb sõltuvusel `selfsigned`), mis:

- Genereerib pika kehtivusajaga CA funktsiooni `generateMitmCa()` kaudu (CN `"OmniRoute MITM CA"`,
  10-aastane kehtivusaeg, `basicConstraints CA=true` + `keyUsage keyCertSign,cRLSign`,
  2048-bitine RSA / SHA-256).
- Väljastab funktsiooni `issueLeafCert()` kaudu **iga SNI-hostinime jaoks nõudmisel eraldi
  leaf-sertifikaadi** (1-aastane kehtivusaeg, `subjectAltName` = SNI-host) ja salvestab
  vahemällu ühe `tls.SecureContext`-i iga hostinime kohta.
- Avaldab TLS-i lõpetava serveri jaoks funktsiooni `createSNICallback()` (vt [§5](#5-how-decrypt-and-capture-work)).
- Selle saab luua parameetriga `existingCa`, et hoida CA taaskäivituste vahel stabiilsena
  (nii ei pea usaldushoidlat uuesti paigaldama).

CA privaatvõti **ei lahku kunagi masinast**.

### Usaldushoidla paigaldaja (`src/mitm/tproxy/caTrust.ts`)

Kinnipüütav klient peab dünaamilist CA-d usaldama, seega paigaldatakse hõiverežiimi
käivitamisel CA-sertifikaat operatsioonisüsteemi usaldushoidlasse **eraldi pessa** —
`omniroute-tproxy-ca.crt` (konstant `TPROXY_CA_CERT_NAME`) — mida hoitakse staatilise
MITM-sertifikaadi pesast (`omniroute-mitm.crt`) eraldi, et need teineteist kunagi
üle ei kirjutaks.

`installTproxyCa(caPem, sudoPassword?)` tuvastab distributsiooni ankrukataloogi
(järjekorras, alustades Debiani stiilist) ja käivitab vastava värskenduskäsu:

| Ankrukataloog                               | Värskenduskäsk           |
| ------------------------------------------- | ------------------------ |
| `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

Paigaldamisel paigutatakse PEM esmalt ajutisse faili, seejärel käivitatakse
(privilegeeritult) ankrukataloogi jaoks `mkdir -p`, kopeeritakse ajutine fail
käsuga `cp` sinna ja käivitatakse värskenduskäsk. `uninstallTproxyCa()` eemaldab
ainult eraldi pesa (jättes staatilise MITM-sertifikaadi puutumata) ja värskendab
hoidlat — muudel süsteemidel kui Linux ei tee see midagi.

Kõik privilegeeritud käsud käivitatakse funktsiooni `execFileWithPassword`
(`src/mitm/systemCommands.ts`) kaudu — `spawn` koos **argumentide massiividega,
ilma kestata ja ilma stringide interpoleerimiseta** (range reegel nr 13).
Kui protsess töötab juurkasutajana (nt VPS-is), käivitatakse sihtkäsk otse ja
parooli pole vaja; mitte-juurkasutaja töölaual edastatakse `sudoPassword`
standard­sisendi kaudu käsule `sudo -S`.

> Töölaua `sudoPassword` edastatakse POST-kehas usaldushoidla paigalduse
> autoriseerimiseks; kui protsess töötab juurkasutajana, eiratakse seda täielikult.

## §5 Kuidas dekrüptimine ja hõive toimivad

Konveier (kõik asub kataloogis `src/mitm/tproxy/`):

```
kohalik rakendus  ──TCP/443──▶  mangle OUTPUT märgistab ühenduse (fwmark)
                                ip rule → kohalik marsruuditabel → lo
                                mangle PREROUTING TPROXY → IP_TRANSPARENT kuulaja (port 8443)
                                    │  captureMode.ts: loeb algse sihtkoha atribuudist socket.localAddress
                                    ▼
                                tlsCapture.ts:
                                  1. Lõpetab KLIENDI TLS-ühenduse SNI-põhise leheserdiga (dynamicCert)
                                  2. sisemine http.Server parsib dekrüptitud lihtteksti
                                  3. hõive → globalTrafficBuffer.push() parameetriga source: "tproxy"
                                     (rakendatakse sanitizeHeaders + maskSecret)
                                  4. edastab uuesti krüptituna algsesse sihtkohta
                                     möödaviigumärgisega sokli kaudu (connectMarked, tsüklivastane)
                                    │
                                    ▼
                                algne ülesvooluserver (api.example.com)
```

- **TLS-i lõpetamine** (`createTlsCaptureServer`): mähib töötlemata pealtkuulatud
  sokli serveripoolsesse `tls.TLSSocket`-isse, kasutades dünaamilise CA SNI-tagasikutset,
  ning edastab seejärel dekrüptitud voo sisemisele `http.Server`-ile (standardne MITM-i
  lõpetamise võte). Soklite eluiga piirab `MITM_IDLE_TIMEOUT_MS`, et hangunud
  tunnel ei saaks failideskriptoreid ammendada.
- **Hõive** (`handleDecryptedRequest`): lisab objekti `InterceptedRequest`, mille
  `source: "tproxy"`, algolek on `"in-flight"`, päised töödeldakse funktsiooniga
  `sanitizeHeaders()` ja kehad funktsiooniga `maskSecret()` enne puhvrisse
  sisenemist. Seejärel värskendatakse kirjet vastuse, mahtude ja latentsusega.
- **Uuesti krüptitud edastus** (`createForward` / `realForward`): krüptib liikluse
  uuesti algsesse sihtkohta saatmiseks. `rejectUnauthorized` vaikeväärtus on
  **`true`** (vaikimisi turvaline) — ülesvoolusert kontrollitakse kliendi
  taotletud SNI/Hosti suhtes, seega lükkab puhverserver tagasi täpselt selle,
  mille oleks tagasi lükanud algne klient.

### Tsüklivastane kaitse (SO_MARK)

Kuna reeglid märgistavad uued kohalikud väljuvad ühendused, pealtkuulataks
puhverserveri **enda** uuesti krüptitud edastus tavaliselt uuesti — tekiks
lõputu tsükkel. Edastustee kaitseb selle eest möödaviigu soklimärgisega
(**SO_MARK**):

- `realForward` avab ülesvoolusokli funktsiooniga `connectMarked(ip, port, DEFAULT_BYPASS_MARK)`
  — `DEFAULT_BYPASS_MARK = 0x539` — mis määrab **SO_MARK**-i **enne** funktsiooni `connect()`,
  nii et edastuse SYN kannab möödaviigumärgist.
- Reegel `mangle OUTPUT` välistab ühendused, mis juba kannavad möödaviigumärgist
  (`-m mark ! --mark <bypassMark>`), mistõttu puhverserveri edastust **ei**
  märgistata uuesti ja see ei sisene taas TPROXY-sse.

> Teostusmärkus: möödaviigumärgisega sokkel tuleb paigaldada agendi
> `createConnection`-ile (`https.request({ createConnection })`-i eiratakse vaikimisi,
> kui agent on olemas), vastasel juhul avaks edastus märgistamata sokli ja
> tsükkel taastuks. See oli läbivtestidega valideeritud tsüklivastane parandus.

## §6 Turvalisus

| Kontroll                                 | Üksikasjad                                                                                                                                                                                                                                                                                                                                                                                       |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Ainult tagasisideahela API**           | `/api/tools/agent-bridge/tproxy` on hõlmatud prefiksiga `/api/tools/agent-bridge/` loendis `LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`). Tagasisideahela nõue jõustatakse **enne** autentimist (ranged reeglid #15 + #17) — tunneli kaudu lekkinud JWT ei saa käivitada TPROXY hõivet, mis rakendab `iptables`-i reegleid ja installib alamprotsesside kaudu usaldusankrusse CA. |
| **Eraldi CA pesa**                       | Dünaamiline CA installitakse faili `omniroute-tproxy-ca.crt`, kirjutamata kunagi üle staatilist MITM-sertifikaati.                                                                                                                                                                                                                                                                               |
| **CA võti ei lahku kunagi hostist**      | `DynamicCertStore` hoiab CA võtit mälus; seda ei ekspordita.                                                                                                                                                                                                                                                                                                                                     |
| **Saladuste maskeerimine**               | Funktsiooni `maskSecret()` rakendatakse päringu- ja vastusekehadele ning funktsiooni `sanitizeHeaders()` päistele **enne** funktsiooni `globalTrafficBuffer.push()`.                                                                                                                                                                                                                             |
| **Kestainterpolatsiooni ei kasutata**    | Kõik `iptables`-i/`ip`-i/usaldusankru käsud käivitatakse funktsioonide `execFile`/`execFileWithPassword` kaudu, kasutades argumentide massiive (range reegel #13).                                                                                                                                                                                                                               |
| **Ülesvoolu sertifikaadi kontrollimine** | Uuesti krüptitud edastus kontrollib vaikimisi ülesvoolu sertifikaati (`rejectUnauthorized: true`).                                                                                                                                                                                                                                                                                               |
| **Vigade puhastamine**                   | Marsruudi veavastused läbivad funktsiooni `sanitizeErrorMessage()` (range reegel #12).                                                                                                                                                                                                                                                                                                           |

**MITM CA on võimas funktsioon.** Operatsioonisüsteemi usaldatud CA, mis saab allkirjastada mis tahes
hosti sertifikaadi, tähendab, et kogu OmniRoute'i pealtkuulatava liikluse saab dekrüptida. Selle kasutamine on piiratud
selgesõnalise, ainult kohaliku TPROXY hõiverežiimiga, mis on vaikimisi välja lülitatud, ning usaldusankru
kirje eemaldatakse režiimi peatamisel.

## §7 Tulemüüri transaktsiooniline rakendamine / tagasivõtmine

Krahh ei tohi kunagi jätta maha `mangle`-reeglit ega aegunud marsruuti. Käskude koostaja
(`src/mitm/tproxy/commands.ts`) ja käivitaja (`src/mitm/tproxy/setup.ts`) tagavad, et
**tagasivõtmine on rakendamise täpne pöördtehe vastupidises järjekorras**.

`applyTproxy(cfg)` käivitab rakendamiskäsud järjekorras; **mis tahes** tõrke korral käivitab see
parima võimaliku täieliku `revertTproxy(cfg)` tagasivõtmise ja edastab erindi uuesti — seega on tulemüür kas
täielikult rakendatud või täielikult tagasi võetud, mitte kunagi osaliselt rakendatud. `revertTproxy(cfg)` käivitab
pöördkäsud vastupidises järjekorras ja eirab tõrkeid (idempotentne — seda võib turvaliselt
tingimusteta kutsuda, nt AgentBridge'i `repairMitm()` puhastusest).

`validateTproxyConfig(cfg)` käivitatakse enne mis tahes käsku: pordid peavad olema vahemikus `1–65535`,
`mark`/`routeTable`/`bypassMark` peavad olema positiivsed täisarvud ning `bypassMark` peab
erinema väärtusest `mark` (tsüklivastane kaitse).

### Rakendamiskäsud (järjekorras)

```bash
ip rule add fwmark <mark> lookup <routeTable>
ip route add local 0.0.0.0/0 dev lo table <routeTable>
iptables -t mangle -A OUTPUT -p tcp --dport <dport> -m mark ! --mark <bypassMark> -j MARK --set-mark <mark>
iptables -t mangle -A PREROUTING -p tcp --dport <dport> -m mark --mark <mark> -j TPROXY --on-port <onPort> --tproxy-mark <mark>
```

Tagasivõtmine kustutab need vastupidises järjekorras: `PREROUTING -D`, `OUTPUT -D`, `ip route del`, `ip rule del`.

> Lahendus põhineb ahelal **OUTPUT**, sest MITM-i kasutusjuht hõlmab _kohalikku_ väljaminevat
> liiklust (samal hostil töötavad rakendused), mida ainult `PREROUTING`-us olev TPROXY ei
> näe — `PREROUTING` näeb ainult edastatavat liiklust. Ahel `OUTPUT` märgistab uued
> kohalikud ühendused, `ip rule` suunab need ümber kohalikku edastusse (`lo`) ning
> seejärel määrab `PREROUTING` need läbipaistvale kuulajale.

## §8 Konfiguratsioon

Käivitustaotlus (`POST /api/tools/agent-bridge/tproxy`) aktsepteerib järgmisi
välju, mida valideerib `StartTproxyBodySchema` (`tproxy/route.ts`). Kõik väljad on valikulised
ja nende puudumisel kasutatakse vaikeväärtusi:

| Väli             | Tüüp                   | Vaikeväärtus | Märkused                                                                                                                                |
| ---------------- | ---------------------- | ------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| **dport**        | täisarv (1–65535)      | `443`        | Sihtkoha TCP-port, mille liiklus läbipaistvalt kinni püütakse                                                                           |
| **mark**         | täisarv (≥1)           | `0x2333`     | Tulemüürimärgis, mis määratakse ahelas `OUTPUT` ning millele vastavad `ip rule` + `PREROUTING`                                          |
| **onPort**       | täisarv (1–65535)      | `8443`       | Port, millega seotakse läbipaistev (**IP_TRANSPARENT**) kuulaja                                                                         |
| **routeTable**   | täisarv (≥1)           | `233`        | Reeglipõhise marsruutimise tabeli id, mis sisaldab marsruuti `local 0.0.0.0/0`                                                          |
| **bypassMark**   | täisarv (≥1, ≠ `mark`) | `0x539`      | Möödaviigu soklimärgis (**SO_MARK**), mille proksi määrab oma ülesvooluühendustele; välistatakse ahelas `OUTPUT` (tsüklivastane kaitse) |
| **sudoPassword** | string                 | —            | Ainult mitte-root-töölauasüsteemides: annab loa usaldushoidlasse installimiseks; root-kasutaja korral eiratakse                         |

TPROXY jaoks **ei ole keskkonnamuutujaid** — kogu konfiguratsioon edastatakse
POST-kehas või kasutatakse ülaltoodud vaikeväärtusi.

## §9 Lubamine liiklusinspektorist

1. Avage **liiklusinspektor** (`/dashboard/tools/traffic-inspector`).
2. Leidke hõiverežiimide tööriistaribalt nupp **„TPROXY dekrüptimine”** ⚠
   (`src/app/(dashboard)/dashboard/tools/traffic-inspector/components/CaptureModesToolbar.tsx`).
   - Kui see on **keelatud** kohtspikriga „TPROXY dekrüptimine nõuab Linuxit, juurkasutaja õigusi
     ja omamoodulit”, pole omamoodul selles hostis saadaval (tegu pole Linuxiga,
     puudub tööriistaahel või lisamoodulit pole kompileeritud). Vaadake [§2](#2-requirements) ja [§3](#3-the-native-ip_transparent-addon).
3. Klõpsake nuppu. See kutsub funktsiooni `startTproxyCaptureMode()` kaudu välja
   `POST /api/tools/agent-bridge/tproxy`
   (`src/lib/inspector/tproxyCaptureApi.ts`), mis loob dünaamilise CA, avab
   läbipaistva kuulaja, rakendab tulemüürireeglid ja installib CA operatsioonisüsteemi
   usaldushoidlasse.
4. Töötamise ajal muutub lüliti merevaigukollaseks ja kuvab reaalajas pealtkuulamiste arvu
   (`· <interceptCount>`). Pealtkuulatud päringud kuvatakse päringute loendis väärtusega
   `source: "tproxy"`.
5. Peatamiseks klõpsake uuesti — `DELETE /api/tools/agent-bridge/tproxy` funktsiooni
   `stopTproxyCaptureMode()` kaudu sulgeb kuulaja, desinstallib CA ja tühistab
   tulemüürireeglid.

Hõiverežiimi olek (töötab / saadaval / pealtkuulamiste arv / kuulaja port) pärineb
kutsest `GET /api/tools/agent-bridge/tproxy` (`getCaptureStatus()` failis
`src/mitm/tproxy/captureManager.ts`). Korraga töötab ainult **üks** TPROXY seanss —
teise käivitamise katse lükatakse tagasi teatega „TPROXY hõiverežiim juba töötab”.

## §10 Tõrkeotsing

### Lüliti on keelatud

Omamoodulit ei saa laadida. Veenduge, et kasutate Linuxit, olete lisamooduli
kompileerinud (`npm run build:native:tproxy`) ja protsess saab faili `transparent.node`
laadida. `isTransparentSocketAvailable()` juhib lüliti saadavust; kui lisamoodul
puudub, tagastab `GET /api/tools/agent-bridge/tproxy` väärtuse `available: false`.

### Midagi ei hõivata

- Veenduge, et pealtkuulatav protsess looks tegelikult ühenduse seadistatud pordiga `dport`
  (vaikimisi `443`).
- Veenduge, et protsess usaldaks dünaamilist CA-d. CA installitakse nimega
  `omniroute-tproxy-ca.crt`; oma usaldushoidlaga rakendustes (Firefoxi/Chrome'i NSS)
  võib olla vaja sert lisada ka sinna.
- Käivitage AgentBridge'i enesetest **Diagnose** (vt
  [`AGENTBRIDGE.md`](../frameworks/AGENTBRIDGE.md)), et kontrollida serdi usaldamist ja serveri
  seisundit.

### Pärast krahhi alles jäänud tulemüürireeglid

`revertTproxy()` on rakendamise täpne pöördtehe ja idempotentne. Režiimi peatamine
tühistab reeglid; kui OmniRoute seansi ajal sunniviisiliselt peatati, kasutage AgentBridge'i
toimingut **Repair** (`POST /api/tools/agent-bridge/repair`), et tühistada süsteemi
orvuks jäänud olek (DNS-i võltsimine, juur-CA, süsteemi puhverserver). TPROXY `mangle`-reeglid
ja marsruut eemaldatakse automaatselt ka taaskäivitamisel.

### Lõputu tsükkel / puhverserver kuulab pealt enda edasisuunamist

See on tsüklivastane juhtum. Veenduge, et `bypassMark` erineks väärtusest `mark` (valideerimine
tagab selle) ja et edasisuunamine kasutaks funktsiooni `connectMarked` (funktsioonis `realForward`
on see nii). Vaadake [§5 Tsüklivastane kaitse](#anti-loop-so_mark).
