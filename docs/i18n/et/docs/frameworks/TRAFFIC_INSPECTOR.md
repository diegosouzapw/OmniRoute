Traffic Inspector on OmniRoute’i sisseehitatud HTTPS-liikluse silur — Charles Proxy / mitmweb / HTTP Toolkit-laadne tööriist, mis on **LLM-teadlik** ja **agenditeadlik**. See asub aadressil `/dashboard/tools/traffic-inspector` ja võtab vastu reaalajas liiklust kuni viiest samaaegsest hõiveallikast.

**Asukoht töölaual:** `/dashboard/tools/traffic-inspector`
**Külgriba rühm:** Tööriistad (pärast AgentBridge’i)
**Vaata ka:** [`AGENTBRIDGE.md`](./AGENTBRIDGE.md) — AgentBridge on hõiverežiim 1.

### Arhitektuur ühes lõigus

`TrafficBuffer` (`src/mitm/inspector/buffer.ts`) on ühine mälusisene ringpuhver (vaikimisi 1000 kirjet, seadistatav muutuja `INSPECTOR_BUFFER_SIZE` kaudu). Kõik hõiveallikad kirjutavad sellesse meetodi `push()` kaudu. Puhver liigitab iga kirje faili `kindDetector.ts` abil (määrab, kas tegu on LLM-päringuga), arvutab `contextKey` väärtuse (süsteemiviiba SHA-256-sõrmejälg) ja edastab selle kõigile WebSocketi tellijatele meetodi `globalTrafficBuffer.subscribe()` kaudu. Töölaud loob ühenduse päringuga `GET /api/tools/traffic-inspector/ws` ning saab ühenduse loomisel hetktõmmise, millele järgnevad sündmused `new`/`update`/`clear`.

## §2 Hõiverežiimid

Traffic Inspector toetab **5 samaaegset hõiveallikat**. Igaüht saab teistest sõltumatult sisse ja välja lülitada. Iga `InterceptedRequest`-i (`src/mitm/inspector/types.ts`) väli `source` on üks järgmistest: `"agent-bridge"`, `"custom-host"`, `"http-proxy"`, `"system-proxy"` või `"tproxy"`.

### Režiim 1 — AgentBridge (vaikimisi alati sisse lülitatud)

**Allikas:** AgentBridge'i töötlejad (`src/mitm/handlers/base.ts`)
**Mehhanism:** Iga `intercept()`-i väljakutse klassis `MitmHandlerBase` kutsub enne edastamist välja `hookBufferStart()`-i ja lõpetamisel `hookBufferUpdate()`-i. Täiendavat seadistamist pole vaja — töötab kohe, kui AgentBridge töötab.
**Ulatus:** AgentBridge'is seadistatud 9 IDE agenti
**Märkus:** `InterceptedRequest`-i väli `source` = `"agent-bridge"`

### Režiim 2 — Kohandatud hostid (DNS-i ümbersuunamine)

**Allikas:** Kasutaja määratud hostide loend (tabel `inspector_custom_hosts`)
**Mehhanism:** Hosti lisamisel kasutajaliidese kaudu lisatakse faili `/etc/hosts` rida `127.0.0.1 <host>` (nõuab sudo õigusi). Olemasolev AgentBridge'i MITM-server (port 443) genereerib uue hosti jaoks dünaamiliselt SNI-sertifikaadi.
**Ulatus:** Kõik lisatud hosti kasutavad rakendused — rakenduse konfiguratsiooni pole vaja muuta
**Märkus:** `source` = `"custom-host"`

Kasutusjuhtude näited:

- Python-skriptidest aadressile `api.openai.com` suunatud liikluse jälgimine
- `my-internal-llm.company.com` silumine
- Samas võrgus olevate mobiilseadmete liikluse hõivamine (ARP-võltsimise kaudu — edasijõudnutele)

### Režiim 3 — HTTP_PROXY kuular (port 8080)

**Allikas:** Keskkonnamuutujaid `HTTP_PROXY`/`HTTPS_PROXY` kasutavad rakendused
**Mehhanism:** Teisene kuular pordil 8080 (`src/mitm/inspector/httpProxyServer.ts`), mis toimib standardse selgesõnalise HTTP/HTTPS-proksina. Võtab vastu `CONNECT`-tunneleid (HTTPS) ja otseseid HTTP-päringuid.
**Ulatus:** Kõik rakendused, mis arvestavad keskkonnamuutujat `HTTP_PROXY` — DNS-i pole vaja muuta ja sudo õigusi pole vaja
**Märkus:** `source` = `"http-proxy"`

```bash
# Ühe käsu kiire hõivamine:
HTTPS_PROXY=http://127.0.0.1:8080 curl https://api.openai.com/v1/models

# Püsiv hõivamine shelliseansis:
export HTTP_PROXY=http://127.0.0.1:8080
export HTTPS_PROXY=http://127.0.0.1:8080
```

**TLS-i piirang:** HTTPS-i `CONNECT`-tunnelitest hõivatakse vaikimisi ainult metaandmed (host, port, ajastus) — TLS-i sisu ei dekrüptita. Sisu täielikuks kontrollimiseks lülitage sisse „HTTPS-i dekrüptimine proksirežiimis“ (valikuline, nõuab AgentBridge'i sertifikaadi usaldamist).

**Pordikonflikt:** Kui port 8080 on kasutusel, tagastab AgentBridge struktureeritud veaga vastuse 409. Muutke porti keskkonnamuutuja `INSPECTOR_HTTP_PROXY_PORT` kaudu.

### Režiim 4 — Süsteemiülene proksi (edasijõudnutele, valikuline)

**Allikas:** Operatsioonisüsteemi taseme proksisätted (rakenduvad kõigile masina rakendustele)
**Mehhanism:** Kasutab operatsioonisüsteemi API-sid kogu HTTP/HTTPS-liikluse suunamiseks läbi HTTP_PROXY kuulaja:

- **macOS:** `networksetup -setwebproxy / -setsecurewebproxy`
- **Linux:** `gsettings set org.gnome.system.proxy` + `/etc/environment`
- **Windows:** `netsh winhttp set proxy 127.0.0.1:8080`
  **Ulatus:** Kõik masina rakendused, mis arvestavad süsteemi proksisätteid
  **Märkus:** `source` = `"system-proxy"`

**Ohutusmehhanismid:**

- Automaatse väljalülitamise taimer (vaikimisi 30 minutit, seadistatav muutuja `INSPECTOR_SYSTEM_PROXY_GUARD_MINUTES` kaudu)
- Süsteemi varasem proksiolek salvestatakse andmebaasi ja taastatakse ennistamisel
- Kui kasutaja lahkub aktiivse funktsiooni ajal lehelt, kuvab töölaud viiba „Süsteemiproksi ennistamine“
- Kasutajaliides kuvab märgi `⚠ Edasijõudnutele` ja eraldi kinnitamise märkeruudu

### Režiim 5 — TPROXY läbipaistev dekrüptimine (Linux, root, valikuline)

**Allikas:** Kerneli TPROXY + poliitikapõhine marsruutimine (`src/mitm/tproxy/`)
**Mehhanism:** Märgistab `mangle OUTPUT`-is uued kohalikud väljaminevad TCP-ühendused sihtporti (vaikimisi `443`), `ip rule` suunab märgistatud paketid ümber kohalikku edastusse ning `mangle PREROUTING`-i sihtmärk `TPROXY` annab need üle läbipaistvale (**IP_TRANSPARENT**) kuulajale (vaikimisi port `8443`). Kuulaja lõpetab TLS-ühenduse dünaamilise CA poolt **iga SNI-hostinime jaoks nõudmisel** väljastatud lõppsertifikaadiga, hõivab dekrüptitud andmevahetuse ja edastab päringu uuesti krüptituna algsele sihtkohale.
**Ulatus:** **Suvalised** sihthostid sihtpordil — `/etc/hosts`-i võltsimist, `HTTP_PROXY` keskkonnamuutujat ega süsteemiüleste proksisätete muutmist pole vaja. Pealtkuulatava protsessi konfiguratsiooni pole vaja muuta, kuid see peab dünaamilist CA-d usaldama.
**Märkus:** `source` = `"tproxy"`

**Nõuded:** Ainult Linux (**IP_TRANSPARENT** on saadaval ainult Linuxis), võimekus **CAP_NET_ADMIN** (root) ja natiivne N-API lisamoodul, mis tuleb kompileerida C-tööriistaahelaga (`npm run build:native:tproxy`). Kui need pole saadaval, on töölaua lüliti keelatud kohtspikriga „TPROXY dekrüptimine nõuab Linuxit + root-õigusi + natiivset lisamoodulit“. Tulemüürireegleid rakendatakse ja ennistatakse transaktsiooniliselt (krahh ei jäta kunagi `mangle`-reeglit alles) ning need eemaldatakse taaskäivitamisel. SO_MARK-il põhinev tsüklivastane kaitse takistab proksi enda uuesti krüptitud edastuse korduvat pealtkuulamist.

See on mahukas alamsüsteem, millel on oma spetsiaalne operaatorijuhend — täieliku tulemüüriretsepti, SNI-põhise dünaamilise CA + usaldusväärsuse hoidla installeri, ainult kohaliku marsruudi, tsüklivastase kaitse üksikasjade ja konfiguratsiooniskeemi jaoks vaadake faili `docs/security/MITM-TPROXY-DECRYPT.md` (git; seda ei kompileerita asukohta `/docs`). Lülitit juhitakse `GET / POST / DELETE /api/tools/agent-bridge/tproxy` kaudu (märkus: marsruut asub AgentBridge'i prefiksi, mitte Traffic Inspectori prefiksi all).

## §4 LLM-teadlikud funktsioonid

### 4.1 Tüübi tuvastaja (`src/mitm/inspector/kindDetector.ts`)

Liigitab iga päringu väärtuseks `"llm"`, `"app"` või `"unknown"`, kasutades nelja signaali:

1. **Hostide register** — ~18 teadaolevat LLM API hostinime (OpenAI, Anthropic, Gemini, Groq, Mistral, Together, Fireworks, Cohere, Perplexity, Hugging Face, OpenRouter, xAI, Moonshot jne)
2. **Tee mustrid** — `/v1/chat/completions`, `/v1/messages`, `/generateContent`, `/v1/responses` jne
3. **Keha struktuur** — tuvastab väljad `messages[]` (OpenAI/Claude), `contents[]` (Gemini), `prompt`, `input`
4. **User-agent'i vihjed** — `codex`, `claude`, `gemini`, `antigravity`, `kiro`, `copilot`, `cursor` UA-stringis

Režiimi 2 kaudu lisatud kohandatud hostid pärivad oma `kind`-väärtuse vormi sisendist (vaikeväärtus on `"custom"`).

### 4.2 SSE ühendaja (`src/mitm/inspector/sseMerger.ts`)

**Sõltumatu puhta teostuse implementatsioon.** Sündmuste sõelumine järgib
[WHATWG serverist saadetud sündmuste algoritmi](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream),
rekonstrueerimine aga avalikke [OpenAI](https://platform.openai.com/docs/api-reference/chat/create),
[Anthropicu](https://platform.claude.com/docs/en/build-with-claude/streaming) ja
[Gemini](https://ai.google.dev/api/generate-content#method:-models.streamgeneratecontent)
voogedastusskeeme.

Rekonstrueerib töötlemata SSE deltasündmustest assistendi lõpliku sõnumi:

- **Anthropic**: kogub `content_block_delta` väärtused indeksi järgi; töötleb tüüpe `text_delta`, `input_json_delta` (tööriistakutsed), `thinking_delta`
- **OpenAI**: kogub Chat Completionsi valikud/tööriistakutsed ja Responses API väljundelemendid
  indeksi järgi
- **Gemini**: kogub `candidates[i].content.parts` väärtused
- **Tundmatu**: tagastab töötlemata sündmused muutmata kujul

Vahekaardil Response kuvatakse lüliti: **„Töötlemata sündmused ↔ Ühendatud“**.

### 4.3 Vestluse normaliseerija (`src/mitm/inspector/conversationNormalizer.ts`)

**Sõltumatu puhta teostuse implementatsioon.** Normaliseerimine on määratletud kohalike musta kasti
lepingute ning avalike OpenAI, Anthropicu ja Gemini sõnumiskeemidega; ühegi välise
implementatsiooni lähtekoodi ei kasutata.

Teisendab OpenAI, Anthropicu ja Gemini sõnumivormingud enne renderdamist ühtseks `NormalizedConversation`-objektiks:

```ts
interface NormalizedConversation {
  request: NormalizedTurn[]; // päringu keha messages / contents / prompt
  response: NormalizedTurn[]; // assistendi vastus (ühendatud sseMerger abil)
  contextKey: string | null; // süsteemiviiba SHA-256 sõrmejälg
}
```

Plokitüübid: `text`, `tool_use`, `tool_result`. Vahekaart Conversation kasutab seda struktuuri teenusepakkujast olenemata.

### 4.4 Kontekstivõtme värvimine (`src/mitm/inspector/contextKey.ts`)

- Arvutab süsteemiviiba `SHA-256` räsi (esimene `role:system` sõnum, väli `system` või Gemini `systemInstruction`)
- Tagastab 12-märgilise kuueteistkümnendprefiksi (`"a3f9c2..."`)
- Kasutajaliides vastendab võtme vasaku ääriseriba deterministlikule HSL-värvile
- **Filter „sama kontekst“**: kiibil `ctx #a3f` klõpsamine lisab filtri, mis kuvab ainult sama sõrmejäljega päringud

See võimaldab hõlpsasti visuaalselt eristada samas agendiseansis töötavaid erinevaid „persoonasid“ või ülesandeid.

### 4.5 LLM-i metaandmete eraldamine

LLM-päringute korral eraldab vahekaart LLM Details järgmised andmed:

```ts
interface LlmMetadata {
  provider: string | null; // "openai" | "anthropic" | "gemini" | ...
  apiKind: string | null; // "chat.completions" | "messages" | "embeddings" | ...
  model: string | null; // päringu kehast või vastusest
  messages: number; // voorude arv
  tokensIn: number | null; // usage.prompt_tokens / usage.input_tokens
  tokensOut: number | null; // usage.completion_tokens / usage.output_tokens
  streamed: boolean; // true, kui vastus on SSE
  mappedTo: string | null; // päis x-omniroute-mapped
  costEstimateUsd: number | null; // OmniRoute'i hinnastuse põhjal arvutatud hinnanguline maksumus
}
```

### 4.6 Reaalajas pooleliolevate päringute filter

Päringu välja `status` tüüp on `number | "in-flight" | "error"` — kirje
lisatakse päringu käivitumise hetkel väärtusega `"in-flight"` ja **värskendatakse kohapeal**,
kui saabub vastus (või viga). Tööriistariba lüliti **„Reaalajas“**
(`liveOnly`, i18n-võti `trafficInspector.liveOnly`) piirab loendi kirjetega,
mille `status === "in-flight"`, võimaldades jälgida avatud ühendusi reaalajas.

Filter on puhas kliendipoolne predikaat failis
`src/lib/inspector/matchesTrafficFilter.ts`:

```ts
if (f.liveOnly && req.status !== "in-flight") return false;
```

Lüliti olek asub `useTrafficFilters`-is (inspektori töölaua hook'id) ja
kombineerub teiste filtritega (profiil, host, agent, allikas, olek, kontekst).

### 4.7 Protsessi omistamine (Linux)

Linuxis saab iga pealtkuulatud päringu omistada **selle algatanud kohalikule
protsessile**. `InterceptedRequest`-ile lisatakse kaks valikulist välja:

```ts
pid?: number;          // algatanud protsessi ID (ainult Linux)
processName?: string;  // algatanud protsessi nimi (ainult Linux)
```

`src/mitm/inspector/processAttribution.ts` vastendab ühenduse _kliendi_
ajutise pordi PID-i ja nimega järgmiselt:

1. Loeb faile `/proc/net/tcp` ja `/proc/net/tcp6`, et leida pordi sokli inode
   (`parseProcNetTcpForInode`, puhas fikstuuridega testitav parser).
2. Otsib kataloogist `/proc/<pid>/fd/` sümbollinki sihtkohale `socket:[<inode>]`.
3. Loeb protsessi nime failist `/proc/<pid>/comm`.

Ühesekundilise TTL-iga vahemälu piirab procfs-i skannimise kulu koormuse all. Omistamine toimub
**parima võimaliku pingutusena** — iga tõrke korral tagastatakse `null` ja hõivet ei blokeerita. Süsteemides
macOS/Windows tagastab funktsioon `null` (stub; `lsof`/`GetExtendedTcpTable`
tugi lisatakse edaspidi).

## §5 Seansid

### 5.1 Seansi salvestamine

1. Klõpsake tööriistaribal nuppu **„● Salvesta seanss”** → sisestage nimi (valikuline)
2. Reaalajas voo jälgimine jätkub tavapäraselt; punane pulseeriv indikaator näitab `◉ SALV · <nimi> · 00:42 · 23 päringut`
3. Klõpsake nuppu **„⏹ Peata”** → seansi hetktõmmis salvestatakse tabelitesse `inspector_sessions` + `inspector_session_requests`

### 5.2 Salvestatud seansi vaatamine

Tööriistariba rippmenüüs **Seansid** kuvatakse salvestatud seansid. Seansi valimisel:

- Laaditakse seansi hetktõmmis (külmutatud olek)
- Kuvatakse riba: `Salvestatud seansi "<nimi>" vaatamine — [Tagasi reaalajavaatesse]`
- Vahekaart Statistika muutub kättesaadavaks koos Rechartsi koondandmetega

### 5.3 Ekspordivormingud

Iga seansi saab eksportida järgmistes vormingutes:

| Vorming                   | Kasutus                                                                               |
| ------------------------- | ------------------------------------------------------------------------------------- |
| **HAR** (HTTP-arhiiv 1.2) | Ühildub Chrome DevToolsi, Charlesi ja Fiddleriga — importige võrguväliseks analüüsiks |
| **JSONL**                 | Üks `InterceptedRequest` rea kohta — ühildub `llm-interceptor`-vorminguga             |

Eksportige aadressi `GET /api/tools/traffic-inspector/sessions/{id}/export.har` kaudu või rippmenüü Seansid nupuga ⬇.

## §6 Turvalisus

Traffic Inspector kuvab **kogu pealtkuulatud HTTPS-liikluse**, sealhulgas autoriseerimispäised ja päringukehad. Kasutusel on järgmised kontrollmeetmed:

| Kontrollmeede              | Üksikasjad                                                                                                                                                                                                      |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LOCAL_ONLY**             | Kõik marsruudid ja WebSocketi lõpp-punkt on juurdepääsetavad ainult loopback-liidese kaudu (jõustatakse failis `routeGuard.ts` enne autentimist)                                                                |
| **Saladuste maskimine**    | Lineaarne `maskSecret()`-skanner peidab RFC 6750 Beareri identimisteabe, teenusepakkuja prefiksiga võtmed ja pikad läbipaistmatud sõned enne `TrafficBuffer.push()`-i                                           |
| **Keha mahupiirang**       | Kehad, mis on suuremad kui `INSPECTOR_MAX_BODY_KB` (vaikimisi 1024 KB), kärbitakse teatega `"(jõudluse huvides kärbitud)"`                                                                                      |
| **Päiste sanitiseerimine** | Nimed teisendatakse väiketähtedeks; kadreerimis-, hop-by-hop- ja puhverserveri autentimispäised eemaldatakse; küpsised peidetakse täielikult; identimisteabe väärtused edastatakse funktsioonile `maskSecret()` |
| **CSP**                    | Traffic Inspectori lehtedel rakendatakse ranget sisuturbepoliitikat, et vältida XSS-i sisestatud vastusekehade kaudu                                                                                            |
| **Vaikimisi ei püsi**      | `TrafficBuffer` asub mälus ja kaob serveri taaskäivitamisel. Seansid säilitatakse ainult siis, kui need selgesõnaliselt salvestatakse                                                                           |

### Rakendatud ranged reeglid

| Reegel                            | Rakendus                                                                                     |
| --------------------------------- | -------------------------------------------------------------------------------------------- |
| **#12** `sanitizeErrorMessage`    | Kõik Traffic Inspectori marsruutide HTTP-veavastused sanitiseeritakse                        |
| **#15 + #17** `isLocalOnlyPath()` | `/api/tools/traffic-inspector/` on LOCAL_ONLY + SPAWN_CAPABLE (süsteemi puhverserveri käsud) |

### Teadaolevad piirangud

- **Kogu süsteemi hõlmav puhverserverirežiim** mõjutab kõiki masinas olevaid rakendusi, sealhulgas VPN-kliente ja SSO-d. Kasutage seda alati koos automaatse väljalülitamise taimeriga. Ärge kasutage seda jagatud masinates.
- **CONNECT-tunneli HTTPS**: režiim 3 (HTTP_PROXY) hõivab HTTPS-sihtkohtade puhul ainult tunneli metaandmed, välja arvatud juhul, kui TLS-i pealtkuulamine on lubatud. See on taotluslik — läbipaistev hõivamine ilma AgentBridge'i serdi usaldamiseta katkestaks nende rakenduste TLS-kontrolli.
- **Mõnes komponendis püsiprogrammeeritud sõned**: mõnes kasutajaliidese komponendis (F7/F8) on väike arv püsiprogrammeeritud sõnesid, mida i18n-võtmed veel ei kata. Need on i18n-i lünkade aruandes teadaoleva piiranguna dokumenteeritud; need viiakse üle järgmises etapis. Mõjutatud sõned on kasutajaliidese dekoratiivsed sildid, mis ei vaja funktsionaalseks kasutamiseks tõlkimist.

## §7 Tõrkeotsing

### WebSocketi ühenduse katkemine

Kui reaalajas jälgimine kuvab teate „Ühendus katkestatud“:

1. Kontrollige, kas server töötab endiselt: `GET /api/tools/traffic-inspector/capture-modes`
2. Laadige leht uuesti — WebSocket loob ühenduse uuesti ja saab värske hetktõmmise
3. Kui server taaskäivitati, tühjendati mälusisene puhver — vanad kirjed on kadunud, välja arvatud juhul, kui seanss salvestati

### Pordi 8080 konflikt

Kui HTTP_PROXY režiimi käivitamine nurjub:

```bash
lsof -i :8080    # protsessi leidmine
```

Muutke porti:

```bash
# .env
INSPECTOR_HTTP_PROXY_PORT=8888
```

### Süsteemiproksit ei ennistatud

Kui OmniRoute jookseb kokku ajal, mil süsteemiülene proksirežiim on aktiivne:

**macOS:**

```bash
networksetup -setwebproxystate Wi-Fi off
networksetup -setsecurewebproxystate Wi-Fi off
```

**Linux (GNOME):**

```bash
gsettings set org.gnome.system.proxy mode 'none'
```

**Windows:**

```cmd
netsh winhttp reset proxy
```

Kui juhtpaneel tuvastab järgmisel laadimisel, et andmebaasi oleku järgi oli proksi aktiivne, pakub see ka valikut „Ennista süsteemiproksi“.

### Puhver on täis

Kui puhver saavutab väärtuse `INSPECTOR_BUFFER_SIZE` (vaikimisi 1000), tõrjuvad uued kirjed vanimad välja. Kui olulised päringud lähevad kaotsi:

- Suurendage väärtust `INSPECTOR_BUFFER_SIZE` (nt 5000) — see vahetab suurema mälukasutuse pikema säilitamise vastu
- Salvestage seanss, et asjakohane ajavahemik andmebaasis püsivalt talletada
