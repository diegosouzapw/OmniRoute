Tihendusreeglid on JSON-failid, mis laaditakse käitusajal. Need on teadlikult ainult andmeid sisaldavad, et uusi keelepakette ja RTK-käskude filtreid saaks läbi vaadata ilma mootori koodi muutmata.

> **Kanooniline skeem (tõeallikas):** [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) (JSON Schema mustand 2020-12).
> Allolevad näited on illustratiivsed — kahtluse korral valideerige oma paketti `_schema.json` alusel.

## Cavemani reeglipaketid

Cavemani reeglipaketid asuvad järgmises kataloogis:

```txt
open-sse/services/compression/rules/<language>/<pack>.json
```

Iga pakett sisaldab asendusi, mida rakendatakse tavatekstile pärast kaitstud piirkondade eraldamist.

```json
{
  "language": "en",
  "category": "filler",
  "rules": [
    {
      "name": "question_to_directive",
      "pattern": "\\b(?:Can you explain why|Could you show me how)\\b\\s*",
      "replacement": "Explain why ",
      "replacementMap": {
        "can you explain why": "Explain why ",
        "could you show me how": "Show how "
      },
      "flags": "gi",
      "context": "all",
      "category": "context",
      "minIntensity": "lite",
      "description": "Convert verbose questions into direct requests."
    }
  ]
}
```

### Cavemani väljad

| Väli                     | Kohustuslik | Kirjeldus                                                            |
| ------------------------ | ----------- | -------------------------------------------------------------------- |
| `language`               | jah         | BCP-47-laadne keele võti, näiteks `en`, `pt-BR`, `es`                |
| `category`               | jah         | Paketi kategooria failinimi/kategooria, näiteks `filler` või `dedup` |
| `rules`                  | jah         | Regulaaravaldistega asendusreeglite massiiv                          |
| `rules[].name`           | jah         | Stabiilne reegli nimi                                                |
| `rules[].pattern`        | jah         | JavaScripti regulaaravaldise lähtekood                               |
| `rules[].flags`          | ei          | JavaScripti regulaaravaldise lipud; vaikimisi `gi`                   |
| `rules[].replacement`    | ei          | Asendusstring või varuväärtus, kui `replacementMap` ei leia vastet   |
| `rules[].replacementMap` | ei          | Normaliseeritud vastetekstiga võtmestatud vastepõhised asendused     |
| `rules[].context`        | ei          | `all`, `user`, `assistant` või `system`; vaikimisi `all`             |
| `rules[].category`       | ei          | `filler`, `context`, `structural`, `dedup`, `terse` või `ultra`      |
| `rules[].minIntensity`   | ei          | `lite`, `full` või `ultra`; vaikimisi `lite`                         |
| `rules[].description`    | ei          | Inimloetav reegli kokkuvõte                                          |

Kasutage `flags`, kui tõstutundlik sobitamine on oluline, näiteks artikli eemaldamisel väiketähega algava tavateksti eest ilma fraasist `the OpenAI API` sõna `the` eemaldamata. Kasutage `replacementMap`, kui üks regulaaravaldis sisaldab mitut alternatiivi, mis vajavad erinevaid väljundeid; see võimaldab JSON-reeglipakettidel jääda ainult andmeid sisaldavaks, säilitades samal ajal keerukamate sisseehitatud TypeScripti asendusfunktsioonide käitumise.

## RTK filtrikomplektid

RTK filtrid asuvad kataloogis:

```txt
open-sse/services/compression/engines/rtk/filters/<filter>.json
```

Iga filter kirjeldab, kuidas käsuväljundite rühma tuvastada ja tihendada.

```json
{
  "id": "test-vitest",
  "label": "Vitest output",
  "category": "test",
  "priority": 92,
  "match": {
    "outputTypes": ["test-vitest"],
    "commands": ["vitest", "npm test", "npm run test"],
    "patterns": ["\\bFAIL\\b", "\\bPASS\\b", "\\bTest Files\\b"]
  },
  "rules": {
    "stripAnsi": true,
    "replace": [{ "pattern": "\\s+\\[[0-9]+ms\\]", "replacement": "" }],
    "matchOutput": [
      {
        "pattern": "All tests passed",
        "message": "vitest: ok",
        "unless": "FAIL|Error:"
      }
    ],
    "includePatterns": ["FAIL", "Error:", "Test Files", "Tests"],
    "dropPatterns": ["^\\s*$", "Duration\\s+\\d+"],
    "collapsePatterns": ["^\\s+at "],
    "deduplicate": true,
    "truncateLineAt": 240,
    "maxLines": 160,
    "headLines": 24,
    "tailLines": 40,
    "onEmpty": "vitest: ok",
    "filterStderr": false
  },
  "preserve": {
    "errorPatterns": ["FAIL", "Error:", "AssertionError"],
    "summaryPatterns": ["Test Files", "Tests", "Snapshots"]
  },
  "tests": [
    {
      "name": "keeps failing tests",
      "command": "vitest",
      "input": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed",
      "expected": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed"
    }
  ]
}
```

### RTK väljad

| Väli                       | Kohustuslik | Kirjeldus                                                                   |
| -------------------------- | ----------- | --------------------------------------------------------------------------- |
| `id`                       | jah         | Filtri stabiilne ID                                                         |
| `label`                    | jah         | Juhtpaneelil kuvatav nimi                                                   |
| `category`                 | jah         | Filtrirühm: git, test, build, shell, docker, package, infra, cloud, generic |
| `priority`                 | ei          | Kui sobib mitu filtrit, võidab kõrgema prioriteediga filter                 |
| `match.outputTypes`        | ei          | Detektori väljundi ID-d, mis valivad selle filtri                           |
| `match.commands`           | ei          | Käsutõendid, mis valivad selle filtri                                       |
| `match.patterns`           | ei          | Regulaaravaldised, mis valivad selle filtri väljundteksti põhjal            |
| `rules.stripAnsi`          | ei          | ANSI paojadade eemaldamine enne regulaaravaldiste etappe                    |
| `rules.replace`            | ei          | Järjestatud regulaaravaldisasendused, mida rakendatakse reapõhiselt         |
| `rules.matchOutput`        | ei          | Väljundi lühistamisreeglid valikulise `unless`-tingimusega                  |
| `rules.includePatterns`    | ei          | Read, mille säilitamist tuleks eelistada                                    |
| `rules.dropPatterns`       | ei          | Read, mis tuleks mürana eemaldada                                           |
| `rules.collapsePatterns`   | ei          | Korduvad sobivad read, mida saab koondada                                   |
| `rules.deduplicate`        | ei          | Normaliseeritud duplikaatridade koondamine                                  |
| `rules.truncateLineAt`     | ei          | Unicode'i arvestav tähemärgipiirang rea kohta                               |
| `rules.maxLines`           | ei          | Maksimaalne säilitatavate ridade arv enne lõpuosa säilitamist               |
| `rules.headLines`          | ei          | Kärpimisel säilitatavad algusread                                           |
| `rules.tailLines`          | ei          | Värske konteksti jaoks säilitatavad lõpuread                                |
| `rules.onEmpty`            | ei          | Varuteade juhuks, kui filtreerimine eemaldab kogu sisu                      |
| `rules.filterStderr`       | ei          | Levinud standardveavoo prefiksite normaliseerimine enne hilisemaid filtreid |
| `preserve.errorPatterns`   | ei          | Vearidad, mis peaksid kärpimise üle elama                                   |
| `preserve.summaryPatterns` | ei          | Kokkuvõtteread, mis peaksid kärpimise üle elama                             |
| `tests[]`                  | ei          | RTK kontrollvärava kasutatavad tekstisisesed kontrollnäidised               |

RTK rakendab deklaratiivseid etappe järgmises järjekorras: `stripAnsi`, `filterStderr`, `replace`,
`matchOutput`, `dropPatterns`/`includePatterns`, `truncateLineAt`, `headLines`/`tailLines`,
`maxLines` ja `onEmpty`.

Kohandatud filtreid saab laadida järgmistest kohtadest:

1. Projekti `.rtk/filters.json` failidest ainult pärast seda, kui olemas on vastava räsiga `.rtk/trust.json`, või kui
   `trustProjectFilters` on lubatud.
2. Globaalsest failist `DATA_DIR/rtk/filters.json`.
3. Sisseehitatud filtritest.

Projekti/globaalsed kohandatud failid võivad sisaldada ühte filtriobjekti või filtriobjektide massiivi. Vigased
kohandatud filtrid jäetakse diagnostikateadetega vahele; vigased sisseehitatud filtrid põhjustavad valideerimise nurjumise.

Projekti usaldusfail:

```json
{
  "filtersSha256": "0123456789abcdef..."
}
```

Keskkonna ülekirjutus `OMNIROUTE_RTK_TRUST_PROJECT_FILTERS=1` usaldab projekti filtreid ilma
räsita ning selle kasutamine peaks piirduma kontrollitud kohaliku arendusega.

## Ohutusreeglid

- Hoidke reeglid idempotentsed: sama filtri kahekordne käitamine ei tohiks väljundit rikkuda.
- Säilitage võimaluse korral veatekst, failiteed, reanumbrid ja käskude kokkuvõtted täpselt.
- Vältige reegleid, mis muudavad koodiplokke, JSON-andmeid, URL-e või saladusi.
- Lisage detektori-/filtritestidesse uute käsuperekondade ühiktestid.
- Lisage `tests[]` näidised igale sisseehitatud filtrile ja jagatud kohandatud filtritele.

## Valideerimine

Reeglipakid valideeritakse enne kasutamist. Sisseehitatud Cavemani paketid ja sisseehitatud RTK filtrid annavad valideerimise käigus kohe vea, et vigased väljalaskevarad tuvastataks enne tarnimist. Kohandatud RTK filtrid jäetakse diagnostikateatega vahele, kui parsimine või usaldusväärsuse valideerimine ebaõnnestub.

Sihitud valideerimine:

```bash
node --import tsx/esm --test tests/unit/compression/rule-loader.test.ts tests/unit/compression/language-packs.test.ts
node --import tsx/esm --test tests/unit/compression/rtk-verify.test.ts tests/unit/compression/rtk-dsl-pipeline.test.ts
```
