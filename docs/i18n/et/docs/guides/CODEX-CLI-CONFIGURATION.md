Täielik juhend Codex CLI kasutamiseks, suunates selle OpenAI-ga ühilduva taustsüsteemina OmniRoute'ile.

---

> **TOML on ainus toimiv vorming.** Tänapäevane Codex loeb ainult faili
> `~/.codex/config.toml` (kontrollitud versiooniga codex-cli 0.147.0: `codex --help`
> dokumenteerib `-c/--config` alistused kui „loaded from `~/.codex/config.toml`“).
> Vana `~/.codex/config.yaml` kuulus pärandatud npm-i CLI-le ja seda eiratakse
> ilma hoiatuseta. Juhtpaneeli generaator (`/api/cli-tools/apply`, tööriist `codex`)
> kirjutab TOML-i konservatiivse ühendamisega — olemasolevad võtmed ja teiste
> teenusepakkujate plokid säilitatakse, API-võti jääb muutujasse `OMNIROUTE_API_KEY`
> (mitte kunagi faili) ning allesjäänud pärandfailist `config.yaml` teatatakse
> migreerimismärkusena ilma seda muutmata.

## Kohe kasutatav config.toml

Asenda `<YOUR_HOST>` ja `<YOUR_KEY>` oma väärtustega:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # ajaloo talletamise piirang tööriista väljakutse kohta

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc või ~/.zshrc — võtme tegelik väärtus, mitte kunagi failis config.toml
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: ChatGPT rakendusse integreeritud Codex

Kui installisid Codexi ChatGPT töölauarakenduse kaudu, võib kahendfail `codex`
asuda ainult rakenduse paketis ega pruugi veel olla sinu käsukesta `PATH`-is.
Lisa ressursside kataloog käsukesta käivitusfaili:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

Ava uus käsukest ja seejärel kontrolli:

```bash
command -v codex
codex --version
```

### Autentimiseta kohalik OmniRoute: piisab kohatäitevõtmest

Codex kontrollib, kas võtmega `env_key` määratud keskkonnamuutuja on olemas,
**enne** kui esimene päring CLI-st väljub. Kui sinu **kohalik** OmniRoute'i
eksemplar ei nõua autentimist, sobib mis tahes mittetühi kohatäide:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

Kui sinu OmniRoute'i server on kaitstud või kaugserveris, kasuta selle asemel päris võtit.

> **Levinud hostivalikud**
>
> | Juurdepääs     | URL                           |
> | -------------- | ----------------------------- |
> | Kohalik võrk   | `http://192.168.0.1:20128/v1` |
> | Tailscale      | `http://100.x.x.x:20128/v1`   |
> | Tagasisideahel | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — miks see töötab kõigi mudelitega

Codex CLI kuulutas `wire_api = "chat"` (Chat Completions) 2026. aasta veebruaris aegunuks ja **nõuab** nüüd väärtust `wire_api = "responses"` (OpenAI Responses API). Väärtuse `wire_api = "chat"` määramine põhjustab alates versioonist v0.138 käivitamisel kohe krahhi.

Paljud teenusepakkujad, sealhulgas GLM ja Kimi, pakuvad endiselt ainult Chat Completionsi lõpp-punkti. DeepSeek V4 pakub nüüd nii natiivset Responses API-t kui ka Anthropicuga ühilduvat lõpp-punkti; OmniRoute kasutab vaikimisi Responses API-t ja võimaldab igal DeepSeeki ühendusel valida Anthropicu ühilduvuse.

**OmniRoute lahendab selle läbipaistvalt:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute valib teenusepakkuja natiivse protokolli ja tõlgib vajaduse korral
    → POST /responses (DeepSeek V4) või /chat/completions (Mistral / GLM / Kimi / teised)
```

OmniRoute'i kasutamisel ei vaja sa kunagi eraldi tõlkeproksit. **Kõik mudelid kasutavad väärtust `wire_api = "responses"`** — ülejäänu eest hoolitseb OmniRoute.

> **`wire_api` on vaikeväärtus** — välja vaikeväärtus on `"responses"` ja selle võib failist `config.toml` täielikult välja jätta. Määra see sõnaselgelt ainult siis, kui soovid kavatsuse dokumenteerida.

## Kontekstiaken ja tihendamine

### Tõendite konfiguratsiooniväljad

| Väli                             | Kirjeldus                                                                                                                                                                                                       |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model_context_window`           | Aktiivse mudeli tõendite kogueelarve. Määrake väärtuseks mudeli avaldatud piirang.                                                                                                                              |
| `model_auto_compact_token_limit` | Lävend, mis käivitab ajaloo automaatse tihendamise. **Maksimum: 90% väärtusest `model_context_window`** — üle 90% jäävaid väärtusi eiratakse vaikselt.                                                          |
| `tool_output_token_limit`        | Ajalukku salvestatavate tõendite ülempiir tööriista iga väljakutse väljundi kohta. Takistab ühe suure tööriistavastuse tõttu akna täitumist. **See ei ole väljundi maksimum** — see on ajaloo salvestuspiirang. |
| `compact_prompt`                 | Tihendamisel kasutatava süsteemiviiba tekstisisene alistus (v0.138+).                                                                                                                                           |

> **Märkus välja `model_max_output_tokens` kohta**: see väli **ei kuulu Codex CLI konfiguratsiooniskeemi** (see puudub Codexi Rusti koodibaasist). Kui see määrata, eiratakse seda vaikselt. Ärge tuginege sellele — kasutage välja `tool_output_token_limit`, et kontrollida, kui palju tööriista väljundit ajalukku salvestatakse.

## Arutluse põhjalikkus

Määrab, kui palju mudel enne vastamist „mõtleb“.

| Väärtus  | Kasutus                                                     |
| -------- | ----------------------------------------------------------- |
| `none`   | Arutlus puudub — otsene vastus                              |
| `low`    | Triviaalsed ülesanded (ümbernimetamine, vormindamine)       |
| `medium` | **Serveri vaikeväärtus**, kui pole määratud                 |
| `high`   | Keskmise keerukusega ülesanded (refaktoreerimine, silumine) |
| `xhigh`  | Arhitektuur, süvaanalüüs, keerukad probleemid               |

```bash
# Alista iga käivituse korral
codex -c model_reasoning_effort=low "nimeta muutuja x ümber muutujaks count"
codex -c model_reasoning_effort=xhigh "kavanda autentimismoodul"
```

Määra ka arutluse **kokkuvõte**, et Desktop saaks kuvada mõttekäigu teksti (mitte ainult krüptitud andmeplokke):

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # või ultra, kui seda toetatakse
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### OmniRoute'i mõtlemise eelarve (serveri seadistus)

OmniRoute'i hostis peab **Settings → AI → Thinking Budget** olema seatud väärtusele **`passthrough`**, et Codexi põhjalikkuse/kokkuvõtte sätted jõuaksid ülesvoolu. Režiim **`auto` eemaldab** kõik kliendi väljad `reasoning` / `reasoning_effort` ja jätab mõtlemispaneelid tühjaks isegi siis, kui Codex on õigesti seadistatud.

Täielik juhend: [THINKING_BUDGET.md](./THINKING_BUDGET.md).

Tihendamine ja viibavahemälu on sõltumatud ning töötavad režiimis `passthrough` edasi.

## Profiilid — nimelised seadistused mudeli/töövoo kohta

Profiilid võimaldavad mudelit ja kontekstiakent vahetada ühe lipuga. Iga profiil on lihtne
`~/.codex/<name>.config.toml`, mille sätted rakendatakse baasfaili `config.toml` peale.

> **Nimetamisreegel (Codex CLI v0.137+):** fail peab olema `~/.codex/<name>.config.toml` — **ilma prefiksita `profile-`**.
> CLI lahendab `-p kimi-k27` → `~/.codex/kimi-k27.config.toml`. Kui faili ei leita, rakendatakse vaikeseadistus ilma teavituseta.

```bash
codex --profile kimi-k27 "analüüsi selle koodibaasi 10 000 rida"
codex -p glm52 "arhitektuuri ülevaatus"
codex --profile deepseek-flash "nimeta muutuja ümber"   # kiire, odav
```

### Põhjalikkuse profiilid (sama mudel, erinev põhjalikkus)

```bash

codex -p medium   # cx/gpt-5.5, põhjalikkus=medium

codex -p xhigh    # cx/gpt-5.5, põhjalikkus=xhigh (vaikimisi)
codex -p chat     # cx/gpt-5.5, põhjalikkus määramata (serveri vaikeväärtus)
```

## Profiilide automaatne genereerimine käsuga `omniroute setup-codex`

Kui käitate OmniRoute'i VPS-is, saate reaalajas mudelikataloogi põhjal profiilifailid automaatselt genereerida:

```bash
# VPS-ist (kasutab kohalikku OmniRoute'i pordil 20128)
omniroute setup-codex

# Mis tahes masinast — suunake päring oma VPS-ile
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# Eelvaade ilma faile kirjutamata
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# Genereeri ainult GLM-i ja Kimi profiilid
omniroute setup-codex --only glm,kimi

# Kirjuta kohandatud kataloogi
omniroute setup-codex --codex-home /path/to/.codex
```

Käsk hangib `/v1/models`, kasutab tuntud mudelite jaoks häälestatud profiile, muude ühilduvate tekstimudelite puhul kasutab varuvariandina kataloogi metaandmeid ning kirjutab iga mudeli jaoks faili `~/.codex/<name>.config.toml`. Idempotentne — seda on turvaline uuesti käitada.

OmniRoute saab neid samu profiilifaile ka **automaatselt sünkroonida**, kui teenusepakkuja mudelite edukas tuvastamine/importimine muudab reaalajas kataloogi. See on **vabatahtlik ja vaikimisi välja lülitatud**: lülitage see sisse **CLI Code'i töölaual** ("CLI profile auto-sync" → Codex) või määrake `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` (arvestatakse ka muutujaga `CLI_ALLOW_CONFIG_WRITES`, mis on vaikimisi sisse lülitatud). Kui see on lubatud, kirjutatakse ainult eraldiseisvad profiilifailid `~/.codex/*.config.toml`; aktiivset/vaikimisi faili `~/.codex/config.toml`, Codex-lb sätteid, autentimist ega teenusepakkuja valikut ei muudeta kunagi.

## Pikaajalised ülesanded

Kaks OmniRoute'i vaikeväärtust võivad mitmetunniseid Codex CLI seansse märkamatult kahjustada. Kumbki pole Codex CLI säte — mõlemad asuvad OmniRoute'i poolel. Kasutajad, kes migreerivad konfiguratsiooni ülesvoolu puhverserveritest, mis seovad seansid kontodega ja keelavad jõudeoleku katkestused, puutuvad sageli kokku mõlema probleemiga ning järeldavad, et OmniRoute „ei suuda pikka seanssi töös hoida“.

| Sümptom                                                                           | Tõenäoline põhjus                                                              | Seadistus                |
| --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ------------------------ |
| Seanss vahetab pidevalt kontosid / viiba vahemälu järjepidevus kaob käikude vahel | Seansi afiinsuse TTL on `0` (keelatud)                                         | `sessionAffinityTtlMs`   |
| Ühendus katkeb arutluse ajal ilma kliendile kuvatava viibata                      | Voo jõudeoleku valve käivitus pärast 10 minutit ilma ülesvoolust saabuva osata | `STREAM_IDLE_TIMEOUT_MS` |

Seotud arutelud: [#7126](https://github.com/diegosouzapw/OmniRoute/discussions/7126) (pikkade ülesannete katkemine), [#5718](https://github.com/diegosouzapw/OmniRoute/discussions/5718) (miks afiinsus on vaikimisi välja lülitatud). Jälgimine: [#7287](https://github.com/diegosouzapw/OmniRoute/issues/7287).

### 1. Seansi afiinsus — seo üks vestlus ühe kontoga

**Vaikeväärtus:** `sessionAffinityTtlMs = 0` (keelatud).

**Kus seda määrata**

- Juhtpaneel → **Seaded → Marsruutimine** → **Seansi afiinsus** → **Afiinsuse TTL (sekundites)** (`ComboDefaultsTab`)
- Või kasuta sätete PATCH-päringus välja `sessionAffinityTtlMs` väärtusega **millisekundites** (Zodi vahemik `0`–`86_400_000`, st kuni 24 tundi)

> Nimetati muudatuses #7274 ümber varasemast ainult Codexile mõeldud võtmest `codexSessionAffinityTtlMs`. Pärandvõtit aktsepteeritakse endiselt kirjutuskaitstud aliasena; uued konfiguratsioonid peaksid kasutama võtit `sessionAffinityTtlMs`. Kui TTL on suurem kui `0`, rakendub afiinsus nüüd **kõigile** pakkujatele, mitte ainult Codexile — vt [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → Seansi afiinsus.

**Mis läheb katki, kui väärtuseks jääb 0**

Mitmekäigulise Codexi vestluse iga käik marsruuditakse aktiivse kombineerimisstrateegia alusel iseseisvalt ja võib sattuda **igal käigul eri kontole**. See katkestab ülesvoolu seansi / viiba vahemälu järjepidevuse. OmniRoute arvestab Codexi seansipäiseid (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) ja keha välju, nagu `prompt_cache_key` / `session_id`, ainult siis, kui TTL on suurem kui `0` (`extractSessionAffinityKey` failis `src/sse/services/auth.ts`).

**Soovitus ühe mitmetunnise ülesande jaoks**

Määra TTL **suuremaks kui ülesande eeldatav kogukestus** (kasutajaliidese maksimum on **86400 sekundit** = 24 tundi):

| Ülesande eeldatav kestus | Afiinsuse TTL (kasutajaliides, sekundites) | `sessionAffinityTtlMs` |
| ------------------------ | ------------------------------------------ | ---------------------- |
| Mõni tund                | `14400` (4 h)                              | `14400000`             |
| Üleöö / ~12 h            | `43200` (12 h)                             | `43200000`             |
| Terve päev               | `86400` (24 h, maksimum)                   | `86400000`             |

Sisselülitamine on teadlik valik: afiinsuse keelamine soosib kontodevahelist koormuse tasakaalustamist, selle lubamine aga ühe pika agendiseansi järjepidevust. See juhend **ei** muuda vaikeväärtust — pikki Codexi ülesandeid käitavad operaatorid peavad selle ise sisse lülitama.

### 2. Voo jõudeoleku ajalõpp — ära katkesta vaikseid arutluskäike

**Vaikeväärtus:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 minutit). Kui seda pole määratud, pärib see väärtuse muutujast `REQUEST_TIMEOUT_MS`; ka jagatud lähteväärtus on 600000. Vt [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → Ajalõpud.

**Mis läheb vaikeväärtuse korral katki**

Codexi arutlus-/tööriistavoor, mis püsib vaiksena üle 10 minuti ilma **ühegi tegeliku ülesvoolu andmeplokita**, suletakse SSE jõudeoleku valve (`open-sse/utils/stream.ts`) poolt sunniviisiliselt. Klient näeb sageli lihtsalt ühenduse katkemist — see vastab kirjeldusele „peatati automaatselt ilma ühegi teavituseta“.

Oluline detail: OmniRoute’i sünteetiline SSE **südamelöök ei lähtesta** jõudeoleku taimerit. Ainult tegelik ülesvoolu vastusekeha andmeplokk uuendab väärtust `lastChunkTime`. Vaikne mudel, mis alles „mõtleb“, näib valve seisukohast täpselt samasugune nagu seiskunud ülesvool.

Seotud Undici vastusekeha passiivsuse säte: `FETCH_BODY_TIMEOUT_MS` (vaikimisi samuti sama 10-minutiline lähteväärtus; `0` keelab selle). Voogedastuse puhul hõlmab `FETCH_TIMEOUT_MS` ainult ühenduse loomist / esimesi päiseid — kui voog on aktiivne, juhivad seiskumisi `STREAM_IDLE_TIMEOUT_MS` ja `FETCH_BODY_TIMEOUT_MS`.

**Soovitus mitmetunnise üksikülesande jaoks**

OmniRoute’i protsessi keskkonnas (`.env` / compose / systemd):

```bash
# Keela pikkade arutlusvoorude jaoks voo jõudeoleku ja vastusekeha passiivsuse katkestuspiirangud
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

Või suurenda need väärtused pikimast eeldatavast vaikusest suuremaks (väärtused on millisekundites):

```bash
# Näide: luba ülesvoolu andmeplokkide vahel kuni 2 tundi vaikust
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

Pärast nende keskkonnamuutujate muutmist taaskäivita OmniRoute.

### Konkreetne juhend — mitmetunnine Codexi ülesanne

1. **Kinnista konto:** Dashboard → Settings → Routing → Session affinity → Affinity TTL = `43200` (12 h) või `86400` (maksimaalselt 24 h).
2. **Suurenda jõudeoleku katkestuspiiranguid või keela need** OmniRoute’i keskkonnas:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. Säilita tavapärane Codexi `config.toml` (`wire_api = "responses"`, õige `base_url`, `OMNIROUTE_API_KEY`) — nende kahe käitumise jaoks pole Codexi poolel seansi afiinsuse ega jõudeoleku sätteid.
4. Taaskäivita OmniRoute ja seejärel käivita pikaajaline Codexi ülesanne.

### Vaikeväärtuste otsus (#7287)

| Säte                     | Tarnitav vaikeväärtus | Muuta selles juhendis?                                                                                               |
| ------------------------ | --------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (väljas)          | **Ei** — jääb valikuliseks (koormuse tasakaalustamine vs järjepidevus; vt Discussion #5718)                          |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 min)     | **Ei** — jääb üldise liikluse jaoks 10 minutile; pikaajalise Codexi käitajad suurendavad väärtust või keelavad selle |

Kummagi vaikeväärtuse üleüldine muutmine muudaks käitumist eksemplari iga kliendi, mitte ainult Codexi jaoks. Dokumenteeri sätted; jäta vaikeväärtused muutmata, kuni selgesõnaline käitaja otsus näeb ette teisiti.

### Jõudeolekust tingitud katkestuste diagnoosimine

Kui jõudeoleku valve rakendub, logib OmniRoute järgmise kujuga rea:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

Otsi käsuga grep teksti `Idle timeout: no data from` (või koodi `stream_idle_timeout` / vea nime `StreamIdleTimeoutError`). Teenusepakkuja segment on see, mida OmniRoute vastava päringu jaoks kasutas (`codex`, mõni muu teenusepakkuja ID või `provider`, kui see pole teada) — see ei ole alati sõnasõnaline string `codex`.

## Tõrkeotsing

**`Error: wire_api = "chat" is no longer supported`**
Eemaldage konfiguratsioonist `wire_api = "chat"`. Määrake `wire_api = "responses"` või jätke väli välja (alates versioonist v0.138 on vaikeväärtus `"responses"`).

**`Error: model not found`**
Veenduge, et mudel oleks OmniRoute'is õige prefiksiga olemas. Kasutage käsku `omniroute models list` või avage `/dashboard/providers/<provider>`.

**`Authentication error`**
Veenduge, et `OMNIROUTE_API_KEY` oleks eksporditud: `echo $OMNIROUTE_API_KEY`.

**`ERROR: Missing environment variable: OMNIROUTE_API_KEY`**
Codex kontrollib enne esimese päringu tegemist, kas keskkonnamuutuja on olemas. Eksportige kaitstud serverite jaoks tegelik võti või kasutage mittetühja kohatäidet, näiteks `OMNIROUTE_API_KEY=local`, kui teie **kohalik** OmniRoute'i eksemplar ei nõua autentimist. Kui lisasite selle faili `~/.bashrc` või `~/.zshrc`, taaskäivitage kest.

**`Connection refused`**
Veenduge, et OmniRoute töötaks ning `base_url`-i host/port oleks teie võrgu jaoks õige (kohalik vs. Tailscale vs. VPS).

**Seanss jookseb konteksti piirmäära lähedal kokku**
Määrake `model_context_window` ja `model_auto_compact_token_limit` selgesõnaliselt. Vaadake ülaltoodud kontekstiakna tabelit.

**Tihendamine käivitub liiga hilja**
Vähendage `model_auto_compact_token_limit` väärtust 80–85%-ni akna suurusest. Ärge määrake seda kunagi üle 90%.

**Profiili ei laadita (`-p <name>` eiratakse ilma teateta)**
Veenduge, et fail asuks asukohas `~/.codex/<name>.config.toml` (ilma prefiksita `profile-`). Käivitage `ls ~/.codex/*.config.toml`.

**Pikaajaline Codexi ülesanne katkeb töö käigus / vahetab voorude vahel kontosid**
Vaadake jaotist [Pikaajalised ülesanded](#long-running-tasks). Lubage seansi afiinsus (TTL peab olema ülesande kestusest pikem) ning suurendage väärtusi `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS` või keelake need. Otsige OmniRoute'i logidest käsuga grep teksti `Idle timeout: no data from`.
