`@omniroute/opencode-plugin-v2` lisab kogu teie OmniRoute'i kataloogi — mudelid, kombinatsioonid ja
automaatsed kombinatsioonid — OpenCode v2 mudelivalijasse koos kuvatavate nimede, hinnastuse ning
tasuta kasutustaseme limiitidega.

See on paketist `@omniroute/opencode-plugin` eraldiseisev pakett, sest OpenCode v1 ja v2 laadivad
pistikprogramme erinevate lepingute kaudu. Valige oma OpenCode'i põhiversioonile vastav pakett;
need ei jaga omavahel midagi, mistõttu ühe uuendamine ei sunni kunagi teist uuendama.

## Nõuded

- OpenCode v2.
- Kättesaadav OmniRoute'i lüüs (vaikimisi `http://localhost:20128`).
- Node.js 22 või 24.

## Paigaldamine

Lisage pistikprogramm faili `opencode.json`:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

Seejärel kuvatakse mudelid kujul `omniroute/<provider>/<model>`; `providerId` määrab selle prefiksi ja
integratsiooni ID, mille alla OpenCode identimisteabe salvestab.

## Identimisteave

Pistikprogramm otsib lüüsi võtit kolmest kohast järgmises järjekorras:

1. **OpenCode'is ühendatud identimisteave.** Pistikprogramm registreerib integratsiooni, et
   OpenCode'i enda autentimisvoog saaks võtme salvestada. Faili `opencode.json` ei lisata midagi — eelistage seda.
2. Pistikprogrammi suvandites olev `apiKey` projektipõhiseks alistamiseks. See salvestab võtme faili,
   mille võite versioonihaldusse lisada.
3. Keskkonnas olev `OMNIROUTE_API_KEY`.

Kui ühtegi neist kolmest pole määratud, on kataloog tühi ning pistikprogramm teatab sellest käivitamisel
ühe korra, selle asemel et jätta teile vaikivalt tühi mudelivalija.

### Haldustõend on eraldi võti

Kombinatsioonid, pakkujate seisund ja rikastatud andmed (kuvatavad nimed, hinnastus ning tasuta kasutustaseme limiidid) pärinevad
lüüsi `/api/*` otspunktidest, mida enamik juurutusi kaitseb järelduspäringute võtme asemel **haldus**tõendiga:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<management read token>"
}
```

Kui `managementReadToken` jäetakse määramata, kasutatakse varuvariandina `apiKey` väärtust. Kui lüüs selle varuvariandi
tagasi lükkab, avaldatakse kataloog siiski, kuid kuvatavate nimede asemel kasutatakse mudelite toor-ID-sid,
kanooniliste aliaste duplikaate ei eemaldata ning hinnastus ja kombinatsioonid puuduvad. Pistikprogramm hoiatab sellisel juhul
iga otspunkti kohta ühe korra, nimetades otspunkti ja kaotsi läinud andmed — nii ei jää piiratud funktsionaalsusega mudelivalija kunagi mõistatuseks.

## Suvandid

| Võti                             | Vaikeväärtus                                           | Märkused                                                                                                                              |
| -------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| `providerId`                     | `"omniroute"`                                          | Pakkuja ID, integratsiooni ID ja prefiks, mille all mudelid kuvatakse                                                                 |
| `baseURL`                        | nõutav                                                 | Lüüsi juuraadress, ainult `http(s)`; vajaduse korral lisatakse järelliide `/v1`                                                       |
| `apiKey`                         | ühendatud identimisteave, seejärel `OMNIROUTE_API_KEY` | Vestluse võti otspunktide `/v1/*` jaoks                                                                                               |
| `managementReadToken`            | varuvariandina kasutatakse `apiKey`                    | Võti otspunktide `/api/*` jaoks — tavaliselt **ei ole** see sama võti                                                                 |
| `displayName`                    | `"OmniRoute"`                                          | Pakkuja nimi mudelivalijas                                                                                                            |
| `timeoutMs`                      | `10000`                                                | Otspunktipõhise päringu ajalõpp (automaatsed kombinatsioonid kasutavad 5 s)                                                           |
| `modelCacheTtlMs`                | `300000`                                               | Kataloogi vahemälu TTL; kettale salvestatud hetktõmmis kiirendab külmkäivitusi                                                        |
| `timeouts`                       | varuvariandina kasutatakse `timeoutMs`                 | Otspunktipõhised ajapiirangud millisekundites: `models`, `combos`, `autoCombos`, `enrichment`                                         |
| `enrichment`                     | `true`                                                 | Nimede, hinnastuse ja tasuta kasutustaseme limiitide hankimine                                                                        |
| `providerTag`                    | `true`                                                 | Kuvanimele lisatakse prefiksina ülesvoolu pakkuja, kellele päring suunatakse                                                          |
| `usableOnly`                     | `false`                                                | Säilitatakse ainult need pakkujad, mille lüüs märgib ettevalmistatuks                                                                 |
| `visibleModels` / `hiddenModels` | `[]`                                                   | Täpse vaste või sufiksi alusel lubatud mudelite loendid; keelamine on ülimuslik                                                       |
| `geminiSanitization`             | `true`                                                 | Eemaldatakse JSON-Schema võtmesõnad, mille Gemini tööriistaskeemides tagasi lükkab (`$ref`-iga tööriistad edastatakse muutmata kujul) |
| `apiFormat.allowAnthropic`       | `false`                                                | Lubatud loendisse kuuluvad ID-d suunatakse Anthropicu API ploki kaudu                                                                 |
| `apiFormat.anthropicModels`      | `[]`                                                   | Täielikud mudeli-ID-d, mis suunatakse Anthropicusse                                                                                   |
| `logLevel` / `startupDebug`      | `warn` / `false`                                       | Logija detailsus                                                                                                                      |

## Kuidas kataloog püsib ajakohasena

Kataloog hangitakse viivitusega ja puhverdatakse `modelCacheTtlMs` ajaks ning kettale salvestatud hetktõmmis hoiab viimati teadaoleva kataloogi kättesaadavana, kui lüüs pole ligipääsetav — katkestuse korral kaotate ainult ajakohasuse. Mudelid ja kombinatsioonid avaldatakse kohe pärast saabumist; automaatsed kombinatsioonid, pakkujate loend ja rikastuskiht lisatakse siis, kui need saabuvad, seega ei saa üks aeglane lõpp-punkt kogu valikut blokeerida.

Nimed sisaldavad lüüsile teadaolevat teavet: ülesvoolu pakkujat, kellele mudel suunatakse, tähist `[Free]` ja sellega kaasnevat eelarvet — nii jäävad sama mudelit pakkuvad kaks ühendust eristatavaks. Prefiksi väljalülitamiseks määrake `"providerTag": false`.

Käsitsi värskendamise käsku pole: OpenCode v2 käsud on viibamallid, mitte tagasikutsed, seega ei saa pistikprogramm sellist käsku pakkuda. Värskendamised järgivad TTL-i; hostil palutakse uuesti laadida ainult siis, kui kataloog või rikastuskiht on tegelikult muutunud, mitte iga värskendamise korral.

## Tööriistade väljakutsumine Geminis

Gemini lükkab tagasi kogu päringu, mille tööriistadeklaratsioonid sisaldavad atribuuti `$schema` või `additionalProperties`, vastates veaga `400 INVALID_ARGUMENT`. Pistikprogramm eemaldab need võtmesõnad selle pakkuja Gemini mudelile mõeldud tööriistaskeemidest ja jätab kõik muud päringud muutmata. `$ref`-i sisaldav tööriist edastatakse eemaldamise asemel muutmata kujul, sest viite eemaldamine laiendaks skeemi tähendusele „aktsepteeri kõike”.
Selle väljalülitamiseks määrake `"geminiSanitization": false`.

## Tõrkeotsing

| Sümptom                                                | Põhjus                                                                                                            |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| Valikus ei kuvata ühtegi OmniRoute'i mudelit           | Võtit ei leitud (kontrollige käivitamisel kuvatud hoiatust) või lüüs pole ligipääsetav                            |
| Toored mudeli-ID-d, kombinatsioonid ja hinnad puuduvad | Halduslõpp-punktid keeldusid luba aktsepteerimast — määrake `managementReadToken`                                 |
| Seanss on kinnitatud valikule `opencode-<id>/…`        | v1 pistikprogramm avaldas `opencode-<id>`; v2 avaldab ainult `<id>`, seega valige mudel uuesti jaotisest `<id>/…` |
