> **TL;DR**: OmniRoute järjestab oma **tasuta** pakkujad mudeli kvaliteedi järgi, kasutades **Arena AI
> (LMArena-laadseid) ELO-punkte**. Ava juhtpaneelil leht **Tasuta pakkujate edetabel**, et näha, millised tasuta pakkujad pakuvad sinu ülesande jaoks kõige võimekamaid mudeleid —
> kas üldarvestuses või kategooria järgi filtreerituna (programmeerimine, ülevaatus, dokumentatsioon, silumine).

---

## Mis see on

OmniRoute registreerib 329 pakkujat, sealhulgas 155 kataloogikirjet, mis on märgitud kui **tasuta / autentimiseta**
(autentimiseta,
tasuta taseme OAuth või tasuta taseme API-võti — vt
[tasuta tasemete juhendit](../getting-started/FREE-TIERS-GUIDE.md) ja täielikku
[tasuta tasemete kataloogi](../reference/FREE_TIERS.md)). Konks on selles, et tasuta pakkujate
mudelite kvaliteet varieerub suuresti. Tipptasemel mudelit pakkuv autentimiseta pakkuja on palju kasulikum
kui väikest pärandmudelit pakkuv teenus.

**Tasuta pakkujate edetabel** vastab küsimusele „**milline tasuta pakkuja annab mulle parima mudeli?**“,
ühendades iga tasuta pakkuja kataloogi **ühisloome korras kogutud kvaliteedipunktidega**
**Arena AI edetabelist** (inimeste eelistustel põhinev ELO, sama põhimõte, millel põhineb LMArena
vestlusrobotite areen). Seejärel järjestatakse pakkujad nende **parima tasuta mudeli** võimekuse alusel.

Edetabel arvutatakse kolme tegeliku allika põhjal:

1. Tasuta pakkujate loendid — `NOAUTH_PROVIDERS` ning `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` kirjed, millel on märge `hasFree`
   (`src/shared/constants/providers.ts`).
2. Iga pakkuja mudelikataloog pakkujate registrist
   (`open-sse/config/providerRegistry.ts`).
3. ELO põhjal tuletatud ülesandesobivuse punktid, mille Arena ELO sünkroonimismootor
   (`src/lib/arenaEloSync.ts`) salvestab andmebaasi tabelisse `model_intelligence`.

Ühendamisloogika asub failis `src/lib/freeProviderRankings.ts`.

## Juurdepääs

### Juhtpaneeli leht

Ava juhtpaneel ja vali **Kulud → Tasuta pakkujate edetabel** või liigu otse aadressile:

```
/dashboard/free-provider-rankings
```

Lehel (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) kuvatakse:

- Parima asetusega tasuta pakkujate **esikolmiku poodium** (🥇 🥈 🥉).
- Täielik **edetabel** veergudega **Koht**, **Pakkuja**, **Tippmudel**,
  **Punktisumma**, **Keskmine punktisumma**, **Mudelid**, **Tüüp**.
- **Kategooriafiltri nupud**: _Kõik kategooriad_, _Vaikimisi_, _Programmeerimine_, _Ülevaatus_,
  _Dokumentatsioon_, _Silumine_.

Iga pakkuja **Tüübi** märk näitab, mil viisil on teenus tasuta:

| Märk     | Tähendus                                      |
| -------- | --------------------------------------------- |
| `NOAUTH` | Alati tasuta, autentimisandmeid pole vaja     |
| `OAUTH`  | Tasuta tasemega OAuth-pakkuja (`hasFree`)     |
| `APIKEY` | Tasuta tasemega API-võtme pakkuja (`hasFree`) |

Punktisummasid näidatakse toorarvude asemel inimloetavate hinnangutena (nt _Eliit_, _Suurepärane_, _Väga hea_,
_Hea_, _Keskmine_), sest aluseks olev väärtus väljendab suhtelist
järjestuskvaliteeti, mitte protsenti.

### API lõpp-punkt

Lehe aluseks on avalik lugemislõpp-punkt
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

Päringuparameetrid (valideeritakse Zodiga):

| Parameeter | Tüüp   | Vaikeväärtus | Märkused                                                                                                      |
| ---------- | ------ | ------------ | ------------------------------------------------------------------------------------------------------------- |
| `category` | string | (puudub)     | Üks väärtustest `default`, `coding`, `review`, `documentation`, `debugging`. Koondedetabeli jaoks jäta välja. |
| `limit`    | number | `50`         | Piiratakse vahemikku `1–100`.                                                                                 |

Vastuse struktuur:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` on Arena ELO algne väärtus; `score` on normaliseeritud ülesandesobivuse väärtus
(vt allpool). Pakkujad, kellel pole ühtegi hinnatud mudelit, jäetakse vastusest välja.

## Kuidas skoorid toimivad

### Allikas: Arena AI edetabel

Arena ELO sünkroonimismootor (`src/lib/arenaEloSync.ts`) hangib Arena AI edetabeli API-st
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) kaks edetabelit — `text`
ja `code`. Iga edetabelikirje sisaldab mudeli nime, tarnijat, ELO `score`-i,
usaldusvahemikku ja häälte arvu.

Edetabeli kategooriad vastendatakse OmniRoute'i ülesandekategooriatega:

| Arena edetabel | OmniRoute'i ülesandekategooriad                   |
| -------------- | ------------------------------------------------- |
| `text`         | `default`, `review`, `documentation`, `debugging` |
| `code`         | `coding`                                          |

### Normaliseerimine (ülesandega sobivuse skoor)

ELO toorskoorid normaliseeritakse iga edetabeli kohta **ülesandega sobivuse väärtuseks vahemikus `[0.4, 0.98]`**:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

Skoor ei jõua kunagi väärtuseni `0` ega `1`, jättes varu kasutaja määratud väärtustele.
See on API vastuses kuvatav väli `score` ja töölaual kuvatav silt.

### Usaldusväärsus

Igale kirjele määratakse Arena häälte arvu põhjal usaldusväärsuse tase:

| Usaldusväärsus | Hääli   |
| -------------- | ------- |
| `high`         | ≥ 5,000 |
| `medium`       | ≥ 1,000 |
| `low`          | < 1,000 |

### Salvestamine ja ajakohasus

Normaliseeritud kirjed kirjutatakse andmebaasi tabelisse `model_intelligence`, määrates
`source = "arena_elo"` (`src/lib/db/modelIntelligence.ts`). Kirjed **aeguvad 7 päeva
pärast**, mistõttu sünkroonimise lõpetanud tarnija andmed eemaldatakse lõpuks, selle
asemel et kuvada aegunud andmeid.

Sünkroonimine on **vaikimisi sisse lülitatud**:

- See käivitatakse üks kord serveri käivitamisel ja seejärel perioodilise taimeriga
  (`src/lib/arenaEloSync.ts`, ühendatud failist `src/instrumentation-node.ts`).
- See on **mitteblokeeriv ega põhjusta kunagi kriitilist tõrget** — kui andmete
  hankimine lähteallikast nurjub, jätkab OmniRoute tööd ning pingereas kuvatakse lihtsalt
  viimased korrektsed andmed (või tühi olek).

Seda juhivad kaks keskkonnamuutujat (dokumenteeritud failis
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)):

| Muutuja                   | Vaikeväärtus  | Otstarve                                                    |
| ------------------------- | ------------- | ----------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | Väljuva sünkroonimise keelamiseks määra väärtuseks `false`. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | Sünkroonimisintervall sekundites.                           |

### Käsitsi sünkroonimine / olek / kustutamine

Operaatoritele pakub autenditud halduslõpp-punkt käsitsi juhtimise võimalust
(`src/app/api/intelligence/sync/route.ts` — nõuab halduse autentimist):

```
GET    /api/intelligence/sync          # sünkroonimise praegune olek (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # käivita käsitsi sünkroonimine; body: { "dryRun": true }, et vaadata eelvaadet ilma kirjutamata
DELETE /api/intelligence/sync          # kustuta kõik sünkroonitud arena_elo teabekirjed
```

Kui pingerea leht on tühi, täidab käsitsi tehtav `POST /api/intelligence/sync` (või
lihtsalt serveri taaskäivitamine) selle uuesti.

### Mudelite vastendamine edetabeliga

Registri mudeli-ID-d ja Arena mudelinimed ei kattu alati täpselt. Pingerida kasutab
paindlikku vastendamist (`findMatchingIntelligence` failis `src/lib/freeProviderRankings.ts`):

1. Normaliseeritud mudeli-ID täpne vaste.
2. Vaste pärast lõpus oleva versioonisufiksi eemaldamist (nt `kimi-k2.6` → `kimi-k2`).
3. Prefiksi vaste (edetabelis olev mudelinimi on registri-ID prefiks).

Sünkroonimise poolel eemaldatakse tuntud tarnijaprefiksid (`anthropic/`, `openai/`,
`google/`, …) ning väike pseudonüümikaart laiendab kanoonilised nimed OmniRoute'i
sisemiselt kasutatavateks variantideks, et mudelid oleksid leitavad mis tahes nime all.

### Kuidas tarnija pingerida määratakse

Mootor hindab iga tasuta tarnija kataloogis kõiki mudeleid ning seejärel:

- **Parim mudel** = tarnija kõrgeima skooriga mudel.
- **Keskmine skoor** = kõigi selle tarnija hinnatud mudelite skooride aritmeetiline keskmine.
- **Mudelid** = tarnija nende mudelite arv, millel oli Arena skoor.

Tarnijad sorditakse esmalt **parima mudeli skoori** ja seejärel keskmise skoori järgi.
See premeerib tarnijat, kes pakub vähemalt üht tugevat tasuta mudelit.

## Selle kasutamine tasuta teenusepakkujate valimiseks

1. **Valige õige kategooria.** Kasutage agendipõhiste/koodiga seotud töökoormuste jaoks filtrit **Coding** või
   jätke üldise vestluse jaoks valikuks **All Categories** / **Default**. Sama teenusepakkuja
   võib eri kategooriates paikneda erineval kohal, sest selle tippmudel erineb edetabeliti.
2. **Ühekordse seadistuse korral eelistage poodiumikohti.** Kui soovite ühendada ainult ühe või kaks tasuta
   teenusepakkujat, alustage oma kategooria kõrgeima asetusega pakkujatest.
3. **Kontrollige tüübi märgist.** `NOAUTH`-tüüpi teenusepakkujad saab ühendada kõige kiiremini (ilma
   autentimisandmeteta). `OAUTH`- / `APIKEY`-tüüpi tasuta paketid nõuavad kiiret registreerumist, kuid pakuvad sageli
   võimsamaid mudeleid. Ühendamisjuhiseid vaadake dokumendist [Tasuta pakettide juhend](../getting-started/FREE-TIERS-GUIDE.md).
4. **Ühendage mitu teenusepakkujat ja laske Auto-Combo-l otsustada.** Samad Arena ELO andmed, millel
   see leht põhineb, sisestatakse ka Auto-Combo hindamismootori **ülesandesobivuse tegurisse**
   (`open-sse/services/autoCombo/taskFitness.ts`, lahendusjärjestus
   `user_override → arena_elo → models_dev_tier → static table`). Pärast parimate tasuta teenusepakkujate
   ühendamist eelistab `model: "auto"`-ga marsruutimine (nt `auto/coding`)
   iga päringu puhul automaatselt kvaliteetsemaid tasuta mudeleid. Kõigi 16 hindamisteguri kohta vaadake
   dokumenti [Auto-Combo](../routing/AUTO-COMBO.md).
