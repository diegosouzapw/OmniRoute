OmniRoute pakub OpenAI Codexi kasutamiseks **kahte** võimalust:

| Pakkuja                | Kuidas see OpenAI-ga suhtleb                                                                                                                                                                | Kasutuspiirang                                                                     |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| **`codex`**            | Edastab teie ChatGPT/OpenAI OAuthi loa otse Responses API-le                                                                                                                                | **Jah** — ametlik seanss ei ole puhverserveri/ruuteri kaudu kasutamiseks volitatud |
| **`codex-app-server`** | Juhib **Codex CLI enda `codex app-server`-it** JSON-RPC/WebSocketi kaudu; CLI haldab ja värskendab oma OAuthi (`~/.codex/auth.json`) automaatselt täpselt nagu interaktiivne `codex`-seanss | **Ei** — OmniRoute ei edasta kunagi luba API-le                                    |

Kuna `codex-app-server` ei edasta kunagi luba, ei kaasne sellega
seansi taasesitamise kasutuspiirangut. See nõuab siiski, et **Codex CLI oleks
seadistatud app-serveri URL-il kättesaadav**, ning CLI peab olema **sisse logitud**.

---

## 1. Arhitektuur

```
┌─ OmniRoute'i rakendus ───────────┐        ┌─ codex-app-server'i kõrvalkonteiner ─┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                    │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456          │
│  (+ võimekusluba)                │  JSON  │  --ws-auth capability-token          │
│                                  │  RPC   │  haldab ise OpenAI OAuthi            │
└──────────────────────────────────┘        │  (~/.codex/auth.json, automaatvärskendus) │
        │ jagab (compose'i andmeköited)      └───────────────────────────────────────┘
        ▼
  codex-appserver-token   → WS-i võimekusluba (mõlemad haagivad selle)
  codex-appserver-home    → ~/.codex (auth.json-i kirjutab juhtpaneel,
                             seda loeb kõrvalkonteineri codex app-server)
```

- Kõrvalkonteiner kuulab **ainult** sisemises compose'i võrgus
  (`ws://codex-app-server:1456`) võimekusloa taga. Seda **ei avaldata kunagi**
  hostile ega internetti.
- Codex CLI on `omniroute:base` tõmmisesse sisse ehitatud, mistõttu pole
  kõrvalkonteineri käitamisel vaja codex'it hostile ega kasutaja arvutisse
  installida.

## 2. Käivitamine

```bash
# Käivita pinu KOOS codex app-server'i kõrvalkonteineri profiiliga:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

Kõrvalkonteiner loob esmakordsel käivitamisel oma WS-i võimekusloa (jagatud
`codex-appserver-token` andmeköitesse) ning rakendus loeb sama luba
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE` kaudu. Luba pole vaja käsitsi
ühendada ega seadistada.

## 3. Ühendamine ja sisselogimine

1. Lisage juhtpaneelil ühendus teenuse **OpenAI Codex (App-Server)** jaoks. API
   võtit ega luba pole vaja (see on autentimiseta pakkuja — autentimist haldab
   kõrvalkonteiner).
2. Kui kõrvalkonteineri Codex CLI **pole veel sisse logitud**, kuvab ühenduse
   seisundikontroll teate _„töötab, kuid pole sisse logitud“_ (mitte punast
   autentimisviga). Kasutage valikut **Logi sisse ChatGPT-ga**: see käivitab
   brauseris tavapärase Codexi seadme-OAuthi ja kirjutab seejärel
   **Rakenda autentimine** kaudu faili `~/.codex/auth.json` jagatud andmeköitesse
   (sama sisselogimine teenindab nii `codex`-i kui ka `codex-app-server`-i
   pakkujat).
3. Pärast sisselogimist muutub seisundikontroll roheliseks (see kontrollib nii
   `/readyz` **kui ka** `account/read`-i — st teenus töötab _ja_ on autenditud)
   ning ühendus hakkab tööle.

Juhtpaneel ei kirjuta kunagi üle toimivat olemasolevat faili
`~/.codex/auth.json` — see kirjutab ainult siis, kui fail puudub või selle luba
on aegunud (alati luuakse varukoopia).

## 4. Juurutusstsenaariumid

- **Operaator, kelle Codex CLI on juba autenditud** — haakige hosti
  `~/.codex` kõrvalkonteinerisse (`codex-appserver-home`) ja jätke
  sisselogimisetapp vahele.
- **Avalik kasutaja, kellel pole codex'it kohalikult installitud** — see pole
  oluline: CLI asub kõrvalkonteineris. Kasutaja autendib end ainult juhtpaneeli
  kaudu.
- **OmniRoute otse serveris (ilma kõrvalkonteinerita, codex hostis)** — suunake
  `OMNIROUTE_CODEX_APPSERVER_WS` enda `codex app-server`-ile ja veenduge, et
  hosti codex oleks sisse logitud; kui binaarfail puudub, kuvatakse vihje
  „codex pole installitud“.

## 5. Koduvõrgu / UDP väljaminev liiklus (operaatori lisalahendus, ei kuulu väljalaskesse)

Üldine kõrvalkonteiner suunab väljamineva liikluse ülal kirjeldatud viisil
konteineri tavavõrgu kaudu. Operaator, kellel on vaja suunata Codexi liiklus
**koduvõrgu väljundpunkti** kaudu (nt TUN-i tailscale'i kõrvalkonteiner, mis
edastab TCP- ja UDP/QUIC-liiklust), käitab seda eraldi compose'i
ülekirjutuskonfiguratsioonina; see **ei kuulu** teadlikult väljalaskega kaasas
olevasse `codex-app-server` profiili. Selle seadistuse kohta vaadake sisemist
käitusjuhendit.
