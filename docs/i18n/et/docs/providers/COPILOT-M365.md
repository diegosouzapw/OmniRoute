`copilot-m365-web` (alias `m365copilot`) saadab OpenAI-vormingus vestluspäringuid autentitud Microsoft 365 Copilot BizChati brauseriseansi kaudu aadressil `m365.cloud.microsoft/chat`. See on mitteametlik integratsioon.

> **Kas veebiküpsiste teenusepakkujad on teile uued?**
>
> Enne selle teenusepakkuja spetsiifilise juhendi järgimist lugege üldise seadistusprotsessi, autentimisjuhiste, piirangute ja tõrkeotsingu kohta dokumenti **`docs/getting-started/WEB-COOKIE-GUIDE.md`**.
>
> **Oluline:** selle teenusepakkuja mandaat **ei ole küpsis**. Ärge kopeerige küpsiseid saidilt `m365.cloud.microsoft`. Mandaat koosneb WebSocketi URL-i päringuparameetrist ja teelõigust, mis mõlemad saadakse DevToolsi vahekaardilt Network.

## Eeltingimused

- Microsoft 365 konto, millel on juurdepääs BizChatile aadressil `m365.cloud.microsoft/chat`
- Chromiumil põhinev brauser (Chrome, Edge) WebSocketi ühenduse kontrollimiseks DevToolsiga
- M365 Copiloti litsents (sisaldub paljudes Microsoft 365 Businessi/Enterprise'i pakettides)

## Mandaadi hankimine (WebSocketi meetod)

1. Logige sisse aadressil `https://m365.cloud.microsoft/chat` ja alustage vestlust.
2. Avage **DevTools → Network**.
3. Filtreerige väärtuse **WS** (WebSocket) järgi.
4. Klõpsake Chathubi WebSocketi ühendust. Otsige URL-i, mille algus on `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Kopeerige selle väljal **Request URL**:
   - päringuparameetri `access_token` väärtus (lühikese elueaga JWT);
   - teelõik pärast osa `/Chathub/` (nt `<oid>@<tenant>`).

Täielik URL on järgmisel kujul:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. Avage OmniRoute'is **Providers → Add Provider**, valige **Microsoft 365 Copilot (BizChat)** ja kleepige mandaat järgmises vormingus:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Klõpsake **Test Connection** ja **Save**.

## Mandaadi hankimine (HAR-i importimine)

WebSocketi URL-ist väärtuste käsitsi kopeerimise asemel saate eksportida DevToolsi HAR-faili:

1. Avage **DevTools → Network**.
2. Alustage või jätkake BizChati vestlust (see käivitab WebSocketi ühenduse).
3. Paremklõpsake Networki paneelil ja valige **Save all as HAR with content**.
4. Kasutage OmniRoute'i teenusepakkuja ühenduse dialoogis nuppu **Import .har file**.

OmniRoute otsib HAR-ist Chathubi WebSocketi URL-i, eraldab väärtused `access_token` ja `chathubPath` ning täidab mandaadiväljad automaatselt. HAR-i importimisel dekodeeritakse JWT aegumisaeg ja kuvatakse pääsuloa järelejäänud kehtivusaeg.

> **Ärge kunagi lisage tegelikku HAR-eksporti, pääsuluba ega värskendusluba koodihoidlasse.** Testides ja dokumentatsioonis kasutatavad väärtused peavad alati olema kohatäitjad.

## Pääsuloa kehtivusaeg ja värskendamine

`access_token` on lühikese elueaga (tavaliselt **~75 minutit**). Pärast selle aegumist teatab teenusepakkuja ühenduse veast ja peate mandaadi uuesti hankima.

### Automaatne värskendamine väljaga `refreshToken`

Käsitsi uuesti hankimise vältimiseks saate salvestada Microsofti värskendusloa ühenduse jaotises **Advanced Settings → providerSpecificData**:

| Väli           | Kirjeldus                                                                   |
| -------------- | --------------------------------------------------------------------------- |
| `refreshToken` | Microsoft OAuthi värskendusluba ulatuse `substrate.office.com/sydney` jaoks |
| `tier`         | `individual` (vaikimisi), `edu` või `enterprise`                            |

Hankige värskendusluba Microsofti seadmekoodi- või autoriseerimiskoodivoo kaudu, mille ulatus on `substrate.office.com/sydney`. Kui `refreshToken` on määratud, värskendab OmniRoute enne iga päringut ennetavalt väärtust `access_token`, mistõttu ei pea te mandaati pärast iga ~75-minutilist aegumist uuesti hankima.

Kui `refreshToken` pole määratud, peate WebSocketi mandaadi pärast iga aegumist käsitsi uuesti hankima.

### Taseme valimine

| Tase         | Alias         | Kasutusliides                    |
| ------------ | ------------- | -------------------------------- |
| `individual` | _(vaikimisi)_ | Tarbijatele mõeldud M365 Copilot |
| `edu`        | `included`    | Hariduse M365 Copilot            |
| `enterprise` | `work`        | M365 Copilot for Work            |

Määrake tase jaotises **Advanced Settings → providerSpecificData → tier**. Tase mõjutab BizChati marsruutimist ja mudelitele juurdepääsu.

## Turbemudel

- **Mitteametlik integratsioon.** See pakkuja kasutab pöördprojekteerimise teel tuvastatud BizChati WebSocketi
  protokolli. Kui Microsoft lõpp-punkti muudab, võib integratsioon ette teatamata lakata töötamast.
- Lipp `subscriptionRisk: true` näitab, et integratsioon tugineb
  dokumenteerimata lõpp-punktile. Kontopiirangud on võimalikud, kuid pole kinnitust leidnud.
- Pääsutõend on lühikese kehtivusajaga JWT. Käsitlege seda nagu parooli: ärge lisage seda koodihoidlasse,
  logige ega jagage seda.
- Värskendustõend annab pikaajalise juurdepääsu BizChati teenusele. Hoidke seda
  sama hoolikalt nagu API võtit.

## Tõrkeotsing

### Autentimine nurjub kohe

- Veenduge, et kopeerisite andmed **WebSocketi URL-ist**, mitte XHR/Fetch-päringust.
  Mandaat asub Chathubi WebSocketi ühenduse päringuparameetris `access_token`
  — mitte päises `Authorization: Bearer`.
- Veenduge, et `chathubPath` sisaldaks URL-i teest kogu segmenti `<oid>@<tenant>`.

### Tõend aegub umbes 75 minuti pärast

See on ootuspärane. Ilma `refreshToken`-ita on pääsutõend lühikese kehtivusajaga. Tehke ühte järgmistest:

- Hõivake mandaat DevToolsi kaudu uuesti või
- Seadistage täpsemates sätetes automaatseks värskendamiseks `refreshToken`.

### Ühenduse test õnnestub, kuid vestlus tagastab vea 401

Tõend võis valideerimise ja esimese päringu vahel aeguda. Hõivake
uus mandaat.

### Copilotit ei kuvata pakkujate loendis

Veenduge, et `copilot-m365-web` oleks jaotises **Töölaud → Pakkujad** lubatud. Mõnes
teenusetasemes võib pakkuja olla vaikimisi peidetud.
