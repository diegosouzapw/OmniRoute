See dokument talletab lahenduse juurutamise otsuse
[probleemi #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854) kohta. Avalikud tooted on
esitatud nelja teenusepakkujate perekonnana. Piirkond on ühenduse teave, mitte eraldiseisev toode.

## Otsus

| Teenusepakkuja perekond                    | OmniRoute'i ID          | Globaalne piirkond | Hiina piirkond |
| ------------------------------------------ | ----------------------- | ------------------ | -------------- |
| Alibaba Cloud Model Studio (kasutuspõhine) | `alibaba`               | Singapur           | Peking         |
| Alibaba Cloud Token Plan                   | `bailian-coding-plan`   | Singapur           | Peking         |
| Qwen Cloud (kasutuspõhine)                 | `qwen-cloud`            | Globaalne          | Peking         |
| Qwen Cloud Token Plan                      | `qwen-cloud-token-plan` | Singapur           | Peking         |

Olemasolev ID `alibaba-cn` jääb salvestatud ühenduste, mudelimarsruutide, kombinatsioonide ja
ajaloolise kasutuse käitusaegseks ühilduvusaliasteks. Selle töölauakaart liidetakse teenusepakkujaga
`alibaba`; andmebaasi ümberkirjutamine ei ole vajalik.

Qwen Cloudi kasutuspõhine toode ja Alibaba Cloud Model Studio kasutavad praegu samu
DashScope'iga ühilduvaid käitusaegseid hoste, kuid jäävad eraldi teenusepakkujateks, sest kasutajad
saavad võtmed ja haldavad kontosid erinevate tooteliideste kaudu. Alibaba ja Qwen Cloudi Token Plani
tooted kasutavad erinevaid lõpp-punktide perekondi, mistõttu kõik neli toodet jäävad eraldi
teenusepakkuja ID-deks.

## Lõpp-punktide maatriks

| Teenusepakkuja perekond | `global-sg`                                                              | `china-beijing`                                                      | Andmevorming |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ------------ |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI       |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic    |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI       |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI       |

API-võti ja lõpp-punkt peavad kuuluma samale tootele ja piirkonnale. Piirkonna valimine muudab
eelseadistatud lõpp-punkti, mida kasutatakse valideerimisel ja tavapärastes päringutes.

## Ühenduse leping

Uued ühendused talletavad stabiilse piirkonnavõtme väljal `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

Lubatud väärtused on `global-sg` ja `china-beijing`. Lõpp-punkt tuletatakse keskselt teenusepakkuja
ID-st ja piirkonnast. Eelseadistamata `providerSpecificData.baseUrl` jääb operaatori selgesõnaliseks
alistuseks ja on ülimuslik, samas kui vanad salvestatud eelseadistatud URL-id normaliseeritakse
tagasi piirkondliku maatriksi järgi.

See hoiab ühenduse skeemi laiendatavana: resolverisse saab lisada teise piirkonna ilma uut
teenusepakkuja kaarti loomata või salvestatud teenusepakkuja ID-sid muutmata.

## Ühilduvus ja juurutamine

1. Lisage regionaalse lõpp-punkti resolver ja säilitage praegused globaalsed vaikeväärtused.
2. Kasutage reaalajas regionaalset DashScope’i `/models`-tuvastust teenuse `alibaba`, selle `alibaba-cn`-ühilduvus-ID
   ja `qwen-cloud` puhul. Nende vastused läbivad esmalt ühe tekstigenereerimise filtri, sest üldine
   lõpp-punkt tagastab ka pildi-, video-, heli-, manus- ja muid mittevestlusmudeleid. Seejärel rakendab
   `qwen-cloud` oma teenusepakkuja registris deklareeritud hallatavat lubatud loendit. Alibaba Model Studio
   ja Qwen Cloud säilitavad eraldi kureeritud kataloogid, kuigi nad jagavad praegu käitusaegseid hoste.
3. Registreerige `qwen-cloud-token-plan` praeguse Token Plan’i tekstimudelite lubatud loendiga.
4. Lisage ühenduse lisamise/muutmise dialoogidesse tüübitud regioonivalija.
5. Peitke dubleeritud `alibaba-cn`-kaart ja lisage selle olemasolevad ühendused `alibaba`
   teenusepakkuja lehele.
6. Hoidke kohandatud lõpp-punktide alistused saadaval täiustatud ja tööruumipõhiste juurutuste jaoks.

Token Plan’i meediamudelid jäävad vestluskataloogist välja, sest need kasutavad spetsiaalseid lõpp-punkte.
`wan2.7-image` ja `wan2.7-image-pro` on registreeritud failis `open-sse/config/imageRegistry.ts`;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` ja `happyhorse-1.1-r2v` on registreeritud failis
`open-sse/config/videoRegistry.ts`. Mõlemad registrid taaskasutavad `qwen-cloud-token-plan`-ühenduse
identiteeti ja selle regioonipõhiseid identimisteavet.

Tavalisel Qwen Cloudil on eraldi kasutuspõhise tasuga pildi- ja videokataloogid identiteedi `qwen-cloud`
all. Selle pildimudelid on `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` ja `z-image-turbo`. Selle videomudelid
on `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` ja
`wan2.7-videoedit`. Need mudelid taaskasutavad ainult tavalist `qwen-cloud`-ühendust ja regionaalset
DashScope’i meedia lõpp-punkti. Token Plan’i ja kasutuspõhise tasuga registrid ei päri ega ühenda
üksteise mudeliloendeid.

Identiteedil `bailian-coding-plan` on samuti oma meedia lubatud loendid:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` ja `qwen-image-2.0-pro` piltide
genereerimiseks ning
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` ja `happyhorse-1.1-r2v` videote
genereerimiseks. See kasutab ainult Bailian Coding Plan’i ühendust ja regionaalset Coding Plan’i lõpp-punkti.
Selle pildi- ja videoregistrid ei päri ega ühine kummagi Qwen Cloudi teenusepakkuja registritega.

Tavalisel `alibaba` identiteedil on eraldi pildi- ja videomudelite lubatud loendid. Selle pildimudelid on
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` ja `wan2.6-t2i`. Selle lisatud videomudelid on `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` ja `wan2.7-videoedit`. Need mudelid kasutavad ainult Alibaba Model Studio
ühendust ja selle valitud regionaalset meedia lõpp-punkti; neid ei lisata ühtegi Coding Plan’i ega Qwen
Cloudi registrisse.

Qwen Cloud Token Plan’i vestluskataloog järgib Individual-paketi täpse stringivastega tekstimudelite lubatud loendit:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` ja
`deepseek-v4-pro`. Wan- ja HappyHorse-kirjed kuuluvad eraldi pildi-/videogenereerimise API-desse.

Alibaba Token Plan avaldab samad kuus praegust tekstigenereerimise mudeli-ID-d oma
Anthropicuga ühilduva lõpp-punkti kaudu. Selle Singapuri valik talletab olemasoleva `global-sg` regioonivõtme;
ainult kasutajale kuvatav silt erineb teenusepakkujate perekondadest, mis nimetavad regiooni globaalseks.

Tavaline Qwen Cloudi vestluskataloog on teadlikult kitsam kui täielik reaalajas tekstvastus. Selle
hallatav lubatud loend asub failis `open-sse/config/providers/registry/qwen-cloud/index.ts`; reaalajas
tuvastus tagastab ainult ID-d, mis esinevad nii ülesvoolu vastuses kui ka selles registriloendis.

Alibaba Model Studio järgib sama reaalajas ühisosa reeglit oma sõltumatult hallatava
lubatud loendiga failis `open-sse/config/providers/registry/alibaba/index.ts`. `alibaba-cn`-ühilduvuse
teenusepakkuja taaskasutab seda kataloogi, suunates tuvastuse Pekingi lõpp-punktile.
