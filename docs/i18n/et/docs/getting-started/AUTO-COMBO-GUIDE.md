> **Lühidalt**: määrake mudeliks `auto` ja OmniRoute valib iga päringu jaoks automaatselt parima tehisintellekti teenusepakkuja. Seadistamine pole vajalik.

---

## Mida see teeb?

Selle asemel et valida konkreetne tehisintellektimudel (näiteks GPT-4o või Claude), võite lasta OmniRoute’il **iga päringu jaoks automaatselt parima mudeli valida**. See arvestab järgmist:

- **Tööseisund** — kas teenusepakkuja töötab praegu?
- **Kiirus** — kui kiire see on?
- **Maksumus** — kui palju see maksab?
- **Kvaliteet** — kas see sobib seda tüüpi ülesande jaoks?
- **Maht** — kas kvooti on veel alles?

OmniRoute hindab kõiki teie ühendatud teenusepakkujaid ja valib neist parima. Kui see ebaõnnestub, proovib süsteem automaatselt järgmist.

---

## Kiirjuhend

**1. samm**: määrake oma IDE-s või CLI-s mudeliks `auto`:

```
model: "auto"
```

**2. samm**: ongi kõik! Ülejäänu eest hoolitseb OmniRoute.

**3. samm** (valikuline): kasutage konkreetsete ülesannete jaoks varianti:

```
model: "auto/coding"    # Parim koodi jaoks
model: "auto/fast"      # Kiireim vastus
model: "auto/cheap"     # Odavaim valik
```

---

## Millist „auto” varianti kasutada?

| Kui soovite...         | Kasutage seda  | Sobib kõige paremini            | Kuidas see töötab                              |
| ---------------------- | -------------- | ------------------------------- | ---------------------------------------------- |
| **Üldiselt parimat**   | `auto`         | Üldküsimused, vestlus           | Tasakaalustab kiiruse, maksumuse ja kvaliteedi |
| **Parimat koodi**      | `auto/coding`  | Koodi kirjutamine, silumine     | Valib kodeerimisülesanneteks sobivad mudelid   |
| **Kiireimat vastust**  | `auto/fast`    | Kiired vastused, väike viivitus | Eelistab kiirust kõigele muule                 |
| **Odavaimat valikut**  | `auto/cheap`   | Raha säästmine                  | Valib odavaima teenusepakkuja                  |
| **Nutikaimat mudelit** | `auto/smart`   | Keerukad ülesanded              | Eelistab kvaliteeti ja katsetab uusi mudeleid  |
| **Suurimat saadavust** | `auto/offline` | Kui teenusepakkujad on hõivatud | Valib suurima vaba mahuga teenusepakkujad      |

### Näited

```bash
# Üldine vestlus — tasakaalustatud
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'

# Koodi genereerimine — kvaliteet ennekõike

  -H "Content-Type: application/json" \

# Kiire vastus — kiirus ennekõike
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/fast","messages":[{"role":"user","content":"What is 2+2?"}]}'
```

## Kuidas see töötab? (Lihtsustatud versioon)

Kui saadate päringu väärtusega `model: "auto"`, teeb OmniRoute järgmist:

1. **Vaatab kõiki teie ühendatud teenusepakkujaid** — kõiki teie lisatud teenusepakkujaid (OpenAI, Anthropic, Google jne)
2. **Hindab igaüht**, võttes muu hulgas arvesse järgmist:
   - Kas see töötab? (tööseisund)
   - Kas sellel on vaba mahtu? (kvoot)
   - Kui palju see maksab? (hind)
   - Kui kiire see on? (kiirus)
   - Kas see sobib selle ülesande jaoks? (kvaliteet)
3. **Valib parima** — päring saadetakse kõrgeima punktisummaga teenusepakkujale
4. **Taastub automaatselt** — ebaõnnestumise korral proovib OmniRoute automaatselt järgmist

### Hindamissüsteem

Iga teenusepakkuja saab punktisumma vahemikus 0–1. Mida suurem on punktisumma, seda paremini teenusepakkuja sobib.

| Tegur              | Kaal | Mida see tähendab                                         |
| ------------------ | ---- | --------------------------------------------------------- |
| Tööseisund         | 20%  | Kas teenusepakkuja töötab? (kaitselüliti olek)            |
| Kvoot              | 15%  | Kas sellel on vaba mahtu?                                 |
| Maksumus           | 15%  | Kui kallis see on? (odavam = kõrgem punktisumma)          |
| Kiirus             | 12%  | Kui kiire see on? (väiksem viivitus = kõrgem punktisumma) |
| Sobivus ülesandeks | 8%   | Kas see sobib seda tüüpi ülesande jaoks?                  |
| Stabiilsus         | 5%   | Kas see on järjepidev? (väike veamäär)                    |
| Tase               | 5%   | Konto tase (Ultra > Pro > Free)                           |
| Muu                | 20%  | Konteksti sobivus, ühenduste tihedus jne                  |

### Kuidas variandid hindamist muudavad?

Iga variant kasutab erinevaid kaale:

| Variant        | Eelistab                 | Peamised kaalud                 |
| -------------- | ------------------------ | ------------------------------- |
| `auto`         | Tasakaalu                | health=20%, quota=15%, cost=15% |
| `auto/coding`  | Kvaliteeti               | taskFit=37%, stability=15%      |
| `auto/fast`    | Kiirust                  | latency=32%, health=28%         |
| `auto/cheap`   | Maksumust                | cost=37%                        |
| `auto/smart`   | Kvaliteeti + katsetamist | taskFit=37%, exploration=10%    |
| `auto/offline` | Mahtu                    | quota=37%, health=28%           |

## Kuidas tõrkeid käsitletakse

OmniRoute'il on **kolm kaitsekihti**:

### 1. Automaatne varuvalik

Kui parim teenusepakkuja ebaõnnestub, proovib OmniRoute automaatselt järgmist. Te ei pea midagi tegema.

### 2. Isetaastumine

Kui teenusepakkuja tõrked jätkuvad:

- **Skoor < 0.2** → jäetakse 5 minutiks välja
- **Kaitselüliti on avatud** → jäetakse automaatselt välja
- **Üle 50% teenusepakkujatest ei tööta** → intsidendirežiim (uurimist ei toimu)

### 3. Hädaolukorra varuvalik

Kui kõik teenusepakkujad ebaõnnestuvad, suunab OmniRoute päringu viimase abinõuna stabiilsetele tasuta teenusepakkujatele (nt Kiro või Qoder).

---

## Mitme konto tugi

Kui teil on sama teenusepakkuja juures mitu kontot (nt kaks OpenAI võtit), käsitleb OmniRoute igaüht **eraldi kandidaadina**. See tähendab järgmist:

- Kontol A on kvooti alles → kasuta seda
- Kontole B rakendub päringusageduse piirang → jäta see vahele
- Konto C on odavam → eelista seda

Iga kontot hinnatakse eraldi selle töökindluse, kvoodi ja kiiruse põhjal.

---

## Bandit-meetodil uurimine

OmniRoute **uurib** aeg-ajalt uusi teenusepakkujaid, et leida paremaid valikuid:

- **Vaikimisi**: 5% päringutest suunatakse juhuslikele teenusepakkujatele
- **Auto/smart**: uurimismäär 10%
- **Keelatud**, kui üle 50% teenusepakkujatest ei ole töökorras

See aitab OmniRoute'il õppida, millised teenusepakkujad sobivad teie kasutusmustritega kõige paremini.

## Levinud küsimused

### „Kas see valib alati kõige kallima mudeli?”

**Ei.** Vaikimisi moodustab hind skoorist ainult 15%. Odav, kiire ja töökindel teenusepakkuja võib kallimat edestada. Kasutage valikut `auto/cheap`, kui soovite hinda veelgi enam prioriseerida.

### „Mis juhtub, kui teenusepakkuja lakkab töötamast?”

OmniRoute jätab selle automaatselt vahele ja proovib järgmist. Kui teenusepakkuja tõrked jätkuvad, jäetakse see ajutiselt välja (5–30 minutiks). Te ei pea midagi tegema.

### „Kas ma näen, millist teenusepakkujat kasutati?”

Kontrollige vastuse päiseid — OmniRoute lisab igale vastusele kasutatud teenusepakkuja ja mudeli.

### „Kas see õpib minu kasutusest?”

Jah! Hindamissüsteem kasutab ajaloolisi andmeid (latentsus, tõrkemäärad, õnnestumismäärad), et teha aja jooksul paremaid otsuseid.

### „Mis vahe on valikutel `auto` ja `auto/smart`?”

- `auto` — tasakaalustatud, 5% uurimist
- `auto/smart` — kvaliteet ennekõike (samad kaalud nagu valikul `auto/coding`), 10% uurimist

Kasutage valikut `auto/smart`, kui soovite parimat kvaliteeti ja teile sobib aeg-ajalt toimuv uurimine.

### „Kas saan sundida kasutama kindlat teenusepakkujat?”

Jah! Kasutage `auto` asemel kombinatsiooni strateegiaga `priority` ja seejärel saatke kombinatsiooni **täpne nimi** väljana `model` (nt `model: "my-combo"` — mitte `auto`). Üksikasju vaadake [tehnilisest teatmikust](../routing/AUTO-COMBO.md).

### „Mille poolest erineb see tsüklilisest jaotusest?”

Tsükliline jaotus käib teenusepakkujad järjekorras läbi. Automaatne kombinatsioon **hindab iga teenusepakkujat** ja valib parima. See on nutikam — arvesse võetakse töökindlust, kiirust, hinda ja kvaliteeti.
