Releed (Vercel, Deno, Cloudflare) katkestavad ülesvooluühenduse
serverivabas taustsüsteemis, et OmniRoute saaks väljuda stabiilsest piirkonnast,
hoides samal ajal teenusepakkuja API-võtme serveripoolel. Selles dokumendis
käsitletakse kaht tõrkerežiimi, millega operaatorid tootmiskeskkonnas kokku
puutuvad, ja OmniRoute'i pakutavaid taasteteid kummagi jaoks.

## Kuidas relee autentimisandmeid talletatakse

Kui juurutate relee menüüst **Settings → Proxy Pool → Deploy Relay**,
talletab juurutusvoog relee autentimistõendi proksi `notes` JSON-väljal:

- Kui `STORAGE_ENCRYPTION_KEY` on määratud, kirjutatakse tõend väljana
  `relayAuthEnc` (puhkeolekus AES-krüpteerituna).
- Vastasel juhul kirjutatakse see lihttekstina väljale `relayAuth`.

Päringu ajal tagastab `extractRelayAuth(notes)` olemasoleva vormi,
mistõttu jätkab relee tööd ka pärast taaskäivitusi.

## Tõrkerežiim 1 — pärast võtme vahetamist dekrüpteerimatu tõend

**Sümptom:** varem töötanud releed tagastavad nüüd ülesvoolu `401`/autentimise
vigu pärast `STORAGE_ENCRYPTION_KEY` vahetamist keskkonnas või
saladuste halduris. Talletatud `relayAuthEnc` plokki ei saa enam dekrüpteerida,
mistõttu tagastab `extractRelayAuth` tühja stringi ja relee ei saada
autentimisandmeid.

**Taastamine — parandamine kohapeal (ilma uuesti juurutamata):**

1. Avage **Settings → Proxy Pool**.
2. Puuduvate autentimisandmetega releeridadel kuvatakse kollane märk
   `auth missing` ja nupp **Repair**.
3. Klõpsake nuppu **Repair**. OmniRoute kutsub välja
   `POST /api/settings/proxies/[id]/repair-relay`, mis:
   - dekrüpteerib `relayAuthEnc` **praeguse** võtmega,
   - kirjutab lihttekstina `relayAuth` tagasi väljale `notes`,
   - tagastab `{ repaired: true, mode: "recovered" }`.

Relee jätkab teenindamist, ilma et juurutamise mandaate peaks uuesti sisestama.

See toimib ainult juhul, kui praegune `STORAGE_ENCRYPTION_KEY` suudab ploki
endiselt dekrüpteerida. Kui vahetasite võtme **ilma** migreerimiseta, ei ole
plokki võimalik taastada.

## Tõrkerežiim 2 — taastamatu tõend (võti on välja vahetatud)

**Sümptom:** klõpsasite nuppu **Repair** ja saite vastuseks
`{ repaired: false, mode: "redeploy", status: 409 }`.

**Taastamine — uuesti juurutamine:**

Talletatud tõendit ei saa praeguse võtmega taastada. Juurutage relee uuesti
sama modaaldialoogi kaudu, mida algselt kasutasite (menüü **Deploy Relay** → Vercel / Deno
/ Cloudflare). Juurutusvoog kirjutab uue tõendi (praeguse võtmega
krüpteerituna) ja rea märk `auth missing` kaob.

Kasutajaliideses avab nupp **Repair** ise uuesti juurutamise modaaldialoogi, kui
tõendit pole võimalik taastada, mistõttu ei pea te seda kunagi käsitsi otsima.

## Tõrkerežiim 3 — relee on kättesaadav, kuid ei tööta korrektselt

**Sümptom:** proksi test (nupp `speed`) näitab, et relee töötab, kuid päringud
nurjuvad endiselt aeg-ajalt.

Kontrollige OmniRoute'i automaattesti sondi tagastatud relee olekuteadlikkuse
päiseid (vt **Settings → Proxy Pool** ning loendureid `relayTested` / `relayAlive`):

- `x-relay-url` — milline relee taustsüsteem vastas.
- `x-relay-mode` — selle päringu puhul `ts` | `bifrost` | `auto`.
- `x-relay-attempts` — mitu releehüpet enne õnnestumist prooviti.
- `x-relay-fallback` — `true`, kui päring suunati eelistatud taustsüsteemist
  tagasi TypeScripti releele.

Suur `x-relay-fallback` määr koos väikese `relayAlive` väärtusega tähendab, et
külgprotsessi taustsüsteem ei tööta korrektselt ja peaksite selle parandama või
vahetama relee taustsüsteemi strateegiaks `ts` (vt `RELAY_BACKEND_STRATEGY.md`).

## API viide

| Meetod | Tee                                       | Keha                    | Õnnestumine                                                                                                                             | Tõrge                                                                        |
| ------ | ----------------------------------------- | ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `POST` | `/api/settings/proxies/[id]/repair-relay` | `{ "id": "<proxyId>" }` | `200 { repaired: true, mode: "recovered" }`, kui tuletati uuesti; `200 { repaired: false, mode: "noop" }`, kui lihttekst on juba olemas | `409 { mode: "redeploy" }` taastamatu; `400` pole releetüüp; `404` ei leitud |

Loendimarsruut `GET /api/settings/proxies` lisab igale üksusele saladusi
mittesisaldava `relayInfo: { isRelay, authMissing, repairMode }`, et juhtpaneel
saaks kuvada parandamisvõimaluse ilma tõendit kordagi avaldamata.
