`@omniroute/opencode-plugin-v2` incorpora todo tu catálogo de OmniRoute —modelos, combos y
combos automáticos— al selector de modelos de OpenCode v2, con nombres para mostrar, precios y
límites del nivel gratuito.

Es un paquete independiente de `@omniroute/opencode-plugin` porque OpenCode v1 y v2 cargan
los plugins mediante contratos diferentes. Elige el que coincida con la versión principal de OpenCode; no se
comparte nada entre ambos, por lo que actualizar uno nunca obliga a actualizar el otro.

## Requisitos

- OpenCode v2.
- Una puerta de enlace de OmniRoute accesible (`http://localhost:20128` de forma predeterminada).
- Node.js 22 o 24.

## Instalación

Añade el plugin a `opencode.json`:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

Los modelos aparecerán como `omniroute/<provider>/<model>`; `providerId` determina ese prefijo y
el id de la integración bajo la cual OpenCode almacena la credencial.

## Credenciales

El plugin busca una clave de la puerta de enlace en tres lugares, en este orden:

1. **La credencial que conectaste en OpenCode.** El plugin registra una integración, por lo que
   el propio flujo de autenticación de OpenCode puede almacenar la clave. Nada se guarda en `opencode.json`; esta es la opción preferida.
2. `apiKey` en las opciones del plugin, para una configuración específica del proyecto. Esto coloca la clave en un archivo que
   podrías estar incluyendo en el repositorio.
3. `OMNIROUTE_API_KEY` en el entorno.

Si no se encuentra ninguna de las tres, el catálogo queda vacío y el plugin lo indica una vez durante el inicio, en lugar de
dejarte con un selector vacío sin ninguna explicación.

### El token de administración es una clave diferente

Los combos, el estado de los proveedores y el enriquecimiento (nombres para mostrar, precios y límites del nivel gratuito) proceden de
los endpoints `/api/*` de la puerta de enlace, que en la mayoría de las implementaciones están protegidos por un token de **administración**
en lugar de la clave de inferencia:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<token de lectura de administración>"
}
```

Si no se configura, `managementReadToken` recurre a `apiKey`. Cuando una puerta de enlace rechaza esa alternativa,
el catálogo sigue publicándose, pero con ids de modelo sin procesar en lugar de nombres para mostrar, sin
deduplicación de alias canónicos, sin precios y sin combos. El plugin muestra una advertencia una vez por endpoint cuando esto sucede,
indicando el endpoint y qué se ha perdido, para que un selector degradado nunca sea un misterio.

## Opciones

| Clave                            | Valor predeterminado                            | Notas                                                                                                                                              |
| -------------------------------- | ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `providerId`                     | `"omniroute"`                                   | Id del proveedor, id de la integración y prefijo bajo el cual aparecen los modelos                                                                 |
| `baseURL`                        | obligatorio                                     | Raíz de la puerta de enlace, solo `http(s)`; el sufijo `/v1` se añade cuando es necesario                                                          |
| `apiKey`                         | credencial conectada, luego `OMNIROUTE_API_KEY` | Clave de chat para `/v1/*`                                                                                                                         |
| `managementReadToken`            | recurre a `apiKey`                              | Clave para `/api/*`; normalmente **no** es la misma                                                                                                |
| `displayName`                    | `"OmniRoute"`                                   | Nombre del proveedor en el selector                                                                                                                |
| `timeoutMs`                      | `10000`                                         | Tiempo de espera de obtención por endpoint (los combos automáticos usan 5 s)                                                                       |
| `modelCacheTtlMs`                | `300000`                                        | TTL de la caché del catálogo; una instantánea en disco agiliza los arranques en frío                                                               |
| `timeouts`                       | recurre a `timeoutMs`                           | Límites por endpoint en ms: `models`, `combos`, `autoCombos`, `enrichment`                                                                         |
| `enrichment`                     | `true`                                          | Obtiene nombres, precios y límites del nivel gratuito                                                                                              |
| `providerTag`                    | `true`                                          | Añade al nombre para mostrar el prefijo del proveedor ascendente al que dirige                                                                     |
| `usableOnly`                     | `false`                                         | Conserva solo los proveedores que la puerta de enlace indica como aprovisionados                                                                   |
| `visibleModels` / `hiddenModels` | `[]`                                            | Listas de permitidos por coincidencia exacta o sufijo; la denegación prevalece                                                                     |
| `geminiSanitization`             | `true`                                          | Elimina de los esquemas de herramientas las palabras clave de JSON Schema que Gemini rechaza (las herramientas con `$ref` se reenvían sin cambios) |
| `apiFormat.allowAnthropic`       | `false`                                         | Dirige los ids incluidos en la lista de permitidos mediante el bloque de la API de Anthropic                                                       |
| `apiFormat.anthropicModels`      | `[]`                                            | Ids completos de modelos dirigidos a Anthropic                                                                                                     |
| `logLevel` / `startupDebug`      | `warn` / `false`                                | Nivel de detalle del registrador                                                                                                                   |

## Cómo se mantiene actualizado el catálogo

El catálogo se obtiene de forma diferida y se almacena en caché durante `modelCacheTtlMs`, mientras que una instantánea en disco mantiene disponible el último catálogo conocido cuando no se puede acceder al gateway; una interrupción no le cuesta nada salvo actualidad. Los modelos y combos se publican en cuanto llegan; los combos automáticos, la lista de proveedores y la capa de enriquecimiento se incorporan cuando están disponibles, de modo que un endpoint lento no pueda bloquear todo el selector.

Los nombres incluyen lo que sabe el gateway: el proveedor ascendente al que se enruta un modelo, un indicador `[Free]` y el presupuesto que lo acompaña, para que dos conexiones que ofrecen el mismo modelo sigan siendo distinguibles. Desactive el prefijo con `"providerTag": false`.

No existe un comando de actualización manual: los comandos de OpenCode v2 son plantillas de prompts, no callbacks, por lo que un plugin no puede exponer uno. Las actualizaciones siguen el TTL; solo se solicita al host que vuelva a cargar cuando el catálogo o la capa de enriquecimiento realmente han cambiado, nunca una vez por actualización.

## Llamadas a herramientas en Gemini

Gemini rechaza cualquier solicitud completa cuyas declaraciones de herramientas contengan `$schema` o `additionalProperties`, y responde con `400 INVALID_ARGUMENT`. El plugin elimina esas palabras clave de los esquemas de herramientas destinados a un modelo Gemini de este proveedor y deja intactas todas las demás solicitudes. Una herramienta que contiene un `$ref` se reenvía intacta en lugar de eliminarlo, ya que quitar la referencia ampliaría el esquema para que «acepte cualquier cosa».
Establezca `"geminiSanitization": false` para desactivarlo.

## Solución de problemas

| Síntoma                                            | Causa                                                                                                                     |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| El selector no muestra ningún modelo de OmniRoute  | No se resolvió ninguna clave (compruebe la advertencia de inicio) o no se puede acceder al gateway                        |
| IDs de modelos sin procesar, sin combos ni precios | Los endpoints de administración rechazaron el token; establezca `managementReadToken`                                     |
| Una sesión fijada a `opencode-<id>/…`              | El plugin v1 publicaba `opencode-<id>`; v2 publica `<id>` sin prefijo, así que vuelva a seleccionar el modelo en `<id>/…` |
