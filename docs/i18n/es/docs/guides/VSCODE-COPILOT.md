**OmniCopilot** incorpora todos los modelos ofrecidos por OmniRoute al selector de modelos _nativo_ de GitHub Copilot Chat. Sin una segunda barra lateral ni una interfaz de chat independiente: el modo agente de Copilot, las llamadas a herramientas, los servidores MCP y las instrucciones personalizadas siguen funcionando, pero se ejecutan en el modelo que elijas.

|                               |                                                                                                                                                 |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Instalar (VS Code)**        | [Marketplace → `diegosouzapw.omnicopilot`](https://marketplace.visualstudio.com/items?itemName=diegosouzapw.omnicopilot)                        |
| **Instalar (forks)**          | [Open VSX](https://open-vsx.org/extension/diegosouzapw/omnicopilot) — Cursor, Windsurf, VSCodium, Theia, code-server, Gitpod, Antigravity, Kiro |
| **Código fuente/incidencias** | [github.com/diegosouzapw/OmniCopilot](https://github.com/diegosouzapw/OmniCopilot) (MIT)                                                        |
| **Requiere**                  | VS Code 1.104+                                                                                                                                  |

> **No se necesita una suscripción a Copilot.** Desde VS Code 1.122, un proveedor de modelos de lenguaje funciona
> sin iniciar sesión en GitHub y sin ningún plan de Copilot. Las finalizaciones en línea y
> las funciones basadas en embeddings quedan fuera de la API del proveedor y siguen requiriendo Copilot.

## Configuración

1. **Ejecuta OmniRoute** — `npm install -g omniroute && omniroute` (panel de control en `http://localhost:20128`).
2. **Instala la extensión** — busca "OmniRoute" en la vista de Extensiones.
3. **Elige un modelo** — Copilot Chat → selector de modelos → **Administrar modelos…** → **OmniRoute** y, después, marca
   los que quieras.

No hay nada que configurar cuando OmniRoute se ejecuta en el puerto predeterminado. Para una instancia remota, abre el
**icono de OmniRoute en la barra de actividad** (o ejecuta `OmniRoute: Manage Connection`) y configura:

- **URL del servidor** — la raíz del servidor, p. ej., `http://192.168.0.15:20128`. La extensión añade
  el sufijo `/v1`; no lo incluyas.
- **Clave de API** — solo cuando el servidor establece `REQUIRE_API_KEY`. Se almacena en el llavero del sistema operativo mediante
  SecretStorage de VS Code, nunca en `settings.json`.

## Qué mostrará el selector

La extensión no muestra la carga útil sin procesar de `GET /v1/models`: le da forma, y el número que
ves es menor que el tamaño del catálogo por dos motivos deliberados.

### Solicita un id por modelo

El valor predeterminado de `MODELS_CATALOG_PREFIX_MODE` es **`dual`**, que anuncia cada modelo dos veces: una
con el prefijo corto del alias y otra con el prefijo canónico del proveedor, para que las configuraciones de clientes
antiguos sigan resolviendo ambas formas:

```
cc/claude-sonnet-4-6        ← prefijo del alias
claude/claude-sonnet-4-6    ← prefijo canónico, mismo modelo
```

La extensión solicita **`GET /v1/models?prefix=alias`** para recibir un id por modelo, sin
cambiar la configuración global del servidor para los demás clientes. En una instancia de referencia, esto redujo
**2345 entradas a 1396: 949 duplicados y ningún modelo perdido.**

Si prefieres solucionarlo en todo el servidor para _todos_ los clientes, establece la marca de función
`MODELS_CATALOG_PREFIX_MODE` en `alias` desde el panel de control. Consulta
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) para conocer el
parámetro de consulta y la tabla de cada modo.

### Oculta los modelos que no pueden chatear

El catálogo también enumera modelos de imagen, vídeo, audio, reranking, embeddings y moderación. De todos modos,
estos se rechazan en las solicitudes de chat:

```
HTTP 400 — El modelo '<id>' es un modelo de generación de imágenes y no se puede utilizar en
/v1/chat/completions. Utiliza POST /v1/images/generations en su lugar.
```

por lo que se filtran mediante su campo `type` antes de llegar al selector. **Los modelos de la API Responses
se conservan**: cada entrada de Codex/GPT-5.x anuncia `supported_endpoints: ["responses"]`,
y OmniRoute las traduce para `/v1/chat/completions`, por lo que pueden utilizarse perfectamente.

### Proveedores que nunca configuraste

El catálogo enumera modelos de proveedores con una **conexión activa**, además de todos los proveedores **noAuth**:
los que no necesitan claves y conforman gran parte del nivel gratuito. Esto es intencionado. Para ocultarlos,
añádelos a `blockedProviders` en la configuración del panel de control; no es necesario cambiar nada en la
extensión.

## Panel de control dentro de una pestaña de VS Code

`omnicopilot.dashboardOpen: "editor"` muestra el panel de control de OmniRoute en una pestaña del editor mediante
Simple Browser en lugar de un navegador externo. La incrustación debe **habilitarse explícitamente en el servidor** mediante
`DASHBOARD_ALLOW_EMBED=vscode`, lo que sirve las páginas HTML con
`frame-ancestors 'self' vscode-webview:` en lugar de los valores predeterminados `frame-ancestors 'none'` +
`X-Frame-Options: DENY`. La superficie de la API (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) mantiene los
encabezados estrictos en ambos casos.

> ⚠️ **Es una opción de compilación, no de tiempo de ejecución.** Next.js compila `headers()` en el manifiesto de
> rutas, por lo que `next.config.mjs` lee la variable mientras se compila el paquete
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> Exportarla antes de iniciar un servidor ya compilado no cambia nada: los encabezados están incorporados.

```bash
# la variable debe estar presente en el comando de COMPILACIÓN
DASHBOARD_ALLOW_EMBED=vscode npm run build        # o npm run build:release
npm start
```

| Cómo se instaló            | ¿Se puede habilitar la incrustación?                                                                                                              |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Desde el código fuente     | ✅ establezca la variable en el comando de compilación, como se muestra arriba                                                                    |
| `npm install -g omniroute` | ❌ el paquete publicado incluye un paquete precompilado; compile desde el código fuente                                                           |
| Imagen de Docker           | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — la imagen precompilada de Docker Hub no permite la incrustación |

Sin una compilación que permita la incrustación, la página rechaza mostrarse en un marco; la extensión lo detecta mediante los
encabezados de respuesta y recurre al navegador externo. Nada deja de funcionar y se informa de ello una vez.
Consulte [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) y la incidencia
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273).

## Configuración de otras herramientas desde VS Code

**`OmniRoute: Configure Coding CLI`** utiliza la CLI `omniroute` para crear perfiles listos para usar
para Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code,
Kilo y Roo: las mismas configuraciones descritas en
[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md). La clave de API se proporciona a la CLI mediante la
variable de entorno `OMNIROUTE_API_KEY`, nunca en la línea de comandos.

## Solución de problemas

| Síntoma                                                               | Causa / solución                                                                                                                                                                                                                                                                                                                       |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No hay modelos de OmniRoute en el selector                            | No se puede acceder al servidor. El punto de la barra de estado se vuelve gris; ejecute `OmniRoute: Check Connection`. La detección es silenciosa por diseño y no aporta ningún modelo en lugar de mostrar una solicitud.                                                                                                              |
| Cada modelo aparece dos veces                                         | Está usando una versión de OmniCopilot anterior a 1.0.1; actualícela. Ahora la extensión solicita `?prefix=alias`.                                                                                                                                                                                                                     |
| Un modelo de imagen/audio que aparecía ya no está                     | Es intencionado desde 1.0.1: nunca podía responder a una solicitud de chat.                                                                                                                                                                                                                                                            |
| Falta el panel en la barra de actividades                             | VS Code mueve los contenedores de vistas adicionales al menú de desbordamiento **"…"** situado en la parte inferior de la barra de actividades, y los contenedores ocultos mediante clic derecho permanecen ocultos. Haga clic derecho en la barra de actividades → marque **OmniRoute**, o ábralo con `OmniRoute: Manage Connection`. |
| El panel de control se abre en el navegador a pesar del modo `editor` | El servidor no se **compiló** con `DASHBOARD_ALLOW_EMBED=vscode` (consulte más arriba); configurarlo al iniciar una instalación precompilada no tiene ningún efecto. El mecanismo alternativo es intencionado.                                                                                                                         |
| La lista de modelos está obsoleta tras cambiar de proveedores         | Ejecute `OmniRoute: Refresh Models` o use el enlace ↻ del panel.                                                                                                                                                                                                                                                                       |
