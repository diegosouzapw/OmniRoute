## 1. Antigravity frente a Antigravity CLI (agy)

Ambos proveedores comparten el **mismo backend de Google**: cliente OAuth, renovación de tokens, endpoints y cuentas de Google idénticos. La diferencia radica en los modelos que puedes ver.

> Consulta el [anuncio de Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli) para ver la comparación oficial de Google.

| Aspecto                        | `antigravity` (IDE)                                   | `agy` (CLI)                                                             |
| ------------------------------ | ----------------------------------------------------- | ----------------------------------------------------------------------- |
| **Producto de Google**         | Antigravity 2.0 / Antigravity IDE                     | Antigravity CLI                                                         |
| **Backend**                    | La misma API de Google Cloud Code                     | La misma API de Google Cloud Code                                       |
| **OAuth / Token**              | El mismo cliente y la misma renovación                | El mismo cliente y la misma renovación                                  |
| **Catálogo de modelos**        | Lista seleccionada estática (codificada en OmniRoute) | Consultado en tiempo real desde Google mediante `:fetchAvailableModels` |
| **Modelos Claude**             | Sonnet 4.6, Opus 4.6 (4 variantes de cada uno)        | Sonnet 4.6, Opus 4.6 (4 variantes de cada uno)                          |
| **Nomenclatura de Gemini**     | Etiquetas claras (Low/Medium/High)                    | IDs del proveedor (extra-low/low/agent)                                 |
| **Modelos adicionales**        | `gpt-oss-120b-medium`                                 | Puede incluir modelos adicionales de Google                             |
| **Caso de uso predeterminado** | Integración con IDE (VS Code, JetBrains)              | Acceso mediante CLI / API                                               |
| **Cuota**                      | Compartida con agy (misma cuenta de Google)           | Compartida con antigravity (misma cuenta de Google)                     |

**Modelos disponibles (verificados mediante experimentación, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (varios niveles de razonamiento)
- Claude: Sonnet 4.6, Opus 4.6 (cada uno con variantes default/low/medium/high)
- Otros: GPT-OSS 120B Medium
- **Claude Sonnet 5 NO está disponible** — solo se admiten las variantes 4.6

**Por qué difiere el catálogo de modelos**: La CLI de Google está «optimizada para ofrecer velocidad y una baja sobrecarga» y «cooptimizada con los modelos Gemini» (según el blog oficial de Google). El producto web/IDE está «optimizado para ofrecer exhaustividad». La CLI utiliza `:fetchAvailableModels` para descubrir modelos dinámicamente, mientras que el IDE utiliza una lista seleccionada estática.

**En la práctica**: Usa el prefijo `agy/` para los modelos Gemini (por ejemplo, `agy/gemini-3.7-flash-high`). Usa `antigravity/` para la lista seleccionada estática. Ambos utilizan el mismo backend de Google, pero exponen una nomenclatura de modelos diferente. La cuota es compartida: el uso de cualquiera de los proveedores se contabiliza en los límites de la misma cuenta de Google.

## 2. Google One AI Pro: Sistema de cuotas

> Consulta [Documentación de Antigravity: Planes](https://antigravity.google/docs/plans) para obtener los detalles oficiales sobre las cuotas y [Cambios en los planes de Antigravity](https://antigravity.google/blog/changes-to-antigravity-plans) para conocer las últimas actualizaciones de precios.

Google Antigravity utiliza una **cuota de doble nivel** basada en el «trabajo realizado» (peso computacional), no en el número de mensajes.

### Los dos niveles

| Nivel                | Qué es                                 | Ciclo de renovación                                                                                  |
| -------------------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| **Tramo de 5 horas** | Fondo inmediato de «trabajo realizado» | Se restablece 5 horas después de la primera solicitud de una sesión                                  |
| **Base de 7 días**   | Límite máximo semanal                  | Anula la renovación de 5 horas si se alcanza; bloquea el acceso hasta el siguiente período de 7 días |

**Cómo se calcula el «trabajo realizado»**: Las tareas que requieren un uso intensivo de agentes (p. ej., «Refactoriza todo este repositorio») consumen la cuota mucho más rápido que las tareas sencillas (p. ej., «Corrige esta función»). No existe un panel en tiempo real que muestre el consumo.

### Niveles de los planes

| Plan         | Precio      | Cuota                                      | Límite semanal                         |
| ------------ | ----------- | ------------------------------------------ | -------------------------------------- |
| Gratuito     | $0          | Cuota considerable, renovada semanalmente  | Sí                                     |
| AI Pro       | $19.99/mes  | Cuota alta, renovación continua de 5 horas | Sí (anula la de 5 horas si se alcanza) |
| AI Ultra 5x  | $99.99/mes  | 5x la cuota de Pro                         | Sin límite semanal                     |
| AI Ultra 20x | $199.99/mes | 20x la cuota de Pro                        | Sin límite semanal                     |

### Modelos Gemini frente a modelos que no son Gemini

- **Modelos Gemini** (Flash + Pro): Comparten un único límite de frecuencia, cuyo consumo se basa en los precios de la API. Si Flash es 8x más barato que Pro, obtienes 8x más tokens de Flash.
- **Modelos que no son Gemini** (Claude, GPT-OSS): Tienen límites de frecuencia **independientes**. Es posible que sigan disponibles incluso cuando Gemini esté bloqueado.

### Créditos de IA (uso excedente)

> Consulta [Créditos de IA de Google One](https://support.google.com/googleone/answer/14534406) para saber cómo funcionan los créditos.

Cuando se agota la cuota base:

- **Nunca**: Espera a que la cuota se renueve; muestra «Se alcanzó la cuota base del modelo»
- **Siempre**: Usa automáticamente los créditos de IA; vuelve a la cuota base cuando esta se renueva

Los créditos se compran por separado y se descuentan según los precios estándar de la API.

### Detalles clave

- La cuota se **comparte a nivel de cuenta**: la misma cuenta de Google en el IDE de Antigravity, la CLI y OmniRoute comparte un único fondo de cuota
- Cada cuenta de Google tiene su propia cuota independiente: varias cuentas = varios fondos de cuota
- Los usuarios de AI Pro han informado de **bloqueos de 7 días** en lugar de restablecimientos cada 5 horas cuando se alcanza la base semanal (Google ha confirmado que esto es intencionado debido a la alta demanda)

**Cuando se agota la cuota de tu cuenta**: OmniRoute vuelve a intentarlo automáticamente con la siguiente cuenta disponible en la ruta combinada. No se requiere ninguna intervención manual.

## 3. Cómo obtener un projectId

Cada conexión antigravity/agy necesita un `projectId` de Google Cloud Code. Sin él, el endpoint `/v1internal:models` devuelve un error 404.

### Método A: Automático (recomendado)

OmniRoute se encarga de esto automáticamente. Cuando añades una nueva cuenta de Google mediante OAuth en el panel:

1. OmniRoute renueva el token
2. Llama a `loadCodeAssist` para descubrir el projectId
3. Si no existe ningún proyecto, llama a `onboardUser` para crear uno
4. Vuelve a intentar `loadCodeAssist` para obtener el projectId recién creado
5. Lo guarda en la base de datos

**Esto funciona para la mayoría de las cuentas**; no se requiere ningún paso manual.

### Método B: Manual mediante la CLI de agy

Si el descubrimiento automático falla (consulta la Sección 5 para saber cuándo sucede):

```bash
# Instala la CLI de agy (si aún no está instalada)
npm install -g @anthropic-ai/agy

# Inicia sesión con tu cuenta de Google
agy login

# Selecciona la cuenta que necesita completar la incorporación
# Esto activa el registro de Cloud Code y asigna un projectId
```

Después de que `agy login` se complete correctamente, renueva el token en el panel de OmniRoute. El projectId se descubrirá automáticamente.

### Cómo verificarlo

Comprueba la base de datos:

```bash
# Dentro del contenedor de OmniRoute
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

O comprueba los registros:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. URI de redirección de OAuth

### El problema

Google OAuth requiere un URI de redirección válido. OmniRoute utiliza de forma predeterminada `http://127.0.0.1:20128/callback` (bucle invertido). Esto funciona para compilaciones locales, pero **falla en implementaciones remotas** (por ejemplo, un servidor al que se accede mediante una IP de la LAN).

Google rechaza los URI de redirección que:

- Utilizan direcciones IP (debe ser un dominio terminado en `.com`, `.org`, etc.)
- No coinciden con los URI de redirección registrados en la configuración del cliente OAuth

### La solución

**Opción A: Usar el flujo de OAuth integrado (predeterminado)**

- Funciona cuando accedes a OmniRoute desde `localhost` o `127.0.0.1`
- No requiere configuración

**Opción B: Credenciales de OAuth personalizadas**

- Configura `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` en tu entorno
- Proporciona tus propias credenciales de Google OAuth:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Registra `https://your-domain.com/callback` como URI de redirección autorizado en Google Cloud Console

**Opción C: Usar la CLI agy para el inicio de sesión inicial**

- Ejecuta `agy login` en la máquina que accederá a OmniRoute
- El flujo de OAuth se completa localmente y los tokens se almacenan
- Importa la conexión en OmniRoute mediante el Dashboard

### Limitaciones

- Las credenciales de OAuth personalizadas requieren un nombre de dominio (Google no acepta direcciones IP como URI de redirección)
- Si no tienes un dominio, utiliza la opción A o C

## 5. Solución de problemas: cuando falla la configuración automática

OmniRoute gestiona automáticamente la detección de projectId y la incorporación para la mayoría de las cuentas. Cuando falla, la causa principal suele ser una de las siguientes:

### La región de la cuenta está bloqueada

**Síntoma**: `agy login` devuelve "Eligibility check failed: Your current account is not eligible for Antigravity, because it is not currently available in your location."

**Causa principal**: Las cuentas de Google tienen un campo interno "Country Association" que se establece en el momento del registro. La CLI agy y la API de Cloud Code verifican estrictamente este campo, a diferencia de Gemini en la web, que solo comprueba tu IP actual.

> Para consultar o cambiar la región asociada a tu cuenta, visita el [Formulario de asociación de país de Google](https://policies.google.com/country-association-form).

**Por qué Gemini en la web funciona, pero agy no**:

- Gemini en la web / Google One: solo comprueba la IP actual (el proxy funciona)
- CLI agy / API de Cloud Code: consulta el campo interno Country Association (el proxy no ayuda)

**Solución**:

1. Visita el [Formulario de asociación de país de Google](https://policies.google.com/country-association-form) mientras utilizas una IP de EE. UU.
2. Envía una solicitud de cambio de región (selecciona "I live in a different country")
3. Espera entre 1 y 24 horas para que Google procese la solicitud y envíe una notificación por correo electrónico
4. Después, `agy login` debería completarse correctamente

### La cuenta no tiene un proyecto de Cloud Code

**Síntoma**: Los registros muestran `loadCodeAssist returned no project id` y `onboardUser failed (400)`.

**Causa principal**: La cuenta nunca se ha registrado en Google Cloud Code y la incorporación automática ha fallado.

**Solución**: Ejecuta `agy login` manualmente para iniciar el registro en Cloud Code y, a continuación, actualiza el token en el Dashboard de OmniRoute.

### El token ha caducado o ha sido revocado

**Síntoma**: Errores 401 en los registros o mensajes "Token has expired".

**Solución**: Actualiza el token en Dashboard → Providers → agy → Haz clic en el icono de actualización. Si el propio token de actualización ha sido revocado, tendrás que volver a autenticarte mediante OAuth.

## Diagrama de flujo de decisiones

```
¿La cuenta no funciona?
│
├─ ¿Tiene un projectId en la base de datos?
│  ├─ SÍ → El problema está en otro lugar (token caducado, límite de solicitudes, etc.)
│  └─ NO ↓
│
├─ ¿La Asociación de país de la cuenta está configurada en una región restringida?
│  ├─ SÍ → Cambia la región en el formulario de Asociación de país de Google
│  │         (https://policies.google.com/country-association-form)
│  │         Espera entre 1 y 24 horas y vuelve a intentarlo
│  └─ NO ↓
│
├─ ¿La cuenta tiene una suscripción a Google One AI Pro?
│  ├─ NO → Suscríbete primero en one.google.com
│  └─ SÍ ↓
│
├─ Intenta la detección automática (actualiza el token en el Panel)
│  ├─ Funciona → Listo
│  └─ Sigue fallando ↓
│
└─ Método manual: ejecuta `agy login` en la máquina
   ├─ Funciona → Actualiza el token en el Panel; se detectará el projectId
   └─ Falla → Revisa el mensaje de error; probablemente sea un problema de región o suscripción
```
