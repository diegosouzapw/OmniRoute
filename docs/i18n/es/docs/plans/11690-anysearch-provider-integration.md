## 1. Información de referencia del servicio (documentación oficial, cotejada)

- URL base: `https://api.anysearch.com` (REST) + `POST /mcp` (MCP, JSON-RPC 2.0).
- `POST /v1/search` - parámetros: `query` (obligatorio), `max_results` (1-10, valor predeterminado 10), `tag` (`{domain}.{sub_domain}` para enrutamiento vertical), `zone` (cn/intl), `language`, `params` (campos verticales estructurados), `format` (json/markdown).
- `GET /v1/sub-domains?domain=...` - catálogo de capacidades; NO se contabiliza en la cuota.
- `POST /v1/extract` - obtiene/extrae `{url, title, content}`; cuerpo JSON estricto, límite de 16 KiB.
- `POST /v1/auth/email/register` - registro con una sola llamada; devuelve una clave de texto sin formato de un solo uso `as_sk_...`.
- Autenticación: `Authorization: Bearer <as_sk_...>` opcional; el acceso anónimo queda sujeto a límites por IP que consumen la cuota gratuita diaria; una clave no válida devuelve 401/403 SIN recurrir silenciosamente al acceso anónimo.
- Nivel gratuito: 1000 solicitudes/día, 20 QPS por clave. Nivel de pago: sin precio (Próximamente).
- Estructura de la respuesta: éxito `{code: 0, message: "success", request_id, data}`; error `{code: -1, message}`. Los errores de autenticación/cuota no incluyen un `error_code` estructurado (el texto del mensaje es la señal); los errores específicos de extracción sí incluyen `error_code` (`invalid_extract_url`, `extract_failed`). No se incluye la cabecera `Retry-After` en las respuestas 429.

## 3. Decisiones (todas tomadas el 2026-08-26)

1. **Estrategia de enrutamiento: `fallbackOnly`.** Justificación: un proveedor gratuito con coste 0 nunca debe dominar el enrutamiento automático por coste; la selección explícita y el retorno tras una conmutación por error no se ven afectados. Precedente: entrada de xquik fusionada.
2. **Alcance: webSearch + webFetch mediante `POST /v1/extract` en v1.** En consonancia con el modelo mental de doble capacidad de tavily/exa. Las superficies verticales (`tag`, `sub-domains`, `batch_search`) quedan fuera del alcance: actualmente no existe una IR para parámetros verticales.
3. **Visualización de la cuota: `freeMonthlyQuota: 0`** (visualización conservadora al estilo de xquik). La asignación real (1000 solicitudes/día, con restablecimiento diario) se indica en el texto de `authHint` del catálogo de la interfaz de usuario. Justificación: la visualización de la cuota debe coincidir con la semántica de restablecimiento; convertir un límite diario en un equivalente mensual (30000) es una promesa falsa que la interfaz de usuario no puede cumplir.
4. **searchTypes: `["web"]` únicamente.** No hay evidencia pública de una vertical de noticias/imágenes en la API de AnySearch; las pasarelas que integran APIs sin una vertical documentada (p. ej., Google Custom Search) exponen únicamente la web en lugar de asignar silenciosamente noticias -> web.
5. **Estrategia de claves:** funciona sin clave; una clave no válida devuelve 401/403 y nunca se degrada silenciosamente al acceso anónimo (refleja el contrato del servicio de origen).
6. **Exclusiones deliberadas:** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (la interceptación del chat sigue usando firecrawl/jina/tavily); `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (los endpoints remotos anónimos comparten un único grupo limitado por IP para cada IP de salida, por lo que la extracción sin clave requiere activación explícita y no es candidata para el enrutamiento automático); `QUOTA_STATUS_PROVIDERS` (AnySearch indica la cuota mediante 429/sobre, no mediante el estado 402/403).
