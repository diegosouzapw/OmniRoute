La compresión Caveman puede cargar paquetes de reglas específicos de cada idioma además de las reglas integradas en inglés.
Esto mantiene estable el motor principal y permite que los paquetes de portugués, español, alemán, francés, italiano, japonés y
futuros idiomas evolucionen de forma independiente.

## Ubicación

Los paquetes de idiomas se encuentran en:

```txt
open-sse/services/compression/rules/<language>/
```

Paquetes incluidos actualmente (verificados con el contenido del directorio `rules/`):

| Idioma             | Directorio     | Categorías de reglas presentes                      |
| ------------------ | -------------- | --------------------------------------------------- |
| Inglés             | `rules/en/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Español            | `rules/es/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Portugués (Brasil) | `rules/pt-BR/` | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Indonesio          | `rules/id/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Italiano           | `rules/it/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Alemán             | `rules/de/`    | `context`, `filler`, `structural`                   |
| Francés            | `rules/fr/`    | `context`, `filler`, `structural`                   |
| Japonés            | `rules/ja/`    | `context`, `filler`, `structural`                   |

> **Nota de paridad:** Los paquetes `en`, `es`, `pt-BR`, `id` e `it` incluyen las 5 categorías completas; `de`, `fr` y `ja` incluyen 3 categorías. Las categorías `dedup` y `ultra` que faltan recurren silenciosamente a las reglas integradas en inglés. Se agradecen contribuciones para añadir `dedup.json` y `ultra.json` a los paquetes más pequeños.
>
> El paquete `pt-BR` está basado en **[Troglodita](https://github.com/leninejunior/troglodita)** de Lenine Júnior, un sistema de compresión diseñado desde cero para la gramática del portugués brasileño (reducción de pleonasmos, eliminación de muletillas de PT-BR y abreviaturas técnicas para la comunidad brasileña de desarrollo).
>
> La lista canónica de categorías y el esquema de cada categoría se encuentran en [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) (borrador 2020-12 de JSON Schema).

## Detección de idioma

`languageDetector.ts` utiliza heurísticas ligeras para inferir el idioma a partir del texto de la instrucción. Se sigue respetando el
idioma predeterminado configurado, y la detección puede desactivarse mediante la configuración cuando se requiere un control
exacto.

El resultado de la detección solo se utiliza para elegir los paquetes de reglas. No modifica el enrutamiento del proveedor, la
selección de configuración regional ni el idioma de la interfaz de usuario.

## Estructura de configuración

La configuración de compresión puede incluir:

```json
{
  "languageConfig": {
    "enabled": true,
    "defaultLanguage": "en",
    "autoDetect": true,
    "enabledPacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  },
  "cavemanConfig": {
    "language": "en",
    "autoDetectLanguage": true,
    "enabledLanguagePacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  }
}
```

`languageConfig` controla los valores predeterminados del panel y de la vista previa. `cavemanConfig` es la configuración del motor en tiempo de ejecución
que se utiliza cuando Caveman comprime el texto de los mensajes.

## Añadir un paquete de idioma

1. Crea `open-sse/services/compression/rules/<language>/<pack>.json`.
2. Usa el formato de reglas Caveman de `docs/compression/COMPRESSION_RULES_FORMAT.md`.
3. Mantén los reemplazos conservadores y evita modificar código, identificadores, URLs o JSON.
4. Añade o actualiza las pruebas del comportamiento de selección de idioma y reemplazo.
5. Expón nuevas etiquetas del panel/i18n si el idioma aparece en los selectores de la interfaz de usuario.

## API

Los paquetes disponibles se pueden consultar con:

```bash
curl http://localhost:20128/api/compression/language-packs
```

El endpoint de vista previa acepta anulaciones de la configuración de idioma:

```bash
curl -X POST http://localhost:20128/api/compression/preview \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "standard",
    "text": "Por favor, eu gostaria que voce basicamente resumisse isso.",
    "config": {
      "languageConfig": {
        "defaultLanguage": "pt-BR",
        "autoDetect": true
      }
    }
  }'
```

## SHARED_BOUNDARIES (v3.8.0)

Los 6 paquetes de idioma recibieron una cláusula `SHARED_BOUNDARIES` en v3.8.0 que se aplica en cada
nivel de intensidad de Caveman (LITE, FULL, ULTRA). Esta indica al motor que debe conservar literalmente estos patrones,
independientemente de la eliminación del texto de relleno circundante:

| Tipo de patrón                           | Ejemplo                                |
| ---------------------------------------- | -------------------------------------- |
| Bloques de código delimitados            | ` ```python\n...\n``` `                |
| Código en línea                          | `` `my_var` ``                         |
| URLs                                     | `https://example.com/path`             |
| Rutas de archivo (absolutas + relativas) | `/etc/hosts`, `./src/index.ts`         |
| Encabezados de error                     | `Error:`, `TypeError:`, `SyntaxError:` |
| Líneas de seguimiento de pila            | `  at functionName (file.ts:12:3)`     |

Estos patrones se incluyen en `DEFAULT_CAVEMAN_CONFIG.preservePatterns` (anteriormente `[]`). La
constante se encuentra en `open-sse/services/compression/types.ts`.

### Por qué esto es importante

Sin SHARED_BOUNDARIES, los modos agresivos de Caveman podrían eliminar contenido que pareciera prosa
repetitiva, pero que en realidad fuera un fragmento de código, una ruta de archivo o una pila de errores. SHARED_BOUNDARIES actúa como una
red de seguridad independiente del idioma que se aplica antes de ejecutar las reglas de texto de relleno.

### Personalizar preservePatterns

Se pueden añadir patrones adicionales durante la ejecución mediante la configuración de compresión:

````json
{
  "cavemanConfig": {
    "preservePatterns": [
      "```[\\s\\S]*?```",
      "`[^`]+`",
      "https?://\\S+",
      "(?:/|\\./)[^\\s]+",
      "\\b(?:Error|TypeError|SyntaxError|RangeError):",
      "\\s+at\\s+\\S+\\s+\\(\\S+:\\d+:\\d+\\)"
    ]
  }
}
````

Los patrones personalizados amplían (no reemplazan) los 6 valores predeterminados.

## Notas operativas

- Las reglas integradas en inglés siguen siendo la alternativa cuando falta un paquete de idioma.
- Los paquetes JSON integrados no válidos no superan la validación, para evitar que los recursos de la versión se degraden silenciosamente.
- Los paquetes de reglas solo contienen datos y no deben importar código ni ejecutar lógica arbitraria.
- La capa de análisis de compresión registra el modo y el motor seleccionados, no el texto completo del prompt.
