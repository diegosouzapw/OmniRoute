La puerta de enlace ascendente `agentrouter` ejecuta un filtro de contenido basado en palabras clave sobre
`messages[].content`. El filtro es parcialmente determinista (siempre bloquea
determinadas frases) y parcialmente probabilístico (sensible a ráfagas: se vuelve
más agresivo después de solicitudes rápidas y se recupera tras un período de espera).

Cuando el WAF bloquea una solicitud, devuelve:

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## Alcance del filtro

El WAF inspecciona únicamente `messages[].content`. **No** inspecciona:

- El prompt `system`
- Bloques de contenido estructurado (`tool_result`, `tool_use`, `thinking`, `image`)
- Los campos `description` e `input_schema` de las herramientas
- Los metadatos de la solicitud, los encabezados ni el id del modelo

## Patrones que siempre se bloquean (sin distinguir mayúsculas y minúsculas)

| Patrón                              | Notas                                                     |
| ----------------------------------- | --------------------------------------------------------- |
| Cualquier variante de `Lorem ipsum` | Se bloquea todo el vocabulario latino de lorem            |
| `language model` (solo)             | "the language model" y "large language model" se permiten |
| `virtual assistant`                 | "AI assistant" se permite                                 |
| `I'm here to help`                  | "here to help" por sí solo también se bloquea             |
| `Claude, made by Anthropic`         | Solo la frase completa                                    |

## Patrones que casi siempre se bloquean

| Patrón                                                    | Notas                                                   |
| --------------------------------------------------------- | ------------------------------------------------------- |
| `placeholder`                                             | Cuando aparece solo (no como nombre de parámetro, etc.) |
| `dummy data`                                              | Frase semilla habitual para datos de prueba             |
| `foo bar baz`                                             | Frase de marcador de posición canónica                  |
| Tokens cortos repetidos (`AAA BBB CCC`, `test test test`) | Detector de saturación de palabras clave                |

## Comportamiento bajo carga

Después de unas 5 solicitudes rápidas en un intervalo breve, el WAF comienza a bloquear contenido
que normalmente se permitiría. El depósito se relaja después de unos 5–10 segundos de
inactividad. Este es el mismo limitador de velocidad vinculado a la IP y a la clave que provoca
errores intermitentes `400 content-blocked` cuando Claude Code o Codex CLI
realizan varias llamadas de uso de herramientas o envío de mensajes en una sucesión rápida.

## Mitigaciones ya aplicadas en OmniRoute

1. **`open-sse/services/wafRateLimit.ts`** — protección contra ráfagas que impone un
   intervalo mínimo de 500 ms entre solicitudes salientes a cualquier URL `agentrouter:*`.
   El intervalo está muy por debajo de la percepción humana de latencia y evita
   que el WAF se active con tráfico normal.

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — cuando un servicio ascendente devuelve
   `400 content-blocked`, el ejecutor vuelve a intentar la misma URL con
   retroceso exponencial (1,5 s, 3,0 s, máximo 2 intentos). Después del retroceso,
   el WAF suele relajarse y el reintento se completa correctamente.

3. **`tests/unit/compression/harness.test.ts`** — los datos de prueba
   `longInput` se cambiaron de `"lorem ipsum dolor sit amet ".repeat(40)`
   a `"example content for testing purposes ".repeat(40)` para que, cuando
   Claude Code lea este archivo mediante la herramienta `Read`, el contenido del archivo
   no vuelva a pasar por un bloque `tool_result` y active el WAF.

## Recomendaciones para prompts y resultados de herramientas

Si una sesión de Claude Code o Codex CLI recibe repetidamente
`400 content-blocked`, compruebe si el mensaje de usuario más reciente y el
resultado de herramienta más reciente contienen alguno de los patrones anteriores y reformúlelos. Soluciones
habituales:

- Sustituya `Lorem ipsum …` por `example text …` o por el contenido real
  que la prueba o los datos de prueba intentan representar.
- Sustituya `placeholder` (cuando aparezca solo) por `example value`,
  `sample value` o por el valor real.
- Sustituya `language model` por `large language model` o `the model`.
- Sustituya `dummy data` por `sample data` o por valores semilla realistas.
- Sustituya `I'm here to help` / `here to help` por una introducción más específica
  (p. ej., "Revisaré el archivo que mencionaste").

## Notificación de falsos positivos al proveedor ascendente

El filtro actual es excesivamente agresivo: bloquea "Lorem ipsum" en
bloques `tool_result`, aunque claramente el operador no pretendiera
inyectar un prompt. Los operadores que quieran que esto se corrija en el origen deben
ponerse en contacto con `agentrouter.org` para informar de los falsos positivos. La lista de bloqueo
anterior es el resultado empírico de sondear el servicio ascendente a fecha de 2026-08-03.
