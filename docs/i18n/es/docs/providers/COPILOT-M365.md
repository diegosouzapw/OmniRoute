`copilot-m365-web` (alias `m365copilot`) envía solicitudes de chat en formato OpenAI mediante una
sesión autenticada del navegador de Microsoft 365 Copilot BizChat en
`m365.cloud.microsoft/chat`. Esta es una integración no oficial.

> **¿Es la primera vez que utiliza proveedores de cookies web?**
>
> Lea **`docs/getting-started/WEB-COOKIE-GUIDE.md`** para conocer el proceso general de configuración, las indicaciones de autenticación, las limitaciones y la resolución de problemas antes de seguir esta guía específica del proveedor.
>
> **Importante:** La credencial de este proveedor **no es una cookie**. No copie
> cookies de `m365.cloud.microsoft`. La credencial consta de un parámetro de consulta de una URL de WebSocket
> y un segmento de ruta, ambos obtenidos desde la pestaña Network de DevTools.

## Requisitos previos

- Una cuenta de Microsoft 365 con acceso a BizChat en `m365.cloud.microsoft/chat`
- Un navegador basado en Chromium (Chrome, Edge) para inspeccionar WebSockets mediante DevTools
- Una licencia de M365 Copilot (incluida en muchos planes Microsoft 365 Business/Enterprise)

## Obtención de credenciales (método WebSocket)

1. Inicie sesión en `https://m365.cloud.microsoft/chat` e inicie una conversación.
2. Abra **DevTools → Network**.
3. Filtre por **WS** (WebSocket).
4. Haga clic en la conexión WebSocket de Chathub. Busque una URL que comience por
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Desde su **Request URL**, copie:
   - El valor del parámetro de consulta `access_token` (un JWT de corta duración).
   - El segmento de la ruta de Chathub situado después de `/Chathub/` (p. ej., `<oid>@<tenant>`).

La URL completa tiene el siguiente formato:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. En OmniRoute, vaya a **Providers → Add Provider**, seleccione **Microsoft 365 Copilot
   (BizChat)** y pegue la credencial con el siguiente formato:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Haga clic en **Test Connection** y **Save**.

## Obtención de credenciales (importación de HAR)

En lugar de copiar manualmente los valores de la URL de WebSocket, puede exportar un archivo HAR
desde DevTools:

1. Abra **DevTools → Network**.
2. Inicie o continúe una conversación de BizChat (esto activa la conexión WebSocket).
3. Haga clic con el botón derecho en el panel Network y seleccione **Save all as HAR with content**.
4. En OmniRoute, utilice el botón **Import .har file** del cuadro de diálogo de conexión del proveedor.

OmniRoute examina el HAR en busca de la URL de WebSocket de Chathub, extrae
`access_token` y `chathubPath`, y rellena automáticamente los campos de credenciales. La
importación del HAR descodifica la caducidad del JWT y muestra el tiempo de validez restante del token.

> **Nunca confirme en un repositorio una exportación HAR real, un token de acceso ni un token de actualización.** Los valores de prueba y
> documentación siempre deben ser marcadores de posición.

## Duración y actualización del token

El `access_token` tiene una duración breve (normalmente **~75 minutos**). Tras caducar, el proveedor
informa de un error de conexión y debe volver a obtener la credencial.

### Actualización automática con `refreshToken`

Para evitar tener que volver a obtenerla manualmente, puede almacenar un token de actualización de Microsoft en
**Advanced Settings → providerSpecificData** de la conexión:

| Campo          | Descripción                                                                            |
| -------------- | -------------------------------------------------------------------------------------- |
| `refreshToken` | Token de actualización OAuth de Microsoft para el ámbito `substrate.office.com/sydney` |
| `tier`         | `individual` (predeterminado), `edu` o `enterprise`                                    |

Obtenga el token de actualización mediante un flujo de código de dispositivo o de código de autorización de Microsoft
con el ámbito `substrate.office.com/sydney`. Con `refreshToken` configurado, OmniRoute
actualiza previamente el `access_token` antes de cada solicitud, por lo que no es necesario
volver a obtenerlo tras cada caducidad de ~75 minutos.

Si `refreshToken` no está configurado, deberá volver a obtener manualmente la credencial de WebSocket
después de cada caducidad.

### Selección del nivel

| Nivel        | Alias              | Superficie                     |
| ------------ | ------------------ | ------------------------------ |
| `individual` | _(predeterminado)_ | M365 Copilot para consumidores |
| `edu`        | `included`         | M365 Copilot para educación    |
| `enterprise` | `work`             | M365 Copilot para el trabajo   |

Configure el nivel en **Advanced Settings → providerSpecificData → tier**. El nivel afecta
al enrutamiento de BizChat y al acceso a los modelos.

## Modelo de seguridad

- **Integración no oficial.** Este proveedor aplica ingeniería inversa al protocolo
  WebSocket de BizChat. Puede dejar de funcionar sin previo aviso cuando Microsoft cambie el endpoint.
- La opción `subscriptionRisk: true` refleja que la integración depende de un
  endpoint no documentado. Es posible que se apliquen restricciones a la cuenta, aunque no está confirmado.
- El token de acceso es un JWT de corta duración. Trátelo como una contraseña: no lo incluya en commits,
  no lo registre ni lo comparta.
- El token de actualización otorga acceso a largo plazo a la interfaz de BizChat. Guárdelo con el
  mismo cuidado que una clave de API.

## Solución de problemas

### La autenticación falla inmediatamente

- Verifique que lo haya copiado de la **URL de WebSocket**, no de una solicitud XHR/Fetch. La
  credencial se encuentra en el parámetro de consulta `access_token` de la conexión WebSocket
  de Chathub, no en un encabezado `Authorization: Bearer`.
- Asegúrese de que `chathubPath` incluya el segmento completo `<oid>@<tenant>` de la ruta
  de la URL.

### El token caduca después de unos 75 minutos

Esto es normal. Sin un `refreshToken`, el token de acceso tiene una duración limitada. Puede:

- Volver a capturar la credencial desde DevTools, o
- Configurar un `refreshToken` en Configuración avanzada para que se actualice automáticamente.

### La prueba de conexión se supera, pero el chat devuelve 401

Es posible que el token haya caducado entre la validación y la primera solicitud. Vuelva a capturar una
credencial nueva.

### Copilot no aparece en la lista de proveedores

Asegúrese de que `copilot-m365-web` esté habilitado en **Panel de control → Proveedores**. Es posible que el proveedor
esté oculto de forma predeterminada en algunos niveles.
