`chatgpt-web-codex` (alias `cgpt-codex`) conecta los turnos de Codex Responses mediante una
sesión autenticada de ChatGPT en el navegador. Es independiente del proveedor común
retirado `chatgpt-web` y utiliza la implementación con aviso MIT ubicada en
`open-sse/vendor/codex-chatgpt-web/`, actualizada hasta el commit
`b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494` de la versión v4.0.7 del proyecto original.

## Retirada del proveedor común

Los antiguos identificadores del proveedor común `chatgpt-web` y `cgpt-web` ya no se
distribuyen porque no se pudo esclarecer la procedencia de su implementación de
clave previa/prueba de trabajo. Las solicitudes explícitas a cualquiera de estos
identificadores, incluidos los identificadores de modelo con prefijo de barra y los alias
persistidos, fallan de forma segura con HTTP `410` y el código **PROVIDER_RETIRED** antes
de realizar cualquier solicitud al servicio de origen.

La migración `168_retire_chatgpt_web.sql` marca como eliminadas las conexiones de
proveedor coincidentes e invalida sus concesiones de sesión activas. Conserva el historial
de conexiones y las listas de permitidos de claves de API; no añade acceso de reemplazo a
ninguna lista de permitidos. El proveedor Codex y sus conexiones no se ven afectados por
esta retirada.

## Requisitos previos

- una cabecera Cookie completa de una sesión de ChatGPT con la sesión iniciada;
- Chrome o Chromium, además de una sesión gráfica o una pantalla Xvfb para instalaciones
  con npm, systemd y PM2;
- con el perfil `web` de Docker, el servicio interno de Chromium de
  `docker-compose.yml`;
- OpenAI `tunnel-client` v0.0.13 y un conector personalizado de ChatGPT para las
  herramientas locales de Codex.

El túnel solo es necesario para los turnos con herramientas. Todas las rutas enumeradas,
incluida `pro`, pueden usar la misma capacidad de herramientas locales vinculada al turno
cuando el túnel y el conector están configurados.

## Configuración en el panel

1. Abra el proveedor **ChatGPT Web (Codex)** y añada una conexión.
2. Pegue la cabecera Cookie completa de ChatGPT, el identificador del túnel, la clave de
   tiempo de ejecución y el nombre del conector personalizado. Las nuevas configuraciones
   con capacidad de usar herramientas deben utilizar un conector recién creado llamado
   exactamente `OmniRoute Codex v2`, con Autenticación establecida en Ninguna y Permisos
   establecidos en Permitir todas las acciones.
3. Ejecute la comprobación de la conexión. OmniRoute abre un Chat temporal respaldado por
   navegador y detecta si Sol y Pro están disponibles para la cuenta.
4. Guarde la conexión. OmniRoute sustituye la cookie pegada por el estado de
   almacenamiento verificado de Playwright y lo almacena junto con la clave de tiempo de
   ejecución mediante la abstracción de credenciales cifradas.

La cookie sin procesar no se conserva después de guardarla correctamente. Cuando la
sesión caduque, abra la conexión, pegue una nueva cabecera Cookie completa y vuelva a
ejecutar la comprobación. El estado de diagnóstico del cuadro de diálogo de edición
informa por separado sobre el navegador, el estado de almacenamiento, el inicio de
sesión, el Chat temporal, el túnel, el conector y el recorrido de ida y vuelta de la
herramienta.

> Nunca confirme en el repositorio una cookie real, una clave de tiempo de ejecución, un
> estado de almacenamiento ni un token de capacidad. Los valores de pruebas y
> documentación deben ser siempre marcadores de posición.

## Modelos y combos

Las rutas de modelo fijas son:

- `chatgpt-web-codex/luna` — GPT-5.6 Luna, esfuerzo bajo
- `chatgpt-web-codex/think` — GPT-5.6 Luna, esfuerzo medio
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

Añada una de ellas a un combo como cualquier otro modelo. La aplicación Codex envía el
nombre del combo como `model` al endpoint habitual de Responses, `/v1/responses`; no
existe un endpoint de Codex independiente ni un selector de modo.

Las cuentas Free/Go ofrecen las rutas Luna. Las cuentas con acceso a Sol ofrecen desde
Instant hasta High, y las cuentas con acceso a Pro ofrecen además Extra High y Pro. Cada
ruta tiene un modelo de backend y un nivel de esfuerzo de razonamiento fijos; un esfuerzo
explícito de Responses que entre en conflicto falla de forma segura en lugar de cambiar
silenciosamente el modo de navegador seleccionado.

No cambie el nombre ni reutilice un conector anterior `Codex Native` u `OmniRoute Codex`.
ChatGPT almacena en caché el contrato MCP público según la identidad del conector,
mientras que el puente actualizado utiliza un nuevo contrato directo de tokens por turno.
El entorno de ejecución rechaza esas identidades heredadas y exige un conector nuevo
`OmniRoute Codex v2`.

## Modelo de seguridad

- La ruta nativa requiere una solicitud de Responses, un cliente Codex reconocido e identidades
  de hilo y turno coincidentes.
- El espacio de trabajo, el entorno aislado, la política de aprobación y el catálogo de herramientas provienen del shell nativo de Codex;
  el texto libre del prompt no tiene autoridad sobre ellos.
- ChatGPT recibe únicamente una capacidad de corta duración por turno. El broker MCP solo acepta
  las herramientas que Codex ofreció en ese turno exacto.
- La confirmación automática de **Permitir una vez** solo devuelve la solicitud de herramienta a Codex. Únicamente Codex
  decide sobre su aprobación y ejecución.
- Antes de la primera salida, una combinación puede recurrir a otro destino compatible. Después de que
  comience la salida, el proveedor, el modelo, la conexión y el turno del navegador permanecen fijados hasta que
  finaliza el turno.
- Las cookies, las claves de tiempo de ejecución, el estado de almacenamiento y los tokens de capacidad no aparecen en las respuestas
  del proveedor ni en los registros de solicitudes.

## VPS sin pantalla y Docker

Para instalaciones con npm, systemd y PM2, OmniRoute detecta rutas comunes de Chrome y Chromium.
Como alternativa, configure `CHATGPT_WEB_CODEX_CHROME_PATH`. Los turnos de tiempo de ejecución usan deliberadamente
Chrome con interfaz gráfica porque ChatGPT rechaza la configuración de un navegador realmente sin interfaz. Por lo tanto, un host sin pantalla debe
ejecutar OmniRoute con una pantalla Xvfb privada; configurar únicamente la ruta de Chrome no proporciona una.

El perfil `web` de Docker inicia `chatgpt-web-codex-browser` en la red interna de
Compose. El sidecar ejecuta Chrome con interfaz gráfica dentro de Xvfb, por lo que no se requiere una pantalla física. Su puerto
CDP no se publica en el host. El volumen protegido del perfil del navegador está separado del
volumen de datos de OmniRoute, y el navegador recibe suficiente memoria compartida. El proxy CDP interno
escucha únicamente en el puerto `9223` dentro de la red de Compose; Chrome permanece vinculado a la interfaz de bucle local en el
sidecar.

Un arrendamiento de supervisor bajo `DATA_DIR` evita que varios procesos de OmniRoute sean propietarios
del mismo estado del túnel y del broker. El doctor informa de los conflictos.

## Recuperación interactiva

La ruta automatizada de Docker no tiene una ventana visible desde el host, pero Chrome se ejecuta con interfaz gráfica dentro de la
pantalla Xvfb privada. Cuando ChatGPT requiere un inicio de sesión interactivo o un desafío, se puede usar la infraestructura
de navegador VNC existente para la recuperación. La interfaz del navegador y CDP deben permanecer accesibles únicamente
mediante la interfaz de bucle local, una conexión de administración autenticada o un túnel SSH; noVNC permanece deshabilitado
durante el funcionamiento normal.

## Alternativa WebSocket

Cuando una combinación contiene ChatGPT Web (Codex), el puente WebSocket de Responses solicita la
alternativa HTTP/SSE antes de conectarse con el servidor ascendente. La transferencia se realiza entonces a través de
`/v1/responses`.
