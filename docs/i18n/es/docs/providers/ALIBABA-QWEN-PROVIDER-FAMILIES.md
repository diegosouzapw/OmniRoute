Este documento registra la decisión de implementación para el
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854). Los productos públicos se
representan como cuatro familias de proveedores. La región es un dato de conexión, no un producto independiente.

## Decisión

| Familia de proveedores                    | ID de OmniRoute         | Región global | Región de China |
| ----------------------------------------- | ----------------------- | ------------- | --------------- |
| Alibaba Cloud Model Studio (pago por uso) | `alibaba`               | Singapur      | Pekín           |
| Alibaba Cloud Token Plan                  | `bailian-coding-plan`   | Singapur      | Pekín           |
| Qwen Cloud (pago por uso)                 | `qwen-cloud`            | Global        | Pekín           |
| Qwen Cloud Token Plan                     | `qwen-cloud-token-plan` | Singapur      | Pekín           |

El ID existente `alibaba-cn` se mantiene como alias de compatibilidad en tiempo de ejecución para las conexiones guardadas, las rutas de modelos, las combinaciones y el uso histórico. Su tarjeta del panel se integra en `alibaba`; no es necesario reescribir la base de datos.

Qwen Cloud de pago por uso y Alibaba Cloud Model Studio comparten actualmente los hosts de ejecución compatibles con DashScope, pero conservan identidades de proveedor independientes porque los usuarios obtienen las claves y administran las cuentas mediante interfaces de producto diferentes. Los productos Token Plan de Alibaba y Qwen Cloud utilizan familias de endpoints diferentes, por lo que los cuatro productos conservan ID de proveedor independientes.

## Matriz de endpoints

| Familia de proveedores  | `global-sg`                                                              | `china-beijing`                                                      | Formato de protocolo |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | -------------------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI               |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic            |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI               |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI               |

La clave de API y el endpoint deben pertenecer al mismo producto y región. Al seleccionar una región, se cambia el endpoint preestablecido utilizado por la validación y las solicitudes normales.

## Contrato de conexión

Las conexiones nuevas almacenan la clave estable de la región en `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

Los valores permitidos son `global-sg` y `china-beijing`. El endpoint se deriva de forma centralizada a partir del ID del proveedor y la región. Un valor de `providerSpecificData.baseUrl` que no sea preestablecido continúa siendo una anulación explícita del operador y tiene prioridad, mientras que las antiguas URL preestablecidas guardadas se normalizan de nuevo según la matriz regional.

Esto mantiene extensible el esquema de conexión: se puede añadir otra región al solucionador sin crear otra tarjeta de proveedor ni cambiar los ID de proveedor guardados.

## Compatibilidad y despliegue

1. Añadir el resolvedor de endpoints regionales y conservar los valores predeterminados globales actuales.
2. Usar el descubrimiento regional en tiempo real de `/models` de DashScope para `alibaba`, su ID de compatibilidad `alibaba-cn`
   y `qwen-cloud`. Sus respuestas pasan primero por un filtro de generación de texto porque el endpoint genérico
   también devuelve modelos de imagen, vídeo, audio, embeddings y otros modelos que no son de chat. Después, `qwen-cloud`
   aplica la lista de permitidos mantenida y declarada en su registro de proveedor. Alibaba Model Studio
   y Qwen Cloud mantienen catálogos seleccionados por separado, aunque actualmente compartan hosts de ejecución.
3. Registrar `qwen-cloud-token-plan` con la lista actual de modelos de texto permitidos del Token Plan.
4. Añadir un selector de región tipado a los diálogos para añadir o editar conexiones.
5. Ocultar la tarjeta duplicada de `alibaba-cn` e incluir sus conexiones existentes en la página del proveedor
   `alibaba`.
6. Mantener disponibles las sobrescrituras de endpoints personalizados para despliegues avanzados y específicos de cada espacio de trabajo.

Los modelos multimedia del Token Plan permanecen fuera del catálogo de chat porque utilizan endpoints dedicados.
`wan2.7-image` y `wan2.7-image-pro` están registrados en `open-sse/config/imageRegistry.ts`;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` y `happyhorse-1.1-r2v` están registrados en
`open-sse/config/videoRegistry.ts`. Ambos registros reutilizan la identidad de conexión
`qwen-cloud-token-plan` y sus credenciales específicas de la región.

Qwen Cloud normal tiene catálogos independientes de imágenes y vídeos de pago por uso bajo la identidad
`qwen-cloud`. Sus modelos de imagen son `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` y `z-image-turbo`. Sus modelos de vídeo
son `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` y
`wan2.7-videoedit`. Estos modelos reutilizan únicamente la conexión normal `qwen-cloud` y el endpoint multimedia
regional de DashScope. Los registros del Token Plan y de pago por uso no heredan ni combinan
las listas de modelos del otro.

La identidad `bailian-coding-plan` también tiene sus propias listas de permitidos para contenido multimedia:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` y `qwen-image-2.0-pro` para la generación
de imágenes, además de
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` y `happyhorse-1.1-r2v` para la generación
de vídeos. Utiliza únicamente la conexión de Bailian Coding Plan y el endpoint regional del Coding Plan.
Sus registros de imágenes y vídeos no heredan ni se combinan con ninguno de los proveedores de Qwen Cloud.

La identidad normal `alibaba` tiene listas independientes de permitidos para imágenes y vídeos. Sus modelos de imagen son
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` y `wan2.6-t2i`. Sus modelos de vídeo añadidos son `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` y `wan2.7-videoedit`. Estos modelos utilizan únicamente la conexión de Alibaba Model Studio
y el endpoint multimedia regional seleccionado; no se añaden a ningún registro de Coding Plan ni de Qwen
Cloud.

El catálogo de chat del Qwen Cloud Token Plan sigue la lista de permitidos de texto de coincidencia exacta del plan Individual:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` y
`deepseek-v4-pro`. Las entradas de Wan y HappyHorse pertenecen a las API independientes de generación de imágenes y vídeos.

Alibaba Token Plan expone los mismos seis ID actuales de modelos de generación de texto a través de su
endpoint compatible con Anthropic. Su opción de Singapur almacena la clave de región existente `global-sg`;
solo la etiqueta visible para el usuario difiere de las familias de proveedores que denominan Global a la región.

El catálogo normal de chat de Qwen Cloud es intencionadamente más limitado que la respuesta de texto completa en tiempo real. Su
lista de permitidos mantenida se encuentra en `open-sse/config/providers/registry/qwen-cloud/index.ts`; el
descubrimiento en tiempo real solo devuelve los ID presentes tanto en la respuesta del servicio ascendente como en esa lista del registro.

Alibaba Model Studio sigue la misma regla de intersección en tiempo real con su lista de permitidos mantenida de forma independiente
en `open-sse/config/providers/registry/alibaba/index.ts`. El proveedor de compatibilidad `alibaba-cn`
reutiliza ese catálogo mientras resuelve el descubrimiento mediante el endpoint de Pekín.
