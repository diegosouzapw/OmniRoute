Esta página explica el comportamiento local de `.env` del proyecto y cómo gestionar los archivos de entorno y los secretos al desarrollar OmniRoute.

## Comportamiento de postinstall para .env

El proyecto puede generar un archivo `.env` local durante `npm install` / `postinstall` para facilitar el trabajo de los desarrolladores. Este archivo está destinado exclusivamente al desarrollo y las pruebas locales y nunca debe confirmarse en el control de versiones.

Puntos clave:

- El archivo `.gitignore` del repositorio ya ignora los archivos `.env*` (consulta la entrada de `.gitignore`). No elimines ni modifiques esa regla a menos que tengas la intención deliberada de confirmar un archivo de ejemplo específico y dispongas de un proceso documentado para ello.
- Si se confirma accidentalmente un secreto real en el repositorio, rota o revoca la credencial de inmediato y elimínala del historial del repositorio (por ejemplo, mediante `git filter-repo` o un flujo de corrección equivalente). Ponte en contacto con el responsable de seguridad o de contacto si necesitas ayuda.
- Para CI y producción, utiliza los secretos de CI o un gestor de secretos (GitHub Actions Secrets, Azure Key Vault, HashiCorp Vault, etc.) en lugar de confirmar secretos en archivos.

## Flujo de trabajo local recomendado

- Mantén `.env` únicamente en tu espacio de trabajo local. Utiliza `.env.example` (que ya está bajo seguimiento) para documentar las variables necesarias y los valores de ejemplo aceptables.
- Al ejecutar pruebas locales que requieran valores similares a secretos, utiliza preferentemente marcadores sintéticos o claves efímeras generadas en tiempo de ejecución en lugar de credenciales reales.
- Añade un comentario breve en las pruebas que utilicen marcadores para que los revisores entiendan que los datos de prueba son sintéticos.

## Notas sobre los escáneres

- Algunos recursos compilados o binarios (por ejemplo, blobs WASM incrustados en base64) pueden contener subcadenas ASCII que parecen credenciales y pueden activar escáneres de secretos basados en texto. Si estos recursos son legítimos, inclúyelos en la lista de elementos permitidos del escáner o excluye los directorios en la configuración del escáner.

## Si encuentras una filtración

1. Rota o revoca la clave de inmediato.
2. Elimina el secreto del historial y fuerza el envío de una rama depurada si es necesario.
3. Notifica a los mantenedores y sigue la lista de comprobación de respuesta ante incidentes de tu organización.
