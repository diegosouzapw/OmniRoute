> `src/lib/db/obsidian.ts` (persistencia de token / URL base / WebDAV),
> `src/lib/obsidianSync.ts` (sincronización de la bóveda mediante WebDAV), `open-sse/mcp-server/tools/obsidianTools.ts`
> (22 herramientas MCP), `src/app/api/settings/obsidian/route.ts` +
> `src/app/api/settings/obsidian/webdav/route.ts` (API de configuración). El registro de herramientas
> y la configuración de ámbitos se encuentran en `open-sse/mcp-server/server.ts`.

## Qué es

OmniRoute se conecta a una bóveda de **Obsidian** como **fuente de contexto**: una base
de conocimiento local en Markdown que los agentes leen y escriben mediante el servidor MCP
integrado. La integración se comunica con el plugin comunitario **Obsidian Local REST API** que
se ejecuta dentro de la aplicación de escritorio, por lo que los agentes pueden buscar notas,
leer/escribir/aplicar parches a archivos, listar la bóveda, trabajar con notas periódicas
diarias/semanales, gestionar etiquetas, ejecutar comandos de Obsidian y, opcionalmente,
coordinar una sincronización bidireccional de la bóveda entre escritorio y móvil.

El cliente (`src/lib/obsidian/api.ts`) encapsula la Local REST API con:

- **Reintentos con espera incremental** para errores transitorios `5xx` y un **tiempo de espera de 30 segundos** mediante `AbortController`.
- **Clasificación tipada de errores**: `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- Una **indicación clara de que no se puede acceder a Obsidian** que señala el error
  habitual de puerto (HTTP en `27123`, **no** el endpoint MCP en `27124`) y el formato de Tailscale.
- **Codificación de rutas** relativas a la bóveda para que las rutas de notas con espacios o barras sean seguras.

## Configuración

No existe **ninguna variable de entorno** para el token ni para la URL base de Obsidian:
ambos se almacenan en la tabla `key_value` de SQLite (espacio de nombres `obsidian`) mediante
`src/lib/db/obsidian.ts`. El token está **cifrado en reposo** (AES-256-GCM, con
compatibilidad retroactiva para texto sin formato). Configúralo desde la pestaña **Fuentes de contexto**
del panel del endpoint (`ObsidianSourceCard`) o mediante la API REST de configuración.

> [!IMPORTANT]
> El plugin **Obsidian Local REST API** debe estar instalado y en ejecución. Su interfaz
> REST escucha en **HTTP `127.0.0.1:27123`** (la URL base predeterminada). El puerto `27124`
> es un endpoint MCP/HTTPS _independiente_ y la ruta de configuración lo rechaza explícitamente.
> Si te conectas desde otro dispositivo, usa `http://<tailscale-ip>:27123`.

### Claves de configuración (`key_value` de SQLite, espacio de nombres `obsidian`)

| Clave             | Propósito                                                    | Cifrada |
| ----------------- | ------------------------------------------------------------ | ------- |
| `api_key`         | Token de portador de la Local REST API                       | sí      |
| `base_url`        | URL base REST (predeterminada: `http://127.0.0.1:27123`)     | no      |
| `vault_path`      | Ruta absoluta al directorio de la bóveda (para sincronizar)  | no      |
| `webdav_username` | Nombre de usuario WebDAV generado (sincronización de bóveda) | no      |
| `webdav_password` | Contraseña WebDAV generada (sincronización de bóveda)        | sí      |
| `webdav_enabled`  | Indica si la sincronización de bóveda WebDAV está habilitada | no      |

### Configuración mediante REST

```bash
# Guardar + validar el token de la Local REST API (POST lo valida mediante una comprobación de estado)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Comprobar el estado de la conexión (devuelve connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# Desconectar (borra el token almacenado)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Todos los métodos requieren autenticación en el panel. `POST` rechaza cualquier URL que use
el puerto `27124` y valida el token llamando al endpoint de estado de la Local REST API antes de guardarlo.

### Sincronización de la bóveda mediante WebDAV

`src/app/api/settings/obsidian/webdav/route.ts` gestiona una sincronización opcional de la
bóveda respaldada por WebDAV (controlada por `src/lib/obsidianSync.ts`). Al habilitarla,
OmniRoute apunta a un directorio de bóveda local y genera un par aleatorio de nombre de
usuario y contraseña de WebDAV:

```bash
# Habilitar la sincronización WebDAV para un directorio de bóveda (genera nombre de usuario/contraseña)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# Obtener el estado de la sincronización WebDAV (las credenciales solo se devuelven mientras esté habilitada)
curl http://localhost:20128/api/settings/obsidian/webdav

# Deshabilitar la sincronización WebDAV (borra las credenciales + el archivo .stignore gestionado)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Fuente de contexto por clave de API (opcional)

La configuración de Obsidian puede delimitarse **por clave de API** mediante la tabla
`api_key_context_sources` (`src/lib/db/apiKeyContextSources.ts`). Cuando una llamada MCP
incluye un identificador de clave de API autenticado, `getObsidianConfigForApiKey()` da
preferencia al token, la URL base y la ruta de la bóveda propios de esa clave
(`source: "api_key"`) y, en caso contrario, recurre a la configuración global (`source: "global"`).

## Herramientas MCP (22)

Definidas en `open-sse/mcp-server/tools/obsidianTools.ts`. El token y la URL base se resuelven
en cada llamada (primero por clave de API y luego de forma global). Las herramientas que acceden al **servidor de sincronización**
de OmniRoute (las cuatro herramientas `obsidian_sync_*`) requieren además el token de autenticación de sincronización configurado
en los ajustes de OmniRoute.

### Herramientas de lectura (`read:obsidian`)

| Herramienta                  | Descripción                                                                                                                             |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Comprueba si la API REST local está accesible y autenticada.                                                                            |
| `obsidian_search_simple`     | Búsqueda de texto completo en el contenido de las notas; devuelve fragmentos con rutas de archivo.                                      |
| `obsidian_search_structured` | Busca mediante una expresión de JSON Logic (filtros and/or/regex/path).                                                                 |
| `obsidian_read_note`         | Lee una nota por su ruta relativa al almacén; opcionalmente, un encabezado, bloque o frontmatter concreto.                              |
| `obsidian_list_vault`        | Enumera los archivos y directorios del almacén (árbol de entradas).                                                                     |
| `obsidian_get_document_map`  | Obtiene la estructura de encabezados de la nota como un mapa de encabezados → números de línea.                                         |
| `obsidian_get_note_metadata` | Obtiene el frontmatter, las etiquetas, los enlaces y el recuento de caracteres/palabras sin el contenido completo.                      |
| `obsidian_get_active_file`   | Obtiene la ruta y el contenido del archivo actualmente activo en Obsidian.                                                              |
| `obsidian_get_periodic_note` | Obtiene la nota periódica diaria, semanal o mensual para una fecha (hoy si se omite).                                                   |
| `obsidian_get_tags`          | Enumera todas las etiquetas del almacén junto con sus frecuencias.                                                                      |
| `obsidian_list_commands`     | Enumera los ID de comandos de Obsidian disponibles (para usarlos con `obsidian_execute_command`).                                       |
| `obsidian_sync_status`       | Estado del servidor de sincronización de OmniRoute: ejecución, nombre del almacén, puerto, tiempo de actividad y última sincronización. |
| `obsidian_sync_conflicts`    | Enumera los conflictos de sincronización sin resolver (ruta, ruta del conflicto y momento de detección).                                |

### Herramientas de escritura (`write:obsidian`)

| Herramienta                      | Descripción                                                                                                     |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Crea o sobrescribe una nota con el contenido Markdown proporcionado.                                            |
| `obsidian_append_note`           | Añade contenido a una nota; opcionalmente, a un encabezado o bloque específico.                                 |
| `obsidian_patch_note`            | Añade, antepone o reemplaza de forma precisa en un encabezado, bloque o campo de frontmatter.                   |
| `obsidian_delete_note`           | Elimina permanentemente una nota del almacén.                                                                   |
| `obsidian_move_note`             | Mueve o cambia el nombre de una nota dentro del almacén.                                                        |
| `obsidian_execute_command`       | Ejecuta un comando de Obsidian mediante su ID de comando.                                                       |
| `obsidian_open_file`             | Abre un archivo en Obsidian (lo crea si no existe).                                                             |
| `obsidian_sync_trigger`          | Activa una sincronización bidireccional inmediata del almacén entre escritorio↔móvil.                           |
| `obsidian_sync_resolve_conflict` | Resuelve un conflicto de sincronización: conserva `local` (móvil), `remote` (escritorio) o `keep-both` (ambos). |

> [!NOTE]
> Los destinos de `obsidian_patch_note` aceptan un `targetType` de `heading | block | frontmatter`
> y una `operation` de `append | prepend | replace`, con un
> `createTargetIfMissing` opcional. Las cuatro herramientas `obsidian_sync_*` se comunican con el servidor de sincronización
> local (`http://127.0.0.1:27781` de forma predeterminada) y requieren el token de sincronización.

### Ámbitos

Las herramientas de lectura requieren `read:obsidian`; las herramientas de escritura requieren `write:obsidian`. La aplicación
es idéntica a la de Notion: la gestiona `withScopeEnforcement()` en
`open-sse/mcp-server/server.ts`, condicionada a `OMNIROUTE_MCP_ENFORCE_SCOPES=true`, y los
ámbitos permitidos proceden de `OMNIROUTE_MCP_SCOPES` o del contexto de ámbitos de la clave de API. Consulta
[MCP-SERVER.md](./MCP-SERVER.md).

## Endpoints

| Método   | Ruta                            | Propósito                                                                  |
| -------- | ------------------------------- | -------------------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | Devuelve `{ connected, hasToken, baseUrl, vaultPath }`.                    |
| `POST`   | `/api/settings/obsidian`        | Guarda y valida el token (rechaza el puerto `27124`).                      |
| `DELETE` | `/api/settings/obsidian`        | Desconecta (elimina el token almacenado).                                  |
| `GET`    | `/api/settings/obsidian/webdav` | Estado de sincronización WebDAV y credenciales (mientras está habilitada). |
| `POST`   | `/api/settings/obsidian/webdav` | Habilita la sincronización WebDAV para un directorio de bóveda.            |
| `DELETE` | `/api/settings/obsidian/webdav` | Deshabilita la sincronización WebDAV.                                      |

> Estas son rutas de configuración del panel. Se accede a la propia bóveda mediante la API
> REST local de Obsidian (la `base_url` configurada) y mediante las herramientas MCP anteriores;
> no existe ningún endpoint proxy público `/v1` de Obsidian.

## Casos de uso

- **Respuestas basadas en la bóveda** — `obsidian_search_simple` / `obsidian_search_structured`
  y después `obsidian_read_note`, para que un agente responda a partir de tus notas reales.
- **Creación de notas / diario** — `obsidian_write_note`, `obsidian_append_note` o
  el preciso `obsidian_patch_note` para registrar en la bóveda los resultados del agente,
  resúmenes o notas diarias (`obsidian_get_periodic_note`).
- **Navegación por la bóveda** — `obsidian_list_vault`, `obsidian_get_document_map` y
  `obsidian_get_tags` para explorar la estructura antes de leer o escribir.
- **Automatización de Obsidian** — `obsidian_list_commands` + `obsidian_execute_command` para
  controlar complementos/comandos desde un agente; `obsidian_open_file` para mostrar una nota en la interfaz.
- **Sincronización móvil** — habilita la sincronización WebDAV y, a continuación, usa
  `obsidian_sync_trigger` / `obsidian_sync_status` / `obsidian_sync_conflicts` /
  `obsidian_sync_resolve_conflict` para coordinar el escritorio↔móvil y resolver conflictos.
