> **Fuente:** `src/lib/{a2a,acp,cloudAgent}/`, `src/app/api/{a2a,acp,cloud}/`, `src/app/api/v1/agents/`
> **Última actualización:** 2026-06-28 — v3.8.40

OmniRoute expone tres interfaces diferentes relacionadas con agentes. A primera vista parecen similares, pero resuelven problemas distintos. Usa esta página para elegir la adecuada.

## Resumen

| Interfaz                          | Ideal para                                                                                                                                           | Transporte                            | Estándar                          |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------- | --------------------------------- |
| **A2A — Agente a agente**         | Colaboración entre agentes con agentes pares que utilizan el protocolo A2A                                                                           | JSON-RPC 2.0 sobre HTTP               | A2A v0.3 (especificación abierta) |
| **ACP — Registro de agentes CLI** | Detectar / registrar / iniciar agentes de programación CLI instalados en la máquina del usuario (Cursor, Cline, Codex CLI, Claude Code, Aider, etc.) | HTTP REST                             | Específico de OmniRoute           |
| **Agentes en la nube**            | Enviar tareas de programación de larga duración a servicios externos en la nube (Codex Cloud, Devin, Jules, Cursor Cloud)                            | HTTP REST + tareas respaldadas por BD | Específico de OmniRoute           |

Las tres son independientes; puedes elegir cualquier subconjunto.

## Árbol de decisión

```
¿Necesitas que un servicio en la nube realice trabajo fuera de esta máquina (Codex Cloud / Cursor Cloud / Devin / Jules)?
├─ SÍ → Agentes en la nube (POST /api/v1/agents/tasks)
└─ NO → Continúa
    │
    ¿Tienes un agente par que utiliza A2A y desea colaborar?
    ├─ SÍ → A2A (POST /a2a)
    └─ NO → Continúa
        │
        ¿Necesitas enumerar / configurar agentes de programación CLI instalados localmente?
        ├─ SÍ → ACP (GET /api/acp/agents)
        └─ NO → Usa directamente /v1/chat/completions
```

## 1. A2A — Agente a agente

**Especificación:** [A2A v0.3](https://a2a-protocol.org)
**Endpoint de OmniRoute:** `POST /a2a` (JSON-RPC 2.0)
**Tarjeta del agente:** `GET /.well-known/agent.json`

### Cuándo usarlo

- Al crear un sistema multiagente en el que OmniRoute sea uno de los pares
- Al exponer la inteligencia de enrutamiento de OmniRoute (`smart-routing`, `quota-management`, etc.) a agentes de frameworks como Google ADK o redes genéricas de agentes
- Al encapsular OmniRoute tras una interfaz estándar de descubrimiento e invocación

### Métodos

- `message/send` — envía un mensaje y recibe una respuesta síncrona
- `message/stream` — envía un mensaje y recibe eventos de progreso mediante streaming SSE
- `tasks/get` — consulta una tarea por ID
- `tasks/cancel` — cancela una tarea en ejecución

### Capacidades integradas (6)

- `smart-routing` — enruta un prompt mediante la combinación óptima
- `quota-management` — informa del estado de la cuota de cada proveedor
- `provider-discovery` — enumera los proveedores instalados y sus capacidades
- `cost-analysis` — estima el coste de una solicitud o conversación
- `health-report` — agrega el estado de circuit breaker, cooldown y lockout de cada proveedor
- `list-capabilities` — enumera las capacidades disponibles del agente y sus metadatos

### Más información

Consulta [A2A-SERVER.md](./A2A-SERVER.md) para obtener detalles sobre el transporte, la estructura de la tarjeta del agente, la configuración del TTL de las tareas y la plantilla para añadir nuevas capacidades.

## 2. ACP — Registro de agentes CLI

**Endpoint de OmniRoute:** `GET /api/acp/agents`
**Código fuente:** `src/lib/acp/{index,manager,registry}.ts`

### Qué es

ACP es el **inventario local de agentes CLI** de OmniRoute. Detecta qué CLI de programación están instaladas en el host (Cursor, Cline, Claude Code, Codex CLI, Continue, etc.), determina sus versiones y las muestra en el panel para que el usuario pueda configurar cada CLI de modo que apunte a OmniRoute.

NO es un protocolo externo: es un registro interno que sustenta la interfaz de usuario «CLI Tools» y el seguimiento de huellas digitales de las CLI (consulta [CLI-TOOLS.md](../reference/CLI-TOOLS.md)).

### Qué hace

- Examina el host en busca de binarios de CLI instalados (utiliza `which` / `where` según el sistema operativo)
- Lee la versión de cada CLI (ejecuta `<bin> --version`)
- Opcionalmente, admite agentes personalizados definidos por el usuario (ruta del binario + comprobación de versión + argumentos de inicio)
- Conserva los agentes personalizados en la configuración
- Devuelve la lista unificada al panel

### API REST

| Endpoint          | Método | Descripción                                                                         | Autenticación |
| ----------------- | ------ | ----------------------------------------------------------------------------------- | ------------- |
| `/api/acp/agents` | GET    | Enumera los agentes detectados y personalizados (recuentos de instalados y totales) | Clave de API  |
| `/api/acp/agents` | POST   | Añade/actualiza/elimina un agente personalizado (acción indicada en el cuerpo)      | Clave de API  |

Estructura del cuerpo para POST (`customAgentBodySchema` en `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Casos de uso

- La página «CLI Tools» del panel enumera lo que está instalado y te ayuda a configurar cada herramienta para que apunte a OmniRoute
- Los agentes personalizados permiten a los usuarios avanzados registrar CLI internas/propietarias que OmniRoute no reconoce de forma predeterminada
- El resultado de la detección alimenta la matriz de huellas digitales `cli-tools`

### Cuándo NO utilizar ACP

- ACP no _ejecuta_ tareas. Solo detecta y configura CLI. Para invocar realmente una CLI, debes iniciarla tú mismo con las variables de entorno que proporciona OmniRoute (`OPENAI_BASE_URL`, `OPENAI_API_KEY`, etc.).

## 3. Agentes en la nube

**Endpoints de OmniRoute:** `/api/v1/agents/tasks/*` (ciclo de vida) + `/api/cloud/*` (infraestructura)
**Código fuente:** `src/lib/cloudAgent/`

### Qué es

Una interfaz uniforme para agentes de programación en la nube de terceros. Envías un prompt y la URL de un repositorio; OmniRoute delega la tarea en el agente en la nube adecuado, consulta periódicamente su estado y devuelve los resultados.

### Agentes compatibles (4, todos confirmados en `src/lib/cloudAgent/agents/`)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### Ciclo de vida

```
POST /api/v1/agents/tasks
  → BaseAgent.createTask() por clase de agente
  → el servicio externo comienza a trabajar
  → se crea una fila de tarea en la base de datos (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → sincronización diferida del estado desde el proveedor
  → devuelve el estado actual + plan + registro de actividad
  ↓
POST /api/v1/agents/tasks/[id]   (acción: "approve" | "message" | "cancel")
  → reenvía al proveedor (o marca la tarea como cancelada localmente)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → cancelación local
```

### Autenticación

⚠️ **Todos los endpoints `/api/v1/agents/tasks/*` requieren autenticación de administración** (commit `588a0333`). Desde v3.8.0, los clientes que solo utilizan Bearer reciben un error 401.

### Análisis detallado

Consulta [CLOUD_AGENT.md](./CLOUD_AGENT.md) para obtener información sobre el contrato `CloudAgentBase`, los detalles específicos de cada agente, los detalles del esquema y los endpoints de gestión de credenciales.

## Comparación: A2A frente a Cloud Agents

Ambos tienen «tareas de larga duración», pero en capas diferentes:

| Aspecto                          | A2A                                                                                            | Cloud Agents                                                 |
| -------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Estándar                         | A2A abierto v0.3                                                                               | Específico de OmniRoute                                      |
| Dónde se ejecuta el cómputo      | Dentro de OmniRoute (usa las combinaciones configuradas)                                       | Externo (servidores de Codex / Devin / Jules)                |
| Duración de la tarea             | TTL predeterminado de 5 min (configurable en `TaskManager`)                                    | De minutos a horas                                           |
| Con conocimiento del repositorio | No (solo pasa prompts)                                                                         | Sí (URL del repositorio + rama)                              |
| Caso de uso                      | Colaboración entre agentes, enrutamiento inteligente como servicio                             | Delegar «implementar la funcionalidad X en el repositorio Y» |
| Autenticación                    | `OMNIROUTE_API_KEY` opcional para `/a2a`; administración para los auxiliares REST `/api/a2a/*` | Siempre mediante administración                              |

## Ejemplos de integración

### Descubrir las capacidades A2A de OmniRoute

```bash
curl http://localhost:20128/.well-known/agent.json
```

Devuelve la tarjeta del agente con las 6 habilidades, los transportes y la versión.

### Llamar a OmniRoute como agente A2A

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Enruta este prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### Listar los agentes CLI instalados mediante ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Añadir un agente CLI personalizado

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### Enviar una tarea de Cloud Agent

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implementa la funcionalidad X en el repositorio Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### Consultar el estado de una tarea en la nube

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## Cuándo usar cada opción

- **Frontend de chatbot / copiloto** → `/v1/chat/completions` (compatible con OpenAI; no es un protocolo de agentes)
- **Colaboración multiagente** → A2A
- **Listado de CLI locales en el panel de control** → ACP
- **Delegación de tareas de programación de larga duración a servicios en la nube** → Cloud Agents
