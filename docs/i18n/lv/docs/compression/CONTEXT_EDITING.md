Deleģētā **konteksta rediģēšana** ir tikai Claude pieejams konteksta pārvaldības līdzeklis. Atšķirībā no OmniRoute lokālajiem
saspiešanas dzinējiem (Caveman, RTK, LLMLingua, vairāku posmu konveijeriem), kas pārraksta pieprasījuma pamattekstu,
_pirms_ tas atstāj starpniekserveri, konteksta rediģēšana lūdz **pakalpojuma sniedzējam** iztīrīt novecojušus
rīka lietojuma / rīka rezultātu blokus no paša aktīvā konteksta loga. OmniRoute tikai pievieno pamatteksta
parametru (`context_management.edits[]`); faktisko tīrīšanu Claude veic atbilstoši savam tokenizatoram.

Pēc būtības tā ir deleģēta iespēja: citi pakalpojumu sniedzēji šo parametru noraida, tāpēc OmniRoute stingri ierobežo
tā izmantošanu tikai ar Claude un Claude Code saderīgiem starpniekpakalpojumiem.

Patiesais avots: `open-sse/config/contextEditing.ts` (stratēģiju identifikatori, ievietošana pamattekstā, telemetrijas
izgūšana), `open-sse/executors/base.ts` (ievietošanas pārbaude + atkāpšanās mehānisms 400 kļūdas gadījumā) un
`open-sse/services/compression/types.ts` (konfigurācijas struktūra + noklusējums).

## Ko dara `clear_tool_uses`

OmniRoute izejošajā Anthropic Messages pamattekstā ievieto vienu labojumu:

```json
{
  "context_management": {
    "edits": [
      {
        "type": "clear_tool_uses_20250919",
        "trigger": { "type": "input_tokens", "value": 100000 },
        "keep": { "type": "tool_uses", "value": 3 }
      }
    ]
  }
}
```

- `type: "clear_tool_uses_20250919"` — datētais Anthropic stratēģijas identifikators (`CLEAR_TOOL_USES_STRATEGY`).
- `trigger.value: 100000` — tiklīdz pieprasījuma ievades tokenu skaits pārsniedz šo slieksni, Claude sāk
  dzēst vecos rīka lietojuma/rezultātu pārus (`CONTEXT_EDITING_DEFAULT_TRIGGER_TOKENS`, Anthropic noklusējums).
- `keep.value: 3` — N jaunākie rīka lietojuma/rezultātu pāri tiek saglabāti neskarti
  (`CONTEXT_EDITING_DEFAULT_KEEP_TOOL_USES`).

Beta iespēja tiek pieteikta, izmantojot galveni `anthropic-beta: context-management-2025-06-27`, kuru
OmniRoute jau nosūta Claude pieprasījumos.

Ievietošanu veic `applyContextEditingToBody()`, un tā ir **idempotenta**: ja pamattekstā jau pastāv `clear_tool_uses`
labojums (to pievienojis iepriekšējs izsaukums vai nodrošinājis klients), pamatteksts tiek atstāts
nemainīts. Ja ir arī `clear_thinking_20251015` labojums, OmniRoute ar stabilu kārtošanu pārvieto
`clear_thinking` labojumu uz sākumu, jo Anthropic pieprasa, lai `clear_thinking` atrastos pirms
`clear_tool_uses` masīvā `edits[]`.

## Iespējošanas slēdzis katrai kombinācijai

Konteksta rediģēšana pēc noklusējuma ir **izslēgta**, un tā ir jāiespējo manuāli. Slēdzis ir viena Būla vērtība, kas atrodas
saspiešanas konfigurācijā:

- Iestatījuma atslēga: `contextEditing.enabled` (camelCase — **nevis** `context_editing` / `context-editing`).
- Tips: `ContextEditingConfig { enabled: boolean }` failā
  `open-sse/services/compression/types.ts`.
- Noklusējums: `DEFAULT_CONTEXT_EDITING_CONFIG = { enabled: false }`.
- Zod shēma: `contextEditingConfigSchema` failā `src/shared/validation/compressionConfigSchemas.ts`.
- Glabāšana: tiek saglabāts kopā ar pārējiem saspiešanas iestatījumiem (normalizēts failā
  `src/lib/db/compression.ts`).

Informācijas panelī slēdzis atrodas saspiešanas centrā
(`src/app/(dashboard)/dashboard/context/combos/CompressionHub.tsx`) un, izmantojot `saveSettings()`, saglabā
`{ contextEditing: { enabled: … } }`. Tā kā tas ir iekļauts saspiešanas iestatījumu objektā,
tas tiek kombinēts ar katras kombinācijas saspiešanas profilu, nevis darbojas kā pilnīgi neatkarīga
saskarne — konfigurācija satur tikai ieslēgšanas/izslēgšanas karodziņu; visi sliekšņi (`trigger`,
`keep`) ir iepriekš dokumentētās konstantes.

## Ierobežošana tikai Claude

Injekcija notiek tikai īstam Claude vai ar Claude Code saderīgiem relejiem. Nosacījums failā
`open-sse/executors/base.ts` ir:

```ts
if (
  (this.provider === "claude" || isClaudeCodeCompatible(this.provider)) &&
  contextEditing?.enabled &&
  !contextEditingDisabled
) {
  applyContextEditingToBody(transformedBody, { enabled: true });
}
```

- `this.provider === "claude"` — īsta Anthropic atslēga/OAuth.
- `isClaudeCodeCompatible(this.provider)` — releji, kuru nodrošinātāja ID sākas ar prefiksu
  `anthropic-compatible-cc-` (tie deklarē saderību ar Claude Code, tāpēc tie ir releji, kas
  visdrīzāk pieņems beta funkciju). Skatiet `open-sse/services/provider.ts`.

Apzināti **izslēgti**:

- `claude-web` — pārlūkprogrammas relejs ar `create_conversation_params` pieprasījuma struktūru, kas
  nekad nesaņem `context_management`.
- Vispārīgi `anthropic-compatible-*` releji (bez prefiksa `-cc-`) — trešo pušu galapunkti ar
  neskaidru beta funkcijas atbalstu.

Nodrošinātāji, kas nav Claude, nekad nesaņem parametru `context_management`, pat ja slēdzis ir
ieslēgts.

## 400 atkāpšanās mehānisms / releju pārklājums

Ar Claude saderīgs relejs var deklarēt beta funkcijas atbalstu, taču tomēr noraidīt parametru
`context_management` ar HTTP 400. Lai pieprasījumu neizgāztu, bet korekti turpinātu darbu ar
ierobežotu funkcionalitāti, izpildītājs noņem parametru un **vienreiz** atkārto pieprasījumu uz to
pašu URL:

```ts
if (
  response.status === HTTP_STATUS.BAD_REQUEST &&
  contextEditing?.enabled &&
  !contextEditingDisabled &&
  transformedBody?.context_management !== undefined
) {
  const errText = await response
    .clone()
    .text()
    .catch(() => "");
  if (/context[_-]management|context editing/i.test(errText)) {
    contextEditingDisabled = true;
    delete transformedBody.context_management;
    let retryBody = JSON.stringify(transformedBody);
    if (isClaudeCodeCompatible(this.provider) || this.provider === "claude") {
      retryBody = await signRequestBody(retryBody);
    }
    response = await fetch(url, { ...fetchOptions, body: retryBody });
  }
}
```

Darbība:

1. Aktivizējas tikai `400` atbildes gadījumā, kad konteksta rediģēšana ir iespējota un ķermenī
   faktiski ir `context_management`.
2. 400 atbildes ķermenis tiek nolasīts, izmantojot `clone()`, lai sākotnējā atbilde paliktu neskarta
   gadījumam, kad nav atbilstības.
3. Kļūdas tekstam jāatbilst `/context[_-]management|context editing/i` — nesaistīta 400 kļūda
   (piemēram, `max_tokens must be >= 1`) **neaktivizē** atkāpšanās mehānismu; sākotnējā kļūda tiek
   nodota tālāk.
4. Atbilstības gadījumā tas iestata `contextEditingDisabled = true` (tādējādi novēršot atkārtotu
   injekciju, ja vēlāk atkārtota mēģinājuma/rezerves URL vajadzībām tiek izveidots jauns
   `transformedBody`), izdzēš `context_management`, no jauna paraksta Claude / ar Claude Code
   saderīgo releju ķermeni (`signRequestBody`) un vienreiz atkārto pieprasījumu uz to pašu URL.

Īstam Claude beta funkcija ir iekļauta `ANTHROPIC_BETA_BASE`, un tas nenonāk šajā atkāpšanās
mehānisma ceļā.

## `applied_edits` telemetrija

Pēc Claude atbildes OmniRoute reģistrē, cik lielu konteksta daļu nodrošinātājs faktiski notīrīja. Šie
dati **netiek** straumēti — tie pēc iespējas tiek izgūti no nestraumētas atbildes ķermeņa un nekad
neietekmē atbildi (telemetrijas kļūdas tiek ignorētas).

- Izgūšana: `extractContextEditingTelemetry(responseBody)` failā
  `open-sse/config/contextEditing.ts`. Tas pārbauda `applied_edits` trīs vietās (piesardzības nolūkā,
  ņemot vērā dažādas atbildes struktūras):
  - `context_management.applied_edits`
  - `usage.context_management.applied_edits`
  - `usage.applied_edits`
- No katra ieraksta tiek nolasīti lauki `cleared_input_tokens` un `cleared_tool_uses` (snake_case,
  Anthropic vietējais formāts), ar `clearedInputTokens` / `clearedToolUses` camelCase rezerves
  variantiem.
- Atgriež `null`, ja nav atrasts neviens `applied_edits` masīvs vai nekas faktiski nav notīrīts.

Kvīts struktūra ir `ContextEditingTelemetry { editCount, clearedInputTokens, clearedToolUses }`.
Reģistrēšana notiek failā `open-sse/handlers/chatCore.ts` (ierobežota ar `provider === "claude"`),
izmantojot `recordContextEditingTelemetry()` (`src/lib/db/compressionAnalytics.ts`), kas ieraksta
saspiešanas analītikas rindu ar šādiem tagiem:

- `mode: "context-editing"`
- `engine: "context-editing"`
- `tokens_saved` / `original_tokens` = notīrīto ievades marķieru skaits
- `request_id` ar sufiksu `::context-editing`

Tādējādi deleģētā tīrīšana saspiešanas analītikā tiek attēlota kopā ar lokālajiem dzinējiem zem
`context-editing` dzinēja etiķetes, un to var atšķirt no RTK/Caveman/LLMLingua ietaupījumiem.

## Saistība ar lokālajiem saspiešanas dzinējiem

| Aspekts                 | Lokālie dzinēji (Caveman / RTK / LLMLingua / stacked)          | Deleģētā konteksta rediģēšana                        |
| ----------------------- | -------------------------------------------------------------- | ---------------------------------------------------- |
| Kur tas darbojas        | OmniRoute ietvaros, pirms pieprasījums atstāj starpniekserveri | Pakalpojuma sniedzēja pusē (Claude), servera pusē    |
| Ko tas rediģē           | Uzvednes / konteksta / rīka rezultātu tekstu                   | Vecos rīku izmantošanas / rīku rezultātu blokus      |
| Pakalpojumu tvērums     | Visi pakalpojumu sniedzēji                                     | Tikai `claude` + `anthropic-compatible-cc-*`         |
| Pārslēgšana             | Saspiešanas režīma iestatījumi                                 | `contextEditing.enabled`                             |
| Kļūmes režīms           | Kļūmes gadījumā turpina ar sākotnējo tekstu                    | 400 atkāpšanās: noņem parametru, atkārto vienu reizi |
| Ietaupījumu telemetrija | `engine: <engine id>`                                          | `engine: "context-editing"`                          |

Abi risinājumi viens otru papildina: lokālie dzinēji saspiež OmniRoute nosūtītos baitus; konteksta rediģēšana ļauj
Claude secīgi retināt aktīvo kontekstu vairākos dialoga posmos. Tos var iespējot kopā.
