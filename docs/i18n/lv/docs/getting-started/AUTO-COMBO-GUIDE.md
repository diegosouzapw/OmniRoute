> **Īsumā**: Iestatiet modeli uz `auto`, un OmniRoute automātiski izvēlēsies labāko MI pakalpojumu sniedzēju katram pieprasījumam. Konfigurēšana nav nepieciešama.

---

## Ko tas dara

Tā vietā, lai izvēlētos konkrētu MI modeli (piemēram, GPT-4o vai Claude), varat ļaut OmniRoute **automātiski izvēlēties labāko modeli** katram pieprasījumam. Tas ņem vērā:

- **Darbspēju** — Vai pakalpojumu sniedzējs pašlaik darbojas?
- **Ātrumu** — Cik ātrs tas ir?
- **Izmaksas** — Cik tas maksā?
- **Kvalitāti** — Vai tas ir piemērots šāda veida uzdevumam?
- **Kapacitāti** — Vai tam ir atlikusi kvota?

OmniRoute novērtē visus jūsu pievienotos pakalpojumu sniedzējus un izvēlas labāko. Ja tas neizdodas, OmniRoute automātiski izmēģina nākamo.

---

## Ātrā darba sākšana

**1. darbība**: Iestatiet modeli uz `auto` savā IDE vai CLI:

```
model: "auto"
```

**2. darbība**: Tas arī viss! OmniRoute parūpēsies par pārējo.

**3. darbība** (neobligāta): Izmantojiet variantu konkrētiem uzdevumiem:

```
model: "auto/coding"    # Vislabākais kodam
model: "auto/fast"      # Ātrākā atbilde
model: "auto/cheap"     # Lētākā iespēja
```

---

## Kuru „auto” man vajadzētu izmantot?

| Ja vēlaties...     | Izmantojiet šo | Vislabāk piemērots                     | Kā tas darbojas                                      |
| ------------------ | -------------- | -------------------------------------- | ---------------------------------------------------- |
| **Labāko kopumā**  | `auto`         | Vispārīgiem jautājumiem, tērzēšanai    | Līdzsvaro ātrumu, izmaksas un kvalitāti              |
| **Labāko kodam**   | `auto/coding`  | Koda rakstīšanai, atkļūdošanai         | Izvēlas modeļus, kas ir piemēroti kodēšanai          |
| **Ātrāko atbildi** | `auto/fast`    | Ātrām atbildēm, zemam latentumam       | Piešķir ātrumam augstāko prioritāti                  |
| **Lētāko iespēju** | `auto/cheap`   | Naudas taupīšanai                      | Izvēlas lētāko pakalpojumu sniedzēju                 |
| **Gudrāko modeli** | `auto/smart`   | Sarežģītiem uzdevumiem                 | Kvalitāte pirmajā vietā + jaunu modeļu izpēte        |
| **Vispieejamāko**  | `auto/offline` | Kad pakalpojumu sniedzēji ir noslogoti | Izvēlas pakalpojumu sniedzējus ar lielāko kapacitāti |

### Piemēri

```bash
# Vispārīga tērzēšana — līdzsvarota
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'

# Koda ģenerēšana — kvalitāte pirmajā vietā
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/coding","messages":[{"role":"user","content":"Write a Python function"}]}'

# Ātra atbilde — ātrums pirmajā vietā
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/fast","messages":[{"role":"user","content":"What is 2+2?"}]}'
```

## Kā tas darbojas (vienkāršota versija)

Kad nosūtāt pieprasījumu ar `model: "auto"`, OmniRoute:

1. **Apskata visus jūsu pievienotos pakalpojumu sniedzējus** — Katru pievienoto pakalpojumu sniedzēju (OpenAI, Anthropic, Google utt.)
2. **Novērtē katru no tiem**, cita starpā ņemot vērā:
   - Vai tas darbojas? (darbspēja)
   - Vai tam ir pieejama kapacitāte? (kvota)
   - Cik tas maksā? (cena)
   - Cik ātrs tas ir? (ātrums)
   - Vai tas ir piemērots šim uzdevumam? (kvalitāte)
3. **Izvēlas labāko** — Pakalpojumu sniedzējs ar augstāko vērtējumu saņem jūsu pieprasījumu
4. **Automātiski atjauno darbību** — Ja tas neizdodas, OmniRoute automātiski izmēģina nākamo

### Vērtēšanas sistēma

Katrs pakalpojumu sniedzējs saņem vērtējumu no 0 līdz 1. Jo augstāks vērtējums, jo labāka atbilstība.

| Faktors              | Svars | Ko tas nozīmē                                                     |
| -------------------- | ----- | ----------------------------------------------------------------- |
| Darbspēja            | 20%   | Vai pakalpojumu sniedzējs darbojas? (ķēdes pārtraucēja stāvoklis) |
| Kvota                | 15%   | Vai tam ir atlikusi kapacitāte?                                   |
| Izmaksas             | 15%   | Cik tas ir dārgs? (lētāks = augstāks vērtējums)                   |
| Ātrums               | 12%   | Cik tas ir ātrs? (mazāks latentums = augstāks vērtējums)          |
| Atbilstība uzdevumam | 8%    | Vai tas ir piemērots šāda veida uzdevumam?                        |
| Stabilitāte          | 5%    | Vai tas darbojas konsekventi? (zems kļūdu līmenis)                |
| Līmenis              | 5%    | Konta līmenis (Ultra > Pro > Free)                                |
| Citi faktori         | 20%   | Konteksta atbilstība, savienojumu blīvums utt.                    |

### Kā varianti maina vērtēšanu

Katrs variants izmanto atšķirīgus svarus:

| Variants       | Prioritāte         | Galvenie svari                  |
| -------------- | ------------------ | ------------------------------- |
| `auto`         | Līdzsvars          | health=20%, quota=15%, cost=15% |
| `auto/coding`  | Kvalitāte          | taskFit=37%, stability=15%      |
| `auto/fast`    | Ātrums             | latency=32%, health=28%         |
| `auto/cheap`   | Izmaksas           | cost=37%                        |
| `auto/smart`   | Kvalitāte + izpēte | taskFit=37%, exploration=10%    |
| `auto/offline` | Kapacitāte         | quota=37%, health=28%           |

## Kā tiek apstrādātas kļūmes

OmniRoute nodrošina **trīs aizsardzības līmeņus**:

### 1. Automātiska pārslēgšanās uz rezerves pakalpojumu sniedzēju

Ja labākais pakalpojumu sniedzējs nedarbojas, OmniRoute automātiski izmēģina nākamo. Jums nekas nav jādara.

### 2. Pašatjaunošanās

Ja pakalpojumu sniedzējs atkārtoti nedarbojas:

- **Vērtējums < 0.2** → Izslēgts uz 5 minūtēm
- **Jaudas slēdzis ir atvērts** → Automātiski izslēgts
- **Vairāk nekā 50% pakalpojumu sniedzēju nedarbojas** → Incidenta režīms (bez izpētes)

### 3. Ārkārtas rezerves risinājums

Ja neviens pakalpojumu sniedzējs nedarbojas, OmniRoute kā pēdējo iespēju novirza pieprasījumus stabiliem bezmaksas pakalpojumu sniedzējiem (piemēram, Kiro vai Qoder).

---

## Vairāku kontu atbalsts

Ja jums ir vairāki viena pakalpojumu sniedzēja konti (piemēram, divas OpenAI atslēgas), OmniRoute katru no tiem uzskata par **atsevišķu kandidātu**. Tas nozīmē:

- Kontam A ir atlikusi kvota → izmantot to
- Kontam B ir noteikts pieprasījumu biežuma ierobežojums → izlaist to
- Konts C ir lētāks → dot tam priekšroku

Katrs konts tiek vērtēts neatkarīgi, pamatojoties uz tā darbspēju, kvotu un ātrumu.

---

## Daudzroku bandīta izpēte

OmniRoute laiku pa laikam **izpēta** jaunus pakalpojumu sniedzējus, lai atrastu labākas iespējas:

- **Noklusējums**: 5% pieprasījumu tiek nosūtīti nejauši izvēlētiem pakalpojumu sniedzējiem
- **Auto/smart**: 10% izpētes līmenis
- **Atspējota**, ja vairāk nekā 50% pakalpojumu sniedzēju nav darbspējīgi

Tas palīdz OmniRoute noteikt, kuri pakalpojumu sniedzēji vislabāk atbilst jūsu lietošanas paradumiem.

## Bieži uzdotie jautājumi

### "Vai vienmēr tiks izvēlēts visdārgākais modelis?"

**Nē.** Pēc noklusējuma izmaksas veido tikai 15% no vērtējuma. Lēts, ātrs un darbspējīgs pakalpojumu sniedzējs var pārspēt dārgu pakalpojumu sniedzēju. Izmantojiet `auto/cheap`, ja vēlaties izmaksām piešķirt vēl lielāku prioritāti.

### "Kas notiek, ja pakalpojumu sniedzējs pārtrauc darboties?"

OmniRoute to automātiski izlaiž un izmēģina nākamo. Ja pakalpojumu sniedzējs atkārtoti nedarbojas, tas tiek īslaicīgi izslēgts (uz 5–30 minūtēm). Jums nekas nav jādara.

### "Vai varu redzēt, kurš pakalpojumu sniedzējs tika izmantots?"

Pārbaudiet atbildes galvenes — OmniRoute katrā atbildē norāda izmantoto pakalpojumu sniedzēju un modeli.

### "Vai sistēma mācās no mana lietojuma?"

Jā! Vērtēšanas sistēma izmanto vēsturiskos datus (latentumu, kļūdu īpatsvaru un veiksmīgo pieprasījumu īpatsvaru), lai laika gaitā pieņemtu labākus lēmumus.

### "Kāda ir atšķirība starp `auto` un `auto/smart`?"

- `auto` — Līdzsvarots režīms, 5% izpēte
- `auto/smart` — Kvalitāte pirmajā vietā (tādi paši svari kā `auto/coding`), 10% izpēte

Izmantojiet `auto/smart`, ja vēlaties vislabāko kvalitāti un jums netraucē neregulāra izpēte.

### "Vai varu piespiedu kārtā izvēlēties konkrētu pakalpojumu sniedzēju?"

Jā! Izmantojiet kombināciju ar `priority` stratēģiju, nevis `auto`, un pēc tam laukā `model` norādiet kombinācijas **precīzo nosaukumu** (piemēram, `model: "my-combo"` — nevis `auto`). Plašāku informāciju skatiet [tehniskajā uzziņu materiālā](../routing/AUTO-COMBO.md).

### "Ar ko tas atšķiras no cikliskās sadales?"

Cikliskā sadale secīgi pārslēdzas starp pakalpojumu sniedzējiem. Automātiskā kombinācija **novērtē katru pakalpojumu sniedzēju** un izvēlas labāko. Tā ir gudrāka — tiek ņemta vērā darbspēja, ātrums, izmaksas un kvalitāte.
