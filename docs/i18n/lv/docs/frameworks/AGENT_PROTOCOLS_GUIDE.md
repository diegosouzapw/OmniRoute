> **Pēdējo reizi atjaunināts:** 2026-06-28 — v3.8.40

OmniRoute nodrošina trīs dažādas ar aģentiem saistītas saskarnes. Sākotnēji tās šķiet līdzīgas, taču risina atšķirīgas problēmas. Izmantojiet šo lapu, lai izvēlētos piemērotāko.

## Īsumā

| Saskarne                      | Vispiemērotākā                                                                                                                                    | Transports                      | Standarts                        |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- | -------------------------------- |
| **A2A — Agent-to-Agent**      | Sadarbībai starp aģentiem ar citiem aģentiem, kuri izmanto A2A protokolu                                                                          | JSON-RPC 2.0, izmantojot HTTP   | A2A v0.3 (atvērta specifikācija) |
| **ACP — CLI aģentu reģistrs** | Lietotāja datorā instalētu CLI programmēšanas aģentu noteikšanai, reģistrēšanai un palaišanai (Cursor, Cline, Codex CLI, Claude Code, Aider u.c.) | HTTP REST                       | OmniRoute specifisks             |
| **Mākoņa aģenti**             | Ilgstošu programmēšanas uzdevumu iesniegšanai ārējiem mākoņpakalpojumiem (Codex Cloud, Devin, Jules, Cursor Cloud)                                | HTTP REST + DB glabāti uzdevumi | OmniRoute specifisks             |

Visas trīs saskarnes ir neatkarīgas — izvēlieties jebkuru to kombināciju.

## Lēmumu koks

```
Vai jums ir nepieciešams mākoņpakalpojums, kas veic darbu ārpus šī datora (Codex Cloud / Cursor Cloud / Devin / Jules)?
├─ JĀ → Mākoņa aģenti (POST /api/v1/agents/tasks)
└─ NĒ → Turpiniet
    │
    Vai jums ir cits aģents, kas izmanto A2A un vēlas sadarboties?
    ├─ JĀ → A2A (POST /a2a)
    └─ NĒ → Turpiniet
        │
        Vai jums ir jāuzskaita vai jākonfigurē lokāli instalētie CLI programmēšanas aģenti?
        ├─ JĀ → ACP (GET /api/acp/agents)
        └─ NĒ → Izmantojiet parasto /v1/chat/completions
```

## 1. A2A — Agent-to-Agent

**Specifikācija:** [A2A v0.3](https://a2a-protocol.org)
**OmniRoute galapunkts:** `POST /a2a` (JSON-RPC 2.0)
**Aģenta karte:** `GET /.well-known/agent.json`

### Kad izmantot

- Veidojot vairāku aģentu sistēmu, kurā OmniRoute ir viens no sadarbības dalībniekiem
- Nodrošinot OmniRoute maršrutēšanas iespējas (`smart-routing`, `quota-management` u.c.) aģentiem tādos ietvaros kā Google ADK vai vispārīgos aģentu tīklos
- Ietverot OmniRoute standarta atklāšanas un izsaukšanas saskarnē

### Metodes

- `message/send` — iesniegt ziņojumu un saņemt sinhronu atbildi
- `message/stream` — iesniegt ziņojumu un saņemt SSE straumētus progresa notikumus
- `tasks/get` — nolasīt uzdevumu pēc ID
- `tasks/cancel` — atcelt izpildē esošu uzdevumu

### Iebūvētās prasmes (6)

- `smart-routing` — maršrutēt uzvedni, izmantojot optimālo kombināciju
- `quota-management` — ziņot par katra nodrošinātāja kvotas stāvokli
- `provider-discovery` — uzskaitīt instalētos nodrošinātājus un to iespējas
- `cost-analysis` — novērtēt pieprasījuma vai sarunas izmaksas
- `health-report` — apkopot katra nodrošinātāja slēdža, nogaidīšanas perioda un bloķēšanas stāvokli
- `list-capabilities` — uzskaitīt aģenta pieejamās prasmes un metadatus

### Padziļināta informācija

Transporta informāciju, aģenta kartes struktūru, uzdevumu TTL konfigurāciju un jaunu prasmju pievienošanas veidni skatiet dokumentā [A2A-SERVER.md](./A2A-SERVER.md).

## 2. ACP — CLI aģentu reģistrs

**OmniRoute galapunkts:** `GET /api/acp/agents`
**Avots:** `src/lib/acp/{index,manager,registry}.ts`

### Kas tas ir

ACP ir OmniRoute **lokālais CLI aģentu saraksts**. Tas nosaka, kuri programmēšanas CLI ir instalēti resursdatorā (Cursor, Cline, Claude Code, Codex CLI, Continue u.c.), noskaidro to versijas un parāda tos informācijas panelī, lai lietotājs varētu konfigurēt katru CLI darbam ar OmniRoute.

Tas NAV ārējs protokols — tas ir iekšējs reģistrs, kas nodrošina „CLI Tools” lietotāja saskarnes un CLI ciparnospiedumu izsekošanas darbību (skatiet [CLI-TOOLS.md](../reference/CLI-TOOLS.md)).

### Ko tas dara

- Pārbauda, vai resursdatorā ir instalēti CLI izpildāmie faili (atkarībā no operētājsistēmas izmanto `which` / `where`)
- Nolasa katra CLI versiju (izsauc `<bin> --version`)
- Pēc izvēles pieņem lietotāja definētus pielāgotus aģentus (binārā faila ceļš + versijas pārbaude + palaišanas argumenti)
- Saglabā pielāgotos aģentus iestatījumos
- Atgriež vienotu sarakstu informācijas panelim

### REST API

| Galapunkts        | Metode | Apraksts                                                                   | Autentifikācija |
| ----------------- | ------ | -------------------------------------------------------------------------- | --------------- |
| `/api/acp/agents` | GET    | Uzskaita noteiktos un pielāgotos aģentus (instalēto/kopējais skaits)       | API atslēga     |
| `/api/acp/agents` | POST   | Pievieno/atjaunina/noņem pielāgotu aģentu (darbības noteicējs pamattekstā) | API atslēga     |

POST pamatteksta struktūra (`customAgentBodySchema` failā `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Lietošanas gadījumi

- Informācijas paneļa lapā „CLI Tools” tiek uzskaitīti instalētie rīki un sniegta palīdzība katra rīka konfigurēšanai darbam ar OmniRoute
- Pielāgotie aģenti ļauj pieredzējušiem lietotājiem reģistrēt iekšējus/patentētus CLI, kurus OmniRoute pēc noklusējuma nepazīst
- Noteikšanas rezultāts tiek izmantots `cli-tools` ciparnospiedumu matricā

### Kad ACP NAV jāizmanto

- ACP _neizpilda_ uzdevumus. Tas tikai nosaka un konfigurē CLI. Lai faktiski izsauktu CLI, palaidiet to pats ar OmniRoute nodrošinātajiem vides mainīgajiem (`OPENAI_BASE_URL`, `OPENAI_API_KEY` u.c.).

## 3. Mākoņa aģenti

**OmniRoute galapunkti:** `/api/v1/agents/tasks/*` (dzīves cikls) + `/api/cloud/*` (infrastruktūra)
**Avots:** `src/lib/cloudAgent/`

### Kas tas ir

Vienota saskarne darbam ar trešo pušu mākoņa programmēšanas aģentiem. Jūs iesniedzat uzvedni un repozitorija URL, OmniRoute nosūta pieprasījumu pareizajam mākoņa aģentam, periodiski pārbauda statusu un atgriež rezultātus.

### Atbalstītie aģenti (3, visi apstiprināti mapē `src/lib/cloudAgent/agents/`)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### Dzīves cikls

```
POST /api/v1/agents/tasks
  → BaseAgent.createTask() katrai aģenta klasei
  → ārējais pakalpojums sāk darbu
  → datubāzē tiek izveidota uzdevuma rinda (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → atlikta statusa sinhronizācija no nodrošinātāja
  → atgriež pašreizējo statusu + plānu + darbību žurnālu
  ↓
POST /api/v1/agents/tasks/[id]   (darbība: "approve" | "message" | "cancel")
  → pārsūta nodrošinātājam (vai lokāli atzīmē kā atceltu)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → lokāla atcelšana
```

### Autentifikācija

⚠️ **Visiem `/api/v1/agents/tasks/*` galapunktiem ir nepieciešama pārvaldības autentifikācija** (komits `588a0333`). Izsaucēji, kas izmanto tikai Bearer autentifikāciju, kopš v3.8.0 saņem 401.

### Padziļināta informācija

Informāciju par `CloudAgentBase` līgumu, katra aģenta specifiku, shēmu detaļām un akreditācijas datu infrastruktūras galapunktiem skatiet [CLOUD_AGENT.md](./CLOUD_AGENT.md).

## Salīdzinājums: A2A un mākoņa aģenti

Abiem ir „ilgstoši uzdevumi”, taču dažādos līmeņos:

| Aspekts                  | A2A                                                                                                    | Mākoņa aģenti                               |
| ------------------------ | ------------------------------------------------------------------------------------------------------ | ------------------------------------------- |
| Standarts                | Atvērtais A2A v0.3                                                                                     | Specifisks OmniRoute                        |
| Kur notiek izpilde       | OmniRoute iekšienē (izmanto konfigurētās kombinācijas)                                                 | Ārēji (Codex / Devin / Jules serveros)      |
| Uzdevuma ilgums          | Noklusējuma TTL — 5 min (konfigurējams sadaļā `TaskManager`)                                           | No minūtēm līdz stundām                     |
| Repozitorija pārzināšana | Nē (nodod tikai uzvednes)                                                                              | Jā (repozitorija URL + zars)                |
| Lietošanas gadījums      | Aģentu savstarpēja sadarbība, viedā maršrutēšana kā pakalpojums                                        | Deleģēt „ieviest funkciju X repozitorijā Y” |
| Autentifikācija          | Neobligāts `OMNIROUTE_API_KEY` ceļam `/a2a`; pārvaldības autentifikācija `/api/a2a/*` REST palīgceļiem | Vienmēr pārvaldības autentifikācija         |

## Integrācijas piemēri

### OmniRoute A2A iespēju atklāšana

```bash
curl http://localhost:20128/.well-known/agent.json
```

Atgriež aģenta karti ar visām 6 prasmēm, transportiem un versiju.

### OmniRoute izsaukšana kā A2A aģentam

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### Instalēto CLI aģentu uzskaitīšana, izmantojot ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Pielāgota CLI aģenta pievienošana

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### Mākoņa aģenta uzdevuma iesniegšana

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### Mākoņa uzdevuma statusa periodiska pārbaude

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## Ko un kad izmantot

- **Tērzēšanas robots / otrā pilota priekšgalsistēma** → `/v1/chat/completions` (saderīgs ar OpenAI — nav aģentu protokols)
- **Vairāku aģentu sadarbība** → A2A
- **Lokālo CLI uzskaitīšana informācijas panelī** → ACP
- **Ilgstošu programmēšanas uzdevumu deleģēšana mākoņpakalpojumiem** → mākoņa aģenti
