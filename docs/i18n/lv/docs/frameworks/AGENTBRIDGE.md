AgentBridge ir OmniRoute MITM (Man-in-the-Middle — starpnieka) starpniekserveris, kas pārtver HTTPS datplūsmu no IDE MI aģentiem un novirza to caur OmniRoute vienoto maršrutēšanas dzini. Tas atbalsta **10 IDE aģentus** — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code un Trae (tiek izpētīts) — padarot OmniRoute par tirgū pieejamo MITM starpniekserveri ar visplašāko MI programmēšanas asistentu pārklājumu.

**Informācijas paneļa atrašanās vieta:** `/dashboard/tools/agent-bridge`
**Sānjoslas grupa:** Rīki (pēc Mākoņa aģentiem)
**Skatiet arī:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — pārraugiet visu pārtverto datplūsmu reāllaikā; `docs/security/MITM-TPROXY-DECRYPT.md` (git; netiek kompilēts mapē `/docs`) — Linux TPROXY caurspīdīgās atšifrēšanas tveršanas režīms, ko vada maršruts `/api/tools/agent-bridge/tproxy`.

## §1 Pārskats

### Kas ir AgentBridge?

Kad IDE aģents (piemēram, GitHub Copilot, Cursor, Claude Code) veic API izsaukumu, tas tieši savienojas ar augšupējo MI nodrošinātāju (OpenAI, Anthropic utt.). AgentBridge caurspīdīgi pārtver šo savienojumu TLS līmenī — nepieprasot nekādas aģenta konfigurācijas izmaiņas — un pārraksta pieprasījumu, novirzot to caur OmniRoute.

Tas nozīmē, ka varat:

- **Pārmaršrutēt jebkuru aģentu uz jebkuru nodrošinātāju**: Copilot sazinās ar OpenAI? Novirziet to uz Anthropic Claude, Gemini vai jebkuru no OmniRoute 352 nodrošinātājiem.
- **Lietot modeļu kartējumus**: `gemini-3-flash` → `claude-sonnet-4.7` caurspīdīgi apstrādātāja līmenī.
- **Novērot visu aģentu datplūsmu**: katrs pārtvertais pieprasījums tiek publicēts rīkā [Datplūsmas inspektors](./TRAFFIC_INSPECTOR.md).
- **Izmantot OmniRoute noturības mehānismus**: kombinētā maršrutēšana, ķēdes pārtraucēji, rezerves varianti un izmaksu uzskaite darbojas arī IDE aģentu datplūsmai.

## §2 Arhitektūra

### 2.1 Komponentu pārskats

```
IDE aģents (VS Code / Cursor / u.c.)
    │  HTTPS (ports 443)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← DNS novirzīšana
    │
    ▼
src/mitm/server.cjs  (ports 443, CJS bērnprocess)
    │  nosaka mērķi pēc Host galvenes SNI
    │  ģenerē katram SNI atsevišķu TLS sertifikātu, ko parakstījusi AgentBridge CA
    ├── Atbilst apiešanas sarakstam? → TCP tiešā pārsūtīšana (bez atšifrēšanas)
    ├── Atbilst mērķim? → fetch → OmniRoute maršrutētājs (ports 20128)
    │       └── handler.intercept() — TypeScript
    │               ├── maskSecrets() pieprasījuma ķermenim/galvenēm
    │               ├── TrafficBuffer.push() — publicē Traffic Inspector
    │               └── fetchRouter() → /v1/chat/completions
    └── Nav atbilstības? → TCP tiešā pārsūtīšana (bez atšifrēšanas)
```

### 2.2 MITM serveris (`src/mitm/server.cjs`)

MITM pamatserveris darbojas kā Node.js CJS bērnprocess (lai nebūtu jāpārraksta esošā CJS kodu bāze). Tas:

- Klausās portā 443 (nepieciešamas paaugstinātas privilēģijas vai `authbind`/`setcap`)
- Saņem CONNECT tuneļus no operētājsistēmas (izmantojot `/etc/hosts` DNS novirzīšanu)
- Ģenerē katram SNI atsevišķus TLS sertifikātus, ko parakstījusi AgentBridge CA (`DATA_DIR/mitm/ca.crt`)
- Nosaka mērķa aģentu pēc Host galvenes, izmantojot `targets/index.ts` reģistru
- Nosūta pieprasījumus TypeScript apstrādātāju slānim, izmantojot HTTP adresē `http://127.0.0.1:20128`

`TARGET_HOSTS` tiek ielādēts no `DATA_DIR/mitm/targets.json` (ko palaišanas laikā ieraksta `targets/index.ts`), ļaujot veikt dinamiskus atjauninājumus bez CJS servera restartēšanas.

> **Saknes CA modelis (#6684).** Iepriekš aprakstītais modelis, kurā katram SNI
> paredzēto sertifikātu paraksta CA, ir pastāvīgi saglabātais saknes CA modelis,
> kas pievienots #6684 (`src/mitm/cert/rootCa.ts` +
> `src/mitm/_internal/rootCaShim.cjs`, atkārtoti izmantojot CA/lapas sertifikāta
> kriptogrāfiju, kas jau pārbaudīta TPROXY vajadzībām failā
> `src/mitm/tproxy/dynamicCert.ts`) — tas aizstāj vecāko vienoto statisko,
> pašparakstīto lapas sertifikātu (`src/mitm/cert/generate.ts`, kas joprojām
> attiecas tikai uz antigravity resursdatoriem), par kuru liecina diskā esošs
> `server.crt`/`server.key` pāris. **Migrācijas darbība**: jauna instalācija
> (bez iepriekšēja `server.crt`) automātiski saņem saknes CA modeli; instalācija,
> kas jau uzticas vecajam statiskajam lapas sertifikātam, turpina to izmantot,
> līdz operators iestata `MITM_ROOT_CA_ENABLED=true` un restartē tiltu
> (`src/mitm/cert/migration.ts` ir tīra lēmuma funkcija — uzticama MITM CA, kas
> var parakstīt lapas sertifikātu **jebkuram** resursdatoram, ir būtiski
> ietekmīgāka par veco lapas sertifikātu ar fiksētu SAN, tāpēc jau uzticamai
> instalācijai pārslēgšana nekad nenotiek nemanāmi). CA sertifikāts tiek
> instalēts tajā pašā `omniroute-mitm.crt` uzticamības krātuves vietā, ko
> izmantoja vecais lapas sertifikāts (`cert/install.ts::installCaCert`) —
> dubultas uzticamības tīrīšana nav nepieciešama.

### 2.3 Apstrādātāju bāze (`src/mitm/handlers/base.ts`)

Visi aģentu apstrādātāji paplašina `MitmHandlerBase`:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // Aizsargātās palīgmetodes: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

Katrs apstrādātājs pirms starpniekservera pieprasījuma veikšanas izsauc `hookBufferStart()`, bet pēc pabeigšanas — `hookBufferUpdate()`. Tie ievieto `InterceptedRequest` ierakstus objektā `globalTrafficBuffer` (skatiet [Traffic Inspector](./TRAFFIC_INSPECTOR.md) §4).

### 2.4 Mērķu reģistrs (`src/mitm/targets/`)

Katram aģentam ir deklaratīvs mērķa fails:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

Reģistrs (`targets/index.ts`) eksportē `ALL_TARGETS` un palaišanas laikā izveido `DATA_DIR/mitm/targets.json`.

### 2.5 Tiešā pārsūtīšana un apiešanas saraksts (`src/mitm/passthrough.ts`)

**Apiešanas saraksts** (tiek pārbaudīts vispirms, un tam ir prioritāte pār mērķa atbilstību):

- Noklusējuma modeļi: banku resursdatori, `.gov.`, OAuth/SSO nodrošinātāji (Okta, Auth0) u.c.
- Lietotāja modeļi: glabājas datubāzes tabulā `agent_bridge_bypass`
- Apietie resursdatori saņem caurspīdīgu TCP tuneli — TLS **nekad netiek atšifrēts**

**Noklusējuma tiešā pārsūtīšana** (nav atbilstības mērķim un nav apiešanas sarakstā):

- Arī saņem TCP tuneli — savienojumi nekad netiek pārtraukti
- Neļauj AgentBridge traucēt vispārējo sistēmas HTTPS datplūsmu

Maršrutēšanas prioritāte:

```
apiešanas saraksts → mērķa atbilstība → tiešā pārsūtīšana
```

### 2.6 Augšupstraumes CA sertifikāts (`src/mitm/upstreamTrust.ts`)

Korporatīvajām tīkla vidēm ar pielāgotu CA:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

Kad tas ir iestatīts, `undici` globālais dispečers tiek konfigurēts ar papildu CA sertifikātu, ļaujot AgentBridge sasniegt augšupstraumes nodrošinātājus, izmantojot korporatīvos TLS terminēšanas starpniekserverus.

### 2.7 Noslēpumu maskēšana (`src/mitm/maskSecrets.ts`)

Neatkarīgais, tīras telpas principā izstrādātais skeneris tiek piemērots pieprasījumu ķermeņiem un akreditācijas datu galvenēm
**pirms** tie nonāk Traffic Inspector buferī vai jebkurā žurnālā. Tas veic vienu lineāru pārbaudi:

- Tokeni ar `sk-` / `ak-` / `pk-` prefiksu (OpenAI/Anthropic stilā)
- RFC 6750 `Authorization: Bearer <token>` akreditācijas dati, prioritāti piešķirot visam tokenam
- Vispārīgi gari, necaurskatāmi tokeni (≥40 rakstzīmes), tostarp formas ar punktiem un aizpildījumu

`sanitizeHeaders()` pārveido saglabāto galveņu nosaukumus par mazajiem burtiem, deterministiski apvieno masīvu vērtības, atmet
kopīgo hop-by-hop/kadrēšanas aizliegumu sarakstu (tostarp starpniekservera autentifikāciju), pilnībā aizklāj `cookie` un
`set-cookie` un deleģē akreditācijas datu vērtības skenerim.

## §3 Iestatīšana

### 3.1 MITM servera palaišana/apturēšana

Izmantojiet AgentBridge servera kartīti ceļā `/dashboard/tools/agent-bridge`:

| Darbība                  | Apraksts                                                                                |
| ------------------------ | --------------------------------------------------------------------------------------- |
| Palaist serveri          | Palaiž `src/mitm/server.cjs` portā 443                                                  |
| Apturēt serveri          | Korekti aptur atvasināto procesu                                                        |
| Restartēt serveri        | Aptur un palaiž no jauna (ielādē mērķu izmaiņas)                                        |
| Uzticēties sertifikātam  | Instalē `DATA_DIR/mitm/ca.crt` operētājsistēmas uzticamo sertifikātu krātuvē            |
| Lejupielādēt sertifikātu | Lejupielādē `ca.crt` manuālai instalēšanai                                              |
| Pārģenerēt sertifikātu   | Izveido jaunu CA atslēgu pāri (visi esošie atsevišķo aģentu sertifikāti kļūst nederīgi) |

### 3.2 Sertifikāta pievienošana uzticamajiem

Pirms IDE pieņems MITM savienojumu, AgentBridge CA sertifikātam jābūt pievienotam operētājsistēmas uzticamajiem sertifikātiem.

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Keychain):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

Varat arī izmantot informācijas paneļa pogu "Uzticēties sertifikātam" (tā izpilda jūsu operētājsistēmai atbilstošo komandu un, ja nepieciešams, parāda sudo uzvedni).

#### Electron IDE ignorē operētājsistēmas uzticamo sertifikātu krātuvi (`NODE_EXTRA_CA_CERTS`)

Dažās IDE — jo īpaši **Antigravity IDE**, kā arī citās no Electron / VS Code atvasinātās lietotnēs — ir iekļauta
sava Node.js izpildvide, kas izejošajiem `fetch`/HTTPS pieprasījumiem **neizmanto operētājsistēmas uzticamo sertifikātu krātuvi**.
Uzticēšanās CA operētājsistēmas/NSS līmenī ir pietiekama IDE vietējam **aizmugursistēmas komponentam**
(piemēram, Go valodas serverim, kas izmanto operētājsistēmas CA komplektu), taču **Electron priekšgals**
joprojām nespēs izveidot TLS savienojumu — lietotnē tas izpaužas kā _atteikšanās no konta_ vai
_"savienojuma kļūda"_, lai gan MITM žurnālā redzams, ka aizmugursistēmas inicializācijas izsaukumi atgriež `200`.
Ir jāveic divas darbības, un abas ir būtiskas:

1. Skaidri norādiet izpildvidei CA:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **Palaidiet IDE no šīs čaulas.** Palaižot to no darbvirsmas ikonas / Dock / izvēlnes Start,
   čaulas eksportētie mainīgie **netiek** mantoti, un `~/.config/environment.d/*.conf` stājas spēkā tikai pēc
   jaunas pieteikšanās grafiskajā vidē. Vispirms pilnībā aizveriet IDE — Electron vienas instances bloķēšana nozīmē, ka otrā
   palaišana tikai fokusē esošo procesu un jaunā vide tiek ignorēta.

Iepriekš aprakstītā operētājsistēmas uzticamo sertifikātu un NSS konfigurēšana joprojām ir nepieciešama (Chromium tīkla steks, ko izmanto dažas autentifikācijas
plūsmas, lasa katra lietotāja NSS krātuvi, un tam ir savi statiski piesaistes ieraksti domēnam `*.googleapis.com`, kurus
lokāli uzticams CA ignorē). `NODE_EXTRA_CA_CERTS` papildus aptver Node `fetch` ceļu.

### 3.3 DNS maršrutēšana

Katram aģentam, kura datplūsmu vēlaties pārtvert, tā API resursdatoram(-iem) jāatrisinās uz `127.0.0.1`. AgentBridge automātiski pārvalda `/etc/hosts` ierakstus, kad iestatīšanas vednī pārslēdzat DNS attiecīgajam aģentam.

GitHub Copilot `/etc/hosts` ierakstu piemērs:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 Modeļu kartēšana

Izmantojiet katra aģenta kartītē esošo modeļu kartēšanas tabulu, lai definētu avota → mērķa kartējumus:

| Avota modelis (aģenta vietējais) | Mērķa modelis (OmniRoute) |
| -------------------------------- | ------------------------- |
| `gpt-4o`                         | `claude-sonnet-4.7`       |
| `*` (aizstājējzīme)              | `claude-haiku-4.7`        |

Aizstājējzīme `*` kartē jebkuru neatpazītu modeli uz norādīto mērķi. Kartējumi tiek glabāti tabulā `agent_bridge_mappings`.

> **Padoms — noskaidrojiet aģenta faktiskos modeļu ID.** IDE var sūtīt modeļu nosaukumus, kas atšķiras no
> tās lietotāja saskarnē redzamajiem apzīmējumiem un mainās starp galvenajām versijām. Piemēram, **Antigravity 2** tīklā sūta
> `gemini-3.1-pro-low`, `gemini-pro-agent` un `gemini-3.1-flash-lite`, nevis
> vecākā dokumentācijā norādīto `gemini-2.5-pro`. Nosūtiet vienu tērzēšanas pieprasījumu bez atbilstoša kartējuma: MITM
> reģistrēs precīzo ienākošo `model:` vērtību un pārsūtīs pieprasījumu bez izmaiņām. Kartējiet šo precīzo vērtību, un
> nākamais pieprasījums tiks pārtverts un maršrutēts uz jūsu mērķi.

### 3.5 Paziņojums par risku

AgentBridge pārtver akreditācijas datus (OAuth pilnvaras, API atslēgas), ko IDE izmanto autentifikācijai augšupstraumes pakalpojumu sniedzējos. Pirms reģistrēšanas tie tiek **maskēti** (skatiet §2.7), taču ir redzami OmniRoute MITM slānim. Pirmoreiz aktivizējot katru aģentu, tiek parādīts aizverams modālais paziņojums par risku.

### 3.6 Uzturēšana un diagnostika

Informācijas panelī ir pieejama **Uzturēšanas un diagnostikas** kartīte (`AgentBridgeMaintenanceCard`, mapē `src/app/(dashboard)/dashboard/tools/agent-bridge/components/`), kurā redzami operatīvie MITM maršruti, kam iepriekš nebija lietotāja saskarnes. Tās apakšvirsraksts: _"Veiciet pārtveršanas konveijera pašpārbaudi, atceliet atlikušo sistēmas stāvokli un pārvietojiet savu konfigurāciju starp datoriem."_ Kartītes klienta palīgfunkcijas atrodas failā `src/lib/inspector/agentBridgeMaintenanceApi.ts`.

| Poga                        | Maršruts                               | Ko tā dara                                                                                                                                                                                                          |
| --------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Diagnosticēt**            | `GET /api/tools/agent-bridge/diagnose` | Palaiž tveršanas konveijera paštestu un parāda katras pārbaudes pārskatu (✓/✗ + novēršanas norādi).                                                                                                                 |
| **Labot**                   | `POST /api/tools/agent-bridge/repair`  | Atsauc avārijas vai SIGKILL dēļ atstāto MITM sistēmas stāvokli (DNS viltošanas ierakstus, saknes CA, sistēmas starpniekserveri). Idempotenta darbība — ja stāvoklis ir tīrs, ziņo „Nav ko labot”.                   |

| Pārbaudes nosaukums | Ko tā pārbauda                                               | Norāde kļūmes gadījumā                                                                                                                                                        |
| ------------------- | ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server-running`    | MITM servera process ir aktīvs                               | „MITM serveris nedarbojas. Palaidiet to AgentBridge cilnē.”                                                                                                                   |
| `server-reachable`  | MITM serveris pieņem savienojumus savā portā (TCP zondēšana) | „MITM serveris nepieņem savienojumus savā portā. Pārbaudiet, vai ports ir brīvs un vai jums ir tiesības to piesaistīt.”                                                       |

Palaidiet labošanu, lai to notīrītu.”_ — un tiek izcelta poga **Labot**. `Repair` ir ProxyBridge karoga `--cleanup` analogs lietojumprogrammas slānī (tas deleģē izpildi funkcijai `repairMitm()` failā `src/mitm/manager.ts`).

> MITM saknes CA pēc apturēšanas/palaišanas paliek instalēts, lai izvairītos no
> atkārtotiem sudo pieprasījumiem (tāda pati darbība kā mitmproxy/Charles), tādēļ tā noņemšana ir tieši norādīta
> darbība **Noņemt CA**, nevis process, kas automātiski notiek apturēšanas laikā.

### 3.7 Pārnesamās konfigurācijas importēšana/eksportēšana

AgentBridge var serializēt **operatora pielāgojamo** stāvokli versētā JSON blokā, lai iestatījumu varētu replicēt vairākās ierīcēs. Serializētājs ir `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`), un to validē `AgentBridgeConfigSchema`.

Eksportā ir iekļautas tieši trīs daļas (iebūvētās noklusējuma vērtības apzināti **NETIEK** eksportētas, tādēļ importēšana nekad tās nedublē un ar tām nekonfliktē):

| Lauks            | Avots                                                                | Piezīmes                                                                 |
| ---------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `bypassPatterns` | lietotāja definēti apiešanas modeļi (`agent_bridge_bypass`)          | noklusējuma banku/valdības/Okta modeļi nav iekļauti                      |
| `customHosts`    | Traffic Inspector pielāgotie resursdatori (`inspector_custom_hosts`) | katrs: `{ host, kind: "llm"\|"app"\|"custom", label? }`                  |
| `agentMappings`  | katra aģenta modeļu kartējumi (`agent_bridge_mappings`)              | `{ [agentId]: [{ source, target }] }` katram aģentam, kuram ir kartējumi |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**Importēšanas darbība** (`POST /api/tools/agent-bridge/config`): apiešanas modeļi un katra aģenta kartējumi tiek **pilnībā aizstāti**; pielāgotie resursdatori tiek pievienoti **idempotenti** (`INSERT OR IGNORE`). Atbildē tiek norādīts, cik katra veida vienību tika lietots:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

Kas **NAV** konfigurācijā: servera darbības stāvoklis, sertifikātu ceļi, katra aģenta DNS stāvoklis, augšupstraumes CA ceļš un TPROXY iestatījumi — tie ir resursdatora/izpildlaika stāvokļi, nevis pārnesamas preferences.

### Izņēmumu saraksts sensitīviem resursdatoriem

Izņēmumu saraksts nodrošina, ka finanšu iestāžu, OAuth/SSO nodrošinātāju un citu sensitīvu resursdatoru dati **nekad netiek atšifrēti**. To TLS datplūsma tiek pārsūtīta kā caurspīdīgs TCP tunelis — OmniRoute nekad neredz nešifrēto saturu.

Noklusējuma izņēmumu šabloni ietver:

- `*.bank.*`, `*.gov.*` (finanšu iestādes/valsts iestādes)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/identitāte)
- `*.apple.com`, `*.icloud.com` (Apple sistēmas pakalpojumi)

Lietotāja pievienotie izņēmumu šabloni tiek glabāti tabulā `agent_bridge_bypass`, un tiem ir prioritāte pār visu pārējo.

### Noslēpumu maskēšana

Tiek lietota funkcija `maskSecrets()` no `src/mitm/maskSecrets.ts`:

- Katram pieprasījuma pamattekstam pirms `TrafficBuffer.push()`
- Katrai galvenei pirms žurnalēšanas vai apraides

Šabloni: marķieri ar prefiksu `sk-`/`ak-`/`pk-`, `Bearer` marķieri un vispārīgi marķieri, kuru garums ir ≥40 rakstzīmes.

### Augšupstraumes CA sertifikāts

Ja ir iestatīts `AGENTBRIDGE_UPSTREAM_CA_CERT`, fails tiek nolasīts startēšanas laikā. Ja ceļš pastāv, bet failu nevar nolasīt, AgentBridge reģistrē skaidru kļūdu un atsakās startēt (tas novērš nemanāmas TLS kļūmes korporatīvajās vidēs).

### Zināmie ierobežojumi

- **Portam 443 ir nepieciešamas privilēģijas**: Linux sistēmā AgentBridge nepieciešams izpildīt `setcap 'cap_net_bind_service=+ep'` Node binārajam failam vai palaist, izmantojot `authbind`. Iestatīšanas vednis parāda operētājsistēmai specifiskas instrukcijas.
- **Nepieciešama IDE restartēšana**: Pēc DNS novirzīšanas IDE ir jārestartē, lai jaunā resursdatora adreses noteikšana stātos spēkā.
- **Kodā stingri ierakstīti OAuth marķieri**: Daži aģenti (Kiro, Antigravity) OAuth atsvaidzināšanas marķierus glabā lokāli. AgentBridge tos apstrādā caurspīdīgi — tas redz `Bearer` marķieri katrā pieprasījumā, un pirms žurnalēšanas šis marķieris tiek maskēts.
- **Electron priekšgaliem nepieciešams `NODE_EXTRA_CA_CERTS`**: IDE, kuru priekšgals darbojas komplektā iekļautā Node/Electron izpildlaika vidē, ignorē operētājsistēmas/NSS uzticamības krātuvi, un tās ir jāpalaiž no čaulas ar iestatītu `NODE_EXTRA_CA_CERTS` (skatiet §3.2). Pazīme, ka tā trūkst: IDE aizmugursistēma autentificējas (MITM rāda `200` atbildes), bet lietotāja saskarnē joprojām nav veikta pieteikšanās.
- **Vienas IDE vairākas instalācijas ir neatkarīgas**: sistēmas instalācija (piemēram, `/usr/share/antigravity/antigravity`) un lietotāja lokālā „Full” instalācija (piemēram, `~/AntigravityIDE_Full/antigravity-ide`) ir atsevišķi procesi ar savām izpildlaika vidēm — katra no tām ir jāpalaiž no jauna ar ievadītu CA. Pirms atkārtotas palaišanas pēc binārā faila ceļa nosakiet, kura no tām darbojas.
- **Identitāti nosaka aģenta sistēmas uzvedne, nevis maršrutētais modelis**: pārkartējot aģenta modeli uz citu nodrošinātāju, atbilde joprojām norāda aģenta sākotnējo identitāti (piemēram, Antigravity atbild „Mani darbina Gemini”), jo IDE to ievieto sistēmas uzvednē. Faktisko aizmugursistēmu pārbaudiet `call_logs` / `proxy_logs` laukos (`provider`, `model`, `target_format`), nevis jautājot modelim, kas tas ir.

## §6 Problēmu novēršana

### Porta 443 konflikts

Ja kāds cits process jau klausās portā 443 (tīmekļa serveris, VPN u.c.):

```bash
lsof -i :443          # atrast procesu
sudo fuser -k 443/tcp  # piespiedu kārtā apturēt (lietot piesardzīgi)
```

Alternatīvi AgentBridge iestatījumos konfigurējiet neprivilēģētu portu un iestatiet `iptables` / `pf` novirzīšanas kārtulas.

### Sertifikāts nav uzticams

Ja pēc AgentBridge palaišanas IDE rāda TLS kļūdas:

1. Pārbaudiet, vai sertifikāts tika instalēts: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) vai `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. Dažas lietotnes uztur savu uzticamības krātuvi (Firefox, Chrome operētājsistēmā Linux). Vēlreiz palaidiet „Trust Cert” un pārbaudiet NSS/Firefox specifisko sertifikātu krātuvi.
3. Pēc uzticamības piešķiršanas restartējiet IDE — aktīvās TLS sesijas izmanto iepriekšējo uzticamības stāvokli.

### IDE ir atteikusies / „savienojuma kļūda”, neraugoties uz uzticamu CA

Pazīme: pēc DNS novirzīšanas un uzticamības piešķiršanas CA uz Electron balstīta IDE (piemēram, Antigravity)
tiek atvērta **ar atteiktu lietotāju** vai rāda autentifikācijas/savienojuma kļūdu, lai gan MITM žurnāls rāda, ka
sāknēšanas izsaukumi (`loadCodeAssist`, `fetchAvailableModels`, …) atgriež `200`.

Cēlonis: IDE **komplektācijā iekļautā Node/Electron izpildvide ignorē operētājsistēmas uzticamības krātuvi**. Iebūvētā
aizmugursistēma (Go valodas serveris) uzticas operētājsistēmas CA un veic autentifikāciju, bet Electron priekšgals
to nedara, tāpēc lietotāja saskarne uzskata, ka nav savienojuma.

Risinājums (abas darbības): eksportējiet `NODE_EXTRA_CA_CERTS=<ca.crt>` **un atkārtoti palaidiet IDE no tās
čaulas**, nevis no darbvirsmas ikonas. Vispirms pilnībā aizveriet IDE — Electron vienīgās instances bloķēšana nozīmē,
ka otrā palaišana tikai aktivizē esošo procesu un jaunā vide tiek ignorēta. Skatiet §3.2.
Tas atbilst atvērtam augšupstraumes ziņojumam, kurā savrups aģents darbojas caur MITM, bet IDE
variants ar tādu pašu konfigurāciju nedarbojas.

### DNS izmaiņas nav izplatītas

Pārbaudiet, vai `/etc/hosts` tika atjaunināts:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

Notīriet DNS kešatmiņu:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### IDE nav atrasta

Automātiskā noteikšana izmanto izplatītākos instalēšanas ceļus. Ja noteikšana neizdodas, bet IDE ir instalēta:

- Pārbaudiet, vai IDE binārais fails atrodas nestandarta vietā
- Iestatīšanas vednis joprojām darbojas — noteikšanas kļūme nozīmē tikai to, ka emblēmā netiks parādīts instalēšanas ceļš

### Apstrādātāja kļūdas (augšupstraumes izgūšana neizdodas)

Ja AgentBridge pārtver pieprasījumus, bet tie visi neizdodas:

1. Pārbaudiet, vai ceļā `/dashboard/providers` ir savienots vismaz viens nodrošinātājs
2. Pārbaudiet OmniRoute servera žurnālus: `APP_LOG_LEVEL=debug` failā `.env`
3. Pārbaudiet, vai `OMNIROUTE_BASE_URL` norāda uz pareizo maršrutētāja galapunktu (noklusējums: `http://127.0.0.1:20128`)

## §8 Ceļvedis

### Trae izpēte

Trae ir salīdzinoši jauns MI programmēšanas asistents. Pirms apdarinātāja ieviešanas:

1. Identificējiet bināro failu/paplašinājumu VS Code / JetBrains veikalos vai kā savrupu lietotni
2. Pārtveriet datplūsmu ar mitmproxy, lai atklātu API resursdatorus un galapunktu struktūras
3. Nosakiet autentifikācijas mehānismu
4. Izvērtējiet ieviešanas lietderību, pamatojoties uz pakalpojuma noteikumiem un API atklājamību

Līdz izpētes pabeigšanai Trae kartītē informācijas panelī tiek rādīta emblēma „Notiek izpēte” ar saiti „Ziņot par īstenojamību”. Apdarinātāja aizmetnis failā `src/mitm/handlers/trae.ts` izmet strukturētu kļūdu `Vēl nav ieviests`.

### Neizpildīto darbu aģenti (nepieciešams MITM — pielāgota bāzes URL atbalsta nav)

Tālāk norādītie rīki to pašreizējās versijās neatbalsta pielāgotus bāzes URL, tādēļ MITM ir vienīgais pārtveršanas veids. Īstenojamības izvērtēšana vēl nav pabeigta:

- **Windsurf** (Codeium/Cognition)
- **Amp** (Sourcegraph)
- **Amazon Q / Kiro CLI** (AWS Bedrock — atsevišķi no Kiro IDE)
- **Cowork** (Anthropic darbvirsmas lietotne)

Piezīme. GitHub Copilot CLI ≥v1.0.19 atbalsta `COPILOT_PROVIDER_BASE_URL` — šim rīkam MITM vietā izmantojiet tiešo konfigurāciju.
