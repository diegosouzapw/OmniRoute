Šis dokuments ir uzturētāja sagatavots apliecinājums par sešiem
`AI-detected potential malware` konstatējumiem, kas izvirzīti pret `omniroute@3.8.5`, un
`omniroute@3.8.6` ieviestajiem mazināšanas pasākumiem. Tas pastāv, lai:

1. Drošības konveijera operatoriem būtu viena atsauce, ko citēt, kad tiem nepieciešams
   izvērtēt konstatējumus salīdzinājumā ar faktisko pirmkodu.
2. Turpmākie MI skeneri varētu uztvert uzturētāja parakstīto apliecinājumu, ka katrs
   atzīmētais ceļš ir apzināts, brīvprātīgi aktivizējams un dokumentēts.
3. Mums būtu rakstisks ieraksts par to, _kāpēc_ katra izsaukuma vieta ir veidota tieši šādi —
   lai turpmāka pārstrukturēšana nejauši no jauna neieviestu pazīmi, kas
   tika apzināti noņemta.

Ja uzturat skeneri, kas pēc v3.8.6 mazināšanas pasākumu
izlaišanas atkārtoti atzīmē kādu no tālāk norādītajām izsaukuma vietām, lūdzu, atveriet problēmas pieteikumu ar skenēšanas izsekojumu, un
mēs šeit paplašināsim apliecinājumu.

## §1 — MITM saknes CA instalēšana (`77484.js`)

**Pirmkoda faili**:

- `src/mitm/cert/install.ts` — publiskās `installCert()` / `uninstallCert()`,
  katrai platformai paredzētās `installCertWindows/Mac/Linux`.
- `src/mitm/systemCommands.ts` — kopīgie `execFile` / `spawn` / PowerShell
  palīgrīki, ko izmanto instalēšanas ceļi.

**Aktivizētājs**: lietotājs lokālajā informācijas panelī noklikšķina uz „Enable MITM proxy” adresē
`/dashboard/cli-tools/mitm`. Maršruts ir pieejams tikai atgriezeniskās cilpas saskarnē — skatiet stingro noteikumu #17 failā
`CLAUDE.md` un `src/server/authz/routeGuard.ts::isLocalOnlyPath()`. Nopludināts
JWT, kas pieejams caur tuneli, **nevar** aktivizēt šo koda ceļu.

**Veiktās priviliģētās darbības (katrā platformā)**:

| OS                     | Komanda(-as)                                                                                                      |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | `certutil -addstore Root <cert>` caur UAC                                                                         |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | katra profila NSS DB atjaunināšana ar `certutil -d sql:<profile>`                                                 |

Tās ir tās pašas komandas, ko izmanto `mitmproxy`, Charles Proxy, Fiddler un
Caddy. Fakts, ka tās ir pieejamas OmniRoute, ir dokumentēts failā
`docs/security/STEALTH_GUIDE.md`.

**v3.8.6 mazināšanas pasākumi**:

- `runElevatedPowerShell()` vairs neizmanto `-EncodedCommand <base64utf16le>`.
  Paaugstināto privilēģiju izpildes saturs tiek ierakstīts katram izsaukumam atsevišķā pagaidu `.ps1` failā (režīms 0o600,
  privātā `mkdtempSync` direktorijā) un norādīts ar `-File`. Fails
  tiek atsaistīts blokā `finally`. Tas novērš Socket.dev MI
  klasifikatora atzīmēto tipisko privilēģiju paaugstināšanas ar PowerShell un base64 pazīmi.
- `installCertWindows` satur iekļautu `SECURITY-AUDITOR-NOTE:` bloku
  ar norādi uz šo dokumentu.

**Kāpēc mēs to saglabājam**: MITM starpniekserveris ir dokumentēta funkcija, ko izmanto
`docs/security/STEALTH_GUIDE.md` un `docs/frameworks/MITM-PROXY.md`. Tā
noņemšana izjauktu aģenta tilta funkciju kopumu.

## §2 — Zed akreditācijas datu importēšana (`app/api/providers/zed/import/route.js`)

**Avota faili**:

- `src/app/api/providers/zed/discover/route.ts` _(jauns versijā v3.8.6)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(jauns versijā v3.8.6)_

**Aktivizēšana**: lietotājs lokālā informācijas paneļa pakalpojumu sniedzēju
lapā noklikšķina uz „Importēt no Zed”. Galapunktu aizsargā
`requireManagementAuth`. Pats Zed redaktors ieraksta pakalpojumu sniedzēju API
atslēgas OS atslēgu saišķī ar dokumentētiem pakalpojumu nosaukumiem — skatiet
https://zed.dev/docs/ai/llm-providers.

**v3.8.5 darbība (tā, ko atzīmēja Socket.dev)**:

`POST /import` atrada akreditācijas datus un vienā pieprasījuma-atbildes ciklā
automātiski saglabāja tos lokālajā SQLite krātuvē. Nebija apstiprinājuma katram
kontam un nebija kontrolnosaukuma — tikai „atrasti N marķieri, visi importēti”.

**v3.8.6 riska mazināšana — 2 soļu apstiprināšana**:

1. **`POST /api/providers/zed/discover`** atgriež
   `{ candidates: [{ provider, service, account, fingerprint }] }`. Neapstrādātais
   marķieris **nekad** netiek pārsūtīts. Kontrolnosaukums ir
   `sha256(service|account|token).slice(0,16)`.
2. Informācijas panelī tiek parādīts kandidātu saraksts, operators atlasa
   importējamos kandidātus un nosūta `{ confirmedAccounts: [{ service, account, fingerprint }] }`
   uz **`POST /api/providers/zed/import`**.
3. Importēšanas galapunkts **serverī atkārtoti nolasa atslēgu saišķi** un filtrē
   pēc `(service, account, fingerprint)`. Manipulēta vai atkārtoti izmantota
   atrašanas atbilde nevar likt importēšanas galapunktam saglabāt nesaistītu
   marķieri — ja aktīvais marķieris kopš atrašanas ir mainījies, kontrolnosaukums
   vairs neatbilst un akreditācijas dati tiek izlaisti.

Vides karodziņš `OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` saglabā v3.8.5
darbību operatoriem, kuri vēl nav atjauninājuši savu automatizāciju. Tas tiks
noņemts versijā v3.9.

**Kāpēc mēs to saglabājam**: importēšana no Zed ir lietotājiem ērtākais darba
sākšanas veids, ja viņi jau izmanto Zed un vēlas dublēt savu pakalpojumu
sniedzēju atslēgas OmniRoute, tās atkārtoti neielīmējot.

## §3 — `execFile` / `spawn` / PowerShell ar paaugstinātām privilēģijām (`21843.js`)

**Avota faili**: `src/mitm/systemCommands.ts`.

**Kāpēc atzīmēts**: fragments atkārtoti eksportē `execFileWithPassword`,
`runElevatedPowerShell` un koplietojamo palīgfunkciju `quotePowerShell`.
Socket.dev MI klasifikators tos uzskata par vispārīgu „resursdatora komandu
izpildes un privilēģiju paaugstināšanas rīkkopu”. OmniRoute ietvaros tie tiek
izmantoti tikai MITM sertifikāta instalēšanas ceļā (§1), savukārt
`execFileWithPassword` tiek izmantots `sudo` komandu izpildei.

**v3.8.6 riska mazināšana**:

- `runElevatedPowerShell` pārveide (skatiet §1).
- Iekļautais `SECURITY-AUDITOR-NOTE:` bloks pie
  `runElevatedPowerShell` un `execFileWithPassword` dokumentē atļauto izsaucēju
  un fiksēto izpildāmo failu sarakstu.
- `execFileWithPassword` izsaukumam `spawn()` ir marķieris `nosemgrep` ar
  izpildāmo failu atļauto sarakstu, kurus šī palīgfunkcija drīkst saņemt —
  **no lietotāja ievades nav ceļa uz `finalCommand`/`finalArgs`**.

## §4 / §6 — 9router pakalpojuma pārraugs (`api/services/9router/{start,restart}/route.js`)

**Avota faili**:

- `src/app/api/services/9router/_lib.ts` — pārrauga rūpnīca.
- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`.
- `src/lib/services/ServiceSupervisor.ts` — vispārīga procesu palaišana / darbspējas aptaujāšana / žurnāla buferis.

**Aktivizēšana**: lietotājs lokālā informācijas paneļa iegulto pakalpojumu lapā
noklikšķina uz „Instalēt” / „Palaist”.

**Jau ieviestie aizsardzības pasākumi**:

- Visi `/api/services/*` maršruti ir LOCAL_ONLY atbilstoši
  `src/server/authz/routeGuard.ts` (stingrais noteikums #17). Atgriezeniskās
  cilpas pārbaude notiek pirms jebkuras autentifikācijas pārbaudes — nopludināts
  JWT nevar tiem piekļūt.
- 9router DB rinda tiek sākotnēji aizpildīta ar `status='not_installed', auto_start=0`
  (skatiet `src/lib/db/migrations/071_services.sql:19`). Pakalpojums pirmajā
  palaišanas reizē **netiek** startēts.
- `spawn()` tiek izsaukts ar binārā faila ceļu, ko atgriež
  `resolveSpawnArgs(apiKey, PORT)` failā `src/lib/services/installers/ninerouter.ts`;
  tas ir fiksēts atbalstīto bināro failu atļautais saraksts.
- Standarta izvade/kļūdu izvade tiek buferēta atmiņā (5 MB ierobežojums, skatiet
  `_lib.ts`) — diskā nekas netiek rakstīts, ja vien lietotājs informācijas panelī
  neiespējo žurnalēšanu.

**v3.8.6 riska mazināšana**: nav funkcionālu izmaiņu. Minimālais būvējuma
profils (`OMNIROUTE_BUILD_PROFILE=minimal`) aizstāj
`src/lib/services/installers/ninerouter.ts` ar aizvietotāju lietotājiem, kuri
vēlas fiziski izņemt privileģētos ceļus no pakotnes.

**Kāpēc mēs to saglabājam**: 9router ir neobligāts, lokāli instalējams
pavadošais pakalpojums (līdzīgs WordPress spraudnim) — tikai ar nepārprotamu
piekrišanu.

## §5 — OmniRoute Cloud Sync akreditācijas datu atpakaļierakstīšana (`api/keys/[id]/route.js`)

**Avota faili**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`.
- `src/app/api/keys/[id]/route.ts` — izsauc `syncKeysToCloudIfEnabled()`.

**Aktivizēšanas nosacījums**: `isCloudEnabled()` atgriež `true` (iestatīts informācijas panelī) **un**
ir konfigurēts `CLOUD_URL`. Ja abi ir izslēgti, netiek veikts neviens izejošs tīkla izsaukums uz
Cloud galapunktu.

**v3.8.5 darbība (kļūda, kuru Socket.dev pareizi konstatēja)**:

`updateLocalTokens()` pārrakstīja `accessToken`, `refreshToken` un
`providerSpecificData` ar Cloud atbildes datiem, ja
`cloudUpdatedAt > localUpdatedAt`. Bez HMAC, bez paraksta, bez kontrolsummas.
Nepareizi konfigurēts vai ļaunprātīgs `CLOUD_URL` (vai MITM šajā kanālā) varēja
nemanāmi aizstāt pakalpojumu sniedzēja OAuth marķierus.

**v3.8.6 risinājums**:

1. **HMAC pārbaude**: `verifyCloudSignature(rawBody, sigHeader)` pirms JSON parsēšanas pārbauda
   `X-Cloud-Sig` galveni (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`). Ja noslēpums ir iestatīts, paraksts ir obligāts. Ja tas nav
   iestatīts (mantotais režīms), tiek reģistrēts brīdinājums un atbilde tiek
   pieņemta — v3.9 noslēpums būs obligāts.
2. **Slepeno lauku izvēles iespējošana**: `accessToken` / `refreshToken` /
   `providerSpecificData` tiek pārrakstīti **tikai** tad, ja
   `OMNIROUTE_CLOUD_SYNC_SECRETS=true`. Noklusējuma režīmā tiek sinhronizēti
   tikai ar akreditācijas datiem nesaistīti metadati (`expiresAt`, `status`, `lastError*`,
   `rateLimitedUntil`, `updatedAt`). Šīs ir **nesaderīgas izmaiņas** lietotājiem,
   kuri paļāvās uz attālinātu marķieru sinhronizāciju — viņiem tā ir skaidri jāiespējo.

**Kāpēc mēs to saglabājam**: Cloud Sync ir vienīgais veids, kā OmniRoute Cloud nomnieks
var centralizēti pārvaldīt komandas akreditācijas datus. Labojums padara apdraudējumu modeli godīgu:
"serveris paraksta, klients pārbauda, operators izvēlas iespējot."

## Būvējuma profils: `minimal`

Lietotājiem, kuriem nepieciešams ar Socket saderīgs artefakts, jāveido ar:

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

Webpack `NormalModuleReplacementPlugin` aizstāj četrus moduļus ar aizstājējmoduļiem:

| Modulis                                     | Aizstājējmodulis                                 |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

Katrs aizstājējmodulis eksportē to pašu saskarni, taču izpildlaikā katra funkcija izmet
`featureDisabledError(name)`. Maršruti, kas ir atkarīgi no atspējotā
moduļa, atgriež HTTP 503 ar skaidru ziņojumu, nevis aktivizē sensitīvo
koda ceļu.

Iegūtais komplekts ir paredzēts publicēšanai kā `omniroute-secure`. Publicēšanas norādījumus
skatiet `docs/ops/PUBLISHING_SECURE.md`.

## Spraudņa sadalīšana (plānota v4 versijai)

Ilgtermiņā mēs plānojam sadalīt npm pakotni atsevišķi auditējamos
moduļos. Skatiet v4 atskaites punktu GitHub problēmu izsekotājā, lai atrastu izsekošanas
problēmu.
