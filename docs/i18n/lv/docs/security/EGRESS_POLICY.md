> **Piesaistiet izejošo datplūsmu vienai IP saimei — `auto`, `ipv4` vai `ipv6` — katram starpniekserverim, lai tikai IPv6 izeja nekad nemanāmi nepārslēgtos atpakaļ uz IPv4.**

> **Patiesības avots:** `open-sse/utils/proxyFamily.ts`, `open-sse/utils/proxyDispatcher.ts`, `open-sse/utils/proxyFetch.ts`, `open-sse/utils/socksConnectorWithFamily.ts`, `open-sse/utils/proxyFamilyResolve.ts`, `src/shared/validation/schemas.ts`, `src/lib/db/proxies.ts`, `src/lib/db/upstreamProxy.ts`, `src/lib/db/migrations/099_proxy_family.sql`

OmniRoute ļauj katram starpniekserverim piešķirt **adrešu saimes izejas direktīvu**. Pēc noklusējuma operētājsistēma izvēlas IPv4 vai IPv6 (duālais steks, „Happy Eyeballs”). Iestatot direktīvu uz `ipv4` vai `ipv6`, OmniRoute piesaista katru savienojumu caur šo starpniekserveri izvēlētajai saimei un **droši pārtrauc savienojumu**, nevis atkāpjas uz otru saimi.

Šajā lapā ir aprakstīts, kas ir šī direktīva, kāpēc tā pastāv, kur to konfigurēt un kā izpildlaikā tā tiek atrisināta.

## Kas tā ir

Katram reģistra starpniekserverim ir lauks `family` ar trim iespējamām vērtībām, kuras validē Zod uzskaitījums:

```ts
// src/shared/validation/schemas.ts
family: z.enum(["auto", "ipv4", "ipv6"]).optional().default("auto"),
```

Lauka noklusējuma vērtība ir `"auto"`, kas saglabā iepriekšējo duālā steka darbību. Iestatot to uz `ipv4` vai `ipv6`, šī starpniekservera savienojuma saime tiek piesaistīta attiecīgajai vērtībai.

Direktīva visur tiek normalizēta, izmantojot vienu palīgfunkciju, tāpēc jebkura nezināma vērtība tiek pārveidota par `auto`:

```ts
// open-sse/utils/proxyFamily.ts
export type ProxyFamily = "auto" | "ipv4" | "ipv6";

export function parseProxyFamily(value: unknown): ProxyFamily {
  return value === "ipv4" || value === "ipv6" ? value : "auto";
}
```

## Kāpēc tā pastāv

Ieviesta PR [#3777](https://github.com/diegosouzapw/OmniRoute/pull/3777). Galvenās problēmas, kuru dēļ tā tika ieviesta:

| Problēma                                                        | Ko direktīva novērš                                                                                                                                                                                                                                                                                                                                              |
| --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Tikai IPv6 izejas noplūde uz IPv4**                           | Ja starpniekservera resursdatoram ir gan A, gan AAAA ieraksti (vai operētājsistēma dod priekšroku IPv4), „Happy Eyeballs” var izveidot izejošo savienojumu, izmantojot IPv4, pat ja ir paredzēts tikai IPv6 ceļš. Piesaistīšana `ipv6` novērš šo noplūdi.                                                                                                        |
| **Anomāliju dēļ atsaukta koplietota izeja**                     | Rotējošie pakalpojumu sniedzēji (codex/openai) atsauc pilnvaras, ja daudzi konti lielā apjomā izmanto izeju caur **vienu un to pašu** IP adresi. Izejas saimes kontrolēšana palīdz uzturēt kontus atšķirīgos, paredzamos izejas ceļos (skatiet [`src/lib/proxyEgress.ts`](../../src/lib/proxyEgress.ts), lai uzzinātu par ar to saistīto izejas IP diagnostiku). |
| **Deterministiska izeja atbilstības nodrošināšanai/testēšanai** | Ja ir jāgarantē, ka datplūsma iziet, izmantojot konkrētu saimi, ar `auto` nepietiek.                                                                                                                                                                                                                                                                             |

Direktīva ir apzināti paredzēta **katram starpniekserverim atsevišķi**, nevis globāli — dažādiem starpniekserveriem jūsu pūlā var būt atšķirīgas politikas.

## Trīs vērtības

| Vērtība | UI etiķete                 | Darbība                                                                                                                                                                                   |
| ------- | -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`  | `Automātiski (duālā kopa)` | OS izvēlas saimi. Ja starpniekservera resursdators ir norādīts kā IP literālis, saimi nosaka pats literālis; resursdatora nosaukumam ir pieejamas abas saimes. Šī ir noklusējuma vērtība. |
| `ipv4`  | `Tikai IPv4`               | Piesaista savienojumu IPv4. Savienojums netiek izveidots, ja starpniekservera resursdatoram nav IPv4 (A) ieraksta.                                                                        |
| `ipv6`  | `Tikai IPv6`               | Piesaista savienojumu IPv6. Savienojums netiek izveidots, ja starpniekservera resursdatoram nav IPv6 (AAAA) ieraksta.                                                                     |

UI virknes atrodas failā `src/i18n/messages/en.json` (`labelFamily`, `familyAuto`, `familyIpv4`, `familyIpv6`, `familyHint`).

## Kā to konfigurēt

### Informācijas panelis

Atlasītājs atrodas cilnes **Starpniekserveru pūls** starpniekservera veidlapā:

1. Atveriet **Informācijas panelis → Iestatījumi → Starpniekserveris → Starpniekserveru pūls**
2. Pievienojiet vai rediģējiet starpniekserveri
3. Iestatiet nolaižamajā sarakstā **IP saime** vērtību `Automātiski (duālā kopa)`, `Tikai IPv4` vai `Tikai IPv6`
4. Saglabājiet

Vadīklu atveido `ProxyRegistryManager.tsx` (montēts failā `proxy/ProxyPoolTab.tsx`).

### API

Lauks `family` ir daļa no starpniekserveru reģistra izveides/atjaunināšanas lietderīgajām slodzēm; to validē `createProxyRegistrySchema` / `updateProxyRegistrySchema` (`src/shared/validation/schemas.ts`) un apstrādā `POST` / `PATCH /api/v1/management/proxies`:

```bash
# Izveidot starpniekserveri, kas izmanto tikai IPv6
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "IPv6 egress",
    "type": "socks5",
    "host": "proxy.example.com",
    "port": 1080,
    "family": "ipv6"
  }'

# Mainīt esošu starpniekserveri, lai tas izmantotu tikai IPv4
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{ "id": "proxy-uuid-here", "family": "ipv4" }'
```

To pašu lauku pieņem arī iekļautais starpniekservera konfigurācijas objekts, kas tiek izmantots augšupstraumes starpniekservera ierakstiem (`upstream_proxy_config.family`; skatiet sadaļu [Datu modelis](#data-model)).

Informāciju par pārējo starpniekserveru CRUD/piešķiršanas API skatiet failā [PROXY_GUIDE.md](../ops/PROXY_GUIDE.md).

## Kā tiek atrisināta vērtība `auto`

Ja `family` vērtība ir `auto`, OmniRoute **nepievieno** nevienu direktīvu — starpniekservera URL tiek izmantots bez izmaiņām, un savienojuma saime tiek noteikta iekšēji.

URL izveides laikā (`proxyConfigToUrl` / `normalizeProxyUrl` failā `open-sse/utils/proxyDispatcher.ts`) starpniekserverim ar vērtību `auto` tiek izveidots vienkāršs URL bez marķiera:

```ts
// open-sse/utils/proxyDispatcher.ts
const fam = parseProxyFamily(config.family);
const normalized = normalizeProxyUrl(proxyUrlStr, "context proxy", {
  allowSocks5,
});
return fam === "auto" ? normalized : `${normalized}?family=${fam}`;
```

Nosūtīšanas laikā (`resolveDispatcherFamily`) vērtība `auto` tiek atrisināta kā IP literāļa resursdatora iekšējā saime vai kā `null` (ļaujot OS izlemt), ja izmantots resursdatora nosaukums:

```ts
// open-sse/utils/proxyDispatcher.ts
function resolveDispatcherFamily(parsed: URL): 4 | 6 | null {
  const directive = parseProxyFamily(parsed.searchParams.get("family") ?? undefined);
  const literal = detectIpLiteralFamily(parsed.hostname);
  if (directive === "auto") return literal; // Resursdatora nosaukumam null → izvēlas OS
  // ...
}
```

Tātad:

- `auto` + IP literāļa resursdators (`192.0.2.1` / `[2001:db8::1]`) → šī literāļa saime.
- `auto` + resursdatora nosaukums → `null` → standarta duālās kopas OS atrisināšana.

## Kā tiek uzspiesta `ipv4` / `ipv6` izmantošana

Direktīva, kas nav `auto`, tiek nodota kā viens sintētisks vaicājuma marķieris — `?family=ipv4` vai `?family=ipv6` —, kas vienu reizi tiek pievienots normalizētajam starpniekservera URL. `normalizeProxyUrl` rūpīgi noņem un atkārtoti pievieno šo marķieri tieši vienu reizi, lai tas nekad nesabojātu porta parsēšanu.

Kad tiek izveidots dispečers, marķieris tiek nolasīts un pārveidots par konkrētu savienojuma adrešu saimi. Ja resursdators ir **pretējās** saimes IP literālis, OmniRoute izmet kļūdu (pretrunas gadījumā darbība tiek droši pārtraukta):

```ts
// open-sse/utils/proxyDispatcher.ts
const want = directive === "ipv6" ? 6 : 4;
if (literal !== null && literal !== want) {
  throw new Error(
    `[ProxyDispatcher] Proxy family directive ${directive} contradicts ${literal === 6 ? "IPv6" : "IPv4"} literal host`
  );
}
```

Pēc tam konkrētā saime tiek fiksēta savienotājā:

- **HTTP/HTTPS starpniekserveri** (`ProxyAgent`): `proxyTls: { family, autoSelectFamily: false }` — atspējo Happy Eyeballs, lai savienojums tiktu veidots tikai ar izvēlēto saimi.
- **SOCKS5 starpniekserveri**: pielāgots savienotājs nodod `socket_options: { family, autoSelectFamily: false }` SOCKS klientam (skatiet [SOCKS5 saderība](#socks5-compatibility)).

## SOCKS5 saderība

Saimes fiksēšana darbojas ar SOCKS5 starpniekserveriem, taču standarta `fetch-socks` neatklāj ligzdas opcijas, kas nepieciešamas starpniekservera posma saimes fiksēšanai. Šim nolūkam OmniRoute ietver savu savienotāju:

```ts
// open-sse/utils/socksConnectorWithFamily.ts
export function buildSocksFamilySocketOptions(family: 4 | 6 | null): Record<string, unknown> {
  if (family === 6) return { family: 6, autoSelectFamily: false };
  if (family === 4) return { family: 4, autoSelectFamily: false };
  return {};
}
```

Visi SOCKS5 pieprasījumi tiek virzīti caur `createSocksDispatcherWithFamily` neatkarīgi no `family` vērtības (tostarp `null` / `auto`, izmantojot resursdatora nosaukumu): `buildSocksFamilySocketOptions(null)` atgriež `{}`, un tiek izmantots tas pats `SocksClient.createConnection` + TLS `buildConnector` ceļš ar `socket_options` fiksēšanu, lai Happy Eyeballs nevarētu izvēlēties IPv4 izvadpolitikai, kas atļauj tikai IPv6.

Pats SOCKS5 atbalsts pēc noklusējuma ir iespējots (no tā var atteikties ar `ENABLE_SOCKS5_PROXY=false`); skatiet [PROXY_GUIDE.md → Vides mainīgie](../ops/PROXY_GUIDE.md#environment-variables).

## Drošas pārtraukšanas darbība

Direktīvas galvenais mērķis ir **atteikt**, nevis nemanāmi atkāpties uz nepareizo saimi. To nodrošina divas pārbaudes:

1. **Literāļa pretruna** — direktīva, kas ir pretrunā ar IP literāļa resursdatoru, dispečera izveides laikā izmet kļūdu (`resolveDispatcherFamily`, parādīts iepriekš).

2. **Resursdatora nosaukuma sākotnējā DNS pārbaude** — starpniekserverim ar resursdatora nosaukumu un fiksētu saimi `proxyFetch.ts`, izmantojot `assertHostnameSupportsFamily`, **pirms** izejošā savienojuma izveides pārbauda, vai resursdatora nosaukumam tiešām ir nepieciešamās saimes ieraksts:

   ```ts
   // open-sse/utils/proxyFamilyResolve.ts
   const hasFamily = records.some((r) => r.family === family);
   if (!hasFamily) {
     throw new Error(
       `[ProxyFamily] Proxy host ${host} has no ${family === 6 ? "IPv6 (AAAA)" : "IPv4 (A)"} record; ` +
         `refusing ${family === 6 ? "IPv6" : "IPv4"}-only egress (fail-closed)`
     );
   }
   ```

   Neveiksmes gadījumā `proxyFetch.ts` kļūdai piešķir `code = "PROXY_FAMILY_UNAVAILABLE"` un `statusCode = 503`. Arī DNS atrisināšanas kļūme tiek apstrādāta, droši pārtraucot darbību (izejošais savienojums tiek atteikts).

IP literāļu resursdatoriem sākotnējā DNS pārbaude neko neveic — to saime ir tiem raksturīga, un uzmeklēšana nav nepieciešama.

## Datu modelis

Kolonna `family` ar migrāciju `099_proxy_family.sql` tika pievienota **divām** tabulām:

```sql
-- src/lib/db/migrations/099_proxy_family.sql
ALTER TABLE proxy_registry ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
ALTER TABLE upstream_proxy_config ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
```

- `proxy_registry.family` — katram starpniekserverim noteiktā direktīva reģistra ierakstos (`src/lib/db/proxies.ts`). Atrisināšanas vaicājumi atlasa `family` kopā ar pārējām starpniekservera kolonnām, un trūkstoša vērtība vai vērtība, kas nav virkne, tiek pārveidota par `"auto"`.
- `upstream_proxy_config.family` — direktīva augšupējo starpniekserveru ierakstiem (`src/lib/db/upstreamProxy.ts`) ar tādu pašu noklusējuma vērtību `"auto"`.

Ja atrisinātā starpniekservera objekta `family` vērtība nav `auto`, `proxyConfigToUrl` pievieno marķieri `?family=`, lai fiksētā izvēle tiktu saglabāta līdz pat dispečeram.
