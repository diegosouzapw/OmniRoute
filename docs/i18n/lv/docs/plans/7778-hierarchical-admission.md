1. Nostipriniet esošo vienas atslēgas semafora līgumu un jauno atomāro vairāku atslēgu līgumu ar mērķētiem testiem: nekādu daļēju rezervāciju, FIFO rindošana, pārtraukšana, noildze, pilna rinda, idempotenta atbrīvošana, statistika un tīrīšana.
2. Vispāriniet esošo konta semaforu uz vietas. Saglabājiet `acquire()` kā saderības ietvarfunkciju ap `acquireMany()`; nepievienojiet otru plānotāju vai atkarību.
3. Aizstājiet tikai kontam paredzēto iegūšanu `chatCore` ar vienu kumulatīvu globālu/pakalpojumu sniedzēja/konta iegūšanu tieši pirms `withRateLimit`. Ikreiz, kad konta rotācija maina savienojumu, atkārtoti iegūstiet visu kopu un saglabājiet atbrīvošanu līdz straumēšanas pabeigšanai.
4. Paplašiniet esošo noturības iestatījumu konveijeru (tipus, noklusējuma vērtības, normalizāciju, shēmu, API atbildi, lietotāja saskarni un tulkojumus) ar globālajiem un pakalpojumu sniedzēja ierobežojumiem. Pārdēvējiet veco Bottleneck vienlaicīguma vadīklu par savienojuma/kvotas tvēruma vienlaicīguma vadīklu, lai skaidri norādītu tās faktisko tvērumu.
5. Palaidiet mērķētos testus, lintēšanu, tipu pārbaudi, statiskās pārbaudes un pilno testu komplektu; dokumentējiet darbības izmaiņas izmaiņu žurnālā.

Apzināti saglabātā darbība: nulles/null vienlaicīgums apiet vārteju, tikai kontam paredzētie izsaucēji turpina izmantot `acquire()`, bloķēto kontu vadīklas saglabā savu atslēgas formātu un API, un pakalpojumu sniedzēja ātruma ierobežojuma rindas darbība paliek nemainīga.
