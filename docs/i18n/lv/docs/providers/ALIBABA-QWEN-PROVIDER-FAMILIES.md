Šajā dokumentā ir fiksēts ieviešanas lēmums saistībā ar
[problēmu #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854). Publiskie produkti ir
attēloti kā četras pakalpojumu sniedzēju saimes. Reģions ir savienojuma dati, nevis atsevišķs produkts.

## Lēmums

| Pakalpojumu sniedzēja saime                      | OmniRoute ID            | Globālais reģions | Ķīnas reģions |
| ------------------------------------------------ | ----------------------- | ----------------- | ------------- |
| Alibaba Cloud Model Studio (maksa par lietojumu) | `alibaba`               | Singapūra         | Pekina        |
| Alibaba Cloud Token Plan                         | `bailian-coding-plan`   | Singapūra         | Pekina        |
| Qwen Cloud (maksa par lietojumu)                 | `qwen-cloud`            | Globāls           | Pekina        |
| Qwen Cloud Token Plan                            | `qwen-cloud-token-plan` | Singapūra         | Pekina        |

Esošais `alibaba-cn` ID joprojām ir izpildlaika saderības aizstājvārds saglabātajiem savienojumiem, modeļu
maršrutiem, kombinācijām un vēsturiskajiem lietojuma datiem. Tā informācijas paneļa kartīte ir apvienota ar `alibaba`;
datubāzes pārrakstīšana nav nepieciešama.

Qwen Cloud produkts ar maksu par lietojumu un Alibaba Cloud Model Studio pašlaik koplieto ar DashScope saderīgus
izpildlaika resursdatorus, taču tie joprojām ir atsevišķas pakalpojumu sniedzēju identitātes, jo lietotāji iegūst atslēgas un pārvalda
kontus dažādās produktu saskarnēs. Alibaba un Qwen Cloud Token Plan produkti izmanto
atšķirīgas galapunktu saimes, tādēļ visi četri produkti joprojām izmanto atsevišķus pakalpojumu sniedzēju ID.

## Galapunktu matrica

| Pakalpojumu sniedzēja saime | `global-sg`                                                              | `china-beijing`                                                      | Datu formāts |
| --------------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ------------ |
| `alibaba`                   | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI       |
| `bailian-coding-plan`       | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic    |
| `qwen-cloud`                | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI       |
| `qwen-cloud-token-plan`     | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI       |

API atslēgai un galapunktam ir jāpieder vienam un tam pašam produktam un reģionam. Izvēloties reģionu, tiek mainīts
iepriekšiestatītais galapunkts, ko izmanto validācijai un parastajiem pieprasījumiem.

## Savienojuma kontrakts

Jaunajos savienojumos stabilā reģiona atslēga tiek glabāta laukā `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

Atļautās vērtības ir `global-sg` un `china-beijing`. Galapunkts tiek centralizēti atvasināts no
pakalpojumu sniedzēja ID un reģiona. Laukā `providerSpecificData.baseUrl` norādīta vērtība, kas neatbilst iepriekšiestatījumam, joprojām ir nepārprotama operatora
ignorēšanas vērtība, un tai ir prioritāte, savukārt iepriekš saglabātie iepriekšiestatījumu URL tiek normalizēti atbilstoši reģionālajai
matricai.

Tādējādi savienojuma shēma paliek paplašināma: risinātājam var pievienot vēl vienu reģionu, neveidojot
citu pakalpojumu sniedzēja kartīti un nemainot saglabātos pakalpojumu sniedzēju ID.

## Saderība un ieviešana

1. Pievienojiet reģionālo galapunktu atrisinātāju un saglabājiet pašreizējos globālos noklusējumus.
2. Izmantojiet reāllaika reģionālo DashScope `/models` atklāšanu pakalpojumam `alibaba`, tā saderības
   ID `alibaba-cn` un `qwen-cloud`. To atbildēm vispirms tiek lietots teksta ģenerēšanas filtrs, jo vispārīgais
   galapunkts atgriež arī attēlu, video, audio, iegulumu un citus ar tērzēšanu nesaistītus modeļus. Pēc tam `qwen-cloud`
   lieto uzturēto atļauto modeļu sarakstu, kas deklarēts tā nodrošinātāja reģistrā. Alibaba Model Studio
   un Qwen Cloud saglabā atsevišķus pārvaldītus katalogus, lai gan pašlaik tie izmanto kopīgus izpildlaika resursdatorus.
3. Reģistrējiet `qwen-cloud-token-plan` ar pašreizējo Token Plan teksta modeļu atļauto sarakstu.
4. Pievienojiet tipizētu reģiona atlasītāju savienojumu pievienošanas/rediģēšanas dialogiem.
5. Paslēpiet dublējošo `alibaba-cn` kartīti un iekļaujiet tās esošos savienojumus `alibaba`
   nodrošinātāja lapā.
6. Saglabājiet pielāgotu galapunktu pārrakstīšanas iespēju pieredzējušiem un darbvietai specifiskiem izvietojumiem.

Token Plan multivides modeļi netiek iekļauti tērzēšanas katalogā, jo tie izmanto īpašus galapunktus.
`wan2.7-image` un `wan2.7-image-pro` ir reģistrēti failā `open-sse/config/imageRegistry.ts`;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` un `happyhorse-1.1-r2v` ir reģistrēti failā
`open-sse/config/videoRegistry.ts`. Abi reģistri atkārtoti izmanto `qwen-cloud-token-plan` savienojuma
identitāti un tā reģionam specifiskos akreditācijas datus.

Parastajam Qwen Cloud ir atsevišķi attēlu un video katalogi ar lietošanas apjoma norēķiniem zem `qwen-cloud`
identitātes. Tā attēlu modeļi ir `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` un `z-image-turbo`. Tā video
modeļi ir `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` un
`wan2.7-videoedit`. Šie modeļi atkārtoti izmanto tikai parasto `qwen-cloud` savienojumu un reģionālo
DashScope multivides galapunktu. Token Plan un lietošanas apjoma norēķinu reģistri nemanto un neapvieno
viens otra modeļu sarakstus.

Arī `bailian-coding-plan` identitātei ir savi multivides atļautie saraksti:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` un `qwen-image-2.0-pro` attēlu
ģenerēšanai, kā arī
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` un `happyhorse-1.1-r2v` video
ģenerēšanai. Tā izmanto tikai Bailian Coding Plan savienojumu un reģionālo Coding Plan galapunktu.
Tās attēlu un video reģistri nemanto un netiek apvienoti ne ar vienu Qwen Cloud nodrošinātāju.

Parastajai `alibaba` identitātei ir atsevišķi attēlu un video atļautie saraksti. Tās attēlu modeļi ir
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` un `wan2.6-t2i`. Tās pievienotie video modeļi ir `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` un `wan2.7-videoedit`. Šie modeļi izmanto tikai Alibaba Model Studio
savienojumu un tā atlasīto reģionālo multivides galapunktu; tie netiek pievienoti nevienam Coding Plan vai Qwen
Cloud reģistram.

Qwen Cloud Token Plan tērzēšanas katalogs izmanto Individual plāna precīzo teksta modeļu atļauto sarakstu:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` un
`deepseek-v4-pro`. Wan un HappyHorse ieraksti pieder atsevišķajām attēlu/video ģenerēšanas API.

Alibaba Token Plan nodrošina tos pašus sešus pašreizējos teksta ģenerēšanas modeļu ID, izmantojot tā
ar Anthropic saderīgo galapunktu. Tā Singapūras opcija saglabā esošo `global-sg` reģiona atslēgu;
no nodrošinātāju saimēm, kas reģionu dēvē par Global, atšķiras tikai lietotājam redzamā etiķete.

Parastais Qwen Cloud tērzēšanas katalogs ar nolūku ir šaurāks nekā pilnā reāllaika teksta atbilde. Tā
uzturētais atļautais saraksts atrodas failā `open-sse/config/providers/registry/qwen-cloud/index.ts`; reāllaika
atklāšana atgriež tikai tos ID, kas ir gan augšupstraumes atbildē, gan šajā reģistra sarakstā.

Alibaba Model Studio izmanto to pašu reāllaika šķēluma kārtulu ar savu neatkarīgi uzturēto
atļauto sarakstu failā `open-sse/config/providers/registry/alibaba/index.ts`. `alibaba-cn` saderības
nodrošinātājs atkārtoti izmanto šo katalogu, vienlaikus atklāšanu novirzot uz Pekinas galapunktu.
