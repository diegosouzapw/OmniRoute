> **Īsumā**: OmniRoute sarindo savus **bezmaksas** pakalpojumu sniedzējus pēc modeļu kvalitātes, izmantojot **Arena AI
> (LMArena stila) ELO vērtējumus**. Informācijas panelī atveriet lapu **Bezmaksas pakalpojumu sniedzēju reitings**, lai uzzinātu, kuri bezmaksas pakalpojumu sniedzēji piedāvā jūsu uzdevumam vislabākos modeļus —
> kopumā vai filtrējot pēc kategorijas (programmēšana, pārskatīšana, dokumentācija, atkļūdošana).

---

## Kas tas ir

OmniRoute reģistrē 329 pakalpojumu sniedzējus, tostarp 155 kataloga ierakstus, kas atzīmēti kā **bezmaksas/bez autentifikācijas**
(bez autentifikācijas,
bezmaksas līmeņa OAuth vai bezmaksas līmeņa API atslēga — skatiet
[Bezmaksas līmeņu ceļvedi](../getting-started/FREE-TIERS-GUIDE.md) un pilno
[Bezmaksas līmeņu direktoriju](../reference/FREE_TIERS.md)). Taču bezmaksas pakalpojumu sniedzēju
modeļu kvalitāte ievērojami atšķiras. Pakalpojumu sniedzējs bez autentifikācijas, kas piedāvā progresīvu modeli, ir daudz noderīgāks
par tādu, kas piedāvā nelielu, novecojušu modeli.

**Bezmaksas pakalpojumu sniedzēju reitings** atbild uz jautājumu "**kurš bezmaksas pakalpojumu sniedzējs man piedāvā labāko modeli?**",
apvienojot katra bezmaksas pakalpojumu sniedzēja katalogu ar **kolektīvi iegūtiem kvalitātes vērtējumiem** no
**Arena AI līderu tabulas** (uz cilvēku preferencēm balstīts ELO — tā pati ideja, kas izmantota LMArena
tērzēšanas robotu arēnā). Pēc tam pakalpojumu sniedzēji tiek sarindoti pēc to **labākā bezmaksas modeļa** kvalitātes.

Reitings tiek aprēķināts no trim reāliem avotiem:

1. Bezmaksas pakalpojumu sniedzēju saraksti — `NOAUTH_PROVIDERS`, kā arī `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` ieraksti ar atzīmi `hasFree`
   (`src/shared/constants/providers.ts`).
2. Katra pakalpojumu sniedzēja modeļu katalogs no pakalpojumu sniedzēju reģistra
   (`open-sse/config/providerRegistry.ts`).
3. No ELO atvasināti piemērotības konkrētiem uzdevumiem vērtējumi, kurus Arena ELO sinhronizācijas dzinis glabā
   datubāzes tabulā `model_intelligence` (`src/lib/arenaEloSync.ts`).

Apvienošanas loģika atrodas failā `src/lib/freeProviderRankings.ts`.

## Kā piekļūt

### Informācijas paneļa lapa

Atveriet informācijas paneli un dodieties uz **Izmaksas → Bezmaksas pakalpojumu sniedzēju reitings** vai pārejiet tieši uz:

```
/dashboard/free-provider-rankings
```

Lapā (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) ir redzams:

- Labāko trīs bezmaksas pakalpojumu sniedzēju **pjedestāls** (🥇 🥈 🥉).
- Pilna **reitinga tabula** ar kolonnām: **Vieta**, **Pakalpojumu sniedzējs**, **Labākais modelis**,
  **Vērtējums**, **Vidējais vērtējums**, **Modeļi**, **Tips**.
- **Kategoriju filtra pogas**: _Visas kategorijas_, _Noklusējuma_, _Programmēšana_, _Pārskatīšana_,
  _Dokumentācija_, _Atkļūdošana_.

Katra pakalpojumu sniedzēja **Tipa** emblēma norāda, kādā veidā tas ir pieejams bez maksas:

| Emblēma  | Nozīme                                                             |
| -------- | ------------------------------------------------------------------ |
| `NOAUTH` | Vienmēr bez maksas, akreditācijas dati nav nepieciešami            |
| `OAUTH`  | OAuth pakalpojumu sniedzējs ar bezmaksas līmeni (`hasFree`)        |
| `APIKEY` | API atslēgas pakalpojumu sniedzējs ar bezmaksas līmeni (`hasFree`) |

Vērtējumi tiek rādīti kā cilvēkiem saprotami apzīmējumi (piemēram, _Elitārs_, _Izcils_, _Ļoti labs_,
_Labs_, _Vidējs_), nevis kā neapstrādāti skaitļi, jo pamatā esošā vērtība ir relatīvs
kvalitātes reitings, nevis procentuāls rādītājs.

### API galapunkts

Lapu nodrošina publisks lasīšanas galapunkts
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

Vaicājuma parametri (validēti ar Zod):

| Parametrs  | Tips     | Noklusējums | Piezīmes                                                                                                                     |
| ---------- | -------- | ----------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `category` | virkne   | (nav)       | Viena no vērtībām: `default`, `coding`, `review`, `documentation`, `debugging`. Neiekļaujiet, lai iegūtu apvienoto reitingu. |
| `limit`    | skaitlis | `50`        | Ierobežots diapazonā `1–100`.                                                                                                |

Atbildes struktūra:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` ir sākotnējā Arena ELO vērtība; `score` ir normalizētā piemērotības konkrētam uzdevumam vērtība
(skatiet tālāk). Pakalpojumu sniedzēji, kuriem nav novērtētu modeļu, atbildē netiek iekļauti.

## Kā darbojas vērtējumi

### Avots: Arena AI līderu tabula

Arena ELO sinhronizācijas dzinis (`src/lib/arenaEloSync.ts`) iegūst divas līderu tabulas — `text`
un `code` — no Arena AI līderu tabulas API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`). Katrā līderu tabulas ierakstā
ir modeļa nosaukums, piegādātājs, ELO `score`, ticamības intervāls un balsu skaits.

Līderu tabulas kategorijas atbilst OmniRoute uzdevumu kategorijām:

| Arena līderu tabula | OmniRoute uzdevumu kategorijas                    |
| ------------------- | ------------------------------------------------- |
| `text`              | `default`, `review`, `documentation`, `debugging` |
| `code`              | `coding`                                          |

### Normalizācija (piemērotības uzdevumam vērtējums)

Neapstrādātie ELO vērtējumi katrā līderu tabulā tiek normalizēti par **piemērotības uzdevumam vērtību diapazonā `[0.4, 0.98]`**:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

Vērtējums nekad nesasniedz `0` vai `1`, atstājot rezervi lietotāja norādītām vērtībām. Šis ir
`score` lauks, kas redzams API atbildē, un informācijas paneļa etiķetē parādītā vērtība.

### Pārliecības līmenis

Katram ierakstam tiek piešķirts pārliecības līmenis, pamatojoties uz Arena balsu skaitu:

| Pārliecības līmenis | Balsis  |
| ------------------- | ------- |
| `high`              | ≥ 5,000 |
| `medium`            | ≥ 1,000 |
| `low`               | < 1,000 |

### Glabāšana un datu aktualitāte

Normalizētie ieraksti tiek saglabāti datubāzes tabulā `model_intelligence` ar
`source = "arena_elo"` (`src/lib/db/modelIntelligence.ts`). Ierakstu derīguma termiņš **beidzas pēc
7 dienām**, tāpēc piegādātājs, kura sinhronizācija tiek pārtraukta, ar laiku pazūd, nevis turpina
piedāvāt novecojušus datus.

Sinhronizācija ir **ieslēgta pēc noklusējuma**:

- Tā tiek izpildīta vienreiz servera palaišanas laikā un pēc tam periodiski pēc taimera
  (`src/lib/arenaEloSync.ts`, piesaistīta no `src/instrumentation-node.ts`).
- Tā ir **nebloķējoša un nekad neizraisa fatālu kļūdu** — ja datu iegūšana no ārējā avota neizdodas, OmniRoute turpina
  darboties, un rangos tiek rādīti pēdējie veiksmīgi iegūtie dati (vai tukšs stāvoklis).

To kontrolē divi vides mainīgie (dokumentēti
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)):

| Mainīgais                 | Noklusējums   | Nolūks                                                         |
| ------------------------- | ------------- | -------------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | Iestatiet uz `false`, lai atteiktos no ārējās sinhronizācijas. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | Sinhronizācijas intervāls sekundēs.                            |

### Manuāla sinhronizācija / statuss / notīrīšana

Operatoriem autentificēts pārvaldības galapunkts nodrošina manuālu vadību
(`src/app/api/intelligence/sync/route.ts` — nepieciešama pārvaldības autentifikācija):

```
GET    /api/intelligence/sync          # pašreizējais sinhronizācijas statuss (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # aktivizē manuālu sinhronizāciju; pamatteksts: { "dryRun": true }, lai priekšskatītu bez ierakstīšanas
DELETE /api/intelligence/sync          # notīra visus sinhronizētos arena_elo analītikas ierakstus
```

Ja rangu lapa ir tukša, manuāls `POST /api/intelligence/sync` (vai vienkārši
servera restartēšana) to aizpilda no jauna.

### Modeļu atbilstības noteikšana līderu tabulai

Reģistra modeļu ID un Arena modeļu nosaukumi ne vienmēr precīzi sakrīt. Rangu noteikšanai tiek izmantota
elastīga atbilstības noteikšana (`findMatchingIntelligence` failā `src/lib/freeProviderRankings.ts`):

1. Precīza atbilstība normalizētajam modeļa ID.
2. Atbilstība pēc beigu versijas sufiksa noņemšanas (piemēram, `kimi-k2.6` → `kimi-k2`).
3. Prefiksa atbilstība (līderu tabulas modeļa nosaukums ir reģistra ID prefikss).

Sinhronizācijas pusē zināmie piegādātāju prefiksi (`anthropic/`, `openai/`, `google/`, …) tiek
noņemti, un neliela aizstājvārdu karte izvērš kanoniskos nosaukumus par variantiem, kurus OmniRoute izmanto
iekšēji, lai modeļus varētu atrast ar jebkuru nosaukumu.

### Kā tiek noteikts piegādātāja rangs

Katram bezmaksas piegādātājam dzinis novērtē katru tā kataloga modeli un pēc tam nosaka:

- **Labākais modelis** = piegādātāja modelis ar visaugstāko vērtējumu.
- **Vidējais vērtējums** = visu šī piegādātāja novērtēto modeļu vidējais vērtējums.
- **Modeļi** = to piegādātāja modeļu skaits, kuriem bija pieejams Arena vērtējums.

Piegādātāji vispirms tiek kārtoti pēc **labākā modeļa vērtējuma**, bet pēc tam — pēc vidējā vērtējuma. Tādējādi tiek atalgots
piegādātājs, kas piedāvā vismaz vienu spēcīgu bezmaksas modeli.

## Izmantošana bezmaksas pakalpojumu sniedzēju izvēlei

1. **Izvēlieties pareizo kategoriju.** Aģentu/koda darba slodzēm izmantojiet filtru **Coding**, bet
   vispārīgai tērzēšanai atstājiet **All Categories** / **Default**. Vienam un tam pašam pakalpojumu sniedzējam
   dažādās kategorijās var būt atšķirīga vieta, jo katrā līderu sarakstā atšķiras tā labākais modelis.
2. **Vienreizējai iestatīšanai dodiet priekšroku godalgoto vietu ieguvējiem.** Ja vēlaties pieslēgt tikai vienu vai divus bezmaksas
   pakalpojumu sniedzējus, sāciet ar savā kategorijā visaugstāk novērtētajiem.
3. **Pārbaudiet tipa emblēmu.** `NOAUTH` pakalpojumu sniedzējus var pieslēgt visātrāk (nav nepieciešami
   akreditācijas dati). `OAUTH` / `APIKEY` bezmaksas līmeņiem nepieciešama ātra reģistrācija, taču tie bieži nodrošina
   jaudīgākus modeļus. Savienojuma izveides norādījumus skatiet [Bezmaksas līmeņu ceļvedī](../getting-started/FREE-TIERS-GUIDE.md).
4. **Pieslēdziet vairākus pakalpojumu sniedzējus un ļaujiet Auto-Combo izlemt.** Tie paši Arena ELO dati, kas nodrošina
   šīs lapas darbību, tiek izmantoti arī kā **uzdevuma piemērotības faktors** Auto-Combo vērtēšanas dzinējā
   (`open-sse/services/autoCombo/taskFitness.ts`, noteikšanas secība:
   `user_override → arena_elo → models_dev_tier → static table`). Tādēļ pēc labāko bezmaksas pakalpojumu sniedzēju
   pieslēgšanas maršrutēšana ar `model: "auto"` (piem., `auto/coding`) katram pieprasījumam
   automātiski dos priekšroku kvalitatīvākiem bezmaksas modeļiem. Pilnu 16 faktoru vērtēšanas aprakstu skatiet sadaļā
   [Auto-Combo](../routing/AUTO-COMBO.md).
