OmniRoute piedāvā **divus** veidus, kā izmantot OpenAI Codex:

| Nodrošinātājs          | Kā tas sazinās ar OpenAI                                                                                                                                                                       | Lietošanas atruna                                                                     |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| **`codex`**            | Tieši atkārtoti izmanto jūsu ChatGPT/OpenAI OAuth pilnvaru ar Responses API                                                                                                                    | **Jā** — oficiālā sesija nav pilnvarota izmantošanai ar starpniekserveri/maršrutētāju |
| **`codex-app-server`** | Vada **Codex CLI paša `codex app-server`**, izmantojot JSON-RPC/WebSocket; CLI pārvalda un automātiski atsvaidzina savu OAuth (`~/.codex/auth.json`) tieši tāpat kā interaktīvā `codex` sesijā | **Nē** — OmniRoute nekad atkārtoti neizmanto pilnvaru ar API                          |

Tā kā `codex-app-server` nekad atkārtoti neizmanto pilnvaru, uz to neattiecas
sesijas atkārtotas izmantošanas atruna. Tam ir nepieciešams **Codex CLI, kas
sasniedzams konfigurētajā app-server URL**, un šajā CLI ir jābūt **veiktai
pierakstīšanai**.

---

## 1. Arhitektūra

```
┌─ OmniRoute lietotne ─────────────┐        ┌─ codex-app-server blakusprocess ────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ iespēju pilnvara)             │  JSON  │  --ws-auth iespēju-pilnvara         │
│                                  │  RPC   │  patstāvīgi pārvalda OpenAI OAuth   │
└──────────────────────────────────┘        │  (~/.codex/auth.json, autom. atsvaidz.)│
        │ koplietots (compose sējumi)        └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → WS iespēju pilnvara (to montē abi)
  codex-appserver-home    → ~/.codex (auth.json ieraksta informācijas panelis,
                             bet lasa blakusprocesa codex app-server)
```

- Blakusprocess klausās **tikai** iekšējā compose tīklā
  (`ws://codex-app-server:1456`), aizsargāts ar iespēju pilnvaru. Tas **nekad**
  netiek publicēts resursdatorā vai internetā.
- Codex CLI ir iekļauts `omniroute:base`, tāpēc, palaižot blakusprocesu,
  resursdatorā vai lietotāja ierīcē nav jāinstalē codex.

## 2. Palaišana

```bash
# Palaidiet steku AR codex app-server blakusprocesa profilu:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

Pirmajā palaišanas reizē blakusprocess izveido savu WS iespēju pilnvaru
(koplietotajā `codex-appserver-token` sējumā), un lietotne nolasa to pašu pilnvaru,
izmantojot `OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE`. Manuāla pilnvaras
konfigurēšana nav nepieciešama.

## 3. Savienošana un pierakstīšanās

1. Informācijas panelī pievienojiet savienojumu ar **OpenAI Codex (App-Server)**.
   API atslēga vai pilnvara nav nepieciešama (tas ir nodrošinātājs bez
   autentifikācijas — autentifikāciju pārvalda blakusprocess).
2. Ja blakusprocesa Codex CLI vēl **nav pierakstīts**, savienojuma darbspējas
   pārbaude ziņo _"darbojas, bet nav pierakstīts"_ (nevis parāda sarkanu
   autentifikācijas kļūdu). Izmantojiet **Pierakstīties ar ChatGPT**: tā pārlūkā
   palaiž standarta Codex ierīces OAuth procesu un pēc tam, izmantojot
   **Lietot autentifikāciju**, ieraksta `~/.codex/auth.json` koplietotajā sējumā
   (viena un tā pati pierakstīšanās apkalpo gan `codex`, gan
   `codex-app-server` nodrošinātāju).
3. Pēc pierakstīšanās darbspējas pārbaude kļūst zaļa (tā pārbauda gan `/readyz`,
   **gan** `account/read` — proti, vai process darbojas _un_ ir autentificēts),
   un sistēma sāk darboties.

Informācijas panelis nekad nepārraksta funkcionējošu esošo
`~/.codex/auth.json` — tas raksta tikai tad, ja faila nav vai tā pilnvara ir
novecojusi (vienmēr tiek izveidota dublējumkopija).

## 4. Izvietošanas scenāriji

- **Operators ar jau autentificētu Codex CLI** — montējiet resursdatora
  `~/.codex` blakusprocesā (`codex-appserver-home`) un izlaidiet pierakstīšanās
  darbību.
- **Publisks lietotājs, kam codex nav instalēts lokāli** — tam nav nozīmes:
  blakusprocess ietver CLI. Lietotājs autentificējas tikai informācijas panelī.
- **OmniRoute tieši serverī (bez blakusprocesa, ar resursdatora codex)** —
  norādiet `OMNIROUTE_CODEX_APPSERVER_WS` uz savu `codex app-server` un
  pārliecinieties, ka resursdatora codex ir pierakstīts; ja binārā faila nav,
  tiek parādīta norāde "codex nav instalēts".

## 5. Privātā/UDP izejošā trafika maršrutēšana (operatora papildinājums, netiek piegādāts)

Iepriekš aprakstītā vispārīgā blakusprocesa izejošā datplūsma izmanto konteinera
parasto tīklu. Operators, kuram Codex datplūsma jānovirza caur **privātu
interneta izejas punktu** (piemēram, TUN tailscale blakusprocesu, kas pārvada
TCP + UDP/QUIC), palaiž to kā atsevišķu compose pārdefinējumu; tas apzināti
**nav** daļa no piegādātā `codex-app-server` profila. Šīs konfigurācijas aprakstu
skatiet iekšējā ekspluatācijas rokasgrāmatā.
