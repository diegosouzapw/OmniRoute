## 💰 ~1,51B bezmaksas marķieri / Mēnesī

</div>

> Bezmaksas līmeņu uzkrāšana ar rokām ir sāpīga — desmitiem SDK, desmitiem ātruma ierobežojumu, un nav ne jausmas, cik jums patiesībā ir. OmniRoute apkopo **446 bezmaksas līmeņa ierakstus 38 atkārtoto baseinu atslēgās** un aprēķina marķieru galveno skaitli no **20 baseiniem ar publicētu pozitīvu mēneša budžetu**, de-dublicējot kopīgos baseinus. Rezultāts ir redzams informācijas panelī (`/dashboard/free-tiers`).

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="OmniRoute bezmaksas līmeņa budžeta karte: ~1,51B bezmaksas marķieri mēnesī stabilā līmenī, līdz pat ~2,13B pirmajā mēnesī ar reģistrācijas kredītiem, no 38 dokumentētām atkārtoto baseinu atslēgām, kas aptver 446 katalogizētus bezmaksas līmeņa ierakstus aiz viena gala punkta. Godīga baseinu de-dublikāta matemātika — katrs kopīgais baseins skaitīts vienu reizi, ieskaitot 20 atkārtotos baseinus ar publicētu pozitīvu mēneša marķieru budžetu; 13 pakalpojumu sniedzēji ir atzīti par jāizvairās terminu-riska katalogā, tāpēc jūs izlemjat. Budžeta josla ietver Mistral 1B, LLM7 150M, Nara 150M, Gemini 60M un mazākus baseinus, kā arī pirmā mēneša reģistrācijas kredītus un neatkarīgi bezmaksas marķieru limita pakalpojumu sniedzējus, kas parādīti atsevišķi, lai tie nekad nepalielinātu galveno skaitli. Dzēšamā/atlikušā vērtība uz /dashboard/free-tiers."/>

> Animēts kopsavilkums par dzīvo `/dashboard/free-tiers` lapu. Pilna metodika (baseinu de-dublikāte, kredītu līmeņi, pakalpojumu sniedzēju nosacījumi): **[docs/reference/FREE_TIERS.md](docs/reference/FREE_TIERS.md)**.
>
> <sub>Šie skaitļi tiek pārbaudīti ik pēc divām nedēļām pret dzīvo katalogu un **kustas abos virzienos** — pakalpojumu sniedzējs pārtrauc bezmaksas līmeni, un skaits krītas; nāk jauns, un tas pieaug. Mēs publicējam to, ko katalogs patiesībā aprēķina, nekad neapliekot labāko iespējamo gadījumu.</sub>

## 📡 OmniRoute Radar

Galvenais bezmaksas tarifu virsraksts joprojām ir **~1,51B tokeni/mēnesī** no iepriekš dokumentētā,
pulā deduplicētā kataloga. Pagaidu pakalpojumu sniedzēju reģistrācijas kredīti var atsevišķi pirmo
mēnesi paaugstināt līdz **~2,13B**. Radar ir opcionāls, parakstīts kataloga pārklājums cilvēkiem, kuri
vēlas svaigāku bezmaksas modeļu pieejamību starp OmniRoute laidieniem; kopienas katalogs un katra
esošā bezmaksas funkcija paliek bezmaksas.

Atbalstītāji var saņemt dzīvo katalogu un papildu pakalpojumu sniedzēju iespējas. Tā atsevišķais,
mainīgais griests ir **aptuveni 3B tokeni/mēnesī maksimumā**, atkarībā no pakalpojumu sniedzēju
pieejamības. Šis griests nav garantija: pakalpojumu sniedzēji jebkurā laikā var mainīt kvotas,
pielaidei, modeļus vai reģionus.

Radar ir izvēles iespēja un pieejams tikai ar GET pieprasījumiem. OmniRoute klients neaugšupielādē
pieprasījumus, datplūsmu, pakalpojumu sniedzēju konfigurāciju, lietošanas telemetriju vai lokālos
paziņojumu noraidīšanas stāvus. Uzziniet par pielaidei un pašreizējo katalogu **[radar.omniroute.online/planos](https://radar.omniroute.online/planos)**.

```bash
omniroute               # apkalpot vārteju un informācijas paneli (ports 20128)
```

### 🛰️ Attālais režīms — palaidiet CLI šeit, OmniRoute uz VPS

OmniRoute uz servera? Vadīt to no sava klēpjdatora ar **to pašu CLI**. Pierakstieties vienreiz ar mērogošanas piekļuvas žetonu; tad katrs komanda mērķē uz attālo.

```bash
omniroute connect 192.168.0.15            # parole → mērogošanas žetons, saglabāts kā konteksts
omniroute models list                     # ← darbojas pret ATTĀLO serveri
omniroute configure codex                 # ← izvēlas attālo modeli, raksta lokālu Codex profilu
omniroute tokens create --name ci --scope read   # izveidot šaurākus žetus citām iekārtām
omniroute contexts use default            # ← pārslēgties atpakaļ uz lokālo serveri
```

Žeti ir mērogoti `read` / `write` / `admin`; procesu ģenerēšanas maršruti paliek tikai atpakaļsaitei.

### 📖 Kā tas darbojas — konveijers, arhitektūra un ietaupījumu aprēķini

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute saspiešanas konveijers: ilustratīvs 10 000 marķieru klienta pieprasījums iziet cauri 12 saliekamiem dzinējiem — Session-Dedup, CDR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra un OmniGlyph — un var sasniegt pakalpojumu sniedzēju ar aptuveni 1080 marķieriem aprakstītajā saliktajā piemērā. Strukturēts saturs tiek aizsargāts ar saglabāšanas aizsargiem un uzticības vārtiem katram solim; eksplicīti zaudējoši vai eksperimentāli režīmi var transformēt tiesīg saturu."/>

Noklusējuma saliktais kombinētais režīms izpilda `RTK → Caveman`. Kad abi vienlaikus iedarbojas uz vienu un to pašu rīka/konteksta kravu, ietaupījumi summējas:

```txt
kombinētais = 1 − (1 − RTK) × (1 − Caveman_input)
vidējais  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
diapazons    = 78.4 – 94.6%
```

Koda blokus, URL, JSON un strukturētus datus **vienmēr aizsargā** saglabāšanas dzinējs.

> **Kāpēc izmantot daudz marķieru, ja var iztikt ar mazākiem?** Katrs pieprasījums caur OmniRoute saspiešanas konveijeru iziet **caurspīdīgi** — bez klienta izmaiņām. Tas ir **12 saliekamu dzinēju kopa**, kas izpilda pēc kārtas un tiek kombinēti atkarībā no maršrutēšanas kombinācijas — balstoties uz idejām no [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K+), [LLMLingua-2](https://github.com/microsoft/LLMLingua) un [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR).

### 🎚️ Ārpus dzinējiem — izvades stili, adaptīvais regulators un pieprasījuma līmeņa kontrole

Iepriekš minētie 12 dzinēji samazina to, kas iet **iekšā**. Vēl trīs slāņi veido **kā**, **kad** un kas iznāk **ārā**:

- **🪄 Izvades stili** _(izvades-ass vadība)_ — injicē deterministiskas, kešatmiņai drošas atbildes veidošanas instrukcijas; kombinējamas, katra ar `lite` / `full` / `ultra` intensitāti. Stila pievienošana ir vienas rindiņas reģistra ieraksts:
  - **Īsa proza** — izmet pildījumu / rakstvārdus / neizlēmību; saglabā tehnisko būtību precīzu.
  - **Mazāk koda** — "slinks vecākais izstrādātājs" YAGNI: mazākais darbaizmaiņa, bez neprasītas sastatnes.
  - **Aste (slinks vecākais izstrādātājs)** — kāpj pa YAGNI kāpnēm, izlabo saknes cēloni, mazākais darba diffs.
  - **Man ir ADHD (darbība-vispirms)** — nākamā darbība vada, soļi numurēti, viens konkrēts nākamais solis, bez ievada.
  - **Īss CJK (文言)** — klasiskās ķīniešu ultra-īss stils (lokāles ierobežots uz `zh`).
- **🎯 Adaptīvais konteksta budžets** _(regulators)_ — viena ieslēgšanas/izslēgšanas marķieru slieksņa vietā, paceļ tikai lētākos, vismazāk zaudējošos dzinējus ciktāl nepieciešams, lai **ietilpinātu modeļa konteksta logu**. Politika: `reserve-output` (noklusējums, modeļa apzinīgs) · `percentage` · `absolute`. Režīms: `floor` (garantē ietilpšanu) · `replace-autotrigger` (jūsu eksplicītā izvēle uzvar) · `off` (mantots slieksnis).
- **🎛️ Kur tiek izlemts saspiešana** _(priekšrocība, augsta → zema)_ — pieprasījuma līmeņa `x-omniroute-compression` galvene › maršrutēšanas-kombinācijas pārrakstīšana › aktīvais nosauktais profils › adaptīvais / auto-trigger › paneļa noklusējums › off. Pieliktais plāns atbalsojas `X-OmniRoute-Compression: <režīms>; source=<avots>` atbildes galvenē.

Automātiskais triggers pēc marķieru slieksņa, ieslēdziet adaptīvo regulatoru, piniet nosaukto profilu, iestatiet vienreizēju pieprasījuma līmeni vai piešķiriet konveijeru maršrutēšanas kombinācijai — kas vislabāk piemērots darba slodzei. Izvēles bezsaistes **vērtēšanas rīks** (`npm run eval:compression`) novērtē uzticību pret ietaupījumu fiksētā korpusā pirms jūs paaugstināt izmaiņu.

📖 [`COMPRESSION_GUIDE.md`](docs/compression/COMPRESSION_GUIDE.md) · [`RTK_COMPRESSION.md`](docs/compression/RTK_COMPRESSION.md) · [`COMPRESSION_ENGINES.md`](docs/compression/COMPRESSION_ENGINES.md)

Vadības panelis → **Pakalpojumu sniedzēji** → pievienot **Kiro AI** (bezmaksas Claude, ~50 kredīti/mēnesī uz kontu) vai **OpenCode Free** (bez autentifikācijas) → gatavs.

**3) Norādiet savu kodēšanas rīku**

```txt
Bāzes URL: http://localhost:20128/v1
API atslēga:  [kopēt no Vadības panelis → Galapunkti]
Models:    auto            (nulles konfigurācijas viedā maršrutēšana — vai jebkurš pakalpojuma sniedzēja/modeļa)
```

**4) Pārbaudiet, vai tas strādā**

```bash
curl http://localhost:20128/v1/models -H "Authorization: Bearer YOUR_KEY"
```

Jums vajadzētu redzēt savus pievienotos modeļus sarakstā. 🎉 Tas arī viss — sāciet kodēt, un OmniRoute automātiski maršrutē un nokrīt atpakaļ jūsu vietā.

Ja jūsu klients nevar sūtīt pielāgotas galvenes, OmniRoute arī piedāvā tokenizētas saderības aliāsus:

```txt
OpenAI katalogs:   http://localhost:20128/vscode/YOUR_KEY/
OpenAI modeļi:    http://localhost:20128/vscode/YOUR_KEY/models
Openai tērzēšana:      http://localhost:20128/vscode/YOUR_KEY/chat/completions
OpenAI atbildes: http://localhost:20128/vscode/YOUR_KEY/responses
Ollama tērzēšana:      http://localhost:20128/vscode/YOUR_KEY/api/chat
Ollama tagi:      http://localhost:20128/vscode/YOUR_KEY/api/tags
```

Izmantojiet tos tikai klientiem, kas nevar pievienot `Authorization: Bearer ...`. Galvenes autentifikācija joprojām ir vēlamais režīms.

## 📦 Vairāk instalēšanas veidu — Docker, avotkods, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

`:latest` seko augstākajai **publicētajai** stabilai SemVer versijai. Tas neseko git `main`. Piešķir `:X.Y.Z` GitOps pielietošanai. Skatīt [Docker izlaidumu kanālus](docs/guides/DOCKER_GUIDE.md#release-channels). Attēls fiksē **`OMNIROUTE_MEMORY_MB=1024`**. Tas ir pietiekami paneļa un vieglas tērzēšanas lietošanai. **Kodēšanas aģenti** (`POST /v1/responses` no Claude Code, Codex, Grok, …) prasa daudz lielāku V8 kaudzi, pretējā gadījumā process `FATAL ERROR` rodas pie ~12 GiB, ja ir divi pārklājušies garie konteksti. Izmēri konteineru lielāku par kaudzi (nativie buferi atrodas ārpus V8):

| Slodze                                           | Kaudze (`-e OMNIROUTE_MEMORY_MB`) | Konteiners (`--memory`) |
| ------------------------------------------------ | --------------------------------- | ----------------------- |
| Paneļa/Vieglas tērzēšana                         | `1024` (attēla noklusējums)       | ≥2 g                    |
| Viena kodēšanas aģenta slodze                    | `8192`                            | ≥10 g                   |
| Divas vienlaicīgas garas `/v1/responses` sesijas | `10240`–`12288`                   | ≥12–16 g                |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

Pilna tabula: [Docker rokasgrāmata — darbības RAM kodēšanas aģentiem](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

> **Pirmsizlaiduma Docker kanāls:** `diegosouzapw/omniroute:next` un
> `diegosouzapw/omniroute:next-web` seko pašreizējai noklusējuma `release/v*`
> zarai. Šie mainīgie tagi paredzēti tikai testēšanai vēl nepublicētiem labojumiem
> un **nav paredzēti produkcijas lietošanai**. Skatīt
> [Docker izlaidumu kanālus](docs/guides/DOCKER_GUIDE.md#release-channels).

**🥟 Bun**

Standarta `bun install` un globālā instalēšana (`bun install -g omniroute`) ir atbalstītas, izmantojot Bun runtime noteikšanu:

- **Iebūvēts `bun:sqlite`**: OmniRoute izmanto Bun iebūvēto `bun:sqlite` draiveri, kad darbojas zem Bun, pārslēdzoties uz `better-sqlite3` Node.js vidē vai `sql.js`.
- **Automātiskais Webpack bundlera izvēle izstrādē**: Izstrāde (`bun run dev`) automātiski nosaka Bun un atspējo Turbopack par labu Webpack, lai novērstu natīvo V8 saistību nesaderību. Produkcijas būves (`bun run build`) precīzi seko `OMNIROUTE_USE_TURBOPACK` kā Node vidē: Turbopack pēc noklusējuma, `OMNIROUTE_USE_TURBOPACK=0`, lai būvētu ar Webpack (`Dockerfile.bun` to iz暴露 kā `--build-arg`).
- **Speciāls Bun Dockerfile**: Daudzlīmeņu `Dockerfile.bun` natīvām Bun produkcijas deplojēšanām (`docker build -f Dockerfile.bun -t omniroute:bun .`).

```bash
# Instalēt un palaist ar Bun
bun install
bun run dev
```

**⚡ Ātrāka/vieglāka instalēšana (izlaidiet natīvo būvi)**

instalēšana nekad nebloķē avotkoda kompilēšanu: tā izmanto gatavu bināru, kad tas atbilst
jūsu platformai/Node, un citādi caurspīdīgi pārslēdzas uz tīru JS dzinēju

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 arī to izlaiž
```

[Termux rokasgrāmatu](docs/guides/TERMUX_GUIDE.md). CLI un tīmekļa panelis tiek apkalpoti ar
to pašu procesu vienā portā, tāpēc šodien nav atsevišķa tikai CLI paredzēta pakotnes.

1. Fork repozitoriju
2. Izveido zaru no **aktīvās** `release/vX.Y.Z` galotnes (nevis `main`) — sk. [Zarošanas un izlaišanas modelis](docs/ops/BRANCHING_MODEL.md)
3. Izveido savu funkcijas zaru (`git checkout -b feat/amazing-feature`)
4. Kommitē savas izmaiņas (`git commit -m 'feat: add amazing feature'`)
5. Push zaru (`git push origin feat/amazing-feature`)
6. Atver Izvelkuma pieprasījumu ar **bāzi = to `release/vX.Y.Z` zaru**
