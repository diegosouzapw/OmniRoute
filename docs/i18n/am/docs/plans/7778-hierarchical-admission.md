1. ነባሩን የነጠላ-ቁልፍ semaphore ውል እና አዲሱን አቶሚክ የባለብዙ-ቁልፍ ውል በተለዩ ሙከራዎች ያረጋግጡ፦ ከፊል reservations እንዳይኖሩ፣ FIFO queueing፣ abort፣ timeout፣ queue-full፣ idempotent release፣ stats እና cleanup።
2. ነባሩን የመለያ semaphore በቦታው ላይ አጠቃላይ ያድርጉት። `acquire()`ን በ`acquireMany()` ዙሪያ እንደ compatibility wrapper ያቆዩት፤ ሁለተኛ scheduler ወይም dependency አይጨምሩ።
3. በ`chatCore` ውስጥ ያለውን የመለያ-ብቻ acquisition፣ ከ`withRateLimit` በፊት ወዲያውኑ በሚከናወን አንድ ድምር global/provider/account acquisition ይተኩት። account rotation ግንኙነቱን በቀየረ ቁጥር ሙሉውን ስብስብ እንደገና ያግኙ፣ እና releaseን የstreaming ሂደቱ እስኪጠናቀቅ ድረስ ያቆዩት።
4. ነባሩን የresilience settings pipeline (types፣ defaults፣ normalization፣ schema፣ API response፣ UI እና translations) በglobal እና provider caps ያስፋፉ። እውነተኛው scope ግልጽ እንዲሆን የቀድሞውን Bottleneck concurrency control እንደ connection/quota-scope concurrency እንደገና ይሰይሙት።
5. የተወሰኑ ሙከራዎችን፣ lint፣ typecheck፣ static checks እና ሙሉውን test suite ያስኪዱ፤ የባህሪ ለውጡን በchangelog ውስጥ ይመዝግቡ።

ሆን ተብሎ የተጠበቀ ባህሪ፦ ዜሮ/null concurrency gateን ያልፋል፣ account-only callers `acquire()`ን መጠቀማቸውን ይቀጥላሉ፣ blocked-account controls የkey format እና APIያቸውን ይዘው ይቆያሉ፣ እና የprovider rate-limit queue ባህሪ ሳይለወጥ ይቆያል።
