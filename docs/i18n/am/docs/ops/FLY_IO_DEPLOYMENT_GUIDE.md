ይህ ሰነድ OmniRouteን በFly.io ላይ የማሰማራት ተጨባጭ ሂደትን ይገልጻል፤ የሚከተሉትን ሁኔታዎችም ይሸፍናል፦

- የአሁኑን ፕሮጀክት ለመጀመሪያ ጊዜ ወደ Fly.io ማሰማራት
- ቀጣይ የኮድ ዝማኔዎችን ማተም
- ተመሳሳዩን የማሰማራት የሥራ ፍሰት የሚከተሉ አዳዲስ ፕሮጀክቶች

ይህ መመሪያ ለአሁኑ ፕሮጀክት በተረጋገጠ እና በተሳካ ውቅር ላይ የተመሠረተ ነው። የመተግበሪያው ስም `omniroute` ነው።

---

## 1. የማሰማራት ግቦች

- መድረክ፦ Fly.io
- የማሰማራት ዘዴ፦ በአካባቢያዊ `flyctl` በቀጥታ ማተም
- የማስኬጃ አካባቢ፦ በማከማቻው ውስጥ ያሉትን `Dockerfile` እና `fly.toml` መጠቀም
- የውሂብ ቋሚነት፦ በ`/data` ላይ የተጫነ Fly Volume
- የመዳረሻ URL፦ `https://omniroute.fly.dev/`

---

## 2. የአሁኑ ፕሮጀክት ቁልፍ ውቅር

በአሁኑ ማከማቻ ውስጥ ያለው `fly.toml` የሚከተሉትን ቁልፍ ንጥሎች እንደያዘ ተረጋግጧል፦

```toml
app = 'omniroute'
primary_region = 'sin'

[[mounts]]
  source = 'data'
  destination = '/data'

[processes]
  app = 'node run-standalone.mjs'

[http_service]
  internal_port = 20128

[env]
  TZ = "Asia/Shanghai"
  HOST = "0.0.0.0"
  HOSTNAME = "0.0.0.0"
  BIND = "0.0.0.0"
```

ማስታወሻዎች፦

- `app = 'omniroute'` ማሰማራቱ የትኛውን የFly መተግበሪያ እንደሚያነጣጥር ይወስናል
- `destination = '/data'` የቋሚ ድምጽ መጫኛ ማውጫውን ይወስናል
- ይህ ፕሮጀክት `DATA_DIR=/data`ን ማቀናበር አለበት፤ አለበለዚያ የውሂብ ጎታው እና ቁልፎቹ ወደ ኮንቴነሩ ጊዜያዊ ማውጫ ይጻፋሉ

## 3. ቅድመ ሁኔታዎች

### 3.1 Fly CLIን መጫን

Windows PowerShell፦

```powershell
pwsh -Command "iwr https://fly.io/install.ps1 -useb | iex"
```

የመጫኛ ስክሪፕቱ በአካባቢዎ ውስጥ ካልተሳካ፣ የ`flyctl` ሁለትዮሽ ፋይልን በእጅ አውርደው ወደ `PATH`ዎ ማከልም ይችላሉ።

### 3.2 ወደ Fly መለያዎ መግባት

```powershell
flyctl auth login
```

### 3.3 የመግቢያ ሁኔታን ማረጋገጥ

```powershell
flyctl auth whoami
flyctl version
```

## 4. የአሁኑን ፕሮጀክት ለመጀመሪያ ጊዜ ማሰማራት

### 4.1 ኮዱን መቅዳት እና ወደ ማውጫው መግባት

```powershell
git clone https://github.com/diegosouzapw/OmniRoute.git
cd OmniRoute
```

### 4.2 የመተግበሪያውን ስም ማረጋገጥ

`fly.toml`ን ከፍተው የሚከተለውን መስመር ያረጋግጡ፦

```toml
app = 'omniroute'
```

ወደ ራስዎ አዲስ መተግበሪያ እያሰማሩ ከሆነ፣ ስሙን በዓለም አቀፍ ደረጃ ልዩ ወደሆነ ስም መቀየር ይችላሉ፤ ለምሳሌ፦

```toml
app = 'omniroute-yourname'
```

ማስታወሻ፦

- በኮንሶሉ ውስጥ የሚያዩት መተግበሪያ በ`fly.toml` ውስጥ ካለው `app` እሴት ጋር መዛመዱን ያረጋግጡ
- ከዚህ ቀደም እንደ `oroute` ያለ የተለየ ስም ከተጠቀሙ፣ ከ`omniroute` ጋር አያምታቱት

### 4.3 መተግበሪያውን መፍጠር

መተግበሪያው እስካሁን ከሌለ፦

```powershell
flyctl apps create omniroute
```

የመተግበሪያውን ስም ከቀየሩ፣ `omniroute`ን በመረጡት ስም ይተኩ።

### 4.4 የመጀመሪያ ማሰማራት

```powershell
flyctl deploy
```

## 5. አስፈላጊ መለኪያዎች

ይህ ፕሮጀክት ቢያንስ የሚከተሉትን መለኪያዎች በFly.io ላይ ማዋቀርን ይመክራል።

### 5.1 የተረጋገጡ መለኪያዎች

እነዚህ መለኪያዎች በአሁኑ `omniroute` መተግበሪያ ላይ በተጨባጭ ማሰማራቶች ጥቅም ላይ ውለዋል፦

- `API_KEY_SECRET`
- `DATA_DIR`
- `JWT_SECRET`
- `MACHINE_ID_SALT`
- `NEXT_PUBLIC_BASE_URL`
- `OMNIROUTE_WS_BRIDGE_SECRET` (በምርት አካባቢ ያስፈልጋል — ለWebSocket bridge ማረጋገጫ ያገለግላል)
- `STORAGE_ENCRYPTION_KEY`

### 5.2 ስለ `INITIAL_PASSWORD`

ይህ ማሰማራት `INITIAL_PASSWORD`ን ስለማይፈልግ፣ የአሁኑ ፕሮጀክት አያቀናብረውም።

ካልተቀናበረ፦

- የማስጀመሪያ ምዝግብ ነባሪው የይለፍ ቃል `CHANGEME` መሆኑን ያመለክታል
- ከማሰማራቱ በኋላ በተቻለ ፍጥነት የመግቢያ የይለፍ ቃሉን በስርዓት ቅንብሮች ውስጥ መቀየር አለብዎት

የጀርባ ስርዓቱን የይለፍ ቃል ያለ ክትትል ማስጀመር ከፈለጉ፣ በኋላ የሚከተለውን ማከል ይችላሉ፦

- `INITIAL_PASSWORD`

## 6. የሚመከሩ መለኪያዎች

### 6.1 የሚስጥሮች ውቅር

የሚከተሉት ተለዋዋጮች ለFly Secrets ይመከራሉ፦

| ተለዋዋጭ                        | ምክር             | መግለጫ                                         |
| ---------------------------- | --------------- | -------------------------------------------- |
| `API_KEY_SECRET`             | አስፈላጊ           | API Keyን ለማመንጨትና ለማረጋገጥ ያገለግላል               |
| `JWT_SECRET`                 | አስፈላጊ           | ለመግቢያ ክፍለ ጊዜዎችና JWT ፊርማ ያገለግላል               |
| `OMNIROUTE_WS_BRIDGE_SECRET` | በምርት አካባቢ አስፈላጊ | የWebSocket ድልድይ ማረጋገጫ ሚስጥር                   |
| `STORAGE_ENCRYPTION_KEY`     | በጥብቅ የሚመከር      | ስሱ የግንኙነት መረጃን በማከማቻ ላይ ሳለ ያመሰጥራል            |
| `MACHINE_ID_SALT`            | የሚመከር           | የማይለዋወጥ የማሽን መለያ ያመነጫል                       |
| `INITIAL_PASSWORD`           | አማራጭ            | በመጀመሪያው ስምሪት የመጀመሪያውን የbackend የይለፍ ቃል ያዘጋጃል |
| የOAuth/API የግል ማረጋገጫዎች       | እንደ አስፈላጊነቱ     | የውጫዊ መድረክ ማረጋገጫ ውቅር                          |

### 6.2 ለአሁኑ ፕሮጀክት የሚመከሩ እሴቶች

| ተለዋዋጭ                  | የሚመከር እሴት                   |
| ---------------------- | --------------------------- |
| `DATA_DIR`             | `/data`                     |
| `NEXT_PUBLIC_BASE_URL` | `https://omniroute.fly.dev` |

ማስታወሻዎች፦

- `DATA_DIR=/data` ወሳኝ ሲሆን ከFly Volume የመጫኛ ነጥብ ጋር መዛመድ አለበት
- `NEXT_PUBLIC_BASE_URL` በጊዜ መርሐግብር አስኪያጁ፣ በfrontend መልሶ ጥሪዎችና ተመሳሳይ ሁኔታዎች ጥቅም ላይ ይውላል

### 6.3 የOAuth መልሶ ጥሪ URL ውቅር

በFly.io ስምሪት ላይ OAuthን መሠረት ያደረጉ አቅራቢዎችን (ለምሳሌ Antigravity፣ Gemini፣ Cursor) ማንቃት ካስፈለገዎት፣ የሚከተሉትን ሁለት ነጥቦች ያረጋግጡ፦

1. **`NEXT_PUBLIC_BASE_URL`ን ወደ ይፋዊ HTTPS ጎራዎ ያዘጋጁ**

   ```powershell
   flyctl secrets set NEXT_PUBLIC_BASE_URL=https://omniroute.fly.dev -a omniroute
   ```

   ብጁ ጎራ እየተጠቀሙ ከሆነ፣ በሚዛመደው ጎራ (ለምሳሌ `https://omniroute.yourdomain.com`) ይተኩት።

2. **በአቅራቢው መቆጣጠሪያ ላይ የመልሶ ጥሪ URLን ያዋቅሩ**

   ሁሉም የOAuth አቅራቢዎች አንዱን የመልሶ ጥሪ ዱካ `/callback` ይጋራሉ — ለእያንዳንዱ አቅራቢ የተለየ የመልሶ ጥሪ መስመር የለም፦

   ```text
   <NEXT_PUBLIC_BASE_URL>/callback
   ```

   ለምሳሌ፣ Gemini፣ Antigravity፣ Cursor ወይም GitLab Duo ቢሆንም፦
   - `https://omniroute.fly.dev/callback`

   `NEXT_PUBLIC_BASE_URL` በአቅራቢው ጋር ከተመዘገበው የመልሶ ጥሪ URL ጋር ካልተዛመደ፣ የOAuth ፍሰቱ በአሳሹ አቅጣጫ ማስቀየር ደረጃ ላይ ይከሽፋል።

## 7. በአንድ ትዕዛዝ ሚስጥር ማዋቀር

የሚከተሉት ትዕዛዞች ደህንነታቸው የተጠበቀ የዘፈቀደ እሴቶችን ያመነጫሉ፣ እንዲሁም ለአሁኑ ፕሮጀክት የሚያስፈልጉትን መለኪያዎች በሙሉ በአንድ ደረጃ ወደ Fly Secrets ይጽፋሉ።

ማስታወሻዎች፦

- `INITIAL_PASSWORD`ን አያካትትም
- ለአሁኑ ፕሮጀክት `omniroute` የታሰበ ነው

```powershell
$apiKeySecret = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$jwtSecret = [Convert]::ToHexString((1..64 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$machineIdSalt = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$storageKey = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$wsBridgeSecret = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()

flyctl secrets set `
  API_KEY_SECRET=$apiKeySecret `
  JWT_SECRET=$jwtSecret `
  MACHINE_ID_SALT=$machineIdSalt `
  STORAGE_ENCRYPTION_KEY=$storageKey `
  OMNIROUTE_WS_BRIDGE_SECRET=$wsBridgeSecret `
  DATA_DIR=/data `
  NEXT_PUBLIC_BASE_URL=https://omniroute.fly.dev `
  -a omniroute
```

በLinux / macOS ላይ፣ `openssl rand -hex 32`ንም መጠቀም ይችላሉ፦

```bash
flyctl secrets set OMNIROUTE_WS_BRIDGE_SECRET=$(openssl rand -hex 32) -a omniroute
```

ማስታወሻዎች፦

- `OMNIROUTE_WS_BRIDGE_SECRET` በምርት አካባቢ አስፈላጊ ነው፤ ካልተገኘ የWebSocket ድልድይ የእጅ መጨባበጥ ሂደትን ያበላሻል

የመጀመሪያ የይለፍ ቃልም ማዘጋጀት ከፈለጉ፦

```powershell
flyctl secrets set INITIAL_PASSWORD=your-strong-password -a omniroute
```

## 9. ቀጣይ ማዘመኛዎች እና ልቀቶች

ኮዱ ከተዘመነ በኋላ፣ የልቀት ሂደቱ ቀላል ነው፦

```powershell
git pull
flyctl deploy
```

ኮዱን ሳይቀይሩ መለኪያዎችን ብቻ ማዘመን ካስፈለገዎት፦

```powershell
flyctl secrets set KEY=value -a omniroute
```

Fly በማሽኖቹ ላይ ተከታታይ ማዘመኛን በራስ-ሰር ያከናውናል።

### 9.1 የፎርክዎን `fly.toml` በመጠበቅ የዋናውን ማከማቻ ማዘመኛዎች መከታተል

የአሁኑ ማከማቻ ፎርክ ከሆነ እና ከዋናው `https://github.com/diegosouzapw/OmniRoute` ማዘመኛዎችን ማመሳሰል ከፈለጉ፣ ከታች ያለውን የሥራ ፍሰት ይከተሉ።

በመጀመሪያ፣ የርቀት ማከማቻዎችዎን ያረጋግጡ፦

```powershell
git remote -v
```

ቢያንስ የሚከተሉትን ማየት አለብዎት፦

- `origin` ወደ ራስዎ ፎርክ የሚያመለክት
- `upstream` ወደ ዋናው ማከማቻ የሚያመለክት

`upstream` ካልተዋቀረ፣ ያክሉት፦

```powershell
git remote add upstream https://github.com/diegosouzapw/OmniRoute.git
```

ከ`upstream` ጋር ከማመሳሰልዎ በፊት፣ የቅርብ ጊዜዎቹን ኮሚቶች እና መለያዎች ያምጡ፦

```powershell
git fetch upstream --tags
```

የአሁኑን ስሪት እና የ`upstream` መለያዎችን ያረጋግጡ፦

```powershell
git describe --tags --always
git show --no-patch --oneline v3.4.7
```

> ማስታወሻ፦ የአሁኑ የፕሮጀክት ስሪት `v3.8.0` ነው። ከታች ያሉት የ`v3.4.7` ማጣቀሻዎች እንደ ታሪካዊ ምሳሌዎች ብቻ ተቀምጠዋል። ለተጨባጭ ልቀቶች `:latest` ወይም የአሁኑን የስሪት መለያ (ለምሳሌ `:v3.8.0`) ይጠቀሙ።

የፎርክዎን `fly.toml` በግድ እንደተጠበቀ የቅርብ ጊዜውን የ`upstream` `main` ማዋሃድ ከፈለጉ፣ ይህን የሥራ ፍሰት ይከተሉ፦

```powershell
git merge upstream/main
git checkout HEAD~1 -- fly.toml
git add -- fly.toml
git commit -m "chore(deploy): keep fork fly.toml"
git push origin main
```

ማስታወሻዎች፦

- `git merge upstream/main` የቅርብ ጊዜውን ኮድ ከዋናው ማከማቻ ጋር ያመሳስላል
- `git checkout HEAD~1 -- fly.toml` ከውህደቱ በፊት የነበረውን የፎርክዎን `fly.toml` መልሶ ያስቀምጣል
- `upstream` `fly.toml`ን ካላሻሻለ፣ ይህ ደረጃ ምንም ልዩነት አያስገባም
- `upstream` `fly.toml`ን ካሻሻለ፣ ይህ ደረጃ የFly መተግበሪያዎ ስም፣ የቮልዩም ማያያዣ፣ ክልል እና ሌሎች ለፎርኩ የተወሰኑ የማሰማሪያ ውቅሮች እንዳይተኩ ያረጋግጣል

ከተወሰነ የልቀት መለያ (ለምሳሌ `v3.4.7`) ጋር ማመጣጠን ከፈለጉ፣ በመጀመሪያ መለያው በ`upstream/main` ውስጥ አስቀድሞ የተካተተ መሆኑን ያረጋግጡ፦

```powershell
git merge-base --is-ancestor v3.4.7 upstream/main
```

የተሳካ ውጤት `upstream/main` ያንን ስሪት አስቀድሞ እንደያዘ ያሳያል፤ `upstream/main`ን በቀላሉ ማዋሃድ ይችላሉ።

### 9.2 `upstream`ን ካመሳሰሉ በኋላ የሚከተለው መደበኛ የልቀት ቅደም ተከተል

ከዋናው ማከማቻ ጋር ካመሳሰሉ በኋላ፣ ይህን የሚመከር የልቀት ቅደም ተከተል ይከተሉ፦

1. `git fetch upstream --tags`
2. `git merge upstream/main`
3. የፎርኩን `fly.toml` መልሰው ያስቀምጡ
4. `git push origin main`
5. `flyctl deploy`
6. `flyctl status -a omniroute`
7. `flyctl logs --no-tail -a omniroute`

ይህ የአሁኑን ፕሮጀክት ወደ `v3.4.7` ሲያሻሽሉ በተግባር ጥቅም ላይ የዋለው የሥራ ፍሰት ነው (ምሳሌው ታሪካዊ ስሪትን ይጠቅሳል፤ የአሁኑ ተጨባጭ ስሪት `v3.8.0` ነው)።

የሚከተሉትን ሁለቱንም ያረጋግጡ፦

- `fly.toml` `destination = '/data'` ይዟል
- `DATA_DIR` ወደ `/data` ተዋቅሯል

### 12.5 ያለ `INITIAL_PASSWORD` ሊሠራ ይችላል?

አዎ፣ ሊሠራ ይችላል። ነባሪውን `CHANGEME` የይለፍ ቃል ይጠቀማል። በምርት አካባቢ የጀርባ ስርዓቱን የይለፍ ቃል በተቻለ ፍጥነት መቀየር ይመከራል።

## 13. ለአዳዲስ ፕሮጀክቶች እንደገና መጠቀም

ይህን ሰነድ በመከተል አዲስ ፕሮጀክት እያሰማሩ ከሆነ፣ እነዚህን ንጥሎች ብቻ መቀየር ያስፈልግዎታል፦

1. በ`fly.toml` ውስጥ ያለውን የ`app` እሴት ይቀይሩ
2. `NEXT_PUBLIC_BASE_URL`ን ይቀይሩ
3. `DATA_DIR=/data`ን እንዳለ ያቆዩ
4. `API_KEY_SECRET`፣ `JWT_SECRET`፣ `MACHINE_ID_SALT` እና `STORAGE_ENCRYPTION_KEY`ን እንደገና ያመንጩ
5. ከመጀመሪያው ማሰማራት በኋላ፣ ምዝግቦች ወደ `/data` መጻፋቸውን ያረጋግጡ

ከቀድሞ ፕሮጀክት የተወሰዱ ቁልፎችን እንደገና አይጠቀሙ።

---

## 14. ለአሁኑ ፕሮጀክት አነስተኛው የልቀት ማረጋገጫ ዝርዝር

ለቀጣይ ልቀቶች በብዛት ጥቅም ላይ የሚውሉት ትዕዛዞች እነዚህ ናቸው፦

```powershell
flyctl auth whoami
flyctl status -a omniroute
flyctl secrets list -a omniroute
flyctl deploy
flyctl logs --no-tail -a omniroute
```

ለመደበኛ ልቀት፣ ዋናው ትዕዛዝ ይህ ብቻ ነው፦

```powershell
flyctl deploy
```

በአዲስ አካባቢ ለመጀመሪያ ጊዜ ማሰማራት፣ ዋናዎቹ ደረጃዎች እነዚህ ናቸው፦

1. `flyctl auth login`
2. `flyctl apps create omniroute`
3. `flyctl secrets set ... -a omniroute`
4. `flyctl deploy`
5. `flyctl logs --no-tail -a omniroute`
