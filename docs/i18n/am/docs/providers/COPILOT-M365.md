`copilot-m365-web` (`m365copilot` የሚል ተለዋጭ ስም ያለው) የOpenAI ቅርጸት ያላቸውን የውይይት ጥያቄዎች በ`m365.cloud.microsoft/chat` ላይ በተረጋገጠ የMicrosoft 365 Copilot BizChat የአሳሽ ክፍለ ጊዜ በኩል ይልካል። ይህ ይፋዊ ያልሆነ ውህደት ነው።

> **የWeb Cookie አቅራቢዎችን ሲጠቀሙ አዲስ ነዎት?**
>
> ይህን ለአቅራቢው የተለየ መመሪያ ከመከተልዎ በፊት ለአጠቃላይ የማዋቀር ሂደት፣ የማረጋገጫ መመሪያ፣ ገደቦች እና መላ ፍለጋ **`docs/getting-started/WEB-COOKIE-GUIDE.md`**ን ያንብቡ።
>
> **አስፈላጊ፦** የዚህ አቅራቢ ማረጋገጫ **cookie አይደለም**። ከ`m365.cloud.microsoft` cookiesን አይቅዱ። ማረጋገጫው የWebSocket URL የጥያቄ መለኪያ እና የዱካ ክፍል ሲሆን፣ ሁለቱም ከDevTools Network ትር ይነበባሉ።

## ቅድመ ሁኔታዎች

- በ`m365.cloud.microsoft/chat` ላይ BizChatን ማግኘት የሚችል Microsoft 365 መለያ
- ለDevTools WebSocket ፍተሻ Chromium ላይ የተመሠረተ አሳሽ (Chrome፣ Edge)
- የM365 Copilot ፈቃድ (ከብዙ Microsoft 365 Business/Enterprise ዕቅዶች ጋር የተካተተ)

## ማረጋገጫውን መያዝ (የWebSocket ዘዴ)

1. በ`https://m365.cloud.microsoft/chat` ይግቡና ውይይት ይጀምሩ።
2. **DevTools → Network**ን ይክፈቱ።
3. በ**WS** (WebSocket) ያጣሩ።
4. የChathub WebSocket ግንኙነቱን ጠቅ ያድርጉ። በ`wss://substrate.office.com/m365Copilot/Chathub/` የሚጀምር URL ይፈልጉ።
5. ከ**Request URL** የሚከተሉትን ይቅዱ፦
   - የ`access_token` የጥያቄ መለኪያ እሴት (ለአጭር ጊዜ የሚሠራ JWT)።
   - ከ`/Chathub/` በኋላ ያለውን የChathub ዱካ ክፍል (ለምሳሌ `<oid>@<tenant>`)።

ሙሉው URL የሚከተለው ቅርጽ አለው፦

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. በOmniRoute ውስጥ ወደ **Providers → Add Provider** ይሂዱ፣ **Microsoft 365 Copilot
   (BizChat)**ን ይምረጡ እና ማረጋገጫውን በሚከተለው ቅርጽ ይለጥፉ፦

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. **Test Connection**ን እና **Save**ን ጠቅ ያድርጉ።

## ማረጋገጫውን መያዝ (HAR ማስመጣት)

ከWebSocket URL እሴቶችን በእጅ ከመቅዳት ይልቅ የDevTools HAR ፋይልን ወደ ውጭ መላክ ይችላሉ፦

1. **DevTools → Network**ን ይክፈቱ።
2. የBizChat ውይይት ይጀምሩ ወይም ይቀጥሉ (ይህ የWebSocket ግንኙነቱን ያስጀምራል)።
3. በNetwork ፓነሉ ውስጥ በቀኝ ጠቅ ያድርጉና **Save all as HAR with content**ን ይምረጡ።
4. በOmniRoute ውስጥ፣ በአቅራቢ ግንኙነት መገናኛ ሳጥን ላይ ያለውን **Import .har file** አዝራር ይጠቀሙ።

OmniRoute በHAR ውስጥ የChathub WebSocket URLን ይፈልጋል፣ `access_token`ን እና `chathubPath`ን ያወጣል፣ እንዲሁም የማረጋገጫ መስኮቹን በራስ-ሰር ይሞላል። HAR ማስመጣቱ የJWT ማብቂያ ጊዜን ዲኮድ በማድረግ የቀረውን የቶከን የቆይታ ጊዜ ያሳያል።

> **እውነተኛ HAR ወደ ውጭ የተላከ ፋይል፣ access token ወይም refresh token በፍጹም commit አያድርጉ።** የሙከራ እና የሰነድ እሴቶች ሁልጊዜ ቦታ ያዥ መሆን አለባቸው።

## የቶከን የቆይታ ጊዜ እና ማደስ

`access_token` ለአጭር ጊዜ የሚሠራ ነው (በተለምዶ **~75 ደቂቃዎች**)። ጊዜው ካለፈ በኋላ አቅራቢው የግንኙነት ስህተት ሪፖርት ያደርጋል፣ እና ማረጋገጫውን እንደገና መያዝ ያስፈልግዎታል።

### `refreshToken`ን በመጠቀም በራስ-ሰር ማደስ

በእጅ እንደገና መያዝን ለማስወገድ፣ የMicrosoft refresh tokenን በግንኙነቱ **Advanced Settings → providerSpecificData** ውስጥ ማከማቸት ይችላሉ፦

| መስክ            | መግለጫ                                                              |
| -------------- | ----------------------------------------------------------------- |
| `refreshToken` | ለ`substrate.office.com/sydney` ወሰን የMicrosoft OAuth refresh token |
| `tier`         | `individual` (ነባሪ)፣ `edu` ወይም `enterprise`                        |

የrefresh tokenን ለ`substrate.office.com/sydney` ወሰን ከተዋቀረ የMicrosoft device-code ወይም authorization-code ፍሰት ያግኙ። `refreshToken` ከተዋቀረ፣ OmniRoute ከእያንዳንዱ ጥያቄ በፊት `access_token`ን ቅድመ-በረራ ያድሳል፤ ስለዚህ ከእያንዳንዱ ~75 ደቂቃ ማብቂያ በኋላ እንደገና መያዝ አያስፈልግዎትም።

`refreshToken` ካልተዋቀረ፣ ከእያንዳንዱ ማብቂያ በኋላ የWebSocket ማረጋገጫውን በእጅ እንደገና መያዝ አለብዎት።

### የደረጃ ምርጫ

| ደረጃ          | ተለዋጭ ስም    | መገናኛ ገጽታ            |
| ------------ | ---------- | ------------------- |
| `individual` | _(ነባሪ)_    | የተጠቃሚ M365 Copilot  |
| `edu`        | `included` | የትምህርት M365 Copilot |
| `enterprise` | `work`     | M365 Copilot ለሥራ    |

ደረጃውን በ**Advanced Settings → providerSpecificData → tier** ውስጥ ያዋቅሩ። ደረጃው የBizChat ማዘዋወርን እና የሞዴል መዳረሻን ይነካል።

## የደህንነት ሞዴል

- **ይፋዊ ያልሆነ ውህደት።** ይህ አቅራቢ የBizChat WebSocket
  ፕሮቶኮልን በተቃራኒ ምህንድስና ይተነትናል። Microsoft መዳረሻውን ሲቀይር ያለማሳወቂያ መስራት ሊያቆም ይችላል።
- የ`subscriptionRisk: true` ጠቋሚው ውህደቱ ሰነድ ባልተዘጋጀለት
  መዳረሻ ላይ እንደሚመሰረት ያመለክታል። የመለያ ገደቦች ሊኖሩ ይችላሉ፣ ነገር ግን አልተረጋገጠም።
- የመዳረሻ ቶከኑ ለአጭር ጊዜ የሚያገለግል JWT ነው። እንደ የይለፍ ቃል ይያዙት፦ ወደ ማከማቻ አታስገቡት፣
  በምዝግብ አታስቀምጡት ወይም አያጋሩት።
- የማደሻ ቶከኑ ወደ BizChat በይነገጽ የረጅም ጊዜ መዳረሻ ይሰጣል። እንደ API ቁልፍ
  በተመሳሳይ ጥንቃቄ ያከማቹት።

## ችግር መፍታት

### ማረጋገጫው ወዲያውኑ አይሳካም

- ከXHR/Fetch ጥያቄ ሳይሆን ከ**WebSocket URL** መቅዳትዎን ያረጋግጡ።
  ማረጋገጫው በChathub WebSocket ግንኙነት የ`access_token` መጠይቅ መለኪያ ውስጥ ነው —
  በ`Authorization: Bearer` ራስጌ ውስጥ አይደለም።
- `chathubPath` ከURL ዱካው የተገኘውን ሙሉ `<oid>@<tenant>` ክፍል
  ማካተቱን ያረጋግጡ።

### ቶከኑ ከ~75 ደቂቃዎች በኋላ ጊዜው ያልፋል

ይህ የሚጠበቅ ነው። `refreshToken` ከሌለ የመዳረሻ ቶከኑ ለአጭር ጊዜ ብቻ ያገለግላል። ከሚከተሉት አንዱን ያድርጉ፦

- ማረጋገጫውን ከDevTools እንደገና ይቅረጹ፣ ወይም
- በራስ-ሰር ለማደስ በላቁ ቅንብሮች ውስጥ `refreshToken` ያዋቅሩ።
