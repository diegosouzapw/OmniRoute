[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854) የተደረገውን የትግበራ ውሳኔ ይመዘግባል። ይፋዊ ምርቶቹ እንደ አራት የአቅራቢ ቤተሰቦች ተወክለዋል። ክልል የግንኙነት ውሂብ እንጂ የተለየ ምርት አይደለም።

| የአቅራቢ ቤተሰብ                                   | OmniRoute ID            | ዓለም አቀፍ ክልል | የቻይና ክልል |
| -------------------------------------------- | ----------------------- | ----------- | -------- |
| Alibaba Cloud Model Studio (እንደ አጠቃቀምዎ ይክፈሉ) | `alibaba`               | ሲንጋፖር       | ቤጂንግ     |
| Alibaba Cloud Token Plan                     | `bailian-coding-plan`   | ሲንጋፖር       | ቤጂንግ     |
| Qwen Cloud (እንደ አጠቃቀምዎ ይክፈሉ)                 | `qwen-cloud`            | ዓለም አቀፍ     | ቤጂንግ     |
| Qwen Cloud Token Plan                        | `qwen-cloud-token-plan` | ሲንጋፖር       | ቤጂንግ     |

ነባሩ `alibaba-cn` ID ለተቀመጡ ግንኙነቶች፣ የሞዴል መስመሮች፣ ጥምረቶች እና ታሪካዊ አጠቃቀም የአሂድ ጊዜ ተኳኋኝነት ቅጽል ስም ሆኖ ይቆያል። የዳሽቦርድ ካርዱ ወደ `alibaba` ይጠቃለላል፤ የውሂብ ጎታ ዳግም መጻፍ አያስፈልግም።

Qwen Cloud እንደ አጠቃቀም የሚከፈልበት ምርት እና Alibaba Cloud Model Studio በአሁኑ ጊዜ DashScope-ተኳኋኝ የአሂድ ጊዜ አስተናጋጆችን ይጋራሉ፤ ሆኖም ተጠቃሚዎች ቁልፎችን የሚያገኙትና መለያዎችን የሚያስተዳድሩት በተለያዩ የምርት በይነገጾች ስለሆነ እንደ ተለያዩ የአቅራቢ ማንነቶች ይቆያሉ። የAlibaba እና Qwen Cloud Token Plan ምርቶች የተለያዩ የመጨረሻ ነጥብ ቤተሰቦችን ይጠቀማሉ፤ ስለዚህ አራቱም ምርቶች የተለያዩ የአቅራቢ IDዎች ሆነው ይቆያሉ።

## የግንኙነት ውል

አዲስ ግንኙነቶች የተረጋጋውን የክልል ቁልፍ በ`providerSpecificData` ውስጥ ያከማቻሉ፦

```json
{
  "region": "global-sg"
}
```

የተፈቀዱ እሴቶች `global-sg` እና `china-beijing` ናቸው። የመጨረሻ ነጥቡ ከአቅራቢው ID እና ከክልሉ በማዕከላዊነት ይመነጫል። ቀድሞ ያልተዘጋጀ `providerSpecificData.baseUrl` ግልጽ የኦፕሬተር ሽረት ሆኖ ይቆያል እና ቅድሚያ ይኖረዋል፤ ቀድሞ የተቀመጡ ቅድመ-ቅንብር URLዎች ግን ወደ ክልላዊው ማትሪክስ መልሰው መደበኛ ይደረጋሉ።

ይህ የግንኙነት ንድፉን ሊስፋፋ የሚችል አድርጎ ያቆየዋል፤ ሌላ የአቅራቢ ካርድ ሳይፈጠር ወይም የተቀመጡ የአቅራቢ IDዎች ሳይቀየሩ ሌላ ክልል ወደ ፈቺው ሊጨመር ይችላል።

## ተኳኋኝነት እና የማሰማራት ሂደት

1. ክልላዊ የendpoint መፍቻውን ያክሉ እና አሁን ያሉትን ዓለም አቀፍ ነባሪዎች ያቆዩ።
2. ለ`alibaba`፣ ለ`alibaba-cn` የተኳኋኝነት መታወቂያው እና ለ`qwen-cloud` ቀጥታ ክልላዊ የDashScope `/models` ፍለጋን ይጠቀሙ። አጠቃላዩ
   endpoint ምስል፣ ቪዲዮ፣ ድምፅ፣ embedding እና ሌሎች የውይይት ያልሆኑ ሞዴሎችንም ስለሚመልስ፣ ምላሾቻቸው መጀመሪያ በአንድ የጽሑፍ-ማመንጨት ማጣሪያ ያልፋሉ። `qwen-cloud`
   ከዚያ በአቅራቢ መዝገቡ ውስጥ የተገለጸውን የሚተዳደር allowlist ይተገብራል። Alibaba Model Studio
   እና Qwen Cloud በአሁኑ ጊዜ ተመሳሳይ runtime hosts ቢጋሩም የተለያዩ በጥንቃቄ የተመረጡ catalog-ዎችን ይይዛሉ።
3. `qwen-cloud-token-plan`ን ከአሁኑ Token Plan የጽሑፍ-ሞዴል allowlist ጋር ይመዝግቡ።
4. ወደ ግንኙነት ማከል/ማርትዕ መገናኛ ሳጥኖች የtyped ክልል መራጭ ያክሉ።
5. የተደገመውን `alibaba-cn` ካርድ ይደብቁ እና ነባር ግንኙነቶቹን በ`alibaba`
   አቅራቢ ገጽ ላይ ያካትቱ።
6. ለላቁ እና ለworkspace-ተኮር ማሰማራቶች ብጁ የendpoint overrides መጠቀም እንዲቻል ያቆዩ።

Token Plan የሚዲያ ሞዴሎች ራሳቸውን የቻሉ endpoints ስለሚጠቀሙ ከውይይት catalog ውጭ ይቆያሉ።
`wan2.7-image` እና `wan2.7-image-pro` በ`open-sse/config/imageRegistry.ts` ውስጥ ተመዝግበዋል፤
`happyhorse-1.1-i2v`፣ `happyhorse-1.1-t2v` እና `happyhorse-1.1-r2v` በ
`open-sse/config/videoRegistry.ts` ውስጥ ተመዝግበዋል። ሁለቱም registries የ`qwen-cloud-token-plan` ግንኙነት
ማንነትን እና ክልል-ተኮር credentials-ን እንደገና ይጠቀማሉ።

ሞዴሎቹ `happyhorse-1.1-i2v`፣ `happyhorse-1.1-t2v`፣ `happyhorse-1.1-r2v`፣
