## አጠቃላይ እይታ

የኮታ ማጋሪያ ሞተሩ ተመሳሳይ ግንኙነትን በሚጋሩ በርካታ API ቁልፎች መካከል የአቅራቢውን ጊዜ-ተኮር ኮታ (ለምሳሌ፣ የCodex የ5-ሰዓት መስኮት፣ የKimi 1500 ጥያቄዎች/ሰዓት) በፍትሐዊነት ያሰራጫል።

**የሚፈታው ችግር:** OmniRoute ብዙ API ቁልፎችን በተመሳሳይ የላይኛው ደረጃ አቅራቢ መለያ በኩል ያስተላልፋል። የማጋሪያ አመክንዮ ከሌለ፣ ከቁልፍ A የሚመጣ ድንገተኛ የጥያቄ ጭማሪ የአቅራቢውን የሰዓቱን ኮታ ሊያሟጥጥ ይችላል፤ ይህም ቁልፎች B እና C መስኮቱ ዳግም እስኪጀመር ድረስ እንዲታገዱ ያደርጋል። ሞተሩ ይህን የሚከላከለው፦

1. የእያንዳንዱን ቁልፍ ተንከባላይ ፍጆታ በየልኬቱ (%, ጥያቄዎች፣ ቶከኖች፣ $) በመከታተል።
2. ሥራን የማያባክን ፍትሐዊ-ድርሻ ስልተ ቀመር በመተግበር፦ ዓለም አቀፉ ክምችት እስካልሞላ ድረስ አንድ ቁልፍ ከስራ ፈት ድርሻዎች መዋስ ይችላል።
3. ጥያቄው የላይኛው ደረጃ አስፈጻሚ ጋር ከመድረሱ በፊት ውጤቱን በዋናው የማስፈጸሚያ መንገድ (`chatCore.ts`) ላይ ተፈጻሚ በማድረግ።

## ስልተ ቀመር፦ ሥራን የማያባክን ፍትሐዊ-ድርሻ

በ`src/lib/quota/fairShare.ts` ውስጥ ተተግብሯል።

### ሁነታዎች

| ሁኔታ                                        | ሁነታ     | ባህሪ                                                |
| ------------------------------------------ | ------- | -------------------------------------------------- |
| `globalUsedPercent < saturationThreshold`  | **ለጋስ** | ቁልፉ ከዓለም አቀፍ ገደቡ ላይ ጠቅላላ ፍጆታው እስከሚቀነስ ድረስ መዋስ ይችላል |
| `globalUsedPercent >= saturationThreshold` | **ጥብቅ** | የግለሰቡን ፍትሐዊ ድርሻ በጥብቅ ተፈጻሚ ያደርጋል                    |

ነባሩ `saturationThreshold = 0.5` ነው (env `QUOTA_SATURATION_THRESHOLD`)።

### የእያንዳንዱ ልኬት ውሳኔ

በክምችቱ ውስጥ ላለው እያንዳንዱ ገባሪ ልኬት ሞተሩ የሚከተለውን ያሰላል፦

```
fairShareAllowed = poolLimit × (allocationWeight / 100)
consumed        = የዚህ ቁልፍ የአሁኑ ተንከባላይ እሴት (ከ QuotaStore.peek)
remaining       = fairShareAllowed - consumed
```

ከዚያ፦

- **`policy = hard`**፦ `consumed > fairShareAllowed` ከሆነ እና ሁነታው ጥብቅ ከሆነ → **አግድ**።
- **`policy = soft`**፦ `consumed > fairShareAllowed` ከሆነ እና ሁነታው ጥብቅ ከሆነ → **ቅጣት ተግብር** (በጥምር ውስጥ ቅድሚያውን አሳንስ፤ ፈጽሞ ጠንካራ እገዳ አታድርግ)።
- **`policy = burst`**፦ ፍትሐዊ ድርሻው ምንም ይሁን ምን፣ ዓለም አቀፍ ትርፍ አቅም እስካለ ድረስ ፍቀድ።

### ፍጹም ጣሪያ

በምደባ ላይ ያሉት `capValue` + `capUnit` ከሁነታ ወይም ከመመሪያ ነጻ የሆነ ጠንካራ ጣሪያ ናቸው። `consumed >= capValue` የሆነበት ማንኛውም ልኬት ሁልጊዜ ጥያቄውን **ያግዳል**።

### የብዙ ልኬቶች ማረጋገጫ

በክምችቱ ውስጥ ካሉት ልኬቶች **ማንኛውም** ቢያግደው፣ ጥያቄው ይታገዳል። ልኬቶቹ እርስ በርሳቸው ነጻ ናቸው — የ5h% መሟጠጥ በweekly% ልኬት ላይ ተጽዕኖ አያሳድርም።

### መዋስ

በለጋስ ሁነታ ውስጥ፣ ምደባውን ሙሉ በሙሉ ያልተጠቀመ ቁልፍ ከሌሎች ቁልፎች ያልተጠቀሙ ድርሻዎች የተረፈውን መጠቀም ይችላል። ቀመሩ፦

```
maxAllowed = globalLimit - consumedByOtherKeys
```

እዚህ `consumedByOtherKeys = consumedTotal - consumedByThisKey` ነው። ዓለም አቀፉ ጣሪያ (የዚያ ልኬት የክምችት `limit`) ሁልጊዜ ጠንካራው ጣሪያ ነው።

## ተንከባላይ መስኮት ቆጣሪ

በ`src/lib/quota/sqliteQuotaStore.ts` እና `redisQuotaStore.ts` ውስጥ ተተግብሯል።

ለእያንዳንዱ `(apiKeyId, dimensionKey)` ሁለት ባልዲዎች፦

- `curr`፦ የአሁኑ ባልዲ (`floor(nowMs / windowMs)`)
- `prev`፦ የቀድሞው ባልዲ (`curr - 1`)

ውጤታማው ተንከባላይ እሴት፦

```
effectiveBucketIndex = floor(nowMs / windowMs)
bucketStartMs        = effectiveBucketIndex × windowMs
elapsed              = nowMs - bucketStartMs
weight               = 1 - elapsed / windowMs

effective = prev × weight + curr
```

**ትክክለኛነት**፦ ~99% ትክክለኛ። ስህተቱ በባልዲዎቹ መካከል ባለው ወሰን ላይ ቢበዛ ከመስኮቱ መጠን 1% ነው (ይህም በ2-ባልዲ ግምቱ ውስጣዊ ባህሪ ነው)።

### ተመሳሳይ ጊዜ አፈጻጸም

የSQLite ነጂ፦ ለእያንዳንዱ `(apiKeyId | dimensionKey)` ቁልፍ ያለው የውስጠ-ማህደረ ትውስታ mutex የማንበብ-ማሻሻል-መጻፍ ውድድርን ይከላከላል። ንድፉ የ`src/sse/services/auth.ts` anti-thundering-herd አቀራረብን ይከተላል።

የRedis ነጂ፦ ለአቶሚክ ጭማሪ Lua EVAL ስክሪፕት — እንደ አንድ የRedis ትዕዛዝ ይሰራል።

## ማንቀሳቀሻዎች

### SQLite (ነባሪ፣ 0-ጭነት)

- ሰንጠረዥ፦ `quota_consumption` (ማይግሬሽን `073_quota_pools.sql` / `074_quota_consumption.sql` ይመልከቱ)።
- ለነጠላ-ኢንስታንስ ማሰማራቶች በጣም ተስማሚ ነው።
- ሁሉም ቋሚ ማከማቻ በነባሩ OmniRoute SQLite DB (`DATA_DIR/storage.sqlite`) ውስጥ ነው።

### Redis (አማራጭ፣ ባለብዙ-ኢንስታንስ)

- `ioredis` npm ፓኬጅን ይፈልጋል።
- ቆጣሪዎች በRedis ውስጥ ይከማቻሉ፤ ሜታዳታ (ፑሎች/ድልድሎች) ግን በSQLite ውስጥ ይቀጥላል።
- ቆጣሪዎች መጋራት ለሚኖርባቸው ባለብዙ-ረፕሊካ ማሰማራቶች በጣም ተስማሚ ነው።

### ማንቀሳቀሻዎችን መቀየር

በቅንብሮች UI (`/dashboard/settings` → የኮታ ማከማቻ)፣ ወይም በenv vars፦

```bash
QUOTA_STORE_DRIVER=redis
QUOTA_STORE_REDIS_URL=redis://localhost:6379
```

የDB ቅንብር ከenv ቅድሚያ አለው። `driver=redis` ከሆነ ነገር ግን URL ከሌለ ወይም
`ioredis` ካልተጫነ፣ ፋብሪካው ወደ SQLite ተመልሶ ማስጠንቀቂያ ይመዘግባል።

የማንቀሳቀሻ ምርጫ ቅደም ተከተል፦

1. የDB ቅንብር `quotaStore.driver`
2. Env `QUOTA_STORE_DRIVER`
3. ነባሪ፦ `sqlite`

## ባለብዙ-ልኬት

አንድ ፑል በርካታ ልኬቶች ሊኖሩት ይችላሉ። እያንዳንዱ ልኬት ነጻ ነው፦

```ts
QuotaDimension {
  unit: "percent" | "requests" | "tokens" | "usd",
  window: "5h" | "hourly" | "daily" | "weekly" | "monthly",
  limit: number,  // ለዚህ ልኬት የአጠቃላይ ፑል ከፍተኛ ገደብ
}
```

**ምሳሌ፦ Codex ዕቅድ** (5h% + ሳምንታዊ%)፦

```json
[
  { "unit": "percent", "window": "5h", "limit": 100 },
  { "unit": "percent", "window": "weekly", "limit": 100 }
```

- `quota_pools` + `quota_allocations` — የpool ትርጓሜዎች እና ለእያንዳንዱ ቁልፍ የሚደረጉ allocations።
- `quota_consumption` — ለእያንዳንዱ `(apiKeyId, dimensionKey)` ተንቀሳቃሽ ባለ-2-ማከማቻ ቆጣሪዎች።
- `provider_plans` — በእጅ የሚደረጉ የprovider plan overrides (ለእያንዳንዱ connectionId የdimensions JSON)።

ሁሉም tables በidempotent `CREATE TABLE IF NOT EXISTS` migrations ታክለዋል።
