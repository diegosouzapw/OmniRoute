የምክንያታዊነት ማዘዋወሪያ ደንቦች ነባሩን የሞዴል እና የጥምር ማዘዋወር ያስፋፋሉ። ምንም ንቁ ደንብ ተዛማጅ ሳይሆን ሲቀር፣
ነባሩ የማሰብ፣ የቅጥያ፣ የግንኙነት-ነባሪ እና የአቅራቢ-ትርጉም ባህሪ
ሳይቀየር ይቆያል።

## አስተዳደር

የደንብ አስተዳደር በ**Settings → Global Routing** ስር ይገኛል። የAPI-ቁልፍ አርታዒው ለተመረጠው ቁልፍ
የተጣራውን ተመሳሳይ የአስተዳደር በይነገጽ ያቀርባል።

የአስተዳደር API በእነዚህ መስመሮች ይቀርባል፦

- `GET` እና `POST` በ`/api/settings/reasoning-routing-rules`
- `GET`፣ `PATCH` እና `DELETE` በ`/api/settings/reasoning-routing-rules/[id]`
- `POST` በ`/api/settings/reasoning-routing-rules/simulate`

ሁሉም መስመሮች `requireManagementAuth`ን ይጠቀማሉ። ግብዓቶች በ
`src/shared/validation/schemas/reasoningRouting.ts` ውስጥ ባሉ ንድፎች ይረጋገጣሉ። አስመሳዩ በፍጹም ወደ ላይኛው አገልግሎት ጥሪ አያደርግም።

## የደንብ ውሳኔ

ቀደምት ግምገማው በትክክል አንድ ደንብ ይመርጣል። ወሰኖች በዚህ ቅደም ተከተል ይመረመራሉ፦

1. `apiKey`
2. `combo`
3. `model`
4. `global`

በአንድ ወሰን ውስጥ፣ መጀመሪያ ከፍተኛ `priority` ያሸንፋል፤ ከዚያም ትክክለኛ የሞዴል ተዛማጅነት ከglob ንድፍ ይቀድማል፣
በመቀጠልም የተረጋጋ `createdAt` እና `id` ቅደም ተከተል ይተገበራል። `requestTags` ከ`metadata.tags`
ብቻ ይነበባሉ እና የ`any` ወይም `all` ማዛመድን ይደግፋሉ።

የ`connection` ደንብ የሚገመገመው ምንም ቀደምት ደንብ ሳያሸንፍ እና የተወሰነ የአቅራቢ ግንኙነት
አስቀድሞ ከተመረጠ ብቻ ነው። ይህም ጥረትን እና በጀትን ብቻ ሊቀይር ይችላል።

## ጥረት እና በጀት

`sourceEffort` `any`፣ `missing`፣ `none`፣ `low`፣ `medium`፣ `high`፣ `xhigh`፣ `max` እና
`ultra`ን ይቀበላል። `missing` ማለት ጥያቄው የተለየ ጥረት፣ የማሰብ መቀያየሪያ
ወይም የማሰብ በጀት አልያዘም ማለት ነው። ስለዚህ የበጀት-ብቻ ምልክት በ`any` ብቻ ይዛመዳል።

`effortMode` ሦስት ዓይነቶች አሉት፦

- `inherit` ሞዴሉ ወይም ጥምሩ እንዲቀየር እየፈቀደ፣ የደንበኛውን ጥረት እንዳለ ያቆያል።
- `default` ግልጽ የምክንያታዊነት ምልክት ከሌለ ብቻ `targetEffort`ን ያዘጋጃል።
- `force` የተለየውን ጥረት በ`targetEffort` ይተካል።

ከዚህ ራሱን ችሎ፣ `budgetAction` `preserve`፣ `remove` ወይም `set` ሊሆን ይችላል። `force` ከ`none` ጋር ሲሆን
ሁሉንም የሚታወቁ የጥረት እና የበጀት መስኮች ያስወግዳል። `none` ከ`set` ጋር መጠቀም ልክ አይደለም።

የማይጣጣሙ መሆናቸው የታወቀ ሞዴሎችን የሚያነጣጥሩ ጥያቄዎች ወደ ላይኛው አገልግሎት ጥሪ ከመደረጉ በፊት ውድቅ ይደረጋሉ። ለጥምር
ዒላማዎች፣ የማይጣጣሙ ግቤቶች ይወገዳሉ፤ ምንም ካልቀረ፣ ጥያቄው `400` ሁኔታ ይመልሳል።
ያልታወቀ የችሎታ ውሂብ ማስጠንቀቂያ ያስከትላል እና ደንቡን ንቁ አድርጎ ያቆያል።

## ደህንነት እና ማጓጓዣዎች

የምንጭ እና የዒላማ ሞዴል፣ ወይም የምንጭ እና የዒላማ ጥምር፣ አሁንም ለነባሩ የAPI-ቁልፍ
ፖሊሲ ተገዢ ናቸው። የምክንያታዊነት ደንብ የሞዴል፣ የጥምር ወይም የኮታ ፈቃዶችን በፍጹም አያስፋፋም።

ሞተሩ ከChat Completions፣ Responses፣ Anthropic Messages እና ከውስጣዊው
Codex WebSocket መንገድ ጋር ተዋህዷል። የWebSocket መንገዱ የCodex ዒላማ ሞዴሎችን ብቻ ይቀበላል፤ የጥምር ዒላማዎች
በዚያ ሊፈጸሙ አይችሉም። የደንቡ ውሳኔ ያለ ሚስጥራዊ መረጃ በነባሩ የመስመር ዱካ ውስጥ ይከማቻል።
