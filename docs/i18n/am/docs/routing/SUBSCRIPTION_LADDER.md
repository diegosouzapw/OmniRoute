> ሁለት አዲስ `auto/*` መለያዎች — `auto/subscription` እና `auto/thrifty`። ሁለቱም በመጠየቅ
> የሚነቁ ናቸው፦ ጠሪው መለያውን በስሙ ካልጠየቀ በእነሱ በኩል ምንም አይተላለፍም፤ እንዲሁም ነባር
> ስብስብ፣ ስትራቴጂ ወይም ነባሪ ቅንብር አይቀየርም።

## ይህ ለምን እንዳለ

OmniRoute አስቀድሞ ሁለት የወጪ ጥያቄዎችን ይመልሳል፤ ነገር ግን አንዳቸውም አብዛኛዎቹ ኦፕሬተሮች የሚጠይቁት አይደሉም።

| ነባር ዘዴ                                                   | የሚመልሰው                            |
| -------------------------------------------------------- | --------------------------------- |
| `hidePaidModels` (`autoCombo/paidModelFilter.ts`)        | "ይህ ሞዴል በካታሎጉ ውስጥ ነፃ ተብሎ ተመዝግቧል?" |
| `freeAccessPolicy: "strict"` (`strictZeroCostFilter.ts`) | "ይህ ግንኙነት መቼም ወጪ ሊያስከፍለኝ ይችላል?"   |
| `quotaPreflight` (`combo/quotaExhaustionCutoff.ts`)      | "ይህ ግንኙነት ወደ ገደቡ ተቃርቧል?"          |
| `budgetCap` / `budgetFallback` (`autoCombo/engine.ts`)   | "ወጪን ገድብ፤ ወደ ርካሹ አማራጭ ዝቅ በል"      |

ሁሉም ነፃ-ብቻ ዘዴዎች **ሲሳኩ ይዘጋሉ** — ያለቀ ነፃ ስብስብ ባዶ ስብስብ ነው፤ በፍጹም
ወደ ክፍያ አማራጭ ከፍ አይልም — እና ሁሉም የክፍያ-ወገን ዘዴዎች የደረጃ ልዩነትን አያገናዝቡም። አንዳቸውም ይህን አይመልሱም፦

> "አስቀድሜ የምከፍልበትን ኮታ ተጠቀም። ሲያልቅ፣ ወይ አቁም፣ ወይም በጣም ርካሽ በሆኑ
> የክፍያ አማራጮች ውስጥ አንድ ደረጃ በአንድ ጊዜ ከፍ በል — እና ዳግም እንደተጀመረ ወዲያውኑ ተመለስ።"

## ክፍያ የግንኙነት ባህሪ እንጂ የሞዴል ባህሪ አይደለም

`classifyTier()` (`open-sse/services/tierResolver.ts`) በ`(provider, model)` መሠረት ቁልፍ ያደርግና
ከካታሎግ ዋጋዎች `free | cheap | premium` ይመልሳል። ነገር ግን ጥያቄው ተጨማሪ ገንዘብ
ያስከፍል እንደሆነ የሚወሰነው **የትኛው ግንኙነት እንደሚያገለግለው** ነው፦ ተመሳሳዩ ሞዴል በClaude Code
OAuth ግንኙነት በኩል በዕቅድ ውስጥ የተካተተ ሲሆን፣ በAPI-key ግንኙነት በኩል በቶከን መጠን ይከፈልበታል።

`provider_connections.auth_type` በየትኛውም አቅጣጫ አስተማማኝ ምትክ መለኪያ አይደለም — በአጠቃቀም የሚከፈልባቸው OAuth
ግንኙነቶች አሉ፣ እንዲሁም በዕቅድ ውስጥ የተካተቱ API-key ግንኙነቶች አሉ (የCopilot መቀመጫ ቶከን
በአጠቃቀም የሚከፈልበት API ቁልፍ አይደለም)። ስለዚህ የክፍያ ምድብ የሚመጣው ከ**በጥንቃቄ ከተዘጋጀ ካታሎግ**፣
`open-sse/config/connectionBillingCatalog.ts`፣ ነው፤ ይህም ከእያንዳንዱ አቅራቢ ይፋዊ ውሎች በእጅ የሚዋቀር ነው —
`FreeModelBudget.hardStopGuaranteed` አስቀድሞ ለነፃ ሞዴሎች የመሠረተውን ተመሳሳይ ንድፍ ይከተላል።

```ts
type ConnectionBillingClass = "subscription" | "metered" | "keyless" | "unknown";
type ConnectionOverageBehavior = "hard-stop" | "meters-to-paid" | "unknown";
```

የመፍታት ቅደም ተከተል (`autoCombo/connectionBilling.ts`)፦ ሰው ሠራሽ ማረጋገጫ-አልባ ጠቋሚ →
`keyless`፤ ከአቅራቢው **እና** ከ`authType` ጋር የሚዛመድ የካታሎግ ግቤት፤ አቅራቢ-አቀፍ ግቤት፤
ካልሆነ `unknown`። **በካታሎጉ ያልተዘጋጀ ነፃ አይደለም** — `unknown` በሁሉም ቦታ እንደ `metered`
ይወሰዳል፤ በዚህም ነገ የሚጨመር አቅራቢ ከምዝገባ ደረጃው ውጭ ይጀምራል እና ሆን ተብሎ
በካታሎጉ ውስጥ መዘጋጀት አለበት።

## የደረጃዎች ሞዴል

በማሳደግ ቅደም ተከተል አምስት ደረጃዎች። ልዩነታቸው ከዋጋ ብቻ በላይ ነው — እያንዳንዱ **የራሱ**
የመሟጠጥ ምልክት አለው፤ ስለዚህ ይህ የመደርደር ጉዳይ ብቻ አይደለም።

| #   | ደረጃ            | አባልነት                                                | የሚሟጠጥበት ሁኔታ                       |
| --- | -------------- | ---------------------------------------------------- | --------------------------------- |
| 0   | `subscription` | በካታሎጉ የተዘጋጀ `billing: "subscription"`                | የኮታ ጊዜ መስኮቱ በመቁረጫው ላይ/ከዚያ በታች ሲሆን |
| 1   | `keyless`      | ሰው ሠራሽ ማረጋገጫ-አልባው መንገድ                               | የግንኙነት ማቀዝቀዣ / ሰባሪ                |
| 2   | `free`         | በአጠቃቀም የሚከፈልበት ግንኙነት፣ `classifyTier() === "free"`    | የነፃ ፈቃድ ሲያልቅ                      |
| 3   | `cheap`        | በአጠቃቀም የሚከፈልበት ግንኙነት፣ `classifyTier() === "cheap"`   | የደረጃው በጀት ሲጠቀምበት                  |
| 4   | `premium`      | በአጠቃቀም የሚከፈልበት ግንኙነት፣ `classifyTier() === "premium"` | የደረጃው በጀት ሲጠቀምበት                  |

ደረጃዎች 0-2 በ**ኮታ** ይሟጠጣሉ፤ ይህም ሊታይ የሚችልና አስቀድሞ ክትትል የሚደረግበት ነው። ደረጃዎች 3-4 ግን
ኮታ የላቸውም — የክፍያ ግንኙነት ያለማቋረጥ ያገለግላል — ስለዚህ ብቸኛው ምክንያታዊ የመሟጠጥ ምልክታቸው የየደረጃው
**በጀት** ነው። ያለ እሱ፣ "ርካሹ ሲሟጠጥ ከፍ በል" የሚለው ምንም አስጀማሪ የለውም።

## `auto/subscription` — ዝግ ሆኖ ይክሸፍ

ስብስብ = ደረጃ 0 ብቻ፤ ትርፍ አጠቃቀማቸው በሰነድ የተገለጸ `hard-stop` በሆነባቸው ግንኙነቶች
የተገደበ ሲሆን፣ እያንዳንዳቸውም በኮታቸው ውስጥ በቂ ቀሪ እንዳላቸው በቀጥታ ይረጋገጣሉ። አሻሚ የሆነ ሁሉ
አይካተትም፦ ያልተመረጠ አቅራቢ፣ ሊረጋገጥ የማይችል የኮታ ንባብ፣ ጊዜ ያለፈበት ንባብ፣ ወይም ወደ ክፍያ የሚቆጠር ትርፍ አጠቃቀም።

ባዶ ስብስብ ጉድለት ሳይሆን **የታሰበው** ውጤት ነው — የጠሪው ነባር የባዶ-ስብስብ መንገድ
ይህን ያለድምፅ ወደሚከፈልበት አማራጭ ከመመለስ ይልቅ ወደ ግልጽ ስህተት ይቀይረዋል። የዚህ id ሙሉ ዋስትና
ይህ ነው።

`keyless` ሆን ተብሎ **አያሟላም**፦ ይህ ምድብ “እኔ የምከፍልበት ዕቅድ” ማለት ስለሆነ፣
ማረጋገጫ የማይፈልግ backend በውስጡ አይካተትም። ለዚያ `auto/thrifty` (ወይም `auto/best-free`) ይጠቀሙ።

### የግንኙነት ደህንነት

እጩ ሁልጊዜ ከአንድ ግንኙነት ጋር ብቻ የተሳሰረ አይደለም — ሎጂካዊ እጩ
የ`allowedConnectionIds` የፍቃድ ዝርዝር ይይዛል፣ በእውነት ጥቅም ላይ የሚውለው መለያም በኋላ፣ በማስተላለፍ ጊዜ፣
በ`open-sse/services/combo/autoStrategy.ts` ይመረጣል። ስለዚህ ሁለቱም ምድቦች **እያንዳንዱን ግንኙነት
ለየብቻ ያረጋግጣሉ**፣ እና `allowedConnectionIds`ን በሕይወት ወደቀረው ትክክለኛ ንዑስ ስብስብ ብቻ እንደገና
ይጽፋሉ — ፈጽሞ ሙሉውን የመጀመሪያ ዝርዝር ወይም በዘፈቀደ የተመረጠ አንድ አባል አይጠቀሙም። `autoStrategy.ts`
ይህን ድርድር እንደ ጥብቅ የፍቃድ ዝርዝር አስቀድሞ ስለሚያስፈጽም፣ እዚህ እንደገና መጻፉ “የተረጋገጠውን” እና “በእውነት
ጥቅም ላይ የዋለውን” ስብስብ በአወቃቀሩ አንድ ያደርጋቸዋል። ይህ ከ[STRICT_ZERO_COST](./STRICT_ZERO_COST.md)
ጋር ተመሳሳይ የማይለወጥ መርህ እና ተመሳሳይ አመክንዮ ነው።

## `auto/thrifty` — በአንድ ጊዜ አንድ ደረጃ ከፍ ይበሉ

ስብስብ = ሁሉም ደረጃዎች፣ በደረጃ መረጃ ጠቋሚ የተደረደሩ፣ ያለቁ እጩዎችም እንዳይገቡ የታገዱ። የ`auto` ሞተር
አሁንም በቀረው ስብስብ **ውስጥ** ነጥብ ይሰጣል፦ መሰላሉ የትኞቹ ደረጃዎች እንደሚሳተፉ ይወስናል፣ ነጥብ መስጠቱም
በውስጣቸው የትኛው እጩ እንደሚያሸንፍ ይወስናል። በአንድ ደረጃ ውስጥ ቅደም ተከተሉ የተረጋጋ ነው፣ ስለዚህ የነጥብ ሰጪው
የራሱ ደረጃ አሰጣጥ በዚህ ተደራቢ አማካኝነት ፈጽሞ እንደገና አይደራጅም።

ይህ የቅደም ተከተል + የመግቢያ ቁጥጥር ተደራቢ እንጂ **አዲስ dispatcher አይደለም**፦ የ`combo.ts` ግምታዊ loop
ዒላማዎችን በቅደም ተከተል አስቀድሞ ያልፋል እና ሲከሽፍ ወደ ቀጣዩ ይተላለፋል፤ ስለዚህ preflight ያላገኘው በሂደት ጊዜ የሚከሰት መሟጠጥ
አሁንም በዚያው ጥያቄ ውስጥ ወደ ቀጣዩ ደረጃ ከፍ እንዲል ያደርጋል።

`auto/subscription` ዝግ ሆኖ በሚከሽፍበት ጊዜ፣ `auto/thrifty` **ክፍት** ሆኖ ይከሽፋል፦ ከዕቅዱ ጋር የተካተተ
ግንኙነት ጥቅም ላይ የሚውል የኮታ ንባብ ባይኖረውም አሁንም መጀመሪያ ይሞከራል። መሞከሩ ምንም ወጪ የለውም፣ እና
ተሟጦ ከተገኘ የመተላለፍ ሂደቱ ለማንኛውም ወደ ቀጣዩ ደረጃ ይደርሳል — እሱን ለመሞከር አለመፍቀድ ግን
የቴሌሜትሪ መረጃ በሌለበት ጊዜ ጥያቄውን ወደሚከፈልበት ደረጃ ይልከዋል፤ ይህም ምድቡ እንዲከላከለው
የተፈጠረበት ትክክለኛ ውጤት ነው።

## ዳግም ከተጀመረ በኋላ ወደ ዕቅዱ መመለስ

ማዞሪያው ወደ ደረጃ 0 ከመመለሱ በፊት ሦስት ነጻ ነገሮች ጊዜያቸው ማለፍ አለበት። አንዱን ብቻ ማስተካከል
ዕቅዱ ከተሞላ ከረጅም ጊዜ በኋላም መሰላሉ በሚከፈልባቸው ደረጃዎች ላይ እንደተጣበቀ ያስቀረዋል።

1. **የኮታ ሁኔታ cache** — `freeAccessQuota.ts` ለእያንዳንዱ `(provider, connection)` በ180s TTL cache
   ያደርጋል። የራሱ `resetAt` አስቀድሞ ያለፈበት cache የተደረገ መዝገብ ከእንግዲህ የሌለ የጊዜ መስኮትን
   ይገልጻል፤ ስለዚህ **ዕድሜው ምንም ቢሆን** አሁን ጊዜ ያለፈበት ተደርጎ ይወሰዳል እና መታደስን ያስገድዳል።
   ይህ ከሌለ፣ እኩለ ሌሊት የተሞላ ዕቅድ TTL በአጋጣሚ ጊዜው እስኪያልፍ ድረስ እንደተሟጠጠ መነበቡን ይቀጥላል።
2. **የመሰላሉ የራሱ ሁኔታ** — በንድፍ ምክንያት ምንም የለውም። የደረጃ ብቁነት ስብስቡ በተገነባ ቁጥር
   ከቀጥታ የኮታ ሁኔታ እንደገና ይሰላል፤ ዳግም መጀመርን አልፎ ሊቆይ እና ማዞሪያውን ሊያጣብቅ የሚችል
   የተከማቸ “በአሁኑ ጊዜ በደረጃ 3 ላይ” የሚል መዝገብ የለም።
3. **የግንኙነት cooldown** — መሟጠጡን ያመጣው 429 `rateLimitedUntil`ን ከexponential
   backoff ያዘጋጃል፤ ይህም ለዕቅድ ግንኙነት ትክክለኛውን ዳግም መጀመሪያ ሊያልፍ ይችላል። `clampCooldownToReset()`
   (`subscriptionLadder.ts`) cooldownን ወደ upstream የራሱ የዳግም መጀመሪያ ቅጽበት ያሳጥራል እንጂ
   ፈጽሞ ሊያራዝመው አይችልም። **ተተግብሯል እና ተፈትኗል፣ ነገር ግን ገና አልተገናኘም**፦ በ`src/sse/services/auth.ts` ውስጥ
   ያለው የኮታ cache ማንኛውም cooldown ከመጻፉ _በፊት_ ዋጋ-አልባ ይደረጋል፤ ስለዚህ `resetAt`
   በዚያ ፋንክሽን ውስጥ ቀደም ብሎ መያዝ አለበት — ይህም የresilience hot path ለውጥ ስለሆነ
   የራሱ የተገመገመ PR ያስፈልገዋል። እስከዚያ ድረስ፣ እንደገና መግባት የግንኙነቱ cooldown እስኪያልቅ ይጠብቃል
   (አቅራቢው ሲልካቸው ይህ አስቀድሞ የupstream `Retry-After` ፍንጮችን ይመርጣል)።

### ፈጣን መቀያየርን መከላከል

አሁን ዳግም የጀመረ ደረጃ ከ`reentryMinRemainingPercent` (ነባሪ 5) በላይ ሲሆን ብቻ እንደገና ይገባል፤
አስቀድሞ ጥቅም ላይ ያለ ግንኙነት ግን ከ`exitCutoffPercent` (ነባሪ 2፣
ከ`quotaPreflight.defaultThresholdPercent` ጋር የሚዛመድ) በላይ ብቻ መቆየት ይኖርበታል። በመካከላቸው ያለው ልዩነት የhysteresis band ነው — ይህ
ከሌለ፣ የመጨረሻው ገደብ አካባቢ የሚንሳፈፍ ግንኙነት በተከታታይ ጥያቄዎች መካከል ከአንድ ደረጃ ወደ ሌላ ይዋዥቃል።

## ውቅር

ለማስተካከያ ብቻ ነው። ሆን ተብሎ `enabled` ምልክት **የለም**፦ እነዚህን ማጥፋት የሚችል መቀያየሪያ
`auto/subscription` የሚከፈልባቸውን ሞዴሎችም ጨምሮ ሙሉውን ስብስብ የገባውን ቃል በሚቃረን ስም
በጸጥታ እንዲያቀርብ ያደርገዋል።

```jsonc
{
  "subscriptionLadder": {
    "exitCutoffPercent": 2,
    "reentryMinRemainingPercent": 5,
    "rungBudgetUsd": { "cheap": 5.0, "premium": 0 }, // 0 አንድን ደረጃ ሙሉ በሙሉ ያሰናክላል
  },
}
```

የወጪ መፍቻ እስኪገናኝ ድረስ በበጀት ላይ የተመሠረተው ገደብ የማይሠራ ነው፦ የሂሳብ መረጃ በማይኖርበት ጊዜ የሚከፈልበት
ደረጃ ቅደም ተከተል ይሰጠዋል፣ ነገር ግን በገደብ አይታገድም። ከv3.8.51 ጀምሮ የ`rungBudgetUsd` ቅንብር በschemaው
ተቀባይነት ያገኛል፣ ነገር ግን ገና ተፈጻሚ **አይደለም** — እንደ ንቁ የወጪ ጣሪያ ሳይሆን እንደ ተያዘ ውቅር ይዩት። የደረጃዎች ቅደም ተከተል፣ በኮታ ላይ የተመሠረተ ማለቅ እና ከዳግም ማስጀመር በኋላ እንደገና መግባት ሁሉም
ያለሱ ይሠራሉ።

## ቅንብር

`subscription` እና `thrifty` የ`AutoTier` እሴቶች ናቸው፣ ስለዚህ ከእያንዳንዱ ምድብ ጋር ሊጣመሩ ይችላሉ፦
`auto/coding:thrifty`፣ `auto/reasoning:subscription`፣ ወዘተ። ሁለቱ ጠፍጣፋ ids
(`auto/subscription`፣ `auto/thrifty`) በ`/v1/models` እና በዳሽቦርዱ ላይ ይታወቃሉ።

ከሁለቱም id አንዳቸውም የሚከፈልበት ደረጃ አይደሉም፣ ስለዚህ `isPaidTierAutoId()` ለሁለቱም `false` ይመልሳል እና
`auto/subscription` ከ`hidePaidModels` በኋላም ይቆያል።
