### የጥያቄ / የአጠቃቀም ምዝግቦች

እነዚህ የአሠራር ቴሌሜትሪ መረጃዎች ናቸው (በጥብቅ አነጋገር የአስተዳደር ኦዲት አይደሉም)፣ ነገር ግን ተመሳሳዩን የማቆያ ሂደት ይጋራሉ፦

- `usage_history` — ለእያንዳንዱ ጥያቄ የተጠቃለለ አጠቃቀም
- `call_logs` — ለእያንዳንዱ ጥያቄ ሙሉ ምዝግብ (የረድፍ ከፍተኛ ገደብ ይኖረዋል፤ ከታች ይመልከቱ)
- `proxy_logs` — የፕሮክሲ ትራፊክ ምዝግብ (የረድፍ ከፍተኛ ገደብ ይኖረዋል)
- `request_detail_logs` — የቀድሞ ዝርዝር የጥያቄ ምዝግብ (ካለ አሁንም ይመነጠራል)

## የማከማቻ መዋቅር

`audit_log` ለመጀመሪያ ጊዜ ጥቅም ላይ ሲውል በ`ensureAuditLogSchema()` ቀስ ብሎ ይፈጠራል፦

```sql
CREATE TABLE IF NOT EXISTS audit_log (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  timestamp     TEXT NOT NULL DEFAULT (datetime('now')),
  action        TEXT NOT NULL,
  actor         TEXT NOT NULL DEFAULT 'system',
  target        TEXT,
  details       TEXT,
  ip_address    TEXT,
  resource_type TEXT,
  status        TEXT,
  request_id    TEXT,
  metadata      TEXT
);
```

ኢንዴክሶች በ`timestamp`፣ `action`፣ `actor`፣ `resource_type`፣
`status` እና `request_id` ላይ ይፈጠራሉ። በቀድሞ DBዎች ላይ የጎደሉ ዓምዶች እንደ አስፈላጊነቱ
በ`ALTER TABLE` በኩል ይጨመራሉ።

## የማቆያ ጊዜ እና ማጽዳት

ሁለት የተለያዩ የማቆያ ጊዜያት ይከበራሉ፦

| የአካባቢ ተለዋዋጭ                 | ነባሪ      | ተፈጻሚ የሚሆንባቸው                                                      |
| --------------------------- | -------- | ----------------------------------------------------------------- |
| `APP_LOG_RETENTION_DAYS`    | `7`      | `audit_log`, `mcp_tool_audit`                                     |
| `CALL_LOG_RETENTION_DAYS`   | `7`      | `usage_history`, `call_logs`, `proxy_logs`, `request_detail_logs` |
| `CALL_LOGS_TABLE_MAX_ROWS`  | `100000` | ለ`call_logs` የረድፍ ገደብ ቅነሳ                                         |
| `PROXY_LOGS_TABLE_MAX_ROWS` | `100000` | ለ`proxy_logs` የረድፍ ገደብ ቅነሳ                                        |

`cleanupExpiredLogs()` የማቆያ ሂደቱን ያከናውናል። ከ`src/instrumentation-node.ts`
በአገልጋዩ መነሳት ወቅት ይጠራል። እያንዳንዱ አሂድ የእያንዳንዱን ሰንጠረዥ የስረዛ ብዛት የያዘ
የ`compliance.cleanup` የኦዲት ክስተት ይመዘግባል። ረጅም የመጻፍ መቆለፊያዎችን ለማስወገድ የፕሮክሲ/ጥሪ
ምዝግብ ቅነሳ በቡድን (`BATCH_SIZE = 5000`) ይከናወናል።

በእጅ የሚከናወን የጥያቄ ታሪክ ማጽዳት ከማቆያ ሂደቱ የተለየ ነው። የጥያቄ ምዝግቦች
ገጽ `POST /api/settings/purge-request-history`ን ይጠራል፤ ይህም `call_logs`ን፣
የቆዩ `request_detail_logs`ን እና በ
`${DATA_DIR}/call_logs/` ስር ያሉ የአካባቢ ጥያቄ ቅሪቶችን ይሰርዛል።

ነባሪዎች በ`src/lib/logEnv.ts`
(`DEFAULT_APP_LOG_RETENTION_DAYS = 7`, `DEFAULT_CALL_LOG_RETENTION_DAYS = 7`) ውስጥ ተገልጸዋል።

## የ`noLog` መውጫ ምርጫ (ለእያንዳንዱ API ቁልፍ)

የታችኛው የጥሪ ትራፊካቸው እንዳይመዘገብ API ቁልፎች ምልክት ሊደረግባቸው ይችላል።
ምልክቱ በ`api_keys` ሰንጠረዥ (`no_log INTEGER DEFAULT 0`) ላይ ይኖራል፣ እና ፈጣን የመንገድ ፍለጋዎችን ለማከናወን
ወደ ውስጠ-ማህደረ ትውስታ ስብስብ ይንጸባረቃል።

```bash
# ምዝግብ የሌለው ቁልፍ ይፍጠሩ (የአስተዳደር ማረጋገጫ ያስፈልጋል)
curl -X POST http://localhost:20128/api/keys \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"name": "Privacy key", "noLog": true}'
```

አጋዥ ተግባራት (`src/lib/compliance/index.ts`)፦

- `setNoLog(apiKeyId, true|false)` — የውስጠ-ማህደረ ትውስታ ግቤቱን ያብሩ ወይም ያጥፉ
- `isNoLog(apiKeyId)` — በጥያቄው መንገድ ላይ ይፈተሻል፤ ካልተገኘ ከ`api_keys.no_log`
  የ30 s የተሸጎጠ ንባብን ይጠቀማል
- `NO_LOG_API_KEY_IDS` (env፣ በነጠላ ሰረዝ የተለዩ) — ሲነሳ ቀድሞ ወደ ውስጠ-ማህደረ ትውስታ
  ስብስብ ይጫናል፤ ዓምዱን በቀጥታ ማብራት ወይም ማጥፋት በማይችሉበት ጊዜ ጠቃሚ ነው

የአስተዳደር ኦዲት ክስተቶች (መግባት፣ የአቅራቢ ለውጦች፣ የMCP መሣሪያ ጥሪዎች፣ ወዘተ)
በ`noLog` **አይነኩም** — የመውጫ ምርጫው ተፈጻሚ የሚሆነው ለእያንዳንዱ ጥያቄ የትራፊክ ምዝገባ ብቻ ነው።

| `/api/mcp/audit`            | `GET` | በገጽ የተከፋፈሉ የMCP መሣሪያ ኦዲት መዝገቦች   | (open-sse) |
| `/api/mcp/audit/stats`      | `GET` | የተጠቃለሉ የMCP ኦዲት ስታቲስቲክሶች         | (open-sse) |

በአሁኑ ጊዜ የCSV ወደ ውጭ መላኪያ መጨረሻ ነጥብ አልተካተተም — ከዳሽቦርዱ ወደ ውጭ ይላኩ ወይም
የSQLite የውሂብ ጎታውን በቀጥታ ይጠይቁ።

### `/api/compliance/audit-log`ን መጠየቅ

የሚደገፉ የጥያቄ መለኪያዎች (ሁሉም አማራጭ ሲሆኑ፣ ሁሉም ለጽሑፍ ማጣሪያዎች
የ`LIKE %value%` ማዛመድን ይጠቀማሉ):

- `action`, `actor`, `target`, `resourceType` (ወይም `resource_type`),
  `status`, `requestId` (ወይም `request_id`)
- `from` / `since`, `to` / `until` — የISO የጊዜ ማህተሞች
- `limit` (ነባሪ `50`፣ ዝቅተኛው `1`፣ ከፍተኛው `500`)
- `offset` (ነባሪ `0`፣ ከፍተኛው `10_000`)

ምላሹ የJSON ድርድር ነው። የገጽ ክፍፍል ሜታዳታ በርዕሶች ውስጥ ይመለሳል:
`x-total-count`, `x-page-limit`, `x-page-offset`.

```bash
curl "http://localhost:20128/api/compliance/audit-log?action=provider.credentials&from=2026-05-01" \
  -H "Cookie: auth_token=..."
```

## ዳሽቦርድ

ዳሽቦርዱ የኦዲት ውሂብን በ**`/dashboard/audit`**
(`src/app/(dashboard)/dashboard/audit/page.tsx`) ላይ ያቀርባል። ገጹ ሁለት ትሮች አሉት:

- **ተገዢነት** (`ComplianceTab.tsx`) — ከ
  `/api/compliance/audit-log` የሚመጡ የአስተዳዳሪ ኦዲት ክስተቶች። በክስተት ዓይነት፣ የክብደት ደረጃ (መረጃ / ማስጠንቀቂያ
  / ወሳኝ፣ ከaction + status የሚወጣ) እና በቀን ክልል ያጣራል። የክብደት ደረጃው
  ከaction/status ሕብረቁምፊዎች በደንበኛ በኩል ይሰላል።
- **MCP** (`McpAuditTab.tsx`) — ከ`/api/mcp/audit` የሚመጣ የMCP መሣሪያ ኦዲት፣
  በመሣሪያ ስም እና በስኬት/ውድቀት ማጣሪያዎች ያሉት።

ሁለቱም ትሮች በ`50` (ተገዢነት) እና `25` (MCP) የገጽ መጠኖች
የገጽ ክፍፍል ያደርጋሉ።

## የአቅራቢ ማረጋገጫ መረጃ አጋዥ ተግባራት

`src/lib/compliance/providerAudit.ts` የአቅራቢ አስተዳደር መስመሮች
የማረጋገጫ መረጃ ክስተቶችን ሲለቁ የሚጠቀሙባቸውን የቅርጽ ማዘጋጃ አጋዥ ተግባራት ያቀርባል:

- `summarizeProviderConnectionForAudit(connection)` — የግንኙነቱ ቅጽበታዊ ገጽታ
  ወደ`details` ከመጻፉ በፊት `apiKey`፣
  `accessToken`፣ `refreshToken`፣ `idToken` እና
  `providerSpecificData.consoleApiKey`ን ያስወግዳል።
- `getProviderAuditTarget(connection)` — ለ`target` መስክ የማይለዋወጥ
  `"<provider>:<name|id>"` ሕብረቁምፊ ያቀናብራል።
- `extractProviderWarnings(...payloads)` — የአቅራቢ ምላሾችን ለፖሊሲ/ደህንነት
  ማስጠንቀቂያዎች (`[sanitizer]`፣ `prompt injection detected`፣
  `content has been filtered`፣ `safety filter`፣ `policy violation`) ይቃኛል እና
  እያንዳንዱ እስከ 400 ቁምፊዎች የተቆረጠ እስከ 5 ውጤቶችን ያሳያል።

## ምርጥ ልምዶች

- PIIን (የሕግ፣ የሕክምና ወዘተ) የሚያስተናግዱ የAPI ቁልፎችን በ`noLog: true` ምልክት ያድርጉ።
- የማቆያ ፖሊሲዎን ለማሟላት `APP_LOG_RETENTION_DAYS` / `CALL_LOG_RETENTION_DAYS`ን
  ያስተካክሉ። የ7-ቀን ነባሪ ቅንብሮች ጥንቃቄ የተሞላባቸው ናቸው።
- የተገዢነት ፕሮግራምዎ በሚጠይቀው ማንኛውም የጊዜ ሰሌዳ መሠረት የኦዲት ሰንጠረዡን ከመድረኩ ውጭ
  (`sqlite3 dump`) ይላኩ — አብሮ የተሰራ ማህደር ማከማቻ የለም።
- የጉልበት-ጥቃት ሙከራዎችን ለመለየት የ`auth.login.failed` እና `auth.login.locked`
  ብዛቶችን ይከታተሉ።
- አዲስ የአስተዳዳሪ መጨረሻ ነጥቦችን ሲጨምሩ፣ በማይለዋወጥ
  `domain.verb.outcome` የaction ሕብረቁምፊ `logAuditEvent({ ... })`ን ይጥሩ እና IP እና `requestId`
  በራስ-ሰር እንዲቀረጹ የጥያቄውን አውድ በ
  `getAuditRequestContext(request)` ያስተላልፉ።
