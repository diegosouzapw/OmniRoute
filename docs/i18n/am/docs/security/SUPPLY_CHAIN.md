OmniRoute የnpm + Docker አርቲፋክቶችን ያትማል። እነዚህ ጌቶች የምንጭ ማረጋገጫን፣
ዝርዝር መረጃን (SBOM) እና የCVE ቅኝትን ይሰጣሉ፤ ሁሉም OSS ሲሆኑ ከልቀት የሥራ ፍሰቶች ጋር ተዋህደዋል።
**መጀመሪያ-ማሳሰቢያ** አቋም — አሁን ሪፖርት ያደርጋሉ፣ ከመጀመሪያው
ስኬታማ ልቀት በኋላ ወደ አጋጅነት ያድጋሉ።

| ጌት                    | መሣሪያ                                           | ቦታ                            | ያግዳል?          | ውጤት                                                   |
| --------------------- | ---------------------------------------------- | ----------------------------- | -------------- | ----------------------------------------------------- |
| SLSA የምንጭ ማረጋገጫ (npm) | `npm --provenance` (OIDC)                      | `npm-publish.yml`             | ህትመቱ ካልተሳካ ብቻ  | npmjs ባጅ / `npm audit signatures`                     |
| SBOM npm              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`             | ማመንጨቱ ካልተሳካ ብቻ | የልቀት ንብረት + አርቲፋክት                                    |
| SBOM ምስል              | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (ውህደት)   | ማሳሰቢያ          | CycloneDX አርቲፋክት                                      |
| Trivy CVE (SARIF)     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (ውህደት)   | ማሳሰቢያ          | SARIF (HIGH+CRITICAL) → የደህንነት ትር                     |
| Trivy CRITICAL ጌት     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (ውህደት)   | **አጋጅ**        | ሊስተካከል በሚችል CRITICAL ላይ `exit-code: '1'`              |
| osv vulnCount         | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`) | **አጋጅ**        | `metrics.vulnCount`ን ቀስ በቀስ ያጠናክራል (`direction:down`) |
| OpenSSF Scorecard     | `ossf/scorecard-action`                        | `scorecard.yml` (cron)        | ማሳሰቢያ          | SARIF → ደህንነት + ባጅ                                    |

የምስል CVE ቀስ በቀስ ማጠናከሪያው በ`docker-publish.yml` ውስጥ **ሁለት ደረጃዎችን** ይጠቀማል፦ የSARIF ደረጃው
(`HIGH,CRITICAL`, `exit-code: 0`) ሳያግድ HIGH+CRITICALን በደህንነት ትሩ ውስጥ እንዲታይ ያደርጋል፤
የ_CRITICAL ጌት_ ደረጃ (`severity: CRITICAL`, `ignore-unfixed: true`,
`exit-code: 1`) **ማስተካከያ ባለው** CRITICAL CVE ላይ ልቀቱን ያስወድቃል። `ignore-unfixed`
የላይኛው ምንጭ ማስተካከያ በሌለው የመሠረታዊ ምስል CVE ምክንያት ልቀቱ እንዳይታገድ ይከላከላል።

## ⚠️ የCVE መለዋወጥ (አጋጅ የosv/Trivy ጌቶች)

osv እና Trivy ጥገኞችን **ያለማቋረጥ እያደጉ ካሉ** የCVE የውሂብ ጎታዎች ጋር ያነጻጽራሉ።
**ምንም ጥገኝነቶችን የማይነካ** PR በነባር ጥገኝነት ውስጥ አዲስ CVE
ይፋ ስለተደረገ በድንገት ቀይ ሊሆን ይችላል (osv፦ የተለካው `vulnCount` > መነሻ መስመር፤ Trivy፦ በምስሉ ውስጥ አዲስ
ሊስተካከል የሚችል CRITICAL)። **ይህ የሚጠበቅ የአጋጅ
CVE ጌት የአሠራር ባህሪ እንጂ የምርት ወደኋላ መመለስ አይደለም።**

አዲስ ይፋ በተደረገ CVE ምክንያት osv ወይም Trivy ቀይ ሲሆኑ መፍትሔው፦

1. **ተጽዕኖ የደረሰበትን ጥገኝነት ያሳድጉ** (ይመረጣል) — በ`package.json`
   `overrides` (ተሻጋሪ ጥገኝነቶች) በኩል ወደ ተስተካከለው ስሪት ያሳድጉ ወይም ምስሉን በተስተካከለ መሠረት ላይ እንደገና ይገንቡ።
2. **የላይኛው ምንጭ ማስተካከያ ከሌለ፦**
   - **osv:** በ`config/quality/quality-baseline.json` ውስጥ `metrics.vulnCount`ን እንደገና መነሻ ያድርጉ
     (`npm run quality:ratchet -- --update` ራሳቸውን የቻሉ ጌቶችን አያካትትም — እሴቱን
     በእጅ ያርትዑ፣ `direction:down`)፤ የማረጋገጫ ማስታወሻ + የክትትል ጉዳይ ያክሉ።
   - **Trivy:** በ`.trivyignore` ውስጥ ግቤት (በእያንዳንዱ መስመር CVE-ID) ከማረጋገጫ
     አስተያየት + የክትትል ጉዳይ ጋር ያክሉ። `ignore-unfixed: true` ማስተካከያ
     የሌላቸውን CVEዎች አስቀድሞ በራስ-ሰር ይሸፍናል።

መሣሪያው በማይገኝበት ጊዜ ወይም ልኬቱ ሳይሳካ ሲቀር ሁለቱም ጌቶች **በችግር ሳይወድቁ SKIP ያደርጋሉ**
(exit 0) (osv-scanner በPATH ውስጥ አለመኖር፣ osv.dev/network አለመደረስ፣ ልክ ያልሆነ JSON) —
የ**ልኬት** ውድቀት በፍጹም አያግድም፤ የሚያግደው የ**ተለካ** ወደኋላ መመለስ ብቻ ነው።
