OmniRoute የአቅራቢውን ወደላይኛ የስህተት ምላሾች፣ **መለያው በቋሚነት የተዘጋ** መሆኑን
(የታገደ / የቦዘነ / በአገልግሎት ውሎች ጥሰት የታገደ) የሚያመለክቱ ምልክቶችን ለማግኘት
ይቃኛል፤ ተዛማጅ ምልክት ሲገኝም ግንኙነቱን ወደ **መጨረሻዊ `banned` ሁኔታ**
በማዛወር ከዚያ በኋላ ለጥያቄዎች እንዳይመረጥ ያደርገዋል። የ**Security → Banned Keywords**
ቅንብሮች ካርድ የሚያዋቅረው ይህንን ነው ("ቋሚ የመለያ እገዳን ለማወቅ የሚያነሳሱ ተጨማሪ ቁልፍ ቃላት።
አብረው የተካተቱ ቁልፍ ቃላት ሁልጊዜ ተግባራዊ ይሆናሉ።").

ይህ ገጽ አብሮ የተካተተውን ዝርዝር፣ የማወቂያ ፍሰቱን፣ የተግባር ወሰኑን፣ ብጁ
ቁልፍ ቃላትን በደህንነት እንዴት ማከል እንደሚቻል፣ እና ምልክት የተደረገበትን ግንኙነት
እንዴት መልሶ ማግኘት እንደሚቻል ይመዘግባል። መጨረሻዊው ሁኔታ ራሱ የጽናት ሞዴሉ አካል ነው —
[RESILIENCE_GUIDE](../architecture/RESILIENCE_GUIDE.md) ("መጨረሻዊ ሁኔታዎች")ን ይመልከቱ።

**የትክክለኛው መረጃ ምንጭ:** `open-sse/services/accountFallback.ts`
(`ACCOUNT_DEACTIVATED_SIGNALS`, `getMergedBannedSignals()`, `isAccountDeactivated()`).

## አብረው የተካተቱ ቁልፍ ቃላት

እነዚህ 8 ንዑስ ሕብረቁምፊዎች፣ ማንኛውም ብጁ ዝርዝር ቢኖርም፣ ሁልጊዜ ተግባራዊ ይሆናሉ (የፊደል አቢይነትን ሳይለዩ):

```
account_deactivated
account has been deactivated
account has been disabled
your account has been suspended
this account is deactivated
verify your account to continue                                 (Antigravity / Google Cloud Code)
this service has been disabled in this account for violation    (Antigravity)
this service has been disabled in this account                  (Antigravity)
```

> አቅራቢዎች የእገዳ መልዕክታቸውን ሲቀይሩ ይህ ዝርዝርም አብሮ ይሻሻላል። የባለሥልጣኑ
> ቅጂ `open-sse/services/accountFallback.ts` ውስጥ ያለው `ACCOUNT_DEACTIVATED_SIGNALS` ነው፤
> ከላይ ያለውን ብሎክ እንደ ቅጽበታዊ ቅጂ ይቆጥሩት።

ሁለት አጎራባች፣ **የተለያዩ** የምልክት ሰንጠረዦች በዚሁ ፋይል ውስጥ ይገኛሉ፤ ነገር ግን
የታገዱ ቁልፍ ቃላትን የማወቅ ሂደት አካል _አይደሉም_:

- `CREDITS_EXHAUSTED_SIGNALS` — የክፍያ/ኮታ መሟጠጥ (`insufficient_quota`,
  `credit_balance_too_low`, `payment required`, …) → መጨረሻዊ `credits_exhausted`.
- `OAUTH_INVALID_TOKEN_SIGNALS` — **መጨረሻዊ ያልሆነ**፤ የቶከን እድሳት መልሶ ማስተካከል ይችላል።

ማስታወሻ፦ እንደ **`rate limit`** / `429` ያሉ የተለመዱ ጊዜያዊ ሐረጎች በ
የፍጥነት-ገደብ / የግንኙነት-ማቀዝቀዣ መንገድ ይስተናገዳሉ፤ የእገዳ ምልክቶችም **አይደሉም**።

## የማወቂያ ፍሰት

```
ወደላይኛ የስህተት ምላሽ
  → body ወደ ሕብረቁምፊ ተቀይሮ ወደ ንዑስ ፊደል ይለወጣል
  → isAccountDeactivated(body): getMergedBannedSignals().some(sig => body.includes(sig))   [የንዑስ ሕብረቁምፊ ማዛመድ]
  → ተዛማጅ አለ?
      → የግንኙነቱ testStatus = "banned"      (ቋሚ — የ1 ዓመት ማቀዝቀዣ፣ በራስ-ሰር ፈጽሞ አያገግምም)
      → ቅንብሩ `autoDisableBannedAccounts` በርቶ ከሆነ እና `autoDisableBannedScope`
        ይህን ግንኙነት የሚያካትት ከሆነ (`all`፣ ወይም ለ OAuth/cookie/session `subscription`)
        → እንዲሁም isActive = false። ወሰኑ `subscription` ሲሆን ቅድመ ክፍያ API keys
        ንቁ ሆነው ይቆያሉ።
      → በመለያ ምርጫ ወቅት ግንኙነቱ ይዘለላል (የተጣመሩ QUOTA_BLOCKING ሁኔታዎች)
```

- ማዛመዱ በምላሹ **body** ላይ የሚደረግ **የፊደል አቢይነትን የማይለይ የንዑስ ሕብረቁምፊ**
  ፍለጋ ነው (`isAccountDeactivated`, `accountFallback.ts`)።
- ቋሚው የ`banned` መጨረሻዊ ማድረግ የታገደ ምልክት ያለበት body በ**ማንኛውም
  HTTP status** ሲመጣ ይነሳል (በ`markAccountUnavailable` → `checkFallbackError` በኩል)።
  ይበልጥ የተወሰነው **`deactivated`** መለያ (ግንኙነቱ ተጨማሪ API keys ከሌሉት
  `isActive=false`) በመስመር ውስጥ ባለው `chatCore.ts` መንገድ በ**HTTP 401 / 403**
  ላይ ይጻፋል (በ`classifyProviderError` → `ACCOUNT_DEACTIVATED` ይመደባል)።
  የ`markAccountUnavailable()` መንገድ ለተመሳሳዩ `ACCOUNT_DEACTIVATED` ምልክት
  (በ`resolveTerminalConnectionStatus` በኩል) _የተለየ_ መጨረሻዊ ሁኔታ — **`expired`** —
  እንደሚጽፍ ያስተውሉ፤ ስለዚህ አንድ አይነት እገዳ ምላሹን በየትኛው መንገድ
  እንደተስተናገደ በመመርኮዝ `deactivated` ወይም `expired` ሆኖ ሊታይ ይችላል።
  (የቆየው የኮድ አስተያየት "የ401 body እነዚህን ሕብረቁምፊዎች ሲይዝ" ይላል — ይህም
  የአሁኑን ባህሪ ሙሉ በሙሉ አይገልጽም።)
- `banned` ግንኙነት መጨረሻዊ ሁኔታዎች በሚጣሩባቸው ቦታዎች ሁሉ ከምርጫ ይገለላል
  (`isTerminalConnectionStatus`፣ የተጣመረ `QUOTA_BLOCKING_CONNECTION_STATUSES`)።

## ወሰን — የትኞቹ አቅራቢዎች ይቃኛሉ

**ሁሉም አቅራቢዎች።** ምርመራው እያንዳንዱ ያልተሳካ የupstream ጥያቄ በሚያልፍበት አጠቃላይ የስህተት አያያዝ ፍሰት ውስጥ ይሰራል — ለOAuth/የደንበኝነት ምዝገባ scrapers **ብቻ** የተገደበ አይደለም። የሚፈጠረው የመጨረሻ ሁኔታ በእያንዳንዱ **ግንኙነት** ደረጃ እንጂ በአቅራቢ ደረጃ አይደለም።

ይሁን እንጂ፣ አብረው የሚመጡት _ሕብረቁምፊዎች_ እውነተኛ የእገዳ አደጋ ላላቸው የደንበኝነት ምዝገባ/OAuth አቅራቢዎች (ChatGPT Web Codex, Claude Web, Codex, Muse Spark,
Antigravity) ያተኮሩ ናቸው። የAPI ቁልፍ አቅራቢ መለያውን የሚቀሰቅሰው የስህተት ይዘቱ ከንዑስ ሕብረቁምፊዎቹ አንዱን ቃል በቃል ከያዘ ብቻ ነው።

`autoDisableBannedScope` (`all` | `subscription`፣ ነባሪው `all`) ተዛማጅነት ሲገኝ `isActive=false` እንዲሆንም ይቀየር እንደሆነ ይቆጣጠራል። `subscription` ማለት በመግቢያ መረጃ የሚሰሩ መቀመጫዎችን (የሚከፈልባቸው የደንበኝነት ምዝገባዎችንና ነፃ መለያዎችን፣ የድር-cookie ክፍለ ጊዜዎችንም ጨምሮ) ማለት ነው። ለቅድመ ክፍያ API ቁልፎች አሁንም `testStatus=banned` ይመዘግባል፣ ነገር ግን በማስተላለፊያ ስብስቡ ውስጥ ይተዋቸዋል። ዘላቂው ንድፍ በእያንዳንዱ አቅራቢና መለያ ደረጃ የሚተገበር መሻሪያ ነው፤ ዓለም አቀፉ enum የመጀመሪያው ትግበራ ነው።

## ብጁ የእገዳ ቁልፍ ቃላት

በ**Security → Banned Keywords** ውስጥ ቁልፍ ቃላትን ያክሉ ወይም ያስወግዱ (በ`PATCH /api/settings` በኩል እንደ ዓለም አቀፍ `customBannedSignals` ቅንብር ይቀመጣሉ)። እነዚህ በስርዓቱ አብሮ በሚመጣው ዝርዝር ላይ **ይጨመራሉ** — ፈጽሞ ምትክ አይሆኑም — እና ሲቀመጡ (እንዲሁም ሲጀመር) በ`setCustomBannedSignals()` አማካኝነት ወዲያውኑ እንደገና ይጫናሉ። እያንዳንዱ ቁልፍ ቃል እስከ 200 ቁምፊዎች ይገደባል፤ በድርድሩ ርዝመት ላይ ገደብ የለም።

**⚠ የሐሰት አዎንታዊ ውጤት አደጋ — የተወሰኑ ሐረጎችን ይምረጡ።** ማወቂያው በጠቅላላው የምላሽ ይዘት ላይ የሚደረግ ቀጥተኛ የንዑስ ሕብረቁምፊ ማዛመድ ነው፣ እና አንድ ተዛማጅነት **ቋሚ** ነው (የ1 ዓመት ማቀዝቀዣ፣ በእጅ መመለስ)። ሰፊ ቁልፍ ቃል ሙሉ በሙሉ ጤናማ የሆነ ግንኙነትን ሊያግድ ይችላል፦

- **መጥፎ፦** `quota`፣ `limit`፣ `error`፣ `denied` — በብዙ ጊዜያዊ ስህተቶች ውስጥ ይታያሉ።
- **ጥሩ፦** ሙሉ የእገዳ ዓረፍተ ነገሮች፣ ለምሳሌ `your account has been suspended for`፣
  `account permanently banned`፣ `violation of our terms`።

አቅራቢው በእውነተኛ እገዳ ጊዜ ከሚመልሰው ውስጥ ረጅሙንና ግልጽ የሆነውን ሐረግ ይምረጡ። ጥርጣሬ ሲኖር፣ መጀመሪያ የግንኙነቱን `lastError` ይከታተሉ፣ ከዚያም ትክክለኛውን አገላለጽ ያክሉ።

## ምልክት የተደረገበትን ግንኙነት መመለስ

የመጨረሻ `banned` / `deactivated` ሁኔታዎች **በራስ-ሰር ፈጽሞ አይመለሱም** (ከቅድመ-እርምጃ መልሶ ማግኛ ዙር ይገለላሉ — በራሳቸው የሚመለሱት የ`unavailable` ማቀዝቀዣዎች ብቻ ናቸው)። አንድ ኦፕሬተር በግልጽ ሁኔታ ማጽዳት አለበት፦

1. **ግንኙነቱን እንደገና ይፈትሹ** — የዳሽቦርዱ **Test** እርምጃ
   (`POST /api/providers/{id}/test`)፤ የተሳካ ሙከራ `testStatus`ን ወደ
   `active` ይመልሳል እና የስህት መስኮችን ያጸዳል።
2. **እንደገና ማረጋገጫ ያድርጉ / የመግቢያ ማስረጃዎችን ያርትዑ** — ለOAuth አቅራቢዎች የመግቢያ
   / የማደሻ ፍሰቱን እንደገና ያስኪዱ፤ የአቅራቢ መፍጠሪያ/ማስመጫ መንገዶች `isActive = true` ያደርጋሉ።
3. **ግንኙነቱን እንደገና ያንቁ** — በራስ-ሰር ማሰናከል `isActive = false`
   ካደረገው (`all` ወሰን፣ ወይም ለOAuth/cookie/session ግንኙነት `subscription`)፣
   መለያውን ካስተካከሉ በኋላ እንደገና ያብሩት።

የተለየ "clear ban flag" አዝራር የለም — መልሶ ማግኘት ማለት እንደገና መፈተሽ፣ እንደገና ማረጋገጥ ወይም እንደገና ማንቃት ነው፣ ይህም በ
[RESILIENCE_GUIDE](../architecture/RESILIENCE_GUIDE.md) ውስጥ ካለው አጠቃላይ የመጨረሻ ሁኔታ ደንብ ጋር ይጣጣማል።

## የሙከራ ጥያቄ ማግለል (የሞዴል test-all)

በ`runAsProbe` ውስጥ የሚከናወን **ከሙከራ ጥያቄ የመነጨ ውድቀት** (የሞዴል test-all / health-check መላኪያዎች) ግንኙነትን ከስብስቡ ፈጽሞ አያስወግድም (#9817)፦ **እንዲታይ ይመዘገባል** (`last_error`፣ `last_error_type`፣ `error_code`፣
`last_error_at`)፣ ነገር ግን **ሁሉንም** የማስተላለፊያ ለውጦች — ማቀዝቀዣዎችን፣ የመጨረሻ ሁኔታን (`banned` / `deactivated` / `credits_exhausted`)፣ በእያንዳንዱ ሞዴል የሚደረጉ መቆለፊያዎችን፣ የአቅራቢውን circuit breaker፣ የ5-ደቂቃ quota cache፣ የOAuth token ማደሻንና በራስ-ሰር ማሰናከልን — ይዘላል። የሚያሰናክለው እውነተኛ የጥያቄ መንገድ ውድቀት ብቻ ነው። የተመዘገበው ስህተት ምልክት የተደረገበት መለያ ትራፊክ ማገልገሉን ሳያቋርጥ በዳሽቦርዱ ውስጥ እንዲታይ ያደርገዋል።

ብቸኛው የውሳኔ ነጥብ `shouldIsolateProbeFailures()`
(`src/shared/utils/probeOrigin.ts`) ነው፣ እና ከሙከራ ጥያቄ የመነጨ ውድቀት የማስተላለፊያ ሁኔታን ሊቀይር በሚችልባቸው **ሁሉም** ቦታዎች ይመከራል፦

- `markAccountUnavailable` (`auth.ts`) — መመዝገብ ብቻ (`lastError` ጥሬ ጽሑፍ፣
  `lastErrorType`፣ `errorCode`፣ `lastErrorAt`፤ ሆን ተብሎ `backoffLevel` **አይኖርም**፣ ምክንያቱም ይህ በምርጫ ጊዜ የሚከናወነውን ራስ-ሰር መቀነስ ቀስቅሶ መዝገቡን ያጠፋው ነበር)
- `maybeAutoDisableBannedAccount` — በራስ-ሰር ማሰናከል የለም
- `chatCore` — FORBIDDEN፣ ACCOUNT_DEACTIVATED፣ QUOTA_EXHAUSTED (መመዝገብ ብቻ፣
  የመጨረሻ `credits_exhausted` የለም)፣ GEO_BLOCKED (የ24 ሰዓት ማግለል የለም)፣
  MODEL_NOT_FOUND (`lockModel` የለም)፣ የcodex 429 የመለያ-ማዞሪያ failover
  (`markCodexScopeRateLimited` የለም፣ የተቀመጠ `rate_limited_until` የለም፣
  session-affinity ማጽዳት የለም)፣ `persistCodexQuotaState` (የquota-state መጻፍ የለም፣
  cache ማሰናከል የለም)፣ `recordKeyHealthStatus` (የkey-health rotator
  አይነካም)
- OAuth refresh — በexecutor base ውስጥ ያለው ቅድመ-እርምጃ ማደሻ
  (`base.ts` `execute()`፣ refresh-token rotation አይጠቀምም) እና በ`chatCore` ውስጥ ያለው
  ምላሽ-ሰጪ 401/403 መንገድ (`expired` ማሰናከል የለም)
- `chat.ts` — የአቅራቢ circuit breaker እና የ5-ደቂቃ quota cache
  (`markAccountExhaustedFrom429`) ፈጽሞ አይዳከሙም

የተመዘገበው ስህተት ምልክት የተደረገበት መለያ ትራፊክ ማገልገሉን ሳያቋርጥ በዳሽቦርዱ ውስጥ እንዲታይ ያደርገዋል። ማስታወሻ፦ የሙከራ መዝገቡ ከእውነተኛው መንገድ `slice(0,100)` ማሳጠር በተለየ **ጥሬውን**
(ያልተቆረጠውን) የስህተት ጽሑፍ ያከማቻል።

test-allን እንደ የጥገና መሳሪያ የሚጠቀሙ ኦፕሬተሮች ከሚከተሉት በአንዱ ታሪካዊውን ባህሪ (ሙከራው እንደ እውነተኛ ማመንጨት ይቆጠራል) መመለስ ይችላሉ፦

- የ`probeCanDisable` ቅንብር (`POST /api/settings` ከ
  `{"probeCanDisable": true}` ጋር፣ ወይም ቀጥተኛ የ`key_value` DB ማርትዕ)፣ ወይም
- የባህሪ ጠቋሚ **`PROBE_CAN_DISABLE=true`** (የenv ወይም DB መሻሪያ፤ ከቅንብሩ ቅድሚያ ያገኛል)።

የደህንነት መውደቂያ፦ የጠቋሚው ወይም የቅንብሮቹ ፍለጋ ስህተት ካስነሳ፣ ማግለሉ እንደበራ ይቆያል።
