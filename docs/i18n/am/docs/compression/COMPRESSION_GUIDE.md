> ብቁ በሆነ ኮንቴክስት ላይ 15-95% በራስ-ሰር ይቆጥቡ። ለፈጣን አጠቃላይ እይታ፣ የ[README የማመቅ ክፍልን](../README.md#%EF%B8%8F-prompt-compression--save-15-95-eligible-tokens-automatically) ይመልከቱ።

## አጠቃላይ እይታ

OmniRoute ጥያቄዎች ወደ upstream አቅራቢዎች ከመድረሳቸው በፊት **አስቀድሞ** የሚሠራ ሞዱላር የፕሮምፕት ማመቂያ pipeline ይተገብራል። ይህም የቶከን ቁጠባዎ በማይታይ ሁኔታ እንዲከናወን ያደርጋል — በየዕለት የሥራ ሂደትዎ ላይ ምንም ለውጥ አያስፈልግም።

```
የደንበኛ ጥያቄ
  → የማመቂያ ስልት መራጭ
    → Combo ማሻሻያ አለ? → የcombo ቅንብሩን ተጠቀም
    → የራስ-ሰር ማስጀመሪያ ገደብ ደርሷል? → ራስ-ሰር ሁነታን ተጠቀም
    → ነባሪ ሁነታ? → አጠቃላይ ቅንብሩን ተጠቀም
    → ጠፍቷል? → ማመቅን ዝለል
  → የተመረጠው የማመቂያ ሁነታ
    → ጠፍቷል፦ ምንም ማመቅ የለም
    → Lite፦ አስተማማኝ የክፍተት/ቅርጸት ማጽዳት (~15%)
    → Standard፦ የቀላል-ንግግር ትርፍ ቃላትን ማስወገድ (~30%)
    → Aggressive፦ የታሪክ ማርጀት + ማጠቃለል (~50%)
    → Ultra፦ ሂዩሪስቲክ መመንጠር + የኮድ ብሎክ ማቅጠን (~75%)
    → RTK፦ ትዕዛዝን የሚገነዘብ የተርሚናል/መሣሪያ-ውጤት ማጣሪያ (60-90% upstream ክልል)
    → Stacked፦ በቅደም ተከተል የሚሠራ ባለብዙ-engine pipeline፣ ብዙውን ጊዜ RTK ከዚያ Caveman (78-95% ብቁ ክልል)
  → የታመቀ ጥያቄ → አቅራቢ
```

## የማመቂያ ሁነታዎች

### Off

ምንም ማመቅ አይተገበርም። ሁሉም መልዕክቶች ሳይለወጡ ያልፋሉ።

### Lite ሁነታ (~15% ቁጠባ፣ <1ms መዘግየት)

በጣም አስተማማኙ ሁነታ — ምንም የፍቺ ለውጥ የለም፣ የቅርጸት ማጽዳት ብቻ፦

| ቴክኒክ                     | መግለጫ                                       |
| ------------------------ | ------------------------------------------ |
| `collapseWhitespace`     | ተከታታይ ባዶ መስመሮችንና በመስመር መጨረሻ ያሉ ክፍተቶችን አዋህድ |
| `dedupSystemPrompt`      | የተባዙ የsystem መልዕክቶችን አስወግድ                 |
| `compressToolResults`    | ዝርዝር የtool/function ውጤቶችን አምቅ              |
| `removeRedundantContent` | የተደጋገሙ መመሪያዎችን አስወግድ                       |
| `replaceImageUrls`       | የbase64 ምስል ውሂብ URIዎችን አሳጥር                |

**ለሚከተለው ይመከራል፦** ሁልጊዜ በርቶ የሚቆይ አጠቃቀም፣ ደህንነት-ወሳኝ የሥራ ሂደቶች።

### Standard ሁነታ (~30% ቁጠባ)

በ[Caveman](https://github.com/JuliusBrussee/caveman) የተነሳሳ — ትርጉሙን በመጠበቅ ትርፍ ቃላትንና ረዥም አገላለጾችን ያስወግዳል፦

- ትርፍ ቃላትን ("እባክዎ", "እኔ እንደማስበው", "በመሠረቱ", "በእርግጥ") ያስወግዳል
- ረዥም ሐረጎችን ያሳጥራል ("ለማድረግ ሲባል" → "ለማድረግ"፣ "በዚህ ምክንያት" → "ምክንያቱም")
- ጨዋነት የተሞላባቸውን አገላለጾች ያስወግዳል ("ቢያደርጉ ይቸግርዎታል...", "ከቻሉ...")
- ለኮዲንግ ፕሮምፕቶች የተስተካከሉ ከ30 በላይ የregex ደንቦች

**ለሚከተለው ይመከራል፦** ዕለታዊ የኮዲንግ የሥራ ሂደቶች፣ ወጪን የሚያገናዝቡ ቡድኖች።

### Aggressive ሁነታ (~50% ቁጠባ)

ለረጅም ክፍለ ጊዜዎች ብልህ የታሪክ አስተዳደር፦

- **የመልዕክት ማርጀት** — የቆዩ መልዕክቶች ቀስ በቀስ የበለጠ ይታመቃሉ
- **የመሣሪያ ውጤት ማጠቃለያ** — ረዥም የመሣሪያ ውጤቶች በማጠቃለያዎች ይተካሉ
- **የመዋቅራዊ ወጥነት ጥበቃዎች** — የ`tool_use` + `tool_result` ጥንዶች ወጥነታቸውን እንዲጠብቁ ያረጋግጣል
- **የኮንቴክስት መስኮት ግንዛቤ** — የእያንዳንዱን model የቶከን ገደቦች ያከብራል

**ለሚከተለው ይመከራል፦** የተራዘሙ የስህተት ማረም ክፍለ ጊዜዎች፣ ትላልቅ የኮድ ማከማቻዎች።

### Ultra ሁነታ (~75% ቁጠባ)

ቶከን ወሳኝ ለሆነባቸው ሁኔታዎች ከፍተኛ ማመቅ፦

- **ሂዩሪስቲክ መመንጠር** — ከአግባብነት ገደቡ በታች ያሉ መልዕክቶችን ያስወግዳል
- **የኮድ ብሎክ ማቅጠን** — ተደጋጋሚ የኮድ ምሳሌዎችን ያመቃል
- **የሁለትዮሽ ፍለጋ መቁረጥ** — ለኮንቴክስት መስኮቱ ምርጥ የመቁረጫ ነጥብን ያገኛል
- ሁሉም የAggressive ሁነታ ባህሪያት ተካትተዋል

**ለሚከተለው ይመከራል፦** የኮንቴክስት ገደቦችን በተደጋጋሚ ሲደርሱ።

### RTK ሁነታ (60-90% upstream ክልል)

RTK ሁነታ በኮዲንግ-agent ክፍለ ጊዜዎች ውስጥ ለሚታዩ ዝርዝር የመሣሪያ ውጤቶች የተመቻቸ ነው፦

- እንደ `git status`፣ `git diff`፣ `git log`፣ የፈተና አስኪያጆች፣
  TypeScript/Vite/Webpack ግንባታዎች፣ ESLint/Biome/Prettier፣ npm ኦዲት/ጭነቶች፣ Docker ሎጎች፣ የinfra
  ውጤት እና አጠቃላይ የshell ውጤት ያሉ የትዕዛዝ/ውጤት ምድቦችን ይለያል
- ከ`open-sse/services/compression/engines/rtk/filters/` የJSON ማጣሪያ ጥቅሎችን ይተገብራል
- ከፕሮጀክት ወይም ከአጠቃላይ `filters.toml` ፋይሎች የRTK TOML schema v1 ማጣሪያዎችን ያስመጣል፤ የinline-test
  ማረጋገጫ እና ለፕሮጀክት ፋይሎች በእምነት ላይ የተመሠረተ መቆጣጠሪያ አለው
- 49 አብሮገነብ ማጣሪያዎችን ከinline የማረጋገጫ ናሙናዎች ጋር ይዟል
- የANSI መቆጣጠሪያ ቅደም ተከተሎችን፣ የሂደት አሞሌዎችን፣ የተደጋገሙ መስመሮችን እና እርምጃ የማይወሰድባቸውን ድምፆች ያስወግዳል
- ውድቀቶችን፣ ስህተቶችን፣ ማስጠንቀቂያዎችን፣ የተለወጡ ፋይሎችን፣ ማጠቃለያዎችን እና የረዥም ውጤትን የመጨረሻ ክፍል ይጠብቃል
- በእምነት ላይ የተመሠረቱ የፕሮጀክት ማጣሪያዎችን፣ አጠቃላይ ማጣሪያዎችን እና አማራጭ የተደበቀ ጥሬ-ውጤት መልሶ ማግኘትን ይደግፋል

## የላይኛው ምንጭ ቁጠባ ስሌት

| ------- | --------------------------------------------------------------------------------------------- |

```txt
RTK -> Caveman
```

ጥምር ቁጠባው በማባዛት የሚሰላ እንጂ በመደመር አይደለም፦

ያ `78-95%` ቁጥር RTK እና Caveman ሁለቱም ተመሳሳዩን የግቤት/ዐውድ ውሂብ መቀነስ ሲችሉ ተፈጻሚ ይሆናል።
የCaveman የምላሽ ውጤት ሁነታ የተለየ ነው፦ ሲነቃ የCavemanን የራሱ የውጤት ቁጠባዎች (`65%`

### "ብቁ" ማለት በትክክል ምን ማለት ነው

የ15-95% ዋና ክልል ትክክለኛ ነው፣ ነገር ግን ተፈጻሚ የሚሆነው **ለተደጋገመ ወይም ከመጠን በላይ ዝርዝር** ይዘት ብቻ ነው — ተደጋጋሚ
የስህተት መስመሮች፣ ተመሳሳዩን ማስጠንቀቂያ ደጋግሞ የሚያወጣ የግንባታ ምዝግብ፣ ከመጠን ያለፈ `grep`/የፋይል-ንባብ ውጤት። ይህ
እያንዳንዱ ጥያቄ ያን ያህል ቁጠባ ያስገኛል ማለት **አይደለም**።

በተግባር ተረጋግጧል (`tests/unit/compression/stacked-compression-tool-result-savings.test.ts`)፦ 300 ተመሳሳይ
የስህተት መስመሮችን የያዘ የAnthropic-ቅርጽ `tool_result` ብሎክ ላይ የተካሄደ `stacked` (RTK + Caveman) ሂደት
**95.93% የቶከን ቁጠባ / 96.26% የቁምፊ ቁጠባ** አስገኝቷል — ይህም በታወጀው
ክልል ውስጥ በትክክል ይገኛል። ሆኖም ተመሳሳዩ ሂደት በመደበኛ፣ ያልተደጋገመ የመሣሪያ ውጤት (ንጹህ የ`grep` ተዛማጅ ዝርዝር፣
አጭር የፋይል ንባብ፣ መደበኛ የውይይት ጽሑፍ) ላይ ሲካሄድ **ወደ ዜሮ የቀረበ ቁጠባ** በትክክል ያስገኛል፤ ምክንያቱም
የሚወገድ ተደጋጋሚ ነገር የለም፣ እና `validateCompression()` (`validation.ts`) የኮድ ብሎኮችን፣ URLs፣ ርዕሶችን፣ ስሪቶችን ወይም ሁሉም-በአቢይ-ፊደል የተጻፉ ቋሚ ለዪዎችን የሚያስወግድ ወይም የሚቀይር

ይህ የሚጠበቅ እና ደህንነቱ የተጠበቀ ባህሪ ነው፣ ሳንካ አይደለም፦ በአብዛኛው ንጹህ ፋይሎችን የሚያነብ/በ`grep` የሚፈልግ የኮድ አጻጻፍ ክፍለ ጊዜ

## ውቅር

### ዳሽቦርድ

ወደ `Dashboard → Context & Cache` ይሂዱ፦

- **Caveman** — የሁነታ ምርጫ፣ የቋንቋ ጥቅሎች፣ ቅድመ-ዕይታ እና ዓለም አቀፍ ነባሪዎች
- **RTK** — የትዕዛዝ ማጣሪያ ቅድመ-ዕይታ፣ የRTK ደህንነት ቅንብሮች እና የማጣሪያ ካታሎግ
- **Compression Combos** — ለማዘዋወሪያ ጥምረቶች የተመደቡ ስም ያላቸው የሞተር ቧንቧ-መስመሮች
- **Auto-Trigger Threshold** — የቶከን ብዛት ከገደቡ ሲያልፍ መጭመቅን በራስ-ሰር ያስጀምራል

### በእያንዳንዱ ጥምረት ላይ መሻር

በ`Dashboard → Context & Cache → Compression Combos` ውስጥ ለአንድ የማዘዋወሪያ ጥምረት የመጭመቂያ ጥምረት ይመድቡ፦

```txt
Combo: "free-tier-fallback"
  Compression Combo: "coding-agent-stack"
  Pipeline: RTK -> Caveman
  Targets:
    1. if/kimi-k2.7-code
    2. if/qwen3.8-max-preview
```

ይህ፣ በሚከፈልባቸው ምዝገባዎች ላይ lite ሁነታን እንደተጠበቀ በማቆየት፣ በነጻ/ኮዲንግ አቅራቢዎች ላይ የተደራረበ መጭመቅን እንዲጠቀሙ ያስችልዎታል።

ይህ የ"Per-Combo Override" ምደባ ከ**የማዘዋወሪያ-ጥምረት መጭመቂያ ሁነታ** መሻሪያ (Default/Off/Lite/Standard/Aggressive/Ultra) የተለየ መቆጣጠሪያ ነው — ያ መሻሪያ ስም ያለውን የመጭመቂያ-ጥምረት ቧንቧ-መስመር አይመርጥም፤ `resolveCompressionPlan` የሚያጣቅሰውን `compressionMode` መስክ ብቻ ያዘጋጃል። ይህን በጥምረቱ ካርድ (`Dashboard → Combos`) ላይ ወይም፣ ከ#6760 ጀምሮ፣ በ`Dashboard → Context & Cache → Compression Combos` ውስጥ ባለው "Assign to routing" ዝርዝር ላይ፣ ከላይ ከተመዘገበው የቧንቧ-መስመር ምደባ አመልካች ሳጥን አጠገብ፣ ለእያንዳንዱ የማዘዋወሪያ ጥምረት ማዘጋጀት ይቻላል። ሁለቱም በይነገጾች በተመሳሳዩ `PUT /api/combos/{id}` የመጨረሻ ነጥብ በኩል ቅንብሮቹን ያስቀምጣሉ።

### በእያንዳንዱ ጥያቄ ላይ መሻር

ለአንድ ጥያቄ ብቻ የመጭመቂያ ዕቅዱን ለመሻር `x-omniroute-compression` የጥያቄ ራስጌን ይላኩ። ከሁሉም ከፍተኛው ቅድሚያ አለው — የማዘዋወሪያ-ጥምረት መሻሪያን፣ ንቁውን መገለጫ፣ ራስ-ሰር ማስጀመሪያን እና የፓነሉን Default ይበልጣል። ያልታወቁ እሴቶች ችላ ይባላሉ (ጥያቄው ፈጽሞ ውድቅ አይደረግም)፣ እና ዓለም አቀፉ ዋና ማብሪያ አሁንም ሁሉንም ነገር ይቆጣጠራል፦ መጭመቅ በዓለም አቀፍ ደረጃ ጠፍቶ ሲሆን፣ ራስጌው ሊያበራው አይችልም። እሴቶች፦

| እሴት           | ውጤት                                                                       |
| ------------- | ------------------------------------------------------------------------- |
| `off`         | ለዚህ ጥያቄ ምንም መጭመቅ አይደረግም።                                                  |
| `default`     | ከፓነሉ የሚመነጨው Default መገለጫ (ንቁውን መገለጫ ችላ ይላል)። መረጃ የሚያስጥሉ ሞተሮች እንደጠፉ ይቀራሉ።  |
| `safe`        | ራስጌውን ካለመላክ ጋር ተመሳሳይ፦ የተባዙ ነገሮችን ማስወገድ እና ነጭ ቦታን ማጠፍ ብቻ።                  |
| `allow-lossy` | ማጠቃለያዎችን፣ የተዛማጅነት ማጣሪያዎችን እና የቅጥ ዳግም ጽሑፎችን ጨምሮ የዚህን ጥያቄ ኦፕሬተር ዕቅድ ያቆያል።   |
| `engine:<id>` | ሲነቃ አንድ ሞተር፣ ለምሳሌ `engine:rtk`። ይህ ለዚያ ሞተር በእያንዳንዱ ጥያቄ የሚደረግ መርጦ መግባት ነው። |
| `<combo>`     | በመጀመሪያ በስም (ለፊደል መጠን ልዩነት ደንታ ሳይሰጥ)፣ ከዚያም በid የሚዛመድ ስም ያለው ጥምረት።          |

`allow-lossy`፣ `engine:<id>` ወይም ስም ያለው ጥምረት ከሌለ፣ መረጃ የሚያስጥሉ ሞተሮች አይተገበሩም። መጭመቅ በርቶ ሲሆን ጥያቄው አሁንም የክፍለ-ጊዜ ብዜት ማስወገድን እና የነጭ ቦታ ማጠፍን ያገኛል።

የተተገበረው ዕቅድ በ`X-OmniRoute-Compression: <mode>; source=<source>` የምላሽ ራስጌ ውስጥ ተመልሶ ይታያል፤ በዚህም `<source>` ከ`request-header`፣ `routing-override`፣ `active-profile`፣ `auto-trigger`፣ `default` ወይም `off` አንዱ ነው።

### መሸጎጫን ከግምት ያስገባ ማመቅ

አንዳንድ አቅራቢዎች (ለምሳሌ Anthropic ከጥያቄ መሸጎጫ ጋር) **የጥያቄ መሸጎጫን**
ይደግፋሉ፤ ይህም ወጪንና መዘግየትን ለመቀነስ የጥያቄውን ክፍሎች እንዲሸጉጡ ያስችላቸዋል።
መሸጎጥ ሲነቃ፣ ኃይለኛ ማመቅ የተሸጎጡትን ቶከኖች በመቀየር መሸጎጫውን ዋጋ ቢስ
ስለሚያደርገው አፈጻጸምን በተጨባጭ **ሊጎዳ** ይችላል።

የ`cachingAware.ts` ሞጁል **የመሸጎጫ ዐውዱን በመለየት** እና
በዚሁ መሠረት **የማመቅ ስልቱን በማስተካከል** ይህን ይፈታል።

#### እንዴት እንደሚሰራ

1. **የመሸጎጫ ዐውድን መለየት** — የጥያቄውን አካል ለ`cache_control` ምልክቶች ይፈትሻል
2. **መሸጎጥን የሚደግፉ አቅራቢዎችን መለየት** — የታለመው አቅራቢ መሸጎጥን ይደግፍ እንደሆነ ያረጋግጣል
3. **ስልቱን ማስተካከል** — መሸጎጥን ለሚደግፉ አቅራቢዎች `aggressive`/`ultra`ን ወደ `standard` ዝቅ ያደርጋል
4. **የስርዓት ጥያቄን መዝለል** — የስርዓት ጥያቄዎች ብዙውን ጊዜ ይሸጎጣሉ፣ ስለዚህ አይጨመቁ
5. **ተወስነው የሚደጋገሙ ለውጦችን መጠቀም** — ወጥ የሆነ ውጤት የሚያመነጩ ለውጦችን ብቻ ይጠቀሙ

#### የኮድ ምሳሌ

```ts

  detectCachingContext,

const body = {
  model: "anthropic/claude-sonnet-4.5",
  messages: [{ role: "user", content: "Hello" }],
  cache_control: { type: "ephemeral" }, // ← የመሸጎጫ ምልክት
};

const ctx = detectCachingContext(body, { provider: "anthropic" });
// → { hasCacheControl: true, provider: "anthropic", isCachingProvider: true }

const strategy = getCacheAwareStrategy("aggressive", ctx);
// → { strategy: "standard", skipSystemPrompt: true, deterministicOnly: true }
```

#### መቼ እንደሚጠቀሙበት

መሸጎጫን ከግምት ያስገባ ማመቅ **ሁልጊዜ ንቁ ነው** — ምንም ውቅር አያስፈልግም። የሚሰራው
የሚከተሉት ሲሟሉ ብቻ ነው፦

- ጥያቄው `cache_control` ምልክቶች ሲኖሩት
- የታለመው አቅራቢ የጥያቄ መሸጎጥን ሲደግፍ (Anthropic፣ OpenAI፣ ወዘተ.)

### ተራማጅ ማርጀት

ረጅም ውይይቶች ብዙ የመልዕክት ተራዎችን ያከማቻሉ፣ ነገር ግን የቆዩ ተራዎች ጠቀሜታቸው
እየቀነሰ ይሄዳል። የ`progressiveAging.ts` ሞጁል **መልዕክቶችን በተራ ርቀት መሠረት ያቃልላል**፦

- **የቅርብ ተራዎች (0-3)**: ምንም ሳይቀየሩ ይቀመጣሉ (ሙሉ ዝርዝር)
- **መካከለኛ ተራዎች (4-8)**: ቀላል ማመቅ (ነጭ ቦታና ቅርጸትን ማጽዳት)
- **የቆዩ ተራዎች (9+)**: የዋሻ ሰው ማመቅ (አላስፈላጊ ቃላትን ማስወገድ፣ ማጠቃለል)
- **በጣም የቆዩ ተራዎች (20+)**: በከፍተኛ ደረጃ ይጠቃለላሉ ወይም ይወገዳሉ

#### የኮድ ምሳሌ

```ts
import { applyAging } from "@omniroute/open-sse/services/compression/progressiveAging";

const messages = [
  { role: "system", content: "You are a helpful assistant" },
  { role: "user", content: "What is 2+2?" },
  { role: "assistant", content: "4" },
  // ... 50 ተጨማሪ ተራዎች ...
];

const { messages: aged, saved } = applyAging(messages, {
  verbatim: 3, // የመጀመሪያዎቹ 3 ተራዎች፦ ምንም ሳይቀየሩ
  light: 8, // ከ4-8 ያሉ ተራዎች፦ ቀላል ማመቅ
  moderate: 20, // ከ9-20 ያሉ ተራዎች፦ የዋሻ ሰው ማመቅ
  // ከ21+ ያሉ ተራዎች፦ ከፍተኛ ማጠቃለል
});

// saved = የተቆጠቡ ቶከኖች ብዛት
```

#### መቼ እንደሚጠቀሙበት

ተራማጅ ማርጀት ለ`aggressive` እና `ultra` ሁነታዎች **ሁልጊዜ ንቁ ነው**። በተለይ
ለሚከተሉት ውጤታማ ነው፦

- ለረጅም ጊዜ የሚቀጥሉ የኮድ ክፍለ ጊዜዎች
- ለብዙ ቀናት የሚቆዩ ውይይቶች
- ብዙ የመሣሪያ ጥሪዎች ያሏቸው ወኪላዊ የሥራ ፍሰቶች

### የዋሻ ሰው ውጤት ሁነታ

የ`outputMode.ts` ሞጁል ሞዴሉ ራሱ የተጨመቀና አጭር ውጤትን (“የዋሻ ሰው” ዘይቤ)
እንዲያመነጭ **የስርዓት ጥያቄ መመሪያዎችን** ያስገባል።

#### እንዴት እንደሚሰራ

ግብዓቱን ከመጨመቅ ይልቅ፣ ይህ ሁነታ እንደሚከተለው ያለ የስርዓት ጥያቄ ይጨምራል፦

> “በትንሹ ቃላት መልስ። የጨዋነት መግለጫዎችን ዝለል። አጫጭር ዓረፍተ ነገሮችን ተጠቀም።”

ይህ በተለይ ለሚከተሉት በጥሩ ሁኔታ ይሰራል፦

- ኮድ ማመንጨት (ይበልጥ አጭር ውጤት = ያነሱ ቶከኖች)
- ፈጣን ጥያቄና መልስ (ዝርዝር ማብራሪያዎች አያስፈልጉም)
- ባች ማስኬድ (የማስኬጃ አቅምን ከፍ ማድረግ)

#### መቼ እንደሚጠቀሙበት

የዋሻ ሰው ውጤት ሁነታ **በምርጫ የሚነቃ ነው** — በጥምር ውቅሩ በኩል ያዘጋጁት፦

```json
{
  "strategy": "auto",
  "config": {
    "auto": {
      "outputMode": "caveman"
    }
  }
}
```

ከcatalog ጋር ያዛምዳል (ያልታወቁ ids እና ከlocale ጋር የማይዛመዱ ቅጦች

የወሰን አንቀጹን **አንድ ጊዜ** ያክላል፣ እና ውጤቱን ከአንድ idempotency marker (`[OmniRoute Output Styles]`) በኋላ
በsystem prompt መጀመሪያ ላይ ያስቀምጣል — እንደገና መተግበር ምንም ተጽዕኖ የለውም። የተገኘው የጥያቄ ቋንቋ ትርጉም ሲኖረው፣
ከእንግሊዝኛው ይልቅ አካባቢያዊው መመሪያ ይገባል።

#### እንዴት ማንቃት እንደሚቻል

በdashboard ውስጥ፦ **Context → Settings → Compression** — ለእያንዳንዱ ቅጥ አንድ ረድፍ፣
የማብራት/ማጥፋት toggle እና የደረጃ selector ያለው። በፕሮግራም ሲዋቀር፣ የcompression config ምርጫውን እንዲህ ያከማቻል፦

```json
{
  "outputStyles": [
    { "id": "i-have-adhd", "level": "full" },
    { "id": "less-code", "level": "lite" }
  ]
}
```

የኋላ-ተኳኋኝነት፦ የቀድሞው `outputMode: "caveman"` combo setting አሁንም ይሠራል እና ወደ
`terse-prose` ይዛመዳል፤ በእያንዳንዱ የቀድሞ ቋንቋ ከድሮው injection ጋር byte-identical ነው።

የቋንቋ ምርጫ፦ `languageConfig.enabled` ሲበራ፣ `autoDetect` የቅርብ ጊዜውን
የተጠቃሚ መልዕክት ቋንቋ ይመርጣል (ከinput engines ጋር ተመሳሳይ detector)፤
`autoDetect`ን ማጥፋት `defaultLanguage`ን ያስ固定ታል። ጠፍቶ ከሆነ → እንግሊዝኛ።

የቅጥ × ቋንቋ matrix በ
`tests/unit/compression/output-styles-i18n-matrix.test.ts` ተ固定ቷል፦ አዲስ ቅጥ ቢያንስ የpt-BR ትርጉም
(ወይም በግልጽ የተከታተለ exception) ሳይኖረው ሊለቀቅ አይችልም፣ እና
ነባር ቅጥ አንድ locale በዝምታ ሊያጣ አይችልም። ቅጥ ለማከል
[EXTENDING_COMPRESSION.md](./EXTENDING_COMPRESSION.md#adding-an-output-style)ን ይመልከቱ።

### የTool Result Compression

የ`toolResultCompressor.ts` module ለtool results (function calls፣ agent outputs፣ search results፣ ወዘተ)
**5 ልዩ የcompression strategies** ያቀርባል፦

1. **የSearch result compression** — የተደጋገሙ resultsን ያስወግዳል፣ ከፍተኛዎቹን-N ይይዛል
2. **የFile read compression** — ትልልቅ filesን ያሳጥራል፣ headers/importsን ይጠብቃል
3. **የCode execution compression** — አስፈላጊውን stdout/stderr ብቻ ይይዛል
4. **የDatabase query compression** — rowsን ይገድባል፣ ረጅም metadataን ያስወግዳል
5. **የAPI response compression** — null fieldsን ያስወግዳል፣ arraysን ያጠቃልላል

#### መቼ መጠቀም እንዳለበት

Tool calls በሚኖሩበት ጊዜ tool result compression **ሁልጊዜ በርቷል**።
ምንም configuration አያስፈልግም።

### የተደራረበ Pipeline

የstacked mode **በርካታ enginesን በቅደም ተከተል** ያስኬዳል — ብዙውን ጊዜ መጀመሪያ RTK
(በtool output ላይ 60-90% ቁጠባ)፣ ከዚያ Caveman (በቀሪው ጽሑፍ ላይ ተጨማሪ 30% ቁጠባ)።
ይህ **በአጠቃላይ 78-95% ቁጠባ** ያስገኛል።

#### እንዴት እንደሚሠራ

```
ግብዓት (1000 tokens)
  → RTK (command-aware filter) → 200 tokens
    → Caveman (አላስፈላጊ ቃላትን ማስወገድ) → 140 tokens
  → ውጤት (140 tokens፣ 86% ቁጠባ)
```

#### መቼ መጠቀም እንዳለበት

stacked modeን ለሚከተሉት ይጠቀሙ፦

- Tool-heavy workflows (agentic coding፣ ምርምር)
- ወጪን የሚገነዘብ batch processing
- ከፍተኛውን የtoken ቁጠባ ሲፈልጉ

በcombo በኩል ያዋቅሩ፦

```json
{
  "strategy": "auto",
  "config": {
    "auto": {
      "modePack": "stacked"
    }
  }
}
```

## የኮምፕሬሽን ኮምቦ ማሻሻያዎች

ለተለያዩ የአጠቃቀም ሁኔታዎች ባህሪውን በዝርዝር ለማስተካከል፣ አጠቃላይ የኮምፕሬሽን ሁነታውን **ለእያንዳንዱ ኮምቦ** ማሻሻል ይችላሉ፦

```json
{
  "id": "coding-combo",
  "strategy": "priority",
  "config": {
    "auto": {
      "weights": { "taskFit": 0.5 },
      "modePack": "quality-first"
    }
  },
  "compressionOverride": {
    "mode": "aggressive",
    "stackedPipelines": ["rtk", "caveman"],
    "preserveToolDefinitions": true
  }
}
```

ይህ ለሚከተሉት ጠቃሚ ነው፦

- **የኮዲንግ ኮምቦዎች**፦ ለረጅም ክፍለ ጊዜዎች `aggressive` ሁነታን ይጠቀሙ
- **ፈጣን የጥያቄና መልስ ኮምቦዎች**፦ ለፈጣን ምላሾች `lite` ሁነታን ይጠቀሙ
- **ብዙ መሣሪያዎችን የሚጠቀሙ ኮምቦዎች**፦ ከፍተኛውን ቁጠባ ለማግኘት `stacked` ሁነታን ይጠቀሙ
- **የምርት ኮምቦዎች**፦ ለካሽ አቅራቢዎች `cache-aware` ሁነታን ይጠቀሙ
