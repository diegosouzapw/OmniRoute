የተወከለ **የአውድ አርትዖት** ለClaude ብቻ የተዘጋጀ የአውድ አስተዳደር ባህሪ ነው። የOmniRoute አካባቢያዊ
የማመቅ ሞተሮች (Caveman, RTK, LLMLingua, የተደራረቡ የሂደት ሰንሰለቶች) የጥያቄውን ይዘት
ከፕሮክሲው ከመውጣቱ _በፊት_ እንደገና ከሚጽፉት በተለየ፣ የአውድ አርትዖት **አቅራቢውን**
ጊዜ ያለፈባቸውን የመሣሪያ-አጠቃቀም / የመሣሪያ-ውጤት ብሎኮች ከራሱ ቀጣይነት ካለው የአውድ መስኮት እንዲያጸዳ ይጠይቃል። OmniRoute የሚያክለው
የይዘት መለኪያ (`context_management.edits[]`) ብቻ ነው፤ ትክክለኛውን ማጽዳት Claude በራሱ tokenizer ላይ ያከናውናል።

ይህ በባህሪው የተወከለ ችሎታ ነው፦ ሌሎች አቅራቢዎች መለኪያውን ውድቅ ያደርጋሉ፣ ስለዚህ OmniRoute
ወሰኑን በጥብቅ ለClaude እና Claude-Code-ተኳኋኝ ማስተላለፊያዎች ብቻ ያደርጋል።

ዋና የመረጃ ምንጭ፦ `open-sse/config/contextEditing.ts` (የስትራቴጂ መለያዎች፣ የይዘት ማስገባት፣ የtelemetry
ማውጣት)፣ `open-sse/executors/base.ts` (የማስገባት መግቢያ + የ400 ተተኪ አሠራር)፣ እና
`open-sse/services/compression/types.ts` (የውቅር ቅርጽ + ነባሪ)።

## `clear_tool_uses` ምን ያደርጋል

OmniRoute ወደ ውጭ በሚላከው Anthropic Messages ይዘት ውስጥ አንድ አርትዖት ያስገባል፦

```json
{
  "context_management": {
    "edits": [
      {
        "type": "clear_tool_uses_20250919",
        "trigger": { "type": "input_tokens", "value": 100000 },
        "keep": { "type": "tool_uses", "value": 3 }
      }
    ]
  }
}
```

- `type: "clear_tool_uses_20250919"` — ቀን የተጨመረበት የAnthropic ስትራቴጂ መለያ (`CLEAR_TOOL_USES_STRATEGY`)።
- `trigger.value: 100000` — የጥያቄው input tokens ከዚህ ገደብ ካለፉ በኋላ፣ Claude የቆዩ
  የመሣሪያ-አጠቃቀም/ውጤት ጥንዶችን ማጽዳት ይጀምራል (`CONTEXT_EDITING_DEFAULT_TRIGGER_TOKENS`፣ የAnthropic ነባሪ)።
- `keep.value: 3` — በጣም የቅርብ ጊዜዎቹ N የመሣሪያ-አጠቃቀም/ውጤት ጥንዶች ሳይነኩ ይቀመጣሉ
  (`CONTEXT_EDITING_DEFAULT_KEEP_TOOL_USES`)።

ቤታው `anthropic-beta: context-management-2025-06-27` በሚለው ራስጌ በኩል ይገለጻል፣ ይህንንም
OmniRoute አስቀድሞ በClaude ጥያቄዎች ላይ ይልካል።

ማስገባቱ በ`applyContextEditingToBody()` ይከናወናል እና **idempotent** ነው፦ የ`clear_tool_uses`
አርትዖት አስቀድሞ በይዘቱ ላይ ካለ (በቀደመ ጥሪ የተጨመረ ወይም በደንበኛው የቀረበ)፣ ይዘቱ
እንዳለ ይተዋል። የ`clear_thinking_20251015` አርትዖትም ካለ፣ OmniRoute የ`clear_thinking`
አርትዖቱን ቅደም ተከተሉን ሳያዛባ ወደ ፊት ያደርገዋል፤ ምክንያቱም Anthropic በ`edits[]` ድርድር ውስጥ `clear_thinking` ከ
`clear_tool_uses` እንዲቀድም ይጠይቃል።

## የእያንዳንዱ ጥምረት የማንቃት መቀያየሪያ

የአውድ አርትዖት **በነባሪ ጠፍቷል** እና በምርጫ የሚነቃ ነው። መቀያየሪያው በማመቂያ ውቅሩ ውስጥ የሚያዝ አንድ boolean ነው፦

- የቅንብር ቁልፍ፦ `contextEditing.enabled` (camelCase — `context_editing` / `context-editing` **አይደለም**)።
- ዓይነት፦ `ContextEditingConfig { enabled: boolean }` በ
  `open-sse/services/compression/types.ts` ውስጥ።
- ነባሪ፦ `DEFAULT_CONTEXT_EDITING_CONFIG = { enabled: false }`።
- Zod schema፦ `contextEditingConfigSchema` በ`src/shared/validation/compressionConfigSchemas.ts` ውስጥ።
- ማከማቻ፦ ከቀሩት የማመቂያ ቅንብሮች ጋር በቋሚነት ይቀመጣል (በ
  `src/lib/db/compression.ts` ውስጥ መደበኛ ቅርጽ ይሰጠዋል)።

በዳሽቦርዱ ውስጥ መቀያየሪያው በማመቂያ ማዕከሉ
(`src/app/(dashboard)/dashboard/context/combos/CompressionHub.tsx`) ውስጥ ይገኛል፣ እና
`{ contextEditing: { enabled: … } }`ን በ`saveSettings()` በኩል መልሶ ይጽፋል። በ
compression-settings ኦብጀክት ላይ ስለሚጓዝ፣ ሙሉ በሙሉ ራሱን የቻለ ገጽታ ከመሆን ይልቅ ከእያንዳንዱ ጥምረት የማመቂያ መገለጫ ጋር
አብሮ ይሠራል — ውቅሩ የሚይዘው የማብራት/ማጥፋት ምልክቱን ብቻ ነው፤ ሁሉም ገደቦች (`trigger`,
`keep`) ከላይ የተመዘገቡት ቋሚ እሴቶች ናቸው።

## Claude-ብቻ ማገጃ

መርፌው የሚከናወነው ለእውነተኛ Claude ወይም Claude-Code-ተኳኋኝ ሪሌዎች ብቻ ነው። በ
`open-sse/executors/base.ts` ውስጥ ያለው ማገጃ ይህ ነው፦

```ts
if (
  (this.provider === "claude" || isClaudeCodeCompatible(this.provider)) &&
  contextEditing?.enabled &&
  !contextEditingDisabled
) {
  applyContextEditingToBody(transformedBody, { enabled: true });
}
```

- `this.provider === "claude"` — እውነተኛ Anthropic ቁልፍ/OAuth።
- `isClaudeCodeCompatible(this.provider)` — የአቅራቢ መለያቸው በ
  `anthropic-compatible-cc-` ቅድመ ቅጥያ የሚጀምር ሪሌዎች (Claude Code ተኳኋኝነትን ያስታውቃሉ፤ ስለዚህ betaውን
  የመቀበል ዕድላቸው ከፍተኛ የሆኑ ሪሌዎች ናቸው)። `open-sse/services/provider.ts`ን ይመልከቱ።

ሆን ተብለው **የተገለሉ**፦

- `claude-web` — `context_management`ን ፈጽሞ የማያይ `create_conversation_params` የጥያቄ ቅርጽ ያለው የአሳሽ ሪሌይ።
- አጠቃላይ `anthropic-compatible-*` ሪሌዎች (`-cc-` ቅድመ ቅጥያ የሌላቸው) — የbeta ድጋፋቸው
  እርግጠኛ ያልሆነ የሶስተኛ ወገን መጨረሻ ነጥቦች።

መቀያየሪያው በርቶ ቢሆንም Claude ያልሆኑ አቅራቢዎች `context_management` መለኪያን ፈጽሞ አይቀበሉም።

## የ400 የመጠባበቂያ ሂደት / የሪሌይ ሽፋን

Claude-ተኳኋኝ ሪሌይ betaውን ሊያስታውቅ ይችላል፣ ነገር ግን `context_management` መለኪያን
በHTTP 400 ሊከለክል ይችላል። ጥያቄውን ከማሳካት ይልቅ በለሰለሰ ሁኔታ ወደ አማራጭ ለመውረድ፣ አስፈጻሚው መለኪያውን ያስወግድና ያንኑ URL **አንድ ጊዜ** እንደገና ይሞክራል፦

```ts
if (
  response.status === HTTP_STATUS.BAD_REQUEST &&
  contextEditing?.enabled &&
  !contextEditingDisabled &&
  transformedBody?.context_management !== undefined
) {
  const errText = await response
    .clone()
    .text()
    .catch(() => "");
  if (/context[_-]management|context editing/i.test(errText)) {
    contextEditingDisabled = true;
    delete transformedBody.context_management;
    let retryBody = JSON.stringify(transformedBody);
    if (isClaudeCodeCompatible(this.provider) || this.provider === "claude") {
      retryBody = await signRequestBody(retryBody);
    }
    response = await fetch(url, { ...fetchOptions, body: retryBody });
  }
}
```

ባህሪ፦

1. የአውድ አርትዖት በርቶ ሳለ እና የጥያቄው አካል በእርግጥ
   `context_management`ን ሲይዝ፣ በ`400` ላይ ብቻ ይነሳል።
2. በማይዛመደው መንገድ ላይ ዋናው ምላሽ ሳይነካ እንዲቆይ፣ የ400 አካል በ`clone()` በኩል ይነበባል።
3. የስህተቱ ጽሑፍ ከ`/context[_-]management|context editing/i` ጋር መዛመድ አለበት — ያልተዛመደ 400 (ለምሳሌ
   `max_tokens must be >= 1`) የመጠባበቂያ ሂደቱን **አያስጀምርም**፤ ዋናው ስህተት ይተላለፋል።
4. ሲዛመድ `contextEditingDisabled = true` ያደርጋል (ይህም ለዳግም ሙከራ/የመጠባበቂያ URL አዲስ
   `transformedBody` በኋላ ቢገነባ ዳግም መርፌን ይከላከላል)፣ `context_management`ን ይሰርዛል፣
   ለClaude / Claude-Code-ተኳኋኝ ሪሌዎች አካሉን እንደገና ይፈርማል (`signRequestBody`)፣ እና ያንኑ
   URL አንድ ጊዜ እንደገና ይሞክራል።

እውነተኛ Claude betaውን በ`ANTHROPIC_BETA_BASE` ውስጥ ይይዛል፣ እና ይህን የመጠባበቂያ መንገድ አይጠቀምም።

## `applied_edits` ቴሌሜትሪ

ከClaude ምላሽ በኋላ፣ OmniRoute አቅራቢው በእርግጥ ምን ያህል አውድ እንዳጸዳ ይመዘግባል። ይህ
**በዥረት አይተላለፍም** — ከዥረት-አልባው የምላሽ አካል በተቻለ መጠን ይወጣል፣ እና
ምላሹን ፈጽሞ አይነካም (የቴሌሜትሪ ውድቀቶች ችላ ይባላሉ)።

- ማውጣት፦ `extractContextEditingTelemetry(responseBody)` በ`open-sse/config/contextEditing.ts` ውስጥ።
  የምላሽ ቅርጹን በጥንቃቄ ለመያዝ `applied_edits`ን በሦስት ቦታዎች ይፈትሻል፦
  - `context_management.applied_edits`
  - `usage.context_management.applied_edits`
  - `usage.applied_edits`
- ከእያንዳንዱ ግቤት የሚነበቡ የአርትዖት መስኮች፦ `cleared_input_tokens` እና `cleared_tool_uses`
  (snake_case፣ የAnthropic ተወላጅ)፣ ከ`clearedInputTokens` / `clearedToolUses` camelCase አማራጮች ጋር።
- ምንም የ`applied_edits` ድርድር ካልተገኘ ወይም በእርግጥ ምንም ካልተጸዳ `null`ን ይመልሳል።

የደረሰኙ ቅርጽ `ContextEditingTelemetry { editCount, clearedInputTokens, clearedToolUses }` ነው።
ምዝገባው በ`open-sse/handlers/chatCore.ts` ውስጥ (ለ`provider === "claude"` ብቻ ተገድቦ) በ
`recordContextEditingTelemetry()` (`src/lib/db/compressionAnalytics.ts`) በኩል ይከናወናል፤ ይህም በሚከተለው ሁኔታ መለያ የተሰጠውን የመጭመቂያ
ትንታኔ ረድፍ ይጽፋል፦

- `mode: "context-editing"`
- `engine: "context-editing"`
- `tokens_saved` / `original_tokens` = የጸዳው የግቤት-ቶከን ብዛት
- `request_id` በ`::context-editing` የተጨረሰ

ስለዚህ ውክልና የተሰጠው ማጽዳት ከአካባቢያዊ ሞተሮች ጋር በመጭመቂያ ትንታኔ ውስጥ፣ በ
`context-editing` የሞተር መለያ ስር ይታያል፣ እና ከRTK/Caveman/LLMLingua ቁጠባዎች ሊለይ ይችላል።
