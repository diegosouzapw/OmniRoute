OmniRoute መጭመቅ በሞተር ውሎች ዙሪያ የተገነባ ነው። አንድ ሁነታ አንድን ሞተር በቀጥታ
(`caveman` ወይም `rtk`) ወይም ብዙ ሞተሮችን በቅደም ተከተል የሚያስኬድ ቆራጥ የተደራረበ የማስኬጃ መስመር ሊያስኬድ ይችላል።

## ሁነታዎች

| ሁነታ          | የሞተር መንገድ                        | የታሰበ ግብዓት                              |
| ------------ | -------------------------------- | -------------------------------------- |
| `off`        | የለም                              | የጥያቄውን ትክክለኛ ቅርጽ መጠበቅ                  |
| `lite`       | Caveman lite ረዳቶች                | ዝቅተኛ ስጋት ያለው ሁልጊዜ ንቁ ማጽዳት              |
| `standard`   | Caveman                          | በተፈጥሯዊ ቋንቋ የተጻፈ ጥያቄን ማጠቃለል             |
| `aggressive` | Caveman + የታሪክ/መሣሪያ ማጠቃለያዎች      | ረጅም የውይይት ክፍለ ጊዜዎች                     |
| `ultra`      | Caveman + የመከርከሚያ ረዳቶች           | ከአውድ ገደብ ማገገም                          |
| `rtk`        | RTK                              | የተርሚናል፣ shell፣ build፣ test እና git ውጤት  |
| `omniglyph`  | OmniGlyph                        | በቤተኛው የአቅራቢ ግንኙነት ላይ አውድን እንደ ምስል መጠቀም |
| `stacked`    | የማስኬጃ መስመር፣ ነባሩ `rtk -> caveman` | የተቀላቀሉ የመሣሪያ ምዝግቦች እና ስድ ጽሑፍ፣ ከፍተኛ ቁጠባ |

### OmniGlyph የመጭመቂያ መገለጫዎች

የ`omniglyph` ሞተር (ጥቅል `omniglyph`፣ 1.4.0+) በመጭመቂያ ቅንብሮች ውስጥ
በ`omniglyph.profile` አማካይነት በአጠቃላይ፣ ወይም በተደራረበው የማስኬጃ መስመር የደረጃ ውቅር አማካይነት
ለእያንዳንዱ ደረጃ የሚዘጋጅ በስም የተሰየመ የፍቺ መገለጫ ይቀበላል፦

| መገለጫ          | ወሰን                                                                        |
| ------------- | -------------------------------------------------------------------------- |
| `aggressive`  | ነባሪ። የታተሙት ደረሰኞች የለኩት መመሪያ — የስርዓት፣ የመሣሪያ ሰነዶች እና ጥቅጥቅ ያለ ታሪክ ምስሎች         |
| `balanced`    | ንቁ ሁኔታን በቤተኛ ቅርጹ ያቆያል፣ የመጨረሻዎቹን 8 ዙሮች ይጠብቃል፣ የቆየ የተዘጋ ታሪክን ይሰብስባል          |
| `coding-safe` | ሥልጣንን፣ የመሣሪያ ንድፎችን እና ንቁ የመሣሪያ ውጤትን በቤተኛ ቅርጻቸው ያቆያል፣ የመጨረሻዎቹን 12 ዙሮች ይጠብቃል |
| `passthrough` | ሳይለውጥ ያስተላልፋል፤ ሞተሩ ይዘለላል                                                   |

መገለጫው **ጣሪያ እንጂ ወለል አይደለም**፦ በጥቅሉ ውስጥ ያለው `mergeCompressionProfileOptions`
የጠሪው ሽረዛ መገለጫው የዘጋውን መረጃ-አጥፊ መስመር እንደገና እንዲከፍት አይፈቅድም፤ ስለዚህ የእያንዳንዱ ደረጃ
`preserveSystemPrompt: false` በ`coding-safe` ስር የስርዓት መጭመቅን እንደገና ማንቃት አይችልም።

በዚህ የኮድ መሠረት ላይ እንደተለካው፦ `coding-safe` እና `balanced` `minCompressChars`ን ወደ
ከፍተኛው ያሳድጋሉ፣ እንዲሁም ስርዓቱን፣ የመሣሪያ ንድፎችን እና የመሣሪያ ውጤቶችን በቤተኛ ቅርጻቸው ያቆያሉ፤ ስለዚህ ገና
ታሪክ ያልሰበሰበ ክፍለ ጊዜ በ`below_min_chars` ላይ ይቆማል፣ ሞተሩም ምንም ነገር አይለውጥም። ነባሩ
ከሁሉ ደህንነቱ የተጠበቀው መገለጫ ሳይሆን `aggressive` የሆነው ለዚህ ነው።

ጥቅሉ የራሱን የሞዴል ወሰን እና መገለጫ ከአካባቢ ውቅሩ ይወስናል።
OmniRoute ውሳኔውን ፈጽሞ አይወክልም፦ አስማሚው የሞዴል መግቢያውን በጥቅሉ
እጅግ ገዳቢ በሆነው ወሰን ላይ ይቆልፋል፤ ስለዚህ የአስተናጋጅ አካባቢ ቅንብሮች የተፈቀዱ ዝርዝሩን ማጥበብ ብቻ ይችላሉ እንጂ
ከOmniRoute የተለኩ ደረሰኞች በላይ ማስፋት ፈጽሞ አይችሉም።

## የኤንጂን ሬጅስትሪ

ሬጅስትሪው በ`open-sse/services/compression/engines/registry.ts` ውስጥ ይገኛል። ኤንጂኖቹ የጋራ ውል ያቀርባሉ፦

- `id`፦ እንደ `caveman` ወይም `rtk` ያለ የማይለዋወጥ የኤንጂን መለያ
- `apply(text, config)`፦ በተደራራቢ ፓይፕላይኖች ጥቅም ላይ የሚውል የቀድሞ የማስኬጃ መንገድ
- `compress(input, config)`፦ ጽሑፍ + ስታቲስቲክስ የሚመልስ ዋና የማስኬጃ መንገድ
- `getConfigSchema()`፦ የሚሰራ ውቅር JSON-Schema-መሰል ቅርጽን ይመልሳል
- `validateConfig(config)`፦ `{ valid, errors[] }`ን ይመልሳል

ምዝገባ `registerCompressionEngine(engine)`ን (ወይም ለላቁ አጋጣሚዎች `registerEngine`ን) ይጠቀማል፤ ይህም ተቀባይነት ከመስጠቱ በፊት `assertValidEngine()`ን እና `validateConfig(defaultConfig)`ን ይጠራል።
በሂደት ላይ ሳለ ኤንጂንን ለማስወገድ `unregisterCompressionEngine(id)`ን ይጠቀሙ።

`strategySelector.ts` መጭመቅ ከመካሄዱ በፊት አብረው የተካተቱትን ኤንጂኖች ይመዘግባል። ይህም ቅድመ-ዕይታ፣ የአሂድ-ጊዜ መጭመቅ፣ የተደራራቢ ሁነታ፣ ሙከራዎች እና የወደፊት ኤንጂኖች ተመሳሳይ የማስኬጃ መንገድን እንዲጠቀሙ ያስችላል።

### የMCP መግለጫ መጭመቅ (ተዛማጅ)

የተለየ ሬጅስትሪ የMCP መሣሪያ መግለጫ ሜታዳታን በሬጅስትሪ ደረጃ ይጨምቃል — `open-sse/mcp-server/descriptionCompressor.ts`ን እና [MCP-SERVER.md](../frameworks/MCP-SERVER.md)ን ይመልከቱ። የCaveman ደንቦችን እንደገና ይጠቀማል፣ ነገር ግን የሚሠራው በመሣሪያ ሜታዳታ ላይ እንጂ በጥያቄ ፔይሎዶች ላይ አይደለም።

### ተጨማሪ አብረው የተካተቱ ኤንጂኖች

መዋቅራዊ ኤንጂኖችን ይዞ ይመጣል (በተደራራቢ ፓይፕላይኖች፣ በመሞከሪያ ስፍራው እና በሙከራዎች ጥቅም ላይ የሚውሉ)፦

`package.json` ውስጥ እንደ `optionalDependencies` ተገልጸዋል፣ እና በproduction build በ**ውጭ** ተይዘዋል
(`scripts/build/prepublish.ts` አያጠቃልላቸውም)፦

| ጥቅል                  | ስሪት (የተቆለፈ) | ማስታወሻዎች                      |
| -------------------- | ----------- | ---------------------------- |
| `@atjsh/llmlingua-2` | `2.0.5`     | ዋና ጥቅል፤ ሌሎቹን እንደ peers ይገልጻል |
| `js-tiktoken`        | `^1.0.20`   | ቶከን አውጪ                      |

`@huggingface/transformers` በ`^4.2.0` ላይ ተቆልፏል (ከአካባቢያዊው embeddings ዱካ ጋር የሚጋራ እና
ወደ standalone bundleም የሚካተት)፤ `@atjsh/llmlingua-2@2.0.5` በ
`"^3.5.2 || ^4.0.0"` ላይ peer ጥገኝነት አለው፣ ስለዚህ ሁለቱም Transformers.js v3 እና v4 ይደገፋሉ። ከ2.0.4 ጀምሮ፣
`@atjsh/llmlingua-2` ከእንግዲህ `@tensorflow/tfjs`ን አይፈልግም፤ ይህም ከSLM stack ውስጥ ትልቁን ነጠላ
አስተዋጽኦ አድራጊ (TensorFlow.js) አስወግዷል። ከላይ ያሉት ሁለት ጥቅሎች ብቻ ሊከረከሙ የሚችሉ SLM
peers ናቸው። መደበኛ `npm install` (dev)፣ አማራጭ ጥገኞች ካልተወገዱ በስተቀር፣ አማራጭ stackን በራስ-ሰር ይጭናል።

**ለምን በፍላጎት ጊዜ፦** በnpm የታተመው ጥቅል፣ standalone bundle እና Docker image
መጠናቸውን አነስተኛ ለማድረግ እነዚህን deps **ሳያካትቱ** ይላካሉ። እነሱ በማይኖሩበት ጊዜ፣ የworker ጥገኝነት
በር (`@atjsh/llmlingua-2` resolve probe በ`worker.ts` ውስጥ) ይወድቃል እና ሞተሩ
**ያለምንም ድምፅ ክፍት ሆኖ ይቀጥላል** — LLMLinguaን መምረጥ ምንም ተግባር አይኖረውም (ጽሑፉ ሳይቀየር ይመለሳል፣
ምንም ስህተት አይመዘገብም)። በተከረከመ አካባቢ ውስጥ ለማግበር፣ አማራጭ stackን ይጫኑ፦

```bash
# በpackage.json optionalDependencies ውስጥ የተገለጹትን ስሪቶች ይጠቀሙ
npm install @atjsh/llmlingua-2@2.0.5 js-tiktoken
```

የ`@tensorflow/tfjs` መወገድ (2.0.4+) ከዚህ ቀደም አብዛኛውን የያዘውን ~800 MB
አስተዋጽኦ ያስወግዳል — የቀረው መጠን transformers.js + onnxruntime-node runtimes፣
በመጀመሪያ አጠቃቀም ጊዜ የሚወርደው TinyBERT ሞዴል (~57 MB) ጋር ነው (በnpm በኩል አይደለም)።

በእያንዳንዱ አካባቢ፦

- **Dev / `npm install`** — `--omit=optional` ካላስተላለፉ በስተቀር በራስ-ሰር ይጫናል
  (ወይም `--no-optional`)። ምንም እርምጃ አያስፈልግም።
- **Global npm (`npm i -g omniroute`) / ራሱን የቻለ** — ከላይ ያለውን የመጫኛ ትዕዛዝ በተጫነው
  package ማውጫ ውስጥ ያስኪዱ፣ ወይም አማራጭ dependenciesን ሳያስቀሩ እንደገና ይጫኑ።
- **Docker** — የመጫኛ ትዕዛዙን ከእሱ በተዘጋጀ የimage ንብርብር ውስጥ ያክሉ፤ የታተመው image
  ሆን ተብሎ ቀለል ተደርጎ ይቀርባል።
- **VPS (PM2)** — በመተግበሪያው `node_modules` ውስጥ ይጫኑ፣ ከዚያም worker የgateን ሁኔታ
  እንደገና እንዲፈትሽ ሂደቱን ዳግም ያስጀምሩ።
- **Raw Next standalone (`npm run build` → `.build/next/standalone/server.js`)** — የstandalone
  trace workerንም ሆነ አማራጭ dependenciesን አያካትትም፤ ስለዚህ engine ያለማስጠንቀቂያ ክፍት ሆኖ ውድቀቱን ያልፋል። `scripts/build/colocate-standalone.mjs` ሁለቱንም (worker esbuild +
  የአማራጭ dependency ሙሉ ስብስብን ወደ standalone tree) እንደገና ያክላል፤ ከእያንዳንዱ build በኋላ በ
  `postbuild` npm hook በኩል በራስ-ሰር ይሰራል። ደጋግሞ ሲሰራ ተመሳሳይ ውጤት ያለው ሲሆን፣ dependencies ከሌሉ ችግር ሳያስከትል ያልፋል።

**ንቁ መሆኑን ያረጋግጡ:** LLMLingua ሲመረጥ እውነተኛ ጽሑፍ በትክክል ያጥራል (engine
ውድቀቱን ክፍት ሆኖ ማለፍ ያቆማል)፣ እና የመጀመሪያው ጥያቄ modelን ወደ
`${DATA_DIR}/models/llmlingua` እንዲወርድ ያደርጋል። gate ሆን ብሎ `@atjsh/llmlingua-2`ን ብቻ ይፈትሻል —
ሌሎቹ peers ESM-only ናቸው፣ እና በሚገኙበት ጊዜም `require.resolve` በእነሱ ላይ ስህተት ይጥላል — ስለዚህ
በ`import()` ጊዜ ከpeers መካከል አንዱ በእውነት ከጎደለ worker አሁንም ውድቀቱን ክፍት ሆኖ ያልፋል።

## የተደራረቡ ፓይፕላይኖች

የተደራረበ ሁነታ የፓይፕላይን ደረጃዎችን በቅደም ተከተል ያስኬዳል። ነባሪው፦

```txt
rtk -> caveman
```

አንድ መጠየቂያ የትዕዛዝ ውጤትን ከሰው ወይም ከረዳት ስድ ንባብ ጋር ለሚያጣምርባቸው የኮድ አዘጋጅ ወኪል ክፍለ ጊዜዎች ይህን ይጠቀሙ። RTK በመጀመሪያ ጫጫታ የበዛባቸውን የመሣሪያ ምዝግቦች ይቀንሳል፣ ከዚያም Caveman የቀረውን ተፈጥሯዊ ቋንቋ ይጨምቃል።

የፓይፕላይን ደረጃዎች በመጭመቂያ ቅንብሮች ውስጥ ባለው `stackedPipeline` ወይም በመጭመቂያ ጥምረቶች በኩል ይዋቀራሉ።

ሁለቱም ሞተሮች ተመሳሳዩን ብቁ የውሂብ ጭነት ሲቀንሱ፣ ቁጠባዎቹ ይደራረባሉ፦

```txt
combined = 1 - (1 - RTK savings) * (1 - Caveman input savings)
average  = 1 - (1 - 0.80) * (1 - 0.46) = 89.2%
range    = 1 - (1 - 0.60..0.90) * (1 - 0.46) = 78.4-94.6%
```

## የMCP ተደራሽነት ዛፍ ማጣሪያ

የMCP ተደራሽነት ዛፍ ብልህ ማጣሪያ፣ በመጠየቂያዎች ወይም በዐውድ ላይ ሳይሆን በMCP **የመሣሪያ ውጤቶች** ላይ የሚሠራ ከአፈጻጸም በኋላ የሚተገበር የመጭመቂያ ንብርብር ነው። እንደ Playwright፣ computer-use እና browser-automation MCP አገልጋዮች ባሉ መሣሪያዎች የሚመለሱትን ዝርዝር የተደራሽነት ዛፍ እና የአሳሽ ቅጽበታዊ ምስል የውሂብ ጭነቶችን ያነጣጥራል።

### የሚያከናውነው

1. **ጫጫታን ማስወገድ** — ባዶ አጠቃላይ/የጽሑፍ ግቤቶችን (`- generic:`፣ `- text: ""`) ያስወግዳል
2. **ተመሳሳይ ደረጃ ያላቸውን ማጠቃለል** — ≥ `collapseThreshold` (ነባሪ 30) ተከታታይ መስመሮች የመዋቅር ድግግሞሾች ሲሆኑ፣ ወደ መጀመሪያዎቹ `collapseKeepHead` (ነባሪ 10) መስመሮች + የብዛት ማጠቃለያ + የመጨረሻዎቹ `collapseKeepTail` (ነባሪ 5) መስመሮች ያጠቃልላቸዋል
3. **የማጣቀሻ ጥበቃ** — በPlaywright/computer-use የሚፈለጉ `[ref=eXX]` መልሕቆች ፈጽሞ አይነኩም
4. **ጠንካራ መቁረጥ** — ጽሑፉ ከተጠቃለለ በኋላ አሁንም `maxTextChars`ን (ነባሪ 50,000) የሚያልፍ ከሆነ፣ ወኪሉ ሥራውን እንዲቀጥል በሚያስችል የዳሰሳ ፍንጭ ይቆርጠዋል

### የሞተሩ አካባቢ

```txt
open-sse/services/compression/engines/mcpAccessibility/
  index.ts            ← የsmartFilterText() መግቢያ ነጥብ
  collapseRepeated.ts ← ተመሳሳይ ደረጃ ያላቸውን የማጠቃለል ስልተ ቀመር
  constants.ts        ← DEFAULT_MCP_ACCESSIBILITY_CONFIG
```

### ውቅር

በዓለም አቀፍ ቅንብሮች (ፍልሰት 056) ውስጥ ባለው `compression.mcpAccessibility` ይቆጣጠራል። ነባሪ ውቅር፦

```json
{
  "enabled": true,
  "maxTextChars": 50000,
  "collapseThreshold": 30,
  "collapseKeepHead": 10,
  "collapseKeepTail": 5,
  "minLengthToProcess": 2000
}
```

ማጣሪያው የሚተገበረው `type`ቸው `"text"` በሆነ እና ርዝመታቸው `minLengthToProcess`ን በሚያልፍ የመሣሪያ ውጤት የውሂብ ጭነቶች ላይ ብቻ ነው። የመጠየቂያ መጭመቂያን ወይም የጥያቄ የውሂብ ጭነቶችን አይነካም።

### የሚጠበቁ ቁጠባዎች

እንደ ገጹ ውስብስብነት፣ በአሳሽ ቅጽበታዊ ምስል መሣሪያ ውጤቶች ላይ 60–80%። የማጠቃለያ ስልተ ቀመሩ በመስመር ብዛት O(n) ሲሆን፣ እምብዛም የማይባል መዘግየት ይጨምራል።

## የጨመቃ ጥምረቶች

የጨመቃ ጥምረቶች ለማዘዋወሪያ ጥምረቶች ሊመደቡ የሚችሉ ስም ያላቸው የጨመቃ መገለጫዎች ናቸው፦

- `compression_combos`፦ ሁነታን፣ pipelineን፣ የRTK ውቅርን፣ የቋንቋ ውቅርን እና ነባሪ ምልክትን ያከማቻል
- `compression_combo_assignments`፦ የጨመቃ ጥምረትን ከማዘዋወሪያ ጥምረት ጋር ያዛምዳል
- የruntime ውህደቱ ከአጠቃላይ የጥምረት ሽረቶች በፊት የተመደበውን የጨመቃ ጥምረት ይፈታል
- analytics `compression_combo_id` እና `engine`ን ያካትታል

የDashboard መገኛ፦ `Dashboard -> Context & Cache -> Compression Combos`።

## ወሰን እና ማግለያዎች

**Embeddings በፍጹም አይጨመቁም።** `open-sse/handlers/embeddings.ts` ምንም
የጨመቃ engine አይጠራም — የrequest/response bodies ሳይነኩ በቀጥታ ወደ executor ያልፋሉ።
ይህ በአሁኑ ጊዜ መዋቅራዊ ነው (embeddings እና chat completions የተለያዩ handlers ናቸው)፣
የruntime ፍተሻ አይደለም፤ ነገር ግን ይህ በ#8034 ያለው የvector-distortion ስጋት
በembeddings path ውስጥ የተጋላጭነት መገኛ እንደሌለው ያሳያል።

**የእያንዳንዱ-model/endpoint ማግለያ ማጣሪያ (#8034)።** ለchat completions፣ operator
ፈጽሞ መጨመቅ የሌለባቸውን model ids / `provider/model` targets መጥቀስ ይችላል — ይህ
ወደፊት ጨመቃ ከembeddings አጠገብ ካለ path ጋር ይበልጥ በቅርብ ቢገናኝ ጠቃሚ የሆነ guardrail ሲሆን፣
ትክክለኛው byte-for-byte prompt አስፈላጊ ለሆነበት ማንኛውም model (deterministic evals፣ cache-sensitive
prefixes፣ ወዘተ) በአጠቃላይ ጠቃሚ ነው።

- የቅንብሮች field፦ በዓለም አቀፍ የጨመቃ config ላይ `exclusions?: string[]`
  (`GET`/`PUT /api/settings/compression`)፣ ባለው `key_value` የጨመቃ
  namespace (`src/lib/db/compression.ts`) በኩል ይቀመጣል — አዲስ table የለም።
- የDashboard tab፦ **Dashboard → Compression → Exclusions**
  (`/dashboard/compression/exclusions`)።
- የpattern syntax፦ `*` ብቸኛው wildcard ነው። በpattern ውስጥ ያሉ ሌሎች ሁሉም regex metacharacters
  ከማዛመድ በፊት escaped ይደረጋሉ፤ ስለዚህ `gpt-5.6` ከliteral string ጋር ብቻ ይዛመዳል፣
  ከ`gpt-5x6` ጋር ፈጽሞ አይዛመድም (ReDoS-safe፣ bounded፣ nested quantifiers የሉም)። Patterns
  ከbare model id እና ከ`provider/model` composite ሁለቱም ጋር case-insensitive በሆነ መንገድ
  ይዛመዳሉ — `gpt-5-6`፣ `openai/gpt-5-6` እና `openai/*` ሁሉም ይሰራሉ፣ እንዲሁም `*`
  ብቻውን ሁሉንም model ያገላል።
- ማዛመድ፦ `open-sse/services/compression/exclusions.ts` ውስጥ
  `isCompressionExcluded()` / `normalizeCompressionExclusions()`። `chatCore.ts` የጨመቃ ቅንብሮችን
  ከፈታ በኋላ፣ **ማንኛውም engine ከመስራቱ በፊት**፣ የተገለለውን target ይፈትሻል፣ እና ማዛመድን
  ልክ ጨመቃ በዓለም አቀፍ ደረጃ disabled እንደሆነ ይይዘዋል — የrequest body በማስረጃ
  byte-identical ነው። መዝለሉ ለanalytics ታይነት በ`writeCompressionSkip(..., "excluded")`
  በኩል ይመዘገባል።
- ነባሪ (ባዶ/የሌለ list)፦ ከ#8034 በፊት ከነበረው behavior ጋር ተመሳሳይ ነው — ምንም ነገር አይገለልም።

## የታወቁ ገደቦች

- **LLMLingua-2 (SLM) አማራጭ ጥገኞች በአንድ ቦታ እንዲገኙ ይፈልጋል።** worker-ው በ
  production build ውስጥ የሚሠራው `@atjsh/llmlingua-2` + peers ወደ
  `dist/node_modules` በአንድ ቦታ ሲቀመጡ ብቻ ነው (`scripts/build/colocateOptionals.mjs`ን፣ #4286ን ይመልከቱ)። እነዚህ ከሌሉ
  engine-ው በfail-open ሁኔታ ይሠራል (ዋናውን ጽሑፍ ይመልሳል)። የworker resolution ከእንግዲህ በ
  `import.meta.url` ላይ አይመሠረትም (በstandalone bundle ውስጥ አይሠራም) — በruntime
  cwd / `argv[1]` ላይ ይመሠረታል።
- **የCaveman ቋንቋ packs `de` / `fr` / `ja` ከፊል ናቸው።** `context` +
  `filler` + `structural` ደንቦችን ይዘው ይመጣሉ፣ ነገር ግን `dedup` / `ultra` packs የላቸውም፤ ስለዚህ `ultra` intensity
  ለእነዚያ ቋንቋዎች ከ`full` የበለጠ ጠንካራ አይደለም (የራሳቸውን ደንቦች ብቻ ይጠቀማሉ — የውጭ ቋንቋ ጽሑፍን ሊያበላሹ የሚችሉትን
  የእንግሊዝኛ `dedup`/`ultra` ደንቦች በድብቅ አይጠቀሙም)።
  `en` / `es` / `id` / `pt-BR` የተሟሉ ናቸው። ለከፊል packs የ`dedup.json` + `ultra.json`
  አስተዋጽኦዎች በደስታ ይቀበላሉ።
- **የተደራረበ telemetry የሚዘረዝረው ጨመቃ ያከናወኑ enginesን ብቻ ነው።** engine-ው
  የሠራበት ነገር ግን 0 % ቅነሳ ያስገኘው የstacked-pipeline ደረጃ `stats:null`ን ይመልሳል፣ ስለዚህም በ
  `engineBreakdown` ውስጥ አይታይም — ከተዘለለ ደረጃ ለመለየት አይቻልም።
  "ሠርቷል፣ 0 %"ን ከ"ተዘሏል" መለየት የbreakdown-model ለውጥን የሚፈልግ ሲሆን ለወደፊት ተላልፏል።
