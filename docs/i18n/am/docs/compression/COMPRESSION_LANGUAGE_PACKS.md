Caveman መጭመቂያ አብረው ከተካተቱት የእንግሊዝኛ ደንቦች በተጨማሪ ቋንቋ-ተኮር የደንብ ጥቅሎችን መጫን ይችላል።
ይህም የፖርቱጋልኛ፣ የስፓኒሽ፣ የጀርመንኛ፣ የፈረንሳይኛ፣ የጣሊያንኛ፣ የጃፓንኛ እና
የወደፊት ቋንቋዎች ጥቅሎች በተናጥል እንዲያድጉ እያስቻለ ዋናውን ሞተር የተረጋጋ አድርጎ ይጠብቃል።

## መገኛ

የቋንቋ ጥቅሎች በሚከተለው ሥር ይገኛሉ፦

```txt
open-sse/services/compression/rules/<language>/
```

አሁን የሚቀርቡ ጥቅሎች (ከ`rules/` ማውጫ ይዘቶች ጋር የተረጋገጡ)፦

| ቋንቋ           | ማውጫ            | ያሉ የደንብ ምድቦች                                        |
| ------------- | -------------- | --------------------------------------------------- |
| እንግሊዝኛ        | `rules/en/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| ስፓኒሽ          | `rules/es/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| ፖርቱጋልኛ (ብራዚል) | `rules/pt-BR/` | `context`, `dedup`, `filler`, `structural`, `ultra` |
| ኢንዶኔዥያኛ       | `rules/id/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| ጣሊያንኛ         | `rules/it/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| ጀርመንኛ         | `rules/de/`    | `context`, `filler`, `structural`                   |
| ፈረንሳይኛ        | `rules/fr/`    | `context`, `filler`, `structural`                   |
| ጃፓንኛ          | `rules/ja/`    | `context`, `filler`, `structural`                   |

> **የእኩልነት ማስታወሻ፦** የ`en`፣ `es`፣ `pt-BR`፣ `id` እና `it` ጥቅሎች ሙሉዎቹን 5 ምድቦች ይዘዋል፤ `de`፣ `fr` እና `ja` ደግሞ 3 ምድቦችን ይዘው ይቀርባሉ። የጎደሉት `dedup` እና `ultra` ምድቦች ያለምንም ማሳወቂያ ወደ አብረው የተካተቱት የእንግሊዝኛ ደንቦች ይመለሳሉ። ለአነስተኛዎቹ ጥቅሎች `dedup.json` እና `ultra.json` ለመጨመር አስተዋጽኦዎችን በደስታ እንቀበላለን።
>
> የ`pt-BR` ጥቅል በLenine Júnior በተዘጋጀው **[Troglodita](https://github.com/leninejunior/troglodita)** ላይ የተመሠረተ ነው — ይህም ለብራዚላዊ ፖርቱጋልኛ ሰዋሰው ከመሠረቱ የተነደፈ የመጭመቂያ ሥርዓት ነው (የትርፍ ድግግሞሽ ቅነሳ፣ የPT-BR ሙሌት ቃላት ማስወገድ፣ ለብራዚል ገንቢዎች ማህበረሰብ ቴክኒካዊ አህጽሮተ ቃላት)።
>
> መደበኛው የምድብ ዝርዝር እና የእያንዳንዱ ምድብ ንድፍ በ[`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) (JSON Schema draft 2020-12) ውስጥ ይገኛሉ።

## የቋንቋ መለየት

`languageDetector.ts` ከጥያቄ ጽሑፍ ቋንቋውን ለመገመት ቀላል የግምት ዘዴዎችን ይጠቀማል። የተዋቀረው
ነባሪ ቋንቋ አሁንም ይከበራል፣ እና ትክክለኛ ቁጥጥር ሲያስፈልግ መለየት በውቅረት
ሊሰናከል ይችላል።

የመለየት ውጤቱ የደንብ ጥቅሎችን ለመምረጥ ብቻ ጥቅም ላይ ይውላል። የአቅራቢ ማዘዋወርን፣ የአካባቢ ቅንብር
ምርጫን ወይም የUI ቋንቋን አይለውጥም።

## የውቅረት ቅርጽ

የመጭመቂያ ቅንብሮች የሚከተለውን ሊያካትቱ ይችላሉ፦

```json
{
  "languageConfig": {
    "enabled": true,
    "defaultLanguage": "en",
    "autoDetect": true,
    "enabledPacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  },
  "cavemanConfig": {
    "language": "en",
    "autoDetectLanguage": true,
    "enabledLanguagePacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  }
}
```

`languageConfig` የዳሽቦርድ/ቅድመ ዕይታ ነባሪዎችን ይቆጣጠራል። `cavemanConfig` ደግሞ
Caveman የመልዕክት ጽሑፍን ሲጭመቅ ጥቅም ላይ የሚውለው የአሂድ ጊዜ ሞተር ውቅረት ነው።

## የቋንቋ ጥቅል ማከል

1. `open-sse/services/compression/rules/<language>/<pack>.json` ይፍጠሩ።
2. በ`docs/compression/COMPRESSION_RULES_FORMAT.md` ውስጥ ያለውን የCaveman ደንብ ቅርጸት ይጠቀሙ።
3. ምትኮችን ጥንቃቄ የተሞላባቸው ያድርጉ፣ እንዲሁም ኮድን፣ መለያዎችን፣ URLsን ወይም JSONን ከመቀየር ይቆጠቡ።
4. ለቋንቋ ምርጫ እና ለምትክ ባህሪ ሙከራዎችን ያክሉ ወይም ያዘምኑ።
5. ቋንቋው በUI መምረጫዎች ውስጥ የሚታይ ከሆነ፣ አዲስ የዳሽቦርድ/i18n መለያዎችን ያጋልጡ።

## API

የሚገኙ ጥቅሎችን በሚከተለው መጠየቅ ይቻላል፦

```bash
curl http://localhost:20128/api/compression/language-packs
```

የቅድመ-እይታ መጨረሻ ነጥቡ የቋንቋ ውቅር ሽረቶችን ይቀበላል፦

```bash
curl -X POST http://localhost:20128/api/compression/preview \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "standard",
    "text": "Por favor, eu gostaria que voce basicamente resumisse isso.",
    "config": {
      "languageConfig": {
        "defaultLanguage": "pt-BR",
        "autoDetect": true
      }
    }
  }'
```

## SHARED_BOUNDARIES (v3.8.0)

ሁሉም 6 የቋንቋ ጥቅሎች በv3.8.0 ውስጥ በእያንዳንዱ የCaveman ጥንካሬ ደረጃ (LITE, FULL, ULTRA) ላይ የሚተገበር የ`SHARED_BOUNDARIES` አንቀጽ አግኝተዋል። ይህም ሞተሩ በዙሪያቸው ያለው ትርፍ ጽሑፍ ቢወገድም እነዚህን ቅጦች ሳይለውጥ እንዲጠብቅ ያዛል፦

| የቅጥ ዓይነት                | ምሳሌ                                    |
| ----------------------- | -------------------------------------- |
| በአጥር የተከበቡ የኮድ ብሎኮች     | ` ```python\n...\n``` `                |
| የመስመር ውስጥ ኮድ            | `` `my_var` ``                         |
| URLs                    | `https://example.com/path`             |
| የፋይል ዱካዎች (ፍጹም + አንጻራዊ) | `/etc/hosts`, `./src/index.ts`         |
| የስህተት ራስጌዎች             | `Error:`, `TypeError:`, `SyntaxError:` |
| የቁልል ዱካ መስመሮች           | `  at functionName (file.ts:12:3)`     |

እነዚህ ቅጦች በ`DEFAULT_CAVEMAN_CONFIG.preservePatterns` ውስጥ ይሞላሉ (ከዚህ ቀደም `[]` ነበር)። ቋሚው በ`open-sse/services/compression/types.ts` ውስጥ ይገኛል።

### ይህ አስፈላጊ የሆነው ለምንድን ነው

SHARED_BOUNDARIES ባይኖር፣ ኃይለኛ የCaveman ሁነታዎች ተደጋጋሚ ስድ ንባብ የሚመስል፣ ነገር ግን በእውነቱ የኮድ ቅንጣቢ፣ የፋይል ዱካ ወይም የስህተት ቁልል የሆነ ይዘትን ሊያስወግዱ ይችላሉ። SHARED_BOUNDARIES የትርፍ ጽሑፍ ደንቦች ከመተግበራቸው በፊት የሚተገበር ከቋንቋ ነጻ የሆነ የደህንነት መረብ ሆኖ ያገለግላል።

### preservePatternsን ማበጀት

ተጨማሪ ቅጦችን በሂደት ጊዜ በመጭመቂያ ቅንብሮች በኩል ማከል ይቻላል፦

````json
{
  "cavemanConfig": {
    "preservePatterns": [
      "```[\\s\\S]*?```",
      "`[^`]+`",
      "https?://\\S+",
      "(?:/|\\./)[^\\s]+",
      "\\b(?:Error|TypeError|SyntaxError|RangeError):",
      "\\s+at\\s+\\S+\\s+\\(\\S+:\\d+:\\d+\\)"
    ]
  }
}
````

## የአሠራር ማስታወሻዎች

- የቋንቋ ጥቅል በማይኖርበት ጊዜ አብረው የተካተቱት የእንግሊዝኛ ደንቦች የመጠባበቂያ አማራጭ ሆነው ይቀጥላሉ።
- የልቀት ሀብቶች በድብቅ እንዳይዋረዱ፣ ልክ ያልሆኑ አብረው የተካተቱ JSON ጥቅሎች በማረጋገጫ ወቅት ውድቅ ይሆናሉ።
- የደንብ ጥቅሎች ውሂብ ብቻ ሲሆኑ፣ ኮድ ማስመጣት ወይም የዘፈቀደ አመክንዮ ማስኬድ የለባቸውም።
- የመጭመቂያ ትንታኔ ንብርብሩ ሙሉውን የጥያቄ ጽሑፍ ሳይሆን የተመረጠውን ሁነታ እና ሞተር ይመዘግባል።
