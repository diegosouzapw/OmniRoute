የWeb Cookie አቅራቢዎች OmniRoute ን ከAPI key ይልቅ አሁን ያለዎትን የአሳሽ ክፍለ-ጊዜ በመጠቀም የAI አገልግሎት እንዲጠቀም ያስችሉታል። አንድን አገልግሎት በድረ ገጹ በኩል የመጠቀም ፈቃድ አስቀድሞ ሲኖርዎት እና OmniRoute ያንኑ ማንነቱ የተረጋገጠ ክፍለ-ጊዜ እንዲጠቀም ሲፈልጉ ጠቃሚ ናቸው።

ከAPI-key አቅራቢዎች በተለየ፣ የWeb Cookie አቅራቢዎች አሳሽዎ ወደ ድረ ገጹ የሚልካቸውን የማረጋገጫ መረጃዎች በመጠቀም ማንነትን ያረጋግጣሉ።

# ከመጀመርዎ በፊት

> **አስፈላጊ፦** ሁልጊዜ የማረጋገጫ መረጃዎችን ከአሳሽዎ cookie ማከማቻ **ሳይሆን** ከ**ቀጥታ የአውታረ መረብ ጥያቄ** ይቅዱ።

ብዙ የማንነት ማረጋገጫ ችግሮች cookies ከተሳሳተ ቦታ በመቅዳት ይከሰታሉ።

## ከCookie ማከማቻ አይቅዱ

አብዛኛዎቹ አሳሾች የተከማቹ cookies በሚከተለው መንገድ ያሳያሉ፦

```
DevTools
→ Application (ወይም Storage)
→ Cookies
```

እነዚህ cookies ትክክለኛ ቢመስሉም፣ ሊሆኑ የሚችሉት፦

- ጊዜ ያለፈባቸው
- ያልተሟሉ
- በማንነት በተረጋገጡ ጥያቄዎች ላይ ብቻ የሚላኩ cookies የጎደሏቸው

እነዚህን እሴቶች መጠቀም፣ ትክክለኛ ቢመስሉም እንኳ፣ የማንነት ማረጋገጫ ውድቀቶችን ሊያስከትል ይችላል።

## ከቀጥታ ጥያቄ ይቅዱ

በምትኩ፣ ከተሳካ ጥያቄ የሚገኙትን cookies ይጠቀሙ፦

```
DevTools
→ Network
→ ገጹን ያድሱ
→ የውይይት ወይም የጭውውት ጥያቄ ይክፈቱ
→ Request Headers
→ Cookie
```

የ`Cookie` ጥያቄ ርዕስ አሳሽዎ በተሳካ ሁኔታ የተጠቀመበትን ትክክለኛ የማረጋገጫ መረጃ ይዟል።

ለአብዛኛዎቹ የWeb Cookie አቅራቢዎች፣ ይህ ወደ OmniRoute መለጠፍ ያለበት እሴት ነው።

---

# አጠቃላይ ማዋቀር

የማዋቀሩ ሂደት ለአብዛኛዎቹ የWeb Cookie አቅራቢዎች ተመሳሳይ ነው።

1. ወደ አቅራቢው ድረ ገጽ ይግቡ።
2. የአሳሹን የገንቢ መሣሪያዎች ይክፈቱ።
3. የ**Network** ትርን ይክፈቱ።
4. ገጹን ያድሱ።
5. ማንነቱ የተረጋገጠ የውይይት ወይም የጭውውት ጥያቄ ይክፈቱ።
6. አስፈላጊዎቹን የማረጋገጫ መረጃዎች ይቅዱ።
7. OmniRoute ን ይክፈቱ።
8. ወደ **Providers → Add Provider** ይሂዱ።
9. የWeb Cookie አቅራቢዎን ይምረጡ።
10. የማረጋገጫ መረጃዎቹን ይለጥፉ።
11. **Test Connection** ን ጠቅ ያድርጉ።
12. አቅራቢውን ያስቀምጡ።

ትክክለኛዎቹ አስፈላጊ የማረጋገጫ መረጃዎች እንደ አቅራቢው ይለያያሉ።

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) ምዝገባ የማያስፈልገው ነፃ የተጠቃሚዎች ውይይት መድረክ ነው — ክፍለ-ጊዜው በመጀመሪያው ጉብኝት ላይ ማንነትን ሳይገልጽ የሚፈጠር ሲሆን፣ በሶስት ኩኪዎች በኩል ይቆያል፦ `uid`፣ `si_usr_id` እና `si_ses_id`። OmniRoute ተመሳሳዩን `/api/dispatch` የመዳረሻ ነጥብ በአንድ የሞዴል መታወቂያ (`notrack-c`፣ ቅጽል `ntw`) በኩል ያኪሳል።

### ለማገናኘት የሚከተሉ ደረጃዎች

1. [notrack.ai](https://notrack.ai)ን በአሳሽዎ ውስጥ ይክፈቱ እና የማይታወቅ ክፍለ-ጊዜ ኩኪው እንዲዘጋጅ ይፍቀዱ።
2. **DevTools → Network**ን ይክፈቱ፣ ገጹን ያድሱ እና ማንኛውንም `/api` ጥያቄ ጠቅ ያድርጉ።
3. በ**Request Headers** ውስጥ ሙሉውን የ`Cookie` ራስጌ እሴት ይቅዱ።
4. በOmniRoute ውስጥ ወደ **Providers → Add Provider → NoTrack Web (Free)** ይሂዱ።
5. የኩኪውን ሕብረቁምፊ በ`apiKey` መስክ ውስጥ ይለጥፉ እና **Save**ን ይጫኑ።

OmniRoute ከተለጠፈው ሕብረቁምፊ `uid`፣ `si_usr_id` እና `si_ses_id`ን አውጥቶ እነዚያን ጥንዶች ብቻ የያዘ ንጹሕ የ`Cookie` ራስጌ እንደገና ይገነባል — በተጨማሪም `nt_session` (ወደ መለያቸው ለገቡ መለያዎች የሚዘጋጀው `ntk_…` ቶከን) ካለ ያክላል። ከሶስቱ አንዱ ከጎደለ፣ ኦፕሬተሮች በአማራጭ ቅርጾች መሞከር እንዲችሉ የተለጠፈው ጥሬ ሕብረቁምፊ ሳይቀየር ይተላለፋል።

| ----------- | --------- | ------------------------------------- |

### ችሎታዎች

- **በዥረት እና ያለዥረት** የውይይት ማጠናቀቂያዎች።
- **የመሣሪያ ጥሪ** — በጥያቄው ላይ `tools: [...]`ን ያዘጋጁ፤ አስፈጻሚው ወደ የመሣሪያ-ጥሪ መሸፈኛ ውል በተከታታይ ይቀይራቸዋል እና የሞዴሉን ምላሾች መልሶ ወደ OpenAI `tool_calls` ይተነትናል።
- **`response_format`** — `json_object` እና `json_schema` ይደገፋሉ። አስፈጻሚው ከሞዴሉ ምላሽ የመጀመሪያውን JSON ነገር አውጥቶ ከመመለሱ በፊት ወደ ሕብረቁምፊ ይቀይረዋል።
- **የአስተሳሰብ ፍንጭ** — የላይኛው አገልግሎት `thinking` ክስተት ሲልክ፣ አስፈጻሚው የ`reasoning` ልዩነት ያወጣል።

### ገደቦች

- የላይኛው አገልግሎት ስም-አልባ የአጠቃቀም ኮታዎችን ያስፈጽማል — ገደቡ ሲደረስ፣ አስፈጻሚው 429ን ከለዘብተኛ መልዕክት ጋር ያሳያል።
- ሁሉም የሞዴል መታወቂያዎች ወደ ተመሳሳዩ የላይኛው የመላኪያ ሞዴል ይመራሉ፤ በየሞዴሉ የሚደረግ መቀየሪያ የለም።
- አስፈጻሚው የላይኛውን `/api/chats` የመዳረሻ ነጥብ አይጠራም፣ ስለዚህ የውይይት ታሪክ / ክፍለ-ጊዜዎች በራስ-ሰር አይተዳደሩም። ያለ የላይኛው ውይይት ለመቀጠል `notrack_chat_id`ን ይጠቀሙ።
