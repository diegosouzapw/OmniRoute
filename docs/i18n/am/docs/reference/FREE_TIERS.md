> **ለመጨረሻ ጊዜ የተመረመረው፦** 2026-06-17 — የእያንዳንዱን አቅራቢ የነፃ ደረጃ ኮታ + ToS ያደሰ፣ በአቅራቢ የተከፋፈለ የድር ጥናት (ይፋዊ ሰነዶች + የመጨረሻዎቹ 7 ቀናት ዜና፣ ከተቃራኒ ማረጋገጫ ጋር የ50-ወኪል ምርመራ)። **ከፊል ዳግም ኦዲት 2026-09-02** (`gemini`፣ `ollama-cloud`፣ `groq`፣ `nara`፣ `mistral` — ከታች ያለውን ቀን የተጻፈበት ማስታወሻ ይመልከቱ)።
> **የእውነት ዋና ምንጭ (ካታሎግ)፦** `open-sse/config/freeModelCatalog.ts` (የእያንዳንዱ MODEL በጀቶች፣ በጋራ ማከማቻ የተደጋገሙት የተወገዱ)። ከታች ያሉት የቶከን በጀት ቁጥሮች ከቀጥታ የድር ጥናት የመጡ ሲሆኑ **ግምታዊ** ናቸው — [ዘዴ እና ማስጠንቀቂያዎችን](#methodology--caveats) ይመልከቱ።

## TL;DR — OmniRoute በእርግጥ ምን ያህል ነፃ inference ያሰባስባል?

- **አንድ ግቤት በትክክል ለምን ዋስትና እንደሚሰጥ።** ምንም ግቤት በየረድፉ የተሰጠ የእርግጠኝነት ደረጃ የለውም፣ APIውም አያቀርብም — ከላይ ያለውን እያንዳንዱን አሃዝ ተመሳሳይ፣ በግልጽ ያልተጠቀሰ ጥራት ያለው ግምት አድርገው ይውሰዱት። ሁለት እውነታዎች ግን ከግምት የተገኙ ሳይሆኑ በእጅ የተመረጡ ስለሆኑ የተለዩ ናቸው፦ 44 ግቤቶች በተናጥል የተመዘገበ ጥብቅ ማቆሚያ አላቸው (ከእነዚህ 39ኙ ሁሉም አንድ የዕለት ፈቃድ የሚጋሩት የxKiro ረድፎች ናቸው)፣ እና 13 ግቤቶች የፕሮምፕት ማሰልጠኛ ይፋ መግለጫ አላቸው። `hardStopGuaranteed` የሚዘጋጀው የአቅራቢው የራሱ ውሎች ነፃውን ፈቃድ ማለፍ ያለማስጠንቀቂያ ክፍያ ከመጀመር ይልቅ ጥያቄውን ውድቅ እንደሚያደርግ ሲገልጹ ብቻ ነው፤ ምንጩም ከግቤቱ አጠገብ ባለ አስተያየት ውስጥ ይቀመጣል። ይህ ፈጽሞ በነባሪ `true` አይደረግም፣ እና ማንም ያላረጋገጠው ግቤት ሳይዘጋጅ ይቀራል። ስለዚህ የጥብቅ ማቆሚያ ምልክት አለመኖር ማለት "አልተረጋገጠም" ማለት እንጂ "ክፍያ እንደሚያስከፍልዎት ይታወቃል" ማለት አይደለም። **STRICT ሁነታ** (በፈቃድ የሚነቃው `freeAccessPolicy=strict` የማስተላለፊያ መከላከያ) ምልክቱን የያዙ ግቤቶችን ብቻ ያምናል፤ ማንኛውም ሌላ ነፃ ደረጃ እንደ `no-hard-stop` ይገለላል (`open-sse/services/autoCombo/strictZeroCostFilter.ts`ን ይመልከቱ)።
- `estMonthlyFreeTokens` = በየወሩ የሚደጋገሙ ቶከኖች ብቻ። **የአንድ ጊዜ የምዝገባ ክሬዲቶች አይደጋገሙም** እና እንደ 0 ይቆጠራሉ። የተቋረጡ ደረጃዎችም 0 ናቸው።
- የዕለት ቶከን ገደብ → `monthly = daily × 30`። RPD ብቻ ከተመዘገበ → `RPD × ~800 output tokens × 30`። RPM/TPM ብቻ ከሆነ (የዕለት ገደብ ከሌለ) → **ገደብ የለውም** (ከታች ይመልከቱ)።
- **በቋሚነት ነፃ፣ ነገር ግን የታተመ የቶከን ገደብ የሌላቸው** (`siliconflow`፣ `glm-cn`፣ `tencent`፣ `baidu`፣ `kilo-gateway`፣ `opencode-zen`፣ `gemini`፣ `ollama-cloud`)፦ እነዚህ በፍጥነት/በአንድ ጊዜ አጠቃቀም የተገደቡ እውነተኛ፣ ተደጋጋሚ ነፃ መዳረሻዎች ናቸው። እንደ `recurring-uncapped` እንመድባቸዋለን እና **ፈጽሞ አንደምራቸውም** — `RPM × 24/7 × 30d`ን ማባዛት ምናባዊ ከፍተኛ ወሰን ይፈጥራል (የማንቀበለው የተጋነነ ግምት)። መኖራቸውን እንዲያውቁ በዝርዝሩ ተካተዋል።
- **በተቀማጭ ገንዘብ የሚከፈት ጭማሪ፦** ነፃ ኮታን በቋሚነት ከፍ የሚያደርግ አነስተኛ የአንድ ጊዜ ጭማሪ (OpenRouter፦ $10 → 1000 ጥያቄዎች/ቀን ≈ +24M/ወር)። እንደ የተለየ አሃዝ ይገለጻል፣ ከቋሚው ዋና አሃዝም ውጭ ይቀመጣል።
- **በብቁነት የተገደቡ ኮታዎች** (`eligibilityGate: "regional-identity"`)፦ ከክልል ጋር የተያያዘ የማንነት ማረጋገጫ ከተደረገ በኋላ ብቻ የሚከፈት እውነተኛ፣ ተደጋጋሚ ኮታ (በአሁኑ ጊዜ የዋናው ቻይና የእውነተኛ ስም ማረጋገጫ)። በተመሳሳይ የጋራ ክምችት ድግግሞሽ ማስወገጃ ደንብ መሠረት ወደ ተለየ አሃዝ (`gatedRecurringTokens`) ይቆጠራል፣ በቋሚው ዋና አሃዝ ውስጥ ግን ፈጽሞ አይካተትም። ሥርዓቱ (`freeType`) ስለማይለወጥ፣ ማስተላለፉም አይለወጥም።
- **የማስረጃ ምድቦች።** ደንቡ፦ በካታሎጉ ውስጥ ያለ ቁጥር ምንጩን ከግቤቱ አጠገብ ባለ `// evidence:` አስተያየት ውስጥ ይጠቅሳል — `public-page` (ማንኛውም ሰው ሊያነበው የሚችል የአቅራቢ ገጽ)፣ `api-public` (ማረጋገጫ የማይጠይቅ የአቅራቢው endpoint፣ ለምሳሌ በrouter.bynara.id የሚገኘው የNaraRouter ይፋዊ የዕቅዶች endpoint)፣ ወይም `console-verified <date> por <who>` (አሃዙ በመለያ ኮንሶል ውስጥ ብቻ የሚታይ ነው፤ አስተያየቱ ማን እንዳየውና መቼ እንዳየው፣ እንዲሁም ገደቡ መኖሩን የሚገልጸውን ይፋዊ ገጽ ይመዘግባል)። የአሁኑ ሁኔታ፦ በ2026-09-02 እንደገና የተመረመሩት አምስት ብሎኮች ይህን ይዘዋል (`gemini`፣ `groq`፣ `mistral`፣ `ollama-cloud`፣ `nara`)፤ ከ2026-09-02 ዳግም ምርመራ በፊት የነበሩ ግቤቶች እስኪነኩ ድረስ ቀደምት ምርምሩን ይወርሳሉ፤ የማስረጃ አስተያየት የሌለው ማንኛውም **አዲስ ወይም የተለወጠ** ቁጥር ስህተት ነው። በአሁኑ ጊዜ `mistral` ብቻ በኮንሶል የተረጋገጠ ነው።

## የእኛ ቁጥር ከሌሎች አሰባሳቢዎች ለምን ያነሰ እንደሆነ

በዚህ መስክ ውስጥ ያሉት አብዛኛዎቹ የ«ነፃ ቶከኖች በወር» ቁጥሮች የእያንዳንዱ ሞዴል መለያዎች ድምር ናቸው። የእኛ ግን ሆን ተብሎ እንዲህ አይደለም፦

- **እያንዳንዱ የጋራ ኮታ አንድ ጊዜ ብቻ ይቆጠራል።** የMistral ነፃ ዕቅድ ለእያንዳንዱ ድርጅት በወር አንድ የ1B ፈቃድ ነው፤ ከአምስት ሞዴሎች ስር መዘርዘሩ 5B አያደርገውም። በየሞዴሉ ሲደመር፣ የራሳችን ካታሎግ **~7.4B** ይሆናል (በ2026-09-03 እንደገና የተሰላ፤ ይህ ቁጥር በCI የተገደበ አይደለም — ካታሎጉ በተቀየረ ቁጥር እንደገና ይለኩት) — ዋናው ርዕስ **~1.47B** ይላል፣ ምክንያቱም ከእያንዳንዱ አቅራቢ አንድ መለያ በእውነት ሊጠቀም የሚችለው ያንን ያህል ነው።
- **ዕለታዊ ገደቦች ይቀየራሉ፣ የፍጥነት ገደቦች ግን አይቀየሩም።** በሰነድ የተገለጸ የቶከኖች/ቀን ገደብ `× 30` ይሆናል፤ በሰነድ የተገለጸ የጥያቄዎች/ቀን ገደብ `RPD × ~800 tokens × 30` ይሆናል፤ በደቂቃ የሚፈቀዱ ጥያቄዎችን ብቻ የሚያትም አቅራቢ **ምንም** ወርሃዊ ቁጥር የለውም፣ እና _uncapped_ ተብሎ ይዘረዘራል፤ በድምሩም በፍጹም አይካተትም። የፍጥነት ገደብን በ24/7 ማባዛት እኛ የማንቀበለው ማጋነን ነው።
- **ከክልላዊ የማንነት ማረጋገጫ በስተጀርባ ያሉ ኮታዎች ለብቻቸው ይታያሉ** (`+~6M behind regional identity verification`)፣ ምክንያቱም አብዛኞቹ አንባቢዎች ሊጠቀሙባቸው አይችሉም።
- **የምዝገባ ክሬዲቶች ለመጀመሪያው ወር ብቻ ናቸው** እና ከቋሚው ቁጥር ጋር ፈጽሞ ሳይቀላቀሉ እንደ ሁለተኛ ቁጥር ይዘገባሉ።
- **ቁጥሩ በCI ይተገበራል።** `npm run check:docs-counts` ድምሮቹን ከካታሎጉ እንደገና ያሰላል፣ እና ይህ ፋይል፣ README ወይም የበጀት ካርዱ ከእነሱ ሲለይ buildን ያሰናክላል።

> **የToS ምልክት ምክር ሰጪ እንጂ የማዘዋወር መግቢያ በር አይደለም።** `tos` ምልክት የተደረገባቸው አቅራቢዎች በነባሪነት በማዘዋወር እና በጥምር/ተተኪ አማራጭ ውስጥ አሁንም ይካተታሉ፤ ምልክቱ የሚታየው በ`/dashboard/free-tiers` እና በ`/api/free-tier/summary` ላይ ብቻ ነው። የ`excludeTosAvoid` የጥያቄ መለኪያ የሚነካው የማጠቃለያ እይታውን ብቻ እንጂ አጠቃላይ ማዘዋወርን አይደለም። ውሳኔው በ`open-sse/config/freeTierCatalog.ts` ውስጥ ይገኛል (መረጃ ሰጪ ነው፣ በማዘዋወሪያ ሞተሮች አይነበብም)።

> በራስ ለሚስተናገድ፣ ለአንድ ተጠቃሚ የግል ፕሮክሲ የእያንዳንዱ አቅራቢ ውሎች አጭር ማብራሪያ። `caution` = ሊመረመር የሚገባው የግል አጠቃቀም ወይም የፕሮክሲ አንቀጽ፤ `ambiguous` = ግልጽ ያልሆነ፤ `ok` = በግልጽ የተፈቀደ። ይህ መረጃ ሰጪ እንጂ የሕግ ምክር አይደለም — ውሳኔው የእርስዎ ነው።
