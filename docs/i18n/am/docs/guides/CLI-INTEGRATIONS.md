OmniRoute የኮዲንግ CLI (Codex, Claude Code, OpenCode, Cline, …) OmniRouteን እንደ ባክኤንድ እንዲጠቀም የሚያዋቅሩ የ`setup-*` ትዕዛዞች ቤተሰብ ያቀርባል — ስለዚህ መሳሪያው ከአንድ **ነጠላ** የመጨረሻ ነጥብ ጋር ይነጋገራል እና OmniRoute ወደ ትክክለኛው አቅራቢ በራስ-ሰር ምትኬ (auto-fallback) ያዞራል. እያንዳንዱ ትዕዛዝ ከሚሰራ OmniRoute (አካባቢያዊ ወይም የርቀት) **ቀጥታ** ሞዴል ካታሎግ ያነባል እና የመሳሪያውን የራሱን የማዋቀሪያ ፋይል **በእርስዎ** ማሽን ላይ ይጽፋል. የኤፒአይ ቁልፉ መሳሪያው በሚደግፍበት ቦታ ሁሉ በአካባቢ ተለዋዋጭ (environment variable) ይጠቀሳል. የመሳሪያ-አካባቢያዊ የአካባቢ ፋይልን የሚያስቀምጡ ትዕዛዞች ከታች ተጠቅሰዋል.

አጠቃላይ አስጀማሪም አለ — `omniroute run <target>` — ትክክለኛው አካባቢ (env) ተወግሮበት `claude`, `codex`, `aider`, `goose`, `opencode`, `qwen` ወይም `gemini`ን የሚያስጀምር፣ ምንም አይነት ማዋቀር ሳይጽፍ. ኢላማዎች (Targets) እና ቅጽል ስሞቻቸው (aliases) ከዋናው ማኒፌስት `bin/cli/cli-manifest.mjs` (`claude-code|cc|anthropic`, `codex-cli|openai-codex|openai`, `goose-cli`, `open-code`, `qwen-code`, `gemini-cli`) ይመጣሉ፣ እና `omniroute completion` ተመሳሳይ በማኒፌስት የተገኙ ኢላማ ቃላትን ያቀርባል. የቆዩት የመሳሪያ-ለ-መሳሪያ አስጀማሪዎች — `omniroute launch` (Claude Code) እና `omniroute launch-codex` (Codex) — አሁንም ይገኛሉ.

የአቅራቢ ምዝገባ (onboarding) ከተመሳሳይ አካባቢያዊ/የርቀት አውድ (context) ይገኛል. ከታች ያሉት ኤፒአይ-መጀመሪያ ትዕዛዞች የአስተዳደር ማረጋገጫን ከአቅራቢ ምስክርነቶች (credentials) ይለያሉ እና በተዋቀረ ውፅዓት (structured output) ውስጥ ምስክርነትን በጭራሽ አያትሙም:

```bash
omniroute providers add glm --credential-env GLM_API_KEY --name work
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth openai
omniroute providers edit <connection-id> --default-model glm/glm-5.2
omniroute providers remove <connection-id> --yes
```

ለስክሪፕቶች፣ `--credential-stdin` ወይም `--credential-env`ን ይምረጡ; `--credential` ለቁጥጥር የሚደረግበት አካባቢያዊ አጠቃቀም ተይዟል. `providers remove` መስተጋብራዊ ባልሆነ ተርሚናል ላይ `--yes`ን ይፈልጋል፣ እና አምስቱም ትዕዛዞች ንቁውን አውድ (active context) ወይም ዓለም አቀፋዊውን `--base-url`/`--api-key` አማራጮችን ያከብራሉ.

የአቅራቢ መራጮች ግልጽ ያልሆኑ የመታወቂያ ቅድመ ቅጥያዎችን (ID prefixes)፣ ስሞችን ወይም የአቅራቢ ስሞችን አይቀበሉም; ብዙ ግንኙነቶች ሲዛመዱ ሙሉ የግንኙነት መታወቂያን ይጠቀሙ. የመፍጠር እና የማስተካከል ትዕዛዞች የተቀመጠውን ግንኙነት መልሰው ያነባሉ፣ እና ማስወገድ (removal) ከእንግዲህ ማንበብ እንደማይቻል ያረጋግጣል. ማስመጣት (import) ያለውን የአቅራቢ/ስም ጥንድ ይዘላል. የገቡ ግቤቶች (imported entries) ለCLI የቀረበውን የአስተዳደር የመጨረሻ ነጥብ (management endpoint)፣ አውድ (context) ወይም የአስተዳደር ምስክርነቶችን (management credentials) መሻር አይችሉም.

ለሁለቱ እጅግ የበለጸጉ ውህደቶች የአንድ ጊዜ፣ በእጅ የተጻፈ መሰረታዊ ማዋቀር፣ የመሳሪያ-ለ-መሳሪያ ጥልቅ ዳሰሳዎችን ይመልከቱ:

- [Claude Code ማዋቀር](./CLAUDE-CODE-CONFIGURATION.md)
- [Codex CLI ማዋቀር](./CODEX-CLI-CONFIGURATION.md)
- [የርቀት ሁነታ](./REMOTE-MODE.md) — የርቀት OmniRouteን (VPS / Tailnet) ከላፕቶፕዎ ያንቀሳቅሱ
- [VS Code Copilot Chat](./VSCODE-COPILOT.md) — የOmniCopilot ቅጥያ; እነዚህን `setup-*` ትዕዛዞች ከአርታዒው ውስጥ ለእርስዎ ማስኬድ ይችላል

| `omniroute setup-qwen`     | Qwen Code                   | `~/.qwen/settings.json` — የV4 `modelProviders.openai` ድርድር + `OMNIROUTE_API_KEY` በ `~/.qwen/.env` ውስጥ                                                     | `--remote` `--api-key` `--model` `--yes` `--dry-run` `--port` `--config-path` `--env-path`                                                 | ሁለቱም            |
| `omniroute setup-5dive`    | 5dive (የወኪሎች ስብስብ)          | በ `$HOME` ስር ምንም አይጽፍም — በ `5dive agent auth set` በኩል የ5dive **የማረጋገጫ መገለጫ** (`/var/lib/5dive/auth-profiles/<name>/`) ይጽፋል፤ root ብቻ፣ በስብስቡ አስተናጋጅ ላይ ይሠራል | `--remote` `--api-key` `--model` `--auth-profile` `--agent` `--byo-provider` `--fivedive-bin` `--no-sudo` `--yes` `--dry-run` `--port`     | ሁለቱም            |
| `omniroute run <target>`   | የአሂድ ጊዜ ማስጀመሪያ (አጠቃላይ)      | ምንም — `claude`/`codex`/`aider`/`goose`/`opencode`/`qwen`/`gemini`ን በትክክለኛዎቹ የአካባቢ ተለዋዋጮችና ነጋሪ እሴቶች ያስጀምራል፤ Qwen እና Gemini ጊዜያዊ የተነጠለ መነሻ ይጠቀማሉ            | `--remote` `--base-url` `--context` `--provider` `--model` `--api-key` `--api-key-env` `--dry-run` `--json` `--port` `--profile` `--token` | ሁለቱም            |
| `omniroute launch`         | Claude Code                 | ምንም — `ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN` በመክተት `claude`ን ያስጀምራል                                                                                  | `--remote` `--api-key` `--token` `--profile` `--port`                                                                                      | ሁለቱም            |
| `omniroute launch-codex`   | OpenAI Codex CLI            | ምንም — የ`omniroute` አቅራቢን በ `-c` ጥቆማዎች በመክተት `codex`ን ያስጀምራል                                                                                               | `--remote` `--api-key` `--profile` (`-p`) `--port`                                                                                         | ሁለቱም            |

የሰንደቅ አማራጮች ማስታወሻዎች (በትዕዛዙ ምንጭ ውስጥ የተረጋገጡ):

- `--remote <url>` — ካታሎጉን ከርቀት OmniRoute ያመጣል (`--port`ን
  እና ንቁውን አውድ ይሽራል)። `--api-key <key>` ለዚያ
  አገልጋይ ማረጋገጫ ያቀርባል (በነባሪ `OMNIROUTE_API_KEY` env varን፣ ወይም የንቁውን አውድ token ይጠቀማል)።
- `--only <patterns>` — በኮማ የተለያዩ ንዑስ ሕብረቁምፊዎች፤ የሚዛመዱ የሞዴል IDዎችን
  ብቻ ያስቀምጣል (ለምሳሌ `--only glm,kimi`)። በ`setup-codex`፣ `setup-claude`፣
  `setup-opencode`፣ `setup-continue`፣ `setup-cursor`፣ `setup-crush` ላይ ይገኛል።
- `--dry-run` — ፋይል ስርዓቱን ሳይነካ በትክክል ምን እንደሚጻፍ
  ያትማል። `setup-cursor`ን **በስተቀር** በሁሉም `setup-*` ትዕዛዞች ላይ ይገኛል
  (`setup-cursor` ፋይል ፈጽሞ አይጽፍም)።
- `--model <id>` — ራስ-ሰር የሞዴል ፍለጋ ለሌላቸው መሣሪያዎች
  ያስፈልጋል (ወይም በበይነገጽ ይመረጣል)፦ Cline፣ Kilo፣ Roo፣ Goose፣ Qwen፣ Aider፣ 5dive። እነዚያ መሣሪያዎች
  በይነገጽ ላልሆኑ አሂዶች `--yes`ንም ይቀበላሉ (በዚህ ጊዜ `--model` ያስፈልጋል)።
  `setup-opencode` ነባሪውን የከፍተኛ ደረጃ ሞዴል ለማዘጋጀት `--model`ን ይወስዳል።
- በ`omniroute run` ላይ ያለው `--model <id>` የmanifestን ለእያንዳንዱ target የተዘጋጀ ሽቦ-አገናኝ
  (`bin/cli/cli-manifest.mjs`) ይከተላል፦ **aider** `--model openai/<id>`ን እና
  **opencode** `--model omniroute/<id>`ን ይቀበላሉ (ቅድመ ቅጥያው የሚጨመረው IDው
  አስቀድሞ ካልያዘው ብቻ ነው)፤ **qwen** እና **gemini** IDውን እንዳለ ይቀበላሉ፤
  **claude** በ`ANTHROPIC_MODEL`፣ **goose** በ`GOOSE_MODEL`፣ እና
  **codex** በ`-c model_providers.omniroute.*` args ያገኙታል። **`--model`ን በግድ የሚፈልግ ብቸኛው run
  target Qwen ነው** — `omniroute run qwen` ያለዚህ ሲሄድ ግልጽ ስህተት አሳይቶ
  በ`2` ይወጣል።
- `--port <port>` — የአካባቢ OmniRoute port (ነባሪ `20128`፤ `--remote`
  ሲዘጋጅ ችላ ይባላል)። በሁሉም `setup-*` እና በሁለቱም launchers ላይ ይገኛል።
- የ`omniroute run` መውጫ ኮዶች፦ የልጅ CLIው የራሱ መውጫ ኮድ ምንም ሳይቀየር
  ይተላለፋል፤ `2` = ልክ ያልሆኑ arguments (የማይደገፍ target፣ የሚያስፈልገው
  `--model` የጎደለ፣ container guard)፤ `127` = የtarget binaryው በ`PATH` ውስጥ የለም፤
  `130`/`143`/`129` = launchው በ`SIGINT`/`SIGTERM`/`SIGHUP` ሲቋረጥ፤
  `1` = ሌላ የruntime launch ውድቀት።
- ሁለቱ launchers (`launch`፣ `launch-codex`) በ`setup-claude` / `setup-codex`
  የተጻፈ profileን ለመምረጥ `--profile <name>`ን፣ እንዲሁም ወደ መሠረታዊው
  `claude` / `codex` binary የሚተላለፉ argsን ይቀበላሉ።

በይነገጻዊው መራጭ በsetup recipesም ይጋራል፦

```bash
# ከንቁው የአካባቢ ወይም የርቀት ሞዴል ካታሎግ ይምረጡ እና targetን ያዋቅሩ።
omniroute configure claude
omniroute configure opencode --provider glm
omniroute configure qwen --model qwen/qwen3.8-max-preview --yes
```

`configure` በአሁኑ ጊዜ ለ`codex`፣ `claude`፣
`opencode`፣ `qwen`፣ `aider`፣ `goose`፣ `cline`፣ `continue`፣ `kilo`፣ እና `5dive` ወደተፈተኑት recipes ያስተላልፋል።
ለIDE ብቻ የሆኑ፣
MITM፣ እና ለመመሪያ ብቻ የሆኑ የካታሎግ ግቤቶች ግልጽ `setup-*`/በእጅ የሚከናወኑ flows ሆነው ይቀራሉ እና
እንደሚጀመሩ targets አይቀርቡም።

> `setup-opencode` **ቀላል openai-compatible** የOpenCode integration ነው።
> የበለጠ የተሟላ plugin integrationም አለ — `omniroute setup opencode` — ይህም
> `@omniroute/opencode-plugin`ን ይጭናል። እነዚህ የተለያዩ ትዕዛዞች ናቸው፤ ከላይ ያለው ሰንጠረዥ
> `setup-opencode`ን ይመዘግባል።
>
> ሁለቱ loaders የተለያዩ entrypoints ስለሚጠብቁ pluginው ለእያንዳንዱ ዋና የOpenCode ስሪት
> አንድ በሆኑ ሁለት packages ይመጣል፦
> `@omniroute/opencode-plugin` ለOpenCode v1 እና
> `@omniroute/opencode-plugin-v2` ለOpenCode v2። የv2 package አዲስ
> (`0.1.0`) ሲሆን ገና እየተቀየረ ያለ host contractን ይከተላል፤ ስለዚህ አንድ shape ከመገመት ይልቅ
> OpenCode ወደ catalog draft የሚያስገባውን shape ያነባል። ወደ`opencode.json` የ`plugins` ግቤት በመጨመር
> ይጫኑት፤ `omniroute setup opencode`
> አሁንም የv1 packageን ይጭናል። Options እና የcredential ፍለጋ ቅደም ተከተሉ
> በpackage README ውስጥ ይገኛሉ።

## የአካባቢ አጠቃቀም

OmniRoute በ`localhost:20128` ላይ እየሰራ ሳለ፣ ለመሣሪያዎ የማዋቀሪያ ትዕዛዙን ብቻ ያሂዱ። ካታሎጉ ከአካባቢያዊው አገልጋይ ይመጣል።

```bash
# Codex፦ ለእያንዳንዱ የተዛመደ ሞዴል በ~/.codex/ ውስጥ ፕሮፋይል ይጻፉ
omniroute setup-codex
codex --profile glm52            # የተፈጠረ ፕሮፋይል ይጠቀሙ

# Claude Code፦ ለየሞዴሉ ፕሮፋይሎችን ይጻፉ፣ ከዚያ አንዱን ያስጀምሩ
omniroute setup-claude
omniroute launch --profile glm52

# OpenCode፦ ሁሉንም የካታሎግ ሞዴሎች የያዘውን ከopenai ጋር ተኳሃኝ አቅራቢ ይጻፉ
omniroute setup-opencode
export OMNIROUTE_API_KEY=sk-...  # በ{env:OMNIROUTE_API_KEY} በኩል ይጠቀሳል፣ በዲስክ ላይ ፈጽሞ አይቀመጥም
opencode -m omniroute/glm/glm-5.2 "..."

# ራስ-ሰር ማግኘት የማይችሉ መሣሪያዎች ግልጽ ሞዴል ያስፈልጋቸዋል፦
omniroute setup-aider --model glm/glm-5.2
omniroute setup-qwen --model qwen/qwen3.8-max-preview

# ምንም ሳይጻፍ ቅድመ ዕይታ፦
omniroute setup-continue --dry-run
```

ምንም ውቅር ሳይጻፍ ያስጀምሩ (የአካባቢ ተለዋዋጭ ማስገባት ብቻ)፦

```bash
omniroute launch                 # Claude Code → አካባቢያዊ OmniRoute
omniroute launch-codex           # Codex CLI → አካባቢያዊ OmniRoute
omniroute launch-codex --profile glm52
omniroute run claude --model openai/gpt-5.4
omniroute run codex --model openai/gpt-5.4 --dry-run --json
omniroute run aider --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"
omniroute run qwen --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "reply OK"

# ግልጽ የትዕዛዝ መንገድ፦ ከ-- በኋላ ያለውን ማንኛውንም ነገር እንዳለ ያስተላልፉ
omniroute run claude -- --print-system-prompt "review this diff"
```

## የርቀት አጠቃቀም

ማንኛውንም የማዋቀሪያ ትዕዛዝ `--remote` + `--api-key` በመጠቀም ወደ ሩቅ OmniRoute ያመልክቱ። ካታሎጉ ከሩቅ ይመጣል፤ ውቅሩ ግን በአካባቢያዊ ማሽንዎ ላይ ይጻፋል።

```bash
# OpenCodeን ከሩቅ VPS ጋር ይጠቀሙ፣ glm/kimi ሞዴሎችን ብቻ ያቆዩ
omniroute setup-opencode --remote http://192.168.0.15:20128 --api-key oma_live_xxx \
  --only glm,kimi
opencode -m omniroute/glm/glm-5.2 "..."   # መጀመሪያ OMNIROUTE_API_KEYን export ያድርጉ

# ከሩቅ ካታሎግ የሚመጡ Codex ፕሮፋይሎች
omniroute setup-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# CLIን በቀጥታ ከሩቁ ጋር ያስጀምሩ
omniroute launch       --remote http://192.168.0.15:20128 --api-key oma_live_xxx
omniroute launch-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx
```

በእያንዳንዱ ጊዜ `--remote`/`--api-key`ን ከማስተላለፍ ይልቅ፣ አንድ ጊዜ ይግቡና **ንቁ አውዱ** በራስ-ሰር እንዲያቀርባቸው ያድርጉ፦

```bash
omniroute connect 192.168.0.15        # የተወሰነ ወሰን ያለው ቶከን ያመነጫል፣ አውዱንም ያከማቻል
omniroute setup-codex                 # ← አሁን የሩቁን ካታሎግ ይጠቀማል
omniroute setup-opencode              # ← ተመሳሳይ
omniroute launch                      # ← Claude Code ከሩቁ ጋር
```

ስለ አውዶች፣ ወሰኖች እና የቶከን አስተዳደር [የርቀት ሁነታ](./REMOTE-MODE.md)ን ይመልከቱ።

## የ5dive ወኪል መንጋዎች

[5dive](https://5dive.ai) ለረጅም ጊዜ የሚሰሩ የኮድ መጻፊያ ወኪሎችን መንጋ ያስኬዳል፤ እያንዳንዳቸውም በራሳቸው Unix ተጠቃሚ ስር ያሉ systemd ዩኒቶች ናቸው። እሱ ራሱ የኮድ መጻፊያ CLI አይደለም፣ ስለዚህ `omniroute run` የሚያስጀምረው ነገር የለም — `5dive` **ለማዋቀር-ብቻ** የታለመ ነው።

```bash
omniroute configure 5dive --model failover-demo --yes
omniroute setup-5dive --model failover-demo --auth-profile omniroute --agent worker1
```

ሁለቱም ቅጾች አንድ የ5dive **የማረጋገጫ ፕሮፋይል** ይጽፋሉ፣ ከዚያም ከዚያ ፕሮፋይል ጋር የተያያዘ እያንዳንዱ `claude` መቀመጫ ከOmniRoute ጋር ይገናኛል። ሦስት ነገሮች ለዚህ ዒላማ የተለዩ ናቸው፦

- **በመንጋው አስተናጋጅ ላይ እንደ root ይሰራል።** የ5dive ግሶች በአካባቢያዊ systemd ዩኒቶች እና root በሚቆጣጠረው የሁኔታ ማውጫ ላይ ይሰራሉ፤ የርቀት ሁነታ የለም። አሰራሩ አስቀድሞ root ካልሆነ በ`sudo` በኩል ራሱን እንደገና ያስኬዳል (`--no-sudo` ይህን ያሰናክላል እና በምትኩ ትዕዛዙን ያትማል)።
- **loopback ካልሆነ በስተቀር መጨረሻ ነጥቡ `https://` መሆን አለበት።** የወኪሉ API ቁልፍ በእያንዳንዱ ጥያቄ ላይ በዚያ URL በኩል ይጓዛል፣ እና 5dive ከማሽኑ ውጭ ያለ በግልጽ ጽሑፍ የሚተላለፍ መጨረሻ ነጥብን አይቀበልም። የግል LAN አድራሻም ልዩ ሁኔታ አይደለም።
- **የእያንዳንዱ መቀመጫ የራሱ የሞዴል ማጣበቂያ ከፕሮፋይሉ ይቀድማል።** ፕሮፋይሉ `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL`ን ይይዛል፣ ነገር ግን ከመደበኛ ሞዴል id ጋር አሁንም የተጣበቀ መቀመጫ በመጀመሪያ ዙሩ _"በተመረጠው ሞዴል ላይ ችግር አለ"_ በሚል መልዕክት ይወድቃል። መቀመጫዎቹንም ለማጣበቅ `--agent <name>`ን (ሊደገም የሚችል) ያስተላልፉ፤ ይህን ካላደረጉ አሰራሩ ትዕዛዙን ያትማል።

API ቁልፉ ለ5dive በ**stdin** (`--api-key=-`) ላይ ይሰጣል፣ ስለዚህ በ`ps` ውጤት ውስጥ ፈጽሞ አይታይም።

ፕሮፋይሉን ከአንድ ሞዴል ይልቅ ወደ OmniRoute **ጥምር** ማመልከት ለመንጋው የአቅራቢ መቀያየሪያን የሚያስገኘው ነው፦ በ[#11578](https://github.com/diegosouzapw/OmniRoute/issues/11578) ላይ በተመዘገበው አሂድ ወቅት ዋናው መጨረሻ ነጥብ በዙሩ መካከል ሙሉ በሙሉ ሲቋረጥ፣ ወኪሉ ቀሪ ደረጃዎቹን በመጠባበቂያው ላይ አጠናቀቀ እና መቋረጡን ለተጠቃሚው ፈጽሞ አላሳየም።

## በማዘመን ጊዜ ቤተኛ ጥገኞችን ማቆየት፦ `--include=optional`

በ`omniroute update` ሲያዘምኑ (ካረጋገጡ በኋላ፣ ወይም `--apply`ን በመጠቀም)፣
OmniRoute መጫኑን `--include=optional` በውስጡ ተካቶ ያስኬዳል፦

```bash
npm install -g omniroute@latest --include=optional
```

ይህ ወደ `omniroute update` የሚያስተላልፉት ጠቋሚ **አይደለም** — በአዘማኙ
ሁልጊዜ ይተገበራል። የnpm ውቅርዎ `omit=optional` ተብሎ የተዋቀረ ቢሆንም
`optionalDependencies` (`better-sqlite3`፣ `keytar`፣
`tls-client`፣ የLLMLingua SLM ቁልል) ከዝማኔው በኋላ እንዲቆዩ ዋስትና ይሰጣል፤ አለበለዚያ ቤተኛውን የSQLite
ሾፌርና የOS ቁልፍ-ማከማቻ ማሰሪያ ያለምንም ማሳወቂያ ይጥላቸዋል። ሳይተገበር ትክክለኛውን ትዕዛዝ አስቀድመው ለማየት፦

```bash
omniroute update --dry-run
# [ደረቅ ሙከራ] የሚከናወነው፦ npm install -g omniroute@latest --include=optional
```

ሌሎች የ`omniroute update` ጠቋሚዎች (በምንጩ የተረጋገጡ)፦ `--check` (ጊዜ ያለፈበት ከሆነ
በ1 ይወጣል)፣ `--apply` (ያለጥያቄ ይጭናል)፣ `--changelog`፣ `--no-backup`፣
`--yes`።

## Google Gemini CLI በ`omniroute run gemini` በኩል

ከ`@google/gemini-cli` 0.50.0 ጋር በማነጻጸር የተረጋገጠ ውል፦ CLIው
`GOOGLE_GEMINI_BASE_URL`ን ያከብራል፣ እና `POST /v1beta/models/<model>:generateContent`
(እና `:streamGenerateContent?alt=sse`)ን በእሱ ላይ ይልካል — ይህም በትክክል የOmniRoute ቤተኛ
Gemini በይነገጽ (`/v1beta`) ነው። `omniroute run gemini` ይህን በራስ-ሰር ያዋቅራል፦

- `GOOGLE_GEMINI_BASE_URL` → ገቢሩ የOmniRoute መሠረታዊ URL (ስር፣ `/v1` የሌለው)፤
- `GEMINI_API_KEY` → የተፈታው የOmniRoute ምስክርነት (አማራጭ/አካባቢ/ዐውድ)፤
- በ`.gemini/settings.json` ውስጥ `gemini-api-key` ማረጋገጫን የሚመርጥ
  **ጊዜያዊና የተነጠለ `GEMINI_CLI_HOME`**፤ ስለዚህ የተከማቸ የGoogle OAuth ክፍለ-ጊዜ (Code Assist)
  ወደ OmniRoute የተመራውን ማስጀመሪያ ፈጽሞ አይተካውም — ከመውጣት በኋላ ይወገዳል፤
- **የአካባቢ ንጽህና**፦ የልጅ ሂደቱ አካባቢ `GOOGLE_API_KEY`፣
  `GOOGLE_GENAI_USE_VERTEXAI` እና `GOOGLE_GENAI_USE_GCA`ን (ማረጋገጫውን
  ወደ Vertex/Code Assist የሚያዞሩ) በማስወገድ ይጸዳል፣ እና `GEMINI_DEFAULT_AUTH_TYPE=gemini-api-key`
  እንደ ተጨማሪ መጠባበቂያ ይዋቀራል — ሌሎቹ የ`run` ዒላማዎችም ለየራሳቸው የሚጋጩ
  ተለዋዋጮች ተመሳሳይ አያያዝ ያገኛሉ፤
- ከ`--provider`/`--model` የ`--model <id>` ማስገባት።

```bash
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "hello"
```

የGemini የሥራ-ቦታ እምነት ጥበቃ በራስ-አልባ ሁኔታም ይተገበራል — እርስዎ ራስዎ
`--skip-trust`ን ያስተላልፉ (ወይም ማውጫውን በመስተጋብራዊ ሁኔታ ያመኑ)፤ ማስጀመሪያው
ሆን ብሎ ይህን አያልፈውም። ይህ ማስጀመሪያ ከ**ACP
ምዝገባ** (`src/lib/acp/registry.ts`፣ `gemini --acp`) የተለየ ሲሆን፣ ይህም ለ
`/dashboard/acp-agents` የወኪል-ፕሮቶኮል ውህደት ሆኖ ይቀጥላል።

## እውነተኛ የsmoke ሙሉ ፍተሻ (በፈቃድ የሚነቃ)

ተመሳሳይ ውጤት የሚሰጥ የማስጀመሪያ ዕቅድ regression ሙከራ በCI (`tests/unit/cli/run-command.test.ts`,
`tests/unit/cli/run-execution.test.ts`) ውስጥ ይካሄዳል። እውነተኛዎቹን binaries ከእውነተኛ
OmniRoute server ጋር ለማረጋገጥ፣ በፈቃድ የሚነቃ harness በ
`tests/integration/upstream-cli-smoke.int.test.ts` ይገኛል። በራስ-ሰር ፈጽሞ አይካሄድም
(`RUN_CLI_SMOKE=1` ካልሆነ በስተቀር እያንዳንዱ ንዑስ ሙከራ ይዘለላል)፣ ማረጋገጫውን በenv-var
NAME ያስተላልፋል (በእሴቱ ፈጽሞ አይደለም)፣ በማንኛውም የተመዘገበ ውጤት ውስጥ ያሉ key-shaped ሕብረቁምፊዎችን ይደብቃል፣ binary ያልተጫነላቸውን
ዒላማዎች ይዘልላል፣ እንዲሁም ውድቀቶችን እንደ ቀላል boolean ከመመደብ ይልቅ በ
auth / upstream / config ይመድባል፦

```bash
RUN_CLI_SMOKE=1 \
OMNIROUTE_SMOKE_BASE_URL="http://localhost:20128" \
OMNIROUTE_SMOKE_MODEL="<provider/model>" \
OMNIROUTE_SMOKE_API_KEY_ENV="OMNIROUTE_API_KEY" \
node --import tsx/esm --test tests/integration/upstream-cli-smoke.int.test.ts
```

አማራጭ፦ `OMNIROUTE_SMOKE_TARGETS="codex,opencode,qwen"` ሙሉ ፍተሻውን ይገድባል፤
`OMNIROUTE_SMOKE_TIMEOUT_MS` ለእያንዳንዱ ዒላማ ያለውን የ120s የጊዜ ገደብ ይተካል።
