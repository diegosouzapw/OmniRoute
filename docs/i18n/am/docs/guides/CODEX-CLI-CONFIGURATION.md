Codex CLIን OmniRouteን እንደ OpenAI-ተኳሃኝ backend በመጠቆም ለመጠቀም የተሟላ መመሪያ።

---

> **TOML ብቸኛው ውጤታማ ቅርጸት ነው።** ዘመናዊው Codex `~/.codex/config.toml`ን
> ብቻ ያነባል (በ codex-cli 0.147.0 የተረጋገጠ፦ `codex --help`
> የ`-c/--config` መሻሮች “ከ`~/.codex/config.toml` የተጫነ” መሆኑን ይገልጻል)። የድሮው
> `~/.codex/config.yaml` የቀድሞው npm CLI ነበር እና ያለምንም ማሳወቂያ ችላ ይባላል።
> የdashboard ማመንጫው (`/api/cli-tools/apply`፣ መሣሪያ `codex`) TOMLን
> ጥንቃቄ በተሞላበት ውህደት ይጽፋል — ነባር ቁልፎች እና ሌሎች የprovider ብሎኮች ይጠበቃሉ፣
> የAPI ቁልፉ በ`OMNIROUTE_API_KEY` ውስጥ ይቆያል (ፈጽሞ በፋይሉ ውስጥ አይቀመጥም)፣ እና የቀረ
> የቀድሞ `config.yaml` ሳይነካ እንደ የሽግግር ማስታወሻ ሪፖርት ይደረጋል።

## በቀጥታ ለመለጠፍ ዝግጁ የሆነ config.toml

`<YOUR_HOST>` እና `<YOUR_KEY>`ን በእርስዎ እሴቶች ይተኩ፦

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # ለእያንዳንዱ የመሣሪያ ጥሪ የታሪክ ማከማቻ ገደብ

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc ወይም ~/.zshrc — ትክክለኛው የቁልፍ እሴት፣ ፈጽሞ በ config.toml ውስጥ አይቀመጥም
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS፦ በChatGPT መተግበሪያ ውስጥ የታሸገ Codex

Codexን በChatGPT ዴስክቶፕ መተግበሪያ በኩል ከጫኑት፣ የ`codex` binaryው
በመተግበሪያው bundle ውስጥ ብቻ ሊኖር እና ገና በshell `PATH`ዎ ላይ ላይኖር ይችላል።
የresources ማውጫውን ወደ shell ማስጀመሪያ ፋይልዎ ያክሉ፦

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

አዲስ shell ይክፈቱ፣ ከዚያ ያረጋግጡ፦

```bash
command -v codex
codex --version
```

### ማረጋገጫ የማይፈልግ አካባቢያዊ OmniRoute፦ የplaceholder ቁልፍ በቂ ነው

Codex የመጀመሪያው ጥያቄ ከCLIው ከመውጣቱ **በፊት**
በ`env_key` የተጠቀሰው environment variable መኖሩን ያረጋግጣል። **አካባቢያዊው**
የOmniRoute instanceዎ auth የማይፈልግ ከሆነ፣ ባዶ ያልሆነ ማንኛውም placeholder ይሠራል፦

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

የOmniRoute serverዎ የተጠበቀ ወይም የርቀት ከሆነ በምትኩ እውነተኛ ቁልፍ ይጠቀሙ።

> **የተለመዱ የhost አማራጮች**
>
> | መዳረሻ            | URL                           |
> | --------------- | ----------------------------- |
> | አካባቢያዊ አውታረ መረብ | `http://192.168.0.1:20128/v1` |
> | Tailscale       | `http://100.x.x.x:20128/v1`   |
> | Loopback        | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — ለሁሉም models የሚሠራው ለምንድን ነው

Codex CLI `wire_api = "chat"`ን (Chat Completions) በFebruary 2026 ከአገልግሎት ውጪ አድርጎታል፣ እና አሁን `wire_api = "responses"`ን (OpenAI Responses API) **ይጠይቃል**። `wire_api = "chat"`ን ማዋቀር ከv0.138 ጀምሮ ሲጀመር ወዲያውኑ crash እንዲያደርግ ያስከትላል።

GLM እና Kimiን ጨምሮ ብዙ providers አሁንም የChat Completions endpoint ብቻ ያቀርባሉ። DeepSeek V4 አሁን ከAnthropic-ተኳሃኝ endpoint ጋር ተወላጅ Responses APIንም ያቀርባል፤ OmniRoute Responsesን በነባሪነት ይጠቀማል፣ እና እያንዳንዱ DeepSeek connection የAnthropic ተኳሃኝነትን እንዲመርጥ ያስችለዋል።

**OmniRoute ይህን ያለማስታወቂያ ይፈታዋል፦**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute የproviderውን ተወላጅ protocol ይመርጣል፣ አስፈላጊ ሲሆንም ይተረጉማል
    → POST /responses (DeepSeek V4) ወይም /chat/completions (Mistral / GLM / Kimi / ሌሎች)
```

OmniRouteን ሲጠቀሙ የተለየ translation proxy ፈጽሞ አያስፈልግዎትም። **ሁሉም models `wire_api = "responses"`ን ይጠቀማሉ** — OmniRoute ቀሪውን ያስተናግዳል።

> **`wire_api` ነባሪው ነው** — fieldው በነባሪነት `"responses"` ስለሚሆን ከ`config.toml` ሙሉ በሙሉ ሊቀር ይችላል። ዓላማውን እየመዘገቡ ከሆነ ብቻ በግልጽ ያዋቅሩት።

## የአውድ መስኮት እና ማጠቃለል

### የቶከን ውቅር መስኮች

| መስክ                              | መግለጫ                                                                                                                                 |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `model_context_window`           | ለገቢር ሞዴሉ አጠቃላይ የቶከን በጀት። ሞዴሉ በይፋ ባስታወቀው ገደብ ላይ ያዘጋጁት።                                                                                |
| `model_auto_compact_token_limit` | የታሪክ ራስ-ሰር ማጠቃለልን የሚያስጀምር ገደብ። **ከፍተኛው፦ ከ`model_context_window` 90%** — ከ90% በላይ ያሉ እሴቶች ያለማሳወቂያ ችላ ይባላሉ።                            |
| `tool_output_token_limit`        | በታሪክ ውስጥ ለእያንዳንዱ የመሣሪያ ጥሪ ውጤት የሚከማቹ ቶከኖች ገደብ። አንድ ትልቅ የመሣሪያ ምላሽ መስኮቱን እንዳይሞላ ይከላከላል። **ይህ ከፍተኛው የውጤት መጠን አይደለም** — የታሪክ ማከማቻ ገደብ ነው። |
| `compact_prompt`                 | በማጠቃለል ወቅት ጥቅም ላይ ለሚውለው የስርዓት መጠየቂያ የመስመር ውስጥ መሻሪያ (v0.138+)።                                                                        |

> **ስለ `model_max_output_tokens` ማስታወሻ**፦ ይህ መስክ **የCodex CLI ውቅር መርሃግብር አካል አይደለም** (በCodex Rust ኮድ ማከማቻ ውስጥ የለም)። ከተዘጋጀ ያለማሳወቂያ ችላ ይባላል። በእሱ ላይ አይመኩ — በታሪክ ውስጥ የሚከማቸውን የመሣሪያ ውጤት መጠን ለመቆጣጠር `tool_output_token_limit`ን ይጠቀሙ።

## የማመዛዘን ጥረት

ሞዴሉ ምላሽ ከመስጠቱ በፊት ምን ያህል "እንደሚያስብ" ይቆጣጠራል።

| እሴት      | የአጠቃቀም ዓላማ                        |
| -------- | --------------------------------- |
| `none`   | ምንም ማመዛዘን የለም — ቀጥተኛ ምላሽ          |
| `low`    | ቀላል ተግባራት (ዳግም መሰየም፣ ቅርጸት ማስተካከል) |
| `medium` | ካልተገለጸ **የአገልጋይ ነባሪ**             |
| `high`   | መካከለኛ ተግባራት (ኮድን መልሶ ማዋቀር፣ ማረም)   |
| `xhigh`  | ሥነ ሕንፃ፣ ጥልቅ ትንተና፣ ውስብስብ ችግሮች      |

```bash
# ለእያንዳንዱ ጥሪ መሻር
codex -c model_reasoning_effort=low "ተለዋዋጭ xን ወደ count ዳግም ሰይም"
codex -c model_reasoning_effort=xhigh "የauth ሞጁሉን ንደፍ"
```

Desktop የሐሳብ ጽሑፍን (የተመሰጠሩ ብሎቦችን ብቻ ሳይሆን) ማሳየት እንዲችል የማመዛዘን **ማጠቃለያ** ያዘጋጁ፦

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # ወይም በሚደገፍበት ጊዜ ultra
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### የOmniRoute የማሰብ በጀት (የአገልጋይ ቅንብር)

በOmniRoute አስተናጋጅ ላይ ያለው **Settings → AI → Thinking Budget** የCodex ጥረት/ማጠቃለያ ወደ ላይኛው አቅራቢ እንዲደርስ **`passthrough`** መሆን አለበት። **`auto` ሁነታ** ሁሉንም የደንበኛ `reasoning` / `reasoning_effort` መስኮች ያስወግዳል፣ እና Codex በትክክል ቢዋቀርም የማሰብ ፓነሎችን ባዶ ያደርጋል።

ሙሉ መመሪያ፦ [THINKING_BUDGET.md](./THINKING_BUDGET.md)።

መጭመቅ እና የጥያቄ መሸጎጫ እርስ በርሳቸው የማይያያዙ ሲሆኑ፣ በ`passthrough` ስርም መሥራታቸውን ይቀጥላሉ።

## በ`omniroute setup-codex` ፕሮፋይሎችን በራስ-ሰር ማመንጨት

OmniRouteን በVPS ላይ ካስኬዱ፣ ከቀጥታ የሞዴል ካታሎጉ የፕሮፋይል ፋይሎችን በራስ-ሰር ማመንጨት ይችላሉ፦

```bash
# ከVPS (በፖርት 20128 ላይ ያለውን አካባቢያዊ OmniRoute ይጠቀማል)
omniroute setup-codex

# ከማንኛውም ማሽን — ወደ VPSዎ ያመልክቱ
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# ፋይሎችን ሳይጽፉ ቅድመ-ዕይታ
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# የGLM እና Kimi ፕሮፋይሎችን ብቻ ያመንጩ
omniroute setup-codex --only glm,kimi

# ወደ ብጁ ማውጫ ይጻፉ
omniroute setup-codex --codex-home /path/to/.codex
```

ትዕዛዙ `/v1/models`ን ያመጣል፣ ለሚታወቁ ሞዴሎች የተስተካከሉ ፕሮፋይሎችን ይጠቀማል፣ ለሌሎች ተኳዃኝ የጽሑፍ ሞዴሎች ደግሞ ወደ ካታሎግ ሜታዳታ ይመለሳል፤ ለእያንዳንዱም `~/.codex/<name>.config.toml`ን ይጽፋል። ኢደምፖተንት ነው — እንደገና ማስኬድ ደህንነቱ የተጠበቀ ነው።

OmniRoute የአቅራቢ ሞዴል ማግኘት/ማስመጣት ቀጥታ ካታሎጉን በተሳካ ሁኔታ ከቀየረ በኋላ እነዚህን ተመሳሳይ የፕሮፋይል ፋይሎች **በራስ-ሰር ማመሳሰል**ም ይችላል። ይህ **በምርጫ የሚነቃ ሲሆን በነባሪነት ጠፍቷል**፦ ከ**CLI Code ዳሽቦርድ** ("CLI profile auto-sync" → Codex) ያብሩት፣ ወይም `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true`ን ያዘጋጁ (`CLI_ALLOW_CONFIG_WRITES`ንም ያከብራል፤ ይህም በነባሪነት በርቷል)። ሲነቃ የተለዩ `~/.codex/*.config.toml` የፕሮፋይል ፋይሎችን ብቻ ይጽፋል፤ ንቁ/ነባሪውን `~/.codex/config.toml`፣ የCodex-lb ቅንብሮችን፣ ማረጋገጫን ወይም የአቅራቢ ምርጫን በፍጹም አይቀይርም።

## Codexን በ`omniroute launch-codex` ማስጀመር

Codexን ከማስጀመሩ በፊት የOmniRoute ኢንስታንስዎን የጤና ሁኔታ ይፈትሻል፦


## ለረጅም ጊዜ የሚሄዱ ተግባራት

ሁለት የOmniRoute ነባሪ ቅንብሮች ለብዙ ሰዓታት የሚቆዩ የCodex CLI ክፍለ ጊዜዎችን በድብቅ ሊያበላሹ ይችላሉ። አንዳቸውም የCodex CLI ቅንብር አይደሉም — ሁለቱም በOmniRoute በኩል ይገኛሉ። መለያዎችን ከሚያጣብቁ እና የስራ-ፈት ጊዜ ማቋረጫዎችን ከሚያሰናክሉ የላይኛው ዥረት ፕሮክሲዎች ውቅርን የሚያዛውሩ ተጠቃሚዎች ብዙውን ጊዜ ሁለቱንም ችግሮች ያጋጥማቸዋል እና OmniRoute “ረጅም ክፍለ ጊዜን ማስቀጠል አይችልም” ብለው ይደመድማሉ።

| ምልክት                                                             | ሊሆን የሚችለው ምክንያት                                            | ማስተካከያ                   |
| ---------------------------------------------------------------- | ---------------------------------------------------------- | ------------------------ |
| ክፍለ ጊዜው መለያዎችን መቀያየሩን ይቀጥላል / በዙሮች መካከል የprompt-cache ቀጣይነት ይጠፋል | የክፍለ ጊዜ ቁርኝት TTL `0` ነው (ተሰናክሏል)                           | `sessionAffinityTtlMs`   |
| ለደንበኛው የሚታይ ማሳወቂያ ሳይኖር ግንኙነቱ በማመዛዘን መሃል ይቋረጣል                    | ከላይኛው ዥረት ምንም ቁራጭ ሳይመጣ ከ10 ደቂቃ በኋላ የዥረት ስራ-ፈት ተቆጣጣሪው ተነስቷል | `STREAM_IDLE_TIMEOUT_MS` |

ተዛማጅ ውይይቶች፦ [#7126](https://github.com/diegosouzapw/OmniRoute/discussions/7126) (የረጅም ተግባር መቋረጦች)፣ [#5718](https://github.com/diegosouzapw/OmniRoute/discussions/5718) (ቁርኝት በነባሪ የሚጠፋበት ምክንያት)። ክትትል፦ [#7287](https://github.com/diegosouzapw/OmniRoute/issues/7287)።

### 1. የክፍለ ጊዜ ቁርኝት — አንድን ውይይት ከአንድ መለያ ጋር ማጣበቅ

**ነባሪ፦** `sessionAffinityTtlMs = 0` (ተሰናክሏል)።

**የሚዋቀርበት ቦታ**

- ዳሽቦርድ → **ቅንብሮች → ማዞሪያ** → **የክፍለ ጊዜ ቁርኝት** → **የቁርኝት TTL (ሰከንዶች)** (`ComboDefaultsTab`)
- ወይም ቅንብሮችን በ`sessionAffinityTtlMs` እና **ሚሊሰከንዶች** በመጠቀም PATCH ያድርጉ (የZod ክልል `0`–`86_400_000`፣ ማለትም እስከ 24 ሰዓታት)

> በ#7274 ውስጥ ከCodex-ብቻ `codexSessionAffinityTtlMs` ስሙ ተቀይሯል። የቀድሞው ቁልፍ አሁንም እንደ ለንባብ-ብቻ ተለዋጭ ስም ተቀባይነት አለው፤ አዳዲስ ውቅሮች `sessionAffinityTtlMs`ን መጠቀም አለባቸው። አሁን TTL ከ`0` በላይ ከሆነ ቁርኝት በCodex ብቻ ሳይሆን በ**ማንኛውም** አቅራቢ ላይ ይተገበራል — [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → የክፍለ ጊዜ ቁርኝትን ይመልከቱ።

**በ0 ላይ ሲቆይ የሚበላሸው ነገር**

ባለብዙ ዙር የCodex ውይይት እያንዳንዱ ዙር በንቁው የcombo ስትራቴጂ በተናጥል ይመራል እና በ**እያንዳንዱ ዙር የተለየ መለያ** ላይ ሊደርስ ይችላል። ይህም የላይኛው ዥረት ክፍለ ጊዜ / የprompt-cache ቀጣይነትን ያቋርጣል። OmniRoute የCodex ክፍለ ጊዜ ራስጌዎችን (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) እና እንደ `prompt_cache_key` / `session_id` ያሉ የbody መስኮችን የሚመለከተው TTL ከ`0` በላይ ሲሆን ብቻ ነው (`extractSessionAffinityKey` በ`src/sse/services/auth.ts` ውስጥ)።

**ለብዙ ሰዓታት ለሚቆይ ነጠላ ተግባር የሚመከር**

TTLን **ከተግባሩ ከሚጠበቀው የጠቅላላ የሰዓት ርዝመት በላይ** ያዘጋጁ (የUI ከፍተኛው **86400 ሰከንዶች** = 24 ሰዓታት ነው)፦

| የሚጠበቀው የተግባር ርዝመት | የቁርኝት TTL (UI፣ ሰከንዶች) | `sessionAffinityTtlMs` |
| ----------------- | --------------------- | ---------------------- |
| ጥቂት ሰዓታት          | `14400` (4h)          | `14400000`             |
| ሌሊቱን ሙሉ / ~12h    | `43200` (12h)         | `43200000`             |
| ሙሉ ቀን             | `86400` (24h፣ ከፍተኛው)  | `86400000`             |

መርጦ መግባት ሆን ተብሎ የተደረገ ነው፦ ቁርኝትን ማሰናከል በመለያዎች መካከል የጭነት ማመጣጠንን ይደግፋል፤ ማንቃት ደግሞ ለአንድ ረጅም የወኪል ክፍለ ጊዜ ቀጣይነትን ይደግፋል። ይህ መመሪያ ነባሪውን **አይለውጥም** — ረጅም የCodex ተግባራትን የሚያስኬዱ ኦፕሬተሮች መርጠው መግባት አለባቸው።

### 2. የዥረት ስራ-ፈት ጊዜ ገደብ — ጸጥ ያሉ የማመዛዘን ዙሮችን አታቋርጡ

**ነባሪ፦** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 ደቂቃዎች)። ካልተዋቀረ `REQUEST_TIMEOUT_MS`ን ይወርሳል፤ የጋራው መነሻ መስመርም 600000 ነው። [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → የጊዜ ገደቦችን ይመልከቱ።

**በነባሪው ላይ የሚበላሸው ነገር**

ከ10 ደቂቃዎች በላይ **ምንም እውነተኛ upstream chunk ሳይኖር** ዝም ብሎ የሚቆይ የCodex reasoning / tool turn በSSE idle watchdog (`open-sse/utils/stream.ts`) በግድ ይዘጋል። ደንበኛው ብዙውን ጊዜ ምንም መልዕክት ሳይኖር ግንኙነቱ ሲቋረጥ ብቻ ያያል — ይህም “ምንም ማሳወቂያ ሳይኖር በራስ-ሰር ቆመ” ከሚለው ጋር ይዛመዳል።

ወሳኝ ዝርዝር፦ የOmniRoute ሰው ሠራሽ SSE **heartbeat የidle ሰዓት ቆጠራውን ዳግም አያስጀምርም**። `lastChunkTime`ን የሚያዘምነው እውነተኛ upstream body chunk ብቻ ነው። አሁንም “እያሰበ” ያለ ጸጥ ያለ ሞዴል፣ ከwatchdog እይታ አንጻር ከቆመ upstream ጋር ተመሳሳይ ይመስላል።

ተዛማጅ የUndici body inactivity፦ `FETCH_BODY_TIMEOUT_MS` (ይህም በነባሪ ተመሳሳዩን የ10 ደቂቃ መነሻ ይጠቀማል፤ `0` ያሰናክለዋል)። ለstreaming፣ `FETCH_TIMEOUT_MS` የሚሸፍነው የግንኙነት ማዋቀርን / የመጀመሪያ headersን ብቻ ነው — streamው ንቁ ከሆነ በኋላ፣ መቆም የሚተዳደረው በ`STREAM_IDLE_TIMEOUT_MS` እና `FETCH_BODY_TIMEOUT_MS` ነው።

**ለብዙ ሰዓታት የሚቆይ አንድ ተግባር የሚመከር**

በOmniRoute process environment (`.env` / compose / systemd) ውስጥ፦

```bash
# ለረጅም reasoning turns የstream idle + body inactivity ማቋረጫዎችን ያሰናክሉ
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

ወይም ከሚጠብቁት ረጅሙ የጸጥታ ክፍተት በላይ ያድርጓቸው (እሴቶቹ በሚሊሰከንድ ናቸው)፦

```bash
# ምሳሌ፦ በupstream chunks መካከል እስከ 2 ሰዓታት የሚደርስ ጸጥታን ይፍቀዱ
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

እነዚህን env vars ከቀየሩ በኋላ OmniRouteን ዳግም ያስጀምሩ።

### ተግባራዊ የአሠራር ዘዴ — የብዙ ሰዓታት Codex ተግባር

1. **መለያውን ይሰኩ፦** Dashboard → Settings → Routing → Session affinity → Affinity TTL = `43200` (12h) ወይም `86400` (ከፍተኛው 24h)።
2. በOmniRoute environment ውስጥ **የidle ማቋረጫዎችን ያሳድጉ / ያሰናክሉ**፦

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. የተለመደውን Codex `config.toml` (`wire_api = "responses"`፣ ትክክለኛ `base_url`፣ `OMNIROUTE_API_KEY`) ያቆዩ — ለእነዚህ ሁለት ባህሪያት በCodex በኩል ያሉ affinity/idle knobs የሉም።
4. OmniRouteን ዳግም ያስጀምሩ፣ ከዚያም ረጅሙን Codex ተግባር ይጀምሩ።

### የነባሪ ቅንብሮች ውሳኔ (#7287)

| Knob                     | የሚላከው ነባሪ         | በዚህ መመሪያ ውስጥ ይቀየር?                                                                  |
| ------------------------ | ----------------- | ----------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (ጠፍቷል)        | **አይ** — በምርጫ የሚነቃ ሆኖ ይቀጥላል (load-balancing እና continuity፤ Discussion #5718ን ይመልከቱ) |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 ደቂቃ) | **አይ** — ለአጠቃላይ traffic 10 ደቂቃ ሆኖ ይቀጥላል፤ የረጅም Codex ኦፕሬተሮች ያሳድጉታል ወይም ያሰናክሉታል       |

ከሁለቱ ነባሪዎች አንዱን በዓለም አቀፍ ደረጃ መቀየር፣ የCodexን ብቻ ሳይሆን የአንድ instanceን እያንዳንዱን client ባህሪ ይቀይራል። knobsን በሰነድ ይግለጹ፤ ግልጽ የoperator ውሳኔ ሌላ እስኪል ድረስ ነባሪዎቹን እንዳሉ ይተዉ።

### የidle መቋረጦችን መመርመር

idle watchdog ሲነሳ፣ OmniRoute እንደሚከተለው የተቀረጸ መስመር log ያደርጋል፦

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

`Idle timeout: no data from`ን (ወይም code `stream_idle_timeout`ን / error name `StreamIdleTimeoutError`ን) grep ያድርጉ። provider segment ማለት OmniRoute ለዚያ request የተጠቀመው ማንኛውም ነገር (`codex`፣ ሌላ provider id፣ ወይም የማይታወቅ ከሆነ `provider`) ነው — ሁልጊዜ ቃል በቃል `codex` አይደለም።

## የችግኝ መፍቻ

**`Error: wire_api = "chat" is no longer supported`**
ከውቅርዎ ውስጥ `wire_api = "chat"`ን ያስወግዱ። `wire_api = "responses"`ን ያዘጋጁ ወይም መስኩን ይተዉት (ከv0.138 ጀምሮ ነባሪው `"responses"` ነው)።

**`Error: model not found`**
ሞዴሉ በትክክለኛው ቅድመ ቅጥያ በOmniRoute ውስጥ መኖሩን ያረጋግጡ። `omniroute models list`ን ይጠቀሙ ወይም `/dashboard/providers/<provider>`ን ይክፈቱ።

**`Authentication error`**
`OMNIROUTE_API_KEY` ወደ አካባቢ ተለዋዋጭነት መላኩን ያረጋግጡ፦ `echo $OMNIROUTE_API_KEY`።

**`ERROR: Missing environment variable: OMNIROUTE_API_KEY`**
Codex የመጀመሪያውን ጥያቄ ከመላኩ በፊት የአካባቢ ተለዋዋጩ መኖሩን ያረጋግጣል። ለተጠበቁ ሰርቨሮች እውነተኛ ቁልፍ ወደ አካባቢው ይላኩ፤ ወይም **አካባቢያዊው** OmniRoute ምሳሌዎ ማረጋገጫ የማይፈልግ ከሆነ፣ እንደ `OMNIROUTE_API_KEY=local` ያለ ባዶ ያልሆነ ጊዜያዊ እሴት ይጠቀሙ። ይህን ወደ `~/.bashrc` ወይም `~/.zshrc` ካከሉት ሼሉን እንደገና ያስጀምሩ።

**`Connection refused`**
OmniRoute እየሰራ መሆኑን እና የ`base_url` አስተናጋጅ/ወደብ ለአውታረ መረብዎ (አካባቢያዊ፣ Tailscale ወይም VPS) ትክክል መሆኑን ያረጋግጡ።

**ክፍለ ጊዜው የአውድ ገደቡ አቅራቢያ ይቋረጣል**
`model_context_window`ን እና `model_auto_compact_token_limit`ን በግልጽ ያዘጋጁ። ከላይ ያለውን የአውድ መስኮት ሰንጠረዥ ይመልከቱ።

**ማጠቃለሉ በጣም ዘግይቶ ይጀምራል**
`model_auto_compact_token_limit`ን ወደ 80–85% የመስኮቱ መጠን ዝቅ ያድርጉ። ከ90% በላይ በፍጹም አያዘጋጁት።

**መገለጫው አይጫንም (`-p <name>` ያለማስጠንቀቂያ ችላ ይባላል)**
ፋይሉ በ`~/.codex/<name>.config.toml` (`profile-` ቅድመ ቅጥያ ሳይኖረው) መኖሩን ያረጋግጡ። `ls ~/.codex/*.config.toml`ን ያስኪዱ።

**ረጅም የCodex ተግባር በመሃል ይቋረጣል / በዙሮች መካከል መለያዎችን ይቀይራል**
[ረጅም ጊዜ የሚሰሩ ተግባራት](#long-running-tasks)ን ይመልከቱ። የክፍለ ጊዜ ቁርኝትን (TTL ከተግባሩ ቆይታ በላይ ሆኖ) ያንቁ እና `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS`ን ይጨምሩ ወይም ያሰናክሉ። በOmniRoute ምዝግቦች ውስጥ `Idle timeout: no data from`ን በgrep ይፈልጉ።
