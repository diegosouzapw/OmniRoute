## ምንድን ነው

OmniRoute **ነፃ/ማረጋገጫ-የማይፈልጉ** ተብለው ምልክት የተደረገባቸውን 155 የካታሎግ ግቤቶች ጨምሮ 329 አቅራቢዎችን ይመዘግባል
(ማረጋገጫ-የማይፈልጉ፣
የነፃ ደረጃ OAuth፣ ወይም የነፃ ደረጃ API ቁልፍ — የ
[ነፃ ደረጃዎች መመሪያ](../getting-started/FREE-TIERS-GUIDE.md) እና ሙሉውን
[የነፃ ደረጃዎች ማውጫ](../reference/FREE_TIERS.md) ይመልከቱ)። ችግሩ፦ የነፃ አቅራቢዎች የሞዴል ጥራት
እጅግ ይለያያል። የዘመኑን እጅግ የላቀ ሞዴል የሚያቀርብ ማረጋገጫ-የማይፈልግ አቅራቢ፣
አነስተኛ የቆየ ሞዴል ከሚያቀርብ አቅራቢ እጅግ የበለጠ ጠቃሚ ነው።

**የነፃ አቅራቢዎች ደረጃ** የእያንዳንዱን ነፃ አቅራቢ ካታሎግ ከ
**Arena AI የደረጃ ሰንጠረዥ** በተገኙ **በማኅበረሰብ የተሰበሰቡ የጥራት ውጤቶች** ጋር በማጣመር
"**ምርጡን ሞዴል የሚሰጠኝ የትኛው ነፃ አቅራቢ ነው?**" ለሚለው ጥያቄ መልስ ይሰጣል
(በሰው ምርጫ ላይ የተመሠረተ ELO፣ ከLMArena
የቻትቦት መወዳደሪያ ጀርባ ካለው ሐሳብ ጋር ተመሳሳይ)። ከዚያም አቅራቢዎቹ በ**ምርጥ ነፃ ሞዴላቸው** ጥንካሬ መሠረት ደረጃ ያገኛሉ።

ደረጃው የሚሰላው ከሦስት እውነተኛ ምንጮች ነው፦

1. የነፃ አቅራቢዎች ዝርዝሮች — `NOAUTH_PROVIDERS`፣ እንዲሁም `hasFree` ምልክት የተደረገባቸው `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` ግቤቶች
   (`src/shared/constants/providers.ts`)።
2. ከአቅራቢ መዝገቡ የተገኘው የእያንዳንዱ አቅራቢ የሞዴል ካታሎግ
   (`open-sse/config/providerRegistry.ts`)።
3. በArena ELO ማመሳሰያ ሞተር (`src/lib/arenaEloSync.ts`) ውስጥ ባለው `model_intelligence` DB ሰንጠረዥ
   የተከማቹ ከELO የተወሰዱ የተግባር-ተስማሚነት ውጤቶች።

የማጣመሪያው አመክንዮ `src/lib/freeProviderRankings.ts` ውስጥ ይገኛል።

## እንዴት መድረስ እንደሚቻል

### የዳሽቦርድ ገጽ

ዳሽቦርዱን ይክፈቱና ወደ **ወጪዎች → የነፃ አቅራቢዎች ደረጃ** ይሂዱ፣ ወይም በቀጥታ ወደዚህ ይሂዱ፦

```
/dashboard/free-provider-rankings
```

ገጹ (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) የሚከተሉትን ያሳያል፦

- ደረጃቸው ከፍተኛ የሆኑትን ሦስት ነፃ አቅራቢዎች የሚያሳይ **ከፍተኛ-3 መድረክ** (🥇 🥈 🥉)።
- የሚከተሉት ዓምዶች ያሉት ሙሉ **የደረጃ ሰንጠረዥ**፦ **ደረጃ**፣ **አቅራቢ**፣ **ከፍተኛ ሞዴል**፣
  **ውጤት**፣ **አማካይ ውጤት**፣ **ሞዴሎች**፣ **ዓይነት**።
- **የምድብ ማጣሪያ አዝራሮች**፦ _ሁሉም ምድቦች_፣ _ነባሪ_፣ _ኮድ መጻፍ_፣ _ግምገማ_፣
  _ሰነድ ማዘጋጀት_፣ _ስህተት ማረም_።

የእያንዳንዱ አቅራቢ **ዓይነት** ባጅ አገልግሎቱ በምን መንገድ ነፃ እንደሆነ ያሳያል፦

| ባጅ       | ትርጉም                                 |
| -------- | ------------------------------------ |
| `NOAUTH` | ሁልጊዜ ነፃ፣ ምንም የመግቢያ ማረጋገጫ አያስፈልግም     |
| `OAUTH`  | ነፃ ደረጃ (`hasFree`) ያለው OAuth አቅራቢ    |
| `APIKEY` | ነፃ ደረጃ (`hasFree`) ያለው የAPI ቁልፍ አቅራቢ |

ውጤቶች ከጥሬ ቁጥሮች ይልቅ ለሰው በሚገቡ መለያዎች (ለምሳሌ _እጅግ የላቀ_፣ _በጣም ጥሩ_፣ _እጅግ ጥሩ_፣
_ጥሩ_፣ _አማካይ_) ይታያሉ፤ ምክንያቱም መሠረታዊው እሴት መቶኛ ሳይሆን አንጻራዊ
የደረጃ ጥራት ነው።

### API መገናኛ

ገጹ በሕዝብ ሊደረስበት በሚችል የማንበብ መገናኛ
(`src/app/api/free-provider-rankings/route.ts`) የተደገፈ ነው፦

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

የመጠይቅ መለኪያዎች (በZod የተረጋገጡ)፦

| መለኪያ       | ዓይነት   | ነባሪ   | ማስታወሻዎች                                                                              |
| ---------- | ------ | ----- | ------------------------------------------------------------------------------------ |
| `category` | string | (የለም) | ከ`default`፣ `coding`፣ `review`፣ `documentation`፣ `debugging` አንዱ። ለተዋሃደው ደረጃ አያካትቱት። |
| `limit`    | number | `50`  | በ`1–100` ክልል ውስጥ ይገደባል።                                                              |

የምላሽ ቅርጽ፦

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` የመጀመሪያው የArena ELO እሴት ነው፤ `score` ደግሞ መደበኛ የተደረገው የተግባር-ተስማሚነት እሴት ነው
(ከታች ይመልከቱ)። ውጤት የተሰጣቸው ሞዴሎች የሌሏቸው አቅራቢዎች ከምላሹ ይቀራሉ።

## ውጤቶቹ እንዴት እንደሚሠሩ

### ምንጭ፦ Arena AI የደረጃ ሰንጠረዥ

የArena ELO ማመሳሰያ ሞተር (`src/lib/arenaEloSync.ts`) ሁለት የደረጃ ሰንጠረዦችን — `text`
እና `code` — ከArena AI የደረጃ ሰንጠረዥ API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) ያመጣል። እያንዳንዱ የደረጃ ሰንጠረዥ መዝገብ
የሞዴል ስም፣ አቅራቢ፣ የELO `score`፣ የመተማመኛ ክልል እና የድምፅ ብዛት ይይዛል።

የደረጃ ሰንጠረዥ ምድቦች ከOmniRoute የተግባር ምድቦች ጋር እንዲህ ይዛመዳሉ፦

| የArena ደረጃ ሰንጠረዥ | የOmniRoute ተግባር ምድቦች                              |
| ---------------- | ------------------------------------------------- |
| `text`           | `default`, `review`, `documentation`, `debugging` |
| `code`           | `coding`                                          |

### መደበኛነት ማስያዝ (የተግባር ተስማሚነት ውጤት)

ጥሬ የELO ውጤቶች በየደረጃ ሰንጠረዡ ወደ **በ`[0.4, 0.98]` ውስጥ ያለ የተግባር ተስማሚነት እሴት** ይመጠናሉ፦

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

ውጤቱ ፈጽሞ `0` ወይም `1` አይደርስም፤ ይህም ለተጠቃሚ ማሻሻያዎች ተጨማሪ ክልል ይተዋል። ይህ በAPI ምላሽ ውስጥ የሚያዩት
የ`score` መስክ እና በዳሽቦርዱ ላይ የሚታየው መለያ ነው።

### የመተማመኛ ደረጃ

እያንዳንዱ መዝገብ በArena የድምፅ ብዛት ላይ ተመሥርቶ የመተማመኛ ደረጃ ያገኛል፦

| የመተማመኛ ደረጃ | ድምፆች    |
| ---------- | ------- |
| `high`     | ≥ 5,000 |
| `medium`   | ≥ 1,000 |
| `low`      | < 1,000 |

### ማከማቻ እና ወቅታዊነት

መጠናቸው የተስተካከለ መዝገቦች በ
`source = "arena_elo"` (`src/lib/db/modelIntelligence.ts`) ወደ `model_intelligence` የDB ሰንጠረዥ ይጻፋሉ። መዝገቦቹ **ከ
7 ቀናት በኋላ ጊዜያቸው ያልፋል**፤ ስለዚህ ማመሳሰል ያቆመ አቅራቢ ያረጀ ውሂብ ከማቅረብ ይልቅ
በመጨረሻ ከዝርዝሩ ይወጣል።

ማመሳሰሉ **በነባሪ እንዲሠራ የተደረገ ነው**፦

- አገልጋዩ ሲጀምር አንድ ጊዜ ይሠራል፤ ከዚያም በየተወሰነ ጊዜ ቆጣሪ ይደጋገማል
  (`src/lib/arenaEloSync.ts`፣ ከ`src/instrumentation-node.ts` የተገናኘ)።
- እሱ **የማያግድ እና ፈጽሞ ወሳኝ ስህተት የማያስከትል** ነው — ከላይኛው ምንጭ ውሂብ ማምጣት ካልተሳካ፣ OmniRoute
  መሥራቱን ይቀጥላል፤ የደረጃ ሰንጠረዦቹም የመጨረሻውን ትክክለኛ ውሂብ ብቻ ያሳያሉ (ወይም ባዶ ሁኔታ ያሳያሉ)።

ሁለት የአካባቢ ተለዋዋጮች ይቆጣጠሩታል (በ

### በእጅ ማመሳሰል / ሁኔታ / ማጽዳት

ለኦፕሬተሮች፣ ማንነት ማረጋገጥ የሚጠይቅ የአስተዳደር መዳረሻ ነጥብ በእጅ መቆጣጠሪያ ያቀርባል
(`src/app/api/intelligence/sync/route.ts` — የአስተዳደር ማንነት ማረጋገጫ ያስፈልገዋል)፦

```
GET    /api/intelligence/sync          # የአሁኑ የማመሳሰል ሁኔታ (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # በእጅ ማመሳሰልን ያስጀምሩ፤ ሳይጻፍ ቅድመ ዕይታ ለማየት body: { "dryRun": true }
DELETE /api/intelligence/sync          # ሁሉንም የተመሳሰሉ arena_elo የመረጃ መዝገቦች ያጽዱ
```

የደረጃ ገጹ ባዶ ከሆነ፣ በእጅ የሚደረግ `POST /api/intelligence/sync` (ወይም በቀላሉ
አገልጋዩን እንደገና ማስጀመር) እንደገና ውሂብ ይሞላበታል።

### ሞዴሎችን ከደረጃ ሰንጠረዡ ጋር ማዛመድ

የመዝገብ ሞዴል IDዎች እና የArena ሞዴል ስሞች ሁልጊዜ በትክክል አይዛመዱም። የደረጃ አሰጣጡ
ተለዋዋጭ ማዛመድን ይጠቀማል (`findMatchingIntelligence` በ`src/lib/freeProviderRankings.ts` ውስጥ)፦

1. መደበኛ በተደረገው የሞዴል ID ላይ ትክክለኛ ማዛመድ።
2. በመጨረሻ ያለውን የስሪት ቅጥያ ካስወገዱ በኋላ ማዛመድ (ለምሳሌ `kimi-k2.6` → `kimi-k2`)።
3. በቅድመ ቅጥያ ማዛመድ (የደረጃ ሰንጠረዡ የሞዴል ስም የመዝገቡ ID ቅድመ ቅጥያ ሲሆን)።

በማመሳሰሉ በኩል፣ የታወቁ የአቅራቢ ቅድመ ቅጥያዎች (`anthropic/`, `openai/`, `google/`, …)
ይወገዳሉ፤ እንዲሁም አነስተኛ የተለዋጭ ስም ካርታ መደበኛ ስሞችን OmniRoute በውስጥ ወደሚጠቀምባቸው
ልዩነቶች ያስፋፋል፤ ስለዚህ ሞዴሎች በማንኛውም ስም ሊገኙ ይችላሉ።

### አንድ አቅራቢ እንዴት ደረጃ እንደሚሰጠው

ለእያንዳንዱ ነፃ አቅራቢ፣ ሞተሩ በካታሎጉ ውስጥ ላለ እያንዳንዱ ሞዴል ውጤት ይሰጣል፤ ከዚያም፦

- **ከፍተኛው ሞዴል** = ከአቅራቢው ሞዴሎች ከፍተኛውን ውጤት ያገኘው።
- **አማካይ ውጤት** = ውጤት በተሰጣቸው የአቅራቢው ሞዴሎች ሁሉ ላይ ያለው አማካይ ውጤት።
- **ሞዴሎች** = ከአቅራቢው ሞዴሎች የArena ውጤት የነበራቸው ብዛት።

አቅራቢዎች መጀመሪያ በ**ከፍተኛው ሞዴል ውጤት**፣ ከዚያም በአማካይ ውጤት ይደረደራሉ። ይህ ቢያንስ አንድ
ጠንካራ ነፃ ሞዴል የሚያቀርብ አቅራቢን ይሸልማል።

## ነፃ አቅራቢዎችን ለመምረጥ አጠቃቀሙ

1. **ትክክለኛውን ምድብ ይምረጡ።** ለወኪል-ተኮር/የኮድ የሥራ ጫናዎች **ኮድ ማድረግ** ማጣሪያን ይጠቀሙ፤ ወይም
   ለአጠቃላይ ውይይት **ሁሉም ምድቦች** / **ነባሪ** ላይ ይተዉት። የእያንዳንዱ የደረጃ ሰንጠረዥ ከፍተኛ ሞዴል
   የተለያየ ስለሆነ፣ ተመሳሳዩ አቅራቢ በተለያዩ ምድቦች የተለያየ
   ደረጃ ሊያገኝ ይችላል።
2. **ለአንድ ጊዜ ማዋቀሮች የመድረኩን ከፍተኛ ደረጃዎች ይምረጡ።** አንድ ወይም ሁለት ነፃ
   አቅራቢዎችን ብቻ ማገናኘት ከፈለጉ፣ በምድብዎ ከፍተኛ ደረጃ ካላቸው ይጀምሩ።
3. **የዓይነት ባጁን ያረጋግጡ።** `NOAUTH` አቅራቢዎች ለማገናኘት ፈጣኖቹ ናቸው (ምንም
   የመግቢያ ማረጋገጫ አያስፈልግም)። የ`OAUTH` / `APIKEY` ነፃ ደረጃዎች ፈጣን ምዝገባ ያስፈልጋቸዋል፣ ነገር ግን ብዙውን ጊዜ
   ይበልጥ ኃይለኛ ሞዴሎችን ያቀርባሉ። ስለ ግንኙነት ደረጃዎች [የነፃ ደረጃዎች መመሪያ](../getting-started/FREE-TIERS-GUIDE.md)ን
   ይመልከቱ።
4. **በርካታ አቅራቢዎችን ያገናኙና Auto-Combo እንዲወስን ያድርጉ።** ይህን ገጽ
   የሚያንቀሳቅሰው ተመሳሳይ የArena ELO ውሂብ የAuto-Combo የውጤት አሰጣጥ ሞተርን
   **የተግባር ተስማሚነት ምክንያት**ም ይመግባል
   (`open-sse/services/autoCombo/taskFitness.ts`፣ የመፍትሔ ቅደም ተከተል

   ነፃ አቅራቢዎች ካገናኙ በኋላ፣ `model: "auto"`ን (ለምሳሌ `auto/coding`) በመጠቀም ማዘዋወር
