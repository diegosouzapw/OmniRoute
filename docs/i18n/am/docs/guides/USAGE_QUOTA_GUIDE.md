## አጠቃላይ እይታ

በOmniRoute በኩል የሚያልፍ እያንዳንዱ ጥያቄ የሚከተሉትን የሚይዝ **የአጠቃቀም መዝገብ** ያመነጫል፦

- **ማንነት**: የትኛው API ቁልፍ፣ አቅራቢ፣ ሞዴል እና combo
- **ቶከኖች**: የመጠየቂያ ቶከኖች፣ የማጠናቀቂያ ቶከኖች፣ የተሸጎጡ ቶከኖች፣ ጠቅላላ
- **ወጪ**: የUSD መጠን (ከዋጋ ውሂብ የሚሰላ)
- **ጊዜ**: መዘግየት፣ የመጀመሪያ/ማብቂያ ጊዜ ማህተሞች
- **ሁኔታ**: ስኬት፣ ስህተት፣ የፍጥነት ገደብ፣ ወዘተ።

እነዚህ መዝገቦች ወደ **ትንታኔዎች** ይጠቃለላሉ፣ እንደ **የኮታ ቅጽበታዊ መዝገቦች** በቋሚነት ይቀመጣሉ፣ እንዲሁም **ለእያንዳንዱ ቁልፍ የበጀት ገደቦችን** ለማስከበር ጥቅም ላይ ይውላሉ።

```
ጥያቄ ──▶ chatCore ──▶ usage.record() ──▶ SQLite
                                  │
                          ┌───────┼───────┐
                          ▼       ▼       ▼
                     ትንታኔዎች  ኮታ    ክፍያ
                     (ዳሽቦርድ) (ማስከበር) (መላክ)
```

## የሚመዘገበው ምንድን ነው

የ`usage.ts` አገልግሎት ለእያንዳንዱ ጥያቄ **የአጠቃቀም ክስተት** ይመዘግባል፦

| መስክ                | ዓይነት    | ምንጭ                                                        |
| ------------------ | ------- | ---------------------------------------------------------- |
| `id`               | string  | በምዝገባ ወቅት የሚፈጠር UUID                                       |
| `apiKeyId`         | string  | ጥያቄውን የጀመረው API ቁልፍ                                        |
| `provider`         | string  | የአቅራቢ መለያ (openai፣ anthropic፣ ወዘተ)                         |
| `model`            | string  | የሞዴል መለያ (gpt-5፣ claude-opus-4-6፣ ወዘተ)                     |
| `comboId`          | string? | በcombo በኩል ከተመራ የcombo መለያ                                 |
| `promptTokens`     | number  | ከውጫዊ አቅራቢው ምላሽ                                             |
| `completionTokens` | number  | ከውጫዊ አቅራቢው ምላሽ                                             |
| `cachedTokens`     | number  | በመሸጎጫው ውስጥ የተገኙ ቶከኖች (የAnthropic መጠየቂያ መሸጎጫ፣ ወዘተ)          |
| `totalTokens`      | number  | መጠየቂያ + ማጠናቀቂያ                                             |
| `costUsd`          | number  | ከዋጋ ውሂብ የሚሰላ                                               |
| `latencyMs`        | number  | ከመጀመሪያ እስከ መጨረሻ ያለው የጥያቄ ቆይታ                               |
| `status`           | enum    | `success`, `error`, `rate_limited`, `timeout`, `cancelled` |
| `errorClass`       | string? | ሁኔታው success ካልሆነ የስህተት ክፍል                                |
| `timestamp`        | string  | ISO 8601 UTC                                               |
| `metadata`         | object  | በብጁ ተሰኪ የገባ ውሂብ                                            |

### ቶከኖቹ ከየት ይመጣሉ

ቶከኖች ከውጫዊ አቅራቢው ምላሽ በ**ምላሽ አስተናጋጅ** ውስጥ ይወጣሉ፦

```ts
// ከ open-sse/handlers/chatCore.ts
const response = await providerExecutor.execute(provider, request);
const usage = response.usage || {
  prompt_tokens: 0,
  completion_tokens: 0,
  cached_tokens: 0,
};
```

የአጠቃቀም ውሂብ ለማይመልሱ አቅራቢዎች (አንዳንድ የድር-cookie አቅራቢዎች)፣ OmniRoute `~4 chars per token` የሚለውን ግምታዊ ደንብ በመጠቀም ቶከኖቹን **ይገምታል** (`open-sse/services/autoCombo/pipelineRouter.ts`ን ይመልከቱ)።

### የተሸጎጡ ቶከኖች

OmniRoute `cached_tokens`ን ከ`prompt_tokens` ለይቶ ይከታተላል፣ ምክንያቱም፦

- የAnthropic መጠየቂያ መሸጎጫ ለተሸጎጡ ቶከኖች የተቀነሰ ዋጋ ያስከፍላል (ከመደበኛው 10%)
- አንዳንድ አቅራቢዎች በተለየ መንገድ ዋጋ ሊተመንላቸው የሚገባ `cache_read_input_tokens` ይመልሳሉ
- ትንታኔዎች **የመሸጎጫ ስኬት መጠን** = `cached_tokens / prompt_tokens` ማሳየት ይችላሉ

## የወጪ ስሌት

ወጪዎች ከLiteLLM በተመሳሰለ **የዋጋ መረጃ** (`src/lib/pricingSync.ts`) ይሰላሉ፦

| ሞዴል               | ግብዓት $/1M | ውጤት $/1M | ከመሸጎጫ $/1M |
| ----------------- | --------- | -------- | ---------- |
| gpt-5             | $2.50     | $10.00   | —          |
| claude-opus-4-6   | $15.00    | $75.00   | $1.50      |
| claude-sonnet-4-5 | $3.00     | $15.00   | $0.30      |
| gemini-2.5-pro    | $1.25     | $10.00   | —          |

የወጪ ቀመር (`src/lib/usage/costCalculator.ts`)፦

```ts
cost =
  (prompt_tokens - cached_tokens) * input_price +
  cached_tokens * cached_price +
  completion_tokens * output_price;
```

> **ከጥያቄው የመሸጎጫ ቶከኖችን ለምን እንቀንሳለን?** የተሸጎጠው ክፍል ዋጋው ለብቻው ይሰላል፤ ለጠቅላላው ጥያቄ የግብዓት ዋጋ ማስከፈል ወጪውን ከልክ በላይ ይቆጥራል።

### የዋጋ ማመሳሰል

የዋጋ መረጃ በ`/api/pricing/sync` መጨረሻ ነጥብ አማካኝነት ከLiteLLM በራስ-ሰር ይመሳሰላል (የሚጀመረው አብሮ በተካተተው cron ተግባር እንጂ ለተጠቃሚ በሚታይ env var አይደለም)፦

```bash
# በእጅ ማስጀመሪያ
curl -X POST http://localhost:20128/api/pricing/sync
```

የዋጋ መረጃ ለሌላቸው ሞዴሎች፣ OmniRoute ውስጣዊ አማካይ ተመኖችን (ከLiteLLM የዋጋ መረጃ የተገኙ) በመጠቀም **ወጪውን ወደ መገመት** ይመለሳል።

## የኮታ ቁጥጥር

ለእያንዳንዱ API ቁልፍ የሚደረገው የኮታ ቁጥጥር በሁለት ቦታዎች ይተገበራል፦

1. **ለስላሳ ገደብ** (`quotaWarnAt`)፦ አጠቃቀሙ ከመጠን ገደቡ ሲያልፍ በዳሽቦርዱ ላይ ማስጠንቀቂያ ይታያል
2. **ጠንካራ ገደብ** (`quotaLimit`)፦ ገደቡ ሲታለፍ ጥያቄው በ-HTTP 429 ውድቅ ይደረጋል

### ውቅር

```ts
// ለእያንዳንዱ API ቁልፍ
await updateApiKey(keyId, {
  quotaWarnAt: 5_00,    // $5.00 — ማስጠንቀቂያ አሳይ
  quotaLimit: 10_00,    // $10.00 — ሙሉ በሙሉ አቁም
  quotaWindow: "month", // "day" | "week" | "month" | "all"
});
````

### የቁጥጥር ፍሰት

```
ጥያቄ ──▶ quotaCheck()
              │
              ├── በገደቡ ውስጥ ነው?  ──▶ ፍቀድ
              │
              └── ገደቡን አልፏል?  ──▶ 429 በጣም ብዙ ጥያቄዎች
                                   ከ-Retry-After ራስጌ ጋር
```

`quotaSnapshots` ሰንጠረዥ ለአዝማሚያ ትንተና **ታሪካዊ የኮታ ሁኔታን** ያከማቻል፦

| መስክ | መግለጫ |

| `used` | በዚህ ጊዜ መስኮት ውስጥ ጥቅም ላይ የዋለ ወጪ (በሳንቲም) |

የቆዩ መዝገቦች በ`src/lib/db/cleanup.ts` ይጸዳሉ፦

- በጀርባ በሚሠራው cron ሂደት ይጀመራል

## ችግር መፍታት

### "ወጪው ከተጠበቀው በላይ ነው"

1. **`/api/usage/analytics?groupBy=model`** ያረጋግጡ — ውድ የሆነውን ሞዴል ያግኙ
2. **`/api/usage/analytics?groupBy=apiKey`** ያረጋግጡ — ከፍተኛ ተጠቃሚውን ያግኙ
3. የዋጋ መረጃው ወቅታዊ መሆኑን ያረጋግጡ፦ `POST /api/pricing/sync`

### "መዝገቦች ጠፍተዋል"

- Dashboard → Database → Cleanup ስር ያሉትን የDB ማቆያ ቅንብሮች ያረጋግጡ — የቆዩ መዝገቦች በየጊዜው በሚሠራው የማጽዳት ተግባር (`src/lib/db/cleanup.ts`) ይሰረዛሉ
- በ`src/lib/db/usage*.ts` ውስጥ ስህተቶች እንዳሉ ያረጋግጡ — የDB ጽሑፍ ማስገባት አለመሳካቶች ይመዘገባሉ፣ ነገር ግን ለተጠቃሚው አይታዩም
- ጥያቄው በእርግጥ `chatCore` ላይ መድረሱን ያረጋግጡ — የcombo ማስተላለፊያን ያረጋግጡ

### "ኮታው ተግባራዊ አይሆንም"
