AgentBridge የOmniRoute MITM (Man-in-the-Middle) ፕሮክሲ ሲሆን፣ ከIDE AI ወኪሎች የሚመጣውን HTTPS ትራፊክ በመጥለፍ በOmniRoute የተዋሃደ የማዘዋወሪያ ሞተር በኩል እንደገና ያዞረዋል። **10 IDE ወኪሎችን** — Antigravity፣ Kiro፣ GitHub Copilot፣ GHE Copilot፣ OpenAI Codex፣ Cursor፣ Zed፣ Claude Code፣ Open Code እና Trae (በምርመራ ላይ) — ይደግፋል፤ ይህም OmniRouteን በገበያው ላይ ለAI ኮድ ረዳቶች እጅግ ሰፊ ሽፋን ያለው MITM ፕሮክሲ ያደርገዋል።

**የዳሽቦርድ መገኛ:** `/dashboard/tools/agent-bridge`

## §1 አጠቃላይ እይታ

### AgentBridge ምንድን ነው?

አንድ IDE ወኪል (ለምሳሌ፣ GitHub Copilot፣ Cursor፣ Claude Code) የAPI ጥሪ ሲያደርግ፣ በቀጥታ ከላይኛው AI አቅራቢ (OpenAI፣ Anthropic፣ ወዘተ) ጋር ይገናኛል። AgentBridge ምንም የወኪል ውቅረት ለውጥ ሳያስፈልግ ይህን ግንኙነት በTLS ደረጃ በግልጽ ሁኔታ በመጥለፍ ጥያቄውን በOmniRoute በኩል እንደገና ይጽፈዋል።

ይህም የሚከተሉትን እንድታደርጉ ያስችላችኋል፦

- **ማንኛውንም ወኪል ወደ ማንኛውም አቅራቢ እንደገና ማዘዋወር**: Copilot ከOpenAI ጋር እየተገናኘ ነው? ወደ Anthropic Claude፣ Gemini ወይም ከOmniRoute 352 አቅራቢዎች ወደ ማንኛውም አቅራቢ ያዙሩት።
- **የሞዴል ማመሳሰያዎችን መተግበር**: `gemini-3-flash` → `claude-sonnet-4.7` በአስተናጋጅ ደረጃ በግልጽ ሁኔታ።
- **ሁሉንም የወኪል ትራፊክ መመልከት**: እያንዳንዱ የተጠለፈ ጥያቄ ወደ [ትራፊክ መርማሪ](./TRAFFIC_INSPECTOR.md) ይታተማል።
- **የOmniRoute የመቋቋም ችሎታን መተግበር**: ጥምር ማዘዋወር፣ የወረዳ መቆራረጫዎች፣ ተተኪዎች እና የወጪ ክትትል ለIDE ወኪል ትራፊክም ይሰራሉ።

## §2 አርክቴክቸር

### 2.1 የአካላት አጠቃላይ እይታ

```
IDE ወኪል (VS Code / Cursor / ወዘተ)
    │  HTTPS (ወደብ 443)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← DNS ማዘዋወሪያ
    │
    ▼
src/mitm/server.cjs  (ወደብ 443፣ CJS ልጅ ሂደት)
    │  ዒላማውን በ Host header SNI ይወስናል
    │  በ AgentBridge CA የተፈረመ ለእያንዳንዱ SNI የTLS ሰርቲፊኬት ያመነጫል
    ├── ከማለፊያ ዝርዝሩ ጋር ይዛመዳል? → TCP ቀጥታ ማሳለፊያ (ዲክሪፕት አይደረግም)
    ├── ከዒላማ ጋር ይዛመዳል? → fetch → OmniRoute ራውተር (ወደብ 20128)
    │       └── handler.intercept() — TypeScript
    │               ├── maskSecrets() በጥያቄ አካል/headers ላይ
    │               ├── TrafficBuffer.push() — ወደ Traffic Inspector ያትማል
    │               └── fetchRouter() → /v1/chat/completions
    └── ምንም ተዛማጅ የለም? → TCP ቀጥታ ማሳለፊያ (ዲክሪፕት አይደረግም)
```

### 2.2 MITM አገልጋይ (`src/mitm/server.cjs`)

ዋናው MITM አገልጋይ እንደ Node.js CJS ልጅ ሂደት ይሰራል (ያለውን CJS ኮድቤዝ እንደገና ከመጻፍ ለመቆጠብ)። የሚከተሉትን ያከናውናል፦

- ወደብ 443 ላይ ያዳምጣል (ልዩ ፈቃድ ወይም `authbind`/`setcap` ያስፈልገዋል)
- ከስርዓተ ክወናው CONNECT tunnels ይቀበላል (በ`/etc/hosts` DNS ማዘዋወሪያ በኩል)
- በ AgentBridge CA (`DATA_DIR/mitm/ca.crt`) የተፈረሙ ለእያንዳንዱ SNI የTLS ሰርቲፊኬቶችን ያመነጫል
- የዒላማውን ወኪል በ Host header አማካኝነት በ`targets/index.ts` መዝገብ ይወስናል
- ወደ `http://127.0.0.1:20128` በHTTP በኩል ወደ TypeScript handler ንብርብር ያስተላልፋል

`TARGET_HOSTS` ከ`DATA_DIR/mitm/targets.json` (በመነሳት ጊዜ በ`targets/index.ts` የሚጻፍ) ይጫናል፤ ይህም CJS አገልጋዩን እንደገና ሳያስጀምሩ ተለዋዋጭ ማዘመኖችን ይፈቅዳል።

> **Root-CA ሞዴል (#6684)።** ከላይ የተገለጸው በአንድ CA የተፈረመ ለእያንዳንዱ SNI ሰርቲፊኬት
> በ#6684 የታከለው ቋሚ root-CA ሞዴል ነው (`src/mitm/cert/rootCa.ts` +
> `src/mitm/_internal/rootCaShim.cjs`፣ ቀደም ሲል ለTPROXY በ
> `src/mitm/tproxy/dynamicCert.ts` ውስጥ የተረጋገጠውን CA/leaf ክሪፕቶ እንደገና በመጠቀም) — በዲስክ ላይ
> ያለ `server.crt`/`server.key` ጥንድ የሚያመለክተውን አሮጌውን ነጠላ ቋሚ በራሱ የተፈረመ leaf
> (`src/mitm/cert/generate.ts`፣ አሁንም ለantigravity hosts ብቻ
> የተወሰነ) ይተካል። **የፍልሰት ባህሪ**፦ አዲስ ጭነት (የቀድሞ
> `server.crt` የሌለው) root-CA ሞዴሉን በራስ-ሰር ያገኛል፤ አሮጌውን ቋሚ leaf
> አስቀድሞ ያመነ ጭነት ኦፕሬተሩ
> `MITM_ROOT_CA_ENABLED=true` አዘጋጅቶ bridge እስኪያስጀምር ድረስ እሱን መጠቀሙን ይቀጥላል (`src/mitm/cert/migration.ts`
> ንጹሕ የውሳኔ ፋንክሽን ነው — ለ
> **ማንኛውም** host leaf መፈረም የሚችል የታመነ MITM CA ከአሮጌው fixed-SAN leaf በእጅጉ የበለጠ ኃይል ስላለው፣
> አስቀድሞ ለታመነ ጭነት ሽግግሩ በጭራሽ በጸጥታ አይከናወንም)። የCA ሰርቲፊኬቱ
> አሮጌው leaf በተጠቀመበት ተመሳሳይ `omniroute-mitm.crt` trust-store slot ውስጥ ይጫናል
> (`cert/install.ts::installCaCert`) — ድርብ እምነትን ማጽዳት አያስፈልግም።

### 2.3 Handler መሠረት (`src/mitm/handlers/base.ts`)

ሁሉም የወኪል handlers `MitmHandlerBase`ን ይዘረጋሉ፦

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // የተጠበቁ ረዳቶች፦ fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

እያንዳንዱ handler proxy ከማድረጉ በፊት `hookBufferStart()`ን፣ ሲጠናቀቅም `hookBufferUpdate()`ን ይጠራል። እነዚህ `InterceptedRequest` ግቤቶችን ወደ `globalTrafficBuffer` ይገፋሉ ([Traffic Inspector](./TRAFFIC_INSPECTOR.md) §4ን ይመልከቱ)።

### 2.4 የዒላማዎች መዝገብ (`src/mitm/targets/`)

እያንዳንዱ ወኪል መግለጫዊ የዒላማ ፋይል አለው፦

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

መዝገቡ (`targets/index.ts`) `ALL_TARGETS`ን export ያደርጋል እና በመነሳት ጊዜ `DATA_DIR/mitm/targets.json`ን ያመነጫል።

### 2.5 ቀጥታ ማሳለፊያ እና የማለፊያ ዝርዝር (`src/mitm/passthrough.ts`)

**የማለፊያ ዝርዝር** (መጀመሪያ ይፈተሻል፣ ከዒላማ ማዛመድ በላይ ቅድሚያ አለው)፦

- ነባሪ ስርዓተ ጥለቶች፦ የባንክ hosts፣ `.gov.`፣ OAuth/SSO providers (Okta፣ Auth0)፣ ወዘተ
- የተጠቃሚ ስርዓተ ጥለቶች፦ በDB table `agent_bridge_bypass` ውስጥ ይከማቻሉ
- የሚታለፉ hosts ግልጽ TCP tunnel ያገኛሉ — TLS **በፍጹም ዲክሪፕት አይደረግም**

**የቀጥታ ማሳለፊያ ነባሪ** (ከዒላማ ጋር ሳይዛመድ እና በማለፊያ ዝርዝሩ ውስጥ ሳይሆን)፦

- እንዲሁም TCP tunnel ይቀበላል — ግንኙነቶች ፈጽሞ አይቋረጡም
- AgentBridge አጠቃላይ የስርዓቱን HTTPS ትራፊክ እንዳያውክ ይከላከላል

የማዞሪያ ቅድሚያ፦

```
የማለፊያ ዝርዝር → ከዒላማ ጋር ማዛመድ → ቀጥታ ማሳለፊያ
```

### 2.6 Upstream CA ሰርቲፊኬት (`src/mitm/upstreamTrust.ts`)

ብጁ CA ላላቸው የድርጅት አውታረ መረብ አካባቢዎች፦

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

ሲዘጋጅ፣ የ`undici`ን ዓለም አቀፋዊ dispatcher ተጨማሪውን CA ሰርቲፊኬት እንዲጠቀም ያዋቅራል፤ ይህም AgentBridge በድርጅታዊ TLS termination proxies በኩል upstream providersን እንዲደርስ ያስችለዋል።

### 2.7 ሚስጥር መሸፈኛ (`src/mitm/maskSecrets.ts`)

ገለልተኛው clean-room scanner የጥያቄ አካላት እና የማረጋገጫ headers ወደ Traffic Inspector buffer ወይም ወደ ማንኛውም log ከመግባታቸው
**በፊት** በእነሱ ላይ ይተገበራል። አንድ መስመራዊ ቅኝት ያከናውናል፦

- በ`sk-` / `ak-` / `pk-` የሚጀምሩ tokens (የOpenAI/Anthropic ዓይነት)
- RFC 6750 `Authorization: Bearer <token>` ማረጋገጫዎች፣ ለሙሉ token ቅድሚያ በመስጠት
- አጠቃላይ ረጅም ግልጽ ያልሆኑ tokens (≥40 ቁምፊዎች)፣ ነጥብ ያላቸውን እና padding ያላቸውን ቅርጾች ጨምሮ

`sanitizeHeaders()` የቀሩትን ስሞች ወደ lowercase ይቀይራል፣ የarray እሴቶችን በተወሰነ ቅደም ተከተል ያገናኛል፣
የጋራውን hop-by-hop/framing denylist (የproxy ማረጋገጫን ጨምሮ) ይጥላል፣ `cookie` እና
`set-cookie`ን ሙሉ በሙሉ ይሰውራል፣ እና የማረጋገጫ እሴቶችን ወደ scanner ያስተላልፋል።

### 3.2 የምስክር ወረቀቱን ማመን

IDEs የMITM ግንኙነቱን ከመቀበላቸው በፊት የAgentBridge CA ምስክር ወረቀት በOS የታመነ መሆን አለበት።

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Keychain):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

ወይም በዳሽቦርዱ ውስጥ ያለውን "Trust Cert" አዝራር ይጠቀሙ (ለOSዎ ተገቢውን ትዕዛዝ ያስኬዳል፤ ካስፈለገም የsudo ጥያቄ ያሳያል)።

#### በElectron ላይ የተመሠረቱ IDEs የOS የታመኑ ምስክር ወረቀቶች ማከማቻን ችላ ይላሉ (`NODE_EXTRA_CA_CERTS`)

አንዳንድ IDEs — በተለይም **Antigravity IDE** እና ሌሎች ከElectron / VS Code የተወረሱ መተግበሪያዎች —
ለወጪ `fetch`/HTTPS የOS የታመኑ ምስክር ወረቀቶች ማከማቻን **የማይመለከት**
የራሳቸውን Node.js runtime አብረው ይይዛሉ። CAውን በOS/NSS ደረጃ ማመን ለIDEው ቤተኛ **backend**
(ለምሳሌ፣ የOS CA bundleን የሚጠቀም Go language server) በቂ ነው፤ ነገር ግን **Electron frontend** አሁንም
TLSን ማስኬድ ይሳነዋል — ይህም መተግበሪያው _ከመለያ እንደወጣ_ ወይም _"connection error"_
እንደሚያሳይ ሆኖ ይገለጣል፤ የMITM ምዝግብ ማስታወሻው የbackend bootstrap ጥሪዎች `200` እየመለሱ መሆኑን
ቢያሳይም። ሁለት ደረጃዎች ያስፈልጋሉ፣ ሁለቱም አስፈላጊ ናቸው፦

1. runtimeን በቀጥታ ወደ CAው ያመልክቱ፦
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **IDEውን ከዚያ shell ውስጥ ያስጀምሩ።** ከዴስክቶፕ አዶ / Dock / Start menu ማስጀመር
   የshell exportsን **አይወርስም**፤ እንዲሁም `~/.config/environment.d/*.conf` ተግባራዊ የሚሆነው
   ከአዲስ ግራፊካዊ መግቢያ በኋላ ብቻ ነው። መጀመሪያ IDEውን ሙሉ በሙሉ ይዝጉ — የElectron singleton lock ማለት ሁለተኛ
   ማስጀመር ነባሩን ሂደት ብቻ ትኩረት ያደርግበታል፣ አዲሱም environment ችላ ይባላል።

ከላይ ያለው የOS እምነት + NSS ደረጃ አሁንም አስፈላጊ ነው (በአንዳንድ የማረጋገጫ ፍሰቶች የሚጠቀሙበት
የChromium አውታረ መረብ stack የእያንዳንዱን ተጠቃሚ NSS store ያነባል፤ እንዲሁም በአካባቢው
የታመነ CA የሚሽራቸው ለ`*.googleapis.com` የራሱ static pins አሉት)። `NODE_EXTRA_CA_CERTS` በተጨማሪ የNode `fetch` መንገድን ይሸፍናል።

### 3.3 የDNS ማዘዋወር

### 3.4 የሞዴል ማዛመድ

Wildcard `*` ማንኛውንም ያልታወቀ ሞዴል ወደተገለጸው ዒላማ ያዛምዳል። በ`agent_bridge_mappings` ሰንጠረዥ ውስጥ ይቀመጣል።

> **ጠቃሚ ምክር — የወኪሉን እውነተኛ የሞዴል IDs ያግኙ።** አንድ IDE ከUI መለያዎቹ የሚለዩ እና

> የሚታየውን `gemini-2.5-pro` አይደለም። ተዛማጅ ማዛመጃ ሳይኖር አንድ chat ይላኩ፦ MITM
> ትክክለኛውን ገቢ `model:` በምዝግብ ማስታወሻ ይመዘግባል እና ጥያቄውን እንዲያልፍ ያደርጋል። ያንን ቀጥተኛ እሴት ያዛምዱ፤ ከዚያም
> ቀጣዩ ጥያቄ ተጠልፎ ወደ ዒላማዎ ይዘዋወራል።

### 3.5 የአደጋ ማስታወቂያ

AgentBridge፣ IDEው ከዋና አቅራቢዎች ጋር ራሱን ለማረጋገጥ የሚጠቀምባቸውን ማረጋገጫዎች (OAuth tokens፣ API keys) ይጠልፋል። እነዚህ **በምዝግብ ማስታወሻ ከመመዝገባቸው በፊት ይሸፈናሉ** (§2.7ን ይመልከቱ)፤ ነገር ግን ለOmniRoute MITM layer ይታያሉ። የእያንዳንዱ ወኪል የመጀመሪያ ማግበር ሊዘጋ የሚችል የአደጋ ማስታወቂያ modal ያሳያል።

### 3.6 ጥገና እና ምርመራዎች

ዳሽቦርዱ ከዚህ በፊት UI ያልነበራቸውን የMITM ክዋኔ መንገዶች የሚያሳይ **Maintenance & Diagnostics** ካርድ (`AgentBridgeMaintenanceCard`፣ በ`src/app/(dashboard)/dashboard/tools/agent-bridge/components/` ውስጥ) ያቀርባል። ንዑስ ርዕሱ፦ _"የመያዝ ሂደቱን በራስ-ሰር ይፈትሹ፣ የቀረውን የስርዓት ሁኔታ ይቀልብሱ፣ እና ማዋቀርዎን በማሽኖች መካከል ያንቀሳቅሱ።"_ የካርዱ የclient helpers በ`src/lib/inspector/agentBridgeMaintenanceApi.ts` ውስጥ ይገኛሉ።

| አዝራር          | መስመር                                   | የሚያከናውነው                                                                                                                                                              |
| ------------- | -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ምርመራ**      | `GET /api/tools/agent-bridge/diagnose` | የመቅረጽ ሂደቱን ራስ-ሙከራ ያካሂዳል፣ እንዲሁም ለእያንዳንዱ ፍተሻ ሪፖርት ያሳያል (✓/✗ + የማስተካከያ ፍንጭ)።                                                                                             |
| **ጥገና**       | `POST /api/tools/agent-bridge/repair`  | በብልሽት ወይም በSIGKILL ምክንያት የተረፈውን ባለቤት-አልባ የMITM ስርዓት ሁኔታ (የDNS ማጭበርበሪያ ግቤቶች፣ root CA፣ የስርዓት proxy) ይቀለብሳል። Idempotent ነው — ሁኔታው ንጹሕ ሲሆን "የሚጠገን ነገር የለም" ብሎ ሪፖርት ያደርጋል። |
| **CAን አስወግድ** | `DELETE /api/tools/agent-bridge/cert`  | የMITM root CAን ከOS የእምነት ማከማቻ ያስወግዳል፣ እምነቱንም ይሰርዛል (ግልጽ፣ idempotent)። CAው በአሁኑ ጊዜ የታመነ ሲሆን ብቻ ይታያል፤ በቦታው ላይ "CAን አስወግድ?" የሚል ማረጋገጫ ያስፈልገዋል።                           |
| **ውቅር ላክ**    | `GET /api/tools/agent-bridge/config`   | ተንቀሳቃሹን የውቅር JSON ያወርዳል (§3.7ን ይመልከቱ)።                                                                                                                                |
| **ውቅር አስገባ**  | `POST /api/tools/agent-bridge/config`  | ከዚህ በፊት ወደ ውጭ የተላከ የውቅር JSON ይሰቅላል (§3.7ን ይመልከቱ)።                                                                                                                     |

**የምርመራ ፍተሻዎች** (`summarizeDiagnostics()` በ`src/mitm/inspector/diagnostics.ts` ውስጥ)። መስመሩ ለእያንዳንዱ ፍተሻ ውጤት ያለውን probe ያስኬዳል፣ እና booleansን ወደ pure summarizer ያስገባል፤ አንድ `healthy` ውሳኔ ከእያንዳንዱ ውድቀት ፍንጭ ጋር ይመለሳል፦

| የፍተሻ ስም            | የሚያረጋግጠው                                         | በውድቀት ጊዜ የሚሰጥ ፍንጭ                                                                                               |
| ------------------ | ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| `server-running`   | የMITM server ሂደት ንቁ ነው                           | "የMITM server እየሰራ አይደለም። ከAgentBridge ትር ያስጀምሩት።"                                                              |
| `server-reachable` | የMITM server በportው ላይ ግንኙነቶችን ይቀበላል (TCP probe) | "የMITM server በportው ላይ ግንኙነቶችን እየተቀበለ አይደለም። portው ነጻ መሆኑንና ከእሱ ጋር bind ለማድረግ ፈቃድ እንዳለዎት ያረጋግጡ።"               |
| `cert-exists`      | የMITM certificate በዲስክ ላይ ተፈጥሯል                  | "እስካሁን ምንም የMITM certificate አልተፈጠረም። ከAgentBridge ትር አንድ ይፍጠሩ።"                                                |
| `cert-trusted`     | የMITM root CA በOS የእምነት ማከማቻ ውስጥ አለ              | "የMITM root CA በOS ማከማቻ አልታመነም፣ ስለዚህ የTLS ጣልቃ ገብነት አይሳካም። certificateን ከAgentBridge ትር ያመኑት።"                   |
| `dns-configured`   | የታለሙ hostnameዎች በ`/etc/hosts` ውስጥ ተጭበርብረዋል       | "የታለሙ hostnameዎች በ/etc/hosts ውስጥ አልተጭበረበሩም፣ ስለዚህ traffic ወደ proxyው ፈጽሞ አይደርስም። መቅረጽ ለሚፈልጉት agent(ዎች) DNSን ያንቁ።" |

**የባለቤት-አልባ ሁኔታ ሰንደቅ፦** ገጹ በብልሽት ምክንያት የቀረ ሁኔታን (DNS spoof / CA / system proxy) ሲያገኝ፣ ካርዱ የአምበር ቀለም ሰንደቅ ያሳያል — _"አንድ ቀዳሚ session የስርዓት ሁኔታን (DNS spoof፣ CA ወይም system proxy) ትቶ ሄዷል። ለማጽዳት ጥገናን ያስኪዱ።"_ — እና **ጥገና** አዝራሩን አጉልቶ ያሳያል። `Repair` የProxyBridge `--cleanup` flag የመተግበሪያ-ንብርብር አቻ ነው (`repairMitm()`ን በ`src/mitm/manager.ts` ውስጥ ይወክላል)።

> ተደጋጋሚ የsudo ጥያቄዎችን ለማስወገድ የMITM root CA በማቆም/ማስጀመር መካከል እንደተጫነ
> ይቆያል (ከmitmproxy/Charles ጋር ተመሳሳይ ባህሪ)፣ ስለዚህ ማስወገዱ በማቆም ጊዜ በራስ-ሰር
> ከሚከሰት ነገር ይልቅ ግልጽ የ**CAን አስወግድ** እርምጃ ነው።

### 3.7 ተንቀሳቃሽ ውቅር ማስገባት/መላክ

AgentBridge **በኦፕሬተሩ ሊስተካከል የሚችለውን** ሁኔታ ስሪት ወዳለው JSON blob serialize ማድረግ ይችላል፣ በዚህም አንድ setup በተለያዩ ማሽኖች ላይ እንዲደገም ያስችላል። serializerው `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`) ሲሆን፣ በ`AgentBridgeConfigSchema` ይረጋገጣል።

ወደ ውጭ የሚላከው በትክክል ሦስት ክፍሎችን ያካትታል (አብሮገነብ ነባሪዎች ሆን ተብለው **አይላኩም**፣ ስለዚህ ማስገባት በፍጹም እነሱን አያባዛም ወይም ከእነሱ ጋር አይጋጭም)፦

| መስክ              | ምንጭ                                                         | ማስታወሻዎች                                                         |
| ---------------- | ----------------------------------------------------------- | --------------------------------------------------------------- |
| `bypassPatterns` | በተጠቃሚ የተገለጹ bypass patternዎች (`agent_bridge_bypass`)        | ነባሪ bank/gov/okta patternዎች አይካተቱም                              |
| `customHosts`    | የTraffic Inspector custom hostዎች (`inspector_custom_hosts`) | እያንዳንዱ፦ `{ host, kind: "llm"\|"app"\|"custom", label? }`        |
| `agentMappings`  | ለእያንዳንዱ agent የmodel mappingዎች (`agent_bridge_mappings`)    | mappingዎች ላሉት ሁሉም agentዎች `{ [agentId]: [{ source, target }] }` |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**የማስገባት ባህሪ** (`POST /api/tools/agent-bridge/config`)፦ bypass patternዎች እና የእያንዳንዱ agent mappingዎች **ሙሉ በሙሉ ይተካሉ**፤ custom hostዎች **በidempotent መንገድ** ይጨመራሉ (`INSERT OR IGNORE`)። ምላሹ ከእያንዳንዱ ስንት እንደተተገበሩ ሪፖርት ያደርጋል፦

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

በውቅሩ ውስጥ **የማይካተቱት**፦ የሰርቨሩ የመስራት ሁኔታ፣ የምስክር ወረቀት ዱካዎች፣ የእያንዳንዱ ወኪል DNS ሁኔታ፣ የላይኛው CA ዱካ እና የTPROXY ቅንብሮች ናቸው—እነዚህ ተንቀሳቃሽ ምርጫዎች ሳይሆኑ የአስተናጋጅ/የአሂድ-ጊዜ ሁኔታዎች ናቸው።

### የማዋቀሪያ አዋቂ ደረጃዎች (ለእያንዳንዱ ኤጀንት)

እያንዳንዱ የኤጀንት ካርድ ባለ3-ደረጃ የማዋቀሪያ አዋቂ አለው፦

1. **ቅድመ ሁኔታዎችን ያረጋግጡ** — አገልጋዩ እየሰራ ነው? ሰርተፍኬቱ የታመነ ነው? IDE ተጭኗል (በራስ-ሰር የተገኘ)?

### ኤጀንትን ማግኘት

### የሚታወቁ ገደቦች

- **Port 443 ልዩ ፈቃድ ያስፈልገዋል**፦ በLinux ላይ፣ AgentBridge በNode ሁለትዮሽ ፋይል ላይ `setcap 'cap_net_bind_service=+ep'` ያስፈልገዋል፣ ወይም በ`authbind` በኩል መስራት አለበት። የማዋቀሪያ አዋቂው ለOS የተለዩ መመሪያዎችን ያሳያል።
- **IDEን እንደገና ማስጀመር ያስፈልጋል**፦ ከDNS ማዞሪያ በኋላ፣ አዲሱ የአስተናጋጅ መፍትሔ ተግባራዊ እንዲሆን IDEው እንደገና መጀመር አለበት።
- **በቋሚነት የተቀመጡ OAuth ቶከኖች**፦ አንዳንድ ኤጀንቶች (Kiro፣ Antigravity) የOAuth ማደሻ ቶከኖችን በአካባቢው ያከማቻሉ። እነዚህ ለAgentBridge ግልጽ ናቸው — በእያንዳንዱ ጥያቄ ውስጥ ያለውን Bearer ቶከን ያያል፣ ይህም ከመመዝገቡ በፊት ይሸፈናል።
- **የElectron የፊት ገጽ `NODE_EXTRA_CA_CERTS` ያስፈልገዋል**፦ የፊት ገጻቸው በአብሮ በተጠቃለለ Node/Electron runtime ላይ የሚሰራ IDEዎች የOS/NSS የእምነት ማከማቻን ችላ ይላሉ እና `NODE_EXTRA_CA_CERTS` ተዘጋጅቶ ከshell መጀመር አለባቸው (§3.2ን ይመልከቱ)። ሲጎድል የሚታየው ምልክት፦ የIDE backend ማረጋገጫውን ያልፋል (MITM `200`ዎችን ያሳያል) ነገር ግን UIው እንደወጣ ይቆያል።
- **የአንድ IDE ብዙ ጭነቶች እርስ በርሳቸው ነጻ ናቸው**፦ የስርዓት ጭነት (ለምሳሌ፣ `/usr/share/antigravity/antigravity`) እና በተጠቃሚ አካባቢ ያለ "Full" ጭነት (ለምሳሌ፣ `~/AntigravityIDE_Full/antigravity-ide`) የራሳቸው runtimes ያላቸው የተለያዩ ሂደቶች ናቸው — እያንዳንዳቸው CAው ተጨምሮባቸው እንደገና መጀመር አለባቸው። እንደገና ከማስጀመርዎ በፊት የትኛው እየሰራ እንደሆነ በሁለትዮሽ ፋይሉ ዱካ ይለዩ።
- **ማንነት የሚወሰነው በኤጀንቱ የስርዓት ጥያቄ እንጂ በተዛወረው ሞዴል አይደለም**፦ የኤጀንትን ሞዴል ወደ ሌላ አቅራቢ ሲያዛምዱ፣ IDEው ያንን ወደ ስርዓት ጥያቄው ስለሚያስገባ ምላሹ አሁንም የኤጀንቱን ቤተኛ ማንነት ይገልጻል (ለምሳሌ፣ Antigravity "የሚያንቀሳቅሰኝ Gemini ነው" ብሎ ይመልሳል)። ሞዴሉን ማን እንደሆነ በመጠየቅ ሳይሆን ትክክለኛውን backend በ`call_logs` / `proxy_logs` (`provider`, `model`, `target_format`) ውስጥ ያረጋግጡ።

## §6 ችግር አፈታት

### የፖርት 443 ግጭት

ሌላ ሂደት አስቀድሞ ፖርት 443 ላይ እያዳመጠ ከሆነ (የድር አገልጋይ፣ VPN፣ ወዘተ)፦

```bash
lsof -i :443          # ሂደቱን ያግኙ
sudo fuser -k 443/tcp  # በግድ ያቋርጡ (በጥንቃቄ ይጠቀሙ)
```

እንደ አማራጭ፣ በAgentBridge ቅንብሮች ውስጥ ልዩ ፈቃድ የማይፈልግ ፖርት ያዋቅሩ እና የ`iptables` / `pf` ማዘዋወሪያ ደንቦችን ያዘጋጁ።

### ሰርተፍኬቱ የታመነ አይደለም

AgentBridgeን ካስጀመሩ በኋላ IDEው የTLS ስህተቶችን ካሳየ፦

1. ሰርተፍኬቱ መጫኑን ያረጋግጡ፦ `security find-certificate -c "OmniRoute AgentBridge"` (macOS) ወይም `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. አንዳንድ መተግበሪያዎች የራሳቸውን የታመኑ ሰርተፍኬቶች ማከማቻ ይይዛሉ (Firefox፣ Chrome በLinux ላይ)። "Trust Cert"ን እንደገና ያስኪዱ እና ለNSS/Firefox የተለየውን የሰርተፍኬት ማከማቻ ያረጋግጡ።
3. እምነት ከሰጡ በኋላ IDEውን እንደገና ያስጀምሩ — በሂደት ላይ ያሉ የTLS ክፍለ ጊዜዎች የድሮውን የእምነት ሁኔታ ይጠቀማሉ።

### የታመነ CA ቢኖርም IDEው ከመለያ ወጥቷል / "connection error"

ምልክት፦ DNSን ካዘዋወሩ እና ለCAው እምነት ከሰጡ በኋላ፣ Electronን መሠረት ያደረገ IDE (ለምሳሌ Antigravity)
**ከመለያ የወጣ** ሆኖ ይከፈታል ወይም የማረጋገጫ/ግንኙነት ስህተት ያሳያል፤ ሆኖም የMITM ምዝግብ
የማስነሻ ጥሪዎቹ (`loadCodeAssist`፣ `fetchAvailableModels`፣ …) `200` እየመለሱ መሆናቸውን ያሳያል።

ምክንያት፦ ከIDEው ጋር የታሸገው **የNode/Electron አሂድ አካባቢ የስርዓተ ክወናውን የታመኑ ሰርተፍኬቶች ማከማቻ ችላ ይላል**። ነባሪው
የጀርባ ክፍል (የGo ቋንቋ አገልጋይ) የስርዓተ ክወናውን CA ያምናል እና ማረጋገጫ ያከናውናል፣ ነገር ግን የElectron የፊት ክፍል
አያምነውም — ስለዚህ UIው ከመስመር ውጭ እንደሆነ ያስባል።

መፍትሔ (ሁለቱም ደረጃዎች)፦ `NODE_EXTRA_CA_CERTS=<ca.crt>`ን export ያድርጉ **እና IDEውን ከዚያ
shell እንደገና ያስጀምሩት**፤ ከዴስክቶፕ አዶው አይደለም። በመጀመሪያ IDEውን ሙሉ በሙሉ ይዝጉ — የElectron singleton lock
ማለት ሁለተኛው ማስጀመር ነባሩን ሂደት ብቻ ወደ ትኩረት ያመጣል፣ አዲሱ አካባቢም ችላ ይባላል። §3.2ን ይመልከቱ።
ይህ ራሱን የቻለ ኤጀንት በMITM በኩል የሚሠራ ሲሆን የIDEው ልዩነት ግን
በተመሳሳይ ውቅር ላይ እንደማይሠራ ከሚገልጽ ክፍት የዋና ምንጭ ሪፖርት ጋር ይመሳሰላል።

- የIDEው binary መደበኛ ባልሆነ ቦታ ውስጥ መኖሩን ያረጋግጡ
- Setup Wizard አሁንም ይሠራል — የማግኘት አለመሳካት ማለት badgeው የመጫኛ ዱካውን አያሳይም ማለት ብቻ ነው

### የhandler ስህተቶች (የupstream ሰርስሮ ማምጣት አይሳካም)

AgentBridge ጥያቄዎቹን ቢያቋርጥም ሁሉም ጥያቄዎች ካልተሳኩ፦

1. ቢያንስ አንድ provider በ`/dashboard/providers` ላይ መገናኘቱን ያረጋግጡ
2. የOmniRoute አገልጋይ ምዝግቦችን ያረጋግጡ፦ `APP_LOG_LEVEL=debug` በ`.env` ውስጥ
3. `OMNIROUTE_BASE_URL` ወደ ትክክለኛው የrouter መጨረሻ ነጥብ ማመልከቱን ያረጋግጡ (ነባሪ፦ `http://127.0.0.1:20128`)

## §8 የወደፊት ዕቅድ

### የTrae ምርመራ

Trae በአንጻራዊነት አዲስ የAI ኮድ ማጎልበቻ ረዳት ነው። ማስተናገጃ ከመተግበርዎ በፊት፦

1. በVS Code / JetBrains የመተግበሪያ ገበያዎች ውስጥ ወይም ራሱን የቻለ መተግበሪያ ከሆነ ባይነሪውን/ቅጥያውን ይለዩ
2. የAPI አስተናጋጆችን እና የመግቢያ ነጥቦችን ቅርጽ ለማወቅ ትራፊኩን በmitmproxy ይቅረጹ
3. የማረጋገጫ ዘዴውን ይወስኑ
4. በTOS እና በAPI ተገኝነት ላይ በመመርኮዝ ለመቀጠል/ላለመቀጠል ይገምግሙ

ምርመራው እስኪጠናቀቅ ድረስ፣ በዳሽቦርዱ ውስጥ ያለው የTrae ካርድ የ"በምርመራ ላይ" ባጅ ከ"የአዋጭነት ሪፖርት ያድርጉ" አገናኝ ጋር ያሳያል። `src/mitm/handlers/trae.ts` ላይ ያለው የማስተናገጃ አጽም የተዋቀረ `ገና አልተተገበረም` ስህተት ይጥላል።
