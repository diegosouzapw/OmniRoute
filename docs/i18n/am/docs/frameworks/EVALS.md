## ጽንሰ-ሐሳቦች

### ስብስብ

ስብስብ አንድ `description` እና አንድ ወይም ከዚያ በላይ ጉዳዮች ያሉት ስም የተሰጠው የሙከራ ጉዳዮች ስብስብ ነው። ስብስቦች ከሁለት ምንጮች ይመጣሉ፦

| ምንጭ        | የተገለጸበት ቦታ                                     | በአሂያጅ ጊዜ ሊለወጥ ይችላል? |
| ---------- | ---------------------------------------------- | ------------------- |
| `built-in` | በመነሻ ጊዜ በ`registerSuite()` በኩል ይመዘገባል          | አይ (በኮድ የተገለጸ)      |
| `custom`   | በSQLite `eval_suites` + `eval_cases` ውስጥ ይከማቻል | አዎ (በAPI/UI በኩል)    |

አሁን ያሉት አብሮገነብ ስብስቦች (`src/lib/evals/evalRunner.ts`ን ይመልከቱ)፦

- `golden-set` — በሰላምታ/ሒሳብ/ትርጉም/ደህንነት ዙሪያ 10 የመነሻ ጉዳዮች
- `coding-proficiency` — Python/JS/SQL/TS/የሳንካ ማወቂያ
- `reasoning-logic` — ሎጂካዊ ድምዳሜዎች፣ የቃላት ችግኞች፣ የንድፍ ማወቂያ
- `multilingual` — ትርጉም እና ቋንቋ መለየት
- `safety-guardrails` — PII፣ የደህንነት ገደብ ማለፊያ፣ እምቢታ፣ የአድሎ ግንዛቤ
- `instruction-following` — JSON ብቻ፣ ቁጥር የተሰጣቸው ዝርዝሮች፣ የቋንቋ ገደቦች
- `codex-comparison` — ለንጽጽር ሁነታ የታሰቡ ቀጥተኛ የኮድ ጽሕፈት ተግባራት

### ጉዳይ

እያንዳንዱ ጉዳይ የሚከተሉትን ይይዛል፦

| መስክ        | መግለጫ                                                         |
| ---------- | ------------------------------------------------------------ |
| `id`       | የማይለወጥ መለያ (ውጤቶችን እና መለኪያዎችን ለመፈለጊያ ቁልፍነት ይጠቅማል)             |
| `name`     | ሰው ሊያነበው የሚችል መለያ                                            |
| `model`    | አሂያጁ `suite-default` ዒላማን ሲጠቀም ነባሪ ሞዴል                       |
| `input`    | `{ messages, max_tokens? }` — ወደ `/v1/chat/completions` ይላካል |
| `expected` | `{ strategy, value }` — የውጤት አሰጣጥ መመዘኛ (ከታች ይመልከቱ)           |
| `tags`     | አማራጭ መለያዎች (ለምሳሌ `safety`፣ `pii`፣ `jailbreak`)               |

### ዒላማ

ተመሳሳዩ ስብስብ በተለያዩ ዒላማዎች ላይ ሊካሄድ ይችላል። የዒላማው መርሐግብር
በ`src/shared/validation/schemas.ts` ውስጥ `evalTargetSchema` ነው፦

| የዒላማ አይነት       | `id`      | ባህሪ                                                     |
| --------------- | --------- | ------------------------------------------------------- |
| `suite-default` | `null`    | እያንዳንዱ ጉዳይ የራሱን አብሮገነብ `model` መስክ ይጠቀማል                |
| `model`         | የሞዴል ስም   | እያንዳንዱን ጉዳይ በአንድ ቀጥተኛ ሞዴል በኩል በግድ ያስኬዳል (ለምሳሌ `gpt-4o`) |
| `combo`         | የcombo ስም | እያንዳንዱን ጉዳይ በአንድ combo በኩል ያስኬዳል (የማዞሪያ ሞተሩን ይፈትሻል)     |

ለ`model` እና `combo`፣ የ`id` መስክ ያስፈልጋል (በZod
`superRefine()` የሚተገበር)። `compareTarget` ሲቀርብ፣ ሁለቱም ዒላማዎች የተለያዩ መሆን አለባቸው —
አስኪያጁ ለA/B ንጽጽር ሁለቱንም አሂያጆች በተመሳሳይ `runGroupId` ስር ያከማቻል።

## የውጤት አሰጣጥ መመዘኛዎች

በ `evaluateCase()` (evalRunner.ts) ውስጥ ተተግብሯል፦

| ስልት        | የሚያልፈው…                                                             |
| ---------- | ------------------------------------------------------------------- |
| `exact`    | `actualOutput === expected.value`                                   |
| `contains` | `actualOutput.toLowerCase().includes(expected.value.toLowerCase())` |
| `regex`    | `new RegExp(expected.value).test(actualOutput)` እውነት ከሆነ            |
| `custom`   | `expected.fn(actualOutput, evalCase)` እውነት ከመለሰ (አብሮገነብ ብቻ)         |

**ማስታወሻ፦** ፋንክሽኖች በAPI በኩል ተከታታይ ውሂብ ሆነው ሊቀመጡ ስለማይችሉ፣ በብጁ ፋንክሽን የሚደረግ የውጤት አሰጣጥ በኮድ ለተገለጹ (አብሮገነብ)
ስብስቦች ብቻ የተያዘ ነው። `evalCaseBuilderSchema` በተጠቃሚ ለተፈጠሩ
ስብስቦች `contains | exact | regex` ብቻ ይቀበላል።

በአሁኑ ጊዜ LLM-as-judge ወይም በembedding ላይ የተመሠረተ የተመሳሳይነት መለኪያ የለም — ይህ
በ `evaluateCase()` ውስጥ ግልጽ የማስፋፊያ ነጥብ ሊሆን ይችላል።

## የውሂብ ጎታ ንድፍ

ሦስት ሰንጠረዦች (ማይግሬሽኖች `030_create_eval_runs.sql` እና
`031_create_eval_suites.sql`)፦

| ሰንጠረዥ         | ዓላማ                                                                                                                    |
| ------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `eval_suites` | የብጁ ስብስብ ሜታዳታ (`id`, `name`, `description`)                                                                            |
| `eval_cases`  | በየስብስቡ ያሉ ጉዳዮች — `input_json`, `expected_*`, `tags_json`                                                               |
| `eval_runs`   | ታሪካዊ አሂዶች — `pass_rate`, `total`, `passed`, `failed`, `avg_latency_ms`, `summary_json`, `results_json`, `outputs_json` |

አብሮገነብ ስብስቦች በDB ውስጥ **አይቀመጡም**። በማህደረ ትውስታ ውስጥ ይኖራሉ፣ እና
`evalRunner.ts` በገባ ቁጥር እንደገና ይመዘገባሉ።

## REST API

ሁሉም መዳረሻዎች የአስተዳደር ማረጋገጫ (`requireManagementAuth`) ያስፈልጋቸዋል — የሕዝብ
ፕሮክሲ በይነገጽ አካል አይደሉም።

| መዳረሻ                          | ዘዴ       | መግለጫ                                                     |
| ----------------------------- | -------- | -------------------------------------------------------- |
| `/api/evals`                  | `GET`    | ስብስቦችን + የቅርብ ጊዜ አሂዶችን + የውጤት ሰሌዳን + ዒላማዎችን + ቁልፎችን ዘርዝር |
| `/api/evals`                  | `POST`   | ስብስብን አስኪድ (ነጠላ ወይም ንጽጽር) — ንድፍ `evalRunSuiteSchema`     |
| `/api/evals/{suiteId}`        | `GET`    | አንድ ስብስብ አምጣ (አብሮገነብ ወይም ብጁ)                             |
| `/api/evals/suites`           | `POST`   | ብጁ ስብስብ ፍጠር — ንድፍ `evalSuiteSaveSchema`                  |
| `/api/evals/suites/{suiteId}` | `GET`    | ብጁ ስብስብ አምጣ                                              |
| `/api/evals/suites/{suiteId}` | `PUT`    | ብጁ ስብስብን ተካ (ጉዳዮቹ እንደገና ይገባሉ)                            |
| `/api/evals/suites/{suiteId}` | `DELETE` | ብጁ ስብስብን እና ጉዳዮቹን ሰርዝ                                    |

### ስብስብን ማስኬድ

```bash
curl -X POST http://localhost:20128/api/evals \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "suiteId": "golden-set",
    "target": { "type": "combo", "id": "my-combo" },
    "apiKeyId": "optional-api-key-uuid"
  }'
```

አማራጭ መስኮች፦

- `outputs` — አስቀድሞ የተሰሉ ውጤቶች `Record<caseId, string>`። ሲቀርብ፣
  አስኪያጁ **መላኩን ይዘላል** እና የተሸጎጡትን ውጤቶች ብቻ ይመዝናል (ከመስመር ውጭ
  ለሚደረግ ግምገማ ጠቃሚ ነው)።
- `compareTarget` — በትይዩ የሚካሄድ ሁለተኛ ዒላማ፤ ሁለቱም አሂዶች ጎን ለጎን ለማየት
  የተፈጠረ `runGroupId` ይጋራሉ።
- `apiKeyId` — የሚላኩትን `/v1/chat/completions` ጥሪዎች ለማረጋገጥ የሚያገለግል
  ውስጣዊ API ቁልፍ። `REQUIRE_API_KEY` ሲነቃ ያስፈልጋል።

## የማስተላለፊያ ፓይፕላይን

`runEvalSuiteAgainstTarget()` (`src/lib/evals/runtime.ts`)፦

1. ስብስቡን (አብሮገነብ ወይም ብጁ) ይወስናል።
2. ለእያንዳንዱ ኬዝ፣ የኬዙን `messages`፣ የተወሰነውን `model`፣ `stream: false` እና `max_tokens: 512`
   (ወይም በኬዙ የተተካውን እሴት) በመጠቀም ወደ `/v1/chat/completions` የሚላክ `Request` ይገነባል።
3. የውይይት አስተናጋጁን በቀጥታ ይጠራል (በሂደቱ ውስጥ — ተጨማሪ የHTTP ዝላይ የለም)።
4. መዘግየትን ይመዘግባል እና ጽሑፍን ከ`choices[0].message.content`
   ወይም ከResponses-API `output[]` ጭነት ያወጣል።
5. ሁሉንም ውጤቶች በ`runSuite()` ደረጃ ይሰጣል፣ ከዚያም በ`saveEvalRun()` ያስቀምጣቸዋል።

ኬዞች **በቅደም ተከተል** ይከናወናሉ። በአሁኑ ጊዜ የትይዩነት ጠቋሚ የለም።

## ዳሽቦርድ

የተጠቃሚ በይነገጹ በ`Dashboard → Usage → Evals`
(`src/app/(dashboard)/dashboard/usage/components/EvalsTab.tsx`) ይገኛል። ከዚያ የሚከተሉትን
ማድረግ ይችላሉ፦

- አብሮገነብ እና ብጁ ስብስቦችን በእያንዳንዱ ኬዝ ቅድመ ዕይታ ማሰስ።
- በኬዝ መገንቢያው ብጁ ስብስቦችን መፍጠር/ማርትዕ/መሰረዝ።
- ዒላማ (የስብስብ ነባሪዎች / ሞዴል / ጥምረት) መምረጥ፣ እንደ አማራጭ ሁለተኛ
  `compareTarget` እና API ቁልፍ መምረጥ፣ ከዚያም በፍላጎት ማስኬድ።
- የማስኬድ ታሪክን፣ በእያንዳንዱ ኬዝ ማለፍ/መውደቅን፣ መዘግየትን እና የተመዘገቡ ውጤቶችን መመርመር።
- በእያንዳንዱ `(suite, target)` ወሰን ውስጥ ካለው የቅርብ ጊዜ ማስኬድ የተጠቃለለውን ተንከባላይ የውጤት ሰሌዳ ማየት።

## ከAuto-Assessment RFC ጋር ያለው ግንኙነት

የተለየና ይበልጥ የተወሰነ የግምገማ ንዑስ ስርዓት በ`src/domain/assessment/`
ውስጥ ይገኛል (ለቀጥታ የውጤት አሰጣጥ ሞተሩ [AUTO-COMBO.md](../routing/AUTO-COMBO.md)ንም ይመልከቱ)።
ያ ንዑስ ስርዓት የAuto Combo ሞተሩን ዒላማ ያደርጋል — የላይኛው ምንጭ ሲበላሽ ጥምረቶች ራሳቸውን
እንዲጠግኑ አቅራቢዎችን እና ሞዴሎችን በራስ-ሰር ደረጃ ይሰጣል። የራሱን ማስኬጃ፣
የራሱን መደብ መዳቢ እና የራሱን የውጤት አሰጣጥ አመክንዮ ይጠቀማል።

እዚህ የተዘገበው የEvals ማዕቀፍ **ሰፋ ያለ፣ አጠቃላይ ዓላማ ያለው
የሙከራ ገጽታ** ነው። ለማናቸውም የድግግሞሽ ስህተት ሙከራ ስብስቦች፣ የA/B ንጽጽሮች
እና የእያንዳንዱ ልቀት መሰረታዊ ሙከራዎች ይህን ይምረጡ። ቅጽበታዊ የአቅራቢ ጤና
የማዘዋወር ውሳኔዎችን እንዲያሳድር ሲፈልጉ የAuto-Assessment ንዑስ ስርዓትን ይጠቀሙ።

## የCI ውህደት

በአሁኑ ጊዜ የተለየ `eval:ci` npm ስክሪፕት የለም። ልቀቶችን በግምገማ ውጤቶች ላይ
ተመስርተው እንዲያልፉ ከፈለጉ ሁለት መንገዶች አሉ፦

- **የHTTP መንገድ**፦ ሰርቨሩን ያስነሱ፣ የታወቀ `suiteId` + `target` በመጠቀም
  `POST /api/evals`ን ይጠሩ እና በምላሹ ውስጥ `runs[].summary.passRate >= N` መሆኑን
  ያረጋግጡ።
- **በሂደት ውስጥ የሚከናወን መንገድ**፦ በስክሪፕት ውስጥ `runEvalSuiteAgainstTarget()`ን
  ከ`@/lib/evals/runtime` ያስመጡ፣ በሙከራ DB ላይ ያስኪዱ እና የተመለሰውን
  `PersistedEvalRun.summary` ይፈትሹ።

መስመሩን እና ታሪኩን የሚሸፍኑ ሙከራዎች በ
`tests/unit/evals-route.test.ts` እና `tests/unit/evals-history.test.ts` ይገኛሉ።

## የማስፋፊያ ነጥቦች

የተለመዱ ለውጦች እና ለውጦቹን የሚያደርጉባቸው ቦታዎች፦

- **አዲስ የውጤት አሰጣጥ ስልት** — በ`evaluateCase()` (`evalRunner.ts`) ውስጥ ያለውን
  `switch (evalCase.expected.strategy)` ብሎክ ያስፋፉ እና በ
  `src/lib/db/evals.ts` ውስጥ `EvalCaseStrategy`ን፣ እንዲሁም በ`schemas.ts` ውስጥ
  `evalCaseBuilderSchema`ን ያስፉ።
- **አዲስ አብሮገነብ ስብስብ** — የስብስብ ኦብጀክት ይግለጹ እና በ
  `evalRunner.ts` ግርጌ `registerSuite()`ን ይጥሩ። በ`listSuites()` በራስ-ሰር ይገኛል።
- **በትይዩነት ማስኬድ** — በ`runEvalSuiteAgainstTarget()` ውስጥ ያለውን ተከታታይ `for` ሉፕ
  ወደ የተገደበ `Promise.all` ይቀይሩ (በአሁኑ ጊዜ የትይዩነት መቆጣጠሪያ የለም)።
- **የዥረት/የመሣሪያ-ጥሪ ኬዞች** — በአሁኑ ጊዜ ማስኬጃው `stream: false`ን በግድ ይጠቀማል።
  የዥረት ወይም መሣሪያን የሚያውቅ ግምገማ በ`runtime.ts` ውስጥ ለውጦችን ይፈልጋል
  (ውጤት ከመስጠት በፊት የSSE ቁርጥራጮችን መመዝገብ እና ማጠቃለል)።
