## ለምን የተለየ Workspace Package ያስፈልጋል?

`open-sse/` በOmniRoute monorepo ውስጥ **ራሱን የቻለ workspace** የሆነው በበርካታ ምክንያቶች ነው፦

1. **እንደገና መጠቀም** — `open-sse` በnpm ላይ እንደ `@omniroute/open-sse` ይታተማል፣ ስለዚህ ሌሎች ፕሮጀክቶች በተናጥል ሊጠቀሙበት ይችላሉ
2. **ግልጽ ድንበሮች** — የዥረት ሞተሩ ከOmniRoute-ተኮር UI/DB ንብርብር ተነጥሏል
3. **አፈጻጸም** — ሞተሩ የNext.js ጥገኞች የሉትም፣ ይህም በCLI/serverless አውዶች ፈጣን የመጀመሪያ ማስነሳትን ያስችላል
4. **የስሪት አስተዳደር** — `open-sse` በራሱ የጊዜ ሰሌዳ ልቀት ማድረግ ይችላል

```json
// package.json
"workspaces": ["open-sse"]
```

## የጥያቄ ማስኬጃ ቅደም ተከተል

እያንዳንዱ የLLM ጥያቄ በ**5-ደረጃ የማስኬጃ ቅደም ተከተል** ውስጥ ያልፋል፦

```
                              ┌──────────────┐
   HTTP ጥያቄ                  │  1. ROUTE    │   የcombo መፍታት፣ የmodel ምርጫ
   (Next.js route)             └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  2. TRANSLATE│   የቅርጸት ልወጣ (OpenAI ↔ Claude ↔ Gemini)
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  3. EXECUTE  │   የprovider executor፣ HTTP፣ ድጋሚ ሙከራ፣ breaker
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  4. STREAM   │   የSSE ለውጥ፣ backpressure
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  5. RECORD   │   የአጠቃቀም ክትትል፣ የጥሪ ምዝግብ፣ የስህተት ምደባ
                              └──────┬───────┘
                                     │
                                     ▼
                              HTTP ምላሽ (SSE ወይም JSON)
```

### ደረጃ 1፦ Route (services/combo.ts)

**መግቢያ ነጥብ**: በ`services/combo.ts` ውስጥ ያለው `handleComboChat()`

ጥያቄውን ወደ ተወሰነ `(provider, model, account, credentials)` tuple ይፈታል፦

- combo-ውን በID ይፈልጉ (ወይም ለ`auto/*` models ምናባዊ combo ይገንቡ)
- የrouting ስልቱን ይተግብሩ (priority፣ weighted፣ round-robin፣ ወዘተ)
- ጤናማ ያልሆኑ providersን ያጣሩ (circuit breaker)
- ቀጣዩን አዋጭ target ይምረጡ

ለ`auto/*` models፣ ይህ ደረጃ የሚከተሉትንም ያከናውናል፦

- የ**16-factor scoring** algorithmን ያስኬዳል (`services/autoCombo/`)
- በጤና፣ ወጪ፣ latency፣ ወዘተ ላይ በመመሥረት የ`provider+model` ጥምረት ይመርጣል

### ደረጃ 2፦ Translate (translator/)

የምንጭ ቅርጸቱ (ለምሳሌ፣ OpenAI) ከዒላማ ቅርጸቱ (ለምሳሌ፣ Claude) የተለየ ከሆነ፣ ጥያቄው **ይተረጎማል**፦

- System prompt → system message
- የTool ትርጓሜዎች → ለprovider የተወሰነ የtool ቅርጸት
- የReasoning/thinking parameters → ለprovider የተወሰኑ ተመጣጣኝ አማራጮች
- የMessage role normalization (`developer` → `system` ለOpenAI ላልሆኑ)

`translator/index.ts` የሚከተሉትን ያቀርባል፦

```ts
translateRequest(body, sourceFormat, targetFormat): TranslatedRequest
needsTranslation(source, target): boolean
```

### ደረጃ 3፦ Execute (executors/)

**መግቢያ ነጥብ**: `getExecutor(providerId).execute(request, options)`

ሁሉም providers በ`getExecutor()` factory fallback አማካኝነት `DefaultExecutor`ን (`executors/default.ts`) ይጠቀማሉ። executor-ው፦

- ወደ upstream የሚሄደውን URL ይገነባል (`buildUrl()`)
- ለprovider የተወሰኑ headersን ይጨምራል (`buildHeaders()`)
- የጥያቄውን body ይለውጣል (`transformRequest()`)
- የHTTP ጥያቄውን ከድጋሚ ሙከራ + exponential backoff ጋር ይልካል
- አስፈላጊ ከሆነ የauth refreshን ያስተናግዳል (OAuth providers)

ሁሉም executors `BaseExecutor`ን (`executors/base.ts`፣ 1170 LOC) ይወርሳሉ፣ ይህም የሚከተሉትን ያቀርባል፦

- የጋራ የድጋሚ ሙከራ ሎጂክ
- የProxy ውህደት
- የCircuit breaker ውህደት
- የአጠቃቀም ምዝገባ hooks

### ደረጃ 4፦ Stream (utils/stream.ts)

ለዥረት ምላሾች፣ executor-ው **ReadableStream** ይመልሳል። handler-ው፦

- በSSE transform በኩል ያሳልፋል (`createSSETransformStreamWithLogger`)
- የተቋረጡ ግንኙነቶችን ለመለየት heartbeat pingsን ይተገብራል
- የclient ግንኙነት መቋረጥን በአግባቡ ያስተናግዳል (`pipeWithDisconnect`)
- ዥረት ለማይጠቀሙ clients SSE → JSON ይለውጣል

ዥረት ላልሆኑ ምላሾች፣ executor-ው የተተነተነ JSON object ይመልሳል፣ እሱም ምንም ሳይለወጥ ይተላለፋል።

### ደረጃ 5፦ Record (services/usage.ts)

ምላሹ ከተሰጠ በኋላ (የተሳካም ሆነ ያልተሳካ)፣ አጠቃቀሙ ይመዘገባል፦

- ከምላሹ የተገኙ `prompt_tokens`፣ `completion_tokens`፣ `cached_tokens`
- ከዋጋ መረጃው የሚሰላ `cost_usd`
- `latency_ms`፣ `status`፣ እና ካልተሳካ `error_class`
- በ`usage_history` ሰንጠረዥ ውስጥ ይቀመጣል

የጥሪ ምዝግብ ቅርሶች (ከነቃ) ወደ `${DATA_DIR}/call_logs/` ይጻፋሉ።

### chatCore.ts (5977 መስመሮች)

**ዋናው የጥያቄ አስተናጋጅ**። ምንም እንኳን መጠኑ ቢሰፋም፣ ግልጽ አወቃቀር አለው፦

```ts
// የchatCore.ts ምስላዊ አወቃቀር
export async function handleChat(request: NextRequest) {
  // 1. ማረጋገጫ + CORS
  await authenticateRequest(request);
  applyCorsHeaders(response);

  // 2. የbody ማረጋገጫ
  const body = await parseRequestBody(request);

  // 3. የቅርጸት መለየት + ትርጉም
  const sourceFormat = detectFormat(request);
  const targetFormat = getTargetFormat(providerId);
  if (needsTranslation(sourceFormat, targetFormat)) {
    body = translateRequest(body, sourceFormat, targetFormat);
  }

  // 4. የኮምቦ ማዞሪያ
  const targets = await resolveComboTargets(comboId, body);
  for (const target of targets) {
    try {
      const result = await executeOnTarget(target, body);
      await recordUsage(result);
      return result;
    } catch (err) {
      // ወደ ቀጣዩ ዒላማ ቀጥል
    }
  }

  // 5. የአስቸኳይ ጊዜ አማራጭ መንገድ
  return await emergencyFallback(body);
}
```

### base.ts (1170 LOC)

እያንዳንዱ የአስፈጻሚ ክላስ የሚያራምደው **አርጆ አስፈጻሚ (abstract executor)** ነው (በቀጥታ ወይም በ`DefaultExecutor` እና ሌሎች ንዑስ ክላሶች በኩል)። የሚከተሉትን ይዟል፦

```ts
// open-sse/executors/default.ts

  // አቅራቢዎች ውቅሮችን (URL፣ ማረጋገጫ፣ ራስጌዎች) ይመዘግባሉ ግን የአስፈጻሚ ሎጂክን ያጋራሉ
```

```ts
import { needsTranslation, translateRequest } from "@omniroute/open-sse/translator";

if (needsTranslation(sourceFormat, targetFormat)) {
```

የተለመዱ ትርጉሞች፦

- `OpenAI → Responses API`፦ `input` ድርድር፣ `previous_response_id` ሁኔታ

- `system` ሚና → ለGLM/ERNIE ከመጀመሪያው የተጠቃሚ መልዕክት ጋር ይዋሃዳል

- `tools` → ለአቅራቢው የተለየ የመሣሪያ ቅርጸት
- የማሰብ መለኪያዎች (o1፣ Claude) → ለአቅራቢው የተለዩ አቻዎች

## MCP አገልጋይ

`open-sse/mcp-server/` የ**Model Context Protocol** አገልጋዩን ይተገብራል፦

- **110 መሣሪያዎች** (የአቅራቢ አስተዳደር፣ ጥምረቶች፣ ማህደረ ትውስታ፣ መሸጎጫ፣ ማመቅ፣ ተኪ፣ ክህሎቶች፣ ጨዋታዊነት፣ ተሰኪዎች፣ Notion፣ Obsidian፣ አካባቢያዊ ኮርፐስ)
- **3 ማጓጓዣዎች**፦ stdio፣ SSE፣ Streamable HTTP
- ለዝርዝር ፈቃድ አሰጣጥ **33 ወሰኖች**

### የመሣሪያ ምዝገባ

መሣሪያዎች በ`open-sse/mcp-server/tools/` ውስጥ እንደ ገለልተኛ ፋይሎች ይመዘገባሉ፤ እያንዳንዳቸው ስም፣ መርሐግብር፣ አስተናጋጅ እና ወሰን ወደ ውጭ ያቀርባሉ፦

```ts
// open-sse/mcp-server/tools/getHealth.ts
import { z } from "zod";
export default {
  name: "omniroute_get_health",
```

## ቀያሪዎች

`open-sse/transformer/` በ**Chat Completions** እና **Responses API** ቅርጸቶች መካከል ይቀይራል።

### የተለየ ቀያሪ ለምን ያስፈልጋል?

Responses API **ሁኔታን የሚይዙ ውይይቶች** (`previous_response_id`) ያሉት የOpenAI አዲስ ቅርጸት ነው። ደንበኛ የResponses ጥያቄ ሲልክ፣ OmniRoute፦

1. Responses → Chat Completions በውስጣዊ መንገድ ይቀይራል
2. ወደ አቅራቢው ይልካል (Chat Completionsን የሚደግፍ ማንኛውም አቅራቢ)
3. ምላሹን መልሶ ወደ Responses ቅርጸት ይቀይራል
4. የተቀየረውን ምላሽ ወደ ደንበኛው በዥረት ይልካል

ቀያሪው (`transformer/responsesTransformer.ts`) የሚከተለውን ያቀርባል፦

```ts
createResponsesApiTransformStream(): TransformStream
```

ይህ የሚከተሉትን ያስተናግዳል፦

- `response.output_item.added` ክስተቶች
- `response.output_text.delta` ክስተቶች
- `response.completed` ክስተት
- የመሣሪያ ጥሪ ማዛመድ (`function_call` ↔ `tool_calls`)
