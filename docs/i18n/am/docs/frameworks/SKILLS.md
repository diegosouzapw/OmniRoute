OmniRoute የቋንቋ ሞዴሎች (እና ኦፕሬተሮች) እንደገና ጥቅም ላይ የሚውሉ ችሎታዎችን — ከፋይል ስርዓት ንባብ እና HTTP ጥያቄዎች እስከ በsandbox የተገደበ የኮድ አፈጻጸም እና በጥንቃቄ የተመረጡ የገበያ ቦታ ክህሎቶች — እንዲያቀናብሩ የሚያስችል ሊስፋፋ የሚችል የSkills ማዕቀፍ ያቀርባል።

አንድ skill በስሪት የሚተዳደር፣ በschema የተገለጸ የሥራ አሃድ ነው። OmniRoute በወጪ ጥያቄዎች ውስጥ skillsን እንደ tool definitions ሊያስገባ፣ ከሞዴሉ ተመልሰው የሚመጡ tool callsን ሊያቋርጥ፣ ተዛማጁን handler ሊያስኬድ እና ውይይቱ እንዲቀጥል ውጤቱን መልሶ ለሞዴሉ ሊያቀርብ ይችላል። ሞዴሉ implementationን ፈጽሞ አያይም — የtool interfaceን ብቻ ነው የሚያየው።

## Agent Skills ከ Omni Skills ጋር ሲነጻጸሩ

OmniRoute ሁለት የተለያዩ ግን እርስ በርስ የሚደጋገፉ የskill ስርዓቶች አሉት፦

| መለኪያ         | **Omni Skills** (ይህ ሰነድ)                              | **Agent Skills**                                                                            |
| :----------- | :---------------------------------------------------- | :------------------------------------------------------------------------------------------ |
| ዓላማ          | የLLM tool ማስገባት + በsandbox የተገደበ አፈጻጸም                | ውጫዊ agents እንዲያገኙትና እንዲጠቀሙበት የSKILL.md ካታሎግ                                                 |
| የእውነት ምንጭ    | `src/lib/skills/` + የገበያ ቦታ                           | `src/lib/agentSkills/` + `skills/` ማውጫ                                                      |
| የruntime ሁነታ | ወደ ውጪ በሚላኩ ጥያቄዎች ውስጥ ይገባል፣ በtool-call events ላይ ይፈጸማል | የማይለወጥ markdown ካታሎግ + REST/MCP/A2A የማግኛ endpoints                                          |
| ማን ይጠቀምበታል   | OmniRoute ራሱ (combo routing፣ ገቢ LLM calls)            | ውጫዊ agents፣ MCP clients፣ A2A orchestrators                                                  |
| ብዛት          | ተለዋዋጭ (በገበያ ቦታ የሚመራ)                                  | 45 የካታሎግ ግቤቶች (23 API + 21 CLI + 1 config)                                                  |
| ቅርጸት         | `SkillDefinition` ከtool schema + handler ጋር           | `SKILL.md` frontmatter + markdown body                                                      |
| ማግኘት         | `/api/skills/*` REST + `omniroute_skills_*` MCP tools | `/api/agent-skills/*` REST + `omniroute_agent_skills_*` MCP tools + A2A `list-capabilities` |

**Omni Skills** የአፈጻጸም ሞተር ናቸው — አንድ LLM toolን ሲጠራ OmniRoute _ምን ማድረግ እንደሚችል_ ይገልጻሉ።

**Agent Skills** የሰነድ ካታሎግ ናቸው — በቀጥታ ወደ agent prompts ሊገቡ በሚችሉ የተዋቀሩ SKILL.md ፋይሎች አማካኝነት፣ ውጫዊ agents የOmniRouteን REST API እና CLI _እንዴት መጠቀም እንዳለባቸው_ ያብራራሉ።

ስለ Agent Skills ካታሎግ፣ generator፣ MCP tools እና A2A skill፣ [docs/frameworks/AGENT-SKILLS.md](./AGENT-SKILLS.md)ን ይመልከቱ።

## ጽንሰ-ሐሳቦች

### የSkill ምንጮች

ሦስት የskills ምንጮች በአንድ registry ውስጥ አብረው ይኖራሉ፦

1. **አብሮገነብ skills** (`src/lib/skills/builtins.ts`) — ከOmniRoute ጋር ይቀርባሉ። የተለመዱ አጠቃቀሞችን ይሸፍናሉ፦
   - `file_read`, `file_write` — በእያንዳንዱ API key የተለየ sandbox workspace በ`<DATA_DIR>/skills/workspaces/<hashed-key>/` ስር
   - `http_request` — በ`safeOutboundFetch` በኩል ወደ ውጪ የሚላክ HTTP፣ ከ`guard: "public-only"` ጋር
   - `web_search` — ከcaching (`executeWebSearch`) ጋር ሊቀየር የሚችል search provider
   - `eval_code` — በDocker sandbox የተገደበ `node` ወይም `python` አፈጻጸም
   - `execute_command` — በDocker sandbox የተገደበ የshell command
   - `browser` — በPlaywright የሚደገፍ scaffolding፣ በነባሪ የተሰናከለ (`builtin/browser.ts`)
2. **SkillsMP** (የOmniRoute የገበያ ቦታ) — ከ`https://skillsmp.com/api/v1/skills/search` ይመጣል። በSettings ውስጥ `skillsmpApiKey` ያስፈልጋል።
3. **SkillsSH** (`skills.sh` የማህበረሰብ ካታሎግ) — ከ`https://skills.sh/api/search` ይመጣል። ማረጋገጫ አያስፈልግም፤ የSKILL.md ይዘት ከGitHub raw ይወሰዳል።

አንድ "active provider" dashboardው ከየትኛው ካታሎግ እንደሚጭን ይቆጣጠራል (`src/lib/skills/providerSettings.ts`)። በ**Settings → Memory & Skills** ስር ይቀይሩት። ነባሪ፦ `skillsmp`።

### የSkill ማንነት

Skills በin-memory registry (`src/lib/skills/registry.ts`) ውስጥ በ`name@version` ቁልፍ ይመዘገባሉ። ስሪቱ semver (`^\d+\.\d+\.\d+$`) መሆን አለበት። `resolveVersion()` የ`^`፣ `~`፣ `>`፣ `>=`፣ `<`፣ `<=`፣ `==` እና ትክክለኛ ተዛማጅ ገደቦችን ይረዳል።

### የSkill ሁነታ

እያንዳንዱ skill መቼ እንደሚገባ የሚቆጣጠር runtime ሁነታ አለው፦

| ሁነታ    | ባህሪ                                                                 |
| ------ | ------------------------------------------------------------------- |
| `on`   | ሁልጊዜ እንደ tool definition ይገባል                                       |
| `off`  | ፈጽሞ አይገባም፣ ፈጽሞም ሊፈጸም አይችልም                                          |
| `auto` | ከገቢው ጥያቄ አንጻር ነጥብ ይሰጠዋል፤ ነጥቡ ≥ `AUTO_MIN_SCORE` (ነባሪ 3) ከሆነ ብቻ ይገባል |

`auto` ከገበያ ቦታ ለተጫኑ skills ነባሪው ነው። `enabled=true` እና `mode="off"` አብረው "የተመዘገበ ግን ንቁ ያልሆነ" ማለት ነው — በlegacy column በኩል `enabled`ን መቀያየር የቆዩ codepaths ወጥነታቸውን እንዲጠብቁ `mode`ንም ያሻሽላል (`src/app/api/skills/[id]/route.ts`)።

### ሁኔታ (አፈጻጸሞች)

የSkill አፈጻጸሞች በ`skill_executions` table ውስጥ በሚከተሉት ሁኔታዎች ይከታተላሉ (`src/lib/skills/types.ts`)፦

```ts
enum SkillStatus {
  PENDING = "pending",
  RUNNING = "running",
  SUCCESS = "success",
  ERROR = "error",
  TIMEOUT = "timeout",
}
```

### የRegistry Cache

`SkillRegistry` የ60 ሰከንድ TTL cache (`registry.ts:14`) ያለው singleton ነው። `loadFromDatabase()` idempotent ሲሆን በ`pendingLoad` አማካኝነት በተመሳሳይ ጊዜ የሚደረጉ ጥሪዎችን ያስወግዳል። ማንኛውም write (`register`/`unregister`/`unregisterById`) cacheን ዋጋ አልባ ያደርገዋል። ስሪቶችን በ`getSkillVersions(name)` እና `resolveVersion(name, constraint)` ይፈልጉ።

### Providerን ያገናዘበ ማስገባት

በ`src/lib/skills/injection.ts` ውስጥ ያለው `injectSkills()` የተመዘገቡ skillsን ወደ provider-specific tool definitions የሚቀይር የመግቢያ ነጥብ ነው፦

- **OpenAI** — `{ type: "function", function: { name, description, parameters } }`
- **Anthropic** — `{ name, description, input_schema }`
- **Google (Gemini)** — `{ name, description, parameters }`

ሞዴሉ መልሶ ሲጠራው ተቆጣጣሪው ትክክለኛውን ስሪት መምረጥ እንዲችል የመሣሪያው ስም እንደ `name@version` ይቀመጣል።

`score >= AUTO_MIN_SCORE = 3` ያላቸው ከፍተኛዎቹ `AUTO_MAX_SKILLS = 5` ክህሎቶች ይካተታሉ። እኩል ውጤቶች በ`installCount` (ከከፍተኛ ወደ ዝቅተኛ)፣ ከዚያም በፊደል ቅደም ተከተል ስም ይወሰናሉ (`injection.ts:225-235`)።

### የመሣሪያ ጥሪ መጥለፍ

በ`src/lib/skills/interception.ts` ውስጥ ያለው `handleToolCallExecution()`፣ ከላይኛው አገልግሎት የመሣሪያ ጥሪ ምላሽ ከተመለሰ በኋላ በውይይት ተቆጣጣሪው ይጠራል፦

1. `extractToolCalls()` ለእያንዳንዱ አቅራቢ የተለዩ ቅርጾችን ያነባል (OpenAI `tool_calls` / Responses `function_call`፣ Anthropic `tool_use`፣ Gemini `functionCalls`)።
2. አብሮገነብ የመሣሪያ ተለዋጭ ስሞች (ለምሳሌ፣ `omniroute_web_search` → `web_search`) በመጀመሪያ ይፈታሉ። አብሮገነብ ተቆጣጣሪዎች በቦታው ይሰራሉ።
3. ሌላ ማንኛውም ነገር በ`skillExecutor.execute(name@version, args, { apiKeyId, sessionId })` በኩል ይመራል።
4. ውጤቶች እንደአግባቡ መልሰው በምላሹ ውስጥ ይገባሉ — `tool_results`፣ `function_call_output` ንጥሎች፣ ወይም Anthropic `tool_result` ብሎኮች።

በማስፈጸሚያ ዐውድ ውስጥ ያለው `customSkillExecutionEnabled`፣ አብሮገነብ መጥለፍን ብቻ ለመፍቀድ `false` ሊደረግ ይችላል (በተጠቃሚ የተወሰኑ ተቆጣጣሪዎችን በግልጽ ሁኔታ በሚያሰናክሉ የጥያቄ መንገዶች ይጠቀማል)።

## Docker ሳንድቦክስ

አብሮ ያልተሰሩ የኮድ መንገዶች (`eval_code`, `execute_command`) በDocker ውስጥ በ`SandboxRunner` (`src/lib/skills/sandbox.ts`) በኩል ይሰራሉ። እያንዳንዱ ኮንቴይነር በሚከተሉት አማራጮች ይጀመራል፦

```
--rm --network none|bridge --cap-drop ALL
--security-opt no-new-privileges --pids-limit 100
--cpus <cpuLimit/1000> --memory <memoryLimit>m
--tmpfs /tmp:rw,noexec,nosuid,size=64m
--tmpfs /workspace:rw,noexec,nosuid,size=64m
--read-only (readOnly=true ሲሆን)
```

ነባሪዎች (`SandboxRunner.DEFAULT_CONFIG`)፦

| መስክ              | ነባሪ             | ማስታወሻዎች                                              |
| ---------------- | --------------- | ---------------------------------------------------- |
| `cpuLimit`       | 100 (= 0.1 CPU) | ወደ `--cpus` ከመተላለፉ በፊት በ1000 ይካፈላል                   |
| `memoryLimit`    | 256 MB          | ጥብቅ ገደብ                                              |
| `timeout`        | 30000 ms        | በ`SIGTERM` + `docker kill` አማካኝነት ለስላሳ ማቋረጥ          |
| `networkEnabled` | `false`         | ወደ `--network none` ይቀየራል                            |
| `readOnly`       | `true`          | Root FS ለንባብ ብቻ ነው፤ `/tmp` እና `/workspace` tmpfs ናቸው |

`SandboxRunner.kill(id)` እና `killAll()` ለመዝጋት ተጋልጠዋል፤ እየሰሩ ያሉ ኮንቴይነሮች በ`runningContainers: Map<string, ChildProcess>` ውስጥ ይከታተላሉ።

### የሳንድቦክስ የአካባቢ ተለዋዋጮች

በ`src/lib/skills/builtins.ts` ውስጥ በ`process.env` በኩል የተዋቀሩ፦

| የአካባቢ ተለዋዋጭ                       | ነባሪ              | ዓላማ                                                              |
| --------------------------------- | ---------------- | ---------------------------------------------------------------- |
| `SKILLS_MAX_FILE_BYTES`           | `1048576` (1 MB) | ለ`file_read` እና `file_write` ገደብ                                 |
| `SKILLS_MAX_HTTP_RESPONSE_BYTES`  | `256000`         | ለ`http_request` ምላሽ አካል ገደብ                                      |
| `SKILLS_MAX_SANDBOX_OUTPUT_CHARS` | `100000`         | ወደ ጠሪው ለሚመለሱ stdout/stderr ገደብ                                   |
| `SKILLS_SANDBOX_TIMEOUT_MS`       | `10000`          | በሳንድቦክስ ውስጥ ለሚሰሩ ትዕዛዞች ነባሪ የጊዜ ገደብ፤ ከፍተኛው 60 s ነው                |
| `SKILLS_SANDBOX_NETWORK_ENABLED`  | `false`          | ለውጪ ግንኙነት ዋና መቆጣጠሪያ። በእያንዳንዱ ጥሪ ማስቻልን ለመፍቀድ `1` ወይም `true` ያድርጉት |
| `SKILLS_ALLOWED_SANDBOX_IMAGES`   | (ከታች ይመልከቱ)      | በነጠላ ሰረዝ የተለያዩ የተፈቀዱ Docker images                               |

በነባሪ የተፈቀዱ images፦ `alpine:3.20`, `node:22-alpine`, `python:3.12-alpine`። በ`SKILLS_ALLOWED_SANDBOX_IMAGES` በኩል የሚጨመሩ ማናቸውም images ከነባሪዎቹ ጋር ይዋሃዳሉ፤ የማይታወቁ images በ`normalizeImage()` ውድቅ ይደረጋሉ።

> ማስታወሻ፦ የተለየ `SKILLS_EXECUTION_TIMEOUT_MS` የአካባቢ ተለዋዋጭ የለም። የሳንድቦክስ ያልሆነው አስተናጋጅ የጊዜ ገደብ በ`SkillExecutor` (`executor.ts:13`) ውስጥ ወደ 30 s በቋሚነት ተቀምጧል፤ ነገር ግን በሂደት ጊዜ በ`skillExecutor.setTimeout(ms)` ሊተካ ይችላል።

### የሥራ ቦታ ማግለል

`file_read` እና `file_write` እያንዳንዱን መንገድ በ`<DATA_DIR>/skills/workspaces/<sha256(apiKeyId).slice(0,24)>/` ላይ ካለው ለእያንዳንዱ API ቁልፍ የተመደበ የሥራ ቦታ አንጻር ይፈታሉ። የመንገድ ማቋረጥ (`..`) እና የተከለከሉ ክፍሎች (`.env`, `.git`, `.ssh`, `.omniroute`, `.codex`, `secrets`) ማንኛውም የዲስክ I/O ከመከናወኑ በፊት ውድቅ ይደረጋሉ።

### የHTTP ደህንነት ማጠናከሪያ

`http_request` (`builtins.ts:257`)፦

- የተፈቀዱ ዘዴዎች ዝርዝር፦ `GET, HEAD, POST, PUT, PATCH, DELETE`
- የታገዱ ወደ ውጪ የሚላኩ ራስጌዎች፦ `host, connection, content-length, cookie, set-cookie, authorization, proxy-authorization`
- አቅጣጫ ማዞሪያዎች ተሰናክለዋል (`allowRedirect: false`)
- `guard: "public-only"` በሆነው `safeOutboundFetch` በኩል ይመራል (የግል/loopback ክልሎች ታግደዋል)
- ምላሹ በ`SKILLS_MAX_HTTP_RESPONSE_BYTES` ላይ ይቆረጣል፤ ደንበኛው `truncated: true` ያያል

## REST API

ሁሉም የመዳረሻ ነጥቦች በ`src/app/api/skills/` ስር ይገኛሉ። የአስተዳደር መዳረሻ ነጥቦች (`/api/skills`፣ `/api/skills/[id]`፣ `/api/skills/install`) በ`requireManagementAuth()` በኩል **የአስተዳደር ማረጋገጫ** ይፈልጋሉ። የገበያ/ጭነት ፍሰቶቹ ቀለል ያለውን `isAuthenticated()` (ክፍለ ጊዜ ወይም API ቁልፍ) ይጠቀማሉ።

| የመዳረሻ ነጥብ | ሜተድ | ዓላማ |
| --------------------------------- | ------ | ------------------------------------------------------------------------ | --- | ------------------------ | -------- | ------------------ |
| `/api/skills` | GET | የተመዘገቡ ክህሎቶችን ዘርዝር። `?q=`፣ `?mode=onን                        | off | auto`፣ `?source=skillsmp | skillssh | local`፣ ገጽ ከፈላ |

`settings.skillsEnabled === false` ሲሆን፣ `POST /api/skills/executions` መዳረሻ ነጥቡ HTTP `503`ን ከ`{ error: "Skills execution is disabled..." }` ጋር ይመልሳል (`executor.ts:42-45`)። ኦፕሬተሮች ዋናውን መቀየሪያ ከ**ቅንብሮች → AI** ማብራት ይችላሉ።

### ምሳሌ፦ ብጁ ክህሎት መጫን

```bash
curl -X POST http://localhost:20128/api/skills/install \
  -H "Authorization: Bearer $OMNIROUTE_MGMT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "reverse-text",
    "version": "1.0.0",
    "description": "Reverses a string",
    "schema": {
      "input":  { "type": "object", "properties": { "text": { "type": "string" } }, "required": ["text"] },
      "output": { "type": "object", "properties": { "reversed": { "type": "string" } } }
    },
    "handlerCode": "echo-handler",
    "apiKeyId": "your-api-key-id"
  }'
```

የ`handlerCode` ሕብረቁምፊ **የማስተናገጃ ስም ፍለጋ** ነው — ሊፈጸም የሚችል ኮድ አይደለም። አስፈጻሚው `skillExecutor.registerHandler(name, fn)` (`executor.ts:25`)ን በመጠቀም ያዛምደዋል። የገበያ ጭነቶች የSKILL.md ጽሑፍን እንደ ሰነድ በዚህ መስክ ያከማቻሉ፣ እና አፈጻጸሙን በሞዴል በተፈጠሩ የመሣሪያ ጥሪዎች በኩል ያስተላልፋሉ። በተጠቃሚ የቀረበ የዘፈቀደ ምንጭ eval አይደረግም።

## የክወና ምክሮች

- **ዋና ማብሪያ/ማጥፊያ፦** `settings.skillsEnabled = false` ሁሉንም አፈጻጸም ይከለክላል፣ እና በ`/api/skills/executions` ላይ HTTP `503` ይመልሳል። registryው መጫኑን ይቀጥላል።
- **የውጪ ግንኙነትን ይዝጉ፦** ሙሉ በሙሉ ከአውታረ መረብ የተነጠለ sandboxing ለማድረግ `SKILLS_SANDBOX_NETWORK_ENABLED`ን ሳያቀናብሩ ይተዉት (ነባሪ)። በእያንዳንዱ ጥሪ `networkEnabled: true` ቢሆንም አሁንም ዋናውን gate ይፈልጋል።
- **የተወሰኑ imagesን ይፍቀዱ፦** allowlistን ለማስፋት `SKILLS_ALLOWED_SANDBOX_IMAGES="myorg/sandbox:1.0,node:22-alpine"`ን ያቀናብሩ።
- **አፈጻጸሞችን ኦዲት ያድርጉ፦** `/dashboard/skills/executions` እና `omniroute_skills_executions` ሁለቱም `skill_executions`ን ይጠይቃሉ። የተሳኩ አሂዶች `durationMs`ን ያካትታሉ፤ ያልተሳኩት `errorMessage`ን ያካትታሉ።
- **የcache ማጽዳት፦** በDB ላይ በእጅ ለውጦችን ካደረጉ በኋላ `skillRegistry.invalidateCache()`ን ይጥሩ፤ አለበለዚያ 60 s ይጠብቁ።
- **ስም-አልባ workspace፦** `apiKeyId` ባዶ ሲሆን፣ ሁሉም ጥሪዎች ወደ ተመሳሳዩ `"anonymous"` workspace በhash ይመደባሉ — share-aware ኮድ ሁልጊዜ እውነተኛ key ማሳለፍ አለበት።

## የአፈጻጸም የሕይወት ዑደት (v3.8.16+)

`SkillExecutor` (`src/lib/skills/executor.ts`) እያንዳንዱን የክህሎት ጥሪ የሚያስተዳድር **ነጠላ ኢንስታንስ (singleton)** ነው። የጊዜ ማብቃቶችን፣ ዳግም ሙከራዎችን እና የአፈጻጸም ሁኔታን ለማረም የሕይወት ዑደቱን መረዳት ወሳኝ ነው።

### ባለ 5-ደረጃ የሕይወት ዑደት

```
   execute() ተጠራ
        │
        ▼
  ┌─────────────┐
  │  PENDING    │  ← ወረፋ ላይ፣ ገና አልተጀመረም (የDB ረድፍ ተፈጥሯል)
  └──────┬──────┘
         │ አስተናጋጁን አስጀምር
         ▼
  ┌─────────────┐
  │  RUNNING    │  ← አስተናጋጁ ከጊዜ ማብቂያ ጋር ተጠርቷል
  └──────┬──────┘
         │
    ┌────┴────┬──────────┬──────────┐
    │         │          │          │
    ▼         ▼          ▼          ▼
  SUCCESS   ERROR     TIMEOUT   (ሌላ መንገድ የለም — በወላጅ ሂደቱ ተቋርጧል)
    │         │          │
    └────┬────┴──────────┘
         │
         ▼
   የDB ረድፍ በሁኔታ፣ ውጤት፣ durationMs ተዘምኗል
```

### ነባሪ ውቅር

| ቅንብር         | ነባሪ           | በዚህ ሊዋቀር ይችላል                        |
| ------------ | ------------- | ------------------------------------ |
| `timeout`    | `30000` (30s) | `skillExecutor.setTimeout(ms)`       |
| `maxRetries` | `3`           | `skillExecutor.setMaxRetries(count)` |

> **አስፈላጊ**፦ አስፈጻሚው ነጠላ ኢንስታንስ ነው — `setTimeout()`ን መጥራት በዓለም አቀፍ ደረጃ ሁሉንም ቀጣይ ጥሪዎች ይነካል። ለእያንዳንዱ ክህሎት የተለየ የጊዜ ማብቂያ በአሁኑ ጊዜ አይደገፍም፤ ለእያንዳንዱ ክህሎት የተለያዩ የጊዜ ማብቂያዎች ካስፈለጉዎት፣ የተለያዩ ሂደቶችን ያስገቡ ወይም አስፈጻሚውን fork ያድርጉ።

### የሁኔታ እሴቶች

ከ`src/lib/skills/types.ts`፦

```ts
enum SkillStatus {
  PENDING = "pending", // ወረፋ ላይ፣ ገና አልተጀመረም
  RUNNING = "running", // አስተናጋጁ ተጠርቷል
  SUCCESS = "success", // አስተናጋጁ ትክክለኛ ውጤት መልሷል
  ERROR = "error", // አስተናጋጁ ልዩ ሁኔታ አስነስቷል
  TIMEOUT = "timeout", // የአስፈጻሚውን የጊዜ ማብቂያ አልፏል
```

> **ማስታወሻ**፦ የ`TIMEOUT` ሁኔታ በenum ውስጥ ተገልጿል፣ ነገር ግን በአሁኑ የአስፈጻሚ ትግበራ **በተግባር ወደ DB አይጻፍም** — የጊዜ ማብቃቶች `"Skill execution timed out"` ከሚለው መልዕክት ጋር እንደ `ERROR` ይታያሉ። የሁኔታ enum ለወደፊት አጠቃቀም ተይዟል።

### የዳግም ሙከራ ባህሪ

የ`maxRetries` ቅንብር ይቀመጣል፣ ነገር ግን በአስፈጻሚው `execute()` ዘዴ **በአሁኑ ጊዜ ጥቅም ላይ አይውልም** — አንድ ሙከራ ብቻ ያከናውናል። የ`maxRetries` እሴት ለወደፊት ትግበራ እና ሊያነቡት ለሚፈልጉ hooks ተጋልጧል።

ለአሁን፣ ዳግም ሙከራዎች በክህሎት አስተናጋጁ ውስጥ መተግበር አለባቸው። አብሮገነብ
ክህሎቶች በአስፈጻሚው ላይ ይመዘገባሉ (ለምሳሌ፣ `registerBuiltinSkills(executor)`
/ `registerBrowserSkill(executor)` በ`src/lib/skills/builtin/` ውስጥ)፤ የትኛውንም አስተናጋጅ
ቢመዘግቡ፣ የራሱን የዳግም ሙከራ ዑደት ማካተት ይችላል፦

```ts
// በክህሎት አስተናጋጅ ውስጥ
async function handler(input, ctx) {
  const maxRetries = 3;
  let lastError: Error | null = null;

  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      return await fetchSomething(input);
    } catch (err) {
      lastError = err as Error;
      if (attempt < maxRetries) {
        await new Promise((r) => setTimeout(r, 1000 * attempt));
      }
    }
  }
  throw lastError;
}
```

## SkillMode በዝርዝር

የ`SkillMode` enum (`src/lib/skills/types.ts`) ክህሎቶች **መቼ እና እንዴት** እንደሚጠሩ ይቆጣጠራል፦

```ts
enum SkillMode {
  AUTO = "auto", // LLM ክህሎቱን መቼ መጥራት እንዳለበት ይወስናል

}
```

> **ማስታወሻ**፦ የኮድ ማከማቻው `SkillMode` (AUTO/MANUAL/HYBRID)ን ይገልጻል፤ የ`Skill.mode` መስክ ግን የተለየ ቅርጽ (`"on" | "off" | "auto"`) ይጠቀማል። እነዚህ የተዛመዱ ቢሆኑም ተመሳሳይ አይደሉም — `SkillMode` ለአስፈጻሚ ፖሊሲ ሲሆን፣ `Skill.mode` ደግሞ እያንዳንዱ ክህሎት እንዲሰራ ለማድረግ ነው።

| ሁነታ      | የLLM ባህሪ                                                       | የአጠቃቀም ሁኔታ                                  |

| `AUTO`   | LLM አስፈላጊ ነው ብሎ ሲያስብ ክህሎቱን መጥራት ይችላል                           | አጠቃላይ ዓላማ ያላቸው ክህሎቶች (ፋይል ማንበብ፣ HTTP ጥያቄዎች) |
| `MANUAL` | LLM ክህሎቱን መጥራት አይችልም፤ የሚያስነሳው ግልጽ የ`executeSkill` API ጥሪ ብቻ ነው | ስሱ ክዋኔዎች (በውሂብ ጎታ ላይ መጻፍ፣ ክፍያዎች)            |
| `HYBRID` | LLM ክህሎቱን ሊጠቁም ይችላል፤ ተጠቃሚው ማረጋገጥ አለበት                          | ተጓዳኝ ውጤቶች ያሏቸው ነገር ግን አደገኛ ያልሆኑ ክህሎቶች       |

### AUTO ነጥብ አሰጣጥ

የ`AUTO` ሁነታ ሲሰራ፣ እያንዳንዱ እጩ ክህሎት በ`src/lib/skills/injection.ts`
ውስጥ ባለው `scoreAutoSkill()` አማካኝነት ከጥያቄው ዐውድ ጋር በማነጻጸር ነጥብ
ያገኛል — ይህም ድምር ላይ የተመሠረተ የኢንቲጀር ነጥብ ስርዓት ነው (የክህሎት ስም መዛመድ፣ የስም/መለያ/መግለጫ ቶከኖች መደራረብ፣
የበስተጀርባ-ምክንያት ፍንጮች፣ የአቅራቢ-ፍንጭ ጉርሻ/ቅጣት)። `score >= AUTO_MIN_SCORE = 3`
ያላቸው ከፍተኛዎቹ `AUTO_MAX_SKILLS = 5` ክህሎቶች ሊጠሩ እንደሚችሉ መሣሪያዎች
ይጨመራሉ፤ እኩል ነጥቦች በ`installCount` ከዚያም በስም ይለያያሉ። ሙሉውን የነጥብ ሰንጠረዥ
ቀደም ብሎ በዚህ ሰነድ ውስጥ በ[**የመሣሪያ ንድፍ ማመንጨት → AUTO ነጥብ አሰጣጥ**](#auto-scoring)
ይመልከቱ፤ የfloat `0.6` ዓይነት ገደብም ሆነ በ`registry.ts` ውስጥ የነጥብ አሰጣጥ የለም።

## አብረው የተካተቱ ክህሎቶች ካታሎግ

OmniRoute በ`src/lib/skills/builtin/` ውስጥ በጥንቃቄ የተመረጡ አብረው የተካተቱ ክህሎቶችን ይዞ ይመጣል። በጣም የተለመዱት፦

### የአሳሽ ራስ-ሰር ማስኬጃ ክህሎት

የአሳሽ ክህሎቱ (`src/lib/skills/builtin/browser.ts`) በPlaywright/Puppeteer በኩል ያለ ግራፊክ በይነገጽ የአሳሽ ራስ-ሰር ማስኬጃን ይሰጣል። **ተተግብሯል፣ ነገር ግን በነባሪው የክህሎቶች ካታሎግ ውስጥ አልተካተተም** — ለመጠቀም የአሳሽ ቅጥያ ፕለጊኑን ለብቻው ይጫኑ።

```ts
// በውቅርዎ ውስጥ ያንቁ
const config: SkillConfig = {
  enabled: true,
  mode: SkillMode.MANUAL, // ሁልጊዜ ግልጽ ጥሪ እንዲኖር ይጠይቁ
  allowedSkills: ["browser"],
  timeout: 60000, // ለገጽ ጭነቶች 60 ሰከንድ
  maxRetries: 1,
};
```
