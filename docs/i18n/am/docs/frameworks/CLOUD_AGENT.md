ሞጁሉ ሲጫን የሚሞላ ቀላል የውስጠ-ማህደረ ትውስታ `Record<string, CloudAgentBase>` ነው።

## አወቃቀር

```
ደንበኛ (ዳሽቦርድ / CLI / API)
  → POST /api/v1/agents/tasks (የአስተዳደር ማረጋገጫ ያስፈልጋል)
    → የCreateCloudAgentTaskSchema ማረጋገጫ (Zod)
    → registry.getAgent(providerId)
    → getCloudAgentCredentials(providerId)
      └─ ከgetProviderConnections({ provider, isActive: true }) ይወስዳል
         (apiKey በመጀመሪያ፣ ካልተገኘ accessTokenን ይጠቀማል)
    → agent.createTask({ prompt, source, options }, credentials)
      └─ HTTP POST ወደ የላይኛው አቅራቢ API
      └─ CloudAgentTaskን ከውስጣዊ id + externalId ጋር ይመልሳል
    → insertCloudAgentTask(...) ወደ cloud_agent_tasks (SQLite)

ሁኔታን በየጊዜው መፈተሽ (በማንበብ ጊዜ ሰነፍ ማመሳሰል):
  GET /api/v1/agents/tasks/[id]
    → getCloudAgentTaskById(id)
    → agent.getStatus(externalId, credentials)  // ሁኔታውን + እንቅስቃሴዎችን ያድሳል
    → updateCloudAgentTask(...) በአዲሱ ሁኔታ፣ ውጤት፣ completed_at
    → ተከታታይ ቅርጽ የተሰጠውን ተግባር ይመልሳል

መስተጋብሮች:
  POST /api/v1/agents/tasks/[id]  ይዘት: { action: "approve" | "message" | "cancel" }
    → agent.approvePlan(externalId, credentials)        ለ"approve"
    → agent.sendMessage(externalId, message, credentials) ለ"message"
    → ሁኔታው ወደ "cancelled" ይቀየራል             ለ"cancel" (አካባቢያዊ-ብቻ)
```

ማመሳሰሉ **ሰነፍ** ነው፦ በእያንዳንዱ `GET /tasks/[id]` ጊዜ ሁኔታው ከላይኛው ስርዓት
ይታደሳል። ከበስተጀርባ ሁኔታን በየጊዜው የሚፈትሽ ሂደት የለም። የዘመነ ሁኔታ
የሚፈልጉ ዳሽቦርዶች የGET መጨረሻ ነጥቡን በተገቢ የጊዜ ልዩነት መጠየቅ አለባቸው።

## `CloudAgentBase` በይነገጽ

ምንጭ፦ `src/lib/cloudAgent/baseAgent.ts`

```typescript
export interface AgentCredentials {
  apiKey: string;
  baseUrl?: string;
}

export interface CreateTaskParams {
  prompt: string;
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
}

export interface GetStatusResult {
  status: CloudAgentStatus;
  externalId?: string;
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
}

export abstract class CloudAgentBase {
  abstract readonly providerId: string;
  abstract readonly baseUrl: string;

  abstract createTask(p: CreateTaskParams, c: AgentCredentials): Promise<CloudAgentTask>;
  abstract getStatus(externalId: string, c: AgentCredentials): Promise<GetStatusResult>;
  abstract approvePlan(externalId: string, c: AgentCredentials): Promise<void>;
  abstract sendMessage(
    externalId: string,
    message: string,
    c: AgentCredentials
  ): Promise<CloudAgentActivity>;
  abstract listSources(
    c: AgentCredentials
  ): Promise<{ name: string; url: string; branch?: string }[]>;

  protected mapStatus(raw: string): CloudAgentStatus; // በግምት የሚሰራ የውጭ ስርዓት ሕብረቁምፊ → enum
  protected generateTaskId(): string; // `task_<ts>_<rand>`
  protected generateActivityId(): string; // `act_<ts>_<rand>`
}
```

`CodexCloudAgent.approvePlan` ሆን ብሎ ስህተት ይጥላል — Codex Cloud ዕቅድን በራስ-ሰር ያዘጋጃል እና
የማጽደቂያ መግቢያ የለውም። `CodexCloudAgent.listSources` `[]` ይመልሳል።

`CursorCloudAgent` የCursor Background / Cloud Agentsን በይፋዊው REST
API (`api.cursor.com/v0`) እና **የተጠቃሚ ወይም የአገልግሎት-መለያ API ቁልፍ** በመጠቀም ያንቀሳቅሳል — ይህም
የCursor IDE OAuth ክፍለ-ጊዜን እንደገና ከመጠቀም ይልቅ ይበልጥ ደህንነቱ የተጠበቀ፣ የመጀመሪያ ወገን አማራጭ ነው (አቅራቢ `cursor`፣
የእገዳ አደጋ ማስጠንቀቂያ ያለው)። እሱ ቀላል REST አስማሚ ነው (የ`@cursor/sdk` ቤተኛ
ጥገኝነት የለውም)። `approvePlan` ስህተት ይጥላል (የCursor ወኪሎች በራስ-ገዝ ሁኔታ ይሰራሉ)፤ `listSources` ቁልፉ
ሊደርስባቸው የሚችላቸውን ማከማቻዎች ይዘረዝራል። Cursor በአቢይ ሆሄያት የተጻፉ የሁኔታ enum እሴቶችን
(`CREATING`/`RUNNING`/`FINISHED`/`ERROR`) ይመልሳል፤ እነዚህም ወደ የጋራው
`CloudAgentStatus` በግልጽ ሁኔታ ይመደባሉ። `baseUrl` ለእያንዳንዱ ማረጋገጫ መረጃ ሊተካ ስለሚችል፣ የAPI ስሪት/ዱካ
የኮድ ለውጥ ሳያስፈልግ ሊስተካከል ይችላል።

## የጎራ ዓይነቶች

```typescript
export const CLOUD_AGENT_STATUS = {
  QUEUED: "queued",
  RUNNING: "running",
  AWAITING_APPROVAL: "awaiting_approval",
  COMPLETED: "completed",
  FAILED: "failed",
  CANCELLED: "cancelled",
} as const;

export interface CloudAgentSource {
  repoName: string;
  repoUrl: string; // ትክክለኛ URL መሆን አለበት
  branch?: string;
}

export interface CloudAgentResult {
  prUrl?: string;
  prNumber?: number;
  commitMessage?: string;
  diffUrl?: string;
  summary?: string;
  duration?: number; // በሰከንድ፣ አዎንታዊ int
  cost?: number; // አዎንታዊ float
}

export interface CloudAgentActivity {
  id: string;
  type: "plan" | "command" | "code_change" | "message" | "error" | "completion";
  content: string;
  timestamp: string; // ISO 8601
  metadata?: Record<string, unknown>;
}

export interface CloudAgentTask {
  id: string; // ውስጣዊ `task_...` id
  providerId: "jules" | "devin" | "codex-cloud" | "cursor-cloud";
  externalId?: string; // የውጭ አቅራቢው id
  status: CloudAgentStatus;
  prompt: string; // 1..10000 ቁምፊዎች
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
  createdAt: string;
  updatedAt: string;
  completedAt?: string;
}
```

የማረጋገጫ መርሐግብሮች (`CreateCloudAgentTaskSchema`፣ `UpdateCloudAgentTaskSchema`) ከዓይነቶቹ ጋር
አብረው ወደ ውጭ ይላካሉ፣ እንዲሁም በመስመር ተቆጣጣሪዎቹ ጥቅም ላይ ይውላሉ።

## የውሂብ ጎታ

ምንጭ፦ `src/lib/cloudAgent/db.ts` — ሰንጠረዡ በ`createCloudAgentTaskTable()` አማካኝነት እስኪያስፈልግ ድረስ አይፈጠርም (`src/lib/cloudAgent/index.ts` ሞጁሉ ሲመጣም ይጠራል)።

```sql
CREATE TABLE IF NOT EXISTS cloud_agent_tasks (
  id           TEXT PRIMARY KEY,
  provider_id  TEXT NOT NULL,
  external_id  TEXT,
  status       TEXT NOT NULL DEFAULT 'queued',
  prompt       TEXT NOT NULL,
  source       TEXT NOT NULL,             -- JSON
  options      TEXT DEFAULT '{}',         -- JSON
  result       TEXT,                       -- JSON
  activities   TEXT DEFAULT '[]',          -- JSON
  error        TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_provider ON cloud_agent_tasks(provider_id);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_status   ON cloud_agent_tasks(status);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_created  ON cloud_agent_tasks(created_at DESC);
```

`updateCloudAgentTask` የSQL ማስገቢያ ጥቃትን ለመከላከል **የአምዶች ፍቃድ ዝርዝር**ን ያስገድዳል፦
`status`፣ `prompt`፣ `source`፣ `options`፣ `result`፣ `activities`፣ `error`፣
`completed_at`። በከፊል ማዘመኛው ውስጥ ያለ ማንኛውም ሌላ ቁልፍ ያለማሳወቂያ ይወገዳል።

## REST API — የCloud Provider መሠረተ ልማት

በ`src/app/api/cloud/` ስር ያሉት እነዚህ ረዳት endpoints የprovider ግንኙነት metadataን ለማንበብ እና የmodel aliasesን ለመፍታት በርቀት ደንበኞች
(CLI፣ Electron app ወይም sync workers) ይጠቀሙባቸዋል። እነዚህ endpoints የtask endpoints የሚጠቀሙበትን management auth ሳይሆን
**መደበኛ API key** (`validateApiKey` በመጠቀም) ማረጋገጫን ይጠቀማሉ።

| ዘዴ   | መንገድ                            | ዓላማ                                                            |
| ---- | ------------------------------- | -------------------------------------------------------------- |
| POST | `/api/cloud/auth`               | API keyን ያረጋግጣል፣ የተደበቀ የግንኙነት metadata እና model aliasesን ይመልሳል |
| PUT  | `/api/cloud/credentials/update` | `accessToken` / `refreshToken` / `expiresAt`ን ያድሳል             |
| POST | `/api/cloud/model/resolve`      | model aliasን ወደ `{ provider, model }` ይፈታል                     |
| GET  | `/api/cloud/models/alias`       | ሁሉንም model aliases ይዘረዝራል                                      |
| PUT  | `/api/cloud/models/alias`       | model aliasን ያዘጋጃል (ከነቃም በራስ-ሰር ከCloud ጋር ያመሳስላል)              |

`/api/cloud/auth` ጥሬ `apiKey` / `accessToken` / `refreshToken`ን ፈጽሞ አይመልስም።
`hasApiKey`፣ `hasAccessToken`፣ `hasRefreshToken` እና የተደበቀ ቅድመ ዕይታን
(`maskedApiKey`: የመጀመሪያዎቹ 4 + `****` + የመጨረሻዎቹ 4) ይመልሳል።

## የCredentials መፍትሔ

በ`src/lib/cloudAgent/api.ts` ውስጥ ያለው `getCloudAgentCredentials(providerId)`፦

1. `getProviderConnections({ provider: providerId, isActive: true })`ን በመጠቀም ንቁ የprovider ግንኙነቶችን ይጭናል።
2. ለእያንዳንዱ ግንኙነት `apiKey`ን (ከተቆረጡ ትርፍ ክፍተቶች ጋር) ይመርጣል። ከሌለ `accessToken`ን ይጠቀማል።
3. የመጀመሪያውን ባዶ ያልሆነ token በ`{ apiKey: token }` ተጠቅልሎ ይመልሳል።
4. ጥቅም ላይ ሊውል የሚችል token ካልተገኘ `null`ን ይመልሳል — APIው `400`ን ከሚከተለው ጋር ይመልሳል፦
   `"No active credentials configured for cloud agent provider: <id>"`።

ይህ ማለት Cloud Agents እንደ መደበኛ LLM providers ተመሳሳዩን Provider Connection table እንደገና ይጠቀማሉ ማለት ነው።
Julesን ለማንቃት `provider: "jules"` ያለው፣ ንቁ የሆነ እና `apiKey`ው የተሞላ ግንኙነት ይፍጠሩ።
