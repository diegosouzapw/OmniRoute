Is é díchriptiú trédhearcach TPROXY **an 5ú mód gabhála** de chuid OmniRoute don chruach MITM
[Traffic Inspector](../frameworks/TRAFFIC_INSPECTOR.md) / [AgentBridge](../frameworks/AGENTBRIDGE.md).
Idircheapann agus **díchriptíonn** sé trácht HTTPS áitiúil amach ar Linux
trí TPROXY na heithne + ródú bunaithe ar bheartais — **gan** `/etc/hosts` a bhréagú agus
**gan** socruithe seachfhreastalaí córais ar fud an OS a athrú. Tá sé oiriúnach do
thimpeallachtaí gan chomhéadan grafach (níl aon eagarthóireacht DNS le glanadh suas) agus
glantar na rialacha balla dóiteáin go huathoibríoch nuair a atosaítear an córas.

Murab ionann agus na modhanna gabhála eile, ní gá aon socrú in aghaidh an óstaigh le TPROXY:
idircheapann sé óstaigh sprice **treallacha** go trédhearcach ar phort sprice, foirceannann sé TLS
le teastas duille a eisíonn sé ar an toirt do gach óstainm SNI, gabhann sé an malartú
díchriptithe, agus athchriptíonn sé an t-iarratas chuig an gceann scríbe bunaidh.

> **Linux amháin, root amháin, roghnach.** Teastaíonn Linux, breiseán dúchasach
> tógtha le slabhra uirlisí C, agus an cumas **CAP_NET_ADMIN** (root de ghnáth) don mhód seo. Tá sé srianta
> taobh thiar d’API AgentBridge atá teoranta don loopback amháin agus tá sé díchumasaithe de réir réamhshocraithe.
> Is cumas cumhachtach é CA MITM iontaofa ar féidir leis síniú thar ceann aon óstaigh — féach [§6 Slándáil](#6-security).

**Foinse:** `src/mitm/tproxy/`
**Bealach API:** `GET / POST / DELETE /api/tools/agent-bridge/tproxy`
**Scorán an deais:** Traffic Inspector → barra uirlisí na mód gabhála → **"Díchriptiú TPROXY"** ⚠
**Féach freisin:** [`docs/frameworks/TRAFFIC_INSPECTOR.md`](../frameworks/TRAFFIC_INSPECTOR.md),
[`docs/frameworks/AGENTBRIDGE.md`](../frameworks/AGENTBRIDGE.md)

## §1 Cad atá ann agus cathain is ceart é a úsáid

Tá teorainn ag baint le gach ceann de na ceithre mhód gabhála eile:

| Mód                                | An chaoi a stiúrtar trácht                         | Teorainn                                                               |
| ---------------------------------- | -------------------------------------------------- | ---------------------------------------------------------------------- |
| AgentBridge                        | Bréagú DNS in `/etc/hosts` do thacar seasta óstach | óstaigh chláraithe an ghníomhaire IDE amháin                           |
| Óstaigh Shaincheaptha              | Bréagú DNS in `/etc/hosts` in aghaidh an óstaigh   | iontráil amháin in aghaidh an óstaigh; sudo chun hosts a chur in eagar |
| HTTP_PROXY                         | Timpeallacht `HTTP_PROXY`/`HTTPS_PROXY`            | aipeanna a urramaíonn an athróg timpeallachta amháin                   |
| Seachfhreastalaí ar fud an chórais | Socruithe seachfhreastalaí an OS                   | athraíonn sé staid dhomhanda; ní mór í a aisiompú                      |

Ina ionad sin, stiúrann díchriptiú trédhearcach TPROXY trácht ag leibhéal na **heithne**.
Marcálann sé naisc nua TCP áitiúla amach chuig port sprice (`443` de réir réamhshocraithe) sa
slabhra `mangle OUTPUT`; athródálann `ip rule` na paicéid mharcáilte chuig seachadadh áitiúil,
agus, nuair a athiontrálann siad, tugann an sprioc `TPROXY` in `mangle PREROUTING` iad do
éisteoir **IP_TRANSPARENT** — a fhoirceannann TLS ansin agus a ghabhann an gnáth-théacs.

Úsáid é nuair is mian leat trácht a ghabháil agus a dhíchriptiú ó phróiseas:

- a dhéanann cumarsáid le hóstach nach gcláraíonn AgentBridge, agus
- nach n-urramaíonn `HTTP_PROXY`, agus
- nach mian leat cur isteach air trí athrú seachfhreastalaí ar fud an chórais.

Ós rud é go dtarlaíonn an t-idircheapadh san eithne, ní gá **aon athrú cumraíochta**
a dhéanamh ar an bpróiseas tionscnaimh — ach ní mór don phróiseas muinín a bheith aige as an
CA dinimiciúil a shuiteálann OmniRoute (féach [§4](#4-the-per-sni-dynamic-ca-and-trust-store-installer)).

## §3 An breiseán dúchasach IP_TRANSPARENT

Ní féidir le modúl `net` Node `setsockopt(IP_TRANSPARENT)` a dhéanamh _roimh_ `bind()`, rud a
éilíonn TPROXY (murach sin, caitheann an eithne na paicéid atreoraithe uaithi). Is modúl beag N-API é an breiseán
(`src/mitm/tproxy/native/transparent.c`, tógtha trí `binding.gyp`)
a nochtann trí fheidhm, a úsáidtear trí `transparentSocket.ts`:

| Feidhm bhreiseáin                     | Obair soicéid                                                                                     | Úsáidtear é le haghaidh                                                                  |
| ------------------------------------- | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `createTransparentListener(ip, port)` | `socket()` + **SO_REUSEADDR** + **IP_TRANSPARENT** + `bind()` + `listen()`, filleann sé an fd amh | an t-éisteoir gabhála trédhearcach (glacann Node leis an fd trí `server.listen({ fd })`) |
| `setSocketMark(fd, mark)`             | `setsockopt` **SO_MARK** ar fd atá ann cheana                                                     | frith-lúb (marcáil soicéid an tseachfhreastalaí féin)                                    |
| `connectMarked(ip, port, mark)`       | `socket()` + **SO_MARK** **roimh** `connect()` neamhbhlocála, filleann sé fd                      | an cur ar aghaidh réamhtheagmhálach athchriptithe (iompraíonn an SYN an marc)            |

Léitear an ceann scríbe bunaidh ó `socket.localAddress`/`localPort` — caomhnaíonn TPROXY
é, mar sin níl gá le cuardach **SO_ORIGINAL_DST**/NAT.

### An breiseán a thógáil

```bash
npm run build:native:tproxy      # cd src/mitm/tproxy/native && node-gyp rebuild
                                 # -> native/build/Release/transparent.node
```

- Le linn `npm run build`, ritheann `scripts/build/build-tproxy-native.mjs` `node-gyp
rebuild`. Is próiseas **Linux amháin agus neamh-mharfach** é — mura bhfuil slabhra uirlisí ann, ní bhíonn
  an mód gabhála ar fáil.
- Cóipeálann `assembleStandalone.mjs` `build/Release/transparent.node` isteach sa
  bheart neamhspleách; aimsíonn `transparentSocket.ts` é i gcoibhneas leis an modúl agus
  i gcoibhneas le cwd (`<cwd>/src/mitm/tproxy/native/...`).
- Déantar neamhaird git ar `build/` agus `prebuilds/` — déantar an dénártha a **thógáil, ní
  dhéantar é a chur i ngealltanas riamh**.

Déanann an lódálaí tástáil, in ord tosaíochta:
`native/build/Release/transparent.node`, ansin `native/prebuilds/transparent.node`
(an dá cheann i gcoibhneas leis an modúl agus faoi `<cwd>/src/mitm/tproxy/`).

## §4 An CA dinimiciúil in aghaidh SNI agus suiteálaí an stórais iontaoibhe

> **Nuashonrú #6684:** roinneann freastalaí statach AgentBridge (`src/mitm/server.cjs`)
> an patrún céanna ailtireachta CA/duilleoige seo anois in ionad duilleog statach
> fhéinshínithe amháin. Úsáideann sé ásc CA **ar leith**
> (`src/mitm/cert/rootCa.ts`, arna bhuanú ag `<DATA_DIR>/mitm/ca.key`/`ca.crt`)
> agus suiteálann sé faoin sliotán stórais iontaoibhe `omniroute-mitm.crt` atá ann
> cheana (ag teacht in ionad na seanduilleoige aonair ansin — níl aon ghlanadh
> dé-iontaoibhe ag teastáil), agus coinnítear é go hiomlán scartha ó shliotán
> `omniroute-tproxy-ca.crt` TPROXY féin thíos. Faigheann suiteálacha úra AgentBridge
> an tsamhail CA go huathoibríoch; leanann suiteáil a raibh muinín aici cheana as
> an tseanduilleog statach dá húsáid go dtí go roghnaíonn an t-oibreoir páirt a
> ghlacadh trí `MITM_ROOT_CA_ENABLED=true` (féach `src/mitm/cert/migration.ts`) —
> tá CA MITM iontaofa atá in ann duilleog a shíniú d'óstach **ar bith** i bhfad
> níos cumhachtaí ná an tseanduilleog le SAN seasta, mar sin ní dhéantar an t-athrú
> go ciúin riamh i gcás suiteála a bhfuil muinín aici aisti cheana.

Go stairiúil, níor oibrigh teastas statach MITM AgentBridge ach toisc go ndéanann
AgentBridge DNS-spoofáil ar thacar óstach **seasta** (atá aontaithe anois leis an
tsamhail thíos). Idircheapann TPROXY óstaigh **ar bith**, mar sin ní mór dá
éisteoir duilleog bhailí a chur i láthair le haghaidh cibé SNI a iarrann an
cliant — an riachtanas céanna atá ag AgentBridge anois don tacar iomlán
`MITM_TOOL_HOSTS` (9 n-iontráil uirlise) in ionad na 4 óstach antigravity amháin.

### CA dinimiciúil (`src/mitm/tproxy/dynamicCert.ts`)

Ritheann `DynamicCertStore` CA áitiúil (bunaithe ar an spleáchas `selfsigned`) a dhéanann na nithe seo:

- Gineann sé CA fadsaolach trí `generateMitmCa()` (CN `"OmniRoute MITM CA"`,
  bailíocht 10 mbliana, `basicConstraints CA=true` + `keyUsage keyCertSign,cRLSign`,
  RSA 2048-giotán / SHA-256).
- Eisíonn sé **duilleog in aghaidh óstainm SNI ar éileamh** trí `issueLeafCert()`
  (bailíocht 1 bhliana, `subjectAltName` = an t-óstach SNI) agus cuireann sé
  `tls.SecureContext` amháin in aghaidh an óstainm i dtaisce.
- Nochtann sé `createSNICallback()` don fhreastalaí a chríochnaíonn TLS (féach [§5](#5-how-decrypt-and-capture-work)).
- Is féidir é a chruthú le `existingCa` chun an CA a choinneáil cobhsaí thar
  atosuithe (ionas nach gá an stóras iontaoibhe a athshuiteáil).

Ní fhágann eochair phríobháideach an CA **an meaisín choíche**.

### Suiteálaí an stórais iontaoibhe (`src/mitm/tproxy/caTrust.ts`)

Ní mór don chliant idircheaptha muinín a bheith aige as an CA dinimiciúil, mar
sin, nuair a thosaítear an mód gabhála, suiteáiltear teastas an CA i stóras
iontaoibhe an OS faoi **shliotán tiomnaithe** — `omniroute-tproxy-ca.crt`
(tairiseach `TPROXY_CA_CERT_NAME`) — a choinnítear scartha ó shliotán an teastais
stataigh MITM (`omniroute-mitm.crt`) ionas nach ndéanfaidh siad forscríobh ar a
chéile choíche.

Aimsíonn `installTproxyCa(caPem, sudoPassword?)` eolaire ancaire na dáileacháin
(sa chéad dul síos: stíl Debian) agus ritheann sé an t-ordú athnuachana
comhfhreagrach:

| Eolaire ancaire                             | Ordú athnuachana         |
| ------------------------------------------- | ------------------------ |
| `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

Le linn na suiteála, cuirtear an PEM i gcomhad sealadach, ansin déantar
`mkdir -p` (le pribhléidí) ar an eolaire ancaire, úsáidtear `cp` chun an comhad
ullmhaithe a chóipeáil isteach ann, agus ritear an t-ordú athnuachana.
Ní bhaineann `uninstallTproxyCa()` ach an sliotán tiomnaithe (agus fágtar an
teastas statach MITM gan athrú) agus déanann sé athnuachan — ní dhéanann sé aon
ní ar chórais nach Linux iad.

Ritear gach ordú pribhléideach trí `execFileWithPassword` (`src/mitm/systemCommands.ts`)
— `spawn` le **heagair argóintí, gan bhlaosc, gan idirshuíomh teaghrán**
(Riail Dhian #13). Nuair atá an próiseas ina root (m.sh. an VPS), ritear an
sprioc go díreach agus ní theastaíonn aon phasfhocal; ar dheasc nach root í,
seoltar an `sudoPassword` trí `sudo -S` ar stdin.

> Soláthraítear `sudoPassword` na deisce i gcorp POST chun suiteáil an stórais
> iontaoibhe a údarú; déantar neamhaird iomlán de nuair atá an próiseas ina root.

## §5 An chaoi a n-oibríonn díchriptiú agus gabháil

An phíblíne (í ar fad faoi `src/mitm/tproxy/`):

```
aip áitiúil  ──TCP/443──▶  marcálann mangle OUTPUT an nasc (fwmark)
                            ip rule → tábla ródaithe áitiúil → lo
                            mangle PREROUTING TPROXY → éisteoir IP_TRANSPARENT (port 8443)
                                │  captureMode.ts: léann sé an ceann scríbe bunaidh ó socket.localAddress
                                ▼
                            tlsCapture.ts:
                              1. Cuireann sé deireadh le TLS an CHLIAINT le duilleog in aghaidh an SNI (dynamicCert)
                              2. parsálann http.Server inmheánach an gnáth-théacs díchriptithe
                              3. gabháil → globalTrafficBuffer.push() le source: "tproxy"
                                 (sanitizeHeaders + maskSecret curtha i bhfeidhm)
                              4. seolann sé ar aghaidh, athchriptithe, chuig an gceann scríbe bunaidh
                                 thar shoicéad le marc seachbhóthair (connectMarked, frith-lúb)
                                │
                                ▼
                            bunfhoinse réamhtheachtach (api.example.com)
```

- **Foirceannadh TLS** (`createTlsCaptureServer`): timfhilleann sé an soicéad amh idircheaptha
  i `tls.TLSSocket` ar thaobh an fhreastalaí ag úsáid aisghlao SNI an CA dhinimiciúil,
  agus ansin tugann sé an sruth díchriptithe do `http.Server` inmheánach (an gnáthchleas
  foirceanta MITM). Cuireann `MITM_IDLE_TIMEOUT_MS` teorainn le saolré na soicéad ionas
  nach mbeidh tollán crochta in ann tuairisceoirí comhaid a ídiú.
- **Gabháil** (`handleDecryptedRequest`): brúnn sé `InterceptedRequest` le
  `source: "tproxy"`, stádas tosaigh `"in-flight"`, ceanntásca curtha trí
  `sanitizeHeaders()` agus coirp curtha trí `maskSecret()` sula dtéann siad isteach sa
  mhaolán. Nuashonraítear an iontráil ansin leis an bhfreagairt, na méideanna agus an mhoill.
- **Cur ar aghaidh athchriptithe** (`createForward` / `realForward`): athchriptíonn sé chuig an
  gceann scríbe bunaidh. Is é **`true`** luach réamhshocraithe `rejectUnauthorized`
  (slán de réir réamhshocraithe) — déantar teastas na bunfhoinse réamhtheachtaí a fhíorú
  i gcoinne an SNI/Host a d’iarr an cliant, agus mar sin diúltaíonn an seachfhreastalaí
  don rud céanna a ndiúltódh an cliant bunaidh dó.

### Frith-lúb (SO_MARK)

Ós rud é go marcálann na rialacha naisc nua áitiúla amach, dhéanfaí cur ar aghaidh
athchriptithe **an tseachfhreastalaí féin** a idircheapadh arís de ghnáth — lúb
éigríochta. Cosnaíonn an chonair churtha ar aghaidh ina aghaidh seo le marc soicéid
seachbhóthair (**SO_MARK**):

- Osclaíonn `realForward` a shoicéad réamhtheachtach trí `connectMarked(ip, port, DEFAULT_BYPASS_MARK)`
  — `DEFAULT_BYPASS_MARK = 0x539` — a shocraíonn **SO_MARK** **roimh** `connect()`,
  ionas go n-iompraíonn SYN an churtha ar aghaidh an marc seachbhóthair.
- Eisiann an riail `mangle OUTPUT` naisc a bhfuil an marc seachbhóthair orthu cheana féin
  (`-m mark ! --mark <bypassMark>`), mar sin **ní** athmharcáiltear cur ar aghaidh
  an tseachfhreastalaí agus ní théann sé isteach in TPROXY arís.

> Nóta cur chun feidhme: ní mór an soicéad le marc seachbhóthair a shuiteáil ar
> `createConnection` an ghníomhaire (`https.request({ createConnection })` a ndéantar
> neamhaird de gan fógra nuair atá gníomhaire ann), nó d’osclódh an cur ar aghaidh
> soicéad gan mharc agus d’fhillfeadh an lúb. Ba é seo an socrú frith-lúibe a bailíochtaíodh le e2e.

## §7 Cur i bhfeidhm / aisiompú idirbheartaíoch an bhalla dóiteáin

Ní ceadmhach do chliseadh riail `mangle` ná ródbhealach seanchaite a fhágáil ina dhiaidh riamh. Ráthaíonn tógálaí na n-orduithe
(`src/mitm/tproxy/commands.ts`) agus an riteoir (`src/mitm/tproxy/setup.ts`) gurb é
**an t-aisiompú inbhéart beacht an chur i bhfeidhm, san ord droim ar ais**.

Ritheann `applyTproxy(cfg)` na horduithe curtha i bhfeidhm in ord; má tharlaíonn **aon** teip, ritheann sé
`revertTproxy(cfg)` iomlán ar bhonn na hiarrachta is fearr agus athchaitheann sé an earráid — mar sin bíonn an balla dóiteáin
curtha i bhfeidhm go hiomlán nó aisiompaithe go hiomlán, agus ní bhíonn sé leathfheidhmithe riamh. Ritheann `revertTproxy(cfg)`
na horduithe inbhéartacha san ord droim ar ais agus neamhaird á déanamh aige ar theipeanna (idimpótant — is sábháilte é a ghlaoch
gan choinníoll, m.sh. ó ghlantachán `repairMitm()` de chuid AgentBridge).

Ritheann `validateTproxyConfig(cfg)` roimh aon ordú: ní mór do phoirt a bheith idir `1–65535`,
ní mór do `mark`/`routeTable`/`bypassMark` a bheith ina slánuimhreacha dearfacha, agus ní mór do `bypassMark`
a bheith éagsúil le `mark` (frithlúb).

### Orduithe curtha i bhfeidhm (in ord)

```bash
ip rule add fwmark <mark> lookup <routeTable>
ip route add local 0.0.0.0/0 dev lo table <routeTable>
iptables -t mangle -A OUTPUT -p tcp --dport <dport> -m mark ! --mark <bypassMark> -j MARK --set-mark <mark>
iptables -t mangle -A PREROUTING -p tcp --dport <dport> -m mark --mark <mark> -j TPROXY --on-port <onPort> --tproxy-mark <mark>
```

Scriosann an t-aisiompú iad san ord droim ar ais: `PREROUTING -D`, `OUTPUT -D`, `ip route del`, `ip rule del`.

> Tá an t-oideas bunaithe ar **OUTPUT** toisc gurb é cás úsáide MITM trácht amach _áitiúil_
> (aipeanna ar an óstach céanna), rud nach bhfeiceann TPROXY in `PREROUTING` amháin
> — ní fheiceann `PREROUTING` ach trácht a chuirtear ar aghaidh. Marcálann an slabhra `OUTPUT` naisc
> áitiúla nua, athródálann an `ip rule` iad chuig seachadadh áitiúil (`lo`), agus
> sannann `PREROUTING` iad ansin don éisteoir trédhearcach.

## §8 Cumraíocht

Glacann an t-iarratas tosaithe (`POST /api/tools/agent-bridge/tproxy`) leis na réimsí
seo a leanas, arna mbailíochtú ag `StartTproxyBodySchema` (`tproxy/route.ts`). Tá siad uile roghnach
agus úsáidtear a luachanna réamhshocraithe mura soláthraítear iad:

| Réimse           | Cineál                    | Réamhshocrú | Nótaí                                                                                                                                         |
| ---------------- | ------------------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| **dport**        | slánuimhir (1–65535)      | `443`       | Port sprice TCP atá le hidircheapadh go trédhearcach                                                                                          |
| **mark**         | slánuimhir (≥1)           | `0x2333`    | Marc balla dóiteáin a shocraítear ar `OUTPUT`, agus a mheaitseálann an `ip rule` + `PREROUTING`                                               |
| **onPort**       | slánuimhir (1–65535)      | `8443`      | An port lena gceanglaíonn an t-éisteoir trédhearcach (**IP_TRANSPARENT**)                                                                     |
| **routeTable**   | slánuimhir (≥1)           | `233`       | Aitheantas an tábla ródaithe beartais ina bhfuil an ródbhealach `local 0.0.0.0/0`                                                             |
| **bypassMark**   | slánuimhir (≥1, ≠ `mark`) | `0x539`     | Marc seachanta an tsoicéid (**SO_MARK**) a shocraíonn an seachfhreastalaí ar a naisc réamhtheachtacha féin; eisiatar é in `OUTPUT` (frithlúb) |
| **sudoPassword** | teaghrán                  | —           | Deasca nach bhfuil fréamhchead acu amháin: údaraíonn sé suiteáil an stóir iontaoibhe; déantar neamhaird de nuair atá fréamhchead ann          |

Níl **aon athróg timpeallachta** ann do TPROXY — déantar an chumraíocht ar fad trí chorp
POST nó trí na luachanna réamhshocraithe thuas.

2. I mbarra uirlisí na módanna gabhála, aimsigh an cnaipe **"Díchriptiú TPROXY"** ⚠
   (`src/app/(dashboard)/dashboard/tools/traffic-inspector/components/CaptureModesToolbar.tsx`).
   - Má tá sé **díchumasaithe** leis an leid uirlisí "Teastaíonn Linux + root +
     an breiseán dúchasach ó dhíchriptiú TPROXY", níl an breiseán dúchasach ar fáil ar an óstríomhaire seo (ní Linux é,
     níl slabhra uirlisí ann, nó níor tógadh an breiseán). Féach [§2](#2-requirements) agus [§3](#3-the-native-ip_transparent-addon).
3. Cliceáil an cnaipe. Glaonn sé `POST /api/tools/agent-bridge/tproxy` trí
   `startTproxyCaptureMode()` (`src/lib/inspector/tproxyCaptureApi.ts`), rud a:
   thógann an CA dinimiciúil, a osclaíonn an t-éisteoir trédhearcach, a chuireann rialacha an bhalla dóiteáin
   i bhfeidhm, agus a shuiteálann an CA i stór muiníne an chórais oibriúcháin.
4. Agus é ar siúl, iompaíonn an scorán ómra agus taispeánann sé an líon idircheaptha beo
   (`· <interceptCount>`). Feictear iarratais idircheaptha i liosta na n-iarratas le
   `source: "tproxy"`.
5. Cliceáil arís chun stopadh — dúnann `DELETE /api/tools/agent-bridge/tproxy` trí
   `stopTproxyCaptureMode()` an t-éisteoir, díshuiteálann sé an CA, agus aisiompaíonn sé
   rialacha an bhalla dóiteáin.

Tagann stádas an mhóid gabhála (ar siúl / ar fáil / líon idircheaptha / port an éisteora)
ó `GET /api/tools/agent-bridge/tproxy` (`getCaptureStatus()` in
`src/mitm/tproxy/captureManager.ts`). Ní ritheann ach seisiún TPROXY **amháin** ag aon am amháin —
diúltaítear don dara ceann a thosú leis an teachtaireacht "Tá mód gabhála TPROXY ar siúl cheana féin".

## §10 Fabhtcheartú

### Tá an scorán díchumasaithe

Ní féidir an breiseán dúchasach a lódáil. Deimhnigh: go bhfuil tú ar Linux, gur thóg tú an breiseán
(`npm run build:native:tproxy`), agus gur féidir leis an bpróiseas `transparent.node` a lódáil.
Rialaíonn `isTransparentSocketAvailable()` an scorán; filleann `GET /api/tools/agent-bridge/tproxy`
`available: false` nuair atá an breiseán ar iarraidh.

### Ní ghabhtar aon rud

- Deimhnigh go nascann an próiseas idircheaptha leis an `dport` cumraithe i ndáiríre
  (`443` de réir réamhshocraithe).
- Deimhnigh go bhfuil muinín ag an bpróiseas as an CA dinimiciúil. Suiteáiltear an CA faoi
  `omniroute-tproxy-ca.crt`; d'fhéadfadh sé gur ghá an teastas a chur le haipeanna a bhfuil a stór muiníne féin acu (Firefox/Chrome NSS)
  ansin freisin.
- Rith féintástáil **Diagnose** AgentBridge (féach
  [`AGENTBRIDGE.md`](../frameworks/AGENTBRIDGE.md)) le haghaidh seiceálacha ar mhuinín an teastais / ar
  shláinte an fhreastalaí.

### Rialacha balla dóiteáin seanchaite tar éis tuairteála

Is é `revertTproxy()` inbhéarta beacht na hoibríochta cur i bhfeidhm agus tá sé idéimpoitéinseach. Má stoptar an
mód, aisiompaítear na rialacha; má maraíodh OmniRoute i lár seisiúin, úsáid gníomh
**Repair** AgentBridge (`POST /api/tools/agent-bridge/repair`) chun staid chórais dílleachta
(aithris DNS, CA fréimhe, seachfhreastalaí córais) a chealú. Folmhaítear rialacha `mangle` TPROXY agus an bealach
go huathoibríoch freisin nuair a atosaítear an córas.

### Lúb éigríochta / idircheapann an seachfhreastalaí a chur ar aghaidh féin

Seo é an cás frithlúibe. Deimhnigh go bhfuil `bypassMark` difriúil ó `mark` (cuireann an bailíochtú
é seo i bhfeidhm) agus go n-úsáideann an cur ar aghaidh `connectMarked` (úsáideann sé é in `realForward`).
Féach [§5 Frithlúb](#anti-loop-so_mark).
