Sainmhíníonn `open-sse/config/providerPluginManifest.ts` conradh breiseáin soláthraí atá
sábháilte do JSON. Ceanglaíonn `open-sse/config/providerPluginManifestRegistry.ts` an
conradh sin le clárlann reatha na soláthraithe do thaobhcharranna amhail Bifrost,
CLIProxyAPI, nó ródaire Go/Rust amach anseo. Is í clárlann TypeScript foinse
na fírinne i gcónaí, ach is féidir le taobhcharranna an lastliosta a úsáid gan
cód seiceadóra, réamhshocruithe OAuth, ceanntásca ná staid thimpeallacht an phróisis
a iompórtáil.

Tá an lastliosta céanna ar fáil thar HTTP ag
`GET /api/v1/provider-plugin-manifest` do thaobhcharranna a ritheann lasmuigh den phróiseas.

Fógraíonn OmniRoute an URL sin do Bifrost agus CLIProxyAPI tríd an
gceanntásc iarratais `X-OmniRoute-Provider-Manifest-Url`. Socraigh
`OMNIROUTE_PROVIDER_MANIFEST_URL` nuair a bhíonn URL poiblí nó URL líonra coimeádáin
de dhíth ar an taobhcharr in ionad bhunphointe áitiúil an iarratais.

## An Lastliosta a Athnuachan

Filleann an críochphointe HTTP `Cache-Control: public, max-age=60` agus
`ETag` láidir. Ba cheart do thaobhcharr an lastliosta bailíochtaithe deireanach a choinneáil agus a ETag
a sheoladh in `If-None-Match` agus é á athnuachan. Níl corp ag freagra `304 Not Modified`;
coinníonn an taobhcharr a lastliosta taiscthe. Mura bhfuil aon lastliosta bailíochtaithe taiscthe ann,
ní mór don taobhcharr iarratas neamhchoinníollach a dhéanamh seachas glacadh le `304`.

## Sprioc

Meiteashonraí soláthraithe a bhogadh i dtreo conradh breiseáin ionas gur féidir le
taobhcharr a bhfuil aga folaigh níos ísle aige an chonair the iarratais a shealbhú ar deireadh, agus OmniRoute ag coinneáil
an bhealaigh TypeScript mar gheata beartais agus mar chúltaca. Is breisiú é an lastliosta: ní
athraíonn sé ródú iarratas leis féin.

## Conradh

Tá na nithe seo a leanas sa lastliosta:

- aitheantas agus ailias an tsoláthraí
- formáid réamhtheachtach agus ainm an tseiceadóra
- cineál fíordheimhnithe, ceanntásc fíordheimhnithe, agus réimír roghnach fíordheimhnithe
- meiteashonraí statacha críochphointe
- incháilitheacht taobhchairr agus cúiseanna follasacha ar cheart do sholáthraí fanacht ar TS
- meiteashonraí samhla atá sábháilte do JSON amhail fad comhthéacs, bratacha físe/réasúnaíochta, agus
  paraiméadair nach dtacaítear leo
- clibeanna cumais lena n-áirítear `apikey`, `oauth`, `custom-executor`,
  `passthrough-models`, `responses`, `sidecar-candidate`, `usage-fetch`, agus `usage-supported`

Fágann an lastliosta na nithe seo a leanas ar lár d'aon ghnó:

- rúin chliaint OAuth agus luachanna réamhshocraithe rúnda
- taifeach na timpeallachta rite
- ceanntásca iarratais agus cúntóirí poiblí dintiúr
- tógálaithe dinimiciúla URL
- feidhmeanna seiceadóra
- sonraí inmheánacha linn na seisiún

## Clibeanna Cumais

Is eagar sórtáilte clibeanna é `capabilities` a dhíorthaítear ón iontráil sa chlárlann. Ba cheart do chomhtháthóirí
caitheamh leis mar fhreagra meaisín-inléite ar "cad is féidir leis an soláthraí seo a dhéanamh", seachas
foinsí TypeScript a athléamh.

| Clib                 | Brí                                                                                          |
| -------------------- | -------------------------------------------------------------------------------------------- |
| `apikey`             | Glacann sé le heochair API (`authType` is ea `apikey` nó `optional`).                        |
| `oauth`              | Úsáideann sé sreabhadh OAuth nó seisiúin.                                                    |
| `responses`          | Nochtann sé bun-URL OpenAI Responses-API.                                                    |
| `passthrough-models` | Freastalaíonn sé ar shamhlacha díreach ón bhfoinse réamhtheachtach in ionad catalóg statach. |
| `custom-executor`    | Ritheann sé seiceadóir neamh-réamhshocraithe, mar sin fanann sé ar chonair TypeScript.       |
| `sidecar-candidate`  | Scáthánaíonn sé `sidecar.eligible` — sábháilte lena mheas d'iompórtáil taobhchairr.          |
| `usage-fetch`        | Tá faighteoir úsáide nó cuóta sreangaithe aige (`getUsageForProvider`).                      |
| `usage-supported`    | Glacann an API úsáide leis an soláthraí seo (`isSupportedUsageConnection`).                  |

Is le haghaidh fionnachtana amháin atá `usage-fetch`. Tuairiscíonn sé go bhfuil a fhios ag OmniRoute conas úsáid a léamh don
soláthraí; ní ghníomhachtaíonn sé an fháil, ní athraíonn sé séimeantaic chuóta, ná ní thugann sé le tuiscint go bhfuil
giuirléid chuóta an Deais cumasaithe don soláthraí — geataítear an ghiuirléid sin ar leithligh le
`USAGE_SUPPORTED_PROVIDERS`. Is é `USAGE_FETCHER_PROVIDERS` in
`open-sse/services/usage/fetcherProviders.ts` foinse na fírinne.

Tá an liosta sin eochraithe de réir na dteaghrán a nglacann an seoltóir úsáide leo, mar sin meascann sé aitheantais chanónacha
le hailiasanna agus tá sé beagán níos faide ná líon na soláthraithe a bhfuil clib orthu: níl aon iontráil lastliosta le clibeáil ag iontrálacha
nach soláthraithe comhrá iad i gclárlann an lastliosta (mar shampla soláthraí cuardaigh `firecrawl`
agus soláthraí ACP `amazon-q`).

Freagraíonn `usage-supported` cibé acu a ghlacann bealaí úsáide an fhreastalaí agus na Deaise le ceangal
don soláthraí. Scáthánaíonn sé `isSupportedUsageConnection()` (`src/lib/usage/providerLimits.ts`)
agus `supportsProviderQuota()` (`src/shared/utils/providerQuotaVisibility.ts`), agus tá an dá cheann geataithe le
`USAGE_SUPPORTED_PROVIDERS` (`open-sse/services/usage/supportedProviders.ts`). Murab ionann agus
`usage-fetch`, astaítear é ar aitheantas an tsoláthraí amháin — déanann an garda rite
`USAGE_SUPPORTED_PROVIDERS.includes(providerId)` gan taifeach ailiasanna, mar sin coinníonn an lastliosta
an riail chéanna. Tá imlínte éagsúla ag an dá chlib: níl ach
`usage-fetch` ag 3 sholáthraí (`opencode`, `opencode-zen`, `xai`) agus níl ach
`usage-supported` ag 1 cheann amháin (`xiaomi-mimo-token-plan`), mar sin ní thugann ceann amháin an ceann eile le tuiscint.

## Úsáid Sidecar

Ba cheart do sidecars caitheamh le `sidecar.eligible` mar chomhartha coimeádach iarrthóra, seachas mar chinneadh ródaithe neamhchoinníollach. Ba cheart gurb iad soláthraithe a úsáideann eochair API agus críochphointe statach leis an seiceadóir réamhshocraithe an chéad sprioc iompórtála. Fanann soláthraithe a bhfuil seiceadóirí gréasáin saincheaptha, sreafaí OAuth/seisiúin, tógálaithe URL dinimiciúla, nó cumraíocht díorma acu ar chonair chúltaca TypeScript go dtí go gcuireann sidecar iompar coibhéiseach i bhfeidhm agus go gcruthaíonn teiliméadracht paireacht.

Céimeanna imirce molta:

1. Gin agus bailíochtaigh forógra breiseáin an tsoláthraí ón gclárlann TS.
2. Múin do Bifrost nó CLIProxyAPI an forógra a iompórtáil do sholáthraithe a úsáideann eochair API/críochphointe statach.
3. Ródaigh soláthraithe incháilithe tríd an sidecar taobh thiar de `OMNIROUTE_RELAY_BACKEND`, agus coinnigh cúltaca TS cumasaithe.
4. Ná huasghrádaigh soláthraithe ach amháin nuair a mheaitseálann an ráta ratha, aga folaigh p99, iompar sruthaithe, agus láimhseáil paraiméadar nach dtacaítear leo conair TS.
5. Cuir breiseáin dhúchasacha sidecar le haghaidh seiceadóirí saincheaptha leis, teaghlach soláthraithe amháin ag an am.

## Cén Fáth Nach Leabófaí Soláthraithe Go Díreach In Next

Níor cheart don chomhéadan Next cur i gcrích soláthraithe a rialú. Ba cheart dó teorainn an API a ghlaoch. Is féidir leis an inneall ansin cinneadh a dhéanamh ar cheart seiceadóir TypeScript, Bifrost, CLIProxyAPI, nó sidecar dúchasach amach anseo a úsáid. Coinníonn sé seo síniú iarratais, seiceálacha liosta ceadaithe, beartas DB, agus iompar cúltaca láraithe sula dtarlaíonn aon aistriú chuig sidecar.
