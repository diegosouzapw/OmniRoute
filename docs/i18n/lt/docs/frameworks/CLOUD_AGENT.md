> **Pirminis tiesos šaltinis:** `src/lib/cloudAgent/` ir `src/app/api/v1/agents/tasks/`
> **Paskutinį kartą atnaujinta:** 2026-06-28 — v3.8.40 (atnaujintas frontmatter; 4 agentai, įskaitant cursor-cloud)

„OmniRoute“ koordinuoja trečiųjų šalių debesijoje veikiančius programavimo agentus („Codex Cloud“, „Cursor“,
„Devin“, „Jules“) kaip ilgai vykdomas užduotis. Kiekvienas agentas pasiekiamas per vienodą sąsają, todėl
klientai gali pateikti užklausą + saugyklos URL ir gauti rezultatus nesirūpindami
konkrečių teikėjų API.

„Cloud Agent“ užduotis **nėra** įprastas pokalbio užbaigimas. Tai ilgalaikis, kelių etapų
darbo vienetas, kurio vykdymas gali trukti nuo kelių minučių iki kelių valandų, kurio
artefaktas gali būti „Pull Request“ ir kuris palaiko papildomus pranešimus bei (kai kurių teikėjų atveju) plano patvirtinimo etapus.

## Palaikomi agentai

| Teikėjo ID     | Klasė              | Šaltinis                              | Pirminis aukštesniojo lygio URL         | Plano patvirtinimas |
| -------------- | ------------------ | ------------------------------------- | --------------------------------------- | ------------------- |
| `jules`        | `JulesAgent`       | `src/lib/cloudAgent/agents/jules.ts`  | `https://jules.googleapis.com/v1alpha`  | Taip                |
| `devin`        | `DevinAgent`       | `src/lib/cloudAgent/agents/devin.ts`  | `https://api.devin.ai/v1`               | Taip                |
| `codex-cloud`  | `CodexCloudAgent`  | `src/lib/cloudAgent/agents/codex.ts`  | `https://api.openai.com/v1/codex/cloud` | Ne (automatiškai)   |
| `cursor-cloud` | `CursorCloudAgent` | `src/lib/cloudAgent/agents/cursor.ts` | `https://api.cursor.com/v0`             | Ne (automatiškai)   |

Registras: `src/lib/cloudAgent/registry.ts` — eksportuoja `getAgent(providerId)`,
`getAvailableAgents()` ir `isCloudAgentProvider(providerId)`. Registras yra
paprastas atmintyje laikomas `Record<string, CloudAgentBase>`, užpildomas įkeliant modulį.

## Architektūra

```
Klientas (valdymo skydelis / CLI / API)
  → POST /api/v1/agents/tasks (būtinas valdymo autentifikavimas)
    → CreateCloudAgentTaskSchema validacija (Zod)
    → registry.getAgent(providerId)
    → getCloudAgentCredentials(providerId)
      └─ gauna iš getProviderConnections({ provider, isActive: true })
         (pirmiausia apiKey, kitu atveju accessToken)
    → agent.createTask({ prompt, source, options }, credentials)
      └─ HTTP POST užklausa aukštesniojo lygio teikėjo API
      └─ grąžina CloudAgentTask su vidiniu id + externalId
    → insertCloudAgentTask(...) į cloud_agent_tasks (SQLite)

Apklausa (atidėtas sinchronizavimas skaitant):
  GET /api/v1/agents/tasks/[id]
    → getCloudAgentTaskById(id)
    → agent.getStatus(externalId, credentials)  // atnaujina būseną + veiklas
    → updateCloudAgentTask(...) su nauja būsena, rezultatu, completed_at
    → grąžina serializuotą užduotį

Sąveikos:
  POST /api/v1/agents/tasks/[id]  turinys: { action: "approve" | "message" | "cancel" }
    → agent.approvePlan(externalId, credentials)        veiksmui "approve"
    → agent.sendMessage(externalId, message, credentials) veiksmui "message"
    → būsena pakeičiama į "cancelled"                    veiksmui "cancel" (tik vietoje)
```

Sinchronizavimas yra **atidėtas**: būsena atnaujinama iš aukštesniojo lygio paslaugos kiekvienos `GET /tasks/[id]` užklausos metu.
Foninio apklausiklio nėra. Valdymo skydeliai, kuriems reikia naujausios būsenos, turėtų apklausti GET
galinį tašką tinkamu intervalu.

## `CloudAgentBase` sąsaja

Šaltinis: `src/lib/cloudAgent/baseAgent.ts`

```typescript
export interface AgentCredentials {
  apiKey: string;
  baseUrl?: string;
}

export interface CreateTaskParams {
  prompt: string;
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
}

export interface GetStatusResult {
  status: CloudAgentStatus;
  externalId?: string;
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
}

export abstract class CloudAgentBase {
  abstract readonly providerId: string;
  abstract readonly baseUrl: string;

  abstract createTask(p: CreateTaskParams, c: AgentCredentials): Promise<CloudAgentTask>;
  abstract getStatus(externalId: string, c: AgentCredentials): Promise<GetStatusResult>;
  abstract approvePlan(externalId: string, c: AgentCredentials): Promise<void>;
  abstract sendMessage(
    externalId: string,
    message: string,
    c: AgentCredentials
  ): Promise<CloudAgentActivity>;
  abstract listSources(
    c: AgentCredentials
  ): Promise<{ name: string; url: string; branch?: string }[]>;

  protected mapStatus(raw: string): CloudAgentStatus; // euristinis išorinės sistemos eilutės → enum susiejimas
  protected generateTaskId(): string; // `task_<ts>_<rand>`
  protected generateActivityId(): string; // `act_<ts>_<rand>`
}
```

`CodexCloudAgent.approvePlan` sąmoningai išmeta klaidą — „Codex Cloud“ planus kuria automatiškai ir
neturi patvirtinimo etapo. `CodexCloudAgent.listSources` grąžina `[]`.

`CursorCloudAgent` valdo „Cursor“ foninius / debesijos agentus per oficialią REST
API (`api.cursor.com/v0`), naudodamas **naudotojo arba tarnybinės paskyros API raktą** — tai saugesnė,
oficiali alternatyva pakartotiniam „Cursor IDE“ OAuth seanso naudojimui (teikėjas `cursor`,
dėl kurio pateikiamas įspėjimas apie užblokavimo riziką). Tai paprastas REST adapteris (be vietinės
`@cursor/sdk` priklausomybės). `approvePlan` išmeta klaidą („Cursor“ agentai veikia autonomiškai); `listSources` pateikia
raktui pasiekiamų saugyklų sąrašą. „Cursor“ grąžina DIDŽIOSIOMIS RAIDĖMIS parašytas būsenų enum reikšmes
(`CREATING`/`RUNNING`/`FINISHED`/`ERROR`), kurios tiesiogiai susiejamos su bendruoju
`CloudAgentStatus`. Kiekvienuose prisijungimo duomenyse `baseUrl` galima pakeisti, kad API versiją / kelią būtų
galima pataisyti nekeičiant kodo.

## Domeno tipai

Šaltinis: `src/lib/cloudAgent/types.ts`

```typescript
export const CLOUD_AGENT_STATUS = {
  QUEUED: "queued",
  RUNNING: "running",
  AWAITING_APPROVAL: "awaiting_approval",
  COMPLETED: "completed",
  FAILED: "failed",
  CANCELLED: "cancelled",
} as const;

export interface CloudAgentSource {
  repoName: string;
  repoUrl: string; // turi būti tinkamas URL
  branch?: string;
}

export interface CloudAgentResult {
  prUrl?: string;
  prNumber?: number;
  commitMessage?: string;
  diffUrl?: string;
  summary?: string;
  duration?: number; // sekundės, teigiamas sveikasis skaičius
  cost?: number; // teigiamas slankiojo kablelio skaičius
}

export interface CloudAgentActivity {
  id: string;
  type: "plan" | "command" | "code_change" | "message" | "error" | "completion";
  content: string;
  timestamp: string; // ISO 8601
  metadata?: Record<string, unknown>;
}

export interface CloudAgentTask {
  id: string; // vidinis `task_...` identifikatorius
  providerId: "jules" | "devin" | "codex-cloud" | "cursor-cloud";
  externalId?: string; // išorinės sistemos teikėjo identifikatorius
  status: CloudAgentStatus;
  prompt: string; // 1..10000 simbolių
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
  createdAt: string;
  updatedAt: string;
  completedAt?: string;
}
```

Tikrinimo schemos (`CreateCloudAgentTaskSchema`, `UpdateCloudAgentTaskSchema`) yra
eksportuojamos kartu su tipais ir naudojamos maršrutų apdorojimo funkcijose.

## Duomenų bazė

Šaltinis: `src/lib/cloudAgent/db.ts` — lentelė sukuriama atidėtai naudojant
`createCloudAgentTaskTable()` (ji taip pat iškviečiama iš `src/lib/cloudAgent/index.ts`
importuojant modulį).

```sql
CREATE TABLE IF NOT EXISTS cloud_agent_tasks (
  id           TEXT PRIMARY KEY,
  provider_id  TEXT NOT NULL,
  external_id  TEXT,
  status       TEXT NOT NULL DEFAULT 'queued',
  prompt       TEXT NOT NULL,
  source       TEXT NOT NULL,             -- JSON
  options      TEXT DEFAULT '{}',         -- JSON
  result       TEXT,                       -- JSON
  activities   TEXT DEFAULT '[]',          -- JSON
  error        TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_provider ON cloud_agent_tasks(provider_id);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_status   ON cloud_agent_tasks(status);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_created  ON cloud_agent_tasks(created_at DESC);
```

`updateCloudAgentTask` naudoja **leidžiamų stulpelių sąrašą**, kad būtų išvengta SQL injekcijos:
`status`, `prompt`, `source`, `options`, `result`, `activities`, `error`,
`completed_at`. Visi kiti dalinio atnaujinimo raktai tyliai atmetami.

## REST API — užduoties gyvavimo ciklas

**Autentifikavimas:** visiems `/api/v1/agents/tasks*` galiniams taškams reikalingas **valdymo autentifikavimas**
(`requireCloudAgentManagementAuth` apgaubia `requireManagementAuth` iš
`src/lib/api/requireManagementAuth`). Tai užtikrinama nuo pakeitimo `588a0333`
(_„fix(auth): require management auth for agent and cooldown APIs“_).

| Metodas | Kelias                        | Paskirtis                                                                          |
| ------- | ----------------------------- | ---------------------------------------------------------------------------------- |
| OPTIONS | `/api/v1/agents/tasks`        | CORS preliminari užklausa                                                          |
| GET     | `/api/v1/agents/tasks`        | Pateikti užduočių sąrašą (filtrai: `provider`, `status`, `limit≤500`)              |
| POST    | `/api/v1/agents/tasks`        | Sukurti užduotį (persiunčia aukštesnio lygio paslaugai ir išsaugo)                 |
| DELETE  | `/api/v1/agents/tasks?id=...` | Ištrinti užduotį pagal užklausos id (**neatšaukia** aukštesnio lygio paslaugoje)   |
| OPTIONS | `/api/v1/agents/tasks/[id]`   | CORS preliminari užklausa                                                          |
| GET     | `/api/v1/agents/tasks/[id]`   | Nuskaityti užduotį ir atidėtai sinchronizuoti būseną iš aukštesnio lygio paslaugos |
| POST    | `/api/v1/agents/tasks/[id]`   | Veiksmas: `approve` / `message` / `cancel`                                         |
| DELETE  | `/api/v1/agents/tasks/[id]`   | Ištrinti užduotį pagal kelio id                                                    |

### Užduoties kūrimas

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Fix the bug in src/foo.ts where the parser returns null",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    },
    "options": {
      "autoCreatePr": true,
      "planApprovalRequired": false
    }
  }'
```

```json
{
  "data": {
    "id": "task_1731512345678_abc123def",
    "providerId": "devin",
    "externalId": "session_xyz",
    "status": "queued",
    "prompt": "...",
    "source": { "repoName": "user/repo", "repoUrl": "...", "branch": "main" },
    "options": { "autoCreatePr": true },

```

### Plano patvirtinimas

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"action":"approve"}'
```

### Papildomo pranešimo siuntimas

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"message","message":"Also add a unit test for the parser"}'
```

### Atšaukimas (tik vietinė būsena)

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"cancel"}'
```

`cancel` vietinėje DB pakeičia `status` į `"cancelled"`, tačiau **nekviečia**
aukštesnio lygio teikėjo — `CloudAgentBase` nėra nutraukimo RPC. Norėdami sustabdyti
aukštesnio lygio paslaugos apmokestinimą, nutraukite užduotį paties teikėjo konsolėje.

## REST API — debesijos paslaugų teikėjų integracija

Šiuos pagalbinius galinius taškus, esančius `src/app/api/cloud/`, naudoja nuotoliniai klientai
(CLI, Electron programa arba sinchronizavimo procesai), kad nuskaitytų paslaugų teikėjo ryšio metaduomenis
ir išspręstų modelių alternatyviuosius vardus. Jų autentifikavimui naudojamas **įprastas API raktas**
(per `validateApiKey`), o ne užduočių galiniuose taškuose naudojamas valdymo autentifikavimas.

| Metodas | Kelias                          | Paskirtis                                                                                         |
| ------- | ------------------------------- | ------------------------------------------------------------------------------------------------- |
| POST    | `/api/cloud/auth`               | Patikrinti API raktą, grąžinti užmaskuotus ryšio metaduomenis ir modelių alternatyviuosius vardus |
| PUT     | `/api/cloud/credentials/update` | Atnaujinti `accessToken` / `refreshToken` / `expiresAt`                                           |
| POST    | `/api/cloud/model/resolve`      | Susieti modelio alternatyvųjį vardą su `{ provider, model }`                                      |
| GET     | `/api/cloud/models/alias`       | Pateikti visus modelių alternatyviuosius vardus                                                   |
| PUT     | `/api/cloud/models/alias`       | Nustatyti modelio alternatyvųjį vardą (ir automatiškai sinchronizuoti su debesija, jei įjungta)   |

`/api/cloud/auth` niekada negrąžina neapdorotų `apiKey` / `accessToken` / `refreshToken`. Jis
grąžina `hasApiKey`, `hasAccessToken`, `hasRefreshToken` ir užmaskuotą peržiūrą
(`maskedApiKey`: pirmi 4 + `****` + paskutiniai 4).

## Prisijungimo duomenų nustatymas

`getCloudAgentCredentials(providerId)`, esanti `src/lib/cloudAgent/api.ts`:

1. Įkelia aktyvius paslaugų teikėjų ryšius per `getProviderConnections({ provider: providerId, isActive: true })`.
2. Kiekvienam ryšiui pirmenybę teikia `apiKey` (pašalinus tarpus pradžioje ir pabaigoje). Jei jo nėra, naudoja `accessToken`.
3. Grąžina pirmą netuščią prieigos raktą, įtrauktą į `{ apiKey: token }`.
4. Grąžina `null`, jei nerandamas tinkamas prieigos raktas — API atsako `400` su
   `"No active credentials configured for cloud agent provider: <id>"`.

Tai reiškia, kad debesijos agentai naudoja tą pačią paslaugų teikėjų ryšių lentelę kaip ir įprasti LLM
paslaugų teikėjai. Norėdami įjungti Jules, sukurkite aktyvų ryšį su `provider: "jules"`
ir užpildytu `apiKey`.

## Valdymo skydelis

Šaltinis: `src/app/(dashboard)/dashboard/cloud-agents/page.tsx`

`"use client"` React puslapis, kuris:

- Pateikia užduočių sąrašą (periodiškai gaunamą per `GET /api/v1/agents/tasks`).
- Pateikia naujas užduotis naudodamas formą, susietą su `CreateCloudAgentTaskSchema`.
- Rodo būsenų ženklelius (`queued`, `running`, `awaiting_approval`, `completed`,
  `failed`, `cancelled`) ir pateikia `activities[]` laiko juostą.
- Parodo `result.prUrl` / `commitMessage` / `summary`, kai `status === "completed"`.

## Integracija su A2A

Debesijos agentus galima pateikti kaip A2A įgūdžius, užregistruojant A2A įgūdį, kuris perduoda
savo `tasks/send` apdorojimą `getAgent(...).createTask(...)` ir konvertuoja A2A užduoties
būsenos įvykius į JSON-RPC 2.0 protokolą. Žr. [A2A-SERVER.md](./A2A-SERVER.md).

## Naujo debesijos agento pridėjimas

1. Sukurkite `src/lib/cloudAgent/agents/<name>.ts`, išplečiantį `CloudAgentBase`.
2. Įgyvendinkite `createTask`, `getStatus`, `approvePlan` (arba išmeskite klaidą, jei netaikoma),
   `sendMessage`, `listSources`. Būsenoms normalizuoti naudokite `this.mapStatus(...)`.
3. Užregistruokite `src/lib/cloudAgent/registry.ts`, naudodami stabilų `providerId`.
4. Išplėskite `providerId` literalų sąjungą faile `src/lib/cloudAgent/types.ts`
   (`CloudAgentTask.providerId` ir `CreateCloudAgentTaskSchema`).
5. Pridėkite paslaugų teikėją prie `src/shared/constants/providers.ts`, jei jam reikalingas ryšio
   įrašas. OAuth pagrįstiems paslaugų teikėjams taip pat reikia `src/lib/oauth/providers/`.
6. Pridėkite testus kataloge `tests/unit/cloud-agent-*.test.ts`.
7. Atnaujinkite šį dokumentą ir valdymo skydelio konstantą `CLOUD_AGENTS`.

## Konfigūracija

| Aplinkos kintamasis | Paskirtis                                                        |
| ------------------- | ---------------------------------------------------------------- |
| `DATA_DIR`          | SQLite duomenų bazės, kurioje saugoma `cloud_agent_tasks`, vieta |
| `JWT_SECRET`        | Būtinas valdymo autentifikavimui užduočių galiniuose taškuose    |
| `API_KEY_SECRET`    | Būtinas teikėjo ryšio kredencialams šifruoti saugykloje          |

Šiuo metu nėra jokių konkrečiai „Cloud-Agent“ skirtų aplinkos kintamųjų — visos paslaptys saugomos
lentelėje `provider_connections`.
