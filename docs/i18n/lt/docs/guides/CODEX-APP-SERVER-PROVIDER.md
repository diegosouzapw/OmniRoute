---

OmniRoute suteikia **du** būdus naudoti OpenAI Codex:

| Teikėjas               | Kaip jis palaiko ryšį su OpenAI                                                                                                                                                                | Naudojimo išlyga                                                                                 |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **`codex`**            | Tiesiogiai pakartotinai perduoda jūsų ChatGPT/OpenAI OAuth prieigos raktą Responses API                                                                                                        | **Taip** — oficialus seansas nėra autorizuotas naudoti per tarpinį serverį / maršruto parinktuvą |
| **`codex-app-server`** | Valdo **Codex CLI nuosavą `codex app-server`** per JSON-RPC/WebSocket; CLI valdo ir automatiškai atnaujina savo OAuth (`~/.codex/auth.json`) lygiai taip pat kaip interaktyvus `codex` seansas | **Ne** — OmniRoute niekada pakartotinai neperduoda prieigos rakto API                            |

Kadangi `codex-app-server` niekada pakartotinai neperduoda prieigos rakto, jam
netaikoma seanso pakartotinio perdavimo naudojimo išlyga. Tačiau būtina, kad
**Codex CLI būtų pasiekiama sukonfigūruotu app-server URL**, o ta CLI turi būti
**prisijungusi**.

---

## 1. Architektūra

```
┌─ OmniRoute programa ─────────────┐        ┌─ codex-app-server pagalbinis konteineris ┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                        │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456              │
│  (+ galimybių prieigos raktas)   │  JSON  │  --ws-auth capability-token              │
│                                  │  RPC   │  savarankiškai valdo OpenAI OAuth         │
└──────────────────────────────────┘        │  (~/.codex/auth.json, autom. atnaujinimas)│
        │ bendrina (compose tomai)           └───────────────────────────────────────────┘
        ▼
  codex-appserver-token   → WS galimybių prieigos raktas (jį prijungia abu)
  codex-appserver-home    → ~/.codex (auth.json įrašo valdymo skydelis,
                             o skaito pagalbinio konteinerio codex app-server)
```

- Pagalbinis konteineris klausosi **tik** vidiniame compose tinkle
  (`ws://codex-app-server:1456`) ir yra apsaugotas galimybių prieigos raktu. Jis
  **niekada** nepublikuojamas pagrindiniame kompiuteryje ar internete.
- Codex CLI yra integruota į `omniroute:base`, todėl paleidžiant pagalbinį
  konteinerį Codex nereikia diegti pagrindiniame ar naudotojo kompiuteryje.

## 2. Paleidimas

```bash
# Paleiskite rinkinį SU codex app-server pagalbinio konteinerio profiliu:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

Pirmą kartą paleistas pagalbinis konteineris sugeneruoja savo WS galimybių
prieigos raktą (bendrinamame `codex-appserver-token` tome), o programa tą patį
prieigos raktą nuskaito per `OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE`. Nereikia
rankiniu būdu konfigūruoti prieigos rakto.

## 3. Prisijungimas + autentifikavimas

1. Valdymo skydelyje pridėkite **OpenAI Codex (App-Server)** ryšį. API rakto ar
   prieigos rakto nereikia (tai teikėjas be autentifikavimo — autentifikavimą
   valdo pagalbinis konteineris).
2. Jei pagalbinio konteinerio Codex CLI **dar neprisijungusi**, ryšio būklės
   patikra praneša _„veikia, bet neprisijungta“_ (o ne rodo raudoną
   autentifikavimo klaidą). Naudokite **Prisijungti naudojant ChatGPT**: tai
   naršyklėje paleidžia standartinį Codex įrenginio OAuth procesą, o tada per
   **Taikyti autentifikavimo duomenis** įrašo `~/.codex/auth.json` į bendrinamą
   tomą (tas pats prisijungimas naudojamas ir `codex`, ir `codex-app-server`
   teikėjams).
3. Prisijungus būklės patikra tampa žalia (ji patikrina ir `/readyz`, **ir**
   `account/read` — t. y. ar paslauga veikia _ir_ yra autentifikuota), tada
   sistema pradeda veikti.

Valdymo skydelis niekada neperrašo tinkamo esamo `~/.codex/auth.json` — jis įrašo
tik tada, kai failo nėra arba jo prieigos raktas yra pasenęs (visada sukuriama
atsarginė kopija).

## 4. Diegimo scenarijai

- **Operatorius, turintis jau autentifikuotą Codex CLI** — prijunkite pagrindinio
  kompiuterio `~/.codex` prie pagalbinio konteinerio (`codex-appserver-home`) ir
  praleiskite prisijungimo veiksmą.
- **Viešas naudotojas, kurio kompiuteryje Codex neįdiegta** — tai nesvarbu:
  pagalbiniame konteineryje CLI jau yra. Naudotojas autentifikuojasi tik per
  valdymo skydelį.
- **Tiesiogiai kompiuteryje veikianti OmniRoute (be pagalbinio konteinerio, su
  pagrindinio kompiuterio Codex)** — nustatykite
  `OMNIROUTE_CODEX_APPSERVER_WS`, kad ji nurodytų jūsų `codex app-server`, ir
  įsitikinkite, kad pagrindinio kompiuterio Codex yra prisijungusi; jei dvejetainio
  failo nėra, parodoma užuomina „codex neįdiegta“.

## 5. Gyvenamosios vietos / UDP išeinantis ryšys (operatoriaus priedas, netiekiamas)

Pirmiau aprašytas bendrasis pagalbinis konteineris išeinančiam ryšiui naudoja
įprastą konteinerio tinklą. Operatorius, kuriam reikia, kad Codex srautas išeitų
per **gyvenamosios vietos išėjimo mazgą** (pvz., TUN tailscale pagalbinį
konteinerį, perduodantį TCP + UDP/QUIC), paleidžia jį kaip atskirą compose
perrašą; jis sąmoningai **neįtrauktas** į tiekiamą `codex-app-server` profilį.
Šios sąrankos instrukcijas rasite vidiniame eksploatavimo vadove.
