`@omniroute/opencode-plugin-v2` įtraukia visą jūsų OmniRoute katalogą — modelius, kombinacijas ir
automatines kombinacijas — į OpenCode v2 modelių parinkiklį kartu su rodomais pavadinimais, kainomis ir nemokamo lygio
limitais.

Tai atskiras paketas nuo `@omniroute/opencode-plugin`, nes OpenCode v1 ir v2 įskiepius įkelia
naudodamos skirtingas sąsajas. Pasirinkite tą, kuris atitinka jūsų pagrindinę OpenCode versiją; jie
neturi nieko bendro, todėl vieno atnaujinimas niekada nepriverčia atnaujinti kito.

## Reikalavimai

- OpenCode v2.
- Pasiekiamas OmniRoute šliuzas (pagal numatytuosius nustatymus `http://localhost:20128`).
- Node.js 22 arba 24.

## Diegimas

Pridėkite įskiepį prie `opencode.json`:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

Tada modeliai rodomi kaip `omniroute/<provider>/<model>`; `providerId` nustato šį prefiksą ir
integracijos, kurioje OpenCode saugo prisijungimo duomenis, identifikatorių.

## Prisijungimo duomenys

Įskiepis šliuzo rakto ieško trijose vietose šia tvarka:

1. **Prisijungimo duomenyse, kuriuos susiejote su OpenCode.** Įskiepis užregistruoja integraciją, todėl
   OpenCode autentifikavimo procesas gali išsaugoti raktą. Į `opencode.json` niekas neįrašoma — teikite pirmenybę šiam būdui.
2. Įskiepio parinkčių lauke `apiKey`, skirtame konkretaus projekto perrašai. Tokiu atveju raktas įrašomas į failą, kurį
   galite įtraukti į versijų valdymo sistemą.
3. Aplinkos kintamajame `OMNIROUTE_API_KEY`.

Jei nėra nė vieno iš šių trijų, katalogas lieka tuščias, o įskiepis apie tai vieną kartą praneša paleidimo metu,
užuot palikęs jus su nepaaiškinamai tuščiu parinkikliu.

### Valdymo prieigos raktas yra kitas raktas

Kombinacijos, teikėjų būklė ir papildomi duomenys (rodomi pavadinimai, kainos, nemokamo lygio limitai) gaunami iš
šliuzo `/api/*` galinių taškų, kuriuos daugumoje diegimų saugo **valdymo** prieigos raktas,
o ne išvadų generavimo raktas:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<valdymo skaitymo prieigos raktas>"
}
```

Jei `managementReadToken` nenustatytas, vietoje jo naudojamas `apiKey`. Kai šliuzas atmeta šį atsarginį variantą,
katalogas vis tiek paskelbiamas, tačiau vietoje rodomų pavadinimų pateikiami neapdoroti modelių identifikatoriai,
nedubliuojami kanoniniai pseudonimai, nėra kainų ir kombinacijų. Taip nutikus, įskiepis vieną kartą kiekvienam galiniam taškui
pateikia įspėjimą, nurodydamas galinį tašką ir prarastus duomenis — todėl suprastėjęs parinkiklio veikimas niekada nelieka neaiškus.

## Parinktys

| Raktas                           | Numatytoji reikšmė                               | Pastabos                                                                                                              |
| -------------------------------- | ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| `providerId`                     | `"omniroute"`                                    | Teikėjo ID, integracijos ID ir prefiksas, su kuriuo rodomi modeliai                                                   |
| `baseURL`                        | privaloma                                        | Šliuzo šakninis URL, tik `http(s)`; prireikus pridedama priesaga `/v1`                                                |
| `apiKey`                         | prijungti kredencialai, tada `OMNIROUTE_API_KEY` | Pokalbių raktas, skirtas `/v1/*`                                                                                      |
| `managementReadToken`            | jei nenurodyta, naudojamas `apiKey`              | Raktas, skirtas `/api/*` — paprastai tai **ne** tas pats raktas                                                       |
| `displayName`                    | `"OmniRoute"`                                    | Teikėjo pavadinimas pasirinkimo sąraše                                                                                |
| `timeoutMs`                      | `10000`                                          | Kiekvieno galinio taško užklausos skirtasis laikas (automatiniai deriniai naudoja 5 sek.)                             |
| `modelCacheTtlMs`                | `300000`                                         | Katalogo podėlio TTL; diske esanti momentinė kopija paspartina šaltąjį paleidimą                                      |
| `timeouts`                       | jei nenurodyta, naudojamas `timeoutMs`           | Kiekvieno galinio taško laiko limitai milisekundėmis: `models`, `combos`, `autoCombos`, `enrichment`                  |
| `enrichment`                     | `true`                                           | Gauti pavadinimus, kainodarą ir nemokamos pakopos limitus                                                             |
| `providerTag`                    | `true`                                           | Prie rodomo pavadinimo pridėti aukštesnio lygmens teikėjo, į kurį nukreipiama, prefiksą                               |
| `usableOnly`                     | `false`                                          | Palikti tik tuos teikėjus, kuriuos šliuzas nurodo kaip parengtus naudoti                                              |
| `showcasePerOwner`               | `10`                                             | Numatytojo rodinio įrašų, paliekamų kiekvienam teikėjui, skaičius                                                     |
| `freshPerOwner`                  | `10`                                             | Numatytojo rodinio naujų įrašų, paliekamų kiekvienam teikėjui, skaičius                                               |
| `freshWindowDays`                | `90`                                             | Naujausių įrašų šakos naujumo laikotarpis dienomis                                                                    |
| `usageMemory`                    | `true`                                           | Atkurti statiškai pašalintus įrašus, nurodytus 30 dienų naudojimo analizėje (reikalingas valdymo prieigos raktas)     |
| `visibleModels` / `hiddenModels` | `[]`                                             | Tikslaus atitikimo arba priesagos leidžiamųjų reikšmių sąrašai; draudimas turi pirmenybę                              |
| `geminiSanitization`             | `true`                                           | Iš įrankių schemų pašalinti JSON-Schema raktažodžius, kuriuos Gemini atmeta (`$ref` įrankiai persiunčiami nepakeisti) |
| `apiFormat.allowAnthropic`       | `false`                                          | Per Anthropic API bloką nukreipti leidžiamųjų reikšmių sąraše esančius ID                                             |
| `apiFormat.anthropicModels`      | `[]`                                             | Visi modelių ID, nukreipiami į Anthropic                                                                              |
| `logLevel` / `startupDebug`      | `warn` / `false`                                 | Žurnalo išsamumo lygis                                                                                                |

Naudojimo atmintis yra įjungta pagal numatytuosius nustatymus. Be valdymo prieigos rakto ji lieka neaktyvi
(paleidžiant užregistruojamas pranešimas) ir niekas neatkuriama.

## Kaip katalogas išlaikomas aktualus

Katalogas gaunamas tingiai ir talpykloje saugomas `modelCacheTtlMs` laiką, o disko momentinė kopija užtikrina, kad
paskutinis žinomas katalogas būtų pasiekiamas, kai šliuzas nepasiekiamas — sutrikimo metu prarandamas tik
aktualumas. Modeliai ir deriniai paskelbiami iškart, kai tik gaunami; automatiniai deriniai, teikėjų
sąrašas ir papildymo perdanga įtraukiami, kai tik tampa prieinami, todėl vienas lėtas galinis taškas negali sulaikyti
viso parinkiklio.

Pavadinimuose pateikiama šliuzui žinoma informacija: pirminis teikėjas, į kurį nukreipiamas modelis, žymuo `[Free]`
ir kartu suteikiamas biudžetas — todėl du ryšiai, siūlantys tą patį modelį, išlieka
atskiriami. Išjunkite priešdėlį naudodami `"providerTag": false`.

Rankinio atnaujinimo komandos nėra: OpenCode v2 komandos yra užklausų šablonai, o ne atgalinio iškvietimo funkcijos,
todėl papildinys negali tokios komandos pateikti. Atnaujinimai vykdomi pagal TTL; pagrindinės sistemos prašoma įkelti iš naujo tik tada,
kai katalogas arba perdanga iš tiesų pasikeičia, o ne per kiekvieną atnaujinimą.

## Įrankių iškvietimas naudojant Gemini

Gemini atmeta visą užklausą, jei jos įrankių deklaracijose yra `$schema` arba
`additionalProperties`, ir atsako `400 INVALID_ARGUMENT`. Papildinys pašalina šiuos raktažodžius iš
šio teikėjo Gemini modeliui skirtų įrankių schemų, o visas kitas užklausas palieka nepakeistas.
Įrankis, kuriame yra `$ref`, persiunčiamas nepakeistas, užuot pašalinus raktažodžius, nes pašalinus
nuorodą schema būtų išplėsta taip, kad „priimtų bet ką“.
Norėdami tai išjungti, nustatykite `"geminiSanitization": false`.

## Trikčių šalinimas

| Požymis                                           | Priežastis                                                                                                         |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Parinkiklyje nerodomas joks OmniRoute modelis     | Nepavyko gauti rakto (patikrinkite paleidimo įspėjimą) arba šliuzas nepasiekiamas                                  |
| Neapdoroti modelių ID, nėra derinių ir kainodaros | Valdymo galiniai taškai atmetė prieigos raktą — nustatykite `managementReadToken`                                  |
| Seansas susietas su `opencode-<id>/…`             | v1 papildinys paskelbė `opencode-<id>`; v2 skelbia tik `<id>`, todėl iš naujo pasirinkite modelį skiltyje `<id>/…` |
