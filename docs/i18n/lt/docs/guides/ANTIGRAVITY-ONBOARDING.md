## 1. Antigravity ir Antigravity CLI (agy) palyginimas

Abu teikėjai naudoja **tą pačią Google infrastruktūrą** — identišką OAuth klientą, prieigos rakto atnaujinimą, galinius taškus ir Google paskyras. Skiriasi tik jums rodomi modeliai.

> Oficialų Google palyginimą rasite [pranešime apie Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli).

| Aspektas                          | `antigravity` (IDE)                                          | `agy` (CLI)                                                    |
| --------------------------------- | ------------------------------------------------------------ | -------------------------------------------------------------- |
| **Google produktas**              | Antigravity 2.0 / Antigravity IDE                            | Antigravity CLI                                                |
| **Infrastruktūra**                | Ta pati Google Cloud Code API                                | Ta pati Google Cloud Code API                                  |
| **OAuth / prieigos raktas**       | Tas pats klientas, tas pats atnaujinimas                     | Tas pats klientas, tas pats atnaujinimas                       |
| **Modelių katalogas**             | Statiškas atrinktų modelių sąrašas (įrašytas OmniRoute kode) | Dinamiškai tikrinamas Google naudojant `:fetchAvailableModels` |
| **Claude modeliai**               | Sonnet 4.6, Opus 4.6 (po 4 kiekvieno variantus)              | Sonnet 4.6, Opus 4.6 (po 4 kiekvieno variantus)                |
| **Gemini pavadinimai**            | Aiškios žymos (Low/Medium/High)                              | Pirminiai ID (extra-low/low/agent)                             |
| **Papildomi modeliai**            | `gpt-oss-120b-medium`                                        | Gali apimti papildomus Google modelius                         |
| **Numatytasis naudojimo atvejis** | IDE integravimas (VS Code, JetBrains)                        | CLI / API prieiga                                              |
| **Kvota**                         | Bendrinama su agy (ta pati Google paskyra)                   | Bendrinama su antigravity (ta pati Google paskyra)             |

**Pasiekiami modeliai (patikrinta eksperimentu, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (įvairūs samprotavimo lygiai)
- Claude: Sonnet 4.6, Opus 4.6 (kiekvienas turi default/low/medium/high variantus)
- Kiti: GPT-OSS 120B Medium
- **Claude Sonnet 5 NĖRA pasiekiamas** — palaikomi tik 4.6 variantai

**Kodėl modelių katalogai skiriasi**: Google CLI yra „optimizuota spartai ir mažoms pridėtinėms sąnaudoms“ bei „bendrai optimizuota su Gemini modeliais“ (pagal oficialų Google tinklaraštį). Žiniatinklio / IDE produktas yra „optimizuotas išsamumui“. CLI naudoja `:fetchAvailableModels`, kad dinamiškai aptiktų modelius, o IDE naudoja statišką atrinktų modelių sąrašą.

**Praktiškai**: Gemini modeliams naudokite prefiksą `agy/` (pvz., `agy/gemini-3.7-flash-high`). Statiškam atrinktų modelių sąrašui naudokite `antigravity/`. Abu naudoja tą pačią Google infrastruktūrą, tačiau pateikia skirtingus modelių pavadinimus. Kvota yra bendrinama — naudojant bet kurį teikėją skaičiuojami tos pačios Google paskyros limitai.

Google Antigravity naudoja **dviejų lygių kvotą**, pagrįstą „atliktu darbu“ (skaičiavimo apkrova), o ne pranešimų skaičiumi.

### Du lygiai

- **Ne Gemini modeliai** (Claude, GPT-OSS): turi **atskirus** dažnio limitus. Jie gali likti pasiekiami net tada, kai prieiga prie Gemini užblokuota.

### Svarbi informacija

- Kvota yra **bendra visai paskyrai** — ta pati Google paskyra, naudojama Antigravity IDE, CLI ir OmniRoute, dalijasi vienu kvotos rezervu

**Kai jūsų paskyros kvota išnaudojama**: OmniRoute automatiškai pakartoja užklausą naudodama kitą pasiekiamą kombinuotojo maršruto paskyrą. Rankiniu būdu nieko daryti nereikia.

## 3. Kaip gauti projectId

Kiekvienam antigravity/agy ryšiui reikalingas Google Cloud Code `projectId`. Be jo `/v1internal:models` galinis taškas grąžina 404 klaidą.

### A būdas: automatinis (rekomenduojamas)

OmniRoute tai atlieka automatiškai. Kai naudodami valdymo skydelio OAuth pridedate naują Google paskyrą:

1. OmniRoute atnaujina prieigos raktą
2. Iškviečia `loadCodeAssist`, kad aptiktų projectId
3. Jei projektas neegzistuoja, iškviečia `onboardUser`, kad jį sukurtų
4. Dar kartą iškviečia `loadCodeAssist`, kad gautų naujai sukurtą projectId
5. Išsaugo jį duomenų bazėje

**Tai veikia su dauguma paskyrų** — rankiniu būdu nieko daryti nereikia.

### B būdas: rankiniu būdu naudojant agy CLI

Jei automatinis aptikimas nepavyksta (informaciją, kada taip nutinka, žr. 5 skyriuje):

```bash
# Įdiekite agy CLI (jei dar neįdiegta)
npm install -g @anthropic-ai/agy

# Prisijunkite naudodami savo Google paskyrą
agy login

# Pasirinkite paskyrą, kurią reikia užregistruoti
# Taip inicijuojama Cloud Code registracija ir priskiriamas projectId
```

Sėkmingai įvykdę `agy login`, atnaujinkite prieigos raktą OmniRoute valdymo skydelyje. projectId bus aptiktas automatiškai.

### Kaip patikrinti

Patikrinkite duomenų bazę:

```bash
# OmniRoute konteinerio viduje
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Arba patikrinkite žurnalus:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. OAuth peradresavimo URI

### Problema

„Google OAuth“ reikalauja galiojančio peradresavimo URI. „OmniRoute“ pagal numatytuosius nustatymus naudoja `http://127.0.0.1:20128/callback` (grįžtamojo ryšio adresą). Tai veikia vietinėse versijose, bet **neveikia nuotoliniuose diegimuose** (pvz., serveryje, pasiekiamame per LAN IP adresą).

„Google“ atmeta peradresavimo URI, kurie:

- Naudoja IP adresus (turi būti naudojamas domenas, kurio galūnė yra `.com`, `.org` ir pan.)
- Neatitinka OAuth kliento konfigūracijoje užregistruotų peradresavimo URI

### Sprendimas

**A parinktis: naudoti integruotą OAuth procesą (numatytoji parinktis)**

- Veikia, kai „OmniRoute“ pasiekiate per `localhost` arba `127.0.0.1`
- Konfigūruoti nereikia

**B parinktis: pasirinktiniai OAuth prisijungimo duomenys**

- Savo aplinkoje nustatykite `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web`
- Pateikite savo „Google OAuth“ prisijungimo duomenis:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- „Google Cloud Console“ užregistruokite `https://your-domain.com/callback` kaip įgaliotąjį peradresavimo URI

**C parinktis: pradiniam prisijungimui naudoti agy CLI**

- Kompiuteryje, kuris pasieks „OmniRoute“, paleiskite `agy login`
- OAuth procesas užbaigiamas vietoje ir prieigos raktai išsaugomi
- Importuokite ryšį į „OmniRoute“ per valdymo skydelį

### Apribojimai

- Pasirinktiniams OAuth prisijungimo duomenims reikalingas domeno vardas („Google“ nepriima IP adresų kaip peradresavimo URI)
- Jei domeno neturite, naudokite A arba C parinktį

## 5. Trikčių šalinimas: kai automatinė sąranka nepavyksta

Daugumos paskyrų atveju „OmniRoute“ automatiškai aptinka projectId ir atlieka pradinę sąranką. Kai tai nepavyksta, pagrindinė priežastis paprastai būna viena iš šių:

### Paskyros regionas užblokuotas

**Požymis**: `agy login` grąžina „Eligibility check failed: Your current account is not eligible for Antigravity, because it is not currently available in your location.“

**Pagrindinė priežastis**: „Google“ paskyrose yra vidinis „Country Association“ laukas, nustatomas registracijos metu. agy CLI ir „Cloud Code API“ griežtai tikrina šį lauką, kitaip nei žiniatinklio „Gemini“, kuris tikrina tik dabartinį jūsų IP adresą.

> Norėdami patikrinti arba pakeisti su paskyra susietą regioną, apsilankykite [„Google“ šalies susiejimo formoje](https://policies.google.com/country-association-form).

**Kodėl žiniatinklio „Gemini“ veikia, o agy – ne**:

- Žiniatinklio „Gemini“ / „Google One“: tikrina tik dabartinį IP adresą (tarpinis serveris padeda)
- agy CLI / „Cloud Code API“: nuskaito vidinį „Country Association“ lauką (tarpinis serveris nepadeda)

**Sprendimas**:

1. Naudodami JAV IP adresą apsilankykite [„Google“ šalies susiejimo formoje](https://policies.google.com/country-association-form)
2. Pateikite regiono keitimo užklausą (pasirinkite „I live in a different country“)
3. Palaukite 1–24 valandas, kol „Google“ apdoros užklausą ir atsiųs pranešimą el. paštu
4. Po to `agy login` turėtų būti sėkmingas

### Paskyra neturi „Cloud Code“ projekto

**Požymis**: žurnaluose rodoma `loadCodeAssist returned no project id` ir `onboardUser failed (400)`.

**Pagrindinė priežastis**: paskyra niekada nebuvo užregistruota „Google Cloud Code“, o automatinė pradinė sąranka nepavyko.

**Sprendimas**: rankiniu būdu paleiskite `agy login`, kad inicijuotumėte „Cloud Code“ registraciją, tada atnaujinkite prieigos raktą „OmniRoute“ valdymo skydelyje.

### Prieigos rakto galiojimas baigėsi arba jis buvo atšauktas

**Požymis**: žurnaluose rodomos 401 klaidos arba pranešimai „Token has expired“.

**Sprendimas**: atnaujinkite prieigos raktą pasirinkdami Valdymo skydelis → Teikėjai → agy → spustelėkite atnaujinimo piktogramą. Jei pats atnaujinimo prieigos raktas buvo atšauktas, turėsite iš naujo autentifikuotis per OAuth.

## Sprendimų schema

```
Paskyra neveikia?
│
├─ Ar duomenų bazėje jai priskirtas projectId?
│  ├─ TAIP → Problema yra kitur (baigėsi prieigos rakto galiojimas, viršytas užklausų limitas ir pan.)
│  └─ NE ↓
│
├─ Ar paskyros šalies susiejimas nustatytas į ribojamą regioną?
│  ├─ TAIP → Pakeiskite regioną Google šalies susiejimo formoje
│  │         (https://policies.google.com/country-association-form)
│  │         Palaukite 1–24 valandas, tada bandykite dar kartą
│  └─ NE ↓
│
├─ Ar paskyra turi Google One AI Pro prenumeratą?
│  ├─ NE → Pirmiausia užsiprenumeruokite adresu one.google.com
│  └─ TAIP ↓
│
├─ Išbandykite automatinį aptikimą (atnaujinkite prieigos raktą valdymo skydelyje)
│  ├─ Veikia → Baigta
│  └─ Vis tiek nepavyksta ↓
│
└─ Rankiniu būdu: kompiuteryje paleiskite `agy login`
   ├─ Veikia → Atnaujinkite prieigos raktą valdymo skydelyje, projectId aptiktas
   └─ Nepavyksta → Patikrinkite klaidos pranešimą; tikėtina, kad problema susijusi su regionu arba prenumerata
```
