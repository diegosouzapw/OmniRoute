Nukreipkite **Claude Code** CLI (`claude`) į OmniRoute — vietinį arba nuotoliniame VPS —
naudodami kiekvienam modeliui skirtus profilius, analogiškai Codex konfigūracijai.

---

## Greitoji pradžia

```bash
# Paleiskite Claude Code su vietiniu OmniRoute (aktyvus kontekstas aptinkamas automatiškai)
omniroute launch

# Su nuotoliniu OmniRoute (įvykdžius `omniroute connect <host>`, tai atliekama automatiškai)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# Sugeneruokite kiekvienam modeliui skirtus profilius, tada paleiskite vieną iš jų
omniroute setup-claude            # įrašo ~/.claude/profiles/<name>/settings.json
omniroute launch --profile glm52  # Claude Code naudoja glm/glm-5.2 per OmniRoute
```

---

## Kaip Claude Code prisijungia prie šliuzo

Claude Code naudoja **Anthropic Messages API** ir į pasirinktinį galinį tašką
nukreipiamas aplinkos kintamaisiais (jis neturi `--base-url` parametro):

| Kintamasis                                   | Paskirtis                                                                                                |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `ANTHROPIC_BASE_URL`                         | Šliuzo šakninis URL (Claude Code prideda `/v1/messages`). **Be `/v1` priesagos.**                        |
| `ANTHROPIC_AUTH_TOKEN`                       | Siunčiamas kaip `Authorization: Bearer …` — naudokite savo OmniRoute prieigos prieigos raktą / API raktą |
| `ANTHROPIC_API_KEY`                          | Alternatyva: siunčiamas kaip `x-api-key`. Jei nustatyti abu, pirmenybė teikiama `ANTHROPIC_AUTH_TOKEN`   |
| `ANTHROPIC_MODEL`                            | Priverstinai naudoti konkretų modelį (nepaisoma numatytojo `/model` parinkiklio pasirinkimo)             |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` → vietinis `/model` parinkiklis pateikia `claude*`/`anthropic*` modelius iš `/v1/models`             |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`              | Apriboja vieno atsakymo išvesties žetonų skaičių (pvz., `65536`)                                         |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`            | Žetonų slenkstis automatiniam sutankinimui                                                               |

> Aplinkos kintamieji nuskaitomi **vieną kartą paleidimo metu** — juos pakeitę paleiskite Claude Code iš naujo.

`omniroute launch` visa tai nustato už jus: iš aktyvaus konteksto nustato bazinį URL ir prieigos raktą
(todėl po `omniroute connect <vps>` komanda `omniroute launch`
tiesiog veikia), patikrina serverio būklę ir paleidžia `claude`.

## Aptikimo pseudonimai — pateikite ne Claude modelius `/model` parinkiklyje

Claude Code šliuzo modelių aptikimo funkcija pateikia tik tuos ID, kurie prasideda `claude`
arba `anthropic`, todėl, kai `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`, vietinis
`/model` parinkiklis paprastai rodo **tik** OmniRoute Claude / Anthropic modelius —
`kimi/kimi-k2.6` arba `glm/glm-5.2` niekada nepateikiami, nors į juos užklausos nukreipiamos tinkamai.

OmniRoute gali dubliuoti bet kurį įjungtą modelį (ir derinį), suteikdamas jam `claude/…` ID, kad jis
praeitų šį filtrą ir būtų rodomas parinkiklyje:

```
kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<derinys "custo-otimizado"> →  claude/combo/custo-otimizado
```

Kai Claude Code pasirenkate vieną iš jų, prieš nukreipdamas užklausą OmniRoute pašalina `claude/`
apvalkalą ir atkuria tikrąjį ID — autentiškas `claude/<real-claude-model>` ID
(tikrasis Claude OAuth teikėjas) visada paliekamas nepakeistas.

**Pagal numatytuosius nustatymus ši funkcija išjungta** ir valdoma trijų lygių mechanizmu (pirmenybė
teikiama konkrečiausiam nustatymui), todėl įprastas OmniRoute nedubliuoja savo katalogo klientams, kurie
nenaudoja Claude Code:

| Lygis      | Kur                                                                                                |
| ---------- | -------------------------------------------------------------------------------------------------- |
| Modelis    | Teikėjo išsamios informacijos puslapis → kiekvieno modelio „Expose in Claude Code“ jungiklis       |
| Teikėjas   | Teikėjo išsamios informacijos puslapis → teikėjo lygio jungiklis (taikomas visiems jo modeliams)   |
| Visuotinis | Settings → Feature Flags → `EXPOSE_CC_DISCOVERY_ALIASES` (pagal numatytuosius nustatymus išjungta) |

Aplinkos kintamasis `EXPOSE_CC_DISCOVERY_ALIASES` priverstinai įjungia visuotinį lygį
ir turi pirmenybę prieš valdymo skydelio nuostatą (Feature Flags ekrane rodoma
pastaba „active via environment variable“, kai jis naudojamas). Teikėjų ir
modelių jungikliai leidžia nustatymą patikslinti — pvz., išjungus visuotinį lygį ir įjungus Kimi teikėją,
pateikiami tik Kimi modeliai.

> ⚠️ **Ne Claude modelių lango neatitikimas.** Claude Code daro prielaidą, kad bet kurio
> neatpažįstamo ID konteksto langas yra 200K (tikrojo lango dydžio jis negali nuskaityti iš
> `/v1/models`). Jei modelio langas didesnis (pvz., Kimi K2 yra 256K), nustatykite
> `CLAUDE_CODE_AUTO_COMPACT_WINDOW` reikšmę, mažesnę už tikrąjį modelio langą, kad
> automatinis sutankinimas nebūtų atliekamas per anksti. Anksčiau minėti sugeneruoti profiliai tai jau
> nustato kiekvienam modeliui.

## Įvadinis blokas valdymo skydelyje

Claude įrankio kortelėje (**Valdymo skydelis → CLI kodas**), šalia modelių aptikimo pseudonimo informacijos mygtuko, rodomas tikslus šiam egzemplioriui skirtas `settings.json` fragmentas su kopijavimo mygtuku:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<jūsų OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<jūsų OmniRoute API raktas>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}
```

Bazinis URL yra tas, kurį nustatė kortelė (įskaitant jūsų įvestą pasirinktinę reikšmę), ir jis jau normalizuotas — be `/v1` priesagos ir be baigiamojo pasvirojo brūkšnio. **Raktas niekada nerodomas**: bloke pateikiamas vietaženklis, todėl ekrano kopija ar įklijuotas fragmentas negali jo atskleisti. Pakeiskite vietaženklį savo raktu.

Po tuo pačiu `env` bloku pridėkite `CLAUDE_CODE_AUTO_COMPACT_WINDOW` kiekvienam modeliui, kurio tikrasis konteksto langas nėra 200K — Claude Code kiekvienam neatpažįstamam ID priskiria 200K, todėl kitu atveju automatinis glaudinimas suveikia netinkamu metu (žr. ankstesnio skyriaus įspėjimą). Fragmentų kūrimo priemonė taip pat priima šią reikšmę, todėl iškvietėjas, žinantis tikslinio modelio lango dydį, gali ją pateikti tiesiogiai.

Šaltinis: `src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet` (grynoji kūrimo funkcija, patikrinta vienetiniais testais), atvaizduojamas komponento `ClaudeGatewayOnboardingBlock`.

## Profiliai (`CLAUDE_CONFIG_DIR`)

Claude Code **neturi savųjų profilių failų** (kitaip nei Codex `~/.codex/<name>.config.toml`). Įprastas mechanizmas yra `CLAUDE_CONFIG_DIR` — atskiras konfigūracijos katalogas kiekvienam profiliui, turintis nuosavus `settings.json`, kredencialus, istoriją ir podėlį.

`omniroute setup-claude` gauna aktualų `/v1/models` katalogą ir kiekvienam modeliui įrašo po profilį į `~/.claude/profiles/<name>/settings.json`, naudodamas **tuos pačius pavadinimus kaip `setup-codex`** (`glm52`, `kimi-k27`, `deepseek-pro`, …):

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}
```

> **Autentifikavimo prieigos raktas niekada neįrašomas į profilį.** Paleiskite naudodami
> `omniroute launch --profile <name>` (ši komanda įterpia `ANTHROPIC_AUTH_TOKEN` iš
> aktyvaus konteksto) arba patys eksportuokite `ANTHROPIC_AUTH_TOKEN` ir vykdykite
> `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude`.

**Automatinis sinchronizavimas aptikus modelius (pasirenkamas).** OmniRoute gali automatiškai iš naujo sugeneruoti tuos pačius `~/.claude/profiles/<name>/settings.json` failus, kai teikėjo modelių sinchronizavimas pakeičia aktualų katalogą — taip nauji ar pervardyti modeliai gauna profilius, iš naujo nevykdant komandos. Pagal numatytąją nuostatą ši funkcija yra **išjungta**: įjunkite ją **CLI kodo valdymo skydelyje** („Automatinis CLI profilių sinchronizavimas“ → Claude Code) arba nustatykite `OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true` (taip pat atsižvelgiama į `CLI_ALLOW_CONFIG_WRITES`, kuri pagal numatytąją nuostatą įjungta). Įjungus šią funkciją, įrašomi tik profilių failai; aktyvi arba numatytoji Claude konfigūracija, autentifikavimo duomenys ir `~/.claude/settings.json` niekada nekeičiami.

### Profilių generavimas ir naudojimas

```bash
# Vietinis OmniRoute
omniroute setup-claude

# Nuotolinis VPS (VPS URL įrašomas į kiekvieną profilį)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# Tik kai kurie teikėjai
omniroute setup-claude --only glm,kimi

# Peržiūra nieko neįrašant
omniroute setup-claude --dry-run

# Profilio paleidimas
omniroute launch --profile kimi-k27
```

## Modelių lygiai (neprivaloma)

Claude Code nukreipia užklausas pagal galimybių lygius. Jei kiekvienam lygiui norite naudoti skirtingus teikėjus, susiekite jį su OmniRoute modeliu naudodami aplinkos kintamuosius / nustatymus:

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm/glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="kmc/kimi-k2.6"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="glm/glm-4.7-flash"
```

Priešingu atveju viskam naudojamas vienas `ANTHROPIC_MODEL` (kurį nustato profiliai).

## Nuotolinis režimas

Paleidus `omniroute connect <host>` (žr.
[Nuotolinis režimas](./REMOTE-MODE.md)), `omniroute launch` ir `omniroute setup-claude`
automatiškai naudoja tą nuotolinį serverį bei jam skirtą ribotos apimties prieigos prieigos raktą — jokių
papildomų parinkčių nereikia. Konkrečiam paleidimui šį nustatymą galite pakeisti naudodami `--remote` / `--api-key`.

## Trikčių šalinimas

**Claude Code nepaiso šliuzo** — įsitikinkite, kad `ANTHROPIC_BASE_URL` **neturi
`/v1`**, ir iš naujo paleiskite `claude` (aplinkos kintamieji nuskaitomi vieną kartą paleidimo metu). `omniroute launch`
tuo pasirūpina už jus.

**`/model` parinkiklis tuščias / jame nėra šliuzo modelių** — reikia Claude Code
v2.1.219+ ir `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`. Parinkiklyje rodomi tik `claude*` /
`anthropic*` modelių ID; norėdami priverstinai naudoti bet kurį kitą modelį, nustatykite
`ANTHROPIC_MODEL=<id>` (būtent taip veikia profiliai).

**`400 Ambiguous model 'claude-…'`** — Claude Code visada siunčia modelių ID **be prefikso**
(pvz., `claude-opus-4-8`), todėl, kai prijungti ir Claude Code (`cc/…`), ir
Claude (`claude/…`) teikėjai, ID be prefikso atitinka du maršrutus, o
OmniRoute atsisako spėti. Tai galima išspręsti dviem būdais: nurodykite ID su prefiksu naudodami
`ANTHROPIC_MODEL=cc/claude-opus-4-8` arba įjunkite **Teikti pirmenybę Claude Code
Claude modeliams be prefikso** — šį jungiklį rasite Claude teikėjo puslapyje; taip pat galite nustatyti
`OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true` (pagal numatytąsias nuostatas išjungta;
žr. [Aplinka](../reference/ENVIRONMENT.md)) — tuomet ID be prefikso `claude-*`
bus nukreipiami į Claude Code. Aiškiai nurodyti teikėjo prefiksai visada turi pirmenybę.

**Autentifikavimo klaidos** — profilyje nėra prieigos rakto. Naudokite `omniroute launch --profile`
(jis įterpia prieigos raktą) arba eksportuokite `ANTHROPIC_AUTH_TOKEN`.

**Profiliai nėra izoliuoti** — kiekvienas profilis turi atskirą `CLAUDE_CONFIG_DIR`;
seanso viduje patikrinkite, ar `echo $CLAUDE_CONFIG_DIR` nurodo
`~/.claude/profiles/<name>`.
