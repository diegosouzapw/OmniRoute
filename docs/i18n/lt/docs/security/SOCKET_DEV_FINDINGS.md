> **Taikymo srities pastaba:** `socket.yml` konfigūruoja Socket.dev registro pusėje po paskelbimo atliekamą npm artefakto nuskaitymą (neįtraukiamus kelius, skirtus neplatinamam turiniui, pvz., `tests/`, `docs/` ir kompiliavimo ataskaitoms). Jis nesukuria CI/PR suliejimo kontrolės — jokia darbo eiga, esanti `.github/workflows`, joks `package.json` scenarijus ir joks `Makefile` tikslas neiškviečia Socket.dev.

Šis dokumentas yra prižiūrėtojo parengtas patvirtinimas dėl šešių
`DI aptiktos galimos kenkėjiškos programinės įrangos` radinių, nustatytų `omniroute@3.8.5`, ir
rizikos mažinimo priemonių, pritaikytų `omniroute@3.8.6`. Jis skirtas tam, kad:

1. Saugumo procesų operatoriai turėtų vieną nuorodą, kurią galėtų nurodyti, kai jiems reikia
   įvertinti radinius pagal faktinį pirminį kodą.
2. Būsimi DI skaitytuvai galėtų aptikti prižiūrėtojo pasirašytą pareiškimą, kad kiekvienas
   pažymėtas kelias yra numatytas, pasirenkamas ir dokumentuotas.
3. Turėtume rašytinį įrašą, _kodėl_ kiekviena iškvietimo vieta suformuota būtent taip —
   kad ateityje pertvarkant kodą nebūtų netyčia vėl įvestas požymis, kuris
   buvo sąmoningai pašalintas.

Jei naudojate skaitytuvą, kuris po v3.8.6 rizikos mažinimo priemonių išleidimo
vėl pažymi kurią nors iš toliau nurodytų iškvietimo vietų, atidarykite problemą, pridėkite
nuskaitymo seką, ir mes čia papildysime patvirtinimą.

## §1 — MITM šakninio CA diegimas (`77484.js`)

**Pirminio kodo failai**:

- `src/mitm/cert/install.ts` — viešosios `installCert()` / `uninstallCert()`
  funkcijos ir kiekvienai platformai skirtos `installCertWindows/Mac/Linux`.
- `src/mitm/systemCommands.ts` — bendri `execFile` / `spawn` / PowerShell
  pagalbiniai elementai, kuriuos naudoja diegimo keliai.

**Aktyvinimas**: naudotojas vietiniame valdymo skydelyje, adresu
`/dashboard/cli-tools/mitm`, spustelėja „Įjungti MITM tarpinį serverį“. Maršrutas
pasiekiamas tik per grįžtamąją sąsają — žr. griežtą taisyklę Nr. 17 faile
`CLAUDE.md` ir `src/server/authz/routeGuard.ts::isLocalOnlyPath()`. Per tunelį
atskleistas JWT **negali** suaktyvinti šio kodo kelio.

**Atliekamos privilegijuotos operacijos (pagal platformą)**:

| OS                     | Komanda (-os)                                                                                                     |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | `certutil -addstore Root <cert>` per UAC                                                                          |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | kiekvieno profilio NSS DB atnaujinimas naudojant `certutil -d sql:<profile>`                                      |

Tai tos pačios komandos, kurias naudoja `mitmproxy`, Charles Proxy, Fiddler ir
Caddy. Faktas, kad jos egzistuoja OmniRoute, dokumentuotas faile
`docs/security/STEALTH_GUIDE.md`.

**v3.8.6 rizikos mažinimas**:

- `runElevatedPowerShell()` nebenaudoja `-EncodedCommand <base64utf16le>`.
  Padidintomis teisėmis vykdoma naudingoji apkrova įrašoma į kiekvienam
  iškvietimui skirtą laikiną `.ps1` failą (režimas 0o600, privačiame
  `mkdtempSync` kataloge), o į jį nurodoma naudojant `-File`. Failas pašalinamas
  bloke `finally`. Taip pašalinamas tipinis teisių padidinimo per PowerShell
  naudojant base64 požymis, kurį pažymėjo Socket.dev DI klasifikatorius.
- `installCertWindows` turi įterptinį `SECURITY-AUDITOR-NOTE:` bloką,
  nukreipiantį čia.

**Kodėl tai paliekame**: MITM tarpinis serveris yra dokumentuota funkcija,
naudojama `docs/security/STEALTH_GUIDE.md` ir
`docs/frameworks/MITM-PROXY.md`. Ją pašalinus būtų sugadintas agento tilto
funkcijų rinkinys.

## §2 — Zed prisijungimo duomenų importavimas (`app/api/providers/zed/import/route.js`)

**Šaltinio failai**:

- `src/app/api/providers/zed/discover/route.ts` _(naujas v3.8.6 versijoje)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(naujas v3.8.6 versijoje)_

**Aktyvinimas**: naudotojas vietinio valdymo skydelio teikėjų puslapyje
spusteli „Importuoti iš Zed“. Prieiga prie galinio taško ribojama naudojant
`requireManagementAuth`. Pats Zed redaktorius įrašo savo teikėjų API raktus į
OS raktinę, naudodamas dokumentacijoje nurodytus paslaugų pavadinimus — žr.
https://zed.dev/docs/ai/llm-providers.

**v3.8.5 veikimas (kurį pažymėjo Socket.dev)**:

`POST /import` aptikdavo prisijungimo duomenis ir vienos užklausos metu
automatiškai juos įrašydavo į vietinę SQLite saugyklą. Nebuvo nei atskiro
kiekvienos paskyros patvirtinimo, nei kontrolinio atspaudo — tik „rasta N
prieigos raktų, visi importuoti“.

**v3.8.6 rizikos mažinimo priemonė — 2 žingsnių patvirtinimas**:

1. **`POST /api/providers/zed/discover`** grąžina
   `{ candidates: [{ provider, service, account, fingerprint }] }`. Neapdorotas
   prieigos raktas **niekada** neperduodamas. Kontrolinis atspaudas yra
   `sha256(service|account|token).slice(0,16)`.
2. Valdymo skydelyje pateikiamas kandidatų sąrašas, operatorius pasirenka,
   kuriuos iš jų importuoti, ir siunčia
   `{ confirmedAccounts: [{ service, account, fingerprint }] }` į
   **`POST /api/providers/zed/import`**.
3. Importavimo galinis taškas **iš naujo nuskaito raktinę serveryje** ir
   filtruoja pagal `(service, account, fingerprint)`. Suklastotas ar pakartotinai
   panaudotas aptikimo atsakas negali priversti importavimo galinio taško
   išsaugoti nesusijusio prieigos rakto — jei nuo aptikimo momento aktyvus
   prieigos raktas pasikeitė, kontrolinis atspaudas nebesutampa ir prisijungimo
   duomenys praleidžiami.

`OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` aplinkos kintamojo žyma išsaugo
v3.8.5 veikimą operatoriams, kurie dar neatnaujino savo automatizavimo. Ji bus
pašalinta v3.9 versijoje.

**Kodėl tai paliekame**: Zed importavimas yra patogiausias pradinis būdas
naudotojams, kurie jau naudoja Zed ir nori nukopijuoti savo teikėjų raktus į
OmniRoute jų iš naujo neįklijuodami.

## §3 — `execFile` / `spawn` / padidintomis teisėmis vykdoma PowerShell (`21843.js`)

**Šaltinio failai**: `src/mitm/systemCommands.ts`.

**Kodėl pažymėta**: šis fragmentas pakartotinai eksportuoja
`execFileWithPassword`, `runElevatedPowerShell` ir bendrinamą pagalbinę
funkciją `quotePowerShell`. Socket.dev DI klasifikatorius juos vertina kaip
bendrosios paskirties „vykdymo pagrindiniame kompiuteryje ir teisių
padidinimo įrankių rinkinį“. OmniRoute sistemoje jie naudojami tik MITM
sertifikato diegimo procese (§1), o `execFileWithPassword` — `sudo` komandoms
vykdyti.

**v3.8.6 rizikos mažinimo priemonės**:

- `runElevatedPowerShell` pertvarkymas (žr. §1).
- Įterptasis `SECURITY-AUDITOR-NOTE:` blokas prie `runElevatedPowerShell` ir
  `execFileWithPassword` dokumentuoja į leidžiamųjų sąrašą įtrauktus
  iškvietėjus bei fiksuotą vykdomųjų failų sąrašą.
- `execFileWithPassword` funkcijos `spawn()` iškvietime yra `nosemgrep` žymuo
  su vykdomųjų failų, kuriuos leidžiama perduoti šiai pagalbinei funkcijai,
  leidžiamuoju sąrašu — kelio nuo naudotojo įvesties iki
  `finalCommand`/`finalArgs` **nėra**.

## §4 / §6 — 9router paslaugos priežiūros procesas (`api/services/9router/{start,restart}/route.js`)

**Šaltinio failai**:

- `src/app/api/services/9router/_lib.ts` — priežiūros proceso kūrimo funkcija.
- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`.
- `src/lib/services/ServiceSupervisor.ts` — bendrosios paskirties procesų paleidimo / būklės tikrinimo / žurnalų kaupimo atminties buferyje priemonė.

**Aktyvinimas**: naudotojas vietinio valdymo skydelio įterptųjų paslaugų
puslapyje spusteli „Įdiegti“ / „Paleisti“.

**Jau įdiegtos apsaugos priemonės**:

- Visi `/api/services/*` maršrutai pagal
  `src/server/authz/routeGuard.ts` yra LOCAL_ONLY (griežta taisyklė Nr. 17).
  Prieigos tik iš grįžtamojo ryšio sąsajos tikrinimas atliekamas prieš bet kokį
  tapatybės nustatymo patikrinimą — nutekėjęs JWT negali jų pasiekti.
- 9router DB eilutė pradiniais duomenimis užpildoma kaip
  `status='not_installed', auto_start=0` (žr.
  `src/lib/db/migrations/071_services.sql:19`). Pirmą kartą paleidžiant
  programą paslauga **nepaleidžiama**.
- `spawn()` iškviečiama naudojant dvejetainio failo kelią, kurį grąžina
  `resolveSpawnArgs(apiKey, PORT)` faile
  `src/lib/services/installers/ninerouter.ts`; tai yra fiksuotas palaikomų
  dvejetainių failų leidžiamasis sąrašas.
- Stdout/stderr duomenys kaupiami atminties buferyje (5 MB riba, žr.
  `_lib.ts`) — diske niekas neįrašoma, nebent naudotojas valdymo skydelyje
  įjungia žurnalų rašymą.

**v3.8.6 rizikos mažinimo priemonė**: funkcinių pakeitimų nėra. Minimalus
komponavimo profilis (`OMNIROUTE_BUILD_PROFILE=minimal`) pakeičia
`src/lib/services/installers/ninerouter.ts` imitacine realizacija, skirta
naudotojams, kurie nori, kad privilegijuoti keliai būtų fiziškai pašalinti iš
rinkinio.

**Kodėl tai paliekame**: 9router yra pasirinktinė, vietoje įdiegiama papildoma
paslauga (panaši į WordPress papildinį), kuri naudojama tik aiškiai pasirinkus.

## §5 — „OmniRoute Cloud Sync“ prisijungimo duomenų atgalinis įrašymas (`api/keys/[id]/route.js`)

**Šaltinio failai**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`.
- `src/app/api/keys/[id]/route.ts` — iškviečia `syncKeysToCloudIfEnabled()`.

**Aktyvinimo sąlyga**: `isCloudEnabled()` grąžina `true` (nustatoma valdymo skydelyje) **ir**
yra sukonfigūruotas `CLOUD_URL`. Kai abi parinktys išjungtos, jokia išeinanti
tinklo užklausa į „Cloud“ galinį tašką nesiunčiama.

**v3.8.5 veikimas (klaida, kurią „Socket.dev“ teisingai aptiko)**:

`updateLocalTokens()` perrašydavo `accessToken`, `refreshToken` ir
`providerSpecificData` reikšmėmis iš „Cloud“ atsako, kai
`cloudUpdatedAt > localUpdatedAt`. Jokio HMAC, jokio parašo, jokios kontrolinės
sumos. Neteisingai sukonfigūruotas arba priešiškas `CLOUD_URL` (arba kanale
veikiantis MITM) galėjo nepastebimai pakeisti teikėjo OAuth prieigos raktus.

**v3.8.6 rizikos mažinimo priemonės**:

1. **HMAC tikrinimas**: `verifyCloudSignature(rawBody, sigHeader)` prieš
   analizuodama JSON patikrina `X-Cloud-Sig` antraštę
   (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET, rawBody)`). Jei paslaptis
   nustatyta, parašas yra privalomas. Jei ne (senasis režimas), į žurnalą
   įrašomas įspėjimas ir atsakas priimamas — v3.9 versijoje paslaptis bus
   privaloma.
2. **Aiškus sutikimas sinchronizuoti slaptus laukus**: `accessToken` /
   `refreshToken` / `providerSpecificData` perrašomi **tik** tada, kai
   `OMNIROUTE_CLOUD_SYNC_SECRETS=true`. Numatytuoju režimu sinchronizuojami tik
   su prisijungimo duomenimis nesusiję metaduomenys (`expiresAt`, `status`,
   `lastError*`, `rateLimitedUntil`, `updatedAt`). Tai yra **nesuderinamas
   pakeitimas** naudotojams, kurie naudojosi nuotoliniu prieigos raktų
   sinchronizavimu — jie turi aiškiai jį įjungti.

**Kodėl tai paliekame**: „Cloud Sync“ yra vienintelis būdas „OmniRoute Cloud“
nuomininkui centralizuotai valdyti komandos prisijungimo duomenis. Pataisa
tiksliai atspindi grėsmių modelį:
„serveris pasirašo, klientas patikrina, operatorius aiškiai sutinka“.

## Kompiliavimo profilis: `minimal`

Naudotojai, kuriems reikia su „Socket“ suderinamo artefakto, gali jį
sukompiliuoti taip:

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

Webpack `NormalModuleReplacementPlugin` keturiems moduliams priskiria pakaitinius modulius:

| Modulis                                     | Pakaitinis modulis                               |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

Kiekvienas pakaitinis modulis eksportuoja tokią pačią sąsają, tačiau vykdymo
metu kiekviena funkcija išmeta `featureDisabledError(name)`. Maršrutai,
priklausantys nuo išjungto modulio, užuot aktyvinę jautrų kodo kelią, grąžina
HTTP 503 su aiškiu pranešimu.

Gautas paketas skirtas publikuoti kaip `omniroute-secure`. Publikavimo
instrukcijas rasite `docs/ops/PUBLISHING_SECURE.md`.

## Papildinio išskaidymas (stebima v4 versijai)

Ilgainiui ketiname išskaidyti npm paketą į atskirai audituojamus
modulius. Stebėjimo problemą rasite GitHub problemų sekimo sistemos v4 etape.
