„OmniRoute“ publikuoja npm ir Docker artefaktus. Šios patikros užtikrina kilmės informaciją,
inventorizaciją (SBOM) ir CVE nuskaitymą; jos visos yra atvirojo kodo ir integruotos į leidimo darbo eigas.
Taikoma **pirmiausia įspėjanti** strategija — dabar jos tik teikia ataskaitas, o po pirmojo
sėkmingo leidimo bus pakeistos į blokuojančias.

| Patikra                | Įrankis                                        | Kur                               | Blokuoja?                       | Išvestis                                           |
| ---------------------- | ---------------------------------------------- | --------------------------------- | ------------------------------- | -------------------------------------------------- |
| SLSA kilmė (npm)       | `npm --provenance` (OIDC)                      | `npm-publish.yml`                 | tik jei publikavimas nepavyksta | npmjs ženklelis / `npm audit signatures`           |
| npm SBOM               | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`                 | tik jei generavimas nepavyksta  | Leidimo išteklius + artefaktas                     |
| Atvaizdo SBOM          | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (sujungimas) | įspėjamoji                      | CycloneDX artefaktas                               |
| Trivy CVE (SARIF)      | `aquasecurity/trivy-action`                    | `docker-publish.yml` (sujungimas) | įspėjamoji                      | SARIF (HIGH+CRITICAL) → Saugos skirtukas           |
| Trivy CRITICAL patikra | `aquasecurity/trivy-action`                    | `docker-publish.yml` (sujungimas) | **blokuojanti**                 | `exit-code: '1'` esant ištaisomai CRITICAL         |
| osv vulnCount          | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`)     | **blokuojanti**                 | fiksuoja `metrics.vulnCount` ribą (kryptis: žemyn) |
| OpenSSF Scorecard      | `ossf/scorecard-action`                        | `scorecard.yml` (cron)            | įspėjamoji                      | SARIF → Sauga + ženklelis                          |

Atvaizdo CVE slenkstinė patikra naudoja **du žingsnius** faile `docker-publish.yml`: SARIF žingsnis
(`HIGH,CRITICAL`, `exit-code: 0`) užtikrina, kad HIGH+CRITICAL pažeidžiamumai būtų matomi Saugos skirtuke
ir neblokuotų; _CRITICAL patikros_ žingsnis (`severity: CRITICAL`, `ignore-unfixed: true`,
`exit-code: 1`) sustabdo leidimą aptikus CRITICAL CVE, **kurį galima ištaisyti**. `ignore-unfixed`
neleidžia blokuoti leidimo dėl bazinio atvaizdo CVE, kuriam dar nėra aukštesnio lygmens pataisos.

## ⚠️ CVE kintamumas (blokuojančios osv/Trivy patikros)

osv ir Trivy lygina priklausomybes su CVE duomenų bazėmis, kurios **nuolat auga**. PR,
kuris **nekeičia jokių priklausomybių**, gali staiga tapti nesėkmingas, nes esamoje
priklausomybėje buvo paskelbtas naujas CVE (osv: išmatuotas `vulnCount` > bazinė reikšmė; Trivy: atvaizde
atsirado naujas ištaisomas CRITICAL pažeidžiamumas). **Tai yra NUMATYTAS blokuojančios
CVE patikros veikimas, o ne produkto regresija.**

Kai osv arba Trivy patikra nepavyksta dėl naujai paskelbto CVE, reikia:

1. **Atnaujinti paveiktą priklausomybę** (pageidautina) — pereiti prie pataisytos versijos naudojant `package.json`
   `overrides` (tranzityviosioms priklausomybėms) arba iš naujo sukurti atvaizdą naudojant pataisytą bazę.
2. **Jei aukštesniame lygmenyje pataisos nėra:**
   - **osv:** iš naujo nustatyti bazinę `metrics.vulnCount` reikšmę faile `config/quality/quality-baseline.json`
     (`npm run quality:ratchet -- --update` neapima specializuotų patikrų — pakeiskite reikšmę
     rankiniu būdu, `direction:down`), pridėdami pagrindimo pastabą ir stebėjimo užduotį.
   - **Trivy:** pridėti įrašą į `.trivyignore` (po vieną CVE-ID eilutėje), nurodant pagrindimą
     komentare ir stebėjimo užduotį. `ignore-unfixed: true` jau automatiškai apima CVE,
     kuriems pataisų nėra.

Abi patikros **korektiškai PRALEIDŽIAMOS** (baigimo kodas 0), kai įrankio nėra arba matavimas
nepavyksta (`osv-scanner` nėra PATH, osv.dev / tinklas nepasiekiamas, netinkamas JSON) —
**matavimo** klaida niekada neblokuoja; blokuoja tik **išmatuota** regresija.

## Neatliktų darbų sąrašas: Scorecard įspėjamoji patikra → blokuojanti

Po pirmojo sėkmingo leidimo su Scorecard ataskaita:

- Scorecard: įverčio slenkstinė patikra (užfiksuoja išmatuotą įvertį; jis negali mažėti).

Papildo 7 etapo patikras (osv-scanner, gitleaks, actionlint+zizmor): zizmor
tikrina pačias darbo eigas, o Scorecard bendrai vertina saugyklos būklę.
