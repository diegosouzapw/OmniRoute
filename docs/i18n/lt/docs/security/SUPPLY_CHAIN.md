OmniRoute publikuoja npm + Docker artefaktus. Šie vartai užtikrina kilmę,
inventorių (SBOM) ir CVE nuskaitymą, visa tai yra atvirojo kodo (OSS), integruota į išleidimo darbo eigas.
**Pirmiausia patariamoji** pozicija – jie praneša dabar, o blokuojančiais tampa po pirmojo
sėkmingo išleidimo.

| Vartai                | Įrankis                                        | Kur                               | Blokuoja?                       | Išvestis                                     |
| :-------------------- | :--------------------------------------------- | :-------------------------------- | :------------------------------ | :------------------------------------------- |
| SLSA kilmė (npm)      | `npm --provenance` (OIDC)                      | `npm-publish.yml`                 | tik jei publikavimas nepavyksta | ženklelis npmjs / `npm audit signatures`     |
| SBOM npm              | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`                 | tik jei generavimas nepavyksta  | Išleidimo turtas + artefaktas                |
| SBOM atvaizdas        | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (sujungimas) | patariamasis                    | CycloneDX artefaktas                         |
| Trivy CVE (SARIF)     | `aquasecurity/trivy-action`                    | `docker-publish.yml` (sujungimas) | patariamasis                    | SARIF (HIGH+CRITICAL) → Skirtukas „Security“ |
| Trivy CRITICAL vartai | `aquasecurity/trivy-action`                    | `docker-publish.yml` (sujungimas) | **blokuojantis**                | `exit-code: '1'` esant pataisomam CRITICAL   |
| osv vulnCount         | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`)     | **blokuojantis**                | didina `metrics.vulnCount` (kryptis: žemyn)  |
| OpenSSF Scorecard     | `ossf/scorecard-action`                        | `scorecard.yml` (cron)            | patariamasis                    | SARIF → Skirtukas „Security“ + ženklelis     |

Atvaizdo CVE „ratchet“ naudoja **du žingsnius** `docker-publish.yml`: SARIF žingsnis
(`HIGH,CRITICAL`, `exit-code: 0`) išlaiko HIGH+CRITICAL matomus skirtuke „Security“
neblokuodamas; _CRITICAL vartų_ žingsnis (`severity: CRITICAL`, `ignore-unfixed: true`,
`exit-code: 1`) nutraukia išleidimą, jei aptinkamas CRITICAL CVE **su galimu pataisymu**. `ignore-unfixed`
neleidžia blokuoti išleidimo dėl bazinio atvaizdo CVE be aukštesniojo lygio pataisymo.

## ⚠️ CVE Variacija (blokuojantys osv/Trivy vartai)

osv ir Trivy lygina priklausomybes su CVE duomenų bazėmis, kurios **nuolat auga**. PR,
kuris **neliečia jokių priklausomybių**, gali staiga tapti raudonas, nes naujas CVE buvo
atskleistas esamoje priklausomybėje (osv: išmatuotas `vulnCount` > bazinė vertė; Trivy: naujas
pataisomas CRITICAL atvaizde). **Tai yra TIKĖTINAS blokuojančių CVE vartų veikimo elgesys,
o ne produkto regresija.**

Kai osv arba Trivy tampa raudoni dėl naujai atskleisto CVE, sprendimas yra:

1.  **Atnaujinti paveiktą priklausomybę** (pageidautina) – atnaujinti į pataisytą versiją per `package.json`
    `overrides` (tranzityvinės priklausomybės) arba perkurti atvaizdą ant pataisytos bazės.
2.  **Jei nėra aukštesniojo lygio pataisymo:**
    - **osv:** iš naujo nustatyti `metrics.vulnCount` bazinę vertę `config/quality/quality-baseline.json`
      (`npm run quality:ratchet -- --update` neapima specialių vartų – redaguokite reikšmę
      rankiniu būdu, `direction:down`) su pagrindimu ir sekimo problema.
    - **Trivy:** pridėti įrašą į `.trivyignore` (CVE-ID eilutėje) su pagrindimo
      komentaru ir sekimo problema. `ignore-unfixed: true` jau automatiškai apima CVE be
      pataisymų.

Abu vartai **gracingai PRALEIDŽIA** (išeina 0), kai įrankio nėra arba matavimas
nepavyksta (osv-scanner nėra PATH, osv.dev/tinklas nepasiekiamas, neteisingas JSON) –
**matavimo** gedimas niekada neblokuoja, blokuoja tik **išmatuota** regresija.

## Žinomos priimtinos rizikos

### extract-zip 2.0.1 — GHSA-7pqw-9j4j-h8q3 / GHSA-jmr9-qjv8-65gv (#14482)

`extract-zip@2.0.1` turi du nepašalintus didelio rimtumo simbolinių nuorodų perėjimo patarimus.
Pagal aukščiau minėtą CVE Varianto pataisos „nėra pataisymo iš tiekėjo“ šaką, tai yra
**priimtina rizika**, o ne atnaujinimas:

- **Grandinė:** `promptfoo` (kūrimo priklausomybė) → `@openai/codex-security` → `extract-zip@2.0.1`.
  Patvirtinta per `package-lock.json` – lygiai vienas paketas visame priklausomybių
  medyje (`@openai/codex-security`) deklaruoja `extract-zip`, ir lygiai vienas paketas
  (`promptfoo`) deklaruoja `@openai/codex-security`.
- **Visoje grandinėje nėra išleistos pataisytos versijos.** `extract-zip@2.0.1` (išleistas 2020 m.) yra paskutinė paketo versija – jis nebepalaikomas. `@openai/codex-security`
  dabartinė naujausia npm versija (`0.1.29`) vis dar naudoja `extract-zip@2.0.1`.
- **Nepasiekiamas iš gamybos aplinkos.** `promptfoo` yra tik kūrimo priklausomybė (niekada nenurodyta
  `dependencies` sąraše), ir joks failas `src/`, `open-sse/` ar `bin/` kataloguose neimportuoja
  `extract-zip` npm paketo – OmniRoute nuosavas `extractZip()` pagalbinis metodas
  (`src/lib/versionManager/binaryManager.ts:93`) naudoja vietines `unzip`/`tar`
  komandas ir yra nesusijęs. `@openai/codex-security` taip pat turi savo simbolinių nuorodų perėjimo
  apsaugą, papildančią `extract-zip` `onEntry` atgalinio iškvietimo funkciją.
- **Nekurkite** `extract-zip` pseudonimo per `package.json` `overrides` – vienintelis tinkamas
  pakeitimas yra „Electron-org-internal“ ir jis yra API nesuderinamas su
  `@openai/codex-security` `onEntry`/`defaultDirMode`/`defaultFileMode` patikromis;
  jį perrašius, tyliai sugadintų to paketo saugumo patikras.
- **Pradinė reikšmė:** išmatuotas osv `vulnCount` (3) jau yra gerokai mažesnis už užfiksuotą
  `config/quality/quality-baseline.json` pradinę reikšmę (27) – nereikia keisti ribos.
- **Regresijos apsauga:** `tests/unit/extract-zip-14482-exposure.test.ts` patvirtina
  grandinę ir aukščiau minėtą neimportavimo į gamybos aplinką invariantą; CI nepavyks, jei bet kuris iš jų kada nors
  bus pažeistas (pvz., būsimas PR padarys `extract-zip` pasiekiamą iš gamybos aplinkos).
- **Sekimas:** problema #14482.
