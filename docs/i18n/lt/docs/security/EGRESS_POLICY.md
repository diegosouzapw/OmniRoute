> **Kiekvienam tarpiniam serveriui priskirkite siunčiamąjį srautą vienai IP šeimai — `auto`, `ipv4` arba `ipv6`, — kad tik per IPv6 veikiantis išėjimas niekada nepastebimai negrįžtų prie IPv4.**

> **Pirminis tiesos šaltinis:** `open-sse/utils/proxyFamily.ts`, `open-sse/utils/proxyDispatcher.ts`, `open-sse/utils/proxyFetch.ts`, `open-sse/utils/socksConnectorWithFamily.ts`, `open-sse/utils/proxyFamilyResolve.ts`, `src/shared/validation/schemas.ts`, `src/lib/db/proxies.ts`, `src/lib/db/upstreamProxy.ts`, `src/lib/db/migrations/099_proxy_family.sql`

OmniRoute leidžia kiekvienam tarpiniam serveriui turėti **adresų šeimos siunčiamojo srauto direktyvą**. Pagal numatytuosius nustatymus operacinė sistema pasirenka IPv4 arba IPv6 (dvigubas dėklas, „Happy Eyeballs“). Nustačius direktyvą į `ipv4` arba `ipv6`, OmniRoute kiekvieną per tą tarpinį serverį užmezgamą ryšį priskiria pasirinktai šeimai ir **saugiai nutraukia ryšį**, užuot perėjusi prie kitos šeimos.

Šiame puslapyje aprašoma, kas yra ši direktyva, kodėl ji reikalinga, kur ją konfigūruoti ir kaip vykdymo metu ji nustatoma.

## Kas tai yra

Kiekvienas registre esantis tarpinis serveris turi lauką `family` su trimis galimomis reikšmėmis, kurias tikrina Zod išvardijimas:

```ts
// src/shared/validation/schemas.ts
family: z.enum(["auto", "ipv4", "ipv6"]).optional().default("auto"),
```

Numatytoji lauko reikšmė yra `"auto"`, išsauganti ankstesnę dvigubo dėklo elgseną. Nustačius `ipv4` arba `ipv6`, tam tarpiniam serveriui priskiriama atitinkama prisijungimo šeima.

Direktyva visur normalizuojama naudojant vieną pagalbinę funkciją, todėl bet kokia nežinoma reikšmė pakeičiama į `auto`:

```ts
// open-sse/utils/proxyFamily.ts
export type ProxyFamily = "auto" | "ipv4" | "ipv6";

export function parseProxyFamily(value: unknown): ProxyFamily {
  return value === "ipv4" || value === "ipv6" ? value : "auto";
}
```

## Kodėl tai reikalinga

Pristatyta PR [#3777](https://github.com/diegosouzapw/OmniRoute/pull/3777). Pagrindinės problemos, paskatinusios tai įgyvendinti:

| Problema                                               | Ką išsprendžia direktyva                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Tik IPv6 naudojančio išėjimo nutekėjimas į IPv4**    | Kai tarpinio serverio pagrindinio kompiuterio vardas turi ir A, ir AAAA įrašus (arba operacinė sistema teikia pirmenybę IPv4), „Happy Eyeballs“ gali užmegzti išeinantį ryšį per IPv4, net jei numatytas tik IPv6 kelias. Priskyrus `ipv6`, šis nutekėjimas pašalinamas.                                                                                             |
| **Prieigos panaikinimas dėl bendro išėjimo anomalijų** | Rotaciją taikantys paslaugų teikėjai (codex/openai) panaikina prieigos raktus, kai daug paskyrų dideliu srautu naudoja **tą patį** išėjimo IP adresą. Išėjimo šeimos valdymas padeda paskyroms naudoti skirtingus ir nuspėjamus išėjimo kelius (žr. [`src/lib/proxyEgress.ts`](../../src/lib/proxyEgress.ts), kur pateikiama su tuo susieta išėjimo IP diagnostika). |
| **Deterministinis išėjimas atitikčiai / testavimui**   | Kai būtina garantuoti, kad srautas išeis per konkrečią šeimą, `auto` nepakanka.                                                                                                                                                                                                                                                                                      |

Direktyva sąmoningai taikoma **kiekvienam tarpiniam serveriui atskirai**, o ne visuotinai — skirtingi jūsų telkinio tarpiniai serveriai gali turėti skirtingas strategijas.

## Trys reikšmės

| Reikšmė | Naudotojo sąsajos etiketė        | Veikimas                                                                                                                                                                                                           |
| ------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `auto`  | `Automatiškai (dvigubas dėklas)` | OS parenka šeimą. Kai tarpinio serverio prieglobos adresas yra tiesioginis IP adresas, šeimą lemia pats adresas; kai naudojamas pagrindinio kompiuterio vardas, galima naudoti abi šeimas. Tai numatytoji reikšmė. |
| `ipv4`  | `Tik IPv4`                       | Apriboja ryšį iki IPv4. Ryšys saugiai nutraukiamas, jei tarpinio serverio pagrindinio kompiuterio vardas neturi IPv4 (A) įrašo.                                                                                    |
| `ipv6`  | `Tik IPv6`                       | Apriboja ryšį iki IPv6. Ryšys saugiai nutraukiamas, jei tarpinio serverio pagrindinio kompiuterio vardas neturi IPv6 (AAAA) įrašo.                                                                                 |

Naudotojo sąsajos eilutės yra faile `src/i18n/messages/en.json` (`labelFamily`, `familyAuto`, `familyIpv4`, `familyIpv6`, `familyHint`).

## Kaip tai sukonfigūruoti

### Valdymo skydelis

Parinkiklis yra skirtuko **Tarpinių serverių telkinys** tarpinio serverio formoje:

1. Atidarykite **Valdymo skydelis → Nustatymai → Tarpinis serveris → Tarpinių serverių telkinys**
2. Pridėkite arba redaguokite tarpinį serverį
3. Išskleidžiamajame sąraše **IP šeima** pasirinkite `Automatiškai (dvigubas dėklas)`, `Tik IPv4` arba `Tik IPv6`
4. Išsaugokite

Valdiklį atvaizduoja `ProxyRegistryManager.tsx` (prijungtas faile `proxy/ProxyPoolTab.tsx`).

### API

Laukas `family` yra tarpinio serverio registro kūrimo ir atnaujinimo naudingųjų apkrovų dalis; jį tikrina `createProxyRegistrySchema` / `updateProxyRegistrySchema` (`src/shared/validation/schemas.ts`) ir apdoroja `POST` / `PATCH /api/v1/management/proxies`:

```bash
# Sukurti tik IPv6 naudojantį tarpinį serverį
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "IPv6 egress",
    "type": "socks5",
    "host": "proxy.example.com",
    "port": 1080,
    "family": "ipv6"
  }'

# Pakeisti esamą tarpinį serverį, kad jis naudotų tik IPv4
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{ "id": "proxy-uuid-here", "family": "ipv4" }'
```

Tas pats laukas taip pat priimamas įterptajame tarpinio serverio konfigūracijos objekte, naudojamame aukštesnio lygio tarpinio serverio įrašams (`upstream_proxy_config.family`, žr. [Duomenų modelį](#data-model)).

Likusi tarpinio serverio CRUD / priskyrimo API aprašyta faile [PROXY_GUIDE.md](../ops/PROXY_GUIDE.md).

## Kaip nustatoma `auto` reikšmė

Kai `family` yra `auto`, OmniRoute **neprideda** jokios direktyvos — tarpinio serverio URL naudojamas toks, koks yra, o ryšio šeima nustatoma savaime.

Kuriant URL (`proxyConfigToUrl` / `normalizeProxyUrl` faile `open-sse/utils/proxyDispatcher.ts`), `auto` tarpinis serveris pateikia paprastą URL be žymeklio:

```ts
// open-sse/utils/proxyDispatcher.ts
const fam = parseProxyFamily(config.family);
const normalized = normalizeProxyUrl(proxyUrlStr, "context proxy", {
  allowSocks5,
});
return fam === "auto" ? normalized : `${normalized}?family=${fam}`;
```

Persiuntimo metu (`resolveDispatcherFamily`) `auto` nustatoma kaip tiesioginio IP adreso savaiminė šeima arba kaip `null` (leidžiant nuspręsti OS), kai naudojamas pagrindinio kompiuterio vardas:

```ts
// open-sse/utils/proxyDispatcher.ts
function resolveDispatcherFamily(parsed: URL): 4 | 6 | null {
  const directive = parseProxyFamily(parsed.searchParams.get("family") ?? undefined);
  const literal = detectIpLiteralFamily(parsed.hostname);
  if (directive === "auto") return literal; // pagrindinio kompiuterio vardui null → parenka OS
  // ...
}
```

Taigi:

- `auto` + tiesioginio IP adreso priegloba (`192.0.2.1` / `[2001:db8::1]`) → to adreso šeima.
- `auto` + pagrindinio kompiuterio vardas → `null` → standartinis dvigubo dėklo OS vardų nustatymas.

## Kaip užtikrinamos `ipv4` / `ipv6` direktyvos

Ne `auto` direktyva perduodama kaip vienas sintetinis užklausos žymeklis — `?family=ipv4` arba `?family=ipv6` — vieną kartą pridedamas prie normalizuoto tarpinio serverio URL. `normalizeProxyUrl` kruopščiai pašalina ir iš naujo prideda šį žymeklį lygiai vieną kartą, todėl jis niekada nesugadina prievado analizės.

Kuriant dispečerį, žymeklis nuskaitomas ir paverčiamas konkrečia ryšio šeima. Jei pagrindinis kompiuteris yra **priešingos** šeimos IP literalas, OmniRoute pateikia klaidą (prieštaravimo atveju ryšys atmetamas):

```ts
// open-sse/utils/proxyDispatcher.ts
const want = directive === "ipv6" ? 6 : 4;
if (literal !== null && literal !== want) {
  throw new Error(
    `[ProxyDispatcher] Proxy family directive ${directive} contradicts ${literal === 6 ? "IPv6" : "IPv4"} literal host`
  );
}
```

Tada konkreti šeima užfiksuojama jungtyje:

- **HTTP/HTTPS tarpiniai serveriai** (`ProxyAgent`): `proxyTls: { family, autoSelectFamily: false }` — išjungia Happy Eyeballs, todėl ryšys užmezgamas tik naudojant pasirinktą šeimą.
- **SOCKS5 tarpiniai serveriai**: pasirinktinė jungtis perduoda `socket_options: { family, autoSelectFamily: false }` SOCKS klientui (žr. [SOCKS5 suderinamumas](#socks5-compatibility)).

## SOCKS5 suderinamumas

Šeimos fiksavimas veikia su SOCKS5 tarpiniais serveriais, tačiau standartinis `fetch-socks` nesuteikia prieigos prie lizdo parinkčių, reikalingų tarpinio serverio ryšio etapo šeimai užfiksuoti. Tam OmniRoute pateikia savo jungtį:

```ts
// open-sse/utils/socksConnectorWithFamily.ts
export function buildSocksFamilySocketOptions(family: 4 | 6 | null): Record<string, unknown> {
  if (family === 6) return { family: 6, autoSelectFamily: false };
  if (family === 4) return { family: 4, autoSelectFamily: false };
  return {};
}
```

Visos SOCKS5 užklausos perduodamos per `createSocksDispatcherWithFamily`, neatsižvelgiant į `family` (įskaitant `null` / `auto`, kai naudojamas pagrindinio kompiuterio vardas): `buildSocksFamilySocketOptions(null)` grąžina `{}`, o tas pats `SocksClient.createConnection` + TLS `buildConnector` kelias naudojamas su `socket_options` fiksavimu, kad Happy Eyeballs negalėtų pasirinkti IPv4, kai išėjimo politika leidžia tik IPv6.

Pats SOCKS5 palaikymas yra įjungtas pagal numatytąsias nuostatas (galima atsisakyti naudojant `ENABLE_SOCKS5_PROXY=false`); žr. [PROXY_GUIDE.md → Aplinkos kintamieji](../ops/PROXY_GUIDE.md#environment-variables).

## Ryšio atmetimo elgsena

Visa šios direktyvos esmė — **atsisakyti** užmegzti ryšį, o ne nepastebimai grįžti prie netinkamos šeimos. Tai užtikrina dvi apsaugos priemonės:

1. **Literalo prieštaravimas** — direktyva, prieštaraujanti IP literalo pagrindiniam kompiuteriui, sukelia klaidą dispečerio kūrimo metu (`resolveDispatcherFamily`, parodyta pirmiau).

2. **Išankstinė pagrindinio kompiuterio vardo DNS patikra** — kai naudojamas tarpinio serverio pagrindinio kompiuterio vardas su užfiksuota šeima, `proxyFetch.ts`, prieš inicijuodamas išeinantį ryšį, per `assertHostnameSupportsFamily` patikrina, ar pagrindinio kompiuterio vardas iš tiesų turi reikiamos šeimos įrašą:

   ```ts
   // open-sse/utils/proxyFamilyResolve.ts
   const hasFamily = records.some((r) => r.family === family);
   if (!hasFamily) {
     throw new Error(
       `[ProxyFamily] Proxy host ${host} has no ${family === 6 ? "IPv6 (AAAA)" : "IPv4 (A)"} record; ` +
         `refusing ${family === 6 ? "IPv6" : "IPv4"}-only egress (fail-closed)`
     );
   }
   ```

   Įvykus klaidai, `proxyFetch.ts` pažymi ją reikšmėmis `code = "PROXY_FAMILY_UNAVAILABLE"` ir `statusCode = 503`. DNS skyrimo triktis taip pat apdorojama atmetant ryšį (atsisakoma inicijuoti išeinantį ryšį).

IP literalų pagrindiniams kompiuteriams išankstinė DNS patikra neatlieka jokių veiksmų — jų šeima yra savaiminė, todėl paieška nereikalinga.

## Duomenų modelis

Stulpelis `family` buvo pridėtas migracija `099_proxy_family.sql` į **dvi** lenteles:

```sql
-- src/lib/db/migrations/099_proxy_family.sql
ALTER TABLE proxy_registry ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
ALTER TABLE upstream_proxy_config ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
```

- `proxy_registry.family` — kiekvienam tarpiniam serveriui skirta registro įrašų direktyva (`src/lib/db/proxies.ts`). Nustatymo užklausos pasirenka `family` kartu su kitais tarpinio serverio stulpeliais, o trūkstama arba ne eilutės tipo reikšmė pakeičiama į `"auto"`.
- `upstream_proxy_config.family` — aukštesnio lygio tarpinio serverio įrašų direktyva (`src/lib/db/upstreamProxy.ts`) su ta pačia numatytąja reikšme `"auto"`.

Kai nustatyto tarpinio serverio objekto `family` reikšmė nėra `auto`, `proxyConfigToUrl` prideda žymeklį `?family=`, kad fiksuota reikšmė būtų išlaikyta iki pat dispečerio.
