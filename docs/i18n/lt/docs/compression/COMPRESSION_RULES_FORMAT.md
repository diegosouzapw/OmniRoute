Glaudinimo taisyklės yra JSON failai, įkeliami vykdymo metu. Jos sąmoningai sudarytos tik iš duomenų, kad naujus
kalbų paketus ir RTK komandų filtrus būtų galima peržiūrėti nekeičiant variklio kodo.

> **Kanoninė schema (patikimas šaltinis):** [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) (JSON Schema 2020-12 juodraštis).
> Toliau pateikti pavyzdžiai yra iliustraciniai — jei kyla abejonių, patikrinkite savo paketą pagal `_schema.json`.

## Caveman taisyklių paketai

Caveman taisyklių paketai yra šiame kataloge:

```txt
open-sse/services/compression/rules/<language>/<pack>.json
```

Kiekviename pakete yra keitimų, taikomų įprastam tekstui po to, kai apsaugotos sritys yra atskiriamos.

```json
{
  "language": "en",
  "category": "filler",
  "rules": [
    {
      "name": "question_to_directive",
      "pattern": "\\b(?:Can you explain why|Could you show me how)\\b\\s*",
      "replacement": "Explain why ",
      "replacementMap": {
        "can you explain why": "Explain why ",
        "could you show me how": "Show how "
      },
      "flags": "gi",
      "context": "all",
      "category": "context",
      "minIntensity": "lite",
      "description": "Convert verbose questions into direct requests."
    }
  ]
}
```

### Caveman laukai

| Laukas                   | Privalomas | Aprašymas                                                                           |
| ------------------------ | ---------- | ----------------------------------------------------------------------------------- |
| `language`               | taip       | Į BCP-47 panašus kalbos raktas, pvz., `en`, `pt-BR`, `es`                           |
| `category`               | taip       | Paketo kategorijos failo pavadinimas / kategorija, pvz., `filler` arba `dedup`      |
| `rules`                  | taip       | Reguliariųjų išraiškų keitimo taisyklių masyvas                                     |
| `rules[].name`           | taip       | Stabilus taisyklės pavadinimas                                                      |
| `rules[].pattern`        | taip       | JavaScript reguliariosios išraiškos šaltinis                                        |
| `rules[].flags`          | ne         | JavaScript reguliariosios išraiškos vėliavėlės; numatytoji reikšmė `gi`             |
| `rules[].replacement`    | ne         | Keitimo eilutė arba atsarginė reikšmė, kai `replacementMap` neranda atitikties      |
| `rules[].replacementMap` | ne         | Konkrečioms atitiktims skirti keitimai, susieti pagal normalizuotą atitikusį tekstą |
| `rules[].context`        | ne         | `all`, `user`, `assistant` arba `system`; numatytoji reikšmė `all`                  |
| `rules[].category`       | ne         | `filler`, `context`, `structural`, `dedup`, `terse` arba `ultra`                    |
| `rules[].minIntensity`   | ne         | `lite`, `full` arba `ultra`; numatytoji reikšmė `lite`                              |
| `rules[].description`    | ne         | Žmogui suprantama taisyklės santrauka                                               |

Naudokite `flags`, kai svarbu skirti didžiąsias ir mažąsias raides, pavyzdžiui, šalinant artikelį prieš mažąja raide prasidedantį tekstą,
bet nepašalinant jo iš `the OpenAI API`. Naudokite `replacementMap`, kai viena reguliarioji išraiška turi kelias alternatyvas,
kurioms reikia skirtingų rezultatų; taip JSON taisyklių paketuose lieka tik duomenys, kartu išsaugant
sudėtingesnių integruotų TypeScript keitimo funkcijų veikseną.

## RTK filtrų paketai

RTK filtrai yra šiame kataloge:

```txt
open-sse/services/compression/engines/rtk/filters/<filter>.json
```

Kiekvienas filtras aprašo, kaip atpažinti ir glaudinti komandų išvesties grupę.

```json
{
  "id": "test-vitest",
  "label": "Vitest output",
  "category": "test",
  "priority": 92,
  "match": {
    "outputTypes": ["test-vitest"],
    "commands": ["vitest", "npm test", "npm run test"],
    "patterns": ["\\bFAIL\\b", "\\bPASS\\b", "\\bTest Files\\b"]
  },
  "rules": {
    "stripAnsi": true,
    "replace": [{ "pattern": "\\s+\\[[0-9]+ms\\]", "replacement": "" }],
    "matchOutput": [
      {
        "pattern": "All tests passed",
        "message": "vitest: ok",
        "unless": "FAIL|Error:"
      }
    ],
    "includePatterns": ["FAIL", "Error:", "Test Files", "Tests"],
    "dropPatterns": ["^\\s*$", "Duration\\s+\\d+"],
    "collapsePatterns": ["^\\s+at "],
    "deduplicate": true,
    "truncateLineAt": 240,
    "maxLines": 160,
    "headLines": 24,
    "tailLines": 40,
    "onEmpty": "vitest: ok",
    "filterStderr": false
  },
  "preserve": {
    "errorPatterns": ["FAIL", "Error:", "AssertionError"],
    "summaryPatterns": ["Test Files", "Tests", "Snapshots"]
  },
  "tests": [
    {
      "name": "keeps failing tests",
      "command": "vitest",
      "input": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed",
      "expected": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed"
    }
  ]
}
```

### RTK laukai

| Laukas                     | Privalomas | Aprašymas                                                                                  |
| -------------------------- | ---------- | ------------------------------------------------------------------------------------------ |
| `id`                       | taip       | Nekintantis filtro identifikatorius                                                        |
| `label`                    | taip       | Valdymo skydelyje rodomas pavadinimas                                                      |
| `category`                 | taip       | Filtro grupė: git, test, build, shell, docker, package, infra, cloud, generic              |
| `priority`                 | ne         | Kai atitinka keli filtrai, pasirenkamas aukštesnio prioriteto filtras                      |
| `match.outputTypes`        | ne         | Detektoriaus išvesties identifikatoriai, pagal kuriuos pasirenkamas šis filtras            |
| `match.commands`           | ne         | Komandų leksemos, pagal kurias pasirenkamas šis filtras                                    |
| `match.patterns`           | ne         | Reguliariųjų išraiškų šablonai, pagal kuriuos šis filtras pasirenkamas iš išvesties teksto |
| `rules.stripAnsi`          | ne         | Pašalina ANSI valdymo sekas prieš reguliariųjų išraiškų etapus                             |
| `rules.replace`            | ne         | Surikiuoti reguliariųjų išraiškų keitimai, taikomi kiekvienai eilutei                      |
| `rules.matchOutput`        | ne         | Išvesties trumpojo jungimo taisyklės su pasirinktine `unless` sąlyga                       |
| `rules.includePatterns`    | ne         | Eilutės, kurias pageidautina išsaugoti                                                     |
| `rules.dropPatterns`       | ne         | Eilutės, pašalinamos kaip triukšmas                                                        |
| `rules.collapsePatterns`   | ne         | Pasikartojančios atitinkančios eilutės, kurias galima sutraukti                            |
| `rules.deduplicate`        | ne         | Sutraukia pasikartojančias normalizuotas eilutes                                           |
| `rules.truncateLineAt`     | ne         | „Unicode“ saugus kiekvienos eilutės simbolių limitas                                       |
| `rules.maxLines`           | ne         | Didžiausias išsaugomų eilučių skaičius prieš išsaugant pabaigą                             |
| `rules.headLines`          | ne         | Trumpinant išsaugomos pradžios eilutės                                                     |
| `rules.tailLines`          | ne         | Naujausiam kontekstui išsaugomos pabaigos eilutės                                          |
| `rules.onEmpty`            | ne         | Atsarginis pranešimas, kai filtruojant pašalinamas visas turinys                           |
| `rules.filterStderr`       | ne         | Normalizuoja įprastus stderr prefiksus prieš vėlesnius filtravimo etapus                   |
| `preserve.errorPatterns`   | ne         | Klaidų eilutės, kurios turi išlikti trumpinant                                             |
| `preserve.summaryPatterns` | ne         | Suvestinės eilutės, kurios turi išlikti trumpinant                                         |
| `tests[]`                  | ne         | Įterptieji tikrinimo pavyzdžiai, naudojami RTK patikros etape                              |

RTK deklaratyviuosius etapus taiko šia tvarka: `stripAnsi`, `filterStderr`, `replace`,
`matchOutput`, `dropPatterns`/`includePatterns`, `truncateLineAt`, `headLines`/`tailLines`,
`maxLines` ir `onEmpty`.

Pasirinktiniai filtrai gali būti įkeliami iš:

1. Projekto `.rtk/filters.json` failų tik tada, kai yra atitinkama `.rtk/trust.json` maišos reikšmė arba
   įjungta `trustProjectFilters`.
2. Visuotinio `DATA_DIR/rtk/filters.json`.
3. Integruotųjų filtrų.

Projekto arba visuotiniai pasirinktiniai failai gali turėti vieną filtro objektą arba filtrų objektų masyvą. Netinkami
pasirinktiniai filtrai praleidžiami pateikiant diagnostiką; dėl netinkamų integruotųjų filtrų patikra nepavyksta.

Projekto pasitikėjimo failas:

```json
{
  "filtersSha256": "0123456789abcdef..."
}
```

Aplinkos perrašymas `OMNIROUTE_RTK_TRUST_PROJECT_FILTERS=1` leidžia pasitikėti projekto filtrais be
maišos reikšmės ir turėtų būti naudojamas tik kontroliuojamoje vietinio kūrimo aplinkoje.

## Saugos taisyklės

- Užtikrinkite taisyklių idempotentiškumą: du kartus pritaikius tą patį filtrą, išvestis neturėtų būti sugadinta.
- Jei įmanoma, išsaugokite tikslų klaidos tekstą, failų kelius, eilučių numerius ir komandų santraukas.
- Venkite taisyklių, kurios keičia kodo blokus, JSON naudingąsias apkrovas, URL ar slaptus duomenis.
- Detektoriaus / filtro testuose pridėkite naujų komandų šeimų vienetinių testų aprėptį.
- Prie kiekvieno įtaisytojo filtro ir bendrinamų pasirinktinių filtrų pridėkite `tests[]` pavyzdžių.

## Tikrinimas

Taisyklių paketai patikrinami prieš naudojimą. Įtaisytųjų „Caveman“ paketų ir įtaisytųjų RTK filtrų atveju, aptikus tikrinimo klaidą, vykdymas nedelsiant nutraukiamas, kad sugadinti leidimo ištekliai būtų aptikti prieš platinimą. Pasirinktiniai RTK filtrai praleidžiami pateikiant diagnostinę informaciją, kai nepavyksta sintaksinės analizės arba patikimumo tikrinimo.

Tikslinis tikrinimas:

```bash
node --import tsx/esm --test tests/unit/compression/rule-loader.test.ts tests/unit/compression/language-packs.test.ts
node --import tsx/esm --test tests/unit/compression/rtk-verify.test.ts tests/unit/compression/rtk-dsl-pipeline.test.ts
```
