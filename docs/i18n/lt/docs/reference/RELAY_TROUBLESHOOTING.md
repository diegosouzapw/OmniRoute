Perdavimo mazgai (Vercel, Deno, Cloudflare) nutraukia išorinį ryšį
serverless galinėje sistemoje, kad OmniRoute galėtų siųsti srautą iš stabilaus regiono, o
teikėjo API raktas liktų serverio pusėje. Šiame dokumente aprašomi du trikčių režimai,
su kuriais operatoriai susiduria produkcinėje aplinkoje, ir OmniRoute pateikiami kiekvieno
iš jų atkūrimo būdai.

## Kaip saugomi perdavimo mazgo autentifikavimo duomenys

Kai diegiate perdavimo mazgą naudodami **Settings → Proxy Pool → Deploy Relay**,
diegimo procesas išsaugo perdavimo mazgo autentifikavimo prieigos raktą tarpinio serverio
`notes` JSON lauke:

- Jei nustatytas `STORAGE_ENCRYPTION_KEY`, prieigos raktas įrašomas kaip `relayAuthEnc`
  (ramybės būsenoje užšifruotas naudojant AES).
- Kitu atveju jis įrašomas kaip atvirasis tekstas `relayAuth`.

Užklausos metu `extractRelayAuth(notes)` grąžina tą formą, kuri yra prieinama,
todėl perdavimo mazgas veikia ir po paleidimo iš naujo.

## Trikties režimas 1 — po rakto pakeitimo nebeiššifruojamas prieigos raktas

**Požymis:** anksčiau veikę perdavimo mazgai dabar grąžina išorinės sistemos `401` arba
autentifikavimo klaidas po `STORAGE_ENCRYPTION_KEY` pakeitimo aplinkoje ar
paslapčių tvarkytuvėje. Išsaugoto `relayAuthEnc` duomenų bloko nebegalima
iššifruoti, todėl `extractRelayAuth` grąžina tuščią eilutę, o perdavimo mazgas
nesiunčia autentifikavimo duomenų.

**Atkūrimas — taisymas vietoje (be pakartotinio diegimo):**

1. Atidarykite **Settings → Proxy Pool**.
2. Perdavimo mazgų eilutėse, kuriose trūksta autentifikavimo duomenų, rodoma geltona
   žyma `auth missing` ir mygtukas **Repair**.
3. Spustelėkite **Repair**. OmniRoute iškviečia
   `POST /api/settings/proxies/[id]/repair-relay`, kuris:
   - iššifruoja `relayAuthEnc` naudodamas **dabartinį** raktą,
   - įrašo atvirojo teksto `relayAuth` atgal į `notes`,
   - grąžina `{ repaired: true, mode: "recovered" }`.

Perdavimo mazgas vėl pradeda aptarnauti užklausas ir nereikia iš naujo įvesti jokių
diegimo prisijungimo duomenų.

Tai veikia tik tuo atveju, jei dabartinis `STORAGE_ENCRYPTION_KEY` vis dar gali
iššifruoti duomenų bloką. Jei raktą pakeitėte **be** perkėlimo, duomenų bloko
atkurti neįmanoma.

## Trikties režimas 2 — neatkuriamas prieigos raktas (senasis raktas nebepasiekiamas)

**Požymis:** spustelėjote **Repair** ir gavote
`{ repaired: false, mode: "redeploy", status: 409 }`.

**Atkūrimas — pakartotinis diegimas:**

Išsaugoto prieigos rakto negalima atkurti naudojant dabartinį raktą. Iš naujo įdiekite
perdavimo mazgą naudodami tą patį modalinį langą kaip ir iš pradžių (**Deploy Relay**
meniu → Vercel / Deno / Cloudflare). Diegimo procesas įrašo naują prieigos raktą
(užšifruotą dabartiniu raktu), o eilutės žyma `auth missing` išnyksta.

Naudotojo sąsajoje pats mygtukas **Repair** atveria pakartotinio diegimo modalinį langą,
kai prieigos rakto atkurti neįmanoma, todėl jums niekada nereikia jo ieškoti rankiniu būdu.

## Trikties režimas 3 — perdavimo mazgas pasiekiamas, bet veikia netinkamai

**Požymis:** tarpinio serverio testas (mygtukas `speed`) rodo, kad perdavimo mazgas
veikia, tačiau užklausos vis tiek su pertrūkiais nepavyksta.

Patikrinkite perdavimo mazgo būsenos antraštes, kurias grąžina OmniRoute automatinio
testavimo užklausa (žr. **Settings → Proxy Pool** ir `relayTested` / `relayAlive`
skaitiklius):

- `x-relay-url` — kuris perdavimo mazgo serveris atsakė.
- `x-relay-mode` — tai užklausai naudotas `ts` | `bifrost` | `auto`.
- `x-relay-attempts` — kiek perdavimo mazgų buvo išbandyta iki sėkmingo atsakymo.
- `x-relay-fallback` — `true`, kai užklausa iš pageidaujamos galinės sistemos buvo
  perjungta į TypeScript perdavimo mazgą.

Dažnas `x-relay-fallback` kartu su maža `relayAlive` reikšme reiškia, kad sidecar
galinė sistema veikia netinkamai, todėl turėtumėte ją pataisyti arba pakeisti perdavimo
mazgo galinės sistemos strategiją į `ts` (žr. `RELAY_BACKEND_STRATEGY.md`).

## API žinynas

| Metodas | Kelias                                    | Turinys                 | Sėkmė                                                                                                                                      | Triktis                                                                                 |
| ------- | ----------------------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| `POST`  | `/api/settings/proxies/[id]/repair-relay` | `{ "id": "<proxyId>" }` | `200 { repaired: true, mode: "recovered" }`, kai išvedama iš naujo; `200 { repaired: false, mode: "noop" }`, kai atvirasis tekstas jau yra | `409 { mode: "redeploy" }` neatkuriama; `400` nėra perdavimo mazgo tipas; `404` nerasta |

Sąrašo maršrutas `GET /api/settings/proxies` prie kiekvieno elemento prideda paslapčių
neturintį `relayInfo: { isRelay, authMissing, repairMode }`, kad valdymo skydelis galėtų
rodyti taisymo parinktį niekada neatskleisdamas prieigos rakto.
