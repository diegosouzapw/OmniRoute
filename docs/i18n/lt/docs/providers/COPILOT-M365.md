`copilot-m365-web` (alternatyvusis pavadinimas `m365copilot`) siunčia OpenAI formato pokalbių užklausas per autentifikuotą Microsoft 365 Copilot BizChat naršyklės seansą adresu `m365.cloud.microsoft/chat`. Tai yra neoficiali integracija.

> **Pirmą kartą naudojate Web Cookie teikėjus?**
>
> Prieš vadovaudamiesi šiuo konkrečiam teikėjui skirtu vadovu, perskaitykite **`docs/getting-started/WEB-COOKIE-GUIDE.md`**, kuriame aprašytas bendrasis sąrankos procesas, autentifikavimo gairės, apribojimai ir trikčių šalinimas.
>
> **Svarbu:** šio teikėjo prisijungimo duomenys **nėra slapukas**. Nekopijuokite slapukų iš `m365.cloud.microsoft`. Prisijungimo duomenys yra WebSocket URL užklausos parametras ir kelio segmentas; abu jie nuskaitomi DevTools skirtuke Network.

## Būtinosios sąlygos

- Microsoft 365 paskyra, turinti prieigą prie BizChat adresu `m365.cloud.microsoft/chat`
- Chromium pagrindu veikianti naršyklė (Chrome, Edge), skirta WebSocket tikrinti naudojant DevTools
- M365 Copilot licencija (įtraukta į daugelį Microsoft 365 Business/Enterprise planų)

## Prisijungimo duomenų gavimas (WebSocket metodas)

1. Prisijunkite adresu `https://m365.cloud.microsoft/chat` ir pradėkite pokalbį.
2. Atidarykite **DevTools → Network**.
3. Filtruokite pagal **WS** (WebSocket).
4. Spustelėkite Chathub WebSocket ryšį. Ieškokite URL, prasidedančio `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Iš jo **Request URL** nukopijuokite:
   - Užklausos parametro `access_token` reikšmę (trumpalaikį JWT).
   - Chathub kelio segmentą po `/Chathub/` (pvz., `<oid>@<tenant>`).

Visas URL yra tokio formato:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute eikite į **Providers → Add Provider**, pasirinkite **Microsoft 365 Copilot (BizChat)** ir įklijuokite prisijungimo duomenis tokiu formatu:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Spustelėkite **Test Connection** ir **Save**.

## Prisijungimo duomenų gavimas (HAR importavimas)

Užuot rankiniu būdu kopijavę reikšmes iš WebSocket URL, galite eksportuoti DevTools HAR failą:

1. Atidarykite **DevTools → Network**.
2. Pradėkite arba tęskite BizChat pokalbį (tai inicijuoja WebSocket ryšį).
3. Dešiniuoju pelės mygtuku spustelėkite Network skydelyje ir pasirinkite **Save all as HAR with content**.
4. OmniRoute teikėjo ryšio dialogo lange naudokite mygtuką **Import .har file**.

OmniRoute HAR faile ieško Chathub WebSocket URL, išskiria `access_token` bei `chathubPath` ir automatiškai užpildo prisijungimo duomenų laukus. Importuojant HAR iškoduojamas JWT galiojimo laikas ir parodoma likusi prieigos rakto galiojimo trukmė.

> **Niekada neįtraukite tikro HAR eksporto, prieigos rakto ar atnaujinimo rakto į versijų valdymo sistemą.** Testuose ir dokumentacijoje visada turi būti naudojamos vietaženklio reikšmės.

## Prieigos rakto galiojimo trukmė ir atnaujinimas

`access_token` galioja trumpai (paprastai **~75 minutes**). Jam nustojus galioti, teikėjas praneša apie ryšio klaidą, todėl turite iš naujo gauti prisijungimo duomenis.

### Automatinis atnaujinimas naudojant `refreshToken`

Kad nereikėtų duomenų gauti iš naujo rankiniu būdu, Microsoft atnaujinimo raktą galite išsaugoti ryšio skiltyje **Advanced Settings → providerSpecificData**:

| Laukas         | Aprašymas                                                                           |
| -------------- | ----------------------------------------------------------------------------------- |
| `refreshToken` | Microsoft OAuth atnaujinimo raktas, skirtas `substrate.office.com/sydney` aprėpčiai |
| `tier`         | `individual` (numatytasis), `edu` arba `enterprise`                                 |

Gaukite atnaujinimo raktą iš Microsoft įrenginio kodo arba autorizavimo kodo srauto, kurio aprėptis nustatyta į `substrate.office.com/sydney`. Nustačius `refreshToken`, OmniRoute prieš kiekvieną užklausą iš anksto atnaujina `access_token`, todėl nereikia iš naujo gauti duomenų kaskart pasibaigus ~75 minučių galiojimo laikui.

Jei `refreshToken` nenustatytas, pasibaigus kiekvienam galiojimo laikotarpiui turite rankiniu būdu iš naujo gauti WebSocket prisijungimo duomenis.

### Lygio pasirinkimas

| Lygis        | Alternatyvusis pavadinimas | Sąsaja                           |
| ------------ | -------------------------- | -------------------------------- |
| `individual` | _(numatytasis)_            | Vartotojams skirtas M365 Copilot |
| `edu`        | `included`                 | Švietimui skirtas M365 Copilot   |
| `enterprise` | `work`                     | M365 Copilot darbui              |

Nustatykite lygį skiltyje **Advanced Settings → providerSpecificData → tier**. Lygis turi įtakos BizChat maršruto parinkimui ir prieigai prie modelių.

## Saugumo modelis

- **Neoficiali integracija.** Šis teikėjas naudoja atvirkštinės inžinerijos būdu išanalizuotą BizChat WebSocket
  protokolą. Microsoft pakeitus galinį tašką, integracija gali nustoti veikti be įspėjimo.
- Žyma `subscriptionRisk: true` nurodo, kad integracija remiasi
  nedokumentuotu galiniu tašku. Paskyros apribojimai galimi, tačiau nėra patvirtinti.
- Prieigos atpažinimo ženklas yra trumpalaikis JWT. Elkitės su juo kaip su slaptažodžiu: neįtraukite jo į versijų valdymo sistemą,
  nerašykite į žurnalus ir nesidalykite juo.
- Atnaujinimo atpažinimo ženklas suteikia ilgalaikę prieigą prie BizChat sąsajos. Saugokite jį taip pat
  rūpestingai kaip API raktą.

## Trikčių šalinimas

### Autentifikavimas iš karto nepavyksta

- Patikrinkite, ar duomenis nukopijavote iš **WebSocket URL**, o ne iš XHR/Fetch užklausos. Prisijungimo
  duomenys yra Chathub WebSocket ryšio `access_token` užklausos parametre,
  o ne `Authorization: Bearer` antraštėje.
- Įsitikinkite, kad `chathubPath` apima visą URL
  kelio segmentą `<oid>@<tenant>`.

### Atpažinimo ženklo galiojimas baigiasi po ~75 minučių

Tai normalu. Be `refreshToken` prieigos atpažinimo ženklas galioja trumpai. Galite:

- Iš naujo gauti prisijungimo duomenis iš DevTools arba
- Išplėstiniuose nustatymuose sukonfigūruoti `refreshToken`, kad jie būtų atnaujinami automatiškai.

### Ryšio testas sėkmingas, tačiau pokalbis grąžina 401

Atpažinimo ženklo galiojimas galėjo baigtis tarp patikrinimo ir pirmosios užklausos. Iš naujo gaukite
galiojančius prisijungimo duomenis.

### Copilot nerodomas teikėjų sąraše

Įsitikinkite, kad **Dashboard → Providers** skiltyje įjungtas `copilot-m365-web`. Kai kuriuose planuose
teikėjas pagal numatytuosius nustatymus gali būti paslėptas.
