Šiame dokumente užfiksuotas įgyvendinimo sprendimas, susijęs su
[problema #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854). Viešieji produktai
pateikiami kaip keturios teikėjų šeimos. Regionas yra ryšio duomenų dalis, o ne atskiras produktas.

## Sprendimas

| Teikėjų šeima                                    | OmniRoute ID            | Visuotinis regionas | Kinijos regionas |
| ------------------------------------------------ | ----------------------- | ------------------- | ---------------- |
| Alibaba Cloud Model Studio (mokama už naudojimą) | `alibaba`               | Singapūras          | Pekinas          |
| Alibaba Cloud Token Plan                         | `bailian-coding-plan`   | Singapūras          | Pekinas          |
| Qwen Cloud (mokama už naudojimą)                 | `qwen-cloud`            | Visuotinis          | Pekinas          |
| Qwen Cloud Token Plan                            | `qwen-cloud-token-plan` | Singapūras          | Pekinas          |

Esamas `alibaba-cn` ID išlieka vykdymo aplinkos suderinamumo pseudonimu, skirtu išsaugotiems ryšiams, modelių
maršrutams, deriniams ir istoriniams naudojimo duomenims. Jo kortelė valdymo skydelyje sujungiama su `alibaba`; duomenų
bazės perrašyti nereikia.

Qwen Cloud mokėjimo už naudojimą produktas ir Alibaba Cloud Model Studio šiuo metu naudoja tuos pačius su DashScope suderinamus
vykdymo aplinkos pagrindinius kompiuterius, tačiau jie išlieka atskirais teikėjais, nes naudotojai gauna raktus ir valdo
paskyras per skirtingas produktų sąsajas. Alibaba ir Qwen Cloud Token Plan produktai naudoja
skirtingas galinių taškų šeimas, todėl visi keturi produktai išlieka atskirais teikėjų ID.

## Galinių taškų matrica

| Teikėjų šeima           | `global-sg`                                                              | `china-beijing`                                                      | Duomenų perdavimo formatas |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | -------------------------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI                     |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic                  |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI                     |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI                     |

API raktas ir galinis taškas turi priklausyti tam pačiam produktui ir regionui. Pasirinkus regioną, pakeičiamas
iš anksto nustatytas galinis taškas, naudojamas tikrinimo ir įprastoms užklausoms.

## Ryšio sutartis

Naujuose ryšiuose stabilus regiono raktas saugomas `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

Leidžiamos reikšmės yra `global-sg` ir `china-beijing`. Galinis taškas centralizuotai nustatomas pagal
teikėjo ID ir regioną. Iš anksto nenustatytas `providerSpecificData.baseUrl` išlieka aiškia operatoriaus
perrašymo reikšme ir turi pirmenybę, o seni išsaugoti iš anksto nustatyti URL normalizuojami pagal regioninę
matricą.

Taip ryšio schema išlieka išplečiama: kitą regioną galima pridėti prie sprendiklio
nekuriant kitos teikėjo kortelės ir nekeičiant išsaugotų teikėjo ID.

## Suderinamumas ir diegimas

1. Pridėkite regioninių galinių taškų parinkiklį ir išlaikykite dabartines numatytąsias visuotines reikšmes.
2. Naudokite tiesioginį regioninį DashScope `/models` aptikimą `alibaba`, jo suderinamumo
   ID `alibaba-cn` ir `qwen-cloud`. Jų atsakymams pirmiausia pritaikomas teksto generavimo filtras, nes bendrasis
   galinis taškas taip pat grąžina vaizdų, vaizdo įrašų, garso, įterpinių ir kitus ne pokalbiams skirtus modelius. Tada `qwen-cloud`
   pritaiko prižiūrimą leidžiamų modelių sąrašą, deklaruotą jo teikėjo registre. Alibaba Model Studio
   ir Qwen Cloud išlaiko atskirus kuruojamus katalogus, nors šiuo metu naudoja tuos pačius vykdymo aplinkos pagrindinius kompiuterius.
3. Užregistruokite `qwen-cloud-token-plan` su dabartiniu Token Plan teksto modelių leidžiamų modelių sąrašu.
4. Į ryšio pridėjimo / redagavimo dialogo langus įtraukite tipizuotą regiono parinkiklį.
5. Paslėpkite pasikartojančią `alibaba-cn` kortelę ir įtraukite esamus jos ryšius į `alibaba`
   teikėjo puslapį.
6. Palikite galimybę keisti pasirinktinius galinius taškus išplėstiniams ir konkrečioms darbo sritims skirtiems diegimams.

Token Plan medijos modeliai lieka už pokalbių katalogo ribų, nes jie naudoja specializuotus galinius taškus.
`wan2.7-image` ir `wan2.7-image-pro` yra užregistruoti `open-sse/config/imageRegistry.ts`;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` ir `happyhorse-1.1-r2v` yra užregistruoti
`open-sse/config/videoRegistry.ts`. Abu registrai pakartotinai naudoja `qwen-cloud-token-plan` ryšio
tapatybę ir konkrečiam regionui skirtus jos kredencialus.

Įprastas Qwen Cloud turi atskirus mokėjimo pagal naudojimą vaizdų ir vaizdo įrašų katalogus, susietus su `qwen-cloud`
tapatybe. Jo vaizdų modeliai yra `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` ir `z-image-turbo`. Jo vaizdo įrašų
modeliai yra `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` ir
`wan2.7-videoedit`. Šie modeliai pakartotinai naudoja tik įprastą `qwen-cloud` ryšį ir regioninį
DashScope medijos galinį tašką. Token Plan ir mokėjimo pagal naudojimą registrai nepaveldi ir nesujungia
vienas kito modelių sąrašų.

`bailian-coding-plan` tapatybė taip pat turi savo medijos leidžiamų modelių sąrašus:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` ir `qwen-image-2.0-pro`, skirtus vaizdams
generuoti, taip pat
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` ir `happyhorse-1.1-r2v`, skirtus vaizdo įrašams
generuoti. Ji naudoja tik Bailian Coding Plan ryšį ir regioninį Coding Plan galinį tašką.
Jos vaizdų ir vaizdo įrašų registrai nepaveldi iš nė vieno Qwen Cloud teikėjo ir nėra su jais sujungiami.

Įprasta `alibaba` tapatybė turi atskirus vaizdų ir vaizdo įrašų leidžiamų modelių sąrašus. Jos vaizdų modeliai yra
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` ir `wan2.6-t2i`. Jos papildyti vaizdo įrašų modeliai yra `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` ir `wan2.7-videoedit`. Šie modeliai naudoja tik Alibaba Model Studio
ryšį ir jo pasirinktą regioninį medijos galinį tašką; jie nepridedami prie jokio Coding Plan ar Qwen
Cloud registro.

Qwen Cloud Token Plan pokalbių katalogas naudoja Individual plano tikslių eilučių teksto modelių leidžiamų modelių sąrašą:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` ir
`deepseek-v4-pro`. Wan ir HappyHorse įrašai priklauso atskiroms vaizdų / vaizdo įrašų generavimo API.

Alibaba Token Plan per savo su Anthropic suderinamą galinį tašką pateikia tuos pačius šešis dabartinius teksto generavimo modelių ID.
Jo Singapūro parinktis saugo esamą `global-sg` regiono raktą;
nuo teikėjų šeimų, kurios šį regioną vadina visuotiniu, skiriasi tik naudotojui rodomas pavadinimas.

Įprastas Qwen Cloud pokalbių katalogas sąmoningai yra siauresnis už visą tiesioginį tekstinį atsakymą. Jo
prižiūrimas leidžiamų modelių sąrašas yra `open-sse/config/providers/registry/qwen-cloud/index.ts`; tiesioginis
aptikimas grąžina tik tuos ID, kurie yra ir pirminiame atsakyme, ir šiame registro sąraše.

Alibaba Model Studio taiko tą pačią tiesioginės sankirtos taisyklę su atskirai prižiūrimu
leidžiamų modelių sąrašu, esančiu `open-sse/config/providers/registry/alibaba/index.ts`. `alibaba-cn` suderinamumo
teikėjas pakartotinai naudoja tą katalogą, o aptikimo užklausas nukreipia į Pekino galinį tašką.
