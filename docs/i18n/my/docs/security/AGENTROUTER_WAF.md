`agentrouter` အထက်စီး gateway သည် `messages[].content` ပေါ်တွင် keyword အခြေပြု အကြောင်းအရာ filter တစ်ခုကို လုပ်ဆောင်သည်။ Filter သည် တစ်စိတ်တစ်ပိုင်းအားဖြင့် deterministic ဖြစ်ပြီး (အချို့သော စကားစုများကို အမြဲတမ်း ပိတ်ဆို့သည်) တစ်စိတ်တစ်ပိုင်းအားဖြင့် probabilistic ဖြစ်သည် (burst-sensitive — တောင်းဆိုမှုများကို ဆက်တိုက်လျင်မြန်စွာ ပြုလုပ်ပြီးနောက် ပိုမိုတင်းကျပ်လာကာ cooldown ကာလတစ်ခုအပြီးတွင် ပြန်လည်ပုံမှန်ဖြစ်လာသည်)။

WAF က တောင်းဆိုမှုတစ်ခုကို ပိတ်ဆို့သောအခါ အောက်ပါတို့ကို ပြန်ပေးသည်-

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## Filter ၏ စစ်ဆေးမှုနယ်ပယ်

WAF သည် `messages[].content` ကိုသာ စစ်ဆေးသည်။ အောက်ပါတို့ကို **မ**စစ်ဆေးပါ-

- `system` prompt
- ဖွဲ့စည်းပုံပါသော content block များ (`tool_result`, `tool_use`, `thinking`, `image`)
- Tool `description` နှင့် `input_schema` field များ
- Request metadata၊ header များ သို့မဟုတ် model id

## အမြဲတမ်း ပိတ်ဆို့ခံရသော pattern များ (စာလုံးအကြီးအသေး မခွဲခြားပါ)

| Pattern                         | မှတ်ချက်များ                                                               |
| ------------------------------- | -------------------------------------------------------------------------- |
| မည်သည့် `Lorem ipsum` မူကွဲမဆို | Latin lorem ဝေါဟာရအစုံကို ပိတ်ဆို့ထားသည်                                   |
| `language model` (တစ်ခုတည်း)    | "the language model" နှင့် "large language model" တို့သည် ဖြတ်သန်းနိုင်သည် |
| `virtual assistant`             | "AI assistant" သည် ဖြတ်သန်းနိုင်သည်                                        |
| `I'm here to help`              | "here to help" တစ်ခုတည်းဖြစ်လျှင်လည်း ပိတ်ဆို့ခံရသည်                       |
| `Claude, made by Anthropic`     | စကားစုအပြည့်အစုံကိုသာ ပိတ်ဆို့သည်                                          |

## အမြဲတမ်းနီးပါး ပိတ်ဆို့ခံရသော pattern များ

| Pattern                                                              | မှတ်ချက်များ                                                              |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `placeholder`                                                        | သီးခြားတစ်ခုတည်း ပါရှိသည့်အခါ (parameter အမည် စသည်တို့အဖြစ် မဟုတ်သည့်အခါ) |
| `dummy data`                                                         | fixture များအတွက် အသုံးများသော seed စကားစု                                |
| `foo bar baz`                                                        | စံသတ်မှတ်ထားသော placeholder စကားစု                                        |
| ထပ်ခါတလဲလဲ ပါဝင်သော token အတိုများ (`AAA BBB CCC`, `test test test`) | Keyword stuffing ကို ရှာဖွေသည့် detector                                  |

## Load များနေချိန် အပြုအမူ

အချိန်တိုအတွင်း တောင်းဆိုမှု ~5 ခုကို လျင်မြန်စွာ ပြုလုပ်ပြီးနောက် WAF သည် ပုံမှန်အားဖြင့် ဖြတ်သန်းနိုင်မည့် အကြောင်းအရာများကို စတင်ပိတ်ဆို့သည်။ လုပ်ဆောင်မှုမရှိဘဲ ~5–10 စက္ကန့်ကြာပြီးနောက် bucket သည် ပြန်လည်ဖြေလျှော့ပေးသည်။ ၎င်းသည် Claude Code သို့မဟုတ် Codex CLI က tool-use / message-send call အများအပြားကို အချိန်တိုအတွင်း ဆက်တိုက်ပြုလုပ်သည့်အခါ ပြတ်တောင်းပြတ်တောင်း ဖြစ်ပေါ်သော `400 content-blocked` error များကို ဖြစ်စေသည့် IP နှင့် key နှစ်ခုလုံးအပေါ် ချိတ်ဆက်ထားသော rate limiter အတူတူပင် ဖြစ်သည်။

## OmniRoute တွင် အသုံးပြုပြီးသော လျော့ပါးစေသည့် နည်းလမ်းများ

1. **`open-sse/services/wafRateLimit.ts`** — `agentrouter:*` URL တစ်ခုခုသို့ ပေးပို့သော outbound request များကြား အနည်းဆုံး 500 ms ခြားစေရန် သတ်မှတ်ပေးသည့် burst guard ဖြစ်သည်။ ဤကြားကာလသည် လူတို့ latency ကို သတိပြုမိနိုင်သည့် အတိုင်းအတာထက် များစွာနည်းပြီး ပုံမှန် traffic တွင် WAF စတင်အသက်ဝင်ခြင်းကို တားဆီးပေးသည်။

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — အထက်စီးစနစ်တစ်ခုက `400 content-blocked` ကို ပြန်ပေးသောအခါ executor သည် တူညီသော URL ကို exponential backoff (1.5 s၊ 3.0 s၊ အများဆုံး 2 ကြိမ်) ဖြင့် ထပ်မံကြိုးစားသည်။ Backoff အပြီးတွင် WAF သည် ပုံမှန်အားဖြင့် ပြန်လည်ဖြေလျှော့သွားပြီး ထပ်မံကြိုးစားမှု အောင်မြင်သည်။

3. **`tests/unit/compression/harness.test.ts`** — Claude Code က `Read` tool မှတစ်ဆင့် ဤဖိုင်ကို ဖတ်သောအခါ ဖိုင်အကြောင်းအရာများသည် `tool_result` block မှတစ်ဆင့် ပြန်လည်မစီးဆင်းဘဲ WAF ကို မဖြစ်ပေါ်စေရန် test fixture `longInput` ကို `"lorem ipsum dolor sit amet ".repeat(40)` မှ `"example content for testing purposes ".repeat(40)` သို့ ပြောင်းလဲထားသည်။

## Prompt များနှင့် tool output အတွက် လမ်းညွှန်ချက်

Claude Code သို့မဟုတ် Codex CLI session တစ်ခုတွင် `400 content-blocked` ကို ထပ်ခါတလဲလဲ ကြုံနေရပါက နောက်ဆုံး user message နှင့် နောက်ဆုံး tool result တို့တွင် အထက်ပါ pattern တစ်ခုခု ပါဝင်ခြင်း ရှိမရှိ စစ်ဆေးပြီး စကားလုံးအသုံးအနှုန်းကို ပြောင်းလဲရေးသားပါ။ အသုံးများသော ဖြေရှင်းနည်းများ-

- `Lorem ipsum …` ကို `example text …` သို့မဟုတ် test သို့မဟုတ် fixture က ပုံစံတူဖော်ပြရန် ကြိုးစားနေသည့် အမှန်တကယ်အကြောင်းအရာဖြင့် အစားထိုးပါ။
- သီးခြားတစ်ခုတည်းအဖြစ် ပါဝင်သော `placeholder` ကို `example value`၊ `sample value` သို့မဟုတ် အမှန်တကယ်တန်ဖိုးဖြင့် အစားထိုးပါ။
- `language model` ကို `large language model` သို့မဟုတ် `the model` ဖြင့် အစားထိုးပါ။
- `dummy data` ကို `sample data` သို့မဟုတ် လက်တွေ့ဆန်သော seed တန်ဖိုးများဖြင့် အစားထိုးပါ။
- `I'm here to help` / `here to help` ကို ပိုမိုတိကျသော အဖွင့်စကားဖြင့် အစားထိုးပါ (ဥပမာ "သင်ဖော်ပြခဲ့သော ဖိုင်ကို ကျွန်ုပ် စစ်ဆေးပေးပါမည်")။

## False positive များကို အထက်စီးစနစ်သို့ အစီရင်ခံခြင်း

လက်ရှိ filter သည် လွန်ကဲစွာ တင်းကျပ်နေသည် — operator က prompt တစ်ခုကို ထည့်သွင်းရန် ရည်ရွယ်ထားခြင်းမရှိကြောင်း ရှင်းလင်းနေသော်လည်း `tool_result` block များအတွင်းရှိ "Lorem ipsum" ကို ပိတ်ဆို့သည်။ ဤပြဿနာကို မူရင်းရင်းမြစ်တွင် ပြုပြင်စေလိုသော operator များသည် false positive များကို အစီရင်ခံရန် `agentrouter.org` ကို ဆက်သွယ်သင့်သည်။ အထက်ပါ blocklist သည် 2026-08-03 ရက်နေ့အထိ အထက်စီးစနစ်ကို စမ်းသပ်စစ်ဆေးခြင်းမှ ရရှိထားသော လက်တွေ့ရလဒ်ဖြစ်သည်။
