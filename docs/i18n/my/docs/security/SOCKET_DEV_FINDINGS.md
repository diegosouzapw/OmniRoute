> **အကျုံးဝင်မှု မှတ်ချက်:** `socket.yml` သည် Socket.dev ၏ registry ဘက်ခြမ်းရှိ npm artifact အား publish ပြုလုပ်ပြီးနောက် scan ဖတ်ခြင်းကို configure လုပ်ပေးသည် (`tests/`, `docs/` နှင့် build report များကဲ့သို့ ဖြန့်ချိထားခြင်းမရှိသော content များအတွက် ignore-paths)။ ၎င်းသည် CI/PR merge gate ကို ချိတ်ဆက်ပေးခြင်းမရှိပါ — `.github/workflows` အတွင်းရှိ မည်သည့် workflow ကမျှ၊ `package.json` script ကမျှ၊ ထို့အပြင် `Makefile` target ကမျှ Socket.dev ကို invoke မလုပ်ပါ။

ဤစာတမ်းသည် `omniroute@3.8.5` နှင့် ပတ်သက်၍ ထွက်ပေါ်လာသော
`AI-detected potential malware` တွေ့ရှိချက် ခြောက်ခုနှင့် `omniroute@3.8.6` တွင်
အသုံးချထားသော လျော့ပါးသက်သာစေရေး အစီအမံများအတွက် ထိန်းသိမ်းသူရေးသားထားသည့် အတည်ပြုချက်ဖြစ်သည်။ ဤစာတမ်း တည်ရှိရသည့် အကြောင်းရင်းများမှာ-

1. လုံခြုံရေး pipeline ကို လည်ပတ်သူများအနေဖြင့် တွေ့ရှိချက်များကို အမှန်တကယ် source နှင့်
   တိုက်ဆိုင်စစ်ဆေးရန် လိုအပ်သည့်အခါ ကိုးကားနိုင်သော တစ်ခုတည်းသော reference ရှိစေရန်။
2. အလံတင်ဖော်ပြထားသည့် path တစ်ခုချင်းစီသည် ရည်ရွယ်ချက်ရှိရှိ ထည့်သွင်းထားခြင်း၊ opt-in ဖြစ်ခြင်းနှင့် မှတ်တမ်းတင်ထားခြင်းဖြစ်ကြောင်း
   ထိန်းသိမ်းသူ လက်မှတ်ရေးထိုးထားသော အဆိုကို နောင်လာမည့် AI scanner များက ဖော်ထုတ်ရယူနိုင်စေရန်။
3. Call site တစ်ခုချင်းစီကို _အဘယ်ကြောင့်_ ယခုကဲ့သို့ ဖွဲ့စည်းထားရသည်ကို စာဖြင့်ရေးသားထားသော မှတ်တမ်းတစ်ခု ရှိစေရန် —
   သို့မှသာ နောင် refactor ပြုလုပ်ရာတွင် ရည်ရွယ်ချက်ရှိရှိ ဖယ်ရှားထားသော fingerprint တစ်ခုကို
   မတော်တဆ ပြန်လည်ထည့်သွင်းမိခြင်း မဖြစ်စေရန်။

v3.8.6 ၏ လျော့ပါးသက်သာစေရေး အစီအမံများကို ဖြန့်ချိပြီးနောက် အောက်ပါ call site များအနက် တစ်ခုခုကို
သင်လည်ပတ်သော scanner က ထပ်မံအလံတင်ဖော်ပြပါက scan trace နှင့်အတူ issue တစ်ခု ဖွင့်ပေးပါ၊ ထို့နောက်
ကျွန်ုပ်တို့သည် ဤနေရာရှိ အတည်ပြုချက်ကို ထပ်မံဖြည့်စွက်ပါမည်။

## §1 — MITM root-CA ထည့်သွင်းခြင်း (`77484.js`)

**Source file များ**:

- `src/mitm/cert/install.ts` — အများသုံး `installCert()` / `uninstallCert()` နှင့်
  platform တစ်ခုချင်းစီအလိုက် `installCertWindows/Mac/Linux`။
- `src/mitm/systemCommands.ts` — ထည့်သွင်းရေး path များက အသုံးပြုသော မျှဝေထားသည့် `execFile` / `spawn` / PowerShell
  helper များ။

**စတင်လုပ်ဆောင်စေသည့်အရာ**: အသုံးပြုသူသည် local dashboard ရှိ
`/dashboard/cli-tools/mitm` တွင် "Enable MITM proxy" ကို နှိပ်သည်။ ဤ route သည် loopback-only ဖြစ်သည် —
`CLAUDE.md` ရှိ တင်းကျပ်သော စည်းမျဉ်း #17 နှင့်
`src/server/authz/routeGuard.ts::isLocalOnlyPath()` ကို ကြည့်ပါ။ Tunnel မှတစ်ဆင့် ပေါက်ကြားသွားသော
JWT သည် ဤ code path ကို **စတင်လုပ်ဆောင်စေနိုင်ခြင်းမရှိပါ**။

**လုပ်ဆောင်သည့် အထူးအခွင့်အရေးလိုအပ်သော operation များ (platform တစ်ခုချင်းစီအလိုက်)**:

| OS                     | Command များ                                                                                                      |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | UAC မှတစ်ဆင့် `certutil -addstore Root <cert>`                                                                    |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | `certutil -d sql:<profile>` မှတစ်ဆင့် profile တစ်ခုချင်းစီ၏ NSS DB ကို update လုပ်ခြင်း                           |

ဤ command များသည် `mitmproxy`, Charles Proxy, Fiddler နှင့်
Caddy တို့က အသုံးပြုသည့် command များနှင့် အတူတူဖြစ်သည်။ ၎င်းတို့ OmniRoute တွင် ရှိနေသည့်အချက်ကို
`docs/security/STEALTH_GUIDE.md` တွင် မှတ်တမ်းတင်ထားသည်။

**v3.8.6 လျော့ပါးရေးအစီအမံ**:

- `runElevatedPowerShell()` သည် `-EncodedCommand <base64utf16le>` ကို မသုံးတော့ပါ။
  အထူးအခွင့်အရေးဖြင့် လုပ်ဆောင်မည့် payload ကို ခေါ်ယူမှုတစ်ကြိမ်စီအတွက် ယာယီ `.ps1` file တစ်ခုအဖြစ် (mode 0o600 ဖြင့်
  သီးသန့် `mkdtempSync` directory အတွင်း) ရေးသားပြီး `-File` မှတစ်ဆင့် ရည်ညွှန်းသည်။ ထို
  file ကို `finally` အတွင်း unlink လုပ်သည်။ ဤပြောင်းလဲမှုက Socket.dev ၏ AI
  classifier မှ flag လုပ်ထားသော စံပြနမူနာအဖြစ် လူသိများသည့်
  PowerShell မှတစ်ဆင့် base64 elevation fingerprint ကို ဖယ်ရှားပေးသည်။
- `installCertWindows` တွင် ဤနေရာကို ညွှန်ပြထားသည့် inline `SECURITY-AUDITOR-NOTE:` block
  ပါဝင်သည်။

**ဆက်လက်ထားရှိရသည့်အကြောင်းရင်း**: MITM proxy သည်
`docs/security/STEALTH_GUIDE.md` နှင့် `docs/frameworks/MITM-PROXY.md` တို့တွင် အသုံးပြုထားသော မှတ်တမ်းတင်ပြီးသား feature တစ်ခုဖြစ်သည်။ ၎င်းကို ဖယ်ရှားပါက
agent-bridge feature အစုကို ပျက်စီးစေမည်ဖြစ်သည်။

## §2 — Zed အထောက်အထား တင်သွင်းခြင်း (`app/api/providers/zed/import/route.js`)

**မူရင်းဖိုင်များ**:

- `src/app/api/providers/zed/discover/route.ts` _(v3.8.6 တွင် အသစ်ထည့်သွင်းထားသည်)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(v3.8.6 တွင် အသစ်ထည့်သွင်းထားသည်)_

**စတင်လုပ်ဆောင်သည့်အကြောင်းရင်း**: အသုံးပြုသူသည် local dashboard ၏ Providers
စာမျက်နှာတွင် "Import from Zed" ကို နှိပ်သည်။ Endpoint ကို `requireManagementAuth` ဖြင့်
ကန့်သတ်ထားသည်။ Zed editor ကိုယ်တိုင်က ၎င်း၏ provider API key များကို မှတ်တမ်းတင်ထားသော service
အမည်များဖြင့် OS keychain ထဲသို့ ရေးသားသည် — https://zed.dev/docs/ai/llm-providers ကို ကြည့်ပါ။

**v3.8.5 ၏ လုပ်ဆောင်ပုံ (Socket.dev က သတိပေးခဲ့သည့်အရာ)**:

`POST /import` သည် အထောက်အထားများကို ရှာဖွေပြီး round-trip တစ်ကြိမ်တည်းဖြင့် local
SQLite store ထဲသို့ အလိုအလျောက် သိမ်းဆည်းခဲ့သည်။ Account တစ်ခုချင်းစီအတွက် အတည်ပြုချက်မရှိ၊
fingerprint မရှိဘဲ "token N ခု တွေ့ရှိပြီး အားလုံးကို တင်သွင်းပြီးပြီ" ဟုသာ ဖော်ပြခဲ့သည်။

**v3.8.6 လျော့ပါးကာကွယ်မှု — အဆင့် ၂ ဆင့် အတည်ပြုခြင်း**:

1. **`POST /api/providers/zed/discover`** သည်
   `{ candidates: [{ provider, service, account, fingerprint }] }` ကို ပြန်ပေးသည်။ မူရင်း
   token ကို **မည်သည့်အခါမျှ** ပို့ဆောင်ခြင်းမပြုပါ။ Fingerprint သည်
   `sha256(service|account|token).slice(0,16)` ဖြစ်သည်။
2. Dashboard က candidate စာရင်းကို ပြသပြီး operator က တင်သွင်းလိုသည့်အရာများကို ရွေးချယ်ကာ
   `{ confirmedAccounts: [{ service, account, fingerprint }] }` ကို
   **`POST /api/providers/zed/import`** သို့ ပို့သည်။
3. Import endpoint သည် **server ပေါ်ရှိ keychain ကို ပြန်လည်ဖတ်ရှု** ပြီး
   `(service, account, fingerprint)` အလိုက် စစ်ထုတ်သည်။ ပြုပြင်ထားသော သို့မဟုတ် ပြန်လည်အသုံးပြုထားသော discover
   response တစ်ခုက import endpoint အား သက်ဆိုင်မှုမရှိသော token တစ်ခုကို သိမ်းဆည်းရန် လှည့်စား၍မရပါ —
   discover လုပ်ပြီးနောက် live token ပြောင်းလဲသွားပါက fingerprint မကိုက်ညီတော့သဖြင့်
   ထိုအထောက်အထားကို ကျော်သွားမည်ဖြစ်သည်။

`OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` env flag သည် ၎င်းတို့၏ automation ကို
မွမ်းမံရသေးသော operator များအတွက် v3.8.5 ၏ လုပ်ဆောင်ပုံကို ဆက်လက်ထိန်းသိမ်းပေးသည်။ ၎င်းကို
v3.9 တွင် ဖယ်ရှားမည်ဖြစ်သည်။

**ဆက်လက်ထားရှိရသည့်အကြောင်းရင်း**: Zed ကို အသုံးပြုထားပြီးသားဖြစ်ကာ ၎င်းတို့၏ provider key များကို
ပြန်လည်ကူးထည့်စရာမလိုဘဲ OmniRoute ထဲသို့ ပုံတူကူးလိုသည့် အသုံးပြုသူများအတွက် Zed import သည်
အဆင်ပြေဆုံး စတင်အသုံးပြုမှုနည်းလမ်းဖြစ်သည်။

## §3 — `execFile` / `spawn` / အဆင့်မြှင့် PowerShell (`21843.js`)

**မူရင်းဖိုင်များ**: `src/mitm/systemCommands.ts`။

**သတိပေးခံရသည့်အကြောင်းရင်း**: chunk သည် `execFileWithPassword`,
`runElevatedPowerShell` နှင့် မျှဝေသုံးစွဲသော `quotePowerShell` helper ကို ပြန်လည် export လုပ်ထားသည်။ Socket.dev ၏
AI classifier က ၎င်းတို့ကို ယေဘုယျ "host execution + privilege elevation
toolkit" တစ်ခုအဖြစ် သတ်မှတ်သည်။ OmniRoute အတွင်း၌ ၎င်းတို့ကို MITM cert တပ်ဆင်မှုလမ်းကြောင်း

**v3.8.6 လျော့ပါးကာကွယ်မှု**:

- `runElevatedPowerShell` ကို ပြန်လည်ဖွဲ့စည်းထားသည် (§1 ကို ကြည့်ပါ)။
- `runElevatedPowerShell` နှင့် `execFileWithPassword` နှစ်ခုစလုံးရှိ inline
  `SECURITY-AUDITOR-NOTE:` block တွင် allowlist ထည့်ထားသော caller များနှင့် သတ်မှတ်ထားသော
  executable စာရင်းကို မှတ်တမ်းတင်ထားသည်။
- `execFileWithPassword` ၏ `spawn()` call တွင် helper လက်ခံခွင့်ရှိသည့် executable များ၏
  allowlist ပါဝင်သော `nosemgrep` marker တစ်ခုရှိသည် — အသုံးပြုသူ input မှ
  `finalCommand`/`finalArgs` သို့ ရောက်ရှိနိုင်သည့် **လမ်းကြောင်းမရှိပါ**။

- `src/server/authz/routeGuard.ts` အရ `/api/services/*` route အားလုံးသည် LOCAL_ONLY ဖြစ်သည်
  (တင်းကျပ်သော စည်းမျဉ်း #17)။ Loopback ကန့်သတ်မှုကို auth စစ်ဆေးမှုမပြုမီ
  လုပ်ဆောင်သည် — ပေါက်ကြားသွားသော JWT ဖြင့် ၎င်းတို့ကို ဆက်သွယ်၍မရပါ။

  (`src/lib/db/migrations/071_services.sql:19` ကို ကြည့်ပါ)။ Service သည် ပထမဆုံးဖွင့်ချိန်တွင်
  **စတင်မည်မဟုတ်ပါ**။
- `spawn()` ကို `src/lib/services/installers/ninerouter.ts` ရှိ
  `resolveSpawnArgs(apiKey, PORT)` က ပြန်ပေးသော binary path ဖြင့် ခေါ်ယူသည်။
  ၎င်းသည် ပံ့ပိုးထားသော binary များ၏ ပုံသေ allowlist တစ်ခုဖြစ်သည်။
- Stdout/stderr ကို memory ထဲတွင် buffer လုပ်ထားသည် (5 MB ကန့်သတ်ချက်၊ `_lib.ts` ကို ကြည့်ပါ) —
  အသုံးပြုသူက dashboard မှ logging ကို ဖွင့်မထားလျှင် disk ပေါ်သို့ ရေးသားမည်မဟုတ်ပါ။

**v3.8.6 လျော့ပါးကာကွယ်မှု**: လုပ်ဆောင်ချက်ဆိုင်ရာ ပြောင်းလဲမှုမရှိပါ။ အနည်းဆုံး build profile

**ဆက်လက်ထားရှိရသည့်အကြောင်းရင်း**: 9router သည် ရွေးချယ်အသုံးပြုနိုင်ပြီး local တွင် တပ်ဆင်နိုင်သော

## §5 — OmniRoute Cloud Sync အထောက်အထားများ ပြန်လည်ရေးသားခြင်း (`api/keys/[id]/route.js`)

**ရင်းမြစ်ဖိုင်များ**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`။
- `src/app/api/keys/[id]/route.ts` — `syncKeysToCloudIfEnabled()` ကို ခေါ်ယူသည်။

**အစပျိုးအခြေအနေ**: `isCloudEnabled()` က `true` ကို ပြန်ပေးသည် (dashboard မှ သတ်မှတ်ထားသည်) **နှင့်**
`CLOUD_URL` ကို ပြင်ဆင်သတ်မှတ်ထားသည်။ နှစ်ခုစလုံး ပိတ်ထားပါက Cloud endpoint သို့
ပြင်ပ network ခေါ်ဆိုမှု မပြုလုပ်ပါ။

**v3.8.5 ၏ လုပ်ဆောင်ပုံ (Socket.dev က မှန်ကန်စွာ ဖော်ထုတ်ခဲ့သော bug)**:

`cloudUpdatedAt > localUpdatedAt` ဖြစ်သည့်အခါ `updateLocalTokens()` သည် Cloud တုံ့ပြန်ချက်မှ
`accessToken`, `refreshToken` နှင့် `providerSpecificData` တို့ဖြင့်
ရှိပြီးသားတန်ဖိုးများကို ထပ်ရေးခဲ့သည်။ HMAC မရှိ၊ signature မရှိ၊ checksum မရှိပါ။
မှားယွင်းစွာ ပြင်ဆင်သတ်မှတ်ထားသော သို့မဟုတ် မလိုလားအပ်သည့် `CLOUD_URL` (သို့မဟုတ် channel ပေါ်ရှိ MITM) သည်
provider OAuth token များကို အသံတိတ် လဲလှယ်နိုင်ခဲ့သည်။

**v3.8.6 လျော့ပါးကာကွယ်မှု**:

1. **HMAC အတည်ပြုခြင်း**: JSON ကို parse မလုပ်မီ `verifyCloudSignature(rawBody, sigHeader)` က
   `X-Cloud-Sig` header (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`) ကို စစ်ဆေးသည်။ secret ကို သတ်မှတ်ထားပါက signature
   လိုအပ်သည်။ မသတ်မှတ်ထားပါက (legacy mode) သတိပေးချက်တစ်ခုကို log မှတ်တမ်းတင်ပြီး တုံ့ပြန်ချက်ကို
   လက်ခံသည် — v3.9 တွင် secret ကို မဖြစ်မနေ လိုအပ်မည်ဖြစ်သည်။
2. **လျှို့ဝှက် field များအတွက် opt-in**: `accessToken` / `refreshToken` /
   `providerSpecificData` တို့ကို `OMNIROUTE_CLOUD_SYNC_SECRETS=true` ဖြစ်သည့်အခါမှ **သာ**
   ထပ်ရေးသည်။ မူလ mode သည် အထောက်အထားမဟုတ်သော metadata (`expiresAt`, `status`, `lastError*`,
   `rateLimitedUntil`, `updatedAt`) ကိုသာ sync လုပ်သည်။ ၎င်းသည် အဝေးမှ token sync လုပ်ခြင်းကို
   အားထားခဲ့သော အသုံးပြုသူများအတွက် **breaking change** ဖြစ်သည် — ၎င်းတို့သည် opt in ကို
   အတိအလင်း ပြုလုပ်ရမည်။

**၎င်းကို ဆက်လက်ထားရှိရသည့် အကြောင်းရင်း**: Cloud Sync သည် OmniRoute Cloud tenant တစ်ခုအတွက်
အဖွဲ့၏ အထောက်အထားများကို တစ်နေရာတည်းတွင် ဗဟိုပြုထားနိုင်သည့် တစ်ခုတည်းသော နည်းလမ်းဖြစ်သည်။
ပြင်ဆင်ချက်သည် threat model ကို ရှင်းလင်းရိုးသားစေသည်-
"server က sign လုပ်သည်၊ client က verify လုပ်သည်၊ operator က opt in လုပ်သည်။"

## Build profile: `minimal`

Socket နှင့် သဟဇာတဖြစ်သော artifact လိုအပ်သည့် အသုံးပြုသူများအတွက် အောက်ပါအတိုင်း build လုပ်ပါ-

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

webpack `NormalModuleReplacementPlugin` သည် module လေးခုကို stub များအဖြစ် alias လုပ်သည်-

| Module                                      | Stub                                             |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

Stub တစ်ခုစီသည် တူညီသော interface ကို export လုပ်သော်လည်း function တိုင်းသည် runtime တွင်
`featureDisabledError(name)` ကို throw လုပ်သည်။ ပိတ်ထားသော module ကို မှီခိုသည့် route များသည်
ထိရှလွယ်သော code path ကို အသက်သွင်းမည့်အစား ရှင်းလင်းသည့် message နှင့်အတူ HTTP 503 ကို
ပြန်ပေးသည်။

ထွက်ပေါ်လာသော bundle ကို `omniroute-secure` အဖြစ် publish လုပ်ရန် ရည်ရွယ်ထားသည်။
Publish လုပ်နည်းအတွက် `docs/ops/PUBLISHING_SECURE.md` ကို ကြည့်ပါ။
