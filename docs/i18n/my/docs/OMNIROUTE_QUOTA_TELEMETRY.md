OmniRoute သည် provider quota telemetry ကို Ghostlight accounting မှ သီးခြားခွဲထားသည်။

## မှန်ကန်သော အခြေအနေများ

- `healthy` ဆိုသည်မှာ source တစ်ခုက အသုံးပြုနိုင်သော လက်ကျန် capacity ရှိကြောင်း အစီရင်ခံထားခြင်းကို ဆိုလိုသည်။
- `approaching_limit` ဆိုသည်မှာ source တစ်ခုက လက်ကျန် capacity သည် သတ်မှတ်ထားသော threshold နှင့် တူညီနေခြင်း သို့မဟုတ် ၎င်းအောက်သို့ ရောက်ရှိနေခြင်းကို အစီရင်ခံထားသည်ဟု ဆိုလိုသည်။
- `exhausted` ကို source တစ်ခုက capacity သုညဖြစ်ကြောင်း သို့မဟုတ် usage သည် ၎င်း၏ limit သို့ ရောက်ရှိနေကြောင်း အစီရင်ခံသည့်အခါမှသာ ထုတ်ပေးသည်။
- `unavailable` ဆိုသည်မှာ ပံ့ပိုးထားသော source တစ်ခုသည် data ပြန်လည်ပေးပို့ရန် မအောင်မြင်ခြင်းကို ဆိုလိုသည်။
- `unknown` ဆိုသည်မှာ ပံ့ပိုးထားသော source မရှိခြင်း သို့မဟုတ် provider limit ကို မသိရှိခြင်းကို ဆိုလိုသည်။

Unknown သည် exhausted မဟုတ်သည့်အပြင် provider တစ်ခုကိုလည်း ပိတ်ထားခြင်းမရှိပါ။

Source များကို အောက်ပါအစဉ်အတိုင်း ဦးစားပေးသည်- တရားဝင် provider API၊ အထောက်အထားစိစစ်ထားသော usage API၊ အတိအလင်း mapping လုပ်ထားသော response header များ၊ administrator configuration၊ local estimate များ၊ unknown။ Local estimate များကို provider billing data အဖြစ် မည်သည့်အခါမျှ ဖော်ပြခြင်းမရှိပါ။

Response header များကို အတိအလင်းသတ်မှတ်ထားသော provider mapping မှတစ်ဆင့်သာ parse လုပ်သည်။ ယေဘုယျ header အမည်များကို စနစ်တစ်ခုလုံးတွင် အလိုအလျောက် သတ်မှတ်ယူခြင်းမပြုပါ။
