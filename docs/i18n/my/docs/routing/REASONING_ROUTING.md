Reasoning routing စည်းမျဉ်းများသည် ရှိပြီးသား model နှင့် combo routing ကို တိုးချဲ့ပေးသည်။ လက်ရှိအသုံးပြုနိုင်သော စည်းမျဉ်းတစ်ခုမျှ ကိုက်ညီမှုမရှိသည့်အခါ
ရှိပြီးသား thinking၊ suffix၊ connection-default နှင့် provider-translation လုပ်ဆောင်ပုံများသည်
မပြောင်းလဲဘဲ ဆက်လက်ရှိနေမည်။

## စီမံခန့်ခွဲမှု

စည်းမျဉ်းစီမံခန့်ခွဲမှုကို **Settings → Global Routing** အောက်တွင် အသုံးပြုနိုင်သည်။ API-key တည်းဖြတ်ကိရိယာတွင်
ရွေးချယ်ထားသော key အတွက်သာ စစ်ထုတ်ပြသထားသည့် တူညီသော စီမံခန့်ခွဲမှု UI ပါရှိသည်။

စီမံခန့်ခွဲမှု API ကို အောက်ပါ route များမှ ဖော်ထုတ်ပေးထားသည်-

- `/api/settings/reasoning-routing-rules` တွင် `GET` နှင့် `POST`
- `/api/settings/reasoning-routing-rules/[id]` တွင် `GET`၊ `PATCH` နှင့် `DELETE`
- `/api/settings/reasoning-routing-rules/simulate` တွင် `POST`

Route အားလုံးသည် `requireManagementAuth` ကို အသုံးပြုသည်။ Input များကို
`src/shared/validation/schemas/reasoningRouting.ts` ရှိ schema များဖြင့် အတည်ပြုစစ်ဆေးသည်။ Simulator သည် upstream call ကို မည်သည့်အခါမျှ မပြုလုပ်ပါ။

## စည်းမျဉ်း ဖြေရှင်းရွေးချယ်မှု

အစောပိုင်း အကဲဖြတ်မှုသည် စည်းမျဉ်းတစ်ခုတည်းကိုသာ အတိအကျ ရွေးချယ်သည်။ Scope များကို ဤအစဉ်အတိုင်း စစ်ဆေးသည်-

1. `apiKey`
2. `combo`
3. `model`
4. `global`

Scope တစ်ခုအတွင်း ပိုမြင့်သော `priority` က ဦးစွာ အနိုင်ရပြီး၊ ထို့နောက် glob pattern ထက် အတိအကျ model ကိုက်ညီမှုကို ဦးစားပေးကာ
နောက်ဆုံးတွင် တည်ငြိမ်သော `createdAt` နှင့် `id` အစဉ်ကို အသုံးပြုသည်။ `requestTags` များကို `metadata.tags` မှသာ
သီးသန့်ဖတ်ယူပြီး `any` သို့မဟုတ် `all` ကိုက်ညီမှုကို ပံ့ပိုးသည်။

`connection` စည်းမျဉ်းကို အစောပိုင်းစည်းမျဉ်းတစ်ခုမျှ အနိုင်မရဘဲ တိကျသော provider connection တစ်ခုကို
ရွေးချယ်ပြီးသည့်အခါမှသာ အကဲဖြတ်သည်။ ၎င်းသည် effort နှင့် budget ကိုသာ ပြောင်းလဲနိုင်သည်။

## Effort နှင့် Budget

`sourceEffort` သည် `any`၊ `missing`၊ `none`၊ `low`၊ `medium`၊ `high`၊ `xhigh`၊ `max` နှင့်
`ultra` တို့ကို လက်ခံသည်။ `missing` ဆိုသည်မှာ request တွင် သီးခြား effort တစ်ခု၊ thinking toggle တစ်ခု
သို့မဟုတ် thinking budget တစ်ခုမျှ မပါဝင်ခြင်းကို ဆိုလိုသည်။ ထို့ကြောင့် budget သီးသန့် signal သည် `any` နှင့်သာ ကိုက်ညီသည်။

`effortMode` တွင် variant သုံးမျိုးရှိသည်-

- `inherit` သည် model သို့မဟုတ် combo ကို ပြောင်းလဲခွင့် ဆက်လက်ပေးထားစဉ် client effort ကို ထိန်းသိမ်းထားသည်။
- `default` သည် တိကျစွာ သတ်မှတ်ထားသော reasoning signal မရှိမှသာ `targetEffort` ကို သတ်မှတ်သည်။
- `force` သည် သီးခြား effort ကို `targetEffort` ဖြင့် အစားထိုးသည်။

သီးခြားအနေဖြင့် `budgetAction` သည် `preserve`၊ `remove` သို့မဟုတ် `set` ဖြစ်နိုင်သည်။ `none` ပါသော `force` သည်
အသိအမှတ်ပြုထားသော effort နှင့် budget field အားလုံးကို ဖယ်ရှားသည်။ `none` ကို `set` နှင့် တွဲသုံးခြင်းသည် မမှန်ကန်ပါ။

သိရှိထားသော မကိုက်ညီသည့် model များကို ရည်ညွှန်းသော request များကို upstream call မပြုလုပ်မီ ပယ်ချသည်။ Combo
target များအတွက် မကိုက်ညီသော entry များကို ဖယ်ရှားပြီး၊ တစ်ခုမျှ မကျန်ပါက request သည် status `400` ကို ပြန်ပေးသည်။
မသိရှိသော capability data ကြောင့် သတိပေးချက်တစ်ခု ထုတ်ပေးပြီး စည်းမျဉ်းကို ဆက်လက်အသုံးပြုနိုင်စေသည်။

## လုံခြုံရေးနှင့် ပို့ဆောင်မှုနည်းလမ်းများ

Source နှင့် target model သို့မဟုတ် source နှင့် target combo တို့သည် ရှိပြီးသား API-key
မူဝါဒ၏ ကန့်သတ်ချက်များအောက်တွင် ဆက်လက်ရှိသည်။ Reasoning စည်းမျဉ်းတစ်ခုသည် model၊ combo သို့မဟုတ် quota ခွင့်ပြုချက်များကို မည်သည့်အခါမျှ တိုးချဲ့ပေးခြင်းမရှိပါ။

Engine ကို Chat Completions၊ Responses၊ Anthropic Messages နှင့် အတွင်းပိုင်း
Codex WebSocket path တို့တွင် ပေါင်းစပ်ထားသည်။ WebSocket path သည် Codex target model များကိုသာ လက်ခံပြီး combo target များကို
ထိုနေရာတွင် လုပ်ဆောင်၍မရပါ။ စည်းမျဉ်းဆုံးဖြတ်ချက်ကို လျှို့ဝှက်အချက်အလက်များမပါဘဲ ရှိပြီးသား route trace တွင် သိမ်းဆည်းသည်။

## ဒေတာသိမ်းဆည်းမှု

Migration `src/lib/db/migrations/126_reasoning_routing_rules.sql` သည်
`reasoning_routing_rules` table ကို ဖန်တီးသည်။ စည်းမျဉ်းများသည် သိမ်းဆည်းထားသော API key များ၊ combo များနှင့် provider connection များကို ကိုးကားသည်။
ဖျက်ခြင်းများသည် ဆက်စပ်စည်းမျဉ်းများကို ရှင်းလင်းပေးသည်။ `src/lib/db/reasoningRoutingRules.ts` ရှိ database access layer သည်
request path အတွက် ပယ်ဖျက်၍ရသော cache တစ်ခုကို ထိန်းသိမ်းသည်။

စည်းမျဉ်းများကို SQLite backup များ၊ database အပြည့်အစုံ export နှင့် config-sync bundle တို့တွင် ထည့်သွင်းထားသည်။
`reconcileReasoningRulesForSync` သည် ကိုးကားချက်ပျောက်ဆုံးနေသော import လုပ်ထားသည့် စည်းမျဉ်းများကို ပိတ်ထားပြီး ထို
ပဋိပက္ခများကို အစီရင်ခံသည်။
