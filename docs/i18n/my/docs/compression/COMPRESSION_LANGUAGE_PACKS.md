Caveman compression သည် ထည့်သွင်းပါရှိပြီးသား အင်္ဂလိပ်စည်းမျဉ်းများအပြင် ဘာသာစကားအလိုက် စည်းမျဉ်းပက်ကေ့များကိုလည်း ဖွင့်တင်အသုံးပြုနိုင်သည်။
၎င်းကြောင့် အဓိကအင်ဂျင်ကို တည်ငြိမ်စွာ ထိန်းသိမ်းထားနိုင်ပြီး ပေါ်တူဂီ၊ စပိန်၊ ဂျာမန်၊ ပြင်သစ်၊ အီတလီ၊ ဂျပန်နှင့်
အနာဂတ်တွင် ထပ်မံထည့်သွင်းမည့် ဘာသာစကားပက်ကေ့များကို သီးခြားစီ တိုးတက်ပြောင်းလဲနိုင်စေသည်။

## တည်နေရာ

ဘာသာစကားပက်ကေ့များသည် အောက်ပါနေရာတွင် ရှိသည်-

```txt
open-sse/services/compression/rules/<language>/
```

လက်ရှိ ထည့်သွင်းဖြန့်ချိထားသော ပက်ကေ့များ (`rules/` လမ်းညွှန်ရှိ အကြောင်းအရာများနှင့် တိုက်ဆိုင်စစ်ဆေးပြီး)-

| ဘာသာစကား          | လမ်းညွှန်      | ပါဝင်သော စည်းမျဉ်းအမျိုးအစားများ                    |
| ----------------- | -------------- | --------------------------------------------------- |
| အင်္ဂလိပ်         | `rules/en/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| စပိန်             | `rules/es/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| ပေါ်တူဂီ (ဘရာဇီး) | `rules/pt-BR/` | `context`, `dedup`, `filler`, `structural`, `ultra` |
| အင်ဒိုနီးရှား     | `rules/id/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| အီတလီ             | `rules/it/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| ဂျာမန်            | `rules/de/`    | `context`, `filler`, `structural`                   |
| ပြင်သစ်           | `rules/fr/`    | `context`, `filler`, `structural`                   |
| ဂျပန်             | `rules/ja/`    | `context`, `filler`, `structural`                   |

> **တန်းတူညီမျှမှု မှတ်ချက်-** `en`, `es`, `pt-BR`, `id` နှင့် `it` ပက်ကေ့များတွင် အမျိုးအစား ၅ မျိုးလုံး ပါဝင်ပြီး၊ `de`, `fr`, `ja` တို့တွင် အမျိုးအစား ၃ မျိုး ပါဝင်သည်။ မပါဝင်သေးသော `dedup` နှင့် `ultra` အမျိုးအစားများသည် အလိုအလျောက် အသိပေးခြင်းမရှိဘဲ ထည့်သွင်းပါရှိသော အင်္ဂလိပ်စည်းမျဉ်းများကို အစားထိုးအသုံးပြုမည်။ ပက်ကေ့အသေးများအတွက် `dedup.json` နှင့် `ultra.json` တို့ကို ထည့်သွင်းပံ့ပိုးမှုများ ပြုလုပ်ရန် ကြိုဆိုပါသည်။
>
> `pt-BR` ပက်ကေ့သည် Lenine Júnior ရေးသားသော **[Troglodita](https://github.com/leninejunior/troglodita)** ကို အခြေခံထားသည် — ၎င်းသည် ဘရာဇီးပေါ်တူဂီ သဒ္ဒါအတွက် အစမှစ၍ ရေးဆွဲထားသော compression စနစ်တစ်ခုဖြစ်ပြီး ထပ်တလဲလဲ အဓိပ္ပာယ်တူဖော်ပြမှု လျှော့ချခြင်း၊ PT-BR အပိုစကားလုံးများ ဖယ်ရှားခြင်းနှင့် ဘရာဇီး developer အသိုင်းအဝိုင်းအတွက် နည်းပညာဆိုင်ရာ အတိုကောက်များ ပါဝင်သည်။
>
> စံသတ်မှတ်ထားသော အမျိုးအစားစာရင်းနှင့် အမျိုးအစားတစ်ခုချင်းစီ၏ schema ကို [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) (JSON Schema draft 2020-12) တွင် တွေ့နိုင်သည်။

## ဘာသာစကား ရှာဖွေသတ်မှတ်ခြင်း

`languageDetector.ts` သည် prompt စာသားမှ ဘာသာစကားကို ခန့်မှန်းရန် ပေါ့ပါးသော ခန့်မှန်းနည်းများကို အသုံးပြုသည်။ စီစဉ်သတ်မှတ်ထားသော မူလဘာသာစကားကို ဆက်လက်လိုက်နာမည်ဖြစ်ပြီး တိကျသော
ထိန်းချုပ်မှု လိုအပ်ပါက config မှတစ်ဆင့် ရှာဖွေသတ်မှတ်မှုကို ပိတ်နိုင်သည်။

ရှာဖွေသတ်မှတ်မှု ရလဒ်ကို စည်းမျဉ်းပက်ကေ့ ရွေးချယ်ရန်အတွက်သာ အသုံးပြုသည်။ ၎င်းသည် provider routing၊ locale
ရွေးချယ်မှု သို့မဟုတ် UI ဘာသာစကားကို ပြောင်းလဲခြင်းမရှိပါ။

## Config ဖွဲ့စည်းပုံ

Compression ဆက်တင်များတွင် အောက်ပါတို့ ပါဝင်နိုင်သည်-

```json
{
  "languageConfig": {
    "enabled": true,
    "defaultLanguage": "en",
    "autoDetect": true,
    "enabledPacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  },
  "cavemanConfig": {
    "language": "en",
    "autoDetectLanguage": true,
    "enabledLanguagePacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  }
}
```

`languageConfig` သည် dashboard/preview ၏ မူလသတ်မှတ်ချက်များကို ထိန်းချုပ်သည်။ `cavemanConfig` သည် Caveman က မက်ဆေ့ချ်စာသားကို ချုံ့သည့်အခါ
အသုံးပြုသော runtime engine config ဖြစ်သည်။

## ဘာသာစကား Pack တစ်ခု ထည့်သွင်းခြင်း

1. `open-sse/services/compression/rules/<language>/<pack>.json` ကို ဖန်တီးပါ။
2. `docs/compression/COMPRESSION_RULES_FORMAT.md` ရှိ Caveman စည်းမျဉ်းဖော်မတ်ကို အသုံးပြုပါ။
3. အစားထိုးမှုများကို အလွန်အကျွံမဖြစ်စေဘဲ code၊ identifier များ၊ URL များ သို့မဟုတ် JSON ကို ပြောင်းလဲခြင်းမှ ရှောင်ကြဉ်ပါ။
4. ဘာသာစကားရွေးချယ်မှုနှင့် အစားထိုးမှုအပြုအမူအတွက် စမ်းသပ်မှုများကို ထည့်သွင်းပါ သို့မဟုတ် အပ်ဒိတ်လုပ်ပါ။
5. ဘာသာစကားသည် UI selector များတွင် ပေါ်လာပါက dashboard/i18n label အသစ်များကို ဖော်ထုတ်ပေးပါ။

## API

ရရှိနိုင်သော pack များကို အောက်ပါအတိုင်း မေးမြန်းနိုင်သည်-

```bash
curl http://localhost:20128/api/compression/language-packs
```

Preview endpoint သည် ဘာသာစကား configuration override များကို လက်ခံသည်-

```bash
curl -X POST http://localhost:20128/api/compression/preview \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "standard",
    "text": "Por favor, eu gostaria que voce basicamente resumisse isso.",
    "config": {
      "languageConfig": {
        "defaultLanguage": "pt-BR",
        "autoDetect": true
      }
    }
  }'
```

## SHARED_BOUNDARIES (v3.8.0)

v3.8.0 တွင် ဘာသာစကား pack 6 ခုစလုံးသည် Caveman ပြင်းအားအဆင့်တိုင်း (LITE, FULL, ULTRA) တွင်
အသုံးချသည့် `SHARED_BOUNDARIES` clause ကို ရရှိခဲ့သည်။ ၎င်းသည် ပတ်ဝန်းကျင်ရှိ ဖြည့်စွက်စာသားများကို
ဖယ်ရှားသည်ဖြစ်စေ အောက်ပါ pattern များကို မူရင်းအတိုင်း ထိန်းသိမ်းရန် engine အား ညွှန်ကြားသည်-

| Pattern အမျိုးအစား                   | ဥပမာ                                   |
| ------------------------------------ | -------------------------------------- |
| Fenced code block များ               | ` ```python\n...\n``` `                |
| Inline code                          | `` `my_var` ``                         |
| URL များ                             | `https://example.com/path`             |
| File path များ (absolute + relative) | `/etc/hosts`, `./src/index.ts`         |
| Error header များ                    | `Error:`, `TypeError:`, `SyntaxError:` |
| Stack trace line များ                | `  at functionName (file.ts:12:3)`     |

ဤ pattern များကို `DEFAULT_CAVEMAN_CONFIG.preservePatterns` (ယခင်က `[]`) တွင် ဖြည့်သွင်းထားသည်။
Constant သည် `open-sse/services/compression/types.ts` တွင် ရှိသည်။

### ဤအရာက အဘယ်ကြောင့် အရေးကြီးသနည်း

SHARED_BOUNDARIES မရှိပါက ပြင်းထန်သော Caveman mode များသည် ထပ်တလဲလဲဖြစ်နေသော
စကားပြေစာသားကဲ့သို့ ထင်ရသော်လည်း အမှန်တကယ်တွင် code snippet၊ file path သို့မဟုတ် error stack
ဖြစ်နေသည့် အကြောင်းအရာများကို ဖယ်ရှားပစ်နိုင်သည်။ SHARED_BOUNDARIES သည် ဖြည့်စွက်စာသားဆိုင်ရာ
စည်းမျဉ်းများ မလုပ်ဆောင်မီ အသုံးချသည့် ဘာသာစကားအပေါ် မမူတည်သော လုံခြုံရေးအကာအကွယ်အဖြစ် လုပ်ဆောင်သည်။

### preservePatterns ကို စိတ်ကြိုက်ပြင်ဆင်ခြင်း

Compression setting များမှတစ်ဆင့် runtime တွင် နောက်ထပ် pattern များကို ထည့်သွင်းနိုင်သည်-

````json
{
  "cavemanConfig": {
    "preservePatterns": [
      "```[\\s\\S]*?```",
      "`[^`]+`",
      "https?://\\S+",
      "(?:/|\\./)[^\\s]+",
      "\\b(?:Error|TypeError|SyntaxError|RangeError):",
      "\\s+at\\s+\\S+\\s+\\(\\S+:\\d+:\\d+\\)"
    ]
  }
}
````

စိတ်ကြိုက် pattern များသည် မူလ default 6 ခုကို အစားမထိုးဘဲ တိုးချဲ့ပေးသည်။

---

## လုပ်ငန်းလည်ပတ်မှုဆိုင်ရာ မှတ်ချက်များ

- ဘာသာစကား pack မရှိသည့်အခါ ထည့်သွင်းပြီးသား အင်္ဂလိပ်စည်းမျဉ်းများကို fallback အဖြစ် ဆက်လက်အသုံးပြုသည်။
- မမှန်ကန်သော ထည့်သွင်းပြီးသား JSON pack များသည် validation မအောင်မြင်သောကြောင့် release asset များ၏ အရည်အသွေးသည် အသိပေးခြင်းမရှိဘဲ ကျဆင်းသွားမည်မဟုတ်ပါ။
- Rule pack များသည် data သီးသန့်သာဖြစ်ပြီး code ကို import မလုပ်သင့်သကဲ့သို့ မည်သည့် logic ကိုမဆို လွတ်လပ်စွာ မလုပ်ဆောင်သင့်ပါ။
- Compression analytics layer သည် prompt စာသားအပြည့်အစုံကို မဟုတ်ဘဲ ရွေးချယ်ထားသော mode နှင့် engine ကိုသာ မှတ်တမ်းတင်သည်။
