## ၎င်းသည် ဘာလဲ

OmniRoute သည် **Obsidian** vault တစ်ခုကို **context source** အဖြစ် ချိတ်ဆက်ပေးသည် — ၎င်းသည်
agent များက built-in MCP server မှတစ်ဆင့် ဖတ်ရှု၊ ရေးသားနိုင်သည့် local Markdown
knowledge base တစ်ခုဖြစ်သည်။ ဤ integration သည် desktop app အတွင်း လည်ပတ်နေသော
**Obsidian Local REST API** community plugin နှင့် ဆက်သွယ်သောကြောင့် agent များသည်
မှတ်စုများကို ရှာဖွေခြင်း၊ ဖိုင်များကို ဖတ်ခြင်း/ရေးခြင်း/ပြင်ဆင်ခြင်း၊ vault စာရင်းကို ကြည့်ရှုခြင်း၊
နေ့စဉ်/အပတ်စဉ် periodic note များနှင့် လုပ်ဆောင်ခြင်း၊ tag များကို စီမံခြင်း၊ Obsidian command
များကို လုပ်ဆောင်ခြင်းနှင့် (ရွေးချယ်နိုင်သည့်အနေဖြင့်) desktop↔mobile နှစ်လမ်းသွား vault sync
ကို ညှိနှိုင်းခြင်းတို့ ပြုလုပ်နိုင်သည်။

Client (`src/lib/obsidian/api.ts`) သည် Local REST API ကို အောက်ပါလုပ်ဆောင်ချက်များဖြင့်
ထုပ်ပိုးပေးထားသည်-

- ယာယီ `5xx` အမှားများအတွက် **backoff ဖြင့် ပြန်လည်ကြိုးစားခြင်း**၊ `AbortController` မှတစ်ဆင့် **စက္ကန့် 30 timeout**။
- **Type သတ်မှတ်ထားသော error အမျိုးအစားခွဲခြားမှု** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`။
- အဖြစ်များသော port မှားယွင်းမှု (HTTP သည် `27123` တွင်ဖြစ်ပြီး `27124` ရှိ MCP endpoint
  **မဟုတ်ပါ**) နှင့် Tailscale ပုံစံကို ထောက်ပြပေးသည့် နားလည်လွယ်သော
  **"Obsidian သို့ ဆက်သွယ်၍မရပါ" အကြံပြုချက်**။
- space/slash များပါဝင်သည့် note path များကို ဘေးကင်းစေရန် vault-relative **path encoding**။

## စတင်ပြင်ဆင်ခြင်း

Obsidian token သို့မဟုတ် base URL အတွက် **environment variable မရှိပါ** — နှစ်ခုစလုံးကို
`src/lib/db/obsidian.ts` မှတစ်ဆင့် SQLite `key_value` table (namespace `obsidian`) ထဲတွင်
သိမ်းဆည်းထားသည်။ Token ကို **သိမ်းဆည်းထားစဉ် encryption ပြုလုပ်ထားသည်**
(AES-256-GCM၊ plaintext backward-compat fallback ပါဝင်သည်)။ Endpoint dashboard ၏
**Context Sources** tab (`ObsidianSourceCard`) မှဖြစ်စေ၊ settings REST API မှတစ်ဆင့်ဖြစ်စေ
ပြင်ဆင်သတ်မှတ်ပါ။

> [!IMPORTANT]
> **Obsidian Local REST API** plugin ကို ထည့်သွင်းထားပြီး လည်ပတ်နေစေရမည်။ ၎င်း၏ REST
> interface သည် **HTTP `127.0.0.1:27123`** (မူလ base URL) တွင် ချိတ်ဆက်မှုများကို
> လက်ခံသည်။ Port `27124` သည် _သီးခြား_ MCP/HTTPS endpoint ဖြစ်ပြီး settings route
> က ၎င်းကို အတိအလင်း ငြင်းပယ်သည်။ အခြား device တစ်ခုမှ ချိတ်ဆက်ပါက
> `http://<tailscale-ip>:27123` ကို အသုံးပြုပါ။

### Configuration key များ (SQLite `key_value`, namespace `obsidian`)

| Key               | ရည်ရွယ်ချက်                                     | Encryption ပြုလုပ်ထားမှု |
| ----------------- | ----------------------------------------------- | ------------------------ |
| `api_key`         | Local REST API bearer token                     | ရှိ                      |
| `base_url`        | REST base URL (မူလ `http://127.0.0.1:27123`)    | မရှိ                     |
| `vault_path`      | vault directory သို့ absolute path (sync အတွက်) | မရှိ                     |
| `webdav_username` | ထုတ်ပေးထားသော WebDAV username (vault sync)      | မရှိ                     |
| `webdav_password` | ထုတ်ပေးထားသော WebDAV password (vault sync)      | ရှိ                      |
| `webdav_enabled`  | WebDAV vault sync ကို ဖွင့်ထားခြင်း ရှိ/မရှိ    | မရှိ                     |

### REST မှတစ်ဆင့် ပြင်ဆင်သတ်မှတ်ခြင်း

```bash
# Local REST API token ကို သိမ်းဆည်းပြီး အတည်ပြုပါ (POST သည် status စစ်ဆေးခြင်းဖြင့် အတည်ပြုသည်)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# ချိတ်ဆက်မှု status ကို စစ်ဆေးပါ (connected, hasToken, baseUrl, vaultPath တို့ကို ပြန်ပေးသည်)
curl http://localhost:20128/api/settings/obsidian

# ချိတ်ဆက်မှုဖြုတ်ပါ (သိမ်းဆည်းထားသော token ကို ရှင်းလင်းသည်)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Method အားလုံးအတွက် dashboard authentication လိုအပ်သည်။ `POST` သည် port `27124`
ပေါ်ရှိ မည်သည့် URL ကိုမဆို ငြင်းပယ်ပြီး သိမ်းဆည်းခြင်းမပြုမီ Local REST API status endpoint
ကို ခေါ်ခြင်းဖြင့် token ကို အတည်ပြုသည်။

### WebDAV vault sync

`src/app/api/settings/obsidian/webdav/route.ts` သည် `src/lib/obsidianSync.ts` ဖြင့်
မောင်းနှင်သော ရွေးချယ်နိုင်သည့် WebDAV-backed vault sync ကို စီမံသည်။ ၎င်းကို ဖွင့်ထားပါက
OmniRoute ကို local vault directory တစ်ခုသို့ ညွှန်ပြပြီး ကျပန်း WebDAV username/password
တစ်စုံကို ထုတ်ပေးသည်-

```bash
# vault directory တစ်ခုအတွက် WebDAV sync ကို ဖွင့်ပါ (username/password ထုတ်ပေးသည်)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# WebDAV sync status ကို ရယူပါ (ဖွင့်ထားသည့်အချိန်တွင်သာ credentials များကို ပြန်ပေးသည်)
curl http://localhost:20128/api/settings/obsidian/webdav

# WebDAV sync ကို ပိတ်ပါ (credentials + စီမံထားသော .stignore ကို ရှင်းလင်းသည်)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### API key တစ်ခုချင်းစီအလိုက် context source (ရွေးချယ်နိုင်သည်)

Obsidian config ကို `api_key_context_sources` table
(`src/lib/db/apiKeyContextSources.ts`) မှတစ်ဆင့် **API key တစ်ခုချင်းစီအလိုက်** scope
သတ်မှတ်နိုင်သည်။ MCP call တစ်ခုတွင် authentication ပြုလုပ်ထားသော API key id ပါရှိသည့်အခါ
`getObsidianConfigForApiKey()` သည် ထို key ၏ ကိုယ်ပိုင် token/base-URL/vault-path
(`source: "api_key"`) ကို ဦးစားပေးပြီး မရှိပါက global config (`source: "global"`) ကို
fallback အဖြစ် အသုံးပြုသည်။

## MCP ကိရိယာများ (22)

`open-sse/mcp-server/tools/obsidianTools.ts` တွင် သတ်မှတ်ထားသည်။ token/base-URL ကို ခေါ်ဆိုမှုတစ်ခုချင်းစီအလိုက် ဖြေရှင်းသတ်မှတ်သည် (API key အလိုက် ဦးစွာ၊ ထို့နောက် global)။ OmniRoute **sync server** ကို အသုံးပြုသည့် ကိရိယာများ (`obsidian_sync_*` ကိရိယာလေးခု) သည် OmniRoute settings တွင် စီစဉ်သတ်မှတ်ထားသော sync auth token ကိုလည်း ထပ်မံလိုအပ်သည်။

| `obsidian_get_periodic_note` | ရက်စွဲတစ်ခုအတွက် နေ့စဉ်/အပတ်စဉ်/လစဉ် periodic note ကို ရယူသည် (ချန်လှပ်ထားပါက ယနေ့ရက်စွဲ)။                           |
| `obsidian_get_tags`          | vault tag အားလုံးကို ၎င်းတို့၏ အသုံးပြုမှုအကြိမ်ရေများနှင့်အတူ စာရင်းပြုစုသည်။                                       |
| `obsidian_list_commands`     | ရရှိနိုင်သော Obsidian command ID များကို စာရင်းပြုစုသည် (`obsidian_execute_command` နှင့် အသုံးပြုရန်)။              |
| `obsidian_sync_status`       | OmniRoute sync server ၏ အခြေအနေ—လည်ပတ်နေခြင်း၊ vault အမည်၊ port၊ uptime နှင့် နောက်ဆုံး sync ကို ရယူသည်။             |
| `obsidian_sync_conflicts`    | မဖြေရှင်းရသေးသော sync conflict များကို စာရင်းပြုစုသည် (path၊ conflict path၊ တွေ့ရှိသည့်အချိန်)။                      |

### ရေးသားရေးကိရိယာများ (`write:obsidian`)

| ကိရိယာ                           | ဖော်ပြချက်                                                                                                           |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | ပေးထားသော Markdown အကြောင်းအရာဖြင့် note တစ်ခုကို ဖန်တီးသည် သို့မဟုတ် ထပ်ရေးသည်။                                     |
| `obsidian_append_note`           | note တစ်ခုသို့ အကြောင်းအရာကို ဖြည့်စွက်သည်၊ သတ်မှတ်ထားသော heading/block သို့လည်း ဖြည့်စွက်နိုင်သည်။                  |
| `obsidian_patch_note`            | heading၊ block သို့မဟုတ် frontmatter field တစ်ခုတွင် အကြောင်းအရာကို တိကျစွာ ဖြည့်စွက်/ရှေ့တွင်ဖြည့်စွက်/အစားထိုးသည်။ |
| `obsidian_delete_note`           | vault မှ note တစ်ခုကို အပြီးအပိုင် ဖျက်သည်။                                                                          |
| `obsidian_move_note`             | vault အတွင်း note တစ်ခုကို ရွှေ့သည် သို့မဟုတ် အမည်ပြောင်းသည်။                                                        |
| `obsidian_execute_command`       | Obsidian command တစ်ခုကို ၎င်း၏ command ID ဖြင့် လုပ်ဆောင်သည်။                                                       |
| `obsidian_open_file`             | Obsidian တွင် file တစ်ခုကို ဖွင့်သည် (မရှိပါက ဖန်တီးသည်)။                                                            |
| `obsidian_sync_trigger`          | desktop↔mobile vault နှစ်ဖက်အပြန်အလှန် sync ကို ချက်ချင်း စတင်လုပ်ဆောင်သည်။                                          |
| `obsidian_sync_resolve_conflict` | sync conflict တစ်ခုကို ဖြေရှင်းသည်—`local` (mobile)၊ `remote` (desktop) သို့မဟုတ် `keep-both` ကို ထိန်းသိမ်းထားသည်။  |

> [!NOTE]
> `obsidian_patch_note` ၏ target များသည် `heading | block | frontmatter`
> ဟူသော `targetType` နှင့် `append | prepend | replace` ဟူသော `operation` ကို
> လက်ခံပြီး `createTargetIfMissing` ကို ရွေးချယ်ထည့်သွင်းနိုင်သည်။ `obsidian_sync_*`
> ကိရိယာလေးခုသည် local sync server (`http://127.0.0.1:27781` ကို မူလသတ်မှတ်ချက်အဖြစ်)
> နှင့် ဆက်သွယ်ကာ sync token ကို လိုအပ်သည်။

### Scope များ

ဖတ်ရှုရေးကိရိယာများသည် `read:obsidian` ကို လိုအပ်ပြီး ရေးသားရေးကိရိယာများသည် `write:obsidian` ကို လိုအပ်သည်။ Enforcement
သည် Notion နှင့် တူညီပြီး `open-sse/mcp-server/server.ts` ရှိ `withScopeEnforcement()` က
ကိုင်တွယ်သည်။ ၎င်းကို `OMNIROUTE_MCP_ENFORCE_SCOPES=true` ဖြစ်သည့်အခါ အသက်ဝင်စေပြီး
ခွင့်ပြုထားသော scope များကို `OMNIROUTE_MCP_SCOPES` သို့မဟုတ် API key ၏ scope context မှ ရယူသည်။ အသေးစိတ်ကို
[MCP-SERVER.md](./MCP-SERVER.md) တွင် ကြည့်ပါ။

## Endpoint များ

| Method   | Path                            | ရည်ရွယ်ချက်                                                                 |
| -------- | ------------------------------- | --------------------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | `{ connected, hasToken, baseUrl, vaultPath }` ကို ပြန်ပေးသည်။               |
| `POST`   | `/api/settings/obsidian`        | တိုကင်ကို သိမ်းဆည်းပြီး မှန်ကန်မှုစစ်ဆေးသည် (port `27124` ကို ငြင်းပယ်သည်)။ |
| `DELETE` | `/api/settings/obsidian`        | ချိတ်ဆက်မှုဖြုတ်သည် (သိမ်းဆည်းထားသော တိုကင်ကို ရှင်းလင်းသည်)။               |
| `GET`    | `/api/settings/obsidian/webdav` | WebDAV sync အခြေအနေ + အထောက်အထားများ (`enabled` ဖြစ်နေစဉ်)။                 |
| `POST`   | `/api/settings/obsidian/webdav` | vault directory တစ်ခုအတွက် WebDAV sync ကို ဖွင့်သည်။                        |
| `DELETE` | `/api/settings/obsidian/webdav` | WebDAV sync ကို ပိတ်သည်။                                                    |

> ဤအရာများသည် dashboard settings route များဖြစ်သည်။ vault ကိုယ်တိုင်ကို Obsidian
> Local REST API (ပြင်ဆင်သတ်မှတ်ထားသော `base_url`) နှင့် အထက်ပါ MCP tool များမှတစ်ဆင့်
> ဝင်ရောက်သည် — အများသုံး `/v1` Obsidian proxy endpoint မရှိပါ။

## အသုံးပြုမှုများ

- **Vault ကို အခြေခံသော အဖြေများ** — `obsidian_search_simple` / `obsidian_search_structured`
  ပြီးနောက် `obsidian_read_note` ကို အသုံးပြုခြင်းဖြင့် agent သည် သင့်မှတ်စုအစစ်များမှ အခြေခံ၍ အဖြေပေးနိုင်သည်။
- **မှတ်စုရေးသားခြင်း / နေ့စဉ်မှတ်တမ်းတင်ခြင်း** — agent output၊ အနှစ်ချုပ်များ သို့မဟုတ် နေ့စဉ်မှတ်စုများကို
  vault ထဲသို့ မှတ်တမ်းတင်ရန် `obsidian_write_note`၊ `obsidian_append_note` သို့မဟုတ်
  တိကျသော `obsidian_patch_note` ကို အသုံးပြုသည်
  (`obsidian_get_periodic_note`)။
- **Vault လမ်းညွှန်ရှာဖွေခြင်း** — ဖတ်ရှုခြင်း/ရေးသားခြင်းမပြုမီ ဖွဲ့စည်းပုံကို လေ့လာရန်
  `obsidian_list_vault`၊ `obsidian_get_document_map` နှင့်
  `obsidian_get_tags` ကို အသုံးပြုသည်။
- **Obsidian အလိုအလျောက်လုပ်ဆောင်မှု** — agent မှ plugin/command များကို ထိန်းချုပ်မောင်းနှင်ရန်
  `obsidian_list_commands` + `obsidian_execute_command` ကို အသုံးပြုသည်။ UI တွင် မှတ်စုတစ်ခုကို ဖော်ပြရန် `obsidian_open_file` ကို အသုံးပြုသည်။
- **မိုဘိုင်း sync** — WebDAV sync ကို ဖွင့်ပြီးနောက် desktop↔mobile အကြား ညှိနှိုင်းရန်နှင့် ပဋိပက္ခများကို ဖြေရှင်းရန်
  `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  ကို အသုံးပြုသည်။
