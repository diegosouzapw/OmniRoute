> ချိတ်ဆက်ခြင်းတို့သည် `open-sse/mcp-server/server.ts` တွင် ရှိသည်။

## ၎င်းသည် ဘာလဲ

OmniRoute သည် **Notion** workspace တစ်ခုကို **အကြောင်းအရာရင်းမြစ်** အဖြစ် ချိတ်ဆက်နိုင်သည် — ၎င်းသည် agent များက ပါဝင်ပြီးသား MCP server မှတစ်ဆင့် ဝင်ရောက်အသုံးပြုနိုင်သည့် ဖတ်နိုင်/ရေးနိုင်သော
အသိပညာအခြေခံတစ်ခု ဖြစ်သည်။ Notion integration token ကို စီစဉ်သတ်မှတ်ပြီးသည်နှင့် MCP tool များက LLM တစ်ခုအား page များနှင့် database များကို ရှာဖွေခြင်း၊
page အကြောင်းအရာနှင့် block tree များကို ဖတ်ခြင်း၊ filter/sort များဖြင့် database များကို query လုပ်ခြင်းနှင့် block အသစ်များ ထပ်ဖြည့်ခြင်းတို့ ပြုလုပ်နိုင်စေသည် — အားလုံးကို OmniRoute မှတစ်ဆင့် proxy လုပ်ထားပြီး (ပြန်လည်ကြိုးစားမှု၊ အချိန်ကုန်ဆုံးမှုနှင့် error အမျိုးအစားခွဲခြားမှုတို့ ပါဝင်သည်)
ဖြစ်သောကြောင့် model သည် Notion API ကို တိုက်ရိုက် ထိတွေ့အသုံးပြုခြင်း မရှိပါ။

ဤ integration သည် တရားဝင် Notion REST API
(`https://api.notion.com/v1`, `Notion-Version: 2026-03-11`) ကို အခြေခံထားသည့် ပါးလွှာပြီး လုံခြုံခိုင်မာအောင် ပြုလုပ်ထားသော wrapper တစ်ခု ဖြစ်သည်။ Client
(`src/lib/notion/api.ts`) တွင် အောက်ပါတို့ကို ထည့်သွင်းထားသည်-

- `429` နှင့် `5xx` အတွက် **exponential backoff ဖြင့် ပြန်လည်ကြိုးစားခြင်း** (အများဆုံး ၃ ကြိမ်)။
- `AbortController` မှတစ်ဆင့် **၅၅ စက္ကန့် request timeout**။
- **Type သတ်မှတ်ထားသော error အမျိုးအစားခွဲခြားမှု** — `NotionAuthError` (401/403),
  `NotionNotFoundError` (404), `NotionRateLimitError` (429၊ `retry after`
  အကြံပြုချက်များကို လိုက်နာသည်), `NotionValidationError` (400/409), `NotionServerError` (5xx),
  `NotionTimeoutError`။
- ပြသမည့်အကြောင်းအရာထဲမှ stack trace နှင့်တူသော အပိုင်းအစများကို ဖယ်ရှားပေးသည့် **message သန့်စင်မှု**။

## စီစဉ်သတ်မှတ်ခြင်း

Notion token အတွက် **environment variable မရှိပါ** — ၎င်းကို
`src/lib/db/notion.ts` မှတစ်ဆင့် SQLite `key_value` table (namespace `notion`, key `integration_token`) တွင် သိမ်းဆည်းသည်။ ၎င်းကို Endpoint
dashboard ၏ **Context Sources** tab (`ObsidianSourceCard` နှင့် အဆင့်တူ `NotionSourceCard`) မှဖြစ်စေ၊ ဆက်တင် REST API မှဖြစ်စေ စီစဉ်သတ်မှတ်ပါ။

> [!NOTE]
> Token သည် **Notion internal integration token** တစ်ခု ဖြစ်သည်။ Integration တစ်ခုကို
> <https://www.notion.com/my-integrations> တွင် ဖန်တီးပြီးနောက် OmniRoute က ဝင်ရောက်အသုံးပြုစေလိုသော page/database များကို
> ထို integration နှင့် မျှဝေပါ (Notion ၏ permission model သည် workspace တစ်ခုလုံးအပေါ် အခြေခံခြင်းမဟုတ်ဘဲ
> မျှဝေမှုအပေါ် အခြေခံသည်)။

### REST မှတစ်ဆင့် စီစဉ်သတ်မှတ်ခြင်း

```bash
# Integration token ကို သိမ်းဆည်းပြီး အတည်ပြုပါ (POST သည် စမ်းသပ်ရှာဖွေမှုတစ်ခု ပြုလုပ်ခြင်းဖြင့် အတည်ပြုသည်)
curl -X POST http://localhost:20128/api/settings/notion \
  -H "Content-Type: application/json" \
  -d '{"token":"ntn_xxx"}'

# ချိတ်ဆက်မှုအခြေအနေကို စစ်ဆေးပါ
curl http://localhost:20128/api/settings/notion

# ချိတ်ဆက်မှုဖြုတ်ပါ (သိမ်းဆည်းထားသော token ကို ရှင်းလင်းသည်)
curl -X DELETE http://localhost:20128/api/settings/notion
```

Method သုံးခုစလုံးသည် dashboard authentication (`isAuthenticated`) လိုအပ်သည်။ `POST` ပြုလုပ်ချိန်တွင်
OmniRoute သည် token ကို သိမ်းဆည်းပြီး ရလဒ် ၁ ခုပါ စမ်းသပ်ရှာဖွေမှုကို ချက်ချင်း လုပ်ဆောင်သည်။ Notion က error object တစ်ခု ပြန်ပေးပါက token ကို ရှင်းလင်းပြီး call သည် `400` ဖြင့် မအောင်မြင်ပါ။

## MCP tool များ (၆ ခု)

`open-sse/mcp-server/tools/notionTools.ts` တွင် သတ်မှတ်ထားသည်။ Token ကို call
ပြုလုပ်ချိန်တွင် `getNotionToken()` မှတစ်ဆင့် ရယူသည်။ စီစဉ်သတ်မှတ်ထားခြင်း မရှိပါက tool က
`"Notion integration token not configured. Set it in Settings > Context Sources."` ကို throw လုပ်သည်။

| Tool                         | Scope          | ဖော်ပြချက်                                                                                                                             |
| ---------------------------- | -------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `notion_search`              | `read:notion`  | စာသား query ဖြင့် page များနှင့် database များကို ရှာဖွေသည် (ခေါင်းစဉ်များ၊ ID များနှင့် URL များကို ပြန်ပေးသည်)။ Pagination ပါဝင်သည်။ |
| `notion_get_page`            | `read:notion`  | ID ဖြင့် page တစ်ခု၏ အကြောင်းအရာနှင့် metadata ကို ရယူသည်။                                                                             |
| `notion_list_block_children` | `read:notion`  | Block သို့မဟုတ် page တစ်ခု၏ block child အားလုံး (block tree) ကို စာရင်းပြုစုသည်။ Pagination ပါဝင်သည်။                                  |
| `notion_query_database`      | `read:notion`  | ရွေးချယ်နိုင်သော `filter` + `sorts` (Notion API format) ဖြင့် database တစ်ခုကို query လုပ်သည်။ Pagination ပါဝင်သည်။                    |
| `notion_get_database`        | `read:notion`  | ID ဖြင့် database တစ်ခု၏ schema/metadata ကို ရယူသည်။                                                                                   |
| `notion_append_blocks`       | `write:notion` | ရှိပြီးသား block သို့မဟုတ် page တစ်ခုသို့ block child များ ထပ်ဖြည့်သည် (request တစ်ခုလျှင် အများဆုံး block ၁၀၀)။                       |

### Input parameter များ

- `notion_search` — `query` (စာလုံးရေ ၁–၅၀၀), `pageSize` (၁–၁၀၀၊ မူလတန်ဖိုး ၂၀),
  `startCursor` (ရွေးချယ်နိုင်သည်)။
- `notion_get_page` — `pageId` (စာလုံးရေ ၃၂ လုံးရှိသော hex သို့မဟုတ် UUID)။
- `notion_list_block_children` — `blockId`, `pageSize` (၁–၁၀၀၊ မူလတန်ဖိုး ၅၀),
  `startCursor` (ရွေးချယ်နိုင်သည်)။
- `notion_query_database` — `databaseId`, `filter` (ရွေးချယ်နိုင်သည်၊ Notion filter format),
  `sorts` (ရွေးချယ်နိုင်သော array), `pageSize` (၁–၁၀၀၊ မူလတန်ဖိုး ၅၀), `startCursor` (ရွေးချယ်နိုင်သည်)။
- `notion_get_database` — `databaseId`။
- `notion_append_blocks` — `blockId`, `children` (block object များ၏ array),
  `after` (ရွေးချယ်နိုင်သော နေရာ)။

### Scope များ

ဖတ်ရှုရေး tool များသည် `read:notion` လိုအပ်ပြီး ရေးသားရေး tool သည် `write:notion` လိုအပ်သည်။
`OMNIROUTE_MCP_ENFORCE_SCOPES=true` ဖြစ်သည့်အခါမှသာ
`open-sse/mcp-server/server.ts` ရှိ `withScopeEnforcement()` က scope များကို မဖြစ်မနေ လိုက်နာစေသည်။ Call ပြုလုပ်သူ၏ ခွင့်ပြုထားသော scope များကို `OMNIROUTE_MCP_SCOPES` (ကော်မာဖြင့် ပိုင်းခြားထားသည်) သို့မဟုတ်
authentication ပြုလုပ်ထားသော API key ၏ scope context မှ ရယူသည်။ Scope model အပြည့်အစုံအတွက်
[MCP-SERVER.md](./MCP-SERVER.md) ကို ကြည့်ပါ။

## Endpoints

| နည်းလမ်း | Path                   | ရည်ရွယ်ချက်                                                   |
| -------- | ---------------------- | ------------------------------------------------------------- |
| `GET`    | `/api/settings/notion` | `{ connected, hasToken }` ကို ပြန်ပေးသည်။                     |
| `POST`   | `/api/settings/notion` | ပေါင်းစည်းမှု token ကို သိမ်းဆည်းပြီး အတည်ပြုသည်။             |
| `DELETE` | `/api/settings/notion` | ချိတ်ဆက်မှုဖြုတ်သည် (သိမ်းဆည်းထားသော token ကို ရှင်းလင်းသည်)။ |

> ဤအရာများသည် dashboard ဆက်တင်များအတွက် route များဖြစ်သည်။ အများသုံး `/v1` Notion proxy
> endpoint **မရှိပါ** — Notion ကို အထက်ပါ MCP tool များမှတစ်ဆင့်သာ သီးသန့် အသုံးပြုနိုင်သည်။

## အသုံးပြုမှုများ

- **အသိပညာအခြေပြု အဖြေများ** — အဖြေမပေးမီ agent တစ်ခုက workspace ကို `notion_search` လုပ်ပြီး
  ထိပ်ဆုံးရလဒ်ကို `notion_get_page` လုပ်စေခြင်းဖြင့် တုံ့ပြန်ချက်များတွင် အမှန်တကယ်ရှိသော အဖွဲ့တွင်းစာရွက်စာတမ်းများကို ကိုးကားနိုင်စေသည်။
- **Database အခြေပြု လုပ်ငန်းစဉ်များ** — filter များ + sort များဖြင့် tasks/CRM database တစ်ခုကို
  `notion_query_database` လုပ်ပြီးနောက် row များကို အကျဉ်းချုပ်ခြင်း သို့မဟုတ် ဦးစားပေးခွဲခြားခြင်း ပြုလုပ်သည်။
- **ပြန်လည်ရေးသားခြင်း / မှတ်တမ်းတင်ခြင်း** — အစည်းအဝေးမှတ်စုများ၊ လုပ်ဆောင်မှု
  အကျဉ်းချုပ်များ သို့မဟုတ် agent output ကို ရှိပြီးသား page တစ်ခုထဲသို့ ထပ်ဖြည့်ရန် `notion_append_blocks` ကို အသုံးပြုသည် (ထပ်ဖြည့်ခြင်းသာဖြစ်ပြီး ဖျက်ဆီးနိုင်သော ပြင်ဆင်မှုများ မရှိပါ)။
- **ဖွဲ့စည်းပုံ လေ့လာခြင်း** — page တစ်ခု၏ block tree တစ်လျှောက် ကြည့်ရှုရန်
  `notion_list_block_children` ကို အသုံးပြုခြင်း သို့မဟုတ် database တစ်ခုကို query မလုပ်မီ ၎င်း၏ property schema ကို ရှာဖွေသိရှိရန် `notion_get_database` ကို အသုံးပြုသည်။
