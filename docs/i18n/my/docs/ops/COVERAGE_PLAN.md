## စည်းမျဉ်းများ

- လွှမ်းခြုံမှု ရည်မှန်းချက်များသည် `tests/**` မဟုတ်ဘဲ ရင်းမြစ်ဖိုင်များနှင့် သက်ဆိုင်သည်။
- `open-sse/**` သည် ထုတ်ကုန်၏ အစိတ်အပိုင်းဖြစ်ပြီး အတိုင်းအတာအတွင်း ဆက်လက်ပါဝင်ရမည်။
- ကုဒ်အသစ်သည် ပြင်ဆင်ထိတွေ့ထားသော နေရာများ၏ လွှမ်းခြုံမှုကို မလျော့ကျစေသင့်ပါ။
- အကောင်အထည်ဖော်မှု အသေးစိတ်များကို စမ်းသပ်ခြင်းထက် အပြုအမူနှင့် အကိုင်းခွဲရလဒ်များကို စမ်းသပ်ခြင်းအား ဦးစားပေးပါ။
- `src/lib/db/**` အတွက် ကျယ်ပြန့်သော mock များထက် ယာယီ SQLite ဒေတာဘေ့စ်များနှင့် သေးငယ်သော fixture များကို ဦးစားပေးပါ။

## လက်ရှိ command အစု

- `npm run test:coverage`
  - unit test suite အတွက် အဓိက ရင်းမြစ်ကုဒ်လွှမ်းခြုံမှု စစ်ဆေးကန့်သတ်ချက်
  - `text-summary`၊ `html`၊ `json-summary` နှင့် `lcov` တို့ကို ထုတ်ပေးသည်
- `npm run coverage:report`
  - နောက်ဆုံး run မှ ဖိုင်တစ်ဖိုင်ချင်းစီအလိုက် အသေးစိတ်အစီရင်ခံစာ
- `npm run test:coverage:legacy`
  - သမိုင်းကြောင်းဆိုင်ရာ နှိုင်းယှဉ်မှုအတွက်သာ

## Ratchet မူဝါဒ

Project က နောက်ထပ် milestone ကို လုံလောက်သော အရန်အကွာအဝေးဖြင့် အမှန်တကယ် ကျော်လွန်ပြီးမှသာ `npm run test:coverage` threshold များကို အပ်ဒိတ်လုပ်ပါ။

**လက်ရှိ gate:** `npm run test:coverage` သည် **60 statements / 60 lines / 60 functions / 60 branches** ကို မဖြစ်မနေ သတ်မှတ်ထားသည် (Quality-Gates အဆင့် 6A.1 တွင် metric ကို baseline ပြန်လည်သတ်မှတ်ခဲ့သည် — ယခင် 82.58% baseline သည် test file များကို ထည့်တွက်ပြီး `open-sse` ကို ချန်လှပ်ထားသောကြောင့် အမှန်ထက် မြင့်တက်နေခဲ့သည်)။ `test:coverage:legacy` command သည် သမိုင်းကြောင်းဆိုင်ရာ နှိုင်းယှဉ်မှုအတွက် 50/50/50 metric အဟောင်းကို ဆက်လက်ထိန်းသိမ်းထားသည်။

နောက်ဆုံး report ကို အခြေခံ၍ လိုအပ်သလို threshold စစ်ဆေးမှုများ ပြုလုပ်ရန် အောက်ပါ command ကို အသုံးပြုပါ-

```bash
node scripts/check/test-report-summary.mjs --threshold 75
```

အကြံပြုထားသော ratchet အစဉ် (အစီအစဉ်မှာ `statements-lines / branches / functions` ဖြစ်သည်)-

1. 55/60/55
2. 60/62/58
3. 65/64/62
4. 70/66/66
5. 75/70/72 <-- လက်ရှိ gate (75/70/75)
6. 80/75/78
7. 85/80/84
8. 90/85/88

Branch coverage သည် နှစ်ကြိမ်ဆက်တိုက် run ရာတွင် 78% အထက်၌ တည်ငြိမ်နေပါက နောက်ထပ် ratchet ပစ်မှတ်မှာ `80/75/78` ဖြစ်သည်။

## သိရှိထားသော လစ်ဟာချက်

လက်ရှိ coverage command သည် ပင်မ Node unit suite ကို တိုင်းတာပြီး `open-sse` အပါအဝင် ၎င်းမှ ရောက်ရှိအသုံးပြုသော source များကို ထည့်သွင်းထားသည်။ Vitest coverage ကို တစ်ခုတည်းသော ပေါင်းစည်းထားသည့် report အဖြစ် မပေါင်းစည်းရသေးပါ။ ထိုသို့ ပေါင်းစည်းခြင်းကို နောင်တွင် လုပ်ဆောင်သင့်သော်လည်း 60% -> 80% သို့ မြှင့်တင်မှု စတင်ရန်အတွက် အတားအဆီးမဟုတ်ပါ။
