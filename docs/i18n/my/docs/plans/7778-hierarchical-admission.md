1. လက်ရှိ single-key semaphore contract နှင့် atomic multi-key contract အသစ်တို့ကို အဓိကထားသော စမ်းသပ်မှုများဖြင့် ခိုင်မာစွာ သတ်မှတ်ပါ- တစ်စိတ်တစ်ပိုင်း reservation မရှိခြင်း၊ FIFO queueing၊ abort၊ timeout၊ queue-full၊ idempotent release၊ stats နှင့် cleanup တို့ကို စမ်းသပ်ပါ။
2. လက်ရှိ account semaphore ကို မူလနေရာတွင်ပင် ယေဘုယျအသုံးပြုနိုင်အောင် ပြင်ဆင်ပါ။ `acquire()` ကို `acquireMany()` ကို ခေါ်သုံးသည့် compatibility wrapper အဖြစ် ဆက်လက်ထားရှိပါ။ ဒုတိယ scheduler သို့မဟုတ် dependency တစ်ခု မထည့်ပါနှင့်။
3. `chatCore` ရှိ account-only acquisition ကို `withRateLimit` မတိုင်မီ ချက်ချင်းလုပ်ဆောင်မည့် စုစည်းထားသော global/provider/account acquisition တစ်ခုဖြင့် အစားထိုးပါ။ account rotation ကြောင့် connection ပြောင်းလဲသည့်အခါတိုင်း set တစ်ခုလုံးကို ပြန်လည်ရယူပြီး streaming ပြီးဆုံးသည်အထိ release ကို ဆက်လက်ထိန်းသိမ်းထားပါ။
4. လက်ရှိ resilience settings pipeline (types၊ defaults၊ normalization၊ schema၊ API response၊ UI နှင့် translations) ကို global နှင့် provider caps များဖြင့် တိုးချဲ့ပါ။ ယခင် Bottleneck concurrency control ၏ အမှန်တကယ် scope ကို ရှင်းလင်းစေရန် connection/quota-scope concurrency ဟု label ပြန်တပ်ပါ။
5. အဓိကထားသော စမ်းသပ်မှုများ၊ lint၊ typecheck၊ static checks နှင့် test suite အပြည့်အစုံကို လုပ်ဆောင်ပါ။ ပြောင်းလဲသွားသော behavior ကို changelog တွင် မှတ်တမ်းတင်ပါ။

ရည်ရွယ်ချက်ရှိရှိ ဆက်လက်ထိန်းသိမ်းထားသော behavior- သုည/null concurrency သည် gate ကို ကျော်သွားခြင်း၊ account-only callers များက `acquire()` ကို ဆက်လက်အသုံးပြုခြင်း၊ blocked-account controls များ၏ key format နှင့် API ကို မပြောင်းလဲဘဲ ထိန်းသိမ်းထားခြင်းနှင့် provider rate-limit queue behavior ကို မပြောင်းလဲဘဲ ထားရှိခြင်း။
