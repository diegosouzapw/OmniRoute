တမ်းပလိတ်: xquik #11370 (release/v3.8.51 တွင် ပေါင်းစည်းထားသည်)။ အနေအထား: `fallbackOnly`။
Upstream အဆိုပြုချက်: issue diegosouzapw/OmniRoute#11637။

## 1. ဝန်ဆောင်မှု၏ အတည်ပြုထားသော အချက်အလက်များ (တရားဝင်စာရွက်စာတမ်းများဖြင့် အပြန်အလှန်စစ်ဆေးထားသည်)

- အခြေခံ URL: `https://api.anysearch.com` (REST) + `POST /mcp` (MCP၊ JSON-RPC 2.0)။
- `POST /v1/search` - ပါရာမီတာများ: `query` (မဖြစ်မနေလိုအပ်သည်)၊ `max_results` (1-10၊ မူလတန်ဖိုး 10)၊ `tag` (`{domain}.{sub_domain}` ဒေါင်လိုက်လမ်းကြောင်းခွဲခြားမှု)၊ `zone` (cn/intl)၊ `language`၊ `params` (ဖွဲ့စည်းပုံပါသော ဒေါင်လိုက်နယ်ပယ်ဆိုင်ရာ အကွက်များ)၊ `format` (json/markdown)။
- `GET /v1/sub-domains?domain=...` - လုပ်ဆောင်နိုင်စွမ်း ကက်တလောက်ဖြစ်ပြီး quota တွင် ထည့်တွက်ခြင်း မရှိပါ။
- `POST /v1/extract` - `{url, title, content}` ကို ရယူ/ထုတ်ယူသည်၊ တင်းကျပ်သော JSON body ဖြစ်ပြီး ကန့်သတ်ချက်မှာ 16 KiB ဖြစ်သည်။
- `POST /v1/auth/email/register` - တစ်ကြိမ်တည်းခေါ်ဆို၍ မှတ်ပုံတင်ခြင်းဖြစ်ပြီး တစ်ကြိမ်သာအသုံးပြုနိုင်သော plaintext key `as_sk_...` ကို ပြန်ပေးသည်။
- အထောက်အထားစိစစ်ခြင်း: `Authorization: Bearer <as_sk_...>` ကို ရွေးချယ်အသုံးပြုနိုင်သည်။ အမည်မသိအသုံးပြုမှုသည် နေ့စဉ်အခမဲ့ quota ကို သုံးစွဲသည့် IP တစ်ခုချင်းစီအလိုက် ကန့်သတ်ချက်များသို့ လျှော့ချသွားသည်။ မမှန်ကန်သော key သည် အသံတိတ် အမည်မသိ fallback မလုပ်ဘဲ 401/403 ကို ပြန်ပေးသည်။
- အခမဲ့အဆင့်: တစ်ရက်လျှင် တောင်းဆိုမှု 1000 ခု၊ key တစ်ခုလျှင် 20 QPS။ အခပေးအဆင့်: စျေးနှုန်းမသတ်မှတ်ရသေးပါ (မကြာမီ ရရှိနိုင်မည်)။
- တုံ့ပြန်မှု envelope: အောင်မြင်ပါက `{code: 0, message: "success", request_id, data}`၊ မအောင်မြင်ပါက `{code: -1, message}`။ အထောက်အထားစိစစ်ခြင်း/quota ဆိုင်ရာ အမှားများတွင် ဖွဲ့စည်းပုံပါသော `error_code` မပါရှိပါ (message စာသားသည် အချက်ပြမှုဖြစ်သည်)။ extract သီးသန့်အမှားများတွင်မူ `error_code` (`invalid_extract_url`, `extract_failed`) ပါရှိသည်။ 429 တွင် `Retry-After` header မပါရှိပါ။

## 3. ဆုံးဖြတ်ချက်များ (အားလုံးကို 2026-08-26 တွင် ချမှတ်ခဲ့သည်)

1. **Routing အနေအထား: `fallbackOnly`။** အကြောင်းပြချက်: ကုန်ကျစရိတ် 0 ဖြစ်သည့် အခမဲ့ provider သည် အလိုအလျောက် ကုန်ကျစရိတ်အခြေပြု routing ကို မည်သည့်အခါမျှ လွှမ်းမိုးမထားရပါ။ တိကျစွာ ရွေးချယ်ခြင်းနှင့် failover မှ ပြန်လည်ရောက်ရှိခြင်းတို့အပေါ် သက်ရောက်မှုမရှိပါ။ ရှေ့နမူနာ: merge လုပ်ထားသော xquik entry။
2. **နယ်ပယ်: v1 တွင် `POST /v1/extract` မှတစ်ဆင့် webSearch + webFetch။** tavily/exa ၏ capability နှစ်မျိုးပါ mental model နှင့် ကိုက်ညီသည်။ Vertical မျက်နှာပြင်များ (`tag`, `sub-domains`, `batch_search`) သည် နယ်ပယ်ပြင်ပတွင် ဆက်ရှိမည် — လက်ရှိတွင် vertical params အတွက် IR မရှိပါ။
3. **Quota ပြသမှု: `freeMonthlyQuota: 0`** (xquik ပုံစံ အကဲဖြတ်မှုကို ထိန်းသိမ်းထားသော ပြသမှု)။ အမှန်တကယ်ရရှိနိုင်သည့် ပမာဏ (တစ်ရက်လျှင် request 1000 ခု၊ နေ့စဉ် reset) ကို ယင်းအစား UI catalog ၏ `authHint` စာသားတွင် ထည့်သွင်းထားသည်။ အကြောင်းပြချက်: quota ပြသမှုသည် reset semantics နှင့် ကိုက်ညီရမည်။ နေ့စဉ်ကန့်သတ်ချက်ကို လစဉ်နှင့်ညီမျှသော ပမာဏ (30000) အဖြစ် ပြောင်းလဲခြင်းသည် UI က အာမခံမပေးနိုင်သော မှားယွင်းသည့် ကတိတစ်ခုဖြစ်သည်။
4. **searchTypes: `["web"]` သာ။** AnySearch API တွင် news/images vertical ရှိကြောင်း အများပြည်သူကြည့်ရှုနိုင်သည့် အထောက်အထားမရှိပါ။ မှတ်တမ်းတင်ထားသော vertical မရှိသည့် API များကို ပေါင်းစည်းသော gateway များ (ဥပမာ Google Custom Search) သည် news -> web ဟု တိတ်တဆိတ် mapping မလုပ်ဘဲ web ကိုသာ ဖော်ထုတ်ပေးသည်။
5. **Key အနေအထား:** key မပါဘဲ အလုပ်လုပ်သည်။ မမှန်ကန်သော key သည် 401/403 ကို ပြန်ပေးပြီး anonymous အဖြစ် မည်သည့်အခါမျှ တိတ်တဆိတ် downgrade မလုပ်ပါ (upstream contract ကို ထင်ဟပ်သည်)။
6. **ရည်ရွယ်ချက်ရှိရှိ ချန်လှပ်ထားမှုများ:** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (chat interception ကို firecrawl/jina/tavily အဖြစ် ဆက်ထားမည်)၊ `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (anonymous remote endpoint များသည် egress IP တစ်ခုစီအလိုက် IP ကန့်သတ်ထားသော pool တစ်ခုကို မျှဝေသုံးစွဲသောကြောင့် keyless extract သည် opt-in ဖြစ်ပြီး auto-routing candidate မဟုတ်ပါ)၊ `QUOTA_STATUS_PROVIDERS` (AnySearch သည် quota ကို 402/403 status ဖြင့်မဟုတ်ဘဲ 429/envelope မှတစ်ဆင့် အချက်ပြသည်)။

## 4. ကိုးကားချက်များ

- xquik template: commit a0ceccc၊ PR #11370 (release/v3.8.51 တွင် in-tree ဖြစ်သည်)။
- AnySearch တရားဝင် docs: https://anysearch.com/docs၊ https://anysearch.com/pricing; MCP catalog mcpservers.org/servers/anysearch-ai/anysearch-mcp-server; skill repo github.com/anysearch-ai/anysearch-skill။
- လုပ်ငန်းနယ်ပယ် mental model: LiteLLM search docs (registry + ပေါင်းစည်းထားသော search() + Perplexity-spec IR)၊ open-webui web search (built-in provider များ၊ search_web/fetch_url tool နှစ်မျိုး)၊ Dify tool plugin pattern; ကုန်ကျစရိတ်အခြေပြု fallback အဆင့်ဆင့်: self-hosted -> အခမဲ့ quota -> အခပေး။
