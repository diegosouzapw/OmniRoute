> **အသုံးပြုသူများအတွက်**: ရိုးရှင်းသော လမ်းညွှန်ကို ရှာနေပါသလား။ အခမဲ့ AI ရယူရန် အဆင့်ဆင့်ညွှန်ကြားချက်များအတွက် [အခမဲ့အဆင့် လမ်းညွှန်](../getting-started/FREE-TIERS-GUIDE.md) ကို ကြည့်ပါ။

> **နောက်ဆုံး သုတေသနပြုခဲ့သည့်ရက်:** 2026-06-17 — အခမဲ့အဆင့် quota နှင့် ToS တိုင်းကို အပ်ဒိတ်လုပ်ရန် ဝန်ဆောင်မှုပေးသူတစ်ခုချင်းအလိုက် ဝဘ်သုတေသန (တရားဝင်စာရွက်စာတမ်းများ + နောက်ဆုံး 7 ရက်အတွင်း သတင်းများ၊ ဆန့်ကျင်ဘက်ရှုထောင့်မှ အတည်ပြုစစ်ဆေးသည့် agent 50 ခုဖြင့် စိစစ်မှု)။ **တစ်စိတ်တစ်ပိုင်း ပြန်လည်စစ်ဆေးမှု 2026-09-02** (`gemini`, `ollama-cloud`, `groq`, `nara`, `mistral` — အောက်ရှိ ရက်စွဲတပ်ထားသော မှတ်ချက်ကို ကြည့်ပါ)။
> **တရားဝင်အခြေခံရင်းမြစ် (ကတ်တလောက်):** `open-sse/config/freeModelCatalog.ts` (MODEL တစ်ခုချင်းအလိုက် ဘတ်ဂျက်များ၊ ထပ်နေသော pool များကို ဖယ်ထားသည်)။ အောက်ပါ token ဘတ်ဂျက်ကိန်းဂဏန်းများသည် လက်ရှိ ဝဘ်သုတေသနမှ ရရှိပြီး **အနီးစပ်ဆုံး ခန့်မှန်းချက်** ဖြစ်သည် — [နည်းလမ်းနှင့် သတိပြုရန်အချက်များ](#methodology--caveats) ကို ကြည့်ပါ။

> **ယခင် ~1.94B မှ လျော့ကျသွားရသည့် အကြောင်းရင်း။** 2026-06-17 ပြန်လည်မွမ်းမံမှုသည် ဆုံးရှုံးမှုမဟုတ်ဘဲ အချက်အလက်မှန်ကန်မှုအတွက် ပြင်ဆင်ခြင်းဖြစ်သည်။ `gemini` ကို ယခု pool အလိုက် ထပ်နေမှုဖယ်ရှားတွက်ချက်ထားသည် (ယခင်က Flash မူကွဲတစ်ခုစီကို သီးခြားရေတွက်ခဲ့သဖြင့် 462M → 60M အထိ ပိုများနေခဲ့သည်)၊ `cloudflare-ai` ကို ၎င်း၏ အမှန်တကယ် 10k-Neurons/day အဖြစ် ပြင်ဆင်ခဲ့သည် (122M → 30M)၊ `doubao` ကို ထပ်တလဲလဲရရှိသော ခွဲတမ်းမဟုတ်ဘဲ အကောင့်ဖွင့်ချိန် တစ်ကြိမ်သာရရှိသော credit အဖြစ် ပြန်လည်အမျိုးအစားခွဲခဲ့ပြီး၊ ပိတ်သိမ်းလိုက်သော အဆင့်များကို ဖယ်ရှားခဲ့သည် (`chutes`/`phind`/`kluster` တို့ ရပ်ဆိုင်းသွားပြီ)။ ယင်းလျော့ကျမှုကို `llm7` (မှန်ကန်သော 5M/day → 150M) နှင့် အခမဲ့ provider အသစ်များ (Kilo၊ OpenCode Zen၊ Z.AI GLM-Flash) က တစ်စိတ်တစ်ပိုင်း ပြန်လည်ဖြည့်ဆည်းပေးထားသည်။

> အောက်ဘက်ရှိ ပံ့ပိုးသူတစ်ဦးချင်းစီအလိုက် အသေးစိတ်ဇယားသည် **2026-06-05 snapshot** ဖြစ်ပြီး အထက်ပါ ပြောင်းလဲချက်များက ၎င်းကို အစားထိုးလွှမ်းမိုးသည်။ လက်ရှိအသုံးပြုနေသော စံကိုးကားရင်းမြစ်မှာ မော်ဒယ်တစ်ခုချင်းစီအလိုက် ကတ်တလောက် `open-sse/config/freeModelCatalog.ts` ဖြစ်သည်။

## နည်းလမ်းနှင့် သတိပြုရန်အချက်များ

- ကိန်းဂဏန်းများသည် ဝဘ်သုတေသနဖြင့် စုဆောင်းထားသော၊ **2026-06-17** ရက်နေ့အထိ ဝန်ဆောင်မှုပေးသူတစ်ဦးချင်းစီ၏ မှတ်တမ်းတင်ဖော်ပြထားသည့် အခမဲ့အဆင့် ကန့်သတ်ချက်များမှ **ဖြစ်နိုင်သည့် အမြင့်ဆုံးပမာဏ ခန့်မှန်းချက်များ** ဖြစ်သည်။ အခမဲ့အဆင့်များသည် အမြဲတမ်း ပြောင်းလဲနေသောကြောင့် ကိန်းဂဏန်းတစ်ခုကို အားကိုးအသုံးမပြုမီ ပြန်လည်အတည်ပြုပါ။
- **အချက်အလက်တစ်ခုက အမှန်တကယ် အာမခံသည့်အရာ။** အချက်အလက်တစ်ခုချင်းစီတွင် သီးခြားယုံကြည်နိုင်မှု အဆင့်သတ်မှတ်ချက် မပါဝင်သကဲ့သို့ API ကလည်း ယင်းအဆင့်သတ်မှတ်ချက်ကို မပေးပါ — အထက်ပါကိန်းဂဏန်းတိုင်းကို တူညီသော်လည်း ထုတ်ဖော်မထားသော အရည်အသွေးရှိသည့် ခန့်မှန်းချက်များအဖြစ် သတ်မှတ်ပါ။ သို့သော် လက်ဖြင့် စုစည်းထားခြင်းဖြစ်ပြီး ခန့်မှန်းကောက်ချက်ချထားခြင်း မဟုတ်သောကြောင့် အချက်နှစ်ချက်မှာ ကွဲပြားသည်။ အချက်အလက် 44 ခုတွင် သီးခြားမှတ်တမ်းတင်ထားသော အတိအကျ ရပ်တန့်မှု ပါဝင်သည် (၎င်းတို့ထဲမှ 39 ခုသည် xKiro အတန်းများဖြစ်ပြီး နေ့စဉ်ခွင့်ပြုပမာဏ တစ်ခုတည်းကို မျှဝေသုံးစွဲသည်)၊ အချက်အလက် 13 ခုတွင် prompt-training ထုတ်ဖော်ချက် ပါဝင်သည်။ အခမဲ့ခွင့်ပြုပမာဏကို ကျော်လွန်သည့်အခါ သင့်အား အသိမပေးဘဲ ငွေစတင်ကောက်ခံခြင်းအစား တောင်းဆိုချက်ကို ငြင်းပယ်မည်ဟု ဝန်ဆောင်မှုပေးသူ၏ ကိုယ်ပိုင်စည်းမျဉ်းများတွင် ဖော်ပြထားမှသာ `hardStopGuaranteed` ကို သတ်မှတ်ပြီး၊ အရင်းအမြစ်ကိုလည်း သက်ဆိုင်ရာအချက်အလက်ဘေးရှိ မှတ်ချက်တွင် ထည့်သွင်းထားသည်။ ၎င်းကို မည်သည့်အခါမျှ ပုံသေအဖြစ် `true` မသတ်မှတ်ဘဲ မည်သူမျှ မစစ်ဆေးရသေးသော အချက်အလက်တွင် သတ်မှတ်မထားဘဲ ထားရှိသည်။ ထို့ကြောင့် အတိအကျ ရပ်တန့်မှု အလံမရှိခြင်းသည် "အတည်မပြုရသေး" ဟု ဆိုလိုပြီး "သင့်အား ငွေကောက်ခံမည်ဟု သိထားသည်" ဟု မဆိုလိုပါ။ **STRICT မုဒ်** (ရွေးချယ်ဖွင့်နိုင်သော `freeAccessPolicy=strict` လမ်းကြောင်းရွေးချယ်မှု အကာအကွယ်) သည် အဆိုပါအလံပါရှိသည့် အချက်အလက်များကိုသာ ယုံကြည်သည်။ အခြားအခမဲ့အဆင့်အားလုံးကို `no-hard-stop` အဖြစ် ဖယ်ထုတ်သည် (`open-sse/services/autoCombo/strictZeroCostFilter.ts` ကို ကြည့်ပါ)။ အကာအကွယ်က pool တစ်ခုကို စစ်ထုတ်သည့်အခါ အော်ပရေတာမြင်နိုင်သော မှတ်တမ်းတွင် ဖယ်ထုတ်ထားသည့် အရေအတွက်နှင့် ၎င်းအတွင်းရှိ `no-hard-stop` အချိုးကို နှစ်ခုစလုံး ဖော်ပြသည်။
- `estMonthlyFreeTokens` = လစဉ် ပြန်လည်ရရှိသော token များသာ။ **အကောင့်ဖွင့်ချိန် တစ်ကြိမ်တည်းရရှိသော credit များသည် ပြန်လည်မရရှိပါ**၊ ထို့ကြောင့် 0 အဖြစ် ရေတွက်သည်။ ရပ်ဆိုင်းလိုက်သော အဆင့်များကိုလည်း 0 အဖြစ် ရေတွက်သည်။
- နေ့စဉ် token အများဆုံးပမာဏ → `monthly = daily × 30`။ RPD ကိုသာ မှတ်တမ်းတင်ထားပါက → `RPD × ~800 output tokens × 30`။ RPM/TPM သာရှိပြီး နေ့စဉ်အများဆုံးပမာဏ မရှိပါက → **အများဆုံးပမာဏ မကန့်သတ်ထား** (အောက်တွင် ကြည့်ပါ)။
- **အမြဲတမ်း အခမဲ့ဖြစ်သော်လည်း ထုတ်ပြန်ထားသော token အများဆုံးပမာဏ မရှိသည့် ဝန်ဆောင်မှုများ** (`siliconflow`, `glm-cn`, `tencent`, `baidu`, `kilo-gateway`, `opencode-zen`, `gemini`, `ollama-cloud`) — ၎င်းတို့သည် အမှန်တကယ် ထပ်တလဲလဲရရှိနိုင်သော အခမဲ့အသုံးပြုခွင့်များဖြစ်ပြီး နှုန်းထား/တစ်ပြိုင်နက်အသုံးပြုမှုဖြင့် ကန့်သတ်ထားသည်။ ၎င်းတို့ကို `recurring-uncapped` ဟု အမျိုးအစားခွဲပြီး **မည်သည့်အခါမျှ စုစုပေါင်းထဲ မထည့်ပါ** — `RPM × 24/7 × 30d` ဟု မြှောက်ခြင်းသည် လက်တွေ့မကျသော အမြင့်ဆုံးပမာဏကို ရရှိစေမည်ဖြစ်ပြီး၊ ယင်းကဲ့သို့ ဖောင်းပွတွက်ချက်မှုကို ကျွန်ုပ်တို့ လက်မခံပါ။ ယင်းဝန်ဆောင်မှုများ ရှိကြောင်း သိရှိနိုင်ရန် စာရင်းတွင် ထည့်သွင်းထားသည်။
- **ငွေသွင်းခြင်းဖြင့် ဖွင့်ပေးသည့် တိုးမြှင့်မှု:** တစ်ကြိမ်တည်း ငွေပမာဏအနည်းငယ် ထပ်ဖြည့်ခြင်းဖြင့် အခမဲ့ခွဲတမ်းကို အမြဲတမ်းတိုးပေးသည် (OpenRouter: $10 → 1000 req/day ≈ +24M/mo)။ ၎င်းကို သီးခြားကိန်းဂဏန်းအဖြစ် တင်ပြပြီး ပုံမှန်အကျဉ်းချုပ်ကိန်းဂဏန်းထဲ မထည့်ပါ။
- **အရည်အချင်းပြည့်မီမှုဖြင့် ကန့်သတ်ထားသော ခွဲတမ်းများ** (`eligibilityGate: "regional-identity"`) — ဒေသနှင့်ဆက်စပ်သော ကိုယ်ရေးအထောက်အထား စစ်ဆေးမှု ပြီးဆုံးမှသာ ဖွင့်ပေးသည့် အမှန်တကယ် ထပ်တလဲလဲရရှိနိုင်သော ခွဲတမ်းဖြစ်သည် (လက်ရှိတွင် တရုတ်ပြည်မကြီး၏ အမည်ရင်းအတည်ပြုခြင်း)။ တူညီသော pool-dedupe စည်းမျဉ်းဖြင့် သီးခြားကိန်းဂဏန်း (`gatedRecurringTokens`) ထဲတွင် ရေတွက်ပြီး ပုံမှန်အကျဉ်းချုပ်ကိန်းဂဏန်းထဲသို့ မည်သည့်အခါမျှ မထည့်ပါ။ စနစ်အမျိုးအစား (`freeType`) မပြောင်းလဲသဖြင့် လမ်းကြောင်းရွေးချယ်မှုလည်း မပြောင်းလဲပါ။
- **အထောက်အထား အမျိုးအစားများ။** စည်းမျဉ်းမှာ catalog ထဲရှိ ကိန်းဂဏန်းတစ်ခု၏ အရင်းအမြစ်ကို သက်ဆိုင်ရာအချက်အလက်ဘေးရှိ `// evidence:` မှတ်ချက်တွင် ကိုးကားဖော်ပြရမည် — `public-page` (မည်သူမဆို ဖတ်ရှုနိုင်သော ဝန်ဆောင်မှုပေးသူ၏ စာမျက်နှာ)၊ `api-public` (အထောက်အထားစိစစ်ဝင်ရောက်ရန် မလိုသော ဝန်ဆောင်မှုပေးသူ၏ endpoint၊ ဥပမာ router.bynara.id ရှိ NaraRouter ၏ အများသုံး plans endpoint)၊ သို့မဟုတ် `console-verified <date> por <who>` (ကိန်းဂဏန်းကို အကောင့် console အတွင်း၌သာ မြင်နိုင်သည်။ မှတ်ချက်တွင် ၎င်းကို မည်သူက မည်သည့်အချိန်တွင် မြင်ခဲ့ကြောင်းနှင့် အများဆုံးပမာဏရှိကြောင်း ဖော်ပြထားသည့် အများသုံးစာမျက်နှာကို မှတ်တမ်းတင်ထားသည်) ဖြစ်သည်။ လက်ရှိအခြေအနေအရ 2026-09-02 တွင် ပြန်လည်စစ်ဆေးထားသော block ငါးခု (`gemini`, `groq`, `mistral`, `ollama-cloud`, `nara`) တွင် ယင်းအထောက်အထား ပါဝင်သည်။ 2026-09-02 ပြန်လည်စစ်ဆေးမှုမတိုင်မီကတည်းက ရှိနေသော အချက်အလက်များသည် ပြင်ဆင်မွမ်းမံသည့်အချိန်အထိ အစောပိုင်းသုတေသနကို ဆက်လက်အမွေဆက်ခံထားသည်။ အထောက်အထားမှတ်ချက်မပါဘဲ **အသစ်ထည့်သွင်းသော သို့မဟုတ် ပြောင်းလဲထားသော** ကိန်းဂဏန်းတိုင်းသည် bug တစ်ခုဖြစ်သည်။ လက်ရှိတွင် `mistral` တစ်ခုတည်းသာ console ဖြင့် အတည်ပြုထားသည်။

## ကျွန်ုပ်တို့၏ အရေအတွက်က အခြား aggregator များထက် ဘာကြောင့် နည်းရသနည်း

ဤနယ်ပယ်ရှိ "တစ်လလျှင် အခမဲ့ token များ" ကိန်းဂဏန်းအများစုသည် model တစ်ခုချင်းစီအလိုက် ဖော်ပြထားသော ပမာဏများကို ပေါင်းထားခြင်းဖြစ်သည်။ ကျွန်ုပ်တို့၏ ကိန်းဂဏန်းမှာ ရည်ရွယ်ချက်ရှိရှိ ထိုသို့ ပေါင်းထားခြင်းမဟုတ်ပါ-

- **မျှဝေသုံးစွဲသည့် pool တစ်ခုစီကို တစ်ကြိမ်သာ ရေတွက်ထားသည်။** Mistral ၏ အခမဲ့အစီအစဉ်သည် organization တစ်ခုလျှင် တစ်လ 1B ရရှိသည့် allowance တစ်ခုဖြစ်သည်။ ၎င်းကို model ငါးခုအောက်တွင် စာရင်းပြုစုထားရုံဖြင့် 5B ဖြစ်သွားမည်မဟုတ်ပါ။ Model တစ်ခုချင်းစီအလိုက် ပေါင်းလျှင် ကျွန်ုပ်တို့၏ ကိုယ်ပိုင် catalog သည် **~7.4B** ဟု ဖော်ပြမည်ဖြစ်သည် (2026-09-03 တွင် ပြန်လည်တွက်ချက်ထားသည်၊ ဤကိန်းဂဏန်းကို CI ဖြင့် စစ်ဆေးတားဆီးထားခြင်းမရှိသောကြောင့် catalog ပြောင်းလဲတိုင်း ပြန်လည်တိုင်းတာပါ) — ခေါင်းစီးတွင် **~1.47B** ဟု ဖော်ပြထားခြင်းမှာ provider တစ်ခုစီ၏ account တစ်ခုက အမှန်တကယ် သုံးစွဲနိုင်သည့် ပမာဏဖြစ်သောကြောင့် ဖြစ်သည်။
- **နေ့စဉ်ကန့်သတ်ချက်များကို ပြောင်းလဲတွက်ချက်သော်လည်း rate များကို မပြောင်းလဲတွက်ချက်ပါ။** မှတ်တမ်းတင်ထားသော tokens/day ကန့်သတ်ချက်ကို `× 30` ဖြင့် တွက်ချက်သည်။ မှတ်တမ်းတင်ထားသော requests/day ကန့်သတ်ချက်ကို `RPD × ~800 tokens × 30` ဖြင့် တွက်ချက်သည်။ requests-per-minute ကိုသာ ထုတ်ပြန်ထားသော provider တွင် လစဉ်ကိန်းဂဏန်း **မရှိ** သဖြင့် _uncapped_ ဟု စာရင်းသွင်းပြီး မည်သည့်အခါမျှ စုစုပေါင်းထဲ မပေါင်းပါ။ Rate limit ကို 24/7 ဖြင့် မြှောက်၍ ကိန်းဂဏန်းဖောင်းပွစေခြင်းကို ကျွန်ုပ်တို့ လက်မခံပါ။
- **ဒေသဆိုင်ရာ identity စစ်ဆေးမှုနောက်ကွယ်ရှိ quota များကို သီးခြားဖော်ပြထားသည်** (`+~6M behind regional identity verification`)၊ အဘယ်ကြောင့်ဆိုသော် စာဖတ်သူအများစုက ၎င်းတို့ကို အသုံးမပြုနိုင်သောကြောင့်ဖြစ်သည်။
- **Signup credit များသည် ပထမလအတွက်သာ ဖြစ်ပြီး** ပုံမှန်ရရှိသည့် ကိန်းဂဏန်းထဲ မည်သည့်အခါမျှ ရောနှောမထည့်ဘဲ ဒုတိယကိန်းဂဏန်းအဖြစ် ဖော်ပြထားသည်။
- **ဤကိန်းဂဏန်းကို CI ဖြင့် မဖြစ်မနေ ကိုက်ညီစေထားသည်။** `npm run check:docs-counts` သည် catalog မှ စုစုပေါင်းများကို ပြန်လည်တွက်ချက်ပြီး ဤဖိုင်၊ README သို့မဟုတ် budget card တို့နှင့် မကိုက်ညီပါက build ကို မအောင်မြင်စေပါ။

## ToS သတိပြုရန် ဇယား

> **ToS flag သည် အကြံပြုအသိပေးချက်သာဖြစ်ပြီး routing gate မဟုတ်ပါ။** `tos` ဟု မှတ်သားထားသော provider များကိုလည်း ပုံမှန်အားဖြင့် routing နှင့် combo/fallback တို့တွင် ဆက်လက်ထည့်သွင်းထားသည်။ Flag ကို `/dashboard/free-tiers` နှင့် `/api/free-tier/summary` တို့တွင်သာ ဖော်ပြသည်။ `excludeTosAvoid` query parameter သည် summary view ကိုသာ သက်ရောက်ပြီး global routing ကို မသက်ရောက်ပါ။ ဆုံးဖြတ်ချက်ကို `open-sse/config/freeTierCatalog.ts` တွင် သိမ်းဆည်းထားသည် (သတင်းအချက်အလက်အတွက်သာဖြစ်ပြီး routing engine များက ဖတ်ရှုခြင်းမရှိပါ)။

> ကိုယ်တိုင် host လုပ်ထားသော single-user personal proxy တစ်ခုအတွက် provider တစ်ခုစီ၏ စည်းမျဉ်းများကို အမြန်သုံးသပ်ထားခြင်းဖြစ်သည်။ `caution` = စစ်ဆေးသင့်သည့် personal-use သို့မဟုတ် proxy ဆိုင်ရာ စည်းကမ်းချက်၊ `ambiguous` = မရှင်းလင်း၊ `ok` = ပြတ်သားစွာ ခွင့်ပြုထားသည်။ သတင်းအချက်အလက်အတွက်သာဖြစ်ပြီး ဥပဒေအကြံဉာဏ်မဟုတ်ပါ — သင်ကိုယ်တိုင် ဆုံးဖြတ်ရမည်။

## OpenCode Free: client-contract ကန့်သတ်ချက် (#14313)

သော့မလိုအပ်သော `opencode` provider (အများသုံး `https://opencode.ai/zen/v1`) သည် OpenCode client contract နှင့် မကိုက်ညီသည့် မည်သည့် request ကိုမဆို **403 `FreeTierError`** နှင့် _"OpenCode ၏ အခမဲ့အဆင့်ကို OpenCode အတွင်းမှသာ အသုံးပြုနိုင်သည်"_ ဟူသော စာကြောင်းဖြင့် ငြင်းပယ်သည်။ ၎င်းသည် request အလိုက် သတ်မှတ်သော ငြင်းပယ်မှု (တူညီသော request ပုံစံအတွက် account တိုင်းတွင် တူညီသော ဆုံးဖြတ်ချက်) ဖြစ်ပြီး model ပိတ်ပင်မှု သို့မဟုတ် connection cooldown မဟုတ်ပါ — OmniRoute က ၎င်းကို `project_route_error` အဖြစ် အမျိုးအစားခွဲခြား၍ model lockout / cooldown ကို ကျော်သွားပြီး (`noauth` အတု path တွင်) auto-combo ပြန်လည်ရွေးချယ်မှုကို TTL အချိန်တိုတစ်ခုအတွက် ခေတ္တရပ်ထားသည်။ ဗလာမဟုတ်သော tool စာရင်း၊ `stream: true` နှင့် OpenCode session/UA headers (`opencodeFreeTierContract.ts`) ပါဝင်သည့် request များကို ပေးပို့ပါ၊ မဟုတ်ပါက 403 ရရှိမည်ဟု မျှော်လင့်ထားပါ။
