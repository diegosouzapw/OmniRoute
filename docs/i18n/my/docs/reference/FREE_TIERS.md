> **အသုံးပြုသူများအတွက်**: ရိုးရှင်းသော လမ်းညွှန်ကို ရှာနေပါသလား။ အခမဲ့ AI ရယူရန် အဆင့်ဆင့်ညွှန်ကြားချက်များအတွက် [အခမဲ့အဆင့်များ လမ်းညွှန်](../getting-started/FREE-TIERS-GUIDE.md) ကို ကြည့်ပါ။

> **နောက်ဆုံး သုတေသနပြုထားသည့်ရက်:** 2026-06-17 — အခမဲ့အဆင့် quota နှင့် ToS တိုင်းကို အသစ်ပြန်လည်စစ်ဆေးထားသော ဝန်ဆောင်မှုပေးသူတစ်ဦးချင်းစီအလိုက် ဝဘ်သုတေသန (တရားဝင်စာရွက်စာတမ်းများ + နောက်ဆုံး 7 ရက်အတွင်း သတင်းများ၊ ဆန့်ကျင်ဘက်အမြင်ဖြင့် အတည်ပြုစစ်ဆေးသည့် agent 50 ခုပါ pass)။ **2026-09-02 တွင် တစ်စိတ်တစ်ပိုင်း ပြန်လည်စစ်ဆေးခဲ့သည်** (`gemini`, `ollama-cloud`, `groq`, `nara`, `mistral` — အောက်ရှိ ရက်စွဲပါမှတ်ချက်ကို ကြည့်ပါ)။
> **အမှန်တရား၏ မူရင်းရင်းမြစ် (catalog):** `open-sse/config/freeModelCatalog.ts` (MODEL တစ်ခုချင်းစီအလိုက် budget များ၊ pool ထပ်နေမှုများကို ဖယ်ရှားထားသည်)။ အောက်ပါ token-budget ကိန်းဂဏန်းများသည် လက်ရှိ ဝဘ်သုတေသနမှ ရရှိထားပြီး **ခန့်မှန်းချက်** တစ်ခုသာဖြစ်သည် — [နည်းလမ်းနှင့် သတိပြုရန်အချက်များ](#methodology--caveats) ကို ကြည့်ပါ။

## TL;DR — OmniRoute က အခမဲ့ inference မည်မျှကို အမှန်တကယ် စုစည်းပေးသနည်း။

| မက်ထရစ်                                                  | တစ်လလျှင် Tokens  | အဓိပ္ပာယ်                                                                                                                                                                                                                                                                                                                                                                     |
| -------------------------------------------------------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **မှတ်တမ်းတင်ထားသော ထပ်တလဲလဲရရှိသည့် ခွဲတမ်း (ပုံမှန်)** | **~1.62B**        | အခမဲ့အဆင့် **pools** (မော်ဒယ်တစ်ခုချင်းအလိုက် catalog) ဖြစ်ပြီး မျှဝေထားသော pool တစ်ခုစီကို **တစ်ကြိမ်သာ** ရေတွက်ထားသည်။ `/api/free-tier/summary` နှင့် dashboard ၏ Free-Tier Budget စာမျက်နှာနောက်ကွယ်ရှိ လက်ရှိ source ဖြစ်သည်။ **ဤကိန်းဂဏန်းကို အသုံးပြုပါ။**                                                                                                              |
| **+ စာရင်းသွင်းခ credits ပါဝင်သည့် ပထမလ**                | **~2.22B**        | ပုံမှန်ခွဲတမ်း + တစ်ကြိမ်သာရသည့် စာရင်းသွင်းခ credits (Z.AI 20M၊ DeepSeek 5M၊ …) ဖြစ်ပြီး account တစ်ခုစီအလိုက် ထပ်နေမှုများကို ဖယ်ရှားထားသည်။ **ပထမလအတွက်သာ** — ထပ်မံမရရှိပါ။                                                                                                                                                                                                |
| **+ အမြဲတမ်းအခမဲ့၊ ထုတ်ပြန်ထားသော ကန့်သတ်ချက်မရှိ**      | _ပမာဏတွက်ချက်၍မရ_ | `siliconflow`, `glm-cn` (GLM-4-Flash), `tencent`, `baidu`, `kilo-gateway`, `opencode-zen`, `gemini`, `ollama-cloud` — အမှန်တကယ် ထပ်တလဲလဲ အသုံးပြုနိုင်ပြီး rate/concurrency ကန့်သတ်ထားသော်လည်း **ရေတွက်နိုင်သည့် token ကန့်သတ်ချက် မရှိပါ**။ စာရင်းတွင် ဖော်ပြသော်လည်း ပေါင်းမတွက်ပါ (`RPM×24/7` ဖြင့် ရေတွက်ခြင်းသည် ကျွန်ုပ်တို့ လက်မခံသည့် ကိန်းဂဏန်းဖောင်းပွမှု ဖြစ်သည်)။ |
| **+ deposit ဖြင့် unlock လုပ်သည့် အပိုခွဲတမ်း**          | **+~24M**         | OpenRouter တွင် တစ်ကြိမ်သာ **$10** top-up လုပ်ခြင်းဖြင့် ၎င်း၏ အခမဲ့ pool ကို 50 → 1000 req/day အထိ တိုးပေးသည်။ ပုံမှန်ကိန်းဂဏန်းကို လုံးဝ မဖောင်းပွစေရန် သီးခြားဖော်ပြထားသည်။                                                                                                                                                                                                |
| **+ ဒေသဆိုင်ရာ identity check နောက်ကွယ်ရှိ ခွဲတမ်း**     | **+~6M**          | `modelscope` (Alibaba Cloud ချိတ်ဆက်မှု + တရုတ်ပြည်မကြီး real-name verification)။ အမှန်တကယ် ထပ်တလဲလဲရသည့် quota ဖြစ်ပြီး `gatedRecurringTokens` / `gatedProviders` အဖြစ်နှင့် dashboard ပေါ်တွင် ဖော်ပြထားသည်။ အဓိကကိန်းဂဏန်းထဲသို့ လုံးဝ ပေါင်းမထည့်ပါ — ဒေသဆိုင်ရာ identity verification နောက်ကွယ်တွင် +~6M ရှိသည်။                                                         |
| သီအိုရီအရ အမြင့်ဆုံးပမာဏ (rate limit အားလုံး၊ 24/7)      | ~10B              | Provider တိုင်း၏ rate limit ကို မရပ်မနားအသုံးပြုမှုအဖြစ် ချဲ့တွက်ထားသော စုစုပေါင်း။ **အာမခံချက်မဟုတ်ပါ** — ၎င်းကို ခေါင်းစီးအဖြစ် မသုံးပါနှင့်။                                                                                                                                                                                                                               |

**ရိုးသားသော ခေါင်းစီး:** _OmniRoute သည် အခမဲ့အဆင့် pool 35 ခုမှတစ်ဆင့် တစ်လလျှင် **~1.62B မှတ်တမ်းတင်ထားသော အခမဲ့ tokens** ကို စုစည်းပေးသည် (စာရင်းသွင်းခ credits ပါဝင်ပါက ပထမလတွင် ~2.22B အထိ) — ထို့အပြင် အမြဲတမ်းအခမဲ့ဖြစ်ပြီး အမြင့်ဆုံးကန့်သတ်ချက်မရှိသော providers အများအပြားလည်း ပါဝင်ကာ RTK + Caveman compression (token သုံးစွဲမှု 15–95% ချွေတာခြင်း) က ယင်းပမာဏကို ပိုမိုအသုံးခံစေသည်။_

> **ယခင် ~1.94B မှ လျော့ကျသွားရသည့်အကြောင်းရင်း။** 2026-06-17 refresh သည် အခွင့်အရေးဆုံးရှုံးမှုမဟုတ်ဘဲ ရိုးသားမှန်ကန်မှုအတွက် ပြင်ဆင်ချက်ဖြစ်သည်။ `gemini` ကို ယခု pool အလိုက် ထပ်နေမှုဖယ်ရှားထားသည် (ယခင်က Flash variant တစ်ခုစီကို သီးခြားရေတွက်၍ 462M → 60M အဖြစ် ဖောင်းပွနေခဲ့သည်)၊ `cloudflare-ai` ကို ၎င်း၏ အမှန်တကယ် 10k-Neurons/day အဖြစ် ပြင်ဆင်ထားသည် (122M → 30M)၊ `doubao` ကို ထပ်တလဲလဲရသည့် ခွဲတမ်းမဟုတ်ဘဲ တစ်ကြိမ်သာရသည့် စာရင်းသွင်းခ credit အဖြစ် ပြန်လည်အမျိုးအစားခွဲထားပြီး ပိတ်သိမ်းထားသော အဆင့်များ (`chutes`/`phind`/`kluster` ရပ်ဆိုင်းထားသည်) ကို ဖယ်ရှားထားသည်။ ယင်းလျော့နည်းမှုကို `llm7` (မှန်ကန်သော 5M/day → 150M) နှင့် အခမဲ့ provider အသစ်များ (Kilo, OpenCode Zen, Z.AI GLM-Flash) က တစ်စိတ်တစ်ပိုင်း ပြန်လည်ဖြည့်ဆည်းပေးထားသည်။

> အောက်ဘက်ရှိ ဝန်ဆောင်မှုပေးသူတစ်ခုချင်းစီအလိုက် အသေးစိတ်ဇယားသည် **2026-06-05 အခြေအနေမှတ်တမ်း** ဖြစ်ပြီး အထက်ပါပြောင်းလဲမှုများက ၎င်းကို အစားထိုးအကျုံးဝင်သည်။ လက်ရှိအသုံးပြုနေသည့် စံရင်းမြစ်မှာ မော်ဒယ်တစ်ခုချင်းစီအလိုက် ကတ်တလောက် `open-sse/config/freeModelCatalog.ts` ဖြစ်သည်။

## နည်းစနစ်နှင့် သတိပြုရန်အချက်များ

- ကိန်းဂဏန်းများသည် **2026-06-17** ရက်နေ့အထိ ဝဘ်သုတေသနဖြင့် စုဆောင်းထားသော provider တစ်ခုစီ၏ မှတ်တမ်းတင်ထားသည့် free-tier ကန့်သတ်ချက်များအပေါ် အခြေခံသည့် **အများဆုံးဖြစ်နိုင်ခြေ ခန့်မှန်းချက်များ** ဖြစ်သည်။ Free tier များသည် အမြဲပြောင်းလဲနေသောကြောင့် ကိန်းဂဏန်းတစ်ခုကို အားကိုးအသုံးမပြုမီ ပြန်လည်အတည်ပြုပါ။
- **Entry တစ်ခုက အမှန်တကယ် အာမခံဖော်ပြသည့်အရာ။** Entry တစ်ခုချင်းစီတွင် confidence rating မပါဝင်သကဲ့သို့ API ကလည်း ထိုအချက်အလက်ကို မပေးပါ — အထက်ပါကိန်းဂဏန်းတိုင်းကို ဖော်ပြမထားသော တူညီသည့် အရည်အသွေးအဆင့်ရှိ ခန့်မှန်းချက်များအဖြစ်သာ သတ်မှတ်ပါ။ သို့သော် အောက်ပါအချက်နှစ်ခုမှာ ကောက်ချက်ချထားခြင်းမဟုတ်ဘဲ လူကိုယ်တိုင် စိစစ်ထည့်သွင်းထားသောကြောင့် ကွဲပြားသည် — entry 44 ခုတွင် သီးခြားမှတ်တမ်းတင်ထားသော hard stop ပါရှိပြီး (၎င်းတို့အနက် 39 ခုမှာ တူညီသည့် နေ့စဉ်ခွင့်ပြုပမာဏကို မျှဝေသည့် xKiro row များဖြစ်သည်)၊ entry 13 ခုတွင် prompt-training disclosure ပါရှိသည်။ Provider ၏ ကိုယ်ပိုင်စည်းမျဉ်းများက အခမဲ့ခွင့်ပြုပမာဏ ကျော်လွန်ပါက သင့်ထံ အလိုအလျောက် ကောက်ခံခြင်းမပြုဘဲ request ကို ငြင်းပယ်မည်ဟု ဖော်ပြထားသည့်အခါမှသာ `hardStopGuaranteed` ကို သတ်မှတ်ပြီး source ကို entry ဘေးရှိ comment တွင် ထည့်ထားသည်။ ၎င်းကို `true` အဖြစ် မည်သည့်အခါမျှ default မသတ်မှတ်ဘဲ မည်သူမျှ အတည်မပြုရသေးသော entry ကို unset အဖြစ်ထားသည်။ ထို့ကြောင့် hard-stop flag မရှိခြင်းသည် "အတည်မပြုရသေး" ဟု ဆိုလိုခြင်းသာဖြစ်ပြီး "ငွေကောက်ခံမည်ဟု သိထားသည်" ဟု မဆိုလိုပါ။ **STRICT mode** (ရွေးချယ်အသုံးပြုရသည့် `freeAccessPolicy=strict` routing guard) သည် flag ပါရှိသော entry များကိုသာ ယုံကြည်သည်။ အခြား free tier အားလုံးကို `no-hard-stop` အဖြစ် ဖယ်ထုတ်သည် (`open-sse/services/autoCombo/strictZeroCostFilter.ts` ကို ကြည့်ပါ)။
- `estMonthlyFreeTokens` = လစဉ် ထပ်တလဲလဲရရှိသော token များသာ။ **တစ်ကြိမ်သာရရှိသည့် signup credit များသည် ထပ်မံမရရှိပါ**၊ ထို့ကြောင့် 0 အဖြစ် ရေတွက်သည်။ ရပ်ဆိုင်းထားသော tier များကိုလည်း 0 အဖြစ် ရေတွက်သည်။
- နေ့စဉ် token ကန့်သတ်ချက် → `monthly = daily × 30`။ RPD ကိုသာ မှတ်တမ်းတင်ထားပါက → `RPD × ~800 output tokens × 30`။ RPM/TPM သာရှိပြီး နေ့စဉ်ကန့်သတ်ချက် မရှိပါက → **ကန့်သတ်မထား** (အောက်တွင် ကြည့်ပါ)။
- **အမြဲတမ်းအခမဲ့ဖြစ်သော်လည်း ထုတ်ပြန်ထားသည့် token ကန့်သတ်ချက် မရှိသော provider များ** (`siliconflow`, `glm-cn`, `tencent`, `baidu`, `kilo-gateway`, `opencode-zen`, `gemini`, `ollama-cloud`) — ၎င်းတို့သည် rate/concurrency ဖြင့် ကန့်သတ်ထားသည့် အမှန်တကယ် ထပ်တလဲလဲရရှိသော အခမဲ့အသုံးပြုခွင့်များဖြစ်သည်။ ၎င်းတို့ကို `recurring-uncapped` အဖြစ် အမျိုးအစားခွဲပြီး **မည်သည့်အခါမျှ စုစုပေါင်းမတွက်ပါ** — `RPM × 24/7 × 30d` ဟု မြှောက်ခြင်းသည် လက်တွေ့မကျသော အများဆုံးပမာဏတစ်ခုကို ဖြစ်ပေါ်စေမည်ဖြစ်ပြီး ထိုသို့ ပုံကြီးချဲ့တွက်ချက်ခြင်းကို ကျွန်ုပ်တို့ လက်မခံပါ။ ၎င်းတို့ ရှိနေကြောင်း သိရှိနိုင်ရန် စာရင်းထည့်ထားခြင်းဖြစ်သည်။
- **Deposit-unlock boost:** တစ်ကြိမ်သာ ငွေပမာဏအနည်းငယ် ဖြည့်သွင်းခြင်းဖြင့် အခမဲ့ quota ကို အမြဲတမ်းမြှင့်ပေးသည့် စနစ် (OpenRouter: $10 → 1000 req/day ≈ +24M/mo)။ သီးခြားကိန်းဂဏန်းအဖြစ် ဖော်ပြထားပြီး ပုံမှန်ဆက်တိုက်ရရှိသည့် အဓိကကိန်းဂဏန်းတွင် မထည့်သွင်းပါ။
- **အရည်အချင်းပြည့်မီမှုဖြင့် ကန့်သတ်ထားသော quota များ** (`eligibilityGate: "regional-identity"`) — ဒေသနှင့်ချိတ်ဆက်ထားသော ကိုယ်ရေးအထောက်အထား စစ်ဆေးမှု ပြီးဆုံးမှသာ အသုံးပြုနိုင်သည့် အမှန်တကယ် ထပ်တလဲလဲရရှိသော quota ဖြစ်သည် (လက်ရှိတွင် တရုတ်ပြည်မကြီး၏ အမည်ရင်းဖြင့် အတည်ပြုခြင်း)။ တူညီသော pool-dedupe စည်းမျဉ်းဖြင့် သီးခြားကိန်းဂဏန်း (`gatedRecurringTokens`) ထဲသို့ ရေတွက်ပြီး ပုံမှန်ဆက်တိုက်ရရှိသည့် အဓိကကိန်းဂဏန်းတွင် မည်သည့်အခါမျှ မထည့်ပါ။ Regime (`freeType`) သည် မပြောင်းလဲသောကြောင့် routing လည်း မပြောင်းလဲပါ။
- **အထောက်အထား အမျိုးအစားများ။** စည်းမျဉ်းမှာ catalog ထဲရှိ ကိန်းဂဏန်းတစ်ခုသည် entry ဘေးရှိ `// evidence:` comment တွင် ၎င်း၏ source ကို ကိုးကားဖော်ပြရမည်ဖြစ်သည် — `public-page` (မည်သူမဆို ဖတ်ရှုနိုင်သည့် provider စာမျက်နှာ)၊ `api-public` (provider ၏ authentication မလိုသော endpoint၊ ဥပမာ router.bynara.id ရှိ NaraRouter ၏ public plans endpoint) သို့မဟုတ် `console-verified <date> por <who>` (ကိန်းဂဏန်းကို account console အတွင်း၌သာ မြင်နိုင်သည်။ Comment တွင် မည်သူက မည်သည့်အချိန်တွင် မြင်တွေ့ခဲ့သည်ကိုလည်းကောင်း၊ cap ရှိကြောင်း ဖော်ပြထားသည့် public page ကိုလည်းကောင်း မှတ်တမ်းတင်ထားသည်) ဖြစ်သည်။ လက်ရှိအခြေအနေမှာ 2026-09-02 ရက်နေ့တွင် ပြန်လည်စစ်ဆေးခဲ့သည့် block ငါးခု (`gemini`, `groq`, `mistral`, `ollama-cloud`, `nara`) တွင် ၎င်းပါဝင်သည်။ 2026-09-02 ပြန်လည်စစ်ဆေးမှုမတိုင်မီ ရှိနှင့်ပြီးသော entry များသည် ၎င်းတို့ကို ပြင်ဆင်စစ်ဆေးသည့်အချိန်အထိ ယခင်သုတေသနကို ဆက်လက်အမွေဆက်ခံထားသည်။ Evidence comment မပါသော **အသစ် သို့မဟုတ် ပြောင်းလဲထားသည့်** ကိန်းဂဏန်းတိုင်းသည် bug ဖြစ်သည်။ လက်ရှိတွင် `mistral` တစ်ခုသာ console-verified ဖြစ်သည်။

## ကျွန်ုပ်တို့၏ ကိန်းဂဏန်းသည် အခြား aggregator များ၏ ကိန်းဂဏန်းများထက် အဘယ်ကြောင့် ပိုနည်းသနည်း

ဤနယ်ပယ်ရှိ "တစ်လလျှင် အခမဲ့ token" ကိန်းဂဏန်းအများစုသည် model တစ်ခုချင်းစီအလိုက် ဖော်ပြထားသော ပမာဏများကို ပေါင်းထားခြင်းဖြစ်သည်။ ကျွန်ုပ်တို့၏ ကိန်းဂဏန်းမှာ ရည်ရွယ်ချက်ရှိရှိ ထိုသို့မဟုတ်ပါ-

- **မျှဝေသုံးစွဲရသော pool တစ်ခုစီကို တစ်ကြိမ်သာ ရေတွက်ပါသည်။** Mistral ၏ အခမဲ့အစီအစဉ်သည် organization တစ်ခုလျှင် တစ်လ 1B ပမာဏရှိသည့် allowance တစ်ခုဖြစ်သည်။ ၎င်းကို model ငါးခုအောက်တွင် စာရင်းပြုစုထားခြင်းက 5B ဖြစ်လာစေမည်မဟုတ်ပါ။ Model အလိုက် ပေါင်းလျှင် ကျွန်ုပ်တို့၏ ကိုယ်ပိုင် catalog သည် **~7.4B** ဟု ဖော်ပြမည်ဖြစ်သည် (2026-09-03 တွင် ပြန်လည်တွက်ချက်ထားသည်၊ ဤကိန်းဂဏန်းကို CI ဖြင့် စစ်ဆေးထိန်းချုပ်ထားခြင်း မရှိပါ — catalog ပြောင်းလဲသည့်အခါတိုင်း ပြန်လည်တိုင်းတာပါ) — headline တွင် **~1.47B** ဟု ဖော်ပြရခြင်းမှာ provider တစ်ခုစီ၏ account တစ်ခုစီက အမှန်တကယ် သုံးစွဲနိုင်သည့် ပမာဏဖြစ်သောကြောင့် ဖြစ်သည်။
- **နေ့စဉ် cap များကို ပြောင်းလဲတွက်ချက်သော်လည်း rate များကို မပြောင်းလဲတွက်ချက်ပါ။** စာရွက်စာတမ်းတွင် ဖော်ပြထားသော tokens/day cap ကို `× 30` အဖြစ် ပြောင်းလဲသည်။ စာရွက်စာတမ်းတွင် ဖော်ပြထားသော requests/day cap ကို `RPD × ~800 tokens × 30` အဖြစ် ပြောင်းလဲသည်။ requests-per-minute ကိုသာ ထုတ်ပြန်ထားသော provider တွင် လစဉ်ကိန်းဂဏန်း **မရှိပါ**၊ ထို့ကြောင့် _uncapped_ အဖြစ် စာရင်းပြုစုပြီး မည်သည့်အခါမျှ ပေါင်းထည့်ခြင်းမပြုပါ။ Rate limit ကို 24/7 ဖြင့် မြှောက်ခြင်းသည် ကျွန်ုပ်တို့ လက်မခံသော ကိန်းဂဏန်းဖောင်းပွမှု ဖြစ်သည်။
- **ဒေသအလိုက် identity check လုပ်ပြီးမှ ရရှိနိုင်သော quota များကို သီးခြားဖော်ပြထားပါသည်** (`+~6M behind regional identity verification`)၊ အကြောင်းမှာ စာဖတ်သူအများစုက ၎င်းတို့ကို အသုံးမပြုနိုင်သောကြောင့် ဖြစ်သည်။
- **Signup credit များသည် ပထမလအတွက်သာ ဖြစ်ပြီး** ဒုတိယကိန်းဂဏန်းအဖြစ် ဖော်ပြထားကာ ပုံမှန်ရရှိသည့် ကိန်းဂဏန်းနှင့် မည်သည့်အခါမျှ ရောနှောထားခြင်းမရှိပါ။
- **ဤကိန်းဂဏန်းကို CI ဖြင့် စစ်ဆေးထိန်းချုပ်ထားပါသည်။** `npm run check:docs-counts` သည် catalog မှ စုစုပေါင်းများကို ပြန်လည်တွက်ချက်ပြီး ဤဖိုင်၊ README သို့မဟုတ် budget card ရှိ ကိန်းဂဏန်းများနှင့် ကွာဟလာသည့်အခါ build ကို မအောင်မြင်စေပါသည်။

## ToS သတိပြုရန်ဇယား

> **ToS အလံသည် အကြံပြုသတိပေးချက်သာဖြစ်ပြီး လမ်းကြောင်းရွေးချယ်မှုကို တားဆီးသည့် စည်းမျဉ်းမဟုတ်ပါ။** `tos` ဟု မှတ်သားထားသော ဝန်ဆောင်မှုပေးသူများကို ပုံမှန်အားဖြင့် လမ်းကြောင်းရွေးချယ်မှုနှင့် combo/fallback တို့တွင် ဆက်လက်ထည့်သွင်းထားသည်။ အလံကို `/dashboard/free-tiers` နှင့် `/api/free-tier/summary` တို့တွင်သာ ဖော်ပြသည်။ `excludeTosAvoid` query parameter သည် summary မြင်ကွင်းအပေါ်သာ သက်ရောက်ပြီး ကမ္ဘာလုံးဆိုင်ရာ လမ်းကြောင်းရွေးချယ်မှုအပေါ် မသက်ရောက်ပါ။ သုံးသပ်ဆုံးဖြတ်ချက်ကို `open-sse/config/freeTierCatalog.ts` တွင် ထားရှိထားသည် (သတင်းအချက်အလက်ပေးရန်သာဖြစ်ပြီး လမ်းကြောင်းရွေးချယ်ရေးအင်ဂျင်များက ဖတ်ရှုခြင်းမရှိပါ)။

> ကိုယ်တိုင် host လုပ်ထားသော၊ အသုံးပြုသူတစ်ဦးတည်းသုံး ကိုယ်ပိုင် proxy အတွက် ဝန်ဆောင်မှုပေးသူတစ်ခုချင်းစီ၏ စည်းကမ်းချက်များကို အကျဉ်းချုပ်ဖတ်ရှုထားခြင်းဖြစ်သည်။ `caution` = စစ်ဆေးသင့်သော ကိုယ်ပိုင်အသုံးပြုမှု သို့မဟုတ် proxy ဆိုင်ရာ စည်းကမ်းချက်ရှိခြင်း၊ `ambiguous` = မရှင်းလင်းခြင်း၊ `ok` = အတိအလင်း ခွင့်ပြုထားခြင်း။ သတင်းအချက်အလက်ပေးရန်သာဖြစ်ပြီး ဥပဒေအကြံဉာဏ်မဟုတ်ပါ — သင်ကိုယ်တိုင် ဆုံးဖြတ်ပါ။

### ⚠️ သတိပြုရန် — စစ်ဆေးသင့်သော ကိုယ်ပိုင်အသုံးပြုမှု / proxy ဆိုင်ရာ စည်းကမ်းချက်များ (16)

> ၎င်းတို့၏ အခမဲ့အသုံးပြုခွင့်သည် အမှန်တကယ်ရှိပြီး OmniRoute က ၎င်းတို့ထံ လမ်းကြောင်းပို့နိုင်သည်။ အောက်ပါစည်းကမ်းချက်များမှာ သိထားသင့်သည့်အချက်များသာဖြစ်သည်။ OAuth/keyless အသုံးပြုသည့်အရာများကို token အရ အရေအတွက်တွက်ချက်၍ မရသောကြောင့် အဓိကဖော်ပြသည့် ကိန်းဂဏန်းတွင် မပါဝင်ခြင်းဖြစ်သည် (အသုံးမပြုနိုင်သောကြောင့် မဟုတ်ပါ)။
