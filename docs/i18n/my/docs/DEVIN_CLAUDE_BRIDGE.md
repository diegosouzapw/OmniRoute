`devin-cli-agentic` သည် တရားဝင် Devin CLI က ACP stdio မှတစ်ဆင့် model တုံ့ပြန်ချက်များကို ပံ့ပိုးနေစဉ် အမှန်တကယ် Claude Code runtime အနေဖြင့် OmniRoute ၏ local Anthropic Messages endpoint ကို အသုံးပြုနိုင်စေသည်။ ၎င်းသည် ရှိပြီးသား Anthropic၊ Claude OAuth၊ Claude Web သို့မဟုတ် `devin-cli` provider များကို ပြင်ဆင်ခြင်းမရှိပါ။

> **လက်ရှိအခြေအနေ- Claude Code `2.1.258` ကို pin လုပ်ထားပြီး၊ offline နှင့် live validation ကို
> `2.1.220` တွင် နောက်ဆုံးမှတ်တမ်းတင်ထားသည်။** `2.1.220` pin သည် Devin CLI
> `3000.2.17` နှင့် model `swe-1-7-lightning` မှတစ်ဆင့် သီးခြားခွဲထားသော scenario သုံးခုကို
> ပြီးမြောက်ခဲ့သည်။ ထိုနောက်ဆုံး live run က client ပိုင် `Read`၊ `Edit` နှင့် `Bash` turn များ၊
> အောင်မြင်သော `npm test` ရလဒ်များ၊ project command နှင့် skill ရှာဖွေတွေ့ရှိမှု၊ Devin သီးသန့်
> routing နှင့် Claude egress လုံးဝမရှိခြင်းတို့ကို အတည်ပြုခဲ့သည်။ ထို့နောက် pin ကို `2.1.258`
> သို့ မြှင့်တင်ခဲ့သည်။ ၎င်းသည် OmniRoute ၏ Claude identity က အယောင်ဆောင်ထားသော CLI generation
> ဖြစ်ပြီး Fable 5.1 tier ကို မူလအတိုင်း ထည့်သွင်းပေးသည့် ပထမဆုံး line လည်းဖြစ်သည်။
> pin အသစ်တွင် pinned base image ပေါ်ရှိ install layer နှင့် `claude --version` ကို
> အတည်ပြုထားပြီး bridge unit suite၊ `compose config` နှင့် static isolation proof တို့လည်း
> အောင်မြင်သည် — သို့သော် offline mock scenario နှင့် live scenario သုံးခုပါ suite ကို
> ပြန်လည် run မလုပ်ရသေးပါ။ ဤ pin ဖြင့် bridge ကို အားကိုးအသုံးမပြုမီ ၎င်းတို့ကို
> ပြန်လည် run လုပ်ပါ ("Updating pinned tools" ကို ကြည့်ပါ)။

## ဖွဲ့စည်းပုံ

```text
Claude Code 2.1.258 (သီးခြားခွဲထားသော non-root Linux container)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude-format၊ authentication မလိုသော provider)
  -> devin acp --agent-type summarizer (တရားဝင် ACP stdio၊ Devin tool မပါ)
  -> သီးသန့် devin-auth volume ရှိ Devin account
```

တရားဝင် CLI ၏ default ACP agent သည် ၎င်း၏ကိုယ်ပိုင် tool များကို execute လုပ်နိုင်သောကြောင့် ဤ bridge သည် ၎င်းကို အသုံးမပြုပါ။ ၎င်းအစား tool များမပါရှိသည့် တရားဝင် CLI mode ဖြစ်သော ပုံသေ `summarizer` ACP agent ကို စတင်ပြီး serialized Anthropic request ကို execution trace အဖြစ် ဘောင်သတ်မှတ်သည်။ Claude ပိုင် အခြား action တစ်ခု လိုအပ်လာပါက တုံ့ပြန်ချက်တွင် client tool envelope တစ်ခုတည်း အတိအကျ ပါဝင်ရမည်။ တုံ့ပြန်ချက်တစ်ခုကို အောင်မြင်သည်ဟု အစီရင်မခံမီ မည်သည့် ACP `tool_call` သို့မဟုတ် `tool_call_update` ကိုမဆို ပယ်ချသည်။

`open-sse/executors/devin-agentic/serializer.ts` ရှိ serializer သည် `system`၊ `text`၊ `tool_use`၊ `tool_result`၊ `thinking`၊ `redacted_thinking`၊ `tool_choice` နှင့် Claude Code က ပံ့ပိုးထားသော tool များကို မပြောင်းလဲဘဲ ထိန်းသိမ်းထားသည်။ ပုံများနှင့် မသိရှိသော block များကို အတိအလင်း error ဖြစ်စေသည်။ ကြီးမားသော tool result များတွင် မြင်သာသော truncation marker ကို အသုံးပြုသည်။

Parser သည် model turn တစ်ခုလျှင် သီးခြား `<tool>{...}</tool>` envelope တစ်ခုကို လက်ခံသည်။ ၎င်းသည် request ၏ tool စာရင်းနှင့် name ကို တိုက်စစ်ပြီး argument များကို ထို tool ၏ JSON Schema ဖြင့် validate လုပ်ကာ narrative/action ရောနှောမှုကို ပယ်ချသည့်အပြင် ကန့်သတ်ထားသော repair တစ်ကြိမ်ကို ခွင့်ပြုသည်။ ထို့နောက် Claude Code သည် ရရှိလာသော Anthropic `tool_use` ကို local တွင် execute လုပ်ပြီး `tool_result` ကို OmniRoute မှတစ်ဆင့် ပြန်ပို့သည်။

## သီးခြားခွဲထားမှုနှင့် ခြိမ်းခြောက်မှုဆိုင်ရာ model

Host ၏ Claude installation၊ account နှင့် configuration တို့သည် သတ်မှတ်နယ်ပယ်ပြင်ပတွင်ရှိပြီး အသုံးပြုခွင့်မရှိဟု သတ်မှတ်ထားသည်။ Compose service များသည်-

- UID/GID `10001:10001` ဖြင့် run ပြီး read-only root filesystem၊ ဖယ်ရှားထားသော capability များနှင့်
  `no-new-privileges` ကို အသုံးပြုသည်၊
- သီးသန့် `/home/bridge`၊ သီးခြား Claude config volume၊ သီးခြားခွဲထားသော OmniRoute data
  နှင့် သီးခြား `devin-auth` volume ကို အသုံးပြုသည်၊
- စွန့်ပစ်နိုင်သော `.sandbox` workspace/evidence များကိုသာ mount လုပ်သည်၊
- host home၊ Keychain၊ SSH၊ cloud credential များ သို့မဟုတ် Docker socket ကို mount မလုပ်ပါ၊
- environment များကို အတိအလင်း တည်ဆောက်ပြီး Anthropic API/OAuth/routing variable များကို ဖယ်ရှားသည်၊
- Claude Code inference ကို local-only key ဖြင့် `http://omniroute:20128` သို့သာ ညွှန်ကြားသည်။

Offline profile သည် internal network တစ်ခုကို အသုံးပြုသည်။ Live profile တွင် OmniRoute သည် တရားဝင် Devin endpoint များကို `network-guard` မှတစ်ဆင့်သာ ဆက်သွယ်ပြီး မသက်ဆိုင်သော destination များကို ငြင်းပယ်သည်။ Claude Code တွင် သီးခြား deny-all egress guard တစ်ခုရှိပြီး `NO_PROXY` မှတစ်ဆင့် local OmniRoute service ကိုသာ ဆက်သွယ်နိုင်သည်။ Guard audit file များကို သက်ဆိုင်ရာ guard process ကသာ mount လုပ်ထားသည်။ Script များသည် token မပါသော evidence ကို export မလုပ်မီ file ownership၊ mode၊ link count နှင့် decision အားလုံးကို စစ်ဆေးသည်။

Isolation proof ကို သီးခြား run လုပ်ပါ-

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

၎င်းသည် topology၊ named mount များ၊ non-root/read-only setting များ၊ အတိအလင်း local routing၊ အရေးကြီး environment variable များ မရှိခြင်း၊ Docker socket မရှိခြင်း၊ `api.anthropic.com` နှင့် `claude.ai` သို့ access ပိတ်ထားခြင်း၊ Devin-only provider ရွေးချယ်မှုနှင့် ACP backend မရရှိနိုင်ချိန်တွင် အတိအလင်း failure ဖြစ်ခြင်းတို့ကို validate လုပ်သည်။

## ပထမအကြိမ် စနစ်ထည့်သွင်းခြင်းနှင့် ပုံမှန်အသုံးပြုခြင်း

သတ်မှတ်ထားသော image ကို build လုပ်ပါ-

```bash
./scripts/devin-bridge/build
```

သီးခြားခွဲထားသော Devin volume ကိုသာ စစ်မှန်ကြောင်းအတည်ပြုပါ-

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

login command သည် remote/container ပတ်ဝန်းကျင်များအတွက် ရည်ရွယ်ထားသော တရားဝင် manual-token လုပ်ငန်းစဉ်ကို အသုံးပြုသည်။ တန်ဖိုးကို CLI prompt ထဲသို့ တိုက်ရိုက်ထည့်သွင်းရပြီး process argument အဖြစ် ပေးပို့ခြင်း၊ Git ထဲသို့ ရေးသားခြင်း သို့မဟုတ် host မှ ကူးယူခြင်း မပြုပါ။

သီးခြားခွဲထားသော Claude Code runtime ကို စတင်ပါ-

```bash
./scripts/devin-bridge/launch
```

`launch` သည် container အတွင်းရှိ Claude Code ကို မစတင်မီ ခွဲခြားထားမှု၊ Devin စစ်မှန်ကြောင်းအတည်ပြုမှုနှင့် model ရှာဖွေတွေ့ရှိမှုတို့ကို ပြန်လည်စစ်ဆေးသည်။ ၎င်းသည် host ၏ Claude executable ကို မည်သည့်အခါမျှ မလုပ်ဆောင်ပါ။ Model alias များကို `.env.devin-bridge` တွင် သတ်မှတ်နိုင်ပြီး ပြင်ဆင်သတ်မှတ်ထားသော တန်ဖိုးတိုင်းတွင် `devin-cli-agentic/` prefix ကို ဆက်လက်ထားရှိရမည်။

## စစ်ဆေးအတည်ပြုရန် command များ

ပြန်လည်ထုတ်လုပ်နိုင်သော offline လမ်းကြောင်းသည် Devin account မလိုအပ်သည့်အပြင် runtime Internet လည်း မရှိပါ-

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

စစ်မှန်ကြောင်းအတည်ပြုထားပြီး ကိုယ်တိုင်ရွေးချယ်ဖွင့်သုံးရသော live လမ်းကြောင်းမှာ-

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

live runner သည် ACP session များကို တစ်ပြိုင်နက်တည်း အများအပြား မဖွင့်မိစေရန် scenario များကြားတွင် စောင့်ဆိုင်းပြီး စာသားဖြင့် ဖော်ပြထားသော အဆိုများကို ယုံကြည်ခြင်းအစား ဖွဲ့စည်းပုံကျသော Claude stream event များကို စစ်ဆေးအတည်ပြုသည်။ ၎င်း၏ scenario သုံးခုက အောက်ပါတို့ကို သက်သေပြသည်-

1. project ကို တိုက်ရိုက်ဖတ်ရှုခြင်းနှင့် ချို့ယွင်းချက် ဆန်းစစ်ခြင်း၊
2. အမှန်တကယ် `Edit` တစ်ခု၊ client က ထိန်းချုပ်သော `Bash` `npm test` တစ်ခုနှင့် နောက်ဆုံးရလဒ်တစ်ခု၊
3. `/bridge-check` နှင့် `bridge-proof` ရှာဖွေတွေ့ရှိမှု၊ project ဖတ်ရှုမှုများ၊ အောင်မြင်သော အခြား client က ထိန်းချုပ်သည့် `npm test` တစ်ခုနှင့် ဆိုင်းငံ့အလုပ်မရှိဘဲ ပြီးဆုံးမှု။

နောက်ဆုံး gate သည် Devin network audit ကိုလည်း စစ်ဆေးပြီး Claude egress audit သည် ဗလာအဖြစ် ဆက်လက်ရှိနေရန် လိုအပ်သည်။

## သတ်မှတ်ထားသော tool များကို အပ်ဒိတ်လုပ်ခြင်း

image သည် Node၊ Claude Code နှင့် Devin CLI တို့ကို `docker/devin-bridge/Dockerfile` တွင် version သတ်မှတ်ထားသည်။ အပ်ဒိတ်လုပ်ရန်-

1. အတိအလင်းသတ်မှတ်ထားသော version များကို ပြောင်းပါ၊
2. architecture အလိုက် Devin archive checksum နှစ်ခုစလုံးကို တရားဝင် artifact အတွက် တန်ဖိုးများဖြင့် အစားထိုးပါ၊
3. ပြန်လည် build လုပ်ပြီး offline စစ်ဆေးအတည်ပြုရေး command အားလုံးကို လုပ်ဆောင်ပါ၊
4. image အတွင်းရှိ version များကို အတည်ပြုပါ၊
5. စစ်မှန်ကြောင်းအတည်ပြုထားသော scenario သုံးခုပါ live suite ကို ပြန်လည်လုပ်ဆောင်ပါ။

CLI နှစ်ခုအနက် မည်သည့်တစ်ခုကိုမျှ host တွင် global အဖြစ် မတပ်ဆင်ပါနှင့်။ ထို့ပြင် checksum စစ်ဆေးအတည်ပြုမှုကို အတည်မပြုထားသော download ဖြင့် မအစားထိုးပါနှင့်။

## ပြဿနာရှာဖွေခြင်းနှင့် ရှင်းလင်းခြင်း

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  သည် local routing နှင့် အရေးကြီးအချက်အလက်များ ဖယ်ရှားထားသော executor error များကို ပြသသည်။
- `.sandbox/evidence/mock-acp.jsonl` သည် ကြိုတင်သတ်မှတ်နိုင်သော mock ACP လုပ်ဆောင်ချက်များကို မှတ်တမ်းတင်သည်။
- `.sandbox/evidence/claude-stream.jsonl` သည် Claude Code ၏ အမှန်တကယ် offline run ကို မှတ်တမ်းတင်သည်။
- `.sandbox/evidence/live-*.jsonl` သည် စစ်ဆေးအတည်ပြုထားသော live stream သုံးခုကို မှတ်တမ်းတင်သည်။
- `.sandbox/evidence/egress.jsonl` နှင့် `.sandbox/evidence/claude-egress.jsonl` တို့သည် စစ်ဆေးအတည်ပြုထားပြီး token မပါဝင်သော guard audit မိတ္တူများ ဖြစ်သည်။

login/config volume များကို ထိန်းသိမ်းထားလျက် ပိုင်ဆိုင်သော container နှင့် network များကို ရပ်တန့်ပါ-

```bash
./scripts/devin-bridge/clean
```

အမည်ပေးထားသော volume များအပါအဝင် bridge က ပိုင်ဆိုင်သည့် environment အပြည့်အစုံကို ဖယ်ရှားပါ-

```bash
./scripts/devin-bridge/clean --all
```

## ကန့်သတ်ချက်များ

- Devin CLI `3000.2.17` တွင် ဘက်မလိုက်သော ကိရိယာမဲ့ ACP agent ကို ဖော်ထုတ်မပေးထားသောကြောင့် bridge သည် ပုံသေ no-tools `summarizer` role ကို အားကိုးပါသည်။ Adapter သည် အနှစ်ချုပ်ပုံစံ အလယ်အလတ်တုံ့ပြန်ချက်များကို ဖြည့်ဆည်းကိုင်တွယ်ပေးသော်လည်း ကန့်သတ်ထားသော ပြန်လည်ပြင်ဆင်မှုတစ်ကြိမ်သည်ပင် အတိအလင်း မအောင်မြင်နိုင်သေးသည်။
- တိုက်ရိုက် ACP ခေါ်ဆိုမှုများသည် ယာယီ `502`/`504` တုံ့ပြန်ချက်များကို ပြန်ပေးနိုင်သည်။ Harness သည် scenario များကြား အချိန်ခြားပေးထားသော်လည်း ဆက်တိုက်မအောင်မြင်ပါက fail-closed အဖြစ် ဆက်လက်ထားရှိပြီး အခြား provider ကို မည်သည့်အခါမျှ မရွေးချယ်ပါ။
- ACP context ကို Anthropic request တစ်ခုစီမှ ပြန်လည်တည်ဆောက်ထားပြီး process/session ဆက်နွှယ်မှု မရှိပါ။
- Model တုံ့ပြန်ချက်တစ်ခုလျှင် tool call တစ်ခုကိုသာ ပံ့ပိုးထားပြီး အပြိုင်ခေါ်ဆိုမှုများကို ငြင်းပယ်ပါသည်။
- ပုံများကို အတိအလင်း ပံ့ပိုးမထားပါ။ Vision၊ thinking output၊ effort controls နှင့် 1M context window တို့ကို ရရှိနိုင်သည့် လုပ်ဆောင်ချက်များအဖြစ် ကြေညာမထားပါ။
- SSE သည် မှန်ကန်သော Anthropic lifecycle event များကို အသုံးပြုသော်လည်း ကန့်သတ်ထားသော ACP turn ကို စုဆောင်းပြီးမှသာ ထုတ်လွှင့်ပါသည်။ ACP chunk များကို ရရှိသည်နှင့် တစ်ပြိုင်နက် တစ်ဆင့်ချင်း ထပ်ဆင့်ပို့ခြင်း မပြုပါ။
