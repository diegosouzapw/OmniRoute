## အခမဲ့အဆင့်များဆိုသည်မှာ အဘယ်နည်း?

AI provider အများအပြားသည် **အခမဲ့အသုံးပြုခွင့်** ပုံစံတစ်မျိုးမျိုးကို ပေးထားသည်။ Provider ပေါ်မူတည်၍ ၎င်းသည်
အထောက်အထားစစ်ဆေးရန်မလိုသော endpoint၊ ပုံမှန်ပြန်လည်ရရှိသည့် quota၊ နှုန်းကန့်သတ်ထားသော်လည်း စုစုပေါင်းပမာဏအကန့်အသတ်မရှိသော အသုံးပြုခွင့်၊ စာရင်းသွင်းခြင်းဆိုင်ရာ အခမဲ့ပမာဏ၊
လူကိုယ်တိုင် အတည်ပြုခွင့်ပေးခြင်း သို့မဟုတ် ယာယီပရိုမိုးရှင်းတစ်ခု ဖြစ်နိုင်သည်။ ရွေးချယ်စရာအချို့အတွက် account၊ API key၊
credit card၊ KYC သို့မဟုတ် provider အလိုက် သတ်မှတ်ထားသော စည်းမျဉ်းများကို လက်ခံခြင်း လိုအပ်နိုင်သည်။

OmniRoute သည် ဤအခမဲ့အဆင့်များကို endpoint တစ်ခုတည်းသို့ **စုစည်းပေးသည်**။ မတူညီသော service 10 ခုတွင် စာရင်းသွင်းမည့်အစား ၎င်းတို့အားလုံးကို OmniRoute နှင့် ချိတ်ဆက်ပြီး request တစ်ခုချင်းစီအတွက် အကောင်းဆုံးအခမဲ့ရွေးချယ်စရာကို အလိုအလျောက်ရွေးချယ်ရန် `model: "auto"` ကို အသုံးပြုနိုင်သည်။

## အခမဲ့အဆင့်များကို ပေါင်းစပ်အသုံးပြုနည်း

OmniRoute ၏ အားသာချက်မှာ **အခမဲ့အဆင့်များကို ပေါင်းစပ်အသုံးပြုခြင်း** ဖြစ်သည်။ ဝန်ဆောင်မှုပေးသူတစ်ခုတည်းကိုသာ အားကိုးမည့်အစား အခမဲ့ဝန်ဆောင်မှုပေးသူများစွာကို ချိတ်ဆက်နိုင်ပြီး တောင်းဆိုမှုတစ်ခုစီအတွက် အသင့်တော်ဆုံးတစ်ခုကို OmniRoute က အလိုအလျောက်ရွေးချယ်ပေးနိုင်သည်။

### ဥပမာ- ပိုမိုကျယ်ပြန့်သော အခမဲ့အဆင့် လွှမ်းခြုံမှု

ခွဲတမ်းတစ်ခုတည်းအပေါ် မှီခိုမှုကို လျှော့ချရန် ဝန်ဆောင်မှုပေးသူအများအပြားကို ချိတ်ဆက်ပါ-

1. **Gemini** — ပုံမှန်ပြန်လည်ရရှိသည့် API key ခွဲတမ်း
2. **Groq** — ပုံမှန်ပြန်လည်ရရှိသည့် API key ခွဲတမ်း
3. **Pollinations** — key မလိုအပ်ဘဲ နှုန်းထားကန့်သတ်ချက်ဖြင့် အသုံးပြုခွင့်
4. **LongCat** — စာရင်းသွင်းချိန်တွင် တစ်ကြိမ်သာရရှိသည့် ခွင့်ပြုချက် (KYC လိုအပ်သည်)

ထို့နောက် `model: "auto"` ကို အသုံးပြုပါ။ OmniRoute က အောက်ပါအတိုင်း လုပ်ဆောင်မည်-

- အရည်အချင်းပြည့်မီသော ချိတ်ဆက်မှုများထဲမှ အဆင့်အမြင့်ဆုံးတစ်ခုကို ဦးစွာ စမ်းသပ်မည်
- ၎င်း၏ ခွဲတမ်း သို့မဟုတ် ကျန်းမာရေးစစ်ဆေးမှု မအောင်မြင်ပါက → ပြင်ဆင်သတ်မှတ်ထားသည့် နောက်ထပ်ဝန်ဆောင်မှုပေးသူကို စမ်းသပ်မည်
- key မလိုအပ်သော ဝန်ဆောင်မှုပေးသူကို အသုံးမပြုနိုင်ပါက → ကျန်ရှိသော ပစ်မှတ်များကို ဆက်လက်စမ်းသပ်မည်
- အားလုံးမအောင်မြင်ပါက → LongCat ကို အရန်အဖြစ် အသုံးပြုမည်

**ရလဒ်**- အလိုအလျောက် အရန်ပြောင်းလဲမှုဖြင့် ပိုမိုကျယ်ပြန့်သော အခမဲ့အဆင့် လွှမ်းခြုံမှုကို ရရှိမည်ဖြစ်သော်လည်း အကန့်အသတ်မရှိသော စွမ်းဆောင်ရည်ကို အာမခံခြင်းမဟုတ်ပါ။

ကတ်တလောက်ကို ကြည့်ရှုပြီး ဝန်ဆောင်မှုပေးသူတစ်ခုစီ၏ လက်ရှိ `hasFree`၊ အထောက်အထားစိစစ်မှု၊ ခွဲတမ်း၊ ကိုယ်ရေးအချက်အလက်လုံခြုံမှုနှင့်
ToS မက်တာဒေတာတို့ကို စစ်ဆေးပါ။ ဝန်ဆောင်မှုပေးသူကတ်နှင့်
[အခမဲ့အဆင့်များ အကိုးအကား](../reference/FREE_TIERS.md) တွင် ပုံမှန်ပြန်လည်ရရှိသည့် အရင်းအမြစ်အစုများ၊

၎င်းတို့၏ မှတ်တမ်းပြုစုထားသော အကောင့်လုပ်ငန်းစဉ်မှတစ်ဆင့် ချိတ်ဆက်ရမည်။

သင့်အသုံးပြုမှုနှင့် ကိုက်ညီသော စည်းကမ်းချက်များနှင့် ကိုယ်ရေးအချက်အလက်ဆိုင်ရာ ပုံစံရှိသည့် ဝန်ဆောင်မှုပေးသူအများအပြားကို ချိတ်ဆက်ပါ။

## ကတ်တလောက်ကို မှန်ကန်စွာ ဖတ်ရှုနည်း

- `NOAUTH` ဆိုသည်မှာ OmniRoute က ဝန်ဆောင်မှုပေးသူဆိုင်ရာ အထောက်အထားအချက်အလက်ကို သင့်ထံမှ မတောင်းဆိုခြင်းကို ဆိုလိုသည်။ ၎င်းသည်
  စနစ်အသုံးပြုနိုင်ချိန်၊ ကိုယ်ရေးအချက်အလက်လုံခြုံမှု သို့မဟုတ် အကန့်အသတ်မရှိသော စွမ်းဆောင်ရည်ကို အာမခံခြင်းမဟုတ်ပါ။
- `hasFree` သည် ရှာဖွေဖော်ထုတ်မှုဆိုင်ရာ မက်တာဒေတာဖြစ်သည်။ ၎င်းသည် ပုံမှန်ပြန်လည်ရရှိသည့် ခွဲတမ်း၊ key မလိုအပ်သည့် အသုံးပြုခွင့်၊
  စာရင်းသွင်းခြင်းဆိုင်ရာ ခရက်ဒစ်၊ ခွင့်ပြုချက်အစီအစဉ် သို့မဟုတ် ပရိုမိုးရှင်းကို ကိုယ်စားပြုနိုင်သည်။
- `recurring-uncapped` ဆိုသည်မှာ ထုတ်ပြန်ထားသော token အများဆုံးကန့်သတ်ချက် မရှိကြောင်း ဆိုလိုသည်။ သို့သော် နှုန်းထားနှင့်
  တစ်ပြိုင်နက်လုပ်ဆောင်မှု ကန့်သတ်ချက်များမှာ ဆက်လက်သက်ရောက်သည်။
- `one-time-initial` သည် စာရင်းသွင်းချိန်တွင် ရရှိသော ခွင့်ပြုချက်ကို သုံးစွဲပြီးနောက် ပြန်လည်ရရှိမည်မဟုတ်ပါ။
- `tos: avoid` သည် အသုံးမပြုမီ ဝန်ဆောင်မှုပေးသူ၏ စည်းကမ်းချက်များနှင့် အကောင့်ဆိုင်ရာ အန္တရာယ်များကို ပြန်လည်သုံးသပ်ရန် သတိပေးချက်ဖြစ်သည်။
- `discontinued` ဟု အမှတ်အသားပြုထားသော ထည့်သွင်းချက်များသည် သမိုင်းဆိုင်ရာ အထောက်အထားအဖြစ် ဆက်လက်တည်ရှိနေသော်လည်း
  လက်ရှိတွင် အခမဲ့ဖြစ်ကြောင်း မဖော်ပြရပါ။

## OmniRoute က အခမဲ့အဆင့်များကို ပိုမိုကောင်းမွန်စေပုံ

### 1. အလိုအလျောက် အရန်ပြောင်းလဲမှု

အခမဲ့ဝန်ဆောင်မှုပေးသူတစ်ခု အလုပ်များနေပါက သို့မဟုတ် အသုံးပြု၍မရပါက OmniRoute က နောက်တစ်ခုကို အလိုအလျောက် စမ်းသပ်မည်။ သင် ဘာမှလုပ်ရန်မလိုပါ။

### 2. စမတ်ကျသော လမ်းကြောင်းရွေးချယ်မှု

တောင်းဆိုမှုတစ်ခုစီအတွက် **အကောင်းဆုံး အခမဲ့ဝန်ဆောင်မှုပေးသူ** ကို OmniRoute က အောက်ပါတို့အပေါ် အခြေခံ၍ ရွေးချယ်သည်-

- အမြန်နှုန်း — လက်ရှိတွင် မည်သည့်ဝန်ဆောင်မှုပေးသူက အမြန်ဆုံးဖြစ်သနည်း။
- အရည်အသွေး — ဤလုပ်ငန်းအတွက် မည်သည့်ဝန်ဆောင်မှုပေးသူက အကောင်းဆုံးဖြစ်သနည်း။
- စွမ်းဆောင်ရည် — မည်သည့်ဝန်ဆောင်မှုပေးသူတွင် ခွဲတမ်းကျန်ရှိသနည်း။

### 3. Token ချွေတာမှု

OmniRoute ၏ ချုံ့ခြင်း pipeline သည် ချုံ့နိုင်သော prompt နှင့် tool output token များကို လျှော့ချပေးနိုင်သည်။
အမှန်တကယ် ချွေတာနိုင်မှုသည် အကြောင်းအရာ၊ ရွေးချယ်ထားသော engine များ၊ ဝန်ဆောင်မှုပေးသူ၏ တွက်ချက်မှုပုံစံနှင့် မူရင်းအတိုင်း ထိန်းသိမ်းမှု
ဆက်တင်များအပေါ် မူတည်သည်။ ချုံ့ခြင်းက ဝန်ဆောင်မှုပေးသူတိုင်း၏ ခွဲတမ်းကို သတ်မှတ်ထားသော ဆတစ်ခုဖြင့် တိုးပွားစေခြင်းမဟုတ်ပါ။

### 4. အကောင့်အများအပြား ပံ့ပိုးမှု

ဝန်ဆောင်မှုပေးသူ၏ စည်းကမ်းချက်များက အကောင့် သို့မဟုတ် အထောက်အထားအချက်အလက် အများအပြားကို ခွင့်ပြုပါက OmniRoute သည်
ချိတ်ဆက်မှုတစ်ခုစီကို သီးခြားလမ်းကြောင်းရွေးချယ်မှု ကိုယ်စားလှယ်လောင်းတစ်ခုအဖြစ် သတ်မှတ်နိုင်သည်။ ဝန်ဆောင်မှုပေးသူ၏
ခွဲတမ်း သို့မဟုတ် အသုံးပြုခွင့်မူဝါဒကို ရှောင်လွှဲရန် အပိုအကောင့်များ မဖန်တီးပါနှင့်။

## မကြာခဏမေးလေ့ရှိသော မေးခွန်းများ

### "ဒါက တကယ်အခမဲ့လား?"

catalog တွင် provider များက ထုတ်ပြန်ထားသော စည်းကမ်းချက်များနှင့် project သုတေသနအချက်အလက်များကို မှတ်တမ်းတင်ထားသော်လည်း ကမ်းလှမ်းချက်များသည် ပြောင်းလဲနိုင်ပါသည်။
အသုံးမပြုမီ provider ၏ လက်ရှိစျေးနှုန်း၊ quota၊ ကိုယ်ရေးအချက်အလက် မူဝါဒနှင့် အရည်အချင်းပြည့်မီမှုတို့ကို အတည်ပြုစစ်ဆေးပါ။

### "အခမဲ့အဆင့်က ကုန်သွားနိုင်သလား?"

provider တိုင်းသည် အသုံးပြုနှုန်းကို ကန့်သတ်ခြင်း၊ model များ ပြောင်းလဲခြင်း၊ အသုံးပြုခွင့် ရပ်ဆိုင်းခြင်း သို့မဟုတ် ဝန်ဆောင်မှု ရပ်တန့်ခြင်းတို့ ပြုလုပ်နိုင်သည်။ connection အများအပြားသည် အရန်အသုံးပြုနိုင်မှုကို ကောင်းမွန်စေသော်လည်း
အသုံးပြုနိုင်သော အခမဲ့ route တစ်ခု အမြဲရှိမည်ဟု အာမမခံပါ။

### "ထုတ်လုပ်ရေးစနစ်အတွက် အခမဲ့ provider တွေကို သုံးလို့ရလား?"

provider ၏ SLA၊ ဒေတာကိုင်တွယ်ပုံ၊ ကန့်သတ်ချက်များနှင့် စည်းကမ်းချက်များက သင့်ထုတ်လုပ်ရေး
လိုအပ်ချက်များကို ဖြည့်ဆည်းပေးနိုင်မှသာ သုံးသင့်သည်။ အရေးကြီးသော workload များအတွက် စောင့်ကြည့်ထားပြီး စာချုပ်အရ သင့်လျော်သော အရန်စနစ် ရှိသင့်သည်။

### "ဘယ်လို အားနည်းချက်တွေရှိလဲ?"

အပေးအယူများတွင် တင်းကျပ်သော ကန့်သတ်ချက်များ၊ စောင့်ဆိုင်းစာရင်းများ၊ KYC၊ credit-card အတည်ပြုခြင်း၊
prompt များဖြင့် လေ့ကျင့်ခြင်း၊ ကိုယ်ရေးအချက်အလက်ကာကွယ်မှု အားနည်းခြင်း၊ SLA မရှိခြင်း၊ model မကြာခဏပြောင်းလဲခြင်း၊ ပထဝီဝင်ဆိုင်ရာ ကန့်သတ်ချက်များ၊ အခပေးပိုသုံးစွဲမှု သို့မဟုတ်
အကောင့်မူဝါဒဆိုင်ရာ အန္တရာယ်တို့ ပါဝင်နိုင်သည်။ OmniRoute က ရရှိနိုင်သော metadata ကို ဖော်ပြပေးပြီး မည်သည်တို့ကို ဖွင့်ထားမည်ကို သင်က ရွေးချယ်ရသည်။

### "အခမဲ့ quota ပိုရအောင် ဘယ်လိုလုပ်မလဲ?"

1. အခမဲ့ provider များကို ပိုမိုချိတ်ဆက်ပါ
2. သင့်လျော်သော compression engine များကို ဖွင့်ပြီး သင့် workload အတွက် ချွေတာနိုင်မှုကို တိုင်းတာပါ
3. အခမဲ့/စျေးသက်သာသော provider များကို ဦးစားပေးရန် `auto/cheap` ကို အသုံးပြုပါ
4. provider ၏ စည်းကမ်းချက်များကို မချိုးဖောက်ဘဲ ခွင့်ပြုထားသော provider သို့မဟုတ် credential များကို ထပ်ထည့်ပါ

### "အခမဲ့ provider တွေရဲ့ အရည်အသွေးက ပိုဆိုးသလား?"

မဖြစ်မနေ ပိုဆိုးသည်မဟုတ်ပါ။ အချို့ provider များသည် အခပေး
route များမှ ရရှိနိုင်သော model family များနှင့် တူညီသည့်အရာများကို ပေးထားသော်လည်း ကန့်သတ်ချက်များ၊ latency၊ ကိုယ်ရေးအချက်အလက်ကာကွယ်မှု၊ ယုံကြည်စိတ်ချရမှုနှင့် model version များသည် ကွာခြားနိုင်သည်။ အခမဲ့ Provider အဆင့်သတ်မှတ်ချက်များ စာမျက်နှာကို အရည်အသွေးညွှန်ပြချက်အဖြစ် အသုံးပြုပြီး အမှန်တကယ် ပံ့ပိုးပေးနေသော model ကို အတည်ပြုစစ်ဆေးပါ။
