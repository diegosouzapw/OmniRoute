## အခမဲ့အဆင့်များဆိုသည်မှာ အဘယ်နည်း?

AI ဝန်ဆောင်မှုပေးသူများစွာသည် **အခမဲ့အသုံးပြုခွင့်** ပုံစံတစ်မျိုးမျိုးကို ပေးထားပါသည်။ ဝန်ဆောင်မှုပေးသူအလိုက် ယင်းသည်
အထောက်အထားစိစစ်ရန်မလိုသော endpoint၊ ပုံမှန်ပြန်လည်ရရှိသည့် quota၊ နှုန်းကန့်သတ်ထားသော်လည်း စုစုပေါင်းပမာဏကန့်သတ်ချက်မရှိသော အသုံးပြုခွင့်၊ အကောင့်ဖွင့်လှစ်ခြင်းအတွက် grant၊
လူကိုယ်တိုင်အတည်ပြုချက် သို့မဟုတ် ယာယီ promotion တို့ကို ဆိုလိုနိုင်ပါသည်။ အချို့ရွေးချယ်စရာများတွင် အကောင့်၊ API key၊
credit card၊ KYC သို့မဟုတ် ဝန်ဆောင်မှုပေးသူအလိုက် သတ်မှတ်ထားသော စည်းကမ်းချက်များကို လက်ခံခြင်းတို့ လိုအပ်ပါသည်။

OmniRoute သည် စီစဉ်သတ်မှတ်ထားသော ချိတ်ဆက်မှုများကို endpoint တစ်ခုတည်းအဖြစ် **စုစည်းပေးပါသည်**။ အကောင့်လိုအပ်သည့် ဝန်ဆောင်မှုပေးသူတစ်ဦးစီအတွက် သီးခြားအကောင့်ဖွင့်ရန် လိုအပ်ဆဲဖြစ်ပါသည်။ ထိုအကောင့်များကို ချိတ်ဆက်ပြီး အကျုံးဝင်သော target များအကြား လမ်းကြောင်းရွေးချယ်ရန် `model: "auto"` ကို အသုံးပြုပါ။ အသစ်ထည့်သွင်းထားသော စနစ်တစ်ခုတွင် key မလိုဘဲ အသုံးပြုနိုင်သည့် အကျုံးဝင်သော target မရှိနိုင်ပါ။ OmniRoute ကို ထည့်သွင်းရုံမျှဖြင့် အောင်မြင်သော chat response တစ်ခု ရရှိမည်ဟု အာမခံမထားပါ။

## အခမဲ့အဆင့်များကို ပေါင်းစပ်အသုံးပြုနည်း

- key မလိုသော ဝန်ဆောင်မှုပေးသူကို အသုံးမပြုနိုင်လျှင် → ကျန်ရှိသော ပစ်မှတ်များကို ဆက်လက်စမ်းသပ်မည်
- အရည်အချင်းပြည့်မီသည့် ချိတ်ဆက်မှုတစ်ခုမျှ မအောင်မြင်လျှင် → အမှားတစ်ခုကို ပြန်ပေးမည်။ စာရင်းသွင်းခြင်းဖြင့်ရရှိသော ခရက်ဒစ်များကို သက်တမ်းရှိပြီး လက်ကျန်ရှိနေချိန်တွင်သာ အသုံးပြုနိုင်သည်

## ကတ်တလောက်ကို မှန်ကန်စွာ ဖတ်ရှုခြင်း

- `NOAUTH` ဆိုသည်မှာ OmniRoute က provider အထောက်အထားကို သင့်ထံမှ မတောင်းခံခြင်းဖြစ်သည်။ သို့သော် ဝန်ဆောင်မှု အမြဲရရှိနိုင်မှု၊ ကိုယ်ရေးအချက်အလက် လုံခြုံမှု သို့မဟုတ် အကန့်အသတ်မရှိ အသုံးပြုနိုင်မှုကို အာမခံခြင်း မဟုတ်ပါ။
- `hasFree` သည် ရှာဖွေဖော်ထုတ်ရန် အသုံးပြုသည့် metadata ဖြစ်သည်။ ၎င်းသည် ထပ်တလဲလဲ ရရှိသော quota၊ key မလိုဘဲ အသုံးပြုခွင့်၊ အကောင့်ဖွင့်လှစ်မှုအတွက် credit၊ အတည်ပြုခွင့်ပြုသည့် အစီအစဉ် သို့မဟုတ် ပရိုမိုးရှင်းကို ကိုယ်စားပြုနိုင်သည်။
- `recurring-uncapped` ဆိုသည်မှာ ထုတ်ပြန်ထားသော token အများဆုံးကန့်သတ်ချက်ကို မတွေ့ရှိနိုင်ခြင်းဖြစ်သည်။ သို့သော် rate နှင့် concurrency ကန့်သတ်ချက်များသည် ဆက်လက်သက်ရောက်ဆဲဖြစ်သည်။
- `one-time-initial` သည် အကောင့်ဖွင့်လှစ်စဉ် ပေးအပ်သည့် grant ကို အသုံးပြုပြီးနောက် ထပ်မံရရှိမည် မဟုတ်ပါ။
- `tos: avoid` ဟု သတ်မှတ်ထားသော provider များကို ပုံသေအားဖြင့် အလိုအလျောက် routing ပြုလုပ်ခြင်းမှ ဖယ်ထုတ်ထားသည် (`excludeTosAvoid`)။ အကောင့်တစ်ခုကို ချိတ်ဆက်ခြင်းဖြင့် ဤ filter ကို ကျော်လွှားနိုင်မည် မဟုတ်ပါ။ operator မှ ခြွင်းချက်ဖြင့် ပြောင်းလဲသတ်မှတ်ခြင်းတိုင်းကို provider ၏ စည်းမျဉ်းများနှင့် အကောင့်ဆိုင်ရာ အန္တရာယ်များအား ပြန်လည်သုံးသပ်ပြီးမှသာ ပြုလုပ်သင့်သည်။
- `discontinued` ဟု သတ်မှတ်ထားသော entry များသည် သမိုင်းဆိုင်ရာ အထောက်အထားအဖြစ် ဆက်လက်တည်ရှိပြီး လက်ရှိတွင် အခမဲ့ဖြစ်နေသကဲ့သို့ မဖော်ပြရပါ။

### 2. စမတ်ကျသော လမ်းကြောင်းရွေးချယ်မှု

တောင်းဆိုမှုတစ်ခုစီအတွက် **အကောင်းဆုံး အခမဲ့ဝန်ဆောင်မှုပေးသူ** ကို OmniRoute က အောက်ပါတို့အပေါ် အခြေခံ၍ ရွေးချယ်သည်-

- အမြန်နှုန်း — လက်ရှိတွင် မည်သည့်ဝန်ဆောင်မှုပေးသူက အမြန်ဆုံးဖြစ်သနည်း။
- အရည်အသွေး — ဤလုပ်ငန်းအတွက် မည်သည့်ဝန်ဆောင်မှုပေးသူက အကောင်းဆုံးဖြစ်သနည်း။
- စွမ်းဆောင်ရည် — မည်သည့်ဝန်ဆောင်မှုပေးသူတွင် ခွဲတမ်းကျန်ရှိသနည်း။

### 3. Token ချွေတာမှု

OmniRoute ၏ ချုံ့ခြင်း pipeline သည် ချုံ့နိုင်သော prompt နှင့် tool output token များကို လျှော့ချပေးနိုင်သည်။
အမှန်တကယ် ချွေတာနိုင်မှုသည် အကြောင်းအရာ၊ ရွေးချယ်ထားသော engine များ၊ ဝန်ဆောင်မှုပေးသူ၏ တွက်ချက်မှုပုံစံနှင့် မူရင်းအတိုင်း ထိန်းသိမ်းမှု
ဆက်တင်များအပေါ် မူတည်သည်။ ချုံ့ခြင်းက ဝန်ဆောင်မှုပေးသူတိုင်း၏ ခွဲတမ်းကို သတ်မှတ်ထားသော ဆတစ်ခုဖြင့် တိုးပွားစေခြင်းမဟုတ်ပါ။

### 4. အကောင့်အများအပြား ပံ့ပိုးမှု

ဝန်ဆောင်မှုပေးသူ၏ စည်းကမ်းချက်များက အကောင့် သို့မဟုတ် အထောက်အထားအချက်အလက် အများအပြားကို ခွင့်ပြုပါက OmniRoute သည်
ချိတ်ဆက်မှုတစ်ခုစီကို သီးခြားလမ်းကြောင်းရွေးချယ်မှု ကိုယ်စားလှယ်လောင်းတစ်ခုအဖြစ် သတ်မှတ်နိုင်သည်။ ဝန်ဆောင်မှုပေးသူ၏
ခွဲတမ်း သို့မဟုတ် အသုံးပြုခွင့်မူဝါဒကို ရှောင်လွှဲရန် အပိုအကောင့်များ မဖန်တီးပါနှင့်။

## မကြာခဏမေးလေ့ရှိသော မေးခွန်းများ

### "ဒါက တကယ်အခမဲ့လား?"

catalog တွင် provider များက ထုတ်ပြန်ထားသော စည်းကမ်းချက်များနှင့် project သုတေသနအချက်အလက်များကို မှတ်တမ်းတင်ထားသော်လည်း ကမ်းလှမ်းချက်များသည် ပြောင်းလဲနိုင်ပါသည်။
အသုံးမပြုမီ provider ၏ လက်ရှိစျေးနှုန်း၊ quota၊ ကိုယ်ရေးအချက်အလက် မူဝါဒနှင့် အရည်အချင်းပြည့်မီမှုတို့ကို အတည်ပြုစစ်ဆေးပါ။

### "အခမဲ့အဆင့်က ကုန်သွားနိုင်သလား?"

provider တိုင်းသည် အသုံးပြုနှုန်းကို ကန့်သတ်ခြင်း၊ model များ ပြောင်းလဲခြင်း၊ အသုံးပြုခွင့် ရပ်ဆိုင်းခြင်း သို့မဟုတ် ဝန်ဆောင်မှု ရပ်တန့်ခြင်းတို့ ပြုလုပ်နိုင်သည်။ connection အများအပြားသည် အရန်အသုံးပြုနိုင်မှုကို ကောင်းမွန်စေသော်လည်း
အသုံးပြုနိုင်သော အခမဲ့ route တစ်ခု အမြဲရှိမည်ဟု အာမမခံပါ။

### "ထုတ်လုပ်ရေးစနစ်အတွက် အခမဲ့ provider တွေကို သုံးလို့ရလား?"

provider ၏ SLA၊ ဒေတာကိုင်တွယ်ပုံ၊ ကန့်သတ်ချက်များနှင့် စည်းကမ်းချက်များက သင့်ထုတ်လုပ်ရေး
လိုအပ်ချက်များကို ဖြည့်ဆည်းပေးနိုင်မှသာ သုံးသင့်သည်။ အရေးကြီးသော workload များအတွက် စောင့်ကြည့်ထားပြီး စာချုပ်အရ သင့်လျော်သော အရန်စနစ် ရှိသင့်သည်။

### "ဘယ်လို အားနည်းချက်တွေရှိလဲ?"

အပေးအယူများတွင် တင်းကျပ်သော ကန့်သတ်ချက်များ၊ စောင့်ဆိုင်းစာရင်းများ၊ KYC၊ credit-card အတည်ပြုခြင်း၊
prompt များဖြင့် လေ့ကျင့်ခြင်း၊ ကိုယ်ရေးအချက်အလက်ကာကွယ်မှု အားနည်းခြင်း၊ SLA မရှိခြင်း၊ model မကြာခဏပြောင်းလဲခြင်း၊ ပထဝီဝင်ဆိုင်ရာ ကန့်သတ်ချက်များ၊ အခပေးပိုသုံးစွဲမှု သို့မဟုတ်
အကောင့်မူဝါဒဆိုင်ရာ အန္တရာယ်တို့ ပါဝင်နိုင်သည်။ OmniRoute က ရရှိနိုင်သော metadata ကို ဖော်ပြပေးပြီး မည်သည်တို့ကို ဖွင့်ထားမည်ကို သင်က ရွေးချယ်ရသည်။

### "အခမဲ့ quota ပိုရအောင် ဘယ်လိုလုပ်မလဲ?"

1. အခမဲ့ provider များကို ပိုမိုချိတ်ဆက်ပါ
2. သင့်လျော်သော compression engine များကို ဖွင့်ပြီး သင့် workload အတွက် ချွေတာနိုင်မှုကို တိုင်းတာပါ
3. အခမဲ့/စျေးသက်သာသော provider များကို ဦးစားပေးရန် `auto/cheap` ကို အသုံးပြုပါ
4. provider ၏ စည်းကမ်းချက်များကို မချိုးဖောက်ဘဲ ခွင့်ပြုထားသော provider သို့မဟုတ် credential များကို ထပ်ထည့်ပါ

### "အခမဲ့ provider တွေရဲ့ အရည်အသွေးက ပိုဆိုးသလား?"

မဖြစ်မနေ ပိုဆိုးသည်မဟုတ်ပါ။ အချို့ provider များသည် အခပေး
route များမှ ရရှိနိုင်သော model family များနှင့် တူညီသည့်အရာများကို ပေးထားသော်လည်း ကန့်သတ်ချက်များ၊ latency၊ ကိုယ်ရေးအချက်အလက်ကာကွယ်မှု၊ ယုံကြည်စိတ်ချရမှုနှင့် model version များသည် ကွာခြားနိုင်သည်။ အခမဲ့ Provider အဆင့်သတ်မှတ်ချက်များ စာမျက်နှာကို အရည်အသွေးညွှန်ပြချက်အဖြစ် အသုံးပြုပြီး အမှန်တကယ် ပံ့ပိုးပေးနေသော model ကို အတည်ပြုစစ်ဆေးပါ။
