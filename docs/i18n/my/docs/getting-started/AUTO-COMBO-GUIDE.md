## ၎င်းက ဘာလုပ်ပေးသလဲ

သတ်မှတ်ထားသော AI model တစ်ခု (ဥပမာ GPT-4o သို့မဟုတ် Claude) ကို ရွေးချယ်မည့်အစား request တစ်ခုချင်းစီအတွက် **အကောင်းဆုံးတစ်ခုကို အလိုအလျောက် ရွေးချယ်ရန်** OmniRoute ကို အသုံးပြုနိုင်သည်။ ၎င်းက အောက်ပါတို့ကို ထည့်သွင်းစဉ်းစားသည်-

- **လုပ်ဆောင်မှုအခြေအနေ** — Provider သည် ယခု လုပ်ဆောင်နေပါသလား။
- **မြန်နှုန်း** — မည်မျှမြန်ဆန်ပါသလဲ။
- **ကုန်ကျစရိတ်** — မည်မျှ ကုန်ကျပါသလဲ။
- **အရည်အသွေး** — ဤလုပ်ငန်းအမျိုးအစားကို ကောင်းစွာ လုပ်ဆောင်နိုင်ပါသလား။
- **စွမ်းဆောင်ရည်ပမာဏ** — အသုံးပြုနိုင်သည့် quota ကျန်ရှိပါသလား။

OmniRoute သည် သင်ချိတ်ဆက်ထားသော provider များအားလုံးကို အမှတ်ပေးပြီး အကောင်းဆုံးတစ်ခုကို ရွေးချယ်သည်။ ၎င်း မအောင်မြင်ပါက နောက်တစ်ခုကို အလိုအလျောက် စမ်းသပ်သည်။

## အမြန်စတင်ရန်

**အဆင့် 1**: သင့် IDE သို့မဟုတ် CLI တွင် model ကို `auto` ဟု သတ်မှတ်ပါ-

```
model: "auto"
```

**အဆင့် 2**: ဒါပါပဲ! ကျန်တာအားလုံးကို OmniRoute က ကိုင်တွယ်ပေးပါမည်။

**အဆင့် 3** (ရွေးချယ်နိုင်သည်): သတ်မှတ်ထားသော လုပ်ငန်းများအတွက် variant တစ်ခုကို အသုံးပြုပါ-

```
model: "auto/coding"    # ကုဒ်အတွက် အကောင်းဆုံး
model: "auto/fast"      # တုံ့ပြန်မှုအမြန်ဆုံး
model: "auto/cheap"     # ကုန်ကျစရိတ်အနည်းဆုံး ရွေးချယ်မှု
```

## လုပ်ဆောင်ပုံ (ရိုးရှင်းသော ဗားရှင်း)

`model: "auto"` ဖြင့် request တစ်ခုကို ပေးပို့သောအခါ OmniRoute သည်-

1. **သင်ချိတ်ဆက်ထားသော provider များအားလုံးကို ကြည့်ရှုသည်** — သင်ထည့်သွင်းထားသော provider တစ်ခုချင်းစီ (OpenAI၊ Anthropic၊ Google စသည်)
2. **တစ်ခုချင်းစီကို အမှတ်ပေးသည်**၊ အခြားအရာများအပြင် အောက်ပါတို့ကို ထည့်သွင်းတွက်ချက်သည်-
   - အလုပ်လုပ်နေပါသလား။ (လုပ်ဆောင်မှုအခြေအနေ)
   - စွမ်းဆောင်ရည်ပမာဏ ရှိပါသလား။ (quota)
   - မည်မျှ ကုန်ကျပါသလဲ။ (ဈေးနှုန်း)
   - မည်မျှမြန်ဆန်ပါသလဲ။ (မြန်နှုန်း)
   - ဤလုပ်ငန်းကို ကောင်းစွာ လုပ်ဆောင်နိုင်ပါသလား။ (အရည်အသွေး)
3. **အကောင်းဆုံးတစ်ခုကို ရွေးချယ်သည်** — အမှတ်အများဆုံး provider က သင့် request ကို လက်ခံရရှိသည်
4. **အလိုအလျောက် ပြန်လည်ဆောင်ရွက်သည်** — မအောင်မြင်ပါက OmniRoute သည် နောက်တစ်ခုကို အလိုအလျောက် စမ်းသပ်သည်

### အမှတ်ပေးစနစ်

Provider တစ်ခုချင်းစီသည် 0 မှ 1 အထိ အမှတ်ရရှိသည်။ အမှတ်မြင့်လေလေ ပိုမိုသင့်တော်လေလေ ဖြစ်သည်။

| အချက်                    | အလေးချိန် | ဆိုလိုသည်မှာ                                              |
| ------------------------ | --------- | --------------------------------------------------------- |
| လုပ်ဆောင်မှုအခြေအနေ      | 20%       | Provider သည် အလုပ်လုပ်နေပါသလား။ (circuit breaker အခြေအနေ) |
| Quota                    | 15%       | အသုံးပြုနိုင်သည့် စွမ်းဆောင်ရည်ပမာဏ ကျန်ရှိပါသလား။        |

| မြန်နှုန်း               | 12%       | မည်မျှမြန်ဆန်ပါသလဲ။ (latency ပိုနည်းလေ = အမှတ်ပိုမြင့်လေ) |
| လုပ်ငန်းနှင့် ကိုက်ညီမှု | 8%        | ဤလုပ်ငန်းအမျိုးအစားကို ကောင်းစွာ လုပ်ဆောင်နိုင်ပါသလား။    |
| တည်ငြိမ်မှု              | 5%        | တသမတ်တည်းရှိပါသလား။ (error rate နည်းခြင်း)                |

Variant တစ်ခုချင်းစီသည် မတူညီသော အလေးချိန်များကို အသုံးပြုသည်-

## ချို့ယွင်းမှုများကို ကိုင်တွယ်ပုံ

OmniRoute တွင် **ကာကွယ်မှု အလွှာသုံးဆင့်** ရှိသည်-

### 1. အလိုအလျောက် အရန်ပြောင်းခြင်း

အကောင်းဆုံး provider ချို့ယွင်းပါက OmniRoute သည် နောက်တစ်ခုကို အလိုအလျောက် စမ်းသုံးသည်။ သင် ဘာမှလုပ်ရန် မလိုပါ။

### 2. အလိုအလျောက် ပြန်လည်ကောင်းမွန်ခြင်း

provider တစ်ခု ဆက်တိုက်ချို့ယွင်းနေပါက-

- **Score < 0.2** → ၅ မိနစ်ကြာ ဖယ်ထုတ်ထားမည်
- **Circuit breaker open** → အလိုအလျောက် ဖယ်ထုတ်မည်
- **Provider များ၏ 50% ထက်ပို၍ အလုပ်မလုပ်ပါက** → ဖြစ်ရပ်အရေးပေါ်မုဒ် (စမ်းသပ်ရွေးချယ်မှု မပြုလုပ်ပါ)

### 3. အရေးပေါ် အရန်ပြောင်းခြင်း

provider အားလုံး ချို့ယွင်းပါက နောက်ဆုံးဖြေရှင်းချက်အဖြစ် OmniRoute သည် တည်ငြိမ်သော အခမဲ့ provider များ (Kiro သို့မဟုတ် Qoder ကဲ့သို့) ထံသို့ လမ်းကြောင်းပြောင်းပေးသည်။

---

## အကောင့်များစွာ ပံ့ပိုးမှု

provider တစ်ခုတည်းအတွက် အကောင့်များစွာ (ဥပမာ OpenAI key နှစ်ခု) ရှိပါက OmniRoute သည် တစ်ခုချင်းစီကို **သီးခြား ရွေးချယ်စရာ** အဖြစ် သတ်မှတ်သည်။ ဆိုလိုသည်မှာ-

- Account A တွင် quota ကျန်ရှိသည် → အသုံးပြုမည်
- Account B သည် rate-limited ဖြစ်နေသည် → ကျော်သွားမည်
- Account C က ပိုစျေးသက်သာသည် → ဦးစားပေးမည်

အကောင့်တစ်ခုချင်းစီကို ၎င်း၏ ကိုယ်ပိုင် ကျန်းမာရေးအခြေအနေ၊ quota နှင့် မြန်နှုန်းတို့အပေါ် အခြေခံ၍ သီးခြား အမှတ်ပေးသည်။

---

## Bandit စမ်းသပ်ရွေးချယ်မှု

ပိုကောင်းသော ရွေးချယ်စရာများကို ရှာဖွေရန် OmniRoute သည် provider အသစ်များကို ရံဖန်ရံခါ **စမ်းသပ်ရွေးချယ်** သည်-

- **မူလသတ်မှတ်ချက်**: request များ၏ 5% ကို ကျပန်း provider များထံ ပို့သည်
- **Auto/smart**: စမ်းသပ်ရွေးချယ်မှုနှုန်း 10%
- provider များ၏ 50% ထက်ပို၍ အခြေအနေမကောင်းသည့်အခါ **ပိတ်ထားမည်**

ဤလုပ်ဆောင်ချက်သည် သင့်အသုံးပြုပုံများအတွက် မည်သည့် provider များ အကောင်းဆုံးအလုပ်လုပ်သည်ကို OmniRoute က လေ့လာနိုင်ရန် ကူညီပေးသည်။

## မကြာခဏမေးလေ့ရှိသော မေးခွန်းများ

### "စျေးအကြီးဆုံး model ကို အမြဲရွေးမလား?"

**မရွေးပါ။** မူလသတ်မှတ်ချက်အရ ကုန်ကျစရိတ်သည် score ၏ 15% သာ ဖြစ်သည်။ စျေးသက်သာပြီး မြန်ဆန်ကာ အခြေအနေကောင်းသော provider သည် စျေးကြီးသော provider ထက် ပိုမိုဦးစားပေးခံရနိုင်သည်။ ကုန်ကျစရိတ်ကို ပိုမိုဦးစားပေးလိုပါက `auto/cheap` ကို အသုံးပြုပါ။

### "Provider တစ်ခု အလုပ်မလုပ်တော့လျှင် ဘာဖြစ်မလဲ?"

OmniRoute သည် ၎င်းကို အလိုအလျောက် ကျော်သွားပြီး နောက်တစ်ခုကို စမ်းသုံးသည်။ provider တစ်ခု ဆက်တိုက်ချို့ယွင်းနေပါက ၎င်းကို ယာယီ (၅-၃၀ မိနစ်) ဖယ်ထုတ်ထားမည်။ သင် ဘာမှလုပ်ရန် မလိုပါ။

### "ဘယ် provider ကို အသုံးပြုခဲ့လဲဆိုတာ ကြည့်နိုင်သလား?"

Response header များကို စစ်ဆေးပါ — OmniRoute သည် response တစ်ခုချင်းစီတွင် အသုံးပြုခဲ့သော provider နှင့် model ကို ထည့်သွင်းပေးသည်။

### "ကျွန်ုပ်၏ အသုံးပြုမှုမှ လေ့လာသလား?"

လေ့လာပါသည်! အမှတ်ပေးစနစ်သည် အချိန်ကြာလာသည်နှင့်အမျှ ပိုကောင်းသော ဆုံးဖြတ်ချက်များချနိုင်ရန် သမိုင်းဒေတာများ (latency၊ error rate များနှင့် success rate များ) ကို အသုံးပြုသည်။

### "`auto` နှင့် `auto/smart` အကြား ဘာကွာခြားသလဲ?"

- `auto` — မျှတသောပုံစံ၊ စမ်းသပ်ရွေးချယ်မှု 5%
- `auto/smart` — အရည်အသွေးဦးစားပေး (`auto/coding` နှင့် weight များ တူညီသည်)၊ စမ်းသပ်ရွေးချယ်မှု 10%

အကောင်းဆုံးအရည်အသွေးကို လိုချင်ပြီး ရံဖန်ရံခါ စမ်းသပ်ရွေးချယ်မှု ပြုလုပ်ခြင်းကို လက်ခံနိုင်ပါက `auto/smart` ကို အသုံးပြုပါ။

### "သတ်မှတ်ထားသော provider တစ်ခုကို အတင်းအကျပ် ရွေးချယ်ခိုင်းနိုင်သလား?"

ရနိုင်ပါသည်! `auto` အစား `priority` strategy ပါသော combo ကို အသုံးပြုပြီးနောက် combo ၏ **အမည်အတိအကျ** ကို `model` field အဖြစ် ပို့ပါ (ဥပမာ `model: "my-combo"` — `auto` မဟုတ်ပါ)။ အသေးစိတ်အတွက် [နည်းပညာဆိုင်ရာ ကိုးကားချက်](../routing/AUTO-COMBO.md) ကို ကြည့်ပါ။

### "ဤနည်းလမ်းသည် round-robin နှင့် မည်သို့ကွာခြားသလဲ?"

Round-robin သည် provider များကို အစဉ်လိုက် လှည့်လည်အသုံးပြုသည်။ Auto-combo သည် **provider တစ်ခုချင်းစီကို အမှတ်ပေး** ပြီး အကောင်းဆုံးတစ်ခုကို ရွေးချယ်သည်။ ၎င်းက ပိုမိုထက်မြက်ပြီး ကျန်းမာရေးအခြေအနေ၊ မြန်နှုန်း၊ ကုန်ကျစရိတ်နှင့် အရည်အသွေးတို့ကို ထည့်သွင်းစဉ်းစားသည်။

## ပိုမိုလေ့လာရန်

ဆော့ဖ်ဝဲရေးသားသူများနှင့် ပါဝင်ပံ့ပိုးသူများအတွက် အောက်ပါအကြောင်းအရာများကို [Auto-Combo နည်းပညာဆိုင်ရာ ကိုးကားချက်](../routing/AUTO-COMBO.md) တွင် ကြည့်ရှုပါ-

- အချက် 16 ချက်ပါ အမှတ်ပေး အယ်လ်ဂိုရီသမ် အပြည့်အစုံ
- Mode pack အလေးချိန်ဇယားများ
- အကောင်အထည်ဖော်မှု ဖိုင်လမ်းကြောင်းများ
- API endpoint များ
- အလိုအလျောက် ပြန်လည်ပြုပြင်သည့် အယ်လ်ဂိုရီသမ် အသေးစိတ်များ
