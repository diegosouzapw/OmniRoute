## ၎င်းသည် ဘာလဲ (နှင့် ဘာမဟုတ်သလဲ)

OmniRoute သည် token အရေအတွက်ကို model တစ်ခု၏ ဈေးနှုန်းနှုန်းထားများဖြင့် မြှောက်ခြင်းအားဖြင့်
ပြီးမြောက်သည့် တောင်းဆိုမှုတိုင်းအတွက် USD ကုန်ကျစရိတ်ကို သတ်မှတ်ပေးသည်။ ဤကိန်းဂဏန်းများကို **ကုန်ကျစရိတ်များ** dashboard၊
`omniroute cost` / `omniroute usage` CLI၊ CSV/JSON export များနှင့် API key တစ်ခုချင်းစီအလိုက် budget များတွင် အသုံးပြုသည်။

> **Dashboard ပေါ်ရှိ "ကုန်ကျစရိတ်" သည် ငွေတောင်းခံလွှာမဟုတ်ဘဲ ချွေတာမှု ခြေရာခံစနစ်တစ်ခု ဖြစ်သည်။** OmniRoute က သင့်ထံမှ မည်သည့်အခါမျှ ငွေကောက်ခံခြင်းမရှိပါ
> — ၎င်းသည် သင်ချိတ်ဆက်ထားပြီးဖြစ်သည့် provider များ (သင့်ကိုယ်ပိုင်
> subscription များ၊ အခမဲ့အဆင့်များနှင့် API key များ) ထံသို့ သင့်တောင်းဆိုမှုများကို လမ်းကြောင်းခွဲပေးခြင်းသာ ဖြစ်သည်။ အခမဲ့
> model များပေါ်တွင်သာ စုဆောင်းရရှိထားသည့် "$290 total cost" သည် အကြမ်းဖျင်းအားဖြင့် အခပေး API တစ်ခုအတွက်
> **သင် _မပေးခဲ့ရသည့်_ $290** ကို ဆိုလိုသည်။ ဤကိန်းဂဏန်းသည် တူညီသော traffic ကို ပုံမှန်ကြေညာထားသော ဈေးနှုန်းများဖြင့် အသုံးပြုခဲ့ပါက
> ကုန်ကျမည့်ပမာဏ၏ _ခန့်မှန်းချက်_ ဖြစ်သဖြင့် သင့်အသုံးပြုမှုသည် မည်သည့်နေရာတွင် အများဆုံး စုဝေးနေကြောင်းနှင့်
> ပိုမိုဈေးသက်သာသော/အခမဲ့ provider များထံ လမ်းကြောင်းခွဲပေးခြင်းကြောင့် မည်မျှ ချွေတာနိုင်ကြောင်း မြင်တွေ့နိုင်သည်။

ဤအဓိပ္ပာယ်သတ်မှတ်ချက်ကို project [README](../../README.md) တွင်လည်း တိုက်ရိုက်ဖော်ပြထားသည် ("dashboard ပေါ်ရှိ
'ကုန်ကျစရိတ်' သည် ငွေတောင်းခံလွှာမဟုတ်ဘဲ ချွေတာမှု ခြေရာခံစနစ်တစ်ခု ဖြစ်သည်")။

ဤကိန်းဂဏန်းသည် ခန့်မှန်းချက်တစ်ခု ဖြစ်သောကြောင့်-

- ၎င်းသည် model တစ်ခုချင်းစီအတွက် OmniRoute တွင်ရှိသော ဈေးနှုန်းဇယားပေါ် မူတည်သည်။ ဈေးနှုန်း
  ထည့်သွင်းထားခြင်းမရှိသည့် model သည် ကုန်ကျစရိတ် `0` အဖြစ် ပါဝင်မည် (explorer တွင် "Legacy / Free" အတန်းအဖြစ် ပြသမည်)။
- အခမဲ့အဆင့်နှင့် subscription traffic များအတွက်လည်း _ခန့်မှန်း_ ကုန်ကျစရိတ် စုဆောင်းတွက်ချက်ဆဲဖြစ်သည် — ၎င်းသည်
  သင်ချွေတာနေသည့်ပမာဏဖြစ်ပြီး ပေးရန်ရှိသည့်ပမာဏ မဟုတ်ပါ။

## ကုန်ကျစရိတ်များကို ခန့်မှန်းပုံ

### ဈေးနှုန်း အရင်းအမြစ်

ကုန်ကျစရိတ်များသည် အောက်ပါဦးစားပေးအစဉ်အတိုင်း သတ်မှတ်သည့် ဈေးနှုန်းဇယားမှ ရရှိသည်
([`src/lib/pricingSync.ts`](../../src/lib/pricingSync.ts))-

1. **အသုံးပြုသူ၏ ကိုယ်ပိုင်သတ်မှတ်ချက်များ** — dashboard တွင် / `PATCH /api/pricing` မှတစ်ဆင့် သင်သတ်မှတ်ထားသည့် ဈေးနှုန်းများ။
2. **စင့်ခ်လုပ်ထားသော ပြင်ပဈေးနှုန်းများ** — sync ဖွင့်ထားသည့်အခါ LiteLLM ၏ အများပြည်သူသုံး
   `model_prices_and_context_window.json` မှ ရယူသည် (သင့်ကိုယ်ပိုင်သတ်မှတ်ချက်များကို မည်သည့်အခါမျှ ထပ်ရေးမသွားစေရန် သီးခြား
   `pricing_synced` namespace တွင် သိမ်းဆည်းထားသည်)။
3. **Code ထဲတွင် ကြိုတင်သတ်မှတ်ထားသော မူလတန်ဖိုးများ** — OmniRoute နှင့်အတူ ထည့်သွင်းပေးထားသည်။

ပြင်ပဈေးနှုန်း sync သည် **ရွေးချယ်ဖွင့်ရသည့်စနစ်** ဖြစ်ပြီး မူလအခြေအနေတွင် ပိတ်ထားသည်။ သက်ဆိုင်ရာ env var များ
([`.env.example`](../../.env.example) ကို ကြည့်ပါ)-

| Env var                 | မူလတန်ဖိုး | ရည်ရွယ်ချက်                                                                        |
| ----------------------- | ---------- | ---------------------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`    | စတင်ချိန်တွင် နောက်ကွယ်မှ LiteLLM ဈေးနှုန်း sync ကို ဖွင့်ရန်။                     |
| `PRICING_SYNC_INTERVAL` | `86400`    | **စက္ကန့်** ဖြင့် sync ကြားကာလ (မူလမှာ နေ့စဉ်)။                                    |
| `PRICING_SYNC_SOURCES`  | `litellm`  | ကော်မာဖြင့် ခွဲထားသော အရင်းအမြစ်စာရင်း (လက်ရှိတွင် `litellm` ကိုသာ ပံ့ပိုးထားသည်)။ |

### ကုန်ကျစရိတ် တွက်ချက်ပုံသေနည်း

ကုန်ကျစရိတ်ကို token အရေအတွက်နှင့် token တစ်သန်းလျှင် နှုန်းထားများမှ တောင်းဆိုမှုတစ်ခုချင်းစီအလိုက် တွက်ချက်သည်-
[`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts)
(`computeCostFromPricing` / `calculateCost`)-

- **Input token များ** (cache ဖတ်ရှုမှုနှင့် cache ဖန်တီးမှု token များကို နုတ်ပြီး) × `input` နှုန်းထား။
- **Cache ဖတ်ရှုမှု token များ** × `cached` နှုန်းထား (`input` နှုန်းထားကို အစားထိုးအသုံးပြုသည်)။
- **Cache ဖန်တီးမှု token များ** × `cache_creation` နှုန်းထား (`input` နှုန်းထားကို အစားထိုးအသုံးပြုသည်)။
- **Output token များ** × `output` နှုန်းထား။
- **Reasoning token များ** × `reasoning` နှုန်းထား (`output` နှုန်းထားကို အစားထိုးအသုံးပြုသည်)။

နှုန်းထားအားလုံးကို token 1,000,000 လျှင် USD အဖြစ် သတ်မှတ်တွက်ချက်သည်။ Codex "fast"/"priority" သို့မဟုတ်
"flex" service tier သည် ကုန်ကျစရိတ် မြှောက်ဖော်ကိန်း (`getCodexFastCostMultiplier`) ကို အသုံးပြုသည် — ဥပမာ flex တွင်
token ကုန်ကျစရိတ်ကို 50% လျှော့တွက်ပြီး dashboard တွင် **flex ချွေတာမှု** အဖြစ် ဖော်ပြသည်။

ဦးစွာ model အမည်များကို စံပုံစံဖြစ်အောင် ပြောင်းလဲသည် (`openai/` သို့မဟုတ်
`accounts/fireworks/models/` ကဲ့သို့ provider လမ်းကြောင်း prefix များကို ဖယ်ရှားသည်)၊ ထို့ကြောင့် သမိုင်းမှတ်တမ်းအတန်းများသည်လည်း ဈေးနှုန်းနှင့် ကိုက်ညီနေဆဲ ဖြစ်သည်။

### အသုံးစရိတ်ကို မှတ်တမ်းတင်ပုံ

- တောင်းဆိုမှုတစ်ခုချင်းစီ၏ ကုန်ကျစရိတ်ကို response ရရှိပြီးနောက် တွက်ချက်ကာ client အတွက် latency
  လုံးဝမတိုးစေရန် fire-and-forget ပုံစံဖြင့် မှတ်တမ်းတင်သည်။ မျှဝေ quota အသုံးပြုမှုကို နောက်တစ်ကြိမ်
  event-loop tick တွင် လုပ်ဆောင်ရန် [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts) မှတစ်ဆင့် စီစဉ်သည်။
- API key အသုံးစရိတ်ကို buffer ထဲတွင် ထားရှိပြီး
  [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) က batch များဖြင့် သိမ်းဆည်းသည် (မူလ flush ကြားကာလ 60s၊
  entry 1,000 ပါသော buffer)။ အောက်ပါတို့မှတစ်ဆင့် ချိန်ညှိနိုင်သည်-

  | Env var                             | မူလတန်ဖိုး | ရည်ရွယ်ချက်                                                        |
  | ----------------------------------- | ---------- | ------------------------------------------------------------------ |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000`    | မီလီစက္ကန့်ဖြင့် flush ကြားကာလ။                                    |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`     | flush မလုပ်မီ buffer ထဲတွင် ထားနိုင်သည့် အများဆုံး entry အရေအတွက်။ |

Dashboard ၏ ကုန်ကျစရိတ်ကိန်းဂဏန်းများကို သိမ်းဆည်းထားသော အတန်းတစ်ခုချင်းစီ၏ dollar ပမာဏမှ **မဖတ်ယူပါ** — analytics endpoint အလုပ်လုပ်သည့်အခါတိုင်း
token အရေအတွက်နှင့် လက်ရှိဈေးနှုန်းဇယားမှ ချက်ချင်း ပြန်လည်တွက်ချက်သည်။ ဆိုလိုသည်မှာ မှားယွင်းသောဈေးနှုန်းကို ပြင်ဆင်ခြင်း (နှင့် ပြန်လည် sync လုပ်ခြင်း) သည်
သမိုင်းမှတ်တမ်းရှိ ကုန်ကျစရိတ်ခန့်မှန်းချက်များကို နောက်ကြောင်းပြန်၍ မွမ်းမံပေးသည်။

## Dashboard: ကုန်ကျစရိတ် စာမျက်နှာ

**ကုန်ကျစရိတ်** စာမျက်နှာသည် `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`) တွင် ရှိသည်။
၎င်း၏ အဓိကမြင်ကွင်းမှာ **ကုန်ကျစရိတ် အနှစ်ချုပ်** တက်ဘ်
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`) ဖြစ်ပြီး
`GET /api/usage/analytics` မှ အချက်အလက်အားလုံးကို ရယူသည်။

၎င်းတွင် ပြသသည့်အရာများ-

- **အသုံးစရိတ် အကွက်များ** — _ယနေ့ (1d)_, _7d_, _30d_ နှင့် ရွေးချယ်ထားသော
  ကာလအတွက် ခန့်မှန်းအသုံးစရိတ်။ ကာလရွေးချယ်မှု- `7d`, `30d`, `90d`, `all`။
- **အဓိက မက်ထရစ်များ** — ကာလအတွင်း တောင်းဆိုမှုများ၊ လက်ရှိအသုံးပြုနေသော provider များ၊ လက်ရှိအသုံးပြုနေသော model များနှင့် တောင်းဆိုမှုတစ်ခုလျှင် ပျမ်းမျှ
  ကုန်ကျစရိတ်။
- **ကုန်ကျစရိတ် လေ့လာစိစစ်ကိရိယာ** — **provider**, **model**,
  **API key**, **account** သို့မဟုတ် **service tier** အလိုက် အုပ်စုဖွဲ့ထားပြီး စီစဉ်နိုင်/စစ်ထုတ်နိုင်သော ဇယားတစ်ခုဖြစ်ကာ ကုန်ကျစရိတ်၊ တောင်းဆိုမှုများ၊ token များ၊ တောင်းဆိုမှုတစ်ခုလျှင် ပျမ်းမျှ
  ကုန်ကျစရိတ်နှင့် စုစုပေါင်း၏ ရာခိုင်နှုန်းဝေစုတို့ ပါဝင်သည်။
- **Token အသုံးပြုမှု** — စုစုပေါင်း / input / output token များနှင့် input:output အချိုး။
- **လမ်းကြောင်းခွဲဝေမှု ထိရောက်မှု** — fallback အရေအတွက်၊ fallback နှုန်းနှင့် တောင်းဆိုထားသော model လွှမ်းခြုံမှု။
- **လစဉ် ခန့်မှန်းချက်** — မကြာသေးမီ နေ့စဉ်ပျမ်းမျှကို အခြေခံ၍ လကုန်အသုံးစရိတ်ကို ခန့်မှန်းသည်။
- **ကာလ နှိုင်းယှဉ်ချက်** — ကာလ၏ ပထမတစ်ဝက်နှင့် ဒုတိယတစ်ဝက်အကြား ပြောင်းလဲမှု ရာခိုင်နှုန်း။
- **ဇယားကွက်များ** — နေ့စဉ်ကုန်ကျစရိတ် လမ်းကြောင်း၊ provider ဝေစု (စက်ဝိုင်းပုံ)၊ ထိပ်တန်း provider များ၊ ထိပ်တန်း model များ၊ API key အလိုက် ကုန်ကျစရိတ်၊ account အလိုက် ကုန်ကျစရိတ်၊ အပတ်စဉ် အသုံးပြုမှုပုံစံနှင့် လုပ်ဆောင်မှု heatmap။
- **ထုတ်ယူခြင်း** — လက်ရှိကာလကို **CSV** သို့မဟုတ် **JSON** အဖြစ် ဒေါင်းလုဒ်လုပ်နိုင်သည် (သုညမဟုတ်သော ကုန်ကျစရိတ်ဒေတာ ရှိလာသည့်အခါ
  ခလုတ်များ ပေါ်လာသည်)။

စျေးနှုန်းသတ်မှတ်ထားသော traffic မရှိသည့်အခါ အတန်းများတွင် `$0` အစား "အဟောင်း / အခမဲ့" အညွှန်းကို ပြသပြီး
ကုန်ကျစရိတ်သက်သာမှု ခြေရာခံသည့် model ကို ထင်ဟပ်စေသည်။

### ဆက်စပ် ကုန်ကျစရိတ် စာမျက်နှာခွဲများ

ကုန်ကျစရိတ် ဧရိယာတွင် (`/dashboard/costs/` အောက်၌) အောက်ပါတို့လည်း ပါဝင်သည်-

- **စျေးနှုန်းသတ်မှတ်ခြင်း** (`/dashboard/costs/pricing`) — model တစ်ခုချင်းစီ၏ စျေးနှုန်းများကို ကြည့်ရှုပြီး အစားထိုးသတ်မှတ်နိုင်သည် (မျှဝေထားသော Pricing တက်ဘ်ကို
  ပြသသည်)။
- **ဘတ်ဂျက်** (`/dashboard/costs/budget`) — scope တစ်ခုချင်းစီအလိုက် အသုံးစရိတ်ကန့်သတ်ချက်များ သတ်မှတ်နိုင်သည် (မျှဝေထားသော
  Budget တက်ဘ်ကို ပြသသည်)။
- **Quota မျှဝေမှု** (`/dashboard/costs/quota-share`) — မျှဝေထားသော quota pool များနှင့် သုံးစွဲနှုန်း
  မြင်ကွင်းများ။

### ဘတ်ဂျက်များ

| နည်းလမ်း | Endpoint                 | ရည်ရွယ်ချက်                                                                                         |

## CLI

OmniRoute ၏ CLI တွင် ကုန်ကျစရိတ်၊ အသုံးပြုမှုနှင့် ဈေးနှုန်းဆိုင်ရာ command များကို အသုံးပြုနိုင်သည် ([`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs) တွင် စာရင်းသွင်းထားသည်)။

### `omniroute cost`

`/api/usage/analytics` မှ စုစည်းထားသော ကုန်ကျစရိတ်အစီရင်ခံစာ။

```bash
omniroute cost                          # နောက်ဆုံး 30 ရက်၊ provider အလိုက် အုပ်စုဖွဲ့ထားသည်
omniroute cost --period 7d              # နောက်ဆုံး 7 ရက်
omniroute cost --group-by model         # provider | model | combo | api-key | day အလိုက် အုပ်စုဖွဲ့ရန်
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

ကော်လံများ- အုပ်စု၊ request အရေအတွက်၊ အဝင်/အထွက် token များ၊ ကုန်ကျစရိတ် (USD) နှင့် စုစုပေါင်း၏ ရာခိုင်နှုန်း။ နောက်ဆုံးတွင် စုစုပေါင်းစာကြောင်းကို ဖော်ပြသည် (`--quiet` သို့မဟုတ် `--output json` ဖြင့် ပိတ်ထားနိုင်သည်)။

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # provider တစ်ခုချင်းစီအလိုက် ကုန်ကျစရိတ်အကျဉ်းချုပ်
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# ဘတ်ဂျက်များ
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` သည် `GET /api/pricing/defaults` ကို ဖတ်ရှုသည်။ Model တစ်ခုချင်းစီ၏
> ဈေးနှုန်းများကို ပြင်ဆင်လိုပါက **Pricing** dashboard စာမျက်နှာ သို့မဟုတ် `PATCH /api/pricing` ကို အသုံးပြုပါ။

## ပြဿနာဖြေရှင်းခြင်း

- **ကုန်ကျစရိတ်အားလုံးတွင် $0 / "Legacy / Free" ဟု ဖော်ပြနေသည်။** အသုံးပြုနေသော model များအတွက် ဈေးနှုန်းထည့်သွင်းချက် မရှိပါ။
  ပြင်ပ sync ကို ဖွင့်ရန် (`PRICING_SYNC_ENABLED=true`) သတ်မှတ်ပြီး `omniroute pricing sync` ကို လုပ်ဆောင်ပါ၊ သို့မဟုတ်
  Pricing စာမျက်နှာ / `PATCH /api/pricing` မှတစ်ဆင့် ဈေးနှုန်းများကို ကိုယ်တိုင် သတ်မှတ်ပါ။
- **ယခင်က အသုံးပြုခဲ့သော model တစ်ခု၏ ဈေးနှုန်း မှားယွင်းနေသည်။** ဈေးနှုန်းကို ပြင်ဆင်ပါ (override လုပ်ခြင်း သို့မဟုတ် ပြန်လည် sync လုပ်ခြင်း) — analytics ကို ဖတ်ရှုသည့်အခါတိုင်း token အရေအတွက်များမှ ကုန်ကျစရိတ်ကို ပြန်လည်တွက်ချက်သောကြောင့် ခန့်မှန်းချက်များကို နောက်ကြောင်းပြန် အပ်ဒိတ်လုပ်ပေးသည်။
- **သုံးစွဲငွေပမာဏသည် အချိန်နှင့်တစ်ပြေးညီ မဖြစ်ဘဲ နောက်ကျနေသည်။** Key တစ်ခုချင်းစီ၏ သုံးစွဲငွေကို အစုလိုက် လုပ်ဆောင်သည်၊ ပိုမိုလတ်ဆတ်သော ကိန်းဂဏန်းများ လိုအပ်ပါက
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` ကို လျှော့ချပါ။
