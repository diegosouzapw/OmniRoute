## ထည့်သွင်းနည်းများ

### npm (အကြံပြုထားသည်)

```bash
npm install -g omniroute
omniroute
```

Dashboard ကို `http://localhost:20128` တွင် ဖွင့်မည်ဖြစ်ပြီး API အခြေခံ URL မှာ `http://localhost:20128/v1` ဖြစ်သည်။

### pnpm

```bash
pnpm add -g omniroute@latest --allow-build=better-sqlite3 --allow-build=@swc/core
omniroute
```

> **pnpm အသုံးပြုသူများ:** `better-sqlite3` နှင့် `@swc/core` အတွက် native build script များကို ဖွင့်ရန် `--allow-build` flag လိုအပ်သည်။ pnpm v11 တွင် global install များအတွက် `pnpm approve-builds -g` command ကို မပံ့ပိုးပါ။

### Arch Linux (AUR)

```bash
yay -S omniroute-bin
systemctl --user enable --now omniroute.service
```

[AUR package](https://aur.archlinux.org/packages/omniroute-bin) သည် OmniRoute ကို ထည့်သွင်းပေးပြီး systemd user service တစ်ခုကို ပံ့ပိုးပေးသည်။

### Source မှ

```bash
npm install
PORT=20128 DASHBOARD_PORT=20129 NEXT_PUBLIC_BASE_URL=http://localhost:20129 npm run dev
```

> **Windows မှတ်ချက်:** ပုံမှန်အားဖြင့် legacy `%USERPROFILE%\.omniroute` directory မရှိပါက OmniRoute သည် `%APPDATA%\omniroute` ကို အသုံးပြုသည်။ အခြား data-directory တည်နေရာကို ရွေးချယ်ရန် `DATA_DIR` ကို သတ်မှတ်ပါ။

> **မှတ်ချက်:** ပထမဆုံး run လုပ်ချိန်တွင် `npm install` သည် `.env.example` မှ `.env` ကို အလိုအလျောက် ထုတ်ပေးသည်။ နောက်ပိုင်း install များသည် ရှိပြီးသား `.env` ကို ထပ်ရေးမည်မဟုတ်သောကြောင့် စိတ်ကြိုက်ပြင်ဆင်မှုများကို ထိန်းသိမ်းထားမည်ဖြစ်သည်။ ပြန်လည်အစပြုရန် ထပ်မံ run မလုပ်မီ `.env` ကို ဖျက်ပါ။

### Docker

Compose profile များနှင့် Caddy HTTPS အပါအဝင် Docker စနစ်ထည့်သွင်းမှု အပြည့်အစုံအတွက် [Docker လမ်းညွှန်](./DOCKER_GUIDE.md) ကို ကြည့်ပါ။

### Desktop App (Electron)

OmniRoute တွင် Electron 41 + electron-builder 26.10 ကို အခြေခံတည်ဆောက်ထားသည့် desktop wrapper ပါဝင်သည်။ ရရှိနိုင်သော script များ (workspace root) မှာ-

```bash
npm run electron:dev          # hot-reload ဖြင့် desktop ကို run ပါ
npm run electron:build        # လက်ရှိ OS အတွက် build လုပ်ပါ (အလိုအလျောက် သိရှိသည်)
npm run electron:build:win    # Windows installer (NSIS + portable)
npm run electron:build:mac    # macOS (dmg + zip, arm64+x64)
npm run electron:build:linux  # Linux (AppImage + deb + rpm)
npm run electron:smoke:packaged  # package လုပ်ထားသည့် build ကို smoke-test လုပ်ပါ
```

Desktop installer release များကို GitHub Releases တွင် ပူးတွဲတင်ထားသည်။ Electron အကြောင်း အပြည့်အစုံ အသေးစိတ်လေ့လာရန် (signing၊ IPC bridge၊ distro များ) [`ELECTRON_GUIDE.md`](./ELECTRON_GUIDE.md) ကို ကြည့်ပါ _(နောက်ပိုင်းအဆင့်တွင် ဖန်တီးထားသည်)_။

### Headless server (CI/automation)

လူကိုယ်တိုင် ကြီးကြပ်ရန်မလိုသော စနစ်ထည့်သွင်းမှုများ (Docker၊ Kubernetes၊ CI) အတွက် အောက်ပါတို့ကို အသုံးပြုပါ-

```bash
omniroute setup --non-interactive
omniroute providers test-batch
```

၎င်းကို env var များ (`INITIAL_PASSWORD`, `OMNIROUTE_WS_BRIDGE_SECRET` စသည်) နှင့် တွဲဖက်အသုံးပြုခြင်းဖြင့် OmniRoute instance တစ်ခုကို script ဖြင့် အပြည့်အဝ စတင်နိုင်သည်။

### CLI ရွေးချယ်စရာများ

| Command                 | ဖော်ပြချက်                                                                                  |
| ----------------------- | ------------------------------------------------------------------------------------------- |
| `omniroute`             | Server ကို စတင်ပါ (`PORT=20128`၊ API နှင့် dashboard သည် port တစ်ခုတည်းတွင် ရှိသည်)         |
| `omniroute setup`       | Password နှင့် ပထမဆုံး provider အတွက် လမ်းညွှန်ပေးသော CLI onboarding                        |
| `omniroute doctor`      | Server ကို မစတင်ဘဲ local health check များကို လုပ်ဆောင်ပါ                                   |
| `omniroute providers`   | CLI မှ provider များကို ရှာဖွေ၊ စာရင်းပြုစု၊ အတည်ပြု၊ စမ်းသပ်ပါ                             |
| `omniroute config`      | CLI ကိရိယာ စီစဉ်သတ်မှတ်ခြင်း — config များကို စာရင်းပြုစု၊ ရယူ၊ သတ်မှတ်၊ အတည်ပြုပါ          |
| `omniroute status`      | Offline status dashboard — version၊ DB၊ ကိရိယာများ၊ config                                  |
| `omniroute logs`        | API မှ အသုံးပြုမှု log များကို stream လုပ်ပါ (`--follow` ကို ပံ့ပိုးသည်)                    |
| `omniroute update`      | OmniRoute update များကို စစ်ဆေးပါ သို့မဟုတ် အသုံးပြုပါ                                      |
| `omniroute provider`    | Provider ချိတ်ဆက်မှုများကို စီမံပါ — ထည့်၊ စာရင်းပြုစု၊ ဖယ်ရှား၊ စမ်းသပ်၊ default သတ်မှတ်ပါ |
| `omniroute --port 3000` | canonical/API port ကို 3000 အဖြစ် သတ်မှတ်ပါ                                                 |
| `omniroute --mcp`       | MCP server ကို စတင်ပါ (stdio transport)                                                     |
| `omniroute --no-open`   | Browser ကို အလိုအလျောက် မဖွင့်ပါနှင့်                                                       |
| `omniroute --help`      | အကူအညီကို ပြပါ                                                                              |

Headless စနစ်ထည့်သွင်းမှုကို flag များ သို့မဟုတ် environment variable များဖြင့် script ရေးသားနိုင်သည်-

```bash
omniroute setup --non-interactive --password "$OMNIROUTE_PASSWORD"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY"
omniroute setup --non-interactive --add-provider --provider openai --api-key "$OPENAI_API_KEY" --test-provider
```

Dashboard ကို မဖွင့်ဘဲ local diagnostic များကို လုပ်ဆောင်ပါ-

```bash
omniroute doctor
omniroute doctor --json
omniroute doctor --no-liveness
```

Dashboard ကို မဖွင့်ဘဲ SSH သို့မဟုတ် script များမှ provider များကို စီမံပါ-

```bash
omniroute providers available
omniroute providers available --search openai
omniroute providers available --category api-key
omniroute providers list
omniroute providers test <id-or-name>
omniroute providers test-all
omniroute providers validate
```

## CLI Tool ဖွဲ့စည်းသတ်မှတ်ခြင်း

### 1) Provider များကို ချိတ်ဆက်ပြီး API Key ဖန်တီးခြင်း

1. Dashboard → `Providers` ကိုဖွင့်ပြီး အနည်းဆုံး provider တစ်ခုကို ချိတ်ဆက်ပါ (OAuth သို့မဟုတ် API key)။
2. Dashboard → `Endpoints` ကိုဖွင့်ပြီး API key တစ်ခု ဖန်တီးပါ။
3. (ရွေးချယ်နိုင်သည်) Dashboard → `Combos` ကိုဖွင့်ပြီး သင်၏ fallback chain ကို သတ်မှတ်ပါ။

### 2) သင်၏ Coding Tool ကို ချိတ်ဆက်သတ်မှတ်ခြင်း

```txt
Base URL: http://localhost:20128/v1
API Key:  [copy from Endpoint page]
Model:    if/qwen3.8-max-preview (or any provider/model prefix)
```

သင်၏ editor က `Authorization: Bearer ...` ကို မပို့နိုင်ပါက၊ token ထည့်သွင်းထားသော compatibility base ကို အစားထိုးအသုံးပြုပါ-

```txt
Base URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/
Models URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/models
Chat URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/chat/completions
Ollama Tags URL: http://localhost:20128/api/v1/vscode/YOUR_KEY/api/tags
```

Claude Code၊ Codex CLI၊ Cursor၊ Cline၊ OpenClaw၊ OpenCode နှင့် OpenAI-compatible SDK များတွင် အသုံးပြုနိုင်သည်။

#### `setup-*` ဖြင့် အလိုအလျောက် ဖွဲ့စည်းသတ်မှတ်ခြင်း

Base URL နှင့် key ကို ကိုယ်တိုင်ထည့်သွင်းမည့်အစား၊ လက်ရှိ model catalog မှ tool တစ်ခုစီ၏ ကိုယ်ပိုင် config ကို OmniRoute အား ရေးသားခိုင်းနိုင်သည်။ Tool တစ်ခုစီအတွက် command တစ်ခုစီဖြစ်သည်-

```bash
omniroute setup-codex        # ~/.codex/<name>.config.toml ပရိုဖိုင်များ
omniroute setup-claude       # ~/.claude/profiles/<name>/settings.json
omniroute setup-opencode     # ~/.config/opencode/opencode.json (OpenAI နှင့် တွဲဖက်အသုံးပြုနိုင်သော)
omniroute setup-cline        # Cline CLI + VS Code extension ဆက်တင်များ
omniroute setup-kilo         # Kilo Code
omniroute setup-continue     # ~/.continue/config.yaml (Continue / cn)
omniroute setup-cursor       # Cursor အက်ပ်အတွင်း လုပ်ဆောင်ရမည့် အဆင့်များကို ပြသသည်
omniroute setup-roo          # Roo Code တင်သွင်းမှု + autoImport ညွှန်တံ
omniroute setup-crush        # ~/.config/crush/crush.json
omniroute setup-goose        # ~/.config/goose/config.yaml
omniroute setup-aider        # ~/.aider.conf.yml
omniroute setup-qwen         # ~/.qwen/settings.json + ~/.qwen/.env
```

တစ်ခုစီသည် local tool တစ်ခုကို **remote** OmniRoute နှင့် ချိတ်ဆက်ဖွဲ့စည်းရန် `--remote <url> --api-key <key>` ကို လက်ခံသကဲ့သို့၊ ကြိုတင်ကြည့်ရှုရန် `--dry-run` ကိုလည်း လက်ခံသည်။ မှန်ကန်သော env ကို ထည့်သွင်းပေးပြီး config တစ်စုံတစ်ရာ လုံးဝမရေးဘဲ CLI တစ်ခုကို စတင်ရန် ယေဘုယျ launcher ဖြစ်သော `omniroute run <target>` (claude, codex, aider, goose, opencode, qwen, gemini) ကို အသုံးပြုပါ။ ယခင် tool တစ်ခုချင်းစီအလိုက် launcher များဖြစ်သော `omniroute launch` (Claude Code) နှင့် `omniroute launch-codex` (Codex) တို့ကိုလည်း ဆက်လက်အသုံးပြုနိုင်သည်။

ဇယားအပြည့်အစုံ (command တစ်ခုစီက ရေးသားသည့်အရာ၊ flag အားလုံး၊ local နှင့် remote ကွာခြားချက်၊ base-URL `/v1` စံသတ်မှတ်ချက်များ) ကို **[CLI ပေါင်းစည်းအသုံးပြုမှုများ](./CLI-INTEGRATIONS.md)** တွင် ကြည့်ပါ။

Tool တစ်ခုချင်းစီအတွက် အသေးစိတ်ဖွဲ့စည်းသတ်မှတ်မှု (Claude Code၊ Codex CLI၊ Cursor၊ Cline၊ OpenClaw၊ Kilo Code၊ Copilot နှင့် အခြားအရာများ) ကို သီးခြား **[CLI Tools လမ်းညွှန်](../reference/CLI-TOOLS.md)** တွင် ကြည့်ပါ။

## Protocol ဖွဲ့စည်းသတ်မှတ်ခြင်း (MCP + A2A)

### MCP ဖွဲ့စည်းသတ်မှတ်ခြင်း (Model Context Protocol)

MCP transport ကို stdio mode ဖြင့် စတင်ပါ-

```bash
omniroute --mcp
```

အကြံပြုထားသော စစ်ဆေးအတည်ပြုမှု အဆင့်စဉ်-

```bash
# 1. MCP server ကို စတင်ပါ
omniroute --mcp

# 2. သင်၏ MCP client မှ အောက်ပါတို့ကို ခေါ်ဆိုပါ-
omniroute_get_health        # System health ကို ပြန်ပေးသင့်သည်
omniroute_list_combos       # လက်ရှိအသုံးပြုနေသော combos များကို ပြန်ပေးသင့်သည်

# 3. သို့မဟုတ် E2E suite အပြည့်အစုံကို run ပါ-
npm run test:protocols:e2e
```

#### MCP Client ဖွဲ့စည်းသတ်မှတ်ခြင်း

**Claude Code:**

```bash
claude mcp add-server omniroute --type http --url http://localhost:20128/api/mcp/stream
```

**Cursor / Cline:**

သင်၏ MCP ဆက်တင်များတွင် အောက်ပါတို့ကို ထည့်ပါ-

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"],
      "env": {}
    }
  }
}
```

**MCP စာရွက်စာတမ်းအပြည့်အစုံ:** [MCP Server README](../../open-sse/mcp-server/README.md) — tool 110 ခု၊ IDE config များ၊ Python/TS/Go client များ။

### A2A ဖွဲ့စည်းသတ်မှတ်ခြင်း (Agent-to-Agent Protocol)

Agent Card ကို စစ်ဆေးအတည်ပြုပါ-

```bash
curl http://localhost:20128/.well-known/agent.json
```

Task တစ်ခု ပို့ပါ-

```bash
curl -X POST http://localhost:20128/a2a \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":"quickstart","method":"message/send","params":{"skill":"quota-management","messages":[{"role":"user","content":"Give me a short quota summary."}]}}'
```

**A2A စာရွက်စာတမ်းအပြည့်အစုံ:** [A2A Server README](../../src/lib/a2a/README.md) — JSON-RPC 2.0၊ skill များ၊ streaming၊ task lifecycle။

## အချိန်ကုန်ဆုံးမှု သတ်မှတ်ခြင်း

### အခြေခံ အချိန်ကုန်ဆုံးမှုများ

Deployment အများစုအတွက် အောက်ပါ variable နှစ်ခုသာ လိုအပ်သည်-

| Variable                 | မူလတန်ဖိုး                        | ရည်ရွယ်ချက်                                                                                                                                                                                            |
| ------------------------ | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `REQUEST_TIMEOUT_MS`     | `600000`                          | Upstream တုံ့ပြန်မှုစတင်ချိန်ကုန်ဆုံးမှု၊ မမြင်ရသော Undici အချိန်ကုန်ဆုံးမှုများ၊ TLS fingerprint request များနှင့် API bridge request/proxy အချိန်ကုန်ဆုံးမှုများအတွက် မျှဝေသုံးစွဲသည့် အခြေခံတန်ဖိုး |
| `STREAM_IDLE_TIMEOUT_MS` | `REQUEST_TIMEOUT_MS` ကို ဆက်ခံသည် | OmniRoute က SSE stream ကို မရပ်တန့်မီ streaming chunk များကြား ခွင့်ပြုထားသည့် အများဆုံးကြာချိန်                                                                                                       |

နောက်ပြန်လိုက်ဖက်ညီမှုကို ဆက်လက်ထိန်းသိမ်းထားသည်- ရှိပြီးသား `FETCH_TIMEOUT_MS`၊ `API_BRIDGE_PROXY_TIMEOUT_MS` နှင့် layer တစ်ခုချင်းစီအလိုက် အခြား timeout variable များသည် ဆက်လက်အလုပ်လုပ်ပြီး မျှဝေသုံးစွဲသည့် အခြေခံတန်ဖိုးကို အစားထိုးသတ်မှတ်နိုင်သည်။

### Provider အလိုက် မှတ်ချက်များ

Claude Code နှင့် လိုက်ဖက်ညီသော upstream များ (`anthropic-compatible-cc-*`) အတွက် provider ဘက်ရှိ read timeout များကို သင်၏ env configuration နှင့် ကိုက်ညီနေစေရန် OmniRoute သည် outbound `X-Stainless-Timeout` header ကို ဖြေရှင်းသတ်မှတ်ပြီးသော fetch timeout မှ တွက်ချက်ရယူသည်။

Third-party Claude Code နှင့် လိုက်ဖက်ညီသော reverse proxy များအတွက် OmniRoute သည် မူလ `anthropic-beta` အစုကို ကန့်သတ်ထိန်းသိမ်းထားပြီး `Client Cache Control` ကို `Auto` အဖြစ်ထားသည့်အခါ client က ပေးပို့ထားသော `cache_control` marker များကိုသာ ဆက်လက်ပေးပို့သည်။ Upstream က ဖျောက်ထားသော Claude thinking stream များကို သီးသန့်လိုအပ်မှသာ connection တစ်ခုချင်းစီအလိုက် "ဖျောက်ထားသော thinking beta ကို ဖွင့်ရန်" toggle ကို ဖွင့်ပါ။

### အဆင့်မြင့် အချိန်ကုန်ဆုံးမှု အစားထိုးသတ်မှတ်ချက်များ

| Variable                                 | မူလတန်ဖိုး                                           | ရည်ရွယ်ချက်                                                                                  |
| ---------------------------------------- | ---------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `FETCH_TIMEOUT_MS`                       | `REQUEST_TIMEOUT_MS` ကို ဆက်ခံသည်                    | တုံ့ပြန်မှု header များ မရောက်ရှိမီအထိ အသုံးပြုသည့် upstream တုံ့ပြန်မှုစတင်ချိန်ကုန်ဆုံးမှု |
| `FETCH_HEADERS_TIMEOUT_MS`               | `FETCH_TIMEOUT_MS` ကို ဆက်ခံသည်                      | Upstream တုံ့ပြန်မှု header များကို လက်ခံရရှိရန် Undici ၏ အချိန်ကန့်သတ်ချက်                  |
| `FETCH_BODY_TIMEOUT_MS`                  | `FETCH_TIMEOUT_MS` ကို ဆက်ခံသည်                      | Upstream body chunk များကြား Undici ၏ အချိန်ကန့်သတ်ချက် (`0` က ၎င်းကို ပိတ်သည်)              |
| `FETCH_CONNECT_TIMEOUT_MS`               | `30000`                                              | Undici TCP connection အချိန်ကုန်ဆုံးမှု                                                      |
| `FETCH_KEEPALIVE_TIMEOUT_MS`             | `4000`                                               | Undici ၏ အသုံးမပြုဘဲ ရှိနေသော keep-alive socket အချိန်ကုန်ဆုံးမှု                            |
| `TLS_CLIENT_TIMEOUT_MS`                  | `FETCH_TIMEOUT_MS` ကို ဆက်ခံသည်                      | `wreq-js` မှတစ်ဆင့် ပြုလုပ်သော TLS fingerprint request များအတွက် အချိန်ကုန်ဆုံးမှု           |
| `API_BRIDGE_PROXY_TIMEOUT_MS`            | `REQUEST_TIMEOUT_MS` သို့မဟုတ် `600000` ကို ဆက်ခံသည် | API port မှ dashboard port သို့ `/v1` proxy forwarding အတွက် အချိန်ကုန်ဆုံးမှု               |
| `API_BRIDGE_SERVER_REQUEST_TIMEOUT_MS`   | `max(API_BRIDGE_PROXY_TIMEOUT_MS, 300000)`           | API bridge server ရှိ ဝင်လာသော request များအတွက် အချိန်ကုန်ဆုံးမှု                           |
| `API_BRIDGE_SERVER_HEADERS_TIMEOUT_MS`   | `60000`                                              | API bridge server ရှိ ဝင်လာသော header များအတွက် အချိန်ကုန်ဆုံးမှု                            |
| `API_BRIDGE_SERVER_KEEPALIVE_TIMEOUT_MS` | `5000`                                               | API bridge server ရှိ keep-alive အချိန်ကုန်ဆုံးမှု                                           |
| `API_BRIDGE_SERVER_SOCKET_TIMEOUT_MS`    | `0`                                                  | API bridge server ရှိ socket လှုပ်ရှားမှုမရှိခြင်း အချိန်ကုန်ဆုံးမှု (`0` က ၎င်းကို ပိတ်သည်) |

> **မှတ်ချက်:** Streaming request များအတွက် `FETCH_TIMEOUT_MS` သည် connection စတင်တည်ဆောက်ခြင်း / ပထမဆုံး upstream တုံ့ပြန်မှုကို စောင့်ဆိုင်းခြင်းကိုသာ အကျုံးဝင်သည်။ Stream အလုပ်လုပ်နေပြီဆိုသည်နှင့် OmniRoute သည် အမှန်တကယ် ရပ်တန့်နေခြင်း (`STREAM_IDLE_TIMEOUT_MS`) သို့မဟုတ် Undici body လှုပ်ရှားမှုမရှိခြင်း (`FETCH_BODY_TIMEOUT_MS`) ဖြစ်သည့်အခါမှသာ ရပ်တန့်မည်။

### Reverse Proxy လိုက်ဖက်ညီမှု

OmniRoute ကို Nginx၊ Caddy၊ Cloudflare သို့မဟုတ် အခြား reverse proxy တစ်ခု၏ နောက်ကွယ်တွင် အသုံးပြုပါက proxy timeout များသည် သင်၏ OmniRoute stream/fetch timeout များထက်လည်း ပိုမြင့်ကြောင်း သေချာစေပါ။

## Void Linux (xbps-src) Template

Void Linux အသုံးပြုသူများသည် `xbps-src` ကို အသုံးပြု၍ native package တစ်ခု တည်ဆောက်နိုင်ပါသည်။ ဤ block ကို `srcpkgs/omniroute/template` အဖြစ် သိမ်းဆည်းပါ-

```bash
# 'omniroute' အတွက် Template ဖိုင်
pkgname=omniroute
version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"
maintainer="zenobit <zenobit@disroot.org>"
license="MIT"
homepage="https://github.com/diegosouzapw/OmniRoute"
distfiles="https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz"
# Release တစ်ခုစီအတွက် checksum ကို အောက်ပါအတိုင်း ပြန်လည်ဖန်တီးပါ-
#   curl -L -o /tmp/omniroute.tar.gz "https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz" && sha256sum /tmp/omniroute.tar.gz
checksum=PLACEHOLDER_REGENERATE_PER_RELEASE
system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	NODE_ENV=development npm ci --ignore-scripts
	npm run build
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	rm -rf .next/standalone/node_modules/@img

	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
		touch "${DESTDIR}/usr/lib/omniroute/${_d}/.keep"
	done

	cat > "${WRKDIR}/omniroute" <<'EOF'
#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"
mkdir -p "${DATA_DIR}"
exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```
