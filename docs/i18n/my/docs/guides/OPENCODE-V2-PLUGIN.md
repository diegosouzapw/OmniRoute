`@omniroute/opencode-plugin-v2` သည် သင်၏ OmniRoute ကတ်တလောက်တစ်ခုလုံး — မော်ဒယ်များ၊ combo များနှင့်
auto-combo များ — ကို ပြသမည့်အမည်များ၊ ဈေးနှုန်းများနှင့် အခမဲ့အဆင့်
သုံးစွဲခွင့်ပမာဏများနှင့်အတူ OpenCode v2 ၏ မော်ဒယ်ရွေးချယ်ကိရိယာထဲသို့ ထည့်ပေးသည်။

၎င်းသည် `@omniroute/opencode-plugin` နှင့် သီးခြား package တစ်ခုဖြစ်သည်၊ အဘယ်ကြောင့်ဆိုသော် OpenCode v1 နှင့် v2 တို့သည်
plugin များကို မတူညီသော contract များဖြင့် load လုပ်သောကြောင့်ဖြစ်သည်။ သင်၏ OpenCode major version နှင့် ကိုက်ညီသည့်တစ်ခုကို
ရွေးချယ်ပါ။ ၎င်းတို့ကြားတွင် မည်သည့်အရာမျှ မျှဝေထားခြင်းမရှိသောကြောင့် တစ်ခုကို upgrade လုပ်ခြင်းက အခြားတစ်ခုကို မည်သည့်အခါမျှ အတင်းအကျပ် upgrade မလုပ်စေပါ။

## လိုအပ်ချက်များ

- OpenCode v2။
- ချိတ်ဆက်အသုံးပြုနိုင်သော OmniRoute gateway (`http://localhost:20128` ကို မူလအဖြစ် သတ်မှတ်ထားသည်)။
- Node.js 22 သို့မဟုတ် 24။

## ထည့်သွင်းခြင်း

Plugin ကို `opencode.json` ထဲသို့ ထည့်ပါ။

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

ထို့နောက် မော်ဒယ်များသည် `omniroute/<provider>/<model>` အဖြစ် ပေါ်လာမည်။ `providerId` က ထို prefix နှင့်
OpenCode က credential ကို သိမ်းဆည်းမည့် integration ၏ id ကို သတ်မှတ်သည်။

## အထောက်အထားများ

Plugin သည် gateway key ကို အောက်ပါနေရာသုံးခုတွင် အစဉ်လိုက် ရှာဖွေသည်။

1. **OpenCode တွင် သင်ချိတ်ဆက်ထားသော credential။** Plugin သည် integration တစ်ခုကို မှတ်ပုံတင်ပေးသောကြောင့်
   OpenCode ၏ ကိုယ်ပိုင် auth flow က key ကို သိမ်းဆည်းနိုင်သည်။ `opencode.json` ထဲသို့ မည်သည့်အရာမျှ မရောက်ရှိပါ — ဤနည်းကို ဦးစားပေးပါ။
2. Project တစ်ခုချင်းစီအလိုက် override လုပ်ရန် plugin options ထဲရှိ `apiKey`။ ၎င်းက key ကို သင်
   commit လုပ်နေနိုင်သည့် file တစ်ခုထဲတွင် ထည့်သွင်းထားမည်။
3. Environment ထဲရှိ `OMNIROUTE_API_KEY`။

သုံးခုလုံး မရှိပါက ကတ်တလောက်သည် ဗလာဖြစ်နေမည်ဖြစ်ပြီး plugin က အသံတိတ် ဗလာဖြစ်နေသော ရွေးချယ်ကိရိယာတစ်ခုကို
ထားပေးမည့်အစား စတင်ချိန်တွင် တစ်ကြိမ် အသိပေးမည်။

### စီမံခန့်ခွဲမှု token သည် မတူညီသော key တစ်ခုဖြစ်သည်

Combo များ၊ provider အခြေအနေနှင့် အချက်အလက်ဖြည့်စွက်ခြင်း (ပြသမည့်အမည်များ၊ ဈေးနှုန်းများ၊ အခမဲ့အဆင့် သုံးစွဲခွင့်ပမာဏများ) ကို
gateway ၏ `/api/*` endpoint များမှ ရယူသည်။ Deployment အများစုတွင် ၎င်း endpoint များကို inference key အစား
**management** token ဖြင့် ကာကွယ်ထားသည်။

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<management read token>"
}
```

`managementReadToken` ကို မသတ်မှတ်ထားပါက `apiKey` ကို အစားထိုးအသုံးပြုသည်။ Gateway က ထိုအစားထိုးအသုံးပြုမှုကို
ငြင်းပယ်သည့်အခါ ကတ်တလောက်ကို ဆက်လက်ထုတ်ပြန်ပေးမည်ဖြစ်သော်လည်း ပြသမည့်အမည်များအစား မူရင်း model id များသာ ပါမည်၊ canonical
alias ထပ်တူဖယ်ရှားခြင်း မရှိ၊ ဈေးနှုန်းများ မရှိသကဲ့သို့ combo များလည်း မရှိပါ။ ထိုသို့ဖြစ်သည့်အခါ plugin က endpoint တစ်ခုစီအတွက် တစ်ကြိမ်
သတိပေးပြီး endpoint နှင့် ဆုံးရှုံးသွားသည့်အရာကို ဖော်ပြပေးသည် — ထို့ကြောင့် လုပ်ဆောင်နိုင်စွမ်းလျော့နည်းနေသော ရွေးချယ်ကိရိယာသည် မည်သည့်အခါမျှ နားမလည်နိုင်စရာ မဖြစ်ပါ။

## ရွေးချယ်စရာများ

| Key                              | မူလတန်ဖိုး                                               | မှတ်ချက်များ                                                                                                                    |
| -------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `providerId`                     | `"omniroute"`                                            | Provider id၊ integration id နှင့် မော်ဒယ်များ ပေါ်လာမည့် prefix                                                                 |
| `baseURL`                        | လိုအပ်သည်                                                | Gateway root၊ `http(s)` သာဖြစ်ရမည်။ လိုအပ်သည့်နေရာတွင် `/v1` suffix ကို ထည့်ပေးသည်                                              |
| `apiKey`                         | ချိတ်ဆက်ထားသော credential၊ ထို့နောက် `OMNIROUTE_API_KEY` | `/v1/*` အတွက် chat key                                                                                                          |
| `managementReadToken`            | `apiKey` ကို အစားထိုးအသုံးပြုသည်                         | `/api/*` အတွက် key — ပုံမှန်အားဖြင့် **တူညီသော key မဟုတ်ပါ**                                                                    |
| `displayName`                    | `"OmniRoute"`                                            | ရွေးချယ်ကိရိယာထဲရှိ provider အမည်                                                                                               |
| `timeoutMs`                      | `10000`                                                  | Endpoint တစ်ခုစီအတွက် fetch timeout (auto-combo များက 5s အသုံးပြုသည်)                                                           |
| `modelCacheTtlMs`                | `300000`                                                 | ကတ်တလောက် cache TTL၊ disk snapshot တစ်ခုက cold start များကို အရှိန်မြှင့်ပေးသည်                                                 |
| `timeouts`                       | `timeoutMs` ကို အစားထိုးအသုံးပြုသည်                      | Endpoint တစ်ခုစီအတွက် ms ဖြင့် သတ်မှတ်ထားသော အချိန်ပမာဏများ: `models`, `combos`, `autoCombos`, `enrichment`                     |
| `enrichment`                     | `true`                                                   | အမည်များ၊ ဈေးနှုန်းများနှင့် အခမဲ့အဆင့် သုံးစွဲခွင့်ပမာဏများကို ရယူရန်                                                          |
| `providerTag`                    | `true`                                                   | ပြသမည့်အမည်၏ ရှေ့တွင် route လုပ်ပေးသည့် upstream provider ကို prefix အဖြစ် ထည့်ရန်                                              |
| `usableOnly`                     | `false`                                                  | Gateway က provisioned ဖြစ်သည်ဟု ဖော်ပြသော provider များကိုသာ ထားရှိရန်                                                          |
| `visibleModels` / `hiddenModels` | `[]`                                                     | အတိအကျ သို့မဟုတ် suffix ကိုက်ညီသော allowlist များ၊ deny က ဦးစားပေးသည်                                                           |
| `geminiSanitization`             | `true`                                                   | Tool schema များမှ Gemini က ငြင်းပယ်သော JSON-Schema keyword များကို ဖယ်ရှားရန် (`$ref` tool များကို မပြောင်းလဲဘဲ ဆက်လက်ပို့သည်) |
| `apiFormat.allowAnthropic`       | `false`                                                  | Allowlist ထဲရှိ id များကို Anthropic API block မှတစ်ဆင့် route လုပ်ရန်                                                          |
| `apiFormat.anthropicModels`      | `[]`                                                     | Anthropic သို့ route လုပ်မည့် model id အပြည့်အစုံများ                                                                           |
| `logLevel` / `startupDebug`      | `warn` / `false`                                         | Logger ၏ အသေးစိတ်မှတ်တမ်းတင်မှုအဆင့်                                                                                            |

## ကတ်တလောက်ကို နောက်ဆုံးအခြေအနေအတိုင်း ထိန်းသိမ်းပုံ

ကတ်တလောက်ကို လိုအပ်သည့်အချိန်မှသာ ရယူပြီး `modelCacheTtlMs` အတွက် cache လုပ်ထားသည်။ ထို့အပြင် gateway ကို ဆက်သွယ်၍မရသည့်အခါ နောက်ဆုံးသိရှိထားသော ကတ်တလောက်ကို ဆက်လက်အသုံးပြုနိုင်ရန် disk snapshot တစ်ခုက ထိန်းသိမ်းပေးထားသည် — ချို့ယွင်းမှုတစ်ခု ဖြစ်ပေါ်ပါက သင်ဆုံးရှုံးရမည့်အရာမှာ နောက်ဆုံးပေါ်ဖြစ်မှုသာ ဖြစ်သည်။ Models နှင့် combos များကို ရောက်ရှိလာသည်နှင့်တစ်ပြိုင်နက် ထုတ်ပြန်သည်။ auto-combos၊ provider စာရင်းနှင့် enrichment overlay တို့ကိုလည်း ရောက်ရှိလာချိန်တွင် ပေါင်းစည်းထည့်သွင်းသောကြောင့် နှေးကွေးသည့် endpoint တစ်ခုက picker တစ်ခုလုံးကို ပိတ်ဆို့ထားနိုင်မည် မဟုတ်ပါ။

အမည်များတွင် gateway သိရှိထားသည့် အချက်အလက်များ ပါဝင်သည်။ ၎င်းတို့မှာ model တစ်ခု ချိတ်ဆက်သွားသည့် upstream provider၊ `[Free]` အမှတ်အသားနှင့် ၎င်းနှင့်အတူ ပါလာသည့် budget တို့ဖြစ်သည် — ထို့ကြောင့် တူညီသော model ကို ရောင်းချသည့် connection နှစ်ခုကို ခွဲခြားသိရှိနိုင်သည်။ Prefix ကို ပိတ်ရန် `"providerTag": false` ကို သတ်မှတ်ပါ။

ကိုယ်တိုင် refresh လုပ်ရန် command မရှိပါ။ OpenCode v2 commands များသည် callbacks မဟုတ်ဘဲ prompt templates များဖြစ်သောကြောင့် plugin တစ်ခုက ထိုသို့သော command ကို ဖော်ထုတ်ပေးနိုင်ခြင်း မရှိပါ။ Refresh များသည် TTL အတိုင်း လုပ်ဆောင်သည်။ ကတ်တလောက် သို့မဟုတ် overlay အမှန်တကယ် ပြောင်းလဲသည့်အခါမှသာ host ကို reload လုပ်ရန် တောင်းဆိုပြီး refresh တိုင်းတွင် တောင်းဆိုခြင်း မရှိပါ။

## Gemini တွင် tool ခေါ်ယူခြင်း

Tool declarations များတွင် `$schema` သို့မဟုတ် `additionalProperties` ပါဝင်ပါက Gemini သည် request တစ်ခုလုံးကို ပယ်ချပြီး `400 INVALID_ARGUMENT` ဟု တုံ့ပြန်သည်။ Plugin သည် ဤ provider ၏ Gemini model သို့ ပို့မည့် tool schemas များမှ ထို keywords များကို ဖယ်ရှားပြီး အခြား request အားလုံးကို မပြောင်းလဲဘဲ ထားရှိသည်။ `$ref` ပါဝင်သော tool တစ်ခုကိုမူ မဖယ်ရှားဘဲ မူလအတိုင်း ဆက်လက်ပို့ပေးသည်။ အကြောင်းမှာ reference ကို ဖယ်ရှားလိုက်ပါက schema သည် "မည်သည့်အရာမဆို လက်ခံရန်" အထိ ကျယ်ပြန့်သွားမည်ဖြစ်သောကြောင့် ဖြစ်သည်။
၎င်းကို ပိတ်ရန် `"geminiSanitization": false` ဟု သတ်မှတ်ပါ။

## ပြဿနာဖြေရှင်းခြင်း

| လက္ခဏာ                                                       | အကြောင်းရင်း                                                                                                                                       |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Picker တွင် OmniRoute model မပြခြင်း                         | Key ကို မဖြေရှင်းနိုင်ခဲ့ခြင်း (စတင်ချိန် သတိပေးချက်ကို စစ်ဆေးပါ) သို့မဟုတ် gateway ကို ဆက်သွယ်၍မရခြင်း                                            |
| Model ids အကြမ်းများသာရှိပြီး combos နှင့် pricing မရှိခြင်း | Management endpoints များက token ကို ငြင်းပယ်ခဲ့ခြင်း — `managementReadToken` ကို သတ်မှတ်ပါ                                                        |
| Session တစ်ခုကို `opencode-<id>/…` တွင် pin လုပ်ထားခြင်း     | v1 plugin သည် `opencode-<id>` ကို ထုတ်ပြန်ခဲ့သည်။ v2 တွင် `<id>` ကို prefix မပါဘဲ ထုတ်ပြန်သောကြောင့် `<id>/…` အောက်ရှိ model ကို ပြန်လည်ရွေးချယ်ပါ |
