## 1. Antigravity နှင့် Antigravity CLI (agy) နှိုင်းယှဉ်ချက်

ပံ့ပိုးသူနှစ်ခုစလုံးသည် **တူညီသော Google backend** — တူညီသည့် OAuth client၊ token refresh၊ endpoints နှင့် Google accounts များကို မျှဝေအသုံးပြုသည်။ ကွာခြားချက်မှာ သင်မြင်ရသည့် မော်ဒယ်များဖြစ်သည်။

> Google ၏ တရားဝင်နှိုင်းယှဉ်ချက်အတွက် [Antigravity CLI ကြေညာချက်](https://antigravity.google/blog/introducing-google-antigravity-cli) ကို ကြည့်ပါ။

| အချက်                  | `antigravity` (IDE)                                                      | `agy` (CLI)                                                          |
| ---------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- |
| **Google ထုတ်ကုန်**    | Antigravity 2.0 / Antigravity IDE                                        | Antigravity CLI                                                      |
| **Backend**            | တူညီသော Google Cloud Code API                                            | တူညီသော Google Cloud Code API                                        |
| **OAuth / Token**      | တူညီသော client၊ တူညီသော refresh                                          | တူညီသော client၊ တူညီသော refresh                                      |
| **မော်ဒယ်စာရင်း**      | ကြိုတင်ရွေးချယ်ထားသည့် ပုံသေစာရင်း (OmniRoute တွင် hardcoded လုပ်ထားသည်) | `:fetchAvailableModels` မှတစ်ဆင့် Google ထံမှ တိုက်ရိုက်စစ်ဆေးရယူသည် |
| **Claude မော်ဒယ်များ** | Sonnet 4.6၊ Opus 4.6 (တစ်ခုစီတွင် မူကွဲ 4 မျိုး)                         | Sonnet 4.6၊ Opus 4.6 (တစ်ခုစီတွင် မူကွဲ 4 မျိုး)                     |
| **Gemini အမည်ပေးပုံ**  | ရှင်းလင်းသော အညွှန်းများ (Low/Medium/High)                               | မူလရင်းမြစ် IDs (extra-low/low/agent)                                |
| **အပိုမော်ဒယ်များ**    | `gpt-oss-120b-medium`                                                    | Google မှ နောက်ထပ်မော်ဒယ်များ ပါဝင်နိုင်သည်                          |
| **ပုံသေအသုံးပြုမှု**   | IDE ချိတ်ဆက်အသုံးပြုမှု (VS Code၊ JetBrains)                             | CLI / API အသုံးပြုခွင့်                                              |
| **Quota**              | agy နှင့် မျှဝေသည် (တူညီသော Google account)                              | antigravity နှင့် မျှဝေသည် (တူညီသော Google account)                  |

**ရရှိနိုင်သော မော်ဒယ်များ (စမ်းသပ်မှုဖြင့် အတည်ပြုထားသည်၊ 2026-07-29)**:

- Gemini: 3.6 Flash၊ 3.5 Flash၊ 3.1 Pro၊ 3 Flash၊ 2.5 Flash (thinking level အမျိုးမျိုး)
- Claude: Sonnet 4.6၊ Opus 4.6 (တစ်ခုစီတွင် default/low/medium/high မူကွဲများပါဝင်သည်)
- အခြား: GPT-OSS 120B Medium
- **Claude Sonnet 5 ကို အသုံးပြု၍မရပါ** — 4.6 မူကွဲများကိုသာ ပံ့ပိုးထားသည်

**မော်ဒယ်စာရင်း ကွာခြားရသည့်အကြောင်းရင်း**: Google ၏ CLI သည် "မြန်နှုန်းနှင့် အရင်းအမြစ်သုံးစွဲမှုနည်းပါးစေရန် အကောင်းဆုံးပြုလုပ်ထားသည်" ဖြစ်ပြီး "Gemini မော်ဒယ်များနှင့် ပူးတွဲအကောင်းဆုံးပြုလုပ်ထားသည်" (Google ၏ တရားဝင်ဘလော့ဂ်အရ)။ Web/IDE ထုတ်ကုန်သည် "ပြည့်စုံကျယ်ပြန့်မှုအတွက် အကောင်းဆုံးပြုလုပ်ထားသည်။" CLI သည် မော်ဒယ်များကို အလိုအလျောက်ရှာဖွေရန် `:fetchAvailableModels` ကို အသုံးပြုပြီး IDE သည် ကြိုတင်ရွေးချယ်ထားသည့် ပုံသေစာရင်းကို အသုံးပြုသည်။

**လက်တွေ့အသုံးပြုရာတွင်**: Gemini မော်ဒယ်များအတွက် `agy/` prefix ကို အသုံးပြုပါ (ဥပမာ `agy/gemini-3.7-flash-high`)။ ကြိုတင်ရွေးချယ်ထားသည့် ပုံသေစာရင်းအတွက် `antigravity/` ကို အသုံးပြုပါ။ နှစ်ခုစလုံးသည် တူညီသော Google backend ကို အသုံးပြုသော်လည်း မတူညီသော မော်ဒယ်အမည်ပေးပုံများကို ဖော်ပြသည်။ Quota ကို မျှဝေအသုံးပြုသည် — မည်သည့် provider ကိုမဆို အသုံးပြုခြင်းသည် တူညီသော Google account ၏ ကန့်သတ်ချက်များထဲတွင် ထည့်သွင်းတွက်ချက်သည်။

## 2. Google One AI Pro: Quota စနစ်

> တရားဝင် quota အသေးစိတ်အချက်အလက်များအတွက် [Antigravity Docs: Plans](https://antigravity.google/docs/plans) ကိုလည်းကောင်း၊ နောက်ဆုံးဈေးနှုန်းပြောင်းလဲမှုများအတွက် [Changes to Antigravity Plans](https://antigravity.google/blog/changes-to-antigravity-plans) ကိုလည်းကောင်း ကြည့်ပါ။

Google Antigravity သည် မက်ဆေ့ချ်အရေအတွက်အစား "Work Done" (တွက်ချက်မှုဆိုင်ရာ ဝန်ထုပ်ဝန်ပိုး) အပေါ် အခြေခံသည့် **နှစ်ဆင့် quota** ကို အသုံးပြုသည်။

### အဆင့်နှစ်ဆင့်

| အဆင့်                      | အဓိပ္ပာယ်                                               | ပြန်လည်သတ်မှတ်သည့် စက်ဝန်း                                                                                                      |
| -------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **၅ နာရီတာကာလ**            | ချက်ချင်းအသုံးပြုနိုင်သည့် "လုပ်ဆောင်ပြီးသောအလုပ်" ပမာဏ | session တစ်ခုအတွင်း ပထမဆုံးတောင်းဆိုမှု ပြုလုပ်ပြီးနောက် ၅ နာရီတွင် ပြန်လည်သတ်မှတ်သည်                                           |
| **၇ ရက်အခြေခံကန့်သတ်ချက်** | အပတ်စဉ် အမြင့်ဆုံးကန့်သတ်ချက်                           | ကန့်သတ်ချက်ပြည့်သွားပါက ၅ နာရီတစ်ကြိမ် ပြန်လည်သတ်မှတ်မှုကို ကျော်လွန်ပယ်ဖျက်ပြီး နောက်ထပ် ၇ ရက်တာကာလအထိ အသုံးပြုခွင့်ပိတ်ထားသည် |

**"Work Done" ကို တွက်ချက်ပုံ**: Agent ကို အဓိကအသုံးပြုရသော လုပ်ဆောင်ချက်များ (ဥပမာ "ဤ repository တစ်ခုလုံးကို refactor လုပ်ပါ") သည် ရိုးရှင်းသော လုပ်ဆောင်ချက်များ (ဥပမာ "ဤ function ကို ပြင်ပါ") ထက် quota ကို ပိုမိုမြန်ဆန်စွာ ကုန်ဆုံးစေသည်။ သုံးစွဲမှုကို အချိန်နှင့်တစ်ပြေးညီ ပြသသည့် dashboard မရှိပါ။

### Gemini နှင့် Gemini မဟုတ်သော Model များ

- **Gemini model များ** (Flash + Pro): API ဈေးနှုန်းအလိုက် နုတ်ယူသည့် rate limit တစ်ခုတည်းကို မျှဝေအသုံးပြုသည်။ Flash သည် Pro ထက် 8x ပိုဈေးသက်သာပါက Flash token များကို 8x ပိုမိုရရှိမည်။
- **Gemini မဟုတ်သော model များ** (Claude, GPT-OSS): **သီးခြား** rate limit များရှိသည်။ Gemini ကို အသုံးပြုခွင့်ပိတ်ထားသည့်အချိန်တွင်ပင် ၎င်းတို့ကို ဆက်လက်အသုံးပြုနိုင်ဖွယ်ရှိသည်။

### AI Credit များ (သတ်မှတ်ပမာဏထက် ကျော်လွန်သုံးစွဲမှု)

> Credit များ၏ အလုပ်လုပ်ပုံကို သိရှိရန် [Google One AI credits](https://support.google.com/googleone/answer/14534406) ကို ကြည့်ပါ။

အခြေခံ quota ကုန်ဆုံးသွားသည့်အခါ-

- **ဘယ်တော့မှ မသုံးပါ**: Quota ပြန်လည်သတ်မှတ်သည်အထိ စောင့်ဆိုင်းပြီး "Baseline model quota reached" ဟု ပြသသည်
- **အမြဲသုံးပါ**: AI credit များကို အလိုအလျောက်အသုံးပြုပြီး အခြေခံ quota ပြန်လည်သတ်မှတ်သည့်အခါ ၎င်းထံ ပြန်လည်ပြောင်းသည်

Credit များကို သီးခြားဝယ်ယူရပြီး စံ API ဈေးနှုန်းအတိုင်း နုတ်ယူသည်။

### အဓိကအသေးစိတ်အချက်များ

- Quota ကို **account အဆင့်တွင် မျှဝေအသုံးပြုသည်** — Antigravity IDE၊ CLI နှင့် OmniRoute တို့တွင် Google account တစ်ခုတည်းကို အသုံးပြုပါက quota ပမာဏတစ်ခုတည်းကို မျှဝေသုံးစွဲသည်
- Google account တစ်ခုစီတွင် သီးခြားလွတ်လပ်သော quota ရှိသည် — account အများအပြား = quota ပမာဏအများအပြား
- AI Pro အသုံးပြုသူများသည် အပတ်စဉ်အခြေခံကန့်သတ်ချက် ပြည့်သွားသည့်အခါ ၅ နာရီတစ်ကြိမ် ပြန်လည်သတ်မှတ်မှုအစား **၇ ရက်ကြာ အသုံးပြုခွင့်ပိတ်ခြင်း** ကြုံတွေ့ရကြောင်း အစီရင်ခံထားသည် (အသုံးပြုမှုမြင့်မားသည့်အချိန်များအတွက် ရည်ရွယ်ဒီဇိုင်းပြုလုပ်ထားခြင်းဖြစ်ကြောင်း Google က အတည်ပြုထားသည်)

**သင့် account ၏ quota ကုန်ဆုံးသွားသည့်အခါ**: OmniRoute သည် combo route ထဲရှိ နောက်ထပ်အသုံးပြုနိုင်သော account ဖြင့် အလိုအလျောက် ပြန်လည်ကြိုးစားသည်။ ကိုယ်တိုင်ဝင်ရောက်ဆောင်ရွက်ရန် မလိုအပ်ပါ။

## 3. projectId ရယူနည်း

antigravity/agy connection တိုင်းတွင် Google Cloud Code `projectId` တစ်ခု လိုအပ်သည်။ ၎င်းမရှိပါက `/v1internal:models` endpoint သည် 404 ကို ပြန်ပေးသည်။

### နည်းလမ်း A: အလိုအလျောက် (အကြံပြုထားသည်)

OmniRoute က ဤလုပ်ငန်းစဉ်ကို အလိုအလျောက် ကိုင်တွယ်ပေးသည်။ Dashboard OAuth မှတစ်ဆင့် Google account အသစ်တစ်ခု ထည့်သည့်အခါ-

1. OmniRoute သည် token ကို refresh လုပ်သည်
2. projectId ကို ရှာဖွေဖော်ထုတ်ရန် `loadCodeAssist` ကို ခေါ်သည်
3. Project မရှိပါက တစ်ခုဖန်တီးရန် `onboardUser` ကို ခေါ်သည်
4. အသစ်ဖန်တီးထားသော projectId ကို ရယူရန် `loadCodeAssist` ကို ထပ်မံကြိုးစားသည်
5. ၎င်းကို database ထဲသို့ သိမ်းဆည်းသည်

**ဤနည်းလမ်းသည် account အများစုအတွက် အလုပ်လုပ်သည်** — ကိုယ်တိုင်လုပ်ဆောင်ရမည့် အဆင့်များ မလိုအပ်ပါ။

### နည်းလမ်း B: agy CLI မှတစ်ဆင့် ကိုယ်တိုင်လုပ်ဆောင်ခြင်း

အလိုအလျောက်ရှာဖွေမှု မအောင်မြင်ပါက (မည်သည့်အချိန်တွင် ဖြစ်ပေါ်ကြောင်း အပိုင်း 5 တွင် ကြည့်ပါ)-

```bash
# agy CLI ကို ထည့်သွင်းပါ (မထည့်သွင်းရသေးပါက)
npm install -g @anthropic-ai/agy

# သင့် Google account ဖြင့် login ဝင်ပါ
agy login

# Onboarding လုပ်ရန်လိုအပ်သော account ကို ရွေးချယ်ပါ
# ဤလုပ်ဆောင်ချက်သည် Cloud Code မှတ်ပုံတင်ခြင်းကို စတင်ပြီး projectId တစ်ခု သတ်မှတ်ပေးသည်
```

`agy login` အောင်မြင်ပြီးနောက် OmniRoute Dashboard တွင် token ကို refresh လုပ်ပါ။ projectId ကို အလိုအလျောက် ရှာဖွေဖော်ထုတ်မည်။

### စစ်ဆေးအတည်ပြုနည်း

## 4. OAuth Redirect URI

### ပြဿနာ

Google OAuth သည် မှန်ကန်သော redirect URI တစ်ခု လိုအပ်သည်။ OmniRoute ၏ မူလသတ်မှတ်ချက်သည် `http://127.0.0.1:20128/callback` (loopback) ကို အသုံးပြုသည်။ ၎င်းသည် local build များအတွက် အလုပ်လုပ်သော်လည်း **အဝေးမှ ဖြန့်ကျက်အသုံးပြုမှုများတွင် အလုပ်မလုပ်ပါ** (ဥပမာ၊ LAN IP မှတစ်ဆင့် ဝင်ရောက်အသုံးပြုသော server တစ်ခု)။

Google သည် အောက်ပါ redirect URI များကို ငြင်းပယ်သည်-

- IP address များကို အသုံးပြုထားခြင်း (`.com`၊ `.org` စသည်ဖြင့် အဆုံးသတ်သော domain တစ်ခု ဖြစ်ရမည်)
- OAuth client config တွင် မှတ်ပုံတင်ထားသော redirect URI များနှင့် မကိုက်ညီခြင်း

### ဖြေရှင်းနည်း

**ရွေးချယ်မှု A: အသင့်ပါရှိသော OAuth flow ကို အသုံးပြုခြင်း (မူလသတ်မှတ်ချက်)**

- OmniRoute ကို `localhost` သို့မဟုတ် `127.0.0.1` မှ ဝင်ရောက်အသုံးပြုသည့်အခါ အလုပ်လုပ်သည်
- မည်သည့် configuration မျှ မလိုအပ်ပါ

**ရွေးချယ်မှု B: စိတ်ကြိုက် OAuth credentials**

- သင့် environment တွင် `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` ဟု သတ်မှတ်ပါ
- သင့်ကိုယ်ပိုင် Google OAuth credentials များကို ထည့်သွင်းပါ-
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Google Cloud Console တွင် `https://your-domain.com/callback` ကို ခွင့်ပြုထားသော redirect URI အဖြစ် မှတ်ပုံတင်ပါ

**ရွေးချယ်မှု C: ကနဦး login အတွက် agy CLI ကို အသုံးပြုခြင်း**

- OmniRoute ကို ဝင်ရောက်အသုံးပြုမည့် စက်ပေါ်တွင် `agy login` ကို လုပ်ဆောင်ပါ
- OAuth flow သည် local တွင် ပြီးစီးပြီး token များကို သိမ်းဆည်းထားမည်
- Dashboard မှတစ်ဆင့် connection ကို OmniRoute ထဲသို့ ထည့်သွင်းပါ

### ကန့်သတ်ချက်များ

- စိတ်ကြိုက် OAuth credentials များအတွက် domain name တစ်ခု လိုအပ်သည် (Google သည် IP address များကို redirect URI အဖြစ် လက်မခံပါ)
- သင့်တွင် domain မရှိပါက ရွေးချယ်မှု A သို့မဟုတ် C ကို အသုံးပြုပါ

## 5. ပြဿနာဖြေရှင်းခြင်း: အလိုအလျောက် စနစ်ထည့်သွင်းမှု မအောင်မြင်သည့်အခါ

OmniRoute သည် account အများစုအတွက် projectId ရှာဖွေခြင်းနှင့် onboarding ပြုလုပ်ခြင်းကို အလိုအလျောက် ကိုင်တွယ်ပေးသည်။ မအောင်မြင်သည့်အခါ အရင်းခံအကြောင်းရင်းသည် များသောအားဖြင့် အောက်ပါအချက်များထဲမှ တစ်ခုဖြစ်သည်-

### Account region ကို ပိတ်ဆို့ထားခြင်း

**လက္ခဏာ**: `agy login` သည် "Eligibility check failed: Your current account is not eligible for Antigravity, because it is not currently available in your location." ဟု ပြန်ပေးသည်။

**အရင်းခံအကြောင်းရင်း**: Google account များတွင် မှတ်ပုံတင်ချိန်၌ သတ်မှတ်ထားသော backend "Country Association" field တစ်ခု ရှိသည်။ လက်ရှိ IP ကိုသာ စစ်ဆေးသည့် web Gemini နှင့် မတူဘဲ agy CLI နှင့် Cloud Code API တို့သည် ဤ field ကို တင်းကျပ်စွာ စစ်ဆေးသည်။

> သင့် account နှင့် ဆက်စပ်ထားသော region ကို စစ်ဆေးရန် သို့မဟုတ် ပြောင်းလဲရန် [Google Country Association Form](https://policies.google.com/country-association-form) သို့ သွားရောက်ပါ။

**web Gemini အလုပ်လုပ်သော်လည်း agy အလုပ်မလုပ်ရသည့် အကြောင်းရင်း**-

- Web Gemini / Google One: လက်ရှိ IP ကိုသာ စစ်ဆေးသည် (proxy ဖြင့် အောင်မြင်နိုင်သည်)
- agy CLI / Cloud Code API: backend Country Association field ကို ဖတ်ရှုသည် (proxy က မကူညီနိုင်ပါ)

**ပြင်ဆင်နည်း**:

1. US IP ကို အသုံးပြုနေစဉ် [Google Country Association Form](https://policies.google.com/country-association-form) သို့ သွားရောက်ပါ
2. Region ပြောင်းလဲရန် တောင်းဆိုချက်ကို တင်သွင်းပါ ("I live in a different country" ကို ရွေးချယ်ပါ)
3. Google က လုပ်ဆောင်ပြီး email အသိပေးချက် ပေးပို့ရန် 1-24 နာရီ စောင့်ပါ
4. ထို့နောက် `agy login` အောင်မြင်သင့်သည်

### Account တွင် Cloud Code project မရှိခြင်း

**လက္ခဏာ**: Log များတွင် `loadCodeAssist returned no project id` နှင့် `onboardUser failed (400)` ဟု ပြသသည်။

**အရင်းခံအကြောင်းရင်း**: Account ကို Google Cloud Code ဖြင့် တစ်ခါမျှ မှတ်ပုံတင်ထားခြင်းမရှိဘဲ အလိုအလျောက် onboarding ပြုလုပ်မှု မအောင်မြင်ခဲ့ခြင်း ဖြစ်သည်။

**ပြင်ဆင်နည်း**: Cloud Code မှတ်ပုံတင်ခြင်းကို စတင်ရန် `agy login` ကို ကိုယ်တိုင် လုပ်ဆောင်ပြီးနောက် OmniRoute Dashboard တွင် token ကို refresh လုပ်ပါ။

### Token သက်တမ်းကုန်ဆုံးခြင်း သို့မဟုတ် ပြန်လည်ရုပ်သိမ်းခံရခြင်း

**လက္ခဏာ**: Log များတွင် 401 error များ သို့မဟုတ် "Token has expired" message များ ပေါ်လာသည်။

**ပြင်ဆင်နည်း**: Dashboard → Providers → agy → refresh icon ကို နှိပ်၍ token ကို refresh လုပ်ပါ။ refresh token ကိုယ်တိုင် ပြန်လည်ရုပ်သိမ်းခံထားရပါက OAuth မှတစ်ဆင့် ထပ်မံ authenticate လုပ်ရန် လိုအပ်မည်ဖြစ်သည်။
