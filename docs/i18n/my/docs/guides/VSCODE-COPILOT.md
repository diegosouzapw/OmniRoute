## စနစ်ထည့်သွင်းခြင်း

1. **OmniRoute ကို ဖွင့်ပါ** — `npm install -g omniroute && omniroute` (`http://localhost:20128` တွင် dashboard ရှိသည်)။
2. **Extension ကို ထည့်သွင်းပါ** — Extensions view တွင် "OmniRoute" ကို ရှာပါ။
3. **Model တစ်ခုကို ရွေးပါ** — Copilot Chat → model picker → **Manage Models…** → **OmniRoute** သို့သွားပြီးနောက်
   သင်အသုံးပြုလိုသည့် model များကို အမှန်ခြစ်ပါ။

OmniRoute သည် မူလ port ပေါ်တွင် လည်ပတ်နေပါက ဘာမှ configure လုပ်ရန်မလိုပါ။ Remote instance အတွက်
**Activity Bar ရှိ OmniRoute icon** ကို ဖွင့်ပါ (သို့မဟုတ် `OmniRoute: Manage Connection` ကို run လုပ်ပါ)၊ ထို့နောက် အောက်ပါတို့ကို သတ်မှတ်ပါ-

- **Server URL** — server root၊ ဥပမာ `http://192.168.0.15:20128`။ `/v1` suffix ကို
  extension က ထပ်ဖြည့်ပေးမည်ဖြစ်သောကြောင့် မထည့်ပါနှင့်။
- **API key** — server က `REQUIRE_API_KEY` ကို သတ်မှတ်ထားမှသာ လိုအပ်သည်။ VS
  Code SecretStorage မှတစ်ဆင့် OS keychain တွင် သိမ်းဆည်းထားပြီး `settings.json` ထဲတွင် မည်သည့်အခါမျှ မသိမ်းပါ။

## Picker တွင် ပြသမည့်အရာများ

Extension သည် မူရင်း `GET /v1/models` payload ကို တိုက်ရိုက်မပြသပါ — ၎င်းကို လိုအပ်သလို ပြင်ဆင်ပေးသဖြင့် သင်မြင်ရသည့်
အရေအတွက်သည် ရည်ရွယ်ချက်ရှိသော အကြောင်းရင်းနှစ်ခုကြောင့် catalog အရွယ်အစားထက် နည်းပါသည်။

### Model တစ်ခုလျှင် id တစ်ခုကိုသာ တောင်းဆိုသည်

`MODELS_CATALOG_PREFIX_MODE` ၏ မူလတန်ဖိုးသည် **`dual`** ဖြစ်ပြီး model တစ်ခုစီကို နှစ်ကြိမ် ကြေညာပေးသည် — တစ်ကြိမ်မှာ
အတိုကောက် alias prefix အောက်တွင်ဖြစ်ပြီး နောက်တစ်ကြိမ်မှာ canonical provider prefix အောက်တွင်ဖြစ်သည် — ထို့ကြောင့် client
config အဟောင်းများသည် ပုံစံနှစ်မျိုးလုံးကို ဆက်လက် resolve လုပ်နိုင်သည်-

```
cc/claude-sonnet-4-6        ← alias prefix
claude/claude-sonnet-4-6    ← canonical prefix၊ model အတူတူပင်
```

Extension သည် **`GET /v1/models?prefix=alias`** ကို တောင်းဆိုသဖြင့် model တစ်ခုလျှင် id တစ်ခုသာ ရောက်ရှိလာပြီး
သင်၏ အခြား client များအတွက် server တစ်ခုလုံးဆိုင်ရာ setting ကို မပြောင်းလဲစေပါ။ Reference instance တစ်ခုတွင် ဤလုပ်ဆောင်ချက်က
**entry 2345 ခုကို 1396 ခုအထိ လျှော့ချပေးခဲ့သည် — duplicate 949 ခု၊ ပျောက်ဆုံးသွားသည့် model လုံးဝမရှိပါ။**

_Client အားလုံး_ အတွက် server တစ်ခုလုံးတွင် ပြင်ဆင်လိုပါက dashboard ထဲရှိ
`MODELS_CATALOG_PREFIX_MODE` feature flag ကို `alias` ဟု သတ်မှတ်ပါ။ Query parameter နှင့် mode တစ်ခုချင်းစီအလိုက် ဇယားကို
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) တွင် ကြည့်ပါ။

### Chat မလုပ်နိုင်သော model များကို ဖျောက်ထားသည်

Catalog တွင် image၊ video၊ audio၊ rerank၊ embedding နှင့် moderation model များလည်း ပါဝင်သည်။ ၎င်းတို့ကို
chat request ပြုလုပ်သည့်အခါ မည်သို့ပင်ဖြစ်စေ ငြင်းပယ်မည်ဖြစ်သည်-

```
HTTP 400 — Model '<id>' သည် image-generation model ဖြစ်ပြီး
/v1/chat/completions တွင် အသုံးပြု၍မရပါ။ ၎င်းအစား POST /v1/images/generations ကို အသုံးပြုပါ။
```

ထို့ကြောင့် picker သို့ မရောက်မီ ၎င်းတို့၏ `type` field အလိုက် စစ်ထုတ်ထားသည်။ **Responses-API
model များကို ဆက်လက်ထိန်းသိမ်းထားသည်** — Codex / GPT-5.x entry တစ်ခုစီသည် `supported_endpoints: ["responses"]` ကို ကြေညာထားပြီး
OmniRoute က ၎င်းတို့ကို `/v1/chat/completions` အတွက် ဘာသာပြန်ပြောင်းလဲပေးသဖြင့် အပြည့်အဝ အသုံးပြုနိုင်သည်။

### သင် တစ်ခါမျှ configure မလုပ်ထားသည့် provider များ

Catalog တွင် **active connection** ရှိသော provider များမှ model များအပြင် **noAuth**
provider အားလုံးကိုလည်း စာရင်းပြုစုထားသည် — ၎င်းတို့သည် အခမဲ့အဆင့်၏ အစိတ်အပိုင်းအများစုကို ဖွဲ့စည်းထားသော key မလိုသည့် provider များဖြစ်သည်။ ယင်းသည် ရည်ရွယ်ထားသည့် အပြုအမူဖြစ်သည်။ ၎င်းတို့ကို ဖျောက်ရန်
dashboard settings ရှိ `blockedProviders` ထဲသို့ ထည့်ပါ၊ extension တွင် မည်သည့်အရာမျှ ပြောင်းလဲမည်မဟုတ်ပါ။

## VS Code တက်ဘ်အတွင်းရှိ Dashboard

`omnicopilot.dashboardOpen: "editor"` သည် OmniRoute dashboard ကို ပြင်ပ browser တွင် ဖွင့်မည့်အစား Simple Browser မှတစ်ဆင့် editor တက်ဘ်တစ်ခုအတွင်း ဖော်ပြပေးသည်။ ထည့်သွင်းဖော်ပြခြင်းကို server ပေါ်တွင် **အထူးရွေးချယ်ဖွင့်ထားရန် လိုအပ်ပြီး** `DASHBOARD_ALLOW_EMBED=vscode` မှတစ်ဆင့် လုပ်ဆောင်ရသည်။ ၎င်းသည် HTML စာမျက်နှာများကို မူလသတ်မှတ်ချက်ဖြစ်သည့် `frame-ancestors 'none'` + `X-Frame-Options: DENY` အစား `frame-ancestors 'self' vscode-webview:` ဖြင့် ပံ့ပိုးပေးသည်။ API မျက်နှာပြင် (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) သည် မည်သည့်အခြေအနေတွင်မဆို တင်းကျပ်သော header များကို ဆက်လက်အသုံးပြုသည်။

> ⚠️ **၎င်းသည် runtime flag မဟုတ်ဘဲ build-time flag ဖြစ်သည်။** Next.js သည် `headers()` ကို route
> manifest အတွင်း compile လုပ်သဖြင့် bundle ကို build လုပ်နေချိန်တွင် `next.config.mjs` က variable ကို ဖတ်သည်
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`)။
> Build လုပ်ပြီးသား server တစ်ခု၏ ရှေ့တွင် ၎င်းကို export လုပ်ခြင်းသည် မည်သည့်အရာကိုမျှ ပြောင်းလဲမပေးပါ — header များကို build အတွင်း အပြီးသတ်ထည့်သွင်းထားပြီးဖြစ်သည်။

```bash
# variable သည် BUILD command တွင် ရှိနေရမည်
DASHBOARD_ALLOW_EMBED=vscode npm run build        # သို့မဟုတ် npm run build:release
npm start
```

| `npm install -g omniroute`  | ❌ ဖြန့်ချိထားသော package တွင် ကြိုတင် build လုပ်ထားသည့် bundle ပါရှိသည် — ထိုအစား source မှ build လုပ်ပါ                                                                    |
| Docker image                | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — Docker Hub ပေါ်ရှိ ကြိုတင် build လုပ်ထားသော image တွင် ထည့်သွင်းဖော်ပြခြင်းကို ဖွင့်မထားပါ |

ထည့်သွင်းဖော်ပြခြင်း ဖွင့်ထားသည့် build မရှိပါက စာမျက်နှာသည် frame အတွင်း ဖော်ပြရန် ငြင်းပယ်မည်ဖြစ်ပြီး၊ extension က response header များမှတစ်ဆင့် ၎င်းကို သိရှိကာ ပြင်ပ browser ကို အစားထိုးအသုံးပြုမည် — မည်သည့်အရာမျှ ပျက်စီးမည်မဟုတ်သကဲ့သို့ ၎င်းအကြောင်းကိုလည်း တစ်ကြိမ် အသိပေးမည်ဖြစ်သည်။ [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) နှင့် issue [#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273) ကို ကြည့်ပါ။

## VS Code အတွင်းမှ သင်၏အခြား tool များကို စီစဉ်သတ်မှတ်ခြင်း

**`OmniRoute: Configure Coding CLI`** သည် Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code, Kilo နှင့် Roo တို့အတွက် အသင့်သုံးနိုင်သော profile များကို ရေးသားရန် `omniroute` CLI ကို မောင်းနှင်ပေးသည် — ၎င်းတို့သည် [`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md) တွင် ဖော်ပြထားသည့် config များနှင့် တူညီသည်။ API key ကို command line ပေါ်မှ မည်သည့်အခါမျှ မပေးပို့ဘဲ `OMNIROUTE_API_KEY` environment variable မှတစ်ဆင့် CLI သို့ ပေးပို့သည်။
