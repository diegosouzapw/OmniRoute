OmniRoute သည် OpenAI Codex ကို အသုံးပြုရန် နည်းလမ်း **နှစ်ခု** ပံ့ပိုးပေးသည်-

| ပံ့ပိုးသူ              | OpenAI နှင့် ဆက်သွယ်ပုံ                                                                                                                                                                                                                                | အသုံးပြုမှုဆိုင်ရာ သတိပြုရန်                                                          |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| **`codex`**            | သင်၏ ChatGPT/OpenAI OAuth တိုကင်ကို Responses API သို့ တိုက်ရိုက် ပြန်လည်ပေးပို့သည်                                                                                                                                                                    | **ရှိသည်** — တရားဝင် session ကို proxy/router အသုံးပြုမှုအတွက် ခွင့်ပြုမထားပါ         |
| **`codex-app-server`** | **Codex CLI ၏ ကိုယ်ပိုင် `codex app-server`** ကို JSON-RPC/WebSocket မှတစ်ဆင့် မောင်းနှင်သည်။ CLI သည် အပြန်အလှန်တုံ့ပြန်နိုင်သော `codex` session ကဲ့သို့ပင် ၎င်း၏ OAuth (`~/.codex/auth.json`) ကို ကိုယ်တိုင်ပိုင်ဆိုင်ပြီး အလိုအလျောက် သက်တမ်းတိုးသည် | **မရှိပါ** — OmniRoute သည် API သို့ တိုကင်ကို မည်သည့်အခါမျှ ပြန်လည်ပေးပို့ခြင်းမရှိပါ |

`codex-app-server` သည် တိုကင်ကို မည်သည့်အခါမျှ ပြန်လည်ပေးပို့ခြင်းမရှိသောကြောင့်
session ပြန်လည်ပေးပို့မှုဆိုင်ရာ အသုံးပြုမှု သတိပြုချက်နှင့် မသက်ဆိုင်ပါ။ သို့သော်
**သတ်မှတ်ထားသော app-server URL မှတစ်ဆင့် ချိတ်ဆက်နိုင်သည့် Codex CLI** တစ်ခု
လိုအပ်ပြီး ထို CLI တွင် **အကောင့်ဝင်ထားရမည်**။

## 1. တည်ဆောက်ပုံ

```
┌─ OmniRoute အက်ပ် ────────────────┐        ┌─ codex-app-server sidecar ─────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ လုပ်ဆောင်နိုင်ခွင့် တိုကင်)      │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  OpenAI OAuth ကို ကိုယ်တိုင်စီမံသည်     │
└──────────────────────────────────┘        │  (~/.codex/auth.json၊ အလိုအလျောက်တိုး) │
        │ မျှဝေသည် (compose volumes)          └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → WS လုပ်ဆောင်နိုင်ခွင့် တိုကင် (နှစ်ဖက်စလုံးက mount လုပ်သည်)
  codex-appserver-home    → ~/.codex (dashboard က auth.json ကို ရေးသားပြီး
                             sidecar ၏ codex app-server က ဖတ်သည်)
```

- Sidecar သည် လုပ်ဆောင်နိုင်ခွင့် တိုကင်ဖြင့် ကာကွယ်ထားသည့် အတွင်းပိုင်း compose
  network (`ws://codex-app-server:1456`) ပေါ်တွင်သာ စောင့်ဆိုင်းသည်။ ၎င်းကို host
  သို့မဟုတ် အင်တာနက်သို့ **မည်သည့်အခါမျှ** ဖွင့်မပေးပါ။
- Codex CLI ကို `omniroute:base` အတွင်း ကြိုတင်ထည့်သွင်းထားသောကြောင့် sidecar ကို
  အသုံးပြုသည့်အခါ host သို့မဟုတ် အသုံးပြုသူ၏ စက်တွင် codex ထည့်သွင်းရန် မလိုအပ်ပါ။

## 2. စတင်အသုံးပြုခြင်း

```bash
# codex app-server sidecar profile နှင့်အတူ stack ကို စတင်ပါ-
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

Sidecar သည် ပထမဆုံး စတင်ချိန်တွင် ၎င်း၏ WS လုပ်ဆောင်နိုင်ခွင့် တိုကင်ကို ဖန်တီးပြီး
မျှဝေထားသော `codex-appserver-token` volume ထဲသို့ ထည့်သည်။ အက်ပ်သည်လည်း
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE` မှတစ်ဆင့် အလားတူတိုကင်ကို ဖတ်သည်။
တိုကင်ကို ကိုယ်တိုင် ချိတ်ဆက်သတ်မှတ်ရန် မလိုအပ်ပါ။

## 3. ချိတ်ဆက်ခြင်း + အကောင့်ဝင်ခြင်း

1. Dashboard တွင် **OpenAI Codex (App-Server)** အတွက် ချိတ်ဆက်မှုတစ်ခု ထည့်ပါ။ API
   key သို့မဟုတ် တိုကင် မလိုအပ်ပါ (၎င်းသည် စစ်မှန်ကြောင်းအတည်ပြုမှုမလိုသော
   ပံ့ပိုးသူဖြစ်ပြီး sidecar က အထောက်အထားစိစစ်မှုကို တာဝန်ယူသည်)။
2. Sidecar ၏ Codex CLI တွင် **အကောင့်မဝင်ရသေးပါက** ချိတ်ဆက်မှု အခြေအနေ
   စစ်ဆေးချက်တွင် _"အလုပ်လုပ်နေသော်လည်း အကောင့်မဝင်ရသေးပါ"_ ဟု ပြသမည်
   (အနီရောင် အထောက်အထားစိစစ်မှု အမှားမဟုတ်ပါ)။ **ChatGPT ဖြင့် အကောင့်ဝင်ရန်**
   ကို အသုံးပြုပါ။ ၎င်းက ပုံမှန် Codex device-OAuth ကို သင့် browser တွင်
   လုပ်ဆောင်ပြီးနောက် **အထောက်အထား အသုံးချရန်** မှတစ်ဆင့် `~/.codex/auth.json`
   ကို မျှဝေထားသော volume ထဲသို့ ရေးသားပေးသည် (`codex` နှင့်
   `codex-app-server` ပံ့ပိုးသူနှစ်ခုစလုံးသည် တစ်ကြိမ်တည်း အကောင့်ဝင်ထားမှုကို
   အသုံးပြုသည်)။
3. အကောင့်ဝင်ပြီးသည်နှင့် အခြေအနေ စစ်ဆေးချက်သည် အစိမ်းရောင်ဖြစ်သွားပြီး
   (`/readyz` **နှင့်** `account/read` နှစ်ခုလုံးကို စစ်ဆေးသည် — ဆိုလိုသည်မှာ
   အလုပ်လုပ်နေခြင်း _နှင့်_ အထောက်အထားစိစစ်ပြီးခြင်း) အသုံးပြုနိုင်ပြီဖြစ်သည်။

Dashboard သည် လက်ရှိ အသုံးပြု၍ရသော `~/.codex/auth.json` ကို မည်သည့်အခါမျှ
ထပ်ရေးမည်မဟုတ်ပါ။ ဖိုင်မရှိသည့်အခါ သို့မဟုတ် ၎င်း၏ တိုကင် သက်တမ်းဟောင်းနေသည့်
အခါမှသာ ရေးသားသည် (အရန်မိတ္တူကို အမြဲယူထားသည်)။

## 4. အသုံးချတပ်ဆင်မှု အခြေအနေများ

- **အထောက်အထားစိစစ်ပြီးသား Codex CLI ရှိသည့် အော်ပရေတာ** — သင့် host ရှိ
  `~/.codex` ကို sidecar (`codex-appserver-home`) ထဲသို့ mount လုပ်ပြီး
  အကောင့်ဝင်သည့် အဆင့်ကို ကျော်လိုက်ပါ။
- **အများပြည်သူအသုံးပြုသူ၊ စက်တွင် codex ထည့်သွင်းထားခြင်းမရှိ** — ပြဿနာမရှိပါ။
  Sidecar တွင် CLI ပါရှိပြီးသားဖြစ်သည်။ အသုံးပြုသူသည် dashboard မှတစ်ဆင့်သာ
  အထောက်အထားစိစစ်ရန် လိုအပ်သည်။
- **Bare-metal OmniRoute (sidecar မရှိဘဲ host codex ကို အသုံးပြုခြင်း)** —
  `OMNIROUTE_CODEX_APPSERVER_WS` ကို သင့်ကိုယ်ပိုင် `codex app-server` သို့
  ညွှန်ပြပြီး host ရှိ codex တွင် အကောင့်ဝင်ထားကြောင်း သေချာပါစေ။ binary
  မရှိပါက "codex ထည့်သွင်းမထားပါ" ဟူသော အကြံပြုချက် ပေါ်လာမည်။

## 5. လူနေအိမ်သုံး / UDP အထွက်လမ်းကြောင်း (အော်ပရေတာအတွက် ထပ်ဆောင်းရွေးချယ်မှု၊ ထည့်သွင်းပေးမထားပါ)

အထက်ပါ ယေဘုယျ sidecar သည် container ၏ ပုံမှန် network မှတစ်ဆင့် အထွက်လမ်းကြောင်း
အသုံးပြုသည်။ Codex traffic ကို **လူနေအိမ်သုံး ထွက်ပေါက်** မှတစ်ဆင့် ထွက်စေလိုသည့်
အော်ပရေတာတစ်ဦးသည် (ဥပမာ TCP + UDP/QUIC ကို သယ်ဆောင်သည့် TUN tailscale sidecar)
၎င်းကို သီးခြား compose override အဖြစ် လုပ်ဆောင်ရမည်။ ၎င်းကို ဖြန့်ချိထားသော
`codex-app-server` profile တွင် ရည်ရွယ်ချက်ရှိရှိ **ထည့်သွင်းမထားပါ**။ ထိုသို့
တပ်ဆင်သတ်မှတ်ရန် အတွင်းပိုင်း လုပ်ငန်းဆောင်ရွက်မှု လမ်းညွှန်ကို ကြည့်ပါ။
