## `claude-web`

`claude-web` သည် အထောက်အထားစိစစ်ပြီးသော `claude.ai` ဘရောက်ဇာ session မှတစ်ဆင့် OpenAI-format chat request များကို ပေးပို့သည်။ executor သည် ပေးထားသော cookie ကို ပုံမှန်ပုံစံဖြစ်အောင် ပြုလုပ်ပြီး၊ အထောက်အထားစိစစ်ပြီးသော organization တစ်ခုကို ရှာဖွေသတ်မှတ်ကာ၊ conversation state ကို ပြင်ဆင်ပြီး၊ direct သို့မဟုတ် browser transport ကို ရွေးချယ်ကာ upstream SSE response ကို တင်းကျပ်စွာ ဘာသာပြန်ပြောင်းလဲသည်။ orchestration ကို `open-sse/executors/claude-web.ts:320` တွင် ထည့်သွင်းထားသည်။

> **Web Cookie provider များကို စတင်အသုံးပြုနေပါသလား?**
>
> ဤ provider အတွက် သီးခြားလမ်းညွှန်ချက်ကို မလိုက်နာမီ အထွေထွေ setup လုပ်ငန်းစဉ်၊ authentication လမ်းညွှန်ချက်၊ ကန့်သတ်ချက်များနှင့် ပြဿနာဖြေရှင်းနည်းများအတွက် **`docs/getting-started/WEB-COOKIE-GUIDE.md`** ကို ဖတ်ပါ။

### Model စာရင်း

provider registry သည် လက်ရှိတွင် အောက်ပါ static model ID ခုနစ်ခုကိုသာ အတိအကျ ဖော်ပြပေးထားသည်
(`open-sse/config/providers/registry/claude/web/index.ts:11`):

| Model ID                    | ပြသမည့်အမည်             |
| --------------------------- | ----------------------- |
| `claude-fable-5`            | Claude Fable 5 (web)    |
| `claude-opus-4-8`           | Claude Opus 4.8 (web)   |
| `claude-sonnet-5`           | Claude Sonnet 5 (web)   |
| `claude-haiku-4-5-20251001` | Claude Haiku 4.5 (web)  |
| `claude-opus-4-7`           | Claude Opus 4.7 (web)   |
| `claude-opus-4-6`           | Claude Opus 4.6 (web)   |
| `claude-sonnet-4-6`         | Claude Sonnet 4.6 (web) |

ဤ provider အတွက် dynamic model ရှာဖွေဖော်ထုတ်မှုကို အကောင်အထည်ဖော်ထားခြင်း မရှိပါ။ အထက်ပါစာရင်းသည် runtime catalog ဖြစ်သည်။

### အထောက်အထားများနှင့် organization ရှာဖွေသတ်မှတ်ခြင်း

`claude.ai` Cookie header အပြည့်အစုံ သို့မဟုတ် session value သီးသန့်ကို ပေးပါ။ value သီးသန့်များကို `sessionKey` အဖြစ် ပုံမှန်ပုံစံဖြစ်အောင် ပြုလုပ်သည်။ အခြား cookie များကို ပေးထားပါက မူလအတိုင်း ထိန်းသိမ်းထားသည်။ executor သည် cookie ကို `cookie` သို့မဟုတ် `apiKey` မှတစ်ဆင့် လက်ခံပြီး connection data မှ ရွေးချယ်နိုင်သော `deviceId` နှင့် `orgId` value များကို ဖတ်သည်
(`open-sse/executors/claude-web.ts:72`)။

`orgId` မရှိပါက executor သည် `GET https://claude.ai/api/organizations` ကို ခေါ်ဆိုပြီး အထောက်အထားစိစစ်ပြီးသော Claude Web session မှ ပြန်ပေးသည့် ပထမဆုံး organization ကို အသုံးပြုသည်
(`open-sse/executors/claude-web.ts:141`)။ တရားဝင် organization တစ်ခုမျှ ပြန်မရပါက လုံခြုံသောနည်းလမ်းဖြင့် မအောင်မြင်စေသည်၊ ငြင်းပယ်ခံရသော session authorization ကို 401 အဖြစ် အစီရင်ခံပြီး Cloudflare challenge နှင့် authentication မအောင်မြင်မှုကို ခွဲခြားသတ်မှတ်သည်။

### Conversation လုပ်ဆောင်ချက်များ

ရွေးချယ်နိုင်သော top-level `claude_web` object သည် တင်းကျပ်သော စည်းမျဉ်းများကို လိုက်နာသည်။ မသိရှိသော field များကို ငြင်းပယ်သည်။ ၎င်းလက်ခံသည့် field များကို `open-sse/executors/claude-web/session.ts:50` တွင် သတ်မှတ်ထားသည်-

| Field                 | အဓိပ္ပာယ်                                                                          |
| --------------------- | ---------------------------------------------------------------------------------- |
| `operation`           | မူလသတ်မှတ်ချက်အရ `completion`; ထပ်မံကြိုးစားသည့် turn အတွက် `retry` ကို အသုံးပြုပါ |
| `conversation_id`     | ရှိပြီးသား conversation အတွက် တိကျစွာ သတ်မှတ်ထားသော UUID                           |
| `parent_message_uuid` | parent assistant message အတွက် တိကျစွာ သတ်မှတ်ထားသော UUID                          |
| `timezone`            | တရားဝင် IANA time-zone အမည်                                                        |
| `locale`              | ဖွဲ့စည်းပုံအရ တရားဝင်သော locale                                                    |
| `tool_states`         | ရွေးချယ်နိုင်သော account tool-state array၊ entry 128 ခုအထိ ကန့်သတ်ထားသည်           |

ပြင်ဆင်ထားသော request များသည် upstream endpoint နှစ်ခုအနက် တစ်ခုကို အသုံးပြုသည်
(`open-sse/executors/claude-web.ts:203`):

- turn အသစ် သို့မဟုတ် ဆက်လက်လုပ်ဆောင်သည့် turn သည်
  `POST https://claude.ai/api/organizations/{orgId}/chat_conversations/{conversationId}/completion` သို့ post လုပ်သည်။
- ထပ်မံကြိုးစားမှုသည်
  `POST https://claude.ai/api/organizations/{orgId}/chat_conversations/{conversationId}/retry_completion` သို့ post လုပ်သည်။

turn အသစ်တွင် `create_conversation_params` ပါဝင်သည်။ cache လုပ်ထားသော သို့မဟုတ် အတိအလင်း ချိတ်ဆက်ထားသော follow-up တွင် `parent_message_uuid` ပါဝင်ပြီး `create_conversation_params` ကို ချန်လှပ်ထားသည်။ Retry အတွက် conversation state နှင့် parent-message state နှစ်ခုစလုံး လိုအပ်ပြီး prompt မပို့ပါ
(`open-sse/executors/claude-web/session.ts:254`)။ conversation အသစ်များသည် အထောက်အထားစိစစ်ပြီးသော UI ကို `/new` တွင် ဖွင့်သည်။ cache လုပ်ထားသော သို့မဟုတ် အတိအလင်း ချိတ်ဆက်ထားသော follow-up များသည် သက်ဆိုင်ရာ conversation page အတိအကျကို ဖွင့်သည်
(`open-sse/executors/claude-web/session.ts:324`)။

Conversation state သည် SHA-256 account scope နှင့် caller ၏ canonical transcript ကို key အဖြစ် အသုံးပြုထားသော in-memory cache ဖြစ်သည်။ entry များသည် မိနစ် 30 ကြာပြီးနောက် သက်တမ်းကုန်ဆုံးကာ cache ကို entry 5,000 အထိ ကန့်သတ်ထားသည်
(`open-sse/executors/claude-web/session.ts:12`)။ တင်းကျပ်သော stream parser က `message_stop` ကို တွေ့ရှိပြီးမှသာ state ကို commit လုပ်သည်။ process ပြန်လည်စတင်ခြင်းက ၎င်းကို စွန့်ပစ်သည်။ cache miss ဖြစ်ပါက ယခင် message များကို အသိပေးခြင်းမရှိဘဲ စွန့်ပစ်မည့်အစား multi-message request ကို recovery prompt တစ်ခုတည်းအဖြစ် serialize လုပ်သည်။

Locale နှင့် time zone သည် အောက်ပါ ဦးစားပေးအစီအစဉ်ကို အသုံးပြုသည်- request `claude_web` value၊ connection value၊ runtime value၊ ထို့နောက် locale အတွက် `en-US` သို့မဟုတ် time zone အတွက် `UTC`
(`open-sse/executors/claude-web/session.ts:218`)။

### Tool များနှင့် request payload များ

Direct request များသည် caller ပေးထားသော ဖွဲ့စည်းပုံအရ တရားဝင်သည့် OpenAI function tool များကိုသာ ပြောင်းလဲသည်။ လုပ်ကြံဖန်တီးထားသော static default tool စာရင်း မရှိပါ
(`open-sse/executors/claude-web/payload.ts:102`)။

Browser request များသည် ထိုသို့လုပ်ဆောင်မည့်အစား အထောက်အထားစိစစ်ပြီးသော UI request ကို ဖမ်းယူပြီး ၎င်း၏ account tool များ၊ tool state များနှင့် စိတ်ကြိုက်ပြင်ဆင်ထားသော style များကို ထိန်းသိမ်းထားသည်။ ပြင်ဆင်ထားသော conversation၊ model၊ reasoning၊ prompt နှင့် message UUID field များသည် ဖမ်းယူထားသော request ကို ဆက်လက်၍ override လုပ်သည်
(`open-sse/executors/claude-web/browserTransport.ts:175`)။ Browser template များကို account၊ organization၊ cookie၊ locale နှင့် time zone တို့၏ hash ဖြင့် scope သတ်မှတ်ထားပြီး မိနစ် 30 ကြာပြီးနောက် သက်တမ်းကုန်ဆုံးသည်
(`open-sse/executors/claude-web/browserTransport.ts:11`,
`open-sse/executors/claude-web/browserTransport.ts:158`)။ direct request တစ်ခုတွင် caller tool များ မပါရှိပါက ထို scope သတ်မှတ်ထားသော template ကို ပြန်လည်အသုံးပြုနိုင်သည်။ အတိအလင်းပေးထားသော caller tool များကို ဦးစားပေးသည်
(`open-sse/executors/claude-web/browserTransport.ts:214`)။

### Transport ရွေးချယ်ခြင်း

မူလသတ်မှတ်ထားသော လမ်းကြောင်းမှာ `sendClaudeWebDirect()` ဖြစ်ပြီး ၎င်းသည် ပြင်ဆင်သတ်မှတ်ထားသော Chrome 146 profile နှင့် ပေးထားသော cookie ကို အသုံးပြု၍ `tlsFetchClaude()` ကို ခေါ်ဆိုသည် (`open-sse/services/claudeTlsClient.ts:23`)။ ၎င်းသည် solver ကို စတင်ခြင်း သို့မဟုတ် အစားထိုး cookie တစ်ခုကို ဖန်တီးခြင်း မပြုလုပ်ပါ။

အကောင့်အလိုက် သတ်မှတ်ထားသော browser adapter ကို အဓိက transport အဖြစ် အသုံးပြုရန် `WEB_COOKIE_USE_BROWSER` ကို `1`, `true` သို့မဟုတ် `on` ဟု သတ်မှတ်ပါ။ သိရှိပြီးဖြစ်သော Cloudflare 403 challenge တစ်ခု ကြုံတွေ့သည့်အခါ direct transport မှ browser adapter သို့ fallback လုပ်ခွင့်ပြုရန် `OMNIROUTE_BROWSER_POOL` ကိုလည်း အလားတူတန်ဖိုးများထဲမှ တစ်ခုအဖြစ် သတ်မှတ်ပါ (`open-sse/executors/claude-web.ts:195`)။ အခြား HTTP ချို့ယွင်းမှုများသည် ထို fallback ကို မဖြစ်ပေါ်စေပါ။

Browser adapter သည် cookies များကို တူညီသော pooled Playwright context အတွင်း ထိန်းသိမ်းထားပြီး၊ အထက်တွင် ဖော်ပြထားသော အကန့်အသတ်သတ်မှတ်ထားသည့် hashed key ကို အသုံးပြုကာ ထို context မှ completion ကို ပေးပို့သည် (`open-sse/executors/claude-web/browserTransport.ts:444`)။ ၎င်းသည် browser ဖြင့် ဖြေရှင်းရရှိထားသော cookie ကို direct TLS client ထဲသို့ မည်သည့်အခါမျှ export မလုပ်ပါ။ Browser retry များအတွက် တူညီသော အမှန်တကယ် Playwright context နှင့် ချိတ်ဆက်ထားသည့် သက်တမ်းမကုန်သေးသော UI template တစ်ခု လိုအပ်သည် (`open-sse/executors/claude-web/browserTransport.ts:467`)။ Browser response ဖတ်ရှုမှုများကို authenticated page အတွင်း တစ်ဆင့်ချင်း လုပ်ဆောင်ပြီး request cancellation ကို လိုက်နာကာ 16 MiB ကျော်လွန်သည်နှင့် upstream body ကို ချက်ချင်း cancel လုပ်သည် (`open-sse/executors/claude-web/browserTransport.ts:259`)။

Executor သည် shared request logger သို့ အရေးကြီးဒေတာများ ဖယ်ရှားထားသော audit projection တစ်ခု ပြန်ပေးသည်။ organization၊ conversation နှင့် message UUID များ၊ prompt စာသား၊ tool definition များ၊ cookies များနှင့် device identifier များကို ချန်လှပ်ထားသည် (`open-sse/executors/claude-web.ts:237`,
`open-sse/executors/claude-web.ts:252`)။ Transport exception များသည်လည်း throw လုပ်ထားသော message အစား ယေဘုယျ connection error တစ်ခုကို ပြန်ပေးသည်။

### SSE လုပ်ဆောင်ပုံ

`createClaudeWebResponse()` သည် LF သို့မဟုတ် CRLF framing နှင့် စာကြောင်းများစွာပါသော `data:` field များကို ကိုင်တွယ်သည်။ ၎င်းသည် text delta များကို `content` သို့၊ thinking delta များကို `reasoning_content` သို့၊ သိရှိပြီးသား metadata event များကို `claude_web` response extension သို့ map လုပ်သည်။ Metadata event တစ်ခုချင်းစီကို ၎င်း၏ကိုယ်ပိုင် field allowlist မှတစ်ဆင့် projection လုပ်သည် (`open-sse/executors/claude-web/stream.ts:37`)။ Conversation၊ parent-message၊ assistant-message နှင့် operation metadata များကိုလည်း `X-OmniRoute-Claude-Web-*` header များတွင် ပြန်ပေးသည် (`open-sse/executors/claude-web/stream.ts:364`)။

Parser သည် ပျက်ယွင်းနေသော JSON၊ upstream `error` event များ၊ မသိရှိသော event type များ၊ မမှန်ကန်သော အစီအစဉ်၊ content-block ကိုက်ညီမှုမရှိခြင်း သို့မဟုတ် `message_stop` မရောက်မီ EOF ဖြစ်ခြင်းတို့တွင် fail closed လုပ်သည်။ Streaming output သည် finish chunk တစ်ခုနှင့် `[DONE]` တစ်ခုကို ထုတ်ပေးပြီး buffered output သည် တူညီသော parser ကို အသုံးပြုသည်။ Parser သည် `message_stop` ကို ချက်ချင်း အဆုံးသတ်အခြေအနေအဖြစ် သတ်မှတ်ပြီး၊ နောက်ဆက်တွဲ upstream data များကို cancel လုပ်ကာ downstream cancellation ကို upstream reader ထံ ဆက်လက်ဖြန့်ပို့သည် (`open-sse/executors/claude-web/stream.ts:461`,
`open-sse/executors/claude-web/stream.ts:563`)။ အဆုံးသတ်မထားသော SSE စာကြောင်းများနှင့် စုစည်းထားသော event များကို 1 MiB အထိ ကန့်သတ်ထားသည် (`open-sse/executors/claude-web/stream.ts:17`,
`open-sse/executors/claude-web/stream.ts:62`)။

### စမ်းသပ်ခြင်း

အမှန်တကယ် credential များမပါဘဲ deterministic Claude Web suite ကို run ပါ။

```powershell
node --import tsx/esm --test tests/unit/claude-web-auto-refresh.test.ts tests/unit/claude-web-browser-transport.test.ts tests/unit/claude-web-executor-split.test.ts tests/unit/claude-web-live-alignment.test.ts tests/unit/claude-web-payload-runtime.test.ts tests/unit/claude-web-session.test.ts tests/unit/claude-web-sonnet5-registry-6209.test.ts tests/unit/claude-web-stream.test.ts tests/unit/claude-web-transport.test.ts tests/unit/claude-web.test.ts tests/unit/issue-6662-repro.test.ts
```

`tests/unit/claude-web-auto-refresh.test.ts` ရှိ Playwright ကို မှီခိုသော case များကို အတိအလင်း skip လုပ်ထားသည်။ ဤ repository တွင် လက်ရှိ credential ပါဝင်သော Claude Web live-test script ကို သတ်မှတ်ထားခြင်းမရှိသောကြောင့် ထို skip လုပ်ထားသည့် case များသည် runtime အထောက်အထား မဟုတ်ပါ။

### စနစ်ထည့်သွင်းခြင်း

1. OmniRoute ကို `npm run dev` ဖြင့် သို့မဟုတ် build လုပ်ထားသော installation မှ စတင်ပါ။
2. Dashboard → Providers → Add Provider ကို ဖွင့်ပါ။
3. Web Cookie category နှင့် Claude Web ကို ရွေးချယ်ပါ။
4. Authenticated `claude.ai` request တစ်ခုမှ ကူးယူထားသော Cookie header အပြည့်အစုံကို paste လုပ်ပါ။
