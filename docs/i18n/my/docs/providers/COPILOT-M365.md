`copilot-m365-web` (အမည်ပွား `m365copilot`) သည် အထောက်အထားစိစစ်ထားသော Microsoft 365 Copilot BizChat ဘရောက်ဇာဆက်ရှင်မှတစ်ဆင့် OpenAI ဖော်မတ် ချတ်တောင်းဆိုချက်များကို
`m365.cloud.microsoft/chat` သို့ ပေးပို့သည်။ ဤပေါင်းစည်းမှုသည် တရားဝင်မဟုတ်ပါ။

> **Web Cookie ပံ့ပိုးသူများကို စတင်အသုံးပြုနေပါသလား။**
>
> ဤပံ့ပိုးသူအတွက် သီးသန့်လမ်းညွှန်ချက်ကို မလိုက်နာမီ အထွေထွေစီစဉ်သတ်မှတ်မှုလုပ်ငန်းစဉ်၊ အထောက်အထားစိစစ်ခြင်းလမ်းညွှန်ချက်၊ ကန့်သတ်ချက်များနှင့် ပြဿနာဖြေရှင်းခြင်းအတွက် **`docs/getting-started/WEB-COOKIE-GUIDE.md`** ကို ဖတ်ရှုပါ။
>
> **အရေးကြီးသည်:** ဤပံ့ပိုးသူအတွက် အထောက်အထားသည် **cookie မဟုတ်ပါ**။ `m365.cloud.microsoft` မှ
> cookie များကို မကူးယူပါနှင့်။ အထောက်အထားသည် WebSocket URL query
> parameter နှင့် path segment ဖြစ်ပြီး ၎င်းနှစ်ခုလုံးကို DevTools Network tab မှ ရယူရပါသည်။

## ကြိုတင်လိုအပ်ချက်များ

- `m365.cloud.microsoft/chat` ရှိ BizChat ကို ဝင်ရောက်အသုံးပြုနိုင်သော Microsoft 365 အကောင့်တစ်ခု
- DevTools WebSocket စစ်ဆေးမှုအတွက် Chromium အခြေခံ ဘရောက်ဇာတစ်ခု (Chrome၊ Edge)
- M365 Copilot လိုင်စင်တစ်ခု (Microsoft 365 Business/Enterprise အစီအစဉ်များစွာတွင် ပါဝင်သည်)

## အထောက်အထားရယူခြင်း (WebSocket နည်းလမ်း)

1. `https://m365.cloud.microsoft/chat` တွင် လက်မှတ်ထိုးဝင်ရောက်ပြီး စကားဝိုင်းတစ်ခု စတင်ပါ။
2. **DevTools → Network** ကို ဖွင့်ပါ။
3. **WS** (WebSocket) ဖြင့် စစ်ထုတ်ပါ။
4. Chathub WebSocket ချိတ်ဆက်မှုကို နှိပ်ပါ။ `wss://substrate.office.com/m365Copilot/Chathub/` ဖြင့်
   စတင်သော URL ကို ရှာပါ။
5. ၎င်း၏ **Request URL** မှ အောက်ပါတို့ကို ကူးယူပါ:
   - `access_token` query parameter တန်ဖိုး (သက်တမ်းတို JWT တစ်ခု)။
   - `/Chathub/` နောက်ရှိ Chathub path segment (ဥပမာ `<oid>@<tenant>`)။

URL အပြည့်အစုံ၏ ပုံစံမှာ အောက်ပါအတိုင်းဖြစ်သည်:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute တွင် **Providers → Add Provider** သို့ သွားပြီး **Microsoft 365 Copilot
   (BizChat)** ကို ရွေးချယ်ကာ အောက်ပါဖော်မတ်ဖြင့် အထောက်အထားကို ထည့်သွင်းပါ:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. **Test Connection** နှင့် **Save** ကို နှိပ်ပါ။

## အထောက်အထားရယူခြင်း (HAR တင်သွင်းမှု)

WebSocket URL မှ တန်ဖိုးများကို ကိုယ်တိုင်ကူးယူမည့်အစား DevTools HAR
ဖိုင်တစ်ခုကို ထုတ်ယူနိုင်သည်:

1. **DevTools → Network** ကို ဖွင့်ပါ။
2. BizChat စကားဝိုင်းတစ်ခုကို စတင်ပါ သို့မဟုတ် ဆက်လက်လုပ်ဆောင်ပါ (၎င်းက WebSocket ချိတ်ဆက်မှုကို အစပြုသည်)။
3. Network အကန့်အတွင်း ညာဘက်ကလစ်နှိပ်ပြီး **Save all as HAR with content** ကို ရွေးချယ်ပါ။
4. OmniRoute ရှိ ပံ့ပိုးသူချိတ်ဆက်မှု ဒိုင်ယာလော့ဂ်တွင် **Import .har file** ခလုတ်ကို အသုံးပြုပါ။

OmniRoute သည် Chathub WebSocket URL ကို ရှာဖွေရန် HAR ကို စစ်ဆေးပြီး
`access_token` နှင့် `chathubPath` ကို ထုတ်ယူကာ အထောက်အထားကွက်လပ်များကို အလိုအလျောက် ဖြည့်ပေးသည်။ HAR
တင်သွင်းမှုသည် JWT သက်တမ်းကုန်ဆုံးချိန်ကို ဖော်ထုတ်ပြီး ကျန်ရှိသော တိုကင်သက်တမ်းကို ပြသသည်။

> **တကယ့် HAR ထုတ်ယူမှု၊ access token သို့မဟုတ် refresh token ကို မည်သည့်အခါမျှ commit မလုပ်ပါနှင့်။** စမ်းသပ်မှုနှင့်
> စာရွက်စာတမ်းတန်ဖိုးများသည် အမြဲတမ်း placeholder များသာ ဖြစ်ရမည်။

## တိုကင်သက်တမ်းနှင့် ပြန်လည်ရယူခြင်း

`access_token` သည် သက်တမ်းတိုပါသည် (ပုံမှန်အားဖြင့် **~75 မိနစ်**)။ သက်တမ်းကုန်ဆုံးပြီးနောက် ပံ့ပိုးသူက
ချိတ်ဆက်မှုအမှားကို အစီရင်ခံမည်ဖြစ်ပြီး အထောက်အထားကို ပြန်လည်ရယူရပါမည်။

### `refreshToken` ဖြင့် အလိုအလျောက် ပြန်လည်ရယူခြင်း

ကိုယ်တိုင် ပြန်လည်ရယူရန် မလိုအပ်စေရန် Microsoft refresh token တစ်ခုကို ချိတ်ဆက်မှု၏
**Advanced Settings → providerSpecificData** တွင် သိမ်းဆည်းနိုင်သည်:

| ကွက်လပ်        | ဖော်ပြချက်                                                              |
| -------------- | ----------------------------------------------------------------------- |
| `refreshToken` | `substrate.office.com/sydney` scope အတွက် Microsoft OAuth refresh token |
| `tier`         | `individual` (မူလသတ်မှတ်ချက်)၊ `edu` သို့မဟုတ် `enterprise`             |

`substrate.office.com/sydney` ကို scope သတ်မှတ်ထားသော Microsoft device-code သို့မဟုတ် authorization-code flow
မှ refresh token ကို ရယူပါ။ `refreshToken` ကို သတ်မှတ်ထားပါက OmniRoute သည်
တောင်းဆိုချက်တစ်ခုစီမတိုင်မီ `access_token` ကို ကြိုတင်ပြန်လည်ရယူပေးသောကြောင့် ~75 မိနစ်တိုင်း သက်တမ်းကုန်ဆုံးပြီးနောက်
ပြန်လည်ရယူရန် မလိုအပ်ပါ။

`refreshToken` ကို မသတ်မှတ်ထားပါက သက်တမ်းကုန်ဆုံးသည့်အကြိမ်တိုင်း WebSocket အထောက်အထားကို ကိုယ်တိုင်
ပြန်လည်ရယူရပါမည်။

### Tier ရွေးချယ်ခြင်း

| Tier         | အမည်ပွား           | အသုံးပြုမျက်နှာပြင်        |
| ------------ | ------------------ | -------------------------- |
| `individual` | _(မူလသတ်မှတ်ချက်)_ | သုံးစွဲသူသုံး M365 Copilot |
| `edu`        | `included`         | ပညာရေးသုံး M365 Copilot    |
| `enterprise` | `work`             | လုပ်ငန်းသုံး M365 Copilot  |

**Advanced Settings → providerSpecificData → tier** တွင် tier ကို သတ်မှတ်ပါ။ tier သည်
BizChat လမ်းကြောင်းရွေးချယ်မှုနှင့် မော်ဒယ်အသုံးပြုခွင့်အပေါ် သက်ရောက်မှုရှိသည်။

## လုံခြုံရေးပုံစံ

- **တရားဝင်မဟုတ်သော ပေါင်းစည်းမှု။** ဤ provider သည် BizChat WebSocket protocol ကို reverse-engineer လုပ်ထားသည်။ Microsoft က endpoint ကို ပြောင်းလဲသည့်အခါ ကြိုတင်အသိပေးခြင်းမရှိဘဲ အလုပ်မလုပ်တော့နိုင်ပါသည်။
- `subscriptionRisk: true` flag သည် ဤပေါင်းစည်းမှုက မှတ်တမ်းတင်ဖော်ပြမထားသော endpoint တစ်ခုအပေါ် မှီခိုနေကြောင်း ဖော်ပြသည်။ အကောင့်ကန့်သတ်မှုများ ဖြစ်နိုင်သော်လည်း အတည်ပြုထားခြင်းမရှိသေးပါ။
- access token သည် သက်တမ်းတိုသော JWT တစ်ခုဖြစ်သည်။ ၎င်းကို စကားဝှက်ကဲ့သို့ သဘောထားပါ—commit မလုပ်ပါနှင့်၊ log မမှတ်ပါနှင့်၊ သို့မဟုတ် မျှဝေခြင်းမပြုပါနှင့်။
- refresh token သည် BizChat မျက်နှာပြင်သို့ ရေရှည်ဝင်ရောက်အသုံးပြုခွင့် ပေးသည်။ ၎င်းကို API key တစ်ခုကဲ့သို့ အလားတူဂရုစိုက်၍ သိမ်းဆည်းပါ။

## ပြဿနာဖြေရှင်းခြင်း

### စစ်မှန်ကြောင်းအတည်ပြုခြင်း ချက်ချင်းမအောင်မြင်ပါ

- XHR/Fetch request မှမဟုတ်ဘဲ **WebSocket URL** မှ ကူးယူထားကြောင်း စစ်ဆေးပါ။ အထောက်အထားသည် Chathub WebSocket ချိတ်ဆက်မှု၏ `access_token` query parameter တွင် ရှိပြီး `Authorization: Bearer` header တွင် မရှိပါ။
- `chathubPath` တွင် URL path မှ `<oid>@<tenant>` segment အပြည့်အစုံ ပါဝင်ကြောင်း သေချာပါစေ။

### Token သည် ~75 မိနစ်အကြာတွင် သက်တမ်းကုန်သွားသည်

ဤသည်မှာ မျှော်လင့်ထားသည့် အပြုအမူဖြစ်သည်။ `refreshToken` မရှိပါက access token သည် သက်တမ်းတိုပါသည်။ အောက်ပါတစ်ခုခုကို လုပ်ဆောင်ပါ-

- DevTools မှ အထောက်အထားကို ပြန်လည်ဖမ်းယူပါ၊ သို့မဟုတ်
- အလိုအလျောက်ပြန်လည်ရယူရန် Advanced Settings တွင် `refreshToken` ကို စီစဉ်သတ်မှတ်ပါ။

### Test Connection အောင်မြင်သော်လည်း chat က 401 ပြန်ပေးသည်

အတည်ပြုစစ်ဆေးမှုနှင့် ပထမဆုံး request ကြားတွင် token သက်တမ်းကုန်သွားနိုင်သည်။ အထောက်အထားအသစ်တစ်ခုကို ပြန်လည်ဖမ်းယူပါ။

### Copilot သည် provider စာရင်းတွင် မပေါ်ပါ

**Dashboard → Providers** တွင် `copilot-m365-web` ကို ဖွင့်ထားကြောင်း သေချာပါစေ။ အချို့သော tier များတွင် provider ကို ပုံသေအားဖြင့် ဖျောက်ထားနိုင်သည်။
