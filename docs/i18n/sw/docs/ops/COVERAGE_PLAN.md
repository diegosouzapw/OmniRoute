## Kanuni

- Malengo ya ufunikaji yanatumika kwa faili za msimbo chanzo, si kwa `tests/**`.
- `open-sse/**` ni sehemu ya bidhaa na lazima iendelee kujumuishwa katika upeo.
- Msimbo mpya haupaswi kupunguza ufunikaji katika maeneo yaliyoguswa.
- Pendelea kujaribu tabia na matokeo ya matawi kuliko maelezo ya utekelezaji.
- Pendelea hifadhidata za muda za SQLite na data ndogo za majaribio kuliko viigizo vya jumla kwa `src/lib/db/**`.

## Seti ya sasa ya amri

- `npm run test:coverage`
  - Kigezo kikuu cha ufunikaji wa msimbo chanzo kwa mkusanyiko wa majaribio ya kitengo
  - Huzalisha `text-summary`, `html`, `json-summary`, na `lcov`
- `npm run coverage:report`
  - Ripoti ya kina ya kila faili kutoka kwenye utekelezaji wa hivi karibuni
- `npm run test:coverage:legacy`
  - Kwa ulinganisho wa kihistoria pekee

## Sera ya ratchet

Sasisha vizingiti vya `npm run test:coverage` tu baada ya mradi kuzidi hatua inayofuata kwa kiasi cha kutosha.

**Kizingiti cha sasa:** `npm run test:coverage` kinatekeleza **kauli 60 / mistari 60 / vitendakazi 60 / matawi 60** (kipimo kiliwekewa msingi mpya katika Quality-Gates Awamu ya 6A.1 — msingi wa awali wa 82.58% ulikuwa umeongezwa kupita kiasi kwa sababu ulihesabu faili za majaribio na kuondoa `open-sse`). Amri ya `test:coverage:legacy` huhifadhi kipimo cha zamani cha 50/50/50 kwa ajili ya ulinganisho wa kihistoria.

Kwa ukaguzi wa papo hapo wa vizingiti dhidi ya ripoti ya hivi karibuni, tumia:

```bash
node scripts/check/test-report-summary.mjs --threshold 75
```

## Pengo linalojulikana

Amri ya sasa ya ufunikaji hupima mkusanyiko mkuu wa majaribio ya kitengo cha Node na hujumuisha msimbo chanzo uliofikiwa kutoka humo, ikiwa ni pamoja na `open-sse`. Bado haiunganishi ufunikaji wa Vitest katika ripoti moja iliyounganishwa. Muunganisho huo unafaa kufanywa baadaye, lakini si kikwazo cha kuanza kupanda kutoka 60% -> 80%.
