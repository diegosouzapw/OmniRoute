Tumia mwongozo huu kuchagua mzunguko mdogo zaidi wa maendeleo unaotegemewa kwa ombi la kuunganisha mabadiliko. Hauchukui
nafasi ya nyaraka mahususi za usanifu na usalama zilizounganishwa hapa chini; unaunganisha kila aina ya kawaida ya
mabadiliko na mikataba yake, ukaguzi mahususi, na ufunikaji wa CI.

## Njia inayofuatwa na kila badiliko

1. **Chagua tawi msingi kabla ya kuhariri.** Tafuta tawi amilifu la juu zaidi la `release/v*` na uunde tawi kutoka
   kwenye ncha yake. Lenga tawi hilo, si `main`. Ikiwa usitishaji wa mabadiliko kwa ajili ya toleo unaendelea, usilenge tawi
   lililositishwa; tumia mzunguko amilifu unaofuata ulioelezwa katika
   [Muundo wa Matawi na Matoleo](BRANCHING_MODEL.md).
2. **Taja mikataba.** Tambua kila katalogi, schema, artifact iliyozalishwa, API ya umma, au kiolesura cha
   mtumiaji kinachoathiriwa na badiliko. Jedwali lililo hapa chini linaonyesha seti ya chini kabisa ya kuanzia.
3. **Andika au sasisha majaribio mahususi.** Mabadiliko ya uzalishaji katika `src/`, `open-sse/`, `electron/`, au
   `bin/` yanahitaji jaribio la kiotomatiki katika PR hiyo hiyo. Endesha faili chache zaidi za majaribio zinazothibitisha
   tabia, kisha ukaguzi mahususi ulioorodheshwa.
4. **Ruhusu CI iendeshe matriki pana.** Sehemu kamili za majaribio ya unit, Vitest, kizingiti cha ufunikaji, na
   build ya uzalishaji huendeshwa kwenye PR. Endesha mkusanyiko mpana wa majaribio ndani ya mazingira yako tu pale hitilafu mahususi inapoashiria
   athari pana zaidi au pale badiliko linapohusisha mifumo midogo kadhaa.
5. **Sawazisha kabla ya ukaguzi.** Leta tawi msingi amilifu, kagua commit zake mpya na diff yako dhidi
   yake, kisha fanya rebase au merge ya tawi msingi kulingana na mtiririko wa kazi wa wachangiaji. Tatua migongano ya faili
   zilizozalishwa na katalogi kutoka kwenye chanzo chake, zizalishe upya, endesha tena mzunguko mahususi, na uthibitishe kuwa
   PR bado inalenga tawi amilifu la toleo.
6. **Rekodi ushahidi.** Katika kiolezo cha PR, orodhesha amri zilizoendeshwa, kila faili ya jaribio iliyoongezwa au kubadilishwa,
   migration au feature flag, na uthibitishaji wowote wa CI pekee ambao bado unasubiri.

## Njia zinazopendekezwa kulingana na aina ya badiliko

Amri zilizo hapa chini ni ukaguzi mahususi wa kiwango cha chini, si ruhusa ya kuruka jaribio linaloshughulikia moja kwa moja
tabia uliyobadilisha.

### Provider

**Mikataba**

- Ufafanuzi wa provider katika `src/shared/constants/providers/` na uundaji wake katika
  `src/shared/constants/providers.ts`.
- Model na uwezo katika `open-sse/config/providerRegistry.ts` au faili zake za registry zilizotengwa.
- Uteuzi wa executor/translator, usanidi wa OAuth au API key, asset za dashboard, na rejeleo la provider
  lililozalishwa inapohitajika.
- Credentials za umma lazima zitumie `resolvePublicCred()`; majibu ya hitilafu lazima yatumie visaidizi vya pamoja vya
  kusafisha hitilafu. Tazama `docs/security/PUBLIC_CREDS.md` (git; haijumuishwi ndani ya `/docs`) na
  [Usafishaji wa Hitilafu](../security/ERROR_SANITIZATION.md).

**Mzunguko mahususi**

```bash
npm run check:provider-consistency
npm run check:provider-assets
node --import tsx/esm --test tests/unit/provider-translate-path-golden.test.ts
node --import tsx/esm --test tests/unit/<provider-or-executor>.test.ts
npm run gen:provider-reference   # katalogi inapobadilika; commit diff iliyozalishwa
npm run lint
```

Pia jaribu kila familia ya request iliyoathiriwa: chat, Responses, images, embeddings, audio, au video.
Kagua katalogi zilizozalishwa na diff za marejeo kama mabadiliko ya mikataba; usizikubali bila kuzichunguza.

### Routing

**Mikataba**

- Thamani za strategy za umma na metadata ya UI katika `src/shared/constants/routingStrategies.ts`.
- Dispatch na mpangilio chini ya `open-sse/services/combo.ts` na `open-sse/services/combo/`.
- Schema za combo, persistence, hali ya resilience, uwezo wa model, na vidhibiti vya API/UI.
- [Injini ya Auto-Combo](../routing/AUTO-COMBO.md) na nyaraka za resilience tabia inapobadilika.

**Mzunguko mahususi**

```bash
node --import tsx/esm --test tests/unit/combo-<behavior>.test.ts
npm run test:combo:matrix        # mabadiliko ya strategy au dispatch
npm run check:known-symbols      # mabadiliko ya usajili wa strategy
npm run lint
```

Tumia majaribio ya upstream yaliyodhihakiwa na yanayotoa matokeo thabiti ndani ya mazingira yako. Majaribio ya moja kwa moja ya combo yanahitaji credentials na
ni ya mikono; si mbadala wa CI.

### UI / UX

**Mikataba**

- Route/page ya Next.js na mipaka ya component za pamoja chini ya `src/app/` na
  `src/shared/components/`.
- Miundo ya majibu ya API, hali za loading/empty/error, tabia ya keyboard na screen reader,
  layout inayobadilika kulingana na skrini, theming, na upanuzi wa locale.
- String za chanzo cha UI cha Kiingereza katika `src/i18n/messages/en.json`; usiweke moja kwa moja copy mpya inayoonekana kwa mtumiaji.

**Mzunguko mahususi**

```bash
node --import tsx --test tests/unit/dashboard/<feature>.test.ts
npx vitest run --config vitest.config.ts tests/unit/ui/<component>.test.tsx
npm run check:dashboard-typecheck
npm run lint
```

Endesha programu kwa mabadiliko ya mwingiliano au mwonekano na ukague viewport nyembamba na pana. CI huendesha
build ya uzalishaji na mikusanyiko mipana zaidi ya majaribio; tabia ya mwonekano bado inahitaji component mahususi, Playwright,
au ukaguzi wa mikono uliorekodiwa unaofaa kwa badiliko.

### i18n

**Mikataba**

- `src/i18n/messages/en.json` ndiyo chanzo cha UI; `config/i18n.json` ndiyo chanzo cha locale.
- Katalogi za CLI zinapatikana kando chini ya `bin/cli/locales/`.
- Hifadhi ICU placeholder na tag bila mabadiliko yoyote. Usitafsiri majina ya bidhaa/provider/model,
  majina ya protocol na header, amri, vitambulishi vya code/JSON, URL, environment variable, au
  istilahi zinazolindwa kama `OmniRoute`, `OAuth`, `MCP`, na `A2A`. Orodha ya sasa ya chanzo ni
  `scripts/i18n/glossary/protected-terms.json`.

**Mzunguko mahususi**

```bash
npm run i18n:sync-ui:dry
npm run i18n:check-ui-coverage
npm run i18n:check-value-drift
npm run i18n:check-glossary
npm run check:cli-i18n          # string/katalogi za CLI zinapobadilika
npm run lint
```

Huu ni mwongozo wa mfumo uliopo, si mwaliko wa kupanua zana zake au muundo wa key.
Weka patch za i18n ziwe mahususi huku mfumo mbadala ukiendelea kubuniwa. Usiendeshe amri za tafsiri
zinazotumia huduma za nje isipokuwa jukumu linahitaji waziwazi tafsiri zinazozalishwa na
umekagua diff iliyotokea.

### CLI

**Mikataba**

- Amri na bendera za umma katika `bin/cli/`, amri za API zinazozalishwa, misimbo ya kutoka, stdout/stderr na
  miundo ya matokeo ya JSON, tabia ya usanidi/mazingira, na faili zilizofungashwa.
- Maandishi ya CLI yanayoonekana kwa mtumiaji lazima yatumie safu ya i18n ya CLI na yaweke katalogi za `en`/`pt-BR` zikiwa zimeoanishwa.
- Dumisha Node kama mazingira ya utekelezaji yanayotumika na mkataba wa binary iliyochapishwa.

**Mzunguko unaolenga eneo mahususi**

```bash
node --import tsx/esm --test tests/unit/cli/<command>.test.ts
npm run check:cli-i18n
npm run build:cli             # mabadiliko ya CLI iliyozalishwa/iliyofungamanishwa
npm run check:pack-policy     # mabadiliko ya sehemu inayoonekana ya kifurushi
npm run lint
```

Tumia amri halisi katika saraka ya muda ya data wakati tabia inategemea uchanganuzi, faili, au hali ya
kutoka. CI hufanya ukaguzi mpana zaidi wa vizalia vya kifurushi na mfumo ikolojia.

### Hifadhidata

**Mikataba**

- Moduli za kikoa chini ya `src/lib/db/`; leta moduli mahususi moja kwa moja (safu ya zamani ya kuuza tena ya `localDb.ts` iliondolewa).
- Uhamishaji wa SQL wenye nambari na unaoweza kutekelezwa mara nyingi bila athari za ziada chini ya `src/lib/db/migrations/`, usalama wa miamala, tabia ya
  usasishaji, faharasa, na kila sehemu inayouita iliyoathiriwa na muundo wa hifadhidata.
- Njia na vishughulikiaji havitoi SQL ghafi moja kwa moja kamwe.

**Mzunguko unaolenga eneo mahususi**

```bash
npm run check:migration-numbering
npm run check:db-rules
node --import tsx/esm --test tests/unit/db/<domain>.test.ts
node --import tsx/esm --test tests/unit/db/migration-<number>.test.ts
npm run lint
```

Jaribu hifadhidata mpya na usasishaji kutoka muundo wa awali unapoongeza uhamishaji. Majaribio ya hifadhidata
lazima yafunge vishikio na yaite `resetDbInstance()` wakati wa usafishaji. Endesha `npm run test:bun:db` tu wakati
njia ya adapta ya Bun ya juhudi bora inapobadilika; Node inabaki kuwa yenye mamlaka.

### Uundaji / upelekaji

**Mikataba**

- Faili za maelezo za mzizi na nafasi ya kazi/faili ya kufunga, `scripts/build/`, ukusanyaji wa Next.js unaojitegemea, maudhui ya kifurushi cha `dist/`,
  metadata ya majukwaa ya Electron, mtiririko wa kazi wa CI, na viashiria vya upelekaji.
- Masafa ya Node yanayotumika na matumizi ya Bun yaliyoruhusiwa katika `CLAUDE.md` lazima yabaki bila kubadilishwa.
- Vizalia vya uundaji havifuatiliwi; sera za vitegemezi, leseni, mtiririko wa kazi, na vifurushi zinatumika.

**Mzunguko unaolenga eneo mahususi**

```bash
node --import tsx/esm --test tests/unit/build/<behavior>.test.ts
npm run check:build-scope
npm run check:lockfile         # mabadiliko ya kitegemezi au faili ya kufunga
npm run check:pack-policy      # mabadiliko ya sehemu ya kifurushi kilichochapishwa
npm run lint
```

Tumia `npm run build` ndani ya mazingira yako tu wakati mabadiliko yanaathiri ukusanyaji, ukusanyaji unaojitegemea, rasilimali,
au ufungamanishaji wa mazingira ya utekelezaji. Tumia `npm run build:release` tu kwa uthibitishaji wa toleo/upelekaji. Uundaji wa CI ndio
ishara ya mwisho ya majukwaa mbalimbali; mabadiliko ya Electron yanayohusu jukwaa mahususi yanahitaji uundaji lengwa unaolingana
au ushahidi wa jaribio la msingi.

## Mzunguko wa ndani dhidi ya CI

| Endesha ndani kwa kila kiraka                                                                   | CI hutoa ishara pana                                                                 |
| ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Majaribio ya moja kwa moja ya tabia na vigezo vya kategoria vilivyo hapo juu                    | Seti kamili ya majaribio ya vitengo iliyogawanywa na majaribio ya mfululizo          |
| `npm run lint`                                                                                  | Seti za Vitest na viwango vya kuzuia kurudi nyuma kwa ufunikaji/ubora                |
| Ukaguzi wa aina au ujenzi pale tu mkataba ulioathiriwa unapohitaji                              | Ujenzi wa uzalishaji, usalama, nyaraka, vitegemezi na vigezo vya sera ya PR          |
| Ukaguzi wa mwingiliano wa mkono/moja kwa moja pale tu otomatiki inaposhindwa kuthibitisha tabia | Ukaguzi wa ujumuishaji kati ya kazi na wa majukwaa uliosanidiwa na mtiririko wa kazi |

Mzunguko lengwa unaofaulu ni ushahidi kuhusu mkataba uliobadilishwa, si uthibitisho kwamba ukaguzi wa CI usiohusiana
utafaulu. Vilevile, usifanye kila hariri ya ndani isubiri matriki kamili ya hazina.

## Orodha hakiki ya ulandanishaji

Kabla ya kuomba ukaguzi:

- Thibitisha kwamba msingi wa PR bado ni tawi amilifu la juu zaidi la `release/v*`.
- Pakua msingi huo na ukague commits zilizoingizwa tangu ulipounda tawi lako.
- Kagua `git diff <active-base>...HEAD` ili kubaini mabadiliko yasiyokusudiwa au yaliyozalishwa.
- Tatua migogoro ya katalogi na nyaraka zilizozalishwa kwa kusasisha chanzo na kuzalisha upya matokeo.
- Endesha upya kila jaribio/kigezo lengwa kilichoorodheshwa katika maelezo ya PR baada ya ulandanishaji.
- Kamwe usilegeze masharti ya uthibitishaji wala kuondoa majaribio yanayohitajika ili tu kuendana na msingi uliosogezwa.

Kwa sheria za kusitisha mabadiliko wakati wa toleo na kulenga upya, tumia
[Muundo wa Matawi na Matoleo](BRANCHING_MODEL.md). Kwa orodha kamili ya CI, tumia
[Marejeleo ya Vigezo vya Ubora](../architecture/QUALITY_GATES.md).
