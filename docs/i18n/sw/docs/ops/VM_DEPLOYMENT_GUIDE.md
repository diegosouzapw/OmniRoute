## Mahitaji ya awali

| Kipengee   | Kiwango cha chini       | Kinachopendekezwa |
| ---------- | ----------------------- | ----------------- |
| **CPU**    | 1 vCPU                  | 2 vCPU            |
| **RAM**    | 1 GB                    | 2 GB              |
| **Diski**  | 10 GB SSD               | 25 GB SSD         |
| **OS**     | Ubuntu 22.04 LTS        | Ubuntu 24.04 LTS  |
| **Kikoa**  | Kimesajiliwa Cloudflare | —                 |
| **Docker** | Docker Engine 24+       | Docker 27+        |

**Watoa huduma waliojaribiwa**: Akamai (Linode), DigitalOcean, Vultr, Hetzner, AWS Lightsail.

## 1. Sanidi VM

### 1.1 Unda instance

Kwa mtoa huduma wako wa VPS unayependelea:

- Chagua Ubuntu 24.04 LTS
- Chagua mpango wa kiwango cha chini (1 vCPU / 1 GB RAM)
- Weka nenosiri imara la root au usanidi ufunguo wa SSH
- Andika **IP ya umma** (k.m., `203.0.113.10`)

### 1.2 Unganisha kupitia SSH

```bash
ssh root@203.0.113.10
```

### 1.3 Sasisha mfumo

```bash
apt update && apt upgrade -y
```

### 1.4 Sakinisha Docker

```bash
# Sakinisha vitegemezi
apt install -y ca-certificates curl gnupg

# Ongeza hazina rasmi ya Docker
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
chmod a+r /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $ (. /etc/os-release && echo "$VERSION_CODENAME") stable" | tee /etc/apt/sources.list.d/docker.list > /dev/null
apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

### 1.5 Sakinisha nginx

```bash
apt install -y nginx
```

### 1.6 Sanidi ngome ya mtandao (UFW)

```bash
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp    # SSH
ufw allow 80/tcp    # HTTP (uelekezaji upya)
ufw allow 443/tcp   # HTTPS
ufw enable
```

> **Kidokezo**: Kwa usalama wa kiwango cha juu, ruhusu IP za Cloudflare pekee kutumia porti 80 na 443. Angalia sehemu ya [Usalama wa Kina](#advanced-security).

## 2. Sakinisha OmniRoute

### 2.1 Unda saraka ya usanidi

```bash
mkdir -p /opt/omniroute
```

### 2.2 Unda faili ya vigeu vya mazingira

```bash
cat > /opt/omniroute/.env << 'EOF'
# === Usalama ===
JWT_SECRET=CHANGE-TO-A-UNIQUE-64-CHAR-SECRET-KEY
INITIAL_PASSWORD=YourSecurePassword123!
API_KEY_SECRET=REPLACE-WITH-ANOTHER-SECRET-KEY
STORAGE_ENCRYPTION_KEY=REPLACE-WITH-THIRD-SECRET-KEY
STORAGE_ENCRYPTION_KEY_VERSION=v1
MACHINE_ID_SALT=CHANGE-TO-A-UNIQUE-SALT
OMNIROUTE_WS_BRIDGE_SECRET=REPLACE-WITH-WS-BRIDGE-SECRET  # INAHITAJIKA katika uzalishaji: inatumiwa na Codex Responses WS bridge

# === Programu ===
PORT=20128
NODE_ENV=production
HOSTNAME=0.0.0.0
DATA_DIR=/app/data
APP_LOG_TO_FILE=true
AUTH_COOKIE_SECURE=true
REQUIRE_API_KEY=false

# === URL (badilisha ziwe kikoa chako) ===
# URL msingi ya ndani ya mawasiliano baina ya seva kwa kazi zilizoratibiwa / maombi kwa seva yenyewe.
BASE_URL=http://127.0.0.1:20128
# URL inayoonekana kwenye kivinjari, inayotumiwa kwa miito ya kurejea ya OAuth, viungo vya dashibodi na URL za umma zinazozalishwa.
NEXT_PUBLIC_BASE_URL=https://llms.seudominio.com
# Mpangilio wa hiari wa kubatilisha origin ya umma kwa URL za rasilimali za umma zinazozalishwa.
# OMNIROUTE_PUBLIC_BASE_URL=https://llms.seudominio.com

# === Usawazishaji wa Cloud (hiari) ===
# CLOUD_URL=https://cloud.omniroute.online
# NEXT_PUBLIC_CLOUD_URL=https://cloud.omniroute.online
EOF
```

> ⚠️ **MUHIMU**: Tengeneza funguo za siri za kipekee! Tumia `openssl rand -hex 32` kwa kila ufunguo.

### 2.3 Anzisha container

```bash
docker pull diegosouzapw/omniroute:latest

docker run -d \
  --name omniroute \
  --restart unless-stopped \
  --env-file /opt/omniroute/.env \
  -p 20128:20128 \
  -v omniroute-data:/app/data \
  diegosouzapw/omniroute:latest
```

### 2.4 Thibitisha kuwa inaendelea kufanya kazi

```bash
docker ps | grep omniroute
docker logs omniroute --tail 20
```

Inapaswa kuonyesha: `[DB] SQLite database ready` na `listening on port 20128`.

## 3. Sanidi nginx (Proksi ya Nyuma)

### 3.1 Tengeneza cheti cha SSL (Cloudflare Origin)

Katika dashibodi ya Cloudflare:

1. Nenda kwenye **SSL/TLS → Origin Server**
2. Bofya **Create Certificate**
3. Acha mipangilio chaguo-msingi (miaka 15, \*.yourdomain.com)
4. Nakili **Origin Certificate** na **Private Key**

```bash
mkdir -p /etc/nginx/ssl

# Bandika cheti
nano /etc/nginx/ssl/origin.crt

# Bandika ufunguo binafsi
nano /etc/nginx/ssl/origin.key

chmod 600 /etc/nginx/ssl/origin.key
```

### 3.2 Usanidi wa Nginx

```bash
cat > /etc/nginx/sites-available/omniroute << 'NGINX'
# Seva chaguo-msingi — huzuia ufikiaji wa moja kwa moja kupitia IP
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    listen 443 ssl default_server;
    listen [::]:443 ssl default_server;
    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    server_name _;
    return 444;
}

# OmniRoute — HTTPS
server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name llms.yourdomain.com;  # Badilisha kuwa kikoa chako

    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    client_max_body_size 100M;

    location / {
        proxy_pass http://127.0.0.1:20128;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Usaidizi wa WebSocket
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # SSE (Matukio Yanayotumwa na Seva) — utiririshaji wa majibu ya AI
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }
}

# Uelekezaji upya wa HTTP → HTTPS
server {
    listen 80;
    listen [::]:80;
    server_name llms.yourdomain.com;
    return 301 https://$server_name$request_uri;
}
NGINX
```

Weka muda wa kuisha wa mtiririko wa proksi ya nyuma ukilingana na vigeu vya mazingira vya muda wa kuisha vya OmniRoute. Ukiongeza
`FETCH_TIMEOUT_MS` / `STREAM_IDLE_TIMEOUT_MS`, ongeza `proxy_read_timeout` / `proxy_send_timeout`
zaidi ya kiwango hicho hicho.

OmniRoute hutumia `NEXT_PUBLIC_BASE_URL` kama chanzo rasmi kinachoonekana kwenye kivinjari kwa miito ya kurejesha ya OAuth
na viungo vya umma vinavyozalishwa. Uandishi wa dashibodi ulioidhinishwa hutumia maombi ya chanzo kilekile
pamoja na ulinzi wa CSRF unaofungamana na kipindi, kwa hivyo hauhitaji URL tuli ya msingi ya umma. Vichwa vya
`X-Forwarded-*` vilivyo hapo juu bado ni metadata muhimu ya uelekezaji, lakini si mbadala
wa kuweka URL dhahiri ya umma wakati OAuth au viungo vinavyozalishwa vya kivinjari vinapohitaji URL hiyo. Washa
`OMNIROUTE_TRUST_PROXY` ikiwa tu OmniRoute haifikiwi moja kwa moja na wateja na proksi yako
huondoa/huunda upya vichwa vya maombi vilivyowasilishwa.

### 3.3 Washa na Ujaribu

```bash
# Ondoa usanidi chaguo-msingi
rm -f /etc/nginx/sites-enabled/default

# Washa OmniRoute
ln -sf /etc/nginx/sites-available/omniroute /etc/nginx/sites-enabled/omniroute

# Jaribu na upakie upya
nginx -t && systemctl reload nginx
```

## 4. Sanidi DNS ya Cloudflare

### 4.1 Ongeza rekodi ya DNS

Kwenye dashibodi ya Cloudflare → DNS:

| Aina | Jina   | Maudhui                   | Proksi                    |
| ---- | ------ | ------------------------- | ------------------------- |
| A    | `llms` | `203.0.113.10` (IP ya VM) | ✅ Imewekwa kwenye proksi |

### 4.2 Sanidi SSL

Chini ya **SSL/TLS → Overview**:

- Hali: **Full (Strict)**

Chini ya **SSL/TLS → Edge Certificates**:

- Tumia HTTPS Kila Wakati: ✅ Imewashwa
- Toleo la Chini Kabisa la TLS: TLS 1.2
- Uandikaji Upya wa HTTPS Kiotomatiki: ✅ Umewashwa

### 4.3 Majaribio

```bash
curl -sI https://llms.seudominio.com/health
# Inapaswa kurudisha HTTP/2 200
```

## 5. Uendeshaji na Matengenezo

### Sasisha hadi toleo jipya

```bash
docker pull diegosouzapw/omniroute:latest
docker stop omniroute && docker rm omniroute
docker run -d --name omniroute --restart unless-stopped \
  --env-file /opt/omniroute/.env \
  -p 20128:20128 \
  -v omniroute-data:/app/data \
  diegosouzapw/omniroute:latest
```

### Tazama kumbukumbu

```bash
docker logs -f omniroute          # Mtiririko wa wakati halisi
docker logs omniroute --tail 50   # Mistari 50 ya mwisho
```

### Hifadhi rudufu ya hifadhidata kwa mikono

```bash
# Nakili data kutoka kwenye volume hadi kwenye host
docker cp omniroute:/app/data ./backup-$(date +%F)

# Au bana volume nzima
docker run --rm -v omniroute-data:/data -v $(pwd):/backup \
  alpine tar czf /backup/omniroute-data-$(date +%F).tar.gz /data
```

### Rejesha kutoka kwenye hifadhi rudufu

```bash
docker stop omniroute
docker run --rm -v omniroute-data:/data -v $(pwd):/backup \
  alpine sh -c "rm -rf /data/* && tar xzf /backup/omniroute-data-YYYY-MM-DD.tar.gz -C /"
docker start omniroute
```

## Uboreshaji kwa Kumbukumbu Ndogo / VPS Ndogo

Kwa usakinishaji kwenye VPS ndogo (RAM ya GB 1 au chini):

- **Zima huduma za chinichini** — weka `OMNIROUTE_DISABLE_BACKGROUND_SERVICES=1` ili kuruka kipanga ratiba, seva ya MCP, na kazi za matengenezo ya mara kwa mara. Angalia `docs/reference/ENVIRONMENT.md`.
- **Tumia hali ya SQLite WAL** — imewashwa kwa chaguo-msingi, hupunguza kiwango cha juu cha matumizi ya kumbukumbu wakati wa usomaji unaofanyika kwa wakati mmoja.
- **Weka kikomo cha heap ya V8** — weka `OMNIROUTE_MEMORY_MB` (k.m. `512`) ili mazingira ya utekelezaji yasikadirie kikomo kikubwa kuliko VM. Angalia `docs/reference/ENVIRONMENT.md`.
- **Upokeaji wa kazi nzito hujirekebisha kiotomatiki kulingana na kikomo cha heap** -- baada ya `OMNIROUTE_MEMORY_MB` kuwekwa kama ilivyo hapo juu, bajeti ya baiti za uingizaji (`OMNIROUTE_CHAT_MAX_INFLIGHT_BYTES`) huhesabiwa kutokana na kikomo hicho hicho, kwa hivyo VM yenye kumbukumbu finyu hupata bajeti ndogo ya maombi ya wakati mmoja bila urekebishaji wa ziada; maombi yanayozidi kikomo hupata `503` inayoweza kujaribiwa tena pamoja na `Retry-After` badala ya kushindania kumbukumbu. Weka kikomo cha zamani cha idadi ya maombi cha `OMNIROUTE_CHAT_MAX_HEAVY_IN_FLIGHT` ikiwa tu unahitaji kikomo madhubuti cha ziada.
- **Epuka `next build` kwenye VPS** — jenga kwenye mashine ya ndani na usambaze matokeo ya standalone (`.next/standalone/`).
- **Fuatilia kwa `top` / `free -m`** — kwa kawaida OmniRoute hutumia RSS ya MB 200-400 ikiwa haitumiki kwenye VM ya GB 1.
