> **Chanzo rasmi:** `src/lib/cloudAgent/` na `src/app/api/v1/agents/tasks/`
> **Ilisasishwa mara ya mwisho:** 2026-06-28 — v3.8.40 (usasishaji wa frontmatter; mawakala 4 ikijumuisha cursor-cloud)

OmniRoute huratibu mawakala wa uandishi wa msimbo wanaopangishwa kwenye wingu na wahusika wengine (Codex Cloud, Cursor,
Devin, Jules) kama majukumu yanayoendelea kwa muda mrefu. Kila wakala huwekwa nyuma ya kiolesura kimoja ili
wateja waweze kuwasilisha prompt + URL ya repo na kupokea matokeo bila kushughulikia
API mahususi za watoa huduma.

Jukumu la Cloud Agent **si** ukamilishaji wa kawaida wa gumzo. Ni kitengo cha kazi cha kudumu, chenye hatua nyingi
ambacho kinaweza kuchukua dakika hadi saa, kinaweza kutoa Pull Request kama
artifact yake, na kinaauni ujumbe wa ufuatiliaji pamoja na (kwa baadhi ya watoa huduma) hatua za kuidhinisha mpango.

| Kitambulisho cha Mtoa Huduma | Class              | Chanzo                                | URL ya Msingi ya Upstream               | Uidhinishaji wa Mpango |

| `devin`                      | `DevinAgent`       | `src/lib/cloudAgent/agents/devin.ts`  | `https://api.devin.ai/v1`               | Ndiyo                  |
| `codex-cloud`                | `CodexCloudAgent`  | `src/lib/cloudAgent/agents/codex.ts`  | `https://api.openai.com/v1/codex/cloud` | Hapana (kiotomatiki)   |

Registry: `src/lib/cloudAgent/registry.ts` — husafirisha `getAgent(providerId)`,
`getAvailableAgents()`, na `isCloudAgentProvider(providerId)`. Registry ni
`Record<string, CloudAgentBase>` rahisi ya ndani ya kumbukumbu inayojazwa wakati moduli inapopakiwa.

## Usanifu

```
Mteja (Dashibodi / CLI / API)
  → POST /api/v1/agents/tasks (uthibitishaji wa usimamizi unahitajika)
    → uthibitishaji wa CreateCloudAgentTaskSchema (Zod)
    → registry.getAgent(providerId)
    → getCloudAgentCredentials(providerId)
      └─ huchukua kutoka getProviderConnections({ provider, isActive: true })
         (apiKey kwanza, accessToken hutumika kama mbadala)
    → agent.createTask({ prompt, source, options }, credentials)
      └─ HTTP POST kwenda kwenye API ya mtoa huduma wa upstream
      └─ hurejesha CloudAgentTask yenye id ya ndani + externalId
    → insertCloudAgentTask(...) ndani ya cloud_agent_tasks (SQLite)

Uchunguzi wa mara kwa mara (ulandanishaji wa polepole wakati wa kusoma):
  GET /api/v1/agents/tasks/[id]
    → getCloudAgentTaskById(id)
    → agent.getStatus(externalId, credentials)  // huonyesha upya hali + shughuli
    → updateCloudAgentTask(...) kwa hali, matokeo, completed_at mpya
    → hurejesha jukumu lililowekwa katika mfululizo

Mwingiliano:
  POST /api/v1/agents/tasks/[id]  mwili: { action: "approve" | "message" | "cancel" }
    → agent.approvePlan(externalId, credentials)        kwa "approve"
    → agent.sendMessage(externalId, message, credentials) kwa "message"
    → hali hubadilika kuwa "cancelled"                  kwa "cancel" (ya ndani pekee)
```

Ulandanishaji ni wa **polepole**: hali huonyeshwa upya kutoka upstream kila `GET /tasks/[id]`.
Hakuna kichunguzi cha chinichini. Dashibodi zinazohitaji hali mpya zinapaswa kufanya uchunguzi wa endpoint ya GET
kwa kipindi kinachofaa.

## Kiolesura cha `CloudAgentBase`

Chanzo: `src/lib/cloudAgent/baseAgent.ts`

```typescript
export interface AgentCredentials {
  apiKey: string;
  baseUrl?: string;
}

export interface CreateTaskParams {
  prompt: string;
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
}

export interface GetStatusResult {
  status: CloudAgentStatus;
  externalId?: string;
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
}

export abstract class CloudAgentBase {
  abstract readonly providerId: string;
  abstract readonly baseUrl: string;

  abstract createTask(p: CreateTaskParams, c: AgentCredentials): Promise<CloudAgentTask>;
  abstract getStatus(externalId: string, c: AgentCredentials): Promise<GetStatusResult>;
  abstract approvePlan(externalId: string, c: AgentCredentials): Promise<void>;
  abstract sendMessage(
    externalId: string,
    message: string,
    c: AgentCredentials
  ): Promise<CloudAgentActivity>;
  abstract listSources(
    c: AgentCredentials
  ): Promise<{ name: string; url: string; branch?: string }[]>;

  protected mapStatus(raw: string): CloudAgentStatus; // mfuatano wa herufi wa upstream kwa njia ya ukadiriaji → enum
  protected generateTaskId(): string; // `task_<ts>_<rand>`
  protected generateActivityId(): string; // `act_<ts>_<rand>`
}
```

`CodexCloudAgent.approvePlan` hutupa hitilafu kimakusudi — Codex Cloud hupanga kiotomatiki na
haina lango la idhini. `CodexCloudAgent.listSources` hurudisha `[]`.

`CursorCloudAgent` huendesha Background / Cloud Agents za Cursor kupitia REST API yake rasmi
(`api.cursor.com/v0`) kwa kutumia **ufunguo wa API wa mtumiaji au akaunti ya huduma** — njia mbadala salama zaidi
ya mhusika wa kwanza kuliko kutumia tena kipindi cha OAuth cha Cursor IDE (mtoa huduma `cursor`,
ambacho kina onyo la hatari ya kupigwa marufuku). Ni adapta ya kawaida ya REST (haina utegemezi asilia
wa `@cursor/sdk`). `approvePlan` hutupa hitilafu (mawakala wa Cursor hujiendesha wenyewe); `listSources` huorodhesha
hazina zinazoweza kufikiwa kwa ufunguo huo. Cursor hurudisha enum za hali kwa HERUFI KUBWA
(`CREATING`/`RUNNING`/`FINISHED`/`ERROR`), ambazo huunganishwa moja kwa moja na
`CloudAgentStatus` ya pamoja. `baseUrl` inaweza kubadilishwa kwa kila kitambulisho ili toleo/njia ya API iweze
kusahihishwa bila kubadilisha msimbo.

## Aina za Kikoa

Chanzo: `src/lib/cloudAgent/types.ts`

```typescript
export const CLOUD_AGENT_STATUS = {
  QUEUED: "queued",
  RUNNING: "running",
  AWAITING_APPROVAL: "awaiting_approval",
  COMPLETED: "completed",
  FAILED: "failed",
  CANCELLED: "cancelled",
} as const;

export interface CloudAgentSource {
  repoName: string;
  repoUrl: string; // lazima iwe URL halali
  branch?: string;
}

export interface CloudAgentResult {
  prUrl?: string;
  prNumber?: number;
  commitMessage?: string;
  diffUrl?: string;
  summary?: string;
  duration?: number; // sekunde, nambari kamili chanya
  cost?: number; // nambari ya desimali chanya
}

export interface CloudAgentActivity {
  id: string;
  type: "plan" | "command" | "code_change" | "message" | "error" | "completion";
  content: string;
  timestamp: string; // ISO 8601
  metadata?: Record<string, unknown>;
}

export interface CloudAgentTask {
  id: string; // kitambulisho cha ndani cha `task_...`
  providerId: "jules" | "devin" | "codex-cloud" | "cursor-cloud";
  externalId?: string; // kitambulisho cha mtoa huduma wa upstream
  status: CloudAgentStatus;
  prompt: string; // herufi 1..10000
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
  createdAt: string;
  updatedAt: string;
  completedAt?: string;
}
```

Skima za uthibitishaji (`CreateCloudAgentTaskSchema`, `UpdateCloudAgentTaskSchema`)
husafirishwa pamoja na aina hizo na hutumiwa na vidhibiti vya njia.

## Hifadhidata

Chanzo: `src/lib/cloudAgent/db.ts` — jedwali huundwa kwa kucheleweshwa kupitia
`createCloudAgentTaskTable()` (ambayo pia huitwa kutoka `src/lib/cloudAgent/index.ts` wakati wa
kuingiza moduli).

```sql
CREATE TABLE IF NOT EXISTS cloud_agent_tasks (
  id           TEXT PRIMARY KEY,
  provider_id  TEXT NOT NULL,
  external_id  TEXT,
  status       TEXT NOT NULL DEFAULT 'queued',
  prompt       TEXT NOT NULL,
  source       TEXT NOT NULL,             -- JSON
  options      TEXT DEFAULT '{}',         -- JSON
  result       TEXT,                       -- JSON
  activities   TEXT DEFAULT '[]',          -- JSON
  error        TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_provider ON cloud_agent_tasks(provider_id);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_status   ON cloud_agent_tasks(status);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_created  ON cloud_agent_tasks(created_at DESC);
```

`updateCloudAgentTask` hutekeleza **orodha inayoruhusiwa ya safu wima** ili kuzuia uingizaji hasidi wa SQL:
`status`, `prompt`, `source`, `options`, `result`, `activities`, `error`,
`completed_at`. Ufunguo mwingine wowote katika sasisho la sehemu huondolewa bila kutoa taarifa.

## API ya REST — Mzunguko wa Maisha wa Kazi

**Uthibitishaji:** Vituo vyote vya `/api/v1/agents/tasks*` vinahitaji **uthibitishaji wa usimamizi**
(`requireCloudAgentManagementAuth` hufunika `requireManagementAuth` kutoka
`src/lib/api/requireManagementAuth`). Hili limetekelezwa baada ya commit `588a0333`
(_"fix(auth): require management auth for agent and cooldown APIs"_).

| Mbinu   | Njia                          | Madhumuni                                                          |
| ------- | ----------------------------- | ------------------------------------------------------------------ |
| OPTIONS | `/api/v1/agents/tasks`        | Ukaguzi wa awali wa CORS                                           |
| GET     | `/api/v1/agents/tasks`        | Orodhesha kazi (kichujio: `provider`, `status`, `limit≤500`)       |
| POST    | `/api/v1/agents/tasks`        | Unda kazi (hutuma kwa huduma ya juu + huihifadhi)                  |
| DELETE  | `/api/v1/agents/tasks?id=...` | Futa kazi kwa kitambulisho cha hoja (**haighairi** huduma ya juu)  |
| OPTIONS | `/api/v1/agents/tasks/[id]`   | Ukaguzi wa awali wa CORS                                           |
| GET     | `/api/v1/agents/tasks/[id]`   | Soma kazi + landanisha hali kutoka huduma ya juu kwa kucheleweshwa |
| POST    | `/api/v1/agents/tasks/[id]`   | Kitendo: `approve` / `message` / `cancel`                          |
| DELETE  | `/api/v1/agents/tasks/[id]`   | Futa kazi kwa kitambulisho kilicho kwenye njia                     |

### Unda kazi

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Fix the bug in src/foo.ts where the parser returns null",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    },
    "options": {
      "autoCreatePr": true,
      "planApprovalRequired": false
    }
  }'
```

```json

  "data": {

    "providerId": "devin",
    "externalId": "session_xyz",
    "status": "queued",
    "prompt": "...",
    "source": { "repoName": "user/repo", "repoUrl": "...", "branch": "main" },
```

### Idhinisha mpango

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"action":"approve"}'
```

### Tuma ujumbe wa ufuatiliaji

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"message","message":"Also add a unit test for the parser"}'
```

### Ghairi (hali ya ndani pekee)

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"cancel"}'
```

`cancel` hubadilisha `status` kuwa `"cancelled"` katika hifadhidata ya ndani lakini **haiiti**
mtoa huduma wa juu — hakuna RPC ya kusitisha katika `CloudAgentBase`. Ili kusimamisha utozaji
kwenye huduma ya juu, sitisha kazi katika dashibodi ya mtoa huduma mwenyewe.

## REST API — Miundombinu ya Mtoa Huduma za Cloud

Endpointi hizi saidizi zilizo chini ya `src/app/api/cloud/` hutumiwa na wateja wa mbali
(CLI, programu ya Electron, au wafanyakazi wa ulandanishi) kusoma metadata ya muunganisho wa mtoa huduma
na kutatua lakabu za modeli. Zinathibitishwa kwa **ufunguo wa kawaida wa API**
(kupitia `validateApiKey`), si uthibitishaji wa usimamizi unaotumiwa na endpointi za kazi.

| Mbinu | Njia                            | Madhumuni                                                                                 |
| ----- | ------------------------------- | ----------------------------------------------------------------------------------------- |
| POST  | `/api/cloud/auth`               | Thibitisha ufunguo wa API, rudisha metadata ya muunganisho iliyofichwa + lakabu za modeli |
| PUT   | `/api/cloud/credentials/update` | Onyesha upya `accessToken` / `refreshToken` / `expiresAt`                                 |
| POST  | `/api/cloud/model/resolve`      | Tatua lakabu ya modeli kuwa `{ provider, model }`                                         |
| GET   | `/api/cloud/models/alias`       | Orodhesha lakabu zote za modeli                                                           |
| PUT   | `/api/cloud/models/alias`       | Weka lakabu ya modeli (na uilandanishe kiotomatiki na Cloud ikiwa imewezeshwa)            |

`/api/cloud/auth` hairudishi kamwe `apiKey` / `accessToken` / `refreshToken` ghafi. Huwa
inarudisha `hasApiKey`, `hasAccessToken`, `hasRefreshToken`, na onyesho la awali lililofichwa
(`maskedApiKey`: herufi 4 za kwanza + `****` + herufi 4 za mwisho).

## Utatuzi wa Vitambulisho

`getCloudAgentCredentials(providerId)` katika `src/lib/cloudAgent/api.ts`:

1. Hupakia miunganisho hai ya watoa huduma kupitia `getProviderConnections({ provider: providerId, isActive: true })`.
2. Kwa kila muunganisho, hupendelea `apiKey` (iliyoondolewa nafasi za pembeni). Ikiwa haipatikani, hutumia `accessToken`.
3. Hurudisha tokeni ya kwanza isiyo tupu ikiwa imefungwa kama `{ apiKey: token }`.
4. Hurudisha `null` ikiwa hakuna tokeni inayoweza kutumiwa iliyopatikana — API hujibu `400` ikiwa na
   `"Hakuna vitambulisho hai vilivyosanidiwa kwa mtoa huduma wa wakala wa cloud: <id>"`.

Hii inamaanisha kuwa Cloud Agents hutumia tena jedwali lilelile la Provider Connection kama watoa huduma
wa kawaida wa LLM. Ili kuwezesha Jules, unda muunganisho hai wenye `provider: "jules"`
na `apiKey` iliyojazwa.

## Dashibodi

Chanzo: `src/app/(dashboard)/dashboard/cloud-agents/page.tsx`

Ukurasa wa React wa `"use client"` ambao:

- Huorodhesha kazi (zinazokaguliwa mara kwa mara kupitia `GET /api/v1/agents/tasks`).
- Huwasilisha kazi mpya kupitia fomu inayolingana na `CreateCloudAgentTaskSchema`.
- Huonyesha beji za hali (`queued`, `running`, `awaiting_approval`, `completed`,
  `failed`, `cancelled`) na huonyesha ratiba ya matukio ya `activities[]`.
- Huonyesha `result.prUrl` / `commitMessage` / `summary` wakati `status === "completed"`.

## Ujumuishaji na A2A

Cloud Agents wanaweza kutolewa kama ujuzi wa A2A kwa kusajili ujuzi wa A2A unaokabidhi
kishughulikiaji chake cha `tasks/send` kwa `getAgent(...).createTask(...)` na kutafsiri matukio ya hali
ya kazi za A2A kwenda kwenye itifaki ya JSON-RPC 2.0. Tazama [A2A-SERVER.md](./A2A-SERVER.md).

## Kuongeza Cloud Agent Mpya

1. Unda `src/lib/cloudAgent/agents/<name>.ts` inayopanua `CloudAgentBase`.
2. Tekeleza `createTask`, `getStatus`, `approvePlan` (au toa hitilafu ikiwa haitumiki),
   `sendMessage`, `listSources`. Tumia `this.mapStatus(...)` kusawazisha hali.
3. Isajili katika `src/lib/cloudAgent/registry.ts` chini ya `providerId` thabiti.
4. Panua muungano wa thamani halisi wa `providerId` katika `src/lib/cloudAgent/types.ts`
   (`CloudAgentTask.providerId` na `CreateCloudAgentTaskSchema`).
5. Ongeza mtoa huduma kwenye `src/shared/constants/providers.ts` ikiwa anahitaji rekodi ya
   muunganisho. Watoa huduma wanaotumia OAuth pia wanahitaji `src/lib/oauth/providers/`.
6. Ongeza majaribio chini ya `tests/unit/cloud-agent-*.test.ts`.
7. Sasisha hati hii na konstanti ya `CLOUD_AGENTS` ya dashibodi.
