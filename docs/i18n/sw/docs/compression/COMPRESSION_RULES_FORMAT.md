> **Skima rasmi (chanzo cha ukweli):** [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) (rasimu ya 2020-12 ya JSON Schema).
> Mifano iliyo hapa chini ni ya ufafanuzi — ukiwa na shaka, thibitisha kifurushi chako dhidi ya `_schema.json`.

## Vifurushi vya Kanuni za Caveman

Vifurushi vya kanuni za Caveman hupatikana chini ya:

```txt
open-sse/services/compression/rules/<language>/<pack>.json
```

Kila kifurushi kina vibadilisho vinavyotumika kwenye maandishi ya kawaida baada ya maeneo yaliyolindwa kutengwa.

```json
{
  "language": "en",
  "category": "filler",
  "rules": [
    {
      "name": "question_to_directive",
      "pattern": "\\b(?:Can you explain why|Could you show me how)\\b\\s*",
      "replacement": "Explain why ",
      "replacementMap": {
        "can you explain why": "Explain why ",
        "could you show me how": "Show how "
      },
      "flags": "gi",
      "context": "all",
      "category": "context",
      "minIntensity": "lite",
      "description": "Convert verbose questions into direct requests."
    }
  ]
}
```

### Sehemu za Caveman

| Sehemu                   | Inahitajika | Maelezo                                                                                             |
| ------------------------ | ----------- | --------------------------------------------------------------------------------------------------- |
| `language`               | ndiyo       | Kitambulisho cha lugha kinachofanana na BCP-47 kama vile `en`, `pt-BR`, `es`                        |
| `category`               | ndiyo       | Jina/kategoria ya faili ya kategoria ya kifurushi, kwa mfano `filler` au `dedup`                    |
| `rules`                  | ndiyo       | Safu ya kanuni za ubadilishaji za regex                                                             |
| `rules[].name`           | ndiyo       | Jina thabiti la kanuni                                                                              |
| `rules[].pattern`        | ndiyo       | Chanzo cha regex cha JavaScript                                                                     |
| `rules[].flags`          | hapana      | Alama za regex za JavaScript; chaguo-msingi ni `gi`                                                 |
| `rules[].replacement`    | hapana      | Mfuatano wa ubadilishaji au thamani mbadala wakati `replacementMap` haipati ulinganifu              |
| `rules[].replacementMap` | hapana      | Vibadilisho maalumu vya ulinganifu, vilivyoainishwa kwa maandishi yaliyolinganishwa na kusawazishwa |
| `rules[].context`        | hapana      | `all`, `user`, `assistant`, au `system`; chaguo-msingi ni `all`                                     |
| `rules[].category`       | hapana      | `filler`, `context`, `structural`, `dedup`, `terse`, au `ultra`                                     |
| `rules[].minIntensity`   | hapana      | `lite`, `full`, au `ultra`; chaguo-msingi ni `lite`                                                 |
| `rules[].description`    | hapana      | Muhtasari wa kanuni unaoweza kusomeka na binadamu                                                   |

Tumia `flags` wakati ulinganishaji unaozingatia herufi kubwa na ndogo ni muhimu, kwa mfano kuondoa kibainishi kabla ya maandishi yenye herufi ndogo bila kuondoa `the OpenAI API`. Tumia `replacementMap` wakati regex moja ina mbadala nyingi zinazohitaji matokeo tofauti; hii huwezesha vifurushi vya kanuni vya JSON kubaki na data pekee huku vikihifadhi tabia ya vitendaji vya ubadilishaji vya TypeScript vilivyojengewa ndani na vyenye uwezo zaidi.

## Vifurushi vya Vichujio vya RTK

Vichujio vya RTK vinapatikana chini ya:

```txt
open-sse/services/compression/engines/rtk/filters/<filter>.json
```

Kila kichujio hufafanua jinsi ya kutambua na kubana familia ya matokeo ya amri.

```json
{
  "id": "test-vitest",
  "label": "Vitest output",
  "category": "test",
  "priority": 92,
  "match": {
    "outputTypes": ["test-vitest"],
    "commands": ["vitest", "npm test", "npm run test"],
    "patterns": ["\\bFAIL\\b", "\\bPASS\\b", "\\bTest Files\\b"]
  },
  "rules": {
    "stripAnsi": true,
    "replace": [{ "pattern": "\\s+\\[[0-9]+ms\\]", "replacement": "" }],
    "matchOutput": [
      {
        "pattern": "All tests passed",
        "message": "vitest: ok",
        "unless": "FAIL|Error:"
      }
    ],
    "includePatterns": ["FAIL", "Error:", "Test Files", "Tests"],
    "dropPatterns": ["^\\s*$", "Duration\\s+\\d+"],
    "collapsePatterns": ["^\\s+at "],
    "deduplicate": true,
    "truncateLineAt": 240,
    "maxLines": 160,
    "headLines": 24,
    "tailLines": 40,
    "onEmpty": "vitest: ok",
    "filterStderr": false
  },
  "preserve": {
    "errorPatterns": ["FAIL", "Error:", "AssertionError"],
    "summaryPatterns": ["Test Files", "Tests", "Snapshots"]
  },
  "tests": [
    {
      "name": "keeps failing tests",
      "command": "vitest",
      "input": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed",
      "expected": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed"
    }
  ]
}
```

### Sehemu za RTK

| Sehemu                     | Inahitajika | Maelezo                                                                                |
| -------------------------- | ----------- | -------------------------------------------------------------------------------------- |
| `id`                       | ndiyo       | Kitambulisho thabiti cha kichujio                                                      |
| `label`                    | ndiyo       | Jina linalosomeka kwenye dashibodi                                                     |
| `category`                 | ndiyo       | Familia ya kichujio: git, test, build, shell, docker, package, infra, cloud, generic   |
| `priority`                 | hapana      | Kipaumbele cha juu hushinda vichujio vingi vinapolingana                               |
| `match.outputTypes`        | hapana      | Vitambulisho vya matokeo ya kigunduzi vinavyochagua kichujio hiki                      |
| `match.commands`           | hapana      | Tokeni za amri zinazochagua kichujio hiki                                              |
| `match.patterns`           | hapana      | Ruwaza za regex zinazochagua kichujio hiki kutoka kwenye maandishi ya matokeo          |
| `rules.stripAnsi`          | hapana      | Ondoa mifuatano ya escape ya ANSI kabla ya hatua za regex                              |
| `rules.replace`            | hapana      | Ubadilishaji wa regex uliopangwa unaotekelezwa mstari kwa mstari                       |
| `rules.matchOutput`        | hapana      | Kanuni za matokeo ya kusitisha mapema zenye kinga ya hiari ya `unless`                 |
| `rules.includePatterns`    | hapana      | Mistari ya kupewa kipaumbele ili ihifadhiwe                                            |
| `rules.dropPatterns`       | hapana      | Mistari ya kuondoa kama kelele                                                         |
| `rules.collapsePatterns`   | hapana      | Mistari inayojirudia na inayolingana ambayo inaweza kukunjwa                           |
| `rules.deduplicate`        | hapana      | Kunja mistari iliyorekebishwa inayojirudia                                             |
| `rules.truncateLineAt`     | hapana      | Kikomo cha herufi kwa kila mstari ambacho ni salama kwa Unicode                        |
| `rules.maxLines`           | hapana      | Idadi ya juu zaidi ya mistari inayohifadhiwa kabla ya kuhifadhi sehemu ya mwisho       |
| `rules.headLines`          | hapana      | Mistari ya mwanzo inayohifadhiwa wakati wa ufupishaji                                  |
| `rules.tailLines`          | hapana      | Mistari ya mwisho inayohifadhiwa kwa muktadha wa hivi karibuni                         |
| `rules.onEmpty`            | hapana      | Ujumbe wa akiba wakati uchujaji unapoondoa maudhui yote                                |
| `rules.filterStderr`       | hapana      | Rekebisha viambishi-awali vya kawaida vya stderr kabla ya hatua za baadaye za uchujaji |
| `preserve.errorPatterns`   | hapana      | Mistari ya hitilafu inayopaswa kubaki baada ya ufupishaji                              |
| `preserve.summaryPatterns` | hapana      | Mistari ya muhtasari inayopaswa kubaki baada ya ufupishaji                             |
| `tests[]`                  | hapana      | Sampuli za uthibitishaji za ndani zinazotumiwa na lango la uthibitishaji la RTK        |

RTK hutekeleza hatua za kitamko kwa mpangilio huu: `stripAnsi`, `filterStderr`, `replace`,
`matchOutput`, `dropPatterns`/`includePatterns`, `truncateLineAt`, `headLines`/`tailLines`,
`maxLines`, na `onEmpty`.

Vichujio maalum vinaweza kupakiwa kutoka:

1. Faili za mradi za `.rtk/filters.json` baada tu ya hash inayolingana ya `.rtk/trust.json` kuwepo au
   `trustProjectFilters` kuwashwa.
2. `DATA_DIR/rtk/filters.json` ya kimataifa.
3. Vichujio vilivyojengewa ndani.

Faili maalum za mradi/kimataifa zinaweza kuwa na kipengee kimoja cha kichujio au safu ya vipengee vya vichujio. Vichujio maalum visivyo halali
hurukwa pamoja na taarifa za uchunguzi; vichujio vilivyojengewa ndani visivyo halali husababisha uthibitishaji kushindwa.

Faili ya uaminifu ya mradi:

```json
{
  "filtersSha256": "0123456789abcdef..."
}
```

Ubatilishaji wa mazingira `OMNIROUTE_RTK_TRUST_PROJECT_FILTERS=1` huamini vichujio vya mradi bila
hash na unapaswa kutumika tu kwa uendelezaji wa ndani unaodhibitiwa.

## Kanuni za Usalama

- Weka kanuni ziwe idempotent: kuendesha kichujio kilekile mara mbili kusiharibu matokeo.
- Hifadhi maandishi halisi ya hitilafu, njia za faili, nambari za mistari, na muhtasari wa amri inapowezekana.
- Epuka kanuni zinazorekebisha vizuizi vya msimbo, payload za JSON, URLs, au siri.
- Ongeza ufunikaji wa unit kwa familia mpya za amri katika majaribio ya detector/filter.
- Ongeza sampuli za `tests[]` kwenye kila kichujio kilichojengewa ndani na kwenye vichujio maalum vinavyoshirikiwa.

## Uthibitishaji

Vifurushi vya kanuni huthibitishwa kabla ya kutumiwa. Vifurushi vya Caveman vilivyojengewa ndani na vichujio vya RTK vilivyojengewa ndani hushindwa mara moja
wakati wa uthibitishaji ili rasilimali za toleo zilizoharibika zigunduliwe kabla ya kusambazwa. Vichujio maalum vya RTK
hurukwa huku taarifa za uchunguzi zikitolewa wakati uchanganuzi au uthibitishaji wa uaminifu unaposhindwa.

Uthibitishaji mahususi:

```bash
node --import tsx/esm --test tests/unit/compression/rule-loader.test.ts tests/unit/compression/language-packs.test.ts
node --import tsx/esm --test tests/unit/compression/rtk-verify.test.ts tests/unit/compression/rtk-dsl-pipeline.test.ts
```
