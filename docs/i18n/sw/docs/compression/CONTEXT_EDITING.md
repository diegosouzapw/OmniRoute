**Uhariri wa Muktadha** Uliokabidhiwa ni kipengele cha usimamizi wa muktadha kinachopatikana kwa Claude pekee. Tofauti na injini za ndani za OmniRoute za
mbano (Caveman, RTK, LLMLingua, mifumo iliyopangwa kwa safu) — ambazo huandika upya sehemu ya ombi
_kabla_ halijaondoka kwenye proksi — Uhariri wa Muktadha huiomba **provider** kuondoa vizuizi vya zamani vya
matumizi ya zana / matokeo ya zana kutoka kwenye dirisha lake la muktadha linaloendelea. OmniRoute huambatisha tu kigezo cha mwili
(`context_management.edits[]`); Claude hufanya uondoaji halisi kwa kutumia tokenizer yake mwenyewe.

Huu kwa asili ni uwezo uliokabidhiwa: watoa huduma wengine hukataa kigezo hicho, kwa hivyo OmniRoute huuwekea upeo
madhubuti kwa Claude na relays zinazooana na Claude Code.

Chanzo cha ukweli: `open-sse/config/contextEditing.ts` (vitambulisho vya mikakati, uingizaji kwenye mwili, uchukuaji wa
telemetria), `open-sse/executors/base.ts` (kizuizi cha uingizaji + mbinu mbadala ya 400), na
`open-sse/services/compression/types.ts` (muundo wa usanidi + chaguo-msingi).

## Kile ambacho `clear_tool_uses` hufanya

OmniRoute huingiza uhariri mmoja kwenye mwili wa Anthropic Messages unaotumwa:

```json
{
  "context_management": {
    "edits": [
      {
        "type": "clear_tool_uses_20250919",
        "trigger": { "type": "input_tokens", "value": 100000 },
        "keep": { "type": "tool_uses", "value": 3 }
      }
    ]
  }
}
```

- `type: "clear_tool_uses_20250919"` — kitambulisho cha mkakati wa Anthropic chenye tarehe (`CLEAR_TOOL_USES_STRATEGY`).
- `trigger.value: 100000` — tokeni za ingizo za ombi zikizidi kiwango hiki, Claude huanza
  kuondoa jozi za zamani za matumizi ya zana/matokeo (`CONTEXT_EDITING_DEFAULT_TRIGGER_TOKENS`, chaguo-msingi la Anthropic).
- `keep.value: 3` — jozi N za hivi karibuni zaidi za matumizi ya zana/matokeo huachwa bila kuguswa
  (`CONTEXT_EDITING_DEFAULT_KEEP_TOOL_USES`).

Beta hutangazwa kupitia kichwa cha `anthropic-beta: context-management-2025-06-27`, ambacho
OmniRoute tayari hutuma kwenye maombi ya Claude.

Uingizaji hufanywa na `applyContextEditingToBody()` na ni **idempotent**: ikiwa uhariri wa `clear_tool_uses`
tayari upo kwenye mwili (umeongezwa na mwito wa awali au umetolewa na mteja), mwili
huachwa jinsi ulivyo. Ikiwa uhariri wa `clear_thinking_20251015` pia upo, OmniRoute hupanga kwa uthabiti uhariri wa
`clear_thinking` uwe mwanzo, kwa sababu Anthropic inahitaji `clear_thinking` itangulie
`clear_tool_uses` katika safu ya `edits[]`.

## Kibadili cha kuwezesha kwa kila mchanganyiko

Uhariri wa Muktadha **umezimwa kwa chaguo-msingi** na lazima uwezeshwe kwa hiari. Kibadili ni thamani moja ya boolean iliyo katika
usanidi wa mbano:

- Ufunguo wa mpangilio: `contextEditing.enabled` (camelCase — **si** `context_editing` / `context-editing`).
- Aina: `ContextEditingConfig { enabled: boolean }` katika
  `open-sse/services/compression/types.ts`.
- Chaguo-msingi: `DEFAULT_CONTEXT_EDITING_CONFIG = { enabled: false }`.
- Skima ya Zod: `contextEditingConfigSchema` katika `src/shared/validation/compressionConfigSchemas.ts`.
- Hifadhi: huhifadhiwa pamoja na mipangilio mingine ya mbano (ikisawazishwa katika
  `src/lib/db/compression.ts`).

Katika dashibodi, kibadili hiki kinapatikana kwenye kitovu cha mbano
(`src/app/(dashboard)/dashboard/context/combos/CompressionHub.tsx`) na huandika
`{ contextEditing: { enabled: … } }` tena kupitia `saveSettings()`. Kwa kuwa husafirishwa ndani ya
kitu cha mipangilio ya mbano, huunganishwa na wasifu wa mbano wa kila mchanganyiko badala ya kuwa
sehemu inayojitegemea kikamilifu — usanidi hubeba tu alama ya kuwasha/kuzima; viwango vyote (`trigger`,
`keep`) ni konstanti zilizoelezwa hapo juu.

## Udhibiti kwa Claude pekee

Uingizaji hutokea tu kwa Claude halisi au relay zinazooana na Claude Code. Kigezo katika
`open-sse/executors/base.ts` ni:

```ts
if (
  (this.provider === "claude" || isClaudeCodeCompatible(this.provider)) &&
  contextEditing?.enabled &&
  !contextEditingDisabled
) {
  applyContextEditingToBody(transformedBody, { enabled: true });
}
```

- `this.provider === "claude"` — ufunguo/OAuth halisi wa Anthropic.
- `isClaudeCodeCompatible(this.provider)` — relay ambazo kitambulisho cha mtoa huduma huanza na kiambishi awali
  `anthropic-compatible-cc-` (zinatangaza uoanifu na Claude Code, kwa hivyo ndizo relay
  zenye uwezekano mkubwa zaidi wa kukubali beta). Tazama `open-sse/services/provider.ts`.

Zimeondolewa **kimakusudi**:

- `claude-web` — relay ya kivinjari yenye muundo wa ombi wa `create_conversation_params` ambao haupati kamwe
  `context_management`.
- Relay za jumla za `anthropic-compatible-*` (zisizo na kiambishi awali cha `-cc-`) — endpoint za wahusika wengine zenye
  uwezo usio na uhakika wa kutumia beta.

Watoa huduma wasio wa Claude hawapokei kamwe kigezo cha `context_management` hata wakati swichi imewashwa.

## Njia mbadala ya 400 / ufikiaji wa relay

Relay inayoana na Claude inaweza kutangaza beta lakini bado ikakataa kigezo cha `context_management`
kwa HTTP 400. Ili kupunguza athari kwa ustahimilivu badala ya ombi kushindwa, kitekelezaji huondoa
kigezo hicho na kujaribu tena URL ileile **mara moja**:

```ts
if (
  response.status === HTTP_STATUS.BAD_REQUEST &&
  contextEditing?.enabled &&
  !contextEditingDisabled &&
  transformedBody?.context_management !== undefined
) {
  const errText = await response
    .clone()
    .text()
    .catch(() => "");
  if (/context[_-]management|context editing/i.test(errText)) {
    contextEditingDisabled = true;
    delete transformedBody.context_management;
    let retryBody = JSON.stringify(transformedBody);
    if (isClaudeCodeCompatible(this.provider) || this.provider === "claude") {
      retryBody = await signRequestBody(retryBody);
    }
    response = await fetch(url, { ...fetchOptions, body: retryBody });
  }
}
```

Tabia:

1. Hufanya kazi tu wakati wa `400` huku uhariri wa muktadha ukiwa umewezeshwa na body ikiwa kweli ina
   `context_management`.
2. Body ya 400 husomwa kupitia `clone()` ili response asili ibaki bila kubadilishwa kwa njia
   isiyolingana.
3. Maandishi ya hitilafu lazima yalingane na `/context[_-]management|context editing/i` — 400 isiyohusiana (k.m.
   `max_tokens must be >= 1`) **haianzishi** njia mbadala; hitilafu asili huenezwa.
4. Inapolingana, huweka `contextEditingDisabled = true` (jambo linalozuia uingizaji upya ikiwa
   `transformedBody` mpya itaundwa baadaye kwa URL ya kujaribu tena/mbadala), hufuta `context_management`,
   husaini upya body kwa relay za Claude / zinazooana na Claude Code (`signRequestBody`), na kujaribu tena
   URL ileile mara moja.

Claude halisi hubeba beta katika `ANTHROPIC_BETA_BASE` na haiingii kwenye njia hii mbadala.

## Telemetria ya `applied_edits`

Baada ya response ya Claude, OmniRoute hurekodi kiasi cha muktadha ambacho mtoa huduma aliondoa. Hii
**haitiririshwi** — hutolewa kutoka kwenye body ya response isiyotiririshwa, kwa kadiri inavyowezekana, na kamwe
haiathiri response (hitilafu za telemetria hupuuzwa).

- Utoaji: `extractContextEditingTelemetry(responseBody)` katika `open-sse/config/contextEditing.ts`.
  Huchunguza `applied_edits` katika maeneo matatu (kwa tahadhari dhidi ya tofauti za muundo wa response):
  - `context_management.applied_edits`
  - `usage.context_management.applied_edits`
  - `usage.applied_edits`
- Sehemu zinazosomeka kwa kila hariri kutoka kwa kila ingizo: `cleared_input_tokens` na `cleared_tool_uses`
  (snake_case, asilia ya Anthropic), pamoja na mbadala za camelCase za `clearedInputTokens` / `clearedToolUses`.
- Hurejesha `null` ikiwa hakuna safu ya `applied_edits` inayopatikana au ikiwa hakuna chochote kilichoondolewa.

Muundo wa risiti ni `ContextEditingTelemetry { editCount, clearedInputTokens, clearedToolUses }`.
Urekodi hufanyika katika `open-sse/handlers/chatCore.ts` (ukidhibitiwa kwa `provider === "claude"`) kupitia
`recordContextEditingTelemetry()` (`src/lib/db/compressionAnalytics.ts`), ambayo huandika safu ya uchanganuzi wa
mbano yenye lebo:

- `mode: "context-editing"`
- `engine: "context-editing"`
- `tokens_saved` / `original_tokens` = idadi ya tokeni za ingizo zilizoondolewa
- `request_id` yenye kiambishi tamati cha `::context-editing`

Kwa hivyo uondoaji uliokabidhiwa huonekana katika uchanganuzi wa mbano pamoja na injini za ndani, chini ya
lebo ya injini ya `context-editing`, na unaweza kutofautishwa na akiba za RTK/Caveman/LLMLingua.

## Uhusiano na injini za ndani za ukandamizaji

| Kipengele             | Injini za ndani (Caveman / RTK / LLMLingua / stacked)     | Uhariri wa Muktadha Uliokabidhiwa                          |
| --------------------- | --------------------------------------------------------- | ---------------------------------------------------------- |
| Mahali inapoendeshwa  | Ndani ya OmniRoute, kabla ombi halijaondoka kwenye proksi | Ndani ya mtoa huduma (Claude), upande wa seva              |
| Inachohariri          | Maandishi ya kidokezo / muktadha / matokeo ya zana        | Bloku za zamani za matumizi ya zana / matokeo ya zana      |
| Wigo wa watoa huduma  | Watoa huduma wote                                         | `claude` + `anthropic-compatible-cc-*` pekee               |
| Kigeuzi               | Mipangilio ya hali ya ukandamizaji                        | `contextEditing.enabled`                                   |
| Hali ya hitilafu      | Endelea inaposhindikana (maandishi asili)                 | Njia mbadala ya 400: ondoa parameta, jaribu tena mara moja |
| Telemetria ya uokoaji | `engine: <engine id>`                                     | `engine: "context-editing"`                                |

Mbinu hizi mbili zinakamilishana: injini za ndani hukandamiza baiti ambazo OmniRoute hutuma; Uhariri wa Muktadha humruhusu
Claude kupunguza muktadha unaoendelea katika zamu mbalimbali. Zinaweza kuwezeshwa pamoja.
