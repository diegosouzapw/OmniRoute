---

OmniRoute hutoa njia **mbili** za kutumia OpenAI Codex:

| Mtoa huduma            | Jinsi inavyowasiliana na OpenAI                                                                                                                                                          | Tahadhari ya matumizi                                                           |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| **`codex`**            | Hutuma tena tokeni yako ya ChatGPT/OpenAI OAuth moja kwa moja kwenye Responses API                                                                                                       | **Ndiyo** — kipindi rasmi hakijaidhinishwa kutumiwa kupitia proksi/kipanga njia |
| **`codex-app-server`** | Huendesha **`codex app-server` ya Codex CLI yenyewe** kupitia JSON-RPC/WebSocket; CLI inamiliki na kujisasishia OAuth yake (`~/.codex/auth.json`) kama tu kipindi shirikishi cha `codex` | **Hapana** — OmniRoute haitumi tena tokeni kwenye API                           |

Kwa sababu `codex-app-server` haitumi tena tokeni, haina tahadhari ya matumizi
inayohusiana na kutuma tena kipindi. Hata hivyo, inahitaji **Codex CLI inayofikika
kwenye URL iliyosanidiwa ya app-server**, na CLI hiyo lazima iwe **imeingia katika
akaunti**.

---

## 1. Usanifu

```
┌─ Programu ya OmniRoute ──────────┐        ┌─ Huduma saidizi ya codex-app-server ┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ tokeni ya uwezo)             │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  hujidhibitia OpenAI OAuth          │
└──────────────────────────────────┘        │  (~/.codex/auth.json, kujisasisha)   │
        │ hushiriki (volumu za compose)      └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → tokeni ya uwezo wa WS (zote mbili huiunganisha)
  codex-appserver-home    → ~/.codex (auth.json huandikwa na dashibodi,
                             na kusomwa na codex app-server ya huduma saidizi)
```

- Huduma saidizi husikiliza **pekee** kwenye mtandao wa ndani wa compose
  (`ws://codex-app-server:1456`) nyuma ya tokeni ya uwezo. **Haichapishwi kamwe**
  kwa seva mwenyeji au intaneti.
- Codex CLI imejumuishwa ndani ya `omniroute:base`, kwa hivyo hakuna haja ya
  kusakinisha codex kwenye seva mwenyeji au mashine ya mtumiaji unapoendesha
  huduma saidizi.

## 2. Iwashe

```bash
# Anzisha mfumo PAMOJA NA wasifu wa huduma saidizi ya codex app-server:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

Huduma saidizi huunda tokeni yake ya uwezo wa WS inapowashwa kwa mara ya kwanza
(ndani ya volumu inayoshirikiwa ya `codex-appserver-token`) na programu husoma
tokeni hiyo hiyo kupitia `OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE`. Hakuna haja
ya kuunganisha tokeni mwenyewe.

## 3. Unganisha + ingia katika akaunti

1. Kwenye dashibodi, ongeza muunganisho wa **OpenAI Codex (App-Server)**. Hakuna
   ufunguo wa API au tokeni inayohitajika (ni mtoa huduma asiyehitaji uthibitishaji
   — huduma saidizi ndiyo inayomiliki uthibitishaji).
2. Ikiwa Codex CLI ya huduma saidizi **bado haijaingia katika akaunti**, ukaguzi
   wa hali ya muunganisho huripoti _"inafanya kazi lakini haijaingia katika
   akaunti"_ (si hitilafu nyekundu ya uthibitishaji). Tumia **Ingia kwa ChatGPT**:
   hii huendesha device-OAuth ya kawaida ya Codex kwenye kivinjari chako na kisha
   huandika `~/.codex/auth.json` ndani ya volumu inayoshirikiwa kupitia
   **Tekeleza uthibitishaji** (uingiaji huo mmoja hutumika kwa watoa huduma wote
   wawili, `codex` na `codex-app-server`).
3. Baada ya kuingia katika akaunti, ukaguzi wa hali huwa wa kijani (huthibitisha
   `/readyz` **na pia** `account/read` — yaani, inafanya kazi _na_ imethibitishwa)
   na huanza kufanya kazi.

Dashibodi haibadilishi kamwe `~/.codex/auth.json` iliyopo na yenye hali nzuri —
huandika tu wakati faili haipo au tokeni yake imepitwa na wakati (nakala rudufu
huundwa kila wakati).

## 4. Mazingira ya usambazaji

- **Mwendeshaji mwenye Codex CLI ambayo tayari imethibitishwa** — unganisha
  `~/.codex` ya seva yako mwenyeji kwenye huduma saidizi
  (`codex-appserver-home`) na uruke hatua ya kuingia katika akaunti.
- **Mtumiaji wa umma, bila codex iliyosakinishwa ndani ya mashine yake** — hili
  si tatizo: huduma saidizi ina CLI. Mtumiaji huthibitisha tu kupitia dashibodi.
- **OmniRoute ya moja kwa moja kwenye mashine halisi (bila huduma saidizi, codex
  ya seva mwenyeji)** — elekeza `OMNIROUTE_CODEX_APPSERVER_WS` kwenye
  `codex app-server` yako mwenyewe na uhakikishe codex ya seva mwenyeji imeingia
  katika akaunti; kidokezo cha "codex haijasakinishwa" huonekana ikiwa faili
  tekelezi haipo.

## 5. Mtandao wa makazi / njia ya kutoka ya UDP (nyongeza ya mwendeshaji, haijasambazwa)

Huduma saidizi ya jumla iliyo hapo juu hutumia mtandao wa kawaida wa kontena kwa
trafiki inayotoka. Mwendeshaji anayehitaji trafiki ya Codex itoke kupitia
**njia ya kutoka ya mtandao wa makazi** (kwa mfano, huduma saidizi ya tailscale
ya TUN inayobeba TCP + UDP/QUIC) huiendesha kama ubatilishaji tofauti wa compose;
kwa makusudi **si** sehemu ya wasifu wa `codex-app-server` unaosambazwa. Angalia
mwongozo wa ndani wa uendeshaji kwa usanidi huo.
