**OmniCopilot** huweka kila modeli inayotolewa na OmniRoute yako kwenye kichagua modeli cha _asili_ cha GitHub Copilot Chat.
Hakuna utepe wa pili wa pembeni, wala kiolesura tofauti cha gumzo — hali ya wakala ya Copilot, uitaji wa zana,
seva za MCP na maagizo maalum yote huendelea kufanya kazi, ila sasa yakitumia modeli unayochagua.

| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Sakinisha (VS Code)**      | [Marketplace → `diegosouzapw.omnicopilot`](https://marketplace.visualstudio.com/items?itemName=diegosouzapw.omnicopilot)                        |
| **Sakinisha (forks)**        | [Open VSX](https://open-vsx.org/extension/diegosouzapw/omnicopilot) — Cursor, Windsurf, VSCodium, Theia, code-server, Gitpod, Antigravity, Kiro |
| **Msimbo chanzo / matatizo** | [github.com/diegosouzapw/OmniCopilot](https://github.com/diegosouzapw/OmniCopilot) (MIT)                                                        |
| **Inahitaji**                | VS Code 1.104+                                                                                                                                  |

> **Usajili wa Copilot hauhitajiki.** Tangu VS Code 1.122, mtoa modeli za lugha hufanya kazi
> bila kuingia katika GitHub na bila mpango wowote wa Copilot. Ukamilishaji ndani ya mistari na
> vipengele vinavyotegemea embeddings hubaki nje ya API ya mtoa huduma na bado vinahitaji Copilot.

## Usanidi

1. **Endesha OmniRoute** — `npm install -g omniroute && omniroute` (dashibodi kwenye `http://localhost:20128`).
2. **Sakinisha kiendelezi** — tafuta "OmniRoute" katika mwonekano wa Extensions.
3. **Chagua modeli** — Copilot Chat → kichagua modeli → **Manage Models…** → **OmniRoute**, kisha teua
   unazotaka.

Hakuna cha kusanidi wakati OmniRoute inaendeshwa kwenye kituo chaguomsingi. Kwa instansi ya mbali, fungua
**ikoni ya OmniRoute katika Activity Bar** (au endesha `OmniRoute: Manage Connection`) na uweke:

- **URL ya seva** — mzizi wa seva, k.m. `http://192.168.0.15:20128`. Kiambishi `/v1`
  huongezwa na kiendelezi; usikijumuishe.
- **Ufunguo wa API** — pale tu seva inapoweka `REQUIRE_API_KEY`. Huhifadhiwa katika mkufu wa funguo wa OS kupitia VS
  Code SecretStorage, kamwe si katika `settings.json`.

## Kile kitakachoonyeshwa na kichagua modeli

Kiendelezi hakionyeshi data ghafi ya `GET /v1/models` — huiunda upya, na idadi
unayoweza kuona ni ndogo kuliko ukubwa wa katalogi kwa sababu mbili za makusudi.

### Huomba id moja kwa kila modeli

`MODELS_CATALOG_PREFIX_MODE` hutumia **`dual`** kama chaguomsingi, hali ambayo hutangaza kila modeli mara mbili — mara moja
chini ya kiambishi kifupi cha jina mbadala na mara nyingine chini ya kiambishi rasmi cha mtoa huduma — ili usanidi wa viteja
vya zamani uendelee kutambua aina zote mbili:

```
cc/claude-sonnet-4-6        ← kiambishi cha jina mbadala
claude/claude-sonnet-4-6    ← kiambishi rasmi, modeli ileile
```

Kiendelezi huomba **`GET /v1/models?prefix=alias`** ili id moja ipokelewe kwa kila modeli, bila
kubadilisha mpangilio wa seva nzima kwa ajili ya viteja vyako vingine. Kwenye instansi ya marejeleo, hatua hii ilipunguza
**vipengee 2345 hadi 1396 — nakala 949, hakuna modeli iliyopotea.**

Ikiwa ungependa kurekebisha hili kwenye seva nzima kwa ajili ya _kila_ kiteja, weka alama ya kipengele
`MODELS_CATALOG_PREFIX_MODE` kuwa `alias` katika dashibodi. Tazama
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) kwa
kigezo cha hoja na jedwali la kila hali.

### Huficha modeli ambazo haziwezi kupiga gumzo

Katalogi pia huorodhesha modeli za picha, video, sauti, upangaji upya, embedding na udhibiti wa maudhui. Hizo
hukataliwa wakati wa ombi la gumzo kwa vyovyote vile:

```
HTTP 400 — Model '<id>' is an image-generation model and cannot be used on
/v1/chat/completions. Use POST /v1/images/generations instead.
```

kwa hiyo huchujwa kwa kutumia uga wao wa `type` kabla ya kufika kwenye kichagua modeli. **Modeli za Responses-API
hubakizwa** — kila ingizo la Codex / GPT-5.x hutangaza `supported_endpoints: ["responses"]`,
na OmniRoute huzitafsiri kwa ajili ya `/v1/chat/completions`, kwa hiyo zinaweza kutumika kikamilifu.

### Watoa huduma ambao hujawahi kusanidi

Katalogi huorodhesha modeli kutoka kwa watoa huduma wenye **muunganisho unaotumika** _pamoja na_ kila mtoa huduma wa **noAuth**
— wale wasiohitaji ufunguo ambao wanaunda sehemu kubwa ya kiwango cha bila malipo. Hili limekusudiwa. Ili
kuwaficha, waongeze kwenye `blockedProviders` katika mipangilio ya dashibodi; hakuna kinachobadilika katika
kiendelezi.

## Dashibodi ndani ya kichupo cha VS Code

`omnicopilot.dashboardOpen: "editor"` huonyesha dashibodi ya OmniRoute katika kichupo cha kihariri kupitia
Simple Browser badala ya kivinjari cha nje. Upachikaji **huchaguliwa kwa hiari kwenye seva** kupitia
`DASHBOARD_ALLOW_EMBED=vscode`, ambayo hutoa kurasa za HTML zikiwa na
`frame-ancestors 'self' vscode-webview:` badala ya chaguo-msingi la `frame-ancestors 'none'` +
`X-Frame-Options: DENY`. Kiolesura cha API (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) huendelea kutumia
vichwa madhubuti kwa hali zote.

> ⚠️ **Hii ni alama ya wakati wa kujenga, si ya wakati wa utekelezaji.** Next.js hukusanya `headers()` ndani ya manifesti ya route,
> kwa hivyo `next.config.mjs` husoma kigezo wakati kifurushi kinapojengwa
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> Kukisafirisha mbele ya seva ambayo tayari imejengwa hakubadilishi chochote — vichwa vimejumuishwa kabisa.

```bash
# kigezo lazima kiwepo kwenye amri ya BUILD
DASHBOARD_ALLOW_EMBED=vscode npm run build        # au npm run build:release
npm start
```

| Jinsi ulivyosakinisha       | Je, unaweza kuwezesha upachikaji?                                                                                                                           |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Kutoka kwenye msimbo chanzo | ✅ weka kigezo kwenye amri ya kujenga, kama ilivyo hapo juu                                                                                                 |
| `npm install -g omniroute`  | ❌ kifurushi kilichochapishwa huja na kifurushi kilichojengwa tayari — badala yake jenga kutoka kwenye msimbo chanzo                                        |
| Taswira ya Docker           | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — taswira iliyojengwa tayari kwenye Docker Hub haijawezeshwa kwa upachikaji |

Bila toleo lililojengwa huku upachikaji ukiwa umewezeshwa, ukurasa hukataa kuonyeshwa ndani ya fremu; kiendelezi hutambua hilo kupitia
vichwa vya jibu na kurudi kutumia kivinjari cha nje — hakuna kinachoharibika, na hutoa taarifa hiyo mara moja.
Tazama [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) na suala
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273).

## Kusanidi zana zako nyingine ukiwa ndani ya VS Code

**`OmniRoute: Configure Coding CLI`** huendesha CLI ya `omniroute` ili kuandika wasifu ulio tayari kutumika
kwa Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code,
Kilo na Roo — usanidi uleule uliofafanuliwa katika
[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md). Ufunguo wa API hupitishwa kwa CLI kupitia
kigezo cha mazingira cha `OMNIROUTE_API_KEY`, kamwe si kwenye mstari wa amri.
