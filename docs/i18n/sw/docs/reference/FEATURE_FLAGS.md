> Vigeuzi vya wakati wa utekelezaji vinavyobadilisha tabia ya OmniRoute **bila kusambaza upya**.
> Kila bendera iliyoorodheshwa hapa imefafanuliwa katika
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> — chanzo pekee cha ukweli. Dashibodi na REST API zote husoma kutoka
> kwenye faili hiyo, kwa hivyo jedwali lililo hapa chini limetengenezwa ili lilingane nayo kwa uwiano wa 1:1.

---

## Bendera za Vipengele Ni Nini

Bendera ya kipengele ni kigeuzi chenye jina (boolean au enum) ambacho thamani yake inaweza kubadilishwa
wakati wa utekelezaji na kuhifadhiwa katika hifadhidata, bila kuhitaji kusambaza upya mchakato. Kila
bendera inafafanuliwa na `FeatureFlagDefinition` yenye `key`, `label`,
`description`, `category`, `defaultValue`, `type`, na kidokezo cha `requiresRestart`.

### Mpangilio wa Utatuzi

**Thamani inayotumika** ya bendera hutatuliwa na
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) kwa kufuata
mpangilio huu wa kipaumbele (ya juu zaidi ndiyo hushinda):

1. **Ubatilishaji wa DB** — thamani iliyohifadhiwa katika jedwali la `key_value` chini ya
   nafasi ya majina ya `feature_flags` (huwekwa kupitia dashibodi au REST API).
2. **Kigezo cha mazingira** — `process.env[<KEY>]`, ikiwa kimewekwa na si tupu.
3. **Chaguo-msingi la ufafanuzi** — `defaultValue` kutoka `featureFlagDefinitions.ts`.

Bendera ya boolean huchukuliwa kuwa **imewashwa** wakati thamani yake inayotumika ni `"true"`,
`"1"`, au `"yes"` (angalia `isFeatureFlagEnabled()`).

> [!NOTE]
> Bendera nyingi pia zina kigezo cha mazingira kinacholingana chenye **jina lilelile**
> kilichoelezwa katika [`ENVIRONMENT.md`](./ENVIRONMENT.md). Ubatilishaji wa DB wa bendera
> unapewa kipaumbele kuliko kigezo hicho cha mazingira. Bendera yenye
> `requiresRestart: true` huhifadhiwa mara moja lakini husomwa tena tu wakati mchakato
> unapoanza — kuibadilisha huonyesha bango la **"Anzisha Seva Upya"** kwenye dashibodi.

## Kuwasha na Kuzima Bendera

### Dashibodi

Nenda kwenye **Dashibodi → Mipangilio → Bendera za Vipengele**
(`/dashboard/settings/feature-flags`). Gridi
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
inaauni:

- **Utafutaji** kwa ufunguo au maelezo, na **uchujaji** kwa kategoria (pamoja na mwonekano maalum wa
  **Inahitaji Kuanzishwa Upya**).
- **Kitufe cha kuwasha/kuzima** kwa bendera za boolean na **orodha kunjuzi** kwa bendera za enum
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- **Beji ya chanzo** kwa kila bendera — `DB`, `ENV`, au `DEF` — inayoonyesha thamani
  inayotumika ilikotoka.
- Kitufe cha **Weka Upya** (kinaonyeshwa tu kwa bendera zinazotoka kwenye `DB`) ili kuondoa ubatilishaji,
  na kitufe cha **Weka Upya Ubatilishaji Wote** kilicho chini.
- Bango la **Anzisha Seva Upya** wakati bendera ya `requiresRestart` inapobadilishwa.

### API ya REST

Operesheni zote hupitia njia moja:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Kila method inahitaji kipindi cha dashibodi kilichothibitishwa (`401` vinginevyo).

#### `GET /api/settings/feature-flags`

Hurejesha kila bendera pamoja na thamani yake inayotumika, chanzo na muhtasari.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... bendera zote 74
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Weka au ondoa ubatilishaji mmoja. Mwili: `{ key: string; value?: string }`.
Kuacha `value` huondoa ubatilishaji (na kurejesha env / chaguomsingi).

```bash
# Weka ubatilishaji wa DB
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Ondoa ubatilishaji (bila "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Jibu hurudisha `effectiveValue`/`source` mpya, `previousValue`/
`previousSource`, na `requiresRestart`. Funguo zisizojulikana na thamani za enum zilizo nje ya kiwango
hukataliwa kwa `400`.

#### `DELETE /api/settings/feature-flags`

Huondoa ubatilishaji **wote** wa DB kwa wakati mmoja, na kurejesha kila bendera kwenye thamani yake ya env / chaguomsingi.
Hurejesha `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> Bendera zenye `requiresRestart: true` huanza kutumika tu baada ya mchakato kupakiwa upya.
> Mtiririko wa kuanzisha upya wa dashibodi huita `POST /api/restart` kisha huuliza mara kwa mara
> `GET /api/health/ping` hadi seva iwashwe tena.

## Njia Mbadala ya Dharura ya Bajeti

`OMNIROUTE_EMERGENCY_FALLBACK` (kategoria `runtime`, chaguo-msingi `true`) hudhibiti
njia ya dharura ya kutumia chaguo mbadala lisilolipishwa katika
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Ikiwashwa, maombi yanayomaliza bajeti yao huelekezwa kwa provider/model mbadala
isiyolipishwa badala ya kushindwa kabisa. Iweke kuwa `false` (au `0`) — kupitia
kitufe cha kubadilisha hali kwenye dashibodi, ubatilishaji wa DB, au environment variable ya `OMNIROUTE_EMERGENCY_FALLBACK`
— ili kuzima tabia hiyo na kuruhusu maombi yaliyomaliza bajeti
yashindwe. (Imeonyeshwa kama kitufe cha kubadilisha hali kwenye dashibodi katika PRs #3741 / #3752.)
