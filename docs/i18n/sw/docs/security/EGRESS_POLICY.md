> **Weka trafiki inayotoka itumie familia moja tu ya IP — `auto`, `ipv4`, au `ipv6` — kwa kila proksi, ili njia ya kutoka ya IPv6 pekee isivuje kimyakimya na kurudi kwenye IPv4.**

> **Chanzo cha ukweli:** `open-sse/utils/proxyFamily.ts`, `open-sse/utils/proxyDispatcher.ts`, `open-sse/utils/proxyFetch.ts`, `open-sse/utils/socksConnectorWithFamily.ts`, `open-sse/utils/proxyFamilyResolve.ts`, `src/shared/validation/schemas.ts`, `src/lib/db/proxies.ts`, `src/lib/db/upstreamProxy.ts`, `src/lib/db/migrations/099_proxy_family.sql`

OmniRoute huruhusu kila proksi kuwa na **agizo la familia ya anwani kwa trafiki inayotoka**. Kwa chaguo-msingi, mfumo wa uendeshaji huchagua IPv4 au IPv6 (dual-stack, "Happy Eyeballs"). Unapoweka agizo kuwa `ipv4` au `ipv6`, OmniRoute hulazimisha kila muunganisho unaopitia proksi hiyo kutumia familia iliyochaguliwa na **huzuia muunganisho unaposhindikana** badala ya kurudi kwenye familia nyingine.

Ukurasa huu unafafanua agizo hilo ni nini, kwa nini lipo, mahali pa kulisanidi, na jinsi mazingira ya utekelezaji yanavyolitatua.

## Ni Nini

Kila proksi katika sajili ina sehemu ya `family` yenye thamani tatu zinazowezekana, zinazothibitishwa na enum ya Zod:

```ts
// src/shared/validation/schemas.ts
family: z.enum(["auto", "ipv4", "ipv6"]).optional().default("auto"),
```

Sehemu hiyo hutumia `"auto"` kwa chaguo-msingi, jambo linalodumisha tabia ya awali ya dual-stack. Kuiweka kuwa `ipv4` au `ipv6` hulazimisha familia ya muunganisho kwa proksi hiyo.

Agizo husawazishwa kila mahali kupitia kisaidizi kimoja, ili thamani yoyote isiyojulikana ibadilishwe kuwa `auto`:

```ts
// open-sse/utils/proxyFamily.ts
export type ProxyFamily = "auto" | "ipv4" | "ipv6";

export function parseProxyFamily(value: unknown): ProxyFamily {
  return value === "ipv4" || value === "ipv6" ? value : "auto";
}
```

## Kwa Nini Lipo

Lilianzishwa katika PR [#3777](https://github.com/diegosouzapw/OmniRoute/pull/3777). Matatizo yaliyochochea kuanzishwa kwake:

| Tatizo                                                            | Kile ambacho agizo hurekebisha                                                                                                                                                                                                                                                                                                                                                           |
| ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Njia ya kutoka ya IPv6 pekee kuvuja hadi IPv4**                 | Wakati seva mwenyeji ya proksi ina rekodi za A na AAAA (au mfumo wa uendeshaji unapendelea IPv4), Happy Eyeballs inaweza kuanzisha muunganisho unaotoka kupitia IPv4 hata unapokusudia njia ya IPv6 pekee. Kulazimisha `ipv6` huondoa uvujaji huo.                                                                                                                                       |
| **Ubatilishaji kutokana na hitilafu ya njia ya pamoja ya kutoka** | Watoa huduma wanaozungusha miunganisho (codex/openai) hubatilisha tokeni wakati akaunti nyingi zinatoka kupitia IP **ileile** kwa kiwango kikubwa. Kudhibiti familia ya njia ya kutoka ni sehemu ya kuweka akaunti kwenye njia tofauti na zinazotabirika za kutoka (tazama [`src/lib/proxyEgress.ts`](../../src/lib/proxyEgress.ts) kwa uchunguzi wa IP ya kutoka unaoambatana na hili). |
| **Njia thabiti ya kutoka kwa uzingatiaji/majaribio**              | Unapohitaji kuhakikisha kuwa trafiki inatoka kupitia familia mahususi, `auto` haitoshi.                                                                                                                                                                                                                                                                                                  |

Agizo limekusudiwa kuwa **kwa kila proksi**, si la kimataifa — proksi tofauti katika mkusanyiko wako zinaweza kuwa na sera tofauti.

## Thamani Tatu

| Thamani | Lebo ya UI               | Tabia                                                                                                                                                                                                   |
| ------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`  | `Otomatiki (dual-stack)` | OS huchagua familia. Kwa seva pangishi ya proksi iliyo anwani halisi ya IP, familia huamuliwa na anwani hiyo; kwa jina la seva pangishi, familia zote mbili zinaweza kutumika. Hii ndiyo chaguo-msingi. |
| `ipv4`  | `IPv4 pekee`             | Huweka muunganisho kwenye IPv4. Hushindwa kwa usalama ikiwa seva pangishi ya proksi haina rekodi ya IPv4 (A).                                                                                           |
| `ipv6`  | `IPv6 pekee`             | Huweka muunganisho kwenye IPv6. Hushindwa kwa usalama ikiwa seva pangishi ya proksi haina rekodi ya IPv6 (AAAA).                                                                                        |

Vifungu vya UI vipo katika `src/i18n/messages/en.json` (`labelFamily`, `familyAuto`, `familyIpv4`, `familyIpv6`, `familyHint`).

## Jinsi ya Kuisanidi

### Dashibodi

Kiteuzi kipo katika fomu ya proksi kwenye kichupo cha **Kundi la Proksi**:

1. Fungua **Dashibodi → Mipangilio → Proksi → Kundi la Proksi**
2. Ongeza au hariri proksi
3. Weka menyu kunjuzi ya **Familia ya IP** kuwa `Otomatiki (dual-stack)`, `IPv4 pekee`, au `IPv6 pekee`
4. Hifadhi

Kidhibiti kinaonyeshwa na `ProxyRegistryManager.tsx` (kilichopachikwa katika `proxy/ProxyPoolTab.tsx`).

### API

Sehemu ya `family` ni sehemu ya mizigo ya ombi la kuunda/kusasisha sajili ya proksi, inayothibitishwa na `createProxyRegistrySchema` / `updateProxyRegistrySchema` (`src/shared/validation/schemas.ts`) na kushughulikiwa na `POST` / `PATCH /api/v1/management/proxies`:

```bash
# Unda proksi ya IPv6 pekee
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "IPv6 egress",
    "type": "socks5",
    "host": "proxy.example.com",
    "port": 1080,
    "family": "ipv6"
  }'

# Badilisha proksi iliyopo iwe ya IPv4 pekee
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{ "id": "proxy-uuid-here", "family": "ipv4" }'
```

Sehemu hiyo hiyo pia inakubaliwa na kipengee cha ndani cha usanidi wa proksi kinachotumiwa kwa maingizo ya proksi ya upande wa juu (`upstream_proxy_config.family`, angalia [Muundo wa Data](#data-model)).

Kwa sehemu nyingine ya API ya CRUD/ugawaji wa proksi, angalia [PROXY_GUIDE.md](../ops/PROXY_GUIDE.md).

## Jinsi `auto` Inavyotatua

Wakati `family` ni `auto`, OmniRoute **haiongezi** agizo lolote — URL ya proksi hutumiwa jinsi ilivyo na familia ya muunganisho huamuliwa moja kwa moja.

Wakati wa kuunda URL (`proxyConfigToUrl` / `normalizeProxyUrl` katika `open-sse/utils/proxyDispatcher.ts`), proksi ya `auto` hutoa URL ya kawaida isiyo na alama:

```ts
// open-sse/utils/proxyDispatcher.ts
const fam = parseProxyFamily(config.family);
const normalized = normalizeProxyUrl(proxyUrlStr, "context proxy", {
  allowSocks5,
});
return fam === "auto" ? normalized : `${normalized}?family=${fam}`;
```

Wakati wa kutuma (`resolveDispatcherFamily`), `auto` hutatuliwa kuwa familia halisi ya seva pangishi iliyo anwani halisi ya IP, au `null` (kuiacha OS iamue) kwa jina la seva pangishi:

```ts
// open-sse/utils/proxyDispatcher.ts
function resolveDispatcherFamily(parsed: URL): 4 | 6 | null {
  const directive = parseProxyFamily(parsed.searchParams.get("family") ?? undefined);
  const literal = detectIpLiteralFamily(parsed.hostname);
  if (directive === "auto") return literal; // null kwa jina la seva pangishi → OS huchagua
  // ...
}
```

Kwa hivyo:

- `auto` + seva pangishi iliyo anwani halisi ya IP (`192.0.2.1` / `[2001:db8::1]`) → familia ya anwani hiyo.
- `auto` + jina la seva pangishi → `null` → utatuzi wa kawaida wa dual-stack wa OS.

## Jinsi `ipv4` / `ipv6` Zinavyotekelezwa

Maagizo yasiyo ya `auto` husafirishwa kama alama moja ya hoja ya usanifu — `?family=ipv4` au `?family=ipv6` — inayoongezwa mara moja kwenye URL ya proksi iliyosawazishwa. `normalizeProxyUrl` huondoa na kuongeza tena alama hii kwa uangalifu mara moja tu ili isiharibu kamwe uchanganuzi wa porti.

Dispatcher inapoundwa, alama hiyo husomwa na kubadilishwa kuwa family mahususi ya muunganisho. Ikiwa host ni IP halisi ya family **kinyume**, OmniRoute hutupa hitilafu (mgongano hufungwa kwa usalama):

```ts
// open-sse/utils/proxyDispatcher.ts
const want = directive === "ipv6" ? 6 : 4;
if (literal !== null && literal !== want) {
  throw new Error(
    `[ProxyDispatcher] Proxy family directive ${directive} contradicts ${literal === 6 ? "IPv6" : "IPv4"} literal host`
  );
}
```

Kisha family hiyo mahususi hufungwa kwenye connector:

- **Proksi za HTTP/HTTPS** (`ProxyAgent`): `proxyTls: { family, autoSelectFamily: false }` — huzima Happy Eyeballs ili family iliyochaguliwa iwe ndiyo pekee inayopigiwa.
- **Proksi za SOCKS5**: connector maalum hupitisha `socket_options: { family, autoSelectFamily: false }` hadi kwenye kiteja cha SOCKS (angalia [Uoanifu wa SOCKS5](#socks5-compatibility)).

## Uoanifu wa SOCKS5

Ufungaji wa family hufanya kazi na proksi za SOCKS5, lakini `fetch-socks` ya kawaida haiwezeshi kufikia chaguo za socket zinazohitajika ili kufunga family ya hatua ya proksi. OmniRoute huja na connector yake yenyewe kwa ajili hiyo:

```ts
// open-sse/utils/socksConnectorWithFamily.ts
export function buildSocksFamilySocketOptions(family: 4 | 6 | null): Record<string, unknown> {
  if (family === 6) return { family: 6, autoSelectFamily: false };
  if (family === 4) return { family: 4, autoSelectFamily: false };
  return {};
}
```

Dispatch zote za SOCKS5 hupitia `createSocksDispatcherWithFamily` bila kujali `family` (ikiwemo `null` / `auto` kupitia hostname): `buildSocksFamilySocketOptions(null)` hutoa `{}`, na njia ileile ya `SocksClient.createConnection` + TLS `buildConnector` hutumika pamoja na ufungaji wa `socket_options` ili Happy Eyeballs isiweze kuchagua IPv4 kwa sera ya egress ya IPv6 pekee.

Usaidizi wenyewe wa SOCKS5 umewashwa kwa chaguo-msingi (unaweza kujiondoa kupitia `ENABLE_SOCKS5_PROXY=false`); angalia [PROXY_GUIDE.md → Vigezo vya Mazingira](../ops/PROXY_GUIDE.md#environment-variables).

## Tabia ya Kufungwa kwa Usalama

Lengo kuu la maagizo haya ni **kukataa** badala ya kurudi kimyakimya kwenye family isiyo sahihi. Vizuizi viwili hutekeleza hili:

1. **Mgongano wa IP halisi** — agizo linalokinzana na host ya IP halisi hutupa hitilafu wakati wa kuunda dispatcher (`resolveDispatcherFamily`, imeonyeshwa hapo juu).

2. **Ukaguzi wa awali wa DNS wa hostname** — kwa proksi ya hostname yenye family iliyofungwa, `proxyFetch.ts` huthibitisha kwamba hostname kweli ina rekodi katika family inayohitajika **kabla** ya kufanya egress, kupitia `assertHostnameSupportsFamily`:

   ```ts
   // open-sse/utils/proxyFamilyResolve.ts
   const hasFamily = records.some((r) => r.family === family);
   if (!hasFamily) {
     throw new Error(
       `[ProxyFamily] Proxy host ${host} has no ${family === 6 ? "IPv6 (AAAA)" : "IPv4 (A)"} record; ` +
         `refusing ${family === 6 ? "IPv6" : "IPv4"}-only egress (fail-closed)`
     );
   }
   ```

   Inaposhindwa, `proxyFetch.ts` hutia hitilafu alama ya `code = "PROXY_FAMILY_UNAVAILABLE"` na `statusCode = 503`. Kushindwa kwa utatuzi wa DNS pia huchukuliwa kama hali ya kufungwa kwa usalama (egress hukataliwa).

Host za IP halisi hazifanyi chochote katika ukaguzi wa awali wa DNS — family yao ni ya asili na haihitaji utafutaji.

## Muundo wa Data

Safu wima ya `family` iliongezwa na uhamishaji `099_proxy_family.sql` kwenye majedwali **mawili**:

```sql
-- src/lib/db/migrations/099_proxy_family.sql
ALTER TABLE proxy_registry ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
ALTER TABLE upstream_proxy_config ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
```

- `proxy_registry.family` — maelekezo ya kila proksi kwa maingizo ya sajili (`src/lib/db/proxies.ts`). Hoja za utatuzi huchagua `family` pamoja na safu wima nyingine za proksi, na thamani inayokosekana/isiyo tungo hubadilishwa kuwa `"auto"`.
- `upstream_proxy_config.family` — maelekezo ya maingizo ya proksi ya juu (`src/lib/db/upstreamProxy.ts`), yenye chaguo-msingi lilelile la `"auto"`.

Wakati kipengee cha proksi kilichotatuliwa kina `family` isiyo ya `auto`, `proxyConfigToUrl` huambatisha kiashiria cha `?family=` ili uteuzi huo udumu hadi kwenye kisambazaji.
