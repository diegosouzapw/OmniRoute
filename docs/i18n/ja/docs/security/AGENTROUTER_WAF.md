`agentrouter` アップストリームゲートウェイは、`messages[].content` に対してキーワードベースのコンテンツフィルターを実行します。このフィルターは一部が決定論的（特定のフレーズを常にブロック）で、一部が確率的（バーストに敏感で、短時間にリクエストが集中するとより厳しくなり、クールダウン後に回復）です。

WAF がリクエストをブロックすると、次のレスポンスを返します。

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## フィルターの適用範囲

WAF が検査するのは `messages[].content` のみです。以下は検査**されません**。

- `system` プロンプト
- 構造化コンテンツブロック（`tool_result`、`tool_use`、`thinking`、`image`）
- ツールの `description` および `input_schema` フィールド
- リクエストのメタデータ、ヘッダー、モデル ID

## 常にブロックされるパターン（大文字・小文字を区別しない）

| パターン                       | 備考                                                      |
| ------------------------------ | --------------------------------------------------------- |
| `Lorem ipsum` のあらゆる派生形 | ラテン語の Lorem 語彙全体がブロックされる                 |
| `language model`（単独）       | "the language model" と "large language model" は通過する |
| `virtual assistant`            | "AI assistant" は通過する                                 |
| `I'm here to help`             | "here to help" だけでもブロックされる                     |
| `Claude, made by Anthropic`    | 完全なフレーズの場合のみ                                  |

## ほぼ常にブロックされるパターン

| パターン                                                  | 備考                                                       |
| --------------------------------------------------------- | ---------------------------------------------------------- |
| `placeholder`                                             | 単独で使用されている場合（パラメーター名などの場合を除く） |
| `dummy data`                                              | フィクスチャでよく使われるシードフレーズ                   |
| `foo bar baz`                                             | 標準的なプレースホルダーフレーズ                           |
| 短いトークンの繰り返し（`AAA BBB CCC`、`test test test`） | キーワード詰め込みを検出するためのもの                     |

## 負荷がかかった場合の動作

短時間に約 5 回のリクエストを送信すると、WAF は通常なら通過するコンテンツもブロックし始めます。バケットは約 5～10 秒間アイドル状態が続くと緩和されます。これは、Claude Code または Codex CLI が複数のツール使用／メッセージ送信呼び出しを立て続けに行ったとき、断続的な `400 content-blocked` エラーを引き起こすものと同じ、IP とキーに紐付けられたレートリミッターです。

## OmniRoute ですでに適用されている緩和策

1. **`open-sse/services/wafRateLimit.ts`** — `agentrouter:*` URL への送信リクエスト間に最低 500 ms の間隔を設けるバーストガード。この間隔は、人間が遅延として認識する水準を大きく下回っており、通常のトラフィックで WAF が作動するのを防ぎます。

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — アップストリームが `400 content-blocked` を返した場合、エグゼキューターは指数バックオフ（1.5 秒、3.0 秒、最大 2 回試行）を使用して同じ URL へのリクエストを再試行します。バックオフ後には通常 WAF が緩和され、再試行が成功します。

3. **`tests/unit/compression/harness.test.ts`** — テストフィクスチャ `longInput` を `"lorem ipsum dolor sit amet ".repeat(40)` から `"example content for testing purposes ".repeat(40)` に変更しました。これにより、Claude Code が `Read` ツール経由でこのファイルを読み取った際に、ファイルの内容が `tool_result` ブロックを通じて送り返され、WAF が作動することを防ぎます。

## プロンプトとツール出力に関するガイダンス

Claude Code または Codex CLI のセッションで `400 content-blocked` が繰り返し発生する場合は、直近のユーザーメッセージと直近のツール結果に上記のパターンが含まれていないか確認し、表現を変更してください。一般的な回避策は以下のとおりです。

- `Lorem ipsum …` を `example text …`、またはテストやフィクスチャがモデル化しようとしている実際のコンテンツに置き換える。
- 単独で使用されている `placeholder` を `example value`、`sample value`、または実際の値に置き換える。
- `language model` を `large language model` または `the model` に置き換える。
- `dummy data` を `sample data` または現実的なシード値に置き換える。
- `I'm here to help`／`here to help` を、より具体的な書き出し（例："I'll review the file you mentioned"）に置き換える。

## 誤検知をアップストリームに報告する

現在のフィルターは過度に厳格です。操作者にプロンプトを注入する意図が明らかにない場合でも、`tool_result` ブロック内の "Lorem ipsum" をブロックします。この問題を根本から修正してほしい運用者は、`agentrouter.org` に連絡して誤検知を報告してください。上記のブロックリストは、2026-08-03 時点でアップストリームを調査して得られた実証的な結果です。
