`devin-cli-agentic` を使用すると、実際の Claude Code ランタイムは OmniRoute のローカル Anthropic
Messages エンドポイントを利用し、公式の Devin CLI は ACP stdio 経由でモデル応答を提供できます。
既存の Anthropic、Claude OAuth、Claude Web、または `devin-cli` プロバイダーは変更されません。

> **現在の状態: Claude Code `2.1.258` に固定済み。オフラインおよびライブ検証が最後に記録された
> バージョンは `2.1.220` です。** `2.1.220` の固定では、Devin CLI
> `3000.2.17` とモデル `swe-1-7-lightning` を使用して、分離された3つのシナリオが完了しました。最後のライブ実行では、
> クライアント側で実行される `Read`、`Edit`、`Bash` ターン、`npm test` の成功、
> プロジェクトコマンドおよびスキルの検出、Devin のみに限定されたルーティング、Claude への送信がゼロであることが
> 確認されました。その後、固定バージョンは `2.1.258` に引き上げられました
> （OmniRoute の Claude アイデンティティが偽装する CLI 世代であり、Fable 5.1 ティアを
> ネイティブで搭載する最初のリリース系列です）。新しい固定バージョンでは、固定されたベースイメージ上で
> インストールレイヤーと `claude --version` が検証され、ブリッジのユニットテストスイート、`compose config`、
> および静的な分離証明も成功しています。ただし、オフラインのモックシナリオとライブの3シナリオ
> スイートはまだ再実行されていません。この固定バージョンでブリッジを利用する前に、それらを再実行してください
> （「固定ツールの更新」を参照）。

## アーキテクチャ

```text
Claude Code 2.1.258（分離された非 root Linux コンテナ）
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic（Claude 形式、認証なしのプロバイダー）
  -> devin acp --agent-type summarizer（公式 ACP stdio、Devin ツールなし）
  -> 専用 devin-auth ボリューム内の Devin アカウント
```

公式 CLI のデフォルト ACP エージェントは独自のツールを実行できるため、このブリッジでは
使用しません。代わりに、公式 CLI モードではツールを持たない固定の `summarizer` ACP エージェントを起動し、
シリアライズされた Anthropic リクエストを実行トレースとして構成します。Claude 側で別の
アクションが必要な場合、応答にはクライアントツールのエンベロープを正確に1つだけ含める必要があります。ACP の
`tool_call` または `tool_call_update` は、応答を成功として報告できるようになる前に
拒否されます。

`open-sse/executors/devin-agentic/serializer.ts` のシリアライザーは、`system`、
`text`、`tool_use`、`tool_result`、`thinking`、`redacted_thinking`、`tool_choice`、および
Claude Code から提供されたツールを保持します。画像と未知のブロックは明示的に失敗します。大きなツール結果には、
目に見える切り詰めマーカーが使用されます。

パーサーは、モデルの各ターンにつき、単独の `<tool>{...}</tool>` エンベロープを1つ受け付けます。パーサーは、
リクエストのツール一覧と照合して名前を確認し、そのツールの JSON
Schema に照らして引数を検証し、説明文とアクションが混在した応答を拒否し、回数制限付きの修復を1回許可します。その後、
Claude Code は生成された Anthropic `tool_use` をローカルで実行し、`tool_result` を
OmniRoute 経由で送り返します。

## 分離と脅威モデル

ホストの Claude インストール、アカウント、および設定は対象外であり、使用禁止として扱われます。
Compose サービスは、次のように構成されています。

- UID/GID `10001:10001` で実行され、ルートファイルシステムは読み取り専用、ケーパビリティは削除され、
  `no-new-privileges` が設定される。
- プライベートな `/home/bridge`、専用の Claude 設定ボリューム、分離された OmniRoute データ、
  および独立した `devin-auth` ボリュームを使用する。
- 破棄可能な `.sandbox` ワークスペース／エビデンスのみをマウントする。
- ホストのホームディレクトリ、Keychain、SSH、クラウド認証情報、または Docker ソケットをマウントしない。
- 明示的な環境を構築し、Anthropic の API／OAuth／ルーティング変数を削除する。
- Claude Code の推論を、ローカル専用キーを使用して `http://omniroute:20128` のみに転送する。

オフラインプロファイルは内部ネットワークを使用します。ライブプロファイルでは、OmniRoute は
公式 Devin エンドポイントに `network-guard` 経由でのみ到達でき、それ以外の宛先は拒否されます。
Claude Code には、すべての外向き通信を拒否する独立したガードがあり、`NO_PROXY` を通じてローカルの OmniRoute
サービスにのみ到達できます。ガードの監査ファイルは、それぞれのガードプロセスからのみマウントされます。
スクリプトは、トークンを含まないエビデンスをエクスポートする前に、ファイルの所有権、モード、リンク数、および
すべての判定を検証します。

分離証明を独立して実行します。

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

このスクリプトは、トポロジー、名前付きマウント、非 root／読み取り専用設定、明示的なローカルルーティング、
機密性の高い環境変数が存在しないこと、Docker ソケットが存在しないこと、
`api.anthropic.com` および `claude.ai` へのアクセスがブロックされていること、Devin のみに限定された
プロバイダー選択、ならびに ACP バックエンドが利用できない場合に明示的に失敗することを検証します。

## 初回セットアップと通常利用

固定バージョンのイメージをビルドします。

```bash
./scripts/devin-bridge/build
```

隔離された Devin ボリュームのみを認証します。

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

このログインコマンドは、リモート／コンテナ環境向けの公式手動トークンフローを使用します。値は CLI のプロンプトに直接入力され、プロセス引数として渡されたり、Git に書き込まれたり、ホストからコピーされたりすることはありません。

隔離された Claude Code ランタイムを起動します。

```bash
./scripts/devin-bridge/launch
```

`launch` は、コンテナ化された Claude Code を起動する前に、隔離、Devin 認証、モデル検出を再確認します。ホストの Claude 実行ファイルを実行することはありません。モデルエイリアスは `.env.devin-bridge` で設定できます。設定するすべての値には、`devin-cli-agentic/` プレフィックスを維持する必要があります。

## 検証コマンド

再現可能なオフライン手順では Devin アカウントは不要で、実行時にインターネット接続も必要ありません。

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

認証が必要なオプトイン形式のライブ手順は次のとおりです。

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

ライブランナーは、ACP セッションが一斉に開始されるのを避けるため、シナリオ間で待機します。また、テキストによる申告をそのまま信用するのではなく、構造化された Claude ストリームイベントを検証します。次の 3 つのシナリオを実証します。

1. プロジェクトの直接読み取りと不具合分析。
2. 実際の `Edit`、クライアント所有の `Bash` による `npm test`、および最終結果。
3. `/bridge-check` と `bridge-proof` の検出、プロジェクトの読み取り、クライアント所有の `npm test` の再度の成功、および保留中の作業がない状態での完了。

最終ゲートでは Devin のネットワーク監査も確認し、Claude の外向き通信監査が空のままであることを必須とします。

## 固定バージョンのツールの更新

イメージでは、Node、Claude Code、Devin CLI のバージョンが `docker/devin-bridge/Dockerfile` で固定されています。更新手順は次のとおりです。

1. 明示的に指定されたバージョンを変更する。
2. アーキテクチャごとに用意された 2 つの Devin アーカイブチェックサムを、公式アーティファクトの値に置き換える。
3. 再ビルドし、すべてのオフライン検証コマンドを実行する。
4. イメージ内のバージョンを確認する。
5. 認証済みの 3 シナリオのライブスイートを再実行する。

いずれの CLI もホストへグローバルインストールしないでください。また、チェックサム検証を、検証されていないダウンロードに置き換えないでください。

## 診断とクリーンアップ

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  は、ローカルルーティングとサニタイズされたエグゼキューターエラーを表示します。
- `.sandbox/evidence/mock-acp.jsonl` には、決定論的なモック ACP アクションが記録されます。
- `.sandbox/evidence/claude-stream.jsonl` には、実際の Claude Code オフライン実行が記録されます。
- `.sandbox/evidence/live-*.jsonl` には、検証済みの 3 つのライブストリームが記録されます。
- `.sandbox/evidence/egress.jsonl` と `.sandbox/evidence/claude-egress.jsonl` は、検証済みでトークンを含まないガード監査のコピーです。

ログイン／設定ボリュームを保持したまま、所有するコンテナとネットワークを停止します。

```bash
./scripts/devin-bridge/clean
```

名前付きボリュームを含む、ブリッジが所有する環境全体を削除します。

```bash
./scripts/devin-bridge/clean --all
```

## 制限事項

- このブリッジは、Devin CLI `3000.2.17` がツールなしの中立的な ACP エージェントを公開していないため、固定されたツールなしの `summarizer` ロールに依存しています。アダプターは要約形式の中間レスポンスを補正しますが、1 回に制限された修復処理でも明示的に失敗する場合があります。
- 実際の ACP 呼び出しでは、一時的な `502`/`504` レスポンスが返される場合があります。ハーネスはシナリオ間に間隔を設けますが、障害が継続する場合はフェイルクローズとなり、別のプロバイダーが選択されることはありません。
- ACP コンテキストは各 Anthropic リクエストから再構築されるため、プロセスやセッションへのアフィニティはありません。
- モデルのレスポンスごとに 1 回のツール呼び出しがサポートされます。並列呼び出しは拒否されます。
- 画像は明示的にサポートされていません。ビジョン、思考出力、エフォート制御、および 1M コンテキストウィンドウは提供機能として公開されていません。
- SSE は有効な Anthropic ライフサイクルイベントを使用しますが、制限された ACP ターンの収集後に送信されます。ACP チャンクは逐次転送されません。
