**OmniCopilot** は、OmniRoute が提供するすべてのモデルを、_ネイティブの_ GitHub Copilot Chat
モデルピッカーに追加します。2つ目のサイドバーも、別個のチャット UI も不要です。Copilot のエージェントモード、ツール呼び出し、
MCP サーバー、カスタム指示はすべてそのまま機能し、選択したモデル上で実行されます。

|                              |                                                                                                                                                 |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **インストール（VS Code）**  | [Marketplace → `diegosouzapw.omnicopilot`](https://marketplace.visualstudio.com/items?itemName=diegosouzapw.omnicopilot)                        |
| **インストール（フォーク）** | [Open VSX](https://open-vsx.org/extension/diegosouzapw/omnicopilot) — Cursor、Windsurf、VSCodium、Theia、code-server、Gitpod、Antigravity、Kiro |
| **ソース / Issue**           | [github.com/diegosouzapw/OmniCopilot](https://github.com/diegosouzapw/OmniCopilot)（MIT）                                                       |
| **要件**                     | VS Code 1.104+                                                                                                                                  |

> **Copilot のサブスクリプションは不要です。** VS Code 1.122 以降では、GitHub へのサインインや
> Copilot プランなしで言語モデルプロバイダーが動作します。インライン補完や
> 埋め込みベースの機能はプロバイダー API の対象外であり、引き続き Copilot が必要です。

## セットアップ

1. **OmniRoute を実行** — `npm install -g omniroute && omniroute`（ダッシュボードは `http://localhost:20128`）。
2. **拡張機能をインストール** — 拡張機能ビューで「OmniRoute」を検索します。
3. **モデルを選択** — Copilot Chat → モデルピッカー → **Manage Models…** → **OmniRoute** の順に進み、使用するモデルに
   チェックを入れます。

OmniRoute がデフォルトポートで実行されている場合、設定は不要です。リモートインスタンスの場合は、
**アクティビティバーの OmniRoute アイコン**を開く（または `OmniRoute: Manage Connection` を実行する）ことで、次を設定します。

- **サーバー URL** — サーバーのルート URL（例：`http://192.168.0.15:20128`）。`/v1` サフィックスは
  拡張機能によって追加されるため、含めないでください。
- **API キー** — サーバーで `REQUIRE_API_KEY` が設定されている場合のみ必要です。VS Code SecretStorage を介して OS の
  キーチェーンに保存され、`settings.json` には保存されません。

## ピッカーに表示される内容

拡張機能は未加工の `GET /v1/models` ペイロードをそのまま表示するのではなく、整形して表示します。そのため、表示される
件数はカタログのサイズより少なくなります。これには意図的な理由が2つあります。

### モデルごとに1つの ID をリクエストする

`MODELS_CATALOG_PREFIX_MODE` のデフォルトは **`dual`** です。このモードでは、各モデルが2回公開されます。1つは
短いエイリアスプレフィックス、もう1つは正規のプロバイダープレフィックスであり、古いクライアント設定でも
どちらの形式も引き続き解決できるようになっています。

```
cc/claude-sonnet-4-6        ← エイリアスプレフィックス
claude/claude-sonnet-4-6    ← 正規プレフィックス、同じモデル
```

拡張機能は **`GET /v1/models?prefix=alias`** をリクエストするため、他のクライアントに対するサーバー全体の設定を
変更することなく、モデルごとに1つの ID が返されます。リファレンスインスタンスでは、これにより
**2345 件が 1396 件に集約されました。重複は 949 件、失われたモデルはゼロです。**

_すべての_ クライアントに対してサーバー全体でこの問題を解消したい場合は、ダッシュボードで
`MODELS_CATALOG_PREFIX_MODE` 機能フラグを `alias` に設定してください。クエリパラメーターとモードごとの表については、
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) を参照してください。

### チャットできないモデルを非表示にする

カタログには、画像、動画、音声、リランキング、埋め込み、モデレーションのモデルも含まれています。これらは
チャットリクエストを送っても拒否されます。

```
HTTP 400 — モデル '<id>' は画像生成モデルのため、
/v1/chat/completions では使用できません。代わりに POST /v1/images/generations を使用してください。
```

そのため、ピッカーに到達する前に `type` フィールドに基づいて除外されます。**Responses API
モデルは保持されます**。すべての Codex / GPT-5.x エントリは `supported_endpoints: ["responses"]` を公開しており、
OmniRoute がそれらを `/v1/chat/completions` 用に変換するため、問題なく使用できます。

### 一度も設定していないプロバイダー

カタログには、**アクティブな接続**を持つプロバイダーのモデルに加えて、すべての **noAuth**
プロバイダーのモデルも表示されます。これらは、無料枠の大部分を占めるキー不要のプロバイダーです。これは意図された動作です。非表示にするには、
ダッシュボード設定の `blockedProviders` に追加してください。拡張機能側では何も変更する必要はありません。

## VS Code タブ内のダッシュボード

`omnicopilot.dashboardOpen: "editor"` を設定すると、OmniRoute ダッシュボードが外部ブラウザーではなく、Simple Browser を介してエディタータブに表示されます。埋め込みは、サーバー側で `DASHBOARD_ALLOW_EMBED=vscode` を設定して**明示的に有効化**する必要があります。この設定により、HTML ページはデフォルトの `frame-ancestors 'none'` + `X-Frame-Options: DENY` の代わりに、`frame-ancestors 'self' vscode-webview:` を指定して配信されます。API サーフェス（`/api`、`/v1`、`/v1beta`、`/a2a`、`/healthz`）では、どちらの場合も厳格なヘッダーが維持されます。

> ⚠️ **これは実行時ではなく、ビルド時のフラグです。** Next.js は `headers()` をルートマニフェストにコンパイルするため、`next.config.mjs` はバンドルのビルド時にこの変数を読み取ります
> （`next.config.mjs` → `resolveDashboardEmbedMode`、`scripts/build/dashboardEmbed.mjs`）。
> すでにビルド済みのサーバーを起動する直前にこの変数をエクスポートしても、何も変わりません。ヘッダーはビルド済みのバンドルに組み込まれています。

```bash
# この変数はビルドコマンドの実行時に設定されている必要があります
DASHBOARD_ALLOW_EMBED=vscode npm run build        # または npm run build:release
npm start
```

| インストール方法           | 埋め込みを有効にできるか？                                                                                                                          |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| ソースから                 | ✅ 上記のとおり、ビルドコマンドで変数を設定します                                                                                                   |
| `npm install -g omniroute` | ❌ 公開パッケージにはビルド済みのバンドルが含まれています。代わりにソースからビルドしてください                                                     |
| Docker イメージ            | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — Docker Hub のビルド済みイメージでは埋め込みが有効になっていません |

埋め込み対応ビルドでない場合、ページはフレーム内での表示を拒否します。拡張機能はレスポンスヘッダーからそれを検出し、外部ブラウザーにフォールバックします。機能が壊れることはなく、その旨が一度だけ通知されます。
[`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) および Issue
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273) を参照してください。

## VS Code 内から他のツールを設定する

**`OmniRoute: Configure Coding CLI`** は `omniroute` CLI を操作し、Codex CLI、Claude Code、Cline、Continue、Cursor、Aider、OpenCode、Goose、Crush、Qwen Code、Kilo、Roo 向けの、すぐに使用できるプロファイルを書き込みます。これらは
[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md) で説明されているものと同じ設定です。API キーはコマンドラインではなく、`OMNIROUTE_API_KEY` 環境変数を介して CLI に渡されます。

## トラブルシューティング

| 症状                                                          | 原因／解決方法                                                                                                                                                                                                                                                                     |
| ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| モデル選択リストに OmniRoute モデルが表示されない             | サーバーに到達できません。ステータスバーのドットが灰色になります。`OmniRoute: Check Connection` を実行してください。検出処理は設計上サイレントに行われ、ユーザーに確認を求める代わりに、モデルを追加しません。                                                                     |
| すべてのモデルが二重に表示される                              | 使用している OmniCopilot が 1.0.1 より古いため、更新してください。拡張機能は現在 `?prefix=alias` を指定してリクエストします。                                                                                                                                                      |
| 以前表示されていた画像／音声モデルが表示されなくなった        | 1.0.1 以降の意図的な変更です。これらのモデルはチャットリクエストに応答できませんでした。                                                                                                                                                                                           |
| Activity Bar にパネルが表示されない                           | VS Code は追加のビューコンテナーを Activity Bar 下部の **「…」** オーバーフローに移動します。また、右クリックで非表示にしたコンテナーは非表示のままになります。Activity Bar を右クリックして **OmniRoute** にチェックを入れるか、`OmniRoute: Manage Connection` で開いてください。 |
| `editor` モードにもかかわらずダッシュボードがブラウザーで開く | サーバーが `DASHBOARD_ALLOW_EMBED=vscode` を指定して**ビルド**されていません（上記参照）。ビルド済みのインストール環境で起動時に設定しても何も変わりません。このフォールバックは意図された動作です。                                                                               |
| プロバイダーを変更した後もモデル一覧が古いままである          | `OmniRoute: Refresh Models` を実行するか、パネル内の ↻ リンクをクリックしてください。                                                                                                                                                                                              |
