> **要約**: OmniRoute は、**Arena AI
> （LMArena 形式）の ELO スコア**を使用して、モデル品質に基づき**無料**プロバイダーをランク付けします。ダッシュボードの
> **無料プロバイダーランキング**ページを開くと、タスクに最適なモデルを提供する無料プロバイダーを確認できます。
> 総合ランキングのほか、カテゴリ（コーディング、レビュー、ドキュメント作成、デバッグ）で絞り込むこともできます。

---

## 概要

OmniRoute には 329 件のプロバイダーが登録されており、そのうち 155 件のカタログエントリが**無料／認証不要**としてマークされています
（認証不要、
無料枠の OAuth、または無料枠の API キー —
[無料枠ガイド](../getting-started/FREE-TIERS-GUIDE.md)および完全な
[無料枠ディレクトリ](../reference/FREE_TIERS.md)を参照してください）。ただし、無料プロバイダーの
モデル品質には大きなばらつきがあります。フロンティアモデルを提供する認証不要のプロバイダーは、
小規模なレガシーモデルを提供するプロバイダーよりもはるかに有用です。

**無料プロバイダーランキング**では、各無料プロバイダーのカタログと、
**Arena AI リーダーボード**の**クラウドソーシングによる品質スコア**（人間の選好に基づく ELO。LMArena
チャットボットアリーナと同じ考え方）を結合することで、「**最適なモデルを提供する無料プロバイダーはどれか？**」という問いに答えます。
その後、各プロバイダーが提供する**最も優れた無料モデル**の性能に基づいてランク付けされます。

ランキングは、次の 3 つの実データソースから計算されます。

1. 無料プロバイダーのリスト — `NOAUTH_PROVIDERS`、および `hasFree` フラグが設定された
   `OAUTH_PROVIDERS` / `APIKEY_PROVIDERS` のエントリ
   （`src/shared/constants/providers.ts`）。
2. プロバイダーレジストリにある各プロバイダーのモデルカタログ
   （`open-sse/config/providerRegistry.ts`）。
3. Arena ELO 同期エンジン（`src/lib/arenaEloSync.ts`）によって
   `model_intelligence` DB テーブルに保存された、ELO から算出されるタスク適合度スコア。

結合ロジックは `src/lib/freeProviderRankings.ts` にあります。

## アクセス方法

### ダッシュボードページ

ダッシュボードを開き、**コスト → 無料プロバイダーランキング**に移動するか、次のパスに直接アクセスします。

```
/dashboard/free-provider-rankings
```

このページ（`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`）には、次の内容が表示されます。

- 上位の無料プロバイダーを示す**トップ 3 の表彰台**（🥇 🥈 🥉）。
- **順位**、**プロバイダー**、**トップモデル**、
  **スコア**、**平均スコア**、**モデル数**、**タイプ**の各列を含む完全な**ランキング表**。
- **カテゴリフィルターボタン**：_すべてのカテゴリ_、_デフォルト_、_コーディング_、_レビュー_、
  _ドキュメント作成_、_デバッグ_。

各プロバイダーの**タイプ**バッジは、無料で利用できる仕組みを示します。

| バッジ   | 意味                                           |
| -------- | ---------------------------------------------- |
| `NOAUTH` | 常に無料で、認証情報は不要                     |
| `OAUTH`  | 無料枠（`hasFree`）のある OAuth プロバイダー   |
| `APIKEY` | 無料枠（`hasFree`）のある API キープロバイダー |

基となる値は割合ではなく相対的なランキング品質を表すため、スコアは生の数値ではなく、
人が読みやすいラベル（例：_最高峰_、_非常に優秀_、_とても良い_、
_良い_、_平均的_）で表示されます。

### API エンドポイント

このページは、公開読み取りエンドポイント
（`src/app/api/free-provider-rankings/route.ts`）によって提供されています。

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

クエリパラメーター（Zod で検証）：

| パラメーター | 型     | デフォルト | 注記                                                                                                       |
| ------------ | ------ | ---------- | ---------------------------------------------------------------------------------------------------------- |
| `category`   | string | （なし）   | `default`、`coding`、`review`、`documentation`、`debugging` のいずれか。統合ランキングの場合は省略します。 |
| `limit`      | number | `50`       | `1–100` の範囲に制限されます。                                                                             |

レスポンス形式：

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` は元の Arena ELO 値で、`score` は正規化されたタスク適合度の値です
（以下を参照）。スコアが付与されたモデルを持たないプロバイダーは、レスポンスから除外されます。

## スコアの仕組み

### ソース: Arena AI リーダーボード

Arena ELO 同期エンジン（`src/lib/arenaEloSync.ts`）は、Arena AI リーダーボード API
（`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`）から `text` と
`code` の2つのリーダーボードを取得します。各リーダーボードのエントリには、
モデル名、ベンダー、ELO `score`、信頼区間、投票数が含まれます。

リーダーボードのカテゴリは、OmniRoute のタスクカテゴリに次のように対応します。

| Arena リーダーボード | OmniRoute タスクカテゴリ                          |
| -------------------- | ------------------------------------------------- |
| `text`               | `default`、`review`、`documentation`、`debugging` |
| `code`               | `coding`                                          |

### 正規化（タスク適合度スコア）

生の ELO スコアは、リーダーボードごとに **`[0.4, 0.98]` の範囲のタスク適合度値**へ正規化されます。

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

スコアが `0` または `1` に達することはなく、ユーザーによるオーバーライドの余地が残されています。これは、
API レスポンスに表示される `score` フィールドであり、ダッシュボードに表示されるラベルでもあります。

### 信頼度

各エントリには、Arena の投票数に基づいて信頼度レベルが設定されます。

| 信頼度   | 投票数     |
| -------- | ---------- |
| `high`   | 5,000 以上 |
| `medium` | 1,000 以上 |
| `low`    | 1,000 未満 |

### 保存と鮮度

正規化されたエントリは、`source = "arena_elo"` として `model_intelligence` DB テーブルに書き込まれます
（`src/lib/db/modelIntelligence.ts`）。エントリは **7日後に期限切れ**となるため、
同期を停止したプロバイダーは、古いデータを提供し続けるのではなく、最終的に表示対象から除外されます。

同期は**デフォルトで有効**です。

- サーバー起動時に一度実行され、その後は定期タイマーで実行されます
  （`src/lib/arenaEloSync.ts`、`src/instrumentation-node.ts` から接続）。
- 同期処理は**ノンブロッキングで、致命的なエラーになることはありません**。上流からの取得に失敗しても、OmniRoute は
  稼働を継続し、ランキングには最後に正常取得されたデータ（または空の状態）が表示されます。

この動作は、2つの環境変数で制御できます（
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md) に記載）。

| 変数                      | デフォルト    | 用途                                                |
| ------------------------- | ------------- | --------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | 外部への同期を無効にするには `false` に設定します。 |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | 同期間隔（秒単位）。                                |

### 手動同期 / ステータス / クリア

運用者向けに、認証済みの管理エンドポイントから手動で制御できます
（`src/app/api/intelligence/sync/route.ts` — 管理認証が必要）。

```
GET    /api/intelligence/sync          # 現在の同期ステータス（enabled、lastSync、nextSync、intervalMs）
POST   /api/intelligence/sync          # 手動同期をトリガー。書き込まずにプレビューするには本文に { "dryRun": true } を指定
DELETE /api/intelligence/sync          # 同期済みの arena_elo インテリジェンスエントリをすべてクリア
```

ランキングページが空の場合は、`POST /api/intelligence/sync` を手動で実行するか、
単にサーバーを再起動すると、データが再登録されます。

### モデルとリーダーボードの照合

レジストリのモデル ID と Arena のモデル名は、常に完全に一致するとは限りません。ランキングでは、
柔軟な照合（`src/lib/freeProviderRankings.ts` の `findMatchingIntelligence`）を使用します。

1. 正規化されたモデル ID との完全一致。
2. 末尾のバージョンサフィックスを除去した後に照合（例: `kimi-k2.6` → `kimi-k2`）。
3. プレフィックス一致（リーダーボードのモデル名がレジストリ ID のプレフィックスである場合）。

同期側では、既知のベンダープレフィックス（`anthropic/`、`openai/`、`google/` など）を
除去し、小規模なエイリアスマップを使用して、正規名を OmniRoute が内部で使用するバリアントへ展開します。
これにより、どの名前でもモデルを検索できます。

### プロバイダーのランキング方法

無料プロバイダーごとに、エンジンがカタログ内のすべてのモデルを採点し、次の値を算出します。

- **トップモデル** = プロバイダー内で最もスコアの高いモデル。
- **平均スコア** = そのプロバイダーでスコアが付与された全モデルの平均スコア。
- **モデル数** = そのプロバイダーのモデルのうち、Arena スコアが付与されたモデルの数。

プロバイダーは、まず**トップモデルのスコア**、次に平均スコアの順で並べ替えられます。これにより、
少なくとも1つの高性能な無料モデルを提供するプロバイダーが高く評価されます。

## 無料プロバイダーの選択に活用する

1. **適切なカテゴリーを選択します。** エージェント型／コード関連のワークロードには **Coding** フィルターを使用し、一般的なチャットには **All Categories** / **Default** のままにします。同じプロバイダーでも、リーダーボードごとに最上位モデルが異なるため、カテゴリーによって順位が変わる場合があります。
2. **1 回限りのセットアップでは上位 3 位を優先します。** 無料プロバイダーを 1 つか 2 つだけ接続する場合は、カテゴリー内で最上位のプロバイダーから始めてください。
3. **Type バッジを確認します。** `NOAUTH` プロバイダーは認証情報が不要なため、最も迅速に接続できます。`OAUTH` / `APIKEY` の無料枠では簡単なサインアップが必要ですが、多くの場合、より高性能なモデルを利用できます。接続手順については、[無料枠ガイド](../getting-started/FREE-TIERS-GUIDE.md)を参照してください。
4. **複数を接続し、Auto-Combo に選択を任せます。** このページを支えるものと同じ Arena ELO データが、Auto-Combo スコアリングエンジンの**タスク適合度係数**にも使用されます（`open-sse/services/autoCombo/taskFitness.ts`、解決順序は `user_override → arena_elo → models_dev_tier → static table`）。そのため、上位の無料プロバイダーを接続した後、`model: "auto"`（例：`auto/coding`）でルーティングすると、リクエストごとに高品質な無料モデルが自動的に優先されます。16 要素すべてのスコアリングについては、[Auto-Combo](../routing/AUTO-COMBO.md)を参照してください。
