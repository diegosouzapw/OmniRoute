## 1. Antigravity と Antigravity CLI (agy) の比較

両プロバイダーは、同一の OAuth クライアント、トークン更新、エンドポイント、Google アカウントを含む、**同じ Google バックエンド**を共有しています。違いは、表示されるモデルです。

> Google による公式の比較については、[Antigravity CLI の発表](https://antigravity.google/blog/introducing-google-antigravity-cli)を参照してください。

| 項目                 | `antigravity` (IDE)                          | `agy` (CLI)                                                    |
| -------------------- | -------------------------------------------- | -------------------------------------------------------------- |
| **Google 製品**      | Antigravity 2.0 / Antigravity IDE            | Antigravity CLI                                                |
| **バックエンド**     | 同じ Google Cloud Code API                   | 同じ Google Cloud Code API                                     |
| **OAuth / トークン** | 同じクライアント、同じ更新方式               | 同じクライアント、同じ更新方式                                 |
| **モデルカタログ**   | 静的な厳選リスト（OmniRoute にハードコード） | `:fetchAvailableModels` を介して Google からリアルタイムに取得 |
| **Claude モデル**    | Sonnet 4.6、Opus 4.6（各4バリエーション）    | Sonnet 4.6、Opus 4.6（各4バリエーション）                      |
| **Gemini の命名**    | 分かりやすいラベル（Low/Medium/High）        | アップストリーム ID（extra-low/low/agent）                     |
| **追加モデル**       | `gpt-oss-120b-medium`                        | Google から追加モデルが提供される場合あり                      |
| **デフォルトの用途** | IDE 統合（VS Code、JetBrains）               | CLI / API アクセス                                             |
| **クォータ**         | agy と共有（同じ Google アカウント）         | antigravity と共有（同じ Google アカウント）                   |

**利用可能なモデル（実験により検証済み、2026-07-29）**:

- Gemini: 3.6 Flash、3.5 Flash、3.1 Pro、3 Flash、2.5 Flash（さまざまな思考レベル）
- Claude: Sonnet 4.6、Opus 4.6（それぞれ default/low/medium/high バリエーション）
- その他: GPT-OSS 120B Medium
- **Claude Sonnet 5 は利用できません** — サポートされるのは 4.6 のバリエーションのみです

**モデルカタログが異なる理由**: Google の公式ブログによると、Google の CLI は「速度と低オーバーヘッドに最適化」され、「Gemini モデルと協調して最適化」されています。Web/IDE 製品は「包括性に最適化」されています。CLI は `:fetchAvailableModels` を使用してモデルを動的に検出しますが、IDE は静的な厳選リストを使用します。

**実際の使用方法**: Gemini モデルには `agy/` プレフィックスを使用してください（例: `agy/gemini-3.7-flash-high`）。静的な厳選リストには `antigravity/` を使用してください。どちらも同じ Google バックエンドにアクセスしますが、公開されるモデルの命名が異なります。クォータは共有されるため、どちらのプロバイダーを使用しても、同じ Google アカウントの上限に対してカウントされます。

## 2. Google One AI Pro: クォータシステム

> 公式のクォータ詳細については[Antigravity Docs: Plans](https://antigravity.google/docs/plans)を、最新の料金改定については[Changes to Antigravity Plans](https://antigravity.google/blog/changes-to-antigravity-plans)を参照してください。

Google Antigravityでは、メッセージ数ではなく「Work Done」（計算負荷）に基づく**2層クォータ**が使用されます。

### 2つのレイヤー

| レイヤー              | 概要                              | 更新サイクル                                                         |
| --------------------- | --------------------------------- | -------------------------------------------------------------------- |
| **5時間スプリント**   | 即時利用可能な「Work Done」プール | セッション内の最初のリクエストから5時間後にリセット                  |
| **7日間ベースライン** | 週単位のハード上限                | 到達した場合は5時間更新より優先され、次の7日間期間まで利用不可になる |

**「Work Done」の計算方法**: エージェントを多用するタスク（例: 「このリポジトリ全体をリファクタリングして」）は、単純なタスク（例: 「この関数を修正して」）よりもはるかに速くクォータを消費します。消費量を表示するリアルタイムダッシュボードはありません。

### プラン階層

| プラン       | 料金       | クォータ                              | 週間上限                                |
| ------------ | ---------- | ------------------------------------- | --------------------------------------- |
| Free         | $0         | 実用的なクォータ、毎週更新            | あり                                    |
| AI Pro       | $19.99/月  | 高クォータ、5時間ごとのローリング更新 | あり（到達した場合は5時間更新より優先） |
| AI Ultra 5x  | $99.99/月  | Proの5倍のクォータ                    | 週間上限なし                            |
| AI Ultra 20x | $199.99/月 | Proの20倍のクォータ                   | 週間上限なし                            |

### Geminiモデルと非Geminiモデル

- **Geminiモデル**（Flash + Pro）: API料金に応じて消費される、単一のレート制限を共有します。FlashがProより8倍安い場合、Flashでは8倍多くのトークンを利用できます。
- **非Geminiモデル**（Claude、GPT-OSS）: **個別の**レート制限があります。Geminiが利用不可になっても、引き続き利用できる場合があります。

### AIクレジット（超過利用）

> クレジットの仕組みについては、[Google One AI credits](https://support.google.com/googleone/answer/14534406)を参照してください。

ベースラインクォータを使い切った場合:

- **Never**: クォータが更新されるまで待機し、「Baseline model quota reached」と表示される
- **Always**: AIクレジットを自動的に使用し、ベースラインが更新されると元に戻る

クレジットは別途購入され、標準のAPI料金に基づいて差し引かれます。

### 重要事項

- クォータは**アカウント単位で共有**されます。同じGoogleアカウントをAntigravity IDE、CLI、OmniRouteで使用すると、1つのクォータプールが共有されます
- 各Googleアカウントには、それぞれ独立したクォータがあります。つまり、複数のアカウントを使用すれば、複数のクォータプールを利用できます
- AI Proユーザーからは、週間ベースラインに到達すると5時間後にリセットされず、**7日間利用不可**になるとの報告があります（Googleは、高い需要に対応するための意図された仕様であると確認しています）

**アカウントのクォータを使い切った場合**: OmniRouteは、コンボルート内で次に利用可能なアカウントを使用して自動的に再試行します。手動操作は必要ありません。

## 3. projectIdの取得方法

すべてのantigravity/agy接続には、Google Cloud Codeの`projectId`が必要です。これがない場合、`/v1internal:models`エンドポイントは404を返します。

### 方法A: 自動（推奨）

OmniRouteがこれを自動的に処理します。Dashboard OAuthを使用して新しいGoogleアカウントを追加すると、次の処理が行われます。

1. OmniRouteがトークンを更新する
2. `loadCodeAssist`を呼び出してprojectIdを検出する
3. プロジェクトが存在しない場合、`onboardUser`を呼び出して作成する
4. `loadCodeAssist`を再試行して、新しく作成されたprojectIdを取得する
5. データベースに保存する

**ほとんどのアカウントでこの方法を使用できます**。手動の手順は必要ありません。

### 方法B: agy CLIを使用して手動で取得

自動検出に失敗する場合（発生条件についてはセクション5を参照）:

```bash
# agy CLIをインストール（まだインストールしていない場合）
npm install -g @anthropic-ai/agy

# Googleアカウントでログイン
agy login

# オンボーディングが必要なアカウントを選択
# これによりCloud Codeへの登録が開始され、projectIdが割り当てられる
```

`agy login`が成功したら、OmniRoute Dashboardでトークンを更新します。projectIdは自動的に検出されます。

### 確認方法

データベースを確認します。

```bash
# OmniRouteコンテナ内
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

または、ログを確認します。

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. OAuth リダイレクト URI

### 問題

Google OAuth では、有効なリダイレクト URI が必要です。OmniRoute のデフォルトでは、`http://127.0.0.1:20128/callback`（ループバック）が使用されます。これはローカルビルドでは機能しますが、**リモートデプロイでは失敗します**（例：LAN IP 経由でアクセスするサーバー）。

Google は、以下に該当するリダイレクト URI を拒否します。

- IP アドレスを使用している（`.com`、`.org` などで終わるドメインである必要があります）
- OAuth クライアント設定に登録されたリダイレクト URI と一致しない

### 解決策

**オプション A：組み込みの OAuth フローを使用する（デフォルト）**

- `localhost` または `127.0.0.1` から OmniRoute にアクセスする場合に機能します
- 設定は不要です

**オプション B：カスタム OAuth 認証情報**

- 環境に `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` を設定します
- 独自の Google OAuth 認証情報を指定します：
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Google Cloud Console で、`https://your-domain.com/callback` を承認済みリダイレクト URI として登録します

**オプション C：初回ログインに agy CLI を使用する**

- OmniRoute にアクセスするマシン上で `agy login` を実行します
- OAuth フローはローカルで完了し、トークンが保存されます
- Dashboard から OmniRoute に接続をインポートします

### 制限事項

- カスタム OAuth 認証情報にはドメイン名が必要です（Google はリダイレクト URI として IP アドレスを受け付けません）
- ドメインがない場合は、代わりにオプション A または C を使用してください

## 5. トラブルシューティング：自動セットアップが失敗する場合

OmniRoute は、ほとんどのアカウントで projectId の検出とオンボーディングを自動的に処理します。失敗する場合、通常は以下のいずれかが根本原因です。

### アカウントのリージョンがブロックされている

**症状**：`agy login` が「Eligibility check failed: Your current account is not eligible for Antigravity, because it is not currently available in your location.」を返します。

**根本原因**：Google アカウントには、登録時に設定されるバックエンドの「Country Association」フィールドがあります。agy CLI と Cloud Code API は、このフィールドを厳密に確認します。一方、Web 版 Gemini は現在の IP のみを確認します。

> アカウントに関連付けられたリージョンを確認または変更するには、[Google Country Association Form](https://policies.google.com/country-association-form) にアクセスしてください。

**Web 版 Gemini は機能するのに、agy が機能しない理由**：

- Web 版 Gemini / Google One：現在の IP のみを確認します（プロキシで通過できます）
- agy CLI / Cloud Code API：バックエンドの Country Association フィールドを読み取ります（プロキシは役に立ちません）

**修正方法**：

1. 米国の IP を使用している状態で [Google Country Association Form](https://policies.google.com/country-association-form) にアクセスします
2. リージョン変更リクエストを送信します（「I live in a different country」を選択）
3. Google による処理とメール通知を 1～24 時間待ちます
4. その後、`agy login` が成功するようになります

### アカウントに Cloud Code プロジェクトがない

**症状**：ログに `loadCodeAssist returned no project id` および `onboardUser failed (400)` と表示されます。

**根本原因**：アカウントが Google Cloud Code に一度も登録されておらず、自動オンボーディングも失敗しています。

**修正方法**：Cloud Code の登録を開始するために `agy login` を手動で実行し、その後 OmniRoute Dashboard でトークンを更新します。

### トークンの有効期限切れまたは失効

**症状**：ログに 401 エラー、または「Token has expired」というメッセージが表示されます。

**修正方法**：Dashboard → Providers → agy に移動し、更新アイコンをクリックしてトークンを更新します。リフレッシュトークン自体が失効している場合は、OAuth を介して再認証する必要があります。

## 判断フローチャート

```
アカウントが機能していない？
│
├─ データベースにprojectIdがある？
│  ├─ はい → 原因は別にある（トークンの期限切れ、レート制限など）
│  └─ いいえ ↓
│
├─ アカウントの国/地域の関連付けが制限対象の地域に設定されている？
│  ├─ はい → Google Country Association Formで地域を変更
│  │         (https://policies.google.com/country-association-form)
│  │         1～24時間待ってから再試行
│  └─ いいえ ↓
│
├─ アカウントにGoogle One AI Proサブスクリプションがある？
│  ├─ いいえ → まずone.google.comで登録
│  └─ はい ↓
│
├─ 自動検出を試す（ダッシュボードでトークンを更新）
│  ├─ 成功 → 完了
│  └─ まだ失敗する ↓
│
└─ 手動：マシン上で`agy login`を実行
   ├─ 成功 → ダッシュボードでトークンを更新すると、projectIdが検出される
   └─ 失敗 → エラーメッセージを確認。地域またはサブスクリプションの問題である可能性が高い
```
