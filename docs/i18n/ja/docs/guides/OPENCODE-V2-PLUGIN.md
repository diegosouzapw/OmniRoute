`@omniroute/opencode-plugin-v2` は、OmniRoute のカタログ全体（モデル、コンボ、オートコンボ）を、表示名、料金、無料利用枠の予算とともに OpenCode v2 のモデルピッカーへ追加します。

OpenCode v1 と v2 では異なる契約を通じてプラグインを読み込むため、これは `@omniroute/opencode-plugin` とは別のパッケージです。使用している OpenCode のメジャーバージョンに合うものを選択してください。両者の間で共有されるものはないため、一方をアップグレードしても、もう一方のアップグレードを強制されることはありません。

## 要件

- OpenCode v2。
- 接続可能な OmniRoute ゲートウェイ（デフォルトでは `http://localhost:20128`）。
- Node.js 22 または 24。

## インストール

`opencode.json` にプラグインを追加します。

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

モデルは `omniroute/<provider>/<model>` として表示されます。`providerId` はこのプレフィックスと、OpenCode が認証情報を保存する統合の ID を決定します。

## 認証情報

プラグインは、次の3か所から以下の順序でゲートウェイキーを探します。

1. **OpenCode で接続した認証情報。** プラグインは統合を登録するため、OpenCode 独自の認証フローでキーを保存できます。`opencode.json` には何も保存されません。この方法を推奨します。
2. プロジェクト単位で上書きするための、プラグインオプション内の `apiKey`。コミットする可能性があるファイルにキーが保存されます。
3. 環境内の `OMNIROUTE_API_KEY`。

この3つのいずれも設定されていない場合、カタログは空になります。プラグインは、何の通知もなく空のピッカーを表示する代わりに、起動時にその旨を一度だけ通知します。

### 管理トークンは別のキーです

コンボ、プロバイダーの状態、エンリッチメント（表示名、料金、無料利用枠の予算）は、ゲートウェイの `/api/*` エンドポイントから取得されます。ほとんどのデプロイでは、これらは推論キーではなく、**管理**トークンによって保護されています。

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<管理用読み取りトークン>"
}
```

`managementReadToken` が未設定の場合、`apiKey` にフォールバックします。ゲートウェイがこのフォールバックを拒否した場合でもカタログは公開されますが、表示名の代わりに生のモデル ID が使用され、正規エイリアスの重複排除、料金、コンボは提供されません。この場合、プラグインはエンドポイントごとに一度だけ警告し、対象のエンドポイントと利用できなくなった情報を示します。そのため、ピッカーの機能が低下している理由が不明なままになることはありません。

## オプション

| キー                             | デフォルト                                   | 注記                                                                                                      |
| -------------------------------- | -------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `providerId`                     | `"omniroute"`                                | プロバイダー ID、統合 ID、およびモデルが表示されるプレフィックス                                          |
| `baseURL`                        | 必須                                         | ゲートウェイのルート。`http(s)` のみ。必要に応じて `/v1` サフィックスが追加されます                       |
| `apiKey`                         | 接続済みの認証情報、次に `OMNIROUTE_API_KEY` | `/v1/*` 用のチャットキー                                                                                  |
| `managementReadToken`            | `apiKey` にフォールバック                    | `/api/*` 用のキー。通常は**同じキーではありません**                                                       |
| `displayName`                    | `"OmniRoute"`                                | ピッカー内のプロバイダー名                                                                                |
| `timeoutMs`                      | `10000`                                      | エンドポイントごとの取得タイムアウト（オートコンボでは 5 秒）                                             |
| `modelCacheTtlMs`                | `300000`                                     | カタログキャッシュの TTL。ディスクスナップショットによってコールドスタートが高速化されます                |
| `timeouts`                       | `timeoutMs` にフォールバック                 | エンドポイントごとの時間上限（ミリ秒）：`models`、`combos`、`autoCombos`、`enrichment`                    |
| `enrichment`                     | `true`                                       | 名前、料金、無料利用枠の予算を取得                                                                        |
| `providerTag`                    | `true`                                       | 表示名の先頭に、ルーティング先となるアップストリームプロバイダーを付加                                    |
| `usableOnly`                     | `false`                                      | ゲートウェイがプロビジョニング済みと報告したプロバイダーのみを保持                                        |
| `visibleModels` / `hiddenModels` | `[]`                                         | 完全一致またはサフィックス一致の許可リスト。拒否が優先されます                                            |
| `geminiSanitization`             | `true`                                       | Gemini が拒否する JSON-Schema キーワードをツールスキーマから削除（`$ref` ツールは変更せずに転送されます） |
| `apiFormat.allowAnthropic`       | `false`                                      | 許可リストにある ID を Anthropic API ブロック経由でルーティング                                           |
| `apiFormat.anthropicModels`      | `[]`                                         | Anthropic にルーティングされる完全なモデル ID                                                             |
| `logLevel` / `startupDebug`      | `warn` / `false`                             | ロガーの詳細度                                                                                            |

## カタログを最新に保つ仕組み

カタログは遅延取得され、`modelCacheTtlMs` の期間キャッシュされます。また、ディスク上のスナップショットによって、ゲートウェイに到達できない場合でも最後に確認されたカタログを利用できます。そのため、障害が発生しても失われるのは鮮度だけです。モデルとコンボは到着するとすぐに公開されます。自動コンボ、プロバイダー一覧、エンリッチメントオーバーレイも到着次第反映されるため、1 つの遅いエンドポイントがピッカー全体を待たせることはありません。

名前には、ゲートウェイが把握している情報、つまりモデルのルーティング先となるアップストリームプロバイダー、`[Free]` マーカー、およびそれに付随する予算が含まれます。そのため、同じモデルを提供する 2 つの接続も区別できます。プレフィックスを無効にするには、`"providerTag": false` を設定します。

手動更新コマンドはありません。OpenCode v2 のコマンドはコールバックではなくプロンプトテンプレートであるため、プラグインからそのようなコマンドを公開することはできません。更新は TTL に従います。ホストに再読み込みを要求するのは、カタログまたはオーバーレイが実際に変更された場合のみであり、更新のたびに要求することはありません。

## Gemini でのツール呼び出し

Gemini は、ツール宣言に `$schema` または `additionalProperties` が含まれているリクエスト全体を拒否し、`400 INVALID_ARGUMENT` を返します。プラグインは、このプロバイダーの Gemini モデル宛てのツールスキーマからこれらのキーワードを削除し、それ以外のリクエストには変更を加えません。`$ref` を含むツールは、参照を削除するとスキーマが「何でも受け入れる」ように拡張されてしまうため、削除処理を行わず、そのまま転送されます。
無効にするには、`"geminiSanitization": false` を設定します。

## トラブルシューティング

| 症状                                                 | 原因                                                                                                                                         |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| ピッカーに OmniRoute モデルが表示されない            | キーを解決できていない（起動時の警告を確認してください）か、ゲートウェイに到達できません                                                     |
| 生のモデル ID しか表示されず、コンボも料金情報もない | 管理エンドポイントがトークンを拒否しました。`managementReadToken` を設定してください                                                         |
| セッションが `opencode-<id>/…` に固定されている      | v1 プラグインは `opencode-<id>` を公開していましたが、v2 は `<id>` をそのまま公開します。そのため、`<id>/…` 配下のモデルを再選択してください |
