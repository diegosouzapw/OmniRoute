## ルール

- カバレッジ目標はソースファイルに適用し、`tests/**` には適用しません。
- `open-sse/**` は製品の一部であり、対象範囲に含め続ける必要があります。
- 新しいコードによって、変更対象領域のカバレッジが低下しないようにしてください。
- 実装の詳細よりも、動作とブランチの結果をテストすることを優先してください。
- `src/lib/db/**` では、大規模なモックよりも、一時 SQLite データベースと小規模なフィクスチャを優先してください。

## 現在のコマンドセット

- `npm run test:coverage`
  - ユニットテストスイートにおける、ソースカバレッジの主要ゲート
  - `text-summary`、`html`、`json-summary`、`lcov` を生成
- `npm run coverage:report`
  - 最新の実行結果に基づく、ファイル単位の詳細レポート
- `npm run test:coverage:legacy`
  - 過去との比較専用

## ラチェットポリシー

`npm run test:coverage` のしきい値は、プロジェクトが十分な余裕をもって次のマイルストーンを実際に上回った後にのみ更新してください。

**現在のゲート:** `npm run test:coverage` では、**ステートメント 60 / 行 60 / 関数 60 / 分岐 60** が適用されます（Quality-Gates フェーズ 6A.1 でメトリクスの基準が再設定されました。それ以前の 82.58% というベースラインは、テストファイルをカウントし、`open-sse` を除外していたため、水増しされていました）。`test:coverage:legacy` コマンドでは、過去との比較用に旧来の 50/50/50 メトリクスが維持されています。

最新のレポートに対して臨時でしきい値を確認するには、以下を使用します。

```bash
node scripts/check/test-report-summary.mjs --threshold 75
```

推奨されるラチェットの順序（並びは `ステートメント-行 / 分岐 / 関数`）:

2. 60/62/58
3. 65/64/62

## 既知のギャップ

現在のカバレッジコマンドは、Node のメインユニットテストスイートを測定し、`open-sse` を含め、そのスイートから到達したソースを対象にします。現時点では、Vitest のカバレッジを単一の統合レポートにマージしていません。このマージは今後行う価値がありますが、60% から 80% への引き上げを開始するうえでの障害ではありません。
