> **要約**: OmniRoute には 357 個のプロバイダー ID が登録されており、**152 個のプロバイダーカタログエントリが `hasFree` としてマークされています**。より厳格に監査された無料モデルカタログは、**35 個の継続提供プールキー / 482 個のエントリ**（提供中 475 個 + 提供終了 7 個）を対象としています。フォールバック容量を拡大するには、条件に適した複数のプロバイダーを接続してください。ただし、各プロバイダーのクォータ、承認ルール、プライバシーポリシー、有料超過利用の条件は、引き続きすべて適用されます。

## 無料枠とは？

多くの AI プロバイダーは、何らかの形で**無料アクセス**を提供しています。プロバイダーによって、
認証不要のエンドポイント、定期的に補充されるクォータ、レート制限付きの上限なしアクセス、登録時の付与枠、
手動承認、一時的なプロモーションなど、その形態は異なります。一部のオプションでは、アカウント、API キー、
クレジットカード、KYC、またはプロバイダー固有の規約への同意が必要です。

OmniRoute は、これらの無料枠を 1 つのエンドポイントに**集約**します。10 個の異なるサービスに個別に登録する代わりに、それらすべてを OmniRoute に接続し、`model: "auto"` を使用することで、リクエストごとに最適な無料オプションを自動的に選択できます。

## 無料枠をスタックする方法

OmniRoute の真価は、**無料枠のスタック**にあります。1 つのプロバイダーだけに依存するのではなく、複数の無料プロバイダーを接続し、リクエストごとに OmniRoute が最適なものを自動的に選択できるようにします。

### 例：無料枠のカバー範囲を拡大する

複数のプロバイダーを接続して、単一のクォータへの依存を減らします。

1. **Gemini** — 定期的に更新される API キーのクォータ
2. **Groq** — 定期的に更新される API キーのクォータ
3. **Pollinations** — キー不要で、レート制限付きのアクセス
4. **LongCat** — サインアップ時に一度だけ付与される枠（KYC が必要）

その後、`model: "auto"` を使用すると、OmniRoute は次のように動作します。

- 適格な接続のうち、最も優先順位の高いものを最初に試す
- そのクォータが不足しているか、ヘルスチェックに失敗した場合 → 次に設定されているプロバイダーを試す
- キー不要のプロバイダーが利用できない場合 → 残りの接続先を順に試す
- すべて失敗した場合 → LongCat をバックアップとして使用する

**結果**：自動フォールバックによって無料枠のカバー範囲が広がります。ただし、無制限の容量が保証されるわけではありません。

## 無料プロバイダーを接続する方法

### ステップ 1：ダッシュボードを開く

ブラウザーで `http://localhost:20128` にアクセスします。

### ステップ 2：プロバイダー画面に移動する

サイドバーの **Providers** をクリックします。

### ステップ 3：プロバイダーを追加する

**+ Add Provider** ボタンをクリックします。

### ステップ 4：無料プロバイダーを選択する

カタログを確認し、各プロバイダーの現在の `hasFree`、認証、クォータ、プライバシー、
および ToS のメタデータを調べます。プロバイダーカードと
[無料枠リファレンス](../reference/FREE_TIERS.md)では、定期更新される枠、
上限なし／キー不要のアクセス、サインアップクレジット、提供終了済みの項目、およびリスクの高い提供元を区別しています。

### ステップ 5：接続する

`NOAUTH` プロバイダーには認証情報は必要ありません。OAuth および API キーを使用するプロバイダーは、
それぞれのドキュメントに記載されたアカウントフローを通じて接続する必要があります。

### ステップ 6：繰り返す

利用規約とプライバシーモデルがユースケースに適合するプロバイダーを複数接続します。

## カタログを正しく読み取る方法

- `NOAUTH` は、OmniRoute がプロバイダーの認証情報を要求しないことを意味します。稼働時間、プライバシー、
  または無制限の容量を保証するものではありません。
- `hasFree` は検索用のメタデータです。定期更新されるクォータ、キー不要のアクセス、
  サインアップクレジット、承認制プログラム、またはプロモーションを表す場合があります。
- `recurring-uncapped` は、公開されたトークン上限が確認できなかったことを意味します。レート制限と
  同時実行数の制限は引き続き適用されます。
- `one-time-initial` は、サインアップ時に付与された枠を使い切っても更新されません。
- `tos: avoid` は、利用前にプロバイダーの規約とアカウント上のリスクを確認すべきことを示す警告です。
- `discontinued` と記された項目は履歴上の記録として残されているものであり、
  現在も無料であるかのように提示してはいけません。

## OmniRoute が無料枠をさらに有効活用する仕組み

### 1. 自動フォールバック

ある無料プロバイダーが混雑しているか停止している場合、OmniRoute は次のプロバイダーを自動的に試します。ユーザーが何か操作する必要はありません。

### 2. スマートルーティング

OmniRoute は、以下に基づいてリクエストごとに**最適な無料プロバイダー**を選択します。

- 速度 — 現在最も高速なプロバイダーはどれか？
- 品質 — このタスクに最適なプロバイダーはどれか？
- 容量 — クォータが残っているプロバイダーはどれか？

### 3. トークンの節約

OmniRoute の圧縮パイプラインは、圧縮対象となるプロンプトとツール出力のトークン数を削減できます。
実際の削減量は、コンテンツ、選択したエンジン、プロバイダーの計算方式、および忠実度の
設定によって異なります。圧縮によって各プロバイダーのクォータが一定の倍率で増えるわけではありません。

### 4. 複数アカウントのサポート

プロバイダーの規約で複数のアカウントまたは認証情報が許可されている場合、OmniRoute は各
接続を個別のルーティング候補として扱うことができます。プロバイダーのクォータやアクセスポリシーを
回避する目的で追加のアカウントを作成しないでください。

## 無料枠の計算

現在、共有プールを重複排除した実稼働カタログでは、以下の値が報告されています。

| 指標                                              |                                   現在の監査済み値 | 解釈                                                                                                                                 |
| ------------------------------------------------- | -------------------------------------------------: | ------------------------------------------------------------------------------------------------------------------------------------ |
| 定期的に付与される定量化可能な枠                  |                            **約16.2億トークン/月** | 共有プールは1回のみ計上。上限なしのプロバイダーは合計から除外                                                                        |
| サインアップ時の付与分を含む初月                  |                               **約22.2億トークン** | 定期付与の合計に、1回限りおよび定期的なクレジットを加算                                                                              |
| 監査済み無料モデルインベントリ                    | **35個の定期プールキー / 482件のカタログエントリ** | 稼働中475件 + 提供終了7件。357プロバイダーのカタログとは別                                                                           |
| 対象となる定期/keylessの永久無料プロバイダー      |                                             **53** | 日次/月次/クレジット/上限なしの定期カタログ種別およびkeylessカタログ種別に含まれる一意のプロバイダー数。利用資格で制限される行は除外 |
| `hasFree`と記載されたプロバイダーカタログエントリ |                                      **152 / 357** | より広範なプロバイダーメタデータ。すべてに定量化可能な定期クォータがあるわけではない                                                 |

提供終了エントリ、およびサインアップクレジットの算出方法については、[無料枠リファレンス](../reference/FREE_TIERS.md)を参照してください。

## よくある質問

### 「本当に無料ですか？」

カタログには、プロバイダーが公開している条件とプロジェクトによる調査結果が記録されていますが、提供内容は変更される可能性があります。
利用前に、プロバイダーの現在の料金、クォータ、プライバシーポリシー、利用資格を確認してください。

### 「無料枠を使い切ることはありますか？」

どのプロバイダーも、レート制限の適用、モデルの変更、アクセスの停止、サービスの停止を行う可能性があります。複数の
接続を設定するとフォールバックの対象範囲は広がりますが、利用可能な無料ルートが保証されるわけではありません。

### 「無料プロバイダーを本番環境で使用できますか？」

プロバイダーのSLA、データ処理、制限、利用規約が本番環境の
要件を満たしている場合に限ります。重要なワークロードには、監視され、契約上の要件を満たす適切なフォールバックを用意する必要があります。

### 「何かデメリットはありますか？」

厳しい制限、待機リスト、KYC、クレジットカード認証、プロンプトを使用した学習、
プライバシー保護の弱さ、SLAの欠如、モデルの頻繁な入れ替え、地域制限、有料の超過利用、アカウントポリシー上のリスクなどのトレードオフが考えられます。
OmniRouteは利用可能なメタデータを提示し、何を有効にするかは利用者が選択します。

### 「無料クォータを増やすにはどうすればよいですか？」

1. より多くの無料プロバイダーに接続する
2. 適切な圧縮エンジンを有効にし、ワークロードに対する削減効果を測定する
3. `auto/cheap` を使用して無料または低価格のプロバイダーを優先する
4. プロバイダーの利用規約に違反しない範囲で、許可されている追加のプロバイダーまたは認証情報を追加する

### 「無料プロバイダーは品質が低いですか？」

必ずしもそうではありません。一部のプロバイダーでは、有料
ルートで利用できるものと同じモデルファミリーが提供されていますが、制限、レイテンシ、プライバシー、信頼性、モデルのバージョンが異なる場合があります。
品質の目安として無料プロバイダーランキングページを使用し、実際に提供されるモデルを確認してください。
