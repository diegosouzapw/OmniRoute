> **要約**: 利用条件を満たすプロバイダーアカウントをご自身で用意してください。OmniRoute は、設定した接続を統合するものであり、表示されている合計トークン枠を提供するものではありません。無料アクセスには、サインアップ、API キー、承認、または支払い方法の登録が必要な場合があります。各プロバイダーの利用制限、プライバシーポリシー、および利用規約は引き続き適用されます。

## 無料枠とは？

多くのAIプロバイダーは、何らかの形で**無料アクセス**を提供しています。プロバイダーによって、認証不要のエンドポイント、定期的に更新されるクォータ、レート制限付きの無制限アクセス、サインアップ時の付与枠、手動承認、一時的なプロモーションなど、その内容は異なります。一部のオプションでは、アカウント、APIキー、クレジットカード、KYC、またはプロバイダー固有の利用規約への同意が必要です。

OmniRouteは、設定された接続を1つのエンドポイントに**集約**します。アカウントが必要な各プロバイダーには、引き続き個別にサインアップする必要があります。それらのアカウントを接続し、`model: "auto"`を使用して、利用可能なターゲット間でルーティングします。新規インストール直後は、キー不要で利用可能なターゲットが存在しない場合があります。OmniRouteをインストールするだけでは、チャット応答が正常に返されることは保証されません。

## 無料枠を組み合わせる方法

OmniRoute の真価は、**無料枠を組み合わせること**にあります。1つのプロバイダーだけに依存するのではなく、複数の無料プロバイダーを接続し、リクエストごとに最適なものを OmniRoute に自動選択させます。

### 例：無料枠のカバー範囲を拡大する

単一のクォータへの依存を減らすため、複数のプロバイダーを接続します。

1. **Gemini** — 定期的に更新される API キーのクォータ
2. **Groq** — 定期的に更新される API キーのクォータ
3. **Pollinations** — キー不要、レート制限付きアクセス
4. **LongCat** — サインアップ時に一度だけ付与されるクレジット（KYC が必要）

次に `model: "auto"` を使用すると、OmniRoute は以下のように動作します。

- 利用条件を満たす接続のうち、最も優先順位が高いものを最初に試す
- そのクォータまたはヘルスチェックに問題がある場合 → 次に設定されているプロバイダーを試す
- キー不要のプロバイダーが利用できない場合 → 残りの接続先を順に試す
- 利用条件を満たす接続がどれも成功しない場合 → エラーを返す。サインアップ時に付与されたクレジットは、有効かつ残高がある場合にのみ利用可能

**結果**：自動フォールバックにより無料枠のカバー範囲を拡大できますが、無制限のキャパシティが保証されるわけではありません。

## 無料プロバイダーへの接続方法

### ステップ 1：ダッシュボードを開く

ブラウザで `http://localhost:20128` にアクセスします。

### ステップ 2：プロバイダーに移動する

サイドバーの **プロバイダー** をクリックします。

### ステップ 3：プロバイダーを追加する

**+ プロバイダーを追加** ボタンをクリックします。

### ステップ 4：無料プロバイダーを選択する

カタログを参照し、各プロバイダーの現在の `hasFree`、認証、クォータ、プライバシー、および利用規約（ToS）のメタデータを確認します。プロバイダーカードと
[無料枠リファレンス](../reference/FREE_TIERS.md)では、定期的に更新される利用枠、上限なし／キー不要のアクセス、サインアップクレジット、提供終了した項目、およびリスクの高いソースを区別しています。

### ステップ 5：接続する

`NOAUTH` プロバイダーの場合、OmniRoute はアップストリームの認証情報を要求しません。ただし、アップストリームがサードパーティ製クライアントを受け入れることや、利用可能なキャパシティがあることを保証するものではありません。OAuth および API キーを使用するプロバイダーは、文書化されたアカウントフローに従って接続する必要があります。ルーター認証が有効な場合でも、クライアントは引き続き **ダッシュボード → エンドポイント** に表示される OmniRoute API キーを使用します。

### ステップ 6：繰り返す

利用規約とプライバシーモデルがユースケースに適合する複数のプロバイダーを接続します。

## カタログを正しく読む

- `NOAUTH` は、OmniRoute がプロバイダーの認証情報を要求しないことを意味します。稼働時間、プライバシー、または無制限の容量を保証するものではありません。
- `hasFree` は検出用メタデータです。定期的なクォータ、キー不要のアクセス、サインアップクレジット、承認制プログラム、またはプロモーションを表す場合があります。
- `recurring-uncapped` は、公開されているトークン上限が確認できなかったことを意味します。レート制限および同時実行数の制限は引き続き適用されます。
- `one-time-initial` は、サインアップ時に付与された分を使い切った後に再付与されません。
- `tos: avoid` のプロバイダーは、デフォルトで自動ルーティングから除外されます（`excludeTosAvoid`）。アカウントを接続しても、このフィルターを回避することはできません。運用者がオーバーライドする場合は、プロバイダーの利用規約とアカウントのリスクを確認したうえで行う必要があります。
- `discontinued` と記載されたエントリは、過去の記録として残されているものであり、現在無料であるかのように提示してはなりません。

## OmniRoute が無料枠をさらに有効活用する仕組み

### 1. 自動フォールバック

ある無料プロバイダーが混雑しているか停止している場合、OmniRoute は次のプロバイダーを自動的に試します。ユーザーが何か操作する必要はありません。

### 2. スマートルーティング

OmniRoute は、以下に基づいてリクエストごとに**最適な無料プロバイダー**を選択します。

- 速度 — 現在最も高速なプロバイダーはどれか？
- 品質 — このタスクに最適なプロバイダーはどれか？
- 容量 — クォータが残っているプロバイダーはどれか？

### 3. トークンの節約

OmniRoute の圧縮パイプラインは、圧縮対象となるプロンプトとツール出力のトークン数を削減できます。
実際の削減量は、コンテンツ、選択したエンジン、プロバイダーの計算方式、および忠実度の
設定によって異なります。圧縮によって各プロバイダーのクォータが一定の倍率で増えるわけではありません。

### 4. 複数アカウントのサポート

プロバイダーの規約で複数のアカウントまたは認証情報が許可されている場合、OmniRoute は各
接続を個別のルーティング候補として扱うことができます。プロバイダーのクォータやアクセスポリシーを
回避する目的で追加のアカウントを作成しないでください。

## 無料枠の計算

現在のライブ環境における、プール単位で重複排除されたカタログの報告値は次のとおりです。

| 指標                     |      現在の監査済みの値 | 解釈                                                          |
| ------------------------ | ----------------------: | ------------------------------------------------------------- |
| 定期的に付与される定量枠 | **約16.2億トークン/月** | 共有プールは1回のみ集計。上限なしのプロバイダーは合計から除外 |
| 登録時付与分を含む初月   |    **約22.2億トークン** | 定期付与分の合計に、1回限りおよび定期的なクレジットを加算     |

これらは、要件を満たす個別アカウント全体を対象としたカタログ規模の推定値であり、OmniRoute が提供する利用枠でも、新規インストール時の予測値でもありません。実際に利用可能な容量は、接続するプロバイダーとその時点の条件によって異なります。これらの値は `open-sse/config/freeModelCatalog.ts` から算出されています。プールの重複排除、利用規約フラグ、提供終了済みの項目、登録クレジットの算出方法については、
[無料枠リファレンス](../reference/FREE_TIERS.md)を参照してください。

## よくある質問

### 「本当に無料ですか？」

カタログには、プロバイダーが公開している条件とプロジェクトによる調査結果が記録されていますが、提供内容は変更される可能性があります。
利用前に、プロバイダーの現在の料金、クォータ、プライバシーポリシー、利用資格を確認してください。

### 「無料枠を使い切ることはありますか？」

どのプロバイダーも、レート制限の適用、モデルの変更、アクセスの停止、サービスの停止を行う可能性があります。複数の
接続を設定するとフォールバックの対象範囲は広がりますが、利用可能な無料ルートが保証されるわけではありません。

### 「無料プロバイダーを本番環境で使用できますか？」

プロバイダーのSLA、データ処理、制限、利用規約が本番環境の
要件を満たしている場合に限ります。重要なワークロードには、監視され、契約上の要件を満たす適切なフォールバックを用意する必要があります。

### 「何かデメリットはありますか？」

厳しい制限、待機リスト、KYC、クレジットカード認証、プロンプトを使用した学習、
プライバシー保護の弱さ、SLAの欠如、モデルの頻繁な入れ替え、地域制限、有料の超過利用、アカウントポリシー上のリスクなどのトレードオフが考えられます。
OmniRouteは利用可能なメタデータを提示し、何を有効にするかは利用者が選択します。

### 「無料クォータを増やすにはどうすればよいですか？」

1. より多くの無料プロバイダーに接続する
2. 適切な圧縮エンジンを有効にし、ワークロードに対する削減効果を測定する
3. `auto/cheap` を使用して無料または低価格のプロバイダーを優先する
4. プロバイダーの利用規約に違反しない範囲で、許可されている追加のプロバイダーまたは認証情報を追加する

### 「無料プロバイダーは品質が低いですか？」

必ずしもそうではありません。一部のプロバイダーでは、有料
ルートで利用できるものと同じモデルファミリーが提供されていますが、制限、レイテンシ、プライバシー、信頼性、モデルのバージョンが異なる場合があります。
品質の目安として無料プロバイダーランキングページを使用し、実際に提供されるモデルを確認してください。
