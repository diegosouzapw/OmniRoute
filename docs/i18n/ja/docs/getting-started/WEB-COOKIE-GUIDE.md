Web Cookie プロバイダーを使用すると、API キーの代わりに既存のブラウザーセッションを通じて、OmniRoute から AI サービスを利用できます。サービスの Web サイトを通じてすでにアクセス権があり、OmniRoute でも同じ認証済みセッションを使用したい場合に便利です。

API キープロバイダーとは異なり、Web Cookie プロバイダーは、ブラウザーが Web サイトに送信する認証情報を使用して認証します。

---

# はじめる前に

> **重要:** 認証情報は必ずブラウザーの Cookie ストレージからではなく、**実際のネットワークリクエスト**からコピーしてください。

認証に関する問題の多くは、誤った場所から Cookie をコピーすることによって発生します。

## Cookie ストレージからコピーしないでください

ほとんどのブラウザーでは、次の場所から保存済み Cookie を確認できます。

```
DevTools
→ Application（または Storage）
→ Cookies
```

これらの Cookie は正しいように見えても、次のような可能性があります。

- 古くなっている
- 不完全である
- 認証済みリクエストでのみ送信される Cookie が含まれていない

これらの値を使用すると、有効に見えても認証に失敗する場合があります。

## 実際のリクエストからコピーする

代わりに、成功したリクエストの Cookie を使用してください。

```
DevTools
→ Network
→ ページを更新
→ チャットまたは会話のリクエストを開く
→ Request Headers
→ Cookie
```

`Cookie` リクエストヘッダーには、ブラウザーが正常に使用した正確な認証情報が含まれています。

ほとんどの Web Cookie プロバイダーでは、この値を OmniRoute に貼り付けます。

---

# 一般的なセットアップ

セットアップ手順は、ほとんどの Web Cookie プロバイダーで共通です。

1. プロバイダーの Web サイトにサインインします。
2. ブラウザーの開発者ツールを開きます。
3. **Network** タブを開きます。
4. ページを更新します。
5. 認証済みのチャットまたは会話のリクエストを開きます。
6. 必要な認証情報をコピーします。
7. OmniRoute を開きます。
8. **Providers → Add Provider** に移動します。
9. 使用する Web Cookie プロバイダーを選択します。
10. 認証情報を貼り付けます。
11. **Test Connection** をクリックします。
12. プロバイダーを保存します。

必要となる正確な認証情報は、プロバイダーによって異なります。

Web サイトごとに認証情報の保存方法が異なります。Cookie のみを必要とするものもあれば、追加のヘッダーやトークンを必要とするものもあります。

| ChatGPT Web (Codex)             | Cookie ヘッダー全体           | `docs/providers/CHATGPT_WEB.md`  |
| Gemini Web                      | _（要確認）_                  |                                  |
| Copilot Web                     | _（要確認）_                  | `docs/providers/COPILOT-M365.md` |
| Microsoft 365 Copilot (BizChat) | WS access_token + chathubPath | `docs/providers/COPILOT-M365.md` |
| Grok Web                        | _（要確認）_                  |                                  |
| ...                             | ...                           | ...                              |

> 新しい Web Cookie プロバイダーが追加された場合、または既存のプロバイダーの認証要件が変更された場合は、この表を更新してください。

# Web Cookie プロバイダーでできることとできないこと

Web Cookie プロバイダーは、Web サイトのチャットインターフェイスを再利用します。公式 API と同じ機能を提供するものでは**ありません**。

## サポート対象

- 既存のブラウザーセッションを使用した認証
- アカウントで利用可能なモデルへのアクセス
- チャット応答のストリーミング
- API キー不要

## サポート対象外

- 関数呼び出し
- ツール呼び出し
- ファイルの自動編集
- エージェント型 IDE ワークフロー
- API 専用機能

これは想定された動作であり、**バグではありません**。

ツールの実行、ファイルの自動編集、またはその他のエージェントワークフローが必要な場合は、Web Cookie プロバイダーではなく**API キープロバイダー**を使用してください。

---

# 検証に関する注意事項

**Test Connection** または Cookie の検証に成功しても、指定された認証情報が想定された形式に見えることを確認するだけです。

Issue #7857 が解決されるまでは、検証に成功しても、プロバイダーでの認証が成功することは**保証されません**。

認証が引き続き失敗する場合は、ブラウザーの Cookie ストレージではなく、実際のネットワークリクエストから認証情報をコピーしたことを確認してください。

---

# トラブルシューティング

## 認証に失敗する

認証情報が次の場所からコピーされたことを確認してください。

```
Network
→ Request Headers
→ Cookie
```

次の場所からはコピー**しないでください**。

```
Application
→ Cookies
```

---

## ブラウザーでは Cookie が機能するが OmniRoute では機能しない

一部のプロバイダーには、認証済みリクエスト時にのみ送信される Cookie が含まれています。

会話を正常に開いた後、新しいネットワークリクエストから認証情報を再度コピーしてください。

---

## セッションの有効期限が切れた

Web Cookie プロバイダーは、既存のブラウザーセッションを使用します。

ブラウザーセッションの有効期限が切れた場合、またはサインアウトした場合は、新しい認証情報をコピーする必要があります。

---

## Test Connection は成功するがリクエストに失敗する

Issue #7857 が解決されるまでは、検証に合格しても認証リクエストが成功することは保証されません。

さらにトラブルシューティングを行う前に、新しい認証済みリクエストから認証情報を再度コピーしてください。

# ベストプラクティス

- 新しい認証済みリクエストから認証情報をコピーしてください。
- 古い Cookie の再利用は避けてください。
- Web Cookie プロバイダーを使用している間は、ブラウザーセッションを有効な状態に保ってください。
- コピーした Cookie は機密性の高い認証情報として扱ってください。
- 関数呼び出しまたはエージェントワークフローが必要な場合は、API キープロバイダーを使用してください。
