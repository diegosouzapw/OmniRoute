`chatgpt-web-codex`（エイリアス `cgpt-codex`）は、認証済みの ChatGPT ブラウザーセッションを介して Codex Responses のターンを中継します。これは廃止された共通の `chatgpt-web` プロバイダーとは独立しており、`open-sse/vendor/codex-chatgpt-web/` 配下の MIT 表示付き実装を使用しています。この実装は upstream v4.0.7 のコミット `b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494` まで更新されています。

## 共通プロバイダーの廃止

以前の共通プロバイダー ID `chatgpt-web` および `cgpt-web` は、pre-key／proof-of-work 実装の出所を確認できなかったため、提供されなくなりました。スラッシュで始まるモデル ID や保存済みエイリアスを含め、いずれかの ID を明示的に指定したリクエストは、upstream へのリクエストが行われる前に、HTTP `410` およびコード **PROVIDER_RETIRED** でフェイルクローズします。

マイグレーション `168_retire_chatgpt_web.sql` は、一致するプロバイダー接続を廃止済みとして記録し、それらのアクティブなセッションリースを無効化します。接続履歴と API キーの許可リストは保持されますが、代替アクセスが許可リストに追加されることはありません。Codex プロバイダーとその接続は、この廃止処理の対象にはなりません。

## 前提条件

- サインイン済みの ChatGPT セッションから取得した完全な Cookie ヘッダー
- npm、systemd、および PM2 でのインストールには、Chrome または Chromium と、グラフィカルセッションまたは Xvfb ディスプレイ
- Docker の `web` プロファイルでは、`docker-compose.yml` の内部 Chromium サービス
- ローカル Codex ツール用の OpenAI `tunnel-client` v0.0.13 と ChatGPT カスタムコネクター

トンネルが必要なのは、ツールを使用するターンのみです。`pro` を含む一覧のすべてのルートで、トンネルとコネクターが設定されていれば、同じターン限定のローカルツール機能を使用できます。

## ダッシュボードでのセットアップ

1. **ChatGPT Web (Codex)** プロバイダーを開き、接続を追加します。
2. 完全な ChatGPT Cookie ヘッダー、トンネル ID、ランタイムキー、およびカスタムコネクター名を貼り付けます。新しいツール対応セットアップでは、名前が正確に `OmniRoute Codex v2` で、Authentication が None、Permissions が Allow all actions に設定された新規作成のコネクターを使用する必要があります。
3. 接続チェックを実行します。OmniRoute はブラウザーベースの Temporary Chat を開き、そのアカウントで Sol と Pro が利用可能かどうかを検出します。
4. 接続を保存します。OmniRoute は貼り付けられた Cookie を、検証済みの Playwright ストレージ状態に置き換え、暗号化された認証情報抽象化を通じてランタイムキーとともに保存します。

正常に保存された後、未加工の Cookie は保持されません。セッションの有効期限が切れた場合は、接続を開いて新しい完全な Cookie ヘッダーを貼り付け、チェックを再実行してください。編集ダイアログの doctor ステータスでは、ブラウザー、ストレージ状態、サインイン、Temporary Chat、トンネル、コネクター、およびツールのラウンドトリップが個別に報告されます。

> 実際の Cookie、ランタイムキー、ストレージ状態、または capability token は絶対にコミットしないでください。テストおよびドキュメントの値には、常にプレースホルダーを使用する必要があります。

## モデルとコンボ

固定モデルルートは次のとおりです。

- `chatgpt-web-codex/luna` — GPT-5.6 Luna、低 effort
- `chatgpt-web-codex/think` — GPT-5.6 Luna、中 effort
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

他のモデルと同様に、これらのいずれかをコンボに追加します。Codex アプリは、通常の Responses エンドポイント `/v1/responses` にコンボ名を `model` として送信します。Codex 専用のエンドポイントやモード切り替えはありません。

Free／Go アカウントでは Luna ルートが公開されます。Sol 対応アカウントでは Instant から High までが公開され、Pro 対応アカウントではさらに Extra High と Pro が公開されます。各ルートには、固定のバックエンドモデルと推論 effort が設定されています。競合する明示的な Responses effort を指定すると、選択されたブラウザーモードが暗黙的に変更されるのではなく、フェイルクローズします。

以前の `Codex Native` または `OmniRoute Codex` コネクターの名前を変更したり、再利用したりしないでください。ChatGPT はコネクターの識別情報ごとに公開 MCP コントラクトをキャッシュしますが、更新されたブリッジでは新しい直接ターントークンコントラクトが使用されます。ランタイムはこれらのレガシーな識別情報を拒否し、新しい `OmniRoute Codex v2` コネクターを要求します。

## セキュリティモデル

- ネイティブパスには、Responses リクエスト、認識済みの Codex クライアント、および一致するスレッド ID とターン ID が必要です。
- ワークスペース、サンドボックス、承認ポリシー、ツールカタログは、ネイティブ Codex シェルから取得されます。自由形式のプロンプトテキストには、それらを決定する権限はありません。
- ChatGPT が受け取るのは、ターンごとに付与される有効期間の短いケイパビリティのみです。MCP ブローカーは、そのターンで Codex が提示したツールのみを受け入れます。
- **Allow once** を自動確認しても、ツールリクエストが Codex に返されるだけです。承認と実行を決定するのは Codex のみです。
- 最初の出力前であれば、コンボは別の互換性のあるターゲットにフォールバックする場合があります。出力の開始後は、ターンが完了するまで、プロバイダー、モデル、接続、ブラウザーターンが固定されます。
- Cookie、ランタイムキー、ストレージ状態、ケイパビリティトークンが、プロバイダーのレスポンスやリクエストログに現れることはありません。

## ディスプレイのない VPS と Docker

npm、systemd、PM2 によるインストールでは、OmniRoute が一般的な Chrome および Chromium のパスを検出します。代わりに、`CHATGPT_WEB_CODEX_CHROME_PATH` を設定することもできます。ChatGPT は完全なヘッドレスブラウザーの特性を拒否するため、ランタイムターンでは意図的にヘッド付き Chrome を使用します。そのため、ディスプレイのないホストでは、プライベートな Xvfb ディスプレイで OmniRoute を実行する必要があります。Chrome のパスを設定するだけでは、ディスプレイは提供されません。

Docker の `web` プロファイルは、内部 Compose ネットワーク上で `chatgpt-web-codex-browser` を起動します。サイドカーは Xvfb 内でヘッド付き Chrome を実行するため、物理ディスプレイは必要ありません。その CDP ポートはホストには公開されません。保護されたブラウザープロファイル用ボリュームは OmniRoute のデータボリュームとは分離されており、ブラウザーには十分な共有メモリが割り当てられます。内部 CDP プロキシは Compose ネットワーク内のポート `9223` でのみ待ち受け、Chrome はサイドカー内のループバックにバインドされたままです。

`DATA_DIR` 配下のスーパーバイザーリースにより、複数の OmniRoute プロセスが同じトンネルおよびブローカー状態を所有することを防ぎます。競合は doctor によって報告されます。

## 対話的な復旧

自動化された Docker パスにはホストから見えるウィンドウはありませんが、Chrome 自体はプライベートな Xvfb ディスプレイ内でヘッド付きモードで動作します。ChatGPT が対話的なサインインやチャレンジを要求した場合は、既存の VNC ブラウザー基盤を復旧に使用できます。ブラウザー UI と CDP は、ループバック、認証済みの管理接続、または SSH トンネルを介してのみ到達可能な状態にする必要があります。通常運用中、noVNC は無効のままです。

## WebSocket フォールバック

コンボに ChatGPT Web (Codex) が含まれている場合、Responses WebSocket ブリッジはアップストリームへの接続前に HTTP/SSE フォールバックを要求します。その後、転送は `/v1/responses` を経由します。
