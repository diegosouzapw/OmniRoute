このドキュメントは、
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854) に関する実装上の決定を記録するものです。公開製品は4つのプロバイダーファミリーとして表現されます。リージョンは接続データであり、個別の製品ではありません。

## 決定

| プロバイダーファミリー                 | OmniRoute ID            | グローバルリージョン | 中国リージョン |
| -------------------------------------- | ----------------------- | -------------------- | -------------- |
| Alibaba Cloud Model Studio（従量課金） | `alibaba`               | シンガポール         | 北京           |
| Alibaba Cloud Token Plan               | `bailian-coding-plan`   | シンガポール         | 北京           |
| Qwen Cloud（従量課金）                 | `qwen-cloud`            | グローバル           | 北京           |
| Qwen Cloud Token Plan                  | `qwen-cloud-token-plan` | シンガポール         | 北京           |

既存の `alibaba-cn` ID は、保存済みの接続、モデルルート、コンボ、および過去の使用履歴に対するランタイム互換性エイリアスとして維持されます。ダッシュボードカードは `alibaba` に統合され、データベースの書き換えは不要です。

Qwen Cloud の従量課金製品と Alibaba Cloud Model Studio は、現在 DashScope 互換のランタイムホストを共有していますが、ユーザーが異なる製品画面を通じてキーを取得し、アカウントを管理するため、別々のプロバイダーIDとして維持されます。Alibaba と Qwen Cloud の Token Plan 製品は異なるエンドポイントファミリーを使用するため、4つの製品はすべて別々のプロバイダーIDとして維持されます。

## エンドポイントマトリックス

| プロバイダーファミリー  | `global-sg`                                                              | `china-beijing`                                                      | ワイヤーフォーマット |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | -------------------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI               |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic            |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI               |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI               |

APIキーとエンドポイントは、同じ製品およびリージョンに属している必要があります。リージョンを選択すると、検証および通常のリクエストで使用されるプリセットエンドポイントが変更されます。

## 接続コントラクト

新しい接続では、安定したリージョンキーを `providerSpecificData` に保存します。

```json
{
  "region": "global-sg"
}
```

許可される値は `global-sg` と `china-beijing` です。エンドポイントは、プロバイダーIDとリージョンから一元的に導出されます。プリセットではない `providerSpecificData.baseUrl` は、引き続きオペレーターによる明示的なオーバーライドとして扱われ、優先されます。一方、古い保存済みプリセットURLはリージョンマトリックスに基づいて正規化されます。

これにより、接続スキーマの拡張性が維持されます。別のプロバイダーカードを作成したり、保存済みのプロバイダーIDを変更したりすることなく、リゾルバーに新しいリージョンを追加できます。

## 互換性とロールアウト

1. リージョナルエンドポイントリゾルバーを追加し、現在のグローバルデフォルトを維持します。
2. `alibaba`、その互換 ID である `alibaba-cn`、および `qwen-cloud` では、リージョナル DashScope `/models` のライブディスカバリーを使用します。汎用エンドポイントは画像、動画、音声、埋め込み、およびその他の非チャットモデルも返すため、これらのレスポンスには最初にテキスト生成用フィルターを1つ適用します。その後、`qwen-cloud` ではプロバイダーレジストリで宣言された管理対象の許可リストを適用します。Alibaba Model Studio と Qwen Cloud は現在ランタイムホストを共有していますが、それぞれ個別に管理されたカタログを維持します。
3. 現在の Token Plan テキストモデル許可リストを使用して `qwen-cloud-token-plan` を登録します。
4. 接続の追加・編集ダイアログに、型付きリージョンセレクターを追加します。
5. 重複している `alibaba-cn` カードを非表示にし、その既存の接続を `alibaba` プロバイダーページに含めます。
6. 高度なデプロイメントやワークスペース固有のデプロイメント向けに、カスタムエンドポイントのオーバーライドを引き続き利用可能にします。

Token Plan のメディアモデルは専用エンドポイントを使用するため、チャットカタログには含まれません。
`wan2.7-image` と `wan2.7-image-pro` は `open-sse/config/imageRegistry.ts` に登録されています。
`happyhorse-1.1-i2v`、`happyhorse-1.1-t2v`、`happyhorse-1.1-r2v` は
`open-sse/config/videoRegistry.ts` に登録されています。どちらのレジストリも
`qwen-cloud-token-plan` の接続 ID とそのリージョン固有の認証情報を再利用します。

通常の Qwen Cloud には、`qwen-cloud` ID 配下に従量課金制の画像カタログと動画カタログが別々にあります。画像モデルは `wan2.7-image-pro`、`wan2.7-image`、`qwen-image-3.0-pro`、
`qwen-image-2.0-pro-2026-06-22`、`qwen-image-2.0-2026-03-03`、`z-image-turbo` です。動画モデルは `happyhorse-1.1-i2v`、`happyhorse-1.1-t2v`、`happyhorse-1.1-r2v`、
`happyhorse-1.0-video-edit`、`wan2.7-t2v`、`wan2.7-i2v`、`wan2.7-r2v-2026-06-12`、
`wan2.7-videoedit` です。これらのモデルは、通常の `qwen-cloud` 接続とリージョナル DashScope メディアエンドポイントのみを再利用します。Token Plan と従量課金制のレジストリは、互いのモデルリストを継承もマージもしません。

`bailian-coding-plan` ID にも独自のメディア許可リストがあります。画像生成用には
`wan2.7-image`、`wan2.7-image-pro`、`qwen-image-2.0`、`qwen-image-2.0-pro`、
動画生成用には
`happyhorse-1.1-i2v`、`happyhorse-1.1-t2v`、`happyhorse-1.1-r2v` が含まれます。
この ID は Bailian Coding Plan 接続とリージョナル Coding Plan エンドポイントのみを使用します。
その画像レジストリと動画レジストリは、いずれの Qwen Cloud プロバイダーからも継承せず、マージもしません。

通常の `alibaba` ID には、画像と動画の許可リストが別々にあります。画像モデルは
`qwen-image-3.0-pro`、`qwen-image-2.0-pro-2026-06-22`、`qwen-image-2.0`、
`z-image-turbo`、`wan2.6-t2i` です。追加される動画モデルは `happyhorse-1.1-i2v`、
`happyhorse-1.1-t2v`、`happyhorse-1.1-r2v`、`happyhorse-1.0-video-edit`、
`wan2.7-i2v-2026-04-25`、`wan2.6-i2v-flash`、`wan2.7-t2v-2026-06-12`、
`wan2.7-r2v-2026-06-12`、`wan2.7-videoedit` です。これらのモデルは Alibaba Model Studio 接続と、そこで選択されたリージョナルメディアエンドポイントのみを使用します。Coding Plan または Qwen Cloud のレジストリには追加されません。

Qwen Cloud Token Plan のチャットカタログは、Individual プランの完全一致テキスト許可リストに従います。
`qwen3.8-max-preview`、`qwen3.7-max`、`qwen3.7-plus`、`qwen3.6-flash`、`glm-5.2`、
`deepseek-v4-pro` です。Wan と HappyHorse のエントリは、個別の画像・動画生成 API に属します。

Alibaba Token Plan は、Anthropic 互換エンドポイントを通じて、同じ6つの現行テキスト生成モデル ID を公開します。シンガポールオプションには既存の `global-sg` リージョンキーが保存されます。リージョンを Global と呼ぶ他のプロバイダーファミリーとは、ユーザー向けラベルのみが異なります。

通常の Qwen Cloud チャットカタログは、ライブのテキストレスポンス全体よりも意図的に範囲を狭めています。管理対象の許可リストは `open-sse/config/providers/registry/qwen-cloud/index.ts` にあります。ライブディスカバリーは、アップストリームレスポンスとそのレジストリリストの両方に存在する ID のみを返します。

Alibaba Model Studio も同じライブ交差ルールに従い、`open-sse/config/providers/registry/alibaba/index.ts` にある独立管理の許可リストを使用します。`alibaba-cn` 互換プロバイダーは、北京エンドポイントに対してディスカバリーを解決しつつ、そのカタログを再利用します。
