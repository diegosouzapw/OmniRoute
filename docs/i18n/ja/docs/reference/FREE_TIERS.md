## 要約 — OmniRoute は実際にどれだけの無料推論枠を集約しているのか？

| 指標                                         | トークン数 / 月 | 意味                                                                                                                                                                                                                                                                                                                       |
| -------------------------------------------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **文書化された継続付与枠（定常時）**         | **約 1.62B**    | 無料枠の**プール**（モデルごとのカタログ）。共有プールはそれぞれ**一度だけ**計上されます。`/api/free-tier/summary` およびダッシュボードの無料枠予算ページが参照するライブソースです。**この数値を使用してください。**                                                                                                      |
| **+ 登録クレジットを含む初月**               | **約 2.22B**    | 定常枠 + 1 回限りの登録クレジット（Z.AI 20M、DeepSeek 5M、…）。アカウント単位で重複排除済みです。**初月のみ**で、繰り返し付与されるものではありません。                                                                                                                                                                    |
| **+ 恒久的に無料、公開上限なし**             | _定量化不可_    | `siliconflow`、`glm-cn`（GLM-4-Flash）、`tencent`、`baidu`、`kilo-gateway`、`opencode-zen`、`gemini`、`ollama-cloud` — 実際に継続利用でき、レートまたは同時実行数の制限はありますが、**計上可能なトークン上限はありません**。一覧には含めますが、合計には含めません（`RPM×24/7` として計上するような水増しは行いません）。 |
| **+ 入金による解除ブースト**                 | **+約 24M**     | OpenRouter に 1 回限りで **$10** をチャージすると、無料プールが 50 → 1000 リクエスト/日に増加します。定常時の数値を水増ししないよう、別途記載しています。                                                                                                                                                                  |

## 2つのレジーム — 集計と判定

OmniRouteは「無料か？」という問いに対し、意図的に異なる情報源を参照する2つのレジームで回答します：

| レジーム        | 正式な情報源                                                                                                                                                                  | 適用対象                                                                                                                                     |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **集計 / 表示** | 解決済みカタログ — 配布時のベースラインにRadarフィード（`getRadarCatalog`）を重ねたもの                                                                                       | 無料枠の合計、予算カード、ダッシュボード                                                                                                     |
| **判定**        | 配布時のカタログのみ（`open-sse/config/freeModelCatalog.data.ts`内の`FREE_MODEL_BUDGETS`）とローカルヒューリスティクス（`:free`サフィックス、価格がゼロ、`grantsFreeAccess`） | `src/shared/utils/freeModels.ts`を利用するすべての機能：モデルのインポート、`auto/*`ルーティング、`GET /v1/models`、およびブラウザプレビュー |

フィードが利用可能であれば、集計はいつでも改善できます。一方、判定は
リリース成果物に固定されるため、ブラウザとサーバーで回答が同一になり、
オフラインで再現でき、データベースなしでテストできます。ブラウザの
プレビューがある情報源を参照し、サーバーのインポートが別の情報源を参照すると、
プレビューとクリック時の実際の動作が一致しなくなります。そのため、この分離は
意図的に維持されています。

## 方法論と注意事項

- 数値は、ウェブ調査で収集した、**2026-06-17** 時点における各プロバイダーの文書化された無料枠上限に基づく**上限推定値**です。無料枠は頻繁に変更されるため、数値を前提として利用する前に再確認してください。
- **各エントリが実際に保証する内容。** 行ごとの信頼度評価が付与されたエントリはなく、API からも提供されません。上記のすべての数値は、明示されていない同一水準の品質による推定値として扱ってください。ただし、推論ではなく手作業で精査されているため、次の 2 つの事実は異なります。44 件のエントリには、独立して文書化されたハードストップがあり（そのうち 39 件は xKiro の行で、すべて同一の日次割当量を共有しています）、13 件のエントリには、プロンプトの学習利用に関する開示があります。`hardStopGuaranteed` は、無料割当量を超過すると暗黙に課金が開始されるのではなく、リクエストが拒否されるとプロバイダー自身の利用規約に明記されている場合にのみ設定され、その出典はエントリの横のコメントに記載されます。デフォルトで `true` に設定されることはなく、誰も検証していないエントリでは未設定のままです。したがって、ハードストップフラグがないことは「確認されていない」ことを意味し、「課金されることが判明している」という意味ではありません。**STRICT モード**（オプトインの `freeAccessPolicy=strict` ルーティングガード）は、このフラグが付いたエントリのみを信頼します。それ以外の無料枠はすべて `no-hard-stop` として除外されます（`open-sse/services/autoCombo/strictZeroCostFilter.ts` を参照）。ガードがプールをフィルタリングすると、オペレーター向けログには除外数と、そのうち `no-hard-stop` が占める割合の両方が記録されます。
- `estMonthlyFreeTokens` = 毎月繰り返し付与されるトークンのみ。**登録時に一度だけ付与されるクレジットは継続しない**ため、0 として数えます。廃止された無料枠も 0 です。
- 日次トークン上限 → `monthly = daily × 30`。RPD のみが文書化されている場合 → `RPD × 約 800 出力トークン × 30`。RPM/TPM のみ（日次上限なし）の場合 → **上限なし**（以下を参照）。
- **恒久的に無料だが、公開されたトークン上限がないもの**（`siliconflow`、`glm-cn`、`tencent`、`baidu`、`kilo-gateway`、`opencode-zen`、`gemini`、`ollama-cloud`）：これらは実際に継続利用できる無料アクセスであり、レートまたは同時実行数の制限があります。これらは `recurring-uncapped` に分類し、**合計には決して含めません**。`RPM × 24/7 × 30d` を計算すると、非現実的な上限値になってしまうためです（当方が排除している水増しです）。これらの選択肢が存在することを示すため、一覧には掲載しています。
- **入金によるアンロック増量：** 少額を一度だけ追加購入することで、無料クォータが恒久的に増加するものです（OpenRouter：$10 → 1000 リクエスト/日 ≈ +24M/月）。通常時の主要数値には含めず、別の数値として報告します。
- **利用資格で制限されるクォータ**（`eligibilityGate: "regional-identity"`）：地域に紐づく本人確認（現時点では中国本土の実名認証）を完了した場合にのみ利用可能になる、実在する継続的クォータです。同一のプール重複排除ルールで集計して別の数値（`gatedRecurringTokens`）とし、通常時の主要数値には決して含めません。区分（`freeType`）は変わらないため、ルーティングも変わりません。
- **エビデンス区分。** ルール：カタログ内の数値は、そのエントリの横にある `// evidence:` コメントで出典を示します。区分は、`public-page`（誰でも閲覧できるプロバイダーのページ）、`api-public`（プロバイダーの未認証エンドポイント。例：router.bynara.id にある NaraRouter の公開プランエンドポイント）、または `console-verified <date> por <who>`（数値がアカウントコンソール内でのみ確認できる場合。コメントには誰がいつ確認したかと、上限の存在を示す公開ページを記録）です。現状では、2026-09-02 に再監査された 5 つのブロック（`gemini`、`groq`、`mistral`、`ollama-cloud`、`nara`）にこのコメントが付いています。2026-09-02 の再監査より前から存在するエントリは、更新されるまで以前の調査結果を引き継ぎます。エビデンスコメントのない**新規または変更された**数値はバグです。現時点でコンソール確認済みなのは `mistral` のみです。

## 当社の数値が他のアグリゲーターより小さい理由

この分野で示される「1 か月あたりの無料トークン」の数値の多くは、モデルごとに表示された値を合計したものです。当社では意図的にそうしていません。

- **各共有プールは一度だけ数えます。** Mistral の無料プランは、組織ごとに月間 1B の割り当てが 1 つです。5 つのモデルに分けて掲載しても 5B にはなりません。モデルごとに合計すると、当社自身のカタログでも **~7.4B** になります（2026-09-03 に再計算。この数値は CI による検証対象ではありません。カタログが変更されるたびに再計測してください）が、見出しでは **~1.47B** としています。これは、各プロバイダーで 1 つずつアカウントを使用した場合に実際に消費できる量だからです。
- **日次上限は換算しますが、レート制限は換算しません。** 文書化された 1 日あたりのトークン上限は `× 30`、文書化された 1 日あたりのリクエスト上限は `RPD × ~800 tokens × 30` として換算します。1 分あたりのリクエスト数しか公開していないプロバイダーには月間数値を設定せず、_上限なし_ と記載し、合計には含めません。レート制限を 24 時間 365 日で乗算するような水増しは行いません。
- **地域別の本人確認が必要なクォータは別に表示します**（`+~6M behind regional identity verification`）。ほとんどの読者が利用できないためです。
- **サインアップクレジットは初月のみ**であり、定常的な数値には混ぜず、2 つ目の数値として報告します。
- **この数値は CI によって検証されます。** `npm run check:docs-counts` はカタログから合計を再計算し、このファイル、README、または予算カードの数値にずれがある場合はビルドを失敗させます。

## 用語集

| 用語                     | 意味                                                                                      |
| ------------------------ | ----------------------------------------------------------------------------------------- |
| **RPM / RPD / RPH**      | 1分あたり / 1日あたり / 1時間あたりのリクエスト数                                         |
| **TPM / TPD**            | 1分あたり / 1日あたりのトークン数                                                         |
| **文書化された割り当て** | プロバイダーが明示的な1日 / 1か月あたりのトークン上限を公開しているもの（根拠のある予算） |
| **理論上の上限**         | `レート制限 × 24時間/日 × 30日` — 付与された予算ではなく、最大値                          |
| **Neuron**               | Cloudflareのコンピューティング単位（約1出力トークン）                                     |

> 2026-06-05に実施したプロバイダーごとの調査に基づいて生成されています。更新するには、調査ワークフロー（`_tasks/features-v3.8.12`を参照）を再実行してください。
