> **ソース:** `src/lib/{a2a,acp,cloudAgent}/`, `src/app/api/{a2a,acp,cloud}/`, `src/app/api/v1/agents/`
> **最終更新:** 2026-06-28 — v3.8.40

OmniRoute は、エージェントに関連する3つの異なるインターフェースを提供します。一見似ていますが、それぞれ異なる問題を解決します。このページを参考に、適切なものを選択してください。

## 要約

| インターフェース                     | 最適な用途                                                                                                                                   | トランスポート                      | 標準                     |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- | ------------------------ |
| **A2A — エージェント間連携**         | A2A プロトコルに対応するピアエージェントとの、エージェントをまたぐコラボレーション                                                           | HTTP 上の JSON-RPC 2.0              | A2A v0.3（オープン仕様） |
| **ACP — CLI エージェントレジストリ** | ユーザーのマシンにインストールされている CLI コーディングエージェント（Cursor、Cline、Codex CLI、Claude Code、Aider など）の検出、登録、起動 | HTTP REST                           | OmniRoute 固有           |
| **クラウドエージェント**             | 外部クラウドサービス（Codex Cloud、Devin、Jules、Cursor Cloud）への長時間実行されるコーディングタスクの送信                                  | HTTP REST + DB バックエンドのタスク | OmniRoute 固有           |

これら3つは独立しています。必要なものを自由に組み合わせて選択してください。

## 判断フロー

```
このマシンの外部にあるクラウドサービス（Codex Cloud / Cursor Cloud / Devin / Jules）に作業を依頼する必要がありますか？
├─ はい → クラウドエージェント（POST /api/v1/agents/tasks）
└─ いいえ → 続行
    │
    A2A に対応し、連携を希望するピアエージェントがありますか？
    ├─ はい → A2A（POST /a2a）
    └─ いいえ → 続行
        │
        ローカルにインストールされている CLI コーディングエージェントを一覧表示または設定する必要がありますか？
        ├─ はい → ACP（GET /api/acp/agents）
        └─ いいえ → 通常の /v1/chat/completions を使用
```

## 1. A2A — エージェント間連携

**仕様:** [A2A v0.3](https://a2a-protocol.org)
**OmniRoute エンドポイント:** `POST /a2a`（JSON-RPC 2.0）
**エージェントカード:** `GET /.well-known/agent.json`

### 使用する場面

- OmniRoute がピアの1つとなるマルチエージェントシステムを構築する場合
- OmniRoute のルーティング機能（スマートルーティング、クォータ管理など）を、Google ADK のようなフレームワークや汎用エージェントメッシュ内のエージェントに公開する場合
- OmniRoute を標準の検出および呼び出しインターフェースでラップする場合

### メソッド

- `message/send` — メッセージを送信し、同期レスポンスを受信
- `message/stream` — メッセージを送信し、SSE ストリーミングによる進捗イベントを受信
- `tasks/get` — ID を指定してタスクを取得
- `tasks/cancel` — 実行中のタスクをキャンセル

### 組み込みスキル（6種類）

- `smart-routing` — 最適な組み合わせを通じてプロンプトをルーティング
- `quota-management` — プロバイダーごとのクォータ状態を報告
- `provider-discovery` — インストール済みプロバイダーとその機能を一覧表示
- `cost-analysis` — リクエストまたは会話のコストを見積もり
- `health-report` — プロバイダーごとのブレーカー、クールダウン、ロックアウト状態を集約
- `list-capabilities` — エージェントで利用可能なスキルとメタデータを列挙

### 詳細

トランスポートの詳細、エージェントカードの構造、タスクの TTL 設定、新しいスキルを追加するためのテンプレートについては、[A2A-SERVER.md](./A2A-SERVER.md)を参照してください。

## 2. ACP — CLI エージェントレジストリ

**OmniRoute エンドポイント:** `GET /api/acp/agents`
**ソース:** `src/lib/acp/{index,manager,registry}.ts`

### 概要

ACP は OmniRoute の**ローカル CLI エージェントインベントリ**です。ホストにインストールされているコーディング CLI（Cursor、Cline、Claude Code、Codex CLI、Continue など）を検出し、それぞれのバージョンを特定してダッシュボードに表示します。これにより、ユーザーは各 CLI の接続先を OmniRoute に設定できます。

これは外部プロトコルではありません。「CLI Tools」UI と CLI フィンガープリント追跡を支える内部レジストリです（[CLI-TOOLS.md](../reference/CLI-TOOLS.md) を参照）。

### 機能

- インストール済みの CLI バイナリをホスト上で探索します（OS に応じて `which` / `where` を使用）
- 各 CLI のバージョンを取得します（`<bin> --version` を呼び出します）
- 必要に応じて、ユーザー定義のカスタムエージェント（バイナリパス + バージョン確認コマンド + 起動引数）を受け付けます
- カスタムエージェントを設定に永続化します
- 統合された一覧をダッシュボードに返します

### REST API

| エンドポイント    | メソッド | 説明                                                                        | 認証     |
| ----------------- | -------- | --------------------------------------------------------------------------- | -------- |
| `/api/acp/agents` | GET      | 検出済みエージェントとカスタムエージェントの一覧（インストール済み数/総数） | API キー |
| `/api/acp/agents` | POST     | カスタムエージェントの追加/更新/削除（body 内のアクション識別子）           | API キー |

POST の body 形式（`src/app/api/acp/agents/route.ts` の `customAgentBodySchema`）:

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### ユースケース

- ダッシュボードの「CLI Tools」ページにインストール済みのツールを一覧表示し、それぞれの接続先を OmniRoute に設定できるようにします
- カスタムエージェントにより、上級ユーザーは OmniRoute がデフォルトでは認識しない社内用/プロプライエタリな CLI を登録できます
- 検出結果は `cli-tools` フィンガープリントマトリクスに使用されます

### ACP を使用すべきでない場合

- ACP はタスクを_実行_しません。CLI の検出と設定のみを行います。CLI を実際に呼び出すには、OmniRoute が提供する環境変数（`OPENAI_BASE_URL`、`OPENAI_API_KEY` など）を使用して、ユーザー自身で起動します。

## 3. クラウドエージェント

**OmniRoute エンドポイント:** `/api/v1/agents/tasks/*`（ライフサイクル）+ `/api/cloud/*`（基盤処理）
**ソース:** `src/lib/cloudAgent/`

### 概要

サードパーティ製クラウドコーディングエージェントに対する統一インターフェースです。プロンプトとリポジトリ URL を送信すると、OmniRoute が適切なクラウドエージェントに処理を割り当て、ステータスをポーリングし、結果を返します。

### サポート対象エージェント（4、すべて `src/lib/cloudAgent/agents/` で確認済み）

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### ライフサイクル

```
POST /api/v1/agents/tasks
  → エージェントクラスごとに BaseAgent.createTask()
  → 外部サービスが処理を開始
  → DB にタスク行を作成（cloud_agent_tasks）
  ↓
GET /api/v1/agents/tasks/[id]
  → プロバイダーから遅延ステータス同期
  → 現在のステータス + 計画 + アクティビティログを返す
  ↓
POST /api/v1/agents/tasks/[id]   （action: "approve" | "message" | "cancel"）
  → プロバイダーに転送（またはローカルでキャンセル済みとして記録）
  ↓
DELETE /api/v1/agents/tasks/[id]
  → ローカルキャンセル
```

### 認証

⚠️ **すべての `/api/v1/agents/tasks/*` エンドポイントには管理認証が必要です**（コミット `588a0333`）。v3.8.0 以降、Bearer のみを使用する呼び出し元には 401 が返されます。

### 詳細

`CloudAgentBase` のコントラクト、エージェントごとの詳細、スキーマの詳細、および認証情報に関する基盤エンドポイントについては、[CLOUD_AGENT.md](./CLOUD_AGENT.md) を参照してください。

## 比較: A2A と Cloud Agents

どちらも「長時間実行タスク」を扱いますが、異なるレイヤーで動作します。

| 観点                         | A2A                                                                              | Cloud Agents                             |
| ---------------------------- | -------------------------------------------------------------------------------- | ---------------------------------------- |
| 標準                         | Open A2A v0.3                                                                    | OmniRoute 固有                           |
| コンピューティングの実行場所 | OmniRoute 内部（設定済みの組み合わせを使用）                                     | 外部（Codex / Devin / Jules のサーバー） |
| タスクの所要時間             | デフォルト TTL は 5 分（`TaskManager` で設定可能）                               | 数分から数時間                           |
| リポジトリ対応               | なし（プロンプトのみを渡す）                                                     | あり（リポジトリ URL + ブランチ）        |
| ユースケース                 | エージェント間連携、サービスとしてのスマートルーティング                         | 「リポジトリ Y に機能 X を実装」を委任   |
| 認証                         | `/a2a` では `OMNIROUTE_API_KEY` は任意。`/api/a2a/*` REST ヘルパーでは管理者認証 | 常に管理者認証が必要                     |

## 統合例

### OmniRoute の A2A 機能を検出する

```bash
curl http://localhost:20128/.well-known/agent.json
```

6 つのスキル、トランスポート、バージョンをすべて含む Agent Card を返します。

### OmniRoute を A2A エージェントとして呼び出す

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### ACP 経由でインストール済みの CLI エージェントを一覧表示する

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### カスタム CLI エージェントを追加する

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### Cloud Agent タスクを送信する

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### クラウドタスクのステータスをポーリングする

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## 用途別の使い分け

- **チャットボット / コパイロットのフロントエンド** → `/v1/chat/completions`（OpenAI 互換 — エージェントプロトコルではない）
- **マルチエージェント連携** → A2A
- **ダッシュボードでのローカル CLI の一覧表示** → ACP
- **長時間実行されるコーディングタスクのクラウドサービスへの委任** → Cloud Agents

```
                ┌─────────────────────┐
                │   OmniRoute コア    │
                └─────────────────────┘
                  ↑       ↑        ↑
        ┌─────────┘       │        └─────────┐
        │                 │                  │
    ┌───────┐        ┌─────────┐       ┌────────────┐

   外部ピア            CLIバイナリ               ↓
   エージェント                           Codex Cloud、Cursor、
                                          Devin、Jules
```
