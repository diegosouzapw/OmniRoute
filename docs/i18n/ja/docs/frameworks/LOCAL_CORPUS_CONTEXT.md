> **信頼できる唯一の情報源:** `src/lib/localCorpus/index.ts`（上限付きテキストインデックス）、
> `src/lib/localCorpus/configured.ts`（構成済みランタイム）、
> `src/lib/db/localCorpus.ts`（ルートパスの永続化）、
> `open-sse/mcp-server/tools/localCorpusTools.ts`（3 つの読み取り専用 MCP ツール）、および
> `src/app/api/settings/local-corpus/route.ts`（設定 API）。

## 概要

Local Corpus を使用すると、オペレーターは、明示的に承認された 1 つのテキストファイル用ディレクトリを OmniRoute の MCP サーバーに公開できます。ファイルは元のディレクトリに保持されます。OmniRoute は正規化されたルートパスのみを SQLite に保存し、インメモリ検索インデックスを維持します。コーパスの内容をリポジトリやデータベースにコピーすることはありません。

インデックスの更新は差分方式です。変更されていないファイルはサイズと更新日時に基づいて再利用され、変更されたファイルは再読み込みされて SHA-256 でハッシュ化され、削除されたファイルはインデックスから除去されます。検索時には、30 秒以上経過したインデックスが更新されます。呼び出し側から即時更新を要求することもできます。

## ソースの構成

設定ルートには、他の設定 API と同じ管理認証が必要です。送信するパスは、既に存在する絶対ディレクトリパスである必要があります。

```bash
# 承認済みディレクトリを接続
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# 構成とインデックスの状態を確認
curl http://localhost:20128/api/settings/local-corpus

# ソースファイルを変更せずに接続を解除
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## MCP ツール

3 つのツールすべてに `read:local-corpus` が必要です。ツールのレスポンスには相対パスとルートディレクトリのベース名のみが含まれ、絶対パスが含まれることはありません。

| ツール                | 説明                                                                                     |
| :-------------------- | :--------------------------------------------------------------------------------------- |
| `local_corpus_status` | 構成状態、インデックスサイズ、上限、および最終更新日時を報告します                       |
| `local_corpus_search` | インデックス化されたテキストを検索し、行単位の上限付きスニペットを返します（最大 20 件） |
| `local_corpus_read`   | 許可されたコーパス相対ファイルから、上限付きの行範囲を読み取ります                       |

MCP 入力の例:

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## 安全性の境界

- 許可リストはテキスト形式を対象としており、`.cfg`、`.csv`、`.geojson`、`.htm`、`.html`、`.ini`、
  `.js`、`.json`、`.jsonl`、`.jsx`、`.log`、`.md`、`.mjs`、`.ps1`、`.py`、`.sh`、
  `.sql`、`.toml`、`.ts`、`.tsx`、`.txt`、`.xml`、`.yaml`、`.yml` が含まれます。
- シンボリックリンクはスキップされます。読み取りパスは正規化され、構成済みルート内に収まっている必要があります。絶対パスおよびディレクトリトラバーサルの試行は拒否されます。
- 機密性の高いディレクトリ名および生成されたディレクトリ名は除外されます: `.build`、`.codex`、`.env`、
  `.git`、`.next`、`.omniroute`、`.ssh`、`coverage`、`dist`、`node_modules`、および
  `secrets`。
- デフォルトの上限は、ファイル数 5,000、ファイルあたり 1 MiB、インデックス化するコンテンツの合計 64 MiB、
  検索チャンクあたり約 4,000 文字、読み取りあたり 400 行です。
- NUL を含むファイルは非テキストとして扱われ、スキップまたは拒否されます。

PDF、DOCX、画像、アーカイブなどのバイナリドキュメントは、意図的にサポートされていません。インデックス化する前に、構成済みディレクトリ内で許可されたテキスト形式に変換してください。

## 運用上の注意事項

- 構成済みルートを変更または削除すると、共有インメモリインデックスがクリアされます。
- プロセスを再起動するとインデックスは破棄されます。次回の検索時に、構成済みソースから再構築されます。
- `local_corpus_status` はスキャンを強制しません。即時再スキャンが必要な場合は、`refresh: true` を指定して `local_corpus_search` を使用してください。
- スキャンおよび読み取りの失敗は、件数として記録されるか、機密情報を除去したエラーとして返されます。ソースファイルが変更されることはありません。
