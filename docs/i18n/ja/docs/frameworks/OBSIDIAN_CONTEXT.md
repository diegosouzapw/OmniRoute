> （22 個の MCP ツール）、`src/app/api/settings/obsidian/route.ts` +
> `src/app/api/settings/obsidian/webdav/route.ts`（設定 API）。ツールの登録と
> スコープの配線は `open-sse/mcp-server/server.ts` にあります。

## 概要

OmniRoute は、**Obsidian** Vault を**コンテキストソース**として接続します。これは、
エージェントが組み込みの MCP サーバーを通じて読み書きするローカルの Markdown
ナレッジベースです。この連携は、デスクトップアプリ内で動作するコミュニティプラグイン
**Obsidian Local REST API** と通信します。これにより、エージェントはノートの検索、
ファイルの読み書きやパッチ適用、Vault の一覧表示、日次・週次の定期ノートの操作、
タグの管理、Obsidian コマンドの実行、および（任意で）デスクトップ↔モバイル間の
双方向 Vault 同期の調整を行えます。

クライアント（`src/lib/obsidian/api.ts`）は、Local REST API を次の機能でラップしています。

- 一時的な `5xx` に対する**バックオフ付きリトライ**と、`AbortController` による
  **30 秒のタイムアウト**。
- **型付きエラー分類** — `ObsidianAuthError`（401/403）、
  `ObsidianNotFoundError`（404）、`ObsidianServerError`（5xx）、`ObsidianTimeoutError`。
- よくあるポートの間違い（`27124` の MCP エンドポイントでは**なく**、
  `27123` の HTTP を使用）と Tailscale 形式を案内する、わかりやすい
  **「Obsidian に接続できない」ヒント**。
- スペースやスラッシュを含むノートパスを安全に扱うための、Vault 相対の
  **パスエンコーディング**。

## セットアップ

Obsidian のトークンまたはベース URL 用の**環境変数はありません**。どちらも
`src/lib/db/obsidian.ts` を介して SQLite の `key_value` テーブル（名前空間
`obsidian`）に保存されます。トークンは**保存時に暗号化**されます
（AES-256-GCM、平文との後方互換フォールバックあり）。Endpoint ダッシュボードの
**Context Sources** タブ（`ObsidianSourceCard`）から、または設定 REST API を介して
構成してください。

> [!IMPORTANT]
> **Obsidian Local REST API** プラグインがインストールされ、実行中である必要があります。
> その REST インターフェースは **HTTP `127.0.0.1:27123`**（デフォルトのベース URL）で
> 待ち受けます。ポート `27124` は_別の_ MCP/HTTPS エンドポイントであり、設定ルートでは
> 明示的に拒否されます。別のデバイスから接続する場合は、
> `http://<tailscale-ip>:27123` を使用してください。

### 構成キー（SQLite `key_value`、名前空間 `obsidian`）

| キー              | 用途                                                   | 暗号化 |
| ----------------- | ------------------------------------------------------ | ------ |
| `api_key`         | Local REST API の Bearer トークン                      | はい   |
| `base_url`        | REST ベース URL（デフォルト `http://127.0.0.1:27123`） | いいえ |
| `vault_path`      | Vault ディレクトリの絶対パス（同期用）                 | いいえ |
| `webdav_username` | 生成された WebDAV ユーザー名（Vault 同期）             | いいえ |
| `webdav_password` | 生成された WebDAV パスワード（Vault 同期）             | はい   |
| `webdav_enabled`  | WebDAV Vault 同期が有効かどうか                        | いいえ |

### REST 経由で構成

```bash
# Local REST API トークンを保存して検証（POST はステータスチェックによって検証）
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# 接続ステータスを確認（connected、hasToken、baseUrl、vaultPath を返す）
curl http://localhost:20128/api/settings/obsidian

# 切断（保存されているトークンを消去）
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

すべてのメソッドでダッシュボード認証が必要です。`POST` は、ポート `27124` を使用する
すべての URL を拒否し、保存する前に Local REST API のステータスエンドポイントを
呼び出してトークンを検証します。

### WebDAV Vault 同期

`src/app/api/settings/obsidian/webdav/route.ts` は、オプションの WebDAV ベースの
Vault 同期（`src/lib/obsidianSync.ts` によって駆動）を管理します。有効にすると、
OmniRoute がローカルの Vault ディレクトリを参照するよう設定され、ランダムな
WebDAV ユーザー名とパスワードの組み合わせが生成されます。

```bash
# Vault ディレクトリの WebDAV 同期を有効化（ユーザー名とパスワードを生成）
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# WebDAV 同期ステータスを取得（認証情報は有効な間のみ返される）
curl http://localhost:20128/api/settings/obsidian/webdav

# WebDAV 同期を無効化（認証情報と管理対象の .stignore を消去）
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### API キーごとのコンテキストソース（任意）

Obsidian の構成は、`api_key_context_sources` テーブル
（`src/lib/db/apiKeyContextSources.ts`）を介して**API キーごと**にスコープ設定できます。
MCP 呼び出しに認証済み API キー ID が含まれる場合、`getObsidianConfigForApiKey()` は
そのキー固有のトークン、ベース URL、Vault パス（`source: "api_key"`）を優先し、
存在しない場合はグローバル構成（`source: "global"`）にフォールバックします。

## MCP ツール（22）

`open-sse/mcp-server/tools/obsidianTools.ts` で定義されています。トークン／ベース URL は呼び出しごとに解決されます（API キー単位の設定が優先され、その後グローバル設定が使用されます）。OmniRoute **同期サーバー**を利用するツール（4 つの `obsidian_sync_*` ツール）には、追加で OmniRoute の設定に構成された同期認証トークンが必要です。

### 読み取りツール（`read:obsidian`）

| ツール                       | 説明                                                                                                           |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Local REST API に到達でき、認証済みかどうかを確認します。                                                      |
| `obsidian_search_simple`     | ノート内容を全文検索し、ファイルパス付きのスニペットを返します。                                               |
| `obsidian_search_structured` | JSON Logic 式（and/or/regex/path フィルター）を使用して検索します。                                            |
| `obsidian_read_note`         | 保管庫からの相対パスでノートを読み取ります。必要に応じて特定の見出し／ブロック／フロントマターを指定できます。 |
| `obsidian_list_vault`        | 保管庫内のファイルとディレクトリを一覧表示します（エントリのツリー）。                                         |
| `obsidian_get_document_map`  | ノートの見出し構造を、見出し → 行番号のマップとして取得します。                                                |
| `obsidian_get_note_metadata` | 内容全体を取得せずに、フロントマター、タグ、リンク、文字数／単語数を取得します。                               |
| `obsidian_get_active_file`   | Obsidian で現在アクティブなファイルのパスと内容を取得します。                                                  |
| `obsidian_get_periodic_note` | 指定した日付の日次／週次／月次の定期ノートを取得します（省略時は今日）。                                       |
| `obsidian_get_tags`          | 保管庫内のすべてのタグを使用頻度とともに一覧表示します。                                                       |
| `obsidian_list_commands`     | 利用可能な Obsidian コマンド ID を一覧表示します（`obsidian_execute_command` で使用）。                        |
| `obsidian_sync_status`       | OmniRoute 同期サーバーの状態（稼働状況、保管庫名、ポート、稼働時間、最終同期）を取得します。                   |
| `obsidian_sync_conflicts`    | 未解決の同期競合（パス、競合パス、検出日時）を一覧表示します。                                                 |

### 書き込みツール（`write:obsidian`）

| ツール                           | 説明                                                                                                   |
| -------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `obsidian_write_note`            | 指定された Markdown 内容でノートを作成または上書きします。                                             |
| `obsidian_append_note`           | ノートに内容を追記します。必要に応じて特定の見出し／ブロックを指定できます。                           |
| `obsidian_patch_note`            | 見出し、ブロック、またはフロントマターフィールドに対して、追加／前置／置換を部分的に実行します。       |
| `obsidian_delete_note`           | 保管庫からノートを完全に削除します。                                                                   |
| `obsidian_move_note`             | 保管庫内でノートを移動または名前変更します。                                                           |
| `obsidian_execute_command`       | コマンド ID を指定して Obsidian コマンドを実行します。                                                 |
| `obsidian_open_file`             | Obsidian でファイルを開きます（存在しない場合は作成します）。                                          |
| `obsidian_sync_trigger`          | デスクトップ↔モバイル間の双方向保管庫同期を即時実行します。                                            |
| `obsidian_sync_resolve_conflict` | 同期競合を解決します：`local`（モバイル）、`remote`（デスクトップ）、または `keep-both` を保持します。 |

> [!NOTE]
> `obsidian_patch_note` のターゲットには、`targetType` として `heading | block | frontmatter`
> を、`operation` として `append | prepend | replace` を指定でき、任意で
> `createTargetIfMissing` も指定できます。4 つの `obsidian_sync_*` ツールはローカル同期
> サーバー（デフォルトでは `http://127.0.0.1:27781`）と通信し、同期トークンを必要とします。

### スコープ

読み取りツールには `read:obsidian`、書き込みツールには `write:obsidian` が必要です。適用方式は
Notion と同一で、`open-sse/mcp-server/server.ts` 内の `withScopeEnforcement()` によって処理されます。
`OMNIROUTE_MCP_ENFORCE_SCOPES=true` の場合に有効になり、許可されるスコープは
`OMNIROUTE_MCP_SCOPES` または API キーのスコープコンテキストから取得されます。詳細については
[MCP-SERVER.md](./MCP-SERVER.md) を参照してください。

## エンドポイント

| メソッド | パス                            | 目的                                                            |
| -------- | ------------------------------- | --------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | `{ connected, hasToken, baseUrl, vaultPath }` を返します。      |
| `POST`   | `/api/settings/obsidian`        | トークンを保存して検証します（ポート `27124` は拒否されます）。 |
| `DELETE` | `/api/settings/obsidian`        | 接続を解除します（保存されているトークンを消去）。              |
| `GET`    | `/api/settings/obsidian/webdav` | WebDAV 同期のステータスと認証情報を返します（有効な場合）。     |
| `POST`   | `/api/settings/obsidian/webdav` | Vault ディレクトリの WebDAV 同期を有効にします。                |
| `DELETE` | `/api/settings/obsidian/webdav` | WebDAV 同期を無効にします。                                     |

> これらはダッシュボードの設定ルートです。Vault 自体には、Obsidian
> Local REST API（設定された `base_url`）および上記の MCP ツールを介してアクセスします。
> 公開の `/v1` Obsidian プロキシエンドポイントはありません。

## ユースケース

- **Vault に基づく回答** — `obsidian_search_simple` / `obsidian_search_structured`
  の後に `obsidian_read_note` を使用することで、エージェントが実際のノートに基づいて回答できます。
- **ノート作成 / ジャーナリング** — `obsidian_write_note`、`obsidian_append_note`、または
  ピンポイントな編集が可能な `obsidian_patch_note` を使用して、エージェントの出力、要約、日次ノート
  （`obsidian_get_periodic_note`）を Vault に記録します。
- **Vault のナビゲーション** — `obsidian_list_vault`、`obsidian_get_document_map`、および
  `obsidian_get_tags` を使用し、読み書きの前に構造を確認します。
- **Obsidian の自動化** — `obsidian_list_commands` + `obsidian_execute_command` を使用して、
  エージェントからプラグインやコマンドを操作します。`obsidian_open_file` を使用すると、UI にノートを表示できます。
- **モバイル同期** — WebDAV 同期を有効にしてから、`obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  を使用し、デスクトップ↔モバイル間の同期を調整して競合を解決します。
