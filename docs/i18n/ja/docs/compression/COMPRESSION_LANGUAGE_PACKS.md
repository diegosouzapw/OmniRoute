Caveman 圧縮では、組み込みの英語ルールに加えて、言語固有のルールパックを読み込めます。
これにより、コアエンジンの安定性を維持しながら、ポルトガル語、スペイン語、ドイツ語、フランス語、イタリア語、日本語、および
将来追加される言語パックを個別に進化させることができます。

## 場所

言語パックは以下に配置されています。

```txt
open-sse/services/compression/rules/<language>/
```

現在同梱されているパック（`rules/` ディレクトリの内容と照合済み）：

| 言語                     | ディレクトリ   | 含まれるルールカテゴリ                              |
| ------------------------ | -------------- | --------------------------------------------------- |
| 英語                     | `rules/en/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| スペイン語               | `rules/es/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| ポルトガル語（ブラジル） | `rules/pt-BR/` | `context`, `dedup`, `filler`, `structural`, `ultra` |
| インドネシア語           | `rules/id/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| イタリア語               | `rules/it/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| ドイツ語                 | `rules/de/`    | `context`, `filler`, `structural`                   |
| フランス語               | `rules/fr/`    | `context`, `filler`, `structural`                   |
| 日本語                   | `rules/ja/`    | `context`, `filler`, `structural`                   |

> **同等性に関する注記：** `en`、`es`、`pt-BR`、`id`、`it` の各パックには、5 つのカテゴリがすべて含まれています。`de`、`fr`、`ja` には 3 つのカテゴリが同梱されています。欠けている `dedup` および `ultra` カテゴリについては、暗黙的に組み込みの英語ルールへフォールバックします。小規模なパックに `dedup.json` と `ultra.json` を追加するコントリビューションを歓迎します。
>
> `pt-BR` パックは、Lenine Júnior による **[Troglodita](https://github.com/leninejunior/troglodita)** をベースにしています。これは、ブラジルポルトガル語の文法に合わせてゼロから設計された圧縮システムです（冗語表現の削減、PT-BR のフィラー除去、ブラジルの開発者コミュニティ向け技術略語）。
>
> 正式なカテゴリ一覧とカテゴリごとのスキーマは、[`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json)（JSON Schema draft 2020-12）にあります。

## 言語検出

`languageDetector.ts` は、軽量なヒューリスティクスを使用してプロンプトテキストから言語を推定します。
設定されたデフォルト言語は引き続き尊重され、厳密な制御が必要な場合は設定で検出を無効にできます。

検出結果は、ルールパックの選択にのみ使用されます。プロバイダーのルーティング、ロケールの選択、
または UI の言語には影響しません。

## 設定形式

圧縮設定には以下を含めることができます。

```json
{
  "languageConfig": {
    "enabled": true,
    "defaultLanguage": "en",
    "autoDetect": true,
    "enabledPacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  },
  "cavemanConfig": {
    "language": "en",
    "autoDetectLanguage": true,
    "enabledLanguagePacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  }
}
```

`languageConfig` は、ダッシュボード／プレビューのデフォルト設定を制御します。`cavemanConfig` は、Caveman がメッセージテキストを圧縮するときに使用するランタイムエンジンの設定です。

## 言語パックの追加

1. `open-sse/services/compression/rules/<language>/<pack>.json` を作成します。
2. `docs/compression/COMPRESSION_RULES_FORMAT.md` に記載されている Caveman ルール形式を使用します。
3. 置換は控えめにし、コード、識別子、URL、JSON を変更しないようにします。
4. 言語選択と置換動作のテストを追加または更新します。
5. UI セレクターに言語を表示する場合は、新しいダッシュボード/i18n ラベルを公開します。

## API

利用可能なパックは、次のコマンドで照会できます。

```bash
curl http://localhost:20128/api/compression/language-packs
```

プレビューエンドポイントは、言語設定のオーバーライドを受け付けます。

```bash
curl -X POST http://localhost:20128/api/compression/preview \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "standard",
    "text": "Por favor, eu gostaria que voce basicamente resumisse isso.",
    "config": {
      "languageConfig": {
        "defaultLanguage": "pt-BR",
        "autoDetect": true
      }
    }
  }'
```

## SHARED_BOUNDARIES (v3.8.0)

v3.8.0 では、6 つすべての言語パックに `SHARED_BOUNDARIES` 句が追加され、すべての
Caveman 強度（LITE、FULL、ULTRA）で適用されます。この句は、周囲のフィラーが削除されるかどうかにかかわらず、
以下のパターンをそのまま保持するようエンジンに指示します。

| パターンの種類              | 例                                     |
| --------------------------- | -------------------------------------- |
| フェンス付きコードブロック  | ` ```python\n...\n``` `                |
| インラインコード            | `` `my_var` ``                         |
| URL                         | `https://example.com/path`             |
| ファイルパス（絶対 + 相対） | `/etc/hosts`, `./src/index.ts`         |
| エラーヘッダー              | `Error:`, `TypeError:`, `SyntaxError:` |
| スタックトレース行          | `  at functionName (file.ts:12:3)`     |

これらのパターンは `DEFAULT_CAVEMAN_CONFIG.preservePatterns`（以前は `[]`）に設定されています。この
定数は `open-sse/services/compression/types.ts` にあります。

### これが重要な理由

SHARED_BOUNDARIES がない場合、積極的な Caveman モードでは、反復的な
文章のように見えても、実際にはコードスニペット、ファイルパス、またはエラースタックであるコンテンツが削除される可能性があります。SHARED_BOUNDARIES は、
フィラールールが実行される前に適用される、言語に依存しないセーフティネットとして機能します。

### preservePatterns のカスタマイズ

圧縮設定を使用して、実行時に追加のパターンを指定できます。

````json
{
  "cavemanConfig": {
    "preservePatterns": [
      "```[\\s\\S]*?```",
      "`[^`]+`",
      "https?://\\S+",
      "(?:/|\\./)[^\\s]+",
      "\\b(?:Error|TypeError|SyntaxError|RangeError):",
      "\\s+at\\s+\\S+\\s+\\(\\S+:\\d+:\\d+\\)"
    ]
  }
}
````

カスタムパターンは、6 つのデフォルトを置き換えるのではなく拡張します。

## 運用上の注意事項

- 言語パックが存在しない場合、組み込みの英語ルールが引き続きフォールバックとして使用されます。
- 無効な組み込み JSON パックは検証に失敗するため、リリースアセットの品質が気付かないうちに低下することはありません。
- ルールパックはデータ専用であり、コードをインポートしたり任意のロジックを実行したりしてはなりません。
- 圧縮分析レイヤーは、プロンプトの全文ではなく、選択されたモードとエンジンを記録します。
