1. 既存の単一キーセマフォ契約と新しいアトミックな複数キー契約を、部分的な予約が発生しないこと、FIFO キューイング、中止、タイムアウト、キュー満杯、冪等な解放、統計、クリーンアップに焦点を当てたテストで固定する。
2. 既存のアカウントセマフォをその場で汎用化する。`acquire()` は `acquireMany()` の互換ラッパーとして維持し、第 2 のスケジューラーや依存関係は追加しない。
3. `chatCore` におけるアカウントのみの取得を、`withRateLimit` の直前に行う、グローバル／プロバイダー／アカウントを累積した 1 回の取得に置き換える。アカウントローテーションによって接続が変更されるたびにセット全体を再取得し、ストリーミングが完了するまで解放を保持する。
4. 既存のレジリエンス設定パイプライン（型、デフォルト値、正規化、スキーマ、API レスポンス、UI、翻訳）を、グローバル上限とプロバイダー上限に対応するよう拡張する。従来の Bottleneck 同時実行制御は、その実際のスコープが明確になるよう、接続／クォータスコープの同時実行制御としてラベルを変更する。
5. 対象を絞ったテスト、lint、型チェック、静的チェック、および完全なテストスイートを実行し、動作変更を changelog に記載する。

意図的に維持する動作：同時実行数がゼロ／null の場合はゲートをバイパスすること、アカウントのみを扱う呼び出し元は引き続き `acquire()` を使用すること、ブロック済みアカウントの制御は既存のキー形式と API を維持すること、プロバイダーのレート制限キューの動作は変更しないこと。
