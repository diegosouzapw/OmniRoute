## 1. サービスのグラウンドトゥルース（公式ドキュメント、クロスチェック済み）

- ベース URL: `https://api.anysearch.com`（REST）+ `POST /mcp`（MCP、JSON-RPC 2.0）。
- `POST /v1/search` - パラメーター: `query`（必須）、`max_results`（1～10、デフォルト 10）、`tag`（`{domain}.{sub_domain}` による垂直ルーティング）、`zone`（cn/intl）、`language`、`params`（構造化された垂直フィールド）、`format`（json/markdown）。
- `GET /v1/sub-domains?domain=...` - ケイパビリティカタログ。クォータにはカウントされない。
- `POST /v1/extract` - `{url, title, content}` を取得・抽出。厳密な JSON ボディ、上限 16 KiB。
- `POST /v1/auth/email/register` - 1 回の呼び出しで登録し、1 回限り表示される平文キー `as_sk_...` を返す。
- 認証: `Authorization: Bearer <as_sk_...>` は任意。匿名アクセスでは、1 日の無料クォータを消費する IP 単位の制限に縮退する。無効なキーの場合、匿名アクセスへ暗黙的にフォールバックせず、401/403 を返す。
- 無料枠: 1 日あたり 1000 リクエスト、キーごとに 20 QPS。有料枠: 価格未定（近日提供予定）。
- レスポンスエンベロープ: 成功時は `{code: 0, message: "success", request_id, data}`、失敗時は `{code: -1, message}`。認証/クォータエラーには構造化された `error_code` がなく、メッセージテキストが判定シグナルとなる。抽出固有のエラーには `error_code`（`invalid_extract_url`、`extract_failed`）が含まれる。429 には `Retry-After` ヘッダーがない。

## 3. 決定事項（すべて 2026-08-26 に決定）

1. **ルーティング方針: `fallbackOnly`。** 理由: コスト 0 の無料プロバイダーが、自動コストルーティングで優先されることがあってはならないため。明示的な選択とフェイルオーバーからの復帰には影響しない。先例: マージ済みの xquik エントリ。
2. **スコープ: v1 では `POST /v1/extract` を介した webSearch + webFetch。** tavily/exa の二重機能モデルに準拠。垂直型サーフェス（`tag`、`sub-domains`、`batch_search`）はスコープ外のまま — 現時点では垂直型パラメーター用の IR が存在しない。
3. **クォータ表示: `freeMonthlyQuota: 0`**（xquik 方式の保守的な表示）。実際の許容量（1000 リクエスト/日、毎日リセット）は、代わりに UI カタログの `authHint` 文言に記載する。理由: クォータ表示はリセット方式と一致している必要があり、日次上限を月間相当（30000）に換算することは、UI が保証できない誤った約束になるため。
4. **searchTypes: `["web"]` のみ。** AnySearch API にニュース/画像の垂直検索が存在することを示す公開情報はない。文書化された垂直検索を持たない API を統合するゲートウェイ（例: Google Custom Search）は、news -> web を暗黙的にマッピングするのではなく、web のみを公開する。
5. **キー方針:** キーなしでも動作する。無効なキーの場合は 401/403 を返し、暗黙的に匿名アクセスへダウングレードすることはない（アップストリームの契約を踏襲）。
6. **意図的な除外:** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend`（チャットインターセプトは引き続き firecrawl/jina/tavily を使用）。`ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS`（匿名リモートエンドポイントは送信元 IP ごとに単一の IP 制限付きプールを共有するため、キーなしの extract はオプトインであり、自動ルーティングの候補ではない）。`QUOTA_STATUS_PROVIDERS`（AnySearch は 402/403 ステータスではなく、429/エンベロープでクォータを通知する）。
