> **Извор:** `src/lib/{a2a,acp,cloudAgent}/`, `src/app/api/{a2a,acp,cloud}/`, `src/app/api/v1/agents/`
> **Последње ажурирање:** 2026-06-28 — v3.8.40

OmniRoute пружа три различита интерфејса повезана са агентима. На први поглед делују слично, али решавају различите проблеме. Користите ову страницу да бисте изабрали одговарајући.

## Укратко

| Интерфејс                      | Најпогодније за                                                                                                                                            | Транспорт                                  | Стандард                          |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ | --------------------------------- |
| **A2A — агент-агент**          | Сарадњу између агената са равноправним агентима који користе A2A протокол                                                                                  | JSON-RPC 2.0 преко HTTP-а                  | A2A v0.3 (отворена спецификација) |
| **ACP — регистар CLI агената** | Откривање / регистровање / покретање CLI агената за програмирање инсталираних на корисниковом рачунару (Cursor, Cline, Codex CLI, Claude Code, Aider итд.) | HTTP REST                                  | Специфично за OmniRoute           |
| **Агенти у облаку**            | Слање дуготрајних програмерских задатака спољним услугама у облаку (Codex Cloud, Devin, Jules, Cursor Cloud)                                               | HTTP REST + задаци подржани базом података | Специфично за OmniRoute           |

Ова три интерфејса су независна — изаберите било коју комбинацију.

## Стабло одлучивања

```
Да ли вам је потребна услуга у облаку да обавља посао ван овог рачунара (Codex Cloud / Cursor Cloud / Devin / Jules)?
├─ ДА → Агенти у облаку (POST /api/v1/agents/tasks)
└─ НЕ → Наставите
    │
    Да ли имате равноправног агента који користи A2A и жели да сарађује?
    ├─ ДА → A2A (POST /a2a)
    └─ НЕ → Наставите
        │
        Да ли треба да наведете / конфигуришете локално инсталиране CLI агенте за програмирање?
        ├─ ДА → ACP (GET /api/acp/agents)
        └─ НЕ → Користите обичан /v1/chat/completions
```

## 1. A2A — агент-агент

**Спецификација:** [A2A v0.3](https://a2a-protocol.org)
**OmniRoute крајња тачка:** `POST /a2a` (JSON-RPC 2.0)
**Картица агента:** `GET /.well-known/agent.json`

### Када користити

- Изградња система са више агената у којем је OmniRoute један од равноправних учесника
- Омогућавање приступа OmniRoute интелигентном усмеравању (`smart-routing`, `quota-management` итд.) агентима у радним оквирима као што су Google ADK или генеричке мреже агената
- Постављање OmniRoute-а иза стандардног интерфејса за откривање и позивање

### Методе

- `message/send` — пошаљите поруку и примите синхрони одговор
- `message/stream` — пошаљите поруку и примајте SSE догађаје о напретку у виду тока
- `tasks/get` — прочитајте задатак према ID-у
- `tasks/cancel` — откажите задатак који је у току

### Уграђене вештине (6)

- `smart-routing` — усмерите упит кроз оптималну комбинацију
- `quota-management` — прикажите стање квоте за сваког добављача
- `provider-discovery` — наведите инсталиране добављаче са њиховим могућностима
- `cost-analysis` — процените трошак захтева/разговора
- `health-report` — обједините стања прекидача, периода хлађења и блокаде за сваког добављача
- `list-capabilities` — наведите доступне вештине агента и метаподатке

### Детаљније

Погледајте [A2A-SERVER.md](./A2A-SERVER.md) за детаље о транспорту, структури картице агента, конфигурацији TTL-а задатка и шаблону за додавање нових вештина.

## 2. ACP — Регистар CLI агената

**OmniRoute крајња тачка:** `GET /api/acp/agents`
**Извор:** `src/lib/acp/{index,manager,registry}.ts`

### Шта је то

ACP је OmniRoute-ов **локални инвентар CLI агената**. Он открива који су CLI алати за програмирање инсталирани на хосту (Cursor, Cline, Claude Code, Codex CLI, Continue итд.), утврђује њихове верзије и приказује их на контролној табли како би корисник могао да подеси сваки CLI да користи OmniRoute.

Ово НИЈЕ спољни протокол — то је интерни регистар који покреће кориснички интерфејс „CLI Tools“ и праћење CLI отисака (погледајте [CLI-TOOLS.md](../reference/CLI-TOOLS.md)).

### Шта ради

- Проверава да ли на хосту постоје инсталиране CLI извршне датотеке (користи `which` / `where`, у зависности од ОС-а)
- Чита верзију сваког CLI алата (позива `<bin> --version`)
- Опционо прихвата прилагођене агенте које дефинише корисник (путања до извршне датотеке + провера верзије + аргументи за покретање)
- Трајно чува прилагођене агенте у подешавањима
- Враћа обједињену листу контролној табли

### REST API

| Крајња тачка      | Метод | Опис                                                                 | Аутентификација |
| ----------------- | ----- | -------------------------------------------------------------------- | --------------- |
| `/api/acp/agents` | GET   | Приказује откривене + прилагођене агенте (број инсталираних/укупних) | API кључ        |
| `/api/acp/agents` | POST  | Додаје/ажурира/уклања прилагођени агент (дискриминатор радње у телу) | API кључ        |

Облик тела за POST (`customAgentBodySchema` у `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Случајеви употребе

- Страница „CLI Tools“ на контролној табли приказује шта је инсталирано и помаже вам да сваки алат усмерите на OmniRoute
- Прилагођени агенти омогућавају напредним корисницима да региструју интерне/власничке CLI алате које OmniRoute подразумевано не препознаје
- Резултат откривања попуњава матрицу отисака `cli-tools`

### Када НЕ треба користити ACP

- ACP не _покреће_ задатке. Он само открива и конфигурише CLI алате. Да бисте заиста позвали CLI, сами га покрените помоћу променљивих окружења које OmniRoute обезбеђује (`OPENAI_BASE_URL`, `OPENAI_API_KEY` итд.).

## 3. Агенти у облаку

**OmniRoute крајње тачке:** `/api/v1/agents/tasks/*` (животни циклус) + `/api/cloud/*` (пратећа инфраструктура)
**Извор:** `src/lib/cloudAgent/`

### Шта је то

Јединствен интерфејс за агенте за програмирање у облаку независних добављача. Пошаљете упит + URL репозиторијума, а OmniRoute га прослеђује одговарајућем агенту у облаку, периодично проверава статус и враћа резултате.

### Подржани агенти (4, сви потврђени у `src/lib/cloudAgent/agents/`)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### Животни циклус

```
POST /api/v1/agents/tasks
  → BaseAgent.createTask() за сваку класу агента
  → спољна услуга започиње рад
  → ред задатка се креира у бази података (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → одложена синхронизација статуса са добављачем
  → враћа тренутни статус + план + евиденцију активности
  ↓
POST /api/v1/agents/tasks/[id]   (радња: "approve" | "message" | "cancel")
  → прослеђује добављачу (или локално означава као отказано)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → локално отказивање
```

### Аутентификација

⚠️ **Све `/api/v1/agents/tasks/*` крајње тачке захтевају управљачку аутентификацију** (комит `588a0333`). Позиваоци који користе само Bearer токен добијају 401 од верзије v3.8.0.

### Детаљније

Погледајте [CLOUD_AGENT.md](./CLOUD_AGENT.md) за уговор `CloudAgentBase`, специфичности сваког агента, детаље шеме и крајње тачке инфраструктуре за акредитиве.

## Поређење: A2A и Cloud Agents

Оба подржавају „дуготрајне задатке“, али на различитим слојевима:

| Аспект                   | A2A                                                                                                   | Cloud Agents                                    |
| ------------------------ | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| Стандард                 | Отворени A2A v0.3                                                                                     | Специфично за OmniRoute                         |
| Где се извршава обрада   | Унутар OmniRoute-а (користи конфигурисане комбинације)                                                | Екстерно (Codex / Devin / Jules сервери)        |
| Трајање задатка          | Подразумевани TTL је 5 минута (може се конфигурисати у `TaskManager`)                                 | Од неколико минута до неколико сати             |
| Познавање репозиторијума | Не (прослеђује само упите)                                                                            | Да (URL репозиторијума + грана)                 |
| Случај употребе          | Сарадња између агената, паметно усмеравање као услуга                                                 | Делегирање „имплементирај функцију X у репоу Y“ |
| Аутентификација          | Опциони `OMNIROUTE_API_KEY` за `/a2a`; управљачка аутентификација за `/api/a2a/*` REST помоћне API-је | Увек управљачка аутентификација                 |

## Примери интеграције

### Откривање A2A могућности OmniRoute-а

```bash
curl http://localhost:20128/.well-known/agent.json
```

Враћа картицу агента са свих 6 вештина, транспортима и верзијом.

### Позивање OmniRoute-а као A2A агента

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### Листање инсталираних CLI агената преко ACP-а

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Додавање прилагођеног CLI агента

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### Слање задатка Cloud Agent-у

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### Провера статуса задатка у облаку

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## Када шта користити

- **Чет-бот / копилот кориснички интерфејс** → `/v1/chat/completions` (компатибилно са OpenAI-јем — није протокол за агенте)
- **Сарадња више агената** → A2A
- **Листање локалних CLI алата на контролној табли** → ACP
- **Делегирање дуготрајних програмерских задатака услугама у облаку** → Cloud Agents
