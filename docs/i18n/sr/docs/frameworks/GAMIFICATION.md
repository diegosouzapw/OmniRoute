> **Извор истине:** `src/lib/gamification/`, `src/lib/db/gamification.ts`, `src/app/api/gamification/`
> **Последње ажурирање:** 2026-06-28 — v3.8.40

OmniRoute садржи слој гејмификације који првенствено ради локално и награђује кориснике за
интеракцију са платформом — упућивање захтева, промену провајдера, креирање
комбинација, дељење токена и допринос заједници. Целокупно стање чува се у
SQLite-у; федерација са серверима заједнице је опциона и заснована на слању података.

Систем је пројектован тако да има **нулто кашњење на критичној путањи** — догађаји
гејмификације шаљу се по принципу „пошаљи и настави“ из цевовода за обраду захтева и никада не блокирају
LLM одговор.

## Преглед

### Сврха

Повећање ангажованости и задржавања корисника пружањем видљивог напретка (XP,
нивои, значке), друштвене потврде (ранг-листе) и економских подстицаја (дељење
токена, награде за позиве).

### Обухват

| Функционалност           | Опис                                                                             |
| ------------------------ | -------------------------------------------------------------------------------- |
| XP и нивои               | Освајање XP-а по радњи; прелазак на виши ниво по полиномској кривој              |
| Значке                   | Више од 20 достигнућа у 5 категорија са 4 нивоа реткости                         |
| Низови активности        | Праћење дневне активности са тренутним и најдужим низом                          |
| Ранг-листе               | Глобални, недељни, месечни, за дељење токена и доприносе                         |
| Дељење токена            | Пренос кредита између корисника путем књиге двојног књижења                      |
| Позивање и искоришћавање | Реферални кодови који се чувају као SHA-256 хешеви                               |
| Сервери заједнице        | Федерација са спољним OmniRoute инстанцама                                       |
| Заштита од варања        | Серверско бодовање, ограничавање учесталости, откривање аномалија помоћу z-скора |

### Принципи дизајна

1. **Првенствено локално** — целокупно стање је у SQLite-у, без потребе за спољним услугама.
2. **Неблокирајуће** — догађаји се шаљу по принципу „пошаљи и настави“; путања LLM одговора се
   никада не успорава логиком гејмификације.
3. **Сервер је меродаван** — XP се израчунава искључиво на серверу; клијенти не могу
   вештачки увећавати резултате.
4. **Поштовање приватности** — учешће на ранг-листи је опционо; корисници могу
   сакрити свој профил.
5. **Спремно за федерацију** — сервери заједнице могу слати резултате путем потписаног API-ја;
   синхронизација преписује вредности уместо да их сабира.

## Архитектура

### Ток високог нивоа

```
Захтев клијента
  → /v1/chat/completions
    → handleChatCore()                      [open-sse/handlers/chatCore.ts]
      → ... (постојећи цевовод) ...
      → одговор узводног сервера послат клијенту
      → setImmediate (пошаљи и настави):
        → emitGamificationEvent()           [src/lib/gamification/events.ts]
          → awardXp()                       [src/lib/gamification/xp.ts]
          → updateStreak()                  [src/lib/gamification/streaks.ts]
          → evaluateBadges()                [src/lib/gamification/badges.ts]
          → updateLeaderboard()             [src/lib/gamification/leaderboard.ts]
          → checkAnomalies()                [src/lib/gamification/antiCheat.ts]
```

Емитер догађаја представља јединствену интеграциону тачку. `chatCore.ts` позива
`emitGamificationEvent()` након слања одговора; модул догађаја прослеђује
догађај подсистемима за XP, низове активности, значке, ранг-листе и заштиту од варања.

## XP / систем нивоа

**Датотека:** `src/lib/gamification/xp.ts`

### Крива нивоа

XP потребан за достизање нивоа `n` прати полиномску криву:

```
xp_for_level(n) = floor(100 * n^1.5)
```

| Ниво | XP до следећег нивоа | Кумулативни XP | Титула     |
| ---- | -------------------- | -------------- | ---------- |
| 1    | 100                  | 100            | Почетник   |
| 5    | 1,118                | 2,415          | Почетник   |
| 10   | 3,162                | 10,523         | Истраживач |
| 25   | 12,500               | 86,024         | Истраживач |
| 50   | 35,355               | 345,529        | Стручњак   |
| 75   | 64,952               | 948,683        | Мајстор    |
| 100  | 100,000              | 2,050,000      | Легенда    |

### Титуле

| Опсег нивоа | Титула     |
| ----------- | ---------- |
| 1 – 9       | Почетник   |
| 10 – 24     | Истраживач |
| 25 – 49     | Стручњак   |
| 50 – 74     | Мајстор    |
| 75 – 100    | Легенда    |

### XP награде

| Радња             | XP  | Опис                                                  |
| ----------------- | --- | ----------------------------------------------------- |
| `request`         | 1   | За сваки API захтев усмерен кроз OmniRoute            |
| `provider_switch` | 5   | Прелазак на другог добављача                          |
| `model_switch`    | 3   | Прелазак на други модел                               |
| `combo_create`    | 10  | Креирање нове комбинације                             |
| `combo_use`       | 2   | Коришћење комбинације за захтев                       |
| `token_share`     | 1   | За сваких 1 000 токена подељених са другим корисником |
| `invite_redeem`   | 50  | Искоришћавање позивног кода                           |
| `daily_login`     | 5   | Дневно активно коришћење (једном дневно)              |
| `streak_bonus`    | 2   | За сваки узастопни дан низа (помножено дужином низа)  |
| `badge_unlock`    | 10  | Откључавање значке                                    |

### Ток додељивања

```typescript
export async function awardXp(
  apiKeyId: string,
  action: XpAction,
  metadata?: Record<string, unknown>
): Promise<{ xp: number; level: number; title: string; levelUp: boolean }>;
```

1. Потражите `XP_REWARDS[action]` да бисте добили количину XP-а.
2. Проследите кроз `checkRateLimit()` (заштита од варања: највише 1000 XP/мин по кључу).
3. Отворите трансакцију:
   - Прочитајте тренутни ред из `user_levels`.
   - Додајте XP; поново израчунајте ниво помоћу `levelFromXp(totalXp)`.
   - Ако се ниво променио, поставите `levelUp = true`.
   - Ажурирајте ред у `user_levels`.
   - Уметните запис у `xp_audit_log`.
4. Вратите резултат. Позивалац обрађује обавештења.

### Помоћна функција: `levelFromXp(totalXp)`

Пролази кроз нивое 1..100, сабирајући `xp_for_level(n)` док кумулативни XP
не премаши `totalXp`. Враћа највиши ниво чији је праг достигнут.
Ово је O(100) — прихватљиво, јер су нивои ограничени на 100.

| `action_count` | `count`      | Извршити радњу N пута (нпр. 1000 захтева)           |

| `unique_count` | `field`, `n` | Користити N јединствених вредности (нпр. 10 модела) |
| `rank`         | `scope`, `n` | Достићи ранг N у оквиру ранг-листе                  |
| `first`        | —            | Бити први који је извршио радњу                     |
| `hidden`       | (варира)     | Критеријуми се не приказују док се значка не освоји |

Дефиниције значки чувају се у `badge_definitions` као JSON `criteria`:

```json
{
  "type": "action_count",
  "action": "request",
  "count": 1000
}
```

### Ток процене

```
emitGamificationEvent(event)
  → evaluateBadges(apiKeyId, event)
    → getBadgeDefinitions()           # све дефиниције
    → getUserBadges(apiKeyId)         # већ освојене (прескочи)
    → за сваку неосвојену значку:
       → matchesCriteria(badge, event, userState)
       → ако се подудара: awardBadge(apiKeyId, badgeId)
         → врати садржај обавештења
```

Процена је **вођена догађајима** — покреће се након сваког догађаја гејмификације, али
проверава само значке чији је `criteria.type` усклађен са радњом догађаја. Ово
одржава процену брзом (< 5ms за већину догађаја).

### `matchesCriteria(badge, event, userState)`

| Тип критеријума | Провера                                                  |
| --------------- | -------------------------------------------------------- |
| `action_count`  | `getActionCount(apiKeyId, action) >= count`              |
| `streak`        | `getCurrentStreak(apiKeyId) >= days`                     |
| `unique_count`  | `getUniqueCount(apiKeyId, field) >= n`                   |
| `rank`          | `getRank(apiKeyId, scope) <= n`                          |
| `first`         | Нема претходног уноса у `xp_audit_log` за овај тип радње |
| `hidden`        | Делегира одговарајућој потпровери                        |

## Праћење низа

**Датотека:** `src/lib/gamification/streaks.ts`

### Модел података

Низови се чувају у табели `key_value` (дељена помоћна табела) под кључевима са именским простором:

| Кључ                          | Вредност                         | Опис                   |
| ----------------------------- | -------------------------------- | ---------------------- |
| `gamification:streak:{keyId}` | `{current},{longest},{lastDate}` | Подаци о активном низу |

### Логика

```typescript
export async function updateStreak(
  apiKeyId: string
): Promise<{ current: number; longest: number; milestone: boolean }>;
```

1. Прочитајте запис о низу из `key_value`.
2. Рашчланите `{current}`, `{longest}`, `{lastDate}` (ниска датума у ISO формату).
3. Ако је `lastDate === today` — без измена (већ је урачунато данас).
4. Ако је `lastDate === yesterday` — увећајте `current`; ажурирајте `longest` ако је потребно.
5. Ако је `lastDate < yesterday` — ресетујте `current = 1` (низ је прекинут).
6. Упишите ажурирани запис.
7. Проверите прекретнице: 7, 14, 30, 60, 90, 180, 365 дана. Ако је нека достигнута, поставите
   `milestone = true` (позивалац додељује XP и проверава значке).

### Гранични случајеви

- **Временска зона**: низови користе UTC датуме (`new Date().toISOString().slice(0, 10)`).
  Ово је намерно — једна канонска временска зона спречава манипулацију
  променом временских зона.
- **Нови корисници**: запис о низу не постоји; први захтев га креира са
  `current=1, longest=1, lastDate=today`.
- **Више захтева дневно**: само први захтев у UTC дану
  увећава низ.

## Ранг-листа

**Датотека:** `src/lib/gamification/leaderboard.ts`

### Опсези

| Опсег           | Период  | Опис                                                           |
| --------------- | ------- | -------------------------------------------------------------- |
| `global`        | `all`   | Укупан XP за све време                                         |
| `weekly`        | `week`  | XP освојен у текућој UTC недељи (пон–нед)                      |
| `monthly`       | `month` | XP освојен у текућем UTC месецу                                |
| `tokens_shared` | `all`   | Укупан број токена пренетих другима                            |
| `contributions` | `all`   | Креиране комбинације + коришћени добављачи + коришћене вештине |

### Израчунавање ранга

Рангови се **израчунавају приликом читања**, а не чувају. Тиме се избегавају застарели подаци о рангу
и елиминише потреба за периодичним пословима поновног израчунавања ранга.

```typescript
export async function getLeaderboard(
  scope: LeaderboardScope,
  period: string,
  limit: number,
  offset: number
): Promise<{ entries: LeaderboardEntry[]; total: number }>;
```

Образац упита:

```sql
SELECT api_key_id, score,
       RANK() OVER (ORDER BY score DESC) as rank
FROM leaderboard
WHERE scope = ? AND period = ?
ORDER BY score DESC
LIMIT ? OFFSET ?
```

### Ротација периода

Недељне и месечне ранг-листе се аутоматски ротирају:

1. **Архивирање**: на граници периода, копирајте тренутне уносе у
   `leaderboard_archive` са ознаком периода.
2. **Ресетовање**: избришите уносе за истекли период.
3. **Окидач**: проверава се при сваком позиву `updateLeaderboard()`; први захтев
   у новом периоду покреће ротацију.

Ово обезбеђује да се недељне листе ресетују сваког понедељка у 00:00 UTC, а месечне листе
првог дана сваког месеца.

### SSE ажурирања у реалном времену

**Крајња тачка:** `GET /api/gamification/stream`

```
Клијент → GET /api/gamification/stream
  → SSE веза је успостављена
  → Сервер одмах шаље снимак 10 најбољих на ранг-листи
  → Сваких 5 секунди: шаље ажурираних 10 најбољих ако је дошло до промене
  → Сваких 15 секунди: коментар за одржавање везе (": heartbeat\n\n")
  → Клијент прекида везу → чишћење (уклањање слушаоца)
```

Формат догађаја:

```
event: leaderboard
data: {"scope":"global","entries":[...]}

event: leaderboard
data: {"scope":"weekly","entries":[...]}

: heartbeat
```

SSE менаџер прати повезане клијенте по опсегу и шаље ажурирања само
када су се подаци ранг-листе заиста променили од последњег слања.

## Дељење токена

**Датотека:** `src/lib/gamification/sharing.ts`

### Двојно књиговодство

Сваки пренос креира два реда у `token_ledger`:

| Ред      | `from_key_id` | `to_key_id` | `amount` |
| -------- | ------------- | ----------- | -------- |
| Задужење | пошиљалац     | прималац    | +износ   |
| Одобрење | прималац      | пошиљалац   | -износ   |

Заправо — конвенција је:

| Ред     | `from_key_id` | `to_key_id` | `amount` | Значење            |
| ------- | ------------- | ----------- | -------- | ------------------ |
| Слање   | пошиљалац     | прималац    | +износ   | Одлив од пошиљаоца |
| Примање | прималац      | пошиљалац   | +износ   | Прилив ка примаоцу |

Стање се израчунава на следећи начин:

```sql
SELECT
  COALESCE(SUM(CASE WHEN to_key_id = ? THEN amount ELSE 0 END), 0)
  - COALESCE(SUM(CASE WHEN from_key_id = ? THEN amount ELSE 0 END), 0)
  AS balance
FROM token_ledger
WHERE from_key_id = ? OR to_key_id = ?
```

### Ток преноса

```typescript
export async function transferTokens(
  fromKeyId: string,
  toKeyId: string,
  amount: number,
  idempotencyKey: string
): Promise<{ success: boolean; balance: number }>;
```

1. **Валидација**: `amount > 0`, `fromKeyId !== toKeyId`.
2. **Идемпотентност**: проверити да ли `idempotency_key` већ постоји у евиденцији.
   Ако постоји, вратити кеширани резултат.
3. **Трансакција** (једна SQLite трансакција):
   a. Израчунати стање пошиљаоца.
   b. Ако је `balance < amount`, прекинути (недовољно средстава).
   c. Уметнути ред слања (`from=sender,`.

### Ограничење учесталости

- Највише 10 преноса у минути по API кључу.
- Највише 10.000 токена по појединачном преносу.
- Највише 100.000 пренетих токена дневно по API кључу.

## Токени за позиве и искоришћавање

**Датотека:** `src/lib/gamification/invites.ts`

### Формат кода

- **Код**: алфанумерички низ од 8 знакова (нпр. `A3K9-X7M2`), читљив људима,
  који се приказује кориснику.
- **Токен**: насумични токен од 32 бајта, који се чува као SHA-256 хеш. Користи се за
  програмско искоришћавање (нпр. URL везе).

### Складиштење

| Колона       | Вредност                            |
| ------------ | ----------------------------------- |
| `code`       | `A3K9X7M2` (јединствен, индексиран) |
| `token_hash` | SHA-256(raw_token)                  |

Необрађени токен се кориснику враћа тачно једном, приликом креирања. OmniRoute
га више никада не чува нити приказује — трајно се чува само хеш.

### Спречавање самопрепорука

Када корисник искористи код, систем проверава:

1. Да код припада другом `api_key_id`.
2. Да корисник који искоришћава код није претходно искористио ниједан код истог
   препоручиоца (спајање над `invite_tokens` + евиденцијом искоришћавања).

Ако било која провера не успе, искоришћавање се одбија уз јасну поруку о грешци.

### Истек и ограничења

- Подразумевано `max_uses`: 10 (може се подесити приликом креирања).
- Подразумевано `expires_at`: 30 дана од креирања.
- Истекли или у потпуности искоришћени кодови враћају HTTP 410 Gone.

## Федерација сервера заједнице

**Датотека:** `src/lib/gamification/servers.ts`

### Повезивање

Сервер заједнице се региструје помоћу токена позивнице који издаје удаљени
сервер. Локална инстанца:

1. Прима токен позивнице (нпр. налепљен у контролну таблу).
2. Позива `POST /api/gamification/federation/leaderboard` на удаљеном серверу
   ради провере токена и преузимања тренутне ранг-листе.
3. Чува запис о серверу са `status: connected`.

### Модел синхронизације

Федерација користи **синхронизацију преписивањем**, а не сабирањем:

```
Локална инстанца              Сервер заједнице
     │                              │
     ├── слање резултата ──────────►│  POST /federation/score
     │   { api_key_id, score }      │  (сервер проверава хеш токена)
     │                              │
     ├── преузимање ранг-листе ────►│  GET /federation/leaderboard
     │◄── првих N ставки ───────────┤  (преписује локални кеш)
     │                              │
     └── провера исправности ──────►│  GET /federation/health
         (сваких 60s, рок 5s)       │
```

### Аутентификација

Захтеви федерације садрже:

```
Authorization: Bearer <необрађени_токен>
X-Federation-Version: 1
```

Удаљени сервер хешира токен и проналази одговарајући ред у
`community_servers`. Тиме се избегава пренос сачуваног хеша.

### Праћење исправности

Сваки запис о серверу прати:

| Поље        | Опис                                                 |
| ----------- | ---------------------------------------------------- |
| `status`    | `connected`, `degraded`, `unreachable`               |
| `last_sync` | ISO временска ознака последње успешне синхронизације |
| `failures`  | Узастопни неуспеси провере исправности               |

Након 5 узастопних неуспеха, статус се мења у `unreachable`, а синхронизација се
паузира док ручна провера исправности не буде успешна.

## Заштита од варања

**Датотека:** `src/lib/gamification/antiCheat.ts`

### Израчунавање резултата на страни сервера

Сва израчунавања XP-а обављају се у `src/lib/gamification/xp.ts`. Клијенти никада
не шаљу резултат — они шаљу радње, а сервер израчунава XP. У колону
`leaderboard.score` може да уписује само код на страни сервера.

### Ограничавање брзине

| Ограничење                       | Вредност | Обухват      |
| -------------------------------- | -------- | ------------ |
| Максимални XP у минуту           | 1,000    | По API кључу |
| Максималан број преноса у минуту | 10       | По API кључу |
| Максималан износ преноса         | 10,000   | По преносу   |
| Максималан дневни износ преноса  | 100,000  | По API кључу |

Ограничења брзине користе клизни прозор у меморији (исти образац као
`RateLimitManager` у `open-sse/services/`). Ако се процес поново покрене,
користе се резервни бројачи засновани на SQLite-у.

### Откривање аномалија помоћу Z-скора

За сваки API кључ систем одржава клизни седмодневни прозор XP-а зарађеног по
сату. При свакој додели XP-а:

1. Израчунава тренутну сатницу стицања XP-а корисника.
2. Израчунава средњу вредност и стандардну девијацију популације.
3. Израчунава `z = (user_rate - mean) / stddev`.
4. Ако је `z > 3.0` (3 стандардне девијације), означава догађај као аномалију.

Аномалије се евидентирају у `xp_audit_log` са `action = 'anomaly_detected'`
и приказују се на администраторској контролној табли.

### Ревизиони траг

Свака додела XP-а, пренос, освајање значке и откривање аномалије евидентирају се у
`xp_audit_log` са:

| Поље         | Опис                                             |
| ------------ | ------------------------------------------------ |
| `api_key_id` | Ко                                               |
| `action`     | Шта се догодило (xp_award, transfer, anomaly, …) |
| `xp_awarded` | Количина (0 за догађаје који нису XP)            |
| `metadata`   | JSON са контекстом (врста радње, циљ, …)         |
| `created_at` | Када (ISO 8601)                                  |

Администратори могу да претражују комплетан ревизиони траг путем `GET /api/gamification/anomalies`.

## Странице контролне табле

### `/dashboard/leaderboard`

- Приказ подијума (најбоља 3 корисника са аватарима и XP-ом).
- Бирач опсега: Глобално / Недељно / Месечно / Дељени токени / Доприноси.
- Табела са пагинацијом (25 по страници) која садржи ранг, име, резултат, ниво и титулу.
- SSE ажурирања у реалном времену — промене ранга су анимиране.
- Тренутни корисник је истакнут у табели лепљивим редом „Ваш ранг“.

### `/dashboard/profile`

- Трака напретка XP-а са тренутним нивоом и прагом за следећи ниво.
- Значка титуле је истакнуто приказана.
- Галерија значки — освојене значке са датумом освајања, а неосвојене значке су засивљене
  (скривене значке приказују „???“ док не буду освојене).
- Бројач низа са иконом пламена; календар низа (последњих 30 дана).
- Графикон историје XP-а (дневни XP током последњих 30 дана).

### `/dashboard/tokens`

- Стање токена (истакнуто, на врху странице).
- Образац за пренос: прималац, износ, дијалог за потврду.
- Табела историје преноса са филтерима (послато/примљено/све).
- Одељак за позивнице: активни кодови, генерисање нових, дељење везе.
- Сервери заједнице: листа са здравственим статусом, повезивање/прекидање везе.

### `/dashboard/gamification/admin`

- Листа аномалија са озбиљношћу, корисником, временском ознаком и z-резултатом.
- Прегледач евиденције ревизије са филтерима (тип радње, корисник, опсег датума).
- Системска статистика: укупан додељени XP, активни корисници, стопе освајања значки.
- Преглед здравственог стања федеративних сервера.

## Интеграција у ток обраде

### Тачка интеграције

Гејмификација се укључује у ток обраде захтева на једној тачки у
`open-sse/handlers/chatCore.ts`:

```typescript
// Након што је одговор послат клијенту:
setImmediate(() => {
  emitGamificationEvent({
    type: "request.completed",
    apiKeyId,
    metadata: {
      provider: selectedProvider,
      model: selectedModel,
      comboId: resolvedCombo?.id,
      compressionUsed: compressionStats?.applied,
      skillUsed: skillExecution?.name,
    },
  }).catch(() => {
    // Покрени и заборави: евидентирати, али никада не прослеђивати клијенту
  });
});
```

### Типови догађаја

| Тип догађаја        | Када се емитује                                                |
| ------------------- | -------------------------------------------------------------- |
| `request.completed` | Успешан LLM одговор је послат                                  |
| `provider.switch`   | Добављач је промењен (рачунају се резервни избори комбинације) |
| `combo.created`     | Нова конфигурација комбинације је сачувана                     |
| `combo.used`        | Циљ комбинације је успешно достигнут                           |
| `badge.earned`      | Процена значке је пронашла подударање                          |
| `streak.milestone`  | Праг низа је пређен                                            |
| `transfer.sent`     | Пренос токена је завршен                                       |
| `referral.redeemed` | Позивни код је успешно искоришћен                              |
| `compression.used`  | Примењена је компресија упита                                  |
| `skill.executed`    | Извршавање вештине је завршено                                 |
| `model.first_use`   | Модел није коришћен током претходних 7 дана                    |

### Гаранција неблокирајућег извршавања

Образац `setImmediate` + `.catch(() => {})` обезбеђује:

1. Одговор је у потпуности послат пре покретања гејмификације.
2. Грешке гејмификације никада се не приказују клијенту.
3. Обрада догађаја се извршава у следећем микрозадатку, а не непосредно.

## Безбедност

### Модел претњи

| Претња                         | Мера заштите                                                                       |
| ------------------------------ | ---------------------------------------------------------------------------------- |
| Вештачко увећавање резултата   | Израчунавање XP-а искључиво на серверу; клијенти шаљу радње, а не резултате        |
| Напади поновним слањем         | Кључеви идемпотентности за трансфере; дедупликација дневника ревизије              |
| Превара при трансферу          | Двојно књиговодство; атомске трансакције; ограничења учесталости захтева           |
| Самостална препорука           | Унакрсна провера `api_key_id` приликом искоришћавања                               |
| Манипулација ранг-листом       | Откривање аномалија помоћу Z-скора; администраторска контролна табла за аномалије  |
| Крађа федерацијског токена     | Складиштење SHA-256 хеша; необрађени токен приказује се само једном                |
| Груба сила над кодовима позива | Ограничавање учесталости на крајњој тачки за искоришћавање; ентропија од 8 знакова |
| XSS у приказаним именима       | Приказана имена се санитизују; уноси на ранг-листи се избегавају                   |
| Временски напади на хешеве     | `crypto.timingSafeEqual` за поређење хешева токена                                 |

### Захтеви за аутентификацију

- **Јавно** (без аутентификације): `GET /leaderboard`, `GET /stream` (ранг-листе
  само за читање).
- **Потребан API кључ**: све операције писања, профил, трансфери, позиви.
- **Само за администраторе**: контролна табла за аномалије, прегледач дневника ревизије.
- **Федерација**: засебна путања за аутентификацију која користи необрађени токен у
  `Authorization` заглављу, проверен у односу на сачувани SHA-256 хеш.

## Будућа разматрања

- **Сезонски догађаји**: временски ограничени скупови значки и сезоне ранг-листа.
- **Тимске ранг-листе**: груписање корисника према организацији или комбинацији.
- **XP множиоци**: повећање XP-а током промотивних периода.
- **Дељење достигнућа**: генерисање дељивих картица са значкама (OpenGraph слике).
- **Мобилна push обавештења**: обавештења заснована на webhook-овима за догађаје у вези са значкама/нивоима.
- **API ранг-листе**: јавни API за интеграције трећих страна.
