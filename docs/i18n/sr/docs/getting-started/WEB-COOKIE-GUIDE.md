Добављачи веб-колачића омогућавају OmniRoute-у да користи AI услугу преко ваше постојеће сесије у прегледачу уместо API кључа. Корисни су када већ имате приступ услузи преко њеног веб-сајта и желите да OmniRoute користи исту аутентификовану сесију.

За разлику од добављача са API кључем, добављачи веб-колачића обављају аутентификацију помоћу акредитива које ваш прегледач шаље веб-сајту.

---

# Пре него што почнете

> **Важно:** Увек копирајте акредитиве из **активног мрежног захтева**, а **не** из складишта колачића прегледача.

Многи проблеми са аутентификацијом настају због копирања колачића са погрешног места.

## НЕ копирајте из складишта колачића

Већина прегледача приказује сачуване колачиће преко:

```
DevTools
→ Application (или Storage)
→ Cookies
```

Иако ови колачићи изгледају исправно, могу бити:

- застарели
- непотпуни
- без колачића који се шаљу само у аутентификованим захтевима

Коришћење ових вредности може довести до неуспешне аутентификације чак и ако изгледају исправно.

## Копирајте из активног захтева

Уместо тога, користите колачиће из успешног захтева:

```
DevTools
→ Network
→ Освежите страницу
→ Отворите захтев за ћаскање или разговор
→ Request Headers
→ Cookie
```

Заглавље захтева `Cookie` садржи тачне информације за аутентификацију које је ваш прегледач успешно употребио.

За већину добављача веб-колачића, ово је вредност коју треба налепити у OmniRoute.

---

# Опште подешавање

Поступак подешавања је исти за већину добављача веб-колачића.

1. Пријавите се на веб-сајт добављача.
2. Отворите алатке за програмере у прегледачу.
3. Отворите картицу **Network**.
4. Освежите страницу.
5. Отворите аутентификовани захтев за ћаскање или разговор.
6. Копирајте потребне акредитиве за аутентификацију.
7. Отворите OmniRoute.
8. Идите на **Providers → Add Provider**.
9. Изаберите свог добављача веб-колачића.
10. Налепите акредитиве.
11. Кликните на **Test Connection**.
12. Сачувајте добављача.

Тачни потребни акредитиви зависе од добављача.

---

Различити веб-сајтови чувају податке за аутентификацију на различите начине. Неки захтевају само колачиће, док други могу захтевати додатна заглавља или токене.

| ------------------------------- | ----------------------------- | -------------------------------- |

| ChatGPT Web (Codex)             | Пуно Cookie заглавље          | `docs/providers/CHATGPT_WEB.md`  |
| Gemini Web                      | _(проверити)_                 |                                  |

> Ажурирајте ову табелу када се додају нови добављачи веб-колачића или када постојећи добављачи промене захтеве за аутентификацију.

---

# Шта добављачи веб-колачића могу, а шта не могу да раде

Добављачи веб-колачића поново користе интерфејс веб-сајта за ћаскање. Они **не** пружају исте могућности као званични API-ји.

## Подржано

- Аутентификација помоћу постојеће сесије у прегледачу
- Приступ моделима доступним преко вашег налога
- Стримовање одговора у ћаскању
- Није потребан API кључ

## Није подржано

- Позивање функција
- Позивање алата
- Аутоматско уређивање датотека
- Агентички IDE токови рада
- Функције доступне само преко API-ја

Ово је очекивано понашање и **није** грешка.

Ако вам је потребно извршавање алата, аутоматско уређивање датотека или други агентски токови рада, користите **добављача са API кључем** уместо добављача веб-колачића.

---

# Ограничење провере ваљаности

Успешан **Test Connection** или успешна провера ваљаности колачића само потврђује да достављени акредитиви изгледају као да су у очекиваном формату.

Док се проблем #7857 не реши, успешна провера ваљаности **не гарантује** да ће добављач успешно обавити аутентификацију.

Ако аутентификација и даље не успева, проверите да ли сте акредитиве копирали из активног мрежног захтева, а не из складишта колачића прегледача.

---

# Решавање проблема

## Аутентификација не успева

Проверите да ли су акредитиви копирани из:

```
Network
→ Request Headers
→ Cookie
```

а **не** из:

```
Application
→ Cookies
```

---

## Колачић ради у прегледачу, али не и у OmniRoute-у

Неки добављачи укључују колачиће који се шаљу само током аутентификованих захтева.

Поново копирајте акредитиве из новог мрежног захтева након што успешно отворите разговор.

---

## Сесија је истекла

Добављачи веб-колачића користе вашу постојећу сесију у прегледачу.

Ако сесија у прегледачу истекне или се одјавите, морате да копирате нови скуп акредитива.

---

## Test Connection пролази, али захтеви не успевају

Док се проблем #7857 не реши, пролазак провере ваљаности не гарантује да ће захтев за аутентификацију успети.

Поново копирајте акредитиве из новог аутентификованог захтева пре него што наставите са решавањем проблема.

---

# Пример добављача

Комплетно упутство за одређеног добављача потражите овде:

- **Claude Web** — `docs/providers/CLAUDE_WEB.md`

Водич за Claude Web приказује комплетан поступак подешавања добављача веб-колачића и служи као референтна имплементација.

---

# Најбоље праксе

- Копирајте акредитиве из новог аутентификованог захтева.
- Избегавајте поновну употребу старих колачића.
- Одржавајте сесију у прегледачу активном док користите добављаче веб-колачића.
- Третирајте копиране колачиће као осетљиве акредитиве.
- Користите добављаче са API кључем када вам је потребно позивање функција или агентски токови рада.
