Провајдери са веб колачићима омогућавају OmniRoute-у да користи AI услугу преко ваше постојеће сесије у прегледачу уместо API кључа. Корисни су када већ имате приступ услузи преко њеног веб-сајта и желите да OmniRoute користи исту аутентификовану сесију.

За разлику од провајдера који користе API кључеве, провајдери са веб колачићима обављају аутентификацију помоћу акредитива које ваш прегледач шаље веб-сајту.

---

# Пре него што почнете

> **Важно:** Увек копирајте акредитиве из **активног мрежног захтева**, а **не** из складишта колачића у прегледачу.

Многи проблеми са аутентификацијом настају због копирања колачића са погрешног места.

## НЕ копирајте из складишта колачића

Већина прегледача приказује сачуване колачиће путем:

```
DevTools
→ Application (или Storage)
→ Cookies
```

Иако ови колачићи изгледају исправно, могу бити:

- застарели
- непотпуни
- без колачића који се шаљу само у аутентификованим захтевима

Коришћење ових вредности може довести до неуспешне аутентификације, чак и ако делују исправно.

## Копирајте из активног захтева

Уместо тога, користите колачиће из успешног захтева:

```
DevTools
→ Network
→ Освежите страницу
→ Отворите захтев за ћаскање или разговор
→ Request Headers
→ Cookie
```

Заглавље захтева `Cookie` садржи тачне информације за аутентификацију које је ваш прегледач успешно употребио.

За већину провајдера са веб колачићима, ово је вредност коју треба налепити у OmniRoute.

---

# Опште подешавање

Поступак подешавања је исти за већину провајдера са веб колачићима.

1. Пријавите се на веб-сајт провајдера.
2. Отворите развојне алатке прегледача.
3. Отворите картицу **Network**.
4. Освежите страницу.
5. Отворите аутентификовани захтев за ћаскање или разговор.
6. Копирајте потребне акредитиве за аутентификацију.
7. Отворите OmniRoute.
8. Идите на **Providers → Add Provider**.
9. Изаберите свог провајдера са веб колачићима.
10. Налепите акредитиве.
11. Кликните на **Test Connection**.
12. Сачувајте провајдера.

Тачни потребни акредитиви зависе од провајдера.

> Ажурирајте ову табелу када се додају нови провајдери са веб колачићима или када постојећи провајдери промене своје захтеве за аутентификацију.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) је бесплатна платформа за ћаскање намењена корисницима, за коју није потребна регистрација — сесија се креира анонимно при првој посети и задржава се помоћу три колачића: `uid`, `si_usr_id` и `si_ses_id`. OmniRoute прослеђује исти `/api/dispatch` endpoint преко једног ID-а модела (`notrack-c`, алијас `ntw`).

### Кораци за повезивање

1. Отворите [notrack.ai](https://notrack.ai) у прегледачу и сачекајте да се постави колачић анонимне сесије.
2. Отворите **DevTools → Network**, освежите страницу и кликните на било који `/api` захтев.
3. У одељку **Request Headers** копирајте целу вредност `Cookie` заглавља.
4. У OmniRoute-у идите на **Providers → Add Provider → NoTrack Web (Free)**.
5. Налепите ниску колачића у поље `apiKey` и кликните на **Save**.

OmniRoute издваја `uid`, `si_usr_id` и `si_ses_id` из налепљене ниске и поново формира чисто `Cookie` заглавље које садржи само те парове — уз `nt_session` (`ntk_…` токен који се поставља за пријављене налоге), када је присутан. Ако било која од те три вредности недостаје, необрађена налепљена ниска прослеђује се непромењена како би оператори могли да експериментишу са алтернативним облицима.

### ID-ови модела

| ID модела   | Назив за приказ | Напомене                                               |
| ----------- | --------------- | ------------------------------------------------------ |
| `notrack-c` | NoTrack C       | Подразумевано — upstream dispatch модел `C`.           |
| `C`         | NoTrack C       | Алијас за `notrack-c` (изворни upstream dispatch кôд). |
| `notrack`   | NoTrack C       | Алијас за `notrack-c`.                                 |
| `ntw`       | NoTrack C       | Кратак алијас за `notrack-c`.                          |

Сва четири ID-а модела мапирају се на исти upstream dispatch модел (`C`).

### Опције захтева

Извршилац прихвата следећа опциона поља у телу захтева:

| Поље тела             | Подразумевано | Намена                                                                              |
| --------------------- | ------------- | ----------------------------------------------------------------------------------- |
| `notrack_mode`        | `usual`       | Режим отпремања (произвољна ниска; upstream прихвата `usual`, …)                    |
| `notrack_max_turns`   | `6`           | Број интерних корака које upstream може да изврши пре него што одговори.            |
| `notrack_chat_id`     | `null`        | Настављање постојећег upstream ћаскања (изоставите за ново ћаскање).                |
| `notrack_attachments` | `[]`          | Непосредно прослеђен низ upstream дескриптора прилога.                              |
| `notrack_regenerate`  | `false`       | Поставите на `true` да бисте затражили поново генерисан одговор за претходни корак. |

### Могућности

- **Стриминг и одговори без стриминга** за довршавање ћаскања.
- **Позивање алатки** — поставите `tools: [...]` у захтеву; извршилац их серијализује у уговор омотача за позив алатке и одговоре модела поново рашчлањује у OpenAI `tool_calls`.
- **`response_format`** — подржани су `json_object` и `json_schema`. Извршилац издваја први JSON објекат из одговора модела и претвара га у ниску пре враћања.
- **Назнака резоновања** — извршилац емитује `reasoning` делту када upstream пошаље `thinking` догађај.

### Ограничења

- Upstream примењује квоте за анонимно коришћење — када се прекораче, извршилац враћа статус 429 са разумљивом поруком.
- Сви ID-ови модела разрешавају се у исти upstream dispatch модел; није могуће пребацивање по моделу.
- Извршилац не позива upstream `/api/chats` endpoint, па се историја ћаскања / сесије не управљају аутоматски. Користите `notrack_chat_id` да бисте наставили постојеће upstream ћаскање.

# Шта добављачи веб-колачића могу, а шта не могу да ураде

Добављачи веб-колачића поново користе интерфејс за ћаскање веб-сајта. Они **не** пружају исте могућности као званични API-ји.

## Подржано

- Аутентификација помоћу постојеће сесије прегледача
- Приступ моделима доступним преко вашег налога
- Стримовање одговора у ћаскању
- API кључ није потребан

## Није подржано

- Позивање функција
- Позивање алата
- Аутоматско уређивање датотека
- Агентички IDE токови рада
- Функције доступне само преко API-ја

Ово је очекивано понашање и **није** грешка.

Ако вам је потребно извршавање алата, аутоматско уређивање датотека или други агентички токови рада, користите **добављача са API кључем** уместо Web Cookie добављача.

# Напомена о валидацији

Успешна **провера везе** или валидација колачића само потврђује да су достављени акредитиви наизглед у очекиваном формату.

Док се проблем #7857 не реши, успешна валидација **не гарантује** да ће добављач успешно извршити аутентификацију.

Ако аутентификација и даље не успева, проверите да ли сте копирали акредитиве из активног мрежног захтева, а не из складишта колачића прегледача.

---

# Решавање проблема

## Аутентификација не успева

Проверите да ли су акредитиви копирани из:

```
Мрежа
→ Заглавља захтева
→ Колачић
```

а **не** из:

```
Апликација
→ Колачићи
```

---

## Колачић ради у прегледачу, али не и у OmniRoute-у

Неки добављачи укључују колачиће који се шаљу само током аутентификованих захтева.

Поново копирајте акредитиве из новог мрежног захтева након што успешно отворите разговор.

---

## Сесија је истекла

Web Cookie добављачи користе вашу постојећу сесију прегледача.

Ако сесија прегледача истекне или се одјавите, морате да копирате нови скуп акредитива. Да бисте аутоматизовали обнављање колачића за подржане веб-добављаче, погледајте пратећи алат [проширење за синхронизацију сесије прегледача](../guides/SESSION-SYNC-EXTENSION.md).

---

## Провера везе пролази, али захтеви не успевају

Док се проблем #7857 не реши, успешна валидација не гарантује да ће захтев за аутентификацију успети.

Поново копирајте акредитиве из новог аутентификованог захтева пре него што наставите са решавањем проблема.

---

# Пример добављача

За комплетно упутство специфично за добављача, погледајте:

- **Claude Web** — `docs/providers/CLAUDE_WEB.md`

Водич за Claude Web приказује комплетан поступак подешавања Web Cookie добављача и служи као референтна имплементација.

# Најбоље праксе

- Копирајте акредитиве из новог аутентификованог захтева.
- Избегавајте поновно коришћење старих колачића.
- Одржавајте сесију прегледача активном док користите Web Cookie добављаче.
- Третирајте копиране колачиће као осетљиве акредитиве.
- Користите добављаче са API кључем када вам је потребно позивање функција или агентички токови рада.
