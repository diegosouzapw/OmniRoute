---

## Шта ради

Уместо да изаберете одређени модел вештачке интелигенције (попут GPT-4o или Claude), можете дозволити да OmniRoute **аутоматски изабере најбољи** за сваки захтев. Узима у обзир:

- **Стање** — Да ли добављач тренутно ради?
- **Брзину** — Колико је брз?
- **Цену** — Колико кошта?
- **Квалитет** — Да ли је добар за ову врсту задатка?
- **Капацитет** — Да ли му је преостала квота?

OmniRoute оцењује све ваше повезане добављаче и бира најбољег. Ако он не успе, аутоматски покушава са следећим.

---

## Брзи почетак

**Корак 1**: Подесите модел на `auto` у свом IDE-у или CLI-ју:

```
model: "auto"
```

**Корак 2**: То је све! OmniRoute се брине за остало.

**Корак 3** (опционално): Користите варијанту за одређене задатке:

```
model: "auto/coding"    # Најбоље за кôд
model: "auto/fast"      # Најбржи одговор
model: "auto/cheap"     # Најјефтинија опција
```

---

## Коју варијанту „auto“ треба да користим?

| Ако желите...           | Користите ово  | Најбоље за                     | Како функционише                                   |
| ----------------------- | -------------- | ------------------------------ | -------------------------------------------------- |
| **Најбоље у целини**    | `auto`         | Општа питања, ћаскање          | Уравнотежује брзину, цену и квалитет               |
| **Најбољи кôд**         | `auto/coding`  | Писање кода, отклањање грешака | Бира моделе добре за програмерске задатке          |
| **Најбржи одговор**     | `auto/fast`    | Брзи одговори, мала латенција  | Даје предност брзини над свим осталим              |
| **Најјефтинија опција** | `auto/cheap`   | Уштеду новца                   | Бира најјефтинијег добављача                       |
| **Најпаметнији модел**  | `auto/smart`   | Сложене задатке                | Квалитет на првом месту + испробавање нових модела |
| **Најдоступнији**       | `auto/offline` | Када су добављачи заузети      | Бира добављаче са највише капацитета               |

### Примери

```bash
# Опште ћаскање — уравнотежено
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'

# Генерисање кода — квалитет на првом месту
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/coding","messages":[{"role":"user","content":"Write a Python function"}]}'

# Брз одговор — брзина на првом месту
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/fast","messages":[{"role":"user","content":"What is 2+2?"}]}'
```

## Како функционише (поједностављено)

Када пошаљете захтев са `model: "auto"`, OmniRoute:

1. **Прегледа све ваше повезане добављаче** — Сваког добављача којег сте додали (OpenAI, Anthropic, Google итд.)
2. **Оцењује сваког од њих**, узимајући, између осталог, у обзир:
   - Да ли ради? (стање)
   - Да ли има капацитета? (квота)
   - Колико кошта? (цена)
   - Колико је брз? (брзина)
   - Да ли је добар за овај задатак? (квалитет)
3. **Бира најбољег** — Добављач са највишом оценом добија ваш захтев
4. **Аутоматски се опоравља** — Ако не успе, OmniRoute аутоматски покушава са следећим

### Систем оцењивања

Сваки добављач добија оцену од 0 до 1. Што је оцена виша, то је добављач погоднији.

| Фактор               | Тежина | Шта значи                                    |
| -------------------- | ------ | -------------------------------------------- |
| Стање                | 20%    | Да ли добављач ради? (стање прекидача кола)  |
| Квота                | 15%    | Да ли му је преостао капацитет?              |
| Цена                 | 15%    | Колико је скуп? (јефтиније = виша оцена)     |
| Брзина               | 12%    | Колико је брз? (мања латенција = виша оцена) |
| Погодност за задатак | 8%     | Да ли је добар за ову врсту задатка?         |
| Стабилност           | 5%     | Да ли је доследан? (ниска стопа грешака)     |
| Ниво                 | 5%     | Ниво налога (Ultra > Pro > Free)             |
| Остало               | 20%    | Сродност контекста, густина веза итд.        |

### Како варијанте мењају оцењивање

Свака варијанта користи различите тежине:

| Варијанта      | Даје предност           | Кључне тежине                   |
| -------------- | ----------------------- | ------------------------------- |
| `auto`         | Равнотежи               | health=20%, quota=15%, cost=15% |
| `auto/coding`  | Квалитету               | taskFit=37%, stability=15%      |
| `auto/fast`    | Брзини                  | latency=32%, health=28%         |
| `auto/cheap`   | Цени                    | cost=37%                        |
| `auto/smart`   | Квалитету + истраживању | taskFit=37%, exploration=10%    |
| `auto/offline` | Капацитету              | quota=37%, health=28%           |

## Како се поступа са отказима

OmniRoute има **три слоја заштите**:

### 1. Аутоматски прелазак на резервног провајдера

Ако најбољи провајдер откаже, OmniRoute аутоматски покушава са следећим. Не морате ништа да предузимате.

### 2. Самоопоравак

Ако провајдер настави да отказује:

- **Оцена < 0.2** → Искључује се на 5 минута
- **Прекидач кола је отворен** → Аутоматски се искључује
- **Више од 50% провајдера није доступно** → Режим инцидента (без истраживања)

### 3. Резервна опција за хитне случајеве

Ако сви провајдери откажу, OmniRoute као последњу опцију усмерава захтев ка стабилним бесплатним провајдерима (као што су Kiro или Qoder).

---

## Подршка за више налога

Ако имате више налога за истог провајдера (нпр. два OpenAI кључа), OmniRoute сваки од њих третира као **засебног кандидата**. То значи:

- Налог A има преосталу квоту → користи га
- Налог B има ограничену стопу захтева → прескочи га
- Налог C је јефтинији → дај му предност

Сваки налог се оцењује независно на основу сопственог стања, квоте и брзине.

---

## Истраживање методом вишеруких бандита

OmniRoute повремено **истражује** нове провајдере како би пронашао боље опције:

- **Подразумевано**: 5% захтева одлази насумично изабраним провајдерима
- **Auto/smart**: стопа истраживања од 10%
- **Онемогућено** када више од 50% провајдера није у исправном стању

Ово помаже систему OmniRoute да научи који провајдери најбоље одговарају вашим обрасцима коришћења.

## Честа питања

### „Да ли ће увек изабрати најскупљи модел?“

**Не.** Цена подразумевано чини само 15% оцене. Јефтин, брз и поуздан провајдер може надмашити скупљег. Користите `auto/cheap` ако желите да цена има још већи приоритет.

### „Шта ако провајдер престане да ради?“

OmniRoute га аутоматски прескаче и покушава са следећим. Ако провајдер настави да отказује, привремено се искључује (на 5–30 минута). Не морате ништа да предузимате.

### „Могу ли да видим који је провајдер коришћен?“

Проверите заглавља одговора — OmniRoute у сваки одговор укључује коришћеног провајдера и модел.

### „Да ли учи на основу мог коришћења?“

Да! Систем оцењивања користи историјске податке (кашњење, стопе грешака и стопе успешности) како би временом доносио боље одлуке.

### „Која је разлика између `auto` и `auto/smart`?“

- `auto` — Уравнотежен режим, 5% истраживања
- `auto/smart` — Квалитет на првом месту (исте тежине као код `auto/coding`), 10% истраживања

Користите `auto/smart` када желите најбољи квалитет и прихватате повремено истраживање.

### „Могу ли да наметнем одређеног провајдера?“

Да! Користите комбинацију са стратегијом `priority` уместо `auto`, а затим пошаљите **тачан назив** комбинације као поље `model` (нпр. `model: "my-combo"` — не `auto`). За детаље погледајте [Техничку референцу](../routing/AUTO-COMBO.md).

### „По чему се ово разликује од кружног распоређивања?“

Кружно распоређивање редом пролази кроз провајдере. Аутоматска комбинација **оцењује сваког провајдера** и бира најбољег. Паметнија је — узима у обзир стање, брзину, цену и квалитет.
