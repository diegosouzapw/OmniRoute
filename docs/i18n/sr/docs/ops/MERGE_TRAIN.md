Од v3.8.49 (WS3.2/WS3.4 плана квалитета/брзине), подразумевана путања спајања
прегледаних PR-ова у `release/vX.Y.Z` јесте **Mergify ред за спајање** (`.mergify.yml`);
**ручни воз за спајање**, документован у наставку, представља РЕЗЕРВНУ ОПЦИЈУ — користи се током инцидената,
замрзавања издања или ако се Mergify Open Source план икада промени.

## Подразумевана путања: Mergify ред

1. Кампање су прегледале PR и потврдиле да је зелен, а власник га је одобрио путем своје ⭐
   контроле пре спајања (извештај + одлука по појединачној ставци — погледајте `/merge-prs`, корак 0.75).
2. Власник (или сесија која поступа на основу одлуке власника) примењује ознаку **`queue`**.
   Та ознака ЈЕСТЕ одобрење за спајање; Mergify га само извршава.
3. Mergify групише до 10 PR-ова из реда, проверава групу помоћу брзих контрола
   и спаја их (squash). Црвена група се **аутоматски дели на половине** — проблематични PR
   изолује се за приближно log2(N) поновних провера и уклања из реда; остали настављају.
4. После спајања, континуирани ток рада за проверу исправности издања проверава нови врх при push-у
   и отвара проблем за утврђивање одговорности ако је комбинација изазвала регресију (без аутоматског враћања измена).

Заштитна правила (одговарају строгим правилима #21/#22 из `CLAUDE.md`):

- **Замрзавање издања је активно** → НЕ означавајте PR-ове који циљају замрзнуту грану; најпре их преусмерите на
  активну грану `release/vX+1`.
- **PR друге сесије на којем се тренутно ради** → никада га не означавајте; само власничка сесија ставља
  сопствени рад у ред.
- Измене које се односе само на тестове и PR-ови са ознаком `hotfix` већ покрећу смањени CI (погледајте
  `RELEASE_CHECKLIST.md` → Hotfix Fast-Lane); услови реда прихватају било који
  скуп провера који је заиста покренут (`#check-failure=0` + `#check-pending=0`).

## Резервна опција: ручни воз за спајање

Користи се када ред није доступан. Овим се формализује пракса којом су током циклуса v3.8.47
обрађена 33 PR-а за један дан:

1. **Саставите групу** (~10–30 прегледаних и одобрених PR-ова). Проверите колизије `linked:`
   (исти `tap.testFiles`, исти одељци CHANGELOG-а) и обрадите их серијски.
2. **Проверите ЈЕДНОМ**: у изолованом worktree-у заснованом на врху гране издања локално спојите све
   врхове из групе, а затим покрените скуп провера еквивалентан издању
   (`npm run check:release-green`, додајте `--with-build` пре издања).
   `scripts/release/merge-train.sh <base> <PR#>…` аутоматизује кораке 1–2 (PR-ови са конфликтима
   се избацују, а воз наставља). Потпуни режим покреће `npm run test:unit` — покретач
   подешен за машину (`--test-concurrency=20`), **а не** два узастопна CI сегмента са по 4 језгра,
   због којих је доминантна фаза користила око 25% машине са 16 језгара (исправљено
   2026-07-18). `--fast` (унутардневна пражњења великих возова, одобрио власник 2026-07-18)
   задржава сваку статичку контролу + vitest, али покреће само node:test датотеке које су изменили
   укрцани PR-ови; ПОТПУНИ скуп и даље мора да се покрене најмање једном дневно над
   акумулираним врхом (један воз без `--fast`).
3. **Зелено** → спојите PR-ове редом (поново проверавајући `state,headRefOid` пре сваког —
   PR чији је врх померен враћа се на преглед). Докажите да је нето разлика сваког спајања
   управо сопствена измена тог PR-а (без враћања измена путем аутоматског разрешавања: прегледајте `git diff --stat`
   ради брисања ван опсега).
4. **Црвено** → поделите групу на половине (проверите сваку половину) уместо да поново проверавате
   један по један PR; вратите проблематични PR у ред за преглед, заједно са доказима.
5. **Никада**: не спајати у замрзнуту грану током замрзавања; не користити `git stash` нигде;
   не покретати CI изнова без разлике у нади да ће црвени резултат нестати (правило: црвени резултат је информација).

## Нивои (зашто је ред безбедан само са брзим контролама)

- **По PR-у** (брзе контроле из quality.yml): тестови на које утиче TIA + потпуни јединични тестови у 4 сегмента +
  vitest + скуп lint провера + провера типова + интегритет документације/евиденције измена.
- **По групи/врху** (континуирана провера исправности издања): `--quick` СТРОГЕ контроле при сваком push-у на
  грану издања; потпуне провере `--with-build --full-ci` 3× дневно.
- **По издању** (ci.yml на PR-у издања): комплетна матрица, укључујући E2E ×9,
  артефакт пакета + основни тест покретања tarball-а, покривеност/прагове који се само повећавају.

Ништа се не проверава мање него раније — захтевне провере се само покрећу по групи/врху
уместо по PR-у, чиме се уклања O(N) кругова провере.
