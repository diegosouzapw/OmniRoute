Користите овај водич да изаберете најмањи поуздан развојни циклус за pull request. Он не
замењује доле наведене документе о архитектури и безбедности специфичне за појединачне области; он повезује сваки уобичајени
тип измене са његовим уговорима, циљаним проверама и CI покривеношћу.

## Путања коју прати свака измена

1. **Изаберите основну грану пре уређивања.** Пронађите највишу активну грану `release/v*` и направите грану од
   њеног врха. Усмерите измену ка тој грани, а не ка `main`. Ако је замрзавање издања активно, немојте усмеравати измену ка замрзнутој
   грани; користите следећи активни циклус описан у документу
   [Модел гранања и издавања](BRANCHING_MODEL.md).
2. **Наведите уговоре.** Идентификујте сваки каталог, шему, генерисани артефакт, јавни API или кориснички
   интерфејс на који измена утиче. Табела испод даје минимални почетни скуп.
3. **Напишите или ажурирајте циљане тестове.** Измене продукционог кода у `src/`, `open-sse/`, `electron/` или
   `bin/` захтевају аутоматизовани тест у истом PR-у. Покрените најмањи скуп тест-датотека који доказује
   понашање, а затим наведене циљане контроле.
4. **Препустите CI-ју покретање широке матрице.** Комплетни сегменти јединичних тестова, Vitest, постепено пооштравање покривености и
   продукционо изграђивање покрећу се у оквиру PR-а. Шири скуп тестова покрените локално само када циљани неуспех указује на
   шири утицај или када измена обухвата више подсистема.
5. **Ускладите измене пре прегледа.** Преузмите активну основну грану, прегледајте њене нове commit-ове и разлику својих измена у односу
   на њу, а затим примените rebase или merge основне гране у складу са поступком за сараднике. Решите конфликте у генерисаним датотекама
   и каталозима почевши од њиховог извора, поново их генеришите, поново покрените циљани циклус и потврдите да
   је PR и даље усмерен ка активној грани издања.
6. **Забележите доказе.** У PR шаблону наведите покренуте команде, сваку додату или измењену тест-датотеку,
   миграције или заставице функција и све провере које се извршавају само у CI-ју, а које су још на чекању.

## Препоручене путање према типу измене

Команде испод представљају минималне циљане провере, а не дозволу да прескочите тест који непосредно покрива
понашање које сте изменили.

### Провајдер

**Уговори**

- Дефиниција провајдера у `src/shared/constants/providers/` и њено компоновање у
  `src/shared/constants/providers.ts`.
- Модели и могућности у `open-sse/config/providerRegistry.ts` или његовим издвојеним датотекама регистра.
- Избор извршиоца/преводиоца, OAuth конфигурација или конфигурација API кључа, ресурси контролне табле и генерисана
  референца провајдера када је применљиво.
- Јавни акредитиви морају да користе `resolvePublicCred()`; одговори о грешкама морају да користе дељене помоћне функције за
  уклањање осетљивих података. Погледајте `docs/security/PUBLIC_CREDS.md` (git; не компајлира се у `/docs`) и
  [Уклањање осетљивих података из грешака](../security/ERROR_SANITIZATION.md).

**Циљани циклус**

```bash
npm run check:provider-consistency
npm run check:provider-assets
node --import tsx/esm --test tests/unit/provider-translate-path-golden.test.ts
node --import tsx/esm --test tests/unit/<provider-or-executor>.test.ts
npm run gen:provider-reference   # када се каталог промени; commit-ујте генерисану разлику
npm run lint
```

Такође тестирајте сваку погођену породицу захтева: ћаскање, Responses, слике, угнежђивања, звук или видео.
Прегледајте генерисане разлике каталога и референтних резултата као измене уговора; немојте их прихватати без провере.

### Усмеравање

**Уговори**

- Јавне вредности стратегија и метаподаци корисничког интерфејса у `src/shared/constants/routingStrategies.ts`.
- Расподела и редослед у `open-sse/services/combo.ts` и `open-sse/services/combo/`.
- Combo шеме, трајно чување, стање отпорности, могућности модела и API/UI контроле.
- [Auto-Combo механизам](../routing/AUTO-COMBO.md) и документација о отпорности када се понашање промени.

**Циљани циклус**

```bash
node --import tsx/esm --test tests/unit/combo-<behavior>.test.ts
npm run test:combo:matrix        # измене стратегије или расподеле
npm run check:known-symbols      # измене регистрације стратегије
npm run lint
```

Локално користите детерминистичке тестове са симулираним узводним системом. Кратки тестови живог combo система захтевају акредитиве и
извршавају се ручно; они нису замена за CI.

### UI / UX

**Уговори**

- Next.js рута/страница и границе дељених компоненти у `src/app/` и
  `src/shared/components/`.
- Облици API одговора, стања учитавања/празног садржаја/грешке, понашање тастатуре и читача екрана,
  прилагодљив распоред, теме и проширење локализације.
- Изворни енглески текстови корисничког интерфејса у `src/i18n/messages/en.json`; немојте директно уносити нови текст намењен корисницима у кôд.

**Циљани циклус**

```bash
node --import tsx --test tests/unit/dashboard/<feature>.test.ts
npx vitest run --config vitest.config.ts tests/unit/ui/<component>.test.tsx
npm run check:dashboard-typecheck
npm run lint
```

Покрените апликацију за измене интеракције или визуелног приказа и проверите и уске и широке приказе. CI покреће
продукционо изграђивање и шире скупове тестова; визуелно понашање и даље захтева циљани тест компоненте, Playwright
или документовану ручну проверу примерену измени.

### i18n

**Уговори**

- `src/i18n/messages/en.json` је извор корисничког интерфејса; `config/i18n.json` је извор локализација.
- CLI каталози се чувају одвојено у `bin/cli/locales/`.
- Сачувајте ICU места за уметање и ознаке у потпуности непромењене. Немојте преводити називе производа/провајдера/модела,
  називе протокола и заглавља, команде, идентификаторе кода/JSON-а, URL-ове, променљиве окружења или
  заштићене термине као што су `OmniRoute`, `OAuth`, `MCP` и `A2A`. Тренутна изворна листа је
  `scripts/i18n/glossary/protected-terms.json`.

**Циљани циклус**

```bash
npm run i18n:sync-ui:dry
npm run i18n:check-ui-coverage
npm run i18n:check-value-drift
npm run i18n:check-glossary
npm run check:cli-i18n          # када се CLI текстови/каталози промене
npm run lint
```

Ово су смернице за постојећи систем, а не позив да се проширују његови алати или модел кључева.
Нека i18n исправке буду строго ограничене док се осмишљава заменски систем. Немојте покретати команде за превођење
које позивају спољне услуге, осим ако задатак изричито захтева генерисане преводе и
ако сте прегледали насталу разлику.

### CLI

**Уговори**

- Јавне команде и заставице у `bin/cli/`, генерисане API команде, излазни кодови, stdout/stderr и
  облици JSON излаза, понашање конфигурације/окружења и датотеке укључене у пакет.
- CLI текстови намењени корисницима морају да користе CLI i18n слој и да одржавају каталоге `en`/`pt-BR` усклађеним.
- Очувајте Node као подржано извршно окружење и уговор објављене бинарне датотеке.

**Фокусирани циклус**

```bash
node --import tsx/esm --test tests/unit/cli/<command>.test.ts
npm run check:cli-i18n
npm run build:cli             # измене генерисаног/обједињеног CLI-ја
npm run check:pack-policy     # измене површине пакета
npm run lint
```

Користите тачну команду у привременом директоријуму за податке када понашање зависи од рашчлањивања, датотека или излазног
статуса. CI обавља шире провере артефаката пакета и екосистема.

### База података

**Уговори**

- Модули домена у `src/lib/db/`; директно увозите одређене модуле (стари слој за поновни извоз `localDb.ts` је уклоњен).
- Нумерисане, идемпотентне SQL миграције у `src/lib/db/migrations/`, безбедност трансакција, понашање
  надоградње, индекси и сваки позивалац на који шема утиче.
- Руте и обрађивачи никада не извршавају сирови SQL директно.

**Фокусирани циклус**

```bash
npm run check:migration-numbering
npm run check:db-rules
node --import tsx/esm --test tests/unit/db/<domain>.test.ts
node --import tsx/esm --test tests/unit/db/migration-<number>.test.ts
npm run lint
```

При додавању миграције тестирајте и нову базу података и надоградњу са претходне шеме. Тестови базе података
морају да затворе ресурсе и позову `resetDbInstance()` током чишћења. Покрените `npm run test:bun:db` само када
се промени незагарантована путања Bun адаптера; Node остаје меродаван.

### Изградња / примена

**Уговори**

- Коренски манифести и манифести радних простора/датотека закључавања, `scripts/build/`, самостално Next.js склапање, садржај
  пакета `dist/`, Electron метаподаци платформе, CI токови рада и контролне ознаке примене.
- Подржани Node опсези и дозвољена употреба Bun-а наведена у `CLAUDE.md` морају остати непромењени.
- Артефакти изградње остају ван праћења; примењују се смернице за зависности, лиценце, токове рада и пакете.

**Фокусирани циклус**

```bash
node --import tsx/esm --test tests/unit/build/<behavior>.test.ts
npm run check:build-scope
npm run check:lockfile         # измене зависности или датотеке закључавања
npm run check:pack-policy      # измене површине објављеног пакета
npm run lint
```

Локално користите `npm run build` само када измена утиче на компилацију, самостално склапање, ресурсе
или обједињавање извршног окружења. Користите `npm run build:release` само за проверу издања/примене. CI изградња је
коначни сигнал за више платформи; измене Electron-а специфичне за платформу захтевају одговарајућу фокусирану изградњу
или доказ основне провере.

## Lokalna petlja naspram CI-ja

| Pokrenuti lokalno za svaku izmenu                                                    | CI pruža širi signal                                                                          |
| ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| Direktni testovi ponašanja i gore navedene provere kategorija                        | Podeljeni komplet svih jediničnih testova i serijski testovi                                  |
| `npm run lint`                                                                       | Vitest skupovi testova i pragovi pokrivenosti/kvaliteta                                       |
| Provera tipova ili izgradnja samo kada to zahteva ugovor na koji izmena utiče        | Produkciona izgradnja, bezbednosne provere, dokumentacija, zavisnosti i provere pravila za PR |
| Ručne interakcije/provere uživo samo kada automatizacija ne može potvrditi ponašanje | Integracione provere između poslova i provere platformi konfigurisane tokom rada              |

Uspešna fokusirana petlja jeste dokaz u vezi sa izmenjenim ugovorom, ali nije potvrda da će nepovezane CI provere
proći. S druge strane, nemojte da svaka lokalna izmena čeka punu matricu repozitorijuma.

## Kontrolna lista za usaglašavanje

Pre nego što zatražite pregled:

- Potvrdite da je osnova PR-a i dalje najviša aktivna grana `release/v*`.
- Preuzmite tu osnovu i pregledajte commit-e koji su dodati otkako ste napravili svoju granu.
- Pregledajte `git diff <active-base>...HEAD` kako biste uočili slučajne ili generisane izmene.
- Rešite konflikte u katalozima i generisanim dokumentima ažuriranjem izvora i ponovnim generisanjem izlaza.
- Nakon usaglašavanja ponovo pokrenite svaki fokusirani test/proveru navedenu u opisu PR-a.
- Nikada nemojte ublažavati tvrdnje niti uklanjati obavezne testove samo da biste se uskladili sa pomerenom osnovom.

Za pravila zamrzavanja izdanja i promene ciljne grane koristite
[Model grananja i izdanja](BRANCHING_MODEL.md). Za kompletan spisak CI provera koristite
[Referencu za provere kvaliteta](../architecture/QUALITY_GATES.md).
