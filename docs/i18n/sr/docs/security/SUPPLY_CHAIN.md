OmniRoute објављује npm + Docker артефакте. Ове контроле обезбеђују порекло,
инвентар (SBOM) и CVE скенирање, све помоћу OSS алата, интегрисаних у токове рада за издавање.
Приступ је **прво упозорење** — сада само извештавају, а постају блокирајуће након првог
успешног издања.

| Контрола                | Алат                                           | Где                            | Блокира?                     | Излаз                                             |
| ----------------------- | ---------------------------------------------- | ------------------------------ | ---------------------------- | ------------------------------------------------- |
| SLSA порекло (npm)      | `npm --provenance` (OIDC)                      | `npm-publish.yml`              | само ако објављивање не успе | npmjs беџ / `npm audit signatures`                |
| SBOM за npm             | `@cyclonedx/cyclonedx-npm`                     | `npm-publish.yml`              | само ако генерисање не успе  | Артефакт издања + артефакт                        |
| SBOM слике              | `anchore/sbom-action` (syft)                   | `docker-publish.yml` (спајање) | упозоравајуће                | CycloneDX артефакт                                |
| Trivy CVE (SARIF)       | `aquasecurity/trivy-action`                    | `docker-publish.yml` (спајање) | упозоравајуће                | SARIF (HIGH+CRITICAL) → картица Security          |
| Trivy CRITICAL контрола | `aquasecurity/trivy-action`                    | `docker-publish.yml` (спајање) | **блокирајуће**              | `exit-code: '1'` за поправљиве CRITICAL рањивости |
| osv vulnCount           | `osv-scanner` (`check:vuln-ratchet --ratchet`) | `ci.yml` (`quality-extended`)  | **блокирајуће**              | ограничава `metrics.vulnCount` (direction:down)   |
| OpenSSF Scorecard       | `ossf/scorecard-action`                        | `scorecard.yml` (cron)         | упозоравајуће                | SARIF → Security + беџ                            |

CVE ограничење за слику користи **два корака** у `docker-publish.yml`: SARIF корак
(`HIGH,CRITICAL`, `exit-code: 0`) одржава HIGH+CRITICAL рањивости видљивим на картици Security
без блокирања; корак _CRITICAL контроле_ (`severity: CRITICAL`, `ignore-unfixed: true`,
`exit-code: 1`) обара издање ако постоји CRITICAL CVE **за који је доступна исправка**. `ignore-unfixed`
спречава блокирање издања због CVE-а у основној слици за који не постоји узводна закрпа.

## ⚠️ CVE варијабилност (блокирајуће osv/Trivy контроле)

osv и Trivy пореде зависности са CVE базама података које **непрекидно расту**. PR
који **не мења ниједну зависност** може изненада постати црвен зато што је откривен нови CVE
у постојећој зависности (osv: измерени `vulnCount` > основна вредност; Trivy: нова
поправљива CRITICAL рањивост у слици). **Ово је ОЧЕКИВАНО оперативно понашање блокирајуће
CVE контроле, а не регресија производа.**

Када osv или Trivy постану црвени због новооткривеног CVE-а, решење је:

1. **Ажурирајте погођену зависност** (препоручено) — надоградите је на закрпљену верзију преко `package.json`
   `overrides` (транзитивне зависности) или поново изградите слику на закрпљеној основи.
2. **Ако не постоји узводна исправка:**
   - **osv:** поново поставите основну вредност за `metrics.vulnCount` у `config/quality/quality-baseline.json`
     (`npm run quality:ratchet -- --update` не обухвата наменске контроле — ручно измените вредност,
     `direction:down`) уз напомену са образложењем + проблем за праћење.
   - **Trivy:** додајте унос у `.trivyignore` (један CVE-ID по реду) уз коментар
     са образложењем + проблем за праћење. `ignore-unfixed: true` већ аутоматски
     обухвата CVE-ове без закрпа.

Обе контроле **безбедно ПРЕСКАЧУ** проверу (излаз 0) када алат није присутан или мерење
не успе (osv-scanner није у PATH, osv.dev/мрежа је недоступна, неважећи JSON) —
неуспех **мерења** никада не блокира; блокира само **измерена** регресија.

## Заостатак: Scorecard упозоравајући → блокирајући

Након првог успешног издања са Scorecard извештавањем:

- Scorecard: ограничење резултата (замрзава измерени резултат; не може се смањити).

Допуњује контроле из фазе 7 (osv-scanner, gitleaks, actionlint+zizmor): zizmor
проверава саме токове рада; Scorecard мери укупан безбедносни положај репозиторијума.
