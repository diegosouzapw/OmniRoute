> **Напомена о опсегу:** `socket.yml` конфигурише скенирање npm артефакта које Socket.dev обавља на страни регистра након објављивања (путање које се занемарују за садржај који се не испоручује, као што су `tests/`, `docs/` и извештаји о изградњи). Он не поставља контролну тачку за спајање у CI/PR процесу — ниједан ток рада у `.github/workflows`, ниједна скрипта у `package.json` и ниједан циљ у `Makefile` не позива Socket.dev.

Овај документ је потврда аутора-одржаваоца за шест налаза
`AI-detected potential malware` пријављених за `omniroute@3.8.5` и
мере ублажавања примењене у `omniroute@3.8.6`. Постоји како би:

1. Оператери безбедносног процеса имали једну референцу коју могу да наведу када треба
   да процене налазе у односу на стварни изворни код.
2. Будући AI скенери могли да препознају тврдњу коју је потписао одржавалац да је свака
   означена путања намерна, опциона и документована.
3. Имали писани запис о томе _зашто_ је свако место позива обликовано на тај начин —
   како нека будућа рефакторизација не би случајно поново увела образац који
   је намерно уклоњен.

Ако управљате скенером који поново означи било које од места позива у наставку након што
мере ублажавања из v3.8.6 буду објављене, отворите пријаву проблема са трагом скенирања и
овде ћемо проширити потврду.

## §1 — Инсталација MITM кореног CA сертификата (`77484.js`)

**Изворне датотеке**:

- `src/mitm/cert/install.ts` — јавне функције `installCert()` / `uninstallCert()`,
  као и `installCertWindows/Mac/Linux` специфичне за сваку платформу.
- `src/mitm/systemCommands.ts` — заједничке помоћне функције за `execFile` / `spawn` / PowerShell
  које користе путање за инсталацију.

**Окидач**: корисник кликне на „Омогући MITM прокси“ на локалној контролној табли на
`/dashboard/cli-tools/mitm`. Рута је доступна само преко loopback интерфејса — погледајте строго правило бр. 17 у
`CLAUDE.md` и `src/server/authz/routeGuard.ts::isLocalOnlyPath()`. Процурели
JWT изложен преко тунела **не може** да покрене ову путању кода.

**Извршене привилеговане операције (по платформи)**:

| OS                     | Команда/команде                                                                                                   |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | `certutil -addstore Root <cert>` преко UAC                                                                        |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | ажурирање NSS DB-а за сваки профил преко `certutil -d sql:<profile>`                                              |

Ово су исте команде које користе `mitmproxy`, Charles Proxy, Fiddler и
Caddy. Чињеница да постоје у OmniRoute-у документована је у
`docs/security/STEALTH_GUIDE.md`.

**Мере ублажавања у v3.8.6**:

- `runElevatedPowerShell()` више не користи `-EncodedCommand <base64utf16le>`.
  Садржај који се извршава са повишеним привилегијама уписује се у привремену `.ps1` датотеку за сваки позив (режим 0o600,
  унутар приватног `mkdtempSync` директоријума) и прослеђује преко `-File`. Датотека
  се уклања у блоку `finally`. Тиме се уклања препознатљиви образац
  подизања привилегија преко PowerShell-а коришћењем base64 кодирања, који је означио AI
  класификатор компаније Socket.dev.
- `installCertWindows` садржи уграђени блок `SECURITY-AUDITOR-NOTE:`
  који упућује на овај документ.

**Зашто ово задржавамо**: MITM прокси је документована функција која се користи у
`docs/security/STEALTH_GUIDE.md` и `docs/frameworks/MITM-PROXY.md`. Њено уклањање
би онемогућило скуп функција agent-bridge-а.

## §2 — Увоз Zed акредитива (`app/api/providers/zed/import/route.js`)

**Изворне датотеке**:

- `src/app/api/providers/zed/discover/route.ts` _(ново у v3.8.6)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(ново у v3.8.6)_

**Окидач**: корисник кликне на „Увези из Zed-а“ на страници „Провајдери“
локалне контролне табле. Приступ крајњој тачки је ограничен помоћу
`requireManagementAuth`. Сам Zed уређивач уписује API кључеве својих провајдера
у складиште кључева оперативног система под документованим називима услуга —
погледајте https://zed.dev/docs/ai/llm-providers.

**Понашање у v3.8.5 (оно које је Socket.dev означио)**:

`POST /import` је проналазио акредитиве и аутоматски их чувао у локалном
SQLite складишту у једном циклусу захтева и одговора. Без потврде за сваки
налог, без отиска, само „пронађено је N токена, сви су увезени“.

**Ублажавање ризика у v3.8.6 — потврда у 2 корака**:

1. **`POST /api/providers/zed/discover`** враћа
   `{ candidates: [{ provider, service, account, fingerprint }] }`. Необрађени
   токен се **никада** не преноси. Отисак је
   `sha256(service|account|token).slice(0,16)`.
2. Контролна табла приказује листу кандидата, оператер бира које жели да
   увезе и шаље `{ confirmedAccounts: [{ service, account, fingerprint }] }`
   на **`POST /api/providers/zed/import`**.
3. Крајња тачка за увоз **поново чита складиште кључева на серверу** и филтрира
   према `(service, account, fingerprint)`. Измењен или поново употребљен
   одговор операције откривања не може да наведе крајњу тачку за увоз да сачува
   неповезан токен — ако се активни токен променио након откривања, отисак се
   више не подудара и акредитив се прескаче.

Променљива окружења `OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` задржава
понашање из v3.8.5 за оператере који још нису ажурирали своју аутоматизацију.
Биће уклоњена у v3.9.

**Зашто ово задржавамо**: Zed увоз је најједноставнији начин почетног
подешавања за кориснике који већ користе Zed и желе да пресликају кључеве својих
провајдера у OmniRoute без поновног налепљивања.

## §3 — `execFile` / `spawn` / PowerShell са повишеним привилегијама (`21843.js`)

**Изворне датотеке**: `src/mitm/systemCommands.ts`.

**Зашто је означено**: сегмент поново извози `execFileWithPassword`,
`runElevatedPowerShell` и заједничку помоћну функцију `quotePowerShell`.
AI класификатор сервиса Socket.dev препознаје их као генерички „комплет алата
за извршавање на рачунару домаћину и подизање привилегија“. У оквиру
OmniRoute-а користе се само у путањи за инсталацију MITM сертификата (§1) и
у `execFileWithPassword` за извршавање `sudo` команде.

**Ублажавање ризика у v3.8.6**:

- Рефакторисање функције `runElevatedPowerShell` (погледајте §1).
- Уметнути блок `SECURITY-AUDITOR-NOTE:` код функција
  `runElevatedPowerShell` и `execFileWithPassword` документује позиваоце са
  листе дозвољених и фиксирану листу извршних датотека.
- Позив `spawn()` у `execFileWithPassword` садржи ознаку `nosemgrep` са
  листом дозвољених извршних датотека које помоћна функција сме да прими —
  **не постоји путања од корисничког уноса до `finalCommand`/`finalArgs`**.

## §4 / §6 — Надзорник услуге 9router (`api/services/9router/{start,restart}/route.js`)

**Изворне датотеке**:

- `src/app/api/services/9router/_lib.ts` — фабрика надзорника.
- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`.
- `src/lib/services/ServiceSupervisor.ts` — генеричко покретање / провера
  стања / баферовање евиденције.

**Окидач**: корисник кликне на „Инсталирај“ / „Покрени“ на страници уграђених
услуга у локалној контролној табли.

**Већ примењене заштите**:

- Све руте `/api/services/*` имају ограничење LOCAL_ONLY у складу са
  `src/server/authz/routeGuard.ts` (строго правило #17). Ограничавање на
  интерфејс повратне петље спроводи се пре било какве провере аутентичности —
  JWT који је процурео не може да им приступи.
- Ред за 9router у бази података иницијално се поставља на
  `status='not_installed', auto_start=0` (погледајте
  `src/lib/db/migrations/071_services.sql:19`). Услуга се **не** покреће при
  првом покретању апликације.
- `spawn()` се позива са путањом бинарне датотеке коју враћа
  `resolveSpawnArgs(apiKey, PORT)` у `src/lib/services/installers/ninerouter.ts`,
  што представља фиксну листу подржаних бинарних датотека.
- Стандардни излаз/излаз грешака баферује се у меморији (ограничење од 5 MB,
  погледајте `_lib.ts`) — нема уписивања на диск осим ако корисник не омогући
  вођење евиденције на контролној табли.

**Ублажавање ризика у v3.8.6**: нема функционалних измена. Минимални профил
изградње (`OMNIROUTE_BUILD_PROFILE=minimal`) замењује
`src/lib/services/installers/ninerouter.ts` заменском имплементацијом за
кориснике који желе да привилеговане путање буду физички уклоњене из пакета.

**Зашто ово задржавамо**: 9router је опционална пратећа услуга која се може
локално инсталирати (слично WordPress додатку) — искључиво уз изричито
укључивање.

## §5 — Упис акредитива из OmniRoute Cloud Sync-а назад (`api/keys/[id]/route.js`)

**Изворне датотеке**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`.
- `src/app/api/keys/[id]/route.ts` — позива `syncKeysToCloudIfEnabled()`.

**Окидач**: `isCloudEnabled()` враћа `true` (подешава се преко контролне табле) **и**
`CLOUD_URL` је конфигурисан. Када су оба искључена, не упућује се ниједан одлазни мрежни позив ка
Cloud крајњој тачки.

**Понашање у v3.8.5 (грешка коју је Socket.dev исправно открио)**:

`updateLocalTokens()` је преписивао `accessToken`, `refreshToken` и
`providerSpecificData` из Cloud одговора када је
`cloudUpdatedAt > localUpdatedAt`. Без HMAC-а, без потписа, без контролне суме.
Погрешно конфигурисан или злонамеран `CLOUD_URL` (или MITM на каналу) могао је
неприметно да замени OAuth токене добављача.

**Ублажавање ризика у v3.8.6**:

1. **HMAC верификација**: `verifyCloudSignature(rawBody, sigHeader)` проверава
   заглавље `X-Cloud-Sig` (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`) пре парсирања JSON-а. Ако је тајна подешена, потпис је
   обавезан. Ако није (застарели режим), бележи се упозорење и одговор се
   прихвата — тајна ће бити обавезна у v3.9.
2. **Експлицитно укључивање тајних поља**: `accessToken` / `refreshToken` /
   `providerSpecificData` преписују се **само** када је
   `OMNIROUTE_CLOUD_SYNC_SECRETS=true`. Подразумевани режим синхронизује само
   метаподатке који нису акредитиви (`expiresAt`, `status`, `lastError*`,
   `rateLimitedUntil`, `updatedAt`). Ово је **неускладива промена** за кориснике
   који су се ослањали на удаљену синхронизацију токена — морају је експлицитно укључити.

**Зашто ово задржавамо**: Cloud Sync је једини начин да закупац OmniRoute Cloud-а
централизује тимске акредитиве. Исправка чини модел претњи реалним:
„сервер потписује, клијент проверава, оператер експлицитно укључује.“

## Профил изградње: `minimal`

За кориснике којима је потребан артефакт прилагођен Socket-у, изградњу покрените са:

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

Webpack додатак `NormalModuleReplacementPlugin` замењује четири модула псеудоимплементацијама:

| Модул                                       | Псеудоимплементација                             |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

Свака псеудоимплементација извози исти интерфејс, али свака функција током извршавања баца
`featureDisabledError(name)`. Руте које зависе од онемогућеног
модула враћају HTTP 503 са јасном поруком уместо активирања
осетљиве путање кода.

Добијени пакет је намењен објављивању као `omniroute-secure`. Рецепт за објављивање потражите у
`docs/ops/PUBLISHING_SECURE.md`.
