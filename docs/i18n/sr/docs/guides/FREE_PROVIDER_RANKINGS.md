> **Укратко**: OmniRoute рангира своје **бесплатне** провајдере према квалитету модела користећи **Arena AI
> (у стилу LMArena) ELO резултате**. Отворите страницу **Рангирање бесплатних провајдера** на
> контролној табли да бисте видели који бесплатни провајдери нуде најмоћније моделе за ваш задатак —
> укупно или филтрирано по категорији (кодирање, преглед, документација, отклањање грешака).

---

## Шта је то

OmniRoute региструје 329 провајдера, укључујући 155 ставки каталога означених као **бесплатне/без аутентификације**
(без аутентификације,
OAuth бесплатног нивоа или API кључ бесплатног нивоа — погледајте
[Водич за бесплатне нивое](../getting-started/FREE-TIERS-GUIDE.md) и комплетан
[директоријум бесплатних нивоа](../reference/FREE_TIERS.md)). Проблем је у томе што се бесплатни провајдери
веома разликују по квалитету модела. Провајдер без аутентификације који нуди најсавременији модел далеко је кориснији
од оног који нуди мали застарели модел.

**Рангирање бесплатних провајдера** одговара на питање „**који бесплатни провајдер ми пружа најбољи модел?**“ тако што
повезује каталог сваког бесплатног провајдера са **оценама квалитета заснованим на доприносима заједнице** са
**Arena AI ранг-листе** (ELO заснован на људским преференцама, исти концепт који стоји иза LMArena
арене чет-ботова). Провајдери се затим рангирају према снази свог **најбољег бесплатног модела**.

Рангирање се израчунава на основу три стварна извора:

1. Листе бесплатних провајдера — `NOAUTH_PROVIDERS`, као и ставке `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` означене са `hasFree`
   (`src/shared/constants/providers.ts`).
2. Каталог модела сваког провајдера из регистра провајдера
   (`open-sse/config/providerRegistry.ts`).
3. Резултати прикладности за задатке изведени из ELO-а, које механизам за синхронизацију Arena ELO-а чува у
   DB табели `model_intelligence` (`src/lib/arenaEloSync.ts`).

Логика повезивања налази се у `src/lib/freeProviderRankings.ts`.

## Како приступити

### Страница контролне табле

Отворите контролну таблу и идите на **Трошкови → Рангирање бесплатних провајдера** или директно отворите:

```
/dashboard/free-provider-rankings
```

Страница (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) приказује:

- **Победничко постоље за прва 3 места** (🥇 🥈 🥉) најбоље рангираних бесплатних провајдера.
- Комплетну **табелу рангирања** са колонама: **Позиција**, **Провајдер**, **Најбољи модел**,
  **Резултат**, **Просечан резултат**, **Модели**, **Тип**.
- **Дугмад за филтрирање категорија**: _Све категорије_, _Подразумевано_, _Кодирање_, _Преглед_,
  _Документација_, _Отклањање грешака_.

Ознака **Тип** за сваког провајдера показује на који начин је бесплатан:

| Ознака   | Значење                                                 |
| -------- | ------------------------------------------------------- |
| `NOAUTH` | Увек бесплатно, нису потребни акредитиви                |
| `OAUTH`  | OAuth провајдер са бесплатним нивоом (`hasFree`)        |
| `APIKEY` | Провајдер са API кључем и бесплатним нивоом (`hasFree`) |

Резултати су приказани као лако разумљиве ознаке (нпр. _Елитан_, _Одличан_, _Веома добар_,
_Добар_, _Просечан_), а не као необрађени бројеви, јер основна вредност представља релативни
квалитет рангирања, а не проценат.

### API крајња тачка

Страница користи јавну крајњу тачку за читање
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

Параметри упита (проверени помоћу Zod-а):

| Параметар  | Тип    | Подразумевано | Напомене                                                                                                   |
| ---------- | ------ | ------------- | ---------------------------------------------------------------------------------------------------------- |
| `category` | string | (нема)        | Једно од `default`, `coding`, `review`, `documentation`, `debugging`. Изоставите за комбиновано рангирање. |
| `limit`    | number | `50`          | Ограничено на опсег `1–100`.                                                                               |

Облик одговора:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` је оригинална Arena ELO вредност; `score` је нормализована вредност прикладности за задатак
(погледајте испод). Провајдери без оцењених модела изостављају се из одговора.

## Како функционишу оцене

### Извор: Arena AI ранг-листа

Механизам за синхронизацију Arena ELO оцена (`src/lib/arenaEloSync.ts`) преузима две ранг-листе — `text`
и `code` — из API-ја Arena AI ранг-листе
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`). Свака ставка ранг-листе
садржи назив модела, добављача, ELO `score`, интервал поузданости и број гласова.

Категорије ранг-листе мапирају се на OmniRoute категорије задатака:

| Arena ранг-листа | OmniRoute категорије задатака                     |
| ---------------- | ------------------------------------------------- |
| `text`           | `default`, `review`, `documentation`, `debugging` |
| `code`           | `coding`                                          |

### Нормализација (оцена прикладности за задатак)

Необрађене ELO оцене нормализују се за сваку ранг-листу у **вредност прикладности за задатак у опсегу `[0.4, 0.98]`**:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

Оцена никада не достиже `0` или `1`, чиме се оставља простор за корисничка прилагођавања. То је
поље `score` које видите у API одговору и ознака приказана на контролној табли.

### Поузданост

Свака ставка добија ниво поузданости на основу броја гласова у Arena систему:

| Поузданост | Гласови |
| ---------- | ------- |
| `high`     | ≥ 5.000 |
| `medium`   | ≥ 1.000 |
| `low`      | < 1.000 |

### Складиштење и свежина података

Нормализоване ставке уписују се у DB табелу `model_intelligence` са
`source = "arena_elo"` (`src/lib/db/modelIntelligence.ts`). Ставке **истичу након
7 дана**, тако да добављач који престане да се синхронизује временом нестаје уместо да
приказује застареле податке.

Синхронизација је **подразумевано укључена**:

- Покреће се једном при покретању сервера, а затим периодично помоћу тајмера
  (`src/lib/arenaEloSync.ts`, повезано из `src/instrumentation-node.ts`).
- Она је **неблокирајућа и никада није фатална** — ако преузимање са изворног сервера не успе, OmniRoute наставља
  да ради, а ранг-листе једноставно приказују последње исправне податке (или празно стање).

Њоме управљају две променљиве окружења (документоване у
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)):

| Променљива                | Подразумевано | Намена                                                          |
| ------------------------- | ------------- | --------------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | Поставите на `false` да бисте искључили одлазну синхронизацију. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | Интервал синхронизације, у секундама.                           |

### Ручна синхронизација / статус / брисање

Операторима је за ручно управљање доступна аутентификована управљачка крајња тачка
(`src/app/api/intelligence/sync/route.ts` — захтева управљачку аутентификацију):

```
GET    /api/intelligence/sync          # тренутни статус синхронизације (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # покрени ручну синхронизацију; тело: { "dryRun": true } за преглед без уписивања
DELETE /api/intelligence/sync          # обриши све синхронизоване arena_elo intelligence ставке
```

Ако је страница са ранг-листама празна, ручни `POST /api/intelligence/sync` (или једноставно
поновно покретање сервера) поново је попуњава.

### Упаривање модела са ранг-листом

ID-ови модела у регистру и називи Arena модела не подударају се увек у потпуности. Рангирање користи
флексибилно упаривање (`findMatchingIntelligence` у `src/lib/freeProviderRankings.ts`):

1. Потпуно подударање нормализованог ID-а модела.
2. Подударање након уклањања суфикса верзије на крају (нпр. `kimi-k2.6` → `kimi-k2`).
3. Подударање префикса (назив модела на ранг-листи је префикс ID-а у регистру).

На страни синхронизације, познати префикси добављача (`anthropic/`, `openai/`, `google/`, …) се
уклањају, а мала мапа алијаса проширује канонске називе у варијанте које OmniRoute користи
интерно, тако да модели остају доступни под било којим називом.

### Како се добављач рангира

За сваког бесплатног добављача механизам оцењује сваки модел у његовом каталогу, а затим:

- **Најбољи модел** = модел добављача са највишом оценом.
- **Просечна оцена** = средња оцена свих оцењених модела тог добављача.
- **Модели** = број модела добављача који су имали Arena оцену.

Добављачи се прво сортирају према **оцени најбољег модела**, а затим према просечној оцени. Тиме се награђује
добављач који нуди барем један добар бесплатан модел.

## Како га користити за избор бесплатних провајдера

1. **Изаберите одговарајућу категорију.** Користите филтер **Coding** за агентска/програмерска радна оптерећења или
   га оставите на **All Categories** / **Default** за опште ћаскање. Исти провајдер може
   имати различит пласман у различитим категоријама јер се његов најбољи модел разликује у зависности од ранг-листе.
2. **Дајте предност онима на победничком постољу за једнократна подешавања.** Ако желите да повежете само једног или два бесплатна
   провајдера, почните од најбоље рангираних у вашој категорији.
3. **Проверите ознаку Type.** Провајдери типа `NOAUTH` се најбрже повезују (без
   приступних података). Бесплатни нивои типа `OAUTH` / `APIKEY` захтевају брзу регистрацију, али често нуде
   моћније моделе. Погледајте [Водич за бесплатне нивое](../getting-started/FREE-TIERS-GUIDE.md) за
   кораке повезивања.
4. **Повежите више њих и препустите избор Auto-Combo-у.** Исти Arena ELO подаци који покрећу
   ову страницу такође обезбеђују **фактор погодности за задатак** механизма за бодовање Auto-Combo
   (`open-sse/services/autoCombo/taskFitness.ts`, редослед разрешавања:
   `user_override → arena_elo → models_dev_tier → static table`). Дакле, након што повежете
   најбоље бесплатне провајдере, рутирање са `model: "auto"` (нпр. `auto/coding`) ће
   аутоматски давати предност квалитетнијим бесплатним моделима за сваки захтев. Погледајте
   [Auto-Combo](../routing/AUTO-COMBO.md) за комплетно бодовање на основу 16 фактора.
