Како OmniRoute процењује, бележи и приказује трошак сваког захтева — и зашто број на
контролној табли представља **праћење уштеде**, а не рачун.

Погледајте и: [Корисничко упутство](./USER_GUIDE.md) · [Галерија функција](./FEATURES.md)

---

## Шта јесте (а шта није)

OmniRoute сваком довршавању приписује трошак у USD по захтеву тако што множи број
токена ценама одговарајућег модела. Ови бројеви се користе за контролну таблу
**Трошкови**, CLI команде `omniroute cost` / `omniroute usage`, CSV/JSON извозе и
буџете по API кључу.

> **„Трошак“ на контролној табли представља праћење уштеде, а не рачун.** OmniRoute вам
> никада ништа не наплаћује — он усмерава ваше захтеве ка добављачима које сте већ
> повезали (ваше претплате, бесплатни нивои и API кључеви). „Укупан трошак од $290“
> остварен искључиво на бесплатним моделима значи да приближно **$290 _нисте_ платили**
> API-ју који се плаћа. Тај износ је _процена_ тога колико би исти саобраћај коштао по
> стандардним каталошким ценама, како бисте могли да видите где је ваша употреба
> концентрисана и колико штедите усмеравањем ка јефтинијим/бесплатним добављачима.

Ово тумачење је директно наведено у пројектном документу [README](../../README.md)
(„'трошак' на контролној табли представља праћење уштеде, а не рачун“).

Пошто је овај број процена:

- Зависи од табеле цена коју OmniRoute има за сваки модел. Модел без уноса цене
  доприноси трошку са `0` (у прегледачу се приказује као ред „Застарело / Бесплатно“).
- Саобраћај у оквиру бесплатног нивоа и претплате и даље акумулира _процењени_
  трошак — то је износ који штедите, а не износ који дугујете.

## Како се трошкови процењују

### Извор цена

Трошкови потичу из табеле цена која се разрешава према следећем редоследу приоритета
([`src/lib/pricingSync.ts`](../../src/lib/pricingSync.ts)):

1. **Корисничка прилагођавања** — цене које поставите на контролној табли / путем `PATCH /api/pricing`.
2. **Синхронизоване спољне цене** — преузимају се из јавне LiteLLM датотеке
   `model_prices_and_context_window.json` када је синхронизација омогућена (чувају се у
   засебном простору имена `pricing_synced`, тако да никада не преписују ваша прилагођавања).
3. **Подразумеване вредности уграђене у кôд** — испоручују се уз OmniRoute.

Синхронизација спољних цена је **опциона** и подразумевано је онемогућена. Релевантне
променљиве окружења (погледајте [`.env.example`](../../.env.example)):

| Променљива окружења     | Подразумевано | Намена                                                                  |
| ----------------------- | ------------- | ----------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`       | Омогућава позадинску синхронизацију LiteLLM цена при покретању.         |
| `PRICING_SYNC_INTERVAL` | `86400`       | Интервал синхронизације у **секундама** (подразумевано једном дневно).  |
| `PRICING_SYNC_SOURCES`  | `litellm`     | Листа извора раздвојених зарезима (тренутно је подржан само `litellm`). |

### Формула трошка

Трошак се израчунава за сваки захтев на основу броја токена и цена по милион токена у
[`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts)
(`computeCostFromPricing` / `calculateCost`):

- **Улазни токени** (умањени за читања из кеша и токене за креирање кеша) × цена `input`.
- **Токени прочитани из кеша** × цена `cached` (ако није доступна, користи се улазна цена).
- **Токени за креирање кеша** × цена `cache_creation` (ако није доступна, користи се улазна цена).
- **Излазни токени** × цена `output`.
- **Токени закључивања** × цена `reasoning` (ако није доступна, користи се излазна цена).

Све цене се тумаче као USD на 1.000.000 токена. Codex ниво услуге „fast“/„priority“ или
„flex“ примењује множилац трошка (`getCodexFastCostMultiplier`) — на пример, flex се
наплаћује уз попуст од 50% на токене, што се на контролној табли приказује као
**flex уштеда**.

Називи модела се најпре нормализују (уклањају се префикси путање добављача као што су
`openai/` или `accounts/fireworks/models/`) како би се и историјски редови подударали
са ценом.

### Како се потрошња бележи

- Трошак по захтеву израчунава се након одговора и бележи по принципу „покрени и не
  чекај“, тако да клијенту никада не додаје кашњење. Потрошња заједничке квоте заказује
  се у следећем циклусу петље догађаја путем
  [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts).
- Потрошња по API кључу се баферује и пакетно уписује помоћу
  [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (подразумевани интервал уписа
  је 60s, а бафер има 1.000 уноса). Подешава се путем:

  | Променљива окружења                 | Подразумевано | Намена                                       |
  | ----------------------------------- | ------------- | -------------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000`       | Интервал уписа у милисекундама.              |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`        | Максималан број баферованих уноса пре уписа. |

Вредности трошкова на контролној табли се **не** читају из сачуваног доларског износа
за сваки ред — оне се изнова израчунавају у ходу на основу броја токена и тренутне
табеле цена сваки пут када се изврши аналитичка крајња тачка. То значи да исправљање
погрешне цене (и поновна синхронизација) ретроактивно ажурира процене историјских
трошкова.

## Контролна табла: страница Трошкови

Страница **Трошкови** налази се на `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`).
Њен главни приказ је картица **Преглед трошкова**
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`),
која учитава све преко `GET /api/usage/analytics`.

Шта приказује:

- **Плочице потрошње** — процењена потрошња за _данас (1d)_, _7d_, _30d_ и изабрани
  период. Бирач опсега: `7d`, `30d`, `90d`, `all`.
- **Главне метрике** — захтеви у оквиру периода, активни добављачи, активни модели, просечан
  трошак по захтеву.
- **Истраживач трошкова** — табела која се може сортирати и филтрирати, груписана по **добављачу**, **моделу**,
  **API кључу**, **налогу** или **нивоу услуге**, са трошковима, захтевима, токенима, просечним
  трошком по захтеву и процентуалним уделом у укупном износу.
- **Потрошња токена** — укупан број / улазни / излазни токени и однос улазних и излазних токена.
- **Ефикасност усмеравања** — број резервних преусмеравања, стопа резервних преусмеравања и покривеност захтеваног модела.
- **Месечна прогноза** — пројектује потрошњу до краја месеца на основу недавног дневног просека.
- **Поређење периода** — процентуална промена између прве и друге половине периода.
- **Графикони** — дневни тренд трошкова, удео добављача (кружни графикон), водећи добављачи, водећи модели, трошкови
  по API кључу, трошкови по налогу, седмични образац коришћења и топлотна мапа активности.
- **Извоз** — преузимање података за тренутни период у формату **CSV** или **JSON** (дугмад се појављују
  када постоје подаци о трошковима већим од нуле).

Када нема тарифираних захтева, редови уместо `$0` приказују ознаку „Застарело / Бесплатно“,
у складу са моделом праћења уштеде.

### Повезане потстранице о трошковима

Област Трошкови такође садржи (све под `/dashboard/costs/`):

- **Цене** (`/dashboard/costs/pricing`) — приказ и измена цена по моделу (приказује
  заједничку картицу Цене).
- **Буџет** (`/dashboard/costs/budget`) — постављање ограничења потрошње по опсегу (приказује заједничку
  картицу Буџет).
- **Дељење квоте** (`/dashboard/costs/quota-share`) — скупови дељених квота и прикази
  стопе потрошње.

## API крајње тачке

Све оне захтевају управљачку аутентификацију (локална петља/JWT, преко `requireManagementAuth`), осим ако
није другачије наведено.

### Аналитика коришћења и трошкова

| Метод | Крајња тачка             | Сврха                                                                                                                                                                     |
| ----- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET` | `/api/usage/analytics`   | Комплетна аналитика трошкова/коришћења: сажетак, дневни тренд, по добављачу/моделу/API кључу/налогу/нивоу. Упит: `range`, `startDate`, `endDate`, `apiKeyIds`, `presets`. |
| `GET` | `/api/usage/utilization` | Искоришћеност квоте по добављачу током времена. Упит: `range` (`1h`/`24h`/`7d`/`30d`), `provider`.                                                                        |
| `GET` | `/api/usage/history`     | Необрађени редови историје коришћења.                                                                                                                                     |
| `GET` | `/api/usage/call-logs`   | Евиденција појединачних захтева (модел, токени, трошак, кашњење, статус).                                                                                                 |
| `GET` | `/api/usage/quota`       | Статус квоте добављача.                                                                                                                                                   |
| `GET` | `/api/usage/proxy-logs`  | Евиденција прокси захтева.                                                                                                                                                |

### Буџети

| Метод  | Крајња тачка             | Сврха                                                                                         |
| ------ | ------------------------ | --------------------------------------------------------------------------------------------- |
| `GET`  | `/api/usage/budget`      | Сажетак трошкова + провера буџета за један API кључ (параметар упита `apiKeyId` је обавезан). |
| `POST` | `/api/usage/budget`      | Постављање дневних/седмичних/месечних ограничења у USD + прага упозорења за API кључ.         |
| `GET`  | `/api/usage/budget/bulk` | Збирни сажеци буџета за више API кључева.                                                     |

> API за буџет има опсег по **API кључу** (`apiKeyId`). Ограничења која враћа
> `GET /api/usage/budget` обухватају `dailyLimitUsd`, `weeklyLimitUsd`, `monthlyLimitUsd`,
> `warningThreshold` и текуће укупне износе (`totalCostToday`, `totalCostMonth`, …).

### Цене

| Метод    | Крајња тачка            | Сврха                                                                                                                        |
| -------- | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/pricing`          | Тренутне обједињене цене (корисничке + синхронизоване + подразумеване). `?includeSources=1` приказује извор за сваку ставку. |
| `PATCH`  | `/api/pricing`          | Измена цена за `{ provider: { model: { input, output, cached, … } } }`.                                                      |
| `DELETE` | `/api/pricing`          | Враћање цена на подразумеване вредности (опционо ограничено помоћу `?provider=&model=`).                                     |
| `GET`    | `/api/pricing/defaults` | Приказ подразумеваних резервних тарифа по 1M.                                                                                |
| `GET`    | `/api/pricing/models`   | Цене организоване по моделу.                                                                                                 |
| `POST`   | `/api/pricing/sync`     | Покретање ручне синхронизације из спољних извора (LiteLLM).                                                                  |
| `GET`    | `/api/pricing/sync`     | Тренутни статус синхронизације.                                                                                              |
| `DELETE` | `/api/pricing/sync`     | Брисање свих синхронизованих података о ценама.                                                                              |

### Остале крајње тачке релевантне за трошкове

| Метод | Крајња тачка                  | Сврха                                                                         |
| ----- | ----------------------------- | ----------------------------------------------------------------------------- |
| `GET` | `/api/free-tier/summary`      | Укупан број токена бесплатног модела, потрошња овог месеца и преостала квота. |
| `GET` | `/api/quota/pools/[id]/usage` | Потрошња за скуп дељене квоте.                                                |

## CLI

OmniRoute CLI pruža komande za troškove, korišćenje i cene (registrovane u
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)).

### `omniroute cost`

Izveštaj o troškovima objedinjen iz `/api/usage/analytics`.

```bash
omniroute cost                          # poslednjih 30 dana, grupisano po provajderu
omniroute cost --period 7d              # poslednjih 7 dana
omniroute cost --group-by model         # grupiši po provider | model | combo | api-key | day
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

Kolone: grupa, zahtevi, ulazni/izlazni tokeni, trošak (USD) i procenat ukupnog iznosa. Red sa ukupnim zbirom
ispisuje se na kraju (izostavlja se uz `--quiet` ili `--output json`).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # pregled troškova po provajderu
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# Budžeti
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` čita `GET /api/pricing/defaults`. Da biste umesto toga izmenili cene pojedinačnih modela,
> koristite stranicu **Cene** na kontrolnoj tabli ili `PATCH /api/pricing`.

---

## Rešavanje problema

- **Svi troškovi prikazuju $0 / „Nasleđeno / Besplatno“.** Modeli koji se koriste nemaju unos sa cenom.
  Omogućite spoljnu sinhronizaciju (`PRICING_SYNC_ENABLED=true`) i pokrenite `omniroute pricing sync` ili
  ručno podesite cene preko stranice Cene / `PATCH /api/pricing`.
- **Cena istorijskog modela je pogrešna.** Ispravite cenu (zamenite je ili ponovo sinhronizujte) — trošak se
  ponovo izračunava na osnovu broja tokena pri svakom čitanju analitike, pa se procene retroaktivno ažuriraju.
- **Potrošnja kasni za stvarnim vremenom.** Potrošnja po ključu obrađuje se grupno; smanjite
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` ako su vam potrebni ažurniji podaci.
