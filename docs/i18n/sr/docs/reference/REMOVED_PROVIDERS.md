Неки сервиси су били интегрисани у OmniRoute, а касније уклоњени јер су људи који њима
управљају то затражили. Ова страница представља трајну евиденцију тих уклањања. Њена једина
сврха је да спречи њихово случајно враћање: сараднику који пронађе стари форк, кеширани npm
тарбол, архивирани проблем или захтев „вратите добављача X“ потребно је једно место на којем
пише **не уводити поново**.

Ова страница **није** списак угашених или обустављених сервиса. Они се прате у
[`FREE_TIERS.md`](FREE_TIERS.md) („Уклоњено / нема бесплатног нивоа“) и могу се вратити ако
се сервис врати. Ставке у наставку могу се вратити само уз писмену дозволу оператера наведеног
у захтеву, а веза до те дозволе мора бити наведена у ставци.

## Правила

1. **Захтев оператера сервиса за уклањање се поштује и није предмет преговора.** OmniRoute
   није повезан ни са једним спољним сервисом. Када оператер сервиса затражи уклањање
   интеграције, она се уклања, без обзира на то да ли је интеграција користила званични API.
2. **„Уклоњено“ значи са сваке површине коју OmniRoute контролише.** Извршилац, ставка
   регистра, идентификатор и псеудоним добављача, списак модела, крајње тачке, променљиве
   окружења, икона, картице контролне табле, генерисана референца добављача, `FREE_TIERS.md`,
   референца окружења, бројеви у README датотеци, `llm.txt` огледала, наменски тестови и
   референтни снимци, коментари у коду, ставке у CHANGELOG датотеци (уз евидентирано
   усаглашавање, погледајте `config/release/changelog-reconciliations.json`), белешке GitHub
   издања, вики, као и GitHub проблеми, дискусије и захтеви за спајање чија је тема била тај
   добављач (проблеми и дискусије се бришу; захтевима за спајање мења се наслов, њихов опис
   се замењује, а нит закључава, јер GitHub не може да брише захтеве за спајање).
3. **Никада немојте поново уводити ставку са ове странице без писмене дозволе.** То обухвата
   поновно додавање идентификатора или псеудонима у било који каталог добављача, додавање
   домена у извршиоца, прихватање PR-а сарадника који је „враћа“, додавање у каталог бесплатних
   модела или документовање ручног начина да јој се приступи путем OmniRoute-а. Затворите такве
   PR-ове и проблеме уз везу до ове странице.
4. **Нека ставка буде минимална.** Забележите само оно што је рецензенту потребно да препозна
   поновно увођење: идентификаторе, домене, датуме и захтев за спајање којим је извршено
   уклањање. Немојте описивати како је интеграција функционисала.
5. **Заштита од регресије је `tests/unit/removed-providers-blocklist.test.ts`.** Она не пролази
   када се било који идентификатор или домен наведен у наставку поново појави у каталозима
   добављача, мапи извршиоца или изворима регистра добављача. Додајте нове идентификаторе у
   тај тест у истом PR-у којим додајете ред овде.

## Додавање ставке

Када стигне нови захтев за уклањање:

1. Потврдите да захтев долази од оператера сервиса (са њихове адресе подршке или домена који
   контролишу) и сачувајте поруку приватно.
2. Уклоните интеграцију пратећи контролну листу из ставке 2 правила. Користите
   [#12440](https://github.com/diegosouzapw/OmniRoute/pull/12440) као референцу за добављача
   без кључа, а [#10210](https://github.com/diegosouzapw/OmniRoute/pull/10210) за добављача
   са API кључем и сачуваним везама (додајте миграцију).
3. Додајте један ред у горњу табелу и идентификаторе у
   `tests/unit/removed-providers-blocklist.test.ts`, у истом PR-у.
4. Одговорите оператеру након спајања PR-а, наводећи шта је уклоњено и шта OmniRoute
   не може да промени (већ објављене npm и Docker верзије, git историју и форкове трећих страна).
