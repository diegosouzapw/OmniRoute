`copilot-m365-web` (алијас `m365copilot`) шаље захтеве за ћаскање у OpenAI формату преко
аутентификоване Microsoft 365 Copilot BizChat сесије прегледача на
`m365.cloud.microsoft/chat`. Ово је незванична интеграција.

> **Први пут користите добављаче Web Cookie?**
>
> Пре него што наставите са овим водичем специфичним за добављача, прочитајте **`docs/getting-started/WEB-COOKIE-GUIDE.md`** ради упознавања са општим поступком подешавања, смерницама за аутентификацију, ограничењима и решавањем проблема.
>
> **Важно:** Акредитив за овог добављача **није колачић**. Немојте копирати
> колачиће са `m365.cloud.microsoft`. Акредитив чине параметар упита WebSocket URL-а
> и сегмент путање, а оба се читају на картици Network у DevTools-у.

## Предуслови

- Microsoft 365 налог са приступом услузи BizChat на `m365.cloud.microsoft/chat`
- Прегледач заснован на Chromium-у (Chrome, Edge) за преглед WebSocket веза у DevTools-у
- M365 Copilot лиценца (укључена у многе Microsoft 365 Business/Enterprise планове)

## Преузимање акредитива (WebSocket метод)

1. Пријавите се на `https://m365.cloud.microsoft/chat` и започните разговор.
2. Отворите **DevTools → Network**.
3. Филтрирајте према **WS** (WebSocket).
4. Кликните на Chathub WebSocket везу. Потражите URL који почиње са
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Из његовог поља **Request URL** копирајте:
   - Вредност параметра упита `access_token` (краткотрајни JWT).
   - Сегмент Chathub путање после `/Chathub/` (нпр. `<oid>@<tenant>`).

Пун URL има следећи облик:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. У OmniRoute-у идите на **Providers → Add Provider**, изаберите **Microsoft 365 Copilot
   (BizChat)** и налепите акредитив у следећем формату:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Кликните на **Test Connection**, а затим на **Save**.

## Преузимање акредитива (увоз HAR датотеке)

Уместо ручног копирања вредности из WebSocket URL-а, можете извести DevTools HAR
датотеку:

1. Отворите **DevTools → Network**.
2. Започните или наставите BizChat разговор (ово покреће WebSocket везу).
3. Кликните десним тастером миша у панелу Network и изаберите **Save all as HAR with content**.
4. У OmniRoute-у употребите дугме **Import .har file** у дијалогу за повезивање добављача.

OmniRoute претражује HAR датотеку како би пронашао Chathub WebSocket URL, издваја
`access_token` и `chathubPath` и аутоматски попуњава поља акредитива. При увозу
HAR датотеке декодира се време истека JWT-а и приказује преостало време важења токена.

> **Никада немојте прослеђивати стварни HAR извоз, приступни токен или токен за освежавање у репозиторијум.** Вредности за тестирање и
> документацију увек морају бити резервисане вредности.

## Време важења и освежавање токена

`access_token` је краткотрајан (обично **~75 минута**). Након истека, добављач
пријављује грешку при повезивању и морате поново да преузмете акредитив.

### Аутоматско освежавање помоћу `refreshToken`

Да бисте избегли ручно поновно преузимање, можете сачувати Microsoft токен за освежавање у
**Advanced Settings → providerSpecificData** везе:

| Поље           | Опис                                                                       |
| -------------- | -------------------------------------------------------------------------- |
| `refreshToken` | Microsoft OAuth токен за освежавање за опсег `substrate.office.com/sydney` |
| `tier`         | `individual` (подразумевано), `edu` или `enterprise`                       |

Преузмите токен за освежавање из Microsoft тока са кодом уређаја или ауторизационим кодом,
са опсегом `substrate.office.com/sydney`. Када је `refreshToken` подешен, OmniRoute
превентивно освежава `access_token` пре сваког захтева, тако да не морате поново да га
преузимате након сваког истека од приближно 75 минута.

Ако `refreshToken` није подешен, морате ручно поново да преузмете WebSocket акредитив
након сваког истека.

### Избор нивоа

| Ниво         | Алијас            | Окружење                     |
| ------------ | ----------------- | ---------------------------- |
| `individual` | _(подразумевано)_ | Потрошачки M365 Copilot      |
| `edu`        | `included`        | Образовни M365 Copilot       |
| `enterprise` | `work`            | M365 Copilot за пословни рад |

Подесите ниво у **Advanced Settings → providerSpecificData → tier**. Ниво утиче на
BizChat усмеравање и приступ моделима.

## Безбедносни модел

- **Незванична интеграција.** Овај добављач користи обрнути инжењеринг BizChat WebSocket
  протокола. Може престати да ради без најаве када Microsoft промени крајњу тачку.
- Ознака `subscriptionRisk: true` указује на то да се интеграција ослања на
  недокументовану крајњу тачку. Ограничења налога су могућа, али нису потврђена.
- Приступни токен је краткотрајни JWT. Третирајте га као лозинку: немојте га уносити у комитове,
  евидентирати нити делити.
- Токен за освежавање омогућава дугорочан приступ BizChat интерфејсу. Чувајте га са
  истом пажњом као API кључ.

## Решавање проблема

### Аутентификација одмах не успева

- Проверите да ли сте вредност копирали из **WebSocket URL-а**, а не из XHR/Fetch захтева. Акредитив
  се налази у параметру упита `access_token` Chathub WebSocket
  везе — а не у заглављу `Authorization: Bearer`.
- Уверите се да `chathubPath` садржи цео сегмент `<oid>@<tenant>` из URL
  путање.

### Токен истиче након приближно 75 минута

То је очекивано. Без `refreshToken`, приступни токен је краткотрајан. Урадите једно од следећег:

- Поново преузмите акредитив из DevTools-а или
- Конфигуришите `refreshToken` у напредним подешавањима ради аутоматског освежавања.

### Тест везе је успешан, али ћаскање враћа 401

Токен је можда истекао између провере ваљаности и првог захтева. Поново преузмите
свеж акредитив.

### Copilot се не појављује на листи добављача

Уверите се да је `copilot-m365-web` омогућен у одељку **Контролна табла → Добављачи**. Добављач може
подразумевано бити скривен на неким нивоима претплате.
