Овај документ бележи одлуку о имплементацији за
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854). Јавни производи су
представљени као четири породице провајдера. Регион је податак о вези, а не засебан производ.

## Одлука

| Породица провајдера                             | OmniRoute ID            | Глобални регион | Регион у Кини |
| ----------------------------------------------- | ----------------------- | --------------- | ------------- |
| Alibaba Cloud Model Studio (плаћање по утрошку) | `alibaba`               | Сингапур        | Пекинг        |
| Alibaba Cloud Token Plan                        | `bailian-coding-plan`   | Сингапур        | Пекинг        |
| Qwen Cloud (плаћање по утрошку)                 | `qwen-cloud`            | Глобално        | Пекинг        |
| Qwen Cloud Token Plan                           | `qwen-cloud-token-plan` | Сингапур        | Пекинг        |

Постојећи ID `alibaba-cn` остаје псеудоним за компатибилност током извршавања за сачуване везе, руте
модела, комбинације и историјску употребу. Његова картица на контролној табли спојена је са `alibaba`;
није потребно преписивање базе података.

Qwen Cloud са плаћањем по утрошку и Alibaba Cloud Model Studio тренутно деле хостове компатибилне са
DashScope-ом током извршавања, али остају засебни идентитети провајдера јер корисници добијају кључеве
и управљају налозима преко различитих интерфејса производа. Производи Alibaba и Qwen Cloud Token Plan
користе различите породице крајњих тачака, па сва четири производа остају засебни ID-ови провајдера.

## Матрица крајњих тачака

| Породица провајдера     | `global-sg`                                                              | `china-beijing`                                                      | Формат протокола |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ---------------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI           |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic        |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI           |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI           |

API кључ и крајња тачка морају припадати истом производу и региону. Избор региона мења
унапред подешену крајњу тачку која се користи за валидацију и уобичајене захтеве.

## Уговор везе

Нове везе чувају стабилни кључ региона у `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

Дозвољене вредности су `global-sg` и `china-beijing`. Крајња тачка се централно изводи из
ID-а провајдера и региона. Вредност `providerSpecificData.baseUrl` која није унапред подешена остаје
експлицитно операторско замењивање и има предност, док се старе сачуване унапред подешене URL адресе
нормализују назад на регионалну матрицу.

Овим шема везе остаје проширива: још један регион може да се дода у разрешивач без
прављења нове картице провајдера или мењања сачуваних ID-ова провајдера.

## Компатибилност и увођење

1. Додајте разрешавач регионалних крајњих тачака и задржите тренутне глобалне подразумеване вредности.
2. Користите живо регионално DashScope `/models` откривање за `alibaba`, његов компатибилни
   ID `alibaba-cn` и `qwen-cloud`. Њихови одговори најпре пролазе кроз један филтер за генерисање текста јер генеричка
   крајња тачка враћа и моделе за слике, видео, аудио, угнежђивање и друге моделе који нису намењени ћаскању. `qwen-cloud`
   затим примењује одржавану листу дозвољених модела декларисану у свом регистру добављача. Alibaba Model Studio
   и Qwen Cloud задржавају засебне уређене каталоге иако тренутно деле хостове окружења за извршавање.
3. Региструјте `qwen-cloud-token-plan` са тренутном листом дозвољених текстуалних модела за Token Plan.
4. Додајте типизовани бирач региона у дијалоге за додавање/уређивање веза.
5. Сакријте дуплирану картицу `alibaba-cn` и укључите њене постојеће везе на страници добављача
   `alibaba`.
6. Задржите могућност прилагођеног замењивања крајњих тачака за напредна увођења и увођења специфична за радни простор.

Медијски модели за Token Plan остају изван каталога за ћаскање јер користе наменске крајње тачке.
`wan2.7-image` и `wan2.7-image-pro` регистровани су у `open-sse/config/imageRegistry.ts`;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` и `happyhorse-1.1-r2v` регистровани су у
`open-sse/config/videoRegistry.ts`. Оба регистра поново користе идентитет везе `qwen-cloud-token-plan`
и њене акредитиве специфичне за регион.

Редовни Qwen Cloud има засебне каталоге слика и видео-записа са плаћањем по потрошњи у оквиру
идентитета `qwen-cloud`. Његови модели за слике су `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` и `z-image-turbo`. Његови видео
модели су `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` и
`wan2.7-videoedit`. Ови модели поново користе само редовну везу `qwen-cloud` и регионалну
DashScope медијску крајњу тачку. Регистри за Token Plan и плаћање по потрошњи не наслеђују нити обједињују
међусобне листе модела.

Идентитет `bailian-coding-plan` такође има сопствене листе дозвољених медијских модела:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` и `qwen-image-2.0-pro` за генерисање
слика, као и
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` и `happyhorse-1.1-r2v` за генерисање
видео-записа. Он користи само везу Bailian Coding Plan и регионалну крајњу тачку Coding Plan.
Његови регистри слика и видео-записа не наслеђују нити се обједињују ни са једним Qwen Cloud добављачем.

Редовни идентитет `alibaba` има засебне листе дозвољених модела за слике и видео-записе. Његови модели за слике су
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` и `wan2.6-t2i`. Његови додати видео-модели су `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` и `wan2.7-videoedit`. Ови модели користе само везу Alibaba Model Studio
и њену изабрану регионалну медијску крајњу тачку; не додају се ни у један регистар за Coding Plan или Qwen
Cloud.

Каталог за ћаскање Qwen Cloud Token Plan прати листу дозвољених текстуалних модела Individual плана са тачним подударањем ниски:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` и
`deepseek-v4-pro`. Wan и HappyHorse ставке припадају засебним API-јима за генерисање слика/видео-записа.

Alibaba Token Plan излаже истих шест тренутних ID-јева модела за генерисање текста преко своје
крајње тачке компатибилне са Anthropic-ом. Његова опција за Сингапур чува постојећи кључ региона `global-sg`;
само се ознака приказана кориснику разликује од породица добављача које регион називају Global.

Редовни Qwen Cloud каталог за ћаскање намерно је ужи од потпуног живог текстуалног одговора. Његова
одржавана листа дозвољених модела налази се у `open-sse/config/providers/registry/qwen-cloud/index.ts`; живо
откривање враћа само ID-јеве који постоје и у одговору узводног сервиса и на тој листи регистра.

Alibaba Model Studio примењује исто правило пресека живих резултата са својом независно одржаваном
листом дозвољених модела у `open-sse/config/providers/registry/alibaba/index.ts`. Компатибилни
добављач `alibaba-cn` поново користи тај каталог, док откривање разрешава преко пекиншке крајње тачке.
