Два начина да поставите Cursor иза OmniRoute-а без IDE сесије:

1. **`cursor-api` провајдер** (картица „Cursor API“, алијас `cua`): провајдер са
   API кључем који чува кориснички Cursor API кључ (`crsr_…`, генерисан на
   `https://cursor.com/dashboard/api`). Сваки OmniRoute клијент затим приступа
   Cursor моделима преко `/v1/chat/completions` као `cursor-api/<model>` или
   `cua/<model>`, уз уобичајене слојеве за квоте, резервне опције и евидентирање.
   IDE провајдер (`cursor`, OAuth/IDE сесија) остаје непромењен.
2. **Директно прослеђивање Cursor CLI-ја**: усмерите Cursor CLI (`agent`) ка
   OmniRoute-у тако да сваки RPC који CLI упути буде аутентификован OmniRoute API
   кључем, прослеђен Cursor-у помоћу акредитива `cursor-api` везе и забележен на
   страници Logs.

## Зашто се кључ размењује

`api2.cursor.sh` одбија необрађени `crsr_…` кључ као Bearer токен (401). Cursor
CLI најпре шаље кључ POST захтевом на `/auth/exchange_user_api_key` и добија
JWT сесије који истиче после једног сата; враћени `refreshToken` има исту
вредност `exp`, па освежавање подразумева поновну размену кључа.
`open-sse/services/cursorApiKeyAuth.ts` обавља ту размену, кешира по један токен
сесије за сваки кључ, поново обавља размену пет минута пре истека и уклања
кеширани токен када Cursor одговори статусом 401. `CursorExecutor` га позива
непосредно пре отварања узводног тока за `cursor-api` везе.

## `cursor-api` провајдер

Регистар: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, исти `format`, `baseUrl` и
`models` као код `cursor`). Картица каталога:
`src/shared/constants/providers/apikey/specialty-media.ts`. Мапа извршилаца:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

Контролна табла: Providers → Cursor API → Add API key.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

Затим:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

Напомене:

- Листа модела за `cursor-api` потиче из статичког Cursor регистра (исте листе
  на коју се IDE провајдер ослања као резервну опцију); инсталација
  `cursor-agent` није потребна на OmniRoute хосту.
- `POST /api/providers/{id}/refresh-cursor` намењен је искључиво `cursor` IDE
  провајдеру; `cursor-api` везе немају IDE сесију коју треба обновити.

## Изворни ID-ови модела и ниво напора

За `cursor` / `cu` и `cursor-api` / `cua`, заједнички нормализатор нивоа напора
за Claude оставља тражени ID модела непромењеним. Cursor може да огласи суфикс
као што је `-low` као део стварног ID-а модела, уместо као OmniRoute алијас
нивоа напора. Cursor извршилац задржава тачно подударање са активним каталогом;
када подударање не постоји, његов постојећи разрешивач модела управља резервним
претварањем суфикса у параметар.

Ово не мења нормализацију нивоа напора за директне Claude, Claude-компатибилне
или Vertex руте. Доступност и даље зависи од каталога и права изабраног Cursor
налога.

## Прослеђивање кроз Cursor CLI

Рута: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. Префикс `/api/cursor-cli/` је
регистрован у `src/shared/constants/publicApiRoutes.ts` зато што руковалац
спроводи сопствену аутентификацију:

| Путања                                                                                                                         | Аутентификација коју CLI очекује | Шта OmniRoute ради                                                                                                                                                    |
| ------------------------------------------------------------------------------------------------------------------------------ | -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                             | `Bearer <OmniRoute API кључ>`    | Проверава кључ, генерише HS256 JWT са трајањем од 1 сата (потписан помоћу `JWT_SECRET`) и враћа га                                                                    |
| свака друга путања (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <тај JWT>`               | Проверава издаваоца/публику/истек, бира активну `cursor-api` везу, замењује заглавље Authorization размењеним Cursor токеном и прослеђује одговор назад у виду стрима |

CLI декодира `exp` из сваког токена који прими, па би му прослеђивање непрозирног
токена проузроковало поновну размену пре готово сваког захтева; генерисани JWT то
спречава. Одговор 401 од OmniRoute-а доводи до тога да CLI поново изврши размену.

### Подешавање

1. Направите OmniRoute API кључ (Контролна табла → API кључеви) и `cursor-api`
   везу.
2. Подесите CLI да користи HTTP/1.1 за стрим агента. У
   `~/.cursor/cli-config.json`:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   Без овога CLI отвара интеракцију агента преко HTTP/2 ка засебно
   конфигурисаном хосту агента, а само RPC позиви контролне равни пролазе кроз
   крајњу тачку.

3. Покрените CLI усмерен ка OmniRoute-у:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

Сваки корак се евидентира у евиденцији као добављач `cursor-api`, тип захтева
`cursor-cli` и путања `/api/cursor-cli/<rpc>`, приписан OmniRoute API кључу и
вези која га је опслужила.

### Начини отказа

| Ситуација                                        | Одговор CLI-ју                                   |
| ------------------------------------------------ | ------------------------------------------------ |
| Непознат OmniRoute кључ и `REQUIRE_API_KEY=true` | 401 `unauthenticated` приликом размене           |
| `REQUIRE_API_KEY=false`                          | анонимна сесија (одговара понашању `/v1/*`)      |
| Истекао / страни / измењени JWT сесије           | 401, CLI поново обавља размену                   |
| OmniRoute API кључ опозван након размене         | 401 при следећем RPC позиву                      |
| Нема активне `cursor-api` везе                   | 503 `unavailable`                                |
| Cursor одбија кључ везе                          | 401 `unauthenticated`, кеширана сесија се уклања |
| Изворни сервер није доступан                     | 502 `unavailable` (санитизована порука)          |
| `JWT_SECRET` није постављен                      | 503 приликом размене                             |
