Два начина да поставите Cursor иза OmniRoute-а без IDE сесије:

1. **`cursor-api` провајдер** (картица „Cursor API“, алијас `cua`): провајдер са API кључем
   који чува Cursor кориснички API кључ (`crsr_…`, генерисан на
   `https://cursor.com/dashboard/api`). Сваки OmniRoute клијент затим приступа
   Cursor моделима преко `/v1/chat/completions` као `cursor-api/<model>` или
   `cua/<model>`, уз уобичајене слојеве за квоту, резервни избор и евидентирање. IDE
   провајдер (`cursor`, OAuth/IDE сесија) остаје непромењен.
2. **Cursor CLI прослеђивање**: усмерите Cursor CLI (`agent`) на OmniRoute тако да
   се сваки RPC који CLI упути аутентификује OmniRoute API кључем, проследи
   Cursor-у помоћу акредитива `cursor-api` везе и забележи на
   страници Logs.

## Зашто се кључ размењује

`api2.cursor.sh` одбија необрађени `crsr_…` кључ као Bearer токен (401). Cursor
CLI најпре POST захтевом шаље кључ на `/auth/exchange_user_api_key` и добија JWT
сесије који истиче након једног сата; враћени `refreshToken` има исти
`exp`, па освежавање подразумева поновну размену кључа.
`open-sse/services/cursorApiKeyAuth.ts` обавља ту размену, кешира један токен
сесије по кључу, поново га размењује пет минута пре истека и уклања кеширани
токен када Cursor одговори статусом 401. `CursorExecutor` га позива непосредно
пре отварања узводног тока за `cursor-api` везе.

## `cursor-api` провајдер

Регистар: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, исти `format`, `baseUrl` и
`models` као код `cursor`). Картица каталога:
`src/shared/constants/providers/apikey/specialty-media.ts`. Мапа извршилаца:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

Контролна табла: Providers → Cursor API → Add API key.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

Затим:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

Напомене:

- Листа модела за `cursor-api` долази из статичког Cursor регистра (исте
  листе коју IDE провајдер користи као резервну); инсталација `cursor-agent`
  на OmniRoute хосту није потребна.
- `POST /api/providers/{id}/refresh-cursor` служи само за `cursor` IDE провајдер;
  `cursor-api` везе немају IDE сесију коју треба обновити.

## Cursor CLI прослеђивање

Рута: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. Префикс `/api/cursor-cli/` регистрован је
у `src/shared/constants/publicApiRoutes.ts` јер обрађивач
спроводи сопствену аутентификацију:

| Путања                                                                                                                         | Аутентификација коју CLI очекује | Шта OmniRoute ради                                                                                                                                          |
| ------------------------------------------------------------------------------------------------------------------------------ | -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                             | `Bearer <OmniRoute API key>`     | Проверава кључ, генерише HS256 JWT са трајањем од 1 сата (потписан помоћу `JWT_SECRET`) и враћа га                                                          |
| свака друга путања (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`              | Проверава издаваоца/намену/истек, бира активну `cursor-api` везу, замењује Authorization заглавље размењеним Cursor токеном и прослеђује ток одговора назад |

CLI декодира `exp` из било ког токена који прими, па би му прослеђивање непрозирног
токена узроковало поновну размену пре готово сваког захтева; генерисани JWT то
спречава. Одговор 401 од OmniRoute-а наводи CLI да поново обави размену.

### Подешавање

1. Направите OmniRoute API кључ (Dashboard → API keys) и `cursor-api`
   везу.
2. Подесите CLI да користи HTTP/1.1 за ток агента. У датотеци
   `~/.cursor/cli-config.json`:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   Без овога CLI отвара интеракцију агента преко HTTP/2 ка засебно
   конфигурисаном хосту агента, а само RPC позиви контролне равни пролазе кроз
   крајњу тачку.

3. Покрените CLI усмерен на OmniRoute:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

Сваки корак се појављује у Logs са провајдером `cursor-api`, типом захтева
`cursor-cli`, путањом `/api/cursor-cli/<rpc>`, приписан OmniRoute API кључу и
вези која га је обрадила.

### Начини отказа

| Ситуација                                        | Одговор CLI-ју                                     |
| ------------------------------------------------ | -------------------------------------------------- |
| Непознат OmniRoute кључ и `REQUIRE_API_KEY=true` | 401 `unauthenticated` приликом размене             |
| `REQUIRE_API_KEY=false`                          | анонимна сесија (одражава понашање `/v1/*`)        |
| Истекао / страни / измењени JWT сесије           | 401, CLI поново обавља размену                     |
| OmniRoute API кључ опозван након размене         | 401 при следећем RPC-у                             |
| Нема активне `cursor-api` везе                   | 503 `unavailable`                                  |
| Cursor одбија кључ везе                          | 401 `unauthenticated`, кеширана сесија се одбацује |
| Надређени сервис није доступан                   | 502 `unavailable` (санитизована порука)            |
| `JWT_SECRET` није подешен                        | 503 приликом размене                               |
