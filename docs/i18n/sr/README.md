## 💰 ~1,62 млрд токена месечно преко бесплатних пакета независних добављача

</div>

> **Користите сопствене налоге код добављача.** Ово је процењени збир засебно доступних бесплатних пакета независних добављача, а не додела токена од стране OmniRoute-а. Региструјте се, прибавите акредитиве тамо где су потребни и повежите добављаче које можете да користите; сваки добављач контролише своја ограничења, доступност и услове.
>
> Ручно комбиновање бесплатних пакета је напорно — десетине SDK-ова, десетине ограничења брзине и никаква представа о томе колико заправо имате. OmniRoute каталогизује **471 ставку бесплатних пакета у оквиру 34 кључа периодичних пулова** и израчунава истакнути број токена на основу **17 пулова са објављеним позитивним месечним буџетом, уз пет Groq ограничења по моделу**, уз уклањање дупликата који деле исти пул. Квоте које постају доступне тек након регионалне провере идентитета (тренутно: ModelScope) приказују се засебно, +~6M након регионалне провере идентитета, и никада се не сабирају у истакнути број. Резултат остаје видљив на контролној табли (`/dashboard/free-tiers`).

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="Картица буџета бесплатних пакета OmniRoute-а: стабилних ~1,62 млрд бесплатних токена месечно, до ~2,22 млрд током првог месеца са кредитима за регистрацију, из 34 документована кључа периодичних пулова који обухватају 471 каталогизовану ставку бесплатних пакета иза једне крајње тачке. Транспарентан прорачун са уклањањем дупликата по пуловима — сваки дељени пул рачуна се једном, укључујући 17 периодичних пулова са објављеним позитивним месечним буџетом токена и пет Groq ограничења по моделу; 12 добављача је означено као непожељно у каталогу ризика услова коришћења, тако да ви одлучујете. Трака буџета обухвата Mistral 1B, Nara 210M, LLM7 150M, xKiro 150M, Groq 30M (пет ограничења по моделу) и мање пулове, уз кредите за регистрацију током првог месеца и трајно бесплатне добављаче без ограничења токена, који су приказани засебно како никада не би увећавали истакнути број. Тренутна потрошња и преостали износ на /dashboard/free-tiers."/>

> Анимирани сажетак активне странице `/dashboard/free-tiers`. Потпуна методологија (уклањање дупликата по пуловима, нивои кредита, услови добављача): **[docs/reference/FREE_TIERS.md](docs/reference/FREE_TIERS.md)**.
>
> <sub>Ове вредности се поново проверавају сваке две недеље у односу на активни каталог и **мењају се у оба смера** — када добављач укине бесплатни пакет, број се смањује; када се појави нови, број расте. Објављујемо оно што каталог заиста израчунава, никада заокружену најбољу могућу вредност.</sub>

## 🆓 Инсталирајте, повежите провајдера, а затим усмеравајте преко једне крајње тачке

</div>

<img src="./docs/diagrams/works-zero-config.svg" width="100%" alt="Три корака: инсталирајте и покрените OmniRoute, повежите одговарајућег провајдера помоћу сопственог налога или API кључа, а затим усмерите свој алат на localhost:20128/v1 користећи OmniRoute API кључ и модел auto. Усмеравање зависи од доступних одговарајућих веза и ограничења провајдера."/>

```bash
# Након повезивања провајдера, копирајте свој OmniRoute кључ са Контролна табла → Крајње тачке:
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer YOUR_OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

<sub>За `auto` је потребна одговарајућа рута. Нова инсталација можда нема ниједно одговарајуће одредиште без кључа, а провајдер без кључа може одбити клијенте трећих страна. Провајдери означени са `tos: avoid`, укључујући Kiro, подразумевано су искључени из аутоматског усмеравања; повезивање налога не мења ту поставку. Пре него што изаберете провајдера, погледајте [Водич за бесплатне пакете](docs/getting-started/FREE-TIERS-GUIDE.md).</sub>

<sub>📦 Скрипте за брзи почетак које можете копирати и налепити за **Python, Node.js, PHP и cURL** → [`examples/quickstart/`](examples/quickstart/)</sub>

## 🎯 Комбинације — главна функционалност

</div>

<img src="./docs/diagrams/strategies-grid.svg" width="100%" alt="Анимирани примери за 18 од 21 стратегија комбинованог рутирања — по једна плочица за сваку стратегију: priority, fill-first, weighted, round-robin, p2c, least-used, random, strict-random, cost-optimized, headroom, reset-window, reset-aware, context-relay, context-optimized, lkgp, auto, fusion, pipeline. cache-optimized, quota-weighted и expiry-first нису анимиране; табела испод описује свих 21."/>

> **Комбинација** је ланац модела између којих OmniRoute рутира **аутоматски**. Ако се квота потроши, добављач откаже или трошкови нагло порасту, комбинација може да пређе на следећи одговарајући исправан модел. 🛡️

### ⚡ Без конфигурације — само користите `auto`

Нема потребе да правите комбинацију. Подесите модел на `auto` (или неку варијанту) и OmniRoute ће направити виртуелну комбинацију од ваших повезаних добављача, уз оцењивање уживо:

<table>

## 📡 OmniRoute Radar

Главна бројка за бесплатни ниво остаје **~1,62 млрд. токена месечно** из горе наведеног документованог
каталога, из ког су уклоњена преклапања између група. Привремени кредити за регистрацију код добављача могу засебно повећати обим током првог
месеца на **~2,22 млрд.** Radar је опционални, потписани слој каталога за кориснике који желе ажурнију
доступност бесплатних модела између OmniRoute издања; каталог заједнице и све постојеће бесплатне
функционалности остају бесплатни.

Подржаваоци могу добити актуелни каталог и додатне могућности добављача. Његова засебна,
променљива горња граница износи **највише приближно 3 млрд. токена месечно**, у зависности од доступности добављача.
Та горња граница није загарантована: добављачи могу у било ком тренутку променити квоте, услове испуњавања, моделе или регионе.

Radar се користи по избору и подржава само GET. OmniRoute клијент не отпрема упите, саобраћај, конфигурацију
добављача, телеметрију коришћења нити локално стање одбацивања обавештења. Сазнајте више о условима испуњавања и
актуелном каталогу на **[radar.omniroute.online/planos](https://radar.omniroute.online/planos)**.

акредитиви се убацују засебно за сваки процес, а Qwen/Gemini добијају привремени изоловани матични директоријум:

```bash
omniroute run claude   --model openai/gpt-5.4          # Claude Code
omniroute run codex    --model glm/glm-5.2             # OpenAI Codex CLI
omniroute run aider    --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose    --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"
omniroute run qwen     --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini   --model glm/glm-5.2 -- --skip-trust -p "reply OK"

# Или интерактивно изаберите добављача и модел и упишите сопствену конфигурацију алата:
omniroute configure codex          # такође: claude opencode qwen aider goose gemini cline continue kilo 5dive
```

Свака команда поштује активни удаљени контекст (`omniroute connect <host>`), `--dry-run`
приказује тачне променљиве окружења и аргументе без извршавања, а `--api-key-env NAME` спречава да тајне
доспеју у историју ваше љуске. → [CLI интеграције](docs/guides/CLI-INTEGRATIONS.md)

## 🔌 Комплетан CLI + A2A и MCP

</div>

> Поред сервера, OmniRoute је **комплетан командни центар за командну линију** са **више од 80 команди**, као и отвореним протоколима за агенте, тако да AI агент може да управља њиме **самостално**.

### ⌨️ Прави CLI (не само `start`)

```bash
omniroute               # покрени мрежни пролаз + контролну таблу (порт 20128)
omniroute chat          # интерактивни TUI клијент за ћаскање (команде: /model /combo /skill /memory)
omniroute setup         # вођени чаробњак за прво покретање
omniroute doctor        # дијагностикуј добављаче, портове и изворне зависности
```

### 🛰️ Удаљени режим — покрените CLI овде, а OmniRoute на VPS-у

OmniRoute је на серверу? Управљајте њиме са свог лаптопа помоћу **истог CLI-ја**. Пријавите се једном
помоћу приступног токена ограниченог опсега; свака команда ће затим бити усмерена на удаљени сервер.

```bash
omniroute connect 192.168.0.15            # лозинка → токен ограниченог опсега, сачуван као контекст
omniroute models                         # ← извршава се на УДАЉЕНОМ серверу
omniroute configure codex                 # ← бира удаљени модел, уписује локални Codex профил
omniroute tokens create --name ci --scope read   # издај токене ужег опсега за друге машине
omniroute contexts use default            # ← врати се на локални сервер
```

Токени имају опсег `read` / `write` / `admin`; руте које покрећу процесе остају доступне само преко повратне петље.

## 🗜️ Uštedite 15–95% tokena — automatski

</div>

### 📖 Kako funkcioniše — pipeline, arhitektura i matematika uštede

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute compression pipeline: ilustrativni klijentski zahtev od 10.000 tokena prolazi kroz 12 kompozabilnih engine-a — Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra i OmniGlyph — i u dokumentovanom stacked primeru može stići do provajdera sa oko 1.080 tokena. Strukturisani sadržaj je zaštićen preservation guard-ovima i fidelity gate-ovima po koraku; eksplicitni lossy ili eksperimentalni režimi mogu transformisati podoban sadržaj."/>

Podrazumevani stacked combo pokreće `RTK → Caveman`. Kada oba deluju na isti tool/context payload, uštede se sabiraju:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

Code blokovi, URL-ovi, JSON i strukturisani podaci su **uvek zaštićeni** od strane preservation engine-a.

> **Zašto koristiti mnogo tokena kada malo tokena radi posao?** Svaki zahtev prolazi kroz OmniRoute compression pipeline **transparentno** — bez izmena na klijentu. To je sada **stek od 12 kompozabilnih engine-a** koji se izvršavaju po redu i kombinuju po potrebi za svaki routing combo — nadograđujući ideje iz [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K+), [LLMLingua-2](https://github.com/microsoft/LLMLingua) i [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR).

### 🧱 Stek od 12 engine-a

Engine-i se izvršavaju u redosledu pipeline-a; svaki se nezavisno uključuje/isključuje i konfiguriše po combo-u:

<table>
  <tr><th align="center">#</th><th align="left">Engine</th><th align="left">Šta radi</th></tr>
  <tr><td align="center" nowrap>1</td><td align="left" nowrap><b>Session-Dedup</b></td><td align="left">Uklanja sadržaj koji se ponavlja kroz turnove (content-addressed, cross-turn)</td></tr>

### 🎚️ Више од механизама — стилови излаза, адаптивно подешавање и контрола по захтеву

Горњих 12 механизама смањују оно што улази **на улазу**. Још три слоја обликују **како**, **када** и шта излази **на излазу**:

- **🪄 Стилови излаза** _(усмеравање по оси излаза)_ — убацују детерминистичка упутства за обликовање одговора која не ремете кеширање; могу се комбиновати, а сваки има интензитет `lite` / `full` / `ultra`. Додавање стила захтева један ред у регистру:
  - **Сажета проза** — уклања поштапалице / чланове / ограђивање; технички садржај остаје прецизан.
  - **Мање кода** — YAGNI приступ „лењег искусног програмера“: најмања функционална измена, без незатражене пратеће структуре.
  - **Коњски реп (лењи искусни програмер)** — пење се YAGNI лествицом, отклања основни узрок, прави најмању функционалну разлику.
  - **Имам ADHD (прво радња)** — почиње следећом радњом, кораци су нумерисани, један конкретан следећи корак, без увода.
  - **Сажети CJK (文言)** — ултрасажети стил класичног кинеског (ограничен на локализацију `zh`).
- **🎯 Адаптивни буџет контекста** _(регулатор)_ — уместо једног укљученог/искљученог прага токена, активира најјефтиније механизме са најмање губитака само онолико колико је потребно да би се садржај **уклопио у контекстни прозор модела**. Политика: `reserve-output` (подразумевано, прилагођено моделу) · `percentage` · `absolute`. Режим: `floor` (гарантује уклапање) · `replace-autotrigger` (ваш изричити избор има предност) · `off` (застарели праг).
- **🎛️ Где се одлучује о компресији** _(приоритет, од највишег ка најнижем)_ — заглавље `x-omniroute-compression` по захтеву › замена за комбинацију рутирања › активни именовани профил › адаптивно / аутоматско активирање › подразумевана поставка панела › искључено. Примењени план враћа се у заглављу одговора `X-OmniRoute-Compression: <mode>; source=<source>`.

Користите аутоматско активирање по прагу токена, укључите адаптивни регулатор, закачите именовани профил, задајте једнократно подешавање по захтеву или доделите ток обраде комбинацији рутирања — шта год одговара радном оптерећењу. Опциони офлајн **оквир за евалуацију** (`npm run eval:compression`) оцењује верност у односу на уштеду на фиксном корпусу пре него што унапредите измену.

## 📦 Још начина инсталације — Docker, изворни код, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

`:latest` прати највишу **објављену** стабилну SemVer верзију. Не прати git `main`. Закуцајте `:X.Y.Z` за GitOps. Погледајте [Канале издања за Docker](docs/guides/DOCKER_GUIDE.md#release-channels).Слика фиксира **`OMNIROUTE_MEMORY_MB=1024`**. То је довољно за контролну таблу и лагану преписку. **Агенти за кодирање** (`POST /v1/responses` из Claude Code, Codex, Grok, …) захтевају много већи V8 хеап, иначе процес доживи `FATAL ERROR` на ~12 GiB под два дуга контекста која се преклапају. Димензионишите контејнер изнад хеапа (нативни бафери се налазе изван V8):

| Радно оптерећење                        | Хеап (`-e OMNIROUTE_MEMORY_MB`) | Контејнер (`--memory`) |
| --------------------------------------- | ------------------------------- | ---------------------- |
| Контролна табла / лагана преписка       | `1024` (подразумевано за слику) | ≥2 g                   |
| Један агент за кодирање                 | `8192`                          | ≥10 g                  |
| Два истовремена дугачка `/v1/responses` | `10240`–`12288`                 | ≥12–16 g               |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

Пуна табела: [Водич за Docker — RAM у време извршавања](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

> **Docker канал за претходна издања:** `diegosouzapw/omniroute:next` и
> `diegosouzapw/omniroute:next-web` прате тренутну подразумевану грану `release/v*`.
> Ове промењиве ознаке намењене су само за тестирање необјављених исправки и

**⚡ Бржа / лакша инсталација (прескочите нативну изградњу)**

Нативни SQLite мотор (`better-sqlite3`) је **опциона** зависност, тако да се глобална
инсталација никада не блокира на компајлирању из изворног кода: користи унапред изграђени бинарни фајл када одговара
вашој платформи/Node-у, а у супротном се транспарентно враћа на чисто-JS мотор
(`node:sqlite` на Node 22+, иначе уграђени `sql.js` WASM) — алати за изградњу нису потребни.

Да у потпуности прескочите **нативно загревање** након инсталације (CI, без графичког интерфејса или споре машине).
Напомена: ово прескаче само корак нативног SQLite загревања (`scripts/postinstall.mjs`);
кука за копирање/поправку бинарног фајла (`scripts/build/postinstall.mjs`) се и даље извршава нормално:

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 такође га прескаче
```

За најбрже инсталације преферирајте **pnpm** (складиште са адресирањем садржаја + тврде везе — види горе).
За извршавање без контролне табле и без графичког интерфејса користите Docker `base` профил (горе) или
[водич за Termux](docs/guides/TERMUX_GUIDE.md). CLI и веб контролна табла се служе из истог
процеса на једном порту, тако да данас не постоји засебан пакет само за CLI.

### Како да допринесете

1. Направите форк репозиторијума
2. Направите грану од врха **активне** гране `release/vX.Y.Z` (не од `main`) — погледајте [Модел гранања и издавања](docs/ops/BRANCHING_MODEL.md)
3. Направите своју грану за функционалност (`git checkout -b feat/amazing-feature`)
4. Комитујте измене (`git commit -m 'feat: add amazing feature'`)
5. Отпремите грану (`git push origin feat/amazing-feature`)
6. Отворите захтев за преузимање измена са **base = том граном `release/vX.Y.Z`**

Детаљна упутства потражите у документу [CONTRIBUTING.md](CONTRIBUTING.md).
