> **Tetapkan trafik keluar kepada satu keluarga IP — `auto`, `ipv4`, atau `ipv6` — bagi setiap proksi, supaya laluan keluar IPv6 sahaja tidak sekali-kali bocor kembali ke IPv4 secara senyap.**

> **Sumber rujukan utama:** `open-sse/utils/proxyFamily.ts`, `open-sse/utils/proxyDispatcher.ts`, `open-sse/utils/proxyFetch.ts`, `open-sse/utils/socksConnectorWithFamily.ts`, `open-sse/utils/proxyFamilyResolve.ts`, `src/shared/validation/schemas.ts`, `src/lib/db/proxies.ts`, `src/lib/db/upstreamProxy.ts`, `src/lib/db/migrations/099_proxy_family.sql`

OmniRoute membolehkan setiap proksi mempunyai **arahan keluarga alamat untuk trafik keluar**. Secara lalai, OS memilih IPv4 atau IPv6 (dwitindan, "Happy Eyeballs"). Apabila anda menetapkan arahan kepada `ipv4` atau `ipv6`, OmniRoute menetapkan setiap sambungan melalui proksi tersebut kepada keluarga yang dipilih dan **gagal secara tertutup** dan bukannya beralih kembali kepada keluarga yang lain.

Halaman ini mendokumentasikan maksud arahan tersebut, sebab ia diwujudkan, tempat untuk mengkonfigurasikannya dan cara masa jalan menyelesaikannya.

## Maksudnya

Setiap proksi dalam pendaftaran mempunyai medan `family` dengan tiga nilai yang mungkin, yang disahkan oleh enum Zod:

```ts
// src/shared/validation/schemas.ts
family: z.enum(["auto", "ipv4", "ipv6"]).optional().default("auto"),
```

Medan tersebut secara lalai ditetapkan kepada `"auto"`, yang mengekalkan tingkah laku dwitindan terdahulu. Menetapkannya kepada `ipv4` atau `ipv6` akan menetapkan keluarga sambungan bagi proksi tersebut.

Arahan tersebut dinormalkan di semua tempat melalui satu pembantu supaya sebarang nilai yang tidak diketahui ditukarkan kepada `auto`:

```ts
// open-sse/utils/proxyFamily.ts
export type ProxyFamily = "auto" | "ipv4" | "ipv6";

export function parseProxyFamily(value: unknown): ProxyFamily {
  return value === "ipv4" || value === "ipv6" ? value : "auto";
}
```

## Sebab Ia Diwujudkan

Diperkenalkan dalam PR [#3777](https://github.com/diegosouzapw/OmniRoute/pull/3777). Masalah yang mendorong pelaksanaannya:

| Masalah                                                   | Perkara yang dibetulkan oleh arahan tersebut                                                                                                                                                                                                                                                                                                                                                         |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Trafik keluar IPv6 sahaja bocor ke IPv4**               | Apabila hos proksi mempunyai kedua-dua rekod A dan AAAA (atau OS mengutamakan IPv4), Happy Eyeballs boleh membuat sambungan keluar melalui IPv4 walaupun anda mahukan laluan IPv6 sahaja. Penetapan `ipv6` menghapuskan kebocoran tersebut.                                                                                                                                                          |
| **Pembatalan akibat anomali trafik keluar dikongsi**      | Penyedia berputar (codex/openai) membatalkan token apabila banyak akaun menggunakan alamat IP keluar yang **sama** pada volum tinggi. Mengawal keluarga trafik keluar merupakan sebahagian daripada usaha mengekalkan akaun pada laluan keluar yang berbeza dan boleh diramal (lihat [`src/lib/proxyEgress.ts`](../../src/lib/proxyEgress.ts) untuk diagnostik IP keluar yang digunakan bersamanya). |
| **Trafik keluar deterministik untuk pematuhan/pengujian** | Apabila anda mesti menjamin trafik keluar melalui keluarga tertentu, `auto` tidak mencukupi.                                                                                                                                                                                                                                                                                                         |

Arahan tersebut sengaja ditetapkan **bagi setiap proksi**, bukannya secara global — proksi yang berbeza dalam kumpulan anda boleh mempunyai dasar yang berbeza.

## Tiga Nilai

| Nilai  | Label UI                   | Tingkah laku                                                                                                                                                          |
| ------ | -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto` | `Auto (tindanan berganda)` | OS memilih keluarga. Bagi hos proksi literal IP, keluarga ditentukan oleh literal tersebut; bagi nama hos, kedua-dua keluarga layak digunakan. Ini ialah nilai lalai. |
| `ipv4` | `IPv4 sahaja`              | Mengehadkan sambungan kepada IPv4. Gagal secara tertutup jika hos proksi tidak mempunyai rekod IPv4 (A).                                                              |
| `ipv6` | `IPv6 sahaja`              | Mengehadkan sambungan kepada IPv6. Gagal secara tertutup jika hos proksi tidak mempunyai rekod IPv6 (AAAA).                                                           |

Rentetan UI terletak dalam `src/i18n/messages/en.json` (`labelFamily`, `familyAuto`, `familyIpv4`, `familyIpv6`, `familyHint`).

## Cara Mengkonfigurasikannya

### Papan Pemuka

Pemilih tersebut terdapat dalam borang proksi pada tab **Kumpulan Proksi**:

1. Buka **Papan Pemuka → Tetapan → Proksi → Kumpulan Proksi**
2. Tambah atau edit proksi
3. Tetapkan menu lungsur **Keluarga IP** kepada `Auto (tindanan berganda)`, `IPv4 sahaja`, atau `IPv6 sahaja`
4. Simpan

Kawalan tersebut dipaparkan oleh `ProxyRegistryManager.tsx` (dilekapkan dalam `proxy/ProxyPoolTab.tsx`).

### API

Medan `family` ialah sebahagian daripada muatan penciptaan/kemas kini pendaftaran proksi, disahkan oleh `createProxyRegistrySchema` / `updateProxyRegistrySchema` (`src/shared/validation/schemas.ts`) dan dikendalikan oleh `POST` / `PATCH /api/v1/management/proxies`:

```bash
# Cipta proksi IPv6 sahaja
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "IPv6 egress",
    "type": "socks5",
    "host": "proxy.example.com",
    "port": 1080,
    "family": "ipv6"
  }'

# Tukar proksi sedia ada kepada IPv4 sahaja
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{ "id": "proxy-uuid-here", "family": "ipv4" }'
```

Medan yang sama turut diterima oleh objek konfigurasi proksi sebaris yang digunakan untuk entri proksi huluan (`upstream_proxy_config.family`, lihat [Model Data](#data-model)).

Untuk API CRUD/penugasan proksi yang selebihnya, lihat [PROXY_GUIDE.md](../ops/PROXY_GUIDE.md).

## Cara `auto` Diselesaikan

Apabila `family` ialah `auto`, OmniRoute **tidak** menambahkan sebarang arahan — URL proksi digunakan seperti sedia ada dan keluarga sambungan ditentukan secara intrinsik.

Pada masa pembinaan URL (`proxyConfigToUrl` / `normalizeProxyUrl` dalam `open-sse/utils/proxyDispatcher.ts`), proksi `auto` menghasilkan URL biasa tanpa penanda:

```ts
// open-sse/utils/proxyDispatcher.ts
const fam = parseProxyFamily(config.family);
const normalized = normalizeProxyUrl(proxyUrlStr, "context proxy", {
  allowSocks5,
});
return fam === "auto" ? normalized : `${normalized}?family=${fam}`;
```

Pada masa penghantaran (`resolveDispatcherFamily`), `auto` diselesaikan kepada keluarga intrinsik bagi hos literal IP, atau `null` (biarkan OS membuat keputusan) bagi nama hos:

```ts
// open-sse/utils/proxyDispatcher.ts
function resolveDispatcherFamily(parsed: URL): 4 | 6 | null {
  const directive = parseProxyFamily(parsed.searchParams.get("family") ?? undefined);
  const literal = detectIpLiteralFamily(parsed.hostname);
  if (directive === "auto") return literal; // null bagi nama hos → OS memilih
  // ...
}
```

Jadi:

- `auto` + hos literal IP (`192.0.2.1` / `[2001:db8::1]`) → keluarga literal tersebut.
- `auto` + nama hos → `null` → resolusi OS tindanan berganda standard.

## Cara `ipv4` / `ipv6` Dikuatkuasakan

Arahan bukan-`auto` dihantar sebagai satu penanda pertanyaan sintetik — `?family=ipv4` atau `?family=ipv6` — yang ditambahkan sekali pada URL proksi yang telah dinormalkan. `normalizeProxyUrl` memastikan penanda ini dibuang dan ditambahkan semula tepat sekali supaya ia tidak merosakkan penghuraian port.

Apabila dispatcher dibina, penanda tersebut dibaca dan ditukarkan kepada keluarga sambungan yang konkrit. Jika hos ialah literal IP daripada keluarga yang **bertentangan**, OmniRoute akan melontarkan ralat (percanggahan dikendalikan secara tutup-selamat):

```ts
// open-sse/utils/proxyDispatcher.ts
const want = directive === "ipv6" ? 6 : 4;
if (literal !== null && literal !== want) {
  throw new Error(
    `[ProxyDispatcher] Proxy family directive ${directive} contradicts ${literal === 6 ? "IPv6" : "IPv4"} literal host`
  );
}
```

Keluarga konkrit tersebut kemudiannya ditetapkan pada penyambung:

- **Proksi HTTP/HTTPS** (`ProxyAgent`): `proxyTls: { family, autoSelectFamily: false }` — menyahdayakan Happy Eyeballs supaya keluarga yang dipilih ialah satu-satunya keluarga yang didail.
- **Proksi SOCKS5**: penyambung tersuai menghantar `socket_options: { family, autoSelectFamily: false }` kepada klien SOCKS (lihat [Keserasian SOCKS5](#socks5-compatibility)).

## Keserasian SOCKS5

Penetapan keluarga berfungsi dengan proksi SOCKS5, tetapi `fetch-socks` standard tidak mendedahkan pilihan soket yang diperlukan untuk menetapkan keluarga bagi lompatan proksi. OmniRoute menyediakan penyambungnya sendiri untuk tujuan tersebut:

```ts
// open-sse/utils/socksConnectorWithFamily.ts
export function buildSocksFamilySocketOptions(family: 4 | 6 | null): Record<string, unknown> {
  if (family === 6) return { family: 6, autoSelectFamily: false };
  if (family === 4) return { family: 4, autoSelectFamily: false };
  return {};
}
```

Semua penghantaran SOCKS5 melalui `createSocksDispatcherWithFamily` tanpa mengira `family` (termasuk `null` / `auto` melalui nama hos): `buildSocksFamilySocketOptions(null)` menghasilkan `{}`, dan laluan `SocksClient.createConnection` + TLS `buildConnector` yang sama digunakan dengan penetapan `socket_options` supaya Happy Eyeballs tidak dapat memilih IPv4 bagi dasar egress IPv6 sahaja.

Sokongan SOCKS5 itu sendiri didayakan secara lalai (boleh dinyahaktifkan melalui `ENABLE_SOCKS5_PROXY=false`); lihat [PROXY_GUIDE.md → Pemboleh Ubah Persekitaran](../ops/PROXY_GUIDE.md#environment-variables).

## Tingkah Laku Tutup-Selamat

Tujuan utama arahan ini adalah untuk **menolak** dan bukannya beralih secara senyap kepada keluarga yang salah. Dua perlindungan menguatkuasakan perkara ini:

1. **Percanggahan literal** — arahan yang bercanggah dengan hos literal IP akan melontarkan ralat semasa dispatcher dibina (`resolveDispatcherFamily`, ditunjukkan di atas).

2. **Semakan DNS prapenerbangan nama hos** — bagi proksi nama hos dengan keluarga yang ditetapkan, `proxyFetch.ts` mengesahkan bahawa nama hos tersebut benar-benar mempunyai rekod dalam keluarga yang diperlukan **sebelum** melakukan egress, melalui `assertHostnameSupportsFamily`:

   ```ts
   // open-sse/utils/proxyFamilyResolve.ts
   const hasFamily = records.some((r) => r.family === family);
   if (!hasFamily) {
     throw new Error(
       `[ProxyFamily] Proxy host ${host} has no ${family === 6 ? "IPv6 (AAAA)" : "IPv4 (A)"} record; ` +
         `refusing ${family === 6 ? "IPv6" : "IPv4"}-only egress (fail-closed)`
     );
   }
   ```

   Jika berlaku kegagalan, `proxyFetch.ts` menandai ralat tersebut dengan `code = "PROXY_FAMILY_UNAVAILABLE"` dan `statusCode = 503`. Kegagalan resolusi DNS turut dikendalikan secara tutup-selamat (enggan melakukan egress).

Hos literal IP tidak memerlukan sebarang tindakan bagi prapenerbangan DNS — keluarganya bersifat intrinsik dan tidak memerlukan carian.

## Model Data

Lajur `family` telah ditambahkan oleh migrasi `099_proxy_family.sql` pada **dua** jadual:

```sql
-- src/lib/db/migrations/099_proxy_family.sql
ALTER TABLE proxy_registry ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
ALTER TABLE upstream_proxy_config ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
```

- `proxy_registry.family` — arahan bagi setiap proksi untuk entri pendaftaran (`src/lib/db/proxies.ts`). Pertanyaan resolusi memilih `family` bersama-sama lajur proksi yang lain, dan nilai yang tiada/bukan rentetan ditukar secara paksa kepada `"auto"`.
- `upstream_proxy_config.family` — arahan untuk entri proksi huluan (`src/lib/db/upstreamProxy.ts`), dengan nilai lalai `"auto"` yang sama.

Apabila objek proksi yang telah diselesaikan membawa `family` bukan `auto`, `proxyConfigToUrl` menambahkan penanda `?family=` supaya penetapan tersebut kekal sehingga ke penghantar.
