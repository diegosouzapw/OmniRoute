> **Versi:** v3.8.44
> **Kemas kini terakhir:** 2026-07-03
> **Khalayak:** Jurutera yang menambah, menyelenggara atau menyahpepijat perkhidmatan terbenam (9Router, CLIProxyAPI, Mux, Bifrost).

Perkhidmatan terbenam ialah alat sesampai proses yang dipasang secara setempat, diselia dan
didedahkan oleh OmniRoute sebagai sasaran penghalaan kelas pertama. Tidak seperti penyedia luaran (yang dicapai melalui internet
menggunakan kunci API), perkhidmatan terbenam berjalan pada mesin yang sama dengan OmniRoute dan berkomunikasi melalui gelung balik.

## 1. Gambaran keseluruhan

### Mengapakah perkhidmatan terbenam diperlukan?

Lima perkhidmatan disertakan secara terbenam:

| Perkhidmatan    | Pakej npm                             | Port lalai | Tujuan                                                                                                                                                                                                     |
| --------------- | ------------------------------------- | :--------: | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **9Router**     | `9router`                             |   20130    | Penghala AI yang boleh digunakan oleh OmniRoute sebagai subpenyedia. Model didedahkan sebagai `9router/{sub}/{model}`                                                                                      |
| **CLIProxyAPI** | Binari keluaran GitHub (`cliproxy`)   |    8317    | Penyesuai proksi setempat untuk aliran pengesahan CLI Anthropic. Menyediakan penghalaan sandaran apabila token OAuth tamat tempoh                                                                          |
| **Mux**         | `mux` (`mux server` tanpa antaramuka) |    8322    | Daemon orkestrasi ejen setempat (coder/mux). Diuruskan dari segi kitar hayat sahaja — bukan sasaran penghalaan (tiada pemproksian LLM).                                                                    |
| **Bifrost**     | `@maximhq/bifrost`                    |    8080    | Bahagian belakang geganti get laluan AI Go. Apabila berjalan, dipilih secara automatik oleh laluan geganti (`/v1/relay/`)                                                                                  |
| **Dario**       | `@askalf/dario`                       |    3456    | Proksi langganan Claude — alternatif/sandaran kepada CLIProxyAPI untuk trafik berformat Claude Code; kunci yang disuntik menjadi `DARIO_ADMIN_TOKEN` yang mengawal satah kawalan OAuth `/admin/*` miliknya |

Kelima-limanya mengikuti model penyeliaan yang sama:

- OmniRoute memasangnya di bawah `DATA_DIR/services/{name}/` (diasingkan daripada `package.json` milik OmniRoute)
- OmniRoute memulakan dan memantau perkhidmatan tersebut sebagai proses anak
- OmniRoute menyuntik kunci API sementara ke dalam persekitaran proses anak dan menggilirnya tanpa masa henti (jika berkenaan)
- Semua laluan pengurusan (`/api/services/*`) ialah **LOCAL_ONLY** — hanya boleh dicapai melalui gelung balik (peraturan tegas #17)

### Keputusan utama (daripada pelan reka bentuk)

| Keputusan                                  | Nilai                                                                                  |
| ------------------------------------------ | -------------------------------------------------------------------------------------- |
| Akses papan pemuka kepada UI natif 9Router | Proksi songsang di `/dashboard/providers/services/9router/embed/*`                     |
| Mekanisme pemasangan                       | `npm install {package}` melalui `execFile` (tanpa interpolasi shell)                   |
| Mod penggunaan                             | Penyedia didaftarkan sebagai `9router/{sub}/{model}` dalam enjin penghalaan            |
| Pengurusan kunci API                       | OmniRoute menjana, menyulitkan semasa disimpan (AES-256-GCM) dan menyuntik melalui env |
| Lokasi papan pemuka                        | `/dashboard/providers/services` (tiga tab)                                             |
| Mula automatik                             | Togol bagi setiap perkhidmatan, MATI secara lalai                                      |

## 3. Mesin keadaan kitar hayat

```
                    install()
  ┌─────────────┐ ──────────► ┌─────────────┐
  │ not_installed│             │   stopped   │◄──────────────────┐
  └─────────────┘             └──────┬──────┘                   │
                                     │ start()                   │
                                     ▼                           │ stop()
                               ┌──────────┐                      │
                               │ starting │                      │
                               └────┬─────┘                     │
             semakan kesihatan ok   │         ranap / SIGTERM    │
                               ┌────▼─────┐  (keluar dalam 5s)  │
                               │ running  │──── ranap ──────────►┤
                               └────┬─────┘                   ┌─▼────┐
                             stop() │                          │error │
                                    ▼                          └──────┘
                               ┌──────────┐
                               │ stopping │
                               └──────────┘
```

Keadaan disimpan dalam jadual DB `version_manager` (lajur `status`) dan dicerminkan
dalam keadaan dalam memori `ServiceSupervisor`. Keadaan dalam memori ialah sumber
berwibawa bagi proses yang sedang berjalan; keadaan DB ialah sandaran berkekalan semasa but.

### Peralihan keadaan

| Dari            | Peristiwa                            | Ke                     |
| --------------- | ------------------------------------ | ---------------------- |
| `not_installed` | `install()` berjaya                  | `stopped`              |
| `stopped`       | `start()` dipanggil                  | `starting`             |
| `starting`      | semakan kesihatan mengembalikan 200  | `running`              |
| `starting`      | proses keluar sebelum sihat          | `error`                |
| `running`       | `stop()` dipanggil                   | `stopping` → `stopped` |
| `running`       | proses keluar tanpa dijangka (< 5 s) | `error` (ranap pantas) |
| `running`       | proses keluar tanpa dijangka (> 5 s) | `error`                |
| `error`         | `start()` dipanggil                  | `starting`             |
| mana-mana       | `stop()` semasa `stopping`           | tiada operasi          |

### Kunci operasi

`ServiceSupervisor` menyusun operasi kitar hayat secara bersiri melalui kunci operasi tak segerak
(`withLock()`). Panggilan `start()` serentak pada penyelia yang sama menghasilkan tepat
satu proses baharu; pemanggil kedua menunggu dan mengembalikan status sedia ada. Ini mencegah
keadaan perlumbaan apabila, contohnya, mula automatik dan butang UI dicetuskan serentak.

## 4. Rujukan API

Semua laluan di bawah `/api/services/` adalah **LOCAL_ONLY** (gelung balik sahaja, peraturan tegas #17).
Permintaan bukan gelung balik menerima `403 LOCAL_ONLY` tanpa mengira token pengesahan.

### 4.1 Titik akhir 9Router (11 laluan)

#### `POST /api/services/9router/install`

Pasang 9Router daripada npm. Mencipta `DATA_DIR/services/9router/` dengan
`package.json` dan `node_modules/` tersendiri. Tidak bercanggah dengan kebergantungan OmniRoute sendiri.

**Badan permintaan** (semuanya pilihan):

```json
{ "version": "latest" }
```

| Medan     | Jenis    | Lalai      | Penerangan                               |
| --------- | -------- | ---------- | ---------------------------------------- |
| `version` | `string` | `"latest"` | tag versi npm atau semver untuk dipasang |

**Respons:**

| Status | Penerangan                                                             |
| ------ | ---------------------------------------------------------------------- |
| `200`  | `{ ok: true, installedVersion: "x.y.z", path: "..." }`                 |
| `400`  | Badan permintaan tidak sah (kegagalan pengesahan Zod)                  |
| `409`  | Sedang dipasang (kunci dipegang)                                       |
| `500`  | Pemasangan npm gagal — lihat `message` untuk ralat yang mudah difahami |

**Nota:** Menggunakan `execFile('npm', [...])` — tanpa shell, tanpa interpolasi (peraturan tegas #13).
Ralat EACCES dipaparkan sebagai mesej yang mudah difahami.

---

#### `POST /api/services/9router/start`

Mulakan 9Router. Mendaftarkan penyelia jika belum didaftarkan, kemudian memanggil
`supervisor.start()`. Idempoten apabila sudah berjalan.

**Badan permintaan:** tiada

**Respons:**

| Status | Penerangan                                         |
| ------ | -------------------------------------------------- |
| `200`  | Objek `ServiceStatus` (lihat skema di bawah)       |
| `409`  | 9Router tidak dipasang (`status: "not_installed"`) |
| `503`  | Gagal dimulakan (ralat proses — lihat `lastError`) |

**Skema ServiceStatus:**

```json
{
  "tool": "9router",
  "state": "running",
  "pid": 12345,
  "port": 20130,
  "health": "healthy",
  "startedAt": "2026-05-25T10:00:00.000Z",
  "lastError": null
}
```

---

#### `POST /api/services/9router/stop`

Hentikan 9Router dengan tertib. Menghantar SIGTERM, menunggu 15 s, kemudian SIGKILL jika masih hidup.
Idempoten apabila sudah dihentikan.

**Badan permintaan:** tiada

**Respons:**

| Status | Penerangan                         |
| ------ | ---------------------------------- |
| `200`  | `ServiceStatus` (state: "stopped") |
| `503`  | Penghentian gagal tanpa dijangka   |

---

#### `POST /api/services/9router/restart`

Bersamaan dengan `stop()` kemudian `start()` di bawah kunci operasi.

**Badan permintaan:** tiada

**Respons:** sama seperti `start` (mengembalikan `ServiceStatus` akhir).

---

#### `POST /api/services/9router/update`

Mengemas kini 9Router kepada versi npm yang lebih baharu. Jika perkhidmatan sedang berjalan, ia dihentikan
terlebih dahulu, pemasangan npm dijalankan (memasang versi yang lebih baharu di lokasi yang sama), kemudian
perkhidmatan dimulakan semula.

**Badan permintaan** (semuanya pilihan):

```json
{ "version": "latest" }
```

**Respons:**

| Status | Penerangan                                                      |
| ------ | --------------------------------------------------------------- |
| `200`  | `{ ok: true, previousVersion: "...", installedVersion: "..." }` |
| `400`  | Badan tidak sah                                                 |
| `500`  | Kemas kini npm gagal                                            |

---

#### `POST /api/services/9router/rotate-key`

Menjana kunci API baharu untuk 9Router, menyulitkannya semasa disimpan dan memulakan semula perkhidmatan
(jika sedang berjalan) supaya perkhidmatan menggunakan kunci baharu daripada persekitarannya. Kunci lama
dibatalkan serta-merta.

**Badan permintaan:** tiada

**Respons:**

| Status | Penerangan                                 |
| ------ | ------------------------------------------ |
| `200`  | `{ keyRotated: true, restarted: boolean }` |
| `500`  | Putaran gagal                              |

**Keselamatan:** Kunci baharu tidak pernah dikembalikan dalam respons (tiada kebocoran kelayakan).
Kunci tersebut disimpan dalam bentuk tersulit (AES-256-GCM) dalam jadual `version_manager`.

---

#### `GET /api/services/9router/status`

Mengembalikan gabungan status langsung + DB termasuk metadata versi dan pratonton kunci API.

**Respons:**

| Status | Penerangan             |
| ------ | ---------------------- |
| `200`  | Lihat skema di bawah   |
| `500`  | Pembacaan status gagal |

  "pid": 12345,
  "port": 20130,
  "health": "healthy",
  "startedAt": "2026-05-25T10:00:00.000Z",
  "lastError": null,
  "installedVersion": "1.2.3",
  "latestVersion": "1.2.4",
  "updateAvailable": true,

### 4.6 Proksi songsang (benaman papan pemuka 9Router)

Papan pemuka membenamkan UI web 9Router di dalam iframe melalui proksi songsang
dalaman di:

```
GET|POST|... /dashboard/providers/services/9router/embed/[...path]
```

Proksi ini:

- Memajukan permintaan kepada `http://127.0.0.1:{port}/{path}` (gelung balik sahaja)
- Membuang pengepala `cookie` dan `authorization` yang masuk (tiada kebocoran sesi OmniRoute)
- Menyuntik `Authorization: Bearer {apiKey}` untuk pengesahan 9Router
- Membuang `set-cookie`, `content-security-policy`, `x-frame-options`, `cross-origin-*` daripada respons
- Menulis semula respons HTML untuk menyuntik `<base href>` dan menormalkan laluan mutlak (`/foo` → `/dashboard/.../embed/foo`)

Peningkatan WebSocket untuk papan pemuka terbenam dikendalikan oleh pelayan pendamping pada
port khusus (lihat `src/lib/services/embedWsProxy.ts`).

**Keselamatan:** Laluan proksi benaman diklasifikasikan di bawah `LOCAL_ONLY_API_PREFIXES`
dan hanya boleh dicapai daripada gelung balik. Penyerang yang memperoleh JWT melalui
terowong Cloudflare/Ngrok tidak boleh menggunakan proksi untuk memasuki perkhidmatan terbenam.

## 5. Keselamatan

### Penguatkuasaan LOCAL_ONLY (peraturan keras #17)

Semua laluan di bawah `/api/services/` dan `/dashboard/providers/services/*/embed/`
diklasifikasikan sebagai LOCAL_ONLY dalam `src/server/authz/routeGuard.ts`. Semakan loopback
dijalankan tanpa syarat sebelum mana-mana cabang pengesahan:

```
permintaan tiba
  → isLocalOnlyPath(path)?
      → bukan loopback → 403 LOCAL_ONLY (sentiasa, sebelum semakan pengesahan)
      → loopback       → teruskan kepada pengesahan biasa
```

Ini menghalang JWT yang bocor (contohnya, melalui terowong) daripada mencetuskan `npm install` atau
penciptaan proses. Lihat `docs/security/ROUTE_GUARD_TIERS.md` untuk matriks peringkat
penuh.

### Suntikan kunci API

9Router dan Mux memerlukan kunci API/token pembawa untuk titik akhir HTTP mereka sendiri.
OmniRoute:

1. Menjana kunci melalui `crypto.randomBytes(32).toString("base64url")` dengan
   awalan khusus perkhidmatan (`nr_` untuk 9Router, `mx_` untuk Mux).
2. Menyulitkannya ketika disimpan menggunakan AES-256-GCM (sifer yang sama digunakan untuk kelayakan penyedia).
3. Menyahsulit dan menyuntiknya sebagai pemboleh ubah persekitaran semasa penciptaan proses —
   `NINEROUTER_API_KEY` untuk 9Router, `MUX_SERVER_AUTH_TOKEN` untuk Mux (tidak sekali-kali sebagai bendera CLI,
   supaya token tidak pernah muncul dalam penyenaraian `ps`/proses).
4. Tidak pernah mengembalikan kunci teks biasa dalam sebarang respons HTTP.

CLIProxyAPI menerima kunci satah data khusus yang disuntik semasa penciptaan proses
(`needsApiKey: true` — digunakan untuk penyegerakan model terhadap penyesuai).

### Pertahanan SSRF

Proksi HTTP songsang (`/dashboard/.../embed/[...path]`) dikodkan secara tetap untuk memajukan
hanya kepada `http://127.0.0.1:{port}`. Ia tidak pernah mengikuti ubah hala ke destinasi
bukan loopback. Pustaka `ssrf-req-filter` digunakan untuk menolak sebarang URL huluan yang
ditentukan berada di luar julat loopback.

### Keselamatan shell (peraturan keras #13)

`npm install` dipanggil melalui `execFile('npm', ['install', pkg, '--prefix', dir])` —
tiada literal templat, tiada shell dan tiada interpolasi laluan luaran ke dalam rentetan
perintah. Nilai masa jalan (port, kunci API) dihantar melalui objek `env` proses anak.

### Pensanitasian ralat (peraturan keras #12)

Semua respons ralat daripada `/api/services/*` melalui `buildErrorBody()` atau
`sanitizeErrorMessage()`. `err.stack` dan `err.message` mentah tidak pernah dikembalikan
secara verbatim kepada pemanggil.

## 7. Penyelesaian Masalah

### Perkhidmatan tidak dapat dimulakan

**Gejala:** Butang mula mengembalikan 503, keadaan kekal `"error"` atau `"starting"`.

**Senarai semak:**

1. Semak `GET /api/services/{name}/logs` (atau panel Log dalam papan pemuka). Cari
   baris seperti `Error: ENOENT`, `address already in use`, atau `Cannot find module`.
2. Sahkan `npm` berada dalam PATH: jalankan `which npm` daripada akaun pengguna yang sama yang menjalankan OmniRoute.
3. Sahkan perkhidmatan telah dipasang: semak `GET /api/services/{name}/status` untuk
   `installedVersion`. Jika `null`, jalankan pemasangan terlebih dahulu.
4. Semak bahawa `DATA_DIR/services/{name}/node_modules/` wujud dan tidak kosong.
5. Semak medan `lastError` dalam respons status untuk sebab keluar yang telah disanitasi.

---

### Permulaan sejuk adalah perlahan (> 10 s untuk mencapai `running`)

**Gejala:** Keadaan kekal `"starting"` untuk tempoh yang lama sebelum bertukar kepada `"running"` atau `"error"`.

**Penjelasan:** Permulaan sejuk 9Router merangkumi pengimportan pepohon kebergantungan yang besar (modul DNS,
terowong, MITM). Selang pemeriksaan kesihatan lalai ialah 2 s dengan 3 percubaan sebelum
penyelia mengisytiharkan tamat masa (tetapi terus membuat tinjauan).

**Penyelesaian:** `healthIntervalMs` dan tamat masa `waitForHealthy`
(`healthIntervalMs * 3`) boleh dikonfigurasikan dalam `bootstrap.ts`. Untuk perkhidmatan dengan masa
permulaan yang lebih lama, tingkatkan `healthIntervalMs` kepada 5000 dan `stopTimeoutMs` kepada 30 000.

---

### Pertembungan port (`EADDRINUSE`)

**Gejala:** Log menunjukkan `address already in use :::20130`.

**Punca:**

- Proses lain sedang menggunakan port 20130.
- Proses 9Router terdahulu tidak dihentikan sepenuhnya (PID zombi).

**Penyelesaian:**

1. Tukar port lalai melalui pemboleh ubah persekitaran `NINEROUTER_PORT` dalam `.env`.
2. Cari dan matikan proses yang berkonflik: `lsof -ti :20130 | xargs kill -9`.
3. Port boleh dikonfigurasikan bagi setiap perkhidmatan dalam `bootstrap.ts` melalui medan `port`.

**Nota:** 9Router menggunakan port 20130 secara lalai khusus untuk mengelakkan pertembungan dengan
port lalai OmniRoute, iaitu 20128.

---

### Kebenaran ditolak (EACCES) semasa pemasangan

**Gejala:** Pemasangan mengembalikan 500, log menunjukkan `EACCES` atau `permission denied`.

**Punca:**

- `DATA_DIR` atau direktori induknya tidak boleh ditulis oleh proses OmniRoute.
- Berjalan dalam Docker tanpa akar tanpa akses tulis kepada volum yang dipetakan.

**Penyelesaian:**

1. Semak `DATA_DIR` (lalai: `~/.omniroute/`): `ls -la ~/.omniroute/`
2. Pastikan pengguna proses OmniRoute memiliki direktori tersebut: `chown -R $USER ~/.omniroute/`
3. Dalam Docker, pastikan lekapan volum mempunyai kebenaran yang betul untuk pengguna bekas.

---

### Kemas kini gagal (tamat masa `npm install` atau ralat rangkaian)

**Gejala:** Kemas kini mengembalikan 500 dengan `InstallError`, log menunjukkan tamat masa rangkaian.

**Senarai semak:**

1. Sahkan pendaftaran npm boleh dicapai: `npm ping`.
2. Semak proksi korporat: `npm config get proxy`, `npm config get https-proxy`.
3. Cuba pemasangan secara manual: `npm install {package}@latest --prefix ~/.omniroute/services/{name}/`.
4. Jika berada di belakang rangkaian terpencil, muat turun awal fail tar dan gunakan `npm install /path/to/tarball.tgz`.

---

### Perkhidmatan menunjukkan keadaan `"error"` serta-merta selepas dimulakan (ranap pantas)

**Gejala:** Keadaan berubah daripada `"starting"` kepada `"error"` dalam masa kurang daripada 5 saat.
`lastError` menunjukkan `"Fast crash (exited with code 1)"`.

**Senarai semak:**

1. Baca keseluruhan penghujung log: `GET /api/services/{name}/logs?tail=500`.
2. Punca lazim: pemboleh ubah persekitaran yang diperlukan oleh perkhidmatan tiada.
3. Untuk 9Router: sahkan `NINEROUTER_DISABLE_MITM=true` dan
   `NINEROUTER_DISABLE_TUNNEL=true` terdapat dalam persekitaran yang dihantar semasa proses diwujudkan (lihat
   `installers/ninerouter.ts` `resolveSpawnArgs`).

## 8. Soalan Lazim

**S: Bolehkah saya mendedahkan titik akhir perkhidmatan terbenam kepada klien bukan gelung balik?**

Tidak. Tahap LOCAL_ONLY ditetapkan sedemikian dengan sengaja (peraturan mutlak #17). Laluan yang boleh menjalankan
`npm install` atau memulakan proses `node` tidak boleh dicapai daripada trafik bukan gelung balik,
kerana JWT yang bocor melalui terowong (Cloudflare, Ngrok, Tailscale) akan membolehkan
proses sewenang-wenangnya dimulakan. Tiada pengecualian untuk
`/api/services/` — tidak seperti `/api/mcp/`, laluan ini dikecualikan daripada senarai pintasan skop pengurusan.
Lihat `docs/security/ROUTE_GUARD_TIERS.md`.

---

**S: Adakah 9Router dan CLIProxyAPI akan tersedia dalam penggunaan produksi/awan?**

Ya. Kedua-dua perkhidmatan menggunakan model mengutamakan setempat yang sama seperti OmniRoute. Perkhidmatan tersebut berjalan
pada mesin yang sama dan berkomunikasi melalui gelung balik. "Produksi" di sini bermaksud VPS
atau pelayan setempat tempat OmniRoute digunakan, bukan penyedia awan jauh.

---

**S: Bagaimanakah cara untuk saya menyahpepijat penyelia?**

1. Ikuti strim log SSE: `curl -N http://localhost:20128/api/services/9router/logs`.
2. Semak log berstruktur dalam output pino OmniRoute yang ditapis mengikut
   ruang nama `service:supervisor`.
3. Periksa baris DB: `sqlite3 ~/.omniroute/omniroute.db "SELECT * FROM version_manager WHERE tool='9router'"`.
4. Gunakan `GET /api/services/9router/status` untuk melihat keadaan langsung semasa, PID, kesihatan
   dan `lastError` dalam satu panggilan.

---

**S: Penyelia menunjukkan `health: "degraded"` atau `health: "unknown"` tetapi keadaannya ialah `"running"`. Adakah itu suatu masalah?**

`"degraded"` bermaksud prob kesihatan mengembalikan respons selain 200. `"unknown"` bermaksud belum ada
prob yang selesai (keadaan perlumbaan dengan tinjauan pertama). Kedua-duanya bersifat sementara semasa permulaan.
Jika kesihatan kekal `"degraded"` selama lebih daripada `healthIntervalMs * 3` ms selepas
`"running"`, perkhidmatan terbenam sedang berjalan tetapi API HTTP perkhidmatan tersebut tidak memberikan respons. Semak
sama ada port dalam respons status adalah betul dan sama ada perkhidmatan benar-benar
mendengar pada port tersebut.

---

**S: Bolehkah saya menukar kunci API 9Router tanpa memulakan semula sepenuhnya?**

Tidak. Kunci API dihantar kepada 9Router melalui pemboleh ubah persekitaran semasa proses dimulakan.
Pemboleh ubah persekitaran tidak boleh diubah dalam proses yang sedang berjalan. `POST .../rotate-key`
menghentikan dan memulakan semula perkhidmatan secara automatik untuk menggunakan kunci baharu. Pemutaran kunci
berkuat kuasa dalam tempoh `stopTimeoutMs` perkhidmatan (lalai 15 s) ditambah masa
permulaannya.

---

**S: Apakah had penimbal gelang dan apakah yang berlaku apabila ia penuh?**

Setiap perkhidmatan mempunyai penimbal gelang khusus sebesar 5 MB. Apabila penimbal penuh, baris
log paling lama disingkirkan untuk memberi ruang kepada baris baharu. Peristiwa `snapshot` SSE mengembalikan
baris terkini dalam had `tail`. Log tidak disimpan secara berterusan pada cakera melainkan
`logsBufferPath` ditetapkan dalam baris DB.
