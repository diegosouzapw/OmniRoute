> **Sumber:** `src/lib/{a2a,acp,cloudAgent}/`, `src/app/api/{a2a,acp,cloud}/`, `src/app/api/v1/agents/`
> **Kemas kini terakhir:** 2026-06-28 — v3.8.40

OmniRoute menyediakan tiga antara muka berkaitan ejen yang berbeza. Ketiga-tiganya kelihatan serupa pada pandangan pertama tetapi menyelesaikan masalah yang berbeza. Gunakan halaman ini untuk memilih antara muka yang sesuai.

## Ringkasan

| Antara muka               | Paling sesuai untuk                                                                                                                              | Pengangkutan                      | Piawaian                       |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------- | ------------------------------ |
| **A2A — Ejen-ke-Ejen**    | Kerjasama merentas ejen dengan ejen rakan setara yang menggunakan protokol A2A                                                                   | JSON-RPC 2.0 melalui HTTP         | A2A v0.3 (spesifikasi terbuka) |
| **ACP — Daftar Ejen CLI** | Mengesan / mendaftarkan / melancarkan ejen pengekodan CLI yang dipasang pada mesin pengguna (Cursor, Cline, Codex CLI, Claude Code, Aider, dll.) | HTTP REST                         | Khusus untuk OmniRoute         |
| **Ejen Awan**             | Menghantar tugas pengekodan jangka panjang kepada perkhidmatan awan luaran (Codex Cloud, Devin, Jules, Cursor Cloud)                             | HTTP REST + tugas bersandarkan DB | Khusus untuk OmniRoute         |

Ketiga-tiganya adalah bebas — pilih mana-mana gabungan.

## Pepohon Keputusan

```
Adakah anda memerlukan perkhidmatan awan untuk melakukan kerja di luar mesin ini (Codex Cloud / Cursor Cloud / Devin / Jules)?
├─ YA → Ejen Awan (POST /api/v1/agents/tasks)
└─ TIDAK → Teruskan
    │
    Adakah anda mempunyai ejen rakan setara yang menggunakan A2A dan mahu bekerjasama?
    ├─ YA → A2A (POST /a2a)
    └─ TIDAK → Teruskan
        │
        Adakah anda perlu menyenaraikan / mengkonfigurasi ejen pengekodan CLI yang dipasang secara setempat?
        ├─ YA → ACP (GET /api/acp/agents)
        └─ TIDAK → Gunakan /v1/chat/completions biasa
```

## 1. A2A — Ejen-ke-Ejen

**Spesifikasi:** [A2A v0.3](https://a2a-protocol.org)
**Titik akhir OmniRoute:** `POST /a2a` (JSON-RPC 2.0)
**Kad Ejen:** `GET /.well-known/agent.json`

### Bila hendak digunakan

- Membina sistem berbilang ejen dengan OmniRoute sebagai salah satu rakan setara
- Mendedahkan kecerdasan penghalaan OmniRoute (penghalaan pintar, pengurusan kuota, dll.) kepada ejen dalam rangka kerja seperti Google ADK atau rangkaian ejen generik
- Membungkus OmniRoute di sebalik antara muka penemuan + penyeruan standard

### Kaedah

- `message/send` — hantar mesej dan terima respons segerak
- `message/stream` — hantar mesej + terima peristiwa kemajuan yang distrim melalui SSE
- `tasks/get` — baca tugas mengikut ID
- `tasks/cancel` — batalkan tugas yang sedang berjalan

### Kemahiran terbina dalam (6)

- `smart-routing` — halakan gesaan melalui gabungan yang optimum
- `quota-management` — laporkan keadaan kuota bagi setiap penyedia
- `provider-discovery` — senaraikan penyedia yang dipasang berserta keupayaannya
- `cost-analysis` — anggarkan kos permintaan/perbualan
- `health-report` — agregatkan keadaan pemutus/lengahan/sekat masuk bagi setiap penyedia
- `list-capabilities` — senaraikan kemahiran dan metadata yang tersedia untuk ejen

### Penjelasan terperinci

Lihat [A2A-SERVER.md](./A2A-SERVER.md) untuk butiran pengangkutan, struktur kad ejen, konfigurasi TTL tugas dan templat bagi menambahkan kemahiran baharu.

## 2. ACP — Pendaftaran Ejen CLI

**Titik akhir OmniRoute:** `GET /api/acp/agents`
**Sumber:** `src/lib/acp/{index,manager,registry}.ts`

### Apakah itu

ACP ialah **inventori ejen CLI setempat** OmniRoute. Ia mengesan CLI pengekodan yang dipasang pada hos (Cursor, Cline, Claude Code, Codex CLI, Continue, dll.), menentukan versinya dan memaparkannya pada papan pemuka supaya pengguna boleh mengkonfigurasi setiap CLI agar menghala ke OmniRoute.

Ini BUKAN protokol luaran — ia merupakan pendaftaran dalaman yang menggerakkan UI "Alat CLI" dan penjejakan cap jari CLI (lihat [CLI-TOOLS.md](../reference/CLI-TOOLS.md)).

### Fungsinya

- Memeriksa hos untuk binari CLI yang dipasang (menggunakan `which` / `where` mengikut OS)
- Membaca versi setiap CLI (memanggil `<bin> --version`)
- Secara pilihan menerima ejen tersuai yang ditakrifkan pengguna (laluan binari + semakan versi + argumen pelancaran)
- Menyimpan ejen tersuai secara berterusan dalam tetapan
- Mengembalikan senarai bersepadu kepada papan pemuka

### API REST

| Titik akhir       | Kaedah | Penerangan                                                              | Pengesahan |
| ----------------- | ------ | ----------------------------------------------------------------------- | ---------- |
| `/api/acp/agents` | GET    | Senaraikan ejen yang dikesan + tersuai (bilangan dipasang/jumlah)       | Kunci API  |
| `/api/acp/agents` | POST   | Tambah/kemas kini/alih keluar ejen tersuai (pembeza tindakan dalam isi) | Kunci API  |

Bentuk isi untuk POST (`customAgentBodySchema` dalam `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Kes penggunaan

- Halaman "Alat CLI" pada papan pemuka menyenaraikan alat yang dipasang dan membantu anda mengarahkan setiap alat tersebut ke OmniRoute
- Ejen tersuai membolehkan pengguna mahir mendaftarkan CLI dalaman/proprietari yang tidak dikenali oleh OmniRoute secara lalai
- Hasil pengesanan membekalkan data kepada matriks cap jari `cli-tools`

### Bila ACP TIDAK patut digunakan

- ACP tidak _menjalankan_ tugas. Ia hanya mengesan + mengkonfigurasi CLI. Untuk benar-benar menggunakan CLI, anda perlu melancarkannya sendiri dengan pemboleh ubah persekitaran yang disediakan oleh OmniRoute (`OPENAI_BASE_URL`, `OPENAI_API_KEY`, dll.).

## 3. Ejen Awan

**Titik akhir OmniRoute:** `/api/v1/agents/tasks/*` (kitaran hayat) + `/api/cloud/*` (infrastruktur)
**Sumber:** `src/lib/cloudAgent/`

### Apakah itu

Antara muka seragam untuk ejen pengekodan awan pihak ketiga. Anda menyerahkan gesaan + URL repositori, OmniRoute menghantarnya kepada ejen awan yang betul, meninjau status dan mengembalikan hasil.

### Ejen yang disokong (4, semuanya disahkan dalam `src/lib/cloudAgent/agents/`)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### Kitaran hayat

```
POST /api/v1/agents/tasks
  → BaseAgent.createTask() bagi setiap kelas ejen
  → perkhidmatan luaran mula berfungsi
  → baris tugas dicipta dalam DB (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → penyegerakan status secara malas daripada penyedia
  → mengembalikan status semasa + rancangan + log aktiviti
  ↓
POST /api/v1/agents/tasks/[id]   (tindakan: "approve" | "message" | "cancel")
  → memajukan kepada penyedia (atau menandakan sebagai dibatalkan secara setempat)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → pembatalan setempat
```

### Pengesahan

⚠️ **Semua titik akhir `/api/v1/agents/tasks/*` memerlukan pengesahan pengurusan** (komit `588a0333`). Pemanggil yang hanya menggunakan Bearer menerima 401 sejak v3.8.0.

### Perincian mendalam

Lihat [CLOUD_AGENT.md](./CLOUD_AGENT.md) untuk kontrak `CloudAgentBase`, butiran khusus bagi setiap ejen, butiran skema dan titik akhir infrastruktur kelayakan.

## Perbandingan: A2A berbanding Ejen Awan

Kedua-duanya mempunyai "tugas jangka panjang", tetapi pada lapisan yang berbeza:

| Aspek                    | A2A                                                                                   | Ejen Awan                                 |
| ------------------------ | ------------------------------------------------------------------------------------- | ----------------------------------------- |
| Piawaian                 | Open A2A v0.3                                                                         | Khusus untuk OmniRoute                    |
| Tempat pengiraan berlaku | Dalam OmniRoute (menggunakan gabungan yang dikonfigurasikan)                          | Luaran (pelayan Codex / Devin / Jules)    |
| Tempoh tugas             | TTL lalai 5 min (boleh dikonfigurasikan dalam `TaskManager`)                          | Beberapa minit hingga beberapa jam        |
| Peka repositori          | Tidak (hanya menghantar gesaan)                                                       | Ya (URL repositori + cabang)              |
| Kes penggunaan           | Kerjasama merentas ejen, penghalaan pintar sebagai perkhidmatan                       | Wakilkan "laksanakan ciri X dalam repo Y" |
| Pengesahan               | `OMNIROUTE_API_KEY` pilihan untuk `/a2a`; pengurusan untuk pembantu REST `/api/a2a/*` | Sentiasa menggunakan pengurusan           |

## Contoh Integrasi

### Temui keupayaan A2A OmniRoute

```bash
curl http://localhost:20128/.well-known/agent.json
```

Mengembalikan Kad Ejen dengan kesemua 6 kemahiran, pengangkutan dan versi.

### Panggil OmniRoute sebagai ejen A2A

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### Senaraikan ejen CLI yang dipasang melalui ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Tambah ejen CLI tersuai

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### Hantar tugas Ejen Awan

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### Semak status tugas awan secara berkala

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## Bila Perlu Menggunakan Apa

- **Antara muka chatbot / pembantu pengaturcaraan** → `/v1/chat/completions` (serasi dengan OpenAI — bukan protokol ejen)
- **Kerjasama berbilang ejen** → A2A
- **Menyenaraikan CLI setempat dalam papan pemuka** → ACP
- **Mewakilkan tugas pengekodan jangka panjang kepada perkhidmatan awan** → Ejen Awan
