AgentBridge ialah proksi MITM (Man-in-the-Middle) OmniRoute yang memintas trafik HTTPS daripada ejen AI IDE dan menghalakannya semula melalui enjin penghalaan bersepadu OmniRoute. Ia menyokong **10 ejen IDE** — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code dan Trae (sedang disiasat) — menjadikan OmniRoute proksi MITM dengan liputan paling luas untuk pembantu pengekodan AI di pasaran.

**Lokasi papan pemuka:** `/dashboard/tools/agent-bridge`
**Kumpulan bar sisi:** Alat (selepas Ejen Awan)
**Lihat juga:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — pantau semua trafik yang dipintas dalam masa nyata; `docs/security/MITM-TPROXY-DECRYPT.md` (git; tidak dikompil ke dalam `/docs`) — mod tangkapan nyahsulit telus TPROXY Linux yang dikendalikan oleh laluan `/api/tools/agent-bridge/tproxy`.

## §1 Gambaran Keseluruhan

### Apakah itu AgentBridge?

Apabila ejen IDE (cth., GitHub Copilot, Cursor, Claude Code) membuat panggilan API, ia bersambung secara langsung kepada penyedia AI huluan (OpenAI, Anthropic, dll.). AgentBridge memintas sambungan tersebut secara telus pada peringkat TLS — tanpa memerlukan sebarang perubahan konfigurasi ejen — dan menulis semula permintaan melalui OmniRoute.

Ini bermakna anda boleh:

- **Halakan semula mana-mana ejen kepada mana-mana penyedia**: Copilot berkomunikasi dengan OpenAI? Alihkan ia kepada Anthropic Claude, Gemini atau mana-mana daripada 352 penyedia OmniRoute.
- **Gunakan pemetaan model**: `gemini-3-flash` → `claude-sonnet-4.7` secara telus pada peringkat pengendali.
- **Pantau semua trafik ejen**: setiap permintaan yang dipintas diterbitkan kepada [Pemeriksa Trafik](./TRAFFIC_INSPECTOR.md).
- **Gunakan daya tahan OmniRoute**: penghalaan kombo, pemutus litar, sandaran dan penjejakan kos turut berfungsi untuk trafik ejen IDE.

## §2 Seni bina

### 2.1 Gambaran keseluruhan komponen

```
Ejen IDE (VS Code / Cursor / dll.)
    │  HTTPS (port 443)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← Pengalihan DNS
    │
    ▼
src/mitm/server.cjs  (port 443, proses anak CJS)
    │  menentukan sasaran melalui SNI pengepala Host
    │  menjana sijil TLS bagi setiap SNI yang ditandatangani oleh CA AgentBridge
    ├── Sepadan dengan senarai pintasan? → laluan terus TCP (tiada penyahsulitan)
    ├── Sepadan dengan sasaran? → fetch → penghala OmniRoute (port 20128)
    │       └── handler.intercept() — TypeScript
    │               ├── maskSecrets() pada isi/pengepala permintaan
    │               ├── TrafficBuffer.push() — menerbitkan kepada Pemeriksa Trafik
    │               └── fetchRouter() → /v1/chat/completions
    └── Tiada padanan? → laluan terus TCP (tiada penyahsulitan)
```

### 2.2 Pelayan MITM (`src/mitm/server.cjs`)

Pelayan MITM teras berjalan sebagai proses anak CJS Node.js (untuk mengelakkan penulisan semula pangkalan kod CJS sedia ada). Ia:

- Mendengar pada port 443 (memerlukan keistimewaan atau `authbind`/`setcap`)
- Menerima terowong CONNECT daripada OS (melalui pengalihan DNS `/etc/hosts`)
- Menjana sijil TLS bagi setiap SNI yang ditandatangani oleh CA AgentBridge (`DATA_DIR/mitm/ca.crt`)
- Menentukan ejen sasaran melalui pengepala Host menggunakan registri `targets/index.ts`
- Menghantar ke lapisan pengendali TypeScript melalui HTTP ke `http://127.0.0.1:20128`

`TARGET_HOSTS` dimuatkan daripada `DATA_DIR/mitm/targets.json` (ditulis oleh `targets/index.ts` semasa but), membolehkan kemas kini dinamik tanpa memulakan semula pelayan CJS.

> **Model CA akar (#6684).** Penerangan sijil-bagi-setiap-SNI-yang-ditandatangani-oleh-CA di atas
> ialah model CA akar tersimpan yang ditambahkan dalam #6684 (`src/mitm/cert/rootCa.ts` +
> `src/mitm/_internal/rootCaShim.cjs`, menggunakan semula kriptografi CA/daun yang telah
> dibuktikan untuk TPROXY dalam `src/mitm/tproxy/dynamicCert.ts`) — ia menggantikan
> sijil daun ditandatangani sendiri statik tunggal yang lebih lama (`src/mitm/cert/generate.ts`, masih
> terhad hanya kepada hos antigravity) yang ditunjukkan oleh pasangan `server.crt`/`server.key`
> semata-mata pada cakera. **Tingkah laku migrasi**: pemasangan baharu (tiada
> `server.crt` terdahulu) mendapat model CA akar secara automatik; pemasangan yang telah
> mempercayai sijil daun statik lama akan terus menggunakannya sehingga pengendali menetapkan
> `MITM_ROOT_CA_ENABLED=true` dan memulakan semula perantara (`src/mitm/cert/migration.ts`
> ialah fungsi keputusan tulen — CA MITM dipercayai yang boleh menandatangani sijil daun untuk
> **mana-mana** hos secara nyata lebih berkuasa daripada sijil daun SAN tetap yang lama, maka
> pertukaran tidak pernah berlaku secara senyap untuk pemasangan yang telah dipercayai). Sijil CA dipasang
> ke dalam slot stor kepercayaan `omniroute-mitm.crt` yang sama seperti yang digunakan oleh sijil daun lama
> (`cert/install.ts::installCaCert`) — tiada pembersihan dwi-kepercayaan diperlukan.

### 2.3 Asas pengendali (`src/mitm/handlers/base.ts`)

Semua pengendali ejen melanjutkan `MitmHandlerBase`:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // Pembantu terlindung: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

Setiap pengendali memanggil `hookBufferStart()` sebelum membuat proksi dan `hookBufferUpdate()` apabila selesai. Fungsi ini menghantar entri `InterceptedRequest` ke dalam `globalTrafficBuffer` (lihat [Pemeriksa Trafik](./TRAFFIC_INSPECTOR.md) §4).

### 2.4 Registri sasaran (`src/mitm/targets/`)

Setiap ejen mempunyai fail sasaran deklaratif:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

Registri (`targets/index.ts`) mengeksport `ALL_TARGETS` dan menghasilkan `DATA_DIR/mitm/targets.json` semasa but.

### 2.5 Laluan terus dan senarai pintasan (`src/mitm/passthrough.ts`)

**Senarai pintasan** (disemak terlebih dahulu, dengan keutamaan mengatasi padanan sasaran):

- Corak lalai: hos perbankan, `.gov.`, penyedia OAuth/SSO (Okta, Auth0), dll.
- Corak pengguna: disimpan dalam jadual DB `agent_bridge_bypass`
- Hos yang dipintas menerima terowong TCP telus — TLS **tidak pernah dinyahsulit**

**Laluan terus lalai** (tiada padanan sasaran dan bukan dalam senarai pintasan):

- Turut menerima terowong TCP — sambungan tidak pernah diputuskan
- Menghalang AgentBridge daripada mengganggu trafik HTTPS sistem umum

Keutamaan penghalaan:

```
senarai pintasan → padanan sasaran → laluan terus
```

### 2.6 Sijil CA huluan (`src/mitm/upstreamTrust.ts`)

Untuk persekitaran rangkaian korporat dengan CA tersuai:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

Apabila ditetapkan, ini mengkonfigurasi penghantar global `undici` dengan sijil CA tambahan, membolehkan AgentBridge mencapai penyedia huluan melalui proksi penamatan TLS korporat.

### 2.7 Penyembunyian rahsia (`src/mitm/maskSecrets.ts`)

Pengimbas bilik bersih bebas digunakan pada isi permintaan dan pengepala bukti kelayakan
**sebelum** data tersebut memasuki penimbal Pemeriksa Trafik atau mana-mana log. Ia melakukan satu laluan linear:

- Token berawalan `sk-` / `ak-` / `pk-` (gaya OpenAI/Anthropic)
- Bukti kelayakan RFC 6750 `Authorization: Bearer <token>`, dengan keutamaan seluruh token
- Token legap panjang generik (≥40 aksara), termasuk bentuk bertitik dan berlapik

`sanitizeHeaders()` menukar nama yang dikekalkan kepada huruf kecil, menggabungkan nilai tatasusunan secara deterministik, menggugurkan
senarai larangan hop-demi-hop/pembingkaian yang dikongsi (termasuk pengesahan proksi), menyunting sepenuhnya `cookie` dan
`set-cookie`, serta menyerahkan nilai bukti kelayakan kepada pengimbas.

## §3 Persediaan

### 3.1 Mulakan/hentikan pelayan MITM

Gunakan Kad Pelayan AgentBridge di `/dashboard/tools/agent-bridge`:

| Tindakan               | Penerangan                                                                            |
| ---------------------- | ------------------------------------------------------------------------------------- |
| Mulakan Pelayan        | Melancarkan `src/mitm/server.cjs` pada port 443                                       |
| Hentikan Pelayan       | Menamatkan proses anak dengan selamat                                                 |
| Mulakan Semula Pelayan | Hentikan + mulakan (mengambil perubahan sasaran)                                      |
| Percayai Sijil         | Memasang `DATA_DIR/mitm/ca.crt` ke dalam stor kepercayaan OS                          |
| Muat Turun Sijil       | Memuat turun `ca.crt` untuk pemasangan manual                                         |
| Jana Semula Sijil      | Mencipta pasangan kunci CA baharu (semua sijil sedia ada bagi setiap ejen dibatalkan) |

### 3.2 Percayai sijil

Sijil CA AgentBridge mesti dipercayai oleh OS sebelum IDE menerima sambungan MITM.

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Rantai Kunci):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

Atau gunakan butang "Percayai Sijil" dalam papan pemuka (menjalankan perintah yang sesuai untuk OS anda, dengan gesaan sudo jika diperlukan).

#### IDE berasaskan Electron mengabaikan stor kepercayaan OS (`NODE_EXTRA_CA_CERTS`)

Sesetengah IDE — terutamanya **Antigravity IDE**, serta aplikasi lain yang diterbitkan daripada Electron / VS Code — menyertakan
masa jalan Node.js sendiri yang **tidak merujuk stor kepercayaan OS** untuk `fetch`/HTTPS
keluar. Mempercayai CA pada peringkat OS/NSS sudah memadai untuk **bahagian belakang** natif IDE
(cth. pelayan bahasa Go, yang menggunakan berkas CA OS), tetapi **bahagian hadapan Electron** masih
akan gagal TLS — ia kelihatan seolah-olah aplikasi telah _dilog keluar_ atau memaparkan _"ralat sambungan"_
walaupun log MITM menunjukkan panggilan but bahagian belakang mengembalikan `200`. Dua langkah
diperlukan dan kedua-duanya penting:

1. Halakan masa jalan kepada CA secara eksplisit:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **Lancarkan IDE daripada shell tersebut.** Memulakannya daripada ikon desktop / Dock / menu Mula
   **tidak** mewarisi eksport shell dan `~/.config/environment.d/*.conf` hanya berkuat kuasa selepas
   log masuk grafik yang baharu. Keluar sepenuhnya daripada IDE terlebih dahulu — kunci tika tunggal Electron
   bermakna pelancaran kedua hanya memfokuskan proses sedia ada dan persekitaran baharu diabaikan.

Langkah kepercayaan OS + NSS di atas masih diperlukan (tindanan rangkaian Chromium yang digunakan oleh sesetengah aliran
pengesahan membaca stor NSS setiap pengguna dan mempunyai sematan statik sendiri untuk `*.googleapis.com` yang
diatasi oleh CA yang dipercayai secara setempat). `NODE_EXTRA_CA_CERTS` turut meliputi laluan `fetch` Node.

### 3.3 Penghalaan DNS

Bagi setiap ejen yang ingin anda pintas, hos APInya mesti diselesaikan kepada `127.0.0.1`. AgentBridge mengurus entri `/etc/hosts` secara automatik apabila anda menogol DNS untuk sesuatu ejen dalam Bestari Persediaan.

Contoh entri `/etc/hosts` untuk GitHub Copilot:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 Pemetaan model

Gunakan Jadual Pemetaan Model dalam setiap kad ejen untuk menentukan pemetaan sumber → sasaran:

| Model sumber (natif ejen) | Model sasaran (OmniRoute) |
| ------------------------- | ------------------------- |
| `gpt-4o`                  | `claude-sonnet-4.7`       |
| `*` (kad bebas)           | `claude-haiku-4.7`        |

Kad bebas `*` memetakan mana-mana model yang tidak dikenali kepada sasaran yang ditentukan. Disimpan dalam jadual `agent_bridge_mappings`.

> **Petua — temukan ID model sebenar ejen.** IDE mungkin menghantar nama model yang berbeza daripada
> label UInya dan yang berubah antara versi utama. Contohnya, **Antigravity 2** menghantar
> `gemini-3.1-pro-low`, `gemini-pro-agent`, dan `gemini-3.1-flash-lite` melalui rangkaian — bukan
> `gemini-2.5-pro` yang ditunjukkan dalam dokumentasi lama. Hantar satu sembang tanpa pemetaan sepadan: MITM
> merekodkan `model:` masuk yang tepat dan meneruskan permintaan. Petakan nilai literal tersebut, kemudian
> permintaan seterusnya akan dipintas dan dihalakan kepada sasaran anda.

### 3.5 Notis risiko

AgentBridge memintas kelayakan (token OAuth, kunci API) yang digunakan oleh IDE untuk mengesahkan identiti dengan penyedia huluan. Ini **disamarkan sebelum dilog** (lihat §2.7), tetapi dapat dilihat oleh lapisan MITM OmniRoute. Pengaktifan pertama setiap ejen memaparkan modal notis risiko yang boleh ditutup.

### 3.6 Penyelenggaraan & Diagnostik

Papan pemuka menyediakan kad **Penyelenggaraan & Diagnostik** (`AgentBridgeMaintenanceCard`, dalam `src/app/(dashboard)/dashboard/tools/agent-bridge/components/`) yang memaparkan laluan operasi MITM yang sebelum ini tidak mempunyai UI. Sarikata kad tersebut: _"Uji sendiri saluran penangkapan, batalkan keadaan sistem yang tertinggal dan pindahkan persediaan anda antara mesin."_ Pembantu klien kad tersebut terletak dalam `src/lib/inspector/agentBridgeMaintenanceApi.ts`.

| Butang                  | Laluan                                 | Fungsinya                                                                                                                                                                                                   |
| ----------------------- | -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Diagnosis**           | `GET /api/tools/agent-bridge/diagnose` | Menjalankan ujian kendiri saluran tangkapan dan memaparkan laporan bagi setiap pemeriksaan (✓/✗ + petunjuk pemulihan).                                                                                      |
| **Baiki**               | `POST /api/tools/agent-bridge/repair`  | Membatalkan keadaan sistem MITM yatim (entri pemalsuan DNS, CA akar, proksi sistem) yang tertinggal akibat ranap atau SIGKILL. Idempoten — melaporkan "Tiada apa-apa untuk dibaiki" apabila keadaan bersih. |
| **Alih keluar CA**      | `DELETE /api/tools/agent-bridge/cert`  | Menyahpercayai dan mengalih keluar CA akar MITM daripada stor kepercayaan OS (eksplisit, idempoten). Dipaparkan hanya apabila CA sedang dipercayai; memerlukan pengesahan sebaris "Alih keluar CA?".        |
| **Eksport konfigurasi** | `GET /api/tools/agent-bridge/config`   | Memuat turun JSON konfigurasi mudah alih (lihat §3.7).                                                                                                                                                      |
| **Import konfigurasi**  | `POST /api/tools/agent-bridge/config`  | Memuat naik JSON konfigurasi yang telah dieksport sebelum ini (lihat §3.7).                                                                                                                                 |

**Pemeriksaan diagnostik** (`summarizeDiagnostics()` dalam `src/mitm/inspector/diagnostics.ts`). Laluan tersebut menjalankan prob berkesan untuk setiap pemeriksaan dan memasukkan nilai boolean ke dalam peringkas tulen; satu keputusan `healthy` berserta petunjuk bagi setiap kegagalan dikembalikan:

| Nama pemeriksaan   | Perkara yang disahkan                                   | Petunjuk apabila gagal                                                                                                                               |
| ------------------ | ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server-running`   | Proses pelayan MITM sedang aktif                        | "Pelayan MITM tidak berjalan. Mulakannya daripada tab AgentBridge."                                                                                  |
| `server-reachable` | Pelayan MITM menerima sambungan pada portnya (prob TCP) | "Pelayan MITM tidak menerima sambungan pada portnya. Pastikan port tersebut tersedia dan anda mempunyai keistimewaan untuk mengikatnya."             |
| `cert-exists`      | Sijil MITM telah dijana pada cakera                     | "Belum ada sijil MITM yang dijana. Jana satu daripada tab AgentBridge."                                                                              |
| `cert-trusted`     | CA akar MITM berada dalam stor kepercayaan OS           | "CA akar MITM tidak dipercayai oleh stor OS, jadi pemintasan TLS akan gagal. Percayai sijil tersebut daripada tab AgentBridge."                      |
| `dns-configured`   | Nama hos sasaran dipalsukan dalam `/etc/hosts`          | "Nama hos sasaran tidak dipalsukan dalam /etc/hosts, jadi trafik tidak pernah sampai kepada proksi. Dayakan DNS untuk ejen yang ingin anda tangkap." |

**Sepanduk keadaan yatim:** apabila halaman mengesan keadaan yang tertinggal akibat ranap (pemalsuan DNS / CA / proksi sistem), kad memaparkan sepanduk kuning jingga — _"Sesi terdahulu meninggalkan keadaan sistem (pemalsuan DNS, CA atau proksi sistem). Jalankan Baiki untuk membersihkannya."_ — dan menyerlahkan butang **Baiki**. `Repair` ialah analog lapisan aplikasi bagi bendera `--cleanup` ProxyBridge (ia mewakilkan kepada `repairMitm()` dalam `src/mitm/manager.ts`).

> CA akar MITM kekal dipasang merentasi henti/mula untuk mengelakkan gesaan sudo
> berulang (tingkah laku yang sama seperti mitmproxy/Charles), maka pengalihannya ialah tindakan
> **Alih keluar CA** yang eksplisit dan bukannya sesuatu yang berlaku secara automatik ketika berhenti.

### 3.7 Import/eksport konfigurasi mudah alih

AgentBridge boleh menyirikan keadaan yang **boleh dilaraskan oleh pengendali** ke dalam blob JSON berversi supaya persediaan boleh direplikasi merentasi mesin. Pensiri ialah `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`), yang disahkan oleh `AgentBridgeConfigSchema`.

Eksport tersebut mengandungi tepat tiga bahagian (nilai lalai terbina dalam sengaja **TIDAK** dieksport, supaya pengimportan tidak sekali-kali menduplikasi atau bercanggah dengannya):

| Medan            | Sumber                                                    | Catatan                                                                        |
| ---------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `bypassPatterns` | corak pintasan takrifan pengguna (`agent_bridge_bypass`)  | corak lalai bank/gov/okta dikecualikan                                         |
| `customHosts`    | hos tersuai Pemeriksa Trafik (`inspector_custom_hosts`)   | setiap satu: `{ host, kind: "llm"\|"app"\|"custom", label? }`                  |
| `agentMappings`  | pemetaan model bagi setiap ejen (`agent_bridge_mappings`) | `{ [agentId]: [{ source, target }] }` bagi setiap ejen yang mempunyai pemetaan |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**Tingkah laku import** (`POST /api/tools/agent-bridge/config`): corak pintasan dan pemetaan bagi setiap ejen **digantikan sepenuhnya**; hos tersuai ditambahkan secara **idempoten** (`INSERT OR IGNORE`). Respons melaporkan bilangan bagi setiap jenis yang telah digunakan:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

Perkara yang **TIDAK** terdapat dalam konfigurasi: status pelayan sedang berjalan, laluan sijil, status DNS bagi setiap ejen, laluan CA huluan dan tetapan TPROXY — semua itu ialah status hos/masa jalan, bukan keutamaan mudah alih.

## §5 Keselamatan

### Peraturan Tegas yang digunakan

| Peraturan                         | Penggunaan                                                                                                   |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| **#12** `sanitizeErrorMessage`    | Semua ralat pengendali dibersihkan sebelum respons atau kemasukan penimbal                                   |
| **#13** Penghantaran env shell    | Suntingan `/etc/hosts` menggunakan pilihan `env` — tiada interpolasi rentetan bagi laluan                    |
| **#15 + #17** `isLocalOnlyPath()` | `/api/tools/agent-bridge/` ialah LOCAL_ONLY + SPAWN_CAPABLE — gelung balik dikuatkuasakan sebelum pengesahan |

### Senarai pintasan untuk hos sensitif

Senarai pintasan memastikan institusi kewangan, penyedia OAuth/SSO dan hos sensitif lain **tidak pernah dinyahsulitkan**. Trafik TLS mereka melalui terowong TCP telus — OmniRoute tidak pernah melihat teks biasa.

Corak pintasan lalai termasuk:

- `*.bank.*`, `*.gov.*` (kewangan/kerajaan)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/identiti)
- `*.apple.com`, `*.icloud.com` (perkhidmatan sistem Apple)

Corak pintasan yang ditambahkan pengguna disimpan dalam jadual `agent_bridge_bypass` dan mengatasi segala-galanya.

### Penyamaran rahsia

`maskSecrets()` daripada `src/mitm/maskSecrets.ts` digunakan:

- Pada setiap isi permintaan sebelum `TrafficBuffer.push()`
- Pada setiap pengepala sebelum pengelogan atau penyiaran

Corak: token berawalan `sk-`/`ak-`/`pk-`, token `Bearer` dan token generik ≥40 aksara.

### Sijil CA huluan

Apabila `AGENTBRIDGE_UPSTREAM_CA_CERT` ditetapkan, fail dibaca semasa permulaan. Jika laluan wujud tetapi fail tidak boleh dibaca, AgentBridge merekodkan ralat yang jelas dan enggan dimulakan (menghalang kegagalan TLS senyap dalam persekitaran korporat).

### Batasan yang diketahui

- **Port 443 memerlukan keistimewaan**: Pada Linux, AgentBridge memerlukan `setcap 'cap_net_bind_service=+ep'` pada binari Node atau dijalankan melalui `authbind`. Wizard Persediaan memaparkan arahan khusus OS.
- **IDE perlu dimulakan semula**: Selepas pengalihan DNS, IDE mesti dimulakan semula agar resolusi hos baharu berkuat kuasa.
- **Token OAuth berkod keras**: Sesetengah ejen (Kiro, Antigravity) menyimpan token segar semula OAuth secara setempat. Token ini telus kepada AgentBridge — ia melihat token Bearer dalam setiap permintaan, yang disamarkan sebelum pengelogan.
- **Antara muka Electron memerlukan `NODE_EXTRA_CA_CERTS`**: IDE yang antara mukanya berjalan pada masa jalan Node/Electron terbundel mengabaikan gedung amanah OS/NSS dan mesti dilancarkan daripada shell dengan `NODE_EXTRA_CA_CERTS` ditetapkan (lihat §3.2). Gejala apabila tiada: bahagian belakang IDE berjaya disahkan (MITM menunjukkan `200`) tetapi UI kekal dilog keluar.
- **Berbilang pemasangan IDE yang sama adalah bebas**: pemasangan sistem (contohnya `/usr/share/antigravity/antigravity`) dan pemasangan "Full" setempat pengguna (contohnya `~/AntigravityIDE_Full/antigravity-ide`) ialah proses berasingan dengan masa jalan masing-masing — setiap satunya mesti dilancarkan semula dengan CA disuntik. Kenal pasti pemasangan yang sedang berjalan berdasarkan laluan binarinya sebelum melancarkannya semula.
- **Identiti ditetapkan oleh gesaan sistem ejen, bukan model yang dihalakan**: apabila anda memetakan semula model ejen kepada penyedia lain, balasan masih mendakwa identiti asal ejen tersebut (contohnya Antigravity menjawab "Saya dikuasakan oleh Gemini") kerana IDE menyuntik perkara itu ke dalam gesaan sistem. Sahkan bahagian belakang sebenar dalam `call_logs` / `proxy_logs` (`provider`, `model`, `target_format`), bukan dengan bertanya kepada model tentang identitinya.

## §6 Penyelesaian masalah

### Konflik port 443

Jika proses lain sudah mendengar pada port 443 (pelayan web, VPN, dan sebagainya):

```bash
lsof -i :443          # cari proses
sudo fuser -k 443/tcp  # paksa hentikan (gunakan dengan berhati-hati)
```

Sebagai alternatif, konfigurasikan port tanpa keistimewaan dalam tetapan AgentBridge dan sediakan peraturan pengalihan `iptables` / `pf`.

### Sijil tidak dipercayai

Jika IDE memaparkan ralat TLS selepas memulakan AgentBridge:

1. Sahkan sijil telah dipasang: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) atau `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. Sesetengah aplikasi mengekalkan stor kepercayaan mereka sendiri (Firefox, Chrome pada Linux). Jalankan "Trust Cert" sekali lagi dan semak stor sijil khusus NSS/Firefox.
3. Mulakan semula IDE selepas mempercayai sijil — sesi TLS yang sedang berlangsung menggunakan keadaan kepercayaan lama.

### IDE dilog keluar / "ralat sambungan" walaupun CA dipercayai

Gejala: selepas mengubah hala DNS dan mempercayai CA, IDE berasaskan Electron (contohnya Antigravity)
dibuka dalam keadaan **dilog keluar** atau memaparkan ralat pengesahan/sambungan, namun log MITM menunjukkan
panggilan pemula (`loadCodeAssist`, `fetchAvailableModels`, …) mengembalikan `200`.

Punca: masa jalan **Node/Electron terbina dalam IDE mengabaikan stor kepercayaan OS**. Bahagian belakang
asli (pelayan bahasa Go) mempercayai CA OS dan berjaya membuat pengesahan, tetapi bahagian hadapan Electron
tidak — oleh itu UI menganggap ia berada di luar talian.

Penyelesaian (kedua-dua langkah): eksport `NODE_EXTRA_CA_CERTS=<ca.crt>` **dan lancarkan semula IDE daripada
shell tersebut**, bukan daripada ikon desktop. Tutup IDE sepenuhnya terlebih dahulu — kunci tika tunggal Electron
menyebabkan pelancaran kedua hanya memfokuskan proses sedia ada dan persekitaran baharu diabaikan. Lihat §3.2.
Ini mencerminkan laporan huluan terbuka yang menyatakan bahawa ejen kendiri berfungsi melalui MITM tetapi varian IDE
gagal dalam persediaan yang sama.

### DNS tidak disebarkan

Semak bahawa `/etc/hosts` telah dikemas kini:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

Kosongkan cache DNS:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### IDE tidak dikesan

Pengesanan automatik menggunakan laluan pemasangan lazim. Jika pengesanan gagal tetapi IDE telah dipasang:

- Semak sama ada binari IDE berada di lokasi bukan standard
- Wizard Persediaan masih berfungsi — kegagalan pengesanan hanya bermakna lencana tidak akan menunjukkan laluan pemasangan

### Ralat pengendali (pengambilan huluan gagal)

Jika AgentBridge berjaya memintas tetapi semua permintaan gagal:

1. Sahkan sekurang-kurangnya satu penyedia disambungkan di `/dashboard/providers`
2. Semak log pelayan OmniRoute: `APP_LOG_LEVEL=debug` dalam `.env`
3. Sahkan `OMNIROUTE_BASE_URL` menghala ke titik akhir penghala yang betul (lalai: `http://127.0.0.1:20128`)

## §8 Hala Tuju

### Siasatan Trae

Trae ialah pembantu pengekodan AI yang agak baharu. Sebelum melaksanakan pengendali:

1. Kenal pasti binari/sambungan dalam gedung VS Code / JetBrains atau sebagai aplikasi kendiri
2. Tangkap trafik dengan mitmproxy untuk mengenal pasti hos API dan bentuk titik akhir
3. Tentukan mekanisme pengesahan
4. Nilai teruskan/hentikan berdasarkan TOS dan kebolehkesanan API

Sehingga siasatan selesai, kad Trae dalam papan pemuka memaparkan lencana "Sedang Disiasat" dengan pautan "Laporkan kebolehlaksanaan". Rangka pengendali di `src/mitm/handlers/trae.ts` melontarkan ralat berstruktur `Belum dilaksanakan`.

### Ejen tertunggak (MITM diperlukan — tiada sokongan URL asas tersuai)

Alat berikut tidak menyokong URL asas tersuai dalam versi semasa, menjadikan MITM satu-satunya laluan pemintasan. Penilaian kebolehlaksanaan masih belum selesai:

- **Windsurf** (Codeium/Cognition)
- **Amp** (Sourcegraph)
- **Amazon Q / Kiro CLI** (AWS Bedrock — berasingan daripada Kiro IDE)
- **Cowork** (desktop Anthropic)

Nota: GitHub Copilot CLI ≥v1.0.19 menyokong `COPILOT_PROVIDER_BASE_URL` — gunakan konfigurasi langsung dan bukannya MITM untuk alat tersebut.
