> **TL;DR**: `open-sse/` ialah enjin penstriman teras yang mengendalikan setiap permintaan LLM dalam OmniRoute. Ia mengandungi ~1,400 fail yang melaksanakan saluran permintaan, pelaksana, perkhidmatan, pelayan MCP dan lapisan penterjemahan. Panduan ini menerangkan cara semua komponen tersebut saling berfungsi.

**Sumber:** `open-sse/` (pakej ruang kerja, ~1,440 fail `.ts` bukan ujian)

---

## Mengapa Pakej Ruang Kerja Berasingan?

`open-sse/` ialah **ruang kerja kendiri** dalam monorepo OmniRoute atas beberapa sebab:

1. **Kebolehgunaan semula** — `open-sse` diterbitkan sebagai `@omniroute/open-sse` di npm, jadi projek lain boleh menggunakannya secara bebas
2. **Sempadan yang jelas** — enjin penstriman dipisahkan daripada lapisan UI/DB khusus OmniRoute
3. **Prestasi** — enjin ini tidak mempunyai kebergantungan Next.js, membolehkan permulaan sejuk yang lebih pantas dalam konteks CLI/tanpa pelayan
4. **Pengurusan versi** — `open-sse` boleh membuat keluaran mengikut jadualnya sendiri

```json
// package.json
"workspaces": ["open-sse"]
```

## Saluran Permintaan

Setiap permintaan LLM mengalir melalui **saluran 5 peringkat**:

```
                              ┌──────────────┐
   Permintaan HTTP             │  1. HALAKAN  │   peleraian kombo, pemilihan model
   (laluan Next.js)            └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │ 2. TERJEMAH  │   penukaran format (OpenAI ↔ Claude ↔ Gemini)
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │ 3. LAKSANAKAN│   pelaksana penyedia, HTTP, cuba semula, pemutus
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  4. STRIM    │   transformasi SSE, tekanan balik
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  5. REKOD    │   penjejakan penggunaan, log panggilan, pengelasan ralat
                              └──────┬───────┘
                                     │
                                     ▼
                              Respons HTTP (SSE atau JSON)
```

### Peringkat 1: Halakan (services/combo.ts)

**Titik masuk**: `handleComboChat()` dalam `services/combo.ts`

Meleraikan permintaan kepada tupel `(provider, model, account, credentials)` yang konkrit:

- Cari kombo mengikut ID (atau bina kombo maya untuk model `auto/*`)
- Gunakan strategi penghalaan (keutamaan, berwajaran, round-robin dan sebagainya)
- Tapis keluar penyedia yang tidak sihat (pemutus litar)
- Pilih sasaran berdaya maju yang seterusnya

Untuk model `auto/*`, peringkat ini turut:

- Menjalankan algoritma **pemarkahan 16 faktor** (`services/autoCombo/`)
- Memilih pasangan `provider+model` berdasarkan kesihatan, kos, kependaman dan sebagainya

### Peringkat 2: Terjemah (translator/)

Jika format sumber (contohnya, OpenAI) berbeza daripada format sasaran (contohnya, Claude), permintaan tersebut akan **diterjemahkan**:

- Prom sistem → mesej sistem
- Takrif alat → format alat khusus penyedia
- Parameter penaakulan/pemikiran → padanan khusus penyedia
- Penyeragaman peranan mesej (`developer` → `system` untuk selain OpenAI)

`translator/index.ts` mendedahkan:

```ts
translateRequest(body, sourceFormat, targetFormat): TranslatedRequest
needsTranslation(source, target): boolean
```

### Peringkat 3: Laksanakan (executors/)

**Titik masuk**: `getExecutor(providerId).execute(request, options)`

Semua penyedia menggunakan `DefaultExecutor` (`executors/default.ts`) melalui sandaran kilang `getExecutor()`. Pelaksana tersebut:

- Membina URL huluan (`buildUrl()`)
- Menambahkan pengepala khusus penyedia (`buildHeaders()`)
- Mengubah badan permintaan (`transformRequest()`)
- Menghantar permintaan HTTP dengan percubaan semula + undur eksponen
- Mengendalikan penyegaran pengesahan jika diperlukan (penyedia OAuth)

Semua pelaksana melanjutkan `BaseExecutor` (`executors/base.ts`, 1170 LOC), yang menyediakan:

- Logik percubaan semula umum
- Penyepaduan proksi
- Penyepaduan pemutus litar
- Cangkuk perekodan penggunaan

### Peringkat 4: Strim (utils/stream.ts)

Bagi respons penstriman, pelaksana mengembalikan **ReadableStream**. Pengendali tersebut:

- Menyalurkan melalui transformasi SSE (`createSSETransformStreamWithLogger`)
- Menggunakan ping denyutan jantung untuk mengesan sambungan terputus
- Mengendalikan pemutusan sambungan klien dengan baik (`pipeWithDisconnect`)
- Mengubah SSE → JSON untuk klien bukan penstriman

Bagi respons bukan penstriman, pelaksana mengembalikan objek JSON yang telah dihuraikan dan diteruskan tanpa perubahan.

### Peringkat 5: Rekod (services/usage.ts)

Selepas respons (berjaya atau gagal), penggunaan direkodkan:

- `prompt_tokens`, `completion_tokens`, `cached_tokens` daripada respons
- `cost_usd` dikira berdasarkan data harga
- `latency_ms`, `status`, `error_class` jika gagal
- Disimpan dalam jadual `usage_history`

Artifak log panggilan (jika didayakan) ditulis ke `${DATA_DIR}/call_logs/`.

## Analisis Mendalam Fail Utama

### chatCore.ts (5977 baris)

**Pengendali permintaan utama**. Walaupun saiznya besar, ia mempunyai struktur yang jelas:

```ts
// Pseudo-struktur chatCore.ts
export async function handleChat(request: NextRequest) {
  // 1. Autentikasi + CORS
  await authenticateRequest(request);
  applyCorsHeaders(response);

  // 2. Validasi badan
  const body = await parseRequestBody(request);

  // 3. Pengesanan format + terjemahan
  const sourceFormat = detectFormat(request);
  const targetFormat = getTargetFormat(providerId);
  if (needsTranslation(sourceFormat, targetFormat)) {
    body = translateRequest(body, sourceFormat, targetFormat);
  }

  // 4. Penghalaan combo
  const targets = await resolveComboTargets(comboId, body);
  for (const target of targets) {
    try {
      const result = await executeOnTarget(target, body);
      await recordUsage(result);
      return result;
    } catch (err) {
      // Teruskan ke sasaran seterusnya
    }
  }

  // 5. Fallback kecemasan
  return await emergencyFallback(body);
}
```

Walaupun ia satu fungsi gergasi, ia disusun dalam **bahagian berkomen** yang memetakan kepada pipeline 5 peringkat.

### combo.ts (4456 LOC)

**Enjin penghalaan** yang menyelesaikan combo kepada sasaran mengikut tertib.

```ts
// services/combo.ts
export async function handleComboChat(body, comboId): Promise<ChatResult> {
  const targets = await resolveComboTargets(comboId, body);
  for (const target of targets) {
    try {
      return await handleSingleModel(target, body);
    } catch (err) {
      log.warn("target failed, trying next", { target, err });
    }
  }
  throw new ComboExhaustedError("All targets failed");
}
```

Menyokong **21 strategi penghalaan** (lihat `src/shared/constants/routingStrategies.ts`):

| Strategi            | Tingkah Laku                                                                             |
| ------------------- | ---------------------------------------------------------------------------------------- |
| `priority`          | Senarai tertib sasaran-pertama                                                           |
| `weighted`          | Probabilistik mengikut pemberat setiap sasaran                                           |
| `round-robin`       | Mengitar melalui sasaran mengikut tertib                                                 |
| `context-relay`     | Menyerahkan konteks merentasi sasaran                                                    |
| `fill-first`        | Mengisi kuota sebelum beralih ke seterusnya                                              |
| `p2c`               | Kuasa dua pilihan                                                                        |
| `random`            | Rawak seragam                                                                            |
| `least-used`        | Pilih yang paling sedikit digunakan baru-baru ini                                        |
| `cost-optimized`    | Sasaran sihat termurah dahulu                                                            |
| `reset-aware`       | Sedar tentang tetingkap tetapan semula pembekal                                          |
| `reset-window`      | Penghalaan berasaskan tetingkap tetapan semula                                           |
| `expiry-first`      | Menggunakan dahulu akaun yang kuotanya akan luput tanpa digunakan                        |
| `headroom`          | Baki ruang kuota terbanyak dahulu                                                        |
| `quota-weighted`    | Langkau akaun yang kehabisan, kemudian cabut mengikut baki kuota ÷ beban sedang diproses |

| `context-optimized` | Terbaik untuk permintaan konteks panjang                                                 |

| `fusion`            | Sebarkan ke panel secara selari, kemudian sintesis melalui hakim (`fusion.ts`)           |

### base.ts (1170 LOC)

**Executor abstrak** yang diwarisi oleh setiap kelas executor (secara langsung atau melalui `DefaultExecutor` dan subclass lain). Ia mengandungi:

- `buildUrl()` — pembinaan URL lalai (subclass override untuk tersuai)
- `buildHeaders()` — pengepala lalai (auth, content-type)
- `transformRequest()` — lulus terus secara lalai
- `execute()` — gelung HTTP utama dengan retry/backoff/breaker

```ts
// open-sse/executors/default.ts
export class DefaultExecutor extends BaseExecutor {
  // Mengendalikan semua pembekal serasi OpenAI/Anthropic
  // Pembekal mendaftar konfigurasi (URL, autentikasi, pengepala) tetapi berkongsi logik executor
}
```

Tingkah laku khusus pembekal (pengepala autentikasi, URL asas, pengepala versi) dikonfigurasikan melalui pendaftar pembekal, bukan kelas executor yang berasingan.

````

## Executor (150 modul)

Kebanyakannya satu fail bagi setiap penyedia. Semua kelas executor melanjutkan `BaseExecutor` dan mengatasi bahagian yang berbeza; modul lain ialah pembantu khusus penyedia (skema alat, penyesuai fetch/TTS, pengendali quirk).

### Corak Biasa

Penyedia diselesaikan melalui `getExecutor(providerId)`, yang mengembalikan executor yang dikonfigurasikan. Penyedia serasi OpenAI/Anthropic menggunakan `DefaultExecutor` (`executors/default.ts`). Tingkah laku khusus penyedia (URL asas, pengepala auth, versi API) dikonfigurasikan dalam `open-sse/config/providers/`, manakala transformasi badan permintaan dikendalikan dalam `open-sse/translator/`.

**URL tersuai** ditetapkan melalui konfigurasi penyedia:

```ts
// Konfigurasi penyedia dalam open-sse/config/providers/
export default {
  id: "together",
  baseURL: "https://api.together.xyz/v1/chat/completions",
}
````

**Auth tersuai** dikendalikan melalui konfigurasi auth registri penyedia (kunci API, OAuth, profil pengepala).

Transformasi **badan permintaan tersuai** (cth., Anthropic mengasingkan `system` daripada `messages`) didaftarkan mengikut penyedia dalam `open-sse/translator/`.

````

### Kilang Executor

`executors/index.ts` mengeksport `getExecutor(providerId)`:

```ts
import { getExecutor } from "@omniroute/open-sse/executors";

const executor = getExecutor("anthropic");
const result = await executor.execute({
  model: "claude-sonnet-4-5",
  messages: [...],
});
````

Penyelesaian berlaku melalui `ExecutorRegistry` (`executors/registry.ts`): setiap executor khusus diisytiharkan dalam jadual terbina dalam `executors/index.ts` dan didaftarkan melalui `registerExecutor(alias, instance)` semasa pemuatan modul; `getExecutor()` merujuk registri dan kembali kepada `DefaultExecutor` termemo untuk mana-mana penyedia tanpa entri khusus. Pemetaan penuh alias → executor dicirikan oleh ujian golden `tests/unit/executor-map-golden.test.ts`.

## Penterjemah

Terjemahkan antara **3 format**: OpenAI, Anthropic, Gemini, serta Responses API yang baharu.

### Bila Terjemahan Berlaku

```ts
import { needsTranslation, translateRequest } from "@omniroute/open-sse/translator";

if (needsTranslation(sourceFormat, targetFormat)) {
  body = translateRequest(body, sourceFormat, targetFormat);
}
```

Terjemahan lazim:

- `OpenAI → Anthropic`: medan `system` berasingan, pengepala `x-api-key`
- `OpenAI → Gemini`: `contents` menggantikan `messages`, `systemInstruction`
- `OpenAI → Responses API`: tatasusunan `input`, keadaan `previous_response_id`

### Kes Pinggir yang Dikendalikan

- Peranan `developer` → `system` untuk penyedia bukan OpenAI
- Peranan `system` → digabungkan ke dalam mesej pengguna pertama untuk GLM/ERNIE
- `json_schema` → `responseMimeType` + `responseSchema` Gemini
- `tools` → format alat khusus penyedia
- Parameter penaakulan (o1, Claude) → padanan khusus penyedia

## Pelayan MCP

`open-sse/mcp-server/` melaksanakan pelayan **Model Context Protocol**:

- **110 alat** (pengurusan penyedia, gabungan, memori, cache, pemampatan, proksi, kemahiran, gamifikasi, pemalam, Notion, Obsidian, korpus setempat)
- **3 pengangkutan**: stdio, SSE, HTTP Boleh Strim
- **33 skop** untuk kebenaran terperinci

### Pendaftaran Alat

Alat didaftarkan sebagai fail kendiri dalam `open-sse/mcp-server/tools/`, dengan setiap fail mengeksport nama, skema, pengendali dan skop:

```ts
// open-sse/mcp-server/tools/getHealth.ts
import { z } from "zod";
export default {
  name: "omniroute_get_health",
  description: "Dapatkan petikan keadaan sistem",
  scope: "read:health",
  inputSchema: z.object({}),
  handler: async (_args, ctx) => {
    return await getSystemHealth();
  },
};
```

### Pengangkutan

```ts
// stdio (penggunaan CLI)
startMcpStdio(server);

// SSE (penstriman berasaskan HTTP)
startMcpSse(server, port);

// HTTP Boleh Strim (MCP moden)
startMcpStreamable(server, port);
```

Setiap panggilan alat melalui semakan skop (`open-sse/mcp-server/auth/`):

```ts
if (!hasScope(apiKey, "providers:read")) {
  throw new Error("Skop tidak mencukupi");
}
```

## Pengubah

`open-sse/transformer/` menukar antara format **Chat Completions** dan **Responses API**.

### Mengapa Pengubah Berasingan?

Responses API ialah format baharu OpenAI dengan **perbualan berkeadaan** (`previous_response_id`). Apabila klien menghantar permintaan Responses, OmniRoute:

1. Menukar Responses → Chat Completions secara dalaman
2. Menghantar kepada penyedia (mana-mana penyedia yang menyokong Chat Completions)
3. Menukar respons kembali kepada format Responses
4. Menstrim respons yang ditukar kepada klien

Pengubah (`transformer/responsesTransformer.ts`) menyediakan:

```ts
createResponsesApiTransformStream(): TransformStream
```

Ini mengendalikan:

- Peristiwa `response.output_item.added`
- Peristiwa `response.output_text.delta`
- Peristiwa `response.completed`
- Pemetaan panggilan alat (`function_call` ↔ `tool_calls`)

## Kekangan Prestasi

Enjin penghalaan mempunyai belanjawan prestasi yang ketat:

| Operasi                                              | Sasaran | Pengukuran                        |
| ---------------------------------------------------- | ------- | --------------------------------- |
| Penyelesaian kombo                                   | <10ms   | Untuk 50 sasaran                  |
| Semakan had kadar                                    | <1ms    | Baldi token dalam memori          |
| Sandaran keluarga model                              | <5ms    | Takrifan keluarga yang dicachekan |
| Penghantaran penghalaan permintaan                   | <2ms    | Laluan panas                      |
| **Tiada I/O menyekat dalam laluan panas penghalaan** | —       | Semuanya tak segerak              |

## Antipola

❌ **Panggilan DB segerak dalam `combo.ts`** — prahitung dan cache
❌ **Logik cuba semula dalam pengendali** — gunakan `retry()` daripada perkhidmatan daya tahan
❌ **Akses terus kepada konfigurasi penyedia** — gunakan pengambil `providerRegistry`
❌ **Rantaian sandaran yang dikodkan keras** — takrifkan dalam `modelFamilyFallback.ts`
❌ **Mutasi keadaan merentas permintaan serentak** — gunakan konteks berskop permintaan sahaja

## Menambahkan Komponen Baharu

### Menambahkan Perkhidmatan Baharu

1. Cipta `open-sse/services/[serviceName].ts` dengan tanggungjawab yang terfokus
2. Eksport fungsi pengendali utama dan sebarang pemalar
3. Tambahkan ujian unit dalam `tests/unit/services/[serviceName].test.mjs`
4. Sepadukan ke dalam saluran paip permintaan dalam `handlers/chatCore.ts` (jika berkaitan dengan penghalaan)
5. Kemas kini logik penghalaan dalam `combo.ts` jika perkhidmatan mempengaruhi pemilihan sasaran
6. Dokumentasikan dalam fail ini

### Menambahkan Pelaksana Baharu

1. Cipta `open-sse/executors/[provider].ts` yang melanjutkan `BaseExecutor`
2. Daftarkan dalam `config/providerRegistry.ts`
3. Tambahkan pada kilang `executors/index.ts`
4. Tambahkan ujian unit untuk pelaksana
5. Dokumentasikan dalam `docs/architecture/ARCHITECTURE.md`

### Menambahkan Alat MCP Baharu

1. Cipta atau kemas kini `open-sse/mcp-server/tools/[category]Tools.ts`
2. Takrifkan skema Zod untuk input
3. Daftarkan alat dalam `mcp-server/index.ts`
4. Tambahkan pada matriks skop dalam `mcp-server/auth/`
5. Tambahkan ujian unit
