Pemampatan Caveman boleh memuatkan pek peraturan khusus bahasa sebagai tambahan kepada peraturan bahasa Inggeris terbina dalam.
Ini memastikan enjin teras kekal stabil sambil membolehkan pek bahasa Portugis, Sepanyol, Jerman, Perancis, Itali, Jepun dan
bahasa akan datang berkembang secara bebas.

## Lokasi

Pek bahasa terletak di bawah:

```txt
open-sse/services/compression/rules/<language>/
```

Pek semasa yang disertakan (disahkan berdasarkan kandungan direktori `rules/`):

| Bahasa            | Direktori      | Kategori peraturan yang tersedia                    |
| ----------------- | -------------- | --------------------------------------------------- |
| Inggeris          | `rules/en/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Sepanyol          | `rules/es/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Portugis (Brazil) | `rules/pt-BR/` | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Indonesia         | `rules/id/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Itali             | `rules/it/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| Jerman            | `rules/de/`    | `context`, `filler`, `structural`                   |
| Perancis          | `rules/fr/`    | `context`, `filler`, `structural`                   |
| Jepun             | `rules/ja/`    | `context`, `filler`, `structural`                   |

> **Catatan kesetaraan:** Pek `en`, `es`, `pt-BR`, `id` dan `it` mempunyai kesemua 5 kategori; `de`, `fr` dan `ja` disertakan dengan 3 kategori. Kategori `dedup` dan `ultra` yang tiada akan kembali menggunakan peraturan terbina dalam bahasa Inggeris secara senyap. Sumbangan dialu-alukan untuk menambahkan `dedup.json` dan `ultra.json` bagi pek yang lebih kecil.
>
> Pek `pt-BR` adalah berdasarkan **[Troglodita](https://github.com/leninejunior/troglodita)** oleh Lenine Júnior — sistem pemampatan yang direka dari awal untuk tatabahasa Portugis Brazil (pengurangan pleonasme, penyingkiran kata pengisi PT-BR, singkatan teknikal untuk komuniti pembangun BR).
>
> Senarai kategori kanonik dan skema bagi setiap kategori tersedia dalam [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) (JSON Schema draf 2020-12).

## Pengesanan Bahasa

`languageDetector.ts` menggunakan heuristik ringan untuk menentukan bahasa daripada teks prom. Bahasa lalai yang
dikonfigurasikan masih dihormati, dan pengesanan boleh dilumpuhkan melalui konfigurasi apabila kawalan tepat
diperlukan.

Output pengesanan hanya digunakan untuk memilih pek peraturan. Ia tidak mengubah penghalaan penyedia, pemilihan
tempatan atau bahasa UI.

## Bentuk Konfigurasi

Tetapan pemampatan boleh merangkumi:

```json
{
  "languageConfig": {
    "enabled": true,
    "defaultLanguage": "en",
    "autoDetect": true,
    "enabledPacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  },
  "cavemanConfig": {
    "language": "en",
    "autoDetectLanguage": true,
    "enabledLanguagePacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  }
}
```

`languageConfig` mengawal nilai lalai papan pemuka/pratonton. `cavemanConfig` ialah konfigurasi enjin masa jalan
yang digunakan apabila Caveman memampatkan teks mesej.

## Menambah Pek Bahasa

1. Cipta `open-sse/services/compression/rules/<language>/<pack>.json`.
2. Gunakan format peraturan Caveman daripada `docs/compression/COMPRESSION_RULES_FORMAT.md`.
3. Pastikan penggantian dibuat secara konservatif dan elakkan perubahan pada kod, pengecam, URL atau JSON.
4. Tambah atau kemas kini ujian untuk pemilihan bahasa dan tingkah laku penggantian.
5. Dedahkan label papan pemuka/i18n yang baharu jika bahasa tersebut muncul dalam pemilih UI.

## API

Pek yang tersedia boleh ditanya dengan:

```bash
curl http://localhost:20128/api/compression/language-packs
```

Titik akhir pratonton menerima penggantian konfigurasi bahasa:

```bash
curl -X POST http://localhost:20128/api/compression/preview \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "standard",
    "text": "Por favor, eu gostaria que voce basicamente resumisse isso.",
    "config": {
      "languageConfig": {
        "defaultLanguage": "pt-BR",
        "autoDetect": true
      }
    }
  }'
```

## SHARED_BOUNDARIES (v3.8.0)

Kesemua 6 pek bahasa menerima klausa `SHARED_BOUNDARIES` dalam v3.8.0 yang digunakan pada setiap
keamatan Caveman (LITE, FULL, ULTRA). Klausa ini mengarahkan enjin untuk mengekalkan corak ini secara verbatim,
tanpa mengira penyingkiran kata pengisi di sekelilingnya:

| Jenis corak                    | Contoh                                 |
| ------------------------------ | -------------------------------------- |
| Blok kod berpagar              | ` ```python\n...\n``` `                |
| Kod sebaris                    | `` `my_var` ``                         |
| URL                            | `https://example.com/path`             |
| Laluan fail (mutlak + relatif) | `/etc/hosts`, `./src/index.ts`         |
| Pengepala ralat                | `Error:`, `TypeError:`, `SyntaxError:` |
| Baris surih tindanan           | `  at functionName (file.ts:12:3)`     |

Corak ini diisikan dalam `DEFAULT_CAVEMAN_CONFIG.preservePatterns` (sebelum ini `[]`). Pemalar
tersebut terletak dalam `open-sse/services/compression/types.ts`.

### Mengapa perkara ini penting

Tanpa SHARED_BOUNDARIES, mod Caveman yang agresif boleh membuang kandungan yang kelihatan seperti prosa
berulang tetapi sebenarnya merupakan coretan kod, laluan fail atau tindanan ralat. SHARED_BOUNDARIES bertindak sebagai
jaring keselamatan bebas bahasa yang digunakan sebelum peraturan kata pengisi dijalankan.

### Menyesuaikan preservePatterns

Corak tambahan boleh ditambah pada masa jalan melalui tetapan pemampatan:

````json
{
  "cavemanConfig": {
    "preservePatterns": [
      "```[\\s\\S]*?```",
      "`[^`]+`",
      "https?://\\S+",
      "(?:/|\\./)[^\\s]+",
      "\\b(?:Error|TypeError|SyntaxError|RangeError):",
      "\\s+at\\s+\\S+\\s+\\(\\S+:\\d+:\\d+\\)"
    ]
  }
}
````

Corak tersuai melanjutkan (bukan menggantikan) 6 corak lalai.

## Nota Operasi

- Peraturan terbina dalam bahasa Inggeris kekal sebagai pilihan sandaran apabila pek bahasa tiada.
- Pek JSON terbina dalam yang tidak sah akan gagal pengesahan supaya aset keluaran tidak merosot secara senyap.
- Pek peraturan mengandungi data sahaja dan tidak seharusnya mengimport kod atau menjalankan logik sembarangan.
- Lapisan analitik pemampatan merekodkan mod dan enjin yang dipilih, bukan teks gesaan penuh.
