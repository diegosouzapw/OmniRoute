Peraturan pemampatan ialah fail JSON yang dimuatkan semasa masa jalan. Peraturan ini sengaja mengandungi data sahaja supaya pek bahasa baharu dan penapis perintah RTK boleh disemak tanpa mengubah kod enjin.

> **Skema kanonik (sumber rujukan muktamad):** [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) (JSON Schema draf 2020-12).
> Contoh di bawah adalah untuk tujuan ilustrasi — jika ragu-ragu, sahkan pek anda berdasarkan `_schema.json`.

## Pek Peraturan Caveman

Pek peraturan Caveman terletak di bawah:

```txt
open-sse/services/compression/rules/<language>/<pack>.json
```

Setiap pek mengandungi penggantian yang digunakan pada prosa biasa selepas kawasan yang dilindungi diasingkan.

```json
{
  "language": "en",
  "category": "filler",
  "rules": [
    {
      "name": "question_to_directive",
      "pattern": "\\b(?:Can you explain why|Could you show me how)\\b\\s*",
      "replacement": "Explain why ",
      "replacementMap": {
        "can you explain why": "Explain why ",
        "could you show me how": "Show how "
      },
      "flags": "gi",
      "context": "all",
      "category": "context",
      "minIntensity": "lite",
      "description": "Convert verbose questions into direct requests."
    }
  ]
}
```

### Medan Caveman

| Medan                    | Diperlukan | Penerangan                                                                              |
| ------------------------ | ---------- | --------------------------------------------------------------------------------------- |
| `language`               | ya         | Kunci bahasa seperti BCP-47, contohnya `en`, `pt-BR`, `es`                              |
| `category`               | ya         | Nama fail/kategori pek, contohnya `filler` atau `dedup`                                 |
| `rules`                  | ya         | Tatasusunan peraturan penggantian regex                                                 |
| `rules[].name`           | ya         | Nama peraturan yang stabil                                                              |
| `rules[].pattern`        | ya         | Sumber regex JavaScript                                                                 |
| `rules[].flags`          | tidak      | Bendera regex JavaScript; lalai `gi`                                                    |
| `rules[].replacement`    | tidak      | Rentetan penggantian atau nilai sandaran apabila `replacementMap` tidak menemui padanan |
| `rules[].replacementMap` | tidak      | Penggantian khusus padanan yang dikunci mengikut teks padanan yang dinormalkan          |
| `rules[].context`        | tidak      | `all`, `user`, `assistant`, atau `system`; lalai `all`                                  |
| `rules[].category`       | tidak      | `filler`, `context`, `structural`, `dedup`, `terse`, atau `ultra`                       |
| `rules[].minIntensity`   | tidak      | `lite`, `full`, atau `ultra`; lalai `lite`                                              |
| `rules[].description`    | tidak      | Ringkasan peraturan yang boleh dibaca manusia                                           |

Gunakan `flags` apabila pemadanan sensitif huruf besar dan kecil penting, contohnya penyingkiran kata sandang sebelum prosa huruf kecil tanpa menyingkirkan `the OpenAI API`. Gunakan `replacementMap` apabila satu regex mempunyai berbilang alternatif yang memerlukan output berbeza; ini memastikan pek peraturan JSON hanya mengandungi data sambil mengekalkan tingkah laku fungsi penggantian TypeScript terbina dalam yang lebih kaya.

## Pek Penapis RTK

Penapis RTK terletak di bawah:

```txt
open-sse/services/compression/engines/rtk/filters/<filter>.json
```

Setiap penapis menerangkan cara untuk mengenal pasti dan memampatkan satu keluarga output perintah.

```json
{
  "id": "test-vitest",
  "label": "Vitest output",
  "category": "test",
  "priority": 92,
  "match": {
    "outputTypes": ["test-vitest"],
    "commands": ["vitest", "npm test", "npm run test"],
    "patterns": ["\\bFAIL\\b", "\\bPASS\\b", "\\bTest Files\\b"]
  },
  "rules": {
    "stripAnsi": true,
    "replace": [{ "pattern": "\\s+\\[[0-9]+ms\\]", "replacement": "" }],
    "matchOutput": [
      {
        "pattern": "All tests passed",
        "message": "vitest: ok",
        "unless": "FAIL|Error:"
      }
    ],
    "includePatterns": ["FAIL", "Error:", "Test Files", "Tests"],
    "dropPatterns": ["^\\s*$", "Duration\\s+\\d+"],
    "collapsePatterns": ["^\\s+at "],
    "deduplicate": true,
    "truncateLineAt": 240,
    "maxLines": 160,
    "headLines": 24,
    "tailLines": 40,
    "onEmpty": "vitest: ok",
    "filterStderr": false
  },
  "preserve": {
    "errorPatterns": ["FAIL", "Error:", "AssertionError"],
    "summaryPatterns": ["Test Files", "Tests", "Snapshots"]
  },
  "tests": [
    {
      "name": "keeps failing tests",
      "command": "vitest",
      "input": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed",
      "expected": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed"
    }
  ]
}
```

### Medan RTK

| Medan                      | Diperlukan | Penerangan                                                                        |
| -------------------------- | ---------- | --------------------------------------------------------------------------------- |
| `id`                       | ya         | Id penapis yang stabil                                                            |
| `label`                    | ya         | Nama yang boleh dibaca pada papan pemuka                                          |
| `category`                 | ya         | Keluarga penapis: git, test, build, shell, docker, package, infra, cloud, generic |
| `priority`                 | tidak      | Keutamaan lebih tinggi diutamakan apabila berbilang penapis sepadan               |
| `match.outputTypes`        | tidak      | Id output pengesan yang memilih penapis ini                                       |
| `match.commands`           | tidak      | Token perintah yang memilih penapis ini                                           |
| `match.patterns`           | tidak      | Corak regex yang memilih penapis ini daripada teks output                         |
| `rules.stripAnsi`          | tidak      | Alih keluar jujukan lepasan ANSI sebelum peringkat regex                          |
| `rules.replace`            | tidak      | Penggantian regex bertertib yang diterapkan baris demi baris                      |
| `rules.matchOutput`        | tidak      | Peraturan output pintasan dengan pengadang `unless` pilihan                       |
| `rules.includePatterns`    | tidak      | Baris yang perlu diutamakan untuk dikekalkan                                      |
| `rules.dropPatterns`       | tidak      | Baris yang perlu dialih keluar sebagai hingar                                     |
| `rules.collapsePatterns`   | tidak      | Baris sepadan berulang yang boleh diringkaskan                                    |
| `rules.deduplicate`        | tidak      | Ringkaskan baris ternormal yang berulang                                          |
| `rules.truncateLineAt`     | tidak      | Had aksara setiap baris yang selamat untuk Unicode                                |
| `rules.maxLines`           | tidak      | Bilangan maksimum baris yang dikekalkan sebelum pengekalan bahagian akhir         |
| `rules.headLines`          | tidak      | Baris bahagian awal yang dikekalkan semasa pemangkasan                            |
| `rules.tailLines`          | tidak      | Baris bahagian akhir yang dikekalkan untuk konteks terkini                        |
| `rules.onEmpty`            | tidak      | Mesej sandaran apabila penapisan mengalih keluar semua kandungan                  |
| `rules.filterStderr`       | tidak      | Normalkan awalan stderr lazim sebelum peringkat penapisan seterusnya              |
| `preserve.errorPatterns`   | tidak      | Baris ralat yang perlu dikekalkan selepas pemangkasan                             |
| `preserve.summaryPatterns` | tidak      | Baris ringkasan yang perlu dikekalkan selepas pemangkasan                         |
| `tests[]`                  | tidak      | Sampel pengesahan sebaris yang digunakan oleh get pengesahan RTK                  |

RTK menerapkan peringkat deklaratif dalam tertib ini: `stripAnsi`, `filterStderr`, `replace`,
`matchOutput`, `dropPatterns`/`includePatterns`, `truncateLineAt`, `headLines`/`tailLines`,
`maxLines`, dan `onEmpty`.

Penapis tersuai boleh dimuatkan daripada:

1. Fail `.rtk/filters.json` projek hanya selepas cincangan `.rtk/trust.json` yang sepadan tersedia atau
   `trustProjectFilters` didayakan.
2. `DATA_DIR/rtk/filters.json` global.
3. Penapis terbina dalam.

Fail tersuai projek/global boleh mengandungi satu objek penapis atau satu tatasusunan objek penapis. Penapis
tersuai yang tidak sah dilangkau dengan diagnostik; penapis terbina dalam yang tidak sah akan menggagalkan pengesahan.

Fail amanah projek:

```json
{
  "filtersSha256": "0123456789abcdef..."
}
```

Penggantian persekitaran `OMNIROUTE_RTK_TRUST_PROJECT_FILTERS=1` mempercayai penapis projek tanpa
cincangan dan penggunaannya hendaklah dihadkan kepada pembangunan setempat yang terkawal.

## Peraturan Keselamatan

- Pastikan peraturan bersifat idempoten: menjalankan penapis yang sama dua kali tidak seharusnya merosakkan output.
- Kekalkan teks ralat, laluan fail, nombor baris dan ringkasan arahan yang tepat jika boleh.
- Elakkan peraturan yang mengubah blok kod, muatan JSON, URL atau rahsia.
- Tambahkan liputan unit untuk keluarga arahan baharu dalam ujian pengesan/penapis.
- Tambahkan sampel `tests[]` kepada setiap penapis terbina dalam dan penapis tersuai yang dikongsi.

## Pengesahan

Pek peraturan disahkan sebelum digunakan. Pek Caveman terbina dalam dan penapis RTK terbina dalam akan gagal serta-merta
semasa pengesahan supaya aset keluaran yang rosak dikesan sebelum diedarkan. Penapis RTK tersuai akan
dilangkau bersama diagnostik apabila penghuraian atau pengesahan kepercayaan gagal.

Pengesahan berfokus:

```bash
node --import tsx/esm --test tests/unit/compression/rule-loader.test.ts tests/unit/compression/language-packs.test.ts
node --import tsx/esm --test tests/unit/compression/rtk-verify.test.ts tests/unit/compression/rtk-dsl-pipeline.test.ts
```
