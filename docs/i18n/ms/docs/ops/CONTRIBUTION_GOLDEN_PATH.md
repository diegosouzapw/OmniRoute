Gunakan panduan ini untuk memilih kitaran pembangunan andal yang paling kecil bagi sesuatu pull request. Panduan ini tidak
menggantikan dokumen seni bina dan keselamatan khusus bidang yang dipautkan di bawah; sebaliknya, ia menghubungkan setiap jenis
perubahan lazim kepada kontrak, semakan berfokus dan liputan CI masing-masing.

## Laluan yang diikuti oleh setiap perubahan

1. **Pilih asas sebelum mengedit.** Cari cabang `release/v*` aktif yang tertinggi dan cipta cabang daripada
   hujungnya. Sasarkan cabang tersebut, bukan `main`. Jika pembekuan keluaran sedang berkuat kuasa, jangan sasarkan cabang
   yang dibekukan; gunakan kitaran aktif seterusnya yang diterangkan dalam
   [Model Percabangan & Keluaran](BRANCHING_MODEL.md).
2. **Nyatakan kontrak.** Kenal pasti setiap katalog, skema, artifak terjana, API awam atau antara muka
   pengguna yang dipengaruhi oleh perubahan tersebut. Jadual di bawah memberikan set permulaan minimum.
3. **Tulis atau kemas kini ujian berfokus.** Perubahan produksi dalam `src/`, `open-sse/`, `electron/` atau
   `bin/` memerlukan ujian automatik dalam PR yang sama. Jalankan fail ujian terkecil yang membuktikan
   tingkah laku tersebut, kemudian gerbang berfokus yang disenaraikan.
4. **Biarkan CI menjalankan matriks yang luas.** Keseluruhan serpihan unit, Vitest, ratchet liputan dan
   binaan produksi dijalankan pada PR. Jalankan suite yang luas secara setempat hanya apabila kegagalan berfokus menunjukkan
   kesan yang lebih meluas atau apabila perubahan merangkumi beberapa subsistem.
5. **Selaraskan sebelum semakan.** Ambil asas aktif, periksa commit baharunya dan diff anda berbanding
   asas tersebut, kemudian lakukan rebase atau merge asas mengikut aliran kerja penyumbang. Selesaikan konflik fail terjana
   dan katalog daripada sumbernya, jana semula fail tersebut, jalankan semula kitaran berfokus dan sahkan bahawa
   PR masih menyasarkan cabang keluaran aktif.
6. **Catat bukti.** Dalam templat PR, senaraikan arahan yang dijalankan, setiap fail ujian yang ditambah atau diubah,
   migrasi atau feature flag, serta sebarang pengesahan khusus CI yang masih belum selesai.

## Laluan utama mengikut jenis perubahan

Arahan di bawah ialah semakan berfokus minimum, bukan kebenaran untuk melangkau ujian yang secara langsung meliputi
tingkah laku yang anda ubah.

### Penyedia

**Kontrak**

- Takrif penyedia dalam `src/shared/constants/providers/` dan komposisinya dalam
  `src/shared/constants/providers.ts`.
- Model dan keupayaan dalam `open-sse/config/providerRegistry.ts` atau fail pendaftaran yang diekstrak daripadanya.
- Pemilihan pelaksana/penterjemah, konfigurasi OAuth atau kunci API, aset papan pemuka dan rujukan
  penyedia terjana apabila berkenaan.
- Kelayakan awam mesti menggunakan `resolvePublicCred()`; respons ralat mesti menggunakan pembantu ralat
  tersanitasi yang dikongsi. Lihat `docs/security/PUBLIC_CREDS.md` (git; tidak dikompil ke dalam `/docs`) dan
  [Sanitasi Ralat](../security/ERROR_SANITIZATION.md).

**Kitaran berfokus**

```bash
npm run check:provider-consistency
npm run check:provider-assets
node --import tsx/esm --test tests/unit/provider-translate-path-golden.test.ts
node --import tsx/esm --test tests/unit/<provider-or-executor>.test.ts
npm run gen:provider-reference   # apabila katalog berubah; commit diff yang dijana
npm run lint
```

Uji juga setiap keluarga permintaan yang terjejas: chat, Responses, imej, embedding, audio atau video.
Semak katalog terjana dan diff golden sebagai perubahan kontrak; jangan menerimanya secara membuta tuli.

### Penghalaan

**Kontrak**

- Nilai strategi awam dan metadata UI dalam `src/shared/constants/routingStrategies.ts`.
- Penghantaran dan penyusunan di bawah `open-sse/services/combo.ts` dan `open-sse/services/combo/`.
- Skema combo, persistensi, keadaan daya tahan, keupayaan model serta kawalan API/UI.
- [Enjin Auto-Combo](../routing/AUTO-COMBO.md) dan dokumentasi daya tahan apabila tingkah laku berubah.

**Kitaran berfokus**

```bash
node --import tsx/esm --test tests/unit/combo-<behavior>.test.ts
npm run test:combo:matrix        # perubahan strategi atau penghantaran
npm run check:known-symbols      # perubahan pendaftaran strategi
npm run lint
```

Gunakan ujian upstream olokan yang deterministik secara setempat. Smoke test combo langsung memerlukan kelayakan dan
dilakukan secara manual, bukan sebagai pengganti CI.

### UI / UX

**Kontrak**

- Laluan/halaman Next.js dan sempadan komponen dikongsi di bawah `src/app/` dan
  `src/shared/components/`.
- Bentuk respons API, keadaan pemuatan/kosong/ralat, tingkah laku papan kekunci dan pembaca skrin,
  susun atur responsif, tema dan pengembangan locale.
- Rentetan sumber UI bahasa Inggeris dalam `src/i18n/messages/en.json`; jangan kod keraskan teks baharu yang dilihat pengguna.

**Kitaran berfokus**

```bash
node --import tsx --test tests/unit/dashboard/<feature>.test.ts
npx vitest run --config vitest.config.ts tests/unit/ui/<component>.test.tsx
npm run check:dashboard-typecheck
npm run lint
```

Jalankan aplikasi untuk perubahan interaksi atau visual dan periksa kedua-dua viewport sempit dan lebar. CI menjalankan
binaan produksi dan suite yang lebih luas; tingkah laku visual masih memerlukan komponen berfokus, Playwright
atau semakan manual berdokumen yang sesuai dengan perubahan tersebut.

### i18n

**Kontrak**

- `src/i18n/messages/en.json` ialah sumber UI; `config/i18n.json` ialah sumber locale.
- Katalog CLI disimpan secara berasingan di bawah `bin/cli/locales/`.
- Kekalkan placeholder dan tag ICU dengan tepat. Jangan terjemahkan nama produk/penyedia/model,
  nama protokol dan pengepala, arahan, pengecam kod/JSON, URL, pemboleh ubah persekitaran atau
  istilah terlindung seperti `OmniRoute`, `OAuth`, `MCP` dan `A2A`. Senarai sumber semasa ialah
  `scripts/i18n/glossary/protected-terms.json`.

**Kitaran berfokus**

```bash
npm run i18n:sync-ui:dry
npm run i18n:check-ui-coverage
npm run i18n:check-value-drift
npm run i18n:check-glossary
npm run check:cli-i18n          # apabila rentetan/katalog CLI berubah
npm run lint
```

Ini ialah panduan untuk sistem sedia ada, bukan undangan untuk mengembangkan peralatan atau model kekuncinya.
Pastikan tampalan i18n kekal terfokus sementara sistem pengganti sedang direka bentuk. Jangan jalankan arahan terjemahan
yang memanggil perkhidmatan luaran melainkan tugas tersebut secara jelas memerlukan terjemahan terjana dan
anda telah menyemak diff yang terhasil.

### CLI

**Kontrak**

- Arahan dan bendera awam dalam `bin/cli/`, arahan API yang dijana, kod keluar, stdout/stderr dan
  bentuk output JSON, tingkah laku konfigurasi/persekitaran, serta fail yang dipakejkan.
- Rentetan CLI yang dipaparkan kepada pengguna mesti menggunakan lapisan i18n CLI dan memastikan katalog `en`/`pt-BR` diselaraskan.
- Kekalkan Node sebagai masa jalan yang disokong serta kontrak perduaan yang diterbitkan.

**Kitaran berfokus**

```bash
node --import tsx/esm --test tests/unit/cli/<command>.test.ts
npm run check:cli-i18n
npm run build:cli             # perubahan CLI yang dijana/dihimpunkan
npm run check:pack-policy     # perubahan permukaan pakej
npm run lint
```

Gunakan arahan yang tepat dalam direktori data sementara apabila tingkah laku bergantung pada penghuraian, fail atau status
keluar. CI menjalankan semakan artifak pakej dan ekosistem yang lebih menyeluruh.

### Pangkalan data

**Kontrak**

- Modul domain di bawah `src/lib/db/`; import modul tertentu secara langsung (lapisan eksport semula `localDb.ts` yang lama telah dialih keluar).
- Migrasi SQL bernombor dan idempoten di bawah `src/lib/db/migrations/`, keselamatan transaksi, tingkah laku
  naik taraf, indeks serta setiap pemanggil yang terjejas oleh skema.
- Laluan dan pengendali tidak boleh mengeluarkan SQL mentah secara langsung.

**Kitaran berfokus**

```bash
npm run check:migration-numbering
npm run check:db-rules
node --import tsx/esm --test tests/unit/db/<domain>.test.ts
node --import tsx/esm --test tests/unit/db/migration-<number>.test.ts
npm run lint
```

Uji kedua-dua pangkalan data baharu dan naik taraf daripada skema terdahulu apabila menambahkan migrasi. Ujian pangkalan data
mesti menutup pemegang dan memanggil `resetDbInstance()` semasa pembersihan. Jalankan `npm run test:bun:db` hanya apabila
laluan penyesuai Bun usaha terbaik berubah; Node kekal sebagai rujukan muktamad.

### Binaan / penggunaan

**Kontrak**

- Manifes/fail kunci akar dan ruang kerja, `scripts/build/`, pemasangan kendiri Next.js, kandungan pakej `dist/`,
  metadata platform Electron, aliran kerja CI dan sentinel penggunaan.
- Julat Node yang disokong dan penggunaan Bun yang disenaraikan sebagai dibenarkan dalam `CLAUDE.md` mesti dikekalkan.
- Artifak binaan kekal tidak dijejaki; dasar kebergantungan, lesen, aliran kerja dan pakej terpakai.

**Kitaran berfokus**

```bash
node --import tsx/esm --test tests/unit/build/<behavior>.test.ts
npm run check:build-scope
npm run check:lockfile         # perubahan kebergantungan atau fail kunci
npm run check:pack-policy      # perubahan permukaan pakej yang diterbitkan
npm run lint
```

Gunakan `npm run build` secara setempat hanya apabila perubahan menjejaskan pengkompilan, pemasangan kendiri, aset
atau penghimpunan masa jalan. Gunakan `npm run build:release` hanya untuk pengesahan keluaran/penggunaan. Binaan CI ialah
isyarat rentas platform muktamad; perubahan Electron khusus platform memerlukan binaan berfokus yang sepadan
atau bukti ujian asap.

## Gelung setempat berbanding CI

| Jalankan secara setempat bagi setiap tampalan                                                 | CI menyediakan isyarat yang luas                                                   |
| --------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Ujian tingkah laku langsung dan get kategori di atas                                          | Set lengkap ujian unit berpecah dan ujian bersiri                                  |
| `npm run lint`                                                                                | Set ujian Vitest dan mekanisme peningkatan liputan/kualiti                         |
| Semakan jenis atau binaan hanya apabila diperlukan oleh kontrak yang terjejas                 | Binaan produksi, keselamatan, dokumentasi, kebergantungan dan get dasar PR         |
| Semakan interaksi manual/langsung hanya apabila automasi tidak dapat membuktikan tingkah laku | Semakan integrasi merentas kerja dan platform yang dikonfigurasi oleh aliran kerja |

Gelung berfokus yang berjaya ialah bukti tentang kontrak yang diubah, bukannya bukti bahawa semakan CI
yang tidak berkaitan akan lulus. Sebaliknya, jangan biarkan setiap suntingan setempat menunggu keseluruhan matriks repositori.

## Senarai semak penyelarasan

Sebelum meminta semakan:

- Sahkan bahawa asas PR masih merupakan cabang `release/v*` aktif yang tertinggi.
- Ambil asas tersebut dan semak komit yang dimasukkan sejak anda mencipta cabang.
- Semak `git diff <active-base>...HEAD` untuk perubahan tidak sengaja atau perubahan dijana.
- Selesaikan konflik katalog dan dokumen dijana dengan mengemas kini sumber dan menjana semula output.
- Jalankan semula setiap ujian/get berfokus yang disenaraikan dalam perihalan PR selepas penyelarasan.
- Jangan sekali-kali melonggarkan penegasan atau menggugurkan ujian yang diperlukan semata-mata untuk dipadankan dengan asas yang telah berubah.

Untuk peraturan pembekuan keluaran dan penyasaran semula, gunakan
[Model Percabangan & Keluaran](BRANCHING_MODEL.md). Untuk inventori CI yang lengkap, gunakan
[Rujukan Get Kualiti](../architecture/QUALITY_GATES.md).
