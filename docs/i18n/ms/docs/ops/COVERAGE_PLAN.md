Garis dasar yang disyorkan ialah angka yang perlu dioptimumkan.

## Peraturan

- Sasaran liputan digunakan pada fail sumber, bukan pada `tests/**`.
- `open-sse/**` ialah sebahagian daripada produk dan mesti kekal dalam skop.
- Kod baharu tidak seharusnya mengurangkan liputan dalam bahagian yang disentuh.
- Utamakan pengujian tingkah laku dan hasil cabang berbanding butiran pelaksanaan.
- Utamakan pangkalan data SQLite sementara dan lekapan kecil berbanding olok-olok yang meluas untuk `src/lib/db/**`.

## Set perintah semasa

- `npm run test:coverage`
  - Gerbang liputan sumber utama untuk suit ujian unit
  - Menjana `text-summary`, `html`, `json-summary`, dan `lcov`
- `npm run coverage:report`
  - Laporan terperinci bagi setiap fail daripada pelaksanaan terkini
- `npm run test:coverage:legacy`
  - Untuk perbandingan sejarah sahaja

## Dasar ratchet

Kemas kini ambang `npm run test:coverage` hanya selepas projek benar-benar melepasi pencapaian seterusnya dengan margin yang selesa.

**Gerbang semasa:** `npm run test:coverage` menguatkuasakan **60 pernyataan / 60 baris / 60 fungsi / 60 cabang** (metrik tersebut telah ditetapkan semula dalam Quality-Gates Fasa 6A.1 — garis dasar 82.58% terdahulu terlebih tinggi kerana ia mengira fail ujian dan mengecualikan `open-sse`). Perintah `test:coverage:legacy` mengekalkan metrik lama 50/50/50 untuk perbandingan sejarah.

Untuk semakan ambang ad hoc terhadap laporan terkini, gunakan:

```bash
node scripts/check/test-report-summary.mjs --threshold 75
```

Urutan ratchet yang disyorkan (susunannya ialah `pernyataan-baris / cabang / fungsi`):

1. 55/60/55
2. 60/62/58
3. 65/64/62
4. 70/66/66
5. 75/70/72 <-- gerbang semasa (75/70/75)
6. 80/75/78
7. 85/80/84
8. 90/85/88

Sasaran ratchet seterusnya ialah `80/75/78` setelah liputan cabang kekal melebihi 78% untuk dua pelaksanaan berturut-turut.

## Jurang yang diketahui

Perintah liputan semasa mengukur suite ujian unit Node utama dan menyertakan sumber yang dicapai daripadanya, termasuk `open-sse`. Perintah tersebut masih belum menggabungkan liputan Vitest ke dalam satu laporan bersepadu. Penggabungan itu wajar dilakukan kemudian, tetapi ia bukan penghalang untuk memulakan peningkatan daripada 60% -> 80%.
