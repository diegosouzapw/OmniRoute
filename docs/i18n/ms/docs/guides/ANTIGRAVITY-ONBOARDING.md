## 1. Antigravity berbanding Antigravity CLI (agy)

Kedua-dua penyedia berkongsi **bahagian belakang Google yang sama** — klien OAuth, penyegaran token, titik akhir dan akaun Google yang serupa. Perbezaannya ialah model yang dapat anda lihat.

> Lihat [pengumuman Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli) untuk perbandingan rasmi daripada Google.

| Aspek                    | `antigravity` (IDE)                            | `agy` (CLI)                                                             |
| ------------------------ | ---------------------------------------------- | ----------------------------------------------------------------------- |
| **Produk Google**        | Antigravity 2.0 / Antigravity IDE              | Antigravity CLI                                                         |
| **Bahagian belakang**    | Google Cloud Code API yang sama                | Google Cloud Code API yang sama                                         |
| **OAuth / Token**        | Klien yang sama, penyegaran yang sama          | Klien yang sama, penyegaran yang sama                                   |
| **Katalog model**        | Senarai pilihan statik (dikod keras OmniRoute) | Disemak secara langsung daripada Google melalui `:fetchAvailableModels` |
| **Model Claude**         | Sonnet 4.6, Opus 4.6 (masing-masing 4 varian)  | Sonnet 4.6, Opus 4.6 (masing-masing 4 varian)                           |
| **Penamaan Gemini**      | Label ringkas (Rendah/Sederhana/Tinggi)        | ID huluan (extra-low/low/agent)                                         |
| **Model tambahan**       | `gpt-oss-120b-medium`                          | Mungkin termasuk model tambahan daripada Google                         |
| **Kes penggunaan lalai** | Penyepaduan IDE (VS Code, JetBrains)           | Akses CLI / API                                                         |
| **Kuota**                | Dikongsi dengan agy (akaun Google yang sama)   | Dikongsi dengan antigravity (akaun Google yang sama)                    |

**Model yang tersedia (disahkan melalui eksperimen, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (pelbagai tahap penaakulan)
- Claude: Sonnet 4.6, Opus 4.6 (masing-masing dengan varian default/low/medium/high)
- Lain-lain: GPT-OSS 120B Medium
- **Claude Sonnet 5 TIDAK tersedia** — hanya varian 4.6 disokong

**Mengapa katalog model berbeza**: CLI Google "dioptimumkan untuk kelajuan dan overhed yang rendah" dan "dioptimumkan bersama model Gemini" (menurut blog rasmi Google). Produk Web/IDE "dioptimumkan untuk kelengkapan." CLI menggunakan `:fetchAvailableModels` untuk menemukan model secara dinamik, manakala IDE menggunakan senarai pilihan statik.

**Dalam amalan**: Gunakan awalan `agy/` untuk model Gemini (contohnya `agy/gemini-3.7-flash-high`). Gunakan `antigravity/` untuk senarai pilihan statik. Kedua-duanya mengakses bahagian belakang Google yang sama, tetapi mendedahkan penamaan model yang berbeza. Kuota dikongsi — penggunaan mana-mana penyedia akan dikira terhadap had akaun Google yang sama.

## 2. Google One AI Pro: Sistem Kuota

> Lihat [Dokumentasi Antigravity: Pelan](https://antigravity.google/docs/plans) untuk butiran kuota rasmi dan [Perubahan pada Pelan Antigravity](https://antigravity.google/blog/changes-to-antigravity-plans) untuk kemas kini harga terkini.

Google Antigravity menggunakan **kuota dwilapisan** berdasarkan "Kerja yang Dilakukan" (beban pengkomputeran), bukan bilangan mesej.

### Dua Lapisan

| Lapisan                | Penerangan                             | Kitaran pembaharuan                                                                        |
| ---------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------ |
| **Pecutan 5 jam**      | Kumpulan segera "kerja yang dilakukan" | Ditetapkan semula 5 jam selepas permintaan pertama dalam sesuatu sesi                      |
| **Garis dasar 7 hari** | Had maksimum mingguan                  | Mengatasi pembaharuan 5 jam jika dicapai; menyekat akses sehingga tempoh 7 hari berikutnya |

**Cara "Kerja yang Dilakukan" dikira**: Tugas yang banyak menggunakan ejen (cth. "Faktorkan semula seluruh repositori ini") menghabiskan kuota dengan jauh lebih pantas berbanding tugas mudah (cth. "Baiki fungsi ini"). Tiada papan pemuka masa nyata yang menunjukkan penggunaan.

### Peringkat Pelan

| Pelan        | Harga         | Kuota                                           | Had mingguan                             |
| ------------ | ------------- | ----------------------------------------------- | ---------------------------------------- |
| Percuma      | $0            | Kuota yang bermakna, diperbaharui setiap minggu | Ya                                       |
| AI Pro       | $19.99/bulan  | Kuota tinggi, pembaharuan bergulir 5 jam        | Ya (mengatasi tempoh 5 jam jika dicapai) |
| AI Ultra 5x  | $99.99/bulan  | 5x kuota Pro                                    | Tiada had mingguan                       |
| AI Ultra 20x | $199.99/bulan | 20x kuota Pro                                   | Tiada had mingguan                       |

### Model Gemini berbanding Bukan Gemini

- **Model Gemini** (Flash + Pro): Berkongsi satu had kadar, yang digunakan berdasarkan harga API. Jika Flash 8x lebih murah daripada Pro, anda mendapat 8x lebih banyak token Flash.
- **Model bukan Gemini** (Claude, GPT-OSS): Mempunyai had kadar yang **berasingan**. Mungkin kekal tersedia walaupun akses Gemini disekat.

### Kredit AI (Penggunaan Lebihan)

> Lihat [Kredit Google One AI](https://support.google.com/googleone/answer/14534406) untuk mengetahui cara kredit berfungsi.

Apabila kuota garis dasar habis:

- **Jangan sekali-kali**: Tunggu kuota diperbaharui; memaparkan "Kuota model garis dasar telah dicapai"
- **Sentiasa**: Gunakan kredit AI secara automatik; bertukar kembali kepada garis dasar apabila kuota diperbaharui

Kredit dibeli secara berasingan dan ditolak mengikut harga API standard.

### Butiran Utama

- Kuota **dikongsi pada peringkat akaun** — akaun Google yang sama dalam Antigravity IDE, CLI dan OmniRoute berkongsi satu kumpulan kuota
- Setiap akaun Google mempunyai kuota tersendiri yang bebas — berbilang akaun = berbilang kumpulan kuota
- Pengguna AI Pro telah melaporkan **sekatan akses selama 7 hari** dan bukannya penetapan semula 5 jam apabila garis dasar mingguan dicapai (Google mengesahkan bahawa ini memang direka sedemikian untuk permintaan tinggi)

**Apabila kuota akaun anda habis**: OmniRoute mencuba semula secara automatik menggunakan akaun tersedia yang seterusnya dalam laluan gabungan. Tiada campur tangan manual diperlukan.

## 3. Cara Mendapatkan projectId

Setiap sambungan antigravity/agy memerlukan `projectId` Google Cloud Code. Tanpanya, titik akhir `/v1internal:models` mengembalikan 404.

### Kaedah A: Automatik (Disyorkan)

OmniRoute mengendalikan perkara ini secara automatik. Apabila anda menambahkan akaun Google baharu melalui OAuth Papan Pemuka:

1. OmniRoute memperbaharui token
2. Memanggil `loadCodeAssist` untuk menemukan projectId
3. Jika tiada projek wujud, memanggil `onboardUser` untuk menciptanya
4. Mencuba semula `loadCodeAssist` untuk mendapatkan projectId yang baru dicipta
5. Menyimpannya dalam pangkalan data

**Ini berfungsi untuk kebanyakan akaun** — tiada langkah manual diperlukan.

### Kaedah B: Secara Manual melalui agy CLI

Jika penemuan automatik gagal (lihat Bahagian 5 untuk mengetahui bila perkara ini berlaku):

```bash
# Pasang agy CLI (jika belum dipasang)
npm install -g @anthropic-ai/agy

# Log masuk dengan akaun Google anda
agy login

# Pilih akaun yang perlu melalui proses penyediaan
# Ini mencetuskan pendaftaran Cloud Code dan menetapkan projectId
```

Selepas `agy login` berjaya, perbaharui token dalam Papan Pemuka OmniRoute. projectId akan ditemukan secara automatik.

### Cara mengesahkan

Semak pangkalan data:

```bash
# Di dalam bekas OmniRoute
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Atau semak log:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. URI Ubah Hala OAuth

### Masalah

Google OAuth memerlukan URI ubah hala yang sah. Tetapan lalai OmniRoute menggunakan `http://127.0.0.1:20128/callback` (gelung balik). Ini berfungsi untuk binaan setempat tetapi **gagal untuk penggunaan jauh** (contohnya, pelayan yang dicapai melalui IP LAN).

Google menolak URI ubah hala yang:

- Menggunakan alamat IP (mestilah domain yang berakhir dengan `.com`, `.org`, dan sebagainya)
- Tidak sepadan dengan URI ubah hala yang didaftarkan dalam konfigurasi klien OAuth

### Penyelesaian

**Pilihan A: Gunakan aliran OAuth terbina dalam (lalai)**

- Berfungsi apabila anda mengakses OmniRoute daripada `localhost` atau `127.0.0.1`
- Tiada konfigurasi diperlukan

**Pilihan B: Bukti kelayakan OAuth tersuai**

- Tetapkan `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` dalam persekitaran anda
- Berikan bukti kelayakan Google OAuth anda sendiri:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Daftarkan `https://your-domain.com/callback` sebagai URI ubah hala yang dibenarkan dalam Google Cloud Console

**Pilihan C: Gunakan CLI agy untuk log masuk awal**

- Jalankan `agy login` pada mesin yang akan mengakses OmniRoute
- Aliran OAuth diselesaikan secara setempat dan token disimpan
- Import sambungan ke dalam OmniRoute melalui Dashboard

### Batasan

- Bukti kelayakan OAuth tersuai memerlukan nama domain (Google tidak menerima alamat IP sebagai URI ubah hala)
- Jika anda tidak mempunyai domain, gunakan Pilihan A atau C

## 5. Penyelesaian Masalah: Apabila Persediaan Automatik Gagal

OmniRoute mengendalikan penemuan projectId dan penerimaan masuk secara automatik untuk kebanyakan akaun. Apabila proses tersebut gagal, punca utamanya biasanya salah satu daripada yang berikut:

### Rantau akaun disekat

**Gejala**: `agy login` mengembalikan "Semakan kelayakan gagal: Akaun semasa anda tidak layak untuk Antigravity kerana ia tidak tersedia di lokasi anda pada masa ini."

**Punca utama**: Akaun Google mempunyai medan bahagian belakang "Country Association" yang ditetapkan semasa pendaftaran. CLI agy dan Cloud Code API memeriksa medan ini dengan ketat — tidak seperti Gemini web yang hanya memeriksa IP semasa anda.

> Untuk menyemak atau menukar rantau yang dikaitkan dengan akaun anda, lawati [Borang Perkaitan Negara Google](https://policies.google.com/country-association-form).

**Mengapa Gemini web berfungsi tetapi agy tidak**:

- Gemini web / Google One: hanya memeriksa IP semasa (proksi berjaya)
- CLI agy / Cloud Code API: membaca medan bahagian belakang Country Association (proksi tidak membantu)

**Penyelesaian**:

1. Lawati [Borang Perkaitan Negara Google](https://policies.google.com/country-association-form) semasa menggunakan IP AS
2. Hantar permintaan perubahan rantau (pilih "Saya tinggal di negara lain")
3. Tunggu 1-24 jam untuk Google memprosesnya serta menghantar pemberitahuan e-mel
4. Kemudian `agy login` sepatutnya berjaya

### Akaun tidak mempunyai projek Cloud Code

**Gejala**: Log menunjukkan `loadCodeAssist returned no project id` dan `onboardUser failed (400)`.

**Punca utama**: Akaun tersebut tidak pernah didaftarkan dengan Google Cloud Code dan penerimaan masuk automatik gagal.

**Penyelesaian**: Jalankan `agy login` secara manual untuk mencetuskan pendaftaran Cloud Code, kemudian segarkan semula token dalam Dashboard OmniRoute.

### Token tamat tempoh atau dibatalkan

**Gejala**: Ralat 401 dalam log atau mesej "Token telah tamat tempoh".

**Penyelesaian**: Segarkan semula token dalam Dashboard → Providers → agy → Klik ikon segar semula. Jika token penyegaran itu sendiri telah dibatalkan, anda perlu mengesahkan semula melalui OAuth.
