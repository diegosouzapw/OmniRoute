---

OmniRoute menyediakan **dua** cara untuk menggunakan OpenAI Codex:

| Penyedia               | Cara ia berkomunikasi dengan OpenAI                                                                                                                                                                  | Peringatan penggunaan                                                 |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| **`codex`**            | Memainkan semula token OAuth ChatGPT/OpenAI anda secara langsung kepada Responses API                                                                                                                | **Ya** — sesi rasmi tidak dibenarkan untuk penggunaan proksi/penghala |
| **`codex-app-server`** | Mengendalikan **`codex app-server` milik Codex CLI sendiri** melalui JSON-RPC/WebSocket; CLI memiliki dan memperbaharui sendiri OAuthnya (`~/.codex/auth.json`) sama seperti sesi `codex` interaktif | **Tidak** — OmniRoute tidak pernah memainkan semula token kepada API  |

Oleh sebab `codex-app-server` tidak pernah memainkan semula token, ia tidak
tertakluk pada peringatan penggunaan main semula sesi. Ia memerlukan **Codex CLI
yang boleh dicapai pada URL app-server yang dikonfigurasikan**, dan CLI tersebut
mestilah **telah dilog masuk**.

---

## 1. Seni bina

```
┌─ Aplikasi OmniRoute ─────────────┐        ┌─ Sidecar codex-app-server ──────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ token keupayaan)             │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  mengurus sendiri OAuth OpenAI      │
└──────────────────────────────────┘        │  (~/.codex/auth.json, auto-segar semula) │
        │ dikongsi (volum compose)           └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → token keupayaan WS (kedua-duanya melekapkannya)
  codex-appserver-home    → ~/.codex (auth.json ditulis oleh papan pemuka,
                             dibaca oleh codex app-server milik sidecar)
```

- Sidecar hanya mendengar pada rangkaian compose dalaman
  (`ws://codex-app-server:1456`) di sebalik token keupayaan. Ia **tidak pernah**
  diterbitkan kepada hos atau internet.
- Codex CLI telah disertakan dalam `omniroute:base`, jadi pemasangan codex tidak
  diperlukan pada hos atau mesin pengguna apabila anda menjalankan sidecar.

## 2. Jalankannya

```bash
# Mulakan tindanan DENGAN profil sidecar codex app-server:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

Sidecar menjana token keupayaan WS semasa but pertama (ke dalam volum
`codex-appserver-token` yang dikongsi) dan aplikasi membaca token yang sama
melalui `OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE`. Tiada penyambungan token
secara manual diperlukan.

## 3. Sambungkan + log masuk

1. Dalam papan pemuka, tambahkan sambungan untuk **OpenAI Codex (App-Server)**.
   Tiada kunci API atau token diperlukan (ia penyedia tanpa pengesahan —
   sidecar mengurus pengesahan).
2. Jika Codex CLI sidecar **belum dilog masuk**, semakan kesihatan sambungan
   melaporkan _"sedang berjalan tetapi belum dilog masuk"_ (bukan ralat
   pengesahan berwarna merah). Gunakan **Log masuk dengan ChatGPT**: tindakan ini
   menjalankan OAuth peranti Codex standard dalam pelayar anda, kemudian menulis
   `~/.codex/auth.json` ke dalam volum yang dikongsi melalui **Gunakan
   pengesahan** (log masuk yang sama digunakan oleh kedua-dua penyedia `codex`
   dan `codex-app-server`).
3. Selepas dilog masuk, semakan kesihatan bertukar hijau (ia mengesahkan kedua-dua
   `/readyz` **dan** `account/read` — iaitu aktif _dan_ disahkan) lalu mula
   berfungsi.

Papan pemuka tidak pernah menulis ganti `~/.codex/auth.json` sedia ada yang
sihat — ia hanya menulis apabila fail tersebut tiada atau tokennya telah lapuk
(sandaran sentiasa dibuat).

## 4. Senario pelaksanaan

- **Pengendali dengan Codex CLI yang telah disahkan** — lekapkan
  `~/.codex` hos anda ke dalam sidecar (`codex-appserver-home`) dan langkau
  langkah log masuk.
- **Pengguna awam, tiada codex dipasang secara setempat** — tidak berkaitan:
  sidecar mempunyai CLI tersebut. Pengguna hanya membuat pengesahan melalui
  papan pemuka.
- **OmniRoute bare-metal (tanpa sidecar, codex hos)** — halakan
  `OMNIROUTE_CODEX_APPSERVER_WS` kepada `codex app-server` anda sendiri dan
  pastikan codex hos telah dilog masuk; petunjuk "codex tidak dipasang" muncul
  jika binari tiada.

## 5. Egres kediaman / UDP (tambahan untuk pengendali, tidak disertakan)

Sidecar generik di atas melakukan egres melalui rangkaian biasa bekas. Pengendali
yang memerlukan trafik Codex melakukan egres melalui **jalan keluar kediaman**
(contohnya sidecar tailscale TUN yang membawa TCP + UDP/QUIC) menjalankannya
sebagai tindanan compose berasingan; ia sengaja **tidak** menjadi sebahagian
daripada profil `codex-app-server` yang disertakan. Lihat buku panduan operasi
dalaman untuk persediaan tersebut.
