Dua cara untuk meletakkan Cursor di belakang OmniRoute tanpa sesi IDE:

1. **Penyedia `cursor-api`** (kad "Cursor API", alias `cua`): penyedia kunci API
   yang menyimpan kunci API pengguna Cursor (`crsr_…`, dijana di
   `https://cursor.com/dashboard/api`). Mana-mana klien OmniRoute kemudiannya boleh mencapai
   model Cursor melalui `/v1/chat/completions` sebagai `cursor-api/<model>` atau
   `cua/<model>`, dengan lapisan kuota, sandaran dan pengelogan yang biasa. Penyedia IDE
   (`cursor`, sesi OAuth/IDE) tidak berubah.
2. **Laluan terus Cursor CLI**: halakan Cursor CLI (`agent`) ke OmniRoute supaya
   setiap RPC yang dibuat oleh CLI disahkan dengan kunci API OmniRoute, dimajukan
   ke Cursor dengan kelayakan sambungan `cursor-api`, dan direkodkan pada
   halaman Log.

## Mengapa kunci ditukar

`api2.cursor.sh` menolak kunci `crsr_…` mentah sebagai token Bearer (401). Cursor
CLI terlebih dahulu menghantar POST dengan kunci tersebut ke `/auth/exchange_user_api_key` dan menerima JWT
sesi yang tamat tempoh selepas satu jam; `refreshToken` yang dikembalikan mempunyai
`exp` yang sama, jadi penyegaran bermaksud menukar semula kunci tersebut.
`open-sse/services/cursorApiKeyAuth.ts` melakukan pertukaran itu, menyimpan satu token
sesi dalam cache bagi setiap kunci, menukarnya semula lima minit sebelum tamat tempoh dan membuang
token yang dicache apabila Cursor membalas dengan 401. `CursorExecutor` memanggilnya sejurus sebelum membuka
strim huluan untuk sambungan `cursor-api`.

## Penyedia `cursor-api`

Pendaftaran: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, `format`, `baseUrl` dan
`models` yang sama seperti `cursor`). Kad katalog:
`src/shared/constants/providers/apikey/specialty-media.ts`. Peta pelaksana:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

Papan pemuka: Penyedia → Cursor API → Tambah kunci API.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

Kemudian:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

Nota:

- Penyenaraian model untuk `cursor-api` diperoleh daripada pendaftaran Cursor statik (
  senarai yang sama yang digunakan oleh penyedia IDE sebagai sandaran); pemasangan `cursor-agent` tidak
  diperlukan pada hos OmniRoute.
- `POST /api/providers/{id}/refresh-cursor` adalah untuk penyedia IDE `cursor`
  sahaja; sambungan `cursor-api` tidak mempunyai sesi IDE untuk diperbaharui.

## Laluan terus Cursor CLI

Laluan: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. Awalan `/api/cursor-cli/`
didaftarkan dalam `src/shared/constants/publicApiRoutes.ts` kerana pengendali
menguatkuasakan pengesahannya sendiri:

| Laluan                                                                                                                         | Pengesahan yang dijangkakan daripada CLI | Tindakan OmniRoute                                                                                                                                                                               |
| ------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `POST /auth/exchange_user_api_key`                                                                                             | `Bearer <OmniRoute API key>`             | Mengesahkan kunci, menjana JWT HS256 1 jam (ditandatangani dengan `JWT_SECRET`) dan mengembalikannya                                                                                             |
| setiap laluan lain (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`                      | Mengesahkan pengeluar/khalayak/tamat tempoh, memilih sambungan `cursor-api` yang aktif, menggantikan pengepala Authorization dengan token Cursor yang telah ditukar dan menstrim balasan kembali |

CLI menyahkod `exp` daripada apa-apa token yang diterimanya, jadi memberikan token legap
kepadanya menyebabkan pertukaran semula dilakukan sebelum hampir setiap permintaan; JWT yang dijana mengelakkan
perkara itu. Respons 401 daripada OmniRoute menyebabkan CLI melakukan pertukaran semula.

### Persediaan

1. Cipta kunci API OmniRoute (Papan pemuka → Kunci API) dan sambungan `cursor-api`.
2. Arahkan CLI supaya menggunakan HTTP/1.1 untuk strim ejen. Dalam
   `~/.cursor/cli-config.json`:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   Tanpa ini, CLI membuka pusingan ejen melalui HTTP/2 ke hos ejen yang
   dikonfigurasikan secara berasingan dan hanya RPC satah kawalan melalui
   titik akhir tersebut.

3. Jalankan CLI melalui OmniRoute:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

Setiap lompatan muncul dalam Log sebagai penyedia `cursor-api`, jenis permintaan `cursor-cli`,
laluan `/api/cursor-cli/<rpc>`, yang dikaitkan dengan kunci API OmniRoute dan
sambungan yang mengendalikannya.

### Mod kegagalan

| Situasi                                                    | Respons kepada CLI                                  |
| ---------------------------------------------------------- | --------------------------------------------------- |
| Kunci OmniRoute tidak diketahui dan `REQUIRE_API_KEY=true` | 401 `unauthenticated` semasa pertukaran             |
| `REQUIRE_API_KEY=false`                                    | sesi tanpa nama (mencerminkan tingkah laku `/v1/*`) |
| JWT sesi tamat tempoh / asing / diusik                     | 401, CLI melakukan pertukaran semula                |
| Kunci API OmniRoute dibatalkan selepas pertukaran          | 401 pada RPC seterusnya                             |
| Tiada sambungan `cursor-api` yang aktif                    | 503 `unavailable`                                   |
| Cursor menolak kunci sambungan                             | 401 `unauthenticated`, sesi cache digugurkan        |
| Huluan tidak dapat dicapai                                 | 502 `unavailable` (mesej disanitasi)                |
| `JWT_SECRET` tidak ditetapkan                              | 503 semasa pertukaran                               |
