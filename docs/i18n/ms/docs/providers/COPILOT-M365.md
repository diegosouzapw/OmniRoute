`copilot-m365-web` (alias `m365copilot`) menghantar permintaan sembang berformat OpenAI melalui
sesi pelayar Microsoft 365 Copilot BizChat yang telah disahkan di
`m365.cloud.microsoft/chat`. Ini ialah integrasi tidak rasmi.

> **Baharu menggunakan penyedia Kuki Web?**
>
> Baca **`docs/getting-started/WEB-COOKIE-GUIDE.md`** untuk proses persediaan umum, panduan pengesahan, batasan dan penyelesaian masalah sebelum mengikuti panduan khusus penyedia ini.
>
> **Penting:** Bukti kelayakan untuk penyedia ini **bukan kuki**. Jangan salin
> kuki daripada `m365.cloud.microsoft`. Bukti kelayakan tersebut ialah parameter pertanyaan URL WebSocket
> dan segmen laluan, yang kedua-duanya dibaca daripada tab Network dalam DevTools.

## Prasyarat

- Akaun Microsoft 365 dengan akses kepada BizChat di `m365.cloud.microsoft/chat`
- Pelayar berasaskan Chromium (Chrome, Edge) untuk pemeriksaan WebSocket dalam DevTools
- Lesen M365 Copilot (disertakan dengan banyak pelan Microsoft 365 Business/Enterprise)

## Mendapatkan bukti kelayakan (kaedah WebSocket)

1. Log masuk di `https://m365.cloud.microsoft/chat` dan mulakan perbualan.
2. Buka **DevTools → Network**.
3. Tapis mengikut **WS** (WebSocket).
4. Klik sambungan WebSocket Chathub. Cari URL yang bermula dengan
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. Daripada **Request URL**, salin:
   - Nilai parameter pertanyaan `access_token` (JWT berjangka hayat pendek).
   - Segmen laluan Chathub selepas `/Chathub/` (contohnya `<oid>@<tenant>`).

URL penuh mempunyai format berikut:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. Dalam OmniRoute, pergi ke **Providers → Add Provider**, pilih **Microsoft 365 Copilot
   (BizChat)** dan tampalkan bukti kelayakan dalam format berikut:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. Klik **Test Connection** dan **Save**.

## Mendapatkan bukti kelayakan (import HAR)

Daripada menyalin nilai secara manual daripada URL WebSocket, anda boleh mengeksport fail HAR
DevTools:

1. Buka **DevTools → Network**.
2. Mulakan atau teruskan perbualan BizChat (tindakan ini mencetuskan sambungan WebSocket).
3. Klik kanan dalam panel Network dan pilih **Save all as HAR with content**.
4. Dalam OmniRoute, gunakan butang **Import .har file** pada dialog sambungan penyedia.

OmniRoute mengimbas HAR untuk URL WebSocket Chathub, mengekstrak
`access_token` dan `chathubPath`, serta mengisi medan bukti kelayakan secara automatik. Import
HAR menyahkod tamat tempoh JWT dan menunjukkan baki jangka hayat token.

> **Jangan sekali-kali komit eksport HAR sebenar, token akses atau token penyegaran.** Nilai ujian dan
> dokumentasi mestilah sentiasa menggunakan ruang letak.

## Jangka hayat dan penyegaran token

`access_token` berjangka hayat pendek (biasanya **~75 minit**). Selepas tamat tempoh, penyedia
melaporkan ralat sambungan dan anda perlu mendapatkan semula bukti kelayakan.

### Penyegaran automatik dengan `refreshToken`

Untuk mengelakkan keperluan mendapatkan semula bukti kelayakan secara manual, anda boleh menyimpan token penyegaran Microsoft dalam
**Advanced Settings → providerSpecificData** sambungan:

| Medan          | Penerangan                                                                |
| -------------- | ------------------------------------------------------------------------- |
| `refreshToken` | Token penyegaran Microsoft OAuth untuk skop `substrate.office.com/sydney` |
| `tier`         | `individual` (lalai), `edu` atau `enterprise`                             |

Dapatkan token penyegaran daripada aliran kod peranti atau kod kebenaran Microsoft
yang diskopkan kepada `substrate.office.com/sydney`. Apabila `refreshToken` ditetapkan, OmniRoute
menyegarkan `access_token` terlebih dahulu sebelum setiap permintaan, jadi anda tidak perlu
mendapatkannya semula selepas setiap tamat tempoh ~75 minit.

Jika `refreshToken` tidak ditetapkan, anda perlu mendapatkan semula bukti kelayakan WebSocket secara manual
selepas setiap tamat tempoh.

### Pemilihan peringkat

| Peringkat    | Alias      | Antara muka              |
| ------------ | ---------- | ------------------------ |
| `individual` | _(lalai)_  | M365 Copilot Pengguna    |
| `edu`        | `included` | M365 Copilot Pendidikan  |
| `enterprise` | `work`     | M365 Copilot untuk Kerja |

Tetapkan peringkat dalam **Advanced Settings → providerSpecificData → tier**. Peringkat tersebut mempengaruhi
penghalaan BizChat dan akses model.

## Model keselamatan

- **Integrasi tidak rasmi.** Penyedia ini melakukan kejuruteraan songsang terhadap protokol WebSocket BizChat. Ia mungkin berhenti berfungsi tanpa notis apabila Microsoft mengubah titik akhir tersebut.
- Penanda `subscriptionRisk: true` menunjukkan bahawa integrasi ini bergantung pada titik akhir yang tidak didokumenkan. Sekatan akaun mungkin berlaku tetapi belum disahkan.
- Token akses ialah JWT berjangka pendek. Kendalikannya seperti kata laluan: jangan komit, log atau kongsikannya.
- Token muat semula memberikan akses jangka panjang kepada permukaan BizChat. Simpannya dengan tahap keselamatan yang sama seperti kunci API.

## Penyelesaian masalah

### Pengesahan gagal serta-merta

- Pastikan anda menyalinnya daripada **URL WebSocket**, bukan daripada permintaan XHR/Fetch. Bukti kelayakan berada dalam parameter pertanyaan `access_token` bagi sambungan WebSocket Chathub — bukan dalam pengepala `Authorization: Bearer`.
- Pastikan `chathubPath` menyertakan segmen `<oid>@<tenant>` yang lengkap daripada laluan URL.

### Token tamat tempoh selepas ~75 minit

Ini adalah keadaan yang dijangka. Tanpa `refreshToken`, token akses mempunyai jangka hayat yang pendek. Anda boleh:

- Tangkap semula bukti kelayakan daripada DevTools, atau
- Konfigurasikan `refreshToken` dalam Tetapan Lanjutan untuk muat semula automatik.

### Uji Sambungan berjaya tetapi sembang mengembalikan 401

Token mungkin telah tamat tempoh antara pengesahan dengan permintaan pertama. Tangkap semula bukti kelayakan yang baharu.

### Copilot tidak dipaparkan dalam senarai penyedia

Pastikan `copilot-m365-web` didayakan dalam **Papan Pemuka → Penyedia**. Penyedia mungkin disembunyikan secara lalai dalam sesetengah peringkat.
