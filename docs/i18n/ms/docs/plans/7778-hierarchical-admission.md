1. Kunci kontrak semafor kunci tunggal sedia ada dan kontrak atomik berbilang kunci baharu dengan ujian berfokus: tiada tempahan separa, baris gilir FIFO, pembatalan, tamat masa, baris gilir penuh, pelepasan idempoten, statistik dan pembersihan.
2. Umumkan semafor akaun sedia ada di tempatnya. Kekalkan `acquire()` sebagai pembalut keserasian untuk `acquireMany()`; jangan tambahkan penjadual kedua atau kebergantungan.
3. Gantikan pemerolehan akaun sahaja dalam `chatCore` dengan satu pemerolehan global/penyedia/akaun secara kumulatif sejurus sebelum `withRateLimit`. Peroleh semula keseluruhan set apabila penggiliran akaun mengubah sambungan, dan kekalkan pelepasan sehingga penstriman selesai.
4. Lanjutkan saluran tetapan daya tahan sedia ada (jenis, lalai, penormalan, skema, respons API, UI dan terjemahan) dengan had global dan penyedia. Labelkan semula kawalan konkurensi Bottleneck lama sebagai konkurensi skop sambungan/kuota supaya skop sebenarnya dinyatakan dengan jelas.
5. Jalankan ujian berfokus, lint, semakan jenis, semakan statik dan suite ujian penuh; dokumentasikan perubahan tingkah laku dalam log perubahan.

Tingkah laku yang sengaja dikekalkan: konkurensi sifar/null memintas get, pemanggil akaun sahaja terus menggunakan `acquire()`, kawalan akaun tersekat mengekalkan format kunci dan API mereka, dan tingkah laku baris gilir had kadar penyedia kekal tidak berubah.
