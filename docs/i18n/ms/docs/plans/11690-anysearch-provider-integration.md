## 1. Maklumat sahih perkhidmatan (dokumentasi rasmi, disemak silang)

- URL asas: `https://api.anysearch.com` (REST) + `POST /mcp` (MCP, JSON-RPC 2.0).
- `POST /v1/search` - parameter: `query` (diperlukan), `max_results` (1-10, lalai 10), `tag` (`{domain}.{sub_domain}` penghalaan menegak), `zone` (cn/intl), `language`, `params` (medan menegak berstruktur), `format` (json/markdown).
- `GET /v1/sub-domains?domain=...` - katalog keupayaan, TIDAK dikira dalam kuota.
- `POST /v1/extract` - mengambil/mengekstrak `{url, title, content}`; isi JSON yang ketat, had 16 KiB.
- `POST /v1/auth/email/register` - pendaftaran satu panggilan, mengembalikan kunci teks biasa sekali guna `as_sk_...`.
- Pengesahan: `Authorization: Bearer <as_sk_...>` pilihan; akses tanpa nama diturunkan kepada had per-IP yang menggunakan kuota percuma harian; kunci tidak sah mengembalikan 401/403 TANPA sandaran senyap kepada akses tanpa nama.
- Peringkat percuma: 1000 permintaan/hari, 20 QPS bagi setiap kunci. Peringkat berbayar: belum ditetapkan harga (Akan Datang).
- Sampul respons: berjaya `{code: 0, message: "success", request_id, data}`; gagal `{code: -1, message}`. Ralat pengesahan/kuota tidak membawa `error_code` berstruktur (teks mesej ialah isyaratnya); ralat khusus pengekstrakan membawa `error_code` (`invalid_extract_url`, `extract_failed`). Tiada pengepala `Retry-After` pada 429.

## 3. Keputusan (semuanya dicapai pada 2026-08-26)

1. **Pendekatan penghalaan: `fallbackOnly`.** Rasional: penyedia percuma dengan kos 0 tidak boleh mendominasi penghalaan kos automatik; pemilihan eksplisit dan pengembalian kegagalan tidak terjejas. Duluan: entri xquik yang telah digabungkan.
2. **Skop: webSearch + webFetch melalui `POST /v1/extract` dalam v1.** Sejajar dengan model mental dwi-keupayaan tavily/exa. Permukaan menegak (`tag`, `sub-domains`, `batch_search`) kekal di luar skop — tiada IR untuk parameter menegak pada masa ini.
3. **Paparan kuota: `freeMonthlyQuota: 0`** (paparan konservatif gaya xquik). Elaun sebenar (1000 permintaan/hari, ditetapkan semula setiap hari) sebaliknya dinyatakan dalam teks `authHint` katalog UI. Rasional: paparan kuota mesti sepadan dengan semantik penetapan semula; menukar had harian kepada nilai setara bulanan (30000) merupakan janji palsu yang tidak dapat ditunaikan oleh UI.
4. **searchTypes: `["web"]` sahaja.** Tiada bukti awam tentang carian menegak berita/imej dalam AnySearch API; gerbang yang menyepadukan API tanpa carian menegak yang didokumenkan (contohnya Google Custom Search) hanya menyediakan web dan bukannya memetakan berita -> web secara senyap.
5. **Pendekatan kunci:** penggunaan tanpa kunci disokong; kunci yang tidak sah mengembalikan 401/403 dan tidak sekali-kali diturunkan taraf secara senyap kepada tanpa nama (mencerminkan kontrak huluan).
6. **Pengecualian yang disengajakan:** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (pemintasan sembang kekal menggunakan firecrawl/jina/tavily); `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (titik akhir jauh tanpa nama berkongsi satu kumpulan terhad IP bagi setiap IP egress, maka pengekstrakan tanpa kunci ialah pilihan ikut serta, bukannya calon penghalaan automatik); `QUOTA_STATUS_PROVIDERS` (AnySearch menandakan kuota melalui 429/envelope, bukannya status 402/403).
