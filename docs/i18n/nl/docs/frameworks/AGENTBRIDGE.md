AgentBridge is de MITM-proxy (Man-in-the-Middle) van OmniRoute die HTTPS-verkeer van AI-agents in IDE's onderschept en omleidt via de uniforme routeringsengine van OmniRoute. De proxy ondersteunt **10 IDE-agents** — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code en Trae (wordt onderzocht) — waardoor OmniRoute de MITM-proxy met de breedste dekking voor AI-programmeerassistenten op de markt is.

**Dashboardlocatie:** `/dashboard/tools/agent-bridge`
**Zijbalkgroep:** Tools (na Cloud Agents)
**Zie ook:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — bewaak al het onderschepte verkeer in realtime; `docs/security/MITM-TPROXY-DECRYPT.md` (git; niet gecompileerd in `/docs`) — de transparante decryptie-opnamemodus van Linux TPROXY, aangestuurd door de route `/api/tools/agent-bridge/tproxy`.

## §1 Overzicht

### Wat is AgentBridge?

Wanneer een IDE-agent (bijvoorbeeld GitHub Copilot, Cursor of Claude Code) een API-aanroep uitvoert, maakt deze rechtstreeks verbinding met de bovenliggende AI-provider (OpenAI, Anthropic enzovoort). AgentBridge onderschept die verbinding transparant op TLS-niveau — zonder dat de configuratie van de agent hoeft te worden gewijzigd — en herschrijft het verzoek zodat het via OmniRoute loopt.

Dit betekent dat u het volgende kunt doen:

- **Elke agent omleiden naar elke provider**: communiceert Copilot met OpenAI? Leid het om naar Anthropic Claude, Gemini of een van de 352 providers van OmniRoute.
- **Modeltoewijzingen toepassen**: `gemini-3-flash` → `claude-sonnet-4.7`, transparant op handlerniveau.
- **Al het agentverkeer observeren**: elk onderschept verzoek wordt gepubliceerd in de [Traffic Inspector](./TRAFFIC_INSPECTOR.md).
- **De veerkracht van OmniRoute toepassen**: combinatieroutering, circuitbreakers, fallbacks en kostentracering werken ook voor verkeer van IDE-agents.

## §2 Architectuur

### 2.1 Overzicht van componenten

```
IDE-agent (VS Code / Cursor / enz.)
    │  HTTPS (poort 443)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← DNS-omleiding
    │
    ▼
src/mitm/server.cjs  (poort 443, CJS-subproces)
    │  bepaalt doel op basis van Host-header-SNI
    │  genereert per SNI een TLS-certificaat, ondertekend door de AgentBridge-CA
    ├── Overeenkomst met bypasslijst? → TCP-doorvoer (geen ontsleuteling)
    ├── Overeenkomst met doel? → fetch → OmniRoute-router (poort 20128)
    │       └── handler.intercept() — TypeScript
    │               ├── maskSecrets() op aanvraagbody/headers
    │               ├── TrafficBuffer.push() — publiceert naar Traffic Inspector
    │               └── fetchRouter() → /v1/chat/completions
    └── Geen overeenkomst? → TCP-doorvoer (geen ontsleuteling)
```

### 2.2 MITM-server (`src/mitm/server.cjs`)

De centrale MITM-server wordt uitgevoerd als een Node.js CJS-subproces (om te voorkomen dat de bestaande CJS-codebase moet worden herschreven). Deze:

- Luistert op poort 443 (vereist bevoegdheden of `authbind`/`setcap`)
- Ontvangt CONNECT-tunnels van het besturingssysteem (via een DNS-omleiding in `/etc/hosts`)
- Genereert per SNI TLS-certificaten die zijn ondertekend door de AgentBridge-CA (`DATA_DIR/mitm/ca.crt`)
- Bepaalt de doelagent op basis van de Host-header via het register `targets/index.ts`
- Stuurt aanvragen via HTTP door naar de TypeScript-handlerlaag op `http://127.0.0.1:20128`

`TARGET_HOSTS` wordt geladen uit `DATA_DIR/mitm/targets.json` (bij het opstarten geschreven door `targets/index.ts`), waardoor dynamische updates mogelijk zijn zonder de CJS-server opnieuw te starten.

> **Root-CA-model (#6684).** De hierboven beschreven aanpak met een per SNI door een CA ondertekend certificaat
> is het permanente root-CA-model dat is toegevoegd in #6684 (`src/mitm/cert/rootCa.ts` +
> `src/mitm/_internal/rootCaShim.cjs`, waarbij de CA/leaf-cryptografie wordt hergebruikt die zich al
> voor TPROXY heeft bewezen in `src/mitm/tproxy/dynamicCert.ts`) — dit vervangt het
> oudere, afzonderlijke statische zelfondertekende leaf-certificaat (`src/mitm/cert/generate.ts`, nog steeds
> alleen beperkt tot de antigravity-hosts) waarop een los `server.crt`/`server.key`-paar
> op schijf duidt. **Migratiegedrag**: een nieuwe installatie (zonder bestaande
> `server.crt`) krijgt automatisch het root-CA-model; een installatie die het oude
> statische leaf-certificaat al vertrouwde, blijft dit gebruiken totdat de beheerder
> `MITM_ROOT_CA_ENABLED=true` instelt en de bridge opnieuw start (`src/mitm/cert/migration.ts`
> is de zuivere beslisfunctie — een vertrouwde MITM-CA die een leaf-certificaat voor
> **elke** host kan ondertekenen, is aanzienlijk krachtiger dan het oude leaf-certificaat met vaste SAN's, zodat de
> omschakeling nooit stilzwijgend plaatsvindt voor een installatie die dit al vertrouwde). Het CA-certificaat wordt geïnstalleerd
> in hetzelfde `omniroute-mitm.crt`-truststoreslot dat door het oude leaf-certificaat werd gebruikt
> (`cert/install.ts::installCaCert`) — er is geen opschoning van dubbele vertrouwensrelaties nodig.

### 2.3 Handlerbasis (`src/mitm/handlers/base.ts`)

Alle agenthandlers breiden `MitmHandlerBase` uit:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // Beschermde hulpfuncties: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

Elke handler roept vóór het proxyen `hookBufferStart()` aan en na voltooiing `hookBufferUpdate()`. Deze voegen `InterceptedRequest`-items toe aan `globalTrafficBuffer` (zie [Traffic Inspector](./TRAFFIC_INSPECTOR.md) §4).

### 2.4 Doelregister (`src/mitm/targets/`)

Elke agent heeft een declaratief doelbestand:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

Het register (`targets/index.ts`) exporteert `ALL_TARGETS` en genereert bij het opstarten `DATA_DIR/mitm/targets.json`.

### 2.5 Doorvoer en bypasslijst (`src/mitm/passthrough.ts`)

**Bypasslijst** (wordt eerst gecontroleerd en heeft voorrang op een overeenkomst met een doel):

- Standaardpatronen: hosts van banken, `.gov.`, OAuth-/SSO-providers (Okta, Auth0), enz.
- Gebruikerspatronen: opgeslagen in de databasetabel `agent_bridge_bypass`
- Hosts waarvoor de bypass geldt, krijgen een transparante TCP-tunnel — TLS wordt **nooit ontsleuteld**

**Standaarddoorvoer** (geen overeenkomst met een doel en niet in de bypasslijst):

- Krijgt eveneens een TCP-tunnel — verbindingen worden nooit verbroken
- Voorkomt dat AgentBridge het algemene HTTPS-verkeer van het systeem verstoort

Routeringsvolgorde:

```
bypasslijst → overeenkomst met doel → doorvoer
```

### 2.6 Upstream-CA-certificaat (`src/mitm/upstreamTrust.ts`)

Voor bedrijfsnetwerkomgevingen met een aangepaste CA:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

Wanneer dit is ingesteld, wordt de globale dispatcher van `undici` geconfigureerd met het extra CA-certificaat, zodat AgentBridge upstream-providers kan bereiken via bedrijfsproxy's voor TLS-beëindiging.

### 2.7 Maskeren van geheimen (`src/mitm/maskSecrets.ts`)

De onafhankelijke cleanroomscanner wordt toegepast op aanvraagbody's en headers met aanmeldgegevens
**voordat** deze in de buffer van Traffic Inspector of in een logbestand terechtkomen. De scanner voert één lineaire doorgang uit:

- Tokens met het voorvoegsel `sk-` / `ak-` / `pk-` (OpenAI-/Anthropic-stijl)
- RFC 6750-aanmeldgegevens van de vorm `Authorization: Bearer <token>`, waarbij het volledige token voorrang heeft
- Algemene lange, ondoorzichtige tokens (≥40 tekens), inclusief vormen met punten en opvulling

`sanitizeHeaders()` zet behouden namen om naar kleine letters, voegt arraywaarden deterministisch samen, verwijdert de
gedeelde blokkeerlijst voor hop-by-hop-/framingheaders (inclusief proxyauthenticatie), redigeert `cookie` en
`set-cookie` volledig en delegeert waarden met aanmeldgegevens aan de scanner.

## §3 Installatie

### 3.1 De MITM-server starten/stoppen

Gebruik de AgentBridge-serverkaart op `/dashboard/tools/agent-bridge`:

| Actie                  | Beschrijving                                                                     |
| ---------------------- | -------------------------------------------------------------------------------- |
| Server starten         | Start `src/mitm/server.cjs` op poort 443                                         |
| Server stoppen         | Sluit het onderliggende proces correct af                                        |
| Server herstarten      | Stoppen + starten (neemt wijzigingen in doelen over)                             |
| Certificaat vertrouwen | Installeert `DATA_DIR/mitm/ca.crt` in het vertrouwensarchief van het OS          |
| Certificaat downloaden | Downloadt `ca.crt` voor handmatige installatie                                   |
| Certificaat vernieuwen | Maakt een nieuw CA-sleutelpaar (alle bestaande certificaten per agent vervallen) |

### 3.2 Het certificaat vertrouwen

Het CA-certificaat van AgentBridge moet door het OS worden vertrouwd voordat IDE's de MITM-verbinding accepteren.

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Sleutelhanger):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

U kunt ook de knop "Certificaat vertrouwen" in het dashboard gebruiken (hiermee wordt de juiste opdracht voor uw OS uitgevoerd, zo nodig met een sudo-prompt).

#### Op Electron gebaseerde IDE's negeren het vertrouwensarchief van het OS (`NODE_EXTRA_CA_CERTS`)

Sommige IDE's — met name **Antigravity IDE** en andere van Electron / VS Code afgeleide apps — bundelen
hun eigen Node.js-runtime die **het vertrouwensarchief van het OS niet raadpleegt** voor uitgaande
`fetch`/HTTPS-verzoeken. De CA vertrouwen op OS-/NSS-niveau is voldoende voor de systeemeigen **backend**
van de IDE (bijvoorbeeld een Go-taalserver, die de CA-bundel van het OS gebruikt), maar de **Electron-frontend**
ondervindt nog steeds TLS-fouten — dit uit zich doordat de app _uitgelogd_ lijkt of een
_"verbindingsfout"_ toont, ook al laten de MITM-logboeken zien dat de bootstrap-aanroepen van de backend
`200` retourneren. Er zijn twee stappen vereist, die beide van belang zijn:

1. Wijs de runtime expliciet naar de CA:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **Start de IDE vanuit die shell.** Als u deze start via het bureaubladpictogram / Dock / Startmenu,
   worden shell-exports **niet** overgenomen, en `~/.config/environment.d/*.conf` wordt pas toegepast
   na een nieuwe grafische aanmelding. Sluit de IDE eerst volledig af — door de singletonvergrendeling
   van Electron brengt een tweede startpoging alleen het bestaande proces naar de voorgrond en wordt
   de nieuwe omgeving genegeerd.

De bovenstaande stap voor OS-vertrouwen + NSS blijft noodzakelijk (de Chromium-netwerkstack die door
sommige authenticatiestromen wordt gebruikt, leest het NSS-archief per gebruiker en heeft eigen statische
pins voor `*.googleapis.com` die door een lokaal vertrouwde CA worden overschreven). `NODE_EXTRA_CA_CERTS`
dekt daarnaast het Node-`fetch`-pad af.

### 3.3 DNS-routering

Voor elke agent die u wilt onderscheppen, moeten de bijbehorende API-host(s) worden omgezet naar `127.0.0.1`. AgentBridge beheert vermeldingen in `/etc/hosts` automatisch wanneer u DNS voor een agent in de installatiewizard in- of uitschakelt.

Voorbeeldvermeldingen in `/etc/hosts` voor GitHub Copilot:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 Modeltoewijzing

Gebruik de modeltoewijzingstabel in elke agentkaart om toewijzingen van bron → doel te definiëren:

| Bronmodel (eigen aan agent) | Doelmodel (OmniRoute) |
| --------------------------- | --------------------- |
| `gpt-4o`                    | `claude-sonnet-4.7`   |
| `*` (jokerteken)            | `claude-haiku-4.7`    |

Het jokerteken `*` wijst elk niet-herkend model toe aan het opgegeven doel. Wordt opgeslagen in de tabel `agent_bridge_mappings`.

> **Tip — ontdek de werkelijke model-ID's van de agent.** Een IDE kan modelnamen verzenden die afwijken van
> de labels in de gebruikersinterface en die tussen hoofdversies veranderen. **Antigravity 2** verzendt
> bijvoorbeeld `gemini-3.1-pro-low`, `gemini-pro-agent` en `gemini-3.1-flash-lite` via de verbinding — niet
> de `gemini-2.5-pro` die in oudere documentatie wordt vermeld. Verstuur één chatbericht zonder dat er een
> overeenkomende toewijzing bestaat: de MITM registreert de exacte binnenkomende `model:` en laat het verzoek
> door. Wijs die letterlijke waarde toe; het volgende verzoek wordt vervolgens onderschept en naar uw doel gerouteerd.

### 3.5 Risicomelding

AgentBridge onderschept referenties (OAuth-tokens, API-sleutels) die de IDE gebruikt om zich bij upstreamproviders te authenticeren. Deze worden **gemaskeerd voordat ze worden gelogd** (zie §2.7), maar zijn zichtbaar voor de MITM-laag van OmniRoute. Bij de eerste activering van elke agent wordt een sluitbare modale risicomelding weergegeven.

### 3.6 Onderhoud en diagnostiek

| `cert-exists`      | Het MITM-certificaat is op schijf gegenereerd                                    | "Er is nog geen MITM-certificaat gegenereerd. Genereer er een vanaf het tabblad AgentBridge."                                                                                           |
| `cert-trusted`     | De MITM-root-CA bevindt zich in het vertrouwensarchief van het besturingssysteem | "De MITM-root-CA wordt niet vertrouwd door het vertrouwensarchief van het besturingssysteem, waardoor TLS-interceptie mislukt. Vertrouw het certificaat vanaf het tabblad AgentBridge." |
| `dns-configured`   | Doelhostnamen worden gespooft in `/etc/hosts`                                    | "Doelhostnamen worden niet gespooft in /etc/hosts`, waardoor verkeer de proxy nooit bereikt. Schakel DNS in voor de agent(en) waarvan u verkeer wilt vastleggen."                       |

**Banner voor verweesde status:** wanneer de pagina status detecteert die door een crash is achtergebleven (DNS-spoofing / CA / systeemproxy), toont de kaart een amberkleurige banner — _"Een vorige sessie heeft systeemstatus achtergelaten (DNS-spoofing, CA of systeemproxy). Voer Herstellen uit om deze op te ruimen."_ — en wordt de knop **Herstellen** gemarkeerd. `Repair` is het equivalent op applicatieniveau van de vlag `--cleanup` van ProxyBridge (delegeert naar `repairMitm()` in `src/mitm/manager.ts`).

> De MITM-root-CA blijft bij stoppen/starten geïnstalleerd om herhaalde sudo-
> prompts te voorkomen (hetzelfde gedrag als mitmproxy/Charles), dus het verwijderen ervan is een expliciete
> actie **CA verwijderen** in plaats van iets dat automatisch gebeurt bij het stoppen.

### 3.7 Overdraagbare configuratie importeren/exporteren

AgentBridge kan de door de **operator instelbare** status serialiseren naar een geversioneerde JSON-blob, zodat een configuratie op verschillende machines kan worden gerepliceerd. De serializer is `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`), gevalideerd door `AgentBridgeConfigSchema`.

De export bevat precies drie onderdelen (ingebouwde standaardwaarden worden opzettelijk **NIET** geëxporteerd, zodat ze bij het importeren nooit worden gedupliceerd of ermee conflicteren):

| Veld             | Bron                                                                       | Opmerkingen                                                            |
| ---------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `bypassPatterns` | door de gebruiker gedefinieerde omzeilingspatronen (`agent_bridge_bypass`) | standaardpatronen voor banken/overheden/okta zijn uitgesloten          |
| `customHosts`    | aangepaste hosts van Traffic Inspector (`inspector_custom_hosts`)          | elk: `{ host, kind: "llm"\|"app"\|"custom", label? }`                  |
| `agentMappings`  | modeltoewijzingen per agent (`agent_bridge_mappings`)                      | `{ [agentId]: [{ source, target }] }` voor elke agent met toewijzingen |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**Importgedrag** (`POST /api/tools/agent-bridge/config`): omzeilingspatronen en toewijzingen per agent worden **volledig vervangen**; aangepaste hosts worden **idempotent** toegevoegd (`INSERT OR IGNORE`). Het antwoord vermeldt hoeveel items van elk type zijn toegepast:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

Wat **NIET** in de configuratie staat: de uitvoeringsstatus van de server, certificaatpaden, DNS-status per agent, het pad naar de upstream-CA en TPROXY-instellingen — dit zijn host-/runtimestatusgegevens, geen overdraagbare voorkeuren.

## §5 Beveiliging

### Toegepaste strikte regels

| Regel                                           | Toepassing                                                                                               |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| **#12** `sanitizeErrorMessage`                  | Alle handlerfouten worden opgeschoond vóór opname in een antwoord of buffer                              |
| **#13** Omgevingsvariabelen doorgeven aan shell | Bewerkingen van `/etc/hosts` gebruiken de optie `env` — geen stringinterpolatie van paden                |
| **#15 + #17** `isLocalOnlyPath()`               | `/api/tools/agent-bridge/` is LOCAL_ONLY + SPAWN_CAPABLE — loopback wordt vóór authenticatie afgedwongen |

### Omzeilingslijst voor gevoelige hosts

De omzeilingslijst zorgt ervoor dat financiële instellingen, OAuth-/SSO-providers en andere gevoelige hosts **nooit worden ontsleuteld**. Hun TLS-verkeer wordt als transparante TCP-tunnel doorgestuurd — OmniRoute ziet de platte tekst nooit.

Standaard omzeilingspatronen zijn onder meer:

- `*.bank.*`, `*.gov.*` (financieel/overheid)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/identiteit)
- `*.apple.com`, `*.icloud.com` (Apple-systeemservices)

Door gebruikers toegevoegde omzeilingspatronen worden opgeslagen in de tabel `agent_bridge_bypass` en hebben voorrang op alles.

### Maskering van geheimen

`maskSecrets()` uit `src/mitm/maskSecrets.ts` wordt toegepast:

- Op elke aanvraagbody vóór `TrafficBuffer.push()`
- Op elke header vóór logboekregistratie of verzending

Patronen: tokens met het voorvoegsel `sk-`/`ak-`/`pk-`, `Bearer`-tokens en generieke tokens van ≥40 tekens.

### Upstream-CA-certificaat

Wanneer `AGENTBRIDGE_UPSTREAM_CA_CERT` is ingesteld, wordt het bestand bij het opstarten gelezen. Als het pad bestaat maar het bestand niet leesbaar is, registreert AgentBridge een duidelijke fout en weigert het te starten (dit voorkomt ongemerkte TLS-fouten in bedrijfsomgevingen).

### Bekende beperkingen

- **Poort 443 vereist privileges**: op Linux heeft AgentBridge `setcap 'cap_net_bind_service=+ep'` nodig op het binaire bestand van Node, of moet het via `authbind` worden uitgevoerd. De installatiewizard toont besturingssysteemspecifieke instructies.
- **Herstart van de IDE vereist**: na de DNS-omleiding moet de IDE opnieuw worden gestart voordat de nieuwe hostomzetting van kracht wordt.
- **Hardgecodeerde OAuth-tokens**: sommige agenten (Kiro, Antigravity) slaan OAuth-vernieuwingstokens lokaal op. Deze zijn transparant voor AgentBridge — het ziet het Bearer-token in elke aanvraag, dat vóór logboekregistratie wordt gemaskeerd.
- **Electron-frontends hebben `NODE_EXTRA_CA_CERTS` nodig**: IDE's waarvan de frontend op een gebundelde Node-/Electron-runtime draait, negeren het vertrouwensarchief van het besturingssysteem/NSS en moeten vanuit een shell worden gestart waarin `NODE_EXTRA_CA_CERTS` is ingesteld (zie §3.2). Symptoom wanneer dit ontbreekt: de IDE-backend wordt geauthenticeerd (MITM toont `200`-antwoorden), maar de gebruikersinterface blijft afgemeld.
- **Meerdere installaties van dezelfde IDE zijn onafhankelijk**: een systeeminstallatie (bijv. `/usr/share/antigravity/antigravity`) en een gebruikerslokale 'Full'-installatie (bijv. `~/AntigravityIDE_Full/antigravity-ide`) zijn afzonderlijke processen met hun eigen runtimes — elke installatie moet opnieuw worden gestart met de geïnjecteerde CA. Bepaal vóór het opnieuw starten aan de hand van het pad van het binaire bestand welke installatie actief is.
- **De identiteit wordt bepaald door de systeemprompt van de agent, niet door het gerouteerde model**: wanneer u het model van een agent opnieuw toewijst aan een andere provider, beweert het antwoord nog steeds de oorspronkelijke identiteit van de agent te hebben (bijv. Antigravity antwoordt 'I am powered by Gemini'), omdat de IDE dit in de systeemprompt injecteert. Controleer de werkelijke backend in `call_logs` / `proxy_logs` (`provider`, `model`, `target_format`) en niet door het model te vragen wie het is.

## §6 Probleemoplossing

### Conflict op poort 443

Als een ander proces al luistert op poort 443 (webserver, VPN enz.):

```bash
lsof -i :443          # zoek het proces
sudo fuser -k 443/tcp  # geforceerd beëindigen (voorzichtig gebruiken)
```

U kunt ook een niet-geprivilegieerde poort configureren in de AgentBridge-instellingen en omleidingsregels instellen met `iptables` / `pf`.

### Certificaat wordt niet vertrouwd

Als de IDE TLS-fouten weergeeft nadat AgentBridge is gestart:

1. Controleer of het certificaat is geïnstalleerd: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) of `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. Sommige apps beheren hun eigen vertrouwensarchief (Firefox, Chrome op Linux). Voer ‘Certificaat vertrouwen’ opnieuw uit en controleer het NSS-/Firefox-specifieke certificaatarchief.
3. Start de IDE opnieuw nadat u het certificaat hebt vertrouwd — actieve TLS-sessies gebruiken nog de oude vertrouwensstatus.

### IDE afgemeld / ‘verbindingsfout’ ondanks een vertrouwde CA

Symptoom: na het omleiden van DNS en het vertrouwen van de CA wordt een op Electron gebaseerde IDE (bijv. Antigravity)
**afgemeld** geopend of wordt er een verificatie-/verbindingsfout weergegeven, terwijl uit het MITM-logboek blijkt dat de
bootstrap-aanroepen (`loadCodeAssist`, `fetchAvailableModels`, …) een `200` retourneren.

Oorzaak: de **meegeleverde Node-/Electron-runtime van de IDE negeert het vertrouwensarchief van het besturingssysteem**. De systeemeigen
backend (een in Go geschreven taalserver) vertrouwt de CA van het besturingssysteem en voert de verificatie uit, maar de Electron-frontend
doet dat niet — waardoor de gebruikersinterface denkt dat deze offline is.

Oplossing (beide stappen): exporteer `NODE_EXTRA_CA_CERTS=<ca.crt>` **en start de IDE opnieuw vanuit die
shell**, niet via het bureaubladpictogram. Sluit de IDE eerst volledig af — door Electrons singletonvergrendeling
activeert een tweede start alleen het bestaande proces en wordt de nieuwe omgeving genegeerd. Zie §3.2.
Dit komt overeen met een openstaand upstream-rapport waarin een zelfstandige agent via een MITM werkt, maar de IDE-
variant met dezelfde configuratie niet werkt.

### DNS niet doorgevoerd

Controleer of `/etc/hosts` is bijgewerkt:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

Leeg de DNS-cache:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### IDE niet gedetecteerd

Voor automatische detectie worden gangbare installatiepaden gebruikt. Als de detectie mislukt terwijl de IDE wel is geïnstalleerd:

- Controleer of het binaire IDE-bestand zich op een niet-standaardlocatie bevindt
- De installatiewizard werkt nog steeds — een mislukte detectie betekent alleen dat de badge het installatiepad niet weergeeft

### Handlerfouten (ophalen bij upstream mislukt)

Als AgentBridge verzoeken onderschept, maar alle verzoeken mislukken:

1. Controleer of ten minste één provider is verbonden via `/dashboard/providers`
2. Controleer de OmniRoute-serverlogboeken: `APP_LOG_LEVEL=debug` in `.env`
3. Controleer of `OMNIROUTE_BASE_URL` naar het juiste routereindpunt verwijst (standaard: `http://127.0.0.1:20128`)

## §8 Roadmap

### Trae-onderzoek

Trae is een relatief nieuwe AI-codeerassistent. Voordat een handler wordt geïmplementeerd:

1. Identificeer het binaire bestand/de extensie in de marketplaces van VS Code / JetBrains of als zelfstandige app

3. Bepaal het authenticatiemechanisme
4. Beoordeel go/no-go op basis van de TOS en de vindbaarheid van de API

Totdat het onderzoek is afgerond, toont de Trae-kaart in het dashboard een badge 'In onderzoek' met een link 'Haalbaarheid rapporteren'. De handlerstub in `src/mitm/handlers/trae.ts` genereert een gestructureerde fout `Nog niet geïmplementeerd`.

### Agents in de backlog (MITM vereist — geen ondersteuning voor aangepaste basis-URL)

De volgende tools ondersteunen in hun huidige versies geen aangepaste basis-URL's, waardoor MITM de enige manier is om verkeer te onderscheppen. De haalbaarheidsbeoordeling is nog niet afgerond:

- **Amp** (Sourcegraph)
- **Amazon Q / Kiro CLI** (AWS Bedrock — niet hetzelfde als Kiro IDE)

Opmerking: GitHub Copilot CLI ≥v1.0.19 ondersteunt `COPILOT_PROVIDER_BASE_URL` — gebruik voor die tool directe configuratie in plaats van MITM.
