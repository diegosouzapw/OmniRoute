## Wat het is

Met Local Corpus kan een beheerder één expliciet goedgekeurde map met tekstbestanden beschikbaar stellen aan de MCP-server van OmniRoute. Bestanden blijven in hun oorspronkelijke map: OmniRoute slaat alleen het canonieke hoofdpad op in SQLite en houdt een zoekindex in het geheugen bij. Corpusinhoud wordt niet naar de repository of database gekopieerd.

De index wordt incrementeel vernieuwd. Ongewijzigde bestanden worden hergebruikt op basis van grootte en wijzigingstijd, gewijzigde bestanden worden opnieuw gelezen en gehasht met SHA-256 en verwijderde bestanden worden uit de index verwijderd. Bij een zoekopdracht wordt een index vernieuwd die ouder is dan 30 seconden; aanroepers kunnen ook om een onmiddellijke vernieuwing vragen.

## De bron configureren

De instellingenroute vereist dezelfde beheerauthenticatie als andere instellingen-API's. Het ingediende pad moet al bestaan en moet een absoluut pad naar een map zijn.

```bash
# Een goedgekeurde map verbinden
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# De configuratie en indexstatus controleren
curl http://localhost:20128/api/settings/local-corpus

# De verbinding verbreken zonder bronbestanden te wijzigen
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## MCP-tools

Alle drie de tools vereisen `read:local-corpus`. Toolreacties tonen relatieve paden en de basisnaam van de hoofdmap, maar nooit het absolute pad ervan.

| Tool                  | Beschrijving                                                                                         |
| :-------------------- | :--------------------------------------------------------------------------------------------------- |
| `local_corpus_status` | De configuratiestatus, indexgrootte, limieten en het tijdstip van de laatste vernieuwing tonen       |
| `local_corpus_search` | Geïndexeerde tekst doorzoeken en begrensde fragmenten per regel retourneren (maximaal 20 resultaten) |
| `local_corpus_read`   | Een begrensd regelbereik lezen uit één toegestaan corpusrelatief bestand                             |

Voorbeelden van MCP-invoer:

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## Veiligheidsgrenzen

- De toelatingslijst is gericht op tekstbestanden: `.cfg`, `.csv`, `.geojson`, `.htm`, `.html`, `.ini`, `.js`, `.json`, `.jsonl`, `.jsx`, `.log`, `.md`, `.mjs`, `.ps1`, `.py`, `.sh`, `.sql`, `.toml`, `.ts`, `.tsx`, `.txt`, `.xml`, `.yaml` en `.yml`.
- Symbolische koppelingen worden overgeslagen. Leespaden worden gecanonicaliseerd en moeten binnen de geconfigureerde hoofdmap blijven; absolute paden en pogingen tot padtraversering worden geweigerd.
- Namen van gevoelige en gegenereerde mappen worden uitgesloten: `.build`, `.codex`, `.env`, `.git`, `.next`, `.omniroute`, `.ssh`, `coverage`, `dist`, `node_modules` en `secrets`.
- De standaardlimieten zijn 5.000 bestanden, 1 MiB per bestand, in totaal 64 MiB aan geïndexeerde inhoud, ongeveer 4.000 tekens per zoekfragment en 400 regels per leesbewerking.
- Bestanden die NUL-tekens bevatten, worden als niet-tekstbestanden beschouwd en overgeslagen of geweigerd.

Binaire documenten zoals PDF-, DOCX- en afbeeldingsbestanden en archieven worden bewust niet ondersteund. Converteer ze vóór het indexeren naar een goedgekeurde tekstindeling in de geconfigureerde map.

## Operationele opmerkingen

- Als de geconfigureerde hoofdmap wordt gewijzigd of verwijderd, wordt de gedeelde index in het geheugen gewist.
- Wanneer een proces opnieuw wordt gestart, gaat de index verloren; bij de volgende zoekopdracht wordt deze opnieuw opgebouwd vanuit de geconfigureerde bron.
- `local_corpus_status` forceert geen scan. Gebruik `local_corpus_search` met `refresh: true` wanneer een onmiddellijke nieuwe scan vereist is.
- Scan- en leesfouten worden geteld of als opgeschoonde fouten geretourneerd; bronbestanden worden nooit gewijzigd.
