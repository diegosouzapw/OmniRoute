> **Gezaghebbende bron:** `src/lib/obsidian/api.ts` (REST- en synchronisatieclient),
> `src/lib/db/obsidian.ts` (opslag van token / basis-URL / WebDAV),
> `src/lib/obsidianSync.ts` (WebDAV-kluissynchronisatie), `open-sse/mcp-server/tools/obsidianTools.ts`
> (22 MCP-tools), `src/app/api/settings/obsidian/route.ts` +
> `src/app/api/settings/obsidian/webdav/route.ts` (instellingen-API's). Toolregistratie
> en configuratie van scopes bevinden zich in `open-sse/mcp-server/server.ts`.

## Wat het is

OmniRoute maakt verbinding met een **Obsidian**-kluis als **contextbron** — een lokale
Markdown-kennisbank die agents lezen en schrijven via de ingebouwde MCP-server. De
integratie communiceert met de communityplug-in **Obsidian Local REST API** die in de
desktopapp wordt uitgevoerd, zodat agents notities kunnen doorzoeken, bestanden kunnen
lezen/schrijven/patchen, de kluis kunnen weergeven, met dagelijkse/wekelijkse periodieke
notities kunnen werken, tags kunnen beheren, Obsidian-opdrachten kunnen uitvoeren en
(optioneel) een bidirectionele desktop↔mobiel-kluissynchronisatie kunnen coördineren.

De client (`src/lib/obsidian/api.ts`) vormt een wrapper rond de Local REST API met:

- **Opnieuw proberen met back-off** voor tijdelijke `5xx`-fouten, en een **time-out van 30 seconden** via `AbortController`.
- **Getypeerde foutclassificatie** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- Een **gebruiksvriendelijke hint voor "kan Obsidian niet bereiken"** die wijst op de
  veelvoorkomende vergissing met de poort (HTTP op `27123`, **niet** het MCP-eindpunt op
  `27124`) en de Tailscale-vorm.
- Kluisrelatieve **padcodering**, zodat notitiepaden met spaties/schuine strepen veilig zijn.

## Installatie

Er is **geen omgevingsvariabele** voor het Obsidian-token of de basis-URL — beide worden
opgeslagen in de SQLite-tabel `key_value` (naamruimte `obsidian`) via
`src/lib/db/obsidian.ts`. Het token is **versleuteld wanneer het is opgeslagen**
(AES-256-GCM, met terugvalmogelijkheid voor achterwaartse compatibiliteit met platte tekst).
Configureer dit via het tabblad **Context Sources** van het Endpoint-dashboard
(`ObsidianSourceCard`), of via de REST-API voor instellingen.

> [!IMPORTANT]
> De plug-in **Obsidian Local REST API** moet geïnstalleerd en actief zijn. De
> REST-interface luistert op **HTTP `127.0.0.1:27123`** (de standaardbasis-URL). Poort
> `27124` is een _afzonderlijk_ MCP/HTTPS-eindpunt en wordt expliciet geweigerd door de
> instellingenroute. Gebruik `http://<tailscale-ip>:27123` wanneer u vanaf een ander
> apparaat verbinding maakt.

### Configuratiesleutels (SQLite `key_value`, naamruimte `obsidian`)

| Sleutel           | Doel                                                     | Versleuteld |
| ----------------- | -------------------------------------------------------- | ----------- |
| `api_key`         | Bearer-token voor de Local REST API                      | ja          |
| `base_url`        | REST-basis-URL (standaard `http://127.0.0.1:27123`)      | nee         |
| `vault_path`      | Absoluut pad naar de kluismap (voor synchronisatie)      | nee         |
| `webdav_username` | Gegenereerde WebDAV-gebruikersnaam (kluissynchronisatie) | nee         |
| `webdav_password` | Gegenereerd WebDAV-wachtwoord (kluissynchronisatie)      | ja          |
| `webdav_enabled`  | Of WebDAV-kluissynchronisatie is ingeschakeld            | nee         |

### Configureren via REST

```bash
# Het Local REST API-token opslaan en valideren (POST valideert via een statuscontrole)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# De verbindingsstatus controleren (retourneert connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# De verbinding verbreken (wist het opgeslagen token)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Alle methoden vereisen dashboardauthenticatie. `POST` weigert elke URL op poort `27124`
en valideert het token door het statuseindpunt van de Local REST API aan te roepen voordat
het wordt opgeslagen.

### WebDAV-kluissynchronisatie

`src/app/api/settings/obsidian/webdav/route.ts` beheert een optionele, door WebDAV
ondersteunde kluissynchronisatie (aangestuurd door `src/lib/obsidianSync.ts`). Als deze
wordt ingeschakeld, wordt OmniRoute gekoppeld aan een lokale kluismap en wordt een
willekeurig WebDAV-gebruikersnaam-/wachtwoordpaar aangemaakt:

```bash
# WebDAV-synchronisatie voor een kluismap inschakelen (maakt een gebruikersnaam/wachtwoord aan)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# De WebDAV-synchronisatiestatus ophalen (referenties worden alleen geretourneerd wanneer deze is ingeschakeld)
curl http://localhost:20128/api/settings/obsidian/webdav

# WebDAV-synchronisatie uitschakelen (wist referenties + beheerde .stignore)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Contextbron per API-sleutel (optioneel)

De Obsidian-configuratie kan **per API-sleutel** worden afgebakend via de tabel
`api_key_context_sources` (`src/lib/db/apiKeyContextSources.ts`). Wanneer een MCP-aanroep
een geauthenticeerde API-sleutel-id bevat, geeft `getObsidianConfigForApiKey()` de voorkeur
aan het eigen token, de eigen basis-URL en het eigen kluispad van die sleutel
(`source: "api_key"`); anders wordt teruggevallen op de globale configuratie
(`source: "global"`).

## MCP-tools (22)

Gedefinieerd in `open-sse/mcp-server/tools/obsidianTools.ts`. Het token/de basis-URL worden
per aanroep bepaald (eerst per API-sleutel, daarna globaal). Tools die de OmniRoute-**synchronisatieserver**
gebruiken (de vier `obsidian_sync_*`-tools), vereisen daarnaast het synchronisatie-authenticatietoken dat
in de OmniRoute-instellingen is geconfigureerd.

### Leestools (`read:obsidian`)

| Tool                         | Beschrijving                                                                                                  |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Controleer of de Local REST API bereikbaar is en geauthenticeerd is.                                          |
| `obsidian_search_simple`     | Doorzoek de inhoud van notities op volledige tekst; retourneert fragmenten met bestandspaden.                 |
| `obsidian_search_structured` | Zoek met een JSON Logic-expressie (and/or/regex/path-filters).                                                |
| `obsidian_read_note`         | Lees een notitie via een kluisrelatief pad; optioneel een specifieke kop/blok/frontmatter.                    |
| `obsidian_list_vault`        | Toon bestanden en mappen in de kluis (boomstructuur van items).                                               |
| `obsidian_get_document_map`  | Haal de kopstructuur van de notitie op als een koppeling van koppen → regelnummers.                           |
| `obsidian_get_note_metadata` | Haal frontmatter, tags, links en het aantal tekens/woorden op zonder de volledige inhoud.                     |
| `obsidian_get_active_file`   | Haal het pad en de inhoud op van het momenteel actieve bestand in Obsidian.                                   |
| `obsidian_get_periodic_note` | Haal de dagelijkse/wekelijkse/maandelijkse periodieke notitie voor een datum op (vandaag indien weggelaten).  |
| `obsidian_get_tags`          | Toon alle kluistags met hun frequenties.                                                                      |
| `obsidian_list_commands`     | Toon beschikbare Obsidian-opdracht-ID's (te gebruiken met `obsidian_execute_command`).                        |
| `obsidian_sync_status`       | Status van de OmniRoute-synchronisatieserver: actief, kluisnaam, poort, bedrijfstijd, laatste synchronisatie. |
| `obsidian_sync_conflicts`    | Toon onopgeloste synchronisatieconflicten (pad, conflictpad, detectietijdstip).                               |

### Schrijftools (`write:obsidian`)

| Tool                             | Beschrijving                                                                                   |
| -------------------------------- | ---------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Maak of overschrijf een notitie met de opgegeven Markdown-inhoud.                              |
| `obsidian_append_note`           | Voeg inhoud toe aan een notitie; optioneel aan een specifieke kop/blok.                        |
| `obsidian_patch_note`            | Voeg gericht toe, voeg vooraan toe of vervang bij een kop, blok of frontmatter-veld.           |
| `obsidian_delete_note`           | Verwijder een notitie permanent uit de kluis.                                                  |
| `obsidian_move_note`             | Verplaats of hernoem een notitie binnen de kluis.                                              |
| `obsidian_execute_command`       | Voer een Obsidian-opdracht uit via de opdracht-ID.                                             |
| `obsidian_open_file`             | Open een bestand in Obsidian (maakt het aan als het niet bestaat).                             |
| `obsidian_sync_trigger`          | Start onmiddellijk een bidirectionele desktop↔mobiel-kluissynchronisatie.                      |
| `obsidian_sync_resolve_conflict` | Los een synchronisatieconflict op: behoud `local` (mobiel), `remote` (desktop) of `keep-both`. |

> [!NOTE]
> Doelen van `obsidian_patch_note` accepteren een `targetType` van `heading | block | frontmatter`
> en een `operation` van `append | prepend | replace`, met een optionele
> `createTargetIfMissing`. De vier `obsidian_sync_*`-tools communiceren met de lokale synchronisatieserver
> (`http://127.0.0.1:27781` standaard) en vereisen het synchronisatietoken.

### Scopes

Leestools vereisen `read:obsidian`; schrijftools vereisen `write:obsidian`. De handhaving
is identiek aan die van Notion — afgehandeld door `withScopeEnforcement()` in
`open-sse/mcp-server/server.ts`, afhankelijk van `OMNIROUTE_MCP_ENFORCE_SCOPES=true`, met
toegestane scopes afkomstig uit `OMNIROUTE_MCP_SCOPES` of de scopecontext van de API-sleutel. Zie
[MCP-SERVER.md](./MCP-SERVER.md).

## Eindpunten

| Methode  | Pad                             | Doel                                                          |
| -------- | ------------------------------- | ------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | Retourneert `{ connected, hasToken, baseUrl, vaultPath }`.    |
| `POST`   | `/api/settings/obsidian`        | Token opslaan en valideren (poort `27124` wordt geweigerd).   |
| `DELETE` | `/api/settings/obsidian`        | Verbinding verbreken (opgeslagen token wissen).               |
| `GET`    | `/api/settings/obsidian/webdav` | WebDAV-synchronisatiestatus en inloggegevens (indien actief). |
| `POST`   | `/api/settings/obsidian/webdav` | WebDAV-synchronisatie voor een vaultmap inschakelen.          |
| `DELETE` | `/api/settings/obsidian/webdav` | WebDAV-synchronisatie uitschakelen.                           |

> Dit zijn instellingenroutes van het dashboard. De vault zelf wordt benaderd via de lokale REST API van Obsidian
> (de geconfigureerde `base_url`) en via de bovenstaande MCP-tools — er is
> geen openbaar `/v1`-Obsidian-proxyeindpunt.

## Gebruiksscenario's

- **Antwoorden op basis van de vault** — `obsidian_search_simple` / `obsidian_search_structured`
  en vervolgens `obsidian_read_note`, zodat een agent antwoordt op basis van je echte notities.
- **Notities schrijven / dagboek bijhouden** — `obsidian_write_note`, `obsidian_append_note` of
  de gerichte `obsidian_patch_note` om agentuitvoer, samenvattingen of dagelijkse notities
  (`obsidian_get_periodic_note`) in de vault vast te leggen.
- **Door de vault navigeren** — `obsidian_list_vault`, `obsidian_get_document_map` en
  `obsidian_get_tags` om de structuur te verkennen voordat je leest/schrijft.
- **Obsidian-automatisering** — `obsidian_list_commands` + `obsidian_execute_command` om
  plug-ins/opdrachten vanuit een agent aan te sturen; `obsidian_open_file` om een notitie in de UI weer te geven.
- **Mobiele synchronisatie** — schakel WebDAV-synchronisatie in en gebruik vervolgens `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  om desktop↔mobiel te coördineren en conflicten op te lossen.
