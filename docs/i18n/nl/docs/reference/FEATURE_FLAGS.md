> Runtime-schakelaars die het gedrag van OmniRoute wijzigen **zonder opnieuw te implementeren**.
> Elke vlag die hier wordt vermeld, is gedefinieerd in
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> — de enige bron van waarheid. Zowel het dashboard als de REST-API leest uit
> dat bestand, zodat de onderstaande tabel zo wordt gegenereerd dat deze er 1-op-1 mee overeenkomt.

---

## Wat featureflags zijn

Een featureflag is een benoemde schakelaar (boolean of enum) waarvan de waarde tijdens
runtime kan worden gewijzigd en in de database kan worden opgeslagen, zonder dat het proces opnieuw hoeft te worden geïmplementeerd. Elke
vlag wordt beschreven door een `FeatureFlagDefinition` met een `key`, `label`,
`description`, `category`, `defaultValue`, `type` en een `requiresRestart`-aanduiding.

### Resolutievolgorde

De **effectieve waarde** van een vlag wordt bepaald door
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) met de volgende
prioriteitsvolgorde (de hoogste heeft voorrang):

1. **Database-overschrijving** — een waarde die is opgeslagen in de tabel `key_value` onder de
   naamruimte `feature_flags` (ingesteld via het dashboard of de REST-API).
2. **Omgevingsvariabele** — `process.env[<KEY>]`, indien ingesteld en niet leeg.
3. **Standaardwaarde uit de definitie** — de `defaultValue` uit `featureFlagDefinitions.ts`.

Een boolean-vlag wordt als **ingeschakeld** beschouwd wanneer de effectieve waarde `"true"`,
`"1"` of `"yes"` is (zie `isFeatureFlagEnabled()`).

> [!NOTE]
> De meeste vlaggen hebben ook een overeenkomstige omgevingsvariabele met **dezelfde naam**,
> gedocumenteerd in [`ENVIRONMENT.md`](./ENVIRONMENT.md). De database-overschrijving van de vlag
> heeft voorrang op die omgevingsvariabele. Een vlag met
> `requiresRestart: true` wordt onmiddellijk opgeslagen, maar alleen opnieuw ingelezen wanneer het proces
> wordt gestart — als deze wordt omgeschakeld, verschijnt in het dashboard een banner **"Server opnieuw starten"**.

76 vlaggen verdeeld over 6 categorieën. **Standaard** is de standaardwaarde van de definitie — de waarde
die wordt gebruikt wanneer er geen database-override of omgevingsvariabele aanwezig is.

## Functievlaggen in- en uitschakelen

### Dashboard

Navigeer naar **Dashboard → Instellingen → Functievlaggen**
(`/dashboard/settings/feature-flags`). Het raster
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
ondersteunt:

- **Zoeken** op sleutel of beschrijving en **filteren** op categorie (plus een synthetische
  weergave **Opnieuw opstarten vereist**).
- Een **schakelaar** voor booleaanse vlaggen en een **vervolgkeuzelijst** voor enum-vlaggen
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- Een **bronbadge** per vlag — `DB`, `ENV` of `DEF` — die aangeeft waar de
  effectieve waarde vandaan kwam.
- Een knop **Opnieuw instellen** (alleen weergegeven voor vlaggen met `DB` als bron) om de overschrijving
  te verwijderen, en onderaan een knop **Alle overschrijvingen opnieuw instellen**.
- Een banner **Server opnieuw opstarten** wanneer een vlag met `requiresRestart` wordt gewijzigd.

### REST-API

Alle bewerkingen verlopen via één route:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Elke methode vereist een geauthenticeerde dashboardsessie (anders `401`).

#### `GET /api/settings/feature-flags`

Retourneert elke vlag met de effectieve waarde, bron en een samenvatting.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... alle 75 vlaggen
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Stel één overschrijving in of verwijder deze. Body: `{ key: string; value?: string }`.
Als `value` wordt weggelaten, wordt de overschrijving verwijderd (waarmee de env-waarde /
standaardwaarde wordt hersteld).

```bash
# Een DB-overschrijving instellen
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# De overschrijving verwijderen (geen "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Het antwoord bevat de nieuwe `effectiveValue`/`source`, de `previousValue`/
`previousSource` en `requiresRestart`. Onbekende sleutels en enum-waarden buiten het toegestane bereik
worden geweigerd met `400`.

#### `DELETE /api/settings/feature-flags`

Verwijdert **alle** DB-overschrijvingen in één keer, zodat elke vlag wordt hersteld naar de bijbehorende env-waarde /
standaardwaarde. Retourneert `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> Vlaggen met `requiresRestart: true` worden pas van kracht nadat het proces opnieuw is geladen.
> De herstartprocedure van het dashboard roept `POST /api/restart` aan en voert vervolgens herhaaldelijk
> `GET /api/health/ping` uit totdat de server weer beschikbaar is.

## Noodfallback voor budgetten

`OMNIROUTE_EMERGENCY_FALLBACK` (categorie `runtime`, standaardwaarde `true`) beheert het
gratis noodfallbackpad in
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Wanneer dit is ingeschakeld, worden verzoeken die hun budget opgebruiken doorgestuurd naar een gratis fallbackprovider/-model,
in plaats van direct te mislukken. Stel dit in op `false` (of `0`) — via de
schakelaar in het dashboard, een DB-overschrijving of de omgevingsvariabele `OMNIROUTE_EMERGENCY_FALLBACK`
— om dit gedrag uit te schakelen en verzoeken waarvan het budget is opgebruikt
te laten mislukken. (Als dashboardschakelaar beschikbaar gemaakt in PR's #3741 / #3752.)
