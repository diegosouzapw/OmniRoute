Sommige services werden in OmniRoute geïntegreerd en later verwijderd omdat de beheerders
ervan daarom vroegen. Deze pagina is het permanente register van die verwijderingen. Het enige
doel ervan is te voorkomen dat ze per ongeluk terugkomen: een bijdrager die een oude fork, een
gecachete npm-tarball, een gearchiveerd issue of een verzoek om "provider X te herstellen"
vindt, heeft één plek nodig waarop staat: **niet opnieuw introduceren**.

Deze pagina is **geen** lijst van opgeheven of beëindigde services. Die worden bijgehouden in
[`FREE_TIERS.md`](FREE_TIERS.md) ("Verwijderd / geen gratis niveau") en kunnen terugkomen als
de service dat ook doet. De onderstaande vermeldingen kunnen alleen terugkomen met schriftelijke
toestemming van de in het verzoek genoemde beheerder, en vanuit de vermelding moet naar die
toestemming worden gelinkt.

## Beleid

1. **Een verwijderingsverzoek van een servicebeheerder wordt gehonoreerd, niet ter discussie
   gesteld.** OmniRoute is niet verbonden aan enige bovenliggende service. Wanneer de beheerder
   van een service vraagt om de integratie te verwijderen, wordt die verwijderd, ongeacht of
   de integratie een officiële API gebruikte.
2. **"Verwijderd" betekent van elk oppervlak waarover OmniRoute zeggenschap heeft.** Executor,
   registervermelding, provider-id en alias, modellenlijst, endpoints, omgevingsvariabelen,
   pictogram, dashboardkaarten, de gegenereerde providerreferentie, `FREE_TIERS.md`, de
   omgevingsreferentie, aantallen in de README, `llm.txt`-spiegels, specifieke tests en gouden
   snapshots, codecommentaar, CHANGELOG-punten (met een geregistreerde reconciliatie, zie
   `config/release/changelog-reconciliations.json`), GitHub Releases-opmerkingen, de wiki en de
   GitHub-issues, -discussies en pull requests waarvan die provider het onderwerp was (issues en
   discussies worden verwijderd; pull requests krijgen een nieuwe titel, hun beschrijving
   wordt vervangen en de thread wordt vergrendeld, omdat GitHub pull requests niet kan
   verwijderen).
3. **Introduceer een vermelding op deze pagina nooit opnieuw zonder schriftelijke toestemming.**
   Dit omvat ook het opnieuw toevoegen van de id of alias aan een providercatalogus, het
   toevoegen van de domeinen aan een executor, het accepteren van een PR van een bijdrager die
   de provider "herstelt", het toevoegen ervan aan de catalogus met gratis modellen of het
   documenteren van een handmatige manier om de service via OmniRoute te bereiken. Sluit
   dergelijke PR's en issues met een link naar deze pagina.
4. **Houd de vermelding minimaal.** Leg alleen vast wat een reviewer nodig heeft om een
   herintroductie te herkennen: identifiers, domeinen, datums en de pull request waarmee de
   verwijdering is uitgevoerd. Beschrijf niet hoe de integratie werkte.
5. **De regressiebeveiliging is `tests/unit/removed-providers-blocklist.test.ts`.** Deze faalt
   wanneer een van de onderstaande identifiers of domeinen opnieuw voorkomt in de
   providercatalogi, de executor-toewijzing of de bronbestanden van het providerregister. Voeg
   de nieuwe identifiers toe aan die test in dezelfde PR waarin hier een rij wordt toegevoegd.

## Een vermelding toevoegen

Wanneer een nieuw verwijderingsverzoek binnenkomt:

1. Bevestig dat het verzoek afkomstig is van de beheerder van de service (via diens
   supportadres of een domein waarover diegene zeggenschap heeft) en bewaar het bericht
   privé.
2. Verwijder de integratie volgens de checklist in beleidspunt 2. Gebruik
   [#12440](https://github.com/diegosouzapw/OmniRoute/pull/12440) als referentie voor een
   provider zonder sleutel en [#10210](https://github.com/diegosouzapw/OmniRoute/pull/10210)
   voor een provider met API-sleutel en opgeslagen verbindingen (voeg een migratie toe).
3. Voeg in dezelfde PR één rij toe aan de bovenstaande tabel en de identifiers aan
   `tests/unit/removed-providers-blocklist.test.ts`.
4. Antwoord de beheerder zodra de PR is gemerged, met een opsomming van wat is verwijderd en
   wat OmniRoute niet kan wijzigen (reeds gepubliceerde npm- en Docker-versies, git-geschiedenis,
   forks van derden).
