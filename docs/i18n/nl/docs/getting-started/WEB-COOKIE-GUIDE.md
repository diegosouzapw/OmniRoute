Web Cookie-providers laten OmniRoute een AI-service gebruiken via je bestaande browsersessie in plaats van via een API-sleutel. Ze zijn handig wanneer je al via de website toegang hebt tot een service en je wilt dat OmniRoute dezelfde geauthenticeerde sessie gebruikt.

In tegenstelling tot providers met een API-sleutel verifiëren Web Cookie-providers je identiteit met de aanmeldgegevens die je browser naar de website verzendt.

---

# Voordat je begint

> **Belangrijk:** Kopieer aanmeldgegevens altijd uit een **live netwerkverzoek**, **niet** uit de cookieopslag van je browser.

Veel verificatieproblemen worden veroorzaakt doordat cookies vanaf de verkeerde locatie worden gekopieerd.

## Kopieer NIET uit de cookieopslag

De meeste browsers tonen opgeslagen cookies via:

```
DevTools
→ Application (of Storage)
→ Cookies
```

Hoewel deze cookies correct lijken, kunnen ze:

- verouderd zijn
- onvolledig zijn
- cookies missen die alleen bij geauthenticeerde verzoeken worden verzonden

Het gebruik van deze waarden kan tot verificatiefouten leiden, zelfs als ze geldig lijken.

## Kopieer uit een live verzoek

Gebruik in plaats daarvan de cookies uit een geslaagd verzoek:

```
DevTools
→ Network
→ Vernieuw de pagina
→ Open een chat- of gespreksverzoek
→ Request Headers
→ Cookie
```

De `Cookie`-requestheader bevat exact de verificatiegegevens die je browser met succes heeft gebruikt.

Voor de meeste Web Cookie-providers is dit de waarde die je in OmniRoute moet plakken.

---

# Algemene configuratie

Het configuratieproces is voor de meeste Web Cookie-providers hetzelfde.

1. Meld je aan op de website van de provider.
2. Open de ontwikkelaarstools van de browser.
3. Open het tabblad **Network**.
4. Vernieuw de pagina.
5. Open een geauthenticeerd chat- of gespreksverzoek.
6. Kopieer de vereiste verificatiegegevens.
7. Open OmniRoute.
8. Ga naar **Providers → Add Provider**.
9. Selecteer je Web Cookie-provider.
10. Plak de aanmeldgegevens.
11. Klik op **Test Connection**.
12. Sla de provider op.

Welke aanmeldgegevens precies vereist zijn, hangt af van de provider.

# Wat Web Cookie-providers wel en niet kunnen

Web Cookie-providers hergebruiken de chatinterface van een website. Ze bieden **niet** dezelfde mogelijkheden als officiële API's.

## Ondersteund

- Verificatie via je bestaande browsersessie
- Toegang tot modellen die via je account beschikbaar zijn
- Chatantwoorden streamen
- Geen API-sleutel vereist

## Niet ondersteund

- Functies aanroepen
- Tools aanroepen
- Automatische bestandsbewerking
- Agentische IDE-workflows
- Functies die alleen via de API beschikbaar zijn

Dit is het verwachte gedrag en is **geen** bug.

Als je tools wilt uitvoeren, bestanden automatisch wilt bewerken of andere agentworkflows nodig hebt, gebruik dan een **provider met een API-sleutel** in plaats van een Web Cookie-provider.

---

# Kanttekening bij validatie

Een geslaagde **Test Connection** of cookievalidatie controleert alleen of de opgegeven aanmeldgegevens de verwachte indeling lijken te hebben.

Totdat Issue #7857 is opgelost, biedt een geslaagde validatie **geen garantie** dat de provider zich met succes kan verifiëren.

Als de verificatie nog steeds mislukt, controleer dan of je de aanmeldgegevens uit een live netwerkverzoek hebt gekopieerd en niet uit de cookieopslag van de browser.

---

# Problemen oplossen

## Verificatie mislukt

Controleer of de aanmeldgegevens zijn gekopieerd uit:

```
Network
→ Request Headers
→ Cookie
```

en **niet** uit:

```
Application
→ Cookies
```

---

## Cookie werkt in de browser, maar niet in OmniRoute

Sommige providers gebruiken cookies die alleen tijdens geauthenticeerde verzoeken worden verzonden.

Kopieer de aanmeldgegevens opnieuw uit een recent netwerkverzoek nadat je met succes een gesprek hebt geopend.

---

## Sessie verlopen

Web Cookie-providers gebruiken je bestaande browsersessie.

Als je browsersessie verloopt of je je afmeldt, moet je een nieuwe set aanmeldgegevens kopiëren.

---

## Test Connection slaagt, maar verzoeken mislukken

Totdat Issue #7857 is opgelost, biedt een geslaagde validatie geen garantie dat het verificatieverzoek zal slagen.

Kopieer je aanmeldgegevens opnieuw uit een recent geauthenticeerd verzoek voordat je verdergaat met het oplossen van problemen.

# Aanbevolen werkwijzen

- Kopieer aanmeldgegevens uit een recent geauthenticeerd verzoek.
- Gebruik geen oude cookies opnieuw.
- Houd je browsersessie actief terwijl je Web Cookie-providers gebruikt.
- Behandel gekopieerde cookies als gevoelige aanmeldgegevens.
- Gebruik providers met een API-sleutel wanneer je functies wilt aanroepen of agentworkflows nodig hebt.
