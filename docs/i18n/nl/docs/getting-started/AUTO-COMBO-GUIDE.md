> **TL;DR**: Stel je model in op `auto` en OmniRoute kiest automatisch de beste AI-provider voor elke aanvraag. Geen configuratie nodig.

---

## Wat het doet

In plaats van een specifiek AI-model te kiezen (zoals GPT-4o of Claude), kun je OmniRoute voor elke aanvraag **automatisch het beste model laten kiezen**. Het houdt rekening met:

- **Status** — Werkt de provider op dit moment?
- **Snelheid** — Hoe snel is deze?
- **Kosten** — Hoeveel kost deze?
- **Kwaliteit** — Is deze geschikt voor dit type taak?
- **Capaciteit** — Is er nog quotum beschikbaar?

OmniRoute beoordeelt al je verbonden providers en kiest de beste. Als die niet werkt, probeert het automatisch de volgende.

---

## Snel aan de slag

**Stap 1**: Stel je model in je IDE of CLI in op `auto`:

```
model: "auto"
```

**Stap 2**: Dat is alles! OmniRoute doet de rest.

**Stap 3** (optioneel): Gebruik een variant voor specifieke taken:

```
model: "auto/coding"    # Het beste voor code
model: "auto/fast"      # Snelste antwoord
model: "auto/cheap"     # Goedkoopste optie
```

## Welke "auto" moet ik gebruiken?

| Als je dit wilt...        | Gebruik dit    | Het beste voor                   | Hoe het werkt                               |
| ------------------------- | -------------- | -------------------------------- | ------------------------------------------- |
| **Beste in het algemeen** | `auto`         | Algemene vragen, chat            | Balanceert snelheid, kosten en kwaliteit    |
| **Beste code**            | `auto/coding`  | Code schrijven, fouten opsporen  | Kiest modellen die goed zijn in codeertaken |
| **Snelste antwoord**      | `auto/fast`    | Snelle antwoorden, lage latentie | Geeft prioriteit aan snelheid boven alles   |
| **Goedkoopste optie**     | `auto/cheap`   | Geld besparen                    | Kiest de goedkoopste provider               |
| **Slimste model**         | `auto/smart`   | Complexe taken                   | Kwaliteit eerst + verkent nieuwe modellen   |
| **Meest beschikbaar**     | `auto/offline` | Wanneer providers bezet zijn     | Kiest providers met de meeste capaciteit    |

### Voorbeelden

```bash
# Algemene chat — gebalanceerd
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'

# Code genereren — kwaliteit eerst
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/coding","messages":[{"role":"user","content":"Write a Python function"}]}'

# Snel antwoord — snelheid eerst
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/fast","messages":[{"role":"user","content":"What is 2+2?"}]}'
```

## Hoe het werkt (eenvoudige versie)

Wanneer je een aanvraag verstuurt met `model: "auto"`, doet OmniRoute het volgende:

1. **Het bekijkt al je verbonden providers** — Elke provider die je hebt toegevoegd (OpenAI, Anthropic, Google enzovoort)
2. **Het beoordeelt elke provider** en weegt daarbij onder andere mee:
   - Werkt deze? (status)
   - Heeft deze capaciteit? (quotum)
   - Hoeveel kost deze? (prijs)
   - Hoe snel is deze? (snelheid)
   - Is deze geschikt voor deze taak? (kwaliteit)
3. **Het kiest de beste** — De provider met de hoogste score krijgt je aanvraag
4. **Het herstelt automatisch** — Als de provider niet werkt, probeert OmniRoute automatisch de volgende

### Het scoresysteem

Elke provider krijgt een score van 0 tot 1. Hoe hoger de score, hoe beter de provider geschikt is.

| Factor      | Gewicht | Wat het betekent                                   |
| ----------- | ------- | -------------------------------------------------- |
| Status      | 20%     | Werkt de provider? (status van de circuit breaker) |
| Quotum      | 15%     | Is er nog capaciteit beschikbaar?                  |
| Kosten      | 15%     | Hoe duur is deze? (goedkoper = hogere score)       |
| Snelheid    | 12%     | Hoe snel is deze? (lagere latentie = hogere score) |
| Taakmatch   | 8%      | Is deze geschikt voor dit type taak?               |
| Stabiliteit | 5%      | Is deze consistent? (laag foutenpercentage)        |
| Niveau      | 5%      | Accountniveau (Ultra > Pro > Free)                 |
| Overige     | 20%     | Contextaffiniteit, verbindingsdichtheid enzovoort  |

### Hoe varianten de beoordeling veranderen

Elke variant gebruikt andere gewichten:

| Variant        | Geeft prioriteit aan   | Belangrijkste gewichten         |
| -------------- | ---------------------- | ------------------------------- |
| `auto`         | Balans                 | health=20%, quota=15%, cost=15% |
| `auto/coding`  | Kwaliteit              | taskFit=37%, stability=15%      |
| `auto/fast`    | Snelheid               | latency=32%, health=28%         |
| `auto/cheap`   | Kosten                 | cost=37%                        |
| `auto/smart`   | Kwaliteit + verkenning | taskFit=37%, exploration=10%    |
| `auto/offline` | Capaciteit             | quota=37%, health=28%           |

## Hoe het omgaat met storingen

OmniRoute heeft **drie beschermingslagen**:

### 1. Automatische fallback

Als de beste provider uitvalt, probeert OmniRoute automatisch de volgende. Je hoeft niets te doen.

### 2. Zelfherstel

Als een provider blijft uitvallen:

- **Score < 0.2** → 5 minuten uitgesloten
- **Circuitbreaker open** → Automatisch uitgesloten
- **Meer dan 50% van de providers uitgevallen** → Incidentmodus (geen verkenning)

### 3. Noodfallback

Als alle providers uitvallen, routeert OmniRoute als laatste redmiddel naar stabiele gratis providers (zoals Kiro of Qoder).

---

## Ondersteuning voor meerdere accounts

Als je meerdere accounts voor dezelfde provider hebt (bijvoorbeeld twee OpenAI-sleutels), behandelt OmniRoute elk account als een **afzonderlijke kandidaat**. Dit betekent:

- Account A heeft nog quotum over → gebruiken
- Account B heeft een snelheidslimiet bereikt → overslaan
- Account C is goedkoper → voorkeur geven

Elk account wordt onafhankelijk beoordeeld op basis van de eigen status, het quotum en de snelheid.

---

## Bandit-verkenning

OmniRoute **verkent** af en toe nieuwe providers om betere opties te ontdekken:

- **Standaard**: 5% van de aanvragen gaat naar willekeurige providers
- **Auto/smart**: verkenningspercentage van 10%
- **Uitgeschakeld** wanneer meer dan 50% van de providers ongezond is

Dit helpt OmniRoute te leren welke providers het beste werken voor jouw gebruikspatronen.

## Veelgestelde vragen

### "Kiest het altijd het duurste model?"

**Nee.** Kosten bepalen standaard slechts 15% van de score. Een goedkope, snelle en gezonde provider kan beter scoren dan een dure. Gebruik `auto/cheap` als je kosten nog meer prioriteit wilt geven.

### "Wat gebeurt er als een provider uitvalt?"

OmniRoute slaat deze automatisch over en probeert de volgende. Als een provider blijft uitvallen, wordt deze tijdelijk uitgesloten (5-30 minuten). Je hoeft niets te doen.

### "Kan ik zien welke provider is gebruikt?"

Controleer de responseheaders — OmniRoute vermeldt in elke response welke provider en welk model zijn gebruikt.

### "Leert het van mijn gebruik?"

Ja! Het scoresysteem gebruikt historische gegevens (latentie, foutpercentages en succespercentages) om in de loop van de tijd betere beslissingen te nemen.

### "Wat is het verschil tussen `auto` en `auto/smart`?"

- `auto` — Evenwichtig, 5% verkenning
- `auto/smart` — Kwaliteit voorop (dezelfde wegingen als `auto/coding`), 10% verkenning

Gebruik `auto/smart` wanneer je de beste kwaliteit wilt en incidentele verkenning geen probleem vindt.

### "Kan ik een specifieke provider afdwingen?"

Ja! Gebruik een combinatie met de strategie `priority` in plaats van `auto` en stuur vervolgens de **exacte naam** van de combinatie als het veld `model` (bijvoorbeeld `model: "my-combo"` — niet `auto`). Zie de [Technische referentie](../routing/AUTO-COMBO.md) voor meer informatie.

### "Hoe verschilt dit van round-robin?"

Round-robin doorloopt providers op volgorde. Auto-combo **geeft elke provider een score** en kiest de beste. Het is slimmer — het houdt rekening met status, snelheid, kosten en kwaliteit.
