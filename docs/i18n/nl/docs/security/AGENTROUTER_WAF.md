De upstreamgateway `agentrouter` voert een op trefwoorden gebaseerd inhoudsfilter uit op
`messages[].content`. Het filter is deels deterministisch (blokkeert altijd
bepaalde woordgroepen) en deels probabilistisch (gevoelig voor piekbelasting — wordt
agressiever na snel opeenvolgende verzoeken en herstelt na een afkoelperiode).

Wanneer de WAF een verzoek blokkeert, retourneert deze:

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## Bereik van het filter

De WAF inspecteert alleen `messages[].content`. Deze inspecteert **niet**:

- De `system`-prompt
- Gestructureerde inhoudsblokken (`tool_result`, `tool_use`, `thinking`, `image`)
- De velden `description` en `input_schema` van tools
- Metadata van verzoeken, headers of model-id

## Altijd geblokkeerde patronen (hoofdletterongevoelig)

| Patroon                        | Opmerkingen                                                       |
| ------------------------------ | ----------------------------------------------------------------- |
| Elke variant van `Lorem ipsum` | De volledige Latijnse lorem-woordenschat wordt geblokkeerd        |
| `language model` (zelfstandig) | "the language model" en "large language model" worden doorgelaten |
| `virtual assistant`            | "AI assistant" wordt doorgelaten                                  |
| `I'm here to help`             | Alleen "here to help" wordt ook geblokkeerd                       |
| `Claude, made by Anthropic`    | Alleen de volledige woordgroep                                    |

## Bijna altijd geblokkeerde patronen

| Patroon                                                  | Opmerkingen                                                    |
| -------------------------------------------------------- | -------------------------------------------------------------- |
| `placeholder`                                            | Wanneer het zelfstandig voorkomt (niet als parameternaam enz.) |
| `dummy data`                                             | Veelgebruikte seed-woordgroep voor fixtures                    |
| `foo bar baz`                                            | Canonieke placeholder-woordgroep                               |
| Herhaalde korte tokens (`AAA BBB CCC`, `test test test`) | Detector voor keyword stuffing                                 |

## Gedrag onder belasting

Na ongeveer 5 snel opeenvolgende verzoeken binnen een kort tijdsvenster begint de WAF inhoud
te blokkeren die normaal gesproken zou worden doorgelaten. De bucket wordt na ongeveer 5–10 seconden
inactiviteit weer minder streng. Dit is dezelfde aan IP en sleutel gekoppelde rate limiter die
incidentele `400 content-blocked`-fouten veroorzaakt wanneer Claude Code of Codex CLI
meerdere tool-use-/message-send-aanroepen snel achter elkaar uitvoert.

## Reeds toegepaste oplossingen in OmniRoute

1. **`open-sse/services/wafRateLimit.ts`** — een piekbeveiliging die een
   minimale tussenpauze van 500 ms afdwingt tussen uitgaande verzoeken naar elke `agentrouter:*`-
   URL. Deze tussenpauze ligt ruim onder de voor mensen waarneembare latentie en voorkomt
   dat de WAF bij normaal verkeer wordt geactiveerd.

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — wanneer een upstream
   `400 content-blocked` retourneert, probeert de executor dezelfde URL opnieuw met
   exponentiële back-off (1,5 s, 3,0 s, maximaal 2 pogingen). Na de back-off
   is de WAF meestal weer minder streng en slaagt de nieuwe poging.

3. **`tests/unit/compression/harness.test.ts`** — de testfixture
   `longInput` is gewijzigd van `"lorem ipsum dolor sit amet ".repeat(40)`
   naar `"example content for testing purposes ".repeat(40)`, zodat wanneer
   Claude Code dit bestand via de tool `Read` leest, de bestandsinhoud
   niet via een `tool_result`-blok terugstroomt en de WAF activeert.

## Richtlijnen voor prompts en tooluitvoer

Als een Claude Code- of Codex CLI-sessie herhaaldelijk op
`400 content-blocked` stuit, controleer dan het meest recente gebruikersbericht en het meest
recente toolresultaat op een van de bovenstaande patronen en herformuleer de inhoud. Veelgebruikte
oplossingen:

- Vervang `Lorem ipsum …` door `example text …` of door de daadwerkelijke inhoud
  die de test of fixture probeert te modelleren.
- Vervang `placeholder` (wanneer het zelfstandig voorkomt) door `example value`,
  `sample value` of de werkelijke waarde.
- Vervang `language model` door `large language model` of `the model`.
- Vervang `dummy data` door `sample data` of realistische seedwaarden.
- Vervang `I'm here to help` / `here to help` door een specifiekere
  openingszin (bijv. "I'll review the file you mentioned").

## De fout-positieven upstream melden

Het huidige filter is te agressief — het blokkeert "Lorem ipsum" in
`tool_result`-blokken, hoewel de operator duidelijk niet van plan was om
een prompt te injecteren. Operators die willen dat dit bij de bron wordt opgelost, moeten
contact opnemen met `agentrouter.org` om de fout-positieven te melden. De bovenstaande blokkeerlijst
is het empirische resultaat van het testen van de upstream op 2026-08-03.
