> **TOML is de enige effectieve indeling.** Moderne versies van Codex lezen uitsluitend
> `~/.codex/config.toml` (geverifieerd met codex-cli 0.147.0: `codex --help`
> documenteert `-c/--config`-overschrijvingen die worden geladen vanuit
> `~/.codex/config.toml`). Het oude `~/.codex/config.yaml` behoorde toe aan de
> verouderde npm-CLI en wordt stilzwijgend genegeerd. De dashboardgenerator
> (`/api/cli-tools/apply`, tool `codex`) schrijft TOML met een conservatieve
> samenvoeging — bestaande sleutels en andere providerblokken blijven behouden,
> de API-sleutel blijft in `OMNIROUTE_API_KEY` (nooit in het bestand) en een
> achtergebleven verouderd `config.yaml` wordt als migratieopmerking gemeld
> zonder te worden gewijzigd.

## Direct te plakken config.toml

Vervang `<YOUR_HOST>` en `<YOUR_KEY>` door je eigen waarden:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # opslaglimiet voor geschiedenis per toolaanroep

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc of ~/.zshrc — daadwerkelijke sleutelwaarde, nooit in config.toml
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: Codex gebundeld in de ChatGPT-app

Als je Codex via de ChatGPT-desktopapp hebt geïnstalleerd, bevindt het
`codex`-binaire bestand zich mogelijk alleen in de appbundel en nog niet in je
shell-`PATH`. Voeg de resourcemap toe aan het opstartbestand van je shell:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

Open een nieuwe shell en controleer vervolgens:

```bash
command -v codex
codex --version
```

### Lokale OmniRoute zonder authenticatie: een tijdelijke sleutel volstaat

Codex controleert of de door `env_key` aangeduide omgevingsvariabele bestaat
**voordat** het eerste verzoek de CLI verlaat. Als je **lokale** OmniRoute-
instantie geen authenticatie vereist, werkt elke niet-lege tijdelijke waarde:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

Gebruik in plaats daarvan een echte sleutel wanneer je OmniRoute-server
beveiligd of extern is.

> **Veelgebruikte hostopties**
>
> | Toegang        | URL                           |
> | -------------- | ----------------------------- |
> | Lokaal netwerk | `http://192.168.0.1:20128/v1` |
> | Tailscale      | `http://100.x.x.x:20128/v1`   |
> | Loopback       | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — waarom dit voor alle modellen werkt

Codex CLI heeft `wire_api = "chat"` (Chat Completions) in februari 2026
afgeschaft en **vereist** nu `wire_api = "responses"` (OpenAI Responses API).
Het instellen van `wire_api = "chat"` veroorzaakt sinds v0.138 onmiddellijk
een crash tijdens het opstarten.

Veel providers, waaronder GLM en Kimi, bieden nog steeds alleen een Chat
Completions-endpoint aan. DeepSeek V4 biedt nu zowel een native Responses API
als een Anthropic-compatibel endpoint; OmniRoute gebruikt standaard Responses
en laat voor elke DeepSeek-verbinding Anthropic-compatibiliteit selecteren.

**OmniRoute lost dit transparant op:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute selecteert het native protocol van de provider en vertaalt waar nodig
    → POST /responses (DeepSeek V4) of /chat/completions (Mistral / GLM / Kimi / overige)
```

Wanneer je OmniRoute gebruikt, heb je nooit een afzonderlijke vertaalproxy
nodig. **Alle modellen gebruiken `wire_api = "responses"`** — OmniRoute
verwerkt de rest.

> **`wire_api` is de standaardwaarde** — het veld is standaard ingesteld op
> `"responses"` en kan volledig uit `config.toml` worden weggelaten. Stel het
> alleen expliciet in als je de bedoeling wilt documenteren.

## Contextvenster en compactie

### Velden voor tokenconfiguratie

| Veld                             | Beschrijving                                                                                                                                                                                                                                    |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model_context_window`           | Totaal tokenbudget voor het actieve model. Stel dit in op de opgegeven limiet van het model.                                                                                                                                                    |
| `model_auto_compact_token_limit` | Drempelwaarde die automatische compactie van de geschiedenis activeert. **Maximum: 90% van `model_context_window`** — waarden boven 90% worden stilzwijgend genegeerd.                                                                          |
| `tool_output_token_limit`        | Limiet voor het aantal tokens dat per uitvoer van een toolaanroep in de geschiedenis wordt opgeslagen. Voorkomt dat één grote toolrespons het venster vult. **Dit is niet de maximale uitvoer** — het is een opslaglimiet voor de geschiedenis. |
| `compact_prompt`                 | Inline overschrijving van de systeemprompt die tijdens compactie wordt gebruikt (v0.138+).                                                                                                                                                      |

> **Opmerking over `model_max_output_tokens`**: Dit veld maakt **geen deel uit van het configuratieschema van de Codex CLI** (het ontbreekt in de Rust-codebase van Codex). Het wordt stilzwijgend genegeerd als het is ingesteld. Vertrouw er niet op — gebruik `tool_output_token_limit` om te bepalen hoeveel tooluitvoer in de geschiedenis wordt opgeslagen.

| ----------------------- | ------------------ |
| `cx/gpt-5.5`            | GPT-5.5 standaard  |

## Redeneerinspanning

Bepaalt hoeveel het model „denkt” voordat het antwoordt.

| Waarde   | Gebruiken voor                                          |
| -------- | ------------------------------------------------------- |
| `none`   | Geen redenering — direct antwoord                       |
| `low`    | Triviale taken (hernoemen, formatteren)                 |
| `medium` | **Standaardwaarde van de server** indien niet opgegeven |
| `high`   | Taken van gemiddeld niveau (refactoring, debuggen)      |
| `xhigh`  | Architectuur, diepgaande analyse, complexe problemen    |

```bash
# Overschrijven per aanroep
codex -c model_reasoning_effort=low "rename variable x to count"
codex -c model_reasoning_effort=xhigh "design the auth module"
```

Stel ook een **samenvatting** van de redenering in, zodat Desktop de gedachtetekst kan weergeven (en niet alleen versleutelde blobs):

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # of ultra indien ondersteund
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### OmniRoute-denkbudget (serverinstelling)

Op de OmniRoute-host moet **Settings → AI → Thinking Budget** zijn ingesteld op **`passthrough`**, zodat de inspanning/samenvatting van Codex stroomopwaarts wordt doorgegeven. De modus **`auto` verwijdert** alle `reasoning`- / `reasoning_effort`-velden van de client en maakt denkpanelen leeg, zelfs wanneer Codex correct is geconfigureerd.

Volledige handleiding: [THINKING_BUDGET.md](./THINKING_BUDGET.md).

Compressie en promptcache zijn onafhankelijk en blijven werken met `passthrough`.

## Profielen — benoemde configuraties per model/workflow

Met profielen kunt u met één vlag van model en contextvenster wisselen. Elk profiel is een plat
`~/.codex/<name>.config.toml`-bestand dat boven op het basisbestand `config.toml` wordt toegepast.

> **Naamgevingsregel (Codex CLI v0.137+):** het bestand moet `~/.codex/<name>.config.toml` heten — **zonder het voorvoegsel `profile-`**.
> De CLI zet `-p kimi-k27` om naar `~/.codex/kimi-k27.config.toml`. Als het bestand niet wordt gevonden, wordt stilzwijgend de standaardinstelling toegepast.

```bash
codex --profile kimi-k27 "analyze 10k lines of this codebase"
codex -p glm52 "architecture review"
codex --profile deepseek-flash "rename variable"   # snel, goedkoop
```

### Inspanningsprofielen (hetzelfde model, verschillende inspanning)

```bash
codex -p low      # cx/gpt-5.5, inspanning=low
codex -p medium   # cx/gpt-5.5, inspanning=medium
codex -p high     # cx/gpt-5.5, inspanning=high
codex -p xhigh    # cx/gpt-5.5, inspanning=xhigh (standaard)
codex -p chat     # cx/gpt-5.5, geen inspanning ingesteld (serverstandaard)
```

## Automatisch profielen genereren met `omniroute setup-codex`

Als u OmniRoute op een VPS uitvoert, kunt u automatisch profielbestanden genereren op basis van de actuele modelcatalogus:

```bash
# Vanaf een VPS (gebruikt lokale OmniRoute op poort 20128)
omniroute setup-codex

# Vanaf elke machine — verwijs naar uw VPS
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# Voorbeeld bekijken zonder bestanden te schrijven
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# Alleen GLM- en Kimi-profielen genereren
omniroute setup-codex --only glm,kimi

# Naar een aangepaste map schrijven
omniroute setup-codex --codex-home /path/to/.codex
```

De opdracht haalt `/v1/models` op, gebruikt geoptimaliseerde profielen voor bekende modellen, valt voor andere compatibele tekstmodellen terug op catalogusmetadata en schrijft voor elk model `~/.codex/<name>.config.toml`. Idempotent — kan veilig opnieuw worden uitgevoerd.

OmniRoute kan dezelfde profielbestanden ook **automatisch synchroniseren** nadat een geslaagde detectie/import van providermodellen de actuele catalogus heeft gewijzigd. Dit is **optioneel en standaard uitgeschakeld**: schakel het in via het **CLI Code-dashboard** ("Automatische synchronisatie van CLI-profielen" → Codex), of stel `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` in (ook `CLI_ALLOW_CONFIG_WRITES` wordt gerespecteerd, standaard ingeschakeld). Wanneer deze functie is ingeschakeld, schrijft deze alleen afzonderlijke profielbestanden in `~/.codex/*.config.toml`; de actieve/standaardconfiguratie in `~/.codex/config.toml`, Codex-lb-instellingen, authenticatie of providerselectie worden nooit gewijzigd.

## Codex starten met `omniroute launch-codex`

Controleert de status van uw OmniRoute-instance voordat Codex wordt gestart:

```bash
# Starten met lokale OmniRoute (standaardpoort 20128)
omniroute launch-codex

# Starten met een specifiek profiel
omniroute launch-codex --profile kimi-k27

# Starten met een externe VPS
```

## Langlopende taken

Twee standaardinstellingen van OmniRoute kunnen urenlange Codex CLI-sessies ongemerkt saboteren. Geen van beide is een Codex CLI-instelling — ze bevinden zich allebei aan de OmniRoute-zijde. Gebruikers die een configuratie migreren van upstream-proxy's die accounts vastzetten en time-outs bij inactiviteit uitschakelen, lopen vaak tegen beide problemen aan en concluderen dat OmniRoute „geen lange sessie kan volhouden”.

| Symptoom                                                                                          | Waarschijnlijke oorzaak                                                                    | Instelling               |
| ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | ------------------------ |
| Sessie blijft van account wisselen / continuïteit van de promptcache gaat tussen beurten verloren | TTL voor sessieaffiniteit is `0` (uitgeschakeld)                                           | `sessionAffinityTtlMs`   |
| Verbinding wordt tijdens het redeneren verbroken zonder prompt aan de clientzijde                 | Watchdog voor inactieve streams is geactiveerd nadat er 10 minuten geen upstream-chunk was | `STREAM_IDLE_TIMEOUT_MS` |

Gerelateerde discussies: [#7126](https://github.com/diegosouzapw/OmniRoute/discussions/7126) (langlopende taken worden afgebroken), [#5718](https://github.com/diegosouzapw/OmniRoute/discussions/5718) (waarom affiniteit standaard is uitgeschakeld). Tracking: [#7287](https://github.com/diegosouzapw/OmniRoute/issues/7287).

### 1. Sessieaffiniteit — zet één gesprek vast op één account

**Standaard:** `sessionAffinityTtlMs = 0` (uitgeschakeld).

**Waar u dit instelt**

- Dashboard → **Instellingen → Routering** → **Sessieaffiniteit** → **Affiniteits-TTL (seconden)** (`ComboDefaultsTab`)
- Of PATCH de instellingen met `sessionAffinityTtlMs` in **milliseconden** (Zod-bereik `0`–`86_400_000`, oftewel maximaal 24 uur)

> In #7274 hernoemd van het uitsluitend voor Codex gebruikte `codexSessionAffinityTtlMs`. De verouderde sleutel wordt nog steeds geaccepteerd als alleen-lezen alias; nieuwe configuraties moeten `sessionAffinityTtlMs` gebruiken. Affiniteit is nu van toepassing op **elke** provider zodra de TTL hoger is dan `0`, niet alleen op Codex — zie [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → Sessieaffiniteit.

**Wat er misgaat wanneer deze op 0 blijft staan**

Elke beurt van een Codex-gesprek met meerdere beurten wordt onafhankelijk gerouteerd door de actieve combinatiestrategie en kan bij elke beurt op een **ander account** terechtkomen. Daardoor wordt de continuïteit van upstream-sessies en promptcaches verbroken. OmniRoute raadpleegt Codex-sessieheaders (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) en velden in de body, zoals `prompt_cache_key` / `session_id`, alleen wanneer de TTL groter is dan `0` (`extractSessionAffinityKey` in `src/sse/services/auth.ts`).

**Aanbevolen voor één taak die meerdere uren duurt**

Stel de TTL in op een waarde **boven de verwachte totale duur van de taak** (het maximum in de UI is **86400 seconden** = 24 uur):

| Verwachte taakduur  | Affiniteits-TTL (UI, seconden) | `sessionAffinityTtlMs` |
| ------------------- | ------------------------------ | ---------------------- |
| Enkele uren         | `14400` (4 uur)                | `14400000`             |
| Een nacht / ~12 uur | `43200` (12 uur)               | `43200000`             |
| Een volledige dag   | `86400` (24 uur, maximum)      | `86400000`             |

Opt-in is bewust gekozen: het uitschakelen van affiniteit bevordert taakverdeling over accounts; het inschakelen ervan bevordert continuïteit voor één lange agentsessie. Deze handleiding wijzigt de standaardinstelling **niet** — beheerders die langlopende Codex-taken uitvoeren, moeten dit zelf inschakelen.

### 2. Time-out voor inactieve streams — breek stille redeneerbeurten niet af

**Standaard:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 minuten). Wanneer deze niet is ingesteld, neemt deze de waarde over van `REQUEST_TIMEOUT_MS`; de gedeelde basiswaarde is eveneens 600000. Zie [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → Time-outs.

**Wat er bij de standaardinstelling misgaat**

Een Codex-reasoning-/toolbeurt die langer dan 10 minuten stil blijft zonder **enkele echte upstreamchunk**, wordt geforceerd beëindigd door de SSE-idlewatchdog (`open-sse/utils/stream.ts`). De client ziet vaak alleen dat de verbinding wordt verbroken — wat overeenkomt met “automatisch gestopt zonder enige melding”.

Cruciaal detail: OmniRoute’s synthetische SSE-**heartbeat stelt de idleklok niet opnieuw in**. Alleen een echte upstream-bodychunk werkt `lastChunkTime` bij. Een stil model dat nog steeds “nadenkt”, ziet er vanuit het perspectief van de watchdog hetzelfde uit als een vastgelopen upstream.

Gerelateerde Undici-body-inactiviteit: `FETCH_BODY_TIMEOUT_MS` (heeft standaard eveneens dezelfde basiswaarde van 10 minuten; `0` schakelt dit uit). Voor streaming dekt `FETCH_TIMEOUT_MS` alleen het opzetten van de verbinding / de eerste headers — zodra de stream actief is, worden onderbrekingen beheerd door `STREAM_IDLE_TIMEOUT_MS` en `FETCH_BODY_TIMEOUT_MS`.

**Aanbevolen voor één taak die meerdere uren duurt**

In de procesomgeving van OmniRoute (`.env` / compose / systemd):

```bash
# Schakel time-outs voor stream-idle en body-inactiviteit uit voor lange reasoningbeurten
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

Of verhoog ze tot boven de langste stille periode die je verwacht (waarden zijn in milliseconden):

```bash
# Voorbeeld: sta maximaal 2 uur stilte tussen upstreamchunks toe
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

Start OmniRoute opnieuw nadat je deze omgevingsvariabelen hebt gewijzigd.

### Concreet recept — Codex-taak van meerdere uren

1. **Zet het account vast:** Dashboard → Settings → Routing → Session affinity → Affinity TTL = `43200` (12 uur) of `86400` (maximaal 24 uur).
2. **Verhoog / schakel idlegrenzen uit** in de omgeving van OmniRoute:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. Behoud de gebruikelijke Codex-`config.toml` (`wire_api = "responses"`, correcte `base_url`, `OMNIROUTE_API_KEY`) — aan de Codex-kant bestaan geen instellingen voor affiniteit/idle voor deze twee gedragingen.
4. Start OmniRoute opnieuw en start daarna de langdurige Codex-taak.

### Besluit over standaardwaarden (#7287)

| Instelling               | Meegeleverde standaardwaarde | Wijzigen in deze handleiding?                                                                                          |
| ------------------------ | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (uit)                    | **Nee** — blijft opt-in (load balancing versus continuïteit; zie Discussion #5718)                                     |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 min)            | **Nee** — blijft 10 minuten voor algemeen verkeer; beheerders van langdurige Codex-taken verhogen of schakelen dit uit |

Het wereldwijd wijzigen van een van beide standaardwaarden zou het gedrag voor elke client van een instantie veranderen, niet alleen voor Codex. Documenteer de instellingen; laat de standaardwaarden ongewijzigd totdat een expliciete beslissing van de beheerder anders bepaalt.

### Idle-onderbrekingen diagnosticeren

Wanneer de idlewatchdog wordt geactiveerd, logt OmniRoute een regel met ongeveer deze vorm:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

Zoek met grep naar `Idle timeout: no data from` (of de code `stream_idle_timeout` / foutnaam `StreamIdleTimeoutError`). Het providersegment is de waarde die OmniRoute voor die aanvraag gebruikte (`codex`, een andere provider-id of `provider` als deze onbekend is) — dit is niet altijd letterlijk de tekenreeks `codex`.

## Problemen oplossen

**`Error: wire_api = "chat" is no longer supported`**
Verwijder `wire_api = "chat"` uit je configuratie. Stel `wire_api = "responses"` in of laat het veld weg (standaard is dit sinds v0.138 `"responses"`).

**`Error: model not found`**
Controleer of het model in OmniRoute bestaat met het juiste voorvoegsel. Gebruik `omniroute models list` of open `/dashboard/providers/<provider>`.

**`Authentication error`**
Controleer of `OMNIROUTE_API_KEY` is geëxporteerd: `echo $OMNIROUTE_API_KEY`.

**`ERROR: Missing environment variable: OMNIROUTE_API_KEY`**
Codex controleert vóór het eerste verzoek of de omgevingsvariabele bestaat. Exporteer
een echte sleutel voor beveiligde servers, of een niet-lege tijdelijke waarde zoals
`OMNIROUTE_API_KEY=local` wanneer je **lokale** OmniRoute-instantie geen
authenticatie vereist. Start de shell opnieuw als je deze aan `~/.bashrc` of `~/.zshrc` hebt toegevoegd.

**`Connection refused`**
Controleer of OmniRoute actief is en of de host/poort van `base_url` correct is voor je netwerk (lokaal versus Tailscale versus VPS).

**Sessie crasht wanneer de contextlimiet wordt benaderd**
Stel `model_context_window` en `model_auto_compact_token_limit` expliciet in. Zie de tabel met contextvensters hierboven.

**Compactie wordt te laat geactiveerd**
Verlaag `model_auto_compact_token_limit` tot 80–85% van het venster. Stel dit nooit hoger in dan 90%.

**Profiel wordt niet geladen (`-p <name>` wordt zonder melding genegeerd)**
Controleer of het bestand bestaat op `~/.codex/<name>.config.toml` (zonder het voorvoegsel `profile-`). Voer `ls ~/.codex/*.config.toml` uit.

**Langdurige Codex-taak wordt tussentijds afgebroken / wisselt tussen beurten van account**
Zie [Langdurige taken](#long-running-tasks). Schakel sessieaffiniteit in (TTL langer dan de taakduur) en verhoog of deactiveer `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS`. Doorzoek de OmniRoute-logboeken met grep naar `Idle timeout: no data from`.
