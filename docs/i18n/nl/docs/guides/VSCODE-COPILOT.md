**OmniCopilot** plaatst elk model dat je OmniRoute aanbiedt in de _native_ modelkiezer van GitHub Copilot Chat.
Geen tweede zijbalk, geen afzonderlijke chatinterface — Copilots agentmodus, het aanroepen van tools,
MCP-servers en aangepaste instructies blijven allemaal werken, maar dan op het model dat je kiest.

|                           |                                                                                                                                                 |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Installeren (VS Code)** | [Marketplace → `diegosouzapw.omnicopilot`](https://marketplace.visualstudio.com/items?itemName=diegosouzapw.omnicopilot)                        |
| **Installeren (forks)**   | [Open VSX](https://open-vsx.org/extension/diegosouzapw/omnicopilot) — Cursor, Windsurf, VSCodium, Theia, code-server, Gitpod, Antigravity, Kiro |
| **Broncode / issues**     | [github.com/diegosouzapw/OmniCopilot](https://github.com/diegosouzapw/OmniCopilot) (MIT)                                                        |
| **Vereist**               | VS Code 1.104+                                                                                                                                  |

> **Geen Copilot-abonnement nodig.** Sinds VS Code 1.122 werkt een taalmodelprovider
> zonder aanmelding bij GitHub en zonder Copilot-abonnement. Inline aanvullingen en
> functies op basis van embeddings vallen buiten de provider-API en vereisen nog steeds Copilot.

## Installatie

1. **Start OmniRoute** — `npm install -g omniroute && omniroute` (dashboard op `http://localhost:20128`).
2. **Installeer de extensie** — zoek naar "OmniRoute" in de extensieweergave.
3. **Kies een model** — Copilot Chat → modelkiezer → **Modellen beheren…** → **OmniRoute** en vink vervolgens
   aan wat je wilt.

Je hoeft niets te configureren wanneer OmniRoute op de standaardpoort draait. Open voor een externe instantie het
**OmniRoute-pictogram in de activiteitenbalk** (of voer `OmniRoute: Manage Connection` uit) en stel het volgende in:

- **Server-URL** — de hoofd-URL van de server, bijvoorbeeld `http://192.168.0.15:20128`. Het achtervoegsel `/v1` wordt
  door de extensie toegevoegd; neem dit niet zelf op.
- **API-sleutel** — alleen wanneer op de server `REQUIRE_API_KEY` is ingesteld. Wordt via VS
  Code SecretStorage opgeslagen in de sleutelhanger van het besturingssysteem, nooit in `settings.json`.

## Wat de modelkiezer toont

De extensie toont niet de onbewerkte payload van `GET /v1/models` — deze wordt aangepast, waardoor het weergegeven
aantal om twee bewuste redenen lager is dan de catalogusomvang.

### Er wordt om één id per model gevraagd

`MODELS_CATALOG_PREFIX_MODE` is standaard ingesteld op **`dual`**, waardoor elk model tweemaal wordt aangeboden — eenmaal
met het korte aliasvoorvoegsel en eenmaal met het canonieke providervoorvoegsel — zodat oudere clientconfiguraties
beide vormen kunnen blijven herkennen:

```
cc/claude-sonnet-4-6        ← aliasvoorvoegsel
claude/claude-sonnet-4-6    ← canoniek voorvoegsel, hetzelfde model
```

De extensie vraagt **`GET /v1/models?prefix=alias`** op, zodat er één id per model binnenkomt, zonder
de serverbrede instelling voor je andere clients te wijzigen. Op een referentie-instantie bracht dit
**2345 vermeldingen terug tot 1396 — 949 duplicaten, nul modellen verloren.**

Als je dit liever serverbreed voor _elke_ client oplost, stel je de functievlag
`MODELS_CATALOG_PREFIX_MODE` in het dashboard in op `alias`. Zie
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) voor de
queryparameter en de tabel per modus.

### Modellen die niet kunnen chatten, worden verborgen

De catalogus bevat ook modellen voor afbeeldingen, video, audio, herrangschikking, embeddings en moderatie. Deze worden
toch geweigerd bij een chatverzoek:

```
HTTP 400 — Model '<id>' is een model voor het genereren van afbeeldingen en kan niet worden gebruikt op
/v1/chat/completions. Gebruik in plaats daarvan POST /v1/images/generations.
```

Daarom worden ze op basis van hun veld `type` uitgefilterd voordat ze de modelkiezer bereiken. **Responses-API-
modellen blijven behouden** — elke Codex- of GPT-5.x-vermelding vermeldt `supported_endpoints: ["responses"]`,
en OmniRoute vertaalt deze voor `/v1/chat/completions`, zodat ze zonder problemen kunnen worden gebruikt.

### Providers die je nooit hebt geconfigureerd

De catalogus bevat modellen van providers met een **actieve verbinding**, plus alle **noAuth**-
providers — de providers zonder sleutel die een groot deel van de gratis laag vormen. Dat is bewust zo gedaan. Als je
ze wilt verbergen, voeg je ze toe aan `blockedProviders` in de dashboardinstellingen; in de
extensie verandert er niets.

## Dashboard in een VS Code-tabblad

`omnicopilot.dashboardOpen: "editor"` geeft het OmniRoute-dashboard via de
Simple Browser weer in een editortabblad in plaats van in een externe browser. Insluiten moet **expliciet op de server worden ingeschakeld** via
`DASHBOARD_ALLOW_EMBED=vscode`, waardoor de HTML-pagina's worden aangeboden met
`frame-ancestors 'self' vscode-webview:` in plaats van de standaardinstelling `frame-ancestors 'none'` +
`X-Frame-Options: DENY`. Het API-oppervlak (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) behoudt in
beide gevallen de strikte headers.

> ⚠️ **Dit is een build-time-vlag, geen runtime-vlag.** Next.js compileert `headers()` in het route-
> manifest, waardoor `next.config.mjs` de variabele leest terwijl de bundel wordt gebouwd
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> De variabele exporteren voordat een reeds gebouwde server wordt gestart, verandert niets — de headers zijn ingebakken.

```bash
# de variabele moet aanwezig zijn bij de BUILD-opdracht
DASHBOARD_ALLOW_EMBED=vscode npm run build        # of npm run build:release
npm start
```

| Installatiemethode         | Kun je insluiten inschakelen?                                                                                                                               |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Vanuit de broncode         | ✅ stel de variabele in bij de build-opdracht, zoals hierboven                                                                                              |
| `npm install -g omniroute` | ❌ het gepubliceerde pakket bevat een vooraf gebouwde bundel — bouw in plaats daarvan vanuit de broncode                                                    |
| Docker-image               | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — bij de vooraf gebouwde image op Docker Hub is insluiten niet ingeschakeld |

Zonder een build waarin insluiten is ingeschakeld, weigert de pagina om in een frame te worden weergegeven. De extensie detecteert dit aan de hand van de
responseheaders en valt terug op de externe browser — er gaat niets stuk en dit wordt eenmalig gemeld.
Zie [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) en issue
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273).

## Je andere tools configureren vanuit VS Code

**`OmniRoute: Configure Coding CLI`** gebruikt de `omniroute`-CLI om direct bruikbare profielen te schrijven
voor Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code,
Kilo en Roo — dezelfde configuraties die worden beschreven in
[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md). De API-sleutel wordt via de
omgevingsvariabele `OMNIROUTE_API_KEY` aan de CLI doorgegeven, nooit via de opdrachtregel.

## Problemen oplossen

| Symptoom                                                 | Oorzaak / oplossing                                                                                                                                                                                                                                                                                 |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Geen OmniRoute-modellen in de kiezer                     | De server is niet bereikbaar. De stip in de statusbalk wordt grijs; voer `OmniRoute: Check Connection` uit. Detectie verloopt bewust stil en levert geen modellen op in plaats van een melding te tonen.                                                                                            |
| Elk model wordt tweemaal weergegeven                     | Je gebruikt een versie van OmniCopilot ouder dan 1.0.1 — werk deze bij. De extensie vraagt nu `?prefix=alias` op.                                                                                                                                                                                   |
| Een eerder vermeld beeld-/audiomodel is verdwenen        | Dit is sinds 1.0.1 opzettelijk — het kon nooit een chatverzoek beantwoorden.                                                                                                                                                                                                                        |
| Paneel ontbreekt in de Activity Bar                      | VS Code verplaatst extra weergavecontainers naar het overloopmenu **"…"** onderaan de Activity Bar, en een container die via rechtsklikken is verborgen, blijft verborgen. Klik met de rechtermuisknop op de Activity Bar → vink **OmniRoute** aan, of open het met `OmniRoute: Manage Connection`. |
| Dashboard opent ondanks de modus `editor` in de browser  | De server is niet **gebouwd** met `DASHBOARD_ALLOW_EMBED=vscode` (zie hierboven) — dit bij het opstarten instellen voor een vooraf gebouwde installatie heeft geen effect. Het terugvallen is opzettelijk.                                                                                          |
| Modellenlijst is verouderd na het wijzigen van providers | `OmniRoute: Refresh Models`, of de ↻-link in het paneel.                                                                                                                                                                                                                                            |
