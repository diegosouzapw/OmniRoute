## 1. Antigravity versus Antigravity CLI (agy)

Beide providers gebruiken **dezelfde Google-backend** — identieke OAuth-client, tokenvernieuwing, endpoints en Google-accounts. Het verschil zit in de modellen die je ziet.

> Zie de [aankondiging van Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli) voor de officiële vergelijking van Google.

| Aspect                | `antigravity` (IDE)                                         | `agy` (CLI)                                            |
| --------------------- | ----------------------------------------------------------- | ------------------------------------------------------ |
| **Google-product**    | Antigravity 2.0 / Antigravity IDE                           | Antigravity CLI                                        |
| **Backend**           | Dezelfde Google Cloud Code API                              | Dezelfde Google Cloud Code API                         |
| **OAuth / token**     | Dezelfde client, dezelfde vernieuwing                       | Dezelfde client, dezelfde vernieuwing                  |
| **Modelcatalogus**    | Statische, samengestelde lijst (hardgecodeerd in OmniRoute) | Live opgevraagd bij Google via `:fetchAvailableModels` |
| **Claude-modellen**   | Sonnet 4.6, Opus 4.6 (elk 4 varianten)                      | Sonnet 4.6, Opus 4.6 (elk 4 varianten)                 |
| **Gemini-naamgeving** | Duidelijke labels (Low/Medium/High)                         | Upstream-ID's (extra-low/low/agent)                    |
| **Extra modellen**    | `gpt-oss-120b-medium`                                       | Kan aanvullende modellen van Google bevatten           |
| **Standaardgebruik**  | IDE-integratie (VS Code, JetBrains)                         | CLI-/API-toegang                                       |
| **Quota**             | Gedeeld met agy (hetzelfde Google-account)                  | Gedeeld met antigravity (hetzelfde Google-account)     |

**Beschikbare modellen (experimenteel geverifieerd, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (verschillende denkniveaus)
- Claude: Sonnet 4.6, Opus 4.6 (elk met varianten default/low/medium/high)
- Overig: GPT-OSS 120B Medium
- **Claude Sonnet 5 is NIET beschikbaar** — alleen de 4.6-varianten worden ondersteund

**Waarom de modelcatalogus verschilt**: Googles CLI is volgens de officiële blog van Google „geoptimaliseerd voor snelheid en geringe overhead” en „samen met Gemini-modellen geoptimaliseerd”. Het web-/IDE-product is „geoptimaliseerd voor volledigheid”. De CLI gebruikt `:fetchAvailableModels` om modellen dynamisch te ontdekken, terwijl de IDE een statische, samengestelde lijst gebruikt.

**In de praktijk**: Gebruik het voorvoegsel `agy/` voor Gemini-modellen (bijvoorbeeld `agy/gemini-3.7-flash-high`). Gebruik `antigravity/` voor de statische, samengestelde lijst. Beide gebruiken dezelfde Google-backend, maar hanteren verschillende modelnamen. Het quotum wordt gedeeld — het gebruik van een van beide providers telt mee voor de limieten van hetzelfde Google-account.

## 2. Google One AI Pro: quotasysteem

> Zie [Antigravity-documentatie: abonnementen](https://antigravity.google/docs/plans) voor officiële quotadetails en [Wijzigingen in Antigravity-abonnementen](https://antigravity.google/blog/changes-to-antigravity-plans) voor de nieuwste prijsupdates.

Google Antigravity gebruikt een **quotum met twee lagen**, gebaseerd op "Uitgevoerd werk" (computele belasting), niet op het aantal berichten.

### De twee lagen

| Laag                        | Wat het is                                       | Vernieuwingscyclus                                                                                                 |
| --------------------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| **Sprint van 5 uur**        | Direct beschikbare hoeveelheid "uitgevoerd werk" | Wordt 5 uur na de eerste aanvraag in een sessie opnieuw ingesteld                                                  |
| **Basislimiet van 7 dagen** | Harde wekelijkse limiet                          | Overschrijft de vernieuwing na 5 uur als deze wordt bereikt; blokkeert toegang tot de volgende periode van 7 dagen |

**Hoe "Uitgevoerd werk" wordt berekend**: Taken waarbij agents intensief worden gebruikt (bijv. "Herstructureer deze volledige repository") verbruiken het quotum veel sneller dan eenvoudige taken (bijv. "Herstel deze functie"). Er is geen realtime dashboard waarop het verbruik wordt weergegeven.

### Abonnementsniveaus

| Abonnement   | Prijs      | Quotum                                        | Wekelijkse limiet                                |
| ------------ | ---------- | --------------------------------------------- | ------------------------------------------------ |
| Free         | $0         | Substantieel quotum, wekelijks vernieuwd      | Ja                                               |
| AI Pro       | $19.99/mo  | Hoog quotum, doorlopende vernieuwing na 5 uur | Ja (overschrijft de 5-uurslimiet indien bereikt) |
| AI Ultra 5x  | $99.99/mo  | 5x het Pro-quotum                             | Geen wekelijkse limiet                           |
| AI Ultra 20x | $199.99/mo | 20x het Pro-quotum                            | Geen wekelijkse limiet                           |

### Gemini- versus niet-Gemini-modellen

- **Gemini-modellen** (Flash + Pro): Delen één snelheidslimiet, die wordt verbruikt op basis van API-prijzen. Als Flash 8x goedkoper is dan Pro, krijgt u 8x meer Flash-tokens.
- **Niet-Gemini-modellen** (Claude, GPT-OSS): Hebben **afzonderlijke** snelheidslimieten. Ze kunnen beschikbaar blijven, zelfs wanneer Gemini is geblokkeerd.

### AI-tegoeden (extra verbruik)

> Zie [Google One AI-tegoeden](https://support.google.com/googleone/answer/14534406) voor informatie over hoe tegoeden werken.

Wanneer het basisquotum is opgebruikt:

- **Nooit**: Wacht totdat het quotum wordt vernieuwd; toont "Basisquotum voor model bereikt"
- **Altijd**: Gebruikt automatisch AI-tegoeden; schakelt terug naar het basisquotum wanneer dit wordt vernieuwd

Tegoeden worden afzonderlijk aangeschaft en tegen de standaard API-prijzen afgeschreven.

### Belangrijke details

- Het quotum wordt **op accountniveau gedeeld** — hetzelfde Google-account in Antigravity IDE, CLI en OmniRoute deelt één quotumpool
- Elk Google-account heeft een eigen onafhankelijk quotum — meerdere accounts = meerdere quotumpools
- AI Pro-gebruikers hebben melding gemaakt van **blokkeringen van 7 dagen** in plaats van resets na 5 uur wanneer de wekelijkse basislimiet wordt bereikt (Google heeft bevestigd dat dit vanwege de grote vraag zo is ontworpen)

**Wanneer het quotum van uw account is opgebruikt**: OmniRoute probeert het automatisch opnieuw met het volgende beschikbare account in de combinatieroute. Handmatige tussenkomst is niet nodig.

## 3. Een projectId verkrijgen

Elke antigravity/agy-verbinding heeft een Google Cloud Code-`projectId` nodig. Zonder deze waarde retourneert het `/v1internal:models`-endpoint een 404-fout.

### Methode A: automatisch (aanbevolen)

OmniRoute regelt dit automatisch. Wanneer u via Dashboard OAuth een nieuw Google-account toevoegt:

1. OmniRoute vernieuwt het token
2. Roept `loadCodeAssist` aan om de projectId te achterhalen
3. Als er geen project bestaat, wordt `onboardUser` aangeroepen om er een aan te maken
4. Probeert `loadCodeAssist` opnieuw aan te roepen om de nieuw aangemaakte projectId op te halen
5. Slaat deze op in de database

**Dit werkt voor de meeste accounts** — er zijn geen handmatige stappen nodig.

### Methode B: handmatig via agy CLI

Als automatische detectie mislukt (zie Sectie 5 voor wanneer dit gebeurt):

```bash
# Installeer agy CLI (indien nog niet geïnstalleerd)
npm install -g @anthropic-ai/agy

# Meld u aan met uw Google-account
agy login

# Selecteer het account dat moet worden geactiveerd
# Dit activeert de Cloud Code-registratie en wijst een projectId toe
```

Nadat `agy login` is geslaagd, vernieuwt u het token in het OmniRoute Dashboard. De projectId wordt automatisch gedetecteerd.

### Controleren

Controleer de database:

```bash
# In de OmniRoute-container
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Of controleer de logboeken:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. OAuth-omleidings-URI

### Het probleem

Google OAuth vereist een geldige omleidings-URI. OmniRoute gebruikt standaard `http://127.0.0.1:20128/callback` (loopback). Dit werkt voor lokale builds, maar **werkt niet voor externe implementaties** (bijvoorbeeld een server die via een LAN-IP wordt benaderd).

Google weigert omleidings-URI's die:

- IP-adressen gebruiken (het moet een domein zijn dat eindigt op `.com`, `.org`, enz.)
- Niet overeenkomen met de geregistreerde omleidings-URI's in de configuratie van de OAuth-client

### De oplossing

**Optie A: De ingebouwde OAuth-flow gebruiken (standaard)**

- Werkt wanneer u OmniRoute benadert via `localhost` of `127.0.0.1`
- Geen configuratie nodig

**Optie B: Aangepaste OAuth-inloggegevens**

- Stel `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` in uw omgeving in
- Geef uw eigen Google OAuth-inloggegevens op:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Registreer `https://your-domain.com/callback` als een geautoriseerde omleidings-URI in Google Cloud Console

**Optie C: De agy-CLI gebruiken voor de eerste aanmelding**

- Voer `agy login` uit op de machine die toegang zal krijgen tot OmniRoute
- De OAuth-flow wordt lokaal voltooid en de tokens worden opgeslagen
- Importeer de verbinding via het Dashboard in OmniRoute

### Beperkingen

- Aangepaste OAuth-inloggegevens vereisen een domeinnaam (Google accepteert geen IP-adressen als omleidings-URI's)
- Als u geen domein hebt, gebruikt u in plaats daarvan optie A of C

## 5. Probleemoplossing: wanneer de automatische installatie mislukt

OmniRoute verwerkt de detectie van projectId en de onboarding voor de meeste accounts automatisch. Wanneer dit mislukt, is de hoofdoorzaak meestal een van de volgende:

### De accountregio is geblokkeerd

**Symptoom**: `agy login` geeft de melding "Eligibility check failed: Your current account is not eligible for Antigravity, because it is not currently available in your location."

**Hoofdoorzaak**: Google-accounts hebben een backendveld genaamd "Country Association" dat tijdens de registratie wordt ingesteld. De agy-CLI en de Cloud Code API controleren dit veld strikt — in tegenstelling tot Gemini op het web, dat alleen uw huidige IP-adres controleert.

> Ga naar het [Google-formulier voor landkoppeling](https://policies.google.com/country-association-form) om de aan uw account gekoppelde regio te controleren of te wijzigen.

**Waarom Gemini op het web wel werkt, maar agy niet**:

- Gemini op het web / Google One: controleert alleen het huidige IP-adres (een proxy werkt)
- agy-CLI / Cloud Code API: leest het backendveld Country Association (een proxy helpt niet)

**Oplossing**:

1. Ga naar het [Google-formulier voor landkoppeling](https://policies.google.com/country-association-form) terwijl u een Amerikaans IP-adres gebruikt
2. Dien een verzoek tot wijziging van de regio in (selecteer "I live in a different country")
3. Wacht 1-24 uur totdat Google het verzoek heeft verwerkt en u een e-mailmelding ontvangt
4. Daarna zou `agy login` moeten slagen

### Het account heeft geen Cloud Code-project

**Symptoom**: In de logboeken staat `loadCodeAssist returned no project id` en `onboardUser failed (400)`.

**Hoofdoorzaak**: Het account is nooit geregistreerd bij Google Cloud Code en de automatische onboarding is mislukt.

**Oplossing**: Voer `agy login` handmatig uit om de registratie bij Cloud Code te activeren en vernieuw daarna het token in het OmniRoute Dashboard.

### Token is verlopen of ingetrokken

**Symptoom**: 401-fouten in de logboeken of meldingen met "Token has expired".

**Oplossing**: Vernieuw het token via Dashboard → Providers → agy → Klik op het vernieuwingspictogram. Als het vernieuwingstoken zelf is ingetrokken, moet u zich opnieuw verifiëren via OAuth.

```
└─ Handmatig: voer `agy login` uit op de machine

```
