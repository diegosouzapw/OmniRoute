## مسیریابی خودکار بدون پیکربندی (پیشوند `auto/`)

> **جدید:** نیازی به ساخت combo نیست. پیشوند `auto/` را مستقیماً در هر کلاینتی استفاده کنید.

### مثالهای سریع

| شناسه مدل      | گونه    | رفتار                                                  |
| -------------- | ------- | ------------------------------------------------------ |
| `auto`         | پیشفرض  | همه ارائهدهندگان متصل، راهبرد LKGP، وزنهای متعادل      |
| `auto/coding`  | کدنویسی | وزنهای کیفیتمحور، مناسب برای تولید کد                  |
| `auto/fast`    | سریع    | انتخاب وزندار با تأخیر کم                              |
| `auto/cheap`   | ارزان   | مسیریابی بهینهشده از نظر هزینه (ابتدا کمترین هزینه)    |
| `auto/offline` | آفلاین  | ارائهدهندگانی با بیشترین سهمیه در دسترس را ترجیح میدهد |
| `auto/smart`   | هوشمند  | کیفیتمحور + نرخ کاوش بالاتر (10٪) برای کشف بهتر مدلها  |
| `auto/lkgp`    | lkgp    | LKGP صریح (همان `auto` پیشفرض)                         |
| `auto/chaos`   | آشوب    | وزنهای تزریق خطا برای آزمون تابآوری (مهندسی آشوب)      |

### ترکیب دسته × سطح (`auto/<category>:<tier>`)

پسوندهای سبک OpenRouter، **نوع مسیر** (دسته) را از **نحوه بهینهسازی آن** (سطح) جدا میکنند؛ بنابراین میتوانید آنها را آزادانه با یکدیگر ترکیب کنید (#4235 Phase B، `open-sse/services/autoCombo/suffixComposition.ts`):

- **دستهها** (فیلتر کردن مجموعه کاندیداها بر اساس قابلیت): `coding` · `reasoning` · `vision` · `chat` · `multimodal`. گزینههای `vision`/`multimodal` مدلهای دارای قابلیت بینایی را نگه میدارند؛ `reasoning` نیز مدلهای استدلالی/تفکری را نگه میدارد.
- **سطوح** (انتخاب وزنهای امتیازدهی / فیلتر مجموعه): `fast` (ارسال سریع) · `cheap` (نام مستعار `floor`، صرفهجویی در هزینه) · `reliable` (سلامت قطعکننده مدار + پایداری تأخیر) · `free` / `pro` (فیلتر کردن مجموعه بر اساس سطح مدل از طریق `classifyTier` — سطح رایگان در برابر پریمیوم).

| مثال                   | نتیجه                                                                  |
| ---------------------- | ---------------------------------------------------------------------- |
| `auto/coding:fast`     | مجموعه کدنویسی، وزنهای با تأخیر کم                                     |
| `auto/coding:cheap`    | مجموعه کدنویسی، بهینهشده از نظر هزینه (نام مستعار `auto/coding:floor`) |
| `auto/reasoning:pro`   | فقط مدلهای استدلالی/تفکری، سطح پریمیوم                                 |
| `auto/vision`          | مدلهای دارای قابلیت بینایی (بدون سطح ← وزنهای متعادل)                  |
| `auto/multimodal:free` | مدلهای دارای قابلیت چندوجهی، فقط سطح رایگان                            |

هر `auto/<category>[:<tier>]` معتبری هنگام تقاضا resolve میشود؛ زیرمجموعهای گزینششده در `/v1/models` و داشبورد نمایش داده میشود (`AUTO_SUFFIX_VARIANTS` در `open-sse/services/autoCombo/builtinCatalog.ts`). فیلتر کردن بهصورت **fail-open** انجام میشود — اگر هیچ مدل متصلی با یک محدودیت مطابقت نداشته باشد، از کل مجموعه استفاده میشود تا مسیریابی هرگز مختل نشود. امتیازدهنده اصلی (`combo.ts`) بدون تغییر باقی میماند؛ فیلتر دسته/سطح در `buildAutoCandidates` اعمال میشود.

> **هوشمندی زنده مدل:** هنگامی که پرچم `ARENA_ELO_SYNC_ENABLED` فعال باشد، تناسب مسیریابی خودکار با رتبهبندیهای زنده **Arena ELO** و دادههای سطح **models.dev** تعیین میشود (در غیر این صورت، به نگاشت ایستای تناسب بازمیگردد).

**نحوه استفاده:**

```bash
# هر IDE یا ابزار CLI که از قالب OpenAI پشتیبانی میکند
Base URL: http://localhost:20128/v1
API Key:  <کلید-endpoint-شما>

# در کد/پیکربندی خود، مدل را روی مقدار زیر تنظیم کنید:
model: "auto"                 # حالت پیشفرض متعادل
model: "auto/coding"          # بهترین گزینه برای وظایف کدنویسی
model: "auto/fast"            # سریعترین گزینه موجود
model: "auto/cheap"           # ارزانترین گزینه بهازای هر توکن
```

**چه اتفاقی میافتد:**

1. OmniRoute پیشوند `auto/` را در `src/sse/handlers/chat.ts` تشخیص میدهد
2. همه **اتصالهای فعال ارائهدهندگان** را از پایگاه داده واکشی میکند
3. آنها را به موارد دارای اعتبارنامه معتبر (کلید API یا توکن OAuth) محدود میکند
4. مدل را برای هر اتصال تعیین میکند (`connection.defaultModel` یا نخستین مدل ارائهدهنده)
5. یک **combo مجازی** در حافظه میسازد (در DB ذخیره نمیشود)
6. با استفاده از پروفایل وزن گونه انتخابشده + راهبرد LKGP مسیریابی میکند

**ویژگیهای کلیدی:**

- ✅ **همیشه فعال:** بدون نیاز به کلید تغییر وضعیت، ساخت combo یا پیکربندی
- ✅ **پویا:** ارائهدهندگان متصل فعلی را بهصورت خودکار بازتاب میدهد
- ✅ **چسبندگی نشست:** LKGP تضمین میکند آخرین ارائهدهنده موفق در اولویت قرار گیرد
- ✅ **آگاه از چندحسابی:** هر اتصال ارائهدهنده به یک کاندیدای جداگانه تبدیل میشود
- ✅ **بدون نوشتن در DB:** combo مجازی فقط برای همان درخواست وجود دارد و سربار ماندگاری آن صفر است

### کنترل کاندیدا برای هر کلید (#7819، سطح 1+2)

`GET /v1/auto-combo/{channel}/candidates` (`{channel}` = پسوند بعد از `auto/`، یا
مقدار تحتاللفظی `auto` برای کانال پایه) یک endpoint **فقطخواندنی** است که مجموعه
کاندیداهای فعلی یک کانال `auto/*` را همراه با دسترسپذیری زنده فهرست میکند و از
خواندنهای موجود مربوط به تابآوری مجدداً استفاده میکند (و هرگز `state` خام قطعکننده را نمیخواند):

- قطعکننده مدار ارائهدهنده — `getCircuitBreaker(provider).getStatus()` / `.canExecute()`
- دوره انتظار اتصال — `rateLimitedUntil` / `testStatus` در ردیف resolveشده
  `provider_connections`
- قفلشدن مدل — `isModelLocked(provider, connectionId, model)`

هر کاندیدا همچنین دارای پرچم `excluded` مربوط به این کلید API است. موارد مستثنا
بهازای هر کلید API ذخیره میشوند (جدول `auto_candidate_overrides`، migration شماره `128`) — OmniRoute
تکمستأجری است و جدول `users` ندارد؛ بنابراین `apiKeyId` نزدیکترین هویت واقعی
برای هر فراخواننده است — و این موارد در نقطه کنترل مجموعه کاندیداها در
`open-sse/services/autoCombo/virtualFactory.ts` از طریق تابع خالص و آزمودهشده با تست واحد
`filterExcludedCandidates()` (`open-sse/services/autoCombo/candidateOverrides.ts`)
اعمال میشوند. فیلتر بهصورت **fail-open** عمل میکند: تنظیم نبودن apiKeyId/کانال یا شکست در
واکشی DB، هر دو مجموعه را بدون فیلتر باقی میگذارند؛ بنابراین اپراتوری که هیچ overrideای
پیکربندی نکرده باشد، مسیریابیای کاملاً یکسان در سطح بایت با پیش از این قابلیت مشاهده میکند.

**موکول به یک issue تکمیلی:** وزندهی به هر candidate + ترتیبدهی صریح (سطح 3
— به مسیرهای موجودِ strategy وزندار/اولویتدار متصل میشود) و pin کردن یک strategy مشخص از
`combo.ts` برای هر channel از نوع `auto/*` (سطح 4). برای پرسش باز دربارهٔ اینکه با توجه به
مدل single-tenant، overrideها باید بهازای هر API key باقی بمانند یا global شوند، به طرح #7819
مراجعه کنید.

**پشت صحنه:**

```txt
درخواست: { model: "auto/coding" }
   ↓
src/sse/handlers/chat.ts پیشوند را تشخیص میدهد
   ↓
createVirtualAutoCombo('coding') → candidatePool از connectionهای فعال
   ↓
handleComboChat (همان engine مورد استفاده برای comboهای ذخیرهشده)
   ↓
امتیازدهی خودکار، بهترین provider/model را برای هر درخواست انتخاب میکند
```

**فایلهای پیادهسازی:**

| فایل                                                      | هدف                                          |
| --------------------------------------------------------- | -------------------------------------------- |
| `open-sse/services/autoCombo/autoPrefix.ts`               | تجزیهکنندهٔ پیشوند (`parseAutoPrefix`)       |
| `open-sse/services/autoCombo/virtualFactory.ts`           | ساخت objectهای مجازی `AutoComboConfig`       |
| `open-sse/services/autoCombo/providerRegistryAccessor.ts` | هوک تست برای mock کردن registry ارائهدهندگان |
| `src/sse/handlers/chat.ts`                                | یکپارچهسازی: short-circuit پیشوند خودکار     |
| `src/shared/constants/providers.ts`                       | ورودی سیستمی `SYSTEM_PROVIDERS.auto`         |

## نامهای Combo که با شناسه یک مدل واقعی مطابقت دارند

یک combo که `name` آن با شناسه بدون پیشوند یک مدل یکسان است (برای مثال، comboای با نام
`gpt-5.5`)، یک **الگوی عمدی و پشتیبانیشده** است، نه یک باگ: این همان
سازوکار بازگشت به ارائهدهنده جایگزین برای هر شناسه مدل است که در
[#6940](https://github.com/diegosouzapw/OmniRoute/issues/6940) مستند شده است. از آنجا که
تفکیک combo پیش از تفکیک شناسه بدون پیشوند مدل بررسی میشود
(`getComboForModel()` در `src/sse/services/model.ts`)، درخواست برای شناسه بدون پیشوند
`gpt-5.5` بهجای اینکه مستقیماً به یک ارائهدهنده واحد هدایت شود، از طریق
مقصدهای combo (برای مثال،
`acme-responses/gpt-5.5` و `backup-responses/gpt-5.5`) مسیریابی میشود — این رفتار
از اولویت combo پیش از بازنویسی که برای
[#3227/#3233](https://github.com/diegosouzapw/OmniRoute/issues/3227) ساخته شده بود
دوباره استفاده میکند و در برابر رگرسیون توسط `tests/unit/responses-combo-resolution-3227.test.ts` و
`tests/unit/combo-name-codex-responses-rewrite.test.ts` آزمایش میشود.

ایجاد یا تغییر نام یک combo به نامی که شناسه یک مدل واقعی را تحتالشعاع قرار میدهد
**هرگز رد نمیشود** — انجام این کار گردشکار مستندشده را مختل میکند. در عوض
(#8530)، `POST /api/combos` و `PUT /api/combos/[id]` هنگامی که نام (جدید) با شناسه
یک مدل واقعی تداخل داشته باشد، یک فیلد غیرمسدودکننده `warning` به پاسخ اضافه
میکنند:

```json
{
  "warning": {
    "code": "COMBO_NAME_SHADOWS_MODEL",
    "modelId": "gpt-5.5",
    "providerId": "openai"
  }
}
```

هنگام راهاندازی، `scanComboModelNameCollisionsAtBoot()`
(`src/instrumentation-node.ts`) همچنین یک هشدار تکخطی `[STARTUP]` ثبت میکند که
تمام comboهای موجودی را که یک شناسه مدل را تحتالشعاع قرار میدهند فهرست میکند؛
در نتیجه، اپراتورهایی که بهطور تصادفی با این وضعیت روبهرو شدهاند (و نه بهصورت
عمدی، مطابق #6940)، نشانهای برای تشخیص آن خواهند داشت.
تابع کمکی تشخیص در `src/lib/combos/modelNameCollision.ts` قرار دارد.

## فراخوانی یک Combo سفارشی از یک کلاینت

comboهای ذخیرهشده (Settings → Combos) فقط زمانی استفاده میشوند که کلاینت **نام دقیق** combo را در فیلد `model` ارسال کند — هیچ تطبیق مبهم یا جزئی برای نام combo انجام نمیشود و پیشوند `auto/` نیز در کار نیست. ترتیب تفکیک (`getComboForModel()` در `src/sse/services/model.ts`):

1. تطبیق دقیق نام combo (`model: "my-combo"`)،
2. پیشوند `combo/<name>` (`model: "combo/my-combo"`)،
3. نگاشتهای glob از مدل به combo (`/api/model-combo-mappings`).

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"my-combo","messages":[{"role":"user","content":"Hello"}]}'
```

دو اشتباه رایج:

- **`auto` از comboهای شما استفاده نمیکند.** `auto`/`auto/*` مجموعه کاندیداهای بدون نیاز به پیکربندی خودش را ایجاد میکند و تنها در صورتی comboهای ذخیرهشده را بررسی میکند که یک combo دقیقاً `auto` نام داشته باشد (توصیه نمیشود). برای مسیریابی از طریق یک combo، نام دقیق آن را ارسال کنید — نه `auto`.
- **`openrouter/auto` یک محصول واقعی و پولی OpenRouter است** ("Auto Best Available")، نه یک نام مستعار OmniRoute. این مورد، تنها ورودی مدل ایستای رجیستری OpenRouter (`open-sse/config/providers/registry/openrouter/index.ts`) است و هزینه آن جداگانه محاسبه میشود. برای حذف آن از مجموعههای `auto`، از Settings → Routing → Hide paid models استفاده کنید.

برای سردرگمی اولیهای که این بخش مستند میکند، به [#7992](https://github.com/diegosouzapw/OmniRoute/issues/7992) و [#7111](https://github.com/diegosouzapw/OmniRoute/issues/7111) مراجعه کنید.

## نحوهٔ عملکرد (ترکیبهای خودکار ماندگار)

موتور Auto-Combo با استفاده از یک **تابع امتیازدهی ۱۶عاملی** (تعریفشده در `open-sse/services/autoCombo/scoring.ts` ← `DEFAULT_WEIGHTS`) بهصورت پویا بهترین ارائهدهنده/مدل را برای هر درخواست انتخاب میکند. مجموع وزنهای پیشفرض برابر با `1.0` است؛ وزنهای سفارشی توسط `normalizeScoringWeights()` دوباره نرمالسازی میشوند. دو عامل از این شانزده عامل — `cacheAffinity` و `resetWindowAffinity` — وزن پیشفرض `0` دارند؛ `reliability` در `DEFAULT_WEIGHTS` وزن `0` دارد، اما وزن آن در بستههای عمومی `0.03` و در `reliability-first` برابر با `0.04` است؛ همچنین `quality` در بستهها وزن `0.02` دارد (در `quality-first` برابر با `0.03` است): بااینحال، این عوامل همچنان برای هر نامزد محاسبه میشوند و `cacheAffinity` خارج از امتیاز، حذف موارد تکراری کش پرامپت را کنترل میکند؛ بنابراین عوامل دارای وزن پیشفرض صفر، صرفاً بهطور پیشفرض در رأیگیری مشارکت نمیکنند، درحالیکه بستهها از آنها استفاده میکنند.

### کنترلهای هر درخواست (هدرها) — #6023 / #6024 / #6025 / #3470

یک ترکیب `auto` را میتوان **برای هر درخواست** از طریق سه هدر هدایت کرد، بدون آنکه پیکربندی ذخیرهشده ترکیب تغییر کند. این موارد فقط برای راهبرد `auto` و فقط برای درخواستی اعمال میشوند که آنها را همراه دارد؛ در صورت نبود هدر، از `modePack`/`budgetCap`/`budgetFallback` ذخیرهشده ترکیب استفاده میشود.

| هدر                           | مقادیر قابلقبول                                                                                                                                                                                     | اثر                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| :---------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `X-OmniRoute-Mode`            | یک نام مستعار از پیش تنظیمشده (`fast`، `balanced`، `quality`، `cheap`، `reliable`، `offline`) یا نام خام بسته (`ship-fast`، `cost-saver`، `quality-first`، `offline-friendly`، `reliability-first`) | وزنهای امتیازدهی را برای این درخواست بازنویسی میکند. `balanced`/`default` وزنهای پیشفرض را اجباری میکنند (بدون بسته). مقادیر ناشناخته نادیده گرفته میشوند (پیکربندی حفظ میشود).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "X-OmniRoute-Mode: fast" \
  -H "X-OmniRoute-Budget: 0.05" \
  -H "X-OmniRoute-Budget-Fallback: strict" \

```

تفکیکشده به ورودیهای موجود `config.modePack` / `config.budgetCap` /
`config.budgetFallback` موتور داده میشوند. مقدار ذخیرهشدهٔ `config.budgetFallback` یک ترکیب ("strict" |
"cheapest") خطمشی پایدار را تعیین میکند؛ هدر آن را برای یک درخواست واحد بازنویسی میکند.

| `lkgp`              | آخرین مسیر سالم شناختهشده (اتصال به آخرین ارائهدهندهٔ موفق را ثابت نگه میدارد و سپس به قوانین جایگزین رجوع میکند)                                                                                 |
| `context-optimized` | انتخاب هدفی که بهترین تناسب را با اندازهٔ فعلی زمینه دارد                                                                                                                                         |
| `cache-optimized`   | مرتبسازی مجدد هدفها بر اساس نزدیکی به کش پرامپت — اتصالی که به احتمال زیاد پیشوند کششدهٔ این درخواست را از قبل دارد، ابتدا امتحان میشود (`open-sse/services/combo/promptCacheAffinity.ts`، #8008) |
| `fusion` 🧬         | ارسال موازی درخواست به مجموعهای از مدلها و سپس ترکیب پاسخها در قالب یک پاسخ واحد بهوسیلهٔ یک داور (پایین را ببینید)                                                                               |
| `pipeline`          | اجرای ترتیبی هدفها با انتقال خروجی هر مرحله به ورودی مرحلهٔ بعد؛ فقط پاسخ نهایی بازگردانده میشود (#6396)                                                                                          |

⭐ = جدید در v3.8.0 · 🧬 = جدید در v3.8.36

### معناشناسی `weighted`

`weighted` یک **انتخاب تصادفی متناسب در هر درخواست** است
(`open-sse/services/combo/targetSorters.ts` ← `selectWeightedTarget`)، نه یک همترازکننده:

- هر درخواست **یک** مرحله را با احتمال `weight / totalWeight` انتخاب میکند؛ مراحل باقیمانده
  بر اساس وزن نزولی بهعنوان زنجیرهٔ جایگزین آن درخواست مرتب میشوند.
- مرحلهای که وزن آن `0` باشد (یا وزن نداشته باشد)، تا زمانی که هر مرحلهٔ دیگری
  وزنی > 0 داشته باشد، **هرگز انتخاب نمیشود** — چنین مرحلهای فقط پس از شکست مرحلهٔ انتخابشده میتواند بهعنوان جایگزین عمل کند. تنها زمانی که وزن **همهٔ**
  مراحل 0 باشد، انتخاب یکنواخت میشود.
- مراحلی که همهٔ هدفهایشان در دسترس نیستند — قطعکنندهٔ مدار ارائهدهنده در وضعیت `OPEN`، دورهٔ انتظار
  اتصال یا قفلشدن مدل — پیش از انجام انتخاب از آن حذف میشوند
  (`open-sse/services/combo/targetResolution.ts`)؛ بنابراین یک مرحلهٔ سالم میتواند موقتاً
  در تمام درخواستها برنده شود.
- `stickyWeightedLimit` (پیکربندی ترکیب، مقدار پیشفرض `1` = غیرفعال) مرحلهٔ انتخابشده را برای همین تعداد
  موفقیت متوالی ثابت نگه میدارد و سپس دوباره انتخاب انجام میشود.

برای چرخش دقیق از `round-robin` استفاده کنید؛ وزنهای برابر در `weighted` تعادل آماری ایجاد میکنند — نه
تعادل دقیق.

## راهبرد Fusion

`fusion` تنها راهبردی است که یک مقصد واحد را انتخاب **نمیکند**. این راهبرد پرامپت را بهصورت
موازی به **تمام مدلهای پنل** ارسال میکند و سپس یک **مدل داور** قابلپیکربندی، از همه پاسخهای
پنل یک پاسخ نهایی واحد میسازد. این قابلیت از `decolua/9router` بالادستی
(طراحی Fusion متعلق به OpenRouter) منتقل شده است؛ پیادهسازی آن در `open-sse/services/fusion.ts` قرار دارد.

نحوه کار:

0. **عبور مستقیم درخواستهای دارای ابزار** — درخواستی که یک آرایه غیرخالی `tools` داشته باشد و
   مقدار `tool_choice` آن صراحتاً `"none"` نباشد، پنل را کاملاً کنار میگذارد: درخواست مستقیماً به
   یک مدل واحد (داور پیکربندیشده یا `panel[0]`) هدایت میشود و `tools`/`tool_choice`
   بدون تغییر عبور داده میشوند. اعضای پنل به ابزارها دسترسی ندارند و دستورالعمل
   ترکیب پاسخِ داور، تولید فراخوانی ابزار را منع میکند؛ بنابراین کلاینتهای عاملی/فراخواننده ابزار
   بهجای متن ترکیبشده، یک تصمیم واقعی برای فراخوانی ابزار دریافت میکنند (#6771).
1. **ارسال همزمان** (فقط برای درخواستهای بدون ابزار) — پرامپت بهطور همزمان به همه مدلهای
   پنل ارسال میشود؛ حالت غیرجریانی بهاجبار فعال و ابزارها حذف میشوند (داور برای ترکیب پاسخ
   به متن کامل نیاز دارد).
2. **گردآوری با حد نصاب و مهلت** — بهمحض رسیدن `minPanel` پاسخ، یک زمانسنج کوتاه برای
   مدلهای عقبمانده آغاز میشود؛ سپس Fusion با هر تعداد پاسخی که گردآوری شده است ادامه میدهد.
   این کار تأثیر کندترین مدل بر زمان سپریشده را محدود میکند و یک مهلت نهایی سخت نیز آن را
   کراندار نگه میدارد.
3. **ترکیب توسط داور** — پاسخهای پنل ناشناسسازی میشوند (`Source 1`، `Source 2`، … — تا
   داور محتوا را بسنجد، نه برند مدل) و در اختیار داور قرار میگیرند. داور توافقها /
   تناقضها / پوشش ناقص / بینشهای منحصربهفرد / نقاط کور را تحلیل میکند و سپس
   **یک** پاسخ معتبر مینویسد. فراخوانی داور، پرچم اصلی `stream` کلاینت و ابزارها را
   حفظ میکند؛ بنابراین پخش جریانی و استفاده پاییندستی از ابزارها همچنان کار میکنند.
4. **افت تدریجی و کنترلشده** — ۰ پاسخ پنل ← `503`؛ دقیقاً ۱ پاسخ باقیمانده ← همان پاسخ
   مستقیماً برگردانده میشود (چیزی برای ترکیب وجود ندارد)؛ پنلی با یک مدل نیز مستقیماً پاسخ میدهد.

یکی از اعضای پنل میتواند یک مرحله `combo-ref` نیز باشد (`{kind: "combo-ref", comboName: "..."}`) که
به ترکیب دیگری ارجاع میدهد — این مرحله بهعنوان **یک صدای مستقل و جعبهسیاه در پنل** حل میشود
(یک ارسال بازگشتی کامل به ترکیب مورد ارجاع، نه ارسال همزمان به مقصدهای خود آن ترکیب)، با همان
محافظت در برابر عمق/چرخه که همه راهبردهای دیگرِ مصرفکننده combo-ref از آن استفاده میکنند (#6764).

### پیکربندی

پیکربندی در داده `config` ترکیب انجام میشود (بدون مهاجرت طرحواره — از جدول موجود
`combos` دوباره استفاده میکند):

| فیلد                                     | نوع      | پیشفرض        | هدف                                                                             |
| :--------------------------------------- | :------- | :------------ | :------------------------------------------------------------------------------ |
| `config.judgeModel`                      | `string` | اولین مدل پنل | مدلی که پاسخ نهایی را ترکیب میکند                                               |
| `config.fusionTuning.minPanel`           | `number` | `2`           | تعداد پاسخهای موفق لازم پیش از شروع زمانسنج مهلت (محدودشده به `[2, panelSize]`) |
| `config.fusionTuning.stragglerGraceMs`   | `number` | `8000`        | مدت انتظار برای مدلهای عقبمانده پس از رسیدن به حد نصاب                          |
| `config.fusionTuning.panelHardTimeoutMs` | `number` | `90000`       | سقف مطلق برای جلوگیری از اینکه یک مدل متوقفشده، درخواست را معطل کند             |

مقادیر پیشفرض در `FUSION_DEFAULTS` (`open-sse/services/fusion.ts`) قرار دارند.

### مثال

```bash
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "fusion-panel",
    "strategy": "fusion",
    "targets": [
      { "model": "cc/claude-opus-4-7" },
      { "model": "cx/gpt-5.5" },
      { "model": "glm/glm-5.1" }
    ],
    "config": {
      "judgeModel": "cc/claude-opus-4-7",
      "fusionTuning": { "minPanel": 2, "stragglerGraceMs": 8000, "panelHardTimeoutMs": 90000 }
    }
  }'
```

سپس آن را مانند هر ترکیب دیگری فراخوانی کنید: `{"model":"fusion-panel","messages":[...]}`.

## کارخانهٔ مجازی Auto-Combo

موتور Auto Combo به کمبوهای ازپیشتعریفشده نیازی ندارد. در عوض، `open-sse/services/autoCombo/virtualFactory.ts` کاندیداها را بهصورت پویا میسازد:

1. `getProviderConnections({ isActive: true })` را دریافت میکند (همهٔ اتصالهای فعال)
2. مواردی را که اعتبارنامهٔ معتبر دارند فیلتر میکند (کلید API یا توکن OAuth منقضینشده از طریق `hasUsableOAuthToken()`)
3. برای بررسی دسترسپذیری مدل و قیمتگذاری، آنها را با `getProviderRegistry()` تطبیق میدهد
4. برای هر سهتایی `(provider, model, connection)`، یک `VirtualAutoComboCandidate` میسازد
5. `connection.defaultModel` (یا اولین مدل رجیستری) را بهعنوان مقصد ارسال انتخاب میکند
6. هر کاندیدا را با استفاده از `scorePool()` شانزدهعاملی و بستهٔ وزن آن واریانت امتیازدهی میکند
7. `AutoComboConfig` حاصل را که در حافظه قرار دارد، برای `handleComboChat()` برمیگرداند — و هرگز آن را در DB ذخیره نمیکند

این یعنی **افزودن یک ارائهدهندهٔ جدید که `auto/*` برای آن فعال است، بهطور خودکار مجموعهٔ کاندیداها را گسترش میدهد** — و نیازی به ویرایش دستی کمبو نیست. کمبوی مجازی برای هر درخواست از نو ساخته میشود، بنابراین اتصالهایی که بهتازگی اضافه شدهاند یا دوباره سالم شدهاند، بلافاصله در نظر گرفته میشوند.

## خودترمیمی

- **حذف موقت**: امتیاز < 0.2 ← حذف بهمدت ۵ دقیقه (عقبنشینی تدریجی، حداکثر ۳۰ دقیقه)
- **آگاهی از قطعکنندهٔ مدار**: OPEN ← حذف خودکار؛ HALF_OPEN ← درخواستهای آزمایشی
- **حالت رخداد**: بیش از ۵۰٪ OPEN ← غیرفعالکردن کاوش و بهحداکثررساندن پایداری
- **بازیابی پس از دورهٔ انتظار**: پس از پایان حذف، اولین درخواست یک «آزمایش» با زمانانتظار کاهشیافته است

## کاوش Bandit

۵٪ از درخواستها (قابل پیکربندی) برای کاوش به ارائهدهندگان تصادفی هدایت میشوند. این قابلیت در حالت رخداد غیرفعال است.

## API

**هیچ نقطهٔ پایانی اختصاصی `POST /api/combos/auto` وجود ندارد** — Auto-Combo به دو روش استفاده میشود:

1. **بدون پیکربندی (پیشنهادی):** هر درخواست تکمیل چت را با `model: "auto"` یا `model: "auto/<variant>"` ارسال کنید. کارخانهٔ مجازی کمبو را برای هر درخواست میسازد — بدون ماندگارسازی و بدون نیاز به فراخوانی API.

2. **کمبوی ماندگار با `strategy: "auto"`:** از طریق `POST /api/combos` یک کمبوی عادی ایجاد کنید و `strategy: "auto"` را همراه با `config.auto.weights` / `config.auto.candidatePool` تنظیم کنید. همان موتور امتیازدهی استفاده میشود؛ کمبو در `combos` ذخیره میشود و با ID قابل استفادهٔ مجدد است.

برای کشف، `GET /api/combos/auto` همهٔ واریانتها را بههمراه مجموعهٔ کاندیداهای نهاییشده و نیز `context_length` / `max_output_tokens` فهرست میکند — یعنی مقدار MAX در میان پنجرههای مجموعهٔ کاندیداها. کلاینتها (برای مثال افزونهٔ opencode) باید این مقادیر را بهجای `0` اعلام کنند: کانتکست صفر، فشردهسازی خودکار opencode را کاملاً غیرفعال میکند و اجازه میدهد نشستها آنقدر رشد کنند تا پاکسازی تاریخچه در درگاه، کانتکست را از بین ببرد. اعلام MAX ایمن است، زیرا پیشفیلتر کانتکست Auto-Combo درخواستهای بیشازحد بزرگ را به کاندیداهای دارای پنجرهٔ بزرگ هدایت میکند.

```bash
# استفاده بدون پیکربندی (بدون ایجاد کمبو)
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/coding","messages":[{"role":"user","content":"Hello"}]}'

# کمبوی خودکار ماندگار از طریق نقطهٔ پایانی عادی کمبوها
curl -X POST http://localhost:20128/api/combos \
  -H "Content-Type: application/json" \
  -d '{"id":"my-auto","name":"Auto Coder","strategy":"auto","config":{"auto":{"candidatePool":["anthropic","google","openai"],"weights":{"quota":0.15,"health":0.3,"costInv":0.05,"latencyInv":0.35,"taskFit":0.1,"stability":0,"tierPriority":0.05}}}}'
```

### استراتژیهای مسیریاب خودکار

کمبوهای ماندگار با `strategy: "auto"` میتوانند `config.routerStrategy` (یا مقدار قدیمی
`config.auto.routerStrategy`) را روی یکی از موارد زیر تنظیم کنند:

- `rules` — امتیازدهی وزندار پیشفرض
- `score` — بالاترین امتیاز وزندار پیکربندیشده را انتخاب میکند. در تساوی کامل،
  ترتیب پیکربندیشدهٔ کاندیداها حفظ میشود؛ `explorationRate` موجود از کل مجموعهٔ رتبهبندیشده نمونهبرداری میکند.
- `cost` / `eco` — ارزانترین ارائهدهندهٔ سالم
- `latency` / `fast` — کمترین تأخیر p95 همراه با جریمهٔ قابلیت اطمینان
- `sla-aware` / `sla` — کاندیداهایی را ترجیح میدهد که تأخیر p95، نرخ خطا و در صورت وجود،
  SLOهای هزینه را برآورده میکنند
- `lkgp` — ابتدا آخرین ارائهدهندهٔ سالم شناختهشده

### جزئیات استراتژیهای مسیریاب

موتور Auto-Combo شش پیادهسازی قابلجایگزینی **RouterStrategy** ارائه میکند که
میتوانید آنها را از طریق `config.routerStrategy` (یا مقدار قدیمی `config.auto.routerStrategy`) تعویض کنید.
هر استراتژی با توجه به یک `RoutingContext`، یک ارائهدهنده را از مجموعهٔ کاندیداها انتخاب میکند
(نوع وظیفه، نشانههای ابزار/بینایی، تخمین توکن، خطمشی اختیاری SLA و
آخرین ارائهدهندهٔ سالم اختیاری).

#### 1. `rules` (پیشفرض) — امتیازدهی وزندار ۱۶ عاملی

موتور امتیازدهی موجود را دربر میگیرد. کاندیداهای قطعکنندهٔ مدار با وضعیت `OPEN` را
حذف میکند، سپس `scorePool()` را با نوع وظیفهٔ فعلی و `getTaskFitness()` اجرا میکند
و ارائهدهندهای را که بالاترین امتیاز را دارد انتخاب میکند.

```ts
class RulesStrategyImpl implements RouterStrategy {
  readonly name = "rules";
  readonly description = "16-factor weighted scoring (see DEFAULT_WEIGHTS)";

  select(pool, context) {
    const eligible = pool.filter((c) => c.circuitBreakerState !== "OPEN");
    const ranked = scorePool(
      eligible.length > 0 ? eligible : pool,
      context.taskType,
      undefined,
      getTaskFitness
    );
    return { provider: ranked[0].provider /* ... */ };
  }
}
```

**زمان استفاده**: پیشفرض. زمانی استفاده کنید که به مصالحهای متوازن میان همهٔ سیگنالها نیاز دارید.

**نام مستعار**: `rules` (بدون نام مستعار)

---

#### 2. `cost` / `eco` — ارزانترین ارائهدهندهٔ سالم

مجموعهٔ کاندیداها را بر اساس `costPer1MTokens` (صعودی) مرتب میکند و ارزانترین مورد را انتخاب میکند.
ابتدا کاندیداهای دارای وضعیت `OPEN` را حذف میکند.

```ts
class CostStrategyImpl implements RouterStrategy {
  readonly name = "cost";
  readonly description = "Always selects cheapest available provider";

  select(pool, context) {
    const healthy = pool.filter((c) => c.circuitBreakerState !== "OPEN");
    const sorted = [...healthy].sort((a, b) => a.costPer1MTokens - b.costPer1MTokens);
    return { provider: sorted[0].provider /* ... */ };
  }
}
```

**زمان استفاده**: بارهای کاری حساس به هزینه، پردازش دستهای یا کارهای پسزمینه.

**نامهای مستعار**: `cost`، `eco`

---

#### 3. `latency` / `fast` — کمترین تأخیر p95 همراه با جریمهٔ قابلیت اطمینان

بر اساس `p95LatencyMs + (errorRate * 1000)` مرتبسازی میکند. جریمه نرخ خطا تضمین میکند که
ارائهدهندگان غیرقابلاعتماد، حتی اگر تأخیر اسمی کمی داشته باشند، در رتبه پایینتری قرار گیرند.

```ts
class LatencyStrategyImpl implements RouterStrategy {
  readonly name = "latency";
  readonly description = "Prioritizes lowest p95 latency with reliability weighting";

  select(pool, context) {
    const healthy = pool.filter((c) => c.circuitBreakerState !== "OPEN");
    const sorted = [...healthy].sort(
      (a, b) => a.p95LatencyMs + a.errorRate * 1000 - (b.p95LatencyMs + b.errorRate * 1000)
    );
    return { provider: sorted[0].provider /* ... */ };
  }
}
```

**زمان استفاده**: بارهای کاری حساس به تأخیر، مانند گفتوگوی بلادرنگ، تکمیل خودکار یا
دستیارهای تعاملی برنامهنویسی.

**نامهای مستعار**: `latency`، `fast`

---

#### 4. `sla-aware` / `sla` — انطباق با SLO تأخیر/خطا/هزینه

به هر گزینه بر اساس میزان انطباق آن با سیاست SLO پیکربندیشده امتیاز میدهد:

| عامل           | وزن | فرمول                                             |
| -------------- | --- | ------------------------------------------------- |
| امتیاز تأخیر   | 35% | `threshold / max(value, ε)`                       |
| امتیاز خطا     | 35% | `threshold / max(value, ε)`                       |
| امتیاز سلامت   | 15% | `1.0` (CLOSED) / `0.5` (HALF_OPEN) / `0.0` (OPEN) |
| امتیاز هزینه   | 10% | `threshold / max(value, ε)` یا معکوس نرمالشده     |
| امتیاز پایداری | 5%  | انحراف معیار تأخیر بهصورت معکوس نرمالشده          |

وقتی `hardConstraints: true` باشد، گزینهها ابتدا بر اساس **امتیاز نقض**
(میزان عبور آنها از هر SLO) و سپس بر اساس امتیاز ترکیبی مرتب میشوند. در غیر این صورت،
فقط امتیاز ترکیبی ملاک است.

```ts
class SLAStrategyImpl implements RouterStrategy {
  readonly name = "sla-aware";
  readonly description =
    "Selects the provider most likely to satisfy latency, error-rate, and cost SLOs";

  select(pool, context) {
    // ... هر گزینه را در برابر سیاست امتیازدهی میکند: { targetP95Ms, maxErrorRate, maxCostPer1MTokens, hardConstraints }
  }
}
```

**فیلدهای SLA** (در پیکربندی ترکیبی تنظیم میشوند):

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "sla-aware",
    "slaTargetP95Ms": 1500,
    "slaMaxErrorRate": 0.05,
    "slaMaxCostPer1MTokens": 5,
    "slaHardConstraints": true
  }
}
```

**زمان استفاده**: بارهای کاری عملیاتی با محدودیتهای سختگیرانه برای تأخیر، نرخ خطا یا هزینه.

**نامهای مستعار**: `sla-aware`، `sla`

---

#### 5. `lkgp` — ابتدا آخرین ارائهدهنده مطلوب شناختهشده

ابتدا **آخرین ارائهدهنده مطلوب شناختهشده** را (در صورت تنظیم بودن) امتحان میکند و سپس به
استراتژی `rules` بازمیگردد. برای حفظ وابستگی نشست مفید است — یک ارائهدهنده یکسان
درخواستهای بعدی یک مکالمه را مدیریت میکند.

```ts
class LKGPStrategyImpl implements RouterStrategy {
  readonly name = "lkgp";
  readonly description = "Tries last known good provider first, then falls back to rules";

  select(pool, context) {
    if (context.lkgpEnabled === false) {
      return getStrategy("rules").select(pool, context);
    }

    if (context.lastKnownGoodProvider) {
      const candidates = pool.filter(
        (c) => c.provider === context.lastKnownGoodProvider && c.circuitBreakerState !== "OPEN"
      );
      if (candidates.length > 0) {
        return { provider: candidates[0].provider /* ... */ };
      }
    }

    // بازگشت به استراتژی rules
    return getStrategy("rules").select(pool, context);
  }
}
```

**زمان استفاده**: مکالمات چندمرحلهای که میخواهید همان ارائهدهنده
درخواستهای بعدی را مدیریت کند (برای مثال، بهمنظور کشکردن، تداوم زمینه یا ثبات قیمتگذاری).

**نام مستعار**: `lkgp` (بدون نام مستعار)

---

### استراتژیهای سفارشی مسیریاب

میتوانید پیادهسازی `RouterStrategy` خود را از طریق API عمومی ثبت کنید:

```ts
import {
  registerStrategy,
  type RouterStrategy,
} from "@omniroute/open-sse/services/autoCombo/routerStrategy";

class MyCustomStrategy implements RouterStrategy {
  readonly name = "my-custom";
  readonly description = "My custom routing strategy";

  select(pool, context) {
    // منطق مسیریابی شما در اینجا
    return {
      provider: pool[0].provider,
      model: pool[0].model,
      strategy: this.name,
      reason: "MyCustomStrategy: ...",
      candidatesConsidered: pool.length,
      finalScore: 1.0,
    };
  }
}

registerStrategy("my-custom", new MyCustomStrategy());
```

سپس از آن استفاده کنید:

```json
{
  "strategy": "auto",
  "config": {
    "routerStrategy": "my-custom"
  }
}
```

## تناسب وظیفه

بیش از ۳۰ مدل در ۶ نوع وظیفه (`coding`، `review`، `planning`، `analysis`، `debugging`، `documentation`) امتیازدهی شدهاند. از الگوهای wildcard پشتیبانی میشود (برای مثال، `*-coder` → امتیاز بالای کدنویسی).

## مرور گونههای Auto

با احتساب `auto` ساده (پیشفرض) بهعلاوهٔ ۶ مقدار `AutoVariant` تعریفشده در `autoPrefix.ts`، در مجموع **۷ شناسهٔ مدل قابل فراخوانی** وجود دارد:

`auto`، `auto/coding`، `auto/fast`، `auto/cheap`، `auto/offline`، `auto/smart`، `auto/lkgp`

(`AutoVariant` خود شامل ۶ مقدار است؛ گزینهٔ هفتم «بدون گونه» — یعنی `auto` ساده — است که توسط `parseAutoPrefix()` بهشکل `variant: undefined` مدیریت میشود.)

## جایگاه سطحها در Auto-Combo

تابع امتیازدهی ۱۶ عاملی (`open-sse/services/autoCombo/scoring.ts`) عضویت در سطح را بهعنوان دو سیگنال در نظر میگیرد: `tierPriority` (0.0476) و `tierAffinity` (0.0476). برای مشاهدهٔ مجموعهٔ کامل `DEFAULT_WEIGHTS`، جدول مرجع [عوامل امتیازدهی](#how-it-works-persisted-auto-combos) در بالا را ببینید — مقادیر بازنویسیشده برای هر بسته (ship-fast/cost-saver/quality-first/
offline-friendly) در جدول «پروفایلهای وزن برای هر بسته» فهرست شدهاند.

سطح بهتنهایی **باعث نمیشود** که Tier 1 الزاماً نخست انتخاب شود — اگر تأخیر Tier 1 نامطلوب باشد یا نسبت هزینه به کیفیت آن بهینه نباشد، Tier 2 برنده میشود. برای تحمیل ترتیب سطحها، از راهبرد ترکیبی `priority` استفاده کنید و ارائهدهندگان را بر اساس سطح مرتب کنید.

برای ترجیح شدید Tier 1 (اشتراک)، وزن `tierPriority` را افزایش دهید:

```json
{
  "strategy": "auto",
  "config": { "auto": { "weights": { "tierPriority": 0.3, "costInv": 0.05 } } }
}
```

برای تعاریف سطحها و طبقهبندی ارائهدهندگان، به `docs/marketing/TIERS.md` مراجعه کنید.

## آزمون و پوشش

### ماتریس قطعی تصمیمگیری مسیریابی (`npm run test:combo:matrix`)

`tests/integration/combo-matrix/*.test.ts` **تصمیم** مسیریابی هر ۱۹ راهبرد عمومی را بهصورت سرتاسری، از طریق خط لولهٔ واقعی combo و با upstream شبیهسازیشده، اثبات میکند.
پوشش شامل موارد زیر است:

- هر ۱۹ راهبرد `ROUTING_STRATEGY_VALUES` (ordered، weighted، cost، context، fusion، …).
- `quota-share` (داخلی) بهصورت سرتاسری: عدالت DRR + کاهش اولویت هنگام اشباع، از طریق نقطهٔ اتصال واقعی `selectQuotaShareTarget` (`registerQuotaFetcher` / `setLKGP` /
  `__setHeadroomSaturationFetcherForTests`).
- پوشش واگذاری همگانی `context-relay` برای تمام تعدادهای ممکن هدف.

این مجموعه در CI (کار `test:integration`) با `--test-concurrency=1` و
`--test-force-exit` اجرا میشود؛ بنابراین قطعی است و به اعتبارنامههای زنده نیاز ندارد.

### آزمون دود زندهٔ مشروط (در CI نیست — ارائهدهندگان واقعی)

| فرمان                                  | کاری که انجام میدهد                                                                                 |
| :------------------------------------- | :-------------------------------------------------------------------------------------------------- |
| `npm run test:combo:live`              | مسیریابی واقعی درونفرایندی با `RUN_COMBO_LIVE=1`؛ از یک پایگاه دادهٔ زندهٔ OmniRoute اسنپشات میگیرد |
| `npm run test:combo:live:vps`          | فراخوانیهای HTTP علیه یک سرور زندهٔ OmniRoute (`COMBO_LIVE_BASE_URL` را تنظیم کنید)                 |
| `npm run test:combo:live:vps:failover` | همان مورد، همراه با سناریوهای failover عمدی                                                         |

این آزمونهای دود مسیر واقعی ارتباط را آزمایش میکنند (combo → ارائهدهنده → تکمیل). آنها
عمداً از CI کنار گذاشته شدهاند، زیرا به اعتبارنامههای زنده و دسترسی VPS نیاز دارند.
