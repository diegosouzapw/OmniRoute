برخی سرویسها در OmniRoute یکپارچه شدند و بعداً، به درخواست افرادی که آنها را اداره
میکنند، حذف شدند. این صفحه سابقهای ماندگار از آن حذفها است. تنها هدف آن جلوگیری از
بازگشت تصادفی آنها است: مشارکتکنندهای که یک فورک قدیمی، یک بسته npm کششده،
یک ایشوی بایگانیشده یا درخواستی برای «بازیابی ارائهدهنده X» پیدا میکند، به یک مرجع نیاز دارد که بگوید **دوباره
اضافه نکنید**.

این صفحه فهرستی از سرویسهای ازکارافتاده یا متوقفشده **نیست**. آنها در
[`FREE_TIERS.md`](FREE_TIERS.md) («حذفشده / بدون سطح رایگان») پیگیری میشوند و اگر سرویس
بازگردد، آنها نیز میتوانند بازگردند. موارد زیر فقط با اجازه کتبی اپراتوری که در
درخواست نام برده شده است میتوانند بازگردند و پیوند آن اجازه باید در ورودی مربوطه درج شود.

## خطمشی

1. **درخواست حذف از سوی اپراتور سرویس پذیرفته میشود، نه مذاکره.** OmniRoute
   به هیچ سرویس بالادستی وابسته نیست. وقتی اپراتور یک سرویس درخواست میکند که
   یکپارچهسازی حذف شود، حذف میشود؛ چه آن یکپارچهسازی از API رسمی استفاده کرده باشد و چه نکرده باشد.
2. **«حذفشده» یعنی از تمام بخشهایی که تحت کنترل OmniRoute هستند.** اجراکننده، ورودی رجیستری، شناسه و نام مستعار
   ارائهدهنده، فهرست مدلها، نقاط پایانی، متغیرهای محیطی، آیکون، کارتهای داشبورد،
   مرجع تولیدشده ارائهدهنده، `FREE_TIERS.md`، مرجع محیط، شمارشهای README،
   نسخههای آینهای `llm.txt`، تستهای اختصاصی و اسنپشاتهای طلایی، نظرات کد، موارد CHANGELOG
   (همراه با تطبیق ثبتشده؛ `config/release/changelog-reconciliations.json` را ببینید)،
   یادداشتهای GitHub Releases، ویکی و ایشوها، گفتوگوها و درخواستهای کشش GitHub که
   موضوعشان آن ارائهدهنده بوده است (ایشوها و گفتوگوها حذف میشوند؛ عنوان درخواستهای کشش تغییر میکند،
   توضیحاتشان جایگزین و رشته گفتوگو قفل میشود، زیرا GitHub نمیتواند درخواستهای کشش را حذف کند).
3. **هرگز بدون اجازه کتبی، ورودی موجود در این صفحه را دوباره اضافه نکنید.** این شامل
   بازگرداندن شناسه یا نام مستعار به هر کاتالوگ ارائهدهنده، افزودن دامنهها به یک اجراکننده،
   پذیرفتن PR مشارکتکنندهای که آن را «بازیابی» میکند، افزودن آن به کاتالوگ مدلهای رایگان، یا
   مستندسازی روشی دستی برای دسترسی به آن از طریق OmniRoute نیز میشود. چنین PRها و ایشوهایی را با
   پیوندی به این صفحه ببندید.
4. **ورودی را مختصر نگه دارید.** فقط مواردی را ثبت کنید که بازبین برای تشخیص
   اضافهشدن مجدد نیاز دارد: شناسهها، دامنهها، تاریخها و درخواست کششی که حذف را انجام داده است.
   نحوه عملکرد یکپارچهسازی را توضیح ندهید.
5. **محافظ رگرسیون `tests/unit/removed-providers-blocklist.test.ts` است.** اگر
   هرکدام از شناسهها یا دامنههای زیر دوباره در کاتالوگهای ارائهدهندگان، نگاشت اجراکننده یا
   منابع رجیستری ارائهدهندگان ظاهر شوند، این تست شکست میخورد. شناسههای جدید را در همان PR که
   یک ردیف به اینجا اضافه میکند، به آن تست بیفزایید.

## افزودن یک ورودی

هنگامی که درخواست حذف جدیدی دریافت میشود:

1. تأیید کنید که درخواست از سوی اپراتور سرویس آمده است (نشانی پشتیبانی آنها یا
   دامنهای که کنترل میکنند) و پیام را بهصورت خصوصی نگه دارید.
2. یکپارچهسازی را مطابق چکلیست بند 2 خطمشی حذف کنید. از
   [#12440](https://github.com/diegosouzapw/OmniRoute/pull/12440) بهعنوان مرجع برای یک
   ارائهدهنده بدون کلید و از [#10210](https://github.com/diegosouzapw/OmniRoute/pull/10210) برای یک
   ارائهدهنده مبتنی بر کلید API با اتصالهای ذخیرهشده استفاده کنید (یک مهاجرت اضافه کنید).
3. در همان PR، یک ردیف به جدول بالا و شناسهها را به
   `tests/unit/removed-providers-blocklist.test.ts` اضافه کنید.
4. پس از ادغام PR به اپراتور پاسخ دهید و موارد حذفشده و مواردی را که OmniRoute
   نمیتواند تغییر دهد فهرست کنید (نسخههای npm و Docker که قبلاً منتشر شدهاند، تاریخچه git و فورکهای شخص ثالث).
