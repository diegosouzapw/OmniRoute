این سند تصمیم پیادهسازی مربوط به
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854) را ثبت میکند. محصولات عمومی بهصورت
چهار خانواده ارائهدهنده نمایش داده میشوند. منطقه، داده اتصال است و محصولی جداگانه محسوب نمیشود.

## تصمیم

| خانواده ارائهدهنده                              | شناسه OmniRoute         | منطقه جهانی | منطقه چین |
| ----------------------------------------------- | ----------------------- | ----------- | --------- |
| Alibaba Cloud Model Studio (پرداخت بهازای مصرف) | `alibaba`               | سنگاپور     | پکن       |
| Alibaba Cloud Token Plan                        | `bailian-coding-plan`   | سنگاپور     | پکن       |
| Qwen Cloud (پرداخت بهازای مصرف)                 | `qwen-cloud`            | جهانی       | پکن       |
| Qwen Cloud Token Plan                           | `qwen-cloud-token-plan` | سنگاپور     | پکن       |

شناسه موجود `alibaba-cn` بهعنوان نام مستعار سازگاری زمان اجرا برای اتصالهای ذخیرهشده، مسیرهای
مدل، ترکیبها و سوابق استفاده باقی میماند. کارت داشبورد آن در `alibaba` ادغام میشود؛ هیچ بازنویسی
پایگاه دادهای لازم نیست.

Qwen Cloud با پرداخت بهازای مصرف و Alibaba Cloud Model Studio در حال حاضر از میزبانهای زمان اجرای
سازگار با DashScope مشترک استفاده میکنند، اما هویتهای ارائهدهنده جداگانه باقی میمانند، زیرا کاربران
کلیدها را دریافت کرده و حسابها را از طریق سطوح محصول متفاوت مدیریت میکنند. محصولات Alibaba و Qwen Cloud Token Plan
از خانوادههای نقطه پایانی متفاوتی استفاده میکنند؛ بنابراین هر چهار محصول بهعنوان شناسههای ارائهدهنده
جداگانه باقی میمانند.

## ماتریس نقاط پایانی

| خانواده ارائهدهنده      | `global-sg`                                                              | `china-beijing`                                                      | قالب انتقال |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ----------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI      |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic   |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI      |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI      |

کلید API و نقطه پایانی باید متعلق به یک محصول و منطقه یکسان باشند. انتخاب یک منطقه،
نقطه پایانی ازپیشتنظیمشده مورد استفاده برای اعتبارسنجی و درخواستهای عادی را تغییر میدهد.

## قرارداد اتصال

اتصالهای جدید، کلید پایدار منطقه را در `providerSpecificData` ذخیره میکنند:

```json
{
  "region": "global-sg"
}
```

مقادیر مجاز `global-sg` و `china-beijing` هستند. نقطه پایانی بهصورت متمرکز از شناسه
ارائهدهنده و منطقه استخراج میشود. یک `providerSpecificData.baseUrl` که ازپیشتنظیمشده نیست، همچنان
بهعنوان جایگزینی صریح توسط اپراتور باقی میماند و اولویت دارد، درحالیکه URLهای ازپیشتنظیمشده قدیمی
به ماتریس منطقهای بازگردانده و نرمالسازی میشوند.

این کار طرحواره اتصال را توسعهپذیر نگه میدارد: میتوان منطقه دیگری را بدون ایجاد
کارت ارائهدهندهای دیگر یا تغییر شناسههای ارائهدهنده ذخیرهشده، به حلکننده اضافه کرد.

## سازگاری و عرضه

1. تفکیککنندهٔ نقطه پایانی منطقهای را اضافه کنید و پیشفرضهای سراسری فعلی را حفظ کنید.
2. از کشف زندهٔ `/models` منطقهای DashScope برای `alibaba`، شناسهٔ سازگاری آن یعنی `alibaba-cn` و `qwen-cloud` استفاده کنید. پاسخهای آنها ابتدا از یک فیلتر تولید متن عبور میکنند، زیرا نقطه پایانی عمومی مدلهای تصویر، ویدئو، صوت، تعبیهسازی و سایر مدلهای غیرگفتوگویی را نیز برمیگرداند. سپس `qwen-cloud` فهرست مجاز نگهداریشدهای را اعمال میکند که در رجیستری ارائهدهندهٔ آن تعریف شده است. Alibaba Model Studio و Qwen Cloud، با وجود اینکه در حال حاضر از میزبانهای زمان اجرای مشترک استفاده میکنند، کاتالوگهای گزینششدهٔ جداگانهای را حفظ میکنند.
3. `qwen-cloud-token-plan` را با فهرست مجاز فعلی مدلهای متنی Token Plan ثبت کنید.
4. یک انتخابگر منطقهٔ نوعدار به پنجرههای افزودن/ویرایش اتصال اضافه کنید.
5. کارت تکراری `alibaba-cn` را پنهان کنید و اتصالهای موجود آن را در صفحهٔ ارائهدهندهٔ `alibaba` بگنجانید.
6. امکان بازنویسی سفارشی نقاط پایانی را برای استقرارهای پیشرفته و مختص فضای کاری حفظ کنید.

مدلهای رسانهای Token Plan خارج از کاتالوگ گفتوگو باقی میمانند، زیرا از نقاط پایانی اختصاصی استفاده میکنند.
`wan2.7-image` و `wan2.7-image-pro` در `open-sse/config/imageRegistry.ts` ثبت شدهاند؛
`happyhorse-1.1-i2v`، `happyhorse-1.1-t2v` و `happyhorse-1.1-r2v` در
`open-sse/config/videoRegistry.ts` ثبت شدهاند. هر دو رجیستری از هویت اتصال
`qwen-cloud-token-plan` و اعتبارنامههای مختص منطقهٔ آن مجدداً استفاده میکنند.

Qwen Cloud معمولی، کاتالوگهای جداگانهٔ پرداخت بهازای مصرف برای تصویر و ویدئو تحت هویت
`qwen-cloud` دارد. مدلهای تصویری آن عبارتاند از `wan2.7-image-pro`، `wan2.7-image`، `qwen-image-3.0-pro`،
`qwen-image-2.0-pro-2026-06-22`، `qwen-image-2.0-2026-03-03` و `z-image-turbo`. مدلهای ویدئویی
آن عبارتاند از `happyhorse-1.1-i2v`، `happyhorse-1.1-t2v`، `happyhorse-1.1-r2v`،
`happyhorse-1.0-video-edit`، `wan2.7-t2v`، `wan2.7-i2v`، `wan2.7-r2v-2026-06-12` و
`wan2.7-videoedit`. این مدلها فقط از اتصال معمولی `qwen-cloud` و نقطه پایانی رسانهای منطقهای
DashScope مجدداً استفاده میکنند. رجیستریهای Token Plan و پرداخت بهازای مصرف، فهرست مدلهای
یکدیگر را به ارث نمیبرند یا با هم ادغام نمیکنند.

هویت `bailian-coding-plan` نیز فهرستهای مجاز رسانهای مخصوص خود را دارد:
`wan2.7-image`، `wan2.7-image-pro`، `qwen-image-2.0` و `qwen-image-2.0-pro` برای تولید
تصویر، بهعلاوهٔ
`happyhorse-1.1-i2v`، `happyhorse-1.1-t2v` و `happyhorse-1.1-r2v` برای تولید
ویدئو. این هویت فقط از اتصال Bailian Coding Plan و نقطه پایانی منطقهای Coding Plan استفاده میکند.
رجیستریهای تصویر و ویدئوی آن از هیچیک از ارائهدهندگان Qwen Cloud به ارث برده نمیشوند و با آنها ادغام نمیشوند.

هویت معمولی `alibaba` فهرستهای مجاز جداگانهای برای تصویر و ویدئو دارد. مدلهای تصویری آن
عبارتاند از `qwen-image-3.0-pro`، `qwen-image-2.0-pro-2026-06-22`، `qwen-image-2.0`،
`z-image-turbo` و `wan2.6-t2i`. مدلهای ویدئویی افزودهشدهٔ آن عبارتاند از `happyhorse-1.1-i2v`،
`happyhorse-1.1-t2v`، `happyhorse-1.1-r2v`، `happyhorse-1.0-video-edit`،
`wan2.7-i2v-2026-04-25`، `wan2.6-i2v-flash`، `wan2.7-t2v-2026-06-12`،
`wan2.7-r2v-2026-06-12` و `wan2.7-videoedit`. این مدلها فقط از اتصال Alibaba Model Studio
و نقطه پایانی رسانهای منطقهای انتخابشدهٔ آن استفاده میکنند؛ آنها به هیچ رجیستری Coding Plan یا Qwen
Cloud اضافه نمیشوند.

کاتالوگ گفتوگوی Qwen Cloud Token Plan از فهرست مجاز متنی با تطبیق دقیق رشتهایِ طرح Individual پیروی میکند:
`qwen3.8-max-preview`، `qwen3.7-max`، `qwen3.7-plus`، `qwen3.6-flash`، `glm-5.2` و
`deepseek-v4-pro`. ورودیهای Wan و HappyHorse به APIهای جداگانهٔ تولید تصویر/ویدئو تعلق دارند.

Alibaba Token Plan همان شش شناسهٔ فعلی مدل تولید متن را از طریق نقطه پایانی سازگار با
Anthropic ارائه میکند. گزینهٔ سنگاپور آن کلید منطقهای موجود `global-sg` را ذخیره میکند؛
فقط برچسبی که به کاربر نمایش داده میشود با خانوادههای ارائهدهندهای که این منطقه را Global مینامند، تفاوت دارد.

کاتالوگ گفتوگوی معمولی Qwen Cloud عمداً محدودتر از پاسخ کامل و زندهٔ متنی است. فهرست مجاز
نگهداریشدهٔ آن در `open-sse/config/providers/registry/qwen-cloud/index.ts` قرار دارد؛ کشف زنده
فقط شناسههایی را برمیگرداند که هم در پاسخ بالادستی و هم در فهرست آن رجیستری وجود داشته باشند.

Alibaba Model Studio از همان قاعدهٔ اشتراک با دادههای زنده پیروی میکند، اما فهرست مجاز آن بهطور مستقل
در `open-sse/config/providers/registry/alibaba/index.ts` نگهداری میشود. ارائهدهندهٔ سازگاری
`alibaba-cn` هنگام انجام کشف از طریق نقطه پایانی پکن، از همان کاتالوگ مجدداً استفاده میکند.
