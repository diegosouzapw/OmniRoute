`copilot-m365-web` (نام مستعار `m365copilot`) درخواستهای چت با فرمت OpenAI را از طریق یک نشست مرورگر احراز هویتشده Microsoft 365 Copilot BizChat در
`m365.cloud.microsoft/chat` ارسال میکند. این یک یکپارچهسازی غیررسمی است.

> **با ارائهدهندگان Web Cookie تازه آشنا شدهاید؟**
>
> پیش از دنبال کردن این راهنمای مختص ارائهدهنده، برای آشنایی با فرایند کلی راهاندازی، راهنمای احراز هویت، محدودیتها و عیبیابی، **`docs/getting-started/WEB-COOKIE-GUIDE.md`** را مطالعه کنید.
>
> **مهم:** اعتبارنامه این ارائهدهنده **کوکی نیست**. کوکیها را از
> `m365.cloud.microsoft` کپی نکنید. اعتبارنامه شامل یک پارامتر کوئری URL مربوط به WebSocket و یک بخش مسیر است که هر دو از زبانه Network در DevTools خوانده میشوند.

## پیشنیازها

- یک حساب Microsoft 365 با دسترسی به BizChat در `m365.cloud.microsoft/chat`
- یک مرورگر مبتنی بر Chromium‏ (Chrome، Edge) برای بررسی WebSocket در DevTools
- یک مجوز M365 Copilot (همراه بسیاری از طرحهای Microsoft 365 Business/Enterprise ارائه میشود)

## دریافت اعتبارنامه (روش WebSocket)

1. در `https://m365.cloud.microsoft/chat` وارد شوید و یک مکالمه را آغاز کنید.
2. **DevTools → Network** را باز کنید.
3. بر اساس **WS**‏ (WebSocket) فیلتر کنید.
4. روی اتصال WebSocket مربوط به Chathub کلیک کنید. بهدنبال URLای بگردید که با
   `wss://substrate.office.com/m365Copilot/Chathub/` آغاز میشود.
5. از **Request URL** آن، موارد زیر را کپی کنید:
   - مقدار پارامتر کوئری `access_token` (یک JWT کوتاهعمر).
   - بخش مسیر Chathub پس از `/Chathub/` (برای مثال `<oid>@<tenant>`).

URL کامل دارای قالب زیر است:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. در OmniRoute، به **Providers → Add Provider** بروید، **Microsoft 365 Copilot
   (BizChat)** را انتخاب کنید و اعتبارنامه را با قالب زیر جایگذاری کنید:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. روی **Test Connection** و سپس **Save** کلیک کنید.

## دریافت اعتبارنامه (وارد کردن HAR)

بهجای کپی دستی مقادیر از URL مربوط به WebSocket، میتوانید یک فایل HAR از DevTools صادر کنید:

1. **DevTools → Network** را باز کنید.
2. یک مکالمه BizChat را آغاز یا ادامه دهید (این کار اتصال WebSocket را فعال میکند).
3. در پنل Network راستکلیک کنید و **Save all as HAR with content** را انتخاب کنید.
4. در OmniRoute، از دکمه **Import .har file** در پنجره اتصال ارائهدهنده استفاده کنید.

OmniRoute فایل HAR را برای یافتن URL مربوط به WebSocket‏ Chathub اسکن میکند، مقادیر
`access_token` و `chathubPath` را استخراج میکند و فیلدهای اعتبارنامه را بهصورت خودکار پر میکند. وارد کردن HAR، زمان انقضای JWT را رمزگشایی کرده و مدت اعتبار باقیمانده توکن را نمایش میدهد.

> **هرگز یک فایل HAR واقعی، توکن دسترسی یا توکن نوسازی را commit نکنید.** مقادیر مورد استفاده در آزمونها و مستندات باید همیشه جاینگهدار باشند.

## طول عمر و نوسازی توکن

`access_token` کوتاهعمر است (معمولاً **حدود ۷۵ دقیقه**). پس از انقضا، ارائهدهنده یک خطای اتصال گزارش میکند و باید اعتبارنامه را دوباره دریافت کنید.

### نوسازی خودکار با `refreshToken`

برای جلوگیری از دریافت دستی مجدد، میتوانید یک توکن نوسازی Microsoft را در
**Advanced Settings → providerSpecificData** اتصال ذخیره کنید:

| فیلد           | توضیحات                                                               |
| -------------- | --------------------------------------------------------------------- |
| `refreshToken` | توکن نوسازی Microsoft OAuth برای محدوده `substrate.office.com/sydney` |
| `tier`         | `individual` (پیشفرض)، `edu` یا `enterprise`                          |

توکن نوسازی را از یک جریان device-code یا authorization-code مایکروسافت با محدوده
`substrate.office.com/sydney` دریافت کنید. با تنظیم `refreshToken`، ‏OmniRoute پیش از هر درخواست `access_token` را از قبل نوسازی میکند؛ بنابراین لازم نیست پس از هر انقضای حدوداً ۷۵ دقیقهای، اعتبارنامه را دوباره دریافت کنید.

اگر `refreshToken` تنظیم نشده باشد، باید پس از هر انقضا، اعتبارنامه WebSocket را بهصورت دستی دوباره دریافت کنید.

### انتخاب سطح

| سطح          | نام مستعار | محیط                       |
| ------------ | ---------- | -------------------------- |
| `individual` | _(پیشفرض)_ | M365 Copilot مصرفکنندگان   |
| `edu`        | `included` | M365 Copilot آموزشی        |
| `enterprise` | `work`     | M365 Copilot برای محیط کار |

سطح را در **Advanced Settings → providerSpecificData → tier** تنظیم کنید. سطح انتخابشده بر مسیریابی BizChat و دسترسی به مدل تأثیر میگذارد.

## مدل امنیتی

- **یکپارچهسازی غیررسمی.** این ارائهدهنده پروتکل WebSocket مربوط به BizChat را با مهندسی معکوس پیادهسازی میکند. اگر Microsoft نقطه پایانی را تغییر دهد، ممکن است بدون اطلاع قبلی از کار بیفتد.
- پرچم `subscriptionRisk: true` نشان میدهد که این یکپارچهسازی به یک نقطه پایانی مستندنشده متکی است. احتمال اعمال محدودیت روی حساب وجود دارد، اما تأیید نشده است.
- توکن دسترسی یک JWT کوتاهعمر است. با آن مانند رمز عبور رفتار کنید: آن را commit نکنید، در log ننویسید و به اشتراک نگذارید.
- توکن نوسازی، دسترسی بلندمدت به رابط BizChat را فراهم میکند. آن را با همان سطح مراقبتی که برای یک کلید API به کار میبرید، نگهداری کنید.

## عیبیابی

### احراز هویت بلافاصله ناموفق میشود

- بررسی کنید که مقدار را از **URL مربوط به WebSocket** کپی کردهاید، نه از یک درخواست XHR/Fetch. اعتبارنامه در پارامتر query با نام `access_token` در اتصال WebSocket مربوط به Chathub قرار دارد — نه در هدر `Authorization: Bearer`.
- مطمئن شوید `chathubPath` شامل بخش کامل `<oid>@<tenant>` از مسیر URL است.

### توکن پس از حدود 75 دقیقه منقضی میشود

این رفتار مورد انتظار است. بدون `refreshToken`، توکن دسترسی کوتاهعمر خواهد بود. یکی از این کارها را انجام دهید:

- اعتبارنامه را دوباره از DevTools دریافت کنید، یا
- برای نوسازی خودکار، یک `refreshToken` را در تنظیمات پیشرفته پیکربندی کنید.

### آزمایش اتصال موفق است، اما چت خطای 401 برمیگرداند

ممکن است توکن در فاصله بین اعتبارسنجی و اولین درخواست منقضی شده باشد. یک اعتبارنامه جدید دوباره دریافت کنید.

### Copilot در فهرست ارائهدهندگان نمایش داده نمیشود

مطمئن شوید `copilot-m365-web` در **داشبورد ← ارائهدهندگان** فعال است. ممکن است این ارائهدهنده در برخی سطوح بهصورت پیشفرض مخفی باشد.
