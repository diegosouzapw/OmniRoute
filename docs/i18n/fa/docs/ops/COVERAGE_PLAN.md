## قواعد

- اهداف پوشش برای فایلهای منبع اعمال میشوند، نه برای `tests/**`.
- `open-sse/**` بخشی از محصول است و باید در محدوده باقی بماند.
- کد جدید نباید پوشش را در بخشهای تغییریافته کاهش دهد.
- آزمون رفتار و نتایج شاخهها را به جزئیات پیادهسازی ترجیح دهید.
- برای `src/lib/db/**`، پایگاههای داده موقت SQLite و دادههای آزمون کوچک را به ماکهای گسترده ترجیح دهید.

## مجموعه دستورات فعلی

- `npm run test:coverage`
  - دروازه اصلی پوشش کد منبع برای مجموعه آزمون واحد
  - `text-summary`، `html`، `json-summary` و `lcov` را تولید میکند
- `npm run coverage:report`
  - گزارش تفصیلی فایلبهفایل از آخرین اجرا
- `npm run test:coverage:legacy`
  - فقط برای مقایسه تاریخی

## سیاست جغجغهای

آستانههای `npm run test:coverage` را تنها زمانی بهروزرسانی کنید که پروژه واقعاً با حاشیهای مطمئن از نقطهٔ عطف بعدی عبور کرده باشد.

**حد فعلی:** `npm run test:coverage` مقادیر **60 دستور / 60 خط / 60 تابع / 60 شاخه** را اعمال میکند (معیار در Quality-Gates Fase 6A.1 مجدداً مبناگذاری شد — خط مبنای قبلی 82.58% بیشبرآورد شده بود، زیرا فایلهای آزمون را محاسبه و `open-sse` را مستثنا میکرد). فرمان `test:coverage:legacy` معیار قدیمی 50/50/50 را برای مقایسهٔ تاریخی حفظ میکند.

برای بررسی موردی آستانهها در برابر آخرین گزارش، از این فرمان استفاده کنید:

```bash
node scripts/check/test-report-summary.mjs --threshold 75
```

## شکاف شناختهشده

فرمان فعلی پوشش، مجموعهٔ اصلی آزمونهای واحد Node را اندازهگیری میکند و کد منبعی را که از طریق آن اجرا میشود، از جمله `open-sse`، در بر میگیرد. این فرمان هنوز پوشش Vitest را در یک گزارش یکپارچه ادغام نمیکند. انجام این ادغام در آینده ارزشمند است، اما مانعی برای آغاز صعود از 60% به 80% محسوب نمیشود.
