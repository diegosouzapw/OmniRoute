> **یادداشت دامنه:** `socket.yml` اسکن پس از انتشارِ سمت رجیستری Socket.dev را برای آرتیفکت npm پیکربندی میکند (مسیرهای نادیدهگرفتهشده برای محتوایی که منتشر نمیشود، مانند `tests/`، `docs/` و گزارشهای ساخت). این فایل یک دروازه ادغام CI/PR ایجاد نمیکند — هیچ گردش کاری در `.github/workflows`، هیچ اسکریپتی در `package.json` و هیچ هدفی در `Makefile`، Socket.dev را فراخوانی نمیکند.

این سند، گواهی تدوینشده توسط نگهدارنده برای شش یافته
`AI-detected potential malware` مطرحشده درباره `omniroute@3.8.5` و
اقدامات کاهشی اعمالشده در `omniroute@3.8.6` است. این سند وجود دارد تا:

1. گردانندگان خط لوله امنیتی، هنگامی که نیاز دارند یافتهها را در برابر
   کد منبع واقعی ارزیابی کنند، مرجعی واحد برای استناد داشته باشند.
2. اسکنرهای هوش مصنوعی آینده بتوانند ادعای امضاشده توسط نگهدارنده را تشخیص دهند که هر
   مسیر علامتگذاریشده، عمدی، اختیاری و مستندسازیشده است.
3. سابقهای مکتوب از _چرایی_ شکل فعلی هر محل فراخوانی داشته باشیم —
   تا بازآرایی کد در آینده بهطور تصادفی اثری را که عمداً
   حذف شده بود، دوباره ایجاد نکند.

اگر اسکنری را اجرا میکنید که پس از انتشار اقدامات کاهشی
v3.8.6 هر یک از محلهای فراخوانی زیر را دوباره علامتگذاری میکند، لطفاً یک issue بههمراه ردّ اسکن باز کنید تا
گواهی اینجا را گسترش دهیم.

## §1 — نصب CA ریشهٔ MITM (`77484.js`)

**فایلهای منبع**:

- `src/mitm/cert/install.ts` — توابع عمومی `installCert()` / `uninstallCert()` و
  توابع مختص هر پلتفرم `installCertWindows/Mac/Linux`.
- `src/mitm/systemCommands.ts` — توابع کمکی مشترک `execFile` / `spawn` / PowerShell
  که توسط مسیرهای نصب استفاده میشوند.

**محرک**: کاربر در داشبورد محلی در
`/dashboard/cli-tools/mitm` روی «فعالسازی پروکسی MITM» کلیک میکند. این مسیر فقط از loopback قابل دسترسی است — قانون سختگیرانهٔ شمارهٔ 17 را در
`CLAUDE.md` و `src/server/authz/routeGuard.ts::isLocalOnlyPath()` ببینید. یک JWT افشاشده
از طریق تونل **نمیتواند** این مسیر کد را فعال کند.

**عملیات دارای دسترسی ویژه که انجام میشوند (به تفکیک پلتفرم)**:

| سیستمعامل              | فرمان(ها)                                                                                                         |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | `certutil -addstore Root <cert>` از طریق UAC                                                                      |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | بهروزرسانی پایگاه دادهٔ NSS برای هر پروفایل از طریق `certutil -d sql:<profile>`                                   |

اینها همان فرمانهایی هستند که توسط `mitmproxy`، Charles Proxy، Fiddler و
Caddy استفاده میشوند. وجود آنها در OmniRoute در
`docs/security/STEALTH_GUIDE.md` مستند شده است.

**راهکار کاهشی v3.8.6**:

- `runElevatedPowerShell()` دیگر از `-EncodedCommand <base64utf16le>` استفاده نمیکند.
  payload دارای دسترسی ارتقایافته در یک فایل موقت `.ps1` مختص هر فراخوانی نوشته میشود (با حالت 0o600،
  داخل یک دایرکتوری خصوصی `mkdtempSync`) و از طریق `-File` به آن ارجاع داده میشود. این
  فایل در `finally` حذف میشود. این تغییر، اثرانگشت شناختهشدهٔ
  ارتقای دسترسی از طریق PowerShell با استفاده از base64 را که توسط دستهبند هوش مصنوعی Socket.dev
  علامتگذاری شده بود، حذف میکند.
- `installCertWindows` شامل یک بلوک درونخطی `SECURITY-AUDITOR-NOTE:` است
  که به این سند اشاره میکند.

**چرا آن را حفظ میکنیم**: پروکسی MITM یک قابلیت مستندسازیشده است که توسط
`docs/security/STEALTH_GUIDE.md` و `docs/frameworks/MITM-PROXY.md` استفاده میشود. حذف
آن، مجموعه قابلیتهای agent-bridge را مختل میکند.

## §2 — وارد کردن اعتبارنامههای Zed (`app/api/providers/zed/import/route.js`)

**فایلهای منبع**:

- `src/app/api/providers/zed/discover/route.ts` _(جدید در v3.8.6)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(جدید در v3.8.6)_

**محرک**: کاربر در صفحه Providers داشبورد محلی روی «Import from Zed» کلیک میکند. دسترسی به نقطه پایانی توسط `requireManagementAuth` کنترل میشود. خود ویرایشگر Zed کلیدهای API ارائهدهندگان را با نامهای سرویس مستندشده در زنجیرهکلید سیستمعامل ذخیره میکند — به https://zed.dev/docs/ai/llm-providers مراجعه کنید.

**رفتار v3.8.5 (نسخهای که Socket.dev علامتگذاری کرد)**:

`POST /import` اعتبارنامهها را کشف میکرد و آنها را در یک رفتوبرگشت بهطور خودکار در ذخیرهساز محلی SQLite ذخیره میکرد. بدون تأیید جداگانه برای هر حساب و بدون اثر انگشت؛ فقط «N توکن پیدا شد و همه وارد شدند.»

**راهکار کاهش خطر در v3.8.6 — تأیید دومرحلهای**:

1. **`POST /api/providers/zed/discover`** مقدار
   `{ candidates: [{ provider, service, account, fingerprint }] }` را برمیگرداند. توکن خام **هرگز** منتقل نمیشود. اثر انگشت برابر است با
   `sha256(service|account|token).slice(0,16)`.
2. داشبورد فهرست گزینهها را نمایش میدهد، اپراتور موارد موردنظر برای وارد کردن را انتخاب میکند و
   `{ confirmedAccounts: [{ service, account, fingerprint }] }`
   را به **`POST /api/providers/zed/import`** ارسال میکند.
3. نقطه پایانی وارد کردن، **زنجیرهکلید را دوباره در سرور میخواند** و بر اساس
   `(service, account, fingerprint)` فیلتر میکند. پاسخ دستکاریشده یا بازپخششدهٔ discover نمیتواند نقطه پایانی وارد کردن را فریب دهد تا توکنی نامرتبط را ذخیره کند — اگر توکن فعال از زمان discover تغییر کرده باشد، اثر انگشت دیگر مطابقت نخواهد داشت و اعتبارنامه نادیده گرفته میشود.

پرچم محیطی `OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` رفتار v3.8.5 را برای اپراتورهایی که هنوز اتوماسیون خود را بهروزرسانی نکردهاند حفظ میکند. این پرچم در v3.9 حذف خواهد شد.

**چرا آن را نگه میداریم**: وارد کردن از Zed سادهترین مسیر شروع به کار برای کاربرانی است که از قبل از Zed استفاده میکنند و میخواهند کلیدهای ارائهدهندگان خود را بدون جایگذاری مجدد در OmniRoute همگامسازی کنند.

## §3 — `execFile` / `spawn` / PowerShell با سطح دسترسی بالا (`21843.js`)

**فایلهای منبع**: `src/mitm/systemCommands.ts`.

**دلیل علامتگذاری**: این قطعه، `execFileWithPassword`،‏
`runElevatedPowerShell` و ابزار کمکی مشترک `quotePowerShell` را دوباره صادر میکند. دستهبند هوش مصنوعی Socket.dev آنها را بهعنوان یک «مجموعهابزار عمومی اجرای دستورات روی میزبان + ارتقای سطح دسترسی» تشخیص میدهد. در OmniRoute، این موارد فقط توسط مسیر نصب گواهی MITM (§1) و توسط `execFileWithPassword` برای اجرای فرمان `sudo` استفاده میشوند.

**راهکار کاهش خطر در v3.8.6**:

- بازآرایی `runElevatedPowerShell` (به §1 مراجعه کنید).
- بلوک درونخطی `SECURITY-AUDITOR-NOTE:` در هر دو محل
  `runElevatedPowerShell` و `execFileWithPassword`، فراخوانندههای مجاز و فهرست ثابت فایلهای اجرایی را مستند میکند.
- فراخوانی `spawn()` در `execFileWithPassword` دارای یک نشانگر `nosemgrep` بههمراه فهرست مجاز فایلهای اجرایی است که این تابع کمکی اجازه دریافت آنها را دارد — **هیچ مسیری از ورودی کاربر به `finalCommand`/`finalArgs` وجود ندارد**.

## §4 / §6 — ناظر سرویس 9router (`api/services/9router/{start,restart}/route.js`)

**فایلهای منبع**:

- `src/app/api/services/9router/_lib.ts` — کارخانه ناظر.
- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`.
- `src/lib/services/ServiceSupervisor.ts` — راهاندازی عمومی / نظرسنجی سلامت / بافر گزارش.

**محرک**: کاربر در صفحه سرویسهای تعبیهشده در داشبورد محلی روی «Install» / «Start» کلیک میکند.

**محافظتهای ازپیشموجود**:

- همه مسیرهای `/api/services/*` مطابق
  `src/server/authz/routeGuard.ts` فقط محلی (`LOCAL_ONLY`) هستند (قانون قطعی #17). اعمال محدودیت loopback پیش از هرگونه بررسی احراز هویت انجام میشود — حتی JWT افشاشده نیز نمیتواند به آنها دسترسی پیدا کند.
- ردیف پایگاهداده 9router با مقادیر `status='not_installed', auto_start=0` مقداردهی اولیه میشود (به
  `src/lib/db/migrations/071_services.sql:19` مراجعه کنید). سرویس در نخستین اجرا **راهاندازی نمیشود**.
- `spawn()` با مسیر فایل دودویی برگرداندهشده توسط
  `resolveSpawnArgs(apiKey, PORT)` در `src/lib/services/installers/ninerouter.ts` فراخوانی میشود؛ این تابع از فهرست ثابتی از فایلهای دودویی پشتیبانیشده استفاده میکند.
- خروجیهای Stdout/stderr در حافظه بافر میشوند (با سقف 5 MB؛ به `_lib.ts` مراجعه کنید) — هیچ نوشتنی روی دیسک انجام نمیشود، مگر اینکه کاربر ثبت گزارش را از داشبورد فعال کند.

**راهکار کاهش خطر در v3.8.6**: هیچ تغییر عملکردی وجود ندارد. پروفایل ساخت حداقلی
(`OMNIROUTE_BUILD_PROFILE=minimal`) برای کاربرانی که میخواهند مسیرهای دارای دسترسی ویژه بهصورت فیزیکی از بسته حذف شوند، فایل
`src/lib/services/installers/ninerouter.ts` را با یک پیادهسازی جایگزین خنثی جایگزین میکند.

**چرا آن را نگه میداریم**: 9router یک سرویس همراه اختیاری و قابلنصب بهصورت محلی است (مشابه افزونه WordPress) — فعالسازی آن کاملاً داوطلبانه است.

## §5 — بازنویسی اعتبارنامه در همگامسازی ابری OmniRoute (`api/keys/[id]/route.js`)

**فایلهای منبع**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`.
- `src/app/api/keys/[id]/route.ts` — `syncKeysToCloudIfEnabled()` را فراخوانی میکند.

**محرک**: `isCloudEnabled()` مقدار `true` را برمیگرداند (که از طریق داشبورد تنظیم میشود) **و**
`CLOUD_URL` پیکربندی شده است. وقتی هر دو غیرفعال باشند، هیچ فراخوانی شبکهای خروجی به
نقطه پایانی Cloud انجام نمیشود.

**رفتار v3.8.5 (اشکالی که Socket.dev بهدرستی شناسایی کرد)**:

`updateLocalTokens()` مقادیر `accessToken`، `refreshToken` و
`providerSpecificData` را از پاسخ Cloud بازنویسی میکرد، مشروط بر اینکه
`cloudUpdatedAt > localUpdatedAt` باشد. بدون HMAC، بدون امضا، بدون checksum. یک
`CLOUD_URL` با پیکربندی نادرست یا خصمانه (یا یک MITM در کانال) میتوانست
توکنهای OAuth ارائهدهنده را بیسروصدا جایگزین کند.

**راهکار کاهش خطر در v3.8.6**:

1. **اعتبارسنجی HMAC**: تابع `verifyCloudSignature(rawBody, sigHeader)`
   هدر `X-Cloud-Sig` را (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`) پیش از تجزیه JSON بررسی میکند. اگر secret تنظیم شده باشد، وجود امضا
   الزامی است. در غیر این صورت (حالت قدیمی)، یک هشدار ثبت میشود و پاسخ
   پذیرفته میشود — در v3.9 وجود secret الزامی خواهد شد.
2. **فعالسازی اختیاری فیلدهای محرمانه**: مقادیر `accessToken` / `refreshToken` /
   `providerSpecificData` **فقط** زمانی بازنویسی میشوند که
   `OMNIROUTE_CLOUD_SYNC_SECRETS=true` باشد. حالت پیشفرض فقط
   فرادادههای غیرمرتبط با اعتبارنامه (`expiresAt`، `status`، `lastError*`،
   `rateLimitedUntil`، `updatedAt`) را همگامسازی میکند. این یک **تغییر ناسازگار** برای کاربرانی
   است که به همگامسازی راهدور توکنها متکی بودند — آنها باید صراحتاً آن را فعال کنند.

**چرا آن را حفظ میکنیم**: همگامسازی ابری تنها راهی است که یک مستأجر OmniRoute Cloud
میتواند اعتبارنامههای تیم را متمرکز کند. این اصلاح، مدل تهدید را شفاف میکند:
«سرور امضا میکند، کلاینت اعتبارسنجی میکند و اپراتور آن را فعال میکند.»

## پروفایل ساخت: `minimal`

برای کاربرانی که به یک artifact سازگار با Socket نیاز دارند، با دستور زیر build کنید:

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

پلاگین `NormalModuleReplacementPlugin` در webpack چهار ماژول را به stubها alias میکند:

| ماژول                                       | Stub                                             |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

هر stub همان سطح رابط را export میکند، اما هر تابع در زمان اجرا یک
`featureDisabledError(name)` پرتاب میکند. routeهایی که به ماژول غیرفعالشده
وابستهاند، بهجای فعالکردن مسیر کد حساس، HTTP 503 را همراه با پیامی شفاف
برمیگردانند.

باندل حاصل برای انتشار با نام `omniroute-secure` در نظر گرفته شده است. برای
دستورالعمل انتشار به `docs/ops/PUBLISHING_SECURE.md` مراجعه کنید.
