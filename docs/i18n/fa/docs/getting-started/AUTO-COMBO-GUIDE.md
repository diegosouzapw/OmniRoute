## چه کاری انجام میدهد

بهجای انتخاب یک مدل هوش مصنوعی مشخص (مانند GPT-4o یا Claude)، میتوانید اجازه دهید OmniRoute برای هر درخواست **بهطور خودکار بهترین مدل را انتخاب کند**. این سامانه موارد زیر را در نظر میگیرد:

- **سلامت** — آیا ارائهدهنده در حال حاضر کار میکند؟
- **سرعت** — چقدر سریع است؟
- **هزینه** — چقدر هزینه دارد؟
- **کیفیت** — آیا برای این نوع وظیفه مناسب است؟
- **ظرفیت** — آیا سهمیهٔ باقیمانده دارد؟

OmniRoute به همهٔ ارائهدهندگان متصل شما امتیاز میدهد و بهترین گزینه را انتخاب میکند. اگر آن گزینه با خطا مواجه شود، بهطور خودکار گزینهٔ بعدی را امتحان میکند.

## شروع سریع

**مرحلهٔ ۱**: مدل خود را در IDE یا CLI روی `auto` تنظیم کنید:

```
model: "auto"
```

**مرحلهٔ ۲**: تمام شد! OmniRoute بقیهٔ کارها را انجام میدهد.

**مرحلهٔ ۳** (اختیاری): برای وظایف خاص از یک گونه استفاده کنید:

```
model: "auto/coding"    # بهترین گزینه برای کدنویسی
model: "auto/fast"      # سریعترین پاسخ
model: "auto/cheap"     # ارزانترین گزینه
```

## از کدام «auto» استفاده کنم؟

| اگر میخواهید...          | از این استفاده کنید | مناسب برای                      | نحوهٔ کار                                      |
| ------------------------ | ------------------- | ------------------------------- | ---------------------------------------------- |
| **بهترین گزینهٔ کلی**    | `auto`              | پرسشهای عمومی، گفتوگو           | ایجاد تعادل میان سرعت، هزینه و کیفیت           |
| **بهترین گزینه برای کد** | `auto/coding`       | نوشتن کد، اشکالزدایی            | انتخاب مدلهای مناسب برای وظایف کدنویسی         |
| **سریعترین پاسخ**        | `auto/fast`         | پاسخهای سریع، تأخیر کم          | اولویت دادن به سرعت بیش از هر چیز دیگر         |
| **ارزانترین گزینه**      | `auto/cheap`        | صرفهجویی در هزینه               | انتخاب ارزانترین ارائهدهنده                    |
| **هوشمندترین مدل**       | `auto/smart`        | وظایف پیچیده                    | اولویت دادن به کیفیت + بررسی مدلهای جدید       |
| **بیشترین دسترسپذیری**   | `auto/offline`      | هنگامی که ارائهدهندگان مشغولاند | انتخاب ارائهدهندگانی که بیشترین ظرفیت را دارند |

### نمونهها

```bash
# گفتوگوی عمومی — متعادل
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'

# تولید کد — اولویت با کیفیت
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/coding","messages":[{"role":"user","content":"Write a Python function"}]}'

# پاسخ سریع — اولویت با سرعت
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/fast","messages":[{"role":"user","content":"What is 2+2?"}]}'
```

## نحوهٔ کار (نسخهٔ ساده)

هنگامی که درخواستی با `model: "auto"` ارسال میکنید، OmniRoute:

1. **همهٔ ارائهدهندگان متصل شما را بررسی میکند** — هر ارائهدهندهای که اضافه کردهاید (OpenAI، Anthropic، Google و غیره)
2. **به هرکدام امتیاز میدهد** و از جمله موارد زیر را وزندهی میکند:
   - آیا کار میکند؟ (سلامت)
   - آیا ظرفیت دارد؟ (سهمیه)
   - چقدر هزینه دارد؟ (قیمت)
   - چقدر سریع است؟ (سرعت)
   - آیا برای این وظیفه مناسب است؟ (کیفیت)
3. **بهترین گزینه را انتخاب میکند** — ارائهدهندهای با بالاترین امتیاز درخواست شما را دریافت میکند
4. **بهطور خودکار بازیابی میشود** — اگر با خطا مواجه شود، OmniRoute بهطور خودکار گزینهٔ بعدی را امتحان میکند

### سیستم امتیازدهی

هر ارائهدهنده امتیازی بین ۰ تا ۱ دریافت میکند. هرچه امتیاز بالاتر باشد، تناسب آن بیشتر است.

| عامل        | وزن | مفهوم آن                                         |
| ----------- | --- | ------------------------------------------------ |
| سلامت       | ۲۰٪ | آیا ارائهدهنده کار میکند؟ (وضعیت قطعکنندهٔ مدار) |
| سهمیه       | ۱۵٪ | آیا ظرفیت باقیمانده دارد؟                        |
| هزینه       | ۱۵٪ | چقدر گران است؟ (ارزانتر = امتیاز بالاتر)         |
| سرعت        | ۱۲٪ | چقدر سریع است؟ (تأخیر کمتر = امتیاز بالاتر)      |
| تناسب وظیفه | ۸٪  | آیا برای این نوع وظیفه مناسب است؟                |
| پایداری     | ۵٪  | آیا عملکرد ثابتی دارد؟ (نرخ خطای پایین)          |
| سطح         | ۵٪  | سطح حساب (Ultra > Pro > Free)                    |
| سایر        | ۲۰٪ | وابستگی زمینه، تراکم اتصال و غیره                |

### نحوهٔ تغییر امتیازدهی توسط گونهها

هر گونه از وزنهای متفاوتی استفاده میکند:

| گونه           | اولویتها     | وزنهای کلیدی                    |
| -------------- | ------------ | ------------------------------- |
| `auto`         | متعادل       | health=20%, quota=15%, cost=15% |
| `auto/coding`  | کیفیت        | taskFit=37%, stability=15%      |
| `auto/fast`    | سرعت         | latency=32%, health=28%         |
| `auto/cheap`   | هزینه        | cost=37%                        |
| `auto/smart`   | کیفیت + کاوش | taskFit=37%, exploration=10%    |
| `auto/offline` | ظرفیت        | quota=37%, health=28%           |

## نحوه مدیریت خطاها

OmniRoute دارای **سه لایه محافظتی** است:

### 1. جایگزینی خودکار

اگر بهترین ارائهدهنده با خطا مواجه شود، OmniRoute بهطور خودکار ارائهدهنده بعدی را امتحان میکند. نیازی نیست کاری انجام دهید.

### 2. خودترمیمی

اگر یک ارائهدهنده پیوسته با خطا مواجه شود:

- **امتیاز < 0.2** → بهمدت ۵ دقیقه کنار گذاشته میشود
- **مدارشکن باز** → بهطور خودکار کنار گذاشته میشود
- **از دسترس خارج بودن بیش از ۵۰٪ ارائهدهندگان** → حالت رخداد (بدون کاوش)

### 3. جایگزین اضطراری

اگر همه ارائهدهندگان با خطا مواجه شوند، OmniRoute بهعنوان آخرین راهکار، درخواست را به ارائهدهندگان رایگان و پایدار (مانند Kiro یا Qoder) هدایت میکند.

---

## پشتیبانی از چند حساب

اگر برای یک ارائهدهنده چند حساب داشته باشید (برای مثال، دو کلید OpenAI)، OmniRoute هرکدام را بهعنوان یک **گزینه مجزا** در نظر میگیرد. این یعنی:

- حساب A سهمیه باقیمانده دارد → از آن استفاده میشود
- حساب B با محدودیت نرخ مواجه است → نادیده گرفته میشود
- حساب C ارزانتر است → در اولویت قرار میگیرد

هر حساب بهطور مستقل و بر اساس وضعیت سلامت، سهمیه و سرعت خودش امتیازدهی میشود.

---

## کاوش بندیت

OmniRoute گاهی برای یافتن گزینههای بهتر، ارائهدهندگان جدید را **کاوش** میکند:

- **پیشفرض**: ۵٪ از درخواستها به ارائهدهندگان تصادفی ارسال میشوند
- **Auto/smart**: نرخ کاوش ۱۰٪
- **غیرفعال** در زمانی که بیش از ۵۰٪ ارائهدهندگان ناسالم باشند

این قابلیت به OmniRoute کمک میکند یاد بگیرد کدام ارائهدهندگان برای الگوهای استفاده شما بهترین عملکرد را دارند.

## پرسشهای متداول

### «آیا همیشه گرانترین مدل را انتخاب میکند؟»

**خیر.** هزینه در حالت پیشفرض تنها ۱۵٪ از امتیاز را تشکیل میدهد. یک ارائهدهنده ارزان، سریع و سالم میتواند از یک ارائهدهنده گرانقیمت امتیاز بیشتری کسب کند. اگر میخواهید هزینه را بیشتر در اولویت قرار دهید، از `auto/cheap` استفاده کنید.

### «اگر یک ارائهدهنده از دسترس خارج شود چه اتفاقی میافتد؟»

OmniRoute بهطور خودکار آن را نادیده میگیرد و ارائهدهنده بعدی را امتحان میکند. اگر یک ارائهدهنده پیوسته با خطا مواجه شود، بهطور موقت (بین ۵ تا ۳۰ دقیقه) کنار گذاشته میشود. نیازی نیست کاری انجام دهید.

### «آیا میتوانم ببینم از کدام ارائهدهنده استفاده شده است؟»

هدرهای پاسخ را بررسی کنید — OmniRoute ارائهدهنده و مدل استفادهشده را در هر پاسخ درج میکند.

### «آیا از نحوه استفاده من یاد میگیرد؟»

بله! سیستم امتیازدهی از دادههای تاریخی (تأخیر، نرخ خطا و نرخ موفقیت) استفاده میکند تا بهمرور زمان تصمیمهای بهتری بگیرد.

### «تفاوت میان `auto` و `auto/smart` چیست؟»

- `auto` — متعادل، با ۵٪ کاوش
- `auto/smart` — کیفیتمحور (با وزنهای یکسان با `auto/coding`)، با ۱۰٪ کاوش

زمانی از `auto/smart` استفاده کنید که بهترین کیفیت را میخواهید و با کاوشهای گاهبهگاه مشکلی ندارید.

### «آیا میتوانم استفاده از یک ارائهدهنده مشخص را اجباری کنم؟»

بله! بهجای `auto` از ترکیبی با راهبرد `priority` استفاده کنید، سپس **نام دقیق** ترکیب را بهعنوان فیلد `model` ارسال کنید (برای مثال، `model: "my-combo"` — نه `auto`). برای جزئیات، به [مرجع فنی](../routing/AUTO-COMBO.md) مراجعه کنید.

### «این روش چه تفاوتی با Round-robin دارد؟»

Round-robin ارائهدهندگان را بهترتیب و بهصورت چرخشی انتخاب میکند. Auto-combo **به هر ارائهدهنده امتیاز میدهد** و بهترین را انتخاب میکند. این روش هوشمندتر است — زیرا سلامت، سرعت، هزینه و کیفیت را در نظر میگیرد.
