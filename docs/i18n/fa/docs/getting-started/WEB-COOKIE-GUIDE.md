ارائهدهندگان Web Cookie به OmniRoute امکان میدهند بهجای کلید API، از طریق نشست فعلی مرورگر شما از یک سرویس هوش مصنوعی استفاده کند. این ارائهدهندگان زمانی مفید هستند که از قبل از طریق وبسایت یک سرویس به آن دسترسی دارید و میخواهید OmniRoute از همان نشست احراز هویتشده استفاده کند.

برخلاف ارائهدهندگان مبتنی بر کلید API، ارائهدهندگان Web Cookie با استفاده از اعتبارنامههایی که مرورگر شما به وبسایت ارسال میکند، احراز هویت میشوند.

---

# پیش از شروع

> **مهم:** همیشه اعتبارنامهها را از یک **درخواست زندهٔ شبکه** کپی کنید، **نه** از محل ذخیرهسازی کوکی مرورگر.

بسیاری از مشکلات احراز هویت بهدلیل کپیکردن کوکیها از محل اشتباه رخ میدهند.

## از محل ذخیرهسازی کوکی کپی نکنید

بیشتر مرورگرها کوکیهای ذخیرهشده را از مسیر زیر نمایش میدهند:

```
DevTools
→ Application (یا Storage)
→ Cookies
```

اگرچه ممکن است این کوکیها صحیح به نظر برسند، احتمال دارد:

- منقضی یا قدیمی باشند
- ناقص باشند
- کوکیهایی را که فقط در درخواستهای احراز هویتشده ارسال میشوند، نداشته باشند

استفاده از این مقادیر ممکن است حتی در صورت معتبر بهنظررسیدن آنها باعث شکست احراز هویت شود.

## از یک درخواست زنده کپی کنید

در عوض، از کوکیهای یک درخواست موفق استفاده کنید:

```
DevTools
→ Network
→ صفحه را تازهسازی کنید
→ یک درخواست چت یا مکالمه را باز کنید
→ Request Headers
→ Cookie
```

هدر درخواست `Cookie` حاوی اطلاعات دقیق احراز هویتی است که مرورگر شما با موفقیت از آن استفاده کرده است.

برای بیشتر ارائهدهندگان Web Cookie، این همان مقداری است که باید در OmniRoute جایگذاری شود.

# راهاندازی عمومی

فرایند راهاندازی برای بیشتر ارائهدهندگان Web Cookie یکسان است.

1. وارد وبسایت ارائهدهنده شوید.
2. ابزارهای توسعهدهندهٔ مرورگر را باز کنید.
3. زبانهٔ **Network** را باز کنید.
4. صفحه را تازهسازی کنید.
5. یک درخواست چت یا مکالمهٔ احراز هویتشده را باز کنید.
6. اعتبارنامههای احراز هویت موردنیاز را کپی کنید.
7. OmniRoute را باز کنید.
8. به **Providers → Add Provider** بروید.
9. ارائهدهندهٔ Web Cookie خود را انتخاب کنید.
10. اعتبارنامهها را جایگذاری کنید.
11. روی **Test Connection** کلیک کنید.
12. ارائهدهنده را ذخیره کنید.

اعتبارنامههای دقیق موردنیاز به ارائهدهنده بستگی دارند.

# قالبهای اعتبارنامهٔ ارائهدهندگان

وبسایتهای مختلف اطلاعات احراز هویت را بهشکلهای متفاوتی ذخیره میکنند. برخی فقط به کوکیها نیاز دارند، درحالیکه برخی دیگر ممکن است به هدرها یا توکنهای اضافی نیز نیاز داشته باشند.

| ارائهدهنده                      | قالب اعتبارنامه               | راهنمای ارائهدهنده               |
| ------------------------------- | ----------------------------- | -------------------------------- |
| Claude Web                      | هدر کامل درخواست Cookie       | `docs/providers/CLAUDE_WEB.md`   |
| ChatGPT Web (Codex)             | هدر کامل Cookie               | `docs/providers/CHATGPT_WEB.md`  |
| Gemini Web                      | _(نیازمند بررسی)_             |                                  |
| Copilot Web                     | _(نیازمند بررسی)_             | `docs/providers/COPILOT-M365.md` |
| Microsoft 365 Copilot (BizChat) | WS access_token + chathubPath | `docs/providers/COPILOT-M365.md` |
| Grok Web                        | _(نیازمند بررسی)_             |                                  |
| ...                             | ...                           | ...                              |

> با اضافهشدن ارائهدهندگان جدید Web Cookie یا تغییر الزامات احراز هویت ارائهدهندگان موجود، این جدول را بهروزرسانی کنید.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) یک پلتفرم رایگان گفتوگو برای کاربران است که به ثبتنام نیاز ندارد — نشست در اولین بازدید بهصورت ناشناس ایجاد میشود و از طریق سه کوکی `uid`، `si_usr_id` و `si_ses_id` پایدار میماند. OmniRoute همان نقطه پایانی `/api/dispatch` را از طریق یک شناسه مدل واحد (`notrack-c`، با نام مستعار `ntw`) پروکسی میکند.

### مراحل اتصال

1. [notrack.ai](https://notrack.ai) را در مرورگر خود باز کنید و اجازه دهید کوکی نشست ناشناس تنظیم شود.
2. **DevTools → Network** را باز کنید، صفحه را تازهسازی کنید و روی یکی از درخواستهای `/api` کلیک کنید.
3. در بخش **Request Headers**، مقدار کامل هدر `Cookie` را کپی کنید.
4. در OmniRoute، به **Providers → Add Provider → NoTrack Web (Free)** بروید.
5. رشته کوکی را در فیلد `apiKey` جایگذاری کنید و **Save** را بزنید.

OmniRoute مقادیر `uid`، `si_usr_id` و `si_ses_id` را از رشته جایگذاریشده استخراج میکند و یک هدر تمیز `Cookie` را تنها با همین جفتها بازسازی میکند — و در صورت وجود، `nt_session` (توکن `ntk_…` که برای حسابهای واردشده تنظیم میشود) را نیز اضافه میکند. اگر هر یک از این سه مقدار موجود نباشد، رشته خام جایگذاریشده بدون تغییر ارسال میشود تا اپراتورها بتوانند قالبهای جایگزین را آزمایش کنند.

### شناسههای مدل

| شناسه مدل   | نام نمایشی | توضیحات                                         |
| ----------- | ---------- | ----------------------------------------------- |
| `notrack-c` | NoTrack C  | پیشفرض — مدل ارسال بالادستی `C`.                |
| `C`         | NoTrack C  | نام مستعار `notrack-c` (کد خام ارسال بالادستی). |
| `notrack`   | NoTrack C  | نام مستعار `notrack-c`.                         |
| `ntw`       | NoTrack C  | نام مستعار کوتاه برای `notrack-c`.              |

هر چهار شناسه مدل به یک مدل ارسال بالادستی یکسان (`C`) نگاشت میشوند.

### گزینههای درخواست

اجراکننده این فیلدهای اختیاری را در بدنه درخواست میپذیرد:

| فیلد بدنه             | پیشفرض  | کاربرد                                                         |
| --------------------- | ------- | -------------------------------------------------------------- |
| `notrack_mode`        | `usual` | حالت ارسال (رشته با قالب آزاد؛ بالادست `usual` و … را میپذیرد) |
| `notrack_max_turns`   | `6`     | تعداد نوبتهای داخلی که بالادست میتواند پیش از پاسخدادن طی کند. |
| `notrack_chat_id`     | `null`  | ادامه یک گفتوگوی بالادستی موجود (برای گفتوگوی جدید حذف شود).   |
| `notrack_attachments` | `[]`    | آرایه عبوری توصیفگرهای پیوست بالادستی.                         |
| `notrack_regenerate`  | `false` | برای درخواست تولید مجدد پاسخ نوبت قبلی، روی `true` تنظیم شود.  |

### قابلیتها

- تکمیل گفتوگو بهصورت **جریانی و غیرجریانی**.
- **فراخوانی ابزار** — در درخواست، `tools: [...]` را تنظیم کنید؛ اجراکننده آنها را در قالب قرارداد پوششی فراخوانی ابزار سریالسازی میکند و پاسخهای مدل را دوباره به `tool_calls` در قالب OpenAI تبدیل میکند.
- **`response_format`** — از `json_object` و `json_schema` پشتیبانی میشود. اجراکننده نخستین شیء JSON را از پاسخ مدل استخراج میکند و پیش از بازگرداندن، آن را به رشته تبدیل میکند.
- **نشانه استدلال** — هنگامی که بالادست یک رویداد `thinking` ارسال کند، اجراکننده یک دلتا از نوع `reasoning` منتشر میکند.

### محدودیتها

- بالادست سهمیههای استفاده ناشناس را اعمال میکند — در صورت عبور از سهمیه، اجراکننده خطای 429 را همراه با پیامی مناسب نمایش میدهد.
- همه شناسههای مدل به یک مدل ارسال بالادستی یکسان منتهی میشوند؛ امکان تغییر جداگانه مدل وجود ندارد.
- اجراکننده نقطه پایانی `/api/chats` بالادست را فراخوانی نمیکند، بنابراین تاریخچه گفتوگوها / نشستها بهصورت خودکار مدیریت نمیشوند. برای ادامه یک گفتوگوی بالادستی موجود، از `notrack_chat_id` استفاده کنید.

# ارائهدهندگان کوکی وب چه کارهایی میتوانند و نمیتوانند انجام دهند

ارائهدهندگان کوکی وب از رابط گفتوگوی یک وبسایت دوباره استفاده میکنند. آنها قابلیتهایی یکسان با APIهای رسمی ارائه **نمیدهند**.

## پشتیبانیشده

- احراز هویت با استفاده از نشست فعلی مرورگر شما
- دسترسی به مدلهای موجود از طریق حساب شما
- دریافت جریانی پاسخهای چت
- بدون نیاز به کلید API

## پشتیبانینشده

- فراخوانی تابع
- فراخوانی ابزار
- ویرایش خودکار فایل
- گردشکارهای عاملمحور IDE
- قابلیتهای مختص API

این رفتار مورد انتظار است و **اشکال** محسوب نمیشود.

اگر به اجرای ابزار، ویرایش خودکار فایل یا سایر گردشکارهای عاملمحور نیاز دارید، بهجای ارائهدهنده Web Cookie از یک **ارائهدهنده مبتنی بر کلید API** استفاده کنید.

# ملاحظه اعتبارسنجی

موفقیتآمیز بودن **Test Connection** یا اعتبارسنجی کوکی فقط تأیید میکند که اعتبارنامههای ارائهشده ظاهراً در قالب مورد انتظار هستند.

تا زمان رفع Issue #7857، اعتبارسنجی موفقیتآمیز **تضمین نمیکند** که ارائهدهنده بتواند احراز هویت را با موفقیت انجام دهد.

اگر احراز هویت همچنان ناموفق است، مطمئن شوید که اعتبارنامهها را بهجای محل ذخیرهسازی کوکیهای مرورگر، از یک درخواست فعال شبکه کپی کردهاید.

---

# عیبیابی

## احراز هویت ناموفق است

مطمئن شوید که اعتبارنامهها از این بخش کپی شدهاند:

```
Network
→ Request Headers
→ Cookie
```

و **نه** از این بخش:

```
Application
→ Cookies
```

---

## کوکی در مرورگر کار میکند اما در OmniRoute کار نمیکند

برخی ارائهدهندگان کوکیهایی دارند که فقط هنگام درخواستهای احراز هویتشده ارسال میشوند.

پس از باز کردن موفقیتآمیز یک مکالمه، اعتبارنامهها را دوباره از یک درخواست جدید شبکه کپی کنید.

---

## نشست منقضی شده است

ارائهدهندگان Web Cookie از نشست فعلی مرورگر شما استفاده میکنند.

اگر نشست مرورگر شما منقضی شود یا از حساب خارج شوید، باید مجموعه جدیدی از اعتبارنامهها را کپی کنید. برای خودکارسازی تمدید کوکی برای ارائهدهندگان وب پشتیبانیشده، ابزار همراه [افزونه همگامسازی نشست مرورگر](../guides/SESSION-SYNC-EXTENSION.md) را ببینید.

---

## Test Connection موفق است اما درخواستها ناموفقاند

تا زمان رفع Issue #7857، موفقیت در اعتبارسنجی تضمین نمیکند که درخواست احراز هویت با موفقیت انجام شود.

پیش از ادامه عیبیابی، اعتبارنامههای خود را دوباره از یک درخواست جدید و احراز هویتشده کپی کنید.

- اعتبارنامهها را از یک درخواست جدید و احراز هویتشده کپی کنید.
- از استفاده مجدد کوکیهای قدیمی خودداری کنید.
- هنگام استفاده از ارائهدهندگان Web Cookie، نشست مرورگر خود را فعال نگه دارید.
- با کوکیهای کپیشده مانند اعتبارنامههای حساس رفتار کنید.
- هنگامی که به فراخوانی تابع یا گردشکارهای عاملمحور نیاز دارید، از ارائهدهندگان مبتنی بر کلید API استفاده کنید.
