> **خلاصه**: OmniRoute ارائهدهندگان **رایگان** خود را بر اساس کیفیت مدل و با استفاده از **امتیازهای ELO در Arena AI
> (به سبک LMArena)** رتبهبندی میکند. صفحهٔ **رتبهبندی ارائهدهندگان رایگان** را در
> داشبورد باز کنید تا ببینید کدام ارائهدهندگان رایگان، قدرتمندترین مدلها را برای وظیفهٔ شما عرضه میکنند —
> چه بهصورت کلی و چه با فیلتر بر اساس دستهبندی (کدنویسی، بازبینی، مستندسازی، اشکالزدایی).

## چیست

OmniRoute تعداد 329 ارائهدهنده را ثبت میکند که شامل 155 ورودی کاتالوگ با برچسب **رایگان/بدون احراز هویت**
است (بدون احراز هویت،
OAuth با سطح رایگان، یا کلید API با سطح رایگان — به
[راهنمای سطوح رایگان](../getting-started/FREE-TIERS-GUIDE.md) و
[فهرست کامل سطوح رایگان](../reference/FREE_TIERS.md) مراجعه کنید). نکته اینجاست که کیفیت
مدلهای ارائهدهندگان رایگان تفاوت بسیار زیادی دارد. یک ارائهدهندهٔ بدون احراز هویت که مدلی پیشرو ارائه میکند، بسیار کاربردیتر
از ارائهدهندهای است که یک مدل قدیمی و کوچک عرضه میکند.

**رتبهبندی ارائهدهندگان رایگان** با ترکیب کاتالوگ هر ارائهدهندهٔ رایگان و **امتیازهای کیفیت جمعسپاریشده**
از **جدول امتیازات Arena AI** (ELO مبتنی بر ترجیحات انسانی، همان ایدهای که زیربنای میدان رقابت
چتبات LMArena است) به این پرسش پاسخ میدهد: «**کدام ارائهدهندهٔ رایگان بهترین مدل را در اختیار من میگذارد؟**».
سپس ارائهدهندگان بر اساس قدرت **بهترین مدل رایگان** خود رتبهبندی میشوند.

این رتبهبندی از سه منبع واقعی محاسبه میشود:

1. فهرستهای ارائهدهندگان رایگان — `NOAUTH_PROVIDERS`، بههمراه ورودیهای `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` که با `hasFree` علامتگذاری شدهاند
   (`src/shared/constants/providers.ts`).
2. کاتالوگ مدلهای هر ارائهدهنده از رجیستری ارائهدهندگان
   (`open-sse/config/providerRegistry.ts`).
3. امتیازهای تناسب با وظیفه که از ELO مشتق شدهاند و توسط موتور همگامسازی Arena ELO در جدول
   `model_intelligence` پایگاه داده ذخیره میشوند (`src/lib/arenaEloSync.ts`).

منطق اتصال دادهها در `src/lib/freeProviderRankings.ts` قرار دارد.

## نحوهٔ دسترسی

### صفحهٔ داشبورد

داشبورد را باز کنید و به **هزینهها ← رتبهبندی ارائهدهندگان رایگان** بروید، یا مستقیماً به مسیر زیر مراجعه کنید:

```
/dashboard/free-provider-rankings
```

این صفحه (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) موارد زیر را نمایش میدهد:

- یک **سکوی سه رتبهٔ برتر** (🥇 🥈 🥉) برای ارائهدهندگان رایگان با بالاترین رتبه.
- یک **جدول رتبهبندی** کامل با ستونهای **رتبه**، **ارائهدهنده**، **مدل برتر**،
  **امتیاز**، **میانگین امتیاز**، **مدلها** و **نوع**.
- **دکمههای فیلتر دستهبندی**: _همهٔ دستهبندیها_، _پیشفرض_، _کدنویسی_، _بازبینی_،
  _مستندسازی_، _اشکالزدایی_.

نشان **نوع** هر ارائهدهنده مشخص میکند که خدمات آن چگونه رایگان است:

| نشان     | معنی                                                    |
| -------- | ------------------------------------------------------- |
| `NOAUTH` | همیشه رایگان، بدون نیاز به اطلاعات احراز هویت           |
| `OAUTH`  | ارائهدهندهٔ OAuth با سطح رایگان (`hasFree`)             |
| `APIKEY` | ارائهدهندهٔ مبتنی بر کلید API با سطح رایگان (`hasFree`) |

امتیازها بهجای اعداد خام، بهصورت برچسبهای قابلفهم برای انسان (مانند _نخبه_، _عالی_، _بسیار خوب_،
_خوب_، _متوسط_) نمایش داده میشوند، زیرا مقدار زیربنایی نشاندهندهٔ کیفیت نسبی
رتبهبندی است، نه درصد.

### نقطهٔ پایانی API

این صفحه توسط یک نقطهٔ پایانی عمومی و فقطخواندنی
(`src/app/api/free-provider-rankings/route.ts`) پشتیبانی میشود:

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

پارامترهای کوئری (اعتبارسنجیشده با Zod):

| پارامتر    | نوع  | پیشفرض    | توضیحات                                                                                                  |
| ---------- | ---- | --------- | -------------------------------------------------------------------------------------------------------- |
| `category` | رشته | (هیچکدام) | یکی از `default`، `coding`، `review`، `documentation`، `debugging`. برای رتبهبندی ترکیبی آن را حذف کنید. |
| `limit`    | عدد  | `50`      | به بازهٔ `1–100` محدود میشود.                                                                            |

ساختار پاسخ:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` مقدار اصلی Arena ELO است؛ `score` مقدار نرمالشدهٔ تناسب با وظیفه
است (در ادامه ببینید). ارائهدهندگانی که هیچ مدل امتیازدهیشدهای ندارند، از پاسخ حذف میشوند.

## نحوهٔ محاسبهٔ امتیازها

### منبع: جدول رتبهبندی Arena AI

موتور همگامسازی ELO مربوط به Arena (`src/lib/arenaEloSync.ts`) دو جدول رتبهبندی — `text`
و `code` — را از API جدول رتبهبندی Arena AI
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) دریافت میکند. هر ورودی جدول رتبهبندی
شامل نام مدل، ارائهدهنده، `score` مربوط به ELO، بازهٔ اطمینان و تعداد رأیها است.

دستهبندیهای جدول رتبهبندی به دستهبندیهای وظایف OmniRoute نگاشت میشوند:

| جدول رتبهبندی Arena | دستهبندیهای وظایف OmniRoute                       |
| ------------------- | ------------------------------------------------- |
| `text`              | `default`، `review`، `documentation`، `debugging` |
| `code`              | `coding`                                          |

### نرمالسازی (امتیاز تناسب با وظیفه)

امتیازهای خام ELO در هر جدول رتبهبندی به یک **مقدار تناسب با وظیفه در بازهٔ `[0.4, 0.98]`** نرمالسازی میشوند:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

این امتیاز هرگز به `0` یا `1` نمیرسد تا فضای کافی برای بازنویسیهای کاربر باقی بماند. این همان
فیلد `score` است که در پاسخ API میبینید و همان برچسبی است که در داشبورد نمایش داده میشود.

### اطمینان

هر ورودی بر اساس تعداد رأیهای Arena یک سطح اطمینان دریافت میکند:

| اطمینان  | رأیها   |
| -------- | ------- |
| `high`   | ≥ ۵٬۰۰۰ |
| `medium` | ≥ ۱٬۰۰۰ |
| `low`    | < ۱٬۰۰۰ |

### ذخیرهسازی و تازگی دادهها

ورودیهای نرمالشده در جدول DB با نام `model_intelligence` و با
`source = "arena_elo"` نوشته میشوند (`src/lib/db/modelIntelligence.ts`). ورودیها **پس از
۷ روز منقضی میشوند**؛ بنابراین ارائهدهندهای که همگامسازی آن متوقف شود، در نهایت حذف میشود و
دادههای قدیمی ارائه نخواهد شد.

همگامسازی **بهطور پیشفرض فعال است**:

- یکبار هنگام راهاندازی سرور و سپس بر اساس یک زمانسنج دورهای اجرا میشود
  (`src/lib/arenaEloSync.ts` که از `src/instrumentation-node.ts` متصل شده است).
- این فرایند **غیرمسدودکننده است و هرگز باعث خطای مهلک نمیشود** — اگر دریافت داده از منبع بالادستی ناموفق باشد، OmniRoute به کار
  خود ادامه میدهد و رتبهبندیها صرفاً آخرین دادهٔ معتبر را نشان میدهند (یا حالت خالی نمایش داده میشود).

دو متغیر محیطی آن را کنترل میکنند (مستندشده در
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)):

| متغیر                     | پیشفرض            | کاربرد                                                        |
| ------------------------- | ----------------- | ------------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`            | برای انصراف از همگامسازی خروجی، آن را روی `false` تنظیم کنید. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (۲۴ ساعت) | فاصلهٔ زمانی همگامسازی، بر حسب ثانیه.                         |

### همگامسازی دستی / وضعیت / پاکسازی

برای اپراتورها، یک نقطهٔ پایانی مدیریتی احراز هویتشده امکان کنترل دستی را فراهم میکند
(`src/app/api/intelligence/sync/route.ts` — نیازمند احراز هویت مدیریتی است):

```
GET    /api/intelligence/sync          # وضعیت فعلی همگامسازی (enabled، lastSync، nextSync، intervalMs)
POST   /api/intelligence/sync          # راهاندازی همگامسازی دستی؛ بدنه: { "dryRun": true } برای پیشنمایش بدون نوشتن
DELETE /api/intelligence/sync          # پاککردن همهٔ ورودیهای اطلاعاتی همگامشدهٔ arena_elo
```

اگر صفحهٔ رتبهبندی خالی است، یک درخواست دستی `POST /api/intelligence/sync` (یا صرفاً
راهاندازی مجدد سرور) آن را دوباره پر میکند.

### تطبیق مدلها با جدول رتبهبندی

شناسههای مدل در رجیستری و نام مدلها در Arena همیشه دقیقاً یکسان نیستند. رتبهبندی از
تطبیق انعطافپذیر استفاده میکند (`findMatchingIntelligence` در `src/lib/freeProviderRankings.ts`):

1. تطبیق دقیق با شناسهٔ نرمالشدهٔ مدل.
2. تطبیق پس از حذف پسوند نسخه از انتها (برای مثال `kimi-k2.6` ← `kimi-k2`).
3. تطبیق پیشوندی (نام مدل در جدول رتبهبندی، پیشوند شناسهٔ رجیستری باشد).

در سمت همگامسازی، پیشوندهای شناختهشدهٔ ارائهدهندگان (`anthropic/`، `openai/`، `google/`، …)
حذف میشوند و یک نگاشت کوچک نامهای مستعار، نامهای متعارف را به گونههایی که OmniRoute بهصورت
داخلی استفاده میکند گسترش میدهد تا مدلها با هر نامی قابل یافتن باقی بمانند.

### نحوهٔ رتبهبندی یک ارائهدهنده

برای هر ارائهدهندهٔ رایگان، موتور به همهٔ مدلهای موجود در کاتالوگ آن امتیاز میدهد، سپس:

- **مدل برتر** = مدلی از ارائهدهنده که بالاترین امتیاز را دارد.
- **میانگین امتیاز** = میانگین امتیاز تمام مدلهای امتیازدهیشدهٔ آن ارائهدهنده.
- **مدلها** = تعداد مدلهای ارائهدهنده که امتیاز Arena داشتهاند.

ارائهدهندگان ابتدا بر اساس **امتیاز مدل برتر** و سپس بر اساس میانگین امتیاز مرتب میشوند. این روش به
ارائهدهندهای که دستکم یک مدل رایگان قدرتمند عرضه میکند، امتیاز بیشتری میدهد.

## استفاده از آن برای انتخاب ارائهدهندگان رایگان

1. **دستهبندی مناسب را انتخاب کنید.** برای بارهای کاری عاملمحور/کدنویسی از فیلتر **Coding** استفاده کنید، یا
   برای گفتوگوی عمومی آن را روی **All Categories** / **Default** بگذارید. رتبه یک ارائهدهنده یکسان ممکن است
   در دستهبندیهای مختلف متفاوت باشد، زیرا مدل برتر آن در هر تابلوی امتیازات متفاوت است.
2. **برای راهاندازیهای تکمرحلهای، رتبههای برتر را ترجیح دهید.** اگر فقط میخواهید یک یا دو ارائهدهنده رایگان را
   متصل کنید، از ارائهدهندگان دارای بالاترین رتبه در دستهبندی خود شروع کنید.
3. **نشان Type را بررسی کنید.** ارائهدهندگان `NOAUTH` سریعترین گزینه برای اتصال هستند (بدون
   نیاز به اطلاعات احراز هویت). سطوح رایگان `OAUTH` / `APIKEY` به یک ثبتنام سریع نیاز دارند، اما اغلب
   مدلهای قدرتمندتری ارائه میکنند. برای مراحل اتصال، به [راهنمای سطوح رایگان](../getting-started/FREE-TIERS-GUIDE.md) مراجعه کنید.
4. **چندین ارائهدهنده را متصل کنید و اجازه دهید Auto-Combo تصمیم بگیرد.** همان دادههای Arena ELO که
   این صفحه را تغذیه میکنند، در **عامل تناسب با وظیفه** موتور امتیازدهی Auto-Combo نیز به کار میروند
   (`open-sse/services/autoCombo/taskFitness.ts`، ترتیب اولویت
   `user_override → arena_elo → models_dev_tier → static table`). بنابراین، پس از اتصال
   برترین ارائهدهندگان رایگان، مسیریابی با `model: "auto"` (برای مثال، `auto/coding`) در هر درخواست
   بهطور خودکار مدلهای رایگان باکیفیتتر را ترجیح میدهد. برای مشاهده امتیازدهی کامل ۱۶ عاملی، به
   [Auto-Combo](../routing/AUTO-COMBO.md) مراجعه کنید.

## مستندات مرتبط

- [راهنمای سطوح رایگان](../getting-started/FREE-TIERS-GUIDE.md) — نحوه اتصال ارائهدهندگان رایگان،
  بدون نیاز به کارت اعتباری.
- [فهرست سطوح رایگان](../reference/FREE_TIERS.md) — فهرست کامل ارائهدهندگان رایگان
  و محدودیتهای آنها.
- [Auto-Combo](../routing/AUTO-COMBO.md) — موتور مسیریابی ۱۶ عاملی که از همان
  دادههای تناسب با وظیفه Arena ELO استفاده میکند.
- [متغیرهای محیطی](../reference/ENVIRONMENT.md) — مرجع `ARENA_ELO_SYNC_ENABLED` /
  `ARENA_ELO_SYNC_INTERVAL`.
