OmniRoute چگونه هزینهٔ هر درخواست را تخمین میزند، ثبت میکند و گزارش میدهد — و چرا عدد
داشبورد یک **ردیاب صرفهجویی** است، نه یک صورتحساب.

همچنین ببینید: [راهنمای کاربر](./USER_GUIDE.md) · [گالری قابلیتها](./FEATURES.md)

---

## چیست (و چه چیزی نیست)

OmniRoute با ضرب تعداد توکنها در نرخهای قیمتگذاری مدل، برای هر تکمیل یک هزینهٔ دلاری
بهازای هر درخواست تعیین میکند. این اعداد مبنای داشبورد **هزینهها**، رابط خط فرمان
`omniroute cost` / `omniroute usage`، خروجیهای CSV/JSON و بودجههای هر کلید API هستند.

> **«هزینه» در داشبورد یک ردیاب صرفهجویی است، نه یک صورتحساب.** OmniRoute هرگز از شما
> هزینهای دریافت نمیکند — بلکه درخواستهایتان را به ارائهدهندگانی هدایت میکند که از قبل
> متصل کردهاید (اشتراکهای خودتان، سطوح رایگان و کلیدهای API). اگر «هزینهٔ کل ۲۹۰ دلار»
> کاملاً از مدلهای رایگان ناشی شده باشد، یعنی تقریباً **۲۹۰ دلار است که به یک API پولی
> پرداخت _نکردهاید_**. این رقم، _تخمینی_ از هزینهای است که همان ترافیک بر اساس قیمتهای
> فهرست استاندارد میداشت؛ بنابراین میتوانید ببینید مصرفتان در کجا متمرکز است و هدایت
> درخواستها به ارائهدهندگان ارزانتر/رایگان چقدر برایتان صرفهجویی ایجاد میکند.

این توضیح مستقیماً در [README](../../README.md) پروژه نیز آمده است («هزینهٔ داشبورد یک
ردیاب صرفهجویی است، نه یک صورتحساب»).

از آنجا که این عدد تخمینی است:

- به جدول قیمتگذاریای وابسته است که OmniRoute برای هر مدل در اختیار دارد. مدلی که ورودی
  قیمتگذاری نداشته باشد، هزینهٔ `0` ایجاد میکند (در مرورگر بهصورت ردیف «قدیمی / رایگان»
  نمایش داده میشود).
- ترافیک سطح رایگان و اشتراکی نیز همچنان یک هزینهٔ _تخمینی_ انباشته میکند — این همان
  مبلغی است که صرفهجویی میکنید، نه مبلغی که بدهکار هستید.

## هزینهها چگونه تخمین زده میشوند

### منبع قیمتگذاری

هزینهها از یک جدول قیمتگذاری میآیند که با ترتیب اولویت زیر تعیین میشود
([`src/lib/pricingSync.ts`](../../src/lib/pricingSync.ts)):

1. **بازنویسیهای کاربر** — قیمتهایی که در داشبورد یا از طریق `PATCH /api/pricing` تعیین میکنید.
2. **قیمتگذاری خارجی همگامشده** — هنگامی که همگامسازی فعال باشد، از فایل عمومی
   `model_prices_and_context_window.json` متعلق به LiteLLM دریافت میشود (در فضای نام جداگانهٔ
   `pricing_synced` ذخیره میشود تا هرگز بازنویسیهای شما را جایگزین نکند).
3. **مقادیر پیشفرض کدنویسیشده** — همراه OmniRoute ارائه میشوند.

همگامسازی قیمتگذاری خارجی **اختیاری** است و بهطور پیشفرض غیرفعال است. متغیرهای محیطی مرتبط
(به [`.env.example`](../../.env.example) مراجعه کنید):

| متغیر محیطی             | پیشفرض    | هدف                                                                      |
| ----------------------- | --------- | ------------------------------------------------------------------------ |
| `PRICING_SYNC_ENABLED`  | `false`   | فعالسازی همگامسازی پسزمینهای قیمتگذاری LiteLLM هنگام راهاندازی.          |
| `PRICING_SYNC_INTERVAL` | `86400`   | فاصلهٔ همگامسازی برحسب **ثانیه** (پیشفرض: روزانه).                       |
| `PRICING_SYNC_SOURCES`  | `litellm` | فهرست منابع جداشده با ویرگول (در حال حاضر فقط `litellm` پشتیبانی میشود). |

### فرمول هزینه

هزینهٔ هر درخواست بر اساس تعداد توکنها و نرخهای هر یک میلیون توکن در
[`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts)
(`computeCostFromPricing` / `calculateCost`) محاسبه میشود:

- **توکنهای ورودی** (منهای خواندنهای کش و توکنهای ایجاد کش) × نرخ `input`.
- **توکنهای خواندن از کش** × نرخ `cached` (در صورت نبود، نرخ ورودی استفاده میشود).
- **توکنهای ایجاد کش** × نرخ `cache_creation` (در صورت نبود، نرخ ورودی استفاده میشود).
- **توکنهای خروجی** × نرخ `output`.
- **توکنهای استدلال** × نرخ `reasoning` (در صورت نبود، نرخ خروجی استفاده میشود).

همهٔ نرخها بهصورت دلار آمریکا بهازای هر ۱٬۰۰۰٬۰۰۰ توکن تفسیر میشوند. سطح سرویس
«fast»/«priority» یا «flex» در Codex یک ضریب هزینه اعمال میکند
(`getCodexFastCostMultiplier`) — برای مثال، flex با ۵۰٪ تخفیف توکن محاسبه میشود که در
داشبورد بهصورت **صرفهجویی flex** نمایش داده میشود.

نام مدلها ابتدا نرمالسازی میشوند (پیشوندهای مسیر ارائهدهنده مانند `openai/` یا
`accounts/fireworks/models/` حذف میشوند) تا ردیفهای تاریخی همچنان با یک قیمت مطابقت داشته باشند.

### نحوهٔ ثبت هزینه

- هزینهٔ هر درخواست پس از پاسخ محاسبه میشود و بدون انتظار برای نتیجه ثبت میگردد تا هرگز
  تأخیری به کلاینت اضافه نکند. مصرف سهمیهٔ مشترک در تیک بعدی حلقهٔ رویداد، از طریق
  [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts) زمانبندی میشود.
- هزینهکرد کلید API در بافر نگهداری شده و بهصورت دستهای توسط
  [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) تخلیه میشود (فاصلهٔ پیشفرض تخلیه
  ۶۰ ثانیه و بافر ۱٬۰۰۰ ورودی). قابل تنظیم از طریق:

  | متغیر محیطی                         | پیشفرض  | هدف                                   |
  | ----------------------------------- | ------- | ------------------------------------- |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000` | فاصلهٔ تخلیه برحسب میلیثانیه.         |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`  | حداکثر ورودیهای بافرشده پیش از تخلیه. |

ارقام هزینه در داشبورد از یک مبلغ دلاری ذخیرهشده برای هر ردیف خوانده **نمیشوند** — در عوض،
هر بار که نقطهٔ پایانی تحلیل اجرا میشود، بر اساس تعداد توکنها و جدول قیمتگذاری فعلی مجدداً
محاسبه میشوند. این یعنی اصلاح یک قیمت نادرست (و همگامسازی مجدد) تخمین هزینههای تاریخی را
بهصورت عطفبهماسبق بهروزرسانی میکند.

## داشبورد: صفحه هزینهها

صفحه **هزینهها** در `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`) قرار دارد.
نمای اصلی آن، زبانه **نمای کلی هزینهها** است
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`)
که همهچیز را از `GET /api/usage/analytics` بارگذاری میکند.

مواردی که نمایش میدهد:

- **کاشیهای مخارج** — مخارج تخمینی برای _امروز (1d)_، _7d_، _30d_ و بازه انتخابشده.
  انتخابگر بازه: `7d`، `30d`، `90d`، `all`.
- **معیارهای اصلی** — درخواستهای بازه، ارائهدهندگان فعال، مدلهای فعال و میانگین
  هزینه بهازای هر درخواست.
- **کاوشگر هزینه** — جدولی قابل مرتبسازی/فیلتر که بر اساس **ارائهدهنده**، **مدل**،
  **کلید API**، **حساب** یا **سطح سرویس** گروهبندی میشود و هزینه، درخواستها، توکنها،
  میانگین هزینه/درخواست و درصد سهم از کل را نشان میدهد.
- **مصرف توکن** — تعداد کل توکنها / توکنهای ورودی / توکنهای خروجی و نسبت ورودی به خروجی.
- **کارایی مسیریابی** — تعداد بازگشتها، نرخ بازگشت و پوشش مدل درخواستشده.
- **پیشبینی ماهانه** — مخارج پایان ماه را بر اساس میانگین روزانه اخیر پیشبینی میکند.
- **مقایسه دورهای** — درصد تغییر بین نیمه اول و دوم بازه.
- **نمودارها** — روند روزانه هزینه، سهم ارائهدهندگان (دایرهای)، ارائهدهندگان برتر،
  مدلهای برتر، هزینه بر اساس کلید API، هزینه بر اساس حساب، الگوی مصرف هفتگی و نقشه حرارتی فعالیت.
- **برونبری** — بازه فعلی را بهصورت **CSV** یا **JSON** دانلود میکند (دکمهها زمانی
  ظاهر میشوند که داده هزینه غیرصفر وجود داشته باشد).

وقتی ترافیک قیمتگذاریشدهای وجود نداشته باشد، ردیفها بهجای `$0` با برچسب
"قدیمی / رایگان" نمایش داده میشوند که بازتابدهنده مدل ردیاب صرفهجویی است.

### زیربرگههای مرتبط با هزینهها

بخش هزینهها همچنین میزبان موارد زیر است (همه در مسیر `/dashboard/costs/`):

- **قیمتگذاری** (`/dashboard/costs/pricing`) — مشاهده و بازنویسی قیمتهای هر مدل
  (زبانه مشترک قیمتگذاری را رندر میکند).
- **بودجه** (`/dashboard/costs/budget`) — تعیین محدودیت مخارج برای هر دامنه
  (زبانه مشترک بودجه را رندر میکند).
- **اشتراک سهمیه** (`/dashboard/costs/quota-share`) — نماهای مخازن سهمیه مشترک و نرخ مصرف.

## نقاط پایانی API

همه این موارد به احراز هویت مدیریتی نیاز دارند (loopback/JWT، از طریق
`requireManagementAuth`)، مگر اینکه خلاف آن ذکر شده باشد.

### تحلیل مصرف و هزینه

| متد   | نقطه پایانی              | هدف                                                                                                                                                  |
| ----- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET` | `/api/usage/analytics`   | تحلیل کامل هزینه/مصرف: خلاصه، روند روزانه، بر اساس ارائهدهنده/مدل/کلید API/حساب/سطح. کوئری: `range`، `startDate`، `endDate`، `apiKeyIds`، `presets`. |
| `GET` | `/api/usage/utilization` | میزان استفاده از سهمیه هر ارائهدهنده در گذر زمان. کوئری: `range` ‏(`1h`/`24h`/`7d`/`30d`)، `provider`.                                               |
| `GET` | `/api/usage/history`     | ردیفهای خام تاریخچه مصرف.                                                                                                                            |
| `GET` | `/api/usage/call-logs`   | گزارش فراخوانی هر درخواست (مدل، توکنها، هزینه، تأخیر، وضعیت).                                                                                        |
| `GET` | `/api/usage/quota`       | وضعیت سهمیه ارائهدهنده.                                                                                                                              |
| `GET` | `/api/usage/proxy-logs`  | گزارش درخواستهای پراکسی.                                                                                                                             |

### بودجهها

| متد    | نقطه پایانی              | هدف                                                                                  |
| ------ | ------------------------ | ------------------------------------------------------------------------------------ |
| `GET`  | `/api/usage/budget`      | خلاصه هزینه + بررسی بودجه برای یک کلید API (پارامتر کوئری `apiKeyId` الزامی است).    |
| `POST` | `/api/usage/budget`      | تنظیم محدودیتهای روزانه/هفتگی/ماهانه به دلار آمریکا + آستانه هشدار برای یک کلید API. |
| `GET`  | `/api/usage/budget/bulk` | خلاصههای بودجه بهصورت انبوه در میان کلیدهای API.                                     |

> API بودجه برای هر **کلید API** (`apiKeyId`) دامنهبندی میشود. محدودیتهای بازگرداندهشده توسط
> `GET /api/usage/budget` شامل `dailyLimitUsd`، `weeklyLimitUsd`، `monthlyLimitUsd`،
> یک `warningThreshold` و مجموعهای جاری (`totalCostToday`، `totalCostMonth`، …) هستند.

### قیمتگذاری

| متد      | نقطه پایانی             | هدف                                                                                                                   |
| -------- | ----------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/pricing`          | قیمتگذاری ادغامشده فعلی (کاربر + همگامشده + پیشفرضها). برای مشاهده منبع هر ورودی از `?includeSources=1` استفاده کنید. |
| `PATCH`  | `/api/pricing`          | بازنویسی قیمتگذاری برای `{ provider: { model: { input, output, cached, … } } }`.                                      |
| `DELETE` | `/api/pricing`          | بازنشانی قیمتگذاری به مقادیر پیشفرض (با امکان محدودسازی اختیاری از طریق `?provider=&model=`).                         |
| `GET`    | `/api/pricing/defaults` | نمایش نرخهای جایگزین پیشفرض بهازای هر 1M.                                                                             |
| `GET`    | `/api/pricing/models`   | قیمتگذاری کلیدگذاریشده بر اساس مدل.                                                                                   |
| `POST`   | `/api/pricing/sync`     | راهاندازی همگامسازی دستی از منابع خارجی (LiteLLM).                                                                    |
| `GET`    | `/api/pricing/sync`     | وضعیت فعلی همگامسازی.                                                                                                 |
| `DELETE` | `/api/pricing/sync`     | پاککردن تمام دادههای قیمتگذاری همگامشده.                                                                              |

## CLI

رابط خط فرمان OmniRoute فرمانهای هزینه، مصرف و قیمتگذاری را ارائه میکند (ثبتشده در
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs)).

### `omniroute cost`

گزارش هزینه تجمیعشده از `/api/usage/analytics`.

```bash
omniroute cost                          # ۳۰ روز گذشته، گروهبندیشده بر اساس ارائهدهنده
omniroute cost --period 7d              # ۷ روز گذشته
omniroute cost --group-by model         # گروهبندی بر اساس provider | model | combo | api-key | day
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

ستونها: گروه، درخواستها، توکنهای ورودی/خروجی، هزینه (USD) و درصد از کل. یک خط جمع کل
در انتها نمایش داده میشود (با `--quiet` یا `--output json` نمایش داده نمیشود).

### `omniroute usage`

```bash
omniroute usage analytics --period 30d [--provider <id>]   # خلاصه هزینه بهازای هر ارائهدهنده
omniroute usage logs [--limit 100] [--follow] [--api-key <k>] [--search <q>]
omniroute usage quota [--provider <id>] [--check]
omniroute usage utilization [--api-key <k>]
omniroute usage history [--limit 100]
omniroute usage proxy-logs [--limit 100]

# بودجهها
omniroute usage budget list
omniroute usage budget get [scope]
omniroute usage budget set <amount> [--scope global] [--period monthly]
omniroute usage budget reset [scope]
```

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
omniroute pricing get <model>
omniroute pricing sync [--provider <p>] [--force]   # POST /api/pricing/sync
omniroute pricing diff [--model <m>]
omniroute pricing defaults show
omniroute pricing defaults set [--input <p>] [--output <p>] [--cache-read <p>] [--cache-write <p>]
```

> `pricing defaults show` دادهها را از `GET /api/pricing/defaults` میخواند. برای ویرایش قیمت
> مدلهای منفرد، بهجای آن از صفحه **قیمتگذاری** در داشبورد یا `PATCH /api/pricing` استفاده کنید.

## عیبیابی

- **همه هزینهها $0 / «قدیمی / رایگان» نمایش داده میشوند.** مدلهای در حال استفاده ورودی قیمتگذاری ندارند.
  همگامسازی خارجی را فعال کنید (`PRICING_SYNC_ENABLED=true`) و `omniroute pricing sync` را اجرا کنید، یا
  قیمتها را بهصورت دستی از طریق صفحه قیمتگذاری / `PATCH /api/pricing` تنظیم کنید.
- **قیمت یک مدل قدیمی اشتباه است.** قیمت را اصلاح کنید (با لغو مقدار یا همگامسازی مجدد) — هزینه
  در هر بار خواندن تحلیلها بر اساس تعداد توکنها دوباره محاسبه میشود، بنابراین برآوردها بهصورت عطفبهماسبق بهروزرسانی میشوند.
- **میزان هزینهکرد از زمان واقعی عقبتر است.** هزینهکرد هر کلید بهصورت دستهای ثبت میشود؛ اگر به اعداد
  بهروزتری نیاز دارید، مقدار `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` را کاهش دهید.
