> **خلاصه**: OmniRoute مصرف توکنِ هر درخواست را ردیابی میکند، هزینه را محاسبه میکند، سهمیهٔ هر کلید API را اعمال میکند و تحلیلها را در داشبورد نمایش میدهد. این راهنما نحوهٔ عملکرد همهٔ این بخشها را توضیح میدهد.

**منابع:**

- `open-sse/services/usage.ts` (~70KB) — ردیابی اصلی مصرف
- `src/lib/usageAnalytics.ts` (~10KB) — تجمیع دادهها برای داشبورد
- `src/lib/db/quotaSnapshots.ts` — دادههای تاریخی سهمیه
- `src/lib/db/usage*.ts` — چندین ماژول پایگاه داده مرتبط با مصرف

## نمای کلی

هر درخواستی که از OmniRoute عبور میکند، یک **رکورد مصرف** ایجاد میکند که موارد زیر را ثبت میکند:

- **هویت**: کلید API، ارائهدهنده، مدل و ترکیب مربوطه
- **توکنها**: توکنهای پرامپت، توکنهای تکمیل، توکنهای کششده و مجموع
- **هزینه**: مبلغ به دلار آمریکا (محاسبهشده از دادههای قیمتگذاری)
- **زمانبندی**: تأخیر و مهرهای زمانی شروع/پایان
- **وضعیت**: موفق، خطا، محدودشده بر اساس نرخ و غیره

این رکوردها در قالب **تحلیلها** تجمیع میشوند، بهصورت **تصاویر لحظهای سهمیه** ذخیره میشوند و برای اعمال **محدودیت بودجهٔ هر کلید** مورد استفاده قرار میگیرند.

```
درخواست ──▶ chatCore ──▶ usage.record() ──▶ SQLite
                                  │
                          ┌───────┼───────┐
                          ▼       ▼       ▼
                    تحلیلها   سهمیه   صورتحساب
                    (داشبورد)  (اعمال)  (خروجی)
```

## چه اطلاعاتی ثبت میشود

سرویس `usage.ts` برای هر درخواست یک **رویداد مصرف** ثبت میکند:

| فیلد               | نوع     | منبع                                                       |
| ------------------ | ------- | ---------------------------------------------------------- |
| `id`               | string  | UUID تولیدشده هنگام ثبت                                    |
| `apiKeyId`         | string  | کلید API که درخواست را آغاز کرده است                       |
| `provider`         | string  | شناسهٔ ارائهدهنده (openai، anthropic و غیره)               |
| `model`            | string  | شناسهٔ مدل (gpt-5، claude-opus-4-6 و غیره)                 |
| `comboId`          | string? | شناسهٔ ترکیب، اگر مسیریابی از طریق یک ترکیب انجام شده باشد |
| `promptTokens`     | number  | از پاسخ سرویس بالادستی                                     |
| `completionTokens` | number  | از پاسخ سرویس بالادستی                                     |
| `cachedTokens`     | number  | توکنهای حاصل از برخورد کش (کشکردن پرامپت Anthropic و غیره) |
| `totalTokens`      | number  | پرامپت + تکمیل                                             |
| `costUsd`          | number  | محاسبهشده از دادههای قیمتگذاری                             |
| `latencyMs`        | number  | مدتزمان سرتاسری درخواست                                    |
| `status`           | enum    | `success`، `error`، `rate_limited`، `timeout`، `cancelled` |
| `errorClass`       | string? | کلاس خطا در صورتی که وضعیت success نباشد                   |
| `timestamp`        | string  | ISO 8601 UTC                                               |
| `metadata`         | object  | دادهٔ سفارشی تزریقشده توسط افزونه                          |

### توکنها از کجا میآیند

توکنها در **کنترلکنندهٔ پاسخ** از پاسخ ارائهدهندهٔ بالادستی استخراج میشوند:

```ts
// از open-sse/handlers/chatCore.ts
const response = await providerExecutor.execute(provider, request);
const usage = response.usage || {
  prompt_tokens: 0,
  completion_tokens: 0,
  cached_tokens: 0,
};
```

برای ارائهدهندگانی که اطلاعات مصرف را بازنمیگردانند (برخی ارائهدهندگان مبتنی بر کوکی وب)، OmniRoute تعداد توکنها را با استفاده از قاعدهٔ تقریبی `~4 chars per token` **تخمین میزند** (به `open-sse/services/autoCombo/pipelineRouter.ts` مراجعه کنید).

### توکنهای کششده

OmniRoute مقدار `cached_tokens` را جدا از `prompt_tokens` ردیابی میکند، زیرا:

- کشکردن پرامپت در Anthropic برای توکنهای کششده نرخ کمتری دریافت میکند (۱۰٪ نرخ عادی)
- برخی ارائهدهندگان مقدار `cache_read_input_tokens` را بازمیگردانند که باید قیمتگذاری متفاوتی داشته باشد
- تحلیلها میتوانند **نرخ برخورد کش** را نمایش دهند = `cached_tokens / prompt_tokens`

## محاسبه هزینه

هزینهها بر اساس **دادههای قیمتگذاری** همگامسازیشده از LiteLLM (`src/lib/pricingSync.ts`) محاسبه میشوند:

| مدل               | ورودی $/1M | خروجی $/1M | کششده $/1M |
| ----------------- | ---------- | ---------- | ---------- |
| gpt-5             | $2.50      | $10.00     | —          |
| claude-opus-4-6   | $15.00     | $75.00     | $1.50      |
| claude-sonnet-4-5 | $3.00      | $15.00     | $0.30      |
| gemini-2.5-pro    | $1.25      | $10.00     | —          |

فرمول هزینه (`src/lib/usage/costCalculator.ts`):

```ts
cost =
  (prompt_tokens - cached_tokens) * input_price +
  cached_tokens * cached_price +
  completion_tokens * output_price;
```

> **چرا مقدار کششده از پرامپت کم میشود؟** بخش کششده بهصورت جداگانه قیمتگذاری میشود؛ اعمال قیمت ورودی بر کل پرامپت باعث محاسبه بیشازحد هزینه خواهد شد.

### همگامسازی قیمتگذاری

دادههای قیمتگذاری از طریق نقطه پایانی `/api/pricing/sync` بهطور خودکار از LiteLLM همگامسازی میشوند (این فرایند توسط وظیفه cron داخلی اجرا میشود، نه یک متغیر محیطی در دسترس کاربر):

```bash
# اجرای دستی
curl -X POST http://localhost:20128/api/pricing/sync
```

برای مدلهایی که داده قیمتگذاری ندارند، OmniRoute با استفاده از نرخهای میانگین داخلی (برگرفته از دادههای قیمتگذاری LiteLLM)، **هزینه را تخمین میزند**.

## تجمیع بازه تاریخی

ماژول `usageAnalytics.ts` ویجتهای داشبورد را از دادههای خام مصرف محاسبه میکند. این ماژول از 7 بازه زمانی پشتیبانی میکند:

| بازه     | محدوده زمانی                         | کاربرد                     |
| -------- | ------------------------------------ | -------------------------- |
| `1d`     | 24 ساعت گذشته                        | تشخیص جهش ساعتی هزینه      |
| `7d`     | 7 روز گذشته                          | بررسی هفتگی                |
| `30d`    | 30 روز گذشته                         | صورتحساب ماهانه            |
| `90d`    | 90 روز گذشته                         | تحلیل فصلی                 |
| `ytd`    | از 1 ژانویه سال جاری تاکنون          | پیگیری بودجه سالانه        |
| `all`    | تمام زمانها                          | آمار کل دوره               |
| `custom` | تاریخ شروع/پایان تعریفشده توسط کاربر | حسابرسیها، پرسوجوهای موردی |

### ویجتهای محاسبهشده داشبورد

لایه تحلیل برای هر بازه تاریخی، موارد زیر را محاسبه میکند:

| ویجت                   | توضیحات                                                |
| ---------------------- | ------------------------------------------------------ |
| **کارتهای خلاصه**      | مجموع درخواستها، مجموع هزینه، مجموع توکنها، نرخ موفقیت |
| **نمودار روند روزانه** | هزینه + توکنهای روزانه، انباشتهشده بر اساس مدل         |
| **نقشه حرارتی فعالیت** | شبکه ساعت روز × روز هفته، رنگ = تعداد درخواستها        |
| **تفکیک مدلها**        | نمودار دایرهای هزینه بر اساس مدل                       |
| **تفکیک ارائهدهندگان** | نمودار میلهای درخواستها بر اساس ارائهدهنده             |
| **کلیدهای API برتر**   | جدول 10 کلید برتر بر اساس هزینه                        |
| **تحلیل خطا**          | نرخ خطا در طول زمان، کلاسهای خطای پرتکرار              |

### دسترسی برنامهنویسی

````ts
import { computeAnalytics } from "@/lib/usageAnalytics";

const analytics = await computeAnalytics(
  history,              // رکوردهای تاریخچه مصرف
  "7d",                 // بازه زمانی: "1d" | "7d" | "30d" | "90d" | "ytd" | "all" | "custom"
  connectionMap,        // نگاشت اتصال ارائهدهنده (connectionId → نام حساب)
  {
    startDate: "2025-01-01",  // اختیاری: برای بازه "custom"
    endDate: "2025-06-01",   // اختیاری: برای بازه "custom"
  }
);

console.log(analytics.summary.totalCost);   // 12.34 (سنت)
console.log(analytics.byModel[0]);           // { model, cost, requests, promptTokens, completionTokens }

## اعمال سهمیه

سهمیهٔ هر کلید API در دو محل اعمال میشود:

1. **محدودیت نرم** (`quotaWarnAt`): نمایش هشدار در داشبورد هنگامی که مصرف از آستانه عبور کند
2. **محدودیت سخت** (`quotaLimit`): رد درخواست با HTTP 429 هنگامی که مصرف از حد مجاز عبور کند

### پیکربندی

```ts
// برای هر کلید API
await updateApiKey(keyId, {
  quotaWarnAt: 5_00,    // $5.00 — نمایش هشدار
  quotaLimit: 10_00,    // $10.00 — توقف قطعی
  quotaWindow: "month", // "day" | "week" | "month" | "all"
});
````

### جریان اعمال محدودیت

```
درخواست ──▶ quotaCheck()
              │
              ├── در محدودهٔ مجاز؟  ──▶ اجازه
              │
              └── فراتر از محدوده؟  ──▶ 429 درخواستهای بیشازحد
                                   همراه با سرآیند Retry-After
```

### اسنپشاتهای سهمیه

جدول `quotaSnapshots`، **وضعیت تاریخی سهمیه** را برای تحلیل روند ذخیره میکند:

| فیلد | توضیحات |
| ----------- | -------------------------------- | ------ | ------- |
| `apiKeyId` | کلیدی که ردیابی میشود |
| `window` | "day" | "week" | "month" |
| `used` | هزینهٔ مصرفشده در این بازه (سنت) |
| `limit` | محدودیت (سنت) |
| `resetAt` | زمان بازنشانی بازه |
| `createdAt` | زمان ثبت اسنپشات |

اسنپشاتها **در هر درخواست** با هزینهٔ بیشتر از 0 ثبت میشوند و برای موارد زیر به کار میروند:

- نمایش نوار پیشرفت سهمیه در داشبورد
- نمایش نمودارهای روند ۳۰روزهٔ سهمیه
- فعالسازی هشدارها هنگامی که مصرف به محدودیت نزدیک میشود

### واکشی تحلیلهای مصرف

دادههای مصرف از طریق داشبورد یا ابزارهای MCP قابل دسترسی هستند، نه نقاط پایانی مستقیم REST برای برونبری. تحلیلهای موجود عبارتاند از:

- **`/api/usage/analytics`** — معیارهای تجمیعشدهٔ مصرف (گروهبندی بر اساس مدل، ارائهدهنده و کلید)
- **`/api/usage/quota`** — وضعیت فعلی سهمیه برای هر کلید API
- **`/api/usage/history`** — گزارشهای تاریخچهٔ درخواستها

## ابزارهای MCP

دو ابزار MCP دادههای مصرف را در اختیار عاملها قرار میدهند (به `open-sse/mcp-server/tools/` مراجعه کنید):

| ابزار                   | توضیحات                                                 |
| ----------------------- | ------------------------------------------------------- |
| `omniroute_cost_report` | گزارشی از هزینهٔ هر کلید برای یک دورهٔ مشخص تولید میکند |
| `omniroute_check_quota` | وضعیت فعلی سهمیه را برای یک کلید API برمیگرداند         |

نمونهٔ فراخوانی عامل:

```json
{
  "tool": "omniroute_cost_report",
  "args": { "period": "week" }
}
```

## نگهداری و پاکسازی

دادههای مصرف بهازای هر درخواست حدود ~1-10KB افزایش مییابد. در مقیاس بالا، این مقدار میتواند قابلتوجه باشد.

### تنظیمات نگهداری

مدت نگهداری تاریخچه مصرف از طریق تنظیمات پایگاه داده در رابط کاربری یا از طریق `/api/settings/database` پیکربندی میشود.

بهطور پیشفرض، تاریخچه مصرف بهمدت **۹۰ روز** نگهداری میشود.

### پاکسازی

رکوردهای قدیمی توسط `src/lib/db/cleanup.ts` پاکسازی میشوند:

- توسط فرایند زمانبندیشده پسزمینه اجرا میشود
- رکوردهای جدول `usage_history` را که قدیمیتر از دوره نگهداری پیکربندیشده در تنظیم `usageHistory` هستند، حذف میکند

### برآورد فضای ذخیرهسازی

| نرخ درخواست         | فضای ذخیرهسازی ۳۰روزه | فضای ذخیرهسازی ۹۰روزه |
| ------------------- | --------------------- | --------------------- |
| ۱۰۰ درخواست/روز     | ~3MB                  | ~9MB                  |
| ۱٬۰۰۰ درخواست/روز   | ~30MB                 | ~90MB                 |
| ۱۰٬۰۰۰ درخواست/روز  | ~300MB                | ~900MB                |
| ۱۰۰٬۰۰۰ درخواست/روز | ~3GB                  | ~9GB                  |

برای ترافیک بسیار بالا، این موارد را در نظر بگیرید:

- کاهش دوره نگهداری از طریق تنظیمات پایگاه داده
- استفاده از `aggregated_metrics` بهجای رکوردهای خام (فقط برای تحلیل)

## نکات بهینهسازی هزینه

### ۱. از مدل مناسب استفاده کنید

```bash
# پاسخ سریع — از مدل ارزان و سریع استفاده کنید
curl -d '{"model":"auto/fast","messages":[...]}'

# وظیفه پیچیده — از مدل باکیفیت استفاده کنید
curl -d '{"model":"auto/smart","messages":[...]}'
```

### ۲. کش را فعال کنید

کش پرامپت Anthropic در زمینه تکراری **۹۰٪ صرفهجویی** ایجاد میکند:

```ts
// کش بهصورت خودکار انجام میشود — کافی است همان پرامپت سیستمی بزرگ را وارد کنید
const response = await openai.chat({
  model: "claude-sonnet-4-5",
  system: longSystemPrompt, // بهصورت خودکار کش خواهد شد
  messages: [{ role: "user", content: "..." }],
});
```

### ۳. از فشردهسازی استفاده کنید

فشردهسازی RTK + Caveman در نشستهایی با استفاده زیاد از ابزارها **۱۵ تا ۹۵٪ صرفهجویی** ایجاد میکند:

```ts
const config = {
  compression: {
    engine: "rtk",
    intensity: "aggressive",
  },
};
```

### ۴. برای هر کلید سهمیه تعیین کنید

برای جلوگیری از هزینههای خارج از کنترل، همیشه `quotaLimit` را تنظیم کنید:

```ts
await updateApiKey(keyId, { quotaLimit: 10_00 }); // سقف ۱۰ دلار در ماه
```

### ۵. پرمصرفترینها را بررسی کنید

از داشبورد یا **`/api/usage/analytics`** برای گروهبندی بر اساس کلید API و مرتبسازی بر اساس هزینه استفاده کنید:

```bash
GET /api/usage/analytics?groupBy=apiKey
```

## عیبیابی

### «هزینه بیشتر از حد انتظار است»

1. **`/api/usage/analytics?groupBy=model`** را بررسی کنید — مدل گرانقیمت را پیدا کنید
2. **`/api/usage/analytics?groupBy=apiKey`** را بررسی کنید — مصرفکننده پرمصرف را پیدا کنید
3. از بهروز بودن دادههای قیمتگذاری اطمینان حاصل کنید: `POST /api/pricing/sync`

### «رکوردها موجود نیستند»

- تنظیمات نگهداری پایگاه داده را در داشبورد ← پایگاه داده ← پاکسازی بررسی کنید — رکوردهای قدیمی توسط وظیفه پاکسازی دورهای (`src/lib/db/cleanup.ts`) حذف میشوند
- خطاهای `src/lib/db/usage*.ts` را بررسی کنید — خطاهای نوشتن در پایگاه داده ثبت میشوند، اما نمایش داده نمیشوند
- بررسی کنید که درخواست واقعاً به `chatCore` رسیده باشد — مسیریابی ترکیبی را بررسی کنید

### «سهمیه اعمال نمیشود»

- تنظیم `quotaLimit` کلید را بررسی کنید
- مطمئن شوید `quotaWindow` بهدرستی تنظیم شده است
- رکوردهای `quotaSnapshots` را بررسی کنید — این رکوردها باید برای هر درخواست ایجاد شوند
