`@omniroute/opencode-plugin-v2` کل کاتالوگ OmniRoute شما — شامل مدلها، ترکیبها و
ترکیبهای خودکار — را همراه با نامهای نمایشی، قیمتگذاری و سهمیههای سطح رایگان
به انتخابگر مدل OpenCode v2 اضافه میکند.

این بسته از `@omniroute/opencode-plugin` جدا است، زیرا OpenCode v1 و v2 افزونهها را
از طریق قراردادهای متفاوتی بارگذاری میکنند. بستهای را انتخاب کنید که با نسخهٔ اصلی OpenCode شما مطابقت دارد؛
هیچچیز بین آنها مشترک نیست، بنابراین ارتقای یکی هرگز شما را مجبور به ارتقای دیگری نمیکند.

## پیشنیازها

- OpenCode v2.
- یک درگاه OmniRoute قابلدسترسی (`http://localhost:20128` بهصورت پیشفرض).
- Node.js 22 یا 24.

## نصب

افزونه را به `opencode.json` اضافه کنید:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

پس از آن، مدلها بهشکل `omniroute/<provider>/<model>` ظاهر میشوند؛ `providerId` پیشوند و
شناسهٔ یکپارچهسازیای را تعیین میکند که OpenCode اعتبارنامه را زیر آن ذخیره میکند.

## اعتبارنامهها

افزونه کلید درگاه را بهترتیب در سه محل جستوجو میکند:

1. **اعتبارنامهای که در OpenCode متصل کردهاید.** افزونه یک یکپارچهسازی ثبت میکند تا
   جریان احراز هویت خود OpenCode بتواند کلید را ذخیره کند. هیچچیز در `opencode.json` قرار نمیگیرد — این روش را ترجیح دهید.
2. `apiKey` در گزینههای افزونه، برای بازنویسی مختص هر پروژه. این روش کلید را در فایلی قرار میدهد
   که ممکن است آن را commit کنید.
3. `OMNIROUTE_API_KEY` در محیط.

اگر هیچیک از این سه مورد وجود نداشته باشد، کاتالوگ خالی خواهد بود و افزونه بهجای
رها کردن شما با یک انتخابگر خالی و بدون توضیح، هنگام راهاندازی یکبار این موضوع را اعلام میکند.

### توکن مدیریتی کلیدی متفاوت است

ترکیبها، سلامت ارائهدهندگان و غنیسازی (نامهای نمایشی، قیمتگذاری و سهمیههای سطح رایگان) از
endpointهای `/api/*` درگاه دریافت میشوند که در بیشتر استقرارها بهجای کلید استنتاج، پشت یک توکن
**مدیریتی** محافظت میشوند:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<توکن خواندن مدیریتی>"
}
```

اگر `managementReadToken` تنظیم نشده باشد، از `apiKey` بهعنوان مقدار جایگزین استفاده میشود. وقتی درگاه این مقدار جایگزین را
رد کند، کاتالوگ همچنان منتشر میشود، اما شناسههای خام مدل بهجای نامهای نمایشی نشان داده میشوند،
حذف موارد تکراری بر اساس نام مستعار متعارف انجام نمیشود و قیمتگذاری و ترکیبها نیز وجود نخواهند داشت. در این حالت، افزونه برای هر endpoint
یکبار هشدار میدهد و نام endpoint و قابلیتهای ازدسترفته را ذکر میکند — بنابراین دلیل افت کیفیت انتخابگر هرگز مبهم نخواهد بود.

## گزینهها

| کلید                             | پیشفرض                                    | توضیحات                                                                                                    |
| -------------------------------- | ----------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `providerId`                     | `"omniroute"`                             | شناسهٔ ارائهدهنده، شناسهٔ یکپارچهسازی و پیشوندی که مدلها زیر آن ظاهر میشوند                                |
| `baseURL`                        | الزامی                                    | ریشهٔ درگاه، فقط `http(s)`؛ پسوند `/v1` در محلهای لازم اضافه میشود                                         |
| `apiKey`                         | اعتبارنامهٔ متصل، سپس `OMNIROUTE_API_KEY` | کلید چت برای `/v1/*`                                                                                       |
| `managementReadToken`            | مقدار جایگزین آن `apiKey` است             | کلید مربوط به `/api/*` — معمولاً با کلید قبلی **یکسان نیست**                                               |
| `displayName`                    | `"OmniRoute"`                             | نام ارائهدهنده در انتخابگر                                                                                 |
| `timeoutMs`                      | `10000`                                   | مهلت دریافت برای هر endpoint (ترکیبهای خودکار از 5 ثانیه استفاده میکنند)                                   |
| `modelCacheTtlMs`                | `300000`                                  | TTL حافظهٔ نهان کاتالوگ؛ یک snapshot دیسکی شروعهای سرد را آماده میکند                                      |
| `timeouts`                       | مقدار جایگزین آن `timeoutMs` است          | بودجههای زمانی هر endpoint برحسب میلیثانیه: `models`، `combos`، `autoCombos`، `enrichment`                 |
| `enrichment`                     | `true`                                    | دریافت نامها، قیمتگذاری و سهمیههای سطح رایگان                                                              |
| `providerTag`                    | `true`                                    | افزودن نام ارائهدهندهٔ بالادستی که درخواست به آن هدایت میشود، به ابتدای نام نمایشی                         |
| `usableOnly`                     | `false`                                   | فقط ارائهدهندگانی را نگه میدارد که درگاه آنها را تأمینشده گزارش میکند                                      |
| `visibleModels` / `hiddenModels` | `[]`                                      | فهرستهای مجاز بر اساس تطبیق دقیق یا پسوند؛ فهرست غیرمجاز اولویت دارد                                       |
| `geminiSanitization`             | `true`                                    | حذف کلیدواژههای JSON-Schema که Gemini از schema ابزارها رد میکند (ابزارهای `$ref` بدون تغییر ارسال میشوند) |
| `apiFormat.allowAnthropic`       | `false`                                   | هدایت شناسههای موجود در فهرست مجاز از طریق بلوک API مربوط به Anthropic                                     |
| `apiFormat.anthropicModels`      | `[]`                                      | شناسههای کامل مدل که به Anthropic هدایت میشوند                                                             |
| `logLevel` / `startupDebug`      | `warn` / `false`                          | میزان جزئیات logger                                                                                        |

## چگونه کاتالوگ بهروز میماند

کاتالوگ بهصورت تنبل دریافت میشود و بهمدت `modelCacheTtlMs` در حافظهٔ نهان نگهداری میشود، و یک تصویر لحظهای روی دیسک باعث میشود که هنگام در دسترس نبودن درگاه، آخرین کاتالوگ شناختهشده همچنان در دسترس باشد — بنابراین قطعی فقط تازگی دادهها را تحت تأثیر قرار میدهد و هزینهٔ دیگری برای شما ندارد. مدلها و ترکیبها بهمحض رسیدن منتشر میشوند؛ ترکیبهای خودکار، فهرست ارائهدهندگان و لایهٔ غنیسازی نیز هنگام رسیدن ادغام میشوند، بنابراین یک نقطهٔ پایانی کند نمیتواند کل انتخابگر را معطل نگه دارد.

نامها اطلاعاتی را که درگاه در اختیار دارد منتقل میکنند: ارائهدهندهٔ بالادستی که یک مدل به آن مسیریابی میشود، یک نشانگر `[رایگان]` و بودجهٔ همراه آن — بنابراین دو اتصال که یک مدل یکسان را عرضه میکنند، قابل تشخیص باقی میمانند. با `"providerTag": false` پیشوند را غیرفعال کنید.

هیچ فرمانی برای تازهسازی دستی وجود ندارد: فرمانهای OpenCode v2 الگوهای پرامپت هستند، نه callback، بنابراین افزونه نمیتواند چنین فرمانی ارائه کند. تازهسازیها از TTL پیروی میکنند؛ تنها زمانی از میزبان خواسته میشود دوباره بارگذاری کند که کاتالوگ یا لایهٔ پوششی واقعاً تغییر کرده باشد، نه در هر بار تازهسازی.

## فراخوانی ابزار در Gemini

Gemini هر درخواستی را که اعلانهای ابزار آن شامل `$schema` یا
`additionalProperties` باشند، بهطور کامل رد میکند و با `400 INVALID_ARGUMENT` پاسخ میدهد. افزونه این کلیدواژهها را از شِمای ابزارهایی که برای یک مدل Gemini از این ارائهدهنده ارسال میشوند حذف میکند و تمام درخواستهای دیگر را بدون تغییر باقی میگذارد.
ابزاری که دارای `$ref` باشد، بهجای حذف این موارد، بدون تغییر ارسال میشود، زیرا حذف ارجاع باعث میشود شِما به حالت «پذیرش هر چیزی» گسترش یابد.
برای غیرفعال کردن آن، `"geminiSanitization": false` را تنظیم کنید.

## عیبیابی

| نشانه                                         | علت                                                                                                                                             |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| انتخابگر هیچ مدل OmniRoute را نشان نمیدهد     | هیچ کلیدی پیدا نشده است (هشدار هنگام راهاندازی را بررسی کنید)، یا درگاه در دسترس نیست                                                           |
| شناسههای خام مدل، بدون ترکیب و بدون قیمتگذاری | نقاط پایانی مدیریتی توکن را رد کردهاند — `managementReadToken` را تنظیم کنید                                                                    |
| یک نشست روی `opencode-<id>/…` ثابت مانده است  | افزونهٔ v1 مقدار `opencode-<id>` را منتشر میکرد؛ v2 مقدار `<id>` را بدون پیشوند منتشر میکند، بنابراین مدل را دوباره از زیر `<id>/…` انتخاب کنید |
