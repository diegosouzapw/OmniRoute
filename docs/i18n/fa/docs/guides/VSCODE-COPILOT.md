**OmniCopilot** تمام مدلهایی را که OmniRoute شما ارائه میدهد، به انتخابگر مدل _بومی_ GitHub Copilot Chat اضافه میکند. خبری از نوار کناری دوم یا رابط چت جداگانه نیست — حالت عامل Copilot، فراخوانی ابزارها، سرورهای MCP و دستورالعملهای سفارشی همگی همچنان کار میکنند، با این تفاوت که روی مدل انتخابی شما اجرا میشوند.

|                      |                                                                                                                                                 |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **نصب (VS Code)**    | [Marketplace → `diegosouzapw.omnicopilot`](https://marketplace.visualstudio.com/items?itemName=diegosouzapw.omnicopilot)                        |
| **نصب (فورکها)**     | [Open VSX](https://open-vsx.org/extension/diegosouzapw/omnicopilot) — Cursor، Windsurf، VSCodium، Theia، code-server، Gitpod، Antigravity، Kiro |
| **کد منبع / مشکلات** | [github.com/diegosouzapw/OmniCopilot](https://github.com/diegosouzapw/OmniCopilot) (MIT)                                                        |
| **نیازمند**          | VS Code 1.104+                                                                                                                                  |

> **به اشتراک Copilot نیازی نیست.** از VS Code 1.122 به بعد، ارائهدهندهٔ مدل زبانی بدون ورود به GitHub و بدون هیچگونه طرح Copilot کار میکند. تکمیلهای درونخطی و قابلیتهای مبتنی بر تعبیهسازی خارج از API ارائهدهنده باقی میمانند و همچنان به Copilot نیاز دارند.

## راهاندازی

1. **OmniRoute را اجرا کنید** — `npm install -g omniroute && omniroute` (داشبورد در `http://localhost:20128`).
2. **افزونه را نصب کنید** — در نمای Extensions عبارت "OmniRoute" را جستوجو کنید.
3. **یک مدل انتخاب کنید** — Copilot Chat ← انتخابگر مدل ← **Manage Models…** ← **OmniRoute**، سپس موارد دلخواه خود را علامت بزنید.

وقتی OmniRoute روی پورت پیشفرض اجرا میشود، نیازی به پیکربندی نیست. برای یک نمونهٔ راهدور، **آیکون OmniRoute در Activity Bar** را باز کنید (یا `OmniRoute: Manage Connection` را اجرا کنید) و موارد زیر را تنظیم کنید:

- **نشانی URL سرور** — ریشهٔ سرور، برای مثال `http://192.168.0.15:20128`. پسوند `/v1` توسط افزونه اضافه میشود؛ آن را وارد نکنید.
- **کلید API** — فقط زمانی که سرور `REQUIRE_API_KEY` را تنظیم کرده باشد. این کلید از طریق SecretStorage متعلق به VS Code در زنجیرهکلید سیستمعامل ذخیره میشود و هرگز در `settings.json` قرار نمیگیرد.

## آنچه انتخابگر نمایش میدهد

افزونه محتوای خام `GET /v1/models` را نمایش نمیدهد — آن را شکلدهی میکند، و تعداد نمایشدادهشده به دو دلیل عمدی کمتر از اندازهٔ کاتالوگ است.

### برای هر مدل یک شناسه درخواست میکند

مقدار پیشفرض `MODELS_CATALOG_PREFIX_MODE` برابر با **`dual`** است که هر مدل را دو بار معرفی میکند — یک بار با پیشوند کوتاه مستعار و یک بار با پیشوند رسمی ارائهدهنده — تا پیکربندیهای قدیمیتر کلاینت همچنان بتوانند هر دو شکل را تفسیر کنند:

```
cc/claude-sonnet-4-6        ← پیشوند مستعار
claude/claude-sonnet-4-6    ← پیشوند رسمی، همان مدل
```

افزونه **`GET /v1/models?prefix=alias`** را درخواست میکند تا بدون تغییر تنظیم سراسری سرور برای سایر کلاینتهای شما، بهازای هر مدل یک شناسه دریافت شود. در یک نمونهٔ مرجع، این کار **2345 ورودی را به 1396 کاهش داد — 949 مورد تکراری و صفر مدل ازدسترفته.**

اگر ترجیح میدهید این مورد را در سطح سرور برای _همهٔ_ کلاینتها اصلاح کنید، پرچم قابلیت `MODELS_CATALOG_PREFIX_MODE` را در داشبورد روی `alias` تنظیم کنید. برای پارامتر پرسوجو و جدول مربوط به هر حالت، به [API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) مراجعه کنید.

### مدلهایی را که نمیتوانند چت کنند پنهان میکند

کاتالوگ همچنین مدلهای تصویر، ویدئو، صدا، رتبهبندی مجدد، تعبیهسازی و تعدیل محتوا را فهرست میکند. این مدلها در هر صورت هنگام درخواست چت رد میشوند:

```
HTTP 400 — مدل '<id>' یک مدل تولید تصویر است و نمیتواند در
/v1/chat/completions استفاده شود. در عوض از POST /v1/images/generations استفاده کنید.
```

بنابراین پیش از رسیدن به انتخابگر، بر اساس فیلد `type` خود فیلتر میشوند. **مدلهای Responses-API حفظ میشوند** — هر ورودی Codex / GPT-5.x مقدار `supported_endpoints: ["responses"]` را اعلام میکند و OmniRoute آنها را برای `/v1/chat/completions` ترجمه میکند؛ بنابراین کاملاً قابل استفاده هستند.

### ارائهدهندگانی که هرگز پیکربندی نکردهاید

کاتالوگ، مدلهای ارائهدهندگانی با **اتصال فعال** را بههمراه تمام ارائهدهندگان **noAuth** فهرست میکند — همان ارائهدهندگان بدون کلیدی که بخش بزرگی از سطح رایگان را تشکیل میدهند. این رفتار عمدی است. برای پنهان کردن آنها، در تنظیمات داشبورد به `blockedProviders` اضافهشان کنید؛ هیچ تغییری در افزونه لازم نیست.

## داشبورد درون یک تب VS Code

`omnicopilot.dashboardOpen: "editor"` داشبورد OmniRoute را از طریق Simple Browser در یک تب ویرایشگر نمایش میدهد، نه در یک مرورگر خارجی. جاسازی باید **در سمت سرور بهصورت اختیاری فعال شود**؛ این کار از طریق `DASHBOARD_ALLOW_EMBED=vscode` انجام میشود که صفحات HTML را با
`frame-ancestors 'self' vscode-webview:` بهجای مقدار پیشفرض `frame-ancestors 'none'` +
`X-Frame-Options: DENY` ارائه میکند. سطح API (`/api`، `/v1`، `/v1beta`، `/a2a`، `/healthz`) در هر دو حالت هدرهای سختگیرانه را حفظ میکند.

> ⚠️ **این یک پرچم زمان ساخت است، نه زمان اجرا.** Next.js تابع `headers()` را در مانیفست مسیر کامپایل میکند؛ بنابراین `next.config.mjs` متغیر را هنگام ساخت باندل میخواند
> (`next.config.mjs` → `resolveDashboardEmbedMode`، `scripts/build/dashboardEmbed.mjs`).
> تعریف آن پیش از اجرای سروری که از قبل ساخته شده است، هیچ تغییری ایجاد نمیکند — هدرها در زمان ساخت تثبیت شدهاند.

```bash
# متغیر باید در فرمان BUILD وجود داشته باشد
DASHBOARD_ALLOW_EMBED=vscode npm run build        # یا npm run build:release
npm start
```

| روش نصب                    | آیا میتوانید جاسازی را فعال کنید؟                                                                                                             |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| از کد منبع                 | ✅ متغیر را همانطور که در بالا آمده است، روی فرمان ساخت تنظیم کنید                                                                            |
| `npm install -g omniroute` | ❌ بسته منتشرشده همراه با یک باندل ازپیشساختهشده ارائه میشود — در عوض، آن را از کد منبع بسازید                                                |
| ایمیج Docker               | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — ایمیج ازپیشساختهشده در Docker Hub برای جاسازی فعال نشده است |

بدون یک بیلد با قابلیت جاسازی، صفحه از قرار گرفتن در فریم خودداری میکند؛ افزونه این موضوع را از روی هدرهای پاسخ تشخیص میدهد و به مرورگر خارجی برمیگردد — چیزی از کار نمیافتد و افزونه یکبار این موضوع را اطلاع میدهد.
به [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) و ایشوی
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273) مراجعه کنید.

## پیکربندی ابزارهای دیگر از داخل VS Code

**`OmniRoute: Configure Coding CLI`** ابزار خط فرمان `omniroute` را برای نوشتن پروفایلهای آماده استفاده برای Codex CLI، Claude Code، Cline، Continue، Cursor، Aider، OpenCode، Goose، Crush، Qwen Code، Kilo و Roo اجرا میکند — همان پیکربندیهایی که در
[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md) توضیح داده شدهاند. کلید API از طریق متغیر محیطی `OMNIROUTE_API_KEY` به CLI تحویل داده میشود و هرگز در خط فرمان قرار نمیگیرد.

## عیبیابی

| نشانه                                             | علت / راهحل                                                                                                                                                                                                                                                               |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| هیچ مدل OmniRoute در انتخابگر وجود ندارد          | سرور در دسترس نیست. نقطه نوار وضعیت خاکستری میشود؛ `OmniRoute: Check Connection` را اجرا کنید. فرایند کشف عمداً بیصدا است و بهجای نمایش اعلان، هیچ مدلی اضافه نمیکند.                                                                                                     |
| هر مدل دو بار نمایش داده میشود                    | از نسخهای قدیمیتر از 1.0.1 در OmniCopilot استفاده میکنید — آن را بهروزرسانی کنید. افزونه اکنون `?prefix=alias` را درخواست میکند.                                                                                                                                          |
| یک مدل تصویر/صوت قبلاً فهرست میشد، اما اکنون نیست | این تغییر از نسخه 1.0.1 عمدی است — چنین مدلی هیچگاه نمیتوانست به درخواست چت پاسخ دهد.                                                                                                                                                                                     |
| پنل در Activity Bar وجود ندارد                    | VS Code کانتینرهای نمای اضافی را به منوی سرریز **"…"** در پایین Activity Bar منتقل میکند و کانتینری که با کلیک راست مخفی شده باشد، مخفی باقی میماند. روی Activity Bar کلیک راست کنید ← **OmniRoute** را علامت بزنید، یا آن را با `OmniRoute: Manage Connection` باز کنید. |
| داشبورد با وجود حالت `editor` در مرورگر باز میشود | سرور با `DASHBOARD_ALLOW_EMBED=vscode` **ساخته نشده است** (بالا را ببینید) — تنظیم آن هنگام راهاندازی روی یک نصب ازپیشساختهشده هیچ اثری ندارد. این بازگشت به مرورگر عمدی است.                                                                                             |
| فهرست مدلها پس از تغییر ارائهدهندگان قدیمی است    | `OmniRoute: Refresh Models` را اجرا کنید، یا روی پیوند ↻ در پنل کلیک کنید.                                                                                                                                                                                                |
